1. Introduction

In C++, constructors and destructors are special member functions that manage the initialization and cleanup of objects.

When inheritance is used, constructors and destructors execute in a specific order. Understanding this sequence is important when working with base classes and derived classes.

  • Constructor: Initializes an object.
  • Destructor: Performs cleanup when an object is destroyed.
Basic rule: Constructors execute from base class to derived class, while destructors execute from derived class to base class.

2. Constructor and Destructor Sequence in Single Inheritance

In single inheritance, a derived class object contains its base-class portion. Therefore, the base-class constructor executes before the derived-class constructor.

Base Class | v Derived Class Constructor: Base → Derived Destructor: Derived → Base

Example Program

#include <iostream> using namespace std; class Base { public: Base() { cout << "Base Constructor" << endl; } ~Base() { cout << "Base Destructor" << endl; } }; class Derived : public Base { public: Derived() { cout << "Derived Constructor" << endl; } ~Derived() { cout << "Derived Destructor" << endl; } }; int main() { Derived obj; return 0; }

Expected Output

Base Constructor
Derived Constructor
Derived Destructor
Base Destructor

Explanation

  1. The Base constructor executes first.
  2. The Derived constructor executes after the Base constructor.
  3. When the object is destroyed, the Derived destructor executes first.
  4. The Base destructor executes last.

3. Constructor and Destructor Sequence in Multilevel Inheritance

Multilevel inheritance occurs when a class is derived from another derived class.

Class A | v Class B | v Class C Constructor: A → B → C Destructor: C → B → A

Example Program

#include <iostream> using namespace std; class A { public: A() { cout << "A Constructor" << endl; } ~A() { cout << "A Destructor" << endl; } }; class B : public A { public: B() { cout << "B Constructor" << endl; } ~B() { cout << "B Destructor" << endl; } }; class C : public B { public: C() { cout << "C Constructor" << endl; } ~C() { cout << "C Destructor" << endl; } }; int main() { C obj; return 0; }

Expected Output

A Constructor
B Constructor
C Constructor
C Destructor
B Destructor
A Destructor
Remember: In multilevel inheritance, construction follows the inheritance chain from the topmost base class to the final derived class. Destruction follows the reverse order.

4. Constructor and Destructor Sequence in Multiple Inheritance

In multiple inheritance, one derived class inherits from two or more base classes.

Class A Class B \ / \ / Class C Constructor: A → B → C Destructor: C → B → A

The base-class constructors execute in the order in which the base classes are declared in the derived class's inheritance list. The derived-class constructor executes after all base-class constructors.

Example Program

#include <iostream> using namespace std; class A { public: A() { cout << "A Constructor" << endl; } ~A() { cout << "A Destructor" << endl; } }; class B { public: B() { cout << "B Constructor" << endl; } ~B() { cout << "B Destructor" << endl; } }; class C : public A, public B { public: C() { cout << "C Constructor" << endl; } ~C() { cout << "C Destructor" << endl; } }; int main() { C obj; return 0; }

Expected Output

A Constructor
B Constructor
C Constructor
C Destructor
B Destructor
A Destructor
Important: Here, class C declares its base classes in the order public A, public B. Therefore, A is constructed before B, regardless of the order of the constructor's member-initializer list.

5. Constructor and Destructor Sequence in Hybrid Inheritance

Hybrid inheritance combines two or more inheritance types. Its constructor sequence follows the same general rules: base-class subobjects are constructed before the derived class, and destroyed after it.

Class A / \ v v Class B Class C \ / v v Class D Construction: Base classes → Derived classes Destruction: Derived classes → Base classes

If virtual base classes are used, they are initialized before non-virtual direct bases. In a diamond hierarchy, the virtual base is constructed only once.

Example: Hybrid Inheritance with Virtual Base Class

#include <iostream> using namespace std; class A { public: A() { cout << "A Constructor" << endl; } ~A() { cout << "A Destructor" << endl; } }; class B : virtual public A { public: B() { cout << "B Constructor" << endl; } ~B() { cout << "B Destructor" << endl; } }; class C : virtual public A { public: C() { cout << "C Constructor" << endl; } ~C() { cout << "C Destructor" << endl; } }; class D : public B, public C { public: D() { cout << "D Constructor" << endl; } ~D() { cout << "D Destructor" << endl; } }; int main() { D obj; return 0; }

Expected Output

A Constructor
B Constructor
C Constructor
D Constructor
D Destructor
C Destructor
B Destructor
A Destructor
The virtual base class A is constructed only once. It is initialized before the non-virtual direct bases B and C. Destruction takes place in reverse order.

6. Constructor Initialization Order

C++ follows a fixed initialization order. It does not depend on the order in which members appear in the constructor's member-initializer list.

The initialization order is:

  1. Virtual base classes, if any, in depth-first, left-to-right traversal of the inheritance graph.
  2. Direct non-virtual base classes, in the order declared in the inheritance list.
  3. Non-static data members, in the order declared inside the class.
  4. The constructor body executes last.

Example Program

#include <iostream> using namespace std; class Test { int x; int y; public: Test() : y(20), x(10) { cout << "Constructor Body" << endl; cout << "x = " << x << endl; cout << "y = " << y << endl; } }; int main() { Test obj; return 0; }

Expected Output

Constructor Body
x = 10
y = 20

Although the initializer list mentions y before x, x is initialized first because it is declared first in the class.

Important: Always write member initializers in the same order as the member declarations to avoid confusion and compiler warnings.

7. Order of Destruction

Destruction follows the reverse order of construction. When an object is destroyed:

  1. The derived-class destructor body executes first.
  2. Its non-static data members are destroyed in reverse declaration order.
  3. Its direct non-virtual base classes are destroyed in reverse construction order.
  4. Virtual base classes are destroyed after the other bases, in reverse order of their construction.
Core concept: The object is cleaned up in the reverse order of the sequence in which its subobjects were constructed.

8. Constructor and Destructor Order Summary

Inheritance Type Constructor Order Destructor Order
Single Base → Derived Derived → Base
Multilevel A → B → C C → B → A
Multiple Declared base order → Derived Derived → Reverse base order
Hybrid According to base initialization rules Reverse construction order

9. Why Is Constructor and Destructor Order Important?

  • Ensures that base-class data is initialized before derived-class initialization uses it.
  • Helps manage resources such as memory, files and connections.
  • Prevents cleanup from occurring before dependent objects are destroyed.
  • Helps understand program execution in inheritance.
  • Supports reliable object lifecycle management.

10. Important Points

  • Constructors execute from base to derived.
  • Destructors execute from derived to base.
  • In multiple inheritance, base constructors follow the declared inheritance order.
  • Member variables initialize in their declaration order.
  • Virtual base classes are initialized before non-virtual direct bases.
  • A virtual base subobject is constructed only once in the most-derived object.
  • Destruction occurs in reverse construction order.
  • Constructors and destructors are not inherited as ordinary member functions.

11. Interview Questions

Q1. Which constructor executes first in inheritance?

Answer: The base-class constructor executes first.

Q2. Which destructor executes first?

Answer: The derived-class destructor executes first.

Q3. What is the constructor sequence in multilevel inheritance?

Answer: It executes from the topmost base class to the final derived class.

Q4. What is the destructor sequence in multilevel inheritance?

Answer: It executes in reverse order, from the final derived class to the topmost base class.

Q5. How is constructor order decided in multiple inheritance?

Answer: By the order in which base classes are declared in the inheritance list.

Q6. Does the member-initializer list decide member initialization order?

Answer: No. Member declaration order inside the class decides it.

Q7. How many times is a virtual base class constructed in a diamond hierarchy?

Answer: Once for the most-derived object.

Q8. Why do destructors execute in reverse order?

Answer: To ensure derived-class cleanup happens before the base-class subobject is destroyed.

13. Summary

Constructor and destructor execution order is an essential concept in C++ inheritance. Constructors initialize base-class subobjects before derived-class subobjects, while destructors clean up the object in reverse order.

Understanding these rules helps programmers manage object initialization, resource cleanup and complex inheritance structures correctly.

Remember:
Constructor: Base → Derived
Destructor: Derived → Base
