1. Introduction to Named Casts

Type casting is the process of converting a value or expression from one data type to another. C++ provides four named casting operators that make type conversions more explicit and easier to understand.

The four named casts in C++ are:

  • static_cast
  • dynamic_cast
  • const_cast
  • reinterpret_cast
Why named casts? Named casts clearly indicate the intended type conversion. They are generally easier to identify and review than C-style casts.

2. General Syntax

cast_operator<target_type>(expression);

Example:

double value = 25.75; int result = static_cast<int>(value);
Result:
result = 25

The target type is written inside angle brackets, and the expression to be converted is passed inside parentheses.

3. static_cast

static_cast performs conversions that are checked and permitted by the compiler according to C++ type conversion rules. It is commonly used for numeric conversions and conversions between related class types.

Syntax

static_cast<target_type>(expression);

Example 1: Converting double to int

#include <iostream> using namespace std; int main() { double num = 45.89; int result = static_cast<int>(num); cout << "Original value: " << num << endl; cout << "Converted value: " << result << endl; return 0; }
Expected Output:
Original value: 45.89
Converted value: 45

The fractional part is discarded when converting this floating-point value to an integer.

Example 2: Conversion between related class pointers

#include <iostream> using namespace std; class Base { public: void showBase() { cout << "Base class function" << endl; } }; class Derived : public Base { public: void showDerived() { cout << "Derived class function" << endl; } }; int main() { Derived obj; Base* basePtr = &obj; Derived* derivedPtr = static_cast<Derived*>(basePtr); derivedPtr->showBase(); derivedPtr->showDerived(); return 0; }
Expected Output:
Base class function
Derived class function
Important: static_cast does not perform a runtime check for a downcast. The programmer must ensure that the base pointer actually points to an object of the derived type. An invalid downcast can result in undefined behavior.

Common Uses

  • Converting numeric data types.
  • Performing permitted conversions between related types.
  • Converting a derived-class pointer to a base-class pointer.
  • Performing an explicit conversion when the compiler permits it.

4. dynamic_cast

dynamic_cast performs runtime-checked conversions in polymorphic class hierarchies. It is especially useful when converting a base-class pointer or reference to a derived-class pointer or reference.

The base class must be polymorphic. A class is polymorphic when it has at least one virtual function.

Syntax

dynamic_cast<target_type>(expression);

Example: Runtime downcasting

#include <iostream> using namespace std; class Base { public: virtual void display() { cout << "Base class" << endl; } virtual ~Base() = default; }; class Derived : public Base { public: void show() { cout << "Derived class function" << endl; } }; int main() { Base* basePtr = new Derived; Derived* derivedPtr = dynamic_cast<Derived*>(basePtr); if (derivedPtr != nullptr) { cout << "Conversion successful" << endl; derivedPtr->show(); } else { cout << "Conversion failed" << endl; } delete basePtr; return 0; }
Expected Output:
Conversion successful
Derived class function

What happens if conversion fails?

  • For a pointer target, a failed dynamic_cast returns nullptr.
  • For a reference target, a failed dynamic_cast throws std::bad_cast.
Remember: dynamic_cast is used for runtime-checked conversions in polymorphic class hierarchies. It requires Run-Time Type Information (RTTI) support.

5. const_cast

const_cast is used to add or remove const or volatile qualification from a type. It does not perform an ordinary conversion between unrelated data types.

Syntax

const_cast<target_type>(expression);

Example: Removing const qualification

#include <iostream> using namespace std; int main() { int value = 100; const int* ptr = &value; int* modifiablePtr = const_cast<int*>(ptr); *modifiablePtr = 200; cout << "Updated value: " << value << endl; return 0; }
Expected Output:
Updated value: 200

In this example, the original object is not declared const. Therefore, modifying it through the converted pointer is valid.

Important: Removing const qualification does not make an originally const object modifiable. Modifying an object that was originally defined as const after casting away const results in undefined behavior.

Common Uses

  • Adding or removing const qualification.
  • Working with legacy interfaces that do not use const correctly.
  • Adapting pointers when an API requires a different cv-qualified type.

6. reinterpret_cast

reinterpret_cast performs low-level reinterpretation of a value as another type. It is generally used for pointer conversions and other low-level programming situations.

Syntax

reinterpret_cast<target_type>(expression);

Example: Pointer reinterpretation

#include <iostream> using namespace std; int main() { int num = 65; int* intPtr = &num; char* charPtr = reinterpret_cast<char*>(intPtr); cout << "Integer value: " << *intPtr << endl; cout << "Address through char pointer: " << static_cast<void*>(charPtr) << endl; return 0; }
Expected Output (illustrative):
Integer value: 65
Address through char pointer: an implementation-dependent address

The address shown depends on the system and execution environment. This example demonstrates pointer reinterpretation; it does not mean that the integer's stored bytes can safely be treated as an ordinary character string.

Important: reinterpret_cast is a low-level operation. Its use can be implementation-dependent and may lead to undefined behavior if the resulting pointer is used in an invalid way. It should not be treated as a general-purpose safe conversion.

7. Comparison of Four Named Casts

Cast Purpose Runtime Check
static_cast Permitted conversions between related or compatible types No runtime check for downcasting
dynamic_cast Runtime-checked conversions in polymorphic hierarchies Yes
const_cast Adds or removes const/volatile qualification No
reinterpret_cast Low-level reinterpretation of types No

8. Named Casts vs C-Style Cast

C++ also supports the traditional C-style casting syntax. However, named casts make the programmer's intention clearer.

C-Style Cast

double num = 45.75; int result = (int)num;

Named Cast

double num = 45.75; int result = static_cast<int>(num);
C-Style Cast Named Cast
Uses syntax such as (int)value. Uses named conversion operators.
Does not clearly identify the intended conversion category. Makes the intended conversion more explicit.
Can be harder to review in complex code. Improves readability and code review.

9. Which Cast Should You Use?

Requirement Recommended Cast
Convert double to int static_cast
Safely check a derived-class pointer at runtime dynamic_cast
Add or remove const qualification const_cast
Perform a low-level pointer reinterpretation reinterpret_cast
Prefer the most specific named cast that expresses the conversion you intend. Avoid reinterpret_cast unless a genuine low-level requirement exists.

10. Important Interview Questions

Q1. What are named casts in C++?

Named casts are explicit type conversion operators provided by C++. The four types are static_cast, dynamic_cast, const_cast and reinterpret_cast.

Q2. What is the purpose of static_cast?

It performs conversions permitted by the compiler's type-conversion rules, such as numeric conversions.

Q3. What is the main difference between static_cast and dynamic_cast?

static_cast does not perform a runtime check for downcasting, whereas dynamic_cast performs runtime checking in a polymorphic class hierarchy.

Q4. Why does dynamic_cast require a polymorphic base class?

Runtime-checked downcasting requires runtime type information. A polymorphic base class provides the necessary type information.

Q5. What happens when a pointer dynamic_cast fails?

It returns nullptr.

Q6. What happens when a reference dynamic_cast fails?

It throws an exception of type std::bad_cast.

Q7. What is the purpose of const_cast?

It adds or removes const or volatile qualification.

Q8. What is reinterpret_cast?

It performs low-level type reinterpretation, commonly involving pointers.

Q9. Can const_cast safely modify every const object?

No. Modifying an object that was originally defined as const after removing const qualification causes undefined behavior.

Q10. Why are named casts preferred in C++?

They make the intended conversion more explicit and easier to understand during code review and maintenance.

12. Lesson Summary

  • Type casting converts an expression from one type to another.
  • static_cast performs permitted compile-time conversions.
  • dynamic_cast performs runtime-checked conversions in polymorphic hierarchies.
  • const_cast changes const or volatile qualification.
  • reinterpret_cast performs low-level type reinterpretation.
  • Named casts make conversion intentions clearer.
