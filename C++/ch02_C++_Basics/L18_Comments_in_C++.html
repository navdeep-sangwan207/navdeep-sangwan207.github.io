1. Introduction

Comments in C++ are explanatory notes written inside a program to describe its code, logic, functionality, or purpose.

Comments help programmers understand the source code and make programs easier to read, debug, maintain, and modify.

Comments are ignored by the compiler during normal program compilation and do not directly affect program execution.

Important: Comments are written for programmers, not for the computer. They explain the source code but do not execute as program statements.

2. Types of Comments in C++

C++ supports two main types of comments:

  1. Single-line comments
  2. Multi-line comments

3. Single-Line Comments

A single-line comment begins with two forward slashes (//).

Everything after // on that source line is treated as a comment, unless the characters occur inside a string or character literal.

Syntax

// This is a single-line comment

Example 1: Basic Single-Line Comment

#include <iostream> using namespace std; int main() { // Declare an integer variable int number = 100; // Display the value cout << number << endl; return 0; }
Expected Output: 
100

The comments explain the purpose of the variable declaration and output statement.

Example 2: Comment at the End of a Statement

int age = 25; // Stores the person's age

A single-line comment can also appear after a valid statement on the same line.

4. Multi-Line Comments

A multi-line comment begins with /* and ends with */.

It can extend across multiple lines and is useful for writing longer explanations.

Syntax

/* This is a multi-line comment. It can contain multiple lines. */

Example: Multi-Line Comment

#include <iostream> using namespace std; /* Program: Addition of two numbers Purpose: Calculate and display the sum of two integer values. */ int main() { int a = 10; int b = 20; int sum = a + b; cout << "Sum = " << sum << endl; return 0; }
Expected Output: 
Sum = 30

The multi-line comment describes the program's purpose. It does not affect the addition operation.

5. Difference Between Single-Line and Multi-Line Comments

Basis Single-Line Comment Multi-Line Comment
Symbol // /* ... */
Ending Ends at the end of the source line Ends at the closing */
Usage Short explanations Longer explanations
Multiple lines Each line needs its own // Can cover multiple lines
Example // Calculate sum /* Calculate the sum of two numbers */

6. Comments Inside a C++ Program

Comments can be placed in different parts of a program, including before declarations, beside statements, and before functions.

#include <iostream> using namespace std; // Function to calculate the square int square(int number) { return number * number; } int main() { int value = 5; // Input value // Call the square function int result = square(value); // Display the result cout << "Square = " << result << endl; return 0; }
Expected Output: 
Square = 25

Comments describe the function, input variable, function call, and output operation.

7. Comments Are Not Executed

Comments do not perform calculations, display output, or change variable values.

Example

#include <iostream> using namespace std; int main() { // This statement is a comment // cout << "Hello World"; cout << "Program is running" << endl; return 0; }
Expected Output: 
Program is running

The commented-out cout statement is not compiled as an executable statement, so it produces no output.

8. Nested Multi-Line Comments

C++ block comments do not support nesting. A block comment ends at the first matching */ encountered after its opening delimiter.

Incorrect Example

/* Outer comment /* Inner comment */ More comment text */
Warning: The inner */ closes the outer block comment. The remaining text can cause compilation errors.

Correct Alternative

/* Outer explanation // Inner explanation written as a single-line comment More explanation */

A single-line comment marker can be used inside a block comment as ordinary comment text. It does not create a nested block.

9. Comments and String Literals

Comment-like characters inside string literals are treated as part of the string, not as comments.

Example

#include <iostream> using namespace std; int main() { cout << "This is not a // comment" << endl; cout << "Symbols /* and */ inside a string" << endl; return 0; }
Expected Output: 
This is not a // comment
Symbols /* and */ inside a string

The compiler recognizes these symbols as string contents because they are enclosed within quotation marks.

10. Good Commenting Practices

  • Write comments that explain the purpose of code.
  • Use meaningful comments for complex logic.
  • Keep comments short, clear, and relevant.
  • Update comments whenever the related code changes.
  • Use consistent commenting style throughout a project.
  • Explain important assumptions and limitations.
  • Avoid unnecessary comments that repeat obvious code.

Good Example

// Convert temperature from Celsius to Fahrenheit double fahrenheit = (celsius * 9.0 / 5.0) + 32.0;

Poor Example

// Add 1 to number number = number + 1;

The second comment simply repeats what the statement already makes clear. A comment should add useful information.

11. Documentation Comments

In larger C++ projects, comments can be written in a structured format to document functions, classes, parameters, and return values.

Documentation tools such as Doxygen can process specially formatted comments and generate documentation.

Example: Doxygen-Style Function Comment

/** * Calculates the sum of two integers. * * @param a First integer. * @param b Second integer. * @return Sum of the two integers. */ int add(int a, int b) { return a + b; }

The special tags describe the function parameters and its return value.

Documentation comments are still comments in C++. Their special formatting is interpreted by documentation tools, not by the C++ compiler as executable instructions.

12. Common Mistakes

  • Forgetting the closing */ in a multi-line comment.
  • Trying to nest block comments.
  • Using comments to explain code that has already changed.
  • Writing lengthy comments that do not add useful information.
  • Assuming comment symbols inside a string literal start a comment.
  • Using comments instead of correcting unclear variable or function names.
  • Commenting out code permanently instead of removing unused code when appropriate.

15. Important Points to Remember

  • Comments explain the source code to programmers.
  • // is used for single-line comments.
  • /* ... */ is used for multi-line comments.
  • Comments do not execute as program statements.
  • Block comments cannot be nested.
  • Comment markers inside string literals are treated as string contents.
  • Doxygen can generate documentation from specially formatted comments.
  • Good comments explain purpose, assumptions, and complex logic.
