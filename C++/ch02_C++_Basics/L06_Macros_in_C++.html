1. Introduction

A macro is a name or instruction defined using the preprocessor. The C++ preprocessor processes macro directives before the actual compilation of the program.

Macros are commonly used for symbolic constants, conditional compilation and small text substitutions.

Learning Objectives:
  • Understand macros and the preprocessor.
  • Learn the #define and #undef directives.
  • Understand object-like and function-like macros.
  • Learn macro parameters and replacement text.
  • Understand conditional compilation.
  • Identify common macro problems.
  • Compare macros with const, constexpr and inline functions.

2. What Is a Macro?

A macro is a preprocessor definition that associates an identifier with replacement text. When the preprocessor encounters that macro, it substitutes the replacement text according to the macro rules.

Basic Syntax

#define MACRO_NAME replacement_text

Example

#define PI 3.14159

Whenever the preprocessor encounters the macro name PI in an eligible context, it replaces it with 3.14159.

A macro is not an ordinary C++ variable. It does not have a C++ data type or normal variable scope.

3. Understanding the C++ Preprocessor

The preprocessor performs operations on source code before the compiler translates the program into machine code.

Basic Program Processing Flow

C++ Program Processing:
  1. Preprocessing
  2. Compilation
  3. Assembly
  4. Linking

During preprocessing, directives such as #include and #define are processed.

Example

#include <iostream> #define VALUE 100 int main() { std::cout << VALUE; return 0; }

Conceptual Preprocessed Code

int main() { std::cout << 100; return 0; }

The macro name VALUE is replaced with its replacement text before compilation.

4. Types of Macros

Macros are commonly classified according to how they are defined and used.

A. Object-Like Macros

An object-like macro has an identifier followed by replacement text. It does not accept parameters.

Syntax

#define NAME replacement_text

Example

#define MAX_SIZE 100 #define PI 3.14159 #define MESSAGE "Welcome to C++"

The preprocessor replaces the macro identifiers with their corresponding replacement text.

B. Function-Like Macros

A function-like macro accepts parameters and uses them in its replacement text.

Syntax

#define MACRO_NAME(parameters) replacement_text

Example

#define SQUARE(x) ((x) * (x))

When SQUARE(5) is encountered, the preprocessor substitutes the parameter and produces ((5) * (5)).

Object-Like Macro Function-Like Macro
Does not accept parameters. Accepts parameters.
#define SIZE 100 #define SQUARE(x) ((x)*(x))
Replaces an identifier. Replaces a macro invocation with arguments.

5. Using #define Directive

The #define directive defines a macro. It is processed by the preprocessor.

Example 1: Defining a Constant-Like Macro

#include <iostream> #define MAX_MARKS 100 int main() { std::cout << "Maximum Marks: " << MAX_MARKS; return 0; }
Expected Output: 
Maximum Marks: 100

Example 2: Multiple Macros

#include <iostream> #define LENGTH 10 #define WIDTH 5 int main() { int area = LENGTH * WIDTH; std::cout << "Area: " << area; return 0; }
Expected Output: 
Area: 50

6. Function-Like Macros with Parameters

Function-like macros use parameters that are replaced with the corresponding arguments supplied in the macro invocation.

Example 1: Finding the Square

#include <iostream> #define SQUARE(x) ((x) * (x)) int main() { int result = SQUARE(5); std::cout << "Square: " << result; return 0; }
Expected Output: 
Square: 25

Example 2: Finding the Sum

#include <iostream> #define ADD(a, b) ((a) + (b)) int main() { int result = ADD(10, 20); std::cout << "Sum: " << result; return 0; }
Expected Output: 
Sum: 30

Example 3: Finding the Cube

#include <iostream> #define CUBE(x) ((x) * (x) * (x)) int main() { std::cout << "Cube: " << CUBE(3); return 0; }
Expected Output: 
Cube: 27

7. Importance of Parentheses in Macros

Macro replacement is based on textual substitution. Without proper parentheses, operator precedence can produce unexpected results.

Incorrect Macro

#define SQUARE(x) x * x

Consider this statement:

int result = SQUARE(2 + 3);

The replacement becomes:

int result = 2 + 3 * 2 + 3;

Multiplication has higher precedence than addition, so the result is 11 instead of 25.

Correct Macro

#define SQUARE(x) ((x) * (x))

Now the replacement is:

int result = ((2 + 3) * (2 + 3));
Correct Result: 
25
Always parenthesize macro parameters and the complete replacement expression when writing arithmetic macros. Parentheses do not solve every macro problem, especially repeated evaluation of arguments.

8. Side Effects in Function-Like Macros

A macro parameter may be substituted more than once. If an argument contains an operation that changes state, the operation may execute multiple times.

Example

#include <iostream> #define SQUARE(x) ((x) * (x)) int main() { int number = 5; int result = SQUARE(number++); std::cout << "Result: " << result << std::endl; std::cout << "Number: " << number; return 0; }

The macro expands to an expression equivalent to:

(number++) * (number++)

This modifies the same scalar object twice without sequencing between the modifications. The behavior is undefined in C++.

Avoid passing expressions with side effects, such as number++, to macros that may evaluate their arguments more than once.

Safer Alternative: Inline Function

#include <iostream> inline int square(int x) { return x * x; } int main() { int number = 5; int result = square(number++); std::cout << "Result: " << result << std::endl; std::cout << "Number: " << number; return 0; }
Expected Output: 
Result: 25
Number: 6

9. The #undef Directive

The #undef directive removes an existing macro definition. After it is undefined, the macro name is no longer replaced by that definition.

Syntax

#undef MACRO_NAME

Example

#include <iostream> #define VALUE 100 int main() { std::cout << "Value: " << VALUE << std::endl; #undef VALUE // VALUE is no longer a defined macro here. return 0; }
Expected Output: 
Value: 100

The macro is available before the #undef directive and is undefined afterward.

10. Conditional Compilation

Conditional compilation allows the preprocessor to include or exclude portions of source code based on specified conditions.

Common Conditional Directives

Directive Purpose
#if Compiles code when a constant expression is nonzero.
#ifdef Checks whether a macro is defined.
#ifndef Checks whether a macro is not defined.
#elif Checks another condition.
#else Selects the alternative branch.
#endif Ends a conditional preprocessing block.

A. Using #ifdef

#include <iostream> #define DEBUG int main() { #ifdef DEBUG std::cout << "Debug mode is enabled"; #endif return 0; }
Expected Output: 
Debug mode is enabled

B. Using #ifndef

#include <iostream> #define VERSION 1 #ifndef TEST_MODE #define TEST_MODE 0 #endif int main() { std::cout << "Version: " << VERSION; std::cout << "\nTest Mode: " << TEST_MODE; return 0; }
Expected Output: 
Version: 1
Test Mode: 0

C. Using #if and #else

#include <iostream> #define VERSION 2 int main() { #if VERSION == 1 std::cout << "Version One"; #elif VERSION == 2 std::cout << "Version Two"; #else std::cout << "Unknown Version"; #endif return 0; }
Expected Output: 
Version Two

11. Predefined Macros

C++ implementations provide several predefined macros that supply information about the source file, compilation date and other details.

Macro Meaning
__FILE__ Name of the current source file.
__LINE__ Current source line number.
__DATE__ Date of compilation.
__TIME__ Time of compilation.
__cplusplus Integer macro indicating the C++ standard level.

Example

#include <iostream> int main() { std::cout << "File: " << __FILE__ << std::endl; std::cout << "Line: " << __LINE__ << std::endl; std::cout << "Date: " << __DATE__ << std::endl; std::cout << "Time: " << __TIME__ << std::endl; return 0; }
The file name, line number, date and time depend on the source file and compilation environment. The value of __cplusplus depends on the C++ language standard selected by the compiler.

12. Multi-Line Macros

A macro replacement can span multiple physical lines by using a backslash at the end of each continued line.

Example

#include <iostream> #define DISPLAY_VALUES(a, b) \ std::cout << "First: " << (a) << std::endl; \ std::cout << "Second: " << (b) << std::endl; int main() { DISPLAY_VALUES(10, 20); return 0; }
Expected Output: 
First: 10
Second: 20
Multi-line macros can introduce control-flow and readability problems. For complex operations, prefer an inline function.

13. Stringizing and Token Pasting

The preprocessor provides two special operators that can be used in function-like macros.

A. Stringizing Operator (#)

The # operator converts a macro parameter into a string literal.

#include <iostream> #define MAKE_STRING(x) #x int main() { std::cout << MAKE_STRING(Hello C++); return 0; }
Expected Output: 
Hello C++

B. Token-Pasting Operator (##)

The ## operator joins two preprocessing tokens to form a new token.

#include <iostream> #define JOIN(a, b) a##b int main() { int number10 = 100; std::cout << JOIN(number, 10); return 0; }
Expected Output: 
100

Here, JOIN(number, 10) produces the token number10.

14. Advantages and Disadvantages of Macros

Advantages

  • Useful for conditional compilation.
  • Can define symbolic replacement text.
  • Can support platform-specific code.
  • Can simplify some repetitive preprocessor tasks.
  • Can provide compile-time configuration options.

Disadvantages

  • Macros do not provide normal C++ type checking.
  • Text substitution can create unexpected expressions.
  • Arguments may be evaluated more than once.
  • Macros do not follow ordinary variable scope rules.
  • Debugging macro expansions can be difficult.
  • Macros can cause naming conflicts.

15. Macros vs const, constexpr and Inline Functions

C++ provides language features that are often safer alternatives to macros.

Feature Purpose Type Checking
Macro Preprocessor text substitution. No normal C++ type checking.
const Read-only object. Yes
constexpr Compile-time constant expression or function. Yes
Inline function Function with inline specification. Yes

Macro Example

#define SQUARE(x) ((x) * (x))

Inline Function Alternative

inline int square(int x) { return x * x; }

constexpr Function Alternative

constexpr int square(int x) { return x * x; }
Best Practice:
  • Use const for read-only objects.
  • Use constexpr when compile-time evaluation is required.
  • Use inline functions for small reusable operations.
  • Use macros when preprocessor functionality is actually needed.

16. Common Mistakes

1. Missing Parentheses

#define ADD(a, b) a + b

Safer definition:

#define ADD(a, b) ((a) + (b))

2. Missing # Before define

define PI 3.14 // Incorrect #define PI 3.14 // Correct

3. Adding a Semicolon to a Macro Definition

#define SIZE 100;

The semicolon becomes part of the replacement text and may cause syntax errors when the macro is used inside an expression.

Correct definition:

#define SIZE 100

4. Using Side Effects in Macro Arguments

#define SQUARE(x) ((x) * (x)) int result = SQUARE(number++);

Avoid arguments that modify their own values when a macro may substitute them multiple times.

5. Defining Macros with Unclear Names

#define X 100 #define MAX_BUFFER_SIZE 100

Descriptive macro names make code easier to understand.

17. Practice Programs

Program 1: Find the Maximum of Two Numbers

#include <iostream> #define MAX(a, b) (((a) > (b)) ? (a) : (b)) int main() { int first = 25; int second = 40; std::cout << "Maximum: " << MAX(first, second); return 0; }
Expected Output: 
Maximum: 40
This macro can evaluate an argument more than once. Do not use arguments with side effects. Prefer a type-safe function for general-purpose code.

Program 2: Calculate the Area of a Circle

#include <iostream> #define PI 3.14159 #define AREA(r) (PI * (r) * (r)) int main() { double radius = 5.0; std::cout << "Area: " << AREA(radius); return 0; }
Expected Output: 
Area: 78.5397

Program 3: Conditional Compilation

#include <iostream> #define DEBUG_MODE int main() { #ifdef DEBUG_MODE std::cout << "Debug information enabled\n"; #endif std::cout << "Program is running"; return 0; }
Expected Output: 
Debug information enabled
Program is running

18. Interview Questions

Q1. What is a macro in C++?

A macro is a preprocessor definition that provides replacement text for an identifier or macro invocation.

Q2. Which directive is used to define a macro?

The #define directive.

Q3. What are the two common types of macros?

Object-like macros and function-like macros.

Q4. What is the purpose of #undef?

It removes an existing macro definition.

Q5. What is conditional compilation?

It allows the preprocessor to include or exclude source code based on preprocessing conditions.

Q6. Why should macro parameters be parenthesized?

Parentheses help preserve the intended grouping of expressions and prevent operator-precedence errors.

Q7. What is the difference between a macro and a function?

A macro performs preprocessor substitution, while a function is a C++ language construct with type checking and normal argument evaluation.

Q8. What is the ## operator?

It joins two preprocessing tokens to form a new token.

Q9. What is the # operator in a macro?

It converts a macro parameter into a string literal.

Q10. Why are macros sometimes avoided in modern C++?

They lack normal type checking and can cause unexpected substitutions and side effects.

19. Quick Revision

  • Macros are handled by the preprocessor.
  • #define defines a macro.
  • #undef removes a macro definition.
  • Object-like macros do not accept parameters.
  • Function-like macros accept parameters.
  • #ifdef checks whether a macro is defined.
  • #ifndef checks whether a macro is not defined.
  • #if supports conditional preprocessing.
  • # performs stringizing.
  • ## performs token pasting.
  • Prefer const, constexpr and inline functions where appropriate.
