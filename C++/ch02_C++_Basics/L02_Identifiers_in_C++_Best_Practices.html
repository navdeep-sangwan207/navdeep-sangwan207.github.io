1. Introduction

An identifier is a name used to identify a program element such as a variable, function, class, object or namespace. Choosing meaningful identifiers is an important part of writing clean and maintainable C++ programs.

Although C++ defines rules for valid identifiers, good programming requires more than simply following those rules. Identifiers should communicate the purpose of the element they represent.

Learning Objective: Learn how to select meaningful, consistent and readable identifiers and avoid common naming mistakes in C++ programs.

2. Use Meaningful Names

An identifier should describe the purpose or role of the variable, function or class. Meaningful names make code easier to understand without requiring additional explanation.

Example: Poor Naming vs Meaningful Naming

Less Readable Code
#include <iostream> using namespace std; int main() { int a = 80; int b = 90; int c = (a + b) / 2; cout << c; return 0; }
Improved Code
#include <iostream> using namespace std; int main() { int firstSubjectMarks = 80; int secondSubjectMarks = 90; int averageMarks = (firstSubjectMarks + secondSubjectMarks) / 2; cout << "Average Marks = " << averageMarks; return 0; }
Expected Output: 
Average Marks = 85

The improved version makes the purpose of each variable clear and reduces the effort required to understand the code.

3. Follow Consistent Naming Conventions

A naming convention is a consistent style used to name variables, functions, classes and other program elements. Consistency improves readability across a project.

3.1 camelCase

In camelCase, the first word begins with a lowercase letter and each following word begins with an uppercase letter.

studentName totalMarks calculateAverage accountBalance

This style is commonly used for variables and functions.

3.2 PascalCase

In PascalCase, every word begins with an uppercase letter.

Student BankAccount EmployeeRecord PaymentProcessor

This style is commonly used for class and type names.

3.3 snake_case

In snake_case, words are separated using underscores and are usually written in lowercase.

student_name total_marks calculate_average account_balance

This is another readable naming style. A project should use a consistent convention rather than mixing styles unnecessarily.

Comparison

Convention Example Common Usage
camelCase studentName Variables and functions
PascalCase StudentRecord Classes and types
snake_case student_name Variables and functions in some codebases
C++ does not require one particular naming convention. Follow the convention used by your project or development team.

4. Avoid Single-Letter Names

Single-letter identifiers can make code difficult to understand when their purpose is not obvious. Use descriptive names for variables that represent meaningful information.

Less Descriptive
int x = 5000; int y = 12; int z = x * y;
More Descriptive
int monthlySalary = 5000; int numberOfMonths = 12; int annualSalary = monthlySalary * numberOfMonths;
Expected Result: 
annualSalary = 60000
Single-letter names are acceptable in limited situations, such as short mathematical formulas or loop counters where their meaning is immediately clear.

5. Avoid Unnecessary Abbreviations

Unclear abbreviations make code harder to understand. Prefer complete words or widely understood abbreviations.

Unclear Name Recommended Name
stdntNm studentName
totMks totalMarks
calcAvg calculateAverage
empSal employeeSalary
accBal accountBalance
Common technical abbreviations such as ID, URL, CPU and RAM may be appropriate when their meaning is widely understood.

6. Use Names That Match Their Purpose

Variables, functions and classes represent different kinds of program elements. Their names should communicate their roles clearly.

Variable Names

Use nouns or descriptive phrases for variables.

int employeeAge; double productPrice; string customerName;

Function Names

Use action-oriented names that describe what a function does.

calculateTotal(); displayResult(); readInput(); validatePassword();

Class Names

Use names that describe the type of object represented by the class.

class Student { }; class BankAccount { };

7. Avoid Names That Differ Only by Case

C++ treats identifiers with different capitalization as separate names. However, using names that differ only by case can confuse programmers.

int totalMarks = 80; int TotalMarks = 90;

Although both declarations are valid, using both names in the same scope is generally a poor naming choice.

Avoid identifiers such as value, Value and VALUE in the same scope because they are easy to confuse.

8. Avoid Reserved Names

Some identifiers are reserved by the C++ language or implementation. Programmers should avoid using these names for their own variables, functions or classes.

  • Do not use C++ keywords such as int, class or return.
  • Avoid identifiers containing double underscores.
  • Avoid names beginning with an underscore followed by an uppercase letter.
  • Avoid names beginning with an underscore at global namespace scope.
Names such as __value and _Student should not be used for ordinary user-defined identifiers because they fall into reserved-name categories.

9. Keep Identifiers Clear and Reasonably Concise

An identifier should contain enough information to communicate its purpose without becoming unnecessarily long.

Too Short Too Long Better Choice
p priceOfTheProductInTheStore productPrice
n numberOfStudentsCurrentlyEnrolled studentCount
r radiusOfTheCircularObject circleRadius

10. Best Practices Summary

  • Choose meaningful and descriptive identifiers.
  • Follow a consistent naming convention.
  • Use nouns for variables and action-oriented names for functions.
  • Use PascalCase or the project's established style for classes.
  • Avoid unclear abbreviations.
  • Use single-letter names only when their meaning is obvious.
  • Avoid names that differ only by capitalization.
  • Never use keywords as ordinary identifiers.
  • Avoid reserved underscore-based names.
  • Keep names clear, readable and reasonably concise.

11. Practical Programming Example

The following program demonstrates meaningful identifiers and consistent naming in a simple student marks calculation.

C++ Program
#include <iostream> using namespace std; int main() { int mathematicsMarks = 85; int physicsMarks = 90; int chemistryMarks = 80; int totalMarks = mathematicsMarks + physicsMarks + chemistryMarks; double averageMarks = totalMarks / 3.0; cout << "Mathematics = " << mathematicsMarks << endl; cout << "Physics = " << physicsMarks << endl; cout << "Chemistry = " << chemistryMarks << endl; cout << "Total Marks = " << totalMarks << endl; cout << "Average Marks = " << averageMarks << endl; return 0; }
Expected Output: 
Mathematics = 85
Physics = 90
Chemistry = 80
Total Marks = 255
Average Marks = 85

Identifier Analysis

Identifier Purpose
mathematicsMarks Stores mathematics marks.
physicsMarks Stores physics marks.
chemistryMarks Stores chemistry marks.
totalMarks Stores the sum of all marks.
averageMarks Stores the calculated average.

12. Common Naming Mistakes

  1. Using meaningless names such as a, b and c for important data.
  2. Using inconsistent naming styles throughout a project.
  3. Using abbreviations that other programmers cannot understand.
  4. Choosing names that do not describe the purpose of the element.
  5. Using names that differ only by uppercase and lowercase letters.
  6. Using reserved identifiers or C++ keywords.
  7. Making identifiers unnecessarily long.

14. Interview Questions

Q1. What is a naming convention?

A naming convention is a consistent style used to name program elements such as variables, functions and classes.

Q2. What is camelCase?

camelCase starts with a lowercase letter and capitalizes the first letter of each subsequent word, such as studentName.

Q3. What is PascalCase?

PascalCase capitalizes the first letter of every word, such as StudentRecord.

Q4. What is snake_case?

snake_case separates words using underscores, such as student_name.

Q5. Why are meaningful identifiers important?

They make programs easier to read, understand, debug and maintain.

Q6. Does C++ enforce camelCase or snake_case?

No. C++ does not require a specific naming convention. Programmers choose a consistent style.

Q7. Can two identifiers differ only by case?

Yes. C++ is case-sensitive, so they are treated as different identifiers. However, using such names together is generally discouraged.

Q8. Why should reserved names be avoided?

Reserved names are used by the language implementation. Using them can cause conflicts and non-portable code.
