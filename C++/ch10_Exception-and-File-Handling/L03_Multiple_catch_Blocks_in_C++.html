Handling Different Types of Exceptions in a Single Program

1. Introduction to Multiple catch Blocks

In C++, a single try block can be followed by multiple catch blocks. Each catch block is designed to handle a particular type of exception.

When an exception is thrown, the C++ runtime searches the associated catch handlers in order. The first matching handler is executed.

Definition: Multiple catch blocks allow a program to handle different types of exceptions separately using multiple handlers associated with one try block.

Why Use Multiple catch Blocks?

  • To handle different exception types separately.
  • To display specific error messages.
  • To organize error-handling logic.
  • To improve program readability and maintainability.
  • To provide different responses for different errors.

2. Syntax of Multiple catch Blocks

Multiple catch blocks are written immediately after a try block.

General Syntax

try { // Statements that may throw exceptions } catch (int x) { // Handles integer exceptions } catch (double x) { // Handles double exceptions } catch (char x) { // Handles character exceptions }

Explanation

  • The try block contains potentially exceptional code.
  • The first catch block handles integer exceptions.
  • The second catch block handles double exceptions.
  • The third catch block handles character exceptions.
  • Only the first matching catch handler is executed for a thrown exception.
A single thrown exception does not execute all catch blocks. After a matching handler completes, control continues after the complete try-catch construct.

3. Example: Handling Different Data Types

The following program demonstrates multiple catch blocks for different exception types.

Program

#include <iostream> using namespace std; int main() { try { throw 10; } catch (int x) { cout << "Integer exception: " << x << endl; } catch (double x) { cout << "Double exception: " << x << endl; } catch (char x) { cout << "Character exception: " << x << endl; } cout << "Program completed." << endl; return 0; }

Expected Output

Integer exception: 10
Program completed.

Explanation

  1. The program enters the try block.
  2. The statement throw 10; throws an integer.
  3. The runtime checks the catch handlers in order.
  4. The first handler, catch (int x), matches.
  5. The integer exception message is displayed.
  6. The other catch blocks are skipped.
  7. The program continues after the try-catch construct.

4. Handling Different Exceptions Using Conditions

Multiple catch blocks are useful when a program needs to handle different exceptional conditions with different messages.

Program: Number Validation

#include <iostream> using namespace std; int main() { int number; cout << "Enter a number: "; cin >> number; try { if (number == 0) { throw 0; } else if (number < 0) { throw -1.5; } else if (number > 100) { throw 'E'; } cout << "Valid number: " << number << endl; } catch (int x) { cout << "Error: Number cannot be zero." << endl; } catch (double x) { cout << "Error: Negative number entered." << endl; } catch (char x) { cout << "Error: Number exceeds the limit." << endl; } return 0; }

Example Output 1

Enter a number: 0
Error: Number cannot be zero.

Example Output 2

Enter a number: -5
Error: Negative number entered.

Example Output 3

Enter a number: 150
Error: Number exceeds the limit.

Explanation

  • Zero causes an integer exception.
  • A negative number causes a double exception.
  • A number greater than 100 causes a character exception.
  • Each exception is handled by its corresponding catch block.
  • A valid number between 1 and 100 is displayed normally.

5. Order of catch Blocks

The order of catch blocks is important. When an exception is thrown, handlers are checked in the order in which they appear.

The first matching handler is selected. Therefore, more specific handlers should generally appear before more general handlers.

Example: Specific Handler Before General Handler

#include <iostream> using namespace std; int main() { try { throw 25; } catch (int x) { cout << "Integer exception: " << x << endl; } catch (...) { cout << "Some other exception occurred." << endl; } return 0; }
Expected Output: 
Integer exception: 25

Important Rule

Always place specific catch handlers before general handlers. A catch-all handler written before other handlers prevents those later handlers from being selected and can make them unreachable.

6. Catch-All Handler with Multiple catch Blocks

C++ provides a special catch-all handler written as catch (...). It can handle exceptions of any type that have not already matched an earlier handler.

Program

#include <iostream> using namespace std; int main() { try { throw 10.5; } catch (int x) { cout << "Integer exception caught." << endl; } catch (char x) { cout << "Character exception caught." << endl; } catch (...) { cout << "Unknown exception caught." << endl; } return 0; }
Expected Output: 
Unknown exception caught.

Explanation

  • The program throws a double value, 10.5.
  • The integer handler does not match.
  • The character handler does not match.
  • The catch-all handler matches the exception.
  • The unknown exception message is displayed.

7. Multiple catch Blocks with Functions

A function can throw different types of exceptions. The calling function can use multiple catch blocks to handle them separately.

Program

#include <iostream> using namespace std; void checkValue(int value) { if (value == 0) { throw 0; } else if (value < 0) { throw "Negative value"; } else if (value > 100) { throw 100.5; } cout << "Value is valid." << endl; } int main() { try { checkValue(-10); } catch (int x) { cout << "Integer exception: " << x << endl; } catch (const char* message) { cout << "String exception: " << message << endl; } catch (double x) { cout << "Double exception: " << x << endl; } return 0; }
Expected Output: 
String exception: Negative value

Explanation

  1. The main function calls checkValue(-10).
  2. The function detects a negative value.
  3. It throws a string literal.
  4. The exception propagates to main.
  5. The catch (const char* message) handler matches.
  6. The error message is displayed.

8. Catching Standard Exception Objects

C++ provides standard exception classes through the standard library. Many standard exceptions derive from std::exception.

The following example demonstrates catching a standard exception object using a reference.

Program

#include <iostream> #include <stdexcept> using namespace std; int main() { try { throw runtime_error("Runtime error occurred"); } catch (const invalid_argument& e) { cout << "Invalid argument: " << e.what() << endl; } catch (const runtime_error& e) { cout << "Runtime error: " << e.what() << endl; } catch (const exception& e) { cout << "Standard exception: " << e.what() << endl; } return 0; }
Expected Output: 
Runtime error: Runtime error occurred

Explanation

  • runtime_error is a standard exception class.
  • The program throws a runtime_error object.
  • The invalid_argument handler does not match.
  • The runtime_error handler matches and executes.
  • The what() function returns the exception description.
Important: When catching standard exception hierarchies, place derived-class handlers before base-class handlers. Otherwise, a base-class handler may catch the exception first.

9. Difference Between Single and Multiple catch Blocks

Basis Single catch Block Multiple catch Blocks
Number of handlers One catch handler. More than one catch handler.
Exception types Handles a matching type. Can handle different types separately.
Error messages Usually one handling path. Different messages for different types.
Use Simple exception handling. Programs with different exceptional conditions.

10. Important Rules of Multiple catch Blocks

  1. A try block can have multiple catch handlers.
  2. Each handler specifies an exception type.
  3. Handlers are checked in their written order.
  4. Only the first matching handler executes for a thrown exception.
  5. Specific handlers should appear before general handlers.
  6. A catch-all handler uses catch (...).
  7. A catch-all handler should be placed last.
  8. After a handler finishes, execution continues after the try-catch construct.
  9. If no handler matches, the exception propagates outward.

11. Interview Questions and Answers

Q1. What are multiple catch blocks in C++?

Multiple catch blocks allow a program to handle different exception types using separate handlers.

Q2. Can one try block have multiple catch blocks?

Yes. A try block can be followed by multiple catch handlers.

Q3. Which catch block is executed first?

The first matching catch handler in the written order is executed.

Q4. Can multiple catch blocks execute for one exception?

No. Only one matching handler is selected for a particular thrown exception.

Q5. What is a catch-all handler?

It is a handler written as catch (...) that can handle any exception type.

Q6. Why should catch (...) be written last?

Because it can match any exception and would prevent later handlers from being selected.

Q7. Can catch blocks handle different data types?

Yes. They can handle types such as int, double, char, and user-defined exception classes.

Q8. Can a function throw different exception types?

Yes. Different conditions inside a function can throw different types of exceptions.

Q9. What is the purpose of std::exception?

It is the base class for many standard library exception types and provides the virtual what() member function.

Q10. Why should derived exception handlers come first?

A base-class handler can also match a derived exception object. Placing the derived handler first ensures that the more specific handler is selected.

13. Lesson Summary

  • A try block can be followed by multiple catch blocks.
  • Each catch handler can handle a different exception type.
  • The first matching handler is executed.
  • Only one handler executes for a particular thrown exception.
  • Specific handlers should be placed before general handlers.
  • catch (...) is used as a catch-all handler.
  • Standard exception objects can be handled using const references.
  • Exceptions thrown by functions can be caught by their callers.
