1. Introduction to Nested try Blocks

In C++, a nested try block means placing one try block inside another try block. It allows a program to handle exceptions at different levels.

An inner try block can handle an exception locally. If the inner block does not handle the exception, it can propagate to an enclosing try block.

Purpose: Nested try blocks are useful when a program needs separate exception handling for specific operations as well as general exception handling at a higher level.

2. Syntax of Nested try Blocks

try
{
    // Outer try block

    try
    {
        // Inner try block

        throw exception;
    }
    catch (int e)
    {
        // Inner catch block
    }
}
catch (int e)
{
    // Outer catch block
}

Structure:

  1. The outer try block contains another try block.
  2. The inner try block contains statements that may throw exceptions.
  3. The inner catch block handles matching exceptions first.
  4. If no inner handler matches, the exception can propagate outward.

3. First Example: Exception Handled by Inner catch

In this example, an exception is thrown inside the inner try block. The inner catch block handles it, so the outer catch block does not execute. 

#include <iostream>
using namespace std;

int main()
{
    try
    {
        cout << "Inside outer try block" << endl;

        try
        {
            cout << "Inside inner try block" << endl;

            throw 10;
        }
        catch (int x)
        {
            cout << "Inner catch: " << x << endl;
        }

        cout << "After inner catch block" << endl;
    }
    catch (int x)
    {
        cout << "Outer catch: " << x << endl;
    }

    cout << "Program continues..." << endl;

    return 0;
}
Expected Output: 
Inside outer try block
Inside inner try block
Inner catch: 10
After inner catch block
Program continues...

Explanation:

  • Execution enters the outer try block.
  • Execution enters the inner try block.
  • throw 10; throws an integer exception.
  • The inner catch(int x) matches and handles it.
  • Execution continues after the inner catch block.
  • The outer catch block is skipped because the exception was already handled.

4. Second Example: Exception Propagated to Outer catch

If the inner try block does not have a matching catch handler, the exception propagates to the enclosing try block. 

#include <iostream>
using namespace std;

int main()
{
    try
    {
        cout << "Inside outer try block" << endl;

        try
        {
            cout << "Inside inner try block" << endl;

            throw 20;
        }
        catch (double x)
        {
            cout << "Inner catch: " << x << endl;
        }

        cout << "After inner try-catch block" << endl;
    }
    catch (int x)
    {
        cout << "Outer catch: " << x << endl;
    }

    cout << "Program continues..." << endl;

    return 0;
}
Expected Output: 
Inside outer try block
Inside inner try block
Outer catch: 20
Program continues...

Explanation:

  • The inner try block throws integer value 20.
  • The inner catch expects a double, so it does not match.
  • The exception propagates to the enclosing try block.
  • The outer catch(int x) handles the exception.
  • Execution continues after the outer try-catch structure.
When an exception propagates out of the inner try block, the remaining statements in that inner try block and the enclosing try block are skipped until a matching handler is found.

5. Third Example: Rethrowing an Exception

An inner catch block can handle an exception partially and then rethrow it using throw;. The enclosing catch block can then handle the rethrown exception. 

#include <iostream>
using namespace std;

int main()
{
    try
    {
        try
        {
            throw 100;
        }
        catch (int x)
        {
            cout << "Inner catch: " << x << endl;

            throw;
        }
    }
    catch (int x)
    {
        cout << "Outer catch: " << x << endl;
    }

    cout << "Program continues..." << endl;

    return 0;
}
Expected Output: 
Inner catch: 100
Outer catch: 100
Program continues...

Explanation:

  1. The inner try block throws the integer value 100.
  2. The inner catch block receives the exception.
  3. throw; rethrows the currently handled exception.
  4. The outer catch block receives and handles the rethrown exception.
  5. Execution continues after the outer catch block.
Important: A bare throw; can be used to rethrow the currently handled exception from inside a catch handler. It should not be used outside an active exception handler.

6. Difference Between Nested try and Multiple catch Blocks

Nested try Blocks Multiple catch Blocks
One try block is placed inside another try block. Multiple catch blocks are associated with a try block.
Provides exception handling at different levels. Handles different exception types at the same level.
Exceptions can propagate from inner to outer handlers. The first matching handler is executed.
Useful for separating local and general error handling. Useful when one operation can throw different exception types.

7. Important Rules of Nested try Blocks

  • A try block can contain another try block.
  • Each try block can have its own catch handlers.
  • The inner catch block gets the first opportunity to handle an exception thrown in the inner try block.
  • If no inner handler matches, the exception propagates to an enclosing handler.
  • If no enclosing handler matches, the exception continues propagating to the next applicable outer handler.
  • If no matching handler exists anywhere, the program terminates due to an unhandled exception.
  • Use throw; inside a catch block to rethrow the current exception.
  • After a matching handler completes, execution continues after the associated try-catch structure.

8. Common Mistakes

Mistake Correct Understanding
Assuming the outer catch always executes. If the inner catch handles the exception, the outer catch is skipped.
Using a non-matching inner catch and expecting it to handle the exception. The exception propagates to an enclosing matching handler.
Writing throw; outside a catch block. Use bare rethrow only while handling an active exception.
Assuming statements after a throw execute normally. Control transfers to a matching exception handler.

9. Interview Questions

Q1. What is a nested try block?

A nested try block is a try block placed inside another try block. It allows exception handling at different levels.

Q2. Can a try block be placed inside another try block?

Yes. C++ supports nested try blocks.

Q3. What happens if the inner catch block does not match?

The exception propagates to the enclosing try block, where an appropriate outer catch handler may handle it.

Q4. Does the outer catch execute if the inner catch handles the exception?

No. The outer catch is skipped for that exception.

Q5. What is rethrowing an exception?

Rethrowing means passing an already caught exception to another handler using the bare throw; statement.

Q6. What happens if no catch block handles an exception?

If the exception remains unhandled, C++ calls std::terminate(), which normally ends the program.

11. Chapter Summary

  • Nested try blocks mean placing one try block inside another.
  • They support exception handling at multiple levels.
  • The inner catch block gets the first opportunity to handle an inner exception.
  • An unmatched exception can propagate to an outer catch block.
  • The throw; statement rethrows the currently handled exception.
  • Nested exception handling helps organize error handling in complex programs.
