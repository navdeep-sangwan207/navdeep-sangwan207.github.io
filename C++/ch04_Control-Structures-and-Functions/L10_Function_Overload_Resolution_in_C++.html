1. Introduction

Function overload resolution is the process used by the C++ compiler to select the most appropriate function when multiple overloaded functions have the same name.

When a function call is encountered, the compiler examines the available overloaded functions and compares their parameter lists with the arguments supplied in the call.

Definition: Function overload resolution is the compile-time process of identifying the best matching function from a set of overloaded function candidates.

The compiler considers argument types, number of arguments, implicit conversions and other overload-resolution rules.

2. Why Overload Resolution Is Required

Consider these overloaded functions:

void display(int a); void display(double a); void display(char a);

All three functions have the same name. However, when we call display(10), the compiler must decide which function should execute.

  • display(10) selects the integer overload.
  • display(10.5) selects the double overload.
  • display('A') selects the character overload.
The compiler performs this selection during compilation, before the program executes.

3. Steps in Function Overload Resolution

The compiler generally performs the following steps:

  1. Name lookup: Finds functions with the called name that are visible at the call location.
  2. Candidate selection: Forms the set of functions that may be called.
  3. Viability checking: Determines which candidates can accept the supplied arguments.
  4. Conversion ranking: Compares the conversion sequences required by each viable candidate.
  5. Best candidate selection: Selects the uniquely best viable function, if one exists.
If no viable function exists, the call is invalid. If multiple candidates are equally good and no unique best candidate exists, the compiler reports an ambiguous call.

4. Types of Argument Conversions

During overload resolution, C++ compares the conversions required to pass the supplied arguments to function parameters. The following categories are important.

4.1 Exact Match

An exact match is generally preferred over a conversion requiring a promotion or a standard conversion.

#include <iostream> using namespace std; void show(int a) { cout << "Integer function" << endl; } void show(double a) { cout << "Double function" << endl; } int main() { show(10); return 0; }
Expected Output: 
Integer function

The argument 10 has type int. Therefore, the integer overload is an exact match.

4.2 Promotion

A promotion converts a value to a type that can represent it more generally. Promotions are preferred over ordinary standard conversions when comparing otherwise equivalent conversion sequences.

Example: a character argument can be promoted to an integer.

#include <iostream> using namespace std; void display(int a) { cout << "Integer overload" << endl; } void display(double a) { cout << "Double overload" << endl; } int main() { char ch = 'A'; display(ch); return 0; }
Expected Output: 
Integer overload

The char argument is promoted to int, which is preferred over conversion to double.

4.3 Standard Conversion

A standard conversion can convert an argument to another compatible type. For example, an integer can be converted to a floating-point type.

#include <iostream> using namespace std; void print(double a) { cout << "Double value: " << a << endl; } int main() { print(10); return 0; }
Expected Output: 
Double value: 10

The integer argument is converted to double because the function accepts a double parameter.

General preference: When comparing otherwise equivalent conversion sequences, an exact match is preferred over a promotion, and a promotion is preferred over an ordinary standard conversion.

5. Example: Exact Match vs Promotion

#include <iostream> using namespace std; void test(int a) { cout << "Integer function selected" << endl; } void test(double a) { cout << "Double function selected" << endl; } int main() { char ch = 'B'; test(ch); return 0; }
Expected Output: 
Integer function selected

Explanation:

  • The argument is of type char.
  • It can be promoted to int.
  • It can also be converted to double.
  • The promotion to int is preferred.
  • Therefore, test(int) is selected.

6. Ambiguous Function Calls

An ambiguous call occurs when the compiler cannot identify one uniquely best overloaded function.

#include <iostream> using namespace std; void show(int a, double b) { cout << "First function" << endl; } void show(double a, int b) { cout << "Second function" << endl; } int main() { show(10, 10); return 0; }
Compilation Error: The call is ambiguous. The compiler cannot select a unique best overload.

Explanation:

  • The first function requires the second argument to be converted from int to double.
  • The second function requires the first argument to be converted from int to double.
  • Each candidate has one exact match and one conversion.
  • Neither candidate is better for all arguments.
  • Therefore, the compiler reports ambiguity.

How to Resolve Ambiguity

Use arguments with types that clearly match the intended overload.

show(10, 10.5); // Calls show(int, double) show(10.5, 10); // Calls show(double, int)

7. No Matching Function

If none of the available overloaded functions can accept the supplied arguments, the compiler reports an error.

#include <iostream> using namespace std; void display(int a) { cout << a << endl; } int main() { display(10, 20); return 0; }
Compilation Error: No matching function call exists because display() accepts only one argument, but the call supplies two.

8. Role of Default Arguments in Overload Resolution

Default arguments can affect which overloaded functions are viable. They do not automatically make a call ambiguous, but overlapping parameter combinations can create ambiguity.

#include <iostream> using namespace std; void display(int a) { cout << "One parameter function" << endl; } void display(int a, int b = 0) { cout << "Two parameter function" << endl; } int main() { display(10); return 0; }
Compilation Error: The call is ambiguous. Both functions are viable and provide equally good matches for the single integer argument.

To avoid this situation, design overloaded functions so their accepted argument combinations do not overlap unnecessarily.

9. Summary of Conversion Preferences

Conversion category Description Relative preference
Exact Match Argument matches the parameter type directly. Highest among these three categories
Promotion Conversion such as char to int. After exact match
Standard Conversion Conversion such as int to double. After promotion
This table gives the basic ranking commonly used in introductory examples. Full C++ overload resolution also considers reference binding, qualification conversions, user-defined conversions, template candidates and tie-breaking rules.

10. Important Points to Remember

  • Overload resolution takes place during compilation.
  • The compiler identifies candidate functions and checks their viability.
  • The best viable function is selected according to conversion-ranking rules.
  • Exact matches are generally preferred over promotions.
  • Promotions are generally preferred over ordinary standard conversions.
  • An ambiguous call has no unique best candidate.
  • A call with no viable candidate produces a compilation error.
  • Default arguments can make multiple overloads viable.

12. Interview Questions

Q1. What is function overload resolution?

It is the compile-time process of selecting the most appropriate function from a group of overloaded functions.

Q2. When does overload resolution occur?

It occurs during compilation.

Q3. What is a viable function?

A viable function is a candidate that can accept the supplied arguments according to the applicable parameter and conversion rules.

Q4. What is an ambiguous function call?

It occurs when multiple viable functions are equally good and the compiler cannot select one uniquely best function.

Q5. Which is preferred: promotion or standard conversion?

A promotion is preferred over an ordinary standard conversion when the conversion sequences are otherwise comparable.

Q6. What happens when no matching function is found?

The compiler reports an error because no viable function can handle the supplied arguments.

Q7. Can default arguments create ambiguity?

Yes. If multiple overloaded functions become viable for the same call and neither is better, the call is ambiguous.
