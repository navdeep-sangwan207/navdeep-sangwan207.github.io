1. Introduction to Move Constructor

A move constructor is a special member function introduced in C++11. It initializes a new object by transferring resources from an existing object, usually a temporary object that is about to be destroyed.

Instead of copying the resource, a move constructor can transfer ownership of that resource to the new object. This can reduce unnecessary memory allocation and copying.

Definition: A move constructor is a special constructor that initializes an object by transferring resources from another object, typically an rvalue.

Why is a Move Constructor Needed?

  • To avoid unnecessary copying of large objects.
  • To transfer ownership of dynamically allocated resources.
  • To improve performance in resource-management classes.
  • To support efficient movement of objects in containers and other operations.

2. Syntax of Move Constructor

A move constructor normally accepts an rvalue reference to an object of the same class.

ClassName(ClassName&& obj) { // Transfer resources from obj }

Understanding the Syntax

  • ClassName is the name of the class.
  • && declares an rvalue reference.
  • obj refers to the source object.
  • The constructor transfers resources from the source object.
A move constructor commonly takes ClassName&&, while a copy constructor takes const ClassName&.

3. Understanding Copying and Moving

Copy Operation

In copying, a new resource is created and the source data is duplicated. Both objects have their own independent data when a proper deep copy is implemented.

Object A Object B | | |---- Data Block 1 |---- Data Block 2 Value: 100 Value: 100 Separate copies of the data

Move Operation

In moving, ownership of the existing resource is transferred to the destination object. The source object is left in a valid state, usually with no ownership of that resource.

Before move: Object A | |---- Data Block 1 Value: 100 After move: Object A Object B | | |---- nullptr |---- Data Block 1 Value: 100 Resource ownership transferred
The source object remains valid after a move. Its exact state depends on the class implementation. For standard-library types, moved-from objects are generally valid but have an unspecified value unless otherwise documented.

4. Move Constructor Example

The following example uses a dynamically allocated integer. The move constructor transfers the pointer from the source object to the destination object.

Program

#include <iostream> #include <utility> using namespace std; class Number { private: int *ptr; public: // Parameterized constructor Number(int value) { ptr = new int(value); cout << "Constructor called" << endl; } // Copy constructor Number(const Number &obj) { ptr = new int(*obj.ptr); cout << "Copy constructor called" << endl; } // Move constructor Number(Number&& obj) noexcept { ptr = obj.ptr; obj.ptr = nullptr; cout << "Move constructor called" << endl; } // Display function void display() const { if (ptr != nullptr) cout << "Value: " << *ptr << endl; else cout << "No resource owned" << endl; } // Destructor ~Number() { delete ptr; } }; int main() { Number obj1(100); cout << "\nOriginal object:" << endl; obj1.display(); Number obj2 = move(obj1); cout << "\nAfter moving:" << endl; cout << "Source object: "; obj1.display(); cout << "Destination object: "; obj2.display(); return 0; }

Expected Output

Constructor called

Original object:
Value: 100
Move constructor called

After moving:
Source object: No resource owned
Destination object: Value: 100

Explanation

  1. obj1 is created and allocates memory for an integer.
  2. std::move(obj1) converts the expression into an xvalue, allowing the move constructor to be selected.
  3. The move constructor transfers the pointer to obj2.
  4. obj1.ptr is set to nullptr.
  5. obj2 now owns the allocated memory.
  6. When the objects are destroyed, only obj2 releases that allocation.
std::move() does not move data by itself. It casts an expression to an rvalue-reference type so that a suitable move operation can be selected.

5. Understanding std::move()

std::move() is a utility function provided in the <utility> header.

It converts an expression into an xvalue, which can enable move construction or move assignment when the appropriate operation is available.

Syntax

std::move(object);

Example Using std::string

#include <iostream> #include <string> #include <utility> using namespace std; int main() { string str1 = "Embedded Systems"; string str2 = move(str1); cout << "Destination string: " << str2 << endl; cout << "Source string: " << str1 << endl; return 0; }

Possible Output

Destination string: Embedded Systems
Source string:

The source string's exact value after moving is unspecified. It is valid to use or assign a new value to it.

Do not assume that every moved-from object becomes empty. Its state is determined by the type's move-operation contract.

6. Copy Constructor vs Move Constructor

Copy Constructor Move Constructor
Creates a copy of the source object's data. Transfers resources from the source object.
Commonly accepts const ClassName&. Commonly accepts ClassName&&.
May allocate new memory and copy data. Can transfer ownership without copying the resource.
Source object remains unchanged. Source object remains valid but may be in a changed state.
Useful when an independent copy is required. Useful when resources can be transferred efficiently.

7. Lvalue and Rvalue References

Understanding lvalues and rvalues helps explain how move constructors work.

Lvalue

An lvalue is an expression that identifies an object with a persistent identity.

int x = 10; int& ref = x;

Rvalue

An rvalue is an expression that can be used as a temporary value, such as a literal or a temporary object.

int x = 10; int&& ref = 20;

Rvalue Reference

An rvalue reference is declared using two ampersands (&&). It allows functions and constructors to accept rvalues and implement move operations.

Remember: A named rvalue-reference variable is itself an lvalue expression when used by its name. This is why std::move() is often used when transferring its resources again.

8. Move Assignment Operator

A move constructor initializes a new object from another object. A move assignment operator transfers resources into an object that already exists.

Syntax

ClassName& operator=(ClassName&& obj) { // Release current resource // Transfer resource from obj // Return current object }

Example

#include <iostream> #include <utility> using namespace std; class Number { private: int *ptr; public: Number(int value) { ptr = new int(value); } // Move constructor Number(Number&& obj) noexcept { ptr = obj.ptr; obj.ptr = nullptr; } // Move assignment operator Number& operator=(Number&& obj) noexcept { if (this != &obj) { delete ptr; ptr = obj.ptr; obj.ptr = nullptr; } return *this; } void display() const { if (ptr != nullptr) cout << *ptr << endl; else cout << "No resource" << endl; } ~Number() { delete ptr; } }; int main() { Number obj1(100); Number obj2(200); obj2 = move(obj1); cout << "Source object: "; obj1.display(); cout << "Destination object: "; obj2.display(); return 0; }

Expected Output

Source object: No resource
Destination object: 100

Explanation

  • Both objects initially own separate dynamically allocated integers.
  • std::move(obj1) enables selection of the move assignment operator.
  • The destination object's existing resource is released.
  • The pointer from obj1 is transferred to obj2.
  • The source pointer is set to nullptr.

9. Rule of Five

When a class manually manages a resource, it may need to define five special member functions. This is commonly called the Rule of Five.

  1. Destructor: Releases the resource.
  2. Copy constructor: Creates an independent copy.
  3. Copy assignment operator: Copies into an existing object.
  4. Move constructor: Transfers resources into a new object.
  5. Move assignment operator: Transfers resources into an existing object.
The Rule of Five is especially relevant to classes that directly manage resources such as raw dynamically allocated memory. Using standard containers and smart pointers can often eliminate the need to write these functions manually.

10. noexcept in Move Constructors

The noexcept specifier indicates that a function is not expected to throw exceptions.

Move constructors are often declared noexcept when they can genuinely guarantee not to throw.

Number(Number&& obj) noexcept { ptr = obj.ptr; obj.ptr = nullptr; }

Some standard-library containers, including std::vector, can use move operations more effectively during reallocation when moving is known not to throw.

Do not add noexcept blindly. If a function declared noexcept allows an exception to escape, the program calls std::terminate().

11. Important Points to Remember

  • Move constructors were introduced in C++11.
  • A move constructor commonly accepts an rvalue reference.
  • It transfers resources rather than creating an independent copy.
  • std::move() is available through <utility>.
  • std::move() performs a cast; it does not itself transfer resources.
  • A moved-from object must remain valid according to its type's contract.
  • Move assignment is different from move construction.
  • noexcept can help containers choose move operations safely.
  • The Rule of Five covers the five special member functions for resource-managing classes.

12. Interview Questions

Q1. What is a move constructor?

A move constructor initializes a new object by transferring resources from another object, commonly an rvalue.

Q2. When was the move constructor introduced?

It was introduced in C++11.

Q3. What is the difference between copy and move constructors?

A copy constructor duplicates data, while a move constructor transfers resources from the source object.

Q4. What is std::move()?

It is a utility function that casts an expression to an rvalue-reference type, enabling move operations when available.

Q5. Does std::move() actually move an object?

No. It performs a cast. The selected move constructor or move assignment operator performs the resource transfer.

Q6. What is an rvalue reference?

It is a reference type declared using && that can bind to rvalues.

Q7. What happens to a moved-from object?

It remains valid, but its state may have changed. The exact state depends on the type's documented contract.

Q8. What is the difference between move constructor and move assignment?

A move constructor initializes a new object. Move assignment transfers resources into an already existing object.

Q9. What is the Rule of Five?

It identifies five special member functions that may need coordinated implementation in a resource-managing class.

Q10. Why is noexcept useful for move constructors?

It communicates that moving will not throw, which can help standard-library containers choose efficient move operations.
