1. Introduction to Shallow Copy

Shallow copy is a copying technique in which the values of an object's data members are copied directly into another object. When a data member is a pointer, only the pointer address is copied, not the dynamically allocated memory to which it points.

As a result, both objects may refer to the same memory location.

Definition: Shallow copy copies the member values of an object directly. For pointer members, it copies the address rather than creating a separate copy of the pointed-to resource.

2. Understanding Shallow Copy

Consider a class containing a pointer that stores the address of dynamically allocated memory.

class Sample { int *ptr; public: Sample(int value) { ptr = new int(value); } };

Suppose an object obj1 is copied into obj2 using the compiler-generated copy constructor.

The pointer value is copied. Both objects therefore point to the same dynamically allocated integer.

Conceptual Memory Representation

Before copying:

obj1.ptr ─────────► Memory location
                       Value: 100

After shallow copying:

obj1.ptr ─────┐
              ├──────► Same memory location
obj2.ptr ─────┘        Value: 100

The pointer members are different data members, but their stored addresses are identical.

3. Program: Demonstrating Shallow Copy

This program demonstrates how the compiler-generated copy constructor copies a pointer member.

#include <iostream> using namespace std; class Sample { public: int *ptr; Sample(int value) { ptr = new int(value); } }; int main() { Sample obj1(100); Sample obj2 = obj1; cout << "Original Object Value: " << *obj1.ptr << endl; cout << "Copied Object Value: " << *obj2.ptr << endl; cout << "Original Pointer Address: " << obj1.ptr << endl; cout << "Copied Pointer Address: " << obj2.ptr << endl; *obj2.ptr = 500; cout << endl; cout << "After modifying copied object:" << endl; cout << "Original Object Value: " << *obj1.ptr << endl; cout << "Copied Object Value: " << *obj2.ptr << endl; delete obj1.ptr; return 0; }

Expected Output

Original Object Value: 100
Copied Object Value: 100
Original Pointer Address: [same address]
Copied Pointer Address: [same address]

After modifying copied object:
Original Object Value: 500
Copied Object Value: 500

The actual memory address varies between program executions. Both printed addresses will be identical.

Explanation

  1. obj1 is created and allocates memory for an integer.
  2. obj2 = obj1 invokes the compiler-generated copy constructor.
  3. The pointer address is copied from obj1.ptr to obj2.ptr.
  4. Both pointers refer to the same integer.
  5. Changing the value through obj2.ptr also changes the value observed through obj1.ptr.
Important: This example deliberately uses a shallow copy to demonstrate shared memory. It releases the allocation only once. Do not add independent destructors that both delete the same pointer.

4. Shallow Copy Using a User-Defined Copy Constructor

A programmer can also explicitly implement shallow copying by copying the pointer address.

Program

#include <iostream> using namespace std; class Sample { public: int *ptr; Sample(int value) { ptr = new int(value); } Sample(const Sample &obj) { ptr = obj.ptr; } }; int main() { Sample obj1(100); Sample obj2(obj1); cout << "Original Value: " << *obj1.ptr << endl; cout << "Copied Value: " << *obj2.ptr << endl; cout << "Original Address: " << obj1.ptr << endl; cout << "Copied Address: " << obj2.ptr << endl; *obj2.ptr = 700; cout << "Modified Original Value: " << *obj1.ptr << endl; // Release the shared allocation exactly once. delete obj1.ptr; return 0; }

Expected Output

Original Value: 100
Copied Value: 100
Original Address: [same address]
Copied Address: [same address]
Modified Original Value: 700

Explanation

The statement ptr = obj.ptr; copies the address stored in the source object's pointer. It does not allocate new memory.

5. Problems Associated with Shallow Copy

Shallow copying can cause problems when objects manage dynamically allocated memory or other resources.

Problem 1: Shared Memory

Both objects point to the same memory. A modification through one object is visible through the other.

Problem 2: Double Deletion

If both objects have destructors that delete the same pointer, the same allocation may be released twice. This results in undefined behavior.

Problem 3: Dangling Pointer

If one object deletes the shared memory, the pointer in the other object becomes dangling. Accessing the released memory is invalid.

Remember: A shallow copy is not automatically incorrect. It becomes dangerous when multiple objects incorrectly assume independent ownership of the same resource.

6. Example of the Double Deletion Problem

The following code demonstrates a dangerous design. It is intentionally not a program to execute.

class Sample { public: int *ptr; Sample(int value) { ptr = new int(value); } ~Sample() { delete ptr; } }; int main() { Sample obj1(100); Sample obj2 = obj1; // Dangerous: // Both objects contain the same pointer. // Both destructors attempt to delete it. return 0; }
Warning: When obj2 and obj1 are destroyed, both destructors attempt to delete the same allocation. The second deletion is invalid and causes undefined behavior.

This is one of the main reasons programmers use deep copying or suitable resource-management techniques for classes that own dynamic memory.

7. Shallow Copy vs Deep Copy

Shallow Copy Deep Copy
Copies pointer addresses. Allocates separate memory and copies the pointed-to data.
Both objects may share the same resource. Each object can own an independent resource.
Changes through one pointer can affect the other object. Changes to one independent copy do not affect the other.
Can cause ownership and lifetime problems. Can provide independent ownership when implemented correctly.
Often occurs with compiler-generated copying of raw pointers. Usually requires custom copying logic or suitable resource-management types.

8. When Is Shallow Copy Suitable?

Shallow copying can be suitable when copying member values is the intended behavior and shared ownership is safe.

  • When a class contains only ordinary value-type members.
  • When pointer members are non-owning references to external resources.
  • When shared access to the same resource is intentional.
  • When resource lifetime is managed separately and safely.
Important: The correct copying strategy depends on ownership. A pointer does not necessarily mean that the object owns the memory it points to.

9. How to Avoid Shallow Copy Problems

  • Implement a proper deep-copy constructor when independent ownership is required.
  • Implement suitable copy assignment behavior for resource-owning classes.
  • Use smart pointers such as std::unique_ptr or std::shared_ptr according to ownership requirements.
  • Prefer standard containers such as std::vector over manually managed arrays when appropriate.
  • Follow the Rule of Three or Rule of Five when manually managing resources.
Note: std::unique_ptr prevents copying by default because it represents exclusive ownership. std::shared_ptr supports shared ownership through reference counting.

10. Important Rules of Shallow Copy

  • Shallow copy copies data members directly.
  • For pointer members, the address is copied.
  • The pointed-to memory is not duplicated automatically.
  • Two objects can refer to the same dynamically allocated memory.
  • Modifying shared data through one pointer affects what the other pointer observes.
  • Incorrect resource ownership can lead to double deletion and dangling pointers.
  • Shallow copying is not always wrong; its safety depends on resource ownership and lifetime.

11. Common Mistakes

Mistake Correct Understanding
Assuming pointer addresses are duplicated into separate memory. Shallow copy copies the address, not the allocated resource.
Deleting shared memory through both objects. Ensure the resource has a clear ownership strategy.
Using a pointer after another object has deleted its resource. Do not access memory after its lifetime has ended.
Assuming every shallow copy is unsafe. It can be appropriate when shared access is intentional and lifetime is managed correctly.

12. Interview Questions

Q1. What is shallow copy?

Shallow copy copies the values of data members directly. For pointer members, it copies the address rather than duplicating the pointed-to memory.

Q2. What happens when a pointer member is shallow-copied?

Both objects can contain the same pointer address and refer to the same resource.

Q3. What is the main problem with shallow copying?

Incorrect resource ownership can cause shared modification, dangling pointers, and double deletion.

Q4. Does the compiler-generated copy constructor perform shallow copying?

It performs memberwise copying. For raw pointer members, this copies the pointer value rather than the pointed-to data.

Q5. What is double deletion?

It occurs when the same dynamically allocated memory is released more than once.

Q6. What is the difference between shallow copy and deep copy?

Shallow copy copies pointer addresses, while deep copy creates separate resources and copies the required data.

Q7. How can shallow copy problems be avoided?

Use correct ownership rules, implement deep copying when needed, or use smart pointers and standard containers.

Q8. Is shallow copy always bad?

No. It is appropriate when sharing the same resource is intentional and its lifetime is managed safely.

  3. Modify a shared value through the copied object and display the value through the original object.
  4. Implement a user-defined copy constructor that explicitly copies a pointer address.
  5. Write a deep-copy constructor that allocates separate memory for the copied object.

14. Summary

  • Shallow copy copies data members directly.
  • Pointer members are copied as addresses.
  • Two objects can point to the same memory location.
  • Changes to shared data are visible through both pointers.
  • Incorrect ownership can cause double deletion and dangling pointers.
  • Deep copying or suitable resource-management techniques can provide safer independent ownership.
Remember: Shallow copy duplicates the pointer value, not the dynamically allocated memory. Understand ownership before copying resource-managing objects.
