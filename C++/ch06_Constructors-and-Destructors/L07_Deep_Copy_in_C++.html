1. Introduction to Deep Copy

A deep copy creates a separate copy of an object's dynamically allocated data instead of copying only the pointer that refers to that data.

Each object gets its own independent memory allocation. Therefore, modifying the copied object's data does not affect the original object's data.

Definition: Deep copy is the process of copying an object along with the dynamically allocated memory it owns, so that the original and copied objects have independent data.

Why is Deep Copy Needed?

  • To create independent copies of dynamically allocated data.
  • To prevent unintended sharing of memory between objects.
  • To avoid double deletion when objects own the same raw pointer.
  • To ensure changes in one object's data do not affect another.

2. Understanding Deep Copy

Consider a class containing a pointer to dynamically allocated memory. When an object is copied using a shallow copy, only the pointer address is copied. Both objects refer to the same memory.

In a deep copy, a new memory block is allocated and the value from the original memory block is copied into it.

Memory Concept

Original object:

Object A | |---- ptr ----> Memory Block 1 Value: 100

After deep copy:

Object A Object B | | |---- ptr ----> Block 1 |---- ptr ----> Block 2 Value: 100 Value: 100 Separate memory allocations
Both memory blocks initially contain the same value, but they occupy different memory locations. Updating one does not change the other.

3. Deep Copy Using a Copy Constructor

A copy constructor can implement deep copying by allocating new memory and copying the value stored in the original object's pointer.

Syntax

ClassName(const ClassName &obj) { // Allocate new memory // Copy the original object's data }

Example: Deep Copy Constructor

#include <iostream> using namespace std; class Number { private: int *ptr; public: // Parameterized constructor Number(int value) { ptr = new int(value); } // Deep copy constructor Number(const Number &obj) { ptr = new int(*obj.ptr); } // Display function void display() { cout << "Value: " << *ptr << endl; } // Modify stored value void setValue(int value) { *ptr = value; } // Destructor ~Number() { delete ptr; } }; int main() { Number obj1(100); Number obj2 = obj1; cout << "Original object:" << endl; obj1.display(); cout << "\nCopied object:" << endl; obj2.display(); obj2.setValue(200); cout << "\nAfter modifying copied object:" << endl; cout << "Original object: "; obj1.display(); cout << "Copied object: "; obj2.display(); return 0; }

Expected Output

Original object:
Value: 100

Copied object:
Value: 100

After modifying copied object:
Original object: Value: 100
Copied object: Value: 200

Explanation

  1. obj1 is created with the value 100.
  2. obj2 is initialized using the copy constructor.
  3. The copy constructor allocates a new integer using new int(*obj.ptr).
  4. The value 100 is copied into the newly allocated memory.
  5. Changing obj2 to 200 does not change obj1.
  6. Both objects independently release their memory through their destructors.
Important statement: ptr = new int(*obj.ptr); allocates a new integer and initializes it with the value pointed to by the source object's pointer.

4. Deep Copy with a User-Defined Class

Deep copying is especially useful when a class manages dynamically allocated resources such as arrays.

Example: Dynamically Allocated Array

#include <iostream> using namespace std; class Array { private: int *data; int size; public: // Constructor Array(int s) { size = s; data = new int[size]; for (int i = 0; i < size; i++) { data[i] = i + 1; } } // Deep copy constructor Array(const Array &obj) { size = obj.size; data = new int[size]; for (int i = 0; i < size; i++) { data[i] = obj.data[i]; } } // Display array void display() { for (int i = 0; i < size; i++) { cout << data[i] << " "; } cout << endl; } // Modify an element void setElement(int index, int value) { if (index >= 0 && index < size) { data[index] = value; } } // Destructor ~Array() { delete[] data; } }; int main() { Array arr1(3); Array arr2 = arr1; cout << "Original array: "; arr1.display(); cout << "Copied array: "; arr2.display(); arr2.setElement(0, 100); cout << "\nAfter modifying copied array:" << endl; cout << "Original array: "; arr1.display(); cout << "Copied array: "; arr2.display(); return 0; }

Expected Output

Original array: 1 2 3
Copied array: 1 2 3

After modifying copied array:
Original array: 1 2 3
Copied array: 100 2 3

Explanation

  • The constructor allocates an array of three integers.
  • The copy constructor allocates another array of the same size.
  • A loop copies each element into the new array.
  • Both objects have independent arrays.
  • The destructor uses delete[] to release each array.
Use delete[] for memory allocated using new[]. Use delete for memory allocated using a single-object new.

5. Deep Copy vs Shallow Copy

Shallow Copy Deep Copy
Copies pointer values or addresses. Allocates separate memory and copies the data.
Objects may refer to the same memory. Objects refer to independent memory.
Changes to shared data can affect both objects. Changes to one object's data do not affect the other.
Can cause ownership and lifetime problems with raw pointers. Can provide independent ownership when implemented correctly.
Usually requires less copying work. Requires additional memory allocation and data copying.
Remember: Shallow copy copies the pointer; deep copy creates a separate copy of the pointed-to data.

6. Problems Prevented by Deep Copy

1. Shared Memory Modification

With a shallow copy, two objects may point to the same memory. Changing the data through one object can affect the other object.

2. Double Deletion

If two objects both believe they own the same dynamically allocated memory, their destructors may attempt to release that memory twice.

3. Dangling Pointers

When shared memory is released by one object, another object's pointer may still refer to the released memory. Such a pointer is called a dangling pointer.

Deep copy helps prevent these problems by giving each object its own allocation. However, the copy constructor, assignment operator and destructor must all manage ownership correctly.

7. Deep Copy and the Rule of Three

When a class manually manages a resource using a raw pointer, implementing only a copy constructor may not be sufficient.

The Rule of Three states that if a class needs a user-defined destructor, copy constructor, or copy assignment operator, it will often need all three.

  1. Destructor: Releases the owned resource.
  2. Copy constructor: Creates an independent copy when a new object is initialized.
  3. Copy assignment operator: Handles copying into an already existing object.
A deep-copying copy constructor handles initialization such as Number obj2 = obj1;. Copy assignment is a separate operation and needs its own correct implementation.

8. Modern C++ Alternatives

Modern C++ provides resource-management tools that can reduce the need to write manual memory-management code.

Standard Containers

Containers such as std::vector manage their dynamically allocated storage automatically. Copying a vector creates an independent copy of its elements.

#include <iostream> #include <vector> using namespace std; int main() { vector<int> v1 = {10, 20, 30}; vector<int> v2 = v1; v2[0] = 100; cout << "Original: "; for (int x : v1) cout << x << " "; cout << "\nCopied: "; for (int x : v2) cout << x << " "; return 0; }

Expected Output

Original: 10 20 30
Copied: 100 20 30

Smart Pointers

  • std::unique_ptr provides exclusive ownership and is not copyable by default.
  • std::shared_ptr allows shared ownership through reference counting.
  • Use smart pointers when their ownership model matches the design of the program.
Prefer standard containers and smart pointers over manually managing raw dynamic memory in most modern C++ applications.

9. Important Points to Remember

  • Deep copy creates independent copies of dynamically allocated data.
  • A deep-copy constructor allocates new memory.
  • The original object's data is copied into the new allocation.
  • Modifying one object's copied data does not affect the other.
  • Use delete for single-object allocation and delete[] for array allocation.
  • A class managing raw resources may need the Rule of Three.
  • Modern C++ offers containers and smart pointers for safer resource management.

10. Interview Questions

Q1. What is deep copy?

Deep copy creates a separate memory allocation and copies the actual data into it.

Q2. Why is deep copy required?

It provides independent data ownership and prevents unintended sharing of dynamically allocated memory.

Q3. How is deep copy implemented?

By allocating new memory and copying the contents of the source object's memory into that allocation.

Q4. What is the difference between shallow copy and deep copy?

Shallow copy copies pointer values, whereas deep copy creates a separate allocation and copies the pointed-to data.

Q5. What is the Rule of Three?

It describes the need to consider a destructor, copy constructor and copy assignment operator together when a class manages a resource manually.

Q6. Does a deep-copy constructor automatically implement copy assignment?

No. Copy assignment is a separate operation and must be implemented separately when required.

Q7. Why is delete[] used in the array example?

Because the array was allocated using new[].
