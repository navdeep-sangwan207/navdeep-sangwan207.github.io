1. Introduction to Destructor

A destructor is a special member function of a class that is automatically called when an object is destroyed. It is commonly used to release resources acquired by the object, such as dynamically allocated memory.

Definition: A destructor is a special class member function that performs cleanup when an object reaches the end of its lifetime.

Why is a Destructor Needed?

  • To release dynamically allocated memory.
  • To close resources such as files when required.
  • To release other resources owned by an object.
  • To perform cleanup before an object is destroyed.

2. Syntax of Destructor

A destructor has the same name as its class, preceded by a tilde (~).

class ClassName { public: ~ClassName() { // Cleanup code } };

Important Characteristics

  • The destructor name is the class name preceded by ~.
  • It has no return type, not even void.
  • It takes no parameters.
  • A class can have only one destructor.
  • It cannot be overloaded.
  • It is normally called automatically when an object's lifetime ends.
A destructor cannot have parameters, so a class cannot define multiple destructors with different parameter lists.

3. Simple Destructor Example

#include <iostream> using namespace std; class Demo { public: Demo() { cout << "Constructor called" << endl; } ~Demo() { cout << "Destructor called" << endl; } }; int main() { Demo obj; cout << "Inside main function" << endl; return 0; }

Expected Output

Constructor called
Inside main function
Destructor called

Explanation

  1. When obj is created, the constructor is called.
  2. The program prints the message inside main().
  3. When main() ends, the local object reaches the end of its lifetime.
  4. The destructor is automatically called.

4. Destructor with Dynamic Memory

When a class allocates memory dynamically using new, its destructor can release that memory using delete.

Example

#include <iostream> using namespace std; class Number { private: int *ptr; public: Number(int value) { ptr = new int(value); cout << "Memory allocated" << endl; } void display() { cout << "Value: " << *ptr << endl; } ~Number() { delete ptr; cout << "Memory released" << endl; } }; int main() { Number obj(100); obj.display(); return 0; }

Expected Output

Memory allocated
Value: 100
Memory released

Explanation

  • The constructor allocates memory using new.
  • The pointer stores the address of the allocated integer.
  • The display() function displays the stored value.
  • When the object is destroyed, the destructor calls delete ptr.
  • The dynamically allocated memory is released.
Every dynamically allocated resource must have a clear ownership and cleanup strategy. Do not delete the same allocation more than once.

5. When is a Destructor Called?

A destructor is called when an object's lifetime ends. Common situations include:

1. Local Object

A local object is destroyed when execution leaves the block in which it was created.

void display() { Demo obj; cout << "Inside function" << endl; } // obj is destroyed here

2. Dynamically Created Object

An object created using new is destroyed when delete is applied to its pointer.

Demo *ptr = new Demo(); delete ptr; // Destructor is called

3. Program Scope

Objects with static storage duration are destroyed during program termination, subject to C++ static destruction rules.

4. Scope Exit

Objects inside nested blocks are destroyed when their respective blocks finish.

int main() { Demo obj1; { Demo obj2; } // obj2 is destroyed here // obj1 is still alive return 0; } // obj1 is destroyed here

6. Order of Constructor and Destructor Calls

For local automatic objects, constructors are called in the order objects are created. Destructors are called in the reverse order.

Example

#include <iostream> using namespace std; class Demo { private: int id; public: Demo(int n) { id = n; cout << "Constructor: " << id << endl; } ~Demo() { cout << "Destructor: " << id << endl; } }; int main() { Demo obj1(1); Demo obj2(2); Demo obj3(3); return 0; }

Expected Output

Constructor: 1
Constructor: 2
Constructor: 3
Destructor: 3
Destructor: 2
Destructor: 1
Remember: Construction follows creation order; destruction of local automatic objects follows reverse order.

7. Destructor and Array of Objects

When an array of objects is created, constructors are called for its elements in order. When the array is destroyed, destructors are called in reverse element order.

Example

#include <iostream> using namespace std; class Demo { private: int id; public: Demo(int n) { id = n; cout << "Constructor: " << id << endl; } ~Demo() { cout << "Destructor: " << id << endl; } }; int main() { Demo arr[3] = {Demo(1), Demo(2), Demo(3)}; return 0; }

Expected Output

Constructor: 1
Constructor: 2
Constructor: 3
Destructor: 3
Destructor: 2
Destructor: 1

8. Virtual Destructor

In inheritance, a base class destructor should generally be declared virtual when objects of derived classes may be deleted through base-class pointers.

This ensures that deleting an object through a base-class pointer invokes the derived-class destructor first, followed by the base-class destructor.

Example

#include <iostream> using namespace std; class Base { public: virtual ~Base() { cout << "Base destructor" << endl; } }; class Derived : public Base { public: ~Derived() { cout << "Derived destructor" << endl; } }; int main() { Base *ptr = new Derived(); delete ptr; return 0; }

Expected Output

Derived destructor
Base destructor
If an object of a derived class is deleted through a base pointer and the base class destructor is not virtual, the behavior is undefined. A virtual destructor is essential for this polymorphic deletion case.

9. Destructor vs Constructor

Constructor Destructor
Initializes an object. Performs cleanup when an object is destroyed.
Name is the class name. Name is the class name preceded by ~.
Can accept parameters. Cannot accept parameters.
Can be overloaded. Cannot be overloaded.
Has no return type. Has no return type.
Called when an object is initialized. Called when an object's lifetime ends.

10. Important Points to Remember

  • A destructor is a special member function.
  • Its name begins with a tilde (~).
  • It has no return type and no parameters.
  • A class has only one destructor.
  • It cannot be overloaded.
  • It is called automatically when an object's lifetime ends.
  • It is useful for releasing resources owned by an object.
  • Destructors of local objects execute in reverse construction order.
  • Base classes intended for polymorphic deletion should have virtual destructors.

11. Interview Questions

Q1. What is a destructor in C++?

A destructor is a special member function called when an object's lifetime ends. It performs cleanup.

Q2. What is the syntax of a destructor?

It uses the class name preceded by a tilde, for example ~Demo().

Q3. Can a destructor be overloaded?

No. A class can have only one destructor, and it cannot take parameters.

Q4. When is a destructor called?

It is called when an object's lifetime ends, such as when a local object leaves scope or a dynamically allocated object is deleted.

Q5. What is a virtual destructor?

A virtual destructor allows the correct derived-class destructor to be invoked when a derived object is deleted through a base-class pointer.

Q6. In which order are destructors called?

Local automatic objects are destroyed in reverse order of their construction.

Q7. Is a destructor called for an object created using new?

Yes. The destructor is called when the object is deleted using delete.
