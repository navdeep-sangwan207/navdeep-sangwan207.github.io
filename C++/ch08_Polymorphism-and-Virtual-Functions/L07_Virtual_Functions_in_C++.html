Virtual Functions in C++

Understanding Runtime Polymorphism and Dynamic Function Binding

Home C++ Course Chapter 8

After completing this lesson, you will be able to:

  • Understand virtual functions and their purpose.

  • Declare and override virtual functions.
  • Understand runtime polymorphism using base-class pointers.
  • Use the override specifier correctly.
  • Understand virtual destructors and their importance.

1. Introduction to Virtual Functions

A virtual function is a member function declared in a base class using the virtual keyword. It allows a derived class to provide its own implementation of that function.

When a virtual function is called through a base-class pointer or reference, C++ determines at runtime which function implementation should execute based on the actual object type.

Main concept: A virtual function enables runtime polymorphism, allowing one base-class interface to represent different derived-class behaviours.

Basic Syntax

class Base {
public:
    virtual void display() {
        // Base-class implementation
    }
};

class Derived : public Base {
public:
    void display() override {
        // Derived-class implementation
    }
};
  • virtual declares a virtual function in the base class.
  • override indicates that the derived function overrides a virtual base-class function.

2. Why Do We Need Virtual Functions?

Consider a base class named Animal and two derived classes named Dog and Cat.

Each animal produces a different sound. We want to call the same function through a base-class pointer and get the correct behaviour for the actual object.

Virtual functions make this possible.

class Animal {
public:
    virtual void sound() {
        cout << "Animal makes a sound";
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks";
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows";
    }
};
Without virtual dispatch, a call through a base-class pointer normally selects the base-class implementation. Declaring the base function virtual enables runtime selection of the derived implementation.

3. Static Binding vs Dynamic Binding

Binding means associating a function call with the function implementation that will execute.

Static Binding Dynamic Binding
Function call is resolved at compile time. Virtual function call is resolved at runtime.
Common with non-virtual functions. Used with virtual functions.
Selection depends on the declared type in the call. Selection depends on the actual object type.
Does not provide runtime polymorphism through a base pointer. Enables runtime polymorphism.
Remember: Dynamic binding is also called late binding, while static binding is also called early binding.

4. Program Without a Virtual Function

First, observe what happens when a base-class pointer points to a derived-class object but the base function is not virtual.

#include <iostream>
using namespace std;

class Base {
public:
    void display() {
        cout << "Base class display function" << endl;
    }
};

class Derived : public Base {
public:
    void display() {
        cout << "Derived class display function" << endl;
    }
};

int main() {
    Derived obj;

    Base *ptr = &obj;

    ptr->display();

    return 0;
}
Expected Output 
Base class display function

Explanation: The base-class function is called because display() is not virtual. The function call is resolved using the pointer's declared type, which is Base*.

5. Program Using a Virtual Function

Now declare the base-class function as virtual. The derived-class implementation will execute when the call is made through the base-class pointer.

#include <iostream>
using namespace std;

class Base {
public:
    virtual void display() {
        cout << "Base class display function" << endl;
    }
};

class Derived : public Base {
public:
    void display() override {
        cout << "Derived class display function" << endl;
    }
};

int main() {
    Derived obj;

    Base *ptr = &obj;

    ptr->display();

    return 0;
}
Expected Output 
Derived class display function

Explanation:

  1. Base declares display() as virtual.
  2. Derived overrides the function.
  3. A Base* pointer stores the address of a Derived object.
  4. The virtual call selects the derived implementation at runtime.

6. Runtime Polymorphism with Multiple Derived Classes

A single base-class pointer can refer to different derived-class objects at different times. The same virtual function call can therefore produce different results.

#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal makes a sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Dog dog;
    Cat cat;

    Animal *ptr;

    ptr = &dog;
    ptr->sound();

    ptr = &cat;
    ptr->sound();

    return 0;
}
Expected Output 
Dog barks
Cat meows
The pointer type remains Animal*, but the actual object changes. Runtime polymorphism selects the appropriate overridden function.

7. Virtual Functions and Base-Class References

Virtual functions also work when a derived object is accessed through a base-class reference.

#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() {
        cout << "Drawing a shape" << endl;
    }
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing a circle" << endl;
    }
};

void showShape(Shape &s) {
    s.draw();
}

int main() {
    Circle c;

    showShape(c);

    return 0;
}
Expected Output 
Drawing a circle

The reference parameter has type Shape&, but it refers to a Circle object. The virtual call executes Circle::draw().

8. The override Specifier

The override specifier is used in a derived class to explicitly indicate that a member function is intended to override a virtual function from the base class.

class Base {
public:
    virtual void display() {
        cout << "Base display";
    }
};

class Derived : public Base {
public:
    void display() override {
        cout << "Derived display";
    }
};

Advantages of override

  • Helps the compiler detect incorrect function signatures.
  • Makes the programmer's intention clear.
  • Improves code readability and maintenance.
  • Prevents accidental function hiding from being mistaken for overriding.
If the derived function does not correctly match a virtual function in the base class, using override causes a compile-time error.

9. Important Rules of Virtual Functions

  1. Virtual functions must be member functions of a class.
  2. They are declared using the virtual keyword in the base class.
  3. Constructors cannot be virtual.
  4. Destructors can be virtual.
  5. Static member functions cannot be virtual.
  6. Friend functions cannot be virtual because they are not member functions.
  7. Virtual functions are commonly called through base-class pointers or references.
  8. A derived-class override remains virtual even if the virtual keyword is not repeated.
  9. Private virtual functions can also be overridden in a derived class.

10. Virtual Destructors

A destructor is a special member function that runs when an object is destroyed. In a polymorphic base class, the destructor should generally be declared virtual.

This is especially important when a derived object may be deleted through a base-class pointer.

#include <iostream>
using namespace std;

class Base {
public:
    virtual ~Base() {
        cout << "Base destructor" << endl;
    }
};

class Derived : public Base {
public:
    ~Derived() override {
        cout << "Derived destructor" << endl;
    }
};

int main() {
    Base *ptr = new Derived();

    delete ptr;

    return 0;
}
Expected Output 
Derived destructor
Base destructor
Important: If an object of a derived class is deleted through a base-class pointer, the base-class destructor must be virtual for correct polymorphic destruction. Otherwise, the behaviour is undefined.

11. Virtual Function vs Pure Virtual Function

A normal virtual function can provide an implementation in the base class. A pure virtual function declares an interface that derived classes are expected to implement.

Virtual Function Pure Virtual Function
Declared using virtual. Declared using virtual and = 0.
Can have a base-class implementation. Declares a pure virtual interface.
Does not by itself make the class abstract. Makes the class abstract.
Derived classes may override it. Concrete derived classes must provide an override. 
// Virtual function
virtual void display() {
    cout << "Base display";
}

// Pure virtual function
virtual void display() = 0;
Pure virtual functions and abstract classes are covered in detail in the next lesson: Lesson 8.

12. Applications of Virtual Functions

  • Graphics applications: Different shapes can implement their own drawing functions.
  • Game development: Different characters can implement their own movement or attack behaviour.
  • Device drivers: Different device implementations can expose a common interface.
  • GUI frameworks: Different controls can implement their own rendering and event-handling behaviour.
  • Software architecture: Common interfaces can support interchangeable implementations.
Virtual functions help build extensible object-oriented software by separating a common interface from class-specific behaviour.

15. Short Answer Questions

Q1. What is a virtual function?

A virtual function is a base-class member function declared using the virtual keyword. It supports runtime polymorphism.

Q2. What is runtime polymorphism?

Runtime polymorphism allows a function call to execute different derived-class implementations depending on the actual object type.

Q3. What is dynamic binding?

Dynamic binding is the process of selecting the appropriate virtual function implementation at runtime.

Q4. Why is a virtual destructor important?

It ensures that the derived-class destructor is called when a derived object is deleted through a base-class pointer.

Q5. What is the purpose of override?

The override specifier tells the compiler that a derived member function is intended to override a virtual base-class function.

Q6. Can constructors be virtual?

No. Constructors cannot be virtual because an object must be constructed before its virtual behaviour can be used.

16. Lesson Summary

  • A virtual function is declared using the virtual keyword.
  • Virtual functions support runtime polymorphism.
  • Dynamic binding selects the appropriate overridden function at runtime.
  • Base-class pointers and references can access derived-class implementations.
  • The override specifier helps verify correct overriding.
  • Constructors cannot be virtual, but destructors can be virtual.
  • A polymorphic base class should generally have a virtual destructor.
  • Pure virtual functions are used to define abstract interfaces.
