Bank Management System Using C and File Handling

A menu-driven, file-based banking application demonstrating structures, functions, validation, searching, updating records and persistent data storage in C.

Home / Programming Projects / C Programming Projects / Bank Management System

1. Project Overview

The Bank Management System is a console-based application developed using the C programming language. It allows an operator to manage basic bank account records through a menu-driven interface.

The application stores account information in a binary file. Consequently, account records remain available after the program terminates and can be accessed during the next execution.

Project Type Console-based application
Programming Language C (C11 standard)
Core Concepts Structures, functions and file handling
Storage Binary file
Difficulty Intermediate
Project Focus Practical coding and placement preparation
Important: This is an educational project intended to demonstrate C programming concepts. It is not production banking software. It does not implement real banking security, authentication, encryption, audit controls or financial transaction guarantees.

2. Problem Statement

A small organization needs a basic system to maintain bank account information. Manual record management makes it difficult to search for accounts, update balances and maintain consistent records.

Develop a C application that provides account creation, account listing, account searching, deposit, withdrawal, balance enquiry and account closure. The application must store records in a file so that information is retained between program executions.

3. Project Objectives

  • Understand how structures represent real-world records.
  • Develop a menu-driven console application.
  • Divide a large program into reusable functions.
  • Store and retrieve structured records using file handling.
  • Search for records using an account number.
  • Update existing records without rewriting the entire file.
  • Apply validation to prevent invalid financial operations.
  • Understand persistent data storage and record management.

4. Functional Requirements

Operation Description

Display All Accounts Display all active account records stored in the file.

Account closure uses a status field instead of immediately deleting the record. This is a useful introduction to soft deletion and helps preserve the original record in this educational application.

7. Data Structure Design

Each bank account is represented by a structure containing four fields: 

typedef struct
{
    long long accountNumber;
    char name[50];
    double balance;
    int active;
} Account;
Member Data Type Purpose
accountNumber long long Unique account identifier.
name char array Customer name.
balance double Account balance for this learning exercise.
active int 1 means active; 0 means closed.
Real financial software should use carefully designed monetary representations, such as integer minor currency units, rather than relying on floating-point arithmetic. The double field here keeps the introductory project focused on C structures and file handling.

/* Read a complete line safely */
static int readLine(const char *prompt, char *buffer, size_t size)
{
    size_t length;
    int ch;

    printf("%s", prompt);

    if (fgets(buffer, (int)size, stdin) == NULL)
    {
        return 0;
    }

    length = strlen(buffer);

    if (length > 0 && buffer[length - 1] == '\n')
    {
        buffer[length - 1] = '\0';
    }
    else
    {
        while ((ch = getchar()) != '\n' && ch != EOF)
        {
            /* Discard excess input */
        }
    }

    return 1;
}

/* Read an integer without accepting trailing characters */
static int readInteger(const char *prompt, int *value)
{
    char input[100];
    char *end;
    long result;

    if (!readLine(prompt, input, sizeof(input)))
    {
        return 0;
    }

    errno = 0;
    result = strtol(input, &end, 10);

    while (isspace((unsigned char)*end))
    {
        end++;
    }

    if (input == end || *end != '\0' ||
        errno == ERANGE || result < INT_MIN || result > INT_MAX)
    {
        printf("Invalid integer input.\n");
        return -1;
    }

    *value = (int)result;
    return 1;
}

/* Read and validate account number */
static int readAccountNumber(long long *number)
{
    char input[100];
    char *end;
    long long result;

    if (!readLine("Enter account number: ", input, sizeof(input)))
    {
        return 0;
    }

    errno = 0;
    result = strtoll(input, &end, 10);

    while (isspace((unsigned char)*end))
    {
        end++;
    }

    if (input == end || *end != '\0' ||
        errno == ERANGE || result <= 0)
    {
        printf("Invalid account number.\n");
        return -1;
    }

    *number = result;
    return 1;
}

/* Read and validate a positive transaction amount */
static int readAmount(const char *prompt, double *amount)
{
    char input[100];
    char *end;
    double result;

    if (!readLine(prompt, input, sizeof(input)))
    {
        return 0;
    }

    errno = 0;
    result = strtod(input, &end);

    while (isspace((unsigned char)*end))
    {
        end++;
    }

    if (input == end || *end != '\0' ||
        errno == ERANGE || !isfinite(result) || result <= 0)
    {
        printf("Enter a valid positive amount.\n");
        return -1;
    }

    *amount = result;
    return 1;
}

/* Search for an account and return its file position */
static int findAccount(FILE *fp, long long number,
                       Account *account, long *position)
{
    Account current;
    long currentPosition;

    if (fseek(fp, 0L, SEEK_SET) != 0)
    {
        return -1;
    }

    while ((currentPosition = ftell(fp)) >= 0 &&
           fread(¤t, sizeof(Account), 1, fp) == 1)
    {
        if (current.accountNumber == number && current.active == 1)
        {
            *account = current;
            *position = currentPosition;
            return 1;
        }
    }

    if (ferror(fp))
    {
        return -1;
    }

    return 0;
}

/* Display one account */
static void displayAccount(const Account *account)
{
    printf("\nAccount Number : %lld\n", account->accountNumber);
    printf("Customer Name  : %s\n", account->name);
    printf("Balance        : %.2f\n", account->balance);

/* Create a new account */
static void createAccount(void)
{
    FILE *fp;
    Account account;
    Account existing;
    long position;
    int result;
    size_t nameLength;

    printf("\n========== CREATE ACCOUNT ==========\n");

    result = readAccountNumber(&account.accountNumber);
    if (result != 1)
    {
        return;
    }

    fp = fopen(DATA_FILE, "rb+");

    if (fp == NULL)
    {
        fp = fopen(DATA_FILE, "wb+");
    }

    if (fp == NULL)
    {
        perror("Unable to open account file");
        return;
    }

    result = findAccount(fp, account.accountNumber,
                         &existing, &position);

    if (result == -1)
    {
        printf("Error while searching account records.\n");
        fclose(fp);
        return;
    }

    if (result == 1)
    {
        printf("An active account with this number already exists.\n");
        fclose(fp);
        return;
    }

    if (!readLine("Enter customer name: ",
                  account.name, sizeof(account.name)))
    {
        fclose(fp);
        return;
    }

    nameLength = strlen(account.name);

    if (nameLength == 0)
    {
        printf("Customer name cannot be empty.\n");
        fclose(fp);
        return;
    }

    result = readAmount("Enter opening balance: ", &account.balance);

    if (result != 1)
    {
        fclose(fp);
        return;
    }

    account.active = 1;

    if (fseek(fp, 0L, SEEK_END) != 0 ||
        fwrite(&account, sizeof(Account), 1, fp) != 1)
    {
        printf("Unable to save account record.\n");
        fclose(fp);
        return;
    }

    if (fclose(fp) != 0)
    {
        printf("Warning: error while closing the account file.\n");
        return;
    }

    printf("\nAccount created successfully.\n");
    displayAccount(&account);
}

/* Display all active accounts */
static void displayAllAccounts(void)
{
    FILE *fp;
    Account account;
    int count = 0;

    printf("\n========== ALL ACTIVE ACCOUNTS ==========\n");

    fp = fopen(DATA_FILE, "rb");

    if (fp == NULL)
    {
        if (errno == ENOENT)
        {
            printf("No account records found.\n");
        }
        else
        {
            perror("Unable to open account file");
        }
        return;
    }

    while (fread(&account, sizeof(Account), 1, fp) == 1)
    {
        if (account.active == 1)
        {
            displayAccount(&account);
            printf("----------------------------------\n");
            count++;
        }
    }

    if (ferror(fp))
    {
        printf("Error while reading account records.\n");
    }
    else if (count == 0)
    {
        printf("No active accounts available.\n");
    }

    printf("Total active accounts: %d\n", count);
    fclose(fp);
}

/* Search for an account */
static void searchAccount(void)
{
    FILE *fp;
    Account account;
    long position;
    long long number;
    int result;

    printf("\n========== SEARCH ACCOUNT ==========\n");

    result = readAccountNumber(&number);
    if (result != 1)
    {
        return;
    }

    fp = fopen(DATA_FILE, "rb");

    if (fp == NULL)
    {
        printf("Account data file is not available.\n");
        return;

    result = findAccount(fp, number, &account, &position);

    if (result == 1)
    {
        printf("\nAccount found.\n");

    else if (result == 0)
    {
        printf("Account not found.\n");
    }
    else
    {
        printf("Error while reading account records.\n");
    }

    fclose(fp);
}

/* Deposit money */
static void depositMoney(void)
{
    FILE *fp;
    Account account;
    long position;
    long long number;
    double amount;
    int result;

    printf("\n========== DEPOSIT MONEY ==========\n");

    result = readAccountNumber(&number);
    if (result != 1)
    {
        return;
    }

    result = readAmount("Enter deposit amount: ", &amount);
    if (result != 1)
    {
        return;
    }

    fp = fopen(DATA_FILE, "rb+");

    if (fp == NULL)
    {
        printf("Account data file is not available.\n");
        return;
    }

    result = findAccount(fp, number, &account, &position);

    if (result != 1)
    {
        printf(result == 0 ? "Account not found.\n"
                           : "Error reading account file.\n");
        fclose(fp);
        return;
    }

    if (!isfinite(account.balance + amount))
    {
        printf("Transaction amount exceeds supported range.\n");
        fclose(fp);
        return;
    }

    account.balance += amount;

    if (fseek(fp, position, SEEK_SET) != 0 ||
        fwrite(&account, sizeof(Account), 1, fp) != 1 ||
        fflush(fp) != 0)
    {
        printf("Unable to update account balance.\n");
        fclose(fp);
        return;
    }

    fclose(fp);

    printf("Deposit successful.\n");
    printf("Updated balance: %.2f\n", account.balance);
}

static void withdrawMoney(void)
{

    long position;

    int result;

    printf("\n========== WITHDRAW MONEY ==========\n");

    result = readAccountNumber(&number);
    if (result != 1)
    {
        return;
    }

    result = readAmount("Enter withdrawal amount: ", &amount);
    if (result != 1)
    {
        return;
    }

    fp = fopen(DATA_FILE, "rb+");

    if (fp == NULL)
    {
        printf("Account data file is not available.\n");
        return;

    result = findAccount(fp, number, &account, &position);

    if (result != 1)
    {
        printf(result == 0 ? "Account not found.\n"

    if (amount > account.balance)
    {
        printf("Insufficient balance. Withdrawal denied.\n");

    if (fseek(fp, position, SEEK_SET) != 0 ||
        fwrite(&account, sizeof(Account), 1, fp) != 1 ||
        fflush(fp) != 0)
    {
        printf("Unable to update account balance.\n");
        fclose(fp);
        return;
    }

    fclose(fp);

    printf("Withdrawal successful.\n");
    printf("Remaining balance: %.2f\n", account.balance);
}

10. File Handling Explained

The project uses binary file operations to store complete structure records.

Function / Mode Purpose
fopen() Open a file in the requested mode.
fread() Read account records from the binary file.
fwrite() Write account records to the binary file.
fseek() Move the file position to a particular record.
ftell() Obtain the current file position.
fflush() Request that buffered output be written to the file.
fclose() Close the file after an operation.

Important File Modes

Mode Meaning
rb Open an existing binary file for reading.
wb Open a binary file for writing; existing contents are truncated.
ab Open a binary file for appending.
rb+ Open an existing binary file for both reading and writing.
wb+ Create or truncate a binary file for reading and writing.

How Random Record Updating Works

1. Open bank.dat using rb+.
2. Read account records using fread().
3. Find the matching account number.
4. Save its file position using ftell().
5. Modify the structure in memory.
6. Move back to the saved position using fseek().
7. Write the updated structure using fwrite().
8. Close the file.

This avoids rewriting every account record when a single account balance or customer name changes.

Binary structure files are generally compiler- and platform-dependent because structure padding, alignment and data representation can vary. This project assumes the same program layout is used when writing and reading the records. A portable application would use an explicitly defined serialization format.

15. Complexity Analysis

This implementation uses a sequential search through fixed-size records.

Operation Time Complexity Reason
Create Account O(n) Checks existing records before appending.
Search Account O(n) May examine every record.
Display All Accounts O(n) Traverses all records.
Deposit O(n) Searches for the account before updating it.
Withdraw O(n) Searches for the account before updating it.
Balance Enquiry O(n) Uses sequential account search.

Here, n represents the number of account records. A more advanced version could introduce indexing or a database to improve record lookup and data management.

16. Placement Interview Questions and Answers

Q1. Why are structures used in this project?

A structure groups related data members of different types into one logical record. Here it stores the account number, customer name, balance and account status together.

Q2. Why is binary file handling used?

Binary file handling allows the program to read and write structure records directly using fread() and fwrite(). It avoids manually parsing each individual field from a text file.

Q3. What is the difference between rb and rb+?

rb opens an existing binary file for reading. rb+ opens an existing binary file for both reading and writing without truncating its contents.

Q4. Why is fseek() used?

It moves the file position indicator to a specified location. This allows the application to update a particular record without rewriting all records.

Q5. What is the purpose of ftell()?

It returns the current file position. The program uses it to remember where a matching account record begins.

Q6. Why is a unique account number necessary?

It identifies each account independently and prevents transactions from being applied to the wrong customer.

Q7. How does the program prevent overdrawing?

Before withdrawal, it compares the requested amount with the available balance. If the requested amount is greater, the operation is rejected.

Q8. What is persistent storage?

Persistent storage means data remains available after a program terminates. The application achieves this by saving account records in bank.dat.

Q9. What is the difference between fread() and fwrite()?

fread() reads data from a file into memory, whereas fwrite() writes data from memory into a file.

Q10. Why should fclose() be called?

It closes the file, releases associated resources and completes normal buffered file output.

Q11. What is soft deletion?

Soft deletion marks a record as inactive instead of physically removing it. This project uses the active member for that purpose.

Q12. What are the limitations of this project?

It uses sequential search, a local binary file and a single-user execution model. It does not implement authentication, encryption, concurrency control, transaction recovery or production-grade financial security.

  2. Account Types: Introduce savings and current account categories.
  3. Sorting: Display account records sorted by account number or name.
  4. Search Optimization: Implement an index or a suitable data structure for faster lookup.
  5. Modular Programming: Separate declarations, functions and the main program into multiple source and header files.
  6. Input and Error Handling: Improve recovery from file errors, corrupted records and unexpected input.
  7. Database Integration: Replace the binary file with SQLite or another database.
  8. Authentication: Add an educational login workflow. A real implementation would require secure password hashing, access controls and a proper security design.
