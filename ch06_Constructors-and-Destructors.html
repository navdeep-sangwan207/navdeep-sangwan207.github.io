6.1 Introduction

A constructor initializes an object when it is created. A destructor performs cleanup when an object's lifetime ends.

  • A constructor has the same name as its class.
  • A constructor has no return type.
  • A destructor uses the class name preceded by ~.
  • A destructor has no parameters and cannot be overloaded.
  • Constructors can be overloaded.

6.2 Default Constructor

A default constructor is a constructor that can be called without supplying arguments. If no constructors are declared, the compiler can implicitly declare a default constructor.

Program 1: Default Constructor

#include <iostream>
using namespace std;

class Student
{
public:
    Student()
    {
        cout << "Default constructor called" << endl;
    }
};

int main()
{
    Student s1;
    return 0;
}

Expected Output

Default constructor called

6.3 Parameterized Constructor

A parameterized constructor accepts arguments to initialize an object.

Program 2: Initialize Object Data

#include <iostream>
#include <string>
using namespace std;

class Student
{
private:
    string name;
    int age;

public:
    Student(string n, int a)
        : name(n), age(a)
    {
    }

    void display() const
    {
        cout << "Name: " << name << endl;
        cout << "Age: " << age << endl;
    }
};

int main()
{
    Student s1("Rahul", 22);
    s1.display();

    return 0;
}

Expected Output

Name: Rahul
Age: 22

The initializer list : name(n), age(a) initializes the data members before the constructor body executes.

6.4 Constructor Overloading

A class can have multiple constructors with different parameter lists.

Program 3: Overloaded Constructors

#include <iostream>
using namespace std;

class Rectangle
{
private:
    int length;
    int width;

public:
    Rectangle() : length(1), width(1) {}

    Rectangle(int l, int w) : length(l), width(w) {}

    int area() const
    {
        return length * width;
    }
};

int main()
{
    Rectangle r1;
    Rectangle r2(5, 4);

    cout << "Default area: " << r1.area() << endl;
    cout << "Parameterized area: " << r2.area() << endl;

    return 0;
}

Expected Output

Default area: 1
Parameterized area: 20

6.5 Copy Constructor

A copy constructor initializes a new object from an existing object of the same class.

Program 4: Copy Constructor

#include <iostream>
using namespace std;

class Number
{
private:
    int value;

public:
    Number(int v) : value(v) {}

    Number(const Number& other)
        : value(other.value)
    {
        cout << "Copy constructor called" << endl;
    }

    void display() const
    {
        cout << "Value: " << value << endl;
    }
};

int main()
{
    Number n1(100);
    Number n2(n1);

    n2.display();
    return 0;
}

Expected Output

Copy constructor called
Value: 100

Important: The parameter is a const reference to avoid copying the source object again. A compiler-generated copy constructor copies members individually; for raw pointers, this copies the address, not the dynamically allocated data.

6.6 Member Initializer Lists

Initializer lists initialize data members before the constructor body. They are required for reference members and const data members, and for directly initializing members that have no default constructor.

#include <iostream>
using namespace std;

class Sensor
{
private:
    const int sensorId;
    int pin;

public:
    Sensor(int id, int p)
        : sensorId(id), pin(p)
    {
    }

    void display() const
    {
        cout << "Sensor ID: " << sensorId << endl;
        cout << "Pin: " << pin << endl;
    }
};

int main()
{
    Sensor s1(101, 5);
    s1.display();

    return 0;
}

Expected Output

Sensor ID: 101
Pin: 5

6.7 Destructor

A destructor runs when an object's lifetime ends. It is commonly used to release resources owned by an object.

Program 5: Destructor Execution

#include <iostream>
using namespace std;

class Demo
{
public:
    Demo()
    {
        cout << "Constructor called" << endl;
    }

    ~Demo()
    {
        cout << "Destructor called" << endl;
    }
};

int main()
{
    Demo d1;
    cout << "Inside main" << endl;

    return 0;
}

Expected Output

Constructor called
Inside main
Destructor called

For this local object, the destructor runs when execution leaves main() and the object's lifetime ends.

6.8 Order of Constructors and Destructors

Local objects in the same scope are destroyed in reverse order of their completed construction.

#include <iostream>
using namespace std;

class Demo
{
private:
    int id;

public:
    Demo(int n) : id(n)
    {
        cout << "Construct " << id << endl;
    }

    ~Demo()
    {
        cout << "Destroy " << id << endl;
    }
};

int main()
{
    Demo a(1);
    Demo b(2);

    return 0;
}

Expected Output

Construct 1
Construct 2
Destroy 2
Destroy 1

6.9 Dynamic Resources and Destructors

Manually managing dynamic memory requires care. A destructor may release owned resources, but copying an object that owns a raw pointer can cause double deletion unless copying is correctly implemented.

Modern C++ usually favors resource-managing standard types such as std::vector and std::unique_ptr instead of manually owning memory through raw pointers.

#include <iostream>
#include <memory>
using namespace std;

class Buffer
{
private:
    unique_ptr<int[]> data;

public:
    Buffer(int size)
        : data(make_unique<int[]>(size))
    {
        cout << "Buffer allocated" << endl;
    }
};

int main()
{
    Buffer b(10);
    cout << "Buffer in use" << endl;

    return 0;
}

Expected Output

Buffer allocated
Buffer in use

The unique_ptr automatically releases its array when the owning object is destroyed. No custom destructor is required here.

6.10 Constructor vs Destructor

  • A constructor initializes an object; a destructor cleans up resources as the object's lifetime ends.
  • A constructor can accept parameters; a destructor cannot.
  • Constructors can be overloaded; a class has only one destructor.
  • Constructors have no return type; destructors have no return type.
  • Construction proceeds from base classes to derived classes; destruction proceeds in the reverse order.

6.11 Common Mistakes

  • Giving a constructor a return type.
  • Trying to overload a destructor.
  • Using assignment in the constructor body when an initializer list is required.
  • Shallow-copying a raw owning pointer.
  • Releasing the same resource twice.
  • Forgetting that member initialization order follows the order of declaration in the class, not the initializer list.
