Lesson 06: Process vs Thread

Lesson Overview

Processes and threads are two important execution models used by operating systems. A process provides an independent execution environment, while threads provide multiple execution paths within a process. This lesson compares their memory organization, resource sharing, communication, performance and practical applications.

Learning Objectives:

  • Understand process and thread architecture.
  • Compare memory and resource management.
  • Understand inter-process and inter-thread communication.
  • Compare process and thread context switching.
  • Understand concurrency and parallelism.
  • Identify when to use processes or threads.
  • Relate threads to RTOS tasks.

1. Introduction

An operating system manages multiple executing programs. It uses processes and threads to organize application execution and allocate processor resources.

A process is an executing instance of a program. A thread is an execution unit within a process.

Simple example

Consider a web browser. The browser may use multiple processes to isolate different components and multiple threads to handle activities such as user-interface updates, network operations and background processing.

A process is primarily a resource-ownership and protection container. A thread is an independently schedulable execution flow within that process.

2. Process Architecture

A process has its own execution environment and resources managed by the operating system. In a protected operating system, different processes normally have separate virtual address spaces.

Typical process components

  • Program code (text section).
  • Initialized data section.
  • Uninitialized data section (BSS).
  • Heap for dynamic memory allocation.
  • One or more thread stacks.
  • Process identification and scheduling information.
  • Open file descriptors and other resources.

A process may contain multiple threads. Each thread has its own execution context and stack, while the process provides shared resources and an address space.

3. Thread Architecture

A thread is an execution unit that runs within a process. Threads belonging to the same process share many resources but maintain separate execution contexts.

Thread-specific information

  • Thread ID.
  • Program counter.
  • CPU registers.
  • Stack pointer and stack.
  • Thread scheduling information.
  • Thread-local storage, where supported.

Shared process resources

  • Executable code.
  • Global and static data.
  • Heap memory.
  • Open file descriptors.
  • Other process-level resources.

Threads share the process address space, but each thread has its own stack and register context. Thread-local storage can provide additional data that is private to an individual thread.

6. Communication: IPC vs Shared Memory

Processes and threads need communication mechanisms to exchange data and coordinate activities.

Inter-Process Communication (IPC)

IPC refers to mechanisms that allow separate processes to exchange information or coordinate their execution.

IPC Mechanism Description
Pipes Provide a data stream between processes.
Named Pipes Allow communication through a named communication endpoint.
Message Queues Exchange structured messages.
Shared Memory Allows processes to access a common memory region.
Signals Notify a process that an event has occurred.
Sockets Support communication between local or remote processes.

Thread communication

Threads in the same process can communicate through shared variables, common data structures and synchronization mechanisms.

  • Shared variables.
  • Mutexes.
  • Condition variables.
  • Semaphores.
  • Thread-safe queues.
Shared memory does not automatically guarantee safe communication. Synchronization is required when multiple execution flows access shared data concurrently.

7. Context Switching: Process vs Thread

Context switching allows the operating system to stop one execution flow and resume another.

Process context switch

A switch between threads belonging to different processes may require changing address-space information, memory mappings and other process-specific state in addition to saving and restoring CPU context.

Thread context switch

A switch between threads in the same process generally involves saving one thread's execution context and restoring another's. The address space may remain unchanged.

Operation Typical Work
Switch between threads of same process Save and restore thread execution context.
Switch between processes Save and restore thread context and potentially change address-space state.
Thread switching is often less expensive than switching between different processes, but this is not an absolute rule. Actual overhead depends on the operating system, processor architecture, memory-management hardware and implementation.

8. Concurrency and Parallelism

Concurrency

Concurrency means that multiple execution flows make progress during overlapping periods. A single CPU core can support concurrency by switching between tasks.

Parallelism

Parallelism means that multiple execution flows execute simultaneously on different processing units or CPU cores.

Concurrency Parallelism
Multiple tasks make progress over overlapping periods. Multiple tasks execute at the same instant.
Can occur on a single CPU core. Requires multiple execution resources.
Can use time-slicing and scheduling. Uses multiple cores or processors.

Single-core example

A multithreaded application does not automatically execute in parallel. Parallel execution depends on available processor resources and operating-system scheduling.

9. Advantages and Disadvantages

Processes

Advantages:

  • Strong isolation between independent applications.
  • Separate address spaces improve fault containment.
  • Independent resource and security management.
  • Suitable for applications requiring separation.

Disadvantages:

  • Process creation can require more resources.
  • IPC may introduce additional overhead.
  • Switching between processes can involve address-space changes.

Threads

Advantages:

  • Efficient sharing of process resources.
  • Generally lower creation overhead.
  • Useful for responsive applications.
  • Can support multicore parallelism.

Disadvantages:

  • Shared memory requires synchronization.
  • Race conditions and deadlocks can occur.
  • A thread error may affect the entire process.
  • Concurrent programs can be difficult to debug.

10. When Should We Use Processes or Threads?

Requirement Suitable Approach Reason
Strong application isolation Separate processes Independent address spaces improve protection.
Multiple activities sharing data Threads Threads share the process address space.
Independent services Separate processes Services can be managed and restarted independently.
Background work within one application Threads Multiple execution flows can share application resources.
Fault containment Separate processes Failures are often better isolated.
Shared-memory computation Threads Shared data can be accessed directly with synchronization.

The best design depends on application requirements, security, performance, reliability and communication needs.

11. Practical Linux Example: Process Information

Linux provides commands to inspect running processes and their identifiers.

Commands

ps -ef
ps -eLf
top
pstree
Command Purpose
ps -ef Displays process information in full format.
ps -eLf Displays processes and thread-related information in Linux.
top Displays dynamic process information.
pstree Displays process relationships as a tree.

Important identifiers

  • PID: Process ID.
  • PPID: Parent Process ID.
  • TID: Thread ID in Linux terminology.

In Linux, threads are represented by schedulable tasks and have task identifiers. Threads in the same thread group share the process ID reported as the thread-group ID.

12. Practical C Example: Creating a Process

The following Linux C program uses fork() to create a child process.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid = fork();

    if (pid < 0)
    {
        perror("fork failed");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child Process\n");
        printf("Child PID: %d\n", getpid());
    }
    else
    {
        printf("Parent Process\n");
        printf("Parent PID: %d\n", getpid());

        wait(NULL);
    }

    return 0;
}

Compilation and execution

gcc process_demo.c -o process_demo
./process_demo

Expected result

Parent Process
Parent PID: 2500
Child Process
Child PID: 2501

The PID values and the order of printed lines can vary. The parent waits for the child to finish before exiting.

13. Practical C Example: Creating Threads

POSIX threads (pthreads) allow a Linux program to create multiple threads within one process.

Program

#include <stdio.h>
#include <pthread.h>

void *task(void *arg)
{
    int number = *(int *)arg;

    printf("Thread %d is executing\n", number);

    return NULL;
}

int main(void)
{
    pthread_t thread1;
    pthread_t thread2;

    int a = 1;
    int b = 2;

    pthread_create(&thread1, NULL, task, &a);
    pthread_create(&thread2, NULL, task, &b);

    pthread_join(thread1, NULL);
    pthread_join(thread2, NULL);

    printf("Main thread completed\n");

    return 0;
}

Compilation and execution

gcc thread_demo.c -o thread_demo -pthread
./thread_demo

Possible output

Thread 1 is executing
Thread 2 is executing
Main thread completed

The order of thread messages may vary because the operating system scheduler determines when each thread executes. The pthread_join() calls ensure the main thread waits for both worker threads to complete.

14. Relationship Between Threads and RTOS Tasks

In an RTOS, a task is an independently schedulable unit of execution. Its behavior is similar to a thread in a general-purpose operating system, although the underlying implementation differs.

General-Purpose OS RTOS
Thread Task
Thread stack Task stack
Thread priority Task priority
Thread scheduling Task scheduling
Thread context Task context

Example: FreeRTOS task design

Task 1: Sensor Monitoring
Task 2: UART Communication
Task 3: LCD Display
Task 4: Control Logic

The FreeRTOS scheduler selects which ready task executes according to the configured scheduling policy and task priorities.

FreeRTOS tasks are not necessarily equivalent to processes. In a typical microcontroller FreeRTOS application, tasks share one address space and execute within the same firmware image. MPU-enabled configurations can provide additional protection.

15. Lesson Summary

  • A process is an executing instance of a program.
  • A thread is an execution unit within a process.
  • Processes generally have separate protected address spaces.
  • Threads share many resources of their parent process.
  • Every thread maintains its own execution context and stack.
  • Processes commonly communicate using IPC mechanisms.
  • Threads can communicate through shared memory and synchronization.
  • Thread switching within a process may avoid some address-space changes.
  • Concurrency and parallelism are related but different concepts.
  • RTOS tasks are independently schedulable execution units.
