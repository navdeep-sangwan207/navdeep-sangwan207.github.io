2. Introduction to Multitasking

Multitasking is the ability of an operating system to manage multiple tasks or processes so that they make progress during overlapping periods of time.

A task may represent a running application, a background service, or a thread performing a particular operation.

Example

Consider a computer performing these activities:

  • Playing music.
  • Downloading a file.
  • Running a web browser.
  • Scanning files using antivirus software.

The operating system schedules CPU time among these activities so that the computer remains responsive.

Important: Multitasking does not necessarily mean that multiple tasks execute at exactly the same instant. On a single-core processor, tasks generally take turns using the CPU.

3. Why Is Multitasking Required?

Without multitasking, a program might occupy the processor while waiting for an input/output operation to complete. Other programs could remain unable to use the CPU during that time.

Multitasking improves system operation by allowing the processor to work on another ready task while one task is waiting.

Main benefits

  • Better CPU utilization: The processor can execute another task while a task waits for I/O.
  • Responsiveness: Interactive applications can receive CPU time without waiting for unrelated work to finish.
  • Resource sharing: Multiple tasks can use system resources under operating-system control.
  • Background processing: Services can operate while the user performs other activities.
  • Improved throughput: More work can be completed over a given period when scheduling and resource use are effective.

4. Time-Sharing in Multitasking

Time-sharing is a technique in which the operating system allocates CPU time to tasks in small intervals called time slices or time quanta.

On a single-core processor, the CPU may execute Task A for a short interval, then Task B, followed by Task C. This switching can happen quickly enough to give the impression that all tasks are running simultaneously.

Example of time-sharing

Time interval Task using CPU
0–10 msTask A
10–20 msTask B
20–30 msTask C
30–40 msTask A
40–50 msTask B

This is a simplified illustration. Actual scheduling depends on task priority, blocking, interrupts, and the operating-system scheduling policy.

Time slice

A time slice is the maximum CPU interval assigned to a task before the scheduler may select another eligible task. The timer interrupt can help the operating system regain control when a time slice expires.

5. Task States During Multitasking

Tasks commonly move between three important scheduling states:

State Description
Ready The task can execute but is waiting for CPU allocation.
Running The task is currently executing on a CPU core.
Blocked / Waiting The task is waiting for an event, resource, or I/O operation.

A running task may become blocked when it requests data from a device. The scheduler can then select another ready task.

When the required event occurs, the blocked task may return to the ready state.

6. Cooperative and Preemptive Multitasking

6.1 Cooperative Multitasking

In cooperative multitasking, a running task voluntarily gives up control so another task can execute.

A task may yield the CPU or wait for an event. If a task does not yield when expected, other tasks may be delayed.

6.2 Preemptive Multitasking

In preemptive multitasking, the operating system or RTOS scheduler can interrupt a running task and select another task according to its scheduling policy.

Preemption can occur when a time slice expires or when a higher-priority task becomes ready, depending on the scheduler configuration.

Feature Cooperative Preemptive
CPU release Task voluntarily yields Scheduler can preempt
Scheduling control More dependent on task behavior Controlled by scheduler policy
Responsiveness Can suffer if a task does not yield Can respond more promptly to eligible higher-priority tasks
Complexity Often simpler Requires careful synchronization and shared-resource management

7. Introduction to Multiprocessing

Multiprocessing is the use of two or more processing units to execute work within a computer system.

These processing units may be separate physical processors or multiple CPU cores within one processor package.

Example

A computer with a four-core CPU can execute eligible work on four cores at the same time. This enables true parallel execution when the operating system and applications provide suitable independent work.

Key idea: Multitasking concerns managing multiple tasks. Multiprocessing concerns using multiple processing units. A multiprocessing system can also support multitasking.

8. Single-Core and Multicore Processors

8.1 Single-Core Processor

A single-core processor contains one CPU core that executes instructions. It can support multitasking by switching between tasks, but it cannot execute two independent instruction streams simultaneously on that one core.

8.2 Multicore Processor

A multicore processor contains multiple CPU cores. Each core can execute its own instruction stream, allowing multiple tasks or threads to run in parallel.

Feature Single-Core Multicore
CPU cores One Two or more
Multitasking Yes, through scheduling Yes
True parallel execution Not on one core Possible across cores
Typical benefit Simpler processing architecture Higher potential parallel throughput

9. Symmetric and Asymmetric Multiprocessing

9.1 Symmetric Multiprocessing (SMP)

In SMP, multiple processors or cores operate as peers under one operating system. The operating system can schedule eligible tasks across the available processing units.

Modern multicore general-purpose computers commonly use SMP-style operating-system architectures.

9.2 Asymmetric Multiprocessing (AMP)

In AMP, processing units may have different responsibilities. One processor may act as a master and coordinate work performed by other processors, or processors may run separate software environments.

AMP is used in some embedded and heterogeneous computing systems.

Feature SMP AMP
Processor roles Generally peer processors May have different assigned roles
Scheduling OS can distribute work across processors May use processor-specific scheduling
Typical use Multicore computers and servers Some embedded and heterogeneous systems

10. Multitasking vs Multithreading vs Multiprocessing

Concept Meaning Example
Multitasking Managing multiple tasks or processes Browser and music player running together
Multithreading Using multiple threads within a process Browser UI and background download threads
Multiprocessing Using multiple processing units Two CPU cores executing separate threads

These concepts are related but are not interchangeable. A single-core system can perform multitasking and multithreading through scheduling, while multiprocessing provides multiple processing units for parallel execution.

11. Concurrency vs Parallelism

Concurrency

Concurrency means multiple tasks make progress during overlapping periods. A single-core processor can achieve concurrency by switching between tasks.

Parallelism

Parallelism means multiple tasks execute at the same instant using separate execution resources, such as different CPU cores.

Concurrency Parallelism
Tasks make overlapping progress. Tasks execute simultaneously.
Possible on a single core. Requires multiple execution resources.
Often achieved through scheduling and interleaving. Achieved by executing work on separate cores or processors.
Remember: Concurrency is about coordinating multiple activities. Parallelism is about executing multiple activities simultaneously.

12. Context Switching in Multitasking

A context switch occurs when the processor stops executing one task and starts executing another task.

The operating system or RTOS preserves the execution state of the previous task and restores the state of the selected task.

Typical context information

  • CPU registers.
  • Program counter.
  • Stack pointer.
  • Processor status information.
  • Other architecture- or operating-system-specific state.

Context switching allows multiple tasks to share CPU resources. However, it introduces overhead because the processor performs management work instead of application work.

The complete context-switching mechanism is covered in the next lesson.

13. CPU-Bound and I/O-Bound Tasks

CPU-Bound Task

A CPU-bound task spends most of its time performing computations.

Example: Image processing, mathematical calculations, and data compression.

I/O-Bound Task

An I/O-bound task spends a significant amount of time waiting for input/output operations.

Example: Reading a file, receiving network data, or waiting for a sensor interface.

When an I/O-bound task blocks, another ready task can use the CPU. This helps improve processor utilization.

14. Advantages and Challenges of Multitasking and Multiprocessing

Advantages

  • Improved responsiveness and resource utilization.
  • Potentially higher throughput.
  • Ability to divide complex applications into independent activities.
  • Parallel execution on multicore processors.
  • Better support for background services and real-time workloads.

Challenges

  • Scheduling overhead: Selecting tasks and switching contexts consumes processing time.
  • Race conditions: Concurrent access to shared data can produce incorrect results.
  • Synchronization: Tasks may require mutexes, semaphores, or other coordination mechanisms.
  • Deadlocks: Tasks may wait indefinitely for resources held by one another.
  • Load balancing: Work may not be distributed evenly across CPU cores.
  • Cache contention: Cores may compete for shared memory resources or cache capacity.
  • Scalability: Adding cores does not guarantee proportional performance improvement.

15. Multitasking in Embedded Systems

Embedded systems often perform several activities, such as:

  • Reading sensor values.
  • Processing input data.
  • Updating display information.
  • Handling UART communication.
  • Controlling motors or actuators.
  • Monitoring system faults.

Bare-Metal Cooperative Superloop

A simple embedded system can use an infinite loop to perform several operations sequentially.

int main(void)
{
    System_Init();

    while (1)
    {
        Read_Sensor();
        Process_Data();
        Update_Display();
        Handle_Communication();
    }
}

This is a cooperative superloop. Each function must return control promptly. A long-running function can delay the remaining activities.

RTOS-Based Multitasking

An RTOS allows application activities to be organized into separate tasks. The scheduler determines which ready task receives CPU time.

void SensorTask(void *argument)
{
    for (;;)
    {
        Read_Sensor();
        Process_Sensor_Data();

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void CommunicationTask(void *argument)
{
    for (;;)
    {
        Handle_Communication();

        vTaskDelay(pdMS_TO_TICKS(20));
    }
}

This is an illustrative FreeRTOS-style example. It assumes that the required FreeRTOS headers, task creation, scheduler startup, and hardware functions are configured separately.

Configuration note: FreeRTOS scheduling behavior depends on the selected port and configuration. Preemption and time slicing are configurable; equal-priority time slicing is not an unconditional behavior in every configuration.

16. Multitasking on LPC2129

The LPC2129 uses an ARM7TDMI-S processor with a single CPU core. It can support multitasking when an appropriate RTOS or scheduling mechanism is used.

Possible embedded activities

Task Responsibility
Sensor Task Acquire and process sensor readings.
UART Task Handle serial communication.
Display Task Prepare LCD display updates.
Control Task Execute control logic.

On this single-core processor, only one task executes on the CPU core at a time. An RTOS can switch between tasks to provide concurrent progress, but it does not provide true multicore parallel execution.

In a Keil uVision simulator-only environment, you can study program flow, CPU registers, memory, and debugger behavior. Do not interpret a simulated task schedule as proof of physical peripheral timing or real hardware performance.

17. FreeRTOS Multitasking Concepts

FreeRTOS provides task-management and scheduling services for embedded applications.

Important task-related functions

Function Purpose
xTaskCreate() Creates a task.
vTaskStartScheduler() Starts the task scheduler.
vTaskDelay() Places a task in the blocked state for a specified number of ticks.
taskYIELD() Requests a task yield.
vTaskSuspend() Suspends a task.
vTaskResume() Resumes a suspended task.

In a typical preemptive FreeRTOS configuration, the scheduler selects the highest-priority ready task. Other configuration options can change scheduling behavior.

Task synchronization and communication mechanisms are covered in later chapters.

18. Observing Multitasking in Linux

Linux provides several commands for examining processor resources and running processes.

1. Display available processing units

nproc

Displays the number of processing units available to the current process, subject to system restrictions.

2. Display CPU architecture information

lscpu

Displays CPU architecture, cores, threads, sockets, and related information.

3. Monitor running processes

top

Displays running processes and system resource usage.

4. Display processes and threads

ps -eLf

Displays processes and their threads in a detailed format.

5. Display process hierarchy

pstree

Displays processes in a tree structure.

Practical observation: A system may show many processes and threads even when it has only one CPU core. This is possible because the scheduler shares CPU time among runnable work.

19. Real-World Applications

Desktop Operating Systems

Windows and Linux manage foreground applications, background services, and system processes through multitasking and CPU scheduling.

Servers

Servers handle multiple client requests and background operations. Multicore processors can execute independent work in parallel.

Automotive Embedded Systems

Electronic control units may perform sensor acquisition, communication, diagnostics, and control activities under timing constraints.

Industrial Automation

Industrial controllers may coordinate input acquisition, control algorithms, communication, and fault monitoring.

Consumer Electronics

Devices such as smart televisions and networking equipment perform multiple software activities concurrently.

20. Lesson Summary

  • Multitasking allows multiple tasks to make progress through CPU scheduling.
  • Time-sharing allocates CPU time in intervals.
  • Cooperative multitasking relies on tasks voluntarily yielding control.
  • Preemptive multitasking allows the scheduler to interrupt a running task.
  • Multiprocessing uses multiple processing units.
  • Concurrency can occur on a single core; parallelism requires multiple execution resources.
  • SMP uses peer processors, while AMP may assign different processor roles.
  • Multitasking introduces scheduling and synchronization challenges.
  • RTOS task scheduling is useful for organizing embedded applications.
  • The LPC2129 is single-core and can provide multitasking without true multicore parallelism.
