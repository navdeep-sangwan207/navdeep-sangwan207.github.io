Functions of an Operating System

Chapter 02 | Lesson 02

Process management, memory management, file systems, device management and security

1. Introduction

An operating system performs several important functions to manage computer hardware and provide a reliable environment for application software.

These functions allow multiple programs to execute, manage memory, access files, communicate with hardware and share system resources safely.

Definition: Operating system functions are the services and management operations performed by an OS to control hardware resources and support application execution.

2. Process Management

A process is a program in execution. The operating system manages processes and coordinates their use of CPU resources.

Main Responsibilities

  • Creating and terminating processes.
  • Scheduling processes for CPU execution.
  • Suspending and resuming processes.
  • Managing process states.
  • Supporting inter-process communication.
  • Providing process synchronization.
  • Handling process-related resource allocation.

Process States

State Description
New The process is being created.
Ready The process is ready and waiting for CPU time.
Running The process is currently executing.
Waiting / Blocked The process is waiting for an event or resource.
Terminated The process has completed or been stopped.

Example

Suppose a computer runs a browser, a music player and a text editor. The operating system schedules their processes so that they can share CPU time.

A process is not the same as a program. A program is a set of instructions; a process is an executing instance of a program with its own execution context and allocated resources.

3. CPU Scheduling

CPU scheduling is the mechanism through which the operating system selects a ready process or thread to execute on the processor.

Common Scheduling Algorithms

  • First Come First Served (FCFS).
  • Shortest Job First (SJF).
  • Priority Scheduling.
  • Round Robin Scheduling.
  • Multilevel Queue Scheduling.

Example: Round Robin

In Round Robin scheduling, each ready process receives a fixed CPU time interval called a time quantum. If it does not finish within that interval, it is preempted and placed back in the ready queue.

Example:
  • Process P1 executes for up to 4 ms.
  • Process P2 executes for up to 4 ms.
  • Process P3 executes for up to 4 ms.
  • The scheduler repeats the cycle while processes remain ready.

4. Memory Management

Memory management is the function of the operating system that controls the allocation and use of main memory (RAM).

Main Responsibilities

  • Tracking used and available memory.
  • Allocating memory to processes.
  • Releasing memory when it is no longer required.
  • Protecting process memory spaces.
  • Managing virtual memory where supported.
  • Handling memory-related errors.

Memory Management Techniques

Technique Purpose
Contiguous Allocation Allocates a continuous memory region to a process.
Paging Divides virtual memory into fixed-size pages and physical memory into frames.
Segmentation Organizes memory into logical variable-sized segments.
Virtual Memory Provides an address-space abstraction that can use secondary storage as backing.

Example

If a system has 8 GB RAM and several applications are running, the operating system tracks memory usage and manages allocation among them.

Embedded systems often have limited RAM. Some microcontrollers have no memory-management unit (MMU), so their software may use static allocation or simpler memory-management techniques.

5. File Management

File management is the operating system function responsible for organizing, storing, retrieving and protecting files and directories.

Main Responsibilities

  • Creating and deleting files.
  • Opening and closing files.
  • Reading and writing file data.
  • Creating and managing directories.
  • Maintaining file metadata.
  • Managing file permissions.
  • Organizing storage allocation.

Linux File Management Commands

Command Function
touch file.txt Creates an empty file if it does not exist.
mkdir test Creates a directory.
cp a.txt b.txt Copies a file.
mv a.txt b.txt Moves or renames a file.
rm file.txt Removes a file.
cat file.txt Displays file contents.

6. Device Management

Device management controls access to input/output devices and coordinates data transfer between hardware and software.

Examples of Devices

  • Keyboard and mouse.
  • Display and printer.
  • Hard disk and SSD.
  • Network interface.
  • USB devices.
  • Serial communication interfaces.

Responsibilities

  • Device allocation and release.
  • Communication through device drivers.
  • Handling device interrupts.
  • Buffering and data transfer.
  • Monitoring device status and errors.

Example: Keyboard Input

  1. The user presses a key.
  2. The keyboard hardware generates an event.
  3. The device controller signals the processor.
  4. The operating system handles the input event.
  5. The application receives the input through an OS interface.

7. I/O Management

Input/Output (I/O) management coordinates data exchange between applications, memory and peripheral devices.

Important I/O Techniques

  • Programmed I/O: The processor controls the I/O operation by checking device status and transferring data.
  • Interrupt-Driven I/O: The device signals the processor when attention is required.
  • Direct Memory Access (DMA): A DMA controller transfers data between a device and memory with reduced CPU involvement.
  • Buffering: Temporary storage helps coordinate data transfer between components operating at different speeds.

8. Security and Protection

The operating system provides security and protection mechanisms to prevent unauthorized access to data, programs and system resources.

Important Security Functions

  • User authentication.
  • File and directory permissions.
  • Process isolation.
  • Access control.
  • Security auditing and logging.
  • Privilege management.

Linux Permission Example

ls -l
chmod 755 script.sh
chmod 644 file.txt

The chmod command changes file permissions. For example, permission 755 gives the owner read, write and execute permissions, while group and other users receive read and execute permissions.

9. User Interface Management

An operating system provides interfaces through which users interact with the computer.

Command-Line Interface (CLI)

A CLI accepts text commands entered by a user. 

pwd
ls
cd Documents
mkdir Projects

Graphical User Interface (GUI)

A GUI allows users to interact through windows, icons, menus, buttons and other graphical elements.

CLI GUI
Uses text commands. Uses graphical elements.
Can be efficient for automation and administration. Can be easier for visual interaction.
Requires command knowledge. Often requires less command memorization.

10. Error Detection and Handling

An operating system monitors system operations and handles errors that occur during program execution or hardware interaction.

Examples

  • Invalid memory access.
  • Disk read or write errors.
  • Device communication failures.
  • Illegal instructions.
  • File permission errors.
  • Process execution failures.

The OS may report an error, return an error code, terminate a faulty process or initiate recovery actions depending on the failure.

11. Networking and Communication

Modern operating systems provide networking services that allow computers and applications to communicate with other systems.

Networking Responsibilities

  • Network interface management.
  • Protocol implementation and support.
  • Socket communication.
  • Network configuration.
  • Data transmission and reception.
  • Network security and access control.

Example: Network Connectivity Check

ping -c 4 8.8.8.8
ip addr
ip route

12. Resource Allocation and Accounting

The operating system allocates available resources among processes and users according to system policies.

Resources Managed

  • CPU time.
  • Main memory.
  • Storage space.
  • Peripheral devices.
  • Network resources.

Resource accounting records or measures how system resources are being used. This information helps administrators monitor system activity and performance.

13. System Services and System Calls

Applications use operating-system interfaces to request services such as file access, process creation and communication.

A system call is a controlled entry point through which a user-space program requests a service from the operating-system kernel.

Examples of Linux System Calls

System Call Purpose
open() Opens a file.
read() Reads data from a file descriptor.
write() Writes data to a file descriptor.
close() Closes a file descriptor.
fork() Creates a new process on Linux.
execve() Replaces the current process image with a new program.

14. Operating System Functions in RTOS

An RTOS provides many operating-system services, but these services are designed around embedded application requirements and predictable timing behavior.

OS Function Typical RTOS Service
Task Management Task creation, deletion, suspension and scheduling.
Memory Management Static or dynamic memory allocation.
Synchronization Semaphores, mutexes and event groups.
Communication Queues, notifications and shared memory.
Time Management System ticks, delays and software timers.
Interrupt Management Interrupt service routines and deferred processing.
FreeRTOS Note: FreeRTOS provides core kernel services such as task scheduling, queues, semaphores and software timers. It does not provide every service found in a full-featured general-purpose OS, such as a standard desktop GUI or a complete general-purpose file system.

15. Practical Linux Demonstration

The following commands demonstrate several operating system functions in Ubuntu.

16. Lesson Summary

  • Process management controls process creation, execution and termination.
  • CPU scheduling selects processes or threads for execution.
  • Memory management allocates and protects memory.
  • File management organizes files and directories.
  • Device and I/O management coordinate hardware communication.
  • Security and protection prevent unauthorized access.
  • User interface management provides CLI and GUI interaction.
  • Error handling detects and responds to system failures.
  • Networking services support communication between systems.
  • System calls provide controlled access to kernel services.
  • RTOS kernels provide task, timing, synchronization and communication services.
