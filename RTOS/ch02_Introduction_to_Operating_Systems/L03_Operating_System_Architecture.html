Understanding OS structure, kernel organization and architectural approaches

1. Introduction

Operating System Architecture describes how the internal components of an operating system are organized and how they communicate with each other.

It defines the relationship between the kernel, device drivers, system services, application programs and computer hardware.

The architecture determines how operating-system services are implemented, how components interact and how the system handles performance, reliability, security and maintenance.

Definition: Operating system architecture is the structural organization of an operating system, including its components, interfaces and communication mechanisms.

3. Monolithic Kernel Architecture

A monolithic kernel implements many operating-system services within a large kernel address space.

Core services such as process management, memory management, file systems, networking and device drivers can execute in kernel mode.

Architecture Diagram

System Call Interface
Monolithic Kernel
Process Management
Memory Management
File System
Device Drivers
Networking
Hardware

Characteristics

  • Many operating-system services execute in kernel mode.
  • Kernel components can communicate through internal function calls and shared kernel data.
  • Kernel services can have efficient communication paths.
  • A fault in a privileged component can affect the entire system.

Advantages

  • Efficient communication between kernel components.
  • Potentially low service-call overhead.
  • Direct access to kernel-managed resources.

Disadvantages

  • Large and complex kernel implementation.
  • Debugging can be difficult.
  • A faulty kernel-mode driver can crash the system.
  • Changes to internal components require careful integration.

Examples

Traditional UNIX systems use a monolithic kernel design. Modern Linux is commonly described as a modular monolithic kernel because it supports dynamically loadable kernel modules while retaining many services in kernel space.

4. Layered Operating System Architecture

In a layered architecture, the operating system is divided into multiple layers. Each layer provides services to the layer above it and uses services from the layer below it.

Architecture Diagram

Layer 5: User Applications
Layer 4: System Services
Layer 3: Process and Memory Management
Layer 2: Device and I/O Management
Layer 1: Hardware Interface
Physical Hardware

Characteristics

  • System functionality is divided into logical layers.
  • Each layer has defined responsibilities.
  • Higher layers use services provided by lower layers.
  • Interfaces between layers help organize the design.

Advantages

  • Modular organization.
  • Easier testing of individual layers.
  • Clear separation of responsibilities.
  • Maintenance can be simplified.

Disadvantages

  • Layer-to-layer communication may add overhead.
  • Strict layer boundaries can restrict optimization.
  • Designing suitable layers and interfaces can be difficult.
The diagram represents a conceptual layered design. Actual operating systems do not necessarily follow these exact five layers.

5. Microkernel Architecture

A microkernel keeps only essential operating-system mechanisms inside the kernel.

Other services, such as file systems, network services and device drivers, may execute as separate user-space processes or servers.

Architecture Diagram

User Applications
User-Space Servers
File System Server
Network Server
Device Driver Services
Microkernel

Basic Scheduling, IPC, Address-Space Management and Interrupt Handling

Hardware

Characteristics

  • Small set of essential kernel functions.
  • Many services execute outside the kernel.
  • Inter-process communication (IPC) is important.
  • Service isolation can improve fault containment.

Advantages

  • Smaller trusted kernel core.
  • Better isolation of many system services.
  • Individual services can be developed and maintained separately.
  • Some service failures may be recoverable without crashing the kernel.

Disadvantages

  • IPC can introduce communication overhead.
  • Coordination between services can be complex.
  • Performance depends on implementation and workload.

Examples

  • MINIX 3.
  • QNX Neutrino.
  • seL4.

6. Modular Kernel Architecture

A modular kernel supports a core kernel that can be extended using separately organized modules.

Modules may provide device drivers, file systems, network protocols or other kernel functionality. Depending on the operating system, modules may be loaded and unloaded while the system is running.

Architecture Diagram

User Applications
System Call Interface
Core Kernel
Process and Memory Management
Module Interface
Loadable Kernel Modules
Device Drivers
File Systems
Network Modules
Hardware

Advantages

  • Extends kernel functionality without rebuilding the entire kernel in every case.
  • Supports modular development.
  • Modules can be loaded when required.
  • Useful for device-driver and file-system support.

Disadvantages

  • Faulty kernel modules can compromise system stability.
  • Module compatibility and dependency management are important.
  • Kernel-mode modules require careful security review.

Example: Linux Kernel Modules

Linux supports loadable kernel modules (LKMs). Administrators can inspect and manage modules using commands such as: 

lsmod
modinfo module_name
sudo modprobe module_name
sudo modprobe -r module_name

These commands list loaded modules, display module information, load a module and request its removal.

7. Hybrid Kernel Architecture

A hybrid kernel combines design ideas from monolithic and microkernel architectures.

It may use a modular internal structure while keeping many performance-critical services in kernel mode.

Characteristics

  • Combines selected architectural approaches.
  • May keep drivers and core services in kernel space.
  • Can use modular organization.
  • Attempts to balance performance, modularity and maintainability.

Advantages

  • Flexible architectural organization.
  • Can provide efficient internal communication.
  • Supports a wide range of operating-system services.

Disadvantages

  • Can be complex to design and maintain.
  • Kernel-mode components can still affect overall stability.
  • Architectural boundaries may be less strict than in a microkernel.

Examples

Windows NT-family operating systems are commonly described as using a hybrid architecture. Apple's XNU kernel also combines Mach and BSD components, with additional kernel extensions.

8. Exokernel Architecture

An exokernel is an operating-system architecture that aims to provide applications with more direct and controlled access to hardware resources.

Instead of implementing many high-level abstractions inside a large kernel, an exokernel focuses on securely protecting and allocating physical resources.

Characteristics

  • Small kernel focused on resource protection and allocation.
  • Applications can use library operating systems.
  • Applications may customize resource abstractions.
  • Provides flexibility for specialized workloads.

Advantages

  • Greater application-level control over resources.
  • Potential for specialized performance optimization.
  • Flexible abstraction design.

Disadvantages

  • More responsibility is placed on application developers.
  • Application development can become complex.
  • It is less common in mainstream general-purpose systems.

9. Comparison of Operating System Architectures

Architecture Organization Main Advantage Main Limitation
Monolithic Many services execute in kernel space. Efficient internal communication. Large kernel fault impact.
Layered Services organized into layers. Clear separation of responsibilities. Layer communication overhead.
Microkernel Minimal kernel with external services. Service isolation. IPC and coordination overhead.
Modular Core kernel with loadable modules. Extensibility. Module faults can affect the kernel.
Hybrid Combines architectural approaches. Flexible design. Complexity.
Exokernel Minimal resource-protection kernel. Application-level flexibility. More application complexity.

10. RTOS Kernel Architecture

An RTOS kernel is designed to manage tasks and provide services required by real-time applications.

Typical RTOS Kernel Components

  • Scheduler: Selects the task to execute.
  • Task Manager: Maintains task states and control information.
  • Clock and Tick Management: Maintains system time and task delays.
  • Interrupt Management: Handles hardware interrupt events.
  • Synchronization: Coordinates access to shared resources.
  • Inter-Task Communication: Transfers information between tasks.
  • Memory Management: Provides supported memory allocation services.

11. FreeRTOS Architecture Overview

FreeRTOS follows a compact kernel architecture intended for embedded microcontrollers and resource-constrained systems.

Important Components

Component Purpose
Scheduler Controls task selection and execution.
Tasks Represent independent units of application execution.
Queues Transfer data between tasks and supported ISR contexts.
Semaphores Provide synchronization and event signaling.
Mutexes Protect shared resources between tasks.
Software Timers Execute timer callbacks through the timer service task.
Portable Layer Connects the kernel to processor-specific functionality.
FreeRTOS is a kernel rather than a complete desktop operating system. File systems, networking stacks and device drivers may be supplied separately or integrated through additional components.

12. How to Select an OS Architecture

Selecting an operating-system architecture depends on the application's requirements and constraints.

Important Selection Factors

  • Processor performance and available memory.
  • Real-time timing requirements.
  • Reliability and fault-isolation requirements.
  • Security and privilege boundaries.
  • Device-driver requirements.
  • Development and maintenance complexity.
  • Communication and synchronization needs.
  • Hardware and software ecosystem support.

Example Applications

Application Possible Architecture
General-purpose Linux system Modular monolithic kernel.
High-isolation embedded control platform Microkernel-based RTOS.
Small microcontroller application Compact RTOS kernel or bare-metal firmware.
Desktop operating system Hybrid or modular architecture.

13. Lesson Summary

  • OS architecture defines the internal organization of an operating system.
  • Monolithic kernels implement many services in kernel space.
  • Layered architecture separates functions into logical layers.
  • Microkernels keep a minimal set of services inside the kernel.
  • Modular kernels support extensions through modules.
  • Hybrid architectures combine design approaches.
  • Exokernels focus on protected resource allocation and application flexibility.
  • RTOS kernels provide task scheduling, timing and synchronization services.
  • FreeRTOS uses a compact kernel with a processor-specific portable layer.
