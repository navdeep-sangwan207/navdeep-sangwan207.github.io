Lesson 05: Process and Thread Concepts

Lesson Overview

Processes and threads are fundamental concepts in operating systems. A process represents a program in execution, while a thread represents an execution path within a process. Operating systems use processes and threads to organize application execution and share CPU resources.

Learning Objectives:

  • Understand programs and processes.
  • Study process states and state transitions.
  • Understand the Process Control Block (PCB).
  • Learn the concept and characteristics of threads.
  • Differentiate processes and threads.
  • Relate processes and threads to embedded RTOS tasks.

1. Introduction to a Program

A program is a set of instructions written to perform a particular task. It is generally stored as an executable file or another form of program code.

A program is passive when it is stored on a storage device. When the operating system loads it and begins executing it, an active execution instance is created. This is called a process.

Examples of programs

  • A calculator application.
  • A web browser.
  • A text editor.
  • A C or C++ executable program.
  • A Linux command-line utility.
A program is not the same as a process. A program is the executable code, whereas a process is an executing instance with associated resources and execution state.

2. What is a Process?

A process is an instance of a program that is being executed by the operating system. It includes the program code and the information required to manage its execution.

Components associated with a process

  • Text section: Contains executable instructions.
  • Data section: Contains initialized global and static data.
  • BSS section: Contains uninitialized or zero-initialized static storage.
  • Heap: Provides memory for dynamic allocation.
  • Stack: Stores function call information and local variables.
  • Process control information: Contains identifiers, state and resource-management information.

Example

Suppose a user opens a text editor. The operating system creates a process for the application and allocates the resources required for its execution.

If the user opens another independent instance of the same application, the operating system may create another process. Each process has its own execution context and resource-management information.

3. Process States

During execution, a process moves through different states. The operating system maintains the current state to determine whether the process can execute, must wait or has completed.

Major process states

State Description
New The process is being created.
Ready The process is prepared to execute and waiting for CPU allocation.
Running The process is currently executing on a CPU core.
Waiting / Blocked The process is waiting for an event, I/O operation or another condition.
Terminated The process has finished or has been terminated.

Process state transition diagram

↓ Admission

↓ Scheduler dispatch
Running
↓ I/O request / event wait
Waiting / Blocked
↓ Event completed
Ready
↓ Completion
Terminated

Important state transitions

  • New → Ready: The process is admitted for execution.
  • Ready → Running: The CPU scheduler selects the process.
  • Running → Ready: The process is preempted or its time slice expires.
  • Running → Waiting: The process waits for I/O or another event.
  • Waiting → Ready: The required event completes.
  • Running → Terminated: The process completes or is terminated.
Process-state models can contain additional states, such as suspended-ready and suspended-blocked. The five-state model is a common introductory representation.

4. Process Control Block (PCB)

The Process Control Block (PCB) is a kernel-maintained data structure containing information required to manage a process. It allows the operating system to track process execution and restore its context when necessary.

Information stored in a PCB

PCB Field Purpose
Process ID (PID) Uniquely identifies a process within its process namespace.
Process State Stores whether the process is ready, running, blocked or terminated.
Program Counter Identifies the instruction address to resume execution.
CPU Registers Stores the processor context required for execution.
Scheduling Information Contains priority and scheduling-related information.
Memory Management Information References address-space and memory-management data.
I/O Information Tracks relevant open files and I/O resources.
Accounting Information May contain CPU usage and other resource statistics.

When a process is interrupted or preempted, the operating system saves the necessary execution context. Later, it can restore that context so the process can continue.

5. What is a Thread?

A thread is a basic unit of CPU execution within a process. A process can contain one or more threads.

Threads belonging to the same process generally share the process's address space and resources, while each thread has its own execution context.

Thread characteristics

  • Each thread has its own program counter.
  • Each thread has its own CPU register context.
  • Each thread has its own stack.
  • Threads in a process share code and data regions.
  • Threads can communicate through shared process memory.
  • Threads can execute concurrently or in parallel, depending on scheduling and available CPU cores.

Example: Web browser

A browser may use multiple threads for different activities:

  • User-interface processing.
  • Network communication.
  • Background data processing.
  • Rendering and other application work.

These threads may belong to the same process or to different processes, depending on the browser architecture.

6. Thread States

Threads also move through execution states. A simplified thread state model is similar to the process state model.

Thread State Description
New The thread is being created.
Ready The thread is ready and waiting for CPU time.
Running The thread is currently executing.
Blocked / Waiting The thread is waiting for an event or resource.
Terminated The thread has completed or has been stopped.

A thread can be preempted and returned to the ready state. A blocked thread becomes ready when the event or resource for which it was waiting becomes available.

7. Process vs Thread

Processes and threads both represent execution, but they differ in resource ownership, memory organization and management overhead.

Parameter Process Thread
Definition An executing program instance. An execution unit within a process.
Address Space Normally has its own protected address space. Shares the process address space with sibling threads.
Memory Has process-specific memory and resources. Has its own stack and execution context.
Communication Often uses IPC mechanisms. Can communicate through shared process memory.
Creation Overhead Generally higher. Generally lower.
Context Switching May involve address-space and resource changes. May be less expensive when switching within the same process.
Failure Impact Often isolated from unrelated processes. A serious thread failure can affect its entire process.
Resource Sharing Uses controlled sharing mechanisms. Shares many resources with other threads in the process.
Process and thread creation and switching costs depend on the operating system, architecture and implementation. Threads are generally lighter-weight, but they still require scheduling and context-management work.

8. Single-Threaded and Multithreaded Processes

Single-threaded process

A single-threaded process contains one thread of execution. It performs its work through a single execution path.

Multithreaded process

A multithreaded process contains multiple threads. Each thread can perform a separate activity while sharing the process's common resources.

↓
Shared Code, Data and Process Resources

Advantages of multithreading

  • Improves application responsiveness.
  • Allows independent activities to progress concurrently.
  • Can use multiple CPU cores for parallel execution.
  • Allows efficient sharing of process resources.

Challenges of multithreading

  • Race conditions.
  • Deadlocks.
  • Shared-data synchronization.
  • More complex debugging.
  • Coordination and scheduling overhead.

9. Process Creation and Termination

An operating system creates processes when applications are launched or when an existing process requests a new process. A process can terminate normally after completing its work or abnormally because of an error or external request.

Linux process creation

Linux provides system calls such as fork() and execve() for process creation and program execution.

  • fork() creates a child process.
  • execve() replaces the calling process image with another program.
  • wait() and related calls allow a parent to collect a child's termination status.
  • exit() terminates the calling process.

Useful Linux commands

10. Process and Thread Context Switching

Context switching is the process of saving the execution state of one task and restoring the state of another task so that execution can continue.

Information involved in a context switch

  • Program counter.
  • CPU registers.
  • Stack pointer.
  • Processor status information.
  • Scheduling state and other required context.
  • Address-space information when switching between processes, where applicable.

Context switch sequence

Task A is Running
↓
Save Task A Context
↓
Scheduler Selects Task B
↓
Restore Task B Context
↓
Task B Starts / Resumes Execution

Switching between threads of the same process can avoid some address-space changes. Switching between different processes may require additional memory-management changes.

Context switching consumes CPU time. Excessive switching can reduce useful processing time, so operating systems and RTOS kernels must manage scheduling overhead carefully.

11. Processes and Threads in Embedded Systems

Embedded systems often use a simpler execution model than a general-purpose desktop operating system. A bare-metal program may execute as one main program with interrupt handlers.

Bare-metal execution

  • Usually one main application execution flow.
  • Interrupt handlers respond to hardware events.
  • No general-purpose process manager is necessarily present.
  • Tasks are often coordinated through loops and interrupt flags.

RTOS-based execution

An RTOS commonly manages multiple tasks. Each task has its own stack and execution context, and the scheduler selects which task executes.

RTOS tasks are conceptually similar to threads because they represent independently schedulable execution flows. However, the exact relationship between tasks, processes and threads depends on the RTOS architecture.

Example: Embedded monitoring system

Task Responsibility
Sensor Task Reads sensor measurements.
Communication Task Transmits data using UART.
Display Task Updates the LCD or display interface.
Control Task Performs control decisions.

The RTOS scheduler coordinates these tasks according to their priorities and scheduling rules.

On the LPC2129, Keil uVision simulator-based exercises can help demonstrate program execution and processor state. Actual RTOS task switching and peripheral behavior depend on the selected software port and simulator support.

12. Advantages and Challenges of Processes and Threads

Advantages of processes

  • Provide resource and address-space isolation.
  • Improve fault containment between applications.
  • Support independent program execution.

Advantages of threads

  • Allow multiple execution flows within one process.
  • Support responsive applications.
  • Enable shared-memory communication.
  • Can take advantage of multicore processors.

Common challenges

  • Scheduling and context-switching overhead.
  • Synchronization of shared resources.
  • Race conditions and deadlocks.
  • Memory and stack management.
  • Debugging concurrent execution.

13. Lesson Summary

  • A program is a set of instructions stored for execution.
  • A process is an executing instance of a program.
  • Processes move through states such as new, ready, running, waiting and terminated.
  • The PCB stores process-management information.
  • A thread is an execution unit within a process.
  • Threads have their own stacks and execution contexts.
  • Threads belonging to one process share many process resources.
  • Multithreading supports concurrent application activities.
  • Context switching saves and restores execution state.
  • RTOS tasks are independently schedulable execution units.

  1. Open the Ubuntu terminal.
  2. Execute ps -ef.
  3. Identify process IDs and parent process IDs.
  4. Execute top and observe running processes.
  5. Use pstree if available to examine process relationships.
  6. Compare the process information displayed by each command.

  1. Draw the five-state process model.
  2. Identify the transition from ready to running.
  3. Explain why a running process may become blocked.
  4. Explain how a blocked process returns to ready.
  5. Describe how a process reaches the terminated state.

  1. Design a simple embedded monitoring system.
  2. Identify at least three independent tasks.
  3. Assign a responsibility to each task.
  4. Identify which resources may be shared.
