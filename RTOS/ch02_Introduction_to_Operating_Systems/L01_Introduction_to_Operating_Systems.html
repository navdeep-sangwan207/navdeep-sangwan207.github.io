Understanding operating systems, their purpose, architecture and role in computer systems

1. Introduction

An Operating System (OS) is system software that manages computer hardware and provides services to application programs.

It acts as an intermediary between users, application software and computer hardware. It coordinates processor execution, memory, storage devices and input/output operations.

Without an operating system, application programs would need to manage many hardware details directly.

Definition: An operating system is a collection of system software components that manages hardware resources, controls program execution and provides an environment for applications to run.

2. Position of an Operating System in a Computer System

A computer system can be understood as a set of layers. The operating system sits between application software and the underlying hardware.

Computer System Layer Model

User
Application Software
Operating System
Hardware

Explanation of Each Layer

Layer Function
User Interacts with the computer through commands or graphical interfaces.
Application Software Performs tasks such as browsing, editing documents and calculations.
Operating System Manages hardware resources and provides system services.
Hardware Includes CPU, RAM, storage, display and peripheral devices.

3. Why Is an Operating System Needed?

An operating system simplifies computer operation by managing hardware resources and providing standard interfaces to applications.

Main Reasons

  • Hardware Management: Controls processor, memory and peripheral devices.
  • Program Execution: Loads and executes application programs.
  • Resource Sharing: Coordinates access to shared resources.
  • File Management: Organizes files and directories.
  • Security: Provides authentication and access-control mechanisms.
  • User Interface: Provides command-line or graphical interaction.
  • Error Handling: Detects and manages various system errors.

4. Main Components of an Operating System

An operating system contains several cooperating components that perform different system-management functions.

4.1 Kernel

The kernel is the central component of an operating system. It manages core resources and provides essential services to programs.

Typical kernel responsibilities include:

  • Process and thread management.
  • Memory management.
  • Device and I/O management.
  • Interrupt handling.
  • System-call handling.
  • Scheduling and synchronization.

4.2 Device Drivers

Device drivers are software components that allow the operating system to communicate with hardware devices.

Examples include:

  • Display drivers.
  • Network interface drivers.
  • USB device drivers.
  • Storage device drivers.
  • Audio drivers.

4.3 File System

The file system organizes and manages data stored on storage devices. It provides mechanisms for creating, reading, writing and deleting files and directories.

4.4 System Libraries

System libraries provide reusable functions that applications can use to access operating-system services.

4.5 Shell and User Interface

A shell or graphical interface allows users to interact with the operating system.

  • CLI: Command-Line Interface.
  • GUI: Graphical User Interface.

5. Operating System Examples

Operating System Typical Application

FreeRTOS Resource-constrained embedded microcontroller applications.
Important Distinction: FreeRTOS is a real-time operating system kernel designed for embedded applications. It is not a general-purpose desktop operating system like Windows or a typical Linux distribution.

6. Operating System and Hardware Interaction

Applications generally do not directly control every hardware operation. They request services through operating-system interfaces.

For example, when an application reads a file, the operating system coordinates file-system operations, storage access and data transfer.

Example: Reading a File

  1. The application requests a file read operation.
  2. The system-call interface transfers the request to the OS.
  3. The kernel checks permissions and file information.
  4. The file system identifies the required storage blocks.
  5. The device driver communicates with the storage device.
  6. The requested data is made available to the application.

7. Operating Systems in Embedded Systems

Embedded systems are dedicated computing systems designed to perform specific functions. Depending on their complexity and timing requirements, they may use bare-metal software, an RTOS or a more general-purpose operating system.

Examples

  • Automotive control units.
  • Industrial automation controllers.
  • Smart home devices.
  • Medical monitoring equipment.
  • Communication equipment.
  • IoT gateways and edge devices.

OS Selection in Embedded Systems

System Type Typical Software Approach
Simple sensor controller Bare-metal firmware may be sufficient.
Multitasking controller RTOS may be appropriate.
Embedded Linux gateway Linux-based operating system.
Smartphone General-purpose mobile operating system.

8. Operating System Versus RTOS

A general-purpose operating system focuses on overall system usability, throughput, resource sharing and responsiveness. An RTOS is designed to provide predictable timing behavior for tasks with real-time constraints.

Feature General-Purpose OS RTOS
Primary Goal General system performance and usability. Predictable timing and deadline handling.
Scheduling Often balances fairness, throughput and responsiveness. Often uses priority-based real-time scheduling.
Timing Predictability Not generally guaranteed. Designed to provide bounded timing behavior.
Typical Use Desktops, laptops and servers. Embedded and control systems.
Examples Windows, desktop Linux. FreeRTOS, Zephyr, QNX.
An RTOS does not automatically guarantee that every application meets its deadlines. Correct task design, WCET analysis, scheduling, synchronization and resource management are also required.

9. Basic Operating System Operations

The following Linux commands demonstrate common interactions with an operating system.

Display System Information

uname -a

Displays kernel and system information.

Display Current Directory

pwd

Displays the current working directory.

List Files and Directories

ls -l

Displays directory contents in a detailed format.

Display Memory Information

free -h

Displays memory usage in a human-readable format.

Display Running Processes

ps aux

Displays information about running processes.

10. Advantages of an Operating System

  • Simplifies interaction with computer hardware.
  • Manages processor and memory resources.
  • Supports application execution.
  • Provides file and storage management.
  • Supports multiple processes and users, depending on the OS.
  • Provides security and access-control mechanisms.
  • Improves system organization and resource utilization.

11. Limitations and Design Challenges

  • Operating systems consume processor time and memory.
  • Software defects can affect system stability.
  • Resource contention can reduce application performance.
  • Security vulnerabilities can expose system resources.
  • Complex operating systems may require significant configuration and maintenance.
  • General-purpose operating systems may not provide strict timing guarantees.

12. Lesson Summary

  • An operating system is system software that manages computer hardware and application execution.
  • The kernel is the central component of an operating system.
  • Device drivers provide hardware communication interfaces.
  • The file system manages files and directories.
  • System libraries provide reusable operating-system services.
  • Shells and graphical interfaces allow user interaction.
  • Embedded systems may use bare-metal firmware, an RTOS or a general-purpose OS.
  • An RTOS focuses on predictable timing behavior.
