2. Introduction to Types of Operating Systems

An operating system manages computer hardware and software resources and provides services to application programs.

Operating systems are classified according to how they manage tasks, users, processors, resources, and timing requirements.

Different operating systems are designed for different environments:

  • Personal computers.
  • Servers and data centers.
  • Mobile devices.
  • Industrial controllers.
  • Automotive systems.
  • Embedded and real-time applications.
Important: These categories are not always mutually exclusive. A modern operating system may combine features of several classifications.

3. Batch Operating System

A Batch Operating System collects similar jobs and processes them in groups called batches, generally without requiring continuous user interaction during execution.

How It Works

  1. Users submit jobs to the computer system.
  2. Jobs are collected and organized into batches.
  3. The operating system schedules the jobs for execution.
  4. The system processes the jobs in sequence or according to its scheduling policy.
  5. Results are made available after processing.

Examples of Applications

  • Payroll processing.
  • Bank statement generation.
  • Large-scale billing operations.
  • Periodic report generation.

Advantages

  • Suitable for repetitive jobs.
  • Reduces the need for continuous user interaction.
  • Can process large volumes of similar work efficiently.

Limitations

  • Limited interactive operation.
  • Results may not be available immediately.
  • Debugging and identifying errors can be difficult.

4. Multiprogramming Operating System

A Multiprogramming Operating System keeps multiple programs in main memory so that the CPU can execute another ready program when the currently running program waits for an I/O operation.

Working Principle

  1. Several programs are loaded into memory.
  2. The CPU executes one program.
  3. If that program waits for I/O, the operating system selects another ready program.
  4. The CPU continues executing useful work.
  5. Waiting programs become ready when their I/O operations complete.

Example

Program A is waiting for disk input. Instead of leaving the CPU idle, the operating system executes Program B.

Advantages

  • Improves CPU utilization.
  • Reduces CPU idle time.
  • Allows several programs to remain in memory.

Limitations

  • Requires memory management.
  • Needs CPU scheduling.
  • Requires protection between programs.
  • Can introduce resource-management complexity.

5. Multitasking Operating System

A Multitasking Operating System allows multiple tasks or processes to make progress during overlapping periods.

The CPU scheduler allocates processing time among eligible tasks. On a single-core processor, tasks generally execute in an interleaved manner.

Example

  • Running a web browser.
  • Playing audio.
  • Downloading files.
  • Running background services.

Common techniques

  • Preemptive scheduling.
  • Cooperative scheduling.
  • Time-sharing.
  • Priority-based scheduling.

Advantages

  • Improves system responsiveness.
  • Supports background activities.
  • Allows applications to share system resources.

Limitations

  • Context switching introduces overhead.
  • Shared resources require synchronization.
  • Scheduling and debugging become more complex.

6. Time-Sharing Operating System

A Time-Sharing Operating System allows multiple users or interactive processes to share CPU resources through short execution intervals called time slices.

Working Principle

  1. Multiple users or processes request CPU time.
  2. The scheduler selects a process.
  3. The process executes for its allocated time interval or until it blocks.
  4. The scheduler selects another eligible process.
  5. The cycle continues to provide interactive service.

Example

Multiple users connected to a shared server can run commands and applications while the operating system distributes CPU time among their processes.

Advantages

  • Supports interactive computing.
  • Allows multiple users to share a system.
  • Provides responsive access when appropriately configured.

Limitations

  • Frequent context switching can introduce overhead.
  • System performance may decrease under heavy load.
  • Resource contention can affect response time.

7. Multiprocessing Operating System

A Multiprocessing Operating System manages a computer system containing multiple processors or CPU cores.

It can distribute eligible processes and threads across available processing units to support parallel execution.

Types of Multiprocessing

7.1 Symmetric Multiprocessing (SMP)

In SMP, processors or cores operate as peers under a common operating-system environment. The scheduler can assign work to available processing units.

7.2 Asymmetric Multiprocessing (AMP)

In AMP, processors may have different responsibilities. One processor may coordinate other processors, or processors may execute separate software environments.

Advantages

  • Supports parallel execution.
  • Can increase processing throughput.
  • Can improve performance for parallel workloads.
  • Allows workloads to be distributed across cores.

Limitations

  • Requires synchronization between parallel tasks.
  • Shared memory and cache contention may occur.
  • Load balancing can be challenging.
  • Not every application can benefit from additional cores.

8. Distributed Operating System

A Distributed Operating System manages a collection of interconnected computers and coordinates their resources so that distributed computing activities can be carried out across the system.

Characteristics

  • Multiple connected computing nodes.
  • Resource sharing across nodes.
  • Distributed processing.
  • Communication between nodes.
  • Coordination of distributed activities.

Advantages

  • Supports resource sharing.
  • Can improve scalability.
  • Allows work to be distributed across computers.
  • Can improve availability when designed with redundancy.

Limitations

  • Network failures can affect operation.
  • Distributed coordination is complex.
  • Security management is challenging.
  • Communication introduces latency.
Note: A distributed operating system is not simply another name for a network operating system. The degree of integration and transparency of resource management differs.

9. Network Operating System

A Network Operating System (NOS) provides services that allow computers to communicate and share resources over a network.

Common services

  • File and printer sharing.
  • Network user authentication.
  • Centralized resource management.
  • Network security and access control.
  • Remote administration.

Examples

  • Windows Server.
  • Linux server distributions.
  • Network file and authentication services.

Advantages

  • Enables centralized administration.
  • Supports resource sharing.
  • Helps manage network users and permissions.

Limitations

  • Depends on network availability for remote services.
  • Requires security configuration and maintenance.
  • Centralized services may become bottlenecks or failure points.

10. Real-Time Operating System (RTOS)

A Real-Time Operating System (RTOS) is designed to provide predictable responses to events and support tasks with timing requirements.

In real-time computing, correctness depends not only on the result but also on whether the result is delivered within the required time constraints.

Types of Real-Time Systems

10.1 Hard Real-Time System

In a hard real-time system, missing a specified deadline is considered a failure of the required service.

Examples: Certain flight-control functions and safety-critical protection systems.

10.2 Soft Real-Time System

In a soft real-time system, a late result may still be useful, although its usefulness or quality decreases.

Examples: Multimedia playback and interactive audio applications.

10.3 Firm Real-Time System

In a firm real-time system, a result delivered after its deadline has no value. Occasional missed deadlines may be tolerated at the overall system level, depending on system requirements.

Example: A time-sensitive data update that becomes useless after its specified processing window.

RTOS Characteristics

  • Predictable scheduling behavior.
  • Priority-based task management.
  • Interrupt handling support.
  • Task synchronization and communication.
  • Deterministic or bounded response behavior where supported by the design.
  • Efficient resource management.

11. Embedded Operating System

An Embedded Operating System is designed for a dedicated computing device that performs specific functions within a larger system.

Embedded operating systems are often designed around constraints such as:

  • Limited memory.
  • Limited processing power.
  • Low power consumption.
  • Dedicated peripheral interfaces.
  • Reliability requirements.
  • Real-time or near-real-time requirements in some applications.

Examples of Embedded Operating Systems

  • FreeRTOS.
  • Zephyr.
  • Embedded Linux.
  • QNX Neutrino.
  • ThreadX / Azure RTOS.

Applications

  • Automotive electronic control units.
  • Industrial automation.
  • Medical equipment.
  • Networking devices.
  • Smart home appliances.
  • Consumer electronics.
Important: Not every embedded operating system is an RTOS. Embedded Linux, for example, is commonly used in embedded products but does not automatically provide hard real-time guarantees.

12. Mobile Operating Systems

A Mobile Operating System is designed for portable devices such as smartphones and tablets.

Examples

  • Android.
  • iOS.

Characteristics

  • Touchscreen user interfaces.
  • Wireless connectivity.
  • Power and battery management.
  • Application lifecycle management.
  • Security and permission controls.
  • Camera, audio, and sensor integration.

13. General-Purpose vs Real-Time Operating Systems

Feature General-Purpose OS RTOS
Primary objective General usability, throughput, and responsiveness Predictable response to timing requirements
Scheduling Designed for general workloads Designed to support real-time task requirements
Deadline handling No general hard-deadline guarantee May support bounded response and deadline-oriented design
Resource usage May require comparatively more resources Often designed for constrained environments
Typical applications Desktops, laptops, servers Control systems, industrial devices, embedded applications

Examples of general-purpose operating systems include Windows, desktop Linux, and macOS. Examples of RTOS include FreeRTOS, QNX, and Zephyr.

15. Selecting an Appropriate Operating System

The selection of an operating system depends on the requirements of the application.

Important selection factors

  • Performance: Required processing capability.
  • Timing: Whether tasks have strict deadlines.
  • Memory: Available RAM and storage.
  • Power: Battery and energy constraints.
  • Reliability: Required availability and fault handling.
  • Connectivity: Required communication interfaces.
  • Security: Protection and access-control requirements.
  • Development support: Toolchains, drivers, libraries, and debugging facilities.
  • Maintenance: Long-term support and update requirements.

Examples

Application Possible OS choice Reason
Desktop computer Windows or Linux General-purpose computing
Small microcontroller controller FreeRTOS or bare-metal firmware Constrained resources and task timing
Industrial control device Suitable RTOS or real-time platform Predictable control response
Smart television Embedded Linux or another embedded platform Multimedia and application support
Network server Linux or Windows Server Networking and multi-user services

16. Operating Systems in the Embedded Systems Domain

Embedded applications use different software architectures depending on complexity and timing requirements.

1. Bare-Metal System

Application firmware runs directly on the microcontroller without a general-purpose operating-system kernel.

2. RTOS-Based System

An RTOS manages tasks, scheduling, synchronization, and timing-related services.

3. Embedded Linux System

Embedded Linux provides a more extensive operating-system environment with process management, networking, filesystems, drivers, and application support.

Feature Bare Metal RTOS Embedded Linux
Kernel No OS kernel RTOS kernel Linux kernel
Task management Application-defined Kernel-managed tasks Process and thread management
Memory requirements Often very low Low to moderate Generally higher
Application complexity Simple to moderate Moderate to complex Complex applications
Typical platform Small microcontroller Microcontroller or suitable processor Application processor or capable SoC

17. Linux Practical: Identify Your Operating-System Environment

Ubuntu provides commands for identifying operating-system information and hardware architecture.

1. Display kernel information

uname -a

2. Display distribution information

cat /etc/os-release

3. Display CPU information

lscpu

4. Display memory information

free -h

5. Display running processes

ps -ef

6. Display system uptime

uptime

Observe the operating-system version, kernel version, processor architecture, available memory, and running processes.

18. Lesson Summary

  • Operating systems are classified according to their processing and resource-management approaches.
  • Batch OS processes groups of jobs.
  • Multiprogramming keeps multiple programs in memory to improve CPU utilization.
  • Multitasking manages multiple tasks through scheduling.
  • Time-sharing provides CPU access to multiple users or processes through time intervals.
  • Multiprocessing uses multiple processing units.
  • Distributed OS coordinates computing across interconnected systems.
  • Network OS provides network-related services and resource sharing.
  • RTOS supports applications with timing requirements.
  • Embedded OS is designed for dedicated devices.
  • Mobile OS is designed for portable computing devices.
  • Operating-system selection depends on performance, timing, memory, power, and reliability requirements.
