2. What Is a Semaphore?

A semaphore is a synchronization object used to coordinate tasks or signal events. It maintains a state or count that controls whether a task can proceed.

A task can attempt to take a semaphore. If the semaphore is available, the task takes it and continues. If it is unavailable, the task may wait for another task or an ISR to give it.

Common Semaphore Types

TypePurpose
Binary semaphoreEvent signaling or basic synchronization.
Counting semaphoreCounting events or tracking available resource units.
MutexMutual exclusion for shared resources, with ownership semantics.
Recursive mutexAllows the owning task to take the same mutex recursively.

3. What Is a Binary Semaphore?

A binary semaphore has only two possible states:

  • Available (1): A task can successfully take it.
  • Unavailable (0): A task cannot take it immediately.

A binary semaphore can be used as an event signal. One task or an ISR gives the semaphore, and another task takes it. 

       Binary Semaphore
       +-------------+
       |             |
       |  Available  |  1
       |             |
       +-------------+
              |
          Take |
              v
       +-------------+
       |             |
       | Unavailable |  0
       |             |
       +-------------+
              |
          Give |
              v
       +-------------+
       |             |
       |  Available  |  1
       |             |
       +-------------+
A FreeRTOS binary semaphore stores at most one token. Giving it repeatedly while it is already full does not build up a count of pending events.

4. Binary Semaphore Working Principle

Consider two tasks:

  • Task A: Performs an operation and signals completion.
  • Task B: Waits until Task A signals that the operation is complete.
       Task A
          |
          | Event occurs
          v
   xSemaphoreGive()
          |
          v
   +----------------+
   | Binary         |
   | Semaphore      |
   +----------------+
          |
          v
   xSemaphoreTake()
          |
          v
       Task B
   Continues Execution

If Task B is blocked waiting for the semaphore, a successful give can make Task B Ready. Whether it runs immediately depends on task priorities and scheduler behavior.

5. Creating a Binary Semaphore

FreeRTOS provides xSemaphoreCreateBinary() to create a binary semaphore dynamically.

Syntax

SemaphoreHandle_t xSemaphoreCreateBinary(void);

Example

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t eventSemaphore;

void CreateSemaphore(void)
{
    eventSemaphore = xSemaphoreCreateBinary();

    if (eventSemaphore == NULL)
    {
        /* Semaphore creation failed */
    }
}

Important Behavior

  • The function returns a semaphore handle.
  • It returns NULL if creation fails.
  • The newly created binary semaphore is initially empty.
  • A task or ISR must give it before a task can successfully take it.
  • Dynamic allocation is used by this creation function.
Unlike some older semaphore creation patterns, xSemaphoreCreateBinary() creates an initially empty semaphore. It does not provide an initial token.

6. xSemaphoreTake() Function

The xSemaphoreTake() function attempts to take a semaphore. If the semaphore is unavailable, the calling task may block for the specified number of ticks.

Syntax

BaseType_t xSemaphoreTake(
    SemaphoreHandle_t xSemaphore,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xSemaphoreHandle of the semaphore.
xTicksToWaitMaximum time to wait for availability, in ticks.

Return Values

  • pdPASS: Semaphore successfully taken.
  • pdFAIL: Semaphore could not be taken within the permitted wait.

Wait Behavior

ValueMeaning
0Check immediately without blocking.
Finite tick valueWait up to the specified number of ticks.
portMAX_DELAYWait indefinitely where the selected configuration supports it.
if (xSemaphoreTake(
        eventSemaphore,
        portMAX_DELAY
    ) == pdPASS)
{
    /* Semaphore successfully taken */
}

7. xSemaphoreGive() Function

The xSemaphoreGive() function gives a semaphore. For a binary semaphore, this makes the token available if it is currently empty.

Syntax

BaseType_t xSemaphoreGive(
    SemaphoreHandle_t xSemaphore
);

Return Values

  • pdPASS: Semaphore successfully given.
  • pdFAIL: The binary semaphore was already full or the operation could not be completed.

Example

if (xSemaphoreGive(eventSemaphore) == pdPASS)
{
    /* Event signal successfully posted */
}
Giving a binary semaphore does not transfer data. If an event includes payload data, use a queue or another appropriate data-transfer mechanism.

8. Binary Semaphore Example – Two Tasks

Objective: Synchronize two tasks using a binary semaphore.

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t eventSemaphore;

void SenderTask(void *pvParameters)
{
    for (;;)
    {
        /* Perform an operation */

        if (xSemaphoreGive(eventSemaphore) == pdPASS)
        {
            /* Signal posted */
        }

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void ReceiverTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                eventSemaphore,
                portMAX_DELAY
            ) == pdPASS)
        {
            /* Handle the event */
        }
    }
}

int main(void)
{
    eventSemaphore = xSemaphoreCreateBinary();

    if (eventSemaphore == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
            SenderTask,
            "Sender",
            configMINIMAL_STACK_SIZE,
            NULL,
            2,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
            ReceiverTask,
            "Receiver",
            configMINIMAL_STACK_SIZE,
            NULL,
            2,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. A binary semaphore is created.
  2. The sender task performs its operation.
  3. The sender gives the semaphore.
  4. The receiver task waits for the semaphore.
  5. After a successful take, the receiver handles the event.
  6. The receiver waits again for the next signal.

Expected Result

The receiver task processes an event after the sender gives the semaphore. The semaphore provides synchronization between the two tasks.

9. Binary Semaphore for Task Synchronization

A binary semaphore can synchronize two tasks that need to coordinate the order of their operations.

Example Scenario

A communication task receives a response from a peripheral. Another task waits for the response-complete event before continuing its operation. 

Task A:
    Start communication
    Wait for peripheral response
    Give binary semaphore

Task B:
    Take binary semaphore
    Process response-complete event

The semaphore signals that an event has occurred. If the response also contains data, transfer that data separately using a queue or shared buffer with an appropriate synchronization protocol.

10. Binary Semaphore From an ISR

A hardware interrupt can give a binary semaphore to notify a task that an event has occurred. FreeRTOS provides a dedicated ISR-safe function: xSemaphoreGiveFromISR().

Syntax

BaseType_t xSemaphoreGiveFromISR(
    SemaphoreHandle_t xSemaphore,
    BaseType_t *pxHigherPriorityTaskWoken
);

Example ISR Body

void HardwareISR(void)
{
    BaseType_t xHigherPriorityTaskWoken =
        pdFALSE;

    xSemaphoreGiveFromISR(
        eventSemaphore,
        &xHigherPriorityTaskWoken
    );

    /*
     * Use the ISR-yield mechanism required
     * by the selected FreeRTOS port.
     */
    portYIELD_FROM_ISR(
        xHigherPriorityTaskWoken
    );
}

Important Rules

  • Use xSemaphoreGiveFromISR() in interrupt context.
  • Do not use xSemaphoreGive() from an ISR.
  • Do not block inside an ISR.
  • Check the return value if repeated signals or a full semaphore matter.
  • Follow the port-specific interrupt-priority restrictions.
  • Use the correct ISR-yield mechanism for the selected port.
The ISR declaration and portYIELD_FROM_ISR() convention are port-dependent. Verify the selected FreeRTOS port documentation. ARM7/LPC2129 interrupt rules must not be replaced with Cortex-M NVIC or BASEPRI assumptions.

13. Important Limitation – Binary Semaphore Does Not Count Every Event

A binary semaphore can store only one pending token. If several events occur while the semaphore is already available, additional give operations do not create additional tokens.

Example

Initial state: Empty

Event 1: Give
State: Available

Event 2: Give
State: Already available

Event 3: Give
State: Already available

Task takes semaphore
State: Empty

The receiving task may process one signal, even though multiple events occurred. If every event must be counted, use a counting semaphore or queue instead.

14. Binary Semaphore Best Practices

  • Use binary semaphores primarily for event signaling.
  • Check whether creation succeeds.
  • Remember that xSemaphoreCreateBinary() creates an empty semaphore.
  • Check take and give return values when failures matter.
  • Use a queue when event payload data must be transferred.
  • Use a counting semaphore when every event must be counted.
  • Use a mutex to protect shared resources.
  • Never use a mutex as an ISR signaling object.
  • Keep ISRs short and use FromISR APIs.
  • Define the behavior for repeated or coalesced events.

16. Practical Experiment

Objective: Demonstrate synchronization between two tasks using a binary semaphore.

Procedure

  1. Include the FreeRTOS semaphore header.
  2. Declare a SemaphoreHandle_t variable.
  3. Create a binary semaphore.
  4. Create a sender task and a receiver task.
  5. Make the receiver wait using xSemaphoreTake().
  6. Make the sender signal using xSemaphoreGive().
  7. Observe the semaphore state and task transitions.
  8. Repeat with a longer sender delay.
  9. Try multiple give operations before the receiver takes the semaphore.

Expected Result

The receiver remains Blocked while the semaphore is unavailable. A successful give makes the semaphore available and can unblock the receiver. Repeated give operations while the semaphore is already full do not accumulate additional tokens.

19. Lesson Summary

  • A binary semaphore has two states: available and unavailable.
  • xSemaphoreCreateBinary() creates an initially empty semaphore.
  • xSemaphoreTake() attempts to take the semaphore.
  • xSemaphoreGive() makes the semaphore available.
  • Binary semaphores are useful for task synchronization and event signaling.
  • xSemaphoreGiveFromISR() is used to give a semaphore from an ISR.
  • Repeated gives can coalesce while the semaphore is already full.
  • A counting semaphore is more appropriate when every event must be counted.
  • A mutex is the appropriate mechanism for mutual exclusion and ownership-based resource protection.
