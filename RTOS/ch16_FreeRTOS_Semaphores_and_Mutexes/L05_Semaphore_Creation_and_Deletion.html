Chapter 16: FreeRTOS Semaphores and Mutexes

Lesson 05 – Semaphore Creation and Deletion

RTOS & FreeRTOS Chapter Index Learning Portal

Lesson Overview

FreeRTOS provides APIs to create and delete synchronization objects such as binary semaphores, counting semaphores, mutexes, and recursive mutexes.

These objects can be created dynamically using the FreeRTOS heap or statically using memory supplied by the application. Choosing the correct allocation method is important for predictable memory usage and reliable embedded software.

Learning Objectives

  • Understand semaphore object creation.
  • Differentiate dynamic and static allocation.
  • Learn binary and counting semaphore creation APIs.
  • Understand mutex and recursive mutex creation.
  • Learn semaphore deletion.
  • Understand memory allocation requirements.
  • Manage synchronization object lifecycles safely.

1. Introduction to Semaphore Creation

Before a task can use a semaphore, the application must create the semaphore object and obtain its handle.

The handle is stored in a variable of type SemaphoreHandle_t. 

SemaphoreHandle_t xSemaphore;

The handle is used in subsequent operations such as xSemaphoreTake(), xSemaphoreGive(), and vSemaphoreDelete().

A semaphore handle is an opaque reference to a kernel object. It is not the semaphore's internal control structure, and application code should not modify internal kernel data.

2. Dynamic Memory Allocation

In dynamic allocation, FreeRTOS obtains memory for the synchronization object from its configured heap.

The application calls a creation API, and the kernel allocates the required memory internally.

General Process

  1. Declare a semaphore handle.
  2. Call the appropriate creation API.
  3. FreeRTOS allocates memory for the object.
  4. The creation API returns a handle on success.
  5. The application checks the handle before using it.

Example

SemaphoreHandle_t xBinarySemaphore;

xBinarySemaphore = xSemaphoreCreateBinary();

if (xBinarySemaphore == NULL)
{
    /* Creation failed */
}
else
{
    /* Semaphore is ready for use */
}

Advantages

  • Simple creation APIs.
  • Memory is allocated when the object is required.
  • Objects can be created and deleted during application execution when the design permits.

Disadvantages

  • Requires a configured FreeRTOS heap.
  • Allocation can fail when insufficient memory is available.
  • Repeated allocation and deletion can contribute to heap fragmentation, depending on the allocator.
  • Allocation timing can complicate strict timing analysis.

3. Static Memory Allocation

In static allocation, the application provides the memory required by the synchronization object.

FreeRTOS uses the supplied storage rather than allocating the object's memory from the FreeRTOS heap.

Static Creation Requirements

  • Enable static allocation in the configuration when required.
  • Declare a StaticSemaphore_t storage object.
  • Call the corresponding static creation API.
  • Keep the supplied storage valid for the lifetime of the semaphore.

Example: Static Binary Semaphore

#include "FreeRTOS.h"
#include "semphr.h"

static StaticSemaphore_t xBinarySemaphoreStorage;
static SemaphoreHandle_t xBinarySemaphore;

void CreateSemaphore(void)
{
    xBinarySemaphore =
        xSemaphoreCreateBinaryStatic(
            &xBinarySemaphoreStorage
        );

    if (xBinarySemaphore == NULL)
    {
        /* Handle creation failure */
    }
}
The static storage must not be a short-lived local variable. A global or static-duration object is commonly used so that the memory remains valid throughout the semaphore's lifetime.

4. Binary Semaphore Creation

FreeRTOS provides separate APIs for dynamic and static binary semaphore creation.

Dynamic API

SemaphoreHandle_t xSemaphoreCreateBinary(void);

Static API

SemaphoreHandle_t xSemaphoreCreateBinaryStatic(
    StaticSemaphore_t *pxSemaphoreBuffer
);

Initial State

A newly created binary semaphore is initially empty. Its count is zero, so a task cannot successfully take it until a token is given. 

xBinarySemaphore = xSemaphoreCreateBinary();

if (xBinarySemaphore != NULL)
{
    /* Initially empty */
    xSemaphoreGive(xBinarySemaphore);
}
Do not assume that a newly created binary semaphore is initially available. If the application needs an initially available token, it must explicitly give the semaphore after successful creation.

5. Counting Semaphore Creation

A counting semaphore is created by specifying its maximum count and initial count.

Dynamic API

SemaphoreHandle_t xSemaphoreCreateCounting(
    UBaseType_t uxMaxCount,
    UBaseType_t uxInitialCount
);

Static API

SemaphoreHandle_t xSemaphoreCreateCountingStatic(
    UBaseType_t uxMaxCount,
    UBaseType_t uxInitialCount,
    StaticSemaphore_t *pxSemaphoreBuffer
);

Example

SemaphoreHandle_t xCountingSemaphore;

void CreateCountingSemaphore(void)
{
    xCountingSemaphore =
        xSemaphoreCreateCounting(5, 2);

    if (xCountingSemaphore == NULL)
    {
        /* Creation failed */
    }
}

In this example:

  • Maximum count = 5.
  • Initial count = 2.
  • Two tokens are initially available.
  • The count cannot exceed five.

6. Mutex Creation

FreeRTOS provides dynamic and static APIs for normal mutexes.

Dynamic API

SemaphoreHandle_t xSemaphoreCreateMutex(void);

Static API

SemaphoreHandle_t xSemaphoreCreateMutexStatic(
    StaticSemaphore_t *pxMutexBuffer
);

Example

SemaphoreHandle_t xMutex;

void CreateMutex(void)
{
    xMutex = xSemaphoreCreateMutex();

    if (xMutex == NULL)
    {
        /* Handle creation failure */
    }
}
A newly created mutex is initially available. A task can take it to become the owner.

7. Recursive Mutex Creation

Recursive mutexes also support dynamic and static creation.

Dynamic API

SemaphoreHandle_t xSemaphoreCreateRecursiveMutex(void);

Static API

SemaphoreHandle_t xSemaphoreCreateRecursiveMutexStatic(
    StaticSemaphore_t *pxMutexBuffer
);

Example

SemaphoreHandle_t xRecursiveMutex;

void CreateRecursiveMutex(void)
{
    xRecursiveMutex =
        xSemaphoreCreateRecursiveMutex();

    if (xRecursiveMutex == NULL)
    {
        /* Handle creation failure */
    }
}

The recursive mutex must be used with xSemaphoreTakeRecursive() and xSemaphoreGiveRecursive().

8. Static vs Dynamic Allocation

Feature Dynamic Allocation Static Allocation
Memory source FreeRTOS heap Application-provided storage
Creation Dynamic creation API Static creation API
Heap dependency Requires suitable heap allocation Does not allocate object storage from FreeRTOS heap
Allocation failure Can fail due to insufficient heap memory Depends on application-provided storage and configuration
Memory planning Memory allocated at runtime Memory reserved by application
Typical use Flexible object creation Predictable memory layout
Embedded-system recommendation: Static allocation is useful when the application needs predictable memory usage and wants to avoid runtime heap allocation for kernel objects. It does not automatically guarantee that the entire application is deterministic or free from memory errors.

9. Configuration Requirements

Static and dynamic allocation are controlled by FreeRTOS configuration options. 

/* Example FreeRTOSConfig.h settings */

#define configSUPPORT_STATIC_ALLOCATION       1
#define configSUPPORT_DYNAMIC_ALLOCATION      1

Meaning

Configuration Meaning
configSUPPORT_STATIC_ALLOCATION Enables supported static creation APIs.
configSUPPORT_DYNAMIC_ALLOCATION Enables supported dynamic creation APIs.

If dynamic allocation is enabled, the project must include a suitable heap implementation and enough memory for the requested objects.

Exact configuration requirements and available APIs depend on the selected FreeRTOS kernel release. Check the matching kernel headers and documentation before configuring a project.

10. Deleting a Semaphore or Mutex

FreeRTOS provides vSemaphoreDelete() to delete a semaphore or mutex object. 

void vSemaphoreDelete(
    SemaphoreHandle_t xSemaphore
);

Example

SemaphoreHandle_t xSemaphore;

void DeleteSemaphore(void)
{
    if (xSemaphore != NULL)
    {
        vSemaphoreDelete(xSemaphore);
        xSemaphore = NULL;
    }
}

What Happens During Deletion?

  • The kernel object is deleted.
  • For a dynamically allocated object, its allocated memory is returned through the configured allocator.
  • For a statically allocated object, the application-provided storage remains allocated to the application.
  • The old handle must no longer be used.
Deleting a semaphore does not provide a safe shutdown protocol for tasks waiting on or using it. Coordinate all users first, ensure no task can access the object after deletion, and only then delete it.

11. Semaphore Lifecycle

A semaphore follows a lifecycle from creation to deletion. 

        Application Startup
                |
                v
        Declare Semaphore Handle
                |
                v
        Create Semaphore Object
                |
                v
        Check Creation Result
                |
                v
        Use Semaphore in Tasks
                |
                v
        Coordinate Application Shutdown
                |
                v
        Ensure No Active Users
                |
                v
        Delete Semaphore
                |
                v
             Finished

Lifecycle Stages

  1. Declaration: Define the handle variable.
  2. Creation: Allocate or supply object storage.
  3. Initialization: Establish the initial count or availability state.
  4. Operation: Tasks use take and give APIs.
  5. Shutdown: Stop users from accessing the object.
  6. Deletion: Delete the object when no longer needed.

12. Complete Example: Dynamic Binary Semaphore Lifecycle

Objective

To create a binary semaphore, use it for task synchronization, and delete it during a coordinated shutdown.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xBinarySemaphore;

void ProducerTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulate an event */

        if (xSemaphoreGive(xBinarySemaphore) != pdTRUE)
        {
            /* Semaphore may already contain a token */
        }

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void ConsumerTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xBinarySemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            /* Process the signaled event */
        }
    }
}

int main(void)
{
    xBinarySemaphore = xSemaphoreCreateBinary();

    if (xBinarySemaphore == NULL)
    {
        for (;;);
    }

    xTaskCreate(ProducerTask,
                "Producer",
                256,
                NULL,
                2,
                NULL);

    xTaskCreate(ConsumerTask,
                "Consumer",
                256,
                NULL,
                2,
                NULL);

    vTaskStartScheduler();

    for (;;);
}

Program Explanation

  • The binary semaphore is created before the tasks.
  • The producer periodically gives the semaphore.
  • The consumer waits for a token.
  • The consumer processes the event after a successful take.
  • The semaphore synchronizes the two tasks.
This example demonstrates normal operation. It does not delete the semaphore because the scheduler and tasks run continuously. A real shutdown design must stop or coordinate all users before deletion.

13. Common Programming Errors

  1. Not checking the returned handle: Creation can fail. Check for NULL.
  2. Using an uninitialized handle: Create the object before passing its handle to kernel APIs.
  3. Incorrect initial count: Counting semaphore initial count must not exceed its maximum.
  4. Insufficient heap: Dynamic creation can fail when memory is unavailable.
  5. Invalid static storage lifetime: Do not use temporary local storage for a long-lived object.
  6. Deleting an active object: Stop and coordinate all users before deletion.
  7. Using a deleted handle: Do not use a handle after its object has been deleted.
  8. Mixing allocation methods: Use the correct creation API for the selected allocation method.

14. Practical Experiment

Objective

To compare dynamic and static creation of a FreeRTOS binary semaphore.

Experiment A: Dynamic Creation

  1. Declare a SemaphoreHandle_t.
  2. Call xSemaphoreCreateBinary().
  3. Check whether the returned handle is NULL.
  4. Use the semaphore in a task.

Experiment B: Static Creation

  1. Declare a StaticSemaphore_t storage object.
  2. Call xSemaphoreCreateBinaryStatic().
  3. Check the returned handle.
  4. Use the semaphore in a task.

Expected Result

  • Both methods create a binary semaphore when correctly configured.
  • The dynamic method uses the FreeRTOS heap.
  • The static method uses application-provided storage.
  • Both can be used with the normal binary semaphore APIs.

16. Lesson Summary

  • FreeRTOS synchronization objects are accessed through handles.
  • Dynamic allocation obtains object memory from the FreeRTOS heap.
  • Static allocation uses application-provided storage.
  • Binary, counting, mutex, and recursive mutex objects have different creation APIs.
  • Creation results should be checked before use.
  • vSemaphoreDelete() deletes semaphore and mutex objects.
  • Static object storage remains application-owned after deletion.
  • All tasks must stop using an object before it is deleted.
