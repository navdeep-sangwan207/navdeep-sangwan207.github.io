Lesson 09 – Mutex and Semaphore Programming

Lesson Overview

FreeRTOS applications often use multiple synchronization objects to coordinate task execution and protect shared resources. Semaphores are useful for event signaling and counting available tokens, while mutexes provide exclusive ownership of shared resources between tasks.

This lesson combines these mechanisms in practical programming examples involving task synchronization, resource protection, producer-consumer systems, and interrupt notification.

Learning Objectives

  • Combine mutexes and semaphores in FreeRTOS programs.
  • Protect shared resources using mutexes.
  • Use binary semaphores for task synchronization.
  • Use counting semaphores for resource counting.
  • Understand producer-consumer synchronization.
  • Coordinate tasks using multiple synchronization objects.
  • Identify deadlock and resource ownership problems.
  • Apply practical RTOS programming conventions.

1. Choosing the Correct Synchronization Object

ObjectMain PurposeTypical Application
Binary semaphoreEvent notification and task synchronizationNotify a task that an event occurred
Counting semaphoreCount available tokens or pending eventsTrack a limited number of available resources
MutexProtect a shared resourcePrevent simultaneous task access to a shared UART
QueueTransfer data between tasksSend sensor readings to a processing task
A semaphore does not automatically protect a shared data structure. Use a mutex for task-level mutual exclusion or a queue with a clear ownership model when transferring data.

2. Program 1 – Shared Resource Protection Using a Mutex

Objective

Allow two tasks to access a shared variable safely using a mutex.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xMutex;
int sharedCounter = 0;

void Task1(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xMutex,
                portMAX_DELAY) == pdTRUE)
        {
            sharedCounter++;

            /* Protected operation */

            xSemaphoreGive(xMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void Task2(void *pvParameters)
{
    int localValue;

    for (;;)
    {
        if (xSemaphoreTake(
                xMutex,
                portMAX_DELAY) == pdTRUE)
        {
            localValue = sharedCounter;

            /* Use protected value */

            (void)localValue;

            xSemaphoreGive(xMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(150));
    }
}

int main(void)
{
    xMutex = xSemaphoreCreateMutex();

    if (xMutex == NULL)
    {
        for (;;);
    }

    xTaskCreate(Task1, "Task1", 256, NULL, 2, NULL);
    xTaskCreate(Task2, "Task2", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;);
}

Expected Result

  • Both tasks share the same counter.
  • Only one task accesses the protected section at a time.
  • The mutex is released after each protected operation.
  • The counter is updated without simultaneous task access.
The shared counter is protected only when every task that accesses it follows the same mutex protocol. An unprotected access elsewhere would still create a race condition.

3. Program 2 – Binary Semaphore for Task Synchronization

Objective

Use a binary semaphore to notify a consumer task when a producer task has completed an operation.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xBinarySemaphore;

void ProducerTask(void *pvParameters)
{
    for (;;)
    {
        /* Perform event-producing operation */

        if (xSemaphoreGive(xBinarySemaphore) != pdTRUE)
        {
            /* A token may already be pending */
        }

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void ConsumerTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xBinarySemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            /* Process notification */
        }
    }
}

int main(void)
{
    xBinarySemaphore = xSemaphoreCreateBinary();

    if (xBinarySemaphore == NULL)
    {
        for (;;);
    }

    xTaskCreate(ProducerTask, "Producer", 256, NULL, 2, NULL);
    xTaskCreate(ConsumerTask, "Consumer", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;);
}

Expected Result

  • The consumer initially waits for a semaphore token.
  • The producer gives the semaphore periodically.
  • The consumer becomes Ready and processes the notification.
  • The consumer waits again for the next token.
A binary semaphore stores at most one pending token. If the producer gives it repeatedly while it is already full, additional events are not accumulated. Use a counting semaphore or queue if every event must be retained.

4. Program 3 – Counting Semaphore for Resource Management

Objective

Use a counting semaphore to represent a limited number of identical available resources.

Example Scenario

Assume an application has three identical communication channels. A task must obtain one available channel before using it and return the token when finished.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xResourceSemaphore;

void ResourceTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xResourceSemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            /* One availability token obtained. */

            /* Use an allocated resource. */

            xSemaphoreGive(xResourceSemaphore);
        }

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

int main(void)
{
    xResourceSemaphore =
        xSemaphoreCreateCounting(3, 3);

    if (xResourceSemaphore == NULL)
    {
        for (;;);
    }

    xTaskCreate(ResourceTask, "Resource1", 256, NULL, 2, NULL);
    xTaskCreate(ResourceTask, "Resource2", 256, NULL, 2, NULL);
    xTaskCreate(ResourceTask, "Resource3", 256, NULL, 2, NULL);
    xTaskCreate(ResourceTask, "Resource4", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;);
}

Expected Result

  • The semaphore begins with three available tokens.
  • At most three tasks can hold tokens simultaneously.
  • A fourth task waits until a token is returned.
  • When a task gives the semaphore, another waiting task may proceed.
A counting semaphore tracks the number of available tokens. It does not identify which physical channel a task owns. A real resource pool also needs an allocation mechanism, such as a protected free-list or queue of resource identifiers. Only the task that successfully obtained a resource token should return it.

5. Program 4 – Producer-Consumer Using a Mutex and Counting Semaphores

Objective

Implement a bounded shared buffer using:

  • An empty counting semaphore to count free slots.
  • A full counting semaphore to count occupied slots.
  • A mutex to protect buffer operations.

Initial Configuration

ObjectInitial ValuePurpose
empty5Five free buffer slots
full0No occupied slots
mutexAvailableProtect buffer indexes and data

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

#define BUFFER_SIZE 5

int buffer[BUFFER_SIZE];
int writeIndex = 0;
int readIndex = 0;

SemaphoreHandle_t xEmpty;
SemaphoreHandle_t xFull;
SemaphoreHandle_t xBufferMutex;

void ProducerTask(void *pvParameters)
{
    int item = 0;

    for (;;)
    {
        if (xSemaphoreTake(
                xEmpty,
                portMAX_DELAY) == pdTRUE)
        {
            if (xSemaphoreTake(
                    xBufferMutex,
                    portMAX_DELAY) == pdTRUE)
            {
                buffer[writeIndex] = item;
                writeIndex = (writeIndex + 1) % BUFFER_SIZE;
                item++;

                xSemaphoreGive(xBufferMutex);

                xSemaphoreGive(xFull);
            }
            else
            {
                /* Recover the reserved empty-slot token. */
                xSemaphoreGive(xEmpty);
            }
        }

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

void ConsumerTask(void *pvParameters)
{
    int item;

    for (;;)
    {
        if (xSemaphoreTake(
                xFull,
                portMAX_DELAY) == pdTRUE)
        {
            if (xSemaphoreTake(
                    xBufferMutex,
                    portMAX_DELAY) == pdTRUE)
            {
                item = buffer[readIndex];
                readIndex = (readIndex + 1) % BUFFER_SIZE;

                xSemaphoreGive(xBufferMutex);

                xSemaphoreGive(xEmpty);

                /* Process item outside the critical section. */
                (void)item;
            }
            else
            {
                /* Restore the reserved full-slot token. */
                xSemaphoreGive(xFull);
            }
        }

        vTaskDelay(pdMS_TO_TICKS(300));
    }
}

int main(void)
{
    xEmpty = xSemaphoreCreateCounting(
        BUFFER_SIZE, BUFFER_SIZE);

    xFull = xSemaphoreCreateCounting(
        BUFFER_SIZE, 0);

    xBufferMutex = xSemaphoreCreateMutex();

    if (xEmpty == NULL ||
        xFull == NULL ||
        xBufferMutex == NULL)
    {
        for (;;);
    }

    xTaskCreate(ProducerTask, "Producer", 256, NULL, 2, NULL);
    xTaskCreate(ConsumerTask, "Consumer", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;);
}

Expected Result

  • The producer waits when the buffer has no free slots.
  • The consumer waits when the buffer has no stored items.
  • The mutex protects the buffer indexes and data operations.
  • The producer gives full after inserting an item.
  • The consumer gives empty after removing an item.
  • The circular indexes wrap around the buffer.
The producer and consumer acquire the counting semaphore before the mutex. Both release the mutex before updating the opposite counting semaphore. This keeps the protected buffer operation short and avoids holding the mutex while notifying the other task.

6. Program 5 – Protecting a Shared UART Using a Mutex

Objective

Prevent two tasks from interleaving output through the same UART transmit interface.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xUARTMutex;

/* Replace with the actual UART driver function. */
void UART_WriteString(const char *message);

void TaskA(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xUARTMutex,
                portMAX_DELAY) == pdTRUE)
        {
            UART_WriteString("Task A message\r\n");

            xSemaphoreGive(xUARTMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xUARTMutex,
                portMAX_DELAY) == pdTRUE)
        {
            UART_WriteString("Task B message\r\n");

            xSemaphoreGive(xUARTMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(700));
    }
}

int main(void)
{
    xUARTMutex = xSemaphoreCreateMutex();

    if (xUARTMutex == NULL)
    {
        for (;;);
    }

    /* Initialize the UART driver before task execution. */

    xTaskCreate(TaskA, "UART_A", 256, NULL, 2, NULL);
    xTaskCreate(TaskB, "UART_B", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;);
}

Expected Result

  • Task A and Task B share the UART transmitter.
  • The mutex allows only one task to own the UART resource at a time.
  • Each message is transmitted within one protected operation.
  • Messages from the two tasks do not interleave at the task level.
The example assumes the UART driver operation is safe to call in task context and completes according to its documented behavior. For asynchronous DMA or interrupt-driven transmission, the mutex alone does not protect the lifetime of transmit buffers or indicate when hardware transmission has completed. Use a driver ownership protocol, queue, or completion notification as appropriate.

7. Program 6 – ISR Notification with a Binary Semaphore

Objective

Notify a task when a hardware interrupt occurs.

Generic ISR Structure

SemaphoreHandle_t xEventSemaphore;

void Peripheral_IRQHandler(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    /* Acknowledge the peripheral interrupt. */

    xSemaphoreGiveFromISR(
        xEventSemaphore,
        &xHigherPriorityTaskWoken
    );

    /* Use the ISR-yield mechanism required by
       the selected FreeRTOS port. */
}

void EventTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xEventSemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            /* Process the event in task context. */
        }
    }
}

Expected Result

  • The task waits for an interrupt notification.
  • The ISR gives the semaphore without blocking.
  • The task becomes Ready when notified.
  • Longer processing occurs in task context.
The ISR-yield mechanism and interrupt priority restrictions are port-specific. Do not use Cortex-M NVIC or BASEPRI assumptions for the LPC2129 ARM7TDMI-S architecture.

8. Important Resource Management Rules

  1. Always check whether semaphore and mutex creation succeeded.
  2. Check the return value of take and give operations.
  3. Release a mutex after completing the protected operation.
  4. Do not give a mutex from a task that does not own it.
  5. Never use mutex APIs from an ISR.
  6. Keep mutex-protected sections short.
  7. Use a consistent resource acquisition order.
  8. Do not assume a counting semaphore identifies a particular resource.
  9. Use a queue when the application needs to transfer data.
  10. Define a recovery strategy for resource allocation failures.
  11. Do not delete synchronization objects while tasks are using or waiting on them.

9. Common Programming Mistakes

MistakePossible ConsequenceCorrect Approach

Holding a mutex during long processingIncreased blocking timeKeep the critical section short

Procedure

  4. Create a counting semaphore with an initial count of three.

Expected Result

  • The binary semaphore signals an event.

12. Lesson Summary

  • Mutexes protect shared resources between tasks.
  • Binary semaphores provide event notification and synchronization.
  • Counting semaphores represent available tokens or pending event counts.
  • Queues transfer data between tasks.
  • Producer-consumer systems can use empty and full counting semaphores with a mutex.
  • Mutex ownership must be maintained correctly.
  • Priority inheritance is associated with FreeRTOS mutexes.
  • ISRs must use ISR-specific APIs and must never block.
  • Resource ownership, buffer lifetime, and error handling are essential in practical systems.
