Chapter 17: FreeRTOS Event Groups and Software Timers

Lesson 07 – Starting, Stopping and Resetting Software Timers

RTOS & FreeRTOS Chapter Index Learning Portal

Lesson Overview

After creating a software timer, an application must control its operation. FreeRTOS provides timer API functions to start, stop, reset, and change the period of a timer.

These functions submit commands to the timer service task through the timer command queue. Understanding their behavior is important for implementing reliable timeout and periodic operations.

Learning Objectives

  • Understand xTimerStart().
  • Understand xTimerStop().
  • Understand xTimerReset().
  • Understand xTimerChangePeriod().
  • Learn the role of the command queue and block time.
  • Understand timer command return values.
  • Develop a timer-control application.

1. Timer Control Functions

FreeRTOS provides several functions for controlling a timer after it has been created.

FunctionPurpose
xTimerStart()Starts a dormant timer.
xTimerStop()Stops an active timer.
xTimerReset()Restarts the timer period from the command's processing time.
xTimerChangePeriod()Changes the timer period and starts or restarts its countdown.
xTimerDelete()Requests deletion of a timer.
These task-context APIs submit commands to the timer command queue. The timer service task processes the commands later. A successful return indicates that the command was accepted into the queue, not necessarily that the timer state has already changed.

2. xTimerStart() Function

The xTimerStart() function submits a command to start a timer. It is used to activate a newly created timer or start a timer that is currently stopped.

Function Prototype

BaseType_t xTimerStart(
    TimerHandle_t xTimer,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xTimerHandle of the timer to start.
xTicksToWaitMaximum time the calling task waits for space in the timer command queue.

Return Value

  • pdPASS: Start command successfully entered the timer command queue.
  • pdFAIL: Command could not be queued within the allowed time.

Example

if (xTimerStart(xStatusTimer, 0) == pdPASS)
{
    /* Start command accepted */
}
else
{
    /* Timer command queue was unavailable */
}

A block time of zero means the task does not wait for queue space.

3. xTimerStop() Function

The xTimerStop() function submits a command to stop an active timer. A stopped timer does not generate further expirations until it is started again.

Function Prototype

BaseType_t xTimerStop(
    TimerHandle_t xTimer,
    TickType_t xTicksToWait
);

Example

if (xTimerStop(xStatusTimer, 0) == pdPASS)
{
    /* Stop command accepted */
}
else
{
    /* Handle queue submission failure */
}

Applications

  • Stop a communication timeout after receiving a valid response.
  • Stop periodic monitoring when a system enters maintenance mode.
  • Stop a temporary notification timer after the required action.
A callback already executing cannot be cancelled by merely submitting a stop command. The command affects timer processing when it is handled by the timer service task.

4. xTimerReset() Function

The xTimerReset() function restarts the timer's countdown. The timer's expiry is recalculated from the time at which the reset command is processed by the timer service task.

Function Prototype

BaseType_t xTimerReset(
    TimerHandle_t xTimer,
    TickType_t xTicksToWait
);

Example

if (xTimerReset(xCommunicationTimer, 0) == pdPASS)
{
    /* Reset command accepted */
}

Example – Communication Timeout

Assume a communication timeout timer has a period of five seconds. Whenever valid data is received, the application resets the timer. 

void OnValidDataReceived(void)
{
    xTimerReset(xCommunicationTimer, 0);
}

If the timer expires without another reset, its callback can notify the application that communication has timed out.

Resetting a timer does not change its configured period. It restarts the countdown using the existing period. The timer command queue processing time, rather than the exact time the application called the function, determines the reset point.

5. xTimerChangePeriod() Function

The xTimerChangePeriod() function changes a timer's period. Processing the command also starts or restarts the timer using the new period.

Function Prototype

BaseType_t xTimerChangePeriod(
    TimerHandle_t xTimer,
    TickType_t xNewPeriod,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xTimerTimer handle.
xNewPeriodNew timer period in ticks; it must be nonzero.
xTicksToWaitMaximum time to wait for command queue space.

Example

if (xTimerChangePeriod(
        xStatusTimer,
        pdMS_TO_TICKS(2000),
        0) == pdPASS)
{
    /* New period command accepted */
}

This example requests a new two-second period. When the command is processed, the timer countdown uses the new period.

6. xTimerDelete() Function

The xTimerDelete() function submits a command to delete a timer object.

Function Prototype

BaseType_t xTimerDelete(
    TimerHandle_t xTimer,
    TickType_t xTicksToWait
);

Example

if (xTimerDelete(xStatusTimer, 0) == pdPASS)
{
    /* Delete command accepted */
    xStatusTimer = NULL;
}
The command is processed asynchronously. Do not assume the timer has already been deleted merely because the command was accepted. Coordinate access to the handle so that other tasks do not submit commands using a timer that is being deleted.

7. Understanding xTicksToWait

The xTicksToWait parameter specifies how long the calling task is prepared to wait for space in the timer command queue. It does not specify the timer period or the timer's expiry time.

ValueMeaning
0Do not block if the command queue is full.
Finite valueWait for the specified number of ticks for queue space.
portMAX_DELAYRequest the longest supported wait; indefinite blocking depends on configuration.

Example

BaseType_t result;

result = xTimerStart(
    xStatusTimer,
    pdMS_TO_TICKS(100)
);

if (result == pdPASS)
{
    /* Command accepted */
}
else
{
    /* Queue submission failed */
}
Do not use a long queue block time from a task that must meet a strict response deadline without considering the possible delay. Choose the queue wait time according to the application's scheduling requirements.

8. Timer Command Queue

Timer control functions generally communicate with the timer service task through a command queue. 

Application Task
      |
      | xTimerStart()
      | xTimerStop()
      | xTimerReset()
      | xTimerChangePeriod()
      v
Timer Command Queue
      |
      v
Timer Service Task
      |
      v
Timer State Updated

If the command queue is full, a command may fail when the specified block time is insufficient to obtain queue space.

Important Configuration

#define configUSE_TIMERS          1
#define configTIMER_QUEUE_LENGTH  10

The queue length should be selected according to the expected number and frequency of timer commands.

9. Complete Program – Communication Timeout Control

Objective

Create a five-second one-shot communication timeout timer. Start it when communication begins, reset it whenever valid data is received, and stop it when communication completes.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "timers.h"

static TimerHandle_t xCommunicationTimer;

void CommunicationTimeoutCallback(TimerHandle_t xTimer)
{
    /* Notify the application that communication timed out */
}

void CommunicationTask(void *pvParameters)
{
    /* Start the timeout period */
    if (xTimerStart(xCommunicationTimer, 0) != pdPASS)
    {
        /* Handle command submission failure */
    }

    for (;;)
    {
        /*
         * Application-specific communication handling
         *
         * When valid data is received:
         * xTimerReset(xCommunicationTimer, 0);
         *
         * When communication completes:
         * xTimerStop(xCommunicationTimer, 0);
         */

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void)
{
    xCommunicationTimer = xTimerCreate(
        "CommTimeout",
        pdMS_TO_TICKS(5000),
        pdFALSE,
        NULL,
        CommunicationTimeoutCallback
    );

    if (xCommunicationTimer == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        CommunicationTask,
        "Communication",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    ) != pdPASS)
    {
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Create a one-shot timer with a five-second period.
  2. Define the timeout callback.
  3. Create the communication task.
  4. Start the timer when communication begins.
  5. Reset the timer when valid communication data arrives.
  6. Stop the timer when communication completes.
  7. If the timer expires, the callback notifies the application.
The communication receive logic is intentionally represented as an application-specific placeholder. In a complete project, use a queue, task notification, or another suitable mechanism to deliver received-data events to the communication task. Do not perform lengthy communication processing inside the timer callback.

11. Common Programming Errors

ErrorCorrection
Assuming a command executes immediatelyRemember that the timer service task processes queued commands.
Ignoring a failed command submissionCheck the returned BaseType_t.
Confusing reset with change-periodReset keeps the existing period; change-period uses a new period.
Using zero as a new periodSpecify a positive period.
Assuming stop cancels an executing callbackAccount for callback execution and command processing.
Using a timer handle after deletionCoordinate ownership and invalidate application references safely.
Ignoring timer command queue capacityConfigure sufficient queue capacity and handle failures.

14. Lesson Summary

  • xTimerStart() starts a timer.
  • xTimerStop() stops a timer.
  • xTimerReset() restarts the countdown using the existing period.
  • xTimerChangePeriod() changes the period and restarts the countdown.
  • xTimerDelete() requests deletion.
  • xTicksToWait controls waiting for command queue space.
  • Timer commands are processed by the timer service task.
  • Check the return value of every timer command.
  • Successful queue submission does not mean the command has already executed.
