Chapter 17: FreeRTOS Event Groups and Software Timers

Lesson 02 – xEventGroupCreate() Function

RTOS & FreeRTOS Chapter Index Learning Portal

Lesson Overview

The xEventGroupCreate() function dynamically creates a FreeRTOS event group. The returned event-group handle is used by tasks to set, clear, read, and wait for event bits.

Learning Objectives

  • Understand the purpose of xEventGroupCreate().
  • Understand the function prototype and return value.
  • Learn how to declare and use an event-group handle.
  • Understand dynamic and static event-group allocation.
  • Check event-group creation failure.
  • Develop a basic event-group initialization program.

1. What Is xEventGroupCreate()?

FreeRTOS requires an event-group object before an application can use event-group operations. The function xEventGroupCreate() creates this object using the FreeRTOS memory allocator. 

EventGroupHandle_t xEventGroupCreate(void);

The function returns a handle that identifies the created event group. Application tasks use this handle when calling event-group APIs.

The event group is initially created with all application event bits cleared. Its initial event-bit pattern is therefore zero.

2. Header Files

Include the required FreeRTOS headers:

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"
HeaderPurpose

3. EventGroupHandle_t Data Type

The returned event-group handle is stored using the EventGroupHandle_t type. 

EventGroupHandle_t xEventGroup;

This variable stores a reference to the event-group object. It is not the event group's internal data structure.

Basic Creation

EventGroupHandle_t xEventGroup;

xEventGroup = xEventGroupCreate();

After successful creation, xEventGroup can be passed to other event-group APIs.

Do not use an uninitialized or NULL event-group handle. Check the creation result before passing the handle to other APIs.

4. Return Value and Error Handling

Return ValueMeaning
Valid event-group handleEvent-group creation succeeded.
NULLCreation failed, commonly because the required memory was unavailable.

Recommended Creation Pattern

EventGroupHandle_t xEventGroup;

xEventGroup = xEventGroupCreate();

if (xEventGroup == NULL)
{
    /* Event-group creation failed */
    ErrorHandler();
}
else
{
    /* Event-group created successfully */
}

The application should define an appropriate failure policy, such as reporting an error, entering a safe state, or stopping initialization.

5. Dynamic Memory Allocation

The xEventGroupCreate() function uses the FreeRTOS heap to allocate memory for the event-group object.

Dynamic allocation must be enabled in the FreeRTOS configuration: 

#define configSUPPORT_DYNAMIC_ALLOCATION 1

The selected FreeRTOS heap implementation must also be included and configured correctly.

Memory Considerations

  • Event-group creation consumes heap memory.
  • Creation can fail when insufficient memory is available.
  • Repeated creation and deletion should be managed carefully.
  • Memory usage depends on the kernel version, port, and data types.
  • Use static allocation when predictable, application-controlled memory is required.
The total FreeRTOS heap is not necessarily the same as the complete RAM available to the application. Stack, global variables, heap, and other memory regions must be considered separately.

6. Static Event Group Allocation

FreeRTOS also supports static event-group creation through xEventGroupCreateStatic() when static allocation support is enabled. 

StaticEventGroup_t xEventGroupBuffer;
EventGroupHandle_t xEventGroup;

xEventGroup = xEventGroupCreateStatic(&xEventGroupBuffer);

if (xEventGroup == NULL)
{
    /* Handle creation failure */
}

Required Configuration

#define configSUPPORT_STATIC_ALLOCATION 1

The application supplies storage for the event-group control structure. The exact type and API availability should be checked against the selected FreeRTOS release.

Dynamic CreationStatic Creation
xEventGroupCreate()xEventGroupCreateStatic()
Kernel allocator obtains memory.Application supplies memory.
Can fail due to heap exhaustion.Does not need heap allocation for this object.
Requires dynamic allocation support.Requires static allocation support.

Static allocation does not mean the object can never be deleted. The application remains responsible for object lifetime and must not reuse its storage while the event group is still in use.

7. Complete Program – Creating an Event Group

Objective

Create an event group during application initialization and check whether its creation succeeds.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

EventGroupHandle_t xSystemEvents;

int main(void)
{
    /* Create an event group */
    xSystemEvents = xEventGroupCreate();

    if (xSystemEvents == NULL)
    {
        /* Creation failed */
        for (;;)
        {
            /* Remain in error state */
        }
    }

    /* Create application tasks here */

    vTaskStartScheduler();

    /* Reached only if scheduler startup fails */
    for (;;)
    {
    }
}

Program Explanation

  1. Include the required FreeRTOS header files.
  2. Declare an event-group handle.
  3. Call xEventGroupCreate().
  4. Check whether the returned handle is NULL.
  5. Continue initialization only after successful creation.
  6. Start the scheduler after creating the required application tasks.

Expected Result

If sufficient memory is available and dynamic allocation is configured correctly, the event group is created and the application continues initialization.

If creation fails, the application enters its error-handling path.

8. Program – Static Event Group Creation

Objective

Create an event group using application-provided storage.

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

static StaticEventGroup_t xSystemEventStorage;
static EventGroupHandle_t xSystemEvents;

int main(void)
{
    xSystemEvents =
        xEventGroupCreateStatic(&xSystemEventStorage);

    if (xSystemEvents == NULL)
    {
        for (;;)
        {
            /* Handle failure */
        }
    }

    /* Create tasks and initialize application */

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Expected Result

The event group is initialized using the storage supplied by the application, provided static allocation is enabled and the selected FreeRTOS implementation supports the API.

11. Lesson Summary

  • xEventGroupCreate() dynamically creates an event group.
  • The returned handle has the type EventGroupHandle_t.
  • A successful creation returns a valid handle.
  • A NULL return value indicates creation failure.
  • Dynamic creation requires dynamic allocation support and sufficient heap memory.
  • xEventGroupCreateStatic() uses application-provided storage.
  • Check object creation before using the handle.
  • Event-group operations are declared in event_groups.h.
