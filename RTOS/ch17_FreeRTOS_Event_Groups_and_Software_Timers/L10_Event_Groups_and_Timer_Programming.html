Lesson Overview

This lesson combines FreeRTOS event groups, software timers, timer callbacks, and task notifications through integrated programming examples. It focuses on applying the concepts introduced in the previous lessons to practical embedded software designs.

Learning Objectives

  • Combine multiple event conditions using event groups.
  • Use software timers to generate periodic events.
  • Coordinate tasks using event bits.
  • Use timer callbacks to signal application tasks.
  • Understand command queue and callback limitations.
  • Debug common event-group and timer programming errors.
  • Design a small event-driven monitoring application.

1. Revision of Event Groups

An event group is a synchronization object containing multiple event bits. Tasks can set, clear, and wait for selected bits.

APIPurpose
xEventGroupCreate()Create an event group dynamically.
xEventGroupSetBits()Set selected event bits.
xEventGroupClearBits()Clear selected event bits.
xEventGroupWaitBits()Wait for one or more event conditions.
xEventGroupGetBits()Read the current event-bit snapshot.

Example Event Bits

#define EVENT_SENSOR_READY   (1U << 0)
#define EVENT_DATA_READY     (1U << 1)
#define EVENT_COMM_READY     (1U << 2)

Each bit represents an application-defined condition. Event groups carry condition information, not a data queue or event counter. Repeatedly setting an already-set bit does not count multiple occurrences.

2. Revision of Software Timers

A software timer allows an application to execute a callback after a configured period.

Timer TypeBehavior
One-shotExpires once and becomes inactive.
Auto-reloadExpires repeatedly while active.

Timer Creation

xTimerCreate(
    "TimerName",
    pdMS_TO_TICKS(1000),
    pdTRUE,
    NULL,
    TimerCallback
);

The timer is created but not started. The application must submit a start command using xTimerStart().

4. Program 1 – Event Group with Multiple Conditions

Objective

Create an event group and make a task wait until sensor and communication conditions are both ready.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

#define SENSOR_READY_BIT   (1U << 0)
#define COMM_READY_BIT     (1U << 1)

static EventGroupHandle_t xSystemEvents;

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulate sensor initialization */
        xEventGroupSetBits(
            xSystemEvents,
            SENSOR_READY_BIT
        );

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void CommunicationTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulate communication initialization */
        xEventGroupSetBits(
            xSystemEvents,
            COMM_READY_BIT
        );

        vTaskDelay(pdMS_TO_TICKS(1500));
    }
}

void MonitorTask(void *pvParameters)
{
    EventBits_t result;

    for (;;)
    {
        result = xEventGroupWaitBits(
            xSystemEvents,
            SENSOR_READY_BIT | COMM_READY_BIT,
            pdFALSE,
            pdTRUE,
            portMAX_DELAY
        );

        if ((result &
             (SENSOR_READY_BIT | COMM_READY_BIT)) ==
             (SENSOR_READY_BIT | COMM_READY_BIT))
        {
            /* Both conditions are satisfied */
        }

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

int main(void)
{
    xSystemEvents = xEventGroupCreate();

    if (xSystemEvents == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        SensorTask, "Sensor",
        configMINIMAL_STACK_SIZE,
        NULL, 2, NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        CommunicationTask, "Communication",
        configMINIMAL_STACK_SIZE,
        NULL, 2, NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        MonitorTask, "Monitor",
        configMINIMAL_STACK_SIZE,
        NULL, 3, NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Create an event group.
  2. Create sensor and communication tasks.
  3. Each task sets its corresponding event bit.
  4. The monitoring task waits for both bits.
  5. When both conditions are satisfied, monitoring can proceed.
The example keeps both bits set after initialization. It therefore models persistent readiness conditions, not individual recurring sensor or communication events. Use queues or notifications when each occurrence must be recorded separately.

5. Program 2 – Software Timer Sets an Event Bit

Objective

Create an auto-reload timer. Its callback sets an event bit when the timer expires. A worker task waits for that event.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"
#include "timers.h"

#define TIMER_EVENT_BIT (1U << 0)

static EventGroupHandle_t xEvents;
static TimerHandle_t xTimer;

void TimerCallback(TimerHandle_t xTimerHandle)
{
    /* Callback executes in timer service task context */
    xEventGroupSetBits(
        xEvents,
        TIMER_EVENT_BIT
    );
}

void WorkerTask(void *pvParameters)
{
    EventBits_t bits;

    for (;;)
    {
        bits = xEventGroupWaitBits(
            xEvents,
            TIMER_EVENT_BIT,
            pdTRUE,
            pdFALSE,
            portMAX_DELAY
        );

        if ((bits & TIMER_EVENT_BIT) != 0)
        {
            /* Process the timer event */
        }
    }
}

int main(void)
{
    xEvents = xEventGroupCreate();

    if (xEvents == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        WorkerTask,
        "Worker",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    ) != pdPASS)
    {
        for (;;)
        {
        }
    }

    xTimer = xTimerCreate(
        "MonitorTimer",
        pdMS_TO_TICKS(2000),
        pdTRUE,
        NULL,
        TimerCallback
    );

    if (xTimer == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTimerStart(xTimer, 0) != pdPASS)
    {
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Create an event group.
  2. Create a worker task.
  3. Create a two-second auto-reload timer.
  4. Start the timer.
  5. When the timer expires, its callback sets the event bit.
  6. The worker task becomes Ready when the event condition is met.
  7. The worker clears the event bit on successful exit from the wait.
  8. The timer repeats while active.
The callback runs in the timer service task, so xEventGroupSetBits() is a task-context API here. Do not replace it with an ISR API merely because the callback is triggered by timer expiry.

6. Program 3 – Multiple Event Bits with Timer Control

Objective

Use an event group to represent three application conditions: sensor ready, communication ready, and periodic timer event. The monitoring task waits until all three conditions are set.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"
#include "timers.h"

#define SENSOR_READY_BIT   (1U << 0)
#define COMM_READY_BIT     (1U << 1)
#define TIMER_EVENT_BIT    (1U << 2)

#define ALL_EVENTS (SENSOR_READY_BIT | \
                    COMM_READY_BIT  | \
                    TIMER_EVENT_BIT)

static EventGroupHandle_t xEvents;
static TimerHandle_t xTimer;

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulated sensor-ready condition */
        xEventGroupSetBits(
            xEvents,
            SENSOR_READY_BIT
        );

        vTaskDelay(pdMS_TO_TICKS(5000));
    }
}

void CommunicationTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulated communication-ready condition */
        xEventGroupSetBits(
            xEvents,
            COMM_READY_BIT
        );

        vTaskDelay(pdMS_TO_TICKS(5000));
    }
}

void TimerCallback(TimerHandle_t xTimerHandle)
{
    xEventGroupSetBits(
        xEvents,
        TIMER_EVENT_BIT
    );
}

void MonitorTask(void *pvParameters)
{
    EventBits_t bits;

    for (;;)
    {
        bits = xEventGroupWaitBits(
            xEvents,
            ALL_EVENTS,
            pdTRUE,
            pdTRUE,
            portMAX_DELAY
        );

        if ((bits & ALL_EVENTS) == ALL_EVENTS)
        {
            /* All three conditions were satisfied */
        }
    }
}

int main(void)
{
    xEvents = xEventGroupCreate();

    if (xEvents == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        SensorTask, "Sensor",
        configMINIMAL_STACK_SIZE,
        NULL, 2, NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        CommunicationTask, "Comm",
        configMINIMAL_STACK_SIZE,
        NULL, 2, NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
        MonitorTask, "Monitor",
        configMINIMAL_STACK_SIZE,
        NULL, 3, NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    xTimer = xTimerCreate(
        "Periodic",
        pdMS_TO_TICKS(2000),
        pdTRUE,
        NULL,
        TimerCallback
    );

    if (xTimer == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTimerStart(xTimer, 0) != pdPASS)
    {
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Define three event bits.
  2. Create the event group.
  3. Create sensor, communication, and monitoring tasks.
  4. Create and start the periodic timer.
  5. Sensor and communication tasks set their readiness bits.
  6. The timer callback sets the timer event bit.
  7. The monitoring task waits until all three bits are set.
  8. With clear-on-exit enabled, the selected bits are cleared when the wait condition is satisfied.
This example demonstrates event synchronization. The sensor and communication tasks set their readiness bits repeatedly, but the bits represent persistent conditions and can coalesce. For a production design, define whether each bit means "initialized", "currently ready", or "new event received". Use queues or counting notifications when individual events must not be lost.

7. Timer Command Queue and Failure Handling

Timer commands are submitted asynchronously to the timer service task. A successful API return means the command was accepted into the command queue; it does not mean the command has already been processed.

Example

BaseType_t status;

status = xTimerStart(
    xTimer,
    pdMS_TO_TICKS(100)
);

if (status == pdPASS)
{
    /* Start command was queued successfully */
}
else
{
    /* Command could not be queued */
}

The wait parameter specifies how long the calling task may wait for space in the timer command queue. It is not the timer period and does not control callback execution time.

Design Considerations

  • Choose sufficient timer command queue capacity.
  • Check every timer command return value.
  • Consider bursts of commands from multiple tasks.
  • Keep callbacks short to prevent service-task delays.
  • Define recovery behavior when a command cannot be queued.

13. Important Technical Notes

  • Event groups represent conditions, not message storage.
  • Repeatedly setting an already-set bit does not count repeated events.
  • Multiple tasks can wait on the same event group.
  • Clear-on-exit can affect what other waiting tasks observe.
  • Software timers use the RTOS tick count.
  • Timer callbacks run in timer service task context.
  • Timer API commands are generally processed asynchronously.
  • Timer callbacks should not block.
  • Use queues or notifications to delegate application work.
  • Software timers are not a replacement for precision hardware timers.

14. Chapter 17 Summary

This chapter covered FreeRTOS event groups and software timers. Event groups allow tasks to synchronize using event bits, while software timers provide time-based application events. The timer service task manages timer commands and executes callbacks. Correct use of these mechanisms requires attention to callback execution time, queue capacity, scheduling, and event ownership.
