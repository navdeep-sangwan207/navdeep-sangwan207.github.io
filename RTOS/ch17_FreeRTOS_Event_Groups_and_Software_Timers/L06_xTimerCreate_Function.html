Chapter 17: FreeRTOS Event Groups and Software Timers

Lesson 06 – xTimerCreate() Function

RTOS & FreeRTOS Chapter Index Learning Portal

Lesson Overview

The xTimerCreate() function creates a software timer dynamically. It configures the timer name, period, operating mode, timer ID, and callback function.

The function returns a timer handle that is used by other timer API functions to start, stop, reset, change, or delete the timer.

Learning Objectives

  • Understand the purpose of xTimerCreate().
  • Learn the function prototype and parameters.
  • Understand timer handles and timer IDs.
  • Configure one-shot and auto-reload timers.
  • Understand dynamic memory allocation for timers.
  • Check timer creation success or failure.
  • Create and configure multiple software timers.

1. What Is xTimerCreate()?

FreeRTOS uses xTimerCreate() to create a software timer object. The timer object stores information required by the kernel to manage its period, state, callback, and other timer-related information. 

TimerHandle_t xTimerCreate(
    const char * const pcTimerName,
    const TickType_t xTimerPeriodInTicks,
    const BaseType_t xAutoReload,
    void * const pvTimerID,
    TimerCallbackFunction_t pxCallbackFunction
);

The function returns a TimerHandle_t. If the timer cannot be created, it returns NULL.

Creating a timer does not automatically start it. A newly created timer is dormant until a start command is successfully submitted and processed by the timer service task.

2. Parameters of xTimerCreate()

ParameterDescription
pcTimerNameHuman-readable timer name, useful during debugging and trace analysis.
xTimerPeriodInTicksTimer period expressed in RTOS ticks. It must be greater than zero.
xAutoReloadpdTRUE creates an auto-reload timer; pdFALSE creates a one-shot timer.
pvTimerIDApplication-defined pointer value associated with the timer.
pxCallbackFunctionPointer to the callback function called when the timer expires.

Return Value

ReturnMeaning
Valid timer handleTimer object was created successfully.
NULLTimer creation failed, commonly because required memory was unavailable.

3. Understanding Timer Name

The first parameter specifies the timer's name. It helps developers identify timers during debugging and system analysis. 

TimerHandle_t xStatusTimer;

xStatusTimer = xTimerCreate(
    "StatusTimer",
    pdMS_TO_TICKS(1000),
    pdTRUE,
    NULL,
    StatusCallback
);

Here, StatusTimer is the name assigned to the timer. The name does not determine the timer's timing behavior.

4. Understanding Timer Period

The second parameter specifies the timer period in RTOS ticks. The application can use pdMS_TO_TICKS() to convert a millisecond value into ticks.

Example – One-Second Period

pdMS_TO_TICKS(1000)

Example – Five-Second Period

pdMS_TO_TICKS(5000)
PeriodTick RateApproximate Tick Count
1000 ms100 Hz100 ticks
1000 ms500 Hz500 ticks
1000 ms1000 Hz1000 ticks
2000 ms1000 Hz2000 ticks
A zero timer period is invalid. Also, tick conversion and timer expiry resolution depend on the selected tick rate and the kernel's tick handling.

5. Understanding xAutoReload

The third parameter selects the timer mode.

ValueTimer TypeBehavior
pdFALSEOne-shotExpires once and becomes inactive.
pdTRUEAuto-reloadAutomatically schedules another expiry after each period while active.

One-Shot Timer

xOneShotTimer = xTimerCreate(
    "OneShot",
    pdMS_TO_TICKS(3000),
    pdFALSE,
    NULL,
    TimerCallback
);

Auto-Reload Timer

xPeriodicTimer = xTimerCreate(
    "Periodic",
    pdMS_TO_TICKS(1000),
    pdTRUE,
    NULL,
    TimerCallback
);
Use a one-shot timer for a three-second communication timeout. Use an auto-reload timer for a recurring one-second status update.

6. Understanding Timer ID

The fourth parameter, pvTimerID, stores an application-defined pointer value associated with the timer. It can be retrieved later using pvTimerGetTimerID().

Timer IDs are useful when several timers share one callback function. Each timer can carry a different identifier or pointer.

Example

#define TIMER_ID_SENSOR  1
#define TIMER_ID_UART    2

/* Example using pointer-sized integer values */
xSensorTimer = xTimerCreate(
    "SensorTimer",
    pdMS_TO_TICKS(1000),
    pdTRUE,
    (void *)TIMER_ID_SENSOR,
    TimerCallback
);

xUARTTimer = xTimerCreate(
    "UARTTimer",
    pdMS_TO_TICKS(2000),
    pdTRUE,
    (void *)TIMER_ID_UART,
    TimerCallback
);

For portable application code, a pointer to a persistent object or a suitable application-defined context structure is often preferable to converting integer IDs into pointers.

Reading the Timer ID

void TimerCallback(TimerHandle_t xTimer)
{
    void *timerID;

    timerID = pvTimerGetTimerID(xTimer);

    if (timerID == &sensorContext)
    {
        /* Handle sensor timer */
    }
}
The timer ID is application data. FreeRTOS does not automatically allocate, copy, or free the object pointed to by the ID. Ensure that the pointed-to object remains valid for as long as it is used.

7. Understanding Callback Function

The fifth parameter specifies the callback function to execute when the timer expires.

Callback Function Prototype

void TimerCallback(TimerHandle_t xTimer);

Example

void StatusCallback(TimerHandle_t xTimer)
{
    /* Perform a short status operation */
}
  • The callback receives the timer handle.
  • The timer handle can be used to identify the timer.
  • The callback executes in timer service task context.
  • The callback should not block.
  • Long operations should be delegated to application tasks.

8. Dynamic Memory Allocation

The standard xTimerCreate() function creates a timer using the FreeRTOS memory allocator. Therefore, timer creation can fail if the configured heap cannot provide the required memory.

Checking Creation Success

TimerHandle_t xTimer;

xTimer = xTimerCreate(
    "MyTimer",
    pdMS_TO_TICKS(1000),
    pdTRUE,
    NULL,
    TimerCallback
);

if (xTimer == NULL)
{
    /* Timer creation failed */
}
else
{
    /* Timer created successfully */
}

FreeRTOS versions that support static allocation can also provide xTimerCreateStatic(). In that approach, the application provides the timer's storage instead of relying on dynamic allocation for the timer object.

Static timer creation requires the appropriate configuration support, including configSUPPORT_STATIC_ALLOCATION where applicable. Check the documentation for the selected FreeRTOS version.

9. Complete Program – Creating Two Timers

Objective

Create one one-shot timer and one auto-reload timer using a shared callback function. Use timer IDs to distinguish them.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "timers.h"

static TimerHandle_t xOneShotTimer;
static TimerHandle_t xPeriodicTimer;

static int sensorTimerID;
static int statusTimerID;

void TimerCallback(TimerHandle_t xTimer)
{
    void *timerID;

    timerID = pvTimerGetTimerID(xTimer);

    if (timerID == &sensorTimerID)
    {
        /* One-shot sensor timeout event */
    }
    else if (timerID == &statusTimerID)
    {
        /* Periodic status event */
    }
}

void ApplicationTask(void *pvParameters)
{
    if (xTimerStart(xOneShotTimer, 0) != pdPASS)
    {
        /* Handle command submission failure */
    }

    if (xTimerStart(xPeriodicTimer, 0) != pdPASS)
    {
        /* Handle command submission failure */
    }

    for (;;)
    {
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    xOneShotTimer = xTimerCreate(
        "SensorTimeout",
        pdMS_TO_TICKS(5000),
        pdFALSE,
        &sensorTimerID,
        TimerCallback
    );

    xPeriodicTimer = xTimerCreate(
        "StatusTimer",
        pdMS_TO_TICKS(1000),
        pdTRUE,
        &statusTimerID,
        TimerCallback
    );

    if ((xOneShotTimer == NULL) ||
        (xPeriodicTimer == NULL))
    {
        for (;;)
        {
            /* Timer creation failed */
        }
    }

    if (xTaskCreate(
        ApplicationTask,
        "Application",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    ) != pdPASS)
    {
        for (;;)
        {
            /* Task creation failed */
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Declare two timer handles.
  2. Create an application identifier for each timer.
  3. Define a common callback function.
  4. Create a five-second one-shot timer.
  5. Create a one-second auto-reload timer.
  6. Pass the address of each identifier as its timer ID.
  7. Check both timer handles for successful creation.
  8. Create an application task.
  9. Submit the timer start commands from the task.
  10. The shared callback identifies the expiring timer through its ID.

Expected Behavior

TimerModePeriodExpected Expiry Behavior
SensorTimeoutOne-shot5 secondsCallback executes once, then timer becomes inactive.
StatusTimerAuto-reload1 secondCallback executes periodically while the timer remains active.
The timer command queue must be processed by the timer service task. A return value of pdPASS from xTimerStart() means the command was successfully queued; it does not mean the timer has already started.

10. Common Programming Errors

ErrorCorrection
Using a zero timer periodSpecify a positive period in ticks.
Not checking the returned handleCheck for NULL.
Assuming timer creation starts itSubmit a start command separately.
Confusing one-shot and auto-reloadChoose pdFALSE or pdTRUE correctly.
Using a temporary timer-ID objectUse storage that remains valid while needed.
Using a blocking callbackDelegate lengthy work to an application task.
Ignoring timer command queue capacityConfigure and monitor the timer command queue appropriately.
Ignoring dynamic allocation failureCheck heap availability and timer creation results.

13. Lesson Summary

  • xTimerCreate() dynamically creates a software timer.
  • It returns a TimerHandle_t or NULL.
  • The period is specified in RTOS ticks.
  • pdFALSE selects one-shot mode.
  • pdTRUE selects auto-reload mode.
  • The timer ID stores an application-defined pointer value.
  • The callback executes when the timer expires.
  • Standard timer creation uses the FreeRTOS memory allocator.
  • Creating a timer does not start it.
  • Timer commands are processed by the timer service task.
