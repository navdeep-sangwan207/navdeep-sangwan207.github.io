Chapter 17: FreeRTOS Event Groups and Software Timers

Lesson 03 – xEventGroupSetBits() and xEventGroupClearBits()

RTOS & FreeRTOS Chapter Index Learning Portal

Lesson Overview

FreeRTOS provides xEventGroupSetBits() and xEventGroupClearBits() to modify event bits in an event group. Setting a bit indicates that a condition has occurred or become true. Clearing a bit indicates that the condition is no longer active or should be considered incomplete.

Learning Objectives

  • Understand how event bits are set and cleared.
  • Learn the syntax and parameters of both functions.
  • Understand bit masks and bitwise operations.
  • Interpret function return values.
  • Write programs for setting and clearing event bits.
  • Understand task synchronization using event groups.
  • Identify common programming errors.

1. Event-Bit Representation

Each usable event bit represents a Boolean condition. A set bit has the value 1, while a cleared bit has the value 0. 

#define EVENT_SENSOR_READY   (1U << 0)
#define EVENT_UART_READY     (1U << 1)
#define EVENT_STORAGE_READY  (1U << 2)
#define EVENT_NETWORK_READY  (1U << 3)
EventBit PositionMask
Sensor ready00001
UART ready10010
Storage ready20100
Network ready31000

These four-bit patterns are simplified illustrations of the corresponding bit masks.

2. xEventGroupSetBits() Function

The xEventGroupSetBits() function sets one or more selected event bits in an event group.

Function Syntax

EventBits_t xEventGroupSetBits(
    EventGroupHandle_t xEventGroup,
    const EventBits_t uxBitsToSet
);

Parameters

ParameterDescription
xEventGroupHandle of the event group to modify.
uxBitsToSetBit mask specifying which bits should be set.

Return Value

The function returns an EventBits_t value representing the event-group bits after the operation and the kernel's synchronization processing. It is not a simple success/failure status.

Example

xEventGroupSetBits(
    xSystemEvents,
    EVENT_SENSOR_READY
);

This sets the sensor-ready bit. Other event bits are not changed by this operation.

3. Setting Multiple Event Bits

The bitwise OR operator (|) combines multiple event masks. This allows several conditions to be marked as set in one operation. 

xEventGroupSetBits(
    xSystemEvents,
    EVENT_SENSOR_READY |
    EVENT_UART_READY   |
    EVENT_STORAGE_READY
);

Bitwise Example

EVENT_SENSOR_READY  = 0001
EVENT_UART_READY    = 0010
EVENT_STORAGE_READY = 0100

Combined mask:
                      0111

After this operation, bits 0, 1, and 2 are set. Bit 3 remains unchanged.

4. xEventGroupClearBits() Function

The xEventGroupClearBits() function clears one or more selected event bits.

Function Syntax

EventBits_t xEventGroupClearBits(
    EventGroupHandle_t xEventGroup,
    const EventBits_t uxBitsToClear
);

Parameters

ParameterDescription
xEventGroupHandle of the event group.
uxBitsToClearMask specifying which bits must be cleared.

Return Value

The function returns the event-bit pattern from before the requested bits were cleared.

Example

xEventGroupClearBits(
    xSystemEvents,
    EVENT_SENSOR_READY
);

The sensor-ready bit is cleared. Other bits retain their previous values.

5. Setting and Clearing Bits – Worked Example

Assume the initial event-group bit pattern is zero.

OperationBit Pattern (bits 3–0)

This example shows that setting or clearing a selected bit does not automatically modify unrelated event bits.

6. Complete Program – Setting and Clearing Event Bits

Objective

Create an event group, set three event bits, clear one event bit, and inspect the returned bit patterns.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

#define EVENT_SENSOR_READY   (1U << 0)
#define EVENT_UART_READY     (1U << 1)
#define EVENT_STORAGE_READY  (1U << 2)

static EventGroupHandle_t xSystemEvents;

int main(void)
{
    EventBits_t bits;

    xSystemEvents = xEventGroupCreate();

    if (xSystemEvents == NULL)
    {
        for (;;)
        {
            /* Creation error */
        }
    }

    /* Set sensor and UART bits */
    bits = xEventGroupSetBits(
        xSystemEvents,
        EVENT_SENSOR_READY | EVENT_UART_READY
    );

    /* Set storage bit */
    bits = xEventGroupSetBits(
        xSystemEvents,
        EVENT_STORAGE_READY
    );

    /* Clear UART bit */
    bits = xEventGroupClearBits(
        xSystemEvents,
        EVENT_UART_READY
    );

    /* Read current event bits */
    bits = xEventGroupGetBits(xSystemEvents);

    /* Application can inspect bits here */

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Create an event group dynamically.
  2. Check whether creation succeeded.
  3. Set sensor-ready and UART-ready bits.
  4. Set the storage-ready bit.
  5. Clear the UART-ready bit.
  6. Read the current event-group bit pattern.
  7. Start the scheduler.

Expected Result

Initial event bits:       000

After setting sensor:     001
After setting UART:       011
After setting storage:    111
After clearing UART:      101

Final state:
Storage ready = 1
Sensor ready  = 1
UART ready    = 0
The example demonstrates the API sequence. In a real application, create the event group and perform initialization before the scheduler starts, or use an appropriate task to perform operations after scheduler startup.

7. Reading Event Bits After Modification

The current event-bit pattern can be read using xEventGroupGetBits() from task context. 

EventBits_t currentBits;

currentBits = xEventGroupGetBits(xSystemEvents);

if ((currentBits & EVENT_SENSOR_READY) != 0)
{
    /* Sensor-ready condition is set */
}

if ((currentBits & EVENT_UART_READY) != 0)
{
    /* UART-ready condition is set */
}

Use bitwise AND (&) to test whether a particular event bit is set.

A read of the current bits is a snapshot. Another task may set or clear bits immediately afterward. Do not treat a separate read followed by an action as an atomic test-and-reserve operation.

8. Important Difference – Task and ISR Context

The functions xEventGroupSetBits() and xEventGroupClearBits() are task-context APIs. They must not be called directly from an ISR.

For setting event bits from an ISR, FreeRTOS provides: 

BaseType_t xEventGroupSetBitsFromISR(
    EventGroupHandle_t xEventGroup,
    EventBits_t uxBitsToSet,
    BaseType_t *pxHigherPriorityTaskWoken
);

This ISR API defers the event-bit setting operation to the FreeRTOS timer service task. It can fail if the timer command queue cannot accept the request.

The ISR must not block. Check the return value of xEventGroupSetBitsFromISR() and use the port-appropriate ISR yield mechanism when a higher-priority task is unblocked. The exact yield macro depends on the selected port.

9. Common Programming Errors

ErrorCorrection
Using an invalid event-group handleCreate the event group and check its handle first.
Calling task-context APIs from an ISRUse the supported ISR-specific API.

Clearing unrelated bitsPass only the intended clear mask.
Assuming a bit counts repeated eventsUse a queue or counting semaphore if every occurrence matters.

12. Lesson Summary

  • xEventGroupSetBits() sets selected event bits.
  • xEventGroupClearBits() clears selected event bits.
  • Bitwise OR combines multiple event masks.
  • Bitwise AND checks whether selected bits are set.
  • The set-bits API returns the event-bit value after synchronization processing.
  • The clear-bits API returns the previous event-bit value.
  • Task-context APIs must not be called directly from an ISR.
  • xEventGroupSetBitsFromISR() provides an ISR-safe deferred mechanism.
  • Event bits represent conditions, not counts of repeated events.
