Chapter 17: FreeRTOS Event Groups and Software Timers

Lesson 04 – xEventGroupWaitBits() Function

RTOS & FreeRTOS Chapter Index Learning Portal

Lesson Overview

The xEventGroupWaitBits() function allows a task to wait until one or more selected event bits become set. It supports waiting for any selected bit or all selected bits, optional clearing of bits when the wait condition is satisfied, and a configurable timeout.

Learning Objectives

  • Understand the purpose of xEventGroupWaitBits().
  • Learn its function prototype and parameters.
  • Understand wait-any and wait-all conditions.
  • Understand clear-on-exit behavior.
  • Learn how timeout values affect task blocking.
  • Interpret the returned event-bit value.
  • Write a task synchronization program using event groups.

1. What Is xEventGroupWaitBits()?

An application task may need to wait for a condition before continuing its execution. For example, a controller may need to wait until sensor initialization and UART initialization are complete.

The xEventGroupWaitBits() function blocks the calling task when the requested event condition is not yet satisfied and the timeout has not expired. 

EventBits_t xEventGroupWaitBits(
    EventGroupHandle_t xEventGroup,
    const EventBits_t uxBitsToWaitFor,
    const BaseType_t xClearOnExit,
    const BaseType_t xWaitForAllBits,
    TickType_t xTicksToWait
);

2. Function Parameters

ParameterDescription
xEventGroupHandle of the event group.
uxBitsToWaitForMask containing the event bits the task waits for.
xClearOnExitpdTRUE requests clearing the specified bits when the wait condition is satisfied; pdFALSE leaves them set.
xWaitForAllBitspdTRUE waits for all selected bits; pdFALSE waits for any selected bit.
xTicksToWaitMaximum time to wait, expressed in RTOS ticks.
The calling task enters the Blocked state while waiting when the condition is not met and the timeout is nonzero. It becomes Ready when the required condition is met or the timeout expires. Becoming Ready does not guarantee immediate execution.

3. Wait-Any Condition

When xWaitForAllBits is set to pdFALSE, the task waits until at least one selected event bit becomes set.

Example

#define EVENT_SENSOR_READY  (1U << 0)
#define EVENT_UART_READY    (1U << 1)
#define EVENT_FAULT         (1U << 2)

EventBits_t result;

result = xEventGroupWaitBits(
    xSystemEvents,
    EVENT_SENSOR_READY | EVENT_UART_READY,
    pdFALSE,
    pdFALSE,
    portMAX_DELAY
);

The task continues when either the sensor-ready bit or the UART-ready bit is set.

Example condition:
  • Sensor ready = 0
  • UART ready = 1
The wait-any condition is satisfied because at least one selected bit is set.

4. Wait-All Condition

When xWaitForAllBits is set to pdTRUE, the task waits until every selected event bit becomes set.

Example

result = xEventGroupWaitBits(
    xSystemEvents,
    EVENT_SENSOR_READY | EVENT_UART_READY,
    pdFALSE,
    pdTRUE,
    portMAX_DELAY
);

The task continues only when both sensor-ready and UART-ready bits are set.

SensorUARTWait-All Result
00Not satisfied
01Not satisfied
10Not satisfied
11Satisfied

5. Clear-on-Exit Behavior

The xClearOnExit parameter determines whether the selected event bits are cleared after the wait condition is met.

ParameterBehavior
pdTRUEClear the selected bits when the wait condition is satisfied.
pdFALSELeave the selected bits unchanged.

Example – Clear on Exit Enabled

result = xEventGroupWaitBits(
    xSystemEvents,
    EVENT_SENSOR_READY | EVENT_UART_READY,
    pdTRUE,
    pdTRUE,
    portMAX_DELAY
);

After both selected bits satisfy the wait condition, the kernel clears those requested bits as part of processing the wait.

Example – Clear on Exit Disabled

result = xEventGroupWaitBits(
    xSystemEvents,
    EVENT_SENSOR_READY | EVENT_UART_READY,
    pdFALSE,
    pdTRUE,
    portMAX_DELAY
);

After the condition is satisfied, the selected bits remain set.

Clear-on-exit is applied when the wait condition is satisfied. A timeout by itself does not clear the requested bits. When multiple tasks wait on the same event group, one task's clear-on-exit operation can affect what other tasks observe.

6. Timeout Behavior

The final parameter specifies how long the task is prepared to wait. The value is expressed in RTOS ticks, not directly in milliseconds.

TimeoutMeaning
0Check the condition without blocking.
Finite tick countWait for the specified maximum number of ticks.
portMAX_DELAYRequest the longest supported wait; indefinite blocking depends on configuration.

Milliseconds to Ticks

TickType_t waitTime;

waitTime = pdMS_TO_TICKS(1000);

At a tick rate of 1000 Hz, 1000 milliseconds corresponds to approximately 1000 ticks. Actual timing resolution depends on the configured tick rate and tick boundaries.

Timeout Example

result = xEventGroupWaitBits(
    xSystemEvents,
    EVENT_SENSOR_READY,
    pdFALSE,
    pdTRUE,
    pdMS_TO_TICKS(2000)
);

if ((result & EVENT_SENSOR_READY) != 0)
{
    /* Sensor-ready bit was observed */
}
else
{
    /* Timeout or condition not satisfied */
}

When a finite timeout expires without the requested condition being satisfied, the task becomes Ready and receives the event-bit snapshot returned by the function.

7. Understanding the Return Value

The function returns an EventBits_t value representing the event-group bits observed when the task leaves the wait. This is not a simple Boolean success/failure value.

Testing the Returned Bits

EventBits_t result;

result = xEventGroupWaitBits(
    xSystemEvents,
    EVENT_SENSOR_READY | EVENT_UART_READY,
    pdFALSE,
    pdTRUE,
    pdMS_TO_TICKS(3000)
);

if ((result & (EVENT_SENSOR_READY |
              EVENT_UART_READY)) ==
             (EVENT_SENSOR_READY |
              EVENT_UART_READY))
{
    /* Both requested bits were set */
}
else
{
    /* Requested condition was not fully satisfied */
}
Check the returned bits against the requested mask. Do not assume that a nonzero return value automatically means all requested conditions were satisfied.

8. Complete Program – Waiting for Sensor and UART Initialization

Objective

Create an event group and two initialization tasks. A monitoring task waits until both initialization conditions are set.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

#define EVENT_SENSOR_READY  (1U << 0)
#define EVENT_UART_READY    (1U << 1)

static EventGroupHandle_t xSystemEvents;

void SensorTask(void *pvParameters)
{
    /* Simulate sensor initialization */
    vTaskDelay(pdMS_TO_TICKS(1000));

    xEventGroupSetBits(
        xSystemEvents,
        EVENT_SENSOR_READY
    );

    for (;;)
    {
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void UARTTask(void *pvParameters)
{
    /* Simulate UART initialization */
    vTaskDelay(pdMS_TO_TICKS(2000));

    xEventGroupSetBits(
        xSystemEvents,
        EVENT_UART_READY
    );

    for (;;)
    {
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void MonitorTask(void *pvParameters)
{
    EventBits_t result;
    EventBits_t requiredBits;

    requiredBits =
        EVENT_SENSOR_READY | EVENT_UART_READY;

    result = xEventGroupWaitBits(
        xSystemEvents,
        requiredBits,
        pdFALSE,
        pdTRUE,
        portMAX_DELAY
    );

    if ((result & requiredBits) == requiredBits)
    {
        /* Both initialization conditions are ready */
    }

    for (;;)
    {
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    xSystemEvents = xEventGroupCreate();

    if (xSystemEvents == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(
        SensorTask,
        "Sensor",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        UARTTask,
        "UART",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        MonitorTask,
        "Monitor",
        configMINIMAL_STACK_SIZE,
        NULL,
        3,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Create the event group before starting the scheduler.
  2. Create the sensor initialization task.
  3. Create the UART initialization task.
  4. Create the monitoring task with a higher priority.
  5. The monitoring task waits for both event bits.
  6. The sensor task sets its bit after initialization.
  7. The UART task sets its bit after initialization.
  8. Once both bits are set, the monitoring task can continue.

Expected Result

Approximate TimeEvent
0 msAll event bits initially cleared.
1000 msSensor-ready bit is set.
2000 msUART-ready bit is set.
After both bits are setMonitoring task's wait condition is satisfied.
The example uses dynamic task creation and simplified delays. For a production project, check every task-creation return value, select adequate stack sizes, and define what the monitor should do after initialization. The delay values are illustrative, not precision hardware timing guarantees.

9. Multiple Tasks Waiting on the Same Event Group

Multiple tasks can wait on the same event group. Each task can specify its own event mask and whether it needs any or all of the selected bits.

Consider the following example:

Task A waits for:
EVENT_SENSOR_READY

Task B waits for:
EVENT_SENSOR_READY | EVENT_UART_READY

Task C waits for:
EVENT_STORAGE_READY

When event bits are set, each task's wait condition is evaluated against the event group.

When several tasks wait on shared bits, clear-on-exit behavior must be designed carefully. A task that clears a bit can change the result observed by another waiting task. If several tasks must observe the same event, leaving bits set or using separate notification mechanisms may be more appropriate.

10. Common Programming Errors

ErrorCorrection
Using an invalid event-group handleCreate the event group and check for NULL.
Confusing wait-any and wait-allUse pdFALSE for any selected bit and pdTRUE for all selected bits.
Clearing bits unintentionallyChoose the clear-on-exit parameter deliberately.
Ignoring timeout behaviorInspect the returned event-bit pattern.
Assuming Ready means RunningRemember that the scheduler determines when a Ready task executes.
Using an incorrect timeout unitConvert milliseconds using pdMS_TO_TICKS().
Ignoring other waiting tasksDesign shared-bit clearing rules carefully.

13. Lesson Summary

  • xEventGroupWaitBits() allows a task to wait for selected event bits.
  • Wait-any mode requires at least one selected bit.
  • Wait-all mode requires every selected bit.
  • Clear-on-exit can clear selected bits when the wait condition is satisfied.
  • A timeout limits how long the task waits.
  • The returned value contains an event-bit snapshot.
  • Always inspect the requested bits in the returned value.
  • Multiple tasks can wait on one event group, so shared-bit clearing must be considered.
