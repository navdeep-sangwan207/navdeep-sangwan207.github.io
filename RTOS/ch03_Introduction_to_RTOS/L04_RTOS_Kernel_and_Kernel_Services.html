2. What Is an RTOS Kernel?

An RTOS kernel is the central software component of a real-time operating system. It manages processor execution and provides services required by real-time applications.

It coordinates multiple tasks, handles scheduling decisions, provides synchronization mechanisms, and manages time-related operations.

Main Responsibilities

  • Managing application tasks.
  • Selecting tasks for execution.
  • Handling task context switching.
  • Providing inter-task communication.
  • Coordinating shared resource access.
  • Managing task delays and timeouts.
  • Providing memory allocation services where supported.
  • Coordinating with processor interrupts and timers.
The kernel does not automatically guarantee that every application deadline will be met. Correct task design, scheduling analysis, bounded execution times, and controlled resource sharing are also necessary.

4. Types of Kernel Services

Kernel services are functions provided by the RTOS to application software.

Kernel Service Purpose
Task Management Create, delete, suspend, and resume tasks.
Scheduling Select the next eligible task.
Context Switching Save and restore processor execution context.
Communication Exchange information between tasks.
Synchronization Coordinate tasks and shared resources.
Time Management Manage delays, timeouts, and periodic operations.
Memory Management Manage memory used by tasks and kernel objects.
Interrupt Integration Coordinate interrupt events with task execution.

5. Task Management Services

Task management services allow an application to control the lifecycle of its tasks.

Common Operations

  • Create: Establish a new task and its associated resources.
  • Delete: Remove a task from the kernel.
  • Suspend: Prevent a task from being scheduled.
  • Resume: Make a suspended task eligible for scheduling.
  • Delay: Block a task for a specified period.
  • Change priority: Modify a task's scheduling priority.
  • Query: Obtain task-related information.

Example: Task Creation in FreeRTOS

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        /* Perform sensor-related processing. */

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void)
{
    Hardware_Init();

    xTaskCreate(
        SensorTask,
        "Sensor",
        256,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

The example illustrates task creation and periodic blocking. Stack-depth units and available APIs depend on the selected FreeRTOS version and port.

6. Scheduling Services

The scheduler is responsible for deciding which ready task should execute.

Scheduling Functions

  • Maintaining ready-task information.
  • Comparing task priorities.
  • Selecting the highest-priority eligible task in fixed-priority systems.
  • Managing task blocking and unblocking.
  • Supporting preemption where configured.
  • Supporting equal-priority time slicing where configured.

Example

Assume a fixed-priority preemptive scheduler with three ready tasks:

Task Priority Scheduling Status
Control Task 3 Selected first
Sensor Task 2 Ready and waiting
Display Task 1 Ready and waiting

If the Control Task blocks while waiting for an event, the scheduler can select the next highest-priority ready task.

Priority alone does not guarantee deadline satisfaction. Blocking, interrupt interference, execution time, and resource contention must also be considered.

7. Context-Switching Service

Context switching enables the processor to move from one task to another.

Typical Operations

  1. Preserve the outgoing task's required CPU state.
  2. Update task scheduling information.
  3. Select the incoming task.
  4. Restore its saved CPU state.
  5. Resume execution.

The implementation is processor-specific. It may involve assembly language, interrupt handlers, processor registers, and stack management.

Context-Switch Overhead

Context switching consumes CPU time. Excessive task switching can reduce the time available for useful application processing.

For example, if a measured context switch takes 5 microseconds and 2000 switches occur per second:

Total switching time = 5 × 2000 = 10,000 microseconds per second.

CPU time spent switching = 1%.

8. Inter-Task Communication Services

Communication services allow tasks to exchange data without requiring every task to directly access the same variables.

Common Services

  • Message queues.
  • Task notifications.
  • Message buffers.
  • Stream buffers.
  • Shared memory with synchronization.

Example: Queue Communication

QueueHandle_t sensorQueue;

void SensorTask(void *pvParameters)
{
    int temperature = 25;

    for (;;)
    {
        xQueueSend(
            sensorQueue,
            &temperature,
            portMAX_DELAY
        );

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void ControlTask(void *pvParameters)
{
    int receivedTemperature;

    for (;;)
    {
        if (xQueueReceive(
                sensorQueue,
                &receivedTemperature,
                portMAX_DELAY) == pdPASS)
        {
            /* Process received temperature. */
        }
    }
}

This is a conceptual FreeRTOS example. The queue must be created successfully before the tasks use it, and error handling should be added in a complete application.

9. Synchronization Services

Synchronization services coordinate the execution of tasks and protect shared resources.

Binary Semaphore

Can be used to signal an event or synchronize two activities.

Counting Semaphore

Can represent a count of available resources or pending events.

Mutex

Provides mutual exclusion when multiple tasks need access to a shared resource. Some RTOS mutex implementations support priority inheritance.

Critical Section

Protects a short region of code against specified forms of concurrent access or interruption.

A mutex and a semaphore are not interchangeable in every situation. A mutex generally has ownership semantics, while a semaphore is commonly used for signaling or resource counting.

10. Time Management Services

Time management services support operations that depend on time.

Important Services

  • System tick counting.
  • Task delays.
  • Periodic task execution.
  • Timeout management.
  • Software timers.
  • Tickless idle operation where supported.

FreeRTOS Timing Examples

/* Delay for 500 milliseconds */
vTaskDelay(pdMS_TO_TICKS(500));

/* Delay until a periodic wake-up time */
TickType_t lastWakeTime = xTaskGetTickCount();

for (;;)
{
    /* Perform periodic work. */

    vTaskDelayUntil(
        &lastWakeTime,
        pdMS_TO_TICKS(100)
    );
}

vTaskDelayUntil() is useful for periodic execution because it schedules against an incrementing reference wake time rather than simply delaying relative to the end of the previous operation.

11. Software Timer Services

Software timers allow an application to schedule functions to execute after a specified time or repeatedly at a configured interval.

Types of Software Timers

  • One-shot timer: Expires once and then stops.
  • Auto-reload timer: Repeats after each expiry.

FreeRTOS Timer Example

void TimerCallback(TimerHandle_t xTimer)
{
    /* Execute timer-related processing. */
}

int main(void)
{
    TimerHandle_t periodicTimer;

    periodicTimer = xTimerCreate(
        "Periodic",
        pdMS_TO_TICKS(1000),
        pdTRUE,
        NULL,
        TimerCallback
    );

    if (periodicTimer != NULL)
    {
        xTimerStart(periodicTimer, 0);
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}
FreeRTOS software timer callbacks execute in the timer service task, not directly in the hardware timer ISR. Keep callbacks short and avoid blocking operations.

12. Memory Management Services

Memory management services control the memory used by tasks and kernel objects.

Common Memory Requirements

  • Task stacks.
  • Task control blocks.
  • Queue storage.
  • Semaphore and mutex structures.
  • Timer structures.
  • Application buffers.

Static Allocation

Memory is provided by the application or reserved before runtime allocation is needed.

Dynamic Allocation

Memory is allocated at runtime using an available allocator.

FreeRTOS provides multiple heap implementations. The selected implementation determines allocation behavior, including whether memory can be freed and whether adjacent free blocks can be combined.

13. Interrupt-Related Kernel Services

The RTOS kernel works with processor interrupt mechanisms to respond to external events.

Typical Sequence

  1. A hardware peripheral generates an interrupt.
  2. The processor enters the appropriate interrupt handler.
  3. The ISR acknowledges the interrupt and performs essential processing.
  4. The ISR may signal a task using an ISR-safe API.
  5. The kernel may request a reschedule.
  6. The processor returns to the appropriate task context.

FreeRTOS ISR API Concept

BaseType_t higherPriorityTaskWoken = pdFALSE;

/* Example inside a suitable ISR */
xSemaphoreGiveFromISR(
    eventSemaphore,
    &higherPriorityTaskWoken
);

portYIELD_FROM_ISR(higherPriorityTaskWoken);

This is a generic FreeRTOS pattern. The exact yield macro and interrupt-priority rules depend on the processor port.

14. Kernel Objects

Kernel objects are data structures used by the RTOS to provide services.

Kernel Object Purpose
Task Represents an independently scheduled execution unit.
Queue Stores messages or data items.
Semaphore Provides event signaling or resource counting.
Mutex Provides mutual exclusion.
Event Group Represents multiple event bits.
Software Timer Schedules timer callbacks.
Stream Buffer Transfers a stream of bytes.
Message Buffer Transfers discrete messages.

15. Kernel APIs

A kernel API is an interface through which application code requests operating-system services.

Examples of FreeRTOS APIs

API Purpose
xTaskCreate() Create a task.
vTaskDelete() Delete a task.
vTaskDelay() Block a task for a period.
vTaskDelayUntil() Support periodic task timing.
xQueueSend() Send data to a queue.
xQueueReceive() Receive data from a queue.
xSemaphoreTake() Take a semaphore or mutex.
xSemaphoreGive() Give a semaphore or mutex.
vTaskStartScheduler() Start the scheduler.

16. Kernel Configuration

RTOS kernel configuration determines which features are enabled and how the kernel behaves.

FreeRTOS Configuration File

The FreeRTOSConfig.h file contains application-specific kernel configuration settings.

Examples of Configuration Options

  • configTICK_RATE_HZ – configures the kernel tick frequency.
  • configMAX_PRIORITIES – defines the number of task priority levels.
  • configUSE_PREEMPTION – controls preemptive scheduling support.
  • configUSE_MUTEXES – enables mutex functionality.
  • configUSE_TIMERS – enables software timer functionality.
  • configTOTAL_HEAP_SIZE – configures heap size for heap implementations that use this setting.

Available settings and their effects depend on the FreeRTOS version, selected port, and enabled features.

17. Kernel and Hardware Interaction

An RTOS kernel depends on processor-specific mechanisms to perform scheduling and context switching.

Hardware Components Commonly Used

  • Processor registers.
  • Stack pointer and program counter.
  • Timer or system tick source.
  • Interrupt controller.
  • Memory and stack regions.
  • Processor exception or interrupt mechanisms.

Processor Port

A processor port adapts the RTOS kernel to a particular processor architecture and toolchain. It normally contains architecture-specific context-switch and interrupt-handling code.

The same RTOS API can be used across multiple processor families when suitable ports exist, but the low-level implementation is not interchangeable.

18. LPC2129 and Keil uVision Context

The LPC2129 is based on the ARM7TDMI-S processor core. Understanding its architecture helps explain how a kernel interacts with an embedded processor.

Relevant Hardware Features

  • ARM7TDMI-S CPU core.
  • Vectored Interrupt Controller (VIC).
  • Timer peripherals.
  • UART communication interfaces.
  • GPIO ports.
  • ADC and other peripheral interfaces.

Practical Study in Keil

  1. Create a simple ARM7 C project.
  2. Configure a timer interrupt.
  3. Inspect CPU registers in the debugger.
  4. Observe interrupt entry and return behavior where supported by the simulator.
  5. Inspect relevant VIC and timer registers.
  6. Study how an interrupt handler can set a flag for foreground processing.
Keil uVision simulation of LPC2129 registers does not establish that a compatible FreeRTOS port is available. Verify the actual ARM7TDMI-S port, compiler support, startup code, interrupt integration, and build configuration before attempting a FreeRTOS port. Do not apply Cortex-M NVIC-specific instructions to the LPC2129 VIC.

19. Advantages and Limitations of Kernel Services

Advantages

  • Organized multitasking.
  • Reusable task and communication services.
  • Structured synchronization.
  • Better separation of application functions.
  • Support for periodic and event-driven activities.
  • More manageable application architecture.

Limitations and Design Considerations

  • Kernel services consume CPU time and memory.
  • Context switching introduces overhead.
  • Incorrect synchronization can cause deadlocks and priority inversion.
  • Dynamic memory allocation can introduce fragmentation and nondeterministic delays.
  • Poor priority assignment can cause deadline misses.
  • Incorrect ISR/API usage can corrupt kernel state.
