2. Introduction to RTOS System Time

An RTOS requires a time reference to manage task delays, timeouts, periodic operations, and scheduling decisions.

The kernel maintains a system time value that advances as timer events occur.

In a tick-based RTOS, this time reference is commonly updated by a periodic hardware timer interrupt called the system tick interrupt.

Why Does an RTOS Need System Time?

  • To delay tasks for specified periods.
  • To wake blocked tasks after a timeout.
  • To execute periodic application activities.
  • To manage software timers.
  • To determine when time-based scheduling operations are required.
  • To maintain elapsed kernel time.
The RTOS system tick is a kernel timing mechanism. It is not necessarily the same as a calendar clock or real-time clock (RTC) that stores date and time.

3. What Is a System Tick?

A system tick is a periodic timing event used by a tick-based RTOS to maintain its kernel time reference.

A hardware timer generates an interrupt at regular intervals. The RTOS tick handler updates the kernel tick count and processes time-dependent kernel operations.

System Tick Architecture

+---------------------------+
|       Hardware Timer      |
+---------------------------+
             |
             v
+---------------------------+
|   Periodic Timer Event    |
+---------------------------+
             |
             v
+---------------------------+
|    Tick Interrupt (ISR)   |
+---------------------------+
             |
             v
+---------------------------+
|     RTOS Tick Handler     |
|                           |
| Increment Tick Count      |
| Check Task Delays         |
| Process Timeouts          |
| Update Scheduling State  |
+---------------------------+
             |
             v
+---------------------------+
|  Scheduler Decision       |
+---------------------------+

The exact operations performed by the tick handler depend on the RTOS implementation and configuration.

4. Tick Frequency

Tick frequency is the number of system tick events generated in one second.

It is measured in Hertz (Hz).

Common Tick Frequencies

Tick Frequency Tick Period
100 Hz 10 ms
250 Hz 4 ms
500 Hz 2 ms
1000 Hz 1 ms

Tick Period Formula

The time between consecutive tick events is:

\[ T_{tick} = \frac{1}{f_{tick}} \]

Where:

  • Ttick = tick period in seconds.
  • ftick = tick frequency in Hertz.

Example 1

Calculate the tick period for a tick frequency of 1000 Hz.

Tick Frequency = 1000 Hz

Tick Period = 1 / 1000
            = 0.001 seconds
            = 1 ms

Example 2

Calculate the tick frequency if the tick period is 5 ms.

Tick Period = 5 ms
            = 0.005 seconds

Frequency = 1 / 0.005
          = 200 Hz

5. Tick Interrupt

A timer interrupt is generated whenever the configured hardware timer reaches its programmed event condition.

The processor transfers execution to the interrupt handler, which performs the required tick processing.

Basic Tick Interrupt Sequence

  1. Configure a hardware timer.
  2. Set the required timer period.
  3. Enable the timer interrupt.
  4. The timer reaches its match or overflow condition.
  5. The processor enters the interrupt handler.
  6. The RTOS updates its tick count.
  7. Time-dependent task states are examined.
  8. The processor returns to the appropriate execution context.
A tick interrupt does not necessarily cause a task context switch. A switch occurs only when required by the scheduler and supported by the configured scheduling policy.

6. RTOS System Tick Counter

The RTOS maintains a numerical counter representing the number of tick events that have occurred.

For example, if the tick frequency is 1000 Hz, approximately 1000 tick increments occur in one second.

Example

Tick Count Elapsed Time at 1000 Hz
100100 ms
250250 ms
500500 ms
10001 second
50005 seconds

Elapsed Time Formula

\[ t = \frac{N}{f_{tick}} \]

Where:

  • t = elapsed time in seconds.
  • N = number of elapsed ticks.
  • ftick = tick frequency in Hertz.

Example

Tick Count = 2500
Tick Rate  = 1000 Hz

Elapsed Time = 2500 / 1000
             = 2.5 seconds

7. Task Delay Using System Tick

An RTOS can use the system tick to manage task delays.

When a task requests a delay, the kernel moves it from the Running state to the Blocked state for the specified duration.

Task Delay Sequence

+-----------------------+
|       Task Running    |
+-----------------------+
            |
            v
+-----------------------+
|   Request Task Delay  |
+-----------------------+
            |
            v
+-----------------------+
|    Task Blocked       |
+-----------------------+
            |
            v
+-----------------------+
| Delay Period Expires  |
+-----------------------+
            |
            v
+-----------------------+
|      Task Ready       |
+-----------------------+
            |
            v
+-----------------------+
| Task Scheduled Again  |
+-----------------------+

FreeRTOS Example

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        Read_Sensor();

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

The task requests a delay of approximately 100 milliseconds. It becomes eligible to run after the delay expires, but actual execution depends on scheduler state and task priority.

8. Tick Resolution

Tick resolution is the smallest time interval represented by one tick in a tick-based timing mechanism.

For example, a 1000 Hz tick rate has a nominal resolution of 1 ms.

Tick Rate Nominal Resolution
100 Hz10 ms
250 Hz4 ms
500 Hz2 ms
1000 Hz1 ms

Higher Tick Rate

  • Provides finer tick-based timing granularity.
  • Can support shorter tick-based delays.
  • Increases the frequency of tick interrupt processing.
  • May increase CPU overhead and power consumption.

Lower Tick Rate

  • Reduces the number of periodic tick interrupts.
  • Can reduce timing-related CPU overhead.
  • Provides coarser tick-based timing resolution.
Tick resolution is not the same as guaranteed application response time. Interrupt latency, scheduling, blocking, execution time, and timer accuracy also affect actual behavior.

9. Periodic Task Execution

Many embedded applications require operations to execute at regular intervals.

Examples include:

  • Reading a temperature sensor every 100 ms.
  • Updating a display every 500 ms.
  • Monitoring communication status every 50 ms.
  • Executing a control algorithm at a fixed period.

Using vTaskDelay()

void MonitoringTask(void *pvParameters)
{
    for (;;)
    {
        Monitor_System();

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

This inserts a relative delay after the monitoring operation. The actual interval between task start times also includes execution time and scheduling effects.

Using vTaskDelayUntil()

void PeriodicTask(void *pvParameters)
{
    TickType_t lastWakeTime;
    const TickType_t period = pdMS_TO_TICKS(100);

    lastWakeTime = xTaskGetTickCount();

    for (;;)
    {
        Perform_Periodic_Work();

        vTaskDelayUntil(&lastWakeTime, period);
    }
}

vTaskDelayUntil() is designed for periodic execution using an absolute tick schedule. It helps avoid cumulative drift caused by adding the task execution time to a relative delay.

If the task execution time exceeds its period, the task cannot maintain the intended periodic completion behavior. The design must account for execution time, blocking, preemption, and missed periods.

10. vTaskDelay() vs vTaskDelayUntil()

Parameter vTaskDelay() vTaskDelayUntil()
Delay Type Relative delay Absolute tick schedule
Reference Current time when called Previous scheduled wake time
Periodic Tasks May accumulate execution-time drift Designed to maintain a regular period
Typical Use Simple delays and waits Periodic task execution

11. Tick-Based Timeouts

RTOS timing services can also manage timeout conditions.

For example, a task may wait for a queue message for a maximum of 100 milliseconds.

FreeRTOS Queue Timeout Example

void ReceiverTask(void *pvParameters)
{
    SensorMessage message;

    for (;;)
    {
        if (xQueueReceive(
                sensorQueue,
                &message,
                pdMS_TO_TICKS(100)) == pdPASS)
        {
            Process_Message(&message);
        }
        else
        {
            Handle_Receive_Timeout();
        }
    }
}

The task waits for a message or until the specified timeout expires. This example assumes that the queue and message type have been defined and initialized correctly.

12. Tick Counter Overflow

An RTOS tick counter has a finite data width. When its maximum value is reached, the counter wraps around to zero.

For example, an unsigned 16-bit counter has a maximum value of 65535.

Maximum 16-bit value = 65535

After incrementing:

65535 + 1 = 0 (wraparound)

FreeRTOS uses TickType_t for tick values. Its width depends on the port and configuration.

Example: Unsigned Counter Arithmetic

#include 

uint16_t start = 65530;
uint16_t now   = 5;

uint16_t elapsed = (uint16_t)(now - start);

/* elapsed = 11 ticks */

Unsigned subtraction can correctly measure short elapsed intervals across a single wraparound, provided the measurement interval and comparison logic are designed within the counter's range.

Do not assume that a tick counter can represent unlimited elapsed time. Use the RTOS-provided time types and wraparound-safe comparison methods.

13. Tickless Idle

Tickless idle is a power-saving technique in which the RTOS suppresses unnecessary periodic tick interrupts while the system is idle for a known interval.

Normal Tick Operation

  • The timer generates periodic tick interrupts.
  • The kernel updates the tick count regularly.
  • The processor handles each scheduled tick event.

Tickless Idle Operation

  • The scheduler determines how long the system can remain idle.
  • The periodic tick can be suppressed temporarily.
  • A low-power timer or equivalent time source tracks the idle interval.
  • The system wakes when an event or timeout requires processing.
  • The RTOS corrects its time accounting after the idle period.

Conceptual Diagram

Normal Tick Mode:

Tick  Tick  Tick  Tick  Tick  Tick
 |     |     |     |     |     |
 v     v     v     v     v     v

Tickless Idle Mode:

Tick                         Wake
 |                             |
 v                             v
 +-----------------------------+
 |       Idle Interval         |
 |  Suppressed Periodic Ticks  |
 +-----------------------------+

Advantages

  • Reduces unnecessary periodic interrupts during idle periods.
  • Can reduce processor wakeups.
  • Can improve energy efficiency.

Limitations

  • Requires suitable hardware timer support.
  • Needs correct time compensation after sleep.
  • Wake-up latency must be considered.
  • Not useful when the processor is continuously busy.

14. FreeRTOS Tick Configuration

FreeRTOS provides configuration options for controlling tick behavior.

configTICK_RATE_HZ

Defines the configured tick frequency in ticks per second.

#define configTICK_RATE_HZ    1000

This represents a nominal tick period of 1 millisecond.

configUSE_TICKLESS_IDLE

Controls whether tickless idle support is enabled when the selected port implements it.

#define configUSE_TICKLESS_IDLE    1

The actual configuration and required hardware support depend on the FreeRTOS port.

pdMS_TO_TICKS()

Converts a time expressed in milliseconds into RTOS ticks.

TickType_t delayTicks;

delayTicks = pdMS_TO_TICKS(250);

For a 1000 Hz tick rate, 250 ms corresponds to approximately 250 ticks.

Millisecond-to-tick conversion has finite resolution. A requested delay shorter than one tick may convert to zero ticks. Check the configured tick rate and conversion behavior when designing short timing intervals.

15. Hardware Timer and RTOS Tick

A hardware timer is commonly used to generate the RTOS tick interrupt.

For example, a timer may be configured to generate an interrupt every 1 millisecond for a 1000 Hz tick rate.

General Timer Configuration

Timer Clock = 15 MHz
Required Tick Frequency = 1000 Hz

Timer Period = 15,000 timer counts

Tick Interval = 15,000 / 15,000,000
              = 0.001 seconds
              = 1 ms

This simplified calculation assumes one timer count per peripheral clock and does not include prescaler, reset, or match-register encoding details.

LPC2129 Timer Example

For your LPC2129 setup:

  • Peripheral clock (PCLK) = 15 MHz.
  • Timer prescaler PR = 14999.
  • Timer counter increments once per 1 ms.
  • MR0 = 1 can be used to produce a nominal 1 ms match interval when the timer is configured to reset on MR0.
Timer Counter Clock =
PCLK / (PR + 1)

= 15,000,000 / 15,000
= 1000 Hz

Timer Counter Period = 1 ms

This demonstrates how a hardware timer can provide a 1 ms time base. It is not by itself a complete FreeRTOS tick port.

16. Tick Timing Accuracy and Limitations

Tick-based timing is useful, but the configured tick period does not guarantee that every application operation starts or finishes at an exact instant.

Factors Affecting Timing

  • Hardware timer clock accuracy.
  • Timer configuration and prescaler values.
  • Interrupt latency.
  • Interrupt masking and higher-priority interrupts.
  • Scheduler behavior.
  • Task priority and blocking.
  • Execution time of application code.

For high-resolution measurement or precise waveform generation, a dedicated hardware timer or capture/compare peripheral may be more appropriate than relying only on the RTOS tick.
