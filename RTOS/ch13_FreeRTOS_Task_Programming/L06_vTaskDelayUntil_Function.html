vTaskDelayUntil() Function

2. Introduction to vTaskDelayUntil()

Many embedded applications require operations to start at regular intervals. Examples include sensor sampling, control-loop execution and periodic communication.

vTaskDelayUntil() is designed to help a task maintain a regular execution period. It uses a previously stored wake-time reference and a fixed time increment. 

void vTaskDelayUntil(
    TickType_t *pxPreviousWakeTime,
    TickType_t xTimeIncrement
);

The function delays the calling task until the calculated absolute wake time, provided that the wake time is still in the future.

3. Parameters of vTaskDelayUntil()

ParameterDescription
pxPreviousWakeTimePointer to a variable holding the previous scheduled wake time. The function updates this value for the next cycle.
xTimeIncrementNumber of ticks between scheduled wake times. This represents the task period.

Important Variables

  • xLastWakeTime stores the previous scheduled wake time.
  • xFrequency stores the periodic interval in ticks.
  • pdMS_TO_TICKS() converts a millisecond period into RTOS ticks.
The previous wake-time variable should be initialized before the periodic loop. A common approach is to initialize it using xTaskGetTickCount() at the beginning of the task.

4. Basic Syntax and Usage

void PeriodicTask(void *pvParameters)
{
    TickType_t xLastWakeTime;
    const TickType_t xFrequency =
        pdMS_TO_TICKS(500);

    xLastWakeTime = xTaskGetTickCount();

    for (;;)
    {
        /* Periodic task operation */

        vTaskDelayUntil(
            &xLastWakeTime,
            xFrequency
        );
    }
}

Explanation

  1. Declare xLastWakeTime to store the previous scheduled wake time.
  2. Calculate the desired period in ticks.
  3. Initialize xLastWakeTime using the current tick count.
  4. Perform the periodic operation.
  5. Call vTaskDelayUntil() with the stored wake time and period.
  6. The function updates the reference for the next cycle.
  7. The task repeats at the scheduled period when it can meet that schedule.

5. Understanding Absolute Wake-Time Scheduling

Absolute scheduling calculates each wake time from a stored timing reference rather than starting a new delay after the task's work completes.

Suppose a task has a period of 100 milliseconds. Its scheduled start times are:

Execution CycleScheduled Start Time
Cycle 10 ms
Cycle 2100 ms
Cycle 3200 ms
Cycle 4300 ms
Cycle 5400 ms

The next scheduled wake time is based on the previous scheduled wake time plus the period, not simply the time at which the task last called the delay function.

6. Timing Example: vTaskDelay() Versus vTaskDelayUntil()

Assume a task performs an operation that takes 20 milliseconds and has a requested period of 100 milliseconds.

Using vTaskDelay()

Operation time = 20 ms
Relative delay = 100 ms

Start of operation 1 = 0 ms
Start of operation 2 = 120 ms
Start of operation 3 = 240 ms
Start of operation 4 = 360 ms

The execution time is added to the relative delay, so the start-to-start interval becomes approximately 120 milliseconds.

Using vTaskDelayUntil()

Task period = 100 ms

Scheduled start 1 = 0 ms
Scheduled start 2 = 100 ms
Scheduled start 3 = 200 ms
Scheduled start 4 = 300 ms

The function attempts to maintain the 100 millisecond schedule. The task's execution time does not intentionally extend the configured period.

This does not guarantee that the task will execute exactly at each scheduled time. Scheduler delays, interrupts, higher-priority tasks and execution overruns can still cause lateness or missed periods.

7. Tick Calculation for Periodic Tasks

The period supplied to vTaskDelayUntil() is expressed in RTOS ticks.

Example 1: 1000 Hz Tick Rate

Tick rate = 1000 Hz
Task period = 200 ms

Ticks = 200 * 1000 / 1000

Ticks = 200

Example 2: 100 Hz Tick Rate

Tick rate = 100 Hz
Task period = 500 ms

Ticks = 500 * 100 / 1000

Ticks = 50

Use pdMS_TO_TICKS() rather than manually calculating tick conversions in application code. 

const TickType_t xFrequency =
    pdMS_TO_TICKS(200);
Ensure the converted period is greater than zero. A period that converts to zero ticks cannot provide the intended positive periodic interval.

8. Complete Periodic Sensor Monitoring Example

The following example creates a task that performs a sensor-monitoring operation at a nominal 500 millisecond period. 

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    TickType_t xLastWakeTime;

    const TickType_t xFrequency =
        pdMS_TO_TICKS(500);

    xLastWakeTime = xTaskGetTickCount();

    for (;;)
    {
        /* Read sensor */

        /* Process sensor data */

        /* Wait for next scheduled period */
        vTaskDelayUntil(
            &xLastWakeTime,
            xFrequency
        );
    }
}

int main(void)
{
    BaseType_t result;

    result = xTaskCreate(
        SensorTask,
        "Sensor",
        256,
        NULL,
        2,
        NULL
    );

    if (result == pdPASS)
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Program Explanation

  • The task period is configured as 500 milliseconds.
  • The initial wake-time reference is obtained from the tick count.
  • The sensor operation executes once per cycle.
  • vTaskDelayUntil() maintains the scheduled timing reference.
  • The task becomes Ready at the scheduled wake time, subject to scheduler behavior.

9. What Happens When a Task Misses Its Scheduled Wake Time?

If the task reaches vTaskDelayUntil() after its next scheduled wake time has already passed, the function does not block the task for a positive delay. The task continues execution and the scheduled reference is advanced.

Example

Assume a periodic task has a 100 millisecond period. Its next scheduled wake time is 200 ms, but the task does not reach the delay call until 215 ms.

EventTime
Previous scheduled wake time100 ms
Next scheduled wake time200 ms
Task reaches delay call215 ms
Scheduled wake time already passedYes
Positive blocking delayNot performed

The task continues rather than waiting for another full 100 milliseconds. The next scheduled reference is advanced according to the periodic increment.

vTaskDelayUntil() does not automatically skip application work, count missed deadlines or recover the control algorithm. The application must define its own overrun and missed-period policy.

10. Handling Execution Overruns

An execution overrun occurs when a task takes longer than the available time in its period. For example, a task with a 100 millisecond period may require 130 milliseconds to complete.

Possible Consequences

  • The task misses its intended release schedule.
  • The task may execute again without blocking if the next wake time has passed.
  • Repeated overruns can cause timing instability.
  • Other tasks may experience increased response times.
  • Real-time deadlines may be missed.

Design Approaches

  1. Measure and analyze worst-case execution time.
  2. Optimize expensive processing operations.
  3. Review task priorities and blocking time.
  4. Reduce unnecessary work inside periodic tasks.
  5. Define a deliberate missed-period recovery policy.
  6. Use a suitable hardware timer or other mechanism when the required timing precision exceeds tick-based scheduling.

12. Tick Counter Overflow Considerations

The RTOS tick counter uses a finite-width unsigned integer type. Eventually, it wraps around to zero. FreeRTOS time-management APIs are designed to handle normal tick-count wraparound when used according to their documented rules.

Applications should avoid writing custom absolute tick comparisons using ordinary signed arithmetic. Use the kernel's timing APIs and appropriate tick types.

Tick counter width depends on the FreeRTOS configuration, including configUSE_16_BIT_TICKS in applicable versions.

13. Important Design Considerations

  • Initialize xLastWakeTime before entering the periodic loop.
  • Use a positive period expressed in ticks.
  • Use pdMS_TO_TICKS() for millisecond conversion.
  • Keep periodic task execution time within the intended timing budget.
  • Account for higher-priority task interference and blocking.
  • Do not assume the function guarantees a deadline.
  • Define an overrun policy for tasks with strict timing requirements.
  • Measure actual timing on the target platform.

14. Practical Activity – Fixed-Period Task

Objective: Create a periodic task that performs an operation every 250 milliseconds using vTaskDelayUntil().

Procedure

  1. Define a task function named PeriodicTask.
  2. Declare xLastWakeTime.
  3. Set the period using pdMS_TO_TICKS(250).
  4. Initialize xLastWakeTime with xTaskGetTickCount().
  5. Perform the periodic operation.
  6. Call vTaskDelayUntil() to wait for the next scheduled release.
  7. Observe the timing using a supported trace or debugger facility.
  8. Compare the actual execution interval with the configured period.

Expected Result

The task attempts to execute at 250 millisecond intervals. Its scheduled period is maintained independently of normal operation execution time, provided that the task can meet its schedule.

17. Lesson Summary

  • vTaskDelayUntil() supports fixed-period task scheduling.
