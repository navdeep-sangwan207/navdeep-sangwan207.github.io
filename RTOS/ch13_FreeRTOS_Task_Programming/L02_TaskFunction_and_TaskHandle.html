Task Function and Task Handle

Task Declaration, TaskHandle_t, Identification and Handle Management

1. Learning Objectives

FreeRTOS uses task functions to define the work performed by individual tasks. A task handle provides an application-level reference to a task and allows selected kernel APIs to operate on that task.

  • Understand the FreeRTOS task function prototype.
  • Learn the role of pvParameters.
  • Understand the TaskHandle_t data type.
  • Create and store task handles.
  • Use task handles with task-management APIs.
  • Pass task handles between functions.
  • Understand handle validity and task lifetime.

2. FreeRTOS Task Function

A task function contains the instructions that a FreeRTOS task executes. The function is supplied to the kernel when the task is created.

General Syntax

void TaskFunction(void *pvParameters)
{
    for (;;)
    {
        /* Task operations */
    }
}

Function Components

Component Description
void The task function does not return a value.
TaskFunction The name of the task function.
void *pvParameters A pointer to optional application data passed during task creation.
for (;;) A common infinite loop for a continuously running task.
The function signature must match the FreeRTOS task-function type. Do not declare a task function with an incompatible return type or parameter list.

3. Example of a Simple Task Function

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        /* Sensor processing */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

Explanation

  1. The function is named SensorTask.
  2. pvParameters can receive application data.
  3. The infinite loop keeps the task active.
  4. The task performs its sensor-processing operation.
  5. vTaskDelay() places the task in the Blocked state for the specified tick interval.

4. What Is a Task Handle?

A task handle is an application-visible reference to a FreeRTOS task. It is represented by the data type TaskHandle_t. 

TaskHandle_t sensorTaskHandle;

Once a task is created successfully, its handle can be stored and used with APIs that operate on a particular task.

Common Uses

  • Referencing a specific task.
  • Suspending or resuming a task.
  • Deleting a task.
  • Changing or reading task priority.
  • Sending a direct task notification.
  • Retrieving task information where supported.
A TaskHandle_t is an opaque reference managed by FreeRTOS. It is not the Task Control Block itself. Application code must not modify internal TCB fields through a task handle.

5. Creating a Task and Storing Its Handle

The xTaskCreate() API creates a task dynamically. Its final parameter can receive the handle of the newly created task.

Syntax

BaseType_t xTaskCreate(
    TaskFunction_t pvTaskCode,
    const char * const pcName,
    configSTACK_DEPTH_TYPE usStackDepth,
    void *pvParameters,
    UBaseType_t uxPriority,
    TaskHandle_t *pxCreatedTask
);

The exact declaration and stack-depth type can vary with FreeRTOS version and configuration. Consult the headers shipped with the selected kernel release.

Example

TaskHandle_t sensorTaskHandle = NULL;

BaseType_t result;

result = xTaskCreate(
    SensorTask,
    "Sensor",
    256,
    NULL,
    2,
    &sensorTaskHandle
);

if (result == pdPASS)
{
    /* Task created successfully */
}
else
{
    /* Task creation failed */
}

Explanation

  • SensorTask is the task function.
  • "Sensor" is the task name.
  • 256 is the requested stack depth in stack words for common FreeRTOS configurations.
  • NULL means no task parameter is supplied.
  • 2 is the task priority.
  • &sensorTaskHandle supplies the address where the created task handle is stored.
The handle is valid for use after successful task creation. Check the return value before using it.

6. Task Handle Initialization

A task handle can be initialized to NULL before the corresponding task is created. 

TaskHandle_t communicationTaskHandle = NULL;

Initializing a handle to NULL makes it easier to distinguish an unassigned handle from a successfully stored task reference.

Example

if (communicationTaskHandle != NULL)
{
    vTaskSuspend(communicationTaskHandle);
}

The check prevents an API from being called with an uninitialized handle. It does not, by itself, prove that a non-NULL handle still refers to a live task.

7. Using a Task Handle with Task APIs

Several FreeRTOS APIs accept a task handle to identify the task on which an operation should be performed.

API Purpose
vTaskSuspend() Suspends the specified task.
vTaskResume() Resumes a task that has been suspended.
vTaskDelete() Deletes the specified task.
vTaskPrioritySet() Changes the priority of a task.
uxTaskPriorityGet() Reads a task's priority.
xTaskNotify() Sends a direct task notification.

Example: Suspend and Resume

TaskHandle_t sensorTaskHandle = NULL;

/* After successful task creation: */

vTaskSuspend(sensorTaskHandle);

/* Later, when resumption is required: */

vTaskResume(sensorTaskHandle);
Suspending a task does not automatically release resources it owns. A suspended task may still hold a mutex or other resource. Design suspension and resumption carefully.

8. Getting the Current Task Handle

FreeRTOS provides xTaskGetCurrentTaskHandle() to obtain the handle of the task that is currently executing.

Syntax

TaskHandle_t xTaskGetCurrentTaskHandle(void);

Example

void SensorTask(void *pvParameters)
{
    TaskHandle_t currentTask;

    currentTask = xTaskGetCurrentTaskHandle();

    for (;;)
    {
        /* Use currentTask when needed */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

This API is useful when a task needs to identify itself, for example when registering a task handle for later notification.

Availability can depend on the FreeRTOS configuration, including INCLUDE_xTaskGetCurrentTaskHandle in configurations that use this inclusion option.

9. Passing a Task Handle to Another Function

A task handle can be passed to another function so that the function can operate on the referenced task.

Example

#include "FreeRTOS.h"
#include "task.h"

void SuspendTask(TaskHandle_t taskHandle)
{
    if (taskHandle != NULL)
    {
        vTaskSuspend(taskHandle);
    }
}

void ResumeTask(TaskHandle_t taskHandle)
{
    if (taskHandle != NULL)
    {
        vTaskResume(taskHandle);
    }
}

Application code can call these functions after storing the handle returned during successful task creation.

10. Passing Parameters and Task Handles Together

A task can receive a pointer to a structure containing several application parameters. A handle can be stored separately or included in an application-managed structure when appropriate.

Example

typedef struct
{
    int sensorChannel;
    int sampleIntervalMs;
} SensorConfig;

void SensorTask(void *pvParameters)
{
    SensorConfig *config =
        (SensorConfig *)pvParameters;

    for (;;)
    {
        /* Use config->sensorChannel */

        vTaskDelay(
            pdMS_TO_TICKS(config->sampleIntervalMs)
        );
    }
}

SensorConfig sensorConfig = {0, 500};

TaskHandle_t sensorTaskHandle = NULL;

BaseType_t result = xTaskCreate(
    SensorTask,
    "Sensor",
    256,
    &sensorConfig,
    2,
    &sensorTaskHandle
);

The configuration structure must remain valid while the task accesses it. In this example, it has static storage duration if declared at file scope.

11. Task Handle Lifetime and Validity

A task handle must only be used while it correctly identifies a valid task. Deleting a task ends the lifetime of that task object.

Important Rules

  • Initialize handles before task creation.
  • Check task creation success.
  • Do not use a handle after its task has been deleted.
  • Coordinate task deletion with other tasks that may use the handle.
  • Clear or update application-held references when the task is deleted.
  • Do not assume a non-NULL handle always represents a live task.

Example: Clear a Stored Handle

if (sensorTaskHandle != NULL)
{
    vTaskDelete(sensorTaskHandle);

    sensorTaskHandle = NULL;
}
This example is safe only when the application has exclusive control over the handle and no other task can concurrently use it. Shared handle updates require appropriate synchronization.

12. NULL Task Handle and Current Task Operations

Some FreeRTOS task APIs use a NULL task handle to indicate the calling task. The meaning of NULL is API-specific and should be checked in the relevant API documentation.

Example

vTaskDelete(NULL);

This deletes the task that calls the function. It is a common way for a task to delete itself.

Do not assume NULL has the same meaning for every FreeRTOS API. Follow the documentation for the particular function being used.

13. Common Mistakes in Task Function and Handle Usage

Mistake Problem Correct Approach
Incorrect task function prototype Incompatible function type. Use the required void-returning task function signature.
Using an uninitialized handle Invalid task reference. Initialize to NULL and check task creation success.
Using a handle after deletion Reference no longer identifies a live task. Coordinate deletion and update stored references.
Returning from a task function Task lifecycle is not handled correctly. Use an appropriate task termination method.
Passing a temporary parameter pointer Task may access expired storage. Ensure the pointed-to data remains valid.
Modifying TCB fields directly Can corrupt internal kernel state. Use documented FreeRTOS APIs.

14. Practical Activity – Task Handle Management

Objective: Create a task, store its handle and use the handle to control the task.

Procedure

  1. Declare a task function named SensorTask.
  2. Declare a variable of type TaskHandle_t.
  3. Initialize the handle to NULL.
  4. Create the task using xTaskCreate().
  5. Store the returned task handle.
  6. Check whether task creation was successful.
  7. Use the handle with a suitable task-management API.
  8. Verify task behavior using a supported debugger or trace facility.

Expected Result

A task is created successfully, its handle is stored, and the application can use that handle to identify and manage the task through documented FreeRTOS APIs.

16. Lesson Summary

  • A task function defines the work performed by a task.
  • The standard task function receives a void pointer parameter.
  • TaskHandle_t provides an application-visible reference to a task.
  • xTaskCreate() can return a handle through its final parameter.
  • Task handles are used with documented task-management APIs.

  • A task handle is not the internal TCB itself.
