2. Introduction to the FreeRTOS Scheduler

The scheduler is a central component of the FreeRTOS kernel. It selects a Ready task for execution according to task priorities and the configured scheduling policy.

Before the scheduler starts, the application normally creates its initial tasks using functions such as xTaskCreate() or xTaskCreateStatic(). These tasks are prepared for execution but do not begin normal scheduled operation until the scheduler starts.

Scheduler Startup Function

void vTaskStartScheduler(void);

The function initializes the scheduler and starts the first task according to the selected FreeRTOS port and configuration.

3. Syntax of vTaskStartScheduler()

void vTaskStartScheduler(void);
ParameterDescription
NoneThe function does not accept any parameters.

Return Behavior

In a normal successful startup, the scheduler continues running and vTaskStartScheduler() does not return to the application code.

It can return if the scheduler cannot be started, for example, when required memory allocation fails. Some ports also support stopping the scheduler through vTaskEndScheduler(), after which control may return to the calling code.

Do not write application logic that assumes vTaskStartScheduler() will return immediately after starting the scheduler.

4. Why Is vTaskStartScheduler() Required?

Creating a task and starting the scheduler are two different operations.

OperationFunctionPurpose
Task creationxTaskCreate()Creates a task and prepares its execution context.
Scheduler startupvTaskStartScheduler()Starts normal scheduled task execution.
Task deletionvTaskDelete()Deletes a specified task.
Task delayvTaskDelay()Blocks the calling task for a specified tick interval.

Without scheduler startup, tasks created by the application will not begin normal multitasking execution.

5. Scheduler Startup Sequence

A typical FreeRTOS application follows this sequence: 

Reset / Hardware Startup
          |
          v

          v

          |

          |

Explanation

  1. The processor starts executing the application's startup code.
  2. Required hardware initialization is performed.
  3. Application tasks are created.
  4. Required queues, semaphores and other objects are initialized.
  5. vTaskStartScheduler() is called.
  6. The kernel prepares required internal tasks and scheduler resources.
  7. The port starts the first task.
  8. Normal multitasking begins.

6. Role of the Idle Task

FreeRTOS automatically creates an Idle Task when the scheduler starts. The Idle Task normally has the lowest task priority, which is zero in the standard FreeRTOS priority convention.

Functions of the Idle Task

  • Runs when no other Ready task can execute.
  • Provides an opportunity for cleanup of memory belonging to dynamically deleted tasks.
  • Can execute an application-defined Idle Hook if configured.
  • Provides an idle execution context for the kernel.

Idle Hook Configuration

#define configUSE_IDLE_HOOK 1

When enabled, the application can provide an Idle Hook function with the appropriate FreeRTOS-defined name and signature. 

void vApplicationIdleHook(void)
{
    /* Short, non-blocking background operation */
}
The Idle Hook must not block or call APIs that cause the Idle Task to enter the Blocked state. Keep its execution short so that kernel cleanup and other Idle Task responsibilities can proceed.

7. Timer Service Task

When FreeRTOS software timers are enabled, the kernel uses a Timer Service Task, also known as the Timer Daemon Task.

This task processes timer commands and executes software timer callback functions.

Related Configuration

#define configUSE_TIMERS                 1
#define configTIMER_TASK_PRIORITY        2
#define configTIMER_QUEUE_LENGTH          10
#define configTIMER_TASK_STACK_DEPTH      256

These values are illustrative. Actual settings must be selected according to the application's requirements and the selected FreeRTOS version.

The Timer Service Task is created when software timers are enabled and the scheduler starts. Its memory and configuration requirements must be considered during scheduler initialization.

8. Complete FreeRTOS Program

The following example creates two application tasks and starts the FreeRTOS scheduler. 

#include "FreeRTOS.h"
#include "task.h"

/* Task 1 */
void Task1(void *pvParameters)
{
    for (;;)
    {
        /* Perform Task 1 operation */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

/* Task 2 */
void Task2(void *pvParameters)
{
    for (;;)
    {
        /* Perform Task 2 operation */

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    BaseType_t result1;
    BaseType_t result2;

    /* Initialize hardware here */

    /* Create Task 1 */
    result1 = xTaskCreate(
        Task1,
        "Task1",
        256,
        NULL,
        2,
        NULL
    );

    /* Create Task 2 */
    result2 = xTaskCreate(
        Task2,
        "Task2",
        256,
        NULL,
        1,
        NULL
    );

    if ((result1 == pdPASS) &&
        (result2 == pdPASS))
    {
        /* Start FreeRTOS scheduler */
        vTaskStartScheduler();
    }

    /*
       Reaching here may indicate that
       task creation or scheduler startup failed.
    */
    for (;;)
    {
    }
}

Program Explanation

  1. FreeRTOS headers are included.
  2. Task1 and Task2 are defined.
  3. Task1 is created with priority 2.
  4. Task2 is created with priority 1.
  5. The return values of both task creation calls are checked.
  6. vTaskStartScheduler() is called if both tasks are created successfully.
  7. The scheduler selects Ready tasks according to priority and scheduling configuration.

When both tasks are Ready, Task1 has the higher priority. When Task1 blocks for its delay, Task2 or another Ready task can execute.

#define configSUPPORT_STATIC_ALLOCATION  1

#define configSUPPORT_DYNAMIC_ALLOCATION 1

10. Idle Task Memory and Static Allocation

When static allocation is used, the application must provide memory for kernel tasks that require static storage, including the Idle Task.

FreeRTOS provides an application callback for supplying the Idle Task's memory when the relevant static-allocation configuration is enabled. 

void vApplicationGetIdleTaskMemory(
    StaticTask_t **ppxIdleTaskTCBBuffer,
    StackType_t **ppxIdleTaskStackBuffer,
    configSTACK_DEPTH_TYPE *pulIdleTaskStackSize
)
{
    static StaticTask_t xIdleTaskTCB;
    static StackType_t xIdleTaskStack[
        configMINIMAL_STACK_SIZE
    ];

    *ppxIdleTaskTCBBuffer = &xIdleTaskTCB;
    *ppxIdleTaskStackBuffer = xIdleTaskStack;

    *pulIdleTaskStackSize =
        configMINIMAL_STACK_SIZE;
}
The exact callback signature can differ across FreeRTOS kernel versions. Older versions may use a different stack-depth parameter type. Use the prototype supplied by the selected kernel's headers and examples.

11. Scheduler Startup Failure Conditions

The scheduler may fail to start if required resources cannot be created or initialized.

Possible CauseExplanation
Insufficient heap memoryRequired kernel task or internal allocation cannot be completed.
Incorrect heap configurationThe selected heap implementation or size is unsuitable.
Invalid port integrationProcessor, compiler and FreeRTOS port configuration do not match.
Incorrect startup codeProcessor initialization or required port setup is incomplete.
Missing static memory callbackRequired static kernel-task memory is not supplied when configured.
Incorrect interrupt or timer setupPort-specific tick or interrupt initialization is not functioning correctly.

Basic Debugging Checklist

  • Verify all xTaskCreate() return values.
  • Check configTOTAL_HEAP_SIZE when using a heap implementation that uses it.
  • Verify the selected heap implementation.
  • Check static allocation callback requirements.
  • Verify processor and compiler compatibility with the FreeRTOS port.
  • Check system tick and interrupt initialization.
  • Inspect available heap and task diagnostic information.

12. Scheduler and Preemption

After the scheduler starts, FreeRTOS selects the highest-priority Ready task under its standard fixed-priority scheduling policy.

If preemption is enabled, a newly Ready task with a higher priority can preempt the currently running lower-priority task at an appropriate scheduling point.

Preemption Configuration

#define configUSE_PREEMPTION 1

When preemption is disabled, task switching follows cooperative scheduling behavior and depends on tasks yielding or entering appropriate kernel blocking operations.

Time Slicing Configuration

#define configUSE_TIME_SLICING 1

Time slicing can share execution among Ready tasks of equal priority, subject to the port and scheduler configuration.

13. vTaskStartScheduler() Versus vTaskEndScheduler()

FunctionPurpose
vTaskStartScheduler()Starts the FreeRTOS scheduler and normal task execution.
vTaskEndScheduler()Attempts to stop the scheduler and return to the calling context on ports that support it.
vTaskEndScheduler() is not supported by every FreeRTOS port. It should not be assumed to provide a portable way to stop and restart the scheduler. Check the selected port's documentation.

14. Practical Activity – Starting the Scheduler

Objective: Create two FreeRTOS tasks and start the scheduler.

Procedure

  1. Prepare a compatible FreeRTOS project and port.
  2. Include FreeRTOS.h and task.h.
  3. Write two task functions.
  4. Create both tasks using xTaskCreate().
  5. Check the return value of each task creation call.
  6. Call vTaskStartScheduler().
  7. Inspect task execution and state transitions using supported debugger or trace facilities.
  8. Check the behavior when task creation or memory allocation fails.

Expected Result

After successful initialization, the scheduler starts and selects Ready tasks according to their priorities and configured scheduling policy. If required startup resources cannot be allocated, the scheduler may fail to start and the application may continue after the function returns.

15. Important Notes for LPC2129 and Keil uVision

The LPC2129 uses an ARM7TDMI-S processor. A FreeRTOS application for this device requires a compatible ARM7 port, compiler integration, startup code, interrupt handling and tick source configuration.

  • Do not select a Cortex-M FreeRTOS port for the LPC2129.
  • Verify that the chosen FreeRTOS release contains or supports a compatible ARM7 port.
  • Verify compatibility with the selected Keil compiler and linker setup.
  • Check the tick interrupt implementation and context-switch assembly.
  • Do not assume the Keil simulator supports every peripheral or port-specific operation.
The examples in this lesson are generic FreeRTOS application examples. They are not proof that a working LPC2129 FreeRTOS project can be built and executed in the current Keil simulator setup.
