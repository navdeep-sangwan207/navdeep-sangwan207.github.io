1. Learning Objectives

Mutexes are essential for protecting shared resources in multitasking embedded applications. This lesson applies mutex concepts through practical FreeRTOS programming examples.

  • Create and delete FreeRTOS mutexes.
  • Protect shared variables from concurrent access.
  • Coordinate multiple tasks accessing a shared UART.
  • Understand mutex ownership and timeout handling.
  • Observe priority inheritance in a practical example.
  • Apply safe resource-management practices.

2. FreeRTOS Mutex API Overview

API Purpose
xSemaphoreCreateMutex() Creates a mutex dynamically.
xSemaphoreCreateMutexStatic() Creates a mutex using application-provided static memory, when supported and configured.
xSemaphoreTake() Attempts to acquire a mutex.
xSemaphoreGive() Releases a mutex owned by the calling task.
vSemaphoreDelete() Deletes a semaphore or mutex object when it is no longer in use.

Basic Syntax

SemaphoreHandle_t xMutex;

xMutex = xSemaphoreCreateMutex();

if (xMutex != NULL)
{
    if (xSemaphoreTake(xMutex, portMAX_DELAY) == pdTRUE)
    {
        /* Protected operation */

        xSemaphoreGive(xMutex);
    }
}
A FreeRTOS mutex is a special semaphore with ownership and priority inheritance behavior. The task that takes it must release it. Mutexes must not be used from an ISR.

3. Example 1 – Protecting a Shared Counter

Objective: Protect a shared counter accessed by two tasks.

Problem

Two tasks increment the same global counter. Without synchronization, concurrent read-modify-write operations can cause lost updates.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xCounterMutex;

unsigned int counter = 0;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(xCounterMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            counter++;

            xSemaphoreGive(xCounterMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(xCounterMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            counter++;

            xSemaphoreGive(xCounterMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(150));
    }
}

int main(void)
{
    xCounterMutex = xSemaphoreCreateMutex();

    if (xCounterMutex != NULL)
    {
        xTaskCreate(TaskA, "TaskA", 256, NULL, 2, NULL);
        xTaskCreate(TaskB, "TaskB", 256, NULL, 2, NULL);

        vTaskStartScheduler();
    }

    for (;;);
}

Expected Behavior

  • Both tasks access the shared counter under mutex protection.
  • Only one task can execute the protected increment at a time.
  • The counter is protected against concurrent lost updates, assuming every access uses the same mutex.
The counter is incremented repeatedly, so there is no single final value. Inspect it during execution using a debugger. Any other task or ISR accessing this counter must follow an appropriate protection strategy as well.

4. Example 2 – Shared UART Resource Protection

Objective: Prevent two tasks from interleaving messages on a shared UART.

Problem

Two tasks transmit messages using the same UART peripheral. If transmission is not coordinated, bytes from the two messages may become interleaved.

Program Structure

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xUARTMutex;

/* Replace with the UART driver function for the target platform. */
void UART_SendString(const char *message)
{
    /*
     * Transmit the complete message using the configured UART driver.
     * This function is illustrative.
     */
}

void TaskSensor(void *pvParameters)
{
    const char message[] = "Sensor data received\r\n";

    for (;;)
    {
        if (xSemaphoreTake(xUARTMutex,
                           pdMS_TO_TICKS(100)) == pdTRUE)
        {
            UART_SendString(message);

            xSemaphoreGive(xUARTMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void TaskMonitor(void *pvParameters)
{
    const char message[] = "System monitoring active\r\n";

    for (;;)
    {
        if (xSemaphoreTake(xUARTMutex,
                           pdMS_TO_TICKS(100)) == pdTRUE)
        {
            UART_SendString(message);

            xSemaphoreGive(xUARTMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(700));
    }
}

int main(void)
{
    /* Initialize the UART driver before starting the tasks. */

    xUARTMutex = xSemaphoreCreateMutex();

    if (xUARTMutex != NULL)
    {
        xTaskCreate(TaskSensor, "Sensor", 256, NULL, 2, NULL);
        xTaskCreate(TaskMonitor, "Monitor", 256, NULL, 2, NULL);

        vTaskStartScheduler();
    }

    for (;;);
}

Expected Behavior

  • TaskSensor and TaskMonitor share the UART resource.
  • One task owns the mutex during its message transmission.
  • The other task waits until the mutex is released.
  • Complete messages are protected from task-to-task interleaving, provided the driver operation is synchronous and all callers use the same mutex.
If the UART driver uses interrupt-driven or DMA transmission, releasing the mutex immediately after starting transmission may not protect the complete transfer. Use a driver-level transaction mechanism or a dedicated UART-owner task with a queue. Do not block while holding a mutex waiting for a completion event if that event requires another task to acquire the same mutex.

5. Example 3 – Three Tasks Sharing One Resource

Objective: Coordinate three tasks accessing a shared resource.

Task Arrangement

Task Priority Operation
Task A 3 Updates shared data.
Task B 2 Reads shared data.
Task C 1 Checks shared data.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xDataMutex;

int sharedData = 0;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(xDataMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            sharedData += 10;

            xSemaphoreGive(xDataMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

void TaskB(void *pvParameters)
{
    int localCopy;

    for (;;)
    {
        if (xSemaphoreTake(xDataMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            localCopy = sharedData;

            xSemaphoreGive(xDataMutex);
        }

        /* Process localCopy outside the critical section. */

        vTaskDelay(pdMS_TO_TICKS(300));
    }
}

void TaskC(void *pvParameters)
{
    int localCopy;

    for (;;)
    {
        if (xSemaphoreTake(xDataMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            localCopy = sharedData;

            xSemaphoreGive(xDataMutex);
        }

        /* Perform checking outside the critical section. */

        vTaskDelay(pdMS_TO_TICKS(400));
    }
}

int main(void)
{
    xDataMutex = xSemaphoreCreateMutex();

    if (xDataMutex != NULL)
    {
        xTaskCreate(TaskA, "TaskA", 256, NULL, 3, NULL);
        xTaskCreate(TaskB, "TaskB", 256, NULL, 2, NULL);
        xTaskCreate(TaskC, "TaskC", 256, NULL, 1, NULL);

        vTaskStartScheduler();
    }

    for (;;);
}

Explanation

  • All three tasks use the same mutex.
  • Task A modifies the shared variable.
  • Task B and Task C take a consistent local snapshot.
  • Processing is performed after releasing the mutex to reduce blocking time.
The local snapshots in Task B and Task C are consistent at the time they are copied. They may become older than the current shared value immediately afterward.

6. Example 4 – Mutex and Priority Inheritance

Objective: Understand how a FreeRTOS mutex can reduce priority inversion.

Task Arrangement

Task Priority Operation
LowTask 1 Owns the mutex.
MediumTask 2 Performs unrelated processing.
HighTask 3 Requests the mutex and may block.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xResourceMutex;

void LowTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(xResourceMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            /*
             * Simulate a short protected operation.
             * Do not use this delay pattern in production
             * while holding a mutex unless explicitly justified.
             */
            vTaskDelay(pdMS_TO_TICKS(100));

            xSemaphoreGive(xResourceMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void MediumTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulate medium-priority processing. */

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

void HighTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(xResourceMutex,
                           portMAX_DELAY) == pdTRUE)
        {
            /* Perform high-priority resource operation. */

            xSemaphoreGive(xResourceMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(300));
    }
}

int main(void)
{
    xResourceMutex = xSemaphoreCreateMutex();

    if (xResourceMutex != NULL)
    {
        xTaskCreate(LowTask, "Low", 256, NULL, 1, NULL);
        xTaskCreate(MediumTask, "Medium", 256, NULL, 2, NULL);
        xTaskCreate(HighTask, "High", 256, NULL, 3, NULL);

        vTaskStartScheduler();
    }

    for (;;);
}

How Priority Inheritance Works

  1. LowTask acquires the mutex.
  2. HighTask becomes ready and requests the same mutex.
  3. HighTask blocks because LowTask owns the mutex.
  4. FreeRTOS can temporarily raise LowTask's effective priority to help it release the mutex sooner.
  5. LowTask releases the mutex.
  6. HighTask becomes eligible to run according to scheduler priority rules.
This program illustrates the API and task arrangement; it does not guarantee the exact inversion sequence on every execution. The medium task may not run at the intended point without controlled timing. Use a trace facility or controlled test harness to observe priority inheritance.

7. Example 5 – Safe Mutex Timeout Handling

Objective: Handle a mutex acquisition failure safely.

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xMutex;

void ResourceTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(xMutex,
                           pdMS_TO_TICKS(100)) == pdTRUE)
        {
            /* Access the protected resource. */

            xSemaphoreGive(xMutex);
        }
        else
        {
            /*
             * Mutex was not acquired.
             * Perform timeout handling here.
             */
        }

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

int main(void)
{
    xMutex = xSemaphoreCreateMutex();

    if (xMutex != NULL)
    {
        xTaskCreate(ResourceTask,
                    "Resource",
                    256,
                    NULL,
                    2,
                    NULL);

        vTaskStartScheduler();
    }

    for (;;);
}

Explanation

  • The task waits for a maximum of 100 RTOS ticks.
  • If the mutex is acquired, the protected operation executes.
  • If the wait expires, the task handles the failure without giving a mutex it does not own.
  • The application should define whether to retry, report a fault, skip the operation, or enter a safe state.
pdMS_TO_TICKS(100) converts 100 milliseconds to the configured RTOS tick count. The actual resolution depends on the FreeRTOS tick frequency.

8. Common Mutex Programming Errors

Error Consequence Correct Practice
Forgetting to give a mutex Other tasks may remain blocked. Use a clear acquire/release structure and check all execution paths.
Giving a mutex without owning it Violates mutex ownership rules. Only the owning task should release it.
Using mutex in an ISR Invalid blocking and ownership behavior. Use suitable FromISR synchronization APIs.
Holding mutex for too long Increases blocking and response time. Keep protected sections short.
Taking mutexes in inconsistent order Can create deadlock. Use a global lock ordering rule.
Ignoring timeout failure Application may use an unprotected resource. Handle failed acquisition explicitly.
Deleting a mutex while in use Can invalidate synchronization state. Ensure all users have stopped and ownership is released before deletion.

9. Mutex vs Critical Section

Feature Mutex Critical Section
Purpose Task-level mutual exclusion for shared resources. Protects a short section from specified interrupt or task interference according to the port's implementation.
Blocking Can block a task while waiting. Does not block waiting for ownership.
Ownership Has task ownership. Does not provide mutex-style ownership.
Priority inheritance FreeRTOS mutexes support priority inheritance. No mutex-style priority inheritance.
ISR use Cannot be taken or given from an ISR. Use only according to the specific port's ISR and critical-section rules.

10. Practical Activity

Activity A – Shared Counter

Objective: Verify mutex protection of a shared variable.

  1. Create two tasks that increment a shared counter.
  2. First run the program without a mutex.
  3. Then protect the increment operation with a mutex.
  4. Inspect the counter using the debugger.
  5. Compare the behavior and explain the role of mutual exclusion.

Activity B – Shared UART

Objective: Protect a shared serial communication resource.

  1. Create two tasks that send different messages.
  2. Use a shared mutex around each synchronous message transmission.
  3. Observe whether message bytes interleave.
  4. Consider how the design changes when using interrupt-driven or DMA transmission.

Activity C – Timeout Handling

Objective: Handle unsuccessful mutex acquisition.

  1. Create two tasks sharing one mutex.
  2. Use a finite timeout in one task.
  3. Make the other task hold the mutex for a controlled period.
  4. Observe successful acquisition and timeout cases.
  5. Implement an appropriate recovery action.
The FreeRTOS programs require a compatible FreeRTOS port or simulator. Your current LPC2129 Keil uVision setup should not be assumed to have a working FreeRTOS port. UART transmission also requires a correctly configured driver and suitable target or simulator support.

12. Lesson Summary

  • xSemaphoreCreateMutex() creates a FreeRTOS mutex.
  • xSemaphoreTake() acquires a mutex, and xSemaphoreGive() releases it.
  • Mutexes protect shared resources accessed by multiple tasks.
  • Priority inheritance can reduce priority inversion.
  • Mutexes have ownership and cannot be used from ISRs.
  • Timeout failures must be handled explicitly.
  • Short protected operations improve system responsiveness.
  • Consistent locking order helps prevent deadlock.
  • Queues and dedicated owner tasks are useful alternatives for complex peripheral access.
