2. Introduction to Task Yielding

Task yielding is the process in which a currently Running task voluntarily gives the scheduler an opportunity to select another Ready task.

Yielding is useful when a task has completed a portion of its work and does not need to continue using the CPU immediately.

Example

Consider two tasks:

  • Task A – processes communication data.
  • Task B – performs background calculations.

Task A can yield after completing a processing stage so that another eligible task can receive CPU time.

Yielding does not permanently stop a task. The task remains eligible for scheduling unless another operation changes its state.

3. Why Task Yielding Is Required

Task yielding can be useful in cooperative scheduling and in situations where an application explicitly wants to request a scheduling opportunity.

Main Reasons

  • Allow another eligible task to execute.
  • Improve cooperation between equal-priority tasks.
  • Reduce continuous execution by a task.
  • Support controlled scheduling points.
  • Improve responsiveness in suitable application designs.

Yielding alone does not provide synchronization, event waiting, or a guaranteed execution interval.

4. FreeRTOS taskYIELD()

FreeRTOS provides the taskYIELD() macro to request a context switch or scheduling opportunity.

Syntax

taskYIELD();

Example

void TaskA(void *pvParameters)
{
    for (;;)
    {
        Process_Data();

        taskYIELD();
    }
}

After the yield request, the scheduler may select another eligible task.

If no other task is eligible to run, or if no scheduling change is required, the calling task may continue executing. Yielding does not guarantee that a different task will run.

5. Task Yielding with Equal-Priority Tasks

Consider two Ready tasks having the same priority.

Task Priority State
Task A 2 Running
Task B 2 Ready

If Task A calls taskYIELD(), the scheduler may select Task B.

Before Yield:

Task A: RUNNING
Task B: READY

Task A calls taskYIELD()

After Yield:

Task A: READY
Task B: RUNNING

This illustrates the usual effect when another equal-priority task is eligible. Exact behavior depends on the scheduler implementation and configuration.

6. Yielding in Cooperative Scheduling

In cooperative scheduling, a task generally continues executing until it explicitly gives up the processor or blocks.

Example

void TaskA(void *pvParameters)
{
    for (;;)
    {
        Process_Part_One();

        taskYIELD();

        Process_Part_Two();
    }
}

The yield creates an opportunity for another eligible task to execute between the two processing stages.

In a preemptive scheduler, tasks may also be switched because of higher-priority task readiness, blocking, or other scheduling events.

7. Yielding vs Blocking

Task Yielding Task Blocking
Requests a scheduling opportunity. Waits for an event, timeout, or condition.
Task generally remains Ready. Task enters the Blocked state.
Does not specify a waiting period. May specify a timeout or delay.
Uses taskYIELD(). Uses APIs such as vTaskDelay() or queue receive.
If a task is waiting for data, use an appropriate blocking API rather than repeatedly yielding or polling. Blocking allows the kernel to schedule other work efficiently.

8. Task Resumption

Task resumption makes an explicitly suspended task eligible for scheduling again.

FreeRTOS provides the following API:

vTaskResume(TaskHandle_t xTaskToResume);

Example

TaskHandle_t displayHandle;

/* Resume a previously suspended task. */
vTaskResume(displayHandle);

After resumption, the task becomes Ready. It runs when selected by the scheduler.

9. Resuming a Task from an ISR

An interrupt service routine may need to make a suspended task Ready.

FreeRTOS provides xTaskResumeFromISR() in supported ports and versions.

Conceptual Example

void ExternalInterruptHandler(void)
{
    BaseType_t higherPriorityTaskWoken = pdFALSE;

    xTaskResumeFromISR(displayHandle);

    /* Port-specific ISR exit and yield handling
       must be used where required. */
}

This is a conceptual illustration. The exact ISR entry, exit, and yield handling depend on the FreeRTOS port.

Task suspension/resumption is not generally a reliable substitute for event communication. If an interrupt signals that data or an event is available, a task notification or semaphore is often more appropriate.

10. Task Notifications for Resumption and Event Signaling

FreeRTOS task notifications provide a direct mechanism for one task or an ISR to signal another task.

Important APIs

API Purpose
xTaskNotifyGive() Increments a task notification value and can unblock a task waiting for a notification.
ulTaskNotifyTake() Waits for a notification and optionally clears or decrements its value.
xTaskNotify() Sends a notification using a selected notification action.
xTaskNotifyFromISR() Sends a task notification from an ISR.

Example

void WorkerTask(void *pvParameters)
{
    for (;;)
    {
        ulTaskNotifyTake(
            pdTRUE,
            portMAX_DELAY
        );

        Process_Received_Event();
    }
}

void ControllerTask(void *pvParameters)
{
    for (;;)
    {
        if (Event_Occurred())
        {
            xTaskNotifyGive(workerHandle);
        }

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

The worker task blocks until a notification is received, then processes the event.

In this example, portMAX_DELAY requests an indefinite wait where supported by the configuration. Its exact behavior depends on FreeRTOS settings.

11. Yielding vs Preemption

Yielding Preemption
Voluntary scheduling request by a task. Scheduler switches away from a task due to scheduling conditions.
Usually initiated through taskYIELD(). Can occur when a higher-priority task becomes Ready.
Does not necessarily involve a higher-priority task. Often occurs because a higher-priority task becomes eligible.
Task remains Ready unless another state-changing operation occurs. Preempted task normally returns to Ready.

12. Context Switching During Yield

When yielding causes a task switch, the RTOS saves the current task context and restores the context of the selected task.

Typical Context Information

  • CPU registers.
  • Stack pointer.
  • Program counter or return address information.
  • Processor status information where required.
  • Other architecture-specific execution state.
Task A Running
      |
      v
taskYIELD()
      |
      v
Save Task A Context
      |
      v
Scheduler Selects Task B
      |
      v
Restore Task B Context
      |
      v
Task B Running

The precise context-switch mechanism depends on the processor architecture and RTOS port.

13. Complete Example: Two Tasks Using Yield

#include "FreeRTOS.h"
#include "task.h"

void TaskA(void *pvParameters)
{
    for (;;)
    {
        Process_Data_A();

        taskYIELD();
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        Process_Data_B();

        taskYIELD();
    }
}

int main(void)
{
    Hardware_Init();

    xTaskCreate(
        TaskA,
        "TaskA",
        128,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        TaskB,
        "TaskB",
        128,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Explanation:

  1. Two tasks are created at the same priority.
  2. Both tasks become eligible for execution.
  3. Task A performs its operation and yields.
  4. Task B may be selected next.
  5. Task B performs its operation and yields.
  6. The scheduler continues selecting eligible tasks.

This example illustrates voluntary yielding. Actual rotation depends on scheduler behavior and configuration.

14. Common Mistakes

  • Assuming taskYIELD() always switches to another task.
  • Using yield instead of blocking while waiting for an event.
  • Assuming a resumed task executes immediately.
  • Using vTaskResume() from an ISR.
  • Using task suspension as a substitute for synchronization.
  • Ignoring the task handle when resuming another task.
  • Writing a high-priority task that continuously executes without blocking.
  • Assuming all equal-priority tasks rotate in every configuration.

15. LPC2129 and Keil uVision Practical

The LPC2129 uses an ARM7TDMI-S processor and has a single CPU core. Task yielding can be studied conceptually through a scheduler model.

Suggested Exercises

16. Lesson Summary

  • Task yielding voluntarily gives the scheduler an opportunity to select another task.
  • FreeRTOS provides taskYIELD().
  • Yielding does not necessarily cause a different task to run.
  • A yielded task generally remains Ready.
  • Blocking places a task in the Blocked state until its wait condition is satisfied.
  • vTaskResume() resumes an explicitly suspended task.
  • xTaskResumeFromISR() supports task resumption from an ISR where available.
  • Task notifications provide efficient event signaling.
  • Yielding, preemption, blocking, and suspension are different scheduling operations.
  • A context switch saves and restores task execution context.
