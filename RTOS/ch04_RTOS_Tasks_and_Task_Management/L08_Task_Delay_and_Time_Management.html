2. Introduction to Task Delay

Task delay is a mechanism that temporarily prevents a task from executing for a specified period.

During the delay, the task enters the Blocked state. The scheduler can execute other eligible Ready tasks.

Example

Consider a temperature-monitoring task that reads a sensor every 100 milliseconds.

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        Read_Temperature();

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

After reading the temperature, the task blocks for approximately the requested delay interval, measured in RTOS ticks.

Task delay is useful for periodic operations, reducing unnecessary CPU usage, and allowing other tasks to execute.

3. RTOS System Tick

The system tick is a periodic timing event used by an RTOS kernel to maintain time-dependent operations.

A hardware timer typically generates periodic interrupts. The RTOS tick handler updates the kernel's tick count and processes timing-related task state changes.

Basic Tick Operation

       Hardware Timer
              |
              v
        Timer Interrupt
              |
              v
        RTOS Tick Handler
              |
              v
        Update Tick Count
              |
              v
        Check Delayed Tasks
              |
              v
        Make Eligible Tasks Ready

The tick handler does not necessarily cause a context switch on every tick. A switch is needed only when scheduling conditions require one.

4. Tick Frequency

Tick frequency indicates how many RTOS tick interrupts occur per second.

It is commonly represented by:

f_tick = Number of ticks per second

The tick period is the time between consecutive tick events.

Formula

T_tick = 1 / f_tick
Tick Frequency Tick Period
100 Hz 10 ms
250 Hz 4 ms
500 Hz 2 ms
1000 Hz 1 ms

Numerical Example

If the RTOS tick frequency is 1000 Hz:

T_tick = 1 / 1000

       = 0.001 seconds

       = 1 millisecond

Therefore, one tick represents a nominal time interval of 1 millisecond.

5. Tick Count

Tick count represents the number of RTOS tick events counted since the kernel's tick counter started.

It is used for managing task delays and timeouts.

Example

Assume:

  • Tick frequency = 1000 Hz.
  • Tick period = 1 ms.
  • Current tick count = 5000.

The approximate elapsed tick time is:

Elapsed time = Tick count × Tick period

             = 5000 × 1 ms

             = 5000 ms

             = 5 seconds

The tick count is a kernel timing counter, not necessarily a calendar clock or an accurate wall-clock time source.

6. FreeRTOS vTaskDelay()

The vTaskDelay() function blocks the calling task for a specified number of ticks.

Function Prototype

void vTaskDelay(TickType_t xTicksToDelay);

Example

void TaskFunction(void *pvParameters)
{
    for (;;)
    {
        Process_Data();

        vTaskDelay(100);
    }
}

If the tick period is 1 ms, the requested delay is 100 ticks, nominally 100 ms.

vTaskDelay(100) means 100 ticks, not automatically 100 milliseconds. The actual duration depends on the configured tick frequency.

7. pdMS_TO_TICKS() Macro

FreeRTOS provides pdMS_TO_TICKS() to convert milliseconds into RTOS ticks.

Syntax

pdMS_TO_TICKS(milliseconds)

Example

vTaskDelay(pdMS_TO_TICKS(100));

This requests a delay corresponding to 100 milliseconds, converted using the configured tick frequency.

More Examples

vTaskDelay(pdMS_TO_TICKS(10));

vTaskDelay(pdMS_TO_TICKS(100));

vTaskDelay(pdMS_TO_TICKS(1000));

These represent nominal delay requests of 10 ms, 100 ms, and 1000 ms respectively, subject to tick resolution and scheduling behavior.

Very short durations may convert to zero ticks. Check the conversion and use a suitable tick frequency or hardware timer when finer timing resolution is required.

8. Relative Delay

A relative delay specifies how long a task should wait from the time it calls the delay function.

FreeRTOS uses vTaskDelay() for relative delays.

Example

void MonitoringTask(void *pvParameters)
{
    for (;;)
    {
        Read_Sensor();

        Process_Data();

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

The delay starts when the task reaches the delay call. Therefore, the interval between successive task executions includes both processing time and the requested delay.

9. Absolute Delay

An absolute delay schedules a task to resume at a specified tick-based time relative to a maintained reference schedule.

FreeRTOS provides vTaskDelayUntil() for periodic task execution.

Function Prototype

void vTaskDelayUntil(
    TickType_t *pxPreviousWakeTime,
    TickType_t xTimeIncrement
);

The function updates the previous wake-time reference and delays the calling task until the next scheduled wake time when that time is still in the future.

Example

void PeriodicTask(void *pvParameters)
{
    TickType_t previousWakeTime;
    const TickType_t period =
        pdMS_TO_TICKS(100);

    previousWakeTime = xTaskGetTickCount();

    for (;;)
    {
        Perform_Periodic_Work();

        vTaskDelayUntil(
            &previousWakeTime,
            period
        );
    }
}

This structure maintains a regular tick-based execution schedule rather than adding the processing time to every delay interval.

10. Difference Between vTaskDelay() and vTaskDelayUntil()

vTaskDelay() vTaskDelayUntil()
Uses a relative delay. Uses an absolute wake-time reference.
Delay starts when the function is called. Wake time is based on the previous scheduled wake time.
Processing time adds to the interval between task starts. Helps maintain a regular periodic schedule.
Useful for simple delays and event spacing. Useful for periodic control and monitoring tasks.

Timing Illustration

vTaskDelay():

Work -- Delay -- Work -- Delay -- Work
       ^ Processing time adds to cycle

vTaskDelayUntil():

Work ---- Scheduled Wake ---- Work
Work ---- Scheduled Wake ---- Work
       Regular target periods

11. Periodic Task Execution

A periodic task executes repeatedly at a defined interval.

Examples include:

  • Reading a temperature sensor every 100 ms.
  • Updating a control algorithm every 10 ms.
  • Sending system status over UART every 500 ms.
  • Updating a display every 1 second.

Periodic Task Example

void TemperatureTask(void *pvParameters)
{
    TickType_t lastWakeTime;
    const TickType_t period =
        pdMS_TO_TICKS(100);

    lastWakeTime = xTaskGetTickCount();

    for (;;)
    {
        Read_Temperature();
        Calculate_Temperature();

        vTaskDelayUntil(
            &lastWakeTime,
            period
        );
    }
}

The example targets a 100 ms task period. Actual timing depends on tick resolution, execution time, interrupt interference, and scheduler behavior.

12. Time Management APIs

API Purpose
vTaskDelay() Blocks a task for a relative tick interval.
vTaskDelayUntil() Maintains an absolute periodic wake-time reference.
xTaskGetTickCount() Returns the current RTOS tick count.
xTaskGetTickCountFromISR() Returns the tick count from an ISR context.
pdMS_TO_TICKS() Converts milliseconds into tick units.
portTICK_PERIOD_MS Provides a port-defined tick-period conversion constant where available.

API availability and conversion behavior depend on the FreeRTOS version, port, and configuration.

13. Numerical Problems

Problem 1: Calculate Tick Period

Given tick frequency = 500 Hz, calculate the tick period.

T_tick = 1 / f_tick

       = 1 / 500

       = 0.002 seconds

       = 2 ms

Problem 2: Calculate Delay Time

A task requests 250 ticks at a 1000 Hz tick frequency.

Delay = Number of ticks × Tick period

      = 250 × 1 ms

      = 250 ms

Problem 3: Calculate Tick Count

How many ticks are required for a nominal 500 ms delay at 250 Hz?

Tick period = 1 / 250
            = 4 ms

Ticks = 500 / 4
      = 125 ticks

Problem 4: Periodic Task

A task must execute every 200 ms. The tick frequency is 1000 Hz.

Tick period = 1 ms

Period in ticks = 200 / 1

                = 200 ticks

14. Task Timing and Jitter

Task timing describes when a task starts, executes, and completes.

Jitter is the variation in timing across repeated task executions. It may affect the start time, completion time, or execution period.

Sources of Jitter

  • Interrupt activity.
  • Higher-priority task execution.
  • Critical sections and interrupt masking.
  • Context-switch overhead.
  • Tick resolution.
  • Variable execution time.
  • Resource blocking.
vTaskDelayUntil() helps maintain a periodic schedule, but it does not eliminate all timing jitter or guarantee a deadline.

15. Tick Counter Overflow

The RTOS tick count is stored in an integer type with a finite range. Eventually, the counter wraps around from its maximum value to zero.

FreeRTOS time-management functions are designed to handle tick-count wraparound according to the kernel's implementation.

Conceptual Example

Tick count:

4294967293
4294967294
4294967295
0
1
2
3

Application code that compares tick counts manually must use wraparound-safe techniques. Avoid assuming that the tick count always increases without resetting.

16. Delays and CPU Utilization

When a task blocks using a delay function, it does not continuously consume CPU time while waiting.

Example

Consider a task that performs 2 ms of work and then blocks for approximately 98 ms in a 100 ms cycle.

Work time = 2 ms
Cycle time = 100 ms

Approximate task CPU utilization:

U = (2 / 100) × 100

  = 2%

This is a simplified estimate. It excludes context-switch overhead, interrupt execution, and other kernel or application activity.

17. LPC2129 Timer and Time Management

The LPC2129 includes hardware timers that can generate timing events independently of an RTOS tick.

For the example configuration:

  • Peripheral clock (PCLK) = 15 MHz.
  • Prescaler register (PR) = 14999.
  • Timer counter increment frequency = 1 kHz.
  • Timer counter increment period = 1 ms.

Calculation

Timer increment frequency =
    PCLK / (PR + 1)

  = 15,000,000 / 15,000

  = 1000 Hz

Timer increment period = 1 ms

With an appropriate match-register and reset configuration, the hardware timer can generate periodic match events.

This LPC2129 timer calculation demonstrates hardware timing. It does not establish that a particular FreeRTOS port or tick configuration is available for the LPC2129. A hardware timer interrupt and an RTOS tick are related concepts but are not automatically the same event.

18. Common Programming Mistakes

  • Assuming one tick always equals one millisecond.
  • Using raw tick values without checking tick frequency.
  • Using vTaskDelay() when a stable periodic schedule is required.
  • Assuming vTaskDelayUntil() guarantees exact physical timing.
  • Ignoring zero-tick conversions for short delays.
  • Using long busy-wait loops instead of appropriate blocking mechanisms.
  • Assuming tick count is a real-time clock.
  • Comparing tick counts without considering wraparound.
  • Ignoring execution time when designing periodic tasks.

19. Lesson Summary

  • The RTOS tick provides a time base for kernel operations.
