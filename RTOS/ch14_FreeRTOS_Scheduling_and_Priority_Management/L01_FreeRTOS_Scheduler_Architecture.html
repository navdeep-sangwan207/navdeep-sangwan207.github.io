  • Understand preemptive and cooperative scheduling.
  • Distinguish scheduler behavior from interrupt handling.

2. Introduction to the FreeRTOS Scheduler

A scheduler determines which task should execute on the processor at a particular time. FreeRTOS normally uses a fixed-priority scheduler: among the Ready tasks, the scheduler selects a task with the highest configured priority.

A task can be Ready, Running, Blocked or Suspended. Only Ready tasks are eligible for normal task selection. A higher-priority task that is Blocked does not prevent a lower-priority Ready task from running.

A scheduler does not execute all tasks at the same time on a single-core microcontroller. It switches between task contexts to provide concurrent progress.

4. Task Control Block (TCB)

Each FreeRTOS task has an associated Task Control Block. The TCB contains information that the kernel needs to manage that task.

Typical TCB Information

  • Task stack pointer.
  • Task priority.
  • Task state and list-management information.
  • Task name, when name storage is configured.
  • Stack boundaries or related stack information, depending on configuration.
  • Task-specific kernel bookkeeping information.
The internal TCB structure is implementation specific. Its fields can change across kernel versions and configurations. Application code should use public FreeRTOS APIs rather than accessing or modifying internal TCB fields.

Task Handle

TaskHandle_t taskHandle = NULL;

xTaskCreate(
    MyTask,
    "MyTask",
    256,
    NULL,
    2,
    &taskHandle
);

TaskHandle_t is an opaque reference used to identify a task through supported APIs. It is not the TCB itself.

6. Ready Lists and Priority-Based Selection

FreeRTOS maintains internal lists to organize tasks by state and priority. Ready tasks are managed so that the scheduler can select a highest-priority Ready task.

Conceptually, a system with four configured priorities may have the following Ready tasks:

PriorityReady TasksSelection
3Task A, Task BHighest-priority Ready group.
2Task CSelected only when no priority-3 task is Ready.
1Task DSelected when higher-priority tasks are not Ready.
0Idle TaskRuns when no higher-priority task is Ready.

If multiple tasks share the same priority, time slicing may allow them to share processor time when enabled and when they remain Ready.

The exact internal list implementation is a kernel detail. The table illustrates scheduling behavior, not the complete internal data structure.

7. Role of the Tick Interrupt

The RTOS tick is a periodic timing event used by FreeRTOS to maintain its tick count and process time-based task delays.

For example, with a tick rate of 1000 Hz, the nominal tick interval is 1 millisecond. A task delayed for 100 ticks is scheduled to become Ready after approximately 100 tick intervals, subject to tick timing and scheduling.

Tick Rate Configuration

#define configTICK_RATE_HZ 1000

Tick Count API

TickType_t currentTick;

currentTick = xTaskGetTickCount();

xTaskGetTickCount() returns the current RTOS tick count. It is not a calendar clock or a high-resolution hardware timestamp.

What Happens During a Tick?

  1. The configured tick interrupt occurs.
  2. The port-specific interrupt handler performs required processing.
  3. The kernel updates its tick count.
  4. Time-based blocked tasks are checked for expiry.
  5. Tasks whose delays expire can become Ready.
  6. A scheduling decision may be requested if required.
A tick interrupt does not necessarily cause a context switch on every tick. A switch is needed only when scheduling conditions require one.

8. Context Switching

A context switch changes the currently executing task. The processor-specific port saves the outgoing task's required execution context and restores the context of the selected task.

Conceptual Steps

  1. A scheduling event occurs.
  2. The current task's execution context is saved.
  3. The scheduler determines the next task to run.
  4. The selected task's saved context is restored.
  5. Execution continues from the selected task's saved location.

The exact registers saved, stack operations and exception or interrupt mechanism depend on the processor architecture and FreeRTOS port.

9. Preemptive Scheduling

In preemptive scheduling, a higher-priority Ready task can interrupt the execution of a lower-priority task at an appropriate scheduling point.

Configuration

#define configUSE_PREEMPTION 1

Example

TaskPriorityState
Task A1Running
Task B3Blocked

When Task B becomes Ready, it has a higher priority than Task A. With preemption enabled, the scheduler can select Task B and preempt Task A.

10. Cooperative Scheduling

When preemption is disabled, a running task normally continues until it blocks, yields or otherwise reaches a kernel scheduling point. A higher-priority task becoming Ready does not necessarily interrupt the current task immediately.

Configuration

#define configUSE_PREEMPTION 0

Cooperative scheduling requires tasks to relinquish the processor appropriately. A task that never blocks or yields can prevent other tasks from receiving CPU time.

FeaturePreemptiveCooperative
Higher-priority Ready taskCan preempt a lower-priority running task.Waits for a scheduling point.
Task controlKernel can switch tasks at preemption points.Tasks must cooperate by yielding or blocking.
Response behaviorGenerally more responsive to newly Ready higher-priority tasks.Can suffer long delays if tasks do not yield.
Design considerationRequires careful shared-resource and timing design.Requires disciplined task execution.

11. Time Slicing Between Equal-Priority Tasks

When time slicing is enabled, FreeRTOS can rotate execution among Ready tasks at the same priority. This is useful when several tasks have equal scheduling priority.

Configuration

#define configUSE_TIME_SLICING 1

Time slicing is commonly associated with tick interrupt scheduling behavior. Its exact effect depends on the kernel version, scheduler configuration and port.

Time slicing does not mean that every task receives an identical amount of CPU time over all circumstances. Blocking, yielding, priority changes and execution readiness affect actual CPU allocation.

12. Idle Task and Scheduler Operation

The Idle Task is created automatically by FreeRTOS when the scheduler starts. It normally runs at priority zero.

  • Runs when no higher-priority task is Ready.
  • Supports cleanup of memory used by dynamically deleted tasks.
  • Can execute an application Idle Hook if enabled.
  • Provides a low-priority execution context.

The Idle Task must receive CPU time so that kernel cleanup can proceed. Applications should avoid continuously starving it.

14. Standard FreeRTOS Scheduling Model

The standard FreeRTOS scheduler uses fixed task priorities. It does not automatically schedule tasks according to Earliest Deadline First (EDF).

Scheduling ConceptStandard FreeRTOS Behavior
Fixed-priority schedulingSupported by the standard scheduler.
Priority-based preemptionSupported when preemption is configured.
Equal-priority time slicingSupported through scheduler configuration.
Automatic EDF schedulingNot the standard scheduler policy.
Automatic deadline guaranteeNot provided simply by using FreeRTOS.
An RTOS does not automatically guarantee that every task meets its deadline. Task execution times, blocking, interrupt interference, priorities and system workload must be analyzed.

15. Practical Example – Observe Scheduler Selection

Objective: Create two tasks with different priorities and observe how Ready and Blocked states affect task selection.

#include "FreeRTOS.h"
#include "task.h"

volatile unsigned long taskA_Count = 0;
volatile unsigned long taskB_Count = 0;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        taskA_Count++;

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        taskB_Count++;

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    BaseType_t resultA;
    BaseType_t resultB;

    resultA = xTaskCreate(
        TaskA,
        "TaskA",
        256,
        NULL,
        2,
        NULL
    );

    resultB = xTaskCreate(
        TaskB,
        "TaskB",
        256,
        NULL,
        1,
        NULL
    );

    if ((resultA == pdPASS) &&
        (resultB == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Procedure

  1. Build the application in a verified FreeRTOS target environment.
  2. Set breakpoints in both task functions.
  3. Inspect task states using supported debugger or trace facilities.
  4. Observe that TaskA has priority 2 and TaskB has priority 1.
  5. Observe how each task blocks after its delay.
  6. Inspect the counter variables while execution is running.

Expected Result

Both tasks execute when Ready. TaskA has higher priority, but when it is Blocked during its delay, TaskB can execute. The scheduler selects from the Ready tasks rather than simply choosing the task with the highest priority in the entire system.

ProblemCauseDesign Approach

Priority inversionHigh-priority task waits for a resource held by a lower-priority task.Use suitable mutexes and bounded resource holding.

17. Important Notes for ARM7 LPC2129

The LPC2129 uses an ARM7TDMI-S core. FreeRTOS scheduler context switching must be implemented by a port compatible with this processor and the selected compiler.

  • ARM7TDMI-S is not a Cortex-M processor.
  • ARM7 exception modes and interrupt handling differ from Cortex-M NVIC behavior.
  • The processor port must provide compatible context-switch and tick-interrupt code.
  • Do not use Cortex-M-specific interrupt-priority configuration assumptions for LPC2129.
  • Verify the availability and build compatibility of an ARM7 FreeRTOS port before attempting execution.
This lesson explains generic FreeRTOS scheduler architecture. It does not assume that the current LPC2129 Keil simulator setup contains a working FreeRTOS port.
