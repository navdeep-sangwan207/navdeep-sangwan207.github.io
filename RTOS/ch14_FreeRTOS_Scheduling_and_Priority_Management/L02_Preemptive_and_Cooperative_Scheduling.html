Preemptive and Cooperative Scheduling

Scheduling Policies, Task Preemption and Processor Control

1. Learning Objectives

Scheduling policy determines when a running task can be replaced by another Ready task. Two important scheduling approaches are preemptive and cooperative scheduling.

  • Understand preemptive scheduling.
  • Understand cooperative scheduling.
  • Compare their execution behavior.
  • Study task preemption conditions.
  • Understand the role of task priority.
  • Learn FreeRTOS scheduling configuration.
  • Analyze task execution timelines.
  • Identify the advantages and limitations of each approach.

2. Introduction to Scheduling Policies

A scheduling policy defines how the operating system selects a task and when it may switch from one task to another.

In FreeRTOS, the scheduling configuration determines whether a higher-priority Ready task can preempt a currently Running lower-priority task, or whether the current task must first reach a scheduling point.

Scheduling TypeBasic Principle
PreemptiveThe scheduler can replace a running task when a higher-priority task becomes Ready.
CooperativeA running task normally continues until it blocks, yields or reaches a scheduling point.

3. Preemptive Scheduling

Preemptive scheduling allows the kernel to interrupt the execution of a lower-priority task when a higher-priority task becomes Ready, subject to the processor port and scheduling configuration.

Example

Assume two tasks:

TaskPriorityInitial State
Task A1Running
Task B3Blocked

When Task B receives an event and becomes Ready, it has a higher priority than Task A. With preemption enabled, the scheduler can switch execution to Task B.

Execution Sequence

Time 0:
Task A is Running.
Task B is Blocked.

Time 1:
An event occurs.
Task B becomes Ready.

Time 2:
Task B has higher priority.
Task A is preempted.

Time 3:
Task B executes.

Time 4:
Task B blocks or completes its work.
Task A can become Running again.

4. Preemptive Scheduling Timeline

Consider the following conceptual timeline: 

Time       0      1      2      3      4      5
           |------|------|------|------|------|

Task A     RUN    RUN    PRE    PRE    RUN    RUN
Task B     BLK    BLK    RUN    RUN    BLK    BLK

BLK = Blocked
RUN = Running
PRE = Preempted / Ready

Task B becomes Ready at time 2 and preempts Task A because Task B has a higher priority. After Task B blocks, Task A can resume.

Preemption does not mean that the interrupted task is deleted. Its execution context is saved, and it normally remains Ready so that it can resume later.

5. Advantages of Preemptive Scheduling

  • Higher-priority tasks can respond promptly when they become Ready.
  • Useful for applications with different urgency levels.
  • Supports priority-based task management.
  • Allows low-priority tasks to be interrupted when necessary.
  • Useful for many embedded control and monitoring applications.

Limitations

  • Shared resources require careful synchronization.
  • Race conditions can occur if shared data is not protected.
  • Context switching introduces execution overhead.
  • Priority inversion can affect response time.
  • Poor priority assignment can cause starvation.

6. Cooperative Scheduling

In cooperative scheduling, a running task normally continues until it voluntarily blocks, yields or reaches a kernel scheduling point. A newly Ready higher-priority task does not necessarily preempt it immediately.

A task should periodically give other tasks the opportunity to execute.

Example

void TaskA(void *pvParameters)
{
    for (;;)
    {
        /* Perform a limited operation */

        taskYIELD();
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        /* Perform another operation */

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

taskYIELD() requests a scheduling decision. It does not guarantee that a different task will execute; another eligible task must be available.

7. Cooperative Scheduling Timeline

Consider a cooperative scheduler with Task A running and Task B becoming Ready. 

Time       0      1      2      3      4      5
           |------|------|------|------|------|

Task A     RUN    RUN    RUN    YIELD  READY  RUN
Task B     BLK    READY  READY  RUN    RUN    BLK

BLK   = Blocked
RUN   = Running
READY = Ready
YIELD = Task A voluntarily yields

Task B becomes Ready at time 1, but Task A continues until it reaches a scheduling point. At time 3, Task A yields and the scheduler can select Task B.

A cooperative task that never blocks or yields can prevent other tasks from executing. Long non-yielding operations must therefore be avoided.

8. Advantages and Limitations of Cooperative Scheduling

Advantages

  • Task switching occurs at controlled scheduling points.
  • Can simplify some execution-flow reasoning.
  • May reduce unnecessary preemption in suitable designs.
  • Can be useful in small systems with carefully bounded task operations.

Limitations

  • A task may delay other tasks if it does not yield.
  • Response time depends on the duration of non-yielding work.
  • Long-running tasks can make the system unresponsive.
  • Application developers must manage yielding and blocking carefully.

9. FreeRTOS Configuration for Preemption

The following configuration controls whether preemptive scheduling is enabled. 

#define configUSE_PREEMPTION 1

When this option is set to 1, the standard FreeRTOS scheduler supports preemptive priority-based scheduling.

When it is set to 0, the scheduler operates cooperatively in the traditional FreeRTOS configuration model.

Check the selected FreeRTOS version and port documentation for configuration details. Scheduler behavior also depends on task blocking, yielding and interrupt integration.

10. Cooperative Scheduling Configuration

A cooperative FreeRTOS configuration can be selected using: 

#define configUSE_PREEMPTION 0

Tasks should be designed to reach scheduling points regularly. Common ways to do this include:

  • Using vTaskDelay() to block for a relative interval.
  • Using vTaskDelayUntil() for periodic execution.
  • Waiting on queues, semaphores or event groups.
  • Calling taskYIELD() when appropriate.

Blocking on a kernel object is often preferable to repeatedly yielding because it avoids unnecessary CPU usage while waiting.

11. Preemptive vs Cooperative Scheduling

Shared resource designRequires careful synchronization.Still requires synchronization when access can overlap through interrupts or other mechanisms.

12. Task Priority and Preemption

In standard FreeRTOS, a larger numerical priority represents a higher task priority. A higher-priority Ready task takes precedence over lower-priority Ready tasks.

Example

TaskPriorityPurpose
ControlTask4Time-sensitive control operation
SensorTask3Sensor acquisition
CommunicationTask2Data transmission
LoggingTask1Background logging

If all four tasks are Ready, the scheduler selects ControlTask. If ControlTask blocks, SensorTask may run next.

Assigning a high priority does not guarantee a deadline will be met. Execution time, blocking, interrupt interference and other higher-priority workload must be considered.

13. Equal-Priority Tasks and Time Slicing

Two or more tasks may have the same priority. When time slicing is enabled, the scheduler can rotate execution among Ready tasks at that priority. 

#define configUSE_TIME_SLICING 1

For example, Task A and Task B both have priority 2. If both remain Ready, time slicing can allow them to share processor time.

Time slicing is not the same as preemption by a higher-priority task. It is a scheduling mechanism for equal-priority Ready tasks.

14. Practical Example – Comparing Scheduling Modes

Objective: Understand how preemptive and cooperative configurations affect task execution.

Example Program

#include "FreeRTOS.h"
#include "task.h"

volatile unsigned long lowCount = 0;
volatile unsigned long highCount = 0;

void LowPriorityTask(void *pvParameters)
{
    for (;;)
    {
        lowCount++;

        /* In cooperative mode, this gives
           another task a scheduling point. */
        taskYIELD();
    }
}

void HighPriorityTask(void *pvParameters)
{
    for (;;)
    {
        highCount++;

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void)
{
    BaseType_t result1;
    BaseType_t result2;

    result1 = xTaskCreate(
        LowPriorityTask,
        "LowTask",
        256,
        NULL,
        1,
        NULL
    );

    result2 = xTaskCreate(
        HighPriorityTask,
        "HighTask",
        256,
        NULL,
        3,
        NULL
    );

    if ((result1 == pdPASS) &&
        (result2 == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Procedure

  1. Build and run the example using a verified FreeRTOS port.
  2. First configure preemptive scheduling.
  3. Observe both task counters and task states.
  4. Configure cooperative scheduling and rebuild.
  5. Observe how taskYIELD() creates a scheduling point.
  6. Compare task execution and responsiveness.

Expected Result

In preemptive mode, the higher-priority task can preempt the lower-priority task when it becomes Ready. In cooperative mode, the lower-priority task must reach a scheduling point before another task can take over.

This is an illustrative scheduling experiment. Actual counter values and execution timing depend on the port, tick rate, compiler, debugger and processor speed.

15. Important Design Considerations

  • Keep task execution segments bounded.
  • Do not use busy loops as a replacement for blocking.
  • Use queues and synchronization objects appropriately.
  • Protect shared resources when concurrent access is possible.
  • Keep interrupt service routines short.
  • Consider priority inversion and starvation.
  • Measure worst-case execution time under realistic load.
  • Analyze blocking and interference before assigning priorities.
  • Test both normal operation and overload conditions.

16. ARM7 LPC2129 and Keil Simulator Notes

The LPC2129 uses an ARM7TDMI-S processor. A working FreeRTOS application requires a compatible ARM7 port and correct compiler, startup, interrupt and linker configuration.

  • Do not use Cortex-M-specific port files for LPC2129.
  • Verify the port's context-switch implementation.
  • Verify tick interrupt setup and interrupt return behavior.
  • Confirm that the selected Keil toolchain supports the port.
  • Confirm that the simulator can execute the required RTOS mechanisms.
The generic code in this lesson is not proof that FreeRTOS will execute on an LPC2129 Keil simulator project without a compatible port and integration.

18. Lesson Summary

  • Preemptive scheduling allows higher-priority Ready tasks to interrupt lower-priority task execution at appropriate scheduling points.
  • Cooperative scheduling relies on tasks reaching scheduling points.
  • FreeRTOS uses configUSE_PREEMPTION to configure the scheduling mode.
  • taskYIELD() requests a scheduling decision but does not guarantee another task will run.
  • Time slicing can rotate execution among equal-priority Ready tasks.
  • Both scheduling modes require careful task design and timing analysis.
  • Preemption alone does not guarantee real-time deadlines.
