2. Introduction to Time Slicing

Time slicing is a scheduling technique in which the processor's execution time is shared among eligible tasks of the same priority.

In a typical preemptive FreeRTOS configuration, when multiple tasks of equal priority remain Ready, the scheduler can rotate execution among them at tick boundaries.

Example

TaskPriorityState
Task A2Ready
Task B2Ready
Task C2Ready

All three tasks have equal priority. Time slicing can give each task an opportunity to execute while they remain Ready.

3. What Is a Time Slice?

A time slice is the interval associated with a scheduler rotation opportunity. In a typical FreeRTOS system using tick-based time slicing, the scheduling decision can occur at a tick interrupt.

For example, if the RTOS tick rate is 1000 Hz: 

Tick frequency = 1000 Hz

Tick period = 1 / 1000 second

Tick period = 1 millisecond

A tick represents a nominal time interval used by the kernel. It does not mean every task receives exactly one millisecond of CPU time in every situation.

The actual execution interval of a task depends on tick configuration, higher-priority tasks, interrupts, blocking, scheduler behavior and the processor port.

4. Introduction to Round-Robin Scheduling

Round-robin scheduling gives tasks an opportunity to execute in a repeating order. When a task's turn ends, the next eligible task receives processor time.

Assume three equal-priority tasks remain Ready and the scheduler rotates them at successive tick boundaries.

RUN   = Running

The diagram illustrates a possible rotation. Exact ordering depends on the kernel's ready-list handling and the timing of task state changes.

6. Time Slicing in FreeRTOS

FreeRTOS provides a configuration option for time slicing: 

#define configUSE_TIME_SLICING 1

When enabled in a preemptive configuration, the scheduler can rotate execution among equal-priority Ready tasks at tick interrupts.

When disabled, the tick does not perform the normal equal-priority time-slicing rotation. Tasks can still change state through blocking, yielding and other scheduling events.

Related Configuration

#define configUSE_PREEMPTION    1
#define configUSE_TIME_SLICING  1
#define configTICK_RATE_HZ      1000
Time slicing is associated with preemptive scheduling in the standard FreeRTOS kernel. Check the selected kernel version and port documentation for exact behavior.

7. Time Slicing vs Higher-Priority Preemption

Time slicing and priority-based preemption are different scheduling mechanisms.

8. Role of the RTOS Tick Interrupt

The RTOS tick interrupt provides periodic timing events to the kernel. It supports task delays, time measurement and scheduling operations.

Tick Operation

  1. A hardware timer generates a periodic interrupt.
  2. The FreeRTOS tick handler updates kernel time.
  3. Tasks whose delay periods have expired may become Ready.
  4. The scheduler evaluates the eligible tasks.
  5. A context switch may occur if required.
A tick interrupt does not automatically cause a task switch every time. A switch depends on the scheduling policy and the task states.

9. Equal-Priority Task Creation Example

The following example creates three tasks at the same priority. Each task performs a small operation and then delays. 

#include "FreeRTOS.h"
#include "task.h"

volatile unsigned long countA = 0;
volatile unsigned long countB = 0;
volatile unsigned long countC = 0;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        countA++;

        /* Allow other tasks to run */
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        countB++;

        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

void TaskC(void *pvParameters)
{
    for (;;)
    {
        countC++;

        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

int main(void)
{
    BaseType_t resultA;
    BaseType_t resultB;
    BaseType_t resultC;

    resultA = xTaskCreate(
        TaskA,
        "TaskA",
        256,
        NULL,
        2,
        NULL
    );

    resultB = xTaskCreate(
        TaskB,
        "TaskB",
        256,
        NULL,
        2,
        NULL
    );

    resultC = xTaskCreate(
        TaskC,
        "TaskC",
        256,
        NULL,
        2,
        NULL
    );

    if ((resultA == pdPASS) &&
        (resultB == pdPASS) &&
        (resultC == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Explanation

  • Three tasks are created.
  • All tasks use priority 2.
  • Each task increments its own counter.
  • Each task blocks for approximately 10 milliseconds.
  • While one task is Blocked, another Ready task can execute.

Because the tasks deliberately block, this example demonstrates equal-priority task sharing and blocking behavior. It does not isolate tick-driven time slicing by itself.

10. Practical Example – Observing Tick-Based Rotation

Objective: Observe how equal-priority Ready tasks share processor time.

Example Program

#include "FreeRTOS.h"
#include "task.h"

volatile unsigned long taskACount = 0;
volatile unsigned long taskBCount = 0;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        taskACount++;

        /* Deliberately remain Ready.
           Observe using a debugger or trace tool. */
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        taskBCount++;

        /* Deliberately remain Ready.
           Observe using a debugger or trace tool. */
    }
}

int main(void)
{
    BaseType_t resultA;
    BaseType_t resultB;

    resultA = xTaskCreate(
        TaskA,
        "TaskA",
        256,
        NULL,
        2,
        NULL
    );

    resultB = xTaskCreate(
        TaskB,
        "TaskB",
        256,
        NULL,
        2,
        NULL
    );

    if ((resultA == pdPASS) &&
        (resultB == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Procedure

  1. Enable preemptive scheduling.
  2. Enable time slicing.
  3. Build and run on a verified FreeRTOS target or port.
  4. Inspect taskACount and taskBCount using a debugger or trace tool.
  5. Observe which task is Running at successive scheduling intervals.
  6. Disable time slicing and repeat the experiment.
  7. Compare the execution behavior.

Expected Result

With time slicing enabled, both continuously Ready equal-priority tasks should receive processor time through scheduler rotation. With time slicing disabled, the tick alone does not perform the normal equal-priority rotation. Other scheduling events can still cause a task switch.

This example contains intentional busy loops for observing scheduler behavior. It consumes processor time and should be used only as a short controlled experiment, not as a production application design.

11. What Happens When a Task Blocks?

Time slicing applies to tasks that are eligible to execute. If a task blocks while waiting for a delay, queue, semaphore or event, it is removed from the Ready state.

The scheduler selects another Ready task, which may have the same priority or a lower priority if no higher-priority task is Ready. 

Task A: Running
Task B: Ready

Task A calls vTaskDelay()

Task A: Blocked
Task B: Running

Task A delay expires

Task A: Ready
Task B: Running or Ready
Scheduler selects according to priority
and scheduling policy.

12. Advantages of Time Slicing

  • Shares processor time among equal-priority tasks.
  • Prevents one continuously Ready task from monopolizing the processor under normal time-slicing operation.
  • Supports responsive multitasking.
  • Provides a simple way to schedule peer tasks.
  • Can improve fairness among tasks at the same priority.

Limitations

  • Context switching introduces overhead.
  • Tick frequency affects timing granularity and interrupt overhead.
  • Time slicing does not guarantee equal CPU usage.
  • Higher-priority tasks can still delay lower-priority tasks.
  • Shared resources still require synchronization.

13. Time Slicing and Real-Time Performance

Time slicing improves processor sharing among equal-priority tasks, but it is not a complete real-time scheduling solution.

For real-time applications, engineers must consider:

  • Task periods and deadlines.
  • Worst-case execution time.
  • Blocking time and resource contention.
  • Interrupt interference.
  • Context-switch overhead.
  • Tick rate and timing resolution.
  • Response-time and schedulability analysis.
A task can receive regular CPU time and still miss its deadline. Time slicing does not replace real-time scheduling analysis.

14. Important Notes for LPC2129 and Keil

The LPC2129 uses an ARM7TDMI-S processor. A real FreeRTOS experiment requires a compatible ARM7 port, correct tick interrupt setup and working context-switch integration.

  • Do not use Cortex-M-specific FreeRTOS port files.
  • Verify the selected port's tick handler.
  • Verify context-switch behavior at tick interrupts.
  • Confirm compiler, startup and linker integration.
  • Confirm Keil simulator support before expecting task rotation.
The examples are generic FreeRTOS code. They are not guaranteed to run on the LPC2129 Keil simulator without a verified ARM7 port.

16. Lesson Summary

  • Time slicing shares processor time among equal-priority Ready tasks.
  • Round-robin scheduling rotates execution among eligible peer tasks.
  • configUSE_TIME_SLICING controls the normal FreeRTOS time-slicing behavior.

  • Time slicing does not guarantee equal CPU usage or deadline satisfaction.
