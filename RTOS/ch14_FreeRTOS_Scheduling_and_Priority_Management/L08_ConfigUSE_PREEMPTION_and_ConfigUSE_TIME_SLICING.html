1. Learning Objectives

FreeRTOS provides configuration options that control important aspects of task scheduling. Two key options are configUSE_PREEMPTION and configUSE_TIME_SLICING.

  • Understand configUSE_PREEMPTION.
  • Understand configUSE_TIME_SLICING.
  • Configure preemptive and cooperative scheduling behavior.
  • Understand equal-priority task rotation.
  • Compare scheduling configurations.
  • Study the relationship between priorities and tick interrupts.
  • Understand scheduling implications of each configuration.
  • Apply the configuration in a FreeRTOS project.

2. Introduction to FreeRTOSConfig.h

FreeRTOS uses an application-specific configuration header called FreeRTOSConfig.h. It defines compile-time settings for kernel features and scheduling behavior.

This file commonly contains settings for:

  • Preemptive scheduling.
  • Time slicing.
  • Tick frequency.
  • Maximum task priorities.
  • Task notification support.
  • Software timers.
  • Memory allocation.
  • API inclusion and debugging options.

Example Configuration

#define configUSE_PREEMPTION       1
#define configUSE_TIME_SLICING     1
#define configTICK_RATE_HZ         1000
#define configMAX_PRIORITIES       5

3. configUSE_PREEMPTION

The macro configUSE_PREEMPTION controls whether the standard FreeRTOS scheduler uses preemptive scheduling. 

#define configUSE_PREEMPTION 1

When set to 1, a higher-priority task that becomes Ready can preempt a lower-priority Running task at an appropriate scheduling point.

When set to 0, the standard scheduler uses cooperative scheduling behavior. A running task generally continues until it blocks, suspends or explicitly yields, subject to kernel and port-specific scheduling behavior.

SettingBehavior
1Preemptive scheduling enabled.
0Cooperative scheduling mode.

4. configUSE_TIME_SLICING

The macro configUSE_TIME_SLICING controls normal tick-based rotation among equal-priority Ready tasks in the standard preemptive scheduler. 

#define configUSE_TIME_SLICING 1

When enabled, equal-priority Ready tasks can share processor time through rotation at tick interrupts.

When disabled, the tick does not perform the normal equal-priority time-slicing rotation. Tasks may still switch because they block, yield or otherwise cause a scheduling event.

SettingBehavior
1Tick-based time slicing enabled.
0Normal tick-based time slicing disabled.

5. Difference Between the Two Configuration Options

ParameterconfigUSE_PREEMPTIONconfigUSE_TIME_SLICING

Typical triggerHigher-priority task becomes Ready.Tick interrupt and eligible equal-priority tasks.

These macros control different aspects of scheduling. Time slicing is not a substitute for higher-priority preemption.

6. Configuration Combination 1 – Preemption Enabled and Time Slicing Enabled

#define configUSE_PREEMPTION    1
#define configUSE_TIME_SLICING  1

This is a common configuration for multitasking embedded applications.

  • Higher-priority Ready tasks can preempt lower-priority Running tasks.
  • Equal-priority Ready tasks can rotate at tick boundaries.
  • Tasks can block on delays, queues and semaphores.
  • The scheduler selects the highest-priority Ready task.

Example

TaskPriorityState
Task A3Running
Task B2Ready
Task C2Ready

Task A has the highest priority. Tasks B and C do not execute while Task A remains continuously Ready. When Task A blocks, B and C can share processor time through time slicing.

7. Configuration Combination 2 – Preemption Enabled and Time Slicing Disabled

#define configUSE_PREEMPTION    1
#define configUSE_TIME_SLICING  0

Higher-priority task preemption remains enabled. However, the tick does not perform the normal equal-priority rotation.

  • Higher-priority Ready tasks can still preempt lower-priority tasks.
  • Equal-priority tasks do not receive normal tick-based rotation.
  • Blocking and explicit yielding can still cause task switches.
  • Task execution order depends on scheduling events and Ready-list behavior.
Disabling time slicing does not mean equal-priority tasks can never switch. A task can still block, yield or be affected by another scheduling event.

8. Configuration Combination 3 – Preemption Disabled

#define configUSE_PREEMPTION 0

In cooperative scheduling mode, a running task normally continues until it reaches a scheduling point such as blocking, suspension or an explicit yield.

Example

void TaskA(void *pvParameters)
{
    for (;;)
    {
        /* Perform a short operation */

        taskYIELD();
    }
}

The explicit yield gives the scheduler an opportunity to select another eligible task. Without blocking or yielding, a task can prevent other application tasks from executing.

9. Configuration Comparison Table

For standard FreeRTOS kernel configurations, configUSE_TIME_SLICING is intended for the preemptive scheduler. Do not treat the preemption-disabled/time-slicing-enabled combination as an independent round-robin scheduler mode.

10. Example – Preemptive Scheduling

Consider two tasks with different priorities. 

#include "FreeRTOS.h"
#include "task.h"

volatile unsigned long lowCount = 0;
volatile unsigned long highCount = 0;

void LowTask(void *pvParameters)
{
    for (;;)
    {
        lowCount++;

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void HighTask(void *pvParameters)
{
    for (;;)
    {
        highCount++;

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

int main(void)
{
    BaseType_t lowResult;
    BaseType_t highResult;

    lowResult = xTaskCreate(
        LowTask,
        "Low",
        256,
        NULL,
        1,
        NULL
    );

    highResult = xTaskCreate(
        HighTask,
        "High",
        256,
        NULL,
        3,
        NULL
    );

    if ((lowResult == pdPASS) &&
        (highResult == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

HighTask has priority 3 and LowTask has priority 1. When both tasks are Ready, HighTask takes precedence. When HighTask blocks, LowTask can execute.

11. Example – Equal-Priority Time Slicing

The following example creates two equal-priority tasks that remain Ready for a controlled scheduling experiment. 

#include "FreeRTOS.h"
#include "task.h"

volatile unsigned long countA = 0;
volatile unsigned long countB = 0;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        countA++;
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        countB++;
    }
}

int main(void)
{
    BaseType_t resultA;
    BaseType_t resultB;

    resultA = xTaskCreate(
        TaskA,
        "TaskA",
        256,
        NULL,
        2,
        NULL
    );

    resultB = xTaskCreate(
        TaskB,
        "TaskB",
        256,
        NULL,
        2,
        NULL
    );

    if ((resultA == pdPASS) &&
        (resultB == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Expected Behavior

  • With preemption and time slicing enabled, both continuously Ready tasks can share processor time.
  • With time slicing disabled, the tick does not perform normal equal-priority rotation.
  • The experiment should be performed using a verified FreeRTOS target or port.
These busy-loop tasks intentionally consume CPU time. Use them only for a short scheduling experiment, not in production firmware.

12. Task Blocking and Explicit Yielding

Even when time slicing is disabled, tasks can give up the processor by entering the Blocked state or explicitly yielding.

Blocking Example

vTaskDelay(pdMS_TO_TICKS(100));

Yield Example

taskYIELD();

Blocking is appropriate when a task is waiting for time or an event. Yielding requests a scheduling decision but does not guarantee that another task will execute.

13. Relationship with configMAX_PRIORITIES

The maximum number of available task priority levels is configured through: 

#define configMAX_PRIORITIES 5

With this example, valid application priority values are 0 through 4.

PriorityMeaning
4Highest available priority.
3High priority.
2Medium priority.
1Low priority.
0Idle Task priority.

A higher numerical value represents a higher priority in the standard FreeRTOS scheduler.

14. Scheduling Configuration Best Practices

  • Select preemptive scheduling when higher-priority work must receive prompt processor access.
  • Use time slicing when equal-priority tasks should share execution time.
  • Choose task priorities based on timing requirements.
  • Avoid continuously Ready busy-loop tasks.
  • Use queues and semaphores for task synchronization.
  • Use mutexes for shared-resource ownership where appropriate.
  • Keep critical sections short.
  • Measure worst-case execution and response times.
  • Check stack and heap usage.
  • Verify the selected port's scheduling implementation.

15. Practical Experiment – Compare Scheduling Configurations

Objective: Observe the effect of preemption and time-slicing configuration on task execution.

Experiment A

#define configUSE_PREEMPTION    1
#define configUSE_TIME_SLICING  1

Observe higher-priority preemption and equal-priority rotation.

Experiment B

#define configUSE_PREEMPTION    1
#define configUSE_TIME_SLICING  0

Observe higher-priority preemption without normal tick-based equal-priority rotation.

Experiment C

#define configUSE_PREEMPTION 0

Observe cooperative scheduling behavior. Ensure tasks block or yield so that other tasks can run.

Procedure

  1. Back up the original FreeRTOSConfig.h file.
  2. Build a test application with two equal-priority tasks and one higher-priority task.
  3. Run Experiment A and record task execution.
  4. Change the configuration and rebuild for Experiment B.
  5. Repeat for Experiment C.
  6. Compare task execution order and scheduling behavior.
  7. Restore the intended production configuration.

Expected Result

The experiments demonstrate that preemption controls higher-priority task scheduling, while time slicing controls normal tick-based rotation among equal-priority Ready tasks in the preemptive scheduler.

17. Important Notes for LPC2129 and Keil

The LPC2129 uses an ARM7TDMI-S processor. The FreeRTOS scheduling configuration must be combined with a compatible ARM7 port.

  • Verify the port's context-switch implementation.
  • Verify tick interrupt integration.
  • Check compiler and startup-code compatibility.
  • Do not use Cortex-M-specific port assumptions.
  • Verify Keil simulator support before running the examples.
The programs in this lesson are generic FreeRTOS examples. They do not establish that the current LPC2129 Keil simulator setup supports FreeRTOS.

19. Lesson Summary

  • FreeRTOS scheduling options are defined in FreeRTOSConfig.h.
  • configUSE_PREEMPTION controls preemptive versus cooperative scheduling.
  • configUSE_TIME_SLICING controls normal tick-based rotation among equal-priority Ready tasks in the preemptive scheduler.
  • Higher-priority task preemption and equal-priority time slicing are different behaviors.
  • Blocking and yielding can cause task switches independently of normal tick-based rotation.
  • Correct task priorities and configuration are essential for predictable scheduling.
  • Processor-port behavior must be verified for the target MCU.
