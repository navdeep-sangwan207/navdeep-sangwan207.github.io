2. What Is an RTOS Tick?

An RTOS tick is a periodic timing event generated by a hardware timer or another time base configured for the selected processor port. The kernel uses this event to update its internal tick count.

The tick count provides a time reference for operations such as:

  • Task delay management.
  • Timeout calculations.
  • Time-based blocking.
  • Waking tasks whose delay has expired.
  • Time slicing among equal-priority Ready tasks, when enabled.

3. What Is Tick Rate?

Tick rate is the number of RTOS tick events generated per second. It is configured through the FreeRTOS configuration macro: 

#define configTICK_RATE_HZ 1000

The value 1000 means the kernel is configured for 1000 tick events per second.

Formula

Tick Period:

Tick Period = 1 / Tick Rate

For a tick rate of 1000 Hz: 

Tick Period = 1 / 1000
            = 0.001 second
            = 1 millisecond

4. Common Tick Rates

A higher tick rate provides finer tick-based timing granularity, but it also increases the frequency of tick interrupts and associated processing overhead.

Tick period is not the same as guaranteed task response time. Interrupt latency, scheduler activity and higher-priority work can delay actual task execution.

5. Hardware Timer Used for RTOS Tick

A hardware timer or system timer generates periodic interrupts. The FreeRTOS processor port configures this timer to provide the kernel tick.

General Timer Operation

  1. Configure the timer clock.
  2. Calculate the required timer interval.
  3. Configure the timer match or reload value.
  4. Enable the timer interrupt.
  5. Connect the interrupt to the FreeRTOS tick handler.
  6. Allow the kernel to update its time count on each tick.

The exact timer peripheral, interrupt vector and reload calculation depend on the microcontroller and FreeRTOS port.

6. Tick Frequency Calculation

For a simple timer that counts at frequency F and generates an interrupt every N timer counts: 

Tick Rate = Timer Count Frequency / N

If a timer counts at 1 MHz and the required tick rate is 1000 Hz: 

Timer Count Frequency = 1,000,000 Hz
Required Tick Rate    = 1,000 Hz

N = 1,000,000 / 1,000
  = 1,000 timer counts

The timer must therefore generate one tick after every 1000 timer counts, subject to the timer's counting convention and register semantics.

Real timer reload calculations must account for prescalers, inclusive counting, clock dividers, timer register behavior and integer rounding. Always verify the selected MCU reference manual.

7. FreeRTOS Tick Configuration

The tick rate is configured in FreeRTOSConfig.h. 

#define configTICK_RATE_HZ 1000

The tick type used by the kernel is TickType_t. Its width depends on the selected FreeRTOS configuration and port.

8. Tick Interrupt Processing

When the hardware timer generates the tick interrupt, the FreeRTOS port invokes the appropriate kernel tick-processing mechanism.

Typical Processing Steps

  1. Hardware timer generates an interrupt.
  2. Processor enters the appropriate interrupt handler.
  3. The port invokes the FreeRTOS tick-processing function.
  4. The kernel increments its tick count.
  5. Expired task delays and timeouts are processed.
  6. Tasks whose delays have expired can become Ready.
  7. A scheduling decision is made if required.
  8. The interrupt handler completes and execution resumes according to the port's context-switch mechanism.
The exact ISR wrapper and tick-processing function depend on the FreeRTOS port. Application code should not directly call internal kernel tick functions unless the port documentation specifically requires it.

9. Relationship Between Tick and Task Delay

FreeRTOS task delays are normally specified in ticks. The kernel uses the tick count to determine when a blocked task's delay expires.

Example

vTaskDelay(100);

At a tick rate of 1000 Hz, 100 ticks represent a nominal 100 milliseconds. 

Delay Time = Number of Ticks / Tick Rate

Delay Time = 100 / 1000

Delay Time = 0.1 second

Delay Time = 100 milliseconds

The task becomes eligible to run when its delay expires. It does not necessarily execute at that exact instant because other Ready tasks and interrupts may take precedence.

10. Converting Milliseconds to Ticks

FreeRTOS provides the pdMS_TO_TICKS() macro for converting milliseconds into the corresponding tick count. 

TickType_t delayTicks;

delayTicks = pdMS_TO_TICKS(100);

vTaskDelay(delayTicks);

Example at 1000 Hz

Tick Rate = 1000 Hz
Requested Delay = 100 ms

Ticks = 100 x 1000 / 1000

Ticks = 100

Important Limitation

If a requested delay is shorter than the tick resolution, conversion can produce zero ticks. For example, a 1 ms delay at 100 Hz is shorter than one 10 ms tick interval.

A zero-tick delay does not provide a positive time delay. Check converted values when designing short timing intervals.

11. Tick Rate and Timing Resolution

Tick resolution describes the granularity of time represented by the kernel tick.

Tick RateNominal Tick Resolution
100 Hz10 ms
500 Hz2 ms
1000 Hz1 ms

A 1 ms tick does not mean the operating system can guarantee every task will execute with 1 ms precision. Actual timing depends on interrupt latency, scheduling, execution time and the timer implementation.

12. Tick Count and Tick Overflow

The RTOS tick count is stored in an unsigned integer type. It therefore wraps around when the maximum representable value is reached.

For example, an illustrative 16-bit unsigned tick counter has a range from 0 to 65535. After reaching 65535, the next increment returns the count to zero.

FreeRTOS manages tick overflow in its internal timekeeping and delay mechanisms. Application code that calculates elapsed time should use wrap-safe unsigned arithmetic and appropriate kernel APIs.

Elapsed Time Example

TickType_t startTick;
TickType_t elapsedTicks;

startTick = xTaskGetTickCount();

/* Perform an operation */

elapsedTicks = xTaskGetTickCount() - startTick;

Unsigned subtraction supports wrap-around elapsed-time calculations when the measured interval is within the applicable counter range.

13. Tick Rate and CPU Overhead

Every tick interrupt requires processor time. A higher tick rate increases the number of interrupts processed per second.

Tick RateInterrupts per SecondGeneral Effect
100 Hz100Lower tick interrupt frequency.
500 Hz500Moderate tick interrupt frequency.
1000 Hz1000Higher tick interrupt frequency.
2000 Hz2000More frequent tick processing.

The best tick rate is selected according to application timing requirements, processor capacity, interrupt overhead and port support.

14. Tick Interrupt vs Context Switch

A tick interrupt and a context switch are different operations.

Tick InterruptContext Switch
A periodic timing event.A change from one task's execution context to another.
Updates kernel timekeeping.Saves and restores task execution state.
Processes delays and timeouts.Allows a different Ready task to execute.
May lead to a scheduling decision.Occurs only when required by scheduler and port behavior.
Not every tick interrupt causes a context switch. A switch occurs only when the scheduling conditions require one.

15. Tickless Idle

Tickless idle is a power-management technique in which periodic tick interrupts can be suppressed during a suitable idle period. The processor may enter a low-power state until an expected wake-up event.

Tickless idle can reduce power consumption in embedded systems, but it requires correct hardware timer and port-specific integration.

16. Practical Example – Reading the Tick Count

Objective: Read the current FreeRTOS tick count and observe elapsed ticks.

#include "FreeRTOS.h"
#include "task.h"

volatile TickType_t currentTick = 0;
volatile TickType_t startTick = 0;
volatile TickType_t elapsedTicks = 0;

void TickMonitorTask(void *pvParameters)
{
    startTick = xTaskGetTickCount();

    for (;;)
    {
        currentTick = xTaskGetTickCount();

        elapsedTicks = currentTick - startTick;

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void)
{
    BaseType_t result;

    result = xTaskCreate(
        TickMonitorTask,
        "TickMonitor",
        256,
        NULL,
        1,
        NULL
    );

    if (result == pdPASS)
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Procedure

  1. Configure the tick rate in FreeRTOSConfig.h.
  2. Create the TickMonitorTask.
  3. Start the scheduler.
  4. Inspect currentTick and elapsedTicks in the debugger.
  5. Observe how the tick count increases.
  6. Change the configured tick rate in a controlled test.
  7. Compare the relationship between ticks and elapsed time.

Expected Result

The current tick count increases as the kernel receives tick events. The elapsed tick count represents the number of ticks since the recorded starting value, subject to unsigned counter wrap-around.

17. Important Notes for LPC2129 and Keil

The LPC2129 has hardware timers that can generate periodic interrupts. A FreeRTOS port must configure an appropriate timer and connect it to the kernel tick mechanism.

For the user's LPC2129 clock configuration:

ParameterValue
FOSC12 MHz
CCLK60 MHz
PCLK15 MHz
Timer prescaler examplePR = 14999
Timer counter increment1 ms per TC increment

With PCLK = 15 MHz and PR = 14999: 

Timer Input Frequency = 15,000,000 Hz

Prescaler Divisor = PR + 1
                  = 15,000

TC Frequency = 15,000,000 / 15,000
             = 1,000 Hz

TC Increment Period = 1 ms

This is a useful hardware timer calculation for the LPC2129. It does not by itself configure a FreeRTOS tick port; the timer match value, interrupt handler and kernel integration must also be implemented correctly.

Do not assume that an existing standalone LPC2129 timer program is automatically a FreeRTOS tick implementation. A compatible ARM7 port and verified Keil integration are required.
