2. Introduction to Task Priority

A task priority represents its relative importance to the scheduler. In the standard FreeRTOS scheduler, a higher numerical priority represents a higher scheduling priority.

When multiple tasks are Ready, the scheduler normally selects a task from the highest-priority Ready group.

PriorityExample TaskTypical Responsibility
4ControlTaskTime-sensitive control operation.
3SensorTaskPeriodic sensor acquisition.
2CommunicationTaskData transmission and reception.
1LoggingTaskBackground data logging.
0Idle TaskKernel idle processing.
These priority values are illustrative. Actual priorities must be selected from the application's timing requirements and scheduling analysis.

3. Priority Levels in FreeRTOS

FreeRTOS provides a configurable number of priority levels. The number of levels is defined using configMAX_PRIORITIES in FreeRTOSConfig.h.

Configuration Example

#define configMAX_PRIORITIES 5

With five configured priority levels, the application priority values are: 

Priority 0
Priority 1
Priority 2
Priority 3
Priority 4

Priority zero is the lowest priority and is normally used by the automatically created Idle Task. Application tasks can be assigned higher levels.

configMAX_PRIORITIES defines the number of priority levels, not the maximum valid priority number. With a value of 5, valid priority values are 0 through 4.

4. Assigning Priority During Task Creation

The xTaskCreate() API accepts a priority parameter. This parameter determines the initial priority of the newly created task.

General Syntax

BaseType_t xTaskCreate(
    TaskFunction_t pxTaskCode,
    const char * const pcName,
    configSTACK_DEPTH_TYPE usStackDepth,
    void *pvParameters,
    UBaseType_t uxPriority,
    TaskHandle_t *pxCreatedTask
);

Example

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        /* Sensor operation */

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void LoggingTask(void *pvParameters)
{
    for (;;)
    {
        /* Logging operation */

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    xTaskCreate(
        SensorTask,
        "Sensor",
        256,
        NULL,
        3,
        NULL
    );

    xTaskCreate(
        LoggingTask,
        "Logging",
        256,
        NULL,
        1,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

SensorTask is assigned priority 3, while LoggingTask is assigned priority 1. If both are Ready, SensorTask is selected first.

5. Reading Task Priority

FreeRTOS provides uxTaskPriorityGet() to read the priority of a task.

Syntax

UBaseType_t uxTaskPriorityGet(
    TaskHandle_t xTask
);
  • Pass a valid task handle to read another task's priority.
  • In APIs where NULL means the calling task, NULL can be used to query the current task.
  • The function returns the task's current priority.

Example

TaskHandle_t sensorHandle = NULL;

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        UBaseType_t priority;

        priority = uxTaskPriorityGet(NULL);

        /* Inspect priority using debugger */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

Here, NULL identifies the calling task, so the task reads its own current priority.

6. Changing Task Priority at Runtime

FreeRTOS provides vTaskPrioritySet() to change the priority of an existing task.

Syntax

void vTaskPrioritySet(
    TaskHandle_t xTask,
    UBaseType_t uxNewPriority
);

The new priority must be within the configured range. Changing a task's priority can affect which task the scheduler selects next.

Example

#include "FreeRTOS.h"
#include "task.h"

TaskHandle_t taskHandle = NULL;

void WorkerTask(void *pvParameters)
{
    for (;;)
    {
        /* Perform worker operation */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void ManagerTask(void *pvParameters)
{
    for (;;)
    {
        if (taskHandle != NULL)
        {
            vTaskPrioritySet(taskHandle, 3);
        }

        vTaskDelay(pdMS_TO_TICKS(2000));
    }
}

int main(void)
{
    xTaskCreate(
        WorkerTask,
        "Worker",
        256,
        NULL,
        1,
        &taskHandle
    );

    xTaskCreate(
        ManagerTask,
        "Manager",
        256,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

ManagerTask periodically changes WorkerTask's priority to 3. The scheduler then considers WorkerTask at its new priority whenever it is Ready.

A task priority change does not automatically make a Blocked task Ready. It changes the priority used when the task is eligible for scheduling.

7. Understanding Priority-Based Preemption

In preemptive FreeRTOS configurations, a higher-priority task can preempt a lower-priority Running task when it becomes Ready.

Example Scenario

TaskPriorityInitial State
Task A1Running
Task B3Blocked

When an event makes Task B Ready, it becomes the highest-priority Ready task. Task A can be preempted, and Task B can execute. 

Task A: Running
Task B: Blocked

Event occurs

Task A: Ready
Task B: Running

Task B blocks

Task A: Running again

8. Same-Priority Tasks

Two tasks may have the same priority. When both are Ready, the scheduler may share processor time between them through time slicing when enabled.

Example

xTaskCreate(
    TaskA,
    "TaskA",
    256,
    NULL,
    2,
    NULL
);

xTaskCreate(
    TaskB,
    "TaskB",
    256,
    NULL,
    2,
    NULL
);

Both tasks have priority 2. Their execution depends on their Ready or Blocked states, time-slicing configuration and scheduling events.

9. Priority Inversion

Priority inversion occurs when a high-priority task is indirectly delayed by a lower-priority task that holds a resource the high-priority task needs.

Example

  1. Low-priority Task L takes a shared mutex.
  2. High-priority Task H becomes Ready and requests the same mutex.
  3. Task H blocks because Task L owns the mutex.
  4. Medium-priority Task M becomes Ready and executes.
  5. Task L cannot run to release the mutex, delaying Task H.

This can cause a lower-priority task to delay a higher-priority task indirectly.

Priority Inheritance

FreeRTOS mutexes support basic priority inheritance. A lower-priority mutex owner can temporarily inherit a higher priority while blocking a higher-priority task.

Priority inheritance helps reduce certain forms of priority inversion. It does not eliminate all blocking or guarantee that every deadline will be met.

10. Task Starvation

Starvation occurs when a task receives insufficient processor time because other tasks repeatedly take precedence.

Example

TaskPriorityBehavior
HighTask4Remains continuously Ready.
MediumTask2Rarely receives CPU time.
LowTask1May be starved.

Ways to Reduce Starvation

  • Ensure tasks block when waiting for events.
  • Avoid unnecessary high-priority busy loops.
  • Review priority assignments.
  • Use bounded execution periods.
  • Measure CPU utilization and task response time.

11. Priority Assignment Guidelines

Priority assignment should be based on the application's timing requirements rather than on the apparent importance of a task alone.

  • Identify task deadlines and periods.
  • Estimate worst-case execution time.
  • Consider blocking from shared resources.
  • Consider interrupt interference.
  • Analyze response time and schedulability.
  • Keep background operations at lower priorities where appropriate.
  • Avoid assigning unnecessarily high priorities.
  • Validate the design under worst-case workload.
A task that appears important is not automatically the task that should receive the highest priority. Priority assignment must follow a consistent scheduling analysis.

12. Practical Example – Dynamic Priority Management

Objective: Create two tasks and change the priority of one task while the scheduler is running.

Program

#include "FreeRTOS.h"
#include "task.h"

TaskHandle_t workerHandle = NULL;

volatile unsigned long workerCount = 0;
volatile unsigned long managerCount = 0;

void WorkerTask(void *pvParameters)
{
    for (;;)
    {
        workerCount++;

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

void ManagerTask(void *pvParameters)
{
    UBaseType_t currentPriority;

    for (;;)
    {
        managerCount++;

        if (workerHandle != NULL)
        {
            currentPriority =
                uxTaskPriorityGet(workerHandle);

            if (currentPriority == 1)
            {
                vTaskPrioritySet(
                    workerHandle,
                    3
                );
            }
            else
            {
                vTaskPrioritySet(
                    workerHandle,
                    1
                );
            }
        }

        vTaskDelay(pdMS_TO_TICKS(2000));
    }
}

int main(void)
{
    BaseType_t result1;
    BaseType_t result2;

    result1 = xTaskCreate(
        WorkerTask,
        "Worker",
        256,
        NULL,
        1,
        &workerHandle
    );

    result2 = xTaskCreate(
        ManagerTask,
        "Manager",
        256,
        NULL,
        2,
        NULL
    );

    if ((result1 == pdPASS) &&
        (result2 == pdPASS))
    {
        vTaskStartScheduler();
    }

    for (;;)
    {
    }
}

Procedure

  1. Create the WorkerTask and ManagerTask.
  2. Initially assign WorkerTask priority 1.
  3. Start the scheduler.
  4. ManagerTask reads WorkerTask's priority.
  5. ManagerTask changes its priority between 1 and 3.
  6. Inspect the priority and counter variables using debugger or trace facilities.

Expected Result

WorkerTask's priority alternates between 1 and 3 at approximately two-second intervals, subject to tick timing and task execution. Its scheduling position changes whenever its priority changes.

14. Important Notes for LPC2129 and Keil

The LPC2129 uses an ARM7TDMI-S processor. A working FreeRTOS project requires a compatible ARM7 port, compiler support and correct interrupt and context-switch integration.

  • Do not use Cortex-M-specific FreeRTOS port files.
  • Verify the selected port supports the compiler and processor.
  • Verify the simulator can execute the port's context-switch mechanism.
  • Check task stack and heap requirements.
  • Use debugger or trace tools only after the RTOS port is running correctly.
The code examples are generic FreeRTOS examples. They are not guaranteed to run in an ordinary LPC2129 Keil project without a compatible FreeRTOS port.
