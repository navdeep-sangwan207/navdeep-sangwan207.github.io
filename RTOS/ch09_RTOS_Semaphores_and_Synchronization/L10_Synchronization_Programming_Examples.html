1. Introduction

This lesson combines the synchronization concepts covered in the previous lessons and applies them to practical FreeRTOS programming scenarios.

The examples demonstrate how to use:

  • Binary semaphores for event notification.
  • Counting semaphores for event counting and resource availability.
  • Mutexes for shared resource protection.
  • Queues for data transfer between tasks.
  • ISR-safe APIs for interrupt-to-task communication.
Programming objective: Select the correct synchronization mechanism for each application instead of using semaphores for every type of communication.

2. Example 1 – Binary Semaphore for Task Synchronization

Application: One task performs an operation and signals another task when the operation is complete.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xSyncSemaphore;

void TaskA(void *pvParameters)
{
    for (;;)
    {
        /* Perform operation */
        PerformOperationA();

        /* Notify Task B */
        xSemaphoreGive(xSyncSemaphore);

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xSyncSemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            PerformOperationB();
        }
    }
}

int main(void)
{
    xSyncSemaphore = xSemaphoreCreateBinary();

    if (xSyncSemaphore == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(TaskA, "TaskA", 256, NULL, 2, NULL);
    xTaskCreate(TaskB, "TaskB", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Expected behavior

  • Task B waits for a semaphore token.
  • Task A performs its operation.
  • Task A gives the semaphore.
  • Task B becomes eligible to run and continues after a successful take.

Concept: Binary semaphore-based event notification.

3. Example 2 – Counting Semaphore for Event Counting

Application: Count multiple events generated by a producer task and process them in another task.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xEventSemaphore;

void EventProducerTask(void *pvParameters)
{
    for (;;)
    {
        GenerateEvent();

        if (xSemaphoreGive(xEventSemaphore) != pdTRUE)
        {
            /* Event count reached maximum */
            HandleEventOverflow();
        }

        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

void EventConsumerTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xEventSemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            ProcessOneEvent();
        }
    }
}

int main(void)
{
    xEventSemaphore =
        xSemaphoreCreateCounting(10, 0);

    if (xEventSemaphore == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(EventProducerTask, "Producer", 256, NULL, 2, NULL);
    xTaskCreate(EventConsumerTask, "Consumer", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Expected behavior

The semaphore count increases when events are generated and decreases when the consumer processes them. The maximum count is ten.

Concept: Counting semaphore-based event tracking.

4. Example 3 – Mutex for Shared Resource Protection

Application: Two tasks access a shared UART communication peripheral.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xUARTMutex;

void UARTTaskA(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xUARTMutex,
                portMAX_DELAY) == pdTRUE)
        {
            UART_SendString("Message from Task A\r\n");

            xSemaphoreGive(xUARTMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(300));
    }
}

void UARTTaskB(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xUARTMutex,
                portMAX_DELAY) == pdTRUE)
        {
            UART_SendString("Message from Task B\r\n");

            xSemaphoreGive(xUARTMutex);
        }

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

int main(void)
{
    xUARTMutex = xSemaphoreCreateMutex();

    if (xUARTMutex == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(UARTTaskA, "UART_A", 256, NULL, 2, NULL);
    xTaskCreate(UARTTaskB, "UART_B", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Expected behavior

Only one task owns the mutex at a time. The other task waits until the mutex becomes available.

A mutex is appropriate for task-level resource ownership. It is not an ISR synchronization mechanism.

5. Example 4 – Producer-Consumer Using a FreeRTOS Queue

Application: One task generates sensor readings and another task processes them.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include 

QueueHandle_t xSensorQueue;

void SensorProducerTask(void *pvParameters)
{
    uint16_t sensorValue;

    for (;;)
    {
        sensorValue = ReadSensor();

        if (xQueueSend(
                xSensorQueue,
                &sensorValue,
                pdMS_TO_TICKS(100)) != pdTRUE)
        {
            HandleQueueFull();
        }

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void SensorConsumerTask(void *pvParameters)
{
    uint16_t receivedValue;

    for (;;)
    {
        if (xQueueReceive(
                xSensorQueue,
                &receivedValue,
                portMAX_DELAY) == pdTRUE)
        {
            ProcessSensorValue(receivedValue);
        }
    }
}

int main(void)
{
    xSensorQueue = xQueueCreate(
        10,
        sizeof(uint16_t)
    );

    if (xSensorQueue == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(SensorProducerTask, "Sensor", 256, NULL, 2, NULL);
    xTaskCreate(SensorConsumerTask, "Process", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Expected behavior

  • The producer reads a sensor value.
  • The value is copied into the queue.
  • The consumer waits until an item is available.
  • The consumer receives and processes the value.

Concept: Queue-based data communication.

6. Example 5 – ISR-to-Task Communication Using a Binary Semaphore

Application: A hardware interrupt signals a task after an external event.

Program structure

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xInterruptSemaphore;

void ExternalInterruptHandler(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    /* Acknowledge the interrupt source */

    xSemaphoreGiveFromISR(
        xInterruptSemaphore,
        &xHigherPriorityTaskWoken
    );

    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

void InterruptProcessingTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xInterruptSemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            ProcessExternalEvent();
        }
    }
}

int main(void)
{
    xInterruptSemaphore = xSemaphoreCreateBinary();

    if (xInterruptSemaphore == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(
        InterruptProcessingTask,
        "IRQ_Task",
        256,
        NULL,
        3,
        NULL
    );

    /* Configure the hardware interrupt here */

    vTaskStartScheduler();

}

7. Example 6 – Resource Management Using a Counting Semaphore

Application: Manage access to a pool of three identical resources.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xResourceSemaphore;

void ResourceTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xResourceSemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            /* Obtain a specific free resource */
            UseAvailableResource();

            /* Return the resource availability token */
            xSemaphoreGive(xResourceSemaphore);
        }

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void)
{
    xResourceSemaphore =
        xSemaphoreCreateCounting(3, 3);

    if (xResourceSemaphore == NULL)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(ResourceTask, "Resource1", 256, NULL, 2, NULL);
    xTaskCreate(ResourceTask, "Resource2", 256, NULL, 2, NULL);
    xTaskCreate(ResourceTask, "Resource3", 256, NULL, 2, NULL);

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Concept: Counting semaphore-based resource availability.

The semaphore tracks the number of available resources, not their identities. A real resource pool also needs a free-resource list or queue and a correct ownership/release protocol.

8. Example 7 – Synchronization with a Finite Timeout

Application: A task waits for a communication event for a maximum of 500 milliseconds.

Program fragment

void CommunicationTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xCommunicationSemaphore,
                pdMS_TO_TICKS(500)) == pdTRUE)
        {
            ProcessCommunicationEvent();
        }
        else
        {
            HandleCommunicationTimeout();
        }
    }
}

Expected behavior

ConditionResult
Semaphore becomes available before timeoutTask obtains it and processes the event.
No semaphore token becomes availableTake returns failure after the timeout.
Token becomes available after timeoutIt may remain available for a later take.

9. Selecting the Correct Synchronization Mechanism

RequirementRecommended mechanism
Notify a task that an event occurredBinary semaphore or task notification.
Count pending eventsCounting semaphore.
Protect a shared resource between tasksMutex.
Transfer structured data between tasksQueue.
Coordinate multiple event conditionsEvent group.
Notify a task from an ISRISR-safe semaphore, queue, or task notification API.
Manage a pool of identical resourcesCounting semaphore plus resource ownership tracking.

10. Common Programming Mistakes

  • Using a binary semaphore when every event must be counted.
  • Using a semaphore instead of a queue when data must be transferred.
  • Using a binary semaphore as a mutex without considering ownership requirements.
  • Calling normal RTOS APIs from an ISR.
  • Using a mutex inside an ISR.
  • Ignoring semaphore creation failures.
  • Ignoring the return values of take, give, queue send, and queue receive operations.
  • Failing to release a mutex after a successful take.
  • Assuming a counting semaphore identifies a particular free resource.
  • Using shared variables without a proper ownership or synchronization protocol.
  • Assuming volatile makes shared data thread-safe.

11. Testing and Debugging Synchronization Programs

Synchronization problems can be difficult to reproduce because they depend on task scheduling and event timing.

Testing checklist

  1. Check that every synchronization object is created successfully.
  2. Verify task priorities and stack sizes.
  3. Test producer and consumer at different execution rates.
  4. Test full and empty queue conditions.
  5. Test semaphore timeout behavior.
  6. Test repeated interrupt events.
  7. Check for deadlocks and starvation.
  8. Inspect task states and semaphore counts where supported.
  9. Check stack usage and heap usage.
  10. Repeat tests under different timing conditions.
Debugging can change task timing. A program that appears correct while single-stepping may still contain race conditions under normal execution.

12. LPC2129 and Keil uVision Learning Considerations

The LPC2129 uses an ARM7TDMI-S processor. The synchronization examples in this chapter describe generic FreeRTOS APIs and concepts.

  • Keil uVision can be used to inspect registers, memory, and supported processor execution.
  • Actual FreeRTOS task execution requires a compatible port, startup code, interrupt configuration, and build setup.
  • Do not assume a Cortex-M FreeRTOS port or Cortex-M interrupt-priority configuration applies to LPC2129.
  • Use a verified FreeRTOS-supported target for practical execution if the LPC2129 toolchain setup does not provide a suitable port.

15. Lesson Summary

  • Binary semaphores coordinate task execution and event notification.
  • Counting semaphores count events or available resource tokens.
  • Mutexes protect shared resources between tasks.
  • Queues transfer data between tasks and provide built-in synchronization.
  • ISR-safe APIs allow interrupt-to-task communication.
  • Timeouts, overflow handling, resource ownership, and task priorities must be considered.
  • Correct synchronization requires testing under different timing and execution conditions.
