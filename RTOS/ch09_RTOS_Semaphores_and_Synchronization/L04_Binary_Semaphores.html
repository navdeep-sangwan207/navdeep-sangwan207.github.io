Binary Semaphores

Chapter 09 – Semaphores and Synchronization | Lesson 04

1. Introduction

A binary semaphore is a synchronization object that can hold one of two states: available or unavailable. It is commonly used to signal an event or coordinate execution between tasks.

In an RTOS, a task can wait for a binary semaphore. When another task or an interrupt service routine gives the semaphore, a waiting task can become ready to execute.

Key idea: A binary semaphore has a maximum count of one. It is useful for event signaling, such as notifying a task that a UART interrupt or sensor event has occurred.

2. What Is a Semaphore?

A semaphore is a synchronization mechanism used to coordinate execution or manage access to resources.

A semaphore generally maintains a count that determines whether a task can proceed or must wait.

Types of semaphores

TypePurpose
Binary semaphoreEvent signaling or simple synchronization.
Counting semaphoreCounting multiple events or managing a limited number of identical resources.
MutexMutual exclusion with task ownership semantics.

3. Binary Semaphore States

A binary semaphore has two possible states:

StateCountMeaning
Available / Given1A task can successfully take it.
Unavailable / Empty0A task attempting to take it must wait or fail, depending on the timeout.

Basic operation

       +----------------------+
       | Binary Semaphore     |
       +----------------------+
                  |
          +-------+-------+
          |               |
          v               v
     Count = 0       Count = 1
     Empty           Available
          |               |
          |               |
       Take waits      Take succeeds
       or fails        Count becomes 0

4. Binary Semaphore Operations

4.1 Take Operation

A task takes a semaphore to consume its available token.

If the semaphore is available, the take operation succeeds and the count becomes zero. If unavailable, the task may block for the specified timeout.

4.2 Give Operation

A task or an appropriate ISR gives the semaphore to make it available.

When a task is waiting, giving the semaphore can unblock one waiting task according to the scheduler's rules.

Important behavior

A binary semaphore cannot accumulate more than one token. If it is already available, another give does not create a second token.

5. Binary Semaphore Example

Consider a system with two tasks:

  • Task A: Waits for an event.
  • Task B: Detects the event and gives the semaphore.
       +-------------------+
       |      Task A       |
       |                   |
       | Wait for Event    |
       | xSemaphoreTake()  |
       +-------------------+
                 ^
                 |
                 |
       +-------------------+
       | Binary Semaphore  |
       +-------------------+
                 ^
                 |
                 |
       +-------------------+
       |      Task B       |
       |                   |
       | Detect Event      |
       | xSemaphoreGive()  |
       +-------------------+

Task A remains blocked until the semaphore becomes available. Once Task B gives it, Task A becomes eligible to execute.

6. Creating a Binary Semaphore in FreeRTOS

FreeRTOS provides the xSemaphoreCreateBinary() function.

Syntax

SemaphoreHandle_t xSemaphoreCreateBinary(void);

Return value

ReturnMeaning
Valid handleSemaphore created successfully.
NULLSemaphore creation failed, commonly because memory allocation failed.

Example

#include "FreeRTOS.h"
#include "semphr.h"

SemaphoreHandle_t xBinarySemaphore;

void CreateSemaphore(void)
{
    xBinarySemaphore = xSemaphoreCreateBinary();

    if (xBinarySemaphore == NULL)
    {
        /* Handle creation failure */
        for (;;)
        {
        }
    }
}
A newly created FreeRTOS binary semaphore is initially empty. It must be given before a task can successfully take it without waiting.

7. Taking a Binary Semaphore

The xSemaphoreTake() function is used by a task to obtain a semaphore.

Syntax

BaseType_t xSemaphoreTake(
    SemaphoreHandle_t xSemaphore,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xSemaphoreHandle of the semaphore.
xTicksToWaitMaximum time to wait, expressed in RTOS ticks.

Return values

Return valueMeaning
pdTRUESemaphore successfully taken.
pdFALSESemaphore was not obtained within the permitted wait time.

Example

if (xSemaphoreTake(
        xBinarySemaphore,
        portMAX_DELAY) == pdTRUE)
{
    /* Event received */
    ProcessEvent();
}

portMAX_DELAY requests an indefinite wait in common FreeRTOS configurations when the relevant suspension support is enabled.

8. Giving a Binary Semaphore

The xSemaphoreGive() function makes the semaphore available.

Syntax

BaseType_t xSemaphoreGive(
    SemaphoreHandle_t xSemaphore
);

Return values

Return valueMeaning
pdTRUEGive operation succeeded.
pdFALSEGive operation failed, for example because the semaphore was already available.

Example

if (xSemaphoreGive(xBinarySemaphore) == pdTRUE)
{
    /* Semaphore successfully given */
}

A successful give makes the token available. A waiting task may then be unblocked.

9. Complete FreeRTOS Binary Semaphore Program

This example demonstrates two tasks communicating through a binary semaphore.

#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

SemaphoreHandle_t xBinarySemaphore;

void EventTask(void *pvParameters)
{
    for (;;)
    {
        if (xSemaphoreTake(
                xBinarySemaphore,
                portMAX_DELAY) == pdTRUE)
        {
            /* Process the received event */
        }
    }
}

void EventGeneratorTask(void *pvParameters)
{
    for (;;)
    {
        /* Simulate an event */
        vTaskDelay(pdMS_TO_TICKS(1000));

        if (xSemaphoreGive(xBinarySemaphore) == pdTRUE)
        {
            /* Event notification sent */
        }
    }
}

int main(void)
{
    xBinarySemaphore = xSemaphoreCreateBinary();

    if (xBinarySemaphore == NULL)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
            EventTask,
            "EventTask",
            256,
            NULL,
            2,
            NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xTaskCreate(
            EventGeneratorTask,
            "Generator",
            256,
            NULL,
            2,
            NULL) != pdPASS)
    {
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program explanation

  1. Create a binary semaphore.
  2. Create the event-waiting task.
  3. Create the event-generator task.
  4. Start the scheduler.
  5. The event task blocks while the semaphore is empty.
  6. The generator task gives the semaphore after its delay.
  7. The event task becomes ready and processes the event.
  8. The event task takes the token, returning the semaphore to the empty state.

Expected behavior

The event task processes notifications generated approximately once per second, subject to scheduler timing and task execution.

10. Binary Semaphore for Interrupt-to-Task Communication

A common embedded application uses a binary semaphore to notify a task that an interrupt event has occurred.

Architecture

       +----------------------+
       | Hardware Event       |
       | UART / Timer / GPIO  |
       +----------------------+
                  |
                  v
       +----------------------+
       | Interrupt Service    |
       | Routine (ISR)        |
       +----------------------+
                  |
                  | Give semaphore
                  v
       +----------------------+
       | Binary Semaphore     |
       +----------------------+
                  |
                  v
       +----------------------+
       | Processing Task      |
       | Takes semaphore      |
       +----------------------+

Illustrative ISR code

void UART_ISR(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    /* Acknowledge and service the UART interrupt source */

    xSemaphoreGiveFromISR(
        xBinarySemaphore,
        &xHigherPriorityTaskWoken
    );

    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

Explanation:

  • xSemaphoreGiveFromISR() is the ISR-safe give operation.
  • The ISR must not use the normal task-context xSemaphoreGive() API.
  • The wake flag records whether a higher-priority task was unblocked.
  • The yield macro allows the scheduler to switch to an eligible higher-priority task when appropriate.
The exact ISR API and yield macro signature depend on the FreeRTOS port. The ISR must also acknowledge the actual peripheral interrupt source correctly. Do not copy this example as hardware-ready code without checking the selected port and peripheral documentation.

11. Binary Semaphore vs Mutex

Although both can be used for synchronization, they have different semantics.

FeatureBinary SemaphoreMutex
Primary purposeEvent signaling and synchronization.Mutual exclusion.
OwnershipNo ownership requirement.Task that takes it owns it.
Give operationCan be given by a task other than the one that took it; can also be given from an ISR using the ISR API.Must be released by the owning task.
Priority inheritanceNo.Yes, in FreeRTOS mutex implementations.
ISR usageISR-safe give API is available.Must not be used from an ISR.
Typical applicationNotify a task about an event.Protect a shared resource between tasks.
Use a binary semaphore to signal an event. Use a mutex to protect a shared resource that requires exclusive task ownership.

12. Binary Semaphore vs Counting Semaphore

FeatureBinary SemaphoreCounting Semaphore
Maximum count1Configured maximum value
Event accumulationMultiple gives can collapse into one available token.Can retain multiple tokens up to its maximum count.
Resource managementSimple event notification.Manage multiple identical resources.
ExampleNotify a task that an event occurred.Track available buffers or resource slots.

13. Important Limitation: Binary Semaphore Event Loss

A binary semaphore stores at most one pending token. Consider this sequence:

StepEventSemaphore count
1Initially empty0
2First event gives semaphore1
3Second event gives semaphore before a take1
4Task takes semaphore0

The task receives one notification token, not a count of two events.

If every event must be counted, use a counting semaphore, queue, or another mechanism that preserves the required event information. A binary semaphore is suitable when one or more pending events can be represented by a single notification.

14. Common Mistakes

  • Assuming a newly created binary semaphore is initially available.
  • Using a normal task API from an ISR.
  • Using a mutex in an ISR.
  • Assuming repeated gives are counted.
  • Ignoring semaphore creation failure.
  • Ignoring the return value of take and give operations.
  • Using a binary semaphore when every event must be preserved.
  • Assuming a semaphore automatically protects unrelated shared data.
  • Using the wrong ISR yield mechanism for the selected port.

15. Practical Applications

  • UART receive event notification.
  • Timer interrupt notification.
  • GPIO external event notification.
  • Sensor conversion-complete signaling.
  • Communication completion notification.
  • Task synchronization after hardware operations.
  • Notification that a shared buffer is ready for processing.

16. Practical Activity – Task Synchronization

Develop a two-task application using a binary semaphore.

Task A – Event Handler

  1. Create an event-processing task.
  2. Make the task wait on a binary semaphore.
  3. Process an event after successfully taking the semaphore.

Task B – Event Generator

  1. Create an event-generator task.
  2. Generate a simulated event periodically.
  3. Give the binary semaphore.
  4. Check whether the give operation succeeded.

Expected result

The event-handler task remains blocked until it receives a semaphore token. It then processes the notification and waits again.

18. Lesson Summary

  • A binary semaphore has two states: empty and available.
  • It is commonly used for task synchronization and event notification.
  • xSemaphoreCreateBinary() creates a binary semaphore.
  • xSemaphoreTake() obtains the semaphore token.
  • xSemaphoreGive() makes the token available.
  • xSemaphoreGiveFromISR() is used to give a semaphore from an ISR.
  • A binary semaphore does not provide mutex ownership or priority inheritance.
  • Repeated events can collapse into one pending notification.
  • Use a counting semaphore or queue when event counts or event data must be preserved.
