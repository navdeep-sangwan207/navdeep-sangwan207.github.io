1. Introduction

Scheduling algorithms determine the order in which processes or real-time tasks receive CPU execution time. Numerical analysis helps us understand scheduling behavior, calculate waiting and response times, and determine whether task deadlines can be satisfied.

This lesson combines the major scheduling algorithms studied in this chapter:

  • First Come First Served (FCFS)
  • Round Robin (RR)
  • Priority-Based Scheduling
  • Rate Monotonic Scheduling (RMS)
  • Earliest Deadline First (EDF)
  • CPU utilization and response-time analysis

2. Important Scheduling Terminology

Parameter Meaning
AT Arrival Time: time when a process enters the Ready queue.
BT Burst Time: CPU execution time required by a process.
CT Completion Time: time when the process finishes.
TAT Turnaround Time: total time from arrival to completion.
WT Waiting Time: total time spent waiting in the Ready queue.
RT Response Time: time from arrival until first CPU execution.
C Worst-case or specified execution-time parameter used in real-time analysis.
T Task period or minimum inter-arrival time, depending on the task model.
D Task relative deadline.

3. Important Formulas

Turnaround Time

TAT = CT - AT

Waiting Time

WT = TAT - BT

Response Time

RT = First CPU Start Time - AT

Average Waiting Time

Average WT = Sum of Waiting Times / Number of Processes

Average Turnaround Time

Average TAT = Sum of Turnaround Times / Number of Processes

CPU Utilization for Periodic Tasks

U = Σ(Ci / Ti)

Rate Monotonic Sufficient Utilization Bound

Ubound = n(2^(1/n) - 1)

EDF Utilization Condition

U = Σ(Ci / Ti)

For independent periodic tasks on one preemptive processor,
with deadlines equal to periods:

U ≤ 1

7. Numerical Problem 4: Rate Monotonic Scheduling

Consider two independent periodic tasks.

Task Execution Time (C) Period (T) Deadline (D)
T12 ms5 ms5 ms
T23 ms10 ms10 ms

Step 1: Assign RMS Priorities

RMS assigns a higher fixed priority to the task with the shorter period.

  • T1 period = 5 ms: higher priority.
  • T2 period = 10 ms: lower priority.

Step 2: Calculate CPU Utilization

U = C1/T1 + C2/T2

  = 2/5 + 3/10

  = 0.4 + 0.3

  = 0.7

  = 70%

Step 3: Calculate RMS Sufficient Bound

Ubound = n(2^(1/n) - 1)

n = 2

Ubound = 2(2^(1/2) - 1)

       ≈ 0.8284

       ≈ 82.84%

Step 4: Compare Utilization

Actual Utilization = 70%

RMS Sufficient Bound = 82.84%

70% ≤ 82.84%
The task set satisfies the classical RMS sufficient utilization test under its assumptions.

Step 5: Construct the Schedule

RMS Schedule: 0 to 10 ms
T1
T2
T1
T2

0    2    5    7    10 ms

At 0 ms, T1 and T2 are released. T1 executes first because it has higher priority. T2 then executes until 5 ms. At 5 ms, the next T1 job is released and preempts T2. T1 completes at 7 ms, allowing T2 to finish its remaining execution before its deadline at 10 ms.

The RMS bound is sufficient, not necessary. A task set exceeding the bound is not automatically unschedulable. More detailed response-time analysis may establish feasibility.

8. Numerical Problem 5: Earliest Deadline First

Consider two independent periodic tasks with deadlines equal to their periods.

Task Execution Time Period Deadline
T12 ms5 ms5 ms
T24 ms10 ms10 ms

Step 1: Calculate Utilization

U = C1/T1 + C2/T2

  = 2/5 + 4/10

  = 0.4 + 0.4

  = 0.8

  = 80%

Step 2: Apply the EDF Condition

U ≤ 1

0.8 ≤ 1
Under the classical assumptions of independent periodic tasks on one preemptive processor, with deadlines equal to periods, this task set is schedulable under EDF.

Step 3: Understand Deadline Selection

EDF dynamically selects the Ready job with the earliest absolute deadline.

Illustrative EDF Schedule
T1
T2
T1
T2

0    2    5    7    10 ms

In this example, the first T1 job has an absolute deadline of 5 ms, while the first T2 job has an absolute deadline of 10 ms. T1 executes first. The next T1 job is released at 5 ms and has an earlier deadline than the unfinished T2 job, so T1 executes next.

9. Numerical Problem 6: CPU Utilization

Consider three periodic tasks:

Task Execution Time Period
T11 ms4 ms
T22 ms8 ms
T33 ms12 ms

Calculation

U = 1/4 + 2/8 + 3/12

  = 0.25 + 0.25 + 0.25

  = 0.75

  = 75%

The processor is required to execute these tasks for 75% of the available time under the specified periodic task model, excluding additional overhead.

Available CPU Capacity

Idle Capacity = 100% - 75%

              = 25%
This 25% is nominal unused capacity under the ideal task utilization model. Actual available capacity is lower when interrupt processing, kernel overhead and other execution demands are included.

10. Numerical Problem 7: Response-Time Analysis

Consider two fixed-priority periodic tasks on a single processor. T1 has the higher priority.

Task Execution Time Period Deadline
T12 ms5 ms5 ms
T23 ms10 ms10 ms

Response-Time Formula

Ri = Ci + Bi + Σ ceil(Ri/Tj) × Cj

For this example, assume zero blocking time and no additional overhead.

Step 1: Response Time of T1

T1 has no higher-priority task. 

R1 = C1

   = 2 ms

Since R1 = 2 ms is less than its 5 ms deadline, T1 meets its deadline.

Step 2: Response Time of T2

R2 = C2 + ceil(R2/T1) × C1

Start with the execution time of T2: 

R2(0) = 3 ms

First iteration:

R2(1) = 3 + ceil(3/5) × 2

      = 3 + 1 × 2

      = 5 ms

Second iteration:

R2(2) = 3 + ceil(5/5) × 2

      = 3 + 1 × 2

      = 5 ms

The calculation has converged.

R2 = 5 ms, which is less than the 10 ms deadline. Therefore, both tasks meet their deadlines under the stated assumptions.

11. Numerical Problem 8: Scheduling Overhead

Suppose a system executes tasks for an observation period of 200 ms. During that interval, scheduling and context switching consume 6 ms.

Calculation

Overhead Percentage = (Overhead / Total Time) × 100

                    = (6 / 200) × 100

                    = 3%

The measured scheduling overhead is 3% of the observation interval.

Remaining Time

Remaining Time = 200 - 6

               = 194 ms

This remaining time includes application execution and any other activity not counted in the specified scheduling-overhead measurement.

12. Numerical Problem 9: Response Time and Deadline

A task is released at 15 ms and completes at 21 ms. Its deadline is 20 ms after release.

Step 1: Calculate Response Time

Response Time = Completion Time - Release Time

              = 21 - 15

              = 6 ms

Step 2: Calculate Absolute Deadline

Absolute Deadline = Release Time + Relative Deadline

                  = 15 + 20

                  = 35 ms

Step 3: Check Deadline

The task completes at 21 ms, which is before its absolute deadline of 35 ms.

Deadline status: Met.
A relative deadline of 20 ms is not an absolute completion timestamp. It must be measured from the task's release time.

14. FreeRTOS Scheduling Considerations

Standard FreeRTOS uses fixed-priority scheduling. It does not automatically implement RMS or EDF as separate scheduling algorithms.

Important Configuration Parameters

#define configUSE_PREEMPTION       1
#define configUSE_TIME_SLICING     1
#define configTICK_RATE_HZ         1000
#define configMAX_PRIORITIES       5

These are illustrative configuration values. Their availability and exact behavior depend on the selected FreeRTOS version and port.

FreeRTOS Priority Example

TaskHandle_t Task1Handle;
TaskHandle_t Task2Handle;

xTaskCreate(
    Task1,
    "Task1",
    256,
    NULL,
    3,
    &Task1Handle
);

xTaskCreate(
    Task2,
    "Task2",
    256,
    NULL,
    2,
    &Task2Handle
);

In this example, Task1 has a higher numerical priority than Task2. If both tasks are Ready, Task1 is selected to run under normal priority-based scheduling.

The stack-depth arguments above are illustrative and are expressed in StackType_t elements, not necessarily bytes. They must be sized appropriately for the target port.

Important Points

  • Higher numerical task priority means higher priority.
  • Preemption depends on scheduler configuration and state.
  • Equal-priority time slicing can be enabled where supported.
  • Task priority assignment alone does not guarantee deadlines.
  • Use response-time and schedulability analysis for timing requirements.

15. LPC2129 and Keil uVision Practice

The LPC2129 is based on the ARM7TDMI-S processor. Its timer, interrupt controller and CPU execution can be studied using Keil uVision simulation.

Suggested Exercises

  1. Configure Timer0 with a 1 ms counter increment using the selected PCLK and prescaler.
  2. Study the timer match and interrupt flags.
  3. Calculate the expected interrupt interval.
  4. Prepare a manual task scheduling timeline for two periodic activities.
  5. Calculate CPU utilization for the activities.
  6. Compare the calculated execution budget with the timing assumptions.
  7. Explain how interrupt and scheduler overhead would affect the actual timing budget.
These activities teach scheduling calculations and peripheral timing. Do not treat the exercise as proof of a compatible FreeRTOS port for LPC2129 or as a measurement of physical board timing.

18. Chapter 05 Summary

  • Scheduling determines which Ready task receives CPU time.
  • FCFS selects tasks according to arrival order.
  • Round Robin allocates CPU time using a time quantum.
  • Priority scheduling selects tasks according to priority.
  • RMS assigns fixed priorities based on task periods.
  • EDF selects the Ready job with the earliest absolute deadline.
  • CPU utilization estimates the processor demand of periodic tasks.
  • Response-time analysis accounts for higher-priority interference.
  • Scheduling overhead must be considered in real systems.
  • FreeRTOS uses fixed-priority scheduling by default.
