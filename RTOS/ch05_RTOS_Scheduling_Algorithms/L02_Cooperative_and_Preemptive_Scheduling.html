2. Introduction to Scheduling Approaches

An RTOS scheduler determines which Ready task should execute. The way CPU control is transferred between tasks depends partly on the scheduling approach.

Two important scheduling approaches are:

  1. Cooperative Scheduling: A running task generally continues until it voluntarily yields, blocks, or otherwise gives up CPU execution.
  2. Preemptive Scheduling: The scheduler can interrupt a running task and select another eligible task, commonly when a higher-priority task becomes Ready.
The key difference is how a running task loses CPU control: cooperative scheduling relies on voluntary relinquishing, whereas preemptive scheduling permits scheduler-controlled interruption at defined scheduling points.

3. Cooperative Scheduling

Cooperative scheduling is a scheduling approach in which a running task normally retains CPU control until it voluntarily gives up execution.

A task may give up CPU control by:

  • Calling a yield operation.
  • Blocking while waiting for an event.
  • Waiting for a delay.
  • Calling an operation that blocks the task.

Basic Working

       TASK A RUNNING
              |
              v
       Performs Operation
              |
              v
       Continues Execution
              |
              v
       Yield / Block / Wait
              |
              v
       SCHEDULER SELECTS
         ANOTHER TASK
              |
              v
       TASK B RUNNING

Example

Suppose Task A and Task B are both Ready. Task A begins execution. Under cooperative scheduling, Task B normally cannot take CPU control merely because it has a higher priority. Task A must reach a point where it yields or blocks.

void TaskA(void *pvParameters)
{
    for (;;)
    {
        Perform_Task_A_Work();

        taskYIELD();
    }
}

void TaskB(void *pvParameters)
{
    for (;;)
    {
        Perform_Task_B_Work();

        taskYIELD();
    }
}

This illustrates voluntary yielding. The exact execution order also depends on the RTOS implementation and scheduling policy.

4. Characteristics of Cooperative Scheduling

  • Tasks voluntarily relinquish CPU control.
  • Task switching occurs at suitable yield or blocking points.
  • Scheduling behavior can be relatively simple to understand.
  • A task that does not yield or block can delay other tasks.
  • Task execution time must be controlled carefully.
  • Long-running operations can reduce system responsiveness.

Advantages

  • Can reduce some forms of scheduler-driven task switching.
  • Can simplify execution analysis in carefully structured applications.
  • Tasks retain CPU control until they reach a defined cooperation point.
  • Can be suitable for small systems with predictable task behavior.

Disadvantages

  • A task that fails to yield can delay other tasks indefinitely.
  • Responsiveness depends heavily on task design.
  • High-priority work may have to wait for a lower-priority task to cooperate.
  • Long computation sections can cause deadline misses.

5. Preemptive Scheduling

Preemptive scheduling allows the scheduler to interrupt a currently running task and select another eligible task.

In a common fixed-priority preemptive RTOS, a higher-priority task can preempt a lower-priority running task when the higher-priority task becomes Ready.

              |
              v
       HIGHER-PRIORITY
       TASK B BECOMES READY
              |
              v
        SCHEDULING DECISION
              |
              v
       TASK A PREEMPTED
              |
              v
        TASK B RUNNING
              |
              v
       TASK B BLOCKS OR
       LOSES CPU CONTROL
              |
              v
       TASK A MAY RESUME

Example

Task Priority Initial State
Task A 2 Running
Task B 4 Blocked

When an event makes Task B Ready, the scheduler can preempt Task A and execute Task B, assuming preemption is enabled and scheduling is permitted.

6. Characteristics of Preemptive Scheduling

  • The scheduler can interrupt a running task.
  • Higher-priority Ready tasks can receive CPU time promptly, subject to system constraints.
  • Task execution can be interrupted at scheduling points.
  • Context switching is required when a different task is selected.
  • Task synchronization becomes especially important when shared resources are used.
  • Interrupts and critical sections can delay preemption.

Advantages

  • Supports responsive execution of high-priority tasks.
  • Suitable for many event-driven embedded applications.
  • Allows urgent work to interrupt lower-priority work.
  • Can support priority-based real-time scheduling analysis.

Disadvantages

  • Requires careful synchronization of shared resources.
  • Can introduce priority inversion and race conditions.
  • Context switching introduces execution overhead.
  • More complex timing analysis may be required.
  • Incorrect priority assignment can cause starvation.

7. Cooperative vs Preemptive Scheduling

Parameter Cooperative Preemptive
CPU control Normally relinquished voluntarily. Can be taken by scheduler.
Task switching At yield, blocking, or other cooperation points. At eligible scheduling points, including preemption events.
Higher-priority task May wait until the running task cooperates. Can preempt a lower-priority task.
Responsiveness Depends on how frequently tasks cooperate. Often better for urgent high-priority work.
Synchronization Still required for shared data and asynchronous events. Particularly important due to task interleaving.
Design complexity Can be simpler in structured systems. Requires careful priority and resource management.
Typical use Cooperative task loops and simple schedulers. Priority-driven embedded and real-time systems.

8. Scheduling Timeline: Cooperative Scheduling

Consider two tasks, A and B. Task A executes first and voluntarily yields before Task B executes.

Time  -------------------------------------->

CPU   | Task A | Task A | Yield | Task B | Task B |
      |--------|--------|-------|--------|--------|

Task A:
      RUNNING  RUNNING  YIELDS  READY

Task B:
      READY    READY    READY   RUNNING

The exact order after yielding depends on the scheduler's selection rules and task priorities.

9. Scheduling Timeline: Preemptive Scheduling

Suppose Task A is running and a higher-priority Task B becomes Ready.

Time  -------------------------------------->

CPU   | Task A | Task A | Task B | Task B | Task A |
      |--------|--------|--------|--------|--------|

Event:
      Normal   Normal   B READY  B runs   B blocks

Task A:
      RUNNING  RUNNING  READY    READY    RUNNING

Task B:
      BLOCKED  BLOCKED  READY    RUNNING  BLOCKED

Task A is preempted when Task B becomes eligible and the scheduler selects it. Task A can resume after Task B blocks or otherwise stops being the selected task.

10. Context Switching in Both Approaches

A context switch occurs when the processor stops executing one task and restores the saved execution context of another task.

Typical Context Information

  • CPU registers.
  • Stack pointer.
  • Program counter or return address.
  • Processor status information.
  • Other architecture-specific execution state.

Cooperative Context Switch

The running task reaches a point where it yields or blocks, allowing the scheduler to select another task.

Preemptive Context Switch

A scheduling event can cause the currently running task to be interrupted and another task to be selected.

Preemption does not mean that every interrupt causes a context switch. The scheduler must determine that another task should execute.

11. Preemption and Interrupts

Interrupts can cause events that make tasks Ready. In a preemptive RTOS, this may lead to a scheduling decision.

Example: UART Reception

  1. A UART interrupt occurs when data is received.
  2. The ISR reads or records the received data as appropriate.
  3. The ISR signals a task using a supported ISR-safe RTOS API.
  4. The waiting communication task becomes Ready.
  5. If it has a higher priority than the current task, the scheduler may select it when interrupt processing completes.
       UART INTERRUPT
              |
              v
          UART ISR
              |
              v
       SIGNAL WAITING TASK
              |
              v
       TASK BECOMES READY
              |
              v
       SCHEDULING DECISION
              |
              v
       HIGHER-PRIORITY TASK
       MAY START EXECUTION
An ISR must use only the documented ISR-safe APIs supported by the selected FreeRTOS port. The ISR should remain short and should not perform lengthy processing.

12. Cooperative and Preemptive Scheduling in FreeRTOS

FreeRTOS supports configurable scheduling behavior.

Preemptive Scheduling

When preemption is enabled, a newly Ready higher-priority task can preempt the currently running lower-priority task at an appropriate scheduling point.

#define configUSE_PREEMPTION    1

Cooperative Scheduling Mode

When preemption is disabled, task switching generally occurs when the running task blocks, yields, or reaches another kernel scheduling point. Interrupts still occur, but an interrupt does not automatically mean that another task immediately preempts the current task.

#define configUSE_PREEMPTION    0

Equal-Priority Time Slicing

In applicable FreeRTOS configurations, equal-priority Ready tasks can share CPU time through time slicing.

#define configUSE_TIME_SLICING  1

The time-slicing option is relevant to the applicable preemptive scheduler behavior. Configuration details should be checked against the kernel version being used.

13. FreeRTOS Example: Preemptive Task Scheduling

The following conceptual application creates two tasks with different priorities.

#include "FreeRTOS.h"
#include "task.h"

void LowPriorityTask(void *pvParameters)
{
    for (;;)
    {
        Perform_Low_Priority_Work();

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void HighPriorityTask(void *pvParameters)
{
    for (;;)
    {
        Perform_High_Priority_Work();

        vTaskDelay(pdMS_TO_TICKS(50));
    }
}

int main(void)
{
    Hardware_Init();

    xTaskCreate(
        LowPriorityTask,
        "LowTask",
        128,
        NULL,
        1,
        NULL
    );

    xTaskCreate(
        HighPriorityTask,
        "HighTask",
        128,
        NULL,
        3,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Explanation

  1. LowPriorityTask is created with priority 1.
  2. HighPriorityTask is created with priority 3.
  3. Both tasks become eligible for execution.
  4. The scheduler selects the higher-priority Ready task.
  5. Each task blocks for its configured delay.
  6. When a task becomes Ready again, the scheduler evaluates the Ready tasks.
This is an API illustration, not a complete application. Production code must check task-creation results and implement the application-specific functions. Stack depths shown are in StackType_t elements, not bytes.

14. Important Design Considerations

For Cooperative Scheduling

  • Ensure every task reaches yield or blocking points regularly.
  • Avoid long-running CPU-intensive operations without cooperation.
  • Break lengthy operations into smaller execution sections.
  • Use event-driven blocking instead of continuous polling where possible.

For Preemptive Scheduling

  • Assign priorities according to task timing requirements.
  • Protect shared data with suitable synchronization mechanisms.
  • Keep critical sections short.
  • Analyze priority inversion and blocking time.
  • Consider interrupt interference and context-switch overhead.
  • Verify that important tasks can meet their deadlines.

15. Common Mistakes

Mistake Why It Is a Problem Correct Approach
Assuming cooperative tasks switch automatically by priority A running task may retain CPU control until it cooperates. Design suitable yield and blocking points.
Assuming every interrupt causes a task switch Many interrupts do not require a different task to run. Understand ISR-to-task signaling and scheduler behavior.
Using busy waiting unnecessarily Consumes CPU time and can delay other work. Use blocking and event-driven APIs.
Ignoring shared resources Can cause race conditions and data corruption. Use suitable synchronization.
Assigning every task a high priority Can starve lower-priority tasks. Use deliberate priority assignment.
Assuming preemption guarantees deadlines Blocking, interference, and execution time still matter. Perform timing and schedulability analysis.

16. LPC2129 and Keil uVision Practical

The LPC2129 uses an ARM7TDMI-S processor with a single CPU core. Cooperative and preemptive scheduling can be studied conceptually using task-state variables and a simulated scheduling model.

Suggested Exercises

  1. Create two conceptual tasks with different priorities.
  2. Model cooperative execution where Task A voluntarily yields.
  3. Model preemptive execution where a higher-priority Task B becomes Ready.
  4. Track task states using debugger-visible variables.
  5. Compare the execution sequence in both models.
  6. Calculate the additional execution time associated with an assumed context-switch overhead.
These are conceptual scheduling exercises. They do not establish that a compatible FreeRTOS kernel port is available for the LPC2129 in the current Keil simulator environment. ARM7 interrupt handling must not be confused with Cortex-M NVIC behavior.

17. Lesson Summary

  • Cooperative scheduling relies on tasks voluntarily yielding or blocking.
  • Preemptive scheduling allows the scheduler to interrupt a running task.
  • Higher-priority Ready tasks can preempt lower-priority tasks in a preemptive fixed-priority system.
  • Cooperative systems require carefully designed cooperation points.
  • Preemptive systems require careful synchronization and priority management.
  • Context switching saves and restores task execution context.
  • Interrupts can make tasks Ready but do not always cause context switches.
  • FreeRTOS supports configurable scheduling behavior.
  • configUSE_PREEMPTION controls preemptive scheduling in common configurations.
  • Correct scheduling design requires timing analysis and resource management.
