1. Introduction

First Come First Served (FCFS) is a CPU scheduling algorithm in which processes are executed in the order in which they arrive in the Ready queue.

The process that arrives first receives the CPU first. After completing its CPU burst, the next process in the queue is selected.

Basic principle: The first process to enter the Ready queue is the first process selected for execution.

FCFS is a simple non-preemptive scheduling algorithm commonly studied in operating-system fundamentals.

2. What Is FCFS Scheduling?

FCFS scheduling follows the FIFO (First In, First Out) principle. The Ready queue maintains the arrival order of processes.

Characteristics

  • Processes are selected according to arrival order.
  • The first arrived process is executed first.
  • In its basic form, FCFS is non-preemptive.
  • A running process normally continues until its CPU burst completes or it blocks.
  • It does not use task priority to choose the next process.
  • It is simple to implement using a FIFO queue.

3. Working Principle of FCFS

The scheduler maintains a Ready queue. When a process becomes Ready, it is added to the end of the queue.

Scheduling Procedure

  1. A process arrives in the system.
  2. If the CPU is available, the process can begin execution.
  3. Otherwise, it enters the end of the Ready queue.
  4. The scheduler selects the process at the front of the queue.
  5. The process executes until its CPU burst completes or it blocks for an event or I/O operation.
  6. The next eligible process is selected according to queue order.
In non-preemptive FCFS, a newly arriving process does not automatically interrupt a currently running process.

4. FCFS Numerical Example

Consider three processes with the following arrival times and CPU burst times.

Process Arrival Time (AT) Burst Time (BT)
P1 0 ms 5 ms
P2 1 ms 3 ms
P3 2 ms 2 ms

Step-by-Step Execution

Process Start Time Completion Time Explanation
P1 0 ms 5 ms Arrives first and executes first.
P2 5 ms 8 ms Waits for P1 to complete.
P3 8 ms 10 ms Executes after P2.

Gantt Chart

P1 P2 P3

0 ms     5 ms     8 ms     10 ms

Waiting Time Calculation

Waiting time is the total time a process spends in the Ready queue waiting for CPU allocation.

Formula:

Waiting Time = Start Time - Arrival Time
Process Calculation Waiting Time
P1 0 - 0 0 ms
P2 5 - 1 4 ms
P3 8 - 2 6 ms

Average Waiting Time: 

=(0 + 4 + 6) / 3
= 10 / 3
= 3.33 ms

Turnaround Time Calculation

Formula:

Turnaround Time = Completion Time - Arrival Time
Process Calculation Turnaround Time
P1 5 - 0 5 ms
P2 8 - 1 7 ms
P3 10 - 2 8 ms

Average Turnaround Time: 

=(5 + 7 + 8) / 3
= 20 / 3
= 6.67 ms
Numerical result: Average Waiting Time = 3.33 ms. Average Turnaround Time = 6.67 ms.

6. Convoy Effect in FCFS

The convoy effect occurs when several short processes wait behind one long CPU-bound process in a non-preemptive FCFS scheduling system.

Example

Process Burst Time Type
P1 30 ms Long CPU-bound process
P2 2 ms Short process
P3 3 ms Short process

If P1 arrives first, P2 and P3 must wait until P1 completes its CPU burst. This increases their waiting times even though their execution requirements are small.

Convoy effect: A long-running process can delay many short processes in FCFS, reducing overall responsiveness and potentially affecting resource utilization.

7. FCFS in Operating Systems

FCFS is commonly used to explain basic CPU scheduling and FIFO queue behavior.

Typical Components

  • Process: A program in execution.
  • Ready queue: Holds processes waiting for CPU time.
  • CPU scheduler: Selects the next process.
  • Dispatcher: Transfers control to the selected process.
  • Context switch: Saves and restores execution state when the processor changes execution context.

FCFS can be implemented using a FIFO queue. Processes are added at the rear and removed from the front.

8. FCFS and RTOS Scheduling

FCFS is useful for understanding queue ordering, but it is not generally the primary task-selection policy of a priority-based embedded RTOS such as FreeRTOS.

FreeRTOS normally selects the highest-priority Ready task. Within a given priority level, equal-priority tasks may receive time slicing depending on configuration.

Important Distinction

FCFS FreeRTOS Priority-Based Scheduling
Selection follows arrival order. Selection follows task priority.
Basic form is non-preemptive. Preemption is configurable.
Does not inherently use task priorities. Uses configured task priorities.
Long processes can delay short processes. Higher-priority Ready tasks receive preference.
FCFS queue ordering should not be confused with FreeRTOS's internal Ready-list implementation. FreeRTOS uses priority-based Ready lists and has its own rules for equal-priority task selection.

9. Advantages of FCFS Scheduling

  • Simple to understand and implement.
  • Uses straightforward FIFO queue management.
  • Processes are served in arrival order.
  • No complex priority-assignment mechanism is required.
  • In its basic form, it avoids indefinite overtaking by newly arriving processes in the queue.

10. Limitations of FCFS Scheduling

  • Long CPU bursts can delay short processes.
  • Average waiting time can be high.
  • It does not prioritize urgent or critical work.
  • It is unsuitable as the sole scheduling policy for many deadline-sensitive systems.
  • Non-preemptive execution can reduce responsiveness.
  • It does not directly account for task deadlines or timing constraints.

11. FCFS vs Round Robin Scheduling

Feature FCFS Round Robin
Selection Arrival order Cyclic order
Preemption Normally non-preemptive Time-quantum preemption
Time quantum Not used Used in classic Round Robin
Responsiveness Can be poor for short processes behind long ones Provides repeated turns to eligible processes
Implementation FIFO queue Cyclic queue

12. Practical Embedded System Example

Consider a simple embedded data-processing application that receives three independent jobs:

Job Arrival Order Operation
Job A 1 Process a data packet
Job B 2 Generate a status report
Job C 3 Store a data record

Under FCFS, Job A is selected first, followed by Job B and then Job C, assuming all are queued and each job continues until its CPU burst completes or blocks.

In a real embedded system, urgent protection and control tasks usually require scheduling policies that account for priority, deadlines and worst-case response time rather than relying only on arrival order.

13. LPC2129 and Keil uVision Practical

The LPC2129 uses an ARM7TDMI-S single-core processor. FCFS can be studied as a conceptual queue-based scheduling algorithm without requiring physical hardware.

Suggested Simulator Exercise

  1. Create a conceptual list of three jobs.
  2. Assign arrival times of 0 ms, 2 ms and 4 ms.
  3. Assign CPU burst times of 5 ms, 3 ms and 2 ms.
  4. Arrange the jobs in arrival order.
  5. Draw the Gantt chart.
  6. Calculate waiting time and turnaround time for each job.
  7. Compare the result with a Round Robin execution model.
This exercise is an algorithm simulation. It does not demonstrate a working FCFS RTOS scheduler on the LPC2129. The Keil simulator can be used to study program execution and processor state, but it does not automatically provide a FreeRTOS or FCFS scheduling implementation.

14. Common Mistakes

  • Confusing arrival time with CPU burst time.
  • Assuming FCFS selects the shortest process first.
  • Forgetting that the CPU may be idle before the first arrival.
  • Calculating waiting time without considering arrival time.
  • Confusing turnaround time with waiting time.
  • Assuming FCFS automatically provides real-time scheduling.
  • Ignoring the convoy effect.

15. Lesson Summary

  • FCFS stands for First Come First Served.
  • It follows the FIFO principle.
  • The earliest arrived process is selected first.
  • Basic FCFS scheduling is non-preemptive.
  • Waiting Time = Start Time − Arrival Time.
  • Turnaround Time = Completion Time − Arrival Time.
  • FCFS can suffer from the convoy effect.
  • It is simple but does not inherently prioritize urgent tasks.
  • FCFS is useful for learning CPU scheduling and queue behavior.
  • Priority-based scheduling is more suitable for many deadline-sensitive RTOS applications.
