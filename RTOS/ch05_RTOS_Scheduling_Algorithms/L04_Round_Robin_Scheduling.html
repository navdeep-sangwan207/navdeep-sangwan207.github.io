1. Introduction

Round Robin Scheduling is a CPU scheduling algorithm in which eligible tasks receive processor time in a cyclic order. Each task receives a fixed time interval called a time quantum or time slice.

If a task does not complete its work within the allocated time quantum, it may be moved to the end of the scheduling queue so another eligible task can execute.

Basic principle: Round Robin scheduling distributes processor time among eligible tasks by giving each task a turn in a repeating sequence.

Round Robin is commonly introduced in operating-system scheduling and is also relevant to RTOS configurations that provide time-slicing between tasks of equal priority.

2. What Is a Time Quantum?

A time quantum is the maximum processor time allocated to a task during one turn in a time-sliced Round Robin scheduling system.

For example, if the time quantum is 10 milliseconds, a continuously Ready task may execute for up to approximately 10 milliseconds before the scheduler gives another eligible task a turn.

Example

Parameter Value
Number of tasks 3
Time quantum 10 ms
Task A execution requirement 25 ms
Task B execution requirement 15 ms
Task C execution requirement 20 ms

Assuming all tasks remain Ready, have equal scheduling eligibility, and no other work interferes, each task receives a turn of up to 10 ms.

3. Working Principle of Round Robin Scheduling

Round Robin scheduling follows a cyclic execution sequence.

Scheduling Procedure

  1. Tasks become Ready and enter the applicable scheduling queue.
  2. The scheduler selects the next eligible task.
  3. The selected task executes for up to one time quantum.
  4. If the task finishes or blocks, another eligible task can run.
  5. If the time quantum expires while the task remains Ready, it may be placed behind other eligible tasks.
  6. The process repeats while eligible tasks remain.

Round Robin Execution Cycle

Task A Task B Task C

↓

Fixed Time Quantum

↓

A: Turn 1 B: Turn 1 C: Turn 1

↓

Repeat the Scheduling Cycle

4. Numerical Example of Round Robin Scheduling

Consider three processes with the following CPU burst times. Assume all processes arrive at time zero and the time quantum is 4 milliseconds.

Process CPU Burst Time Arrival Time
P1 10 ms 0 ms
P2 5 ms 0 ms
P3 8 ms 0 ms

Execution Sequence

Time Interval Process Remaining Burst Time
0–4 ms P1 6 ms
4–8 ms P2 1 ms
8–12 ms P3 4 ms
12–16 ms P1 2 ms
16–17 ms P2 Completed
17–21 ms P3 Completed
21–23 ms P1 Completed

Gantt Chart

P1 P2 P3 P1 P2 P3 P1

0    4    8    12    16   17   21   23 ms

Completion Time

Process Completion Time Turnaround Time Waiting Time
P1 23 ms 23 ms 13 ms
P2 17 ms 17 ms 12 ms
P3 21 ms 21 ms 13 ms
Formulas:
  • Turnaround Time = Completion Time − Arrival Time
  • Waiting Time = Turnaround Time − CPU Burst Time

Average waiting time = (13 + 12 + 13) / 3 = 12.67 ms.

Average turnaround time = (23 + 17 + 21) / 3 = 20.33 ms.

5. Role of the Ready Queue

The Ready queue contains tasks that are eligible to execute but are waiting for processor time.

In a simple Round Robin model, tasks are organized in a cyclic queue. After using their time quantum, unfinished tasks are placed at the back of the queue.

Example Queue Rotation

Initial Queue

A B C

↓ Task A uses its quantum

Next Queue Order

B C A

If a task blocks before its quantum expires, it leaves the Ready queue. When the awaited event occurs, it can become Ready again according to the RTOS scheduling rules.

6. Choosing the Time Quantum

The time quantum affects scheduling overhead and the responsiveness of tasks.

Small Time Quantum

  • Tasks receive processor time more frequently.
  • Interactive responsiveness may improve.
  • More frequent task switches may increase overhead.
  • Very small quanta can reduce useful CPU time.

Large Time Quantum

  • Tasks execute for longer intervals.
  • Fewer time-slice-driven switches may occur.
  • Other tasks may wait longer for their turn.
  • Behavior may approach non-time-sliced execution when the quantum is very large relative to task execution intervals.
Time Quantum Possible Effect
Very small Higher scheduling overhead
Moderate Balance between responsiveness and overhead
Very large Longer waiting intervals for other tasks
There is no universally optimal time quantum. It must be selected according to task behavior, scheduler implementation, tick resolution and application timing requirements.

7. Round Robin Scheduling in RTOS

In an RTOS, Round Robin scheduling is commonly used to share processor time among tasks having equal priority.

A priority-based RTOS may first select the highest-priority Ready task group. Within that group, equal-priority tasks may receive time slices according to the scheduler's configuration.

Example

Task Priority Function
Task A 2 Sensor processing
Task B 2 Communication processing
Task C 2 Display processing
Task D 4 Critical monitoring

If Task D is Ready, it has higher priority than Tasks A, B and C in this example. Round Robin time slicing among A, B and C does not normally allow them to preempt a Ready higher-priority Task D.

Round Robin scheduling and priority-based scheduling can work together. Priority determines which priority level gets CPU time; time slicing can distribute CPU time among eligible tasks at the same priority.

8. FreeRTOS Time Slicing

FreeRTOS uses priority-based scheduling. In common configurations, time slicing can share processor time among Ready tasks that have equal priority.

8.1 Configuration

The following settings are commonly used in FreeRTOSConfig.h: 

#define configUSE_PREEMPTION       1
#define configUSE_TIME_SLICING     1
#define configTICK_RATE_HZ         1000

Here:

  • configUSE_PREEMPTION enables preemptive scheduling in common FreeRTOS configurations.
  • configUSE_TIME_SLICING enables time slicing between equal-priority Ready tasks where supported.
  • configTICK_RATE_HZ sets the configured RTOS tick frequency.

8.2 Example with Equal-Priority Tasks

#include "FreeRTOS.h"
#include "task.h"

void Task_A(void *pvParameters)
{
    while (1)
    {
        /* Task A processing */

        /* Remain Ready for scheduling */
    }
}

void Task_B(void *pvParameters)
{
    while (1)
    {
        /* Task B processing */

        /* Remain Ready for scheduling */
    }
}

int main(void)
{
    xTaskCreate(
        Task_A,
        "TaskA",
        256,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        Task_B,
        "TaskB",
        256,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    while (1)
    {
    }
}

Both tasks have priority 2. If both remain Ready and time slicing is enabled for the selected FreeRTOS port/configuration, the scheduler can rotate execution between them at scheduling ticks.

This example is intended to demonstrate equal-priority time slicing. The task loops perform no blocking operations and may consume the available CPU time. Real application tasks should perform bounded work and block or wait for events when appropriate.

9. FreeRTOS Time Delay and Task Blocking

A task can voluntarily leave the Ready state by calling a blocking API such as vTaskDelay() or waiting for a queue, semaphore or task notification. 

void Task_A(void *pvParameters)
{
    while (1)
    {
        /* Perform processing */

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

During the delay, Task A is Blocked and cannot consume processor time. Another Ready task can execute.

When the delay expires, Task A becomes Ready again. It does not necessarily execute immediately; higher-priority Ready tasks may execute first.

10. Round Robin Scheduling vs Priority-Based Scheduling

Feature Round Robin Priority-Based
Selection principle Cyclic order among eligible tasks Assigned task priority
Time quantum Central to classic Round Robin Not required by priority selection itself
Task preference Fair turn among queue participants Higher-priority Ready tasks preferred
Typical use Time-sharing and equal-priority time slicing Embedded task importance and urgency
Potential issue Switching overhead Starvation and priority inversion

Classic operating-system Round Robin and FreeRTOS equal-priority time slicing are related concepts, but they are not identical scheduling architectures.

11. Advantages of Round Robin Scheduling

  • Provides repeated processor turns to eligible tasks.
  • Supports fair CPU sharing among participating tasks.
  • Prevents one equal-priority task from monopolizing execution indefinitely under a functioning time-slicing policy.
  • Simple to understand and illustrate.
  • Useful in time-sharing and multitasking systems.

12. Limitations of Round Robin Scheduling

  • Frequent task switches can increase scheduling overhead.
  • Time quantum selection affects responsiveness and efficiency.
  • It does not inherently consider task deadlines.
  • It does not automatically prioritize critical embedded tasks.
  • Classic equal-turn fairness does not necessarily apply to different-priority tasks in a priority-based RTOS.

13. Practical Embedded System Example

Consider an embedded monitoring device with three equal-priority background tasks:

Task Operation Priority
Task A Process sensor data 2
Task B Prepare communication data 2
Task C Update display information 2

If all three tasks remain Ready, equal-priority time slicing can allow them to share processor time. If one task blocks while waiting for an event, the scheduler can select another Ready task.

A separate high-priority protection task could be added to the system. It would receive scheduling preference whenever it becomes Ready under preemptive priority-based scheduling.

14. LPC2129 and Keil uVision Practical

The LPC2129 uses an ARM7TDMI-S processor with a single CPU core. The Round Robin scheduling concept can be studied by modeling multiple tasks and observing their execution sequence.

Suggested Simulator Exercise

  1. Define three conceptual tasks: sensor, communication and display.
  2. Assign each task the same illustrative priority.
  3. Choose a hypothetical time quantum of 10 ms.
  4. Draw the execution order for the three tasks.
  5. Calculate how many turns each task receives over 60 ms if all remain Ready.
  6. Repeat the model with one task becoming Blocked.
The exercise is a scheduling model, not a claim that FreeRTOS is running on the LPC2129 simulator. Verify a compatible ARM7 FreeRTOS port before attempting an actual RTOS build. Keil simulator timing is not proof of real-time hardware performance.

15. Common Mistakes

  • Assuming every RTOS uses classic Round Robin scheduling for all tasks.
  • Confusing equal-priority time slicing with priority-based task selection.
  • Assuming every task always receives exactly one full time quantum.
  • Ignoring task blocking and task completion.
  • Assuming a smaller time quantum always improves performance.
  • Assuming time slicing guarantees real-time deadlines.
  • Assuming a lower-priority task can preempt a higher-priority Ready task in a normal preemptive priority-based scheduler.

16. Lesson Summary

  • Round Robin scheduling distributes CPU time in a cyclic order.
  • A time quantum determines the maximum time allocated during one scheduling turn in classic Round Robin.
  • Unfinished Ready tasks may return to the end of the queue.
  • Task completion or blocking can end a task's current turn early.
  • Small time quanta may increase scheduling overhead.
  • Large time quanta may increase waiting time for other tasks.
  • FreeRTOS can use time slicing among equal-priority Ready tasks in supported configurations.
  • configUSE_TIME_SLICING controls equal-priority time slicing in common FreeRTOS configurations.
  • Priority-based selection still determines which priority level receives processor time.
  • Round Robin alone does not guarantee real-time deadlines.
