Lesson 08: Static and Dynamic Priority Scheduling

1. Introduction

Priority-based scheduling is an important scheduling technique used by real-time operating systems. Every task is assigned a priority, and the scheduler selects a Ready task according to the scheduling policy.

Priority assignment can be broadly classified into two approaches:

  • Static Priority Scheduling
  • Dynamic Priority Scheduling
Basic distinction: Static priority remains assigned to a task, while dynamic priority can change during system execution according to scheduling conditions.

2. What Is Static Priority Scheduling?

Static Priority Scheduling is a scheduling approach in which each task receives a priority that normally remains unchanged while the system operates.

The scheduler selects the highest-priority Ready task.

Example

Task Function Priority
Task A Motor protection monitoring 5
Task B Sensor processing 3
Task C Display update 1

If all three tasks are Ready, Task A is selected because it has the highest priority.

Priority numbering depends on the RTOS. In FreeRTOS, larger numerical values represent higher task priorities.

3. Characteristics of Static Priority Scheduling

  • Task priorities are assigned before or during task creation.
  • Priorities normally remain fixed during execution.
  • The scheduler selects the highest-priority Ready task.
  • Scheduling decisions are generally predictable when execution and interference are bounded.
  • Priority assignment can be based on task criticality, timing requirements or periodic task analysis.
  • Priority inversion and starvation must be considered.

Common Static Priority Algorithms

Algorithm Priority Assignment
Rate Monotonic Scheduling (RMS) Shorter-period tasks receive higher priority.
Deadline Monotonic Scheduling (DMS) Shorter relative-deadline tasks receive higher priority under its applicable fixed-priority task model.
Application-Defined Fixed Priority Developer assigns priorities based on system requirements.

4. What Is Dynamic Priority Scheduling?

Dynamic Priority Scheduling is a scheduling approach in which task or job priorities can change during system execution.

The scheduler may update priorities according to deadlines, urgency, system state or other scheduling criteria.

Example

Consider three jobs with different absolute deadlines:

Job Absolute Deadline Scheduling Preference
Job A 30 ms Second
Job B 20 ms Highest
Job C 40 ms Third

Job B is selected first because its absolute deadline is the earliest.

If another job is released with an earlier deadline, the scheduling order may change.

5. Characteristics of Dynamic Priority Scheduling

  • Priorities can change during execution.
  • Scheduling decisions depend on changing system conditions.
  • Priority reassignment may occur when new jobs arrive.
  • It can support deadline-driven scheduling.
  • Implementation may require additional scheduling information.
  • Dynamic priority management can increase scheduling overhead.

Common Dynamic Priority Approaches

Algorithm Priority Assignment
Earliest Deadline First (EDF) Job with the earliest absolute deadline receives the highest scheduling preference.
Least Laxity First (LLF) Job with the least remaining execution slack receives the highest scheduling preference.
Adaptive Priority Scheduling Priority is adjusted according to defined runtime conditions or application policies.

6. Static vs Dynamic Priority Scheduling

Feature Static Priority Dynamic Priority
Priority assignment Fixed or predetermined Updated during execution
Priority changes Normally no Yes, according to scheduling policy
Scheduling basis Preassigned task priority Runtime scheduling criteria
Complexity Generally simpler Can require more runtime processing
Examples RMS, DMS EDF, LLF
Deadline information Not necessarily required by the scheduler Required by deadline-based policies
Typical use Fixed-priority embedded systems Deadline-driven scheduling systems

7. Numerical Example: Static Priority Scheduling

Consider three tasks with fixed priorities and the following execution times.

Task Execution Time Priority
T1 3 ms 3 - Highest
T2 4 ms 2 - Medium
T3 2 ms 1 - Lowest

Assume all tasks become Ready at time zero, execute independently and do not block.

Scheduling Order

T1 → T2 → T3

Execution Timeline

T1: 0–3 T2: 3–7 T3: 7–9

Total execution interval: 0–9 ms

Since no new task becomes Ready and no task blocks, each task executes in priority order.

9. Preemption in Priority Scheduling

Preemption allows a higher-priority Ready task to interrupt the execution of a lower-priority task.

Example

  • Task A is running with priority 2.
  • Task B becomes Ready with priority 5.
  • The scheduler selects Task B because its priority is higher.
  • Task A is suspended and can resume later.

Illustrative Preemption Timeline

A: 0–2 B: 2–5 A: 5–8

Task B becomes Ready at 2 ms and preempts Task A.

Preemption depends on the scheduler configuration and execution state. A critical section, interrupt masking or scheduler suspension can delay a task switch.

10. Priority Inversion

Priority inversion occurs when a high-priority task is unable to proceed because a lower-priority task holds a shared resource.

Example

  1. Low-priority Task L acquires a shared mutex.
  2. High-priority Task H becomes Ready and requests the same mutex.
  3. Task H blocks because Task L owns the mutex.
  4. Medium-priority Task M becomes Ready and preempts Task L.
  5. Task L cannot run to release the mutex, so Task H remains blocked.

This situation can delay a high-priority task indirectly because of a lower-priority task.

Priority Inheritance

Priority inheritance temporarily raises the priority of the resource-owning task to reduce the blocking of a higher-priority task.

Priority inheritance reduces certain forms of priority inversion, but it does not eliminate every possible blocking delay or guarantee deadlines.

11. Static and Dynamic Priority in FreeRTOS

Standard FreeRTOS uses a fixed-priority preemptive scheduler in its common configuration. The application assigns task priorities and the scheduler selects the highest-priority Ready task.

Creating Tasks with Different Priorities

#include "FreeRTOS.h"
#include "task.h"

void High_Task(void *pvParameters)
{
    while (1)
    {
        /* High-priority processing */

        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

void Medium_Task(void *pvParameters)
{
    while (1)
    {
        /* Medium-priority processing */

        vTaskDelay(pdMS_TO_TICKS(20));
    }
}

void Low_Task(void *pvParameters)
{
    while (1)
    {
        /* Low-priority processing */

        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void)
{
    xTaskCreate(
        High_Task,
        "High",
        256,
        NULL,
        3,
        NULL
    );

    xTaskCreate(
        Medium_Task,
        "Medium",
        256,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        Low_Task,
        "Low",
        256,
        NULL,
        1,
        NULL
    );

    vTaskStartScheduler();

    while (1)
    {
    }
}

This example illustrates fixed-priority task creation. Stack-depth values are in StackType_t elements, not bytes. The values shown must be checked against the selected port and application's stack requirements.

Changing a Task Priority at Runtime

vTaskPrioritySet(
    taskHandle,
    4
);

The API changes the specified task's priority at runtime. This is a priority-management operation, not an EDF scheduler.

FreeRTOS can change a task's priority using vTaskPrioritySet(), but its standard scheduling policy remains fixed-priority. Dynamic priority changes do not automatically make it an EDF or LLF scheduler.

12. Advantages of Static Priority Scheduling

  • Simple priority assignment and scheduling policy.
  • Suitable for many embedded control applications.
  • Can provide predictable behavior with proper analysis.
  • Widely supported by fixed-priority RTOS kernels.
  • Can use established analysis techniques such as response-time analysis.

13. Advantages of Dynamic Priority Scheduling

  • Can respond to changing job deadlines and urgency.
  • Supports deadline-driven scheduling policies.
  • EDF can achieve high processor utilization under its classical assumptions.
  • Can adapt job scheduling order as new work arrives.

14. Limitations of Both Approaches

Static Priority Limitations

  • Incorrect priority assignment can cause deadline misses.
  • Low-priority tasks may suffer starvation.
  • Shared resources can cause priority inversion.
  • Fixed priorities may not be optimal for every task model.

Dynamic Priority Limitations

  • Runtime priority management can increase complexity.
  • Deadline and timing information must be maintained.
  • Frequent scheduling changes may add overhead.
  • Overload conditions can make deadline management difficult.

15. LPC2129 and Keil uVision Practical

The LPC2129 uses a single-core ARM7TDMI-S processor. You can study priority scheduling by modeling tasks and recording their execution order.

Suggested Exercise

  1. Create three task records with different priorities.
  2. Make all tasks Ready at time zero.
  3. Select the highest-priority Ready task.
  4. Simulate a new higher-priority task becoming Ready.
  5. Record the preemption and resumption sequence.
  6. Repeat the experiment using changing deadline values.
  7. Compare static and dynamic scheduling results.
This is a scheduling simulation exercise. Do not assume that a compatible FreeRTOS port or an EDF kernel is available for LPC2129 in Keil uVision without verifying the actual port.

16. Common Mistakes

  • Assuming static priority means non-preemptive scheduling.
  • Assuming dynamic priority always means EDF.
  • Confusing task priority with interrupt priority.
  • Assuming FreeRTOS automatically changes priorities according to task deadlines.
  • Ignoring priority inversion and resource blocking.
  • Assuming priority changes alone guarantee deadline compliance.
  • Confusing a Ready task with a Running task.

17. Lesson Summary

  • Static priority scheduling uses predetermined task priorities.
  • Dynamic priority scheduling allows priorities to change during execution.
  • RMS and DMS are fixed-priority scheduling algorithms.
  • EDF and LLF are dynamic-priority scheduling algorithms.
  • Preemption allows a higher-priority Ready task to interrupt a lower-priority Running task.
  • Priority inversion can delay high-priority tasks.
  • Priority inheritance can reduce certain priority inversion problems.
  • Standard FreeRTOS uses fixed-priority scheduling but supports runtime priority changes.
