2. Introduction to Task Scheduling

Task scheduling is the process of selecting which Ready task should execute on the CPU at a particular time.

An RTOS may manage several tasks, but on a single-core processor only one task can execute at a time. The scheduler decides which task receives CPU time.

Example

Consider an embedded system containing three tasks:

Task Priority Function
SensorTask 3 Reads sensor information.
UARTTask 2 Processes communication data.
DisplayTask 1 Updates display information.

If all three tasks are Ready and the scheduler uses fixed-priority scheduling, SensorTask is selected first because it has the highest priority.

Task scheduling is not simply about executing tasks in sequence. It is about selecting an eligible task according to the scheduler's policy and current system conditions.

3. What Is a Scheduler?

A scheduler is a kernel component responsible for deciding which Ready task should execute next.

Main Responsibilities

  • Maintain information about Ready tasks.
  • Evaluate task priorities or other scheduling criteria.
  • Select the next task for execution.
  • Coordinate task switching.
  • Support time-based scheduling operations.
  • Respond to scheduling events such as task blocking and task readiness.

Basic Scheduler Architecture

       RTOS APPLICATION
              |
              v
        TASK MANAGEMENT
              |
              v
          READY TASKS
              |
              v
          SCHEDULER
              |
              v
       TASK SELECTION
              |
              v
       CONTEXT SWITCH
              |
              v
        CPU EXECUTION

The scheduler uses kernel data structures to identify eligible tasks and select the next task.

4. Why Is Task Scheduling Required?

Embedded systems often perform multiple operations that must share the available processor time.

Example: Industrial Monitoring System

  • Read temperature sensors.
  • Monitor motor status.
  • Receive UART commands.
  • Update an LCD display.
  • Communicate with other controllers.

Without a suitable scheduling mechanism, one operation may occupy the CPU for too long and delay other operations.

Benefits of Scheduling

  1. Organizes CPU execution among tasks.
  2. Supports priority-based task execution.
  3. Allows multiple activities to make progress.
  4. Supports periodic and event-driven operations.
  5. Helps meet application timing requirements when the system is correctly designed and analyzed.

5. Basic Scheduling Terminology

Term Meaning
Task An independently scheduled unit of execution.
Ready Task A task eligible to execute but waiting for CPU time.
Running Task The task currently executing on the CPU.
Task Priority A value used by priority-based scheduling to determine task preference.
Scheduling Policy The rules used to select the next task.
Preemption Interrupting a Running task's CPU execution to schedule another task.
Time Slice A defined interval of CPU time used by certain scheduling policies.
Context Switch Saving one task's execution context and restoring another's.
Scheduling Latency Time between a task becoming eligible and its execution starting, under a stated definition.

6. How Does Task Scheduling Work?

A simplified scheduling process is:

  1. Tasks are created and become Ready.
  2. The scheduler examines the Ready tasks.
  3. The scheduling policy determines which task should execute.
  4. The selected task enters the Running state.
  5. The task executes until it blocks, yields, is preempted, or completes its scheduled execution opportunity.
  6. The scheduler makes another scheduling decision when required.

Scheduling Flowchart

          START
            |
            v
       READY TASKS?
            |
            v
      APPLY SCHEDULING
          POLICY
            |
            v
       SELECT TASK
            |
            v
       RUN TASK
            |
            v
    SCHEDULING EVENT?
       /          \
     YES           NO
      |             |
      v             |
  SELECT AGAIN <----+
      |
      v
     END

The scheduler does not necessarily make a new task selection after every instruction. Scheduling decisions occur at defined kernel scheduling points.

7. When Does a Scheduling Decision Occur?

Scheduling decisions can occur when the state of the system changes in a way that affects which task should execute.

Event Possible Scheduling Effect
Task creation A new Ready task may have higher priority.
Task blocking The Running task stops executing and waits.
Task delay expiration A Blocked task may become Ready.
Queue data arrival A task waiting for queue data may become Ready.
Semaphore availability A task waiting for the semaphore may become Ready.
Task priority change The preferred task may change.
Task yield The scheduler may select another eligible task.
Tick interrupt Time-dependent tasks and time slicing may require scheduling action.
A timer tick does not automatically cause a context switch. A switch occurs only when kernel scheduling rules and current task states require one.

8. Scheduling Policy and Task Priority

Scheduling policy defines how the scheduler selects the next task. Task priority is one possible selection criterion.

Priority-Based Scheduling

In priority-based scheduling, tasks are assigned priority levels. The scheduler generally selects the highest-priority Ready task.

Task A - Priority 1
Task B - Priority 3
Task C - Priority 2

All tasks are Ready.

Selected Task: Task B
Reason: Highest priority

In common FreeRTOS configurations, a larger numeric priority represents a higher priority.

Scheduling Policies Covered in This Chapter

  • Cooperative scheduling.
  • Preemptive scheduling.
  • Priority-based scheduling.
  • Round Robin scheduling.
  • First Come First Served (FCFS).
  • Rate Monotonic Scheduling (RMS).
  • Earliest Deadline First (EDF).
  • Static and dynamic priority scheduling.

9. Scheduling in FreeRTOS

FreeRTOS commonly uses a priority-based scheduler. The scheduler selects a task from the highest-priority non-empty Ready list.

Example

Task A - Priority 1
Task B - Priority 2
Task C - Priority 3

All tasks are Ready.

FreeRTOS selects Task C.

Important configuration options include:

Configuration Purpose
configUSE_PREEMPTION Enables or disables preemptive scheduling in common FreeRTOS configurations.
configUSE_TIME_SLICING Controls time slicing between equal-priority Ready tasks in applicable configurations.
configMAX_PRIORITIES Defines the number of available task priority levels.
configTICK_RATE_HZ Configures the RTOS tick frequency.

These options and their exact behavior depend on the FreeRTOS kernel version and port configuration.

10. Simple Task Scheduling Example

Consider three Ready tasks with the following priorities:

Task Priority Initial State
Task A 1 Ready
Task B 2 Ready
Task C 3 Ready

Execution Sequence

Initially:
Task A = READY
Task B = READY
Task C = READY

Scheduler selects Task C.

Task C = RUNNING
Task A = READY
Task B = READY

Task C blocks waiting for an event.

Task B = RUNNING
Task A = READY

Task B blocks.

Task A = RUNNING

This example assumes a preemptive fixed-priority scheduler with larger numbers representing higher priority.

11. Scheduling Performance Parameters

Scheduling performance is evaluated using several timing and resource measurements.

Parameter Description
Response Time Time from task release or event to task completion.
Execution Time Time during which the task actually executes on the CPU.
Waiting Time Time spent waiting for CPU access or other required conditions, as defined by the analysis.
CPU Utilization Fraction of processor capacity used by executing tasks.
Scheduling Latency Delay between becoming eligible and starting execution.
Jitter Variation in task timing, such as release or completion times.
Deadline Latest permitted completion time for a task's required result.

12. Advantages of Task Scheduling

  • Organizes multiple tasks sharing one processor.
  • Supports priority-based execution.
  • Allows event-driven and periodic task execution.
  • Improves CPU availability when tasks block appropriately.
  • Provides a structured way to analyze task timing.
  • Supports complex embedded application design.

13. Scheduling Challenges

  • Priority inversion.
  • Task starvation.
  • Unbounded blocking.
  • Excessive context-switch overhead.
  • Interrupt interference.
  • Deadline misses.
  • Task execution-time variation.
  • Scheduling jitter.
  • Incorrect priority assignment.
Using an RTOS scheduler does not automatically guarantee that every task will meet its deadline. Timing analysis must consider execution time, blocking, interrupts, interference, and scheduling policy.

14. LPC2129 and Keil uVision Practical

The LPC2129 is based on the ARM7TDMI-S processor and has a single CPU core.

Scheduling concepts can be studied using a conceptual task model, even when the actual FreeRTOS port is not available in the development environment.

Suggested Exercise

  1. Define three conceptual tasks: Sensor, UART, and Display.
  2. Assign priorities 3, 2, and 1 respectively.
  3. Represent their states using variables.
  4. Implement a simple selection function that chooses the highest-priority Ready task.
  5. Change task states to simulate blocking and readiness.
  6. Observe how the selected task changes.
  7. Inspect program variables in the Keil debugger.
This exercise models scheduling logic. It does not demonstrate a working FreeRTOS port or actual concurrent execution on the LPC2129.

15. Lesson Summary

  • Task scheduling selects the next Ready task for CPU execution.
  • The scheduler is responsible for making task-selection decisions.
  • Scheduling policy defines the selection rules.
  • Task priority is an important criterion in priority-based scheduling.
  • Scheduling decisions may occur after task-state changes or other kernel events.
  • Preemption allows a task to be interrupted by another eligible task.
  • Cooperative scheduling relies on tasks yielding or blocking to permit other tasks to run.
  • FreeRTOS commonly uses priority-based scheduling.
  • Scheduling performance depends on timing, blocking, and CPU utilization.
  • A scheduler alone cannot guarantee all real-time deadlines.
