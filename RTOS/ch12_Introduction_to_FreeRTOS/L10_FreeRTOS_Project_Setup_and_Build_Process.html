1. Learning Objectives

Developing a FreeRTOS application requires more than writing task functions. The kernel source, processor-specific port, configuration file, startup code, linker settings and application code must be integrated into one project.

  • Understand the structure of a FreeRTOS project.
  • Identify the kernel source files and header files.
  • Understand processor-port selection.
  • Configure FreeRTOSConfig.h.
  • Understand compiler and linker requirements.
  • Learn the general project build sequence.
  • Identify common build errors and debugging methods.

2. Introduction to FreeRTOS Project Development

A FreeRTOS project combines application software with the FreeRTOS kernel and a processor-specific port. The compiler translates the source files into object files, and the linker combines them with startup code and libraries to create the final executable image.

3. Hardware and Toolchain Selection

Before creating a project, identify the exact microcontroller, processor architecture, compiler and development environment.

Hardware Selection Factors

  • Processor architecture and instruction set.
  • Available RAM and Flash memory.
  • Timer and interrupt capabilities.
  • Communication peripherals such as UART, SPI and I2C.
  • Debugging support.
  • Availability of a compatible FreeRTOS port.

Toolchain Components

Component Purpose
Compiler Translates C source code into object code.
Assembler Translates assembly source into machine code.
Linker Combines object files and libraries into an executable.
Startup Code Initializes the processor environment before main().
Debugger Supports breakpoints, registers, memory inspection and execution control.
A FreeRTOS port must match the processor architecture and compiler requirements. A port for ARM Cortex-M cannot simply be used for an ARM7TDMI-S processor.

5. Important FreeRTOS Kernel Source Files

Source File Functionality
tasks.c Task creation, deletion, scheduling and task management.
queue.c Queues, semaphores and mutex-related queue mechanisms.
list.c Internal linked-list operations used by the kernel.
timers.c Software timer management.
event_groups.c Event group services.
stream_buffer.c Stream and message buffer services.
The exact set of source files depends on the FreeRTOS release and enabled kernel features. Add only the required kernel files and the matching processor-port files.

7. Selecting the Processor Port

The processor port connects the generic FreeRTOS kernel to the target processor. It contains architecture- and compiler-specific code for context switching, interrupt handling, critical sections and tick integration.

Port Responsibilities

  • Save and restore task CPU context.
  • Implement task context switching.
  • Configure the RTOS tick source.
  • Provide critical-section operations.
  • Define processor-specific stack initialization.
  • Integrate interrupt and scheduler behavior.

Architecture Examples

Processor Family Port Requirement
ARM Cortex-M Matching Cortex-M core and compiler port.
ARM7TDMI-S Compatible ARM7 port and toolchain integration.
RISC-V Matching RISC-V architecture and compiler port.
AVR Compatible AVR port and compiler setup.
Processor-family names alone are insufficient to select a port. Verify the exact core, compiler, ABI, interrupt model and FreeRTOS release documentation.

8. Configuring FreeRTOSConfig.h

FreeRTOSConfig.h contains application-specific configuration settings. It controls scheduler behavior, tick rate, priorities, memory allocation and optional kernel services.

Illustrative Configuration Fragment

#define configUSE_PREEMPTION                    1
#define configUSE_TIME_SLICING                  1

#define configTICK_RATE_HZ                      1000
#define configMAX_PRIORITIES                    5

#define configSUPPORT_STATIC_ALLOCATION         1
#define configSUPPORT_DYNAMIC_ALLOCATION        1

#define configUSE_MUTEXES                       1
#define configUSE_COUNTING_SEMAPHORES            1
#define configUSE_TIMERS                        1
#define configUSE_EVENT_GROUPS                  1

#define configCHECK_FOR_STACK_OVERFLOW          2

This is not a complete configuration file. A real project must include the required definitions for its exact FreeRTOS version and processor port.

Important Settings

  • configUSE_PREEMPTION: enables or disables preemptive scheduling.
  • configUSE_TIME_SLICING: controls time slicing among equal-priority ready tasks where supported.
  • configTICK_RATE_HZ: configures the RTOS tick frequency.
  • configMAX_PRIORITIES: defines the number of available task priority levels.
  • configSUPPORT_STATIC_ALLOCATION: enables static object creation APIs.
  • configSUPPORT_DYNAMIC_ALLOCATION: enables dynamic object creation APIs.
  • configUSE_TIMERS: enables software timer services.
  • configCHECK_FOR_STACK_OVERFLOW: selects supported stack-overflow diagnostic checks.

9. Compiler Configuration

The compiler must be configured to build the kernel, processor port and application code using compatible options.

Important Compiler Settings

  • Correct processor and instruction-set selection.
  • Compatible compiler version and language mode.
  • Correct include directories.
  • Consistent data type and ABI settings.
  • Appropriate optimization settings.
  • Required assembly-language support.
  • Debug information generation.

10. Linker and Startup Configuration

The linker combines compiled object files and libraries into the final executable. It also places code and data into the memory regions defined for the target.

Linker Responsibilities

  • Combine application and kernel object files.
  • Resolve external function and variable references.
  • Assign code and data addresses.
  • Allocate stack and static memory regions.
  • Generate the executable image and map file.

Startup Code Responsibilities

  • Initialize the processor environment.
  • Set up the initial stack pointer.
  • Initialize memory sections as required.
  • Configure low-level processor settings.
  • Transfer execution to the C runtime and main().
FreeRTOS does not replace the microcontroller's startup code or linker configuration. These must be correct for the selected toolchain and target.

11. Writing the Application main() Function

The application usually initializes required peripherals, creates tasks and kernel objects, and then starts the FreeRTOS scheduler.

Illustrative Application Structure

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    for (;;)
    {
        /* Read or process sensor data */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void CommunicationTask(void *pvParameters)
{
    for (;;)
    {
        /* Handle communication */

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    /* Initialize board and peripherals */

    BaseType_t result;

    result = xTaskCreate(
        SensorTask,
        "Sensor",
        256,
        NULL,
        2,
        NULL
    );

    if (result != pdPASS)
    {
        /* Handle task creation failure */
        for (;;)
        {
        }
    }

    result = xTaskCreate(
        CommunicationTask,
        "Comm",
        256,
        NULL,
        1,
        NULL
    );

    if (result != pdPASS)
    {
        /* Handle task creation failure */
        for (;;)
        {
        }
    }

    vTaskStartScheduler();

    /* Reached only if scheduler startup fails
       or the scheduler unexpectedly returns. */
    for (;;)
    {
    }
}
This is an illustrative FreeRTOS application structure. It is not a ready-to-run LPC2129 project. A compatible ARM7 port, tick source, startup integration and compiler configuration are required before it can run.

12. FreeRTOS Build Process

The build process converts source code into an executable image. 

Source Files
     |
     v
Preprocessor
     |
     v
Compiler
     |
     v
Object Files
     |
     v
Assembler (where required)
     |
     v
Linker
     |
     v
Executable Image
     |
     v
Load and Debug

Build Stages

  1. Preprocessing: Expands macros and processes header inclusions.
  2. Compilation: Converts C source into assembly or intermediate code.
  3. Assembly: Converts assembly instructions into object code.
  4. Linking: Combines object files and resolves references.
  5. Image generation: Produces the executable format required by the toolchain.
  6. Programming: Loads the image onto the target when supported.
  7. Debugging: Examines execution, registers, memory and task behavior.

13. Common Build Errors

Error Possible Cause Corrective Action
FreeRTOS.h not found Missing include directory. Add the correct FreeRTOS include path.
Undefined reference to vTaskStartScheduler Kernel source or build configuration missing. Check tasks.c and the required kernel files.
Undefined port symbols Missing or incompatible processor port. Verify the selected port and port source files.
Multiple definition errors Duplicate source files or conflicting implementations. Remove duplicate files and select one heap implementation.
Linker memory overflow Code or data exceeds configured memory. Inspect the map file and adjust memory usage.
Task does not execute Scheduler, tick or interrupt integration problem. Verify port initialization and tick configuration.
Task creation fails Insufficient allocation memory or invalid configuration. Check heap availability, stack size and API result.

14. Debugging a FreeRTOS Application

Debugging helps identify errors in task execution, memory allocation, scheduling and interrupt integration.

Useful Debugging Techniques

  • Set breakpoints in task functions.
  • Inspect the current task and task handles.
  • Examine CPU registers and stack memory.
  • Inspect queue and semaphore behavior.
  • Monitor heap usage where supported.
  • Check stack high-water marks.
  • Inspect the linker map for RAM and Flash usage.
  • Review fault handlers and interrupt execution.

Debugging Checklist

  1. Does the project compile without errors?
  2. Does the linker resolve all symbols?
  3. Is the correct processor port included?
  4. Is the scheduler started successfully?
  5. Is the RTOS tick source configured correctly?
  6. Are task creation return values checked?
  7. Are task stack sizes adequate?
  8. Are interrupt priorities and API rules port-correct?

15. Practical Activity – Build a FreeRTOS Project

Objective: Understand how the FreeRTOS kernel and application files are integrated into a development project.

Procedure

  1. Obtain a FreeRTOS kernel release.
  2. Select a supported development board and compiler.
  3. Identify the processor-specific port.
  4. Create an application project.
  5. Add the required kernel source files.
  6. Add the selected heap implementation if dynamic allocation is used.
  7. Add the correct include directories.
  8. Create or adapt FreeRTOSConfig.h from the matching port example.
  9. Integrate startup and linker configuration.
  10. Write a main() function that creates a simple task.
  11. Build the project and resolve compiler and linker errors.
  12. Debug the application on the supported target.

Expected Result

A successfully compiled FreeRTOS application with a compatible processor port, configured kernel, application task and working scheduler on the selected supported target.

16. Important Note for LPC2129 and Keil uVision

The LPC2129 uses an ARM7TDMI-S processor. It is not an ARM Cortex-M microcontroller. Therefore, a Cortex-M FreeRTOS port must not be selected for an LPC2129 project.

Before Attempting an LPC2129 FreeRTOS Project

  • Verify that a compatible ARM7TDMI-S FreeRTOS port is available for the selected kernel release.
  • Verify compatibility with the exact Keil compiler version and project settings.
  • Check the port's context-switching and interrupt integration requirements.
  • Verify the timer source used for the RTOS tick.
  • Check the linker memory layout and available RAM.
  • Confirm that the simulator supports the required processor and interrupt behavior.
Your current Keil uVision simulator setup is useful for LPC2129 register-level and bare-metal learning. It should not be treated as a working FreeRTOS environment until a compatible port and scheduler behavior have been verified. A successful build alone does not prove that context switching and interrupt behavior work.

For practical FreeRTOS execution, a supported development board with a documented port and suitable debugging support is a more reliable starting point.

18. Lesson Summary

  • A FreeRTOS project combines application code, kernel source and a compatible processor port.
  • FreeRTOSConfig.h controls kernel configuration.
