2. What is FreeRTOS?

FreeRTOS is a compact real-time operating system kernel used to develop multitasking embedded applications. It allows an application to be divided into independent tasks that are scheduled according to their priorities and readiness to execute.

FreeRTOS provides kernel services such as:

  • Task creation and deletion.
  • Task scheduling and priority management.
  • Task delay and time management.
  • Queues and task notifications.
  • Semaphores and mutexes.
  • Event groups.
  • Software timers.
  • Memory allocation mechanisms.
FreeRTOS is primarily a kernel, not a complete desktop-style operating system. It does not automatically provide a filesystem, graphical user interface, networking stack or device drivers. Such facilities may be supplied separately by the platform, libraries or additional software components.

3. Why is FreeRTOS Used?

Embedded applications often need to perform several activities with different timing requirements. For example, a controller may need to acquire sensor data, communicate through UART, monitor faults and update an output.

In a simple program, these activities may be implemented using a large loop and multiple interrupt routines. As the application grows, this approach can become difficult to organize and maintain.

FreeRTOS provides a structured way to separate these activities into tasks and coordinate them using kernel synchronization and communication mechanisms.

4. Brief History and Development

FreeRTOS was created by Richard Barry and became widely used in microcontroller-based embedded development. It was designed to provide a small, portable kernel suitable for resource-constrained processors.

FreeRTOS later became part of the AWS ecosystem. The FreeRTOS project continues to provide kernel and related embedded software components. The kernel is available under the MIT open-source license.

The FreeRTOS kernel is maintained as an open-source project. Its source code, documentation and example projects are available through the official project resources.

5. Important Features of FreeRTOS

5.1 Multitasking

FreeRTOS allows multiple tasks to be created within an application. Each task represents an independent unit of execution with its own stack and task context.

5.2 Priority-Based Scheduling

Tasks are assigned priorities. In the standard FreeRTOS scheduler, a ready task with a higher priority is selected ahead of a ready task with a lower priority.

5.3 Preemptive Scheduling

When preemption is enabled, a newly ready higher-priority task can interrupt the execution of a lower-priority task at a scheduling point.

5.4 Inter-Task Communication

FreeRTOS provides queues, task notifications, stream buffers, message buffers and event groups to exchange information and coordinate tasks.

5.5 Synchronization

Semaphores and mutexes help coordinate task execution and manage access to shared resources.

5.6 Software Timers

Software timers allow applications to execute callback functions after specified tick intervals without requiring a separate application task for every timer.

5.7 Portability

FreeRTOS supports many microcontroller architectures through architecture-specific ports. The selected port provides the low-level mechanisms required for task switching and interrupt integration.

5.8 Configurability

Kernel features and behavior can be configured using FreeRTOSConfig.h. This helps developers adapt the kernel to application and hardware requirements.

6. FreeRTOS Kernel and Application

A FreeRTOS application contains application code and the FreeRTOS kernel. Application tasks use kernel APIs to request services such as task creation, queue communication, delays and synchronization.

7. FreeRTOS vs Bare-Metal Programming

Parameter Bare-Metal FreeRTOS
Program Structure Usually main loop and interrupt routines. Multiple tasks coordinated by a kernel.
Scheduling Application-controlled. Kernel scheduler.
Task Management Usually implemented manually. Provided by kernel APIs.
Communication Application-defined flags and buffers. Queues, notifications and other kernel objects.
Synchronization Implemented by application logic and hardware mechanisms. Semaphores, mutexes and event groups.
Memory Overhead Can be very small. Kernel and task stacks require memory.
Complexity Simple for small applications. Structured for more complex multitasking applications.
Bare-metal programming can also meet real-time requirements. FreeRTOS is useful when the application's task organization, communication and scheduling requirements justify the additional kernel overhead.

8. FreeRTOS Task Execution Concept

A task is an independent execution unit managed by the FreeRTOS scheduler. Each task has a priority, a stack and a task control block maintained by the kernel.

Basic Task States

State Description
Running The task is currently executing on the processor.
Ready The task can execute but is waiting for processor time.
Blocked The task is waiting for a time period or an event.
Suspended The task has been explicitly suspended and is not eligible for scheduling.

9. Basic FreeRTOS Application Structure

A typical FreeRTOS application creates kernel objects, creates tasks and then starts the scheduler. The scheduler manages task execution after it starts.

Basic Program Structure

#include "FreeRTOS.h"
#include "task.h"

void Task1(void *pvParameters)
{
    for (;;)
    {
        /* Task 1 application code */

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void Task2(void *pvParameters)
{
    for (;;)
    {
        /* Task 2 application code */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

int main(void)
{
    /* Initialize hardware and required peripherals. */

    xTaskCreate(
        Task1,
        "Task1",
        256,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        Task2,
        "Task2",
        256,
        NULL,
        1,
        NULL
    );

    vTaskStartScheduler();

    /*
     * Normally the scheduler does not return.
     * If it returns, investigate why it could not start.
     */
    for (;;);
}

Program Explanation

  1. FreeRTOS.h provides common kernel definitions.
  2. task.h provides task-related API declarations.
  3. Task1() and Task2() are task functions.
  4. xTaskCreate() requests creation of a task.
  5. vTaskDelay() blocks a task for a specified tick interval.
  6. vTaskStartScheduler() starts the scheduler.
This is a generic FreeRTOS application structure, not a complete target-specific build. The project must include the correct kernel source files, processor port, memory configuration, interrupt integration and FreeRTOSConfig.h. Check each xTaskCreate() return value in production code.

11. Advantages and Limitations

Advantages

  • Small kernel suitable for many resource-constrained systems.
  • Priority-based task scheduling.
  • Built-in synchronization and communication APIs.
  • Portable architecture-specific implementations.
  • Configurable kernel features.
  • Open-source MIT licensing.

Limitations and Design Considerations

  • Task stacks and kernel objects consume RAM.
  • Incorrect priorities can cause starvation.
  • Blocking and synchronization mistakes can cause deadlocks.
  • Interrupt and scheduling latency must be analyzed.
  • Real-time guarantees depend on the complete system design.
  • Hardware support depends on the availability and quality of the target port.
Using FreeRTOS does not automatically make an application hard real-time. The developer must analyze worst-case execution times, blocking, interrupt latency, scheduling, resource contention and deadline requirements.

12. FreeRTOS Development Workflow

  1. Select a supported microcontroller and development environment.
  2. Obtain the appropriate FreeRTOS kernel source.
  3. Add the correct processor port to the project.
  4. Configure FreeRTOSConfig.h.
  5. Initialize the required hardware.
  6. Create application tasks.
  7. Create queues, semaphores or other kernel objects as required.
  8. Start the scheduler.
  9. Test task behavior and synchronization.
  10. Analyze stack usage, timing and system reliability.
