FreeRTOS Configuration File – FreeRTOSConfig.h

Kernel Configuration, Scheduler Settings, Priorities and Memory Options

Home RTOS Course Chapter 12

1. Learning Objectives

FreeRTOSConfig.h is an application-specific header that controls how the FreeRTOS kernel is configured for a particular embedded project. It allows developers to enable or disable kernel features and define important operating parameters.

  • Understand the purpose of FreeRTOSConfig.h.
  • Identify important configuration macros.
  • Configure scheduler behavior and tick frequency.
  • Set task priorities and stack-related parameters.
  • Understand memory allocation configuration.
  • Configure optional kernel services.
  • Recognize port-specific configuration requirements.

2. Introduction to FreeRTOSConfig.h

FreeRTOSConfig.h is normally created and maintained by the application developer or supplied as part of a board-specific example project. It provides compile-time settings used by the kernel.

The kernel includes this configuration header through its main header file, FreeRTOS.h. Therefore, the compiler must be able to locate the correct configuration file through its include paths. 

Application Project
       |
       +---- FreeRTOSConfig.h
       |
       +---- FreeRTOS.h
                 |
                 +---- includes FreeRTOSConfig.h
                 |
                 +---- Kernel configuration
                              |
                              v
                       FreeRTOS Kernel
FreeRTOSConfig.h is generally project-specific. Two applications using the same FreeRTOS kernel release may use different configuration settings.

3. Structure of FreeRTOSConfig.h

A configuration header contains C preprocessor directives. Most settings are defined using #define statements. 

#ifndef FREERTOS_CONFIG_H
#define FREERTOS_CONFIG_H

/* Scheduler configuration */
#define configUSE_PREEMPTION        1
#define configUSE_TIME_SLICING      1

/* Clock configuration */
#define configTICK_RATE_HZ          1000

/* Task configuration */
#define configMAX_PRIORITIES        5
#define configMINIMAL_STACK_SIZE    128

/* Memory configuration */
#define configSUPPORT_DYNAMIC_ALLOCATION 1
#define configSUPPORT_STATIC_ALLOCATION  0

#endif

This is a simplified illustration. A complete configuration must also provide the required settings for the selected FreeRTOS release, processor port and enabled features.

4. Scheduler Configuration Macros

4.1 configUSE_PREEMPTION

This macro controls whether the scheduler uses preemptive scheduling. 

#define configUSE_PREEMPTION 1
Value Meaning
1 Preemptive scheduling is enabled.
0 Cooperative scheduling behavior is selected.

With preemption enabled, a newly ready task with a higher priority can preempt the currently running lower-priority task at a scheduling point.

4.2 configUSE_TIME_SLICING

#define configUSE_TIME_SLICING 1

This setting controls time slicing among ready tasks that share the same priority in the standard preemptive FreeRTOS scheduler.

Value Behavior
1 Time slicing is enabled.
0 Automatic time slicing is disabled.
Time slicing does not guarantee equal execution time for all tasks in every situation. Task blocking, yielding, priorities and interrupt activity affect actual execution.

5. Tick Rate Configuration

The FreeRTOS tick interrupt provides the kernel with periodic timing information. The tick rate determines how many tick interrupts occur per second. 

#define configTICK_RATE_HZ 1000

Tick Period Calculation

The nominal tick period is calculated as: 

Tick Period = 1 / Tick Frequency

For 1000 Hz:

Tick Period = 1 / 1000
            = 0.001 second
            = 1 millisecond
Tick Frequency Nominal Tick Period
100 Hz10 ms
250 Hz4 ms
500 Hz2 ms
1000 Hz1 ms

A higher tick rate provides finer tick-based timing resolution but increases periodic interrupt overhead.

The tick rate is not the same as the CPU clock frequency. The port must configure a hardware timer or another suitable interrupt source to generate the required RTOS tick.

6. CPU Clock Configuration

Some ports and example configurations use a CPU-clock macro to describe the processor clock frequency. Its exact meaning and use depend on the selected port. 

#define configCPU_CLOCK_HZ 60000000UL

In this illustrative example, the value is 60 MHz. It must match the clock expected by the port and the hardware timer configuration.

Do not assume configCPU_CLOCK_HZ automatically configures the microcontroller clock. Clock initialization and peripheral clock setup are normally handled by startup or platform code.

7. Task Priority Configuration

configMAX_PRIORITIES

#define configMAX_PRIORITIES 5

This macro defines the number of task priority levels available to the application.

With five configured levels, the available priority values are generally: 

Priority 0  - Lowest priority
Priority 1
Priority 2
Priority 3
Priority 4  - Highest configured priority
Priority 0 is the lowest task priority. The maximum usable numeric priority is one less than configMAX_PRIORITIES.

A task priority is assigned during task creation and can be changed later using the appropriate FreeRTOS API when enabled and supported.

8. Stack Configuration

configMINIMAL_STACK_SIZE

#define configMINIMAL_STACK_SIZE 128

This macro defines the minimal stack depth used for certain kernel-created tasks and as a common reference for application task stack sizing. Its unit is StackType_t elements, not bytes.

For example, if StackType_t is 4 bytes:

Stack Depth = 128 words
Stack Memory = 128 × 4
             = 512 bytes

configCHECK_FOR_STACK_OVERFLOW

#define configCHECK_FOR_STACK_OVERFLOW 2

This macro selects the stack-overflow checking method supported by the selected port. Common configurations use:

Value Meaning
0 Stack overflow checking disabled.
1 Method 1 checking.
2 Method 2 checking, including additional stack-fill checks where supported.
Stack checking is diagnostic support, not a guarantee that every possible stack overflow will be detected. The checking method is port-dependent.

9. Memory Allocation Configuration

Dynamic Allocation

#define configSUPPORT_DYNAMIC_ALLOCATION 1

Dynamic allocation allows kernel objects and task stacks to be allocated at runtime using the selected FreeRTOS heap implementation.

Static Allocation

#define configSUPPORT_STATIC_ALLOCATION 1

Static allocation allows the application to provide memory for supported kernel objects before runtime.

Allocation Type Memory Source Characteristic
Dynamic FreeRTOS heap or configured allocator Memory is requested during execution.
Static Application-provided storage Memory is allocated at compile time or otherwise provided in advance.

configTOTAL_HEAP_SIZE

#define configTOTAL_HEAP_SIZE (10 * 1024)

For heap implementations that use this setting, it specifies the configured FreeRTOS heap size in bytes. It does not represent the total RAM available to the entire application.

The heap size macro is not used in the same way by every heap implementation. For example, heap_3 wraps the C library allocator, while heap_5 uses explicitly configured memory regions.

10. Optional Kernel Service Configuration

FreeRTOS provides configuration options for enabling or disabling optional services.

Macro Purpose
configUSE_MUTEXES Enables mutex support.
configUSE_RECURSIVE_MUTEXES Enables recursive mutex support.
configUSE_COUNTING_SEMAPHORES Enables counting semaphore support.
configUSE_TIMERS Enables software timer services.
configUSE_EVENT_GROUPS Enables event group services.
configUSE_TRACE_FACILITY Enables additional kernel trace information.
configUSE_TICK_HOOK Enables the application tick hook when supported.
configUSE_IDLE_HOOK Enables the application idle hook.

The exact set of available macros depends on the FreeRTOS version. Some options require additional configuration or application callback functions.

11. Software Timer Configuration

When software timers are enabled, the kernel uses a timer service task to process timer commands and execute timer callbacks. 

#define configUSE_TIMERS             1
#define configTIMER_TASK_PRIORITY    2
#define configTIMER_QUEUE_LENGTH     10
#define configTIMER_TASK_STACK_DEPTH 256
Macro Purpose
configUSE_TIMERS Enables or disables software timers.
configTIMER_TASK_PRIORITY Sets the priority of the timer service task.
configTIMER_QUEUE_LENGTH Sets the timer command queue capacity.
configTIMER_TASK_STACK_DEPTH Sets the timer service task stack depth in stack words.
Timer callbacks execute in the timer service task, not directly in a hardware ISR. Keep callbacks short and avoid blocking operations.

12. API Inclusion Configuration

Some FreeRTOS APIs can be included or excluded using configuration macros. This helps control code size and application features. 

#define INCLUDE_vTaskSuspend       1
#define INCLUDE_vTaskDelete        1
#define INCLUDE_vTaskDelay         1
#define INCLUDE_vTaskDelayUntil    1
#define INCLUDE_uxTaskPriorityGet  1
#define INCLUDE_vTaskPrioritySet   1

For example, if a particular API is excluded through its corresponding configuration option, application code may not be able to use that API.

INCLUDE_ macros and configUSE_ macros serve different purposes. Check the exact API documentation and configuration requirements for the selected kernel release.

13. Interrupt Priority Configuration

Some FreeRTOS ports require interrupt-priority configuration macros. Their names and meanings depend on the processor architecture and port.

For example, Cortex-M ports may use settings related to interrupt priority grouping and the maximum interrupt priority from which FreeRTOS API functions can be called.

Cortex-M interrupt-priority macros must not be copied into an ARM7/LPC2129 project. LPC2129 uses its own ARM7 exception model and Vectored Interrupt Controller. Always use the requirements of the selected processor port.

14. Example Configuration for a Generic Project

The following example demonstrates how a project might organize common configuration settings. It is not a drop-in configuration for every MCU. 

#ifndef FREERTOS_CONFIG_H
#define FREERTOS_CONFIG_H

/* Scheduler */
#define configUSE_PREEMPTION                 1
#define configUSE_TIME_SLICING               1

/* Clock */
#define configTICK_RATE_HZ                   1000

/* Task priorities and stack */
#define configMAX_PRIORITIES                 5
#define configMINIMAL_STACK_SIZE             128

/* Memory allocation */
#define configSUPPORT_DYNAMIC_ALLOCATION     1
#define configSUPPORT_STATIC_ALLOCATION      0
#define configTOTAL_HEAP_SIZE                (10 * 1024)

/* Kernel services */
#define configUSE_MUTEXES                    1
#define configUSE_RECURSIVE_MUTEXES          1
#define configUSE_COUNTING_SEMAPHORES        1
#define configUSE_TIMERS                     1
#define configUSE_EVENT_GROUPS               1

/* Diagnostics */
#define configCHECK_FOR_STACK_OVERFLOW       2
#define configUSE_TRACE_FACILITY             1

/* API inclusion */
#define INCLUDE_vTaskSuspend                 1
#define INCLUDE_vTaskDelete                  1
#define INCLUDE_vTaskDelay                   1
#define INCLUDE_vTaskDelayUntil              1

#endif
This fragment intentionally omits several release- and port-specific definitions. Before building a real project, start with the configuration template supplied for the exact FreeRTOS port and complete all required settings.

15. Common Configuration Errors

Error Possible Cause
FreeRTOSConfig.h not found Application configuration directory is missing from compiler include paths.
Undefined configuration macro Required setting is missing or incompatible with the selected release.
Scheduler does not operate as expected Incorrect preemption, tick or port configuration.
Unexpected task timing Tick rate, timer setup or clock configuration is incorrect.
Heap allocation failure Insufficient heap memory or incorrect allocation configuration.
Task stack overflow Insufficient task stack depth or excessive function call usage.
Timer commands fail Timer queue capacity or timer service configuration is inadequate.

16. Practical Activity – Configure Kernel Options

Objective: Prepare a configuration plan for a simple multitasking embedded application.

Application Scenario

Consider an embedded controller with three tasks:

  • Sensor task – reads sensor information periodically.
  • Communication task – transmits data through UART.
  • Control task – processes readings and updates control outputs.

Configuration Planning

  1. Select preemptive scheduling if required by the application.
  2. Choose a suitable tick rate based on timing requirements.
  3. Define sufficient priority levels.
  4. Estimate stack requirements for each task.
  5. Choose static or dynamic memory allocation.
  6. Enable queues or other communication services as needed.
  7. Enable mutexes if tasks share protected resources.
  8. Configure stack-overflow diagnostics.

Expected Result

A documented FreeRTOSConfig.h configuration plan with explanations for each selected setting. This is a configuration-planning exercise and does not require running a FreeRTOS port on the LPC2129 simulator.
