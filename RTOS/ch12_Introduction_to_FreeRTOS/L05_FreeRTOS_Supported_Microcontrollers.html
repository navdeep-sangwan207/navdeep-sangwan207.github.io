FreeRTOS Supported Microcontrollers

Processor Architectures, MCU Families, Compiler Ports and Port Selection

1. Learning Objectives

FreeRTOS is designed to be portable across many microcontroller architectures. However, portability does not mean that one compiled kernel binary can run on every processor. Each target requires a compatible processor port and build configuration.

  • Understand FreeRTOS portability.
  • Identify common microcontroller architectures used with FreeRTOS.
  • Understand the relationship between MCU architecture and compiler ports.
  • Differentiate a processor family from a specific MCU model.
  • Learn how to verify FreeRTOS support.
  • Understand important port-selection criteria.
  • Evaluate FreeRTOS suitability for LPC2129 and other embedded targets.

2. Introduction to Microcontroller Support

A microcontroller is an integrated circuit containing a processor core, memory and peripheral interfaces. Examples of peripherals include GPIO, timers, UART, SPI, I2C, ADC and communication controllers.

FreeRTOS provides a kernel that manages tasks, scheduling, communication and synchronization. To operate on a particular MCU, the kernel needs low-level software that understands the processor's architecture.

FreeRTOS support must be checked at the level of the processor architecture, compiler toolchain, port implementation and target hardware. A family name alone is not sufficient proof of compatibility.

3. Meaning of FreeRTOS Portability

Portability means that the same general FreeRTOS kernel design and application APIs can be used across different processor architectures with suitable port implementations.

Portable Kernel Services

  • Task creation and deletion.
  • Priority-based task scheduling.
  • Queues and task communication.
  • Semaphores and mutexes.
  • Event groups.
  • Software timers.
  • Memory management services.

Processor-Dependent Operations

  • Saving and restoring CPU registers.
  • Task context switching.
  • Starting the first task.
  • Tick interrupt integration.
  • Critical-section implementation.
  • Interrupt priority and masking behavior.

The processor port implements these low-level operations for the selected architecture and compiler environment.

5. Popular MCU Families Used with FreeRTOS

5.1 STM32 Microcontrollers

STM32 microcontrollers are based on Arm Cortex-M processor cores. Many STM32 development workflows support FreeRTOS integration through vendor tools, middleware packages or direct kernel integration.

Typical application areas include:

  • Industrial automation.
  • Motor control.
  • Sensor monitoring.
  • Communication gateways.
  • Embedded control systems.

5.2 ESP32 Family

ESP32 devices are used in connected embedded products. FreeRTOS-based software is integrated into the ESP-IDF development framework for supported ESP32 targets.

  • Wi-Fi and Bluetooth applications.
  • Internet of Things devices.
  • Wireless sensor systems.
  • Smart home controllers.

5.3 NXP Microcontrollers

NXP offers multiple MCU families, including Cortex-M-based devices and older ARM-based processors. FreeRTOS compatibility depends on the specific MCU, port and toolchain.

5.4 Nordic Semiconductor Devices

Nordic devices are commonly used for low-power wireless applications. Their software development environments provide device-specific integration options, which must be checked for the exact product and software version.

5.5 RISC-V Microcontrollers

FreeRTOS can be used on supported RISC-V targets through appropriate RISC-V ports. The selected implementation must match the processor's instruction-set features and toolchain.

6. Processor Architecture vs Microcontroller Model

A processor architecture describes the instruction set and CPU behavior. A microcontroller model is a specific product containing a processor core and additional hardware resources.

Level Example
Processor architecture Arm architecture
Processor core Arm Cortex-M4
Microcontroller family STM32F4 series
Specific MCU STM32F407VG

Selecting a processor family is only the first step. The exact core, compiler, port implementation, startup code and interrupt configuration must also be compatible.

7. Role of the Compiler Toolchain

A compiler toolchain converts application and kernel source code into executable machine code. It also provides assembler, linker and debugging tools.

Typical Toolchain Components

  • Compiler: Converts C source code into object code.
  • Assembler: Converts assembly instructions into machine code.
  • Linker: Combines object files and libraries into an executable image.
  • Debugger: Helps inspect program execution and processor state.
  • Build system: Organizes compilation and linking steps.

The selected FreeRTOS port may contain compiler-specific code or assembly instructions. Therefore, the compiler must be compatible with that port.

8. How to Verify FreeRTOS Support

Verification Procedure

  1. Identify the exact microcontroller model.
  2. Identify the processor core and architecture.
  3. Identify the compiler and its version.
  4. Check the FreeRTOS source release and its port directory.
  5. Read the port documentation and supported-target notes.
  6. Check whether the required startup and interrupt integration is available.
  7. Check the memory requirements for kernel objects and task stacks.
  8. Build a minimal application using the selected port.
  9. Test task switching and the tick interrupt on the target or a suitable simulator.
A successful compilation is not sufficient proof that an RTOS port works correctly. Task switching, interrupt handling, tick timing and stack behavior must also be validated.

10. RAM and Flash Requirements

FreeRTOS requires memory for task stacks, task control blocks, queues, synchronization objects and other kernel structures. The application also needs memory for drivers, buffers and product-specific data.

RAM Usage Components

  • Task stacks.
  • Task control blocks.
  • Queue storage.
  • Semaphore and mutex objects.
  • Software timer structures.
  • Application variables and communication buffers.
  • Heap space when dynamic allocation is used.

Flash Usage Components

  • FreeRTOS kernel code.
  • Processor port code.
  • Application code.
  • Hardware drivers.
  • Constant data and lookup tables.
There is no single fixed RAM or Flash requirement for every FreeRTOS project. Actual usage depends on the selected port, enabled features, task count, stack sizes, application code and compiler settings.

11. LPC2129 and FreeRTOS Compatibility

The LPC2129 is based on the ARM7TDMI-S processor. It uses the ARM7 architecture and has a different interrupt and exception model from Cortex-M devices.

Important LPC2129 Characteristics

  • Processor: ARM7TDMI-S.
  • Architecture: ARM7-class 32-bit processor.
  • Interrupt controller: Vectored Interrupt Controller (VIC).
  • Interrupt types: IRQ and FIQ.
  • Development environment in this course: Keil uVision.
  • Current learning setup: Keil simulator without physical hardware.

What Must Be Checked?

  1. Whether the selected FreeRTOS release includes an ARM7-compatible port.
  2. Whether that port supports the selected compiler version.
  3. Whether the startup and context-switching code matches ARM7TDMI-S.
  4. Whether the VIC and timer integration are implemented correctly.
  5. Whether the Keil simulator can support the required execution and interrupt behavior.
Do not assume that a Cortex-M FreeRTOS port works on LPC2129. Also do not assume that the presence of an ARM7 port guarantees compatibility with every Keil compiler version or simulator.

12. Choosing a Development Board for FreeRTOS Practice

For practical FreeRTOS learning, choose a development board with a documented and maintained port, suitable debugging tools and enough memory for the intended exercises.

Board / Family Learning Opportunities
STM32 Nucleo boards Task scheduling, GPIO, UART, timers, ADC and peripheral integration.
ESP32 development boards Multitasking, wireless communication, queues and connected applications.
Supported NXP evaluation boards RTOS integration with NXP MCU peripherals and development tools.
Supported RISC-V development boards RTOS concepts on RISC-V processors and toolchains.

Before purchasing a board, verify the exact MCU, FreeRTOS release, supported toolchain, debugger and availability of example projects.

13. Practical Activity – Check a Target's Compatibility

Objective: Prepare a compatibility checklist for a microcontroller before integrating FreeRTOS.

Procedure

  1. Write down the exact MCU part number.
  2. Identify its processor core.
  3. Record the compiler and version.
  4. Locate the matching FreeRTOS port.
  5. Check the port documentation.
  6. Identify required startup and assembly files.
  7. Check the available RAM and Flash.
  8. Identify the timer or interrupt source for the RTOS tick.
  9. Record any simulator or hardware limitations.

Expected Result

A documented compatibility assessment identifying the target processor, compiler, candidate port, memory resources and outstanding integration checks.

15. Lesson Summary

  • FreeRTOS is portable through architecture- and compiler-specific ports.
  • Different MCU families require appropriate port implementations.
  • Processor architecture and exact MCU model are different levels of identification.
  • Compiler and toolchain compatibility must be verified.
  • RAM, Flash, peripherals and interrupt behavior influence MCU selection.
  • Successful compilation alone does not prove correct RTOS operation.
  • LPC2129 requires an ARM7-compatible implementation, not a Cortex-M port.
