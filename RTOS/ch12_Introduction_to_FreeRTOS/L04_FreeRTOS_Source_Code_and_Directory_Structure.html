FreeRTOS Source Code and Directory Structure

Kernel Files, Processor Ports, Configuration and Project Organization

1. Learning Objectives

FreeRTOS is distributed as source code that can be integrated into an embedded application project. Understanding its directory structure helps developers identify kernel implementation files, processor-specific ports, configuration headers and example projects.

  • Understand the organization of a FreeRTOS source repository.
  • Identify important kernel source and header files.
  • Understand the purpose of the portable directory.
  • Identify processor-specific port files.
  • Understand the role of FreeRTOSConfig.h.
  • Distinguish kernel files from application files.
  • Understand how FreeRTOS source files are added to a project.

2. Introduction to FreeRTOS Source Code

FreeRTOS is a source-based real-time operating system kernel. Developers integrate the required kernel source files, processor port and application configuration into their embedded software project.

A typical project contains the following elements:

  • FreeRTOS kernel source files.
  • Kernel header files.
  • Processor-specific port implementation.
  • Memory allocation implementation, if dynamic allocation is used.
  • FreeRTOSConfig.h configuration file.
  • Application source files and hardware drivers.
  • Compiler and linker configuration.
FreeRTOS source repositories and package layouts can change between releases. The directory names below describe a common source organization; always follow the documentation supplied with the exact release and processor port being used.

4. FreeRTOS Kernel Directory

The kernel directory contains the main implementation of FreeRTOS services. It includes task management, scheduling, queues, synchronization and other kernel functionality.

Important Kernel Source Files

File Purpose
tasks.c Implements task management and core scheduler operations.
queue.c Implements queues and related synchronization objects.
list.c Implements internal list operations used by the kernel.
timers.c Implements software timer services.
event_groups.c Implements event group services.
stream_buffer.c Implements stream and message buffer services.
Some kernel features are implemented in shared source files. For example, semaphore functionality is closely integrated with the queue implementation rather than requiring a separate semphr.c source file.

5. Kernel Include Directory

The include directory contains public kernel header files. Application source files include these headers to access documented FreeRTOS APIs and data types.

Header File Purpose
FreeRTOS.h Core definitions, configuration inclusion and common kernel types.
task.h Task creation, deletion, scheduling and task-control APIs.
queue.h Queue creation, sending, receiving and related operations.
semphr.h Semaphore and mutex API definitions.
timers.h Software timer API definitions.
event_groups.h Event group API definitions.
stream_buffer.h Stream and message buffer API definitions.

Example Header Usage

#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "semphr.h"
#include "timers.h"
#include "event_groups.h"

Include only the headers required by the application. The compiler must also be configured with the correct include-directory paths.

6. Portable Directory

The portable directory contains processor- and compiler-specific implementations required to run the FreeRTOS kernel on a target microcontroller.

Why Is a Port Required?

Different processors have different register sets, exception mechanisms, interrupt behavior and context-switching requirements. The processor port adapts the generic kernel to those differences.

Typical Port Files

File Purpose
port.c Contains port-specific implementation functions, such as context-switching and scheduler support.
portmacro.h Defines port-specific types, macros and low-level operations.

Some ports also include assembly source files or additional compiler-specific implementation files.

A port must match the target processor architecture and compiler requirements. A Cortex-M port cannot simply be selected for an ARM7TDMI-S processor.

7. Compiler-Specific Port

FreeRTOS ports are commonly organized according to processor architecture and compiler toolchain. The compiler-specific implementation handles differences in compiler syntax, assembly integration and low-level context-switching support.

Examples of Compiler Toolchains

  • GCC-based embedded toolchains.
  • Arm Compiler toolchains.
  • IAR Embedded Workbench toolchains.
  • Other supported compiler environments.

The existence of a compiler directory does not guarantee support for every processor when used with that compiler. The exact architecture/compiler combination must be supported.

8. Memory Management Directory

FreeRTOS provides alternative heap implementations for applications that use dynamic allocation. These implementations are commonly stored in a memory-management directory such as portable/MemMang.

File Allocation Behavior
heap_1.c Allocation only; memory cannot be freed.
heap_2.c Allocation and freeing without adjacent-block coalescing.
heap_3.c Wraps standard C malloc() and free().
heap_4.c Allocation, freeing and adjacent-block coalescing.
heap_5.c Supports multiple non-contiguous heap regions.
Normally, include only the selected heap implementation in a dynamically allocated FreeRTOS project. Do not compile all heap implementation files together as competing definitions of the same allocation functions.

9. FreeRTOSConfig.h

FreeRTOSConfig.h is the application-specific configuration header. It defines kernel settings such as tick frequency, priority levels, memory allocation behavior and optional services.

Example Configuration

#ifndef FREERTOS_CONFIG_H
#define FREERTOS_CONFIG_H

#define configUSE_PREEMPTION          1
#define configUSE_TIME_SLICING        1

#define configCPU_CLOCK_HZ            60000000UL
#define configTICK_RATE_HZ            1000

#define configMAX_PRIORITIES          5
#define configMINIMAL_STACK_SIZE      128

#define configTOTAL_HEAP_SIZE         (10 * 1024)

#define configUSE_MUTEXES             1
#define configUSE_TIMERS              1
#define configUSE_COUNTING_SEMAPHORES 1

#define configCHECK_FOR_STACK_OVERFLOW 2

#endif
This is an illustrative configuration fragment, not a universally complete FreeRTOSConfig.h file. A real configuration must define all required settings for the selected release and port, including interrupt-related settings where applicable. The CPU clock value must match the actual port's expected clock definition.

Configuration Responsibilities

  • Configure scheduler behavior.
  • Set the kernel tick rate.
  • Define task priority capacity.
  • Configure memory allocation and heap size.
  • Enable or disable optional kernel services.
  • Configure diagnostic and runtime-statistics features.
  • Set port-specific interrupt and processor options.

10. Demo and Example Directories

FreeRTOS distributions commonly provide demonstration projects and example applications. Their purpose is to show how the kernel can be integrated with a particular microcontroller and compiler.

Typical Example Content

  • Task creation and scheduling examples.
  • Queue-based communication examples.
  • Semaphore and mutex examples.
  • Software timer examples.
  • Interrupt-to-task communication examples.
  • Board-specific peripheral integration.
  • Project files for supported IDEs and toolchains.

A demo may include board-specific startup code, peripheral drivers and linker settings. These components are not necessarily part of the generic FreeRTOS kernel.

11. Application Directory

The application directory contains the source code written for the embedded product. It normally includes the main application entry point, task functions, hardware drivers and configuration files.

Keeping application files separate from kernel source files makes maintenance and kernel upgrades easier.

12. How Source Files Are Integrated into a Project

The compiler and linker must be able to locate the required kernel headers and compile the selected kernel and port source files.

Typical Integration Steps

  1. Download or obtain a supported FreeRTOS source release.
  2. Identify the target processor architecture.
  3. Select a supported processor/compiler port.
  4. Add the required kernel source files to the project.
  5. Add the selected port source files.
  6. Add one heap implementation if dynamic allocation is used.
  7. Create and configure FreeRTOSConfig.h.
  8. Add the kernel include directory and port include directory.
  9. Configure startup code, linker script and interrupt integration.
  10. Build and debug the application.
The exact source-file list depends on which kernel features are enabled and how the selected FreeRTOS release is packaged. Use the release's official build instructions instead of assuming every source file must always be compiled.

The application calls public APIs. The kernel implementation performs task management and scheduling, while the processor port provides low-level operations required by the CPU.

14. Practical Activity – Inspect a FreeRTOS Source Package

Objective: Identify the main directories and files in a FreeRTOS source package.

Procedure

  1. Open a FreeRTOS source package.
  2. Locate the kernel directory.
  3. Find tasks.c, queue.c and list.c.
  4. Open the include directory.
  5. Identify task.h, queue.h and FreeRTOS.h.
  6. Locate the portable directory.
  7. Inspect the processor-specific port folder.
  8. Locate the memory-management implementations.
  9. Find an example FreeRTOSConfig.h file.
  10. Identify application and hardware-driver files in a demo.

Expected Result

A directory map identifying kernel source files, public headers, processor-port files, memory management files, configuration and application code.

15. Common Integration Errors

Error Possible Cause
Header file not found Kernel include path is missing or incorrect.
Undefined reference to kernel API Required kernel source file is not compiled or linked.
Port-related compilation errors Incorrect processor or compiler port selected.
Configuration macro errors FreeRTOSConfig.h is incomplete or incompatible with the port.
Multiple definition errors More than one heap implementation or conflicting source file is compiled.
Linker memory errors Insufficient RAM/Flash or incorrect linker configuration.
Scheduler does not start correctly Port setup, tick interrupt, startup code or configuration problem.

16. Important Notes for LPC2129 and Keil uVision

The LPC2129 uses an ARM7TDMI-S processor. A FreeRTOS project for this device requires a compatible ARM7 port, a compatible compiler toolchain and suitable startup and interrupt integration.

  • ARM7TDMI-S is not a Cortex-M processor.
  • ARM7 uses IRQ and FIQ exception mechanisms rather than the Cortex-M NVIC model.
  • Do not select a Cortex-M FreeRTOS port for LPC2129.
  • Verify that the chosen FreeRTOS release provides a compatible ARM7/compiler port.
  • Check the compiler version and assembly syntax compatibility.
  • Verify the tick interrupt and context-switching implementation.
The fact that an LPC2129 project can be compiled in Keil uVision does not establish that FreeRTOS will run correctly in its simulator. A compatible port and simulator support for the required CPU and interrupt behavior must be verified. The source inspection activity in this lesson does not require physical LPC2129 hardware.
