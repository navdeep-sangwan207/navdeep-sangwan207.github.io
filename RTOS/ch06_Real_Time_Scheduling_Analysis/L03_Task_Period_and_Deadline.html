1. Introduction

Real-time tasks are often designed to execute at specific time intervals and complete their work within defined deadlines. Two fundamental timing parameters used in real-time scheduling are the task period and the task deadline.

  • Period: The time interval between consecutive releases of a periodic task.
  • Deadline: The latest time by which a task instance must complete its required work.

These parameters help determine task frequency, processor utilization, scheduling feasibility, and whether a real-time system can meet its timing requirements.

Example: If a temperature-monitoring task executes every 100 ms, its period is 100 ms. If each execution must finish within 30 ms after release, its relative deadline is 30 ms.

2. Task Period

The task period is the interval between two consecutive releases of a periodic task.

T = r(k+1) − r(k)

Where:

  • T: Task period.
  • r(k): Release time of the current task instance.
  • r(k+1): Release time of the next task instance.

2.1 Example

A sensor-monitoring task is released at 0 ms, 100 ms, 200 ms, and 300 ms.

T = 100 − 0 = 100 ms

The task period is 100 ms.

2.2 Periodic task characteristics

  • Releases occur at regular intervals.
  • Each release creates a new job or task instance.
  • Each job performs the same recurring function, although its execution time may vary.
  • The task period determines the frequency of releases.

3. Periodic, Aperiodic and Sporadic Tasks

Task TypeRelease PatternExample
PeriodicReleased at regular intervals.Read a temperature sensor every 100 ms.
AperiodicReleased irregularly without a guaranteed minimum separation.Process an occasional user command.
SporadicReleased irregularly, but with a known minimum inter-arrival time.Respond to an external event that cannot occur more frequently than a specified interval.
A sporadic task does not have a fixed release period. Its minimum inter-arrival time provides a bound on how frequently new jobs may arrive.

4. Task Deadline

A deadline specifies the latest permitted completion time for a task instance.

In real-time scheduling, the deadline is usually expressed relative to the task's release time.

Absolute Deadline = Release Time + Relative Deadline
d(k) = r(k) + D

Where:

  • d(k): Absolute deadline of job k.
  • r(k): Release time of job k.
  • D: Relative deadline.

Example

A task is released at 50 ms and has a relative deadline of 20 ms.

d = 50 + 20 = 70 ms

The task must complete by 70 ms.

6. Relationship Between Period and Deadline

The relationship between the relative deadline and task period is important in real-time scheduling theory.

6.1 Implicit deadline

A task has an implicit deadline when its relative deadline equals its period.

D = T

Example: A task released every 100 ms must complete within 100 ms of each release.

6.2 Constrained deadline

A task has a constrained deadline when its relative deadline is less than or equal to its period.

D ≤ T

Example: A task has a period of 100 ms and a relative deadline of 60 ms.

6.3 Arbitrary deadline

A task has an arbitrary deadline when its relative deadline may exceed its period.

D > T

Example: A task has a period of 100 ms and a relative deadline of 150 ms. Its previous job may still have an outstanding deadline when the next job is released.

Deadline ModelConditionExample (T = 100 ms)
ImplicitD = TD = 100 ms
ConstrainedD ≤ TD = 60 ms
ArbitraryD may exceed TD = 150 ms
Do not confuse a task's period with its deadline. The period controls the spacing between releases; the deadline controls the completion requirement for each job.

8. Deadline Miss

A deadline miss occurs when a task instance does not complete its required work by its absolute deadline.

Example

A task is released at 0 ms and has an absolute deadline of 50 ms.

  • Completion at 40 ms: deadline met.
  • Completion at 50 ms: deadline met exactly.
  • Completion at 55 ms: deadline missed by 5 ms.
Deadline Miss = Completion Time > Absolute Deadline

Possible causes

  • Excessive execution time.
  • Higher-priority task interference.
  • Long interrupt service routines.
  • Resource contention and priority inversion.
  • Incorrect task period or priority configuration.
  • Unexpected workload or insufficient processor capacity.

The consequence of a deadline miss depends on the system's real-time requirements. A late result may still be useful in a soft real-time system, while a firm real-time result may have no value after its deadline.

10. Numerical Example 2 – Determine Deadline Compliance

A task has the following timing information:

ParameterValue
Release time20 ms
Relative deadline25 ms
Completion time42 ms

Step 1: Calculate absolute deadline

d = 20 + 25 = 45 ms

Step 2: Calculate response time

R = 42 − 20 = 22 ms

Step 3: Check deadline

R = 22 ms ≤ D = 25 ms

Result: The task meets its deadline with a margin of 3 ms.

11. Numerical Example 3 – Determine Deadline Miss

A periodic task has a period of 100 ms and a relative deadline of 70 ms. A job is released at 200 ms and completes at 275 ms.

Step 1: Calculate absolute deadline

d = 200 + 70 = 270 ms

Step 2: Calculate response time

R = 275 − 200 = 75 ms

Step 3: Compare response time and deadline

75 ms > 70 ms

Result: The task misses its deadline by 5 ms.

12. Periodic Task Implementation in FreeRTOS

FreeRTOS provides vTaskDelayUntil() for implementing periodic task execution using an absolute tick schedule.

12.1 Example code

#include "FreeRTOS.h"
#include "task.h"

void SensorTask(void *pvParameters)
{
    TickType_t lastWakeTime;
    const TickType_t period = pdMS_TO_TICKS(100);

    lastWakeTime = xTaskGetTickCount();

    for (;;)
    {
        /* Perform periodic sensor-processing work */
        ReadSensor();
        ProcessSensorData();

        /* Maintain a 100 ms release interval */
        vTaskDelayUntil(&lastWakeTime, period);
    }
}

12.2 Explanation

  • xTaskGetTickCount() obtains the current RTOS tick count.
  • pdMS_TO_TICKS(100) converts 100 milliseconds into RTOS ticks.
  • vTaskDelayUntil() schedules the next periodic wake time relative to the previous scheduled wake time.
  • The task performs its work after each release.
Unlike a simple relative delay after work, vTaskDelayUntil() helps maintain a regular periodic release schedule. It does not guarantee that the task will complete before its deadline.

12.3 Important limitations

  • The tick frequency determines the timing resolution.
  • If the period converts to zero ticks, the intended delay cannot be represented by the tick schedule.
  • Execution time, interference, blocking, and scheduler behavior still affect completion.
  • A task that overruns its next scheduled release requires deliberate overrun handling.
  • Use suitable configuration and timing analysis for deadline guarantees.

13. Relationship with Scheduling Algorithms

Scheduling AlgorithmUse of Period and Deadline
Rate Monotonic Scheduling (RMS)Uses task periods to assign fixed priorities; shorter periods receive higher priorities.
Earliest Deadline First (EDF)Selects the ready job with the earliest absolute deadline.
Fixed-priority schedulingUses assigned priorities; deadlines are checked through timing analysis.
Round RobinUses time slices for eligible tasks; it does not inherently guarantee deadline compliance.

Period and deadline are task timing requirements. A scheduling algorithm determines how processor time is allocated to help satisfy those requirements.

14. Common Mistakes

MistakeCorrect Understanding
Period and deadline are identical.They are equal only in the implicit-deadline model.
Every task is periodic.Tasks can also be aperiodic or sporadic.
Relative deadline is the actual clock time.Absolute deadline is the actual completion time limit on the clock.
A task with D > T is impossible.Such tasks are possible but may have overlapping jobs and need suitable analysis.
vTaskDelayUntil guarantees a deadline.It helps maintain periodic release timing but does not guarantee completion before the deadline.
A deadline miss always causes system failure.The consequence depends on the task and system's real-time requirements.

15. Lesson Summary

  • Task period is the interval between consecutive periodic releases.
  • Relative deadline is the allowed completion interval after release.
  • Absolute deadline equals release time plus relative deadline.
  • Implicit deadline: D = T.
  • Constrained deadline: D ≤ T.
  • Arbitrary deadline: D may exceed T.
  • A deadline miss occurs when completion is later than the absolute deadline.
  • FreeRTOS provides vTaskDelayUntil() for periodic task scheduling.
  • Periodic scheduling alone does not prove deadline compliance.
