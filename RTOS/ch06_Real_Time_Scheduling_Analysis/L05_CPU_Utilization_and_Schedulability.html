CPU Utilization and Schedulability

1. Introduction

A real-time embedded system may execute several periodic, aperiodic, and sporadic tasks. The processor must provide enough execution time for these tasks while ensuring that their timing requirements are satisfied.

Two important concepts are:

  • CPU utilization: The fraction of processor capacity consumed by task execution.
  • Schedulability: Whether a task set can be scheduled so that all required timing constraints are satisfied under the assumed model.
Central concept: CPU utilization measures processor workload. Schedulability analysis determines whether the workload can meet its timing requirements.

2. CPU Utilization

CPU utilization represents the fraction of available processor time used for executing tasks.

For one task with execution time C and period T:

U = C / T

Where:

  • C: Execution time or WCET used by the analysis.
  • T: Task period.
  • U: Task utilization.

Example

A task executes for 2 ms every 10 ms.

U = 2 / 10 = 0.2 = 20%

The task consumes 20% of the processor capacity under this periodic workload model.

3. Total CPU Utilization

For a set of n independent periodic tasks executing on a single processor, total utilization is calculated as:

U = Σ (Cᵢ / Tᵢ), for i = 1 to n

Where:

  • Cᵢ: Execution-time bound of task i.
  • Tᵢ: Period of task i.
  • n: Number of tasks.

Numerical Example 1

Consider the following periodic tasks:

TaskExecution Time (C)Period (T)Utilization
T12 ms10 ms20%
T23 ms20 ms15%
T34 ms40 ms10%
Total——45%
U = 0.20 + 0.15 + 0.10 = 0.45
Total CPU Utilization = 45%

Result: The task set requires 45% of the processor capacity under the stated utilization model.

4. CPU Idle Time

CPU idle time is the time during which the processor has no task ready to execute and can remain idle or enter an appropriate low-power state.

For a simplified single-processor workload where all modeled work is accounted for:

Idle Fraction = 1 − U

If CPU utilization is 45%:

Idle Fraction = 1 − 0.45 = 0.55 = 55%

45%: Modeled CPU workload

55%: Remaining processor capacity in the simplified model

The remaining utilization capacity is not necessarily entirely available to application tasks. Interrupts, kernel overhead, background activities, and other unmodeled work may consume processor time.

5. Processor Capacity and Overload

For a single processor, utilization above 100% indicates that the modeled workload requires more processor execution time than the processor can provide over the long run.

UtilizationInterpretation
U < 1Average modeled demand is below processor capacity.
U = 1Modeled demand uses the entire processor capacity.
U > 1Modeled demand exceeds processor capacity.
For periodic tasks with constrained deadlines and suitable assumptions, utilization is an important schedulability measure. However, utilization below 100% alone does not guarantee that every fixed-priority task set will meet all deadlines.

6. What Is Schedulability?

A task set is schedulable if the scheduling algorithm can execute all required jobs while satisfying their timing constraints.

Schedulability analysis examines:

  • Task execution-time requirements.
  • Task periods and release patterns.
  • Relative and absolute deadlines.
  • Scheduling policy and task priorities.
  • Blocking and resource-sharing behavior.
  • Interrupt and scheduling overhead.

A task set may have low average CPU utilization and still miss a deadline if the scheduling policy or task timing constraints are unsuitable.

7. Schedulability Under Different Scheduling Algorithms

AlgorithmPriority TypeImportant Timing Consideration
Rate Monotonic Scheduling (RMS)Fixed priority based on task period.Shorter-period tasks receive higher priority.
Earliest Deadline First (EDF)Dynamic priority based on absolute deadline.Ready job with earliest absolute deadline is selected.
First-Come First-Served (FCFS)Arrival order.Long jobs can delay short-deadline jobs.
Round RobinEqual-priority time sharing in its basic form.Time slices distribute CPU access but do not inherently guarantee deadlines.

Different scheduling algorithms have different schedulability tests. A utilization threshold derived for one algorithm must not be applied indiscriminately to another.

8. Rate Monotonic Utilization Bound

Rate Monotonic Scheduling (RMS) assigns fixed priorities according to task periods. A task with a shorter period receives a higher priority.

For n independent periodic tasks with implicit deadlines, preemptive fixed-priority scheduling, and the standard ideal assumptions, the Liu-Layland sufficient utilization bound is:

U ≤ n(21/n − 1)

This bound is sufficient, not necessary. If utilization is below or equal to the bound, the task set is schedulable under the theorem's assumptions. If utilization exceeds it, schedulability is not automatically disproved.

9. Numerical Example 2 – RMS Utilization Test

Consider three periodic tasks:

TaskExecution TimePeriod
T11 ms5 ms
T22 ms10 ms
T33 ms20 ms

Step 1: Calculate utilization

U = 1/5 + 2/10 + 3/20
U = 0.20 + 0.20 + 0.15 = 0.55

Total utilization = 55%.

Step 2: Calculate the RMS bound

Ubound = 3(21/3 − 1)
Ubound ≈ 0.7798 = 77.98%

Step 3: Compare

55% ≤ 77.98%

Result: The utilization-bound test confirms schedulability under the standard RMS assumptions.

10. Numerical Example 3 – Utilization Bound Is Inconclusive

Consider three periodic tasks with total utilization of 80%.

U = 0.80
RMS Bound = 0.7798

Since:

0.80 > 0.7798

The Liu-Layland sufficient test does not establish schedulability.

This does not mean the task set is necessarily unschedulable. The sufficient bound is conservative. Response-time analysis or another appropriate exact test may establish whether the task set meets its deadlines.

11. EDF Utilization Test

Earliest Deadline First (EDF) is a dynamic-priority scheduling algorithm. The scheduler selects the ready job with the earliest absolute deadline.

For independent, preemptive periodic tasks on a single processor, with deadlines equal to periods and ideal scheduling assumptions, the utilization condition is:

U ≤ 1

Under these assumptions, this condition is necessary and sufficient for EDF schedulability.

Example

A task set has total utilization of 85%.

U = 0.85 ≤ 1

Result: The task set passes the ideal EDF utilization test, provided all the assumptions hold.

The simple EDF utilization test must not be applied blindly to arbitrary deadlines, blocking, significant overhead, or other non-ideal task models. Additional analysis may be required.

12. Numerical Example 4 – EDF vs RMS

Suppose a task set has utilization of 80% and contains three independent periodic tasks with implicit deadlines.

TestConditionResult
RMS utilization-bound test80% ≤ 77.98%Does not pass the sufficient test.

This demonstrates that the utilization bounds depend on the scheduling algorithm. EDF can theoretically utilize more processor capacity than the classic RMS sufficient bound under the stated ideal task model.

13. Factors That Affect Schedulability

  • WCET: Higher execution-time requirements increase processor demand.
  • Period: Shorter periods create more frequent task releases.
  • Deadline: Short deadlines reduce the available response time.
  • Blocking: Resource contention can delay task completion.
  • Interrupt load: ISRs consume processor time and may interfere with tasks.
  • Context-switch overhead: Switching between tasks adds execution overhead.
  • Priority assignment: Poor priority selection can cause deadline misses.
  • Task dependencies: Communication and synchronization can introduce additional delays.

14. FreeRTOS and CPU Utilization

FreeRTOS is commonly configured as a fixed-priority preemptive scheduler. Task priorities and blocking behavior determine which ready task receives CPU time.

Important concepts

  • Higher-priority ready tasks generally execute before lower-priority ready tasks in a preemptive configuration.
  • Tasks blocked on queues, semaphores, notifications, or delays do not continuously consume CPU time.
  • The idle task runs when no application task is ready to execute.
  • Equal-priority time slicing can be configured.
  • Interrupt service routines execute outside ordinary task scheduling and consume processor capacity.

14.1 Runtime statistics

FreeRTOS can provide optional runtime statistics through facilities such as vTaskGetRunTimeStats(), when configured with a suitable runtime counter.

These statistics help estimate the CPU time consumed by individual tasks. They are useful for profiling and identifying heavily loaded tasks.

Runtime statistics report measured behavior over an observation interval. They do not independently prove that all deadlines will be met under every possible workload.

17. Lesson Summary

  • CPU utilization is the fraction of processor capacity consumed by tasks.
  • For periodic tasks, utilization is calculated as C/T.
  • Total utilization is the sum of individual task utilizations.
  • Schedulability determines whether all required deadlines can be satisfied.
  • The classic RMS utilization bound is a sufficient test under specific assumptions.
  • For ideal EDF scheduling with implicit deadlines on one processor, U ≤ 1 is necessary and sufficient.
  • Blocking, interrupts, overhead, and task dependencies can affect schedulability.
  • FreeRTOS runtime statistics help profile CPU usage but do not prove deadline compliance.
