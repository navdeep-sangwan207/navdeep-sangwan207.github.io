1. Introduction

Rate Monotonic Scheduling (RMS) is a classical fixed-priority scheduling algorithm used in real-time systems. It assigns task priorities according to their periods.

The fundamental rule is:

Shorter Period → Higher Priority

A task that executes more frequently receives a higher fixed priority than a task with a longer period.

RMS is especially useful for analyzing independent periodic tasks in single-processor real-time systems.

Example: If Task A has a period of 10 ms and Task B has a period of 50 ms, RMS assigns higher priority to Task A.

2. What Is Rate Monotonic Scheduling?

RMS is a preemptive, fixed-priority scheduling algorithm. Each periodic task receives a priority based on its period, and that priority remains fixed during normal scheduling.

Important characteristics

  • Static priority assignment.
  • Shorter-period tasks receive higher priority.
  • Preemptive execution is supported.
  • Higher-priority ready tasks can interrupt lower-priority tasks.
  • Priority assignment is based on task periods, not actual execution time.
  • Schedulability can be examined using utilization bounds and response-time analysis.

3. Priority Assignment in RMS

Consider three periodic tasks:

TaskPeriodRMS Priority
T110 msHighest
T220 msMedium
T350 msLowest
Highest priority: T1 – Period 10 ms
Medium priority: T2 – Period 20 ms
Lowest priority: T3 – Period 50 ms

When multiple tasks are ready, the scheduler selects the ready task with the highest assigned priority.

RMS priority assignment is based on period. It does not mean that a task with a shorter period always has a shorter execution time.

4. Assumptions of Classical RMS Analysis

The classical RMS utilization-bound theorem uses an idealized task model. Its standard assumptions include:

  • Tasks are independent periodic tasks.
  • Tasks execute on a single processor.
  • Tasks are preemptible.
  • Execution times are bounded and known.
  • Deadlines are equal to task periods (implicit deadlines).
  • There is no resource blocking or additional scheduling overhead in the basic model.
  • Task release patterns and scheduling behavior follow the assumed periodic model.
If blocking, release jitter, non-preemptive sections, or significant overhead are present, the simple utilization-bound test may not be sufficient. A more detailed analysis is needed.

5. RMS Utilization Formula

For n independent periodic tasks, total processor utilization is:

U = Σ (Cᵢ / Tᵢ)

Where:

  • Cᵢ: Worst-case execution time of task i.
  • Tᵢ: Period of task i.
  • n: Number of periodic tasks.

The Liu-Layland sufficient utilization bound for RMS is:

U ≤ n(21/n − 1)

This expression gives a sufficient utilization threshold for the classical task model.

7. Numerical Example 1 – RMS Utilization Test

Consider three periodic tasks:

TaskExecution Time (C)Period (T)
T11 ms5 ms
T22 ms10 ms
T33 ms20 ms

Step 1: Calculate individual utilization

U1 = 1 / 5 = 0.20
U2 = 2 / 10 = 0.20
U3 = 3 / 20 = 0.15

Step 2: Calculate total utilization

U = 0.20 + 0.20 + 0.15 = 0.55

Total utilization = 55%.

Step 3: Calculate the RMS bound

Ubound = 3(21/3 − 1)
Ubound ≈ 0.7798 = 77.98%

Step 4: Compare the values

55% ≤ 77.98%

Result: The task set passes the RMS sufficient utilization test under the classical assumptions.

8. Numerical Example 2 – Utilization Bound Is Inconclusive

Consider three periodic tasks with a total utilization of 80%.

U = 0.80
Ubound = 0.7798

Since:

0.80 > 0.7798

The task set does not pass the sufficient utilization-bound test.

Conclusion: RMS schedulability is not established by this test. A more detailed response-time analysis or an appropriate exact schedulability test is required.

10. RMS Response-Time Analysis

When the utilization-bound test is inconclusive, response-time analysis can provide a more detailed schedulability check for fixed-priority tasks.

For a task i in a suitable fixed-priority preemptive model, a common response-time recurrence is:

Rᵢ = Cᵢ + Bᵢ + Σ ⌈Rᵢ / Tⱼ⌉ Cⱼ

Where:

  • Rᵢ: Worst-case response time of task i.
  • Cᵢ: WCET of task i.
  • Bᵢ: Blocking time of task i.
  • Tⱼ: Period of each higher-priority task j.
  • Cⱼ: WCET of each higher-priority task j.

The recurrence is evaluated iteratively until the result converges or exceeds the task deadline. More complete models may need to include release jitter, interrupt interference, and overhead.

The full iterative response-time calculation is covered in Lesson 08: Response Time Analysis. This lesson introduces the relationship between RMS priorities and response-time interference.

RMS is commonly used in fixed-priority embedded RTOS designs. EDF is useful when dynamic deadline-based scheduling is required and supported by the system.

12. RMS and FreeRTOS

FreeRTOS commonly uses a fixed-priority scheduler. This makes period-based RMS priority assignment possible for suitable periodic task sets.

12.1 Example priority assignment

TaskPeriodRelative RMS Priority

ControlTask20 msMedium
DisplayTask100 msLowest

In typical FreeRTOS configurations, a larger numeric priority value represents a higher task priority.

12.2 Important configuration considerations

  • Verify that the selected FreeRTOS port supports the target processor.
  • Check configUSE_PREEMPTION for the intended scheduling behavior.
  • Use suitable task periods and execution-time estimates.
  • Use vTaskDelayUntil() to maintain periodic release timing.
  • Analyze blocking caused by mutexes and shared resources.
  • Account for interrupt and kernel overhead.
FreeRTOS fixed-priority scheduling does not automatically perform RMS priority assignment or prove schedulability. The developer must assign priorities and analyze the task set.

13. Advantages of RMS

  • Simple and systematic priority assignment.
  • Static priorities are easy to configure and understand.
  • Suitable for many periodic embedded applications.
  • Works naturally with fixed-priority preemptive RTOS kernels.
  • Has well-established mathematical schedulability analysis.
  • Provides predictable priority relationships for recurring tasks.

14. Limitations of RMS

  • The classic utilization-bound test is conservative.
  • Dynamic priority changes are not part of basic RMS.
  • Blocking and resource-sharing effects need additional analysis.
  • Arbitrary deadlines require more advanced analysis.
  • Incorrect WCET estimates can invalidate the result.
  • High interrupt load and scheduling overhead reduce available processor capacity.

16. Lesson Summary

  • RMS is a preemptive fixed-priority scheduling algorithm.
  • Shorter-period tasks receive higher priority.
  • The classic RMS utilization bound is n(21/n − 1).
  • The Liu-Layland bound is sufficient, not necessary.
  • Response-time analysis provides a more detailed schedulability test.
  • RMS is suitable for many periodic embedded workloads.
  • FreeRTOS can implement period-based fixed priorities, but priority assignment and schedulability analysis remain the developer's responsibility.
