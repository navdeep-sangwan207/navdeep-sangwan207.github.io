Interrupt Nesting and Masking

1. Introduction

Interrupt masking is a mechanism used to prevent selected interrupt requests from being accepted by the processor for a period of time.

It is commonly used to protect critical operations, control interrupt nesting, and prevent unwanted interruption of sensitive code.

Interrupt nesting and interrupt masking are closely related:

  • Interrupt nesting allows eligible interrupts to preempt an active ISR.
  • Interrupt masking prevents selected interrupts from being accepted.
Interrupt masking does not necessarily stop a peripheral from generating an interrupt request. It controls whether the processor or interrupt controller allows that request to be serviced.

2. What Is Interrupt Masking?

When an interrupt is masked, its request is prevented from being accepted according to the applicable processor or controller masking rules.

For example, suppose a timer interrupt occurs while IRQ exceptions are masked. The timer peripheral may still set its interrupt status flag, but the processor will not accept the IRQ until the masking condition is removed, provided the source retains its request.

Simple conceptual example

Disable_Selected_Interrupts();

Update_Shared_Data();

Enable_Selected_Interrupts();

This example illustrates the concept only. A real implementation must preserve the previous interrupt state and use the correct architecture-specific mechanism.

3. Why Is Interrupt Masking Required?

  • To protect shared data during a critical update.
  • To prevent unwanted nesting during sensitive operations.
  • To maintain consistency of multi-step register or data operations.
  • To control interrupt handling during system initialization.
  • To implement processor-specific critical sections.
  • To prevent selected interrupts from interfering with an urgent operation.
Interrupt masking should be as short as possible. Long interrupt-disabled sections increase latency and can cause missed deadlines or peripheral data loss.

4. Types of Interrupt Masking

4.1 Global interrupt masking

Global masking prevents acceptance of a defined class or classes of interrupts at the processor level.

On ARM7TDMI-S, the CPSR contains separate mask bits for IRQ and FIQ.

4.2 Selective interrupt masking

Selective masking disables a particular interrupt source or group of sources through the interrupt controller or peripheral configuration.

For example, a program may disable only the UART interrupt while leaving the timer interrupt enabled.

4.3 Priority-based masking

Some processor architectures and interrupt controllers support masking interrupts based on priority thresholds. This allows selected priority levels to remain serviceable while others are blocked.

Priority-threshold masking is architecture-specific. ARM7TDMI-S does not provide the Cortex-M BASEPRI register or its masking model.

6. ARM7 CPSR Interrupt Mask Bits

The ARM7TDMI-S Current Program Status Register (CPSR) contains two important interrupt mask bits.

BitNameMeaning
IIRQ mask bitWhen set to 1, IRQ exceptions are masked.
FFIQ mask bitWhen set to 1, FIQ exceptions are masked.

When a mask bit is cleared, the corresponding exception class is permitted to be accepted, subject to other processor and interrupt-controller conditions.

Illustrative state table

I bitF bitIRQFIQ
00UnmaskedUnmasked
10MaskedUnmasked
01UnmaskedMasked
11MaskedMasked
These bits control processor exception acceptance. They do not replace peripheral interrupt enables or VIC source configuration.

7. Interrupt Masking During Exception Entry

ARM7 automatically changes processor mode and interrupt mask state during exception entry.

ExceptionEntry ModeMask Behavior
IRQIRQ modeIRQ mask bit is set.
FIQFIQ modeFIQ and IRQ mask bits are set.
SWISupervisor modeIRQ mask bit is set.

This behavior helps prevent immediate re-entry of the same exception class during handler entry.

A handler that wants nested interrupts must deliberately manage the processor's interrupt mask state and preserve the required context.

Clearing an interrupt mask inside an exception handler without a correct context-saving and nesting design can cause corrupted return state, unexpected re-entry, or stack problems.

8. Interrupt Nesting and Masking Relationship

Interrupt nesting is possible only when the relevant interrupt requests are eligible for acceptance.

Consider the following example:

StepEventMasking State
1UART IRQ accepted.IRQ masked on exception entry.
2UART handler saves required context.IRQ remains masked.
3Handler deliberately permits selected nesting.IRQ mask is adjusted according to design.
4Eligible higher-priority event becomes pending.Processor can accept it if all conditions permit.
5Nested handler executes.Its own exception-entry rules apply.
6Nested handler returns.Previous handler state is restored.

In a processor without programmable priority thresholds, the handler may need to use source-level masking or other software techniques to control which requests can nest.

9. Critical Sections

A critical section is a portion of code that must execute without conflicting concurrent access to shared resources.

In some embedded systems, a short critical section is protected by masking interrupts.

Example

Disable_Interrupts();

shared_counter++;

Enable_Interrupts();

The purpose is to prevent an interrupt from observing or modifying shared state during the update.

This simple example is not safe as a general-purpose implementation if interrupts were already disabled before entering the critical section. Unconditionally enabling interrupts afterward could incorrectly change the previous state.

10. Preserving the Previous Interrupt State

A safer critical-section design saves the previous interrupt state and restores it after the protected operation.

Conceptual pseudocode

previous_state = Save_Interrupt_State();

Disable_Required_Interrupts();

Update_Shared_Data();

Restore_Interrupt_State(previous_state);

This approach avoids unintentionally enabling interrupts that were already disabled by an outer critical section.

It also supports nested critical-section designs when implemented correctly for the processor architecture.

The actual implementation must use appropriate atomic operations or processor instructions. The pseudocode above is not a drop-in ARM7 or FreeRTOS implementation.

11. Selective Masking Using the LPC2129 VIC

The LPC2129 Vectored Interrupt Controller provides registers for enabling and disabling individual interrupt sources.

RegisterFunction
VICIntEnableEnables selected interrupt sources.
VICIntEnClrDisables selected interrupt sources.
VICIntSelectSelects IRQ or FIQ routing for interrupt sources.
VICIRQStatusReports enabled pending IRQ sources.
VICFIQStatusReports enabled pending FIQ sources.

Conceptual example

#include <LPC21xx.h>

#define TIMER0_INTERRUPT (1U << 4)

// Disable Timer 0 interrupt source
VICIntEnClr = TIMER0_INTERRUPT;

// Enable Timer 0 interrupt source
VICIntEnable = TIMER0_INTERRUPT;

The example illustrates source-level VIC control. The correct interrupt-source bit must be verified against the LPC2129 documentation and the actual project configuration.

Disabling a VIC source is not the same as disabling the timer peripheral itself. The peripheral may continue running and may retain a pending interrupt condition.

12. Interrupt Masking vs Peripheral Interrupt Disable

OperationEffect
Processor IRQ maskingPrevents the processor from accepting IRQ exceptions.
VIC source disablePrevents a selected source from being presented as an enabled interrupt through the VIC.
Peripheral interrupt disablePrevents a peripheral event from generating its configured interrupt request.
Clear peripheral status flagAcknowledges or removes the stored event condition when supported by the peripheral.

These operations are different and should not be treated as interchangeable.

13. Problems Caused by Excessive Interrupt Masking

  • Increased interrupt latency.
  • Missed deadlines in time-critical applications.
  • UART receive-buffer overrun.
  • Lost external events if the source does not retain pending requests.
  • Delayed timer service.
  • Increased task response time.
  • Reduced system responsiveness.

For example, if a UART receives data while its interrupt is masked, the hardware receive buffer may fill. Additional incoming data can be lost if software does not service the peripheral before the buffer capacity is exceeded.

14. Interrupt Masking in RTOS

An RTOS may use short critical sections to protect kernel data structures and shared state.

Typical mechanisms include:

  • Interrupt disable and restore operations.
  • Architecture-specific critical-section macros.
  • Scheduler suspension.
  • Mutexes for task-level shared resources.
  • Atomic operations for suitable data types and processor support.
MechanismTypical Purpose
Interrupt maskingPrevent selected interrupt handlers from executing during a short critical operation.
MutexProtect a shared resource between tasks.
Scheduler suspensionTemporarily prevent task switching while interrupts may remain enabled.
Atomic operationPerform a supported indivisible data operation.
Scheduler suspension is not equivalent to disabling interrupts. An ISR can still execute during scheduler suspension unless the processor interrupt state is separately changed.

15. FreeRTOS Critical Sections

FreeRTOS provides critical-section mechanisms such as:

taskENTER_CRITICAL();

/* Short protected operation */

taskEXIT_CRITICAL();

The exact behavior depends on the selected FreeRTOS port. Some ports use interrupt masking, while others use architecture-specific mechanisms.

For ISR context, certain ports provide separate ISR critical-section macros. These must be used only according to the relevant port documentation.

Do not assume that FreeRTOS critical sections always disable every interrupt. Some ports protect only a defined interrupt-priority range. Never apply Cortex-M BASEPRI assumptions to ARM7TDMI-S.

16. Worked Numerical Problem 1 – Masking Delay

An IRQ request occurs at 100 µs. IRQ masking is removed at 112 µs. Exception entry and vector dispatch take another 3 µs.

Solution

Masking Delay = 112 − 100 = 12 µs
Interrupt Latency = 12 + 3 = 15 µs

Answer: Interrupt latency is 15 µs under the stated assumptions.

17. Worked Numerical Problem 2 – Selective Interrupt Masking

A controller has three interrupt sources. The UART source is disabled at the VIC, while the timer and ADC sources remain enabled.

InterruptVIC Source StateExpected Behavior
UARTDisabledNot presented as an enabled VIC interrupt source.
TimerEnabledCan be presented for IRQ/FIQ handling according to routing and processor masks.
ADCEnabledCan be presented for IRQ/FIQ handling according to routing and processor masks.

Answer: Disabling the UART source does not automatically disable timer or ADC interrupts. Their operation depends on their own peripheral, VIC, and processor configurations.

18. Worked Numerical Problem 3 – Critical Section Duration

A critical section begins at 20 µs and ends at 28 µs. A maskable interrupt request occurs at 23 µs. After interrupts are restored, the processor requires 2 µs to enter the ISR.

Solution

Masking Delay = 28 − 23 = 5 µs
Interrupt Latency = 5 + 2 = 7 µs

Answer: Interrupt latency is 7 µs.

19. Practical Activity – Study Masking Behavior

Use Keil uVision and an LPC2129 register-level project to study interrupt configuration.

Suggested procedure

  1. Open an LPC2129 project configured for a timer interrupt.
  2. Inspect the timer interrupt-enable and status registers.
  3. Inspect the VIC interrupt-enable and selection registers.
  4. Examine the CPSR I and F mask bits in the debugger.
  5. Study the effect of setting or clearing interrupt masks in a controlled test project.
  6. Inspect pending interrupt status where the simulator supports it.
  7. Verify that the handler acknowledges the peripheral event correctly.
  8. Restore the original interrupt state after the protected operation.
Do not modify CPSR interrupt bits casually in a running application. Incorrect masking or exception-return behavior can make the processor unresponsive to interrupts.

21. Lesson Summary

  • Interrupt masking controls acceptance of selected interrupt requests.
  • Global masking affects a processor-defined interrupt class.
  • Selective masking controls individual interrupt sources.
  • ARM7 CPSR contains separate IRQ and FIQ mask bits.
  • Interrupt masking influences interrupt nesting and latency.
  • Critical sections protect sensitive operations.
  • Preserving and restoring the previous interrupt state avoids unintended changes.
  • LPC2129 VIC source control is different from processor-level interrupt masking.
  • RTOS critical sections must be short and port-specific.
  • Scheduler suspension does not necessarily disable interrupts.
