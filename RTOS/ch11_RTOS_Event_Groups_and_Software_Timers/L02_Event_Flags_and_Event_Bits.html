Event Flags and Event Bits

1. Learning Objectives

Event flags and event bits allow an RTOS application to represent the status or occurrence of multiple events using individual bits in an event group. Understanding bitwise operations is essential for designing reliable event-based synchronization.

  • Understand event flags and event-bit representation.
  • Learn how bit positions and masks are defined.
  • Perform set, clear, test and toggle operations.
  • Understand how multiple event bits are combined.
  • Distinguish event state from event occurrence counting.
  • Apply event-bit operations in embedded applications.

2. What Are Event Flags?

An event flag is a logical indicator used to represent whether a particular event or condition has occurred.

In an event group, multiple event flags are stored as individual bits in a bit field. A set bit represents an active or reported event, while a cleared bit represents an inactive or unreported event.

Example

Consider an embedded controller with these conditions:

  • Sensor initialized.
  • UART initialized.
  • Configuration loaded.
  • System ready.
Bit 3    Bit 2       Bit 1       Bit 0
+--------+-----------+-----------+-----------+
| System | Config    | UART      | Sensor    |
| Ready  | Ready     | Ready     | Ready     |
+--------+-----------+-----------+-----------+
An event bit records a condition, not necessarily the number of times an event occurred. If the same bit is set repeatedly while already set, those repeated occurrences are not counted.

3. Binary Representation of Event Bits

Each bit in a binary value can independently represent one event condition.

Bit Position Binary Mask Decimal Value Event
Bit 0 0001 1 Sensor ready
Bit 1 0010 2 UART ready
Bit 2 0100 4 Configuration ready
Bit 3 1000 8 System ready

Defining Event Masks in C

#define EVENT_SENSOR_READY    (1U << 0)
#define EVENT_UART_READY      (1U << 1)
#define EVENT_CONFIG_READY    (1U << 2)
#define EVENT_SYSTEM_READY    (1U << 3)

The left-shift operator moves the binary value 1 to the required bit position.

For example:

1U << 0  = 0001
1U << 1  = 0010
1U << 2  = 0100
1U << 3  = 1000

4. Bitwise OR – Setting Multiple Event Flags

The bitwise OR operator combines event masks. A bit becomes 1 if at least one corresponding operand bit is 1.

Truth Table

A B A | B
000
011
101
111

Example

unsigned int events = 0;

events |= EVENT_SENSOR_READY;
events |= EVENT_UART_READY;

Result:

Initial value:       0000
Sensor event set:    0001
UART event set:      0011

The OR operation preserves the other bits while setting the selected event bit.

5. Bitwise AND – Checking Event Flags

The bitwise AND operator is used to test whether a particular event bit is set.

Truth Table

A B A & B
000
010
100
111

Example

if ((events & EVENT_SENSOR_READY) != 0U)
{
    /* Sensor-ready event is set. */
}

If the selected bit is 1, the AND operation produces a non-zero result. Otherwise, it produces zero.

Checking Multiple Events

#define REQUIRED_EVENTS \
    (EVENT_SENSOR_READY | EVENT_UART_READY)

if ((events & REQUIRED_EVENTS) == REQUIRED_EVENTS)
{
    /* Both required events are set. */
}
This expression checks whether all selected bits are set. To check whether at least one selected bit is set, use: (events & REQUIRED_EVENTS) != 0U.

6. Bitwise NOT and AND – Clearing Event Flags

The bitwise NOT operator complements every bit. Combining NOT with AND clears selected bits while preserving the others.

Syntax

events &= ~EVENT_SENSOR_READY;

Example

Initial event state:  0011
Clear sensor bit:     0010
Final event state:    0010

The sensor-ready bit becomes zero, while the UART-ready bit remains set.

The NOT operator complements the width of the integer type, not only the visible event bits. Use appropriately typed masks and keep operations within the defined event-bit range.

7. Bitwise XOR – Toggling Event Flags

XOR toggles a selected bit: 0 becomes 1 and 1 becomes 0.

Truth Table

A B A ^ B
000
011
101
110

Example

events ^= EVENT_UART_READY;

If the UART-ready bit was zero, it becomes one. If it was one, it becomes zero.

XOR is useful for bit manipulation, but it is generally not the preferred way to report an event. An event producer normally wants to set a condition, not toggle it unpredictably.

8. Complete C Program – Event Flag Manipulation

This standalone C program demonstrates event-bit definitions, setting, checking, clearing and combining flags. 

#include <stdio.h>

#define EVENT_SENSOR_READY    (1U << 0)
#define EVENT_UART_READY      (1U << 1)
#define EVENT_CONFIG_READY    (1U << 2)

#define ALL_REQUIRED_EVENTS \
    (EVENT_SENSOR_READY | EVENT_UART_READY | EVENT_CONFIG_READY)

int main(void)
{
    unsigned int events = 0U;

    printf("Initial Events: %u\n", events);

    /* Set sensor event */
    events |= EVENT_SENSOR_READY;

    /* Set UART event */
    events |= EVENT_UART_READY;

    printf("After setting sensor and UART: %u\n", events);

    /* Check sensor event */
    if ((events & EVENT_SENSOR_READY) != 0U)
    {
        printf("Sensor is ready.\n");
    }

    /* Check all required events */
    if ((events & ALL_REQUIRED_EVENTS) == ALL_REQUIRED_EVENTS)
    {
        printf("All required events are ready.\n");
    }
    else
    {
        printf("Some required events are missing.\n");
    }

    /* Set configuration event */
    events |= EVENT_CONFIG_READY;

    if ((events & ALL_REQUIRED_EVENTS) == ALL_REQUIRED_EVENTS)
    {
        printf("All required events are ready now.\n");
    }

    /* Clear UART event */
    events &= ~EVENT_UART_READY;

    printf("After clearing UART event: %u\n", events);

    return 0;
}

Expected Output

Initial Events: 0
After setting sensor and UART: 3
Sensor is ready.
Some required events are missing.
All required events are ready now.
After clearing UART event: 5

Explanation

  • Initially, all event bits are cleared.
  • Setting sensor and UART bits produces binary 0011, decimal 3.
  • The configuration bit is initially missing.
  • After setting configuration, the event state becomes binary 0111, decimal 7.
  • Clearing UART leaves binary 0101, decimal 5.

9. Event Flags in FreeRTOS

FreeRTOS event groups provide kernel-managed event bits. Instead of modifying a shared integer directly, application tasks use event-group APIs.

Important Data Types

Type Description
EventGroupHandle_t Handle used to refer to an event-group object.
EventBits_t Type used to represent the event-bit value.

Event-Bit Definitions

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

#define SENSOR_READY_BIT    (1U << 0)
#define UART_READY_BIT      (1U << 1)
#define CONFIG_READY_BIT    (1U << 2)

#define ALL_READY_BITS \
    (SENSOR_READY_BIT | UART_READY_BIT | CONFIG_READY_BIT)

EventGroupHandle_t xSystemEvents;

These definitions create application-level masks. The actual event group must be created before tasks use it.

FreeRTOS event-group APIs provide the synchronization behavior needed for concurrent tasks. Do not replace them with unsynchronized read-modify-write operations on a shared global variable.

10. Event Flags vs Event Counters

An event flag indicates whether a condition is active. An event counter records how many occurrences have been reported, subject to its maximum count.

Feature Event Flag Counting Semaphore
Represents Set or cleared condition Number of available tokens or pending signals
Repeated events Coalesce when the bit is already set Can accumulate tokens up to the configured maximum
Typical use System-ready status Counting interrupt notifications or available resources
Example:
  • Use an event bit to indicate that a sensor is initialized.
  • Use a counting semaphore if each received hardware event must be counted.
  • Use a queue if each event also carries a data value.

11. Practical Applications

A. System Initialization

Set separate bits when clock, communication and sensor initialization are complete.

B. Sensor Monitoring

Use event bits to represent the readiness or availability of different sensor subsystems.

C. Communication Status

Maintain separate event flags for UART, SPI and I2C initialization or operating status.

D. Fault Status

Event bits can represent active fault conditions, such as overtemperature, communication failure or low-voltage detection. Define clear and recovery rules carefully.

14. Lesson Summary

  • Event flags represent individual event conditions.
  • Event bits are represented using binary bit positions.
  • Bit masks identify specific event bits.
  • OR sets bits, AND tests bits, NOT complements bits, and XOR toggles bits.
  • Multiple event flags can be combined into one mask.
  • Event bits represent state and do not count repeated occurrences.
  • FreeRTOS event-group APIs provide synchronization for concurrent tasks.
  • Queues and counting semaphores are alternatives when event counting or data transfer is required.
