Task Synchronization Using Event Groups

RTOS & FreeRTOS – Chapter 11: Event Groups and Software Timers

1. Learning Objectives

In a multitasking embedded system, multiple tasks may need to coordinate their execution based on the completion of different operations. FreeRTOS event groups provide a mechanism for synchronizing tasks through shared event bits.

  • Understand task synchronization using event groups.
  • Learn how one task sets an event bit for another task.
  • Understand waiting for one or multiple event conditions.
  • Learn event-bit clearing behavior.
  • Implement task synchronization using FreeRTOS APIs.
  • Handle timeouts and synchronization failures.

2. What Is Task Synchronization?

Task synchronization is the coordination of multiple tasks so that they perform operations in the required order or proceed only when specified conditions are satisfied.

Example

Consider an embedded monitoring system containing three tasks:

  • SensorTask reads sensor data.
  • UARTTask initializes serial communication.
  • ConfigTask loads application configuration.

MainTask should begin normal operation only after all three initialization operations have completed. 

SensorTask ---------> SENSOR_READY
                           |
UARTTask ----------> UART_READY
                           |
ConfigTask --------> CONFIG_READY
                           |
                           v
                     EVENT GROUP
                           |
                           v
                       MainTask
                           |
                           v
                  Start Normal Operation

3. Event Bits Used for Synchronization

Each task reports completion by setting its assigned event bit. A waiting task checks whether the required combination of bits has been set.

Event-Bit Definitions

#define SENSOR_READY_BIT    (1U << 0)
#define UART_READY_BIT      (1U << 1)
#define CONFIG_READY_BIT    (1U << 2)

#define ALL_READY_BITS \
    (SENSOR_READY_BIT | UART_READY_BIT | CONFIG_READY_BIT)
Bit Task Meaning
Bit 0 SensorTask Sensor initialization completed
Bit 1 UARTTask UART initialization completed
Bit 2 ConfigTask Configuration loading completed

4. FreeRTOS APIs for Task Synchronization

API Purpose
xEventGroupCreate() Creates an event group.
xEventGroupSetBits() Sets one or more event bits.
xEventGroupClearBits() Clears selected event bits.
xEventGroupWaitBits() Blocks a task until specified event conditions are met or a timeout occurs.
xEventGroupGetBits() Reads the current event-bit state.
xEventGroupGetBitsFromISR() Reads event bits from ISR context where supported.
xEventGroupSetBits() and xEventGroupClearBits() are task-context APIs. ISR code uses the appropriate FromISR API where available.

5. Waiting for Event Bits

The xEventGroupWaitBits() API allows a task to wait for one or more event conditions.

Function Syntax

EventBits_t xEventGroupWaitBits(
    EventGroupHandle_t xEventGroup,
    const EventBits_t uxBitsToWaitFor,
    const BaseType_t xClearOnExit,
    const BaseType_t xWaitForAllBits,
    TickType_t xTicksToWait
);

Parameters

Parameter Description
xEventGroup Handle of the event group.
uxBitsToWaitFor Event-bit mask specifying the required conditions.
xClearOnExit Specifies whether the requested bits are cleared when the wait condition is satisfied.
xWaitForAllBits pdTRUE waits for all requested bits; pdFALSE waits for any requested bit.
xTicksToWait Maximum wait time in RTOS ticks.

Wait for All Events

EventBits_t result;

result = xEventGroupWaitBits(
    xSystemEvents,
    ALL_READY_BITS,
    pdTRUE,
    pdTRUE,
    portMAX_DELAY
);

The task waits until all selected event bits are set. With pdTRUE for the clear-on-exit argument, the requested bits are cleared when the all-bits condition is satisfied.

Wait for Any Event

EventBits_t result;

result = xEventGroupWaitBits(
    xSystemEvents,
    ALL_READY_BITS,
    pdFALSE,
    pdFALSE,
    portMAX_DELAY
);

The task proceeds when at least one selected event bit is set. The requested bits are not automatically cleared.

6. Example 1 – Two Tasks Synchronizing Through One Event Bit

Objective: Make one task wait until another task reports completion.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

#define DATA_READY_BIT (1U << 0)

EventGroupHandle_t xEventGroup;

void ProducerTask(void *pvParameters)
{
    for (;;)
    {
        /* Perform data acquisition. */

        xEventGroupSetBits(xEventGroup, DATA_READY_BIT);

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void ConsumerTask(void *pvParameters)
{
    EventBits_t result;

    for (;;)
    {
        result = xEventGroupWaitBits(
            xEventGroup,
            DATA_READY_BIT,
            pdTRUE,
            pdTRUE,
            portMAX_DELAY
        );

        if ((result & DATA_READY_BIT) != 0U)
        {
            /* Process the data-ready condition. */
        }
    }
}

int main(void)
{
    xEventGroup = xEventGroupCreate();

    if (xEventGroup != NULL)
    {
        xTaskCreate(
            ProducerTask,
            "Producer",
            256,
            NULL,
            2,
            NULL
        );

        xTaskCreate(
            ConsumerTask,
            "Consumer",
            256,
            NULL,
            2,
            NULL
        );

        vTaskStartScheduler();
    }

    for (;;);
}

Working

  1. ProducerTask performs its acquisition operation.
  2. It sets DATA_READY_BIT.
  3. ConsumerTask becomes eligible to continue.
  4. ConsumerTask checks the returned event-bit value.
  5. The requested bit is cleared on successful exit from the wait.
  6. The consumer waits again for the next report.
Event bits coalesce repeated occurrences. If the producer sets DATA_READY_BIT several times before the consumer clears it, the consumer may observe only one pending indication. Use a queue or counting semaphore when every produced item or occurrence must be preserved.

7. Example 2 – Synchronizing Three Initialization Tasks

This example demonstrates how a main task waits for sensor, UART and configuration initialization to complete.

Program

#include "FreeRTOS.h"
#include "task.h"
#include "event_groups.h"

#define SENSOR_READY_BIT    (1U << 0)
#define UART_READY_BIT      (1U << 1)
#define CONFIG_READY_BIT    (1U << 2)

#define ALL_READY_BITS \
    (SENSOR_READY_BIT | UART_READY_BIT | CONFIG_READY_BIT)

EventGroupHandle_t xSystemEvents;

void SensorTask(void *pvParameters)
{
    /* Initialize sensor hardware here. */

    xEventGroupSetBits(
        xSystemEvents,
        SENSOR_READY_BIT
    );

    vTaskDelete(NULL);
}

void UARTTask(void *pvParameters)
{
    /* Initialize UART hardware here. */

    xEventGroupSetBits(
        xSystemEvents,
        UART_READY_BIT
    );

    vTaskDelete(NULL);
}

void ConfigTask(void *pvParameters)
{
    /* Load application configuration here. */

    xEventGroupSetBits(
        xSystemEvents,
        CONFIG_READY_BIT
    );

    vTaskDelete(NULL);
}

void MainTask(void *pvParameters)
{
    EventBits_t result;

    result = xEventGroupWaitBits(
        xSystemEvents,
        ALL_READY_BITS,
        pdTRUE,
        pdTRUE,
        pdMS_TO_TICKS(5000)
    );

    if ((result & ALL_READY_BITS) == ALL_READY_BITS)
    {
        /* All initialization conditions are satisfied. */

        for (;;)
        {
            /* Execute normal application operations. */

            vTaskDelay(pdMS_TO_TICKS(1000));
        }
    }
    else
    {
        /* Initialization timeout or incomplete readiness. */

        for (;;)
        {
            /* Enter defined fault-handling behavior. */

            vTaskDelay(pdMS_TO_TICKS(1000));
        }
    }
}

int main(void)
{
    xSystemEvents = xEventGroupCreate();

    if (xSystemEvents != NULL)
    {
        xTaskCreate(SensorTask, "Sensor", 256, NULL, 2, NULL);
        xTaskCreate(UARTTask, "UART", 256, NULL, 2, NULL);
        xTaskCreate(ConfigTask, "Config", 256, NULL, 2, NULL);
        xTaskCreate(MainTask, "Main", 256, NULL, 3, NULL);

        vTaskStartScheduler();
    }

    for (;;);
}

Expected Behavior

  • Each initialization task completes its operation.
  • Each task sets its own event bit.
  • MainTask waits for all three conditions.
  • If all bits are set within the timeout, normal operation begins.
  • If the wait expires before all bits are set, fault handling executes.
xEventGroupWaitBits() returns the event-bit value observed when the task leaves the wait. The condition check determines whether all requested bits were present. This example assumes each initialization task sets its bit only after successful initialization.

8. Example 3 – Waiting for Any One of Multiple Events

Sometimes a task needs to react when any one of several events occurs, rather than waiting for all of them.

Example Scenario

  • UART data received.
  • Sensor threshold exceeded.
  • Communication fault detected.

Program Fragment

#define UART_EVENT_BIT    (1U << 0)
#define SENSOR_EVENT_BIT  (1U << 1)
#define FAULT_EVENT_BIT   (1U << 2)

#define ANY_EVENT_BITS \
    (UART_EVENT_BIT | SENSOR_EVENT_BIT | FAULT_EVENT_BIT)

EventBits_t events;

events = xEventGroupWaitBits(
    xSystemEvents,
    ANY_EVENT_BITS,
    pdFALSE,
    pdFALSE,
    portMAX_DELAY
);

if ((events & UART_EVENT_BIT) != 0U)
{
    /* Handle UART event. */
}

if ((events & SENSOR_EVENT_BIT) != 0U)
{
    /* Handle sensor event. */
}

if ((events & FAULT_EVENT_BIT) != 0U)
{
    /* Handle fault event. */
}

Because clear-on-exit is pdFALSE, the event bits remain set after the wait. The application must define when and how they are cleared.

If several bits are set at the same time, the returned value may contain several of them. Check each relevant bit rather than assuming only one event occurred.

9. Clear-on-Exit Behavior

The clear-on-exit parameter controls whether the requested event bits are automatically cleared when the wait condition is satisfied.

Parameter Behavior
pdTRUE Clear the requested bits when the wait condition is satisfied.
pdFALSE Leave the event bits unchanged after the wait.

Important Detail

When waiting for all requested bits, successful completion clears the requested bits if clear-on-exit is enabled. When waiting for any requested bit, the matching requested bits are cleared on successful completion. A timeout does not cause the requested bits to be automatically cleared by this parameter.

10. Event Groups and Multiple Waiting Tasks

Multiple tasks can wait on the same event group. Each task can wait for a different bit or combination of bits.

Example

Task A waits for SENSOR_READY_BIT.

Task B waits for UART_READY_BIT.

Task C waits for:

    SENSOR_READY_BIT | UART_READY_BIT

When the corresponding bits are set, eligible waiting tasks are unblocked according to their wait conditions and the scheduler's priority rules.

Event groups are shared state. If one waiting task clears a bit on exit, another waiting task may no longer see that bit set. Design clear-on-exit behavior carefully when multiple tasks observe the same events.

11. Event Groups vs Direct Task Notifications

Feature Event Groups Task Notifications
Multiple event conditions Yes, using event bits Can use notification value bits in suitable notification modes
Multiple waiting tasks Multiple tasks can wait on one event group Each notification is directed to a specific task
Resource overhead Separate event-group object Notification state is part of each task
Typical use Shared multi-condition synchronization Efficient task-directed signaling

12. Best Practices

  • Assign a unique bit to each independent event condition.
  • Use named bit-mask macros instead of unexplained numeric values.
  • Choose wait-for-any or wait-for-all behavior deliberately.
  • Define whether bits should be cleared automatically.
  • Handle timeouts explicitly.
  • Do not use event bits to count repeated events.
  • Use queues when event payloads must be transferred.
  • Consider interactions when several tasks wait on the same event group.
  • Use the correct ISR-specific APIs for interrupt context.

Activity – Three-Subsystem Startup Synchronization

Objective: Synchronize sensor, communication and configuration tasks.

  1. Create an event group.
  2. Define SENSOR_READY_BIT, UART_READY_BIT and CONFIG_READY_BIT.
  3. Create three initialization tasks.
  4. Set the appropriate event bit after each successful initialization.
  5. Create a main task that waits for all three bits.
  6. Configure a finite timeout.
  7. Inspect the returned event bits and implement success or failure handling.

Expected Result: MainTask proceeds only when all required initialization events have been reported. If the timeout expires first, the application enters its defined fault-handling path.

15. Lesson Summary

  • Event groups coordinate tasks through shared event bits.
  • Tasks set bits to report that conditions have occurred.
  • xEventGroupWaitBits() supports wait-for-any and wait-for-all behavior.
  • The clear-on-exit parameter controls automatic clearing after a successful wait.
  • Multiple tasks can wait on the same event group.
  • Clearing shared bits requires careful design.
  • Timeout handling is important for reliable synchronization.
  • Queues are preferable when every event or its associated data must be preserved.
