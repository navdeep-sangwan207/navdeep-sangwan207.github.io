One-Shot and Auto-Reload Timers

1. Learning Objectives

FreeRTOS software timers can operate in one-shot or auto-reload mode. Understanding these modes helps developers implement communication timeouts, periodic monitoring and delayed application actions.

  • Understand one-shot timer operation.
  • Understand auto-reload timer operation.
  • Configure timer modes using xTimerCreate().
  • Analyze timer expiration timelines.
  • Understand timer restart and reset behavior.
  • Implement one-shot and auto-reload timer programs.
  • Choose the appropriate timer mode for an application.

2. Timer Operating Modes

A FreeRTOS software timer has an operating mode selected during creation. The mode is controlled by the xAutoReload parameter of xTimerCreate().

Parameter Timer Mode Behavior
pdFALSE One-shot Timer expires once and then becomes inactive.
pdTRUE Auto-reload Timer automatically schedules subsequent expirations. 
TimerHandle_t xTimer;

xTimer = xTimerCreate(
    "ExampleTimer",
    pdMS_TO_TICKS(1000),
    pdFALSE,       /* One-shot mode */
    NULL,
    TimerCallback
);

3. One-Shot Timer

A one-shot timer expires once after its configured period. When the timer expires, its callback is processed and the timer becomes inactive.

Working Sequence

  1. Create a timer in one-shot mode.
  2. Start the timer.
  3. The timer counts down using the RTOS tick time base.
  4. When the timer expires, the callback is executed.
  5. The timer becomes inactive.
  6. The application can start or reset it again when required.

Example Timeline – 3-Second One-Shot Timer

Time:       0s        1s        2s        3s        4s
            |---------|---------|---------|---------|

Timer:      START ---------------------- EXPIRE
Callback:                                   EXECUTE

After 3s:   Timer becomes inactive.

Applications

  • Communication response timeout.
  • Delayed shutdown operation.
  • Temporary warning indication.
  • Waiting for a device initialization response.
  • Application-level inactivity timeout.

4. Auto-Reload Timer

An auto-reload timer automatically repeats its timing cycle after each expiration. Its callback is executed whenever the timer expires.

Working Sequence

  1. Create the timer in auto-reload mode.
  2. Start the timer.
  3. Wait for the configured timer period.
  4. Execute the timer callback.
  5. Automatically schedule the next expiration.
  6. Continue until the timer is stopped or deleted.

Example Timeline – 2-Second Auto-Reload Timer

Time:       0s        2s        4s        6s        8s
            |---------|---------|---------|---------|

Timer:      START     EXPIRE    EXPIRE    EXPIRE    EXPIRE
Callback:             CALL      CALL      CALL      CALL

Operation:  Repeats automatically until stopped.

Applications

  • Periodic system health monitoring.
  • Periodic status reporting.
  • Regular communication checks.
  • Application heartbeat generation.
  • Periodic scheduling of non-critical maintenance work.

5. One-Shot vs Auto-Reload Timer

Feature One-Shot Auto-Reload
Configuration pdFALSE pdTRUE
Expiration count Once per start Repeatedly
Automatic repetition No Yes
After expiration Inactive Next expiration is scheduled
Restart required Yes, for another cycle No, unless stopped or reset
Typical use Timeout or delayed action Periodic operation

6. Creating a One-Shot Timer

The third parameter of xTimerCreate() is pdFALSE for a one-shot timer. 

#include "FreeRTOS.h"
#include "task.h"
#include "timers.h"

TimerHandle_t xOneShotTimer;

void OneShotCallback(TimerHandle_t xTimer)
{
    /* Execute the timeout action. */
}

int main(void)
{
    xOneShotTimer = xTimerCreate(
        "OneShot",
        pdMS_TO_TICKS(3000),
        pdFALSE,
        NULL,
        OneShotCallback
    );

    if (xOneShotTimer != NULL)
    {
        if (xTimerStart(xOneShotTimer, 0) != pdPASS)
        {
            /* Handle command queue failure. */
        }

        vTaskStartScheduler();
    }

    for (;;);
}

Program Explanation

  • The timer period is 3000 milliseconds.
  • pdFALSE selects one-shot operation.
  • The timer starts when the start command is processed.
  • After expiration, the callback executes once.
  • The timer becomes inactive until it is started again.

7. Creating an Auto-Reload Timer

The third parameter of xTimerCreate() is pdTRUE for an auto-reload timer. 

#include "FreeRTOS.h"
#include "task.h"
#include "timers.h"

TimerHandle_t xPeriodicTimer;

void PeriodicCallback(TimerHandle_t xTimer)
{
    /* Perform a short periodic action. */
}

int main(void)
{
    xPeriodicTimer = xTimerCreate(
        "Periodic",
        pdMS_TO_TICKS(2000),
        pdTRUE,
        NULL,
        PeriodicCallback
    );

    if (xPeriodicTimer != NULL)
    {
        if (xTimerStart(xPeriodicTimer, 0) != pdPASS)
        {
            /* Handle command queue failure. */
        }

        vTaskStartScheduler();
    }

    for (;;);
}

Program Explanation

  • The timer period is 2000 milliseconds.
  • pdTRUE selects auto-reload operation.
  • The callback is processed at each timer expiration.
  • The timer automatically schedules subsequent expirations.
  • The timer continues until it is stopped or deleted.

8. Restarting a One-Shot Timer

A one-shot timer can be started again after it expires. The xTimerStart() API sends a start command to the timer service task. 

if (xTimerStart(xOneShotTimer, pdMS_TO_TICKS(100)) != pdPASS)
{
    /* Handle timer command failure. */
}

If the one-shot timer is already active, a start command restarts its timing from the time the command is processed by the timer service task.

Timer API calls are command requests. Their effect occurs when the timer service task processes the command, not necessarily at the exact instant the calling task invokes the API.

9. Resetting a Software Timer

The xTimerReset() API resets a timer so that its next expiration is scheduled relative to the time the reset command is processed.

Function Prototype

BaseType_t xTimerReset(
    TimerHandle_t xTimer,
    TickType_t xTicksToWait
);

Example

if (xTimerReset(xOneShotTimer, pdMS_TO_TICKS(100)) != pdPASS)
{
    /* Handle reset command failure. */
}

Practical Application – Communication Timeout

Consider a communication device that must receive a response within five seconds. Each valid response resets the timeout timer. If no response arrives before expiration, the callback reports a timeout event. 

/* Called after receiving a valid response. */

void CommunicationResponseReceived(void)
{
    xTimerReset(
        xCommunicationTimeout,
        pdMS_TO_TICKS(100)
    );
}

10. Stopping a Software Timer

The xTimerStop() API requests the timer service task to stop an active timer.

Function Prototype

BaseType_t xTimerStop(
    TimerHandle_t xTimer,
    TickType_t xTicksToWait
);

Example

if (xTimerStop(xPeriodicTimer, pdMS_TO_TICKS(100)) != pdPASS)
{
    /* Handle stop command failure. */
}

Once the stop command is processed, the timer becomes inactive and no further expirations occur until it is started again.

11. Changing the Timer Period

FreeRTOS provides xTimerChangePeriod() to change a timer's period.

Function Prototype

BaseType_t xTimerChangePeriod(
    TimerHandle_t xTimer,
    TickType_t xNewPeriod,
    TickType_t xTicksToWait
);

Example

if (xTimerChangePeriod(
        xPeriodicTimer,
        pdMS_TO_TICKS(5000),
        pdMS_TO_TICKS(100)
    ) != pdPASS)
{
    /* Handle command failure. */
}

When processed, the command changes the timer period and starts the timer using the new period. The new expiration is based on when the timer service task processes the command.

12. Timer API Comparison

API Purpose
xTimerCreate() Create a software timer.
xTimerStart() Start or restart a timer.
xTimerStop() Stop a timer.
xTimerReset() Restart the timer period from the command processing time.
xTimerChangePeriod() Change the timer period and start the timer with the new period.
xTimerDelete() Delete a software timer.
xTimerIsTimerActive() Check whether a timer is active.
pvTimerGetTimerID() Retrieve the timer's application-defined ID.

13. Timer ID and Multiple Timers

The timer ID allows an application to associate a user-defined value or pointer with a timer. This is useful when one callback function is shared by multiple timers. 

#define TIMER_ID_SENSOR  1
#define TIMER_ID_UART    2

void CommonCallback(TimerHandle_t xTimer)
{
    void *id;

    id = pvTimerGetTimerID(xTimer);

    if (id == (void *)TIMER_ID_SENSOR)
    {
        /* Handle sensor timer expiration. */
    }
    else if (id == (void *)TIMER_ID_UART)
    {
        /* Handle UART timer expiration. */
    }
}
Timer IDs are application-defined. In production code, use a deliberate representation such as an enum encoded through an integer-sized pointer or a pointer to a valid application object. Avoid dereferencing an integer used only as an identifier.

14. Design Considerations

  • Choose one-shot timers for single delayed actions and timeout monitoring.
  • Choose auto-reload timers for recurring application events.
  • Keep callback execution short and non-blocking.
  • Check the return value of timer API commands.
  • Ensure the timer command queue is large enough for expected command traffic.
  • Consider timer service task priority and stack requirements.
  • Do not assume callback execution occurs at the exact nominal expiration tick.
  • Use hardware timers for precise peripheral timing requirements.

15. Practical Activity

Activity A – Communication Timeout

  1. Create a five-second one-shot timer.
  2. Start the timer when a communication request is transmitted.
  3. Reset the timer whenever a valid response arrives.
  4. Generate a timeout event when the timer expires.
  5. Send the timeout event to a separate monitoring task.

Activity B – Periodic Monitoring

  1. Create a two-second auto-reload timer.
  2. Implement a short callback that notifies a monitoring task.
  3. Let the monitoring task process the notification.
  4. Stop the timer when monitoring is disabled.
  5. Restart it when monitoring is enabled again.

Expected Result: Activity A produces one timeout event per uninterrupted timeout interval. Activity B generates recurring monitoring events until the timer is stopped.

These are generic FreeRTOS exercises. Actual execution requires a compatible FreeRTOS port and target environment. A working LPC2129 Keil uVision simulator port must not be assumed.

17. Lesson Summary

  • One-shot timers expire once and become inactive.
  • Auto-reload timers automatically repeat their expiration cycle.
  • pdFALSE selects one-shot mode.
  • pdTRUE selects auto-reload mode.
  • xTimerStart() starts or restarts a timer.
  • xTimerReset() resets the timer's expiration interval.
  • xTimerStop() stops a timer.
  • xTimerChangePeriod() changes the period and starts the timer with the new period.
  • Timer commands are processed by the timer service task.
  • Timer callbacks should be short and non-blocking.
