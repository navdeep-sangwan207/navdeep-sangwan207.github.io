2. Project Introduction

Sensor monitoring is a common embedded application. A microcontroller periodically reads sensor information, processes the measurements and reports the results.

This project uses FreeRTOS to separate sensor acquisition from data processing.

Example Application

A temperature-monitoring system periodically reads a temperature sensor, transfers the measurement through a queue and checks whether the temperature exceeds a configured threshold.

ComponentResponsibility
SensorProvides a physical measurement.
ADC driverConverts an analog voltage into a digital value, where required.
Sensor TaskSamples the sensor periodically.
FreeRTOS QueueTransfers measurement data between tasks.
Processing TaskChecks measurements and detects threshold violations.
Output DriverReports status through UART, display or another interface.

3. System Architecture

TEMPERATURE SENSOR | v ADC DRIVER | v SENSOR ACQUISITION TASK | SENSOR DATA | v FREERTOS QUEUE | v DATA PROCESSING TASK | +-------+-------+ | | v v NORMAL RANGE HIGH TEMPERATURE | | v v STATUS LOG WARNING / ALARM

The sensor task is responsible for acquisition. The processing task is responsible for interpreting the measurement. The queue separates these responsibilities.

4. Why Use Multiple Tasks?

A single-loop implementation can perform sensor acquisition, processing and reporting sequentially. However, this can make the application difficult to extend and schedule.

Advantages of Task Separation

  • Sensor sampling has its own execution period.
  • Processing does not need to be embedded inside the acquisition routine.
  • Communication is handled through a defined queue interface.
  • Additional tasks can be added for logging or display updates.
  • Task priorities can be selected according to application requirements.
Multiple tasks improve modularity, but they also introduce scheduling, synchronization, stack and communication requirements. They do not automatically make a system faster or more deterministic.

5. Understanding Sensor Acquisition

A sensor converts a physical quantity into an electrical signal or digital measurement.

Common Sensor Types

SensorMeasured QuantityTypical Interface
LM35TemperatureAnalog voltage
NTC thermistorTemperatureAnalog voltage through a divider
LDRLight intensityAnalog voltage through a divider
Pressure sensorPressureAnalog or digital
Digital temperature sensorTemperatureI2C, SPI or another digital interface

Analog Measurement Flow

  1. The sensor produces an analog voltage.
  2. The ADC samples the input voltage.
  3. The ADC produces a digital count.
  4. The application converts the count into engineering units.
  5. The processing task evaluates the measurement.

6. ADC Conversion Basics

An ideal unipolar N-bit ADC has \(2^N\) quantization codes.

For an ADC with a 10-bit resolution:

  • Number of codes = 1024.
  • Digital output range = 0 to 1023.
  • For a 3.3 V reference, the ideal code width is approximately 3.3/1024 volts.

Approximate ADC Voltage Conversion

Voltage = (ADC_Count * Vref) / 1023.0

Here, 1023 is the maximum code for a 10-bit ADC. The exact voltage interpretation depends on the ADC transfer function, reference voltage, input range and calibration.

Example

Suppose:

  • ADC resolution = 10 bits.
  • Reference voltage = 3.3 V.
  • ADC count = 512.

Approximate input voltage:

Voltage = (512 * 3.3) / 1023
        = 1.6516 V approximately
This is an idealized conversion. Real ADC measurements have quantization error, offset error, gain error, noise and reference-voltage uncertainty.

7. Temperature Conversion Example

For an LM35 sensor, the nominal output scale is 10 mV per degree Celsius.

Temperature_C = Sensor_Voltage / 0.010

For example, if the measured voltage is 0.28 V:

Temperature_C = 0.28 / 0.010
              = 28 C
This conversion assumes an LM35-type sensor and its nominal transfer characteristic. It is not suitable for an NTC thermistor or an arbitrary temperature sensor. Verify the actual sensor datasheet and calibration.

8. FreeRTOS Queue for Sensor Data

A queue allows one task to send measurement data and another task to receive it.

Queue Creation

QueueHandle_t sensorQueue;

sensorQueue = xQueueCreate(
    5,
    sizeof(SensorData_t)
);

The example creates a queue with five measurement slots.

Send Measurement

xQueueSend(
    sensorQueue,
    &sensorData,
    0
);

Receive Measurement

xQueueReceive(
    sensorQueue,
    &receivedData,
    portMAX_DELAY
);

FreeRTOS queues copy fixed-size items into and out of queue storage. This example sends a structure by value through the queue.

9. Sensor Data Structure

A structure can carry a measurement and its associated metadata.

typedef struct
{
    uint16_t adcCount;
    float voltage;
    float temperature;
    uint32_t sampleNumber;
} SensorData_t;
MemberPurpose
adcCountRaw ADC measurement.
voltageConverted sensor voltage.
temperatureCalculated temperature.
sampleNumberMeasurement sequence number.

The queue copies the complete structure. The receiving task gets its own copy of the queued measurement.

10. Complete FreeRTOS Sensor Monitoring Program

Objective: Periodically acquire a simulated temperature measurement, send it through a queue and process the received data.

This example uses a simulated ADC reading so that the RTOS task and queue logic can be studied independently of physical sensor hardware. Replace the simulated function with a target-specific ADC driver for a real project.
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "stdint.h"
#include "stdio.h"

/* Sensor data structure */
typedef struct
{
    uint16_t adcCount;
    float voltage;
    float temperature;
    uint32_t sampleNumber;
} SensorData_t;

/* Queue handle */
static QueueHandle_t sensorQueue = NULL;

/* Sample counter */
static uint32_t sampleCounter = 0;

/* Function declarations */
static void SensorTask(void *pvParameters);
static void ProcessingTask(void *pvParameters);

/* Simulated ADC function */
static uint16_t ADC_ReadTemperature(void)
{
    /*
     * Demonstration value.
     * Replace with actual ADC driver.
     */
    static uint16_t simulatedCount = 434;

    simulatedCount += 2;

    if (simulatedCount > 620)
    {
        simulatedCount = 434;
    }

    return simulatedCount;
}

/* Sensor acquisition task */
static void SensorTask(void *pvParameters)
{
    SensorData_t sensorData;

    TickType_t lastWakeTime = xTaskGetTickCount();

    (void) pvParameters;

    for (;;)
    {
        /* Read ADC */
        sensorData.adcCount = ADC_ReadTemperature();

        /* Convert ADC count into voltage */
        sensorData.voltage =
            ((float)sensorData.adcCount * 3.3f) / 1023.0f;

        /*
         * LM35 nominal scale:
         * 10 mV per degree Celsius.
         */
        sensorData.temperature =
            sensorData.voltage / 0.010f;

        /* Increment sequence number */
        sensorData.sampleNumber = ++sampleCounter;

        /* Send complete structure to queue */
        if (xQueueSend(
                sensorQueue,
                &sensorData,
                0
            ) != pdPASS)
        {
            /* Queue full: record or handle dropped sample */
        }

        /* Periodic sampling interval */
        vTaskDelayUntil(
            &lastWakeTime,
            pdMS_TO_TICKS(1000)
        );
    }
}

/* Data processing task */
static void ProcessingTask(void *pvParameters)
{
    SensorData_t receivedData;

    (void) pvParameters;

    for (;;)
    {
        /* Wait for the next measurement */
        if (xQueueReceive(
                sensorQueue,
                &receivedData,
                portMAX_DELAY
            ) == pdPASS)
        {
            /* Process received measurement */
            if (receivedData.temperature >= 40.0f)
            {
                /*
                 * High-temperature condition.
                 * Replace with application alarm logic.
                 */
                printf(
                    "WARNING: High Temperature = %.2f C\r\n",
                    (double)receivedData.temperature
                );
            }
            else
            {
                printf(
                    "Sample %lu | ADC = %u | Voltage = %.3f V | Temperature = %.2f C\r\n",
                    (unsigned long)receivedData.sampleNumber,
                    (unsigned int)receivedData.adcCount,
                    (double)receivedData.voltage,
                    (double)receivedData.temperature
                );
            }
        }
    }
}

int main(void)
{
    /* Create queue with five measurement slots */
    sensorQueue = xQueueCreate(
        5,
        sizeof(SensorData_t)
    );

    if (sensorQueue == NULL)
    {
        for (;;)
        {
            /* Queue creation failed */
        }
    }

    /* Create sensor acquisition task */
    if (xTaskCreate(
            SensorTask,
            "SensorTask",
            256,
            NULL,
            2,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
            /* Sensor task creation failed */
        }
    }

    /* Create processing task */
    if (xTaskCreate(
            ProcessingTask,
            "ProcessingTask",
            256,
            NULL,
            3,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
            /* Processing task creation failed */
        }
    }

    /* Start scheduler */
    vTaskStartScheduler();

    /* Reached if scheduler startup fails */
    for (;;)
    {
    }
}

11. Program Explanation

Step 1 – Define Sensor Structure

typedef struct
{
    uint16_t adcCount;
    float voltage;
    float temperature;
    uint32_t sampleNumber;
} SensorData_t;

The structure groups the measurement and its metadata into one queue item.

Step 2 – Create Queue

sensorQueue = xQueueCreate(
    5,
    sizeof(SensorData_t)
);

The queue stores five structures. Check the returned handle before using it.

Step 3 – Read Sensor

sensorData.adcCount = ADC_ReadTemperature();

The demonstration ADC function returns a simulated digital count. In a real system, use the ADC driver for the selected MCU.

Step 4 – Convert ADC Count

sensorData.voltage =
    ((float)sensorData.adcCount * 3.3f) / 1023.0f;

sensorData.temperature =
    sensorData.voltage / 0.010f;

The voltage is calculated using a 3.3 V reference and the temperature is calculated using the nominal LM35 scale.

Step 5 – Send Data to Queue

xQueueSend(
    sensorQueue,
    &sensorData,
    0
);

The acquisition task sends a copy of the structure. A zero wait time means it does not block if the queue is full.

Step 6 – Receive and Process Data

xQueueReceive(
    sensorQueue,
    &receivedData,
    portMAX_DELAY
);

The processing task blocks until a measurement becomes available.

Step 7 – Check Threshold

if (receivedData.temperature >= 40.0f)
{
    /* High-temperature condition */
}

The example uses 40°C as an illustrative threshold. Actual alarm thresholds must come from the application's requirements and sensor characteristics.

12. Understanding vTaskDelayUntil()

The sensor task uses vTaskDelayUntil() to maintain a nominal periodic sampling schedule.

TickType_t lastWakeTime = xTaskGetTickCount();

vTaskDelayUntil(
    &lastWakeTime,
    pdMS_TO_TICKS(1000)
);

For a 1000 ms interval, the task follows a nominal one-second release pattern, subject to tick resolution and scheduler behavior.

Difference Between Delay APIs

APIBehavior
vTaskDelay()Blocks for a relative number of ticks from the call.
vTaskDelayUntil()Uses a previous wake-time reference to maintain a periodic schedule.
Periodic scheduling does not guarantee that sampling or processing finishes before a deadline. Execution time, higher-priority tasks, interrupt load and blocking must also be considered.

13. Understanding Queue Full Condition

The example uses a queue with five measurement slots.

If the sensor task sends measurements faster than the processing task receives them, the queue may become full.

Possible Queue Policies

PolicyTypical Use
Reject new samplePreserve older queued samples.
Block producerApply backpressure when delayed sampling is acceptable.
Overwrite latest valueKeep the newest state when intermediate samples are not required; commonly use a queue of length one.
Increase queue capacityAbsorb a known burst or temporary processing delay.
Record overflowDetect that the application is not keeping up.

Queue capacity should be selected using the maximum expected burst, producer rate and worst-case consumer delay.

14. Sensor Sampling Rate

Sampling rate is the number of measurements acquired per second.

Sampling Frequency = 1 / Sampling Period

Examples:

Sampling PeriodSampling Frequency
1000 ms1 Hz
500 ms2 Hz
100 ms10 Hz
10 ms100 Hz

The correct sampling frequency depends on the sensor bandwidth, physical process, required response time and signal-processing requirements.

15. Sensor Filtering

Real sensor measurements may contain noise. Filtering can reduce short-term fluctuations.

Moving Average Filter

A simple moving average calculates the mean of the most recent N samples.

\[ y[n]=\frac{1}{N}\sum_{k=0}^{N-1}x[n-k] \]

For four samples:

Filtered Value =
    (Sample1 + Sample2 + Sample3 + Sample4) / 4

Benefits

  • Reduces some random measurement noise.
  • Smooths displayed values.
  • Can reduce false threshold transitions.

Limitations

  • Adds delay to the measurement response.
  • May hide short-duration peaks.
  • Requires buffer or sample-history management.
  • Does not remove every type of interference.

16. Threshold Detection and Hysteresis

A simple threshold may cause an alarm to switch repeatedly when the measurement fluctuates near the threshold.

Example with Hysteresis

  • Set alarm when temperature reaches or exceeds 40°C.
  • Clear alarm when temperature falls below 38°C.
if (temperature >= 40.0f)
{
    alarmActive = 1;
}
else if (temperature < 38.0f)
{
    alarmActive = 0;
}

The two different thresholds create a hysteresis band and reduce rapid switching near the alarm boundary.

17. Adding a Dedicated Alarm Task

A larger application can separate acquisition, processing and alarm handling.

SENSOR TASK | v SENSOR QUEUE | v PROCESSING TASK | ALARM EVENT | v ALARM TASK | BUZZER / RELAY

The processing task can notify the alarm task through an event group, task notification or a separate queue. The selection depends on whether the alarm requires event bits, counts or structured data.

18. Task Priority Selection

Task priorities should reflect response requirements, not simply the order in which tasks were created.

TaskExample PriorityReason
Sensor acquisition2Maintains required sampling schedule.
Data processing3Processes available measurements promptly.
Display or logging1Non-critical reporting activity.
These are illustrative priority values, not universal recommendations. The correct assignment depends on task deadlines, execution times, blocking, interrupt load and the configured priority range.

19. Improving the Project

Consider the following enhancements for a production-quality design:

  • Replace simulated ADC values with a hardware ADC driver.
  • Use calibrated sensor conversion equations.
  • Check ADC conversion and sensor fault status.
  • Track queue-send failures and sequence-number gaps.
  • Implement a suitable filtering method.
  • Add threshold hysteresis.
  • Separate alarm handling from data acquisition.
  • Use a watchdog strategy based on meaningful task progress.
  • Measure task execution time and response time.
  • Validate the system under maximum expected load.

20. Practical Exercise 1 – Add a Second Sensor

Objective: Monitor temperature and light intensity in the same application.

  • Add a second ADC acquisition function.
  • Extend the data structure with a light measurement.
  • Send both readings through the queue.
  • Process both values in the processing task.
  • Report temperature and light status separately.

Expected result: One queue item contains both sensor measurements and their associated metadata.

21. Practical Exercise 2 – Change the Sampling Rate

Objective: Configure periodic sampling at 100 ms.

vTaskDelayUntil(
    &lastWakeTime,
    pdMS_TO_TICKS(100)
);
  • Change the sampling interval from 1000 ms to 100 ms.
  • Observe the measurement sequence numbers.
  • Check whether the queue becomes full.
  • Compare producer and consumer rates.

Expected result: A nominal 10 Hz sampling schedule, subject to tick resolution and task execution behavior.

22. Practical Exercise 3 – Add Moving Average Filtering

Objective: Smooth noisy sensor readings.

  • Maintain a fixed-size sample buffer.
  • Calculate the average of the latest four readings.
  • Send both raw and filtered measurements to the processing task.
  • Compare their response to a sudden measurement change.

Expected result: A smoother output with a measurable response delay.

23. Practical Exercise 4 – Queue Overflow Detection

Objective: Detect when the processing task cannot keep up with sensor acquisition.

  • Keep the queue capacity small.
  • Temporarily slow the processing task.
  • Check the return value of xQueueSend().
  • Maintain a dropped-sample counter.
  • Restore the normal processing rate and inspect sequence numbers.

Expected result: Queue overflow becomes observable instead of silently ignored.
