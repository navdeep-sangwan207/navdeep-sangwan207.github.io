2. Project Introduction

UART (Universal Asynchronous Receiver/Transmitter) is a serial communication interface commonly used in embedded systems for debugging, command processing, device communication and data logging.

This project uses FreeRTOS tasks and queues to organize UART communication.

Project Objective

Develop an application in which multiple tasks can request UART transmission, while received UART data is transferred from an interrupt handler to an application task for processing.

ComponentResponsibility
UART peripheralSerial transmission and reception.
UART driverHandles hardware registers, buffers and interrupts.
Application tasksGenerate messages and process received commands.
TX queueTransfers outgoing messages to the UART-owner task.
RX queueTransfers received bytes from the ISR to a task.
UART-owner taskSerializes outgoing messages and manages transmission requests.

3. UART Communication Basics

UART is an asynchronous serial communication protocol. It normally uses separate transmit and receive signals.

SignalFunction
TXTransmits serial data.
RXReceives serial data.
GNDCommon electrical reference for the interface.

Common UART Configuration

  • Baud rate: 9600, 19200, 38400, 57600 or 115200 bits/s.
  • Data bits: commonly 8.
  • Parity: none, even or odd.
  • Stop bits: commonly 1 or 2.

A common configuration is 9600 baud, 8 data bits, no parity and 1 stop bit, often written as 9600 8N1.

4. UART Frame Format

A UART frame typically contains a start bit, data bits, an optional parity bit and one or more stop bits.

IDLE | START | D0 D1 D2 D3 D4 D5 D6 D7 | STOP | IDLE 1 | 0 | DATA BITS | 1 | 1
FieldDescription
Start bitLogic low indicates the beginning of a frame.
Data bitsCarry the transmitted character or byte.
Parity bitOptional basic error-detection bit.
Stop bitLogic high indicates the end of the frame.
UART is asynchronous: transmitter and receiver use configured baud-rate timing rather than a shared clock signal.

5. UART Communication in FreeRTOS

UART operations can be performed from tasks or through interrupt-driven and DMA-based drivers. The correct design depends on the selected MCU and driver.

Task-Based Transmission

An application task requests transmission. A UART-owner task obtains the message and passes it to the driver.

Interrupt-Driven Reception

The UART peripheral generates an interrupt when receive data is available. The ISR reads the received byte and transfers it to an application task using an ISR-safe communication mechanism.

APPLICATION TASKS | | +---+---+ | v TX QUEUE | v UART OWNER TASK | v UART DRIVER | v UART TRANSMITTER UART RECEIVER | v UART ISR | v RX QUEUE | v RX PROCESSING TASK

6. Why Use a Dedicated UART Task?

If multiple tasks directly write to the same UART peripheral, their transmissions can interfere unless the driver provides suitable serialization.

A dedicated UART-owner task provides a single application-level owner of the transmission interface.

Advantages

  • Centralized transmission management.
  • Consistent message ordering according to queue policy.
  • Reduced need for multiple tasks to use a UART mutex.
  • Centralized handling of transmit errors and completion.
  • Better control over message buffering.
A queue transfers messages to the UART-owner task. The owner task should not release a message buffer or reuse its storage until the driver no longer needs it.

7. UART Driver Design

The UART driver is hardware-specific. It may support polling, interrupts, DMA or a combination of these techniques.

MethodDescriptionTypical Consideration
PollingCPU checks UART status repeatedly.Simple but can waste CPU time.
Interrupt-drivenUART interrupts signal data availability or transmission progress.Requires careful ISR and buffer management.
DMA-drivenDMA transfers data between memory and UART peripheral.Requires transfer-completion and buffer-lifetime management.

Suggested Driver Interface

void UART_Init(void);

int UART_StartTransmit(
    const uint8_t *buffer,
    uint16_t length
);

uint8_t UART_ReadByteFromHardware(void);

void UART_EnableReceiveInterrupt(void);

These are illustrative application-level function declarations. Their implementation must match the target MCU and peripheral driver.

8. FreeRTOS Queue for UART Transmission

A TX queue can transfer complete messages to the UART-owner task.

Message Structure

#define UART_MESSAGE_SIZE 64

typedef struct
{
    char text[UART_MESSAGE_SIZE];
    uint16_t length;
} UART_Message_t;

Create the Queue

QueueHandle_t uartTxQueue;

uartTxQueue = xQueueCreate(
    8,
    sizeof(UART_Message_t)
);

The queue can hold eight message structures. FreeRTOS copies the complete structure into the queue.

Send a Message

UART_Message_t message = {0};

snprintf(
    message.text,
    sizeof(message.text),
    "System Started\r\n"
);

message.length = strlen(message.text);

xQueueSend(
    uartTxQueue,
    &message,
    pdMS_TO_TICKS(50)
);

9. UART Receive Queue

Received bytes can be transferred from the UART ISR to a task through a queue.

Create the RX Queue

QueueHandle_t uartRxQueue;

uartRxQueue = xQueueCreate(
    32,
    sizeof(uint8_t)
);

Receive in a Task

uint8_t receivedByte;

if (xQueueReceive(
        uartRxQueue,
        &receivedByte,
        portMAX_DELAY
    ) == pdPASS)
{
    /* Process received byte */
}

The receive task blocks until a byte becomes available.

10. ISR-to-Task Communication

When the UART peripheral receives data, the interrupt handler can read the byte and place it in a queue.

Important Rules

  • Use ISR-safe FreeRTOS APIs.
  • Do not call task-context blocking APIs from an ISR.
  • Do not wait for queue space inside the ISR.
  • Keep interrupt processing short.
  • Handle queue-full conditions.
  • Request a context switch when required by the selected port.

Conceptual ISR Pattern

void UART_IRQHandler(void)
{
    BaseType_t higherPriorityTaskWoken = pdFALSE;

    uint8_t receivedByte;

    /* Read and acknowledge hardware interrupt */
    receivedByte = UART_ReadByteFromHardware();

    /* Transfer byte to RX queue */
    if (xQueueSendFromISR(
            uartRxQueue,
            &receivedByte,
            &higherPriorityTaskWoken
        ) != pdPASS)
    {
        /* Record receive queue overflow */
    }

    /*
     * Request a context switch if needed.
     * Exact macro is port-specific.
     */
    portYIELD_FROM_ISR(higherPriorityTaskWoken);
}
This is a conceptual ISR template, not a complete LPC2129 interrupt handler. A real handler must inspect the peripheral interrupt identification/status, handle all relevant causes, read the correct UART register and acknowledge the source according to the device documentation. The yield macro and ISR API behavior must match the FreeRTOS port.

11. Complete FreeRTOS UART Application Example

Objective: Implement a queue-based UART transmission task and a receive-processing task.

This example demonstrates the application architecture. Hardware-specific UART functions and the interrupt handler must be implemented separately for the target. The example assumes a driver that provides a synchronous transmit operation, or otherwise waits for transmission completion before returning.
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "stdint.h"
#include "stdio.h"
#include "string.h"

#define UART_MESSAGE_SIZE 64

/* UART message structure */
typedef struct
{
    char text[UART_MESSAGE_SIZE];
    uint16_t length;
} UART_Message_t;

/* Queue handles */
static QueueHandle_t uartTxQueue = NULL;
static QueueHandle_t uartRxQueue = NULL;

/* Hardware-specific UART functions */
void UART_Init(void);

void UART_SendBuffer(
    const uint8_t *buffer,
    uint16_t length
);

/* Task declarations */
static void UART_TxTask(void *pvParameters);
static void UART_RxTask(void *pvParameters);
static void ApplicationTask(void *pvParameters);

/* Send a message through the TX queue */
static BaseType_t UART_QueueMessage(
    const char *text
)
{
    UART_Message_t message = {0};

    size_t length = strlen(text);

    if (length >= UART_MESSAGE_SIZE)
    {
        return pdFAIL;
    }

    memcpy(message.text, text, length);

    message.length = (uint16_t)length;

    return xQueueSend(
        uartTxQueue,
        &message,
        pdMS_TO_TICKS(50)
    );
}

/* UART transmission task */
static void UART_TxTask(void *pvParameters)
{
    UART_Message_t message;

    (void) pvParameters;

    for (;;)
    {
        if (xQueueReceive(
                uartTxQueue,
                &message,
                portMAX_DELAY
            ) == pdPASS)
        {
            /*
             * Driver must complete the transfer
             * or safely manage buffer ownership.
             */
            UART_SendBuffer(
                (const uint8_t *)message.text,
                message.length
            );
        }
    }
}

/* UART receive-processing task */
static void UART_RxTask(void *pvParameters)
{
    uint8_t receivedByte;

    (void) pvParameters;

    for (;;)
    {
        if (xQueueReceive(
                uartRxQueue,
                &receivedByte,
                portMAX_DELAY
            ) == pdPASS)
        {
            /*
             * Example command processing.
             * A production application should
             * assemble and validate complete frames.
             */
            if (receivedByte == '\r')
            {
                UART_QueueMessage(
                    "Carriage return received\r\n"
                );
            }
            else if (receivedByte == '\n')
            {
                UART_QueueMessage(
                    "Line feed received\r\n"
                );
            }
            else
            {
                /* Process or buffer received byte */
            }
        }
    }
}

/* Application task */
static void ApplicationTask(void *pvParameters)
{
    (void) pvParameters;

    for (;;)
    {
        UART_QueueMessage(
            "FreeRTOS UART Application Running\r\n"
        );

        vTaskDelay(pdMS_TO_TICKS(2000));
    }
}

int main(void)
{
    UART_Init();

    /* Create TX queue */
    uartTxQueue = xQueueCreate(
        8,
        sizeof(UART_Message_t)
    );

    /* Create RX queue */
    uartRxQueue = xQueueCreate(
        32,
        sizeof(uint8_t)
    );

    if (uartTxQueue == NULL || uartRxQueue == NULL)
    {
        for (;;)
        {
            /* Queue creation failure */
        }
    }

    /* Create UART TX task */
    if (xTaskCreate(
            UART_TxTask,
            "UART_Tx",
            256,
            NULL,
            3,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
            /* Task creation failure */
        }
    }

    /* Create UART RX task */
    if (xTaskCreate(
            UART_RxTask,
            "UART_Rx",
            256,
            NULL,
            3,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
            /* Task creation failure */
        }
    }

    /* Create application task */
    if (xTaskCreate(
            ApplicationTask,
            "Application",
            256,
            NULL,
            2,
            NULL
        ) != pdPASS)
    {
        for (;;)
        {
            /* Task creation failure */
        }
    }

    vTaskStartScheduler();

    for (;;)
    {
        /* Scheduler startup failure */
    }
}
The code requires a real UART ISR or another driver mechanism to populate uartRxQueue. It also requires a target-specific implementation of UART_SendBuffer(). Do not expect it to compile or run as a complete application without those components.

12. Program Explanation

Step 1 – Define Message Structure

typedef struct
{
    char text[UART_MESSAGE_SIZE];
    uint16_t length;
} UART_Message_t;

The structure contains a complete outgoing message and its length.

Step 2 – Create TX and RX Queues

uartTxQueue = xQueueCreate(
    8,
    sizeof(UART_Message_t)
);

uartRxQueue = xQueueCreate(
    32,
    sizeof(uint8_t)
);

The TX queue stores message structures. The RX queue stores individual received bytes.

Step 3 – Submit Outgoing Messages

UART_QueueMessage(
    "FreeRTOS UART Application Running\r\n"
);

Application tasks submit messages through the TX queue instead of accessing the UART peripheral directly.

Step 4 – Transmit Messages

xQueueReceive(
    uartTxQueue,
    &message,
    portMAX_DELAY
);

The UART TX task receives a message and passes it to the driver.

Step 5 – Receive UART Bytes

The UART ISR reads incoming bytes and sends them to the RX queue using an ISR-safe API.

Step 6 – Process Received Data

The RX task receives bytes and performs application-level command processing.

13. UART Message Framing

UART transmits a continuous stream of bytes. It does not automatically define application-level message boundaries.

A receiver must determine where one message ends and another begins.

Common Framing Methods

MethodDescription
Delimiter-basedMessages end with a delimiter such as newline.
Fixed-lengthEvery message contains a known number of bytes.
Length-prefixedA header specifies the message length.
Start/end markersSpecial bytes identify frame boundaries.
Protocol-basedStructured packets contain header, payload and integrity fields.

Example Line-Based Protocol

TEMP:28.5\r\n
STATUS:RUNNING\r\n
ALARM:OFF\r\n

The receiver can collect bytes until it encounters a newline delimiter and then process the complete line.

14. UART Buffer Management

Buffer management is important in interrupt-driven and DMA-driven communication.

Important Concepts

  • TX buffers contain outgoing data.
  • RX buffers store incoming data.
  • Buffer capacity must account for expected traffic bursts.
  • Queue overflow must be detected.
  • DMA buffers must remain valid until the transfer completes.
  • Shared buffers require a defined ownership or synchronization protocol.
A FreeRTOS queue copies the queued item. If the item contains a pointer, only the pointer value is copied; the pointed-to memory is not copied. Pointer-based designs therefore need an explicit lifetime and ownership policy.

15. UART Baud Rate Calculation

Baud rate represents the number of signaling symbols transmitted per second. For ordinary binary UART signaling, the symbol rate corresponds to the bit rate.

For a common 8N1 frame, each byte requires:

  • 1 start bit.
  • 8 data bits.
  • 1 stop bit.

Total = 10 bits per transmitted byte.

Approximate Throughput

Bytes per second = Baud Rate / Bits per Frame

At 9600 baud with 8N1:

Bytes per second = 9600 / 10
                 = 960 bytes/second

This is a theoretical line-rate estimate before considering protocol overhead, idle time and software delays.

16. UART Interrupt Handling

UART interrupts can indicate different events depending on the peripheral.

Interrupt EventTypical Meaning
Receive data availableOne or more bytes are ready to be read.
Receive timeoutData has stopped arriving for a configured interval.
Transmit holding register emptyMore transmit data can be supplied.
Transmit completeThe final frame has completed transmission.
Line status errorFraming, parity, overrun or other line error.

Actual interrupt causes and register-clearing behavior are peripheral-specific.

17. UART Error Handling

ErrorMeaningPossible Response
Overrun errorNew data arrives before earlier data is serviced.Improve ISR latency or buffering.
Framing errorExpected stop-bit condition was not detected.Check baud rate, wiring and signal quality.
Parity errorReceived parity does not match configured parity.Verify parity configuration and transmission integrity.
Noise errorPeripheral detects a noisy frame, where supported.Check grounding, wiring and electrical interference.
Queue overflowSoftware queue has no free item slot.Increase capacity or improve consumer performance.
UART parity detects some bit errors but is not a substitute for a robust packet integrity mechanism such as a CRC.

18. UART Communication with LPC2129

The LPC2129 provides two UART peripherals: UART0 and UART1.

PeripheralTX PinRX PinVIC Interrupt Source
UART0P0.0P0.1IRQ 6
UART1P0.8P0.9IRQ 7

Relevant UART0 Registers

RegisterPurpose
U0RBRReceive Buffer Register.
U0THRTransmit Holding Register.
U0DLL / U0DLMBaud-rate divisor latches when enabled.
U0LCRLine Control Register.
U0LSRLine Status Register.
U0IERInterrupt Enable Register.
U0IIRInterrupt Identification Register.

Baud Rate Divisor

For the LPC2129 UART baud-rate generator, the divisor is determined using the peripheral clock and the configured fractional divider.

With the fractional divider disabled:

Baud Rate = PCLK / (16 * Divisor)

For PCLK = 15 MHz and 9600 baud:

Divisor = 15000000 / (16 * 9600)
        = 97.65625

The divisor must be an integer, so the selected divisor produces a small baud-rate error. For example, divisor 98 gives approximately 9566.33 baud with the fractional divider disabled.

For accurate configuration, use the LPC2129 fractional baud-rate generator settings where appropriate and verify the resulting baud-rate error. Confirm the actual PCLK and register configuration in the project.

19. FreeRTOS ISR Rules for ARM7 / LPC2129

The LPC2129 uses an ARM7TDMI-S processor and a Vectored Interrupt Controller (VIC). Its interrupt architecture is not the Cortex-M NVIC architecture.

  • Use the FreeRTOS ISR APIs supported by the selected ARM7 port.
  • Keep the UART ISR short.
  • Do not call blocking queue or semaphore APIs from the ISR.
  • Do not use a mutex from an ISR.
  • Handle UART interrupt identification and status correctly.
  • Use the port-specific ISR exit and yield mechanism.
  • Verify interrupt priority and masking behavior for the selected port.
Do not copy Cortex-M-specific interrupt-priority configuration macros or NVIC examples into an ARM7 LPC2129 project. The port's interrupt integration must be followed.

20. Practical Exercise 1 – UART Echo Application

Objective: Receive a character through UART and transmit the same character back.

Operation

  1. Send a character from a terminal.
  2. UART hardware receives the character.
  3. The ISR transfers the character to the RX queue.
  4. The RX task receives it.
  5. The application submits the character for transmission.
  6. The TX task sends it through UART.

Expected result: The terminal displays the received character returned by the embedded application.

22. Practical Exercise 3 – Multiple Tasks Sending Messages

Objective: Allow multiple application tasks to submit UART messages.

  • Create a sensor task.
  • Create a status task.
  • Create a logging task.
  • Allow each task to submit messages to the TX queue.
  • Use one UART-owner task to transmit the messages.
  • Observe queue ordering and message integrity.

Expected result: Messages are transmitted through one owner task without competing direct access to the UART driver.

23. Practical Exercise 4 – Detect UART RX Overflow

Objective: Detect receive queue overflow.

  • Use a small RX queue.
  • Temporarily delay the receive-processing task.
  • Send a continuous stream of data.
  • Count failed ISR queue submissions.
  • Compare received sequence numbers with transmitted sequence numbers.

Expected result: The application identifies dropped data instead of silently assuming all bytes were received.

25. Keil µVision and LPC2129 Simulator Notes

For the LPC2129, UART0 and UART1 can be studied through their peripheral registers and interrupt configuration, subject to the simulator's device-model support.

Suggested Activities

  • Inspect UART0 line-control and divisor registers.
  • Review the calculated PCLK and baud-rate divisor.
  • Study the UART interrupt identification register.
  • Set breakpoints in the UART ISR.

A simulator may not reproduce a physical UART link, external serial adapter, electrical signal quality or every peripheral interrupt behavior. Verify the selected Keil device model and FreeRTOS ARM7 port before treating simulation results as hardware validation.

27. Lesson Summary

  • UART provides asynchronous serial communication.
  • TX and RX are separate communication signals.
  • FreeRTOS tasks can request UART transmission through a queue.
  • A dedicated UART-owner task simplifies shared transmission management.
  • Interrupt-driven reception can transfer bytes to tasks using ISR-safe APIs.
  • Queue overflow and hardware errors must be handled.
  • UART is a byte stream, so application-level framing is required.
  • DMA and interrupt-driven drivers need explicit buffer ownership rules.
  • The LPC2129 has UART0 and UART1 with separate pin assignments and interrupt sources.
  • ARM7 interrupt integration must follow the selected FreeRTOS port.
