Queue Peek and Reset

Inspecting Queue Data Without Removing It and Clearing Queue Contents

Home RTOS Course Chapter 15

1. Learning Objectives

FreeRTOS provides queue operations that allow an application to inspect the next item without removing it and to reset a queue to an empty state. These operations are useful in monitoring, control and communication applications.

  • Understand queue peek operations.
  • Study xQueuePeek().
  • Understand the difference between peek and receive.
  • Study xQueuePeekFromISR().
  • Understand xQueueReset().
  • Learn the limitations of queue reset.
  • Apply peek and reset operations in programs.

2. What Is Queue Peek?

Queue peek allows a task to inspect the item at the front of a queue without removing that item. The queue contents remain unchanged after a successful peek operation. 

Queue:
+----+----+----+
| 10 | 20 | 30 |
+----+----+----+
  ^
  |
Front Item

Peek:
Read 10
Queue remains:
+----+----+----+
| 10 | 20 | 30 |
+----+----+----+

A later receive operation can still retrieve the same front item, provided another operation has not changed the queue.

3. xQueuePeek() Function

The xQueuePeek() function copies the item at the front of a queue into an application buffer without removing the item from the queue.

Syntax

BaseType_t xQueuePeek(
    QueueHandle_t xQueue,
    void *pvBuffer,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xQueueHandle of the queue to inspect.
pvBufferPointer to memory where the copied item is stored.
xTicksToWaitMaximum time to wait if the queue is empty.

Return Value

Return ValueMeaning
pdPASSAn item was successfully copied into the buffer.
errQUEUE_EMPTYNo item became available within the allowed wait time.

4. xQueuePeek() Example

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t dataQueue;

void PeekQueueExample(void)
{
    int receivedValue;

    if (xQueuePeek(
            dataQueue,
            &receivedValue,
            0
        ) == pdPASS)
    {
        /* Inspect receivedValue */
    }
    else
    {
        /* Queue is empty */
    }
}

The example checks the front item without removing it. The queue handle must refer to a valid queue.

6. xQueuePeek() with Blocking Time

Like queue receive, queue peek can wait for an item to become available. 

int nextValue;

if (xQueuePeek(
        dataQueue,
        &nextValue,
        pdMS_TO_TICKS(500)
    ) == pdPASS)
{
    /* Front item inspected */
}
else
{
    /* Timeout occurred */
}

If the queue is empty, the calling task can enter the Blocked state for up to the specified waiting period. If an item becomes available, it is copied without removal.

The peek operation does not reserve the item for the calling task. Another task may receive or change the queue contents after the peek completes.

7. xQueuePeekFromISR() Function

FreeRTOS provides xQueuePeekFromISR() for inspecting the front item from an Interrupt Service Routine. It does not block.

Syntax

BaseType_t xQueuePeekFromISR(
    QueueHandle_t xQueue,
    void *pvBuffer
);

Example

void MyISR(void)
{
    int nextValue;

    if (xQueuePeekFromISR(
            dataQueue,
            &nextValue
        ) == pdPASS)
    {
        /* Inspect copied value */
    }
    else
    {
        /* Queue is empty */
    }
}
This is an illustrative API example. Use only the ISR-safe functions supported by the selected FreeRTOS version and port. The ISR must also obey the processor's interrupt-priority and kernel-calling rules.

8. What Is Queue Reset?

Queue reset returns a queue to an empty state by discarding its currently queued items. It does not delete the queue object. The queue can be used again after reset. 

Before Reset:
+----+----+----+----+
| 10 | 20 | 30 | 40 |
+----+----+----+----+
Queue contains 4 items

After xQueueReset():
+----+----+----+----+
|    |    |    |    |
+----+----+----+----+
Queue is empty

Reset is useful when previously queued data is no longer relevant and the application needs to start a new data-collection phase.

9. xQueueReset() Function

The xQueueReset() function resets an existing queue to its empty state.

Syntax

BaseType_t xQueueReset(
    QueueHandle_t xQueue
);

Return Value

Return ValueMeaning
pdPASSQueue reset successfully.
Other resultReset did not complete successfully.

Example

if (xQueueReset(dataQueue) == pdPASS)
{
    /* Queue is now empty */
}
else
{
    /* Handle reset failure */
}

The queue must already exist. Resetting does not allocate a new queue or change its configured length and item size.

10. Queue Reset vs Queue Delete

FeaturexQueueReset()vQueueDelete()
PurposeClear queued items.Delete the queue object.
Queue objectRemains available.No longer valid.
Queue capacityUnchanged.Object ceases to exist.
Further operationsAllowed after successful reset.Not allowed using the deleted handle.
Typical useDiscard old data and continue.End the queue's lifecycle.

11. Important Considerations When Resetting a Queue

  • All currently queued items are discarded.
  • Reset does not process or return discarded items to the application.
  • Reset does not delete the queue object.
  • Queue length and item size remain unchanged.
  • Coordinate reset with producers and consumers.
  • Do not assume a peeked item remains available after another task changes the queue.
  • Define how waiting tasks and new data are handled during a reset operation.
Resetting a queue while other tasks are using it can change what those tasks observe. Use an application-level synchronization or shutdown protocol when a coordinated reset is required.

12. Practical Program – Peek and Receive

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t dataQueue;

void QueuePeekDemo(void)
{
    int value;
    int peekedValue;
    int receivedValue;

    dataQueue = xQueueCreate(
        5,
        sizeof(int)
    );

    if (dataQueue == NULL)
    {
        return;
    }

    value = 100;

    xQueueSend(
        dataQueue,
        &value,
        0
    );

    value = 200;

    xQueueSend(
        dataQueue,
        &value,
        0
    );

    /* Inspect front item */
    if (xQueuePeek(
            dataQueue,
            &peekedValue,
            0
        ) == pdPASS)
    {
        /* peekedValue is 100 */
    }

    /* Retrieve front item */
    if (xQueueReceive(
            dataQueue,
            &receivedValue,
            0
        ) == pdPASS)
    {
        /* receivedValue is 100 */
    }

    vQueueDelete(dataQueue);
    dataQueue = NULL;
}

Expected Result

The first peek copies 100 without removing it. The subsequent receive retrieves 100 and removes it from the queue.

13. Practical Program – Queue Reset

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t dataQueue;

void QueueResetDemo(void)
{
    int value;
    UBaseType_t count;

    dataQueue = xQueueCreate(
        5,
        sizeof(int)
    );

    if (dataQueue == NULL)
    {
        return;
    }

    value = 10;
    xQueueSend(dataQueue, &value, 0);

    value = 20;
    xQueueSend(dataQueue, &value, 0);

    value = 30;
    xQueueSend(dataQueue, &value, 0);

    count = uxQueueMessagesWaiting(dataQueue);
    /* Expected count: 3 */

    if (xQueueReset(dataQueue) == pdPASS)
    {
        count = uxQueueMessagesWaiting(dataQueue);
        /* Expected count: 0 */
    }

    vQueueDelete(dataQueue);
    dataQueue = NULL;
}

Expected Result

Three items are initially stored. After a successful reset, the queue contains zero items but remains available for future send and receive operations.

15. Common Programming Mistakes

MistakeCorrection
Assuming peek removes an itemUse xQueueReceive() when removal is required.
Peeking an empty queue with zero waitCheck the return value.
Using task-context peek in an ISRUse xQueuePeekFromISR() where supported.
Assuming reset deletes the queueUse vQueueDelete() to delete it.
Resetting without coordinating queue usersDefine a safe synchronization protocol.
Using a queue handle after deletionInvalidate the application handle and stop all users.

19. Lesson Summary

  • xQueuePeek() copies the front item without removing it.
  • xQueueReceive() copies and removes the front item.
  • xQueuePeekFromISR() provides a non-blocking ISR-context peek operation where supported.
  • xQueueReset() clears all currently queued items.
  • Reset does not delete the queue object.
  • Queue capacity and item size remain unchanged after reset.
  • Queue users must be coordinated during reset and deletion.
  • Always check the return values of queue operations.
