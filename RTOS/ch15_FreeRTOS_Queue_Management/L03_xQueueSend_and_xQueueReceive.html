xQueueSend() and xQueueReceive()

Sending and Receiving Data Between FreeRTOS Tasks

1. Learning Objectives

FreeRTOS queues provide a structured method for exchanging data between tasks and between interrupt service routines and tasks. This lesson explains how data is inserted into and removed from a queue.

  • Understand queue send and receive operations.
  • Study xQueueSend() and xQueueReceive().
  • Understand queue handles and item copying.
  • Study blocking and non-blocking operations.
  • Understand queue-full and queue-empty conditions.
  • Learn how tasks communicate through queues.
  • Identify the correct APIs for ISR communication.

2. Queue Communication Overview

A queue acts as a temporary data-storage mechanism between independent tasks. A sending task inserts an item into the queue, and a receiving task retrieves an item. 

       Sender Task
            |
            | xQueueSend()
            v
      +-------------+
      | FreeRTOS    |
      | Queue       |
      | FIFO Buffer |
      +-------------+
            |
            | xQueueReceive()
            v
       Receiver Task

A normal FreeRTOS queue follows FIFO (First In, First Out) behavior when items are sent to the back and received from the front.

3. xQueueSend() Function

The xQueueSend() function copies an item into a queue. It normally inserts the item at the back of the queue.

Syntax

BaseType_t xQueueSend(
    QueueHandle_t xQueue,
    const void *pvItemToQueue,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xQueueHandle of the queue receiving the item.
pvItemToQueuePointer to the data item to copy into the queue.
xTicksToWaitMaximum time the calling task waits if the queue is full.

Return Value

Return ValueMeaning
pdPASSThe item was successfully sent.
errQUEUE_FULLThe item could not be sent within the allowed wait time.

The return type is BaseType_t. Check the result instead of assuming that every send operation succeeds.

4. xQueueSend() Example

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t dataQueue;

void SenderTask(void *pvParameters)
{
    int sensorValue = 250;

    for (;;)
    {
        if (xQueueSend(
                dataQueue,
                &sensorValue,
                0
            ) == pdPASS)
        {
            /* Item successfully queued */
        }
        else
        {
            /* Queue was full */
        }

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

The sender task attempts to insert the integer value into the queue. A wait time of zero means that it does not wait when the queue is full.

5. xQueueReceive() Function

The xQueueReceive() function removes an item from a queue and copies that item into the receiving task's destination memory.

Syntax

BaseType_t xQueueReceive(
    QueueHandle_t xQueue,
    void *pvBuffer,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xQueueHandle of the queue from which data is received.
pvBufferPointer to the destination memory where the received item is copied.
xTicksToWaitMaximum time the calling task waits if the queue is empty.

Return Value

Return ValueMeaning
pdPASSAn item was successfully received.
errQUEUE_EMPTYNo item became available within the allowed wait time.

The item is removed from the queue after a successful receive operation.

6. xQueueReceive() Example

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t dataQueue;

void ReceiverTask(void *pvParameters)
{
    int receivedValue;

    for (;;)
    {
        if (xQueueReceive(
                dataQueue,
                &receivedValue,
                portMAX_DELAY
            ) == pdPASS)
        {
            /* Process receivedValue */
        }
    }
}

The receiver task waits for an item to become available. Once an item is received, it is copied into receivedValue and removed from the queue.

An indefinite wait using portMAX_DELAY depends on the relevant FreeRTOS configuration, including INCLUDE_vTaskSuspend for the traditional indefinite-blocking behavior.

7. Blocking and Non-Blocking Operations

The xTicksToWait parameter determines how long a task waits when the queue cannot immediately complete the requested operation.

Wait ValueBehavior
0Do not wait. Return immediately if the operation cannot be completed.
Finite tick valueWait up to the specified number of ticks.
portMAX_DELAYWait indefinitely when supported by the configuration.

Blocking Send

If the queue is full, the sending task can enter the Blocked state while waiting for space to become available.

Blocking Receive

If the queue is empty, the receiving task can enter the Blocked state while waiting for data.

8. Queue Full and Queue Empty Conditions

Queue Full

A queue is full when it contains the maximum number of items defined during creation. A send operation cannot insert another item until space becomes available.

Queue Empty

A queue is empty when it contains no items. A receive operation cannot retrieve an item until data is inserted. 

Queue Capacity = 4

+---+---+---+---+
One Free Position

9. FIFO Operation

FIFO means First In, First Out. When items are sent to the back of a queue, the oldest queued item is normally received first.

OperationQueue Contents
InitiallyEmpty
Send 1010
Send 2010, 20
Send 3010, 20, 30
Receive10 is returned; queue contains 20, 30.
Receive20 is returned; queue contains 30.

FreeRTOS also provides other queue insertion operations, such as sending to the front. These are covered in the following lessons.

10. Sending and Receiving Different Data Types

A queue can store fixed-size items such as integers, floating-point values, structures and pointer values. The queue's item size must match the size of the item being copied.

Integer Data

int temperature = 28;

xQueueSend(
    dataQueue,
    &temperature,
    0
);

Structure Data

typedef struct
{
    int temperature;
    int humidity;
} SensorData;

SensorData sensor = {28, 65};

xQueueSend(
    sensorQueue,
    &sensor,
    0
);

For a structure queue, create the queue with sizeof(SensorData) and receive into a valid SensorData object.

Pointer Data

If a queue is created to hold pointers, FreeRTOS copies the pointer value, not the memory pointed to by that pointer. The application must manage buffer ownership and lifetime carefully.

11. Complete Task-to-Task Communication Example

The following example demonstrates a sender task transmitting an integer to a receiver task using a FreeRTOS queue. 

#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"

QueueHandle_t sensorQueue;

void SensorTask(void *pvParameters)
{
    int sensorValue = 0;

    for (;;)
    {
        sensorValue += 10;

        if (xQueueSend(
                sensorQueue,
                &sensorValue,
                pdMS_TO_TICKS(100)
            ) != pdPASS)
        {
            /* Handle queue send failure */
        }

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

void DisplayTask(void *pvParameters)
{
    int receivedValue;

    for (;;)
    {
        if (xQueueReceive(
                sensorQueue,
                &receivedValue,
                portMAX_DELAY
            ) == pdPASS)
        {
            /* Process receivedValue */
        }
    }
}

int main(void)
{
    sensorQueue = xQueueCreate(
        5,
        sizeof(int)
    );

    if (sensorQueue == NULL)
    {
        for (;;)
        {
            /* Queue creation failure */
        }
    }

    xTaskCreate(
        SensorTask,
        "Sensor",
         configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    );

    xTaskCreate(
        DisplayTask,
        "Display",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. A queue is created with five integer positions.
  2. SensorTask generates an integer value.
  3. xQueueSend() copies the value into the queue.
  4. DisplayTask waits for an item.
  5. xQueueReceive() copies the item into receivedValue.
  6. The receiver processes the received value.
This is generic FreeRTOS application code. The stack-depth argument is expressed in StackType_t elements in the traditional xTaskCreate() API. The exact build also requires a compatible port, startup code, heap implementation and configuration.

12. Queue Send and Receive from ISR

Interrupt Service Routines must use the appropriate FromISR APIs instead of the ordinary task-context queue functions. 

BaseType_t xQueueSendFromISR(
    QueueHandle_t xQueue,
    const void *pvItemToQueue,
    BaseType_t *pxHigherPriorityTaskWoken
);

BaseType_t xQueueReceiveFromISR(
    QueueHandle_t xQueue,
    void *pvBuffer,
    BaseType_t *pxHigherPriorityTaskWoken
);

These operations do not block. They attempt to complete immediately and report success or failure.

  • Use xQueueSendFromISR() to send data from an ISR.
  • Use xQueueReceiveFromISR() to receive data from an ISR where appropriate.
  • Check the return value.
  • Use the port's ISR-yield mechanism when a higher-priority task is unblocked.
  • Keep ISR processing short.
The exact ISR-yield macro and interrupt-priority rules depend on the selected FreeRTOS port. Do not assume Cortex-M interrupt-priority rules apply to the LPC2129 ARM7 processor.

13. Common Programming Mistakes

MistakeCorrection
Using an invalid queue handleCheck queue creation before using it.
Incorrect item sizeUse the correct sizeof() expression.
Ignoring return valuesCheck pdPASS or failure status.
Using an excessive wait timeChoose a timeout based on system requirements.
Using task APIs inside an ISRUse the appropriate FromISR API.
Assuming pointer data is copiedRemember that only the pointer value is copied.
Deleting a queue while in useCoordinate shutdown of all queue users first.

17. Lesson Summary

  • xQueueSend() inserts an item into a queue by copying it.
  • xQueueReceive() retrieves and removes an item.
  • Queue items have a fixed size defined at creation.
  • Normal send-to-back and receive-from-front operations provide FIFO behavior.
  • xTicksToWait controls blocking time.
  • Zero wait means immediate return if the operation cannot complete.
  • Queue send and receive operations return a status.
  • Pointer queues copy pointer values, not pointed-to objects.
  • ISRs must use suitable FromISR APIs.
  • Queue users must be stopped before the queue is deleted.
