Queue Sets

Monitoring Multiple Queues and Semaphores Using a Single Selection Mechanism

Home RTOS Course Chapter 15

1. Learning Objectives

A FreeRTOS application may use multiple queues and semaphores for communication between tasks. A task sometimes needs to wait until any one of several communication objects becomes ready. Queue sets provide a mechanism for this purpose.

  • Understand the concept of queue sets.
  • Learn why queue sets are used.
  • Study queue-set creation and membership.
  • Understand xQueueSelectFromSet().
  • Learn how to receive data from a selected queue.
  • Study queue-set capacity requirements.
  • Understand limitations and programming precautions.

2. What Is a Queue Set?

A queue set is a FreeRTOS object that allows a task to block while waiting for activity on one or more queues or semaphores. When a member object becomes available, the queue set can report which member is ready.

For example, an application may have:

  • Sensor queue for measurement data.
  • Command queue for control commands.
  • Binary semaphore for an event signal.

Instead of checking each object repeatedly, a task can wait on the queue set and then process the member object identified by it.

3. Why Are Queue Sets Required?

Without a queue set, a task that needs to monitor multiple queues may repeatedly check each queue. This is often called polling. Polling can waste CPU time and complicate the task's waiting behavior.

Without Queue Set

        Monitoring Task
               |
       +-------+-------+
       |       |       |
       v       v       v
    Queue A Queue B Semaphore
       |       |       |
       +-------+-------+
          Repeated Checks

With Queue Set

        Monitoring Task
               |
               v
         Queue Set Wait
               |
       +-------+-------+
       |       |       |
       v       v       v
    Queue A Queue B Semaphore
               |
               v
      Select Ready Member

A queue set allows the task to block until a member object has an available item or token, subject to the queue-set rules.

4. Queue Set Architecture

A queue set is itself a queue-like object used to record which member queue or semaphore has become ready. The application selects a ready member and then performs the normal receive or take operation on that member.

ComponentPurpose
Queue setTracks readiness notifications from member objects.
Member queueStores application data.
Member semaphoreProvides a synchronization token.
Monitoring taskWaits for and selects a ready member.
Selecting a member from a queue set does not itself remove the application data from that member queue or take the semaphore. The task must perform the corresponding receive or take operation.

5. Queue Set Configuration

Queue-set support is controlled by the FreeRTOS configuration option: 

#define configUSE_QUEUE_SETS 1

The option must be enabled in FreeRTOSConfig.h for queue-set APIs to be available in the selected kernel configuration.

6. xQueueCreateSet() Function

The xQueueCreateSet() function creates a queue set with a specified capacity.

Syntax

QueueSetHandle_t xQueueCreateSet(
    const UBaseType_t uxEventQueueLength
);
ParameterDescription
uxEventQueueLengthCapacity of the queue set's internal event queue.

Return Value

Returns a QueueSetHandle_t if creation succeeds, or NULL if the required memory cannot be allocated.

Example

QueueSetHandle_t sensorSet;

sensorSet = xQueueCreateSet(10);

if (sensorSet == NULL)
{
    /* Handle creation failure */
}

7. xQueueAddToSet() Function

The xQueueAddToSet() function adds a queue or semaphore to an existing queue set.

Syntax

BaseType_t xQueueAddToSet(
    QueueSetMemberHandle_t xQueueOrSemaphore,
    QueueSetHandle_t xQueueSet
);

Parameters

ParameterDescription
xQueueOrSemaphoreHandle of the queue or supported semaphore to add.
xQueueSetHandle of the destination queue set.

Example

BaseType_t result;

result = xQueueAddToSet(
    sensorQueue,
    sensorSet
);

if (result != pdPASS)
{
    /* Handle membership failure */
}

A member should be empty when added to a queue set. Existing queued items or available semaphore tokens must be handled before membership is established.

8. xQueueSelectFromSet() Function

The xQueueSelectFromSet() function allows a task to wait for a member of a queue set to become ready. It returns the handle of a ready member.

Syntax

QueueSetMemberHandle_t xQueueSelectFromSet(
    QueueSetHandle_t xQueueSet,
    TickType_t xTicksToWait
);

Parameters

ParameterDescription
xQueueSetQueue-set handle.
xTicksToWaitMaximum waiting time in RTOS ticks.

Return Value

  • Returns a member handle when a member is ready.
  • Returns NULL when no member becomes ready within the specified wait.

Example

QueueSetMemberHandle_t selectedMember;

selectedMember = xQueueSelectFromSet(
    sensorSet,
    portMAX_DELAY
);

if (selectedMember != NULL)
{
    /* Process selected member */
}

9. Receiving Data from a Selected Queue

After a queue is selected, the task must receive data from that queue using xQueueReceive(). 

QueueSetMemberHandle_t selectedMember;
int sensorValue;

selectedMember = xQueueSelectFromSet(
    sensorSet,
    portMAX_DELAY
);

if (selectedMember == sensorQueue)
{
    if (xQueueReceive(
            sensorQueue,
            &sensorValue,
            0
        ) == pdPASS)
    {
        /* Process sensorValue */
    }
}

The zero wait time is appropriate in this pattern because the queue set has already reported the member as ready. The task should still check the receive result.

10. Complete Queue Set Example

The following example demonstrates a monitoring task that waits for data from two queues: a sensor queue and a command queue. 

#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"

#define QUEUE_LENGTH 5

QueueHandle_t sensorQueue;
QueueHandle_t commandQueue;
QueueSetHandle_t applicationSet;

void MonitoringTask(void *pvParameters)
{
    QueueSetMemberHandle_t selectedMember;
    int sensorValue;
    int commandValue;

    for (;;)
    {
        selectedMember = xQueueSelectFromSet(
            applicationSet,
            portMAX_DELAY
        );

        if (selectedMember == sensorQueue)
        {
            if (xQueueReceive(
                    sensorQueue,
                    &sensorValue,
                    0
                ) == pdPASS)
            {
                /* Process sensor data */
            }
        }
        else if (selectedMember == commandQueue)
        {
            if (xQueueReceive(
                    commandQueue,
                    &commandValue,
                    0
                ) == pdPASS)
            {
                /* Process command */
            }
        }
    }
}

int main(void)
{
    sensorQueue = xQueueCreate(
        QUEUE_LENGTH,
        sizeof(int)
    );

    commandQueue = xQueueCreate(
        QUEUE_LENGTH,
        sizeof(int)
    );

    if ((sensorQueue == NULL) ||
        (commandQueue == NULL))
    {
        for (;;)
        {
        }
    }

    /*
     * Queue-set capacity must be at least
     * the sum of the member capacities.
     */
    applicationSet = xQueueCreateSet(
        QUEUE_LENGTH * 2
    );

    if (applicationSet == NULL)
    {
        for (;;)
        {
        }
    }

    if (xQueueAddToSet(
            sensorQueue,
            applicationSet
        ) != pdPASS)
    {
        for (;;)
        {
        }
    }

    if (xQueueAddToSet(
            commandQueue,
            applicationSet
        ) != pdPASS)
    {
        for (;;)
        {
        }
    }

    xTaskCreate(
        MonitoringTask,
        "Monitor",
        configMINIMAL_STACK_SIZE,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    for (;;)
    {
    }
}

Program Explanation

  1. Two queues are created.
  2. A queue set is created with capacity ten.
  3. Both queues are added to the set.
  4. The monitoring task waits for a ready member.
  5. The selected handle identifies the queue to process.
  6. The task receives the item from the selected queue.
This is an illustrative queue-set example. A complete application must also check task-creation results, define producer tasks, and provide a suitable cleanup strategy.

11. Queue Set Capacity Calculation

The queue-set capacity must be at least the sum of the maximum number of items that can be held by all member queues and the maximum number of available tokens in member semaphores.

Example

MemberCapacity
Sensor queue5
Command queue4
Binary semaphore1
Total required queue-set capacity10

Therefore:

Queue-set capacity = 5 + 4 + 1 = 10

An undersized queue set can lose readiness notifications and break the intended selection behavior. Do not size it merely for the number of member objects.

12. Adding Semaphores to Queue Sets

Queue sets can include supported semaphore types as members, allowing a task to wait for either queued data or a semaphore token. 

#include "FreeRTOS.h"
#include "queue.h"
#include "semphr.h"

QueueHandle_t eventSemaphore;
QueueSetHandle_t eventSet;

void CreateSemaphoreSet(void)
{
    eventSemaphore = xSemaphoreCreateBinary();

    eventSet = xQueueCreateSet(1);

    if ((eventSemaphore != NULL) &&
        (eventSet != NULL))
    {
        xQueueAddToSet(
            eventSemaphore,
            eventSet
        );
    }
}

When the semaphore becomes available, the queue set can report the semaphore handle. The task must then take the semaphore. 

QueueSetMemberHandle_t selected;

selected = xQueueSelectFromSet(
    eventSet,
    portMAX_DELAY
);

if (selected == eventSemaphore)
{
    if (xSemaphoreTake(
            eventSemaphore,
            0
        ) == pdPASS)
    {
        /* Handle event */
    }
}

13. Queue Set Restrictions and Precautions

  • Enable configUSE_QUEUE_SETS in FreeRTOSConfig.h.
  • Use the queue-set APIs supported by the selected kernel version.
  • Add only supported queue and semaphore objects.
  • A member must be empty when it is added to a queue set.
  • Do not receive from or take a member independently while relying on the queue set to track its readiness.
  • After selection, perform the matching receive or semaphore-take operation.
  • Size the queue set to cover all possible member items and tokens.
  • Check the return values of creation and membership functions.
  • Queue sets consume additional memory.
  • Consider direct task notifications or another design when a queue set is unnecessary.
Queue sets are generally most useful when one task must wait on several independent queue or semaphore objects. They are not a replacement for every queue communication design.

14. Queue Set vs Individual Queue Monitoring

FeatureIndividual MonitoringQueue Set

15. Practical Experiment

Objective: Create a queue set and monitor two queues.

Procedure

  1. Enable queue-set support in the FreeRTOS configuration.
  2. Create two queues for integer data.
  3. Create a queue set with sufficient capacity.
  4. Add both queues to the set while they are empty.
  5. Create producer tasks that send values to the queues.
  6. Create a monitoring task that calls xQueueSelectFromSet().
  7. Receive data from the selected queue.
  8. Verify which queue supplied each value.

Expected Result

The monitoring task blocks until one of the member queues contains an available item. It then identifies the ready queue and receives data from that queue.

16. Common Programming Mistakes

MistakeCorrection
Forgetting configUSE_QUEUE_SETSEnable the feature in the selected configuration.
Using an undersized queue setCalculate capacity from all member capacities.
Adding a non-empty memberEnsure the member is empty before adding it.
Assuming selection removes dataReceive from the selected queue or take the semaphore.
Ignoring NULL from selectionHandle the timeout case.
Independently consuming member dataKeep member access coordinated with queue-set selection.
Ignoring creation failuresCheck all returned handles and status values.

17. LPC2129 and Keil Simulator Considerations

  • LPC2129 uses ARM7TDMI-S architecture.
  • Verify a compatible FreeRTOS ARM7 port and Keil compiler integration.
  • Check queue-set support in the selected kernel release.
  • Enable the queue-set configuration option.
  • Account for queue-set memory in the available RAM budget.
  • Use debugger or trace facilities to inspect task execution where supported.
The examples use generic FreeRTOS APIs. They are not verified LPC2129 Keil simulator projects. Confirm port and kernel-version compatibility before building.
