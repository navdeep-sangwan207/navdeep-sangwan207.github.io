1. Learning Objectives

Queue creation and deletion are important parts of FreeRTOS memory management. An application must allocate sufficient memory for a queue, check whether creation succeeded and release dynamically allocated queue memory when it is no longer required.

  • Understand dynamic queue creation.
  • Study xQueueCreate().
  • Understand static queue creation.
  • Study xQueueCreateStatic().
  • Understand vQueueDelete().
  • Compare dynamic and static allocation.
  • Calculate queue storage requirements.
  • Learn safe queue lifecycle management.

2. Queue Creation Overview

Before a task can send or receive data, a queue must be created. FreeRTOS provides two common queue-creation methods:

  • xQueueCreate() – dynamically allocates queue memory.
  • xQueueCreateStatic() – uses memory supplied by the application.

The choice depends on the application's memory-management strategy, predictability requirements and FreeRTOS configuration.

3. xQueueCreate() Function

The xQueueCreate() function creates a queue using the FreeRTOS memory allocation mechanism.

Syntax

QueueHandle_t xQueueCreate(
    UBaseType_t uxQueueLength,
    UBaseType_t uxItemSize
);

Parameters

ParameterDescription
uxQueueLengthMaximum number of items the queue can hold.
uxItemSizeSize of each item in bytes.

Return Value

Return ValueMeaning
Valid QueueHandle_tQueue created successfully.
NULLQueue creation failed.

Example

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t dataQueue;

void CreateQueue(void)
{
    dataQueue = xQueueCreate(
        10,
        sizeof(int)
    );

    if (dataQueue == NULL)
    {
        /* Handle allocation failure */
    }
    else
    {
        /* Queue created successfully */
    }
}

4. Queue Memory Calculation

The item-storage requirement of a queue depends on its length and item size.

Item storage = Queue length × Item size

Example

Suppose a queue stores 10 integer items and the target compiler uses a 4-byte int.

\[ 10 \times 4 = 40\text{ bytes} \]

The queue therefore requires 40 bytes for the item-storage area. The total memory required is greater because FreeRTOS also needs queue-control data and allocation overhead.

ParameterValue
Queue length10
Item size4 bytes
Item storage40 bytes
Additional memoryQueue control structure and allocator overhead
Use sizeof() rather than assuming the size of a C data type. The exact size depends on the compiler and target architecture.

5. Dynamic Memory Allocation

Dynamic allocation means that memory is obtained from the configured FreeRTOS heap when the queue is created.

The memory is managed by the selected heap implementation and its allocation rules.

Example

QueueHandle_t commandQueue;

commandQueue = xQueueCreate(
    5,
    sizeof(unsigned int)
);

if (commandQueue != NULL)
{
    /* Use the queue */
}

Advantages

  • Convenient queue creation.
  • Queue size can be selected at runtime.
  • Application does not need to declare queue storage arrays.
  • Queue memory can be released using vQueueDelete().

Limitations

  • Creation can fail if heap memory is insufficient.
  • Allocation and deallocation can introduce timing variability.
  • Repeated allocation and deletion may cause fragmentation with some heap implementations.
  • Memory usage must be monitored carefully.

6. xQueueCreateStatic() Function

The xQueueCreateStatic() function creates a queue using memory supplied by the application. The queue storage area and queue control structure are provided by the application.

Syntax

QueueHandle_t xQueueCreateStatic(
    UBaseType_t uxQueueLength,
    UBaseType_t uxItemSize,
    uint8_t *pucQueueStorage,
    StaticQueue_t *pxStaticQueue
);

Parameters

ParameterDescription
uxQueueLengthMaximum number of queue items.
uxItemSizeSize of each item in bytes.
pucQueueStorageApplication-provided memory for queue items.
pxStaticQueueApplication-provided queue control storage.
The exact public declaration and availability must be checked against the selected FreeRTOS version. Static allocation support must be enabled in FreeRTOSConfig.h.

7. Static Queue Creation Example

#include "FreeRTOS.h"
#include "queue.h"

#define QUEUE_LENGTH 5

typedef struct
{
    int temperature;
    int humidity;
} SensorData;

static StaticQueue_t queueControl;

static uint8_t queueStorage[
    QUEUE_LENGTH * sizeof(SensorData)
];

QueueHandle_t sensorQueue;

void CreateStaticSensorQueue(void)
{
    sensorQueue = xQueueCreateStatic(
        QUEUE_LENGTH,
        sizeof(SensorData),
        queueStorage,
        &queueControl
    );

    if (sensorQueue == NULL)
    {
        /* Handle creation failure */
    }
    else
    {
        /* Queue created successfully */
    }
}

Here, the application provides storage for five SensorData items and a StaticQueue_t object for the queue control structure.

8. Static Allocation Configuration

Static allocation support is controlled by configuration options in FreeRTOSConfig.h. 

#define configSUPPORT_STATIC_ALLOCATION  1
#define configSUPPORT_DYNAMIC_ALLOCATION 1
ConfigurationMeaning
configSUPPORT_STATIC_ALLOCATION = 1Enables static allocation APIs where supported.
configSUPPORT_DYNAMIC_ALLOCATION = 1Enables dynamic allocation APIs where supported.

An application may enable both methods or choose a suitable allocation strategy based on its requirements and kernel configuration.

9. Dynamic vs Static Queue Creation

FeatureDynamicStatic
FunctionxQueueCreate()xQueueCreateStatic()
Memory sourceConfigured FreeRTOS heap.Application-provided memory.
Allocation timeAt runtime when called.Storage is reserved by the application.
Creation failureCan fail if heap allocation fails.Can fail if required arguments or configuration are invalid.
Memory controlManaged through heap implementation.Explicitly declared by application.
Typical useFlexible runtime allocation.Predictable, preallocated memory design.
Static allocation avoids runtime heap allocation for that queue, but it does not automatically guarantee deterministic behavior for the entire application. Scheduling, interrupts and other operations still need analysis.

10. vQueueDelete() Function

The vQueueDelete() function deletes a queue and releases the queue's dynamically allocated memory when applicable.

Syntax

void vQueueDelete(
    QueueHandle_t xQueue
);

Example

QueueHandle_t dataQueue;

void CreateAndDeleteQueue(void)
{
    dataQueue = xQueueCreate(
        5,
        sizeof(int)
    );

    if (dataQueue != NULL)
    {
        /* Perform queue operations */

        vQueueDelete(dataQueue);

        dataQueue = NULL;
    }
}

After deletion, the handle must not be used for further queue operations. Setting the application variable to NULL helps avoid accidental reuse of a stale handle.

11. Deleting a Static Queue

A statically allocated queue can also be deleted using vQueueDelete() when it is no longer required. However, the application-provided storage is not automatically released to a heap.

Memory ComponentAfter Deletion
Dynamic queue allocationReturned through the configured allocator.
Static queue storage arrayRemains application-owned.
Static queue control objectRemains application-owned.
Do not free, reuse or modify static queue storage while the queue is still in use. Ensure that no task or ISR can access the queue during deletion.

13. Practical Example – Dynamic Queue Lifecycle

#include "FreeRTOS.h"
#include "queue.h"

QueueHandle_t numberQueue;

void QueueLifecycleDemo(void)
{
    int value = 25;
    int receivedValue = 0;

    numberQueue = xQueueCreate(
        5,
        sizeof(int)
    );

    if (numberQueue == NULL)
    {
        return;
    }

    if (xQueueSend(
            numberQueue,
            &value,
            0
        ) == pdPASS)
    {
        if (xQueueReceive(
                numberQueue,
                &receivedValue,
                0
            ) == pdPASS)
        {
            /* Inspect receivedValue */
        }
    }

    vQueueDelete(numberQueue);

    numberQueue = NULL;
}

This example demonstrates queue creation, a send operation, a receive operation and queue deletion. It is a demonstration function; a real application must ensure the queue is not being accessed concurrently when it is deleted.

15. Practical Experiment – Dynamic and Static Queue Creation

Objective: Compare dynamic and static queue creation.

Experiment A – Dynamic Allocation

  1. Enable dynamic allocation support.
  2. Create a queue using xQueueCreate().
  3. Check whether the handle is NULL.
  4. Send and receive test data.
  5. Delete the queue using vQueueDelete().

Experiment B – Static Allocation

  1. Enable static allocation support.
  2. Declare a StaticQueue_t control object.
  3. Declare a correctly sized storage array.
  4. Create a queue using xQueueCreateStatic().
  5. Send and receive test data.
  6. Delete the queue when no longer required.

Expected Result

Both methods create queues that support normal queue operations. Dynamic allocation uses the configured heap, while static allocation uses memory supplied by the application.

16. LPC2129 and Keil Simulator Considerations

The LPC2129 uses the ARM7TDMI-S processor. Queue creation examples require a compatible FreeRTOS kernel port and suitable compiler integration.

  • Verify the exact FreeRTOS kernel release.
  • Check static and dynamic allocation configuration.
  • Verify the selected heap implementation.
  • Check available RAM and linker memory regions.
  • Verify the ARM7 port and Keil compiler compatibility.
  • Do not assume that the Keil simulator supports the complete FreeRTOS port.
These are generic FreeRTOS examples. They are not verified LPC2129 Keil simulator projects.

18. Lesson Summary

  • xQueueCreate() creates a queue using dynamic allocation.
  • xQueueCreateStatic() creates a queue using application-provided memory.
  • Queue length specifies the number of items.
  • Item size specifies the size of each item in bytes.
  • StaticQueue_t stores the queue control structure.
  • Static allocation requires appropriate configuration support.
  • vQueueDelete() deletes a queue.
  • Dynamic queue memory is returned through the configured allocator.
  • Static storage remains application-owned after deletion.
  • Never use a queue handle after deleting its queue.
