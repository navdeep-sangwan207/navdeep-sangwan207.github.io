Introduction to Real-Time Systems

Chapter 01 | Lesson 01

Understanding real-time computing and timing-dependent system behavior

Home Chapter Index RTOS Course

1. Introduction

A Real-Time System is a computer-based system in which the correctness of its operation depends not only on the logical result of computation but also on the time at which that result is produced.

In ordinary computing, a result may still be useful even if it arrives slightly later than expected. In a real-time system, however, producing the correct result after its required deadline may be considered a system failure.

Real-time systems are commonly used in embedded applications, industrial automation, automotive electronics, medical equipment, robotics, telecommunications and aerospace systems.

Fundamental Definition: A real-time system must produce logically correct results within specified timing constraints. Both functional correctness and timing correctness are important.

2. What Does Real-Time Mean?

The term real-time does not simply mean that a system operates very quickly. It means that the system responds within a defined and predictable time limit.

For example, consider an airbag controller in a vehicle. When a collision is detected, the controller must process the sensor information and activate the airbag within a specified time. An activation command generated after the required deadline may no longer be useful.

Important Characteristics

  • Timing constraints: Operations must complete within specified time limits.
  • Predictability: System response should be bounded and understood.
  • Deterministic behavior: Under defined conditions, the system should provide predictable timing behavior.
  • Reliability: The system should operate correctly under expected operating conditions.
  • Event responsiveness: The system must respond to external and internal events appropriately.

3. Functional Correctness and Timing Correctness

Real-time system correctness has two important dimensions:

Functional Correctness

The system performs the required computation and produces the logically correct result.

Timing Correctness

The system produces that result within the specified deadline.

Example: Temperature Monitoring System

Assume an industrial temperature controller must detect an unsafe temperature and activate an alarm within 100 milliseconds.

  • Correct temperature detection in 50 ms: functionally and temporally correct.
  • Correct temperature detection in 150 ms: functionally correct, but misses the specified deadline.
  • Incorrect temperature detection in 20 ms: timely, but functionally incorrect.

4. Basic Timing Parameters

Real-time systems are designed and analyzed using several timing parameters.

Parameter Meaning
Release Time The time at which a task becomes ready for execution.
Execution Time The processor time required to execute a task.
Deadline The time by which a task must complete.
Period The interval between successive releases of a periodic task.
Response Time The elapsed time from a task's release until its completion.
Latency The delay between an event and the corresponding system response.
Jitter The variation in the timing of an event or task execution.

5. Example of a Real-Time Task

Consider a motor-control system that checks its operating conditions every 10 milliseconds.

Assume the following task parameters:

Parameter Value
Task Period 10 ms
Execution Time 2 ms
Relative Deadline 10 ms

The task is released at 0 ms, executes for 2 ms and completes at 2 ms. Its next release occurs at 10 ms.

Response Time Calculation:

Response Time = Completion Time − Release Time

Response Time = 2 ms − 0 ms = 2 ms

Since the task completes before its 10 ms deadline, it meets the timing requirement in this simplified example.

6. Real-Time System Execution Cycle

A typical real-time embedded system follows an event-processing sequence:

  1. An external or internal event occurs.
  2. A sensor, peripheral or interrupt detects the event.
  3. The processor receives and processes the event.
  4. The appropriate task or control function executes.
  5. The system generates an output or control action.
  6. The response is completed within the required deadline.
Example: Industrial Motor Protection
  1. A current sensor detects excessive motor current.
  2. The controller receives the sensor information.
  3. The protection logic evaluates the current value.
  4. The controller issues a motor shutdown command.
  5. The system records or reports the fault.

7. Real-Time System Components

A real-time embedded system may contain the following components:

  • Processor: Executes control algorithms and application instructions.
  • Memory: Stores program instructions, variables and system data.
  • Sensors: Collect information from the physical environment.
  • Actuators: Perform physical actions based on control commands.
  • Timers: Provide timing references and periodic events.
  • Interrupt Controller: Handles interrupt requests from peripherals and external sources.
  • Operating System or RTOS: Manages tasks, scheduling and system resources when used.

8. Real-Time Systems in Embedded Applications

Application Real-Time Operation
Automotive Systems Airbag control, engine management and braking systems.
Industrial Automation Motor control, process monitoring and protection.
Medical Equipment Patient monitoring and time-sensitive device control.
Robotics Motion control, obstacle detection and actuator coordination.
Aerospace Flight control and navigation-related operations.
Telecommunications Time-sensitive communication and signal processing.

9. Role of RTOS in Real-Time Systems

An RTOS (Real-Time Operating System) provides kernel services that help applications manage time-sensitive operations.

Common RTOS services include:

  • Task creation and deletion.
  • Task scheduling and priority management.
  • Inter-task communication.
  • Semaphores and mutexes.
  • Software timers and time management.
  • Interrupt and event handling support.
  • Resource synchronization.

An RTOS helps organize concurrent application activities, but selecting an RTOS alone does not guarantee that every deadline will be met. The complete system must be designed and analyzed against its timing requirements.

10. Real-Time System Design Considerations

  • Define task execution periods and deadlines.
  • Determine worst-case execution time where required.
  • Select suitable scheduling and priority strategies.
  • Minimize interrupt and context-switch overhead.
  • Prevent race conditions and unsafe resource sharing.
  • Account for communication delays and peripheral timing.
  • Test behavior under maximum expected system load.
  • Provide fault detection and recovery mechanisms.
Important Note: Real-time does not necessarily mean high-speed execution. A slower system with predictable and bounded response time can be more suitable for a real-time application than a faster system with unpredictable delays.

11. Lesson Summary

  • A real-time system must satisfy both functional and timing correctness.
  • Deadlines are essential requirements in real-time applications.
  • Real-time behavior depends on predictable response and execution timing.
  • Important timing parameters include period, execution time, deadline, latency and jitter.
  • Real-time systems are widely used in automotive, industrial, medical and aerospace applications.
  • An RTOS provides services for managing tasks and time-sensitive operations.
  • Meeting deadlines requires system-level design and timing analysis.

13. Practical Learning Activity

Activity: Analyze a Motor Protection Task

Consider a motor protection controller that checks the motor current every 20 ms.

  • Task period = 20 ms
  • Execution time = 3 ms
  • Relative deadline = 20 ms

Calculate and identify:

  1. The task's response time, assuming it starts immediately and runs without interruption.
  2. Whether the task meets its deadline under that assumption.
  3. What could happen if higher-priority tasks or interrupt processing delay its execution?
