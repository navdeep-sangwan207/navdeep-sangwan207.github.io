Hard Real-Time Systems

Chapter 01 | Lesson 04

Understanding strict deadlines and guaranteed timing requirements

Home Chapter Index RTOS Course

1. Introduction

A Hard Real-Time System is a real-time computing system in which every critical task must complete within its specified deadline.

In these systems, missing a critical deadline is considered a system failure because the result may become invalid, unacceptable or unsafe.

Hard real-time systems are used in applications where timing accuracy is essential, such as aircraft flight control, automotive safety systems, industrial protection and certain medical devices.

Fundamental Definition: A hard real-time system must satisfy all specified critical timing deadlines under its defined operating assumptions. A late result is considered a failure for the affected critical operation.

2. Main Characteristics of Hard Real-Time Systems

1. Strict Deadlines

Critical tasks must complete before or at their specified deadlines. Deadline compliance is a mandatory requirement.

2. Deterministic Timing

The system must provide predictable and bounded timing behavior so that critical operations can be analyzed.

3. Bounded Execution Time

Designers must establish a safe upper bound on task execution time, commonly called Worst-Case Execution Time (WCET).

4. High Reliability

The system must operate correctly under defined conditions and include appropriate fault detection and recovery mechanisms.

5. Predictable Scheduling

Task priorities, execution requirements, blocking and interrupt interference must be considered during scheduling analysis.

6. Safety-Oriented Design

Many hard real-time applications require defined safe states, fault handling and extensive verification.

3. Deadline Requirements

A deadline specifies the maximum permitted time for a task to complete after its release.

For a task with release time \(r_i\) and absolute deadline \(d_i\), its completion time \(f_i\) must satisfy:

Deadline Condition:

\(f_i \leq d_i\)

If \(f_i > d_i\), the task has missed its deadline.

Example

Consider an automotive protection task with a relative deadline of 5 milliseconds.

Parameter Value
Release Time 0 ms
Deadline 5 ms
Execution Time 3 ms
Completion Time 3 ms

The task completes at 3 ms, which is before its 5 ms deadline. Therefore, it meets the timing requirement in this simplified example.

4. What Happens When a Deadline Is Missed?

In a hard real-time system, missing a critical deadline may result in a serious operational or safety problem.

Possible Consequences

  • Incorrect control action.
  • Failure to stop a machine in time.
  • Loss of system stability.
  • Damage to equipment.
  • Unsafe operation.
  • Loss of a required safety function.
Example: Industrial Emergency Shutdown

An industrial controller detects a dangerous operating condition. Its protection function must issue a shutdown command within the specified safety response time.

If the shutdown command arrives after the required deadline, the protection function has failed to meet its timing requirement.

5. Hard Real-Time System Architecture

A typical hard real-time embedded system contains several hardware and software components that work together to meet timing requirements.

Hardware Components

  • Microcontroller or real-time processor.
  • Program and data memory.
  • Hardware timers and counters.
  • Interrupt controller.
  • Sensor interfaces.
  • Actuator and control interfaces.

Software Components

  • Real-time application tasks.
  • RTOS kernel, if used.
  • Interrupt service routines.
  • Device drivers.
  • Scheduling and synchronization services.
  • Fault detection and recovery logic.

6. Role of RTOS in Hard Real-Time Systems

An RTOS can provide mechanisms for implementing time-critical applications. It helps manage concurrent tasks and shared resources.

Important RTOS Services

  • Priority-based scheduling: Assigns execution priority to tasks.
  • Preemption: Allows a higher-priority ready task to interrupt a lower-priority task when supported by the scheduling policy.
  • Task management: Creates, suspends, resumes and deletes tasks.
  • Semaphores: Provide synchronization and event signaling.
  • Mutexes: Protect shared resources.
  • Timers: Support periodic and timeout operations.
  • Queues: Transfer data between tasks.
Important: Using an RTOS does not automatically guarantee hard real-time behavior. The complete hardware and software system must have bounded execution, controlled blocking, suitable interrupt handling and verified schedulability.

7. Task Scheduling in Hard Real-Time Systems

Scheduling is a critical part of hard real-time system design. A scheduling algorithm determines when each task receives processor time.

Common Scheduling Algorithms

  • Rate Monotonic Scheduling (RMS): Assigns higher fixed priority to tasks with shorter periods under the classic RMS assumptions.
  • Earliest Deadline First (EDF): Gives priority to the ready task with the earliest absolute deadline.
  • Fixed-Priority Scheduling: Assigns task priorities before execution.
  • Preemptive Scheduling: Allows eligible higher-priority tasks to preempt running lower-priority tasks.

8. Worst-Case Execution Time (WCET)

Worst-Case Execution Time (WCET) is an upper bound on the time a task may require to complete under specified assumptions about the processor, memory, input conditions and execution environment.

WCET analysis is important because hard real-time systems must be designed for the worst permitted execution conditions, not only average execution time.

Example:

A task has the following execution measurements:

  • Typical execution time = 2 ms
  • Measured maximum in testing = 3 ms
  • Established WCET upper bound = 4 ms
  • Relative deadline = 6 ms

The 4 ms WCET bound is below the 6 ms deadline. However, the task is not proven schedulable from this comparison alone if other tasks, interrupts, blocking or scheduling overhead can interfere.

9. Timing Analysis and Schedulability

Schedulability analysis determines whether a set of tasks can meet their deadlines under a specified scheduling algorithm and workload model.

CPU Utilization

For independent periodic tasks on a single processor, with execution time \(C_i\) and period \(T_i\):

\[ U = \sum_{i=1}^{n}\frac{C_i}{T_i} \]

Here, \(U\) represents the fraction of processor capacity required by the periodic tasks.

Example

Consider two periodic tasks:

Task Execution Time Period
Task 1 2 ms 10 ms
Task 2 3 ms 15 ms

\[ U = \frac{2}{10}+\frac{3}{15} \]

\[ U = 0.2+0.2=0.4 \]

CPU utilization = 40%.

This calculation alone does not establish schedulability. The scheduling policy, deadlines, blocking and other overheads must also be considered.

10. Interrupt Handling in Hard Real-Time Systems

Interrupts allow the processor to respond to hardware events. Their handling must be predictable because interrupt processing can delay other tasks.

Design Guidelines

  • Keep interrupt service routines short.
  • Use appropriate interrupt priorities.
  • Minimize interrupt masking time.
  • Defer lengthy processing to tasks when appropriate.
  • Analyze interrupt interference during timing analysis.
  • Ensure shared resources are accessed safely.

11. Examples of Hard Real-Time Applications

Application Critical Operation Timing Importance
Aircraft Flight Control Flight-control calculations and actuator commands. Late control action may compromise safety.
Automotive Safety Controller Time-critical safety response. Late response may be unacceptable.
Industrial Protection Emergency shutdown. Must meet specified protection time.
Robotic Control Time-critical motion coordination. Late control updates may affect safe operation.
Medical Control Equipment Time-critical device control. Depends on the specific clinical safety requirement.

12. Design Challenges

Hard real-time system development requires careful planning and verification.

  • Determining reliable WCET bounds.
  • Managing task priorities and deadlines.
  • Handling interrupt interference.
  • Controlling priority inversion and blocking.
  • Managing limited memory and processor resources.
  • Preventing race conditions and deadlocks.
  • Testing worst-case operating conditions.
  • Providing safe fault recovery.

13. Lesson Summary

  • Hard real-time systems have strict critical deadlines.
  • Missing a critical deadline is considered a system failure.
  • Timing predictability and bounded execution are essential.
  • WCET is an important input to timing analysis.
  • Scheduling analysis helps determine whether tasks can meet their deadlines.
  • Interrupt latency and resource blocking affect task response time.
  • An RTOS provides useful services but does not automatically guarantee hard real-time operation.
