Characteristics of Real-Time Systems

Chapter 01 | Lesson 02

Understanding the properties of predictable and time-constrained computing systems

Home Chapter Index RTOS Course

1. Introduction

A real-time system is designed to perform operations within specified timing constraints. Its correctness depends on both the accuracy of computation and the time taken to produce the result.

To satisfy real-time requirements, such systems must exhibit certain characteristics such as determinism, predictability, bounded response time, reliability, concurrency and efficient resource management.

Core Concept: A real-time system must provide the required response within its specified timing constraints, even under defined operating conditions and expected system load.

2. Determinism

Determinism refers to the ability of a system to produce predictable behavior under the same defined conditions.

In real-time computing, deterministic behavior is particularly important because tasks must execute within known timing bounds.

Example

Consider an embedded controller that samples a temperature sensor every 10 milliseconds. A deterministic implementation should maintain the required sampling schedule within its specified timing tolerance.

If sampling intervals vary significantly and unpredictably, the system may fail to satisfy its control requirements.

Important Points

  • Predictable execution behavior.
  • Controlled task scheduling.
  • Bounded interrupt response.
  • Known timing behavior under defined conditions.

3. Predictability

Predictability means that the system's timing and functional behavior can be analyzed and estimated before deployment.

A predictable system allows designers to determine whether important tasks can complete before their deadlines.

Example: Motor Control

A motor controller must process feedback and update its control output within a specified interval. Engineers analyze task execution time, interrupt interference and scheduling delays to determine whether the timing requirement can be satisfied.

4. Deadline Constraints

A deadline is the time by which a task or operation must complete.

Real-time applications are designed around deadlines because late results may lose their usefulness or cause unsafe behavior.

Types of Deadline

  • Hard deadline: Missing the deadline is considered a system failure.
  • Soft deadline: Missing the deadline reduces the quality or usefulness of the result.
  • Firm deadline: A result completed after its deadline has no value, although an occasional missed deadline may not cause total system failure.
Example:

An airbag deployment controller has strict timing requirements. A late deployment may be ineffective. A video streaming application may tolerate occasional late frames, although playback quality can decrease.

5. Bounded Response Time

Response time is the elapsed time between the release of a task and its completion.

A real-time system should have a known upper bound on response time for tasks with critical timing requirements.

Response Time:

Response Time = Completion Time − Release Time

Example

A task is released at 5 ms and completes at 8 ms.

  • Release time = 5 ms
  • Completion time = 8 ms
  • Response time = 3 ms

If the task deadline is 5 ms after release, it completes within the required time.

6. Reliability and Availability

Reliability is the ability of a system to perform its required functions correctly for a specified period under stated conditions.

Availability describes the proportion of time that a system is operational and ready to provide its required service.

Reliability Techniques

  • Fault detection and error handling.
  • Watchdog timer mechanisms.
  • Redundant components where required.
  • Safe-state transitions.
  • Recovery and restart procedures.
  • System monitoring and diagnostics.
Note: Reliability and availability are related but different properties. A system may recover quickly after failures and therefore have high availability even if occasional failures occur.

7. Responsiveness

Responsiveness refers to how quickly a system reacts to an event or input.

A real-time controller must respond appropriately to events such as sensor changes, hardware interrupts, communication requests and fault conditions.

Example: Overcurrent Protection

  1. A current sensor detects excessive current.
  2. The controller receives the sensor event.
  3. The protection task processes the event.
  4. The controller issues a shutdown command.

The complete response must satisfy the protection system's specified timing requirement.

8. Concurrency and Multitasking

Real-time embedded systems often need to perform several operations during overlapping time intervals.

Examples include sensor monitoring, communication, display updates and motor control.

An RTOS can organize these operations into independent tasks and manage their execution through scheduling.

Example: Embedded Monitoring System

Task Responsibility
Sensor Task Collects sensor readings.
Processing Task Analyzes the collected data.
Communication Task Sends status information through UART.
Control Task Updates the system output.

9. Resource Management

Real-time systems have limited resources such as CPU time, RAM, memory bandwidth, communication interfaces and peripheral devices.

These resources must be managed carefully so that tasks can execute without unacceptable delays or interference.

Common Resource Management Techniques

  • Priority-based task scheduling.
  • Mutexes for shared resource protection.
  • Semaphores for synchronization and event signaling.
  • Queues for inter-task communication.
  • Static memory allocation where appropriate.
  • Controlled interrupt processing.

10. Low Latency and Low Jitter

Latency

Latency is the delay between an event and the corresponding system response.

Jitter

Jitter is the variation in the timing of an event or task execution across repeated occurrences.

Example: Periodic Sensor Sampling

A sensor task is intended to execute every 10 ms.

Sampling Event Actual Execution Time
1 0 ms
2 10 ms
3 20.5 ms
4 30 ms

The third sampling event occurs 0.5 ms later than the ideal schedule. This timing variation is an example of jitter.

11. Efficient Interrupt Handling

Interrupts allow a processor to respond to important events without continuously polling every peripheral.

In real-time systems, interrupt handling must be designed carefully to reduce latency and avoid unnecessary blocking.

  • Keep interrupt service routines short.
  • Acknowledge interrupt sources correctly.
  • Defer lengthy processing to tasks where appropriate.
  • Use suitable interrupt priorities.
  • Avoid unsafe shared-data access.

12. Stability and Fault Handling

A real-time system should continue to operate safely when it encounters expected disturbances or recoverable faults.

Examples include communication errors, sensor failures, task execution delays, memory allocation failures and unexpected external events.

Fault handling may include:

  • Error detection and reporting.
  • Retry mechanisms.
  • Fallback operating modes.
  • Watchdog-triggered recovery.
  • Transition to a defined safe state.

13. Summary of Real-Time System Characteristics

Characteristic Description Importance
Determinism Predictable behavior under defined conditions. Timing consistency.
Predictability Timing behavior can be analyzed. Deadline planning.
Deadline Constraints Tasks must complete within specified limits. Timely results.
Bounded Response Known upper limit on response time. Timing assurance.
Reliability Correct operation under stated conditions. Dependable operation.
Responsiveness Appropriate reaction to events. Event handling.
Concurrency Management of overlapping activities. Multitasking.
Low Jitter Limited variation in timing. Consistent periodic behavior.

14. Lesson Summary

  • Determinism and predictability are essential for timing analysis.
  • Deadlines define when important operations must complete.
  • Bounded response time helps establish timing guarantees.
  • Reliability and availability support dependable operation.
  • Responsiveness determines how effectively the system handles events.
  • Concurrency enables multiple application activities to be managed.
  • Latency and jitter influence real-time performance.
  • Efficient interrupt handling and resource management are important for predictable behavior.
