Firm Real-Time Systems

Chapter 01 | Lesson 06

Understanding deadlines, result validity and time-sensitive processing

Home Chapter Index RTOS Course

1. Introduction

A Firm Real-Time System is a real-time computing system in which a result has value only if it is delivered before its specified deadline.

An occasional deadline miss may be tolerated by the system, but a result delivered after its deadline is considered useless for the intended operation.

Unlike a hard real-time system, an occasional missed deadline does not necessarily mean that the entire system has failed. Unlike a soft real-time system, however, a late result generally has no useful value.

Fundamental Definition: A firm real-time system allows occasional deadline misses, but a result completed after its deadline loses its usefulness and should not be used for the intended operation.

2. Characteristics of Firm Real-Time Systems

1. Defined Deadlines

Each time-sensitive task has a specified completion deadline.

2. Late Results Are Useless

A result delivered after its deadline is considered obsolete or invalid for the intended operation.

3. Occasional Deadline Misses Are Tolerated

A limited number of deadline misses may be acceptable at the system level, depending on the application requirements.

4. Freshness of Data Is Important

The system must process current information. Old results may no longer represent the actual state of the system.

5. Obsolete Work Can Be Discarded

If a task completes too late, its result can be discarded instead of being delivered to the application.

6. System-Level Performance Requirements

The system may specify an acceptable deadline-miss ratio or maximum number of missed deadlines over a defined observation period.

3. Understanding Firm Deadlines

A deadline defines the latest acceptable completion time for a task. In a firm real-time system, the result is useful only when it is completed within that time.

Example

Consider a monitoring application that generates a measurement result every 100 milliseconds.

Parameter Value
Task Release Time 0 ms
Relative Deadline 100 ms
Expected Completion 80 ms
Actual Completion 120 ms

The task completes 20 milliseconds after its deadline. The generated result is therefore too late to be used for the intended 100-millisecond monitoring cycle.

Important: A firm deadline miss does not automatically mean that the complete system has failed. It means that the particular late result has lost its usefulness.

4. Firm Real-Time System Example

Example: Real-Time Object Tracking

Consider a computer vision system that detects and tracks moving objects using camera frames.

The system must process each frame before the next tracking update.

  • A camera captures a frame.
  • The processor analyzes the image.
  • The system calculates the object's position.
  • The tracking result is delivered before its deadline.

If the result arrives after the relevant tracking deadline, it may describe an outdated object position. The system can discard that result and process a newer frame.

Illustrative Scenario:
Frame Deadline Completion Result
Frame 1 30 ms 24 ms Useful
Frame 2 60 ms 55 ms Useful
Frame 3 90 ms 105 ms Obsolete
Frame 4 120 ms 115 ms Useful

5. Firm Real-Time System Architecture

A firm real-time system contains components that acquire data, process time-sensitive tasks and deliver results within specified deadlines.

Hardware Components

  • Microcontroller or processor.
  • Camera, sensor or data acquisition interface.
  • Memory and storage.
  • Hardware timers.
  • Communication interfaces.
  • Display or control output devices.

Software Components

  • Data acquisition tasks.
  • Processing tasks.
  • Task scheduler.
  • Communication and synchronization services.
  • Deadline monitoring logic.
  • Obsolete-result detection and discard logic.

6. Handling Deadline Misses

A firm real-time system must define what happens when a task cannot complete before its deadline.

Common Handling Techniques

  • Discard Late Results: Prevents obsolete data from being used.
  • Skip Obsolete Jobs: Avoids spending resources on work that is no longer useful.
  • Process New Data: Gives preference to more recent information.
  • Deadline Monitoring: Detects tasks that exceed their permitted execution window.
  • Task Prioritization: Gives important tasks appropriate scheduling priority.
  • Performance Monitoring: Tracks the frequency of deadline misses.

7. Role of RTOS in Firm Real-Time Systems

An RTOS can provide task scheduling, timers, synchronization and communication services that help implement firm real-time applications.

Important RTOS Services

  • Priority-based task scheduling.
  • Preemptive task execution.
  • Task delay and periodic execution.
  • Message queues for data transfer.
  • Semaphores and mutexes for synchronization.
  • Software timers for deadline monitoring.
Design Consideration: An RTOS does not automatically discard late results. The application must implement deadline checks, stale-data detection and appropriate recovery policies.

8. Firm Real-Time vs Hard Real-Time Systems

Parameter Hard Real-Time Firm Real-Time
Deadline Strict critical deadline. Defined deadline.
Late Result Failure of the required critical service. Useless for its intended operation.
Deadline Miss Not permitted for critical tasks. May be tolerated occasionally.
System-Level Effect May cause system or safety failure. May reduce service quality or lose an individual result.
Example Critical flight-control operation. Time-sensitive object tracking.

9. Firm Real-Time vs Soft Real-Time Systems

Parameter Firm Real-Time Soft Real-Time
Late Result Generally useless. May still be useful.
Deadline Miss Occasional misses may be tolerated. Occasional misses may be tolerated.
Performance Effect Loss of the individual result. Reduced quality or performance.
Data Freshness Very important. Important, but late data may retain some value.
Example Time-sensitive object tracking. Video streaming.

10. Performance Metrics

Firm real-time applications can be evaluated using several timing and reliability metrics.

  • Deadline-Miss Ratio: Percentage of jobs that miss their deadlines.
  • Response Time: Time between task release and completion.
  • Data Freshness: How current the processed information is.
  • Throughput: Number of useful results processed per unit time.
  • Task Execution Time: Time required to execute a task.
  • Discarded-Result Count: Number of results rejected because they arrived too late.
Deadline-Miss Ratio: \[ \text{Miss Ratio} = \frac{\text{Missed Jobs}}{\text{Total Jobs}} \] Useful-Result Ratio: \[ \text{Useful Ratio} = \frac{\text{On-Time Useful Results}}{\text{Total Jobs}} \]

11. Applications of Firm Real-Time Systems

Application Operation Reason for Deadline
Object Tracking Calculate object position from camera frames. Late position data may be obsolete.
Radar Data Processing Process time-sensitive detection results. Old detections may no longer be useful.
Sensor Monitoring Generate periodic measurement results. Old measurements may not represent current conditions.
Industrial Inspection Analyze products on a moving production line. A late inspection result may miss the relevant item.
Multimedia Analysis Process time-sensitive media data. Obsolete analysis results may be discarded.

These are illustrative application patterns. Whether a specific implementation is firm, soft or hard real-time depends on its actual deadline and failure requirements.

12. Advantages and Limitations

Advantages

  • Supports applications requiring fresh and timely results.
  • Allows occasional deadline misses without requiring total system failure.
  • Prevents obsolete results from being used.
  • Supports efficient processing of continuously arriving data.
  • Can prioritize current and useful tasks.

Limitations

  • Missed deadlines result in lost processing work.
  • Frequent deadline misses reduce useful throughput.
  • Deadline monitoring adds implementation complexity.
  • Discarding results may affect application quality.
  • Timing analysis is still necessary to control deadline misses.

13. Lesson Summary

  • Firm real-time systems require results before specified deadlines.
  • Late results are useless for their intended operation.
  • Occasional deadline misses may be tolerated at the system level.
  • Obsolete results should be discarded rather than used.
  • Data freshness and deadline-miss ratio are important performance measures.
  • Object tracking and time-sensitive sensor processing are useful examples.
  • Application-level logic is needed to detect and handle missed deadlines.

Activity: Analyze a Firm Real-Time Sensor Processing System

A sensor-processing application generates one result every 50 milliseconds. Consider the following data:

Job Release Time Deadline Completion Time
Job 1 0 ms 50 ms 35 ms
Job 2 50 ms 100 ms 110 ms
Job 3 100 ms 150 ms 140 ms
Job 4 150 ms 200 ms 215 ms

Perform the following tasks:

  1. Identify which jobs meet their deadlines.
  2. Identify which results should be discarded.
  3. Calculate the deadline-miss ratio.
  4. Calculate the useful-result ratio.
  5. Suggest a strategy for processing newer sensor data.
Interview Tip: The key distinction is that a firm real-time system tolerates an occasional missed deadline at the system level, but the result of the late task is no longer useful. A soft real-time system may still use a late result, although its quality or value may be reduced.
