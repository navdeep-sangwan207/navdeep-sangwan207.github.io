2. Introduction

A finite state machine (FSM) can be represented using two common methods:

  1. State Diagram
  2. State Table

Both representations describe how a digital system changes from one state to another depending on its input conditions.

A state diagram provides a graphical representation of an FSM, whereas a state table provides a tabular representation of its state transitions and outputs.

3. What Is a State Diagram?

A state diagram is a graphical representation of a finite state machine. It shows all possible states and the transitions between those states.

Symbols Used in State Diagrams

  • Circle: Represents a state.
  • Arrow: Represents a state transition.
  • Arrow label: Represents the input condition and, in a Mealy machine, the output.
  • Initial arrow: Indicates the reset or initial state.

Example: Two-State Machine

Consider an FSM with two states:

  • S0: Initial state.
  • S1: Second state.

In this example, the input conditions determine whether the machine moves from S0 to S1 or returns to S0.

4. Types of State Diagram Notation

1. Moore Machine State Diagram

In a Moore machine, the output is associated with the state. The output is normally written inside the state circle.

2. Mealy Machine State Diagram

In a Mealy machine, the output is associated with the transition. The transition label is generally written as:

Input / Output

For example, 1/0 means input 1 produces output 0 during that state transition.

5. What Is a State Table?

A state table is a tabular representation of an FSM. It shows:

  • Present state.
  • Input combination.
  • Next state.
  • Output.

General State Table Structure

Present State Input Next State Output
S0 0 S0 0
S0 1 S1 0
S1 0 S0 1
S1 1 S1 1

The table above is an illustrative example of a Mealy machine. Each row defines the next state and output for a particular present state and input.

6. Difference Between State Diagram and State Table

State Diagram State Table
Graphical representation. Tabular representation.
Uses circles and arrows. Uses rows and columns.
Shows state transitions visually. Lists all state transitions systematically.
Useful for understanding FSM behaviour. Useful for deriving logic equations.
Can become complex for large FSMs. Can become lengthy for large FSMs.

7. Steps for Designing an FSM

A systematic FSM design process generally follows these steps:

  1. Understand the required system behaviour.
  2. Identify the input and output signals.
  3. Define all required states.
  4. Determine the transition conditions.
  5. Draw the state diagram.
  6. Prepare the state table.
  7. Assign binary codes to the states.
  8. Select the required flip-flops.
  9. Derive next-state and output logic equations.
  10. Implement and verify the circuit.
The state diagram and state table should describe exactly the same machine. The state table is then used to derive the required combinational logic.

Step 5: Derive the Next-State Equation

From the state table:

  • When Q = 0 and X = 0, next state is 0.
  • When Q = 0 and X = 1, next state is 1.
  • When Q = 1, next state remains 1 for either input.
Q(next) = Q + X

This equation describes the next-state logic for the designed two-state machine.

Step 6: Implement Using a D Flip-Flop

For a D flip-flop:

Q(next) = D

Therefore, connect the D input to the next-state expression:

D = Q + X

At each active clock edge, the flip-flop stores the value of Q OR X.

A reset circuit or reset input must initialise the state register to S0 (Q=0) before normal operation.

9. State Assignment and Encoding

State assignment means allocating binary codes to the symbolic states of an FSM.

For N states, the minimum number of flip-flops required for binary encoding is:

n = ⌈log₂ N⌉

Example: Six-State FSM

For six states:

n = ⌈log₂ 6⌉ = 3 flip-flops

Three flip-flops provide eight possible binary combinations. Six combinations are assigned to the six states; the remaining combinations are unused and should be handled safely.

10. Deriving Logic from a State Table

After preparing the state table, the next-state equations can be derived using Boolean algebra or Karnaugh maps.

The general process is:

  1. Assign binary codes to all states.
  2. Identify the present-state bits.
  3. Identify the next-state bits for every input combination.
  4. Prepare a truth table for each next-state bit.
  5. Simplify each Boolean expression.
  6. Implement the expressions using logic gates and flip-flops.
Unused state combinations must not automatically be treated as don't-care conditions. Their behaviour should be selected deliberately, especially when safe recovery from an invalid state is important.

11. Practical FSM Design Using Embedded C

The same state-based approach can be implemented in embedded C using an enumeration and switch-case statement. 

#include <stdio.h>

typedef enum
{
    STATE_S0,
    STATE_S1
} State;

int main(void)
{
    State currentState = STATE_S0;
    int inputX = 1;

    switch (currentState)
    {
        case STATE_S0:

            if (inputX == 1)
            {
                currentState = STATE_S1;
            }

            break;

        case STATE_S1:

            if (inputX == 0)
            {
                currentState = STATE_S1;
            }

            break;

        default:

            currentState = STATE_S0;
            break;
    }

    printf("Current State: %d\n", currentState);

    return 0;
}

This is a basic software illustration of state-based control. A complete embedded FSM would normally read real input signals, update its state periodically or on events, and control hardware outputs.
