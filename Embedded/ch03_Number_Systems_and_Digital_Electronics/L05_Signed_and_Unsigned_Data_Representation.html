Lesson 05: Signed and Unsigned Data Representation

Understand how computers represent positive and negative integers, interpret binary values, calculate data ranges and handle integer overflow in embedded systems.

1. Introduction

Digital systems store data as binary bits. A group of bits can represent different types of information, including numbers, characters and instructions.

When representing integer values, two common categories are:

  • Unsigned integers: Represent zero and positive values only.
  • Signed integers: Represent both negative and positive values, including zero.

The same binary bit pattern can represent different numerical values depending on whether it is interpreted as signed or unsigned.

2. Unsigned Number Representation

In unsigned representation, all bits are used to represent the magnitude of a number.

There is no sign bit. Every bit contributes a non-negative positional value.

Example: 8-bit unsigned number

Binary: 00000101

= 0×128 + 0×64 + 0×32 + 0×16
  + 0×8 + 1×4 + 0×2 + 1×1

= 4 + 1
= 5

Therefore, 00000101 represents decimal 5.

Maximum unsigned value

For n bits, the maximum unsigned value is:

2n − 1

The complete range is:

0 to 2n − 1

3. Signed Number Representation

Signed representation allows a binary value to represent negative as well as non-negative numbers.

Modern general-purpose processors and microcontrollers commonly use two's complement representation for signed integers.

In a two's complement representation:

  • MSB = 0 indicates a non-negative value.
  • MSB = 1 indicates a negative value.

Example: 8-bit signed values

00000101 = +5
11111011 = -5

The second value is obtained by taking the 8-bit two's complement of 00000101.

The MSB is a sign indicator when the bit pattern is interpreted as a signed two's complement integer. It is still an ordinary data bit when interpreted as unsigned.

5. Understanding the Most Significant Bit (MSB)

The Most Significant Bit is the leftmost bit in a binary number. Its interpretation depends on the number representation.

Example: Binary 11111111

InterpretationDecimal value
Unsigned 8-bit255
Signed 8-bit two's complement−1

Thus, the same eight bits can represent 255 or −1.

Why?

For unsigned interpretation, every bit has a positive positional weight.

For signed two's complement interpretation, the MSB has a negative weight.

For an n-bit two's complement value:

Value = −bn−1 × 2n−1 + Σ bi × 2i

where the remaining bits contribute their ordinary positive positional weights.

7. Signed and Unsigned Addition

The underlying binary addition operation can be identical for signed and unsigned values. However, the interpretation of the result and the overflow conditions differ.

Example: 8-bit addition

  00000101  (5)
+ 00000011  (3)
----------
  00001000  (8)

The result is 8 in both signed and unsigned interpretations.

Example: 8-bit addition producing carry

  11111111
+ 00000001
----------
1 00000000

For 8-bit unsigned arithmetic, the mathematical result is 256. The lower 8 bits are 00000000 and the carry out is 1.

For fixed-width signed interpretation, this operation represents −1 + 1 = 0. The lower 8 bits correctly represent zero.

8. Integer Overflow

Integer overflow occurs when an arithmetic result is outside the range representable by the selected integer type or bit width.

Unsigned overflow example

For an 8-bit unsigned number, the maximum value is 255.

255 + 1 = 256

8-bit result:
00000000

Carry out:
1

The mathematical result cannot fit in an 8-bit unsigned value.

Signed overflow example

For an 8-bit signed two's complement number, the maximum value is +127.

  01111111  (+127)
+ 00000001  (+1)
----------
  10000000  (-128 when interpreted as signed)

The mathematical result is +128, which is outside the 8-bit signed range. Signed overflow has occurred.

In C, unsigned integer arithmetic is defined modulo 2n for an n-bit unsigned type. Signed integer overflow in standard C is undefined behavior; do not rely on wraparound for signed values.

9. Integer Underflow

Underflow occurs when a result falls below the minimum value representable by the selected type.

Example: 8-bit unsigned subtraction

0 - 1

8-bit unsigned result:
11111111

Unsigned interpretation:
255

Unsigned arithmetic wraps modulo 256 in this example.

Example: Signed underflow

For an 8-bit signed value, the minimum is −128.

-128 - 1

The mathematical result is −129, which cannot be represented in an 8-bit signed two's complement value.

10. Signed and Unsigned Data Types in Embedded C

Embedded C programs use integer types to store measurements, counters, flags and calculated values.

Common standard integer types include:

TypeTypical use
uint8_t8-bit unsigned value
int8_t8-bit signed value
uint16_t16-bit unsigned value
int16_t16-bit signed value
uint32_t32-bit unsigned value
int32_t32-bit signed value

These exact-width types are defined in the standard header file stdint.h, when the implementation supports the requested widths.

Example: Signed and unsigned variables

#include <stdint.h>

int main(void)
{
    uint8_t unsigned_value = 200;
    int8_t signed_value = -50;

    uint16_t result_a;
    int16_t result_b;

    result_a = unsigned_value + 20;
    result_b = signed_value + 20;

    while (1)
    {
        /* Inspect variables in the debugger */
    }
}

Expected values:

unsigned_value = 200
signed_value   = -50

result_a       = 220
result_b       = -30

11. Type Conversion: Signed and Unsigned

Type conversion occurs when a value of one integer type is converted to another type.

Conversions between signed and unsigned types require care because the numerical interpretation can change.

Example: Same bit pattern, different interpretation

uint8_t u = 255;
int8_t  s = -1;

On a typical two's complement embedded target, both values have the bit pattern:

11111111

But:

  • u is interpreted as 255.
  • s is interpreted as −1.

Example: Integer promotion and mixed signedness

#include <stdint.h>

int main(void)
{
    int8_t a = -1;
    uint8_t b = 1;

    int result = a + b;

    while (1)
    {
        /* Inspect result */
    }
}

For this example, both 8-bit operands are promoted to int on common embedded C implementations where int can represent all values of uint8_t. The result is 0.

The C language applies integer promotions and the usual arithmetic conversions before performing many arithmetic operations. Always check the types of operands, especially when mixing signed and unsigned values.

13. Practical Embedded Systems Example: ADC Data

Suppose a microcontroller uses a 10-bit ADC. Its output range is:

0 to 1023

An unsigned integer is suitable for storing the raw ADC conversion code because the code is non-negative.

#include <stdint.h>

int main(void)
{
    uint16_t adc_value = 512;

    while (1)
    {
        /* Inspect adc_value in the debugger */
    }
}

Expected result:

adc_value = 512
Binary    = 10 0000 0000
10-bit    = 1000000000

However, if an application converts a sensor reading into a signed temperature or calibration offset, a signed type may be appropriate.

14. Common Mistakes

  • Assuming the same binary pattern always has the same decimal value.
  • Using an unsigned type to store negative measurements.
  • Using a signed type when the complete unsigned range is required.
  • Ignoring integer promotion in C expressions.
  • Mixing signed and unsigned operands without checking conversion rules.
  • Assuming signed overflow wraps around in C.
  • Ignoring the range limits of small integer types.
  • Choosing a data type without considering the maximum possible sensor or counter value.

15. Interview Questions and Answers

Q1. What is the difference between signed and unsigned data?

Unsigned data represents non-negative values, while signed data represents negative and non-negative values.

Q2. What is the range of an 8-bit unsigned integer?

0 to 255.

Q3. What is the range of an 8-bit signed two's complement integer?

−128 to +127.

Q4. What does the MSB indicate in a signed two's complement number?

It indicates the sign: 0 for non-negative and 1 for negative values.

Q5. Can the same binary pattern represent different values?

Yes. For example, 11111111 represents 255 as an 8-bit unsigned value and −1 as an 8-bit signed two's complement value.

Q6. What is integer overflow?

It occurs when an arithmetic result is outside the representable range of the selected integer type.

Q7. What happens when an 8-bit unsigned value 255 is incremented by 1?

Unsigned 8-bit arithmetic wraps to 0, with a carry beyond the 8-bit width.

Q8. Is signed integer overflow defined to wrap around in C?

No. Signed integer overflow in standard C is undefined behavior.

Q9. Which type is suitable for a raw 10-bit ADC result?

An unsigned integer type capable of storing values from 0 to 1023, such as uint16_t.

Q10. Why should signed and unsigned values not be mixed carelessly?

Because integer conversions can change how values are interpreted and can produce unexpected comparisons or arithmetic results.

18. Lesson Summary

  • Unsigned integers represent zero and positive values.
  • Signed integers represent negative and non-negative values.
  • Modern embedded processors commonly use two's complement signed representation.
  • An n-bit unsigned range is 0 to 2n − 1.
  • An n-bit signed two's complement range is −2n−1 to 2n−1 − 1.
  • The same binary pattern can represent different signed and unsigned values.
  • Overflow occurs when a result cannot be represented in the selected type.
  • Standard C defines unsigned wraparound but does not define signed overflow to wrap.
  • Correct type selection is essential in embedded software.
