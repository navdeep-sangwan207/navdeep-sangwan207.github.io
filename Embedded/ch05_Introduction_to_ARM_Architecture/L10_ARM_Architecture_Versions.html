1. Introduction to ARM Architecture Evolution

ARM architecture has evolved through multiple versions to support increasing processing requirements, improved performance, larger memory spaces, enhanced security and different embedded and computing applications.

The early ARM processors were designed around relatively simple and efficient RISC principles. Later architectures introduced additional instructions, improved exception handling, memory management, virtualization and support for 64-bit processing.

ARM architecture evolution can be understood by studying its architecture versions and the processor families that implement them.

Important for this course: The LPC2129 uses the ARM7TDMI-S core, which implements the ARMv4T architecture. Understanding ARMv4T provides the foundation for studying its registers, instruction set, interrupts and programming model.

2. What Is an ARM Architecture Version?

An ARM architecture version defines the instruction set, programmer-visible behavior, processor operating features and other architectural capabilities supported by compatible processor implementations.

Examples include ARMv4, ARMv4T, ARMv5TE, ARMv6, ARMv7 and ARMv8.

Architecture vs Processor Core

Later ARM architecture generations

Each generation introduced architectural changes and additional capabilities. Not every processor implements every feature of its architecture family.

4. ARMv4 and ARMv4T

4.1 ARMv4

ARMv4 is an earlier ARM architecture generation that provides the foundation for several classic ARM processors.

4.2 ARMv4T

ARMv4T introduced support for the Thumb instruction set alongside the existing 32-bit ARM instruction set.

Important features include:

  • 32-bit ARM instructions.
  • Original 16-bit Thumb instructions.
  • ARM and Thumb execution states.
  • Branch and exchange support through BX.
  • Classic ARM processor operating modes and exception model.
ARM7TDMI-S is an important ARMv4T processor implementation. It supports both ARM and original Thumb instruction sets.

5. ARMv5 and ARMv5TE

ARMv5 introduced further architectural improvements and additional instruction capabilities. ARMv5TE added enhancements aimed at improving performance in applications involving signal processing and multimedia.

Important Features

  • Enhanced instruction-set capabilities.
  • Improved support for DSP-oriented operations in applicable implementations.
  • Additional multiply and arithmetic capabilities.
  • Architecture support for processors such as ARM9E-family designs.
ARM926EJ-S is an example of a processor core implementing ARMv5TEJ. It includes additional features beyond the ARM7TDMI-S architecture.

6. ARMv6 Architecture

ARMv6 introduced architectural enhancements for more advanced embedded and application-processing requirements.

Important Features

  • Enhanced instruction-set capabilities.
  • Improved memory-system features.
  • Support for additional media-processing instructions in applicable profiles.
  • Improvements for more advanced processor implementations.

ARM11-family processors are associated with ARMv6-era architectural implementations.

7. ARMv7 Architecture

ARMv7 represents a major architectural generation used in many embedded, real-time and application-processing systems. It introduced three important architecture profiles.

ProfilePurposeExample applications
ARMv7-AApplication processorsSmartphones, tablets and general-purpose computing
ARMv7-RReal-time processorsAutomotive and industrial control
ARMv7-MMicrocontroller processorsEmbedded control and low-power devices

ARMv7-A

  • Designed for application-processing systems.
  • Supports sophisticated operating-system environments.
  • Used in many Cortex-A processor implementations.

ARMv7-R

  • Designed for real-time processing.
  • Used in safety-critical and deterministic applications.
  • Implemented by applicable Cortex-R processors.

ARMv7-M

  • Designed for microcontroller applications.
  • Supports interrupt-driven embedded systems.
  • Implemented by Cortex-M3 and Cortex-M4 processor cores.

8. ARMv8 Architecture

ARMv8 introduced a major architectural transition by providing support for 64-bit execution through AArch64, while retaining AArch32 support in applicable architecture profiles.

Important Features

  • 64-bit execution state called AArch64.
  • 32-bit execution state called AArch32 in applicable profiles.
  • Expanded general-purpose register organization in AArch64.
  • Enhanced memory-management and security capabilities.
  • Support for advanced application-processing systems.
Do not assume that every ARMv8 processor supports both AArch64 and AArch32. Support depends on the architecture profile and specific processor implementation.

10. ARM Processor Families

ARM processor families are designed for different performance, power and application requirements.

10.1 ARM7 Family

  • Classic ARM processor family.
  • Includes ARM7TDMI and ARM7TDMI-S.
  • Uses a three-stage pipeline in ARM7TDMI-S.
  • Supports ARM and Thumb states.
  • Used in earlier embedded microcontrollers.

10.2 ARM9 Family

  • Offers more advanced processing capabilities than ARM7 designs.
  • Commonly associated with a five-stage pipeline in classic ARM9 implementations.
  • Used in embedded systems and application-oriented devices.
  • Specific architecture versions depend on the individual core.

10.3 ARM11 Family

  • Associated with ARMv6-era architecture.
  • Provides more advanced processing capabilities.
  • Used in earlier mobile and multimedia systems.

10.4 Cortex Family

The Cortex family is organized into three major processor categories.

FamilyPurposeExamples
Cortex-AApplication processingCortex-A7, A9, A53
Cortex-RReal-time processingCortex-R4, R5, R52
Cortex-MMicrocontroller applicationsCortex-M0, M3, M4, M7

ARM7, ARM9 and ARM11 are processor families, while Cortex contains several different processor families. There is no single pipeline length or feature set that applies to every Cortex processor.

12. Cortex Processor Applications

Cortex-A: Application Processors

Cortex-A processors are used in systems requiring advanced application processing and operating-system support.

  • Smartphones and tablets.
  • Single-board computers.
  • Embedded Linux systems.
  • Multimedia and networking devices.

Cortex-R: Real-Time Processors

Cortex-R processors are designed for applications that need high reliability and predictable real-time response.

  • Automotive control systems.
  • Industrial automation.
  • Storage controllers.
  • Safety-related control applications.

Cortex-M: Microcontroller Processors

Cortex-M processors are designed for embedded control applications and are widely used in microcontrollers.

  • Sensor systems.
  • Consumer electronics.
  • Motor control.
  • IoT devices.
  • Industrial embedded systems.

13. ARMv4T and LPC2129 Relationship

The LPC2129 is based on the ARM7TDMI-S core, which implements ARMv4T. This means its processor capabilities must be understood according to ARMv4T rather than newer ARM architecture generations.

ComponentDescription
MicrocontrollerNXP LPC2129

ArchitectureARMv4T

When writing assembly for LPC2129, use instructions and features supported by ARMv4T and the ARM7TDMI-S core. Do not use later instructions merely because they are available on modern Cortex processors.

14. Choosing an ARM Processor for an Application

Application requirementSuitable processor category
Basic embedded controlMicrocontroller-class processor such as ARM7 or Cortex-M
Low-power control systemCortex-M family, depending on requirements
Real-time controlCortex-R or an appropriate Cortex-M implementation
Embedded Linux systemSuitable Cortex-A application processor
Smartphone or tabletCortex-A application processor
Automotive safety-related controlSuitable safety-oriented Cortex-R or other qualified processor
Processor selection must also consider clock speed, memory, peripheral interfaces, power consumption, software ecosystem, safety requirements, cost and product lifecycle.

15. Common Mistakes

  • Confusing an ARM architecture version with a processor model.
  • Assuming every ARM7 processor implements exactly the same features.
  • Assuming ARMv4T supports every instruction found in later ARM versions.
  • Confusing ARM7 with Cortex-M.
  • Assuming every Cortex processor is 64-bit.
  • Assuming Cortex-A, Cortex-R and Cortex-M have identical purposes.
  • Assuming every ARMv8 implementation supports both AArch32 and AArch64.
  • Ignoring the exact architecture implemented by the target microcontroller.

16. Interview Questions and Answers

Q1. What is an ARM architecture version?

It defines the architectural features and programmer-visible behavior supported by compatible processor implementations.

Q2. Which architecture does ARM7TDMI-S implement?

ARMv4T.

Q3. What is the main feature introduced by ARMv4T?

Support for the original Thumb instruction set alongside ARM instructions.

Q4. What is ARMv7 divided into?

Application (A), Real-time (R) and Microcontroller (M) profiles.

Q5. What is the purpose of Cortex-A?

Application processing, including systems running sophisticated operating systems.

Q6. What is the purpose of Cortex-R?

Real-time processing in applications requiring predictable response and high reliability.

Q7. What is the purpose of Cortex-M?

Microcontroller and embedded control applications.

Q8. Which architecture family is associated with ARM11?

ARMv6-era architecture.

Q9. What is a major feature of ARMv8-A?

Support for AArch64 64-bit execution, along with AArch32 support in applicable implementations.

Q10. Which processor core is used in LPC2129?

ARM7TDMI-S.
