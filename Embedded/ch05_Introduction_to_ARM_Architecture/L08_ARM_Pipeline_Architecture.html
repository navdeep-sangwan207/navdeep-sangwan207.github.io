Chapter 05: Introduction to ARM Architecture

Topic: Instruction Pipeline, Three-Stage Execution and Pipeline Flow

1. Introduction to Instruction Pipelining

Instruction pipelining is a processor technique in which the execution of multiple instructions is overlapped by dividing instruction processing into separate stages.

Instead of completing one instruction entirely before starting the next instruction, the processor works on different stages of several instructions simultaneously.

The main objective of pipelining is to improve instruction throughput and make better use of processor hardware.

Important: ARM7TDMI-S uses a three-stage pipeline: Fetch, Decode and Execute.

Why Is Pipelining Needed?

  • Improves instruction throughput.
  • Overlaps instruction processing stages.
  • Reduces idle time in processor functional units.
  • Improves overall processor performance.

3. ARM7 Three-Stage Pipeline

The ARM7TDMI-S processor uses three basic instruction pipeline stages.

1. FETCH
→
2. DECODE
→
3. EXECUTE

Stage 1: Fetch

The processor retrieves an instruction from memory using the instruction address held by the program counter.

  • Generates or uses the instruction address.
  • Reads the instruction from memory.
  • Places the instruction into the pipeline.

Stage 2: Decode

The processor interprets the fetched instruction and determines what operation must be performed.

  • Identifies the instruction type.
  • Identifies source and destination registers.
  • Determines the required operation.
  • Prepares the control information for execution.

Stage 3: Execute

The processor performs the operation specified by the instruction.

  • Performs arithmetic or logical operations.
  • Calculates addresses for memory operations.
  • Performs data transfers.
  • Updates the destination register or relevant processor state.

4. ARM7 Pipeline Timing

Once the pipeline is filled, different instructions occupy different stages during the same clock cycle.

After the initial pipeline fill, an ideal pipeline can complete approximately one instruction per clock cycle.

Throughput versus latency: Pipelining improves instruction throughput, but it does not necessarily reduce the latency of an individual instruction. Each instruction still passes through the required stages.

5. Pipeline Filling and Pipeline Drain

5.1 Pipeline Filling

Pipeline filling is the initial period during which the processor places instructions into the pipeline stages.

In a three-stage pipeline, the first instruction reaches the execute stage in the third cycle in the simplified timing model.

5.2 Pipeline Drain

Pipeline drain refers to the process of allowing instructions already in the pipeline to complete before the pipeline becomes empty.

This concept is useful when understanding pipeline control, exceptions and changes in instruction flow.

For a simplified three-stage pipeline, the first two cycles are needed to fill the stages before the first instruction reaches execution.

6. Program Counter and Pipeline

The Program Counter (PC), also known as R15, provides the instruction address used by the processor.

Because instruction fetching overlaps with instruction execution, the visible PC value in ARM state does not always point to the instruction currently being executed.

For ARM7TDMI-S in ARM state, the PC commonly reads as the address of the current instruction plus 8 bytes due to the pipeline. In Thumb state, the corresponding visible value is commonly the current instruction address plus 4 bytes.

These PC offset rules are useful when studying ARM7 assembly, branch instructions, literal loads and PC-relative addressing. The exact interpretation depends on the instruction and architectural context.

7. Branch Instructions and Pipeline Flushing

A branch instruction changes the normal sequential flow of program execution.

When a branch is taken, instructions that were fetched from the old sequential instruction path may no longer be required. The processor must discard the inappropriate pipeline contents and fetch instructions from the branch target.

Example

    MOV R0, #10
    MOV R1, #20
    B   TARGET
    MOV R2, #30       ; Sequential instruction path

TARGET:
    MOV R3, #40

After the branch is taken, execution continues from TARGET rather than continuing through the next sequential instruction.

Branch operation
Sequential instruction fetch
↓
Branch instruction executed
↓
Pipeline contents invalidated
↓
Fetch from branch target
↓
Continue execution
Pipeline flush: A taken branch changes the instruction stream. The processor must refill the pipeline from the new target address. This creates a branch-related performance penalty.

8. Pipeline Hazards

A pipeline hazard is a condition that prevents an instruction from proceeding through its normal pipeline stage in the expected clock cycle.

8.1 Structural Hazard

A structural hazard occurs when multiple operations require the same hardware resource at the same time.

8.2 Data Hazard

A data hazard occurs when an instruction depends on the result of an earlier instruction that has not yet become available.

8.3 Control Hazard

A control hazard occurs when a branch or other control-flow instruction changes which instruction should be fetched next.

HazardCauseExample

These are general pipeline concepts. Do not assume that every hazard is handled identically in every ARM implementation. ARM7TDMI-S has its own specific pipeline and instruction execution behavior.

9. ARM7 Pipeline and ARM/Thumb States

ARM7TDMI-S supports both ARM and Thumb instruction sets. The processor can execute instructions in either state.

  • ARM state uses 32-bit instructions.
  • Thumb state uses 16-bit instructions in the original ARM7TDMI-S implementation.
  • The pipeline fetches instructions according to the current execution state.
  • Changing between ARM and Thumb state requires appropriate control-flow handling.
The ARM7TDMI-S processor supports the original Thumb instruction set. Do not confuse it with later Thumb-2 extensions available on newer ARM processors.

10. Advantages of ARM7 Pipelining

  • Improves instruction throughput.
  • Overlaps instruction fetch, decode and execution.
  • Uses processor resources more efficiently.
  • Supports efficient instruction processing.
  • Helps achieve better performance than a simple non-pipelined design.

Limitations

  • Branch instructions can cause pipeline flushing.
  • Data dependencies can affect instruction flow.
  • Pipeline control increases processor design complexity.
  • Memory wait states can reduce effective throughput.

11. Practical Relevance to LPC2129

The LPC2129 uses an ARM7TDMI-S processor core. Therefore, understanding its pipeline is useful when studying:

  • ARM assembly language execution.
  • Program counter behavior.
  • Branch and subroutine instructions.
  • Instruction timing and performance.
  • Interrupt and exception return behavior.
  • Debugging PC-relative instructions.

Keil uVision Simulator Exercise

  1. Create or open an ARM7TDMI-S assembly project.
  2. Write a short sequence of MOV instructions.
  3. Build the program and enter debug mode.
  4. Open the Disassembly and Registers windows.
  5. Use single-step execution to observe instruction addresses and register changes.
  6. Insert a branch instruction and inspect the new execution address.
  7. Compare the sequential instruction flow with the branch target flow.
The Keil simulator's visible register and pipeline information depends on the selected debugger and processor model. Single-step execution demonstrates program flow; it does not necessarily expose every internal pipeline stage or cycle.

12. Common Mistakes

  • Assuming pipelining executes all stages of one instruction simultaneously.
  • Confusing instruction throughput with instruction latency.
  • Assuming a branch always continues sequential execution.
  • Ignoring the pipeline refill after a taken branch.
  • Assuming the visible PC always points to the instruction currently executing.
  • Confusing the ARM7 three-stage pipeline with later ARM pipeline designs.
  • Assuming the Keil simulator displays every internal pipeline operation.

13. Interview Questions and Answers

Q1. What is instruction pipelining?

It is a technique that overlaps instruction processing stages to improve throughput.

Q2. How many pipeline stages are present in ARM7TDMI-S?

Three: Fetch, Decode and Execute.

Q3. What happens during the Fetch stage?

The processor reads an instruction from memory.

Q4. What happens during the Decode stage?

The processor interprets the instruction and determines the required operation.

Q5. What happens during the Execute stage?

The processor performs the operation specified by the instruction.

Q6. What is pipeline filling?

It is the initial process of placing instructions into the pipeline stages.

Q7. What is pipeline flushing?

It is the invalidation of instructions in the pipeline when the instruction flow changes.

Q8. Why does a branch affect pipeline performance?

The processor must fetch instructions from the new target address and refill the pipeline.

Q9. What is a data hazard?

It is a dependency in which an instruction requires data that is not yet available.

Q10. What is the ARM-state PC offset commonly observed in ARM7?

The visible PC value is commonly the current instruction address plus 8 bytes.

16. Lesson Summary

  • Pipelining overlaps different stages of instruction processing.
  • ARM7TDMI-S uses a three-stage pipeline.
  • The stages are Fetch, Decode and Execute.
  • Pipeline filling occurs when instructions enter the stages.
  • After filling, an ideal pipeline can complete approximately one instruction per cycle.
  • A taken branch changes the instruction flow and requires pipeline refill.
  • Pipeline hazards can affect normal instruction processing.
  • The visible PC value reflects the processor's pipeline behavior.
