Topic: ARM7TDMI-S Programmer's Register Set

1. Introduction

Registers are small, high-speed storage locations inside a processor. They temporarily hold data, addresses, instructions and processor control information during program execution.

The ARM7TDMI-S processor provides a programmer-visible register set consisting of 16 registers at a time, numbered R0 to R15. The exact physical register selected for some register numbers depends on the current processor mode.

The main registers are:

  • R0–R12: General-purpose registers.
  • R13: Stack Pointer (SP).
  • R14: Link Register (LR).
  • R15: Program Counter (PC).
  • CPSR: Current Program Status Register.
  • SPSR: Saved Program Status Register in exception modes.
Important: R0–R15 are the 16 general-purpose register numbers in the ARM programmer's model. CPSR and SPSR are separate status registers, not additional R0–R15 registers.

ARM7TDMI-S is a 32-bit processor core. Its general-purpose registers are 32 bits wide.

Registers are used to hold operands, intermediate results, memory addresses, return addresses and the instruction address.

3. General-Purpose Registers (R0–R12)

R0 through R12 are used for general data storage and processing. They can hold numbers, pointers, addresses and intermediate calculation results.

3.1 Registers R0–R3

These registers are commonly used to pass function arguments and hold temporary values under common ARM procedure calling conventions.

3.2 Registers R4–R11

These registers are often used for local variables and values that need to be preserved across function calls, depending on the procedure calling convention.

3.3 Register R12

R12 is also known as IP (Intra-Procedure-call scratch register) in common ARM calling conventions. It is often used as a temporary register.

4. Stack Pointer (R13 / SP)

R13 is commonly called the Stack Pointer (SP). It holds the address associated with the current top of the stack.

A stack is a memory area used to store temporary information such as function return addresses, saved registers and local data.

4.1 Stack Operations

Two important stack operations are:

  • PUSH: Places data onto the stack.
  • POP: Retrieves data from the stack.

4.2 Example

STMFD SP!, {R0, R1}
LDMFD SP!, {R0, R1}

The first instruction stores R0 and R1 on a full-descending stack. The second restores them.

ARM assembly supports several stack conventions. The full-descending stack is a common convention, but the stack configuration must match the program's chosen convention.

4.3 Banked Stack Pointers

ARM7TDMI-S provides separate banked R13 registers for User/System, FIQ, IRQ, Supervisor, Abort and Undefined modes. This allows each exception mode to have its own stack.

5. Link Register (R14 / LR)

R14 is known as the Link Register. It commonly stores the return address when a subroutine is called using the Branch with Link instruction.

5.1 Branch with Link (BL)

The BL instruction transfers control to a subroutine and saves a return address in LR. 

BL MY_FUNCTION

; Execution returns here after the function returns

MY_FUNCTION:
    ADD R0, R0, #1
    MOV PC, LR

In this simple ARM-state example, MOV PC, LR transfers control back to the address held in LR.

A function that makes another subroutine call must preserve its own return address if it still needs to return to its original caller. A single LR register cannot hold an unlimited chain of return addresses.

5.2 Banked Link Registers

Exception modes have banked R14 registers. This allows the processor to preserve exception return information separately from the ordinary User/System LR.

6. Program Counter (R15 / PC)

R15 is the Program Counter. It represents the instruction address used by the processor during instruction execution.

The processor updates the PC as instructions are fetched and control flow changes.

6.1 Branch Instructions

    MOV R0, #10
    B NEXT

    MOV R0, #20

NEXT:
    ADD R1, R0, #5

The B instruction changes the program flow by branching to the label NEXT.

6.2 PC in ARM State

In ARM state, reading R15 as an ordinary source operand generally returns the current instruction address plus 8 bytes due to the traditional three-stage pipeline behavior.

6.3 PC in Thumb State

In Thumb state, the corresponding visible PC value generally reflects the current instruction address plus 4 bytes, subject to instruction-specific alignment and architectural rules.

The visible PC value is not always identical to the address of the instruction currently being executed. This distinction is important when writing ARM assembly and calculating branch offsets.

7. Register Banking in ARM7TDMI-S

Register banking means that selected register numbers have separate physical copies in different operating modes. The register name visible to a program can remain R13 or R14, while the physical register selected changes with the mode.

R0–R7 are shared by all modes. R8–R12 are also shared by all modes except FIQ, which has separate copies.

Example: If the processor changes from User Mode to IRQ Mode, R13 refers to the IRQ stack pointer rather than the User stack pointer.

8. Current Program Status Register (CPSR)

The CPSR stores the current processor status and control information. It contains condition flags, interrupt-mask bits, the instruction state bit and operating-mode bits.

9. Saved Program Status Register (SPSR)

SPSR stores the previous CPSR value when an exception occurs. Each exception mode has its own SPSR.

When the processor enters an exception mode, the previous CPSR is copied into the new mode's SPSR. This makes it possible to restore the earlier processor status during exception return.

User Mode and System Mode do not have their own SPSR.

10. Example: Register-Based Arithmetic

Consider the following ARM assembly instructions: 

MOV R0, #10
MOV R1, #20
ADD R2, R0, R1

Explanation:

  1. R0 receives the value 10.
  2. R1 receives the value 20.
  3. The ADD instruction adds R0 and R1.
  4. The result 30 is stored in R2.
RegisterValue after execution
R010
R120
R230
This example demonstrates register-to-register arithmetic, which is a central feature of ARM's load/store architecture.

11. Practical Embedded Systems Relevance

ARM registers are essential when developing firmware for microcontrollers such as the LPC2129.

  • General-purpose registers hold intermediate calculation values.
  • SP supports function calls and stack management.
  • LR stores subroutine or exception return information.
  • PC controls program execution flow.
  • CPSR controls processor status and mode information.
  • SPSR preserves status information during exceptions.

Keil uVision Simulator Practice

  2. Build the project.
  3. Start the debugger.
  4. Open the Registers window.

In a simulator, register values and instruction execution can be inspected without a physical LPC2129 board. This exercise verifies the processor's register-level behavior, not external hardware operation.

12. Common Mistakes

  • Confusing R13 with the Link Register.
  • Confusing R14 with the Program Counter.
  • Assuming CPSR is one of the R0–R15 registers.
  • Forgetting that R13 and R14 are banked in exception modes.
  • Assuming every mode has separate copies of all general-purpose registers.
  • Assuming LR can preserve an unlimited number of nested return addresses.
  • Assuming the visible PC always equals the currently executing instruction address.

13. Interview Questions and Answers

Q1. How many programmer-visible general-purpose register numbers are available in ARM7?

Sixteen, R0 through R15.

Q2. What is the width of ARM7 general-purpose registers?

32 bits.

Q3. Which register is the Stack Pointer?

R13.

Q4. Which register is the Link Register?

R14.

Q5. Which register is the Program Counter?

R15.

Q6. What is the function of the Link Register?

It commonly stores the return address generated by a subroutine call or exception entry.

Q7. What is register banking?

It is the provision of separate physical copies of selected registers for particular processor modes.

Q8. Which mode has the largest banked general-purpose register set?

FIQ Mode.

Q9. What does CPSR contain?

Condition flags, interrupt masks, instruction state and operating-mode information.

Q10. What is the purpose of SPSR?

It saves the previous CPSR value during exception entry.

16. Lesson Summary

  • ARM7TDMI-S provides 16 programmer-visible register numbers, R0–R15.
  • R0–R12 are general-purpose registers.
  • R13 is SP, R14 is LR and R15 is PC.
  • General-purpose registers are 32 bits wide.
  • Selected registers are banked in different processor modes.
  • FIQ mode has additional banked registers R8–R14.
  • CPSR holds current processor status and control information.
  • SPSR saves the previous CPSR during exception entry.
