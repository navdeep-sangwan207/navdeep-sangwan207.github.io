Registers and Register Organization

Chapter 2: Embedded System Hardware and Architecture

Lesson 05: CPU registers and register organization

1. Introduction to CPU Registers

Registers are small, high-speed storage locations located inside a processor. They temporarily store data, addresses, instructions and control information required during instruction execution.

Registers are directly accessed by the CPU and are generally faster than main memory.

Definition: A CPU register is a small storage element inside the processor used to hold information required for immediate processing.

Functions of Registers

  • Store operands for arithmetic and logical operations.
  • Hold intermediate calculation results.
  • Store memory addresses.
  • Maintain the address of the next instruction.
  • Store stack-related information.
  • Maintain processor status and control information.

2. Characteristics of Registers

  • Located inside the CPU.
  • Very fast access compared with main memory.
  • Limited storage capacity.
  • Have specific sizes such as 8-bit, 16-bit or 32-bit.
  • May be general-purpose or special-purpose.
  • Used during instruction execution and processor control.

Registers vs RAM

Feature CPU Registers RAM
Location Inside CPU Memory subsystem
Capacity Very small Generally larger
Access Very fast Slower than registers
Purpose Immediate processing and control Program and runtime data storage
Management Defined by processor architecture Accessed through memory operations

3. Register Organization

Register organization describes how registers are arranged, classified and connected to the processor's internal data paths and execution units.

Basic Register Organization

General-Purpose Registers

Operands and temporary data

Special-Purpose Registers

Address and control information

↓
Internal CPU Data Paths

Transfer register data

↓
ALU and Control Unit

Execute and control operations

Major Register Categories

  1. General-purpose registers.
  2. Accumulator registers.
  3. Program Counter (PC).
  4. Stack Pointer (SP).
  5. Link Register (LR).
  6. Status registers.
  7. Instruction Register (IR), in architectures that expose or implement it as a distinct register.

4. General-Purpose Registers (GPR)

General-purpose registers are used to store data, operands, addresses and intermediate results.

Their exact number, size and permitted uses depend on the processor architecture.

Example

Consider the following conceptual operation: 

R0 = 10
R1 = 20
R2 = R0 + R1

After execution:

  • R0 contains 10.
  • R1 contains 20.
  • R2 contains 30.
General-purpose registers reduce the need for repeated memory accesses by keeping frequently used values inside the processor.

5. Special-Purpose Registers

Special-purpose registers perform specific processor functions such as instruction sequencing, stack management, function calls and status monitoring.

5.1 Program Counter (PC)

The Program Counter holds the address associated with the next instruction to be fetched or executed, depending on the processor's execution stage.

  • Controls the sequence of instruction execution.
  • Changes during normal instruction flow.
  • Changes during branches, function calls and exceptions.

5.2 Stack Pointer (SP)

The Stack Pointer identifies the current stack location. The stack is used for temporary storage and function-call management.

  • Stores the current stack position.
  • Supports push and pop operations.
  • Helps manage function calls and local storage.

5.3 Link Register (LR)

The Link Register stores a return address during subroutine calls in architectures such as ARM.

In ARM7, the BL instruction stores the return address in LR before transferring execution to a subroutine.

5.4 Status Register

A status register contains condition flags and processor control information.

In ARM7, the Current Program Status Register (CPSR) stores condition flags, interrupt masks, processor mode and state information.

6. Accumulator Register

An accumulator is a register used to hold intermediate arithmetic and logical results in certain processor architectures.

In accumulator-based architectures, operations often use an implicit accumulator operand.

Example

LOAD A
ADD B
STORE RESULT

Conceptual operation:

  1. Load the value of A into the accumulator.
  2. Add the value of B to the accumulator.
  3. Store the result in memory.
Not every processor has a dedicated accumulator register. ARM7TDMI-S is a load/store architecture with a general register set rather than a conventional accumulator-based programming model.

7. Instruction Register (IR)

An Instruction Register is used in many processor implementations to hold the instruction currently being decoded or processed.

Role in Instruction Execution

  1. The processor fetches an instruction from memory.
  2. The instruction is made available to the decode logic.
  3. The control unit interprets the instruction.
  4. The processor performs the required operation.
The Instruction Register is a useful basic CPU architecture concept. Do not assume that a particular internal IR is directly accessible to software or exposed as a programmer-visible ARM7 register.

8. ARM7TDMI-S Register Organization

ARM7TDMI-S is a 32-bit RISC processor core used in microcontrollers such as the LPC2129.

The ARM7 programmer's model provides 16 registers visible at a time in the current processor mode, named R0 through R15.

8.1 ARM7 Registers

Register Common Name Purpose
R0–R12 General-purpose registers Data, operands and temporary values
R13 SP Stack Pointer
R14 LR Link Register
R15 PC Program Counter

8.2 R0 to R12

R0 through R12 are general-purpose registers. They hold operands, addresses and intermediate results.

8.3 R13 – Stack Pointer

R13 is used as the Stack Pointer. ARM7 has banked versions of R13 for several processor modes.

8.4 R14 – Link Register

R14 is used as the Link Register. It normally receives the return address when a subroutine is called using the BL instruction.

8.5 R15 – Program Counter

R15 is the Program Counter. It controls the instruction execution sequence.

In ARM state, reading R15 has architectural pipeline-related behavior; it should not be treated as a simple copy of the address of the instruction currently being executed. The exact visible value differs between ARM and Thumb states.

9. ARM7 Banked Registers

ARM7 supports multiple processor modes. Some registers are banked, meaning that a processor mode has its own physical copy of selected registers.

Banked registers help the processor handle exceptions efficiently without always saving every register manually.

Banked Register Organization

Processor Mode Banked Registers
User Common R13 and R14
System Shares User-mode registers
FIQ R8_fiq to R14_fiq
IRQ R13_irq and R14_irq
Supervisor R13_svc and R14_svc
Abort R13_abt and R14_abt
Undefined R13_und and R14_und

Why Are Registers Banked?

  • Reduce the time required to enter exception handlers.
  • Provide separate stack pointers for different modes.
  • Allow FIQ to use additional dedicated registers.
  • Reduce unnecessary register saving and restoration.
FIQ has banked R8–R14. IRQ, Supervisor, Abort and Undefined modes have banked R13 and R14. User and System modes share the same general register bank.

10. CPSR and SPSR

ARM7 uses status registers to maintain processor condition flags and control information.

10.1 Current Program Status Register (CPSR)

CPSR is the Current Program Status Register. It contains processor status and control information.

Important fields include:

  • N – Negative flag.
  • Z – Zero flag.
  • C – Carry flag.
  • V – Overflow flag.
  • I – IRQ interrupt mask bit.
  • F – FIQ interrupt mask bit.
  • T – Thumb state bit.
  • M[4:0] – Processor mode bits.

10.2 Saved Program Status Register (SPSR)

SPSR stores a saved copy of CPSR when an exception is entered in processor modes that have an SPSR.

  • Preserves the previous processor status.
  • Supports restoration of the previous processor state.
  • Each exception mode has its own SPSR.
  • User and System modes do not have an SPSR.
Register Purpose
CPSR Holds current processor status and control information
SPSR Stores the previous CPSR during exception entry

Detailed CPSR fields, SPSR behavior and exception processing are covered in Chapter 06: ARM7TDMI Architecture and Programming Model.

11. Register Usage During Function Calls

During a function call, registers are used to pass arguments, hold return values and preserve required processor state.

ARM Calling Convention Concept

  • R0–R3 are commonly used for the first four argument values.
  • R0 is commonly used to return a simple result.
  • R13 is the Stack Pointer.
  • R14 holds the return address during a BL call.
  • R15 is the Program Counter.
These are common ARM procedure-call conventions. The exact register preservation rules depend on the applicable ABI, such as the ARM Architecture Procedure Call Standard.

Example: Subroutine Call

        AREA Example, CODE, READONLY
        ENTRY

        MOV R0, #10
        MOV R1, #20

        BL ADD_NUMBERS

STOP
        B STOP

ADD_NUMBERS
        ADD R2, R0, R1
        MOV R0, R2
        BX LR

        END

Explanation

  1. R0 receives the first operand.
  2. R1 receives the second operand.
  3. BL transfers control to ADD_NUMBERS.
  4. The return address is saved in LR.
  5. The ADD instruction calculates the sum in R2.
  6. The result is copied into R0.
  7. BX LR returns to the calling code.
Expected Result: R0 contains 30 after the subroutine returns. The program then remains in the STOP loop.

This example illustrates register usage. It can be assembled and examined in Keil uVision with an appropriate ARM7 assembler project configuration.

12. Register Operations

The processor performs different operations using registers.

12.1 Data Transfer

MOV R0, #25
MOV R1, R0

The first instruction loads the immediate value 25 into R0. The second copies R0 into R1.

12.2 Arithmetic Operation

MOV R0, #10
MOV R1, #5
ADD R2, R0, R1

Result: R2 contains 15.

12.3 Logical Operation

MOV R0, #0x0F
MOV R1, #0x03
AND R2, R0, R1

Result:

R0 = 0000 1111
R1 = 0000 0011
----------------
R2 = 0000 0011

R2 = 0x03

12.4 Register and Memory Transfer

LDR R0, =0x40000000
LDR R1, [R0]
STR R1, [R0]

LDR and STR are load/store instructions. They transfer data between registers and memory.

The address 0x40000000 is only an illustrative address here. Do not assume it identifies a valid LPC2129 RAM or peripheral register. Always consult the actual device memory map before accessing a hardware address.

13. Register Width and Data Representation

Register width indicates how many bits a register can store.

Register Width Example Range (Unsigned)
8-bit 0 to 255
16-bit 0 to 65,535
32-bit 0 to 4,294,967,295
64-bit 0 to 18,446,744,073,709,551,615

A 32-bit register can store 32 binary digits. In the ARM7 programming model, the general registers are 32 bits wide.

For an n-bit unsigned value, the range is: 0 to 2n - 1.

14. Common Mistakes

  • Confusing CPU registers with RAM.
  • Assuming all registers are general-purpose registers.
  • Confusing R13, R14 and R15 in ARM7.
  • Assuming the Link Register always contains a valid return address.
  • Assuming all ARM7 modes share the same physical R13 and R14.
  • Confusing CPSR with SPSR.
  • Assuming every processor exposes its internal Instruction Register to software.
  • Ignoring ABI rules when writing assembly subroutines.

15. Interview Questions and Answers

Q1. What is a CPU register?

A CPU register is a small, high-speed storage location inside the processor used during instruction execution.

Q2. Why are registers faster than RAM?

Registers are located inside the processor and are directly accessed by its execution units.

Q3. What are general-purpose registers?

They are registers used for operands, addresses and intermediate data.

Q4. What is the function of PC?

The Program Counter controls instruction sequencing by holding the address associated with the next instruction fetch.

Q5. What is the function of SP?

The Stack Pointer identifies the current stack position used for temporary storage and function calls.

Q6. What is the function of LR in ARM7?

The Link Register stores the return address during a subroutine call.

Q7. How many registers are visible in the ARM7 programmer's model?

Sixteen registers, R0 through R15, are visible in the current processor mode.

Q8. Which ARM7 register is used as the Program Counter?

R15.

Q9. Which ARM7 register is used as the Link Register?

R14.

Q10. Which ARM7 register is used as the Stack Pointer?

R13.

Q11. What is a banked register?

A banked register is a separate physical register selected in a particular processor mode.

Q12. What is the difference between CPSR and SPSR?

CPSR holds the current processor status and control information. SPSR preserves the previous CPSR when an exception is entered in a mode with an SPSR.

18. Lesson Summary

  • Registers are high-speed storage locations inside the CPU.
  • General-purpose registers store operands and temporary data.
  • Special-purpose registers support processor control and execution.
  • PC controls instruction sequencing.
  • SP identifies the current stack position.
  • LR stores the return address during subroutine calls.
  • ARM7 provides 16 registers visible in the current mode.
  • R13 is SP, R14 is LR and R15 is PC.
  • ARM7 uses banked registers for exception handling.
  • CPSR holds current processor status and control information.
  • SPSR preserves the previous CPSR during exception entry.
Learning Outcome: You should now be able to explain CPU register organization, identify ARM7 registers and understand how registers participate in arithmetic operations, memory access, subroutine calls and processor control.
