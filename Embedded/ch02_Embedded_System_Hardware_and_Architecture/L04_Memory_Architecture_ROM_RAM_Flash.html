Memory Architecture: ROM, RAM and Flash

Chapter 2: Embedded System Hardware and Architecture

Lesson 04: Memory types, organization and applications

1. Introduction to Memory Architecture

Memory is an essential component of an embedded system. It stores program instructions, application data, configuration information and intermediate processing results.

A processor needs memory to fetch instructions and access the data required during program execution.

Definition: Memory architecture describes how storage components are organized and accessed within a computer or embedded system.

Functions of Memory

  • Stores firmware and application instructions.
  • Stores temporary variables and intermediate results.
  • Maintains stack and heap data.
  • Stores configuration and calibration information.
  • Maintains data required by peripheral drivers.
  • Stores persistent information between power cycles.

2. Memory Classification

Memory can be classified according to whether it retains data after power is removed.

2.1 Volatile Memory

Volatile memory requires electrical power to retain its stored information. When power is removed, its contents are normally lost.

Examples:

  • SRAM (Static Random Access Memory).
  • DRAM (Dynamic Random Access Memory).

2.2 Non-Volatile Memory

Non-volatile memory retains stored information even when the power supply is removed.

Examples:

  • ROM (Read Only Memory).
  • EEPROM (Electrically Erasable Programmable ROM).
  • Flash memory.

3. Memory Hierarchy

Memory hierarchy organizes storage according to speed, capacity, cost and proximity to the processor.

Typical Memory Hierarchy

CPU Registers

Very fast, very small

↓
Cache Memory

Fast, small capacity

↓
Main Memory (RAM)

Working program data

↓
Secondary Storage

Large persistent storage

Characteristics of Memory Hierarchy

  • Registers provide very fast access to processor operands.
  • Cache stores frequently accessed instructions and data.
  • RAM stores active programs and working data.
  • Secondary storage provides larger-capacity persistent storage.
Not every microcontroller contains a dedicated cache or secondary storage device. The hierarchy shown is a general computer architecture model.

4. Read Only Memory (ROM)

ROM is a category of non-volatile memory used to retain information without continuous power.

Traditionally, ROM stores fixed information such as firmware, lookup tables and startup instructions.

Types of ROM

4.1 Mask ROM

Mask ROM is programmed during semiconductor manufacturing. Its contents cannot normally be changed by the end user.

4.2 PROM

Programmable Read Only Memory can be programmed once after manufacturing using a suitable programming device.

4.3 EPROM

Erasable Programmable Read Only Memory can be erased using ultraviolet light and programmed again.

4.4 EEPROM

Electrically Erasable Programmable Read Only Memory can be erased and programmed electrically.

ROM is often used as a broad term for non-volatile read-mostly memory, even though many modern ROM technologies can be electrically reprogrammed.

5. Random Access Memory (RAM)

RAM is memory that allows data to be read and written at addresses in a random-access manner. It is commonly used for temporary storage during program execution.

5.1 Static RAM (SRAM)

SRAM stores each bit using a bistable circuit, commonly implemented with a flip-flop-based cell.

  • Does not require periodic refresh while powered.
  • Provides fast access.
  • Uses more transistors per bit than DRAM.
  • Typically has lower storage density.
  • Commonly used for cache and microcontroller SRAM.

5.2 Dynamic RAM (DRAM)

DRAM stores each bit using a capacitor-based memory cell. Stored charge gradually leaks, so the memory must be periodically refreshed.

  • Requires periodic refresh.
  • Provides high storage density.
  • Usually costs less per bit than SRAM.
  • Commonly used as main memory in computers.

SRAM vs DRAM

Feature SRAM DRAM
Storage method Bistable circuit Capacitor-based cell
Refresh Not required Required
Speed Generally faster Generally slower
Density Lower Higher
Cost per bit Generally higher Generally lower
Typical use Cache and embedded SRAM Computer main memory
Both SRAM and DRAM are volatile. SRAM does not need refresh, but it still loses its stored contents when power is removed.

6. Flash Memory

Flash memory is a type of electrically erasable non-volatile semiconductor memory. It is widely used for firmware storage in embedded systems.

Characteristics of Flash Memory

  • Retains information without power.
  • Can be electrically programmed and erased.
  • Supports high storage density.
  • Uses erase operations organized into blocks or sectors.
  • Has a finite number of program/erase cycles.

6.1 NOR Flash

NOR Flash provides random-access read capability and is commonly used for storing executable firmware.

  • Suitable for direct code access in supported systems.
  • Often used for microcontroller firmware storage.
  • Erase operations are generally block-based.

6.2 NAND Flash

NAND Flash is commonly used for high-capacity data storage.

  • High storage density.
  • Commonly used in SSDs, memory cards and USB drives.
  • Uses page-based read/program operations and block-based erase operations.
  • Often requires error correction and bad-block management.

NOR Flash vs NAND Flash

Feature NOR Flash NAND Flash
Read access Random-access reads Page-oriented reads
Typical application Firmware storage Mass data storage
Storage density Generally lower Generally higher
Erase organization Blocks or sectors Blocks
Typical products Embedded firmware memory SSD, USB drive, memory card

7. EEPROM vs Flash Memory

EEPROM and Flash are both electrically erasable non-volatile memory technologies. Their erase and programming organization differs.

Feature EEPROM Flash
Erasing Often supports byte-level or small-unit erase/write Erased in larger blocks or sectors
Typical capacity Usually smaller Usually larger
Common use Configuration and calibration data Firmware and large data storage
Update granularity Fine-grained Block-oriented erase operations
EEPROM and Flash are non-volatile memories, but their write/erase behavior and endurance characteristics depend on the specific memory device.

8. Memory Parameters and Specifications

8.1 Memory Capacity

Memory capacity indicates how much information a memory device can store.

  • 1 bit = one binary digit.
  • 1 byte = 8 bits.
  • 1 KB = 1024 bytes in common binary capacity notation.
  • 1 MB = 1024 KB.
  • 1 GB = 1024 MB.

8.2 Access Time

Access time is the time required to complete a memory read or write operation under specified conditions.

8.3 Data Width

Data width indicates the number of bits transferred in one data operation.

8.4 Memory Endurance

Endurance describes how many program/erase cycles a non-volatile memory device can tolerate before its reliability may degrade.

8.5 Data Retention

Data retention describes how long a non-volatile memory can preserve stored information under specified conditions.

Example: Memory Capacity Calculation

A memory chip contains 4096 addressable locations, each storing 8 bits. 

Number of locations = 4096

Data width = 8 bits

Total capacity = 4096 × 8 bits

               = 32768 bits

               = 4096 bytes

               = 4 KB

9. Memory Organization and Addressing

Memory is organized as a collection of addressable storage locations. Each location has an address.

Example: 8-bit Memory Organization

Memory Address Stored Data
0x00000x25
0x00010x4A
0x00020x7C
0x00030x12
0x00040xFF

In this example, each address identifies one byte of data. The processor uses addresses to select the required memory locations.

Address Space

An address bus with n address bits can represent up to 2n distinct address values. 

Address bits = 16

Number of addresses = 2^16

                     = 65536 locations

If each location stores one byte, the address space can represent 64 KiB of byte-addressable memory.

The theoretical address space does not mean that all addresses correspond to installed RAM. Some addresses may map to Flash, peripherals, reserved regions or unimplemented memory.

10. Memory Architecture in Embedded Systems

Embedded systems generally use different memory types for different purposes.

Memory Type Typical Embedded-System Purpose
Flash Firmware, program code and constant data
SRAM Variables, stack, heap and runtime buffers
EEPROM Configuration, calibration and settings
External Memory Additional RAM or persistent storage when required

Example: Embedded Temperature Monitoring System

Consider an embedded system that measures temperature and controls a cooling fan.

  • Flash stores the firmware.
  • SRAM stores temperature readings and temporary variables.
  • EEPROM or Flash data storage may retain calibration settings.
  • Processor registers hold operands and intermediate results.

11. LPC2129 Memory Architecture

The LPC2129 is an ARM7TDMI-S-based microcontroller. Its on-chip memory includes Flash memory for program storage and SRAM for runtime data.

11.1 On-Chip Flash Memory

The LPC2129 provides 256 KB of on-chip Flash memory. It is used to store the application firmware and other programmed information.

11.2 On-Chip SRAM

The LPC2129 provides 16 KB of on-chip static RAM. It is used for runtime variables, stack and other temporary data.

11.3 Memory Map

The processor uses a memory map to identify the locations of on-chip memory and peripheral registers. Memory-mapped peripherals are accessed through addresses in the processor's address space.

Memory Resource Capacity Purpose
On-chip Flash 256 KB Program and firmware storage
On-chip SRAM 16 KB Temporary runtime data
Important: The LPC2129 has on-chip Flash and SRAM. Do not confuse the microcontroller's Flash program memory with its SRAM working memory.

11.4 Example of Memory Usage

Consider the following Embedded C program: 

#include <LPC21xx.h>

int main(void)
{
    unsigned int temperature = 30;
    unsigned int threshold = 40;
    unsigned int fan_status = 0;

    if (temperature > threshold)
    {
        fan_status = 1;
    }

    while (1)
    {
        /* Main application loop */
    }
}

Memory usage concept:

  • The compiled program instructions are stored in Flash.
  • Runtime variables are typically stored in SRAM or registers, depending on compiler allocation.
  • Processor registers hold operands and intermediate results during execution.
  • The stack is located in SRAM and supports function calls and local storage.
The exact placement of variables depends on their storage duration, compiler optimization, linker configuration and generated startup code. The example is conceptual, not a fixed memory map for every build.

12. Memory Considerations in Embedded System Design

12.1 Memory Constraints

Embedded systems often operate with limited Flash and RAM. Firmware developers must manage memory carefully.

12.2 Stack Usage

The stack stores function-call information, return addresses and local variables as determined by the processor architecture and compiler.

12.3 Heap Usage

The heap supports dynamic memory allocation using functions such as malloc() and free() in C.

Dynamic allocation must be managed carefully in embedded applications because fragmentation and allocation failure can affect system reliability.

12.4 Firmware Size

The compiled firmware must fit within available program memory. Code optimization and careful library selection help control firmware size.

12.5 Data Retention and Endurance

Frequently changing data should not be written to Flash or EEPROM without considering endurance limits and the device's recommended programming procedures.

13. Common Mistakes

  • Assuming RAM retains information after power is removed.
  • Confusing Flash memory with SRAM.
  • Assuming all ROM technologies are permanently unchangeable.
  • Confusing SRAM and DRAM refresh requirements.
  • Assuming every microcontroller has external DRAM.
  • Assuming every memory address represents physical RAM.
  • Ignoring Flash erase-block limitations.
  • Ignoring memory endurance in frequently updated firmware storage.
  • Confusing the processor's registers with its main memory.

14. Interview Questions and Answers

Q1. What is memory architecture?

It describes the organization, types and access methods of memory in a computer or embedded system.

Q2. What is volatile memory?

Volatile memory requires power to retain its contents. SRAM and DRAM are examples.

Q3. What is non-volatile memory?

Non-volatile memory retains information without continuous power. Flash and EEPROM are examples.

Q4. Differentiate between SRAM and DRAM.

SRAM uses bistable storage circuits and does not need refresh. DRAM uses capacitor-based cells and requires periodic refresh.

Q5. What is Flash memory?

Flash is electrically erasable non-volatile memory used for firmware and data storage.

Q6. Differentiate between NOR and NAND Flash.

NOR Flash supports random-access reads and is commonly used for firmware. NAND Flash provides high-density storage and is commonly used for mass data storage.

Q7. What is EEPROM?

EEPROM is electrically erasable programmable non-volatile memory commonly used for configuration and calibration data.

Q8. What is memory hierarchy?

It is the organization of storage levels according to speed, capacity, cost and proximity to the CPU.

Q9. What is memory endurance?

It describes the number of program/erase cycles a memory device can tolerate under specified conditions.

Q10. How much Flash memory is available in LPC2129?

The LPC2129 provides 256 KB of on-chip Flash memory.

Q11. How much SRAM is available in LPC2129?

The LPC2129 provides 16 KB of on-chip SRAM.

Q12. What is the purpose of SRAM in an embedded system?

SRAM stores temporary data such as variables, buffers, stack information and runtime application data.

17. Lesson Summary

  • Memory stores program instructions and application data.
  • Volatile memory loses its contents when power is removed.
  • Non-volatile memory retains information without power.
  • SRAM is fast and does not require periodic refresh.
  • DRAM requires periodic refresh.
  • Flash memory is widely used for firmware storage.
  • NOR and NAND Flash have different access and storage characteristics.
  • EEPROM is commonly used for configuration data.
  • Memory capacity, access time and endurance are important specifications.
  • The LPC2129 has 256 KB Flash and 16 KB SRAM.
