Lesson 10: Embedded System Block Diagram

Understanding the functional architecture, hardware blocks, data flow and system integration of embedded systems.

1. Introduction

An embedded system is an electronic system designed to perform a specific function. It combines hardware and software to monitor inputs, process information and control outputs.

An embedded system block diagram is a graphical representation of the major functional components of an embedded system and the connections between them.

It helps engineers understand how information moves through the system and how individual hardware components interact.

Why are block diagrams used?

  • To understand the overall system architecture.
  • To identify the major hardware components.
  • To understand input, processing and output operations.
  • To plan hardware and software development.
  • To identify communication paths between components.
  • To simplify troubleshooting and system documentation.

3. Input Section

The input section receives information from the external environment or from a human operator.

Common input devices

  • Temperature sensors
  • Light-dependent resistors (LDRs)
  • Pressure sensors
  • Proximity sensors
  • Push buttons and switches
  • Rotary encoders
  • Digital sensor modules

Signal conditioning

Sensor signals may need conditioning before they can be processed by a microcontroller. Signal conditioning includes:

  • Amplification: increases a low-level signal.
  • Filtering: reduces unwanted noise.
  • Level shifting: adjusts voltage levels.
  • Isolation: provides electrical separation where required.
  • Protection: helps protect the input circuitry from abnormal voltages.

Analog-to-Digital Converter (ADC)

An ADC converts an analog voltage into a digital value that can be processed by a digital controller.

For an ideal N-bit ADC:

Number of quantization levels = 2N

For a 10-bit ADC:

Number of levels = 210 = 1024.

The approximate digital output for an input voltage can be calculated as:

Digital value ≈ (Vin / Vref) × (2N − 1)

For a real ADC, the input voltage must remain within the specified input range. Reference voltage, resolution, accuracy and input configuration affect the conversion.

4. Processing Unit

The processing unit is the central part of an embedded system. It executes the program, processes input data and generates control signals.

It may be implemented using a microcontroller, microprocessor, DSP or another programmable processing device.

Main processing components

CPUExecutes program instructions.

Microcontroller-based processing

A microcontroller generally integrates a CPU, memory and several peripherals on a single chip. This makes it suitable for compact embedded applications.

5. Memory Section

Memory stores the firmware, program data and temporary information required by the embedded system.

Memory organization

  • Program memory stores executable firmware.
  • Data memory stores variables and runtime information.
  • Stack memory supports function calls and local data.
  • Non-volatile data memory preserves selected information after power is removed.

7. Clock and Reset Circuits

Clock circuit

The clock circuit provides timing signals that coordinate processor and peripheral operations.

Clock sources may include:

  • External crystal oscillator
  • Internal RC oscillator
  • External clock source
  • Phase-Locked Loop (PLL) clock multiplication circuitry

Reset circuit

The reset circuit places the microcontroller into a defined initial state. A reset may occur during power-up, through a reset pin, or through a watchdog or software mechanism.

A stable clock and correctly designed reset circuit are essential for reliable system startup and operation.

8. Output Section

The output section converts processor control signals into useful physical or visual actions.

Common output devices

  • LEDs and indicator lamps
  • LCD and OLED displays
  • DC motors
  • Stepper motors
  • Servo motors
  • Relays and solenoids
  • Buzzers and speakers

Driver circuits

A microcontroller GPIO pin generally cannot directly supply the current required by many motors, relays or other high-power loads. Driver circuits provide the required current or voltage interface.

Common driver circuits include:

  • Transistor switching circuits
  • MOSFET drivers
  • H-bridge motor drivers
  • Relay driver circuits
  • Dedicated motor-driver ICs
Inductive loads such as relays and motors can generate voltage spikes when switched off. Suitable protection, such as a flyback diode for appropriate DC inductive loads, must be considered.

10. Power Supply and Voltage Regulation

The power supply provides electrical energy to the embedded system. Different components may require different operating voltages.

Power supply stages

  • Input power source: battery, adapter or regulated supply.
  • Protection: reverse-polarity, overcurrent and transient protection as required.
  • Voltage conversion: converts the input voltage to required levels.
  • Voltage regulation: maintains a stable output voltage.
  • Power distribution: supplies the processor, sensors and output circuits.

11. Watchdog and System Control

A watchdog timer is a hardware or software-supported mechanism that helps recover from certain firmware failures.

The firmware periodically refreshes the watchdog. If the expected refresh does not occur within the configured time, the watchdog may generate a system reset.

Other system-control functions may include:

  • Brown-out detection
  • Power-on reset
  • Clock monitoring
  • Interrupt management
  • Low-power mode control
  • Fault detection

13. Data Flow and Control Flow

Data flow

Data flow describes how information moves through the system.

Example:

  1. A temperature sensor measures the surrounding temperature.
  2. The sensor produces an electrical signal.
  3. The signal is conditioned and converted by an ADC if necessary.
  4. The processor reads the digital value.
  5. The firmware processes the measurement.
  6. The result is displayed or used to control an actuator.

Control flow

Control flow describes how the processor decides which operations should occur and when.

For example, firmware may compare a measured temperature against a threshold and activate a fan when the threshold is exceeded.

14. Design Example: Automatic Temperature-Controlled Fan

Consider an embedded system that automatically controls a fan according to measured temperature.

Functional requirements

  • Measure the surrounding temperature.
  • Process the temperature measurement.
  • Compare the measurement with configured thresholds.
  • Control fan operation using a driver circuit.
  • Display the temperature and fan status.

Working principle

  1. The temperature sensor measures the environment.
  2. The sensor output is acquired by the microcontroller.
  3. The controller converts or interprets the measurement.
  4. The firmware compares the temperature against defined limits.
  5. The controller adjusts the fan command.
  6. A driver circuit supplies the electrical power required by the fan.
  7. The LCD displays the measured temperature and fan status.

Illustrative control logic

START

Initialize sensor interface
Initialize display
Initialize motor control

REPEAT:
    Read temperature

    IF temperature >= HIGH_LIMIT:
        Set fan speed to HIGH

    ELSE IF temperature >= LOW_LIMIT:
        Set fan speed to MEDIUM

    ELSE:
        Set fan speed to LOW

    Update display

UNTIL system is stopped
The thresholds and fan speeds are application-specific. Practical systems should include sensor-fault handling, suitable motor-driver protection and safe startup behavior.

The LPC2129 does not provide an on-chip DAC. Applications requiring analog voltage output need an external DAC or another suitable output-generation method. Physical CAN communication also requires an external CAN transceiver.

Practical simulator consideration

In Keil uVision, the processor execution, program flow and supported registers can be inspected. The simulator does not necessarily reproduce the electrical behavior of external sensors, displays, motors, power supplies or communication networks.

16. Steps to Design an Embedded System Block Diagram

  1. Define the application: Identify the problem the system must solve.
  2. Identify inputs: List sensors, switches and external signals.
  3. Identify outputs: List displays, motors, relays and other controlled devices.
  4. Select the controller: Choose a suitable microcontroller or processor.
  5. Determine memory requirements: Estimate program and data storage needs.
  6. Identify interfaces: Select ADC, GPIO, UART, SPI, I2C, CAN or other required interfaces.
  7. Design the power supply: Determine voltage rails and current requirements.
  8. Include supporting circuits: Add clock, reset, protection and watchdog functions.
  9. Connect the blocks: Show signal, data and control paths clearly.
  10. Review the design: Verify compatibility, electrical requirements and system behavior.

17. Common Mistakes in Block Diagram Design

  • Omitting the power supply and voltage regulation.
  • Connecting high-current loads directly to microcontroller GPIO pins.
  • Ignoring signal conditioning for analog sensors.
  • Forgetting voltage-level compatibility between devices.
  • Not identifying communication interfaces.
  • Ignoring clock and reset requirements.
  • Confusing a functional block diagram with a detailed circuit schematic.
  • Failing to show feedback paths in control systems.
  • Assuming every microcontroller includes every peripheral.

18. Interview Questions and Answers

Q1. What is an embedded system block diagram?

It is a graphical representation of the major functional components of an embedded system and their interconnections.

Q2. What are the three basic functional sections of an embedded system?

Input section, processing section and output section.

Q3. What is the function of signal conditioning?

It prepares sensor signals for reliable processing through operations such as amplification, filtering and level shifting.

Q4. Why is an ADC required?

An ADC converts analog signals into digital values that a digital processor can process.

Q5. What is the purpose of a watchdog timer?

It helps detect certain firmware execution failures and can initiate a reset if the watchdog is not serviced in time.

Q6. What is the difference between a block diagram and a circuit schematic?

A block diagram shows functional components and their relationships. A circuit schematic shows actual electrical connections and components.

Q7. Why are driver circuits used?

They provide the voltage and current capability needed to control loads that cannot be driven directly by processor pins.

Q8. What is the role of the clock circuit?

It provides timing signals that coordinate processor and peripheral operations.

Q9. What is the purpose of a feedback path?

It provides information about the controlled process so the controller can adjust its output.

Q10. Does the LPC2129 contain an on-chip DAC?

No. An external DAC is required when an application needs analog voltage output.

21. Lesson Summary

  • An embedded system block diagram represents the functional architecture of a system.
  • The basic sections are input, processing and output.
  • Signal conditioning prepares sensor signals for processing.
  • ADC converts analog signals into digital data.
  • The processor executes firmware and controls system operations.
  • Memory stores program instructions and runtime data.
  • System buses connect the processor, memory and peripherals.
  • Clock and reset circuits support reliable operation.
  • Driver circuits interface the controller with external loads.
  • Communication interfaces enable data exchange with external devices.
  • Power management and watchdog functions improve system reliability.
