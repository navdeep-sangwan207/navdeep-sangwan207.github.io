Lesson 06: System bus architecture and communication

1. Introduction to System Buses

A system bus is a communication pathway that transfers information between the processor, memory and peripheral devices.

It allows different hardware components to communicate with each other by carrying addresses, data and control signals.

Definition: A system bus is a collection of electrical signal lines and associated communication mechanisms used to transfer information between computer system components.

Why Are System Buses Required?

  • To connect the CPU with memory.
  • To transfer data between hardware components.
  • To identify memory or peripheral locations.
  • To coordinate read and write operations.
  • To communicate with input and output devices.

2. Basic System Bus Architecture

A traditional system bus is commonly described using three groups of signals:

  1. Address bus.
  2. Data bus.
  3. Control bus.

3. Address Bus

The address bus carries the address of the memory location or peripheral register that the processor wants to access.

Characteristics

  • Identifies the target memory or peripheral location.
  • Often driven by the CPU in a simple processor system.
  • Its width determines the number of distinct address values.
  • Usually unidirectional in a basic CPU-to-memory bus model.

Address Bus Width

If an address bus contains n independent address bits, it can represent up to 2n distinct addresses.

Example 1: 8-bit Address Bus

Address bus width = 8 bits

Number of addresses = 2^8

                     = 256 locations

Example 2: 16-bit Address Bus

Address bus width = 16 bits

Number of addresses = 2^16

                     = 65,536 locations

Example 3: 32-bit Address Bus

Address bus width = 32 bits

Number of addresses = 2^32

                     = 4,294,967,296 addresses
A 32-bit address space can represent 4 GiB of byte-addressable locations. The actual installed memory may be much smaller.

4. Data Bus

The data bus carries actual information between the processor, memory and peripheral devices.

Characteristics

  • Transfers instructions and data.
  • Its width determines how many data bits can be transferred in parallel.
  • In a conventional shared memory bus, data transfer can occur in both directions.
  • Its width influences data transfer efficiency.

Example: 8-bit Data Bus

An 8-bit data bus can transfer 8 bits in one data transfer operation. 

Data = 10101010

Data width = 8 bits

Example: 32-bit Data Bus

A 32-bit data bus can transfer 32 bits in one transfer operation when the interface supports that width.

A wider data bus can transfer more bits per transaction, but actual performance also depends on clock frequency, wait states, memory latency and bus protocol.

5. Control Bus

The control bus carries signals that coordinate and manage data transfer operations.

Common Control Signals

Signal Function
Read Indicates a read operation.
Write Indicates a write operation.
Clock Provides timing reference for synchronous transfers.
Reset Places hardware into a defined reset state.
Interrupt Requests processor attention.
Ready/Wait Indicates whether a transfer can complete or must wait.
Byte Enable Identifies selected byte lanes in supported interfaces.
These are common control functions. Actual signal names, polarity and timing depend on the processor and bus architecture. Not every bus has every signal.

7. Memory Read Operation

A memory read operation retrieves information from a selected memory location.

Steps Involved

  1. The CPU places the required memory address on the address bus.
  2. The CPU indicates a read operation using the appropriate control signal.
  3. The memory device decodes the address.
  4. The selected memory location provides its data.
  5. The data is transferred through the data bus.
  6. The CPU receives the data.

Memory Read Cycle

CPU
↓ Address + Read Control
Memory
↑ Data
CPU receives data

Example

Memory address = 0x1000

Stored data = 0x5A

CPU performs READ at 0x1000

Result:
CPU receives 0x5A

8. Memory Write Operation

A memory write operation stores information at a selected memory location.

Steps Involved

  1. The CPU places the target address on the address bus.
  2. The CPU places the data on the data bus.
  3. The CPU indicates a write operation through the control signals.
  4. The memory device decodes the address.
  5. The selected memory location stores the data.

Memory Write Cycle

CPU
↓ Address + Data + Write Control
Memory stores data

Example

Memory address = 0x1000

Data to write = 0xA5

CPU performs WRITE at 0x1000

Result:
Memory[0x1000] = 0xA5

9. Bus Width and System Performance

Bus width is the number of parallel signal lines available for carrying address or data information.

Address Bus Width

Address width determines the theoretical number of distinct addresses.

Data Bus Width

Data width determines the number of bits transferred in a single data transaction.

10. Types of Bus Architecture

10.1 Single Bus Architecture

A single shared bus connects the processor, memory and peripherals.

CPU
Memory
I/O Devices
↕
Shared System Bus

Advantages:

  • Simple design.
  • Lower hardware complexity.
  • Easy to understand and implement.

Limitations:

  • Only a limited number of transfers can occur at a time.
  • Multiple devices compete for bus access.
  • Bus traffic can become a performance bottleneck.

10.2 Multiple Bus Architecture

Multiple bus architectures use separate communication pathways for different components or functions.

↕

Advantages:

  • Can improve communication efficiency.
  • Reduces contention on individual bus segments.
  • Allows different interfaces to operate at different speeds.

11. Synchronous and Asynchronous Buses

11.1 Synchronous Bus

A synchronous bus uses a shared clock signal to coordinate communication.

  • Transfers are coordinated with clock timing.
  • Timing relationships are generally predictable.
  • Suitable for interfaces designed around a common clock.

11.2 Asynchronous Bus

An asynchronous bus does not rely on a shared clock to time every transfer. It may use handshake signals such as request and acknowledge.

  • Communication uses handshaking or control events.
  • Can accommodate devices with different response times.
  • Transfer duration can vary.
Feature Synchronous Asynchronous
Timing Clock-based Handshake-based or event-based
Shared clock Generally required Not required for each transfer
Transfer duration Related to clock cycles Depends on device response
Complexity Clock distribution and timing constraints Handshake control required

12. Bus Arbitration

Bus arbitration is the process of deciding which device is allowed to use a shared bus when multiple devices request access.

Why Is Arbitration Required?

In a system with multiple bus masters, two or more devices may request access simultaneously. Arbitration prevents conflicting bus ownership.

Common Arbitration Methods

  • Centralized arbitration: A central controller grants bus access.
  • Daisy-chain arbitration: Grant signals pass through devices in priority order.
  • Distributed arbitration: Devices participate in selecting the bus owner.

13. Bus Interfaces in Embedded Systems

Embedded systems use different communication interfaces to connect processors, memory and peripherals.

Interface Typical Purpose
AMBA AHB High-performance on-chip communication.
AMBA APB Simple, low-power peripheral register access.
AXI High-performance memory-mapped communication.
SPI Serial communication with external peripherals.
I2C Two-wire communication between integrated circuits.
CAN Robust communication between distributed controllers.
SPI, I2C and CAN are communication interfaces, not simply interchangeable with a traditional CPU address, data and control bus. They have their own signaling and communication protocols.

14. Bus Architecture in ARM-Based Systems

ARM-based embedded systems commonly use AMBA (Advanced Microcontroller Bus Architecture) or other on-chip interconnect architectures.

AMBA Overview

  • AHB: Advanced High-performance Bus.
  • APB: Advanced Peripheral Bus.
  • AXI: Advanced eXtensible Interface.
  • ASB: Advanced System Bus, an earlier AMBA bus specification.

AHB

AHB is designed for high-performance communication between system components such as processors, memory controllers and high-bandwidth peripherals.

APB

APB is designed for simple peripheral communication. It is commonly used for low-bandwidth peripheral registers such as timers, UARTs and GPIO controllers.

15. Common Mistakes

  • Confusing address bus width with data bus width.
  • Assuming a wider data bus automatically guarantees higher system performance.
  • Assuming every control signal travels in the same direction.
  • Confusing a serial communication protocol with a processor system bus.
  • Assuming every bus uses a shared clock.
  • Ignoring bus arbitration in multi-master systems.
  • Assuming every ARM-based microcontroller uses the same AMBA configuration.
  • Assuming the theoretical address space equals installed memory capacity.

16. Interview Questions and Answers

Q1. What is a system bus?

A system bus is a communication pathway used to transfer information between the CPU, memory and peripherals.

Q2. What are the three main bus groups?

Address bus, data bus and control bus.

Q3. What is the function of the address bus?

It carries the address of the memory location or peripheral register being accessed.

Q4. What is the function of the data bus?

It transfers actual data and instruction information between connected components.

Q5. What is the function of the control bus?

It carries signals that coordinate operations such as read, write, reset and interrupt handling.

Q6. How many addresses can a 16-bit address bus represent?

216 = 65,536 distinct addresses.

Q7. What is bus arbitration?

It is the process of selecting which bus master can use a shared bus.

Q8. Differentiate between synchronous and asynchronous buses.

A synchronous bus uses clock-based timing. An asynchronous bus uses handshaking or event-based coordination instead of a shared transfer clock.

Q9. What is AMBA?

AMBA is the Advanced Microcontroller Bus Architecture, a family of on-chip communication specifications used in ARM-based systems.

Q10. What is the difference between AHB and APB?

AHB supports higher-performance system communication, while APB provides a simpler interface for lower-speed peripheral access.

Q11. What is the theoretical address space of a 32-bit address bus?

232 = 4,294,967,296 address values, or 4 GiB for byte-addressable memory.

Q12. What happens during a memory read cycle?

The processor selects an address, requests a read, and receives the selected data through the data path.

19. Lesson Summary

  • A system bus connects the CPU, memory and peripherals.
  • The address bus identifies a target location.
  • The data bus transfers information.
  • The control bus coordinates operations.
  • Address bus width determines theoretical address count.
  • Data bus width determines bits transferred per transaction.
  • Memory read and write operations use address, data and control information.
  • Bus arbitration selects a bus master.
  • Synchronous buses use clock-based timing.
  • Asynchronous buses use handshaking or event-based timing.
  • AMBA includes interfaces such as AHB, APB and AXI.
