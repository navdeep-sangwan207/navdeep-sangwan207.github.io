Lesson 04: I2C Addressing and Data Transfer

Understand 7-bit and 10-bit addressing, read/write direction, ACK and NACK responses, data-byte transmission, and complete I2C communication sequences.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain how I2C devices are addressed.
  • Understand 7-bit and 10-bit addressing.
  • Identify the read/write bit in an address frame.
  • Explain ACK and NACK responses.
  • Understand the structure of an I2C data frame.
  • Describe master-transmitter and master-receiver operations.
  • Understand register-based read and write transactions.
  • Interpret common I2C status codes.

2. Introduction to I2C Addressing

I2C allows multiple target devices to share the same SDA and SCL bus. The controller identifies the intended target by transmitting its address after generating a START condition.

Each target normally has a unique address on the bus. A device recognizes its own address and responds when selected.

Address-Based Device Selection 
              I2C Controller
                    |
              START Condition
                    |
             Address + R/W Bit
                    |
          +---------+---------+
          |         |         |
       Sensor    EEPROM      RTC
       0x48       0x50      0x68
          |         |         |
       Address   Address   Address
       Match?    Match?    Match?
          |         |         |
         ACK       ACK       ACK

Only the target whose address matches responds.
An I2C address identifies a target on the bus. It is not necessarily the same as the target's internal register address or memory location.

3. 7-Bit Addressing

Standard I2C addressing commonly uses a 7-bit target address. The address is transmitted as part of the first byte after the START condition.

The eighth bit is the read/write direction bit.

Address Byte Format

7-Bit Address and R/W Bit 
       Bit:  7   6   5   4   3   2   1   0
            +-----------------------+---+
            |     7-Bit Address     |R/W|
            +-----------------------+---+
             A6  A5  A4  A3  A2  A1  A0

R/W = 0 : Write
R/W = 1 : Read

The address bits are transmitted most-significant bit first. The R/W bit follows the seven address bits.

Address Range

A 7-bit address field represents 128 possible binary values: 

0000000 to 1111111

Decimal range: 0 to 127
Hexadecimal range: 0x00 to 0x7F
Not every 7-bit value is available for ordinary target addressing. Some address ranges are reserved by the I2C specification for special purposes.

Example

Suppose an I2C target has the 7-bit address 0x48. 

7-bit address = 0x48

Binary = 1001000

Write address byte:
1001000 + 0 = 10010000
Hexadecimal = 0x90

Read address byte:
1001000 + 1 = 10010001
Hexadecimal = 0x91

Therefore, the address byte is 0x90 for write and 0x91 for read. The underlying 7-bit target address remains 0x48.

4. 10-Bit Addressing

I2C also supports 10-bit addressing to provide a larger target address space.

A 10-bit address is transmitted using two address bytes. The first byte contains a special prefix, two address bits, and the R/W bit. The second byte contains the remaining eight address bits.

10-Bit Address Format

10-Bit Address Structure 
First Address Byte:
+-----+-----+-----+-----+-----+-----+-----+-----+
|  1  |  1  |  1  |  1  |  0  | A9  | A8  | R/W |
+-----+-----+-----+-----+-----+-----+-----+-----+

Second Address Byte:
+-----+-----+-----+-----+-----+-----+-----+-----+
| A7  | A6  | A5  | A4  | A3  | A2  | A1  | A0  |
+-----+-----+-----+-----+-----+-----+-----+-----+

The controller first sends the special 10-bit address prefix and the two most significant address bits. The target acknowledges and the controller then sends the remaining eight address bits.

A 10-bit address uses a two-byte address sequence. For a 10-bit read operation, the controller normally sends the address prefix in write form, sends the second address byte, and then generates a repeated START followed by the address prefix in read form.

7-Bit vs 10-Bit Addressing

Feature 7-Bit 10-Bit
Address length 7 bits 10 bits
Address sequence One address byte Two address bytes
Address space 128 encoded values 1024 encoded values
Complexity Lower Higher
Common usage Most ordinary I2C devices Systems requiring a larger address space

5. Read and Write Direction Bit

The least significant bit of the address byte specifies the direction of data transfer.

R/W Bit Operation Direction
0 Write Controller transmits data to target.
1 Read Target transmits data to controller.

Write Operation

Controller Writes to Target 
Controller                         Target

START
  |
  |------ Address + W ----------->|
  |<------------- ACK ------------|
  |
  |------ Data Byte ------------->|
  |<------------- ACK ------------|
  |
STOP

Data direction: Controller to Target

Read Operation

Controller Reads from Target 
Controller                         Target

START
  |
  |------ Address + R ----------->|
  |<------------- ACK ------------|
  |
  |<--------- Data Byte -----------|
  |
  |------------- NACK ------------>|
  |

Data direction: Target to Controller
The R/W bit specifies the direction of the data phase. The controller still generates START, controls the bus, and normally generates STOP.

6. Acknowledgment (ACK)

ACK means acknowledgment. It indicates that the receiver has accepted the transmitted byte at the protocol level.

After eight data bits, the transmitter releases SDA. The receiver acknowledges by pulling SDA LOW during the ninth clock pulse.

ACK Response 
Clock pulses:  1 2 3 4 5 6 7 8 9
               | | | | | | | | |
Data:          D D D D D D D D A
                              |
                              ACK

ACK = SDA LOW during ninth clock pulse.

ACK Characteristics

  • ACK is represented by SDA LOW during the ninth clock.
  • The receiver generates the acknowledgment.
  • ACK confirms that the byte was acknowledged.
  • It does not necessarily prove that the target completed its internal operation.

7. Not Acknowledgment (NACK)

NACK means not acknowledgment. It is represented by SDA remaining HIGH during the ninth clock pulse.

NACK Response 
Clock pulses:  1 2 3 4 5 6 7 8 9
               | | | | | | | | |
Data:          D D D D D D D D N
                              |
                              NACK

NACK = SDA HIGH during ninth clock pulse.

Common Reasons for NACK

  • No target responds to the transmitted address.
  • The target is busy or unable to accept data.
  • The target does not recognize the received command.
  • The controller has finished reading and does not want another byte.
During a multi-byte read, the controller commonly acknowledges intermediate bytes and sends NACK after the final byte to indicate that it does not want more data.

8. Complete I2C Data Frame

A typical I2C byte transfer contains eight data bits followed by one acknowledgment bit.

I2C Byte Transfer 
      8 Data Bits                 1 ACK/NACK Bit
+---+---+---+---+---+---+---+---+-------+
| D7| D6| D5| D4| D3| D2| D1| D0| ACK/N |
+---+---+---+---+---+---+---+---+-------+
  1   2   3   4   5   6   7   8     9
             SCL Clock Pulses

The receiver uses the ninth clock pulse to acknowledge or not acknowledge the byte.

Data Transfer Rules

  • Data is transmitted most-significant bit first.
  • Each byte contains eight data bits.
  • Every byte is followed by an ACK/NACK clock.
  • SDA remains stable while SCL is HIGH during normal data bits.
  • START, repeated START, and STOP define transaction boundaries.

9. Register-Based Write Transaction

Many I2C targets contain internal registers. To write to one of these registers, the controller sends the target address, register address, and data.

The meaning and order of register-address and data bytes depend on the target device datasheet. Not every I2C device uses the same register protocol.

11. LPC2129 I2C Status Codes

The LPC2129 I2C controller provides status information through the I2STAT register. Software uses these codes to determine which stage of the transaction has completed.

Status Code Meaning
0x08 START condition transmitted.
0x10 Repeated START condition transmitted.
0x18 SLA+W transmitted and ACK received.
0x20 SLA+W transmitted and NACK received.
0x28 Data transmitted and ACK received.
0x30 Data transmitted and NACK received.
0x38 Arbitration lost.
0x40 SLA+R transmitted and ACK received.
0x48 SLA+R transmitted and NACK received.
0x50 Data received and ACK returned.
0x58 Data received and NACK returned.
The status codes are the standard LPC21xx I2C controller state-machine values. The least significant status bits are not significant; software commonly evaluates I2STAT & 0xF8.

12. Basic Address Byte Calculation in Embedded C

The following standalone C example demonstrates how to construct the address byte for a 7-bit I2C target. 

#include <stdio.h>

int main(void)
{
    unsigned char address = 0x48;

    unsigned char write_byte;
    unsigned char read_byte;

    write_byte = (address << 1) | 0U;
    read_byte  = (address << 1) | 1U;

    printf("7-bit address : 0x%02X\n", address);
    printf("Write byte    : 0x%02X\n", write_byte);
    printf("Read byte     : 0x%02X\n", read_byte);

    return 0;
}

Expected Result

7-bit address : 0x48
Write byte    : 0x90
Read byte     : 0x91

This program demonstrates address formatting only. It does not access the LPC2129 I2C peripheral or communicate with an external target.

13. Common I2C Addressing and Transfer Errors

Error Possible Cause
Wrong target selected Incorrect 7-bit address.
Unexpected NACK Wrong address, device unavailable, or invalid command.
Incorrect read/write operation R/W bit incorrectly constructed.
Wrong register data Incorrect internal register address or byte order.
Read transaction fails Missing repeated START or incorrect target protocol.
Unexpected extra data Controller did not send NACK after the final byte.
Address conflict Multiple targets respond to the same address.

14. Interview Questions and Answers

Q1. What is 7-bit I2C addressing?

It uses seven bits to identify a target. An additional R/W bit is transmitted as the eighth bit of the address byte.

Q2. What is the R/W bit?

It specifies the direction of the data phase. Zero means write and one means read.

Q3. What is the difference between a 7-bit and 10-bit address?

A 7-bit address is transmitted in one address byte, whereas a 10-bit address requires a two-byte address sequence.

Q4. What is ACK?

ACK is a LOW level on SDA during the ninth clock pulse.

Q5. What is NACK?

NACK is a HIGH level on SDA during the ninth clock pulse.

Q6. Who generates ACK?

The receiver generates ACK after receiving a byte.

Q7. Why does the controller send NACK after the final read byte?

It indicates that the controller does not want another byte from the target.

Q8. What does SLA+W mean?

It means the target address followed by the write direction bit.

Q9. What does status code 0x40 indicate?

SLA+R has been transmitted and an ACK has been received.

Q10. What does status code 0x58 indicate?

A data byte has been received and NACK has been returned.

17. Lesson Summary

  • I2C uses target addresses to select devices on a shared bus.
  • 7-bit addressing uses seven address bits and one R/W bit.
  • 10-bit addressing uses a two-byte address sequence.
  • R/W = 0 indicates write; R/W = 1 indicates read.
  • Each transferred byte is followed by an ACK/NACK clock.
  • ACK is SDA LOW; NACK is SDA HIGH.
  • Register-based reads commonly use repeated START.
  • The LPC2129 I2STAT register reports I2C state-machine status.
  • Software should check status after each bus operation.
