Lesson 05: LPC2129 I2C Architecture and Registers

Study the internal I2C peripheral architecture of the LPC2129, its SDA and SCL connections, register organization, control logic, status reporting, data transfer, and clock configuration.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain the I2C peripheral architecture of the LPC2129.
  • Identify the SDA0 and SCL0 pins.
  • Understand the function of each I2C register.
  • Configure the I2C control register.
  • Interpret I2C status codes.
  • Understand the I2C data and slave address registers.
  • Configure the SCL clock frequency.
  • Explain how the I2C controller communicates with external devices.

2. Introduction to LPC2129 I2C Peripheral

The LPC2129 microcontroller contains an on-chip I2C (Inter-Integrated Circuit) interface. It provides a synchronous, two-wire communication interface for connecting external devices.

The I2C peripheral can operate as a master or a slave. In master operation, it generates the clock and controls the communication sequence. In slave operation, it responds to its configured address.

Main Features

  • Two-wire serial communication using SDA and SCL.
  • Master and slave operating modes.
  • 7-bit and 10-bit addressing support.
  • START, repeated START, and STOP generation.
  • ACK and NACK handling.
  • Interrupt/status-based communication.
  • Programmable SCL clock timing.
  • Hardware-assisted serial data transfer.
The LPC2129 has one I2C interface, commonly identified as I2C0. Its signals are SDA0 and SCL0.

4. LPC2129 I2C Pin Configuration

The LPC2129 uses two multiplexed pins for its I2C interface.

Signal Pin Function
SDA0 P0.2 Serial Data
SCL0 P0.3 Serial Clock

PINSEL0 Configuration

The PINSEL0 register selects the alternate functions of Port 0 pins.

  • P0.2 uses PINSEL0 bits 5:4.
  • P0.3 uses PINSEL0 bits 7:6.
  • Function selection 01 selects SDA0 on P0.2.
  • Function selection 01 selects SCL0 on P0.3.
/* Configure P0.2 as SDA0 and P0.3 as SCL0 */

PINSEL0 &= ~(0xFU << 4);
PINSEL0 |=  (0x5U << 4);
The I2C bus uses open-drain/open-collector-style signaling. External pull-up resistors are required on SDA and SCL for a physical bus. The correct resistor values depend on bus capacitance, voltage, speed, and device specifications.

5. LPC2129 I2C Register Map

The I2C peripheral is controlled through memory-mapped registers. Software accesses these registers using their addresses or the corresponding device header definitions.

Register Address Purpose
I2CONSET 0xE001C000 Set I2C control bits.
I2STAT 0xE001C004 Read I2C status.
I2DAT 0xE001C008 Read or write data.
I2ADR 0xE001C00C Slave address configuration.
I2SCLH 0xE001C010 SCL HIGH period count.
I2SCLL 0xE001C014 SCL LOW period count.
I2CONCLR 0xE001C018 Clear I2C control bits.
These are the LPC21xx I2C0 register addresses. Use the device-specific header file and verify that the selected Keil target is the correct LPC2129 device.

6. I2CONSET Register

I2CONSET is the I2C control set register. Writing a 1 to a control bit requests that the corresponding bit be set.

Important Bit Fields

I2CONSET Register 
Bit:  7   6   5   4   3   2   1   0
     +---+---+---+---+---+---+---+---+
     | - |EN |STA|STO| SI| AA| - | - |
     +---+---+---+---+---+---+---+---+

EN  = I2C Enable
STA = START
STO = STOP
SI  = Interrupt Flag
AA  = Assert Acknowledge
-   = Reserved
Bit Name Function
7 Reserved Must not be used.
6 I2EN Enables the I2C interface.
5 STA Requests a START or repeated START condition.
4 STO Requests a STOP condition.
3 SI Indicates that the I2C state machine requires service.
2 AA Controls acknowledgment behavior.
1:0 Reserved Must not be used.

Common Operations

/* Enable I2C */
I2CONSET = (1U << 6);

/* Request START */
I2CONSET = (1U << 5);

/* Request STOP */
I2CONSET = (1U << 4);

/* Enable acknowledgment */
I2CONSET = (1U << 2);
I2CONSET is a write-one-to-set control register. A write of zero to a bit does not clear that bit. Use I2CONCLR for the corresponding clear operations.

7. I2CONCLR Register

I2CONCLR is used to clear selected I2C control bits. Writing a 1 to a supported clear bit clears the corresponding control function.

Bit Name Function
6 I2ENC Clears I2EN and disables the I2C interface.
5 STAC Clears the START request.
3 SIC Clears the SI flag.
2 AAC Clears the AA control bit.

Example

/* Clear START request */
I2CONCLR = (1U << 5);

/* Clear SI flag */
I2CONCLR = (1U << 3);

/* Clear AA */
I2CONCLR = (1U << 2);

/* Disable I2C */
I2CONCLR = (1U << 6);
Do not confuse I2CONSET and I2CONCLR. They have different purposes. Also, do not assume that writing zero to I2CONCLR clears every control bit.

8. I2STAT Register

I2STAT is a read-only status register. It reports the current state of the I2C controller.

The status code is located in bits 7:3. The lower three bits are not significant for status decoding.

I2STAT Register Format 
Bit:  7   6   5   4   3   2   1   0
     +-------------------+-----------+
     |    STATUS[7:3]    | Reserved  |
     +-------------------+-----------+

Status code = I2STAT & 0xF8

Important Status Codes

Status Meaning
0x08 START condition transmitted.
0x10 Repeated START condition transmitted.
0x18 SLA+W transmitted and ACK received.
0x20 SLA+W transmitted and NACK received.
0x28 Data transmitted and ACK received.
0x30 Data transmitted and NACK received.
0x38 Arbitration lost.
0x40 SLA+R transmitted and ACK received.
0x48 SLA+R transmitted and NACK received.
0x50 Data received and ACK returned.
0x58 Data received and NACK returned.

Reading the Status Register

unsigned int status;

status = I2STAT & 0xF8U;

The mask 0xF8 removes the lower three bits and retains the status field.

Software should use the status code to determine the next action. For example, after status 0x08, the controller can proceed to transmit the target address.

9. I2DAT Register

I2DAT is the I2C data register. It is used to hold the byte being transmitted or received.

Functions

  • Stores a byte before transmission.
  • Provides a received byte to the CPU.
  • Works with the I2C hardware shift mechanism.
  • Participates in address and data transfer operations.

Register Format

I2DAT Register 
Bit:  7   6   5   4   3   2   1   0
     +---+---+---+---+---+---+---+---+
     | D7| D6| D5| D4| D3| D2| D1| D0|
     +---+---+---+---+---+---+---+---+

             8-bit data

Example: Write Data

/* Load a data byte for transmission */
I2DAT = 0x55U;

Example: Read Data

unsigned char received_data;

/* Read the received byte */
received_data = (unsigned char)I2DAT;
I2DAT must be accessed in the correct I2C state-machine sequence. Do not assume that writing or reading this register alone completes a transfer.

10. I2ADR Register

I2ADR stores the address used when the LPC2129 operates as an I2C slave.

The address field occupies bits 7:1. Bit 0 is used for general-call recognition.

I2ADR Register Format 
Bit:  7   6   5   4   3   2   1   0
     +-----------------------+---+
     |     Slave Address     | GC|
     +-----------------------+---+

Bits 7:1 = Slave address
Bit 0    = General Call recognition

Example

Suppose the LPC2129 is configured with the 7-bit slave address 0x50. 

/* Configure 7-bit slave address */
I2ADR = (0x50U << 1);

The general-call bit remains zero in this example.

I2ADR is relevant when the LPC2129 is acting as a slave. A master-only application normally does not need to configure its own slave address.

11. I2SCLH and I2SCLL Registers

The I2SCLH and I2SCLL registers determine the HIGH and LOW periods of the SCL clock.

  • I2SCLH controls the SCL HIGH period.
  • I2SCLL controls the SCL LOW period.
  • Both registers contain programmable timing counts.
  • The values are selected according to PCLK and the required bus speed.

SCL Frequency Formula

The approximate I2C clock frequency is: 

SCL Frequency = PCLK / (I2SCLH + I2SCLL)

Where:

  • PCLK = Peripheral Clock.
  • I2SCLH = SCL HIGH period count.
  • I2SCLL = SCL LOW period count.

Example: Configure 100 kHz I2C

Project clock configuration:

  • CCLK = 60 MHz
  • PCLK = 15 MHz
  • Required SCL frequency = 100 kHz

Choose equal HIGH and LOW counts:

I2SCLH = 75;
I2SCLL = 75;

SCL = 15,000,000 / (75 + 75)

SCL = 15,000,000 / 150

SCL = 100,000 Hz

SCL = 100 kHz
This is a nominal timing calculation. The selected HIGH and LOW periods must also satisfy the minimum timing requirements of the chosen I2C speed mode.

12. Enabling the LPC2129 I2C Peripheral

Before starting communication, software must configure the pin functions, clock timing, and peripheral enable bit.

Initialization Sequence

  1. Configure P0.2 as SDA0.
  2. Configure P0.3 as SCL0.
  3. Set I2SCLH and I2SCLL for the required bus speed.
  4. Clear pending control flags if necessary.
  5. Set the I2EN bit in I2CONSET.
  6. Start the required I2C transaction.

Example: I2C Initialization

#include <LPC21xx.h>

#define I2C_I2EN (1U << 6)

void I2C_Init(void)
{
    /* Configure SDA0 and SCL0 pin functions */
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    /* Configure nominal 100 kHz SCL */
    I2SCLH = 75U;
    I2SCLL = 75U;

    /* Enable I2C peripheral */
    I2CONSET = I2C_I2EN;
}

int main(void)
{
    I2C_Init();

    while (1)
    {
        /* I2C application code */
    }
}

Expected Register Configuration

Register Expected Value Purpose
PINSEL0 Relevant fields = 01 Select SDA0 and SCL0.
I2SCLH 75 HIGH period count.
I2SCLL 75 LOW period count.
I2CONSET Bit 6 set Enable I2C.
This initialization configures the peripheral but does not perform a complete transaction. A complete driver must handle START, address transmission, ACK/NACK, data transfer, STOP, and error conditions.

13. I2C Master and Slave Operation

Master Mode

  • Generates the SCL clock.
  • Initiates communication using START.
  • Transmits the target address.
  • Controls the read/write direction.
  • Generates STOP when the transaction is complete.

Slave Mode

  • Waits for its configured address.
  • Responds when its address is matched.
  • Receives or transmits data depending on the R/W bit.
  • Uses the I2C status machine to manage communication.
Master and Slave Communication 
       LPC2129 Master
              |
        SDA0 / SCL0
              |
       +------+------+
       |             |
   Sensor         EEPROM
    Slave          Slave

Master:
- Generates clock
- Selects target
- Controls transaction

Slave:
- Recognizes address
- Responds to master
- Transfers requested data

15. Common Programming Mistakes

  • Using the wrong PINSEL0 fields for SDA0 and SCL0.
  • Forgetting to configure the I2C clock registers.
  • Using an incorrect PCLK value in clock calculations.
  • Confusing I2CONSET with I2CONCLR.
  • Reading I2STAT without masking the lower three bits.
  • Writing data before the controller reaches the appropriate state.
  • Ignoring NACK and arbitration-lost status codes.
  • Using I2ADR as if it were the target address register in master mode.
  • Forgetting external pull-up resistors on a physical I2C bus.
  • Assuming peripheral initialization proves that a target is responding.

16. Interview Questions and Answers

Q1. Which I2C interface is available on LPC2129?

LPC2129 provides one I2C interface, I2C0.

Q2. Which pins are used for I2C0?

P0.2 is SDA0 and P0.3 is SCL0.

Q3. What is the function of I2CONSET?

It sets I2C control bits such as I2EN, STA, STO, SI, and AA.

Q4. What is the function of I2CONCLR?

It clears supported I2C control bits.

Q5. What is the function of I2STAT?

It reports the current I2C controller status.

Q6. What is the function of I2DAT?

It stores transmitted or received I2C data.

Q7. What is the function of I2ADR?

It stores the LPC2129's own address when operating as an I2C slave.

Q8. What do I2SCLH and I2SCLL control?

They determine the HIGH and LOW periods of the SCL clock.

Q9. How is the SCL frequency calculated?

SCL frequency is approximately PCLK divided by the sum of I2SCLH and I2SCLL.

Q10. Why are pull-up resistors required?

I2C uses open-drain signaling. Pull-up resistors establish the HIGH level on SDA and SCL.
