Lesson 08: I2C Programming Using Embedded C

Learn to configure and program the LPC2129 I2C peripheral using Embedded C. Implement master transmission, reception, register-based communication, reusable functions and basic error handling.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Initialize the LPC2129 I2C0 peripheral.
  • Configure SDA0 and SCL0 pin functions.
  • Calculate I2C clock timing.
  • Generate START and STOP conditions.
  • Transmit target addresses and data bytes.
  • Receive data using ACK and NACK.
  • Read an internal register using repeated START.
  • Develop reusable I2C driver functions.
  • Identify common I2C communication errors.

2. LPC2129 I2C Peripheral Overview

The LPC2129 contains an I2C interface that supports communication with external I2C devices. The peripheral can operate as a master or target.

In this lesson, the LPC2129 is primarily used as an I2C master to communicate with external sensors, EEPROMs and other peripheral devices.

3. I2C Pin Configuration

The LPC2129 I2C0 interface uses the following pins:

Pin Alternate Function Purpose
P0.2 SDA0 Serial data
P0.3 SCL0 Serial clock

The PINSEL0 register selects the alternate functions. Each pin uses a two-bit function-selection field. 

#include <LPC21xx.h>

void I2C0_Pin_Init(void)
{
    /* Clear P0.2 and P0.3 function fields */
    PINSEL0 &= ~(0xFU << 4);

    /* Select SDA0 and SCL0 */
    PINSEL0 |= (0x5U << 4);
}
P0.2 uses PINSEL0 bits 5:4, and P0.3 uses bits 7:6. The value 01 selects the I2C function for each pin.

4. I2C Clock Configuration

The I2C clock is configured using I2SCLH and I2SCLL. These registers determine the HIGH and LOW portions of the SCL clock period.

Approximate clock relationship:

SCL Frequency = PCLK / (I2SCLH + I2SCLL)

For the project clock configuration:

  • CCLK = 60 MHz
  • PCLK = 15 MHz
  • Desired SCL frequency = 100 kHz

Choose equal HIGH and LOW counts:

I2SCLH = 75;
I2SCLL = 75;

SCL = 15,000,000 / (75 + 75)

SCL = 100,000 Hz

SCL = 100 kHz
This is a nominal timing calculation. Actual bus timing must also satisfy the I2C timing specification and the electrical characteristics of the connected devices. Pull-up resistance, bus capacitance and signal rise time affect physical communication.

5. I2C Control Register Bit Definitions

The I2CONSET and I2CONCLR registers control the I2C state machine.

I2CONSET

Bit Name Purpose
2AAAssert acknowledge.
3SII2C interrupt/status flag.
4STORequest STOP condition.
5STARequest START condition.
6I2ENEnable I2C peripheral.

I2CONCLR

Bit Name Purpose
2AACClear acknowledge control.
3SICClear SI flag.
5STACClear START control.
6I2ENCDisable I2C peripheral.
Do not confuse I2CONSET and I2CONCLR. They have different register functions even where corresponding control bits use the same bit position.

6. I2C Initialization Function

Initialization configures the I2C pins, clock timing and peripheral enable bit. 

#include <LPC21xx.h>

#define I2C_AA   (1U << 2)
#define I2C_SI   (1U << 3)
#define I2C_STO  (1U << 4)
#define I2C_STA  (1U << 5)
#define I2C_I2EN (1U << 6)

#define I2C_AAC  (1U << 2)
#define I2C_SIC  (1U << 3)
#define I2C_STAC (1U << 5)

void I2C0_Init(void)
{
    /* Configure I2C0 pins */
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    /* Configure nominal 100 kHz */
    I2SCLH = 75U;
    I2SCLL = 75U;

    /* Enable I2C peripheral */
    I2CONSET = I2C_I2EN;
}

Initialization Sequence

  1. Configure P0.2 and P0.3 alternate functions.
  2. Set the SCL HIGH period.
  3. Set the SCL LOW period.
  4. Enable the I2C peripheral.
  5. Begin communication when the bus is available.

7. Waiting for I2C Status

The SI flag indicates that the I2C controller has reached a state requiring software attention.

A blocking driver can poll this flag. A timeout prevents the processor from waiting forever if the expected state does not occur. 

int I2C0_WaitForSI(void)
{
    unsigned long timeout = 1000000UL;

    while ((I2CONSET & I2C_SI) == 0U)
    {
        if (--timeout == 0U)
        {
            return -1;
        }
    }

    return 0;
}
This is a software loop-count timeout, not a calibrated time interval. Its duration depends on CPU clock, compiler optimization and generated instructions.

8. Generating START and STOP Conditions

START Condition

int I2C0_Start(void)
{
    I2CONSET = I2C_STA;

    if (I2C0_WaitForSI() != 0)
        return -1;

    if ((I2STAT & 0xF8U) != 0x08U)
        return -1;

    I2CONCLR = I2C_STAC | I2C_SIC;

    return 0;
}

STOP Condition

void I2C0_Stop(void)
{
    I2CONSET = I2C_STO;
    I2CONCLR = I2C_SIC;
}

START begins a transaction. STOP requests the end of the transaction and releases the bus after the hardware completes the condition.

The START helper above is intended for an initial START condition. A repeated START normally produces status 0x10, which must be handled separately.

9. Master Transmitter Function

The following function sends one byte to an addressed target device. It checks the expected status after transmitting the address and data. 

int I2C0_WriteByte(unsigned char address,
                   unsigned char data)
{
    unsigned char status;

    /* Request START */
    I2CONSET = I2C_STA;

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x08U)
        goto error;

    I2CONCLR = I2C_STAC | I2C_SIC;

    /* Send SLA+W */
    I2DAT = (unsigned char)(address << 1);

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x18U)
        goto error;

    I2CONCLR = I2_SIC;

    /* Send data */
    I2DAT = data;

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x28U)
        goto error;

    I2C0_Stop();

    return 0;

error:
    I2C0_Stop();
    return -1;
}
In the code above, the SI clear operation must use the defined SIC mask. The correct line is: 
I2CONCLR = I2C_SIC;
Use this corrected line in your saved source.

Address Calculation

unsigned char address = 0x48U;

/* Write address byte */
unsigned char write_address = (address << 1);

/* Read address byte */
unsigned char read_address = (address << 1) | 1U;

/* write_address = 0x90 */
/* read_address  = 0x91 */

10. Master Receiver Function

A receiver routine must control the ACK sequence. It acknowledges intermediate bytes and sends NACK after the final byte.

Two-Byte Receive Example

int I2C0_ReadTwoBytes(unsigned char address,
                      unsigned char *buffer)
{
    unsigned char status;

    if (buffer == 0)
        return -1;

    /* Generate START */
    I2CONSET = I2C_STA;

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x08U)
        goto error;

    I2CONCLR = I2C_STAC | I2C_SIC;

    /* Send SLA+R */
    I2DAT = (unsigned char)((address << 1) | 1U);

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x40U)
        goto error;

    /* ACK first received byte */
    I2CONSET = I2C_AA;
    I2CONCLR = I2C_SIC;

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x50U)
        goto error;

    buffer[0] = (unsigned char)I2DAT;

    /* NACK final byte */
    I2CONCLR = I2C_AAC;
    I2CONCLR = I2C_SIC;

    if (I2C0_WaitForSI() != 0)
        goto error;

    status = I2STAT & 0xF8U;

    if (status != 0x58U)
        goto error;

    buffer[1] = (unsigned char)I2DAT;

    I2C0_Stop();

    return 0;

error:
    I2C0_Stop();
    return -1;
}
For a one-byte receive operation, the controller must arrange to return NACK for that byte. For longer reads, acknowledge all intermediate bytes and NACK the final one.

11. Reading an Internal Register Using Repeated START

Many sensors and EEPROMs contain internal registers. To read one, the master first writes the register address and then changes direction using a repeated START.

   |

   |

   |

   |

   |
 NACK
   |

Transaction Pseudocode

START

Transmit target address + WRITE
Check status 0x18

Transmit internal register address
Check status 0x28

Generate repeated START
Check status 0x10

Transmit target address + READ
Check status 0x40

Receive data
Return NACK after final byte
Check status 0x58

Generate STOP

The repeated START keeps control of the bus while changing the transfer direction from write to read.

12. Transmitting Multiple Bytes

Multiple bytes can be sent during a single transaction. The driver should check the status after every transmitted byte before loading the next byte. 

unsigned char data_buffer[] =
{
    0x10U,
    0x20U,
    0x30U,
    0x40U
};

unsigned int data_length = sizeof(data_buffer);

Transmission Algorithm

  1. Generate START.
  2. Transmit SLA+W.
  3. Check status 0x18.
  4. Transmit the next data byte.
  5. Check status 0x28.
  6. Repeat until all bytes are transmitted.
  7. Generate STOP.
If a target returns NACK, the firmware should stop the normal transmission sequence and report an error.

14. Error Handling in I2C Programming

Status Meaning Suggested Handling
0x20 SLA+W NACK Check target address and bus connection.
0x30 Data transmitted, NACK received Check target readiness and protocol.
0x38 Arbitration lost Wait for bus availability and retry when appropriate.
0x48 SLA+R NACK Check target address and read support.
Timeout Expected SI state not reached Abort safely and investigate peripheral/bus state.

Recommended Error-Handling Practices

  • Check every important I2C status code.
  • Use bounded timeouts.
  • Handle address and data NACK separately.
  • Handle arbitration loss when multi-controller operation is possible.
  • Request STOP when appropriate.
  • Do not assume a STOP request has completed immediately.
  • Record error codes for debugging.
  • Keep the bus driver independent from application logic.

16. Common Programming Mistakes

Mistake Correction
Incorrect PINSEL configuration Configure P0.2 and P0.3 for I2C0.
Incorrect SCL calculation Use PCLK and both SCL timing registers.
Wrong target address format Use the 7-bit address and add the R/W bit.
Ignoring I2STAT Check the state after each operation.
Incorrect SI clearing Clear SI through I2CONCLR bit 3.
Incorrect final receive ACK Return NACK after the final byte.
Missing physical pull-ups Use suitable pull-up resistors on SDA and SCL.
No timeout handling Use bounded waits and error recovery.

18. Interview Questions and Answers

Q1. Which pins are used by LPC2129 I2C0?

P0.2 is SDA0 and P0.3 is SCL0.

Q2. Which registers configure the I2C clock?

I2SCLH and I2SCLL.

Q3. What is the purpose of I2STAT?

It reports the current I2C state-machine status.

Q4. What does I2DAT do?

It holds the transmitted or received data byte.

Q5. What does SI indicate?

The I2C controller has reached a state requiring software service.

Q6. What is the purpose of I2CONCLR?

It clears selected I2C control flags and control bits.

Q7. Why is a timeout required?

It prevents firmware from waiting indefinitely for a status transition.

Q8. Why is a repeated START used?

It allows a combined transaction, such as writing a register address and then reading its contents without releasing the bus.

Q9. What is the purpose of a modular I2C driver?

It separates hardware operations from application code and improves reuse and maintenance.

Q10. Why are pull-up resistors needed?

I2C uses open-drain/open-collector signaling, so pull-ups establish the HIGH bus level.
