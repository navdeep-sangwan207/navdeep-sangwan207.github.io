Lesson 03: I2C START and STOP Conditions

Understand START, repeated START, and STOP conditions, their electrical transitions, timing behavior, and implementation using the LPC2129 I2C controller.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain the purpose of an I2C START condition.
  • Understand the electrical transition that creates START.
  • Explain the STOP condition and its electrical transition.
  • Understand repeated START conditions.
  • Differentiate START, repeated START, and STOP.
  • Understand the relationship between SDA and SCL.
  • Identify the timing requirements of these conditions.
  • Understand the LPC2129 control bits used to generate them.

2. Introduction to I2C Bus Conditions

I2C communication uses special signal transitions to identify the beginning and end of a transaction. These transitions are called START and STOP conditions.

Both conditions are generated by changing SDA while SCL is HIGH.

Important rule: During normal I2C data transfer, SDA should remain stable while SCL is HIGH. START and STOP are special exceptions that use an SDA transition while SCL is HIGH.

Three Important Conditions

Condition Function
START (S) Begins an I2C transaction.
Repeated START (Sr) Begins another address phase without releasing the bus.
STOP (P) Terminates the current I2C transaction.

3. START Condition

A START condition indicates the beginning of an I2C transaction. It is generated by the controller.

Electrical Definition

A START condition occurs when SDA changes from HIGH to LOW while SCL remains HIGH.

START Condition 
                 START
                   |
SCL  HIGH  -------------------------------
                   |
SDA  HIGH  --------\______________________
                   |
                HIGH to LOW
                while SCL is HIGH

START Condition Sequence

  1. The I2C bus is initially idle.
  2. Both SDA and SCL are HIGH.
  3. The controller pulls SDA LOW while SCL remains HIGH.
  4. The START condition is recognized by connected devices.
  5. The controller begins transmitting the address byte.

Purpose of START

  • Indicates the beginning of communication.
  • Alerts connected targets that a transaction is starting.
  • Prepares the bus for address transmission.
  • Allows the controller to select a target device.

4. STOP Condition

A STOP condition indicates the end of an I2C transaction. After STOP, the bus is normally released and returns to the idle state.

Electrical Definition

A STOP condition occurs when SDA changes from LOW to HIGH while SCL remains HIGH.

STOP Condition 
                 STOP
                   |
SCL  HIGH  -------------------------------
                   |
SDA  LOW   ________/----------------------
                   |
                LOW to HIGH
                while SCL is HIGH

STOP Condition Sequence

  1. The controller completes the data transfer.
  2. The controller prepares SDA LOW while SCL is LOW.
  3. The controller releases SCL HIGH.
  4. The controller releases SDA HIGH while SCL is HIGH.
  5. The STOP condition is recognized.
  6. The bus returns to the idle state if no other transaction begins.

Purpose of STOP

  • Terminates the current transaction.
  • Releases the bus for another transaction.
  • Indicates that the current transfer is complete.
  • Allows target devices to return to their waiting state.

5. Repeated START Condition

A repeated START condition is generated when a controller wants to begin another address phase without generating a STOP condition first.

It has the same electrical transition as a normal START: SDA changes from HIGH to LOW while SCL is HIGH. The difference is its position within an ongoing transaction.

Repeated START Condition 
  START       ADDRESS + WRITE       Sr
    |                |               |
    v                v               v

---S---[ Address + W ]---[ Register ]---Sr---
                                        |
                                        v
                              ADDRESS + READ
                                        |
                                        v
                                  DATA + NACK
                                        |
                                        v
                                      STOP

Why is Repeated START Used?

Many peripheral devices require a register address to be written before data can be read from that register. Repeated START allows the controller to change the communication direction without releasing the bus.

Example: Reading an I2C Sensor Register

  1. Generate START.
  2. Send the sensor's address with the write direction.
  3. Receive ACK from the sensor.
  4. Send the internal register address.
  5. Receive ACK.
  6. Generate repeated START.
  7. Send the sensor address with the read direction.
  8. Receive ACK.
  9. Read the requested data byte.
  10. Send NACK if no additional byte is required.
  11. Generate STOP.
Repeated START is especially common in register-based sensor and EEPROM communication. The exact sequence depends on the peripheral's communication protocol.

7. Relationship Between SDA and SCL

The timing relationship between SDA and SCL is important for reliable I2C communication.

Normal Data Transfer

  • SDA is normally changed while SCL is LOW.
  • SDA remains stable while SCL is HIGH.
  • The receiver samples the data during the HIGH period of SCL.

Special Conditions

  • START: SDA changes HIGH to LOW while SCL is HIGH.
  • STOP: SDA changes LOW to HIGH while SCL is HIGH.

8. START and STOP Timing Requirements

I2C defines minimum timing requirements for START, repeated START, STOP, and data transitions. These timing parameters vary by speed mode.

Timing Parameter Description
tHD;STA START condition hold time.
tSU;STA Repeated START setup time.
tSU;STO STOP condition setup time.
tBUF Bus-free time between a STOP and the next START.
tLOW SCL LOW period.
tHIGH SCL HIGH period.

Why Timing Matters

  • Ensures all connected devices detect bus conditions.
  • Prevents START and STOP transitions from being mistaken for data.
  • Supports reliable communication at the selected bus speed.
  • Allows devices to meet setup and hold requirements.
Do not use one fixed timing value for every I2C speed mode. Refer to the I2C specification and the target device datasheet when calculating timing requirements.

9. LPC2129 I2C Control Register Bits

The LPC2129 controls I2C operations using the I2CONSET and I2CONCLR registers.

Important I2CONSET Bits

Bit Name Function
7 I2EN Enables the I2C interface.
6 STA Requests a START condition.
5 STO Requests a STOP condition.
4 SI I2C interrupt/status flag.
3 AA Controls acknowledgment behavior.

Control Register Operations

The controller requests a START condition by setting the STA bit in I2CONSET. 

I2CONSET = (1U << 6);

The controller requests a STOP condition by setting the STO bit. 

I2CONSET = (1U << 5);

The STA and STO bits are control requests. Hardware manages their completion according to the I2C state machine. Software must monitor the status and clear control flags as required.

Writing a control request does not mean the physical bus transition has already completed. Check the I2C status and controller behavior before proceeding.

10. Basic LPC2129 START and STOP Programming

The following example demonstrates the basic software requests for START and STOP conditions. It is an introductory register-level example, not a complete I2C transaction with an external target.

Example Program

#include <LPC21xx.h>

int main(void)
{
    /* Configure P0.2 as SDA0 and P0.3 as SCL0 */
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    /* Enable I2C interface */
    I2CONSET = (1U << 7);

    /* Request START condition */
    I2CONSET = (1U << 6);

    /* Wait for the I2C controller status */
    while ((I2CONSET & (1U << 3)) == 0U)
    {
        /* Wait for SI flag */
    }

    /* Clear SI and STA control requests */
    I2CONCLR = (1U << 3) | (1U << 5);

    /* Request STOP condition */
    I2CONSET = (1U << 4);

    while (1)
    {
        /* Main application */
    }
}
Important correction for practical programming: LPC21xx I2C register control must follow the exact peripheral state machine. In this introductory example, the SI flag is bit 3, STA is bit 5, STO is bit 4, and I2EN is bit 6. I2CONCLR bit 5 clears STA, bit 4 clears SI, and bit 6 clears AA. Therefore, the complete example below uses the correct bit assignments and should be used instead.

Corrected Register-Level Example

#include <LPC21xx.h>

#define I2C_AA   (1U << 2)
#define I2C_SI   (1U << 3)
#define I2C_STO  (1U << 4)
#define I2C_STA  (1U << 5)
#define I2C_I2EN (1U << 6)

int main(void)
{
    /* Select SDA0 and SCL0 functions */
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    /* Enable I2C peripheral */
    I2CONSET = I2C_I2EN;

    /* Request START */
    I2CONSET = I2C_STA;

    /* Wait for START-related status */
    while ((I2CONSET & I2C_SI) == 0U)
    {
    }

    /* Read status in a real transaction before proceeding */
    {
        volatile unsigned int status = I2STAT;
        (void)status;
    }

    /* Clear START request and SI flag */
    I2CONCLR = I2C_STA | I2C_SI;

    /* Request STOP */
    I2CONSET = I2C_STO;

    while (1)
    {
    }
}
Register bit assignments: I2CONSET: AA bit 2, SI bit 3, STO bit 4, STA bit 5, I2EN bit 6.
I2CONCLR: AAC bit 2, SIC bit 3, STAC bit 5, I2ENC bit 6.

This code is a register-control illustration only. A production driver must inspect I2STAT after each state transition, configure SCLH/SCLL, handle errors, and communicate with a responding target.

11. Common Mistakes

  • Generating START when SCL is LOW instead of HIGH.
  • Generating STOP when SCL is LOW instead of HIGH.
  • Changing SDA during the HIGH period of normal data transfer.
  • Confusing repeated START with STOP followed by START.
  • Not checking the I2C status register.
  • Using incorrect I2CONSET and I2CONCLR bit positions.
  • Assuming a START request means a target has acknowledged.
  • Ignoring the bus-free time requirement after STOP.

12. Interview Questions and Answers

Q1. What is an I2C START condition?

It is an SDA HIGH-to-LOW transition while SCL remains HIGH.

Q2. What is an I2C STOP condition?

It is an SDA LOW-to-HIGH transition while SCL remains HIGH.

Q3. What is a repeated START condition?

It is another START condition generated during an ongoing transaction without first generating STOP.

Q4. Why is repeated START used?

It allows the controller to begin a new address phase without releasing the bus.

Q5. What is the idle state of the I2C bus?

Both SDA and SCL are HIGH.

Q6. Which register requests START in LPC2129?

I2CONSET, using the STA bit (bit 5).

Q7. Which register requests STOP in LPC2129?

I2CONSET, using the STO bit (bit 4).

Q8. Which register reports I2C status?

I2STAT.

Q9. Can START and STOP be generated during normal data transfer?

They are special bus conditions. A START or repeated START begins an address phase, while STOP ends the transaction.

Q10. What is tBUF?

It is the minimum bus-free time between a STOP condition and the next START condition.

15. Lesson Summary

  • START begins an I2C transaction.
  • STOP terminates an I2C transaction.
  • Repeated START begins another address phase without STOP.
  • START and repeated START use SDA HIGH-to-LOW while SCL is HIGH.
  • STOP uses SDA LOW-to-HIGH while SCL is HIGH.
  • Normal data transitions occur while SCL is LOW.
  • I2C defines timing requirements for START and STOP.
  • LPC2129 uses STA and STO control bits in I2CONSET.
  • I2STAT must be checked to determine the controller state.
