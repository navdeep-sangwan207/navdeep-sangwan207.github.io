Lesson 01: Introduction to I2C

Understand the fundamentals of Inter-Integrated Circuit communication, its two-wire interface, operating principle, addressing mechanism, and applications in embedded systems.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Define I2C communication.
  • Understand why I2C is used in embedded systems.
  • Identify the SDA and SCL signals.
  • Explain the basic I2C communication process.
  • Understand master and slave devices.
  • Explain device addressing and data acknowledgment.
  • Identify the advantages and limitations of I2C.
  • Understand the I2C interface available in LPC2129.

2. What is I2C?

I2C stands for Inter-Integrated Circuit. It is a synchronous, serial communication protocol used to transfer data between integrated circuits.

I2C was originally developed by Philips Semiconductor (now NXP Semiconductors) to simplify communication between a microcontroller and peripheral ICs.

It is commonly used to connect microcontrollers with sensors, memory devices, real-time clocks, display controllers, and other electronic components.

Definition: I2C is a synchronous, two-wire, serial communication bus that allows multiple devices to communicate using a shared clock line and a shared bidirectional data line.

Why is I2C Required?

An embedded system may contain several peripheral devices. Connecting every device using separate communication and control signals increases the number of required microcontroller pins and PCB connections.

I2C reduces this complexity by allowing multiple compatible devices to share the same two communication lines.

3. I2C Communication Interface

I2C uses two main signal lines:

Signal Full Form Function
SDA Serial Data Transfers address and data bits between devices.
SCL Serial Clock Provides clock synchronization for data transfer.

3.1 SDA – Serial Data Line

SDA is a bidirectional data line. It carries address, control, and data information between the master and slave devices.

Depending on the communication operation, the master or the selected slave may transmit data on SDA.

3.2 SCL – Serial Clock Line

SCL carries the clock signal used to synchronize communication.

In a typical single-master I2C transaction, the master generates the clock. In a multi-controller system, clock synchronization and arbitration determine which controller controls the bus.

I2C Two-Wire Interface 
       +-------------------+
       |   Microcontroller |
       |      (Master)     |
       +-------------------+
             |       |
            SDA     SCL
             |       |
   ==========|=======|========== I2C Bus
             |       |
       +-----+-------+-----+
       |                   |
+-------------+     +-------------+
| I2C Sensor  |     | I2C EEPROM  |
|   Slave 1   |     |   Slave 2   |
+-------------+     +-------------+

       SDA and SCL are shared
       by all connected devices.
Important: I2C normally uses open-drain or open-collector outputs. Pull-up resistors are required on SDA and SCL so that the bus can return to its HIGH state.

4. Basic Working Principle of I2C

I2C communication generally follows a master-initiated transaction. The master selects a slave device using its address and then performs a read or write operation.

Basic Communication Sequence

  1. The master generates a START condition.
  2. The master transmits the slave address.
  3. The master sends the read or write direction bit.
  4. The addressed slave responds with ACK or NACK.
  5. Data bytes are transferred between the devices.
  6. The receiver acknowledges received bytes when required.
  7. The master generates a STOP condition to end the transaction.
Basic I2C Transaction 
+-------+---------+------+--------+-------+
| START | ADDRESS | R/W  |  DATA  | STOP  |
+-------+---------+------+--------+-------+
                    |
                    +-- 0 = Write
                    +-- 1 = Read

ACK/NACK responses occur
after address and data bytes.

Each address or data byte contains eight bits. The receiver normally responds with a ninth clock pulse by transmitting ACK or NACK.

A complete I2C transaction may contain multiple data bytes and repeated START conditions. The exact sequence depends on the peripheral device and the operation being performed.

5. Master and Slave Devices

5.1 Master Device

The master is the controller that initiates a transaction and addresses a target device.

Typical master responsibilities include:

  • Generating START and STOP conditions.
  • Transmitting the target slave address.
  • Selecting read or write direction.
  • Generating the SCL clock during a transaction.
  • Managing data transfer and acknowledgment.

5.2 Slave Device

A slave is a device that responds when it recognizes its own address on the bus.

Examples include:

  • Temperature sensors.
  • EEPROM memory devices.
  • Real-time clock modules.
  • Digital input/output expanders.
  • Display controller ICs.
A device's role as a controller or target is determined by the transaction. Some I2C devices can operate in different roles, depending on their capabilities.

6. I2C Addressing

Every I2C slave device must have an address that allows the master to select it.

The most common addressing format is 7-bit addressing. I2C also supports 10-bit addressing.

7-Bit Addressing

In 7-bit addressing, the slave address contains seven address bits. The eighth bit in the first transmitted byte indicates the direction of data transfer.

7-Bit Address and Direction Bit 
Bit:    7  6  5  4  3  2  1  0
       +-----------------------+
       |  7-bit address | R/W  |
       +-----------------------+

R/W = 0 : Write operation
R/W = 1 : Read operation

A 7-bit address provides 128 possible bit patterns. However, some address values are reserved by the I2C specification, so not all values are available for ordinary device addressing.

Example

Suppose a slave has the 7-bit address: 

0x50

The first address byte for a write operation is: 

(0x50 << 1) | 0 = 0xA0

For a read operation: 

(0x50 << 1) | 1 = 0xA1
The 7-bit address is conventionally written as 0x50. The transmitted address-plus-direction byte is 0xA0 for write or 0xA1 for read.

7. ACK and NACK

ACK and NACK are acknowledgment responses used to indicate whether a byte has been accepted or whether the receiver wants to end the transfer.

Response SDA During Ninth Clock Meaning
ACK LOW Receiver acknowledges the byte.
NACK HIGH Receiver does not acknowledge the byte.

After a receiver has accepted a byte, it pulls SDA LOW during the ninth clock pulse to indicate ACK.

A NACK can occur if no slave responds to the address, if a receiver cannot accept more data, or when a master finishes reading and signals that it does not want another byte.

8. I2C Speed Modes

I2C defines several standardized speed modes. The actual supported speed depends on the devices, bus capacitance, pull-up resistors, and electrical design.

Mode Maximum Clock Frequency
Standard-mode 100 kbit/s
Fast-mode 400 kbit/s
Fast-mode Plus 1 Mbit/s
High-speed mode 3.4 Mbit/s
Ultra Fast-mode 5 Mbit/s, unidirectional
Do not assume that an LPC2129 I2C application supports every I2C speed mode. The controller, peripheral devices, and electrical bus design must all support the selected mode.

9. Advantages of I2C

  • Requires only two communication signal lines.
  • Supports multiple devices on the same bus.
  • Provides address-based device selection.
  • Supports bidirectional communication.
  • Includes acknowledgment mechanisms.
  • Reduces wiring and microcontroller pin usage.
  • Widely supported by sensors and peripheral ICs.

10. Limitations of I2C

  • Generally slower than high-speed SPI communication.
  • Pull-up resistors are required.
  • Bus capacitance limits speed and cable length.
  • Devices may have address conflicts.
  • Bus faults can affect multiple connected devices.
  • Communication requires correct timing and bus management.

11. I2C in LPC2129

The LPC2129 microcontroller from NXP provides an I2C controller for communication with external I2C-compatible devices.

The I2C0 interface uses the following pins:

Pin Function
P0.2 SDA0 – I2C serial data
P0.3 SCL0 – I2C serial clock

Important LPC2129 I2C Registers

Register Function
I2CONSET Sets I2C control bits.
I2CONCLR Clears selected I2C control bits.
I2STAT Provides the I2C controller status.
I2DAT Holds the transmitted or received data byte.
I2ADR Stores the device address when operating as a slave.
I2SCLH Configures the SCL HIGH period.
I2SCLL Configures the SCL LOW period.
User project clock configuration:
CCLK = 60 MHz
PCLK = 15 MHz
The I2C clock is configured using I2SCLH and I2SCLL. Detailed register programming is covered in later lessons.

Applications with LPC2129

  • Reading temperature sensor data.
  • Writing and reading external EEPROM memory.
  • Reading time from an RTC module.
  • Communicating with I2C GPIO expanders.
  • Building embedded monitoring systems.

12. I2C vs SPI vs UART

Feature I2C SPI UART
Communication Synchronous Synchronous Asynchronous
Main Signals SDA, SCL MOSI, MISO, SCLK, CS TX, RX
Clock Shared clock Shared clock No shared clock
Device Selection Address Chip Select Usually separate interface or protocol
Wiring Two bus lines Typically four or more Typically two signal lines

I2C is useful when several low- or moderate-speed peripherals need to share a small number of wires. SPI is often selected for higher-speed synchronous communication, while UART is commonly used for asynchronous point-to-point serial communication.

13. Common Mistakes

  • Confusing SDA with SCL.
  • Assuming I2C is asynchronous communication.
  • Forgetting to configure the microcontroller pin functions.
  • Ignoring the need for suitable pull-up resistors.
  • Confusing a 7-bit slave address with the transmitted address byte.
  • Ignoring ACK and NACK responses.
  • Selecting a clock speed unsupported by a connected device.
  • Assuming a successful software build proves physical bus communication.

14. Interview Questions and Answers

Q1. What is I2C?

I2C is a synchronous serial communication protocol that uses SDA and SCL lines to communicate between integrated circuits.

Q2. What is the full form of I2C?

Inter-Integrated Circuit.

Q3. How many wires are used in I2C communication?

Two signal wires: SDA and SCL.

Q4. What is the function of SDA?

SDA carries address, control, and data information between I2C devices.

Q5. What is the function of SCL?

SCL carries the clock signal used to synchronize data communication.

Q6. What is a master device?

A master initiates a transaction and selects the target device by transmitting its address.

Q7. What is a slave device?

A slave responds when its address is selected during a communication transaction.

Q8. What is ACK?

ACK is an acknowledgment in which the receiver pulls SDA LOW during the ninth clock pulse.

Q9. What is the commonly used I2C address format?

Seven-bit addressing is commonly used. Ten-bit addressing is also supported.

Q10. Which pins are used for I2C0 in LPC2129?

P0.2 is SDA0 and P0.3 is SCL0.

17. Lesson Summary

  • I2C means Inter-Integrated Circuit.
  • It is a synchronous serial communication protocol.
  • It uses SDA for data and SCL for clock.
  • Multiple devices can share the same bus.
  • Devices are selected using slave addresses.
  • ACK and NACK indicate acknowledgment status.
  • I2C uses open-drain signaling with pull-up resistors.
  • LPC2129 provides an I2C controller using SDA0 and SCL0.
  • I2C is widely used for sensors, EEPROMs, RTCs, and displays.
