3. Exercise 1: Configure I2C0 Pins

Objective: Configure P0.2 as SDA0 and P0.3 as SCL0.

Program

#include <LPC21xx.h>

int main(void)
{
    /* Clear P0.2 and P0.3 function fields */
    PINSEL0 &= ~(0xFU << 4);

    /* Select SDA0 and SCL0 */
    PINSEL0 |= (0x5U << 4);

    while (1)
    {
    }
}

Expected Result

  • P0.2 is configured for SDA0.
  • P0.3 is configured for SCL0.
  • PINSEL0 bits 7:4 contain 0101.
Verify PINSEL0 in the Keil peripheral or register window. This confirms register configuration, not physical bus activity.

4. Exercise 2: Configure I2C Clock

Objective: Configure a nominal 100 kHz SCL clock.

Calculation

PCLK = 15 MHz

I2SCLH = 75
I2SCLL = 75

SCL = PCLK / (I2SCLH + I2SCLL)

SCL = 15,000,000 / 150

SCL = 100,000 Hz

SCL = 100 kHz

Program

#include <LPC21xx.h>

int main(void)
{
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    I2SCLH = 75U;
    I2SCLL = 75U;

    I2CONSET = (1U << 6);

    while (1)
    {
    }
}

Expected Result

The I2C peripheral is enabled with nominal SCL timing corresponding to 100 kHz.

Actual bus timing must satisfy the I2C specification and the connected devices' requirements. Rise time and bus capacitance also affect the physical SCL waveform.

5. Exercise 3: Generate a START Condition

Objective: Request START and check its status.

Program

#include <LPC21xx.h>

#define I2C_STA  (1U << 5)
#define I2C_SI   (1U << 3)
#define I2C_STAC (1U << 5)
#define I2C_SIC  (1U << 3)

int main(void)
{
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    I2SCLH = 75U;
    I2SCLL = 75U;

    I2CONSET = (1U << 6);

    I2CONSET = I2C_STA;

    while ((I2CONSET & I2C_SI) == 0U)
    {
    }

    if ((I2STAT & 0xF8U) == 0x08U)
    {
        /* START transmitted */
    }

    I2CONCLR = I2C_STAC | I2C_SIC;

    while (1)
    {
    }
}

Expected Result

When the controller completes the START operation, the expected master START status is 0x08.

This demonstration waits indefinitely if the expected SI state never occurs. Production firmware should use a bounded timeout and a suitable recovery path.

6. Exercise 4: Transmit a Target Address

Objective: Calculate and transmit SLA+W.

Address Calculation

7-bit target address = 0x48

SLA+W = 0x48 << 1

SLA+W = 0x90

SLA+R = (0x48 << 1) | 1

SLA+R = 0x91

Program Fragment

unsigned char target_address = 0x48U;

/* Load SLA+W into the data register */
I2DAT = (unsigned char)(target_address << 1);

/* Clear SI to continue the transaction */
I2CONCLR = (1U << 3);

Expected Result

The transmitted address byte is 0x90. If the target acknowledges it, the expected status is 0x18.

7. Exercise 5: Transmit a Data Byte

Objective: Transmit one byte after SLA+W is acknowledged.

Program Fragment

/* Example data byte */
I2DAT = 0x55U;

/* Clear SI to begin data transmission */
I2CONCLR = (1U << 3);

/* Wait for the next controller state */
while ((I2CONSET & (1U << 3)) == 0U)
{
}

/* Check data transmitted and ACK received */
if ((I2STAT & 0xF8U) == 0x28U)
{
    /* Data byte acknowledged */
}

Expected Result

If the target acknowledges the data byte, I2STAT reports 0x28.

9. Exercise 7: Receive Two Data Bytes

Objective: Receive two bytes and use ACK/NACK correctly.

Receive Sequence

  1. Generate START.
  2. Transmit SLA+R.
  3. Check SLA+R ACK status 0x40.
  4. Enable AA for the first received byte.
  5. Check status 0x50 and read the first byte.
  6. Clear AA before the final byte.
  7. Check status 0x58 and read the final byte.
  8. Request STOP.

Program Fragment

unsigned char received_data[2];

/* After SLA+R ACK: status 0x40 */

/* ACK the first received byte */
I2CONSET = (1U << 2);
I2CONCLR = (1U << 3);

/* Wait and check status 0x50 */
while ((I2CONSET & (1U << 3)) == 0U)
{
}

if ((I2STAT & 0xF8U) == 0x50U)
{
    received_data[0] = (unsigned char)I2DAT;
}

/* NACK the final received byte */
I2CONCLR = (1U << 2);
I2CONCLR = (1U << 3);

/* Wait and check status 0x58 */
while ((I2CONSET & (1U << 3)) == 0U)
{
}

if ((I2STAT & 0xF8U) == 0x58U)
{
    received_data[1] = (unsigned char)I2DAT;
}

/* Request STOP */
I2CONSET = (1U << 4);
I2CONCLR = (1U << 3);
This is a receive-sequence fragment. It assumes that initialization, START, SLA+R transmission and the 0x40 status have already been handled.

10. Exercise 8: Implement Timeout Handling

Objective: Avoid indefinite polling of SI.

Program

#include <LPC21xx.h>

#define I2C_SI (1U << 3)

int I2C_WaitForSI(void)
{
    unsigned long timeout = 1000000UL;

    while ((I2CONSET & I2C_SI) == 0U)
    {
        if (--timeout == 0U)
        {
            return -1;
        }
    }

    return 0;
}

int main(void)
{
    int result;

    result = I2C_WaitForSI();

    if (result == 0)
    {
        /* I2C controller needs service */
    }
    else
    {
        /* Timeout detected */
    }

    while (1)
    {
    }
}

Expected Result

The function returns 0 when SI is set and -1 when the software loop-count limit expires.

12. Exercise 10: Debug an I2C Program

Objective: Identify common register and communication errors.

Debugging Checklist

  • Verify the selected LPC2129 target device.
  • Check PINSEL0 configuration.
  • Check I2SCLH and I2SCLL values.
  • Verify I2CONSET I2EN bit.
  • Inspect I2STAT after START.
  • Inspect I2DAT after address transmission.
  • Check whether the target returns ACK or NACK.
  • Verify SI is cleared through I2CONCLR.
  • Check timeout and error branches.
  • Review STOP and recovery handling.
A missing external target can cause address NACK. A simulator that does not model the I2C bus may not reproduce real target responses.

15. Interview Questions and Answers

Q1. Which pins are used for LPC2129 I2C0?

P0.2 is SDA0 and P0.3 is SCL0.

Q2. What is the purpose of I2STAT?

It reports the current I2C controller state.

Q3. What is SLA+W?

The 7-bit target address shifted left by one, with the R/W bit set to zero.

Q4. What is SLA+R?

The 7-bit target address shifted left by one, with the R/W bit set to one.

Q5. What does status 0x28 indicate?

A data byte was transmitted and acknowledged.

Q6. Why does the receiver send NACK after the final byte?

It indicates that the master does not want another byte in the current receive sequence.

Q7. What is arbitration loss?

It occurs when a controller loses arbitration while multiple controllers are competing for the bus.

Q8. Why are pull-up resistors required?

They establish the HIGH level on the open-drain SDA and SCL lines.

Q9. Why is timeout handling important?

It prevents firmware from becoming stuck indefinitely while waiting for a peripheral event.

Q10. What is a repeated START?

A START condition generated without first releasing the bus using STOP.
