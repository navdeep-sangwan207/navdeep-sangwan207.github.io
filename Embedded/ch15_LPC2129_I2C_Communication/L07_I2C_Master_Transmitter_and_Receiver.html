Lesson 07: I2C Master Transmitter and Receiver

Understand how the LPC2129 communicates with I2C target devices in master-transmitter and master-receiver modes. Learn address transmission, data transfer, ACK/NACK handling, status codes and Embedded C programming.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain I2C master-transmitter operation.
  • Explain I2C master-receiver operation.
  • Understand the I2C master state machine.
  • Identify important I2C status codes.
  • Transmit a target address and data bytes.
  • Receive data bytes from a target device.
  • Understand ACK and NACK handling.
  • Use LPC2129 I2C registers in Embedded C programs.

2. Introduction to I2C Master Operation

I2C communication uses a controller-target architecture. The controller initiates communication and generates the SCL clock. The target responds to its address and participates in the requested data transfer.

When the LPC2129 operates as an I2C master, it can perform two main operations:

  • Master Transmitter: The LPC2129 sends data to an I2C target.
  • Master Receiver: The LPC2129 receives data from an I2C target.
I2C Master Communication 
             LPC2129
          I2C Controller
                |
          +-----+-----+
          |           |
         SDA         SCL
          |           |
    +-----+-----------+-----+
    |                       |
    v                       v
 I2C Target 1           I2C Target 2
 Sensor / EEPROM        RTC / Display

 LPC2129 controls START,
 address, direction and SCL
The master generates the clock and initiates the transaction. The target does not independently start a normal master-driven transaction.

3. I2C Master Transmitter

In master-transmitter mode, the LPC2129 sends data to an addressed target device.

Transmission Sequence

  1. Generate a START condition.
  2. Transmit the target address with the write bit (R/W = 0).
  3. Check whether the target acknowledges the address.
  4. Transmit the first data byte.
  5. Check the target's ACK response.
  6. Transmit additional bytes if required.
  7. Generate a STOP condition.
Master Transmitter Sequence 
       START
         |
         v
   Target Address
      + Write
         |
         v
     Target ACK?
         |
         v
      Data Byte
         |
         v
     Target ACK?
         |
         v
   Additional Data
     (if required)
         |
         v
        STOP

Example

Suppose the LPC2129 communicates with a target having the illustrative 7-bit address 0x48. 

7-bit target address = 0x48

Write bit = 0

Address byte = (0x48 << 1) | 0

Address byte = 0x90

The LPC2129 transmits 0x90 as the address byte. The target must acknowledge the address before normal data transmission proceeds.

4. I2C Master Receiver

In master-receiver mode, the LPC2129 reads data from an addressed target device.

Reception Sequence

  1. Generate a START condition.
  2. Transmit the target address with the read bit (R/W = 1).
  3. Check whether the target acknowledges the address.
  4. Enable ACK when another received byte is required.
  5. Read the received data from I2DAT.
  6. Send NACK after the final byte.
  7. Generate a STOP condition.
Master Receiver Sequence 
       START
         |
         v
   Target Address
      + Read
         |
         v
     Target ACK?
         |
         v
    Receive Data
         |
         v
   Controller ACK
   (more data needed)
         |
         v
    Receive Next Byte
         |
         v
   Controller NACK
   (final byte)
         |
         v
        STOP
In master-receiver mode, the LPC2129 controls whether the target should continue sending data. It acknowledges intermediate bytes and normally sends NACK after the final byte.

5. Address and R/W Bit

A standard 7-bit I2C address is transmitted together with a direction bit.

Address Byte Format 
      Bit 7       Bit 1   Bit 0
    +---------------------------+
    | 7-bit target address | R/W|
    +---------------------------+

    R/W = 0 : Write
    R/W = 1 : Read

Address Byte Calculation

Address Byte = (7-bit address << 1) | R/W

Example: Address 0x48

Operation Calculation Address Byte
Write (0x48 << 1) | 0 0x90
Read (0x48 << 1) | 1 0x91
The target address 0x48 is a 7-bit address in this example. The transmitted address bytes 0x90 and 0x91 are not separate 7-bit target addresses. They include the R/W bit.

6. ACK and NACK in Data Transfer

Every I2C address or data byte is followed by a ninth clock pulse used for acknowledgement.

ACK (Acknowledge)

  • The receiver pulls SDA LOW during the ACK clock.
  • It indicates successful reception of the byte.
  • It allows the transfer to continue.

NACK (Not Acknowledge)

  • SDA remains HIGH during the ninth clock.
  • It can indicate that a target did not recognize an address.
  • It can indicate that a target cannot accept more data.
  • In master-receiver mode, the controller sends NACK to indicate the final byte.
Condition Meaning
Address ACK Target recognized its address.
Address NACK No target acknowledged the address.
Data ACK Receiver accepted the transmitted byte.
Data NACK Receiver did not acknowledge the byte.
Final receive NACK Controller indicates that it does not require another byte.

7. LPC2129 I2C Registers Used in Master Operation

Register Purpose
I2CONSET Sets I2C control bits such as STA, STO, SI, AA and I2EN.
I2CONCLR Clears control bits such as STAC, SIC, AAC and I2ENC.
I2STAT Reports the current I2C bus state.
I2DAT Holds the transmitted or received data byte.
I2SCLH Controls SCL HIGH timing.
I2SCLL Controls SCL LOW timing.
I2ADR Contains the LPC2129's own address when operating as a target.

Important I2CONSET Bits

Bit Name Function
2 AA Assert acknowledge.
3 SI I2C interrupt/status flag.
4 STO Generate STOP condition.
5 STA Generate START condition.
6 I2EN Enable I2C peripheral.
I2CONSET and I2CONCLR are separate control registers. Their bit positions must be used correctly. For example, SI is bit 3, not bit 4, and I2EN is bit 6, not bit 7.

8. Important I2C Master Status Codes

The LPC2129 I2STAT register indicates the state of the I2C master state machine. These status codes help the firmware decide what action to perform next.

Status Meaning Operation
0x08 START transmitted Master transmitter/receiver
0x10 Repeated START transmitted Master transmitter/receiver
0x18 SLA+W transmitted, ACK received Master transmitter
0x20 SLA+W transmitted, NACK received Master transmitter
0x28 Data transmitted, ACK received Master transmitter
0x30 Data transmitted, NACK received Master transmitter
0x38 Arbitration lost Master operation
0x40 SLA+R transmitted, ACK received Master receiver
0x48 SLA+R transmitted, NACK received Master receiver
0x50 Data received, ACK returned Master receiver
0x58 Data received, NACK returned Master receiver
I2STAT reports the status code in bits 7:3. The lower three bits are not part of the status code. The values shown above are the conventional complete status-code values for these states.

9. Master Transmitter State Machine

A master-transmitter transaction proceeds through a sequence of states. Firmware must check each status before performing the next operation.

Step Status Firmware Action
START 0x08 Load SLA+W into I2DAT.
Address ACK 0x18 Load first data byte into I2DAT.
Data ACK 0x28 Load next data byte or request STOP.
Address NACK 0x20 Abort the transfer and request STOP.
Data NACK 0x30 Handle the failed transfer and request STOP.

State Machine Flow

10. Master Receiver State Machine

In master-receiver mode, the LPC2129 receives bytes and controls whether each byte is acknowledged.

Step Status Firmware Action
START 0x08 Load SLA+R into I2DAT.
Address ACK 0x40 Set AA to receive and acknowledge the next byte.
Data received 0x50 Read I2DAT and continue receiving.
Final data received 0x58 Read I2DAT and complete the transaction.
Address NACK 0x48 Abort the transfer and request STOP.
To receive multiple bytes, the controller normally enables AA before the next byte is received. Before the final byte, it clears AA so that the controller returns NACK.

11. LPC2129 Master Transmitter Programming

The following example demonstrates the structure of a blocking master-transmitter routine. It sends one data byte to a target with a 7-bit address. 

#include <LPC21xx.h>

#define I2C_AA   (1U << 2)
#define I2C_SI   (1U << 3)
#define I2C_STO  (1U << 4)
#define I2C_STA  (1U << 5)
#define I2C_I2EN (1U << 6)

#define I2C_SIC  (1U << 3)
#define I2C_STAC (1U << 5)

#define I2C_OK       0
#define I2C_ERROR   -1

static int I2C_WaitForSI(void)
{
    unsigned long timeout = 1000000UL;

    while ((I2CONSET & I2C_SI) == 0U)
    {
        if (--timeout == 0U)
            return I2C_ERROR;
    }

    return I2C_OK;
}

static void I2C_ClearSI(void)
{
    I2CONCLR = I2C_SIC;
}

static void I2C_Stop(void)
{
    I2CONSET = I2C_STO;
    I2CONCLR = I2C_SIC;
}

int I2C0_MasterWrite(unsigned char address,
                     unsigned char data)
{
    unsigned char status;

    /* Generate START */
    I2CONSET = I2C_STA;

    if (I2C_WaitForSI() != I2C_OK)
        return I2C_ERROR;

    status = I2STAT & 0xF8U;

    if (status != 0x08U)
    {
        I2C_Stop();
        return I2C_ERROR;
    }

    /* Clear START and SI */
    I2CONCLR = I2C_STAC | I2C_SIC;

    /* Send 7-bit address with write bit */
    I2DAT = (unsigned char)(address << 1);

    if (I2C_WaitForSI() != I2C_OK)
    {
        I2C_Stop();
        return I2C_ERROR;
    }

    status = I2STAT & 0xF8U;

    if (status != 0x18U)
    {
        I2C_Stop();
        return I2C_ERROR;
    }

    I2C_ClearSI();

    /* Send data byte */
    I2DAT = data;

    if (I2C_WaitForSI() != I2C_OK)
    {
        I2C_Stop();
        return I2C_ERROR;
    }

    status = I2STAT & 0xF8U;

    if (status != 0x28U)
    {
        I2C_Stop();
        return I2C_ERROR;
    }

    /* Complete transaction */
    I2C_Stop();

    return I2C_OK;
}

int main(void)
{
    int result;

    /* Configure SDA0 and SCL0 */
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    /* Configure nominal 100 kHz */
    I2SCLH = 75U;
    I2SCLL = 75U;

    /* Enable I2C0 */
    I2CONSET = I2C_I2EN;

    result = I2C0_MasterWrite(0x48U, 0x55U);

    while (1)
    {
        /* Inspect result in debugger */
    }
}

Program Explanation

  1. Configure P0.2 and P0.3 for I2C0.
  2. Set the SCL timing registers.
  3. Enable the I2C peripheral.
  4. Generate START and verify status 0x08.
  5. Transmit the target address with the write bit.
  6. Verify address acknowledgement using status 0x18.
  7. Transmit the data byte.
  8. Verify data acknowledgement using status 0x28.
  9. Request STOP to finish the transaction.
This is a basic blocking example for one data byte. A production driver should also handle arbitration loss, bus errors, timeout recovery, STOP completion and peripheral-specific error conditions. A timeout while waiting for SI does not automatically prove that the physical bus has returned to an idle state.

12. LPC2129 Master Receiver Programming

The following example demonstrates receiving two bytes from a target. The controller acknowledges the first byte and sends NACK after the final byte. 

#include <LPC21xx.h>

#define I2C_AA   (1U << 2)
#define I2C_SI   (1U << 3)
#define I2C_STO  (1U << 4)
#define I2C_STA  (1U << 5)
#define I2C_I2EN (1U << 6)

#define I2C_SIC  (1U << 3)
#define I2C_STAC (1U << 5)
#define I2C_AAC  (1U << 2)

#define I2C_OK       0
#define I2C_ERROR   -1

static int I2C_WaitForSI(void)
{
    unsigned long timeout = 1000000UL;

    while ((I2CONSET & I2C_SI) == 0U)
    {
        if (--timeout == 0U)
            return I2C_ERROR;
    }

    return I2C_OK;
}

int I2C0_MasterReadTwo(unsigned char address,
                       unsigned char *buffer)
{
    unsigned char status;

    if (buffer == 0)
        return I2C_ERROR;

    /* Generate START */
    I2CONSET = I2C_STA;

    if (I2C_WaitForSI() != I2C_OK)
        return I2C_ERROR;

    status = I2STAT & 0xF8U;

    if (status != 0x08U)
        return I2C_ERROR;

    I2CONCLR = I2C_STAC | I2C_SIC;

    /* Send address with read bit */
    I2DAT = (unsigned char)((address << 1) | 1U);

    if (I2C_WaitForSI() != I2C_OK)
        return I2C_ERROR;

    status = I2STAT & 0xF8U;

    if (status != 0x40U)
    {
        I2CONSET = I2C_STO;
        I2CONCLR = I2C_SIC;
        return I2C_ERROR;
    }

    /* ACK the first received byte */
    I2CONSET = I2C_AA;
    I2CONCLR = I2C_SIC;

    if (I2C_WaitForSI() != I2C_OK)
        return I2C_ERROR;

    status = I2STAT & 0xF8U;

    if (status != 0x50U)
        return I2C_ERROR;

    buffer[0] = (unsigned char)I2DAT;

    /* NACK the final received byte */
    I2CONCLR = I2C_AAC;
    I2CONCLR = I2C_SIC;

    if (I2C_WaitForSI() != I2C_OK)
        return I2C_ERROR;

    status = I2STAT & 0xF8U;

    if (status != 0x58U)
        return I2C_ERROR;

    buffer[1] = (unsigned char)I2DAT;

    /* Generate STOP */
    I2CONSET = I2C_STO;
    I2CONCLR = I2C_SIC;

    return I2C_OK;
}

int main(void)
{
    unsigned char received_data[2];
    int result;

    /* Configure I2C0 pins */
    PINSEL0 &= ~(0xFU << 4);
    PINSEL0 |=  (0x5U << 4);

    /* Configure nominal 100 kHz */
    I2SCLH = 75U;
    I2SCLL = 75U;

    /* Enable I2C0 */
    I2CONSET = I2C_I2EN;

    result = I2C0_MasterReadTwo(0x48U, received_data);

    while (1)
    {
        /* Inspect result and received_data in debugger */
    }
}

Important Explanation

  • Address bit R/W is set to 1 for reading.
  • Status 0x40 confirms address acknowledgement.
  • AA is set to acknowledge the first received byte.
  • Status 0x50 indicates that data was received and ACK was returned.
  • AA is cleared before the final byte.
  • Status 0x58 indicates that the final byte was received and NACK was returned.
  • The received bytes are read from I2DAT.
This example illustrates the two-byte receive sequence. For a production implementation, add complete error cleanup and STOP handling on every failure path. The target must also be programmed to provide the requested data in the expected order.

14. Repeated START in Register Read Operations

Many I2C targets contain internal registers. Reading a particular register commonly requires a combined transaction:

  1. Generate START.
  2. Send the target address with write direction.
  3. Send the internal register address.
  4. Generate a repeated START without releasing the bus.
  5. Send the target address with read direction.
  6. Receive the requested data.
  7. Send NACK after the final byte and generate STOP.
Combined Register Read 
 START
   |
 SLA+W
   |
 ACK
   |
 Register Address
   |
 ACK
   |
 Repeated START
   |
 SLA+R
   |
 ACK
   |
 Receive Data
   |
 NACK
   |
 STOP
A repeated START allows the master to change the transfer direction while retaining control of the bus. It is widely used for reading registers from sensors, RTCs and EEPROMs.

15. Master Transmitter vs Master Receiver

Feature Master Transmitter Master Receiver
Direction Master to target Target to master
R/W bit 0 1
Address ACK status 0x18 0x40
Data status 0x28 0x50 or 0x58
Data register I2DAT for transmission I2DAT for reception
ACK control Target acknowledges master data Master controls ACK/NACK response
Typical application Writing sensor configuration Reading sensor measurements

16. Common Programming Errors

Error Explanation
Incorrect address byte Forgetting to shift the 7-bit address left by one.
Wrong R/W bit Using 0 for a read or 1 for a write.
Ignoring I2STAT Continuing without checking the current bus state.
Not clearing SI The state machine may remain waiting for service.
Wrong ACK sequence Failing to acknowledge intermediate receive bytes.
No final NACK Not indicating the end of a master-receive transfer.
Incorrect STOP handling Failing to request STOP or verify bus completion where required.
Missing pull-up resistors The physical open-drain bus cannot operate correctly without suitable pull-ups.

17. Interview Questions and Answers

Q1. What is I2C master-transmitter mode?

The controller transmits data to an addressed target device.

Q2. What is I2C master-receiver mode?

The controller receives data from an addressed target device.

Q3. What is the R/W bit value for writing?

0.

Q4. What is the R/W bit value for reading?

1.

Q5. What is the purpose of I2STAT?

It indicates the current I2C state and transaction status.

Q6. What does status 0x18 indicate?

SLA+W was transmitted and an ACK was received.

Q7. What does status 0x40 indicate?

SLA+R was transmitted and an ACK was received.

Q8. What does status 0x50 indicate?

A data byte was received and ACK was returned.

Q9. What does status 0x58 indicate?

A data byte was received and NACK was returned.

Q10. Why does the master send NACK after the final received byte?

To indicate that it does not require another byte from the target.

Q11. What is a repeated START?

A new START condition generated without first releasing the bus with a STOP condition.

Q12. What is the purpose of I2DAT?

It holds the byte being transmitted or the byte received by the I2C peripheral.

20. Lesson Summary

  • The LPC2129 can operate as an I2C master transmitter or receiver.
  • Master-transmitter mode sends data to a target.
  • Master-receiver mode reads data from a target.
  • The R/W bit is 0 for write and 1 for read.
  • I2STAT reports the I2C state-machine status.
  • I2DAT holds transmitted and received bytes.
  • ACK and NACK control the continuation of data transfer.
  • The master normally sends NACK after the final received byte.
  • A repeated START supports combined write/read transactions.
  • Correct SI, AA, START and STOP handling is essential.
