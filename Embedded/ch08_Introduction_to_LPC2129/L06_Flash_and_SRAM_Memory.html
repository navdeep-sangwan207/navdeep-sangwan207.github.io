1. Introduction

Memory is an essential component of an embedded microcontroller. It stores firmware, application data, variables, and temporary information required during program execution.

LPC2129 provides two important types of on-chip memory:

  • Flash memory – non-volatile memory.
  • SRAM – volatile read/write memory.

Understanding these memories is important when developing firmware because the available memory capacity is limited.

Learning objectives:
  • Understand Flash memory architecture.
  • Understand SRAM architecture.
  • Compare Flash and SRAM.
  • Learn Flash programming and erasing concepts.
  • Understand SRAM usage during program execution.
  • Learn memory optimization techniques.

2. Flash Memory in LPC2129

Flash memory is a non-volatile semiconductor memory used to store firmware and other information that must remain available when power is removed.

LPC2129 provides 256 KB of on-chip Flash memory. The processor executes firmware stored in this memory.

Characteristics of Flash memory

  • Non-volatile storage.
  • Retains information without power.
  • Used for program and firmware storage.
  • Supports electrical erase and programming.
  • Has a finite number of program/erase cycles.
  • Programming and erasing follow device-specific procedures.

3. Purpose of Flash Memory

Flash memory stores information that must remain available after the microcontroller is powered off.

Typical contents

Content Purpose
Firmware instructions Stores executable program code.
Constant data Stores lookup tables and fixed application values.
Initialization code Provides startup routines required by the application.
Boot-related code Supports device startup and programming functions.

Example

#include <LPC21xx.h>

const unsigned int voltage_table[5] =
{
    0, 100, 200, 300, 400
};

int main(void)
{
    unsigned int value;

    value = voltage_table[2];

    while (1)
    {
        // Application code
    }
}

The constant lookup table may be placed in non-volatile program memory by the compiler and linker, depending on the toolchain and memory configuration.

The exact placement of objects depends on compiler options, startup code, and linker configuration. Inspect the generated map file when exact memory placement matters.

4. Flash Memory Programming

Programming Flash means storing new information in the Flash memory cells.

In an embedded development workflow, firmware is compiled and linked before it is programmed into the microcontroller.

Typical firmware programming process

Embedded C Source Code | v Compiler | v Object Files | v Linker | v Firmware Image | v Flash Programming Tool | v LPC2129 Flash

Flash programming stages

  1. Write the application source code.
  2. Compile the source code.
  3. Link the object files and libraries.
  4. Generate the required firmware image.
  5. Connect the programming interface when using hardware.
  6. Program the Flash memory using a supported method.
  7. Verify the programmed contents.
  8. Reset the target and execute the firmware.
In this course setup, Keil uVision is used with the simulator. A simulator build and debugging session do not physically program the Flash memory of an LPC2129 device.

5. Flash Erase and Programming Concepts

Flash memory programming is different from ordinary SRAM writing.

Flash devices generally organize storage into sectors or other erase units. An erase operation prepares a region before new data is programmed.

Important operations

Operation Description
Read Retrieves stored information.
Erase Erases a specified Flash region.
Program Writes data into the erased region.
Verify Checks whether programmed contents are correct.
LPC2129 Flash programming uses device-specific procedures and command sequences. Do not attempt to program Flash by treating it like an ordinary C array. Consult the NXP User Manual and supported programming-tool documentation.

6. SRAM in LPC2129

SRAM stands for Static Random Access Memory. It is volatile read/write memory used to store information while the microcontroller is running.

LPC2129 provides 16 KB of on-chip SRAM.

Characteristics of SRAM

  • Volatile memory.
  • Supports fast read and write operations.
  • Stores runtime variables and buffers.
  • Stores stack data and other temporary information.
  • Does not require periodic refresh like DRAM.
  • Loses its contents when power is removed.

7. SRAM Usage in Embedded C

SRAM is used for variables, arrays, buffers, stack data, and other runtime information.

Example 1: Global variable

#include <LPC21xx.h>

unsigned int counter = 0;

int main(void)
{
    while (1)
    {
        counter++;
    }
}

The global variable is normally allocated in a data section in SRAM after startup initialization.

Example 2: Uninitialized global variable

#include <LPC21xx.h>

unsigned int sensor_value;

int main(void)
{
    sensor_value = 250;

    while (1)
    {
    }
}

The uninitialized global variable is normally placed in the BSS section and initialized to zero during startup.

Example 3: Local variable

#include <LPC21xx.h>

void calculate(void)
{
    unsigned int result = 100;
    result++;
}

int main(void)
{
    calculate();

    while (1)
    {
    }
}

The local variable may be stored in a CPU register or on the stack, depending on compiler optimization and register allocation.

Do not assume that every local variable always occupies a stack location. The compiler may keep some local values in CPU registers.

8. Data Sections and Memory Allocation

A compiled embedded application is commonly organized into sections that are placed into Flash and SRAM by the linker.

Section Typical Purpose
.text Executable instructions.
.rodata Read-only constants, when emitted separately.
.data Initialized writable global and static variables.
.bss Uninitialized or zero-initialized global and static variables.
Stack Function-call and temporary execution data.
Heap Dynamic memory allocation, when configured.

Typical placement concept

FLASH +-------------+ | .text | +-------------+ | .rodata | +-------------+ | Initial | | .data image | +-------------+ SRAM +-------------+ | .data | +-------------+ | .bss | +-------------+ | Heap | +-------------+ | Stack | +-------------+

At startup, initialized data may be copied from its load location in Flash to its runtime location in SRAM. The BSS section is normally cleared to zero.

This is a typical embedded linker arrangement. Exact section names and placement depend on the compiler, startup code, and scatter-loading or linker configuration.

Write behavior Device-specific programming procedure Normal read/write access
Typical use Program code and constants Variables, stack, buffers

10. Memory Optimization Techniques

Since LPC2129 has limited SRAM, embedded developers should carefully manage memory.

Important techniques

  1. Use appropriate data types: Avoid unnecessarily large data types.
  2. Control array sizes: Allocate only the required buffer capacity.
  3. Limit stack usage: Avoid large local arrays and excessive recursion.
  4. Use constants appropriately: Keep fixed lookup data in read-only storage where supported.
  5. Monitor dynamic allocation: Avoid uncontrolled heap usage.
  6. Inspect the map file: Review section sizes and memory placement.
  7. Use efficient algorithms: Reduce unnecessary memory consumption.
  8. Check pointer operations: Prevent invalid memory access and corruption.

12. Common Memory Problems

Problem Cause Possible Solution
Stack overflow Excessive stack consumption Reduce local storage and inspect stack usage.
Heap exhaustion Insufficient dynamic memory Limit allocation and release unused memory.
Memory corruption Invalid pointer or array access Validate memory boundaries.
Incorrect startup data Incorrect initialization or linker configuration Check startup code and memory sections.
Flash programming failure Incorrect programming sequence or image Use supported programming procedures and verification.

13. Interview Questions and Answers

Q1. What is Flash memory?

Flash is non-volatile memory used to store firmware and information that must remain available without power.

Q2. What is SRAM?

SRAM is volatile read/write memory used for runtime application data.

Q3. How much Flash memory does LPC2129 provide?

256 KB.

Q4. How much SRAM does LPC2129 provide?

16 KB.

Q5. Why is Flash memory non-volatile?

It retains stored information even when the power supply is removed.

Q6. Why is SRAM used for variables?

SRAM supports normal read/write operations and is suitable for temporary data required during program execution.

Q7. What is the BSS section?

It contains uninitialized or zero-initialized global and static variables.

Q8. What is the data section?

It contains initialized writable global and static variables.

Q9. What is a linker map file?

It provides information about the memory placement and size of program sections and symbols.

Q10. What is stack overflow?

Stack overflow occurs when stack usage exceeds the available stack memory.

Q11. Can Flash be written like SRAM?

No. Flash programming requires device-specific programming and erase procedures.

Q12. Why is memory optimization important?

It helps the application operate reliably within the limited Flash and SRAM capacities of the microcontroller.

1. Which memory stores firmware in LPC2129?

  1. SRAM
  2. Flash
  3. Stack
  4. Heap

Answer: B – Flash

2. Which memory is volatile?

  1. Flash
  2. SRAM
  3. EEPROM
  4. ROM

Answer: B – SRAM

3. What is the Flash capacity of LPC2129?

Answer: D – 256 KB

4. What is the SRAM capacity of LPC2129?

  1. 8 KB
  2. 16 KB
  3. 64 KB
  4. 128 KB

Answer: B – 16 KB

5. Which section stores uninitialized global variables?

  1. .text
  2. .bss
  3. .rodata
  4. .debug

Answer: B – .bss

6. Which section typically stores initialized writable global variables?

  1. .data
  2. .bss
  3. .text
  4. .stack

Answer: A – .data

7. Which memory region supports dynamic allocation?

  1. Flash
  2. Heap
  3. Boot ROM
  4. Peripheral register space

Answer: B – Heap

8. What does a linker map file show?

  1. Only source code comments
  2. Memory section placement and symbol information

Answer: B – Memory section placement and symbol information

9. What can cause stack overflow?

  1. Excessive local storage
  2. Too little Flash programming

Answer: A – Excessive local storage

Answer: A – Erase, according to the device programming procedure
