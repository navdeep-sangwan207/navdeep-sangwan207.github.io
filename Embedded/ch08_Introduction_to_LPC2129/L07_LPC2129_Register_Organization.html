1. Introduction

Registers are small storage locations used by a processor and its peripherals to hold data, addresses, control information, and status information.

In LPC2129, registers are used by the ARM7TDMI-S processor and peripheral hardware such as GPIO, UART, timers, ADC, PWM, I2C, SPI, and CAN.

Embedded C programs access these registers to configure the microcontroller and control its hardware.

Learning objectives:
  • Understand the purpose of processor registers.
  • Differentiate CPU registers and peripheral registers.
  • Understand memory-mapped register access.
  • Identify important LPC2129 peripheral registers.
  • Understand register bit manipulation.
  • Learn how to inspect registers in Keil uVision.

2. What Is a Register?

A register is a small storage location implemented inside a processor or peripheral hardware block. It holds a fixed number of bits.

A register can store:

  • Data being processed by the CPU.
  • Memory addresses.
  • Processor status information.
  • Peripheral configuration values.
  • Hardware status and control information.

Example: 32-bit register

32-bit Register +----+----+----+----+----+----+----+----+ | 31 | 30 | 29 | 28 | 27 | 26 | ...| 0 | +----+----+----+----+----+----+----+----+ 32 individual bits

A 32-bit register can represent values from 0x00000000 to 0xFFFFFFFF when interpreted as an unsigned integer.

3. Types of Registers in LPC2129

Registers in a microcontroller can be grouped according to their function.

Register Category Purpose Example
CPU registers Store processor data, addresses, and status. R0–R15, CPSR
GPIO registers Control digital input and output. IODIR0, IOSET0
UART registers Configure serial communication. U0LCR, U0DLL
Timer registers Control timers and match operations. T0TC, T0PR, T0MR0
ADC registers Configure analog-to-digital conversion. AD0CR, AD0GDR
System control registers Configure clocking and system operation. PLL and VPB control registers

4. ARM7TDMI-S CPU Registers

The ARM7TDMI-S processor contains a register set used during instruction execution.

Its programmer-visible register organization includes:

  • General-purpose registers R0 to R12.
  • Stack Pointer (SP), also known as R13.
  • Link Register (LR), also known as R14.
  • Program Counter (PC), also known as R15.
  • Current Program Status Register (CPSR).
  • Saved Program Status Registers (SPSRs) in exception modes.
ARM7TDMI-S Register Set +----------------------+ | R0 - R12 | | General Purpose | +----------------------+ | R13 - SP | | Stack Pointer | +----------------------+ | R14 - LR | | Link Register | +----------------------+ | R15 - PC | | Program Counter | +----------------------+ | CPSR | | Current Status | +----------------------+ | SPSR | | Saved Status | +----------------------+
ARM7 register banking depends on processor mode. Some registers have separate banked copies for exception handling. The complete register organization is covered in Chapter 06.

5. General-Purpose Registers

General-purpose registers temporarily store data and intermediate results during instruction execution.

Example

        MOV R0, #10
        MOV R1, #20
        ADD R2, R0, R1

Operation:

  • R0 receives 10.
  • R1 receives 20.
  • R2 receives the sum of R0 and R1.

Expected result:

R0 = 10
R1 = 20
R2 = 30

6. Peripheral Registers

Peripheral registers control the internal hardware modules of LPC2129.

Unlike general-purpose CPU registers, peripheral registers are associated with hardware functions.

Examples

Peripheral Register Purpose
GPIO IODIR0 Configures Port 0 pin direction.
GPIO IOSET0 Sets selected Port 0 output bits.
GPIO IOCLR0 Clears selected Port 0 output bits.
UART0 U0LCR Configures UART line format and divisor access.
UART0 U0THR Transmits a data byte when selected for transmit access.
Timer 0 T0TC Holds the Timer 0 counter value.
ADC AD0CR Controls ADC0 operation.

7. Memory-Mapped Register Organization

LPC2129 uses memory-mapped I/O for peripheral register access.

Each peripheral register is assigned an address in the microcontroller's address space. The processor accesses the register using normal load and store operations.

ARM7TDMI-S CPU | v Address Bus | v Memory-Mapped Register | +--------+--------+ | | | v v v GPIO UART Timer | | | v v v Digital Serial Timing I/O Data Control

Register access in Embedded C

#include <LPC21xx.h>

int main(void)
{
    PINSEL0 &= ~(3U << 10);

    IODIR0 |= (1U << 5);

    IOSET0 = (1U << 5);

    while (1)
    {
    }
}

The device header defines symbolic names for hardware registers. The compiler accesses the corresponding memory-mapped locations.

A peripheral register is not an ordinary variable in SRAM. It represents a hardware register at a defined address.

8. Register Bit Manipulation

Peripheral configuration often requires changing individual bits without affecting unrelated bits.

8.1 Set a bit

REGISTER |= (1U << n);

Sets bit n to 1.

8.2 Clear a bit

REGISTER &= ~(1U << n);

Clears bit n to 0.

8.3 Toggle a bit

REGISTER ^= (1U << n);

Inverts bit n.

8.4 Test a bit

if (REGISTER & (1U << n))
{
    // Bit is set
}
else
{
    // Bit is clear
}
These are common read-modify-write patterns. They are not automatically safe for every hardware register. Some registers have write-one-to-clear, write-only, or special access behavior. Check the register description before applying a generic operation.

9. Control Registers and Status Registers

Control registers

Control registers configure the operation of a hardware peripheral.

Examples include:

  • GPIO direction configuration.
  • UART line control.
  • Timer control and match configuration.
  • ADC conversion configuration.

Status registers

Status registers indicate the current state of a peripheral or an operation.

Examples include:

  • UART line status.
  • Timer interrupt flags.
  • ADC conversion completion status.
  • Interrupt controller status.
Control Register Status Register
Configures hardware behavior. Reports hardware state.
Usually written by software. Often updated by hardware.
Example: U0LCR. Example: U0LSR.

10. Register Access Using Device Header Files

Embedded C development commonly uses a device-specific header file.

For LPC2129 projects, the device header typically provides register definitions such as: 

#include <LPC21xx.h>

int main(void)
{
    // GPIO registers
    IODIR0 = 0x00000020;
    IOSET0 = 0x00000020;

    while (1)
    {
    }
}

This example writes to GPIO registers. In a complete application, the relevant PINSEL configuration and other initialization requirements must also be satisfied.

Why use a device header?

  • Provides readable register names.
  • Reduces the need to write raw addresses.
  • Improves code readability.
  • Helps organize hardware-specific definitions.
  • Reduces errors caused by manually entering addresses.

11. The Volatile Keyword

The volatile keyword tells the compiler that a variable's value may change for reasons outside the normal program flow.

This is important when accessing hardware registers because the peripheral may change a register independently of the CPU's current instructions.

Example

volatile unsigned int *status_register;

status_register = (volatile unsigned int *)0x40000000U;

while ((*status_register & 1U) == 0U)
{
    // Wait until status bit becomes 1
}
The address above is illustrative only. Never use an arbitrary address for a real LPC2129 peripheral register. Use the documented address or the device header definition.

Device header files normally declare hardware register definitions with the appropriate volatile access semantics.

12. Register Inspection in Keil uVision

Keil uVision provides debugging windows for inspecting processor registers and peripheral-related memory locations.

Suggested simulator activity

  1. Open the LPC2129 project.
  2. Build the project successfully.
  3. Start the simulator debugger.
  4. Open the Registers window to inspect CPU registers.
  5. Open the Watch window to inspect C variables.
  6. Use the Memory window to inspect documented peripheral addresses.
  7. Step through register initialization code.
  8. Observe changes in the relevant register values.
The CPU register window and peripheral register memory inspection serve different purposes. Peripheral simulation support depends on the selected device model and debugger configuration.

13. Common Register Programming Mistakes

  1. Using an incorrect peripheral register name.
  2. Writing to an incorrect register address.
  3. Changing unrelated bits unintentionally.
  4. Ignoring special register access behavior.
  5. Failing to configure PINSEL before using a pin.
  6. Forgetting the volatile behavior of hardware registers.
  7. Using an incorrect bit position.
  8. Assuming a register write guarantees physical hardware operation.

14. Interview Questions and Answers

Q1. What is a register?

A register is a small storage location inside a processor or peripheral hardware block.

Q2. What are CPU registers?

CPU registers store data, addresses, and status information used by the processor.

Q3. What are peripheral registers?

Peripheral registers configure and report the status of hardware modules.

Q4. What is memory-mapped I/O?

It is a technique in which peripheral registers are assigned addresses in the processor address space.

Q5. What is IODIR0?

IODIR0 is the GPIO Port 0 direction register. It configures implemented Port 0 pins as inputs or outputs.

Q6. What is IOSET0?

IOSET0 sets selected Port 0 output bits.

Q7. What is IOCLR0?

IOCLR0 clears selected Port 0 output bits.

Q8. Why is volatile important?

It prevents the compiler from assuming that a hardware-related value cannot change unexpectedly.

Q9. What is a control register?

A control register configures the behavior of a hardware module.

Q10. What is a status register?

A status register provides information about the current state of a peripheral.

Q11. What is the purpose of a device header file?

It provides symbolic definitions for device registers, bit fields, and other hardware related definitions.

Q12. How can registers be inspected in Keil?

Use the Registers, Watch, and Memory windows in the debugger.

  • Registers are small storage locations inside the processor and peripherals.

  • LPC2129 uses memory-mapped peripheral registers.
  • GPIO registers include IODIR, IOSET, IOCLR, and IOPIN.
