1. Introduction

Keil uVision is an Integrated Development Environment (IDE) used to develop, compile, build, debug, and test embedded software.

It supports an embedded development workflow that includes source-code editing, compiler configuration, assembling, linking, debugging, and target programming.

In this lesson, we will learn how to create and configure a project for the LPC2129 ARM7TDMI-S microcontroller.

Learning objectives:
  • Understand the Keil uVision project structure.
  • Create a new LPC2129 project.
  • Select the target microcontroller.
  • Configure startup code and memory settings.
  • Add Embedded C source files.
  • Configure compiler and linker options.
  • Build the firmware.
  • Debug the application using the simulator.
  • Inspect registers and variables during execution.

2. What Is Keil uVision?

Keil uVision is an embedded software development environment from Arm's Keil toolchain ecosystem.

It provides tools for developing firmware for supported microcontrollers and processors.

Main features

  • Source-code editor.
  • C and C++ compiler support, depending on the installed toolchain.
  • Assembler and linker integration.
  • Project and target configuration.
  • Build and error reporting.
  • Debugger and simulator support for supported targets.
  • Memory and register inspection.
  • Target programming through supported hardware interfaces.

4. Create a New Keil Project

Step 1: Open Keil uVision

  1. Start Keil uVision from Windows.
  2. Wait for the IDE workspace to load.
  3. Open the Project menu.

Step 2: Create a new project

  1. Select Project → New uVision Project.
  2. Choose a suitable project folder.
  3. Create a separate folder for the project.
  4. Enter the project name.
  5. Click Save.

Example project directory

LPC2129_Project/
│
├── LPC2129_Project.uvproj
│
├── Source/
│   └── main.c
│
├── Headers/
│   └── project.h
│
├── Startup/
│   └── startup.s
│
└── Output/
    ├── LPC2129_Project.axf
    └── LPC2129_Project.hex

The actual project file extension depends on the installed uVision version.

Keeping source files, headers, startup code, and generated output organized makes embedded projects easier to maintain.

5. Select the LPC2129 Target Device

After creating the project, uVision opens the Select Device for Target dialog.

Procedure

  1. Open the device-selection dialog.
  2. Search for LPC2129.
  3. Select the exact device if it is available.
  4. Confirm the selection.
  5. Review the resulting target configuration.

Why is device selection important?

  • Establishes processor-specific settings.
  • Provides device memory information where supported.
  • Helps configure compiler and linker options.
  • Provides target-specific debugging and programming options where supported.
If LPC2129 is not listed, do not select a different LPC device and assume its memory layout, peripheral registers, startup code, or debugger model are identical. Use a verified LPC2129 configuration or create the required legacy project settings manually.

6. Configure Startup Code

Startup code is executed before the application's main() function.

It establishes the initial processor environment and prepares the application to run.

Typical startup operations

  • Initialize processor execution environment.
  • Set up stack pointers for required processor modes.
  • Initialize runtime memory sections.
  • Prepare global and static variables.
  • Configure required exception vectors.
  • Transfer execution to main().

Startup execution flow

Processor Reset | v Reset Entry | v Startup Code | +---------+---------+ | | v v Stack Setup Runtime Setup | | +---------+---------+ | v main() | v Application Code
Use startup code intended for LPC2129 and the selected compiler. A startup file from a different ARM7 device may contain incorrect exception vectors or memory assumptions.

7. Configure Target Memory

The linker needs to know the memory regions available to the application.

LPC2129 provides on-chip Flash and SRAM. Their locations and usable sizes must be reflected correctly in the project.

Course reference memory configuration

Memory Capacity Purpose
On-chip Flash 256 KB Program code and non-volatile data.
On-chip SRAM 16 KB Stack, heap, and runtime data.

Memory configuration considerations

  • Set the correct Flash address range.
  • Set the correct SRAM address range.
  • Reserve sufficient stack space.
  • Reserve heap space if required.
  • Check the linker memory map after building.
The exact memory start addresses and linker settings must follow the LPC2129 memory map and selected startup configuration. Do not copy memory addresses from another LPC family.

8. Add Source Files to the Project

Source files contain the Embedded C or assembly code used by the application.

Procedure

  1. Locate the Project Workspace.
  2. Right-click Source Group 1.
  3. Select Add New Item to Group.
  4. Choose C File (.c).
  5. Enter the filename main.c.
  6. Click Add or OK.

Example source file

#include <LPC21xx.h>

int main(void)
{
    unsigned int counter = 0;

    while (1)
    {
        counter++;
    }
}

This simple program continuously increments a variable. It is useful for checking compilation and observing program execution in the debugger.

The program does not operate an external LED or other physical device. It is a basic software execution example.

9. Add Header Files

Header files contain declarations, definitions, and device register information required by source files.

LPC2129 device header

#include <LPC21xx.h>

This header is commonly used in LPC21xx projects to access device-specific register definitions.

Important header-file functions

  • Defines peripheral register addresses.
  • Defines register names and structures.
  • Provides device-specific constants.
  • Helps make register-level code readable.
Ensure that the header file matches the LPC2129 device and is included in the compiler's configured include path.

10. Configure Compiler Options

Compiler options determine how source files are translated into object code.

Procedure

  1. Right-click Target 1.
  2. Select Options for Target.
  3. Open the C/C++ or compiler settings tab.
  4. Review the compiler version and language options.
  5. Configure the header-file include paths.
  6. Review optimization settings.
  7. Confirm the processor-specific configuration.

Important compiler settings

Setting Purpose
Include Paths Locates device and project header files.
Optimization Controls code optimization level.
Language Standard Controls supported C language features.
Preprocessor Definitions Defines compile-time macros.
Target Processor Ensures correct instruction-set configuration.

11. Configure Assembler and Linker

Assembler configuration

The assembler processes assembly-language files, including startup code where applicable.

Linker configuration

The linker combines object files and libraries into the final application image.

Important linker tasks

  • Assign code and data sections to memory.
  • Resolve external symbol references.
  • Place interrupt vectors correctly.
  • Generate the executable image.
  • Report memory usage and linking errors.

12. Configure Output Files

Keil can generate different output files during the build process.

File Extension Description
.o / .obj Compiled object file.
.axf Executable image containing debug information where configured.
.hex Intel HEX representation of program data.
.map Linker memory and symbol information.
.lst Listing information when generated.

Create HEX File

  1. Open Options for Target.
  2. Select the Output tab.
  3. Enable Create HEX File if required.
  4. Build the project.
  5. Check the configured output directory.
Generating a HEX file does not program the microcontroller. It only creates a firmware file suitable for a compatible programming process.

13. Build the Project

Building translates source code into an executable firmware image.

Build procedure

  1. Save all source files.
  2. Select Project → Build Target.
  3. Wait for compilation and linking.
  4. Review the Build Output window.
  5. Resolve errors if any are reported.
  6. Build again after corrections.

Common build messages

Message Meaning
0 Errors No compiler or linker errors were reported.
Warning Potential issue requiring review.
Undefined Symbol A required symbol could not be resolved.
Cannot Open Include File A required header file could not be found.
Memory Overflow Program sections exceed configured memory regions.
A successful build confirms that the configured toolchain compiled and linked the project. It does not prove that all hardware peripherals work correctly.

14. Configure the Keil Simulator

The Keil simulator allows software execution and debugging without connecting a physical target board, provided the selected processor and simulator support the required features.

Procedure

  1. Open Options for Target.
  2. Select the Debug tab.
  3. Select Use Simulator if supported for the target.
  4. Confirm the debugger configuration.
  5. Click OK.
  6. Select Debug → Start/Stop Debug Session.
Simulator support is device- and toolchain-dependent. Do not assume that every LPC2129 peripheral is fully simulated merely because the project builds or the CPU executes instructions.

15. Debugging the LPC2129 Application

Debugging is the process of examining program execution to identify and correct software errors.

Important debugger features

  • Run and stop program execution.
  • Single-step through instructions.
  • Set and remove breakpoints.
  • Inspect variables.
  • Inspect CPU registers.
  • Inspect memory locations.
  • Observe peripheral registers where supported.

Useful debugging windows

Window Purpose
Watch Displays selected variables and expressions.
Registers Displays CPU register values.
Memory Displays selected memory contents.
Disassembly Displays machine instructions.
Call Stack Displays function-call information.

16. Practical: Debug a Simple LPC2129 Program

Use the following program to practise building and debugging.

Objective

Create an LPC2129 project and observe a software counter using the Keil debugger.

Program

#include <LPC21xx.h>

volatile unsigned int counter = 0;

int main(void)
{
    while (1)
    {
        counter++;
    }
}

Procedure

  1. Create the LPC2129 project.
  2. Add the device header file to the include path.
  3. Add main.c to the source group.
  4. Build the project.
  5. Start the simulator debugger if supported.
  6. Open the Watch window.
  7. Add the variable counter.
  8. Set a breakpoint inside the while loop.
  9. Execute the program and inspect counter.

Expected software-visible observation

counter = 0
counter = 1
counter = 2
counter = 3
counter = 4
...

The counter increases during program execution. Its displayed value depends on the debugger execution and breakpoint settings.

The volatile keyword prevents the compiler from treating the variable as an ordinary value that never changes through externally observable operations. It does not make the increment atomic.

17. LPC2129 Clock Configuration in the Project

The following values are used as the reference clock configuration in this course.

Parameter Value
External oscillator (FOSC) 12 MHz
Processor clock (CCLK) 60 MHz
Peripheral clock (PCLK) 15 MHz
VPBDIV 0x00 – CCLK/4

Clock initialization must be implemented according to the LPC2129 PLL and peripheral clock configuration requirements.

Do not assume that the debugger's target crystal setting alone configures the LPC2129 PLL or VPBDIV register. Software clock initialization and debugger target settings have different purposes.

18. Common Keil Project Errors

Error Possible Solution
Header file not found Check the compiler include path.
Undefined symbol Check source files, declarations, and libraries.
Startup file missing Add the correct device startup code.
Incorrect memory configuration Verify the linker memory map.
Wrong processor target Review the selected ARM7 target and compiler settings.
Simulator unavailable Check target and simulator support.
HEX file not generated Enable Create HEX File in Output settings.
Peripheral behavior not visible Check simulator peripheral support and use register-level inspection where possible.

19. Simulator vs Physical Hardware Debugging

Feature Simulator Physical Hardware
CPU instruction execution Supported according to simulator model. Actual processor execution.
Variable inspection Yes, during debugging. Yes, with a compatible debugger.
Memory inspection Within simulator support. Actual target memory.
GPIO electrical output Not a physical voltage measurement. Can be measured with instruments.
UART electrical transmission Depends on simulator support. Can be measured using a serial interface or oscilloscope.
Flash programming Not physical Flash programming. Requires a compatible programming interface.
Oscillator measurement Cannot physically measure it. Can be checked using suitable test equipment.
This course uses Keil uVision simulation without a physical LPC2129 board. Practical results should therefore be described as software execution, register inspection, or simulated behavior—not as physical hardware measurements.

20. Interview Questions and Answers

Q1. What is Keil uVision?

It is an IDE used for embedded software development, compilation, building, and debugging.

Q2. What is a Keil project?

It is a collection of source files, configuration settings, device information, and build instructions for an application.

Q3. What is startup code?

Startup code initializes the processor environment and runtime system before main() executes.

Q4. What is the purpose of device selection?

It helps configure processor-specific compiler, memory, and target settings.

Q5. What is the function of the linker?

The linker combines object files and libraries and assigns program sections to memory addresses.

Q6. What is an AXF file?

It is an executable output format commonly used by Keil and can contain debugging information.

Q7. What is a HEX file?

It is a text-based representation of firmware data using the Intel HEX format.

Q8. What is the purpose of the Watch window?

It displays selected variables and expressions during debugging.

Q9. What is the difference between simulation and target debugging?

Simulation executes software in a supported software model, whereas target debugging interacts with actual hardware through a compatible debug interface.

Q10. Does a successful build guarantee correct hardware operation?

No. It confirms compilation and linking, not correct electrical or peripheral behavior.

Q11. Why is the LPC2129 header file important?

It provides register definitions and device-specific declarations for firmware.

Q12. What is the purpose of a map file?

It provides information about memory allocation, sections, and linked symbols.
