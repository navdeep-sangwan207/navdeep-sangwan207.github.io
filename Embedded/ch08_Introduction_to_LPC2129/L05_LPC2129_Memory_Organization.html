1. Introduction

Memory organization describes how a microcontroller stores program instructions, application data, temporary variables, and peripheral control information.

The LPC2129 uses an ARM7TDMI-S processor and provides on-chip Flash memory and SRAM. It also has memory-mapped peripheral registers that allow software to control hardware.

Learning objectives:
  • Understand the memory requirements of an embedded system.
  • Identify the memory types available in LPC2129.
  • Understand Flash memory and SRAM.
  • Learn the concept of an address space.
  • Understand the memory map and memory-mapped peripherals.
  • Learn how program and data memory are used during execution.

2. Why Memory Is Required

A microcontroller needs memory to store and execute firmware and to maintain data while an embedded application is running.

Memory Requirement Purpose
Program storage Stores compiled machine instructions.
Variable storage Stores application variables and data.
Stack storage Stores function-call information and local variables.
Heap storage Supports dynamic memory allocation when used.
Peripheral registers Store control and status information for hardware peripherals.

3. Memory Types in LPC2129

The main on-chip memory types in LPC2129 are Flash memory and static RAM (SRAM).

Memory Type Capacity Purpose
On-chip Flash 256 KB Non-volatile program and firmware storage.
On-chip SRAM 16 KB Temporary program data, stack, and runtime variables.

Memory organization overview

LPC2129 | +--------+--------+ | | v v Flash Memory SRAM 256 KB 16 KB | | v v Program Code Runtime Data Constants Stack Firmware Variables
Flash and SRAM serve different purposes. Flash retains stored information without power, whereas SRAM is volatile.

4. Address Space

An address is a numerical location used by the processor to identify a memory location or memory-mapped hardware register.

ARM7TDMI-S uses a 32-bit address model. A 32-bit address space can represent:

232 = 4,294,967,296 byte addresses

This corresponds to a theoretical 4 GB byte-addressable address space.

Address range

The theoretical 32-bit address range is: 

0x00000000 to 0xFFFFFFFF

Not every address in this range represents installed physical RAM or Flash. The LPC2129 implements specific regions for internal memory, peripherals, and other system functions.

The address space is not the same as the physical memory capacity. A processor may support a large address range while having much smaller on-chip memory.

5. Memory Map Concept

A memory map describes the address ranges assigned to different memory and hardware regions in a microcontroller.

These regions can include:

  • Boot ROM and boot-related functions.
  • On-chip Flash memory.
  • On-chip SRAM.
  • Peripheral register space.
  • System control registers.
  • Reserved address regions.

Conceptual memory map

32-bit Processor Address Space +---------------------------+ | Reserved Areas | +---------------------------+ | Peripheral Registers | +---------------------------+ | On-chip SRAM | +---------------------------+ | On-chip Flash | +---------------------------+ | Boot / System Regions | +---------------------------+
This is a conceptual illustration, not the exact LPC2129 address map. The actual start addresses, sizes, aliases, and reserved regions must be taken from the LPC2129 User Manual.

6. Memory-Mapped Peripherals

LPC2129 uses memory-mapped I/O to access peripheral hardware.

In memory-mapped I/O, hardware control and status registers are assigned specific addresses in the processor's address space.

The processor reads from or writes to these addresses to interact with peripherals.

Example: GPIO register access

#include <LPC21xx.h>

int main(void)
{
    // Configure P0.5 as GPIO
    PINSEL0 &= ~(3U << 10);

    // Configure P0.5 as output
    IODIR0 |= (1U << 5);

    // Set P0.5 high
    IOSET0 = (1U << 5);

    while (1)
    {
    }
}

Explanation

  • PINSEL0 selects the GPIO function for P0.5.
  • IODIR0 controls the direction of the pin.
  • IOSET0 sets the output latch.
  • The device header provides symbolic register names.

These registers are hardware registers, not ordinary application variables.

7. Program Memory and Data Memory

Program memory

Program memory stores the executable firmware. The LPC2129 uses on-chip Flash memory for non-volatile program storage.

Data memory

Data memory stores information required while the application executes. SRAM is used for variables, stack data, and other runtime data.

Program Memory Data Memory
Stores firmware instructions. Stores runtime application data.
Uses Flash memory. Uses SRAM.
Non-volatile. Volatile.
Retains contents without power. Normally loses contents when power is removed.

8. Stack and Heap

Stack

The stack is a memory region used for function calls, return information, saved processor context, and local variables according to the compiler's calling convention.

Heap

The heap is a memory region used for dynamic memory allocation through functions such as malloc() and free(), when the application and runtime library support them.

SRAM +-------------+ | | | Stack | | | | | v | | | | Free | | Space | | | | ^ | | | | | Heap | | | +-------------+
This is a conceptual illustration only. Actual stack and heap placement and growth depend on the startup code, linker configuration, and compiler settings.

Embedded system considerations

  • SRAM is limited, so memory usage must be controlled.
  • Large local arrays can consume stack space.
  • Uncontrolled recursion can cause stack overflow.
  • Dynamic allocation can lead to fragmentation.
  • Memory requirements should be checked during debugging.

9. Little-Endian Data Organization

ARM7TDMI-S supports little-endian and big-endian data formats, with the system configuration determining the selected mode.

In little-endian representation, the least significant byte of a multi-byte value is stored at the lowest memory address.

Example

Consider the 32-bit hexadecimal value: 

0x12345678

In little-endian byte order:

Memory Address Stored Byte
0x1000 0x78
0x1001 0x56
0x1002 0x34
0x1003 0x12
Endianness describes byte ordering in memory. It does not change the numerical value of the stored integer.

10. Memory Access During Program Execution

During execution, the processor fetches instructions from program memory, decodes them, and performs the required operations.

Data may be read from or written to SRAM, while peripheral registers are accessed through their memory-mapped addresses.

Flash Memory | v Instruction Fetch | v ARM7TDMI-S CPU | +------+------+ | | v v SRAM Peripheral | Registers | | v v Variables Hardware and Stack Control

Example application

Consider a temperature-monitoring application:

  1. Firmware instructions are stored in Flash.
  2. ADC configuration is performed through peripheral registers.
  3. ADC conversion results are read by the processor.
  4. Temporary values are stored in SRAM.
  5. The application processes the measurement.
  6. UART registers are used to transmit the result.

11. Memory Inspection in Keil uVision

The Keil uVision debugger provides tools to inspect memory contents and processor registers.

Suggested simulator activity

  1. Create or open an LPC2129 project.
  2. Build the program successfully.
  3. Start the debugger using the available simulator.
  4. Open the Memory window.
  5. Enter a valid memory address from the device memory map.
  6. Inspect the displayed contents.
  7. Use the Watch window to inspect variables.
  8. Step through the program and observe data changes.
Use the LPC2129 memory map to select valid addresses. Do not assume that an arbitrary address is readable or writable. Simulator visibility also depends on the selected target and debugger configuration.

12. Common Memory-Related Problems

Problem Possible Cause
Stack overflow Excessive local variables, deep function calls, or recursion.
Heap exhaustion Insufficient available SRAM for dynamic allocation.
Memory corruption Invalid pointer access or writing beyond an array.
Incorrect peripheral operation Wrong peripheral register address or configuration.
Firmware does not start Incorrect startup code, linker configuration, or programming process.
Unexpected variable values Uninitialized data, invalid access, or memory overwrite.

13. Interview Questions and Answers

Q1. What is memory organization?

It describes how memory is arranged and assigned to program instructions, data, and peripheral registers.

Q2. How much Flash memory does LPC2129 provide?

256 KB of on-chip Flash memory.

Q3. How much SRAM does LPC2129 provide?

16 KB of on-chip SRAM.

Q4. What is the difference between Flash and SRAM?

Flash is non-volatile and stores firmware, while SRAM is volatile and stores runtime data.

Q5. What is an address space?

It is the range of addresses that a processor can use to identify memory and mapped hardware.

Q6. What is a memory map?

A memory map describes the address ranges assigned to different memory and peripheral regions.

Q7. What is memory-mapped I/O?

It is a technique in which peripheral registers are assigned addresses in the processor's address space.

Q8. What is the stack?

The stack stores function-call information, local variables, and other temporary data.

Q9. What is the heap?

The heap is used for dynamic memory allocation when supported by the application runtime.

Q10. What is little-endian format?

It stores the least significant byte at the lowest memory address.

Q11. Why is SRAM important in embedded systems?

SRAM stores variables, buffers, stack data, and other information required during execution.

Q12. Why must embedded developers monitor memory usage?

Embedded microcontrollers have limited memory, and excessive memory consumption can cause runtime failures.
