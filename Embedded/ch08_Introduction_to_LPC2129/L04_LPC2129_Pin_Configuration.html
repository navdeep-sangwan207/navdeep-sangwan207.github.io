1. Introduction

The LPC2129 microcontroller provides physical pins for connecting external electronic devices and communication interfaces.

These pins support different functions such as GPIO, UART, I2C, SPI, CAN, ADC, PWM, and external interrupt signals.

Many LPC2129 pins are multiplexed. This means that one physical pin can support more than one function, but only the selected function is available at a time.

Learning objectives:
  • Understand the LPC2129 physical pin arrangement.
  • Learn about GPIO port pins.
  • Understand alternate pin functions.
  • Learn the purpose of PINSEL registers.
  • Identify common UART, I2C, SPI, CAN, and ADC pins.
  • Understand the importance of correct pin configuration.

2. Physical Pin Configuration

LPC2129 is available in a specified package with physical pins for power, ground, oscillator, reset, GPIO, and peripheral functions.

Each physical pin is identified by its package pin number and its signal name. The same pin may have multiple signal names because of alternate-function multiplexing.

Major pin categories

Pin Category Purpose
Power supply Provides the required operating supply voltage.
Ground Provides the electrical reference and return path.
Oscillator pins Connect the external clock crystal or oscillator circuit.
Reset pin Resets the microcontroller.
GPIO pins Provide digital input and output.
Communication pins Support UART, I2C, SPI, and CAN.
Analog input pins Connect analog signals to the ADC.
Special-function pins Support functions such as external interrupts and PWM.
Always use the pin diagram for the exact LPC2129 package when identifying physical pin numbers. Port names such as P0.0 are not physical package pin numbers.

3. GPIO Port Organization

The LPC2129 provides two GPIO ports: Port 0 and Port 1.

Port GPIO Bit Range Organization
Port 0 P0.0 to P0.31 32-bit GPIO port register organization
Port 1 P1.16 to P1.31 Upper GPIO bit positions are implemented

The GPIO port registers allow the processor to configure pin direction and read or control digital logic levels.

Example GPIO pin names

  • P0.0 – Port 0, bit 0.
  • P0.1 – Port 0, bit 1.
  • P0.5 – Port 0, bit 5.
  • P0.10 – Port 0, bit 10.
  • P0.28 – Port 0, bit 28.
  • P1.16 – Port 1, bit 16.
LPC2129 has up to 46 GPIO pins. Not every possible bit position in the 32-bit port register corresponds to a physical GPIO pin.

4. Alternate Pin Functions

A multiplexed pin can perform multiple hardware functions. The required function is selected through the pin-selection configuration registers.

Example

Physical pin P0.0 can be used as a GPIO pin or configured for UART0 transmit functionality.

Pin Possible Functions
P0.0 GPIO, TXD0, PWM1
P0.1 GPIO, RXD0, PWM3
P0.2 GPIO, SCL0, CAP0.0
P0.3 GPIO, SDA0, MAT0.0
P0.8 GPIO, TXD1, PWM4
P0.9 GPIO, RXD1, PWM6
The table shows selected alternate functions for learning purposes. Check the complete device pin-function table before selecting a peripheral signal for a particular pin.

Pin multiplexing concept

Physical Pin | +------+------+ | | | v v v GPIO UART PWM | | | +------+------+ | Pin Selection Logic | v Selected Function

The selected function determines how the physical pin behaves.

5. PINSEL Registers

PINSEL registers control the alternate functions of multiplexed pins.

LPC2129 provides PINSEL0, PINSEL1, and PINSEL2. Their fields select functions for the corresponding port pins and special pin configurations.

PINSEL0

PINSEL0 configures the alternate functions associated with Port 0 pin groups.

PINSEL1

PINSEL1 configures the alternate functions associated with additional Port 0 pin groups.

PINSEL2

PINSEL2 controls selected special pin functions and Port 1-related configuration.

Two-bit function selection

For many Port 0 pins, two bits in a PINSEL register select the function.

Bit Value Selected Function
00 Function 0 – GPIO
01 Function 1
10 Function 2
11 Function 3
The exact meaning of Function 1, Function 2, and Function 3 depends on the individual pin. Always refer to the device pin-function table.

6. Example: Configuring P0.0 for UART0 TXD0

P0.0 supports UART0 transmit functionality. To use it as TXD0, its pin-selection field must select the UART0 function.

Embedded C example

#include <LPC21xx.h>

int main(void)
{
    /*
       Configure P0.0 as TXD0.
       PINSEL0 bits 1:0 = 01.
    */

    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    while (1)
    {
        // UART application
    }
}

Code explanation

  1. Include the LPC2129 device header.
  2. Clear the two PINSEL0 bits associated with P0.0.
  3. Set the function-selection field to binary 01.
  4. P0.0 is now configured for TXD0 operation.
This example configures the pin function only. It does not initialize UART0 baud rate, line control, or transmit data.

Peripheral Signal Port Pin

7.3 SPI pins

SPI-related functions are available on selected Port 0 pins. The exact pin mapping depends on the SPI signal and the device pin-function table.

7.4 CAN pins

CAN controller signals are multiplexed with selected Port 0 pins. The appropriate pin functions must be selected before using CAN.

7.5 ADC pins

Analog input channels are available on selected Port 0 pins. The relevant pin must be configured for its analog input function before ADC conversion.

Do not assume that every pin in a peripheral's signal group is interchangeable. Confirm the exact pin assignment, package availability, and function-select value in the LPC2129 datasheet.

8. Pin Configuration for GPIO

To use a multiplexed pin as GPIO, its pin selection must be configured for Function 0 where the device pin table specifies GPIO.

Example: Configure P0.5 as GPIO

#include <LPC21xx.h>

int main(void)
{
    // Select GPIO function for P0.5
    PINSEL0 &= ~(3U << 10);

    // Configure P0.5 as output
    IODIR0 |= (1U << 5);

    // Set P0.5 high
    IOSET0 = (1U << 5);

    while (1)
    {
    }
}

Explanation

  • P0.5 is selected as GPIO through its PINSEL0 field.
  • IODIR0 configures P0.5 as an output.
  • IOSET0 sets the output latch for P0.5.
  • The program remains in the infinite loop.
In the Keil simulator, inspect the relevant register values to verify configuration. A register-level result does not demonstrate that a physical LED has illuminated.

9. Pin Configuration for UART0

UART0 uses P0.0 as TXD0 and P0.1 as RXD0. The pin-selection configuration is required before UART communication can take place. 

#include <LPC21xx.h>

void UART0_Pin_Init(void)
{
    // P0.0 = TXD0
    // P0.1 = RXD0

    PINSEL0 &= ~(0x0FU << 0);
    PINSEL0 |=  (0x05U << 0);
}

int main(void)
{
    UART0_Pin_Init();

    while (1)
    {
        // UART0 configuration and application
    }
}

The two-bit function field for P0.0 is set to 01 and the field for P0.1 is set to 01.

This code configures only the UART0 pins. UART0 itself must still be initialized using its divisor, line-control, and enable registers.

10. Important Pin Configuration Considerations

  1. Identify the required peripheral signal.
  2. Check the device pin-function table.
  3. Confirm that the selected pin is available in the package.
  4. Configure the appropriate PINSEL field.
  5. Configure GPIO direction when using GPIO mode.
  6. Check electrical input and output limits.
  7. Check whether the peripheral requires pull-up or external circuitry.
  8. Ensure that two peripherals are not assigned conflicting functions on the same pin.
I2C and CAN interfaces have electrical requirements beyond pin selection. For example, I2C normally requires suitable pull-up resistors, and CAN requires a suitable external transceiver.

11. Common Mistakes

  1. Confusing a port pin name with a physical package pin number.
  2. Assuming every pin supports every peripheral function.
  3. Forgetting to configure PINSEL registers.
  4. Writing a peripheral function value into the wrong PINSEL field.
  5. Configuring GPIO direction before checking the pin function.
  6. Assuming UART pin configuration alone initializes UART communication.
  7. Ignoring package-specific pin availability.
  8. Ignoring external electrical requirements.

12. Interview Questions and Answers

Q1. What is pin multiplexing?

Pin multiplexing allows one physical pin to support multiple alternate functions.

Q2. What are PINSEL registers?

PINSEL registers select the functions assigned to multiplexed microcontroller pins.

Q3. How many GPIO ports are available in LPC2129?

Two: Port 0 and Port 1.

Q4. How many GPIO pins are available?

Up to 46 GPIO pins.

Q5. Which pin is UART0 TXD0?

P0.0.

Q6. Which pin is UART0 RXD0?

P0.1.

Q7. Which pins are used for I2C0?

P0.2 for SCL0 and P0.3 for SDA0.

Q8. What happens if the wrong PINSEL function is selected?

The pin may perform an unintended function, and the required peripheral signal may not be available on that pin.

Q9. Why must GPIO pins be configured correctly?

Correct pin selection and direction configuration are required for reliable digital input and output.

Q10. Does configuring a UART pin initialize UART?

No. UART peripheral registers must also be configured for baud rate, data format, and transmit/receive operation.

Q11. Why is a CAN transceiver required?

The CAN controller provides protocol-level functionality, while the external transceiver interfaces with the physical differential bus.

Q12. What is the difference between a port pin and a package pin?

A port pin is identified by its logical port and bit name, such as P0.0. A package pin is the physical terminal number on the IC package.

15. Lesson Summary

  • LPC2129 provides physical pins for power, clock, reset, GPIO, and peripherals.
  • It has Port 0 and Port 1 GPIO organizations.
  • Up to 46 GPIO pins are available.
  • Many pins support alternate functions.
  • PINSEL registers select the required pin functions.
  • P0.0 and P0.1 support UART0 TXD0 and RXD0.
  • P0.2 and P0.3 support I2C0 SCL0 and SDA0.
  • Pin configuration must be completed before peripheral operation.
  • Physical package pin assignments must be checked in the datasheet.
