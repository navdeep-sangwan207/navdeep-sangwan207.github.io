1. Introduction

A switch-controlled LED system is a basic embedded application in which a microcontroller reads a digital input and controls a digital output.

In this application, a push button is connected to an LPC2129 GPIO input pin, while an LED is controlled through a GPIO output pin.

The microcontroller continuously monitors the button state and changes the LED state according to the program logic.

Learning objectives:
  • Understand switch-controlled LED operation.
  • Configure GPIO input and output pins together.
  • Read a push button using IOPIN.
  • Control an LED using IOSET and IOCLR.
  • Implement active-LOW switch logic.
  • Understand polling-based input monitoring.
  • Implement basic switch debouncing.
  • Observe GPIO register activity in Keil uVision.

2. Working Principle

The push button provides an input signal to the microcontroller.

The LPC2129 reads this signal through its GPIO input register. Based on the input state, the program controls the LED through its GPIO output register.

PUSH BUTTON | v GPIO INPUT P0.6 | v LPC2129 CPU | Program Logic | v GPIO OUTPUT P0.5 | v LED

Basic operation

  1. Configure the push-button pin as an input.
  2. Configure the LED pin as an output.
  3. Read the push-button state.
  4. Check whether the button is pressed.
  5. Turn the LED ON or OFF according to the input.

4. GPIO Pin Configuration

The LPC2129 requires separate configuration for the input and output pins.

Push-button pin P0.6

  • PINSEL0 bits 13:12 select the P0.6 function.
  • GPIO function is selected using 00.
  • IODIR0 bit 6 is cleared to configure input mode.
// Configure P0.6 as GPIO
PINSEL0 &= ~(3U << 12);

// Configure P0.6 as input
IODIR0 &= ~(1U << 6);

LED output pin P0.5

  • PINSEL0 bits 11:10 select the P0.5 function.
  • GPIO function is selected using 00.
  • IODIR0 bit 5 is set to configure output mode.
// Configure P0.5 as GPIO
PINSEL0 &= ~(3U << 10);

// Configure P0.5 as output
IODIR0 |= (1U << 5);

5. Program 1: LED ON While Button Is Pressed

This program turns the LED ON while the push button is pressed. The LED turns OFF when the button is released.

The circuit uses:

  • Active-LOW push button on P0.6.
  • Active-HIGH LED on P0.5.
#include <LPC21xx.h>

int main(void)
{
    unsigned int button_status;

    // Configure P0.6 as GPIO input
    PINSEL0 &= ~(3U << 12);
    IODIR0 &= ~(1U << 6);

    // Configure P0.5 as GPIO output
    PINSEL0 &= ~(3U << 10);
    IODIR0 |= (1U << 5);

    // Initially turn LED OFF
    IOCLR0 = (1U << 5);

    while (1)
    {
        // Read push button
        button_status =
            (IOPIN0 >> 6) & 1U;

        if (button_status == 0U)
        {
            // Button pressed
            IOSET0 = (1U << 5);
        }
        else
        {
            // Button released
            IOCLR0 = (1U << 5);
        }
    }
}

Program explanation

  1. Configure P0.6 as an input.
  2. Configure P0.5 as an output.
  3. Initially clear P0.5 to turn the active-HIGH LED OFF.
  4. Read P0.6 using IOPIN0.
  5. If the input is LOW, set P0.5 HIGH.
  6. If the input is HIGH, clear P0.5 LOW.
  7. Repeat continuously.
Important logic: The button is active-LOW. Therefore, a zero input value indicates that the button is pressed.

6. Program 2: Toggle LED When Button Is Pressed

In this application, each valid button press changes the LED to the opposite state.

The behavior is:

Button Press LED Action
First press LED turns ON.
Second press LED turns OFF.
Third press LED turns ON.
Fourth press LED turns OFF. 
#include <LPC21xx.h>

void delay(void)
{
    volatile unsigned int i;

    for (i = 0; i < 10000; i++)
    {
    }
}

int main(void)
{
    unsigned int led_state = 0;

    // P0.6 as GPIO input
    PINSEL0 &= ~(3U << 12);
    IODIR0 &= ~(1U << 6);

    // P0.5 as GPIO output
    PINSEL0 &= ~(3U << 10);
    IODIR0 |= (1U << 5);

    // LED initially OFF
    IOCLR0 = (1U << 5);

    while (1)
    {
        // Detect active-LOW button press
        if ((IOPIN0 & (1U << 6)) == 0U)
        {
            delay();

            // Confirm button is still pressed
            if ((IOPIN0 & (1U << 6)) == 0U)
            {
                // Change LED state
                if (led_state == 0U)
                {
                    IOSET0 = (1U << 5);
                    led_state = 1U;
                }
                else
                {
                    IOCLR0 = (1U << 5);
                    led_state = 0U;
                }

                // Wait until button is released
                while ((IOPIN0 & (1U << 6)) == 0U)
                {
                }

                delay();
            }
        }
    }
}

Program explanation

  1. Initialize led_state to zero.
  2. Continuously check the push-button input.
  3. Detect an active-LOW button press.
  4. Apply a short delay to reduce contact-bounce effects.
  5. Confirm that the button remains pressed.
  6. Change the LED state using IOSET0 or IOCLR0.
  7. Wait for the button to be released.
  8. Repeat the process.
This is a basic blocking debounce example. The software delay is not calibrated. A production system should use a non-blocking, timer-based debounce method when responsive processing is required.

7. Program 3: Two Switches Control One LED

This example uses two active-LOW switches and one active-HIGH LED.

Component GPIO Pin Direction
Switch 1 P0.6 Input
Switch 2 P0.7 Input
LED P0.5 Output

The LED turns ON if either switch is pressed. 

#include <LPC21xx.h>

int main(void)
{
    unsigned int sw1;
    unsigned int sw2;

    // Configure P0.6 and P0.7 as GPIO
    PINSEL0 &= ~((3U << 12) |
                 (3U << 14));

    // Configure P0.5 as GPIO
    PINSEL0 &= ~(3U << 10);

    // Configure switch pins as inputs
    IODIR0 &= ~((1U << 6) |
                (1U << 7));

    // Configure LED pin as output
    IODIR0 |= (1U << 5);

    while (1)
    {
        sw1 = (IOPIN0 >> 6) & 1U;
        sw2 = (IOPIN0 >> 7) & 1U;

        // Either active-LOW switch pressed
        if ((sw1 == 0U) || (sw2 == 0U))
        {
            IOSET0 = (1U << 5);
        }
        else
        {
            IOCLR0 = (1U << 5);
        }
    }
}

Logic explanation

The OR operator checks whether at least one of the switches is pressed.

Switch 1 Switch 2 LED
Released Released OFF
Pressed Released ON
Released Pressed ON
Pressed Pressed ON

8. Polling-Based Switch Monitoring

The programs in this lesson use polling to monitor the push-button input.

Polling means that the CPU repeatedly checks the input state inside a program loop.

Start | v Read GPIO Input | v Button Pressed? / \ Yes No | | v v LED ON LED OFF \ / \ / v v Repeat Loop

Advantages

  • Simple implementation.
  • Easy to understand and debug.
  • Suitable for basic GPIO applications.

Limitations

  • CPU continuously checks the input.
  • Blocking delays can prevent other tasks from running.
  • Input response depends on polling frequency.

9. Improving the Program Using a State Machine

A finite state machine can make button handling more structured.

The application can use states such as:

State Meaning
RELEASED Button is not pressed.
PRESS_DETECTED Potential button press detected.
DEBOUNCE Wait for the input to stabilize.
PRESSED Valid button press confirmed.

A timer-based state machine can check the button at regular intervals without blocking the entire program with long delay loops.

State-machine-based input handling is useful when an embedded system must monitor multiple switches while continuing other operations.

10. Common Programming Mistakes

  1. Wrong input logic: An active-LOW button is pressed when the input reads LOW.
  2. Incorrect GPIO direction: Configure the switch pin as input and the LED pin as output.
  3. Incorrect pin function: Select GPIO mode through PINSEL.
  4. Floating switch input: Provide a suitable pull-up or pull-down.
  5. Missing debounce: One physical press may produce multiple detected transitions.
  6. Not waiting for release: A toggle program may repeatedly change the LED state while the button remains pressed.
  7. Using an uncalibrated delay: Software loop duration depends on clock and compiler configuration.

12. Interview Questions and Answers

Q1. What is switch-controlled LED programming?

It is an embedded application in which a microcontroller reads a switch input and controls an LED output.

Q2. Which register reads the switch state?

IOPIN.

Q3. Which registers control the LED output?

IOSET and IOCLR.

Q4. What is an active-LOW switch?

It is a switch arrangement in which pressing the button produces a LOW input level.

Q5. What is polling?

Polling is the repeated checking of a hardware input by the processor.

Q6. Why is debounce logic required?

It prevents unwanted multiple detections caused by mechanical contact bounce.

Q7. What is the difference between LED control and LED toggling?

Direct control makes the LED follow the button state. Toggling changes the LED state once per valid press.

Q8. Why should a toggle program wait for button release?

To prevent repeated toggles while the same physical press is being held.

Q9. What is a finite state machine?

A finite state machine is a programming model in which system behavior is organized into defined states and transitions.

Q10. What is the limitation of blocking debounce?

The CPU waits during the delay or release loop and cannot perform other work in that execution path.
