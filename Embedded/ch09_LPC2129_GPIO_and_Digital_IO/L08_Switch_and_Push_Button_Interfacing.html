1. Introduction

Switches and push buttons are commonly used as digital input devices in embedded systems. They allow users or external circuits to provide control signals to a microcontroller.

The LPC2129 can read these signals through its GPIO input pins.

A GPIO input pin can detect two basic digital logic states: HIGH and LOW.

  • Understand normally open and normally closed contacts.
  • Understand pull-up and pull-down resistors.
  • Understand active-HIGH and active-LOW inputs.

2. What Is a Switch?

A switch is an electrical component used to open or close an electrical circuit.

It can control the connection between two electrical points.

Switch State Electrical Condition
Open Current path through the switch is interrupted.
Closed Current can flow through the switch, subject to the circuit.

Applications

  • Power ON/OFF control.
  • Mode selection.
  • Reset input.
  • User command input.
  • Machine start and stop controls.
  • Embedded system configuration.

3. What Is a Push Button?

A push button is a momentary switch that changes its contact state while it is pressed.

When the button is released, its contacts normally return to their original state.

Types of push buttons

Type Operation
Normally Open (NO) Contacts are open when not pressed and close when pressed.
Normally Closed (NC) Contacts are closed when not pressed and open when pressed.
NORMALLY OPEN (NO) Not pressed: --/ /-- Pressed: -------- NORMALLY CLOSED (NC) Not pressed: -------- Pressed: --/ /--

NO and NC describe the contact state when the push button is not pressed.

4. GPIO Input Configuration

To read a switch, the selected LPC2129 pin must be configured as a GPIO input.

Configuration steps

  1. Select GPIO function using the appropriate PINSEL register.
  2. Configure the pin as an input using IODIR.
  3. Read the pin state through IOPIN.
  4. Interpret the HIGH or LOW state according to the circuit design.

IODIR input configuration

A zero in the relevant IODIR bit configures the pin as an input. 

// Configure P0.6 as GPIO
PINSEL0 &= ~(3U << 12);

// Configure P0.6 as input
IODIR0 &= ~(1U << 6);
P0.6 uses PINSEL0 bits 13:12. The function selection and direction must both be configured correctly.

5. Why Is a Pull-Up Resistor Required?

An unconnected digital input may become floating. A floating input does not have a reliably defined logic level and can change unpredictably due to electrical noise.

A pull-up resistor connects the input to a positive supply through a resistance.

Pull-up connection

+3.3 V | Pull-up Resistor | +-------- LPC2129 GPIO Input | Switch | GND Switch OPEN = HIGH Switch CLOSED = LOW
Switch State GPIO Input
Released / Open HIGH
Pressed / Closed LOW
This is an active-LOW input arrangement because pressing the switch produces a LOW input level.

6. Pull-Down Resistor

A pull-down resistor connects the GPIO input to ground through a resistance.

It keeps the input LOW when the switch is open.

Pull-down connection

+3.3 V | Switch | +-------- LPC2129 GPIO Input | Pull-down Resistor | GND Switch OPEN = LOW Switch CLOSED = HIGH
Switch State GPIO Input
Released / Open LOW
Pressed / Closed HIGH
This is an active-HIGH input arrangement because pressing the switch produces a HIGH input level.

7. Difference Between Pull-Up and Pull-Down Resistors

Feature Pull-Up Pull-Down
Connection Input connected to supply through resistance. Input connected to ground through resistance.
Default input state HIGH LOW
Typical switch action Pressing connects input to ground. Pressing connects input to supply.
Pressed state LOW HIGH

8. Active-HIGH and Active-LOW Inputs

Active-HIGH input

An input is considered active when its logic level is HIGH. A pull-down arrangement is commonly used.

Active-LOW input

An input is considered active when its logic level is LOW. A pull-up arrangement is commonly used.

Input Type Inactive State Active State
Active-HIGH LOW HIGH
Active-LOW HIGH LOW
Active-HIGH and active-LOW describe the logical meaning assigned to an input. They are not properties of the switch itself.

9. Reading a Push Button Using IOPIN

IOPIN is used to read the current logic state of a GPIO pin.

Example: Read P0.6

unsigned int switch_status;

switch_status = IOPIN0 & (1U << 6);

The bitwise AND operation extracts bit 6 from IOPIN0.

Normalize the result to 0 or 1

unsigned int switch_status;

switch_status = (IOPIN0 >> 6) & 1U;
Normalized Value Pin State
0 LOW
1 HIGH

10. Program: Read Push Button State

This program reads a push button connected to P0.6. 

#include <LPC21xx.h>

int main(void)
{
    unsigned int switch_status;

    // Select GPIO function for P0.6
    PINSEL0 &= ~(3U << 12);

    // Configure P0.6 as input
    IODIR0 &= ~(1U << 6);

    while (1)
    {
        // Read input state
        switch_status =
            (IOPIN0 >> 6) & 1U;

        if (switch_status == 1U)
        {
            // Input is HIGH
        }
        else
        {
            // Input is LOW
        }
    }
}

The program continuously reads the input pin and stores its normalized state in switch_status.

The program does not assume that HIGH always means pressed. That interpretation depends on whether the circuit uses a pull-up or pull-down arrangement.

11. Switch Bouncing

Mechanical switches do not always change cleanly from one logic state to another. When their contacts open or close, they may produce several rapid transitions.

This phenomenon is called switch bouncing or contact bounce.

Illustrative bouncing waveform

Ideal transition: LOW __________|‾‾‾‾‾‾‾‾‾‾ HIGH Bouncing transition: LOW _______|‾|_|‾|__|‾‾‾‾‾ HIGH

A microcontroller may interpret these rapid transitions as multiple button presses.

Problems caused by switch bouncing

  • Multiple counts from one press.
  • Repeated menu selection.
  • Unwanted state changes.
  • Incorrect event detection.

12. Switch Debouncing

Debouncing is the process of filtering unwanted rapid transitions so that one physical button action is interpreted as one logical event.

Common debouncing techniques

Technique Description
Software delay Wait briefly and check the input again.
Repeated sampling Require several consistent input samples.
State machine Track press, release, and stable states.
Hardware filtering Use suitable RC or dedicated debounce circuitry.

Basic software debounce example

#include <LPC21xx.h>

void delay(void)
{
    volatile unsigned int i;

    for (i = 0; i < 10000; i++)
    {
    }
}

int main(void)
{
    unsigned int button;

    // P0.6 as GPIO
    PINSEL0 &= ~(3U << 12);

    // P0.6 as input
    IODIR0 &= ~(1U << 6);

    while (1)
    {
        // Active-LOW button:
        // LOW means pressed
        if ((IOPIN0 & (1U << 6)) == 0U)
        {
            delay();

            // Confirm button is still pressed
            if ((IOPIN0 & (1U << 6)) == 0U)
            {
                button = 1U;

                // Wait for release
                while ((IOPIN0 & (1U << 6)) == 0U)
                {
                }

                button = 0U;
            }
        }
    }
}
This is a basic illustrative debounce method. The delay is not calibrated, and the release-wait loop blocks program execution. More advanced firmware can use timer-based sampling and a non-blocking state machine.

13. Practical Applications

  • Start and stop buttons.
  • Reset switches.
  • Mode selection buttons.
  • User interface navigation.
  • Emergency stop input monitoring.
  • Digital sensor and limit-switch inputs.
  • Industrial control panels.
Emergency stop systems should use appropriate safety-rated hardware and safety design. A general-purpose GPIO input and software loop alone are not a substitute for a certified safety circuit.

14. Common Programming and Circuit Mistakes

  1. Floating input: An input without a defined pull-up or pull-down may change unpredictably.
  2. Incorrect PINSEL setting: The pin may be assigned to an alternate peripheral function.
  3. Incorrect IODIR setting: An input pin must have its direction bit cleared.
  4. Wrong active logic: A pull-up switch commonly produces LOW when pressed.
  5. Missing debounce: Mechanical contact bounce may create multiple events.
  6. Unsafe input voltage: Never apply a voltage outside the microcontroller pin's permitted electrical range.
  7. Assuming an internal pull resistor: Do not assume that a particular pin has a configurable internal pull-up or pull-down. Check the LPC2129 documentation and design the external circuit accordingly.

16. Interview Questions and Answers

Q1. What is a switch?

A switch is an electrical component that opens or closes a circuit.

Q2. What is a push button?

A push button is a momentary switch that changes contact state while pressed.

Q3. What is the difference between NO and NC switches?

NO contacts are open at rest, whereas NC contacts are closed at rest.

Q4. What is a pull-up resistor?

A resistor that connects a digital input to a positive supply through a resistance.

Q5. What is a pull-down resistor?

A resistor that connects a digital input to ground through a resistance.

Q6. Why are pull-up and pull-down resistors used?

They provide a defined default logic level and prevent floating inputs.

Q7. Which register reads GPIO input states?

IOPIN.

Q8. What is switch bouncing?

It is the rapid electrical transition of mechanical switch contacts during pressing or releasing.

Q9. What is debouncing?

Debouncing filters unwanted transitions so that one physical switch action is interpreted as one event.

Q10. What is an active-LOW input?

An input in which LOW represents the active condition.
