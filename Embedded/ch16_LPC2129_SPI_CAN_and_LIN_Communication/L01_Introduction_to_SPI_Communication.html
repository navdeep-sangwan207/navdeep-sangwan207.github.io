Lesson 01: Introduction to SPI Communication

Understand Serial Peripheral Interface (SPI), its communication principles, signal lines, master and slave architecture, data transmission and applications in embedded systems.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Define Serial Peripheral Interface (SPI).
  • Understand the need for serial communication.
  • Explain synchronous serial communication.
  • Identify the four common SPI signal lines.
  • Understand SPI master and slave operation.
  • Explain SPI data transmission and reception.
  • Understand full-duplex communication.

  • Identify common SPI applications.

2. Introduction to Serial Communication

Serial communication is a method of transferring data between electronic devices one bit at a time through a communication channel.

Embedded systems use serial communication to exchange information between microcontrollers, sensors, memory devices, displays and other electronic components.

Why Serial Communication Is Used

  • Reduces the number of communication wires.
  • Allows communication between separate electronic devices.
  • Supports communication over different distances depending on the protocol.
  • Reduces the number of required MCU pins compared with parallel interfaces.
  • Provides standardized communication methods.

Types of Serial Communication

Serial Communication Classification 
          Serial Communication
                  |
          +-------+-------+
          |               |
       Synchronous     Asynchronous
          |               |
       +--+--+          UART
       |     |
      SPI   I2C

SPI and I2C use a clock signal to synchronize data transfer. UART commonly uses configured baud rates and start/stop bits without a separate clock line.

3. What Is SPI?

SPI stands for Serial Peripheral Interface. It is a synchronous serial communication protocol commonly used for communication between a controller and peripheral devices.

SPI uses a clock signal generated by the controller and separate data paths for transmission and reception. A chip-select signal identifies the peripheral that should participate in the communication.

SPI Characteristics

  • Synchronous serial communication.
  • Controller-generated serial clock.
  • Separate transmit and receive data lines.
  • Usually uses a chip-select signal for each peripheral.
  • Supports full-duplex data transfer.
  • Commonly uses shift registers for data movement.
  • Does not define a universal device-addressing mechanism.
SPI is widely used in embedded systems because of its simple hardware interface and ability to transfer data at relatively high clock rates.

4. SPI Communication Architecture

A typical SPI connection consists of one controller and one or more peripheral devices.

Basic SPI Architecture 
              SPI Controller
          +--------------------+
          |                    |
          |       MCU          |
          |                    |
          |  MOSI ------------+----------------+
          |  MISO <-----------+----------------|
          |  SCLK ------------+----------------|
          |  CS0 -------------|----------+     |
          +--------------------+          |     |
                                          |     |
                                  +-------v-----v--+
                                  | SPI Peripheral |
                                  |                |
                                  |  MOSI          |
                                  |  MISO          |
                                  |  SCLK          |
                                  |  CS            |
                                  +----------------+

The controller generates SCLK and selects the target peripheral using its chip-select signal. The selected peripheral then participates in the data transfer.

Multiple Peripheral Devices

A controller can communicate with multiple SPI peripherals. In a common arrangement, SCLK, MOSI and MISO are shared, while each peripheral has a separate chip-select signal.

One Controller with Multiple SPI Peripherals 
                   MCU
            +----------------+
            |                |
            | MOSI ----------+----------+----------+
            | MISO <----------+----------+----------|
            | SCLK ----------+----------+----------|
            |                |          |          |
            | CS0 -----------|--+       |          |
            | CS1 -----------|---------|--+       |
            +----------------+          |          |
                                        |          |
                                 +------v---+ +----v------+
                                 | Device 1 | | Device 2  |
                                 +----------+ +-----------+

Only the selected peripheral should actively drive the shared MISO line. Unselected devices normally place their output in a high-impedance state when designed for a shared SPI bus.

5. SPI Signal Lines

The conventional SPI interface uses four signal lines. Their names can vary between manufacturers and microcontroller documentation.

Signal Alternative Name Function
MOSI SDO / COPI Controller sends data to peripheral.
MISO SDI / CIPO Peripheral sends data to controller.
SCLK SCK Serial clock generated by controller.
SS / CS NSS Selects the target peripheral.

5.1 MOSI – Master Out Slave In

MOSI carries data from the SPI controller to the selected peripheral.

Examples include:

  • Sending a command to an SPI display.
  • Writing data into external Flash memory.
  • Sending configuration values to an SPI sensor.

5.2 MISO – Master In Slave Out

MISO carries data from the selected peripheral to the SPI controller.

Examples include:

  • Reading sensor measurements.
  • Reading data from external memory.
  • Receiving device status information.

5.3 SCLK – Serial Clock

SCLK synchronizes data transfer between the controller and peripheral.

  • Generated by the SPI controller in conventional master mode.
  • Controls when data is sampled and shifted.
  • Its polarity and phase determine the clocking mode.
  • Its frequency affects the transfer rate.

5.4 SS / CS – Slave Select / Chip Select

The chip-select signal selects the peripheral that should communicate with the controller.

  • Often active LOW.
  • Usually one CS signal is provided for each peripheral.
  • Must follow the timing requirements of the target device.
Some SPI devices support different chip-select polarity or special addressing arrangements. Always check the peripheral datasheet.

6. SPI Controller and Peripheral Operation

In a typical SPI transaction, the controller initiates communication by selecting a peripheral and generating the serial clock.

Controller Responsibilities

  • Configure the SPI clock.
  • Configure clock polarity and phase.
  • Select the target peripheral.
  • Load data for transmission.
  • Generate the clock pulses.
  • Read the received data.
  • End the transaction by releasing chip select.

Peripheral Responsibilities

  • Respond when selected.
  • Receive controller data.
  • Transmit response data when required.
  • Follow the configured clock mode.
  • Observe chip-select timing requirements.
Typical SPI Transaction 
 Controller                  Peripheral
     |                            |
     |------ CS LOW ------------->|
     |                            |
     |------ SCLK --------------->|
     |                            |
     |------ MOSI DATA ---------->|
     |                            |
     |<----- MISO DATA -----------|
     |                            |
     |------ CS HIGH ------------>|
     |                            |
     +-------- Transaction -------+

7. SPI Data Transmission

SPI transfers data serially using shift registers. A data word is loaded into the transmit path and shifted one bit at a time according to the clock signal.

A common SPI data word contains 8 bits, although peripheral and controller implementations may support other word lengths.

Example: Transmitting 8 Bits

Assume the controller wants to transmit:

Data = 0xA5

Binary = 10100101

The controller selects the peripheral and shifts the data according to the configured SPI bit order. Many SPI devices use MSB-first transfer, but LSB-first operation is also possible.

Conceptual 8-Bit SPI Transfer 
Data:       1  0  1  0  0  1  0  1
            |  |  |  |  |  |  |  |
Clock:     _|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
            1  2  3  4  5  6  7  8

The exact sampling edge depends on SPI clock polarity and phase. These settings are explained in Lesson 03.

8. SPI Full-Duplex Communication

SPI supports full-duplex communication because it uses separate transmit and receive data lines.

During a clock cycle, the controller can transmit one bit through MOSI while simultaneously receiving one bit through MISO.

Full-Duplex Data Transfer 
              Controller             Peripheral
              ----------             ----------

MOSI  ------>  Data Bit 1 --------->  Receive Bit 1

MISO  <------  Receive Bit 1 <------- Data Bit 1

SCLK  ------>  Clock Pulse --------> Clock Pulse

              Both directions operate
              during the same clock cycles.

Important Observation

Even when the controller only wants to receive data, it must generate clock pulses. It commonly transmits dummy bytes to generate the required clocks. 

Transmit dummy byte: 0xFF

Clock pulses are generated.

Controller receives the peripheral response
through MISO.
SPI is electrically full-duplex, but a particular peripheral protocol may use only one direction at a time or may define the returned bits as status or dummy data.

9. SPI Clock Frequency and Data Rate

The SPI clock frequency determines how quickly bits are shifted between the controller and peripheral.

Basic relationship:

Bit Transfer Rate = SPI Clock Frequency

This relationship assumes one transferred bit per clock cycle and does not include transaction gaps or software overhead.

Example 1: 1 MHz SPI Clock

SPI Clock = 1 MHz

Clock Period = 1 / 1,000,000

Clock Period = 1 microsecond

8-bit transfer time = 8 microseconds

Example 2: 4 MHz SPI Clock

SPI Clock = 4 MHz

Clock Period = 1 / 4,000,000

Clock Period = 0.25 microseconds

8-bit transfer time = 2 microseconds
These are ideal transfer-time calculations. Actual transaction time can be longer because of chip-select timing, peripheral delays, software overhead and controller configuration.

10. SPI Communication Modes

SPI supports four clock modes based on two parameters: Clock Polarity (CPOL) and Clock Phase (CPHA).

Mode CPOL CPHA
Mode 000
Mode 101
Mode 210
Mode 311

CPOL determines the idle level of SCLK. CPHA determines which clock edge is used for data sampling.

The controller and peripheral must use compatible SPI modes. A mismatch can cause incorrect received data or unreliable communication.

Detailed clock edge diagrams and all four modes are covered in the next lesson: SPI Modes and Clock Polarity.

11. SPI Advantages

  • Simple communication interface.
  • High data-transfer rates in many implementations.
  • Full-duplex data transfer capability.
  • No device-address field is required in the basic protocol.
  • Separate transmit and receive paths.
  • Flexible clock configuration.
  • Widely supported by microcontrollers and peripherals.
  • Suitable for communication with memory and sensors.

12. SPI Limitations

  • Requires more signal wires than I2C for a basic connection.
  • Each peripheral commonly requires a separate chip-select signal.
  • There is no universally defined SPI device-addressing mechanism.
  • There is no standard acknowledgement mechanism in basic SPI.
  • Controller and peripheral must agree on clock configuration.
  • Signal integrity becomes important at higher clock frequencies.
  • Maximum cable length depends on electrical implementation and signal quality.

13. SPI vs I2C vs UART

Feature SPI I2C UART
Communication Synchronous Synchronous Asynchronous
Clock line Yes Yes No separate clock
Basic signal lines 4 2 2 for TX/RX
Data direction Full-duplex capable Half-duplex on shared SDA Full-duplex capable
Addressing Usually chip select Device address No basic device address
Clock configuration CPOL and CPHA SCL timing Baud rate agreement
Typical use Flash, display, sensors Sensors, RTC, EEPROM Debugging, serial terminals

The actual maximum communication speed depends on the MCU, peripheral, electrical design and protocol configuration. There is no universal speed limit applicable to every SPI, I2C or UART implementation.

14. SPI Applications in Embedded Systems

1. External Flash Memory

SPI is used to read, write and erase data in external Flash memory devices.

2. Sensor Interfacing

SPI sensors can provide measurements such as temperature, acceleration, pressure and angular velocity.

3. Display Controllers

SPI transfers commands and pixel data to compatible display controllers.

4. External ADC and DAC

SPI can transfer configuration values and digital conversion data to and from external converters.

5. Memory Cards

Certain memory cards support SPI mode for communication with microcontrollers.

15. SPI in LPC2129 Embedded Systems

The LPC2129 provides an SPI peripheral that can be programmed using its control, status and data registers. The SPI peripheral can communicate with compatible external devices.

The SPI programming process generally involves:

  1. Configure the required SPI pin functions.
  2. Configure the SPI control register.
  3. Set the required clock rate and operating mode.
  4. Configure the data format.
  5. Load the transmit data register.
  6. Wait for transfer completion.
  7. Read the received data.
  8. Manage the target chip-select signal.
The LPC2129 also has a separate SSP peripheral on supported device variants. Do not assume that the legacy SPI and SSP register sets or pin mappings are interchangeable. The following lessons focus on the specific LPC2129 SPI peripheral and its documented register interface.

18. Interview Questions and Answers

Q1. What is SPI?

SPI is a synchronous serial communication protocol commonly used between microcontrollers and peripheral devices.

Q2. What is the full form of SPI?

Serial Peripheral Interface.

Q3. What are the four common SPI signals?

MOSI, MISO, SCLK and CS/SS.

Q4. What is MOSI?

It carries data from the controller to the peripheral.

Q5. What is MISO?

It carries data from the peripheral to the controller.

Q6. What is the function of SCLK?

It synchronizes the transmission and reception of data.

Q7. What is chip select?

It identifies which peripheral should participate in an SPI transaction.

Q8. Is SPI synchronous or asynchronous?

SPI is synchronous.

Q9. Does SPI support full-duplex communication?

Yes. Separate MOSI and MISO paths allow simultaneous transmission and reception.

Q10. What are CPOL and CPHA?

They define the SPI clock polarity and clock phase.

Q11. Why are dummy bytes transmitted?

They generate clock pulses when the controller needs to receive data from a peripheral.

Q12. Does basic SPI use a standard device address?

No. Peripheral selection commonly uses individual chip-select signals.
