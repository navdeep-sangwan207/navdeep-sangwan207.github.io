Lesson 04: LPC2129 SPI Architecture and Registers

Study the LPC2129 SPI hardware architecture, internal data-transfer mechanism, register map, control bits, status flags and clock configuration.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand the SPI peripheral architecture of LPC2129.
  • Identify the SPI0 and SPI1 interfaces.
  • Understand the internal SPI block diagram.
  • Identify the five main SPI registers.
  • Explain the SPI Control Register (SPCR).
  • Understand the SPI Status Register (SPSR).
  • Explain the SPI Data Register (SPDR).
  • Calculate SPI clock frequency using SPCCR.
  • Understand the SPI Interrupt Register (SPINT).
  • Configure the SPI peripheral for basic master operation.

2. Introduction to LPC2129 SPI

The LPC2129 microcontroller provides two legacy SPI interfaces called SPI0 and SPI1.

These interfaces allow the microcontroller to communicate synchronously with external devices such as sensors, memory devices and display controllers.

SPI Features

  • Two SPI interfaces: SPI0 and SPI1.
  • Master and slave operating modes.
  • Synchronous serial communication.
  • Separate MOSI and MISO data paths.
  • Programmable clock polarity and phase.
  • Programmable clock rate in master mode.
  • Transfer-complete and error status flags.
  • Interrupt generation support.
Device variant distinction: The standard LPC2129 without the /01 enhancement uses the legacy SPI peripheral with fixed 8-bit transfers. The LPC2129/01 includes enhanced capabilities and an SSP peripheral. The SPI and SSP register interfaces are different.

3. SPI0 and SPI1 Interfaces

The LPC2129 provides two SPI hardware interfaces. Each interface has its own register set and communication signals.

Interface Register Prefix Function
SPI0 S0 First SPI communication interface
SPI1 S1 Second SPI communication interface

Register Naming Examples

SPI0 Control Register  = S0SPCR
SPI0 Status Register   = S0SPSR
SPI0 Data Register     = S0SPDR

SPI1 Control Register  = S1SPCR
SPI1 Status Register   = S1SPSR
SPI1 Data Register     = S1SPDR

The SPI0 and SPI1 register sets operate independently. A program can configure an interface according to the connected peripheral and required communication mode.

4.1 Register Interface

The register interface connects the CPU to the SPI peripheral through the peripheral bus.

The CPU uses the registers to configure communication, write transmit data, read received data and check transfer status.

4.2 SPI Shift Register

The shift register moves data serially between the controller and peripheral.

  • Accepts transmit data from the data register.
  • Shifts outgoing data onto MOSI.
  • Samples incoming data from MISO.
  • Builds the received data word.

4.3 SPI Clock Generator

The clock generator produces the serial clock in master mode.

The clock frequency is configured through the SPI Clock Counter Register (SPCCR).

4.4 SPI State Control

The state-control logic manages the internal transfer sequence, clock operation, data movement and completion status.

4.5 Output Enable Logic

The output-enable logic controls which SPI signals are driven by the peripheral depending on whether the SPI is operating as a master or slave.

5. LPC2129 SPI Register Map

The legacy SPI peripheral contains five main registers. SPI0 and SPI1 have separate register addresses.

Register SPI0 Address SPI1 Address Access
SPCR 0xE0020000 0xE0030000 Read/Write
SPSR 0xE0020004 0xE0030004 Read Only
SPDR 0xE0020008 0xE0030008 Read/Write
SPCCR 0xE002000C 0xE003000C Read/Write
SPINT 0xE002001C 0xE003001C Read/Write
These are the peripheral register addresses from the NXP LPC21xx/LPC22xx User Manual UM10114. Use the correct SPI0 or SPI1 register names for the interface being programmed.

6. SPI Control Register (SPCR)

SPCR stands for SPI Control Register. It configures the operating mode and data-transfer behavior of the SPI peripheral.

SPCR Bit Organization

SPCR Register Fields 
Bit:  15       12 11        8 7  6  5  4  3  2  1   0
     +-----------+-----------+--+--+--+--+--+--+------+
     | Reserved  |   BITS    |IE|LS|M |P |P |BE|Reserved
     +-----------+-----------+--+--+--+--+--+--+------+

     M  = Master mode select
     LS = LSB first
     IE = SPI interrupt enable
     P  = CPOL / CPHA
     BE = BitEnable
Bit Field Function
1:0 Reserved Must remain zero.
2 BitEnable Enables programmable transfer length on enhanced variants.
3 CPHA Controls clock phase.
4 CPOL Controls clock polarity.
5 MSTR Selects master or slave mode.
6 LSBF Selects LSB-first or MSB-first transfer.
7 SPIE Enables SPI interrupt generation.
11:8 BITS Transfer width on enhanced variants when BitEnable is set.
15:12 Reserved Must remain zero.

6.1 Bit 2 – BitEnable

On enhanced variants, this bit controls whether the transfer width is fixed at 8 bits or selected through the BITS field.

  • 0: 8 bits per transfer.
  • 1: Transfer width selected by SPCR bits 11:8.
The standard LPC2129 legacy version has fixed 8-bit SPI transfers. Do not enable programmable transfer width or assume that the BITS field is available on that version.

6.2 Bit 3 – CPHA

This bit controls the clock phase.

  • 0: Data sampled on the first clock edge.
  • 1: Data sampled on the second clock edge.

6.3 Bit 4 – CPOL

This bit controls the clock polarity.

  • 0: SCK is active HIGH; idle level is LOW.
  • 1: SCK is active LOW; idle level is HIGH.

6.4 Bit 5 – MSTR

This bit selects the operating mode.

  • 0: SPI operates in slave mode.
  • 1: SPI operates in master mode.

6.5 Bit 6 – LSBF

This bit selects the order in which bits are shifted.

  • 0: MSB first.
  • 1: LSB first.

6.6 Bit 7 – SPIE

This bit enables SPI interrupt generation.

  • 0: SPI interrupts inhibited.
  • 1: Interrupt generated when SPIF or MODF changes from 0 to 1.

6.7 Bits 11:8 – BITS

On enhanced versions, this field selects the number of bits per transfer when BitEnable is set.

Supported transfer lengths include 8 to 16 bits. This programmable feature does not apply to the standard LPC2129 legacy SPI interface.

7. SPI Status Register (SPSR)

SPSR stands for SPI Status Register. It contains flags that indicate transfer completion and error conditions.

SPSR Bit Organization

Bit Flag Description
2:0 Reserved Reserved bits.
3 ABRT Slave transfer aborted.
4 MODF Mode fault detected.
5 ROVR Read overrun detected.
6 WCOL Write collision detected.
7 SPIF SPI transfer complete.

7.1 ABRT – Slave Abort

This flag indicates that an SPI slave transfer was aborted.

A slave transfer can be aborted if SSEL becomes inactive before the transfer is completed.

ABRT is cleared by reading SPSR.

7.2 MODF – Mode Fault

This flag indicates a mode fault.

In master mode, the SSEL signal must remain inactive. If it becomes active, the SPI hardware detects a mode fault.

The hardware deactivates the SPI signal drivers and changes the SPI operating mode to slave.

To clear MODF, read SPSR and then write SPCR.

7.3 ROVR – Read Overrun

Read overrun occurs when received data is not read before another transfer completes and new data needs to enter the receive buffer.

The previously unread data is retained and the new received data is lost.

ROVR is cleared by reading SPSR.

7.4 WCOL – Write Collision

Write collision occurs when software writes to SPDR while a previous transfer is still in progress or before the required status-register access.

The attempted write is lost.

WCOL is cleared by reading SPSR and then accessing SPDR.

7.5 SPIF – SPI Transfer Complete

SPIF indicates that the SPI transfer has completed.

  • In master mode, it is set at the end of the last transfer cycle.
  • In slave mode, it is set on the last data-sampling clock edge.

To clear SPIF, software must first read SPSR and then access SPDR by reading or writing it.

SPIF and the SPI interrupt flag are different. SPIF is located in SPSR bit 7. The separate SPI interrupt flag is located in SPINT bit 0.

8. SPI Data Register (SPDR)

SPDR stands for SPI Data Register. It is used for both transmitting and receiving data.

SPDR Functions

  • Writing to SPDR loads data for transmission.
  • Reading SPDR retrieves received data.
  • In master mode, writing SPDR starts a transfer.
  • The register is used for serial data exchange.

SPDR Register Format

SPDR Data Register 
Bit:  15                         0
     +----------------------------+
     |         DATA               |
     +----------------------------+

        Bidirectional data register

The register is described as a 16-bit data port. On the standard LPC2129 legacy SPI interface, each transfer is fixed at 8 bits.

Example: Transmit Data

S0SPDR = 0x55;

This writes the value 0x55 to the SPI0 data register. In master mode, the write initiates an SPI transfer.

Example: Receive Data

unsigned int received_data;

received_data = S0SPDR;

This reads the received data from the SPI0 data register.

SPI is full-duplex capable. During a master transmission, incoming data is also shifted into the receive path. Software should read the received result when required.

9. SPI Clock Counter Register (SPCCR)

SPCCR controls the frequency of the SPI clock generated by the master.

Clock Frequency Formula

SPI Clock Frequency = PCLK / SPCCR

Where:

  • PCLK = Peripheral clock frequency.
  • SPCCR = SPI clock counter value.

SPCCR Requirements in Master Mode

  • SPCCR must be an even number.
  • SPCCR must be greater than or equal to 8.
  • Invalid values can cause unpredictable behavior.

Example 1: SPI Clock Calculation

Given:

PCLK = 15 MHz
SPCCR = 16

SPI Clock = 15 MHz / 16

SPI Clock = 0.9375 MHz

SPI Clock = 937.5 kHz

Example 2: Select SPCCR for Approximately 1 MHz

The required counter value is calculated as: 

SPCCR = PCLK / Desired SPI Clock

SPCCR = 15 MHz / 1 MHz

SPCCR = 15

However, 15 is odd and is not a valid master-mode counter value.

Choose the nearest valid even value of 16: 

Actual SPI Clock = 15 MHz / 16

                 = 937.5 kHz

Example 3: Higher SPI Clock

PCLK = 15 MHz
SPCCR = 8

SPI Clock = 15 MHz / 8

          = 1.875 MHz
The maximum usable SPI clock must also satisfy the electrical and timing specifications of the connected peripheral. In slave mode, the external clock supplied by the master must not exceed PCLK divided by 8.

10. SPI Interrupt Register (SPINT)

SPINT contains the SPI interrupt flag. It is used when SPI interrupt generation is enabled.

SPINT Register Format

SPINT Register 
Bit:  7                  1  0
     +-------------------+--+
     |     Reserved      |IF|
     +-------------------+--+

     IF = SPI Interrupt Flag

Bit 0 – SPI Interrupt Flag

  • 0: SPI interrupt flag is inactive.
  • 1: SPI interrupt flag is active.

The hardware sets this flag when SPIE is enabled and either SPIF or MODF changes from 0 to 1.

Software clears the flag by writing 1 to bit 0. 

S0SPINT = (1U << 0);

The SPI interrupt must also be enabled in the Vectored Interrupt Controller (VIC) for the CPU to process the interrupt.

The SPI interrupt flag is not the same as the transfer-complete flag. SPIF is a status flag; SPINT bit 0 is the interrupt flag.

11. Master and Slave Operating Modes

Master Mode

In master mode, the LPC2129 controls the communication.

  • Generates the SCK clock.
  • Starts a transfer by writing to SPDR.
  • Controls the communication sequence.
  • Reads received data from SPDR.

Slave Mode

In slave mode, the LPC2129 responds to an external SPI master.

  • Receives the clock from the external master.
  • Receives data through MOSI.
  • Transmits data through MISO.
  • Uses SSEL to identify the selected transfer.
When the legacy LPC2129 SPI is configured as a master, the SSEL pin must be configured for its SSEL function and held HIGH to avoid a mode fault. External peripheral chip-select signals can be managed separately using suitable GPIO outputs.

Step-by-Step Explanation

  1. Configure the SPI clock counter.
  2. Configure master/slave mode and clock settings.
  3. Select the peripheral.
  4. Write the data to SPDR.
  5. Wait for the SPIF flag.
  6. Read SPSR.
  7. Read SPDR to retrieve received data and complete the SPIF clearing sequence.
  8. Release the peripheral chip select.

13. Embedded C: Configure SPI0 as Master

The following example configures SPI0 for master operation, MSB-first transfer and SPI Mode 0.

Project clock configuration:

CCLK = 60 MHz
PCLK = 15 MHz

Desired SPI Clock: Approximately 1 MHz
SPCCR = 16

Actual SPI Clock = 937.5 kHz

Program

#include <LPC21xx.h>

#define SPI_SPIF    (1U << 7)
#define SPI_MASTER  (1U << 5)

void SPI0_Init(void)
{
    /*
       SPCCR = 16
       PCLK = 15 MHz
       SPI clock = 937.5 kHz
    */
    S0SPCCR = 16U;

    /*
       Bit 5 = 1 : Master mode
       Bit 6 = 0 : MSB first
       Bit 4 = 0 : CPOL = 0
       Bit 3 = 0 : CPHA = 0
       Bit 7 = 0 : Interrupt disabled
       Bit 2 = 0 : Fixed 8-bit transfer
    */
    S0SPCR = SPI_MASTER;
}

unsigned int SPI0_Transfer(unsigned int data)
{
    unsigned int status;
    unsigned int received;

    /*
       Writing SPDR starts the master transfer.
       Standard LPC2129 legacy SPI uses 8-bit frames.
    */
    S0SPDR = (data & 0xFFU);

    /*
       Wait for transfer completion.
       Production firmware should use a bounded timeout.
    */
    while ((S0SPSR & SPI_SPIF) == 0U)
    {
        /* Wait */
    }

    /*
       Read status first, then access SPDR.
       This sequence clears SPIF.
    */
    status = S0SPSR;

    received = S0SPDR;

    return (received & 0xFFU);
}

int main(void)
{
    unsigned int received_data;

    SPI0_Init();

    received_data = SPI0_Transfer(0x55U);

    while (1)
    {
        /* Inspect received_data in the debugger */
    }
}

Program Explanation

  • S0SPCCR = 16 configures the SPI clock divider.
  • S0SPCR = SPI_MASTER selects master mode with Mode 0 and MSB-first transfer.
  • S0SPDR = data starts the transfer.
  • S0SPSR is checked for the SPIF flag.
  • The status register is read before SPDR.
  • Reading SPDR retrieves the received data.
This is a register-level programming example. It does not configure the SPI pin multiplexing or external peripheral chip select. Those are covered in the next lessons. The wait loop also has no timeout, so production firmware should add one.

14. SPI Clock Mode Configuration Examples

CPHA is SPCR bit 3 and CPOL is SPCR bit 4. The master-mode bit is SPCR bit 5.

Mode CPOL CPHA SPCR Value
Mode 0 0 0 0x20
Mode 1 0 1 0x28
Mode 2 1 0 0x30
Mode 3 1 1 0x38

Example for SPI Mode 3:

S0SPCR = (1U << 5) |
          (1U << 4) |
          (1U << 3);

This selects master mode, CPOL = 1 and CPHA = 1. The peripheral datasheet must specify that Mode 3 is appropriate.

15. SPI Error Conditions

Error Flag Cause
Slave abort ABRT SSEL becomes inactive before transfer completion.
Mode fault MODF SSEL becomes active while operating as master.
Read overrun ROVR Received data is not read before another transfer completes.
Write collision WCOL SPDR is written while a previous transfer is still active or not properly serviced.

Important Programming Practices

  • Do not write new data to SPDR before the previous transfer is serviced.
  • Read received data when required.
  • Check SPSR for transfer completion.
  • Handle mode-fault conditions.
  • Use bounded waits instead of infinite polling loops in production code.
  • Follow the correct status-read and data-register access sequence.

16. SPI0 and SPI1 Interrupt Sources

The SPI interfaces can generate interrupts through the SPI interrupt logic and the Vectored Interrupt Controller.

Peripheral VIC Interrupt Source
SPI0 Source 10
SPI1 Source 11

To use SPI interrupts, enable SPIE in SPCR, handle the interrupt in the appropriate ISR, clear the SPI interrupt flag and configure the corresponding VIC source.

Detailed interrupt-based SPI programming can be added to the practical programming lessons.

17. SPI Legacy Peripheral vs SSP

The LPC2129/01 enhanced version includes an SSP peripheral that shares physical pins with SPI1. The SSP is a separate hardware interface.

Feature Legacy SPI SSP
Data transfer 8-bit on standard LPC2129 legacy part 4 to 16 bits
FIFO No SSP-style FIFO Transmit and receive FIFOs
Register names SPCR, SPSR, SPDR SSPCR0, SSPCR1, SSPDR
Clock configuration SPCCR SSPCPSR and SSPCR0
Interface Legacy SPI SSP supporting SPI, SSI and Microwire formats
Do not use SSP register names such as SSPCR0, SSPDR or SSPSR in a program intended for the legacy SPI peripheral. Check the exact MCU ordering code and the Keil device selection before choosing a peripheral interface.

19. Common Mistakes

  • Confusing SPI registers with SSP registers.
  • Using an odd SPCCR value in master mode.
  • Using an SPCCR value below 8.
  • Forgetting to configure master mode.
  • Using the wrong CPOL or CPHA setting.
  • Writing SPDR before the previous transfer is serviced.
  • Failing to read SPSR before accessing SPDR to clear SPIF.
  • Ignoring the SSEL requirements in master mode.
  • Assuming the standard LPC2129 legacy SPI supports programmable frame lengths.
  • Assuming the simulator proves external device communication.

20. Interview Questions and Answers

Q1. How many SPI interfaces are available in LPC2129?

Two: SPI0 and SPI1.

Q2. What is SPCR?

SPI Control Register. It configures the SPI operating mode, clock phase, polarity and other control options.

Q3. What is SPSR?

SPI Status Register. It contains transfer completion and error flags.

Q4. What is SPDR?

SPI Data Register. It is used to transmit and receive data.

Q5. What is SPCCR?

SPI Clock Counter Register. It controls the master-mode SCK frequency.

Q6. What is SPINT?

SPI Interrupt Register. It contains the SPI interrupt flag.

Q7. What is the SPIF flag?

It indicates completion of an SPI data transfer.

Q8. What is the minimum valid SPCCR value in master mode?

8, and the value must be even.

Q9. What is the formula for SPI clock frequency?

SPI Clock = PCLK / SPCCR.

Q10. What is a write collision?

It occurs when software attempts to write to SPDR while the previous transfer has not been properly completed and serviced.

Q11. What is a mode fault?

It occurs when the SSEL signal becomes active while the SPI peripheral is operating as a master.

Q12. Does the standard LPC2129 legacy SPI support 16-bit transfers?

No. The standard legacy LPC2129 SPI uses fixed 8-bit transfers. Programmable transfer widths are available on enhanced variants.
