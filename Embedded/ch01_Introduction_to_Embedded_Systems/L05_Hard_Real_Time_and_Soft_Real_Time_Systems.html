2. Introduction to Real-Time Systems

A real-time system is a computing system in which the correctness of an operation depends on both the logical result and the time at which the result is produced.

In many embedded applications, the controller must respond to external events within a specified time. Producing the correct result too late may reduce system performance or cause a system failure.

Definition: A real-time system is a system that must perform its required operations within specified timing constraints.

Examples

  • Automotive airbag deployment systems.
  • Industrial motor control systems.
  • Aircraft flight control systems.
  • Medical monitoring and control equipment.
  • Robotics and automation systems.

3. Why Are Timing Constraints Important?

Embedded controllers often interact with physical processes. These processes may change continuously, so the controller must respond within an acceptable time interval.

Consider an automotive braking control application:

  1. Sensors detect wheel-speed information.
  2. The controller processes the sensor data.
  3. The control algorithm calculates the required action.
  4. The system adjusts brake pressure through the appropriate hardware.

If the controller responds too late, the quality or safety of the control operation may be affected.

Real-time performance does not simply mean executing instructions as fast as possible. It means completing required operations within their specified deadlines.

4. Important Real-Time Terminology

4.1 Deadline

A deadline is the time by which a task or operation must be completed.

Example: A controller may be required to process a sensor event within 10 milliseconds.

4.2 Execution Time

Execution time is the amount of processor time required to execute a task.

Example: A signal-processing task may require 2 milliseconds of CPU execution time.

4.3 Response Time

Response time is the elapsed time between the occurrence of an event or task release and the completion of the required response.

It may include waiting time, scheduling delay, interrupt handling and task execution.

4.4 Latency

Latency is the delay between an event and the corresponding system response.

Interrupt latency, for example, is the time between an interrupt request becoming active and the processor beginning the corresponding interrupt service routine.

4.5 Jitter

Jitter is the variation in the timing of an event or operation from one occurrence to another.

Example: A periodic task intended to execute every 10 milliseconds may experience small variations in its actual start times.

4.6 Determinism

Determinism means that system behavior can be predicted under defined operating conditions.

A deterministic real-time system is designed to provide bounded and predictable response times.

5. Types of Real-Time Systems

Based on the consequences of missing a deadline, real-time systems are commonly classified into three categories.

5.1 Hard Real-Time Systems

A hard real-time system must complete critical operations within their specified deadlines. Missing a critical deadline is considered a system failure.

Characteristics:

  • Strict timing requirements.
  • Predictable and bounded response times.
  • Careful worst-case execution-time analysis.
  • High reliability and fault-handling requirements.
  • Often used in safety-critical applications.

Examples:

  • Airbag deployment control.
  • Aircraft flight-control functions.
  • Critical industrial protection systems.
  • Certain medical device control functions.
Key Concept: In a hard real-time system, meeting the deadline is part of the correctness requirement.

5.2 Firm Real-Time Systems

In a firm real-time system, a result produced after its deadline has no practical value. However, occasional missed deadlines may be tolerated by the overall application.

Characteristics:

  • Results are useful only before their deadlines.
  • Late results may be discarded.
  • Occasional deadline misses may be acceptable.
  • System usefulness depends on timely results.

Examples:

  • Some automated visual inspection systems.
  • Time-sensitive data acquisition applications.
  • Some real-time tracking and measurement applications.
A firm real-time system differs from a hard real-time system because an occasional missed deadline does not necessarily mean the entire system has failed.

5.3 Soft Real-Time Systems

A soft real-time system attempts to meet its deadlines, but missing a deadline generally reduces performance or quality rather than causing complete system failure.

Characteristics:

  • Timing is important but occasional delays are tolerated.
  • Late results may still have some value.
  • Performance generally degrades gradually.
  • Average response time and user experience are important.

Examples:

  • Audio and video streaming.
  • Video conferencing.
  • Multimedia playback.
  • Interactive user-interface applications.
Key Concept: A missed deadline in a soft real-time system normally affects quality or responsiveness rather than causing immediate system failure.

7. Real-Time System Timing Example

Consider a controller that must complete a task within a deadline of 10 milliseconds.

Task Completion Time Deadline Result
Task A 6 ms 10 ms On time
Task B 10 ms 10 ms On time
Task C 12 ms 10 ms Late

Task A and Task B complete within their deadlines. Task C misses its deadline.

The consequence of this missed deadline depends on whether the application is hard, firm or soft real-time.

The numbers in this example are illustrative. Actual deadline requirements must be established from the application's functional and safety specifications.

8. Task Scheduling in Real-Time Systems

Real-time embedded systems often execute multiple tasks. A scheduling mechanism determines which task receives processor time and when it executes.

8.1 Priority-Based Scheduling

Tasks are assigned priorities. The scheduler selects tasks according to the scheduling policy and their current states.

In a fixed-priority preemptive system, a higher-priority ready task can interrupt the execution of a lower-priority task.

8.2 Rate-Monotonic Scheduling (RMS)

Rate-Monotonic Scheduling is a fixed-priority scheduling algorithm. Tasks with shorter periods receive higher priorities.

8.3 Earliest Deadline First (EDF)

Earliest Deadline First is a dynamic-priority scheduling algorithm. The ready task with the earliest absolute deadline is selected for execution.

Scheduling Algorithm Priority Type Priority Assignment
Rate-Monotonic Fixed Shorter period means higher priority.
Earliest Deadline First Dynamic Earlier absolute deadline means higher priority.
Detailed task scheduling, RTOS services, synchronization and scheduling algorithms are studied in the dedicated RTOS course.

9. Factors Affecting Real-Time Performance

9.1 Processor Speed

Processor speed influences how quickly instructions can be executed, but processor frequency alone does not guarantee deadline compliance.

9.2 Interrupt Latency

Excessive interrupt latency can delay the handling of important external events.

9.3 Task Execution Time

A task must complete its required computation within the available execution budget.

9.4 Scheduling Overhead

Context switching and scheduler operations consume processor time.

9.5 Resource Contention

Shared resources such as memory, communication buses and peripherals can cause delays.

9.6 Interrupt and Task Priorities

Incorrect priority assignment can delay important work or cause priority inversion when shared resources are involved.

10. Practical Embedded System Example: Motor Protection

Consider an industrial motor protection controller that monitors current and detects an overcurrent condition.

System Operation

  1. A current sensor measures motor current.
  2. The controller reads the sensor output.
  3. The firmware compares the measured value with a configured limit.
  4. If overcurrent is detected, the protection logic initiates a trip action.
  5. The system records or indicates the fault condition.

Real-Time Requirements

  • Sensor acquisition must occur at suitable intervals.
  • Processing must complete within the required time.
  • The protective output must operate within the specified response time.
  • Fault handling must be reliable.
A real protection system requires a complete safety and electrical design. A software example alone does not establish that the protection function meets a required safety deadline.

11. LPC2129 Programming Connection

The LPC2129 includes timers, interrupts and GPIO peripherals that can be used to build time-dependent embedded applications.

The following example uses Timer0 Match Register 0 to create a periodic event. It illustrates how timer hardware can be used instead of relying only on a software delay loop.

Example: Timer0 Match Event

#include <LPC21xx.h> int main(void) { /* Configure P0.5 as GPIO */ PINSEL0 &= ~(3U << 10); /* Configure P0.5 as output */ IO0DIR |= (1U << 5); /* Reset Timer0 */ T0TCR = 0x02; /* Prescaler: 14999 */ T0PR = 14999; /* Match value for 1 second at PCLK = 15 MHz */ T0MR0 = 999; /* Reset timer on MR0 match */ T0MCR = (1U << 1); /* Start Timer0 */ T0TCR = 0x01; while (1) { if (T0IR & 0x01) { /* Clear MR0 interrupt flag */ T0IR = 0x01; /* Toggle P0.5 */ IO0PIN ^= (1U << 5); } } }

Program Explanation

  • T0TCR controls Timer0 operation.
  • T0PR sets the timer prescaler.
  • T0MR0 defines the match value.
  • T0MCR configures the timer action on a match.
  • T0IR indicates and clears the match flag.
  • IO0PIN is used here to toggle the output latch bit.

Timing Calculation

Assume:

  • Peripheral clock (PCLK) = 15 MHz.
  • Prescaler register (PR) = 14999.
  • Match register (MR0) = 999.

Timer increment frequency:

Timer Frequency = PCLK / (PR + 1)

= 15,000,000 / 15,000

= 1,000 Hz

Match interval:

Time = (MR0 + 1) / Timer Frequency

= 1,000 / 1,000

= 1 second

Simulator note: This is a polling-based timer example, not an interrupt service routine. It assumes a 15 MHz peripheral clock and a correctly configured LPC2129 timer. In the Keil simulator, verify the timer register behavior and execution. It does not demonstrate a physical LED. The GPIO pin configuration and external LED circuit must also be correct for hardware operation.

12. Interview Questions and Answers

Q1. What is a real-time system?

A real-time system is a computing system whose correctness depends on producing the required result within specified timing constraints.

Q2. What is a hard real-time system?

A hard real-time system must meet critical deadlines. Missing such a deadline is considered a system failure.

Q3. What is a soft real-time system?

A soft real-time system tolerates occasional delays, although late responses can reduce performance or quality.

Q4. What is a firm real-time system?

In a firm real-time system, a late result has no practical value, but occasional deadline misses may be tolerated.

Q5. What is a deadline?

A deadline is the specified time by which a task must complete its required operation.

Q6. What is interrupt latency?

It is the time between an interrupt request becoming active and the processor beginning the corresponding interrupt service routine.

Q7. What is jitter?

Jitter is the variation in the timing of an event or operation.

Q8. What is determinism?

Determinism is the ability to predict system behavior under defined operating conditions.

Q9. What is Rate-Monotonic Scheduling?

It is a fixed-priority scheduling algorithm in which tasks with shorter periods receive higher priorities.

Q10. What is Earliest Deadline First scheduling?

EDF is a dynamic-priority scheduling algorithm that selects the ready task with the earliest absolute deadline.

13. Multiple-Choice Questions

Q1. What determines correctness in a real-time system?

  1. Only output value
  2. Only processor speed
  3. Output value and timing
  4. Only memory size

Answer: C – Output value and timing.

Q2. Which system treats a missed critical deadline as a failure?

  1. Soft real-time
  2. Hard real-time
  3. Non-real-time
  4. General-purpose system

Answer: B – Hard real-time.

Q3. Which system may still use a result produced after its deadline?

  1. Hard real-time
  2. Soft real-time
  3. Firm real-time
  4. None of these

Answer: B – Soft real-time.

Q4. What is jitter?

  1. Memory capacity
  2. Timing variation
  3. Processor voltage
  4. Clock architecture

Answer: B – Timing variation.

Q5. Which scheduling algorithm assigns higher fixed priority to shorter-period tasks?

  1. EDF
  2. Rate-Monotonic Scheduling
  3. Round Robin
  4. First Come First Served

Answer: B – Rate-Monotonic Scheduling.

Q6. Which algorithm selects the ready task with the earliest absolute deadline?

  1. Rate-Monotonic
  2. Earliest Deadline First
  3. First Come First Served
  4. Simple polling

Answer: B – Earliest Deadline First.

15. Lesson Summary

Real-time systems must produce the required results within specified timing constraints. Their correctness depends on both the output and the time at which it is delivered.

Hard real-time systems cannot miss critical deadlines. Firm real-time systems treat late results as useless, while soft real-time systems tolerate delays with reduced performance or quality.

Deadlines, execution time, response time, latency, jitter and determinism are fundamental concepts in real-time embedded system design.
