Lesson 04: Classification of Embedded Systems

Chapter 01 – Introduction to Embedded Systems

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand why embedded systems are classified.
  • Classify embedded systems based on functionality.
  • Understand small-scale, medium-scale and sophisticated embedded systems.
  • Differentiate standalone and networked embedded systems.
  • Understand mobile and real-time embedded systems.
  • Identify suitable examples of each category.

2. Introduction

Embedded systems are used in many different applications, ranging from simple electronic devices to complex industrial and automotive control systems.

Their hardware architecture, processing capability, software complexity, communication requirements and response-time requirements vary significantly.

To understand these differences, embedded systems are classified into different categories based on their functionality, complexity and application requirements.

Important: There is more than one way to classify embedded systems. A single embedded product may belong to multiple categories depending on the classification criterion.

3. Classification Based on Functionality

Based on the way they operate and interact with their environment, embedded systems can be classified into the following categories:

3.1 Standalone Embedded Systems

A standalone embedded system performs its assigned function independently. It receives input from users or sensors, processes the information and generates the required output.

Examples:

  • Digital calculator.
  • Digital thermometer.
  • Microwave oven controller.
  • Electronic weighing machine.
  • Washing machine controller.

Working Principle

Input → Processing → Output

For example, a digital thermometer reads temperature through a sensor, processes the measurement and displays the result on an LCD.

3.2 Real-Time Embedded Systems

A real-time embedded system must perform its operations within specified timing constraints.

The correctness of its operation depends not only on the output but also on whether the output is produced within the required time.

Examples:

  • Automotive airbag control systems.
  • Industrial automation controllers.
  • Medical monitoring and control equipment.
  • Aircraft control systems.

Real-time systems are commonly divided into:

Category Description Example
Hard Real-Time Missing a critical deadline is considered a system failure. Airbag deployment control.
Firm Real-Time A late result has no practical value, but occasional deadline misses may be tolerated. Some industrial inspection systems.
Soft Real-Time Late results reduce system quality but do not necessarily cause total failure. Audio and video streaming.

3.3 Networked Embedded Systems

A networked embedded system communicates with other devices or computers through a communication network.

It may exchange information using wired or wireless communication technologies.

Examples:

  • Wi-Fi routers.
  • Smart energy meters.
  • Network-enabled security cameras.
  • Industrial monitoring systems.
  • Internet of Things (IoT) devices.

Common communication technologies include:

  • Ethernet.
  • Wi-Fi.
  • Bluetooth.
  • CAN bus.
  • UART-based communication links.
  • Cellular communication.
Network connectivity does not automatically make a system an IoT device. IoT systems generally involve connected devices that collect, exchange or act on data as part of a broader networked application.

3.4 Mobile Embedded Systems

Mobile embedded systems are designed to operate in portable or moving devices. They commonly require compact hardware, efficient power management and suitable communication interfaces.

Examples:

  • Smartwatches.
  • Fitness trackers.
  • Portable medical devices.
  • GPS navigation devices.
  • Handheld barcode scanners.

Important design requirements include:

  • Low power consumption.
  • Small physical size.
  • Battery management.
  • Wireless communication.
  • Efficient processing.

4. Classification Based on Complexity and Performance

Embedded systems can also be classified according to their hardware complexity, processing requirements, memory capacity and software architecture.

4.1 Small-Scale Embedded Systems

Small-scale embedded systems are relatively simple systems designed to perform limited functions.

Typical characteristics:

  • Use low-cost microcontrollers.
  • Have limited RAM and program memory.
  • Perform a small number of tasks.
  • Often use simple firmware.
  • Frequently operate without an operating system.

Examples:

  • Digital alarm clock.
  • Simple electronic calculator.
  • Basic temperature controller.
  • LED blinking controller.

4.2 Medium-Scale Embedded Systems

Medium-scale embedded systems have greater processing and software requirements than small-scale systems.

Typical characteristics:

  • Use 16-bit or 32-bit microcontrollers or processors.
  • Have more memory and peripheral interfaces.
  • Support multiple functional modules.
  • May use an RTOS.
  • Require more structured firmware development.

Examples:

  • Industrial control units.
  • Advanced instrumentation systems.
  • Automotive subsystem controllers.
  • Network-enabled electronic equipment.

4.3 Sophisticated or Complex Embedded Systems

Sophisticated embedded systems are designed for complex applications involving substantial processing, communication, control or safety requirements.

Typical characteristics:

  • Use powerful microprocessors or application processors.
  • May contain multiple processing cores.
  • Use larger memory and external storage.
  • May run embedded Linux or other advanced operating systems.
  • Support complex networking and user interfaces.
  • May integrate multiple subsystems.

Examples:

  • Automotive infotainment systems.
  • Advanced medical imaging equipment.
  • Aircraft control and monitoring systems.
  • Industrial robotics systems.
  • Advanced telecommunications equipment.
Parameter Small-Scale Medium-Scale Sophisticated
Complexity Low Moderate High
Processor Simple microcontroller More capable MCU or processor Advanced processor or multicore platform
Memory Limited Moderate Large relative to the application
Software Simple firmware Structured firmware, possibly RTOS Complex software, RTOS or embedded OS
Example Digital clock Industrial controller Automotive infotainment unit
These complexity categories are descriptive rather than strict processor-bit classifications. A 32-bit processor can be used in a relatively simple product, and a complex system may contain several different processors.

5. Classification Based on Timing Requirements

Another useful classification is based on the timing requirements of the application.

5.1 Non-Real-Time Embedded Systems

These systems do not have strict deadlines for every operation. They still need to operate correctly, but small variations in response time may be acceptable.

Examples:

  • Simple digital clocks.
  • Basic electronic calculators.
  • Some display and measurement devices.

5.2 Real-Time Embedded Systems

These systems must satisfy defined response-time or deadline requirements.

Examples:

  • Engine control systems.
  • Industrial motion controllers.
  • Medical control systems.
  • Aircraft control systems.
A system may be standalone, networked or mobile and also be real-time. These categories are not mutually exclusive.

6. Classification Based on Connectivity

6.1 Non-Networked Embedded Systems

These systems perform their functions without depending on a communication network.

Examples:

  • Basic electronic weighing machine.
  • Simple digital clock.
  • Standalone temperature controller.

6.2 Networked Embedded Systems

These systems communicate with other devices or networks to exchange data, receive commands or provide services.

Examples:

  • Smart home controllers.
  • Industrial Ethernet controllers.
  • Connected surveillance cameras.
  • Remote monitoring equipment.

7. Multiple Classification of One Embedded System

A single embedded product may belong to several categories. Its classification depends on the features being considered.

Example: Smartwatch

  • Functionality: Mobile embedded system.
  • Connectivity: Networked embedded system when connected to other devices.
  • Complexity: May be medium-scale or sophisticated, depending on its design.
  • Timing: Some monitoring and notification functions have timing requirements.

Example: Automotive Engine Control Unit

  • Functionality: Real-time embedded system.
  • Complexity: Typically medium-scale or sophisticated, depending on its architecture.
  • Connectivity: May communicate with other vehicle controllers over CAN or other networks.
  • Application: Automotive control.

Example: Wi-Fi Router

  • Functionality: Networked embedded system.
  • Complexity: Usually sophisticated compared with simple microcontroller applications.
  • Software: Commonly uses embedded Linux or another embedded operating environment.
  • Application: Network communication and routing.

8. Practical Example: Classification of an LPC2129-Based Controller

Consider a temperature-monitoring and fan-control system implemented using the LPC2129 microcontroller.

Its classification may be described as follows:

Classification Basis Category Reason
Functionality Standalone It can monitor temperature and control a fan independently.
Complexity Small-scale or medium-scale Depends on the complete hardware and software design.
Timing Potentially real-time It may need to respond within defined temperature-control deadlines.
Connectivity Non-networked If no communication network is included.
The LPC2129 is a 32-bit ARM7TDMI-S-based microcontroller. The system's classification depends on the complete application design, not just the processor architecture.

9. Interview Questions and Answers

Q1. What are the major classifications of embedded systems?

They can be classified by functionality, complexity, performance, timing requirements and connectivity. Common functional categories include standalone, real-time, networked and mobile embedded systems.

Q2. What is a standalone embedded system?

It is an embedded system that performs its assigned function independently without requiring a network connection.

Q3. What is a networked embedded system?

It is an embedded system that communicates with other devices through wired or wireless networks.

Q4. What is a small-scale embedded system?

It is a relatively simple embedded system with limited hardware resources and a small number of functions.

Q5. What is a sophisticated embedded system?

It is a complex system that may use powerful processors, larger memory, advanced operating systems and multiple communication interfaces.

Q6. Is every networked embedded system a real-time system?

No. Network connectivity and real-time behavior are separate classification criteria.

Q7. Can one embedded system belong to multiple categories?

Yes. For example, a connected automotive controller may be networked, real-time and sophisticated.

Q8. What is the difference between firm and soft real-time systems?

In a firm real-time system, a late result may have no value. In a soft real-time system, late results reduce quality but may still be useful.

10. Multiple-Choice Questions

Q1. Which system performs its assigned function independently?

  1. Networked embedded system
  2. Standalone embedded system
  3. Distributed server
  4. General-purpose workstation

Answer: B – Standalone embedded system.

Q2. Which system communicates through a network?

  1. Networked embedded system
  2. Basic standalone controller
  3. Simple calculator
  4. Non-networked clock

Answer: A – Networked embedded system.

Q3. Which category generally has limited hardware resources?

  1. Sophisticated embedded system
  2. Small-scale embedded system
  3. Large server
  4. Workstation

Answer: B – Small-scale embedded system.

Q4. Which of the following is an example of a mobile embedded system?

  1. Smartwatch
  2. Desktop monitor
  3. Fixed industrial cabinet
  4. Desktop keyboard

Answer: A – Smartwatch.

Q5. Which system is most likely to require strict real-time response?

  1. Digital photo frame
  2. Airbag deployment controller
  3. Basic calculator
  4. Digital wall clock

Answer: B – Airbag deployment controller.

Q6. Can an embedded system be both networked and real-time?

  1. No
  2. Yes
  3. Only if it uses Windows
  4. Only if it has no processor

Answer: B – Yes.

  7. Give five examples of mobile embedded systems.

12. Lesson Summary

Embedded systems can be classified according to their functionality, complexity, performance, timing requirements and connectivity.

Common functional categories include standalone, real-time, networked and mobile embedded systems. Based on complexity, they may be described as small-scale, medium-scale or sophisticated systems.

These classifications help engineers understand application requirements and select suitable processors, memory, communication interfaces and software architectures.
