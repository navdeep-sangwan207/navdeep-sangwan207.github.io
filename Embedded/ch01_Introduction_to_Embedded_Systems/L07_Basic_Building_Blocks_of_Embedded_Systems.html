Lesson 07: Basic Building Blocks of Embedded Systems

Chapter 01 – Introduction to Embedded Systems

1. Learning Objectives

After completing this lesson, you will be able to:

  • Identify the major building blocks of an embedded system.
  • Understand the function of a processor or microcontroller.
  • Explain memory organization and its purpose.
  • Understand input and output interfaces.
  • Differentiate between sensors and actuators.
  • Understand communication interfaces and buses.
  • Explain the role of firmware and power supply circuits.
  • Draw and explain a basic embedded system block diagram.

2. Introduction

An embedded system is made up of several hardware and software components that work together to perform a dedicated function.

Each component has a specific responsibility. The processor executes instructions, memory stores programs and data, input interfaces receive signals, and output interfaces control external devices.

Sensors, actuators, communication interfaces, clock circuits and power supplies support the operation of the complete system.

Example: In an automatic water-level controller, a sensor detects the water level, a microcontroller processes the information, and an output circuit controls the water pump.

4. Processor or Microcontroller

The processor is the main computational unit of an embedded system. It executes instructions and controls the operation of other components.

4.1 Central Processing Unit (CPU)

The CPU generally contains:

  • Arithmetic Logic Unit (ALU): Performs arithmetic and logical operations.
  • Control Unit: Coordinates instruction execution and internal operations.
  • Registers: Store temporary data, addresses and control information.

4.2 Microcontroller

A microcontroller integrates a processor core, memory and peripheral interfaces into a single integrated circuit.

Common microcontroller families include:

  • 8051 microcontrollers.
  • AVR microcontrollers.
  • PIC microcontrollers.
  • ARM-based microcontrollers.
  • ESP32 microcontrollers.

4.3 Microprocessor

A microprocessor primarily contains the CPU. It generally relies on external memory and additional support components, although the exact architecture varies by device.

LPC2129 is an ARM7TDMI-S-based microcontroller that integrates the processor core, memory and multiple peripheral interfaces.

5. Memory Unit

Memory stores the program instructions, configuration information and data required by an embedded system.

5.1 Read Only Memory (ROM)

ROM is non-volatile memory used to store information that must be retained without power.

5.2 Flash Memory

Flash memory is non-volatile memory commonly used to store embedded firmware and other persistent data.

5.3 Random Access Memory (RAM)

RAM is volatile memory used for temporary data during program execution.

5.4 Electrically Erasable Programmable ROM (EEPROM)

EEPROM is non-volatile memory that can be electrically erased and rewritten. It is often used to store configuration settings and calibration data.

Memory Type Volatility Typical Purpose
ROM Non-volatile Permanent program or data storage.
Flash Non-volatile Firmware storage.
RAM Volatile Temporary variables and runtime data.
EEPROM Non-volatile Configuration and persistent settings.

6. Input Unit

The input unit receives information from the external environment or user and provides it to the processor.

Examples of Input Devices

  • Push buttons and switches.
  • Temperature sensors.
  • Pressure sensors.
  • Light sensors.
  • Humidity sensors.
  • Keypads.
  • Proximity sensors.
  • Rotary encoders.

6.1 Digital Inputs

Digital inputs represent discrete logic states, typically interpreted as logic LOW and logic HIGH.

Example: A push button connected to a GPIO pin.

6.2 Analog Inputs

Analog inputs represent continuously varying electrical signals, such as sensor voltages.

An Analog-to-Digital Converter (ADC) converts an analog voltage into a digital value that a processor can read.

7. Output Unit

The output unit provides control signals or processed information to external devices.

Examples of Output Devices

  • LED indicators.
  • LCD displays.
  • Buzzers.
  • Relays.
  • DC motors.
  • Stepper motors.
  • Solenoid valves.

7.1 Digital Outputs

Digital outputs generate logic-level signals for controlling external circuits.

7.2 PWM Outputs

Pulse Width Modulation is used to control the average power delivered to suitable loads.

7.3 Digital-to-Analog Conversion

A Digital-to-Analog Converter (DAC) converts digital data into an analog voltage or current. A DAC may be integrated into a controller or connected externally.

Not every microcontroller includes a DAC. The availability of DAC hardware must be checked in the device datasheet. LPC2129 does not have an integrated DAC peripheral.

8. Sensors

A sensor detects a physical quantity and converts it into an electrical signal that can be processed by an embedded system.

Common Sensor Types

Sensor Measured Quantity Application
Temperature Sensor Temperature Air conditioning and temperature control.
Pressure Sensor Pressure Industrial process monitoring.
LDR Light intensity Automatic street lighting.
Ultrasonic Sensor Distance Obstacle detection.
Humidity Sensor Relative humidity Environmental monitoring.
Accelerometer Acceleration Motion detection.

Sensor Signal Processing

Sensor outputs may require signal conditioning before they can be read by a microcontroller.

Signal conditioning may include:

  • Amplification.
  • Filtering.
  • Voltage scaling.
  • Electrical isolation.
  • Analog-to-digital conversion.

9. Actuators

An actuator converts an electrical control signal into a physical action.

Common Actuators

  • DC motors.
  • Stepper motors.
  • Servo motors.
  • Relays.
  • Solenoid valves.
  • Heaters.
  • Electromagnetic devices.

Example: Motor Control

A microcontroller may generate a PWM signal to control a motor driver. The motor driver supplies the required current to the motor.

A microcontroller GPIO pin generally cannot supply the current required by a motor directly. A suitable driver circuit is normally required.

10. Communication Interfaces

Communication interfaces allow an embedded system to exchange data with sensors, memory devices, displays and other controllers.

10.1 UART

UART is an asynchronous serial communication interface commonly used for communication between embedded devices and computers.

10.2 SPI

SPI is a synchronous serial interface commonly used for high-speed communication with external peripherals.

10.3 I2C

I2C is a two-wire synchronous communication interface that supports communication with multiple addressed devices on a shared bus.

10.4 CAN

CAN is a message-based communication protocol widely used in automotive and industrial systems.

Interface Main Characteristics Common Applications
UART Asynchronous serial communication. Debugging and serial devices.
SPI Synchronous serial communication. Displays and external memory.
I2C Two-wire addressed bus. Sensors and RTC devices.
CAN Robust message-based bus. Automotive and industrial networks.

11. Clock Circuit

A clock circuit provides timing signals that coordinate the operation of a processor and its peripherals.

Clock sources may include:

  • Crystal oscillators.
  • External clock generators.
  • Internal RC oscillators.
  • Phase-Locked Loops (PLLs).

The processor clock frequency affects instruction execution speed and timing calculations.

In the LPC2129 configuration used in this course, the oscillator frequency is 12 MHz and the configured CPU clock is 60 MHz.

12. Reset Circuit

A reset circuit initializes the microcontroller and places it into a known startup state.

Reset may occur because of:

  • Power-on reset.
  • External reset signal.
  • Watchdog reset.
  • Software-generated reset, where supported.

Reset behavior is important for reliable system startup and recovery from certain faults.

13. Power Supply Unit

The power supply provides the voltage and current required by the processor and other electronic components.

Functions

  • Voltage conversion.
  • Voltage regulation.
  • Power filtering.
  • Protection against electrical faults.
  • Power distribution to system components.

Common Power Supply Components

  • Transformer, where required.
  • Rectifier circuit.
  • Filter capacitors.
  • Voltage regulators.
  • Protection components.
A microcontroller may operate at a low DC voltage, while motors and relays may require separate power stages. Supply design must account for voltage levels, current requirements and grounding.

14. Firmware and Embedded Software

Firmware is the software stored in an embedded device that controls its hardware and performs the required application functions.

Main Responsibilities

  • Initialize the microcontroller.
  • Configure peripheral registers.
  • Read input signals and sensor data.
  • Process information.
  • Control output devices.
  • Handle communication.
  • Respond to interrupts and events.

Firmware may be written in C, C++ or assembly language, depending on the platform and project.

15. Interconnection Between Building Blocks

The building blocks work together to complete an application.

Example: Automatic Water-Level Controller

  1. A water-level sensor detects the tank level.
  2. The input interface provides the sensor signal to the controller.
  3. The processor reads and evaluates the signal.
  4. Firmware determines whether the pump should run.
  5. The output interface controls a relay or motor driver.
  6. The pump operates according to the control decision.

16. Practical Example: LPC2129-Based Sensor Monitoring

Consider a temperature-monitoring application using the LPC2129 microcontroller.

System Components

  • LPC2129 microcontroller.
  • Analog temperature sensor.
  • ADC input channel.
  • UART interface for debug output.
  • Optional LED or external control circuit.

Working Principle

  1. The sensor produces a voltage corresponding to temperature.
  2. The ADC converts the analog voltage into a digital result.
  3. The firmware processes the ADC value.
  4. The controller can transmit the result through UART.
  5. An output can be controlled when a configured threshold is reached.
The LPC2129 includes ADC functionality, but it does not have an integrated DAC. The exact sensor interface, ADC channel configuration and voltage range must be checked against the device documentation.

Example Pseudocode

initialize_clock(); initialize_adc(); initialize_uart(); initialize_gpio(); while (1) { adc_value = read_adc(); process_sensor_value(adc_value); if (adc_value > threshold) { set_alarm_output(); } else { clear_alarm_output(); } transmit_uart(adc_value); }

This is illustrative pseudocode. The functions must be implemented for the selected LPC2129 registers and project configuration.

Keil uVision Simulator Considerations

  • Inspect CPU registers and memory during program execution.
  • Verify GPIO register changes where the simulator supports them.
  • Check program flow and ADC register handling.
  • Use UART debug output when supported by the project setup.
  • Do not assume that physical sensor voltages or external actuator behavior are reproduced by the simulator.

17. Interview Questions and Answers

Q1. What are the basic building blocks of an embedded system?

Processor, memory, input/output interfaces, sensors, actuators, communication interfaces, clock, reset, power supply and firmware.

Q2. What is the function of a microcontroller?

It executes firmware, processes input data and controls connected peripherals and external devices.

Q3. What is the difference between RAM and Flash?

RAM is volatile and stores temporary runtime data. Flash is non-volatile and commonly stores firmware.

Q4. What is the purpose of an ADC?

An ADC converts an analog input signal into a digital representation.

Q5. What is the difference between a sensor and an actuator?

A sensor detects a physical quantity and produces a signal. An actuator converts a control signal into a physical action.

Q6. Why is a motor driver required?

A motor driver provides the current and switching capability required to operate a motor. A microcontroller output pin generally cannot drive a motor directly.

Q7. What is the purpose of a clock circuit?

It provides timing signals that coordinate processor and peripheral operation.

Q8. What is firmware?

Firmware is software stored in an embedded device that controls its hardware and performs its dedicated functions.

Q9. What is the function of a reset circuit?

It initializes the system and places the microcontroller into a known startup state.

Q10. What is the role of a communication interface?

It allows the embedded system to exchange information with other devices and peripherals.

18. Multiple-Choice Questions

Q1. Which component executes program instructions?

  1. Processor
  2. Sensor
  3. Relay
  4. Power supply

Answer: A – Processor.

Q2. Which memory is generally used to store firmware?

  1. Flash
  2. RAM only
  3. Cache only
  4. Register only

Answer: A – Flash.

Q3. Which component converts an analog signal into digital data?

  1. ADC
  2. DAC
  3. UART
  4. Relay

Answer: A – ADC.

Q4. Which component converts a control signal into physical movement?

  1. Actuator
  2. Memory
  3. Clock
  4. Register

Answer: A – Actuator.

Q5. Which interface uses two main signal lines, SDA and SCL?

  1. I2C
  2. UART
  3. SPI
  4. CAN

Answer: A – I2C.

Q6. Which component provides timing signals?

  1. Clock circuit
  2. Sensor
  3. Relay
  4. Actuator

Answer: A – Clock circuit.

Q7. Which component provides regulated electrical power?

  1. Power supply
  2. Sensor
  3. UART
  4. RAM

Answer: A – Power supply.

Q8. Which of the following is an example of an actuator?

  1. DC motor
  2. Temperature sensor
  3. LDR
  4. Pressure sensor

Answer: A – DC motor.

20. Lesson Summary

An embedded system consists of hardware and software building blocks that work together to perform a dedicated function.

The processor executes instructions, memory stores programs and data, input interfaces receive information, and output interfaces control external devices.

Sensors, actuators, communication interfaces, clock circuits, reset circuits, power supplies and firmware complete the system architecture.
