2. Introduction to Real-Time Clock (RTC)

A Real-Time Clock (RTC) is a hardware peripheral used to maintain the current time and date in an embedded system. It tracks seconds, minutes, hours, days, months and years.

An RTC is useful when an embedded application needs to know the actual time or maintain a calendar independently of the application's main execution sequence.

Typical RTC information includes:

  • Seconds
  • Minutes
  • Hours
  • Day of the month
  • Day of the week
  • Day of the year
  • Month
  • Year
Important concept: An RTC maintains calendar time. It is different from a timer that is commonly configured to generate short delays, periodic interrupts or event-counting operations.

3. Why Do Embedded Systems Need an RTC?

Many embedded applications must perform operations according to a particular time or date. A processor executing normal application code does not automatically know the calendar date. The RTC provides this timekeeping functionality.

Common applications

Application Purpose of RTC
Digital clock Maintains and displays current time.
Data logger Adds date and time information to recorded data.
Industrial automation Schedules operations and records machine events.
Security system Records access events with timestamps.
Energy meter Supports time-based energy measurement and tariff scheduling.
Embedded monitoring Records the time of faults and system events.
Scheduled controller Triggers operations at configured times.

4. RTC Versus General-Purpose Timer

The LPC2129 provides general-purpose Timer0 and Timer1 peripherals as well as an RTC peripheral. Although both use clock pulses and counters, their purposes are different.

Parameter General-Purpose Timer Real-Time Clock
Main purpose Measure intervals and generate timing events. Maintain calendar time and date.
Typical measurement Microseconds, milliseconds and event counts. Seconds, minutes, hours and calendar dates.
Typical registers TC, PR, PC, MR and MCR. Time counters, alarm registers and RTC control registers.
Common application Delay generation and periodic control. Clock display and event timestamping.
Alarm functionality Implemented through timer match operations. Dedicated RTC alarm registers and comparison logic.
Practical example: A timer can generate an interrupt every 10 milliseconds to sample a sensor. An RTC can identify that the sample was recorded on a particular date at 10:30:15 AM.

5. LPC2129 On-Chip RTC Architecture

The LPC2129 includes an integrated RTC peripheral. It contains the clock-generation and timekeeping logic required to maintain calendar information.

The major functional blocks are:

  1. Reference clock and prescaler
  2. RTC clock generator
  3. Time counter group
  4. Alarm register group
  5. Comparator logic
  6. Counter increment interrupt logic

6. Functional Blocks Explained

6.1 Reference Clock and Prescaler

The RTC requires a suitable reference clock for accurate timekeeping. In the LPC2129 RTC architecture, the reference clock divider uses the peripheral clock (PCLK) to generate the required 32.768 kHz reference clock.

The prescaler contains integer and fractional components. These allow different supported PCLK frequencies to be converted into the RTC reference frequency.

The configuration registers PREINT and PREFRAC are used for the integer and fractional prescaler values.

Key concept: 32,768 reference clock ticks correspond to one second. The RTC clock-generation circuitry uses this reference to update the time counters.

6.2 RTC Clock Generator

The clock generator receives the reference clock and produces the timing signals required by the RTC timekeeping logic. It coordinates the progression of the time counters.

6.3 Time Counter Group

The time counter group maintains the current time and calendar information. It includes counters for:

  • Seconds
  • Minutes
  • Hours
  • Day of month
  • Day of week
  • Day of year
  • Month
  • Year

When a counter reaches its valid limit, the RTC updates the next higher time unit. For example, when seconds roll over from 59 to 0, the minute counter is incremented.

6.4 Alarm Register Group

The RTC contains alarm registers that store a target time and date. The alarm comparison logic checks the current time against the configured alarm values.

The Alarm Mask Register (AMR) controls which alarm fields participate in the comparison. This allows applications to configure different alarm conditions.

6.5 Comparator Logic

The comparator logic compares the current time counter values with the programmed alarm values. When the required comparison condition is satisfied, the RTC can generate an alarm interrupt request.

6.6 Interrupt Generation Logic

The RTC can generate interrupt requests for configured counter-increment events and alarm events. These requests can be handled through the LPC2129 Vectored Interrupt Controller (VIC).

The processor can execute an interrupt service routine instead of continuously polling the RTC status.

7. Understanding the 32.768 kHz Reference Frequency

A frequency of 32.768 kHz is commonly used in RTC designs because it is a power of two:

32,768 = 215

Therefore, a suitable divider can reduce this frequency to one pulse per second. 

Reference frequency = 32,768 Hz

Number of reference ticks per second = 32,768

Output frequency = 32,768 / 32,768

Output frequency = 1 Hz

This one-second timing reference is used by the RTC timekeeping logic to advance the calendar counters.

Important distinction: The 32.768 kHz reference frequency is not the same as the CPU clock (CCLK) or peripheral clock (PCLK). Do not use the timer prescaler formula for Timer0 or Timer1 as a substitute for the RTC prescaler calculation.

8. RTC Timekeeping Sequence

A simplified timekeeping sequence is:

  1. The reference clock is supplied to the RTC clock-generation logic.
  2. The prescaler produces the required reference frequency.
  3. The RTC clock generator produces the timing event used by the counters.
  4. The seconds counter advances.
  5. When seconds reach their limit, the minutes counter advances.
  6. Minutes and hours advance according to their limits.
  7. Calendar counters update when the date changes.
  8. Configured counter or alarm events can generate interrupts.

9. RTC and the ARM7 Processor

The RTC operates as a hardware peripheral connected to the LPC2129 internal peripheral bus. The ARM7TDMI-S processor communicates with it through memory-mapped registers.

The software can perform the following operations:

  • Enable or disable the RTC clock.
  • Initialize the RTC time and calendar.
  • Read current time and date values.
  • Configure alarm values.
  • Enable counter-increment interrupts.
  • Read and clear RTC interrupt status flags.
Placement concept: The RTC does not require the CPU to increment the seconds counter manually in a continuously running software loop. The peripheral's hardware timekeeping logic performs the counter updates.

10. RTC Versus External RTC Module

An embedded system may use an on-chip RTC or an external RTC integrated circuit. These are different implementation approaches.

On-Chip RTC External RTC Module
Integrated inside the microcontroller. Separate integrated circuit.
Accessed through internal memory-mapped registers. Usually accessed through I2C or SPI.
Does not require an external RTC communication bus. Requires communication interface configuration.
Uses the clocking and power arrangement supported by the MCU. May provide its own oscillator and backup-battery arrangement.

Examples of external RTC devices include DS1307 and DS3231. They are useful as optional hardware extensions, but they are not required for learning the LPC2129 on-chip RTC.

13. Common RTC Interview Questions

Q1. What is an RTC?

An RTC is a hardware peripheral that maintains current time and calendar information such as seconds, minutes, hours, date, month and year.

Q2. What is the main difference between an RTC and a timer?

A timer is generally used to measure time intervals, generate delays or count events. An RTC maintains calendar time and date.

Q3. Why is 32.768 kHz commonly used in RTC circuits?

It is equal to 215, so a divider can generate a one-second timing reference using a convenient power-of-two division.

Q4. What is the purpose of the RTC prescaler?

It converts the available peripheral clock frequency into the required RTC reference clock frequency.

Q5. What is the purpose of the RTC alarm registers?

They store the target time and date values used by the RTC alarm comparison logic.

Q6. What is the role of the VIC in RTC operation?

The Vectored Interrupt Controller manages interrupt requests from peripherals, including RTC interrupt requests, and helps the processor dispatch the appropriate interrupt service routine.

Q7. Does the CPU need to increment the RTC seconds counter manually?

No. The RTC hardware performs the time counter updates. Software configures and reads the peripheral.

Q8. Can an on-chip RTC and an external RTC be used in the same system?

Yes. A system may use both, for example, to compare time sources or provide an independent external timekeeping device.
