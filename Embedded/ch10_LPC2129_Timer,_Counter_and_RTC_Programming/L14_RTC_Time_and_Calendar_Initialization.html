2. Introduction to RTC Calendar Initialization

The Real-Time Clock (RTC) maintains time and calendar information using dedicated hardware counters. Unlike a software delay loop, the RTC uses its clock-generation and counter circuitry to maintain seconds, minutes, hours and calendar values.

Before relying on the RTC, the application must initialize its time and calendar counters with valid values. The RTC does not automatically determine the correct date from the year, month and day values supplied by the application.

PCLK → RTC Prescaler → Clock Tick Counter

Seconds → Minutes → Hours → Day of Month
Day of Week | Day of Year | Month | Year
Important: The RTC time counters are separate hardware registers. Software must initialize related calendar values consistently. For example, the application must provide a correct day-of-week and day-of-year value when setting a date.

3. LPC2129 RTC Time Counter Registers

The LPC2129 provides eight programmable time and calendar counters. Their addresses are located in the RTC time counter register group.

Register Address Size Valid Range Purpose
SEC 0xE0024020 6 bits 0–59 Seconds
MIN 0xE0024024 6 bits 0–59 Minutes
HOUR 0xE0024028 5 bits 0–23 Hours, 24-hour format
DOM 0xE002402C 5 bits 1–28/29/30/31 Day of month
DOW 0xE0024030 3 bits 0–6 Day of week
DOY 0xE0024034 9 bits 1–365/366 Day of year
MONTH 0xE0024038 4 bits 1–12 Month
YEAR 0xE002403C 12 bits 0–4095 Year
Register address distinction: CTC is located at 0xE0024004. It is the Clock Tick Counter register, not the minutes register. The MIN counter is located at 0xE0024024.

4. Understanding the Calendar Counters

4.1 Seconds, Minutes and Hours

  • SEC: Stores seconds from 0 to 59.
  • MIN: Stores minutes from 0 to 59.
  • HOUR: Stores hours from 0 to 23.

The LPC2129 RTC uses a 24-hour format. Therefore, 2:30 PM is represented as 14 hours, 30 minutes and 0 seconds.

4.2 Day of Month (DOM)

DOM represents the date within the current month. Its valid range depends on the month and leap-year status.

4.3 Day of Week (DOW)

DOW stores the weekday as a number from 0 to 6. For the convention used in this course, the mapping is:

DOW valueWeekday
0Sunday
1Monday

3Wednesday
4Thursday

6Saturday
The weekday numbering above is an application convention. The RTC counter stores a numeric value; it does not calculate the correct weekday from the date during initialization.

4.4 Day of Year (DOY)

DOY represents the sequential day number within a year.

  • 1 January = DOY 1
  • 31 January = DOY 31
  • 1 February = DOY 32
  • 31 December = DOY 365 in a normal year
  • 31 December = DOY 366 in a leap year

4.5 Month and Year

  • MONTH: Stores values from 1 to 12.
  • YEAR: A 12-bit counter with a hardware range of 0 to 4095.

Although the YEAR register has a broad numeric range, the RTC's documented leap-year algorithm has a specific limitation discussed in Section 6.

5. RTC Initialization Registers

5.1 Clock Control Register (CCR)

The Clock Control Register controls the RTC clock circuitry.

BitNameFunction
0CLKENEnables or disables the RTC time counters.
1CTCRSTResets the Clock Tick Counter circuitry while asserted.
Other bitsReserved / testKeep normal-operation test bits at zero.

Important CCR values:

  • CCR = 0x00 — time counters disabled.
  • CCR = 0x02 — clock tick counter reset asserted.
  • CCR = 0x00 — clock tick counter reset released; counters remain disabled.
  • CCR = 0x01 — RTC time counters enabled.

5.2 Prescaler Registers

RegisterAddressValue for PCLK = 15 MHz
PREINT0xE0024080456 (0x01C8)
PREFRAC0xE002408425024 (0x61C0)

These values configure the RTC reference divider for the established 15 MHz peripheral clock. The derivation and fractional correction are covered in Lesson 13.

6. Leap-Year Calculation

A leap year normally contains 366 days. February contains 29 days instead of 28.

The conventional Gregorian calendar rule is:

  • A year divisible by 400 is a leap year.
  • A year divisible by 100 but not by 400 is not a leap year.
  • Otherwise, a year divisible by 4 is a leap year.
int IsLeapYear(unsigned int year)
{
    if ((year % 400U) == 0U)
        return 1;

    if ((year % 100U) == 0U)
        return 0;

    if ((year % 4U) == 0U)
        return 1;

    return 0;
}
LPC2129 hardware limitation: The RTC hardware uses a simpler leap-year check based on whether the two least significant bits of the year counter are zero. It therefore treats every year divisible by 4 as a leap year. This works for the documented period 1901–2099 but incorrectly treats 2100 as a leap year. The application should account for this limitation when supporting dates beyond 2099.

7. Calculating Day of Year

The DOY value is calculated by adding the number of days in all preceding months to the current day of the month.

Example: 1 March 2024

  • January = 31 days
  • February = 29 days because 2024 is a leap year
  • Current date = 1 March

DOY = 31 + 29 + 1 = 61

unsigned int CalculateDayOfYear(
    unsigned int day,
    unsigned int month,
    unsigned int year)
{
    unsigned int days[12] =
    {
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31
    };

    unsigned int i;
    unsigned int total = day;

    if (IsLeapYear(year))
        days[1] = 29;

    for (i = 0; i < (month - 1U); i++)
    {
        total += days[i];
    }

    return total;
}

8. Date and Time Validation

Before writing values into the RTC registers, the application should verify that the supplied date and time are valid.

Examples of invalid values include:

  • Seconds = 60
  • Minutes = 75
  • Hours = 25
  • Month = 13
  • Day = 31 in April
  • 29 February in a non-leap year
  • DOW = 7

Complete Date Validation Function

int ValidateDateTime(
    unsigned int second,
    unsigned int minute,
    unsigned int hour,
    unsigned int day,
    unsigned int month,
    unsigned int year,
    unsigned int dow)
{
    unsigned int monthDays[12] =
    {
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31
    };

    if (year < 1901U || year > 2099U)
        return 0;

    if (month < 1U || month > 12U)
        return 0;

    if (hour > 23U)
        return 0;

    if (minute > 59U)
        return 0;

    if (second > 59U)
        return 0;

    if (dow > 6U)
        return 0;

    if (IsLeapYear(year))
        monthDays[1] = 29;

    if (day < 1U || day > monthDays[month - 1U])
        return 0;

    return 1;
}
The validation function deliberately restricts this example to 1901–2099 so its software leap-year rule agrees with the documented RTC hardware behavior. The RTC YEAR register itself supports 0–4095; that register range should not be confused with the calendar range safely supported by this example.

9. RTC Initialization Sequence

A reliable RTC initialization routine should follow a controlled sequence:

  1. Disable the RTC time counters by clearing CLKEN.
  2. Assert CTCRST to reset the clock tick counter circuitry.
  3. Release CTCRST while keeping CLKEN disabled.
  4. Load the PREINT and PREFRAC prescaler values.
  5. Validate the date and time supplied by the application.
  6. Write the eight time and calendar counter registers.
  7. Enable the RTC time counters by setting CLKEN.

10. Complete Embedded C Program: RTC Initialization

The following program initializes the LPC2129 RTC with a valid date and time. It uses direct memory-mapped register access so that the RTC register addresses and initialization sequence remain visible during debugging.

Clock configuration used:

  • FOSC = 12 MHz
  • CCLK = 60 MHz
  • PCLK = 15 MHz
  • VPBDIV = 4 (divide-by-4 configuration)
  • PREINT = 456
  • PREFRAC = 25024
/*
 * Project: LPC2129 RTC Initialization
 * Controller: LPC2129
 * IDE: Keil uVision
 * Clock: PCLK = 15 MHz
 */

#include <LPC21xx.h>

/* RTC register addresses */

#define RTC_CCR_ADDR       0xE0024008UL

#define RTC_SEC_ADDR       0xE0024020UL
#define RTC_MIN_ADDR       0xE0024024UL
#define RTC_HOUR_ADDR      0xE0024028UL
#define RTC_DOM_ADDR       0xE002402CUL
#define RTC_DOW_ADDR       0xE0024030UL
#define RTC_DOY_ADDR       0xE0024034UL
#define RTC_MONTH_ADDR     0xE0024038UL
#define RTC_YEAR_ADDR      0xE002403CUL

#define RTC_PREINT_ADDR    0xE0024080UL
#define RTC_PREFRAC_ADDR   0xE0024084UL

/* Memory-mapped register access */

#define RTC_REG(address) \
    (*(volatile unsigned long *)(address))

/* CCR bit definitions */

#define RTC_CLKEN          (1UL << 0)
#define RTC_CTCRST         (1UL << 1)

/* PCLK = 15 MHz prescaler values */

#define RTC_PREINT_VALUE   456UL
#define RTC_PREFRAC_VALUE  25024UL

/* Debug variables */

volatile unsigned int rtc_status;
volatile unsigned int rtc_day_of_year;

/* Leap-year function */

int IsLeapYear(unsigned int year)
{
    return ((year % 4U) == 0U);
}

/* Calculate day of year */

unsigned int CalculateDayOfYear(
    unsigned int day,
    unsigned int month,
    unsigned int year)
{
    unsigned int days[12] =
    {
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31
    };

    unsigned int i;
    unsigned int total;

    if (IsLeapYear(year))
    {
        days[1] = 29;
    }

    total = day;

    for (i = 0; i < (month - 1U); i++)
    {
        total += days[i];
    }

    return total;
}

/* Validate the date and time */

int ValidateDateTime(
    unsigned int second,
    unsigned int minute,
    unsigned int hour,
    unsigned int day,
    unsigned int month,
    unsigned int year,
    unsigned int dow)
{
    unsigned int monthDays[12] =
    {
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31
    };

    if (year < 1901U || year > 2099U)
        return 0;

    if (month < 1U || month > 12U)
        return 0;

    if (second > 59U)
        return 0;

    if (minute > 59U)
        return 0;

    if (hour > 23U)
        return 0;

    if (dow > 6U)
        return 0;

    if (IsLeapYear(year))
    {
        monthDays[1] = 29;
    }

    if (day < 1U || day > monthDays[month - 1U])
        return 0;

    return 1;
}

/* Initialize RTC date and time */

int RTC_SetDateTime(
    unsigned int second,
    unsigned int minute,
    unsigned int hour,
    unsigned int day,
    unsigned int month,
    unsigned int year,
    unsigned int dow)
{
    unsigned int doy;

    /* Validate before modifying RTC registers */

    if (!ValidateDateTime(
        second, minute, hour,
        day, month, year, dow))
    {
        return 0;
    }

    /* Calculate day of year */

    doy = CalculateDayOfYear(day, month, year);

    /* Disable RTC time counters */

    RTC_REG(RTC_CCR_ADDR) = 0x00UL;

    /* Reset the clock tick counter */

    RTC_REG(RTC_CCR_ADDR) = RTC_CTCRST;

    /* Release reset; keep RTC counters disabled */

    RTC_REG(RTC_CCR_ADDR) = 0x00UL;

    /* Configure RTC prescaler */

    RTC_REG(RTC_PREINT_ADDR) = RTC_PREINT_VALUE;
    RTC_REG(RTC_PREFRAC_ADDR) = RTC_PREFRAC_VALUE;

    /* Initialize time counters */

    RTC_REG(RTC_SEC_ADDR) = second;
    RTC_REG(RTC_MIN_ADDR) = minute;
    RTC_REG(RTC_HOUR_ADDR) = hour;

    /* Initialize calendar counters */

    RTC_REG(RTC_DOM_ADDR) = day;
    RTC_REG(RTC_DOW_ADDR) = dow;
    RTC_REG(RTC_DOY_ADDR) = doy;
    RTC_REG(RTC_MONTH_ADDR) = month;
    RTC_REG(RTC_YEAR_ADDR) = year;

    /* Enable RTC time counters */

    RTC_REG(RTC_CCR_ADDR) = RTC_CLKEN;

    rtc_day_of_year = doy;

    return 1;
}

/* Main function */

int main(void)
{
    /*
     * Example:
     * 28 February 2024
     * 23:59:50
     * Wednesday = 3
     *
     * 2024 is a leap year.
     * Day of year = 59.
     */

    rtc_status = RTC_SetDateTime(
        50,     /* Seconds */
        59,     /* Minutes */
        23,     /* Hours */
        28,     /* Day */
        2,      /* Month */
        2024,   /* Year */
        3       /* Wednesday */
    );

    while (1)
    {
        /*
         * Inspect RTC registers and rtc_status
         * using the Keil debugger.
         */
    }
}

12. Invalid Date Test

Modify the function call in main() to test an invalid date: 

rtc_status = RTC_SetDateTime(
    0, 0, 12,
    31, 4, 2024,
    3
);

This attempts to set 31 April 2024. April has only 30 days, so the validation function rejects the date.

Expected result:

  • rtc_status = 0
  • The RTC initialization function returns without writing new time values.

14. Keil µVision Simulator Practical

This practical is designed for the LPC2129 simulation environment. No physical RTC hardware or external RTC module is required.

Step 1: Create the project

  1. Open Keil µVision.
  2. Create or open an LPC2129 project.
  3. Select the LPC2129 device.
  4. Add the C source file containing the RTC program.
  5. Build the project and resolve any compiler errors.

Step 2: Configure the debugger

  1. Open Options for Target.
  2. Select the Debug tab.
  3. Choose the simulator option.
  4. Start the debugger.
  5. Run the program until it reaches the infinite loop.

Step 3: Inspect the registers

Use the debugger's Memory window to inspect the RTC memory-mapped register addresses:

  • 0xE0024008 — CCR
  • 0xE0024020 — SEC
  • 0xE0024024 — MIN
  • 0xE0024028 — HOUR
  • 0xE002402C — DOM
  • 0xE0024030 — DOW
  • 0xE0024034 — DOY
  • 0xE0024038 — MONTH
  • 0xE002403C — YEAR
  • 0xE0024080 — PREINT
  • 0xE0024084 — PREFRAC
Simulator limitation: A successful register write verifies the initialization code and memory-mapped values. It does not, by itself, prove that the simulator accurately models real-time RTC ticking. Confirm the simulator's RTC peripheral support before treating elapsed-time behavior as verified. If the RTC peripheral is not modeled, complete the register initialization and validation tests and document the limitation.

17. Placement-Oriented Interview Questions

Q1. What is the purpose of the RTC in an embedded controller?

The RTC maintains time and calendar information using dedicated hardware counters, reducing the need for continuous software timing.

Q2. What is the difference between DOM and DOY?

DOM represents the date within a month, whereas DOY represents the sequential day number within the year.

Q3. What is the valid range of the LPC2129 HOUR register?

0 to 23, because the RTC uses a 24-hour format.

Q4. Does the RTC automatically calculate the weekday?

No. Software must initialize DOW consistently with the selected date.

Q5. Why should date validation be performed before writing RTC registers?

Invalid calendar values can produce incorrect date progression. Validation prevents impossible dates from being initialized.

Q6. What is the purpose of CLKEN in CCR?

CLKEN enables the RTC time counters. Clearing it disables the counters so that software can initialize them.

Q7. What is the purpose of CTCRST?

CTCRST resets the clock tick counter circuitry. The reset remains asserted until software clears the bit.

Q8. Why is DOY initialized separately from DOM and MONTH?

The RTC maintains DOY as an independent counter. It is not calculated automatically from the date registers during initialization.

Q9. What is the leap-year limitation of the LPC2129 RTC?

Its hardware algorithm treats every year divisible by four as a leap year. It is documented as accurate from 1901 through 2099 but fails for 2100.

Q10. What is the difference between CTC and SEC?

CTC is the clock tick counter register in the RTC control register group. SEC is the seconds time counter in the time counter group.

20. Lesson Summary

  • The LPC2129 RTC contains eight time and calendar counters.
  • Time counters must be initialized with valid values.
  • DOM, DOW and DOY are separate counters.
  • Software should validate dates before writing RTC registers.
  • The RTC hardware has a documented leap-year limitation.
  • CCR controls RTC counter enable and clock tick counter reset.
  • The prescaler must match the peripheral clock configuration.
  • Keil simulation can be used to inspect register initialization, subject to peripheral-model support.
