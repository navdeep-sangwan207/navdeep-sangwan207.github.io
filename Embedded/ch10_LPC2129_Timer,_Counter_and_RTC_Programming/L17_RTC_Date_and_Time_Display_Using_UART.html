RTC Date and Time Display Using UART

Chapter 10: LPC2129 Timers and Counters | Lesson 17

Read the LPC2129 Real-Time Clock registers and transmit formatted date and time information through UART0.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand how RTC time and calendar registers are read.
  • Identify the LPC2129 RTC counter register addresses.
  • Read seconds, minutes, hours and calendar information.
  • Understand why a consistent RTC snapshot is important.
  • Configure UART0 for serial communication at 9600 baud.
  • Transmit formatted date and time information.
  • Debug RTC and UART communication using Keil µVision.

2. Introduction

The Real-Time Clock (RTC) maintains time and calendar information independently of the CPU's normal program execution. The microcontroller can read this information whenever an application requires the current date or time.

UART is a serial communication peripheral that allows the microcontroller to transmit information to a computer or another serial device.

In this lesson, the LPC2129 reads its RTC registers and sends the current date and time through UART0. A serial terminal can display the transmitted information.

Application: RTC and UART integration is useful in digital clocks, data loggers, event monitoring systems, industrial controllers and embedded diagnostic applications.

The data flow is:

  1. The RTC maintains the current time and date.
  2. The CPU reads the RTC counter registers.
  3. The program checks that the seconds value has not changed during the read.
  4. The date and time values are converted into readable characters.
  5. UART0 transmits the characters serially.
  6. The serial terminal displays the result.

6. Why a Consistent RTC Snapshot Is Required

RTC counters are updated automatically. A problem can occur if the CPU reads different registers while the RTC changes from one second to the next.

For example, consider the following time:

Before rollover:  10:25:59
After rollover:   10:26:00

If the CPU reads the seconds register before the rollover and the minutes register after the rollover, the collected values may not represent one valid instant.

One practical method is to read SEC before and after reading the other counters. If the two seconds values differ, repeat the operation. 

Read SEC into sec_before

Read MIN
Read HOUR
Read DOM
Read DOW
Read DOY
Read MONTH
Read YEAR

Read SEC into sec_after

If sec_before != sec_after:
    Repeat the complete read
Else:
    Accept the snapshot
This method detects ordinary second rollovers during the snapshot operation. It is suitable for a short register-read routine; it is not a substitute for a hardware-latched snapshot mechanism in systems with stricter timing requirements.

7. UART0 Configuration

UART0 is used to transmit the RTC information to the serial terminal.

7.1 UART0 Pin Configuration

UART0 uses the alternate functions of P0.0 and P0.1. PINSEL0 must select TXD0 and RXD0. 

PINSEL0 = (PINSEL0 & ~0x0F) | 0x05;

7.2 Baud Rate Calculation

For the selected UART configuration:

PCLK = 15 MHz

The basic baud-rate equation is:

Baud Rate = PCLK / (16 x Divisor)

Divisor = PCLK / (16 x Baud Rate)

Divisor = 15000000 / (16 x 9600)

Divisor = 97.65625

Selected integer divisor = 98

Actual baud rate:

Actual Baud Rate = 15000000 / (16 x 98)

                 = 9566.33 bps

The error is approximately 0.35%, which is generally acceptable for this UART configuration.

7.3 UART0 Register Configuration

RegisterPurpose
U0LCRLine Control Register

U0DLMDivisor Latch High

U0LCR is first configured with DLAB = 1 to access the divisor latch registers. After loading the divisor, DLAB is cleared and the UART is configured for 8-N-1.

8. Complete Embedded C Program

Program: Read LPC2129 RTC date and time and display it through UART0.

The program assumes that the RTC has already been initialized and is running, as covered in the previous RTC lessons. The CPU and peripheral clocks must also be configured for CCLK = 60 MHz and PCLK = 15 MHz. 

#include <LPC21xx.h>

/* RTC register addresses */
#define RTC_CCR     (*(volatile unsigned long *)0xE0024008)
#define RTC_SEC     (*(volatile unsigned long *)0xE0024020)
#define RTC_MIN     (*(volatile unsigned long *)0xE0024024)
#define RTC_HOUR    (*(volatile unsigned long *)0xE0024028)
#define RTC_DOM     (*(volatile unsigned long *)0xE002402C)
#define RTC_DOW     (*(volatile unsigned long *)0xE0024030)
#define RTC_DOY     (*(volatile unsigned long *)0xE0024034)
#define RTC_MONTH   (*(volatile unsigned long *)0xE0024038)
#define RTC_YEAR    (*(volatile unsigned long *)0xE002403C)

/* UART0 register addresses */
#define U0THR_REG   (*(volatile unsigned long *)0xE000C000)
#define U0DLL_REG   (*(volatile unsigned long *)0xE000C000)
#define U0DLM_REG   (*(volatile unsigned long *)0xE000C004)
#define U0FDR_REG   (*(volatile unsigned long *)0xE000C028)
#define U0LCR_REG   (*(volatile unsigned long *)0xE000C00C)
#define U0LSR_REG   (*(volatile unsigned long *)0xE000C014)

/* PINSEL0 address */
#define PINSEL0_REG (*(volatile unsigned long *)0xE002C000)

/* RTC data structure */
typedef struct
{
    unsigned int sec;
    unsigned int min;
    unsigned int hour;
    unsigned int dom;
    unsigned int dow;
    unsigned int doy;
    unsigned int month;
    unsigned int year;

} RTC_TIME;

/* Function declarations */
void UART0_Init(void);
void UART0_SendChar(char ch);
void UART0_SendString(char *str);
void UART0_Send2Digits(unsigned int value);
void UART0_Send4Digits(unsigned int value);
void UART0_SendNumber(unsigned int value);
void UART0_PrintDay(unsigned int dow);

int RTC_ReadSnapshot(RTC_TIME *time);

/* UART0 initialization */
void UART0_Init(void)
{
    /* Configure P0.0 as TXD0 and P0.1 as RXD0 */
    PINSEL0_REG = (PINSEL0_REG & ~0x0FUL) | 0x05UL;

    /* Enable access to divisor latch registers */
    U0LCR_REG = 0x83;

    /* PCLK = 15 MHz, divisor = 98 */
    U0DLM_REG = 0;
    U0DLL_REG = 98;

    /* Fractional divider disabled */
    U0FDR_REG = 0x10;

    /* 8 data bits, no parity, 1 stop bit, DLAB = 0 */
    U0LCR_REG = 0x03;
}

/* Transmit one character */
void UART0_SendChar(char ch)
{
    while ((U0LSR_REG & 0x20UL) == 0)
    {
        /* Wait until Transmitter Holding Register is empty */
    }

    U0THR_REG = (unsigned char)ch;
}

/* Transmit a string */
void UART0_SendString(char *str)
{
    while (*str != '\0')
    {
        UART0_SendChar(*str);
        str++;
    }
}

/* Display a two-digit number */
void UART0_Send2Digits(unsigned int value)
{
    UART0_SendChar((char)('0' + ((value / 10) % 10)));
    UART0_SendChar((char)('0' + (value % 10)));
}

/* Display a four-digit year */
void UART0_Send4Digits(unsigned int value)
{
    UART0_SendChar((char)('0' + ((value / 1000) % 10)));
    UART0_SendChar((char)('0' + ((value / 100) % 10)));
    UART0_SendChar((char)('0' + ((value / 10) % 10)));
    UART0_SendChar((char)('0' + (value % 10)));
}

/* Display an unsigned integer */
void UART0_SendNumber(unsigned int value)
{
    char digits[10];
    unsigned int i;

    i = 0;

    if (value == 0)
    {
        UART0_SendChar('0');
        return;
    }

    while (value > 0 && i < sizeof(digits))
    {
        digits[i] = (char)('0' + (value % 10));
        value = value / 10;
        i++;
    }

    while (i > 0)
    {
        i--;
        UART0_SendChar(digits[i]);
    }
}

/* Display day of the week */
void UART0_PrintDay(unsigned int dow)
{
    switch (dow)
    {
        case 0:
            UART0_SendString("Sunday");
            break;

        case 1:
            UART0_SendString("Monday");
            break;

        case 2:
            UART0_SendString("Tuesday");
            break;

        case 3:
            UART0_SendString("Wednesday");
            break;

        case 4:
            UART0_SendString("Thursday");
            break;

        case 5:
            UART0_SendString("Friday");
            break;

        case 6:
            UART0_SendString("Saturday");
            break;

        default:
            UART0_SendString("Unknown");
            break;
    }
}

/*
 * Read a consistent RTC snapshot.
 *
 * If the seconds counter changes during the read,
 * repeat the operation.
 */
int RTC_ReadSnapshot(RTC_TIME *time)
{
    unsigned int sec_before;
    unsigned int sec_after;

    do
    {
        sec_before = RTC_SEC & 0x3FUL;

        time->min   = RTC_MIN & 0x3FUL;
        time->hour  = RTC_HOUR & 0x1FUL;
        time->dom   = RTC_DOM & 0x1FUL;
        time->dow   = RTC_DOW & 0x07UL;
        time->doy   = RTC_DOY & 0x1FFUL;
        time->month = RTC_MONTH & 0x0FUL;
        time->year  = RTC_YEAR & 0x0FFFUL;

        sec_after = RTC_SEC & 0x3FUL;

    } while (sec_before != sec_after);

    time->sec = sec_after;

    return 1;
}

/* Display complete RTC information */
void RTC_Display(RTC_TIME *time)
{
    UART0_SendString("Date: ");

    UART0_Send2Digits(time->dom);
    UART0_SendChar('/');

    UART0_Send2Digits(time->month);
    UART0_SendChar('/');

    UART0_Send4Digits(time->year);

    UART0_SendString("  Day: ");
    UART0_PrintDay(time->dow);

    UART0_SendString("\r\nTime: ");

    UART0_Send2Digits(time->hour);
    UART0_SendChar(':');

    UART0_Send2Digits(time->min);
    UART0_SendChar(':');

    UART0_Send2Digits(time->sec);

    UART0_SendString("\r\n");

    UART0_SendString("Day of Year: ");
    UART0_SendNumber(time->doy);

    UART0_SendString("\r\n");
    UART0_SendString("--------------------------\r\n");
}

/* Main function */
int main(void)
{
    RTC_TIME current_time;
    unsigned int last_sec;

    /* Initialize UART0 */
    UART0_Init();

    UART0_SendString("\r\nLPC2129 RTC Monitor\r\n");
    UART0_SendString("--------------------------\r\n");

    /* Check whether RTC clock is enabled */
    if ((RTC_CCR & 0x01UL) == 0)
    {
        UART0_SendString("ERROR: RTC clock is disabled\r\n");

        while (1)
        {
            /* Stop here until RTC is configured */
        }
    }

    /* Force the first display */
    last_sec = 255;

    while (1)
    {
        RTC_ReadSnapshot(&current_time);

        /*
         * Display only when the seconds counter changes.
         * This avoids repeatedly transmitting the same time.
         */
        if (current_time.sec != last_sec)
        {
            RTC_Display(&current_time);

            last_sec = current_time.sec;
        }
    }
}
Compiler note: This example uses Keil ARMCC-compatible C syntax and direct memory-mapped register access. If your device header or project uses different register declarations, avoid defining duplicate register symbols; use either the header definitions or the explicit address macros consistently.

9. Program Explanation

9.1 UART0 Initialization

UART0 is configured for 9600 baud, 8 data bits, no parity and one stop bit. The program selects the alternate pin functions for P0.0 and P0.1.

9.2 RTC Clock Check

The program checks bit 0 of the Clock Control Register (CCR). If the clock-enable bit is clear, the RTC is not running and the program reports an error.

9.3 Reading RTC Registers

The program reads the individual RTC counters and stores the values in the RTC_TIME structure.

9.4 Snapshot Validation

SEC is read before and after the other counter registers. If the values are different, the operation is repeated. This helps avoid displaying a mixture of values from opposite sides of a second rollover.

9.5 Date and Time Formatting

Helper functions convert numerical values into ASCII characters. For example, the number 7 is displayed as 07 when a two-digit field is required.

9.6 UART Transmission

UART0_SendChar() waits for the Transmitter Holding Register Empty (THRE) status bit before writing the next character. The string function sends a complete message one character at a time.

9.7 Continuous Monitoring

The main loop checks the seconds counter. It transmits another display only when the seconds value changes. This keeps the serial output readable without requiring a separate software delay.

14. Placement Interview Questions and Answers

Q1. What is the purpose of an RTC?

An RTC maintains real-time date and time information, including seconds, minutes, hours, day, month and year.

Q2. Why is UART used with an RTC?

UART provides a simple way to transmit RTC information to a computer, terminal or another serial device.

Q3. What is the purpose of the SEC register?

SEC stores the current seconds value. In the LPC2129 RTC, its normal range is 0 to 59.

Q4. What is the difference between HOUR and DOM?

HOUR stores the current hour of the day, while DOM stores the day number within the current month.

Q5. Why is a consistent RTC snapshot important?

RTC counters update automatically. Reading them across a rollover can produce a combination of values that does not represent one valid time. Snapshot validation reduces this problem.

Q6. What is the function of UART0's U0LCR register?

U0LCR configures the character format and controls access to the divisor latch registers through the DLAB bit.

Q7. What does DLAB mean?

DLAB means Divisor Latch Access Bit. When set, the UART divisor latch registers can be accessed.

Q8. What is THRE?

THRE stands for Transmitter Holding Register Empty. It indicates that the UART transmit holding register can accept another character.

Q9. Why is the UART baud rate calculated using PCLK?

The UART peripheral clock is derived from the peripheral clock domain. Its baud-rate divisor must therefore be calculated using the actual PCLK supplied to UART0.

Q10. What is the difference between UART0 and UART1?

They are separate UART peripherals with their own registers and pin assignments. UART0 uses P0.0 and P0.1 for TXD0 and RXD0, while UART1 uses P0.8 and P0.9 for TXD1 and RXD1.

Q11. Why should sprintf() be used carefully in embedded systems?

Formatted output functions may increase code size and stack usage. Smaller embedded applications can use dedicated conversion functions when only a few numeric fields are required.

Q12. Can the RTC operate while the CPU is executing another task?

Yes. The RTC is a peripheral designed to maintain time independently of the CPU's ordinary instruction execution, provided its clock source and power conditions are maintained.

16. Important Technical Points

  • RTC counters are memory-mapped peripheral registers.
  • RTC time and calendar values must be initialized before use.
  • The LPC2129 RTC uses a 24-hour time representation.
  • A changing RTC can produce inconsistent multi-register reads.
  • UART0 uses P0.0 as TXD0 and P0.1 as RXD0.
  • UART baud-rate calculations must use the actual peripheral clock.
  • U0LSR bit 5 indicates Transmitter Holding Register Empty.
  • RTC and UART can be combined to implement timestamped monitoring.
  • Simulator peripheral support must be verified before drawing conclusions from missing output.

17. Lesson Summary

This lesson demonstrated how to interface the LPC2129 RTC with UART0. Individual RTC counter registers were read, checked for a consistent snapshot and converted into readable date and time information.

UART0 was configured for 9600-8-N-1 communication using a 15 MHz peripheral clock. The program transmitted the date, weekday, time and day-of-year information to a serial terminal.

The same technique can be extended to timestamp sensor measurements, record faults and develop embedded monitoring applications.
