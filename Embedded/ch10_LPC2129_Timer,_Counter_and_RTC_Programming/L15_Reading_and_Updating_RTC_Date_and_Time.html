2. Introduction

For example, an industrial data logger may read the RTC whenever a sensor measurement is stored. The measurement can then be associated with the date and time at which it occurred.

3. RTC Register Groups Used for Reading

The LPC2129 provides two ways to read its current time and calendar information:

  1. Read the individual time counter registers.
  2. Read the consolidated time registers.

3.1 Individual Time Counter Registers

RegisterAddressInformation
SEC0xE0024020Seconds
MIN0xE0024024Minutes
HOUR0xE0024028Hours
DOM0xE002402CDay of month
DOW0xE0024030Day of week
DOY0xE0024034Day of year
MONTH0xE0024038Month
YEAR0xE002403CYear

These registers can be read individually. However, the RTC continues operating while software reads them, so the values may not all represent exactly the same instant.

3.2 Consolidated Time Registers

The LPC2129 provides three read-only consolidated registers. Each register combines multiple time or calendar values into one 32-bit value.

RegisterAddressContents
CTIME00xE0024014Seconds, minutes, hours and day of week
CTIME10xE0024018Day of month, month and year
CTIME20xE002401CDay of year
Consolidated registers are read-only. To update the RTC counters, software must write to the individual time counter registers.

4. Understanding CTIME0

CTIME0 combines the low-order time values into one 32-bit register.

Bit PositionFieldMeaning
5:0Seconds6-bit seconds value
7:6ReservedReserved bits
13:8Minutes6-bit minutes value
15:14ReservedReserved bits
20:16Hours5-bit hours value
23:21ReservedReserved bits
26:24Day of Week3-bit weekday value
31:27ReservedReserved bits

Extracting CTIME0 Fields

seconds =  ctime0        & 0x3F;
minutes = (ctime0 >> 8)  & 0x3F;
hours   = (ctime0 >> 16) & 0x1F;
dow     = (ctime0 >> 24) & 0x07;

The bitwise AND operation masks unwanted bits. The right-shift operation moves the required field into the least significant bit positions.

5. Understanding CTIME1

CTIME1 contains the date, month and year values.

Bit PositionFieldMeaning
4:0Day of Month5-bit date value
7:5ReservedReserved bits
11:8Month4-bit month value
15:12ReservedReserved bits
27:16Year12-bit year value
31:28ReservedReserved bits

Extracting CTIME1 Fields

day   =  ctime1        & 0x1F;
month = (ctime1 >> 8)  & 0x0F;
year  = (ctime1 >> 16) & 0x0FFF;

6. Understanding CTIME2

CTIME2 contains the day-of-year counter.

Bit PositionFieldMeaning
11:0Day of Year12-bit field containing DOY
31:12ReservedReserved bits
doy = ctime2 & 0x0FFF;

7. Why Consistent RTC Reading Is Important

Consider an RTC that currently stores:

23:59:59, 31 December 2024

During a sequence of individual register reads, the RTC may cross midnight. Software might then read the old seconds value but the new date or year value.

Read operationPossible value
SEC read59 from the old second
RTC advancesMidnight occurs
MIN read0 from the new minute
HOUR read0 from the new hour
DOM read1 from the new date

This can produce a software snapshot that never existed as a real RTC time.

Recommended Reading Method

Read CTIME0, CTIME1 and CTIME2, then read CTIME0 again. If CTIME0 changed during the sequence, retry the complete snapshot.

Read CTIME0 (first)
↓ Read CTIME1
↓ Read CTIME2
↓ Read CTIME0 (second)
↓ Compare CTIME0 values
↓ Same? → Accept snapshot
Different? → Retry
This technique detects a time-counter transition during the read sequence. It is a practical consistency check for this RTC. Use a bounded retry count so the application cannot remain stuck in an endless loop.

8. C Structure for RTC Date and Time

A structure provides a convenient way to store all RTC values in one software object. 

typedef struct
{
    unsigned int second;
    unsigned int minute;
    unsigned int hour;

    unsigned int day;
    unsigned int dow;
    unsigned int doy;

    unsigned int month;
    unsigned int year;

} RTC_DateTime;

The structure makes the program easier to read, maintain and extend. It can be passed to display functions, logging routines and application-level date calculations.

9. Complete Embedded C Program: Reading RTC Values

This program reads the consolidated registers and checks whether CTIME0 changed during the snapshot operation. 

/*
 * Project: LPC2129 RTC Read Operation
 * Controller: LPC2129
 * IDE: Keil uVision
 */

#include <LPC21xx.h>

#define RTC_CTIME0_ADDR  0xE0024014UL
#define RTC_CTIME1_ADDR  0xE0024018UL
#define RTC_CTIME2_ADDR  0xE002401CUL

#define RTC_REG(address) \
    (*(volatile unsigned long *)(address))

#define RTC_MAX_RETRIES  10U

typedef struct
{
    unsigned int second;
    unsigned int minute;
    unsigned int hour;

    unsigned int day;
    unsigned int dow;
    unsigned int doy;

    unsigned int month;
    unsigned int year;

} RTC_DateTime;

volatile unsigned int rtc_read_status;
volatile unsigned int rtc_retry_count;

volatile RTC_DateTime rtc_current;

/*
 * Read a consistent RTC snapshot.
 *
 * Return:
 * 1 = successful snapshot
 * 0 = snapshot could not be obtained
 */

int RTC_ReadDateTime(RTC_DateTime *time)
{
    unsigned long ctime0_first;
    unsigned long ctime0_second;
    unsigned long ctime1;
    unsigned long ctime2;

    unsigned int retry;

    if (time == 0)
    {
        return 0;
    }

    for (retry = 0; retry < RTC_MAX_RETRIES; retry++)
    {
        /*
         * Read consolidated registers.
         */

        ctime0_first = RTC_REG(RTC_CTIME0_ADDR);

        ctime1 = RTC_REG(RTC_CTIME1_ADDR);

        ctime2 = RTC_REG(RTC_CTIME2_ADDR);

        /*
         * Read CTIME0 again to detect a time transition.
         */

        ctime0_second = RTC_REG(RTC_CTIME0_ADDR);

        if (ctime0_first == ctime0_second)
        {
            /*
             * Extract CTIME0 fields.
             */

            time->second =
                (unsigned int)(ctime0_first & 0x3FUL);

            time->minute =
                (unsigned int)((ctime0_first >> 8) & 0x3FUL);

            time->hour =
                (unsigned int)((ctime0_first >> 16) & 0x1FUL);

            time->dow =
                (unsigned int)((ctime0_first >> 24) & 0x07UL);

            /*
             * Extract CTIME1 fields.
             */

            time->day =
                (unsigned int)(ctime1 & 0x1FUL);

            time->month =
                (unsigned int)((ctime1 >> 8) & 0x0FUL);

            time->year =
                (unsigned int)((ctime1 >> 16) & 0x0FFFUL);

            /*
             * Extract CTIME2 field.
             */

            time->doy =
                (unsigned int)(ctime2 & 0x0FFFUL);

            return 1;
        }
    }

    return 0;
}

/* Main function */

int main(void)
{
    rtc_read_status = RTC_ReadDateTime(
        (RTC_DateTime *)&rtc_current
    );

    while (1)
    {
        /*
         * Inspect rtc_current in the Keil debugger.
         *
         * rtc_read_status = 1:
         * Snapshot successfully obtained.
         *
         * rtc_read_status = 0:
         * Snapshot could not be obtained.
         */
    }
}
The example uses a bounded retry count of ten. If the RTC changes during every attempt, the function returns failure rather than blocking forever. The application should decide whether to retry later, report an error or use another timing strategy.

10. Updating RTC Date and Time

The consolidated registers are read-only. To change the RTC time, software must write to the individual counter registers.

Registers Used for Updating

RegisterAddressOperation
SEC0xE0024020Write seconds
MIN0xE0024024Write minutes
HOUR0xE0024028Write hours
DOM0xE002402CWrite day of month
DOW0xE0024030Write day of week
DOY0xE0024034Write day of year
MONTH0xE0024038Write month
YEAR0xE002403CWrite year

Safe Update Sequence

  1. Prepare the new date and time values in software.
  2. Validate every value.
  3. Calculate the correct DOY.
  4. Disable the RTC time counters by clearing CLKEN.
  5. Write all eight time and calendar counters.
  6. Enable the RTC time counters again.
  7. Read back the values to verify the update.
Disabling CLKEN stops the time counters so they can be initialized. Do not confuse this with resetting the clock divider. The update operation below does not unnecessarily reset the prescaler.

11. Complete Embedded C Program: Updating RTC

The following example uses the same register definitions and structure as the previous reading program. It validates the new date and time, calculates DOY, updates the counters and reads the values back. 

/*
 * Project: LPC2129 RTC Date and Time Update
 * Controller: LPC2129
 * IDE: Keil uVision
 */

#include <LPC21xx.h>

#define RTC_CCR_ADDR       0xE0024008UL

#define RTC_SEC_ADDR       0xE0024020UL
#define RTC_MIN_ADDR       0xE0024024UL
#define RTC_HOUR_ADDR      0xE0024028UL
#define RTC_DOM_ADDR       0xE002402CUL
#define RTC_DOW_ADDR       0xE0024030UL
#define RTC_DOY_ADDR       0xE0024034UL
#define RTC_MONTH_ADDR     0xE0024038UL
#define RTC_YEAR_ADDR      0xE002403CUL

#define RTC_CTIME0_ADDR    0xE0024014UL
#define RTC_CTIME1_ADDR    0xE0024018UL
#define RTC_CTIME2_ADDR    0xE002401CUL

#define RTC_REG(address) \
    (*(volatile unsigned long *)(address))

#define RTC_CLKEN          (1UL << 0)

typedef struct
{
    unsigned int second;
    unsigned int minute;
    unsigned int hour;

    unsigned int day;
    unsigned int dow;
    unsigned int doy;

    unsigned int month;
    unsigned int year;

} RTC_DateTime;

volatile unsigned int rtc_update_status;
volatile unsigned int rtc_verify_status;

volatile RTC_DateTime rtc_new_time;
volatile RTC_DateTime rtc_readback;

/* Leap-year rule for the RTC-supported example range */

int IsLeapYear(unsigned int year)
{
    return ((year % 4U) == 0U);
}

/* Calculate day of year */

unsigned int CalculateDOY(
    unsigned int day,
    unsigned int month,
    unsigned int year)
{
    unsigned int days[12] =
    {
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31
    };

    unsigned int i;
    unsigned int total = day;

    if (IsLeapYear(year))
    {
        days[1] = 29;
    }

    for (i = 0; i < (month - 1U); i++)
    {
        total += days[i];
    }

    return total;
}

/* Validate date and time */

int ValidateRTC(const RTC_DateTime *time)
{
    unsigned int monthDays[12] =
    {
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31
    };

    if (time == 0)
        return 0;

    if (time->year < 1901U ||
        time->year > 2099U)
        return 0;

    if (time->month < 1U ||
        time->month > 12U)
        return 0;

    if (time->hour > 23U)
        return 0;

    if (time->minute > 59U)
        return 0;

    if (time->second > 59U)
        return 0;

    if (time->dow > 6U)
        return 0;

    if (IsLeapYear(time->year))
    {
        monthDays[1] = 29;
    }

    if (time->day < 1U ||
        time->day > monthDays[time->month - 1U])
        return 0;

    return 1;
}

/* Update RTC registers */

int RTC_UpdateDateTime(RTC_DateTime *time)
{
    unsigned int calculatedDOY;

    if (!ValidateRTC(time))
    {
        return 0;
    }

    calculatedDOY = CalculateDOY(
        time->day,
        time->month,
        time->year
    );

    /*
     * Disable RTC time counters.
     * Other CCR control bits are kept at zero
     * for this normal-operation example.
     */

    RTC_REG(RTC_CCR_ADDR) = 0x00UL;

    /*
     * Write all time counters.
     */

    RTC_REG(RTC_SEC_ADDR) = time->second;
    RTC_REG(RTC_MIN_ADDR) = time->minute;
    RTC_REG(RTC_HOUR_ADDR) = time->hour;

    /*
     * Write calendar counters.
     */

    RTC_REG(RTC_DOM_ADDR) = time->day;
    RTC_REG(RTC_DOW_ADDR) = time->dow;
    RTC_REG(RTC_DOY_ADDR) = calculatedDOY;
    RTC_REG(RTC_MONTH_ADDR) = time->month;
    RTC_REG(RTC_YEAR_ADDR) = time->year;

    /*
     * Enable RTC time counters.
     */

    RTC_REG(RTC_CCR_ADDR) = RTC_CLKEN;

    /*
     * Store calculated DOY in the structure.
     */

    time->doy = calculatedDOY;

    return 1;
}

/*
 * Consistent consolidated-register read.
 */

int RTC_ReadDateTime(RTC_DateTime *time)
{
    unsigned long c0_first;
    unsigned long c0_second;
    unsigned long c1;
    unsigned long c2;

    unsigned int retry;

    if (time == 0)
        return 0;

    for (retry = 0; retry < 10U; retry++)
    {
        c0_first = RTC_REG(RTC_CTIME0_ADDR);
        c1 = RTC_REG(RTC_CTIME1_ADDR);
        c2 = RTC_REG(RTC_CTIME2_ADDR);
        c0_second = RTC_REG(RTC_CTIME0_ADDR);

        if (c0_first == c0_second)
        {
            time->second =
                (unsigned int)(c0_first & 0x3FUL);

            time->minute =
                (unsigned int)((c0_first >> 8) & 0x3FUL);

            time->hour =
                (unsigned int)((c0_first >> 16) & 0x1FUL);

            time->dow =
                (unsigned int)((c0_first >> 24) & 0x07UL);

            time->day =
                (unsigned int)(c1 & 0x1FUL);

            time->month =
                (unsigned int)((c1 >> 8) & 0x0FUL);

            time->year =
                (unsigned int)((c1 >> 16) & 0x0FFFUL);

            time->doy =
                (unsigned int)(c2 & 0x0FFFUL);

            return 1;
        }
    }

    return 0;
}

int main(void)
{
    /*
     * New date:
     * 1 March 2025
     *
     * Time:
     * 10:30:00
     *
     * Saturday = 6
     */

    rtc_new_time.second = 0;
    rtc_new_time.minute = 30;
    rtc_new_time.hour = 10;

    rtc_new_time.day = 1;
    rtc_new_time.month = 3;
    rtc_new_time.year = 2025;
    rtc_new_time.dow = 6;

    rtc_update_status = RTC_UpdateDateTime(
        (RTC_DateTime *)&rtc_new_time
    );

    if (rtc_update_status)
    {
        rtc_verify_status = RTC_ReadDateTime(
            (RTC_DateTime *)&rtc_readback
        );
    }
    else
    {
        rtc_verify_status = 0;
    }

    while (1)
    {
        /*
         * Inspect rtc_new_time and rtc_readback
         * in the Keil debugger.
         */
    }
}

14. Updating Only Selected RTC Fields

Some applications need to update only a selected portion of the RTC information. For example, an operator may need to correct the date without changing the time.

However, the RTC counters are related. Changing the date may require updating DOM, DOW, DOY, MONTH and YEAR together.

Example: Correcting the Calendar Date

  1. Read the current RTC date and time.
  2. Prepare the corrected calendar values.
  3. Calculate the correct DOW and DOY.
  4. Disable the RTC time counters.
  5. Write the related calendar fields.
  6. Enable the RTC time counters again.
  7. Read back the values and verify them.
Never update only one calendar field if the change makes the other calendar counters inconsistent. The RTC increments these counters independently; it does not automatically calculate all related date fields from a single date value.

16. Common Programming Errors

ErrorCauseCorrection
Wrong seconds value Incorrect bit mask Use mask 0x3F.
Wrong minutes value Incorrect bit shift Shift CTIME0 by 8 bits.
Wrong hour value Incorrect field extraction Shift CTIME0 by 16 bits and mask 0x1F.
Wrong year value Incorrect CTIME1 extraction Shift by 16 bits and mask 0x0FFF.
Inconsistent snapshot RTC advances during reading Use the CTIME0 consistency check.
RTC not updated CLKEN remains enabled Disable counters before writing.
Incorrect DOY DOY not recalculated Calculate DOY for the new date.
Incorrect weekday DOW not updated Calculate or verify the weekday.

19. Placement-Oriented Interview Questions

Q1. What are consolidated RTC registers?

They are read-only registers that combine multiple RTC time and calendar fields into 32-bit values.

Q2. How many consolidated time registers are available?

Three: CTIME0, CTIME1 and CTIME2.

Q3. What does CTIME0 contain?

Seconds, minutes, hours and day of week.

Q4. What does CTIME1 contain?

Day of month, month and year.

Q5. What does CTIME2 contain?

Day of year.

Q6. Can consolidated registers be used to update the RTC?

No. They are read-only. Software must write to the individual time counter registers.

Q7. Why should software check CTIME0 before and after reading CTIME1 and CTIME2?

The comparison detects a time transition during the grouped read sequence and allows software to retry rather than accept a potentially inconsistent snapshot.

Q8. Why is CLKEN cleared during an RTC update?

The time counters must be disabled before software initializes or changes their values.

Q9. What is the difference between CTIME0 and SEC?

SEC is an individual seconds counter. CTIME0 combines seconds, minutes, hours and day of week.

Q10. Why should RTC reading functions use a retry limit?

A retry limit prevents the program from blocking indefinitely if it cannot obtain a stable snapshot.

22. Lesson Summary

  • The LPC2129 provides eight individual time and calendar counters.
  • CTIME0, CTIME1 and CTIME2 provide consolidated read-only values.
  • Bitwise masks and shifts extract individual fields.
  • A consistency check helps detect counter transitions during reading.
  • A C structure makes RTC data easier to manage.
  • Individual counter registers are used for updating the RTC.
  • CLKEN must be cleared before changing time counter values.
  • Calendar fields must be updated consistently.
  • Readback verifies the values written by software.
