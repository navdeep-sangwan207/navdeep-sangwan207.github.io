2. Introduction to RTC Alarm

An RTC alarm allows an embedded controller to generate an interrupt when the current RTC time matches a programmed alarm value.

For example, an industrial controller may need to activate a scheduled operation every day at 10:30 AM. Instead of continuously checking the time in a software loop, the RTC alarm hardware can detect the matching time and request an interrupt.

Current RTC Date and Time
↓ Alarm Comparison Hardware
↑ Programmed Alarm Registers
↓ Alarm Match
↓ RTC Interrupt Flag
↓ Vectored Interrupt Controller
↓ RTC Interrupt Service Routine

3. RTC Alarm Register Group

The LPC2129 provides eight alarm registers. Each alarm register corresponds to one of the RTC time and calendar counters.

Alarm RegisterAddressCorresponding Counter
ALSEC0xE0024060SEC
ALMIN0xE0024064MIN
ALHOUR0xE0024068HOUR
ALDOM0xE002406CDOM
ALDOW0xE0024070DOW
ALDOY0xE0024074DOY
ALMON0xE0024078MONTH
ALYEAR0xE002407CYEAR

The alarm registers store the values against which the current RTC counters are compared.

4. Alarm Matching Mechanism

The RTC compares the alarm register values with their corresponding time counter values. The Alarm Mask Register determines which comparisons participate in the alarm match.

An alarm match occurs when every unmasked alarm field matches its corresponding current time counter.

Example: Daily Alarm at 10:30:00 AM

Suppose the required alarm is:

  • Seconds = 0
  • Minutes = 30
  • Hours = 10

If the date-related fields are masked, the RTC compares only seconds, minutes and hours. The alarm can therefore match every day at 10:30:00 AM.

RegisterAlarm ValueComparison
ALSEC0Enabled
ALMIN30Enabled
ALHOUR10Enabled
ALDOM1Masked
ALDOW0Masked
ALDOY1Masked
ALMON1Masked
ALYEAR2025Masked
Values in masked alarm registers do not participate in the comparison. Their stored values do not need to match the current date or calendar counters.

5. Alarm Mask Register (AMR)

The Alarm Mask Register is located at:

AMR address = 0xE0024010

Each bit controls whether its corresponding alarm register is included in the comparison.

BitNameFunction
0AMRSECMask seconds comparison
1AMRMINMask minutes comparison
2AMRHOURMask hours comparison
3AMRDOMMask day-of-month comparison
4AMRDOWMask day-of-week comparison
5AMRDOYMask day-of-year comparison
6AMRMONMask month comparison
7AMRYEARMask year comparison

Important AMR Logic

  • Bit = 0: corresponding alarm field is compared.
  • Bit = 1: corresponding alarm field is ignored.

Daily Alarm Example

To compare seconds, minutes and hours but ignore all calendar fields: 

AMR = 0xF8;

Binary representation:

AMR = 11111000
      ||||||||
      |||||||+-- Seconds: compare
      ||||||+--- Minutes: compare
      |||||+---- Hours: compare
      ||||+----- DOM: mask
      |||+------ DOW: mask
      ||+------- DOY: mask
      |+-------- Month: mask
      +--------- Year: mask

The resulting alarm is based on the time of day and can occur every day.

If all AMR bits are set to 1, all alarm comparisons are masked and the alarm is disabled. If all bits are cleared, all eight alarm fields must match.

6. Interrupt Location Register (ILR)

The Interrupt Location Register identifies the source of an RTC interrupt and provides the mechanism to clear the corresponding RTC interrupt flag.

ILR address = 0xE0024000

BitNameMeaning
0RTCCIFCounter increment interrupt flag
1RTCALFAlarm interrupt flag
7:2ReservedDo not write ones to reserved bits

Interrupt Flag Clearing

The RTC interrupt flags are cleared by writing a one to the corresponding bit. 

/* Clear counter increment interrupt */
ILR = 0x01;

/* Clear alarm interrupt */
ILR = 0x02;

/* Clear both interrupt flags */
ILR = 0x03;
ILR uses write-one-to-clear behavior. Writing zero does not clear the corresponding flag. Do not use an ordinary read-modify-write operation to clear one flag, because writing back another flag that was already set could clear it unintentionally.

7. Counter Increment Interrupt Register (CIIR)

The Counter Increment Interrupt Register allows an interrupt to be generated whenever a selected RTC counter is incremented.

CIIR address = 0xE002400C

BitNameInterrupt Event
0IMSECSeconds counter increment
1IMMINMinutes counter increment
2IMHOURHours counter increment
3IMDOMDay-of-month counter increment
4IMDOWDay-of-week counter increment
5IMDOYDay-of-year counter increment
6IMMONMonth counter increment
7IMYEARYear counter increment

Example: Enable Seconds Increment Interrupt

CIIR = 0x01;

This selects the seconds counter increment event. The RTC can generate a counter increment interrupt whenever the seconds counter advances.

Disable All Counter Increment Interrupts

CIIR = 0x00;
For a scheduled alarm, CIIR is not required. The alarm comparison hardware and AMR perform the time matching independently.

8. RTC Interrupt and VIC

The RTC peripheral generates an interrupt request when its configured interrupt condition occurs. The Vectored Interrupt Controller (VIC) routes that request to the ARM processor.

ParameterValue
PeripheralRTC
VIC channel number13
Counter increment flagRTCCIF
Alarm flagRTCALF
VIC interrupt enable bitBit 13

VIC Registers Used

RegisterAddressPurpose
VICIntEnable0xFFFFF010Enable interrupt sources
VICIntEnClr0xFFFFF014Disable interrupt sources
VICVectAddr0xFFFFF030Interrupt vector address / end-of-ISR acknowledgement
VICVectAddr00xFFFFF100Address of vector slot 0 ISR
VICVectCntl00xFFFFF200Configure vector slot 0

Assign RTC to Vectored IRQ Slot 0

VICVectAddr0 = (unsigned long)RTC_ISR;
VICVectCntl0 = 0x20 | 13;

VICIntEnable = (1UL << 13);

The value 0x20 enables the vector slot. The value 13 selects the RTC interrupt channel.

The RTC is VIC channel 13 on the LPC2129. This is different from the RTC alarm flag number: RTCALF is bit 1 inside ILR, while 13 is the VIC peripheral interrupt channel.

9. Understanding the RTC Interrupt Service Routine

An Interrupt Service Routine (ISR) is a function executed by the processor when an enabled interrupt request is accepted.

A typical RTC alarm ISR performs the following operations:

  1. Read the RTC interrupt flags.
  2. Check whether the alarm flag is set.
  3. Record the alarm event.
  4. Clear the RTC alarm flag by writing one to ILR bit 1.
  5. Write to VICVectAddr to acknowledge completion of the vectored ISR.
  6. Return from the interrupt.
void __irq RTC_ISR(void)
{
    unsigned long status;

    status = ILR;

    if (status & 0x02)
    {
        /* Record alarm event */

        ILR = 0x02;
    }

    /* Acknowledge VIC interrupt */

    VICVectAddr = 0;
}
Keep the ISR short. Avoid long delays, blocking UART transmission, lengthy calculations and complex application processing inside the ISR. Record the event in a shared variable and process it in the main program.

10. Complete Embedded C Program: Daily RTC Alarm

This program configures a daily alarm for 10:30:00 AM. It uses the LPC2129 RTC alarm registers, AMR, ILR and VIC channel 13.

Alarm configuration:

  • Seconds = 0
  • Minutes = 30
  • Hours = 10
  • Date fields are masked.
  • CIIR is disabled.
  • RTC alarm interrupt is routed through VIC channel 13.
/*
 * Project: LPC2129 Daily RTC Alarm
 * Controller: LPC2129
 * IDE: Keil uVision
 *
 * Alarm: Every day at 10:30:00 AM
 */

#include <LPC21xx.h>

/* RTC register addresses */

#define RTC_ILR_ADDR       0xE0024000UL
#define RTC_CIIR_ADDR      0xE002400CUL
#define RTC_AMR_ADDR       0xE0024010UL

#define RTC_ALSEC_ADDR     0xE0024060UL
#define RTC_ALMIN_ADDR     0xE0024064UL
#define RTC_ALHOUR_ADDR    0xE0024068UL
#define RTC_ALDOM_ADDR     0xE002406CUL
#define RTC_ALDOW_ADDR     0xE0024070UL
#define RTC_ALDOY_ADDR     0xE0024074UL
#define RTC_ALMON_ADDR     0xE0024078UL
#define RTC_ALYEAR_ADDR    0xE002407CUL

/* VIC register addresses */

#define VIC_INT_ENABLE     0xFFFFF010UL
#define VIC_INT_EN_CLR     0xFFFFF014UL
#define VIC_VECTOR_ADDR    0xFFFFF030UL
#define VIC_VECTOR_ADDR0   0xFFFFF100UL
#define VIC_VECTOR_CNTL0   0xFFFFF200UL

#define RTC_REG(address) \
    (*(volatile unsigned long *)(address))

/* RTC interrupt definitions */

#define RTC_IRQ_CHANNEL    13UL
#define RTC_ALARM_FLAG     (1UL << 1)

/* Alarm configuration */

#define ALARM_SECONDS      0UL
#define ALARM_MINUTES      30UL
#define ALARM_HOURS        10UL

#define ALARM_MASK         0xF8UL

/* Shared ISR variables */

volatile unsigned int rtc_alarm_event;
volatile unsigned int rtc_alarm_count;
volatile unsigned int rtc_last_status;

/*
 * RTC interrupt service routine.
 *
 * Keil ARMCC syntax is used for the LPC2129
 * ARM7 interrupt handler.
 */

void __irq RTC_ISR(void)
{
    unsigned long status;

    /* Read RTC interrupt flags */

    status = RTC_REG(RTC_ILR_ADDR);

    rtc_last_status = (unsigned int)status;

    /* Check alarm interrupt flag */

    if (status & RTC_ALARM_FLAG)
    {
        /*
         * Record the event.
         * Do not perform lengthy operations here.
         */

        rtc_alarm_event = 1U;
        rtc_alarm_count++;

        /*
         * Clear RTC alarm flag.
         * ILR uses write-one-to-clear.
         */

        RTC_REG(RTC_ILR_ADDR) = RTC_ALARM_FLAG;
    }

    /*
     * Acknowledge completion of the
     * vectored interrupt.
     */

    RTC_REG(VIC_VECTOR_ADDR) = 0UL;
}

/* Configure daily RTC alarm */

void RTC_ConfigureDailyAlarm(void)
{
    /* Disable RTC interrupt at VIC during setup */

    RTC_REG(VIC_INT_EN_CLR) =
        (1UL << RTC_IRQ_CHANNEL);

    /* Disable counter increment interrupts */

    RTC_REG(RTC_CIIR_ADDR) = 0x00UL;

    /* Program alarm time */

    RTC_REG(RTC_ALSEC_ADDR) = ALARM_SECONDS;
    RTC_REG(RTC_ALMIN_ADDR) = ALARM_MINUTES;
    RTC_REG(RTC_ALHOUR_ADDR) = ALARM_HOURS;

    /*
     * Calendar values are not used because
     * their comparison bits are masked.
     */

    RTC_REG(RTC_ALDOM_ADDR) = 1UL;
    RTC_REG(RTC_ALDOW_ADDR) = 0UL;
    RTC_REG(RTC_ALDOY_ADDR) = 1UL;
    RTC_REG(RTC_ALMON_ADDR) = 1UL;
    RTC_REG(RTC_ALYEAR_ADDR) = 2025UL;

    /*
     * AMR = 0xF8
     *
     * Compare:
     * SEC, MIN, HOUR
     *
     * Mask:
     * DOM, DOW, DOY, MONTH, YEAR
     */

    RTC_REG(RTC_AMR_ADDR) = ALARM_MASK;

    /* Clear any pending RTC interrupt flags */

    RTC_REG(RTC_ILR_ADDR) = 0x03UL;

    /* Install RTC ISR in VIC vector slot 0 */

    RTC_REG(VIC_VECTOR_ADDR0) =
        (unsigned long)RTC_ISR;

    RTC_REG(VIC_VECTOR_CNTL0) =
        (0x20UL | RTC_IRQ_CHANNEL);

    /* Enable RTC interrupt source in VIC */

    RTC_REG(VIC_INT_ENABLE) =
        (1UL << RTC_IRQ_CHANNEL);
}

/* Main function */

int main(void)
{
    rtc_alarm_event = 0U;
    rtc_alarm_count = 0U;
    rtc_last_status = 0U;

    RTC_ConfigureDailyAlarm();

    /*
     * The RTC must already be running
     * with a valid time and date.
     *
     * RTC initialization is covered in
     * Lesson 14.
     */

    __enable_irq();

    while (1)
    {
        if (rtc_alarm_event)
        {
            /*
             * Main-loop alarm processing.
             *
             * Example actions:
             * - Set a status flag.
             * - Update an application state.
             * - Request a display refresh.
             * - Start a scheduled task.
             */

            rtc_alarm_event = 0U;
        }
    }
}
This example assumes the RTC is already initialized and running. Configure the RTC time counters and prescaler before relying on the alarm. The program uses Keil ARMCC's __irq and __enable_irq() conventions; use the corresponding compiler-supported interrupt syntax if the project uses a different toolchain.

11. Understanding the Alarm Program

11.1 Alarm Time Configuration

ALSEC  = 0;
ALMIN  = 30;
ALHOUR = 10;

These values represent 10:30:00 AM in the RTC's 24-hour format.

11.2 Alarm Mask Configuration

AMR = 0xF8;

This enables comparisons for seconds, minutes and hours. Date fields do not participate in the alarm comparison.

11.3 RTC Interrupt Flag

if (ILR & 0x02)
{
    rtc_alarm_event = 1;
    ILR = 0x02;
}

The ISR checks bit 1 of ILR to identify an alarm event and clears that flag by writing one to it.

11.4 VIC Configuration

VICVectAddr0 = (unsigned long)RTC_ISR;
VICVectCntl0 = 0x20 | 13;
VICIntEnable = (1UL << 13);

These statements assign RTC channel 13 to vector slot 0 and enable the corresponding interrupt source.

13. Alarm Interrupt vs Polling

Polling Method

In polling, software repeatedly reads the RTC time and compares it with the required alarm time. 

while (1)
{
    if ((HOUR == 10) &&
        (MIN == 30) &&
        (SEC == 0))
    {
        /* Perform scheduled operation */
    }
}

Interrupt Method

In the interrupt method, hardware performs the alarm comparison and requests processor attention when the matching condition occurs.

PollingInterrupt
CPU repeatedly checks a condition.Hardware requests CPU attention.
Can waste processing time.Allows the CPU to perform other work between events.
Simple for basic applications.Useful for scheduled and event-driven applications.
Requires correct polling interval.Requires correct interrupt configuration and flag handling.

14. Important Interrupt Programming Rules

  1. Configure the RTC alarm registers before enabling the VIC source.
  2. Clear pending RTC flags before starting the application.
  3. Use the correct VIC channel number.
  4. Keep the ISR short and deterministic.
  5. Clear the peripheral interrupt flag inside the ISR.
  6. Acknowledge the vectored interrupt through VICVectAddr.
  7. Use volatile for variables shared between the ISR and main program.
  8. Perform lengthy application work outside the ISR.
Important distinction: Clearing the RTC flag and acknowledging the VIC are two separate operations. The ISR must clear the source condition in the RTC and complete the VIC acknowledgement.

18. Placement-Oriented Interview Questions

Q1. What is an RTC alarm?

An RTC alarm is a programmed time or date condition that generates an interrupt when the selected RTC counters match the configured alarm values.

Q2. What is the purpose of AMR?

AMR determines which alarm fields participate in the comparison. A bit set to one masks its corresponding field.

Q3. What is the difference between AMR and CIIR?

AMR controls alarm comparisons. CIIR selects which counter increments generate interrupts.

Q4. What is the purpose of ILR?

ILR identifies the RTC interrupt source through RTCCIF and RTCALF flags and provides write-one-to-clear operations.

Q5. What is the meaning of RTCALF?

RTCALF is the RTC alarm interrupt flag, located at bit 1 of ILR.

Q6. What is the VIC channel number for RTC in LPC2129?

RTC uses VIC channel 13.

Q7. What is an ISR?

An Interrupt Service Routine is a function executed in response to an accepted interrupt request.

Q8. Why should an ISR be short?

A short ISR reduces interrupt latency, limits blocking of other processing and improves system responsiveness.

Q9. Why is VICVectAddr written with zero at the end of a vectored ISR?

Writing to the VIC vector address register signals completion of the current vectored interrupt service.

Q10. How can a daily alarm be configured?

Program the required seconds, minutes and hours in the alarm registers and mask the calendar fields using AMR.

Q11. What happens if all AMR bits are set?

All alarm comparisons are masked, so the alarm is disabled.

Q12. Why should the main program process an alarm event outside the ISR?

It keeps interrupt execution short and allows complex operations to run in normal application context.

20. Lesson Summary

  • The LPC2129 RTC provides eight alarm registers.
  • AMR selects which alarm fields participate in comparison.
  • A zero AMR bit enables comparison; a one masks it.
  • ILR contains counter increment and alarm interrupt flags.
  • RTC interrupt flags are cleared using write-one-to-clear operations.
  • CIIR enables selected counter increment interrupts.
  • RTC uses VIC channel 13 on the LPC2129.
  • The ISR should clear the RTC source flag and acknowledge the VIC.
  • Long application processing should be performed outside the ISR.
