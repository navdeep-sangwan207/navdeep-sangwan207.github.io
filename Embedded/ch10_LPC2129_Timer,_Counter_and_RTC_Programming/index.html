1. Chapter Overview

Timers, counters and Real-Time Clock peripherals are important components of embedded microcontrollers. They provide time measurement, event counting, periodic task scheduling, alarm generation and calendar-based timekeeping.

The LPC2129 provides two 32-bit general-purpose timer/counter blocks: Timer 0 and Timer 1. These peripherals support prescaling, match operations, capture operations and interrupt generation.

The LPC2129 also provides an on-chip Real-Time Clock (RTC) peripheral for maintaining seconds, minutes, hours, date, day, month and year information.

Chapter focus: Configure and program the LPC2129 timers, counters and on-chip RTC using Embedded C. Learn register-level programming, time calculations, interrupt handling, debugging and practical embedded applications.
The RTC covered in this chapter is the LPC2129 on-chip RTC. External RTC modules such as DS1307 and DS3231 are optional hardware extensions and are not substitutes for the on-chip RTC lessons.

5. Important LPC2129 Timer Registers

Register Function
T0TCR / T1TCR Timer Control Register – enables, disables and resets the timer.
T0TC / T1TC Timer Counter Register – stores the current timer count.
T0PR / T1PR Prescale Register – determines the prescaler terminal count.
T0PC / T1PC Prescale Counter Register – counts peripheral clock cycles.
T0MR0–T0MR3 Timer 0 Match Registers.
T1MR0–T1MR3 Timer 1 Match Registers.
T0MCR / T1MCR Match Control Register – configures interrupt, reset and stop actions.
T0IR / T1IR Interrupt Register – indicates timer interrupt sources and supports clearing flags.
T0CCR / T1CCR Capture Control Register – configures capture input behavior.
T0CR0–T0CR3 Timer 0 Capture Registers.
T1CR0–T1CR3 Timer 1 Capture Registers.
Timer register names and behavior should be checked against the LPC2129 User Manual and the device header file used by the Keil project.

6. Important LPC2129 RTC Registers

The LPC2129 RTC uses dedicated registers for clock control, interrupt status, calendar information, alarm configuration and prescaling.

Register Function
ILR Interrupt Location Register – indicates RTC interrupt sources.
CTC Clock Tick Counter – provides information about RTC clock ticks.
CCR Clock Control Register – controls RTC operation and reset behavior.
CIIR Counter Increment Interrupt Register – selects counter increment interrupt sources.
AMR Alarm Mask Register – selects which alarm fields participate in matching.
CTIME0 Provides combined seconds, minutes and hours information.
CTIME1 Provides combined day-of-week, day-of-month and day-of-year information.
CTIME2 Provides combined month and year information.
SEC, MIN, HOUR RTC seconds, minutes and hours registers.
DOM, DOW, DOY Day of month, day of week and day of year registers.
MONTH, YEAR RTC month and year registers.
ALSEC, ALMIN, ALHOUR Alarm seconds, minutes and hours registers.
ALDOM, ALDOW, ALDOY Alarm day-of-month, day-of-week and day-of-year registers.
ALMON, ALYEAR Alarm month and year registers.
PREINT Integer portion of the RTC prescaler.
PREFRAC Fractional portion of the RTC prescaler.
Important register distinction: The timer peripheral also has registers named CCR for Capture Control. The RTC has its own Clock Control Register named CCR. These are different peripheral registers and must not be confused. Confirm the exact register definitions and bit descriptions using the LPC2129 User Manual and the device header file.

8. LPC2129 Project Clock Reference

The following clock configuration is used as the reference for timer calculations in this learning project.

Parameter Project Value
Oscillator Frequency (FOSC) 12 MHz
CPU Clock (CCLK) 60 MHz
Peripheral Clock (PCLK) 15 MHz
VPBDIV Register Encoding 0x00
Peripheral Clock Divider Ratio 4
Timer calculation reference: Timer peripherals use the configured peripheral clock. With PCLK = 15 MHz, one peripheral clock cycle is approximately 66.67 ns.

For example, with PR = 14999, the prescaler produces one timer counter increment for every 15000 peripheral clock cycles, assuming the timer is operating in its normal timer mode.

Timer increment frequency = 15,000,000 / 15,000 = 1,000 Hz.

One timer counter increment occurs every 1 millisecond.

RTC Clock Reference

The RTC uses its dedicated clocking arrangement. The 32.768 kHz clock reference is commonly used for real-time clock operation because it can be divided to obtain a one-second timekeeping interval.

RTC prescaler configuration involves the integer prescaler register (PREINT) and fractional prescaler register (PREFRAC). Their configuration must follow the LPC2129 RTC prescaler equations and the clock conditions specified in the device documentation.

Do not automatically apply the Timer 0/Timer 1 PR = 14999 setting to the RTC. The general-purpose timer prescaler and RTC prescaler are separate peripheral mechanisms.

10. Practical Training and Simulation Guidelines

This chapter is designed around register-level Embedded C programming and practical debugging. Each programming lesson should include an implementation and a verification procedure appropriate to the available development tools.

Standard Practical Lesson Format

  1. Objective: State what the program or experiment must achieve.
  2. Technical Explanation: Explain the peripheral operation and relevant concepts.
  3. Register Details: Identify the registers and bit fields used.
  4. Complete Embedded C Program: Provide a complete, compilable program wherever applicable.
  5. Keil Configuration: Specify target device, header file and relevant project settings.
  6. Simulation Procedure: Give step-by-step debugging and verification instructions.
  7. Expected Result: Describe the expected register values, variable values or observable simulation behavior.
  8. Debugging: Explain common errors, troubleshooting and verification methods.
  9. Practical Applications: Relate the experiment to real embedded products and systems.
  10. Placement-Oriented Questions: Include technical interview questions related to the implementation.

Keil µVision Simulator Requirements

  • Use the Keil µVision simulator as the primary learning and debugging environment.
  • Build and compile every practical program before simulation.
  • Inspect peripheral registers, memory locations and variables where simulator support is available.
  • Use breakpoints, single stepping and watch windows to understand program execution.
  • Verify calculations and register configuration independently.
  • For RTC programs, inspect the relevant RTC registers and software variables where supported by the simulator.
  • For UART programs, verify the transmission logic using available simulator or debugging facilities.
  • Record expected results and distinguish them from results that require physical hardware.

Simulator Limitations

Important: Simulator support is peripheral- and device-model-dependent. Do not assume that every LPC2129 peripheral, RTC clock source, interrupt event or external signal is fully simulated.
  • A register may be visible in the debugger even when its complete peripheral behavior is not simulated.
  • RTC time progression must be verified only to the extent supported by the selected simulator model.
  • External RTC modules such as DS1307 and DS3231 require appropriate hardware for physical I2C communication testing.
  • Physical clock accuracy, oscillator behavior and battery-backed operation cannot be established through software simulation alone.
  • External pulses, electrical signals and real-world timing behavior require suitable hardware and measurement equipment.
  • If a peripheral is not supported by the simulator, explain its expected hardware operation and identify the hardware required for verification.
Simulation versus hardware testing: Never report a simulated result as a physical hardware measurement. Clearly label expected results, debugger observations and hardware-verified results separately.

Embedded C Programming Standards

  • Use the correct LPC2129 device header and register definitions.
  • Use clear register masks and bitwise operations.
  • Use suitable data types for register and time values.
  • Initialize peripherals in a controlled sequence.
  • Handle interrupt flags correctly.
  • Keep interrupt service routines short and predictable.
  • Check date and time ranges when accepting or updating RTC values.
  • Use consistent naming conventions and meaningful comments.
  • Explain compiler warnings and common debugging errors.
