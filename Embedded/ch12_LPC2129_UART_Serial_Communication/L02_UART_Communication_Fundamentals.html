1. Introduction

UART (Universal Asynchronous Receiver/Transmitter) is a hardware peripheral used for asynchronous serial communication between embedded devices.

UART transfers data one bit at a time. The transmitter and receiver do not share a separate clock signal. Instead, both devices use compatible baud-rate and frame-format settings to communicate.

UART adds framing information around the data bits so that the receiver can identify the beginning and end of each data frame.

4. Idle State of UART

In a conventional UART interface, the TXD line remains at logic HIGH when no data is being transmitted. This condition is called the idle state.

A start bit is represented by a transition from HIGH to LOW. This falling edge alerts the receiver that a new frame is beginning.

Conceptual UART signal

Idle      Start       Data       Stop       Idle
HIGH  ─────┐
           └── LOW ── data bits ── HIGH ─────────

The exact waveform depends on the transmitted data and configured frame.

UART logic HIGH and LOW refer to the electrical signal levels of the selected interface. Conventional MCU UART pins use logic-level signaling, not direct RS-232 voltage levels.

5. Start Bit

The start bit indicates the beginning of a UART data frame.

  • The UART line normally remains HIGH when idle.
  • The transmitter changes the line to LOW.
  • The receiver detects the falling edge.
  • The receiver uses the configured baud rate to sample the frame.
In conventional UART signaling, the start bit is always logic 0.

6. Data Bits

Data bits contain the actual information being transmitted. Common UART frame configurations use 5, 6, 7 or 8 data bits.

Example: transmitting character 'A'

The ASCII value of uppercase A is: 

Decimal: 65
Hexadecimal: 0x41
Binary: 01000001

UART commonly transmits the least significant bit first. Therefore, the transmitted data-bit order is: 

D0 D1 D2 D3 D4 D5 D6 D7

 1  0  0  0  0  0  1  0
The binary representation is normally written most significant bit first when displayed as a number. UART transmits the least significant data bit first, so the wire order is reversed relative to that written representation.

7. Parity Bit

Parity is an optional error-detection mechanism. It adds one bit to the frame based on the number of logic 1 values in the data.

7.1 Even parity

The parity bit is selected so that the total number of logic 1 bits in the data and parity field is even.

Example

Data:        10110010
Number of 1s: 4
Even parity:  0

The data already contains an even number of ones, so the even parity bit is 0.

7.2 Odd parity

The parity bit is selected so that the total number of logic 1 bits in the data and parity field is odd.

Example

Data:        10110010
Number of 1s: 4
Odd parity:   1

7.3 No parity

No parity bit is included in the UART frame. This is common in simple embedded UART applications.

Parity can detect some bit errors, but it cannot identify every possible communication error. It does not provide complete error correction.

8. Stop Bits

Stop bits indicate the end of a UART frame. They are transmitted as logic HIGH.

Common configurations include:

  • 1 stop bit
  • 2 stop bits

Some UART hardware also supports other stop-bit timing configurations. The supported settings depend on the peripheral.

More stop-bit time increases the total frame duration and reduces the maximum number of frames that can be sent per second at the same baud rate.

10. What Is Baud Rate?

Baud rate represents the number of signal symbols transmitted per second.

In conventional binary UART signaling, each symbol represents one bit interval. Therefore, the baud rate and bit rate have the same numerical value for ordinary UART data signaling.

Common baud rates

  • 1200 baud
  • 2400 baud
  • 4800 baud
  • 9600 baud
  • 19200 baud
  • 38400 baud
  • 57600 baud
  • 115200 baud
A baud rate of 9600 means that 9600 signal symbols are transmitted per second. For conventional binary UART signaling, this corresponds to 9600 bit intervals per second.

11. Bit Duration Calculation

Bit duration is the time required to transmit one bit interval.

Formula:

Bit Duration = 1 / Baud Rate

12. UART Frame Transmission Time

The time required to transmit a UART frame depends on the total number of bit intervals in that frame and the configured baud rate.

Formula:

Frame Time = Total Frame Bits / Baud Rate

Example: 8N1 at 9600 baud

The frame contains:

  • 1 start bit
  • 8 data bits
  • 0 parity bits
  • 1 stop bit
Total Frame Bits = 1 + 8 + 0 + 1
                 = 10 bits

Frame Time = 10 / 9600
           = 0.00104167 seconds
           = 1.04167 milliseconds

Therefore, one 8N1 frame takes approximately 1.042 ms at 9600 baud.

Character transmission rate

Frames per Second = Baud Rate / Frame Bits

                  = 9600 / 10

                  = 960 frames per second
This is the ideal continuous frame rate for this format. Software delays, gaps between transmissions and protocol overhead can reduce the actual application data rate.

13. UART Data Throughput

Data throughput describes how much useful information is transferred in a given period.

For an 8N1 frame, each 10-bit frame carries 8 data bits. 

Useful Data Rate =
(Baud Rate × Data Bits) / Total Frame Bits

At 9600 baud with 8N1:

Useful Data Rate = (9600 × 8) / 10

                 = 7680 data bits/second

                 = 960 bytes/second

The framing bits consume part of the transmission capacity. This explains why the useful data throughput is lower than the transmitted bit rate.

14. Baud Rate Compatibility

The transmitter and receiver must use compatible baud rates.

If the baud rates differ significantly, the receiver may sample data at incorrect positions, causing corrupted characters or framing errors.

Example

Transmitter Receiver Result
9600 9600 Compatible configuration
115200 115200 Compatible configuration
9600 19200 Significant mismatch; communication may fail
Both devices should also agree on data length, parity and stop-bit settings. Matching baud rate alone is not sufficient.

15. UART Error Conditions

UART peripherals commonly provide status information about reception errors.

Error Meaning
Overrun Error A received character was not read before another character arrived and the receive storage could not accept it.
Parity Error The received parity does not match the configured parity check.
Framing Error The expected stop-bit condition was not detected correctly.
Break Condition The receive line remains LOW for longer than a normal character frame.

These errors can be detected using UART status registers. On LPC2129, the Line Status Register (LSR) provides important receive and transmit status information.

19. Common Mistakes

  • Using different baud rates at the transmitter and receiver.
  • Configuring different data-bit lengths.
  • Using mismatched parity settings.
  • Configuring the wrong number of stop bits.
  • Assuming UART sends the most significant data bit first.
  • Confusing baud rate with useful application data throughput.
  • Ignoring overrun and framing errors.
  • Forgetting that UART is normally idle HIGH.
  • Assuming UART logic-level signals are RS-232 signals.

20. Interview Questions and Answers

Q1. What is a UART frame?

A UART frame is a group of bits containing a start bit, data bits, an optional parity bit and stop bit(s).

Q2. What is the purpose of the start bit?

It indicates the beginning of a new UART frame.

Q3. What is the purpose of the stop bit?

It indicates the end of a frame and establishes a HIGH-level interval before the next frame.

Q4. What is baud rate?

Baud rate is the number of signal symbols transmitted per second.

Q5. What is the bit duration at 9600 baud?

Approximately 104.17 microseconds.

Q6. What does 8N1 mean?

Eight data bits, no parity and one stop bit.

Q7. Which bit is transmitted first in conventional UART data?

The least significant bit (LSB) is transmitted first.

Q8. What is even parity?

It is a parity configuration in which the total number of logic 1 bits in the data and parity field is even.

Q9. What is a framing error?

It occurs when the receiver does not detect the expected stop-bit condition correctly.

Q10. Why must baud rates match?

The receiver uses the configured bit timing to sample the incoming serial data correctly.

Q11. Does UART require a separate clock wire?

No. Conventional asynchronous UART uses agreed timing settings rather than a shared clock wire.

Q12. What is the purpose of parity?

Parity provides basic detection of some data transmission errors.

23. Lesson Summary

  • UART is an asynchronous serial communication peripheral.
  • A UART frame contains a start bit, data bits, optional parity and stop bit(s).
  • The conventional UART idle state is HIGH.
  • The start bit is LOW and stop bit(s) are HIGH.
  • Conventional UART sends data LSB first.
  • Baud rate determines signal timing.
  • Bit duration equals 1 divided by baud rate.
  • An 8N1 frame contains 10 bit intervals.
  • Parity provides basic error detection.
  • UART devices require compatible communication settings.
