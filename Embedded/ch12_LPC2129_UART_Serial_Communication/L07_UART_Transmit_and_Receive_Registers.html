1. Introduction

The LPC2129 UART peripheral contains several registers that control serial data transmission, reception, status monitoring and interrupt handling.

The most important registers for data transfer are:

  • THR – Transmit Holding Register.
  • RBR – Receiver Buffer Register.
  • LSR – Line Status Register.
  • IER – Interrupt Enable Register.
  • IIR – Interrupt Identification Register.
  • FCR – FIFO Control Register.
Learning objectives
  • Understand UART transmit and receive data paths.
  • Understand THR and RBR register access.
  • Understand LSR status flags.
  • Understand IER and IIR.
  • Understand UART FIFO operation.
  • Write polling-based transmit and receive programs.
  • Identify UART transmission and reception errors.

2. UART Register Overview

IIRIdentifies the highest-priority pending UART interrupt.

UART0 and UART1 have corresponding register sets, such as U0THR and U1THR, and U0LSR and U1LSR.

3. Transmit Holding Register (THR)

THR stores the data that the CPU wants to transmit through the UART TXD pin.

Basic operation

  1. The CPU checks whether the transmitter can accept another character.
  2. The CPU writes a data byte to THR.
  3. The UART transfers the byte into its transmit path or FIFO.
  4. The UART serializes the data according to the configured frame format.
  5. The bits are transmitted through the TXD pin.
UART transmit data path
CPU → THR → Transmit FIFO → UART Transmitter → TXD Pin

Example: Write a character to THR

U0THR = 'A';

This writes the character A into the UART0 transmit holding register. It does not mean the entire character has already been transmitted.

THR is write-only at its register address when DLAB = 0. The same address is used by DLL when DLAB = 1.

4. Receiver Buffer Register (RBR)

RBR provides received data to the CPU.

Basic operation

  1. A serial frame arrives at the RXD pin.
  2. The UART receiver detects and processes the frame.
  3. The received character is placed in the receive FIFO or buffer.
  4. The CPU checks the receive status.
  5. The CPU reads the received byte from RBR.
UART receive data path
RXD Pin → UART Receiver → Receive FIFO → RBR → CPU

Example: Read a character

unsigned char received_data;

received_data = U0RBR;

The read operation retrieves the next available received character.

RBR is read-only at its register address when DLAB = 0. The same address is used by DLL when DLAB = 1.

5. Line Status Register (LSR)

LSR provides information about the current transmit and receive status.

It helps the CPU determine whether data can be transmitted, whether received data is available, and whether an error has occurred.

LSR bit organization

BitNameFunction
0RDRReceiver Data Ready.
1OEOverrun Error.
2PEParity Error.
3FEFraming Error.
4BIBreak Interrupt.
5THRETransmit Holding Register Empty.
6TEMTTransmitter Empty.
7RXFEError in Receive FIFO.

Important status flags

RDR – Bit 0

Set when at least one received character is available in the receive FIFO.

OE – Bit 1

Indicates that a new character could not be stored because the receive buffer or FIFO was full and an earlier character had not been read.

PE – Bit 2

Indicates that the received character has a parity error.

FE – Bit 3

Indicates a framing error, such as an incorrectly detected stop bit.

BI – Bit 4

Indicates detection of a break condition.

THRE – Bit 5

Indicates that the transmit holding register or transmit FIFO is empty and can accept more data.

TEMT – Bit 6

Indicates that both the transmit holding register/FIFO and the transmit shift register are empty. The complete final frame has left the UART transmitter.

RXFE – Bit 7

Indicates that at least one error is present in the receive FIFO. It is meaningful when FIFO operation is enabled.

6. Difference Between THRE and TEMT

THRE and TEMT are two different transmitter status indicators.

THRETEMT
Transmit holding register/FIFO is empty.Transmit holding register/FIFO and shift register are empty.
More data can be written to the transmit path.All queued data has completed transmission.
Useful for sending the next character.Useful for confirming completion of the final character.
Important: THRE does not guarantee that the last serial bit has left the TXD pin. Use TEMT when software needs to know that the transmitter is completely idle.

7. Interrupt Enable Register (IER)

IER controls which UART interrupt sources are enabled.

BitInterrupt source
0Receive Data Available interrupt.
1Transmit Holding Register Empty interrupt.
2Receive Line Status interrupt.
3Modem Status interrupt (UART1 functionality).

Example: Enable receive data available interrupt

U0IER |= (1U << 0);

Example: Enable THRE interrupt

U0IER |= (1U << 1);

Disable UART interrupts

U0IER = 0x00;

IER is accessed at the same register address as DLL when DLAB = 1. Ensure DLAB is cleared before configuring IER.

8. Interrupt Identification Register (IIR)

IIR identifies the highest-priority pending interrupt condition in the UART.

The CPU or interrupt service routine reads IIR to determine why the UART requested an interrupt.

BitFieldPurpose
0Interrupt PendingIndicates whether an interrupt is pending.
3:1Interrupt IdentificationIdentifies the interrupt source.
5:4FIFO StatusReports FIFO-related status.
7:6FIFO StatusIndicates FIFO enable state.

Common interrupt identification values

IIR bits 3:1Interrupt conditionPriority
011Receive Line StatusHighest
010Receive Data AvailableSecond
110Character TimeoutThird
001THREFourth
000Modem StatusLowest

These identification codes are interpreted together with the interrupt-pending bit and the peripheral's enabled interrupt sources.

IIR is a status register. Do not treat it as a register in which software enables interrupt sources. Interrupt enables are configured through IER.

9. FIFO Control Register (FCR)

FIFO stands for First-In, First-Out. The UART FIFO temporarily stores multiple characters so that the CPU does not need to service every byte immediately.

FCR controls the transmit and receive FIFOs.

BitFieldFunction
0FIFO EnableEnables both transmit and receive FIFOs.
1RX FIFO ResetClears the receive FIFO.
2TX FIFO ResetClears the transmit FIFO.
5:3ReservedReserved bits.
7:6RX Trigger LevelSelects receive FIFO interrupt trigger level.

Receive FIFO trigger levels

Bits 7:6Trigger level
001 character
014 characters
108 characters
1114 characters

Enable FIFO

U0FCR = 0x01;

Enable FIFO and clear both FIFOs

U0FCR = 0x07;

The reset bits are self-clearing control bits. They should not be interpreted as persistent FIFO status flags.

10. UART Register Address Sharing

Some UART registers share the same address. The selected register depends on whether DLAB is enabled.

Register access depends on both the address and operation type. For example, reading offset 0x00 accesses RBR, while writing offset 0x00 accesses THR when DLAB = 0.

11. Polling-Based UART Transmission

Polling means repeatedly checking a status flag until the required condition becomes true.

Transmission steps

  1. Check LSR bit 5 (THRE).
  2. Wait until THRE becomes 1.
  3. Write the character into THR.
  4. Repeat for the next character.

UART0 transmit character function

#include <LPC21xx.h>

void UART0_TxChar(unsigned char ch)
{
    while ((U0LSR & (1U << 5)) == 0)
    {
        /* Wait until THR is empty */
    }

    U0THR = ch;
}

Transmit string function

void UART0_TxString(const char *str)
{
    while (*str != '\0')
    {
        UART0_TxChar((unsigned char)*str);
        str++;
    }
}

The transmit function waits until the UART can accept another character before writing it to THR.

12. Polling-Based UART Reception

Polling-based reception checks whether the UART has received a character.

Reception steps

  1. Read LSR.
  2. Check bit 0 (RDR).
  3. Wait until RDR becomes 1.
  4. Read the received character from RBR.

UART0 receive character function

unsigned char UART0_RxChar(void)
{
    while ((U0LSR & (1U << 0)) == 0)
    {
        /* Wait for received data */
    }

    return (unsigned char)U0RBR;
}

This function blocks until a received character becomes available.

13. Complete UART0 Initialization, Transmission and Reception

Objective: Configure UART0 for approximately 9600 baud and 8N1, then provide character transmission and reception functions.

#include <LPC21xx.h>

void UART0_Init(void)
{
    /* Select UART0 pin functions */
    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    PINSEL0 &= ~(3U << 2);
    PINSEL0 |=  (1U << 2);

    /* Configure divisor latch */
    U0LCR = 0x83;

    U0DLM = 0x00;
    U0DLL = 0x47;
    U0FDR = 0x83;

    /* Configure 8N1 and clear DLAB */
    U0LCR = 0x03;

    /* Enable and reset FIFOs */
    U0FCR = 0x07;
}

void UART0_TxChar(unsigned char ch)
{
    while ((U0LSR & (1U << 5)) == 0)
    {
    }

    U0THR = ch;
}

unsigned char UART0_RxChar(void)
{
    while ((U0LSR & (1U << 0)) == 0)
    {
    }

    return (unsigned char)U0RBR;
}

void UART0_TxString(const char *str)
{
    while (*str)
    {
        UART0_TxChar((unsigned char)*str);
        str++;
    }
}

int main(void)
{
    unsigned char received;

    UART0_Init();

    UART0_TxString("UART0 Ready\r\n");

    while (1)
    {
        received = UART0_RxChar();
        UART0_TxChar(received);
    }
}

Expected behavior

  • UART0 is configured for approximately 9600 baud.
  • Frame format is 8N1.
  • The startup message is passed to the transmit routine.
  • When a character is received, the program sends the same character back.
This is a blocking polling program. It requires a working UART receive source to progress beyond the receive loop. In Keil simulator-only practice, actual serial input and output depend on the configured UART simulation support.

14. UART Error Conditions

Overrun error

Occurs when a new received character arrives before the previous data can be removed from the receive buffer or FIFO.

Parity error

Occurs when the received parity bit does not match the expected parity calculation.

Framing error

Occurs when the expected stop-bit condition is not detected correctly.

Break condition

Occurs when the RXD input remains in the spacing state for longer than a normal character frame.

ErrorLSR bitTypical cause
Overrun1CPU does not read incoming data in time.
Parity2Parity configuration mismatch or corrupted data.
Framing3Baud-rate mismatch, noise or incorrect frame format.
Break4RXD held LOW for an extended period.

15. UART FIFO and Data Handling

Without FIFO buffering, the CPU must service each received character before the next character overwrites the receive buffer.

With FIFO enabled, multiple characters can be stored temporarily.

Receive FIFO example
Arrival orderStored character
1A
2B
3C
4D

Read order: A → B → C → D

FIFO buffering reduces the frequency of CPU service operations, but software must still read data quickly enough to prevent overflow.

17. Common Mistakes

  • Writing to THR before checking THRE.
  • Reading RBR without checking RDR.
  • Confusing THRE with TEMT.
  • Leaving DLAB enabled while accessing THR, RBR or IER.
  • Ignoring overrun, parity and framing errors.
  • Assuming FCR reset bits remain set after the command.
  • Using polling loops without considering blocking behavior.
  • Assuming FIFO buffering eliminates the need for timely data handling.
  • Assuming a successful register write proves physical serial transmission.

18. Interview Questions and Answers

Q1. What is THR?

THR is the Transmit Holding Register. The CPU writes data into it for serial transmission.

Q2. What is RBR?

RBR is the Receiver Buffer Register. The CPU reads received data from it.

Q3. What is the purpose of LSR?

LSR reports transmitter readiness, receiver data availability and communication error status.

Q4. What does RDR indicate?

It indicates that at least one received character is available.

Q5. What does THRE indicate?

It indicates that the transmit holding register or FIFO is empty and can accept more data.

Q6. What does TEMT indicate?

It indicates that both the transmit holding path and shift register are empty.

Q7. What is the purpose of IER?

IER enables selected UART interrupt sources.

Q8. What is the purpose of IIR?

IIR identifies the highest-priority pending UART interrupt condition.

Q9. What is FIFO?

FIFO is a First-In, First-Out buffer used to temporarily store received and transmitted characters.

Q10. What is an overrun error?

An overrun occurs when incoming data cannot be stored because previously received data has not been read in time.

Q11. What is the difference between THRE and TEMT?

THRE indicates that the holding register or FIFO is empty. TEMT additionally confirms that the transmit shift register is empty.

Q12. Why is polling called a blocking method?

The CPU repeatedly checks a status flag and cannot proceed past the polling loop until the required condition occurs.
