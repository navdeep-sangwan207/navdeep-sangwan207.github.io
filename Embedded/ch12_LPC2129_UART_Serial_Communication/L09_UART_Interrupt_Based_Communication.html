1. Introduction

In polling-based UART communication, the CPU repeatedly checks UART status flags to determine whether data is ready for transmission or reception.

In interrupt-based UART communication, the UART peripheral generates an interrupt when a configured event occurs. The CPU temporarily suspends its current execution, executes an Interrupt Service Routine (ISR), and then returns to the interrupted program.

The LPC2129 UART peripherals can generate interrupts for receive data, transmit holding register status and receiver line errors.

Learning objectives

  • Identify UART interrupt sources.
  • Configure the UART Interrupt Enable Register (IER).
  • Read the Interrupt Identification Register (IIR).
  • Configure the VIC for UART0 interrupts.
  • Write a UART interrupt service routine.
  • Understand receive and transmit buffering.
  • Implement an interrupt-driven UART echo application.

3. UART Interrupt Sources

The UART can generate several types of interrupts. The corresponding interrupt sources are enabled through the IER register.

IER bitInterrupt sourceDescription
0Receive Data AvailableIndicates that received data has reached the configured FIFO trigger level.
1THRE InterruptIndicates that the transmit holding register or transmit FIFO is empty.
2Receive Line StatusIndicates receiver errors or related line-status conditions.
3Modem StatusModem-status interrupt functionality, relevant to UART1.

1. Receive Data Available Interrupt

This interrupt indicates that received characters are available in the receive FIFO. The ISR should read the available characters before the FIFO becomes full.

2. THRE Interrupt

This interrupt indicates that the transmit holding register or FIFO is empty. Software can use this event to provide the next characters for transmission.

3. Receive Line Status Interrupt

This interrupt reports receive-related conditions such as overrun, parity, framing and break errors.

4. Interrupt Enable Register (IER)

The IER register enables or disables individual UART interrupt sources.

BitFunction
0Enable Receive Data Available interrupt.
1Enable THRE interrupt.
2Enable Receive Line Status interrupt.
3Enable Modem Status interrupt where supported.

Enable receive data interrupt

U0IER |= (1U << 0);

Enable transmit holding register empty interrupt

U0IER |= (1U << 1);

Enable receive line status interrupt

U0IER |= (1U << 2);

Enable receive and line status interrupts

U0IER = (1U << 0) | (1U << 2);
IER shares its register address with DLM. Clear DLAB in U0LCR before accessing IER.

5. Interrupt Identification Register (IIR)

IIR identifies the highest-priority pending UART interrupt. The ISR reads IIR to determine which event requires servicing.

The ISR examines the pending bit and identification field to decide which service operation is required.

6. UART Interrupt Connection to VIC

The LPC2129 uses a Vectored Interrupt Controller (VIC) to manage interrupt requests from peripherals.

UART0 and UART1 have separate VIC interrupt source numbers.

The UART peripheral identifies the reason for its interrupt using IIR. The VIC identifies which peripheral requested the processor interrupt.

Important distinction: IIR identifies the UART interrupt condition. VIC identifies and routes the peripheral interrupt request to the ARM7 processor.

7. UART Interrupt Service Routine (ISR)

An Interrupt Service Routine is a special function executed when an interrupt is accepted by the processor.

A UART ISR typically performs the following operations:

  1. Read the UART IIR register.
  2. Identify the interrupt source.
  3. Read received data or provide transmit data as required.
  4. Handle receiver error conditions.
  5. Repeat servicing if another UART interrupt remains pending.
  6. Complete the VIC interrupt using the appropriate acknowledgement operation.

Basic ISR structure

void UART0_ISR(void) __irq
{
    unsigned int status;

    status = U0IIR;

    /* Identify and service UART interrupt */

    VICVectAddr = 0;
}
The exact interrupt function declaration depends on the compiler. The example uses the Keil ARM compiler's __irq convention. Other compilers may require a different ISR attribute or vector arrangement.

8. UART Receive Interrupt

In receive interrupt operation, the CPU does not need to continuously check the RDR flag. The UART generates an interrupt when its configured receive condition occurs.

Receive interrupt sequence

  1. Enable the receive data interrupt in IER.
  2. Configure the UART and FIFO.
  3. Receive characters through RXD.
  4. The UART generates an interrupt when the receive condition is satisfied.
  5. The VIC forwards the request to the CPU.
  6. The ISR reads the received characters from RBR.
  7. The ISR stores the characters in a software buffer.
  8. The main program processes the buffered data.

Receive service example

while (U0LSR & 0x01U)
{
    unsigned char data;

    data = (unsigned char)U0RBR;

    /* Store data in a receive buffer */
}

Checking RDR repeatedly allows the ISR to drain all currently available received characters rather than reading only one byte.

9. UART Transmit Interrupt

The THRE interrupt is useful when software has multiple characters waiting for transmission.

Transmit interrupt sequence

  1. Prepare a software transmit buffer.
  2. Enable the THRE interrupt in IER.
  3. The UART requests an interrupt when the transmit holding path becomes empty.
  4. The ISR writes more characters into the transmit FIFO.
  5. When no more data is available, disable the THRE interrupt.

Transmit service example

if (U0LSR & (1U << 5))
{
    U0THR = transmit_data;
}

In a complete application, the ISR obtains the next character from a transmit queue or ring buffer.

If the THRE interrupt remains enabled while no data is waiting, the UART may repeatedly request service. Disable the THRE interrupt when the software transmit queue becomes empty.

10. Software Ring Buffers

A ring buffer is a circular memory structure used to temporarily store data between an interrupt routine and the main program.

It is particularly useful in UART applications because characters may arrive faster than the main program can process them.

Conceptual circular buffer
Position 0Position 1Position 2Position 3
ABCD

Head points to the next write position.

Tail points to the next read position.

Basic ring buffer operations

  • Producer writes a character at the head position.
  • Head advances to the next position.
  • Consumer reads a character from the tail position.
  • Tail advances to the next position.
  • When the next head position equals tail, the buffer is full.

Using a buffer size that is a power of two allows efficient index wrapping with a bit mask.

11. Complete Interrupt-Driven UART0 Echo Program

Objective: Receive UART0 characters using interrupts, store them in a receive ring buffer, and transmit them back using a transmit ring buffer.

This example uses:

  • UART0 at approximately 9600 baud.
  • 8 data bits, no parity, one stop bit.
  • UART0 VIC source 6.
  • Receive data and receive line status interrupts.
  • THRE interrupt for transmit buffering.
  • 64-byte receive and transmit ring buffers.

Complete Embedded C program

#include <LPC21xx.h>

#define UART0_SOURCE       6U
#define UART_BUFFER_SIZE   64U
#define UART_BUFFER_MASK   (UART_BUFFER_SIZE - 1U)

volatile unsigned char rx_buffer[UART_BUFFER_SIZE];
volatile unsigned char tx_buffer[UART_BUFFER_SIZE];

volatile unsigned int rx_head = 0;
volatile unsigned int rx_tail = 0;

volatile unsigned int tx_head = 0;
volatile unsigned int tx_tail = 0;

volatile unsigned int uart_error_flags = 0;
volatile unsigned int rx_overflow_count = 0;


/* UART0 initialization */
void UART0_Init(void)
{
    /* Configure P0.0 as TXD0 */
    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    /* Configure P0.1 as RXD0 */
    PINSEL0 &= ~(3U << 2);
    PINSEL0 |=  (1U << 2);

    /* Disable UART interrupts during configuration */
    U0IER = 0x00;

    /* Enable divisor latch access */
    U0LCR = 0x83;

    U0DLM = 0x00;
    U0DLL = 0x47;
    U0FDR = 0x83;

    /* 8 data bits, no parity, one stop bit */
    U0LCR = 0x03;

    /* Enable and reset FIFOs */
    U0FCR = 0x07;

    /* Enable receive data and line status interrupts */
    U0IER = (1U << 0) | (1U << 2);
}


/* Add a received character to the RX buffer */
void UART0_StoreReceivedData(unsigned char data)
{
    unsigned int next;

    next = (rx_head + 1U) & UART_BUFFER_MASK;

    if (next != rx_tail)
    {
        rx_buffer[rx_head] = data;
        rx_head = next;
    }
    else
    {
        rx_overflow_count++;
    }
}


/* Add a character to the TX buffer */
void UART0_SendByte(unsigned char data)
{
    unsigned int next;

    do
    {
        next = (tx_head + 1U) & UART_BUFFER_MASK;
    }
    while (next == tx_tail);

    tx_buffer[tx_head] = data;
    tx_head = next;

    /* Enable THRE interrupt */
    U0IER |= (1U << 1);
}


/* UART0 interrupt service routine */
void UART0_ISR(void) __irq
{
    unsigned int iir;
    unsigned int lsr;
    unsigned int count;
    unsigned char data;

    /* Service pending UART interrupt conditions */
    while (1)
    {
        iir = U0IIR;

        /* Bit 0 = 1 means no UART interrupt is pending */
        if (iir & 0x01U)
        {
            break;
        }

        switch (iir & 0x0EU)
        {
            case 0x06U:
                /* Receive Line Status interrupt */
                lsr = U0LSR;

                uart_error_flags |= (lsr & 0x1EU);

                /* Read available data if present */
                while (lsr & 0x01U)
                {
                    data = (unsigned char)U0RBR;
                    UART0_StoreReceivedData(data);

                    lsr = U0LSR;
                }
                break;

            case 0x04U:
            case 0x0CU:
                /* Receive Data Available or Character Timeout */
                while (U0LSR & 0x01U)
                {
                    data = (unsigned char)U0RBR;
                    UART0_StoreReceivedData(data);
                }
                break;

            case 0x02U:
                /* THRE interrupt: fill transmit FIFO */
                count = 0;

                while ((tx_tail != tx_head) &&
                       (count < 16U))
                {
                    U0THR = tx_buffer[tx_tail];

                    tx_tail = (tx_tail + 1U)
                              & UART_BUFFER_MASK;

                    count++;
                }

                /* Disable THRE interrupt when queue is empty */
                if (tx_tail == tx_head)
                {
                    U0IER &= ~(1U << 1);
                }
                break;

            default:
                /* No additional service operation */
                break;
        }
    }

    /* Signal completion of the VIC vectored interrupt */
    VICVectAddr = 0;
}


/* Read one character from the RX buffer */
int UART0_ReadByte(unsigned char *data)
{
    if (rx_tail == rx_head)
    {
        return 0;
    }

    *data = rx_buffer[rx_tail];

    rx_tail = (rx_tail + 1U) & UART_BUFFER_MASK;

    return 1;
}


/* Configure VIC for UART0 */
void UART0_VIC_Init(void)
{
    /* Disable UART0 VIC source while configuring */
    VICIntEnClr = (1U << UART0_SOURCE);

    /* Configure UART0 as an IRQ source */
    VICIntSelect &= ~(1U << UART0_SOURCE);

    /* Install UART0 ISR in vector slot 0 */
    VICVectAddr0 = (unsigned int)UART0_ISR;

    VICVectCntl0 = (1U << 5) | UART0_SOURCE;

    /* Enable UART0 interrupt in VIC */
    VICIntEnable = (1U << UART0_SOURCE);
}


int main(void)
{
    unsigned char received_data;

    UART0_Init();

    UART0_VIC_Init();

    while (1)
    {
        /* Process received characters outside the ISR */
        if (UART0_ReadByte(&received_data))
        {
            /* Echo the received character */
            UART0_SendByte(received_data);
        }
    }
}

Program explanation

Function or variablePurpose
UART0_Init()Configures UART0 pins, baud rate, frame format and interrupts.
UART0_VIC_Init()Configures the VIC to route UART0 interrupts.
UART0_ISR()Services receive, line-status and transmit interrupts.
UART0_StoreReceivedData()Stores incoming characters in the RX ring buffer.
UART0_SendByte()Adds a character to the TX ring buffer and enables THRE interrupt.
UART0_ReadByte()Retrieves a received character from the RX ring buffer.
rx_head / rx_tailManage the receive ring buffer.
tx_head / tx_tailManage the transmit ring buffer.

Expected application behavior

  1. The UART receives a character.
  2. The UART generates a receive interrupt.
  3. The ISR reads the character and stores it in the RX buffer.
  4. The main loop retrieves the character.
  5. The main loop places the character in the TX buffer.
  6. The THRE interrupt sends the character through TXD0.
Important implementation considerations:
  • The example uses a 64-entry ring buffer with one slot reserved to distinguish full from empty; usable capacity is 63 bytes.
  • The main-loop transmit enqueue function waits if the TX buffer is full. It is not suitable for calling from an ISR.
  • The example assumes the Keil ARM compiler's __irq convention.
  • For a production design, review compiler-specific interrupt declarations, atomic access to shared data, interrupt masking requirements, and queue-overflow handling.
  • UART error flags are recorded for diagnosis. A production application should also define an explicit error recovery policy.

12. Interrupt Acknowledgement

Two separate operations are important when servicing a UART interrupt.

1. Service or clear the peripheral condition

The UART interrupt condition must be handled. For example:

  • Read RBR to remove received data from the receive FIFO.
  • Provide more data to THR for a THRE interrupt.
  • Read LSR and handle receiver error conditions.

2. Complete the VIC vectored interrupt

VICVectAddr = 0;

This write indicates completion of the current vectored interrupt service to the VIC.

Clearing or servicing the UART peripheral condition and completing the VIC interrupt are not interchangeable. Both responsibilities must be handled correctly.

13. Character Timeout Interrupt

When FIFO operation is enabled, a receive data available interrupt may be generated when the configured FIFO trigger level is reached.

Consider a receive FIFO trigger level of eight characters. If only three characters arrive and no more data follows, the trigger level may never be reached.

The character timeout interrupt allows software to service data that remains in the receive FIFO after a period of inactivity.

14. UART Interrupt Priority

The UART uses internal interrupt prioritization to determine which pending UART condition should be reported through IIR.

Common priority order:

  1. Receive Line Status.
  2. Receive Data Available.
  3. Character Timeout.
  4. THRE.
  5. Modem Status.

The VIC separately manages interrupt requests from different peripherals. The UART's internal priority and the VIC's interrupt routing are two distinct mechanisms.

15. Best Practices for UART ISR Design

  • Keep interrupt service routines short and predictable.
  • Read received data promptly to prevent FIFO overrun.
  • Use software buffers to separate data reception from application processing.
  • Disable THRE interrupts when no transmit data is waiting.
  • Handle receive errors rather than silently ignoring them.
  • Avoid long delays inside an ISR.
  • Avoid blocking functions inside an ISR.
  • Avoid lengthy formatted output operations such as printf inside an ISR.
  • Use volatile for variables shared between interrupt and main-program contexts where required.
  • Remember that volatile does not guarantee atomicity or mutual exclusion.
  • Review buffer overflow and concurrent-access behavior.
  • Complete VIC interrupt servicing correctly.

17. Common Mistakes

  • Enabling IER interrupts without enabling the corresponding VIC source.
  • Enabling a VIC source without configuring the UART interrupt source.
  • Using the wrong VIC source number for UART0 or UART1.
  • Reading only one byte when several characters are available in the FIFO.
  • Failing to identify the pending interrupt using IIR.
  • Leaving THRE interrupts enabled when the transmit buffer is empty.
  • Failing to service receive line-status errors.
  • Forgetting to complete the VIC interrupt.
  • Performing lengthy operations inside the ISR.
  • Using shared buffer indexes without considering concurrent access.
  • Assuming volatile makes every shared operation atomic.

18. Interview Questions and Answers

Q1. What is interrupt-driven UART communication?

It is a communication method in which the UART generates interrupts when configured transmit or receive events occur.

Q2. What is the purpose of IER?

IER enables or disables individual UART interrupt sources.

Q3. What is the purpose of IIR?

IIR identifies the highest-priority pending UART interrupt condition.

Q4. What is the VIC source number for UART0?

UART0 uses VIC interrupt source number 6 on the LPC2129.

Q5. What is the VIC source number for UART1?

UART1 uses VIC interrupt source number 7.

Q6. What is a UART ISR?

It is an Interrupt Service Routine that handles UART interrupt events such as received data, transmit readiness and receiver errors.

Q7. What is a THRE interrupt?

It indicates that the UART transmit holding path is empty and can accept more data.

Q8. What is a character timeout interrupt?

It indicates that data remains in the receive FIFO without reaching the configured trigger level for the specified timeout period.

Q9. Why are ring buffers used in UART applications?

They temporarily store received or outgoing characters and separate interrupt-level processing from application-level processing.

Q10. Why should an ISR be short?

A short ISR reduces interrupt latency, limits CPU time spent in interrupt context and improves system responsiveness.

Q11. What is the purpose of VICVectAddr = 0?

It signals completion of the current vectored interrupt service to the VIC.

Q12. Does volatile guarantee atomic access?

No. Volatile prevents certain compiler optimizations, but it does not guarantee atomicity, mutual exclusion or thread safety.
