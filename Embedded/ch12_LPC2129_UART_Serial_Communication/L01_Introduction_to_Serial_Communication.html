1. Introduction

Serial communication is a method of transferring digital data between electronic devices by transmitting information sequentially over one or more communication lines.

Instead of sending several data bits simultaneously over separate data wires, serial communication sends individual bits in a sequence.

Serial communication is widely used in embedded systems because it can reduce wiring complexity, simplify hardware connections and support communication over different distances.

Learning objectives

  • Understand how digital data is transmitted serially.
  • Differentiate serial and parallel communication.
  • Understand synchronous and asynchronous communication.
  • Identify common serial communication protocols.
  • Understand the role of UART in embedded systems.
  • Recognize serial communication applications of LPC2129.

2. What Is Serial Communication?

Serial communication transfers data one bit at a time over a communication channel.

A transmitter converts parallel digital data inside a device into a serial bit stream. A receiver collects the incoming bits and reconstructs the original data.

The communication channel may use electrical signals over wires, a differential pair, optical signals or a wireless link, depending on the communication standard.

3. How Serial Data Is Transmitted

Digital information is represented using binary digits: 0 and 1. Serial communication sends these bits in an ordered sequence.

Example: transmitting one byte

Consider the 8-bit binary value: 

Data = 10110010

A serial transmitter sends the bits one after another according to the protocol's timing and framing rules.

Bit 7 → Bit 0 in this illustrative sequence

The actual transmission order depends on the protocol. UART commonly sends the least significant data bit first. Other serial protocols can use different bit-order conventions.

4. Serial Communication vs Parallel Communication

Serial communication

Data bits are transmitted sequentially over a serial data path.

Parallel communication

Multiple data bits are transmitted simultaneously using separate data lines.

Feature Serial Communication Parallel Communication
Data transfer Bits sent sequentially Multiple bits sent simultaneously
Data lines Usually fewer data lines Usually more data lines
Wiring Generally simpler Generally more complex
Distance considerations Can be suitable for longer links depending on the physical interface Timing skew can become a significant limitation
Examples UART, SPI, I2C Parallel memory bus, older printer interfaces
Serial communication is not always slower than parallel communication. Modern high-speed serial interfaces can achieve very high data rates. The actual performance depends on protocol design, clock rate, physical interface and implementation.

5. Advantages of Serial Communication

  • Requires fewer communication wires in many interfaces.
  • Reduces connector pin requirements.
  • Can reduce wiring complexity and cost.
  • Suitable for communication between embedded devices.
  • Supports a wide range of communication distances and speeds.
  • Can use error detection and control mechanisms depending on the protocol.
  • Can support point-to-point and multi-device communication arrangements.

6. Limitations of Serial Communication

  • Data bits are transmitted sequentially in a serial stream.
  • Communication speed depends on protocol timing and interface limits.
  • Transmitter and receiver must follow compatible communication settings.
  • Some protocols require additional control or clock signals.
  • Signal integrity can become a problem at high data rates or long distances.
  • Protocol-specific framing and synchronization must be handled correctly.

7. Types of Serial Communication

Serial communication can be classified according to its clocking method and data transfer arrangement.

7.1 Synchronous Serial Communication

In synchronous communication, the transmitter and receiver use a shared timing reference, commonly a clock signal, to coordinate data transfer.

Master / Clock Source
↓ Clock Signal
Receiver / Slave

Data transfer is synchronized with clock timing.

Examples:

  • SPI
  • I2C

7.2 Asynchronous Serial Communication

In asynchronous communication, a separate clock signal is not normally transmitted along with each data frame. Both devices agree on timing parameters such as baud rate and use framing information to identify individual characters or data units.

Transmitter
↓ Serial Data Line
Receiver

Both devices use compatible baud-rate and frame settings.

Example: UART.

UART is commonly used for asynchronous serial communication. UART does not require a separate clock wire between the communicating devices.

8. Simplex, Half-Duplex and Full-Duplex Communication

8.1 Simplex

8.2 Half-Duplex

Data can flow in both directions, but only one direction is active at a time.

8.3 Full-Duplex

Data can be transmitted and received simultaneously.

A typical UART connection can support full-duplex communication using separate transmit and receive lines.

9. Common Serial Communication Protocols

Protocol Clock Typical Signals Common Applications
UART Asynchronous TXD, RXD and common reference ground Debugging, terminals, module communication
SPI Synchronous SCLK, MOSI, MISO, CS Displays, memory and sensors
I2C Synchronous SCL, SDA Low-speed peripheral communication
CAN Clock is not shared as a separate bus signal CAN_H, CAN_L Automotive and industrial networks
UART, SPI and I2C are commonly used for communication between embedded devices. CAN provides a message-based network protocol with arbitration and error handling.

10. Introduction to UART

UART stands for Universal Asynchronous Receiver/Transmitter. It is a hardware communication peripheral that converts parallel data from a processor into a serial stream for transmission and converts received serial data back into parallel data.

Basic UART block diagram

CPU / Embedded C Application
↓ Parallel Data
UART Transmitter
↓ Serial Data – TXD
Communication Channel
↓ Serial Data – RXD
UART Receiver
↓ Parallel Data
CPU / Embedded C Application

UART functions

  • Parallel-to-serial data conversion.
  • Serial-to-parallel data conversion.
  • Start and stop bit handling.
  • Optional parity generation and checking.
  • Baud-rate timing configuration.
  • Transmit and receive status reporting.
  • Optional interrupt-driven data handling.

11. UART Communication Lines

A basic UART connection uses separate transmit and receive signal lines. The devices also require a common electrical reference, normally ground.

UART connection between two devices
Device A Device B
TXD RXD
RXD TXD
GND GND

The transmitter of one device is connected to the receiver of the other device. The receive and transmit lines are crossed.

UART logic-level signals are not automatically compatible with RS-232 voltage levels. A suitable level-shifting transceiver is required when connecting a microcontroller UART to an RS-232 interface.

12. Applications of Serial Communication

  • Microcontroller-to-PC communication.
  • Embedded system debugging.
  • GPS receiver communication.
  • Bluetooth and wireless modules with UART interfaces.
  • Sensor and actuator modules.
  • Industrial automation equipment.
  • Automotive electronic control systems.
  • Data logging and monitoring systems.
  • Communication between embedded controllers.

13. Serial Communication in LPC2129

The LPC2129 is an ARM7-based microcontroller that provides two UART peripherals:

Peripheral Transmit Pin Receive Pin
UART0 P0.0 – TXD0 P0.1 – RXD0
UART1 P0.8 – TXD1 P0.9 – RXD1

The relevant pin functions must be selected using the PINSEL registers before the UART peripheral signals can be used on those pins.

UART0 and UART1 can be configured independently for baud rate, frame format, transmit and receive operation.

The following lessons examine the LPC2129 UART0 and UART1 architecture, pin configuration, baud-rate generation and programming.

14. Serial Communication Design Considerations

Baud rate compatibility

Both devices must use compatible baud-rate settings. A significant mismatch can cause incorrect reception.

Frame format

Both devices should agree on the number of data bits, parity setting and number of stop bits.

Electrical compatibility

Confirm that the signal voltage levels and interface standards are compatible.

Signal integrity

Wiring quality, grounding, noise and cable characteristics can affect communication reliability.

Data handling

Select polling or interrupt-driven communication according to the application's timing and processing requirements.

15. Common Mistakes

  • Connecting TXD to TXD instead of crossing TXD and RXD.
  • Forgetting to connect a common ground.
  • Using mismatched baud-rate settings.
  • Using incompatible frame formats.
  • Failing to configure the UART pin functions.
  • Assuming UART logic levels are the same as RS-232 levels.
  • Ignoring receive errors and status flags.
  • Assuming every serial protocol uses the same data framing.

16. Interview Questions and Answers

Q1. What is serial communication?

It is a method of transmitting digital data sequentially over a communication channel.

Q2. What is the difference between serial and parallel communication?

Serial communication sends bits sequentially, while parallel communication sends multiple bits simultaneously over separate lines.

Q3. What is UART?

UART stands for Universal Asynchronous Receiver/Transmitter. It handles asynchronous serial data transmission and reception.

Q4. What is synchronous communication?

It is communication in which transmitter and receiver coordinate data transfer using a shared timing reference, commonly a clock signal.

Q5. What is asynchronous communication?

It is communication that does not normally transmit a separate clock signal. Timing and frame boundaries are established using agreed settings and framing information.

Q6. What is full-duplex communication?

It allows data to be transmitted and received simultaneously.

Q7. What is the purpose of TXD?

TXD is the transmit data signal used to send serial data.

Q8. What is the purpose of RXD?

RXD is the receive data signal used to receive serial data.

Q9. How many UART peripherals are available in LPC2129?

LPC2129 provides two UART peripherals: UART0 and UART1.

Q10. Why is a common ground required?

It provides a shared electrical reference for single-ended UART signal voltages.
