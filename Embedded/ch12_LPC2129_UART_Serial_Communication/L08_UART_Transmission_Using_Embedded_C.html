1. Introduction

UART communication can be implemented in Embedded C by configuring the UART registers and writing functions to transmit and receive serial data.

The LPC2129 provides two UART peripherals:

  • UART0
  • UART1

Each UART can operate independently and supports asynchronous serial communication.

Learning objectives
  • Configure UART0 pins and registers.
  • Initialize UART baud rate and frame format.
  • Transmit a single character.
  • Transmit a string.
  • Receive a character.
  • Implement UART echo communication.
  • Understand blocking and polling-based communication.
  • Debug UART programs in Keil uVision.

2. Hardware and Pin Configuration

UART0 uses the following LPC2129 pins when the corresponding alternate functions are selected through PINSEL0.

PinUART functionDirection
P0.0TXD0Output
P0.1RXD0Input

UART1 uses:

PinUART functionDirection
P0.8TXD1Output
P0.9RXD1Input
UART0 communication connection

LPC2129 TXD0 (P0.0) → External device RX

LPC2129 RXD0 (P0.1) ← External device TX

LPC2129 GND ↔ External device GND

TX and RX connections are crossed between two communicating devices. Ensure that both devices use compatible logic voltage levels. UART logic signals are not directly equivalent to RS-232 voltage levels.

3. UART Configuration Sequence

Before transmitting or receiving data, configure the UART peripheral.

  1. Select the UART pin functions using PINSEL0.
  2. Set DLAB to access the divisor registers.
  3. Configure DLL and DLM.
  4. Configure the fractional divider register FDR when required.
  5. Clear DLAB.
  6. Configure the data frame using LCR.
  7. Enable FIFO if required.
  8. Use THR and RBR for transmission and reception.
Project clock configuration: CCLK = 60 MHz and PCLK = 15 MHz. UART baud-rate calculations must use the peripheral clock, not the CPU clock.

4. UART0 Initialization Function

The following function configures UART0 for approximately 9600 baud, 8 data bits, no parity and one stop bit (8N1).

#include <LPC21xx.h>

void UART0_Init(void)
{
    /* Configure P0.0 as TXD0 */
    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    /* Configure P0.1 as RXD0 */
    PINSEL0 &= ~(3U << 2);
    PINSEL0 |=  (1U << 2);

    /* Enable access to baud-rate divisor registers */
    U0LCR = 0x83;

    /* Divisor configuration */
    U0DLM = 0x00;
    U0DLL = 0x47;

    /* Fractional divider:
       MULVAL = 8, DIVADDVAL = 3 */
    U0FDR = 0x83;

    /* Configure 8N1 and clear DLAB */
    U0LCR = 0x03;

    /* Enable and reset transmit/receive FIFOs */
    U0FCR = 0x07;
}

Register explanation

RegisterPurposeConfigured value
PINSEL0Selects UART0 pin functionsP0.0 and P0.1 set to UART0
U0LCRLine control and DLAB0x83, then 0x03
U0DLLDivisor latch low byte0x47
U0DLMDivisor latch high byte0x00
U0FDRFractional divider0x83
U0FCRFIFO control0x07
With PCLK = 15 MHz, DLL = 71, DLM = 0, MULVAL = 8 and DIVADDVAL = 3, the calculated baud rate is approximately 9603 baud. FCR reset bits are command bits and self-clear.

5. Character Transmission

A character is transmitted by writing its byte value into the UART transmit holding register (THR).

Algorithm

  1. Read the UART line status register.
  2. Check THRE (LSR bit 5).
  3. Wait until the transmit holding path is ready.
  4. Write the character to THR.

Embedded C function

void UART0_TxChar(unsigned char ch)
{
    while ((U0LSR & (1U << 5)) == 0)
    {
        /* Wait until transmit holding register is empty */
    }

    U0THR = ch;
}

Function call

UART0_TxChar('A');

This sends the character A through the UART0 transmit path.

6. String Transmission

A string consists of multiple characters terminated by the null character '\0'. A string transmission function sends each character sequentially.

Embedded C function

void UART0_TxString(const char *str)
{
    while (*str != '\0')
    {
        UART0_TxChar((unsigned char)*str);
        str++;
    }
}

Function call

UART0_TxString("Hello LPC2129");

Transmission sequence

H → e → l → l → o → Space → L → P → C → 2 → 1 → 2 → 9

Each character is transmitted as a separate UART frame.

7. Adding a New Line

Serial terminals commonly use carriage return and line feed characters to move to the beginning of the next line.

UART0_TxString("Welcome");
UART0_TxChar('\r');
UART0_TxChar('\n');
UART0_TxString("Embedded Systems");

Expected terminal layout:

Welcome
Embedded Systems

The characters '\r' and '\n' are control characters, not ordinary printable letters.

8. Character Reception

The UART receiver stores incoming data in the receive buffer or FIFO. The CPU checks the RDR flag before reading RBR.

Algorithm

  1. Read U0LSR.
  2. Check bit 0 (RDR).
  3. Wait until received data is available.
  4. Read the character from U0RBR.

Embedded C function

unsigned char UART0_RxChar(void)
{
    while ((U0LSR & (1U << 0)) == 0)
    {
        /* Wait until data is received */
    }

    return (unsigned char)U0RBR;
}
This is a blocking function. If no character arrives, the CPU remains inside the polling loop. A non-blocking or interrupt-driven design is preferable when the application must perform other tasks concurrently.

9. UART Echo Program

An echo application receives a character and transmits the same character back to the sender.

Complete program

#include <LPC21xx.h>

void UART0_Init(void)
{
    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    PINSEL0 &= ~(3U << 2);
    PINSEL0 |=  (1U << 2);

    U0LCR = 0x83;
    U0DLM = 0x00;
    U0DLL = 0x47;
    U0FDR = 0x83;
    U0LCR = 0x03;
    U0FCR = 0x07;
}

void UART0_TxChar(unsigned char ch)
{
    while ((U0LSR & (1U << 5)) == 0)
    {
    }

    U0THR = ch;
}

unsigned char UART0_RxChar(void)
{
    while ((U0LSR & (1U << 0)) == 0)
    {
    }

    return (unsigned char)U0RBR;
}

int main(void)
{
    unsigned char data;

    UART0_Init();

    while (1)
    {
        data = UART0_RxChar();
        UART0_TxChar(data);
    }
}

Expected behavior

If the sender transmits the character A, the receiver reads A and sends A back.

Echo communication

External terminal → UART0 RXD → LPC2129

LPC2129 → UART0 TXD → External terminal

10. Transmitting a Number as Text

UART transmits bytes. If an integer must be displayed as decimal text, it must first be converted into ASCII characters.

Example using sprintf

#include <stdio.h>

void Display_Number(void)
{
    char buffer[20];
    unsigned int temperature = 125;

    sprintf(buffer, "Value = %u\r\n", temperature);

    UART0_TxString(buffer);
}

Expected text:

Value = 125
Some embedded projects avoid sprintf because it can increase code size and RAM usage. For constrained systems, a small integer-to-string conversion function may be more suitable.

13. Common UART Programming Errors

  • Using CCLK instead of PCLK in the baud-rate calculation.
  • Incorrect DLL, DLM or FDR configuration.
  • Forgetting to clear DLAB after configuring the divisor.
  • Incorrect PINSEL0 configuration.
  • Writing to THR without checking THRE.
  • Reading RBR without checking RDR.
  • Using incompatible baud rates or frame formats at the two endpoints.
  • Connecting TX to TX and RX to RX instead of crossing the signals.
  • Connecting MCU UART logic directly to RS-232 voltage levels.
  • Ignoring blocking behavior in receive functions.

16. Interview Questions and Answers

Q1. How do you initialize UART0?

Select the TXD0/RXD0 pin functions, configure DLL/DLM and FDR, set the frame format in LCR, clear DLAB and configure FIFO if required.

Q2. Why is PCLK used for UART baud-rate calculation?

The UART peripheral uses the peripheral clock as its input clock for baud-rate generation.

Q3. How do you transmit a character?

Wait for LSR bit 5 (THRE), then write the character to THR.

Q4. How do you receive a character?

Wait for LSR bit 0 (RDR), then read the received byte from RBR.

Q5. What is a UART echo program?

It receives a character and transmits the same character back to the sender.

Q6. Why is a null character used in string transmission?

It marks the end of a null-terminated C string.

Q7. What is the purpose of PINSEL0?

It selects alternate functions for LPC2129 Port 0 pins, including UART0 and UART1 functions.

Q8. Why should a blocking receive function be used carefully?

Because the CPU remains in the receive polling loop until data becomes available.

Q9. What is the difference between polling and interrupt-driven UART?

Polling repeatedly checks status flags, while interrupt-driven UART uses interrupt requests to notify the CPU of events.

Q10. Why is UART useful for debugging?

It provides a simple serial channel for sending diagnostic messages and receiving commands.
