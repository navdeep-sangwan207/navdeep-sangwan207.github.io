1. Introduction

The LPC2129 microcontroller contains two independent Universal Asynchronous Receiver/Transmitter peripherals:

  • UART0
  • UART1

Both peripherals support asynchronous serial communication. They allow the microcontroller to exchange data with computers, serial terminals, GPS receivers, modems and other compatible devices.

Each UART has its own transmit and receive circuitry, baud-rate generator, control registers and status registers.

Learning objectives
  • Understand the UART0 and UART1 architecture.
  • Identify the major internal functional blocks.
  • Understand the UART register organization.
  • Identify UART0 and UART1 pin assignments.
  • Understand transmit and receive data paths.
  • Understand interrupt and FIFO support.
  • Compare UART0 and UART1.

3.1 CPU / Bus Interface

The CPU communicates with the UART through memory-mapped registers. Software reads status and received data, writes transmit data, and configures UART operation.

3.2 Transmit FIFO

The transmit FIFO temporarily stores data bytes waiting to be transmitted. This allows the CPU to supply multiple bytes without waiting for every individual bit to be sent.

3.3 Receive FIFO

The receive FIFO stores incoming bytes until software reads them. FIFO buffering reduces the need for the CPU to service every character immediately.

3.4 Shift Registers

The transmit shift register converts parallel data into a serial bit stream. The receive shift register collects serial bits and reconstructs a data character.

3.5 Baud-Rate Generator

The baud-rate generator derives the serial bit timing from the peripheral clock and the programmed divisor configuration.

3.6 Interrupt Logic

The interrupt logic generates interrupt requests for supported UART events, such as receive data availability, transmit holding-register status and line-status conditions.

4. UART0 Pin Configuration

UART0 uses the following LPC2129 pins:

PinFunctionDirection
P0.0TXD0Output
P0.1RXD0Input

These pins are multiplexed with GPIO and other peripheral functions. The appropriate PINSEL0 fields must be configured before using them as UART0 signals.

UART0 pin selection

#include <LPC21xx.h>

void UART0_Pin_Init(void)
{
    /* P0.0 = TXD0, function 01 */
    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    /* P0.1 = RXD0, function 01 */
    PINSEL0 &= ~(3U << 2);
    PINSEL0 |=  (1U << 2);
}

This configures the pin-function selections for UART0. It does not configure the baud rate or enable data transmission.

5. UART1 Pin Configuration

UART1 uses these primary serial data pins:

PinFunctionDirection
P0.8TXD1Output
P0.9RXD1Input

UART1 pins are configured through the appropriate PINSEL0 fields.

UART1 pin selection

#include <LPC21xx.h>

void UART1_Pin_Init(void)
{
    /* P0.8 = TXD1, function 01 */
    PINSEL0 &= ~(3U << 16);
    PINSEL0 |=  (1U << 16);

    /* P0.9 = RXD1, function 01 */
    PINSEL0 &= ~(3U << 18);
    PINSEL0 |=  (1U << 18);
}
UART1 also supports additional signals for modem-control and RS-485-related operation. Do not assume that every optional signal is available on every package pin without checking the LPC2129 pin-function table.

6. UART Register Organization

Both UART peripherals use a collection of memory-mapped registers for configuration, data transfer and status monitoring.

RegisterPurpose
RBR – Receiver Buffer RegisterProvides received data to the CPU when read.
THR – Transmit Holding RegisterAccepts data from the CPU for transmission.
DLL – Divisor Latch LowStores the low byte of the baud-rate divisor.
DLM – Divisor Latch HighStores the high byte of the baud-rate divisor.
IER – Interrupt Enable RegisterEnables selected UART interrupt sources.
IIR – Interrupt Identification RegisterIdentifies the highest-priority pending UART interrupt.
FCR – FIFO Control RegisterControls FIFO enable, reset and trigger settings.
LCR – Line Control RegisterConfigures data length, stop bits, parity and divisor access.
LSR – Line Status RegisterReports transmit, receive and error status.
SCR – Scratch Pad RegisterProvides temporary general-purpose storage.
ACR – Auto-baud Control RegisterControls auto-baud functionality.
FDR – Fractional Divider RegisterProvides fractional baud-rate adjustment.
TER – Transmit Enable RegisterControls the transmitter enable function.

UART1 additionally provides registers for its extended modem-control and RS-485-related functionality.

The same register names are used for both UART peripherals, with the peripheral prefix identifying the instance. For example, UART0 uses U0LCR and UART1 uses U1LCR.

7. Transmit Data Path

The transmit path moves data from the CPU to the serial TXD pin.

UART Transmit Data Flow

CPU
→
THR / FIFO
→
Shift Register
→
TXD Pin
  1. The CPU writes a data byte into the transmit holding register.
  2. The byte enters the transmit FIFO when FIFO operation is enabled.
  3. The UART transfers the byte to its transmit shift register.
  4. The UART adds the configured frame bits.
  5. The serial data is transmitted through TXD.
  6. The UART updates its transmit status flags.

Transmit status

The Line Status Register provides two important transmit status indicators:

  • THRE (Transmit Holding Register Empty): indicates that the transmit holding register or FIFO has become empty.
  • TEMT (Transmitter Empty): indicates that both the transmit holding register/FIFO and transmit shift register are empty.
THRE does not necessarily mean that the final stop bit has already left the TXD pin. TEMT is the stronger indication that the transmitter has completed sending pending data.

8. Receive Data Path

The receive path transfers serial data from RXD into the CPU-accessible receive buffer.

UART Receive Data Flow

RXD Pin
→
Shift Register
→
RBR / FIFO
→
CPU
  1. The UART monitors the RXD input line.
  2. The receiver detects the start bit.
  3. Incoming data bits are sampled according to the configured baud rate.
  4. The UART checks the configured parity and stop-bit conditions.
  5. The reconstructed character is placed in the receive buffer or FIFO.
  6. The CPU reads the received character.

Receive status

The Line Status Register provides status information such as:

  • RDR – Receiver Data Ready.
  • OE – Overrun Error.
  • PE – Parity Error.
  • FE – Framing Error.
  • BI – Break Interrupt.

9. FIFO Architecture

UART0 and UART1 provide transmit and receive FIFOs to improve data handling efficiency.

Benefits of FIFO

  • Temporarily stores multiple received bytes.
  • Allows the CPU to write multiple bytes for transmission.
  • Reduces interrupt frequency in suitable applications.
  • Helps handle short periods of CPU latency.

Each FIFO is 16 bytes deep.

FIFO control

The FIFO Control Register is used to:

  • Enable FIFO operation.
  • Reset the receive FIFO.
  • Reset the transmit FIFO.
  • Select the receive FIFO trigger level.
/* Conceptual UART FIFO configuration */

U0FCR = 0x07;

/*
Bit 0: FIFO enable
Bit 1: Reset receive FIFO
Bit 2: Reset transmit FIFO

Reset bits are self-clearing.
*/
This example enables the FIFO and requests both FIFO resets. The reset bits do not remain set as normal configuration bits. The same general approach applies to UART1 using its corresponding register.

10. Baud-Rate Generator

The UART baud-rate generator derives serial timing from the peripheral clock.

It uses divisor latch registers and a fractional divider to achieve the desired baud rate.

Relevant registers

  • DLL – Divisor Latch Low.
  • DLM – Divisor Latch High.
  • FDR – Fractional Divider Register.
  • LCR – Controls access to divisor latch registers.

The divisor latch registers share register addresses with other UART registers. The DLAB bit in LCR controls access to the divisor latches.

/* Enable divisor latch access */
U0LCR |= (1U << 7);

/* DLL and DLM can now be accessed */

/* Disable divisor latch access */
U0LCR &= ~(1U << 7);

The actual divisor calculation and fractional-divider configuration are covered in Lesson 05: UART Baud Rate Generation.

11. UART Interrupt Architecture

UART peripherals can generate interrupt requests when selected events occur.

Interrupt conditionPurpose
Receive Data AvailableNotifies the CPU that received data is available.
Receive Line StatusReports receive errors and line-status conditions.
Transmit Holding Register EmptyNotifies the CPU that more transmit data can be supplied.
Character TimeoutIndicates that data remains in the receive FIFO without new incoming data for the specified interval.

The Interrupt Enable Register controls individual UART interrupt sources. The Interrupt Identification Register reports the pending interrupt type.

The UART interrupt request is connected to the LPC2129 Vectored Interrupt Controller. The interrupt source identifiers are:

  • UART0: VIC source 6.
  • UART1: VIC source 7.
UART interrupt programming, interrupt identification and ISR handling are covered in Lesson 09 of this chapter. The VIC architecture was covered in Chapter 11.

Can UART0 and UART1 operate simultaneously?

Yes. Both UART peripherals can operate independently, provided their pin functions, clock configuration and communication settings are correctly configured.

13. Applications of UART0 and UART1

  • UART0 for communication with a PC serial terminal.
  • UART1 for communication with another embedded controller.
  • Debugging and diagnostic messages.
  • Communication with GPS receivers and serial sensors.
  • Industrial serial communication equipment.
  • Modem-control applications using supported UART1 signals.
  • RS-485-related communication using UART1 support and external interface hardware.
An RS-485 physical interface requires an external RS-485 transceiver. UART1's RS-485-related controller features do not themselves provide the differential electrical bus interface.

14. Practical Program – UART0 Pin Configuration

Objective: Configure the LPC2129 P0.0 and P0.1 pins for UART0 operation.

#include <LPC21xx.h>

int main(void)
{
    /* Configure P0.0 as TXD0 */
    PINSEL0 &= ~(3U << 0);
    PINSEL0 |=  (1U << 0);

    /* Configure P0.1 as RXD0 */
    PINSEL0 &= ~(3U << 2);
    PINSEL0 |=  (1U << 2);

    while (1)
    {
        /* UART0 pin configuration remains active */
    }
}

Expected result

  • PINSEL0 bits [1:0] select the TXD0 function on P0.0.
  • PINSEL0 bits [3:2] select the RXD0 function on P0.1.
  • The program remains in the infinite loop.

This program configures pin multiplexing only. It does not initialize the baud rate or transmit data.

17. Common Mistakes

  • Using UART0 pin assignments while configuring UART1.
  • Forgetting to configure PINSEL0.
  • Confusing UART0 and UART1 register prefixes.
  • Assuming the baud rate is configured automatically.
  • Ignoring the DLAB bit when accessing divisor latch registers.
  • Reading the transmit holding register instead of the receive buffer register.
  • Assuming THRE means the entire frame has left the TXD pin.
  • Ignoring receive FIFO overrun conditions.
  • Assuming UART1 can connect directly to an RS-485 bus without a transceiver.

18. Interview Questions and Answers

Q1. How many UART peripherals are available in LPC2129?

Two: UART0 and UART1.

Q2. What are the UART0 TXD and RXD pins?

P0.0 is TXD0 and P0.1 is RXD0.

Q3. What are the UART1 TXD and RXD pins?

P0.8 is TXD1 and P0.9 is RXD1.

Q4. What is the purpose of a transmit FIFO?

It temporarily stores data bytes waiting for transmission.

Q5. What is the purpose of a receive FIFO?

It stores received bytes until the CPU reads them.

Q6. What is the function of the LSR?

It provides transmitter and receiver status, including data-ready and error information.

Q7. What is the function of the IER?

It enables selected UART interrupt sources.

Q8. What is the function of the IIR?

It identifies the pending UART interrupt condition.

Q9. What is DLAB?

DLAB is the Divisor Latch Access Bit in LCR. It controls access to the baud-rate divisor latch registers.

Q10. Which VIC interrupt sources are used by UART0 and UART1?

UART0 uses source 6 and UART1 uses source 7.

Q11. Can UART0 and UART1 work simultaneously?

Yes, when both peripherals and their pin configurations are initialized correctly.

Q12. Does UART1 provide RS-485-related functionality?

Yes. UART1 includes RS-485-related support, but an external RS-485 transceiver is still required for the physical bus interface.

21. Lesson Summary

  • LPC2129 provides UART0 and UART1.
  • UART0 uses P0.0 TXD0 and P0.1 RXD0.
  • UART1 uses P0.8 TXD1 and P0.9 RXD1.
  • Both peripherals have independent transmit and receive paths.
  • Both provide 16-byte transmit and receive FIFOs.
  • THR and RBR handle transmit and receive data.
  • DLL, DLM and FDR support baud-rate generation.
  • LCR configures the UART frame format and divisor access.
  • LSR reports line and data-transfer status.
  • UART0 and UART1 use VIC sources 6 and 7 respectively.
  • UART1 provides additional modem-control and RS-485-related functionality.
