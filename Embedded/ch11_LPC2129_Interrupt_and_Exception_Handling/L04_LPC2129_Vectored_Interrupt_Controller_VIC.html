1. Introduction

The LPC2129 microcontroller contains a Vectored Interrupt Controller (VIC) that manages interrupt requests generated by internal peripherals and external interrupt sources.

The VIC receives interrupt requests, determines which enabled interrupt should be forwarded to the ARM7 processor, and supports vectored handling of IRQ sources.

Without an interrupt controller, software would need to identify and service interrupt sources through additional handling logic. The VIC provides hardware support for organizing this process.

Learning objectives
  • Understand the purpose of the LPC2129 VIC.
  • Study the VIC architecture.
  • Understand interrupt source identification.
  • Differentiate vectored and non-vectored IRQ handling.
  • Understand interrupt slots and priority.
  • Learn the role of FIQ selection.
  • Understand how the VIC communicates with ARM7.

2. What Is a Vectored Interrupt Controller?

A Vectored Interrupt Controller is a hardware block that manages interrupt requests and helps the processor identify the appropriate interrupt service routine.

In the LPC2129, the VIC supports multiple interrupt sources and provides hardware assistance for IRQ prioritization and vectored interrupt dispatch.

Main functions

  • Receive interrupt requests from peripherals.
  • Maintain interrupt status information.
  • Enable or disable individual interrupt sources.
  • Support FIQ source selection.
  • Provide programmable vectored IRQ slots.
  • Provide a default vector for non-vectored IRQ handling.
  • Signal interrupt requests to the ARM7 processor.

3. Why Is the VIC Required?

An embedded application may use several peripherals simultaneously. For example, a timer may generate periodic events while UART receives serial data and external interrupt pins detect hardware events.

These events may occur at different times. The processor needs a reliable mechanism to identify and service the appropriate interrupt source.

Example interrupt sources

Peripheral Possible interrupt event
Timer 0 Timer match event.
Timer 1 Timer match event.
UART0 Transmit or receive event.
UART1 Transmit or receive event.
External Interrupt Configured external pin event.
ADC Conversion completion event.
A peripheral must generate an interrupt request and its interrupt source must be configured correctly. Merely enabling a VIC source does not create a peripheral event.

5. Interrupt Sources in LPC2129

The LPC2129 VIC supports up to 32 interrupt request sources, identified by source numbers from 0 to 31.

Each source has an associated bit in relevant VIC status and control registers. The source number is used when configuring the interrupt controller.

6. IRQ and FIQ Handling by VIC

The VIC can classify interrupt sources into IRQ or FIQ handling.

IRQ

IRQ is the normal interrupt request mechanism. The VIC can use its vectored interrupt slots to select an IRQ handler.

FIQ

FIQ is designed for fast interrupt handling. The VIC provides an interrupt selection mechanism to assign selected interrupt sources to FIQ.

Feature IRQ FIQ
Purpose General interrupt handling Fast interrupt handling
VIC support Vectored slots and default vector Selected FIQ sources
Processor mode IRQ mode FIQ mode
ARM7 vector 0x00000018 0x0000001C

7. Vectored IRQ Handling

Vectored interrupt handling allows the VIC to provide an address associated with the selected interrupt handler.

The LPC2129 provides 16 vectored IRQ slots. Each slot has a control register for source assignment and an address register for the handler address.

Vectored IRQ process

  1. A peripheral generates an interrupt request.
  2. The VIC recognizes the enabled request.
  3. The VIC determines whether the source is assigned to IRQ or FIQ.
  4. For an eligible vectored IRQ source, the VIC selects a slot according to its configured priority.
  5. The processor accepts the IRQ exception.
  6. The IRQ vector code obtains the VIC-provided handler address.
  7. The corresponding interrupt service routine executes.
  8. The handler services the peripheral and completes VIC interrupt handling.

8. Non-Vectored IRQ Handling

Non-vectored IRQ handling uses a common handler rather than dispatching directly through one of the 16 vectored IRQ slots.

The common handler identifies the pending interrupt source and calls the appropriate service routine.

Example concept

void IRQ_Handler(void)
{
    /*
       Identify the active interrupt source.
       Service the appropriate peripheral.
       Clear or acknowledge its interrupt.
       Complete VIC interrupt handling.
    */
}
This is a conceptual C outline, not a complete ARM7 IRQ entry routine. A real IRQ handler also requires correct exception entry, compiler-specific interrupt conventions or assembly wrapper code, and VIC completion handling.

The VICVectCntl registers contain a slot enable bit and an interrupt source number. The corresponding VICVectAddr register stores the handler address for that slot.

Slot number and interrupt source number are different concepts. A slot is a programmable priority position; a source number identifies a peripheral interrupt.

10. VIC Default Vector

The VIC includes a default vector address register, VICDefVectAddr.

It provides a handler address for IRQ requests that are not dispatched through an enabled vectored IRQ slot.

Why is it useful?

  • Provides a common fallback IRQ handler.
  • Supports non-vectored interrupt processing.
  • Allows software to identify and service pending sources.
  • Helps avoid undefined behavior when an IRQ is not assigned to an active vector slot.

11. VIC Register Overview

The VIC is controlled through memory-mapped registers. These registers are used to inspect status, enable sources, assign priorities, and configure handler addresses.

Register Purpose
VICIRQStatus Shows active IRQ request status.
VICFIQStatus Shows active FIQ request status.
VICRawIntr Shows raw interrupt request status.
VICIntSelect Selects IRQ or FIQ classification for interrupt sources.
VICIntEnable Enables interrupt sources.
VICIntEnClr Disables selected interrupt sources.
VICVectAddr Provides the currently selected vectored IRQ handler address and is used for VIC interrupt completion.
VICDefVectAddr Stores the default IRQ handler address.
VICVectAddr0–15 Store vectored IRQ handler addresses.
VICVectCntl0–15 Configure vectored IRQ slot enable and source selection.
Detailed register fields, bit positions, and programming examples are covered in the next lesson: VIC Interrupt Control Registers.

12. Basic VIC Configuration Concept

A typical vectored interrupt configuration requires several steps:

  1. Configure the peripheral to generate its interrupt event.
  2. Clear any stale peripheral interrupt status.
  3. Write the ISR address into a vector address register.
  4. Configure the associated vector control register with the source number and enable bit.
  5. Enable the source in the VIC.
  6. Ensure the processor IRQ mask permits IRQ handling.
  7. Service the interrupt and complete VIC handling in the ISR.

Illustrative configuration skeleton

#include <LPC21xx.h>

/*
 * Conceptual example only.
 * Replace the source number and peripheral
 * configuration with verified LPC2129 values.
 */

#define TIMER0_SOURCE 4U

void Timer0_ISR(void);

void VIC_Setup_Concept(void)
{
    /*
     * 1. Configure Timer0 peripheral.
     * 2. Clear pending Timer0 interrupt status.
     * 3. Configure a VIC vector slot.
     * 4. Store Timer0_ISR address.
     * 5. Enable Timer0 interrupt source.
     *
     * Exact register names and startup/ISR
     * conventions depend on the device header
     * and compiler project configuration.
     */
}
The code above is a configuration outline, not a complete working program. It intentionally avoids presenting an unverified source mapping or compiler-specific interrupt declaration as a complete LPC2129 implementation.

13. Interrupt Priority Concept

When multiple IRQ sources are active, the VIC uses its configured vectored slot priority arrangement to select an eligible vectored IRQ source.

The lower-numbered vectored slot has higher priority than a higher-numbered vectored slot when both are enabled and eligible.

Example priority arrangement

Slot Example assignment Relative priority
0 Time-critical peripheral Highest vectored slot priority
1 UART communication Second
2 Other peripheral Third
15 Lower-priority peripheral Lowest vectored slot priority
The table is an example of slot assignment, not a fixed priority assignment for particular LPC2129 peripherals. Software determines which sources occupy the slots.

14. Interrupt Handling Best Practices

  • Configure the peripheral before enabling its VIC source.
  • Clear stale peripheral interrupt flags before enabling the source.
  • Assign appropriate vectored slots to important IRQ sources.
  • Keep interrupt service routines short.
  • Clear the peripheral interrupt condition correctly.
  • Complete VIC interrupt handling according to the device manual.
  • Protect shared data between the ISR and main program.
  • Initialize exception-mode stack pointers in startup code.
  • Verify interrupt source numbers against the LPC2129 documentation.
  • Test interrupt behavior using supported debugging facilities.

15. Common Mistakes

Mistake Correct understanding
Confusing a slot number with a source number. Slots are priority positions; source numbers identify interrupt sources.
Enabling the VIC before configuring the peripheral. Configure and clear the peripheral interrupt condition first.
Assuming all IRQs use vectored slots. Non-vectored IRQ handling can use the default vector.
Assuming the VIC clears every peripheral flag automatically. The peripheral's interrupt condition must be handled as specified by that peripheral.
Forgetting VIC completion. Use the required VIC end-of-interrupt procedure.
Using source numbers from another LPC device. Verify the exact LPC2129 interrupt source table.

16. Interview Questions and Answers

Q1. What is VIC?

VIC stands for Vectored Interrupt Controller. It manages interrupt requests from peripheral sources.

Q2. Why is VIC used in LPC2129?

It manages peripheral interrupt requests, supports interrupt enable and disable, and provides vectored IRQ handling.

Q3. How many vectored IRQ slots are available?

The LPC2129 provides 16 vectored IRQ slots.

Q4. What is a vectored interrupt?

It is an interrupt mechanism in which the controller provides a handler address associated with the selected interrupt.

Q5. What is a non-vectored interrupt?

It uses a common handler, which identifies the pending interrupt source in software.

Q6. What is the purpose of VICVectAddr0?

It stores the handler address associated with vectored IRQ slot 0.

Q7. What is VICDefVectAddr?

It stores the default IRQ handler address.

Q8. What is the purpose of VICIntEnable?

It enables selected interrupt sources in the VIC.

Q9. What is the purpose of VICIntEnClr?

It disables selected interrupt sources.

Q10. How does VIC support FIQ?

It allows selected interrupt sources to be assigned to FIQ handling.

Q11. What is the difference between a source and a slot?

A source represents a peripheral interrupt. A slot is a programmable vectored IRQ priority position.

Q12. What happens after an ISR completes?

The handler must service the peripheral and perform the required VIC completion operation before normal interrupt processing can continue correctly.
