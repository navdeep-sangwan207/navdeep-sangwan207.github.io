1. Introduction

The ARM7TDMI-S processor used in the LPC2129 supports an exception-handling mechanism that allows the processor to respond to important events occurring during program execution.

When an exception occurs, the processor temporarily changes its normal execution flow, enters a specific processor mode, saves the required processor state, and transfers execution to an exception handler.

Exception handling is essential for interrupts, software services, processor faults, and system initialization.

Learning objectives:
  • Understand the ARM7 exception architecture.
  • Identify ARM7 exception types.
  • Understand processor modes.
  • Study the exception vector table.
  • Understand CPSR and SPSR during exception entry.
  • Explain IRQ and FIQ processing.
  • Understand exception return and context restoration.

2. What Is Exception Handling?

Exception handling is the mechanism through which a processor responds to events that interrupt or alter normal instruction execution.

Each exception has an associated exception mode and a corresponding vector location. The processor transfers control to the appropriate exception-handling code.

Example

Suppose a timer peripheral generates an interrupt request while the processor is executing the main application.

  1. The timer generates an interrupt request.
  2. The interrupt request reaches the processor through the interrupt controller.
  3. The processor accepts the IRQ if it is eligible.
  4. The processor enters IRQ mode.
  5. The previous CPSR is saved in the IRQ mode SPSR.
  6. The processor branches to the IRQ exception vector.
  7. The interrupt handler services the event.
  8. The processor restores the interrupted state and returns.

3. ARM7 Exception Types

ARM7TDMI-S supports seven major exception types.

Exception Processor Mode Description
Reset Supervisor (SVC) Occurs when the processor is reset.
Undefined Instruction Undefined (UND) Occurs when an instruction cannot be recognized or executed as a defined instruction.
Software Interrupt (SWI) Supervisor (SVC) Generated by executing an SWI instruction.
Prefetch Abort Abort (ABT) Occurs when an instruction fetch encounters an abort condition.
Data Abort Abort (ABT) Occurs when a data access encounters an abort condition.
IRQ IRQ Normal interrupt request exception.
FIQ FIQ Fast interrupt request exception.
ARM7 has seven exception types, including Reset, Undefined Instruction, SWI, Prefetch Abort, Data Abort, IRQ, and FIQ.

4. ARM7 Processor Modes

The ARM7TDMI-S processor supports seven operating modes. These modes determine the processor's register banking and privilege level.

Mode Type Purpose
User (USR) Unprivileged Normal application execution.
FIQ Privileged Fast interrupt handling.
IRQ Privileged Normal interrupt handling.
Supervisor (SVC) Privileged Reset and software interrupt handling.
Abort (ABT) Privileged Prefetch and data abort handling.
Undefined (UND) Privileged Undefined instruction handling.
System (SYS) Privileged Privileged execution using the User register set.
User mode is unprivileged. The other six modes are privileged. System mode is privileged but shares the User mode general-purpose register set.

5. ARM7 Exception Vector Table

The exception vector table contains fixed processor addresses associated with different exception types.

When an exception occurs, the processor uses the corresponding vector location to begin exception handling.

ARM7 Exception Vector Addresses

Address Exception
0x00000000 Reset
0x00000004 Undefined Instruction
0x00000008 Software Interrupt (SWI)
0x0000000C Prefetch Abort
0x00000010 Data Abort
0x00000014 Reserved
0x00000018 IRQ
0x0000001C FIQ
0x00000000 – Reset
0x00000004 – Undefined Instruction
0x00000008 – SWI
0x0000000C – Prefetch Abort
0x00000010 – Data Abort
0x00000014 – Reserved
0x00000018 – IRQ
0x0000001C – FIQ

Each vector location normally contains an instruction that branches to the actual exception handler.

These are the standard low exception vector addresses. ARM7 systems may configure high vectors, and an LPC2129 startup configuration determines how the vector table is mapped and used. The LPC2129 VIC also provides vectored interrupt handling for eligible IRQ sources.

6. CPSR – Current Program Status Register

CPSR is the Current Program Status Register. It stores processor status and control information.

It contains condition flags, interrupt mask bits, processor state information, and processor mode bits.

Important CPSR fields

Bit or Field Name Function
31 N Negative condition flag.
30 Z Zero condition flag.
29 C Carry condition flag.
28 V Overflow condition flag.
7 I IRQ disable mask bit.
6 F FIQ disable mask bit.
5 T Thumb state indicator.
4:0 M[4:0] Processor mode field.

Interrupt mask bits

  • I = 0: IRQ is not disabled by the CPSR IRQ mask.
  • I = 1: IRQ is disabled.
  • F = 0: FIQ is not disabled by the CPSR FIQ mask.
  • F = 1: FIQ is disabled.
The I and F bits control processor-level interrupt masking. Peripheral and VIC enable settings must also be configured for an interrupt to be accepted.

7. SPSR – Saved Program Status Register

SPSR stands for Saved Program Status Register. It stores the CPSR value that existed before the processor entered an exception mode.

This allows the processor to restore its previous execution state when returning from the exception.

SPSR availability

Processor Mode SPSR
User Not available
System Not available
FIQ SPSR_fiq
IRQ SPSR_irq
Supervisor SPSR_svc
Abort SPSR_abt
Undefined SPSR_und
User and System modes do not have an SPSR. Each exception mode has its own banked SPSR.

8. Banked Registers in ARM7

ARM7 uses banked registers to provide separate register storage for certain processor modes.

This reduces the amount of register saving and restoration needed during exception handling.

Banked register organization

Register Banking
R0–R7 Shared across all modes.
R8–R12 Shared in all modes except FIQ. FIQ has banked R8_fiq–R12_fiq.
R13 (SP) Banked in FIQ, IRQ, Supervisor, Abort, Undefined, and User/System register sets.
R14 (LR) Banked in FIQ, IRQ, Supervisor, Abort, Undefined, and User/System register sets.
R15 (PC) Shared program counter.
SPSR One SPSR for each exception mode.

Why are banked registers useful?

  • Reduce register-saving overhead.
  • Provide separate stack pointers for exception modes.
  • Allow FIQ to use additional private registers.
  • Help preserve processor context.

9. IRQ Exception Handling

IRQ stands for Interrupt Request. It is the normal interrupt exception mechanism in ARM7.

When an eligible IRQ is accepted, the processor performs the following operations:

  1. Copies the current CPSR into SPSR_irq.
  2. Stores the return address in LR_irq.
  3. Changes the processor mode to IRQ mode.
  4. Sets the IRQ disable bit in CPSR.
  5. Clears the Thumb state bit to enter ARM state.
  6. Branches to the IRQ exception vector at 0x00000018.
IRQ Request Accepted
↓
Save CPSR in SPSR_irq
↓
Save Return Address in LR_irq
↓
Enter IRQ Mode
↓
Execute IRQ Handler
↓
Restore State and Return

10. FIQ Exception Handling

FIQ stands for Fast Interrupt Request. It is designed to support fast interrupt handling.

FIQ has additional banked registers compared with IRQ mode.

FIQ exception entry

  1. Copies the current CPSR into SPSR_fiq.
  2. Stores the return address in LR_fiq.
  3. Changes the processor mode to FIQ mode.
  4. Sets the IRQ and FIQ mask bits in CPSR.
  5. Clears the Thumb state bit.
  6. Branches to the FIQ vector at 0x0000001C.

Why is FIQ faster?

FIQ has five additional banked registers: R8_fiq, R9_fiq, R10_fiq, R11_fiq, and R12_fiq.

These private registers can reduce the need to save and restore general-purpose registers when executing an FIQ handler.

FIQ is designed for fast handling, but actual response time also depends on instruction execution, memory access, interrupt configuration, and handler implementation.

11. IRQ vs FIQ

Parameter IRQ FIQ
Full form Interrupt Request Fast Interrupt Request
Vector address 0x00000018 0x0000001C
Processor mode IRQ mode FIQ mode
Banked general-purpose registers R13_irq and R14_irq R8_fiq–R14_fiq
SPSR SPSR_irq SPSR_fiq
Typical use General peripheral interrupts Time-critical interrupt handling

12. Exception Entry and Return

Exception entry is the process by which the processor changes its execution state and begins executing an exception handler.

Exception return is the process by which the processor restores the required previous execution state and resumes the interrupted program.

Important operations

  • Save the previous CPSR in the appropriate SPSR.
  • Store a suitable return address in the banked LR.
  • Switch to the required exception mode.
  • Apply interrupt masking as defined for the exception.
  • Execute the exception handler.
  • Restore the saved status and return address.

Conceptual ARM assembly example

; Conceptual IRQ handler structure

IRQ_Handler:

    ; Save registers used by the handler
    STMFD SP!, {R0-R3, R12, LR}

    ; Service interrupt source here

    ; Restore registers
    LDMFD SP!, {R0-R3, R12, LR}

    ; Exception return
    SUBS PC, LR, #4
This is an illustrative ARM-state IRQ handler skeleton, not a complete LPC2129 VIC handler. The exact return-address adjustment depends on the exception type and handler structure. A complete implementation must also acknowledge the interrupt source and correctly handle the VIC's end-of-interrupt mechanism.

13. Role of the LPC2129 VIC

The ARM7 processor provides the basic IRQ and FIQ exception mechanisms. The LPC2129 adds a Vectored Interrupt Controller (VIC) to manage its peripheral interrupt sources.

VIC responsibilities

  • Receive interrupt requests from peripherals.
  • Provide interrupt enable and disable controls.
  • Provide interrupt status information.
  • Support vectored IRQ handling.
  • Provide programmable interrupt slot assignments.
  • Support FIQ source selection.
Timer / UART / ADC / External Interrupt Sources
↓
LPC2129 VIC
↓
ARM7 IRQ / FIQ Exception
↓
Exception Vector and Handler
↓
Interrupt Service Routine
The processor exception architecture and the LPC2129 VIC are related but different components. ARM7 defines exception processing; the VIC manages interrupt sources and their delivery to the processor.

14. Exception Modes and Stack Pointers

Each exception mode has its own banked stack pointer. This allows different exception handlers to use separate stacks.

Mode Stack Pointer
User/System R13_usr / R13_sys (shared register set)
FIQ R13_fiq
IRQ R13_irq
Supervisor R13_svc
Abort R13_abt
Undefined R13_und

Embedded startup code must initialize the stack pointer for every processor mode that the application may use.

Incorrect stack pointer initialization can cause memory corruption, unexpected exceptions, and system crashes.

15. Exception Handling Applications

  • Timer events: Periodic system operations and scheduling.
  • UART communication: Receiving and transmitting serial data.
  • External interrupts: Detecting sensor and switch events.
  • Fault handling: Responding to memory access and instruction errors.
  • Software services: Providing controlled entry into privileged operations.
  • Real-time systems: Handling time-critical events.

16. Common Mistakes

Mistake Correct understanding
Confusing CPSR and SPSR. CPSR holds current processor status; SPSR saves the previous CPSR in an exception mode.
Assuming User mode has an SPSR. User and System modes do not have SPSRs.
Confusing IRQ and FIQ vector addresses. IRQ is 0x18 and FIQ is 0x1C in the standard low vector table.
Assuming all registers are banked. Only selected registers are banked.
Ignoring stack initialization. Initialize the required mode-specific stack pointers.
Confusing the VIC with the ARM7 exception mechanism. The VIC manages interrupt requests; ARM7 handles processor exceptions.
Returning from an exception without restoring state. Use the correct exception-return mechanism and restore the saved context.

17. Interview Questions and Answers

Q1. What is exception handling in ARM7?

It is the mechanism that transfers processor execution to a special handler when an exception occurs.

Q2. How many exception types are supported by ARM7?

Seven major types: Reset, Undefined Instruction, SWI, Prefetch Abort, Data Abort, IRQ, and FIQ.

Q3. What is the purpose of the exception vector table?

It provides fixed addresses associated with different processor exceptions.

Q4. What is CPSR?

CPSR is the Current Program Status Register, which contains processor status and control information.

Q5. What is SPSR?

SPSR stores the previous CPSR value when the processor enters an exception mode.

Q6. Why does FIQ have additional banked registers?

They reduce register-saving overhead and help support fast interrupt handling.

Q7. Which vector address is used for IRQ?

0x00000018 in the standard low vector table.

Q8. Which vector address is used for FIQ?

0x0000001C in the standard low vector table.

Q9. What is the difference between IRQ and FIQ?

IRQ is the normal interrupt exception. FIQ is designed for fast interrupt handling and has additional banked registers.

Q10. What is the purpose of banked registers?

They provide separate register storage for selected processor modes and reduce context-saving overhead.

Q11. Does System mode have an SPSR?

No. System mode shares the User register set and does not have an SPSR.

Q12. What is the role of the LPC2129 VIC?

It manages peripheral interrupt requests and supports vectored interrupt handling.
