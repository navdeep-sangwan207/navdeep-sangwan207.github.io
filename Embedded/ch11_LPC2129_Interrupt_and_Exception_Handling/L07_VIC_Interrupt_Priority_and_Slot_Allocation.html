1. Introduction

In an embedded system, multiple peripherals may generate interrupt requests at nearly the same time. The processor must determine which interrupt should be serviced first.

The LPC2129 Vectored Interrupt Controller (VIC) provides 16 programmable vectored IRQ slots. These slots allow software to assign interrupt sources to priority positions.

A lower-numbered vectored slot has higher priority than a higher-numbered slot. Therefore, slot 0 has the highest vectored IRQ priority and slot 15 has the lowest.

2. What Is Interrupt Priority?

Interrupt priority determines which eligible interrupt request is selected first when multiple requests are pending.

Example

Consider an embedded system containing:

  • Timer 0 for periodic system timing.
  • Timer 1 for another timing function.
  • UART0 for serial communication.

If these interrupt sources request service at nearly the same time, the VIC's configured priority arrangement determines which eligible vectored IRQ source is selected first.

Interrupt priority is especially important in real-time embedded systems, where time-critical events must be handled promptly.

4. Priority Order

The priority of a vectored IRQ source is determined by the slot to which it is assigned.

Slot assignment Relative priority
Slot 0Highest
Slot 1Lower than slot 0
Slot 2Lower than slots 0 and 1
Slot 3Lower than slots 0, 1 and 2
Slot 15Lowest vectored slot priority

Example priority assignment

Slot Example interrupt source Reason
0 Timer 0 Time-critical periodic event.
1 UART0 Serial communication event.
2 Timer 1 Secondary timing event.
3 Other peripheral Less time-critical event.
This is an example software assignment. The VIC does not permanently associate Timer 0 with slot 0 or UART0 with slot 1. The programmer chooses the slot allocation.

5. VICVectCntl Register Format

Each vectored slot has a corresponding VICVectCntl register.

General register organization:

Bit position Function
Bit 5 Enable the vectored IRQ slot.
Bits 4:0 Interrupt source number assigned to the slot.
Bits 31:6 Reserved.

Example register value

VICVectCntl0 = 0x24;

Binary representation:

0000 0000 0000 0000 0000 0000 0010 0100

The value 0x24 sets bit 5 to enable the slot and places source number 4 in bits 4:0.

Formula: 
VICVectCntlN = (1U << 5) | source_number;
Here N represents the selected slot from 0 to 15.

6. Slot Allocation

Slot allocation is the process of assigning interrupt sources to the available vectored IRQ slots.

Example allocation

Slot Source Example source number
0Timer 04
1UART06
2Timer 15

This arrangement gives Timer 0 the highest vectored IRQ slot priority, UART0 the next priority, and Timer 1 the third priority.

Programming example

#include <LPC21xx.h>

#define TIMER0_SOURCE 4U
#define UART0_SOURCE  6U
#define TIMER1_SOURCE 5U

#define VECTOR_ENABLE (1U << 5)

void Allocate_VIC_Slots(void)
{
    /* Highest vectored IRQ priority */
    VICVectCntl0 =
        VECTOR_ENABLE | TIMER0_SOURCE;

    /* Second priority */
    VICVectCntl1 =
        VECTOR_ENABLE | UART0_SOURCE;

    /* Third priority */
    VICVectCntl2 =
        VECTOR_ENABLE | TIMER1_SOURCE;
}

int main(void)
{
    Allocate_VIC_Slots();

    while (1)
    {
    }
}
This example configures slot assignments only. It does not configure the peripheral interrupt conditions, handler addresses, source enables, or processor exception handling.

Each vectored IRQ slot has a corresponding vector address register.

2VICVectAddr2
3VICVectAddr3
......
15VICVectAddr15

Example

#include <LPC21xx.h>

void Timer0_ISR(void);
void UART0_ISR(void);

void Configure_Vector_Addresses(void)
{
    VICVectAddr0 = (unsigned int)Timer0_ISR;
    VICVectAddr1 = (unsigned int)UART0_ISR;
}

void Timer0_ISR(void)
{
    /* Timer 0 service code */
    VICVectAddr = 0;
}

void UART0_ISR(void)
{
    /* UART0 service code */
    VICVectAddr = 0;
}
These are illustrative handler-address assignments. Actual interrupt handlers must use the correct compiler-specific IRQ convention or assembly wrapper. Peripheral status handling and exception return must also be implemented correctly.

8. What Happens When Multiple IRQs Are Pending?

Suppose Timer 0, UART0 and Timer 1 generate IRQ requests at nearly the same time.

Assume this slot allocation:

  • Timer 0 is assigned to slot 0.
  • UART0 is assigned to slot 1.
  • Timer 1 is assigned to slot 2.

Among these eligible vectored IRQ sources, the VIC selects the source with the highest slot priority first.

Timer 0 – Slot 0
UART0 – Slot 1
Timer 1 – Slot 2
↓
VIC Selects Highest-Priority Eligible Source
↓
Selected IRQ Handler
A lower-priority vectored IRQ may remain pending while a higher-priority vectored IRQ is serviced. The precise behavior also depends on processor IRQ masking, exception handling, and the state of the peripheral interrupt request.

9. Priority and IRQ/FIQ Difference

VIC vectored slot priority and ARM7 IRQ/FIQ exception priority are related to interrupt handling, but they are not the same mechanism.

Feature Vectored IRQ slot priority IRQ/FIQ exception priority
Purpose Orders vectored IRQ sources. Distinguishes processor exception classes.
Configuration VICVectCntl0–15 slot assignment. VICIntSelect and processor exception architecture.
Number of slots 16 vectored IRQ slots. IRQ and FIQ exception classes.
Processor mode IRQ mode for vectored IRQ handling. IRQ mode or FIQ mode.
FIQ is a separate ARM7 exception class with higher architectural priority than IRQ. The 16 VIC vectored slots organize IRQ sources; they are not 16 FIQ slots.

10. Priority Allocation Guidelines

Interrupt priority should be assigned according to system requirements.

Consider the following factors

  • Response time: How quickly must the event be handled?
  • Data loss risk: Could delayed service cause received data to be lost?
  • Event frequency: How often does the interrupt occur?
  • Processing time: How long does its ISR take?
  • System criticality: What happens if the event is delayed?
  • Resource sharing: Does the ISR access shared data or peripherals?
High-priority interrupts should generally have short service routines. Long-running operations should be deferred to the main program or a suitable task.

11. Common Mistakes

Mistake Correct understanding
Assuming slot 15 has the highest priority. Slot 0 has the highest vectored IRQ priority.
Confusing a source number with a slot number. A source identifies a peripheral; a slot identifies a priority position.
Configuring only VICVectCntl. The handler address, source enable, and peripheral configuration are also required.
Assuming slot allocation creates a peripheral interrupt. The peripheral must generate the request.
Assigning one source to multiple slots without checking constraints. Use a clear, valid source-to-slot allocation.
Confusing FIQ with slot 0. FIQ is a separate exception class, not vectored IRQ slot 0.

12. Interview Questions and Answers

Q1. What is interrupt priority?

It determines which eligible interrupt request is selected first.

Q2. How many vectored IRQ slots are available in LPC2129?

There are 16 vectored IRQ slots.

Q3. Which slot has the highest priority?

Slot 0.

Q4. Which slot has the lowest priority?

Slot 15.

Q5. What is slot allocation?

It is the assignment of interrupt sources to vectored IRQ priority slots.

Q6. What is VICVectCntl0?

It is the control register for vectored IRQ slot 0.

Q7. What is VICVectAddr0?

It stores the handler address associated with slot 0.

Q8. Can Timer 0 be assigned to slot 0?

Yes. Software can assign Timer 0 to slot 0 if that is appropriate for the application's priority requirements.

Q9. Does slot priority determine the priority of FIQ?

No. FIQ is a separate ARM7 exception class. The vectored slots organize vectored IRQ sources.

Q10. Why should a high-priority ISR be short?

A short ISR reduces interrupt latency for other events and improves system responsiveness.

Q11. Can two interrupt sources use the same slot?

A vectored slot selects one source. Allocate distinct slots to sources that need separate vectored handlers.

Q12. What happens if a pending interrupt is not assigned to a vectored slot?

It can be handled through the default IRQ vector and a common handler, provided the source is configured for IRQ and enabled appropriately.
