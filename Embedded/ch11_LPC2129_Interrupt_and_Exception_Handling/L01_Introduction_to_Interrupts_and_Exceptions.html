1. Introduction

An embedded system continuously interacts with hardware peripherals such as sensors, timers, switches, communication interfaces, and actuators.

These peripherals generate events that may require immediate attention from the microcontroller. For example, a timer may reach a programmed value, a UART may receive data, or an external switch may change its state.

An interrupt allows the processor to respond to such events by temporarily suspending its normal program execution and transferring control to a special function called an Interrupt Service Routine (ISR).

An exception is a broader processor-level event that causes execution to change from the normal instruction flow to a predefined exception-handling routine.

Central concept: Interrupts and exceptions provide mechanisms for handling events that require special processor attention.

2. What Is an Interrupt?

An interrupt is a signal or request that causes the processor to temporarily stop executing its current program and execute an interrupt-handling routine.

The interrupt may originate from an internal peripheral or an external hardware source.

Example: Timer Interrupt

Consider an embedded application that must perform an operation every 1 second.

  1. The processor starts Timer 0.
  2. The timer counts using its configured clock.
  3. The timer reaches its programmed match value.
  4. The timer generates an interrupt request.
  5. The interrupt controller forwards the request to the processor when enabled and eligible.
  6. The processor executes the timer ISR.
  7. The processor returns to the interrupted program.
Normal Program Execution
↓
Timer Reaches Match Value
↓
Interrupt Request Generated
↓
Processor Executes Timer ISR
↓
Return to Normal Program

3. What Is an Exception?

An exception is an event that changes the normal execution flow of a processor. The processor responds by entering an appropriate exception mode and executing instructions from an exception vector.

Exceptions may be generated by external requests, internal processor conditions, or software instructions.

Examples of ARM7 exceptions

Exception Description
Reset Occurs when the processor is reset or powered up through its reset mechanism.
Undefined Instruction Occurs when the processor encounters an instruction it cannot execute as a defined instruction.
Software Interrupt (SWI) Generated by executing a software interrupt instruction.
Prefetch Abort Occurs when an instruction fetch encounters an abort condition.
Data Abort Occurs when a data access encounters an abort condition.
IRQ Normal interrupt request exception.
FIQ Fast interrupt request exception.
ARM7 uses the term exception for several processor events, including IRQ and FIQ. Therefore, an interrupt is one category of exception, not a completely separate processor mechanism.

4. Difference Between Interrupt and Exception

The terms interrupt and exception are related, but they are not always used interchangeably.

Interrupt Exception
Usually refers to an event requesting processor attention. Refers broadly to a processor event that changes normal execution.
Often originates from peripherals or external hardware. May originate from hardware, processor conditions, or software instructions.
Examples include timer, UART, and external interrupts. Examples include reset, SWI, aborts, IRQ, and FIQ.
Handled using interrupt handling mechanisms. Handled using processor exception mechanisms and exception vectors.

In ARM7 terminology, IRQ and FIQ are exception types used to handle interrupt requests.

5. Why Are Interrupts Required?

Without interrupts, a processor may need to continuously check the status of every peripheral. This approach is called polling.

Interrupts allow hardware to notify the processor when an event requires attention.

Important reasons

  • Efficient CPU utilization: The processor does not need to continuously check every event.
  • Fast event response: The processor can respond when an interrupt request is recognized.
  • Real-time operation: Interrupts support event-driven embedded applications.
  • Peripheral communication: UART, timers, and other peripherals can request processor service.
  • Multitasking support: Interrupts can help implement periodic scheduling and time-dependent tasks.

6. Sources of Interrupts

Interrupt requests can originate from internal peripherals or external hardware.

6.1 Internal Interrupt Sources

Source Example
Timer Timer counter reaches a match value.
UART Serial data is received or transmission requires service.
ADC An analog-to-digital conversion completes.
SPI A serial data transfer event occurs.
CAN A CAN controller event requires processing.

6.2 External Interrupt Sources

  • Push-button activation.
  • Sensor output transitions.
  • External event pulses.
  • Alarm signals.
  • Hardware fault signals.
LPC2129 provides external interrupt inputs EINT0, EINT1, EINT2, and EINT3. Their configuration and programming are covered later in this chapter.

7. Basic Interrupt Handling Sequence

When an eligible interrupt request is accepted, the processor performs a sequence of operations to execute the corresponding handler.

  1. Interrupt request: A peripheral or external source requests service.
  2. Interrupt qualification: The interrupt controller and processor interrupt masks determine whether the request can be accepted.
  3. Processor state preservation: The processor saves the information needed to return to the interrupted program.
  4. Exception entry: The processor enters the appropriate exception mode.
  5. Handler execution: The interrupt-handling code executes.
  6. Peripheral servicing: The ISR performs the required operation and acknowledges or clears the relevant source.
  7. Exception return: The processor restores the required state and resumes normal execution.
Peripheral Event
↓
Interrupt Request
↓
Interrupt Controller / Processor
↓
Exception Entry
↓
Interrupt Service Routine
↓
Exception Return
↓
Resume Main Program
The exact exception-entry and return operations depend on the ARM architecture. ARM7 uses banked registers and saved processor status registers for exception handling. These details are covered in Lesson 03.

8. What Is an Interrupt Service Routine?

An Interrupt Service Routine (ISR) is a special function executed in response to an interrupt request.

The ISR performs the operation required to service the interrupt source.

Example applications

  • Increment a software counter after a timer event.
  • Store a received UART character in a buffer.
  • Set a flag to indicate that an ADC conversion is complete.
  • Record an external sensor event.

Conceptual ISR example

volatile unsigned int timer_event = 0;

/*
 * Conceptual timer interrupt handler.
 * Actual ISR declaration and VIC setup
 * depend on the compiler and device.
 */

void Timer0_ISR(void)
{
    timer_event++;

    // Clear the timer interrupt source
    T0IR = (1U << 0);
}

This example demonstrates the basic operation of an interrupt handler. It is not a complete standalone LPC2129 interrupt program: the timer match, VIC configuration, compiler-specific interrupt declaration, and interrupt acknowledgment sequence must also be configured.

9. Interrupt Latency

Interrupt latency is the time between an interrupt request becoming active and the processor beginning execution of the corresponding interrupt handler.

Interrupt latency is important in real-time embedded systems because some events must be serviced within a specified time limit.

Factors affecting interrupt latency

  • Current processor instruction and execution state.
  • Interrupt masking and enable configuration.
  • Higher-priority interrupt activity.
  • Interrupt controller response.
  • Exception entry and context handling.
  • Memory and bus access delays.
Lower interrupt latency can be important in time-critical applications such as motor control, communication handling, and industrial monitoring.

10. Types of Interrupt Requests

10.1 Maskable Interrupt

A maskable interrupt can be disabled or prevented from being accepted using interrupt control or masking mechanisms.

10.2 Non-Maskable Interrupt

A non-maskable interrupt is designed for events that must receive special processor attention regardless of ordinary interrupt masking.

Do not assume that every microcontroller provides a dedicated non-maskable external interrupt input. ARM7's IRQ and FIQ are distinct exception types; FIQ is not the same thing as a dedicated non-maskable interrupt.

10.3 IRQ and FIQ in ARM7

IRQ FIQ
Normal Interrupt Request. Fast Interrupt Request.
Uses IRQ exception mode. Uses FIQ exception mode.
Has fewer banked general-purpose registers. Has additional banked registers to support faster handling.
Suitable for general interrupt handling. Designed for applications requiring fast interrupt response.

11. Interrupts in LPC2129

The LPC2129 uses an ARM7TDMI-S processor and includes a Vectored Interrupt Controller (VIC) for managing interrupt requests from its peripherals and external interrupt sources.

Major components

  • Interrupt sources: Timers, UARTs, external interrupts, and other peripherals.
  • VIC: Manages interrupt requests and supports vectored interrupt handling.
  • ARM7 processor: Accepts IRQ or FIQ exceptions and executes the appropriate exception-handling code.
  • ISR: Performs the required interrupt service operation.
Timer / UART / External Interrupt / Other Sources
↓
LPC2129 Vectored Interrupt Controller (VIC)
↓
ARM7TDMI-S Processor – IRQ / FIQ
↓
Interrupt Service Routine

The VIC provides interrupt source selection, enable control, priority handling through vectored slots, and interrupt status information.

The LPC2129 VIC supports 32 interrupt request inputs. Its detailed registers, source assignments, and slot configuration are covered in the next lessons.

12. Simple Embedded C Example – Event Flag

In embedded applications, an ISR often updates a flag instead of performing lengthy operations. The main program checks the flag and performs the required processing.

Conceptual example

#include <LPC21xx.h>

volatile unsigned int event_flag = 0;

int main(void)
{
    while (1)
    {
        if (event_flag == 1)
        {
            event_flag = 0;

            // Perform event processing here
        }
    }
}

Explanation

  1. The event_flag variable is shared between the main program and an interrupt handler.
  2. The ISR sets event_flag when the event occurs.
  3. The main loop checks the flag.
  4. The main loop performs the required processing.
  5. The flag is cleared after processing.
This is an application pattern, not a complete interrupt configuration. A real implementation must configure the peripheral, interrupt controller, ISR declaration, and source acknowledgment. If the event can occur again before the flag is processed, a counter or event queue may be more appropriate than a single Boolean flag.

13. Advantages of Interrupts

  • Reduce continuous polling of peripherals.
  • Support event-driven program design.
  • Improve CPU availability for other tasks.
  • Provide mechanisms for timely event response.
  • Support communication and peripheral servicing.
  • Help implement periodic and real-time operations.

14. Limitations and Challenges

  • Interrupt handling adds software complexity.
  • Long ISRs can delay other interrupt requests.
  • Shared data must be handled carefully.
  • Interrupt priority must be designed correctly.
  • Incorrect flag clearing can cause repeated interrupts.
  • Debugging interrupt-driven programs can be difficult.

15. Common Mistakes

Mistake Correct approach
Forgetting to enable the interrupt source. Configure the peripheral and VIC enable settings.
Not clearing the interrupt source. Follow the peripheral's documented flag-clearing method.
Writing long operations inside an ISR. Keep the ISR short and defer lengthy processing.
Using shared variables without considering compiler optimization. Use appropriate volatile declarations and synchronization.
Confusing IRQ and FIQ. Understand their separate processor modes and register banks.
Assuming an interrupt always executes immediately. Consider masking, priority, and interrupt latency.

16. Interview Questions and Answers

Q1. What is an interrupt?

An interrupt is a request that causes the processor to suspend normal execution temporarily and execute an interrupt service routine.

Q2. What is an exception?

An exception is a processor event that changes the normal execution flow and transfers control to an exception handler.

Q3. What is an ISR?

An Interrupt Service Routine is a special handler function executed to service an interrupt request.

Q4. What is interrupt latency?

It is the time between an interrupt request becoming active and the start of execution of its handler.

Q5. What is the difference between IRQ and FIQ?

IRQ is the normal interrupt request exception, while FIQ is the fast interrupt request exception with additional banked registers for faster handling.

Q6. What is the purpose of the VIC in LPC2129?

The Vectored Interrupt Controller manages interrupt requests, provides enable and status controls, and supports vectored interrupt handling.

Q7. Why should an ISR be short?

A short ISR reduces the time spent in interrupt context and helps avoid delaying other interrupt requests and main-program execution.

Q8. Can a timer generate an interrupt?

Yes. A timer can generate an interrupt when a configured match or other supported interrupt event occurs.

Q9. What is polling?

Polling is a technique in which the processor repeatedly checks a peripheral status flag to detect an event.

Q10. Are all exceptions interrupts?

No. Exceptions also include reset, undefined instruction, software interrupt, and abort conditions.
