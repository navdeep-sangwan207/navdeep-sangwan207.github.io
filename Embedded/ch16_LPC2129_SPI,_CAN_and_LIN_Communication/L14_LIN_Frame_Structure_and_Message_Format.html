Understanding LIN frame fields, identifiers, data bytes and checksum.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain the structure of a LIN frame.
  • Identify the header and response sections.
  • Explain the break, sync and protected identifier fields.
  • Understand the 6-bit identifier and 2-bit parity.
  • Describe the data and checksum fields.
  • Differentiate classic and enhanced checksum.
  • Understand the role of publisher and subscribers.

2. Introduction to LIN Frames

A LIN frame is the basic unit of communication transmitted over a LIN bus. It carries information between the master node and one or more slave nodes.

Every normal LIN frame consists of two main sections:

  1. Header: Transmitted by the master task.
  2. Response: Transmitted by the publisher of that frame.
Important: The master always initiates a normal scheduled frame by transmitting its header. The response publisher may be the master itself or a slave node. 
             LIN FRAME
  +-----------------------------+
  |           HEADER            |
  |                             |
  |  Break | Sync | Protected ID |
  +-----------------------------+
  |          RESPONSE           |
  |                             |
  |       Data | Checksum       |
  +-----------------------------+

4. Break Field

The break field indicates the beginning of a new LIN frame. It is transmitted by the master node before the sync field.

Functions of the Break Field

  • Indicates the start of a new frame.
  • Helps slave nodes identify frame boundaries.
  • Separates the LIN frame from ordinary UART data.
  • Provides a recognizable start condition for frame reception.

The break is represented by a dominant bus level held longer than a normal UART data character can produce.

LIN Bus:
       Dominant break       Delimiter
   ____________________       ______
                         |____|
The break field is not an ordinary UART data byte. A LIN master must generate it using suitable UART hardware features or firmware timing.

5. Sync Field

The sync field is a fixed byte transmitted immediately after the break delimiter.

Sync byte = 0x55

Binary representation:

Hexadecimal: 0x55
Binary:      01010101

Purpose of the Sync Field

  • Helps slave nodes synchronize their communication timing.
  • Allows a slave to measure bit timing from signal transitions.
  • Supports reliable communication between nodes with different clock tolerances.
The alternating bit pattern of 0x55 provides regular signal transitions that help a slave estimate the bit time.

6. Protected Identifier (PID)

The protected identifier specifies which frame is being transmitted. It consists of:

  • 6-bit frame identifier (ID0 to ID5).
  • 2 parity bits (P0 and P1).
+--------------------------------+
| ID5 ID4 ID3 ID2 ID1 ID0 | P1 P0 |
+--------------------------------+
       6-bit ID           2 parity bits

             Total = 8 bits

6.1 Frame Identifier

The six identifier bits provide 64 possible identifier values, from 0 to 63. Some identifier values have special purposes defined by the LIN specification.

6.2 Parity Bits

The parity bits protect the identifier against certain bit errors.

For LIN 2.x, the parity equations are:

P0 = ID0 XOR ID1 XOR ID2 XOR ID4

P1 = NOT (ID1 XOR ID3 XOR ID4 XOR ID5)

Here, XOR means exclusive OR, and NOT means logical inversion.

Example of PID Construction

Consider a frame identifier with the following six bits:

ID5 ID4 ID3 ID2 ID1 ID0
 0   0   0   0   0   1

Therefore:

  • ID0 = 1
  • ID1 = 0
  • ID2 = 0
  • ID3 = 0
  • ID4 = 0
  • ID5 = 0
P0 = 1 XOR 0 XOR 0 XOR 0
   = 1

P1 = NOT (0 XOR 0 XOR 0 XOR 0)
   = 1

Thus, the protected identifier bits are:

ID5 ID4 ID3 ID2 ID1 ID0 P1 P0
 0   0   0   0   0   1  1  1

PID = 00000111 (binary)
    = 0x07 (hexadecimal)
Do not confuse the 6-bit LIN frame identifier with the complete 8-bit protected identifier. The PID includes two parity bits.

7. Data Field

The data field carries the actual information associated with a LIN frame.

Characteristics

  • Contains 1 to 8 data bytes in LIN 2.x.
  • Each data byte contains 8 bits.
  • Data represents signals such as temperature, switch status or motor commands.
  • The publisher transmits the response data.
  • Subscriber nodes receive and interpret the data.

Example: Door Control Data

Suppose a LIN frame carries the status of a vehicle door:

Data ByteExample ValueMeaning
Byte 10x01Door open status
Byte 20x00Window stopped
Byte 30x64Example motor command value

The exact meaning of each byte depends on the network configuration and signal definitions.

8. Checksum Field

The checksum is transmitted at the end of the response. It is used to detect errors in the data transmission.

Purpose

  • Detects certain transmission errors.
  • Helps the receiver validate the received response.
  • Provides an additional integrity check for frame data.

Types of LIN Checksum

Checksum TypeCalculation Coverage
Classic Checksum Data bytes only.
Enhanced Checksum Protected identifier and data bytes.
Diagnostic frames use the classic checksum. The checksum type for other frames depends on the LIN protocol version and frame configuration.

The detailed checksum calculation, including carry handling and implementation, is covered in Lesson 17.

9. Publisher and Subscriber in a LIN Frame

The response section is associated with a publisher and one or more subscribers.

  • Publisher: The node responsible for transmitting the response.
  • Subscriber: A node that receives and processes the response.
  • Master task: Transmits the header and controls the schedule.

10. Complete LIN Frame Transmission Sequence

  1. The master selects a frame according to its schedule table.
  2. The master transmits the break field.
  3. The master transmits the sync byte 0x55.
  4. The master transmits the protected identifier.
  5. The designated publisher transmits the data bytes.
  6. The publisher transmits the checksum.
  7. Subscribers validate and process the received response.
  8. The master proceeds to the next scheduled frame.
MASTER                 PUBLISHER             SUBSCRIBERS
  |                         |                       |
  |------ Break ----------->|---------------------->|
  |------ Sync ------------>|---------------------->|
  |------ PID ------------->|---------------------->|
  |                         |                       |
  |<----- Data -------------|                       |
  |<----- Checksum ---------|                       |
  |                         |                       |
  |                  Frame completed                |

This diagram is conceptual. The response is transmitted on the shared LIN bus by the designated publisher and is received by the other nodes.

11. LIN Frame vs UART Data Transmission

LIN uses UART-like serial character transmission, but a LIN frame includes additional protocol-level fields and rules.

FeatureUARTLIN
CommunicationSerial communication interfaceAutomotive network protocol
Frame startUART start bitBreak, sync and PID
AddressingNot inherently provided by basic UARTFrame identifier
SchedulingNot defined by basic UARTMaster-controlled schedule
Electrical interfaceDepends on UART implementationSingle-wire LIN bus with transceiver
Error checkingOptional parity and other mechanismsLIN checksum and PID parity
A microcontroller UART is not directly equivalent to a LIN interface. A LIN transceiver is required to connect the MCU logic interface to the physical LIN bus.

12. LPC2129-Based LIN Frame Implementation

The LPC2129 does not contain a dedicated LIN controller. Its UART peripheral can be used as part of a firmware-based LIN implementation with an external LIN transceiver.

Required Components

  • LPC2129 microcontroller.
  • UART peripheral.
  • External LIN transceiver.
  • LIN bus connection and suitable power supply.
  • Firmware for break generation/detection, synchronization and frame handling.
        LPC2129
   +----------------+
   |                |
   | UART TX ------ |---- TXD
   |                |      |
   | UART RX ------ |---- RXD
   |                |      |
   +----------------+  +----------------+
                       | LIN Transceiver|
                       +----------------+
                               |
                               |
                           LIN BUS

Firmware Responsibilities

  • Generate or detect the LIN break field.
  • Transmit and receive the sync byte.
  • Process the protected identifier.
  • Transmit or receive the configured data bytes.
  • Calculate and validate the checksum.
  • Follow the configured frame schedule.
Keil uVision simulation can help test portions of UART and frame-processing firmware. It cannot, by itself, demonstrate the electrical behavior of a physical LIN bus or an external LIN transceiver.

15. Interview Questions and Answers

Q1. What are the main fields of a LIN frame?

Answer: Break, sync, protected identifier, data and checksum.

Q2. What is the value of the LIN sync byte?

Answer: 0x55.

Q3. What is a protected identifier?

Answer: It is an 8-bit field containing a 6-bit frame identifier and two parity bits.

Q4. Why are parity bits used in the PID?

Answer: They provide error detection for the identifier field.

Q5. Who transmits the LIN header?

Answer: The master task transmits the header.

Q6. Who transmits the response?

Answer: The designated publisher transmits the response. It may be the master or a slave node.

Q7. What is the difference between classic and enhanced checksum?

Answer: Classic checksum covers the data bytes, whereas enhanced checksum covers the protected identifier and data bytes. Diagnostic frames use classic checksum.

Q8. Can LPC2129 communicate with a LIN bus?

Answer: Yes, a firmware-based implementation can use its UART with an external LIN transceiver. The LPC2129 does not have a dedicated LIN controller.

Q9. What is the maximum data length of a LIN 2.x frame?

Answer: Eight data bytes.

Q10. What is the function of the sync field?

Answer: It helps slave nodes synchronize their bit timing with the master transmission.

16. Lesson Summary

  • A LIN frame consists of a header and a response.
  • The master task transmits the header.
  • The header contains break, sync and protected identifier fields.
  • The sync byte is 0x55.
  • The protected identifier contains six identifier bits and two parity bits.
  • The response contains data bytes and a checksum.
  • A LIN 2.x frame supports up to eight data bytes.
  • The response publisher may be the master or a slave.
  • LPC2129 can use UART-based firmware with an external LIN transceiver.
