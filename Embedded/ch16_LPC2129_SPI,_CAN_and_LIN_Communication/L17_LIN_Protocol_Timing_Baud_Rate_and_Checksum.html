2. Introduction to LIN Timing

LIN is an asynchronous serial communication protocol. Data is transmitted at a configured bit rate, and the receiver uses the start bit and synchronization information to identify the data bits.

Correct timing is essential for reliable communication between the master and slave nodes.

Important Timing Parameters

  • Baud rate or bit rate.
  • Bit time.
  • UART character time.
  • Break field duration.
  • Break delimiter duration.
  • Inter-byte spacing.
  • Frame slot duration.
LIN communication is commonly operated at speeds up to 20 kbit/s. The configured baud rate must be supported by all nodes in the LIN cluster.

3. Baud Rate

Baud rate represents the number of signaling symbols transmitted per second. In LIN, each symbol represents one bit, so the baud rate is numerically equal to the bit rate.

Common LIN Baud Rates

Baud RateApplication
9,600 bpsLower-speed LIN communication
19,200 bpsCommon LIN communication speed
20,000 bpsUpper limit of the commonly specified LIN bit rate

Baud Rate Formula

Baud Rate = Number of Bits / Time

Bit Time = 1 / Baud Rate

Example

For a baud rate of 19,200 bits per second:

Bit Time = 1 / 19200

         = 0.000052083 seconds

         = 52.083 microseconds

4. Bit Time Calculation

Bit time is the time required to transmit one bit.

Example 1: 9,600 bps

Bit Time = 1 / 9600

         = 104.17 microseconds

Example 2: 19,200 bps

Bit Time = 1 / 19200

         = 52.08 microseconds

Example 3: 20,000 bps

Bit Time = 1 / 20000

         = 50 microseconds

5. UART Character Timing

LIN uses UART-style serial character transmission for the sync, identifier and response bytes.

A typical UART character uses:

  • 1 start bit.
  • 8 data bits.
  • 1 stop bit.

This is commonly called 8N1 format.

+-------+------------------------+----------+
| Start |       8 Data Bits      |   Stop   |
+-------+------------------------+----------+
   1 bit          8 bits           1 bit

Total = 10 bit times

Character Time Example

At 19,200 bps:

Bit Time = 52.08 µs

Character Time = 10 x 52.08 µs

               = 520.8 µs
This is the approximate time for one ordinary 8N1 UART character. LIN break and delimiter timing are special protocol requirements and must be considered separately.

6. LIN Frame Duration

The total duration of a LIN frame depends on the header, response length and protocol timing margins.

Frame Components

+---------+--------+---------+----------------+----------+
| Break   | Sync   | PID     | Data Bytes     | Checksum |
+---------+--------+---------+----------------+----------+
|                 HEADER              | RESPONSE         |

Factors Affecting Frame Duration

  • Configured baud rate.
  • Break field duration.
  • Break delimiter duration.
  • Number of response data bytes.
  • Checksum character transmission.
  • Inter-byte and schedule timing margins.

Approximate Character-Based Calculation

Consider a frame with two header characters after the break and delimiter (sync and PID), four data bytes and one checksum byte.

Sync + PID = 2 characters

Data       = 4 characters

Checksum   = 1 character

Total      = 7 UART characters

At 19,200 bps:

Character Time ≈ 520.8 µs

Character Transmission Time
= 7 x 520.8 µs
≈ 3.646 ms

This is only the character transmission portion. Actual frame duration also includes break, delimiter and protocol timing margins.

7. Why Checksum Is Required

During communication, electrical noise or signal disturbances can change transmitted bits. A checksum helps the receiver detect certain transmission errors.

Checksum Functions

  • Checks the integrity of received frame data.
  • Helps detect corrupted responses.
  • Allows the receiver to reject invalid data.
  • Supports reliable communication between LIN nodes.
A checksum detects certain errors but does not guarantee detection of every possible transmission error.

8. Types of LIN Checksum

LIN defines two checksum models:

Checksum TypeCalculation Includes
Classic Checksum Data bytes only.
Enhanced Checksum Protected identifier and data bytes.

Classic Checksum

Classic checksum is calculated using only the response data bytes.

Enhanced Checksum

Enhanced checksum includes the protected identifier and response data bytes in the calculation.

Diagnostic frames use classic checksum. The checksum model used for other frames depends on the LIN protocol version and frame configuration.

9. LIN Checksum Calculation Method

LIN uses an inverted modulo-256 sum with end-around carry handling.

Calculation Steps

  1. Initialize the sum to zero.
  2. Add the selected bytes one by one.
  3. If the sum exceeds 255, add the carry back to the lower eight bits.
  4. Invert all eight bits of the final sum.

Checksum Formula

Checksum = NOT (Final 8-bit Sum)

The calculation is performed over the data bytes for classic checksum, or over the protected identifier followed by the data bytes for enhanced checksum.

10. Classic Checksum Example

Consider the following three data bytes:

Data 1 = 0x10
Data 2 = 0x20
Data 3 = 0x30

Step 1: Add the Data Bytes

Sum = 0x10 + 0x20 + 0x30

    = 0x60

Step 2: Apply 8-bit Inversion

Sum      = 0110 0000
Checksum = 1001 1111

Checksum = 0x9F

Therefore, the classic checksum is:

Classic Checksum = 0x9F

11. Checksum Example with Carry

Consider two data bytes:

Data 1 = 0xF0
Data 2 = 0x30

Step 1: Add the Bytes

0xF0 + 0x30 = 0x120

Step 2: Add the Carry Back

Lower 8 bits = 0x20
Carry        = 0x01

New Sum = 0x20 + 0x01

        = 0x21

Step 3: Invert the Result

0x21 = 0010 0001

NOT  = 1101 1110

     = 0xDE

Final classic checksum = 0xDE

12. Enhanced Checksum Example

Enhanced checksum includes the protected identifier and all response data bytes.

Assume:

PID    = 0x07
Data 1 = 0x10
Data 2 = 0x20

Step 1: Add PID and Data Bytes

Sum = 0x07 + 0x10 + 0x20

    = 0x37

Step 2: Invert the Result

0x37 = 0011 0111

NOT  = 1100 1000

     = 0xC8

Final enhanced checksum = 0xC8

This is an illustrative calculation for the stated bytes. In an actual LIN network, the checksum model must match the frame configuration and protocol requirements.

13. C Program for LIN Checksum Calculation

The following program calculates the classic checksum for a data array using end-around carry.

#include <stdio.h>
#include <stdint.h>

uint8_t LIN_ClassicChecksum(
    const uint8_t data[],
    uint8_t length)
{
    uint16_t sum = 0;
    uint8_t i;

    for (i = 0; i < length; i++)
    {
        sum += data[i];

        if (sum > 0xFF)
        {
            sum = (sum & 0xFF) + 1;
        }
    }

    return (uint8_t)(~sum);
}

int main(void)
{
    uint8_t data[] = {0x10, 0x20, 0x30};

    uint8_t checksum;

    checksum = LIN_ClassicChecksum(
        data,
        sizeof(data) / sizeof(data[0])
    );

    printf("LIN Classic Checksum = 0x%02X\n",
           checksum);

    return 0;
}

Expected Result

LIN Classic Checksum = 0x9F

14. C Program for Enhanced Checksum

The following program calculates an enhanced checksum by including the protected identifier before the data bytes.

#include <stdio.h>
#include <stdint.h>

uint8_t LIN_EnhancedChecksum(
    uint8_t pid,
    const uint8_t data[],
    uint8_t length)
{
    uint16_t sum = pid;
    uint8_t i;

    for (i = 0; i < length; i++)
    {
        sum += data[i];

        if (sum > 0xFF)
        {
            sum = (sum & 0xFF) + 1;
        }
    }

    return (uint8_t)(~sum);
}

int main(void)
{
    uint8_t pid = 0x07;

    uint8_t data[] = {0x10, 0x20};

    uint8_t checksum;

    checksum = LIN_EnhancedChecksum(
        pid,
        data,
        sizeof(data) / sizeof(data[0])
    );

    printf("LIN Enhanced Checksum = 0x%02X\n",
           checksum);

    return 0;
}

Expected Result

LIN Enhanced Checksum = 0xC8
These programs demonstrate checksum arithmetic. A production LIN implementation must also select the correct checksum model for each frame, handle diagnostic-frame exceptions and validate received frame length and data.

15. Checksum Validation at Receiver

The receiving node calculates the checksum from the received PID and/or data bytes according to the configured checksum model.

Validation Process

  1. Receive the frame response.
  2. Separate the data bytes and received checksum.
  3. Calculate the expected checksum.
  4. Compare the calculated checksum with the received checksum.
  5. Accept the response if they match.
  6. Report or handle an error if they do not match.

16. LPC2129 UART Baud-Rate Configuration

The LPC2129 UART can be used as part of a firmware-based LIN implementation. The UART baud rate must be configured according to the LIN cluster requirements.

Baud-Rate Relationship

Baud Rate = PCLK / (16 x Divisor)

Divisor = PCLK / (16 x Baud Rate)

For example, assume:

  • Peripheral clock (PCLK) = 15 MHz.
  • Required baud rate = 19,200 bps.
Divisor = 15,000,000 / (16 x 19,200)

        = 48.828 approximately

The UART divisor is an integer. The selected divisor and any fractional divider settings must be configured to achieve the closest supported baud rate.

This is the basic UART divisor relationship. Actual LPC2129 configuration must account for the selected UART peripheral, divisor registers, fractional divider settings and clock configuration. UART configuration alone does not implement the complete LIN protocol.

20. Interview Questions and Answers

Q1. What is the maximum LIN bit rate?

Answer: The commonly specified maximum LIN bit rate is 20 kbit/s.

Q2. What is bit time?

Answer: It is the time required to transmit one bit and is calculated as the reciprocal of the bit rate.

Q3. What is the difference between classic and enhanced checksum?

Answer: Classic checksum covers data bytes only. Enhanced checksum covers the protected identifier and data bytes.

Q4. What is end-around carry?

Answer: It is a checksum calculation operation in which a carry beyond the lower eight bits is added back to the lower eight-bit sum.

Q5. What is the purpose of checksum inversion?

Answer: The final eight-bit sum is inverted to produce the transmitted LIN checksum.

Q6. Which checksum is used for diagnostic frames?

Answer: Classic checksum.

Q7. How is LIN bit time calculated?

Answer: Bit time equals 1 divided by the configured bit rate.

Q8. Why is baud-rate accuracy important?

Answer: Incorrect baud-rate timing can cause the receiver to sample bits at incorrect positions.

Q9. Can a UART calculate LIN checksum automatically?

Answer: A standard UART does not automatically implement the LIN checksum rules. Firmware generally performs checksum calculation and validation.

Q10. What is required for LPC2129 LIN communication?

Answer: UART-based firmware, correct timing and an external LIN transceiver.
