2. Introduction to LIN Diagnostics

LIN diagnostics provide a mechanism for reading diagnostic information, configuring nodes and performing certain service operations in a LIN network.

In an automotive system, a LIN master may communicate with slave nodes to obtain status information or configure supported functions.

Examples of Diagnostic Applications

  • Reading node identification information.
  • Reading diagnostic trouble information.
  • Configuring slave node parameters.
  • Assigning or changing node addresses.
  • Performing supported diagnostic services.
  • Identifying communication or application faults.
LIN diagnostics are useful for maintenance, manufacturing, commissioning and troubleshooting of automotive electronic systems.

3. LIN Diagnostic Communication Architecture

Diagnostic communication normally uses the master to initiate a diagnostic request. The addressed slave processes the request and provides a response when required.

4. LIN Diagnostic Frame Identifiers

LIN reserves two frame identifiers for diagnostic communication.

Frame IdentifierProtected IdentifierPurpose
0x3C0x3CMaster Request Frame
0x3D0x7DSlave Response Frame

The six-bit frame identifier is protected by two parity bits to form the transmitted PID.

The master request frame uses frame ID 0x3C, and the slave response frame uses frame ID 0x3D. The values in the PID column include the parity bits.

5. Master Request Frame

The master request frame carries diagnostic information from the master toward the slave nodes.

Frame Characteristics

  • Uses frame identifier 0x3C.
  • Contains eight data bytes in the diagnostic transport format.
  • Is transmitted by the master.
  • May contain a diagnostic service request.
MASTER REQUEST FRAME

+-------------------------------+
| Header                        |
| Break | Sync | PID = 0x3C     |
+-------------------------------+
| Response                      |
| Data Byte 1 ... Data Byte 8   |
| Checksum                      |
+-------------------------------+

6. Slave Response Frame

The slave response frame carries diagnostic information from a slave toward the master.

Frame Characteristics

  • Uses frame identifier 0x3D.
  • Contains eight data bytes in the diagnostic transport format.
  • The master initiates the frame header.
  • The configured slave response publisher supplies the response.
SLAVE RESPONSE FRAME

+-------------------------------+
| Header                        |
| Break | Sync | PID = 0x7D     |
+-------------------------------+
| Response                      |
| Data Byte 1 ... Data Byte 8   |
| Checksum                      |
+-------------------------------+
A slave does not independently start a diagnostic response frame. The master schedules the response frame, and the addressed slave supplies the response when appropriate.

7. Node Address (NAD)

NAD stands for Node Address. It is used in LIN diagnostic communication to identify the addressed slave node or a group of nodes, according to the diagnostic addressing rules.

Purpose of NAD

  • Identify the target slave node.
  • Support diagnostic request routing.
  • Support node configuration procedures.
  • Distinguish responses from different nodes.

Diagnostic messages commonly contain NAD as part of their transport-layer data.

NAD is a diagnostic addressing field. It is not the same as the six-bit LIN frame identifier used to select a frame.

8. LIN Diagnostic Message Structure

LIN diagnostic messages use a transport protocol carried in diagnostic frames. The first data byte identifies the node address, while additional bytes contain transport and diagnostic information.

A simplified diagnostic message may contain:

FieldPurpose
NADNode address.
PCIProtocol control information, including message length or sequence information.
SIDService identifier.
Service DataParameters associated with the diagnostic request or response.

LIN diagnostic transport supports single-frame and multi-frame message transfer, with flow control and sequence handling as defined by the applicable LIN specification.

9. Diagnostic Services

Diagnostic services define the operations that a diagnostic tester can request from a node.

LIN diagnostic systems may use diagnostic services based on the UDS-related service model and LIN-specific configuration services, depending on the applicable protocol version and implementation.

Service ConceptPurpose
Read DataObtain supported node data.
Read Fault InformationRetrieve supported diagnostic trouble information.
Assign NADAssign or change a node address where supported.
Save ConfigurationStore supported node configuration information.
Assign Frame IdentifierConfigure a frame identifier for a supported node.
The exact service identifiers, request formats and supported operations depend on the LIN version and diagnostic profile. Do not assume every LIN slave supports every diagnostic service.

10. LIN Node Configuration

Node configuration is used to establish communication parameters and identify the nodes connected to a LIN cluster.

Configuration Information

  • Node address (NAD).
  • Supplier identification.
  • Function identification.
  • Variant identification.
  • Frame identifiers.
  • Signal assignments.
  • Schedule information.

Configuration procedures allow a master or diagnostic tester to identify and configure supported slave nodes.

12. LIN Description File (LDF)

An LDF (LIN Description File) describes the logical communication structure of a LIN cluster.

Information Defined in an LDF

  • LIN protocol version.
  • Bit rate.
  • Master and slave nodes.
  • Node configuration information.
  • Frames and signals.
  • Signal publishers and subscribers.
  • Schedule tables.
  • Diagnostic-related configuration information.
The LDF is an important engineering configuration file. LIN development tools use it to understand the network definition and support configuration, simulation and analysis.

14. Diagnostic Fault Handling

Diagnostic firmware should detect and record communication and application faults.

Checksum ErrorCorrupted diagnostic frame.Discard invalid data.

16. Embedded C: Diagnostic Data Structure

The following example shows a simple software structure for storing diagnostic information. It is not a complete LIN diagnostic transport implementation.

typedef struct
{
    unsigned char nad;
    unsigned char service_id;
    unsigned char data[5];
    unsigned char data_length;
} LIN_DiagnosticMessage;

LIN_DiagnosticMessage diagnostic;

void LIN_Diagnostic_Init(void)
{
    diagnostic.nad = 0x01;
    diagnostic.service_id = 0x22;
    diagnostic.data[0] = 0x01;
    diagnostic.data[1] = 0x00;
    diagnostic.data[2] = 0x00;
    diagnostic.data[3] = 0x00;
    diagnostic.data[4] = 0x00;
    diagnostic.data_length = 2;
}

This structure stores example diagnostic information. A complete implementation must encode the transport protocol control information, service parameters, checksums and frame timing correctly.

17. LIN Diagnostics Using LPC2129

The LPC2129 can be used to develop a basic diagnostic communication implementation using UART and an external LIN transceiver.

Hardware Connections

LPC2129 UART0LIN Transceiver
P0.0 / TXD0TXD
P0.1 / RXD0RXD
GroundGND reference

Software Responsibilities

  • UART initialization.
  • LIN break and synchronization handling.
  • Diagnostic frame header processing.
  • Master request and slave response handling.
  • NAD validation.
  • Diagnostic service processing.
  • Checksum and timeout handling.
The LPC2129 has no dedicated LIN controller. Diagnostic functionality must be implemented in firmware using UART and an external LIN transceiver. A complete implementation requires the relevant LIN specification and diagnostic profile.

20. Interview Questions and Answers

Q1. What is LIN diagnostics?

Answer: It is a communication mechanism used to obtain diagnostic information and perform supported configuration operations in a LIN network.

Q2. What is the master request frame ID?

Answer: The master request frame uses the six-bit identifier 0x3C.

Q3. What is the slave response frame ID?

Answer: The slave response frame uses the six-bit identifier 0x3D.

Q4. What is NAD?

Answer: NAD is the node address used to identify the addressed node in diagnostic communication.

Q5. What is an LDF?

Answer: An LDF is a LIN Description File that defines network nodes, frames, signals and schedule information.

Q6. What is the purpose of a diagnostic service?

Answer: It defines an operation such as reading supported data, retrieving fault information or configuring a node.

Q7. What happens if a slave does not respond?

Answer: The master can detect a timeout and apply the system's retry or fault-handling strategy.

Q8. Is NAD the same as a LIN frame identifier?

Answer: No. NAD identifies a diagnostic node, whereas the frame identifier selects a LIN frame.

Q9. Can every LIN node support dynamic configuration?

Answer: No. Configuration capabilities depend on the node hardware, firmware and supported diagnostic services.

Q10. Can LPC2129 implement LIN diagnostics?

Answer: Yes, using UART-based firmware and an external LIN transceiver, provided the required diagnostic transport and service functions are implemented.
