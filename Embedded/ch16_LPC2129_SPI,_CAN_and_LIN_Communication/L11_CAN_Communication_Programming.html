Lesson 11: CAN Communication Programming

Learn how to initialize the LPC2129 CAN controller, configure the acceptance filter, transmit CAN frames, receive messages and monitor communication status using Embedded C.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand the CAN communication programming sequence.
  • Identify important LPC2129 CAN registers.
  • Initialize CAN1 in normal operating mode.
  • Configure CAN bit timing.
  • Understand the CAN acceptance filter.
  • Configure a CAN transmit buffer.
  • Transmit standard CAN data frames.
  • Receive CAN messages and extract their data.
  • Monitor transmission and reception status.
  • Develop a basic CAN application using Embedded C.

2. Introduction to CAN Communication Programming

CAN communication programming involves configuring the microcontroller's CAN controller and using its registers to transmit and receive CAN frames.

The LPC2129 has two CAN controllers, CAN1 and CAN2. Each controller can communicate with an external CAN network through a suitable CAN transceiver.

3. LPC2129 CAN Controller Architecture

The CAN controller contains the hardware required to prepare, transmit and receive CAN messages.

Main Functional Blocks

  • CAN Mode Register: Selects normal, reset, listen-only and test-related modes.
  • CAN Command Register: Starts transmission and releases received messages.
  • CAN Status Register: Reports buffer and transmission status.
  • CAN Bit Timing Register: Configures nominal bit timing.
  • Transmit Buffers: Store frames waiting for transmission.
  • Receive Buffer: Holds a received frame until software releases it.
  • Acceptance Filter: Determines which received identifiers are accepted.
The acceptance filter is a shared hardware block for the CAN controllers. It is not a separate independent filter register set inside each CAN controller.

5. CAN Mode Register (C1MOD)

C1MOD controls the operating mode of the CAN1 controller.

BitNameDescription
0RMReset Mode
1LOMListen Only Mode
2STMSelf Test Mode
3TPMTransmit Priority Mode
4SMSleep Mode
5RPMReverse Polarity Mode
7TMTest Mode

Reset Mode

C1MOD = 0x01U;

When RM is set, normal CAN operation is disabled and configuration registers that require Reset Mode can be modified.

Normal Mode

C1MOD = 0x00U;

Clearing RM allows the CAN controller to operate normally, subject to the remaining configuration and physical network requirements.

6. CAN Acceptance Filter

The acceptance filter checks received CAN identifiers and determines whether a frame should be passed to the relevant CAN controller's receive buffer.

Acceptance Filter Modes

AFMR BitNameFunction
0AccOffDisables acceptance filtering when set, subject to AccBP.
1AccBPAcceptance Filter Bypass mode.
2eFCANFullCAN-related mode on supported enhanced devices.

Acceptance Filter Bypass

For a basic learning exercise, the acceptance filter can be placed in bypass mode:

AFMR = 0x02U;

This sets AccBP while leaving AccOff clear. Received messages on enabled CAN controllers are accepted without identifier screening by the lookup tables.

Acceptance Filter Bypass is useful for initial testing, but it is not a selective production filter. A real application should configure suitable identifier entries and filter tables. The acceptance filter must be disabled appropriately before modifying its lookup tables.

7. CAN Bit Timing Configuration

The CAN Bit Timing Register (C1BTR) determines the nominal CAN bit rate and sample timing.

The project clock configuration is:

CCLK = 60 MHz
VPB Clock = 15 MHz

The project configuration uses:

C1BTR = 0x00364004U;

For a 15 MHz VPB clock, this setting gives:

  • BRP field = 4, divider = 5.
  • CAN clock = 3 MHz.
  • TSEG1 field = 6, actual TSEG1 = 7 TQ.
  • TSEG2 field = 3, actual TSEG2 = 4 TQ.
  • Total = 12 TQ.
  • Nominal bit rate = 250 kbps.
  • Sample point = approximately 66.67%.
The BTR value must be written while C1MOD is in Reset Mode. Ensure the other CAN node uses compatible bit timing.

8. CAN Transmit Buffer

The LPC2129 CAN controller provides three transmit buffers. Each buffer stores one CAN message waiting for transmission.

Each transmit buffer has four main registers:

  • TFI – Transmit Frame Information.
  • TID – Transmit Identifier.
  • TDA – Transmit Data A, bytes 1–4.
  • TDB – Transmit Data B, bytes 5–8.

Transmit Frame Information Register

The TFI register contains:

  • Priority field: bits 7:0.
  • Data Length Code (DLC): bits 19:16.
  • Remote Transmission Request (RTR): bit 30.
  • Frame Format (FF): bit 31.

For an eight-byte standard data frame:

C1TFI1 = (8U << 16);

Transmit Identifier Register

For a standard 11-bit CAN identifier, the identifier is stored in bits 10:0.

C1TID1 = 0x123U;

For an extended 29-bit identifier, set the FF bit in TFI and write the 29-bit identifier to the TID register.

9. Packing CAN Data Bytes

The transmit data registers store four bytes each.

Register BitsData Byte
7:0Byte 1

Example

unsigned char data[8] =
{
    0x11, 0x22, 0x33, 0x44,
    0x55, 0x66, 0x77, 0x88
};

C1TDA1 =
      ((unsigned int)data[0])
    | ((unsigned int)data[1] << 8)
    | ((unsigned int)data[2] << 16)
    | ((unsigned int)data[3] << 24);

C1TDB1 =
      ((unsigned int)data[4])
    | ((unsigned int)data[5] << 8)
    | ((unsigned int)data[6] << 16)
    | ((unsigned int)data[7] << 24);

Using unsigned data and explicit casts avoids sign-extension problems when shifting byte values.

10. CAN Command Register (C1CMR)

The CAN Command Register initiates operations in the CAN controller. It is write-only.

BitNameFunction
0TRTransmission Request
1ATAbort Transmission
2RRBRelease Receive Buffer
3CDOClear Data Overrun
4SRRSelf Reception Request
5STB1Select Transmit Buffer 1
6STB2Select Transmit Buffer 2
7STB3Select Transmit Buffer 3

Request Transmission from Buffer 1

C1CMR = (1U << 0) | (1U << 5);

This sets TR and STB1. The controller queues the message in transmit buffer 1.

Release Receive Buffer

C1CMR = (1U << 2);

This releases the current received message so the receive buffer can accept another frame.

11. CAN Status Register (C1SR)

C1SR reports the status of the receive buffer and the three transmit buffers.

Important Status Bits

BitNameMeaning
0RBSReceive buffer status.
1DOSData overrun status.
2TBS1Transmit buffer 1 is available.
3TCS1Transmission from buffer 1 completed successfully.
4RSController is receiving a message.
5TS1Controller is transmitting from buffer 1.
6ESError status.
7BSBus status.

Before writing a transmit buffer, check its TBS bit. After requesting transmission, check the corresponding TCS bit to determine whether the frame was successfully transmitted.

A successful transmission normally requires another active CAN node to acknowledge the frame. A controller that is alone on a physical bus may repeatedly attempt transmission and report errors. Self Test Mode is a separate diagnostic option, not proof of communication with another node.

13. Embedded C: CAN1 Initialization

The following function configures CAN1 for a basic learning application.

#include <LPC21xx.h>

#define CAN_RESET       (1U << 0)
#define CAN_BTR_250K    0x00364004U

void CAN1_Init(void)
{
    /* Enter Reset Mode */
    C1MOD = CAN_RESET;

    /* Disable CAN interrupts for polling example */
    C1IER = 0x00U;

    /* Configure acceptance filter bypass */
    AFMR = 0x02U;

    /* Configure CAN1 nominal bit timing */
    C1BTR = CAN_BTR_250K;

    /* Clear optional command state */
    C1CMR = (1U << 3);

    /* Enter normal operation */
    C1MOD = 0x00U;
}

int main(void)
{
    CAN1_Init();

    while (1)
    {
        /* CAN application */
    }
}
This example assumes the CAN pin multiplexing has already been configured for the selected device package and board. Do not copy a PINSEL value without checking the LPC2129 pin-function table and the actual board schematic.

14. Embedded C: CAN1 Data Transmission

This example sends an eight-byte standard CAN data frame using transmit buffer 1.

#include <LPC21xx.h>

#define TX_BUFFER1_READY  (1U << 2)
#define TX_BUFFER1_DONE   (1U << 3)

#define CAN_TIMEOUT  1000000U

unsigned int CAN1_Transmit(
    unsigned int identifier,
    const unsigned char data[8])
{
    unsigned int timeout;

    /* Check that transmit buffer 1 is available */
    timeout = CAN_TIMEOUT;

    while ((C1SR & TX_BUFFER1_READY) == 0U)
    {
        if (timeout-- == 0U)
            return 0U;
    }

    /* Configure standard data frame, DLC = 8 */
    C1TFI1 = (8U << 16);

    /* Load 11-bit standard identifier */
    C1TID1 = identifier & 0x7FFU;

    /* Pack first four data bytes */
    C1TDA1 =
          ((unsigned int)data[0])
        | ((unsigned int)data[1] << 8)
        | ((unsigned int)data[2] << 16)
        | ((unsigned int)data[3] << 24);

    /* Pack remaining four data bytes */
    C1TDB1 =
          ((unsigned int)data[4])
        | ((unsigned int)data[5] << 8)
        | ((unsigned int)data[6] << 16)
        | ((unsigned int)data[7] << 24);

    /* Request transmission using buffer 1 */
    C1CMR = (1U << 0) | (1U << 5);

    /* Wait for successful transmission */
    timeout = CAN_TIMEOUT;

    while ((C1SR & TX_BUFFER1_DONE) == 0U)
    {
        if (timeout-- == 0U)
            return 0U;
    }

    return 1U;
}

int main(void)
{
    unsigned char tx_data[8] =
    {
        0x11, 0x22, 0x33, 0x44,
        0x55, 0x66, 0x77, 0x88
    };

    /* CAN1_Init() and pin configuration are required here */

    while (1)
    {
        CAN1_Transmit(0x123U, tx_data);
    }
}

Program Explanation

  1. Checks whether transmit buffer 1 is free.
  2. Configures the frame as a standard eight-byte data frame.
  3. Loads the 11-bit identifier.
  4. Packs eight bytes into two 32-bit data registers.
  5. Requests transmission through C1CMR.
  6. Waits for the buffer 1 transmission-complete status.
  7. Returns success or timeout.
The timeout is a software loop-count limit, not a calibrated time interval. The function also needs application-level error handling and a strategy for retrying or reporting failed transmissions.

15. CAN Receive Buffer

When an accepted CAN frame is received, the controller stores its information in the receive registers.

Receive Registers

  • C1RFS: Frame information, including DLC, RTR and frame format.
  • C1RID: Received CAN identifier.
  • C1RDA: First four data bytes.
  • C1RDB: Remaining four data bytes.

Receive Frame Status Register

BitsDescription
9:0Acceptance filter ID index.
10Acceptance filter bypass indication.
19:16Data Length Code.
30Remote Transmission Request.
31Frame Format: 0 = standard, 1 = extended.

Receive Data Length

Extract DLC using:

dlc = (C1RFS >> 16) & 0x0FU;

The received frame can contain zero to eight data bytes. A remote frame does not contain data bytes, even though its DLC indicates the requested data length.

16. Embedded C: CAN1 Data Reception

This function checks for a received frame, extracts its identifier and data bytes, and releases the receive buffer.

#include <LPC21xx.h>

#define RX_BUFFER_READY  (1U << 0)

unsigned int CAN1_Receive(
    unsigned int *identifier,
    unsigned int *dlc,
    unsigned char data[8],
    unsigned int *is_extended,
    unsigned int *is_remote)
{
    unsigned int rfs;
    unsigned int rda;
    unsigned int rdb;
    unsigned int i;

    /* Check receive buffer status */
    if ((C1GSR & RX_BUFFER_READY) == 0U)
        return 0U;

    /* Read frame status and identifier */
    rfs = C1RFS;
    *identifier = C1RID;

    /* Extract frame information */
    *dlc = (rfs >> 16) & 0x0FU;
    *is_remote = (rfs >> 30) & 1U;
    *is_extended = (rfs >> 31) & 1U;

    /* Read data registers */
    rda = C1RDA;
    rdb = C1RDB;

    /* Initialize output data */
    for (i = 0U; i < 8U; i++)
    {
        data[i] = 0U;
    }

    /* Copy data only for a data frame */
    if (*is_remote == 0U)
    {
        if (*dlc > 8U)
            *dlc = 8U;

        for (i = 0U; i < *dlc; i++)
        {
            if (i < 4U)
                data[i] = (unsigned char)(rda >> (8U * i));
            else
                data[i] = (unsigned char)(rdb >> (8U * (i - 4U)));
        }
    }

    /* Release the receive buffer */
    C1CMR = (1U << 2);

    return 1U;
}

Program Explanation

  1. Checks the receive-buffer status bit.
  2. Reads C1RFS to obtain the frame information.
  3. Reads C1RID to obtain the identifier.
  4. Extracts DLC, RTR and extended-frame status.
  5. Reads C1RDA and C1RDB.
  6. Copies the valid data bytes into the application buffer.
  7. Releases the receive buffer through C1CMR.
Read the frame information and data before releasing the receive buffer. Releasing it allows the controller to replace the current message with another received frame.

17. Complete CAN1 Polling Application

The following example combines initialization, transmission and reception into one application structure.

#include <LPC21xx.h>

#define CAN_RESET          (1U << 0)
#define CAN_BTR_250K       0x00364004U
#define CAN_RBS            (1U << 0)
#define CAN_TBS1           (1U << 2)
#define CAN_TCS1           (1U << 3)
#define CAN_TIMEOUT        1000000U

volatile unsigned int received_id;
volatile unsigned int received_dlc;
volatile unsigned int received_extended;
volatile unsigned int received_remote;
volatile unsigned char received_data[8];

void CAN1_Init(void)
{
    C1MOD = CAN_RESET;
    C1IER = 0x00U;

    /* Acceptance Filter Bypass for basic learning */
    AFMR = 0x02U;

    /* 250 kbps when VPB clock is 15 MHz */
    C1BTR = CAN_BTR_250K;

    C1MOD = 0x00U;
}

unsigned int CAN1_Send(
    unsigned int id,
    const unsigned char data[8])
{
    unsigned int i;
    unsigned int timeout;

    timeout = CAN_TIMEOUT;

    while ((C1SR & CAN_TBS1) == 0U)
    {
        if (timeout-- == 0U)
            return 0U;
    }

    C1TFI1 = (8U << 16);
    C1TID1 = id & 0x7FFU;

    C1TDA1 = 0U;
    C1TDB1 = 0U;

    for (i = 0U; i < 4U; i++)
        C1TDA1 |= ((unsigned int)data[i]) << (8U * i);

    for (i = 4U; i < 8U; i++)
        C1TDB1 |= ((unsigned int)data[i]) << (8U * (i - 4U));

    C1CMR = (1U << 0) | (1U << 5);

    timeout = CAN_TIMEOUT;

    while ((C1SR & CAN_TCS1) == 0U)
    {
        if (timeout-- == 0U)
            return 0U;
    }

    return 1U;
}

unsigned int CAN1_Receive(void)
{
    unsigned int rfs;
    unsigned int rda;
    unsigned int rdb;
    unsigned int i;

    if ((C1GSR & CAN_RBS) == 0U)
        return 0U;

    rfs = C1RFS;
    received_id = C1RID;
    received_dlc = (rfs >> 16) & 0x0FU;
    received_remote = (rfs >> 30) & 1U;
    received_extended = (rfs >> 31) & 1U;

    rda = C1RDA;
    rdb = C1RDB;

    for (i = 0U; i < 8U; i++)
        received_data[i] = 0U;

    if (received_remote == 0U)
    {
        if (received_dlc > 8U)
            received_dlc = 8U;

        for (i = 0U; i < received_dlc; i++)
        {
            if (i < 4U)
                received_data[i] =
                    (unsigned char)(rda >> (8U * i));
            else
                received_data[i] =
                    (unsigned char)(rdb >> (8U * (i - 4U)));
        }
    }

    C1CMR = (1U << 2);

    return 1U;
}

int main(void)
{
    unsigned char tx_data[8] =
    {
        0x10, 0x20, 0x30, 0x40,
        0x50, 0x60, 0x70, 0x80
    };

    CAN1_Init();

    while (1)
    {
        /* Send a standard data frame */
        CAN1_Send(0x123U, tx_data);

        /* Check for an incoming CAN frame */
        CAN1_Receive();
    }
}
This is a teaching example, not a complete production driver. It uses polling, acceptance-filter bypass and one transmit buffer. A production implementation should configure the correct pin functions, use bounded and time-based timeouts, handle all CAN error states, manage receive-buffer overruns, filter identifiers and coordinate access to shared buffers. The transmit and receive operations are independent; a received frame is not guaranteed to be the frame just transmitted.

20. CAN Interrupt-Based Communication

Instead of continuously polling status registers, a CAN application can use interrupts to respond to transmission, reception and error events.

Important Interrupt Sources

  • Receive interrupt.
  • Transmit buffer 1, 2 and 3 interrupts.
  • Error warning interrupt.
  • Data overrun interrupt.
  • Wake-up interrupt.
  • Error passive interrupt.
  • Arbitration lost interrupt.
  • Bus error interrupt.

Interrupt Enable Register

C1IER controls which CAN events can generate interrupts.

For example, the following bit selections represent receive and transmit-buffer-1 interrupt enables:

#define CAN_RIE   (1U << 0)
#define CAN_TIE1  (1U << 1)

C1IER = CAN_RIE | CAN_TIE1;
The complete interrupt implementation also requires the appropriate CAN VIC source configuration, an interrupt service routine and correct handling of C1ICR. The interrupt register reports multiple event flags and has read-to-clear behavior for several fields. Read and process it according to the NXP manual.

21. CAN Error Monitoring

CAN controllers continuously monitor communication and detect protocol errors.

Important Error Conditions

  • Bit Error: The transmitted bus level differs from the monitored bus level, subject to CAN protocol exceptions.
  • Stuff Error: An invalid bit-stuffing sequence is detected.
  • CRC Error: The received CRC does not match the calculated CRC.
  • Form Error: A fixed-format field contains an invalid bit value.
  • ACK Error: No node acknowledges a transmitted frame.

Bus-Off Condition

A CAN controller can enter Bus-Off when its transmit error counter reaches the protocol-defined bus-off threshold. In this state, it is prohibited from normal bus communication until the applicable recovery procedure is completed.

Useful status indicators include:

  • Error Status (ES).
  • Bus Status (BS).
  • Transmit Error Counter.
  • Receive Error Counter.

22. CAN Transceiver Interfacing

The LPC2129 CAN controller provides logic-level transmit and receive signals. These signals are not directly equivalent to the differential CAN bus signals.

                                     |

                                     |

                          v                     v
                    CAN Node 2             CAN Node 3

Purpose of the Transceiver

  • Converts controller logic signals to differential CAN bus signals.
  • Receives differential bus signals and converts them to logic levels.
  • Provides the physical-layer interface.
  • Supports the electrical requirements of the selected CAN network.
Do not connect LPC2129 TXD/RXD pins directly to CANH and CANL. Use a compatible external CAN transceiver and follow the board's power, grounding and termination requirements.

23. CAN Bus Termination

A typical high-speed CAN network uses termination resistors at the two physical ends of the main bus.

120 ohm                                      120 ohm
   |                                            |
 CANH ======================================== CANH
 CANL ======================================== CANL
   |                                            |
 Node A          Node B          Node C
  • Typical high-speed CAN termination is 120 Ω at each end.
  • Termination reduces signal reflections.
  • Termination resistors are normally placed at the physical bus ends, not at every node.
  • Actual termination must match the network's cable and physical-layer design.

24. Common CAN Programming Errors

  • Forgetting to configure CAN pin multiplexing.
  • Using the CPU clock instead of VPB clock for BTR calculations.
  • Writing C1BTR while the controller is not in Reset Mode.
  • Using an incorrect DLC value.
  • Writing a standard identifier outside the 11-bit range.
  • Forgetting to check transmit buffer availability.
  • Writing to a transmit buffer while it is still occupied.
  • Requesting transmission without selecting the intended transmit buffer.
  • Reading receive data but forgetting to release the receive buffer.
  • Ignoring data overrun and bus-off status.
  • Using acceptance-filter settings that reject the required identifiers.
  • Assuming the controller can drive CANH and CANL without a transceiver.
  • Expecting a successful transmission without another node to acknowledge it in normal mode.

27. Interview Questions and Answers

Q1. What is CAN communication programming?

It is the process of configuring a CAN controller and using its registers or driver functions to transmit and receive CAN frames.

Q2. How many CAN controllers are available in LPC2129?

Two CAN controllers: CAN1 and CAN2.

Q3. What is the purpose of C1MOD?

It selects the CAN1 operating mode, including Reset Mode and normal operation.

Q4. What is the purpose of C1BTR?

It configures the nominal CAN bit timing and bit rate.

Q5. What is the purpose of AFMR?

It controls the global CAN acceptance filter mode.

Q6. What is DLC?

Data Length Code specifies the number of data bytes in a Classical CAN data frame.

Q7. What is C1TID1?

It stores the identifier for the message in transmit buffer 1.

Q8. What is C1TDA1?

It stores the first four data bytes of the transmit message in buffer 1.

Q9. What is C1TDB1?

It stores data bytes 5–8 of the transmit message in buffer 1.

Q10. What does C1CMR do?

It issues commands such as requesting transmission and releasing the receive buffer.

Q11. What is the purpose of C1GSR?

It reports global CAN status, including receive-buffer availability, transmit-buffer availability and error status.

Q12. Why is a CAN transceiver required?

It converts the controller's logic-level TXD/RXD signals to and from differential CAN bus signals.

Q13. What is a CAN acceptance filter?

It screens received CAN identifiers and determines which messages are accepted by the controller.

Q14. What is a CAN bus-off condition?

It is a fault state in which the controller is prohibited from normal bus communication because its transmit error counter has reached the bus-off threshold.
