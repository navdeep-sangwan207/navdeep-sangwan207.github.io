2. Introduction to LIN Message Scheduling

LIN is a master-controlled communication protocol. Slave nodes do not normally initiate scheduled communication independently.

The master decides:

  • Which frame should be transmitted.
  • When a frame should be transmitted.
  • How frequently a frame should appear.
  • Which schedule table should be active.

This organized communication process is called message scheduling.

Key concept: The LIN master controls frame initiation according to a predefined schedule. This makes communication predictable and avoids normal bus-access collisions.

3. What Is a LIN Schedule Table?

A LIN schedule table is an ordered list of frame transmissions and their associated time slots. The master follows this table to determine when to send each frame header.

Example

LIN SCHEDULE TABLE

Slot 1  -> Door Status Frame
Slot 2  -> Window Control Frame
Slot 3  -> Mirror Position Frame
Slot 4  -> Lighting Status Frame
Slot 5  -> Door Status Frame
              |
              v
          Repeat Cycle

Each entry identifies a frame to be initiated by the master at the corresponding point in the schedule.

Purpose of Schedule Tables

  • Organize communication between nodes.
  • Provide predictable message timing.
  • Control the order of frame transmission.
  • Support periodic data updates.
  • Reduce unnecessary bus traffic.

4. Role of the Master Task in Scheduling

The master node contains the master task, which controls the communication schedule.

Master Task Responsibilities

  1. Select the active schedule table.
  2. Determine the next scheduled frame.
  3. Wait for the required frame slot.
  4. Transmit the frame header.
  5. Allow the designated publisher to transmit the response.
  6. Move to the next schedule entry.
        MASTER TASK
             |
             v

             v

             |

     Advance Schedule

The master task schedules the frame. The slave task associated with a particular frame may publish its response when that frame is requested.

5. Frame Slots and Slot Duration

A frame slot is the time allocated in the schedule for a particular frame transmission.

Slot duration must be sufficient for the expected frame transmission and the required protocol timing margins.

Factors Affecting Slot Duration

  • LIN baud rate.
  • Number of data bytes in the response.
  • Break and delimiter timing.
  • Header and response transmission time.
  • Inter-byte and scheduling margins.

Conceptual Slot Diagram

Time ---------------------------------------------------->

|----------- Slot 1 -----------|
|----------- Slot 2 -----------|
|----------- Slot 3 -----------|
|----------- Slot 4 -----------|

    Frame 1      Frame 2
      |             |
      v             v
   Header         Header
   Response       Response

Slots are arranged so that the next scheduled frame can begin at the correct time without overlapping the previous frame.

6. Unconditional Frames

An unconditional frame is transmitted according to its scheduled slot. Its publisher sends the response whenever the master requests that frame.

Characteristics

  • Has a predefined frame identifier.
  • Has a designated publisher.
  • Is transmitted according to the schedule.
  • Can carry periodic information such as sensor values or switch status.

Example

A door-control module periodically publishes door status.

Master sends Door Status Header
              |
              v
Door Module publishes response
              |
              v
Other nodes receive door status

7. Sporadic Frames

A sporadic frame is used to transmit information that does not need to be sent during every repetition of the schedule.

The master checks whether the associated publisher has updated data. If suitable data is pending, the master schedules the corresponding frame transmission.

Characteristics

  • Supports less frequently changing information.
  • Can reduce unnecessary bus traffic.
  • Is managed by the master schedule.
  • Requires defined conditions for deciding when to transmit.

Example

A vehicle lighting controller may report a change in a less frequently updated status value.

A sporadic frame is not an independently initiated slave transmission. The master still controls when its header is sent.

8. Event-Triggered Frames

An event-triggered frame allows multiple slave nodes to share a frame identifier when their data is associated with the same type of event.

The master sends the event-triggered header. A slave with relevant updated data may respond.

Collision Situation

If more than one slave responds at the same time, a response collision can occur. The master may detect an invalid response and use associated unconditional frames to identify which slave has pending data.

Conceptual Example

             MASTER
                |
                | Event-triggered header
                v

         |             |
         v             v

                v
       Master polls associated
        unconditional frames

Event-triggered frames are useful when events are not always present and multiple nodes may share a response opportunity.

Event-triggered frames require carefully configured identifiers and associated unconditional frames. They are not simply ordinary frames with multiple publishers transmitting simultaneously.

9. Diagnostic Frames and Scheduling

LIN also defines diagnostic communication using specific frame identifiers.

Frame IdentifierPurpose
0x3CMaster request frame
0x3DSlave response frame

These diagnostic frames are used for diagnostic requests and responses between the master and slave nodes.

Examples of Diagnostic Information

  • Read diagnostic information.
  • Retrieve fault information.
  • Perform node configuration operations.
  • Support diagnostic services defined for the network.
Diagnostic frames use the classic checksum. Diagnostic communication must be scheduled by the master.

10. Schedule Table Switching

A LIN master may use different schedule tables for different operating conditions.

Example: Vehicle Operating Modes

Operating ModeSchedule Example
Normal operationDoor, window, mirror and lighting status.
Diagnostic modeDiagnostic request and response frames.
Low-power modeReduced communication activity.
Configuration modeNode configuration-related communication.

The master can switch between schedules according to the network's application requirements and defined timing rules.

12. LIN Description File (LDF)

The LIN Description File (LDF) is used to describe the configuration of a LIN network.

Information Defined in an LDF

  • LIN protocol version and baud rate.
  • Master and slave node information.
  • Frame identifiers and publishers.
  • Signals and their definitions.
  • Schedule tables.
  • Signal-to-frame mapping.

Engineering tools can use the LDF to configure and analyze LIN networks.

The LDF is a network description and configuration artifact. It is not itself the runtime schedule executing inside the microcontroller.

13. Scheduling Advantages

  • Predictable communication timing.
  • Controlled bus access.
  • Reduced communication collisions during normal scheduled operation.
  • Efficient handling of periodic messages.
  • Support for different operating modes.
  • Suitable for low-cost automotive networks.

14. LPC2129-Based LIN Scheduling Concept

The LPC2129 has no dedicated LIN controller. A firmware-based LIN master can use a UART and an external LIN transceiver to implement the communication process.

Firmware Responsibilities

  • Maintain a schedule table in program memory or RAM.
  • Track the active schedule entry.
  • Generate the appropriate frame header.
  • Receive or transmit the response as required.
  • Validate the checksum.
  • Advance to the next schedule entry.

Conceptual C Schedule Table

#include <stdint.h>

typedef struct
{
    uint8_t frame_id;
    uint16_t slot_time_ms;
} LIN_ScheduleEntry;

LIN_ScheduleEntry schedule[] =
{
    {0x10, 10},  // Door status
    {0x11, 20},  // Window command
    {0x12, 20},  // Mirror position
    {0x13, 50}   // Lighting status
};

#define SCHEDULE_COUNT \
    (sizeof(schedule) / sizeof(schedule[0]))

This code only represents a conceptual schedule data structure. A complete implementation also needs timing control, LIN header generation, response handling and checksum processing.

The code above is not a complete LIN driver. Keil simulation can test schedule-table logic, but physical LIN communication requires a suitable transceiver and hardware setup.

17. Interview Questions and Answers

Q1. What is a LIN schedule table?

Answer: It is an ordered list of frame transmissions followed by the master to control LIN communication timing.

Q2. Who controls LIN message scheduling?

Answer: The LIN master task.

Q3. What is a frame slot?

Answer: It is the allocated time interval for a scheduled frame transmission.

Q4. What is an unconditional frame?

Answer: A frame transmitted according to its schedule, with a predefined publisher.

Q5. What is a sporadic frame?

Answer: A frame scheduled by the master when relevant updated data is pending.

Q6. What is an event-triggered frame?

Answer: A frame that allows multiple configured slave nodes to share a response opportunity associated with an event.

Q7. What happens when two slaves respond to an event-triggered frame?

Answer: A response collision may occur. The master can then use associated unconditional frames to identify the responding node or nodes.

Q8. What is an LDF?

Answer: A LIN Description File that defines network configuration, nodes, frames, signals and schedule tables.

Q9. Why are multiple schedule tables useful?

Answer: They allow the master to organize communication differently for operating conditions such as normal operation and diagnostics.

Q10. Does a LIN slave control the schedule?

Answer: No. The master controls the schedule and initiates normal frame communication.

18. Lesson Summary

  • LIN uses master-controlled message scheduling.
  • A schedule table defines the order and timing of frame transmissions.
  • The master task initiates each scheduled frame.
  • A frame slot is the time allocated for a frame.
  • LIN supports unconditional, sporadic and event-triggered frame types.
  • Diagnostic communication uses dedicated frame identifiers.
  • Schedule table switching supports different operating modes.
  • The LDF describes the LIN network configuration.
  • LPC2129 can implement schedule logic using firmware, UART and an external LIN transceiver.
