2. Introduction to UART-Based LIN Communication

LIN communication can be implemented using a microcontroller UART together with an external LIN transceiver.

The UART provides serial data transmission and reception. The microcontroller firmware handles LIN-specific operations such as:

  • Break-field generation.
  • Synchronization byte transmission.
  • Protected identifier generation.
  • Data transmission and reception.
  • Checksum calculation and verification.
  • Frame scheduling and timing.

UART provides the serial communication mechanism, while firmware implements the LIN protocol behavior. The external transceiver provides the LIN physical-layer interface.

3. Difference Between UART and LIN

UARTLIN
Serial communication interface.Automotive communication protocol.
Uses TX and RX logic signals.Uses a single-wire bus.
Does not define a master schedule.Uses master-scheduled communication.
Does not define LIN frame fields.Defines break, sync, PID, data and checksum fields.
Does not require a LIN transceiver for ordinary logic-level UART.Requires a suitable physical-layer transceiver.

A UART can be used as the serial engine for a LIN implementation, but ordinary UART communication alone is not automatically LIN communication.

6. Generating the LIN Break Field

The break field is a special dominant-low signal that marks the beginning of a LIN frame.

In normal UART transmission, a byte begins with a start bit and ends with a stop bit. A LIN break is longer than a normal UART start bit and therefore requires special handling.

Break Generation Methods

  • Use a UART peripheral's break-generation feature, if available.
  • Use a supported low-speed or GPIO-based method to create the required dominant interval.
  • Use timer-controlled signaling when appropriate.

A normal 0x00 UART byte is not automatically a valid LIN break. The break must meet the required LIN timing and delimiter conditions.

7. Synchronization Byte Transmission

After the break field and delimiter, the master transmits the synchronization byte.

The synchronization byte is:

SYNC = 0x55

Binary representation:

0x55 = 01010101

The alternating bit pattern allows a slave node to measure bit timing and synchronize its communication.

Transmission Sequence

1. Generate LIN break
2. Generate break delimiter
3. Transmit 0x55
4. Transmit protected identifier

8. Protected Identifier Transmission

The protected identifier (PID) contains a six-bit frame identifier and two parity bits.

+-----------------------------+
| ID5 ID4 ID3 ID2 ID1 ID0 P1 P0 |
+-----------------------------+
       6-bit ID       2 parity bits

The parity equations are:

P0 = ID0 XOR ID1 XOR ID2 XOR ID4

P1 = NOT (ID1 XOR ID3 XOR ID4 XOR ID5)

The microcontroller firmware calculates the parity bits and combines them with the six-bit identifier before transmitting the PID.

Example

For frame identifier 0x12:

  • Six-bit identifier = 010010
  • P0 = 1
  • P1 = 0
  • PID = 0x52

9. LIN Data Transmission Using UART

After the master transmits the header, the configured publisher sends the response.

The response consists of:

  • One to eight data bytes.
  • One checksum byte.

Example Data

Data Byte 1 = 0x10
Data Byte 2 = 0x20
Data Byte 3 = 0x30

The publisher transmits these bytes through its UART and LIN transceiver according to the frame timing.

The publisher may be the master or a slave node. The master always initiates the frame header in normal scheduled communication.

10. LIN Checksum Handling

The checksum is used to detect transmission errors.

Checksum TypeCalculation
Classic ChecksumCalculated using data bytes only.
Enhanced ChecksumCalculated using the protected identifier and data bytes.

For LIN 2.x, enhanced checksum is generally used for ordinary communication frames, while diagnostic frames use classic checksum.

Checksum Algorithm

  1. Add the required bytes using an 8-bit accumulator.
  2. Whenever the addition exceeds 255, apply end-around carry.
  3. Invert the final 8-bit sum.
checksum = bitwise NOT (8-bit sum)

The checksum must be calculated and checked by the firmware when required by the frame type.

14. LPC2129 UART0 Initialization Example

The following example demonstrates basic UART0 initialization for 19,200 bit/s using the standard divisor relationship. It is a starting point for UART communication, not a complete LIN implementation.

#include <LPC21xx.h>

void UART0_Init(void)
{
    // Configure P0.0 as TXD0 and P0.1 as RXD0
    PINSEL0 |= 0x00000005;

    // Enable access to divisor latches
    U0LCR = 0x83;

    // PCLK = 15 MHz
    // Divisor approximately 49 for 19,200 baud
    U0DLL = 49;
    U0DLM = 0;

    // 8 data bits, no parity, 1 stop bit
    // Disable divisor latch access
    U0LCR = 0x03;
}

void UART0_Tx(char data)
{
    while ((U0LSR & (1 << 5)) == 0);

    U0THR = data;
}

char UART0_Rx(void)
{
    while ((U0LSR & 1) == 0);

    return U0RBR;
}

int main(void)
{
    UART0_Init();

    while (1)
    {
        UART0_Tx('L');
        UART0_Tx('I');
        UART0_Tx('N');

        UART0_Tx('\r');
        UART0_Tx('\n');
    }
}
The divisor value above is an approximate starting value. With PCLK = 15 MHz and a simple 16x divisor calculation, the ideal divisor is about 48.83. Verify the actual baud rate and fractional-divider configuration against the LPC2129 datasheet and the selected clock settings.

15. Basic LIN Frame Transmission Pseudocode

The following pseudocode illustrates the logical sequence of a LIN master frame. Hardware-specific break generation and timing must be implemented separately.

void LIN_Master_Transmit_Frame(void)
{
    // Step 1: Generate LIN break
    LIN_Generate_Break();

    // Step 2: Send synchronization byte
    UART0_Tx(0x55);

    // Step 3: Calculate protected identifier
    unsigned char pid = LIN_Calculate_PID(0x12);

    // Step 4: Send protected identifier
    UART0_Tx(pid);

    // Step 5: Receive or transmit response
    LIN_Process_Response();
}

LIN_Generate_Break(), LIN_Calculate_PID() and LIN_Process_Response() are illustrative functions. Their implementations must follow the selected hardware and LIN timing requirements.

16. Important Implementation Considerations

  • UART baud rate must match the LIN communication rate.
  • The break field must meet the required timing.
  • The synchronization byte must be 0x55.
  • The PID parity bits must be calculated correctly.
  • The publisher must respond within the scheduled frame timing.
  • Checksum type must match the frame type.
  • The transceiver must be in the correct operating mode.
  • Firmware must handle receive errors and timeouts.
  • Master scheduling must be implemented by firmware.

20. Interview Questions and Answers

Q1. Can LIN communication be implemented using UART?

Answer: Yes. A UART can provide serial transmission and reception, while firmware handles LIN protocol operations and an external transceiver provides the physical interface.

Q2. What is the LIN synchronization byte?

Answer: The synchronization byte is 0x55. It allows slave nodes to synchronize their bit timing.

Q3. Why is a break field required?

Answer: It indicates the beginning of a LIN frame and helps the slave nodes recognize the header.

Q4. What is the purpose of the PID?

Answer: The protected identifier identifies the frame and contains two parity bits for error detection.

Q5. Who transmits the LIN header?

Answer: The LIN master transmits the header.

Q6. Who transmits the LIN response?

Answer: The configured publisher transmits the response. It may be the master or a slave.

Q7. What is the maximum LIN bit rate?

Answer: The standard LIN maximum communication rate is 20 kbit/s.

Q8. Does LPC2129 have a dedicated LIN controller?

Answer: No. UART-based firmware and an external LIN transceiver can be used to implement LIN communication.

Q9. What is the purpose of the checksum?

Answer: It helps detect errors in the transmitted frame response.

Q10. How can LIN communication be tested?

Answer: A LIN analyzer and oscilloscope can be used to inspect protocol frames, bus voltage and timing.

21. Lesson Summary

  • UART can be used as the serial engine for LIN communication.
  • An external transceiver is required for the LIN physical layer.
  • Firmware handles break, sync, PID, data, checksum and scheduling.
  • The synchronization byte is 0x55.
  • The PID contains a six-bit identifier and two parity bits.
  • A LIN 2.x response contains 1–8 data bytes and a checksum.
  • The master initiates normal scheduled frames.
  • The configured publisher sends the response.
  • LPC2129 UART0 uses P0.0 and P0.1.
  • Physical LIN behavior requires suitable hardware testing.
