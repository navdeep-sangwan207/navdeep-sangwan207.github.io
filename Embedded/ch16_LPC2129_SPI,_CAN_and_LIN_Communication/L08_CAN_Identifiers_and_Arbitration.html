Lesson 08: CAN Identifiers and Arbitration

Understand CAN message identifiers, priority assignment, bit-by-bit arbitration, standard and extended frame arbitration, and how multiple nodes share the CAN bus without destroying the winning message.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain the purpose of a CAN identifier.
  • Differentiate message identification from node addressing.
  • Understand standard and extended identifiers.
  • Explain how CAN message priority is assigned.
  • Understand dominant and recessive bus states.
  • Describe bit-by-bit CAN arbitration.
  • Explain why CAN arbitration is non-destructive.
  • Analyze arbitration between multiple transmitting nodes.
  • Understand arbitration between standard and extended frames.
  • Identify practical CAN network design considerations.

2. What Is a CAN Identifier?

A CAN identifier is a field in a CAN frame that identifies the message being transmitted. It also determines the message's priority when multiple nodes attempt to transmit simultaneously.

Unlike communication protocols that use a destination address to identify a receiving device, CAN normally uses message-oriented communication. All nodes can observe transmitted frames, and each node decides which messages are relevant to it.

Example

CAN Identifier: 0x123
Message: Vehicle speed information

CAN Identifier: 0x200
Message: Engine temperature information

CAN Identifier: 0x300
Message: Battery voltage information

The identifier-to-message mapping is defined by the network communication design. These examples are illustrative.

Important: A CAN identifier is not necessarily the address of a transmitting node or receiving node. It identifies the message.

4. Identifier and Message Priority

CAN uses identifier-based priority. A lower numerical identifier has higher priority when competing frames are compared under the CAN arbitration rules.

Example Priority Assignment

IdentifierExample MessageRelative Priority
0x080Critical motor-control statusHighest among these examples
0x120Vehicle speedSecond
0x250Temperature dataThird
0x500Diagnostic informationLowest among these examples
A lower identifier generally wins arbitration because its binary representation presents a dominant bit earlier than a competing higher identifier. The actual priority plan must be designed for the complete network.

Important Design Considerations

  • Assign high priority to time-critical messages.
  • Assign lower priority to non-critical background messages.
  • Consider message transmission frequency.
  • Consider worst-case bus loading.
  • Avoid assigning identifiers without a network-wide plan.

5. Dominant and Recessive Bits

CAN uses two logical bus states:

StateLogical ValueBus Behavior
Dominant0Overrides a recessive bit.
Recessive1Remains visible when all transmitting nodes send recessive.

Wired-AND Behavior

At the logical level, the shared CAN bus behaves like a wired-AND arrangement: a dominant zero from any transmitting node makes the observed bus state dominant.

Node A transmits: 0
Node B transmits: 1
--------------------
Bus state:         0
The dominant state wins over the recessive state. This electrical property makes CAN arbitration possible.

6. What Is CAN Arbitration?

CAN arbitration is the process used to decide which node may continue transmitting when two or more nodes begin transmitting at the same time.

Each transmitting node monitors the bus while sending its identifier. If a node sends a recessive bit but observes a dominant bit, it recognizes that another node has a higher-priority message and stops transmitting.

Arbitration Characteristics

  • Multiple nodes may start transmission together.
  • Each node sends its identifier bit by bit.
  • Dominant bits override recessive bits.
  • A node that loses arbitration stops transmitting.
  • The winning node continues its frame without restarting.
  • The losing node can attempt transmission again when the bus becomes available.

7. Non-Destructive Arbitration

CAN arbitration is called non-destructive because the arbitration process does not corrupt the frame transmitted by the winning node.

Nodes compare their transmitted bits with the actual bus state. A losing node stops transmitting as soon as it detects that it has lost arbitration.

Node A:  Identifier bits ----\
                               +---- Shared CAN Bus
Node B:  Identifier bits ----/          |
                                          |
                              Dominant/recessive comparison
                                          |
                                  Winning node continues
                                  Losing node stops

Why Is It Non-Destructive?

  1. All nodes synchronize at the beginning of the frame.
  2. They transmit identifier bits in the same order.
  3. The bus resolves conflicting bits using dominant and recessive states.
  4. A losing node withdraws before it corrupts the winning frame.
  5. The winning node continues transmitting the remaining fields.

8. Bit-by-Bit Arbitration Example

Consider two nodes transmitting standard identifiers simultaneously.

Node A Identifier = 0x100
Node B Identifier = 0x120

Convert Identifiers to 11-Bit Binary

Node A: 00100000000
Node B: 00100100000
Bit PositionNode ANode BBus StateResult
1000Both continue
2000Both continue
3111Both continue
4000Both continue
5000Both continue
6010Node B loses

Explanation

  • Both nodes transmit the same bits through the first five positions.
  • At the sixth position, Node A sends dominant 0.
  • Node B sends recessive 1.
  • The bus state is dominant 0.
  • Node B detects the mismatch and stops transmitting.
  • Node A continues its frame.
Winner: Node A — 0x100
The lower identifier, 0x100, wins because its first differing bit is dominant while the competing identifier transmits recessive.

9. Another Arbitration Example

Consider three nodes transmitting the following standard identifiers:

Node A = 0x080
Node B = 0x100
Node C = 0x200

11-Bit Binary Values

Node A = 00010000000
Node B = 00100000000
Node C = 01000000000

At the first identifier bit:

  • Node A transmits dominant 0.
  • Node B transmits dominant 0.
  • Node C transmits recessive 1.
  • Node C loses arbitration.

Nodes A and B continue comparing their identifiers. At the next differing bit, Node A sends dominant 0 while Node B sends recessive 1. Node B loses.

Winner: Node A — 0x080

10. Arbitration and Identifier Ordering

For standard frames of the same format, comparing identifiers numerically gives the priority order: the smaller identifier wins.

0x080 < 0x100 < 0x200 < 0x500

Priority:
0x080 = Highest
0x100 = Second
0x200 = Third
0x500 = Lowest

This rule is useful for assigning message identifiers in an embedded network.

Do not assume that comparing only the numerical identifier is sufficient for every mixed standard/extended arbitration case. The frame-format bits also participate in arbitration.

11. Standard and Extended Frame Arbitration

Standard and extended frames use different identifier formats. Their arbitration fields must be considered together.

Important Arbitration Fields

FieldStandard FrameExtended Frame
Identifier base11-bit identifier11-bit base identifier
SRRNot presentRecessive substitute remote request bit
IDEDominantRecessive
Identifier extensionNot present18 additional identifier bits

Standard Versus Extended Arbitration

When a standard frame and an extended frame have the same first 11 identifier bits, the standard frame wins at the format comparison point.

The standard frame transmits a dominant RTR bit in the position where the extended frame transmits the recessive SRR bit. The dominant standard-frame bit therefore wins arbitration.

The result depends on the arbitration fields, not simply on comparing an 11-bit number with a 29-bit number as ordinary integers.

12. Arbitration and Remote Frames

In Classical CAN, the RTR bit also participates in arbitration.

FrameRTR BitRelative Result for Otherwise Matching Standard Identifier
Data frameDominant 0Higher priority
Remote frameRecessive 1Loses to matching data frame

If a data frame and remote frame use the same standard identifier and begin together, the data frame wins at the RTR bit because dominant 0 overrides recessive 1.

13. What Happens to a Losing Node?

A node that loses arbitration does not treat the event as a transmission error.

  • It stops transmitting its frame.
  • It changes to receiver behavior and observes the winning frame.
  • It does not send an error frame merely because it lost arbitration.
  • It can attempt to transmit again when the bus becomes available.
Losing arbitration is a normal CAN bus operation. It is not the same as detecting a bit, CRC or form error.

15. CAN Arbitration Timing

Arbitration occurs during the identifier and associated arbitration fields. Each node must sample the bus at the correct point in the bit period.

Important Timing Parameters

  • Nominal bit rate.
  • Synchronization segment.
  • Propagation segment.
  • Phase segments.
  • Sample point.
  • Synchronization jump width.

All nodes on a CAN network must use compatible nominal bit timing.

Arbitration reliability depends on correct bit timing, oscillator tolerance, cable propagation delay, transceiver characteristics and network topology.

16. Priority and Bus Loading

Identifier priority influences how quickly a message can gain access to the bus.

High-Priority Messages

  • Safety-related information.
  • Time-critical motor-control messages.
  • Fast-changing control signals.

Lower-Priority Messages

  • Non-critical diagnostic information.
  • Slow-changing status information.
  • Background monitoring data.
A low-priority message can experience long delays if higher-priority traffic continuously occupies the bus. Network design must consider worst-case response time and bus utilization.

17. CAN Acceptance Filtering

Acceptance filtering allows a CAN controller to select which received identifiers should be passed to the application or receive buffers.

Purpose

  • Reduce unnecessary software processing.
  • Accept relevant message identifiers.
  • Reject unwanted traffic from application-level handling.
  • Improve receive-buffer management.

Acceptance filtering does not change the priority of a message on the bus. Arbitration is performed by the CAN protocol itself.

The LPC2129 includes an Acceptance Filter that can be configured to select messages for its CAN controllers. Detailed LPC2129 CAN controller programming is covered in the later lessons of this chapter.

20. Common Mistakes

  • Assuming the CAN identifier is always a device address.
  • Assuming a higher numerical identifier has higher priority.
  • Confusing dominant and recessive bit values.
  • Assuming arbitration loss is a CAN transmission error.
  • Assuming a losing node corrupts the winning frame.
  • Comparing standard and extended identifiers without considering IDE and SRR.
  • Ignoring bus loading and message deadlines.
  • Assuming acceptance filtering changes bus arbitration.

21. Interview Questions and Answers

Q1. What is a CAN identifier?

A field that identifies a CAN message and participates in determining its priority.

Q2. What is the length of a standard CAN identifier?

11 bits.

Q3. What is the length of an extended CAN identifier?

29 bits.

Q4. Which identifier has higher priority?

For otherwise comparable frames, the lower numerical identifier has higher priority.

Q5. What is CAN arbitration?

A process that selects which node continues transmitting when multiple nodes start together.

Q6. Why is CAN arbitration non-destructive?

A losing node stops transmitting when it detects a dominant bus bit where it sent recessive, allowing the winning frame to continue.

Q7. What is a dominant bit?

Logical 0, which overrides a recessive bit on the shared bus.

Q8. What is a recessive bit?

Logical 1, which is visible when no node drives a dominant state.

Q9. Does arbitration loss generate an error frame?

No. Losing arbitration is normal CAN behavior and does not itself generate an error frame.

Q10. What happens to a node that loses arbitration?

It stops transmitting, receives the winning frame and retries when the bus becomes available.

Q11. Does acceptance filtering determine message priority?

No. Acceptance filtering selects received messages for controller handling; it does not change arbitration priority.

Q12. Which frame wins when matching standard and extended frames have the same first 11 identifier bits?

The standard frame wins at the arbitration comparison between its dominant RTR bit and the extended frame's recessive SRR bit.

24. Lesson Summary

  • CAN identifiers identify messages and determine arbitration priority.
  • Standard identifiers contain 11 bits.
  • Extended identifiers contain 29 bits.
  • Lower numerical identifiers generally have higher priority.
  • Dominant represents logical 0.
  • Recessive represents logical 1.
  • Dominant bits override recessive bits.
  • Arbitration is performed bit by bit.
  • A node loses when it sends recessive but observes dominant during arbitration.
  • Arbitration is non-destructive.
  • Arbitration loss is not itself a transmission error.
  • Acceptance filtering does not change bus priority.
