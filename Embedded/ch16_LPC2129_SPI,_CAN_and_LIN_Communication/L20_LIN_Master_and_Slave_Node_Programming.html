2. Introduction to LIN Node Programming

A LIN network consists of one master node and one or more slave nodes. Each node contains a microcontroller or controller responsible for executing communication-related software.

Master Node Responsibilities

  • Maintain the LIN schedule.
  • Initiate communication by transmitting frame headers.
  • Generate break and synchronization fields.
  • Transmit the protected identifier.
  • Receive or publish the frame response according to the schedule.
  • Monitor communication errors and timing.

Slave Node Responsibilities

  • Monitor the LIN bus.
  • Recognize the break and synchronization fields.
  • Receive and validate the protected identifier.
  • Publish data when configured as the publisher.
  • Receive data when configured as a subscriber.
  • Check the received checksum.
The master initiates normal scheduled communication. The publisher of a particular frame may be either the master or a slave.

5. LIN Protected Identifier Calculation

The protected identifier contains six identifier bits and two parity bits.

+-----------------------------+
| ID5 ID4 ID3 ID2 ID1 ID0 P1 P0 |
+-----------------------------+
       6-bit ID       2 parity bits

The parity equations are:

P0 = ID0 XOR ID1 XOR ID2 XOR ID4

P1 = NOT (ID1 XOR ID3 XOR ID4 XOR ID5)

Embedded C Function

unsigned char LIN_Calculate_PID(unsigned char id)
{
    unsigned char id0, id1, id2;
    unsigned char id3, id4, id5;
    unsigned char p0, p1;

    id = id & 0x3F;

    id0 = (id >> 0) & 1;
    id1 = (id >> 1) & 1;
    id2 = (id >> 2) & 1;
    id3 = (id >> 3) & 1;
    id4 = (id >> 4) & 1;
    id5 = (id >> 5) & 1;

    p0 = id0 ^ id1 ^ id2 ^ id4;

    p1 = !(id1 ^ id3 ^ id4 ^ id5);

    return (id | (p0 << 6) | (p1 << 7));
}

Example

For the six-bit identifier 0x12:

  • Identifier = 010010
  • P0 = 1
  • P1 = 0
  • PID = 0x52
The identifier is limited to six bits before parity calculation. The resulting PID is an eight-bit value.

9. LIN Checksum Function

The checksum calculation uses an 8-bit accumulator with end-around carry, followed by inversion.

Embedded C Function

unsigned char LIN_Checksum(
    unsigned char *data,
    unsigned char length,
    unsigned char pid,
    unsigned char enhanced)
{
    unsigned int sum = 0;
    unsigned char i;

    if (enhanced)
    {
        sum += pid;
    }

    for (i = 0; i < length; i++)
    {
        sum += data[i];

        if (sum > 255)
        {
            sum = (sum & 0xFF) + 1;
        }
    }

    return (unsigned char)(~sum);
}

Use enhanced = 0 for classic checksum and enhanced = 1 for enhanced checksum. The PID is included only in the enhanced calculation.

Diagnostic frames use classic checksum. Checksum selection must follow the LIN frame type and protocol version.

10. Basic UART-Based LIN Master Program Structure

The following is an illustrative firmware structure. It shows the order of master operations; hardware-specific break generation, response timing, timeout handling and schedule execution must be implemented for the selected platform.

#include <LPC21xx.h>

void UART0_Init(void);
void UART0_Tx(unsigned char data);
void LIN_Generate_Break(void);
unsigned char LIN_Calculate_PID(unsigned char id);

void LIN_Master_Send_Header(unsigned char id)
{
    unsigned char pid;

    // Generate LIN break field
    LIN_Generate_Break();

    // Send synchronization byte
    UART0_Tx(0x55);

    // Calculate protected identifier
    pid = LIN_Calculate_PID(id);

    // Send protected identifier
    UART0_Tx(pid);
}

int main(void)
{
    UART0_Init();

    while (1)
    {
        // Send header for frame ID 0x12
        LIN_Master_Send_Header(0x12);

        // Response processing and schedule timing
        // must be implemented here.
    }
}

The program is a structural example, not a complete standards-compliant LIN master. In a real master, frame scheduling, response transmission/reception and timing must be handled correctly.

11. Basic UART-Based LIN Slave Program Structure

The slave waits for a header, validates the received identifier and then performs the configured publisher or subscriber action.

#include <LPC21xx.h>

void UART0_Init(void);
unsigned char UART0_Rx(void);
void UART0_Tx(unsigned char data);

#define SLAVE_FRAME_ID 0x12

void LIN_Slave_Process(void)
{
    unsigned char pid;
    unsigned char frame_id;

    // Receive PID after break and sync
    // have been detected and processed.
    pid = UART0_Rx();

    // Extract six-bit identifier
    frame_id = pid & 0x3F;

    if (frame_id == SLAVE_FRAME_ID)
    {
        // Validate PID parity before use.

        // If this node is the publisher,
        // transmit its configured response.

        // If this node is a subscriber,
        // receive and process the response.
    }
}

int main(void)
{
    UART0_Init();

    while (1)
    {
        LIN_Slave_Process();
    }
}
This is a software-structure example only. A production slave must detect the break field, synchronize, validate PID parity, respect response timing and distinguish publisher from subscriber behavior.

12. Publisher and Subscriber Programming

Each LIN frame has a configured publisher and may have multiple subscribers.

Publisher

  • Provides the response data.
  • Transmits the configured data bytes.
  • Transmits the checksum.

Subscriber

  • Receives the response.
  • Processes the received data.
  • Checks the checksum.

16. Common Programming Mistakes

  • Using an ordinary UART byte instead of a correctly timed LIN break.
  • Incorrect synchronization byte.
  • Incorrect PID parity calculation.
  • Using the wrong checksum type.
  • Allowing a slave to transmit without being the configured publisher.
  • Ignoring the master's schedule.
  • Using incorrect baud-rate settings.
  • Failing to handle response timeouts.
  • Connecting UART pins directly to the LIN bus.

19. Interview Questions and Answers

Q1. What is the main responsibility of a LIN master?

Answer: The master manages the schedule and initiates normal communication by transmitting frame headers.

Q2. Can a slave node transmit data?

Answer: Yes. A slave transmits data when it is the configured publisher for the frame initiated by the master.

Q3. What is a protected identifier?

Answer: It is an eight-bit field containing a six-bit frame identifier and two parity bits.

Q4. What is a schedule table?

Answer: It defines the order and timing of frames initiated by the LIN master.

Q5. What is the difference between publisher and subscriber?

Answer: The publisher supplies the response data, while subscribers receive and process it.

Q6. Why is PID validation important?

Answer: It detects invalid or corrupted protected identifiers before the node processes the frame.

Q7. What happens if the checksum is incorrect?

Answer: The receiving node detects an invalid response and can reject or flag it according to the application error-handling policy.

Q8. Can LPC2129 act as a LIN master?

Answer: Yes, using UART-based firmware and an external LIN transceiver. The firmware must implement the LIN master functions.

Q9. Can LPC2129 act as a LIN slave?

Answer: Yes, using UART-based firmware, an external LIN transceiver and suitable break, synchronization, PID and response handling.

Q10. Why is timing important in LIN?

Answer: LIN is master-scheduled communication. Correct timing is necessary for synchronization, frame slots and response transmission.
