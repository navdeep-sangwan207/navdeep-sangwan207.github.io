2. Introduction to Embedded Communication Protocols

Embedded systems use communication protocols to exchange data between microcontrollers, sensors, memory devices, controllers and other electronic systems.

The five protocols covered in this lesson are:

  • CAN: Controller Area Network.
  • LIN: Local Interconnect Network.
  • UART: Universal Asynchronous Receiver/Transmitter.
  • I2C: Inter-Integrated Circuit.
  • SPI: Serial Peripheral Interface.

3. CAN – Controller Area Network

CAN is a multi-master serial communication protocol widely used in automotive and industrial control systems.

Important Features

  • Multi-master communication.
  • Message-based communication.
  • Identifier-based message arbitration.
  • Differential signaling using CAN_H and CAN_L.
  • Error detection and fault confinement mechanisms.
  • Common Classical CAN data field: up to 8 bytes.
  • CAN FD supports larger data fields, up to 64 bytes.

Applications

  • Automotive engine control.

4. LIN – Local Interconnect Network

LIN is a low-cost, single-wire, master-scheduled communication protocol mainly used for automotive body electronics.

Important Features

  • One master node in a LIN cluster.
  • One or more slave nodes.
  • Single-wire physical bus.
  • Master-controlled frame scheduling.
  • UART-based communication is possible.
  • Maximum standard bit rate of 20 kbit/s.
  • External LIN transceiver required for the physical bus.

  • Power windows.

5. UART – Universal Asynchronous Receiver/Transmitter

UART is an asynchronous serial communication interface used for point-to-point communication between devices.

Important Features

  • Separate transmit and receive signals.
  • Asynchronous communication.
  • No separate clock line.
  • Configurable baud rate.
  • Common formats include 8N1.
  • Can use additional hardware flow-control signals.

UART Connection

Applications

  • Microcontroller debugging.
  • GPS modules.
  • Serial terminals.
  • Bluetooth modules using UART interfaces.
  • UART-based LIN implementations.

6. I2C – Inter-Integrated Circuit

I2C is a synchronous, address-based serial communication protocol that uses two signal lines.

Important Features

  • Two wires: SDA and SCL.
  • Address-based device selection.
  • Supports multiple controllers and targets.
  • Uses open-drain/open-collector signaling with pull-up resistors.
  • Supports acknowledgements.
  • Common standard speed modes include 100 kbit/s and 400 kbit/s.

  • EEPROM interfacing.
  • RTC modules.
  • Temperature sensors.
  • Display controllers.
  • Low-speed peripheral communication.

7. SPI – Serial Peripheral Interface

SPI is a synchronous serial communication interface commonly used for high-speed communication between a controller and peripheral devices.

Important Features

  • Clocked serial communication.
  • Separate data input and output lines.
  • Clock polarity and phase configuration.
  • Chip-select signal for device selection.
  • Full-duplex data transfer is possible.
  • No universal device-addressing mechanism is defined by basic SPI.

8. Synchronous vs Asynchronous Communication

FeatureSynchronousAsynchronous
ClockUses a shared or supplied clock signal.No separate clock line.
TimingData is synchronized to clock transitions.Timing is coordinated using baud rate and framing.
ExamplesSPI and I2C.UART.

CAN and LIN have their own protocol timing mechanisms and should not be treated as simple equivalents of SPI or I2C.

15. Advantages and Limitations

CAN

  • Advantages: Multi-master operation, arbitration, error detection and robust network communication.
  • Limitations: Requires CAN controllers and transceivers; network design and configuration are more involved.

LIN

  • Advantages: Low cost, simple wiring and predictable master-scheduled communication.
  • Limitations: Lower speed and limited network architecture compared with CAN.

UART

  • Advantages: Simple, widely available and easy to debug.
  • Limitations: No built-in network addressing, arbitration or shared-bus protocol.

I2C

  • Advantages: Two-wire interface and device addressing.
  • Limitations: Bus capacitance, pull-up requirements and distance limitations.

SPI

  • Advantages: High local data rates and full-duplex transfer.
  • Limitations: More signal wires and typically a separate chip-select signal for each peripheral.

18. Interview Questions and Answers

Q1. What is the main difference between CAN and LIN?

Answer: CAN is a multi-master message-based network with arbitration, while LIN is a single-master, master-scheduled, single-wire network.

Q2. Why is LIN less expensive than CAN?

Answer: LIN uses a simpler physical layer and communication architecture, making it suitable for cost-sensitive automotive applications.

Q3. What is the main advantage of UART?

Answer: UART provides a simple asynchronous serial interface that is widely supported by microcontrollers and debugging tools.

Q4. Why is I2C called a two-wire protocol?

Answer: It uses SDA for data and SCL for clock.

Q5. What is the main advantage of SPI?

Answer: SPI supports fast synchronous communication and can transfer data in both directions simultaneously.

Q6. Which protocol supports device addressing?

Answer: I2C uses device addresses. CAN uses message identifiers, and LIN uses frame identifiers. UART and basic SPI do not define a universal device-addressing scheme.

Q7. Which protocol is used in automotive body electronics?

Answer: LIN is commonly used for low-cost body electronics such as windows, mirrors and door locks. CAN is used for broader vehicle control networks.

Q8. What is the difference between UART and LIN?

Answer: UART is a serial communication interface, whereas LIN is a complete automotive communication protocol with defined framing, scheduling and physical-layer requirements. UART can be used to implement LIN communication.

Q9. Which protocol is suitable for external flash memory?

Answer: SPI is commonly used for external flash memory, although some devices also support other interfaces.

Q10. Can LPC2129 implement LIN?

Answer: Yes, using UART-based firmware and an external LIN transceiver. It does not have a dedicated LIN controller.
