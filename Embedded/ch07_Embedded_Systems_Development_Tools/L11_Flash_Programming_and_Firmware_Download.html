1. Introduction

Flash programming is the process of writing firmware or other data into non-volatile Flash memory of an embedded system.

Firmware is the software that controls the operation of an embedded device. It is normally stored in non-volatile memory so that it remains available after the system is powered off.

Firmware download is the process of transferring a compiled firmware image from a development computer or programming tool to the target device.

Learning objectives:
  • Understand Flash memory and its characteristics.
  • Understand firmware images and file formats.
  • Learn the Flash programming process.
  • Understand ISP and bootloader-based programming.
  • Understand JTAG and debugging interfaces.
  • Learn how programming tools download firmware.
  • Understand firmware verification and troubleshooting.
  • Explore the LPC2129 firmware programming workflow.

2. What Is Flash Memory?

Flash memory is a type of non-volatile semiconductor memory that can retain stored information without continuous power.

It is widely used in embedded systems to store firmware, boot code, configuration data, and other persistent information.

Characteristics of Flash memory

  • Non-volatile storage.
  • Retains data after power is removed.
  • Can be electrically erased and reprogrammed.
  • Supports high-density storage.
  • Has a finite number of erase/program cycles.
  • Usually requires erasing before rewriting programmed locations.

Types of Flash memory

2.1 NOR Flash

NOR Flash provides random-access read capability and is commonly used for storing executable firmware.

  • Supports direct memory-mapped reads in suitable systems.
  • Often used for boot firmware and program storage.
  • Typically has different erase and programming characteristics from NAND.

2.2 NAND Flash

NAND Flash is commonly used for high-capacity data storage in embedded devices.

  • Organized into pages and erase blocks.
  • Commonly used in storage devices.
  • Requires management of bad blocks in many applications.
  • Often uses error-correction mechanisms.
Parameter NOR Flash NAND Flash
Typical use Firmware and code storage High-capacity data storage
Read access Random access Page-oriented access
Organization Memory locations and erase sectors Pages and erase blocks
Common application Microcontroller program memory Storage devices and embedded data systems

3. Flash Memory Operations

Flash memory programming generally involves three important operations: reading, erasing, and programming.

3.1 Read operation

The processor or programming tool reads stored information from Flash memory.

3.2 Erase operation

An erase operation resets the contents of a selected Flash erase unit, such as a sector or block.

In many Flash technologies, the erased state is represented by bits set to logic 1.

3.3 Program operation

The programming operation writes new data into previously erased Flash locations.

Firmware Image | v Erase Flash Area | v Program New Data | v Verify Program | v Firmware Stored
Flash erase and program operations depend on the memory technology and device specification. Programming software must follow the target device's erase-sector sizes, write restrictions, and timing requirements.

4. What Is Firmware?

Firmware is low-level software stored in non-volatile memory that controls the operation of an embedded device.

It provides the instructions required by the microcontroller to initialize hardware, configure peripherals, process inputs, and control outputs.

Examples of firmware functions

  • Microcontroller initialization.
  • Clock and PLL configuration.
  • GPIO configuration.
  • UART communication.
  • Timer operation.
  • ADC data acquisition.
  • PWM generation.
  • Sensor and actuator control.

Firmware storage

Microcontroller +-------------------+ | | | Flash Memory | | - Firmware | | - Boot Code | | | +-------------------+ | | | SRAM | | - Variables | | - Stack | | - Runtime Data | | | +-------------------+

Flash commonly stores the program image, while SRAM is used for variables, stack, and runtime data.

5. What Is a Firmware Image?

A firmware image is a file or memory representation containing the program data and, where applicable, associated information required to program a target device.

The compiler and linker generate program output. A conversion or post-processing tool may then create a format suitable for the programming tool.

Common firmware file formats

Format Description
HEX Intel HEX text format containing data records and addresses.
BIN Raw binary representation of firmware data.
ELF Executable and Linkable Format containing program sections and metadata.
AXF ARM executable image format commonly used in Keil development workflows.
MAP Linker-generated report describing memory allocation and symbols.

Intel HEX example

:100000000C9445000C946E000C946E000C946E00B7
:00000001FF

Intel HEX records contain fields such as record length, address, record type, data, and checksum. The example above illustrates the general format; its bytes should not be interpreted as LPC2129 firmware.

HEX vs BIN

HEX BIN
Text-based representation. Binary data representation.
Records can contain explicit addresses. Address placement is generally determined by the programming tool or configuration.
Includes record checksums. Does not inherently contain record checksums or address metadata.
Can be viewed in a text editor. Usually inspected with a binary or hexadecimal viewer.

6. Firmware Build and Programming Workflow

Firmware programming normally begins after the application has been compiled and linked successfully.

Embedded C Source Files | v Compiler | v Object Files | v Linker | v Executable Image | v HEX / BIN Generation | v Flash Programming | v Firmware Verification | v Target Device Execution

Step-by-step process

  1. Write the embedded C application.
  2. Configure the target microcontroller.
  3. Compile the source files.
  4. Resolve linker errors and generate the executable image.
  5. Generate a suitable programming file if required.
  6. Connect the target through a supported programming interface.
  7. Erase the required Flash memory area.
  8. Download the firmware image.
  9. Verify the programmed data.
  10. Reset the target and execute the firmware.

7. What Is In-System Programming (ISP)?

In-System Programming is a method of programming a device's non-volatile memory while the device remains installed in its target system.

Many microcontrollers provide an ISP mechanism through a bootloader or dedicated programming interface.

ISP characteristics

  • Can program the microcontroller without removing it from the PCB.
  • May use a serial communication interface.
  • Can support erase, program, and verification operations.
  • Depends on the bootloader and device programming protocol.

General ISP connection

Development Computer | Serial / USB | v Programming Interface | v Microcontroller ISP | v Internal Flash
ISP is a general programming concept. The actual interface, entry procedure, baud rate, and programming commands depend on the microcontroller.

8. LPC2129 In-System Programming

The LPC2129 provides an on-chip bootloader that supports In-System Programming through its UART0 interface.

This allows the internal Flash memory to be programmed through a suitable serial connection and supported programming software.

General LPC2129 ISP requirements

  • LPC2129 microcontroller.
  • Suitable power supply and reset circuit.
  • UART0 communication connection.
  • Compatible serial-to-logic-level interface.
  • Programming software supporting the device protocol.
  • Correct boot-mode configuration.

UART0 pins

Pin Function
P0.0 UART0 Transmit (TXD0)
P0.1 UART0 Receive (RXD0)

General ISP procedure

  1. Connect the UART0 programming interface correctly.
  2. Configure the boot-mode selection as specified by the LPC2129 documentation.
  3. Reset or power-cycle the target as required.
  4. Open compatible programming software.
  5. Select the appropriate serial interface and communication settings.
  6. Establish communication with the on-chip bootloader.
  7. Erase the required Flash sectors.
  8. Transfer the firmware image.
  9. Verify the programmed data.
  10. Return the device to normal execution mode.
Important: The LPC2129 ISP procedure requires physical UART connections and correct boot-mode configuration. The Keil simulator does not physically program the microcontroller's Flash memory.

9. What Is a Bootloader?

A bootloader is a small program that executes during the startup process and performs tasks required before the main application begins.

Depending on the system, a bootloader may initialize hardware, select an application image, validate firmware, or provide firmware-update functionality.

Bootloader functions

  • Initial hardware setup.
  • Application image selection.
  • Firmware integrity checking.
  • Firmware update support.
  • Transfer of execution to the application.

Bootloader architecture

Reset / Power ON | v Bootloader | +-------+-------+ | | v v Update Mode Normal Boot | | v v Program Firmware Start Application | | +-------+-------+ | v Embedded Application

Bootloader vs Application Firmware

Bootloader Application firmware
Handles startup and update-related operations. Performs the main device functions.
Usually smaller. Size depends on application requirements.
May execute before the application. Executes after control is transferred to it.

10. What Is JTAG?

JTAG is a hardware test and debug interface based on the IEEE 1149.1 boundary-scan standard.

In supported embedded systems, JTAG can provide access to debugging functions and, depending on the device and toolchain, programming capabilities.

Common JTAG signals

Signal Purpose
TCK Test clock.
TMS Test mode select.
TDI Test data input.
TDO Test data output.
TRST Optional test reset signal.

JTAG applications

  • Processor debugging.
  • Register and memory inspection.
  • Breakpoint and execution control.
  • Boundary-scan testing.
  • Supported Flash programming operations.
JTAG is not the same as UART ISP. They are different interfaces with different protocols and purposes. The availability of Flash programming over JTAG depends on the processor, debug probe, and software.

11. Other Firmware Programming Interfaces

11.1 SWD

Serial Wire Debug is an ARM debug interface that uses fewer signal connections than traditional JTAG in supported devices.

11.2 USB Bootloader

Some microcontrollers support firmware programming through a USB bootloader.

11.3 UART Bootloader

A UART bootloader transfers firmware through a serial communication interface.

11.4 External Programmer

An external programmer can program supported memory devices directly or through a target programming interface.

Interface Typical purpose
UART ISP Serial firmware programming.
JTAG Debugging, boundary scan, and supported programming.
SWD Debugging and supported programming on compatible ARM devices.
USB Bootloader Firmware transfer over USB.
External Programmer Programming compatible memory devices.

12. Flash Programming Tools

Flash programming tools transfer firmware images into the non-volatile memory of a target device.

Common tool categories

  • Microcontroller vendor programming utilities.
  • Serial bootloader programming applications.
  • JTAG/SWD debug probes and programming software.
  • Universal device programmers.
  • Integrated development environment programming tools.

Typical programming tool features

  • Device selection.
  • Interface configuration.
  • Firmware file selection.
  • Flash erase operations.
  • Firmware download.
  • Verification and status reporting.

13. Firmware Verification

Firmware verification checks whether the intended program image has been written correctly to the target memory.

Common verification methods

  • Read-back comparison.
  • Checksum verification.
  • CRC verification.
  • Memory inspection.
  • Application startup testing.

Checksum

A checksum is a calculated value used to detect certain data errors.

CRC

A Cyclic Redundancy Check is an error-detection technique commonly used to detect accidental corruption in stored or transmitted data.

A successful checksum or CRC comparison indicates that the checked data matches the expected result under that verification method. It does not prove that the firmware is functionally correct or secure.

14. Common Flash Programming Errors

Error Possible cause Suggested check
Target not detected Incorrect connection or power supply Check target power, reset, and interface wiring.
Communication failure Incorrect baud rate or serial configuration Check UART settings and boot mode.
Erase failure Incorrect programming sequence or protected memory Check device programming requirements.
Programming failure Incorrect image or memory configuration Check image format, addresses, and sector layout.
Verification failure Data mismatch Repeat verification and inspect the image.
Application does not start Incorrect startup configuration or invalid image Check reset vector, startup code, and memory mapping.

15. Firmware Update Methods

Firmware updates replace an existing firmware image with a newer or corrected version.

15.1 Factory programming

Firmware is programmed during manufacturing before the product is delivered.

15.2 Service programming

Firmware is updated using a programming interface during maintenance or repair.

15.3 In-field firmware update

Firmware is updated after deployment, often through a communication interface or dedicated bootloader.

15.4 Over-the-Air (OTA) update

OTA updates transfer firmware wirelessly to a connected embedded device.

Firmware update systems should include appropriate integrity checks, authentication, recovery mechanisms, and protection against unauthorized firmware images.

16. Safe Firmware Update Architecture

A robust firmware update system should reduce the risk of leaving a device unusable if power fails or an update is interrupted.

Dual-image approach

Some devices use two firmware slots. One slot runs the current application while the other receives the new firmware image.

Bootloader | v Select Valid Image | +-------+-------+ | | v v Slot A Slot B Current New Image Firmware Download | | +-------+-------+ | v Validate Image | v Switch When Safe

Important protection mechanisms

  • Firmware image integrity checking.
  • Digital signature verification.
  • Authenticated update requests.
  • Power-failure recovery.
  • Rollback to a known-good image.
  • Protection of bootloader memory.

18. Practical Exercise: Generate a Firmware Image

Objective

Build a simple embedded C application and understand the output files generated by the development toolchain.

Example program

#include <LPC21xx.h>

int main(void)
{
    unsigned int value = 100;
    unsigned int result = 0;

    result = value * 2;

    while (1)
    {
    }
}

Procedure

  1. Open the LPC2129 project in Keil uVision.
  2. Add the source file to the project.
  3. Build the project.
  4. Check the build output for errors and warnings.
  5. Inspect the generated executable image.
  6. Enable the appropriate output-file option if a HEX file is required and supported by the configured toolchain.
  7. Inspect the output file using a suitable viewer.
  8. Review the linker map file to understand memory allocation.

Expected result

The build should generate an executable image for the configured target if compilation and linking are successful.

The firmware image can be examined without physically programming a microcontroller.

19. Interview Questions and Answers

Q1. What is Flash memory?

Flash is non-volatile memory used to store firmware and persistent data.

Q2. What is firmware?

Firmware is low-level software that controls an embedded device.

Q3. What is Flash programming?

It is the process of writing firmware or data into Flash memory.

Q4. What is a firmware image?

It is a file or memory representation containing program data intended for a target device.

Q5. What is the difference between HEX and BIN?

HEX is a text-based record format that can contain addresses and checksums, whereas BIN is a raw binary data representation.

Q6. What is ISP?

In-System Programming allows a device to be programmed while installed in its target system.

Q7. What is a bootloader?

A bootloader is a program that executes during startup and may initialize the system, select firmware, or support firmware updates.

Q8. What is JTAG?

JTAG is a hardware test and debug interface based on IEEE 1149.1.

Q9. What is firmware verification?

It checks whether the intended firmware data has been programmed correctly.

Q10. What is a checksum?

A checksum is a calculated value used to detect certain data errors.

Q11. What is CRC?

CRC is an error-detection technique based on polynomial division.

Q12. What is OTA firmware update?

OTA is the process of transferring firmware updates wirelessly to a connected device.

Q13. What is the purpose of a dual-image update?

It allows a device to retain a known-good firmware image while a new image is downloaded and validated.

Q14. How is LPC2129 firmware programmed?

LPC2129 supports internal Flash programming through its bootloader using the UART0 ISP mechanism and compatible programming software.

Q15. Can Keil simulator program physical Flash memory?

No. Simulator debugging does not physically program the Flash memory of an LPC2129 device.
