1. Introduction

Embedded software is often developed on a computer that has a different processor architecture from the microcontroller or processor that will execute the application.

For example, an engineer may write and compile an embedded application on an x86-64 Windows or Linux computer, while the final program is intended to run on an ARM-based microcontroller.

Cross compilation makes this possible. A cross-compiler runs on one system but generates executable code for another target system.

Learning objectives:
  • Understand host and target systems.
  • Understand cross compilation.
  • Differentiate native and cross-compilers.
  • Understand compiler target architecture.
  • Learn about instruction sets and ABI.
  • Understand target configuration in Keil uVision.
  • Explore ARM7-based LPC2129 project configuration.

2. What Is a Host System?

A host system is the computer on which software development tools execute.

It is used for writing source code, compiling programs, managing projects, debugging applications, and generating firmware images.

Examples of host systems

  • Windows desktop or laptop.
  • Linux workstation.
  • macOS development computer.
  • Industrial development workstation.

In a typical embedded development environment, the host system has more memory and storage than the microcontroller being programmed.

3. What Is a Target System?

A target system is the processor, microcontroller, or computing platform for which the application software is developed.

It executes the generated firmware or application.

Examples of target systems

  • ARM7TDMI-based LPC2129 microcontroller.
  • ARM Cortex-M microcontrollers.
  • ARM Cortex-A embedded processors.
  • RISC-V microcontrollers.
  • Embedded Linux development boards.

4. Host System vs Target System

Feature Host System Target System
Purpose Develops and builds software. Executes the generated application.
Processor Runs the development tools. Runs the embedded application.
Operating system Usually Windows or Linux. May run bare-metal firmware or an operating system.
Memory Typically larger. Often limited by the embedded platform.
Software IDE, compiler, debugger, and development utilities. Firmware or target application.
Example Windows laptop. LPC2129 microcontroller.

5. What Is Cross Compilation?

Cross compilation is the process of compiling software on one computer architecture to generate code for a different target architecture.

The compiler executes on the host system but generates instructions for the target processor.

HOST SYSTEM Windows / Linux PC | | Embedded C Source | v Cross-Compiler | v Target-Specific Code | v Firmware Image | | Programming / Loading | v TARGET SYSTEM ARM Microcontroller

Example

An engineer writes an Embedded C program on a Windows laptop and uses an ARM-targeted compiler to generate machine code for an ARM7TDMI-based LPC2129.

The generated program is intended for the LPC2129, not for direct execution as a native Windows application.

Cross compilation is essential when the target processor cannot conveniently run the development tools or when the host and target use different instruction sets.

6. Native Compiler vs Cross-Compiler

A native compiler generates code for the same system architecture on which it runs. A cross-compiler generates code for a different target architecture.

Feature Native Compiler Cross-Compiler
Execution Runs on the host. Runs on the host.
Generated code For the native target environment. For a specified different target.
Architecture Usually the same host and target architecture. Host and target architectures may differ.
Example GCC on x86-64 Linux generating x86-64 Linux programs. ARM GCC on x86-64 Linux generating ARM code.

7. Cross-Compiler Toolchain

A cross-compilation toolchain contains the software components required to generate and inspect programs for a target architecture.

Typical components

  • Cross-compiler.
  • Assembler.
  • Linker.
  • Binary utilities.
  • Target libraries and runtime support.
  • Debugger.

Example: GNU ARM toolchain

A GNU ARM toolchain may provide commands such as: 

arm-none-eabi-gcc
arm-none-eabi-as
arm-none-eabi-ld
arm-none-eabi-objcopy
arm-none-eabi-objdump
arm-none-eabi-gdb
Tool Purpose
gcc Compiles C and coordinates build stages.
as Assembles assembly source files.
ld Links object files and libraries.
objcopy Converts object or executable files between supported formats.
objdump Displays information about object files and disassembly.
gdb Provides debugging facilities for supported targets.
The command prefix depends on the selected target and toolchain version. The listed GNU ARM commands are examples and are not necessarily the tools invoked by every Keil uVision installation.

8. Target Architecture

Target architecture describes the processor design for which the compiler generates machine instructions.

Important architecture properties

  • Instruction set.
  • Register organization.
  • Word size and data types.
  • Memory addressing model.
  • Instruction execution modes.
  • Calling conventions.
  • Supported processor features.

Examples of target architectures

Architecture Example processors
ARM7TDMI LPC2129
ARM Cortex-M3 STM32F1 family
ARM Cortex-M4 Several STM32 and other MCU families
ARM Cortex-A Embedded application processors
RISC-V RISC-V microcontrollers and processors

9. Instruction Set Selection

The instruction set defines the machine instructions supported by a processor.

A compiler must generate instructions supported by the selected target processor.

ARM and Thumb instruction sets

ARM7TDMI supports both ARM and Thumb instruction sets.

Feature ARM State Thumb State
Instruction representation 32-bit ARM instructions. 16-bit Thumb instructions for the original ARM7TDMI instruction set.
Code size Generally larger. Generally more compact.
Instruction availability Full ARM instruction set for the architecture. Subset of ARM functionality.
Purpose General ARM execution. Improved code density.
ARM7TDMI uses the original Thumb instruction set. Do not confuse it with Thumb-2, which was introduced in later ARM architecture generations.

10. Application Binary Interface (ABI)

An Application Binary Interface (ABI) defines low-level rules that allow separately compiled software components to work together.

ABI may define

  • Function calling conventions.
  • Register usage during function calls.
  • Parameter passing rules.
  • Return-value conventions.
  • Data type sizes and alignment.
  • Stack organization and alignment.
  • Object-file and binary compatibility requirements.

Why ABI matters

Suppose one source file calls a function defined in another separately compiled file. Both components must follow compatible calling conventions and data-layout rules.

ABI compatibility is important when combining object files and libraries produced by different compiler configurations or toolchains.

11. Target Configuration in Keil uVision

Target configuration specifies the processor and build-related settings used by the development tools.

Important settings

Setting Purpose
Device selection Specifies the microcontroller or processor.
Processor architecture Determines the supported instruction set and processor features.
Instruction set Selects the supported ARM or Thumb execution code generation mode where applicable.
Clock information Provides target clock information for relevant IDE and debug functions.
Memory configuration Defines relevant program and data memory settings.
Compiler options Controls code generation and optimization.
Linker settings Controls memory layout and section placement.
Debug configuration Specifies the available debugging method.

12. LPC2129 Target Configuration

LPC2129 is based on the ARM7TDMI-S processor core. An LPC2129 project must therefore use a compatible toolchain and target configuration.

Example course configuration

Parameter Value
Microcontroller LPC2129
Processor core ARM7TDMI-S
Architecture family ARM7
Oscillator frequency 12 MHz
CPU clock (CCLK) 60 MHz
Peripheral clock (PCLK) 15 MHz
VPBDIV 4

Clock relationship

For this configuration: 

CCLK = 60 MHz

VPBDIV = 4

PCLK = CCLK / VPBDIV

PCLK = 60 MHz / 4

PCLK = 15 MHz
These values describe the established LPC2129 application configuration. The oscillator, PLL, and peripheral clock must also be configured correctly in the startup or application code. Entering a clock value in an IDE setting does not itself configure the physical clock.

13. Cross Compilation Using Keil uVision

When a supported ARM7 target is selected, the configured Keil toolchain generates code for that target architecture.

General procedure

  1. Open Keil uVision on the host computer.
  2. Create or open the LPC2129 project.
  3. Select the LPC2129 target device.
  4. Verify the compiler and target architecture settings.
  5. Configure memory and linker settings.
  6. Add Embedded C and assembly source files.
  7. Build the project.
  8. Inspect the generated output files.
  9. Use the configured simulator or supported debugging method.
In this workflow, the Windows laptop is the host and the LPC2129 is the target. The generated program is intended for the ARM7TDMI-S architecture.

14. Cross Compilation in Embedded Linux

Cross compilation is also widely used in embedded Linux development. Developers build applications, libraries, kernels, and modules on a host computer for a different target platform.

Example

A developer uses an x86-64 Linux workstation to build an application for an ARM-based embedded Linux board. 

arm-linux-gnueabihf-gcc application.c -o application

This is an illustrative GCC command for a suitable ARM Linux toolchain. The exact compiler prefix and ABI must match the target Linux system.

Common embedded Linux cross-compilation components

  • Cross-compiler.
  • Target system headers.
  • Target libraries.
  • Sysroot.
  • Linker and binary utilities.
  • Target-specific build configuration.

What is a sysroot?

A sysroot is a directory containing the target system's headers, libraries, and related development files. It allows the compiler and linker to use the correct target environment while running on the host.

15. Common Cross-Compilation Problems

Problem Possible cause Solution
Wrong instruction set Incorrect processor target selected. Verify the target architecture and CPU configuration.
Incompatible object files Different architecture or ABI settings. Use compatible compiler and linker configurations.
Missing header files Incorrect include paths or missing target headers. Configure the correct target include directories.
Missing libraries Host libraries used instead of target libraries. Use the correct target library paths or sysroot.
Memory overflow Program exceeds target memory capacity. Review memory layout and reduce resource usage.
Invalid firmware output Incorrect target or linker configuration. Review build settings and inspect the generated image.

17. Interview Questions and Answers

Q1. What is cross compilation?

Cross compilation generates code for a target architecture different from the host system on which the compiler runs.

Q2. What is a host system?

It is the computer on which development tools execute.

Q3. What is a target system?

It is the processor or platform for which the application is developed and on which it is intended to execute.

Q4. What is the difference between a native compiler and a cross-compiler?

A native compiler normally generates code for its own platform, while a cross-compiler generates code for a different target platform.

Q5. Why is cross compilation important in embedded systems?

Many microcontrollers cannot run development tools. Cross compilation allows software to be developed on a more capable host computer.

Q6. What is a toolchain?

A toolchain is a collection of development tools such as a compiler, assembler, linker, and debugger.

Q7. What is an ABI?

ABI defines binary-level conventions that allow separately compiled software components to work together.

Q8. What is a sysroot?

It is a directory containing target headers, libraries, and other development files used during cross compilation.

Q9. What is the target processor of LPC2129?

LPC2129 uses an ARM7TDMI-S processor core.

Q10. What is the purpose of target configuration?

It defines the processor, instruction set, compiler, memory, and other settings required to build suitable target software.

Q11. What is the difference between ARM and Thumb state?

ARM state executes 32-bit ARM instructions, while the original Thumb state supported by ARM7TDMI uses 16-bit Thumb instructions.

Q12. Does selecting a target clock in an IDE configure the microcontroller clock?

No. Clock information in project settings does not automatically configure the hardware. The PLL and peripheral clock registers must be configured by startup or application code.
