1. Chapter Overview

Embedded Systems Development Tools are software and hardware utilities used to design, develop, compile, debug, simulate, test, and program embedded applications.

An embedded development environment typically includes an Integrated Development Environment (IDE), compiler, assembler, linker, locator, debugger, simulator, programmer, and hardware measurement instruments.

This chapter introduces the complete embedded software development toolchain, with particular emphasis on Keil uVision and practical development workflows for ARM-based microcontrollers such as the LPC2129.

Learning goal: Understand how embedded software moves from source code to an executable firmware image and how development tools are used to debug, test, and program the target microcontroller.

4. Embedded Development Toolchain

A typical embedded development toolchain follows a sequence of software development and firmware generation stages.

Development workflow:

Source Code → Compiler → Assembler → Object Files → Linker → Executable/Firmware Image → Debugging → Flash Programming → Target Microcontroller

  • Editor: Used to write source code.
  • Compiler: Converts C/C++ source code into lower-level code.
  • Assembler: Converts assembly instructions into machine code.
  • Linker: Combines object files and resolves symbols.
  • Locator: Assigns program sections to target memory addresses.
  • Debugger: Helps inspect and diagnose program execution.
  • Programmer: Transfers firmware into target memory.

  2. Configure the target microcontroller and project settings.
  3. Compile a program and examine the build messages.
  4. Inspect the generated object and firmware files.
  5. Start a simulator debugging session.
  6. Use breakpoints and single-step execution.
  7. Inspect processor registers and memory values.
  8. Study UART output using a serial terminal where supported.
Simulator note: Practical exercises in this course can use Keil uVision simulator mode. Register-level observations and simulated program execution must be distinguished from physical hardware testing.
