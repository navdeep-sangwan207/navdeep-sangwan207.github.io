1. Introduction

An embedded application may contain multiple C source files, assembly files, libraries, and startup code. These files must be translated and combined to create a firmware image.

The assembler, linker, and locator are important tools in this process. They help convert assembly instructions into object code, combine program components, resolve references, and assign program sections to target memory.

Learning objectives:
  • Understand the role of an assembler.
  • Understand object files and object sections.
  • Learn symbol resolution and relocation.
  • Understand linker operations.
  • Understand the purpose of a locator.
  • Learn embedded memory placement.
  • Understand map files and linker errors.

2. What Is an Assembler?

An assembler is a software tool that translates architecture-specific assembly language into machine-code object representations.

Assembly programs contain mnemonics, registers, operands, labels, and directives. The assembler interprets these elements and generates object code and related information.

Example assembly program

        AREA    ExampleCode, CODE, READONLY
        ENTRY

        MOV     R0, #10
        MOV     R1, #20
        ADD     R2, R0, R1

STOP    B       STOP

        END

This ARM assembly example initializes two registers, adds their values, and enters an infinite branch loop. It illustrates assembly syntax; exact directives and accepted syntax depend on the selected assembler.

Assembler responsibilities

  • Translate assembly mnemonics into instruction encodings.
  • Identify registers and instruction operands.
  • Process labels and branch references.
  • Process assembler directives.
  • Generate object sections.
  • Generate symbol and relocation information.
  • Report invalid instructions and syntax errors.

3. What Is an Object File?

An object file is a binary output generated by a compiler or assembler. It contains program sections and information that allows a linker to combine it with other object files.

Common object-file contents

Component Purpose
Code sections Contain generated processor instructions.
Data sections Contain initialized or uninitialized program data information.
Symbol table Stores information about functions, variables, and labels.
Relocation records Identify locations that require address adjustment during linking.
Debug information Helps debuggers relate machine code to source code.

Common object-file formats

  • ELF – Executable and Linkable Format.
  • COFF – Common Object File Format.
  • Toolchain-specific object formats.
The object-file format depends on the compiler and toolchain. Not every embedded toolchain uses the same format.

4. Object File Sections

Object files organize program information into logical sections. The linker uses these sections when combining application components and arranging memory.

Section Typical contents
.text Executable program instructions.
.rodata Read-only constants and string literals.
.data Initialized writable global and static data.
.bss Uninitialized or zero-initialized static storage.
.stack Stack memory region, when represented as a linker-defined section or region.
.heap Heap memory region, when configured by the runtime or linker.
Section names and exact behavior depend on the toolchain. The names shown above are common in ELF-based embedded development.

5. What Is a Linker?

A linker is a software tool that combines object files and libraries to produce an executable image or another linked output.

It resolves references between separately compiled program modules and organizes their sections according to the linking configuration.

Main responsibilities

  • Combine object files.
  • Resolve external symbols.
  • Search and include required library components.
  • Process relocation information.
  • Arrange sections according to the memory configuration.
  • Report unresolved symbols and other linking errors.
  • Generate executable output and map information when configured.

6. Why Is Linking Required?

Large embedded applications are divided into multiple source files to improve modularity, maintainability, and code reuse.

Each source file can be compiled separately. However, functions and variables defined in one file may be referenced from another file.

Example project structure

LPC2129_Project/
|
|-- main.c
|-- gpio.c
|-- uart.c
|-- timer.c
|
|-- main.obj
|-- gpio.obj
|-- uart.obj
|-- timer.obj
|
|-- firmware.axf

The linker combines the generated object files and resolves the references between the program modules.

Example: multiple source files

File: main.c

extern int add_numbers(int a, int b);

int main(void)
{
    int result;

    result = add_numbers(10, 20);

    while (1)
    {
    }
}

File: math.c

int add_numbers(int a, int b)
{
    return a + b;
}

The function add_numbers() is defined in math.c and called from main.c. The linker resolves the function reference when both required object files are included in the build.

7. Symbol Resolution

A symbol is a named program entity such as a function, global variable, or label.

Symbol resolution is the process of matching references to symbols with their corresponding definitions.

Example

/* main.c */

extern int sensor_value;

int main(void)
{
    int local_copy = sensor_value;

    while (1)
    {
    }
}
/* sensor.c */

int sensor_value = 100;

Here, main.c references the external symbol sensor_value, while sensor.c defines it.

The linker connects the reference with the definition.

Common symbol-related errors

  • Undefined reference: no suitable definition is found.
  • Multiple definition: conflicting definitions are present.
  • Missing object file: the required module is not included in the build.

8. Relocation

Relocation is the process of adjusting address-dependent references when program sections are assigned their final memory locations.

During separate compilation, the final address of a function or variable may not yet be known. The object file therefore contains relocation information that helps the linker update the relevant instruction or data references.

Conceptual example

Before final placement: Function A ---- reference ----> Function B Address unknown | v Linker assigns addresses: Function A : 0x00001000 Function B : 0x00002000 | v Relocation updates address-dependent references using the final layout.
Relocation is not simply changing every address in a program. The linker processes specific relocation records associated with address-dependent code and data.

9. What Is a Locator?

In embedded development, a locator is a tool or linking stage responsible for assigning program sections to specific memory addresses or regions.

Embedded systems often have separate memory regions for Flash, SRAM, peripheral address space, and other memory-mapped resources. The firmware must be arranged according to the target memory architecture.

Locator responsibilities

  • Assign code sections to program memory.
  • Assign writable data sections to RAM.
  • Respect memory-region boundaries.
  • Place special sections at required addresses.
  • Check for memory-region overflow.
  • Generate memory-layout information.
In many modern toolchains, placement is performed by the linker using a linker script or scatter-loading description. A separate locator executable is not necessarily used.

10. Embedded Memory Layout

A microcontroller typically has several memory regions with different purposes.

Embedded Microcontroller Memory +--------------------------------------+ | FLASH | | | | Program instructions (.text) | | Read-only constants (.rodata) | | Initial values for writable data | +--------------------------------------+ +--------------------------------------+ | SRAM | | | | Initialized data (.data) | | Zero-initialized data (.bss) | | Heap (if configured) | | Stack | +--------------------------------------+ +--------------------------------------+ | MEMORY-MAPPED I/O | | | | GPIO registers | | UART registers | | Timer registers | +--------------------------------------+

Important memory sections

Section Typical location Purpose
.text Flash Program instructions.
.rodata Flash Read-only constants.
.data RAM at runtime Initialized writable data.
.bss RAM Zero-initialized static storage.
Stack RAM Function calls, local variables, and saved execution context.
Heap RAM Dynamic memory allocation when used.

The initial values for .data are commonly stored in nonvolatile memory and copied into RAM during startup. The .bss region is commonly initialized to zero.

11. Linker Script and Scatter File

A linker script or scatter-loading description specifies how program sections are assigned to target memory regions.

Typical information

  • Memory region start addresses.
  • Memory region sizes.
  • Code placement rules.
  • Read-only and read-write section placement.
  • Special section placement.
  • Stack and heap configuration where applicable.

Conceptual memory configuration

FLASH:
    Start Address = 0x00000000
    Size          = 256 KB

SRAM:
    Start Address = 0x40000000
    Size          = 16 KB
These values are illustrative only. Always use the actual memory map and capacity specified in the LPC2129 documentation and selected project configuration.

Why is memory placement important?

  • Program code must fit available nonvolatile memory.
  • Runtime data must fit available RAM.
  • Stack and heap allocations must not overlap incorrectly.
  • Special startup and interrupt sections may require specific placement.

12. Map File

A map file is a report generated by the linker that describes the memory layout and symbols of the linked application.

Information commonly found in a map file

  • Memory region usage.
  • Section addresses and sizes.
  • Function and variable addresses.
  • Symbol information.
  • Code and data memory consumption.

Why is a map file useful?

  1. Verify code placement.
  2. Check RAM and Flash usage.
  3. Identify large functions or data objects.
  4. Investigate memory overflow.
  5. Understand the final firmware layout.

13. Common Linker and Locator Errors

Error Possible cause Solution
Undefined symbol Missing function or variable definition. Check declarations, definitions, and included object files.
Multiple definition Same external symbol defined more than once. Correct duplicate definitions.
Region overflow Program section exceeds available memory. Reduce code or data usage, or correct the memory configuration.
Section placement error Section cannot be assigned to the configured memory region. Review linker script or scatter file.
Missing library Required library is unavailable. Check library paths and linker settings.
Incorrect entry point Startup or entry-point configuration is incorrect. Review startup code and linker configuration.

15. Practical Exercise: Multiple Source Files

Objective

Create a multi-file Embedded C project and understand how the linker resolves function references between separate source files.

File 1: main.c

extern int add_numbers(int a, int b);

int main(void)
{
    int result;

    result = add_numbers(10, 20);

    while (1)
    {
    }
}

File 2: math.c

int add_numbers(int a, int b)
{
    return a + b;
}

Procedure

  1. Open the Keil uVision project.
  2. Create main.c.
  3. Create math.c.
  4. Add both files to the source group.
  5. Build the project.
  6. Inspect the build output.
  7. Start a supported debugging session.
  8. Inspect the value of result after the function call.

Expected result

  • Both source files compile successfully.
  • The linker resolves the add_numbers() function reference.
  • The project generates the configured executable output.
  • The expected result value is 30.
If the project reports an undefined reference, check whether math.c has been added to the active target and whether the function name and declaration match.

16. Interview Questions and Answers

Q1. What is an assembler?

An assembler converts assembly-language instructions into machine-code object representations.

Q2. What is a linker?

A linker combines object files and libraries, resolves symbol references, and produces linked output.

Q3. What is a locator?

A locator assigns program sections to specific memory addresses or regions. In many toolchains, this function is integrated into the linker.

Q4. What is an object file?

An object file contains generated code, data sections, symbols, and relocation information.

Q5. What is symbol resolution?

It is the process of matching external symbol references with their corresponding definitions.

Q6. What is relocation?

Relocation adjusts address-dependent references according to the final memory layout.

Q7. What is a linker script?

A linker script defines memory regions and placement rules for program sections in supported toolchains.

Q8. What is a scatter file?

It is a memory-layout description used by supported Arm toolchains to control section placement.

Q9. What is a map file?

It is a linker-generated report containing memory layout, section, and symbol information.

Q10. What is a linker error?

It is an error encountered while combining program components, such as an undefined symbol or memory overflow.

Q11. Why is memory placement important in embedded systems?

Microcontrollers have limited memory, and code and data must be assigned to suitable memory regions.

Q12. Does every embedded toolchain use a separate locator?

No. Many toolchains integrate memory placement and relocation into the linker.

  2. Linker

  4. Simulator

3. What does symbol resolution do?

  1. Matches references with definitions
  2. Changes clock frequency
  3. Resets the processor
  4. Formats memory

Answer: A – Matches references with definitions

4. Which section commonly contains executable code?

  1. .text
  2. .bss
  3. .data
  4. .stack

Answer: A – .text

5. Which section commonly stores zero-initialized static variables?

  1. .text
  2. .bss
  3. .rodata
  4. .debug

Answer: B – .bss

6. What is relocation?

  1. Adjusting address-dependent references
  2. Deleting source files
  3. Changing source language

  1. Map file

  3. Audio file
