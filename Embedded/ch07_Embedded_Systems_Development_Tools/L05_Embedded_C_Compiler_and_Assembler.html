1. Introduction

Embedded software is generally written in a high-level programming language such as C or C++. However, a microcontroller executes machine instructions rather than directly executing high-level source code.

A compiler and an assembler are important components of the embedded software toolchain. They translate source programs into lower-level representations that can eventually be linked into an executable firmware image.

Learning objectives:
  • Understand the role of an Embedded C compiler.
  • Understand preprocessing, compilation, and assembly.
  • Differentiate source code, assembly code, and machine code.
  • Understand object files and compiler output.
  • Learn how Keil uVision uses compiler and assembler tools.
  • Understand compiler optimization and common errors.

2. What Is an Embedded C Compiler?

An Embedded C compiler is a software tool that translates Embedded C source code into target-specific lower-level code suitable for a microcontroller or processor.

It analyzes the source program, checks language syntax and semantics, performs code transformations, and generates assembly code or object code depending on the compiler configuration.

Major responsibilities

  • Analyze C source code.
  • Detect syntax and semantic errors.
  • Perform type checking.
  • Translate expressions and statements into target instructions.
  • Allocate variables to registers or memory.
  • Optimize generated code.
  • Generate assembly or object files.
An embedded compiler must generate code for the selected target architecture. A compiler configured for ARM7TDMI does not automatically generate suitable machine code for an unrelated processor architecture.

3. What Is an Assembler?

An assembler is a software tool that translates assembly language instructions into machine-code representations for a specific processor architecture.

Assembly language uses symbolic instruction names, registers, labels, and operands instead of writing binary machine instructions directly.

Example assembly instruction

    MOV R0, #10
    ADD R1, R0, #5

Conceptually:

  • MOV places an immediate value into a register.
  • ADD performs an addition operation.
  • R0 and R1 are processor registers.
  • #10 and #5 represent immediate values.

The assembler converts these instructions into architecture-specific machine-code encodings.

4. Compiler and Assembler in the Embedded Toolchain

The compiler and assembler are used at different stages of translating a program.

Embedded C Source Code | v Preprocessor | v Expanded C Source Code | v Compiler | v Assembly Code | v Assembler | v Object File | v Linker and Locator | v Firmware Image

This is a conceptual toolchain flow. Actual compiler implementations may combine stages, generate object files directly, or use intermediate representations.

Role of each stage

Stage Function
Preprocessor Processes header inclusion, macros, and conditional compilation.
Compiler Analyzes C code and translates it into target-oriented instructions or an intermediate form.
Assembler Translates assembly instructions into machine-code object sections.
Linker Combines object files and resolves symbols and references.
Locator Places program sections at appropriate target memory addresses when the toolchain uses a separate locating stage.

5. Preprocessing Stage

The preprocessor handles special instructions beginning with the # symbol before normal compilation.

Common preprocessor directives

Directive Purpose
#include Includes the contents of a header file.
#define Defines a macro or symbolic constant.
#ifdef Checks whether a macro is defined.
#ifndef Checks whether a macro is not defined.
#if Evaluates a compile-time condition.
#endif Ends a conditional compilation block.

Example

#include <stdio.h>

#define MAX_VALUE 100

int main(void)
{
    int value = MAX_VALUE;

    return 0;
}

The preprocessor handles the header inclusion and replaces the macro MAX_VALUE with its defined value.

Preprocessing does not itself generate executable machine instructions. It prepares the source for subsequent compilation.

6. Compilation Stage

During compilation, the compiler analyzes the processed source code and translates it into a target-oriented representation.

Compiler operations

  1. Lexical analysis: identifies tokens.
  2. Syntax analysis: checks grammatical structure.
  3. Semantic analysis: checks types and language rules.
  4. Intermediate representation: represents program operations internally.
  5. Optimization: improves generated code where permitted.
  6. Code generation: produces target-oriented instructions.

Example C program

int main(void)
{
    int a = 10;
    int b = 20;
    int result;

    result = a + b;

    while (1)
    {
    }
}

The compiler analyzes the declarations, arithmetic expression, assignment, and infinite loop. It then generates instructions suitable for the configured target architecture.

The exact assembly output depends on the compiler, optimization level, processor architecture, and compilation options.

7. Assembly Language and Machine Code

Assembly language

Assembly language is a low-level symbolic representation of processor instructions. It provides direct access to architecture-specific operations and registers.

Machine code

Machine code consists of encoded instructions represented as binary values. These instructions are interpreted and executed by the processor.

Feature Assembly Language Machine Code
Representation Mnemonic instructions Binary instruction encodings
Human readability Relatively readable Difficult to read directly
Execution Must be assembled or otherwise translated Executed by the processor
Architecture dependency Architecture-specific Architecture-specific
Assembly mnemonics are not directly executed by the CPU. The processor executes their corresponding machine-code encodings.

8. Object Files

An object file is an intermediate binary file generated by a compiler or assembler. It contains machine-code sections and other information required by the linker.

Typical object-file contents

  • Machine-code sections.
  • Initialized data sections.
  • Symbol tables.
  • Relocation information.
  • Debugging information when generated.

Common extensions

Extension Typical use
.o Object file in many GCC-based toolchains.
.obj Object file in several embedded toolchains, including Keil workflows.
.axf Arm executable image commonly used in Keil development.

9. Compiler Optimization

Compiler optimization modifies the generated code to improve performance, reduce memory usage, or achieve other implementation goals while preserving the program's required behavior.

Common optimization objectives

  • Reduce execution time.
  • Reduce code size.
  • Reduce unnecessary memory accesses.
  • Improve instruction scheduling.
  • Use processor registers efficiently.

Common optimization levels

Different compilers provide different optimization levels and options. A typical GCC-style naming scheme is:

Level General meaning
-O0 Little or no optimization; useful during early debugging.
-O1 Basic optimization.
-O2 More extensive optimization.
-O3 More aggressive optimization.
-Os Optimization focused on reducing code size.
These are GCC-style options, not universal Keil settings. Consult the documentation for the compiler selected in your uVision project.

10. Compiler Errors and Warnings

A compiler reports errors when it cannot translate the source code according to the language and target rules. Warnings identify suspicious or potentially problematic code.

Example: syntax error

int main(void)
{
    int value = 10

    return 0;
}

The semicolon after the variable declaration is missing. This can produce a compiler error.

Corrected code

int main(void)
{
    int value = 10;

    return 0;
}

Common compiler problems

Problem Possible cause
Syntax error Incorrect C language structure.
Undeclared identifier Variable or function not declared in scope.
Type mismatch Incompatible data types or conversions.
Missing header Incorrect include path or unavailable header file.
Undefined reference Missing function or variable definition during linking.

  5. Build the target.

12. Embedded C Compiler Considerations

Embedded software has additional constraints compared with many desktop applications. Compiler configuration must account for the target processor and its resources.

Important considerations

  • Processor architecture: generated instructions must match the target CPU.
  • Memory constraints: code and data must fit available memory.
  • Timing requirements: execution time may affect real-time behavior.
  • Interrupt handling: interrupt-related code must follow compiler and architecture requirements.
  • Hardware registers: memory-mapped registers must be accessed correctly.
  • Optimization: optimization must preserve the required hardware behavior.
  • Language extensions: compiler-specific features should be used carefully.

Why volatile matters

volatile unsigned int *GPIO_STATUS =
    (volatile unsigned int *)0xE0028000;

The volatile qualifier tells the compiler that accesses through this pointer are observable and must not be eliminated or treated as ordinary invariant memory accesses.

The address above is an illustrative example, not a recommendation to access a specific LPC2129 register. Always use the correct address and register definition from the device documentation.

15. Interview Questions and Answers

Q1. What is an Embedded C compiler?

It translates Embedded C source code into target-oriented code for a specific processor or microcontroller.

Q2. What is an assembler?

An assembler translates assembly-language instructions into machine-code object representations.

Q3. What is the difference between a compiler and an assembler?

A compiler translates a high-level language such as C, whereas an assembler translates symbolic assembly instructions into machine-code encodings.

Q4. What is preprocessing?

Preprocessing handles directives such as header inclusion, macro expansion, and conditional compilation.

Q5. What is an object file?

An object file contains generated code and related information required for linking.

Q6. What is compiler optimization?

It improves generated code for objectives such as execution speed or reduced memory usage while preserving the required program behavior.

Q7. Why is target architecture important?

Different processors use different instruction sets and machine-code encodings. Generated code must match the intended processor.

Q8. What is the purpose of an assembler in a C project?

It processes assembly source files and may also be used to assemble compiler-generated assembly output.

Q9. What is the difference between an error and a warning?

An error generally prevents successful translation or linking, while a warning reports a potential issue that may not prevent the build.

Q10. What is the purpose of the linker?

The linker combines object files, resolves external symbols, and produces an executable image according to the project configuration.

Q11. Can a compiler directly generate machine code?

Yes. Many compiler toolchains generate object code directly without exposing a separate assembly file.

Q12. Why should optimization be considered carefully in embedded systems?

Optimization can change execution timing, code size, and generated instruction sequences. The resulting firmware must still meet functional and timing requirements.
