1. Introduction

Keil uVision is an Integrated Development Environment (IDE) used to develop, build, and debug embedded applications for supported microcontroller architectures.

It provides a common environment for creating projects, writing Embedded C and assembly programs, configuring target devices, compiling source files, linking object files, and debugging firmware.

Keil MDK is a development tool suite for supported Arm-based microcontrollers. uVision is its IDE and development interface.

Learning objective: Understand Keil uVision, its interface, project organization, target configuration, source-file management, build process, and simulator-based debugging workflow.

2. What Is Keil uVision?

Keil uVision provides an integrated environment for embedded software development. It coordinates different development tools to produce firmware for a selected target microcontroller.

Main functions

  • Create and manage embedded projects.
  • Write and edit Embedded C and assembly source code.
  • Select supported microcontroller devices.
  • Configure compiler and linker settings.
  • Compile and build firmware.
  • View errors and warnings.
  • Debug programs using supported debugging methods.
  • Inspect variables, registers, and memory.
  • Use simulation where supported by the selected target.
Keil uVision supports different device families depending on the installed toolchain and device support. Always verify that the required microcontroller is supported by your installed version.

4. Creating a New Embedded Project

A Keil project stores the source files, target selection, build configuration, and other settings required to develop an embedded application.

Step 1: Open Keil uVision

  1. Launch Keil uVision from the Windows Start menu or desktop shortcut.
  2. Wait for the development environment to open.
  3. Choose the New Project option from the Project menu.

Step 2: Select a project location

  1. Create a dedicated folder for the project.
  2. Choose a meaningful project name.
  3. Save the project file inside the project folder.

Example folder organization:

LPC2129_GPIO_Project/
|
|-- LPC2129_GPIO_Project.uvprojx
|
|-- main.c
|-- gpio.c
|-- gpio.h
|
|-- Objects/
|
|-- Listings/

Step 3: Select the target device

  1. After creating the project, the device selection window appears.
  2. Locate the required manufacturer and device family.
  3. Select LPC2129 if it is available in the installed device database.
  4. Confirm the device selection.
If LPC2129 is missing, check whether the appropriate device database or legacy device support is installed. Do not select a different LPC device merely because it has a similar name.

5. Target Configuration

Target configuration defines how the project is built for the selected microcontroller.

Open the target options or target configuration dialog to review the available settings.

Important configuration categories

Configuration Purpose
Device Selects the target microcontroller.
Target Defines target-related settings such as memory and clock information where supported.
Output Controls output-file generation and related settings.
C/C++ Configures compiler options and include paths.
Assembler Configures assembly-language processing.
Linker Configures linking and memory-layout options.
Debug Selects and configures the debugging environment.

Clock frequency

The target clock information should match the actual application configuration. It is important for debugging, timing calculations, and peripheral configuration.

Example LPC2129 clock configuration used in this course:
  • Oscillator frequency: 12 MHz
  • CPU clock (CCLK): 60 MHz
  • Peripheral clock (PCLK): 15 MHz
  • VPBDIV: 4
These are application configuration values, not automatic guarantees of the project settings.

6. Adding Source Files to a Project

A project may contain multiple source files and header files. Files must be added to the appropriate project target or group so that they are included in the build when required.

Typical procedure

  1. Open the Project Window.
  2. Right-click the appropriate source group.
  3. Select the option to add existing files.
  4. Browse to the source or header file.
  5. Select the required file and confirm.
  6. Verify that the file appears in the project tree.

Example project structure

Target 1
|
+-- Source Group 1
|   |
|   +-- main.c
|   +-- gpio.c
|   +-- uart.c
|   +-- timer.c
|
+-- Header Files
    |
    +-- gpio.h
    +-- uart.h
    +-- timer.h
Adding a file to a project does not necessarily copy it into the project directory. Check the file path and keep project dependencies organized.

7. Writing an Embedded C Program

After configuring the project and adding source files, write the application code in the editor.

Example: Simple LPC2129 GPIO program

The following example configures P0.5 as a GPIO output and sets the corresponding output bit. 

#include <LPC21xx.h>

int main(void)
{
    PINSEL0 = 0x00000000;

    IODIR0 |= (1U << 5);

    IOSET0 = (1U << 5);

    while (1)
    {
        /* Main application loop */
    }
}

Program explanation

  • LPC21xx.h provides device register definitions for a compatible project.
  • PINSEL0 configures the relevant lower Port 0 pin functions.
  • IODIR0 configures P0.5 as an output.
  • IOSET0 sets the P0.5 output latch.
  • The infinite loop keeps the application running.
This example demonstrates register-level configuration. In the simulator, inspect the relevant registers to verify the software operation. A physical LED lighting condition cannot be established from the register operation alone.

8. Building the Project

Building converts the source files into the configured firmware output.

Typical build workflow

  1. Save all source files.
  2. Select the correct project target.
  3. Choose the Build Target command.
  4. Wait for compilation and linking to complete.
  5. Review the output messages.
  6. Correct errors and rebuild if necessary.

Common build results

Result Meaning
0 Errors No errors were reported during the build.
Warnings Potential issues were detected and should be reviewed.
Errors The build could not complete successfully.
Memory information Reports generated code and data memory usage when available.

Common build commands

  • Build: Builds the target and updates required outputs.
  • Rebuild: Regenerates outputs from the project's source inputs.
  • Clean: Removes generated build outputs.

9. Debugging Using Keil uVision

Keil uVision provides debugging facilities for supported targets. The available features depend on the selected device and debugging configuration.

Starting a debugging session

  1. Build the project successfully.
  2. Open the Debug configuration.
  3. Select the simulator if using software simulation.
  4. Start the debugging session.
  5. Open relevant register, memory, and watch windows.
  6. Run or step through the program.

Important debugging operations

Operation Purpose
Run Executes the program continuously.
Stop Pauses program execution.
Reset Resets the simulated or connected target as supported.
Step Executes the next instruction or source statement according to the selected stepping mode.
Breakpoint Pauses execution at a selected location.

10. Register and Memory Inspection

Register inspection is particularly important in microcontroller programming because peripheral operations are controlled through memory-mapped registers.

Registers to inspect in the GPIO example

Register Expected software effect
PINSEL0 Relevant pin-function bits are configured for GPIO.
IODIR0 Bit 5 is set to configure P0.5 as output.
IOSET0 Writing bit 5 requests the P0.5 output latch to be set.

Expected register-level result

IODIR0 bit 5 = 1
IOSET0 write value = 0x00000020

The debugger may show the register values or the effect on the modeled peripheral, depending on simulator support.

IOSET0 is a write-one-to-set register. Do not assume that reading it returns the output state. Use the appropriate port-state register and the device documentation when verifying pin state.

11. Simulator Configuration

A simulator can be selected in the debugging configuration when the installed Keil toolchain supports simulation for the target device.

General procedure

  1. Open the target options or debug configuration.
  2. Locate the Debug settings.
  3. Select the simulator if it is available.
  4. Apply the configuration.
  5. Start the debugging session.
  6. Inspect the CPU and supported peripheral registers.
Important for this course: LPC2129 practical exercises are performed using the Keil uVision simulator. No physical LPC2129 development board is assumed. Simulation results should be described as register-level or model-level observations, not physical hardware tests.

12. Output Files Generated by Keil

Depending on project configuration, the build process can generate several output files.

File type Purpose
.obj Object file generated from source code.
.axf Executable image commonly used in Arm development workflows.
.hex Intel HEX representation of program data when enabled.
.map Linker-generated memory and symbol information when enabled.
.lst Listing output when configured.
.uvprojx Keil uVision project configuration file.
The exact file extensions and output locations depend on the selected Keil version, compiler, and project settings.

13. Common Keil uVision Errors

Error or problem Possible reason Recommended action
Device not available Missing device support Check installed device database and target support.
Cannot open source file Incorrect file path Verify the project file and source-file locations.
Header file not found Incorrect include path or missing device header Check compiler include directories and device support.
Undefined symbol Missing function definition or object file Check declarations, definitions, and project membership.
Linker error Incorrect memory or linker configuration Review target memory settings and linker options.
Simulator unavailable Target or installed toolchain does not support the selected simulation mode Verify device and debugger support.

14. Practical Exercise: Create an LPC2129 Project

Objective

Create a basic LPC2129 Embedded C project in Keil uVision, build it, and inspect GPIO register operations using the simulator.

Procedure

  1. Open Keil uVision.
  2. Create a new project folder named LPC2129_GPIO_Project.
  3. Create a new project with the same name.
  4. Select LPC2129 if supported by the installed device database.
  5. Create a source file named main.c.
  6. Enter the GPIO example from Section 7.
  7. Add the source file to the project.
  8. Configure the simulator if supported.
  9. Build the project.
  10. Start debugging and inspect the GPIO registers.

Expected result

  • The project is created and configured.
  • The source file appears in the project tree.
  • The build completes without reported errors.
  • The debugger starts if the selected simulator supports the target.
  • GPIO register operations can be examined where modeled.
Do not report physical LED operation from this simulator-only exercise. The objective is to verify software configuration and inspect available register-level behavior.

15. Interview Questions and Answers

Q1. What is Keil uVision?

Keil uVision is an IDE used for embedded software development on supported microcontroller platforms.

Q2. What is the difference between Keil MDK and uVision?

Keil MDK is a development tool suite, while uVision is the IDE interface used to manage projects and development operations within supported workflows.

Q3. What is a target device?

The target device is the microcontroller or processor for which the application is being developed.

Q4. What is the purpose of a project file?

It stores project organization, target selection, and build-related configuration.

Q5. Why are source files added to a project?

They become part of the organized project and can be included in the configured build.

Q6. What is the purpose of the Build command?

It invokes the configured build tools to compile and link the project.

Q7. What is the purpose of a Watch Window?

It displays selected variables and expressions during a debugging session.

Q8. What is the difference between simulation and hardware debugging?

Simulation uses a software model of the target, while hardware debugging uses a physical device and supported debug interface.

Q9. What is an AXF file?

It is an executable image commonly generated in Arm development workflows and can contain debugging information.

Q10. Why is target configuration important?

Incorrect device, memory, compiler, or linker settings can result in an invalid or unsuitable firmware image.

Q11. What should be checked when LPC2129 is missing from the device list?

Check whether the correct device database and legacy target support are installed and available in the selected Keil toolchain.

Q12. Does a successful build mean the firmware is correct?

No. It only indicates that the configured build process completed without reported errors. Further debugging, simulation, and hardware validation may be necessary.

18. Lesson Summary

  • Keil uVision is an IDE for supported embedded development targets.
  • It provides project management and source code editing.
  • Target configuration defines the device and build environment.
  • Source and header files are organized into project groups.
  • The build process invokes compiler, assembler, and linker tools as required.
  • The debugger supports program execution control and inspection.
  • Register inspection helps verify software-level peripheral configuration.
  • Simulation results must be distinguished from physical hardware results.
