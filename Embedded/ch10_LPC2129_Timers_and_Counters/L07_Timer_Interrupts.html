1. Introduction

A timer interrupt allows the microcontroller to execute a specific function when a configured timer event occurs. Instead of continuously checking the timer counter in a loop, the CPU can perform other operations until an interrupt request is generated.

The LPC2129 has Timer 0 and Timer 1. Each timer can generate interrupt requests through match and capture events.

Learning objectives:
  • Understand timer interrupt operation.
  • Understand timer interrupt flags.
  • Identify Timer 0 and Timer 1 interrupt sources.
  • Understand the role of the VIC.
  • Configure a timer match interrupt.
  • Understand ISR execution and flag clearing.

2. What Is a Timer Interrupt?

A timer interrupt is an interrupt request generated by a timer peripheral when a configured event occurs.

Examples include:

  • A timer counter reaches a match register value.
  • An external signal causes a capture event.
  • A configured timer event sets an interrupt flag.

When the interrupt is enabled and accepted by the interrupt controller and CPU, execution transfers to the associated interrupt service routine.

3. Polling vs Timer Interrupt

Polling Interrupt
CPU repeatedly checks a timer condition. Timer requests CPU attention when an event occurs.
Can consume CPU time while waiting. CPU can execute other tasks between events.
Program flow is controlled by repeated checks. Program flow temporarily transfers to an ISR.
Simple to implement. Requires interrupt configuration and careful ISR design.
Interrupts are useful when an event must be handled without continuously checking a peripheral status condition.

4. Timer Interrupt Generation

Peripheral Clock | v Prescaler PR / PC | v Timer TC | v Match Comparator (MR) | v Match Control (MCR) | v Timer Interrupt Flag (IR) | v Vectored Interrupt Controller | v ARM7 CPU | v Interrupt Service Routine

The timer event sets an interrupt flag. The VIC receives the interrupt request and provides the configured interrupt handling mechanism to the CPU.

6. Timer Interrupt Register (IR)

The Interrupt Register indicates which timer interrupt events have occurred.

Important characteristics:

  • Bits 0–3 represent match interrupt flags.
  • Bits 4–7 represent capture interrupt flags.
  • A set flag indicates that the corresponding event occurred.
  • Flags are cleared by writing 1 to the corresponding bit.
// Clear Timer 0 Match 0 flag
T0IR = (1U << 0);

// Clear Timer 0 Capture 0 flag
T0IR = (1U << 4);
The timer IR register uses write-one-to-clear behavior. Do not use |= to clear a flag. Writing a 1 to another pending flag can clear that flag as well.

7. Match Interrupt Configuration

To generate an interrupt on a match event, configure the match register and enable the interrupt action in MCR.

For Timer 0 Match 0:

// Set the match value
T0MR0 = 1000;

// Enable interrupt on MR0 match
T0MCR = (1U << 0);

When T0TC equals T0MR0, the timer sets the corresponding match interrupt flag.

The timer interrupt source must also be enabled in the VIC before the CPU can service it through the configured interrupt mechanism.

8. Vectored Interrupt Controller (VIC)

The LPC2129 uses a Vectored Interrupt Controller to manage interrupt sources. It receives requests from peripherals, applies interrupt enable and priority configuration, and supports vectored interrupt handling.

Timer 0 and Timer 1 are separate VIC interrupt sources. The VIC source numbers and slot configuration must be taken from the LPC2129 User Manual.

The VIC is covered in detail in Chapter 11: LPC2129 Interrupt and Exception Handling. This lesson focuses on the timer-side interrupt request and its relationship with the VIC.

9. What Is an Interrupt Service Routine?

An Interrupt Service Routine (ISR) is a function executed in response to an accepted interrupt request.

The ISR should handle the event quickly and return control to the interrupted program.

Typical ISR responsibilities:

  • Identify or handle the interrupt event.
  • Clear the peripheral interrupt flag.
  • Update a small status variable or event counter.
  • Return promptly from the interrupt.
Avoid long delays, blocking loops, lengthy calculations, and unnecessary function calls inside an ISR.

10. Complete Interrupt Configuration Requirements

A complete timer interrupt application requires configuration at multiple levels.

StepConfiguration
1Configure timer prescaler and counter.
2Configure the match register.
3Enable the match interrupt action in MCR.
4Clear any pending timer interrupt flags.
5Configure the corresponding VIC interrupt source.
6Configure the ISR and required interrupt handling mechanism.
7Enable the timer.
8Enable CPU interrupt handling as required.

The exact VIC registers, vector slot setup, and compiler-specific ISR declaration depend on the device and toolchain configuration.

11. Basic Timer Interrupt Request Program

Objective: Configure Timer 0 to generate a match interrupt request.

#include <LPC21xx.h>

int main(void)
{
    // Stop and reset Timer 0
    T0TCR = 0x02;

    // Configure prescaler for a 1 ms TC interval
    T0PR = 14999;

    // Initialize prescaler and timer counters
    T0PC = 0;
    T0TC = 0;

    // Configure match value
    T0MR0 = 1000;

    // Enable interrupt on MR0 match
    T0MCR = (1U << 0);

    // Clear pending timer interrupt flags
    T0IR = 0xFF;

    // Enable Timer 0
    T0TCR = 0x01;

    while (1)
    {
        // Main program continues here.
        // VIC and ISR configuration are not included.
    }
}

Program explanation

  1. Timer 0 is reset.
  2. PR is configured for a nominal 1 ms TC increment interval.
  3. TC and PC are initialized.
  4. MR0 is configured to 1000.
  5. MCR enables the MR0 interrupt action.
  6. Pending timer flags are cleared.
  7. Timer 0 is enabled.
This is a timer-side interrupt request example, not a complete working VIC/ISR application. The main loop does not process the interrupt through an ISR because VIC setup and the compiler-specific interrupt declaration are intentionally left for the dedicated interrupt chapter.

12. Periodic Timer Interrupts

Periodic interrupts are useful when an application needs to perform an operation at regular intervals.

A common configuration uses:

  • A suitable prescaler value.
  • A match register value.
  • Interrupt-on-match enabled in MCR.
  • Reset-on-match enabled in MCR.
  • VIC and ISR configuration.
// Configure Timer 0 for periodic MR0 events
T0TCR = 0x02;
T0PR = 14999;
T0PC = 0;
T0TC = 0;

T0MR0 = 1000;

// Interrupt on MR0 and reset TC on match
T0MCR = (1U << 0) | (1U << 1);

// Clear pending flags
T0IR = 0xFF;

// Start timer
T0TCR = 0x01;

With PCLK = 15 MHz and PR = 14999, the timer counter increments nominally every 1 ms. Starting from zero, TC reaches 1000 after 1000 increments, corresponding to approximately 1 second.

The actual interrupt servicing and periodic behavior must be verified with the complete VIC/ISR configuration and the target timer implementation.

13. Important ISR Programming Practices

  • Keep interrupt service routines short.
  • Clear the correct peripheral interrupt flag.
  • Use appropriate data types for shared variables.
  • Protect shared data when necessary.
  • Avoid blocking delays inside an ISR.
  • Avoid unnecessary operations inside the ISR.
  • Understand interrupt priority and nesting behavior.
  • Verify compiler-specific interrupt syntax.
If a variable is modified inside an ISR and read by the main program, declare it appropriately, commonly using volatile. Volatile alone does not make multi-step operations atomic.

14. Timer Interrupt Applications

  • Periodic sensor sampling.
  • System tick generation.
  • Periodic status monitoring.
  • Task scheduling in firmware.
  • Communication timeout detection.
  • Periodic data acquisition.
  • Time-based control operations.

15. Common Mistakes

  • Enabling an interrupt in MCR but forgetting VIC configuration.
  • Forgetting to clear the timer interrupt flag.
  • Clearing the wrong IR bit.
  • Using read-modify-write operations on a write-one-to-clear IR register.
  • Writing a long delay inside an ISR.
  • Using an incorrect VIC interrupt source number.
  • Using compiler-specific ISR syntax incorrectly.
  • Assuming a timer interrupt is fully configured just by starting the timer.

17. Interview Questions and Answers

Q1. What is a timer interrupt?

It is an interrupt request generated by a timer peripheral when a configured event occurs.

Q2. What is an ISR?

An Interrupt Service Routine is a function executed to handle an accepted interrupt.

Q3. What is the function of the timer IR register?

It records pending match and capture interrupt events.

Q4. How are timer interrupt flags cleared?

By writing 1 to the corresponding IR bit.

Q5. What is the function of the VIC?

It manages interrupt sources and supports interrupt prioritization and vectored interrupt handling.

Q6. Does MCR enable the VIC interrupt?

No. MCR enables the timer's match interrupt request. The VIC and CPU must also be configured.

Q7. Why should an ISR be short?

A short ISR reduces interrupt latency and allows the processor to return quickly to normal program execution.

Q8. What is a periodic timer interrupt?

It is an interrupt generated repeatedly at configured time intervals.

Q9. What does volatile do for a variable shared with an ISR?

It tells the compiler that the variable can change outside the normal program flow and that accesses must not be optimized away on the assumption that its value is stable.

Q10. Can timer interrupts be used for sensor sampling?

Yes. A periodic timer interrupt can trigger or schedule regular sensor sampling.
