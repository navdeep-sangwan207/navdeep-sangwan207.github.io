1. Introduction

Timers and counters are important hardware peripherals used in microcontrollers and embedded systems.

They perform operations related to time measurement, event counting, delay generation, frequency measurement, and periodic task execution.

A microcontroller can use a timer to measure elapsed time without requiring the CPU to execute a software delay loop continuously.

Learning objectives:
  • Understand the concept of a timer.
  • Understand the concept of a counter.
  • Study the working principles of both.
  • Differentiate timers and counters.
  • Understand hardware-based time measurement.
  • Study the timer/counter facilities of LPC2129.
  • Identify practical applications.

2. What Is a Timer?

A timer is a hardware peripheral that counts clock events to measure time intervals.

It normally receives a clock signal from an internal clock source, such as the peripheral clock (PCLK).

Each qualifying clock event advances the timer's counting process. After a configured number of events, the timer can generate a match event, interrupt, reset, or other configured action.

Example

Suppose a timer receives 1,000 clock events per second. If it counts 1,000 events, the elapsed time is:

Time = Number of clock events / Clock frequency

Time = 1,000 / 1,000 = 1 second.

A timer measures elapsed time by counting clock-derived events. The accuracy depends on the clock source, clock configuration, and timer setup.

3. What Is a Counter?

A counter is a hardware peripheral configured to count external events rather than simply count internal clock-derived time increments.

The external events may be electrical transitions received through a configured capture or counter input.

Example

Consider a system that counts objects moving along a conveyor belt. Each sensor event represents one object.

If the sensor generates one qualifying event for every object, the counter records the number of objects.

4. Working Principle of a Timer

A timer uses clock pulses to maintain a count. The timer's counting frequency depends on the input clock and prescaler configuration.

Peripheral Clock (PCLK) | v +---------------+ | Prescaler | +---------------+ | v +---------------+ | Timer Counter | | TC | +---------------+ | v +---------------+ | Match Compare | +---------------+ | v Interrupt / Reset / Stop

Basic operation

  1. The timer receives its clock source.
  2. The prescaler divides the clock events if configured.
  3. The timer counter increments.
  4. The current count is compared with configured match values.
  5. When a match occurs, the configured action takes place.

A match can be configured to generate an interrupt, reset the timer counter, stop the timer, or perform a combination of supported actions.

5. Working Principle of a Counter

In counter mode, the peripheral counts qualifying transitions on a selected external input.

External Events | | | | v v v v +-------------------+ | Counter Input Pin | +-------------------+ | v +-------------------+ | Event Detection | +-------------------+ | v +-------------------+ | Counter Register | | TC | +-------------------+ | v Event Count

Example

Suppose an external sensor produces 25 qualifying transitions. The counter records 25 events, provided its input configuration and counting conditions are satisfied.

A counter input does not automatically count every voltage change. The selected input pin, edge selection, electrical signal quality, and peripheral configuration determine which transitions are counted.

6. Difference Between Timer and Counter

Parameter Timer Counter
Primary purpose Measures time intervals. Counts external events.
Typical source Internal clock-derived events. External input transitions.
Main application Delay and time measurement. Event and pulse counting.
Example Generate a 1-second interval. Count 100 sensor pulses.
Measurement Elapsed time. Number of events.
Input Internal clock source. Configured external counter input.
Important: Timer and counter functions may be implemented using the same hardware peripheral. The operating mode determines whether it counts internal clock events or external input events.

7. Software Delay vs Hardware Timer

Software delay

A software delay uses instructions executed by the CPU to consume time. 

void delay(void)
{
    volatile unsigned int i;

    for (i = 0; i < 100000; i++)
    {
    }
}

The duration depends on processor frequency, compiler optimization, instruction execution, and program configuration.

Hardware timer delay

A hardware timer uses its peripheral counting hardware to measure a configured time interval.

The CPU can perform other work while the timer progresses, particularly when using interrupts or checking timer status.

Software Delay Hardware Timer
Uses CPU instruction loops. Uses dedicated timer hardware.
Usually blocks the CPU while waiting. Can operate while the CPU performs other work.
Timing depends on code execution. Timing is derived from the configured clock.
Useful for simple short waits. Useful for accurate intervals and periodic tasks.

8. LPC2129 Timer/Counter Overview

The LPC2129 ARM7-based microcontroller provides two general-purpose 32-bit timer/counter peripherals:

  • Timer 0
  • Timer 1

Each timer/counter block provides facilities such as:

  • 32-bit timer counter.
  • 32-bit prescale counter.
  • Prescale register.
  • Four match registers.
  • Four capture registers.
  • Match control.
  • Capture control.
  • Interrupt status and control.
+------------------------------+ | LPC2129 | | | | +----------------------+ | | | Timer 0 | | | | | | | | Prescaler / Counter | | | | Match / Capture | | | +----------------------+ | | | | +----------------------+ | | | Timer 1 | | | | | | | | Prescaler / Counter | | | | Match / Capture | | | +----------------------+ | | | +------------------------------+
Timer 0 and Timer 1 are separate peripheral blocks. Their registers and configuration can be controlled independently.

9. Important Timer/Counter Concepts

9.1 Peripheral Clock (PCLK)

PCLK is the peripheral clock supplied to the timer peripheral. The timer's clock-derived counting rate depends on this frequency.

Project reference: PCLK = 15 MHz.

9.2 Prescaler

The prescaler reduces the rate at which the timer counter increments. It is controlled using the Prescale Register (PR).

9.3 Timer Counter (TC)

The Timer Counter Register stores the current timer count. In timer mode, it increments according to the prescaler and peripheral clock.

9.4 Match Register (MR)

A Match Register stores a comparison value. When the timer counter reaches the configured match value, a match event occurs.

9.5 Capture Register (CR)

A Capture Register can store the timer counter value when a configured external capture event occurs.

9.6 Timer Interrupt

A timer can generate an interrupt when a configured timer event occurs. The interrupt can be handled through the LPC2129 Vectored Interrupt Controller.

10. Timer Calculation Example

Consider the following project configuration:

Parameter Value
Peripheral clock (PCLK) 15 MHz
Prescale Register (PR) 14999
Prescaler division factor 15000

In the LPC2129 timer, the prescale counter generates a timer counter increment when it reaches the programmed prescale value.

Timer counter increment frequency:

FTC = PCLK / (PR + 1)

FTC = 15,000,000 / 15,000

FTC = 1,000 Hz

Time between timer counter increments:

T = 1 / 1,000 = 0.001 seconds

One timer count = 1 millisecond.

This configuration is useful when creating millisecond-based timer intervals. The actual match interval also depends on the selected match value and timer control configuration.

11. Applications of Timers and Counters

Timer applications

  • Generating precise time delays.
  • Creating periodic interrupts.
  • Scheduling embedded tasks.
  • Measuring elapsed time.
  • Generating time bases for RTOS systems.
  • Controlling LED blinking intervals.
  • Generating periodic control signals.

Counter applications

  • Counting objects on conveyor belts.
  • Counting pulses from sensors.
  • Measuring rotational speed.
  • Counting machine operations.
  • Monitoring production quantities.
  • Measuring external event frequency.

12. Common Mistakes

  • Confusing timer mode with counter mode.
  • Using CCLK instead of the configured PCLK in timer calculations.
  • Ignoring the PR + 1 prescaler relationship.
  • Using an incorrect match value.
  • Forgetting to enable the timer.
  • Failing to clear an interrupt flag correctly.
  • Assuming a software delay is a precise time interval.
  • Ignoring external input edge configuration in counter mode.
Always verify the timer clock, prescaler, match configuration, and timer control settings before calculating or debugging a time interval.

14. Interview Questions and Answers

Q1. What is a timer in a microcontroller?

A timer is a hardware peripheral that counts clock-derived events to measure time intervals.

Q2. What is a counter?

A counter is a hardware peripheral configured to count qualifying external input events.

Q3. What is the main difference between a timer and a counter?

A timer typically counts internal clock-derived events, whereas a counter counts configured external events.

Q4. How many general-purpose timer/counter blocks does LPC2129 provide?

LPC2129 provides two: Timer 0 and Timer 1.

Q5. What is the function of a prescaler?

A prescaler reduces the frequency of timer counter increments by dividing the incoming clock events.

Q6. What is a Match Register?

A Match Register stores a value that is compared with the timer counter to generate a match event.

Q7. What is a Capture Register?

A Capture Register stores the timer count when a configured external capture event occurs.

Q8. Why are hardware timers preferred for periodic operations?

They provide clock-based timing without requiring the CPU to remain occupied in a software delay loop.

Q9. What is PCLK?

PCLK is the peripheral clock supplied to peripheral modules, including the timer peripheral.

Q10. What is the purpose of a timer interrupt?

It notifies the CPU when a configured timer event occurs, allowing software to respond without continuous polling.
