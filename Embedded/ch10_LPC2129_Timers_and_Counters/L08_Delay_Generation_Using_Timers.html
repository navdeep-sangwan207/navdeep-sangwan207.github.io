1. Introduction

Delay generation is an important operation in embedded systems. A microcontroller often needs to wait for a specific time before performing another operation.

Examples include waiting between output transitions, generating periodic events, allowing a peripheral to complete an operation, and scheduling sensor sampling.

The LPC2129 provides Timer 0 and Timer 1. These hardware timers can be configured to generate time intervals without relying on software instruction-counting loops.

Learning objectives:
  • Understand hardware timer-based delays.
  • Differentiate software delays and hardware timer delays.
  • Calculate timer counter frequency.
  • Configure PR, TC, MR, and MCR.
  • Generate millisecond and second delays.
  • Write timer-based delay programs for LPC2129.

2. What Is Delay Generation?

Delay generation means intentionally waiting for a specified time before continuing program execution.

For example:

  • Wait for 1 millisecond.
  • Wait for 100 milliseconds.
  • Wait for 1 second.
  • Wait between two peripheral operations.

A delay can be generated using software instructions or a hardware timer peripheral.

3. Software Delay vs Hardware Timer Delay

Software Delay Hardware Timer Delay
Uses repeated instructions or loops. Uses a hardware timer counter.
Depends on processor speed and compiler optimization. Depends on configured peripheral clock and timer settings.
Can occupy the CPU while waiting. Can be combined with other processing or interrupt handling.
Less suitable for precise timing. More predictable when correctly configured.
Hardware timer delays are generally preferred when a repeatable time interval is required. However, polling a timer in a blocking delay function still keeps the CPU occupied.

4. Timer-Based Delay Architecture

Peripheral Clock (PCLK) | v Prescaler Register PR | v Timer Counter (TC) | v Match Register (MR) | v Match Control Register (MCR) | v Match Event | v Delay Completed

The prescaler determines how frequently the timer counter increments. The match register stores the target count. When the counter reaches the target, a match event indicates that the configured interval has elapsed.

5. Timer Frequency Calculation

The timer counter frequency is determined by the peripheral clock and prescaler.

Formula:

TC Frequency = PCLK / (PR + 1)

Timer Counter Increment Interval:

TC Interval = (PR + 1) / PCLK

For the project clock configuration:

ParameterValue
FOSC12 MHz
CCLK60 MHz
PCLK15 MHz
PR14999

Calculation:

TC Frequency = 15,000,000 / (14999 + 1)

              = 15,000,000 / 15,000

              = 1000 Hz

TC Interval = 1 / 1000

            = 0.001 second

            = 1 millisecond
With PCLK = 15 MHz and PR = 14999, the timer counter increments once every nominal 1 millisecond.

6. Generating a Delay Using a Match Register

A match register can be used to define the target counter value for a delay.

Suppose TC starts at zero and increments every 1 millisecond.

Match valueNumber of increments from zeroNominal elapsed time
101010 ms
100100100 ms
500500500 ms
100010001 second

The match condition is TC = MR. Starting at TC = 0, the counter must make the corresponding number of increments to reach the programmed value.

Do not confuse the match value with the number of increments. For example, MR0 = 999 is reached after 999 increments from TC = 0, not 1000 increments.

7. Using MCR for Delay Generation

The Match Control Register determines what happens when the timer counter reaches the match value.

For a timer that resets after reaching MR0, enable the reset action: 

// Reset Timer 0 when MR0 matches
T0MCR = (1U << 1);

For a timer that generates an interrupt on MR0 match, enable the interrupt action: 

// Generate interrupt request on MR0
T0MCR = (1U << 0);

For a polling-based delay, the program can instead wait until the relevant timer status flag is set. This lesson uses that approach in the next examples.

8. Timer Match Flag Polling

When a match event occurs, the timer's Interrupt Register records the event. A program can poll the corresponding flag instead of enabling a VIC interrupt.

For Timer 0 Match 0, the flag is bit 0 of T0IR. 

// Wait until Timer 0 Match 0 flag is set
while ((T0IR & (1U << 0)) == 0)
{
    // Wait for match event
}

// Clear Match 0 flag
T0IR = (1U << 0);
The match interrupt action in MCR must be enabled for the match interrupt flag to be generated. The VIC does not need to be enabled when the application only polls the timer flag.

9. Program: Generate a 1 Millisecond Delay

Objective: Generate a nominal 1 ms delay using Timer 0.

#include <LPC21xx.h>

void delay_1ms(void)
{
    // Stop and reset Timer 0
    T0TCR = 0x02;

    // Configure 1 ms TC increment interval
    T0PR = 14999;

    // Initialize counters
    T0PC = 0;
    T0TC = 0;

    // Set match value
    T0MR0 = 1;

    // Enable interrupt flag generation and
    // reset TC on match
    T0MCR = (1U << 0) | (1U << 1);

    // Clear any pending flags
    T0IR = 0xFF;

    // Start Timer 0
    T0TCR = 0x01;

    // Poll the Match 0 flag
    while ((T0IR & (1U << 0)) == 0)
    {
        // Wait
    }

    // Clear Match 0 flag
    T0IR = (1U << 0);

    // Stop Timer 0
    T0TCR = 0x00;
}

int main(void)
{
    while (1)
    {
        delay_1ms();
    }
}

Program explanation

  1. Timer 0 is stopped and reset.
  2. PR is set to 14999.
  3. TC and PC are initialized to zero.
  4. MR0 is set to 1.
  5. MCR enables interrupt flag generation and reset on match.
  6. The timer starts counting.
  7. The program waits for the MR0 flag.
  8. The flag is cleared and the timer is stopped.
This is a conceptual polling example. The actual interval includes timer start and software overhead, and its operation depends on the timer peripheral model. It is not a precision-calibrated 1 ms delay function.

10. Program: Generate a 100 Millisecond Delay

Objective: Generate a nominal 100 ms delay using Timer 0.

#include <LPC21xx.h>

void delay_100ms(void)
{
    // Stop and reset Timer 0
    T0TCR = 0x02;

    // Configure 1 ms TC interval
    T0PR = 14999;

    // Initialize counters
    T0PC = 0;
    T0TC = 0;

    // Match after 100 TC increments
    T0MR0 = 100;

    // Interrupt flag and reset on match
    T0MCR = (1U << 0) | (1U << 1);

    // Clear pending flags
    T0IR = 0xFF;

    // Start timer
    T0TCR = 0x01;

    // Wait for match event
    while ((T0IR & (1U << 0)) == 0)
    {
        // Wait
    }

    // Clear match flag
    T0IR = (1U << 0);

    // Stop timer
    T0TCR = 0x00;
}

int main(void)
{
    while (1)
    {
        delay_100ms();
    }
}

With a 1 ms timer counter interval and an initial TC value of zero, MR0 = 100 is reached after 100 increments.

11. Program: Generate a 1 Second Delay

Objective: Generate a nominal 1 second delay using Timer 0.

#include <LPC21xx.h>

void delay_1second(void)
{
    // Stop and reset Timer 0
    T0TCR = 0x02;

    // Configure 1 ms TC interval
    T0PR = 14999;

    // Initialize counters
    T0PC = 0;
    T0TC = 0;

    // 1000 TC increments = nominal 1 second
    T0MR0 = 1000;

    // Enable match interrupt flag and reset
    T0MCR = (1U << 0) | (1U << 1);

    // Clear pending flags
    T0IR = 0xFF;

    // Start timer
    T0TCR = 0x01;

    // Wait for MR0 match
    while ((T0IR & (1U << 0)) == 0)
    {
        // Wait
    }

    // Clear the match flag
    T0IR = (1U << 0);

    // Stop timer
    T0TCR = 0x00;
}

int main(void)
{
    while (1)
    {
        delay_1second();
    }
}

The timer reaches TC = 1000 after 1000 increments from zero. With a nominal 1 ms increment interval, this represents approximately 1 second.

12. Repeated Delays and Periodic Operation

A delay function can be called repeatedly when an application needs a repeated waiting interval. 

int main(void)
{
    while (1)
    {
        delay_1second();

        // Perform an application operation
        // after each delay.
    }
}

A more efficient design can use a free-running timer or timer interrupts instead of repeatedly stopping and restarting the timer.

A blocking delay prevents the main program from progressing until the delay completes. For multitasking or responsive applications, consider interrupt-driven timing or a non-blocking timer state machine.

13. Timer Delay Accuracy

Hardware timer accuracy depends on several factors:

  • Accuracy of the oscillator.
  • Correct PLL and peripheral clock configuration.
  • Correct prescaler calculation.
  • Correct match value and match action.
  • Timer start and software polling overhead.
  • Peripheral behavior and clock configuration.

A hardware timer provides a more predictable timing reference than an instruction-counting software loop, but the complete delay function still includes software overhead.

14. Applications of Timer-Based Delays

  • Generating periodic firmware events.
  • Creating delays between peripheral operations.
  • Scheduling sensor measurements.
  • Implementing communication timeouts.
  • Creating time intervals for state machines.
  • Periodic status monitoring.
  • Generating timing references for embedded applications.

15. Common Mistakes

  • Using CCLK instead of PCLK in timer calculations.
  • Forgetting that PR divides the timer input clock using PR + 1.
  • Using the wrong match value.
  • Forgetting to enable the match interrupt action when polling the IR flag.
  • Failing to clear a pending match flag before starting a new delay.
  • Using a blocking delay in an application that requires responsive processing.
  • Assuming that a simulator necessarily models timer hardware.
  • Assuming a nominal delay is an exact physical measurement.

17. Interview Questions and Answers

Q1. What is hardware timer-based delay generation?

It uses a timer peripheral to measure a programmed interval before continuing program execution.

Q2. What is the formula for timer counter frequency?

TC frequency = PCLK / (PR + 1).

Q3. What is the purpose of the prescaler?

It divides the peripheral clock before the timer counter increments.

Q4. Why is hardware timer delay preferred over a software delay?

It provides a timing reference based on the configured peripheral clock rather than instruction execution time.

Q5. What is a match register?

It stores the target counter value used to detect a timer match event.

Q6. What is the purpose of MCR?

It selects the interrupt, reset, and stop actions for match events.

Q7. What is a blocking delay?

A delay during which the CPU waits and does not proceed with the main program until the interval has elapsed.

Q8. What is the timer counter interval for PCLK = 15 MHz and PR = 14999?

One millisecond.

Q9. What match value gives 1000 increments from TC = 0?

MR = 1000.

Q10. Can timer interrupts be used instead of polling?

Yes. Interrupt-driven timing allows the CPU to perform other work between timer events.
