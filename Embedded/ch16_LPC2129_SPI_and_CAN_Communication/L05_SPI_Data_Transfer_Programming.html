Lesson 05: SPI Data Transfer Programming

Learn how to initialize the LPC2129 SPI peripheral and transmit, receive and exchange serial data using Embedded C.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand the SPI data-transfer sequence.
  • Configure LPC2129 SPI0 as a master.
  • Configure SPI clock frequency and communication mode.
  • Transmit data through SPDR.
  • Receive data through SPDR.
  • Understand full-duplex SPI communication.
  • Use polling to detect transfer completion.
  • Handle basic SPI error conditions.
  • Develop reusable SPI Embedded C functions.
  • Debug SPI register operations in Keil uVision.

2. Introduction to SPI Data Transfer

SPI data transfer is the process of exchanging serial data between a master device and one or more peripheral devices.

In master mode, the LPC2129 generates the serial clock and initiates communication. The peripheral receives the clock and exchanges data with the microcontroller.

SPI Signals

SignalFunction
SCKSerial clock generated by the master.
MOSIMaster Out, Slave In.
MISOMaster In, Slave Out.
SSEL / CSSelects the target peripheral.
SPI is full-duplex capable. During a clocked transfer, the master transmits bits through MOSI while receiving bits through MISO. Both directions operate simultaneously.

3. SPI Data Transfer Architecture

SPI Master and Peripheral Data Exchange 
        LPC2129 MASTER              SPI PERIPHERAL
       +-------------+             +-------------+
       |             |             |             |
       |   SPDR      |--- MOSI --->| Receive     |
       |             |             | Shift Reg.  |
       |             |             |             |
       |             |<-- MISO ----| Transmit    |
       |             |             | Shift Reg.  |
       |             |             |             |
       |   SPI       |--- SCK ---->| Clock       |
       |   Clock     |             | Input       |
       +-------------+             +-------------+
              |
              +------ CS / SSEL ------> Peripheral

Data Exchange Example

Suppose the master transmits:

0xA5

Binary representation:

10100101

With MSB-first communication, the most significant bit is transmitted first. The peripheral simultaneously shifts its outgoing data back to the master through MISO.

4. SPI Data Transfer Sequence

  1. Configure the SPI pin functions.
  2. Configure the SPI clock counter.
  3. Configure SPCR for master mode and clock mode.
  4. Assert the target peripheral's chip-select signal.
  5. Write the transmit byte to SPDR.
  6. Wait for the SPIF transfer-complete flag.
  7. Read SPSR followed by SPDR.
  8. Deassert chip select when the transaction is complete.
The SPI hardware does not provide a universal transaction protocol. The peripheral datasheet defines when chip select must be asserted, how many bytes must be exchanged and when it may be released.

5. SPI Pin Configuration

The SPI signals are selected through the LPC2129 pin-connect block. The appropriate PINSEL fields must be configured before enabling communication.

The SPI0 interface uses the dedicated SPI0 pin functions. The exact pin mapping must be taken from the pin-function table for the selected LPC2129 package.

Do not assume that SPI0 and SPI1 use the same pin-selection fields. Verify each signal's PINSEL function in the LPC2129 datasheet before configuring the pin multiplexing.

Chip Select Using GPIO

A GPIO output can be used as an external peripheral chip-select signal when the peripheral protocol permits it.

The GPIO should normally be configured as an output and kept inactive while the SPI peripheral is idle. The active level, usually LOW, depends on the peripheral's datasheet.

6. SPI Initialization

SPI initialization configures the communication parameters before the first data transfer.

Initialization Parameters

  • Master or slave operating mode.
  • Clock polarity (CPOL).
  • Clock phase (CPHA).
  • Bit order.
  • SPI clock frequency.
  • Interrupt enable or disable.

Project Clock Configuration

FOSC = 12 MHz
CCLK = 60 MHz
PCLK = 15 MHz

SPCCR = 16

SPI Clock = PCLK / SPCCR
          = 15 MHz / 16
          = 937.5 kHz

SPI0 Initialization Function

#include <LPC21xx.h>

#define SPI_MASTER_MODE  (1U << 5)

void SPI0_Init(void)
{
    /* Configure SPI clock counter */
    S0SPCCR = 16U;

    /* Master mode, Mode 0, MSB first */
    S0SPCR = SPI_MASTER_MODE;
}

This function configures the SPI0 register settings. It does not configure the physical pin multiplexing or external chip-select GPIO.

7. SPI Data Transmission

Data transmission in master mode begins when software writes a byte to the SPI Data Register (SPDR).

Transmission Procedure

  1. Select the target peripheral.
  2. Write the data byte to SPDR.
  3. The SPI hardware generates clock pulses.
  4. Data is shifted out through MOSI.
  5. SPIF becomes set when the transfer completes.
  6. Read the status register and access SPDR.

Program: Transmit One Byte

#include <LPC21xx.h>

#define SPI_SPIF (1U << 7)

void SPI0_Transmit(unsigned char data)
{
    unsigned int status;

    S0SPDR = data;

    while ((S0SPSR & SPI_SPIF) == 0U)
    {
        /* Wait for transfer completion */
    }

    status = S0SPSR;

    /*
       Read SPDR after reading SPSR.
       This completes the SPIF clearing sequence.
    */
    (void)S0SPDR;

    (void)status;
}

int main(void)
{
    SPI0_Init();

    SPI0_Transmit(0x55U);

    while (1)
    {
    }
}
The function discards the simultaneously received byte. If the incoming data is required, save the SPDR value instead of discarding it.

8. SPI Data Reception

SPI reception is synchronized with the serial clock. A master must generate clock pulses to receive data.

Therefore, a master normally transmits a dummy byte when it wants to receive data without sending a meaningful command byte.

Reception Procedure

  1. Select the peripheral.
  2. Write a dummy byte to SPDR to generate clock pulses.
  3. The peripheral shifts its data onto MISO.
  4. Wait for SPIF.
  5. Read SPSR.
  6. Read SPDR to retrieve the received byte.

Program: Receive One Byte

#include <LPC21xx.h>

#define SPI_SPIF (1U << 7)

unsigned char SPI0_Receive(void)
{
    unsigned int status;
    unsigned char received;

    /* Dummy byte generates clock pulses */
    S0SPDR = 0xFFU;

    while ((S0SPSR & SPI_SPIF) == 0U)
    {
        /* Wait for completion */
    }

    status = S0SPSR;

    received = (unsigned char)S0SPDR;

    (void)status;

    return received;
}
A dummy byte is not universally 0xFF. Some peripherals expect a different value or a command/address sequence. Follow the target peripheral's communication protocol.

9. Full-Duplex SPI Communication

In full-duplex communication, the master transmits and receives data during the same clock cycles.

Example

Master transmits: 0xA5
Peripheral sends: 0x3C

During the same 8 clock cycles:

MOSI: 0xA5
MISO: 0x3C

Master receives: 0x3C

Program: Exchange One Byte

#include <LPC21xx.h>

#define SPI_SPIF (1U << 7)

unsigned char SPI0_Transfer(unsigned char data)
{
    unsigned int status;
    unsigned char received;

    S0SPDR = data;

    while ((S0SPSR & SPI_SPIF) == 0U)
    {
        /* Wait for transfer completion */
    }

    status = S0SPSR;
    received = (unsigned char)S0SPDR;

    (void)status;

    return received;
}

The function returns the byte received through MISO while transmitting the supplied byte through MOSI.

10. Multiple-Byte SPI Transmission

Many SPI peripherals require several bytes in a single transaction. For example, a command may be followed by an address and data bytes.

Example Transaction

Byte 1: Command
Byte 2: Register Address
Byte 3: Data

CS: LOW  ----------------------- HIGH
      Command Address Data

Program: Transfer a Byte Array

#include <LPC21xx.h>

#define SPI_SPIF (1U << 7)

void SPI0_TransferBuffer(
    const unsigned char *tx,
    unsigned char *rx,
    unsigned int length)
{
    unsigned int i;
    unsigned int status;

    for (i = 0U; i < length; i++)
    {
        unsigned char received;

        S0SPDR = tx[i];

        while ((S0SPSR & SPI_SPIF) == 0U)
        {
            /* Wait for current byte */
        }

        status = S0SPSR;
        received = (unsigned char)S0SPDR;

        if (rx != 0)
        {
            rx[i] = received;
        }
    }

    (void)status;
}
This function transfers a sequence of bytes. It does not control chip select. The caller must assert chip select before the transaction and release it only when the peripheral protocol permits.

11. Chip-Select Control

SPI does not provide a universal addressing mechanism. The master selects the required peripheral through a chip-select signal.

Typical Active-LOW Chip Select

  • LOW: Peripheral selected.
  • HIGH: Peripheral deselected.

Example GPIO Macros

/*
   Illustrative only.
   Replace CS_PIN with a verified free GPIO pin.
*/

#define CS_PIN (1U << 5)

void CS_Init(void)
{
    /* Select GPIO function for the chosen pin */
    /* Configure the pin as output */
    /* Keep chip select inactive */
}

void CS_Select(void)
{
    /* Active-LOW selection */
    IOCLR0 = CS_PIN;
}

void CS_Deselect(void)
{
    IOSET0 = CS_PIN;
}
This chip-select example is a GPIO concept, not a complete pin configuration for SPI0. Before using it, verify that the selected GPIO is not assigned to another required peripheral function.

12. Complete SPI Master Transfer Example

The following example combines initialization, one-byte transfer and a reusable transfer function. The chip-select GPIO is intentionally left as a board-specific configuration step. 

#include <LPC21xx.h>

#define SPI_MASTER_MODE (1U << 5)
#define SPI_SPIF        (1U << 7)

void SPI0_Init(void)
{
    S0SPCCR = 16U;
    S0SPCR = SPI_MASTER_MODE;
}

int SPI0_Transfer(
    unsigned char tx_data,
    unsigned char *rx_data)
{
    unsigned int status;
    unsigned int timeout = 1000000U;

    S0SPDR = tx_data;

    while ((S0SPSR & SPI_SPIF) == 0U)
    {
        if (timeout == 0U)
        {
            return -1;
        }

        timeout--;
    }

    status = S0SPSR;

    *rx_data = (unsigned char)S0SPDR;

    (void)status;

    return 0;
}

int main(void)
{
    unsigned char received_data;
    int result;

    SPI0_Init();

    result = SPI0_Transfer(0x55U, &received_data);

    while (1)
    {
        /*
           Inspect result and received_data
           using the debugger.
        */
    }
}

Program Explanation

  • SPI0 is configured for master mode.
  • SPCCR is configured for approximately 937.5 kHz.
  • The transmit byte is written to SPDR.
  • The function waits for the SPIF flag.
  • A bounded polling loop prevents indefinite waiting.
  • The received byte is stored through the pointer.
  • A return value of -1 indicates timeout.
The timeout value is a software loop count, not a calibrated time. It must be adjusted and validated for the compiler, clock configuration and application. A production driver should also handle SPI error flags and chip-select cleanup on failure.

13. SPI Polling Method

Polling is a simple method of checking whether an SPI transfer has completed. 

while ((S0SPSR & (1U << 7)) == 0U)
{
    /* Wait */
}

Advantages

  • Simple to implement.
  • Easy to understand and debug.
  • Useful for short transfers.

Disadvantages

  • CPU remains occupied while waiting.
  • Not efficient for long communication operations.
  • Requires timeout handling for reliability.

14. SPI Interrupt-Based Transfer Concept

Interrupt-based SPI communication allows the CPU to perform other operations while the SPI transfer is in progress.

Basic Sequence

  1. Enable SPI interrupt generation in SPCR.
  2. Configure the SPI interrupt source in VIC.
  3. Start the transfer by writing to SPDR.
  4. SPI hardware completes the transfer.
  5. The interrupt handler processes the received data.
  6. The handler clears the SPI interrupt flag correctly.
  7. The handler completes VIC interrupt servicing.
SPI interrupt programming requires careful coordination between the SPI interrupt flag, the SPI status flags and the VIC. A complete interrupt-driven implementation is a separate advanced programming exercise.

15. SPI Error Handling

Flag Meaning Software Action
SPIF Transfer complete Read SPSR, then access SPDR.
MODF Mode fault Read SPSR, then write SPCR to clear.
ROVR Receive overrun Read SPSR and recover the transfer state.
WCOL Write collision Read SPSR, then access SPDR.
ABRT Slave transfer aborted Read SPSR and recover the transaction.

A robust SPI driver should detect errors, release chip select when appropriate, reset its transaction state and report failures to the application.

18. Common Programming Mistakes

  • Forgetting to configure the SPI pin functions.
  • Using an invalid SPCCR value.
  • Selecting the wrong SPI mode.
  • Forgetting to assert chip select.
  • Releasing chip select between bytes when the peripheral requires a continuous transaction.
  • Not waiting for SPIF before accessing the next transfer.
  • Failing to read SPSR before accessing SPDR when clearing SPIF.
  • Ignoring the received byte during transmission.
  • Using a dummy byte that does not match the peripheral protocol.
  • Using an infinite polling loop without a timeout.
  • Confusing legacy SPI with SSP programming.

19. Interview Questions and Answers

Q1. How is SPI data transmitted?

Data is written to SPDR and shifted serially through MOSI using clock pulses generated by the master.

Q2. How does the master receive SPI data?

The master generates clock pulses and samples incoming data through MISO. It retrieves the received byte from SPDR after transfer completion.

Q3. Why is a dummy byte required during reception?

SPI reception requires clock pulses. Writing a dummy byte generates those clock pulses while the peripheral transmits its response.

Q4. What is full-duplex communication?

It is simultaneous transmission and reception of data in both directions.

Q5. What is the role of SPIF?

SPIF indicates that an SPI transfer has completed.

Q6. Why is chip select needed?

It identifies which peripheral should respond to the master's communication.

Q7. What is SPI polling?

Polling means repeatedly checking the status register until the transfer-complete flag is set.

Q8. What is the disadvantage of polling?

The CPU remains occupied while waiting for transfer completion.

Q9. Can SPI receive data without transmitting clocks?

No. In master mode, the master must generate clock pulses to receive data.

Q10. What is the difference between SPI and UART transfer?

SPI is synchronous and uses a clock signal. UART is asynchronous and uses configured baud rates without a shared clock line.
