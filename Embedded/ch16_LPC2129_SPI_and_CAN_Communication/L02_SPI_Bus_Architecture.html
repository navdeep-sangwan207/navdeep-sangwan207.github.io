Lesson 02: SPI Bus Architecture

Understand SPI bus organization, controller and peripheral connections, signal-line sharing, chip-select arrangements, data flow and electrical requirements.

2. Introduction to SPI Bus Architecture

SPI bus architecture describes how an SPI controller communicates with one or more peripheral devices using serial clock, data and selection signals.

The bus typically contains one controller and one or more peripheral devices. The controller initiates transactions and generates the clock signal.

Main Components

  • SPI Controller: Generates the clock and manages communication.
  • SPI Peripheral: Receives commands and exchanges data.
  • SCLK: Synchronizes data transfer.
  • MOSI: Carries controller-to-peripheral data.
  • MISO: Carries peripheral-to-controller data.
  • CS: Selects the target peripheral.
Modern SPI terminology sometimes uses controller/peripheral instead of master/slave. The electrical roles remain the same: the controller generates the clock and selects the peripheral.

3. Basic SPI Bus Connection

A basic SPI connection uses four signal lines between the controller and a peripheral.

Controller-to-Peripheral Connection 
       SPI CONTROLLER                 SPI PERIPHERAL
      +----------------+             +----------------+
      |                |             |                |
      | MOSI ----------+------------>| MOSI           |
      |                |             |                |
      | MISO <---------+-------------| MISO           |
      |                |             |                |
      | SCLK ----------+------------>| SCLK           |
      |                |             |                |
      | CS   ----------+------------>| CS             |
      |                |             |                |
      +----------------+             +----------------+

Signal Direction

Signal Controller Peripheral
MOSI Output Input
MISO Input Output
SCLK Output Input
CS Output Input

This is the conventional signal direction for a controller communicating with a peripheral.

4. Function of Each SPI Bus Signal

4.1 MOSI – Controller-to-Peripheral Data

MOSI is the data line used to send information from the controller to the selected peripheral.

Examples:

  • Sending a register address to a sensor.
  • Writing configuration data to a device.
  • Sending commands to a display controller.
  • Writing data to external memory.

4.2 MISO – Peripheral-to-Controller Data

MISO is the data line used by the selected peripheral to send information back to the controller.

Examples:

  • Reading a sensor measurement.
  • Reading memory contents.
  • Receiving device status information.

4.3 SCLK – Serial Clock

The controller generates SCLK to synchronize the transfer of bits.

  • Clock frequency controls the bit transfer rate.
  • Clock polarity determines the idle clock level.
  • Clock phase determines the sampling edge.
  • The peripheral must support the selected clock timing.

4.4 CS – Chip Select

CS enables or selects the target peripheral for a communication transaction.

Many SPI devices use active-LOW chip select. In this arrangement, LOW selects the peripheral and HIGH deselects it.

Active-LOW Chip Select 
CS
HIGH  -----------+             +---------
                |             |
                +-------------+
                  LOW
                 Selected

HIGH = Peripheral deselected
LOW  = Peripheral selected
Active-LOW chip select is common but not universal. Always verify CS polarity and timing in the peripheral datasheet.

5. Single-Peripheral SPI Architecture

The simplest SPI arrangement connects one controller to one peripheral.

Single-Peripheral Architecture 
             Controller
           +-------------+
           |             |
           | MOSI -------+----------+
           | MISO <------+----------|
           | SCLK -------+----------|
           | CS   -------+----------|
           +-------------+          |
                                    |
                             +------v------+
                             | Peripheral  |
                             |             |
                             | SPI Device  |
                             +-------------+

Communication Sequence

  1. The controller configures the SPI peripheral.
  2. The controller activates chip select.
  3. The controller generates clock pulses.
  4. Data is transferred through MOSI and MISO.
  5. The controller completes the transfer.
  6. The controller deactivates chip select.

This architecture is common when connecting a microcontroller to one sensor, memory device or display.

6. Multiple-Peripheral SPI Architecture

One SPI controller can communicate with multiple peripheral devices. The controller commonly shares MOSI, MISO and SCLK among the peripherals while providing a separate CS signal to each device.

Multiple-Peripheral SPI Bus 
                     MCU
              +----------------+
              |                |
              | MOSI ----------+---------+---------+
              |                |         |         |
              | MISO <---------+---------+---------|
              |                |         |         |
              | SCLK ----------+---------+---------+
              |                |         |         |
              | CS0 -----------|----+    |         |
              | CS1 -----------|---------|----+    |
              | CS2 -----------|---------|---------|----+
              +----------------+         |         |    |
                                         |         |    |
                                    +----v---+ +---v--+ +v------+
                                    |Device 0| |Device1| |Device2|
                                    +--------+ +-------+ +-------+

Shared Signal Lines

  • MOSI is connected to all peripheral inputs.
  • SCLK is connected to all peripheral clock inputs.
  • MISO outputs share a common controller input.
  • Each peripheral has an individual chip-select signal.

How Peripheral Selection Works

The controller activates only the CS signal associated with the target peripheral.

CS0 CS1 CS2 Selected Device
LOW HIGH HIGH Device 0
HIGH LOW HIGH Device 1
HIGH HIGH LOW Device 2
HIGH HIGH HIGH None
The table assumes all three peripherals use active-LOW chip select. The controller should normally ensure that only one peripheral is selected at a time when their MISO outputs share the same line.

7. Shared MISO Line and High-Impedance State

In a multiple-peripheral SPI arrangement, the MISO outputs may be connected to the same controller input.

To prevent electrical conflicts, an unselected peripheral should place its MISO output in a high-impedance state.

What Is High Impedance?

High impedance means that an output is electrically disconnected or effectively not driving the shared signal line.

Conceptual Shared MISO Connection 
             Controller MISO Input
                       |
             +---------+---------+
             |         |         |
             |         |         |
          MISO 0    MISO 1    MISO 2
             |         |         |
          Device 0  Device 1  Device 2

        Selected device:
        Drives its MISO output.

        Unselected devices:
        Place MISO in high impedance,
        if supported by their interface.
Not every device automatically places MISO in a high-impedance state when deselected. Verify the device datasheet. If a peripheral continuously drives MISO, a different connection arrangement or external bus isolation may be necessary.

8. Daisy-Chain SPI Architecture

Some SPI-compatible devices support a daisy-chain arrangement. In this configuration, the serial data output of one device connects to the serial data input of the next device.

Daisy-Chain SPI Connection 
             Controller
           +-------------+
           |             |
           | MOSI -------+----+
           | MISO <------+----|-------------------------+
           | SCLK -------+----|----------+----------+   |
           | CS   -------+----|----------|----------|---|
           +-------------+    |          |          |   |
                              |          |          |   |
                         +----v----+ +---v----+ +---v---+
                         | Device 1| |Device 2| |Device3|
                         |         | |        | |       |
                         | SDI     | | SDI    | | SDI   |
                         | SDO ----+>| SDO ---+>| SDO --+
                         +---------+ +--------+ +-------+

In a supported daisy-chain implementation, data is shifted through multiple devices. A single transaction may contain a sequence of data words corresponding to all devices in the chain.

Advantages

  • Can reduce the number of individual chip-select signals.
  • Useful for certain display drivers and shift-register devices.
  • Allows multiple compatible devices to receive a serial data stream.

Limitations

  • Not supported by every SPI peripheral.
  • Data transfer may require longer shift sequences.
  • Device order affects the data arrangement.
  • Firmware must understand the chain length and word format.
Daisy-chain operation is device-specific. It is not a universal feature of the basic SPI protocol.

9. SPI Bus Timing Overview

SPI communication is synchronized by SCLK. Data transmission and sampling take place on clock edges.

The exact edge used for sampling depends on CPOL and CPHA.

10. SPI Bus Electrical Considerations

10.1 Logic Voltage Compatibility

The controller and peripheral must use compatible logic voltage levels.

For example, a 3.3V controller must not automatically be assumed compatible with every 5V peripheral. Check input thresholds and absolute maximum ratings.

10.2 Common Ground

Devices in a typical SPI connection need a common electrical reference, normally provided by connecting their ground terminals.

10.3 Signal Integrity

Fast clock edges and long PCB traces can cause ringing, reflections and crosstalk.

  • Keep signal traces appropriately short.
  • Use a suitable ground return path.
  • Consider series damping resistors where required.
  • Follow PCB layout recommendations from device datasheets.
  • Reduce clock frequency if signal integrity is poor.

10.4 Pull-Up and Pull-Down Requirements

Some SPI devices require defined CS states during startup. External pull-up or pull-down resistors may be appropriate depending on the device's CS polarity and power-up requirements.

SPI does not have the same mandatory open-drain pull-up bus arrangement as I2C. Do not add pull-up resistors to every SPI signal by default.

11. SPI Bus Design Example

Consider an embedded system with one microcontroller connected to three SPI peripherals:

  • External Flash memory.
  • Temperature sensor.
  • Display controller.

Connection Plan

Controller Signal Peripheral Connection
MOSI All three peripheral data inputs
MISO All three peripheral data outputs, if compatible with shared-bus use
SCLK All three peripheral clock inputs
CS0 Flash memory CS
CS1 Temperature sensor CS
CS2 Display controller CS

Example Transaction

  1. Set CS0 LOW to select Flash memory.
  2. Transmit the Flash memory command through MOSI.
  3. Transmit the required address bytes.
  4. Generate clock pulses to receive memory data through MISO.
  5. Set CS0 HIGH to end the transaction.
  6. Select another peripheral when required.

The exact command sequence depends on the Flash memory device datasheet.

12. SPI Bus Architecture vs I2C Bus Architecture

Feature SPI I2C
Clock SCLK SCL
Data MOSI and MISO SDA
Peripheral selection Usually CS signal Device address

Electrical structure Typically push-pull signal lines Open-drain/open-collector bus
Data direction Separate transmit and receive paths Shared bidirectional SDA
Multiple peripherals Shared bus with CS arrangements Addressed devices on shared bus

14. Interview Questions and Answers

Q1. What is SPI bus architecture?

It is the arrangement of a controller and peripheral devices connected through SPI clock, data and chip-select signals.

Q2. How many signal lines are commonly used in SPI?

Four: MOSI, MISO, SCLK and CS.

Q3. Can one controller communicate with multiple SPI devices?

Yes. The data and clock lines can be shared, while individual chip-select signals select the target.

Q4. Why is a separate CS signal commonly used for each device?

It allows the controller to select one peripheral without activating the others.

Q5. What is a high-impedance output?

It is an output state in which a device does not actively drive the shared signal line.

Q6. Why is high impedance important for shared MISO?

It prevents unselected peripherals from interfering with the selected peripheral's output.

Q7. What is SPI daisy chaining?

It is a device-specific arrangement in which serial data passes through multiple connected peripherals.

Q8. Does SPI require pull-up resistors like I2C?

Not generally. Conventional SPI signal lines are typically push-pull, although a device may require external biasing for particular signals.

Q9. What happens if two peripherals drive MISO simultaneously?

They can cause bus contention and incorrect logic levels. The shared connection must be designed to prevent this.

Q10. What is the role of SCLK?

SCLK provides the timing reference for serial data transmission and reception.

  • SPI bus architecture connects a controller to peripheral devices.
  • MOSI carries controller-to-peripheral data.
  • MISO carries peripheral-to-controller data.
  • SCLK synchronizes communication.
  • CS selects the target peripheral.
  • Multiple devices can share clock and data connections.
