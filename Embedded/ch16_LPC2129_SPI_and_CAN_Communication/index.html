Chapter 16: LPC2129 SPI and CAN Communication

Study Serial Peripheral Interface (SPI) and Controller Area Network (CAN) communication. Learn their bus architectures, communication protocols, data transfer, LPC2129 peripheral registers, configuration and Embedded C programming.

Total Lessons: 11

1. Chapter Overview

Embedded systems frequently communicate with external sensors, memory devices, controllers and other microcontrollers. SPI and CAN are two important communication technologies used in embedded applications.

SPI provides synchronous serial communication between a controller and peripheral devices. CAN provides message-based communication between multiple nodes over a shared network.

SPI Communication

Covers SPI architecture, signals, clock modes, LPC2129 registers, data transmission and reception.

CAN Communication

Covers CAN architecture, message frames, identifiers, arbitration, controller registers and bit timing.

6. Important Technical Notes

SPI: SPI uses clock and data signals, typically SCLK, MOSI, MISO and chip-select. It is commonly used for short-distance communication between a controller and peripheral devices.
CAN: CAN uses differential signaling over CAN_H and CAN_L. The CAN controller handles message framing, arbitration, filtering and error management.
LPC2129 CAN hardware: The LPC2129 includes CAN controller hardware, but a physical CAN bus requires an external CAN transceiver. The MCU controller pins must not be connected directly to the differential CAN_H and CAN_L bus.
Keil uVision simulator: This course uses simulator-based development. Peripheral simulation support depends on the selected device model. Successful compilation and register inspection do not prove physical SPI or CAN bus communication.
