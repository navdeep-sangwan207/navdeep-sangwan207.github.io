2. Introduction to CAN

Controller Area Network (CAN) is a serial communication protocol designed for reliable communication between electronic control units (ECUs) and other embedded devices.

CAN was originally developed for automotive applications, where multiple electronic control units needed to exchange information reliably using a shared communication network.

Why Was CAN Developed?

Earlier electronic systems often used separate communication wires between individual controllers. As the number of electronic modules increased, wiring became complex, expensive and difficult to maintain.

CAN addresses these challenges through:

  • A shared communication bus.
  • Message-based communication.
  • Multi-controller access.
  • Priority-based message arbitration.
  • Error detection and fault handling.
  • Reliable communication in electrically noisy environments.
CAN is a broadcast-oriented, message-based protocol. A message carries an identifier that describes its meaning and priority. It does not normally contain a destination node address like a point-to-point communication protocol.

4. CAN Node

A CAN node is an electronic device capable of participating in CAN communication.

Examples include:

  • Engine Control Unit (ECU).
  • Transmission Control Unit.
  • Anti-lock Braking System controller.
  • Battery Management System.
  • Motor Controller.
  • Industrial automation controller.

Responsibilities of a CAN Node

  • Generate CAN messages.
  • Receive messages from the bus.
  • Filter messages based on identifiers.
  • Participate in arbitration.
  • Detect communication errors.
  • Respond to application requirements.

5. CAN Bus Architecture

CAN uses a multi-controller bus architecture. Multiple nodes share the same communication lines.

Characteristics

  • Two-wire differential physical connection.
  • Multiple nodes can transmit when the bus is available.
  • Message arbitration resolves simultaneous transmission attempts.
  • All nodes can observe transmitted frames.
  • Receivers decide which messages are relevant.
CAN is not a conventional master-slave protocol. Any node may initiate transmission when the bus becomes available, subject to arbitration.

Bus Topology

A typical high-speed CAN network uses a linear bus topology with short stubs connecting individual nodes.

6. CAN Differential Signaling

CAN uses differential signaling to improve communication reliability in electrically noisy environments.

The receiver determines the bus state by measuring the voltage difference between CAN_H and CAN_L.

Differential Voltage

Vdiff = V(CAN_H) - V(CAN_L)

Dominant State

In high-speed CAN, the dominant state is normally represented by CAN_H rising and CAN_L falling. The differential voltage is positive and typically around 2 V in a nominal bus condition.

Recessive State

In the recessive state, CAN_H and CAN_L are normally close to the same common-mode voltage, so the differential voltage is approximately zero.

Bus State CAN_H CAN_L Differential Voltage
Recessive Approximately 2.5 V Approximately 2.5 V Approximately 0 V
Dominant Approximately 3.5 V Approximately 1.5 V Approximately 2 V
These are typical illustrative high-speed CAN voltage levels, not universal guaranteed limits. Actual levels depend on the transceiver, loading, supply voltage and network conditions.

7. Dominant and Recessive Bits

CAN uses two bus states called dominant and recessive.

  • Dominant bit represents logic 0.
  • Recessive bit represents logic 1.

A dominant bit overrides a recessive bit when multiple nodes transmit simultaneously.

Wired-AND Behaviour

The CAN bus behaves logically like a wired-AND system using dominant and recessive states.

Node A Node B Bus Result
Recessive (1)Recessive (1)Recessive (1)
Dominant (0)Recessive (1)Dominant (0)
Recessive (1)Dominant (0)Dominant (0)
Dominant (0)Dominant (0)Dominant (0)
This dominant/recessive behaviour is the basis of CAN's non-destructive bitwise arbitration. A node transmitting recessive but observing dominant during arbitration knows that it has lost arbitration and stops transmitting.

8. CAN Message-Based Communication

CAN communicates using messages called frames. Each frame contains an identifier and other control and data fields.

The identifier describes the message and determines its arbitration priority. It is not simply a unique destination address.

Example

CAN IdentifierPossible Message Meaning
0x100Vehicle speed information
0x120Engine temperature information
0x200Battery voltage information
0x300Motor controller status

These identifiers are illustrative examples. Actual message identifiers and meanings are defined by the system's CAN communication specification.

Message Reception

  1. A node transmits a CAN frame.
  2. The frame appears on the shared bus.
  3. All connected nodes can observe it.
  4. Each receiving controller checks the identifier.
  5. Relevant nodes accept the message for processing.

9. CAN Arbitration

Arbitration is the mechanism used to decide which node can continue transmitting when multiple nodes begin transmission at the same time.

CAN uses bitwise, non-destructive arbitration. The message with the numerically lower identifier generally has higher priority when identifiers use the same frame format.

Example

Node A identifier: 0x100
Node B identifier: 0x200

Node A has higher priority
and wins arbitration.

The losing node stops transmitting without corrupting the winning frame. It can attempt transmission again when the bus becomes available.

Detailed arbitration, identifier comparison and bit-by-bit examples are covered in the next CAN lessons.

10. CAN Controller and CAN Transceiver

The CAN controller and CAN transceiver perform different functions.

CAN ControllerCAN Transceiver
Implements CAN protocol logic. Interfaces with the physical bus.
Creates and checks CAN frames. Drives and senses CAN_H/CAN_L.
Handles arbitration and error detection. Converts logic-level TX/RX signals to differential signaling.
Uses controller registers and buffers. Uses electrical bus drivers and receivers.

LPC2129 Example

The LPC2129 contains integrated CAN controller hardware. A suitable external CAN transceiver is still required to connect the controller to a physical CAN bus.

The LPC2129 CAN controller's logic-level signals cannot be connected directly to CAN_H and CAN_L. Use a compatible external CAN transceiver and follow its electrical and protection requirements.

11. CAN Termination

Termination resistors help prevent signal reflections caused by impedance mismatch on the transmission line.

Typical High-Speed CAN Termination

  • 120-ohm termination at one physical end.
  • 120-ohm termination at the other physical end.
  • No additional 120-ohm termination at every node.

Equivalent Resistance

Rtotal = 120 ohm || 120 ohm

Rtotal = (120 x 120) / (120 + 120)

Rtotal = 60 ohm

With two 120-ohm termination resistors installed at opposite ends, a powered-down measurement across CAN_H and CAN_L commonly reads close to 60 ohms, assuming no other termination networks or circuit paths affect the measurement.

CAN bit rate is determined by the controller's clock configuration and bit-timing parameters. The network bit rate must be compatible across all nodes.

14. Advantages of CAN

  • Reliable communication in electrically noisy environments.
  • Reduced wiring compared with many point-to-point connections.
  • Multi-controller communication.
  • Priority-based arbitration.
  • Built-in error detection.
  • Automatic retransmission in applicable error conditions.
  • Message filtering.
  • Well-established automotive and industrial ecosystem.

15. Limitations of CAN

  • Classical CAN carries a maximum of 8 data bytes per frame.
  • Network bit rate and length are interdependent.
  • Termination and wiring must be designed correctly.
  • Bus loading can increase message latency.
  • High-priority traffic can delay lower-priority messages.
  • CAN requires compatible transceivers and bit timing.
  • It does not provide encryption or authentication by itself.
CAN FD extends the classical CAN data-field capacity to as much as 64 bytes and supports a faster data phase. This is distinct from Classical CAN and requires compatible controllers and network nodes.

17. Introduction to CAN in LPC2129

The LPC2129 microcontroller provides integrated CAN controller hardware that can be used to communicate with other CAN nodes.

CAN Controller Features

  • CAN message transmission.
  • CAN message reception.
  • Message acceptance filtering.
  • Bit timing configuration.
  • Interrupt-based communication.
  • Hardware error-status reporting.

The LPC2129 provides two CAN controller interfaces, CAN1 and CAN2. Each controller requires appropriate pin configuration and an external physical-layer transceiver for connection to the CAN bus.

A CAN controller being present in the microcontroller does not mean that a complete physical CAN network can operate without external hardware. The transceiver, bus wiring, termination and compatible peer node are required for practical communication.

19. Interview Questions and Answers

Q1. What is CAN?

CAN is a serial communication protocol used for reliable message exchange between electronic controllers.

Q2. What is the full form of CAN?

Controller Area Network.

Q3. Why is CAN used in automobiles?

It provides reliable multi-controller communication while reducing wiring complexity.

Q4. What are CAN_H and CAN_L?

They are the two differential bus lines used for CAN communication.

Q5. What is differential signaling?

It is a signaling method in which the receiver detects the voltage difference between two lines.

Q6. What is a CAN node?

A device connected to the CAN network that can transmit, receive or monitor CAN messages.

Q7. What is a CAN transceiver?

It converts controller logic signals into differential bus signals and converts received bus signals back into logic-level signals.

Q8. What are dominant and recessive states?

Dominant represents logic 0 and recessive represents logic 1 in the CAN bus signaling model.

Q9. What is CAN arbitration?

It is the process of selecting which message continues when multiple nodes start transmitting simultaneously.

Q10. Why are termination resistors used?

They reduce signal reflections by matching the transmission-line impedance at the physical ends of the bus.

Q11. Does LPC2129 contain a CAN transceiver?

No. It contains CAN controller hardware. An external compatible CAN transceiver is required for physical bus communication.

Q12. What is the difference between CAN and UART?

UART commonly provides asynchronous point-to-point communication, while CAN provides a shared, message-based multi-controller network.
