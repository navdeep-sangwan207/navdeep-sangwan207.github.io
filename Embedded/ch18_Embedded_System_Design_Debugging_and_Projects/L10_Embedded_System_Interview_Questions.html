Lesson 10: Embedded System Interview Questions

Chapter 18: Embedded System Design, Debugging and Projects

Level: Interview Preparation – Basic to Advanced

Prepare for embedded software, firmware development, microcontroller programming, ARM architecture, LPC2129 peripherals, RTOS, debugging and project-based technical interviews.

1. Embedded Systems Fundamentals

Q1. What is an embedded system?

An embedded system is a combination of hardware and software designed to perform a specific function within a larger product or system.

Q2. What are the main components of an embedded system?

  • Microcontroller or microprocessor.
  • Program and data memory.
  • Input and output interfaces.
  • Power supply.
  • Sensors and actuators.
  • Firmware.

Q3. What is the difference between a microprocessor and a microcontroller?

A microprocessor generally requires external memory and peripheral devices. A microcontroller integrates a processor, memory and peripherals into one chip.

Q4. What is a real-time embedded system?

A real-time system must produce a correct result within a specified timing constraint. Correctness depends on both the result and the time at which it is delivered.

Q5. Differentiate hard real-time and soft real-time systems.

Hard real-time: Missing a critical deadline is considered a system failure.

Soft real-time: Occasional deadline misses reduce performance or quality but do not necessarily cause complete system failure.

Q6. What is firmware?

Firmware is software stored in non-volatile memory that controls the operation of an electronic device.

Q7. What is the difference between polling and interrupts?

Polling repeatedly checks a peripheral or event status. Interrupts allow a peripheral or event to request processor attention when a configured condition occurs.

Q8. What is an ISR?

An Interrupt Service Routine is a function or handler executed in response to an interrupt. It should perform essential work quickly and defer lengthy processing where appropriate.

Q9. What is a watchdog timer?

A watchdog timer is a hardware timer that can reset or otherwise recover a system if firmware fails to service it within the configured time.

Q10. What is a bootloader?

A bootloader is a program that executes during startup and may initialize the system, verify firmware and load or update the application.

2. Embedded C Programming

Q11. Why is Embedded C used?

Embedded C provides low-level hardware access and efficient control over memory, registers, peripherals and timing-sensitive operations.

Q12. What is the volatile keyword?

volatile tells the compiler that a value may change outside the normal flow of the code it can observe. It is commonly used for memory-mapped registers and variables shared with interrupt handlers.

volatile unsigned int timer_flag;

Q13. Does volatile make an operation atomic?

No. volatile does not guarantee atomicity, mutual exclusion or thread safety. Critical sections or suitable synchronization mechanisms may still be required.

Q14. What is a pointer?

A pointer is a variable that stores the memory address of another object or function, subject to the language's pointer rules.

int value = 10;
int *ptr = &value;

Q15. What is a NULL pointer?

A null pointer is a pointer value that does not point to a valid object or function. It should not be dereferenced.

Q16. What is a dangling pointer?

A dangling pointer refers to an object whose lifetime has ended or whose storage is no longer valid for the intended access.

Q17. What is a memory leak?

A memory leak occurs when dynamically allocated memory is no longer reachable or cannot be released even though it is no longer needed.

Q18. What is the difference between stack and heap?

Q19. What is the difference between const and volatile?

const prevents modification through the specified access path. volatile affects compiler assumptions about how a value can change. Both qualifiers can be used together.

volatile const unsigned int *status_reg;

Q20. Why are fixed-width integer types useful?

Types such as uint8_t, uint16_t and uint32_t provide explicit widths where available through stdint.h, which is useful for register operations and communication formats.

Q21. What is bit masking?

Bit masking uses a binary mask to select, set, clear or test specific bits.

reg |=  (1U << 3);  // Set bit 3
reg &= ~(1U << 3); // Clear bit 3
if (reg & (1U << 3))
{
    // Bit 3 is set
}

Q22. What is the difference between structure and union?

A structure allocates storage for its members as separate members, subject to padding and alignment. A union shares storage among its members, so typically only one member's stored representation is intended to be active at a time.

Q23. What is a static variable?

A static variable has static storage duration. A local static variable retains its value between function calls; a file-scope static declaration also gives the identifier internal linkage.

Q24. What is an enumeration?

An enumeration defines a set of named integer constants, improving readability when representing states or modes.

typedef enum
{
    SYSTEM_IDLE,
    SYSTEM_RUNNING,
    SYSTEM_ERROR
} system_state_t;

3. ARM7 and Processor Architecture

Q25. What is ARM architecture?

ARM is a family of processor architectures based on the RISC design approach, used in a wide range of embedded and computing devices.

Q26. What is ARM7TDMI?

ARM7TDMI is an ARM processor core that includes Thumb instruction support, debug support and the EmbeddedICE debug logic, along with the multiplier extension indicated by the name.

Q27. What are the operating modes of ARM7TDMI?

  • User mode.
  • FIQ mode.
  • IRQ mode.
  • Supervisor mode.
  • Abort mode.
  • Undefined mode.
  • System mode.

Q28. What is CPSR?

The Current Program Status Register stores condition flags, processor state information and control bits such as interrupt masks and mode bits.

Q29. What is SPSR?

The Saved Program Status Register stores a copy of the CPSR when an exception is entered in an exception mode that has an SPSR.

Q30. What is the ARM pipeline?

A pipeline overlaps instruction processing stages to improve instruction throughput. ARM7TDMI uses a three-stage Fetch, Decode and Execute pipeline.

Q31. What is the difference between ARM and Thumb states?

ARM state uses 32-bit instructions. Thumb state uses a compact 16-bit instruction encoding in the original ARM7TDMI architecture, improving code density for many applications.

Q32. What is the difference between IRQ and FIQ?

IRQ is a normal interrupt request. FIQ is a fast interrupt request with additional banked registers that support faster handling in suitable designs.

4. LPC2129 Microcontroller

Q33. What is LPC2129?

LPC2129 is an ARM7TDMI-S-based microcontroller from NXP, with on-chip Flash, SRAM and integrated peripherals.

Q34. What is the role of PLL?

The Phase-Locked Loop generates a higher system clock from the external oscillator, within the device's specified operating limits.

Q35. What are CCLK and PCLK?

CCLK is the CPU clock. PCLK is the peripheral clock used by peripheral modules. Their relationship depends on the clock configuration and VPBDIV setting.

Q36. What does VPBDIV do?

VPBDIV selects the peripheral clock divider. On LPC2129, the documented settings select CCLK, CCLK/2 or CCLK/4; the reserved encoding must not be used.

Q37. What is GPIO?

General-Purpose Input/Output pins are configurable digital pins that can be used to read external logic signals or control external logic circuits.

Q38. What is PINSEL?

PINSEL registers configure the pin multiplexing functions of LPC2129 pins, selecting GPIO or an alternate peripheral function where supported.

Q39. What is the difference between IODIR and IOPIN?

IODIR configures GPIO direction. IOPIN reads the pin state and, where supported by the device, can also be used for GPIO output access. IOSET and IOCLR provide dedicated set and clear operations.

Q40. What is the difference between IOSET and IOCLR?

IOSET writes ones to set selected output bits. IOCLR writes ones to clear selected output bits. These registers use write-one-to-set and write-one-to-clear behaviour, so direct assignment is preferred.

IOSET0 = (1U << 5); // Set P0.5
IOCLR0 = (1U << 5); // Clear P0.5

Q41. What is the LPC2129 ADC resolution?

The ADC is 10-bit. Its digital result ranges from 0 to 1023.

Q42. How many ADC channels does LPC2129 provide?

The LPC2129 has four ADC input channels, AIN0 through AIN3. Check the device documentation for the exact pin mapping and electrical limits.

Q43. Does LPC2129 have an internal DAC?

No. An external DAC is required when an application needs a true analog output from this controller.

Q44. How many general-purpose timers are available?

LPC2129 provides Timer0 and Timer1. Each timer includes a prescaler, match channels and capture channels.

5. LPC2129 Peripheral Programming

Q45. What is the purpose of the timer prescaler register?

The PR register divides the peripheral clock before the timer counter increments.

TC increment frequency = PCLK / (PR + 1)

For PCLK = 15 MHz and PR = 14999, the TC increment frequency is 1 kHz, corresponding to a nominal 1 ms increment interval.

Q46. What is a match register?

A match register stores a value compared against the timer counter. A match can generate an interrupt, reset the timer or stop it, depending on MCR configuration.

Q47. What is UART?

UART is an asynchronous serial communication peripheral that transmits and receives data using configured frame parameters such as baud rate, data bits, parity and stop bits.

Q48. What is the difference between UART and USART?

UART supports asynchronous communication. USART can support both asynchronous and synchronous communication modes, depending on the device.

Q49. What is baud rate?

Baud rate is the number of signal symbols transmitted per second. In ordinary binary UART signaling, one symbol represents one bit, so baud rate and bit rate have the same numerical value.

Q50. What is I2C?

I2C is a synchronous serial bus that uses SDA for data and SCL for clock. It supports addressed devices on a shared bus.

Q51. What is an I2C START condition?

A START condition occurs when SDA transitions from HIGH to LOW while SCL is HIGH.

Q52. What is an I2C STOP condition?

A STOP condition occurs when SDA transitions from LOW to HIGH while SCL is HIGH.

Q53. What is SPI?

SPI is a synchronous serial communication interface commonly using SCK, MOSI, MISO and a slave-select signal.

Q54. What is the difference between SPI and I2C?

Q55. What is CAN?

Controller Area Network is a message-based serial communication protocol widely used in automotive and industrial systems.

Q56. What is CAN arbitration?

CAN arbitration resolves simultaneous transmission attempts. A dominant bit overrides a recessive bit, allowing the frame with the higher-priority identifier to continue without corrupting the winning frame.

Q57. Why is an external CAN transceiver required?

The CAN controller handles protocol logic, while the transceiver converts between controller logic-level signals and differential CAN bus signals on CANH and CANL.

Q58. What is PWM?

Pulse Width Modulation controls the average power delivered to a load by varying the duty cycle of a periodic digital waveform.

Q59. What is duty cycle?

Duty cycle is the percentage of a period during which the signal remains in its active state.

Duty Cycle (%) =
    (ON Time / Total Period) × 100

Q60. What is ADC quantization?

Quantization maps a continuous analog input into one of a finite number of digital output codes.

6. RTOS and Real-Time Programming

Q61. What is an RTOS?

A Real-Time Operating System provides scheduling and synchronization services designed to support tasks with timing requirements.

Q62. What is a task?

A task is an independently schedulable unit of execution managed by an RTOS.

Q63. What is context switching?

Context switching saves the execution state of one task and restores the state of another task so the processor can switch between them.

Q64. What is task priority?

Task priority represents the relative scheduling importance assigned to a task. The exact scheduling behaviour depends on the RTOS policy.

Q65. What is a semaphore?

A semaphore is a synchronization mechanism used for signaling or controlling access to shared resources.

Q66. What is a mutex?

A mutex is a mutual-exclusion mechanism used to protect shared resources. Many RTOS mutex implementations support priority inheritance.

Q67. What is a race condition?

A race condition occurs when the result depends on the timing or ordering of concurrent operations accessing shared state.

Q68. What is priority inversion?

Priority inversion occurs when a high-priority task is indirectly blocked by a lower-priority task holding a required resource. Priority inheritance can help mitigate this problem.

Q69. What is deadlock?

Deadlock occurs when tasks wait indefinitely for resources held by each other, preventing progress.

Q70. What is the difference between an RTOS and a general-purpose OS?

An RTOS focuses on predictable timing and scheduling behaviour. A general-purpose OS typically prioritizes overall throughput, responsiveness and broad application support.

7. Debugging and Testing

Q71. What is debugging?

Debugging is the process of locating, understanding and correcting defects in software or firmware.

Q72. What is a breakpoint?

A breakpoint pauses program execution at a selected location so the developer can inspect program state.

Q73. What is a logic analyzer?

A logic analyzer captures and displays digital signals over time, helping diagnose digital communication and timing problems.

Q74. What is an oscilloscope?

An oscilloscope displays electrical signals as a function of time and is used to examine voltage, timing, noise and waveform characteristics.

Q75. What is unit testing?

Unit testing verifies an individual function or software module independently.

Q76. What is regression testing?

Regression testing checks that existing functionality remains correct after firmware changes.

Q77. What is a memory overflow?

A memory overflow occurs when a program accesses or writes beyond the valid bounds of a memory object or region.

Q78. What is stack overflow?

Stack overflow occurs when stack usage exceeds the available stack space, potentially corrupting memory or causing a fault.

8. Embedded System Design and Reliability

Q79. What is EMI?

Electromagnetic Interference is unwanted electromagnetic disturbance that can affect electronic equipment.

Q80. What is EMC?

Electromagnetic Compatibility is the ability of equipment to operate satisfactorily in its electromagnetic environment without causing unacceptable interference.

Q81. Why are decoupling capacitors used?

They provide local transient current and help reduce supply-voltage disturbances near integrated circuits.

Q82. What is a flyback diode?

A flyback diode provides a current path for an inductive DC load when its driving switch turns off, limiting the resulting voltage transient.

Q83. What is low-power design?

Low-power design reduces energy consumption through clock management, suitable low-power modes, peripheral control, duty cycling and efficient hardware selection.

Q84. What is fault tolerance?

Fault tolerance is the ability of a system to continue providing specified functionality despite certain faults.

Q85. What is fail-safe design?

Fail-safe design aims to move the system into a defined safe condition when specified failures occur.

Q86. What is FMEA?

Failure Mode and Effects Analysis is a structured method for identifying potential failure modes, their effects and possible actions to reduce risk.

9. Project-Based Interview Questions

Q87. Explain your embedded systems project.

A clear project explanation should cover:

  1. Problem statement.
  2. Project objective.
  3. Hardware components.
  4. Microcontroller and interfaces.
  5. Firmware architecture.
  6. Important algorithms.
  7. Testing and debugging method.
  8. Results and limitations.
  9. Possible improvements.

Q88. How would you explain an overvoltage and undervoltage protection project?

Explain how the input voltage is sensed, how the comparator thresholds are established, how the control circuit responds to voltage outside the allowed range, and how the output is indicated or disconnected. Include the protection circuit's operating limits and testing method.

Q89. How would you design a temperature monitoring system using LPC2129?

Describe the sensor interface, ADC configuration, temperature conversion, threshold comparison, LCD or UART output, alarm control and fault handling.

Q90. How would you control a DC motor using LPC2129 PWM?

Explain PWM frequency and duty-cycle configuration, the motor-driver interface, direction control if required, power supply design and protection. The motor must be driven through a suitable external driver rather than directly from a microcontroller pin.

Q91. How would you debug a UART communication failure?

  1. Verify pin multiplexing.
  2. Check the peripheral clock.
  3. Check baud-rate divisor and fractional divider.
  4. Verify line format and parity settings.
  5. Inspect line-status and interrupt registers.
  6. Check external signal levels and wiring on hardware.
  7. Use a serial terminal or logic analyzer where available.

Q92. How would you debug an ADC reading that is always zero?

  1. Check the analog pin selection.
  2. Verify the PINSEL configuration.
  3. Check ADC clock configuration.
  4. Verify power-up and conversion-start settings.
  5. Inspect the conversion-complete status.
  6. Check the result-register extraction.
  7. Verify analog input voltage and reference on hardware.

Q93. How would you explain your debugging experience?

Describe a specific problem, the symptoms, your diagnostic steps, the root cause, the corrective action and how you verified the result. Clearly distinguish simulator observations from hardware measurements.

10. Practical Coding Questions

Q94. Write a program to set and clear a GPIO bit.

#include <LPC21xx.h>

int main(void)
{
    unsigned int led_mask = (1U << 5);

    // Select GPIO function for P0.5
    PINSEL0 &= ~(3U << 10);

    // Configure P0.5 as output
    IODIR0 |= led_mask;

    while (1)
    {
        IOSET0 = led_mask;
        // Output bit set

        IOCLR0 = led_mask;
        // Output bit cleared
    }
}

Interview explanation: PINSEL0 selects GPIO, IODIR0 configures the pin as an output, and IOSET0/IOCLR0 set and clear the output bit.

Q95. Write a program to check a bit.

unsigned int status;
unsigned int bit_value;

status = IOPIN0;
bit_value = (status >> 6) & 1U;

if (bit_value == 1U)
{
    // Input is HIGH
}
else
{
    // Input is LOW
}

Q96. Write a function to extract a 10-bit ADC result.

unsigned int ADC_ExtractResult(unsigned int data)
{
    return (data >> 6) & 0x3FFU;
}

Q97. Write a function to calculate ADC voltage.

float ADC_ToVoltage(unsigned int result,
                    float reference_voltage)
{
    return ((float)result * reference_voltage)
           / 1023.0f;
}

Note: This uses an endpoint-scaled conversion estimate. Use the actual ADC reference voltage and account for calibration and converter error in a real measurement system.

Q98. Write a function to set a selected bit.

unsigned int SetBit(unsigned int value,
                    unsigned int bit)
{
    return value | (1U << bit);
}

Q99. Write a function to clear a selected bit.

unsigned int ClearBit(unsigned int value,
                      unsigned int bit)
{
    return value & ~(1U << bit);
}

Q100. Write a function to toggle a selected bit.

unsigned int ToggleBit(unsigned int value,
                       unsigned int bit)
{
    return value ^ (1U << bit);
}

12. Common HR and Technical Discussion Questions

Q101. Tell me about yourself.

Structure your response around your education, relevant technical skills, practical projects, experience and the embedded role you are targeting.

Q102. Why do you want to work in embedded systems?

Explain your interest in combining electronics and programming to develop firmware that controls real devices.

Q103. What tools have you used?

Describe only tools you have actually used. For example, discuss Keil uVision, C/C++, Ubuntu, debugging tools and relevant microcontroller development environments according to your experience.

Q104. What is your approach when you do not know an answer?

Explain what you understand, identify the missing information, refer to the datasheet or technical documentation and propose a method to verify the answer.

Q105. How do you explain a project that was developed using simulation?

State that it was developed and examined in the simulator. Describe the code, register configuration and observed simulator behaviour. Clearly identify what still requires physical hardware validation.

A strong technical interview answer should be specific and evidence-based. Avoid claiming hardware testing, measured performance or project results that you did not actually verify.

13. Final Interview Preparation Checklist

  • Understand microcontroller architecture and memory.
  • Revise C pointers, arrays, structures and bitwise operations.
  • Understand volatile, const, static and fixed-width types.
  • Revise ARM7 operating modes, CPSR and exceptions.
  • Understand LPC2129 clock and GPIO configuration.
  • Practice timer and interrupt programming.
  • Revise UART, I2C, SPI and CAN communication.
  • Understand ADC conversion and PWM control.
  • Revise RTOS tasks, scheduling and synchronization.
  • Practice debugging and test-case preparation.
  • Prepare detailed explanations of your own projects.
  • Review datasheets and reference manuals.

14. Final Practical Assignments

  1. Write a GPIO program that controls an LED using a push button.
  2. Configure Timer0 to generate a periodic match event.
  3. Configure UART0 for serial communication.
  4. Read an analog value using the LPC2129 ADC.
  5. Generate PWM with a selected duty cycle.
  6. Write an I2C master-transmitter state machine.
  7. Write an SPI polling-based data transfer routine.
  8. Configure CAN transmission using a suitable transceiver-based system design.
  9. Design a modular firmware project with separate driver files.
  10. Prepare a test plan and debugging report for a complete embedded application.

15. Lesson Summary

  • Embedded interviews evaluate hardware, firmware and system-level understanding.
  • Embedded C knowledge is essential for low-level programming.
  • ARM7 architecture explains processor operation and exception handling.
  • LPC2129 knowledge includes GPIO, timers, interrupts and communication peripherals.
  • RTOS concepts include tasks, scheduling, synchronization and priority inversion.
  • Debugging requires a systematic approach and suitable tools.
  • Project discussions should explain design decisions and test evidence.
  • Accurate technical answers are more valuable than memorized claims.
