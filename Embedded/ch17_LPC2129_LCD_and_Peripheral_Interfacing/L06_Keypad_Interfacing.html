2. Introduction to Keypads

A keypad is an input device used to enter numbers, characters or commands into an embedded system. It contains multiple switches arranged in a convenient layout.

Common keypad applications include:

  • Digital door locks.
  • Electronic calculators.
  • Industrial control panels.
  • Access-control systems.
  • Banking terminals.
  • Embedded menu navigation.
A keypad provides a human-machine interface (HMI). The microcontroller scans its input lines to determine which key has been pressed.

5. Row and Column Scanning Principle

The microcontroller detects a key by activating one row at a time and reading the column inputs.

Basic Scanning Steps

  1. Configure row lines as outputs.
  2. Configure column lines as inputs.
  3. Set all row outputs to their inactive state.
  4. Activate the first row.
  5. Read all column inputs.
  6. If a column indicates a pressed key, record its row and column.
  7. Repeat for the remaining rows.
  8. Apply debounce and key-release handling.

The example program below uses active-LOW scanning: one row is driven LOW while the other rows remain HIGH. A pressed key pulls its corresponding column LOW. External or internal pull-up resistors are required on the column inputs.

GPIO Direction Configuration

#include <LPC21xx.h>

#define ROW_MASK (0x0FU << 4)

#define COL_MASK ((1U << 8)  | \
                  (1U << 9)  | \
                  (1U << 14) | \
                  (1U << 23))

void Keypad_GPIO_Init(void)
{
    /* Select GPIO function for P0.4 to P0.9 */
    PINSEL0 &= ~0x000FFFF0U;

    /* Select GPIO for P0.14 */
    PINSEL0 &= ~(3U << 28);

    /* Select GPIO for P0.23 */
    PINSEL1 &= ~(3U << 14);

    /* Configure row lines as outputs */
    IODIR0 |= ROW_MASK;

    /* Configure column lines as inputs */
    IODIR0 &= ~COL_MASK;

    /* Set all rows HIGH */
    IOSET0 = ROW_MASK;
}
The example uses P0.4-P0.9, P0.14 and P0.23. Check the complete project pin allocation before using these pins with other peripherals. Column inputs need suitable pull-ups. The GPIO configuration does not automatically enable a pull-up on every LPC2129 pin.

For active-LOW scanning, a column bit equal to zero indicates that a key may be pressed in the currently active row.

For example, row index 1 and column index 1 identify the character '5'. The array uses zero-based indexing.

9. Complete 4x4 Keypad Scanning Program

This program scans one row at a time and returns the first detected key. It uses active-LOW columns and assumes external or verified internal pull-up resistors. 

#include <LPC21xx.h>

#define ROW_MASK (0x0FU << 4)

#define COL_MASK ((1U << 8)  | \
                  (1U << 9)  | \
                  (1U << 14) | \
                  (1U << 23))

const char keypad_map[4][4] =
{
    {'1', '2', '3', 'A'},
    {'4', '5', '6', 'B'},
    {'7', '8', '9', 'C'},
    {'*', '0', '#', 'D'}
};

const unsigned int row_pins[4] =
{
    4U, 5U, 6U, 7U
};

const unsigned int col_pins[4] =
{
    8U, 9U, 14U, 23U
};

void Delay_Short(volatile unsigned int count)
{
    while (count--)
    {
        /* Demonstration delay only */
    }
}

void Keypad_Init(void)
{
    PINSEL0 &= ~0x000FFFF0U;
    PINSEL0 &= ~(3U << 28);
    PINSEL1 &= ~(3U << 14);

    IODIR0 |= ROW_MASK;
    IODIR0 &= ~COL_MASK;

    IOSET0 = ROW_MASK;
}

char Keypad_Scan(void)
{
    unsigned int row;
    unsigned int col;

    for (row = 0U; row < 4U; row++)
    {
        /* Keep all rows inactive */
        IOSET0 = ROW_MASK;

        /* Activate one row LOW */
        IOCLR0 = (1U << row_pins[row]);

        Delay_Short(100U);

        for (col = 0U; col < 4U; col++)
        {
            if ((IOPIN0 & (1U << col_pins[col])) == 0U)
            {
                /* Key detected */
                IOSET0 = ROW_MASK;
                return keypad_map[row][col];
            }
        }
    }

    IOSET0 = ROW_MASK;
    return '\0';
}

int main(void)
{
    char key;

    Keypad_Init();

    while (1)
    {
        key = Keypad_Scan();

        if (key != '\0')
        {
            /* Inspect key in debugger */
            volatile char detected_key = key;
            (void)detected_key;

            /* Wait for key release in a simple demonstration */
            while ((IOPIN0 & COL_MASK) != COL_MASK)
            {
                Delay_Short(100U);
            }

            Delay_Short(5000U);
        }
    }
}

Program Explanation

  • Keypad_Init() configures row outputs and column inputs.
  • keypad_map[][] stores the key labels.
  • row_pins[] stores the row GPIO pin numbers.
  • col_pins[] stores the column GPIO pin numbers.
  • Keypad_Scan() activates each row and checks the columns.
  • A detected row-column combination is converted into a character.
  • '\0' indicates that no key was detected.
This is a basic single-key scanner, not a complete multi-key rollover driver. Its key-release loop assumes the column inputs return HIGH when no key is pressed. With multiple simultaneous keys, matrix ghosting can occur unless the keypad includes isolation diodes and the scanning algorithm handles multiple-key states.

10. Key Debouncing

Mechanical keypad contacts do not always change cleanly between HIGH and LOW. When a key is pressed or released, the contact may produce several rapid transitions.

This behavior is called switch bouncing.

Key Press
↓
Contact Bouncing
↓
Debounce Verification
↓
Stable Key Detection

Software Debouncing Concept

  1. Detect a possible key press.
  2. Wait for a short debounce interval.
  3. Read the same key position again.
  4. Accept the key only if it remains pressed.
  5. Wait for the key to be released before accepting another press.
if (key_detected)
{
    Delay_Short(DEBOUNCE_COUNT);

    if (same_key_is_still_pressed)
    {
        /* Accept key press */
    }
}
The delay above is conceptual. A production implementation should use a timer-based debounce interval selected for the keypad's mechanical characteristics. The release state should also be verified.

11. Interfacing Keypad with LCD

A keypad and LCD can be combined to create a simple user interface. The keypad provides input, and the LCD displays the detected key.

Example Application Logic

char key;

key = Keypad_Scan();

if (key != '\0')
{
    LCD_Command(0x80U);
    LCD_String("KEY PRESSED:");

    LCD_Command(0xC0U);
    LCD_Data(key);
}

The example assumes that the LCD driver from the previous lessons has already been initialized and that the keypad and LCD use non-conflicting GPIO pins.

The keypad example uses P0.4-P0.9, P0.14 and P0.23. The LCD uses P0.10, P0.12, P0.13 and P0.15-P0.22. Check all PINSEL and GPIO assignments before combining the two drivers in one project.

14. Interview Questions and Answers

Q1. What is a matrix keypad?

A matrix keypad arranges switches into rows and columns to reduce GPIO pin requirements.

Q2. How many GPIO lines are required for a 4x4 keypad?

Four row lines plus four column lines, giving eight GPIO lines.

Q3. What is keypad scanning?

It is the process of activating rows one at a time and reading column inputs to identify a pressed key.

Q4. Why are pull-up resistors used?

They keep inactive column inputs at a defined HIGH logic level.

Q5. What is switch debouncing?

It is the process of rejecting rapid unwanted transitions caused by mechanical contact bouncing.

Q6. What is key mapping?

It converts a row-column index into the character assigned to that keypad position.

Q7. What is keypad ghosting?

It is an ambiguous detection condition in which multiple pressed keys can create unintended row-column paths.

Q8. What does a null character returned by a scanner indicate?

In this example, it indicates that no key was detected.

Q9. Why should the program wait for key release?

It prevents one continuous press from being interpreted as repeated separate key presses.

Q10. Can a keypad share GPIO pins with an LCD?

Only if the wiring and software are deliberately designed for sharing. The example drivers here use separate pin allocations.

18. Lesson Summary

  • A matrix keypad organizes switches into rows and columns.
  • A 4x4 keypad uses eight GPIO lines for 16 keys.
  • Row-column scanning identifies the pressed key.
  • Pull-up resistors establish defined inactive input levels.
  • Key mapping converts row and column positions into characters.
  • Debouncing rejects unwanted mechanical transitions.
  • Key-release handling prevents repeated detection of one press.
  • Multiple-key operation may require ghosting prevention.
  • The LPC2129 GPIO interface can scan a matrix keypad.
  • A keypad and LCD can form a simple embedded user interface.
