2. What is an LCD?

LCD stands for Liquid Crystal Display. It is an electronic display technology that uses liquid crystal material to control how light passes through the display.

Character LCD modules are commonly used in embedded systems to display letters, numbers, symbols and short messages.

A typical 16x2 character LCD can display:

  • 16 characters in each row.
  • 2 rows of characters.
  • A total of 32 character positions.
Example: A 16x2 LCD can display a message such as EMBEDDED SYSTEMS on the first row and LPC2129 PROJECT on the second row.
16x2 CHARACTER LCD
EMBEDDED SYSTEMS
LPC2129 PROJECT

16 character positions × 2 rows = 32 positions

3. Why is LCD Interfacing Required?

A microcontroller processes data internally, but users generally need a way to observe the results. An LCD provides a simple visual interface between the embedded system and the user.

LCDs are used to display:

  • Sensor measurements such as temperature and humidity.
  • Voltage, current and frequency readings.
  • System status and operating modes.
  • Error messages and warning notifications.
  • Menu options and user instructions.
  • Numerical values generated by embedded applications.

5. Internal Architecture of a Character LCD

A typical character LCD module contains a controller, display memory, character-generation circuitry and the LCD panel.

Microcontroller Interface
↓
LCD Controller
↓
Display Data RAM (DDRAM)
↓

Main Components

  • LCD Controller: Receives commands and data from the microcontroller and manages display operations.
  • DDRAM: Stores character codes for the positions currently represented on the display.
  • Character Generator ROM: Contains predefined character patterns.
  • Character Generator RAM: Allows custom character patterns to be defined on supported controllers.
  • LCD Panel: Displays the characters using liquid crystal elements and a backlight, if provided.
The exact internal memory organization and command behavior depend on the LCD controller. The HD44780-compatible interface is used as the reference throughout this chapter.

6. LCD Pin Configuration

A standard parallel 16x2 LCD commonly uses a 16-pin connector. The exact module may differ, so its datasheet should always be checked.

Pin Signal Function
1VSSGround
2VDDSupply voltage
3V0 / VEEContrast adjustment
4RSRegister Select
5RWRead/Write control
6ENEnable signal
7–14D0–D78-bit data bus
15LED+Backlight anode, if provided
16LED-Backlight cathode, if provided

Important Control Pins

RS – Register Select

  • RS = 0: Selects the instruction/command register.
  • RS = 1: Selects the data register.

RW – Read/Write

  • RW = 0: Write operation.
  • RW = 1: Read operation.

EN – Enable

  • The enable signal controls the transfer of commands or data.
  • The controller latches the bus information using the required enable transition.
For simple write-only applications, RW can be connected permanently to GND. The microcontroller then needs to control only RS, EN and the data lines. The software must use suitable delays because it cannot read the LCD busy flag in this arrangement.

7. LCD Communication Modes

A character LCD generally supports two parallel communication modes: 8-bit mode and 4-bit mode.

7.1 Eight-Bit Mode

In 8-bit mode, the microcontroller transfers one complete byte using eight data lines, D0 to D7.

  • Uses eight data GPIO connections.
  • Transfers a complete data byte in one bus operation.
  • Requires more microcontroller pins.
  • Useful when sufficient GPIO pins are available.
LPC2129
↓ D0–D7
LCD Data Bus
↓
LCD Controller

7.2 Four-Bit Mode

In 4-bit mode, only data lines D4, D5, D6 and D7 are used. Each 8-bit command or character is transferred in two 4-bit portions.

  • Uses four data GPIO connections.
  • Reduces the number of GPIO pins required.
  • Requires two data transfers for each byte.
  • Requires a specific initialization sequence.

8. LPC2129 and LCD Interfacing

The LPC2129 is an ARM7-based microcontroller with GPIO ports that can be used to communicate with an external character LCD.

The microcontroller sends control signals and data through its GPIO pins. The LCD controller interprets these signals and updates the display.

Project Pin Mapping

The following pin mapping is used in this course:

LCD Signal LPC2129 Pin Purpose
RSP0.10Command/data selection
RWP0.12Read/write selection
ENP0.13Enable control
D0P0.15Data bit 0
D1P0.16Data bit 1
D2P0.17Data bit 2
D3P0.18Data bit 3
D4P0.19Data bit 4
D5P0.20Data bit 5
D6P0.21Data bit 6
D7P0.22Data bit 7
Pin-mapping precautions: All these signals use Port 0. Configure the relevant PINSEL0 and PINSEL1 fields for GPIO before use. P0.10 may conflict with an LED connection in another project, so do not use both functions simultaneously without changing the wiring.

GPIO Configuration

For this 8-bit arrangement, all LCD control and data pins are configured as GPIO outputs. 

#include <LPC21xx.h>

#define LCD_RS   (1U << 10)
#define LCD_RW   (1U << 12)
#define LCD_EN   (1U << 13)

#define LCD_DATA_MASK (0xFFU << 15)

#define LCD_CONTROL_MASK (LCD_RS | LCD_RW | LCD_EN)
#define LCD_ALL_MASK (LCD_CONTROL_MASK | LCD_DATA_MASK)

void LCD_GPIO_Init(void)
{
    /* Select GPIO function for P0.10, P0.12 and P0.13 */
    PINSEL0 &= ~((3U << 20) |
                 (3U << 24) |
                 (3U << 26));

    /* Select GPIO function for P0.15 */
    PINSEL0 &= ~(3U << 30);

    /* Select GPIO function for P0.16 to P0.22 */
    PINSEL1 &= ~(0x3FFFU);

    /* Configure all LCD pins as outputs */
    IODIR0 |= LCD_ALL_MASK;

    /* Set control lines and data lines LOW */
    IOCLR0 = LCD_ALL_MASK;
}

int main(void)
{
    LCD_GPIO_Init();

    while (1)
    {
        /* LCD initialization and display
           routines will be added in later lessons. */
    }
}

Code Explanation

  • LPC21xx.h provides the LPC2129 register definitions in a compatible Keil device setup.
  • PINSEL0 and PINSEL1 select GPIO functions for the required pins.
  • IODIR0 configures the LCD pins as outputs.
  • IOCLR0 drives the selected output pins LOW.
  • The program prepares the GPIO interface; it does not yet initialize or display characters on the LCD.
Register programming note: IOSET0 and IOCLR0 use write-one-to-set and write-one-to-clear behavior. Write the required mask directly rather than using compound operations such as IOSET0 |= mask;.

9. Basic LCD Communication Sequence

Before displaying characters, the LCD must be initialized. After initialization, the microcontroller can send commands and character data.

Basic Write Operation

  1. Select command or data mode using RS.
  2. Select write mode by setting RW LOW.
  3. Place the command or character byte on the data pins.
  4. Apply the required enable pulse.
  5. Wait for the LCD controller to complete the operation.
RS RW Operation
00Write command
10Write character data
01Read status or instruction register, where supported
11Read data register
The LCD enable pulse and setup/hold times must follow the LCD controller datasheet. Clear-display and return-home commands generally need longer execution time than ordinary instructions.

10. LCD Initialization Overview

An LCD cannot reliably display characters immediately after power is applied. The controller must first be placed into the required operating mode.

A typical HD44780-compatible 8-bit initialization sequence is:

Command Purpose
0x388-bit interface, two display lines, 5x8 character font
0x0CDisplay ON, cursor OFF, blink OFF
0x06Increment address after writing data; no display shift
0x01Clear display and return address to home

This is an overview rather than a complete initialization program. The required power-up wait, command delays and enable timing will be covered in Lesson 04.

The 4-bit initialization procedure is different. Do not send the 8-bit initialization sequence unchanged when the LCD is connected in 4-bit mode.

11. LCD Applications in Embedded Systems

  • Industrial automation: Display machine status and process values.
  • Power electronics: Display voltage, current and protection status.
  • Instrumentation: Display measurement readings.
  • Home automation: Display temperature and operating modes.
  • Security systems: Display password prompts and access messages.
  • Embedded controllers: Display configuration menus and error messages.

13. Common Mistakes to Avoid

  • Connecting LCD data lines in the wrong order.
  • Forgetting to configure LPC2129 pin multiplexing.
  • Incorrectly configuring GPIO direction.
  • Confusing RS command mode with data mode.
  • Leaving RW in an undefined state.
  • Ignoring LCD power-up and instruction timing requirements.
  • Using a 4-bit initialization sequence for an 8-bit connection.
  • Ignoring voltage compatibility between the microcontroller and LCD.
  • Assuming that a successful compile proves the LCD is working.

14. Interview Questions and Answers

Q1. What is an LCD?

An LCD is a display device that uses liquid crystal material to control light and display information.

Q2. What does 16x2 LCD mean?

It means the LCD can display 16 characters per row across two rows.

Q3. What is the function of RS?

RS selects whether the LCD receives an instruction or character data.

Q4. What is the function of RW?

RW selects the read or write operation. LOW selects write and HIGH selects read.

Q5. What is the function of EN?

EN provides the control transition used by the LCD controller to latch a command or data transfer.

Q6. What is the difference between 4-bit and 8-bit mode?

8-bit mode uses eight data lines to transfer a byte in one bus operation. 4-bit mode uses four data lines and transfers a byte in two portions.

Q7. What is DDRAM?

DDRAM is Display Data RAM. It stores character codes corresponding to display positions.

Q8. Why is LCD initialization necessary?

Initialization configures the LCD interface, display mode and operating settings before normal communication.

Q9. Can an LCD operate without RW connected to the microcontroller?

Yes. RW can be tied LOW for write-only operation. Software must then provide the required delays instead of reading the busy flag.

Q10. Why is contrast adjustment required?

The contrast input controls the visibility of characters against the LCD background.

17. Keil uVision Simulator Practice

Use the following procedure to study the GPIO configuration:

  1. Create a new LPC2129 project in Keil uVision.
  2. Add the device startup file and required header file.
  3. Add the GPIO initialization program from Section 8.
  4. Build the project and resolve compiler errors.
  5. Start the debugger and execute the initialization function.
  6. Inspect PINSEL0, PINSEL1 and IODIR0.
  7. Inspect IOCLR0 and the relevant GPIO output states.
Simulator limitation: The GPIO exercise verifies program execution and register configuration. It does not guarantee that a visible LCD will be rendered. Actual LCD communication requires a supported simulator peripheral model or physical hardware and correct electrical connections.
