2. Introduction to Peripheral Integration

An embedded system often contains several peripherals working together. A microcontroller reads inputs, processes information and controls output devices.

Sensors / Keypad / Switches
↓
LPC2129 Microcontroller
↓
LCD / Seven-Segment / Buzzer / Relay

For example, a temperature-monitoring system may read an analog sensor using the ADC, calculate temperature, display the result on an LCD and activate an alarm when a threshold is exceeded.

Peripheral integration requires more than connecting devices. Firmware must also manage pin multiplexing, timing, electrical compatibility, shared resources and error conditions.

Develop a digital counter that displays a changing count on a 16x2 LCD.

Required Components

  • LPC2129 microcontroller.
  • 16x2 HD44780-compatible LCD.
  • Push button.
  • Pull-up or pull-down circuit as required.
  • LCD contrast adjustment circuit.

Program Logic

  1. Initialize GPIO and LCD.
  2. Initialize the counter to zero.
  3. Read the push button.
  4. Detect a new button press.
  5. Increment the counter once per press.
  6. Display the updated count on the LCD.
unsigned int counter = 0U;

while (1)
{
    if (Button_Pressed())
    {
        counter++;

        LCD_Command(0x01);
        LCD_DisplayNumber(counter);

        Wait_For_Button_Release();
    }
}

4. Project 2 – Keypad-Based Password Lock

Objective

Develop a password-entry system using a matrix keypad and LCD. The system compares the entered password with a stored code and displays the access result.

Required Components

  • LPC2129 microcontroller.
  • 4x4 matrix keypad.
  • 16x2 LCD.
  • Buzzer.
  • Relay driver and low-voltage demonstration load (optional).
4x4 Keypad
↓
LPC2129
↙ ↓ ↘
LCD
Buzzer
Relay Driver

Working Principle

  1. Initialize keypad, LCD and output drivers.
  2. Display a password-entry prompt.
  3. Read digits entered through the keypad.
  4. Compare the entered sequence with the stored password.
  5. Display an access-granted or access-denied message.
  6. Activate the buzzer for an invalid attempt.
  7. Optionally activate a relay for an authorized low-voltage demonstration load.

Application Logic

if (Password_Matches())
{
    LCD_DisplayString("Access Granted");

    Buzzer_OFF();
    Relay_ON();
}
else
{
    LCD_DisplayString("Access Denied");

    Relay_OFF();
    Buzzer_ON();
}
This is an educational demonstration, not a secure access-control design. A real system needs protected credential storage, retry limits, lockout policy, secure update handling and safe relay control.

5. Project 3 – Temperature Monitoring System

Objective

Measure temperature using an analog sensor, display the result on an LCD and activate an alarm when the temperature reaches a configured threshold.

Required Components

  • LPC2129 microcontroller.
  • LM35 temperature sensor or compatible analog sensor.
  • 16x2 LCD.
  • Buzzer and driver circuit.
  • Optional relay driver for a low-voltage demonstration load.
LM35 Sensor
↓
AIN0 / ADC
↓
Temperature Calculation
↓
LCD + Alarm Control

Temperature Calculation

Sensor Voltage =
    (ADC Result / 1023.0) * VREF

Temperature =
    Sensor Voltage / 0.010

The example uses the nominal LM35 scale of 10 mV/°C. Use the actual ADC reference voltage and sensor datasheet specifications.

Application Logic

temperature = Read_Temperature();

LCD_DisplayTemperature(temperature);

if (temperature >= 50.0f)
{
    Buzzer_ON();
}
else if (temperature <= 47.0f)
{
    Buzzer_OFF();
}

The separate ON and OFF thresholds implement hysteresis and reduce repeated switching near the alarm threshold.

6. Project 4 – Automatic Street Light Controller

Objective

Develop an automatic lighting controller using an analog light sensor and a relay driver.

Required Components

  • LPC2129 microcontroller.
  • Analog light sensor or LDR voltage-divider circuit.
  • ADC input.
  • Relay driver.
  • Low-voltage demonstration lamp.
LDR Sensor Circuit
↓
LPC2129 ADC
↓
Threshold Decision
↓
Relay Driver
↓
Low-Voltage Lamp

Working Principle

  • Measure the light sensor voltage using the ADC.
  • Convert the ADC reading into a relative light level.
  • Compare the reading against a calibrated threshold.
  • Switch the light driver ON when it becomes dark.
  • Switch the light driver OFF when sufficient light is detected.
light_value = ADC_Read_AIN0();

if (light_value < DARK_THRESHOLD)
{
    Relay_ON();
}
else if (light_value > LIGHT_THRESHOLD)
{
    Relay_OFF();
}
The threshold direction depends on the LDR voltage-divider arrangement. Verify whether the ADC reading increases or decreases as illumination changes.
Use only a properly rated low-voltage demonstration load during development. Mains lighting requires certified isolation, enclosures, protection and qualified electrical installation.

7. Project 5 – Seven-Segment Digital Timer

Objective

Display a numerical count on a seven-segment display using LPC2129 GPIO and a hardware timer.

Required Components

  • LPC2129 microcontroller.
  • Seven-segment display.
  • Current-limiting resistors.
  • Suitable digit-driver circuitry for multi-digit displays.

Working Principle

  1. Configure the display segment pins.
  2. Configure a hardware timer to generate periodic events.
  3. Increment a software counter at the required interval.
  4. Convert the numerical digit into a segment pattern.
  5. Update the display.

8. Project 6 – Digital Sensor Alarm

Objective

Use a digital sensor to detect an event and activate a buzzer and LCD warning message.

Required Components

  • LPC2129 microcontroller.
  • Digital proximity or motion sensor module.
  • 16x2 LCD.
  • Buzzer driver.

Application Logic

sensor_state = Sensor_Read();

if (sensor_state == SENSOR_ACTIVE)
{
    LCD_DisplayString("Object Detected");
    Buzzer_ON();
}
else
{
    LCD_DisplayString("Area Clear");
    Buzzer_OFF();
}

The input polarity must be determined from the selected sensor module. Add filtering or debounce where necessary.

14. Pin Allocation and Peripheral Conflicts

The LPC2129 uses multiplexed pins. A pin may support GPIO or an alternate peripheral function, depending on its PINSEL configuration.

15. Project Development Workflow

  1. Define requirements: specify inputs, outputs and expected system behaviour.
  2. Select peripherals: choose GPIO, ADC, timer, LCD, keypad or communication interfaces.
  3. Prepare pin allocation: identify conflicts and configure multiplexed pins.
  4. Design driver circuits: select suitable interface and protection components.
  5. Develop drivers: implement and test each peripheral separately.
  6. Integrate modules: connect the drivers through application logic.
  7. Test normal operation: check expected input and output sequences.
  8. Test fault conditions: consider sensor failures, invalid inputs and communication errors.
  9. Document the system: record pin mapping, register configuration and test results.

16. Testing and Debugging Checklist

  • Verify the system clock and peripheral clock settings.
  • Verify PINSEL configuration for every used pin.
  • Verify IODIR settings for GPIO inputs and outputs.
  • Check LCD initialization and command timing.
  • Check keypad row and column scanning.
  • Check ADC channel selection and clock divider.
  • Check sensor scaling and reference voltage.
  • Check timer configuration and match conditions.
  • Check buzzer and relay driver logic polarity.
  • Check startup output states and fault handling.
  • Check that no two modules use the same pin incompatibly.

17. Keil uVision Simulator Practice

The following activities can be performed as firmware exercises in the Keil uVision simulator:

  1. Create a project for LPC2129.
  2. Build the GPIO counter program.
  3. Inspect the GPIO direction and output registers.
  4. Build the ADC measurement program.
  5. Inspect ADCR and ADDR during conversion.
  6. Build the timer-based display update logic.
  7. Inspect timer control and match registers.
  8. Build the keypad scanning logic.
  9. Review LCD driver function calls and command values.
  10. Debug the combined application one module at a time.
The Keil simulator may not model all external peripherals or their electrical behaviour. It may not render an LCD, detect a physical keypad press, sound a buzzer, energize a relay or simulate a real sensor signal. Treat register inspection and software execution as firmware-level verification, not proof of physical peripheral operation.

19. Interview Questions and Answers

Q1. What is peripheral interfacing?

Peripheral interfacing connects a microcontroller to external or internal devices so that the system can receive inputs and control outputs.

Q2. Why is an LCD used in embedded systems?

An LCD displays measurement values, system status, menus and warning messages.

Q3. Why is keypad scanning required?

Scanning identifies which row and column are connected by a pressed key.

Q4. What is the purpose of an ADC in a sensor project?

It converts an analog sensor voltage into a digital value that the microcontroller can process.

Q5. Why is a relay driver required?

It switches the relay coil current without overloading the microcontroller GPIO.

Q6. Why should firmware be modular?

Modular firmware improves readability, testing, reuse and maintenance.

Q7. What is a pin-allocation table?

It records the pins assigned to each peripheral and helps identify pin multiplexing conflicts.

Q8. What is hysteresis in a sensor control application?

It uses different ON and OFF thresholds to prevent repeated switching near a threshold.

Q9. What is the advantage of using a hardware timer?

It provides more predictable timing than an arbitrary software delay loop.

Q10. What is the difference between simulation and hardware testing?

Simulation verifies supported firmware and model behaviour. Hardware testing checks the actual electrical and physical system.
