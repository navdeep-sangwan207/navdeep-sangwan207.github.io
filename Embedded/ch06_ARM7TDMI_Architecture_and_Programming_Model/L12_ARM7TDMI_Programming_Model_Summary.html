1. Introduction

The ARM7TDMI programming model describes the registers, processor modes, status registers, instruction states, pipeline organization, exception mechanisms, and memory access behavior available to programmers.

Understanding this model is important when writing ARM assembly language, developing embedded firmware, handling interrupts, and interfacing software with microcontroller hardware.

Learning objective: Integrate the major ARM7TDMI architectural concepts into one programming model suitable for embedded software development.

2. ARM7TDMI Architecture Overview

ARM7TDMI is a 32-bit RISC processor core based on the ARMv4T architecture. It supports both ARM and original Thumb instruction sets.

3. ARM7TDMI Internal Architecture

The ARM7TDMI core contains processing and control components that work together to execute instructions.

ARM7TDMI CORE +----------------------------+ | | | Instruction Decoder | | | | Control Unit | | | | Register Bank | | | | ALU | | | | Barrel Shifter | | | | Multiplier | | | | CPSR / SPSR | | | | Pipeline | | | +----------------------------+ | v Memory Interface

Major components

  • ALU: Performs arithmetic and logical operations.
  • Barrel shifter: Performs shift and rotate operations.
  • Multiplier: Supports multiplication operations.
  • Register bank: Stores operands, addresses, and intermediate results.
  • Instruction decoder: Decodes instructions and controls execution.
  • Pipeline: Overlaps instruction processing stages.

4. ARM7TDMI Register Organization

ARM7TDMI uses 32-bit registers. The programmer normally sees 16 registers at a time, named R0 to R15.

RegisterCommon purpose
R0–R3General-purpose registers and procedure arguments/results
R4–R10General-purpose registers
R11Often used as a frame pointer by software conventions
R12Often used as an intra-procedure scratch register
R13Stack Pointer (SP)
R14Link Register (LR)
R15Program Counter (PC)
The use of R11 and R12 described above is a common software convention, not a mandatory hardware assignment.

5. Banked Register Organization

ARM7TDMI provides banked registers to support efficient exception handling and independent execution contexts.

Register groupBanking behavior
R0–R7Shared across all modes
R8–R12FIQ has a separate bank; other modes share the common bank
R13–R14Banked in exception modes; User and System share
R15Shared PC
SPSRSeparate SPSR for each exception mode

Number of physical registers

ARM7TDMI has 37 physical 32-bit registers in its programmer's model: 31 general-purpose registers and six status registers.

  • 31 general-purpose registers, including banked copies and PC.
  • One CPSR.
  • Five SPSRs.
Register banking changes which physical register is visible in a processor mode. It does not automatically preserve every register modified by an exception handler.

6. Processor Modes

ARM7TDMI supports seven processor modes.

ModePurpose
UserNormal application execution
FIQFast interrupt handling
IRQNormal interrupt handling
SupervisorPrivileged system operations and SWI handling
AbortMemory access exception handling
UndefinedUndefined instruction handling
SystemPrivileged operating mode using User register bank
User mode is unprivileged. System mode is privileged but shares the User mode general-purpose register bank.

7. CPSR – Current Program Status Register

CPSR stores the current processor status and control information.

FieldFunction
NNegative flag
ZZero flag
CCarry flag
VOverflow flag
IIRQ mask bit
FFIQ mask bit
TARM/Thumb state bit
M[4:0]Processor mode bits

Condition flags

  • N: Indicates a negative result in signed interpretation.
  • Z: Indicates a zero result.
  • C: Indicates carry or no-borrow according to the operation.
  • V: Indicates signed arithmetic overflow.

8. SPSR – Saved Program Status Register

SPSR stores the previous CPSR when the processor enters an exception mode.

Each exception mode has its own SPSR:

  • SPSR_fiq
  • SPSR_irq
  • SPSR_svc
  • SPSR_abt
  • SPSR_und

User and System modes do not have SPSRs.

Restoring the saved status register is essential for returning to the previous processor mode and ARM/Thumb execution state.

9. ARM and Thumb Execution States

FeatureARM stateThumb state
Instruction width32 bits16 bits in original Thumb
Instruction encodingFull ARM instruction setCompact Thumb instruction set
Code densityGenerally lowerGenerally higher
Register accessFlexible access to registersMany instructions use R0–R7
Conditional executionBroad condition-code supportMore limited conditional forms

State selection

The CPSR T bit identifies the current execution state:

  • T = 0: ARM state.
  • T = 1: Thumb state.

BX instruction

        BX      R0

BX branches to the address in R0 and selects the execution state using bit 0 of the target address. Bit 0 equal to zero selects ARM state; bit 0 equal to one selects Thumb state.

ARM7TDMI implements the original Thumb instruction set. It does not implement Thumb-2.

10. ARM7TDMI Three-Stage Pipeline

ARM7TDMI uses a three-stage pipeline to overlap instruction processing.

+-------------+ +-------------+ +-------------+ | FETCH | -> | DECODE | -> | EXECUTE | +-------------+ +-------------+ +-------------+ | | | Fetch instruction Decode instruction Execute instruction from memory and read operands and write result
StageOperation
FetchFetches instruction from memory
DecodeDecodes instruction and reads operands
ExecutePerforms operation and writes result

The pipeline improves instruction throughput by overlapping different stages of instruction execution.

Branches and exceptions can change the program flow and cause pipeline refill operations.

12. Load-Store Architecture and Memory Interface

ARM7TDMI uses explicit load and store operations to access memory. 

        LDR     R0, [R1]       ; Load word from memory
        ADD     R2, R0, #5     ; Process data
        STR     R2, [R1]       ; Store result

Supported transfer sizes

  • Byte: 8 bits.
  • Halfword: 16 bits.
  • Word: 32 bits.

Important memory concepts

  • 32-bit address space.
  • Byte-addressable memory.
  • Memory alignment.
  • Little-endian and big-endian byte ordering.
  • Memory-mapped peripheral registers.

15. ARM7TDMI in LPC2129 Microcontrollers

The LPC2129 microcontroller uses an ARM7TDMI-S processor core and integrates memory and peripheral modules around it.

LPC2129 +---------------------------+ | | | ARM7TDMI-S | | CORE | | | | | +-------+-------+ | | | | | | FLASH SRAM | | | | SYSTEM BUS | | | | | +---------+----------+ | | | | | | | GPIO UART TIMER| | | | | | | ADC I2C PWM | | | | INTERRUPT VIC | +---------------------------+

Important LPC2129 development concepts

  • Configure the processor clock and peripheral clock.
  • Configure pin functions using PINSEL registers.
  • Configure GPIO direction and data registers.
  • Use timer and interrupt modules for event handling.
  • Configure UART for serial communication and debugging.
  • Use ADC for analog input conversion.
  • Use I2C, SPI, and CAN for communication.
ARM7TDMI defines the processor architecture. LPC2129 documentation defines the actual memory map, pin assignments, peripheral registers, and VIC configuration.

16. Integrated Assembly Example

The following example demonstrates basic register operations, arithmetic, and a memory store. 

        AREA    ARM7_SUMMARY, CODE, READONLY
        ENTRY

        LDR     R1, =0x40000000

        MOV     R0, #10
        MOV     R2, #20

        ADD     R3, R0, R2

        STR     R3, [R1]

STOP
        B       STOP

        END

Explanation

  1. R1 receives an illustrative memory address.
  2. R0 is loaded with decimal 10.
  3. R2 is loaded with decimal 20.
  4. ADD calculates 10 + 20 and stores 30 in R3.
  5. STR requests a word write of R3 to the address in R1.
  6. The program enters an infinite loop.

Expected register values:

RegisterExpected value
R00x0000000A
R10x40000000
R20x00000014
R30x0000001E
The address 0x40000000 is illustrative. For Keil uVision simulation, use a configured writable memory region and inspect the register and memory windows. This example does not demonstrate a physical LPC2129 memory write.

17. Keil uVision Simulator Practice

You can use Keil uVision to examine ARM7TDMI instructions and processor state without a physical LPC2129 board.

Suggested procedure

  1. Create or open an ARM7TDMI-compatible assembly project.
  2. Add the assembly source file.
  3. Select the appropriate target processor.
  4. Build the project.
  5. Start the simulator debugging session.
  6. Open the register window.
  7. Execute the program using Step or Run.
  8. Inspect R0–R15 and CPSR.
  9. Use the memory window to inspect a valid configured memory region.

Suggested observations

  • Observe changes in general-purpose registers.
  • Observe the Program Counter during instruction execution.
  • Examine condition flags after arithmetic operations that update flags.
  • Observe memory after a successful store to a valid memory region.
  • Study ARM and Thumb execution state where supported by the project configuration.
The simulator can show processor registers and memory operations. It does not reproduce every external peripheral or electrical behavior of a physical LPC2129 board.

18. Common Mistakes

  1. Confusing physical register count with the number of visible registers.
  2. Assuming User and System modes have separate register banks.
  3. Assuming every exception mode has the same banked registers.
  4. Confusing CPSR with SPSR.
  5. Assuming ARM7TDMI supports Thumb-2.
  6. Confusing instruction fetch with data memory access.
  7. Assuming every interrupt is handled by the same processor mode.
  8. Confusing the ARM exception vector table with the LPC2129 VIC.
  9. Assuming the theoretical address space equals physical memory capacity.
  10. Ignoring processor state and memory configuration when debugging.

19. Interview Questions and Answers

Q1. What is ARM7TDMI?

ARM7TDMI is a 32-bit RISC processor core implementing ARMv4T with ARM and original Thumb instruction states.

Q2. How many registers are in the ARM7TDMI programmer's model?

It has 37 physical 32-bit registers: 31 general-purpose registers and six status registers.

Q3. What are R13, R14, and R15?

R13 is SP, R14 is LR, and R15 is PC.

Q4. How many processor modes are available?

Seven modes: User, FIQ, IRQ, Supervisor, Abort, Undefined, and System.

Q5. What is the purpose of CPSR?

CPSR stores processor condition flags, interrupt masks, execution state, and processor mode.

Q6. What is the purpose of SPSR?

SPSR saves the previous CPSR when entering an exception mode.

Q7. What is the difference between ARM and Thumb state?

ARM state uses 32-bit instructions, while original Thumb state uses 16-bit instructions.

Q8. What is the ARM7TDMI pipeline?

It is a three-stage pipeline consisting of Fetch, Decode, and Execute.

Q9. What is the difference between IRQ and FIQ?

FIQ has higher priority and more banked registers than IRQ.

Q10. What is the role of the LPC2129 VIC?

It manages and routes peripheral interrupt requests to the ARM processor.

Q11. What is the load-store architecture?

It uses explicit load and store instructions to transfer data between registers and memory.

Q12. Why is ARM7TDMI important in embedded systems?

It provides a processor architecture for executing firmware, controlling peripherals, handling interrupts, and managing embedded application tasks.
