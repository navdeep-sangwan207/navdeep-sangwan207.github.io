1. Introduction

Pipelining is a processor design technique in which instruction processing is divided into multiple stages. Different instructions can occupy different stages simultaneously.

The ARM7TDMI processor uses a three-stage instruction pipeline:

  • Fetch
  • Decode
  • Execute

While one instruction is being executed, the next instruction can be decoded and another instruction can be fetched.

Core concept: Pipelining improves instruction throughput by overlapping instruction-processing stages.

2. What Is Instruction Pipelining?

In a non-pipelined processor, an instruction may complete all its processing stages before the next instruction begins. This can leave parts of the processor unused during portions of instruction execution.

A pipelined processor overlaps the stages of several instructions. This allows hardware resources to perform useful work on different instructions at the same time.

Non-pipelined execution

Instruction 1: FETCH → DECODE → EXECUTE Instruction 2: FETCH → DECODE → EXECUTE Instruction 3: FETCH → DECODE → EXECUTE

Pipelined execution

Clock Cycle 1 2 3 4 5 ---------------------------------------------------------- Instruction 1 FETCH DECODE EXECUTE Instruction 2 FETCH DECODE EXECUTE Instruction 3 FETCH DECODE EXECUTE

The second arrangement overlaps the work of multiple instructions.

3. Three Stages of ARM7TDMI Pipeline

Stage 1: Fetch

The processor fetches an instruction from memory using the program counter (PC). The fetched instruction is placed in the instruction pipeline for subsequent processing.

  • Uses the instruction address from the PC.
  • Reads the instruction from memory.
  • Advances the instruction-fetch sequence.

Stage 2: Decode

The processor decodes the fetched instruction to determine the operation to perform and the required operands.

  • Identifies the instruction type.
  • Determines source and destination registers.
  • Interprets addressing and control information.

Stage 3: Execute

The processor performs the operation specified by the instruction.

  • Performs arithmetic or logical operations.
  • Calculates addresses for memory operations.
  • Performs load or store operations.
  • Updates destination registers and applicable status flags.

5. Pipeline Throughput and Latency

Instruction latency

Latency is the time required for an individual instruction to pass through the processing stages and complete.

Instruction throughput

Throughput describes how frequently instructions complete after the pipeline becomes filled.

In an ideal three-stage pipeline, one instruction can complete per clock cycle after the pipeline is filled, assuming no stalls or other delays.

Pipeline depth is not the same as the number of clock cycles required by every instruction. Memory operations and pipeline disruptions can affect actual execution time.

6. Pipeline Fill and Drain

Pipeline filling

At the beginning of execution, the pipeline stages are not all occupied. Instructions enter the pipeline one after another until all stages are active.

Pipeline draining

When instruction fetching stops, the instructions already present in the pipeline must complete their processing. This is called pipeline draining.

Pipeline Fill: Cycle 1: [FETCH] [ ] [ ] Cycle 2: [FETCH] [DECODE] [ ] Cycle 3: [FETCH] [DECODE] [EXECUTE] Pipeline Full: Cycle N: [FETCH] [DECODE] [EXECUTE] Pipeline Drain: Fetching stops; remaining instructions complete execution.

7. Program Counter and Pipeline Behavior

The program counter (R15) identifies instruction addresses. Because the ARM7TDMI fetches instructions ahead of their execution, the PC value visible to an instruction is affected by pipeline operation.

In ARM state, the PC is commonly observed as the address of the current instruction plus 8 bytes. In Thumb state, it is commonly observed as the current instruction address plus 4 bytes.

These are architectural PC-reading conventions. Exact behavior in address calculations and particular instructions must be interpreted according to the ARM7TDMI instruction specification.

8. Branch Instructions and Pipeline Flushing

A branch changes the normal sequential flow of program execution. Instructions already fetched from the old sequential path may no longer be valid.

The processor must redirect instruction fetching to the branch target. The pipeline is refilled with instructions from the new address.

Example

        MOV     R0, #1
        B       TARGET
        MOV     R1, #2      ; Sequential-path instruction
                            ; may be discarded

TARGET
        MOV     R2, #3
Before branch: Sequential instructions enter the pipeline. | v +----------+ | BRANCH | +----------+ | v Redirect instruction fetch | v Refill pipeline at target

Discarding instructions from the old path is commonly described as a pipeline flush.

A branch can introduce a performance penalty because the processor must redirect and refill the pipeline. The exact penalty depends on the instruction and memory system.

9. Pipeline Behavior During Load and Store Operations

Load and store instructions access memory in addition to using the processor's execution resources.

Load example

        LDR     R0, [R1]

The processor calculates the effective address and obtains the requested data from memory.

Store example

        STR     R0, [R1]

The processor calculates the effective address and writes the register value to memory.

Memory wait states and bus availability can affect how quickly these instructions complete. Therefore, ideal pipeline timing does not always represent real execution timing.

10. Pipeline Hazards and Performance Limitations

A pipeline hazard is a condition that prevents an instruction from proceeding through the pipeline as expected.

Important categories

HazardMeaningExample or cause
Structural hazard Hardware resource conflict Competing requests for a shared resource
Data dependency An instruction requires a result from another instruction ADD followed by an instruction using its result
Control-flow disruption Instruction flow changes unexpectedly Branch or exception

These categories are useful general pipeline concepts. Their specific handling depends on the processor implementation.

Data dependency example

        ADD     R0, R1, R2
        SUB     R3, R0, R4

The second instruction requires the value produced by the first. The processor must ensure that the correct value is available before the dependent operation uses it.

11. Advantages of Pipelining

  • Improves instruction throughput.
  • Overlaps instruction processing stages.
  • Allows more effective use of processor resources.
  • Supports efficient execution of sequential instruction streams.
  • Improves overall processor performance compared with a suitable non-pipelined design.

12. Limitations of Pipelining

  • Branch instructions can disrupt sequential fetching.
  • Data dependencies can delay instruction execution.
  • Memory wait states can reduce throughput.
  • Pipeline control adds hardware complexity.
  • Pipeline filling and draining introduce overhead.
  • Not all instructions complete with identical timing.

13. ARM7TDMI Pipeline and ARM/Thumb States

ARM7TDMI uses a three-stage pipeline in both ARM and Thumb execution states. The instruction encoding differs between the states, but the basic fetch, decode, and execute pipeline organization remains the same.

14. Practical Study Using Keil uVision

You can examine instruction sequencing and pipeline-related behavior using the Keil uVision simulator configured for ARM7TDMI.

Suggested procedure

  1. Create or open an ARM7TDMI target project.
  2. Write a short sequence of arithmetic instructions.
  3. Build the program and open the disassembly window.
  4. Start debugging and use single-step execution.
  5. Observe the PC and instruction sequence.
  6. Add a branch instruction and inspect the target address.
  7. Compare sequential execution with branch execution.
  8. Repeat using a Thumb instruction sequence if the project settings support it.
Simulator limitation: Single-stepping demonstrates instruction flow and register changes. It does not necessarily expose every internal pipeline stage cycle by cycle. Do not infer exact hardware cycle timing from the debugger's step behavior alone.

15. Common Mistakes

  1. Assuming ARM7TDMI uses a five-stage pipeline.
  2. Confusing instruction latency with instruction throughput.
  3. Assuming all instructions complete in one clock cycle.
  4. Ignoring the effect of branches on instruction fetching.
  5. Assuming pipeline overlap eliminates all data dependencies.
  6. Confusing the visible PC value with the address of the currently executing instruction.
  7. Assuming a debugger single-step directly shows internal pipeline timing.

16. Interview Questions and Answers

Q1. What is pipelining?

Pipelining is a technique that overlaps different stages of multiple instructions to improve instruction throughput.

Q2. How many pipeline stages does ARM7TDMI have?

ARM7TDMI has three stages: Fetch, Decode, and Execute.

Q3. What happens during the fetch stage?

The processor obtains an instruction from memory.

Q4. What happens during the decode stage?

The processor interprets the instruction and identifies its operation and operands.

Q5. What happens during the execute stage?

The processor performs the operation specified by the instruction.

Q6. What is pipeline throughput?

It is the rate at which instructions complete. Ideally, a filled three-stage pipeline can complete one instruction per clock cycle under suitable conditions.

Q7. What is pipeline flushing?

Pipeline flushing discards instructions that are no longer valid, such as instructions fetched from the sequential path after a branch.

Q8. Why do branch instructions affect performance?

They redirect instruction fetching and may require the pipeline to be refilled.

Q9. What is a data dependency?

It occurs when an instruction needs a value produced by an earlier instruction.

Q10. Does pipelining guarantee that every instruction takes one cycle?

No. Memory access, dependencies, branches, and other conditions can affect execution time.

  • ARM7TDMI uses a three-stage instruction pipeline.
