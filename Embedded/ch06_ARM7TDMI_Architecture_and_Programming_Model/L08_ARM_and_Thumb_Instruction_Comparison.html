1. Introduction

ARM7TDMI supports two instruction-set states: ARM state and Thumb state. Both states execute on the same processor core and use the same underlying register architecture, but their instruction encodings and programming capabilities differ.

ARM instructions are 32 bits wide, whereas original Thumb instructions are 16 bits wide. ARM provides a more flexible instruction format, while Thumb focuses on compact code representation.

Core concept: ARM and Thumb are alternative instruction-set states, not two separate processors.

3. Instruction Encoding Comparison

An instruction encoding specifies how the processor interprets the bits representing an operation, its operands, and other control information.

ARM instruction format

ARM instructions use a 32-bit encoding. Depending on the instruction type, fields can represent the condition code, opcode, destination register, source registers, and operand information.

ARM INSTRUCTION
+--------------------------------------------------+
| Condition | Opcode | Registers | Operand Fields |
+--------------------------------------------------+

Total width = 32 bits

Thumb instruction format

Original Thumb instructions use 16-bit encodings. Their compact format limits the number of bits available for register selection, immediate values, and operation fields.

THUMB INSTRUCTION
+--------------------------------+
| Opcode | Register | Operand |
+--------------------------------+

Total width = 16 bits
These diagrams are conceptual. Actual ARM and Thumb instruction formats differ according to instruction category.

4. Register Access Comparison

ARM state allows instructions to access the general-purpose registers R0–R15 using the register fields supported by each instruction format.

Original Thumb instructions commonly use R0–R7 because their compact encoding provides fewer bits for register selection. Certain Thumb instructions also support high registers.

Register groupARM stateThumb state
R0–R7SupportedSupported by many instructions
R8–R12SupportedSupported by selected instructions
R13 (SP)SupportedSupported by stack-related and selected instructions
R14 (LR)SupportedSupported by selected instructions
R15 (PC)SupportedSupported with Thumb-specific restrictions
Both states use the same physical register architecture. Instruction encoding determines which registers can be used by a particular instruction.

5. Data Processing Instructions

Both ARM and Thumb support common data-processing operations such as addition, subtraction, logical AND, OR, and exclusive OR. Their syntax and operand restrictions can differ.

ARM example

        MOV     R0, #10
        MOV     R1, #5
        ADD     R2, R0, R1
        SUB     R3, R0, R1

Thumb example

        MOV     R0, #10
        MOV     R1, #5
        ADD     R2, R0, R1
        SUB     R3, R0, R1

These examples illustrate equivalent operations using low registers. The assembler must encode the instructions according to the selected instruction-set state.

6. Conditional Execution Comparison

Conditional execution allows an instruction to execute only when a specified condition is satisfied.

ARM conditional execution

        CMP     R0, R1
        MOVEQ   R2, #1
        MOVNE   R2, #0

MOVEQ executes when the Zero flag is set. MOVNE executes when the Zero flag is clear.

Thumb conditional branching

        CMP     R0, R1
        BEQ     EQUAL

        MOV     R2, #0
        B       DONE

EQUAL
        MOV     R2, #1

DONE
        B       DONE

Original Thumb uses conditional branch instructions for many conditional control-flow operations instead of supporting the same general conditional-execution mechanism as ARM state.

7. Load and Store Instructions

Both instruction sets support memory access through load and store operations.

ARM example

        LDR     R0, [R1]
        STR     R0, [R2]

Thumb example

        LDR     R0, [R1]
        STR     R0, [R2]

The instruction forms shown use basic register-indirect addressing. ARM and Thumb differ in the addressing modes and register combinations available in their respective encodings.

8. Branch Instructions and State Exchange

Branch instructions modify the program counter to change program execution flow.

ARM branch

        B       LOOP
        BL      FUNCTION

Thumb branch

        B       LOOP
        BL      FUNCTION

ARM7TDMI also supports the BX instruction, which branches to an address and selects ARM or Thumb state using bit 0 of the target address. 

        LDR     R0, =THUMB_FUNCTION + 1
        BX      R0

A target address with bit 0 clear selects ARM state; a target address with bit 0 set selects Thumb state.

BX is important for interworking between ARM and Thumb code. The low-order state indicator is not part of the aligned instruction address.

9. Code Density and Memory Utilization

Code density describes how much program functionality can be stored in a given amount of memory.

Instruction sequenceStorage size
One ARM instruction4 bytes
One Thumb instruction2 bytes
Four ARM instructions16 bytes
Four Thumb instructions8 bytes

Advantages of higher code density

  • Less memory required for many instruction sequences.
  • Potentially lower firmware storage cost.
  • More efficient use of limited program memory.
  • Potential reduction in instruction-fetch traffic.
A 50% reduction in instruction width does not guarantee a 50% reduction in total program size. Different instruction sequences, literal pools, alignment, and compiler decisions affect the final binary size.

10. Performance Considerations

Instruction width alone does not determine processor performance. Execution time depends on instruction count, instruction cycles, memory access, pipeline behavior, and the memory system.

FactorARM stateThumb state
Code sizeOften largerOften smaller
Instruction flexibilityGreaterMore restricted
Memory trafficMay be higher for instruction fetchesMay be lower due to compact encoding
Execution speedDepends on code and systemDepends on code and system

Thumb can be beneficial when memory bandwidth or program storage is constrained. ARM state can be useful when its richer instruction forms reduce the number of instructions needed.

11. ARM/Thumb Interworking

Interworking means allowing ARM-state and Thumb-state code to call or branch to one another within the same application.

Important mechanisms

  • BX instruction for state-aware branching.
  • BLX is not part of the original ARM7TDMI ARMv4T instruction set.
  • Compiler and linker support can generate appropriate interworking sequences.
  • Function entry points must be represented with the correct state information.
  • Exception return can restore the previous state using the saved CPSR.
ARM7TDMI supports BX for interworking. Do not assume newer instructions such as BLX are available on this ARMv4T processor.

13. Practical Comparison in Keil uVision

Keil uVision can be used to build and inspect ARM and Thumb instruction sequences for an ARM7TDMI target.

Suggested procedure

  1. Create an ARM7TDMI target project.
  2. Write a short arithmetic routine in ARM state.
  3. Build the program and inspect its disassembly.
  4. Prepare an equivalent Thumb routine.
  5. Build the Thumb version using the supported assembler or compiler settings.
  6. Compare instruction encodings and program memory usage.
  7. Inspect the CPSR T bit during execution.
  8. Test a state transition using BX where supported.
Simulator note: Use the disassembly and memory windows to compare generated code. Results depend on compiler version, optimization settings, and assembler directives. Do not treat a simulated instruction sequence as proof of physical hardware performance.

14. Common Mistakes

  1. Assuming ARM and Thumb are separate processor cores.
  2. Assuming every ARM instruction has an identical Thumb encoding.
  3. Assuming Thumb always executes faster.
  4. Assuming all Thumb instructions can use every general-purpose register.
  5. Confusing instruction width with data width.
  6. Assuming BLX is available on ARM7TDMI.
  7. Ignoring state information when calling a function in another instruction set.
  8. Assuming code size is always reduced by exactly 50%.

15. Interview Questions and Answers

Q1. What is the main difference between ARM and Thumb?

ARM uses 32-bit instructions, while original Thumb uses 16-bit instructions.

Q2. Which state provides better code density?

Thumb generally provides better code density.

Q3. Does Thumb use a separate register bank?

No. Both states use the same underlying processor registers.

Q4. What is the purpose of the CPSR T bit?

It identifies whether the processor is executing in ARM or Thumb state.

Q5. Which instruction supports state exchange?

BX (Branch and Exchange).

Q6. What is ARM/Thumb interworking?

It is the ability to transfer execution between ARM-state and Thumb-state code.

Q7. Why does Thumb have register restrictions?

Its compact instruction encoding has fewer bits available for operand fields.

Q8. Does a 16-bit instruction mean the processor has a 16-bit data bus?

No. Instruction encoding width and data-bus width are separate architectural properties.

Q9. Is BLX supported by ARM7TDMI?

No. BLX is not part of the original ARMv4T instruction set implemented by ARM7TDMI.

Q10. Which state should be selected for an embedded application?

The choice depends on code size, performance, instruction requirements, and toolchain support.

18. Lesson Summary

  • ARM7TDMI supports ARM and original Thumb instruction-set states.
  • ARM instructions are 32 bits wide; Thumb instructions are 16 bits wide.
  • Thumb generally improves code density.
  • ARM provides more flexible instruction encoding and conditional execution.
  • Both states use the same underlying processor registers.
  • Thumb instruction forms often have more restricted register access.
  • BX supports ARM/Thumb state exchange.
  • ARM7TDMI implements ARMv4T and does not support BLX.
  • Performance depends on the program and memory system, not instruction width alone.
