1. Introduction

An exception is an event that causes the ARM processor to suspend its normal program flow and execute a special routine called an exception handler.

Exceptions are used to handle events such as interrupts, software-generated requests, invalid instructions, memory access faults, and processor reset.

ARM7TDMI provides dedicated exception handling mechanisms using processor modes, exception vectors, banked registers, and status registers.

Core concept: Exception handling transfers processor execution to a predefined handler while preserving sufficient information to resume the interrupted program.

2. What Is an Exception?

An exception changes the normal instruction execution sequence. When an exception occurs, the processor performs operations such as:

  • Identifying the exception source.
  • Saving the return address in the appropriate link register.
  • Saving the previous CPSR in the exception mode's SPSR.
  • Switching to the appropriate processor mode.
  • Changing the processor state as required.
  • Branching to the corresponding exception vector.

5. Reset Exception

Reset is generated when the processor is reset. It starts execution from the reset vector.

During reset:

  • The processor enters Supervisor mode.
  • ARM state is selected.
  • IRQ and FIQ are disabled through the CPSR interrupt mask bits.
  • Execution begins at the reset vector address.

Startup code then performs system initialization, establishes stack pointers, initializes memory as required, and transfers control to the application.

6. Undefined Instruction Exception

An Undefined Instruction exception occurs when the processor encounters an instruction that it cannot execute as a valid instruction in the current architecture and execution context.

Common situations include:

  • Executing an unsupported instruction.
  • Executing an invalid instruction encoding.
  • Using an instruction not implemented by the selected processor architecture.

The processor enters Undefined mode and transfers execution to the undefined instruction handler.

7. Software Interrupt (SWI)

A Software Interrupt instruction generates a synchronous exception intentionally requested by software.

It is commonly used to request operating-system or privileged services from software executing in a less privileged mode.

Example

        SWI     0x05

When SWI is executed, the processor enters Supervisor mode and branches to the SWI exception vector.

ARM7TDMI documentation uses the SWI instruction name. Later ARM architecture documentation commonly uses SVC terminology for the corresponding software-generated exception.

8. Prefetch Abort

A Prefetch Abort occurs when the processor encounters an instruction fetch that causes an instruction-side memory access fault.

The exception is associated with fetching an instruction from an invalid or inaccessible address, depending on the memory system.

The processor enters Abort mode and transfers control to the Prefetch Abort vector.

9. Data Abort

A Data Abort occurs when a data memory access generates an abort response from the memory system.

Examples include:

  • An invalid data access.
  • A memory access that is not permitted by the memory system.
  • A data transfer that receives an abort response.

The processor enters Abort mode and branches to the Data Abort vector.

Prefetch Abort relates to instruction fetching; Data Abort relates to data memory access.

10. IRQ – Normal Interrupt Request

IRQ stands for Interrupt Request. It is used for normal-priority interrupt handling.

An IRQ can be generated by a peripheral or an external interrupt source through the processor's interrupt interface.

  • Enters IRQ mode.
  • Saves the previous CPSR in SPSR_irq.
  • Saves the exception return address in LR_irq.
  • Sets the IRQ mask bit in the CPSR.
  • Transfers execution to vector address 0x00000018.

11. FIQ – Fast Interrupt Request

FIQ stands for Fast Interrupt Request. It is designed for low-latency interrupt handling.

FIQ provides:

  • A separate FIQ processor mode.
  • Banked registers R8_fiq through R14_fiq.
  • A dedicated SPSR_fiq.
  • A higher-priority exception vector than IRQ.

The additional banked registers reduce the need to save and restore shared registers in some FIQ handlers.

FIQ is designed for fast handling, but actual latency depends on the complete processor and interrupt system.

13. CPSR and SPSR During Exception Handling

The Current Program Status Register (CPSR) stores the current processor state, including condition flags, interrupt masks, execution state, and processor mode.

Each exception mode has its own Saved Program Status Register (SPSR), which stores the CPSR value from before the exception.

Important CPSR fields

FieldFunction
NNegative condition flag
ZZero condition flag
CCarry condition flag
VOverflow condition flag
IIRQ disable mask
FFIQ disable mask
TARM/Thumb execution state
M[4:0]Processor mode bits
SPSRs are available in exception modes, not in User or System mode. Each exception mode has its own SPSR.

14. Banked Registers and Exception Handling

Banked registers are alternate physical registers that become visible when the processor enters particular modes.

RegisterBanking
R0–R7Shared across all modes
R8–R12FIQ has a separate bank; other modes share the common bank
R13 (SP)Separate stack pointer for each exception mode; User and System share
R14 (LR)Separate link register for each exception mode; User and System share
R15 (PC)Shared across modes
SPSROne for each exception mode

Why are banked registers useful?

  • Exception handlers have dedicated stack pointers.
  • Return addresses can be stored in mode-specific link registers.
  • FIQ can use extra banked registers to reduce context-saving overhead.
  • Some register preservation work is simplified.
Register banking does not automatically save every register. An exception handler must still preserve shared registers that it modifies and that must remain unchanged for the interrupted code.

15. Exception Entry Sequence

When an exception is accepted, the processor performs a sequence of architectural operations.

Normal Program Execution | v Exception Occurs | v Save old CPSR in mode SPSR | v Save return address in mode LR | v Change processor mode | v Update interrupt mask/state | v Load exception vector address | v Execute Exception Handler

The exact return-address adjustment depends on the exception type and instruction pipeline behavior.

16. Exception Return

After handling an exception, the processor must restore the previous execution context and resume the interrupted program when appropriate.

Exception return generally requires:

  • Restoring the saved CPSR from the current exception mode's SPSR.
  • Restoring the correct return address.
  • Returning to the previous processor mode.
  • Restoring the previous ARM or Thumb execution state.

Example: exception return using data processing

        SUBS    PC, LR, #4

In an appropriate exception handler, this form writes the adjusted return address to PC and restores CPSR from SPSR because the instruction has the S bit set and writes to PC.

The adjustment value is exception-dependent. Do not use the same return instruction or offset blindly for every exception. IRQ/FIQ and abort handlers have different return-address requirements.

18. Interrupt Masking

ARM7TDMI uses two CPSR control bits to mask interrupt requests:

  • I bit: When set, IRQ is disabled.
  • F bit: When set, FIQ is disabled.

These bits allow software to control whether IRQ and FIQ exceptions can be accepted.

IRQ and FIQ are separate exception inputs. Disabling IRQ does not automatically disable FIQ, and disabling FIQ does not automatically disable IRQ.

19. ARM7 Exception Handling vs LPC2129 Interrupt Handling

ARM7TDMI defines the processor-level exception mechanism. A microcontroller such as the LPC2129 adds a peripheral interrupt controller that manages interrupt sources.

ARM7TDMI architectureLPC2129 implementation
Defines IRQ and FIQ exceptionsProvides peripheral interrupt sources
Defines exception vector addressesUses the Vectored Interrupt Controller (VIC)
Defines processor modesUses processor modes during interrupt handling
Defines CPSR interrupt masksProvides interrupt source and VIC control registers
Defines exception entry and return behaviorProvides device-specific interrupt routing and vector configuration
This chapter explains ARM7TDMI processor architecture. LPC2129-specific VIC registers, interrupt slots, and peripheral interrupt programming are covered in Chapter 12.

20. Common Mistakes

  1. Confusing exceptions with only hardware interrupts.
  2. Assuming IRQ and FIQ are identical.
  3. Forgetting that each exception mode has its own SPSR.
  4. Assuming User and System modes have SPSRs.
  5. Assuming banked registers automatically save the entire context.
  6. Confusing Prefetch Abort with Data Abort.
  7. Using an incorrect return-address adjustment.
  8. Confusing ARM exception vectors with LPC2129 VIC vector slots.

21. Interview Questions and Answers

Q1. What is an exception in ARM7TDMI?

An event that causes the processor to suspend normal execution and transfer control to a dedicated handler.

Q2. How many exception types does ARM7TDMI define?

Seven defined exception types.

Q3. What is an exception vector?

A predefined address containing the instruction or branch used to start an exception handler.

Q4. What is the difference between IRQ and FIQ?

IRQ handles normal-priority interrupts, while FIQ provides a higher-priority exception with additional banked registers.

Q5. What is the purpose of SPSR?

It saves the CPSR value from before entry into an exception mode.

Q6. Why does FIQ have more banked registers?

Additional banked registers can reduce the need to save and restore shared registers, helping reduce interrupt-handler overhead.

Q7. What is the difference between Prefetch Abort and Data Abort?

Prefetch Abort is associated with instruction fetching; Data Abort is associated with data memory access.

Q8. What is the role of the CPSR I bit?

It masks IRQ exceptions when set.

Q9. What is the role of the CPSR F bit?

It masks FIQ exceptions when set.

Q10. What is the difference between ARM exception handling and VIC?

ARM defines processor-level exception behavior; the LPC2129 VIC manages the microcontroller's peripheral interrupt sources.

24. Lesson Summary

  • ARM7TDMI supports seven defined exception types.
  • Exception vectors provide predefined handler entry locations.
  • Exception entry saves the previous CPSR in the appropriate SPSR.
  • Mode-specific link registers hold exception return information.
  • IRQ handles normal interrupts; FIQ supports higher-priority handling.
  • FIQ has additional banked registers.
  • CPSR I and F bits control IRQ and FIQ masking.
  • Exception return restores the previous processor state.
  • LPC2129 uses a VIC to manage peripheral interrupt sources.
