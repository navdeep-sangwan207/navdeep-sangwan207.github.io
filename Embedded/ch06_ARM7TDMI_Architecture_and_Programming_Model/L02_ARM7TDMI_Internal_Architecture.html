Lesson 02: ARM7TDMI Internal Architecture

Study the internal functional units, datapath, register bank, ALU, barrel shifter, multiplier, instruction pipeline and memory interface of the ARM7TDMI processor.

1. Introduction

The internal architecture of ARM7TDMI describes how the processor's functional units are organized and how they cooperate to execute instructions.

The processor contains a register bank, arithmetic logic unit (ALU), barrel shifter, multiplier, instruction decoder, control logic, pipeline and memory interface.

These components work together to fetch instructions, decode their operations, process operands and write results to registers or memory.

Learning objective: Understand the role of each major internal unit and how data moves through the ARM7TDMI processor.

3. Register Bank

The register bank is a collection of high-speed storage locations inside the processor. It holds operands, addresses, return information and intermediate results.

ARM7TDMI has 16 registers visible at a time in a particular processor mode, named R0 to R15.

Register Common Name Purpose
R0–R12 General-purpose registers Store data, operands and intermediate results.
R13 SP Stack Pointer.
R14 LR Link Register; commonly stores a return address.
R15 PC Program Counter.

Register Banking

Some ARM7TDMI registers have banked copies. When the processor changes operating mode, a different physical register may become visible under the same register name.

  • R0–R7 are shared across all modes.
  • R8–R12 have banked copies for FIQ mode.
  • R13 and R14 have banked copies for exception modes.
  • R15 is shared across all modes.

The register bank allows the processor to switch between certain modes without always saving and restoring every register manually.

The complete register organization, banked registers and register count are covered in Lesson 03: ARM7 Register Set.

4. Arithmetic Logic Unit (ALU)

The ALU is responsible for performing arithmetic and logical operations on data held in registers.

Arithmetic Operations

  • Addition
  • Subtraction
  • Comparison
  • Address calculations

Logical Operations

  • AND
  • ORR (OR)
  • EOR (Exclusive OR)
  • BIC (Bit Clear)
  • MOV (Move)
  • MVN (Move Not)

Example: Addition

ADD R2, R0, R1

This instruction adds the values in R0 and R1 and stores the result in R2.

If R0 contains 10 and R1 contains 20, the resulting value in R2 is 30.

Example: Logical AND

AND R2, R0, R1

This instruction performs a bitwise AND operation between R0 and R1 and stores the result in R2.

The ALU can update condition flags in the CPSR when instructions request flag updates. These flags include Negative, Zero, Carry and Overflow.

5. Barrel Shifter

The barrel shifter is a hardware unit that performs shift and rotate operations on data.

ARM7TDMI can combine a shifted register operand with an arithmetic or logical instruction. This allows certain operations to be performed efficiently.

Types of Shift Operations

Operation Description
LSL Logical Shift Left.
LSR Logical Shift Right.
ASR Arithmetic Shift Right.
ROR Rotate Right.
RRX Rotate Right with Extend; rotates through the Carry flag.

Example: Logical Shift Left

MOV R2, R1, LSL #2

This instruction shifts the value in R1 left by two bit positions and stores the result in R2.

For example, if R1 contains 5: 

Decimal: 5
Binary:  00000101

After LSL #2:

Binary:  00010100
Decimal: 20

For this example, the shift produces the value 20 in R2.

Barrel Shifter with ALU

ADD R2, R0, R1, LSL #2

The processor shifts R1 left by two positions and adds the shifted value to R0. The result is stored in R2.

The barrel shifter is an important feature of ARM datapath design because it supports flexible operand manipulation within data-processing instructions.

6. Multiplier Unit

ARM7TDMI includes hardware multiplication support. The multiplier performs multiplication operations more efficiently than implementing them entirely through repeated software additions.

Important Multiplication Instructions

Instruction Purpose
MUL Performs a 32-bit multiplication and retains the lower 32 bits of the result.
MLA Performs multiplication followed by accumulation.
UMULL Performs unsigned long multiplication and produces a 64-bit result.
UMLAL Performs unsigned long multiply and accumulate.
SMULL Performs signed long multiplication and produces a 64-bit result.
SMLAL Performs signed long multiply and accumulate.

Example: MUL

MUL R2, R0, R1

If R0 contains 6 and R1 contains 4, the lower 32-bit product stored in R2 is 24.

Example: MLA

MLA R3, R0, R1, R2

This instruction performs: 

R3 = (R0 × R1) + R2

If R0 = 5, R1 = 4 and R2 = 3, then R3 = 23.

7. Instruction Decoder and Control Logic

The instruction decoder interprets the instruction fetched from memory. It identifies the operation, source registers, destination register and other instruction fields.

The control logic coordinates the internal processor units so that the required operation is performed.

Main Responsibilities

  • Decode ARM and Thumb instructions.
  • Identify instruction operation types.
  • Select source and destination registers.
  • Control ALU and barrel shifter operations.
  • Coordinate memory read and write operations.
  • Manage processor state and exception processing.

8. Three-Stage Instruction Pipeline

ARM7TDMI uses a three-stage pipeline to improve instruction throughput.

Pipeline Stages

  1. Fetch: Reads the instruction from memory.
  2. Decode: Interprets the instruction and identifies the required operation.
  3. Execute: Performs the operation and completes the appropriate result or memory access.
FETCH
DECODE
EXECUTE

Pipeline Operation

Clock Cycle Instruction 1 Instruction 2 Instruction 3
1 Fetch - -
2 Decode Fetch -
3 Execute Decode Fetch
4 Next instruction Execute Decode

Once the pipeline is filled, different instructions occupy different stages simultaneously. This improves instruction throughput.

Branches and other changes to the program flow can disrupt the pipeline and require it to be refilled. The visible PC value in ARM7TDMI also reflects the pipeline behavior.

Pipeline timing and behavior are explained in detail in Lesson 09: Three-Stage Pipeline.

9. CPSR and SPSR Registers

ARM7TDMI includes status registers that maintain processor state and execution information.

Current Program Status Register (CPSR)

The CPSR stores the current processor status and control information.

Important CPSR fields include:

  • Negative flag (N).
  • Zero flag (Z).
  • Carry flag (C).
  • Overflow flag (V).
  • Interrupt disable bits.
  • Processor mode bits.
  • Thumb state bit.

Saved Program Status Register (SPSR)

SPSR stores a saved copy of the CPSR when an exception is entered into a processor mode that has an SPSR.

This allows the previous processor status to be restored when the exception handler returns.

ARM7TDMI has one CPSR and five SPSRs, one each for FIQ, IRQ, Supervisor, Abort and Undefined modes. User and System modes do not have an SPSR.

10. Memory Interface

The memory interface connects the processor to the memory system. It supports instruction fetching and data transfer operations.

ARM7TDMI uses a unified instruction and data memory interface. Instructions and data share the same address space and external memory interface.

Common Memory Operations

Instruction Purpose
LDR Loads data from memory into a register.
STR Stores data from a register into memory.
LDRB Loads a byte from memory.
STRB Stores a byte into memory.
LDRH Loads a halfword.
STRH Stores a halfword.

Example: Memory Read

LDR R0, [R1]

This instruction reads a word from the memory address contained in R1 and loads it into R0.

Example: Memory Write

STR R0, [R1]

This instruction stores the word contained in R0 at the memory address held in R1.

The memory interface and its bus behavior are examined further in Lesson 11: ARM7 Memory Interface.

11. Datapath Operation: Instruction Example

Consider the following ARM instruction: 

ADD R2, R0, R1

Assume: 

R0 = 10
R1 = 20

Execution Steps

  1. Fetch: The processor fetches the ADD instruction from memory.
  2. Decode: The instruction decoder identifies the ADD operation and the source and destination registers.
  3. Read operands: The register bank supplies values from R0 and R1.
  4. Execute: The ALU adds the two operand values.
  5. Write back: The result is written into R2.

Expected Register Values

Register Value
R0 10
R1 20
R2 30

The result is obtained through the interaction of the instruction decoder, register bank and ALU.

13. Common Mistakes

  1. Confusing the ALU with the barrel shifter: The ALU performs arithmetic and logical operations; the barrel shifter performs shift and rotate operations.
  2. Assuming all registers are shared: Some registers have banked copies in particular modes.
  3. Assuming the multiplier handles every arithmetic operation: Addition and subtraction are performed by the ALU.
  4. Confusing pipeline stages with separate processors: The stages are coordinated parts of one processor pipeline.
  5. Confusing the core with its memory system: Memory capacity and peripheral integration depend on the complete microcontroller or system implementation.

14. Interview Questions and Answers

Q1. What are the main functional units of ARM7TDMI?

The major units include the register bank, ALU, barrel shifter, multiplier, instruction decoder, control logic, pipeline and memory interface.

Q2. What is the function of the ALU?

The ALU performs arithmetic and logical operations such as addition, subtraction, AND, OR and XOR.

Q3. What is a barrel shifter?

It is a hardware unit that performs shift and rotate operations on register operands.

Q4. Why is the barrel shifter useful?

It allows shifted operands to be used directly in many ARM data-processing instructions.

Q5. What is the function of the multiplier?

It performs multiplication operations, including multiply and multiply-accumulate instructions.

Q6. What is the function of the instruction decoder?

It interprets instructions and helps generate the control signals needed for execution.

Q7. What is the purpose of the register bank?

It provides fast storage for operands, addresses and intermediate processing results.

Q8. What is the ARM7TDMI pipeline structure?

It has three stages: Fetch, Decode and Execute.

Q9. What is the role of CPSR?

CPSR stores processor status and control information, including condition flags, mode bits and state information.

Q10. What is the role of the memory interface?

It allows the processor to fetch instructions and transfer data to and from memory.

17. Lesson Summary

  • ARM7TDMI contains several cooperating functional units.
  • The register bank stores operands and processing results.
  • The ALU performs arithmetic and logical operations.
  • The barrel shifter performs shift and rotate operations.
  • The multiplier performs multiplication operations.
  • The instruction decoder interprets instructions.
  • Control logic coordinates processor operations.
  • The processor uses a three-stage pipeline.
  • CPSR and SPSRs maintain processor status information.
  • The memory interface supports instruction and data transfers.
Key Takeaway: The ARM7TDMI internal architecture is based on coordinated datapath and control units. Understanding these units helps explain how ARM instructions are fetched, decoded and executed.
