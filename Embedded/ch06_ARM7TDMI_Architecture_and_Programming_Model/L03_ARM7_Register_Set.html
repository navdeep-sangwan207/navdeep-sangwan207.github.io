Lesson 03: ARM7 Register Set

Understand the ARM7TDMI general-purpose registers, special-purpose registers, banked registers, processor-mode register organization and register banking mechanism.

1. Introduction

Registers are small, high-speed storage locations inside a processor. They temporarily hold data, memory addresses, instruction-related information and intermediate results.

ARM7TDMI provides a register organization designed to support efficient instruction execution and exception handling.

The processor has 37 physical 32-bit registers: 31 general-purpose registers, including banked copies and the program counter, and six status registers consisting of one CPSR and five SPSRs.

Important: Although ARM7TDMI has 37 physical registers, only 16 general-purpose registers (R0–R15) are visible at a time in a particular processor mode.

3. General-Purpose Registers R0–R12

R0 to R12 are primarily used for general-purpose data storage and processing.

They can hold arithmetic operands, function arguments, pointers, counters and intermediate calculation results.

Register Common Use
R0 General-purpose data and function argument/result.
R1 General-purpose data and function argument.
R2 General-purpose data and function argument.
R3 General-purpose data and function argument.
R4–R11 General-purpose storage; often used for preserved variables under calling conventions.
R12 General-purpose register; commonly used as an intra-procedure scratch register.
Register usage conventions can depend on the compiler and ABI. The register names do not permanently assign a single application-specific purpose to R0–R12.

Example: Using General-Purpose Registers

MOV R0, #10
MOV R1, #20

ADD R2, R0, R1

Execution:

  • R0 receives 10.
  • R1 receives 20.
  • The ALU adds R0 and R1.
  • R2 receives 30.

4. Special-Purpose Registers

Three registers have commonly used special-purpose names in the ARM programming model.

4.1 Stack Pointer (R13 / SP)

R13 is called the Stack Pointer. It holds the address associated with the current stack.

The stack is a memory area used for temporary storage, function calls, local data and saving register values.

Stack Operations

STMFD SP!, {R0-R3}

; Restore registers
LDMFD SP!, {R0-R3}

These are common ARM assembly stack-operation forms. STMFD and LDMFD are assembler aliases for corresponding multiple-register transfer addressing modes.

ARM7TDMI supports banked R13 registers for different processor modes. This allows separate stack pointers to be maintained for exception handling and normal execution.

4.2 Link Register (R14 / LR)

R14 is called the Link Register. It commonly stores the return address when a subroutine is called using the Branch with Link instruction. 

BL FUNCTION

; Execution continues here after return

FUNCTION:
    MOV R0, #10
    BX LR

BL transfers control to the subroutine and stores return-address information in LR. BX LR returns using the address held in LR.

A nested function call may overwrite LR. A function that needs to preserve its return address must save LR, commonly on the stack.

4.3 Program Counter (R15 / PC)

R15 is the Program Counter. It is associated with the address of the instruction stream.

The PC is used to determine which instruction is fetched next. Branch instructions and exception handling can change the flow of execution.

In ARM state, reading R15 as an ordinary operand generally produces the address of the current instruction plus 8 bytes because of the pipeline. In Thumb state, the corresponding visible offset is generally plus 4 bytes. Some instructions have specific PC-related behavior.

5. Shared Registers and Banked Registers

ARM7TDMI uses register banking to provide separate physical registers for certain processor modes.

Register banking means that a register with the same architectural name can refer to a different physical storage location depending on the current processor mode.

Shared Registers

The following registers are shared across all processor modes:

  • R0–R7
  • R15 (PC)

R8–R12 are shared among User, System, IRQ, Supervisor, Abort and Undefined modes. FIQ mode has its own banked copies of R8–R12.

Banked Registers

ARM7TDMI provides banked copies of selected registers for exception modes.

Processor Mode Banked General-Purpose Registers
FIQ R8_fiq–R14_fiq
IRQ R13_irq, R14_irq
Supervisor R13_svc, R14_svc
Abort R13_abt, R14_abt
Undefined R13_und, R14_und
User and System Share R13_usr and R14_usr
Important distinction: FIQ has seven banked general-purpose registers: R8–R14. Each of the other exception modes has two banked general-purpose registers: R13 and R14.

The 16 registers visible at a time are R0–R15. The status register is accessed separately.

8. Why Does ARM7TDMI Use Register Banking?

Register banking helps reduce the amount of register saving and restoring required when the processor switches into an exception mode.

Example: Separate Stack Pointers

Consider an application running in User mode. If an IRQ occurs, the processor enters IRQ mode.

Because IRQ mode has its own banked R13 and R14, the interrupt handler can use a separate stack pointer and link register.

User Mode
↓ IRQ Exception
IRQ Mode
↓
IRQ-specific SP and LR
↓
Interrupt Handler
↓
Return to Previous Execution

Why Does FIQ Have More Banked Registers?

FIQ is intended for fast interrupt handling. It has additional banked registers R8–R12, allowing a fast interrupt handler to use more registers without immediately saving the corresponding User-mode registers.

Register banking reduces context-saving overhead, but it does not automatically preserve every register. Exception handlers must still save any shared registers they modify when those values must be preserved.

9. Register Banking and Context Switching

Register banking and context switching are related concepts, but they are not identical.

Register Banking

Register banking selects a different physical register when the processor changes operating mode.

Context Switching

Context switching involves saving the execution state of one task and restoring the state of another task. It is commonly performed by an operating system or RTOS scheduler.

Register Banking Context Switching
Hardware register organization feature. Software-controlled execution-state management.
Changes visible physical registers with processor mode. Saves and restores task-specific state.
Used by exception modes. Used by multitasking systems and RTOSs.
Banked registers do not automatically perform an RTOS task switch. The scheduler must still manage the appropriate task context.

10. Register Set in ARM Assembly Programming

ARM assembly instructions directly use register names to specify operands and destinations.

Example 1: Data Transfer

MOV R0, #25
MOV R1, R0

The first instruction places 25 in R0. The second copies the value of R0 into R1.

Example 2: Arithmetic

MOV R0, #15
MOV R1, #5

ADD R2, R0, R1
SUB R3, R0, R1

Expected values:

Register Expected Value
R0 15
R1 5
R2 20
R3 10

Example 3: Register Indirect Memory Access

LDR R0, [R1]
STR R0, [R2]
  • LDR reads a word from the memory address in R1.
  • STR writes the word in R0 to the memory address in R2.

11. Register Set and LPC2129 Programming

The LPC2129 uses an ARM7TDMI-S processor core. Its embedded C programs are compiled into ARM or Thumb instructions according to the project configuration and compiler settings.

The compiler uses the ARM register set to perform operations such as:

  • Loading peripheral register addresses.
  • Reading GPIO input values.
  • Writing GPIO output values.
  • Performing arithmetic on sensor readings.
  • Managing function calls and return addresses.
  • Handling interrupt routines.

Embedded C Example

#include <LPC21xx.h>

int main(void)
{
    unsigned int value;

    value = 100;

    PINSEL0 &= ~(3U << 10);
    IODIR0 |= (1U << 5);

    if (value > 50)
    {
        IOSET0 = (1U << 5);
    }
    else
    {
        IOCLR0 = (1U << 5);
    }

    while (1)
    {
    }
}

Register-Level Interpretation

The C compiler translates the operations into processor instructions. These instructions use general-purpose registers to hold values and addresses, while peripheral registers are accessed through memory-mapped addresses.

The C variable value may be stored in a CPU register or memory location depending on compiler optimization and register allocation. The source code does not guarantee a specific ARM register assignment.

12. Common Mistakes

  1. Assuming only 16 physical registers exist: R0–R15 are visible at a time, but the processor has 31 general-purpose physical registers.
  2. Assuming all modes have separate R8–R12: Only FIQ has banked R8–R12.
  3. Assuming User and System modes have separate SP and LR: They share the same R13 and R14 bank.
  4. Assuming the PC behaves like an ordinary data register: Pipeline effects and instruction-specific rules affect PC reads and writes.
  5. Confusing banked registers with saved context: Banking changes which physical registers are visible; it does not save every register automatically.
  6. Assuming all C variables occupy fixed CPU registers: Compiler register allocation determines where variables are stored.

13. Interview Questions and Answers

Q1. How many physical registers does ARM7TDMI have?

It has 37 physical 32-bit registers: 31 general-purpose registers and six status registers.

Q2. How many general-purpose registers are visible at a time?

Sixteen registers, R0 through R15, are visible in the current processor mode.

Q3. What is R13?

R13 is the Stack Pointer (SP).

Q4. What is R14?

R14 is the Link Register (LR), commonly used to store subroutine return-address information.

Q5. What is R15?

R15 is the Program Counter (PC).

Q6. What are banked registers?

Banked registers are separate physical registers that become visible when the processor enters particular modes.

Q7. Which registers are banked in FIQ mode?

R8–R14 are banked in FIQ mode.

Q8. Why does FIQ have more banked registers?

Additional banked registers reduce the need to save and restore shared registers during fast interrupt handling.

Q9. How many SPSRs are available?

Five SPSRs are available, one for each exception mode: FIQ, IRQ, Supervisor, Abort and Undefined.

Q10. Do User and System modes share registers?

Yes. User and System modes share the same general-purpose register bank, including R13 and R14.

Q11. What is the difference between register banking and context switching?

Register banking is a processor hardware feature. Context switching is the process of saving and restoring task execution state.

Q12. What is the purpose of the Link Register?

It holds return-address information for subroutine calls and is also used during exception handling.

  • ARM7TDMI has 37 physical 32-bit registers.
  • It has 31 general-purpose physical registers.
  • It has six status registers: one CPSR and five SPSRs.
  • R0–R15 are visible at a time in the current processor mode.
  • R13 is the Stack Pointer.
  • R14 is the Link Register.
