Saved Program Status Register (SPSR)

Course: Embedded Systems – Complete Study Course

Chapter 06: ARM7TDMI Architecture and Programming Model

Lesson 05

1. Introduction

The Saved Program Status Register (SPSR) is a special-purpose register in the ARM7TDMI processor. It stores a copy of the Current Program Status Register (CPSR) when the processor enters an exception mode.

The saved status allows the processor to restore the previous execution state when the exception handler finishes.

Main purpose: SPSR preserves the previous processor status so that an interrupted program or exception-related operation can resume with its original processor mode, instruction-set state, interrupt masks, and condition flags.

2. Why Is SPSR Required?

When an interrupt or exception occurs, the processor must change its execution environment to handle the event. The processor may change its mode, interrupt masks, and execution address.

Without saving the previous status, the processor would not have a reliable way to restore the interrupted program's original processor state.

Example scenario

  1. A program is executing in User mode.
  2. An IRQ interrupt occurs.
  3. The processor enters IRQ mode.
  4. The previous CPSR is copied into SPSR_irq.
  5. The IRQ handler processes the interrupt.
  6. The processor restores the saved status during exception return.
  7. The interrupted program resumes in its previous state.

3. SPSR Organization

Each SPSR is 32 bits wide and stores the saved CPSR value. It therefore preserves the status information represented by the CPSR at the time it was saved.

+--------------------------------------------------------------+
| Saved CPSR Value (32 bits) |
+--------------------------------------------------------------+
| N | Z | C | V | Reserved / implementation-defined | I | F | T | M |
+--------------------------------------------------------------+

The saved status includes:

  • Condition flags: N, Z, C and V.
  • Interrupt mask bits: I and F.
  • Instruction-set state bit: T.
  • Processor mode bits: M[4:0].
SPSR is not a separate set of condition flags. It is a saved processor status register containing the previous CPSR value.

4. Number of SPSR Registers in ARM7TDMI

ARM7TDMI provides five SPSR registers, one for each exception mode.

Exception modeSPSR registerPurpose
FIQSPSR_fiqSaves CPSR during FIQ entry
IRQSPSR_irqSaves CPSR during IRQ entry
Supervisor (SVC)SPSR_svcSaves CPSR during Supervisor exception entry
AbortSPSR_abtSaves CPSR during Abort entry
UndefinedSPSR_undSaves CPSR during Undefined instruction entry
User mode and System mode do not have SPSR registers. Only the five exception modes have an SPSR.

6. SPSR During Exception Entry

When an exception is taken, the processor performs a sequence of architectural operations. One important operation is saving the old CPSR into the SPSR belonging to the destination mode.

Example: IRQ exception entry

  1. The processor is executing the main program.
  2. An IRQ exception is recognized.
  3. The old CPSR is copied into SPSR_irq.
  4. The processor switches to IRQ mode.
  5. The IRQ interrupt mask is set as part of exception entry.
  6. The processor branches to the IRQ exception vector.

The IRQ mode has its own banked SP, LR and SPSR. This allows the handler to maintain a separate stack and preserve the interrupted program's status.

The exception entry mechanism also updates the link register for the destination exception mode. The saved return address is handled separately from the saved status in SPSR.

7. SPSR During Exception Return

At the end of an exception handler, the processor must return to the previous execution context. This involves restoring the saved status from SPSR to CPSR and transferring control to the appropriate return address.

Example: Exception return using data-processing instruction

        SUBS    PC, LR, #4

Explanation:

  • LR contains the exception return address, subject to the exception-specific offset.
  • Subtracting 4 produces the appropriate return address for a typical IRQ return.
  • PC is updated with the resulting address.
  • The S suffix, when used with PC as the destination in a privileged exception mode, causes the SPSR to be copied back into CPSR.
Important: The exact return-address calculation depends on the exception type. The example above is commonly used for IRQ return. Other exception handlers may require different offsets or return sequences. Exception-return instructions must follow the ARM architecture's rules.

8. Reading SPSR Using MRS

The MRS instruction can read the SPSR of the current exception mode. 

        MRS     R0, SPSR

Explanation:

  • MRS means Move to Register from Status Register.
  • R0 receives the current mode's SPSR value.
  • The instruction is meaningful in a mode that has an SPSR.
Executing an SPSR access while in User or System mode is not a valid way to obtain a saved status register because those modes do not have an SPSR.

9. Writing SPSR Using MSR

The MSR instruction can write selected fields of the SPSR associated with the current exception mode. 

        MSR     SPSR_c, R0

The _c field selector specifies the control field. Other field selectors include _f, _s, and _all.

Typical applications include:

  • Preparing a processor status value for an exception return.
  • Managing processor state in low-level exception code.
  • Restoring a previously saved execution context.
SPSR modification is a privileged low-level operation. Software must ensure that the saved mode and state fields form a valid return context. Arbitrary SPSR values can lead to unpredictable program behavior or an invalid execution transition.

10. SPSR and Banked Registers

ARM7TDMI uses banked registers to support efficient exception handling. Each exception mode has its own SPSR and banked R13 (SP) and R14 (LR).

ModeBanked SPBanked LRSPSR
FIQR13_fiqR14_fiqSPSR_fiq
IRQR13_irqR14_irqSPSR_irq
SupervisorR13_svcR14_svcSPSR_svc
AbortR13_abtR14_abtSPSR_abt
UndefinedR13_undR14_undSPSR_und

FIQ mode additionally has banked R8 through R12. These registers reduce the amount of general-purpose register saving needed during fast interrupt handling.

Banked registers and SPSR work together: banked registers provide separate working registers and stack context, while SPSR preserves the previous processor status.

11. Practical Example: Inspecting SPSR in Keil

In Keil uVision Simulator, SPSR can be inspected when the processor is executing in an exception mode such as IRQ or Supervisor mode.

Example assembly instructions

        ; Read current CPSR
        MRS     R0, CPSR

        ; Read SPSR of current exception mode
        MRS     R1, SPSR

        ; Compare saved status and current status
        CMP     R0, R1

Expected observations

  • R0 receives the current CPSR.
  • R1 receives the SPSR belonging to the current exception mode.
  • The two values may differ because exception entry changes the CPSR.
  • The exact values depend on the simulated exception and processor setup.
This is an instruction-level demonstration. A valid exception-mode setup is required before reading SPSR. The Keil simulator may not reproduce every external interrupt or peripheral event.

12. Applications of SPSR

  • Preserving interrupted program status.
  • Returning from IRQ and FIQ handlers.
  • Handling Supervisor calls and other exceptions.
  • Maintaining processor mode and instruction-set state.
  • Operating-system context management.
  • Low-level ARM exception-handler implementation.
  • Restoring condition flags after exception handling.

13. Common Mistakes

  1. Assuming CPSR and SPSR are the same register.
  2. Assuming every processor mode has an SPSR.
  3. Assuming SPSR stores the exception return address.
  4. Confusing SPSR with the banked link register.
  5. Attempting to access SPSR in User or System mode.
  6. Using an incorrect return-address offset for an exception.
  7. Assuming that restoring PC alone always restores the previous CPSR.
  8. Modifying saved processor state without checking mode and privilege rules.

14. Interview Questions and Answers

Q1. What is SPSR?

SPSR is a Saved Program Status Register that stores the previous CPSR value when the processor enters an exception mode.

Q2. How many SPSRs are available in ARM7TDMI?

Five SPSRs, one for each exception mode.

Q3. Which modes have SPSR?

FIQ, IRQ, Supervisor, Abort and Undefined modes.

Q4. Do User and System modes have SPSR?

No. User and System modes do not have SPSR registers.

Q5. What is the relationship between CPSR and SPSR?

CPSR stores current processor status, while SPSR preserves a previous CPSR value during exception handling.

Q6. Which instruction reads SPSR?

MRS is used to read SPSR.

Q7. Which instruction writes SPSR?

MSR is used to write selected SPSR fields.

Q8. When is CPSR copied into SPSR?

When an exception is taken and the processor enters an exception mode.

Q9. What happens during exception return?

The saved status is restored from SPSR to CPSR through an appropriate exception-return mechanism.

Q10. Does SPSR store the return address?

No. The exception mode's banked link register stores the exception return address; SPSR stores the previous processor status.
