Lesson 01: Introduction to ARM7TDMI

Understand the ARM7TDMI processor, its architecture, key features, instruction-set support and importance in embedded systems.

1. Introduction

ARM7TDMI is a widely used 32-bit RISC processor core developed by ARM. It is based on the ARMv4T architecture and supports both the ARM and Thumb instruction sets.

The processor is designed to provide efficient instruction execution with relatively low hardware complexity and power consumption. It has been used in many embedded applications, including industrial controllers, communication equipment, consumer electronics and microcontroller systems.

ARM7TDMI is a processor core, not a complete microcontroller. Semiconductor manufacturers integrate the core with memory, GPIO, timers, communication peripherals and other hardware to create complete microcontrollers.

Important: The LPC2129 microcontroller uses an ARM7TDMI-S processor core. Therefore, understanding ARM7TDMI architecture is essential before studying LPC2129 programming.

2. Meaning of ARM7TDMI

The name ARM7TDMI identifies a processor core with several important architectural and implementation features.

Letter Meaning Description
T Thumb Supports the 16-bit Thumb instruction set.
D Debug Provides hardware debug support, including an embedded debug interface.
M Multiplier Includes enhanced multiplier functionality.
I EmbeddedICE Provides on-chip debug logic for breakpoint and watchpoint support.
The ARM7TDMI-S is a synthesizable version of the ARM7TDMI processor core. The LPC2129 uses this synthesizable core.

3. What is an ARM Processor?

ARM stands for Advanced RISC Machines. ARM processors are based on Reduced Instruction Set Computer (RISC) principles.

RISC architecture emphasizes a relatively simple instruction set, efficient instruction execution and a load/store approach to memory access.

Important RISC Characteristics

  • Relatively simple instruction formats.
  • Large general-purpose register usage.
  • Load/store architecture for accessing data memory.
  • Efficient instruction execution pipeline.
  • Conditional execution support in ARM instructions.
  • Hardware-oriented instruction operations.

Load/Store Architecture

In a load/store architecture, arithmetic and logical instructions generally operate on registers. Data is transferred between memory and registers using load and store instructions. 

; Example ARM assembly instructions

LDR R0, [R1]       ; Load memory data into R0
ADD R2, R0, R3     ; Add register values
STR R2, [R1]       ; Store result back to memory

In this example, LDR reads data from memory, ADD performs register-based arithmetic, and STR writes the result to memory.

4. ARM7TDMI Architecture Overview

ARM7TDMI is a 32-bit processor architecture. Its main functional elements work together to fetch, decode and execute instructions.

Main Functional Units

  1. Register Bank: Stores operands, addresses and intermediate results.
  2. ALU: Performs arithmetic and logical operations.
  3. Barrel Shifter: Performs shift and rotate operations on register data.
  4. Multiplier: Supports multiplication operations.
  5. Control Logic: Controls instruction execution and processor operation.
  6. Pipeline: Organizes instruction fetching, decoding and execution.
  7. Memory Interface: Provides communication between the processor and external memory system.

6. ARM State and Thumb State

ARM7TDMI supports two instruction-set states:

ARM State

  • Uses 32-bit ARM instructions.
  • Provides a rich set of instruction operations.
  • Supports conditional execution for most data-processing instructions.
  • Offers flexible addressing and operand manipulation.

Thumb State

  • Uses 16-bit Thumb instructions in the original ARMv4T Thumb instruction set.
  • Improves code density compared with equivalent ARM instruction sequences in many cases.
  • Is useful where program memory is limited.
  • Uses a more compact instruction encoding.
ARM State Thumb State
32-bit instruction encoding 16-bit instruction encoding
Generally larger code size Generally more compact code
Richer instruction capabilities More restricted instruction formats
Useful for performance-oriented code Useful for code-density-oriented applications
ARM and Thumb are two execution states of the same processor. They are not separate processors. The T bit in the CPSR indicates the current instruction-set state.

7. ARM7TDMI Processor Modes

ARM7TDMI supports seven processor modes. These modes determine the processor's privilege level and the registers available during execution.

Mode Purpose
User Normal application program execution.
System Privileged mode using the User mode register set.
FIQ Fast Interrupt Request handling.
IRQ Normal Interrupt Request handling.
Supervisor (SVC) Privileged mode entered after a software interrupt or reset.
Abort Handles memory access-related abort exceptions.
Undefined Handles undefined instruction exceptions.

User mode is unprivileged. The other six modes are privileged. FIQ, IRQ, Supervisor, Abort and Undefined are exception modes.

The processor mode is selected using the mode bits in the CPSR. Each exception mode has its own banked stack pointer and link register, while FIQ has additional banked registers.

8. ARM7TDMI Core vs ARM7-Based Microcontroller

An important distinction in embedded systems is the difference between a processor core and a complete microcontroller.

ARM7TDMI Core Provides

  • Instruction execution.
  • Register organization.
  • Arithmetic and logical operations.
  • Processor modes and exception mechanisms.
  • Instruction pipeline.

A Microcontroller Adds

  • Program Flash memory.
  • Data SRAM.
  • GPIO ports.
  • Timers and counters.
  • UART communication interfaces.
  • ADC and other peripheral controllers.
  • System clock and reset circuitry.
The exact peripherals and memory sizes depend on the microcontroller implementation. They are not automatically provided by the ARM7TDMI core itself.

9. ARM7TDMI-S in LPC2129

The LPC2129 is an ARM7-based microcontroller from NXP. It integrates an ARM7TDMI-S processor core with on-chip memory and multiple peripheral interfaces.

Important LPC2129 Components

  • ARM7TDMI-S processor core.
  • On-chip Flash program memory.
  • On-chip SRAM.
  • GPIO ports.
  • Two UART interfaces.
  • Timer and counter units.
  • Vectored Interrupt Controller (VIC).
  • ADC peripheral.
  • PWM peripheral.
  • I2C, SPI and CAN interfaces.

Relationship Between ARM7TDMI-S and LPC2129

The ARM7TDMI-S core executes the program instructions. LPC2129 peripherals provide hardware functions such as serial communication, timing, digital input/output and analog-to-digital conversion.

Embedded C programs running on the ARM7 core access these peripherals through memory-mapped registers. 

#include <LPC21xx.h>

int main(void)
{
    // Configure P0.5 as GPIO output
    PINSEL0 &= ~(3U << 10);

    // Set P0.5 as output
    IODIR0 |= (1U << 5);

    // Set P0.5 HIGH
    IOSET0 = (1U << 5);

    while (1)
    {
        // Main program loop
    }
}

Program Explanation

  1. LPC21xx.h provides register definitions for the LPC21xx family.
  2. PINSEL0 configures the pin function.
  3. IODIR0 configures P0.5 as an output.
  4. IOSET0 writes a HIGH value to the output latch for P0.5.
  5. The infinite loop keeps the program running.
Simulation note: This program illustrates LPC2129 register-level programming. In the Keil simulator, inspect the relevant registers to verify their values. Register changes do not prove that a physical LED is actually illuminated.

12. Common Mistakes

  1. ARM7TDMI is a complete microcontroller: Incorrect. It is a processor core.
  2. ARM and Thumb are separate processors: Incorrect. They are two instruction-set states supported by the same processor.
  3. All ARM instructions are 16-bit: Incorrect. ARM instructions are 32-bit; original Thumb instructions are 16-bit.
  4. All processor modes have identical registers: Incorrect. Some modes have banked registers.
  5. All peripherals are part of the ARM7TDMI core: Incorrect. Peripheral integration depends on the microcontroller implementation.

13. Interview Questions and Answers

Q1. What is ARM7TDMI?

ARM7TDMI is a 32-bit RISC processor core based on ARMv4T architecture. It supports ARM and Thumb instruction sets.

Q2. What does the T in ARM7TDMI represent?

T represents Thumb instruction-set support.

Q3. What is the difference between ARM and Thumb states?

ARM state uses 32-bit instructions, whereas the original Thumb state uses 16-bit instructions for improved code density.

Q4. Is ARM7TDMI a microcontroller?

No. It is a processor core that can be integrated into a microcontroller along with memory and peripherals.

Q5. Which processor core is used in LPC2129?

LPC2129 uses an ARM7TDMI-S processor core.

Q6. How many processor modes are supported by ARM7TDMI?

Seven modes: User, FIQ, IRQ, Supervisor, Abort, Undefined and System.

Q7. What is the pipeline structure of ARM7TDMI?

It uses a three-stage pipeline consisting of Fetch, Decode and Execute stages.

Q8. What is the purpose of EmbeddedICE?

EmbeddedICE provides on-chip debug facilities such as hardware breakpoint and watchpoint support.

Q9. What is a load/store architecture?

It is an architecture in which data is transferred between memory and registers using load and store instructions, while arithmetic operations generally work on registers.

Q10. Why is ARM7TDMI important for embedded systems?

It provides an efficient processor architecture for embedded applications and forms the processing core of several ARM7-based microcontrollers.
