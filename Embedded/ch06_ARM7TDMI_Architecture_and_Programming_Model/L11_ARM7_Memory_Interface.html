1. Introduction

The memory interface connects the ARM7TDMI processor core to memory and other system components. It enables the processor to fetch instructions, read data, and write data.

ARM7TDMI follows a load-store architecture. Arithmetic and logical operations generally work on registers, while explicit load and store instructions transfer data between registers and memory.

Core concept: The processor uses memory addresses to access instructions and data through its memory interface.

2. ARM7TDMI Memory Architecture

ARM7TDMI uses a 32-bit address space. This allows it to address up to 4 GB of byte-addressable memory space.

The processor core communicates with the memory system through address, data, and control signals.

ARM7TDMI PROCESSOR +----------------------+ | | | CPU CORE | | | +----------------------+ | | | | | | Address Data Control | | | v v v +----------------------+ | MEMORY SYSTEM | | | | ROM / RAM / FLASH | | Memory-Mapped I/O | +----------------------+

The external memory system determines how addresses are mapped to physical memory devices and peripherals.

3. Address Space

The ARM7TDMI uses 32-bit addresses. Each address identifies a byte location.

The theoretical address range is: 

Start address : 0x00000000
End address   : 0xFFFFFFFF

Address space : 2^32 bytes = 4 GB

Example addresses

AddressMeaning
0x00000000Beginning of address space
0x00001000Example memory location
0x10000000Example memory location
0xFFFFFFFFLast byte address
The 4 GB figure describes the processor's theoretical address space, not the amount of physical RAM installed in a system.

4. Load-Store Architecture

In a load-store architecture, memory is accessed using explicit load and store instructions.

Load operation

A load instruction reads data from memory and places it into a processor register. 

        LDR     R0, [R1]

This instruction loads a word from the memory address held in R1 into R0.

Store operation

A store instruction writes data from a processor register into memory. 

        STR     R0, [R1]

This instruction stores the contents of R0 at the memory address held in R1.

ARM7TDMI does not normally perform arithmetic directly on memory operands. Data is loaded into registers, processed, and stored back when required.

6. Memory Alignment

Memory alignment describes whether a data item is located at an address that satisfies its required boundary.

A word is naturally aligned when its address is divisible by four.

ARM7TDMI has specific architectural behavior for unaligned accesses. Do not assume every unaligned word or halfword access behaves like an aligned access. Follow the ARM7TDMI instruction and memory-interface rules.

9. Memory Read Operation

During a memory read, the processor requests data from a specified address.

ARM7TDMI | | Address v +-------------+ | MEMORY | +-------------+ | | Read data v ARM7TDMI | v Destination Register

Example

        LDR     R0, [R1]
  1. The processor obtains the address stored in R1.
  2. The memory system receives the address and read request.
  3. Memory returns the requested word.
  4. The processor places the returned value in R0.

10. Memory Write Operation

During a memory write, the processor sends data to a specified memory address.

ARM7TDMI | | Address v +-------------+ | MEMORY | +-------------+ ^ | Write data | ARM7TDMI ^ | Source Register

Example

        STR     R0, [R1]
  1. The processor obtains the destination address from R1.
  2. The processor obtains the data from R0.
  3. The memory system receives the address and write request.
  4. The memory system stores the data at the specified location.

11. Memory-Mapped I/O

Memory-mapped I/O is a technique in which peripheral registers are assigned addresses in the processor's memory address space.

The processor accesses these registers using load and store instructions, similar to memory accesses.

Conceptual example

PERIPHERAL_REGISTER EQU 0xE0000000

        LDR     R0, =PERIPHERAL_REGISTER
        LDR     R1, [R0]
        ORR     R1, R1, #1
        STR     R1, [R0]

This example illustrates reading a peripheral register, setting bit 0, and writing the modified value back. The address is illustrative, not an LPC2129 register address.

Peripheral registers can have special read/write behavior. Always check the device datasheet before performing read-modify-write operations.

12. Memory Protection and Access Errors

The memory system can reject an access when the requested address or transfer is not supported or permitted.

In ARM7TDMI systems, an abort response from the memory interface can generate an exception.

  • Prefetch Abort: associated with instruction fetching.
  • Data Abort: associated with data memory access.

The system's memory controller and external logic determine which accesses are valid.

13. ARM7TDMI and LPC2129 Memory Organization

ARM7TDMI is the processor core used in the LPC2129 microcontroller. The LPC2129 integrates memory and peripherals around this processor core.

ComponentPurpose
ARM7TDMI-S coreExecutes program instructions
On-chip FlashStores firmware
On-chip SRAMStores runtime data and stack
Peripheral registersControl GPIO, timers, UART, ADC, and other peripherals
Memory interfaceConnects the processor to its memory system
The ARM7TDMI core's theoretical 4 GB address space does not mean the LPC2129 contains 4 GB of physical memory. The microcontroller implements a device-specific memory map.

14. Practical Assembly Programming Examples

Example 1: Load an immediate value and store it in memory

        AREA    MEMORY_DEMO, CODE, READONLY
        ENTRY

        LDR     R1, =0x40000000
        MOV     R0, #25
        STR     R0, [R1]

STOP
        B       STOP

        END

Explanation: R1 receives the example address. R0 receives decimal value 25. STR requests a word write to the address held in R1.

Example 2: Read a word from memory

        LDR     R1, =0x40000000
        LDR     R0, [R1]

Explanation: The processor reads a word from the address in R1 and places it in R0.

Example 3: Load and store a byte

        LDR     R1, =0x40000000
        MOV     R0, #0x5A
        STRB    R0, [R1]
        LDRB    R2, [R1]

Explanation: STRB writes the least significant byte of R0. LDRB reads one byte and zero-extends it into R2.

These are instruction-level examples using illustrative addresses. Do not run them against arbitrary physical addresses on a real microcontroller. For Keil simulation, configure valid memory regions and inspect the memory window.

15. Common Mistakes

  1. Assuming the 4 GB address space is the same as physical RAM capacity.
  2. Confusing byte addresses with word addresses.
  3. Assuming every memory access is a 32-bit transfer.
  4. Ignoring alignment requirements.
  5. Confusing little-endian and big-endian byte ordering.
  6. Assuming all addresses refer to RAM rather than memory-mapped peripherals.
  7. Using arbitrary addresses in real hardware programs.
  8. Assuming every peripheral register supports ordinary read-modify-write operations.

16. Interview Questions and Answers

Q1. What is the ARM7TDMI address space?

It is a 32-bit address space capable of representing up to 4 GB of byte-addressable locations.

Q2. What is a load-store architecture?

It is an architecture in which explicit load and store instructions transfer data between memory and registers.

Q3. What is the difference between LDR and STR?

LDR transfers data from memory to a register; STR transfers data from a register to memory.

Q4. What is memory alignment?

It is the placement of data at addresses that satisfy the required address boundary.

Q5. What is the difference between little-endian and big-endian?

Little-endian stores the least significant byte at the lowest address; big-endian stores the most significant byte there.

Q6. What is memory-mapped I/O?

It is a technique in which peripheral registers are assigned addresses in the processor's memory address space.

Q7. What is the difference between LDRB and LDR?

LDRB loads one byte and zero-extends it; LDR loads a word.

Q8. What is a Data Abort?

It is an exception associated with a data memory access that receives an abort response.

Q9. Does ARM7TDMI require all word accesses to be aligned?

Word accesses have natural 4-byte alignment. Unaligned accesses have architecture-specific behavior and should not be treated as ordinary aligned transfers.

Q10. How does LPC2129 use the ARM7 memory interface?

The LPC2129 integrates Flash, SRAM, and peripheral registers into a device-specific memory system accessible by the ARM7 core.
