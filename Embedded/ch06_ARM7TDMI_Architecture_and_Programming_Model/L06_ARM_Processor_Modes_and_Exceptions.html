1. Introduction

ARM7TDMI supports different processor operating modes to manage normal program execution, privileged operations, interrupts, and exceptional conditions.

A processor mode determines the currently visible banked registers, privilege level, and access to certain processor control operations.

An exception is an event or condition that causes the processor to suspend its normal instruction flow and transfer execution to a predefined exception-handling routine.

Core concept: Processor modes define the execution environment. Exceptions cause the processor to enter an appropriate handling mode.

2. Seven Operating Modes of ARM7TDMI

ARM7TDMI provides seven operating modes. The current mode is identified by the five mode bits M[4:0] in the CPSR.

3. User Mode

User mode is the normal application execution mode. It is unprivileged and restricts access to certain processor control operations.

Characteristics

  • Used for normal application programs.
  • Has restricted access to processor control features.
  • Cannot freely change CPSR control fields.
  • Does not have its own SPSR.
  • Shares its general-purpose register bank with System mode.

User mode helps separate application-level execution from privileged processor and operating-system operations.

4. System Mode

System mode is a privileged operating mode that uses the same general-purpose register bank as User mode.

Characteristics

  • Provides privileged execution.
  • Uses the User/System shared R0–R15 register bank.
  • Does not have an SPSR.
  • Can execute privileged operations permitted by the architecture.
User and System modes share the same physical general-purpose registers, but they differ in privilege level.

5. Exception Modes

ARM7TDMI has five exception modes. These modes provide separate register resources for handling specific exception types.

5.1 FIQ Mode

Fast Interrupt Request (FIQ) mode is designed for fast interrupt servicing.

  • Entered when an FIQ exception is taken.
  • Has banked R8_fiq through R14_fiq.
  • Has its own SPSR_fiq.
  • Provides more banked general-purpose registers than other exception modes.
  • Supports efficient handling with reduced register-saving overhead.

5.2 IRQ Mode

Interrupt Request (IRQ) mode handles normal interrupt requests.

  • Entered when an IRQ exception is taken.
  • Has banked R13_irq and R14_irq.
  • Has its own SPSR_irq.
  • Commonly used for peripheral interrupt servicing.

5.3 Supervisor Mode

Supervisor mode is a privileged mode used for operating-system and supervisor-level operations.

  • Entered on reset.
  • Entered when a Software Interrupt (SWI) exception occurs.
  • Has banked R13_svc and R14_svc.
  • Has its own SPSR_svc.

5.4 Abort Mode

Abort mode handles memory access faults detected by the processor.

  • Entered for Prefetch Abort and Data Abort exceptions.
  • Has banked R13_abt and R14_abt.
  • Has its own SPSR_abt.

5.5 Undefined Mode

Undefined mode handles execution of an instruction that the processor does not recognize as a valid instruction in the current instruction set.

  • Entered when an Undefined Instruction exception occurs.
  • Has banked R13_und and R14_und.
  • Has its own SPSR_und.

6. Privileged and Unprivileged Modes

ARM7TDMI modes can be grouped according to their privilege level.

Mode categoryModesPrivilege
UnprivilegedUserRestricted
PrivilegedFIQ, IRQ, Supervisor, Abort, Undefined, SystemPrivileged

Why privilege levels are important

  • They separate normal applications from system-level operations.
  • They restrict direct modification of processor control state.
  • They support controlled exception handling.
  • They provide a foundation for operating-system protection mechanisms.

7. What Is an Exception?

An exception is a processor event that interrupts normal program execution and transfers control to an exception handler.

9. ARM7TDMI Exception Vector Table

ARM7TDMI uses a fixed exception vector table. Each exception has a defined address where the processor begins exception handling.

Vector addressException
0x00000000Reset
0x00000004Undefined Instruction
0x00000008Software Interrupt (SWI)
0x0000000CPrefetch Abort
0x00000010Data Abort
0x00000014Reserved
0x00000018IRQ
0x0000001CFIQ
These are the standard ARM7 exception vector offsets. The actual vector base and memory mapping depend on the system implementation. On LPC2129, boot and memory-mapping configuration determine how the vector addresses are mapped.

10. Exception Entry Sequence

When an exception is accepted, the ARM7TDMI processor performs several operations to prepare for exception handling.

  1. Copies the old CPSR into the SPSR of the destination exception mode.
  2. Copies the appropriate return address into the banked link register.
  3. Changes the CPSR mode bits to select the exception mode.
  4. Sets the appropriate interrupt mask bits according to exception type.
  5. Clears the T bit so that the exception handler begins in ARM state.
  6. Branches to the relevant exception vector address.
Exception entry behavior is defined by the architecture. The return address and mask-bit changes are exception-specific; do not assume every exception has identical entry details.

11. Exception Return Sequence

The exception handler must eventually return to the interrupted program or to an appropriate continuation point.

  1. Complete the required exception processing.
  2. Restore any shared registers that the handler modified.
  3. Use the correct exception-specific return address.
  4. Restore the saved processor status from SPSR to CPSR.
  5. Continue execution in the restored processor state.

Example: IRQ exception return

        SUBS    PC, LR, #4

In a typical ARM-state IRQ handler, this instruction returns to the interrupted instruction stream and restores CPSR from SPSR_irq. The exact return sequence depends on the exception and the instruction address at which it occurred.

12. Difference Between IRQ and FIQ

FIQ has additional banked registers to reduce the need for saving and restoring general-purpose registers. This supports faster interrupt servicing, although actual latency also depends on the system and handler implementation.

13. Software Interrupt (SWI)

A Software Interrupt instruction causes the processor to enter Supervisor mode. It provides a controlled mechanism for software to request a privileged service.

Example

        SWI     0x01

When executed, the processor takes a Software Interrupt exception and begins handling it at the SWI vector.

Applications

  • Operating-system service requests.
  • Controlled entry into privileged code.
  • System-call mechanisms in ARM-based systems.

14. Exception Handling in LPC2129

The LPC2129 microcontroller uses an ARM7TDMI-S processor core. Its exception architecture is combined with the on-chip Vectored Interrupt Controller (VIC) for peripheral interrupt management.

  • ARM7 exception modes provide the processor-level handling environment.
  • The VIC manages interrupt sources and prioritization.
  • IRQ and FIQ are processor-level interrupt exception types.
  • Timer, UART, ADC and other peripheral events can generate interrupt requests.
  • Exception handlers must preserve registers and return correctly.
The ARM exception architecture and the LPC2129 VIC are different layers. ARM defines processor exception behavior; the VIC manages interrupt requests from microcontroller peripherals.

17. Common Mistakes

  1. Assuming all seven processor modes are privileged.
  2. Assuming User and System modes have separate general-purpose register banks.
  3. Assuming User and System modes have SPSR registers.
  4. Confusing FIQ and IRQ banked registers.
  5. Confusing exception vectors with peripheral interrupt sources.
  6. Assuming the vector table must always be located in physical ROM at address zero.
  7. Using the same return-address correction for every exception.
  8. Forgetting to preserve shared registers used by an exception handler.

18. Interview Questions and Answers

Q1. How many operating modes are available in ARM7TDMI?

Seven operating modes.

Q2. Which mode is unprivileged?

User mode.

Q3. Which modes have their own SPSR?

FIQ, IRQ, Supervisor, Abort and Undefined modes.

Q4. What is an exception?

An event or condition that causes the processor to suspend its normal instruction flow and transfer control to an exception handler.

Q5. What is the difference between IRQ and FIQ?

FIQ is designed for fast interrupt handling and has more banked registers than IRQ.

Q6. Which mode is entered after a Software Interrupt?

Supervisor mode.

Q7. Which mode handles an undefined instruction?

Undefined mode.

Q8. What is the purpose of an exception vector?

It identifies the address from which the corresponding exception handler begins.

Q9. Which mode is entered on reset?

Supervisor mode.

Q10. What is the role of SPSR during exception handling?

It preserves the previous CPSR so that the processor status can be restored.

Q11. What is the difference between processor exceptions and VIC interrupts?

Processor exceptions define how the ARM core responds to events. The VIC manages and presents microcontroller interrupt requests to the processor.

Q12. Why does FIQ have more banked registers?

To reduce register-saving overhead and support faster interrupt handling.

21. Lesson Summary

  • ARM7TDMI supports seven operating modes.
  • User mode is unprivileged; the other six modes are privileged.
  • Five exception modes have their own SPSR.
  • FIQ has additional banked registers for efficient interrupt handling.
  • Exceptions transfer execution to predefined vector addresses.
  • Exception entry saves the previous CPSR in the destination SPSR.
  • Exception return restores the saved processor status.
  • LPC2129 uses the ARM exception architecture together with its VIC.
