1. Introduction

ARM7TDMI supports two instruction-set states: ARM state and Thumb state. ARM state uses 32-bit ARM instructions, while the original Thumb instruction set supported by ARM7TDMI uses 16-bit instructions.

Thumb was designed to provide a more compact instruction encoding. This can reduce program code size and improve memory utilization, particularly in systems with limited memory.

Core concept: ARM and Thumb are two instruction-set states of the same processor. The CPSR T bit identifies which state is currently active.

2. What Is Thumb State?

Thumb state is an execution state in which the processor executes instructions encoded using the Thumb instruction set.

  • Original Thumb instructions are 16 bits wide.
  • Thumb instructions generally require less code memory than equivalent ARM code.
  • Thumb uses the same underlying ARM7TDMI processor and register architecture.
  • The processor changes between ARM and Thumb state using supported state-transition mechanisms.

3. Why Was Thumb Introduced?

Early embedded systems often had limited ROM, RAM, and memory-bus resources. A compact instruction set helped developers reduce firmware size.

Main objectives

  • Improve code density.
  • Reduce instruction storage requirements.
  • Support cost-effective embedded system designs.
  • Provide a compact instruction set for common programming operations.
  • Allow ARM-based processors to execute smaller firmware programs.

Thumb instructions are not simply shortened versions of every ARM instruction. Thumb has its own instruction encodings and certain operations require different instruction sequences.

5. CPSR T Bit

The T bit is located at bit 5 of the CPSR. It identifies the current instruction-set state.

T bitActive state
0ARM state
1Thumb state

Reading the T bit

        MRS     R0, CPSR
        AND     R1, R0, #0x20

The result in R1 is zero when the processor is in ARM state. It is 0x20 when the processor is in Thumb state.

6. Thumb Register Usage

Thumb instructions use the ARM7TDMI general-purpose register architecture, but many original Thumb instructions have restricted register fields.

Low registers

Many Thumb instructions operate directly on R0 through R7. These are commonly called low registers.

High registers

R8 through R15 are high registers. The original Thumb instruction set provides more restricted access to these registers, with specific instructions supporting high-register operations.

Register rangeUsage
R0–R7Low registers used by many Thumb instructions
R8–R12High registers
R13Stack Pointer (SP)
R14Link Register (LR)
R15Program Counter (PC)
Thumb state does not create a separate set of general-purpose registers. It changes the instruction encoding and the register access available to individual instructions.

7. Thumb Instruction Categories

7.1 Move Instructions

Move instructions transfer values between registers or load immediate values.

        MOV     R0, #10
        MOV     R1, R0

7.2 Arithmetic Instructions

Arithmetic instructions perform addition and subtraction.

        MOV     R0, #10
        MOV     R1, #5
        ADD     R2, R0, R1
        SUB     R3, R0, R1

7.3 Logical Instructions

Logical instructions operate on individual bits.

        AND     R2, R0, R1
        ORR     R3, R0, R1
        EOR     R4, R0, R1
        BIC     R5, R0, R1

7.4 Load and Store Instructions

Load and store instructions transfer data between registers and memory.

        LDR     R0, [R1]
        STR     R0, [R1]

7.5 Compare Instructions

Compare instructions update condition flags without storing an arithmetic result.

        CMP     R0, R1

7.6 Branch Instructions

Branch instructions change the program execution flow.

        B       LOOP
        BEQ     EQUAL
        BNE     NOT_EQUAL

7.7 Stack Instructions

Thumb provides compact PUSH and POP instructions for common stack operations.

        PUSH    {R0, R1, R2, LR}
        POP     {R0, R1, R2, PC}
These examples show common Thumb instruction forms. The exact register combinations and addressing forms are constrained by the original ARMv4T Thumb instruction encoding.

8. Thumb Conditional Execution

In ARM state, many data-processing instructions can include condition suffixes. Original Thumb instructions provide more limited conditional execution.

Thumb commonly uses conditional branch instructions after a comparison. 

        CMP     R0, #10
        BEQ     EQUAL

        MOV     R1, #0
        B       DONE

EQUAL
        MOV     R1, #1

DONE
        B       DONE

BEQ branches to EQUAL when the Zero flag is set by the CMP instruction.

9. Switching Between ARM and Thumb States

ARM7TDMI supports switching between ARM and Thumb state through instructions and exception-return mechanisms that update the processor state correctly.

Using BX

The Branch and Exchange (BX) instruction branches to the address held in a register and selects ARM or Thumb state using bit 0 of that address. 

        LDR     R0, =THUMB_FUNCTION + 1
        BX      R0

        ; Thumb code begins at THUMB_FUNCTION

The low-order address bit indicates the desired state:

  • Bit 0 = 0: ARM state.
  • Bit 0 = 1: Thumb state.
The low-order bit is a state-selection indicator for BX. It is not the actual instruction address bit used to fetch the instruction. The processor aligns the target appropriately.

Returning from an exception

An exception return that restores CPSR from SPSR can also restore the previous ARM/Thumb state through the saved T bit.

10. Thumb and Memory Utilization

Thumb's compact instruction encoding can reduce the amount of memory needed to store a program.

Simple storage comparison

Instruction representationSize
One ARM instruction4 bytes
One original Thumb instruction2 bytes
Two ARM instructions8 bytes
Two original Thumb instructions4 bytes

This comparison describes instruction storage width, not a guaranteed 50% reduction in complete program size. Different instruction sequences may be required to perform the same task.

11. Advantages of Thumb State

  • Improved code density for many applications.
  • Reduced instruction storage requirements.
  • Useful for embedded systems with limited memory.
  • Can reduce instruction-fetch traffic in memory systems.
  • Supports compact firmware implementation.

12. Limitations of Original Thumb State

  • Restricted instruction encoding compared with ARM state.
  • Many instructions have limited register choices.
  • Conditional execution is less flexible.
  • Some operations require multiple instructions.
  • Code density and execution performance depend on the application and memory system.

13. Thumb Programming in Keil uVision

Keil uVision supports ARM and Thumb development for ARM7TDMI targets when the appropriate assembler, compiler, and target configuration are selected.

Suggested procedure

  1. Create or open an ARM7TDMI project.
  2. Configure the target processor and toolchain.
  3. Write a small Thumb-compatible assembly routine.
  4. Use the assembler's supported Thumb code directives or compiler options.
  5. Build the project and inspect the disassembly.
  6. Check the CPSR T bit during Thumb execution.
  7. Use BX or a valid interworking mechanism to change state.
The simulator can help inspect instruction execution, registers, CPSR and disassembly. It does not demonstrate physical memory performance or external hardware behavior.

14. Applications of Thumb State

  • Memory-constrained embedded firmware.
  • Small microcontroller applications.
  • Compact bootloader code.
  • Embedded control systems.
  • Applications where code density is important.

15. Common Mistakes

  1. Assuming Thumb state uses 32-bit instructions.
  2. Assuming Thumb uses a separate physical register bank.
  3. Confusing the CPSR T bit with the BX target-address state indicator.
  4. Assuming all ARM instructions have direct Thumb equivalents.
  5. Assuming Thumb always executes faster than ARM.
  6. Forgetting that many original Thumb instructions have restricted register fields.
  7. Trying to execute ARM instruction encodings while the processor is in Thumb state.

16. Interview Questions and Answers

Q1. What is Thumb state?

Thumb state is an ARM processor execution state that uses the original 16-bit Thumb instruction set on ARM7TDMI.

Q2. What is the instruction width in Thumb state?

16 bits.

Q3. Which CPSR bit selects Thumb state?

The T bit at bit position 5.

Q4. What does T = 1 indicate?

Thumb state.

Q5. What does T = 0 indicate?

ARM state.

Q6. Why was Thumb introduced?

To improve code density and reduce instruction storage requirements.

Q7. Which instruction supports ARM/Thumb state exchange?

BX, Branch and Exchange.

Q8. Which registers are commonly used by original Thumb instructions?

R0 through R7 are used by many Thumb instruction forms.

Q9. Does Thumb state use separate general-purpose registers?

No. It uses the same underlying processor register architecture.

Q10. Does Thumb always provide better execution performance?

No. Performance depends on instruction sequences, memory behavior, processor implementation, and application requirements.
