1. Introduction

A delay is a period during which a microcontroller waits before performing the next operation or waits for a particular time interval between operations.

Delay generation is commonly used in embedded applications for timing control, signal generation, peripheral initialization and communication protocols.

Examples include:

  • Generating an LED blinking interval.
  • Waiting for LCD initialization.
  • Generating timing intervals for sensors.
  • Creating periodic control operations.
  • Providing required delays between hardware commands.
Definition: Delay generation is the process of creating a controlled time interval between two operations in an embedded system.

2. Why Are Delays Required?

Microcontrollers execute instructions at high speed. However, external peripherals and electronic devices may require specific timing intervals.

Delays allow the controller to coordinate its operations with the timing requirements of external hardware.

Application Purpose of Delay
LED control Control the interval between output changes.
LCD interfacing Allow the display controller to process commands.
Sensor interfacing Meet sensor-specific timing requirements.
Communication Maintain required timing between communication events.
Control systems Schedule periodic operations.

3. Types of Delay Generation Techniques

Embedded systems commonly use the following delay generation techniques.

Technique Description
Software delay Uses instruction execution and loops to consume time.
Hardware timer delay Uses a microcontroller timer peripheral to measure time.
Interrupt-based timing Uses timer interrupts to execute periodic tasks.
RTOS-based delay Uses operating-system scheduling and delay services.

4. Clock Frequency and Time Calculation

The clock frequency determines how frequently the processor or peripheral clock operates.

Frequency is measured in Hertz (Hz).

Frequency Meaning
1 Hz1 cycle per second
1 kHz1,000 cycles per second
1 MHz1,000,000 cycles per second
1 GHz1,000,000,000 cycles per second

Clock Period Formula

T = 1 / f

Where:

  • T = Clock period in seconds.
  • f = Clock frequency in Hertz.

Example

If the clock frequency is 60 MHz: 

T = 1 / 60,000,000

T = 16.67 nanoseconds approximately
The processor clock and peripheral clock are not necessarily the same. Delay calculations must use the clock that actually drives the relevant timer or peripheral.

5. Software Delay

A software delay is generated by executing a loop repeatedly for a specified number of iterations.

The processor spends time executing instructions inside the loop.

Example

void delay(void)
{
    unsigned int i;

    for (i = 0U; i < 100000U; i++)
    {
        /* Software delay */
    }
}

Each loop iteration consumes processor time. The total delay depends on the generated machine instructions and the processor execution timing.

Limitation: A software delay loop does not provide a reliable fixed time merely because a particular loop count is used. Compiler optimization, instruction timing, memory access and clock configuration affect it.

6. Software Delay Using a Nested Loop

A nested loop can increase the number of instructions executed and provide a longer approximate delay.

Program

void delay(void)
{
    volatile unsigned int i;
    volatile unsigned int j;

    for (i = 0U; i < 100U; i++)
    {
        for (j = 0U; j < 1000U; j++)
        {
            /* Wait */
        }
    }
}

The inner loop executes 1,000 times for each outer loop iteration.

The total number of inner-loop iterations is: 

100 x 1000 = 100,000 iterations
Declaring loop variables volatile helps prevent certain optimizations to their accesses, but it does not make the delay accurate or deterministic. Each volatile access also adds execution overhead.

7. Limitations of Software Delays

  • CPU time is consumed while the delay loop executes.
  • Delay duration depends on compiler optimization.
  • Changes in clock frequency affect execution time.
  • Different processor instructions take different amounts of time.
  • Interrupts may extend the total elapsed delay.
  • Software delays are unsuitable for many precise timing requirements.
Software delays are useful for simple demonstrations and approximate waits. Hardware timers are generally preferred for accurate and repeatable timing.

8. Hardware Timer-Based Delay

A hardware timer is a peripheral that counts clock events independently of the CPU instruction loop.

The timer can generate a match event when its counter reaches a programmed value.

A hardware timer can be used to generate:

  • Millisecond delays.
  • Microsecond delays, subject to timer resolution.
  • Periodic events.
  • Interrupt requests.
  • Event counting and time measurement.

Basic Timer Operation

Peripheral Clock
       |
       v
Prescaler (PR)
       |
       v
Timer Counter (TC)
       |
       v
Match Register (MR)
       |
       v
Match Event / Interrupt

The timer clock is divided by the prescaler before the timer counter is incremented.

9. Timer Delay Calculation

The LPC2129 timer prescaler determines how many peripheral clock cycles are required before the timer counter increments.

For the LPC2129 timer: 

Timer Counter Frequency = PCLK / (PR + 1)

Where:

  • PCLK = Peripheral clock frequency.
  • PR = Prescale Register value.

Example: Generate a 1 Millisecond Timer Tick

Assume:

  • PCLK = 15 MHz.
  • Required timer counter frequency = 1 kHz.
PR = (PCLK / Timer Frequency) - 1

PR = (15,000,000 / 1,000) - 1

PR = 15,000 - 1

PR = 14,999

The timer counter now increments once every millisecond.

Result: With PCLK = 15 MHz and PR = 14999, one timer counter increment represents approximately 1 millisecond.

10. Generating a 1 Second Delay Using a Timer

If the timer counter increments every millisecond, 1,000 timer increments represent approximately one second. 

Required Time = 1000 ms

Timer Tick = 1 ms

Required Counts = 1000

A match register can be programmed to generate an event after the required number of timer counts.

For a timer that starts from zero, a match at 1000 counter increments corresponds to MR0 = 1000. The precise reset and interrupt behavior depends on the match-control configuration.

12. LPC2129 Program: Timer-Based Delay

Objective

Generate a timer-based delay using Timer 0. The example configures a 1 millisecond timer counter tick and waits for 1,000 counts.

Program

#include <LPC21xx.h>

void Timer0_Delay_1ms(unsigned int delay_ms)
{
    /* Stop Timer 0 */
    T0TCR = 0x02U;

    /* Reset timer counter and prescale counter */
    T0TCR = 0x02U;

    /* PCLK = 15 MHz, PR = 14999 */
    T0PR = 14999U;

    /* Match after the requested number of milliseconds */
    T0MR0 = delay_ms;

    /* Reset TC and stop on match */
    T0MCR = (1U << 1) | (1U << 2);

    /* Clear pending match flag */
    T0IR = (1U << 0);

    /* Start Timer 0 */
    T0TCR = 0x01U;

    /* Wait for Match 0 */
    while ((T0IR & (1U << 0)) == 0U)
    {
    }

    /* Stop Timer 0 */
    T0TCR = 0x00U;

    /* Clear Match 0 interrupt flag */
    T0IR = (1U << 0);
}

int main(void)
{
    /* Configure P0.5 as GPIO */
    PINSEL0 &= ~(3U << 10);

    /* Configure P0.5 as output */
    IODIR0 |= (1U << 5);

    while (1)
    {
        /* Set P0.5 */
        IOSET0 = (1U << 5);

        /* Wait for approximately 1 second */
        Timer0_Delay_1ms(1000U);

        /* Clear P0.5 */
        IOCLR0 = (1U << 5);

        /* Wait for approximately 1 second */
        Timer0_Delay_1ms(1000U);
    }
}

Program Explanation

  1. Timer 0 is stopped and reset.
  2. T0PR is configured to 14999 for a 1 ms counter tick.
  3. T0MR0 is loaded with the requested delay in milliseconds.
  4. T0MCR enables reset and stop on Match 0.
  5. The timer is started.
  6. The program waits until the Match 0 flag is set.
  7. The timer is stopped and the interrupt flag is cleared.
This example assumes the LPC2129 peripheral clock is configured to 15 MHz and Timer 0 receives that PCLK. The timer's match flag is polled rather than using an interrupt. Verify the timer register definitions and clock configuration in the project before running. The example is intended for Keil uVision register-level simulation; external LED behavior is not demonstrated by the simulator.

13. Interrupt-Based Delay Generation

A timer interrupt can be used to generate periodic events without continuously checking the timer status flag in the main program.

When the timer reaches its match value, it generates an interrupt request. The CPU executes the associated interrupt service routine.

Basic Operation

Timer Counter
      |
      v
Match Condition
      |
      v
Interrupt Request
      |
      v
Interrupt Service Routine
      |
      v
Update Software Time Counter

Interrupt-based timing is useful when the main program must perform other work while the timer continues counting.

Timer interrupt configuration, VIC setup, interrupt acknowledgement and ISR implementation are covered in Chapter 12 – LPC2129 Interrupt and Exception Handling.

14. Software Delay vs Hardware Timer Delay

Software Delay Hardware Timer Delay
Uses CPU instruction loops. Uses a timer peripheral.
Consumes CPU time during the delay. Timer counts independently of the instruction loop.
Timing depends on generated instructions and optimization. Timing depends mainly on configured timer clock and registers.
Suitable for simple approximate waits. Suitable for more controlled timing intervals.
Usually simple to implement. Requires peripheral configuration.

15. Common Mistakes

  • Assuming a software loop produces an exact delay.
  • Using CCLK instead of PCLK in timer calculations.
  • Forgetting that the prescaler divides the peripheral clock.
  • Using an incorrect prescaler value.
  • Failing to reset the timer before starting a new delay.
  • Forgetting to clear a previous match flag.
  • Configuring an incorrect match-control action.
  • Assuming the simulator demonstrates physical output behavior.

16. Interview Questions and Answers

Q1. What is delay generation?

Delay generation creates a time interval between two operations in an embedded system.

Q2. What are the two common delay techniques?

Software delay and hardware timer-based delay.

Q3. What is a software delay?

A delay generated by executing instructions repeatedly in a loop.

Q4. What is the limitation of a software delay?

Its duration depends on instruction execution, compiler optimization, clock configuration and possible interrupt activity.

Q5. What is a hardware timer?

A peripheral that counts clock events and generates match events or interrupts.

Q6. What is PCLK?

PCLK is the peripheral clock supplied to microcontroller peripherals.

Q7. What is the function of the prescaler?

It divides the incoming peripheral clock before the timer counter increments.

Q8. Calculate PR for a 1 ms tick when PCLK is 15 MHz.

PR = (15,000,000 / 1,000) - 1 = 14,999.

Q9. What is the difference between polling and timer interrupts?

Polling repeatedly checks a condition in software. An interrupt notifies the CPU when the configured event occurs.

Q10. Why are hardware timers preferred for precise delays?

Their timing is based on a configured hardware clock and counter rather than an instruction loop.

19. Lesson Summary

  • Delays provide timing intervals between embedded operations.
  • Software delays use repeated instruction execution.
  • Software delays are affected by compiler optimization and execution timing.
  • Hardware timers count peripheral clock events.
  • The LPC2129 timer prescaler controls the counter tick rate.
  • Timer match registers can generate events at programmed counts.
  • Polling and interrupts are two ways to respond to timer events.
  • Hardware timers are generally preferred for controlled timing.
