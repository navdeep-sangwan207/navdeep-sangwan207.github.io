1. Introduction

Embedded systems often perform operations that depend on the current condition of the system, external inputs, timers or communication events.

A finite state machine (FSM) is a design model used to represent such behavior using a finite number of states and defined transitions.

For example, a traffic light controller changes between RED, GREEN and YELLOW states according to a timing sequence.

Definition: A finite state machine is a computational model that consists of a finite set of states, inputs, transitions and an initial state. It changes its current state according to defined conditions.

2. Why Are FSMs Used in Embedded Systems?

Many embedded applications have multiple operating modes. An FSM makes these modes and their transitions easier to design and implement.

Applications

  • Traffic light controllers.
  • Washing machine controllers.
  • Elevator control systems.
  • Motor control applications.
  • UART communication protocols.
  • Battery charging systems.
  • Industrial automation.
  • Sensor monitoring systems.
FSMs improve program organization by replacing complicated collections of nested conditions with clearly defined operating states.

3. Basic Components of a Finite State Machine

An FSM consists of the following components:

3.1 State

A state represents a particular operating condition of the system.

Example:

STATE_IDLE
STATE_RUNNING
STATE_STOPPED
STATE_ERROR

3.2 Input or Event

An input or event causes the FSM to evaluate whether a state transition should occur.

Examples:

  • Push button pressed.
  • Timer expired.
  • Sensor threshold crossed.
  • UART character received.
  • Fault condition detected.

3.3 Transition

A transition describes movement from one state to another when a specified condition is met.

3.4 Initial State

The initial state is the state in which the FSM begins operation.

3.5 Output

An output is an action performed by the system in response to its current state or an event.

The basic FSM model is: Current State + Input/Event → Next State

4. State Transition Diagram

A state transition diagram visually represents the states of an FSM and the conditions that cause transitions between them.

Example: Simple Motor Controller

              START command
        +-------------------------+
        |                         v
   +---------+              +-----------+
   |  IDLE   |              |  RUNNING  |
   +---------+              +-----------+
        ^                         |
        |                         |
        +-------------------------+
               STOP command

Explanation:

  • The system starts in the IDLE state.
  • A START command moves it to RUNNING.
  • A STOP command moves it back to IDLE.
In a state diagram, circles or rounded shapes represent states, while arrows represent transitions. Transition labels identify the events or conditions.

5. Types of Finite State Machines

5.1 Moore Machine

In a Moore machine, outputs depend only on the current state.

Example: A traffic light controller in which the light output is determined by the active traffic state.

Relationship:

Output = f(Current State)

5.2 Mealy Machine

In a Mealy machine, outputs depend on both the current state and the current input.

Relationship:

Output = f(Current State, Input)
Moore Machine Mealy Machine
Output depends on current state. Output depends on state and input.
Outputs are associated with states. Outputs are associated with transitions.
Output changes when the state changes. Output may change when the input changes.

6. FSM Implementation Approaches in Embedded C

An FSM can be implemented in Embedded C using different programming techniques.

6.1 switch-case Approach

A switch statement selects the action associated with the current state.

6.2 if-else Approach

Conditional statements determine the current state and evaluate transition conditions.

6.3 Function Pointer Approach

Each state can be associated with a separate function. A function pointer selects the function for the current state.

The switch-case approach is often a good starting point because it is straightforward and easy to debug.

7. Defining States Using enum

The C enumeration type enum can be used to define named states.

Example

typedef enum
{
    STATE_IDLE,
    STATE_RUNNING,
    STATE_STOPPED,
    STATE_ERROR
} SystemState;

A variable of type SystemState can store the current FSM state. 

SystemState current_state = STATE_IDLE;

Named states make the program more readable than using unexplained numeric values.

8. Implementing an FSM Using switch-case

Example: Motor Control FSM

Consider a motor controller with three states:

  • IDLE: Motor is not running.
  • RUNNING: Motor operation is enabled.
  • ERROR: A fault condition has been detected.

Program

#include <stdint.h>

typedef enum
{
    STATE_IDLE,
    STATE_RUNNING,
    STATE_ERROR
} MotorState;

MotorState current_state = STATE_IDLE;

uint8_t start_command = 0U;
uint8_t stop_command = 0U;
uint8_t fault_detected = 0U;

void Motor_On(void)
{
    /* Motor enable operation */
}

void Motor_Off(void)
{
    /* Motor disable operation */
}

void Motor_Fault_Action(void)
{
    /* Fault handling operation */
}

void Motor_FSM(void)
{
    switch (current_state)
    {
        case STATE_IDLE:

            Motor_Off();

            if (fault_detected)
            {
                current_state = STATE_ERROR;
            }
            else if (start_command)
            {
                current_state = STATE_RUNNING;
                start_command = 0U;
            }

            break;

        case STATE_RUNNING:

            Motor_On();

            if (fault_detected)
            {
                current_state = STATE_ERROR;
            }
            else if (stop_command)
            {
                current_state = STATE_IDLE;
                stop_command = 0U;
            }

            break;

        case STATE_ERROR:

            Motor_Off();
            Motor_Fault_Action();

            /* Remain in ERROR until reset logic is applied */

            break;

        default:

            Motor_Off();
            current_state = STATE_ERROR;

            break;
    }
}

int main(void)
{
    while (1)
    {
        Motor_FSM();
    }
}

Program Explanation

  1. The enum defines three motor states.
  2. The initial state is STATE_IDLE.
  3. The switch statement selects the active state.
  4. A start command moves the FSM to STATE_RUNNING.
  5. A stop command moves it back to STATE_IDLE.
  6. A fault condition moves the FSM to STATE_ERROR.
  7. The default case handles an unexpected state value.
This is a logical FSM example. The command variables are placeholders for actual inputs. A complete application must obtain commands from GPIO, communication interfaces or other event sources.

9. Traffic Light Controller Using FSM

A traffic light controller is a common example of an FSM-based embedded application.

States

  • RED
  • GREEN
  • YELLOW

State Transition Sequence

       +---------+
       |   RED   |
       +---------+
            |
       Timer Expired
            |
            v
       +---------+
       |  GREEN  |
       +---------+
            |
       Timer Expired
            |
            v
       +---------+
       | YELLOW  |
       +---------+
            |
       Timer Expired
            |
            +----------> RED

Program

typedef enum
{
    RED,
    GREEN,
    YELLOW
} TrafficState;

TrafficState traffic_state = RED;

unsigned int timer_expired = 0U;

void Set_Red_Light(void)
{
    /* Red light control */
}

void Set_Green_Light(void)
{
    /* Green light control */
}

void Set_Yellow_Light(void)
{
    /* Yellow light control */
}

void Traffic_FSM(void)
{
    switch (traffic_state)
    {
        case RED:

            Set_Red_Light();

            if (timer_expired)
            {
                timer_expired = 0U;
                traffic_state = GREEN;
            }

            break;

        case GREEN:

            Set_Green_Light();

            if (timer_expired)
            {
                timer_expired = 0U;
                traffic_state = YELLOW;
            }

            break;

        case YELLOW:

            Set_Yellow_Light();

            if (timer_expired)
            {
                timer_expired = 0U;
                traffic_state = RED;
            }

            break;

        default:

            traffic_state = RED;

            break;
    }
}
In a real traffic controller, a hardware timer or RTOS timing service should generate the time-based events. The application should also define safe startup and fault behavior.

10. Event-Driven FSM

An event-driven FSM changes state in response to events rather than relying only on continuously checking conditions.

Common events include:

  • BUTTON_PRESSED
  • TIMER_EXPIRED
  • UART_DATA_RECEIVED
  • ADC_CONVERSION_COMPLETE
  • FAULT_DETECTED

Example Event Definition

typedef enum
{
    EVENT_NONE,
    EVENT_START,
    EVENT_STOP,
    EVENT_FAULT
} SystemEvent;

Event-Based Transition Example

void Process_Event(SystemEvent event)
{
    switch (current_state)
    {
        case STATE_IDLE:

            if (event == EVENT_START)
            {
                current_state = STATE_RUNNING;
            }
            else if (event == EVENT_FAULT)
            {
                current_state = STATE_ERROR;
            }

            break;

        case STATE_RUNNING:

            if (event == EVENT_STOP)
            {
                current_state = STATE_IDLE;
            }
            else if (event == EVENT_FAULT)
            {
                current_state = STATE_ERROR;
            }

            break;

        case STATE_ERROR:

            /* Wait for defined recovery procedure */

            break;

        default:

            current_state = STATE_ERROR;

            break;
    }
}
This function illustrates transition logic. In a complete system, the event source, event queue or event flag mechanism must also be designed to avoid losing important events.

11. FSM Using Function Pointers

In some applications, each state is implemented as a separate function. A function pointer can select which state function executes.

Example

#include <stdint.h>

void Idle_State(void);
void Running_State(void);
void Error_State(void);

void (*current_state_function)(void) = Idle_State;

void Idle_State(void)
{
    /* Perform idle operations */

    /* Example transition */
    current_state_function = Running_State;
}

void Running_State(void)
{
    /* Perform running operations */
}

void Error_State(void)
{
    /* Perform fault operations */
}

int main(void)
{
    while (1)
    {
        current_state_function();
    }
}

The function pointer stores the address of the function representing the active state.

The example demonstrates function-pointer-based state selection. The transition shown from IDLE to RUNNING is unconditional and would need to be replaced by an actual event or condition in a practical application.

12. Practical LPC2129 FSM Example

Objective

Implement a simple LED controller FSM using LPC2129 GPIO register operations.

Hardware Configuration

  • Microcontroller: LPC2129.
  • GPIO pin: P0.5.
  • Output: LED control signal.
  • Development environment: Keil uVision simulator.

States

State Action
STATE_OFF Clear P0.5 output latch.
STATE_ON Set P0.5 output latch.

Complete Program

#include <LPC21xx.h>

typedef enum
{
    STATE_OFF,
    STATE_ON
} LED_State;

LED_State current_state = STATE_OFF;

#define LED_PIN  5U
#define LED_MASK (1U << LED_PIN)

void GPIO_Init(void)
{
    /* Select GPIO function for P0.5 */
    PINSEL0 &= ~(3U << 10);

    /* Configure P0.5 as output */
    IODIR0 |= LED_MASK;

    /* Start with output LOW */
    IOCLR0 = LED_MASK;
}

void LED_FSM(void)
{
    switch (current_state)
    {
        case STATE_OFF:

            IOCLR0 = LED_MASK;

            current_state = STATE_ON;

            break;

        case STATE_ON:

            IOSET0 = LED_MASK;

            current_state = STATE_OFF;

            break;

        default:

            IOCLR0 = LED_MASK;
            current_state = STATE_OFF;

            break;
    }
}

void Delay(void)
{
    volatile unsigned int i;

    for (i = 0U; i < 100000U; i++)
    {
        /* Approximate software delay */
    }
}

int main(void)
{
    GPIO_Init();

    while (1)
    {
        LED_FSM();

        Delay();
    }
}

Program Explanation

  1. The enum defines OFF and ON states.
  2. The initial state is STATE_OFF.
  3. GPIO_Init() configures P0.5 as GPIO output.
  4. LED_FSM() executes the action for the current state.
  5. The state changes after each execution.
  6. Delay() slows down the repeated state changes.
Expected register-level behavior: The program alternates between setting and clearing the P0.5 output latch. In Keil uVision, inspect IOSET0, IOCLR0 and IODIR0 to observe register-level operations.
This is a demonstration FSM. In a production application, transitions should normally depend on actual events or timing conditions. The software delay is approximate and does not establish a precise LED blinking frequency. Physical LED behavior is not tested in the simulator.

13. FSM Design Best Practices

  • Define all possible states clearly.
  • Use meaningful state names.
  • Define valid transitions for every state.
  • Include a default or fault-handling path.
  • Keep state actions short and understandable.
  • Avoid long blocking delays inside state handlers.
  • Separate event detection from transition processing.
  • Use hardware timers for accurate time-based transitions.
  • Define safe outputs for fault conditions.
  • Test normal, boundary and unexpected event sequences.

14. Common FSM Implementation Mistakes

  • Forgetting to initialize the starting state.
  • Missing a transition condition.
  • Using unexplained numeric state values.
  • Failing to handle unexpected state values.
  • Allowing a blocking delay to prevent event processing.
  • Performing lengthy operations inside an ISR.
  • Ignoring simultaneous or repeated events.
  • Not defining safe behavior during a fault.

15. Interview Questions and Answers

Q1. What is a finite state machine?

An FSM is a behavioral model containing a finite number of states and transitions controlled by inputs or events.

Q2. What are the main components of an FSM?

States, inputs or events, transitions, initial state and outputs.

Q3. What is a state transition?

It is the movement from one state to another when a defined condition is satisfied.

Q4. What is the difference between Moore and Mealy machines?

Moore outputs depend only on the current state, while Mealy outputs depend on the current state and input.

Q5. Why is enum used in FSM implementation?

It provides meaningful names for states and improves code readability.

Q6. Which C statement is commonly used to implement an FSM?

The switch-case statement is commonly used to select actions based on the current state.

Q7. What is an event-driven FSM?

It is an FSM that changes state in response to events such as button presses, timer expiration or received communication data.

Q8. Why should blocking delays be avoided in complex FSMs?

Blocking delays can prevent the application from processing other events or performing time-critical tasks.

Q9. What is a default state case used for?

It handles unexpected state values and provides a defined recovery or safe response.

Q10. Where are FSMs used in embedded systems?

They are used in motor controllers, traffic systems, communication protocols, industrial automation and appliance controllers.
