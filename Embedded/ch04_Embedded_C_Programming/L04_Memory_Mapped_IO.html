1. Introduction

Memory-Mapped Input/Output (MMIO) is a technique used by microcontrollers and processors to access hardware peripherals through specific addresses in the processor's address space.

In this method, peripheral control and data registers are assigned addresses. The CPU accesses these addresses using normal memory read and write instructions.

For example, a GPIO output register may be assigned a particular address. Writing a value to that address changes the output state of selected GPIO pins.

Definition: Memory-Mapped I/O is a hardware interfacing technique in which peripheral registers are assigned addresses within the processor's memory address space so that software can access them using memory read and write operations.

2. Why Is Memory-Mapped I/O Required?

A microcontroller contains several peripheral modules that must be configured and controlled by software.

These modules include GPIO, timers, UART, SPI, I2C, ADC and interrupt controllers.

MMIO provides a consistent way for the CPU to communicate with these peripherals through their assigned registers.

Applications

  • Configuring GPIO pins.
  • Starting and stopping timers.
  • Transmitting and receiving UART data.
  • Starting ADC conversions.
  • Configuring interrupt controllers.
  • Controlling communication peripherals.

4. How Memory-Mapped I/O Works

The CPU accesses a peripheral register by performing a memory read or write operation at its assigned address.

Write Operation

  1. The program specifies a peripheral register address.
  2. The CPU generates the corresponding address.
  3. The processor bus interface performs a write transaction.
  4. The peripheral receives the data.
  5. The peripheral register changes according to its defined behavior.

  1. The program requests a peripheral register value.
  2. The CPU generates the register address.

  4. The processor receives the data.

5. Memory-Mapped I/O Address Space

Every memory-mapped peripheral register has an address defined by the microcontroller architecture.

A processor uses its address bus and data interface to select the required location and transfer information.

Addressing Example

Consider a hypothetical peripheral register assigned the address 0x40000000.

The actual addresses of LPC2129 peripheral registers must be taken from the official user manual.

6. Memory-Mapped I/O vs Isolated I/O

Processors can use different methods to access peripheral devices. Two commonly discussed approaches are Memory-Mapped I/O and Isolated I/O.

Parameter Memory-Mapped I/O Isolated I/O
Address Space Uses the memory address space. Uses a separate I/O address space.
Instructions Uses normal memory access instructions. May use special I/O instructions.
Addressing Peripheral registers have memory addresses. Peripheral registers have I/O port addresses.
Programming Can be accessed using memory load/store operations. Requires architecture-specific I/O access mechanisms.
Typical Example Many ARM-based microcontrollers. x86 isolated I/O ports.
LPC2129, based on ARM7TDMI, uses memory-mapped peripheral registers.

7. Accessing Memory-Mapped Registers in Embedded C

Embedded C programs commonly access MMIO registers through device header files. 

#include <LPC21xx.h>

The header file provides symbolic register names. The compiler uses their definitions to generate the required target-specific memory access instructions.

Example: GPIO Register Access

#include <LPC21xx.h>

int main(void)
{
    /* Configure P0.10 as GPIO */
    PINSEL0 &= ~(3U << 20);

    /* Configure P0.10 as output */
    IODIR0 |= (1U << 10);

    /* Set output HIGH */
    IOSET0 = (1U << 10);

    while (1)
    {
    }
}

Here, PINSEL0, IODIR0 and IOSET0 are symbolic names for memory-mapped peripheral registers.

8. Direct Register Access Using Pointers

Memory-mapped registers can also be accessed through pointers to volatile objects.

A pointer can hold the address of a hardware register. Dereferencing the pointer allows the program to read or write that register.

Conceptual Example

#include <stdint.h>

#define CONTROL_REG_ADDRESS 0x40000000UL

#define CONTROL_REG \
    (*(volatile uint32_t *)CONTROL_REG_ADDRESS)

int main(void)
{
    CONTROL_REG = 0x00000001U;

    while (1)
    {
    }
}

Explanation

  • uint32_t represents an unsigned 32-bit integer type.
  • volatile indicates that accesses must be treated as observable volatile accesses by the compiler.
  • The pointer represents the register's address.
  • The dereference operator accesses the object at that address.
  • The assignment writes a value to the register.
Important: This example uses a hypothetical address and is not intended to run on the LPC2129. An incorrect register address can cause unpredictable behavior or a processor fault.

9. Role of the Volatile Keyword in MMIO

Hardware registers can change independently of normal program execution.

For example, a timer may update a counter register or a UART peripheral may update a status register.

The volatile type qualifier tells the compiler that accesses to the qualified object are externally observable and must not be removed or treated as ordinary cached program values.

Conceptual Example

volatile unsigned int *status_reg;

while ((*status_reg & 1U) == 0U)
{
    /* Wait until status bit becomes 1 */
}

The compiler must preserve the volatile reads required by this polling loop.

Important distinction: Volatile does not make an operation atomic, synchronize multiple tasks or guarantee memory ordering for all concurrency requirements. Those concerns require appropriate architecture- and platform-specific mechanisms.

The volatile keyword is explained in detail in Lesson 06 of this chapter.

10. Practical Example: LPC2129 GPIO Using MMIO

Objective

To use the LPC2129 memory-mapped GPIO registers to configure P0.5 as an output and set its output latch HIGH.

Program

#include <LPC21xx.h>

int main(void)
{
    /* Select GPIO function for P0.5 */
    PINSEL0 &= ~(3U << 10);

    /* Configure P0.5 as output */
    IODIR0 |= (1U << 5);

    /* Set P0.5 HIGH */
    IOSET0 = (1U << 5);

    while (1)
    {
        /* Continuous execution */
    }
}

Program Explanation

Statement Purpose
PINSEL0 Selects the GPIO function for P0.5.
IODIR0 Configures P0.5 as an output.
IOSET0 Sets the P0.5 output latch HIGH.
while(1) Keeps the program executing continuously.

Expected Result

  • P0.5 is configured as GPIO.
  • IODIR0 bit 5 is set to 1.
  • IOSET0 is written with bit 5 set.
  • The output latch is configured HIGH.

In Keil uVision, inspect the relevant registers using the debugger. This confirms register-level operations only; it does not verify an external LED's electrical behavior.

11. Advantages of Memory-Mapped I/O

  • Provides a consistent register-access mechanism.
  • Uses normal memory read and write instructions.
  • Allows direct control of peripheral hardware.
  • Supports efficient hardware interfacing.
  • Works naturally with C pointers and device headers.
  • Supports peripheral configuration and status monitoring.

12. Limitations and Precautions

  • Peripheral addresses are hardware-specific.
  • Incorrect addresses can cause faults or unintended behavior.
  • Register access may have special read/write semantics.
  • Some peripherals require clock and pin configuration before use.
  • Access width and alignment must follow hardware requirements.
  • Concurrent access to registers may require synchronization.
  • Volatile alone does not guarantee atomic operations.

13. Interview Questions and Answers

Q1. What is Memory-Mapped I/O?

Memory-Mapped I/O is a technique in which peripheral registers are assigned addresses in the processor's memory address space.

Q2. Why is MMIO used in embedded systems?

It allows the CPU to configure and control hardware peripherals using memory read and write operations.

Q3. What is a peripheral register address?

It is the address assigned to a particular hardware register in the processor's address space.

Q4. What is the difference between MMIO and isolated I/O?

MMIO uses the memory address space, while isolated I/O uses a separate I/O address space.

Q5. How does the CPU write to an MMIO register?

It generates the register address and performs a bus write transaction containing the data.

Q6. Why is volatile used with hardware registers?

It ensures that accesses to volatile objects are treated as observable operations rather than ordinary values that can be eliminated or reused by the compiler.

Q7. Can hardware registers be accessed using pointers?

Yes. A correctly typed pointer to a valid memory-mapped register can be used to read or write it.

Q8. Does volatile guarantee atomic access?

No. Volatile does not guarantee atomicity. Atomic access depends on the processor, data width and synchronization requirements.

Q9. Does LPC2129 use memory-mapped peripheral registers?

Yes. LPC2129 peripheral registers are mapped into its processor address space.

Q10. Where can the actual LPC2129 register addresses be found?

In the LPC2129 user manual and its memory-map and register-description sections.
