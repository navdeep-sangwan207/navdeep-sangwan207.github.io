1. Introduction

An Embedded C program is firmware developed to control the operation of an embedded system. It interacts with microcontroller hardware, peripherals, sensors and external devices.

Unlike a simple desktop application, embedded firmware commonly includes hardware initialization, peripheral configuration, event handling and continuous application execution.

A typical Embedded C project contains:

  • Header files and macro definitions.
  • Startup and system initialization code.
  • Peripheral initialization functions.
  • Hardware driver functions.
  • Application logic.
  • Main program loop.
  • Interrupt service routines.
Definition: Embedded C program structure refers to the organization of firmware into initialization, hardware drivers, application functions, event handling and the main execution flow.

Basic Example

#include <LPC21xx.h>

/* Function prototype */
void GPIO_Init(void);

int main(void)
{
    GPIO_Init();

    while (1)
    {
        /* Main application */
    }
}

void GPIO_Init(void)
{
    /* Select GPIO function for P0.5 */
    PINSEL0 &= ~(3U << 10);

    /* Configure P0.5 as output */
    IODIR0 |= (1U << 5);
}

This example initializes one GPIO pin and then enters an infinite application loop.

3. Header Files

Header files provide declarations, macros, data types and hardware register definitions required by the firmware.

For an LPC2129 project, the device-specific header file provides access to peripheral registers. 

#include <LPC21xx.h>

Common Header File Contents

  • Register definitions.
  • Function declarations.
  • Constant definitions.
  • Macro definitions.
  • Shared data structures.
The exact header filename and availability depend on the installed device support package and project configuration. Use the header supplied for the selected microcontroller.

4. Macro Definitions and Configuration Constants

Macros and named constants make firmware easier to maintain and reduce repeated numeric values.

Example

#include <LPC21xx.h>

#define LED_PIN       5U
#define LED_MASK      (1U << LED_PIN)

#define PCLK_HZ       15000000UL
#define TIMER_PR      14999U

These definitions represent the LED pin, its bit mask, peripheral clock frequency and timer prescaler value.

Named constants make hardware configuration easier to understand and update.

5. Global Variables and Shared Data

Global variables can be used to share information between different functions and, when properly designed, between interrupt handlers and the main application.

Example

volatile unsigned int timer_event = 0U;
unsigned int system_status = 0U;

The variable timer_event may be modified by an ISR and read by the main program. The volatile qualifier tells the compiler that accesses to this object must respect its externally observable changes.

Volatile does not guarantee atomic access, mutual exclusion or safe synchronization. Shared data may require additional protection.

6. Function Prototypes

Function prototypes declare the functions that will be defined and used in the program.

Example

void System_Init(void);
void GPIO_Init(void);
void UART0_Init(void);
void Timer0_Init(void);
void Application_Task(void);

These declarations describe the functions responsible for initializing the system and executing application tasks.

7. System Initialization

System initialization prepares the microcontroller before the main application begins.

Typical initialization operations include:

  • Clock and PLL configuration.
  • Peripheral clock configuration.
  • GPIO initialization.
  • UART configuration.
  • Timer initialization.
  • Interrupt controller configuration.
  • Communication peripheral initialization.

Example

void System_Init(void)
{
    /* Configure system clock */
    /* Configure peripheral clock */
    /* Initialize GPIO */
    /* Initialize required peripherals */
    /* Configure interrupts if required */
}
Initialization functions should execute before the application uses the corresponding peripherals. The exact order depends on hardware dependencies.

8. Peripheral Initialization

Each peripheral should be configured according to the requirements of the application.

Peripheral Typical Configuration
GPIO Pin function and input/output direction.
UART Pin selection, baud rate and frame format.
Timer Clock, prescaler and match configuration.
ADC Channel, clock and conversion settings.
I2C Pin selection, clock and communication mode.
SPI Pin configuration, clock polarity and phase.

Separate initialization functions help keep peripheral-specific configuration organized.

9. Main Function

The main function is the entry point of the C application after the runtime startup process has transferred control to it.

In a typical bare-metal embedded application, main performs initialization and then enters an infinite loop.

Example

int main(void)
{
    System_Init();

    while (1)
    {
        Application_Task();
    }
}

The infinite loop allows the microcontroller to continue performing its application tasks as long as the system is running.

10. Infinite Loop in Embedded Systems

Many embedded systems are designed to operate continuously. Their main application therefore commonly executes inside an infinite loop.

Example

while (1)
{
    Read_Sensor();
    Process_Data();
    Update_Output();
}

Why Use an Infinite Loop?

  • Continuously monitor system conditions.
  • Process input data.
  • Update output devices.
  • Handle application events.
  • Maintain continuous control operations.
An infinite loop does not necessarily mean the processor is always busy. The application can use sleep modes, interrupts or an RTOS scheduler when appropriate.

11. Application Functions

Application functions implement the actual functionality required by the embedded product.

Examples include:

  • Reading sensor measurements.
  • Processing temperature data.
  • Controlling a motor.
  • Updating an LCD.
  • Sending data through UART.
  • Monitoring system status.

Example

void Application_Task(void)
{
    /* Read input data */
    /* Process application conditions */
    /* Update output devices */
    /* Handle pending events */
}

12. Interrupt Service Routines in Program Structure

An interrupt service routine handles an interrupt generated by a configured hardware or software interrupt source.

The ISR is associated with the interrupt vector and controller configuration. It is not simply an ordinary function called by the main loop.

Typical ISR Responsibilities

  • Identify or acknowledge the interrupt source.
  • Capture essential event information.
  • Update a small shared state or event flag.
  • Return from the interrupt efficiently.
volatile unsigned int event_flag = 0U;

/* Conceptual interrupt handler */
void Peripheral_ISR(void)
{
    /* Capture event */
    event_flag = 1U;

    /* Perform required peripheral acknowledgement */
}
This is a conceptual example. A real LPC2129 ISR also requires the correct interrupt vector, VIC configuration and peripheral-specific acknowledgement sequence.

14. Complete Example: Structured LPC2129 Program

Objective

Create a simple structured LPC2129 firmware project that initializes GPIO and repeatedly changes the state of P0.5.

Program

#include <LPC21xx.h>

/* Hardware configuration */
#define LED_PIN       5U
#define LED_MASK      (1U << LED_PIN)

/* Function declarations */
void System_Init(void);
void GPIO_Init(void);
void LED_On(void);
void LED_Off(void);
void Delay(void);

/* Main application */
int main(void)
{
    System_Init();

    while (1)
    {
        LED_On();

        Delay();

        LED_Off();

        Delay();
    }
}

/* System initialization */
void System_Init(void)
{
    GPIO_Init();
}

/* GPIO initialization */
void GPIO_Init(void)
{
    /* Select GPIO function for P0.5 */
    PINSEL0 &= ~(3U << 10);

    /* Configure P0.5 as output */
    IODIR0 |= LED_MASK;

    /* Initialize output to LOW */
    IOCLR0 = LED_MASK;
}

/* Turn output ON */
void LED_On(void)
{
    IOSET0 = LED_MASK;
}

/* Turn output OFF */
void LED_Off(void)
{
    IOCLR0 = LED_MASK;
}

/* Approximate software delay */
void Delay(void)
{
    volatile unsigned int i;

    for (i = 0U; i < 100000U; i++)
    {
        /* Wait */
    }
}

Program Explanation

  1. The LPC2129 device header is included.
  2. The LED pin and bit mask are defined.
  3. Function prototypes are declared.
  4. System_Init() calls GPIO_Init().
  5. GPIO_Init() selects GPIO mode and output direction.
  6. LED_On() sets the output latch.
  7. LED_Off() clears the output latch.
  8. The main loop repeatedly calls the output and delay functions.
Expected register-level behavior: In the Keil uVision simulator, inspect PINSEL0, IODIR0, IOSET0 and IOCLR0 to observe the configuration and output-latch operations.
The software delay is approximate and compiler-dependent. This example does not demonstrate physical LED illumination. It is intended for register-level firmware practice.

16. Common Mistakes

  • Writing all firmware functionality inside main().
  • Starting the application before required peripherals are initialized.
  • Using incorrect device header files.
  • Repeating register configuration throughout the application.
  • Writing lengthy operations inside interrupt service routines.
  • Using global variables without a clear ownership strategy.
  • Assuming startup code and main() are the same operation.
  • Using an approximate software delay when accurate timing is required.

17. Interview Questions and Answers

Q1. What is Embedded C firmware?

Firmware is software designed to control the operation of embedded hardware.

Q2. What is the purpose of a header file?

It provides declarations, macros, constants and other definitions shared by source files.

Q3. What is system initialization?

It is the process of configuring the processor, clocks, GPIO and required peripherals before application execution.

Q4. Why is an infinite loop commonly used?

It allows the embedded application to continue monitoring inputs and performing control tasks.

Q5. What is startup code?

Startup code prepares the processor and runtime environment before transferring control to main().

Q6. What is the purpose of a peripheral driver?

It provides an interface for configuring and controlling a hardware peripheral.

Q7. Why divide firmware into functions?

Functions improve readability, reuse, testing and maintainability.

Q8. What is an ISR?

It is a routine executed to handle a configured interrupt request.

Q9. What is modular firmware?

It is firmware organized into separate modules responsible for specific functionality.

Q10. What executes before main()?

The processor startup and runtime initialization sequence, as configured by the toolchain.

18. Multiple Choice Questions (MCQs)

1. What is the entry point of a typical C application?
  1. GPIO_Init()
  2. main()
  3. System_Init()
  4. ISR()

Answer: B – main().

2. Which code executes before main()?
  1. Application task only
  2. Startup and runtime initialization
  3. Only GPIO code
  4. Only UART code

Answer: B – Startup and runtime initialization.

3. What is the purpose of System_Init()?
  1. Configure system resources
  2. Delete firmware
  3. Generate source files
  4. Stop the processor permanently

Answer: A – Configure system resources.

4. Which structure is commonly used for continuous embedded operation?
  1. Single conditional statement
  2. Infinite loop
  3. One-time function call
  4. Preprocessor directive

Answer: B – Infinite loop.

5. Which file commonly contains function declarations?
  1. .h
  2. .obj
  3. .hex
  4. .map

Answer: A – Header file (.h).

6. What is the role of a peripheral driver?
  1. Control a hardware peripheral
  2. Design a PCB automatically
  3. Replace the processor
  4. Generate a clock crystal

Answer: A – Control a hardware peripheral.

7. What improves firmware maintainability?
  1. Duplicating code
  2. Putting everything in one function
  3. Modular organization
  4. Removing all comments

Answer: C – Modular organization.

8. Which routine handles an interrupt?
  1. Application loop
  2. ISR
  3. Header file
  4. Linker script

Answer: B – ISR.

20. Lesson Summary

  • Embedded C programs are firmware designed for embedded hardware.
  • Header files provide declarations and hardware definitions.
  • Initialization configures the processor and peripherals.
  • Startup code prepares the runtime environment before main().
  • The main function commonly contains an infinite application loop.
  • Application functions implement product-specific behavior.
  • Interrupt service routines handle configured interrupt events.
  • Modular organization improves maintainability and reuse.
