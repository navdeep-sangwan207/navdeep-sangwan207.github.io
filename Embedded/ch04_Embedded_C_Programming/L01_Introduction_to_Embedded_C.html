Chapter 04 – Embedded C Programming

Embedded Systems – Complete Study Course

1. Introduction

Embedded C is a programming approach used to develop software for embedded systems. It is based on the C programming language and is widely used to write firmware for microcontrollers and embedded processors.

Unlike an ordinary desktop application, embedded software frequently interacts directly with hardware components such as GPIO pins, timers, UART modules, ADCs, memory controllers and communication peripherals.

Embedded C allows developers to control these hardware resources through memory locations, special function registers and processor-specific features.

Definition: Embedded C is the use of the C language, together with microcontroller-specific headers, registers, compiler features and hardware interfaces, to develop firmware for embedded systems.

2. What Is Firmware?

Firmware is software stored in non-volatile memory, such as Flash memory, that controls the operation of an electronic device.

It initializes hardware, reads inputs, processes data, controls outputs and manages peripheral devices.

Examples of Firmware

  • Washing machine control software.
  • Automotive engine control firmware.
  • Industrial motor control firmware.
  • Digital thermometer software.
  • Router and communication device firmware.
  • Microcontroller-based monitoring systems.

3. Why Is Embedded C Used?

Embedded C is widely used because it provides efficient control over hardware while supporting structured programming and code reuse.

Feature Explanation
Hardware Access Allows access to microcontroller registers and peripheral modules.
Memory Efficiency Supports development of programs for memory-constrained devices.
Execution Efficiency Can produce efficient machine code when used with a suitable compiler.
Portability Application logic can often be reused across compatible platforms with appropriate changes.
Peripheral Control Supports programming of GPIO, timers, UART, ADC and other peripherals.
Code Reusability Supports functions, modules and reusable device drivers.

Typical Microcontroller Resources

  • CPU: Executes program instructions.
  • Flash: Stores firmware.
  • RAM: Stores variables and temporary data.
  • GPIO: Interfaces with digital input and output devices.
  • Timers: Generate timing events and measure intervals.
  • UART: Supports asynchronous serial communication.
  • ADC: Converts analog input signals into digital values.

6. Embedded C Development Workflow

A typical firmware development process follows these steps:

  1. Identify the application requirements.
  2. Select the target microcontroller.
  3. Configure the development environment.
  4. Create the Embedded C source files.
  5. Include the required device header files.
  6. Configure clocks, pins and peripheral registers.
  7. Compile and link the source code.
  8. Check and resolve build errors.
  9. Debug or simulate program execution.
  10. Program the target hardware when available.
  11. Test and validate the firmware.
Development sequence: Requirements → Hardware Selection → Coding → Build → Debugging → Programming → Testing.

7. Introduction to Hardware Register Programming

A microcontroller contains special function registers (SFRs) or peripheral registers that control its internal hardware.

Embedded C programs access these registers to configure and operate hardware peripherals.

Example: GPIO Configuration

On the LPC2129, GPIO Port 0 includes registers such as:

Register Purpose
PINSEL0 / PINSEL1 Select pin functions, including GPIO or alternate peripheral functions.
IODIR0 Configures Port 0 pins as inputs or outputs.
IOPIN0 Reads or accesses the Port 0 pin state.
IOSET0 Sets selected Port 0 output bits to logic HIGH.
IOCLR0 Clears selected Port 0 output bits to logic LOW.

These registers will be studied in greater detail in the upcoming lessons on hardware register programming, memory-mapped I/O and bit manipulation.

8. Practical Example: LPC2129 GPIO Output

Objective

To configure P0.10 as a GPIO output and set its output register bit using Embedded C.

Hardware / Software Requirements

  • Keil uVision IDE.
  • LPC2129 device support and header file.
  • Embedded C compiler for ARM7TDMI.
  • LPC2129 simulator/debug configuration.

Program

#include <LPC21xx.h>

int main(void)
{
    /* Configure P0.10 as GPIO */
    PINSEL0 &= ~(3U << 20);

    /* Configure P0.10 as output */
    IODIR0 |= (1U << 10);

    /* Set P0.10 output HIGH */
    IOSET0 = (1U << 10);

    while (1)
    {
        /* Main application loop */
    }
}

Program Explanation

Statement Explanation
#include <LPC21xx.h> Includes device-specific register definitions.
PINSEL0 &= ~(3U << 20); Selects GPIO function for P0.10 by clearing its two PINSEL0 function-selection bits.
IODIR0 |= (1U << 10); Configures P0.10 as an output.
IOSET0 = (1U << 10); Sets the P0.10 output bit HIGH.
while (1) Keeps the application running continuously.

Expected Result

Expected register-level result:
  • P0.10 is configured for GPIO operation.
  • IODIR0 bit 10 is set to 1.
  • The output latch for P0.10 is set HIGH.
  • The program remains in the infinite loop.
Simulator limitation: In Keil uVision, verify the relevant register values through the debugger. This does not prove that a physical LED lights up. Actual electrical output requires a correctly configured physical target board and external circuit.

Important: The example assumes the device header defines the LPC2129 GPIO registers with the standard names shown. Confirm the selected device and header file in the Keil project.

9. Applications of Embedded C

  • Automotive: Engine control units, airbags and dashboard systems.
  • Industrial Automation: Motor controllers, sensors and process monitoring.
  • Consumer Electronics: Washing machines, microwave ovens and smart appliances.
  • Medical Devices: Patient monitoring and measurement equipment.
  • Communication: Routers, modems and communication controllers.
  • IoT: Smart sensors and connected embedded devices.

10. Common Mistakes in Embedded C Development

  1. Incorrect pin configuration: A pin may be assigned to an alternate peripheral function instead of GPIO.
  2. Incorrect register access: Writing an incorrect bit mask can affect unintended pins.
  3. Ignoring hardware documentation: Register behavior and pin functions must be checked in the microcontroller datasheet and user manual.
  4. Incorrect clock configuration: Peripheral timing may be wrong if the clock settings are not configured correctly.
  5. Assuming simulation equals hardware: A simulator may not model all external devices and electrical behavior.
  6. Ignoring compiler warnings: Warnings may indicate incorrect assumptions or potential firmware defects.

11. Interview Questions and Answers

Q1. What is Embedded C?

Embedded C is the use of C programming techniques and microcontroller-specific features to develop firmware for embedded systems.

Q2. What is firmware?

Firmware is software stored in non-volatile memory that controls the operation of an electronic device.

Q3. Why is C widely used in embedded systems?

C provides efficient code generation, hardware access, low-level programming capabilities and good control over memory usage.

Q4. What is a hardware register?

A hardware register is a storage location used by a processor or peripheral to control operations, store status or exchange data.

Q5. What is a cross-compiler?

A cross-compiler runs on one computer platform but generates executable code for a different target processor or platform.

Q6. What is the role of a linker?

A linker combines object files and libraries, resolves symbol references and produces the firmware image.

Q7. What is the difference between RAM and Flash?

RAM is volatile memory used for runtime data. Flash is non-volatile memory commonly used to store firmware and persistent data.

Q8. What is GPIO?

General Purpose Input/Output is a configurable digital interface used to read external signals or control external devices.

Q9. What is Keil uVision?

Keil uVision is an integrated development environment used to develop, build and debug embedded applications for supported microcontroller families.

Q10. What is the difference between a compiler and an assembler?

A compiler translates a high-level language such as C into lower-level code. An assembler translates assembly language instructions into machine-code object files.
