Lecture 11: Wild, Dangling and Uninitialized Pointers

Understand invalid pointer states, memory lifetime errors, use-after-free, invalid accesses and safe pointer management.

1. Learning Objectives

  • Understand wild and uninitialized pointers.
  • Understand dangling pointers.
  • Identify invalid memory access conditions.
  • Understand use-after-free and use-after-return errors.
  • Differentiate NULL pointers from invalid pointers.
  • Learn safe memory allocation and deallocation practices.
  • Understand pointer lifetime and object lifetime.
  • Use compiler warnings and sanitizers to detect pointer errors.
  • Apply pointer safety practices in embedded C and systems programming.

2. What Is an Uninitialized Pointer?

An uninitialized pointer is a pointer variable that has not been assigned a valid value before it is used.

A pointer with automatic storage duration that is not explicitly initialized has an indeterminate value. Dereferencing it is invalid and can cause undefined behavior.

Incorrect Example

#include <stdio.h>

int main(void)
{
    int *ptr;

    *ptr = 100;

    printf("%d\n", *ptr);

    return 0;
}
This program has undefined behavior because ptr has not been initialized. It does not point to a known valid integer object. Do not execute this example as a test.

Correct Example

#include <stdio.h>

int main(void)
{
    int value = 100;

    int *ptr = &value;

    printf("%d\n", *ptr);

    return 0;
}
Expected Output: 
100

3. What Is a Wild Pointer?

A wild pointer is an informal term for a pointer that contains an indeterminate or otherwise invalid address and is used as though it points to a valid object.

An uninitialized automatic pointer is a common example of a wild pointer.

Example of a Safe Initialization

#include <stdio.h>

int main(void)
{
    int *ptr = NULL;

    if (ptr == NULL)
    {
        printf("Pointer is not assigned\n");
    }

    return 0;
}
Expected Output: 
Pointer is not assigned

Initializing a pointer to NULL provides a known state that can be checked before use.

NULL does not point to a valid object. It is a useful value for representing the absence of an object address.

4. What Is a Dangling Pointer?

A dangling pointer is a pointer that refers to an object whose lifetime has ended or whose storage is no longer valid for that access.

The pointer may still contain an old address, but that address must not be used to access the former object.

Common Causes

  • Accessing dynamically allocated memory after free().
  • Returning the address of a local automatic variable.
  • Retaining a pointer after the pointed-to object's lifetime ends.
  • Using a pointer after an object has been invalidated or its storage reused.

5. Dangling Pointer Due to free()

When dynamically allocated memory is released using free(), pointers to that allocation must no longer be used to access the released object.

Incorrect Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 50;

    free(ptr);

    printf("%d\n", *ptr);

    return 0;
}
The final dereference accesses released storage. This is a use-after-free error and results in undefined behavior. Do not execute this example as a test.

Correct Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    *ptr = 50;

    printf("Value = %d\n", *ptr);

    free(ptr);
    ptr = NULL;

    if (ptr == NULL)
    {
        printf("Pointer reset to NULL\n");
    }

    return 0;
}
Expected Output: 
Value = 50
Pointer reset to NULL

Setting ptr to NULL after free() prevents accidental dereferencing through that particular pointer variable.

Setting one pointer to NULL does not automatically invalidate or clear other pointer variables that refer to the same allocation. Those aliases must also be managed carefully.

6. Dangling Pointer Due to a Local Variable

A local automatic variable generally ceases to exist when its enclosing block finishes. Returning its address creates an invalid pointer for the caller to use.

Incorrect Example

int *get_value(void)
{
    int number = 100;

    return &number;
}
number has automatic storage duration and its lifetime ends when get_value returns. The returned pointer must not be dereferenced.

Correct Approach 1: Use Caller-Owned Storage

#include <stdio.h>

void get_value(int *result)
{
    if (result != NULL)
    {
        *result = 100;
    }
}

int main(void)
{
    int number;

    get_value(&number);

    printf("%d\n", number);

    return 0;
}
Expected Output: 
100

Correct Approach 2: Return a Value

#include <stdio.h>

int get_value(void)
{
    int number = 100;

    return number;
}

int main(void)
{
    int result = get_value();

    printf("%d\n", result);

    return 0;
}
Expected Output: 
100

7. Difference Between Wild and Dangling Pointers

Feature Wild Pointer Dangling Pointer
Meaning Informal term for an invalid or indeterminate pointer used as though valid. Pointer to an object whose lifetime has ended or whose storage is no longer valid.
Common cause Uninitialized pointer. Using a pointer after free() or after object lifetime ends.
Address value May be indeterminate. May retain an old address.
Prevention Initialize pointers before use. Respect object lifetime and manage ownership.

8. NULL Pointer Versus Dangling Pointer

NULL Pointer Dangling Pointer
Represents no object address. Retains a reference to an object whose lifetime has ended.
Can be checked using ptr == NULL. Cannot reliably be detected by checking whether the address is NULL.
Must not be dereferenced. Must not be used to access the former object.
Can be used as a deliberate initial state. Usually indicates a lifetime-management bug.
A non-NULL pointer is not necessarily valid. Checking ptr != NULL does not prove that the pointed-to object is still alive.

9. Use-After-Free

Use-after-free occurs when a program accesses dynamically allocated storage after it has been released.

Typical Sequence

ptr = malloc(...);
        |
        v
Use allocated object
        |
        v
free(ptr);
        |
        v
Access through ptr again
        |
        v
USE-AFTER-FREE ERROR

Possible consequences include:

  • Incorrect program results.
  • Memory corruption.
  • Unexpected crashes.
  • Security vulnerabilities.
  • Intermittent failures that are difficult to reproduce.

10. Double Free Error

A double free occurs when the same allocated storage is released more than once without a new allocation in between.

Incorrect Example

int *ptr = malloc(sizeof *ptr);

if (ptr != NULL)
{
    free(ptr);
    free(ptr);
}
The second free() attempts to release storage that has already been released. This results in undefined behavior. Do not execute this example as a test.

Safer Cleanup Pattern

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 25;

    free(ptr);
    ptr = NULL;

    free(ptr);

    return 0;
}

In C, free(NULL) has no effect. This pattern prevents a second release through this particular pointer variable.

11. Memory Leak and Pointer Lifetime

A memory leak occurs when dynamically allocated storage is no longer reachable or cannot be properly released by the program.

Incorrect Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(10 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    ptr = NULL;

    return 0;
}
The original allocation becomes unreachable when ptr is overwritten with NULL. The allocation cannot be released through ptr afterward, resulting in a memory leak.

Correct Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(10 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    /* Use allocated memory here. */

    free(ptr);
    ptr = NULL;

    return 0;
}

Release dynamically allocated storage when it is no longer needed and ensure ownership responsibilities are clear.

12. Pointer Aliasing and Shared Ownership

Pointer aliasing occurs when multiple pointer variables refer to the same object.

Example

#include <stdio.h>

int main(void)
{
    int value = 10;

    int *p1 = &value;
    int *p2 = p1;

    *p2 = 50;

    printf("%d\n", *p1);

    return 0;
}
Expected Output: 
50

Both p1 and p2 refer to the same integer. Changing the object through p2 is visible when accessing it through p1.

If dynamically allocated storage is released through one alias, the other alias becomes invalid for accessing that storage. Setting one pointer to NULL does not update the others.

13. Safe Pointer Initialization Techniques

Initialize to NULL

int *ptr = NULL;

Initialize with a Valid Object Address

int value = 20;
int *ptr = &value;

Initialize Through Dynamic Allocation

int *ptr = malloc(sizeof *ptr);

if (ptr == NULL)
{
    /* Handle allocation failure. */
}

Use a Pointer Only After Validation

if (ptr != NULL)
{
    printf("%d\n", *ptr);
}

This NULL check is useful, but it is sufficient only when the program also guarantees that ptr refers to a live object.

14. Pointer Safety in Embedded C

Pointer errors are particularly important in embedded software because invalid memory access can affect system reliability.

Typical Risk Areas

  • Peripheral register pointer initialization.
  • Buffer management in UART and SPI drivers.
  • DMA buffer lifetime and ownership.
  • Interrupt callback context and shared pointers.
  • Dynamic memory allocation in long-running systems.
  • Stack lifetime and local buffer addresses.

Example: Safe Buffer Pointer Check

#include <stdio.h>
#include <stddef.h>

void display_buffer(const unsigned char *buffer, size_t length)
{
    if (buffer == NULL)
    {
        printf("Invalid buffer\n");
        return;
    }

    for (size_t i = 0; i < length; i++)
    {
        printf("%02X ", buffer[i]);
    }

    printf("\n");
}

int main(void)
{
    const unsigned char data[] = {
        0x10, 0x20, 0x30, 0x40
    };

    display_buffer(data, sizeof data);

    return 0;
}
Expected Output: 
10 20 30 40

The function validates the pointer before accessing the buffer. The caller must also ensure that the supplied length does not exceed the actual buffer size.

In embedded systems, ownership and lifetime rules are important for buffers shared between application code, interrupts and DMA hardware.

15. Detecting Pointer Errors with Compiler Tools

Compiler warnings and runtime instrumentation help identify memory errors during development.

GCC Warning Options

gcc -std=c11 -Wall -Wextra -Wpedantic -Wuninitialized program.c -o program

AddressSanitizer

gcc -std=c11 -Wall -Wextra -g \
-fsanitize=address -fno-omit-frame-pointer \
program.c -o program

UndefinedBehaviorSanitizer

gcc -std=c11 -Wall -Wextra -g \
-fsanitize=undefined program.c -o program

AddressSanitizer can detect many errors such as heap use-after-free and out-of-bounds accesses. UndefinedBehaviorSanitizer detects several categories of undefined behavior.

Sanitizers do not prove a program is completely free of memory errors. Use them alongside careful code review, testing and compiler warnings.

16. Common Pointer Errors Comparison

Error Cause Prevention
Wild pointer Using an invalid or indeterminate pointer. Initialize pointers before use.
Dangling pointer Object lifetime has ended. Respect lifetime and ownership.
NULL dereference Accessing through a NULL pointer. Validate pointer state.
Use-after-free Accessing released allocation. Stop using pointers after deallocation.
Double free Releasing the same allocation twice. Track ownership and release once.
Memory leak Allocation is not released. Provide a clear cleanup path.
Out-of-bounds access Accessing outside an object or array. Validate indices and lengths.
Use-after-return Using the address of an expired local object. Return values or use caller-owned storage.

20. Key Takeaways

  • Uninitialized pointers must not be dereferenced.
  • Wild pointer is an informal term for an invalid or indeterminate pointer.
  • Dangling pointers refer to objects whose lifetime has ended.
  • Accessing released memory causes undefined behavior.
  • Setting a pointer to NULL does not clear other aliases.
  • Every dynamic allocation needs a clear ownership and cleanup strategy.
  • Returning the address of a local automatic variable is unsafe.
  • Compiler warnings and sanitizers help detect memory errors.
  • Pointer lifetime management is critical in embedded software.
