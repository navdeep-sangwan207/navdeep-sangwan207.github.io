Lecture 5: Preprocessor Directives and Header Files

Learn macros, header inclusion, conditional compilation and modular C programming.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Explain the role of the C preprocessor.
  • Use object-like and function-like macros.
  • Understand macro expansion and common macro pitfalls.
  • Include standard and user-defined header files.
  • Use conditional compilation directives.
  • Protect header files using include guards.
  • Organize C programs into reusable source and header files.
  • Understand the difference between declarations and definitions in header-based projects.

2. What Is the C Preprocessor?

The C preprocessor is a component of the C translation process that handles preprocessing directives before the compiler translates the resulting source code.

Preprocessor directives:

  • Begin with the # symbol.
  • Are processed before normal C compilation.
  • Usually occupy their own logical source lines.
  • Do not normally end with a semicolon.

Example

#include <stdio.h> #define PI 3.14159 int main(void) { printf("PI = %.2f\n", PI); return 0; }

Here, #include and #define are preprocessor directives.

Expected output: 
PI = 3.14

Common preprocessor directives

DirectivePurpose
#includeIncludes another file's contents.
#defineDefines a macro.
#undefUndefines a macro.
#ifCompiles a section when a constant expression is nonzero.
#ifdefChecks whether a macro is defined.
#ifndefChecks whether a macro is not defined.
#elifChecks another conditional expression.
#elseProvides an alternative conditional section.
#endifEnds a conditional section.
#errorProduces a preprocessing diagnostic.
#pragmaProvides implementation-specific instructions.

3. #include Directive

The #include directive makes the contents of another file available at the inclusion point during preprocessing.

3.1 Standard header inclusion

#include <stdio.h> #include <stdlib.h> #include <string.h> #include <math.h>

Angle brackets are commonly used for standard or system-provided headers.

3.2 User-defined header inclusion

#include "myheader.h"

Double quotes are commonly used for project headers. The implementation searches for the header according to its include-search rules, which generally consider the current source file's directory before configured system directories.

SyntaxCommon usage
#include <stdio.h>Standard or system header.
#include "myheader.h"Project or user-defined header.
The difference is primarily the header search strategy. Both forms ultimately include the contents of the selected header.

4. #define: Object-Like Macros

An object-like macro replaces an identifier with a sequence of preprocessing tokens.

Syntax

#define MACRO_NAME replacement_tokens

Example 1: Defining a constant-like macro

#include <stdio.h> #define MAX_SIZE 100 #define PI 3.14159 int main(void) { printf("Maximum size = %d\n", MAX_SIZE); printf("PI = %.2f\n", PI); return 0; }
Expected output: 
Maximum size = 100
PI = 3.14

The preprocessor substitutes the macro names with their replacement tokens. A macro does not create a typed C variable.

Example 2: #undef

#include <stdio.h> #define VALUE 10 #undef VALUE #define VALUE 50 int main(void) { printf("%d\n", VALUE); return 0; }
Expected output: 
50

#undef removes the current definition of a macro. A later definition can then be supplied.

5. Function-Like Macros

A function-like macro accepts arguments and substitutes them into its replacement tokens.

Syntax

#define MACRO_NAME(parameters) replacement_tokens

Example 1: Square macro

#include <stdio.h> #define SQUARE(x) ((x) * (x)) int main(void) { int result = SQUARE(5); printf("Square = %d\n", result); return 0; }
Expected output: 
Square = 25

Why use parentheses?

Consider an unsafe macro:

#define SQUARE(x) x * x

Now consider:

int result = SQUARE(2 + 3);

After macro expansion, the expression becomes:

int result = 2 + 3 * 2 + 3;

Operator precedence makes the result 11, not 25.

The safer macro is:

#define SQUARE(x) ((x) * (x))
Parentheses protect the substituted expression from many precedence-related mistakes. However, macros can still have side effects if an argument is evaluated more than once.

Example 2: Macro argument evaluated more than once

#include <stdio.h> #define SQUARE(x) ((x) * (x)) int main(void) { int i = 3; int result = SQUARE(i++); printf("Result = %d\n", result); printf("i = %d\n", i); return 0; }

This macro expands to an expression that modifies and reads i multiple times without a valid sequencing relationship. The behavior is undefined. Do not use increment or decrement expressions as arguments to macros that evaluate their arguments more than once.

Better alternative: Use a function

#include <stdio.h> static int square(int x) { return x * x; } int main(void) { int i = 3; int result = square(i++); printf("Result = %d\n", result); printf("i = %d\n", i); return 0; }
Expected output: 
Result = 9
i = 4
For ordinary calculations, prefer functions when they provide clearer and safer behavior. Use macros when preprocessing behavior is specifically required.

6. Multiline Macros and the Backslash

A backslash at the end of a preprocessing line can join the next physical line to the current logical line.

Example

#include <stdio.h> #define PRINT_SUM(a, b) \ printf("Sum = %d\n", (a) + (b)) int main(void) { PRINT_SUM(10, 20); return 0; }
Expected output: 
Sum = 30

The backslash must be the final character on the physical line for line splicing. Avoid trailing spaces after it.

7. Predefined Macros

The C implementation provides several predefined macros that supply information about the translation environment.

MacroMeaning
__FILE__Current source file name as a string literal.
__LINE__Current source line number.
__DATE__Date of translation as a string literal.
__TIME__Time of translation as a string literal.
__STDC__Indicates conformance to the standard C implementation requirements.

Example

#include <stdio.h> int main(void) { printf("File: %s\n", __FILE__); printf("Line: %d\n", __LINE__); printf("Date: %s\n", __DATE__); printf("Time: %s\n", __TIME__); return 0; }

The file name, line number, date and time depend on the source file and translation environment.

8. Conditional Compilation

Conditional compilation allows selected sections of source code to be included or excluded during preprocessing.

8.1 #ifdef

Checks whether a macro is defined.

#include <stdio.h> #define DEBUG int main(void) { #ifdef DEBUG printf("Debug mode enabled\n"); #endif printf("Program running\n"); return 0; }
Expected output: 
Debug mode enabled
Program running

8.2 #ifndef

Checks whether a macro is not defined.

#include <stdio.h> #define VERSION 2 #ifndef DEBUG #define MODE "Release" #else #define MODE "Debug" #endif int main(void) { printf("%s mode\n", MODE); return 0; }
Expected output: 
Release mode

8.3 #if, #elif and #else

These directives select code based on constant expressions evaluated during preprocessing.

#include <stdio.h> #define LEVEL 2 int main(void) { #if LEVEL == 1 printf("Beginner\n"); #elif LEVEL == 2 printf("Intermediate\n"); #else printf("Advanced\n"); #endif return 0; }
Expected output: 
Intermediate

8.4 #error

The #error directive produces a preprocessing diagnostic when the directive is reached.

#ifndef REQUIRED_CONFIG #error "Required configuration is missing" #endif

If REQUIRED_CONFIG is not defined, preprocessing reports the specified error message.

9. Compiler-Defined Macros and -D Option

GCC allows macros to be defined from the command line using the -D option.

Source file: main.c

#include <stdio.h> int main(void) { #ifdef DEBUG printf("Debug build\n"); #else printf("Normal build\n"); #endif return 0; }

Build without DEBUG

gcc -std=c11 main.c -o main
Output: 
Normal build

Build with DEBUG

gcc -std=c11 -DDEBUG main.c -o main
Output: 
Debug build

Define a macro with a value

gcc -std=c11 -DLEVEL=3 main.c -o main

This is useful for configuring builds without changing the source file.

10. Header Files in C

A header file normally contains declarations and definitions that need to be shared between source files.

Common header-file contents include:

  • Function declarations (prototypes).
  • Macro definitions.
  • Type definitions using struct, union and enum.
  • typedef declarations.
  • Declarations of shared external variables when required.

Example: Custom header

File: calculator.h

#ifndef CALCULATOR_H #define CALCULATOR_H int add(int a, int b); int subtract(int a, int b); #endif

File: calculator.c

#include "calculator.h" int add(int a, int b) { return a + b; } int subtract(int a, int b) { return a - b; }

File: main.c

#include <stdio.h> #include "calculator.h" int main(void) { printf("Addition = %d\n", add(20, 10)); printf("Subtraction = %d\n", subtract(20, 10)); return 0; }

Compile and link

gcc -std=c11 -Wall -Wextra -Wpedantic main.c calculator.c -o calculator

Run

./calculator
Expected output: 
Addition = 30
Subtraction = 10
The header tells the compiler which functions are available. The source file contains the function definitions. The linker connects the calls in main.c with the definitions in calculator.c.

11. Header Guards

A header guard prevents the same header's contents from being processed repeatedly within a single translation unit.

Problem without header guards

Suppose two headers include the same third header. Without protection, declarations or definitions in the repeated header may be processed multiple times and cause redefinition problems.

Standard header guard pattern

#ifndef MY_HEADER_H #define MY_HEADER_H /* Header declarations */ #endif

Practical example

File: student.h

#ifndef STUDENT_H #define STUDENT_H struct Student { int roll_number; float marks; }; void display_student(struct Student s); #endif

File: student.c

#include <stdio.h> #include "student.h" void display_student(struct Student s) { printf("Roll Number = %d\n", s.roll_number); printf("Marks = %.2f\n", s.marks); }

File: main.c

#include "student.h" int main(void) { struct Student s = {101, 85.5f}; display_student(s); return 0; }

Compile

gcc -std=c11 -Wall -Wextra -Wpedantic main.c student.c -o student
Expected output: 
Roll Number = 101
Marks = 85.50
Header guards prevent repeated inclusion within one translation unit. They do not replace proper linker-level organization. Avoid defining ordinary external functions or variables in headers that are included by multiple source files.

12. #pragma Once and Header Guards

Some compilers support:

#pragma once

This is a widely supported compiler extension that requests a header be included only once in a translation unit.

Header guards#pragma once

For portable C projects, conventional header guards are a reliable choice.

13. Important Macro Operators

13.1 Stringification operator (#)

The # operator converts a macro parameter into a string literal.

#include <stdio.h> #define TO_STRING(x) #x int main(void) { printf("%s\n", TO_STRING(Hello_C)); return 0; }
Expected output: 
Hello_C

13.2 Token-pasting operator (##)

The ## operator joins two preprocessing tokens into one token.

#include <stdio.h> #define JOIN(a, b) a##b int main(void) { int value10 = 100; printf("%d\n", JOIN(value, 10)); return 0; }
Expected output: 
100

The expression JOIN(value, 10) forms the token value10.

gcc -std=c11 -Iinclude main.c -o main

15. Important Interview Questions and Answers

Q1. What is a preprocessor directive?

It is an instruction beginning with # that is processed before the main compilation of the C source code.

Q2. What is the difference between #include and #define?

#include includes another file's contents. #define defines a macro for preprocessing substitution.

Q3. What is an object-like macro?

A macro that replaces an identifier with a sequence of preprocessing tokens, such as #define SIZE 100.

Q4. What is a function-like macro?

A macro that accepts arguments and substitutes them into its replacement tokens, such as #define SQUARE(x) ((x)*(x)).

Q5. Why should macro parameters be enclosed in parentheses?

To reduce unexpected results caused by operator precedence when macro arguments are substituted.

Q6. What is the difference between #ifdef and #ifndef?

#ifdef checks whether a macro is defined. #ifndef checks whether it is not defined.

Q7. What is conditional compilation?

It is the process of including or excluding source-code sections based on preprocessing conditions.

Q8. What is a header guard?

A group of preprocessor directives that prevents a header's contents from being processed repeatedly within one translation unit.

Q9. Is #pragma once part of standard C?

No. It is a commonly supported compiler extension.

Q10. What is the difference between a header file and a source file?

A header commonly contains shared declarations and macros. A source file generally contains function and object definitions and is compiled as a translation unit.

Q11. What does the -D option do in GCC?

It defines a macro from the command line, for example -DDEBUG or -DLEVEL=3.

Q12. What do # and ## do in macro definitions?

# stringifies a macro parameter. ## joins two preprocessing tokens.

Problem 3: Identify the macro expansion
#define ADD(a, b) ((a) + (b)) int result = ADD(10, 20);

Answer: The resulting expression is ((10) + (20)).

#include <stdio.h> #define MODE 1 int main(void) { #if MODE == 1 printf("Mode A\n"); #else printf("Mode B\n"); #endif return 0; }

Mode A
Problem 5: Find the problem
#define SQUARE(x) x * x int result = SQUARE(2 + 3);

Answer: The macro lacks parentheses around its parameter and complete expression. It expands to 2 + 3 * 2 + 3, producing 11 instead of 25.

Problem 6: Which directive prevents repeated header inclusion?

A. #define

B. #include

C. #ifndef

D. #pragma

Answer: C. #ifndef, when used as part of a complete header-guard pattern.

18. Lecture Summary

  • Preprocessor directives begin with # and are processed before normal compilation.
  • #include includes header contents.
  • #define creates object-like or function-like macros.
  • #undef removes an existing macro definition.
  • Conditional compilation uses directives such as #if, #ifdef and #ifndef.
  • Command-line macro definitions can be supplied using GCC's -D option.
  • Header files commonly contain shared declarations and type definitions.
  • Header guards prevent repeated inclusion within a translation unit.
  • Good macro design requires careful attention to parentheses and side effects.
  • Modular C programs separate interfaces in headers from implementations in source files.
