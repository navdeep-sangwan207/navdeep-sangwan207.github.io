Lecture 6: Compiler Errors and Basic Debugging

Learn to identify C programming errors, interpret compiler diagnostics, use warning options and debug programs systematically.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Differentiate syntax, semantic, linker and runtime errors.
  • Understand compiler warnings and diagnostic messages.
  • Identify common C programming mistakes.
  • Compile programs using useful GCC warning options.
  • Use print-based debugging techniques.
  • Understand basic GDB commands and breakpoints.
  • Use debugging information and sanitizers.
  • Follow a systematic approach to troubleshoot C programs.

2. What Is Debugging?

Debugging is the systematic process of finding, understanding and correcting defects in a program.

A program may:

  • Fail to compile.
  • Compile but fail during linking.
  • Execute but produce incorrect output.
  • Crash during execution.
  • Produce incorrect results only for particular input values.
  • Work correctly in one environment but fail in another.

Typical debugging workflow

  1. Reproduce the problem.
  2. Read the error message or observe the incorrect behavior.
  3. Identify the relevant code section.
  4. Form a hypothesis about the cause.
  5. Inspect variables, expressions and program flow.
  6. Correct the underlying defect.
  7. Recompile and test the program.
  8. Retest other inputs to check for regression.
Debugging is not simply changing code until the program works. A good debugging process identifies the root cause and verifies that the correction does not introduce another defect.

3. Types of Errors in C

3.1 Syntax errors

Syntax errors occur when source code violates the grammar of the C language.

#include <stdio.h> int main(void) { printf("Hello World") return 0; }

The semicolon after the printf() statement is missing.

Correction:

printf("Hello World");

The compiler reports a diagnostic for the invalid syntax.

3.2 Semantic and constraint violations

These occur when code does not satisfy the language's semantic or constraint requirements, such as using an undeclared identifier or passing an incompatible argument to a function.

#include <stdio.h> int main(void) { int number = 10; printf("%d\n", total); return 0; }

The identifier total has not been declared.

Correction: Declare and initialize the intended variable before using it.

3.3 Linker errors

Linker errors occur when the linker cannot correctly combine the required object files and libraries.

int calculate(void); int main(void) { return calculate(); }

The function is declared and called, but its definition is missing from the linked files and libraries.

A typical linker diagnostic may contain:

undefined reference to `calculate'

3.4 Runtime errors

Runtime errors occur while the program is executing.

Examples include:

  • Invalid memory access.
  • Dereferencing a null or invalid pointer.
  • Out-of-bounds array access.
  • Using uninitialized data.
  • Division by zero.

3.5 Logical errors

A logical error occurs when a program executes but produces an incorrect result because its algorithm or condition is wrong.

#include <stdio.h> int main(void) { int length = 10; int width = 5; int area = 2 * (length + width); printf("Area = %d\n", area); return 0; }

The expression calculates the perimeter of a rectangle, not its area.

Correction:

int area = length * width;
Correct output: 
Area = 50

4. Understanding Compiler Diagnostics

A compiler diagnostic is a message that reports an error, warning or other relevant information about the source program.

Example

main.c: In function 'main': main.c:6:5: error: expected ';' before 'return'

Important parts of this message:

PartMeaning
main.cSource file name.
In function 'main'Function in which the diagnostic occurred.
6:5Line 6, column 5.
errorSeverity of the diagnostic.
expected ';'Description of the reported problem.

Error vs warning

ErrorWarning
Indicates a problem that prevents successful translation or linking.Indicates suspicious or potentially problematic code.
Normally prevents the build from completing.May allow the build to complete.
Must be corrected for a successful build.Should be investigated and corrected when appropriate.
The compiler's diagnostic location may point to where a problem becomes detectable, not necessarily where the underlying mistake originated.

5. GCC Warning Options

GCC provides options that help detect suspicious code during development.

Recommended basic command

gcc -std=c11 -Wall -Wextra -Wpedantic main.c -o main
OptionPurpose
-std=c11Use the C11 language standard.
-WallEnable many useful warning diagnostics.
-WextraEnable additional warning diagnostics.
-WpedanticReport certain uses outside the selected ISO C standard.
-WerrorTreat enabled warnings as errors.
-gGenerate debugging information.
-O0Disable most optimization for easier debugging.
-O2Enable a higher level of optimization.

Example: Detect a suspicious variable

#include <stdio.h> int main(void) { int number = 10; printf("Program started\n"); return 0; }

The variable number is assigned but never used. GCC may report an unused-variable warning.

Compile with warnings treated as errors

gcc -std=c11 -Wall -Wextra -Wpedantic -Werror main.c -o main
Use -Werror carefully. It can help enforce code quality in a controlled project, but different compiler versions may introduce additional warnings.

6. Common C Programming Errors

6.1 Uninitialized variable

#include <stdio.h> int main(void) { int number; printf("%d\n", number); return 0; }

The automatic local variable is not initialized. Reading its indeterminate value this way has undefined behavior for this ordinary integer example.

Correction:

int number = 0;

6.2 Assignment instead of comparison

if (number = 10) { printf("Matched\n"); }

This assigns 10 to number. Since the assigned value is nonzero, the condition evaluates as true.

Correction:

if (number == 10) { printf("Matched\n"); }

6.3 Incorrect format specifier

int number = 10; printf("%f", number);

The %f conversion specification expects a double argument in printf(), not an int. The mismatch results in undefined behavior.

Correction:

printf("%d", number);

6.4 Array out-of-bounds access

int values[5] = {10, 20, 30, 40, 50}; printf("%d\n", values[5]);

The valid indexes are 0 through 4. Accessing values[5] is out of bounds and causes undefined behavior.

Correction:

printf("%d\n", values[4]);

6.5 Incorrect string input

char name[10]; scanf("%s", name);

This input can overflow the array if the entered word is too long.

Safer bounded input:

char name[10]; if (scanf("%9s", name) == 1) { printf("%s\n", name); }

The width limit leaves space for the terminating null character.

6.6 Null pointer dereferencing

int *ptr = NULL; *ptr = 100;

Dereferencing a null pointer has undefined behavior.

Correction:

if (ptr != NULL) { *ptr = 100; }

7. Print-Based Debugging

Print-based debugging uses output statements to inspect variable values and program execution.

Example: Find an incorrect calculation

#include <stdio.h> int main(void) { int a = 10; int b = 5; int result = a - b; printf("DEBUG: a = %d\n", a); printf("DEBUG: b = %d\n", b); printf("DEBUG: result = %d\n", result); printf("Final result = %d\n", result); return 0; }
Expected output: 
DEBUG: a = 10
DEBUG: b = 5
DEBUG: result = 5
Final result = 5

This technique helps identify:

  • Unexpected variable values.
  • Incorrect calculations.
  • Whether a particular condition is reached.
  • Unexpected loop iterations.
Print-based debugging is simple and useful, but a debugger provides more control over execution, breakpoints, variable inspection and call-stack analysis.

8. Introduction to GDB

GDB (GNU Debugger) is a debugger that allows developers to inspect and control program execution.

It supports operations such as:

  • Starting a program under debugger control.
  • Setting breakpoints.
  • Executing one line or function at a time.
  • Inspecting variable values.
  • Examining the call stack.
  • Continuing execution after a breakpoint.

Step 1: Create a C program

File: debug_demo.c

#include <stdio.h> int add(int a, int b) { int result = a + b; return result; } int main(void) { int x = 10; int y = 20; int sum = add(x, y); printf("Sum = %d\n", sum); return 0; }

Step 2: Compile with debugging information

gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 debug_demo.c -o debug_demo

The -g option includes debugging information. -O0 disables optimization to make source-level debugging easier.

Step 3: Start GDB

gdb ./debug_demo

On Windows, use the executable name and the GDB installation's supported path conventions.

Step 4: Set a breakpoint

(gdb) break main

This sets a breakpoint at the beginning of main().

Step 5: Run the program

(gdb) run

Step 6: Execute one source line

(gdb) next

The next command executes the next source line without stepping into a called function.

Step 7: Inspect a variable

(gdb) print x

Step 8: Step into a function

(gdb) step

The step command enters a called function when possible.

Step 9: Continue execution

(gdb) continue

Step 10: Exit GDB

(gdb) quit

10. Debugging with AddressSanitizer and UndefinedBehaviorSanitizer

Sanitizers are compiler-supported runtime instrumentation tools that help detect certain classes of bugs during testing.

AddressSanitizer (ASan)

It can detect problems such as:

  • Heap buffer overflows.
  • Stack buffer overflows.
  • Use-after-free errors.
  • Some invalid memory accesses.

UndefinedBehaviorSanitizer (UBSan)

It can detect selected forms of undefined behavior, such as certain invalid arithmetic operations and other instrumentable violations.

Example: Compile with sanitizers

gcc -std=c11 -Wall -Wextra -g -O1 \ -fsanitize=address,undefined \ debug_demo.c -o debug_demo

Run the program normally. If an instrumented problem occurs, the runtime may report details including the source location and type of error.

Sanitizers detect many important bugs but cannot detect every possible defect. A clean sanitizer run does not prove that a program is correct.

12. Common Debugging Interview Questions

Q1. What is debugging?

Debugging is the process of identifying, analyzing and correcting defects in software.

Q2. What is the difference between a compiler error and a warning?

An error prevents successful translation or linking. A warning reports suspicious or potentially problematic code and may still allow the build to complete.

Q3. What is a logical error?

A defect in the program's logic or algorithm that causes incorrect results even though the program may compile and execute.

Q4. What is GDB?

GDB is the GNU Debugger. It allows programmers to control program execution, set breakpoints, inspect variables and examine the call stack.

Q5. Why is the -g option used?

It generates debugging information that helps a debugger associate machine instructions with source-level information.

Q6. What is a breakpoint?

A breakpoint is a location at which the debugger pauses program execution so that the programmer can inspect program state.

Q7. What is the difference between next and step in GDB?

next executes the next source line without stepping into a function call. step enters the function when possible.

Q8. What does -Wall do?

It enables many useful GCC warning diagnostics. It does not literally enable every warning available in GCC.

Q9. What is AddressSanitizer?

It is a runtime memory-error detection tool that can identify issues such as buffer overflows and use-after-free errors.

Q10. What is UndefinedBehaviorSanitizer?

It is a runtime instrumentation tool that detects selected forms of undefined behavior.

Q11. Why is testing boundary values important?

Many defects occur at minimum, maximum, zero, empty or out-of-range values that ordinary test inputs may not expose.

Q12. What is a stack trace?

A stack trace shows the sequence of active function calls. It helps identify how execution reached a particular location.

13. Output Prediction and Error Identification

Problem 1: Identify the error
int main(void) { int x = 10 return 0; }

Answer: Missing semicolon after the variable declaration. It is a syntax error.

Problem 2: Identify the logical error
int a = 10; int b = 20; int result = a - b;

The expression performs subtraction. If the intended operation is addition, the correct expression is a + b.

Problem 3: Predict the output
#include <stdio.h> int main(void) { int x = 5; if (x = 0) printf("True\n"); else printf("False\n"); return 0; }
Answer: 
False

The assignment expression sets x to zero. Its value is false in the condition. A compiler may warn about assignment used as a truth value.

Problem 4: Identify the problem
int values[3] = {10, 20, 30}; printf("%d", values[3]);

Answer: Out-of-bounds array access. Valid indexes are 0, 1 and 2.

Problem 5: Choose the correct GCC debugging command

A. gcc -g main.c -o main

B. gcc -E main.c -o main

C. gcc -S main.c -o main

D. gcc -c main.c -o main

Answer: A. The -g option generates debugging information.

14. Practical Exercises

  1. Write a program containing a syntax error, compile it and interpret the diagnostic.
  2. Create an unused variable and observe the warning generated by GCC.
  3. Compile a program using -Wall -Wextra -Wpedantic.
  4. Intentionally introduce an undefined reference and identify the linker diagnostic.
  5. Write a program with an incorrect formula and correct the logical error.
  6. Use print statements to inspect the values of variables inside a loop.
  7. Compile a program with -g -O0 and run it using GDB.
  8. Set a breakpoint inside a function and inspect its parameters.
  9. Use next, step, print and backtrace.
  10. Compile a test program with AddressSanitizer and UndefinedBehaviorSanitizer where supported.
  11. Test array and string programs using boundary inputs.
  12. Document the defect, its root cause, the correction and the test used to verify the fix.
