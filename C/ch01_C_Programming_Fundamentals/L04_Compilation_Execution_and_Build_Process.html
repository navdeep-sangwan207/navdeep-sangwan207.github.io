Lecture 4: Compilation, Execution and Build Process

Understand how C source code is transformed into an executable program using GCC, assemblers and linkers.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Explain how a C program is converted into an executable file.
  • Differentiate preprocessing, compilation, assembly and linking.
  • Use GCC commands to generate preprocessed files, assembly files and object files.
  • Understand the role of object files and executable files.
  • Compile and link programs containing multiple source files.
  • Identify common compilation and linker errors.
  • Use compiler warning options during development.

2. What Is Compilation?

A C program is normally written as human-readable source code in a file with the .c extension.

A processor cannot directly execute ordinary C source code. A toolchain transforms the source code into machine-level instructions and produces an executable program.

Compilation is commonly used to describe this translation process. In a conventional GCC build, it involves four major stages:

Important: The four conventional build stages are preprocessing, compilation, assembly and linking. Loading and execution happen after the executable has been produced. Actual compiler implementations may combine or reorganize internal phases.

3. Stage 1: Preprocessing

The preprocessor handles preprocessing directives before the main translation of the C source code.

Common preprocessing operations include:

  • Expanding macros defined using #define.
  • Including header-file contents through #include.
  • Processing conditional directives such as #if, #ifdef and #ifndef.
  • Removing comments and processing source text according to preprocessing rules.

Example: main.c

#include <stdio.h> #define VALUE 100 int main(void) { printf("Value = %d\n", VALUE); return 0; }

In this example:

  • #include <stdio.h> makes the standard I/O declarations available.
  • #define VALUE 100 defines a macro.
  • The preprocessor replaces the occurrence of VALUE with 100.

GCC command: Generate preprocessed output

gcc -std=c11 -E main.c -o main.i
OptionPurpose
-std=c11Use the C11 language standard.
-ERun preprocessing and stop.
-o main.iWrite the output to main.i.

The file main.i contains preprocessed source text. It is not an executable program.

The next lecture covers preprocessing directives, macros and header files in greater detail. Here, focus on the preprocessor's position in the build pipeline.

4. Stage 2: Compilation

After preprocessing, the compiler translates the preprocessed C source into lower-level instructions, commonly represented as assembly language or an internal intermediate representation.

During this stage, the compiler performs tasks such as:

  • Syntax and semantic analysis.
  • Type checking and other language-rule checks.
  • Translation into lower-level representations.
  • Code optimization when enabled.
  • Generation of assembly code or machine-code-related output.

GCC command: Generate assembly code

gcc -std=c11 -S main.c -o main.s

The -S option tells GCC to stop after generating assembly output.

FileDescription
main.cOriginal C source file.
main.sGenerated assembly-language file.
Assembly instructions depend on the target processor and toolchain. Assembly generated for one architecture is not necessarily valid for another architecture.

5. Stage 3: Assembly

The assembler converts assembly-language instructions into machine-code instructions and creates an object file.

GCC command: Generate an object file

gcc -std=c11 -c main.c -o main.o

The -c option tells GCC to compile the source file into an object file without linking it into a complete executable.

What does an object file contain?

  • Machine-code sections.
  • Symbol information.
  • Relocation information needed by the linker.
  • Other metadata required by the toolchain.
Object file vs executable: An object file is generally an intermediate build artifact. It may contain references to functions or variables that will be resolved during linking. It is not normally ready to run as a complete program.

6. Stage 4: Linking

The linker combines object files and required libraries to produce an executable or another linkable output.

Its major responsibilities include:

  • Combining object files.
  • Resolving references to functions and variables defined in other files.
  • Connecting required library code or library references.
  • Processing symbol and relocation information.
  • Producing the final executable when the build target is an executable.

GCC command: Link an object file

gcc main.o -o main

This command links main.o and creates an executable named main on typical Linux systems.

If a function is declared and called but no matching definition is supplied to the linker, the build may fail with an error such as undefined reference. This is a linker error, not a C syntax error.

7. Complete GCC Build Commands

Consider the following source file:

main.c

#include <stdio.h> int main(void) { int a = 10; int b = 20; int sum = a + b; printf("Sum = %d\n", sum); return 0; }

Command 1: Compile and link in one command

gcc -std=c11 -Wall -Wextra -Wpedantic main.c -o main

This is the normal command for building a small C program with GCC.

Command 2: Preprocess only

gcc -std=c11 -E main.c -o main.i

Command 3: Generate assembly

gcc -std=c11 -S main.c -o main.s

Command 4: Generate object file

gcc -std=c11 -c main.c -o main.o

Command 5: Link object file

gcc main.o -o main

Command 6: Display verbose build information

gcc -v main.c -o main

The -v option displays detailed information about the compiler driver and the tools or commands it invokes. Exact output depends on the GCC installation.

Run the program

On Linux:

./main

On Windows Command Prompt, if the executable is named main.exe:

main.exe
Expected output: 
Sum = 30

9. Compiling a Multi-File C Program

Real-world C applications are often divided into multiple source files. This improves modularity, code reuse and maintainability.

Consider a project containing three files:

project/ | |-- main.c |-- math_utils.c |-- math_utils.h

File 1: math_utils.h

#ifndef MATH_UTILS_H #define MATH_UTILS_H int add(int a, int b); #endif

The header file declares the add() function.

File 2: math_utils.c

#include "math_utils.h" int add(int a, int b) { return a + b; }

This source file contains the actual definition of the function.

File 3: main.c

#include <stdio.h> #include "math_utils.h" int main(void) { int result = add(15, 25); printf("Result = %d\n", result); return 0; }

Method 1: Compile and link both source files together

gcc -std=c11 -Wall -Wextra -Wpedantic main.c math_utils.c -o app

This command compiles both source files and links them into one executable.

Method 2: Compile source files separately

Step 1: Compile main.c.

gcc -std=c11 -Wall -Wextra -Wpedantic -c main.c -o main.o

Step 2: Compile math_utils.c.

gcc -std=c11 -Wall -Wextra -Wpedantic -c math_utils.c -o math_utils.o

Step 3: Link both object files.

gcc main.o math_utils.o -o app

Step 4: Execute the program.

./app
Expected output: 
Result = 40

Why are header files needed?

  • The header provides the function declaration to source files that call it.
  • The source file provides the actual function definition.
  • The linker connects the function call with its definition.
A function declaration tells the compiler about a function's interface. It does not provide the function's implementation. If the definition is missing from the linked files or libraries, the linker cannot resolve the reference.

10. What Happens After Linking?

After a successful build, the operating system can load the executable.

The general execution process is:

  1. The user starts the executable.
  2. The operating system's program loader prepares the process.
  3. Required program segments and shared-library dependencies are mapped or made available.
  4. The runtime environment performs required initialization.
  5. Execution reaches the program's entry point and eventually calls main() in a hosted C environment.
  6. The program executes and returns an exit status.
The C standard describes program startup and execution behavior, while the exact loading and process initialization mechanisms depend on the operating system and executable format.

11. Compiler Errors vs Linker Errors

Understanding the difference is important for debugging build failures.

Error typeWhen it occursExample
Preprocessing errorDuring preprocessingMissing included header file.
Compilation errorDuring compilationSyntax error or incompatible type usage.
Assembly errorDuring assemblyInvalid assembly instruction or syntax.
Linker errorDuring linkingUndefined reference or multiple definition.
Runtime errorDuring program executionInvalid memory access or division by zero.

Example 1: Compilation error

#include <stdio.h> int main(void) { printf("Hello") return 0; }

The semicolon after the printf() statement is missing. The compiler reports a syntax error.

Example 2: Linker error

/* main.c */ int calculate(void); int main(void) { return calculate(); }

The function is declared and called, but no definition is supplied. If no linked object file or library provides it, linking fails with an undefined-reference error.

Example 3: Multiple definition

If the same external function or variable is defined more than once in separately linked translation units, the linker may report a multiple-definition error.

Useful warning options

gcc -std=c11 -Wall -Wextra -Wpedantic main.c -o main
  • -Wall: Enables many useful warning diagnostics.
  • -Wextra: Enables additional warnings.
  • -Wpedantic: Requests diagnostics for certain non-standard language extensions.
Warnings are not necessarily compilation errors. However, they can reveal bugs, portability problems and suspicious code before execution.

Libraries allow programmers to reuse compiled code instead of implementing every function themselves.

14. Important Interview Questions and Answers

Q1. What are the four main stages of the GCC build process?

Preprocessing, compilation, assembly and linking.

Q2. What is the role of the preprocessor?

It processes directives such as #include, #define and conditional compilation directives before the main translation of the source code.

Q3. What is an object file?

An object file contains compiled machine code and related information such as symbols and relocation data. It is generally used as input to the linker.

Q4. What does the GCC -E option do?

It runs the preprocessor and stops before compilation.

Q5. What is the difference between -S and -c?

-S generates assembly output and stops. -c generates an object file without linking.

Q6. What is the role of a linker?

It combines object files and required libraries, resolves external symbols and produces the requested linked output.

Q7. What does undefined reference mean?

It generally means the linker cannot find a required definition for a referenced function or variable.

Q8. Can an object file be executed directly?

Normally, no. It is an intermediate file and may contain unresolved references. It must generally be linked into an executable first.

Q9. What is the difference between compilation and linking?

Compilation translates source code into lower-level code and checks language rules. Linking combines compiled object files and libraries and resolves external references.

Q10. Why should we use -Wall and -Wextra?

They enable useful compiler warnings that help identify potential bugs and suspicious code during development.

Q11. Does a C executable run on every operating system?

No. Executable formats, processor instruction sets, operating-system interfaces and ABI requirements differ. C source portability does not guarantee binary portability.

Q12. What happens after successful linking?

The operating system can load the executable, prepare the process and begin program execution.

17. Lecture Summary

  • Preprocessing handles macros, header inclusion and conditional directives.
  • Compilation translates preprocessed source into lower-level code.
  • Assembly produces object files containing machine code and related metadata.
  • Linking combines object files and libraries and resolves external symbols.
  • The operating system loads an executable to begin execution.
  • GCC provides -E, -S and -c options for examining build stages.
  • Multi-file projects use declarations, definitions and linking to connect modules.
  • Compiler errors and linker errors occur at different stages and require different debugging approaches.
