Lecture 05: File Positioning and Random Access

Topic: fseek(), ftell(), rewind() and random-access operations

C Programming | Chapter 14: File Handling

1. Learning Objectives

After completing this lecture, you will be able to:

  • Understand the file-position indicator.
  • Use fseek() to move to a particular file position.
  • Use ftell() to determine the current file position.
  • Use rewind() to return to the beginning of a file.
  • Understand sequential access and random access.
  • Read particular records from binary files.
  • Modify records without reading the entire file.
  • Handle positioning errors and understand text-stream limitations.

2. What Is a File-Position Indicator?

A file stream maintains a file-position indicator that identifies the position from which the next input operation will read or the next output operation will write.

When a file is opened, the initial position is normally at the beginning, except for certain modes such as append mode.

Example

FILE *fp = fopen("data.txt", "r");

char ch;

ch = fgetc(fp);

After fgetc() successfully reads the first character, the file position advances past that character.

Conceptual representation

File contents:

H   E   L   L   O

^
Position before reading

After reading H:

    E   L   L   L   O
    ^
    Next reading position
The file-position indicator is maintained by the stream. It is not the same thing as a physical disk-sector address.

3. The fseek() Function

The fseek() function changes the file-position indicator to a specified position relative to a reference point.

Syntax

int fseek(FILE *stream, long int offset, int origin);

Parameters

Parameter Description
stream Pointer to the opened file stream.
offset Number of position units to move relative to the origin.
origin Reference point from which the offset is measured.

Return Value

  • Returns 0 if the positioning operation succeeds.
  • Returns a nonzero value if the operation fails.

Reference Positions

Constant Meaning
SEEK_SET Beginning of the file.
SEEK_CUR Current file position.
SEEK_END End of the file.

Examples

/* Move to the beginning */
fseek(fp, 0L, SEEK_SET);

/* Move forward by 5 positions */
fseek(fp, 5L, SEEK_SET);

/* Move 3 positions forward from current position */
fseek(fp, 3L, SEEK_CUR);

/* Move to the end */
fseek(fp, 0L, SEEK_END);
For binary streams, fseek() uses byte offsets. For text streams, portable positioning is more restricted: generally use an offset of zero or a position previously returned by ftell(), with SEEK_SET.

4. The ftell() Function

The ftell() function obtains the current file position.

Syntax

long int ftell(FILE *stream);

Return Value

  • Returns the current file position on success.
  • Returns -1L if an error occurs.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    long int position;

    fp = fopen("data.txt", "r");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    position = ftell(fp);

    if (position == -1L) {
        perror("ftell failed");
        fclose(fp);
        return 1;
    }

    printf("Initial position: %ld\n", position);

    fgetc(fp);

    position = ftell(fp);

    if (position == -1L) {
        perror("ftell failed");
        fclose(fp);
        return 1;
    }

    printf("Position after reading: %ld\n", position);

    fclose(fp);

    return 0;
}

Expected Output

Initial position: 0
Position after reading: 1

This example assumes a suitable single-byte character in the file and a text-stream environment where these positions have the illustrated values.

Interview point: ftell() returns a long int, not an int. Always check for -1L before using the returned position.

5. The rewind() Function

The rewind() function moves the file-position indicator to the beginning of a stream.

Syntax

void rewind(FILE *stream);

Unlike fseek(), rewind() does not return a success or failure status.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int ch;

    fp = fopen("data.txt", "r");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    ch = fgetc(fp);

    if (ch != EOF) {
        printf("First character: %c\n", ch);
    }

    rewind(fp);

    ch = fgetc(fp);

    if (ch != EOF) {
        printf("After rewind: %c\n", ch);
    }

    fclose(fp);

    return 0;
}

Expected Output

First character: H
After rewind: H

Assuming data.txt begins with the character H, the program reads H, returns to the beginning and reads H again.

rewind() also clears the stream's end-of-file and error indicators. Use clearerr() when you need to clear these indicators without changing the file position.

6. Sequential Access vs Random Access

Sequential Access

In sequential access, data is processed in order, starting from the current file position.

Record 1 → Record 2 → Record 3 → Record 4 → Record 5

Example applications:

  • Reading a text file line by line.
  • Processing log files.
  • Reading a data stream from beginning to end.

Random Access

In random access, a program can move directly to a desired position and access data without reading every preceding record.

Record 1    Record 2    Record 3    Record 4    Record 5
                              ^
                       Direct access

Example applications:

  • Retrieving a particular student record.
  • Updating a specific employee record.
  • Accessing fixed-size binary records.
  • Implementing simple file-based record systems.
Sequential Access Random Access
Processes data in sequence. Can reposition to a selected location.
May need to pass preceding data. Can directly position within a suitable file.
Commonly uses fgetc(), fgets(), fread(). Uses fseek() with reading or writing operations.
Useful for streams and logs. Useful for fixed-size record access.

7. Finding the Size of a Binary File

A common technique is to move to the end of a binary file and obtain its position using ftell().

Complete C Program

#include <stdio.h>

int main(void)
{
    FILE *fp;
    long int file_size;

    fp = fopen("data.bin", "rb");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    if (fseek(fp, 0L, SEEK_END) != 0) {
        perror("fseek failed");
        fclose(fp);
        return 1;
    }

    file_size = ftell(fp);

    if (file_size == -1L) {
        perror("ftell failed");
        fclose(fp);
        return 1;
    }

    printf("File size: %ld bytes\n", file_size);

    fclose(fp);

    return 0;
}

Expected Output

File size: 100 bytes

The output assumes that data.bin has a size of 100 bytes.

This is a common technique for ordinary seekable binary files, but it is not a universal file-size method. It may fail for non-seekable streams, and long int may not represent very large file positions on every implementation. Large-file applications may require platform-specific APIs.

8. Random Access Using Fixed-Size Records

Suppose a binary file contains employee records of equal size. We can calculate the position of a particular record.

If records are stored consecutively and each has a fixed size:

Position of record n = (n - 1) * sizeof(record)

For example, to access the third record:

fseek(fp, 2L * sizeof(struct Employee), SEEK_SET);

The offset is calculated using zero-based positioning: record 1 begins at offset zero.

Complete C Program: Read a Particular Record

#include <stdio.h>
#include <stdlib.h>

#define COUNT 4

struct Employee {
    int id;
    char name[30];
    float salary;
};

int main(void)
{
    struct Employee employees[COUNT] = {
        {101, "Aman", 25000.0f},
        {102, "Riya", 30000.0f},
        {103, "Karan", 28000.0f},
        {104, "Neha", 35000.0f}
    };

    struct Employee selected;
    FILE *fp;

    int record_number = 3;
    long int offset;

    fp = fopen("employees.bin", "wb");

    if (fp == NULL) {
        perror("File opening failed");
        return EXIT_FAILURE;
    }

    if (fwrite(employees, sizeof employees[0],
               COUNT, fp) != COUNT) {
        fprintf(stderr, "Writing records failed.\n");
        fclose(fp);
        return EXIT_FAILURE;
    }

    if (fclose(fp) == EOF) {
        perror("File closing failed");
        return EXIT_FAILURE;
    }

    fp = fopen("employees.bin", "rb");

    if (fp == NULL) {
        perror("File opening failed");
        return EXIT_FAILURE;
    }

    if (record_number < 1 || record_number > COUNT) {
        printf("Invalid record number.\n");
        fclose(fp);
        return EXIT_FAILURE;
    }

    offset = (long int)(record_number - 1) *
             (long int)sizeof(struct Employee);

    if (fseek(fp, offset, SEEK_SET) != 0) {
        perror("Positioning failed");
        fclose(fp);
        return EXIT_FAILURE;
    }

    if (fread(&selected, sizeof selected, 1, fp) != 1) {
        fprintf(stderr, "Unable to read selected record.\n");
        fclose(fp);
        return EXIT_FAILURE;
    }

    printf("Selected Employee:\n");
    printf("ID: %d\n", selected.id);
    printf("Name: %s\n", selected.name);
    printf("Salary: %.2f\n", selected.salary);

    if (fclose(fp) == EOF) {
        perror("File closing failed");
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}

Expected Output

Selected Employee:
ID: 103
Name: Karan
Salary: 28000.00

Explanation

  1. Four employee records are written to employees.bin.
  2. The file is reopened in binary read mode.
  3. The program validates the requested record number.
  4. The offset of record number three is calculated.
  5. fseek() moves to the calculated offset.
  6. fread() reads exactly one employee record.
This example assumes the file was created using the same structure layout and compatible implementation. It is a learning demonstration, not a portable database format. Also, the calculation must be checked for overflow in applications handling large record numbers or files.

9. Updating a Particular Record

Random access also allows a program to modify a selected fixed-size record without rewriting all preceding records.

Example

struct Employee employee;
FILE *fp;

int record_number = 2;

/* Open existing binary file for reading and writing */
fp = fopen("employees.bin", "rb+");

if (fp == NULL) {
    perror("File opening failed");
    return 1;
}

/* Move to the second record */
if (fseek(fp,
          (long int)(record_number - 1) *
          (long int)sizeof employee,
          SEEK_SET) != 0) {
    perror("Positioning failed");
    fclose(fp);
    return 1;
}

/* Read the selected record */
if (fread(&employee, sizeof employee, 1, fp) != 1) {
    fprintf(stderr, "Record reading failed.\n");
    fclose(fp);
    return 1;
}

/* Modify a member */
employee.salary = 40000.0f;

/* Position back to the beginning of that record */
if (fseek(fp,
          (long int)(record_number - 1) *
          (long int)sizeof employee,
          SEEK_SET) != 0) {
    perror("Positioning failed");
    fclose(fp);
    return 1;
}

/* Write the modified record */
if (fwrite(&employee, sizeof employee, 1, fp) != 1) {
    fprintf(stderr, "Record update failed.\n");
    fclose(fp);
    return 1;
}

if (fclose(fp) == EOF) {
    perror("File closing failed");
    return 1;
}

The program opens the existing file using rb+ mode, reads the second record, changes its salary, and writes the updated record at the same position.

When switching between input and output operations on an update stream, follow the C standard's positioning and flushing requirements. Here, fseek() is used between the read and write operations to establish the required positioning sequence.

10. Important Rules for File Positioning

  • Always check the return value of fseek().
  • Check ftell() against -1L before using its result.
  • Use SEEK_SET, SEEK_CUR and SEEK_END correctly.
  • For binary streams, offsets are measured in bytes.
  • For text streams, arbitrary byte offsets are not portable.
  • Use rewind() when returning to the beginning is sufficient.
  • Do not assume every stream supports random access.
  • Validate record numbers before calculating offsets.
  • Check arithmetic for overflow in large-file applications.

11. Common Interview Questions

Q1. What is fseek()?

Answer: fseek() changes the file-position indicator to a position relative to a specified origin.

Q2. What are SEEK_SET, SEEK_CUR and SEEK_END?

Answer: They represent the beginning, current position and end of a file, respectively.

Q3. What does ftell() return?

Answer: It returns a long int representing the current file position, or -1L if an error occurs.

Q4. What is the difference between fseek() and rewind()?

Answer: fseek() supports positioning relative to a selected origin and returns a status value. rewind() moves to the beginning and returns no status value.

Q5. How can you find the size of a seekable binary file?

Answer: Move to the end with fseek(fp, 0L, SEEK_END), then obtain the position using ftell().

Q6. What is random file access?

Answer: It is the ability to position a file stream at a selected location and access data without processing every preceding item.

Q7. How do you access the fifth fixed-size record?

Answer: Use an offset of four times the record size from SEEK_SET.

fseek(fp,
      4L * sizeof(struct Employee),
      SEEK_SET);

Q8. Can fseek() be used with every file stream?

Answer: No. Some streams, such as pipes and certain device streams, do not support seeking.

Q9. Why is random access useful in record management?

Answer: It allows a program to retrieve or update a selected fixed-size record without sequentially reading all previous records.

Q10. Does ftell() always return the number of bytes from the beginning?

Answer: Not as a general rule for all streams. Its value is a file-position indicator representation. The simple byte-offset interpretation is appropriate for ordinary binary files.
