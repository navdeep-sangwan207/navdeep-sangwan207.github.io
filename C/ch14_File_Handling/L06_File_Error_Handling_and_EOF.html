Lecture 06: File Error Handling and EOF

Topic: EOF, feof(), ferror(), clearerr() and perror()

C Programming | Chapter 14: File Handling

1. Learning Objectives

After completing this lecture, you will be able to:

  • Understand the EOF concept in C.
  • Differentiate between EOF and the end-of-file indicator.
  • Use feof() to test the end-of-file indicator.
  • Use ferror() to detect stream errors.
  • Use clearerr() to clear stream indicators.
  • Use perror() to display error messages.
  • Handle file-opening, reading and writing failures.
  • Write reliable file-processing programs.

2. What Is EOF in C?

EOF stands for End Of File. It is a special negative integer constant defined in the standard I/O header file <stdio.h>.

Input functions such as fgetc() return EOF when they encounter the end of a file or an input failure.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int ch;

    fp = fopen("data.txt", "r");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    while ((ch = fgetc(fp)) != EOF) {
        putchar(ch);
    }

    fclose(fp);

    return 0;
}

The loop reads characters until fgetc() returns EOF.

Important: Store the result of fgetc() in an int, not a char. The int type can represent every possible unsigned-char value as well as EOF.

3. EOF vs End-of-File Indicator

EOF and the end-of-file indicator are related but different concepts.

EOF End-of-file Indicator
A special negative integer constant. A status indicator maintained by a file stream.
Can be returned by input functions. Can be tested using feof().
Is not a character stored at the end of every file. Is set when an input operation encounters end-of-file.
EOF is not automatically detected before a read attempt. The end-of-file indicator is generally set only after an input operation attempts to read beyond the available input.

4. The feof() Function

The feof() function checks whether the end-of-file indicator is set for a stream.

Syntax

int feof(FILE *stream);

Return Value

  • Returns nonzero if the end-of-file indicator is set.
  • Returns zero if the indicator is not set.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int ch;

    fp = fopen("data.txt", "r");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    while ((ch = fgetc(fp)) != EOF) {
        putchar(ch);
    }

    if (feof(fp)) {
        printf("\nEnd of file reached.\n");
    }

    fclose(fp);

    return 0;
}

Expected Output

Contents of data.txt
End of file reached.

The displayed file contents depend on the actual contents of data.txt.

feof() does not predict whether the next read will reach the end. It checks whether a previous input operation has already set the end-of-file indicator.

5. Why while (!feof(fp)) Is Incorrect

A common beginner mistake is using feof() as the loop condition.

Incorrect approach

while (!feof(fp)) {
    ch = fgetc(fp);
    putchar(ch);
}

This can process an extra invalid input result because the end-of-file indicator is set only after a read operation encounters end-of-file.

Correct approach

int ch;

while ((ch = fgetc(fp)) != EOF) {
    putchar(ch);
}

Here, the return value of the input operation controls the loop.

Placement rule: Check whether the read operation succeeded first. Use feof() afterward when you need to distinguish normal end-of-file from a read error.

6. The ferror() Function

The ferror() function checks whether the error indicator of a file stream is set.

Syntax

int ferror(FILE *stream);

Return Value

  • Returns nonzero if a stream error has occurred.
  • Returns zero if the error indicator is not set.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int ch;

    fp = fopen("data.txt", "r");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    while ((ch = fgetc(fp)) != EOF) {
        putchar(ch);
    }

    if (ferror(fp)) {
        printf("\nAn error occurred while reading.\n");
    } else if (feof(fp)) {
        printf("\nReading completed normally.\n");
    }

    fclose(fp);

    return 0;
}

Explanation

  • fgetc() attempts to read one character at a time.
  • The loop terminates when fgetc() returns EOF.
  • ferror() checks whether an input error occurred.
  • feof() checks whether the stream reached its end.
Both feof() and ferror() return status information. Neither function performs a new read operation.

7. The clearerr() Function

The clearerr() function clears both the end-of-file indicator and the error indicator of a stream.

Syntax

void clearerr(FILE *stream);

It does not return a value.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int ch;

    fp = fopen("data.txt", "r");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    while ((ch = fgetc(fp)) != EOF) {
        putchar(ch);
    }

    if (feof(fp)) {
        printf("\nEnd-of-file indicator is set.\n");
    }

    clearerr(fp);

    if (!feof(fp) && !ferror(fp)) {
        printf("Stream indicators cleared.\n");
    }

    fclose(fp);

    return 0;
}

Expected Output

Contents of data.txt
End-of-file indicator is set.
Stream indicators cleared.

The file position is not reset by clearerr(). If you want to read the file again from its beginning, use rewind() or an appropriate positioning operation.

8. The perror() Function

The perror() function displays a descriptive error message associated with the current value of errno.

Syntax

void perror(const char *str);

It prints the supplied message, followed by a colon and a system error description when available.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;

    fp = fopen("missing.txt", "r");

    if (fp == NULL) {
        perror("Unable to open file");
        return 1;
    }

    fclose(fp);

    return 0;
}

Possible Output

Unable to open file: No such file or directory

The exact error description depends on the operating system and environment.

perror() is useful for diagnosing failures such as missing files, permission problems and other system-level file errors.

9. Understanding errno

errno is an error-reporting facility provided by the C implementation. It is commonly used by library functions to provide additional information about certain failures.

It is declared through standard headers, including <errno.h>.

Example

#include <stdio.h>
#include <errno.h>

int main(void)
{
    FILE *fp;

    errno = 0;

    fp = fopen("missing.txt", "r");

    if (fp == NULL) {
        printf("Error number: %d\n", errno);
        perror("fopen");
        return 1;
    }

    fclose(fp);

    return 0;
}

The numerical value of errno is implementation-dependent. Use perror() or strerror() to obtain a descriptive message.

Do not assume errno is reset to zero by every successful library call. Check it only when the relevant function's documented return value indicates a failure.

10. Handling File-Opening Errors

fopen() returns NULL when a file cannot be opened.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;

    fp = fopen("records.txt", "r");

    if (fp == NULL) {
        perror("Unable to open records.txt");
        return 1;
    }

    printf("File opened successfully.\n");

    if (fclose(fp) == EOF) {
        perror("File closing failed");
        return 1;
    }

    return 0;
}

Possible Reasons for Failure

  • The specified file does not exist when opened for reading.
  • The program does not have sufficient permissions.
  • The specified path is incorrect.
  • The storage device or file system is unavailable.
  • The implementation cannot allocate required resources.

11. Handling Read Errors

For character input, check the return value of fgetc(). For block input, check the item count returned by fread().

Example using fread()

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int numbers[10];

    size_t count;

    fp = fopen("numbers.bin", "rb");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    count = fread(numbers, sizeof numbers[0], 10, fp);

    if (count < 10) {

        if (ferror(fp)) {
            perror("Read error");
        } else if (feof(fp)) {
            printf("Only %zu complete items were available.\n",
                   count);
        }
    } else {
        printf("All 10 integers read successfully.\n");
    }

    if (fclose(fp) == EOF) {
        perror("File closing failed");
        return 1;
    }

    return 0;
}

The program distinguishes between a read error and a normal short read caused by reaching the end of the file.

If fread() returns fewer items than requested, do not assume that the destination array contains valid data in every element. Process only the successfully read items.

12. Handling Write Errors

fwrite() returns the number of complete items successfully written. A smaller count indicates that the entire request was not completed.

Example

#include <stdio.h>

int main(void)
{
    FILE *fp;
    int values[] = {10, 20, 30, 40, 50};

    size_t count;
    int status = 0;

    fp = fopen("values.bin", "wb");

    if (fp == NULL) {
        perror("File opening failed");
        return 1;
    }

    count = fwrite(values, sizeof values[0],
                   sizeof values / sizeof values[0], fp);

    if (count != sizeof values / sizeof values[0]) {
        fprintf(stderr, "Not all values were written.\n");
        status = 1;
    }

    if (ferror(fp)) {
        perror("Stream write error");
        status = 1;
    }

    if (fclose(fp) == EOF) {
        perror("File closing or flushing failed");
        status = 1;
    }

    if (status == 0) {
        printf("Data written successfully.\n");
    }

    return status;
}

Checking fclose() is important because buffered output can fail when the stream is closed and its pending data is flushed.

13. Complete File Processing with Error Handling

This program combines file opening, reading, error detection and closing into one practical example.

Complete C Program

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    FILE *fp;
    int ch;
    int status = EXIT_SUCCESS;

    fp = fopen("input.txt", "r");

    if (fp == NULL) {
        perror("Unable to open input file");
        return EXIT_FAILURE;
    }

    while ((ch = fgetc(fp)) != EOF) {

        if (putchar(ch) == EOF) {
            perror("Output error");
            status = EXIT_FAILURE;
            break;
        }
    }

    if (ferror(fp)) {
        perror("Input file read error");
        status = EXIT_FAILURE;
    } else if (feof(fp)) {
        printf("\nFile reading completed.\n");
    }

    if (fclose(fp) == EOF) {
        perror("Input file close error");
        status = EXIT_FAILURE;
    }

    return status;
}

Expected Output

Contents of input.txt
File reading completed.

The output depends on the contents of input.txt. If the file cannot be opened or read, an appropriate error message is displayed.

14. Important File Error Functions

Function Purpose Return Type
feof() Tests the end-of-file indicator. int
ferror() Tests the stream error indicator. int
clearerr() Clears both stream indicators. void
perror() Prints a descriptive error message. void
fclose() Closes a file stream. int
fopen() Opens a file stream. FILE *

15. Common Mistakes

1. Using feof() as the loop condition

Incorrect:

while (!feof(fp)) {
    ch = fgetc(fp);
}

Correct:

while ((ch = fgetc(fp)) != EOF) {
    /* Process ch */
}

2. Storing fgetc() result in char

Use int to distinguish every valid character value from EOF.

3. Treating EOF as a file character

EOF is a special return value, not a character that must be stored at the end of the file.

4. Ignoring ferror()

A loop ending with EOF may have stopped because of an input error rather than normal end-of-file.

5. Ignoring fclose()

Closing a stream can flush buffered output, so a failure may be reported at that point.

6. Assuming clearerr() resets file position

clearerr() clears indicators only. It does not reposition the stream.

16. Placement-Oriented Interview Questions

Q1. What is EOF?

Answer: EOF is a special negative integer constant returned by certain input functions when they encounter end-of-file or an input failure.

Q2. Is EOF stored as a character at the end of a file?

Answer: No. EOF is a special return value used by input functions.

Q3. What is the purpose of feof()?

Answer: It checks whether the stream's end-of-file indicator is set.

Q4. What is the purpose of ferror()?

Answer: It checks whether the stream's error indicator is set.

Q5. What does clearerr() do?

Answer: It clears both the end-of-file and error indicators for a stream.

Q6. What is the difference between feof() and ferror()?

Answer: feof() checks whether an input operation encountered the end of the file, while ferror() checks whether a stream error occurred.

Q7. Why should fgetc() return value be stored in int?

Answer: Because int can represent all possible unsigned-character values and the special EOF value.

Q8. What does perror() do?

Answer: It prints a descriptive message associated with the current error number.

Q9. Why is while (!feof(fp)) generally incorrect?

Answer: Because the end-of-file indicator is set only after a read attempt reaches the end. The input operation's return value should control the loop.

Q10. Can a successful fwrite() be followed by a failed fclose()?

Answer: Yes. Buffered data may fail to be flushed when fclose() is called, so the closing operation must also be checked.
