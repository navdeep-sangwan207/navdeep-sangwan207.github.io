Chapter 14: File Handling

Lecture 1: File Handling Fundamentals and FILE Pointers

Learn how C programs store, retrieve and manage persistent data using files.

Level: Beginner to Intermediate | Standard: C11

1. Learning Objectives

After completing this lecture, you should be able to:

  • Explain why file handling is required in C programming.
  • Differentiate between volatile memory and persistent storage.
  • Understand files, streams and the FILE type.
  • Explain the purpose of a FILE * pointer.
  • Identify the three standard streams in C.
  • Understand the basic file-handling lifecycle.
  • Open, read, write and close a file using standard C functions.
  • Recognize common file-handling errors asked in technical interviews.

2. Why Do We Need File Handling?

Variables and arrays store data in memory while a program is running. However, this data is generally lost when the program terminates. File handling allows a program to store information in files so that it can be retrieved during a later execution.

Memory vs File Storage

RAM File Storage
Generally volatile memory. Used for persistent storage.
Data normally disappears when power is removed. Data normally remains after the program terminates.
Used for active program data. Used for saving records, reports and configuration.
Accessed through variables, arrays and pointers. Accessed through file streams and file I/O functions.

Real-World Applications

  • Saving student records in an educational management system.
  • Maintaining account details in a banking application.
  • Storing application logs and error messages.
  • Reading configuration files during program startup.
  • Saving sensor measurements in embedded applications.
  • Storing program-generated reports and results.
Placement point: File handling is important because many practical C programs must preserve data beyond a single program execution.

3. What Is a File?

A file is a named collection of data stored on a storage device. A C program can access a file to read existing information, write new information or modify stored information.

Common examples include:

  • students.txt – student information.
  • records.dat – application data.
  • settings.cfg – configuration information.
  • report.txt – generated reports.

Types of Files

Text File Binary File
Stores data as a sequence of characters. Stores data as a sequence of bytes.
Often readable using a text editor. Usually requires an appropriate program to interpret.
Text-mode operations may perform character translations. Binary-mode operations avoid text-mode translations.
Examples: text reports and configuration files. Examples: binary records and image data.
In C, text and binary file modes are distinguished by the mode supplied to fopen(). Detailed mode behavior is covered in Lecture 2.

4. File Handling in C

C provides standard file input/output functions through the <stdio.h> header file.

Important functions include:

Function Purpose
fopen() Opens a file and returns a file stream pointer.
fclose() Closes an opened file stream.
fprintf() Writes formatted output to a file.
fscanf() Reads formatted input from a file.
fputs() Writes a string to a file stream.
fgets() Reads a line or a limited number of characters.
fread() Reads blocks of data.
fwrite() Writes blocks of data.

The functions listed here are part of the C standard I/O library. Their detailed behavior will be covered in the following lectures.

5. Understanding FILE and FILE *

The C standard library defines a type named FILE in <stdio.h>. It represents a file stream. 

#include <stdio.h>

FILE *fp;

What Does FILE * Mean?

  • FILE is a type provided by the standard I/O library.
  • fp is a pointer to a FILE object.
  • The pointer is used to identify the stream in file operations.
  • Functions such as fopen(), fgets() and fclose() work with file stream pointers.

Example

FILE *fp;

fp = fopen("data.txt", "r");

Here, fopen() attempts to open data.txt in read mode. If successful, it returns a pointer to the stream.

Important: The internal representation of FILE is not intended for direct access by application programs. Do not attempt to access or modify its internal members.

6. Standard Streams in C

C provides three standard streams that are available to a program through <stdio.h>.

Stream Purpose Typical Use
stdin Standard input Keyboard input
stdout Standard output Normal program output
stderr Standard error Error messages

Example

#include <stdio.h>

int main(void)
{
    int number;

    printf("Enter a number: ");

    if (scanf("%d", &number) != 1)
    {
        fprintf(stderr, "Invalid input.\n");
        return 1;
    }

    fprintf(stdout, "You entered: %d\n", number);

    return 0;
}

In this example:

  • scanf() reads from stdin.
  • printf() writes to stdout.
  • fprintf(stderr, ...) writes an error message to stderr.
Interview question: What is the difference between stdout and stderr? Both are output streams, but they are intended for normal output and diagnostic output respectively.

7. Basic File Handling Lifecycle

A typical file-handling operation follows these steps:

  1. Declare a FILE * pointer.
  2. Open the file using fopen().
  3. Check whether the returned pointer is NULL.
  4. Perform the required read or write operations.
  5. Close the file using fclose().

Basic Syntax

FILE *fp;

fp = fopen("data.txt", "r");

if (fp == NULL)
{
    /* Handle opening failure */
}

/* Perform file operations */

fclose(fp);
Never use the file stream when fopen() returns NULL. Also, do not use the stream pointer after successfully closing it.

8. Introduction to fopen()

The fopen() function opens a file and associates it with a stream.

Syntax

FILE *fopen(const char *filename, const char *mode);

It accepts two arguments:

  • filename: Name or path of the file.
  • mode: Specifies how the file should be opened.

If opening succeeds, a valid stream pointer is returned. If opening fails, NULL is returned.

Common File Modes – Overview

Mode Basic Purpose
"r" Open an existing text file for reading.
"w" Open a text file for writing; existing contents are discarded.
"a" Open a text file for appending.
"rb" Open a binary file for reading.
"wb" Open a binary file for writing.
"ab" Open a binary file for appending.
"r+" Open an existing file for reading and writing.
"w+" Open a file for reading and writing; discard existing contents.
"a+" Open a file for reading and appending.

The exact behavior of these modes, including the + and b modifiers, is explained in Lecture 2.

9. First File Handling Program

This program demonstrates the basic file-handling lifecycle. It creates a text file, writes a message, closes it, reopens it and reads the saved content.

Program: Write and Read a Text File

#include <stdio.h>

int main(void)
{
    FILE *fp;
    char buffer[100];

    /* Open file for writing */
    fp = fopen("example.txt", "w");

    if (fp == NULL)
    {
        perror("Unable to open file for writing");
        return 1;
    }

    /* Write data */
    if (fputs("Welcome to C File Handling!\n", fp) == EOF)
    {
        fprintf(stderr, "Error while writing to file.\n");
        fclose(fp);
        return 1;
    }

    /* Close the file */
    if (fclose(fp) == EOF)
    {
        fprintf(stderr, "Error while closing the file.\n");
        return 1;
    }

    printf("Data written successfully.\n");

    /* Reopen file for reading */
    fp = fopen("example.txt", "r");

    if (fp == NULL)
    {
        perror("Unable to open file for reading");
        return 1;
    }

    /* Read data */
    if (fgets(buffer, sizeof(buffer), fp) != NULL)
    {
        printf("Data read from file: ");
        fputs(buffer, stdout);
    }
    else
    {
        printf("No data could be read.\n");
    }

    /* Close the file */
    if (fclose(fp) == EOF)
    {
        fprintf(stderr, "Error while closing the file.\n");
        return 1;
    }

    return 0;
}

Expected Output

Data written successfully. Data read from file: Welcome to C File Handling!

Content of example.txt

Welcome to C File Handling!

Program Explanation

  1. FILE *fp declares a file stream pointer.
  2. fopen("example.txt", "w") opens the file for writing.
  3. The NULL check handles a possible opening failure.
  4. fputs() writes the message to the file.
  5. fclose() closes the writing stream.
  6. The file is reopened using read mode.
  7. fgets() reads the saved line into the character array.
  8. fputs() displays the read string on standard output.
Important observation: The file is closed before it is reopened for reading. This makes the write-then-read sequence clear and ensures the output stream is closed before the next stream is opened.

10. File Paths and Working Directories

A file can be opened using either a relative path or an absolute path.

Relative Path

A relative path is interpreted from the program's current working directory. 

FILE *fp = fopen("example.txt", "r");

The program looks for example.txt relative to its current working directory.

Absolute Path

An absolute path identifies the file using its full location. 

/* Example Windows path */
FILE *fp = fopen("C:/Users/Student/Documents/example.txt", "r");

Forward slashes are accepted by common Windows C runtime implementations. If backslashes are used in a C string, they must be escaped. 

FILE *fp = fopen("C:\\Users\\Student\\Documents\\example.txt", "r");
A relative path is not automatically relative to the folder containing the source code. It is relative to the process's current working directory.

11. Why Can fopen() Fail?

File opening can fail for several reasons. A robust program must check the return value of fopen().

Reason Example
File does not exist Trying to read a file that has not been created.
Invalid path Providing an incorrect directory name.
Permission problem Attempting to write into a protected directory.
Resource exhaustion The environment cannot allocate another stream.
Operating system or device error The storage device is unavailable.

Using perror()

#include <stdio.h>

int main(void)
{
    FILE *fp;

    fp = fopen("missing.txt", "r");

    if (fp == NULL)
    {
        perror("fopen failed");
        return 1;
    }

    fclose(fp);

    return 0;
}

perror() prints the supplied message followed by an implementation-provided description of the error associated with errno.

Placement point: Checking fp == NULL after fopen() is a basic requirement in reliable C file-handling code.

12. Importance of fclose()

The fclose() function closes a file stream. It is important for two main reasons:

  • It releases resources associated with the stream.
  • It flushes buffered output data before closing the stream.

Syntax

int fclose(FILE *stream);
Return Value Meaning
0 Successful closure.
EOF An error occurred while closing the stream.
Do not assume that a successful fputs() or fprintf() call guarantees that all data has been successfully stored on the device. Buffered output may be transferred later. Check fclose() when write reliability matters.

After a stream has been successfully closed, its pointer must not be used for further stream operations.

13. FILE Pointer vs File Descriptor

These terms are related but they are not the same.

FILE Pointer File Descriptor
Used by the C standard I/O library. Used by operating-system interfaces such as POSIX.
Has type FILE *. Typically represented as an integer in POSIX systems.
Works with functions such as fopen() and fclose(). Works with interfaces such as open() and close() on POSIX systems.
Provides stream-oriented I/O, including buffering. Represents an operating-system-level file handle.
Interview question: Is a FILE * pointer the same as a file descriptor?
Answer: No. A FILE * identifies a C standard I/O stream, while a file descriptor is an operating-system-level identifier. POSIX provides fileno() to obtain a descriptor associated with a stream, but that function is not part of ISO C11.

14. Common File Handling Mistakes

Mistake Correct Approach
Not checking the return value of fopen(). Always check whether the pointer is NULL.
Forgetting to close a file. Close every successfully opened stream when finished.
Using a stream after closing it. Do not perform operations on a closed stream.
Using the wrong opening mode. Choose the mode according to the required operation.
Assuming a relative path starts from the source file directory. Check the process's current working directory.
Ignoring write or close errors. Check the return values of relevant I/O operations.
Confusing EOF with the null character. Understand their different meanings; they are not interchangeable.

15. Technical Interview Questions

Q1. Why is file handling required in C?

It allows programs to store and retrieve information persistently, even after the program terminates.

Q2. Which header file is required for standard file handling?

<stdio.h>.

Q3. What is FILE in C?

FILE is a type defined by the C standard I/O library to represent a file stream.

Q4. What does FILE * represent?

It is a pointer to a FILE object and is used to identify a stream in standard file operations.

Q5. What does fopen() return when opening fails?

It returns a null pointer, NULL.

Q6. Why should fclose() be called?

It closes the stream, releases associated resources and flushes buffered output.

Q7. What are stdin, stdout and stderr?

They are the standard input, standard output and standard error streams respectively.

Q8. What is the difference between text and binary files?

Text files are handled as character-oriented data and may involve text translations. Binary files are handled as byte-oriented data without text-mode translations.

Q9. Is FILE * a file descriptor?

No. A FILE * is a C standard I/O stream pointer. A file descriptor is an operating-system-level identifier.

Q10. What happens if a program does not close an opened file?

The stream may remain open until program termination, consuming resources. Buffered output may also not be finalized at the intended point in the program.
