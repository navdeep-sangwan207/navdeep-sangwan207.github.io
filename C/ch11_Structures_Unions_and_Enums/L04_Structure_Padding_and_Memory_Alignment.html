Lecture 04: Structure Padding and Memory Alignment

Understand structure memory layout, alignment requirements, compiler-inserted padding, structure size calculation and memory optimization techniques used in C and embedded systems.

1. Learning Objectives

  • Understand how structure members are arranged in memory.
  • Understand byte alignment and alignment requirements.
  • Learn why compilers insert padding bytes.
  • Calculate structure size for common examples.
  • Understand the role of sizeof and offsetof.
  • Compare different member arrangements.
  • Learn how member ordering can reduce padding.
  • Understand nested structure alignment.
  • Explore alignment considerations in embedded systems.
  • Answer placement-oriented memory-layout questions.

2. How Are Structure Members Stored in Memory?

A structure groups variables of different data types under one name. 

struct Data
{
    char a;
    int b;
    float c;
};

The compiler allocates memory for all structure members. However, members are not necessarily placed immediately next to each other without gaps.

The compiler may insert extra bytes between members or after the final member. These extra bytes are called padding.

Structure padding is additional memory inserted by the compiler to satisfy alignment requirements of structure members.

3. What Is Memory Alignment?

Memory alignment is the placement of an object at an address that satisfies the alignment requirement of its data type.

For example, a particular implementation may require a 4-byte integer to begin at an address divisible by 4.

Address Divisible by 4? 4-byte alignment
1000 Yes Aligned
1004 Yes Aligned
1002 No Not aligned
1005 No Not aligned

Alignment requirements depend on the implementation and the data type.

Do not assume that every C compiler uses the same size or alignment for int, float, double or pointers. These properties are implementation-dependent.

4. Why Does the Compiler Insert Padding?

Many processors and memory systems access aligned data more efficiently. Some architectures also impose restrictions on unaligned accesses.

To satisfy these requirements, the compiler may insert unused bytes between structure members.

Example

struct Example
{
    char a;
    int b;
};

Assume the implementation uses:

  • char size: 1 byte, alignment: 1 byte
  • int size: 4 bytes, alignment: 4 bytes

A possible memory layout is: 

Offset       Contents
--------------------------------
0            char a
1            Padding
2            Padding
3            Padding
4 - 7        int b
--------------------------------
Total size   8 bytes

Three padding bytes are inserted before b so that the integer begins at an address aligned to 4 bytes.

This is a common illustrative layout, not a universal C language guarantee. Actual layout depends on the compiler and ABI.

5. Understanding Structure Size with sizeof

The sizeof operator returns the size of a structure object in bytes. 

#include <stdio.h>

struct Example
{
    char a;
    int b;
};

int main(void)
{
    printf("Size of char: %zu\n", sizeof(char));
    printf("Size of int: %zu\n", sizeof(int));
    printf("Size of structure: %zu\n",
           sizeof(struct Example));

    return 0;
}

On an implementation where char is 1 byte, int is 4 bytes and the structure layout uses the alignment described above:

Illustrative Output: 
Size of char: 1
Size of int: 4
Size of structure: 8

The %zu format specifier is used to print values of type size_t, which is the type returned by sizeof.

6. Structure Tail Padding

Padding may also be inserted after the final structure member. 

struct Sample
{
    int a;
    char b;
};

Assume int has size and alignment of 4 bytes and char has size and alignment of 1 byte. 

Offset       Contents
--------------------------------
0 - 3        int a
4            char b
5            Padding
6            Padding
7            Padding
--------------------------------
Total size   8 bytes

The structure size is rounded up to a multiple of its alignment requirement in this common layout.

Why Is Tail Padding Needed?

Consider an array of these structures. Each element must begin at an address satisfying the structure's alignment requirement. 

struct Sample values[3];

If each structure occupies 8 bytes, elements begin 8 bytes apart. Each element remains properly aligned.

7. Member Ordering and Padding

The order of structure members can affect the amount of padding inserted.

Structure A

struct A
{
    char a;
    int b;
    char c;
};

Assuming the common alignment model:

Offset       Contents
--------------------------------
0            char a
1 - 3        Padding
4 - 7        int b
8            char c
9 - 11       Tail padding
--------------------------------
Total size   12 bytes

Structure B

struct B
{
    int b;
    char a;
    char c;
};
Offset       Contents
--------------------------------
0 - 3        int b
4            char a
5            char c
6 - 7        Tail padding
--------------------------------
Total size   8 bytes

Both structures contain the same members, but their sizes differ in this example.

Grouping members with stricter alignment requirements before smaller-alignment members can reduce padding on many common implementations.

8. Comparing Structure Sizes

#include <stdio.h>

struct A
{
    char a;
    int b;
    char c;
};

struct B
{
    int b;
    char a;
    char c;
};

int main(void)
{
    printf("Size of A: %zu\n", sizeof(struct A));
    printf("Size of B: %zu\n", sizeof(struct B));

    return 0;
}
Illustrative Output on a Common ABI: 
Size of A: 12
Size of B: 8

Actual values must be checked on the target compiler and architecture.

9. Using offsetof to Find Member Positions

C provides the offsetof macro in stddef.h to determine the byte offset of a structure member. 

#include <stdio.h>
#include <stddef.h>

struct Data
{
    char a;
    int b;
    char c;
};

int main(void)
{
    printf("Offset of a: %zu\n",
           offsetof(struct Data, a));

    printf("Offset of b: %zu\n",
           offsetof(struct Data, b));

    printf("Offset of c: %zu\n",
           offsetof(struct Data, c));

    printf("Structure size: %zu\n",
           sizeof(struct Data));

    return 0;
}
Illustrative Output on a Common ABI: 
Offset of a: 0
Offset of b: 4
Offset of c: 8
Structure size: 12

offsetof is useful for examining memory layout and understanding compiler-generated structure arrangements.

offsetof is especially useful when working with low-level data structures, embedded interfaces and container-style programming.

10. Alignment of Nested Structures

A nested structure also has its own size and alignment requirements. 

struct Inner
{
    char a;
    int b;
};

struct Outer
{
    char x;
    struct Inner data;
    char y;
};

Assuming the common alignment model used in previous examples: 

struct Inner:
--------------------------------
Offset 0       char a
Offset 1-3     Padding
Offset 4-7     int b
Size           8 bytes

struct Outer:
--------------------------------
Offset 0       char x
Offset 1-3     Padding
Offset 4-11    struct Inner data
Offset 12      char y
Offset 13-15   Tail padding
Size           16 bytes

The nested structure begins at an address that satisfies its alignment requirement.

11. Understanding _Alignof in C11

C11 introduced the _Alignof operator to obtain the alignment requirement of a type. 

#include <stdio.h>

struct Data
{
    char a;
    int b;
    double c;
};

int main(void)
{
    printf("Alignment of char: %zu\n",
           _Alignof(char));

    printf("Alignment of int: %zu\n",
           _Alignof(int));

    printf("Alignment of double: %zu\n",
           _Alignof(double));

    printf("Alignment of structure: %zu\n",
           _Alignof(struct Data));

    return 0;
}

The exact output depends on the implementation.

_Alignof is useful when investigating alignment requirements on the compiler and target architecture used in a project.

12. Explicit Alignment with _Alignas

C11 provides the _Alignas specifier to request a specified alignment for an object or member declaration, subject to the constraints of the language. 

#include <stdio.h>
#include <stdalign.h>

struct Data
{
    _Alignas(16) int value;
};

int main(void)
{
    struct Data d;

    printf("Alignment of int: %zu\n",
           _Alignof(int));

    printf("Alignment of structure: %zu\n",
           _Alignof(struct Data));

    printf("Address of member: %p\n",
           (void *)&d.value);

    return 0;
}

The requested alignment is 16 bytes for the member, provided the implementation supports that alignment request.

Do not confuse _Alignas with packed structures. _Alignas requests stricter alignment; it does not remove padding or guarantee a smaller structure.

13. Packed Structures and Compiler Extensions

Some compilers provide non-standard extensions that allow structure packing.

For example, GCC supports: 

#include <stdio.h>

struct __attribute__((packed)) PackedData
{
    char a;
    int b;
    char c;
};

int main(void)
{
    printf("Packed structure size: %zu\n",
           sizeof(struct PackedData));

    return 0;
}

On a GCC target where the extension is supported, the compiler will generally remove the padding between these members and after the last member.

__attribute__((packed)) is a compiler extension, not standard C11. Packed members may be unaligned. Accessing them can be slower or require special compiler-generated operations. It may also be unsafe to take their addresses and use them as normally aligned pointers.

Use packing only when the data format requires it and the target compiler and processor behavior are understood.

14. Structure Padding in Embedded Systems

Structure layout is important in embedded systems because memory resources and hardware interfaces can be constrained.

Common Applications

  • Sensor data structures.
  • Communication protocol packets.
  • Peripheral configuration structures.
  • DMA data buffers.
  • Firmware state structures.
  • Memory-mapped hardware interfaces.

Example: Sensor Data Structure

#include <stdio.h>

struct SensorData
{
    unsigned int timestamp;
    float temperature;
    float pressure;
    unsigned char status;
};

int main(void)
{
    struct SensorData data = {
        1000,
        28.5f,
        1012.4f,
        1
    };

    printf("Timestamp: %u\n", data.timestamp);
    printf("Temperature: %.2f\n", data.temperature);
    printf("Pressure: %.2f\n", data.pressure);
    printf("Status: %u\n", (unsigned int)data.status);

    printf("Structure size: %zu\n",
           sizeof(data));

    return 0;
}

The structure can represent one sensor measurement record. Its exact memory layout must be verified for the target compiler and processor.

Important Embedded C Considerations

  • Check structure size on the actual target compiler.
  • Consider alignment when designing DMA buffers.
  • Do not assume structure layout is portable across different compilers.
  • Use explicit serialization for communication protocols.
  • Do not assume a structure can be safely transmitted as raw bytes.
A C structure is not automatically a portable network packet or hardware register map. Padding, byte order, integer representation and alignment can differ across systems.

15. Structure Padding vs Memory Wastage

Padding increases the size of a structure, but it is not necessarily useless memory. It can be required for correct and efficient access on the target architecture.

Aspect Explanation
Padding bytes Unused bytes inserted to satisfy layout requirements.
Alignment Requirement for an object's address.
Tail padding Padding after the final member.
Member reordering May reduce padding while preserving member names and types.
Packing Compiler-specific layout control that can create unaligned members.

16. Important Placement Interview Questions

Q1. What is structure padding?

Extra bytes inserted by the compiler between members or at the end of a structure to satisfy alignment requirements.

Q2. What is memory alignment?

The requirement that an object be placed at an address suitable for its type.

Q3. Why does the compiler insert padding?

To satisfy alignment requirements and support efficient or valid memory access on the target architecture.

Q4. What is tail padding?

Extra bytes after the last structure member, often used to ensure the size of each array element preserves the structure's alignment.

Q5. Does member order affect structure size?

Yes. Different member arrangements can cause different amounts of padding.

Q6. How can structure padding be reduced?

On many common implementations, arranging members from stricter to smaller alignment requirements can reduce padding.

Q7. What does sizeof return for a structure?

The total size of the structure object, including any padding bytes.

Q8. What is offsetof?

A macro from stddef.h that returns the byte offset of a specified structure member.

Q9. What is _Alignof?

A C11 operator that obtains the alignment requirement of a type.

Q10. What is _Alignas?

A C11 alignment specifier used to request a particular alignment for an object or member declaration.

Q11. Is packed structure part of standard C?

No. Common packed-structure syntax such as GCC's __attribute__((packed)) is a compiler extension.

Q12. Is structure layout identical on every compiler?

No. Sizes, alignment and padding can depend on the implementation and ABI.

Q13. Can padding affect communication protocols?

Yes. Raw structure transmission may include padding and implementation-specific layouts. Explicit serialization is safer.

Q14. Why is alignment important for DMA?

DMA controllers and hardware interfaces may impose buffer address and alignment constraints. The exact requirements are device-specific.

17. Output Prediction and Memory Layout Problems

Question 1

#include <stdio.h>

struct A
{
    char x;
    int y;
};

int main(void)
{
    printf("%zu\n", sizeof(struct A));

    return 0;
}

Answer: The exact size is implementation-dependent. A common ABI with 4-byte int alignment produces 8 bytes.

Question 2

#include <stdio.h>

struct B
{
    int x;
    char y;
};

int main(void)
{
    printf("%zu\n", sizeof(struct B));

    return 0;
}

Answer: A common ABI produces 8 bytes due to tail padding.

Question 3

#include <stdio.h>
#include <stddef.h>

struct C
{
    int a;
    char b;
};

int main(void)
{
    printf("%zu\n", offsetof(struct C, b));

    return 0;
}

Answer: On common implementations where int occupies 4 bytes, the offset of b is 4. The exact layout is implementation-dependent.

Question 4

If a structure contains three char members, can its size be assumed to be exactly 3 bytes?

Answer: No universal guarantee should be assumed about all implementations. Check sizeof on the target compiler.

18. Practical Coding Exercises

Basic Level

  1. Write a program to print the size of a structure.
  2. Use sizeof to compare the sizes of char, int, float and double.
  3. Use offsetof to print the offsets of all structure members.
  4. Use _Alignof to inspect the alignment of common types.

Intermediate Level

  1. Create two structures with the same members in different orders and compare their sizes.
  2. Calculate possible padding for a nested structure.
  3. Use _Alignas to request a larger alignment.
  4. Write a program that reports structure size and member offsets for a sensor data structure.

Advanced Level

  1. Optimize a firmware data structure for memory usage without changing its logical members.
  2. Investigate structure layout using compiler-generated information or debugger inspection.
  3. Design a portable serialization routine that does not transmit raw structure padding.
  4. Compare aligned and packed layouts using a supported compiler extension.
  5. Analyze alignment requirements for a DMA buffer on a selected microcontroller.

19. Compiler Practice

Save your program as structure_layout.c. Compile it using GCC in C11 mode: 

gcc -std=c11 -Wall -Wextra -pedantic structure_layout.c -o structure_layout

Run the program:

./structure_layout

On Windows with GCC, use: 

gcc -std=c11 -Wall -Wextra -pedantic structure_layout.c -o structure_layout.exe

structure_layout.exe
Compare results using the same compiler on different target architectures when available. Record sizeof, offsetof and _Alignof values rather than assuming a universal memory layout.

20. Quick Revision Checklist

  • Structure members are arranged according to implementation-defined layout rules.
  • Padding can occur between members and after the final member.
  • Alignment requirements depend on the implementation.
  • sizeof includes structure padding.
  • offsetof identifies a member's byte offset.
  • _Alignof obtains a type's alignment requirement in C11.
  • _Alignas requests a specified alignment.
  • Member ordering can reduce padding on common implementations.
  • Packed structures generally use compiler extensions.
  • Unaligned accesses can have performance or correctness consequences.
  • Verify structure layouts on the actual embedded target.
  • Use explicit serialization for portable communication formats.
