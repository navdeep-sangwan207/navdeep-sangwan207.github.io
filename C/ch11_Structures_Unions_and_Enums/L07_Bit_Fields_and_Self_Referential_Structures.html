Lecture 07: Bit Fields and Self-Referential Structures

Understand how to declare bit fields inside structures, manipulate compact status information, and build self-referential structures used in linked lists, trees and embedded firmware.

1. Learning Objectives

  • Understand bit fields in C structures.
  • Learn bit-field declaration and syntax.
  • Control the width of structure members.
  • Understand bit-field storage and implementation dependence.
  • Use bit fields for status and control information.
  • Understand bit-field limitations and restrictions.
  • Learn self-referential structure declarations.
  • Understand how structure pointers connect nodes.
  • Build a simple linked list using self-referential structures.
  • Understand practical applications in embedded systems and interviews.

Part A: Bit Fields

2. What Are Bit Fields?

A bit field is a structure member declared with a specified number of bits.

Ordinary structure members occupy storage according to their data types. Bit fields allow a program to specify a width for certain integer members.

Example

struct Status
{
    unsigned int ready : 1;
    unsigned int error : 1;
    unsigned int mode  : 2;
};

Here:

  • ready has a width of 1 bit.
  • error has a width of 1 bit.
  • mode has a width of 2 bits.

These declarations request compact bit-field storage. The exact allocation and overall structure layout depend on the implementation.

Bit fields are useful when representing small integer values or flags that require only a limited number of bits.

3. Bit-Field Declaration Syntax

struct StructureName
{
    integer_type member_name : width;
};

The width specifies the number of bits allocated to the bit field.

Example

struct DeviceStatus
{
    unsigned int power : 1;
    unsigned int fault : 1;
    unsigned int speed : 3;
    unsigned int reserved : 3;
};

The declared widths total 8 bits. This does not guarantee that the entire structure occupies exactly one byte.

Bit-field allocation units, member ordering within those units, alignment and padding are implementation-dependent.

4. Understanding Bit Width

The width determines the number of bits available to represent a value.

Width Possible unsigned values
1 bit 0 to 1
2 bits 0 to 3
3 bits 0 to 7
4 bits 0 to 15
8 bits 0 to 255

For an unsigned bit field of width n, the mathematical range is:

\[ 0 \text{ to } (2^n - 1) \]

This range describes the representable unsigned values when the implementation supports the declared field as expected.

5. Using Bit Fields in a Program

#include <stdio.h>

struct Status
{
    unsigned int ready : 1;
    unsigned int error : 1;
    unsigned int mode  : 2;
};

int main(void)
{
    struct Status device = {0};

    device.ready = 1;
    device.error = 0;
    device.mode = 2;

    printf("Ready: %u\n", device.ready);
    printf("Error: %u\n", device.error);
    printf("Mode: %u\n", device.mode);

    return 0;
}
Output: 
Ready: 1
Error: 0
Mode: 2

The program assigns values to individual bit fields using ordinary member access.

6. Bit-Field Value Range and Overflow

A bit field can represent only values that fit within its declared width. 

#include <stdio.h>

struct Flags
{
    unsigned int value : 3;
};

int main(void)
{
    struct Flags f;

    f.value = 5;

    printf("Value: %u\n", f.value);

    return 0;
}
Output: 
Value: 5

A 3-bit unsigned field can represent values from 0 to 7.

Do not rely on assigning an out-of-range value to a bit field. For unsigned bit fields, the resulting value is determined by the applicable conversion rules; for signed bit fields, out-of-range behavior can be implementation-defined or otherwise constrained. Validate values before assignment.

7. Signed and Unsigned Bit Fields

Bit fields can be declared using signed or unsigned integer types. 

struct Data
{
    unsigned int positive : 4;
    signed int signed_value : 4;
};

An unsigned 4-bit field can represent values from 0 to 15.

A signed 4-bit field commonly represents values from -8 to 7 when using two's complement representation, but the precise representation and range rules must be considered for the target implementation and C version.

For portable bit-field programming, unsigned integer bit fields are generally easier to reason about when representing flags and non-negative values.

8. Unnamed Bit Fields

An unnamed bit field can be used to reserve bits or influence allocation boundaries. 

struct RegisterFields
{
    unsigned int enable : 1;
    unsigned int        : 3;
    unsigned int mode   : 2;
};

The unnamed field has no member name and cannot be accessed directly.

Zero-Width Unnamed Bit Field

struct Data
{
    unsigned int first : 3;
    unsigned int       : 0;
    unsigned int second : 4;
};

A zero-width unnamed bit field forces the next bit field to begin at an allocation-unit boundary according to the implementation's rules.

A zero-width bit field is not a portable way to specify an exact byte offset. The resulting layout still depends on the implementation.

9. Important Bit-Field Restrictions

  • Bit fields must have an appropriate integer or _Bool type permitted by the C standard.
  • Bit-field width must be a non-negative integer constant expression.
  • The width cannot exceed the permitted width for its declared type.
  • A named bit field cannot have width zero.
  • Unnamed bit fields are not directly accessible.
  • You cannot apply sizeof directly to a bit-field member.
  • You cannot take the address of an individual bit field.
  • Bit fields cannot be arrays or ordinary pointer members.
struct Example
{
    unsigned int flag : 1;
};

/* Not valid:
   sizeof(((struct Example *)0)->flag);
*/

/* Not valid:
   unsigned int *ptr = &example.flag;
*/

10. Practical Bit-Field Example: Device Status

#include <stdio.h>

typedef struct
{
    unsigned int power_on : 1;
    unsigned int motor_on : 1;
    unsigned int fault    : 1;
    unsigned int mode     : 2;
} DeviceStatus;

int main(void)
{
    DeviceStatus status = {0};

    status.power_on = 1;
    status.motor_on = 1;
    status.fault = 0;
    status.mode = 2;

    printf("Power: %u\n", status.power_on);
    printf("Motor: %u\n", status.motor_on);
    printf("Fault: %u\n", status.fault);
    printf("Mode: %u\n", status.mode);

    return 0;
}
Output: 
Power: 1
Motor: 1
Fault: 0
Mode: 2

The structure provides a readable way to represent a collection of status fields.

11. Bit Fields vs Bitwise Operators

Bit fields and bitwise operators are related to bit-level programming, but they are different mechanisms.

Bit Fields Bitwise Operators
Declared inside structures or unions. Used in expressions on integer operands.
Compiler controls field allocation and layout. Programmer controls operations on integer bits.
Useful for compact named fields. Useful for masks, shifts and register manipulation.
Cannot take the address of an individual field. Can manipulate integer objects using normal operators.

Bitwise Mask Example

#include <stdio.h>

int main(void)
{
    unsigned int status = 0;

    status |= (1U << 0);
    status |= (1U << 2);

    printf("Status: %u\n", status);

    return 0;
}
Output: 
Status: 5
In embedded C, bitwise masks are often preferred for hardware register access because they provide explicit control over bit positions.

Part B: Self-Referential Structures

12. What Is a Self-Referential Structure?

A self-referential structure is a structure that contains a pointer to another object of the same structure type.

Syntax

struct Node
{
    int data;
    struct Node *next;
};

Here, next is a pointer to another struct Node object.

A self-referential structure does not contain a complete object of its own type as a member. It contains a pointer to that type.

13. Why Are Self-Referential Structures Needed?

They allow multiple structure objects to be connected through pointers.

This makes it possible to create dynamic data structures such as:

  • Singly linked lists.
  • Doubly linked lists.
  • Circular linked lists.
  • Trees.
  • Graphs.
  • Dynamic queues and stacks.

Conceptual Linked List

+---------+      +---------+      +---------+
| Data:10 | ---> | Data:20 | ---> | Data:30 |
| Next    |      | Next    |      | NULL    |
+---------+      +---------+      +---------+
   Node 1           Node 2           Node 3

Each node stores data and a pointer to the next node.

14. Declaring a Self-Referential Structure

struct Node
{
    int data;
    struct Node *next;
};

The declaration is valid because next is a pointer. The size of a pointer is known independently of the size of struct Node.

Invalid Declaration

struct Node
{
    int data;
    struct Node next;
};

This declaration is invalid because it attempts to include a complete object of the same structure type inside itself. That would require an infinitely large object.

15. Creating Nodes Dynamically

Nodes can be allocated dynamically using malloc. 

#include <stdio.h>
#include <stdlib.h>

struct Node
{
    int data;
    struct Node *next;
};

int main(void)
{
    struct Node *first = malloc(sizeof *first);

    if (first == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    first->data = 100;
    first->next = NULL;

    printf("Data: %d\n", first->data);

    free(first);

    return 0;
}
Output: 
Data: 100

The program allocates one node, initializes its members, uses the node and releases its memory.

16. Creating Two Connected Nodes

#include <stdio.h>
#include <stdlib.h>

struct Node
{
    int data;
    struct Node *next;
};

int main(void)
{
    struct Node *first = malloc(sizeof *first);
    struct Node *second = malloc(sizeof *second);

    if (first == NULL || second == NULL)
    {
        free(first);
        free(second);

        printf("Memory allocation failed\n");
        return 1;
    }

    first->data = 10;
    first->next = second;

    second->data = 20;
    second->next = NULL;

    printf("%d\n", first->data);
    printf("%d\n", first->next->data);

    free(second);
    free(first);

    return 0;
}
Output: 
10
20

The next pointer of the first node points to the second node.

17. Building a Singly Linked List

A singly linked list is a collection of nodes where each node contains data and a pointer to the next node.

Complete Program: Create and Traverse a Linked List

#include <stdio.h>
#include <stdlib.h>

struct Node
{
    int data;
    struct Node *next;
};

int main(void)
{
    struct Node *head = NULL;
    struct Node *second = NULL;
    struct Node *third = NULL;
    struct Node *current;

    head = malloc(sizeof *head);
    second = malloc(sizeof *second);
    third = malloc(sizeof *third);

    if (head == NULL || second == NULL || third == NULL)
    {
        free(head);
        free(second);
        free(third);

        printf("Memory allocation failed\n");
        return 1;
    }

    head->data = 10;
    head->next = second;

    second->data = 20;
    second->next = third;

    third->data = 30;
    third->next = NULL;

    current = head;

    while (current != NULL)
    {
        printf("%d -> ", current->data);
        current = current->next;
    }

    printf("NULL\n");

    free(third);
    free(second);
    free(head);

    return 0;
}
Output: 
10 -> 20 -> 30 -> NULL

The traversal starts at head and follows each next pointer until NULL is reached.

18. Self-Referential Structures with typedef

typedef can simplify the declaration of self-referential structures. 

#include <stdio.h>

typedef struct Node
{
    int data;
    struct Node *next;
} Node;

int main(void)
{
    Node first;
    Node second;

    first.data = 10;
    second.data = 20;

    first.next = &second;
    second.next = NULL;

    printf("%d\n", first.data);
    printf("%d\n", first.next->data);

    return 0;
}
Output: 
10
20

Notice that the pointer member is declared as struct Node *next. The structure tag is used because the typedef alias Node is not available until the declaration has completed.

19. Self-Referential Structure in a Doubly Linked List

A doubly linked list node contains two pointers:

  • prev points to the previous node.
  • next points to the next node.
struct DNode
{
    int data;
    struct DNode *prev;
    struct DNode *next;
};
NULL <--- [10] <---> [20] <---> [30] ---> NULL

This structure supports traversal in both forward and backward directions.

20. Self-Referential Structures in Trees

A binary tree node contains pointers to its left and right child nodes. 

struct TreeNode
{
    int data;
    struct TreeNode *left;
    struct TreeNode *right;
};
              [10]
              /  \
            [5]  [20]
            / \
          [2] [7]

The structure allows a node to connect to two other nodes of the same type.

21. Bit Fields and Hardware Registers: Important Caution

Bit fields may appear attractive for representing hardware register bits. However, their layout is not fully portable.

The following aspects can vary:

  • Bit allocation order within storage units.
  • Whether fields cross allocation-unit boundaries.
  • Alignment and padding.
  • Access width and compiler-generated instructions.

For hardware register manipulation, explicit masks and shifts are often more predictable. 

#include <stdint.h>

#define CONTROL_ENABLE_MASK  (1U << 0)
#define CONTROL_MODE_MASK    (3U << 1)

void configure_control(volatile uint32_t *reg)
{
    *reg |= CONTROL_ENABLE_MASK;

    *reg &= ~CONTROL_MODE_MASK;

    *reg |= (2U << 1);
}
This example illustrates register bit manipulation. Actual hardware code must follow the microcontroller reference manual, register access rules and read-modify-write requirements.

22. Common Mistakes and Pitfalls

Mistake Explanation
Assuming bit fields occupy exactly their declared total width Allocation units, alignment and padding depend on implementation.
Taking the address of a bit field The address-of operator cannot be applied to a bit-field member.
Using an invalid bit-field width Widths must satisfy the C language constraints.
Declaring a structure as its own complete member This would create an infinitely large object.
Forgetting to initialize next pointers Uninitialized pointers can cause invalid memory access.
Forgetting to release dynamically allocated nodes This causes memory leaks.
Dereferencing a NULL pointer It results in undefined behavior.
Accessing freed nodes This creates dangling-pointer use and undefined behavior.

23. Placement-Oriented Interview Questions

Q1. What is a bit field in C?

A structure member declared with a specified number of bits.

Q2. Why are bit fields used?

They can represent small integer values and flags using compact storage.

Q3. Can we take the address of a bit field?

No. The address-of operator cannot be applied to a bit field.

Q4. Can sizeof be applied to a bit field?

No. sizeof cannot be applied directly to a bit-field member.

Q5. What is an unnamed bit field?

A bit field without a member name, which can reserve bits or influence allocation boundaries.

Q6. What does a zero-width unnamed bit field do?

It forces the next bit field to begin at an allocation-unit boundary according to the implementation.

Q7. What is a self-referential structure?

A structure containing a pointer to another object of the same structure type.

Q8. Why can a structure contain a pointer to itself?

The pointer has a known size independent of the complete structure size.

Q9. Why can't a structure contain an ordinary member of its own type?

It would require an infinitely large object, so the declaration is invalid.

Q10. Where are self-referential structures used?

Linked lists, trees, graphs and other dynamic data structures.

Q11. What is the difference between a singly and doubly linked list node?

A singly linked list node has one link pointer. A doubly linked list node has pointers to both previous and next nodes.

Q12. Why are bit fields not always recommended for hardware registers?

Their layout and access behavior are implementation-dependent. Explicit masks and shifts can provide more predictable control.

struct Flags

Question 2: Self-Referential Pointer

#include <stdio.h>

struct Node
{
    int data;
    struct Node *next;
};

int main(void)
{
    struct Node second = {20, NULL};
    struct Node first = {10, &second};

    printf("%d\n", first.next->data);

    return 0;
}

Answer:

20

Question 3: Pointer Traversal

#include <stdio.h>

struct Node
{
    int data;
    struct Node *next;
};

int main(void)
{
    struct Node c = {30, NULL};
    struct Node b = {20, &c};
    struct Node a = {10, &b};

    struct Node *ptr = &a;

    ptr = ptr->next;

    printf("%d\n", ptr->data);

    return 0;
}

Answer:

20

Question 4: Structure Declaration

Is this declaration valid? 

struct Node
{
    int data;
    struct Node next;
};

Answer:

No. A structure cannot contain a complete member of its own type. A pointer to the same structure type must be used instead.
