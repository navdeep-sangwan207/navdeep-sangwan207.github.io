Understand common dynamic memory-management defects, identify their causes, debug memory errors and write safer C programs.

2. Review: Dynamic Memory Allocation

Dynamic memory allocation allows a program to request storage during execution.

The main functions are:

Function Purpose
malloc() Allocates a block of memory without initializing its contents.
calloc() Allocates an array and initializes all allocated bytes to zero.
realloc() Changes the size of an existing allocation.
free() Releases dynamically allocated storage.

Basic Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 100;

    printf("Value = %d\n", *ptr);

    free(ptr);
    ptr = NULL;

    return 0;
}
Output: 
Value = 100

Correct memory management requires releasing allocated storage when it is no longer needed.

3. What Is a Memory Leak?

A memory leak occurs when dynamically allocated memory is no longer reachable through the program's usable pointers but has not been released.

Example of a Memory Leak

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(10 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    ptr = NULL;

    return 0;
}

The allocation is still active, but the program loses its only pointer to it. It cannot subsequently release that allocation through the lost pointer.

Memory Diagram

Before losing the pointer:

ptr ---------> [Allocated memory]


After ptr = NULL:

ptr ---------> NULL

               [Allocated memory]
               Still allocated,
               but no usable pointer remains.
Assigning NULL to a pointer does not release the memory previously allocated through that pointer.

Corrected Program

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(10 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    free(ptr);
    ptr = NULL;

    return 0;
}

4. Common Causes of Memory Leaks

Cause 1: Forgetting free()

int *ptr = malloc(sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

/* Use ptr */

/* Missing free(ptr) */

The allocation remains active after the program stops using it.

Cause 2: Overwriting an Allocated Pointer

int *ptr = malloc(5 * sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

ptr = malloc(10 * sizeof *ptr);

The address of the first allocation is overwritten. The first allocation becomes unreachable.

Cause 3: Incorrect realloc() Usage

ptr = realloc(ptr, new_size);

If realloc() fails for a nonzero requested size, it returns NULL and leaves the original allocation unchanged. Directly assigning the result can lose the original pointer and cause a memory leak.

Safe realloc() Pattern

int *temp = realloc(ptr, new_size);

if (temp == NULL)
{
    /* Original allocation is still valid */
    free(ptr);
    return 1;
}

ptr = temp;
In a program that needs to preserve the original data after realloc() failure, do not free ptr in the failure branch. Retain it for later use or release it during normal cleanup.

Cause 4: Returning from a Function Without Cleanup

void process(void)
{
    int *data = malloc(100 * sizeof *data);

    if (data == NULL)
    {
        return;
    }

    if (some_condition)
    {
        return;  /* Memory leak */
    }

    free(data);
}

If the condition is true, the function returns without releasing the allocation.

Improved Cleanup Pattern

void process(void)
{
    int *data = malloc(100 * sizeof *data);

    if (data == NULL)
    {
        return;
    }

    if (some_condition)
    {
        goto cleanup;
    }

    /* Perform processing */

cleanup:
    free(data);
}

In C, a cleanup label can help centralize resource release when a function has multiple error paths.

5. What Is a Dangling Pointer?

A dangling pointer is a pointer that refers to an object whose lifetime has ended.

Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 50;

    free(ptr);

    printf("%d\n", *ptr);  /* Invalid access */

    return 0;
}

After free(ptr), the allocated object no longer exists. The pointer value must not be dereferenced.

Dereferencing a dangling pointer causes undefined behavior. The program may crash, display unexpected values or appear to work temporarily.

Safer Version

free(ptr);
ptr = NULL;

Setting a pointer to NULL after freeing it helps prevent accidental reuse through that particular pointer.

6. Use-After-Free Error

Use-after-free occurs when a program accesses dynamically allocated memory after that allocation has been released.

Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(3 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    ptr[0] = 10;
    ptr[1] = 20;
    ptr[2] = 30;

    free(ptr);

    ptr[1] = 100;  /* Use-after-free */

    return 0;
}

Why Is It Dangerous?

  • The memory may have been reused for another allocation.
  • Data belonging to another object may be corrupted.
  • The program may crash unpredictably.
  • It can create serious security vulnerabilities.
Do not access an object after its lifetime has ended. Assigning NULL to the pointer immediately after free() is a useful defensive practice.

7. What Is a Double Free Error?

A double free occurs when the same allocation is released more than once without a new allocation establishing a valid object at that address.

Incorrect Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    free(ptr);

    free(ptr);  /* Double free */

    return 0;
}

The second free() call is invalid because the allocation has already been released.

Corrected Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    free(ptr);
    ptr = NULL;

    free(ptr);  /* Safe: free(NULL) does nothing */

    return 0;
}
Calling free(NULL) is explicitly permitted by C. It performs no operation.

8. Invalid Free Operations

The free() function must receive either NULL or a pointer value returned by a compatible memory allocation function that has not already been released.

Example 1: Freeing a Normal Local Variable

#include <stdlib.h>

int main(void)
{
    int value = 100;

    free(&value);  /* Invalid */

    return 0;
}

value is an automatic local object, not a dynamically allocated object.

Example 2: Freeing an Interior Pointer

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(5 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    free(ptr + 1);  /* Invalid */

    free(ptr);

    return 0;
}

ptr + 1 points to an element inside the allocation. It is not the original pointer returned by malloc().

Correct Version

free(ptr);
Never pass an interior pointer, a stack variable address or an already freed pointer to free().

9. Uninitialized and Lost Pointers

Uninitialized Pointer

int *ptr;

*ptr = 100;  /* Undefined behavior */

ptr has not been initialized. It does not point to a valid int object.

Safer Declaration

int *ptr = NULL;

Before dereferencing it, assign it a valid address.

Lost Pointer Example

int *ptr = malloc(5 * sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

ptr = NULL;  /* Allocation becomes unreachable */

The pointer is valid initially, but assigning NULL without first freeing the allocation causes a memory leak.

10. Heap Buffer Overflow

A heap buffer overflow occurs when a program accesses memory beyond the boundaries of a dynamically allocated block.

Incorrect Example

#include <stdlib.h>

int main(void)
{
    int *arr = malloc(3 * sizeof *arr);

    if (arr == NULL)
    {
        return 1;
    }

    arr[0] = 10;
    arr[1] = 20;
    arr[2] = 30;

    arr[3] = 40;  /* Out of bounds */

    free(arr);

    return 0;
}

Only indexes 0, 1 and 2 are valid. Index 3 is outside the allocation.

Correct Practice

for (size_t i = 0; i < 3; i++)
{
    arr[i] = (int)i;
}
Out-of-bounds writes may corrupt unrelated memory and cause failures far away from the original programming mistake.

11. Heap Corruption

Heap corruption occurs when a program damages memory-management data or allocated objects through invalid memory operations.

Common causes include:

  • Writing beyond allocated memory.
  • Writing through dangling pointers.
  • Double-free operations.
  • Invalid free() calls.
  • Incorrect pointer arithmetic.

Heap corruption may not be detected immediately. A failure can occur later when another allocation or deallocation takes place.

Debugging Approach

  1. Identify the first invalid memory operation.
  2. Check allocation sizes and array indexes.
  3. Inspect pointer initialization and lifetime.
  4. Review every free() call.
  5. Use runtime memory-checking tools.

12. Memory Ownership and Lifetime

Memory ownership describes which part of a program is responsible for releasing a dynamically allocated object.

Example: Function Owns the Allocation

#include <stdlib.h>

int *createValue(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return NULL;
    }

    *ptr = 100;

    return ptr;
}

int main(void)
{
    int *data = createValue();

    if (data == NULL)
    {
        return 1;
    }

    /* Caller uses the returned allocation. */

    free(data);
    data = NULL;

    return 0;
}

The function creates the allocation and transfers responsibility to the caller. The caller releases it when finished.

Ownership Rules

  • Every allocation should have a clearly defined owner.
  • The owner is responsible for releasing the allocation.
  • Do not free memory owned by another component unless ownership is transferred.
  • Document whether a function borrows or transfers a pointer.
  • Do not return the address of an automatic local variable.

13. Safe Memory Management Pattern

A reliable C program should follow a consistent allocation and cleanup process. 

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *data = NULL;
    int status = EXIT_FAILURE;

    data = malloc(5 * sizeof *data);

    if (data == NULL)
    {
        fprintf(stderr, "Allocation failed\n");
        goto cleanup;
    }

    for (size_t i = 0; i < 5; i++)
    {
        data[i] = (int)(i + 1) * 10;
    }

    for (size_t i = 0; i < 5; i++)
    {
        printf("%d ", data[i]);
    }

    printf("\n");

    status = EXIT_SUCCESS;

cleanup:
    free(data);
    data = NULL;

    return status;
}
Output: 
10 20 30 40 50

This pattern ensures that the allocated pointer is released through one cleanup section, including error paths.

14. Detecting Memory Errors Using GCC AddressSanitizer

AddressSanitizer is a runtime memory error detector supported by several compilers, including GCC and Clang.

It can detect errors such as:

  • Heap buffer overflow.
  • Stack buffer overflow.
  • Use-after-free.
  • Double free.
  • Some memory leaks, when leak detection is supported.

Compile Command

gcc -std=c11 -Wall -Wextra -g -fsanitize=address -fno-omit-frame-pointer memory_test.c -o memory_test

Run

./memory_test

If the program performs an invalid memory operation, AddressSanitizer can report the error and provide a stack trace.

AddressSanitizer availability and some features depend on the compiler, operating system and runtime environment.

15. Detecting Memory Leaks Using Valgrind

Valgrind is a memory debugging tool commonly used on Linux systems.

Installation on Ubuntu

sudo apt update
sudo apt install valgrind

Compile with Debug Information

gcc -std=c11 -Wall -Wextra -g memory_test.c -o memory_test

Run Valgrind

valgrind --leak-check=full --show-leak-kinds=all ./memory_test

Valgrind can report:

  • Definitely lost memory.
  • Indirectly lost memory.
  • Possibly lost memory.
  • Still reachable allocations.
  • Invalid memory reads and writes.

A clean report is useful evidence that the tested execution did not exhibit the reported memory errors. It does not prove that every execution path is safe.

16. Memory Management in Embedded Systems

Dynamic memory allocation requires particular care in embedded systems.

Potential Problems

  • Limited RAM availability.
  • Heap fragmentation.
  • Unpredictable allocation failures.
  • Allocation and deallocation overhead.
  • Memory leaks during long-running operation.
  • Timing uncertainty in real-time applications.

Example: Embedded Sensor Buffer

Suppose an embedded device receives sensor samples continuously.

Repeatedly allocating and releasing memory for every sample can create unnecessary overhead and fragmentation.

A fixed-size buffer or a preallocated ring buffer may be more appropriate when the maximum data size is known.

Recommended Practices

  • Prefer static or preallocated memory when requirements are known.
  • Define maximum buffer sizes.
  • Avoid unnecessary allocation in time-critical code.
  • Check every allocation result.
  • Use predictable ownership and cleanup rules.
  • Test memory usage over long-running executions.
  • Consider RTOS memory-pool facilities where appropriate.
Dynamic allocation is not universally prohibited in embedded systems. Its suitability depends on memory limits, timing requirements, allocator behavior and the system's reliability requirements.

17. Common Interview Questions

Q1. What is a memory leak?

A memory leak occurs when an allocation is no longer reachable through usable pointers and cannot be released through the program's normal cleanup process.

Q2. What is a dangling pointer?

A dangling pointer refers to an object whose lifetime has ended.

Q3. What is use-after-free?

It is an invalid access to an object after its allocated storage has been released.

Q4. What is a double free?

It is an attempt to release the same allocation more than once.

Q5. What happens if free() is called twice?

The behavior is undefined if the same allocation has already been released.

Q6. What happens when free(NULL) is called?

No operation is performed. It is safe and explicitly permitted by C.

Q7. Does setting a pointer to NULL free memory?

No. It changes the pointer value but does not release the allocation.

Q8. How can a memory leak be detected?

Tools such as Valgrind and AddressSanitizer can detect many memory-management errors.

Q9. What is heap corruption?

It is damage to allocated memory or memory-management data caused by invalid memory operations.

Q10. What is the difference between a memory leak and dangling pointer?

A memory leak involves an allocation that cannot be reached for cleanup. A dangling pointer refers to an object whose lifetime has already ended.

Q11. Why should realloc() use a temporary pointer?

If realloc() fails for a nonzero size, the original allocation remains valid. A temporary pointer prevents losing the original address.

Q12. Why is dynamic memory risky in embedded systems?

Limited RAM, fragmentation, allocation failures and timing uncertainty can affect reliability and real-time behavior.

18. Placement-Oriented Debugging Exercises

Problem 1: Identify the Memory Leak

int *ptr = malloc(10 * sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

ptr = malloc(20 * sizeof *ptr);

free(ptr);

Question: What is wrong?

Answer:

The first allocation is overwritten without being released. The program loses access to that allocation.

Problem 2: Identify the Invalid Access

int *ptr = malloc(sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

*ptr = 100;

free(ptr);

printf("%d", *ptr);

Answer:

The program dereferences ptr after the allocated object has been released. This is a use-after-free error.

Problem 3: Identify the Double Free

int *ptr = malloc(sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

free(ptr);
free(ptr);

Answer:

The same allocation is released twice. The second call has undefined behavior.

Problem 4: Correct the Invalid Free

int *ptr = malloc(5 * sizeof *ptr);

if (ptr == NULL)
{
    return 1;
}

free(ptr + 2);

Correct statement:

free(ptr);

Problem 5: Correct the Missing Cleanup

int *data = malloc(100 * sizeof *data);

if (data == NULL)
{
    return 1;
}

if (input_error)
{
    return 1;
}

free(data);

Answer:

The error path returns without freeing data. Use a common cleanup section or explicitly release data before returning.

  3. Demonstrate why a pointer must not be used after free().
  4. Correct a program containing a double-free error.

Intermediate Level

  1. Write a function that allocates memory and returns it to the caller.
  2. Implement safe resizing with realloc().
  3. Correct a program with multiple early-return memory leaks.
  4. Use AddressSanitizer to identify a heap buffer overflow.
  5. Use Valgrind to detect a memory leak on Ubuntu.

Advanced Level

  1. Design a dynamic array module with clear ownership rules.
  2. Implement a cleanup strategy for a program with multiple allocations.
  3. Debug a use-after-free error involving two pointers to the same allocation.
  4. Analyze heap fragmentation in a long-running application.
  5. Design a bounded memory buffer suitable for an embedded application.

20. Quick Revision Checklist

  • Every successful dynamic allocation needs an appropriate cleanup strategy.
  • Never overwrite the only pointer to an active allocation.
  • Never dereference a pointer after its object's lifetime ends.
  • Never free the same allocation twice.
  • Never pass an interior pointer to free().
  • free(NULL) is safe.
  • Use a temporary pointer with realloc().
  • Check array boundaries before accessing elements.
  • Define clear memory ownership.
  • Use memory debugging tools during testing.
  • Consider fragmentation and deterministic allocation in embedded systems.
