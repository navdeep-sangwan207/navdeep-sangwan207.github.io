Lecture 04: free() and Memory Deallocation

Learn how to release dynamically allocated memory, prevent memory leaks, understand dangling pointers and avoid use-after-free and double-free errors.

1. Learning Objectives

  • Understand the purpose of free().
  • Learn the syntax and working of memory deallocation.
  • Understand allocated object lifetime after free().
  • Identify dangling pointers and use-after-free errors.
  • Understand double-free errors.
  • Learn how NULL assignment helps prevent accidental reuse.
  • Understand memory ownership and cleanup responsibilities.
  • Write programs with safe memory cleanup.
  • Prepare for memory-management interview questions.

2. Why Is Memory Deallocation Necessary?

When a program requests memory dynamically using malloc(), calloc() or realloc(), that storage remains allocated until it is released or the program terminates.

If allocated storage is no longer needed, the program should release it using free().

Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Allocation failed\n");
        return 1;
    }

    *ptr = 100;

    printf("Value = %d\n", *ptr);

    free(ptr);

    return 0;
}
Output: 
Value = 100

The program allocates storage, uses the allocated object and then releases it.

3. free() Function

free() releases allocated storage that was obtained from the standard dynamic memory allocation functions.

Syntax

void free(void *ptr);

Example:

int *ptr = malloc(sizeof *ptr);

if (ptr != NULL)
{
    *ptr = 50;
    free(ptr);
}

Important Rules

  • Pass a pointer to a currently allocated block.
  • The pointer must identify the beginning of the allocation.
  • Do not pass a pointer to an ordinary local or global variable.
  • Do not free the same allocation more than once.
  • Do not access the allocated object after it has been freed.
Calling free(NULL) is valid and has no effect. This makes cleanup code easier to write.

4. What Happens After free()?

Consider the following allocation: 

int *ptr = malloc(sizeof *ptr);

Before deallocation, ptr identifies the allocated integer object. 

Before free():

ptr
 |
 v
+-------------+
| int object  |
+-------------+

After:

free(ptr);

The allocated storage is released. The pointer variable itself still exists, but its previous value must no longer be used to access that allocation.

free() does not automatically set the pointer variable to NULL. Its value becomes indeterminate after the pointed-to allocation is deallocated.

5. Setting a Pointer to NULL After free()

A common defensive programming practice is to set a pointer to NULL after releasing the allocation. 

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 100;

    printf("%d\n", *ptr);

    free(ptr);
    ptr = NULL;

    if (ptr == NULL)
    {
        printf("Pointer is NULL\n");
    }

    return 0;
}
Output: 
100
Pointer is NULL

Assigning NULL makes this particular pointer clearly indicate that it no longer refers to an allocated object.

NULL assignment does not automatically update other pointers that may refer to the same allocation.

6. What Is a Dangling Pointer?

A dangling pointer is a pointer that refers to storage or an object whose lifetime has ended.

Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 200;

    free(ptr);

    /*
       ptr must not be used to access
       the previously allocated object.
    */

    return 0;
}

After free(), ptr no longer identifies a live allocated object.

Do not dereference a pointer after the lifetime of its allocated object ends. Such access results in undefined behavior.

7. Use-After-Free Error

Use-after-free occurs when a program accesses an allocated object after its storage has been released.

Incorrect Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 100;

    free(ptr);

    *ptr = 200;  /* Undefined behavior */

    return 0;
}

The final assignment attempts to access an object whose allocated storage has already been released.

Correct Approach

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 100;

    printf("%d\n", *ptr);

    free(ptr);
    ptr = NULL;

    return 0;
}
Output: 
100

8. What Is a Double-Free Error?

A double-free error occurs when a program attempts to deallocate the same allocation more than once.

Incorrect Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    free(ptr);

    free(ptr);  /* Undefined behavior */

    return 0;
}

The second call attempts to release an allocation that has already been released.

Safer Cleanup Pattern

free(ptr);
ptr = NULL;

free(ptr);  /* Safe: free(NULL) does nothing */
Setting a pointer to NULL helps prevent repeated freeing through that pointer. It does not solve double-free problems involving other aliases to the same allocation.

9. Invalid Use of free()

free() must receive either NULL or a pointer value returned by an allocation function and not already deallocated.

Invalid Example 1: Freeing a Local Variable

int main(void)
{
    int x = 10;

    free(&x);

    return 0;
}

x is not dynamically allocated. Passing its address to free() is undefined behavior.

Invalid Example 2: Freeing an Interior Pointer

int *arr = malloc(5 * sizeof *arr);

if (arr != NULL)
{
    int *ptr = &arr[2];

    free(ptr);  /* Undefined behavior */

    free(arr);
}

ptr points to an element inside the allocation, not to the beginning of the allocated block.

Correct Example

int *arr = malloc(5 * sizeof *arr);

if (arr != NULL)
{
    int *ptr = &arr[2];

    /* Use ptr while the allocation is alive. */

    free(arr);
    arr = NULL;
    ptr = NULL;
}

Release the allocation using the original allocation pointer.

10. Memory Leak

A memory leak occurs when allocated storage is no longer accessible or needed but has not been released.

Incorrect Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(100 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    ptr[0] = 10;

    return 0;
}

The program returns without releasing the allocation.

Correct Example

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(100 * sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    ptr[0] = 10;

    free(ptr);

    return 0;
}
Operating systems generally reclaim a process's memory when it terminates. However, failing to release memory during execution can cause resource exhaustion in long-running programs and embedded systems.

11. Multiple Pointers and Memory Ownership

Two or more pointer variables can refer to the same allocated object.

Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr1 = malloc(sizeof *ptr1);

    if (ptr1 == NULL)
    {
        return 1;
    }

    *ptr1 = 500;

    int *ptr2 = ptr1;

    printf("ptr1 value = %d\n", *ptr1);
    printf("ptr2 value = %d\n", *ptr2);

    free(ptr1);

    ptr1 = NULL;
    ptr2 = NULL;

    return 0;
}
Output: 
ptr1 value = 500
ptr2 value = 500

Both pointers refer to the same allocated object. Releasing the allocation through ptr1 also ends the object's lifetime for ptr2.

Do not dereference ptr2 after freeing the allocation through ptr1. Setting ptr1 to NULL does not automatically invalidate or clear ptr2.

What Is Memory Ownership?

Memory ownership describes which part of a program is responsible for managing an allocated object's lifetime and eventually releasing its storage.

A clear ownership design should identify:

  • Which function creates the allocation.
  • Which function owns the allocation.
  • Whether other functions only borrow the pointer.
  • Which function is responsible for calling free().

12. Memory Cleanup in Functions

A function may allocate memory and return it to its caller. The ownership responsibility should be clear.

Example: Caller Releases Memory

#include <stdio.h>
#include <stdlib.h>

int *createNumber(int value)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return NULL;
    }

    *ptr = value;

    return ptr;
}

int main(void)
{
    int *number = createNumber(250);

    if (number == NULL)
    {
        printf("Allocation failed\n");
        return 1;
    }

    printf("Value = %d\n", *number);

    free(number);
    number = NULL;

    return 0;
}
Output: 
Value = 250

The function creates the allocation. The caller receives it and becomes responsible for releasing it.

13. Cleanup with Multiple Allocations

A program may allocate several independent memory blocks. If a later allocation fails, earlier allocations must still be released.

Example: Safe Cleanup

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *a = NULL;
    int *b = NULL;
    int *c = NULL;

    a = malloc(sizeof *a);

    if (a == NULL)
    {
        goto cleanup;
    }

    b = malloc(sizeof *b);

    if (b == NULL)
    {
        goto cleanup;
    }

    c = malloc(sizeof *c);

    if (c == NULL)
    {
        goto cleanup;
    }

    *a = 10;
    *b = 20;
    *c = 30;

    printf("%d %d %d\n", *a, *b, *c);

cleanup:

    free(c);
    free(b);
    free(a);

    return 0;
}
Output when all allocations succeed: 
10 20 30

All pointers are initialized to NULL. Therefore, the cleanup section can safely call free() on each pointer, including pointers for allocations that were never successfully created.

This is a common C resource-management pattern. The cleanup label centralizes resource release and helps avoid memory leaks.

14. free() After realloc()

When realloc() succeeds, the returned pointer identifies the resized allocation. That pointer should be used for subsequent access and deallocation. 

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *arr = malloc(3 * sizeof *arr);

    if (arr == NULL)
    {
        return 1;
    }

    arr[0] = 10;
    arr[1] = 20;
    arr[2] = 30;

    int *temp = realloc(arr, 6 * sizeof *arr);

    if (temp == NULL)
    {
        free(arr);
        return 1;
    }

    arr = temp;

    arr[3] = 40;

    printf("%d\n", arr[3]);

    free(arr);
    arr = NULL;

    return 0;
}
Output: 
40

After successful resizing, free() must be called on the returned allocation pointer.

15. Common Memory Management Errors

Error Meaning Prevention
Memory leak Allocated storage is not released when no longer needed. Establish clear cleanup responsibility.
Dangling pointer A pointer refers to an object whose lifetime has ended. Stop using pointers after the object's lifetime ends.
Use-after-free Accessing an object after deallocation. Release only after all intended accesses are complete.
Double-free Releasing the same allocation more than once. Track ownership and deallocation.
Invalid free Passing a pointer that does not identify a valid allocation. Free only valid allocation pointers or NULL.
Lost pointer Overwriting the only pointer to an allocation. Use temporary pointers when replacing allocation pointers.

16. Debugging Memory Errors

Memory errors can be difficult to identify because they may not produce an immediate crash.

Useful Debugging Tools

  • GCC and Clang compiler warnings.
  • AddressSanitizer for detecting memory access errors.
  • Valgrind Memcheck on supported Linux systems.
  • GDB for inspecting pointer values and program execution.

Compile with AddressSanitizer

gcc -std=c11 -Wall -Wextra -g -fsanitize=address memory_test.c -o memory_test

Run the Program

./memory_test

Valgrind Example

valgrind --leak-check=full --show-leak-kinds=all ./memory_test
Sanitizers and memory-checking tools help detect errors, but a clean tool run does not prove that a program is completely free from memory-management defects.

17. Embedded Systems Relevance

Correct memory deallocation is especially important in embedded systems and long-running firmware.

Important Considerations

  • Repeated allocations without deallocation can exhaust limited RAM.
  • Memory leaks can cause failures after long operating periods.
  • Double-free errors can corrupt allocator state.
  • Use-after-free errors can produce unpredictable system behavior.
  • RTOS tasks must manage allocated resources consistently.
  • Static allocation may be preferable in systems requiring predictable resource usage.

Embedded Interview Question

Why is a memory leak dangerous in an embedded system?

Many embedded systems operate continuously with limited memory. Repeated leaks can gradually consume available RAM and eventually cause allocation failures or system instability.

RTOS Resource Management

In an RTOS application, memory ownership should be clear when buffers are passed between tasks, queues, callbacks and communication drivers.

A task should not release a buffer while another task is still using it. The application needs a clear ownership-transfer or shared-lifetime policy.

18. Placement-Oriented Interview Questions

Q1. What is free()?

free() releases storage previously allocated by a standard dynamic memory allocation function.

Q2. What happens after free()?

The allocated object's lifetime ends and the storage is released.

Q3. Does free() set the pointer to NULL?

No. The program must assign NULL explicitly if that is required.

Q4. What is a dangling pointer?

It is a pointer that refers to an object whose lifetime has ended.

Q5. What is use-after-free?

It is accessing an object after its allocated storage has been released.

Q6. What is double-free?

It is attempting to release the same allocation more than once.

Q7. Can free() accept NULL?

Yes. free(NULL) has no effect.

Q8. Can we free a local variable?

No. A local automatic variable is not dynamically allocated.

Q9. Can we free a pointer to an array element?

No. free() must receive the pointer identifying the beginning of the allocation.

Q10. What is a memory leak?

It occurs when allocated storage is no longer accessible or needed but remains unreleased.

Q11. What is memory ownership?

It identifies which part of a program is responsible for an allocation's lifetime and release.

Q12. Does setting one pointer to NULL clear all aliases?

No. Other pointer variables retain their own values and must not be used to access the released object.

Question 2: Identify the Problem

int *ptr = malloc(sizeof *ptr);

if (ptr != NULL)
{
    *ptr = 10;
}

free(ptr);

printf("%d\n", *ptr);

Answer:

The final statement accesses the allocated object after free() has ended its lifetime. This is a use-after-free error and results in undefined behavior.

Question 3: Identify the Problem

int *ptr = malloc(sizeof *ptr);

if (ptr != NULL)
{
    free(ptr);
    ptr = NULL;

    free(ptr);
}

Answer:

There is no double-free here. The second call is free(NULL), which is valid and has no effect.

Question 4: Identify the Problem

int *ptr = malloc(5 * sizeof *ptr);

if (ptr != NULL)
{
    int *middle = &ptr[2];

    free(middle);
}

Answer:

middle points inside the allocation. It is not the allocation's beginning. Passing it to free() is undefined behavior.

20. Practical Exercises

Basic Level

  1. Allocate an integer using malloc() and release it using free().
  2. Allocate an array and release it after displaying its elements.
  3. Set a pointer to NULL after deallocation.
  4. Demonstrate that free(NULL) is valid.
  5. Identify invalid calls to free() in sample programs.

Intermediate Level

  1. Write a function that allocates memory and returns it to the caller.
  2. Write a function that accepts a dynamically allocated pointer and releases it.
  3. Manage three allocations using a common cleanup section.
  4. Identify and correct a use-after-free error.
  5. Identify and correct a memory leak.

Advanced Level

  1. Implement a dynamically allocated linked list with proper cleanup.
  2. Write a function that releases an entire linked list.
  3. Design clear ownership rules for a shared data buffer.
  4. Use AddressSanitizer to investigate a memory error.
  5. Review a multi-function program for missing cleanup paths.

22. Quick Revision Checklist

  • free() releases dynamically allocated storage.
  • free(NULL) is valid and has no effect.
  • free() does not automatically set the pointer to NULL.
  • Never access an object after its lifetime ends.
  • A dangling pointer refers to an object whose lifetime has ended.
  • Use-after-free is an invalid memory access.
  • Double-free is an invalid repeated deallocation.
  • Only release the beginning pointer of a valid allocation.
  • Memory ownership should be clearly defined.
  • All allocated resources should have appropriate cleanup paths.
