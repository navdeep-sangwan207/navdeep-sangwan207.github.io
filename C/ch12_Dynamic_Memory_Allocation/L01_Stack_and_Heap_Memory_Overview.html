Lecture 01: Stack and Heap Memory Overview

Understand how C programs use memory, distinguish automatic and dynamic storage, and learn the concepts of stack, heap, scope, lifetime and program memory organization.

1. Learning Objectives

  • Understand how a C program uses memory during execution.
  • Learn the major regions of a typical process address space.
  • Understand stack memory and automatic storage duration.
  • Understand heap memory and dynamic allocation.
  • Differentiate scope, lifetime and storage duration.
  • Understand local, global and static objects.
  • Learn the role of pointers in dynamic memory management.
  • Understand stack overflow and heap exhaustion.
  • Prepare for memory-related technical interview questions.

2. Why Does a C Program Need Memory?

A C program needs memory to store instructions, variables, function calls, arrays, structures, dynamically allocated objects and other data required during execution.

Consider a simple program: 

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    int sum = a + b;

    printf("Sum = %d\n", sum);

    return 0;
}
Output: 
Sum = 30

The program uses memory for its instructions, variables and execution state.

The C language defines object storage duration and lifetime. The operating system and implementation determine how those objects are represented in the process address space.

3. Typical Memory Organization of a C Program

A typical process uses several logical memory regions. 

+--------------------------------------+
|             Stack                    |
|  Function calls and automatic data   |
|                                      |
+--------------------------------------+
|                                      |
|             Heap                     |
|  Dynamically allocated memory        |
|                                      |
+--------------------------------------+
|                                      |
|       Uninitialized Data (BSS)       |
|  Zero-initialized static objects     |
|                                      |
+--------------------------------------+
|                                      |
|       Initialized Data               |
|  Initialized static objects          |
|                                      |
+--------------------------------------+
|                                      |
|       Read-only Data                  |
|  String literals and constants       |
|                                      |
+--------------------------------------+
|                                      |
|       Program Code (Text)             |
|  Executable instructions              |
|                                      |
+--------------------------------------+

This is a simplified conceptual diagram. Actual process memory layout depends on the operating system, executable format, compiler, linker and architecture.

Major Regions

Region Typical Contents
Text segment Executable program instructions.
Read-only data String literals and other read-only constants.
Initialized data Initialized static-storage objects.
BSS Uninitialized or zero-initialized static-storage objects.
Heap Storage requested dynamically during execution.
Stack Commonly used for function-call state and automatic objects.
Stack and heap are common implementation concepts. The C standard does not require every implementation to use these exact physical memory regions.

4. What Is Stack Memory?

Stack memory is commonly used by a program to manage function calls and automatic storage.

When a function is called, the implementation typically maintains information needed for that call, such as return information, saved registers and local execution state.

Example

#include <stdio.h>

void display(void)
{
    int x = 100;

    printf("Inside function: %d\n", x);
}

int main(void)
{
    int a = 10;

    display();

    printf("Inside main: %d\n", a);

    return 0;
}
Output: 
Inside function: 100
Inside main: 10

The local variable x belongs to the execution of display(). Its lifetime ends when that function invocation finishes.

The variable a remains alive throughout the execution of main().

5. Function Calls and Stack Frames

A function call commonly creates a stack frame or equivalent execution context.

Example

#include <stdio.h>

void functionB(void)
{
    int b = 20;

    printf("B = %d\n", b);
}

void functionA(void)
{
    int a = 10;

    functionB();

    printf("A = %d\n", a);
}

int main(void)
{
    functionA();

    return 0;
}
Output: 
B = 20
A = 10

Conceptual Call Sequence

  1. main() calls functionA().
  2. functionA() creates its local execution state.
  3. functionA() calls functionB().
  4. functionB() executes and returns.
  5. functionA() resumes execution and returns.
  6. main() finishes.
A stack frame is an implementation concept. Compilers may optimize function calls, eliminate variables or use registers. Therefore, not every local variable must physically reside on a hardware stack.

6. What Is Heap Memory?

Heap memory is a commonly used region for dynamically allocated storage.

Unlike a fixed-size local array, dynamic allocation allows a program to request memory during execution based on runtime requirements.

Example: Dynamic Allocation

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Allocation failed\n");
        return 1;
    }

    *ptr = 100;

    printf("Value = %d\n", *ptr);

    free(ptr);

    return 0;
}
Output: 
Value = 100

Here:

  1. malloc() requests storage for an int object.
  2. The returned pointer identifies the allocated storage.
  3. The program stores 100 in that object.
  4. free() releases the allocated storage.
The pointer variable ptr and the allocated object have separate storage and lifetimes. The allocated object's lifetime ends when its storage is deallocated.

7. Stack vs Heap Memory

Stack Heap
Commonly used for function-call state and automatic storage. Commonly used for dynamic allocation.
Automatic objects are managed according to their lifetime. Programmer requests and releases allocated storage.
Storage is commonly associated with function execution. Storage can remain allocated after a function returns.
Often limited by implementation-specific stack resources. Limited by available address space and system resources.
Does not require malloc() for ordinary automatic objects. Uses allocation functions such as malloc() and calloc().
Automatic storage duration ends when the relevant block execution ends. Allocated storage remains until deallocated or program termination.
Do not assume that stack allocation is always faster than heap allocation or that every local variable is stored on the physical stack. Actual behavior depends on compiler and target implementation.

8. Automatic Storage Duration

Objects declared inside a block generally have automatic storage duration unless another storage-class specification changes their storage duration. 

#include <stdio.h>

void test(void)
{
    int count = 10;

    printf("%d\n", count);
}

int main(void)
{
    test();
    test();

    return 0;
}
Output: 
10
10

Each function invocation has its own automatic object named count. Its lifetime ends when the function invocation returns.

9. Static Storage Duration

Static-storage-duration objects exist for the entire execution of the program.

Example: Global Variable

#include <stdio.h>

int globalValue = 100;

int main(void)
{
    printf("%d\n", globalValue);

    return 0;
}
Output: 
100

Example: Static Local Variable

#include <stdio.h>

void counter(void)
{
    static int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    counter();
    counter();
    counter();

    return 0;
}
Output: 
1
2
3

The static local variable retains its value between function calls.

Static storage duration is not the same thing as heap allocation. A static object is not dynamically allocated using malloc().

10. Scope, Lifetime and Storage Duration

These three terms are frequently confused in C interviews.

Concept Meaning
Scope The region of source code where an identifier can be used.
Lifetime The period during execution when an object exists.
Storage duration The storage-lifetime category defined by the C language.

Example

#include <stdio.h>

void test(void)
{
    static int value = 10;

    value++;

    printf("%d\n", value);
}

int main(void)
{
    test();
    test();

    return 0;
}
Output: 
11
12

The identifier value has block scope, but the object has static storage duration.

11. Why Is Dynamic Memory Allocation Needed?

Sometimes the amount of memory required is not known until the program starts running.

Example: User-Defined Array Size

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n;
    int *arr;
    int i;

    printf("Enter number of elements: ");

    if (scanf("%d", &n) != 1 || n <= 0)
    {
        printf("Invalid size\n");
        return 1;
    }

    arr = malloc((size_t)n * sizeof *arr);

    if (arr == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    for (i = 0; i < n; i++)
    {
        arr[i] = (i + 1) * 10;
    }

    for (i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }

    printf("\n");

    free(arr);

    return 0;
}
Sample Input: 
5
Output: 
10 20 30 40 50

The program determines the number of elements at runtime and requests enough storage for the array.

12. What Happens When a Function Returns?

Automatic objects associated with a function invocation cease to exist when that invocation ends.

Incorrect Example

int *getValue(void)
{
    int x = 100;

    return &x;
}

This function returns the address of an automatic local object. Once the function returns, that object's lifetime has ended.

Using the returned pointer to access the expired object results in undefined behavior. Compilers commonly warn about returning the address of a local variable.

Correct Approach: Dynamic Allocation

#include <stdio.h>
#include <stdlib.h>

int *getValue(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return NULL;
    }

    *ptr = 100;

    return ptr;
}

int main(void)
{
    int *p = getValue();

    if (p == NULL)
    {
        printf("Allocation failed\n");
        return 1;
    }

    printf("%d\n", *p);

    free(p);

    return 0;
}
Output: 
100

The dynamically allocated object remains alive after getValue() returns. The caller becomes responsible for releasing it.

13. Stack Overflow

Stack overflow occurs when a program exceeds the available stack resources.

Common Causes

  • Excessive recursion depth.
  • Very large automatic arrays.
  • Deep function-call chains.
  • Large automatic objects.

Example: Uncontrolled Recursion

void recursiveFunction(void)
{
    recursiveFunction();
}

int main(void)
{
    recursiveFunction();

    return 0;
}

This function has no terminating condition. It continues calling itself until the implementation can no longer support the execution.

Do not run uncontrolled recursive programs as ordinary practice exercises. They can terminate abnormally or exhaust process resources.

14. Heap Exhaustion

Heap exhaustion occurs when a program cannot obtain the requested dynamic storage.

Allocation functions such as malloc() and calloc() return NULL when allocation cannot be satisfied. 

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    size_t count = 1000;

    int *ptr = malloc(count * sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Allocation failed\n");
        return 1;
    }

    printf("Allocation successful\n");

    free(ptr);

    return 0;
}

The example may succeed on a normal system, but allocation success must never be assumed.

15. Automatic Array vs Dynamic Array

Automatic Array

#include <stdio.h>

int main(void)
{
    int arr[5] = {10, 20, 30, 40, 50};

    printf("%d\n", arr[0]);

    return 0;
}

Dynamic Array

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *arr = malloc(5 * sizeof *arr);

    if (arr == NULL)
    {
        return 1;
    }

    arr[0] = 10;

    printf("%d\n", arr[0]);

    free(arr);

    return 0;
}
Automatic Array Dynamic Array
Declared with a fixed array bound in this example. Size requested during execution.
Automatic storage duration. Allocated storage has allocated storage duration.
No explicit free() required. Must be released using free() when no longer needed.
Lifetime follows its enclosing block execution. Lifetime continues until deallocation or program termination.

16. Pointer and Allocated Memory Relationship

int *ptr = malloc(sizeof *ptr);

This declaration involves two distinct objects:

  1. ptr: a pointer object.
  2. The allocated int object: the memory requested by malloc().

The pointer stores the address of the allocated object when allocation succeeds. 

Pointer object                         Allocated object

+----------------+                     +-------------+
| ptr            | ------------------> | int value   |
+----------------+                     +-------------+

Freeing the allocated object does not automatically destroy the pointer variable. 

free(ptr);
ptr = NULL;

Setting the pointer to NULL prevents that particular pointer from retaining the old address. It does not update other aliases that may point to the same allocation.

17. Common Memory Management Mistakes

Mistake Explanation
Returning address of a local variable The object's lifetime ends when the function returns.
Not checking malloc() Allocation can fail and return NULL.
Forgetting free() Allocated storage remains reserved unnecessarily.
Using memory after free() Accessing an object after its allocated storage is released is undefined behavior.
Freeing the same allocation twice Repeated deallocation without a new valid allocation is undefined behavior.
Dereferencing NULL A NULL pointer does not identify a valid object.
Excessive automatic storage use May exhaust implementation-specific stack resources.

18. Placement-Oriented Interview Questions

Q1. What is stack memory?

Stack is a common implementation mechanism used for function-call state and automatic storage.

Q2. What is heap memory?

Heap is a common implementation mechanism for dynamically allocated storage.

Q3. What is the main difference between stack and heap?

They are commonly used for different storage-management purposes. Automatic objects have lifetimes associated with their execution blocks, while allocated storage remains available until explicitly deallocated or program termination.

Q4. What is automatic storage duration?

It is a storage duration in which an object's lifetime is associated with execution of its enclosing block.

Q5. What is static storage duration?

The object exists for the entire execution of the program.

Q6. What is dynamic memory allocation?

It is the process of requesting storage during program execution using allocation functions.

Q7. What happens when malloc() fails?

malloc() returns NULL when it cannot allocate the requested storage.

Q8. What happens to a local variable when its function returns?

An automatic local object's lifetime ends when execution leaves its block.

Q9. Can dynamically allocated memory be used after a function returns?

Yes, provided the allocated object has not been deallocated and the pointer remains valid.

Q10. What is stack overflow?

It is a failure caused by exceeding available stack resources.

Q11. What is heap exhaustion?

It occurs when the program cannot obtain the requested dynamic storage.

Q12. Does free() destroy the pointer variable?

No. It releases the allocated storage. The pointer object itself remains until its own lifetime ends.

Q13. Is a static local variable stored on the heap?

No. It has static storage duration and is not dynamically allocated.

Q14. What is the difference between scope and lifetime?

Scope determines where an identifier can be used in source code. Lifetime determines how long the associated object exists.

20. Practical Exercises

Basic Level

  1. Write a program containing local and global variables.
  2. Demonstrate the lifetime of an automatic variable.
  3. Demonstrate how a static local variable retains its value.
  4. Draw the typical memory organization of a process.
  5. Allocate memory for one integer using malloc() and release it.

Intermediate Level

  1. Allocate an integer array based on user input.
  2. Pass a dynamically allocated array to a function.
  3. Return dynamically allocated memory from a function.
  4. Compare automatic arrays with dynamically allocated arrays.
  5. Write a program with multiple function calls and trace their execution.

Advanced Level

  1. Implement a dynamic array using pointer arithmetic.
  2. Build a dynamic linked-list node allocator.
  3. Investigate stack usage in recursive functions.
  4. Use a debugger to inspect pointer values and object lifetimes.
  5. Use AddressSanitizer to detect memory access errors in a test program.

22. Quick Revision Checklist

  • A C program uses memory for code, data and execution state.
  • Typical process memory includes text, data, BSS, heap and stack regions.
  • Automatic storage duration is associated with block execution.
  • Static storage duration lasts for the entire program execution.
  • Dynamic allocation is performed using allocation functions.
  • Heap allocation remains valid until deallocation or program termination.
  • Scope and lifetime are different concepts.
  • A pointer and the object it points to are separate objects.
  • Returning the address of an expired automatic object is invalid.
  • Stack overflow and heap exhaustion are different resource problems.
  • Always check allocation results and release allocated memory.
