Chapter 4: Conditional Statements and Decision Making

Handle multiple alternatives and dependent decisions using structured conditional statements.

1. Learning Objectives

  • Understand nested if and nested if-else statements.
  • Understand the execution flow of nested decisions.
  • Use the else-if ladder for multiple alternatives.
  • Choose an appropriate order for conditions.
  • Understand how an else associates with an if statement.
  • Avoid common errors in complex conditional logic.
  • Solve grading, eligibility and classification problems.

2. Why Multiple-Level Decisions Are Required

A basic if-else statement selects between two alternatives. However, practical programming problems frequently require more than two possible outcomes.

Examples include:

  • Classifying a number as positive, negative or zero.
  • Assigning grades based on examination marks.
  • Finding the largest among three numbers.
  • Checking eligibility using several dependent requirements.
  • Determining whether a year is a leap year.
  • Classifying an integer based on multiple properties.

C provides nested if-else statements and else-if ladders to implement these decision structures.

3. Nested if Statement

A nested if is an if statement placed inside the body of another if statement.

Syntax

if (condition1)
{
    if (condition2)
    {
        // Executes when both conditions are true
    }
}

Execution Process

  1. The outer condition is evaluated first.
  2. If the outer condition is false, its entire block is skipped.
  3. If the outer condition is true, the inner condition is evaluated.
  4. The inner block executes only if its condition is also true.

Example: Check Two Eligibility Requirements

A candidate must be at least 18 years old and have a valid identification card to enter. 

#include <stdio.h>

int main(void)
{
    int age = 22;
    int has_id = 1;

    if (age >= 18)
    {
        if (has_id == 1)
        {
            printf("Entry permitted.\n");
        }
    }

    return 0;
}
Expected Output: 
Entry permitted.

The outer condition checks the age. Only when it is true does the program check the identification condition.

Key Concept: The inner if statement is dependent on the execution of the outer if block.

4. Nested if-else Statement

A nested if-else contains an if-else statement inside another if or else block. It is useful when a decision depends on the result of an earlier decision.

General Syntax

if (condition1)
{
    if (condition2)
    {
        // Condition 1 and condition 2 are true
    }
    else
    {
        // Condition 1 is true, condition 2 is false
    }
}
else
{
    // Condition 1 is false
}

Example: Positive Number and Even or Odd

#include <stdio.h>

int main(void)
{
    int number = 24;

    if (number > 0)
    {
        if (number % 2 == 0)
        {
            printf("Positive even number.\n");
        }
        else
        {
            printf("Positive odd number.\n");
        }
    }
    else
    {
        printf("Number is not positive.\n");
    }

    return 0;
}
Expected Output: 
Positive even number.

First, the program checks whether the number is positive. If it is positive, the inner if-else determines whether it is even or odd.

Test Different Values

Number Output
24 Positive even number.
15 Positive odd number.
-8 Number is not positive.
0 Number is not positive.

5. else-if Ladder

An else-if ladder is used when a program must choose one outcome from several alternatives.

Conditions are evaluated from top to bottom. When the first true condition is found, its associated block executes and the remaining conditions are skipped.

Syntax

if (condition1)
{
    // Statement block 1
}
else if (condition2)
{
    // Statement block 2
}
else if (condition3)
{
    // Statement block 3
}
else
{
    // Default block
}

Execution Process

  1. Evaluate the first if condition.
  2. If true, execute its block and skip the remaining branches.
  3. If false, evaluate the next else-if condition.
  4. Continue until a true condition is found.
  5. If all conditions are false, execute the final else block if present.
Important: In an else-if ladder, at most one branch executes. If no condition is true and there is no final else, none of the branch blocks executes.

6. Practical Example: Student Grading System

Consider the following grading criteria:

Marks Grade
90 to 100 A
80 to 89 B
70 to 79 C
60 to 69 D
40 to 59 E
Below 40 Fail

Marks outside the range 0 to 100 are considered invalid. 

#include <stdio.h>

int main(void)
{
    int marks = 85;

    if (marks < 0 || marks > 100)
    {
        printf("Invalid marks.\n");
    }
    else if (marks >= 90)
    {
        printf("Grade A\n");
    }
    else if (marks >= 80)
    {
        printf("Grade B\n");
    }
    else if (marks >= 70)
    {
        printf("Grade C\n");
    }
    else if (marks >= 60)
    {
        printf("Grade D\n");
    }
    else if (marks >= 40)
    {
        printf("Grade E\n");
    }
    else
    {
        printf("Fail\n");
    }

    return 0;
}
Expected Output: 
Grade B

Why Are Conditions Ordered From Highest to Lowest?

The program checks the conditions sequentially. After validating the input range, it checks the highest grade first.

For marks equal to 85:

  1. Invalid marks condition is false.
  2. Marks greater than or equal to 90 is false.
  3. Marks greater than or equal to 80 is true.
  4. Grade B is printed and the remaining branches are skipped.
If the conditions were arranged carelessly, a lower threshold could match before a higher grade is checked. Always plan the order of conditions according to the problem requirements.

7. Nested if-else vs else-if Ladder

Feature Nested if-else else-if Ladder
Structure An if-else statement is placed inside another block. Multiple conditions are arranged sequentially.
Decision relationship Useful for dependent decisions. Useful for selecting among several alternatives.
Execution Inner decisions are evaluated only when their containing block is reached. Conditions are checked from top to bottom until one is true.
Readability Can become difficult to read when deeply nested. Often clearer for a sequence of mutually exclusive choices.
Typical example Check age first, then check identification. Assign grades using multiple mark ranges.

When Should You Use Each?

  • Use nested if-else when one decision determines whether another decision should be evaluated.
  • Use an else-if ladder when several alternative conditions represent different outcomes.
  • Avoid unnecessary nesting when a simpler condition or else-if ladder is easier to understand.

8. Condition Ordering and Boundary Values

The order of conditions is important because an else-if ladder stops at the first true condition.

Example: Incorrect Condition Ordering

int marks = 95;

if (marks >= 40)
{
    printf("Pass\n");
}
else if (marks >= 90)
{
    printf("Grade A\n");
}

The first condition is true for 95, so the program prints Pass. The Grade A branch is never reached.

Correct Condition Ordering

int marks = 95;

if (marks >= 90)
{
    printf("Grade A\n");
}
else if (marks >= 40)
{
    printf("Pass\n");
}
Expected Output: 
Grade A

9. Dangling else Problem

The dangling else problem occurs when nested if statements are written without braces and it is not immediately obvious which if statement an else belongs to.

Example

#include <stdio.h>

int main(void)
{
    int a = 1;
    int b = 0;

    if (a == 1)
        if (b == 1)
            printf("A\n");
        else
            printf("B\n");

    return 0;
}
Expected Output: 
B

In C, an else is associated with the nearest preceding unmatched if. Therefore, the else belongs to if (b == 1), not to if (a == 1).

How to Avoid the Problem

Use braces to make the intended structure explicit.

if (a == 1)
{
    if (b == 1)
    {
        printf("A\n");
    }
    else
    {
        printf("B\n");
    }
}
Interview Tip: Remember this rule: an else matches the nearest unmatched if. Questions based on dangling else are common in C output-prediction exercises.

10. Practical Programming Examples

Program 1: Find the Largest Among Three Numbers

#include <stdio.h>

int main(void)
{
    int a = 45;
    int b = 72;
    int c = 60;

    if (a >= b && a >= c)
    {
        printf("%d is the largest.\n", a);
    }
    else if (b >= a && b >= c)
    {
        printf("%d is the largest.\n", b);
    }
    else
    {
        printf("%d is the largest.\n", c);
    }

    return 0;
}
Expected Output: 
72 is the largest.

The program compares each value against the other two. The greater-than-or-equal-to operator also handles equal values correctly when determining a maximum.

Program 2: Check Leap Year

A year is a leap year if:

  • It is divisible by 400; or
  • It is divisible by 4 but not divisible by 100.
#include <stdio.h>

int main(void)
{
    int year = 2024;

    if (year % 400 == 0)
    {
        printf("Leap year.\n");
    }
    else if (year % 100 == 0)
    {
        printf("Not a leap year.\n");
    }
    else if (year % 4 == 0)
    {
        printf("Leap year.\n");
    }
    else
    {
        printf("Not a leap year.\n");
    }

    return 0;
}
Expected Output: 
Leap year.

The order is important. A year divisible by 100 is not a leap year unless it is also divisible by 400.

Program 3: Classify a Character

Check whether a character is an uppercase letter, lowercase letter, digit or special character. 

#include <stdio.h>

int main(void)
{
    char ch = 'G';

    if (ch >= 'A' && ch <= 'Z')
    {
        printf("Uppercase letter.\n");
    }
    else if (ch >= 'a' && ch <= 'z')
    {
        printf("Lowercase letter.\n");
    }
    else if (ch >= '0' && ch <= '9')
    {
        printf("Digit.\n");
    }
    else
    {
        printf("Special character.\n");
    }

    return 0;
}
Expected Output: 
Uppercase letter.

The comparisons use the basic execution character set ranges for the English letters and decimal digits.

Program 4: Check Divisibility by 3 and 5

#include <stdio.h>

int main(void)
{
    int number = 45;

    if (number % 3 == 0)
    {
        if (number % 5 == 0)
        {
            printf("Divisible by both 3 and 5.\n");
        }
        else
        {
            printf("Divisible by 3 only.\n");
        }
    }
    else if (number % 5 == 0)
    {
        printf("Divisible by 5 only.\n");
    }
    else
    {
        printf("Not divisible by 3 or 5.\n");
    }

    return 0;
}
Expected Output: 
Divisible by both 3 and 5.

11. Common Programming Mistakes

1. Incorrect Condition Order

Checking a broad condition before a more specific condition can make later branches unreachable.

2. Missing Braces

Deeply nested statements without braces are difficult to read and can produce unintended else associations.

3. Overusing Nested if Statements

Excessive nesting makes programs harder to maintain. Use an else-if ladder when it better represents the alternatives.

4. Forgetting Input Validation

Validate the input range before assigning grades or classifying values. For example, marks outside 0 to 100 should not receive a valid grade.

5. Overlooking Equality at Boundaries

Use >= or <= when the problem includes boundary values. A strict comparison can exclude an important input.

6. Writing Redundant Conditions

Avoid repeating checks that have already been established by an earlier branch when a simpler condition is sufficient.

Problem 2: else-if Ladder

#include <stdio.h>

int main(void)
{
    int x = 20;

    if (x > 30)
        printf("A\n");
    else if (x > 15)
        printf("B\n");
    else if (x > 10)
        printf("C\n");
    else
        printf("D\n");

Expected Output:

B

The first condition is false. The second is true, so the remaining branches are skipped.

Problem 3: Dangling else

#include <stdio.h>

int main(void)
{
    int a = 1;
    int b = 0;

    if (a)
        if (b)
            printf("A\n");
        else
            printf("B\n");
    else
        printf("C\n");

    return 0;
}

Expected Output:

B

The first if is true. The second if is false, so its associated else executes.

Problem 4: Assignment Inside a Condition

#include <stdio.h>

int main(void)
{
    int x = 5;

    if (x = 0)
        printf("A\n");
    else
        printf("B\n");

    printf("%d\n", x);

    return 0;

Expected Output:

B
0

The assignment changes x to zero. The resulting expression evaluates to false, so the else block executes.

13. Technical Interview Questions and Answers

Q1. What is a nested if statement?

A nested if is an if statement placed inside another if or else block. It is used for dependent decisions.

Q2. What is an else-if ladder?

It is a sequence of if and else-if conditions used to select one outcome from multiple alternatives.

Q3. How many branches of an else-if ladder execute?

At most one branch executes. It is the first branch whose condition evaluates to true.

Q4. Is the final else compulsory?

No. The final else is optional. If it is omitted and all conditions are false, no branch executes.

Q5. What is the dangling else problem?

It is the ambiguity that can arise in nested conditional statements when an else is not clearly associated with its intended if. C associates an else with the nearest unmatched if.

Q6. Can an else-if ladder contain multiple else-if blocks?

Yes. Multiple else-if blocks can be used to handle multiple alternative conditions.

Q7. What happens if all conditions in an else-if ladder are false?

The final else executes if it exists. Otherwise, the entire conditional structure is skipped.

Q8. What is the difference between nested if and else-if ladder?

Nested if is useful for dependent decisions. An else-if ladder is useful for selecting among alternative conditions.

Q9. Why is condition ordering important?

Because the first true branch executes and the remaining branches are skipped. Incorrect ordering can make the intended branch unreachable.

Q10. Can nested if statements be written without braces?

Yes, but braces are strongly recommended to make the structure clear and avoid dangling else mistakes.

Q11. How would you check a leap year using conditional statements?

A year is a leap year if it is divisible by 400, or if it is divisible by 4 but not by 100.

Q12. Can an else-if ladder be replaced with nested if statements?

Many problems can be implemented using either structure, but the clearest structure should be selected based on whether decisions are dependent or alternative.
