2. What Is Recursion?

Recursion is a programming technique in which a function calls itself to solve a problem by reducing it into smaller instances of the same problem.

A recursive function generally contains two important parts:

  1. Base case: Stops further recursive calls.
  2. Recursive case: Calls the function again with a smaller or simpler problem.

Basic Example

#include <stdio.h>

void countDown(int n)
{
    if (n == 0)
        return;

    printf("%d\n", n);

    countDown(n - 1);
}

int main(void)
{
    countDown(5);

    return 0;
}
Output: 
5
4
3
2
1

The function calls itself with a decreasing value of n. When n becomes zero, the base case executes and recursion stops.

3. Base Case and Recursive Case

Base Case

The base case is the condition under which the function stops making recursive calls.

Recursive Case

The recursive case reduces the problem and calls the same function again.

Example

void printNumbers(int n)
{
    if (n == 0)          // Base case
        return;

    printf("%d ", n);

    printNumbers(n - 1); // Recursive case
}
Every recursive function designed to terminate must have a reachable stopping condition for the inputs it is intended to handle. Recursive calls must make progress toward that condition.
A missing base case, or a recursive call that never approaches the base case, can cause unbounded recursion and eventually exhaust available stack space.

4. How Recursive Calls Execute

Consider the following function: 

#include <stdio.h>

void display(int n)
{
    if (n == 0)
        return;

    printf("Entering: %d\n", n);

    display(n - 1);

    printf("Returning: %d\n", n);
}

int main(void)
{
    display(3);

    return 0;
}
Output: 
Entering: 3
Entering: 2
Entering: 1
Returning: 1
Returning: 2
Returning: 3

Notice that the function first moves deeper into recursion. After reaching the base case, the pending function calls resume in reverse order.

Execution Phase Operation
Forward phase New recursive calls are made.
Base case No further recursive call is made.
Return phase Previous calls resume and finish.

5. Understanding the Function Call Stack

The call stack is a runtime mechanism used to manage active function calls. A function call typically requires a stack frame containing information such as parameters, local variables and return information.

Each recursive call creates another active function invocation with its own parameters and automatic local variables.

Example: display(3)

void display(int n)
{
    if (n == 0)
        return;

    display(n - 1);
}
Call Parameter Action
1 n = 3 Calls display(2)
2 n = 2 Calls display(1)
3 n = 1 Calls display(0)
4 n = 0 Base case returns

Conceptual call-stack growth:

Top of stack
+------------------+
| display(0)       |
+------------------+
| display(1)       |
+------------------+
| display(2)       |
+------------------+
| display(3)       |
+------------------+
Bottom of stack

Once display(0) returns, the pending calls return in reverse order: display(1), display(2), and display(3).

This is a conceptual model. The C standard does not require every implementation to use a particular physical stack layout, but this model is useful for understanding ordinary recursive execution.

6. Recursion with Return Values

A recursive function can return a value to its caller. Each call may use the result returned by a deeper call.

Example: Sum of First N Natural Numbers

#include <stdio.h>

unsigned long long sum(int n)
{
    if (n == 0)
        return 0;

    return (unsigned long long)n + sum(n - 1);
}

int main(void)
{
    int n = 5;

    printf("Sum = %llu\n", sum(n));

    return 0;
}
Output: 
Sum = 15

Return Sequence

sum(5)
= 5 + sum(4)
= 5 + 4 + sum(3)
= 5 + 4 + 3 + sum(2)
= 5 + 4 + 3 + 2 + sum(1)
= 5 + 4 + 3 + 2 + 1 + sum(0)
= 5 + 4 + 3 + 2 + 1 + 0
= 15

The program uses an unsigned long long result. For this example, n is a small positive integer. Larger input values require checking the result range and available recursion depth.

7. Factorial Using Recursion

Factorial of a non-negative integer n is defined as:

n! = n × (n - 1) × (n - 2) × ... × 1

Special case: 0! = 1.

#include <stdio.h>

unsigned long long factorial(unsigned int n)
{
    if (n == 0 || n == 1)
        return 1;

    return n * factorial(n - 1);
}

int main(void)
{
    unsigned int n = 5;

    printf("Factorial = %llu\n", factorial(n));

    return 0;
}
Output: 
Factorial = 120
This example assumes a small input whose factorial fits in unsigned long long and whose recursion depth is supported by the implementation. Unsigned arithmetic wraps modulo its range; it does not report overflow.

8. Direct and Indirect Recursion

Direct Recursion

A function directly calls itself. 

void functionA(int n)
{
    if (n > 0)
        functionA(n - 1);
}

Indirect Recursion

A function calls another function, which eventually calls the first function again. 

#include <stdio.h>

void functionB(int n);

void functionA(int n)
{
    if (n > 0)
    {
        printf("A: %d\n", n);
        functionB(n - 1);
    }
}

void functionB(int n)
{
    if (n > 0)
    {
        printf("B: %d\n", n);
        functionA(n - 1);
    }
}

int main(void)
{
    functionA(4);

    return 0;
}
Output: 
A: 4
B: 3
A: 2
B: 1

9. Recursion Depth and Stack Overflow

Recursion depth is the number of active recursive function calls at a particular point during execution.

Each additional call may require another stack frame. If recursion becomes too deep, the program can exhaust its available stack space.

Example of Unsafe Recursion

void infiniteRecursion(void)
{
    infiniteRecursion();
}

This function has no base case and does not terminate through normal recursive logic.

Do not execute this example as a normal test program. It may exhaust the available stack and terminate abnormally.

Ways to Avoid Excessive Recursion

  • Ensure every recursive path approaches a base case.
  • Reduce the problem size on each recursive call.
  • Estimate maximum recursion depth.
  • Use iteration when recursion depth may become very large.
  • Test boundary inputs.

10. Recursion vs Iteration

Feature Recursion Iteration
Mechanism Function calls itself Uses loops
Termination Base case Loop condition
Execution state Managed through active calls Usually managed through loop variables
Memory use May use additional stack space per call Often uses constant extra space for simple loops
Readability Can be concise for recursive problems Often straightforward for repetitive operations
Risk Excessive recursion depth Incorrect or infinite loop condition
Recursion is useful for naturally recursive problems such as tree traversal and divide-and-conquer algorithms. Iteration is often preferable for simple repetition or when recursion depth may be large.

11. Common Recursion Errors

  1. Missing base case: recursive calls continue without a stopping condition.
  2. Incorrect base condition: the function may stop too early or fail to stop.
  3. No progress toward the base case: the recursive argument does not become simpler.
  4. Incorrect return statement: the recursive result is not returned or used correctly.
  5. Excessive recursion depth: too many active calls can exhaust stack resources.
  6. Arithmetic overflow: recursive calculations may exceed the result type's range.

13. Technical Interview Questions

Q1. What is recursion?

Recursion is a technique in which a function calls itself to solve smaller instances of a problem.

Q2. What is a base case?

It is the condition that stops further recursive calls.

Q3. What happens if a base case is missing?

The function may continue calling itself until available execution resources are exhausted.

Q4. What is a call stack?

It is a runtime mechanism used to manage active function calls and their execution state.

Q5. What is a stack frame?

It is the execution information associated with an active function call, typically including parameters, local variables and return information.

Q6. What is direct recursion?

A function directly calls itself.

Q7. What is indirect recursion?

Two or more functions call one another in a cycle.

Q8. What is recursion depth?

It is the number of active recursive calls at a particular point during execution.

Q9. What is stack overflow?

It is a failure that can occur when execution requires more stack resources than are available.

Q10. Is recursion always slower than iteration?

No. Performance depends on the algorithm and compiler. Recursive calls can introduce overhead, but some compilers optimize certain tail-recursive calls. C does not guarantee tail-call optimization.
