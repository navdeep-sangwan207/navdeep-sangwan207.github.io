2. A Systematic Method for Output Prediction

Output-prediction questions test whether a programmer understands the rules of the C language rather than simply recognizing syntax.

Recommended solving procedure

  1. Identify all variables and their data types.
  2. Record their initial values.
  3. Identify the operators used in each expression.
  4. Apply precedence and associativity.
  5. Consider integer promotions and usual arithmetic conversions.
  6. Track modifications to variables carefully.
  7. Check for undefined behavior before predicting an output.
  8. Determine the values passed to output functions.
Important interview habit: Never assume that every syntactically valid C expression has a predictable output. First establish whether the expression has defined behavior.

Example

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 3;

    int result = a + b * 2;

    printf("%d\n", result);

    return 0;
}
Expected Output: 
16

Multiplication is grouped before addition: 10 + (3 * 2) = 16.

3. Integer Arithmetic Problems

Problem 1: Integer Division

#include <stdio.h>

int main(void)
{
    int a = 17;
    int b = 5;

    printf("%d\n", a / b);
    printf("%d\n", a % b);

    return 0;
}
Expected Output: 
3
2

Integer division discards the fractional part. The remainder operator returns the remainder of integer division.

Problem 2: Negative Integer Division

#include <stdio.h>

int main(void)
{
    printf("%d\n", -17 / 5);
    printf("%d\n", -17 % 5);

    return 0;
}
Expected Output: 
-3
-2

In C11, integer division truncates toward zero. The remainder satisfies the relationship:

\[ a = (a/b)\times b + (a\bmod b) \]

Problem 3: Compound Assignment

#include <stdio.h>

int main(void)
{
    int a = 10;

    a += 5;
    a *= 2;
    a -= 8;
    a /= 3;

    printf("%d\n", a);

    return 0;
}
Expected Output: 
8

Step-by-step values:

Statement Value of a
int a = 10;10
a += 5;15
a *= 2;30
a -= 8;22
a /= 3;7
Correction for the final calculation: 22 / 3 using integer division is 7. Therefore, the program's expected output is 7.

4. Floating-Point and Type Conversion Problems

Problem 1: Integer Division vs Floating-Point Division

#include <stdio.h>

int main(void)
{
    int a = 7;
    int b = 2;

    double result1 = a / b;
    double result2 = (double)a / b;

    printf("%.2f\n", result1);
    printf("%.2f\n", result2);

    return 0;
}
Expected Output: 
3.00
3.50

In the first expression, integer division takes place before assignment to double. In the second, casting a to double causes floating-point division.

Problem 2: Implicit Conversion

#include <stdio.h>

int main(void)
{
    int a = 5;
    float b = 2.0f;

    float result = a / b;

    printf("%.2f\n", result);

    return 0;
}
Expected Output: 
2.50

The integer operand is converted to floating-point for the arithmetic operation.

Problem 3: Explicit Type Casting

#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = 2;

    float result = (float)(a + b) / b;

    printf("%.2f\n", result);

    return 0;
}
Expected Output: 
3.50

The addition is performed first. The result is converted to floating-point before division.

5. Increment and Decrement Problems

Increment and decrement operators are common in output-prediction questions.

Problem 1: Post-Increment

#include <stdio.h>

int main(void)
{
    int a = 5;

    int result = a++;

    printf("a = %d\n", a);
    printf("result = %d\n", result);

    return 0;
}
Expected Output: 
a = 6
result = 5

Post-increment produces the original value of the operand, then increments the variable.

Problem 2: Pre-Increment

#include <stdio.h>

int main(void)
{
    int a = 5;

    int result = ++a;

    printf("a = %d\n", a);
    printf("result = %d\n", result);

    return 0;
}
Expected Output: 
a = 6
result = 6

Pre-increment increments the variable and produces its new value.

Problem 3: Separate Increment Operations

#include <stdio.h>

int main(void)
{
    int a = 4;

    int x = a++;
    int y = ++a;

    printf("x = %d\n", x);
    printf("y = %d\n", y);
    printf("a = %d\n", a);

    return 0;
}
Expected Output: 
x = 4
y = 6
a = 6

Each operation is a separate full expression, so the modifications are properly sequenced.

Avoid expressions such as i++ + ++i. They modify the same scalar object without the required sequencing and therefore have undefined behavior. Do not assign a guessed output.

6. Relational and Logical Operator Problems

Problem 1: Relational Expressions

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    printf("%d\n", a < b);
    printf("%d\n", a == b);
    printf("%d\n", a != b);

    return 0;
}
Expected Output: 
1
0
1

Relational and equality expressions produce integer value 0 or 1.

Problem 2: Logical AND and OR

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 5;

    int result = (a > 5) && (b < 10);

    printf("%d\n", result);

    return 0;
}
Expected Output: 
1

Problem 3: Short-Circuit Evaluation

#include <stdio.h>

int main(void)
{
    int a = 0;
    int b = 10;

    int result = (a != 0) && (b / a > 2);

    printf("%d\n", result);

    return 0;
}
Expected Output: 
0

The left operand of && is false. C therefore does not evaluate the right operand, avoiding division by zero.

Short-circuit evaluation applies to logical AND && and logical OR ||. Bitwise operators & and | do not provide the same short-circuit behavior.

7. Bitwise Operator Problems

Problem 1: Bitwise AND, OR and XOR

#include <stdio.h>

int main(void)
{
    unsigned int a = 12;
    unsigned int b = 10;

    printf("AND = %u\n", a & b);
    printf("OR = %u\n", a | b);
    printf("XOR = %u\n", a ^ b);

    return 0;
}

Binary representation:

a = 12 = 1100
b = 10 = 1010

AND       1000 = 8
OR        1110 = 14
XOR       0110 = 6
Expected Output: 
AND = 8
OR = 14
XOR = 6

Problem 2: Left Shift

#include <stdio.h>

int main(void)
{
    unsigned int a = 5;

    printf("%u\n", a << 1);

    return 0;
}
Expected Output: 
10

For this unsigned value, shifting left by one position produces 10.

Problem 3: Check an Individual Bit

#include <stdio.h>

int main(void)
{
    unsigned int value = 10;
    unsigned int position = 1;

    if ((value & (1u << position)) != 0u)
    {
        printf("Bit is SET\n");
    }
    else
    {
        printf("Bit is CLEAR\n");
    }

    return 0;
}
Expected Output: 
Bit is SET

Binary representation of 10 is 1010. Bit position 1, counting from zero at the least significant bit, is set.

Bitwise operations are especially important in embedded systems programming, register configuration, peripheral control and device-driver development.

8. Operator Precedence and Associativity Problems

Problem 1

#include <stdio.h>

int main(void)
{
    int result = 10 + 6 / 2 * 3 - 4;

    printf("%d\n", result);

    return 0;
}
Expected Output: 
15

Division and multiplication are grouped from left to right:

10 + ((6 / 2) * 3) - 4 = 10 + 9 - 4 = 15.

Problem 2

#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = 3;

    int result = a > b + 1;

    printf("%d\n", result);

    return 0;
}
Expected Output: 
1

Addition has higher precedence than relational comparison. The expression is grouped as 5 > (3 + 1).

Problem 3: Assignment Associativity

#include <stdio.h>

int main(void)
{
    int a, b, c;

    a = b = c = 25;

    printf("%d %d %d\n", a, b, c);

    return 0;
}
Expected Output: 
25 25 25

Assignment operators have right-to-left associativity.

9. Output Prediction: Advanced Interview Traps

Problem 1: Character Arithmetic 
#include <stdio.h>

int main(void)
{
    char ch = 'A';

    printf("%c\n", ch + 2);
    printf("%d\n", ch);

    return 0;
}
Expected Output on an ASCII-compatible execution environment: 
C
65

The character constant is converted to an integer for arithmetic. The numeric value shown assumes an ASCII-compatible character set.

Problem 2: Conditional Operator 
#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    int max = (a > b) ? a : b;

    printf("%d\n", max);

    return 0;
}
Expected Output: 
20

The conditional operator selects the second or third operand according to the condition.

Problem 3: sizeof and Data Types 
#include <stdio.h>

int main(void)
{
    int a = 10;
    double b = 20.5;

    printf("%zu\n", sizeof(a));
    printf("%zu\n", sizeof(b));

    return 0;
}
Output: The exact sizes are implementation-dependent. The program prints the size of an int and a double in bytes on the implementation where it runs.

sizeof returns a value of type size_t, so %zu is the appropriate format specifier.

Problem 4: Signed and Unsigned Arithmetic 
#include <stdio.h>

int main(void)
{
    unsigned int a = 0u;

    a = a - 1u;

    printf("%u\n", a);

    return 0;
}
Expected behavior:

The unsigned value wraps around modulo one more than the maximum representable value of unsigned int.

For example, if unsigned int is 32 bits, the result is:

4294967295
Problem 5: Undefined Behavior 
#include <stdio.h>

int main(void)
{
    int a = 2147483647;

    a = a + 1;

    printf("%d\n", a);

    return 0;
}
Answer:

Assuming a 32-bit int, the addition attempts to exceed the maximum representable signed integer value. This is signed integer overflow and has undefined behavior. There is no standard-defined output.

Problem 6: Floating-Point Comparison 
#include <stdio.h>

int main(void)
{
    double a = 0.1 + 0.2;
    double b = 0.3;

    printf("%d\n", a == b);

    return 0;
}
Answer:

Do not assume that the output is always 1. Floating-point representation and evaluation characteristics can affect the result. For approximate comparisons, use a suitable tolerance.

10. Coding Problems for Placement Practice

Problem 1: Swap Two Numbers Without a Third Variable

Use arithmetic operations to swap two integer variables. Consider overflow limitations of the chosen arithmetic method.

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    a = a + b;
    b = a - b;
    a = a - b;

    printf("a = %d\n", a);
    printf("b = %d\n", b);

    return 0;
}
Expected Output: 
a = 20
b = 10
This arithmetic swap can cause signed overflow for some input values. In production C code, a temporary variable is the safer and clearer approach.

Problem 2: Find the Largest of Three Numbers

#include <stdio.h>

int main(void)
{
    int a = 15;
    int b = 25;
    int c = 20;

    int largest = (a > b)
                    ? ((a > c) ? a : c)
                    : ((b > c) ? b : c);

    printf("Largest = %d\n", largest);

    return 0;
}
Expected Output: 
Largest = 25

Problem 3: Check Even or Odd Using Bitwise AND

#include <stdio.h>

int main(void)
{
    int number = 17;

    if ((number & 1) != 0)
    {
        printf("Odd\n");
    }
    else
    {
        printf("Even\n");
    }

    return 0;
}
Expected Output: 
Odd

Problem 4: Check Whether a Number Is Within a Range

#include <stdio.h>

int main(void)
{
    int number = 45;

    if (number >= 1 && number <= 100)
    {
        printf("Within range\n");
    }
    else
    {
        printf("Outside range\n");
    }

    return 0;
}
Expected Output: 
Within range

Problem 5: Calculate the Average of Three Numbers

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 15;
    int c = 20;

    double average = (double)(a + b + c) / 3;

    printf("Average = %.2f\n", average);

    return 0;
}
Expected Output: 
Average = 15.00

11. Common Interview Questions and Answers

Q1. Why does 5 / 2 produce 2 instead of 2.5?

Both operands are integers, so C performs integer division and truncates the result toward zero.

Q2. What is the difference between i++ and ++i?

Post-increment produces the original value before the increment. Pre-increment increments the variable and produces the new value.

Q3. What is the difference between = and ==?

= assigns a value. == compares two values and produces 0 or 1.

Q4. What is the difference between & and &&?

& performs bitwise AND on integer operands. && performs logical AND with short-circuit evaluation.

Q5. What happens when an unsigned integer exceeds its maximum value?

Unsigned arithmetic wraps modulo one more than the maximum representable value.

Q6. What happens when a signed integer overflows?

Signed integer overflow has undefined behavior in C.

Q7. What is short-circuit evaluation?

For &&, if the left operand is false, the right operand is not evaluated. For ||, if the left operand is true, the right operand is not evaluated.

Q8. Why should floating-point values not always be compared using ==?

Many decimal fractions cannot be represented exactly in binary floating-point. Rounding can make two mathematically equivalent calculations differ slightly.

Q9. What is the purpose of the sizeof operator?

It determines the size in bytes of a type or object. Its result has type size_t.

Q10. Can the result of an expression be undefined?

Yes. Examples include signed integer overflow, division by zero and certain unsequenced modifications of the same scalar object.

12. Multiple-Choice Questions (MCQs)

Q1. What is the result of 15 / 4?
  1. 3.75
  2. 3
  3. 4
  4. 0

Correct answer: B - 3.

Q2. Which operator performs logical AND?
  1. &
  2. &&
  3. ||
  4. !

Correct answer: B - &&.

Q3. What does post-increment return?
  1. The incremented value
  2. The original value
  3. Always zero
  4. An address

Correct answer: B - The original value.

Q4. What is the result of 10 + 5 * 2?
  1. 30
  2. 20
  3. 25
  4. 15

Correct answer: B - 20.

Q5. Which operator performs bitwise XOR?
  1. &
  2. |
  3. ^
  4. ~

Correct answer: C - ^.

Q6. What does a relational expression return in C?
  1. True or false keywords
  2. 0 or 1 as an int result
  3. A floating-point value
  4. A pointer

Correct answer: B - 0 or 1 as an int result.

Q7. Which operation has undefined behavior for signed integers?
  1. Adding 2 and 3
  2. Comparing 5 and 10
  3. Overflowing the signed integer range
  4. Multiplying 2 and 3

Q8. Which format specifier is appropriate for size_t?
  1. %d
  2. %f

Q9. Which operator can skip evaluation of its right operand?

  5. Rewrite an expression that modifies a variable more than once without sequencing.
