Lecture 5: Loop Tracing and Infinite Loops

Chapter 5 – Loops and Iteration

Master loop execution, trace tables, iteration counting, output prediction and infinite-loop debugging.

1. Learning Objectives

  • Trace for, while and do-while loops step by step.
  • Prepare trace tables for program execution.
  • Calculate the number of loop iterations.
  • Understand loop initialization, condition and update order.
  • Identify off-by-one errors.
  • Recognize common causes of infinite loops.
  • Predict the output of nested and modified loops.
  • Debug loop-related programming errors.

2. What Is Loop Tracing?

Loop tracing is the process of following a loop's execution statement by statement to determine how variables change and what output is produced.

It is especially important in C technical interviews, where candidates are often asked to predict output without executing the program.

What Should Be Tracked?

  • Initial value of each loop variable.
  • Result of the loop condition.
  • Statements executed in each iteration.
  • Changes to variables.
  • Execution of break and continue.
  • Final condition result and loop termination.
Tracing rule: Never assume that a loop executes a particular number of times. Follow the exact order of initialization, condition checking, loop body and update.

3. Tracing a for Loop

Example

#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 4; i++)
    {
        printf("%d ", i);
    }

    return 0;
}

Trace Table

Iteration i Condition i <= 4 Output After Update
1 1 True 1 2
2 2 True 2 3
3 3 True 3 4
4 4 True 4 5
Termination check 5 False None —
Output: 
1 2 3 4

The loop executes four times. When i becomes 5, the condition becomes false and the loop terminates.

4. Understanding the Execution Order of for

A for loop follows this execution order:

  1. Initialization executes once.
  2. Condition is evaluated.
  3. If true, the loop body executes.
  4. The update expression executes.
  5. Control returns to condition checking.
  6. If false, the loop terminates.

Example with Multiple Expressions

#include <stdio.h>

int main(void)
{
    int i, j;

    for (i = 1, j = 5; i <= 3; i++, j--)
    {
        printf("%d %d\n", i, j);
    }

    return 0;
}
Output: 
1 5
2 4
3 3

The comma operator allows multiple expressions in the initialization and update portions. Both variables change on each completed iteration.

5. Tracing a while Loop

Example

#include <stdio.h>

int main(void)
{
    int i = 2;

    while (i <= 10)
    {
        printf("%d ", i);
        i += 2;
    }

    return 0;
}

Trace Table

Iteration i Before Body Condition Output i After Update
1 2 True 2 4
2 4 True 4 6
3 6 True 6 8
4 8 True 8 10
5 10 True 10 12
Termination check 12 False None —
Output: 
2 4 6 8 10

A while loop checks its condition before executing the body. Therefore, it may execute zero times if the initial condition is false.

6. Tracing a do-while Loop

Example

#include <stdio.h>

int main(void)
{
    int i = 5;

    do
    {
        printf("%d ", i);
        i++;

    } while (i < 5);

    return 0;
}
Output: 
5

Although the condition is false after the first execution, the body runs once because a do-while loop checks its condition after executing the body.

A do-while loop always executes its body at least once, provided control reaches the loop.

7. Counting Loop Iterations

Iteration counting is frequently tested in coding assessments and output-prediction questions.

Example 1: Increment by 1

for (int i = 1; i <= 10; i++)
{
    printf("%d ", i);
}

Number of iterations: 10.

Example 2: Increment by 2

for (int i = 2; i <= 20; i += 2)
{
    printf("%d ", i);
}

Number of iterations: 10.

Example 3: Decrement by 1

for (int i = 10; i >= 1; i--)
{
    printf("%d ", i);
}

Number of iterations: 10.

Example 4: Increment by 3

for (int i = 1; i <= 10; i += 3)
{
    printf("%d ", i);
}
Output: 
1 4 7 10

Number of iterations: 4.

The values are 1, 4, 7 and 10. The next value becomes 13, so the condition fails.

8. Nested Loop Iteration Counting

Example 1: Equal Inner Iterations

for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 4; j++)
    {
        printf("* ");
    }
}

Outer loop executes 3 times. Inner loop executes 4 times for each outer iteration.

Total inner-body executions = 3 × 4 = 12.

Example 2: Dependent Inner Loop

for (int i = 1; i <= 4; i++)
{
    for (int j = 1; j <= i; j++)
    {
        printf("* ");
    }

    printf("\n");
}
Output: 
*
* *
* * *
* * * *

Total inner-body executions: 1 + 2 + 3 + 4 = 10.

Example 3: Reverse Dependent Loop

for (int i = 4; i >= 1; i--)
{
    for (int j = 1; j <= i; j++)
    {
        printf("* ");
    }

    printf("\n");
}
Output: 
* * * *
* * *
* *
*

Total inner-body executions: 4 + 3 + 2 + 1 = 10.

9. Off-by-One Errors

An off-by-one error occurs when a loop executes one iteration too many or one iteration too few because of an incorrect boundary condition or initialization.

Example: Incorrect Boundary

for (int i = 1; i < 5; i++)
{
    printf("%d ", i);
}
Output: 
1 2 3 4

The loop prints four numbers, not five, because the condition uses i < 5.

Corrected Version for Five Numbers

for (int i = 1; i <= 5; i++)
{
    printf("%d ", i);
}
Output: 
1 2 3 4 5

Common Boundary Mistakes

Incorrect or Different Condition Effect
i < N instead of i <= N Excludes N from the iteration range.
i <= N instead of i < N May execute one extra iteration.
Starting from 0 instead of 1 Changes the number and range of iterations.
Incorrect array boundary May access an element outside the array.
Array safety: For an array of N elements, valid indexes are 0 through N - 1. A condition such as i <= N is incorrect when accessing arr[i].

10. What Is an Infinite Loop?

An infinite loop is a loop that does not terminate through its normal condition evaluation or intended control flow.

It may continue indefinitely because its termination condition never becomes false, or because the loop has no effective termination mechanism.

Example 1: Missing Update

int i = 1;

while (i <= 5)
{
    printf("%d ", i);
}

The value of i never changes. Therefore, i <= 5 remains true and the loop continues indefinitely.

Corrected Version

int i = 1;

while (i <= 5)
{
    printf("%d ", i);
    i++;
}

Example 2: Incorrect Update Direction

for (int i = 1; i <= 5; i--)
{
    printf("%d ", i);
}

The loop starts at 1 and decreases the value. It therefore remains less than or equal to 5, so the condition does not become false.

Corrected Version

for (int i = 1; i <= 5; i++)
{
    printf("%d ", i);
}

11. Common Causes of Infinite Loops

Cause Example Problem
Missing update while (i < 10) without changing i Condition remains true.
Wrong update direction i-- when i must increase Variable moves away from termination.
Incorrect condition i != 10 with an update that skips 10 Target value may never be reached.
continue before update continue skips i++ in a while loop Loop variable may stop changing.
Constant true condition while (1) No normal condition-based termination.
An intentional infinite loop, such as a continuously running embedded-system task, may be valid when it includes a deliberate event-handling or termination mechanism.

12. Infinite Loops and continue

One common interview trap is placing continue before the update statement in a while loop.

Incorrect Program

#include <stdio.h>

int main(void)
{
    int i = 0;

    while (i < 5)
    {
        if (i == 2)
        {
            continue;
        }

        printf("%d ", i);
        i++;
    }

    return 0;
}

When i becomes 2, continue transfers control to the while condition. Since i is not incremented, it remains 2 and the loop repeats indefinitely.

Corrected Program

#include <stdio.h>

int main(void)
{
    int i = 0;

    while (i < 5)
    {
        if (i == 2)
        {
            i++;
            continue;
        }

        printf("%d ", i);
        i++;
    }

    return 0;
}
Output: 
0 1 3 4

13. Output Prediction: Interview-Level Problems

Problem 1: Increment in the Loop Body

int i = 1;

while (i <= 5)
{
    printf("%d ", i);
    i += 2;
}
Output: 
1 3 5

Problem 2: Multiple Increment Operations

for (int i = 1; i <= 5; i++)
{
    printf("%d ", i);

    i++;
}
Output: 
1 3 5

The variable increases once inside the body and once in the update expression.

Problem 3: Empty Loop Body

int i;

for (i = 1; i <= 5; i++)
    ;

printf("%d\n", i);
Output: 
6

The semicolon immediately after the for statement is an empty loop body. The printf executes after the loop terminates.

Problem 4: Nested Loop with break

for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        if (j == 2)
            break;

        printf("%d%d ", i, j);
    }
}
Output: 
11 21 31

The inner loop terminates when j becomes 2. The outer loop continues with its next value.

Problem 5: Nested Loop with continue

for (int i = 1; i <= 2; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        if (j == 2)
            continue;

        printf("%d%d ", i, j);
    }
}
Output: 
11 13 21 23

Problem 6: Condition Uses a Modified Variable

int i = 0;

for (; i < 5; )
{
    printf("%d ", i);
    i += 2;
}
Output: 
0 2 4

Initialization and update expressions are optional in a for loop. The update here occurs inside the body.

14. Debugging Loop Errors Systematically

When a loop produces unexpected output or fails to terminate:

  1. Identify the loop variable and its initial value.
  2. Check the condition carefully, including boundary operators.
  3. Locate every statement that modifies the loop variable.
  4. Check whether break or continue changes the normal flow.
  5. Verify that the variable moves toward the termination condition.
  6. Check nested-loop boundaries independently.
  7. Check array indexes against valid limits.
  8. Use a trace table or debugger to verify each iteration.

Useful GCC Compilation Command

gcc -std=c11 -Wall -Wextra -Wpedantic -g loop.c -o loop

The warning options help identify suspicious code. The -g option includes debugging information for use with a debugger such as GDB.

Example GDB Commands

gdb ./loop

break main
run
next
print i
continue
quit

Use breakpoints and variable inspection to follow loop execution without manually guessing its behavior.

15. Interview Questions and Answers

Q1. What is loop tracing?

Loop tracing is the step-by-step examination of variable values, conditions, statements and output during loop execution.

Q2. What is an off-by-one error?

It is a boundary error that causes a loop to execute one iteration too many or one too few.

Q3. Can a for loop omit its initialization expression?

Yes. The initialization expression is optional. The variable can be initialized before the loop.

Q4. Can a for loop omit its condition?

Yes. If the condition is omitted, it behaves as a nonzero true condition, so the loop does not terminate through that condition.

Q5. Can a while loop execute zero times?

Yes. The condition is checked before the body. If it is initially false, the body is skipped.

Q6. Which loop always executes at least once?

The do-while loop, because it checks its condition after executing the body.

Q7. What causes an infinite loop?

A missing or incorrect update, an ineffective termination condition, or a control-flow path that prevents the loop from progressing.

Q8. What is the output of a loop with a semicolon immediately after its header?

The semicolon forms an empty loop body. The loop may still perform all its iterations, but statements following it execute only after termination.

Q9. How do you count nested-loop iterations?

Count the inner-loop executions for each outer-loop iteration, then add them. If the inner loop always executes M times and the outer loop N times, the total is N × M.

Q10. How can an infinite loop be debugged?

Check the loop condition, variable updates and control-transfer statements. Use a trace table, debugger and compiler warnings.

16. Coding and Tracing Practice

Part A: Output Prediction

  1. Predict the output of a for loop starting at 0 and incrementing by 3 while i is less than 15.
  2. Trace a while loop that starts at 20 and decreases by 4 until the value becomes negative.
  3. Predict the output of a do-while loop whose initial condition is false.
  4. Count the total executions of a nested loop with a dependent inner condition.
  5. Determine the output when a loop variable is incremented both inside the body and in the update expression.

Part B: Debugging

  1. Correct a while loop that never increments its control variable.
  2. Fix a loop that skips its update when continue executes.
  3. Correct an array traversal loop that accesses arr[N].
  4. Fix a countdown loop whose update moves in the wrong direction.
  5. Identify and correct an off-by-one error in a number-printing program.

Part C: Practical Coding

  1. Write a program to print the first N natural numbers and count the iterations.
  2. Write a program to calculate the sum of numbers from 1 to N using a while loop.
  3. Write a program to print a multiplication table using nested loops.
  4. Write a program that searches an array and reports the number of comparisons performed.
  5. Write a program that processes an array while skipping negative values.

17. Key Takeaways

  • Loop tracing helps determine exact execution order and output.
  • Always track initialization, condition, body and update.
  • Iteration counts depend on the actual values and conditions.
  • Nested loops may have fixed or dependent iteration counts.
  • Off-by-one errors commonly arise from incorrect boundaries.
  • Infinite loops often result from missing or incorrect updates.
  • continue can accidentally prevent progress in while and do-while loops.
  • Trace tables and debuggers are useful tools for finding loop errors.
