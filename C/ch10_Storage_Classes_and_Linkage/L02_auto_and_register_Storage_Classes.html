Lecture 02: auto and register Storage Classes

Understand automatic local variables, the auto and register specifiers, initialization rules and practical applications in C programming.

1. Learning Objectives

  • Understand the auto storage-class specifier.
  • Understand automatic storage duration and block scope.
  • Learn how local variables are initialized.
  • Understand the register storage-class specifier.
  • Learn the restrictions on taking the address of register objects.
  • Compare auto, register and static local variables.
  • Predict output involving automatic variables.
  • Apply these concepts to placement and embedded C questions.

2. What Are Storage-Class Specifiers?

Storage-class specifiers are keywords that influence properties of identifiers, including storage duration, linkage and other declaration characteristics.

In this lecture, we focus on two storage-class specifiers:

  • auto
  • register

Both are traditionally associated with local variables and automatic storage duration.

3. auto Storage-Class Specifier

The auto keyword explicitly specifies automatic storage duration for an object declared in a block.

Local variables declared without a storage-class specifier already have automatic storage duration. Therefore, using auto explicitly is usually unnecessary.

Syntax

auto data_type variable_name;

Example 1: Using auto

#include <stdio.h>

int main(void)
{
    auto int number = 100;

    printf("%d\n", number);

    return 0;
}
Expected Output: 
100

The variable number has automatic storage duration and block scope.

Example 2: auto Is Usually Optional

#include <stdio.h>

int main(void)
{
    int a = 10;
    auto int b = 20;

    printf("%d\n", a + b);

    return 0;
}
Expected Output: 
30

Both a and b have automatic storage duration. The auto keyword does not make b fundamentally different from an ordinary local variable.

4. Characteristics of Automatic Variables

Property Automatic Local Variable
Typical declaration int number;
Storage duration Automatic
Typical scope Block scope
Default initialization No guaranteed initial value for an uninitialized ordinary local object.
Lifetime Associated with execution of the enclosing block.
Persistence between calls No guaranteed retention of previous values.

Example 3: Automatic Variable Reinitialized on Every Call

#include <stdio.h>

void counter(void)
{
    int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    counter();
    counter();
    counter();

    return 0;
}
Expected Output: 
1
1
1

Each function call creates a new instance of the automatic variable count. Its initializer sets the value to zero on each execution of the declaration.

5. Initialization of Automatic Variables

An automatic variable without an explicit initializer is not automatically initialized to zero.

Example 4: Explicit Initialization

#include <stdio.h>

int main(void)
{
    int number = 50;

    printf("%d\n", number);

    return 0;
}
Expected Output: 
50

Example 5: Uninitialized Automatic Variable

#include <stdio.h>

int main(void)
{
    int number;

    printf("%d\n", number);

    return 0;
}
Important: Do not predict a numerical output for this program. The value of number is indeterminate, and evaluating it this way results in undefined behavior in this example.

Always initialize local variables before reading their values.

6. Nested Blocks and Automatic Variables

Automatic variables can be declared in nested blocks. Each declaration has its own scope and object.

Example 6: Automatic Variables in Different Blocks

#include <stdio.h>

int main(void)
{
    int x = 10;

    {
        int y = 20;

        printf("%d %d\n", x, y);
    }

    {
        int z = 30;

        printf("%d %d\n", x, z);
    }

    return 0;
}
Expected Output: 
10 20
10 30

x is declared in the outer block and remains visible in both nested blocks. y and z are limited to their respective blocks.

7. register Storage-Class Specifier

The register keyword is a storage-class specifier that indicates a preference for storing an object in a processor register when practical.

Modern compilers generally make register allocation decisions automatically. Therefore, register does not guarantee that a variable will physically reside in a CPU register.

Syntax

register data_type variable_name;

Example 7: Register Variable

#include <stdio.h>

int main(void)
{
    register int count = 100;

    printf("%d\n", count);

    return 0;
}
Expected Output: 
100

The variable count has automatic storage duration and block scope. The register specifier does not change its fundamental lifetime behavior.

8. Characteristics of register Variables

Property register Variable
Storage duration Automatic
Typical scope Block scope
Initialization Can have an explicit initializer.
Persistence between calls No automatic persistence.
Register allocation Only a suggestion to the implementation.
Address-taking The unary & operator cannot be applied to an object declared with register.

9. Address-of Restriction for register Variables

A special restriction applies to objects declared with the register storage-class specifier: the unary address-of operator & cannot be applied to such an object.

Example 8: Valid register Variable

#include <stdio.h>

int main(void)
{
    register int number = 25;

    printf("%d\n", number);

    return 0;
}
Expected Output: 
25

Example 9: Invalid Address-of Operation

#include <stdio.h>

int main(void)
{
    register int number = 25;

    printf("%p\n", (void *)&number);

    return 0;
}
Compilation Error: The address-of operator cannot be applied to an object declared with register.

This restriction also means that you cannot pass the address of a register object to a function expecting a pointer to that object.

10. register Variables in Loops

Historically, register was commonly used for loop counters and frequently accessed variables.

Example 10: Register Loop Counter

#include <stdio.h>

int main(void)
{
    register int i;

    for (i = 1; i <= 5; i++)
    {
        printf("%d ", i);
    }

    printf("\n");

    return 0;
}
Expected Output: 
1 2 3 4 5

The compiler is free to choose the most appropriate register allocation strategy. The program's correctness must not depend on whether i is actually stored in a CPU register.

Modern optimizing compilers perform register allocation automatically. In production code, optimize based on profiling and compiler diagnostics rather than assuming register improves performance.

Example 12: Comparing Three Local Variables

#include <stdio.h>

void display(void)
{
    auto int a = 0;
    register int b = 0;
    static int c = 0;

    a++;
    b++;
    c++;

    printf("%d %d %d\n", a, b, c);
}

int main(void)
{
    display();
    display();
    display();

    return 0;
}
Expected Output: 
1 1 1
1 1 2
1 1 3

Both a and b are initialized again during every call. c retains its value because it has static storage duration.

13. Important C11 Rules and Restrictions

Rule 1: auto and register Are Block-Level Specifiers

In C11, auto and register cannot be used to declare ordinary file-scope objects. Their use is associated with block-scope declarations.

Rule 2: register Does Not Guarantee a CPU Register

It is only an implementation hint. The compiler decides how to allocate storage and generate machine instructions.

Rule 3: Address of a register Object Cannot Be Taken

The unary & operator cannot be applied to an object declared with register.

Rule 4: register and Arrays

A register array declaration is permitted, but array-to-pointer conversion of that array is not permitted under the C11 rules. Consequently, ordinary pointer-based array access patterns cannot be used with a register array.

Rule 5: register Does Not Mean Faster

Do not assume that declaring a variable register improves execution speed. Measure performance using the target compiler and processor.

15. Common Errors and Debugging

Error 1: Reading an Uninitialized Variable

int main(void)
{
    auto int value;

    printf("%d\n", value);

    return 0;
}

Problem: The automatic variable has no explicit initializer. Reading its indeterminate value this way produces undefined behavior.

Correction: 

int main(void)
{
    auto int value = 0;

    printf("%d\n", value);

    return 0;
}

Error 2: Taking the Address of a register Variable

register int count = 10;

int *ptr = &count;

Problem: The address of a register object cannot be taken.

Correction: Use an ordinary automatic object if its address is required. 

int count = 10;

int *ptr = &count;

Error 3: Expecting register to Preserve a Value

void counter(void)
{
    register int count = 0;

    count++;

    printf("%d\n", count);
}

Problem: register does not provide persistent storage between function calls.

Correction: Use static when a local object must retain its value.

16. Practical Applications in Embedded C

1. Temporary Calculations

Automatic variables are useful for local calculations inside driver functions, initialization routines and control algorithms.

2. Loop Processing

Loop counters and temporary values are commonly declared as ordinary local variables. Modern compilers optimize their use.

3. Register Allocation

Processor registers are limited hardware resources. Compilers automatically allocate them to variables and intermediate values according to optimization and calling convention requirements.

4. Predictable Embedded Software

Explicit initialization and controlled variable lifetimes help improve reliability in firmware. Avoid relying on uninitialized automatic variables or assumptions about compiler register allocation.

Practical recommendation: In LPC2129 and other embedded C projects, write clear local variable declarations and let the Keil or GCC compiler optimize register usage. Use compiler optimization reports and assembly inspection when investigating performance.

17. Interview Questions with Answers

Q1. What is auto in C?

auto is a storage-class specifier that explicitly specifies automatic storage duration for a block-scope object.

Q2. Is auto required for local variables?

No. Ordinary local variables already have automatic storage duration by default.

Q3. What is register in C?

register is a storage-class specifier that suggests that the implementation may store an object in a processor register.

Q4. Does register guarantee register storage?

No. It is only a hint and does not guarantee physical register allocation.

Q5. Can we use the address-of operator on a register variable?

No. The unary & operator cannot be applied to an object declared with register.

Q6. Do auto and register variables retain values between function calls?

No. They have automatic storage duration.

Q7. Are automatic variables initialized to zero by default?

No. An uninitialized automatic variable does not have a guaranteed initial value.

Q8. Can a register variable be used as a loop counter?

Yes. However, modern compilers generally perform register allocation automatically.

Q9. What is the difference between register and static?

register has automatic storage duration, whereas static local variables have static storage duration and retain their values between function calls.

Q10. Is register still useful in modern C?

It has limited practical value for performance tuning because compilers already perform register allocation. It remains important for understanding legacy code and C language rules.
