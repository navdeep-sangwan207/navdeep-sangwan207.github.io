Lecture 05: Linkage and Multiple Source Files

Understand external, internal and no linkage, translation units, symbol visibility, separate compilation and multi-file C project development.

1. Learning Objectives

  • Understand the meaning of linkage in C.
  • Differentiate external, internal and no linkage.
  • Understand the relationship between scope and linkage.
  • Learn how identifiers are shared across source files.
  • Understand translation units and preprocessing.
  • Learn separate compilation and linking.
  • Organize multi-file programs using header files.
  • Identify common linker errors and symbol conflicts.
  • Apply modular programming in embedded C projects.

2. What is Linkage?

Linkage determines whether an identifier declared in different scopes or translation units can refer to the same entity.

In C, identifiers can have three types of linkage:

  1. External linkage
  2. Internal linkage
  3. No linkage
Linkage is different from scope and storage duration. These are separate properties that must be understood independently.

3. External Linkage

An identifier with external linkage can refer to the same entity from different translation units.

Ordinary file-scope functions and objects generally have external linkage unless declared static or otherwise subject to a different language rule.

Example 1: External Global Variable

File: data.c

int system_value = 100;

File: main.c

#include <stdio.h>

extern int system_value;

int main(void)
{
    printf("%d\n", system_value);

    return 0;
}

Compile:

gcc -std=c11 -Wall -Wextra -pedantic main.c data.c -o app
Expected Output: 
100

Both translation units refer to the same externally linked object.

Example 2: External Function

File: math.c

int add(int a, int b)
{
    return a + b;
}

File: main.c

#include <stdio.h>

int add(int, int);

int main(void)
{
    printf("%d\n", add(10, 20));

    return 0;
}
Expected Output: 
30

4. Internal Linkage

An identifier with internal linkage refers to the same entity only within the current translation unit.

At file scope, the static specifier gives an object or function internal linkage.

Example 3: Internal Linkage of a Variable

File: module.c

static int private_count = 50;

int get_count(void)
{
    return private_count;
}

File: main.c

#include <stdio.h>

int get_count(void);

int main(void)
{
    printf("%d\n", get_count());

    return 0;
}
Expected Output: 
50

main.c cannot directly refer to private_count. It can access the value through get_count().

Example 4: Internal Linkage of a Function

#include <stdio.h>

static void display_message(void)
{
    printf("Private helper function\n");
}

void application_start(void)
{
    display_message();
}

int main(void)
{
    application_start();

    return 0;
}
Expected Output: 
Private helper function

display_message() is private to the translation unit containing its definition.

5. No Linkage

Identifiers with no linkage cannot refer to the same entity through declarations in different scopes or translation units.

Ordinary local variables declared inside a block generally have no linkage.

Example 5: Local Variables

#include <stdio.h>

void function_one(void)
{
    int number = 10;

    printf("%d\n", number);
}

void function_two(void)
{
    int number = 20;

    printf("%d\n", number);
}

int main(void)
{
    function_one();
    function_two();

    return 0;
}
Expected Output: 
10
20

Both functions have separate local objects named number. The identifiers have no linkage.

Other examples of identifiers with no linkage include function parameters and block-scope identifiers declared without extern.

6. Comparison of the Three Types of Linkage

Property External Internal No Linkage
Meaning Can refer to the same entity across translation units Restricted to one translation unit Identifier does not link to another declaration
Typical example Ordinary global variable File-scope static variable Ordinary local variable
Cross-file reference Possible Not through external linkage Not possible
Common use Shared interfaces Private module implementation Local computation

7. Scope vs Storage Duration vs Linkage

These three concepts are frequently confused in C interviews.

Scope

Scope determines where an identifier can be used in the source code.

Storage Duration

Storage duration determines the lifetime of an object during program execution.

Linkage

Linkage determines whether declarations in different scopes or translation units refer to the same entity.

Declaration Scope Storage Duration Linkage
int local; Block Automatic None
static int local; Block Static None
int global; File Static External
static int global; File Static Internal
void function(void); File Function External
static void helper(void); File Function Internal
A static local variable is an important interview example: it has block scope, static storage duration and no linkage.

8. What is a Translation Unit?

A translation unit is the source file after preprocessing. It includes the contents of headers and the results of preprocessing directives.

Example Project

Project/
|
|-- main.c
|-- math.c
|-- math.h
|-- sensor.c
|-- sensor.h

The compiler processes each source file independently as a translation unit.

  • main.c becomes one translation unit.
  • math.c becomes another translation unit.
  • sensor.c becomes another translation unit.

Header files are included during preprocessing. They do not normally become separate translation units on their own.

9. Preprocessing and Header Inclusion

The preprocessor handles directives such as #include, #define and conditional compilation.

Example 6: Header Inclusion

File: message.h

#ifndef MESSAGE_H
#define MESSAGE_H

void display_message(void);

#endif

File: message.c

#include <stdio.h>
#include "message.h"

void display_message(void)
{
    printf("Hello from message module\n");
}

File: main.c

#include "message.h"

int main(void)
{
    display_message();

    return 0;
}
Expected Output: 
Hello from message module

The header provides the function declaration. The implementation is compiled from message.c.

10. Header Guards

A header guard prevents the same header contents from being processed more than once within one translation unit.

Example 7: Standard Header Guard

#ifndef MOTOR_H
#define MOTOR_H

void motor_start(void);
void motor_stop(void);

#endif

Explanation:

  • #ifndef checks whether MOTOR_H is not defined.
  • #define defines MOTOR_H.
  • The header contents are included.
  • #endif closes the conditional section.
Header guards prevent repeated declarations caused by repeated inclusion. They do not prevent multiple external definitions placed in headers.

11. Separate Compilation

Separate compilation means compiling individual source files independently before linking them together.

Consider a project containing: 

main.c
math.c
sensor.c

Step 1: Compile Each Source File

gcc -std=c11 -Wall -Wextra -pedantic -c main.c
gcc -std=c11 -Wall -Wextra -pedantic -c math.c
gcc -std=c11 -Wall -Wextra -pedantic -c sensor.c

This produces: 

main.o
math.o
sensor.o

Step 2: Link Object Files

gcc main.o math.o sensor.o -o application

Step 3: Run the Program

./application

On Windows with a MinGW GCC environment, the executable may be named application.exe.

Separate compilation allows individual modules to be compiled and tested independently. It also supports larger projects and incremental rebuilding.

12. Complete Multi-File C Project

Build a small calculator application using separate source files and header files.

Project Structure

Calculator/
|
|-- main.c
|-- operations.c
|-- operations.h

File 1: operations.h

#ifndef OPERATIONS_H
#define OPERATIONS_H

int add(int a, int b);
int subtract(int a, int b);
int multiply(int a, int b);

#endif

File 2: operations.c

#include "operations.h"

int add(int a, int b)
{
    return a + b;
}

int subtract(int a, int b)
{
    return a - b;
}

int multiply(int a, int b)
{
    return a * b;
}

File 3: main.c

#include <stdio.h>
#include "operations.h"

int main(void)
{
    int a = 20;
    int b = 5;

    printf("Addition: %d\n", add(a, b));
    printf("Subtraction: %d\n", subtract(a, b));
    printf("Multiplication: %d\n", multiply(a, b));

    return 0;
}

Compilation

gcc -std=c11 -Wall -Wextra -pedantic main.c operations.c -o calculator
Expected Output: 
Addition: 25
Subtraction: 15
Multiplication: 100

This is a basic example of modular programming using separate compilation.

13. Symbol Visibility and Common Linker Errors

The linker works with symbols such as externally linked function and object names. These symbols allow object files to refer to definitions in other object files.

Error 1: Undefined Reference

A source file calls a function, but no matching definition is available during linking. 

int calculate(int, int);

int main(void)
{
    return calculate(10, 20);
}

If calculate() has no definition in any linked object file or library, linking fails.

Error 2: Multiple Definition

Two translation units define the same externally linked object. 

// Incorrect common.h

int count = 0;

If multiple source files include this header, each translation unit may contain a definition of count.

Error 3: Trying to Access an Internal Symbol

// module.c

static int internal_value = 10;

Another source file cannot access internal_value using an extern declaration.

Error 4: Incompatible Function Declarations

If one source file declares a function with an incompatible type compared with its definition, the program has a declaration consistency problem.

Always use a shared header file for declarations used by multiple source files. This reduces the risk of inconsistent declarations.

14. static Functions in Multi-File Projects

A function declared static at file scope is private to its translation unit. It is useful for helper functions that should not form part of a module's public API.

Example 8: Public API with Private Helpers

File: motor.c

#include <stdio.h>

static void enable_driver(void)
{
    printf("Driver enabled\n");
}

void motor_start(void)
{
    enable_driver();
    printf("Motor started\n");
}

File: main.c

#include <stdio.h>

void motor_start(void);

int main(void)
{
    motor_start();

    return 0;
}
Expected Output: 
Driver enabled
Motor started

enable_driver() is an internal helper. motor_start() is the public function.

15. Header Files: Best Practices

  • Use header guards in every reusable header.
  • Place function prototypes in headers.
  • Place extern declarations for shared objects in headers when needed.
  • Put external object definitions in one source file.
  • Use static for private file-scope helpers and state.
  • Avoid unnecessary global variables.
  • Do not put ordinary external object definitions in shared headers.
  • Use consistent function and object types across modules.
  • Include the module's own header in its implementation file.
Including a module's own header in its source file helps the compiler check that the implementation matches the public declarations.

16. Embedded C Applications

1. Peripheral Driver Organization

A microcontroller project can use separate modules for GPIO, UART, SPI, I2C, ADC and timers. 

Embedded_Project/
|
|-- main.c
|-- gpio.c
|-- gpio.h
|-- uart.c
|-- uart.h
|-- adc.c
|-- adc.h
|-- timer.c
|-- timer.h

2. Private Driver State

Each driver can use file-scope static variables to keep implementation details private.

3. Public Driver Interfaces

Header files expose functions such as UART_Init(), UART_SendByte() and ADC_Read().

4. Build Management

Separate compilation helps large embedded projects rebuild only the modules that have changed.

Modular design improves maintainability, testing and code reuse. It is especially useful in embedded firmware projects involving multiple peripherals.

17. Output Prediction and Interview Problems

Question 1: Local Variables with the Same Name

#include <stdio.h>

void first(void)
{
    int x = 10;
    printf("%d\n", x);
}

void second(void)
{
    int x = 20;
    printf("%d\n", x);
}

int main(void)
{
    first();
    second();

    return 0;
}
Expected Output: 
10
20

The two local identifiers have no linkage.

Question 2: Static File-Scope Variable

#include <stdio.h>

static int value = 10;

int main(void)
{
    printf("%d\n", value);

    return 0;
}
Expected Output: 
10

value has internal linkage.

Question 3: Static Local Variable

#include <stdio.h>

void count_calls(void)
{
    static int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    count_calls();
    count_calls();

    return 0;
}
Expected Output: 
1
2

count has no linkage despite having static storage duration.

18. Interview Questions with Answers

Q1. What is linkage in C?

Linkage determines whether declarations in different scopes or translation units refer to the same entity.

Q2. What are the three types of linkage?

External linkage, internal linkage and no linkage.

Q3. What is external linkage?

It allows an identifier to refer to the same entity across translation units.

Q4. What is internal linkage?

It restricts the entity's linkage to one translation unit.

Q5. What is no linkage?

It means the identifier does not link to another declaration of the same entity.

Q6. What is the difference between scope and linkage?

Scope determines where an identifier can be used in source code. Linkage determines whether declarations can refer to the same entity.

Q7. Can a static local variable have internal linkage?

No. A block-scope static local variable has no linkage.

Q8. What is a translation unit?

It is the source file after preprocessing, including included header contents.

Q9. What is separate compilation?

It is the process of compiling individual source files independently and linking their object files.

Q10. What is the purpose of a header file?

It provides shared declarations and interfaces between source files.

Q11. What is the purpose of static functions?

They restrict helper functions to the translation unit in which they are defined.

Q12. What is the difference between a compiler and linker?

The compiler translates source code into object code. The linker combines object files and libraries and resolves external references.
