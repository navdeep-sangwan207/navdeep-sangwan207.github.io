Lecture 03: static Local and Global Variables

Understand static storage duration, persistent local variables, file-scope static objects, internal linkage and practical C applications.

1. Learning Objectives

  • Understand the static storage-class specifier.
  • Differentiate static local and ordinary local variables.
  • Understand static initialization and zero initialization.
  • Learn static variables declared at file scope.
  • Understand internal linkage and file-level encapsulation.
  • Differentiate scope, storage duration and linkage.
  • Predict output involving static variables.
  • Apply static variables in embedded C and modular programming.

2. Introduction to static

The static keyword is a storage-class specifier in C. Its effect depends on where the declaration appears.

There are two important situations:

  1. Block scope: A static local variable has block scope and static storage duration.
  2. File scope: A static file-scope variable has file scope, static storage duration and internal linkage.
The same keyword has different effects on linkage depending on the declaration's scope. Do not confuse static storage duration with internal linkage.

3. Static Local Variables

A local variable declared with static inside a function or block has:

  • Block scope.
  • Static storage duration.
  • Lifetime covering the entire execution of the program.
  • Initialization performed once before program startup when an initializer is specified.
  • Value retention between function calls.

Example 1: Basic Static Local Variable

#include <stdio.h>

void display(void)
{
    static int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    display();
    display();
    display();

    return 0;
}
Expected Output: 
1
2
3

The variable count is initialized only once. Each function call modifies the same object. Its value is retained after display() returns.

4. Static Local vs Automatic Local Variables

Consider two local variables declared in the same function. One has automatic storage duration, while the other has static storage duration.

Example 2: Direct Comparison

#include <stdio.h>

void test(void)
{
    int automatic_count = 0;
    static int static_count = 0;

    automatic_count++;
    static_count++;

    printf("Automatic: %d\n", automatic_count);
    printf("Static: %d\n", static_count);
}

int main(void)
{
    test();
    test();
    test();

    return 0;
}
Expected Output: 
Automatic: 1
Static: 1
Automatic: 1
Static: 2
Automatic: 1
Static: 3

5. Initialization of Static Variables

Objects with static storage duration are initialized before program startup. If no explicit initializer is provided, they are initialized to zero.

Example 3: Static Variable Without Initializer

#include <stdio.h>

void display(void)
{
    static int number;

    number += 10;

    printf("%d\n", number);
}

int main(void)
{
    display();
    display();
    display();

    return 0;
}
Expected Output: 
10
20
30

number is initially zero-initialized. Its value is then increased by 10 on every call.

Example 4: Static Variable With Explicit Initializer

#include <stdio.h>

void calculate(void)
{
    static int value = 50;

    value += 5;

    printf("%d\n", value);
}

int main(void)
{
    calculate();
    calculate();
    calculate();

    return 0;
}
Expected Output: 
55
60
65
A static local variable is not initialized again every time the function is called. Its initializer is not a runtime reset operation.

6. Static Variables in Nested Blocks

A static variable can also be declared inside a nested block. It retains block scope but has static storage duration.

Example 5: Static Variable in a Nested Block

#include <stdio.h>

void process(void)
{
    {
        static int count = 0;

        count++;

        printf("%d\n", count);
    }
}

int main(void)
{
    process();
    process();
    process();

    return 0;
}
Expected Output: 
1
2
3

The variable count is visible only within the nested block. Its storage nevertheless persists throughout program execution.

7. Static Variables at File Scope

A variable declared outside all functions has file scope. When the declaration uses static, the identifier has internal linkage.

Internal linkage means that the identifier refers to the same entity only within the current translation unit. Other translation units cannot access that object through an external declaration of the same name.

Example 6: File-Scope Static Variable

#include <stdio.h>

static int sensor_count = 100;

void display(void)
{
    printf("Sensor count: %d\n", sensor_count);
}

int main(void)
{
    display();

    return 0;
}
Expected Output: 
Sensor count: 100

sensor_count has:

  • File scope.
  • Static storage duration.
  • Internal linkage.
File-scope static variables are useful when data should remain private to one source file.

8. File-Scope static vs File-Scope Global Variable

A file-scope object without static generally has external linkage, unless another applicable language rule changes its linkage.

Adding static gives it internal linkage.

Example 7: Two Different File-Scope Objects

#include <stdio.h>

int public_count = 10;
static int private_count = 20;

int main(void)
{
    printf("%d\n", public_count);
    printf("%d\n", private_count);

    return 0;
}
Expected Output: 
10
20

Scope File scope File scope

9. Internal Linkage and File-Level Encapsulation

Internal linkage is important when a C application contains multiple source files. It allows a source file to keep implementation details private.

Example 8: Private Variable and Public Function

File: sensor.c

#include <stdio.h>

static int sensor_value = 0;

void set_sensor_value(int value)
{
    sensor_value = value;
}

void display_sensor_value(void)
{
    printf("Sensor: %d\n", sensor_value);
}

File: main.c

#include <stdio.h>

void set_sensor_value(int value);
void display_sensor_value(void);

int main(void)
{
    set_sensor_value(75);
    display_sensor_value();

    return 0;
}
Expected Output: 
Sensor: 75

sensor_value is private to sensor.c. The functions provide controlled access to the variable.

Compile both files together: 

gcc main.c sensor.c -o sensor_app
This design is useful for drivers, peripheral modules and reusable C libraries. Other source files use the public functions instead of directly accessing internal state.

10. static Functions

The static specifier can also be applied to a function declared at file scope. Such a function has internal linkage.

It can be called from anywhere within its translation unit after a suitable declaration, but it cannot be called through an external declaration from another translation unit.

Example 9: Private Helper Function

#include <stdio.h>

static int square(int number)
{
    return number * number;
}

void display_result(void)
{
    printf("%d\n", square(5));
}

int main(void)
{
    display_result();

    return 0;
}
Expected Output: 
25

square() is a private helper function. It is accessible only within this translation unit.

File-scope static functions and variables help implement modular C programs with controlled interfaces.

11. static and const Are Different

static and const solve different problems.

  • static: A storage-class specifier that affects storage duration or linkage depending on scope.
  • const: A type qualifier that prevents modification through an expression with a const-qualified lvalue.

Example 10: Static Const Variable

#include <stdio.h>

void display(void)
{
    static const int limit = 100;

    printf("%d\n", limit);
}

int main(void)
{
    display();

    return 0;
}
Expected Output: 
100

limit has static storage duration and block scope. It is also const-qualified, so it cannot be modified through that identifier.

12. Practical Applications of static Local Variables

Application 1: Function Call Counter

#include <stdio.h>

void log_call(void)
{
    static unsigned int calls = 0;

    calls++;

    printf("Function calls: %u\n", calls);
}

int main(void)
{
    log_call();
    log_call();
    log_call();

    return 0;
}
Expected Output: 
Function calls: 1
Function calls: 2
Function calls: 3

Application 2: State Machine

#include <stdio.h>

void state_machine(void)
{
    static int state = 0;

    switch (state)
    {
        case 0:
            printf("IDLE\n");
            state = 1;
            break;

        case 1:
            printf("RUNNING\n");
            state = 2;
            break;

        case 2:
            printf("STOPPED\n");
            state = 0;
            break;
    }
}

int main(void)
{
    state_machine();
    state_machine();
    state_machine();
    state_machine();

    return 0;
}
Expected Output: 
IDLE
RUNNING
STOPPED
IDLE

The static state variable retains the state between calls. This technique can be used for simple state-machine logic.

Application 3: One-Time Initialization Flag

#include <stdio.h>

void initialize_module(void)
{
    static int initialized = 0;

    if (!initialized)
    {
        printf("Module initialized\n");
        initialized = 1;
    }
}

int main(void)
{
    initialize_module();
    initialize_module();
    initialize_module();

    return 0;
}
Expected Output: 
Module initialized
This simple one-time initialization pattern is suitable only when calls are appropriately serialized. A static flag alone does not make initialization thread-safe or interrupt-safe.

13. Important Limitations and Common Mistakes

Mistake 1: Assuming Static Local Variables Have File Scope

A static local variable retains block scope. It cannot be accessed directly outside the block in which it is declared.

Mistake 2: Assuming Every Static Variable Has Internal Linkage

A static local variable has no linkage. A static file-scope variable has internal linkage.

Mistake 3: Assuming Static Variables Are Initialized Every Call

Static initialization is not repeated on each function call. The object retains its stored value.

Mistake 4: Using Too Much Global Static State

Static state can make programs harder to test and maintain when many functions depend on hidden shared data. Keep module state controlled and expose clear interfaces.

Mistake 5: Assuming Static Makes a Variable Thread-Safe

Static storage duration does not guarantee synchronization. Concurrent modifications require appropriate synchronization or atomic operations.

15. Debugging and Identify-the-Error Questions

Problem 1: Accessing a Static Local Variable Outside Its Scope

#include <stdio.h>

void calculate(void)
{
    static int count = 10;
}

int main(void)
{
    calculate();

    printf("%d\n", count);

    return 0;
}

Identify the error: count is declared inside calculate(). It has block scope and cannot be accessed directly from main().

One correction:

#include <stdio.h>

int get_count(void)
{
    static int count = 10;

    return count;
}

int main(void)
{
    printf("%d\n", get_count());

    return 0;
}
Expected Output: 
10

Problem 2: Expecting Static Initialization to Repeat

void test(void)
{
    static int x = 10;

    x++;
}

Identify the misconception: x is not reset to 10 on every function call. Its initializer establishes its initial value before program execution.

Problem 3: Exposing a Private File-Scope Variable

A file-scope static variable cannot be accessed directly from another translation unit using an extern declaration.

Correction: Provide public functions in the source file to read or modify the private variable.

16. Practical Embedded C Applications

1. Peripheral Driver State

A UART driver can keep its internal configuration and status variables private to the driver source file using file-scope static objects.

2. State Machines

A static local variable can preserve the current state between periodic function calls.

3. Software Counters

Static variables can retain event counts, retry counts and function-call counts.

4. Module Encapsulation

Internal linkage prevents other source files from directly referring to private module variables and helper functions.

5. Memory Considerations

Static objects occupy storage for the entire program execution. Embedded developers should account for this when estimating RAM usage, particularly on memory-constrained microcontrollers.

A static variable shared between normal program code and an interrupt service routine may require volatile qualification for appropriate compiler access behavior. volatile alone does not guarantee atomicity or safe synchronization.

17. Interview Questions with Answers

Q1. What is a static local variable?

A block-scope variable declared with static that has static storage duration and retains its value between function calls.

Q2. What is the scope of a static local variable?

It has block scope.

Q3. What is the lifetime of a static local variable?

Its lifetime covers the entire execution of the program.

Q4. What is the default initial value of a static integer?

Zero, if it has no explicit initializer.

Q5. Does a static local variable retain its value between calls?

Yes. The same object is used across calls.

Q6. What is a file-scope static variable?

A file-scope variable declared with static. It has static storage duration and internal linkage.

Q7. What is internal linkage?

It means the identifier refers to the same entity only within the current translation unit.

Q8. What is the difference between static local and static global variables?

A static local variable has block scope and no linkage. A static file-scope variable has file scope and internal linkage. Both have static storage duration.

Q9. Can a static function be called from another source file?

No. A file-scope static function has internal linkage.

Q10. Why are static variables useful in embedded systems?

They can preserve state between function calls and provide private module-level storage for driver implementations.

Q11. Does static make a variable constant?

No. static and const have different purposes.

Q12. Are static variables automatically thread-safe?

No. Static storage duration does not provide synchronization for concurrent access.
