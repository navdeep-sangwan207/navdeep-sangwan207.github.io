Lecture 04: extern and External Linkage

Understand external declarations, global variable sharing, declarations versus definitions, and communication between multiple C source files.

1. Learning Objectives

  • Understand the purpose of the extern keyword.
  • Differentiate declaration and definition.
  • Understand external linkage.
  • Access a global variable declared in another source file.
  • Understand extern function declarations.
  • Organize C programs using header and source files.
  • Identify common linker errors involving global variables.
  • Apply extern in modular and embedded C projects.

2. Introduction to extern

The extern keyword is used to declare an object or function whose definition is provided elsewhere.

It is particularly useful when a C program is divided into multiple source files.

For example, a project may contain:

  • main.c - Main application.
  • sensor.c - Sensor implementation.
  • sensor.h - Sensor declarations.
extern tells the compiler that an object or function is declared here but its definition is provided elsewhere. The linker resolves the external reference.

3. Declaration vs Definition

Understanding this difference is essential for working with extern.

Declaration

A declaration introduces an identifier and describes its type. An external declaration can tell the compiler that an object is defined elsewhere. 

extern int temperature;

Definition

A definition of an object creates the object and reserves storage for it. 

int temperature = 25;

Example 1: Declaration and Definition

#include <stdio.h>

int value = 100;          // Definition

int main(void)
{
    extern int value;     // Declaration

    printf("%d\n", value);

    return 0;
}
Expected Output: 
100

The definition creates value. The extern declaration refers to that same object.

4. extern with Global Variables

A file-scope variable normally has external linkage unless it is declared static or another applicable rule changes its linkage.

An object with external linkage can be referred to from another translation unit using a compatible declaration.

Example 2: Global Variable in One Source File

File: data.c

int system_status = 1;

File: main.c

#include <stdio.h>

extern int system_status;

int main(void)
{
    printf("Status: %d\n", system_status);

    return 0;
}

Compile:

gcc main.c data.c -o app
Expected Output: 
Status: 1

data.c defines system_status. main.c declares it using extern. Both source files refer to the same object.

5. Modifying an Extern Variable

An extern declaration does not create a separate copy of the object. It refers to the object defined elsewhere.

Example 3: Updating a Shared Global Variable

File: data.c

int counter = 10;

File: main.c

#include <stdio.h>

extern int counter;

int main(void)
{
    printf("Initial: %d\n", counter);

    counter += 5;

    printf("Updated: %d\n", counter);

    return 0;
}
Expected Output: 
Initial: 10
Updated: 15

The change is applied to the same global object defined in data.c.

6. extern with Functions

Functions declared at file scope normally have external linkage unless declared static.

A function declaration can use extern, although it is generally optional because external linkage is the default for ordinary file-scope function declarations.

Example 4: Calling a Function from Another File

File: calculation.c

int add(int a, int b)
{
    return a + b;
}

File: main.c

#include <stdio.h>

extern int add(int, int);

int main(void)
{
    int result = add(10, 20);

    printf("Result: %d\n", result);

    return 0;
}
Expected Output: 
Result: 30

The function is defined in calculation.c and called from main.c.

In normal projects, function prototypes are usually placed in header files rather than repeated manually in each source file.

7. extern with and without an Initializer

The placement of an initializer matters.

Example 5: extern Declaration Without Initializer

extern int count;

This is a declaration, not a definition. It refers to an object defined elsewhere.

Example 6: File-Scope extern Declaration with Initializer

extern int count = 10;

At file scope, this is a definition because it has an initializer. It also specifies external linkage.

Do not place initialized extern definitions in a header file that is included by multiple source files. That can produce multiple definition errors at link time.

8. extern and Header Files

Header files are commonly used to share declarations between source files.

A typical structure is:

Project/
|
|-- main.c
|-- sensor.c
|-- sensor.h

File 1: sensor.h

#ifndef SENSOR_H
#define SENSOR_H

extern int sensor_value;

void set_sensor_value(int value);
int get_sensor_value(void);

#endif

File 2: sensor.c

#include "sensor.h"

int sensor_value = 0;

void set_sensor_value(int value)
{
    sensor_value = value;
}

int get_sensor_value(void)
{
    return sensor_value;
}

File 3: main.c

#include <stdio.h>
#include "sensor.h"

int main(void)
{
    set_sensor_value(75);

    printf("Sensor value: %d\n",
           get_sensor_value());

    printf("Direct access: %d\n",
           sensor_value);

    return 0;
}

Compile all source files:

gcc -std=c11 -Wall -Wextra -pedantic main.c sensor.c -o app
Expected Output: 
Sensor value: 75
Direct access: 75

sensor.h provides the declaration. sensor.c provides the definition and functions. main.c includes the header to access the interface.

9. Why Use extern in Header Files?

Suppose five source files need access to the same global variable.

Instead of writing an extern declaration manually in all five files, place the declaration in one shared header.

Every source file can include that header. There should normally be exactly one external definition of the object in the entire program.

Recommended organization:
  • Header file: declarations.
  • One source file: object definitions.
  • Other source files: include the header.

10. extern vs static

These two specifiers are especially important in multi-file C programs.

Property extern static at File Scope
Typical linkage External Internal
Cross-file access Can be referred to from another translation unit Cannot be referred to through external linkage
Typical use Sharing declarations Hiding implementation details

Example 7: static Object Cannot Be Referred to with extern

File: module.c

static int private_value = 50;

File: main.c

#include <stdio.h>

extern int private_value;

int main(void)
{
    printf("%d\n", private_value);

    return 0;
}

Problem: private_value has internal linkage in module.c. The extern declaration in main.c refers to an external-linkage object, but no such definition exists.

This program cannot be linked successfully as intended. A linker will normally report an undefined reference to private_value.

Correct approach:

// module.c

static int private_value = 50;

int get_private_value(void)
{
    return private_value;
}
// main.c

#include <stdio.h>

int get_private_value(void);

int main(void)
{
    printf("%d\n", get_private_value());

    return 0;
}
Expected Output: 
50

11. Multiple Definitions and Linker Errors

A common mistake is defining the same external object in a header file.

Incorrect Example

File: common.h

int counter = 0;

If main.c and module.c both include this header, each translation unit may contain a definition of counter.

The linker will generally report a multiple definition error.

Correct Example

File: common.h

#ifndef COMMON_H
#define COMMON_H

extern int counter;

#endif

File: common.c

#include "common.h"

int counter = 0;

File: main.c

#include <stdio.h>
#include "common.h"

int main(void)
{
    counter = 25;

    printf("%d\n", counter);

    return 0;
}
Expected Output: 
25

12. Translation Units and the Linker

A translation unit is the source file after preprocessing, including the contents of included headers.

Each source file is generally compiled separately into an object file.

For example:

main.c   --> main.o
sensor.c --> sensor.o

main.o + sensor.o
       |
       v
    Linker
       |
       v
  Final executable

If main.o refers to an external symbol defined in sensor.o, the linker resolves that reference.

extern is primarily a declaration mechanism. It does not itself load a library, compile another source file or create an object definition.

13. Practical Embedded C Application

Consider an embedded application with separate sensor and application modules.

File: adc.h

#ifndef ADC_H
#define ADC_H

extern unsigned int adc_result;

void adc_read(void);

#endif

File: adc.c

#include "adc.h"

unsigned int adc_result = 0;

void adc_read(void)
{
    /*
       Hardware-specific ADC conversion
       would be performed here.
    */

    adc_result = 512;
}

File: main.c

#include <stdio.h>
#include "adc.h"

int main(void)
{
    adc_read();

    printf("ADC Result: %u\n", adc_result);

    return 0;
}
Expected Output for this simulated example: 
ADC Result: 512

The ADC module owns the definition of adc_result. The application accesses it through the shared declaration.

In production embedded software, exposing mutable global state should be considered carefully. A getter function or a controlled interface can provide better encapsulation.

Important: extern and volatile

An object can be both externally linked and volatile-qualified. 

// shared.h

extern volatile unsigned int event_count;
// interrupt.c

volatile unsigned int event_count = 0;

This can be useful when an object is modified in an interrupt service routine and observed by normal application code.

volatile does not make an operation atomic, prevent race conditions or provide general thread synchronization. Verify the target processor's access width and use appropriate critical sections or atomic mechanisms where required.

14. Common Errors and Debugging

Error 1: Undefined Reference

A source file declares an external variable, but no matching definition is provided during linking.

Correction: Provide exactly one compatible definition in a compiled source file.

Error 2: Multiple Definition

The same external object is defined in multiple translation units.

Correction: Put an extern declaration in the header and one definition in a source file.

Error 3: Incompatible Declaration

A variable is declared with a type that conflicts with its actual definition.

Correction: Keep declarations and definitions type-compatible. Prefer a shared header to avoid inconsistent declarations.

Error 4: Missing Source File During Compilation

gcc main.c -o app

If a required definition is in sensor.c, compiling only main.c may leave unresolved external symbols.

Correction:

gcc -std=c11 -Wall -Wextra -pedantic main.c sensor.c -o app

16. Interview Questions with Answers

Q1. What is extern in C?

extern is a storage-class specifier commonly used to declare an object or function with external linkage whose definition is available elsewhere.

Q2. What is the difference between declaration and definition?

A declaration introduces an identifier and its type. A definition of an object creates the object and reserves storage.

Q3. Why is extern used in multi-file programs?

It allows one source file to refer to an externally linked object defined in another source file.

Q4. Does extern allocate memory?

A typical file-scope extern declaration without an initializer does not define the object or allocate its storage.

Q5. Can extern be used with functions?

Yes. However, an ordinary file-scope function declaration already has external linkage unless declared static.

Q6. What happens if a global variable is defined twice?

Multiple external definitions generally violate the C language's one-definition requirements and commonly cause linker errors.

Q7. Can extern access a static global variable?

No. A file-scope static variable has internal linkage and cannot be referred to through an external declaration in another translation unit.

Q8. What is a translation unit?

It is the source file after preprocessing, including the text of included headers.

Q9. Why should extern declarations be placed in header files?

It provides a common declaration to all source files and reduces inconsistencies.

Q10. What is the difference between extern and static?

extern commonly refers to an externally linked entity. File-scope static gives an entity internal linkage.

Q11. What is an undefined reference?

It is a linker error that occurs when a required external symbol cannot be resolved to a definition.

Q12. Can an extern variable be modified?

Yes, if it is not const-qualified and the program has permission to modify it. The modification affects the shared object.

18. Quick Revision

Concept Meaning
extern Declares an externally linked object or function.
Declaration Introduces an identifier and its type.
Definition Creates an object or provides a function body.
