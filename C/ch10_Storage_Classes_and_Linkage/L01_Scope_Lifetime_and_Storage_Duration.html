Lecture 01: Scope, Lifetime and Storage Duration

Understand where identifiers are accessible, how long objects exist and how C manages their storage duration.

1. Learning Objectives

  • Understand scope, lifetime and storage duration.
  • Differentiate block scope and file scope.
  • Understand function scope and function-prototype scope.
  • Learn automatic, static and allocated storage duration.
  • Understand object initialization and lifetime.
  • Analyze variable visibility using nested blocks.
  • Predict output involving local and global variables.
  • Identify common scope and lifetime errors.

2. Why Are Scope and Lifetime Important?

In C programming, variables and functions have different visibility and existence rules. A variable may be accessible only inside a particular function, or it may be accessible throughout a source file.

Similarly, an object may exist only while a function is executing, or it may continue to exist throughout the entire execution of the program.

These differences become especially important when developing large applications, embedded firmware and programs containing multiple source files.

Three questions help distinguish the concepts:
  • Scope: Where can an identifier be used?
  • Storage duration: During what period does an object exist?
  • Lifetime: During what part of execution is the object guaranteed to exist?

3. Understanding Scope

Scope is the region of a program in which an identifier's declaration is visible. Identifiers include variable names, function names, typedef names and other declared names.

C11 defines four categories of scope:

  1. Block scope
  2. File scope
  3. Function scope
  4. Function-prototype scope

4. Block Scope

An identifier declared inside a compound statement, also called a block, generally has block scope.

A block begins with an opening brace { and ends with a closing brace }.

Example 1: Local Variable

#include <stdio.h>

int main(void)
{
    int number = 10;

    printf("%d\n", number);

    return 0;
}
Expected Output: 
10

The variable number is declared inside main(). Its identifier has block scope and is visible from its declaration to the end of that block, subject to any nested declarations that hide it.

Example 2: Variable Inside a Nested Block

#include <stdio.h>

int main(void)
{
    int a = 10;

    {
        int b = 20;

        printf("a = %d\n", a);
        printf("b = %d\n", b);
    }

    printf("a = %d\n", a);

    return 0;
}
Expected Output: 
a = 10
b = 20
a = 10

The inner block can access a because a is declared in an enclosing block. The variable b is not visible after the inner block ends.

Trying to access b after the closing brace of the inner block produces a compilation error because b is outside its scope.

5. Variable Shadowing

Shadowing occurs when an identifier declared in an inner scope hides an identifier with the same name from an outer scope.

Example 3: Local Variable Shadowing

#include <stdio.h>

int main(void)
{
    int number = 10;

    {
        int number = 50;

        printf("%d\n", number);
    }

    printf("%d\n", number);

    return 0;
}
Expected Output: 
50
10

The inner number hides the outer number inside the nested block. After the inner block ends, the outer number becomes visible again.

Shadowing changes which declaration an identifier refers to. It does not change the value of the hidden outer variable.

6. File Scope

An identifier declared outside all functions and parameter lists has file scope. Its visibility extends from its declaration to the end of the translation unit.

A translation unit is the source file after preprocessing, including the contents of included header files.

Example 4: Global Variable

#include <stdio.h>

int global_count = 100;

void display(void)
{
    printf("Inside function: %d\n", global_count);
}

int main(void)
{
    printf("Inside main: %d\n", global_count);

    display();

    return 0;
}
Expected Output: 
Inside main: 100
Inside function: 100

global_count is declared at file scope. Both functions can access it because its declaration is visible at their definitions.

Example 5: File-Scope Variable Modified by Functions

#include <stdio.h>

int count = 0;

void increment(void)
{
    count++;
}

int main(void)
{
    increment();
    increment();

    printf("%d\n", count);

    return 0;
}
Expected Output: 
2

The function increment() modifies the same file-scope object each time it is called.

7. Function Scope

Function scope is a special scope category that applies to labels used with goto. A label has function scope, meaning it can be referenced from anywhere within the same function.

Example 6: goto Label

#include <stdio.h>

int main(void)
{
    int number = 1;

    if (number == 1)
    {
        goto finish;
    }

    printf("This statement is skipped.\n");

finish:
    printf("Program completed.\n");

    return 0;
}
Expected Output: 
Program completed.

The label finish can be referenced from another location within the same function. It cannot be used as a goto target from another function.

Avoid unnecessary goto statements. Structured control statements such as if, for and while generally produce clearer code.

8. Function-Prototype Scope

A parameter name declared inside a function prototype has function-prototype scope. It is visible only until the end of that function prototype.

Example 7: Function Prototype

#include <stdio.h>

int add(int first, int second);

int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    printf("%d\n", add(10, 20));

    return 0;
}
Expected Output: 
30

The parameter names first and second in the prototype are not required to match the names a and b in the function definition. Parameter names in the prototype have function-prototype scope.

9. Understanding Storage Duration

Storage duration describes the lifetime characteristics of an object: the period during program execution in which storage for that object is reserved.

C11 defines four storage-duration categories:

Storage Duration General Description
Automatic Storage is associated with execution of the block in which the object is declared.
Static Storage exists for the entire execution of the program.
Allocated Storage is managed through dynamic memory allocation and deallocation.
Thread Storage exists for the lifetime of the thread with which the object is associated.

Thread storage duration is supported by the C11 thread-local storage feature using the _Thread_local specifier.

10. Automatic Storage Duration

Objects declared in a block without a storage duration specifier generally have automatic storage duration.

Their storage is associated with execution of the enclosing block. When execution leaves that block, their lifetime ends.

Example 8: Automatic Local Variable

#include <stdio.h>

void display(void)
{
    int number = 10;

    printf("%d\n", number);
}

int main(void)
{
    display();

    return 0;
}
Expected Output: 
10

The variable number has automatic storage duration. Its lifetime ends when display() finishes executing.

Example 9: Automatic Variables in Repeated Function Calls

#include <stdio.h>

void counter(void)
{
    int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    counter();
    counter();
    counter();

    return 0;
}
Expected Output: 
1
1
1

Each function call creates a new automatic object named count. Its initialization starts at zero on each call.

11. Static Storage Duration

Objects with static storage duration exist throughout the execution of the program. This includes file-scope objects and objects declared with the static specifier inside a function.

Such objects are initialized before program startup. If no explicit initializer is provided, they are initialized to zero.

Example 10: Static Local Variable

#include <stdio.h>

void counter(void)
{
    static int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    counter();
    counter();
    counter();

    return 0;
}
Expected Output: 
1
2
3

The variable count retains its value between function calls because it has static storage duration.

Example 11: Global Variable Without Explicit Initialization

#include <stdio.h>

int total;

int main(void)
{
    printf("%d\n", total);

    return 0;
}
Expected Output: 
0

The file-scope variable total has static storage duration and is zero-initialized.

12. Allocated Storage Duration

Allocated storage duration is associated with dynamically allocated memory. Functions such as malloc(), calloc() and realloc() are used to manage allocated storage.

The lifetime of an allocated object begins when the allocation succeeds and ends when the allocated storage is deallocated.

Example 12: Dynamic Memory Allocation

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Allocation failed\n");
        return 1;
    }

    *ptr = 100;

    printf("%d\n", *ptr);

    free(ptr);
    ptr = NULL;

    return 0;
}
Expected Output: 
100

The allocated object remains available until free() deallocates it. The pointer variable ptr itself is a separate local object with automatic storage duration.

Remember that the pointer and the allocated object are two different objects with potentially different storage durations.

13. Thread Storage Duration in C11

C11 introduced thread-local storage using the _Thread_local storage-class specifier. Each thread gets its own separate instance of a thread-local object.

The object exists for the lifetime of the thread with which it is associated.

Example 13: Thread-Local Variable Declaration

#include <stdio.h>

_Thread_local int thread_count;

int main(void)
{
    thread_count = 10;

    printf("%d\n", thread_count);

    return 0;
}
Expected Output: 
10

This simple program demonstrates the declaration and use of a thread-local object. It does not create multiple threads.

Thread-local storage is useful when each execution thread requires independent state. It is less central to basic single-threaded embedded firmware but relevant to multithreaded systems.

14. Scope vs Lifetime vs Storage Duration

Concept What It Describes Example
Scope Where an identifier is visible. Local variable inside a function block.
Storage Duration Storage availability category and period. Automatic or static storage duration.
Lifetime Period during execution when an object exists. From the beginning to the end of an object's lifetime.

Example 14: Different Scope and Storage Duration

#include <stdio.h>

void display(void)
{
    static int count = 0;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    display();
    display();

    return 0;
}
Expected Output: 
1
2

count has block scope because it is declared inside display(). However, it has static storage duration because of the static storage-class specifier.

Scope and storage duration are independent concepts. A variable can have block scope and static storage duration.

15. Important Relationship Between Scope and Linkage

Scope describes the visibility of an identifier within the source code. Linkage determines whether declarations of the same identifier in different scopes or translation units refer to the same entity.

C11 defines three linkage categories:

  • External linkage: An identifier can refer to the same entity across translation units.
  • Internal linkage: An identifier refers to the same entity within one translation unit.
  • No linkage: The identifier does not refer to the same entity through declarations in other scopes or translation units.

Linkage will be studied in detail in the upcoming lectures on static, extern and multiple-source-file programming.

16. Output Prediction and Interview Practice

Question 1: Local and Global Variables

#include <stdio.h>

int value = 100;

int main(void)
{
    int value = 20;

    printf("%d\n", value);

    return 0;
}
Expected Output: 
20

The local variable hides the file-scope variable within main().

Question 2: Static and Automatic Variables

#include <stdio.h>

void test(void)
{
    int a = 0;
    static int b = 0;

    a++;
    b++;

    printf("%d %d\n", a, b);
}

int main(void)
{
    test();
    test();

    return 0;
}
Expected Output: 
1 1
1 2

a is recreated on each function call. b retains its previous value.

Question 3: Nested Scope

#include <stdio.h>

int main(void)
{
    int x = 10;

    {
        int x = 20;

        {
            int x = 30;

            printf("%d\n", x);
        }

        printf("%d\n", x);
    }

    printf("%d\n", x);

    return 0;
}
Expected Output: 
30
20
10

Each nested block introduces a new declaration that hides the outer declaration with the same identifier.

Question 4: Static Variable Initialization

#include <stdio.h>

void display(void)
{
    static int number;

    number += 5;

    printf("%d\n", number);
}

int main(void)
{
    display();
    display();
    display();

    return 0;
}
Expected Output: 
5
10
15

The static local variable is initialized to zero before program execution and retains its value across calls.

17. Common Programming Errors

Error 1: Accessing a Variable Outside Its Scope

#include <stdio.h>

int main(void)
{
    {
        int number = 10;
    }

    printf("%d\n", number);

    return 0;
}

Problem: number is not visible outside the inner block.

Correction: Declare number in the enclosing block if it must be used there.

Error 2: Returning Address of an Automatic Local Variable

int *get_value(void)
{
    int number = 10;

    return &number;
}

Problem: The lifetime of number ends when the function returns. The returned pointer does not provide a valid way to access that object.

Correction: Use caller-provided storage, allocated storage, or a static object when appropriate.

Corrected Example: Caller-Provided Storage

#include <stdio.h>

void get_value(int *result)
{
    if (result != NULL)
    {
        *result = 10;
    }
}

int main(void)
{
    int number;

    get_value(&number);

    printf("%d\n", number);

    return 0;
}
Expected Output: 
10

18. Practical Applications in Embedded C

1. Function-Local Variables

Automatic variables are useful for temporary calculations, function parameters and local processing data.

2. Persistent State

Static local variables can preserve a counter, state-machine state or initialization status across function calls.

3. File-Level Encapsulation

File-scope static variables can keep peripheral configuration or driver state private to one source file.

4. Dynamic Memory Management

Allocated storage can be useful in systems that support dynamic memory, but many embedded projects restrict or avoid heap allocation because of fragmentation and predictability concerns.

5. Interrupt and Shared State Design

Scope and lifetime help determine where shared state should be declared. When variables are accessed by an interrupt handler and normal code, volatile may be needed for the relevant access semantics. However, volatile alone does not make compound operations atomic or provide thread synchronization.

19. Interview Questions with Answers

Q1. What is scope in C?

Scope defines the region of source code in which an identifier is visible.

Q2. What is lifetime?

Lifetime is the period during program execution when an object exists.

Q3. What is storage duration?

Storage duration describes the storage availability category of an object. C11 defines automatic, static, allocated and thread storage duration.

Q4. What is block scope?

Block scope applies to identifiers declared within a block, such as local variables.

Q5. What is file scope?

File scope applies to identifiers declared outside all functions and parameter lists.

Q6. What is variable shadowing?

Shadowing occurs when a declaration in an inner scope hides a declaration with the same name in an outer scope.

Q7. What is automatic storage duration?

Automatic storage duration is associated with execution of the block in which the object is declared.

Q8. What is static storage duration?

Static storage duration means the object exists throughout program execution.

Q9. What is allocated storage duration?

It applies to dynamically allocated objects whose storage is explicitly managed through allocation and deallocation functions.

Q10. What is thread storage duration?

It applies to thread-local objects that exist for the lifetime of their associated thread.

Q11. Does static always mean global visibility?

No. A static local variable has block scope but static storage duration. A file-scope static variable has internal linkage.

Q12. Is a global variable automatically initialized?

A file-scope object with static storage duration is initialized to zero if it has no explicit initializer.
