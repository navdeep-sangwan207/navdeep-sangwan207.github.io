2. Complete Storage Classes Revision

Storage-class specifiers provide information about an identifier's storage duration, linkage or related properties.

1. auto

auto is used for block-scope objects with automatic storage duration. It is the default storage-class behavior for ordinary local variables. 

void test(void)
{
    auto int number = 10;
}

2. register

register is a storage-class specifier for block-scope objects with automatic storage duration. It is a request that the implementation may use a register for efficient access. 

void calculate(void)
{
    register int count = 0;

    count++;
}

The implementation is not required to actually store the object in a CPU register. The address-of operator cannot be applied directly to an object declared register.

3. static

At block scope, static gives an object static storage duration while retaining block scope and no linkage. 

void counter(void)
{
    static int count = 0;

    count++;
}

At file scope, static gives an object or function internal linkage and static storage duration for objects. 

static int private_value = 100;

static void helper(void)
{
    /* Private to this translation unit */
}

4. extern

extern is commonly used to declare an externally linked object or function defined elsewhere. 

extern int system_status;
The most important distinction is that static at block scope and static at file scope do not have the same linkage behavior.

3. Comparison of Storage Classes

Specifier Typical Scope Storage Duration Linkage
auto Block Automatic None
register Block Automatic None
static local Block Static None
static file-scope object File Static Internal
Ordinary file-scope object File Static External
extern declaration Depends on declaration context Does not independently determine object duration Usually external when referring to an external object
extern is not a separate storage-duration category. It does not itself create a new object when used as a typical file-scope declaration without an initializer.

4. Scope, Lifetime and Storage Duration

Concept Meaning
Scope Where an identifier can be used in source code.
Lifetime The period during program execution when an object exists.
Storage duration The language-defined category determining an object's lifetime.
Linkage Whether declarations can refer to the same entity.

Important Example

#include <stdio.h>

void test(void)
{
    static int value = 0;

    value++;

    printf("%d\n", value);
}

int main(void)
{
    test();
    test();

    return 0;
}
Expected Output: 
1
2

value has block scope, static storage duration and no linkage.

5. Technical Interview Questions: Fundamentals

Q1. What is a storage class in C?

A storage-class specifier provides information about an identifier's storage duration, linkage or other related properties.

Q2. What are the commonly discussed storage-class specifiers?

auto, register, static and extern. C11 also defines thread_local through the _Thread_local specifier, which is outside the scope of this chapter's core single-threaded examples.

Q3. What is the default storage duration of an ordinary local variable?

Automatic storage duration.

Q4. What is the default initial value of an ordinary uninitialized local integer?

It has an indeterminate value. Reading it as an ordinary integer value is not a valid way to obtain a predictable result.

Q5. What is the default initial value of a static integer?

Zero.

Q6. Does a static local variable retain its value?

Yes. Its object persists throughout program execution.

Q7. What is the purpose of register?

It provides a hint that an object may benefit from register storage. The implementation may ignore the hint.

Q8. Can we use the address-of operator on a register variable?

No. The unary & operator cannot be applied directly to an object declared with register.

Q9. Does static always mean internal linkage?

No. A block-scope static variable has no linkage. A file-scope static object or function has internal linkage.

Q10. What is the purpose of extern?

It allows a declaration to refer to an externally linked object or function defined elsewhere.

6. Technical Interview Questions: Linkage

Q11. What are the three types of linkage?

External linkage, internal linkage and no linkage.

Q12. What is external linkage?

It allows declarations in different translation units to refer to the same entity.

Q13. What is internal linkage?

It restricts the identifier's linkage to one translation unit.

Q14. What is no linkage?

It means the identifier does not link to another declaration of the same entity.

Q15. What is a translation unit?

It is a source file after preprocessing, including the contents of included headers.

Q16. What is the difference between scope and linkage?

Scope determines where an identifier is visible in source code. Linkage determines whether declarations can refer to the same entity.

Q17. Can a static local variable be accessed from another function?

Not directly through its identifier. Its scope remains limited to the block in which it is declared. A function can provide controlled access to it.

Q18. Can two source files contain static variables with the same name?

Yes. Each file-scope static object has internal linkage within its own translation unit, so the identifiers do not conflict across translation units.

7. Output Prediction: Static and Automatic Variables

Question 1

#include <stdio.h>

void display(void)
{
    int a = 0;
    static int b = 0;

    a++;
    b++;

    printf("%d %d\n", a, b);
}

int main(void)
{
    display();
    display();
    display();

    return 0;
}
Expected Output: 
1 1
1 2
1 3

a is recreated on each function call. b retains its value.

Question 2

#include <stdio.h>

int main(void)
{
    static int x = 10;

    {
        static int x = 20;

        printf("%d\n", x);
    }

    printf("%d\n", x);

    return 0;
}
Expected Output: 
20
10

The inner declaration shadows the outer identifier within the nested block. These are separate objects.

Question 3

#include <stdio.h>

int count = 5;

void update(void)
{
    static int count = 10;

    count++;

    printf("%d\n", count);
}

int main(void)
{
    update();
    update();

    printf("%d\n", count);

    return 0;
}
Expected Output: 
11
12
5

The local static count shadows the file-scope count inside update(). The global object remains unchanged.

Question 4

#include <stdio.h>

static int number;

int main(void)
{
    number += 5;

    printf("%d\n", number);

    return 0;
}
Expected Output: 
5

The file-scope static object is zero-initialized before program execution.

8. Output Prediction: Extern and Global Variables

Question 6

#include <stdio.h>

int value = 10;

int main(void)
{
    extern int value;

    value += 20;

    printf("%d\n", value);

    return 0;
}
Expected Output: 
30

Question 7

File: data.c

int number = 25;

File: main.c

#include <stdio.h>

extern int number;

int main(void)
{
    number += 5;

    printf("%d\n", number);

    return 0;
}
Expected Output: 
30

Both files refer to the same externally linked object.

Question 8

File: module.c

static int value = 10;

File: main.c

extern int value;

int main(void)
{
    return value;
}

Answer: This is not a valid way to access the static object in module.c. The extern declaration in main.c requires an external-linkage definition, which is not provided.

The expected result is a link failure, typically an undefined reference to value. It is not a predictable numeric output.

9. Identify-the-Error Questions

Problem 1: Address of a register Variable

int main(void)
{
    register int number = 10;

    int *ptr = &number;

    return 0;
}

Error: The address-of operator cannot be applied to an object declared with register.

Problem 2: Accessing a Local Variable Outside Its Scope

void test(void)
{
    static int count = 10;
}

int main(void)
{
    return count;
}

Error: count has block scope inside test(). It is not visible in main().

Problem 3: Nonconstant Initializer for a Static Object

int get_value(void)
{
    return 10;
}

int main(void)
{
    static int value = get_value();

    return value;
}

Error: In C11, an object with static storage duration must have a constant initializer. A function call is not a valid initializer here.

Problem 4: Multiple External Definitions

File: common.h

int counter = 0;

If several source files include this header, they can each produce an external definition of counter.

Correction: Use an extern declaration in the header and define counter once in one source file.

Problem 5: Accessing a File-Scope Static Function

A static function in module.c cannot be called from main.c through an ordinary external function declaration.

Correction: Provide a non-static public function that invokes the private helper.

10. Declaration vs Definition: Interview Revision

Code Meaning
extern int value; External declaration of an object.
int value; File-scope tentative definition.
int value = 10; File-scope definition.
extern int value = 10; File-scope definition with external linkage.
static int value; File-scope tentative definition with internal linkage.
void display(void); Function declaration.
void display(void) { } Function definition.
At file scope, an object declaration without an initializer is generally a tentative definition unless it is an appropriate extern declaration. If no full definition appears in the translation unit, a tentative definition is treated as a zero-initialized definition at the end of that translation unit.

11. Practical Multi-File Coding Challenge

Create a simple counter module using a private static variable and public functions.

Project Structure

Counter_Project/
|
|-- main.c
|-- counter.c
|-- counter.h

File: counter.h

#ifndef COUNTER_H
#define COUNTER_H

void counter_increment(void);
int counter_get(void);
void counter_reset(void);

#endif

File: counter.c

#include "counter.h"

static int count = 0;

void counter_increment(void)
{
    count++;
}

int counter_get(void)
{
    return count;
}

void counter_reset(void)
{
    count = 0;
}

File: main.c

#include <stdio.h>
#include "counter.h"

int main(void)
{
    counter_increment();
    counter_increment();
    counter_increment();

    printf("Count: %d\n", counter_get());

    counter_reset();

    printf("After reset: %d\n", counter_get());

    return 0;
}

Compile

gcc -std=c11 -Wall -Wextra -pedantic main.c counter.c -o counter_app
Expected Output: 
Count: 3
After reset: 0

The count variable is private to counter.c. Other source files can manipulate it only through the public functions.

12. Embedded C Interview Questions

Q1. Why are static variables useful in embedded C?

They retain state between function calls and can provide persistent module-level data.

Q2. Why use file-scope static variables in drivers?

They keep internal driver state private to the driver implementation.

Q3. Can a static variable be shared between an ISR and main code?

Yes, if both operate on the same object and the scope and linkage permit access. It may need volatile qualification where appropriate, but volatile does not provide atomicity or synchronization.

Q4. Is register useful in modern embedded compilers?

Modern compilers generally perform their own register allocation. The register keyword is usually unnecessary, and its address restriction remains important.

Q5. What is the benefit of modular programming?

It improves code reuse, testing, maintenance and separation of peripheral functionality.

Q6. What is the difference between static and extern in a driver?

File-scope static keeps implementation details private. extern allows other translation units to refer to an externally linked object or function.

Q7. Does static guarantee that a variable is stored in RAM?

No. The C language defines storage duration and behavior, not a mandatory physical memory section. The compiler and linker determine actual placement according to the target and program.
