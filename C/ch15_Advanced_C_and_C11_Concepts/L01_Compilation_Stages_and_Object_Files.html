Lecture 01: Compilation Stages and Object Files

Chapter 15 – Advanced C and C11 Concepts

Understand how C source code becomes an executable program.

1. Learning Objectives

  • Understand the complete C program build process.
  • Differentiate preprocessing, compilation, assembly and linking.
  • Understand the role of the compiler driver.
  • Identify source files, header files, assembly files and object files.
  • Understand symbols, relocation information and linking.
  • Compile and inspect a C program using GCC.
  • Recognize common compilation and linking errors.

2. What Is Compilation?

Compilation is the process of translating a program written in a high-level programming language into a lower-level representation that a computer can execute.

C is a compiled language. A C source file is generally processed through multiple stages before an executable program is produced.

For example, consider a source file named:

main.c

The build toolchain processes this file and produces an executable suitable for the target operating system and processor.

Important distinction: The C language standard specifies translation requirements and program behavior. The exact internal compiler architecture, intermediate representations and file formats depend on the implementation and toolchain.

3. Complete C Compilation Pipeline

A typical GCC-based build process can be represented as:

       C Source Code
          main.c
             |
             v
       Preprocessor
             |
             v
    Expanded Source Code
          main.i
             |
             v
          Compiler
             |
             v
       Assembly Code
          main.s
             |
             v
          Assembler
             |
             v
        Object File
          main.o
             |
             v
          Linker
             |
             v
      Executable Program

The four major stages are:

  1. Preprocessing
  2. Compilation
  3. Assembly
  4. Linking

4. Stage 1 – Preprocessing

The preprocessor handles preprocessing directives before the compiler proper processes the C translation unit.

Common preprocessing directives include:

  • #include – includes header contents.
  • #define – defines macros.
  • #if, #ifdef and #ifndef – conditional compilation.
  • #undef – removes a macro definition.

Example: Source Code

#include <stdio.h>

#define VALUE 100

int main(void)
{
    printf("Value = %d\n", VALUE);
    return 0;
}

What Happens?

  • The preprocessor processes the stdio.h inclusion.
  • The macro VALUE is replaced with 100.
  • Conditional preprocessing directives are evaluated.
  • A preprocessed translation unit is produced.

Generate Preprocessed Output

gcc -E main.c -o main.i

Here:

  • -E stops after preprocessing.
  • -o main.i specifies the output filename.
The preprocessed file commonly has the extension .i. It contains expanded source text, including the effects of processed header inclusions and macros.

5. Stage 2 – Compilation

The compiler proper analyzes the preprocessed C translation unit, checks language rules, performs semantic analysis and translates the program into a lower-level representation.

Typical compiler activities include:

  • Lexical analysis and parsing.
  • Syntax and semantic checking.
  • Type checking and conversion analysis.
  • Intermediate representation generation.
  • Optimization.
  • Target-specific code generation.

Generate Assembly Code

gcc -S main.i -o main.s

The -S option instructs GCC to stop after compilation and produce assembly language output.

Assembly instructions depend on the target architecture. For example, x86-64 and ARM processors use different instruction sets.

6. Stage 3 – Assembly

The assembler converts assembly instructions into machine-code representations and generates an object file.

Generate an Object File

gcc -c main.s -o main.o

The -c option produces an object file without performing the final linking stage.

Object files commonly contain:

  • Machine-code sections.
  • Data sections.
  • Symbol information.
  • Relocation information.
  • Debug information, when generated.
An object file is not necessarily a complete executable program. It may contain unresolved external references that must be resolved by the linker.

7. Stage 4 – Linking

Linking combines object files and required libraries to produce an executable or another linkable output.

The linker performs important tasks such as:

  • Combining sections from input object files.
  • Resolving external symbol references.
  • Processing relocation information.
  • Including or connecting required library code.
  • Generating the final executable or shared library.

Example

gcc main.o -o program

This command links the object file and generates an executable named program.

External Symbol Example

Consider two source files.

math.c

int add(int a, int b)
{
    return a + b;
}

main.c

#include <stdio.h>

int add(int a, int b);

int main(void)
{
    printf("Sum = %d\n", add(10, 20));
    return 0;
}

Compile Separately

gcc -std=c11 -Wall -Wextra -c main.c -o main.o

gcc -std=c11 -Wall -Wextra -c math.c -o math.o

Link the Object Files

gcc main.o math.o -o program

Run the Program

./program
Expected Output 
Sum = 30

The function add() is defined in math.c and called from main.c. The linker connects the function reference with its definition.

8. What Is a Compiler Driver?

A compiler driver is the command-line program that coordinates the different tools required to build a program.

When you execute a command such as gcc main.c -o program, the GCC driver normally coordinates preprocessing, compilation, assembly and linking.

Depending on the toolchain, it invokes components such as:

  • Preprocessor.
  • Compiler proper.
  • Assembler.
  • Linker.
Interview distinction: GCC is commonly used as the compiler driver command. It coordinates multiple stages; it is not accurate to say that one single program performs every build operation internally.

9. Object Files and Their Contents

An object file is an intermediate binary file produced by the assembler or compiler toolchain. It is commonly used as input to the linker.

Important Object File Components

Component Purpose
Code section Contains machine instructions.
Data section Contains initialized data objects, depending on the format.
BSS section Represents zero-initialized or uninitialized static-storage data.
Symbol table Records symbols such as functions and external objects.
Relocation entries Provide information needed to adjust addresses and references.
Debug information Supports source-level debugging when included.
These are common object-file concepts, not a fixed layout required by the C language. Exact sections and formats depend on the platform and object-file format, such as ELF or COFF.

10. Symbols and Symbol Resolution

A symbol is a name associated with a function, object or other entity represented in compiled code.

Consider:

int calculate(int x, int y)
{
    return x + y;
}

The function name calculate can appear as a symbol in the generated object file.

Common Symbol Categories

  • Defined symbol: Has a definition in an input object file.
  • Undefined symbol: Is referenced but its definition must be found elsewhere.
  • Global symbol: Can be visible to other translation units according to its linkage.
  • Local symbol: Is limited to its object-file or implementation-specific scope.

The linker uses symbol information to connect references with their definitions.

11. Relocation

During compilation and assembly, the final memory addresses of some functions and objects may not yet be known.

Relocation is the process of adjusting address-dependent references when the linker places sections and resolves symbols.

Example Concept

main.c  ---- references ----> add()

math.c  ---- defines -------> add()

The object file containing main() may initially hold a relocation entry for the call to add(). The linker uses the definition in the other object file to resolve that reference.

Relocation is especially important when understanding object files, static libraries, shared libraries and executable loading.

12. Compilation vs Linking Errors

Error Type Meaning Example
Preprocessing error Problem processing directives or included files. Missing header file.
Compilation error Violation of C syntax or semantic constraints. Missing semicolon or incompatible declaration.
Assembly error Problem translating generated assembly. Invalid target instruction.
Linker error Unresolved or conflicting symbols. Undefined reference to a function.
Runtime error Problem occurring while the program executes. Invalid memory access.

Example of a Linker Error

#include <stdio.h>

int calculate(int, int);

int main(void)
{
    printf("%d\n", calculate(5, 3));
    return 0;
}

If no linked object file or library provides a suitable definition of calculate(), the linker will generally report an undefined reference.

A function declaration tells the compiler about a function's interface. It does not provide the function's implementation.

13. Useful GCC Commands

Command Purpose
gcc -E main.c -o main.i Preprocess source code.
gcc -S main.c -o main.s Generate assembly output.
gcc -c main.c -o main.o Generate an object file.
gcc main.o -o program Link an object file.
gcc main.c -o program Build an executable using the driver.
gcc -Wall -Wextra -Wpedantic main.c Enable useful compiler diagnostics.
nm main.o Inspect symbols on supported systems.
readelf -a main.o Inspect ELF object-file information.
objdump -d main.o Disassemble machine code.
Linux note: nm, readelf and objdump are commonly available with GNU Binutils. Their availability and supported formats depend on the installed toolchain.

14. Static and Dynamic Linking – Introduction

Linking can involve static libraries or shared libraries. The exact behavior depends on the operating system, linker and build configuration.

Static Linking Dynamic Linking
Required library code is incorporated into the linked output. Shared-library code is generally loaded or mapped separately.
Can increase executable size. Can reduce duplicated library code across programs.
Library updates may require rebuilding the executable. Programs may use compatible updated shared libraries.

Static libraries commonly use the .a extension on Unix-like systems. Shared libraries commonly use .so on Linux and .dll on Windows.

A detailed treatment of libraries and dynamic loading can be studied further in system programming.

15. Placement-Oriented Interview Questions

Q1. What are the four major stages of C compilation?

Answer: Preprocessing, compilation, assembly and linking.

Q2. What is the purpose of a preprocessor?

Answer: It processes directives such as #include, #define and conditional compilation directives before compilation.

Q3. What is an object file?

Answer: It is a binary output containing machine-code and related information, such as symbols and relocation entries, that can be used by the linker.

Q4. What is the difference between a compiler and a linker?

Answer: The compiler translates a translation unit into lower-level code. The linker combines object files and libraries and resolves external references.

Q5. What is an undefined reference error?

Answer: It is commonly a linker error that occurs when a required symbol definition cannot be found.

Q6. What is the purpose of the -c option in GCC?

Answer: It compiles and assembles source code into an object file without performing the final link.

Q7. What is a symbol table?

Answer: It is object-file metadata that records information about symbols, such as functions and objects.

Q8. What is relocation?

Answer: It is the adjustment of address-dependent references when the linker assigns final locations to sections and resolves symbols.

Q9. Does a successful compilation always mean the program is correct?

Answer: No. Compilation does not guarantee correct logic, absence of runtime errors or freedom from undefined behavior.

Q10. What does GCC do when we execute gcc main.c -o program?

Answer: The GCC driver coordinates the required build stages and invokes the necessary tools to generate the executable.

16. Practical Lab Exercise

Objective

Compile a C program through separate stages and inspect the generated files.

Step 1 – Create main.c

#include <stdio.h>

#define NUMBER 50

int main(void)
{
    int value = NUMBER;

    printf("Value = %d\n", value);

    return 0;
}

Step 2 – Run Preprocessing

gcc -E main.c -o main.i

Step 3 – Generate Assembly

gcc -S main.i -o main.s

Step 4 – Generate Object File

gcc -c main.s -o main.o

Step 5 – Link the Object File

gcc main.o -o program

Step 6 – Execute

./program
Expected Output 
Value = 50

Expected Generated Files

File Description
main.c Original C source file.
main.i Preprocessed source file.
main.s Assembly source file.
main.o Object file.
program Final executable.
You can perform this exercise in Ubuntu using GCC. The same concepts apply to embedded toolchains, although the target object format, linker and executable output may differ.

18. Key Takeaways

  • C programs commonly pass through four major build stages.
  • The preprocessor handles preprocessing directives.
  • The compiler translates C code into lower-level code.
  • The assembler generates object files.
  • The linker resolves external references and creates the final output.
  • Object files contain code and metadata used during linking.
  • Symbols and relocation entries help the linker connect program components.
  • Compilation success does not guarantee runtime correctness.
