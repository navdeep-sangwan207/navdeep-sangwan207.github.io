Lecture 02: Program Memory Layout and Execution

Chapter 15 – Advanced C and C11 Concepts

Understand how a typical C program uses memory during execution.

1. Learning Objectives

  • Understand the typical memory layout of a C process.
  • Differentiate code, data, BSS, heap and stack regions.
  • Understand local, global and static variable storage.
  • Explain stack frames and function calls.
  • Understand dynamic memory allocation.
  • Recognize memory-related programming errors.
  • Relate memory organization to embedded C programming.

2. What Is Program Memory Layout?

When a program executes, the operating system and runtime environment arrange its code and data in memory according to the executable format, processor architecture and operating-system design.

A typical process memory layout is commonly described using these regions:

  • Text or code segment
  • Read-only data region
  • Initialized data segment
  • BSS segment
  • Heap
  • Stack
Important: This is a common implementation model, not a memory layout mandated by the C language standard. Actual layouts vary across operating systems, processors, linkers and embedded environments.

In a commonly encountered process layout, the stack and heap occupy different address ranges and may grow toward each other. This is not universal.

4. Text or Code Segment

The text segment generally contains the executable machine instructions of a program.

Example:

#include <stdio.h>

int main(void)
{
    printf("Hello C Programming\n");
    return 0;
}

The machine instructions generated for functions such as main() are commonly stored in the code region.

Typical Characteristics

  • Contains executable instructions.
  • Often mapped with execute permission.
  • Frequently mapped read-only during normal execution.
  • May be shared between processes running the same executable.
The exact permissions and mapping behavior are operating-system and executable-format dependent.

5. Read-Only Data Region

A typical executable may have a read-only data region containing constants such as string literals. 

#include <stdio.h>

int main(void)
{
    const char *message = "Hello Embedded C";

    printf("%s\n", message);

    return 0;
}

The string literal may be placed in a read-only section by the compiler and linker. The pointer variable message is a separate object.

Do not attempt to modify a string literal. Modifying a string literal through a pointer results in undefined behavior in C.

6. Initialized Data Segment

The initialized data segment commonly stores initialized objects with static storage duration whose initial values are not all zero.

Example

#include <stdio.h>

int global_value = 100;

static int count = 25;

int main(void)
{
    printf("Global = %d\n", global_value);
    printf("Count = %d\n", count);

    return 0;
}

The variables global_value and count have static storage duration. In a typical implementation, their initialized data is stored in an initialized data section.

Important Characteristics

  • Contains certain initialized static-storage objects.
  • Values are established as part of program initialization.
  • Objects generally retain their values throughout program execution.

7. BSS Segment

BSS is a traditional name for a section used for zero-initialized or uninitialized static-storage objects.

Example

#include <stdio.h>

int global_count;

static int device_status;

int main(void)
{
    printf("Global count = %d\n", global_count);
    printf("Device status = %d\n", device_status);

    return 0;
}
Expected Output 
Global count = 0
Device status = 0

Objects with static storage duration are initialized to zero when no explicit initializer is provided.

Initialized Data vs BSS

Initialized Data BSS
Typically contains initialized static-storage objects. Typically contains zero-initialized static-storage objects.
Initial values are represented in the executable image. Often represented by section size rather than storing all zero bytes in the file.
Example: int x = 10; at file scope. Example: int x; at file scope.
BSS is a toolchain and executable-format concept. The C language specifies initialization and storage duration rules, not a mandatory BSS section.

8. Stack Memory

The stack is commonly used to manage function calls and automatic storage. A function call may create a stack frame containing information such as local variables, saved registers and return-address information.

Example

#include <stdio.h>

void display(void)
{
    int number = 20;
    printf("Number = %d\n", number);
}

int main(void)
{
    int value = 10;

    display();

    printf("Value = %d\n", value);

    return 0;
}

In a common implementation, the automatic variables value and number are stored in stack frames. However, the compiler may use registers or optimize storage in other ways.

Stack Characteristics

  • Supports function-call management.
  • Often stores automatic local variables.
  • Typically uses automatic allocation and deallocation.
  • Function calls and returns manage stack frames.
  • Deep recursion may exhaust available stack space.

Stack Frame Concept

main()
  |
  | calls display()
  v
display() stack frame created
  |
  | function completes
  v
display() stack frame released
  |
  v
main() continues
Returning the address of an ordinary local automatic variable is unsafe because its lifetime ends when the function returns.

Incorrect Example

int *getValue(void)
{
    int number = 100;
    return &number;
}

The returned pointer becomes invalid after the function returns. Using it to access the former local object results in undefined behavior.

9. Heap Memory

The heap is commonly used for dynamic memory allocation. The programmer requests memory during execution and later releases it when it is no longer required.

Important allocation functions:

  • malloc()
  • calloc()
  • realloc()
  • free()

Example: Dynamic Allocation

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    *ptr = 100;

    printf("Value = %d\n", *ptr);

    free(ptr);
    ptr = NULL;

    return 0;
}
Expected Output 
Value = 100

Heap Characteristics

  • Memory is requested dynamically during program execution.
  • Allocation size can depend on runtime requirements.
  • Allocated memory remains reserved until released or until the process terminates.
  • Failure to release unused allocations can cause memory leaks.
  • Accessing memory after free can result in undefined behavior.
In C, dynamically allocated storage is managed using the standard library allocation functions. The C standard does not require that this storage be physically implemented using a region specifically called the heap.

10. Local, Global and Static Variables

Variable scope, storage duration and memory placement are related concepts, but they are not interchangeable. 

#include <stdio.h>

int global_var = 10;

void test(void)
{
    int local_var = 20;
    static int static_var = 30;

    printf("Local = %d\n", local_var);
    printf("Static = %d\n", static_var);

    static_var++;
}

int main(void)
{
    test();
    test();

    printf("Global = %d\n", global_var);

    return 0;
}
Expected Output 
Local = 20
Static = 30
Local = 20
Static = 31
Global = 10
Variable Storage Duration Typical Implementation
Ordinary local variable Automatic Often stack or register
Global variable Static Data or BSS section
Static local variable Static Data or BSS section
Dynamically allocated object Allocated storage duration Commonly heap-managed
An ordinary local variable has automatic storage duration. A local variable declared with static has static storage duration even though its name has block scope.

11. Function Calls and Recursion

Function calls commonly require the runtime environment to preserve return information and manage function-local state. This is often implemented using stack frames.

Example: Recursive Function

#include <stdio.h>

int factorial(int n)
{
    if (n <= 1)
    {
        return 1;
    }

    return n * factorial(n - 1);
}

int main(void)
{
    printf("Factorial = %d\n", factorial(5));
    return 0;
}
Expected Output 
Factorial = 120

Each recursive call must preserve enough information to continue the previous call after the deeper call returns.

Excessive recursion can exhaust the available call stack in implementations that use a stack for function calls.

12. Memory Allocation Errors

1. Memory Leak

A memory leak occurs when dynamically allocated memory is no longer needed but is not released. 

int *ptr = malloc(sizeof *ptr);

/* Missing free(ptr) */

2. Dangling Pointer

A dangling pointer refers to an object whose lifetime has ended or whose allocated storage has been released. 

int *ptr = malloc(sizeof *ptr);

if (ptr != NULL)
{
    *ptr = 50;
    free(ptr);
    ptr = NULL;
}

3. Null Pointer Dereference

int *ptr = NULL;

/* Invalid: do not dereference NULL */
*ptr = 10;

4. Buffer Overflow

A buffer overflow occurs when a program accesses memory outside the bounds of an allocated object.

Memory errors can cause crashes, data corruption, security vulnerabilities and undefined behavior.

13. Memory Layout in Embedded Systems

Embedded systems also require organized storage for code, initialized data, zero-initialized data, stack and dynamically allocated memory when a heap is used.

Unlike a general-purpose operating system process, a microcontroller application often uses a linker script or scatter-loading file to define memory placement.

Typical Embedded Memory Organization

Memory Typical Use
Flash / ROM Program instructions and constant data.
RAM - Data Initialized global and static variables copied or initialized at startup.
RAM - BSS Zero-initialized global and static variables.
Stack Function calls, automatic variables and saved context.
Heap Dynamic allocation, if enabled and configured.
Embedded interview point: Many microcontrollers have limited RAM. Stack sizing, global memory consumption and dynamic allocation strategy are important design considerations. Some embedded applications deliberately avoid heap allocation to improve predictability.

14. Placement-Oriented Interview Questions

Q1. What are the common regions in a process memory layout?

Answer: Commonly described regions include text, read-only data, initialized data, BSS, heap and stack.

Q2. What is the difference between data and BSS?

Answer: The initialized data section typically holds initialized static-storage objects, while BSS commonly represents zero-initialized or uninitialized static-storage objects.

Q3. Where are local variables stored?

Answer: In a common implementation, automatic local variables may be stored in stack frames or registers. The C standard does not require a physical stack.

Q4. What is the difference between stack and heap?

Answer: The stack commonly manages function calls and automatic storage, while heap-managed storage is requested and released dynamically.

Q5. Where is a static local variable stored?

Answer: It has static storage duration and is commonly placed in the data or BSS region.

Q6. What happens when a function returns?

Answer: Its execution ends, and its ordinary automatic local objects cease to exist. A typical implementation also releases the function's stack frame.

Q7. What is a stack overflow?

Answer: It is a failure caused when stack requirements exceed the available stack space in an implementation.

Q8. What is a memory leak?

Answer: It occurs when dynamically allocated storage is no longer needed but remains allocated because the program fails to release it.

Q9. Is heap memory automatically released when a function returns?

Answer: No. Dynamically allocated storage remains allocated until it is released using free() or the program terminates.

Q10. Does the C standard require variables to be stored in stack or heap?

Answer: No. The C standard specifies object lifetimes and storage durations, not mandatory physical memory regions named stack and heap.

Q11. Why is dynamic allocation used?

Answer: It allows a program to request storage at runtime when the required size or lifetime is not conveniently determined at compile time.

Q12. Why is stack usage important in embedded systems?

Answer: Embedded systems often have limited RAM. Excessive stack usage can cause corruption or system failure, so stack requirements must be considered carefully.

15. Practical Lab Exercise

Objective

Observe the behavior of global, static local, automatic and dynamically allocated variables.

Complete C11 Program

#include <stdio.h>
#include <stdlib.h>

int global_value = 100;
int zero_initialized;

void demonstrate(void)
{
    int local_value = 10;
    static int static_value = 20;

    static_value++;

    printf("Local value = %d\n", local_value);
    printf("Static value = %d\n", static_value);
}

int main(void)
{
    int *dynamic_value = malloc(sizeof *dynamic_value);

    if (dynamic_value == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    *dynamic_value = 500;

    printf("Global value = %d\n", global_value);
    printf("Zero initialized = %d\n", zero_initialized);
    printf("Dynamic value = %d\n", *dynamic_value);

    demonstrate();
    demonstrate();

    free(dynamic_value);
    dynamic_value = NULL;

    return 0;
}

Compile

gcc -std=c11 -Wall -Wextra -Wpedantic memory.c -o memory

Run

./memory
Expected Output 
Global value = 100
Zero initialized = 0
Dynamic value = 500
Local value = 10
Static value = 21
Local value = 10
Static value = 22

Lab Observations

  1. The global variable retains its value throughout program execution.
  2. The uninitialized global variable is initialized to zero.
  3. The local variable is initialized each time the function executes.
  4. The static local variable retains its value between function calls.
  5. The dynamically allocated object is explicitly released using free().

17. Key Takeaways

  • A typical process has code, data, BSS, heap and stack regions.
  • The text segment commonly contains executable instructions.
  • Initialized data and BSS commonly hold static-storage objects.
  • Automatic local objects commonly use stack storage.
  • Dynamic allocation is managed using malloc(), calloc(), realloc() and free().
  • Static local variables retain their values between function calls.
  • Memory leaks, dangling pointers and invalid accesses must be avoided.
  • Embedded developers must carefully manage limited RAM and stack space.
