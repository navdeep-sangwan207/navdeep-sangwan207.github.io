  • Differentiate constant pointers and pointers to constant data.

2. What Are Type Qualifiers?

Type qualifiers provide additional information about how an object can be accessed or used in a C program.

C11 defines three principal type qualifiers:

Qualifier Purpose
const Prevents modification of an object through a const-qualified access path.
volatile Indicates that an object's value may change in ways unknown to the implementation.
restrict Provides an association-based promise about pointer access to an object during a block execution.
These qualifiers do not create new fundamental data types. They qualify existing types and influence permitted access and compiler optimization.

3. const Qualifier

The const qualifier specifies that an object is not to be modified through an expression using its const-qualified type.

Basic Syntax

const int value = 100;

The variable value cannot be modified through this identifier.

Example 1 – Basic const Variable

#include <stdio.h>

int main(void)
{
    const int MAX_SIZE = 100;

    printf("Maximum size = %d\n", MAX_SIZE);

    return 0;
}
Expected Output 
Maximum size = 100

Attempting to assign another value to MAX_SIZE violates a constraint and requires a diagnostic from a conforming implementation.

Example 2 – const Function Parameter

#include <stdio.h>

void display(const int number)
{
    printf("Number = %d\n", number);

    /* number = 50;  Constraint violation */
}

int main(void)
{
    int value = 25;

    display(value);

    return 0;
}

The function can read number but cannot assign a new value to it through that parameter.

4. const with Pointers

Understanding const placement is a common C interview topic. The position of const determines whether the pointed-to data, the pointer itself, or both are qualified.

4.1 Pointer to const Data

const int *ptr;

The pointer can point to different integer objects, but the pointed-to value cannot be modified through ptr. 

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    const int *ptr = &a;

    printf("%d\n", *ptr);

    ptr = &b;

    printf("%d\n", *ptr);

    return 0;
}
Expected Output 
10
20

The pointer can be reassigned. However, this expression is not permitted: 

*ptr = 50;  /* Constraint violation */

4.2 Constant Pointer

int *const ptr = &value;

The pointer itself cannot be reassigned after initialization. The pointed-to integer can still be modified through ptr. 

#include <stdio.h>

int main(void)
{
    int value = 10;

    int *const ptr = &value;

    *ptr = 50;

    printf("Value = %d\n", value);

    return 0;
}
Expected Output 
Value = 50

4.3 Constant Pointer to const Data

const int *const ptr = &value;

Neither the pointer nor the pointed-to value can be changed through this pointer.

Comparison

Declaration Can Reassign Pointer? Can Modify Data Through Pointer?
const int *ptr Yes No
int *const ptr No Yes
const int *const ptr No No
Memory trick: Read the declaration from the pointer outward. Determine whether const applies to the pointed-to object or to the pointer itself.

5. const with Arrays and Strings

Example – Constant Array

#include <stdio.h>

int main(void)
{
    const int marks[3] = {80, 85, 90};

    for (int i = 0; i < 3; i++)
    {
        printf("%d\n", marks[i]);
    }

    return 0;
}

The elements cannot be modified through this array expression.

String Literal and Character Array

const char *message = "Hello";

char writable_message[] = "Hello";

The first declaration provides a pointer to const-qualified characters. The second creates a modifiable character array.

A string literal must not be modified. Use a writable character array when the program needs to change string contents.

6. volatile Qualifier

The volatile qualifier tells the implementation that an object's value may change in ways unknown to the implementation.

Consequently, accesses to a volatile-qualified object must follow the observable-access requirements of the C abstract machine. The compiler cannot simply treat every access as an ordinary unchanging value.

Syntax

volatile int status;

Example – Volatile Variable

#include <stdio.h>

int main(void)
{
    volatile int status = 0;

    status = 1;

    printf("Status = %d\n", status);

    return 0;
}
Expected Output 
Status = 1

This example demonstrates the syntax. Its importance becomes clearer when the value may change outside the normal flow of program execution.

7. Why Is volatile Important in Embedded Systems?

Embedded systems frequently communicate with hardware through memory-mapped registers. A register may change because of hardware activity rather than an assignment in the C program.

Common examples include:

  • GPIO input registers.
  • UART status registers.
  • Timer interrupt flags.
  • ADC conversion status registers.
  • Peripheral control and status registers.
  • Variables modified by an interrupt service routine in a supported implementation.

Example – Hardware Status Register

#include <stdint.h>

#define UART_STATUS_REG \
    (*(volatile uint32_t *)0x40000000U)

#define UART_TX_READY (1U << 5)

int main(void)
{
    while ((UART_STATUS_REG & UART_TX_READY) == 0U)
    {
        /* Wait until transmitter is ready */
    }

    return 0;
}

The volatile-qualified lvalue tells the compiler that the register must be accessed according to volatile access rules. Its value may change because of hardware activity.

This address is illustrative only. Actual peripheral addresses, register widths, access permissions and bit definitions must come from the target microcontroller reference manual.

Example – Interrupt-Modified Flag

#include <stdbool.h>

volatile bool interrupt_flag = false;

/* Illustrative ISR body */
void timer_interrupt_handler(void)
{
    interrupt_flag = true;
}

int main(void)
{
    while (!interrupt_flag)
    {
        /* Wait for interrupt */
    }

    /* Continue after the flag is observed */

    return 0;
}

In an embedded toolchain, volatile may be needed for a flag shared between ordinary code and an interrupt handler. The exact ISR declaration and interrupt semantics are platform-specific.

8. What volatile Does NOT Guarantee

This is one of the most important interview topics. volatile is not a universal synchronization mechanism.

Property Guaranteed by volatile?
Prevents the compiler from treating a volatile access as an ordinary removable access Yes, subject to the C volatile access rules.
Guarantees atomic operations No.
Provides thread synchronization No.
Prevents all CPU or hardware reordering No.
Protects shared data from race conditions No.
In multithreaded C11 programs, conflicting non-atomic accesses without proper synchronization can cause a data race and undefined behavior. Use C11 atomic operations or suitable synchronization mechanisms instead of relying on volatile.

9. volatile and const Together

Both qualifiers can be applied to the same object. 

const volatile int *status_register;

This declaration means that the pointer refers to an object that must not be modified through this access path and whose value may change outside the program's normal control.

Typical Embedded Use

#include <stdint.h>

#define UART_STATUS \
    (*(const volatile uint32_t *)0x40000000U)

int main(void)
{
    uint32_t status;

    status = UART_STATUS;

    return (int)status;
}

A status register is often read-only from the software's perspective but may change as hardware operates.

const protects against modification through the C expression. volatile describes the access behavior. Neither qualifier alone establishes the hardware's access permissions.

10. restrict Qualifier

restrict is a pointer type qualifier introduced in C99. It provides the compiler with information about how an object is accessed through a pointer during a particular block execution.

When a pointer is used as a restricted pointer in accordance with the language rules, the programmer promises that the relevant object accesses will follow the required association. Violating that promise can produce undefined behavior.

Syntax

int *restrict ptr;

Example – Array Addition

#include <stdio.h>

void add_arrays(
    size_t n,
    const int *restrict a,
    const int *restrict b,
    int *restrict result)
{
    for (size_t i = 0; i < n; i++)
    {
        result[i] = a[i] + b[i];
    }
}

int main(void)
{
    int a[3] = {1, 2, 3};
    int b[3] = {4, 5, 6};
    int result[3];

    add_arrays(3, a, b, result);

    for (size_t i = 0; i < 3; i++)
    {
        printf("%d ", result[i]);
    }

    printf("\n");

    return 0;
}
Expected Output 
5 7 9

The arrays are separate objects, so the function's restricted pointer assumptions are respected in this example.

Why Use restrict?

  • It communicates non-aliasing access assumptions to the compiler.
  • It can enable better optimization in suitable code.
  • It is useful in numerical routines and array-processing functions.
  • It places a responsibility on the programmer to satisfy its requirements.

11. Understanding Pointer Aliasing

Aliasing occurs when multiple pointers can refer to the same object.

Example – Aliasing

#include <stdio.h>

int main(void)
{
    int value = 10;

    int *p1 = &value;
    int *p2 = &value;

    *p1 = 20;

    printf("%d\n", *p2);

    return 0;
}
Expected Output 
20

Both pointers refer to the same object. Modifying the object through p1 is visible when it is read through p2.

restrict is not a general instruction to make pointers different. It is a language-level promise about accesses to objects during a block execution. The promise must be respected throughout the relevant execution.

13. C11 Atomics and volatile

C11 introduced the standard atomic facilities through the header stdatomic.h.

Atomic objects and operations can be used to coordinate access between threads when the program follows the C11 memory model.

Example – Atomic Counter

#include <stdio.h>
#include <stdatomic.h>

int main(void)
{
    atomic_int counter = ATOMIC_VAR_INIT(0);

    atomic_fetch_add(&counter, 1);
    atomic_fetch_add(&counter, 1);

    printf("Counter = %d\n",
           atomic_load(&counter));

    return 0;
}
Expected Output 
Counter = 2

This example uses C11 atomic operations rather than volatile for an atomic counter.

Atomic operations are not necessarily lock-free on every implementation. Check the target implementation's atomic support when working with embedded systems.

14. Placement-Oriented Interview Questions

Q1. What is const in C?

Answer: const is a type qualifier that prevents modification of an object through a const-qualified access path.

Q2. Differentiate const int *p and int *const p.

Answer: const int *p is a pointer to const-qualified data. int *const p is a constant pointer to modifiable integer data.

Q3. What is volatile?

Answer: volatile indicates that an object's value may change in ways unknown to the implementation.

Q4. Why is volatile used in embedded C?

Answer: It is commonly used for memory-mapped hardware registers and objects that may be modified by interrupt or other external activity.

Q5. Does volatile guarantee atomicity?

Answer: No. volatile does not guarantee atomic operations.

Q6. Does volatile make a variable thread-safe?

Answer: No. Use atomic operations or synchronization mechanisms for thread communication.

Q7. What is restrict?

Answer: It is a C99 pointer type qualifier that provides an access relationship promise, allowing optimizations when the promise is respected.

Q8. What is pointer aliasing?

Answer: Aliasing occurs when multiple pointers can refer to the same object.

Q9. Can const and volatile be used together?

Answer: Yes. A read-only hardware status register that changes due to hardware activity is a common example.

Q10. Which qualifier is especially important for memory-mapped registers?

Answer: volatile. const may also be used when the register must not be modified by software through that access path.

15. Practical Lab Exercise

Objective

Demonstrate const-qualified pointers, volatile variables, and restrict-qualified function parameters in a single C11-compatible program.

Complete C11 Program

#include <stdio.h>
#include <stddef.h>

void add_arrays(
    size_t n,
    const int *restrict a,
    const int *restrict b,
    int *restrict result)
{
    for (size_t i = 0; i < n; i++)
    {
        result[i] = a[i] + b[i];
    }
}

int main(void)
{
    const int maximum = 100;

    int value = 10;

    const int *read_only_ptr = &value;

    int *const fixed_ptr = &value;

    volatile int status = 0;

    int a[3] = {10, 20, 30};
    int b[3] = {1, 2, 3};
    int result[3];

    printf("Maximum = %d\n", maximum);

    printf("Read-only pointer = %d\n", *read_only_ptr);

    *fixed_ptr = 50;

    printf("Modified value = %d\n", value);

    status = 1;

    printf("Status = %d\n", status);

    add_arrays(3, a, b, result);

    printf("Array result: ");

    for (size_t i = 0; i < 3; i++)
    {
        printf("%d ", result[i]);
    }

    printf("\n");

    return 0;
}

Compile

gcc -std=c11 -Wall -Wextra -Wpedantic qualifiers.c -o qualifiers

Run

./qualifiers
Expected Output 
Maximum = 100
Read-only pointer = 10
Modified value = 50
Status = 1
Array result: 11 22 33

Lab Observations

  1. const prevents modification through the qualified pointer.
  2. A constant pointer cannot be reassigned after initialization.
  3. volatile demonstrates a qualified object access.
  4. restrict communicates the required pointer-access relationship to the compiler.

17. Key Takeaways

  • const restricts modification through a qualified access path.
  • volatile describes objects whose values may change outside the implementation's ordinary expectations.
  • restrict provides a pointer-access relationship promise that can enable optimization.
  • const int * and int *const have different meanings.
  • volatile is especially relevant to embedded hardware registers.
  • volatile does not guarantee atomicity or thread synchronization.
  • C11 atomic operations are the standard approach for atomic inter-thread operations.
  • These qualifiers are important for embedded C, systems programming and technical interviews.
