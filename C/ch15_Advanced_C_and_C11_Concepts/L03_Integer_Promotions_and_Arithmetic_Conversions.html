Lecture 03: Integer Promotions and Arithmetic Conversions

Chapter 15 – Advanced C and C11 Concepts

Understand how C converts integer types during expression evaluation.

1. Learning Objectives

  • Understand integer promotions in C.
  • Explain the integer conversion rank.
  • Understand the usual arithmetic conversions.

2. Why Are Integer Conversions Important?

C supports several integer types, including char, short, int, long and long long, with signed and unsigned variants.

When an expression contains different integer types, C applies conversion rules before performing many arithmetic operations.

Consider:

#include <stdio.h>

int main(void)
{
    unsigned int a = 10;
    int b = -5;

    if (a + b > 0)
    {
        printf("Positive\n");
    }
    else
    {
        printf("Not positive\n");
    }

    return 0;
}

The result may surprise beginners because the signed operand can be converted to an unsigned type before the addition.

Integer conversion rules are essential for writing portable C programs, especially when working with registers, counters, array sizes, bit manipulation and protocol fields.

3. Integer Types in C

The standard integer types include:

Type Typical Use
char Character-sized integer type.
signed char Small signed integer.
unsigned char Small unsigned integer.
short Short integer.
int General-purpose integer.
long Long integer.
long long At least 64-bit integer range.

C specifies minimum ranges and ordering requirements, but the exact widths of many integer types depend on the implementation.

Check Sizes Using sizeof

#include <stdio.h>

int main(void)
{
    printf("char = %zu bytes\n", sizeof(char));
    printf("short = %zu bytes\n", sizeof(short));
    printf("int = %zu bytes\n", sizeof(int));
    printf("long = %zu bytes\n", sizeof(long));
    printf("long long = %zu bytes\n", sizeof(long long));

    return 0;
}
Example Output on a Common System 
char = 1 bytes
short = 2 bytes
int = 4 bytes
long = 8 bytes
long long = 8 bytes

Actual sizes may differ on other systems. The example is not a universal output.

4. Integer Conversion Rank

Integer conversion rank is used to determine which integer type takes precedence during integer promotions and the usual arithmetic conversions.

For the standard signed integer types, the rank increases in this order: 

signed char
     |
     v
short
     |
     v
int
     |
     v
long
     |
     v
long long

The corresponding unsigned types have the same rank as their corresponding signed types.

Rank is not simply the number of bytes. It is a language-defined ordering used by conversion rules.

5. Integer Promotions

Integer promotion converts certain integer types with rank lower than int into int or unsigned int before many arithmetic operations.

Integer promotions apply to types such as:

  • _Bool
  • char
  • signed char
  • unsigned char
  • short
  • unsigned short
  • certain enumeration types

How Does Promotion Work?

  1. If int can represent all values of the original type, the value is promoted to int.
  2. Otherwise, it is promoted to unsigned int.

Example 1 – Character Promotion

#include <stdio.h>

int main(void)
{
    char a = 10;
    char b = 20;

    int result = a + b;

    printf("Result = %d\n", result);

    return 0;
}
Expected Output 
Result = 30

On an implementation where int can represent all values of char, both operands are promoted to int before addition.

Example 2 – Short Integer Promotion

#include <stdio.h>

int main(void)
{
    short a = 100;
    short b = 200;

    printf("%zu\n", sizeof(a + b));

    return 0;
}

Assuming the implementation has an int type that can represent every short value, the expression a + b has type int.

Typical Output 
4

The exact size of int is implementation-dependent.

6. Integer Promotion with unsigned char

An unsigned char usually promotes to int because int can represent every value of unsigned char on common systems. 

#include <stdio.h>

int main(void)
{
    unsigned char a = 250;
    unsigned char b = 10;

    int result = a + b;

    printf("Result = %d\n", result);

    return 0;
}
Expected Output 
Result = 260

The addition is performed using promoted int operands. The result is not restricted to the range of unsigned char because the expression itself has type int.

7. Usual Arithmetic Conversions

When arithmetic operators combine operands of different arithmetic types, C applies the usual arithmetic conversions to determine a common type.

For integer operands, integer promotions are performed first. The remaining conversion rules then determine the common type.

General Integer Conversion Rules

  1. Perform integer promotions on both operands.
  2. If the promoted types are identical, no further conversion is required.
  3. If both have the same signedness, convert the lower-rank operand to the higher-rank type.
  4. If signedness differs, apply the signed and unsigned conversion rules.
The full rules also account for whether the signed type can represent all values of the unsigned type. The next sections explain the important cases.

8. Same Signedness Conversion

If both operands have the same signedness, the operand with lower integer conversion rank is converted to the type with higher rank.

Example

#include <stdio.h>

int main(void)
{
    int a = 100;
    long b = 200L;

    printf("%ld\n", a + b);

    return 0;
}
Expected Output 
300

The int operand is converted to long before addition. The resulting expression has type long.

9. Signed and Unsigned Integer Conversions

This is one of the most important topics in C interview questions.

When signed and unsigned integer operands are combined, the following general rules apply after integer promotions.

  1. If both operands have the same type, no conversion is needed.
  2. If both have the same signedness, convert to the higher-rank type.
  3. If the unsigned type has rank greater than or equal to the signed type, convert the signed operand to the unsigned type.
  4. If the signed type has higher rank and can represent every value of the unsigned type, convert the unsigned operand to the signed type.
  5. Otherwise, convert both operands to the unsigned type corresponding to the signed operand.

Example 1 – int and unsigned int

#include <stdio.h>

int main(void)
{
    int a = -5;
    unsigned int b = 10;

    if (a < b)
    {
        printf("A is smaller\n");
    }
    else
    {
        printf("B is smaller or equal\n");
    }

    return 0;
}
Typical Output 
B is smaller or equal

The int value -5 is converted to unsigned int. For an unsigned type, conversion is performed modulo one more than its maximum value. The converted value is therefore a large unsigned value on common implementations.

Example 2 – Unsigned Arithmetic

#include <stdio.h>

int main(void)
{
    unsigned int a = 5;
    unsigned int b = 10;

    printf("%u\n", a - b);

    return 0;
}

Unsigned arithmetic wraps modulo one more than the maximum representable value of the unsigned type.

Typical Output for 32-bit unsigned int 
4294967291

The exact value depends on the width of unsigned int.

Signed integer overflow is undefined behavior. Unsigned integer arithmetic, in contrast, is defined modulo the type's range.

10. Integer Conversion and Assignment

Assignment converts the right-hand value to the type of the left-hand object.

Example 1 – Narrowing Conversion

#include <stdio.h>

int main(void)
{
    int value = 300;
    unsigned char result = value;

    printf("%u\n", (unsigned int)result);

    return 0;
}

If unsigned char has a maximum value of 255, conversion is performed modulo 256.

Typical Output 
44

Example 2 – Floating-Point to Integer

#include <stdio.h>

int main(void)
{
    double value = 12.75;
    int result = (int)value;

    printf("%d\n", result);

    return 0;
}
Expected Output 
12

Conversion from floating-point to integer discards the fractional part by truncating toward zero, provided the resulting integer value is representable.

If the integral part of a floating-point value cannot be represented by the destination integer type, the behavior is undefined in C.

11. Integer Promotions in Bitwise Expressions

Integer promotions also apply to operands of bitwise operators. This is particularly important when working with char and short values in embedded C.

Example

#include <stdio.h>

int main(void)
{
    unsigned char value = 0x0F;

    int result = ~value;

    printf("%d\n", result);

    return 0;
}

On a common implementation where unsigned char promotes to 32-bit int, the bitwise complement is performed on the promoted int value.

Typical Output 
-16
The exact result depends on the implementation's integer representation and widths. For predictable hardware-register operations, use appropriately sized unsigned integer types and explicit masks.

12. Integer Overflow

Integer overflow behavior depends on whether the type is signed or unsigned.

Unsigned Integer Overflow

#include <stdio.h>
#include <limits.h>

int main(void)
{
    unsigned int value = UINT_MAX;

    value = value + 1U;

    printf("%u\n", value);

    return 0;
}
Expected Output 
0

Unsigned arithmetic wraps modulo UINT_MAX + 1.

Signed Integer Overflow

#include <stdio.h>
#include <limits.h>

int main(void)
{
    int value = INT_MAX;

    value = value + 1;

    printf("%d\n", value);

    return 0;
}
Undefined behavior: The signed addition overflows int. Do not expect a particular output or wraparound.

13. Common Integer Conversion Mistakes

Mistake Why It Is Problematic
Mixing signed and unsigned values carelessly Can cause unexpected unsigned conversions.
Assuming char is always signed Plain char signedness is implementation-defined.
Assuming short arithmetic stays short Integer promotions often convert operands to int.
Ignoring narrowing conversions Values may change when assigned to smaller types.
Expecting signed overflow to wrap Signed overflow is undefined behavior.
Ignoring format specifiers Incorrect printf argument types can cause undefined behavior.

14. Embedded C Applications

Integer conversions are particularly important in embedded systems because hardware registers and communication protocols frequently use fixed-width integer values.

Example – Register Mask

#include <stdint.h>
#include <stdio.h>

int main(void)
{
    uint8_t register_value = 0x0F;

    register_value = (uint8_t)(register_value | 0x80U);

    printf("Register = 0x%02X\n",
           (unsigned int)register_value);

    return 0;
}
Expected Output 
Register = 0x8F

The uint8_t value is promoted for the bitwise operation. The explicit cast converts the result back to uint8_t. The printf argument is explicitly converted to unsigned int to match the %X conversion specification.

Important Embedded Programming Practices

  • Use uint8_t, uint16_t and uint32_t when exact-width types are available and required.
  • Use unsigned types for bit masks and register manipulation.
  • Check narrowing conversions.
  • Use explicit casts where they clarify intended conversions.
  • Do not assume that a cast makes an otherwise invalid operation safe.

15. Placement-Oriented Interview Questions

Q1. What is integer promotion?

Answer: It is the conversion of certain integer types of lower rank than int to int or unsigned int before many arithmetic operations.

Q2. Why does char arithmetic often produce an int result?

Answer: Because char operands are generally promoted to int when int can represent all their values.

Q3. What are the usual arithmetic conversions?

Answer: They are the rules used to convert arithmetic operands to a common type before an operation.

Q4. What happens when signed int and unsigned int are added?

Answer: The signed operand is converted to unsigned int, and the addition is performed using unsigned arithmetic.

Q5. Is unsigned integer overflow undefined behavior?

Answer: No. Unsigned arithmetic is defined modulo one more than the maximum value of the type.

Q6. Is signed integer overflow defined in C?

Answer: No. Signed integer overflow results in undefined behavior.

Q7. What is integer conversion rank?

Answer: It is the language-defined ordering used to determine precedence among integer types during conversions.

Q8. What happens when double is assigned to int?

Answer: The fractional part is discarded by truncation toward zero, provided the integral result is representable.

Q9. Why should signed and unsigned comparisons be handled carefully?

Answer: The signed operand may be converted to unsigned, producing a comparison result that differs from the programmer's expectation.

Q10. Why are fixed-width integer types useful in embedded C?

Answer: They provide specified widths when available, making register fields, protocol data and bit manipulation easier to express precisely.

17. Practical Lab Exercise

Objective

Observe integer promotions, unsigned arithmetic and explicit conversions in a C11 program.

Complete C11 Program

#include <stdio.h>
#include <stdint.h>
#include <limits.h>

int main(void)
{
    unsigned char a = 250;
    unsigned char b = 10;

    int promoted_result = a + b;

    unsigned int x = 5U;
    unsigned int y = 10U;

    unsigned int unsigned_result = x - y;

    double decimal_value = 15.75;
    int integer_value = (int)decimal_value;

    printf("Promoted result = %d\n", promoted_result);
    printf("Unsigned result = %u\n", unsigned_result);
    printf("Converted integer = %d\n", integer_value);

    printf("UINT_MAX = %u\n", UINT_MAX);

    return 0;
}

Compile

gcc -std=c11 -Wall -Wextra -Wpedantic conversion.c -o conversion

Run

./conversion
Expected Output on a Typical 32-bit unsigned int System 
Promoted result = 260
Unsigned result = 4294967291
Converted integer = 15
UINT_MAX = 4294967295

Lab Observations

  1. unsigned char operands are promoted before addition.
  2. Unsigned subtraction wraps around.
  3. Floating-point to integer conversion truncates toward zero.
  4. UINT_MAX gives the maximum value of unsigned int on the implementation.

19. Key Takeaways

  • Integer promotions convert many small integer operands to int or unsigned int.
  • Usual arithmetic conversions establish a common operand type.
  • Signed and unsigned conversions can change comparison results.
  • Unsigned arithmetic wraps modulo its range.
  • Signed integer overflow is undefined behavior.
  • Floating-point to integer conversion truncates toward zero when representable.
  • Fixed-width integer types are useful for embedded and low-level programming.
  • Always check conversion rules when predicting C expression results.
