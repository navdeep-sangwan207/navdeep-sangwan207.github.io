Chapter 15 – Advanced C and C11 Concepts

Memory layout, padding, alignment, strict aliasing and C object access rules.

1. Learning Objectives

  • Understand memory alignment in C.

  • Calculate structure size for common member arrangements.
  • Use sizeof and offsetof to inspect structure layout.
  • Understand alignment requirements and the _Alignof operator.

  • Apply these concepts to embedded systems and interview problems.

2. What Is Memory Alignment?

Memory alignment refers to placing an object at a memory address that satisfies the alignment requirement of its type.

Different data types may have different alignment requirements depending on the C implementation and target processor.

Illustrative Example

Suppose an implementation uses the following properties:

Data Type Size Alignment
char 1 byte 1 byte
short 2 bytes 2 bytes
int 4 bytes 4 bytes
double 8 bytes 8 bytes
These values are illustrative, not universal C requirements. Actual size and alignment are implementation-dependent.

Why Is Alignment Important?

  • Some processors require particular alignment for certain memory accesses.
  • Aligned accesses may be more efficient on many architectures.
  • Compilers arrange structure members according to alignment requirements.
  • Incorrect assumptions about alignment can cause portability problems.

3. What Is Structure Padding?

Structure padding refers to unused bytes inserted by the compiler between structure members or at the end of a structure to satisfy alignment requirements.

Example 1 – Structure Without Expected Padding

#include <stdio.h>

struct Data
{
    int a;
    int b;
};

int main(void)
{
    printf("Structure size = %zu\n", sizeof(struct Data));

    return 0;
}

On an implementation where int occupies four bytes and requires four-byte alignment, the structure commonly occupies eight bytes.

Example 2 – Structure With Internal Padding

#include <stdio.h>

struct Example
{
    char a;
    int b;
};

int main(void)
{
    printf("Structure size = %zu\n", sizeof(struct Example));

    return 0;
}

Suppose char occupies one byte and int occupies four bytes, with four-byte alignment.

Illustrative memory layout:

Byte Offset Content
0 Member a
1 Padding
2 Padding
3 Padding
4–7 Member b
Typical Output on the Assumed Implementation 
Structure size = 8

Three padding bytes are inserted so that b begins at an address satisfying its alignment requirement.

4. Internal Padding and Trailing Padding

Structure padding can appear in two important places.

4.1 Internal Padding

Internal padding is inserted between structure members when necessary to align the next member. 

struct Sample
{
    char a;
    int b;
};

4.2 Trailing Padding

Trailing padding is inserted after the last member so that the structure's size is compatible with its alignment requirement. This is important when structures are stored in arrays. 

struct Sample
{
    int a;
    char b;
};

On a typical implementation with four-byte int alignment, the structure may occupy eight bytes rather than five.

The size of a structure includes any padding. The C standard does not prescribe one universal byte layout for every structure on every implementation.

5. Structure Member Ordering and Memory Optimization

Rearranging structure members can reduce padding on some implementations.

Example 1 – Less Efficient Ordering

struct A
{
    char a;
    double b;
    int c;
    char d;
};

Example 2 – Alternative Ordering

struct B
{
    double b;
    int c;
    char a;
    char d;
};

Suppose double requires eight-byte alignment, int requires four-byte alignment, and char requires one-byte alignment.

The second arrangement may require less padding on this implementation.

Do not assume that reordering members always produces a particular size. Measure the result on the target compiler and platform.

Practical Rule

When memory usage matters, consider grouping members with larger alignment requirements before smaller members. Preserve the required data layout when interfacing with hardware, protocols, files or external binary formats.

6. Using sizeof to Inspect Structure Size

The sizeof operator returns the size of an object or type in C bytes. 

#include <stdio.h>

struct Employee
{
    char id;
    int salary;
    char grade;
};

int main(void)
{
    printf("char size = %zu\n", sizeof(char));
    printf("int size = %zu\n", sizeof(int));
    printf("Employee size = %zu\n", sizeof(struct Employee));

    return 0;
}

The actual structure size depends on the implementation's member sizes and alignment rules.

sizeof returns size_t. Use %zu in printf to display a size_t value.

7. Using offsetof() to Find Member Offsets

The offsetof macro is defined in the standard header stddef.h. It returns the byte offset of a structure member from the beginning of its structure.

Syntax

offsetof(structure_type, member_name)

Example

#include <stdio.h>
#include <stddef.h>

struct Data
{
    char a;
    int b;
    char c;
};

int main(void)
{
    printf("Offset of a = %zu\n",
           offsetof(struct Data, a));

    printf("Offset of b = %zu\n",
           offsetof(struct Data, b));

    printf("Offset of c = %zu\n",
           offsetof(struct Data, c));

    printf("Total size = %zu\n",
           sizeof(struct Data));

    return 0;
}

On a common implementation with four-byte int alignment, the offsets may be:

Illustrative Output 
Offset of a = 0
Offset of b = 4
Offset of c = 8
Total size = 12

offsetof is useful for inspecting structure layout and implementing container-style data structures.

8. Alignment in C11 – _Alignof

C11 introduced the _Alignof operator to determine the alignment requirement of a complete object type.

Syntax

_Alignof(type_name)

Example

#include <stdio.h>
#include <stdalign.h>

struct Example
{
    char a;
    int b;
    double c;
};

int main(void)
{
    printf("Alignment of char = %zu\n",
           _Alignof(char));

    printf("Alignment of int = %zu\n",
           _Alignof(int));

    printf("Alignment of double = %zu\n",
           _Alignof(double));

    printf("Alignment of Example = %zu\n",
           _Alignof(struct Example));

    return 0;
}

The output depends on the target implementation.

C11 also provides _Alignas for specifying an alignment requirement for an object or member declaration, subject to the standard's restrictions.

Example – Explicit Alignment

#include <stdio.h>
#include <stdalign.h>

_Alignas(16) int buffer[4];

int main(void)
{
    printf("Alignment = %zu\n",
           _Alignof(int));

    printf("Buffer address = %p\n",
           (void *)buffer);

    return 0;
}

_Alignas(16) requests at least the specified alignment for buffer, provided the requested alignment is valid and supported by the implementation.

9. Structure Alignment and Arrays

An array stores its elements consecutively. The distance between the beginning of adjacent elements is sizeof the element type. 

#include <stdio.h>

struct Item
{
    char code;
    int value;
};

int main(void)
{
    struct Item items[3];

    printf("Item size = %zu\n", sizeof(struct Item));

    printf("Array size = %zu\n", sizeof(items));

    return 0;
}

If sizeof(struct Item) is 8 on the target, the three-element array occupies 24 C bytes.

Padding in each structure element is part of sizeof the structure. This ensures that each array element begins at an address compatible with the structure's alignment.

10. Effective Type in C

Effective type is an important C object-access concept. It determines which types may be used to access the stored value of an object through an lvalue.

For an object with a declared type, its effective type is its declared type.

Dynamically allocated storage has no declared type. Its effective type is determined according to the C standard's rules for accessing and storing values.

Example 1 – Declared Object

int value = 100;

The declared type of value is int. Access it using an appropriate int lvalue.

Example 2 – Dynamically Allocated Storage

#include <stdlib.h>

int main(void)
{
    int *ptr = malloc(sizeof *ptr);

    if (ptr == NULL)
    {
        return 1;
    }

    *ptr = 100;

    free(ptr);

    return 0;
}

The allocated storage has no declared type. Storing through the int lvalue establishes the effective type for that access and subsequent accesses governed by the applicable effective-type rules.

11. Strict Aliasing Rule

The strict aliasing rules are part of C's object-access requirements. They limit the types of lvalues that may be used to access an object's stored value.

This helps the compiler optimize code because it can make assumptions about which pointers may refer to the same object.

Permitted Access Categories

Under the C11 effective-type rules, an object's stored value can generally be accessed through an lvalue of:

  • A type compatible with the effective type of the object.
  • A qualified version of a compatible type.
  • The corresponding signed or unsigned type.
  • A type compatible with the signed or unsigned type corresponding to the effective type.
  • An aggregate or union type that includes one of the permitted types among its members.
  • A character type.
Access through a character type is permitted for examining an object's object representation. This is an important exception to remember.

12. Unsafe Type Punning

Type punning means interpreting an object's stored representation through a different type.

Some techniques are permitted by C, while others violate effective-type or alignment requirements.

Example – Unsafe Pointer Cast

#include <stdio.h>

int main(void)
{
    float value = 3.14f;

    int *ptr = (int *)&value;

    printf("%d\n", *ptr);

    return 0;
}
This is not a portable way to inspect a float's representation. Accessing a float object through an incompatible int lvalue violates the effective-type access rules. Alignment can also be an issue in other cast-based examples.

Safer Approach – memcpy()

#include <stdio.h>
#include <stdint.h>
#include <string.h>

int main(void)
{
    float value = 3.14f;
    unsigned char representation[sizeof value];

    memcpy(representation, &value, sizeof value);

    printf("Object representation bytes: ");

    for (size_t i = 0; i < sizeof value; i++)
    {
        printf("%02X ", (unsigned int)representation[i]);
    }

    printf("\n");

    return 0;
}

memcpy copies the object representation into a character array. This avoids accessing the float through an incompatible int lvalue.

The displayed bytes depend on the implementation's floating-point representation, byte order and object representation. Do not assume a universal byte sequence.

13. Union-Based Type Punning

C permits access to a different member of a union than the member most recently used for storing a value. The resulting representation is interpreted according to the relevant union and object representation rules.

This technique can be implementation-dependent, particularly when the resulting representation does not represent a valid value of the member type.

Example

#include <stdio.h>

union Data
{
    unsigned int integer;
    unsigned char bytes[sizeof(unsigned int)];
};

int main(void)
{
    union Data data = {0};

    data.integer = 0x12345678U;

    printf("Integer = %X\n", data.integer);

    printf("Bytes: ");

    for (size_t i = 0; i < sizeof data.bytes; i++)
    {
        printf("%02X ", (unsigned int)data.bytes[i]);
    }

    printf("\n");

    return 0;
}

The byte sequence depends on the implementation's byte order and the representation of unsigned int.

When the goal is simply to inspect bytes, copying the object representation into an unsigned char array with memcpy() is often a clearer and more portable technique.

14. Packed Structures and Embedded Systems

Embedded applications sometimes need precise data layouts, especially when communicating with hardware or external binary protocols.

Some compilers provide non-standard packed-structure extensions to reduce or eliminate padding.

Illustrative GCC/Clang Extension

struct __attribute__((packed)) Packet
{
    unsigned char type;
    unsigned int length;
    unsigned char flags;
};
__attribute__((packed)) is not standard C11. Its behavior and syntax are compiler-specific.

Potential Problems

  • Unaligned member accesses may be slower.
  • Some processors cannot directly perform certain unaligned accesses.
  • Compiler-generated code may require special handling.
  • Directly mapping external data to structures can create portability issues.

For external packet formats, explicitly serialize and deserialize fields where portability is important.

15. Placement-Oriented Interview Questions

Q1. What is memory alignment?

Answer: Alignment is the requirement that an object's address satisfy the alignment requirement of its type.

Q2. What is structure padding?

Answer: Padding is unused storage inserted between structure members or at the end of a structure to satisfy alignment requirements.

Q3. What is internal padding?

Answer: It is padding inserted between structure members.

Q4. What is trailing padding?

Answer: It is padding inserted at the end of a structure to satisfy its alignment requirements.

Q5. Why can changing structure member order change sizeof?

Answer: Different member arrangements can create different internal and trailing padding requirements.

Q6. What is offsetof()?

Answer: It is a standard macro from stddef.h that determines a structure member's offset.

Q7. What is _Alignof?

Answer: It is a C11 operator that determines the alignment requirement of a type.

Q8. What is effective type?

Answer: It is the type that governs how an object's stored value may be accessed under C's effective-type rules.

Q9. What is strict aliasing?

Answer: It refers to C's restrictions on accessing an object's stored value through incompatible lvalue types.

Q10. How can an object's bytes be inspected safely?

Answer: Use a character-type pointer or copy the object representation into an unsigned char array using memcpy().

Q11. Why are packed structures used?

Answer: They are used in some compiler-specific environments to control padding, often for binary data layouts and hardware interfaces.

Q12. Is structure padding fixed by the C standard?

Answer: No. The exact layout and padding are implementation-dependent, subject to the standard's requirements.

16. Practical Lab Exercise

Objective

Inspect structure size, member offsets, alignment requirements and object representations using standard C11 facilities.

Complete C11 Program

#include <stdio.h>
#include <stddef.h>
#include <stdalign.h>
#include <string.h>

struct Employee
{
    char id;
    int salary;
    char grade;
};

int main(void)
{
    struct Employee emp = {'A', 50000, 'B'};

    unsigned char bytes[sizeof emp];

    printf("Structure size = %zu\n",
           sizeof(struct Employee));

    printf("Structure alignment = %zu\n",
           _Alignof(struct Employee));

    printf("Offset of id = %zu\n",
           offsetof(struct Employee, id));

    printf("Offset of salary = %zu\n",
           offsetof(struct Employee, salary));

    printf("Offset of grade = %zu\n",
           offsetof(struct Employee, grade));

    memcpy(bytes, &emp, sizeof emp);

    printf("Object representation: ");

    for (size_t i = 0; i < sizeof emp; i++)
    {
        printf("%02X ", (unsigned int)bytes[i]);
    }

    printf("\n");

    return 0;
}

Compile

gcc -std=c11 -Wall -Wextra -Wpedantic structure.c -o structure

Run

./structure

The exact size, alignment, offsets and bytes depend on the implementation. Compare your output with the target compiler's documentation and inspect the results.

Lab Observations

  1. sizeof reports the complete structure size, including padding.
  2. offsetof reports the offset of a member.
  3. _Alignof reports the alignment requirement.
  4. memcpy copies the complete object representation without incompatible pointer access.
  5. Padding bytes should not be treated as meaningful application data.

18. Key Takeaways

  • Memory alignment ensures that objects satisfy their type's alignment requirements.
  • Structure padding can occur between members and at the end.
  • Structure size is not necessarily the sum of member sizes.
  • Member ordering can influence padding and memory consumption.
  • offsetof() identifies member offsets.
  • C11 provides _Alignof and _Alignas.
  • Effective type rules govern permitted access to stored values.
  • Strict aliasing allows compilers to make important optimization assumptions.
  • Use memcpy() when copying or examining object representations across different types.
  • Packed structures are compiler-specific extensions and require care in embedded applications.
