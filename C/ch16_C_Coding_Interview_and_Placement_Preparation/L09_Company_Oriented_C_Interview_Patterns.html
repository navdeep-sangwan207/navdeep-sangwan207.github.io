After completing this lecture, you should be able to:

2. How Companies Assess C Programming Skills

Companies recruiting freshers for software, embedded and systems roles commonly assess a combination of programming fundamentals, problem-solving ability and practical debugging skills. The exact process varies by employer and job description.

3. Common Recruitment Categories and Preparation Strategy

3.1 IT services and software fresher roles

For entry-level software development and programming roles, prepare for:

  • C fundamentals and output prediction.
  • Loops, functions, recursion and arrays.
  • String manipulation and searching.
  • Basic sorting and searching algorithms.
  • Pointer fundamentals and dynamic memory allocation.
  • Problem-solving and coding assessments.

3.2 Product and engineering companies

For engineering-focused software roles, prepare for deeper problem-solving and implementation questions:

  • Array and string algorithms.
  • Pointer manipulation and memory safety.
  • Data structures and algorithmic complexity.
  • Bit manipulation.
  • Debugging and edge-case analysis.
  • Operating system and computer architecture fundamentals where relevant.

3.3 Embedded and electronics companies

For embedded firmware and electronics R&D roles, C knowledge is often assessed alongside hardware-oriented concepts.

  • Embedded C and bitwise operations.
  • Memory-mapped registers and volatile.
  • Interrupts and interrupt service routines.
  • Timers, counters and peripheral programming.
  • UART, SPI, I2C and CAN fundamentals.
  • Microcontroller architecture and memory organization.
  • Debugging with development tools and hardware interfaces.

Pattern 2: Operator precedence

#include <stdio.h>

int main(void)
{

11

Multiplication is performed before addition because it has higher precedence.

Pattern 3: Short-circuit evaluation

#include <stdio.h>

int main(void)
{
    int a = 0;
    int b = 5;

    if (a && ++b)
        printf("True\n");

    printf("%d\n", b);

    return 0;
}
5

The second operand of logical AND is not evaluated because the first operand is false.

Pattern 4: Array traversal

#include <stdio.h>

int main(void)
{
    int arr[] = {4, 8, 12, 16, 20};
    int sum = 0;

    for (int i = 0; i < 5; i++)
        sum += arr[i];

    printf("%d\n", sum);

    return 0;
}
60

Pattern 5: Pointer dereferencing

#include <stdio.h>

int main(void)
{
    int x = 25;
    int *p = &x;

    *p = 75;

    printf("%d\n", x);

    return 0;
}
75

Dereferencing p accesses the object x.

Pattern 6: Function argument passing

#include <stdio.h>

void change(int x)
{
    x = 100;
}

int main(void)
{
    int a = 20;

    change(a);

    printf("%d\n", a);

    return 0;
}
20

The function receives a copy of the integer. Changing the parameter does not change the caller's object.

5. Common Coding-Round Problems

Problem 1: Reverse an integer

Problem: Reverse the digits of a signed integer. Handle negative values and detect overflow.

#include <stdio.h>
#include <limits.h>

int reverse_integer(int n, int *result)
{
    int reversed = 0;

    while (n != 0)
    {
        int digit = n % 10;
        n /= 10;

        if (reversed > INT_MAX / 10 ||
            (reversed == INT_MAX / 10 && digit > 7))
            return 0;

        if (reversed < INT_MIN / 10 ||
            (reversed == INT_MIN / 10 && digit < -8))
            return 0;

        reversed = reversed * 10 + digit;
    }

    *result = reversed;
    return 1;
}

int main(void)
{
    int result;

    if (reverse_integer(-1234, &result))
        printf("%d\n", result);
    else
        printf("Overflow\n");

    return 0;
}
-4321

Complexity: O(d) time, where d is the number of digits; O(1) auxiliary space.

Problem 2: Find the second-largest distinct element

#include <stdio.h>
#include <stdbool.h>
#include <limits.h>

int second_largest(const int arr[], size_t n, int *answer)
{
    int largest = 0;
    int second = 0;
    bool has_largest = false;
    bool has_second = false;

    for (size_t i = 0; i < n; i++)
    {
        int value = arr[i];

        if (!has_largest || value > largest)
        {
            if (has_largest)
            {
                second = largest;
                has_second = true;
            }

            largest = value;
            has_largest = true;
        }
        else if (value < largest &&
                 (!has_second || value > second))
        {
            second = value;
            has_second = true;
        }
    }

    if (!has_second)
        return 0;

    *answer = second;
    return 1;
}

int main(void)
{
    int arr[] = {10, 40, 20, 40, 30};
    int result;

    if (second_largest(arr, sizeof(arr) / sizeof(arr[0]), &result))
        printf("Second largest: %d\n", result);
    else
        printf("No distinct second-largest value\n");

    return 0;
}
Second largest: 30

Complexity: O(n) time and O(1) auxiliary space. The function handles negative values and repeated maximum values.

Problem 3: Check whether a string is a palindrome

#include <stdio.h>
#include <string.h>
#include <stdbool.h>

bool is_palindrome(const char str[])
{
    size_t left = 0;
    size_t right = strlen(str);

    if (right == 0)
        return true;

    right--;

    while (left < right)
    {
        if (str[left] != str[right])
            return false;

        left++;
        right--;
    }

    return true;
}

int main(void)
{
    char str[] = "LEVEL";

    if (is_palindrome(str))
        printf("Palindrome\n");
    else
        printf("Not palindrome\n");

    return 0;
}
Palindrome

Complexity: O(n) time and O(1) auxiliary space. This example compares characters exactly and is case-sensitive.

Problem 4: Count set bits

#include <stdio.h>

unsigned int count_set_bits(unsigned int n)
{
    unsigned int count = 0;

    while (n != 0U)
    {
        count += n & 1U;
        n >>= 1;
    }

    return count;
}

int main(void)
{
    unsigned int n = 13U;

    printf("%u\n", count_set_bits(n));

    return 0;
}
3

13 is binary 1101 and contains three set bits.

Complexity: O(w), where w is the width of unsigned int; O(1) auxiliary space.

Problem 5: Find the first non-repeating character

This example assumes the input contains bytes and uses all 256 possible unsigned-char values.

#include <stdio.h>
#include <string.h>

int main(void)
{
    char str[] = "swiss";
    size_t frequency[256] = {0};

    for (size_t i = 0; str[i] != '\0'; i++)
    {
        unsigned char ch = (unsigned char)str[i];
        frequency[ch]++;
    }

    for (size_t i = 0; str[i] != '\0'; i++)
    {
        unsigned char ch = (unsigned char)str[i];

        if (frequency[ch] == 1)
        {
            printf("%c\n", ch);
            return 0;
        }
    }

    printf("No unique character\n");
    return 0;
}
w

Complexity: O(n) time and O(1) auxiliary space because the frequency table has a fixed size.

6. Pointer and Memory Interview Patterns

Question 1: What is the difference between these declarations?

int *p;
int **pp;
int (*ptr)[5];
int *arr[5];
DeclarationMeaning
int *pPointer to int.
int **ppPointer to pointer to int.
int (*ptr)[5]Pointer to an array of five integers.
int *arr[5]Array of five pointers to int.

Question 2: What is a dangling pointer?

A dangling pointer refers to an object whose lifetime has ended or to storage that has been released. Accessing the object through that pointer is invalid.

Question 3: What happens if malloc fails?

For a nonzero allocation request, malloc() returns a null pointer if it cannot allocate the requested storage. The returned pointer must be checked before use.

Question 4: What is the correct realloc pattern?

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    size_t count = 5;

    int *arr = malloc(count * sizeof(*arr));

    if (arr == NULL)
        return 1;

    size_t new_count = 10;

    int *temp = realloc(arr, new_count * sizeof(*arr));

    if (temp == NULL)
    {
        free(arr);
        return 1;
    }

    arr = temp;

    free(arr);
    return 0;
}

The temporary pointer preserves the original allocation if realloc fails. A production implementation should also check for multiplication overflow before calculating allocation sizes.

7. Embedded C Interview Patterns

Problem 1: Set a bit

#include <stdio.h>

int main(void)
{
    unsigned int reg = 0U;
    unsigned int bit = 3U;

    reg |= (1U << bit);

    printf("%u\n", reg);

    return 0;
}
8

The third bit position counted from zero is set. Always ensure the shift count is smaller than the width of the promoted left operand.

Problem 2: Clear a bit

#include <stdio.h>

int main(void)
{
    unsigned int reg = 15U;
    unsigned int bit = 2U;

    reg &= ~(1U << bit);

    printf("%u\n", reg);

    return 0;
}
11

Problem 3: Toggle a bit

#include <stdio.h>

int main(void)
{

    unsigned int bit = 3U;

    reg ^= (1U << bit);

    printf("%u\n", reg);

    return 0;
}
0

Problem 4: Check whether a bit is set

#include <stdio.h>

int main(void)
{
    unsigned int reg = 10U;
    unsigned int bit = 3U;

    if ((reg & (1U << bit)) != 0U)
        printf("Set\n");
    else
        printf("Clear\n");

    return 0;
}
Set

Problem 5: Extract a register field

Assume a two-bit field starts at bit position 4.

#include <stdio.h>

int main(void)
{
    unsigned int reg = 0xB0U;

    unsigned int field = (reg >> 4U) & 0x3U;

    printf("%u\n", field);

    return 0;
}
3

The mask extracts bits 4 and 5 after shifting them to the lowest positions.

Question 6: Why is volatile used for memory-mapped registers?

Hardware registers can change outside the normal flow of C statements. A volatile-qualified access tells the compiler that the access is significant and should not be treated like an ordinary removable memory operation.

Question 7: What is the difference between polling and interrupt-driven programming?

Polling repeatedly checks a hardware status condition. Interrupt-driven programming responds to an event through an interrupt handler. The choice depends on timing requirements, latency, processor workload and system design.

9. Technical Interview Discussion Scenarios

Scenario 1: Your program crashes intermittently. How would you investigate?

Suggested answer:
  1. Reproduce the issue and identify the inputs and conditions.
  2. Compile with warnings and debug symbols.
  3. Use a debugger to inspect the call stack and variable values.
  4. Check pointer validity, array bounds and object lifetime.
  5. Use sanitizers where supported.
  6. Correct the root cause and test boundary cases.

Scenario 2: Your firmware reads an unexpected hardware register value. What would you check?

Suggested answer:
  • Verify the register address and processor-specific header definition.
  • Check clock, pin multiplexing and peripheral configuration.
  • Check whether the register is read-only, write-only or has special access semantics.
  • Check initialization order and required delays.
  • Check whether the register requires volatile-qualified access.
  • Use a debugger or hardware measurement tools to verify actual behavior.

Scenario 3: A program works on your computer but fails on another system. What could be the reason?

Suggested answer:

Possible causes include assumptions about integer sizes, byte order, plain char signedness, alignment, undefined behavior, compiler extensions, library availability and file-format portability. I would review the C standard assumptions, compiler options and platform-specific dependencies.

11. Interview Preparation Checklist

Use this checklist to assess your readiness.

  • Revise all fundamental C data types and conversion rules.
  • Practice operator precedence and output-prediction questions.
  • Write array and string programs without relying entirely on library functions.
  • Explain pointers, double pointers and function pointers.
  • Understand stack, heap and dynamic memory allocation.
  • Explain structure padding and alignment.
  • Understand storage duration, scope and linkage.
  • Practice file handling and error checking.
  • Identify undefined behavior in code snippets.
  • Compile C11 programs with warnings enabled.
  • Practice debugging with GDB and sanitizers.
  • Prepare embedded C and bit manipulation examples.
  • Be able to explain your own projects and design decisions.

12. How to Explain Your Projects in Interviews

For every project, prepare answers to these questions:

  1. What problem does the project solve?
  2. Why did you select the particular hardware and software?
  3. What was your role in the implementation?
  4. Which programming concepts did you use?
  5. What was the most difficult technical issue?
  6. How did you test and debug the system?
  7. What would you improve in the next version?
For embedded and electronics roles, be prepared to explain the complete signal or control flow of a project, including inputs, processing, output stages, power supply, protection and testing.

13. Final Interview Preparation Advice

  • Write code yourself rather than memorizing solutions.
  • Explain the logic before starting implementation.
  • Test normal cases, boundary cases and invalid inputs.
  • Discuss time and auxiliary space complexity.
  • Use meaningful variable names and consistent formatting.
  • Never assume undefined behavior has a predictable output.
  • When you do not know an answer, explain what you understand and reason carefully.
  • Relate language concepts to practical software or embedded applications.

14. Lecture Summary

  • Recruitment assessments may combine MCQs, coding, technical discussions and practical debugging.
  • C fundamentals, arrays, strings, pointers and memory management are core preparation areas.
  • Embedded roles additionally assess registers, volatile, interrupts and communication protocols.
  • Practice problems should include complexity analysis and edge-case handling.
  • Project explanations should demonstrate actual technical understanding.
  • Use timed practice to improve accuracy and problem-solving speed.
Placement Preparation Tip: Do not prepare for a company using only a list of memorized questions. Build the ability to solve unfamiliar variations of familiar problems. A strong candidate can explain the reasoning, write correct C code, test it and discuss trade-offs.
