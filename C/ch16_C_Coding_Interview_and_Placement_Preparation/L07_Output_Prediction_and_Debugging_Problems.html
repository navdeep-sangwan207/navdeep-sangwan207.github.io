1. Learning Objectives

After completing this lecture, you should be able to:

  • Trace C programs statement by statement.
  • Predict output involving operators, loops, arrays and pointers.
  • Understand integer promotions and signed/unsigned comparisons.
  • Identify errors involving format specifiers and memory access.
  • Recognize undefined, unspecified and implementation-defined behavior.
  • Use compiler warnings, GDB and sanitizers to debug programs.
  • Solve output-prediction questions commonly asked in technical interviews.

2. A Systematic Method for Output Prediction

Do not guess the output by reading the entire program quickly. Trace the program in execution order.

Recommended tracing procedure

  1. Identify the data types and initial values of all variables.
  2. Evaluate expressions according to precedence and associativity.
  3. Check where the language specifies the order of evaluation.
  4. Track loop conditions and updates.
  5. Track function calls, return values and variable lifetimes.
  6. Check array boundaries and pointer validity.
  7. Determine whether the program has defined behavior before predicting output.
Important: A C program does not necessarily have a predictable output just because a compiler produces an executable. Undefined behavior means the C standard imposes no requirements on the program's behavior.

3. Operator Precedence and Associativity

Operator precedence determines how an expression is grouped. Associativity determines grouping when operators have the same precedence.

Example 1: Arithmetic precedence

#include <stdio.h>

int main(void)
{
    int result = 10 + 5 * 2 - 8 / 4;

    printf("%d\n", result);

    return 0;
}
Output 
18

Explanation:

  • Multiplication: 5 * 2 = 10
  • Division: 8 / 4 = 2
  • Addition and subtraction: 10 + 10 - 2 = 18

Example 2: Left associativity

#include <stdio.h>

int main(void)
{
    int result = 20 / 5 * 2;

    printf("%d\n", result);

    return 0;
}
Output 
8

Multiplication and division have equal precedence and associate from left to right:

(20 / 5) * 2 = 4 * 2 = 8

Example 3: Parentheses change grouping

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 3;

    printf("%d\n", a + b * 2);
    printf("%d\n", (a + b) * 2);

    return 0;
}
Output 
16
26
Precedence does not specify the order in which operands are evaluated. Never assume that the left operand is always evaluated before the right operand.

4. Evaluation Order and Undefined Behavior

C does not specify a universal left-to-right evaluation order for function arguments or most binary operator operands. The sequencing rules determine whether modifications are valid.

Example: Undefined behavior

#include <stdio.h>

int main(void)
{
    int i = 5;

    printf("%d %d\n", i++, ++i);

    return 0;
}
No defined output. The modifications of i are unsequenced relative to each other. This causes undefined behavior. Do not assign a particular output to this program.

Correct alternative

#include <stdio.h>

int main(void)
{
    int i = 5;

    int first = i++;
    int second = ++i;

    printf("%d %d\n", first, second);

    return 0;
}
Output 
5 7

The statements are separate full expressions. The first stores 5 and increments i to 6. The second increments it to 7 and stores 7.

5. Integer Promotions and Signed/Unsigned Comparisons

Integer promotions and the usual arithmetic conversions can change the types used during expression evaluation.

Example: Signed and unsigned comparison

#include <stdio.h>

int main(void)
{
    int a = -1;
    unsigned int b = 1U;

    if (a < b)
        printf("A is smaller\n");
    else
        printf("B is smaller or equal\n");

    return 0;
}
Typical output on common systems 
B is smaller or equal

Explanation: On common implementations where unsigned int and int have the same rank and width, the signed value is converted to unsigned. The value -1 becomes UINT_MAX, which is greater than 1.

The conversion rules depend on the integer types and their ranges. Always identify the types before evaluating a mixed signed/unsigned expression.

Example: Integer division

#include <stdio.h>

int main(void)
{
    int a = 7;
    int b = 2;

    printf("%d\n", a / b);
    printf("%.2f\n", (double)a / b);

    return 0;
}
Output 
3
3.50

Integer division discards the fractional part when both operands are integers. Casting one operand to double causes floating-point division.

Important: Signed integer overflow

In C, an arithmetic result that cannot be represented by its signed integer type causes undefined behavior.

int x = INT_MAX;
x = x + 1;   /* Undefined behavior */

Include <limits.h> to use INT_MAX. Unsigned arithmetic, in contrast, wraps modulo one more than the maximum representable value.

6. sizeof, Arrays and Pointers

The sizeof operator returns the size in bytes of its operand's type. Its result type is size_t.

Example 1: Array size

#include <stdio.h>

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};

    size_t total = sizeof(arr);
    size_t element = sizeof(arr[0]);
    size_t count = total / element;

    printf("Array size: %zu bytes\n", total);
    printf("Element size: %zu bytes\n", element);
    printf("Number of elements: %zu\n", count);

    return 0;
}
Typical output on a system with 4-byte int 
Array size: 20 bytes
Element size: 4 bytes
Number of elements: 5

The number of elements is calculated using sizeof(arr) / sizeof(arr[0]). This works where arr is an actual array, not a pointer.

Example 2: Array parameter adjustment

#include <stdio.h>

void display(int arr[])
{
    printf("Inside function: %zu\n", sizeof(arr));
}

int main(void)
{
    int arr[5] = {1, 2, 3, 4, 5};

    printf("In main: %zu\n", sizeof(arr));
    display(arr);

    return 0;
}

Typical output on a system with 4-byte int and 8-byte pointers:

In main: 20
Inside function: 8

In a function parameter declaration, int arr[] is adjusted to int *arr. Therefore, sizeof(arr) inside the function gives the pointer size, not the original array size.

Example 3: sizeof versus strlen

#include <stdio.h>
#include <string.h>

int main(void)
{
    char str[] = "HELLO";

    printf("sizeof: %zu\n", sizeof(str));
    printf("strlen: %zu\n", strlen(str));

    return 0;
}
Output 
sizeof: 6
strlen: 5
  • sizeof(str) includes the null terminator.
  • strlen(str) counts characters before the null terminator.

7. Function Calls and Static Local Variables

A static local variable retains its value between function calls. It has static storage duration but block scope.

Example: Static variable tracing

#include <stdio.h>

void counter(void)
{
    static int count = 0;
    count++;

    printf("%d ", count);
}

int main(void)
{
    counter();
    counter();
    counter();

    return 0;
}
Output 
1 2 3

The variable is initialized only once. Its value persists between calls.

Example: Recursion tracing

#include <stdio.h>

int sum(int n)
{
    if (n == 0)
        return 0;

    return n + sum(n - 1);
}

int main(void)
{
    printf("%d\n", sum(4));

    return 0;
}
Output 
10

Expansion:

sum(4) = 4 + sum(3)

= 4 + 3 + sum(2)

= 4 + 3 + 2 + sum(1)

= 4 + 3 + 2 + 1 + sum(0) = 10

8. Pointer and Array Output Prediction

Example 1: Pointer increment

#include <stdio.h>

int main(void)
{
    int arr[] = {10, 20, 30};
    int *ptr = arr;

    printf("%d\n", *ptr);

    ptr++;
    printf("%d\n", *ptr);

    printf("%d\n", *(ptr + 1));

    return 0;
}
Output 
10
20
30

Pointer arithmetic advances by elements of the pointed-to type, not by individual bytes.

Example 2: Array indexing and pointer notation

#include <stdio.h>

int main(void)
{
    int arr[] = {5, 10, 15, 20};

    printf("%d\n", arr[2]);
    printf("%d\n", *(arr + 2));
    printf("%d\n", 2[arr]);

    return 0;
}
Output 
15
15
15

Array subscripting is defined in terms of pointer addition and dereferencing: arr[i] is equivalent to *(arr + i). The expression 2[arr] is also equivalent, though it is rarely used in readable code.

Pointer arithmetic and dereferencing must stay within the bounds and lifetime of the relevant object. A one-past-the-end pointer may be formed for an array, but it must not be dereferenced.

9. Strings and Character Arrays

Example: Modifying a string array

#include <stdio.h>

int main(void)
{
    char str[] = "CODE";

    str[0] = 'N';

    printf("%s\n", str);

    return 0;
}
Output 
NODE

The string is stored in a modifiable character array. Changing an element is valid as long as the array bounds are respected.

Example: String literal pointer

const char *str = "CODE";
printf("%s\n", str);

This is valid for reading the string. Attempting to modify the string literal through a pointer causes undefined behavior. The const qualifier helps prevent accidental modification through this pointer.

10. Structures and Padding

Structure members may have padding between them or at the end of the structure to satisfy alignment requirements.

#include <stdio.h>

struct Data
{
    char c;
    int number;
};

int main(void)
{
    printf("%zu\n", sizeof(struct Data));

    return 0;
}
Typical output on many systems 
8

This result is common when char occupies one byte and int occupies four bytes with four-byte alignment. The C standard does not require this exact structure size on every implementation.

11. printf Format Specifier Errors

Format specifiers must match the types of the corresponding arguments after the default argument promotions. A mismatch can cause undefined behavior.

Data / purposeCorrect format
int%d
unsigned int%u
long%ld
long long%lld
double in printf%f
char promoted to int%c
String%s
size_t%zu
Pointer%p with (void *)ptr

Correct pointer printing

#include <stdio.h>

int main(void)
{
    int value = 100;
    int *ptr = &value;

    printf("Address: %p\n", (void *)ptr);
    printf("Value: %d\n", *ptr);

    return 0;
}

The actual address is implementation-dependent. The cast to void * is the correct argument type for %p.

12. Loops, break and continue

Example 1: continue statement

#include <stdio.h>

int main(void)
{
    int i;

    for (i = 1; i <= 5; i++)
    {
        if (i == 3)
            continue;

        printf("%d ", i);
    }

    return 0;
}
Output 
1 2 4 5

When i becomes 3, the remaining loop body is skipped. The loop update expression still executes.

Example 2: switch fall-through

#include <stdio.h>

int main(void)
{
    int x = 2;

    switch (x)
    {
        case 1:
            printf("One ");

        case 2:
            printf("Two ");

        case 3:
            printf("Three ");
            break;

        default:
            printf("Other ");
    }

    return 0;
}
Output 
Two Three

Execution starts at case 2 and continues into case 3 because there is no break after case 2.

13. Classifying Program Behavior

Before predicting output, classify the behavior of the expression or program.

CategoryMeaningExample
Defined behavior The C standard specifies the behavior. Adding two representable integers.
Unspecified behavior The standard permits multiple possibilities and does not require the implementation to document which one occurs. Order of evaluation of function arguments, where no sequencing rule fixes it.
Implementation-defined behavior The implementation chooses a behavior and documents its choice. Whether plain char is signed or unsigned.
Undefined behavior The C standard imposes no requirements. Signed integer overflow or dereferencing an invalid pointer.

Common undefined behavior examples

  • Modifying the same scalar object multiple times without required sequencing.
  • Signed integer overflow.
  • Dividing an integer by zero.
  • Dereferencing a null or invalid pointer.
  • Accessing an array outside its valid bounds.
  • Using an object after its lifetime has ended.
  • Using a pointer after the allocated memory has been freed.
  • Passing incompatible arguments to variadic functions such as printf.
Never answer an undefined-behavior question by claiming that a particular compiler's observed result is the C language's guaranteed output. Compiler optimization can change what appears to happen.

14. Common Debugging Workflow

Debugging is a structured process of reproducing, isolating, identifying and correcting a defect.

Step 1: Compile with warnings

gcc -std=c11 -Wall -Wextra -Wpedantic -g program.c -o program

Warnings can identify suspicious conversions, incorrect format strings, unused variables and other potential problems.

Step 2: Run the program

./program

Step 3: Use GDB

Compile with debug information using -g, then launch the debugger:

gdb ./program
GDB commandPurpose
break mainSet a breakpoint at main.
runStart execution.
nextExecute the next source line without stepping into a function.
stepStep into a function call.
print variableDisplay a variable's value.
display variableDisplay a variable after each stop.
continueContinue execution.
backtraceDisplay the call stack.
quitExit GDB.

Step 4: Use sanitizers where supported

gcc -std=c11 -Wall -Wextra -g \
    -fsanitize=address,undefined program.c -o program

./program

AddressSanitizer can help detect memory errors such as out-of-bounds access and use-after-free. UndefinedBehaviorSanitizer can detect several classes of undefined behavior. Availability depends on the compiler and platform.

Sanitizers are development tools, not a replacement for understanding the C standard. They cannot detect every possible defect.

15. Placement Practice: Output Prediction Questions

Question 1: Post-increment

#include <stdio.h>

int main(void)
{
    int x = 5;
    int y = x++;

    printf("%d %d\n", x, y);

    return 0;
}
Show answer and explanation 
6 5

x++ produces the old value, 5, and then increments x to 6.

Question 2: Logical operators

#include <stdio.h>

int main(void)
{
    int a = 0;
    int b = 10;

    int result = a && ++b;

    printf("%d %d\n", result, b);

    return 0;
}
Show answer and explanation 
0 10

Logical AND uses short-circuit evaluation. Since a is zero, ++b is not evaluated.

Question 3: Loop tracing

#include <stdio.h>

int main(void)
{
    int i;
    int sum = 0;

    for (i = 1; i <= 5; i++)
    {
        if (i % 2 == 0)
            continue;

        sum += i;
    }

    printf("%d\n", sum);

    return 0;
}
Show answer and explanation 
9

Even numbers are skipped. The sum is 1 + 3 + 5 = 9.

Question 4: Array indexing

#include <stdio.h>

int main(void)
{
    int a[] = {2, 4, 6, 8, 10};
    int sum = 0;

    for (int i = 0; i < 5; i += 2)
        sum += a[i];

    printf("%d\n", sum);

    return 0;
}
Show answer and explanation 
18

The selected elements are a[0] = 2, a[2] = 6 and a[4] = 10. Their sum is 18.

Question 5: Function return value

#include <stdio.h>

int calculate(int x)
{
    x = x * 2;
    return x + 3;
}

int main(void)
{
    int a = 4;

    printf("%d %d\n", calculate(a), a);

    return 0;
}
Show answer and explanation 
11 4

The function receives a copy of a. It calculates 4 * 2 + 3 = 11. The original a remains 4. The two function arguments to printf are not modified relative to one another, so their evaluation order does not affect this output.

Question 6: Static local variable

#include <stdio.h>

int getValue(void)
{
    static int x = 2;
    x += 3;
    return x;
}

int main(void)
{
    printf("%d ", getValue());
    printf("%d ", getValue());
    printf("%d\n", getValue());

    return 0;
}
Show answer and explanation 
5 8 11

The static variable is initialized once to 2. Each call adds 3 and returns the updated value.

Question 7: Bitwise AND

#include <stdio.h>

int main(void)
{
    unsigned int a = 12U;
    unsigned int b = 10U;

    printf("%u\n", a & b);

    return 0;
}
Show answer and explanation 
8

12 is binary 1100 and 10 is binary 1010. Their bitwise AND is 1000, which is 8.

Question 8: Pointer traversal

#include <stdio.h>

int main(void)
{
    int a[] = {3, 6, 9, 12};
    int *p = a + 1;

    printf("%d ", *p);
    printf("%d ", *(p + 2));
    printf("%d\n", p[-1]);

    return 0;
}
Show answer and explanation 
6 12 3

p points to a[1]. Therefore, *p is 6, *(p + 2) is 12, and p[-1] refers to a[0], which is 3. All accesses are within the array.

16. Debugging Challenge

The following program contains a logical error. Identify and correct it.

#include <stdio.h>

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    int sum = 0;

    for (int i = 0; i <= 5; i++)
    {
        sum += arr[i];
    }

    printf("Sum = %d\n", sum);

    return 0;
}

Problem: The loop condition permits i == 5, but the valid array indices are 0 through 4. The access arr[5] is out of bounds and causes undefined behavior.

Corrected program

#include <stdio.h>

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    int sum = 0;
    int count = (int)(sizeof(arr) / sizeof(arr[0]));

    for (int i = 0; i < count; i++)
    {
        sum += arr[i];
    }

    printf("Sum = %d\n", sum);

    return 0;
}
Output 
Sum = 150

19. Lecture Summary

  • Trace variables and expressions systematically rather than guessing output.
  • Precedence and associativity determine grouping, not general operand evaluation order.
  • Integer promotions and signed/unsigned conversions are important in output questions.
  • sizeof and strlen measure different things.
  • Array parameters are adjusted to pointer parameters.
  • Pointer arithmetic must respect object boundaries and lifetime.
  • Static local variables preserve their values between function calls.
  • Undefined behavior has no guaranteed output.
  • Warnings, GDB and sanitizers are important debugging tools.
Placement Preparation Tip: In an output-prediction interview question, first check whether the program has defined behavior. Then trace types, expression grouping, sequencing, variable updates and memory accesses. Explaining why an expression is invalid is often more valuable than guessing what one compiler happens to print.
