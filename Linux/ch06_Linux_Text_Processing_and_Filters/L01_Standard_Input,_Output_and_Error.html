Standard Input, Output and Error

Understanding Linux Standard Streams and File Descriptors

Learning Objectives

After completing this lesson, you will be able to:

  • Understand standard input, standard output, and standard error.
  • Identify the three standard file descriptors.
  • Understand how Linux commands receive input and produce output.
  • Differentiate normal output from error messages.
  • Use basic commands to observe standard streams.
  • Understand the relationship between standard streams and redirection.

1. Introduction to Standard Streams

In Linux, a running program commonly communicates with its environment through three standard data streams: Standard Input, Standard Output, and Standard Error.

These streams provide a consistent way for programs to receive data and display results or error messages.

Standard Streams:
  • stdin: Standard Input
  • stdout: Standard Output
  • stderr: Standard Error

By default, these streams are usually connected to the terminal when a command is executed interactively.

2. Standard Input (stdin)

Standard Input is the default stream through which a program receives input data.

When a user types something into a terminal, the program can receive that data through standard input.

File Descriptor of stdin

File Descriptor: 0 Stream Name: stdin Default Source: Keyboard / Terminal

Example 1: Using the cat Command

cat

The cat command without a filename reads data from standard input and displays it on standard output.

Example Terminal Interaction:
Hello Linux Hello Linux Learning standard input Learning standard input

The first line is typed by the user. The second line is displayed by cat. Press Ctrl + D on an empty input line to signal end-of-file (EOF).

Example 2: Using the read Command

read name echo "Welcome $name"

The read command accepts input from standard input and stores the entered value in the variable name.

Example:
Navdeep Welcome Navdeep

The first line is the user's input.

3. Standard Output (stdout)

Standard Output is the default stream used by a program to display normal results or output.

When a command successfully produces information, it generally writes that information to standard output.

File Descriptor of stdout

File Descriptor: 1 Stream Name: stdout Default Destination: Terminal

Example 1: Using echo

echo "Hello Linux"
Output:
Hello Linux

Example 2: Using pwd

pwd
Example Output:
/home/navdeep

The displayed path is an example. Your actual output depends on your current working directory and username.

Example 3: Using ls

ls

The ls command displays the names of files and directories. Its normal listing is written to standard output.

4. Standard Error (stderr)

Standard Error is the default stream used by a program to display diagnostic messages, warnings, and error information.

It is separate from standard output so that error messages can be handled independently from normal results.

File Descriptor of stderr

File Descriptor: 2 Stream Name: stderr Default Destination: Terminal

Example 1: Accessing a Non-Existing File

cat missing.txt
Example Error Message:
cat: missing.txt: No such file or directory

The exact wording may vary. The diagnostic message is written to standard error.

Example 2: Listing a Non-Existing Directory

ls /nonexistent_directory
Example Error Message:
ls: cannot access '/nonexistent_directory': No such file or directory
Important: A command can produce normal output and error messages during the same execution. These may be written to stdout and stderr independently.

5. Understanding File Descriptors

A file descriptor is a non-negative integer used by a process to identify an open file or input/output resource.

Linux assigns three standard file descriptors to a process:

File Descriptor Stream Purpose Default Destination
0 stdin Receives input Terminal input
1 stdout Displays normal output Terminal output
2 stderr Displays error messages Terminal output

Standard File Descriptor Diagram

Keyboard / Terminal Input

↓ File Descriptor 0 (stdin)

Linux Process / Command

↙ File Descriptor 1 (stdout)

↘ File Descriptor 2 (stderr)

Terminal Output

Both normal output and error messages normally appear on the terminal.

File descriptors 0, 1, and 2 are the conventional standard descriptors. A process can open additional files and receive other file descriptor numbers.

6. Difference Between stdin, stdout and stderr

Feature stdin stdout stderr
Full Form Standard Input Standard Output Standard Error
Descriptor 0 1 2
Purpose Input data Normal results Diagnostic messages
Default Connection Terminal input Terminal output Terminal output

7. Practical Examples

Example 1: Display Normal Output

Output:
Linux Programming

Example 2: Generate an Error Message

cat unknown.txt
Example Error:
cat: unknown.txt: No such file or directory

Example 3: Display Input Using cat

cat

Type a few lines and observe how cat displays them. Press Ctrl + D on an empty line to finish.

Example 4: Read User Input in Bash

#!/bin/bash echo "Enter your name:" read name echo "Hello, $name"
Example Execution:
Enter your name: Navdeep Hello, Navdeep

Example 5: Check Whether a File Exists

if [ -f "data.txt" ]; then echo "File exists" else echo "File does not exist" fi

This Bash example checks whether data.txt exists as a regular file and prints the corresponding message.

8. How Standard Streams Relate to Redirection

Linux allows standard streams to be redirected from their default terminal connections to files or other destinations.

For example, standard output can be redirected into a file instead of being displayed on the terminal.

echo "Hello Linux" > output.txt

This command redirects standard output to output.txt. The output is written to the file rather than displayed on the terminal.

Redirection operators are explained in detail in Lesson 2: Redirection Operators.

10. Common Mistakes

  • Confusing standard output with standard error.
  • Assuming file descriptor 1 represents standard input.
  • Forgetting that stdin uses descriptor 0.
  • Assuming all terminal messages are normal output.
  • Pressing Ctrl + C instead of Ctrl + D when trying to signal end-of-file in the cat example.
Remember: Ctrl + D signals end-of-file (EOF) when entered at the terminal in the appropriate input context. Ctrl + C sends an interrupt signal to the foreground process.

11. Interview Questions and Answers

Q1. What are standard streams in Linux?

Answer: Standard streams are the default communication channels used by a process for input, normal output, and error messages.

Q2. What is stdin?

Answer: stdin stands for Standard Input. It is the default input stream of a process and uses file descriptor 0.

Q3. What is stdout?

Answer: stdout stands for Standard Output. It is used to display normal program results and uses file descriptor 1.

Q4. What is stderr?

Answer: stderr stands for Standard Error. It is used for diagnostic and error messages and uses file descriptor 2.

Q5. What is a file descriptor?

Answer: A file descriptor is a non-negative integer used by a process to identify an open file or input/output resource.

Q6. What are the three standard file descriptors?

Answer: 0 for stdin, 1 for stdout, and 2 for stderr.

Q7. Why are stdout and stderr separate?

Answer: They allow normal program output and diagnostic messages to be handled independently.

Q8. Which command can read data from standard input?

Answer: The cat command without a filename can read from standard input.

Q9. What does Ctrl + D do in the terminal?

Answer: It signals end-of-file (EOF) to a program reading terminal input.

Q10. Where do stdout and stderr normally appear?

Answer: Both normally appear on the terminal in an interactive shell, although they are separate streams.

13. Lesson Summary

  • Linux programs commonly use three standard streams.
  • stdin is Standard Input and uses file descriptor 0.
  • stdout is Standard Output and uses file descriptor 1.
  • stderr is Standard Error and uses file descriptor 2.
  • stdin receives data from the default input source.
  • stdout displays normal program output.
  • stderr displays diagnostic and error messages.
  • Both stdout and stderr normally appear on the terminal.
  • Redirection allows these streams to be connected to other destinations.
Important Concept to Remember:

0 = stdin | 1 = stdout | 2 = stderr
