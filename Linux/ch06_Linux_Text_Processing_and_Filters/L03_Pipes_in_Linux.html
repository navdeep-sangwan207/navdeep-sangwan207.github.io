Pipes in Linux

Connecting Commands and Processing Data Through Pipelines

  • Use the pipe operator (|) between commands.
  • Understand how data flows through a pipeline.

1. Introduction to Pipes

A pipe is a Linux mechanism that connects the standard output of one command to the standard input of another command.

It allows the output produced by one command to be processed directly by another command without creating an intermediate file.

Pipe Operator:
|
The vertical bar is called the pipe operator.

Basic Syntax

command1 | command2
  • command1 produces output.
  • The pipe passes that output to command2.
  • command2 processes the received input.

2. How a Pipe Works

A pipeline connects commands through their standard input and standard output streams.

Data Flow

First Command

↓ Standard Output (stdout)

Pipe Operator ( | )

↓ Standard Input (stdin)

Second Command

↓

Final Output

For a simple pipeline, the shell connects the stdout of the first command to the stdin of the second command.

Important: A normal pipe carries standard output, not standard error. Error messages generally continue to appear on the terminal unless stderr is redirected or explicitly included in the pipe.

3. Basic Pipe Example

Example 1: Using ls and grep

ls /etc | grep passwd

The ls command lists entries in /etc. The grep command receives that listing and displays lines containing the text passwd.

Example Output:
passwd passwd-

Actual output depends on the contents of your /etc directory.

Example 2: Using ps and grep

ps aux | grep bash

The ps aux command displays process information. The grep command filters the output and displays lines containing bash.

The grep command may also match its own process line. This is normal for this basic example.

4. Using Multiple Pipes

Linux allows multiple pipe operators in one command line. This creates a pipeline in which each command processes the output of the previous command.

Syntax

command1 | command2 | command3

Example 1: Sort and Display Data

printf "Orange\nApple\nBanana\n" | sort
Output:
Apple Banana Orange

Example 2: Count Files in a Directory

ls /etc | wc -l

The ls command produces a listing and wc -l counts the lines received through the pipe.

This counts lines in the command's output, not necessarily every filesystem entry under all conditions. For a more reliable count of directory entries, use an appropriate find command.

Example 3: Sort and Display the First Five Lines

ls /etc | sort | head -n 5

The pipeline performs three operations:

  1. ls lists directory entries.
  2. sort arranges the lines alphabetically.
  3. head displays the first five lines.

5. Pipes with Common Linux Commands

Example 1: grep with Pipe

cat /etc/passwd | grep root

Displays lines from /etc/passwd containing root.

For this simple case, grep root /etc/passwd is shorter and avoids an unnecessary cat process. The pipeline is shown here to demonstrate pipe operation.

Example 2: sort with uniq

printf "apple\nbanana\napple\norange\nbanana\n" | sort | uniq
Output:
apple banana orange

sort places identical lines next to each other, and uniq removes adjacent duplicate lines.

Example 3: wc with Pipe

cat /etc/passwd | wc -l

Counts the number of lines in /etc/passwd.

Example 4: head with Pipe

cat /etc/passwd | head -n 5

Displays the first five lines from the file.

Example 5: tail with Pipe

cat /etc/passwd | tail -n 5

Displays the last five lines from the file.

6. Practical Pipeline Examples

Example 1: Find a Running Process

ps aux | grep firefox

Displays process-listing lines containing firefox.

Example 2: Search for a User Account

cat /etc/passwd | grep navdeep

Searches for lines containing navdeep in the user account database.

Example 3: Count Matching Lines

grep "root" /etc/passwd | wc -l

Counts the number of lines in /etc/passwd that contain root.

Example 4: Display Unique Sorted Values

printf "C\nC++\nLinux\nC\nLinux\n" | sort | uniq
Output:
C C++ Linux

Example 5: Display the Ten Largest Files by Size

ls -lhS /var/log | head -n 11

The ls -lhS command lists entries in human-readable format, sorted by size in descending order. head displays the first eleven output lines, including the total line when present.

7. Combining Pipes with Redirection

Pipes and redirection can be used together to process command output and save the final result in a file.

Example 1: Save Filtered Output

ls /etc | grep passwd > result.txt

The pipeline filters the directory listing, and the final standard output is saved in result.txt.

Example 2: Append Pipeline Output

ls /etc | grep conf >> result.txt

Matching lines are appended to result.txt.

Example 3: Count and Save a Result

grep "root" /etc/passwd | wc -l > count.txt

The number of matching lines is saved in count.txt.

8. Pipe Standard Error

By default, the pipe operator sends only standard output to the next command. Standard error is not included.

Example 1: Redirect stderr into stdout

command 2>&1 | grep error

This sends both standard output and standard error into the pipe. The grep command then filters the combined stream.

Example 2: Bash Combined Pipe Operator

command |& grep error

In Bash, the |& operator connects both standard output and standard error to the next command. It is shorthand for 2>&1 |.

The |& operator is supported by Bash and some other shells. It is not POSIX shell syntax.

9. Difference Between Pipe and Redirection

Feature Pipe ( | ) Redirection
Purpose Connects commands. Changes input or output destination.
Data Flow Output of one command becomes input of another. Data is read from or written to a file or other destination.
Example ls | grep txt ls > files.txt
Intermediate File Not normally required. May use a file as the source or destination.
Common Use Command chaining and filtering. Saving or supplying data.

10. Understanding Pipeline Execution

When a shell executes a pipeline, it creates connections between the commands so that data can flow from one process to another.

For example:

cat file.txt | grep Linux | wc -l

Conceptually, the pipeline performs these steps:

  1. cat reads file.txt and writes its contents to stdout.
  2. The pipe passes that data to grep through stdin.
  3. grep selects lines containing Linux.
  4. The next pipe passes matching lines to wc.
  5. wc -l counts the matching lines.
Technical Concept: A Linux pipe is a unidirectional inter-process communication (IPC) mechanism. It allows processes to exchange data through a kernel-managed buffer.

The shell normally starts pipeline commands so they can execute concurrently. A downstream command may begin reading while an upstream command is still producing data.

11. Common Mistakes and Precautions

  • Using a slash (/) instead of the pipe symbol (|).
  • Forgetting that a normal pipe carries stdout, not stderr.
  • Using commands in the wrong order.
  • Forgetting that uniq removes only adjacent duplicate lines.
  • Using unnecessary cat commands when a command can read the file directly.
  • Assuming every command in a pipeline succeeded just because the final command produced output.
Important: Pipeline Exit Status

By default, Bash normally reports the exit status of the last command in a pipeline. Therefore, an earlier command can fail while the final command succeeds.

Bash provides set -o pipefail so that a pipeline returns a non-zero status if a command in the pipeline fails, subject to the pipeline's exit-status rules.

Example

set -o pipefail cat missing.txt | wc -l echo $?

The cat command fails because the file does not exist. With pipefail enabled, the pipeline returns a non-zero exit status.

13. Interview Questions and Answers

Q1. What is a pipe in Linux?

Answer: A pipe connects the standard output of one command to the standard input of another command.

Q2. Which symbol is used for a pipe?

Answer: The vertical bar symbol (|).

Q3. What is the basic syntax of a pipe?

Answer: command1 | command2.

Q4. Which stream is passed through a normal pipe?

Answer: Standard output (stdout) of the first command is connected to standard input (stdin) of the next command.

Q5. Does a normal pipe transfer stderr?

Answer: No. Standard error is not included by default. It must be redirected if it needs to enter the pipe.

Q6. Can multiple pipes be used in one command?

Answer: Yes. Multiple pipes can connect several commands into a pipeline.

Q7. What is the difference between a pipe and redirection?

Answer: A pipe connects commands, while redirection changes where a command receives input or sends output.

Q8. What is inter-process communication?

Answer: Inter-process communication (IPC) is a mechanism that allows separate processes to exchange data or coordinate their activities.

Q9. What does the pipefail option do in Bash?

Answer: It makes a pipeline return a non-zero status if a command in the pipeline fails, according to Bash's pipefail rules.

Q10. Why is sort often used before uniq?

Answer: Because uniq removes adjacent duplicate lines. Sorting places identical lines together.

Q1. Which symbol represents a pipe in Linux?

  1. >
  2. <
  3. |
  4. &

Correct Answer: C. |

Q2. A pipe connects which two streams?

  1. stdin to stderr
  2. stdout to stdin
  3. stderr to stdout
  4. stdin to stdin only

Correct Answer: B. stdout to stdin

Q3. Which command can filter output through a pipe?

  1. grep
  2. mkdir
  3. rmdir
  4. touch

Correct Answer: A. grep

Q4. Which command counts lines?

  1. sort
  2. grep
  3. wc -l
  4. mkdir

Correct Answer: C. wc -l

Q5. Which command sorts text?

  1. sort
  2. cut
  3. pwd
  4. chmod

Correct Answer: A. sort

Q6. Which command removes adjacent duplicate lines?

  1. grep
  2. uniq
  3. head
  4. tail

Correct Answer: B. uniq

Q7. Does the normal pipe operator transfer stderr?

  1. Yes, always
  2. No, not by default

  4. Only with root privileges

Correct Answer: B. No, not by default

Q8. Which Bash option helps detect failures in a pipeline?

  1. set -o pipefail
  2. set -o sort
  3. set -o grep
  4. set -o output

Correct Answer: A. set -o pipefail

15. Lesson Summary

  • A pipe connects two or more Linux commands.
  • The pipe operator is represented by |.
  • stdout of one command becomes stdin of the next command.
  • A normal pipe does not transfer stderr by default.
  • Multiple pipes can be combined into a pipeline.
  • Pipes are useful for filtering, sorting, and counting data.
  • Pipes can be combined with output redirection.
  • A Linux pipe is an inter-process communication mechanism.
  • Bash pipefail helps detect failures in pipeline commands.
Important Concept to Remember:

command1 | command2

stdout of command1 → stdin of command2
