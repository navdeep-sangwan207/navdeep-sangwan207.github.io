Exit Status and Error Handling

Understanding Command Success, Failure and Reliable Shell Scripts

1. Introduction to Exit Status

An exit status is a numeric value returned by a command or shell script when it finishes execution. It indicates whether the operation completed successfully or encountered a problem.

Linux commands generally follow this convention:

Exit Status Meaning
0 Command completed successfully.
Non-zero Command reported failure or another condition.
Exit status zero means success. A non-zero value means something other than success according to that command's documented exit-status convention. Different commands may use different non-zero values for different errors.

Example

#!/bin/bash echo "Hello Linux" echo "Script completed"

Output

Hello Linux
Script completed

2. Understanding the Special Variable $?

The special variable $? stores the exit status of the most recently executed foreground command, pipeline or asynchronous list as applicable to the shell context.

Syntax

echo $?

Example 1: Successful Command

#!/bin/bash echo "Linux Learning" echo "Exit Status: $?"

Output

Linux Learning
Exit Status: 0

Example 2: Failed Command

#!/bin/bash ls /directory_that_does_not_exist echo "Exit Status: $?"

Possible Output

ls: cannot access '/directory_that_does_not_exist': No such file or directory
Exit Status: 2
Explanation: The directory does not exist, so the ls command reports an error. Its exit status is non-zero.
Capture $? immediately after the command you want to check. Running another command first can overwrite the previous status.

3. Using Exit Status with if-else

An exit status can be checked using an if-else statement.

Example

#!/bin/bash ls /home if [ $? -eq 0 ]; then echo "Command executed successfully" else echo "Command failed" fi

Explanation

  • $? contains the previous command's exit status.
  • -eq 0 checks whether the status is zero.
  • If the condition is true, the success message is displayed.
  • Otherwise, the failure message is displayed.

Better Method: Direct Command Check

#!/bin/bash if ls /home; then echo "Command executed successfully" else echo "Command failed" fi
Checking the command directly in an if statement is generally clearer and avoids accidentally checking the exit status of a different command.

4. The exit Command

The exit command terminates the current shell script and returns an exit status to the calling process.

Syntax

exit status

The status is optional. If omitted, Bash normally returns the status of the last command executed.

Example 1: Successful Exit

#!/bin/bash echo "Program started" exit 0 echo "This statement will not execute"

Output

Program started

Example 2: Error Exit

#!/bin/bash echo "Invalid input detected" exit 1
Explanation: The script terminates and returns exit status 1 to the process that started it.

Example 3: Validate Input

#!/bin/bash read -p "Enter your age: " age if [[ ! "$age" =~ ^[0-9]+$ ]]; then echo "Error: Enter a valid non-negative integer" exit 1 fi echo "Your age is $age" exit 0
Exit status 0 is commonly used for success, while non-zero values indicate errors. Choose documented status values consistently in your own scripts.

5. Checking Whether a File Exists

A script can check whether a file exists before attempting to read or modify it.

Example

#!/bin/bash filename="data.txt" if [ -f "$filename" ]; then echo "File exists" else echo "Error: File not found" exit 1 fi echo "Continuing script..."

Output When File Exists

File exists
Continuing script...

Output When File Does Not Exist

Error: File not found

The -f test checks whether the path exists and refers to a regular file.

6. Logical Operators for Command Execution

Bash provides logical operators that allow one command to execute depending on the result of another command.

Operator Meaning
&& Execute the next command only if the previous command succeeds.
|| Execute the next command only if the previous command fails.
; Execute the next command regardless of the previous command's status.

Example 1: Using &&

#!/bin/bash mkdir test_directory && echo "Directory created successfully"

Output When Successful

Directory created successfully

Example 2: Using ||

#!/bin/bash mkdir /root/test_directory || echo "Directory creation failed"

Possible Output

Directory creation failed

This example will normally fail when run as an ordinary user without permission to create a directory under /root.

Example 3: Using Semicolon

#!/bin/bash echo "First command" echo "Second command"

Output

First command
Second command

7. Standard Error (stderr)

Linux uses three standard data streams:

Stream File Descriptor Purpose
Standard Input (stdin) 0 Receives input.
Standard Output (stdout) 1 Displays normal output.
Standard Error (stderr) 2 Displays error messages.

Example 1: Redirect Error Messages

#!/bin/bash ls /invalid_directory 2> error.log echo "Command exit status: $?"

The error message is written to error.log instead of appearing on the terminal.

Example 2: Redirect Both Output and Error

#!/bin/bash ls /home /invalid_directory > output.log 2>&1 echo "Command exit status: $?"

Normal output and error messages are both redirected to output.log.

Example 3: Discard Error Messages

#!/bin/bash ls /invalid_directory 2> /dev/null echo "Script continued"

Output

Script continued
/dev/null is a special device that discards data written to it.

8. Error Handling with set -e

The command set -e enables Bash's errexit behavior. It causes a non-interactive shell to exit when certain commands return non-zero status.

Example

#!/bin/bash set -e echo "Starting script" ls /invalid_directory echo "This statement will normally not execute"

Possible Output

Starting script
ls: cannot access '/invalid_directory': No such file or directory
set -e has exceptions. Commands used in conditions, parts of certain AND/OR lists, and some pipeline contexts do not always cause the shell to exit. Do not treat it as a complete replacement for explicit error checks.

9. Error Handling with set -u

The command set -u enables nounset behavior. It reports an error when a script expands an unset variable, with certain exceptions.

Example

#!/bin/bash set -u name="Navdeep" echo "Name: $name" echo "Age: $age"

Possible Output

Name: Navdeep
bash: age: unbound variable
Explanation: The variable age has not been assigned a value. Because set -u is enabled, Bash reports an error instead of silently expanding it as empty.

10. Error Handling with set -o pipefail

Normally, the exit status of a pipeline is the status of its last command. The pipefail option changes this behavior.

Example Without pipefail

#!/bin/bash false | true echo "Exit Status: $?"

Output

Exit Status: 0

The last command, true, succeeds. Therefore, the pipeline returns status zero by default.

Example With pipefail

#!/bin/bash set -o pipefail false | true echo "Exit Status: $?"

Output

Exit Status: 1

With pipefail, the pipeline returns a non-zero status if a command in the pipeline fails. It returns the status of the rightmost command that failed.

11. Combining Strict Mode Options

A common starting configuration for Bash scripts is:

#!/bin/bash set -euo pipefail echo "Script started" name="Linux" echo "Learning: $name"
Option Purpose
-e Exit on certain command failures.
-u Report expansion of unset variables.
-o pipefail Report pipeline failures.
Strict mode is a useful starting point, not a guarantee that every error is detected. Use explicit validation, checks and cleanup logic where required.

12. Using trap for Error Handling and Cleanup

The trap command allows a shell script to execute commands when it receives a signal or reaches certain shell events.

Syntax

trap 'commands' SIGNAL

Example 1: Handle Ctrl+C

#!/bin/bash trap 'echo "Interrupt received"; exit 130' INT echo "Press Ctrl+C to interrupt" while true do sleep 1 done

Explanation

  • INT represents the interrupt signal.
  • Ctrl+C normally sends SIGINT to the foreground process group.
  • The trap executes the specified commands when the shell handles the signal.
  • exit 130 terminates the script with a conventional interrupt-related status.

Example 2: Cleanup Temporary File

#!/bin/bash temp_file="/tmp/my_script_temp.txt" cleanup() { echo "Cleaning temporary file..." rm -f "$temp_file" } trap cleanup EXIT echo "Temporary data" > "$temp_file" echo "Temporary file created" echo "Script is running..."

Possible Output

Temporary file created
Script is running...
Cleaning temporary file...
The EXIT trap runs when the shell exits, allowing the script to remove temporary files and perform other cleanup tasks.

13. Writing Error Messages to a Log File

Logging helps developers understand what happened when a script encounters a problem.

Example

#!/bin/bash log_file="script.log" if [ -f "data.txt" ]; then echo "SUCCESS: File found" >> "$log_file" else echo "ERROR: File not found" >> "$log_file" exit 1 fi echo "Check completed"

The >> operator appends messages to the log file rather than replacing its existing content.

Example Log Contents

SUCCESS: File found
ERROR: File not found

14. Practical Program: Validate a Number

This program checks whether the user has entered a valid non-negative integer.

#!/bin/bash read -p "Enter a number: " number if [[ ! "$number" =~ ^[0-9]+$ ]]; then echo "Error: Invalid integer" exit 1 fi echo "Valid number: $number" exit 0

Sample Output 1

Enter a number: 250
Valid number: 250

Sample Output 2

Enter a number: hello
Error: Invalid integer

The regular expression ^[0-9]+$ accepts one or more digits and rejects other characters.

15. Practical Program: Safe File Backup

This program checks whether a source file exists before copying it to a backup file.

#!/bin/bash source_file="data.txt" backup_file="data_backup.txt" if [ ! -f "$source_file" ]; then echo "Error: Source file does not exist" exit 1 fi if cp -- "$source_file" "$backup_file"; then echo "Backup completed successfully" else echo "Error: Backup failed" exit 1 fi exit 0

Possible Output

Backup completed successfully
The -- argument tells cp that subsequent arguments are operands, not options. This helps when filenames begin with a hyphen.

16. Running and Checking a Script

You can inspect a script's exit status from the terminal.

Step 1: Create a Script

nano test_status.sh

Step 2: Enter This Code

#!/bin/bash echo "Testing exit status" exit 0

Step 3: Make the Script Executable

chmod +x test_status.sh

Step 4: Execute the Script

./test_status.sh

Step 5: Check Its Exit Status

echo $?

Output

Testing exit status
0
Run echo $? immediately after the script. If you execute another command first, you may see that command's status instead.

18. Interview Questions and Answers

Q1. What is an exit status?

Answer: It is a numeric value returned by a command or script to indicate its result.

Q2. What does exit status 0 mean?

Answer: It conventionally indicates successful execution.

Q3. What does a non-zero exit status mean?

Answer: It indicates failure or another non-success condition defined by the command.

Q4. What is the purpose of $?

Answer: It stores the exit status of the most recently completed command or relevant shell construct.

Q5. What is the purpose of exit?

Answer: It terminates a shell script and returns an exit status.

Q6. What is stderr?

Answer: Standard error is the output stream used for error messages. Its file descriptor is 2.

Q7. What does set -e do?

Answer: It enables errexit behavior, causing the shell to exit after certain command failures.

Q8. What does set -u do?

Answer: It reports errors when an unset variable is expanded.

Q9. What is pipefail?

Answer: It makes a pipeline return a non-zero status if a command in the pipeline fails.

Q10. What is trap?

Answer: It allows a script to execute specified commands when a signal or shell event occurs.

Q11. What is the difference between && and ||?

Answer: && executes the next command after success; || executes the next command after failure.

Q12. Why is error handling important?

Answer: It helps detect failures, prevent incorrect operations, provide useful messages and make scripts more reliable.

  • Exit status indicates the result of command execution.
  • Zero conventionally represents success.
  • Non-zero statuses indicate a non-success result.
  • $? stores the most recent relevant exit status.
  • exit terminates a script.
  • && and || support conditional command execution.
  • Standard error uses file descriptor 2.
  • set -e enables errexit behavior.
  • set -u detects unset variable expansion.
  • set -o pipefail detects pipeline failures.
  • trap handles signals and cleanup events.
  • Explicit checks make shell scripts more reliable.
