Creating and Executing Shell Scripts

Writing, Saving, Giving Permissions and Running Bash Scripts

Home Linux Course Chapter 8

Learning Objectives

  • Understand how to create a shell script file.
  • Learn to use Nano and other text editors.
  • Understand the shebang line.
  • Learn how to save and verify a script.
  • Understand file permissions required for execution.
  • Learn different methods of executing Bash scripts.
  • Understand script debugging and common errors.

1. Introduction

A shell script is a text file containing Linux commands and shell instructions. To execute a script, we first create the file, write the commands, save it, and run it using an appropriate shell interpreter.

Bash scripts are commonly saved with the .sh extension.

Basic workflow: Create file → Write commands → Save file → Verify content → Execute script → Check output.

2. Creating a Shell Script

Linux provides several text editors for creating shell scripts. A beginner can use Nano because it is simple and terminal-based.

Method 1: Using Nano Editor

Open the terminal and execute:

nano first_script.sh

This opens the Nano text editor. If the file does not exist, Nano creates it when the file is saved.

Method 2: Using Vim Editor

vim first_script.sh

Vim is a powerful terminal-based text editor. Press i to enter insert mode, type the script, press Esc, and type :wq to save and exit.

Method 3: Using a Graphical Text Editor

You can also create a script using a graphical text editor. Save the file with a suitable name such as first_script.sh.

Important: Use a plain-text editor. A word processor that inserts rich-text formatting may produce a file that Bash cannot interpret correctly.

3. Writing Your First Shell Script

Open a new file and write the following Bash script.

#!/bin/bash # My first shell script echo "Welcome to Linux Shell Scripting" echo "This is my first Bash program" date pwd

Explanation

Statement Purpose
#!/bin/bash Specifies Bash as the interpreter for direct execution.
# My first shell script A comment that explains the script.
echo Displays a message on the terminal.
date Displays the system date and time.
pwd Displays the current working directory.

4. Saving a Shell Script in Nano

After writing the script in Nano, follow these steps:

  1. Press Ctrl + O to write the file.
  2. Press Enter to confirm the filename.
  3. Press Ctrl + X to exit Nano.
Remember:
  • Ctrl + O = Save / Write Out
  • Ctrl + X = Exit

5. Verifying the Script File

After saving the script, you can use Linux commands to verify that the file exists and contains the expected instructions.

Check the Current Directory

pwd

List the Script File

ls

Display File Details

ls -l first_script.sh

Display Script Contents

cat first_script.sh
Example output of cat:
#!/bin/bash # My first shell script echo "Welcome to Linux Shell Scripting" echo "This is my first Bash program" date pwd

6. File Permissions for Shell Scripts

Linux uses file permissions to control who can read, modify and execute files.

A script needs execute permission when you want to launch it directly using its path, such as ./first_script.sh.

Permission Categories

Permission Symbol Meaning
Read r Allows reading the file.
Write w Allows modifying the file.
Execute x Allows executing the file as a program, subject to system rules.

Check Existing Permissions

ls -l first_script.sh

Example output:

-rw-r--r-- 1 user user 120 Nov 5 10:00 first_script.sh

The displayed permissions indicate that the owner can read and write the file, while group members and others can read it. No execute permission is currently set.

Add Execute Permission

chmod +x first_script.sh

Verify the permission again:

ls -l first_script.sh
Example output:
-rwxr-xr-x 1 user user 120 Nov 5 10:00 first_script.sh

Understanding chmod +x

Part Meaning
chmod Changes file permissions.
+ Adds a permission.
x Execute permission.
Important: chmod +x adds execute permission for the user, group and others, subject to the file's existing permissions and filesystem restrictions. Use chmod u+x if you only want to add execute permission for the owner.

7. Methods of Executing Shell Scripts

There are different ways to execute a Bash script. The choice determines how the interpreter is selected and whether execute permission is required.

Method 1: Using Bash

bash first_script.sh

Bash reads and executes the script. The script file does not need execute permission for this method.

Method 2: Using sh

sh first_script.sh

This runs the file using the interpreter available through sh. It is suitable for scripts written using compatible shell syntax.

Warning: Do not use sh to execute a Bash-specific script if it relies on Bash features. On Ubuntu, /bin/sh commonly points to Dash, which does not support all Bash syntax.

Method 3: Direct Execution

chmod +x first_script.sh ./first_script.sh

The ./ prefix means that the script is located in the current directory. The operating system uses the shebang to select the interpreter.

Method 4: Using an Absolute Path

/home/user/first_script.sh

This method executes the script using its absolute path, provided that the path is correct and the script has suitable execute permission.

Replace /home/user/ with the actual directory containing your script.

Comparison of Execution Methods

Method Execute Permission Required? Interpreter Selection
bash script.sh No Explicitly uses Bash.
sh script.sh No Explicitly uses sh.
./script.sh Yes Uses the shebang.
Absolute path Yes Uses the shebang.

8. Understanding Relative and Absolute Paths

Relative Path

A relative path specifies the location of a script with respect to the current working directory.

./first_script.sh

Absolute Path

An absolute path specifies the complete location of a script starting from the root directory.

/home/user/scripts/first_script.sh
Relative Path Absolute Path
Depends on the current working directory. Starts from the root directory (/).
Usually shorter. Specifies the complete path.
Example: ./script.sh Example: /home/user/script.sh

9. Executing a Script from Another Directory

You can execute a script without first changing into its directory by specifying its path.

Example Directory Structure

/home/user/ | |-- scripts/ | | | |-- backup.sh | |-- documents/

If you are currently in the documents directory, execute the script using:

../scripts/backup.sh

Alternatively, use its absolute path:

/home/user/scripts/backup.sh
The script must have suitable execute permission for direct execution.

10. Debugging Shell Scripts

Debugging means identifying and correcting errors in a program or script.

Bash provides options that help display commands during execution and detect common scripting errors.

Method 1: Display Commands Before Execution

bash -x first_script.sh

The -x option enables execution tracing. Bash displays commands after expansion as it executes them.

Method 2: Check Syntax Without Executing

bash -n first_script.sh

The -n option reads the script and checks its syntax without executing its commands.

Method 3: Stop on an Unhandled Command Failure

bash -e first_script.sh

This enables Bash's errexit behavior. It exits in certain cases when a command returns a non-zero status. Its behavior has exceptions involving conditions, pipelines and command lists.

Common Debugging Options

Option Purpose
-x Displays commands and expansions during execution.
-n Checks syntax without executing commands.
-v Displays input lines as Bash reads them.
-e Enables errexit behavior for certain command failures.
Important: These options are not a substitute for proper error handling. In particular, set -e does not automatically handle every possible failure scenario.

11. Common Errors in Shell Script Execution

Error 1: Permission Denied

Example:

./first_script.sh

Possible error:

Permission denied

Solution:

chmod +x first_script.sh ./first_script.sh

Error 2: No Such File or Directory

This usually occurs when the filename or path is incorrect, or when the interpreter specified in the shebang is unavailable.

Check the current directory:

pwd ls

Error 3: Command Not Found

This can occur when a command is misspelled or its executable cannot be located through PATH.

Example:

ech "Hello Linux"

Correct command:

echo "Hello Linux"

Error 4: Bad Interpreter

This may occur if the interpreter path in the shebang is invalid or the script has incompatible line endings.

Check the first line:

head -n 1 first_script.sh

Expected Bash shebang:

#!/bin/bash

Error 5: Windows Line Endings

A script created or edited in Windows may contain CRLF line endings instead of Linux-style LF endings. This can cause interpreter-related errors.

Check the file type:

file first_script.sh

If necessary, convert line endings:

dos2unix first_script.sh
If dos2unix is not installed, install it using your Linux distribution's package manager or save the file with Unix (LF) line endings in your editor.

12. Practical Lab 1: Create and Execute a Welcome Script

Objective: Create a Bash script and execute it using two different methods.

Step 1: Create the File

nano welcome.sh

Step 2: Write the Code

#!/bin/bash echo "==============================" echo "Welcome to NS Learning Hub" echo "Linux Shell Scripting Course" echo "==============================" echo "Current User:" whoami echo "Current Directory:" pwd

Step 3: Save and Exit

Press Ctrl + O, Enter, and Ctrl + X.

Step 4: Execute Using Bash

bash welcome.sh

Step 5: Add Execute Permission

chmod +x welcome.sh

Step 6: Execute Directly

./welcome.sh
Expected output format:
============================== Welcome to NS Learning Hub Linux Shell Scripting Course ============================== Current User: [Username] Current Directory: [Directory path]

13. Practical Lab 2: Execute a Script Using an Absolute Path

Objective: Execute a shell script from a different working directory.

Step 1: Create a Scripts Directory

mkdir -p ~/scripts

Step 2: Create a Script

nano ~/scripts/message.sh

Step 3: Write the Code

#!/bin/bash echo "Script executed successfully" echo "Current working directory:" pwd

Step 4: Add Execute Permission

chmod +x ~/scripts/message.sh

Step 5: Change to Another Directory

cd /tmp

Step 6: Execute Using Absolute Path

~/scripts/message.sh
Expected output:
Script executed successfully Current working directory: /tmp

Notice that the script's current working directory remains /tmp. Executing a script does not automatically change the caller's working directory.

15. Interview Questions and Answers

Q1. How do you create a shell script in Linux?

Use a text editor such as Nano or Vim, create a file with a suitable name, and write the shell commands inside it.

Q2. Is execute permission necessary to run a script?

Execute permission is necessary for direct execution using the script path. It is not required when the script is passed as input to an interpreter such as bash script.sh.

Q3. What does chmod +x do?

It adds execute permission for the user, group and others, subject to existing permissions and system rules.

Q4. What is the difference between bash script.sh and ./script.sh?

The first explicitly invokes Bash. The second directly executes the file and uses its shebang to select the interpreter.

Q5. What is the purpose of bash -x?

It enables execution tracing and displays commands as Bash executes them.

Q6. What is the purpose of bash -n?

It checks the syntax of a Bash script without executing its commands.

Q7. Why can a script show Permission denied?

The script may lack execute permission, or execution may be restricted by filesystem or security settings.

Q8. What is the purpose of the .sh extension?

It is a common naming convention that indicates a shell script. It is not compulsory.

Q9. Can we execute a shell script from another directory?

Yes. We can use its relative or absolute path, provided the required permissions and interpreter are available.

Q10. What is the difference between chmod u+x and chmod +x?

chmod u+x adds execute permission only for the file owner. chmod +x adds execute permission for the owner, group and others.

17. Lesson Summary

  • Shell scripts are created using text editors such as Nano and Vim.
  • A Bash script commonly starts with #!/bin/bash.
  • The .sh extension is a convention, not a requirement.
  • Use cat and ls -l to inspect a script.
  • Use chmod +x to add execute permission.
  • Use bash script.sh to execute through Bash.
  • Use ./script.sh for direct execution.
  • Use bash -x for execution tracing.
  • Use bash -n for syntax checking.
  • Correct file paths, permissions and line endings to avoid common errors.
