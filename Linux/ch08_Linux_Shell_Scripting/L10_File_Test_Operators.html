File Test Operators

Checking File Existence, Types and Permissions in Bash

1. Introduction to File Test Operators

File test operators are conditional expressions used in shell scripts to check properties of files and directories. They help determine whether a file exists, what type of file it is, and whether the current user has particular permissions.

These operators are commonly used with the if, elif and else statements.

Why Are File Test Operators Used?

  • Verify whether a file exists before opening it.
  • Check whether a directory is available.
  • Verify file permissions before performing an operation.
  • Prevent errors when working with files.
  • Automate file and directory management tasks.
Example: Before reading a configuration file, a shell script can check whether that file exists using the -e operator.

2. Basic Syntax of File Test Operators

Syntax 1: Using Single Square Brackets

if [ -e filename ] then echo "File exists" else echo "File does not exist" fi

Syntax 2: Using Double Square Brackets

if [[ -e filename ]] then echo "File exists" else echo "File does not exist" fi

Both forms are supported by Bash. The double-bracket form is a Bash conditional construct and provides additional features.

Important: Spaces around the test expression are required when using single square brackets. Write [ -e "$file" ], not [-e "$file"].

3. File Existence Operators

These operators check whether a specified path exists or whether it refers to a particular file type.

Operator Description
-e True if the path exists.
-f True if the path is a regular file.
-d True if the path is a directory.
-L or -h True if the path is a symbolic link.

Example 1: Check Whether a Path Exists

#!/bin/bash file="sample.txt" if [ -e "$file" ]; then echo "Path exists" else echo "Path does not exist" fi

Possible Output

Path exists

This output appears only if sample.txt exists in the current working directory.

Example 2: Check Whether It Is a Regular File

#!/bin/bash file="sample.txt" if [ -f "$file" ]; then echo "It is a regular file" else echo "It is not a regular file" fi

Possible Output

It is a regular file

Example 3: Check Whether It Is a Directory

#!/bin/bash directory="Documents" if [ -d "$directory" ]; then echo "Directory exists" else echo "Directory does not exist" fi

Possible Output

Directory exists
Note: These outputs depend on the actual paths available in the current working directory. Use an absolute path when you need to check a specific location.

4. File Permission Test Operators

Permission test operators check whether the current process has permission to perform an operation on a path.

Operator Description
-r True if the path exists and is readable.
-w True if the path exists and is writable.
-x True if the path exists and is executable or searchable.

Example 1: Check Read Permission

#!/bin/bash file="sample.txt" if [ -r "$file" ]; then echo "File is readable" else echo "File is not readable" fi

Example 2: Check Write Permission

#!/bin/bash file="sample.txt" if [ -w "$file" ]; then echo "File is writable" else echo "File is not writable" fi

Example 3: Check Execute Permission

#!/bin/bash file="script.sh" if [ -x "$file" ]; then echo "Executable permission is available" else echo "Executable permission is not available" fi
Important distinction: For a regular file, -x checks execute permission. For a directory, it checks search/traversal permission.

5. File Size Test Operators

Operator Description
-s True if the file exists and has a size greater than zero.

Example: Check Whether a File Is Empty

#!/bin/bash file="data.txt" if [ -s "$file" ]; then echo "File is not empty" else echo "File is empty or does not exist" fi

Possible Output

File is not empty

If the file exists and contains data, the -s test returns true.

Note: An empty file and a nonexistent file both make -s return false. Use -e separately if you need to distinguish between these cases.

6. Special File Type Operators

Linux supports different file types. Bash provides operators to test several special file types.

Operator Description
-b Block special file.
-c Character special file.
-p Named pipe (FIFO).
-S Socket file.

Example: Check for a Block Device

#!/bin/bash device="/dev/sda" if [ -b "$device" ]; then echo "Block device found" else echo "Not a block device" fi

The output depends on whether the specified path is a block special file. Device names differ between systems.

Example: Check for a Character Device

#!/bin/bash device="/dev/null" if [ -c "$device" ]; then echo "Character device found" else echo "Not a character device" fi

Output on a Typical Linux System

Character device found

7. File Ownership and Modification Operators

Operator Description
-O True if the file is owned by the effective user ID.
-G True if the file is owned by the effective group ID.
-N True if the file has been modified since it was last read.

Example: Check File Ownership

#!/bin/bash file="sample.txt" if [ -O "$file" ]; then echo "File is owned by the effective user" else echo "File is not owned by the effective user" fi

Example: Check Modification Status

#!/bin/bash file="sample.txt" if [ -N "$file" ]; then echo "File was modified since it was last read" else echo "File is not newer than its last-read status" fi
Note: The result of -N depends on file access and modification timestamps.

8. Comparing Two Files

Bash provides operators to compare the modification timestamps of two files.

Operator Description
file1 -nt file2 True if file1 is newer than file2.
file1 -ot file2 True if file1 is older than file2.
file1 -ef file2 True if both paths refer to the same file (same device and inode).

Example: Check Which File Is Newer

#!/bin/bash file1="file1.txt" file2="file2.txt" if [ "$file1" -nt "$file2" ]; then echo "File 1 is newer" elif [ "$file1" -ot "$file2" ]; then echo "File 1 is older" else echo "Files have equal modification times" fi

Both files should exist for a meaningful timestamp comparison. The result depends on their actual modification times.

Example: Check Whether Two Paths Refer to the Same File

#!/bin/bash if [ "sample.txt" -ef "./sample.txt" ]; then echo "Both paths refer to the same file" else echo "They refer to different files" fi

9. Combining Multiple File Test Conditions

Multiple file tests can be combined using logical operators such as && and ||.

Example: Check Whether a File Exists and Is Readable

#!/bin/bash file="sample.txt" if [ -f "$file" ] && [ -r "$file" ]; then echo "Regular file exists and is readable" else echo "File is missing, not regular, or not readable" fi

Example: Check Whether a File Exists or a Directory Exists

#!/bin/bash if [ -f "sample.txt" ] || [ -d "Documents" ]; then echo "At least one condition is true" else echo "Neither condition is true" fi
Explanation:
  • && means logical AND.
  • || means logical OR.
  • AND requires both conditions to be true.
  • OR requires at least one condition to be true.

10. Practical File Test Programs

Program 1: Check Whether a File Exists

#!/bin/bash read -p "Enter filename: " file if [ -e "$file" ]; then echo "File or path exists" else echo "File or path does not exist" fi

Program 2: Check File Type

#!/bin/bash read -p "Enter path: " path if [ -f "$path" ]; then echo "Regular file" elif [ -d "$path" ]; then echo "Directory" elif [ -L "$path" ]; then echo "Symbolic link" elif [ -e "$path" ]; then echo "Other existing file type" else echo "Path does not exist" fi
Important: A symbolic link to an existing file can also satisfy -f or -d. In this example, the -L check comes after those tests. To identify symbolic links first, check -L before -f and -d.

Program 3: Check File Permissions

#!/bin/bash read -p "Enter filename: " file if [ -e "$file" ]; then [ -r "$file" ] && echo "Readable" [ -w "$file" ] && echo "Writable" [ -x "$file" ] && echo "Executable or searchable" else echo "Path does not exist" fi

Program 4: Check Whether a File Is Empty

#!/bin/bash read -p "Enter filename: " file if [ ! -e "$file" ]; then echo "File does not exist" elif [ -s "$file" ]; then echo "File contains data" else echo "File is empty" fi

Program 5: Create a File If It Does Not Exist

#!/bin/bash file="newfile.txt" if [ -e "$file" ]; then echo "File already exists" else touch "$file" echo "File created successfully" fi

Program 6: Check Whether a Directory Exists

#!/bin/bash read -p "Enter directory name: " directory if [ -d "$directory" ]; then echo "Directory exists" else echo "Directory does not exist" fi

11. Running File Test Scripts in Ubuntu

Follow these steps to execute a Bash script.

Step 1: Create a Script

nano file_test.sh

Step 2: Write the Script

#!/bin/bash file="sample.txt" if [ -e "$file" ]; then echo "File exists" else echo "File does not exist" fi

Step 3: Save the File

In Nano, press Ctrl + O, Enter, and then Ctrl + X.

Step 4: Give Execute Permission

chmod +x file_test.sh

Step 5: Execute the Script

./file_test.sh

Expected Output

File does not exist

This output appears if sample.txt is absent from the current directory.

Tip: Create a test file with touch sample.txt and run the script again to observe the other result.

14. Interview Questions and Answers

Q1. What are file test operators in Bash?

Answer: They are conditional operators used to check file properties such as existence, type, size and permissions.

Q2. Which operator checks whether a path exists?

Answer: The -e operator.

Q3. What is the difference between -e and -f?

Answer: -e checks whether a path exists, whereas -f checks whether it is a regular file.

Q4. Which operator checks a directory?

Answer: The -d operator.

Q5. Which operator checks read permission?

Answer: The -r operator.

Q6. Which operator checks whether a file is empty?

Answer: The -s operator returns true for a non-empty file. It returns false for an empty file or a nonexistent path.

Q7. What is the purpose of -L?

Answer: It checks whether a path is a symbolic link.

Q8. What is the difference between -b and -c?

Answer: -b checks block special files, while -c checks character special files.

Q9. What does -nt mean?

Answer: It checks whether one file has a newer modification timestamp than another.

Q10. Why are quotes used around filenames?

Answer: Quoting prevents word splitting and pathname expansion, allowing filenames containing spaces or special characters to be handled safely.

16. Lesson Summary

  • File test operators check file and directory properties.
  • -e checks whether a path exists.
  • -f checks regular files.
  • -d checks directories.
  • -L checks symbolic links.
  • -r, -w and -x check permissions.
  • -s checks whether a file has non-zero size.
  • Special operators identify block devices, character devices, pipes and sockets.
  • -nt and -ot compare file modification times.
  • File tests are commonly combined with conditional statements.
