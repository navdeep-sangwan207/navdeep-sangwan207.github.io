Command-Line Arguments in Shell Scripting

Passing information to Bash scripts using positional parameters

Home Linux Course Chapter 8

Learning Objectives

After completing this lesson, you will be able to:

  • Understand command-line arguments in Bash.
  • Use positional parameters such as $0, $1 and $2.
  • Understand $# and the difference between $@ and $*.
  • Pass arguments while executing a shell script.
  • Use shift to process arguments sequentially.
  • Validate the number of arguments.
  • Handle arguments containing spaces correctly.
  • Develop practical Bash scripts using command-line arguments.

1. Introduction to Command-Line Arguments

Command-line arguments are values passed to a program or shell script when it is executed from the terminal.

They allow users to provide input without modifying the script or entering information interactively.

Example

./student.sh Navdeep 25 Chandigarh

In this example, three arguments are passed to the script:

  • Navdeep – First argument.
  • 25 – Second argument.
  • Chandigarh – Third argument.
Bash stores command-line arguments in special variables called positional parameters.

2. Positional Parameters in Bash

Positional parameters are special shell variables that represent the arguments supplied to a shell script or function.

Parameter Description
$0 Name or invocation path of the script.
$1 First command-line argument.
$2 Second command-line argument.
$3 Third command-line argument.
$# Number of positional arguments.
$@ All positional arguments, treated separately when quoted.
$* All positional arguments; when quoted, normally combined into one word using the first character of IFS.
$$ Process ID of the current Bash shell.
$? Exit status of the most recently executed command.
Note: $0 identifies the script invocation. It is not counted in $#, which counts only the positional arguments.

3. Using $0, $1, $2 and $3

Create a script named student.sh.

Program

#!/bin/bash echo "Script Name: $0" echo "Student Name: $1" echo "Age: $2" echo "City: $3"

Execute the script

chmod +x student.sh ./student.sh Navdeep 25 Chandigarh
Expected output:
Script Name: ./student.sh Student Name: Navdeep Age: 25 City: Chandigarh
$0 may appear differently depending on how the script is invoked.

Explanation

  • $0 represents the script invocation name or path.
  • $1 receives Navdeep.
  • $2 receives 25.
  • $3 receives Chandigarh.

4. Using $# to Count Arguments

The $# parameter returns the number of positional arguments passed to the script.

Program

#!/bin/bash echo "Number of arguments: $#"

Execute

./count.sh Linux Ubuntu Bash
Expected output:
Number of arguments: 3

Check whether arguments were provided

#!/bin/bash if [ "$#" -eq 0 ]; then echo "No arguments provided." else echo "Arguments provided: $#" fi

Run:

./count.sh ./count.sh Linux Ubuntu
Expected output:
No arguments provided. Arguments provided: 2

5. Using $@ to Access All Arguments

The $@ parameter represents all positional arguments.

Program

#!/bin/bash echo "All arguments: $@" for arg in "$@" do echo "Argument: $arg" done

Execute

./arguments.sh Linux Ubuntu Bash
Expected output:
All arguments: Linux Ubuntu Bash Argument: Linux Argument: Ubuntu Argument: Bash
Quoted "$@" expands each positional argument as a separate word. This is especially important when arguments contain spaces.

6. Difference Between $@ and $*

Both parameters represent all positional arguments, but their behavior differs when quoted.

Feature "$@" "$*"
Expansion Separate word for each argument Normally one combined word
Preserves argument boundaries Yes No
Best use Passing arguments to commands or loops Combining arguments into one string

Program

#!/bin/bash echo "Using quoted at:" for arg in "$@" do echo "[$arg]" done echo "Using quoted star:" for arg in "$*" do echo "[$arg]" done

Execute

./compare.sh "Linux Programming" Ubuntu Bash
Expected output:
Using quoted at: [Linux Programming] [Ubuntu] [Bash] Using quoted star: [Linux Programming Ubuntu Bash]
Important: When quoted, "$@" preserves each argument as a separate word. "$*" joins the arguments into one word using the first character of IFS, which is normally a space.

7. Handling Arguments Containing Spaces

An argument containing spaces should be enclosed in quotes when executing the script.

Program

#!/bin/bash echo "First argument: $1" echo "Second argument: $2" echo "Total arguments: $#"

Execute correctly

./student.sh "Navdeep Sangwan" Chandigarh
Expected output:
First argument: Navdeep Sangwan Second argument: Chandigarh Total arguments: 2

Execute without quotes

./student.sh Navdeep Sangwan Chandigarh
Expected output:
First argument: Navdeep Second argument: Sangwan Total arguments: 3

Without quotes, Bash performs word splitting and treats the separate words as separate arguments.

8. Using shift Command

The shift command removes positional parameters from the beginning of the current positional parameter list and shifts the remaining arguments to lower positions.

Syntax

shift shift n

Here, n specifies the number of positions to shift. If omitted, one position is shifted.

Program

#!/bin/bash echo "Before shift:" echo "First argument: $1" echo "Second argument: $2" shift echo "After shift:" echo "First argument: $1" echo "Second argument: $2"

Execute

./shift_demo.sh Linux Ubuntu Bash
Expected output:
Before shift: First argument: Linux Second argument: Ubuntu After shift: First argument: Ubuntu Second argument: Bash

Using shift in a loop

#!/bin/bash while [ "$#" -gt 0 ] do echo "Argument: $1" shift done

Execute:

./shift_loop.sh Linux Ubuntu Bash
Expected output:
Argument: Linux Argument: Ubuntu Argument: Bash
Note: shift changes positional parameters in the current shell or function context. In a script, it does not modify the positional parameters of the shell that launched the script.

9. Validating Command-Line Arguments

Argument validation ensures that a script receives the required number of arguments before performing an operation.

Example: Require two arguments

#!/bin/bash if [ "$#" -ne 2 ]; then echo "Usage: $0 name city" exit 1 fi name="$1" city="$2" echo "Name: $name" echo "City: $city"

Execute with correct arguments

./validate.sh Navdeep Chandigarh
Expected output:
Name: Navdeep City: Chandigarh

Execute with incorrect arguments

./validate.sh Navdeep
Expected output:
Usage: ./validate.sh name city

The exit 1 command terminates the script with a non-zero exit status to indicate an error.

10. Special Parameters: $$ and $?

$$ – Current shell process ID

The $$ parameter expands to the process ID of the current Bash shell.

echo "Current Shell PID: $$"

Example output:

Current Shell PID: 2450

The process ID shown is system-dependent.

$? – Exit status of the last command

The $? parameter stores the exit status of the most recently executed command.

ls echo "$?" invalid_command echo "$?"
Typical expected output:
0 bash: invalid_command: command not found 127
The first status is normally 0 if ls succeeds. The second is normally 127 when Bash cannot find the command.
Exit status convention:
  • 0 generally indicates success.
  • Non-zero values generally indicate an error or another condition.

11. Practical Lab Exercises

Lab 1: Student details using arguments

Objective: Accept student information through command-line arguments.

#!/bin/bash if [ "$#" -ne 3 ]; then echo "Usage: $0 name course city" exit 1 fi echo "Student Name: $1" echo "Course: $2" echo "City: $3" echo "Total Arguments: $#"

Execute:

./student_details.sh "Navdeep Sangwan" "Embedded Systems" Chandigarh

Expected Result:

Student Name: Navdeep Sangwan Course: Embedded Systems City: Chandigarh Total Arguments: 3

Lab 2: Addition of two numbers

Objective: Perform arithmetic using two command-line arguments.

#!/bin/bash if [ "$#" -ne 2 ]; then echo "Usage: $0 number1 number2" exit 1 fi if [[ ! "$1" =~ ^-?[0-9]+$ || ! "$2" =~ ^-?[0-9]+$ ]]; then echo "Error: Please provide two integers." exit 1 fi num1=$1 num2=$2 sum=$((num1 + num2)) echo "First Number: $num1" echo "Second Number: $num2" echo "Sum: $sum"

Execute:

./addition.sh 25 15

Expected Result:

First Number: 25 Second Number: 15 Sum: 40

Lab 3: Display all arguments using shift

Objective: Process arguments one by one using shift.

#!/bin/bash if [ "$#" -eq 0 ]; then echo "Please provide at least one argument." exit 1 fi count=1 while [ "$#" -gt 0 ] do echo "Argument $count: $1" count=$((count + 1)) shift done

Execute:

./display_args.sh Linux Bash Ubuntu

Expected Result:

Argument 1: Linux Argument 2: Bash Argument 3: Ubuntu

12. Common Mistakes

Mistake Correct Approach
Forgetting quotes around arguments containing spaces. Use quotes when invoking the script.
Using $# as the first argument. Use $1 for the first argument.
Using unquoted $@ when argument boundaries matter. Use "$@".
Assuming $0 is counted in $#. $# counts only positional arguments.
Using shift without checking the argument count. Check $# before processing arguments.
Assuming command-line inputs are always valid numbers. Validate input before arithmetic.

13. Interview Questions and Answers

Q1. What are command-line arguments?

Answer: Values passed to a script or program when it is executed from the command line.

Q2. What is a positional parameter?

Answer: A special shell parameter that represents an argument based on its position.

Q3. What is the purpose of $0?

Answer: It represents the script's invocation name or path.

Q4. What does $1 represent?

Answer: It represents the first positional argument.

Q5. What does $# represent?

Answer: It gives the number of positional arguments.

Q6. What is the difference between $@ and $*?

Answer: When quoted, "$@" preserves separate arguments, while "$*" combines them into one word.

Q7. What is the purpose of shift?

Answer: It removes one or more positional parameters from the beginning of the argument list and shifts the remaining parameters.

Q8. What does $$ represent?

Answer: It represents the process ID of the current Bash shell.

Q9. What does $? represent?

Answer: It represents the exit status of the most recently executed command.

Q10. How can you check whether a script received exactly two arguments?

Answer: Use if [ "$#" -ne 2 ] to detect an incorrect argument count.

14. Multiple Choice Questions (MCQs)

Q1. Which parameter represents the first command-line argument?

A. $0
B. $1
C. $#
D. $*

Answer: B. $1

Q2. Which parameter counts positional arguments?

A. $@
B. $0
C. $#
D. $$

Answer: C. $#

Q3. Which parameter represents the script invocation name?

A. $0
B. $1
C. $?
D. $@

Answer: A. $0

Q4. Which expansion preserves separate arguments when quoted?

A. "$*"
B. "$@"
C. "$#"
D. "$0"

Answer: B. "$@"

Q5. Which command shifts positional parameters?

A. export
B. unset
C. shift
D. read

Answer: C. shift

Q6. What does $$ represent?

A. Number of arguments
B. Current shell PID
C. First argument
D. Exit status

Answer: B. Current shell PID

Q7. What does $? represent?

A. Last command's exit status
B. Script name
C. Number of arguments
D. Current directory

Answer: A. Last command's exit status

Q8. How many arguments are passed in this command?

A. 1
B. 2

Answer: B. 2

15. Lesson Summary

  • Command-line arguments provide input when a Bash script is executed.
  • $0 represents the script invocation name or path.
  • $1, $2 and $3 represent positional arguments.
  • $# counts positional arguments.
  • "$@" preserves each argument separately.
  • "$*" combines arguments into one word when quoted.
  • shift moves positional parameters.
  • $$ represents the current Bash shell PID.
  • $? stores the most recent command's exit status.
  • Argument validation improves script reliability.
