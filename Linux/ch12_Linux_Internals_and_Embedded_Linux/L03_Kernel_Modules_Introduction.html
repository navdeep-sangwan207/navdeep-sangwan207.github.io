Kernel Modules Introduction

Understand Linux kernel modules, their structure, purpose, advantages, dependencies and basic module management commands.

1. Introduction to Kernel Modules

A Linux kernel module is a piece of code that can be loaded into or removed from a running Linux kernel, subject to kernel configuration and security restrictions.

Kernel modules allow additional functionality to be added without rebuilding the entire kernel. Device drivers are one of the most common types of kernel modules.

Definition: A kernel module is a dynamically loadable component of the Linux kernel that extends kernel functionality at runtime.

Examples

  • USB device drivers.
  • Network interface drivers.
  • Filesystem modules.
  • Sound device drivers.
  • Bluetooth drivers.
  • Other kernel extensions.

2. Why Are Kernel Modules Required?

A Linux system supports many types of hardware and software features. Loading every possible driver and feature permanently into the kernel is not always necessary.

Kernel modules allow the system to load additional functionality when it is required.

Main Reasons

  • Support different hardware devices.
  • Extend kernel functionality.
  • Reduce the need to compile every feature into the kernel.
  • Allow supported drivers to be added or removed at runtime.
  • Simplify kernel development and testing.

3. Built-in Kernel Components vs Loadable Modules

Linux kernel functionality can be compiled directly into the kernel or built as a loadable module.

Built-in Component Loadable Kernel Module
Compiled into the kernel image. Compiled as a separate module file.
Available as part of the running kernel. Can be loaded when required.
Cannot be unloaded independently. Can often be unloaded when no longer in use.
Does not need a separate module file. Usually stored as a .ko file.
Kernel configuration commonly represents built-in functionality with y and loadable module functionality with m.

4. What is a .ko File?

A loadable Linux kernel module is commonly stored in a file with the extension .ko. KO stands for kernel object.

Example Module Files

hello_module.ko
usb_storage.ko
e1000e.ko
snd_hda_intel.ko

Module files are normally installed under a kernel-version-specific directory. 

/lib/modules/<kernel-version>/

Inspect the Current Kernel Module Directory

uname -r

ls /lib/modules/$(uname -r)/

The directory may contain subdirectories such as kernel/, updates/, extra/ and modules-related dependency information.

5. Types of Kernel Modules

1. Device Driver Modules

Device driver modules allow the kernel to communicate with supported hardware.

Examples:

  • USB drivers.
  • Network drivers.
  • Audio drivers.
  • Storage drivers.

2. Filesystem Modules

Filesystem modules provide support for different filesystem formats.

Examples include ext4, FAT and other supported filesystems.

3. Networking Modules

Networking modules provide support for network protocols, interfaces and related functionality.

4. Other Kernel Extensions

Additional modules can implement or extend specific kernel functionality depending on kernel configuration.

Kernel modules execute with kernel privileges. A faulty module can corrupt kernel memory, cause a kernel panic or make the system unstable.

7. Kernel Module Loading and Unloading

Linux provides commands to inspect, load and unload kernel modules.

Important Commands

Command Purpose
lsmod Lists currently loaded modules.
insmod Inserts a specified module file.
rmmod Removes a loaded module.
modprobe Loads or removes modules while handling dependencies.
modinfo Displays module information.
depmod Generates module dependency information.

Detailed loading and unloading procedures are covered in the next lesson.

8. Understanding lsmod

The lsmod command displays currently loaded kernel modules. 

lsmod

Example Output

Module                  Size  Used by
nls_iso8859_1           12288  1
snd_hda_intel           61440  2
snd_hda_codec          204800  1 snd_hda_intel
usb_storage             81920  1

Actual output varies depending on the kernel, hardware and loaded modules.

Output Columns

Column Meaning
Module Name of the loaded module.
Size Module size in bytes.
Used by Usage count and dependent module information.

9. Understanding modinfo

The modinfo command displays information about a kernel module.

Syntax

modinfo module_name

Example

modinfo loop

The loop module supports loop devices, which allow regular files to be used as block devices.

Common Information Fields

  • filename
  • description
  • author
  • license
  • depends
  • alias
  • vermagic
The vermagic field contains kernel-version and build-related compatibility information. A module generally needs to match the running kernel's ABI and build configuration.

10. Kernel Module Dependencies

Some modules depend on other modules or kernel components to operate correctly.

For example, a hardware-specific driver may depend on a common subsystem or helper module.

Dependency Management

The modprobe command uses module dependency information to load required dependencies. 

modprobe module_name

Dependency information is maintained using files generated by depmod. 

sudo depmod -a
Difference: insmod inserts a specified module file without automatically resolving its dependencies. modprobe normally resolves and loads dependencies using the installed module information.

11. Advantages of Kernel Modules

  • Extend kernel functionality at runtime.
  • Support a wide range of hardware devices.
  • Allow optional features to be loaded when needed.
  • Make driver development and testing more flexible.
  • Reduce the need to rebuild the complete kernel for every supported feature.
  • Help organize kernel functionality into separate components.

12. Limitations and Risks

  • A faulty module can crash the kernel.
  • Modules must be compatible with the running kernel.
  • Module dependencies must be satisfied.
  • Kernel security policies may restrict module loading.
  • Some modules cannot be unloaded while in use.
  • Kernel module development requires careful testing.
Never load an unknown or untrusted kernel module. Test your own modules in a disposable virtual machine or snapshot of your Ubuntu guest.

13. Practical Linux Commands

Display Loaded Modules

lsmod

Search for a Module

lsmod | grep loop

Display Module Information

modinfo loop

Check Module Files for the Running Kernel

ls /lib/modules/$(uname -r)/

Search Available Module Names

find /lib/modules/$(uname -r)/kernel \
-type f -name '*.ko*'

Display Module Dependencies

modprobe --show-depends loop

These commands inspect existing modules and module information. They do not require you to create or insert a new kernel module.

15. Interview Questions and Answers

Q1. What is a Linux kernel module?

A kernel module is a loadable component that extends Linux kernel functionality at runtime.

Q2. What is the extension of a Linux kernel module?

The common extension is .ko, meaning kernel object.

Q3. Why are kernel modules used?

They allow additional kernel functionality, including device drivers, to be loaded when required.

Q4. What is the difference between a built-in component and a module?

A built-in component is compiled into the kernel image. A loadable module is built separately and can be loaded at runtime.

Q5. What is lsmod?

lsmod displays the kernel modules currently loaded into the running kernel.

Q6. What is modinfo?

modinfo displays information about a kernel module.

Q7. What is the difference between insmod and modprobe?

insmod inserts a specified module file. modprobe normally resolves dependencies and loads the required modules.

Q8. What is rmmod?

rmmod requests removal of a loaded kernel module. Removal can fail if the module is in use or otherwise cannot be unloaded.

Q9. What is depmod?

depmod generates module dependency and mapping information used by module-management tools.

Q10. Can a kernel module crash Linux?

Yes. Since modules execute with kernel privileges, programming errors can corrupt kernel state or cause a kernel panic.

Q11. Where are kernel modules stored?

They are commonly stored under /lib/modules/kernel-version/.

Q12. What is vermagic?

vermagic is module metadata used to help identify kernel-version and build compatibility.

  • A kernel module extends Linux kernel functionality.
  • Modules can be loaded and removed at runtime when supported.
  • Loadable kernel modules commonly use the .ko extension.
  • Device drivers are common examples of kernel modules.
  • Built-in components are compiled into the kernel image.
  • lsmod lists loaded modules.
  • modinfo displays module information.
  • insmod inserts a specified module file.
  • modprobe normally resolves dependencies.
  • depmod generates module dependency information.
