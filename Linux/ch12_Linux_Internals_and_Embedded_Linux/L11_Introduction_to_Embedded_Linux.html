Introduction to Embedded Linux

Understand Embedded Linux architecture, hardware platforms, kernel, bootloader, root filesystem and embedded development.

1. What Is Embedded Linux?

Embedded Linux is a Linux-based operating system configured to run on embedded devices and dedicated hardware platforms.

Unlike a general-purpose desktop system, an embedded Linux system is usually designed for a specific product or set of functions.

Examples include:

  • Industrial automation controllers.
  • Smart televisions.
  • Network routers and switches.
  • Automotive infotainment systems.
  • Medical equipment.
  • Smart cameras and surveillance systems.
  • IoT gateways.
  • Robotics and machine-control systems.
Definition: Embedded Linux is a customized Linux operating system designed to run on an embedded hardware platform and perform dedicated application tasks.

2. Embedded Linux vs Desktop Linux

Feature Desktop Linux Embedded Linux
Purpose General-purpose computing Dedicated product functions
Hardware PC or laptop Embedded boards and SoCs
Resources Usually more resources Often resource-constrained
User Interface Often full desktop environment May use GUI, CLI or no display
Configuration General-purpose distribution Customized for the product
Boot Time Usually less strictly constrained May require optimized boot time
Storage SSD or HDD eMMC, NAND, NOR, SD card or SSD

Both use the Linux kernel. Their configuration, applications, hardware and resource requirements are different.

3. Embedded Linux System Architecture

A typical Embedded Linux system consists of hardware, boot firmware, a bootloader, the Linux kernel, a root filesystem and application software. 

       +-----------------------------+
       |     User Applications       |
       |  Control / GUI / IoT Apps   |
       +-----------------------------+
       |      System Libraries       |
       +-----------------------------+
       |       Root Filesystem       |
       |  BusyBox / Shell / Config   |
       +-----------------------------+
       |        Linux Kernel        |
       | Drivers / Memory / Network  |
       +-----------------------------+
       |        Bootloader           |
       |            U-Boot           |
       +-----------------------------+
       |      Hardware Platform      |
       | CPU / RAM / Flash / Devices |
       +-----------------------------+

Main Components

  1. Hardware: Processor, memory and peripherals.
  2. Bootloader: Initializes hardware and loads the kernel.
  3. Linux Kernel: Manages hardware, processes, memory and drivers.
  4. Root Filesystem: Provides system libraries, utilities and configuration.
  5. Applications: Perform the product's required functions.

4. Embedded Linux Hardware Platforms

Embedded Linux commonly runs on microprocessor-based platforms and System-on-Chip (SoC) devices.

A. Microprocessor

A microprocessor executes instructions and normally relies on external memory and peripherals, depending on the design.

B. System-on-Chip (SoC)

An SoC integrates several system components into a single chip.

Typical SoC components include:

  • CPU cores.
  • Memory controllers.
  • UART controllers.
  • SPI and I2C controllers.
  • GPIO controllers.
  • Ethernet or USB controllers.
  • Timers and interrupt controllers.

C. Development Boards

Development boards provide a convenient platform for learning and testing Embedded Linux.

  • Raspberry Pi boards.
  • BeagleBone boards.
  • NXP i.MX evaluation boards.
  • TI Sitara development platforms.
  • Other ARM-based development boards.

5. Bootloader in Embedded Linux

A bootloader is software that runs before the operating system kernel. It prepares the platform and loads the Linux kernel.

Common Bootloader: U-Boot

U-Boot (Das U-Boot) is a widely used open-source bootloader in embedded systems.

Responsibilities

  • Initialize essential hardware.
  • Configure memory and clocks as required.
  • Load the Linux kernel.
  • Load or locate the device tree.
  • Pass boot arguments to the kernel.
  • Transfer control to the kernel.

Example U-Boot Commands

printenv
help
bdinfo
version
boot

The actual available commands depend on the bootloader configuration.

6. Linux Kernel in Embedded Systems

The Linux kernel manages the hardware and provides core operating-system services to applications.

Important Kernel Responsibilities

  • Process scheduling.
  • Memory management.
  • Interrupt handling.
  • Device-driver management.
  • File-system support.
  • Networking.
  • Interprocess communication.
  • Security and access control.

Embedded Device Drivers

Drivers allow the kernel to communicate with platform hardware.

Interface Typical Application
UART Serial communication and console.
I2C Sensors and EEPROM devices.
SPI Displays, flash memory and peripherals.
GPIO Digital input and output.
CAN Automotive and industrial communication.
Ethernet Network communication.

7. Root Filesystem

The root filesystem is the filesystem mounted at the root directory (/). It contains the files and directories needed to run the Linux userspace.

Common Directories

Directory Purpose
/bin Essential user commands (may be linked to /usr/bin).
/sbin System administration commands (layout varies).
/etc System configuration.
/dev Device nodes.
/proc Process and kernel information.
/sys Kernel device and subsystem information.
/lib Essential shared libraries and kernel modules (layout varies).
/var Variable data such as logs.
/tmp Temporary files.

Common Embedded Root Filesystem Components

  • Shell.
  • BusyBox utilities.
  • C library.
  • System initialization program.
  • Configuration files.
  • Device nodes and mount points.
  • Application binaries.

8. BusyBox

BusyBox combines many common Unix utilities into a single executable. It is frequently used in resource-limited Embedded Linux systems.

Examples of Utilities

  • ls
  • cp
  • mv
  • rm
  • cat
  • grep
  • mount
  • sh

Check BusyBox in Ubuntu

busybox
busybox ls
busybox --list

If BusyBox is not installed, install it using the package manager in Ubuntu. 

sudo apt update
sudo apt install busybox
BusyBox is not a complete Linux operating system. It provides utilities that can be included in a root filesystem.

9. Device Tree

A Device Tree describes hardware information to the Linux kernel. It is especially important on many ARM and other embedded platforms.

Device Tree Files

File Description
.dts Device Tree Source.
.dtsi Device Tree Source Include.
.dtb Compiled Device Tree Blob.

Example Device Tree Fragment

/dts-v1/;

/ {
    compatible = "example,embedded-board";
    model = "Example Embedded Board";

    chosen {
        bootargs = "console=ttyS0,115200";
    };
};

This is only a small illustrative fragment. A real board description needs the correct hardware nodes, addresses, interrupts, clocks and compatible strings.

10. Cross-Compilation

Cross-compilation means compiling software on one system (host) for execution on a different target architecture.

Example

Host System:
Ubuntu PC (x86-64)
        |
        | Cross Compiler
        v
Target System:
ARM-based Embedded Board

Why Cross-Compilation?

  • Target hardware may have limited resources.
  • Compilation can be faster on a development PC.
  • The target may not have a compiler installed.
  • It supports different CPU architectures.

Example ARM Cross Compiler

aarch64-linux-gnu-gcc

This compiler targets 64-bit ARM Linux systems. The exact compiler and ABI must match the target platform.

The complete cross-compilation workflow is covered in the next lesson.

11. Buildroot and Yocto

Embedded Linux projects need a way to build the kernel, bootloader, root filesystem and application software.

Buildroot

Buildroot is a tool that automates the creation of embedded Linux systems. It can generate a toolchain, kernel, bootloader and root filesystem.

Yocto Project

The Yocto Project provides tools and metadata for creating customized Linux distributions for embedded products.

Buildroot Yocto
Often simpler to start with. Highly configurable build system.
Configuration commonly uses menuconfig. Uses recipes, layers and configuration files.
Suitable for many focused embedded products. Suitable for complex, reusable product distributions.

Both are widely used in embedded Linux development. The appropriate choice depends on project requirements.

12. Real-Time Requirements in Embedded Linux

Some embedded products require predictable response times to external events.

Standard Linux provides multitasking, scheduling and interrupt handling, but it does not automatically guarantee hard real-time deadlines.

PREEMPT_RT

PREEMPT_RT is a set of Linux kernel changes that improves preemption and scheduling latency for real-time workloads.

Examples of Real-Time Applications

  • Industrial control.
  • Robotics.
  • Motor control coordination.
  • Communication systems.
Embedded Linux is not automatically a hard real-time operating system. Hard real-time suitability depends on the kernel configuration, hardware, workload and measured worst-case latency.

14. Practical Commands in Ubuntu

These commands help inspect the architecture and kernel of your Ubuntu development environment.

Check Machine Architecture

Display CPU Information

Display Memory Information

free -h

Display PCI Devices

lspci

Display USB Devices

Display Block Devices

lsblk

Display Mounted Filesystems

Display Kernel Boot Messages

16. Interview Questions and Answers

Q1. What is Embedded Linux?

Embedded Linux is a customized Linux operating system designed for dedicated embedded devices.

Q2. What is an SoC?

A System-on-Chip integrates a CPU and other system components into one chip.

Q3. What is U-Boot?

U-Boot is an open-source bootloader commonly used in embedded systems.

Q4. What is a root filesystem?

It is the filesystem mounted at / that provides userspace programs, libraries and configuration.

Q5. What is BusyBox?

BusyBox combines many common Unix utilities into a single executable.

Q6. What is Device Tree?

Device Tree describes hardware information to the Linux kernel.

Q7. What is cross-compilation?

It is compiling software on a host system for a different target architecture.

Q8. What is Buildroot?

Buildroot is a tool used to generate customized embedded Linux systems.

Q9. What is the Yocto Project?

It provides tools and metadata for building customized Linux distributions.

Q10. What is PREEMPT_RT?

It is a set of Linux kernel changes designed to improve real-time preemption and latency behavior.

Q11. What is the difference between a bootloader and a kernel?

The bootloader initializes the platform and loads the kernel. The kernel manages system resources and hardware after startup.

Q12. Why is Embedded Linux customized?

Customization helps meet the product's hardware, storage, performance, security and application requirements.
