Memory Management Basics

Understand how Linux manages RAM, allocates memory, manages pages and provides memory resources to applications and kernel components.

1. Introduction to Memory Management

Memory management is an important function of an operating system. It controls how memory is allocated, used, protected and released.

Linux manages physical RAM and provides each process with its own virtual address space. It also manages memory used internally by the kernel.

Definition: Memory management is the operating system mechanism responsible for managing memory resources, allocating memory to processes, protecting address spaces and reclaiming unused memory.

Responsibilities of Linux Memory Management

  • Manage physical RAM.
  • Provide virtual address spaces to processes.
  • Allocate and release memory.
  • Manage memory pages and page tables.
  • Protect process memory.
  • Manage kernel memory allocations.
  • Reclaim memory when resources become limited.

2. Types of Computer Memory

Memory Type Description
Registers Very fast storage locations inside the CPU.
Cache Stores frequently accessed data for faster CPU access.
RAM Temporary working memory used by running programs.
ROM / Flash Non-volatile memory used for firmware and persistent storage.
Secondary Storage SSD or HDD used for persistent data storage.

Linux memory management mainly concerns RAM, virtual memory, memory mapping and kernel memory allocation.

3. Physical Memory

Physical memory refers to the actual RAM installed in a computer or embedded system.

The CPU and memory controller access physical memory through hardware-defined addresses.

Example

Suppose a system has 8 GB of physical RAM. The operating system manages this memory and distributes available resources among processes and kernel components.

Check Physical Memory

free -h

View Detailed Memory Information

cat /proc/meminfo

These commands display memory information reported by the running Linux system.

4. Virtual Memory

Virtual memory provides each process with its own virtual address space.

A process uses virtual addresses. The processor's memory management unit (MMU), together with page tables maintained by the operating system, translates virtual addresses into physical addresses when memory is accessed.

Advantages of Virtual Memory

  • Process memory isolation.
  • Memory protection.
  • Efficient memory allocation.
  • Support for demand paging.
  • Memory mapping of files and devices.
Virtual memory is not simply an extension of RAM using disk storage. It is an address-space abstraction that provides isolation and flexible memory mapping.

5. Virtual Address and Physical Address

A virtual address is generated by a process. A physical address identifies a location in physical memory.

Virtual Address Physical Address
Used by programs and processes. Identifies actual RAM locations.
Translated through page tables and MMU. Used by the memory system to access RAM.
Belongs to a process address space. Belongs to the physical memory address space.

Address Translation Concept

Process
   |
   | Virtual Address
   v
MMU and Page Tables
   |
   | Physical Address
   v
Physical RAM

6. Memory Pages

Linux manages memory in fixed-size units called pages.

A page is a basic unit used for virtual memory mapping and many memory-management operations.

Common Page Size

On many x86-64 Linux systems, the base page size is 4 KB. Other architectures and kernel configurations may use different sizes.

Check Page Size

getconf PAGE_SIZE

Another command:

getconf PAGESIZE

Page Calculation Example

If the page size is 4096 bytes and a program requires 16384 bytes: 

Number of pages = Memory required / Page size

                = 16384 / 4096

                = 4 pages

7. Page Frames

A page frame is a fixed-size block of physical memory that can hold a memory page.

  • Page: unit of virtual memory.
  • Page frame: corresponding unit of physical memory.

The page tables map virtual pages to physical page frames.

+-------------+                +-------------+
| Virtual Page| -------------> | Page Frame  |

+-------------+                +-------------+
| Virtual Page| -------------> | Page Frame  |

8. Memory Allocation

Memory allocation means reserving memory resources for a process or kernel component.

User-Space Memory Allocation

Applications commonly use library functions such as malloc(), calloc(), realloc() and free(). 

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *ptr;

    ptr = malloc(5 * sizeof(int));

    if (ptr == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    for (int i = 0; i < 5; i++)
    {
        ptr[i] = (i + 1) * 10;
    }

    for (int i = 0; i < 5; i++)
    {
        printf("%d ", ptr[i]);
    }

    printf("\n");

    free(ptr);

    return 0;
}

Expected Output

10 20 30 40 50

Explanation

  • malloc() requests memory from the C library allocator.
  • sizeof(int) gives the size of an integer.
  • NULL indicates allocation failure.
  • free() releases the allocated block back to the allocator.
malloc() is a user-space C library function. It is not a direct Linux kernel memory-allocation function. The allocator obtains memory through mechanisms such as brk() or mmap().

9. Kernel Memory Allocation

The Linux kernel requires memory for device drivers, kernel data structures, buffers, networking and other internal operations.

Kernel code uses kernel-specific allocation interfaces rather than ordinary user-space malloc().

Common Kernel Memory Allocation Functions

Function Purpose
kmalloc() Allocates physically contiguous kernel memory.
kzalloc() Allocates kernel memory and initializes it to zero.
kcalloc() Allocates an array of kernel objects and zeroes the memory.
vmalloc() Allocates virtually contiguous kernel memory.
kfree() Releases memory allocated by compatible kmalloc-family APIs.
vfree() Releases memory allocated by vmalloc().

Example: kmalloc()

#include <linux/slab.h>

int *ptr;

ptr = kmalloc(10 * sizeof(int), GFP_KERNEL);

if (!ptr)
{
    return -ENOMEM;
}

/* Use allocated memory */

kfree(ptr);

This is a kernel-code fragment, not a standalone C program.

10. GFP Flags

Kernel memory allocation functions use GFP flags to describe the allocation context and permitted allocation behaviour.

Flag Description
GFP_KERNEL Normal allocation context; may sleep.
GFP_ATOMIC Used in atomic contexts where sleeping is not permitted.
GFP_NOWAIT Requests allocation without direct reclaim or sleeping.
GFP_KERNEL must not be used in a context where sleeping is prohibited, such as a hard interrupt handler. GFP_ATOMIC is not a universal replacement; choose allocation flags according to the execution context and kernel API requirements.

11. kmalloc() vs vmalloc()

kmalloc() vmalloc()
Provides physically contiguous memory. Provides virtually contiguous memory.
Generally suited to smaller allocations. Can support larger allocations.
Typically faster and less overhead. Generally has greater mapping overhead.
Physical contiguity is useful for some hardware requirements. Does not guarantee physical contiguity.

Neither function should be selected solely based on allocation size. Hardware DMA requirements may require dedicated DMA allocation APIs instead.

12. Memory Zones

Linux divides physical memory into zones to support different hardware addressing and allocation requirements.

Zone names and their availability depend on the processor architecture and kernel configuration.

Common Memory Zones

Zone Purpose
ZONE_DMA Memory suitable for devices with restricted DMA addressing.
ZONE_DMA32 Memory addressable by devices with 32-bit DMA limits.
ZONE_NORMAL Normal directly mapped memory on architectures that define it.
ZONE_HIGHMEM High memory on architectures that use this zone.
ZONE_MOVABLE Memory reserved for movable pages where configured.

Inspect Memory Zones

cat /proc/zoneinfo

You may also inspect memory allocation information with: 

cat /proc/buddyinfo

13. Buddy System Allocator

Linux uses the buddy allocator to manage physical page frames.

It manages memory in blocks whose sizes are powers of two in units of pages. Free blocks can be split to satisfy smaller requests and compatible adjacent free blocks can be merged.

Example

A free block of 8 pages
          |
          v
     Split into
          |
    +-----+-----+
    |           |
  4 pages    4 pages

Advantages

  • Efficient allocation of page-frame blocks.
  • Supports splitting and merging of blocks.
  • Helps manage external fragmentation.

14. Slab Allocation

Kernel objects are frequently allocated and released. Repeatedly creating these objects can introduce allocation overhead.

Linux provides slab-family allocators to efficiently manage frequently used kernel objects.

Common Slab Allocator Interfaces

  • SLAB
  • SLUB
  • SLOB (historical allocator, removed from modern kernels)

SLUB is the default slab allocator in many modern Linux kernel configurations.

Common Kernel APIs

kmem_cache_create()
kmem_cache_alloc()
kmem_cache_free()
kmem_cache_destroy()

These APIs allow drivers and kernel components to create caches for frequently allocated objects.

15. Swap Memory

Swap is disk-backed storage that Linux can use to hold memory pages that are not currently required in RAM.

Depending on system configuration and memory pressure, Linux may move eligible pages between RAM and swap.

Check Swap Usage

swapon --show

Display Memory and Swap

free -h
Swap is not equivalent to physical RAM. Accessing disk-backed swap is generally much slower than accessing RAM.

16. Page Fault

A page fault occurs when a process accesses a virtual address that requires the processor and operating system to perform additional memory-management work.

Common Causes

  • A page has not yet been loaded into RAM.
  • A page is accessed for the first time.
  • A copy-on-write operation is required.
  • An invalid or disallowed memory access occurs.

Types of Page Faults

Type Description
Minor Page Fault Resolved without requiring disk I/O to load the page.
Major Page Fault Requires I/O, commonly to bring a page from storage.

Not every page fault is an error. Many page faults are normal parts of virtual memory operation.

17. Out of Memory (OOM) Killer

When Linux cannot satisfy memory demands after reclaim attempts, the kernel may invoke the Out of Memory (OOM) killer.

The OOM mechanism selects processes to terminate in an attempt to recover memory.

Check Kernel Messages

sudo dmesg | grep -i -E 'out of memory|oom'

View Memory Statistics

free -h
cat /proc/meminfo
The OOM killer is a recovery mechanism, not a normal memory-management strategy. Avoid terminating processes or changing OOM settings without understanding the system's workload.

18. Linux Memory Monitoring Commands

Command Purpose
free -h Displays RAM and swap usage.
cat /proc/meminfo Displays detailed memory statistics.
top Displays process and memory usage.
htop Interactive process and resource monitor, if installed.
vmstat Displays memory, process and system statistics.
pmap PID Displays a process memory map.
cat /proc/buddyinfo Displays free page blocks by memory zone.
cat /proc/zoneinfo Displays memory zone information.

Example Commands

free -h

vmstat 1 5

top

cat /proc/meminfo

pmap $$

20. Interview Questions and Answers

Q1. What is memory management?

It is the operating system function that allocates, protects, tracks and releases memory resources.

Q2. What is physical memory?

Physical memory is the actual RAM available to the computer.

Q3. What is virtual memory?

Virtual memory provides processes with independent virtual address spaces that are translated to physical memory through hardware and page tables.

Q4. What is a page?

A page is a fixed-size unit of virtual memory management.

Q5. What is a page frame?

A page frame is a fixed-size block of physical memory that holds a page.

Q6. What is malloc()?

malloc() is a C library function used to request dynamic memory in user space.

Q7. What is kmalloc()?

kmalloc() allocates physically contiguous memory for kernel use.

Q8. What is vmalloc()?

vmalloc() allocates virtually contiguous kernel memory that need not be physically contiguous.

Q9. What is GFP_KERNEL?

It is a kernel allocation flag used in contexts where sleeping is permitted.

Q10. What is a page fault?

It is an event that occurs when an access requires additional virtual memory handling.

Q11. What is swap memory?

Swap is disk-backed storage used to hold eligible memory pages when needed.

Q12. What is the OOM killer?

It is a kernel mechanism that may terminate selected processes when memory cannot be recovered sufficiently.

Q13. What is the buddy allocator?

It is a physical page allocator that manages free memory blocks by splitting and merging power-of-two-sized blocks.

Q14. What is slab allocation?

It is a kernel memory-management technique that efficiently manages frequently used kernel objects.

22. Lesson Summary

  • Linux manages physical and virtual memory.
  • Virtual address spaces provide process isolation.
  • The MMU and page tables support address translation.
  • Memory is managed in pages and physical page frames.
  • malloc() allocates user-space memory through the C library.
  • kmalloc() allocates physically contiguous kernel memory.
  • vmalloc() allocates virtually contiguous kernel memory.
  • GFP flags describe kernel allocation requirements.
  • The buddy allocator manages physical page blocks.
  • Slab-family allocators manage kernel objects.
  • Swap provides disk-backed memory storage.
  • Page faults are normal events in virtual memory management.
  • The OOM killer may act during severe memory pressure.
  • Linux provides /proc and command-line tools for memory monitoring.
