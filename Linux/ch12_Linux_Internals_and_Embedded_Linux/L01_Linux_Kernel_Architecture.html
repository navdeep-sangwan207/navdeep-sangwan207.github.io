Linux Kernel Architecture

Understand the internal structure of the Linux kernel, its major subsystems and interaction with computer hardware.

1. Introduction to the Linux Kernel

The Linux kernel is the core component of the Linux operating system. It manages computer hardware and provides essential services to application programs.

Applications do not normally access hardware directly. They request operating system services through interfaces such as system calls.

Definition: The Linux kernel is system software responsible for managing hardware resources, processes, memory, devices, filesystems and communication between applications and hardware.

Main Responsibilities

  • Process and thread management.
  • CPU scheduling.
  • Memory management.
  • Device management.
  • File system management.
  • Network communication.
  • Interrupt handling.
  • Security and access control.

2. What is an Operating System?

An operating system (OS) is system software that manages computer hardware and provides an environment for executing application programs.

Examples of Operating Systems

  • Linux
  • Windows
  • macOS
  • Android
  • FreeBSD

Linux distributions such as Ubuntu, Debian and Fedora use the Linux kernel along with system libraries, utilities and applications.

4. Linux Kernel Architecture Type

Linux uses a monolithic kernel architecture with modular capabilities.

Monolithic Kernel

In a monolithic kernel, major operating system services execute in kernel space.

These services include process management, memory management, networking, filesystems and device drivers.

Modular Design

Linux also supports loadable kernel modules. Many drivers and other kernel components can be loaded or unloaded without rebuilding the entire kernel.

Linux is commonly described as a modular monolithic kernel. Its core subsystems operate in kernel space, while supported modules can extend kernel functionality.

Monolithic vs Microkernel

Monolithic Kernel Microkernel
Most core OS services execute in kernel space. Only essential services execute in the kernel.
Kernel components communicate through internal interfaces. Many services communicate through message passing.
Can provide efficient internal communication. Provides stronger service isolation in many designs.
Linux is a modular monolithic example. MINIX 3 is a microkernel-based example.

5. Major Components of the Linux Kernel

The Linux kernel contains several subsystems. Each subsystem performs a specific responsibility.

1. Process Management

Process management handles process creation, termination, execution and scheduling.

  • Creates and manages processes and threads.
  • Maintains process information.
  • Schedules tasks on CPU cores.
  • Handles context switching.

2. Memory Management

Memory management controls physical and virtual memory used by the operating system and applications.

  • Allocates and frees memory.
  • Manages virtual address spaces.
  • Handles paging and page faults.
  • Provides memory protection.

3. Virtual File System (VFS)

VFS provides a common interface for different filesystem implementations.

  • Supports file and directory operations.
  • Provides common interfaces such as open(), read() and write().
  • Supports filesystems such as ext4, XFS and Btrfs.

4. Device Drivers

Device drivers allow the kernel to communicate with hardware devices.

  • UART controllers.
  • USB devices.
  • Storage controllers.
  • Network interfaces.
  • Display and input devices.

5. Networking Subsystem

The networking subsystem implements network communication protocols and manages network interfaces.

  • TCP/IP networking.
  • Socket interfaces.
  • Packet processing.
  • Network device management.

6. Interrupt Handling

Interrupt handling allows the kernel to respond to hardware and software events that require attention.

  • Handles hardware interrupts.
  • Processes interrupt requests.
  • Coordinates deferred work where required.

7. Security Subsystem

Security mechanisms enforce permissions, access controls and security policies.

  • User and group permissions.
  • Capabilities.
  • Linux Security Modules (LSM).
  • Security frameworks such as SELinux and AppArmor.

6. System Call Interface

A system call is a controlled entry point through which a user-space program requests a service from the kernel.

Examples of System Calls

7. Process Management and CPU Scheduling

The kernel manages processes and threads and decides which runnable task should execute on a CPU.

Important Concepts

  • Process: A program in execution.
  • Thread: An execution unit within a process.
  • PID: Process identifier.
  • Context switching: Switching CPU execution from one task to another.
  • Scheduler: Selects tasks for CPU execution.

Useful Commands

ps aux
top
htop
pidof bash
ps -eLf

8. Memory Management

The kernel manages system memory and provides memory isolation between processes.

Important Concepts

  • Physical memory (RAM).
  • Virtual memory.
  • Paging.
  • Page tables.
  • Page faults.
  • Kernel memory allocation.

Useful Commands

free -h
cat /proc/meminfo
vmstat

These commands display memory usage and memory-management information.

Device drivers are particularly important in Embedded Linux because they connect the operating system to board-specific peripherals and controllers.

10. Interrupt Handling in the Kernel

An interrupt allows hardware or software to request attention from the processor.

Example: UART Interrupt

  1. UART hardware receives a byte.
  2. The UART controller generates an interrupt.
  3. The CPU enters the appropriate interrupt handling path.
  4. The kernel invokes the registered interrupt handler.
  5. The driver processes the received data.

Linux drivers may use threaded interrupt handlers and deferred-work mechanisms when processing requires more time than is suitable in hard interrupt context.

11. Linux Kernel Source Code Structure

Linux kernel source code is organized into directories based on functionality.

Important Directories

Directory Purpose
arch/ Architecture-specific code.
block/ Block I/O layer.
drivers/ Device drivers.
fs/ Filesystem implementations and VFS-related code.
include/ Header files.
init/ Kernel initialization code.
ipc/ Interprocess communication mechanisms.
kernel/ Core kernel functionality.
mm/ Memory management.
net/ Networking subsystem.
scripts/ Build and development scripts.

These are major source-tree directories; their exact contents can change between kernel versions.

13. Linux Kernel vs Linux Distribution

The Linux kernel is only one component of a complete Linux operating system distribution.

Linux Kernel Linux Distribution
Core operating system component. Complete operating system environment.
Manages hardware and system resources. Combines kernel, libraries, utilities and applications.
Example: Linux kernel 6.x. Examples: Ubuntu, Debian and Fedora.

16. Interview Questions and Answers

Q1. What is the Linux kernel?

The Linux kernel is the core of the operating system. It manages hardware, memory, processes, devices and system resources.

Q2. What type of kernel does Linux use?

Linux uses a modular monolithic kernel architecture.

Q3. What is a system call?

A system call is an interface through which a user-space program requests a service from the kernel.

Q4. What is a device driver?

A device driver is kernel software that manages communication with a hardware device.

Q5. What is process management?

Process management handles process creation, termination, scheduling and execution.

Q6. What is memory management?

Memory management controls physical and virtual memory allocation, protection and mapping.

Q7. What is VFS?

VFS is the Virtual File System layer that provides a common interface for different filesystem types.

Q8. What is a kernel module?

A kernel module is code that can be loaded into or removed from a running kernel, subject to kernel configuration and security restrictions.

Q9. What is interrupt handling?

Interrupt handling is the process of responding to hardware or software events that require immediate or deferred processing.

Q10. What is Embedded Linux?

Embedded Linux is a customized Linux-based operating system used in dedicated embedded devices.

Q11. What is the difference between a kernel and a distribution?

The kernel manages hardware and system resources. A distribution includes the kernel along with libraries, utilities and applications.

Q12. Where are Linux device drivers located in the kernel source tree?

Most device driver source code is located in the drivers/ directory.
