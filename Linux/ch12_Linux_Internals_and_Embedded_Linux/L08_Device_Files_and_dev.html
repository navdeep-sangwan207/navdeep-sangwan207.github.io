Device Files and /dev

Learn how Linux represents hardware and virtual devices using special files and how applications interact with device interfaces.

1. Introduction to Device Files

Linux follows the principle that many system resources can be accessed through file-like interfaces.

A device file is a special filesystem entry that provides an interface to a device or device-related kernel facility.

Applications can use familiar file operations such as open(), read(), write() and close() when interacting with supported device files.

Definition: A device file is a special file, usually found under /dev, that provides a userspace interface to a device driver or another kernel device interface.

Examples

/dev/null
/dev/zero
/dev/random
/dev/tty
/dev/sda
/dev/loop0

Not every entry in /dev represents a physical hardware device. Some entries represent virtual devices or kernel-provided interfaces.

2. What Is the /dev Directory?

The /dev directory contains device nodes used to access devices and certain kernel interfaces.

Explore /dev

ls /dev

Display Detailed Information

ls -l /dev

Search for Common Device Entries

ls -l /dev/null
ls -l /dev/zero
ls -l /dev/tty

Important Characteristics

  • Device nodes provide file-like access to device interfaces.
  • They have permissions and ownership.
  • They may contain major and minor device numbers.
  • They are generally managed dynamically on modern Linux systems.
  • Device nodes are not ordinary files containing device data.

3. Types of Device Files

Linux traditionally classifies device nodes into two major categories.

A. Character Device Files

Character devices provide byte-oriented input/output interfaces.

Examples include:

  • Serial ports.
  • Terminal devices.
  • Some input devices.
  • Many embedded hardware interfaces.

Character device drivers commonly implement operations such as open, read, write and release.

B. Block Device Files

Block devices provide access to storage organized into addressable blocks.

Examples include:

  • Hard disk drives.
  • Solid-state drives.
  • USB mass-storage devices.
  • Some flash-storage devices.
Character Device Block Device
Byte-oriented interface. Block-oriented storage interface.
Commonly used for serial and terminal I/O. Commonly used for disks and storage.
Typically accessed through character-device operations. Integrated with the Linux block I/O subsystem.
Examples: /dev/tty, /dev/ttyS0. Examples: /dev/sda, /dev/loop0.
The distinction is about the device interface, not simply whether the underlying hardware transfers data one byte at a time or in blocks.

4. Major and Minor Device Numbers

Device nodes traditionally contain two identifying numbers: major and minor.

Major Number

The major number identifies the device-driver registration or device-number range associated with the device.

Minor Number

The minor number identifies a particular device or instance handled within that major-number range.

Example

ls -l /dev/null

Example output may look similar to: 

crw-rw-rw- 1 root root 1, 3 Nov  5 10:00 /dev/null

Interpretation:

  • c: Character device.
  • 1: Major number.
  • 3: Minor number.
  • root: Owner.
  • root: Group.
  • rw-rw-rw-: Permissions.
Major and minor numbers are displayed by ls -l for device nodes. They are identifiers, not physical hardware addresses.

5. Understanding File Types in ls -l

The first character in the output of ls -l indicates the file type.

Symbol File Type
- Regular file.
d Directory.
c Character device.
b Block device.
l Symbolic link.
p Named pipe (FIFO).
s Socket.

Example

ls -l /dev/null
ls -l /dev/sda
ls -ld /dev

6. Important Device Files

1. /dev/null

/dev/null is a special character device commonly called the null device.

  • Discards data written to it.
  • Reads return end-of-file immediately.
  • Useful for discarding unwanted command output.
echo "Hello Linux" > /dev/null

ls /some-directory 2> /dev/null

2. /dev/zero

/dev/zero produces a continuous stream of zero-valued bytes when read. 

head -c 10 /dev/zero | od -An -t x1

Expected byte values:

00 00 00 00 00 00 00 00 00 00

3. /dev/random

/dev/random provides random data from the kernel random-number generator. 

head -c 16 /dev/random | od -An -t x1

4. /dev/tty

/dev/tty refers to the controlling terminal of the current process, when one exists. 

echo "Terminal message" > /dev/tty

5. /dev/pts

/dev/pts contains device nodes for pseudoterminal slave devices. 

ls -l /dev/pts

6. /dev/loop0

A loop device allows a regular file to be used as a block device. 

losetup -a

Loop devices are useful for disk images, filesystem testing and virtual storage.

7. Device Files and Device Drivers

A device file provides an interface through which a userspace program can communicate with a device driver.

Basic Interaction Flow

       User Application
              |
              v
        open() / read()
         write() / ioctl()
              |
              v
        Device File (/dev)
              |
              v
        Linux VFS Layer
              |
              v
        Device Driver
              |
              v
        Hardware Device

The Virtual File System (VFS) provides a common interface for filesystem and file-like operations. Device-specific operations are handled by the appropriate kernel subsystem and driver.

A device file does not itself contain the device driver. It provides a userspace entry point to the kernel's device interface.

8. How Linux Creates Device Files

Modern Linux systems commonly use devtmpfs and udev to manage device nodes.

devtmpfs

devtmpfs is a special filesystem managed by the kernel. It provides device nodes for registered devices.

udev

udev is a userspace device manager. It processes device events and can apply rules to manage device-node permissions, ownership and symbolic links.

Device Event Flow

Hardware or Virtual Device Event
                |
                v
          Linux Kernel
                |
                v
          Device Event
                |
                v
              udev
                |
                v
      Device Node Management
                |
                v
             /dev

Check udev Information

udevadm info --query=all --name=/dev/null

Monitor Device Events

udevadm monitor

Device-event output depends on available hardware and system configuration.

9. Device Permissions

Device nodes have ownership and permission settings, similar to other filesystem entries.

Display Device Permissions

ls -l /dev/tty
ls -l /dev/null

Inspect Device Information

stat /dev/null

Why Are Permissions Important?

  • Control which users can access device interfaces.
  • Prevent unauthorized hardware access.
  • Support group-based access control.
  • Protect sensitive devices and system resources.
Do not change permissions on system device nodes as a learning experiment. Device-node permissions may be managed dynamically by udev rules and system services.

10. Creating Device Nodes with mknod

The mknod command can create a device node when supplied with the appropriate device type and major/minor numbers.

General Syntax

mknod NAME TYPE MAJOR MINOR

Device Types

  • c — Character device.
  • b — Block device.

Inspect mknod Help

mknod --help
Do not create arbitrary device nodes in /dev or use guessed major/minor numbers. A node is useful only when a matching device-number registration and driver interface exist.

11. Useful Linux Commands for Device Inspection

1. List Device Files

ls -l /dev

2. Display Device Information

stat /dev/null

3. Display Block Devices

lsblk

4. Display Filesystem Usage

df -h

5. Display Device Information

sudo lshw -short

The lshw utility may need to be installed.

6. Display USB Devices

7. Display PCI Devices

lspci

8. Display Kernel Messages

dmesg | tail -n 30

9. Display Block Device Information

12. Device Files in Embedded Linux

Device files are especially important in embedded Linux systems because applications often communicate with hardware through kernel-provided interfaces.

Examples of Embedded Device Interfaces

Device Interface Example
UART serial port /dev/ttyS0 or /dev/ttyUSB0
I2C adapter /dev/i2c-0
SPI interface /dev/spidev0.0
GPIO character device /dev/gpiochip0
CAN interface Usually exposed as a network interface, such as can0
These device nodes appear only when the corresponding hardware, kernel support, driver and system configuration are available. Their names and numbering can vary.

Why Embedded Developers Need This Knowledge

  • Understand how applications access hardware.
  • Debug serial communication problems.
  • Inspect I2C and SPI device interfaces.
  • Understand character-device driver development.
  • Work with Linux-based embedded boards.

14. Interview Questions and Answers

Q1. What is a device file in Linux?

A device file is a special filesystem entry that provides an interface to a device or kernel device facility.

Q2. Where are device files generally located?

They are generally located in /dev.

Q3. What are the two traditional types of device files?

Character devices and block devices.

Q4. What is a character device?

A character device provides a byte-oriented input/output interface.

Q5. What is a block device?

A block device provides an interface to storage organized into addressable blocks.

Q6. What is a major device number?

It identifies the device-number registration or range associated with a driver.

Q7. What is a minor device number?

It identifies a particular device or instance within a major-number range.

Q8. What is /dev/null?

It is a special device that discards written data and returns EOF when read.

Q9. What is /dev/zero?

It provides a stream of zero-valued bytes.

Q10. What is udev?

udev is a userspace device manager that processes device events and manages device-node rules and permissions.

Q11. What is devtmpfs?

devtmpfs is a kernel-managed filesystem used to provide device nodes.

Q12. What is mknod?

mknod creates special filesystem nodes, including character and block device nodes.

Q13. What is the purpose of /dev/pts?

It contains pseudoterminal slave device nodes.

Q14. How do you list block devices?

Use the lsblk command.
