User Space vs Kernel Space

Understand privilege levels, memory protection, user-mode execution, kernel-mode execution and system call transitions in Linux.

1. Introduction

Linux separates program execution into two important protection domains: user space and kernel space. This separation helps protect the operating system from faulty or unauthorized application operations.

Normal applications execute in user space, while the Linux kernel executes in kernel space.

Definition: User space is the environment where ordinary application programs execute with restricted privileges. Kernel space is the privileged environment where the operating system kernel manages hardware and system resources.

2. What is User Space?

User space is the memory and execution environment allocated to user applications.

Applications normally cannot directly execute privileged CPU instructions or access protected kernel memory.

Examples of User-Space Programs

  • Text editors.
  • Web browsers.
  • Terminal applications.
  • Shell programs.
  • Database applications.
  • Custom C and C++ programs.
  • System utilities such as ls, cp and grep.

Characteristics of User Space

  • Runs with restricted privileges.
  • Each process normally has its own virtual address space.
  • Cannot directly access protected kernel memory.
  • Uses system calls to request kernel services.
  • Application crashes are generally isolated from other processes.

3. What is Kernel Space?

Kernel space is the privileged execution and memory environment used by the Linux kernel.

The kernel performs operations that require privileged access to system resources and hardware.

Kernel-Space Components

  • Process scheduler.
  • Memory management subsystem.
  • Device drivers.
  • Filesystem implementation.
  • Networking subsystem.
  • Interrupt handling code.
  • Kernel modules.

Characteristics of Kernel Space

  • Executes with privileged CPU permissions.
  • Can access kernel-managed resources.
  • Manages hardware through appropriate drivers and interfaces.
  • Provides services to user-space applications.
  • Kernel faults can affect the entire operating system.

5. CPU Privilege Levels

Modern processors provide execution privilege levels to control access to protected operations. The Linux kernel uses the processor's privileged execution mode.

x86 and x86-64 Architecture

On x86 processors, privilege levels are commonly called rings.

Privilege Level Description
Ring 0 Most privileged level, normally used by the kernel.
Ring 1 Intermediate privilege level, generally unused by Linux.
Ring 2 Intermediate privilege level, generally unused by Linux.
Ring 3 Least privileged level, normally used by applications.
Important: Ring 0 and Ring 3 are commonly used to explain privilege separation on x86 systems. Other processor architectures use different privilege models. For example, ARM processors have exception levels.

6. User Mode and Kernel Mode

User Mode

User mode is the restricted processor execution mode in which ordinary applications run.

  • Cannot execute privileged instructions.
  • Cannot freely access physical hardware.
  • Cannot access protected kernel memory.
  • Requests operating system services through system calls.

Kernel Mode

Kernel mode is the privileged processor execution mode used by kernel code.

  • Can execute privileged instructions.
  • Can access kernel memory.
  • Can manage hardware resources.
  • Can execute kernel subsystem operations.
User Mode Kernel Mode
Restricted privileges. Privileged execution.
Used by normal applications. Used by the operating system kernel.
Cannot directly access protected kernel memory. Can access kernel memory.
Uses system calls for kernel services. Handles system calls and kernel operations.

7. What is a System Call?

A system call is a controlled interface through which a user-space application requests a service from the Linux kernel.

Examples

System Call Purpose
open() Opens a file.
read() Reads data.
write() Writes data.
close() Closes a file descriptor.
fork() Creates a child process.
execve() Replaces the process image.
mmap() Creates a memory mapping.

8. How Does a System Call Work?

Consider a user application that wants to write data to a file.

Execution Steps

  1. The application executes in user mode.
  2. It calls a library function such as write().
  3. The library or system call wrapper prepares the system call.
  4. The CPU executes the architecture-specific system call instruction.
  5. The processor transitions to privileged execution.
  6. The kernel validates arguments and performs the requested operation.
  7. The kernel returns a result to the application.
  8. Execution continues in user mode.

A system call does not necessarily switch to another process. It changes the execution privilege context while the calling process continues its operation.

9. Practical C Program Using write()

The following program demonstrates a direct use of the write() system call from a C application. 

#include <unistd.h>

int main(void)
{
    const char message[] =
        "Hello from user space!\n";

    write(STDOUT_FILENO, message,
          sizeof(message) - 1);

    return 0;
}

Compile the Program

gcc user_write.c -o user_write

Execute

./user_write

Expected Output

Hello from user space!

The application calls write(). The kernel processes the request and writes the message to the standard output file descriptor.

This is a small demonstration. Production programs should check the return value of write() and handle errors and partial writes.

10. Memory Protection

Memory protection prevents a user-space process from accessing memory regions that it is not permitted to access.

Why is Memory Protection Necessary?

  • Prevents applications from corrupting kernel memory.
  • Isolates processes from one another.
  • Improves system stability.
  • Supports security boundaries.
  • Helps detect invalid memory access.

Example

If an application attempts to access an invalid memory address, the processor and kernel handle the resulting memory fault. The application may receive a signal such as SIGSEGV. 

#include <stdio.h>

int main(void)
{
    int *ptr = NULL;

    printf("%d\n", *ptr);

    return 0;
}

This program attempts to dereference a null pointer. It will typically terminate with a segmentation fault on Linux.

Do not run this kind of invalid-memory-access example in a production program. It is only intended to demonstrate memory protection.

11. What Happens When a User Program Crashes?

If a normal user-space application crashes, the kernel generally terminates or signals that process without crashing the entire system.

Example

  • An application accesses invalid memory.
  • The processor detects a memory access fault.
  • The kernel handles the fault.
  • The application may receive SIGSEGV.
  • The affected process usually terminates.

A serious kernel fault is different. A kernel failure can affect the entire operating system and may result in a kernel panic.

12. Context Switch vs Mode Switch

These two concepts are related to CPU execution but describe different operations.

Mode Switch

A mode switch changes the processor's privilege level, such as a transition from user mode to kernel mode during a system call.

Context Switch

A context switch changes CPU execution from one task or thread to another. The kernel saves and restores the required execution state.

Mode Switch Context Switch
Changes privilege mode. Changes the executing task.
Can occur during a system call. Occurs when the scheduler switches tasks.
Does not necessarily change process identity. Changes the active execution context.
A system call can cause a mode switch without a context switch. A blocking system call may also lead to scheduling another task, resulting in a context switch.

13. User-Space and Kernel-Space Memory

Each process normally has its own virtual address space. The operating system and processor enforce access permissions for mapped memory regions.

Important Concepts

  • Virtual address space.
  • Page tables.
  • Memory protection bits.
  • User-accessible pages.
  • Kernel-only pages.
  • Address-space isolation.

The exact virtual address layout depends on the processor architecture, kernel configuration and operating system version.

14. Why Does Linux Separate User Space and Kernel Space?

Reason Explanation
Security Restricts unauthorized access to privileged resources.
Stability Isolates many application failures from the kernel.
Memory Protection Protects kernel memory and process address spaces.
Resource Management Allows the kernel to control CPU, memory and devices.
Controlled Access Provides system calls for accessing operating system services.

15. Practical Linux Commands

Check Current User

whoami

Display Process Information

ps aux

Inspect System Calls with strace

strace ls

strace displays system calls and signals associated with a process. It may not be installed by default.

Install strace on Ubuntu

sudo apt update
sudo apt install strace

Trace a Specific Program

strace -o trace.txt ./user_write
cat trace.txt

Search the trace output for write(), exit_group() and other system calls.

Inspect Process Memory Information

cat /proc/self/maps

This displays the virtual memory mappings of the process reading the file.

17. Interview Questions and Answers

Q1. What is user space?

User space is the restricted execution environment where normal application programs run.

Q2. What is kernel space?

Kernel space is the privileged execution environment where the Linux kernel manages system resources and hardware.

Q3. What is the difference between user mode and kernel mode?

User mode has restricted privileges, while kernel mode has privileged access to protected system resources.

Q4. What is a system call?

A system call is a controlled mechanism through which an application requests kernel services.

Q5. Why is user space separated from kernel space?

The separation improves security, stability, memory protection and controlled resource access.

Q6. What happens when a system call is executed?

The processor transitions to privileged execution, the kernel performs the requested operation and returns a result to user space.

Q7. What is Ring 0?

Ring 0 is the most privileged CPU protection level on x86 architecture and is normally used by the Linux kernel.

Q8. What is Ring 3?

Ring 3 is the least privileged x86 protection level and is normally used by user applications.

Q9. What is a segmentation fault?

A segmentation fault is an error condition commonly caused by an invalid or prohibited memory access.

Q10. What is the difference between a mode switch and a context switch?

A mode switch changes the CPU privilege level. A context switch changes the executing task.

Q11. Can a user application directly access hardware?

Ordinary applications generally use kernel interfaces and device drivers to access hardware. Special mechanisms can provide controlled device access in particular configurations.

Q12. What is strace?

strace is a Linux diagnostic tool used to trace system calls and signals of a process.

18. Multiple Choice Questions (MCQs)

Q1. Where do normal Linux applications execute?

  1. Kernel space
  2. User space
  3. Bootloader space
  4. BIOS space

Answer: B — User space

Q2. Which execution mode is used by the Linux kernel?

  1. User mode
  2. Kernel mode
  3. Application mode
  4. Shell mode

Answer: B — Kernel mode

Q3. Which interface allows applications to request kernel services?

  1. System call interface
  2. Text editor
  3. File manager
  4. Compiler only

Answer: A — System call interface

Q4. Which x86 privilege level is normally used by the kernel?

  1. Ring 0
  2. Ring 1
  3. Ring 2
  4. Ring 3

Answer: A — Ring 0

Q5. Which x86 privilege level is normally used by applications?

  1. Ring 0
  2. Ring 1
  3. Ring 2
  4. Ring 3

Answer: D — Ring 3

Q6. Which tool traces Linux system calls?

  1. strace
  2. mkdir
  3. pwd
  4. clear

Answer: A — strace

Q7. What does a mode switch change?

  1. CPU privilege level
  2. Hard disk partition

  4. IP address

Answer: A — CPU privilege level

Q8. What does a context switch change?

  1. Executing task
  2. File permissions
  3. Kernel version
  4. Network address

Answer: A — Executing task

Q9. Which signal is commonly associated with an invalid memory access?

  1. SIGINT
  2. SIGSEGV
  3. SIGTERM
  4. SIGALRM

Q10. What generally happens when a user application crashes?

  1. The entire kernel must crash.
  2. Only the affected process is generally terminated.
  3. The CPU is permanently disabled.

Answer: B — Only the affected process is generally terminated

19. Lesson Summary

  • User space is the restricted environment for normal applications.
  • Kernel space is the privileged environment for kernel operations.
  • User mode and kernel mode provide execution privilege separation.
  • System calls provide controlled access to kernel services.
  • On x86, Linux normally uses Ring 0 for the kernel and Ring 3 for applications.
  • Memory protection isolates processes and protects kernel memory.
  • A mode switch is different from a context switch.
  • strace helps inspect system calls made by applications.
