LINUX INTERNALS AND EMBEDDED LINUX • CHAPTER 12 • LESSON 12

Cross Compilation

Learn how to compile applications on a host computer for execution on a different target architecture such as ARM-based Embedded Linux.

1. Introduction to Cross Compilation

Cross compilation is the process of compiling software on one computer (the host system) to generate executable code for another computer (the target system).

It is widely used in Embedded Linux development because embedded boards may have limited processing power, memory or storage.

Definition: Cross compilation is compiling software on a host platform for execution on a different target platform or architecture.

Example

Host System:
Ubuntu PC (x86-64)
        |
        | Cross Compiler
        v
Target System:
ARM64 Embedded Linux Board

The compiled program is transferred to the target board and executed there.

2. Native Compilation vs Cross Compilation

A. Native Compilation

Native compilation means compiling software on the same platform where the resulting program will execute. 

Ubuntu x86-64 Host
       |
       | gcc program.c
       v
x86-64 Executable
       |
       v
Runs on Ubuntu x86-64

B. Cross Compilation

Cross compilation generates a program for a different target architecture. 

Ubuntu x86-64 Host
       |
       | aarch64-linux-gnu-gcc
       v
ARM64 Executable
       |
       v
Runs on ARM64 Linux Target
Native Compilation Cross Compilation
Host and target are generally the same architecture. Host and target architectures may differ.
Uses a native compiler. Uses a cross-compiler.
Usually executes directly on the build system. Must execute on a compatible target system.
Common for desktop applications. Common for embedded development.

3. Host System and Target System

Host System

The host system is the computer used to develop, compile and build software.

Example:

  • Ubuntu development PC.
  • x86-64 processor.
  • GCC compiler and development tools.

Target System

The target system is the device on which the compiled application is intended to run.

Example:

  • ARM64 embedded board.
  • Embedded Linux operating system.
  • ARM-compatible libraries and runtime.
The host architecture does not determine the target architecture. The selected cross-compiler and target toolchain do.

4. What Is a Cross Compiler?

A cross-compiler is a compiler that runs on the host system but generates machine code for a different target.

Common Cross-Compiler Names

Compiler Target
gcc Usually the host system's native target.
arm-linux-gnueabihf-gcc 32-bit ARM Linux using the hard-float ABI.
aarch64-linux-gnu-gcc 64-bit ARM Linux.
riscv64-linux-gnu-gcc 64-bit RISC-V Linux.
arm-none-eabi-gcc Bare-metal ARM targets, not a normal Linux userspace compiler.
Do not confuse arm-none-eabi-gcc with arm-linux-gnueabihf-gcc. The first is commonly used for bare-metal or microcontroller development. The second targets ARM Linux userspace applications.

5. Cross-Compilation Toolchain

A cross-compilation toolchain contains the tools required to build programs for a target architecture.

Main Components

  1. Cross Compiler: Converts source code into target machine code.
  2. Assembler: Converts assembly language into object code.
  3. Linker: Combines object files and libraries.
  4. Binutils: Provides tools such as objdump, readelf and ar.
  5. Target Libraries: Libraries compatible with the target system.
  6. Headers: Header files required during compilation.
  7. Sysroot: A directory representing the target system's development environment.

Toolchain Workflow

C Source Code (.c)
        |
        v
Cross Compiler
        |
        v
Assembly / Object Code
        |
        v
Linker + Target Libraries
        |
        v
Target Executable
        |
        v
Embedded Linux Board

6. What Is a Sysroot?

A sysroot is a directory that provides the target system's filesystem structure and development files to the cross-compiler.

It commonly contains:

  • Target C library files.
  • Header files.
  • Linker-related files.
  • Development libraries.

Example Sysroot Structure

target-sysroot/
    |
    +-- lib/
    |
    +-- usr/
         |
         +-- include/
         |
         +-- lib/

The exact layout depends on the toolchain and target distribution.

Display Compiler Sysroot

aarch64-linux-gnu-gcc -print-sysroot

Display Compiler Search Directories

aarch64-linux-gnu-gcc -print-search-dirs

7. Install an ARM64 Cross Compiler in Ubuntu

We will install an ARM64 GNU/Linux cross-compiler on the Ubuntu host.

Step 1: Update Package Information

sudo apt update

Step 2: Install the Compiler

sudo apt install gcc-aarch64-linux-gnu

This package provides the ARM64 cross-compiler and its required supporting components.

Step 3: Check the Compiler

aarch64-linux-gnu-gcc --version

Step 4: Check the Target Architecture

aarch64-linux-gnu-gcc -dumpmachine

Expected target triple:

aarch64-linux-gnu

Step 5: Check the Host Architecture

uname -m

Your Ubuntu virtual machine may report x86_64 as its host architecture.

8. First Cross-Compilation Program

Step 1: Create a C Source File

Filename: hello.c

#include <stdio.h>

int main(void)
{
    printf("Hello from Embedded Linux!\n");

    return 0;
}

Step 2: Compile for ARM64

aarch64-linux-gnu-gcc hello.c -o hello_arm64

Step 3: Check the Generated File

file hello_arm64

The output should identify an ELF executable for the AArch64 architecture.

Step 4: Inspect ELF Header

aarch64-linux-gnu-readelf -h hello_arm64

Check the Machine field. It should identify AArch64.

Step 5: Check Shared Library Dependencies

aarch64-linux-gnu-readelf -d hello_arm64

Look for the NEEDED entries that identify required shared libraries.

An ARM64 executable cannot normally run directly on an x86-64 Ubuntu host. Transfer it to a compatible ARM64 Linux target, or use a suitable emulator.

9. Cross-Compilation for 32-bit ARM Linux

Some embedded boards use 32-bit ARM processors and a hard-float Linux ABI.

Install the Compiler

sudo apt install gcc-arm-linux-gnueabihf

Check the Compiler

arm-linux-gnueabihf-gcc --version

Compile a Program

arm-linux-gnueabihf-gcc hello.c -o hello_arm32

Inspect the Executable

file hello_arm32

The resulting program targets a compatible 32-bit ARM Linux system using the hard-float ABI.

10. Static and Dynamic Linking

Dynamic Linking

A dynamically linked executable uses shared libraries provided by the target operating system at runtime. 

aarch64-linux-gnu-gcc hello.c -o hello_dynamic

Static Linking

Static linking includes required library code in the executable, where supported by the toolchain. 

aarch64-linux-gnu-gcc -static hello.c -o hello_static
Dynamic Linking Static Linking
Uses shared libraries at runtime. Includes linked library code in the executable.
Usually produces smaller executables. Usually produces larger executables.
Requires compatible runtime libraries. Reduces dependence on shared libraries for linked components.
Static linking does not make an executable architecture-independent. It must still match the target architecture and runtime environment.

11. Transfer the Executable to a Target

After compilation, the executable can be transferred to an embedded Linux board using SSH, SCP or another supported transfer method.

Example Using SCP

scp hello_arm64 user@192.168.1.100:/home/user/

Replace the username and IP address with the actual target system details.

Connect to the Target

ssh user@192.168.1.100

Run the Program

chmod +x hello_arm64

./hello_arm64

Expected output:

Hello from Embedded Linux!

12. Useful Cross-Compilation Tools

Tool Purpose
aarch64-linux-gnu-gcc Compile C programs for ARM64 Linux.
aarch64-linux-gnu-g++ Compile C++ programs for ARM64 Linux.
aarch64-linux-gnu-as Assemble target assembly code.
aarch64-linux-gnu-ld Link object files.
aarch64-linux-gnu-objdump Disassemble and inspect object files.
aarch64-linux-gnu-readelf Inspect ELF file information.
aarch64-linux-gnu-ar Create and modify static archives.

Inspect ELF Architecture

aarch64-linux-gnu-readelf -h hello_arm64

Inspect Assembly or Machine Code

aarch64-linux-gnu-objdump -d hello_arm64

13. Cross-Compilation Problems

Problem 1: Wrong Architecture

An executable built for x86-64 cannot normally run on an ARM64 target.

Solution:

file hello_arm64

Confirm that the executable architecture matches the target processor.

Problem 2: Missing Shared Library

The target system may not contain a required shared library.

Solution:

  • Check the target's available libraries.
  • Use a compatible target sysroot.
  • Build or install the required target library.

Problem 3: Wrong ABI

A binary may use an ABI that is not supported by the target system.

Check the target's architecture, floating-point ABI, C library and toolchain configuration.

Problem 4: Missing Header Files

The cross-compiler may not find required target development headers.

Use a suitable toolchain and sysroot containing the correct target headers.

15. Interview Questions and Answers

Q1. What is cross compilation?

It is compiling software on a host system for execution on a different target architecture.

Q2. What is a host system?

It is the computer on which software is developed and compiled.

Q3. What is a target system?

It is the system on which the compiled program is intended to execute.

Q4. What is a cross compiler?

It is a compiler that runs on the host but generates code for a different target architecture.

Q5. What is a toolchain?

A toolchain is a collection of compiler, assembler, linker, libraries and other development tools.

Q6. What is a sysroot?

A sysroot provides target-system headers, libraries and filesystem development files to the compiler.

Q7. What is the purpose of GCC?

GCC is a compiler collection used to compile languages such as C and C++.

Q8. What is the difference between gcc and aarch64-linux-gnu-gcc?

gcc normally targets the host's native platform, while aarch64-linux-gnu-gcc targets 64-bit ARM Linux.

Q9. What is the difference between arm-none-eabi-gcc and arm-linux-gnueabihf-gcc?

arm-none-eabi-gcc is commonly used for bare-metal ARM development, while arm-linux-gnueabihf-gcc targets 32-bit ARM Linux systems.

Q10. Why is cross compilation useful in embedded systems?

It allows developers to build software on a powerful host computer for resource-constrained embedded hardware.

Q11. What is the ELF format?

ELF stands for Executable and Linkable Format. It is a common binary format used by Linux executables, object files and shared libraries.

Q12. Can an ARM64 executable run directly on x86-64 Linux?

Not normally. It requires compatible hardware or an appropriate emulation environment.
