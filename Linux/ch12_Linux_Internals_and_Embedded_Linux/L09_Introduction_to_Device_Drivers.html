Introduction to Device Drivers

Understand how Linux device drivers connect hardware with the operating system and applications.

1. Introduction to Device Drivers

A device driver is software that allows the operating system to communicate with and control a hardware device or a device-related interface.

Different hardware devices have different registers, communication protocols, operating requirements and control methods. A driver handles these device-specific details.

Definition: A device driver is a software component that provides the operating system with an interface for controlling and communicating with a device.

Examples of Devices Requiring Drivers

  • UART and serial controllers.
  • USB controllers and USB devices.
  • Storage controllers.
  • Network interfaces.
  • Display and graphics hardware.
  • Audio devices.
  • GPIO controllers.
  • I2C and SPI controllers.

2. Why Are Device Drivers Required?

Applications should not need to understand every hardware register and electrical characteristic of a device.

Device drivers provide a standard software interface while managing hardware-specific operations.

Main Responsibilities

  • Initialize and configure hardware.
  • Read data from devices.
  • Write data to devices.
  • Control device operations.
  • Handle hardware interrupts.
  • Manage device resources.
  • Handle errors and device status.
  • Coordinate access to shared hardware.

3. Device Driver Architecture

Linux provides kernel subsystems and common interfaces through which device drivers interact with the rest of the operating system.

Basic Architecture

        User Applications
                |
                v
        System Calls / APIs
                |
                v
       Virtual File System
          or Other APIs
                |
                v
       Linux Kernel Subsystem
                |
                v
          Device Driver
                |
                v
       Hardware Controller
                |
                v
          Hardware Device

The exact path depends on the device class. For example, storage, networking and input devices use different kernel subsystems.

Not every device is accessed through /dev or the VFS. Network interfaces, for example, are primarily accessed through networking APIs and kernel networking subsystems.

4. Types of Linux Device Drivers

A common introductory classification includes character, block and network device drivers.

A. Character Device Drivers

Character device drivers provide byte-oriented input/output interfaces.

Examples:

  • Serial ports.
  • UART interfaces.
  • Some input devices.
  • Simple custom character devices.

Character-device drivers commonly use operations such as open, read, write, ioctl and release.

B. Block Device Drivers

Block device drivers provide storage devices that support block-oriented input/output.

Examples:

  • Hard disks.
  • Solid-state drives.
  • USB mass-storage devices.
  • Some flash-storage devices.

C. Network Device Drivers

Network device drivers connect network hardware to the Linux networking subsystem.

Examples:

  • Ethernet controllers.
  • Wi-Fi adapters.
  • Network interface hardware.
Driver Type Main Purpose Example
Character Byte-oriented I/O UART
Block Block-oriented storage I/O SSD
Network Network packet transmission and reception Ethernet

5. Kernel Space and User Space

Linux separates application execution from privileged kernel execution.

User Space

  • Runs ordinary applications.
  • Uses system calls and kernel APIs.
  • Cannot directly access protected kernel memory.
  • Requests device operations through supported interfaces.

Kernel Space

  • Runs kernel code and kernel modules.
  • Manages hardware resources.
  • Provides kernel subsystems.
  • Executes device-driver code.

6. Loadable Kernel Modules

Linux supports loadable kernel modules that can be inserted into and removed from a running kernel when supported.

Device drivers are often implemented as loadable kernel modules.

Module File Extension

.ko

Common Module Commands

lsmod

Displays currently loaded modules.

sudo modprobe module_name

Loads a module and handles dependencies.

sudo modprobe -r module_name

Requests removal of a module.

modinfo module_name

Displays module information.

dmesg | tail -n 30

Displays recent kernel messages.

Never unload an important system driver simply as an experiment. Removing a module can interrupt devices or affect the running system.

7. Linux Character Device Driver Interface

A character driver commonly registers operations that the kernel can invoke when a userspace process accesses its device node.

Common File Operations

Operation Purpose
open() Opens the device.
read() Reads data from the device.
write() Writes data to the device.
release() Handles closing of the device.
unlocked_ioctl() Handles device-specific control requests.

struct file_operations

In a traditional character-device driver, struct file_operations describes callbacks used for file-like operations. 

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .read = my_read,
    .write = my_write,
    .release = my_release,
};

Each callback must have the correct function signature and appropriate error handling.

This structure is commonly used in character-device drivers. Other driver subsystems use their own operation structures and interfaces.

8. Device Number Registration

Character-device drivers need a device number range to identify their devices.

Important Kernel Functions

  • alloc_chrdev_region()
  • register_chrdev_region()
  • unregister_chrdev_region()
  • cdev_init()
  • cdev_add()
  • cdev_del()

alloc_chrdev_region()

Dynamically allocates a range of character device numbers. 

alloc_chrdev_region(
    &dev_number,
    first_minor,
    count,
    "mydevice"
);

unregister_chrdev_region()

Releases a previously registered device number range. 

unregister_chrdev_region(dev_number, count);

10. Device Tree in Embedded Linux

Embedded Linux systems often use a Device Tree to describe hardware that cannot be discovered automatically.

A Device Tree describes information such as:

  • Hardware devices.
  • Memory regions.
  • Interrupt connections.
  • GPIO assignments.
  • Bus relationships.
  • Device configuration properties.

Common Device Tree File Extensions

  • .dts — Device Tree Source.
  • .dtsi — Device Tree Source Include.
  • .dtb — Compiled Device Tree Blob.

Example Device Tree Fragment

uart0: serial@10000000 {
    compatible = "vendor,example-uart";
    reg = <0x10000000 0x1000>;
    status = "okay";
};

This is an illustrative fragment, not a complete board description. Real addresses and compatible strings must match the hardware and its driver.

Device Tree is especially important when developing Linux drivers for ARM-based embedded boards.

11. Hardware Access Methods

Device drivers communicate with hardware through architecture- and device-specific mechanisms.

Common Methods

  • Memory-mapped I/O (MMIO).
  • Port-mapped I/O on architectures that support it.
  • Interrupt handling.
  • Direct Memory Access (DMA).
  • Bus protocols such as I2C, SPI and PCI.

Memory-Mapped I/O

In MMIO, device registers are mapped into an address range that the CPU can access using architecture-supported mechanisms.

Interrupt Handling

Devices can generate interrupts to notify the processor that an event requires attention. The driver registers appropriate interrupt handlers.

DMA

DMA allows supported devices to transfer data to or from memory without requiring the CPU to copy every byte.

16. Interview Questions and Answers

Q1. What is a device driver?

A device driver is software that allows the operating system to communicate with and control a device.

Q2. Why are device drivers required?

They manage hardware-specific operations and provide standard interfaces to the operating system and applications.

Q3. What are the three common introductory driver categories?

Character, block and network device drivers.

Q4. What is a character device driver?

It provides a byte-oriented device input/output interface.

Q5. What is a block device driver?

It provides access to storage through the Linux block I/O subsystem.

Q6. What is a network device driver?

It connects network hardware to the Linux networking subsystem.

Q7. What is a loadable kernel module?

It is kernel code that can be loaded into or removed from a running kernel when supported.

Q8. What is struct file_operations?

It is a kernel structure that defines callbacks for file-like operations in interfaces such as character devices.

Q9. What is alloc_chrdev_region()?

It dynamically allocates a range of character-device numbers.

Q10. What is cdev_add()?

It adds a character device to the kernel's character-device system.

Q11. What is Device Tree?

Device Tree describes hardware configuration information to the operating system.

Q12. What is MMIO?

Memory-Mapped I/O allows a device's registers to be accessed through mapped address ranges.

Q13. What is DMA?

Direct Memory Access allows supported hardware to transfer data to or from memory with reduced CPU involvement.

Q14. Why are interrupts important in drivers?

They notify the CPU and operating system about device events requiring attention.
