Virtual Memory

Understand how Linux provides virtual address spaces, translates addresses, handles page faults and manages memory efficiently.

1. Introduction to Virtual Memory

Virtual memory is a memory-management technique that gives each process its own virtual address space.

A program uses virtual addresses rather than directly accessing arbitrary physical RAM addresses. The processor's Memory Management Unit (MMU) and page tables translate these addresses into physical addresses.

Definition: Virtual memory is an abstraction that provides processes with independent address spaces and allows the operating system to manage memory through address translation and page mapping.

Why Is Virtual Memory Required?

  • Provides process memory isolation.
  • Protects one process from another.
  • Supports efficient memory allocation.
  • Allows programs to use large virtual address spaces.
  • Supports demand paging and memory mapping.
  • Enables copy-on-write memory sharing.

2. Virtual Memory Architecture

Each process has its own virtual address space. The same virtual address used by two different processes can refer to different physical memory.

Address Translation Flow

        Process
           |
           v
     Virtual Address
           |
           v
    Memory Management
       Unit (MMU)
           |
           v
      Page Tables
           |
           v
    Physical Address
           |
           v
      Physical RAM

The MMU uses page-table information to translate virtual addresses into physical addresses.

3. Virtual Address Space

A virtual address space is the range of virtual addresses available to a process.

A typical process address space contains several logical regions.

Memory Region Purpose
Text Segment Contains executable program instructions.
Data Segment Contains initialized global and static variables.
BSS Segment Contains uninitialized or zero-initialized global and static variables.
Heap Used for dynamic memory allocation.
Memory-Mapped Region Contains mapped files, shared libraries and other mappings.
Stack Used for function calls and automatic local variables.

Conceptual Process Memory Layout

Higher Addresses

|           Heap           |

+--------------------------+

+--------------------------+

Lower Addresses
This is a simplified conceptual layout. Actual address-space organization depends on the processor architecture, executable format, ASLR and kernel configuration.

4. Virtual Address vs Physical Address

Virtual Address Physical Address
Generated by program execution. Identifies a location in physical memory.
Belongs to a process address space. Belongs to the physical memory address space.
Translated through the MMU. Used for physical memory access.
Different processes can use the same virtual address. Physical locations are shared system resources.

Example

Process A and Process B may both access a virtual address such as 0x1000.

Their page tables can map that virtual address to different physical memory locations.

5. Memory Management Unit (MMU)

The MMU is a hardware component responsible for memory address translation and memory access protection.

Responsibilities

  • Translate virtual addresses into physical addresses.
  • Enforce memory access permissions.
  • Support process address-space isolation.
  • Work with page tables maintained by the operating system.

Important MMU Concepts

  • Virtual address.
  • Physical address.
  • Page tables.
  • Translation Lookaside Buffer (TLB).
  • Memory protection.

6. Page Tables

Page tables are data structures used by the operating system and MMU to map virtual pages to physical page frames.

Page-table entries contain mapping information and access permissions.

Typical Page-Table Information

  • Physical page-frame address.
  • Present or valid status.
  • Read/write permission.
  • User/supervisor permission.
  • Accessed and dirty information where supported.
  • Other architecture-specific attributes.

Conceptual Mapping

Virtual Page       Page Table       Physical Frame

Page 0  -------->  Entry 0  ------>  Frame 5

Page 1  -------->  Entry 1  ------>  Frame 9

Page 2  -------->  Entry 2  ------>  Frame 2

Page tables may use multiple levels to organize large virtual address spaces efficiently.

7. Translation Lookaside Buffer (TLB)

The TLB is a hardware cache that stores recently used virtual-to-physical address translations.

Without a TLB, the processor may need to perform multiple memory accesses to walk page tables for address translation.

TLB Hit

The required address translation is found in the TLB.

TLB Miss

The required translation is not found in the TLB. Hardware or software performs the required page-table lookup, depending on the architecture.

A TLB miss is not necessarily a page fault. A TLB miss can be resolved by finding a valid page-table entry. A page fault occurs when the memory access requires operating-system fault handling.

8. Demand Paging

Demand paging is a technique in which pages are brought into physical memory when they are needed rather than loading every possible page in advance.

Working Process

  1. A process accesses a virtual memory page.
  2. The required mapping is not currently available.
  3. The processor raises a page fault.
  4. The kernel checks whether the access is valid.
  5. The kernel obtains or prepares the required page.
  6. The page-table mapping is updated.
  7. The instruction is retried.

Advantages

  • Reduces unnecessary initial memory loading.
  • Allows efficient use of physical RAM.
  • Supports large process address spaces.
  • Works with file-backed memory mappings.

9. Page Fault

A page fault is an exception generated when a memory access requires additional handling by the operating system.

Page Fault Handling

Process accesses virtual address
             |
             v
     Page-table lookup
             |
             v
      Page fault occurs
             |
             v
      Kernel fault handler
             |
       +-----+------+
       |            |
       v            v
  Valid access   Invalid access
       |            |
       v            v
Prepare page    Signal or error
and update map
       |
       v
Retry instruction

Minor Page Fault

A minor page fault can be handled without reading the required page from storage. For example, the kernel may establish a mapping to a page already available in RAM.

Major Page Fault

A major page fault requires storage I/O to obtain the required page.

Page faults are not always errors. Demand paging, copy-on-write and memory mapping can all produce normal page faults.

10. Copy-on-Write (COW)

Copy-on-Write is a memory-management technique that allows processes to share memory pages until one of them attempts to modify a page.

Instead of copying all memory immediately, Linux can initially share eligible pages with suitable read-only mappings.

How COW Works

  1. A parent process creates a child using fork().
  2. Eligible memory pages are initially shared.
  3. The mappings are protected against direct writing.
  4. If either process writes to a shared page, a page fault occurs.
  5. The kernel creates a private copy when required.
  6. The writing process uses its private page.

Example

Parent Process
      |
      | fork()
      v
Child Process

Initially:
Parent ----+
           |
           +---- Shared Physical Page
           |
Child -----+

After Child Writes:
Parent -------- Original Page

Child  -------- Private Copy

Advantages

  • Reduces unnecessary memory copying.
  • Makes process creation more efficient.
  • Reduces initial memory consumption.

11. Memory Mapping

Memory mapping allows files or other objects to be mapped into a process's virtual address space.

Linux provides the mmap() system call for creating memory mappings.

General Syntax

void *mmap(
    void *addr,
    size_t length,
    int prot,
    int flags,
    int fd,
    off_t offset
);

Important Parameters

Parameter Purpose
addr Optional preferred starting address.
length Length of the mapping.
prot Memory protection permissions.
flags Mapping type and behaviour.
fd File descriptor for file-backed mappings.
offset File offset where mapping begins.

Common Protection Flags

  • PROT_READ — Read access.
  • PROT_WRITE — Write access.
  • PROT_EXEC — Execute access.
  • PROT_NONE — No access.

Common Mapping Flags

  • MAP_SHARED — Changes can be shared with other mappings of the same object.
  • MAP_PRIVATE — Creates a private copy-on-write mapping.
  • MAP_ANONYMOUS — Creates a mapping not backed by a regular file.

12. Practical Program Using mmap()

The following C program allocates anonymous virtual memory, writes a value and reads it.

Source Code

#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    int *ptr;
    size_t size = sizeof(int);

    ptr = mmap(
        NULL,
        size,
        PROT_READ | PROT_WRITE,
        MAP_PRIVATE | MAP_ANONYMOUS,
        -1,
        0
    );

    if (ptr == MAP_FAILED)
    {
        perror("mmap");
        return 1;
    }

    *ptr = 100;

    printf("Value = %d\n", *ptr);

    if (munmap(ptr, size) == -1)
    {
        perror("munmap");
        return 1;
    }

    return 0;
}

Compile

gcc mmap_test.c -o mmap_test

Execute

./mmap_test

Expected Output

Value = 100

Explanation

  • mmap() creates a memory mapping.
  • MAP_PRIVATE creates a private mapping.
  • MAP_ANONYMOUS means it is not backed by a regular file.
  • PROT_READ and PROT_WRITE permit reading and writing.
  • munmap() removes the mapping.

13. Swap Space and Virtual Memory

Swap is disk-backed storage that Linux can use for eligible memory pages when physical memory is under pressure.

Check Swap Information

swapon --show

Check RAM and Swap Usage

free -h

Swap is slower than RAM and does not provide the same performance as physical memory. Linux can also operate without swap configured.

14. Memory Protection

Virtual memory supports memory protection by controlling which memory regions a process can access.

Common Protection Permissions

  • Read permission.
  • Write permission.
  • Execute permission.
  • User and kernel access permissions.

Example

If a program attempts to write to a memory region that is read-only, the processor may raise a protection fault. Linux can then deliver a signal such as SIGSEGV.

Memory protection helps isolate processes and prevent unauthorized access to memory.

15. Address Space Layout Randomization (ASLR)

ASLR is a security technique that randomizes selected memory-region locations when processes are started.

It makes memory addresses less predictable and can make certain memory-corruption attacks more difficult.

Check ASLR Setting

cat /proc/sys/kernel/randomize_va_space

Common Values

Value Meaning
0 ASLR disabled.
1 Conservative randomization.
2 Full randomization, where supported.
Do not change the system ASLR setting merely for this exercise. Inspecting the current setting is sufficient.

18. Interview Questions and Answers

Q1. What is virtual memory?

Virtual memory provides each process with an independent virtual address space.

Q2. What is an MMU?

The Memory Management Unit translates virtual addresses and enforces memory access permissions.

Q3. What are page tables?

Page tables store virtual-to-physical memory mapping information and access attributes.

Q4. What is a TLB?

A Translation Lookaside Buffer caches recently used address translations.

Q5. What is a TLB miss?

A TLB miss occurs when the required translation is not found in the TLB.

Q6. Is a TLB miss the same as a page fault?

No. A TLB miss can be resolved using a valid page-table entry without a page fault.

Q7. What is demand paging?

Demand paging brings pages into memory when they are required.

Q8. What is a page fault?

A page fault is an exception that causes the operating system to handle a memory access.

Q9. What is Copy-on-Write?

COW allows memory pages to be shared until a process attempts to modify them.

Q10. What is mmap()?

mmap() creates a mapping in a process's virtual address space.

Q11. What is the difference between MAP_SHARED and MAP_PRIVATE?

MAP_SHARED allows changes to be shared through compatible mappings. MAP_PRIVATE creates a private copy-on-write mapping.

Q12. What is a major page fault?

It is a page fault that requires storage I/O to obtain the required page.

Q13. What is ASLR?

ASLR randomizes selected memory-region locations to improve security.

Q14. Which file shows process memory mappings?

/proc/self/maps
