kill and killall Commands

Sending Signals to Manage and Terminate Linux Processes

Home Linux Course Chapter 7

Learning Objectives

After completing this lesson, you will be able to:

  • Understand how Linux sends signals to processes.
  • Use the kill command to signal a process using its PID.
  • Understand SIGTERM, SIGKILL and other common signals.
  • Use the killall command to signal processes by name.
  • Understand the difference between kill, killall and pkill.
  • Safely terminate and verify processes.

1. Introduction to Process Termination

Linux allows users to manage running processes by sending signals to them. A signal is a notification sent to a process to request or control a particular action.

For example, a user may want to:

  • Request a running program to terminate.
  • Forcefully stop an unresponsive process.
  • Pause or resume a process.
  • Notify a process that its terminal session has ended.

Linux provides commands such as kill, killall and pkill for sending signals.

Important: The name kill can be misleading. The command does not always terminate a process. It sends a signal, and the result depends on the signal selected.

2. kill Command

The kill command sends a signal to one or more processes identified by their Process IDs (PIDs).

Syntax

kill [options] PID

General signal-selection syntax:

kill [-s signal | -n signum | -signal] PID...

Basic Example

kill 2450

This sends the default signal, SIGTERM, to the process with PID 2450.

Check the Process Before Sending a Signal

ps -p 2450
Example output:
PID TTY TIME CMD 2450 pts/0 00:00:00 sleep
The process with PID 2450 is currently visible in the process list.

3. Common Linux Signals

A signal specifies what action should be requested from a process.

Signal Number (common Linux value) Purpose
SIGTERM 15 Requests graceful process termination.
SIGKILL 9 Forcefully terminates a process.
SIGINT 2 Interrupts a process, commonly generated by Ctrl+C.
SIGHUP 1 Traditionally indicates terminal hangup; some programs use it to reload configuration.
SIGSTOP 19 on many Linux architectures Stops a process.
SIGCONT 18 on many Linux architectures Continues a stopped process.
Signal numbers can vary between operating systems and architectures. Use symbolic signal names such as SIGTERM and SIGKILL in scripts for better portability.

List Available Signals

kill -l

This displays the signal names supported by the system.

4. SIGTERM – Graceful Termination

SIGTERM is the default signal sent by the kill command.

It requests a process to terminate. The application can handle this signal and perform cleanup operations before exiting.

Examples

kill 2450 kill -TERM 2450 kill -SIGTERM 2450 kill -15 2450

All four commands send SIGTERM to PID 2450.

Why use SIGTERM first?
  • It allows the application to close files.
  • It gives the application an opportunity to save data.
  • It allows cleanup operations before termination.

5. SIGKILL – Forceful Termination

SIGKILL immediately terminates a process. The process cannot catch, block or ignore this signal.

Examples

kill -9 2450 kill -KILL 2450 kill -SIGKILL 2450

These commands send SIGKILL to the process with PID 2450.

Warning: Do not use SIGKILL as the first choice. It prevents the application from performing its normal cleanup. Unsaved data may be lost, and temporary resources may not be released properly.

SIGTERM vs SIGKILL

Feature SIGTERM SIGKILL
Signal number 15 9
Action Requests termination Forces termination
Can be handled? Yes No
Can be ignored? Yes No
Recommended use First termination attempt Last resort

6. kill -0 – Check Process Existence and Permissions

The kill -0 command performs a signal-zero check. It does not send a normal signal that terminates or changes the process state.

Syntax

kill -0 PID

Example

kill -0 2450

If the command succeeds, the process exists and the user has permission to signal it. If it fails, the process may not exist or the user may lack permission.

Note: A successful signal-zero check does not guarantee that the process will still exist when a later command runs. Process IDs can be reused after processes exit.

7. Sending Signals to Shell Jobs

In Bash, the kill command can also accept a job specification, such as %1.

Example

sleep 300 & jobs -l kill %1

Here:

  • sleep 300 & starts a sleep process in the background.
  • jobs -l displays shell jobs and their PIDs.
  • kill %1 sends the default signal to job number 1.
Remember: A job number such as %1 is assigned by the current shell. It is not the same as a process ID. Shell job-control operations can involve process groups.

8. killall Command

The killall command sends a signal to processes selected by their process name rather than requiring individual PIDs.

Syntax

killall [options] process_name

Example

killall sleep

This sends the default signal, SIGTERM, to matching processes named sleep that the user is permitted to signal.

Send a Specific Signal

killall -TERM sleep killall -9 sleep

The first command sends SIGTERM. The second sends SIGKILL.

Common killall Options

Option Purpose
-i Ask for confirmation before terminating each process.
-I Use case-insensitive process-name matching.
-u USER Select processes belonging to a specified user.
-w Wait for matching processes to exit.
-q Do not report if no matching processes were found.
Implementation note: These options describe the commonly used Linux psmisc version of killall. Available options and behavior can differ across systems. Check your installed version using killall --help.

Check Whether killall Is Available

which killall killall --help

On Ubuntu, killall is commonly provided by the psmisc package. If it is missing, it can generally be installed using:

sudo apt update sudo apt install psmisc

9. Difference Between kill, killall and pkill

Command Process selection Example
kill PID or shell job specification kill 2450
killall Process name killall sleep
pkill Process name or pattern pkill sleep

pkill Example

pkill -TERM sleep

This sends SIGTERM to processes matching the specified name pattern.

Match the Full Command Line

pkill -f "python3 test.py"

The -f option matches against the full command line rather than only the process name.

Safety: Commands that select processes by name or pattern may affect multiple processes. Always inspect the matching processes before sending a signal.

10. Practical Lab 1 – Create and Terminate a Process

Objective: Start a background process, identify its PID and terminate it using SIGTERM.

Step 1: Start a Background Process

sleep 300 &

Step 2: Store Its PID

PID=$!

$! stores the PID of the most recently started background process.

Step 3: Display the PID

echo $PID

Step 4: Verify the Process

ps -p "$PID"

Step 5: Send SIGTERM

kill -TERM "$PID"

Step 6: Check Again

ps -p "$PID"
Expected Result:

The sleep process should terminate. The final ps command should no longer display that process once it has exited.

11. Practical Lab 2 – Check a Process Using kill -0

Objective: Understand how signal zero checks process existence and signaling permission.

Step 1: Start a Background Process

sleep 300 & PID=$!

Step 2: Check the Process

kill -0 "$PID"

Step 3: Check the Exit Status

echo $?
Expected Result:

0 indicates that the check succeeded. A non-zero status indicates failure, such as a missing process or insufficient permission.

Step 4: Clean Up

kill -TERM "$PID"

12. Practical Lab 3 – Forcefully Terminate a Test Process

Objective: Demonstrate SIGKILL on a process created specifically for this lab.

Step 1: Start a Test Process

sleep 300 & PID=$!

Step 2: Verify the Process

ps -p "$PID"

Step 3: Send SIGKILL

kill -KILL "$PID"

Step 4: Verify Termination

ps -p "$PID"
Expected Result:

The test sleep process should be forcefully terminated and should no longer appear in the process listing.

Use SIGKILL only on this controlled test process during the lab. Avoid forcefully terminating important system processes or applications containing unsaved work.

13. Practical Lab 4 – Explore killall Safely

Objective: Examine how killall selects processes by name.

Step 1: Check Available Options

killall --help

Step 2: Inspect Processes Named sleep

pgrep -a sleep

Step 3: Understand the Command

killall -TERM sleep

This command sends SIGTERM to all matching sleep processes that the user is permitted to signal.

Do not run the command in a shared or important environment unless you have confirmed that every matching sleep process can safely be terminated. It is not restricted to a single test process.

14. Important Points to Remember

  • kill sends signals to processes using PIDs or shell job specifications.
  • The default signal sent by kill is SIGTERM.
  • SIGTERM requests graceful termination.
  • SIGKILL forces termination and cannot be caught, blocked or ignored.
  • kill -0 PID checks whether a process can be signaled.
  • killall selects processes by name.
  • pkill selects processes using names or patterns.
  • Only the process owner or a sufficiently privileged user can normally signal a process.
  • Use SIGTERM before considering SIGKILL.
  • Always verify the target process before sending a signal.

15. Interview Questions and Answers

Q1. What is the kill command in Linux?

Answer: The kill command sends a specified signal to a process identified by its PID or, in a shell such as Bash, by a job specification.

Q2. What is the default signal of the kill command?

Answer: The default signal is SIGTERM, signal number 15 on Linux.

Q3. What is the difference between SIGTERM and SIGKILL?

Answer: SIGTERM requests graceful termination and can be handled by the process. SIGKILL forcefully terminates the process and cannot be caught, blocked or ignored.

Q4. What does kill -9 PID do?

Answer: It sends SIGKILL to the process with the specified PID.

Q5. What is the purpose of kill -0 PID?

Answer: It checks whether a process exists and whether the current user has permission to signal it. It does not terminate the process.

Q6. What is the killall command?

Answer: killall sends a signal to processes selected by their process name.

Q7. What is the difference between kill and killall?

Answer: kill normally selects a process using its PID, whereas killall selects processes using their names.

Q8. Can SIGKILL be handled by a program?

Answer: No. SIGKILL cannot be caught, blocked or ignored.

Q9. What is pkill?

Answer: pkill sends signals to processes selected by process name or pattern. Its -f option can match the full command line.

Q10. Why should SIGKILL be used carefully?

Answer: It does not allow the application to perform normal cleanup operations, so unsaved data or temporary resources may be lost.

16. Multiple Choice Questions (MCQs)

Q1. Which command sends the default termination signal to PID 2500?

A. stop 2500
B. kill 2500
C. remove 2500
D. exit 2500

Answer: B. kill 2500

Q2. What is the default signal of kill?

A. SIGKILL
B. SIGSTOP
C. SIGTERM
D. SIGCONT

Answer: C. SIGTERM

Q3. Which signal cannot be caught or ignored?

A. SIGTERM
B. SIGINT
C. SIGHUP
D. SIGKILL

Answer: D. SIGKILL

Q4. Which command sends SIGKILL to PID 2500?

A. kill -9 2500
B. kill -15 2500
C. kill -0 2500
D. kill -1 2500

Answer: A. kill -9 2500

Q5. Which command selects processes by name?

A. pwd
B. killall
C. mkdir
D. chmod

Answer: B. killall

Q6. What does kill -0 PID do?

A. Terminates the process
B. Pauses the process
C. Checks process existence and signaling permission
D. Restarts the process

Answer: C. Checks process existence and signaling permission

Q7. Which command can match the full command line?

A. pkill -f
B. pwd -f
C. ls -f
D. chmod -f

Answer: A. pkill -f

Q8. Which signal should normally be tried first for graceful termination?

A. SIGKILL
B. SIGSTOP
C. SIGTERM
D. SIGCONT

Answer: C. SIGTERM

17. Lesson Summary

Linux uses signals to communicate with and control processes. The kill command sends signals using process IDs or shell job specifications, while killall selects processes by name. SIGTERM is the default signal and requests graceful termination. SIGKILL forces termination when a process cannot be stopped normally. The pkill command provides another way to select processes by name or pattern.

Understanding these commands is essential for Linux process management, system administration, shell scripting and systems programming.
