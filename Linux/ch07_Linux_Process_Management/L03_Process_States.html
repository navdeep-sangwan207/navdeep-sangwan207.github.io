Process States

Understanding the Different States of Linux Processes

Home Linux Course Chapter 7

Learning Objectives

After completing this lesson, you will be able to:

  • Understand what a process state represents.
  • Identify the major Linux process states.
  • Understand running, sleeping and stopped processes.
  • Differentiate between interruptible and uninterruptible sleep.
  • Understand zombie and idle processes.
  • Interpret process state codes displayed by ps.
  • Monitor process states using Linux commands.
  • Understand basic process state transitions.

1. What is a Process State?

A process state describes the current condition of a process while it is being managed by the operating system. It indicates whether a process is executing, waiting for an event, stopped or has completed execution.

Definition: A process state is the status of a process at a particular moment during its lifetime.

Why Are Process States Important?

  • They help the kernel manage process execution.
  • They help the scheduler decide which task can run.
  • They indicate whether a process is waiting for a resource or event.
  • They help administrators troubleshoot unresponsive applications.
  • They help identify stopped and zombie processes.

2. Major Linux Process States

Linux uses several internal process states. The commonly encountered process state codes include the following:

State Code State Name Description
R Running / Runnable Currently executing on a CPU or ready to execute.
S Interruptible Sleep Waiting for an event and can normally be interrupted by signals.
D Uninterruptible Sleep Usually waiting for certain kernel operations, often I/O.
T Stopped Execution has been stopped, commonly by a job-control signal.
t Tracing Stop Stopped by a tracing or debugging mechanism.
Z Zombie Terminated process whose exit status has not yet been collected.
I Idle Idle kernel thread.
Important: These are Linux process state codes commonly displayed by process-monitoring tools. The exact internal kernel state model is more detailed than this simplified table.

3. Running or Runnable State (R)

A process in the R state is either currently executing on a CPU or waiting in a run queue for CPU time.

Two Conditions

  • Running: The process is currently executing instructions on a CPU.
  • Runnable: The process is ready to execute but is waiting for CPU scheduling.

Example

yes

The yes command continuously writes output. While it is actively executing or waiting for CPU time, it can appear in the R state.

Note: The R state does not guarantee that the process is executing on a CPU at the exact moment you inspect it. It may be runnable and waiting for scheduling.

4. Interruptible Sleep State (S)

A process enters the S state when it waits for an event, such as input, a timer or data from another process.

This is called interruptible sleep because the process can normally be awakened by an appropriate signal.

Example

sleep 100

The sleep command waits for a specified duration. During most of this waiting period, it normally appears in the S state.

Other Examples

  • A terminal waiting for user input.
  • A process waiting for a timer.
  • A process waiting for data from a pipe.
  • A service waiting for a request.
Remember: A sleeping process is not necessarily malfunctioning. Waiting is a normal part of process execution.

5. Uninterruptible Sleep State (D)

A process enters the D state when it waits in an uninterruptible sleep condition in the kernel. This commonly occurs while waiting for certain I/O operations.

Common Causes

  • Waiting for storage device operations.
  • Waiting for certain filesystem operations.
  • Waiting for a kernel operation that cannot safely be interrupted.
  • Waiting for a device or driver response.

Important Characteristics

  • The process is not using the CPU while sleeping.
  • It is waiting for a kernel-level condition to complete.
  • Ordinary signals generally do not interrupt this sleep state immediately.
  • A process may return to another state after the required event completes.
Warning: A process stuck in D state for a long time may indicate a storage, filesystem, device or driver problem. Sending SIGKILL does not normally remove it immediately while it remains in uninterruptible sleep.

6. Stopped State (T)

A process enters the T state when its execution is stopped. This can happen through job control or a signal.

Common Signals

Signal Purpose
SIGSTOP Stops a process. It cannot be caught or ignored.
SIGTSTP Requests a terminal-related stop, commonly generated by Ctrl+Z.
SIGCONT Resumes a stopped process.

Example

Start a long-running command:

sleep 300

Press:

Ctrl + Z

The shell suspends the foreground job. The process will normally appear in the T state.

To inspect it:

ps -o pid,stat,comm -C sleep

To resume it in the foreground:

fg
Note: Ctrl+Z normally sends SIGTSTP to the foreground process group. It is different from terminating a process with Ctrl+C.

7. Zombie State (Z)

A zombie process is a process that has already terminated, but its parent has not yet collected its termination status using wait() or a related system call.

How Does a Zombie Process Occur?

  1. A parent process creates a child process.
  2. The child executes its task.
  3. The child terminates.
  4. The kernel retains a small process-table entry containing its exit status.
  5. The parent has not yet collected that status.
  6. The child appears as a zombie process.

Example Process Display

PID    PPID   STAT   COMMAND
2500   1200   Z      child_process <defunct>

Important Characteristics

  • The process has already terminated.
  • It does not execute instructions.
  • It does not consume normal running-process CPU time.
  • A small process-table entry remains until its status is collected.
  • The parent should collect the child's exit status.
Important: Sending a kill signal to a zombie process does not solve the problem because the process has already terminated. The parent must collect its exit status, or the parent must terminate so the child can be reparented and handled by another process.

8. Idle State (I)

The I state is used for idle kernel threads. These are kernel-managed threads that are not currently executing work.

Important Points

  • It is mainly associated with kernel threads.
  • It indicates an idle condition.
  • It is not the same as the normal interruptible sleep state S.
  • It may appear when inspecting system processes.
Note: Ordinary user applications generally do not appear in the I state.

9. Process State Transitions

During execution, a process can move from one state to another depending on CPU scheduling, signals, I/O operations and process termination.

Simplified Process State Flow

Created | v Runnable (R) | v Running (R) / | \ / | \ v v v Sleep Stop Terminated (S/D) (T) | | | v | | Zombie (Z) | | | v v v Runnable Resume Exit status (R) (R) collected | v Removed
Note: This is a simplified conceptual flow. Actual Linux state transitions depend on kernel events, scheduling and process-management operations.

Examples of State Changes

Event Possible State Change
Process becomes ready for CPU execution Runnable (R)
Process waits for an event R to S
Process waits for certain kernel I/O R to D
Process receives SIGSTOP R or S to T
Stopped process receives SIGCONT T to R or another eligible state
Process terminates May become Z until its status is collected

10. Understanding STAT and State Modifiers

The STAT column in the ps command displays the process state and may include additional modifier characters.

Character Meaning
R Running or runnable.
S Interruptible sleep.
D Uninterruptible sleep.
T Stopped by job control signal.
t Tracing stop.
Z Zombie.
I Idle kernel thread.
< High-priority scheduling characteristic.
N Low-priority scheduling characteristic.
L Pages are locked in memory.
s Session leader.
l Multithreaded process.
+ Foreground process group.

Example

PID    STAT   COMMAND
1200   Ss     bash
1300   S      sleep
1400   R+     top
1500   T      stopped_job

These are illustrative examples. A state such as Ss combines a base state and a modifier.

11. Commands to Monitor Process States

Command 1: Display All Processes with States

ps -eo pid,ppid,stat,comm

Displays process ID, parent process ID, state and command name.

Command 2: Display Processes in Detailed Format

ps aux

Displays detailed process information, including the STAT column.

Command 3: Monitor a Specific Process

ps -p PID -o pid,ppid,stat,comm

Replace PID with the actual process ID.

Command 4: Monitor Processes Continuously

top

Displays processes and updates process information periodically.

Command 5: Find Zombie Processes

ps -eo pid,ppid,stat,comm | grep ' Z'

Searches the process listing for state strings containing a zombie state marker.

Note: This grep example is a quick inspection method, not a perfect parser for every possible ps output. For more controlled filtering, use a suitable script or inspect the STAT field separately.

Command 6: Display Process Tree

pstree -p

Displays parent-child relationships and PIDs.

12. Practical Lab

Lab 1: View Process States

Objective: Display process state information.

Command:

ps -eo pid,ppid,stat,comm

Expected Result:

Linux displays a list of processes with their PID, PPID, state and command name.

Lab 2: Create a Sleeping Process

Objective: Observe an interruptible sleeping process.

Step 1: Start a sleep process in the background.

sleep 300 &

Step 2: Display its process information.

ps -p $! -o pid,ppid,stat,comm

Expected Result:

The sleep process will normally show the S state while waiting for its timer to expire.

Lab 3: Stop a Foreground Process

Objective: Observe a stopped process.

Step 1: Execute:

sleep 300

Step 2: Press Ctrl+Z.

Step 3: Display stopped jobs.

jobs

Expected Result:

The shell displays the suspended job. Its process will normally show the T state.

Lab 4: Resume a Stopped Process

Objective: Resume the stopped job.

Command:

bg

Expected Result:

The stopped job resumes execution in the background.

Lab 5: Terminate the Sleep Process

Objective: End the background sleep process.

Command:

pkill -x sleep

Expected Result:

Matching sleep processes are sent SIGTERM. This command may affect more than one sleep process, so use it only in a controlled practice environment.
Safety: Avoid terminating unrelated system processes. For a safer lab, record the PID of the process you created and terminate only that PID with kill PID.

Lab 6: Monitor Process States in Real Time

Objective: Observe changing process information.

Command:

top

Expected Result:

The terminal displays running processes and system activity. Press q to exit top.

13. Interview Questions and Answers

Q1. What is a process state?

Answer: A process state describes the current execution condition of a process.

Q2. What does R state represent?

Answer: R represents a running or runnable process.

Q3. What does S state represent?

Answer: S represents interruptible sleep. The process is waiting for an event and can normally be awakened by a signal.

Q4. What does D state represent?

Answer: D represents uninterruptible sleep, commonly associated with certain kernel operations and I/O waits.

Q5. What does T state represent?

Answer: T represents a stopped process, commonly stopped through job control or a signal.

Q6. What is a zombie process?

Answer: A zombie is a terminated process whose exit status has not yet been collected by its parent.

Q7. What is an idle process state?

Answer: I represents an idle kernel thread.

Q8. Which command displays process states?

Answer: The command ps -eo pid,ppid,stat,comm displays process states.

Q9. What is the difference between S and D states?

Answer: S is interruptible sleep, whereas D is uninterruptible sleep in which ordinary signals generally do not interrupt the wait immediately.

Q10. Which signal resumes a stopped process?

Answer: SIGCONT resumes a stopped process.

Q11. Does a zombie process execute instructions?

Answer: No. A zombie process has already terminated and does not execute instructions.

Q12. What is the purpose of the STAT column?

Answer: The STAT column displays the process state and additional scheduling or process-status modifiers.
