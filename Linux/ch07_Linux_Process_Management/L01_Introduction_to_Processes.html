Introduction to Processes

Understanding How Linux Executes and Manages Programs

Learning Objectives

After completing this lesson, you will be able to:

  • Understand the meaning of a process in Linux.
  • Differentiate between a program and a process.
  • Understand how a process is created and executed.
  • Identify the basic components of a process.

  • Use basic commands to view running processes.
  • Understand process creation using fork() and exec().

1. What is a Process?

A process is an instance of a program that is currently executing in an operating system.

Whenever you open a terminal, launch a browser, execute a shell command or run a C program, the operating system manages the corresponding execution as a process.

Definition: A process is an active execution instance of a program, together with its execution state, memory context and allocated operating system resources.

Examples of Processes

  • Running the Firefox web browser.
  • Executing the ls command.
  • Running a C or C++ application.
  • Executing a Python script.
  • Running a background system service.
  • Opening a terminal window.

2. Program vs. Process

A program and a process are related, but they are not the same. A program is a stored set of instructions, while a process is an executing instance of those instructions.

Program Process
A passive set of instructions. An active execution instance.
Usually stored as a file on storage. Managed in memory by the operating system.
Does not need to be executing. Represents an executing or managed task.
Does not have a PID merely because it exists as a file. Has a process ID (PID) while it exists as a process.
One executable file can be launched multiple times. Each execution instance has its own process identity.

Example

Suppose you have a program named calculator. When you execute it, Linux creates a process for that execution. If you launch it again, another process may be created.

Remember: One program can have multiple processes running at the same time.

3. How Does a Process Work?

When a user starts a program, the operating system loads the required executable code and prepares the process for execution.

Basic Process Execution Flow

  1. The user enters a command or starts an application.
  2. The shell or another application requests execution.
  3. The operating system creates a process.
  4. The kernel assigns a process ID (PID).
  5. The executable code and required data are made available to it.
  6. The process becomes eligible for CPU scheduling.
  7. The CPU executes its instructions when scheduled.
  8. The process eventually terminates or waits for an event.
Note: This is a simplified execution flow. Actual process creation and program loading involve kernel operations, memory management and scheduler decisions.

4. Main Components of a Process

A process requires several resources and execution-related information to operate correctly.

Component Description
Text Segment Contains the executable machine instructions.
Data Segment Contains initialized global and static variables.
BSS Segment Contains uninitialized or zero-initialized global and static variables.
Heap Memory used for dynamic allocation.
Stack Stores function call information, local variables and related execution data.
CPU Registers Hold temporary values and processor execution information.
Process Metadata Includes process identifiers, scheduling information, credentials and state.
Important: The text, data, BSS, heap and stack describe common parts of a process's virtual address space. Their exact layout depends on the architecture and operating system.

5. Role of the Linux Kernel in Process Management

The Linux kernel is responsible for managing processes and coordinating their access to CPU time, memory and other resources.

Major Responsibilities

  • Process Creation: Creates new processes.
  • Process Scheduling: Determines which runnable task receives CPU time.
  • Memory Management: Manages process address spaces and memory mappings.
  • Resource Management: Coordinates access to files, devices and other resources.
  • Process Synchronization: Provides mechanisms for coordinating execution.
  • Signal Handling: Delivers signals to processes and manages their effects.
  • Process Termination: Handles process exit and resource cleanup.

6. Process Creation in Linux

Linux provides system calls that allow processes to create other processes and execute programs.

fork() System Call

The fork() system call creates a new process. The newly created process is called the child process, while the process that created it is called the parent process.

pid_t pid = fork();

After a successful fork(), both parent and child continue execution from the point immediately after the call, although they receive different return values.

  • In the parent process, fork() returns the child's PID.
  • In the child process, fork() returns 0.
  • If creation fails, fork() returns -1 in the parent.

exec() Family

The exec() family of functions replaces the current process image with a new program.

execl("/bin/ls", "ls", "-l", (char *)NULL);

If exec() succeeds, the previous program image is replaced and execution continues in the new program. The process ID normally remains the same.

wait() System Call

A parent process can use wait() or waitpid() to wait for a child process to change state, commonly to terminate, and collect its termination status.

wait(NULL);
Common process creation sequence:
  1. fork() creates a child process.
  2. exec() can load a different program into that child.
  3. wait() allows the parent to collect the child's exit status.

7. Process Identification

Linux identifies processes using unique process identification numbers called Process IDs (PIDs).

A process also has a parent process ID called PPID, which identifies its parent process.

Term Meaning
PID Process Identification Number.
PPID Parent Process Identification Number.
UID User Identification Number associated with process credentials.
GID Group Identification Number associated with process credentials.

These identifiers help the operating system and users distinguish and manage running processes.

8. Types of Processes in Linux

1. Foreground Process

A foreground process is associated with the terminal's foreground job. The shell normally waits for it to finish before presenting the next prompt.

2. Background Process

A background process runs without holding the terminal's foreground job position. It can be started using the & operator.

3. Daemon Process

A daemon is a background service that performs system or application tasks, often without direct interaction with a user.

4. Parent and Child Processes

A parent process can create one or more child processes. These relationships form a process hierarchy.

Note: Foreground/background describe job control in a shell. Daemon describes a service-oriented execution role. These are different ways of classifying processes.

9. Basic Commands to View Processes

Command 1: ps

Displays information about processes.

ps
Example Output: 
    PID TTY          TIME CMD
   1250 pts/0    00:00:00 bash
   1305 pts/0    00:00:00 ps

Command 2: ps aux

Displays detailed information about processes across the system.

ps aux

Command 3: pstree

Displays processes in a tree-like parent-child structure.

pstree

Command 4: pidof

Displays the PIDs of processes matching a program name.

pidof bash

Command 5: pgrep

Searches for processes by name or other supported criteria.

pgrep bash
Note: The exact output and available processes depend on your Linux system and the applications currently running. Some commands, such as pstree, may need to be installed.

10. Practical Lab

Lab 1: Display Running Processes

Objective: View processes running in the terminal.

Command:

ps

Expected Result:

The terminal displays processes associated with the current terminal session, such as the shell and the ps command.

Lab 2: Display All Processes

Objective: Display detailed process information.

Command:

ps aux

Expected Result:

Linux displays a process list containing information such as user, PID, CPU usage, memory usage, process state and command.

Lab 3: Find a Process ID

Objective: Find the PID of the Bash shell.

Command:

pgrep bash

Expected Result:

The terminal displays the PID of matching Bash processes, if any are running.

Lab 4: View the Process Tree

Objective: Understand parent-child process relationships.

Command:

pstree

Expected Result:

Linux displays a tree-like representation of processes and their parent-child relationships.

Lab 5: Display Your Shell PID

Objective: Display the PID of the current shell.

Command:

echo $$

Expected Result:

A number representing the PID of the current shell is displayed.

11. Interview Questions and Answers

Q1. What is a process in Linux?

Answer: A process is an instance of a program that is executing or being managed by the operating system.

Q2. What is the difference between a program and a process?

Answer: A program is a passive set of instructions stored as a file, whereas a process is an active execution instance of that program.

Q3. What is PID?

Answer: PID stands for Process Identification. It is a number used by Linux to identify a process.

Q4. What is PPID?

Answer: PPID stands for Parent Process ID. It identifies the parent process.

Q5. Which system call creates a new process?

Answer: The fork() system call creates a new process.

Q6. What is the purpose of exec()?

Answer: The exec() family replaces the current process image with a new program.

Q7. What is a daemon process?

Answer: A daemon is a background service that performs system or application tasks, usually without direct user interaction.

Q8. Which command displays process information?

Answer: The ps command displays information about processes.

Q9. What is the role of the Linux kernel in process management?

Answer: The kernel manages process creation, scheduling, memory, resources, signals and termination.

Q10. Can multiple processes execute the same program?

Answer: Yes. Multiple instances of the same program can run as separate processes.

12. Multiple Choice Questions (MCQs)

Q1. What is a process?

  1. A stored program file only
  2. An executing instance of a program

  4. A directory

Correct Answer: B. An executing instance of a program

  1. Program Internal Data
  2. Process Identification
  3. Primary Input Device
  4. Program Instruction Directory

Correct Answer: B. Process Identification

Q3. Which system call creates a new process?

  4. close()

Correct Answer: C. fork()

Correct Answer: A. exec()

Q5. Which command displays process information?

  1. mkdir
  2. pwd

  4. touch

Correct Answer: C. ps

Q6. What does PPID represent?

  1. Process Priority ID
  2. Parent Process ID
  3. Program Process Input
  4. Primary Program ID

Correct Answer: B. Parent Process ID

Q7. Which memory area is commonly used for dynamic allocation?

  1. Heap

13. Lesson Summary

  • A process is an executing instance of a program.
  • A program is passive, whereas a process is active.
  • Each process has a PID.
  • PPID identifies the parent process.
  • A process uses memory, CPU time and other resources.
  • The Linux kernel manages process execution and scheduling.
  • fork() creates a child process.
  • exec() replaces the current process image.
  • wait() can collect a child's termination status.
  • ps, pgrep and pstree help inspect processes.
