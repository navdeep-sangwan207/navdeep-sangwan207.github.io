nice and renice Commands

Managing Process Scheduling Priority in Linux

Home Linux Course Chapter 7

Learning Objectives

After completing this lesson, you will be able to:

  • Understand process scheduling priority in Linux.
  • Understand the meaning of nice values.
  • Use the nice command to start a process with an adjusted nice value.
  • Use the renice command to change the nice value of an existing process.
  • Inspect process priority using ps and top.
  • Understand permissions for changing nice values.

1. Introduction to Process Priority

Linux is a multitasking operating system. Multiple processes may need CPU time at the same time. The Linux scheduler decides which runnable process should receive CPU time.

Each normal process has a scheduling attribute called a nice value. It influences how the scheduler shares CPU time among competing processes.

The nice value helps users adjust the relative scheduling preference of processes.

Example: A background data-processing task can be started with a higher nice value so that it receives a lower scheduling preference compared with other normal tasks.

2. Understanding Nice Values

Linux nice values generally range from -20 to +19.

Nice Value Scheduling Preference
-20 Highest preference among normal nice values
-10 Higher preference
0 Default nice value in a typical shell session
+10 Lower preference
+19 Lowest preference among normal nice values
Important rule: A lower nice value means a higher scheduling preference. A higher nice value means a lower scheduling preference.

Conceptual Example

  • Process A: nice value -5.
  • Process B: nice value 0.
  • Process C: nice value 10.

When these processes compete for CPU time under the normal scheduling policy, Process A has a higher scheduling preference than B, and B has a higher preference than C.

Nice values do not guarantee a fixed CPU percentage or an absolute execution order. Actual CPU allocation depends on the scheduler, competing workloads, scheduling policy and other system conditions.

3. What Is the nice Command?

The nice command starts a new command with an adjusted nice value.

Syntax

nice [OPTION] [COMMAND [ARGUMENTS]...]

Start a Command with a Nice Value

nice -n 10 sleep 300

This starts the sleep command with a nice value of 10, subject to the user's permissions and scheduling limits.

Start a Background Process with Nice Value 10

nice -n 10 sleep 300 &

The command runs in the background.

Start a Command with Nice Value 5

nice -n 5 sleep 300

This starts the process with a nice value of 5.

4. Understanding nice -n

The -n option specifies the adjustment value used when starting a command.

Command Meaning
nice -n 10 command Start with a nice adjustment of +10.
nice -n 5 command Start with a nice adjustment of +5.
nice -n -5 command Request a nice adjustment of -5.

For example, if the current nice value is 0, an adjustment of +10 results in a nice value of 10.

Setting a negative nice value increases scheduling preference. Ordinary users generally need elevated privilege, such as root or the CAP_SYS_NICE capability, to make this change.

Default Behaviour

nice sleep 300

On GNU/Linux, when -n is omitted, the default adjustment is +10.

The final nice value depends on the calling process's existing nice value and the permitted adjustment. Do not assume every process always starts at exactly 0.

5. What Is the renice Command?

The renice command changes the nice value of an already running process.

Unlike nice, which adjusts the value when starting a command, renice works on an existing process.

Syntax

renice [OPTION] PRIORITY -p PID

Example

renice 10 -p 2450

This changes the nice value of the process with PID 2450 to 10.

Change the Nice Value to 15

renice 15 -p 2450

The process receives a lower scheduling preference than it would have with a nice value of 10.

Check the Result

ps -o pid,ni,pri,comm -p 2450

6. Common renice Options

Option Purpose
-p Select process IDs.
-g Select process groups.
-u Select processes belonging to a user.
-n Specify the nice-value adjustment in the usual GNU/Linux util-linux implementation.

Examples

renice 10 -p 2450 renice -n 5 -p 2450 renice 10 -u student
Implementation note: On Ubuntu, renice is commonly provided by util-linux. The meaning of -n can differ between implementations. In the common util-linux implementation, it specifies an increment to the existing nice value. The plain form renice 10 -p PID sets the target nice value to 10.

7. Permissions for Changing Nice Values

Linux controls who can change the nice values of processes.

  • A normal user can generally increase the nice value of their own processes, reducing their scheduling preference.
  • A normal user generally cannot decrease the nice value of a process to give it a higher scheduling preference.
  • Root or a process with the appropriate capability can make privileged priority changes.

Example: Increase Nice Value

renice 15 -p 2450

Example: Request a Higher Scheduling Preference

sudo renice -5 -p 2450

The second command requests a nice value of -5 and normally requires elevated privilege.

Use elevated priority carefully. Giving a process a higher scheduling preference can affect the responsiveness of other workloads.

8. Display Nice Values Using ps

The ps command can display process priority-related information.

Display PID, NI, PRI and Command

ps -eo pid,ni,pri,comm
Column Meaning
PID Process ID.
NI Nice value.
PRI Priority value reported by ps.
COMMAND Command name.

Display Information for One Process

ps -o pid,ni,pri,comm -p 2450
Example output:
PID NI PRI COMMAND 2450 10 30 sleep

The example illustrates a process with nice value 10. The reported PRI value is illustrative and can vary with kernel and scheduling details.

9. Display Nice Values Using top

The top command provides a continuously updated view of running processes.

Start top

top

Look for these columns:

Column Meaning
PID Process ID.
PR Scheduling priority shown by top.
NI Nice value.
%CPU CPU usage percentage.
COMMAND Process command.

Press q to exit top.

10. Difference Between nice and renice

Feature nice renice
Purpose Starts a command with an adjusted nice value. Changes the nice value of an existing process.
Process state New process Already running process
Typical syntax nice -n 10 command renice 10 -p PID
Use Set scheduling preference at startup. Adjust scheduling preference later.

11. Practical Lab 1 – Start a Process with nice

Objective: Start a process with a specified nice value and inspect it.

Step 1: Start a Background Process

nice -n 10 sleep 300 &

Step 2: Store Its PID

PID=$!

Step 3: Display the PID

echo "$PID"

Step 4: Check Its Nice Value

ps -o pid,ni,pri,comm -p "$PID"
Expected Result:

The process should normally show a nice value of 10 if the adjustment was permitted and the starting nice value was 0.

12. Practical Lab 2 – Change Priority Using renice

Objective: Change the nice value of an existing process.

Step 1: Start a Test Process

sleep 300 & PID=$!

Step 2: Check Its Current Nice Value

ps -o pid,ni,comm -p "$PID"

Step 3: Change the Nice Value

renice 10 -p "$PID"

Step 4: Verify the Change

ps -o pid,ni,comm -p "$PID"
Expected Result:

The process should show a nice value of 10, assuming the command succeeded and the starting nice value was 0.

Step 5: Terminate the Test Process

kill -TERM "$PID"

13. Practical Lab 3 – Compare Different Nice Values

Objective: Start multiple test processes with different nice values and compare their settings.

Step 1: Start Three Processes

nice -n 0 sleep 300 & PID1=$! nice -n 5 sleep 300 & PID2=$! nice -n 10 sleep 300 & PID3=$!

Step 2: Display Their Nice Values

ps -o pid,ni,comm -p "$PID1","$PID2","$PID3"
Expected Result:

The three processes should normally show nice values of 0, 5 and 10 respectively.

Step 3: Clean Up All Three Processes

kill -TERM "$PID1" "$PID2" "$PID3"
This lab compares configured nice values. Because sleep processes do not create significant CPU competition, it does not demonstrate a measurable CPU scheduling performance difference.

14. Important Points to Remember

  • Nice values generally range from -20 to +19.
  • A lower nice value means a higher scheduling preference.
  • A higher nice value means a lower scheduling preference.
  • The default nice value is commonly 0, but inherited values can differ.
  • nice starts a new command with an adjusted nice value.
  • renice changes the nice value of an existing process.
  • Normal users generally cannot increase the scheduling preference of their processes without additional privilege.
  • ps displays nice values using the NI column.
  • top displays nice values using the NI column.
  • Nice values influence scheduler behaviour but do not guarantee CPU allocation.

15. Interview Questions and Answers

Q1. What is process priority in Linux?

Answer: Process priority influences how the Linux scheduler allocates CPU time among runnable processes.

Q2. What is a nice value?

Answer: A nice value is a scheduling attribute that influences the relative CPU scheduling preference of a normal process.

Q3. What is the range of nice values in Linux?

Answer: The normal nice-value range is -20 to +19.

Q4. Which nice value provides the highest scheduling preference?

Answer: -20 provides the highest scheduling preference among normal nice values.

Q5. Which nice value provides the lowest scheduling preference?

Answer: +19 provides the lowest scheduling preference among normal nice values.

Q6. What is the purpose of the nice command?

Answer: It starts a new command with an adjusted nice value.

Q7. What is the purpose of the renice command?

Answer: It changes the nice value of an already running process.

Q8. Which command starts a process with nice value 10?

Answer: nice -n 10 command

Q9. How can you change the nice value of PID 2500 to 15?

Answer: renice 15 -p 2500

Q10. Which command displays the nice value of a process?

Answer: ps -o pid,ni,comm -p PID

Q11. Can a normal user set a negative nice value?

Answer: Generally, a normal user needs elevated privilege or the appropriate capability to decrease a nice value and increase scheduling preference.

Q12. Does a lower nice value guarantee more CPU time?

Answer: No. It influences relative scheduling preference but does not guarantee a fixed CPU allocation.

17. Lesson Summary

Linux uses nice values to influence the relative scheduling preference of normal processes. Nice values range from -20 to +19. A lower value represents a higher scheduling preference, while a higher value represents a lower scheduling preference.

The nice command starts a new process with an adjusted nice value. The renice command changes the nice value of an existing process. The ps and top commands help inspect process priority information.

Understanding nice and renice is useful for Linux system administration, workload management and systems programming.
