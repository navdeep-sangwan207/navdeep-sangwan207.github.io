Signals in Linux

Inter-Process Notifications and Process Control

1. Introduction to Signals

A signal is an asynchronous notification delivered to a process or thread to inform it that a particular event has occurred or that it should perform a particular action.

Signals are an important mechanism used by Linux for process communication and control.

Examples of Signal Events

  • Pressing Ctrl+C in a terminal.
  • Requesting a process to terminate.
  • Stopping or continuing a process.
  • A program attempting an invalid memory access.
  • A child process terminating.
  • A terminal session being disconnected.
Example: When you press Ctrl+C while a command is running in the foreground, the terminal normally sends SIGINT to the foreground process group.

2. How Signals Work

A signal can be generated by the kernel, a terminal, another process or a hardware-related event.

Basic Signal Flow

Event occurs | v Signal is generated | v Signal is delivered to a process | v Process handles the signal | v Default action / Custom handler / Ignore

Explanation

  1. An event occurs in the system.
  2. The kernel or another source generates a signal.
  3. The signal is made pending for the target process or thread.
  4. The signal is delivered when the process is able to handle it according to its signal mask and execution state.
  5. The process performs the default action, executes a handler or ignores the signal, depending on the signal and its configuration.
Signals are asynchronous notifications. They are not the same as ordinary function calls or messages containing arbitrary amounts of data.

3. Types and Sources of Signals

Signals can originate from several sources.

Source Example
Terminal Ctrl+C generates SIGINT for the foreground process group.
Kernel SIGCHLD notification when a child process changes state.
Another process A process sends SIGTERM using kill.
Hardware-related exception Invalid memory access may generate SIGSEGV.
Timer A timer can generate SIGALRM.

4. Common Linux Signals

Signal Common Number Purpose
SIGHUP 1 Terminal hangup notification.
SIGINT 2 Interrupt signal, commonly Ctrl+C.
SIGQUIT 3 Quit signal, commonly Ctrl+\.
SIGKILL 9 Forceful process termination.
SIGSEGV 11 Invalid memory access.
SIGPIPE 13 Write to a pipe or socket with no reader.
SIGALRM 14 Alarm timer expiration.
SIGTERM 15 Graceful termination request.
SIGCHLD 17 on common Linux architectures Child process state change notification.
SIGCONT 18 on common Linux architectures Continue a stopped process.
SIGSTOP 19 on common Linux architectures Stop a process.
SIGTSTP 20 on common Linux architectures Terminal stop signal, commonly Ctrl+Z.
Signal numbers can vary by architecture and operating system. Prefer symbolic names such as SIGTERM and SIGINT in programs and scripts.

Display Available Signals

kill -l

Display the Number for a Signal

kill -l SIGTERM

5. Default Actions of Signals

When a signal is delivered, the operating system applies its default action unless the process has configured another permitted behaviour.

Default Action Description
Terminate The process exits.
Core dump The process terminates and may produce a core dump.
Stop The process is stopped.
Continue A stopped process resumes execution.
Ignore The signal has no effect under its default disposition.
A process may change the handling of many signals, but SIGKILL and SIGSTOP are special exceptions.

6. Important Signals for Process Control

SIGINT

SIGINT interrupts a process. It is commonly generated when a user presses Ctrl+C in a terminal.

sleep 300

Press Ctrl+C to interrupt the foreground sleep command.

SIGTERM

SIGTERM requests graceful termination.

kill -TERM PID

SIGKILL

SIGKILL forces process termination. It cannot be caught, blocked or ignored.

kill -KILL PID

SIGSTOP

SIGSTOP stops a process. It cannot be caught, blocked or ignored.

kill -STOP PID

SIGCONT

SIGCONT resumes a stopped process.

kill -CONT PID

7. SIGKILL and SIGSTOP Cannot Be Handled

Most signals can be handled, blocked or ignored by a process. However, two important signals cannot be controlled in this way.

Signal Can be caught? Can be ignored? Can be blocked?
SIGKILL No No No
SIGSTOP No No No
SIGKILL should be used only when normal termination methods fail. SIGSTOP immediately stops a process without giving it an opportunity to perform cleanup.

8. Sending Signals Using kill

The kill command sends a signal to a process using its PID.

Syntax

kill -SIGNAL PID

Examples

kill -TERM 2450 kill -INT 2450 kill -STOP 2450 kill -CONT 2450 kill -KILL 2450

Check Whether a Process Can Be Signaled

kill -0 2450

Signal zero checks process existence and permission to signal it. It does not terminate or stop the process.

9. Signals and Keyboard Shortcuts

Interactive terminals can generate signals using special keyboard combinations.

Keyboard Shortcut Signal Purpose
Ctrl+C SIGINT Interrupt foreground process group.
Ctrl+Z SIGTSTP Request a stop for foreground process group.
Ctrl+\ SIGQUIT Quit foreground process group.
These shortcuts are terminal-generated signals, not ordinary keyboard input delivered directly to the application. Terminal settings can change the configured control characters.

10. Signals in Bash Shell Scripts – trap

Bash provides the trap builtin to execute commands when a shell receives certain signals or shell events.

Syntax

trap 'commands' SIGNAL

Example: Handle SIGINT

#!/bin/bash trap 'echo "SIGINT received"' INT echo "Press Ctrl+C to test the trap." while true do sleep 1 done

Explanation

  • #!/bin/bash identifies Bash as the interpreter.
  • trap registers a command to run when SIGINT is received.
  • echo displays a message.
  • The loop keeps the script running.

When Ctrl+C is pressed, Bash executes the trap command. The script can continue running because the trap handles the signal instead of applying the normal termination action.

Run the Script

nano signal_demo.sh chmod +x signal_demo.sh ./signal_demo.sh
The trap is handled by the Bash shell. A foreground external command such as sleep may receive terminal-generated signals as part of the foreground process group, so exact interactive behaviour depends on which process is running.

11. More trap Examples

Handle SIGTERM

#!/bin/bash trap 'echo "Termination request received"' TERM while true do sleep 2 done

Handle Multiple Signals

#!/bin/bash trap 'echo "Interrupt received"' INT trap 'echo "Termination requested"' TERM while true do sleep 2 done

Remove a Trap

trap - INT

This resets the SIGINT trap to its default disposition in the current shell.

Ignore a Signal in Bash

trap '' INT

This configures the shell to ignore SIGINT.

A shell cannot override SIGKILL or SIGSTOP. No trap can be installed for these signals.

12. Signal Handling in C Programming

C programs running on Linux can handle certain signals using signal-handling functions.

The traditional signal() function provides a simple interface. For robust POSIX signal handling, sigaction() is generally preferred.

Basic Syntax

signal(signal_number, handler_function);

Example: Handle SIGINT in C

#include <stdio.h> #include <signal.h> #include <unistd.h> void handle_sigint(int signum) { (void)signum; write(STDOUT_FILENO, "SIGINT received\n", 16); } int main(void) { signal(SIGINT, handle_sigint); while (1) { pause(); } return 0; }

Explanation

  • signal.h provides signal-related declarations.
  • unistd.h provides the POSIX write() and pause() functions.
  • handle_sigint() is the signal handler.
  • signal(SIGINT, handle_sigint) registers the handler.
  • pause() suspends execution until a signal is caught.

Compile the Program

gcc signal_demo.c -o signal_demo

Run the Program

./signal_demo

Press Ctrl+C. The registered signal handler displays a message. Because the program handles SIGINT without terminating, it can continue waiting for another signal.

Advanced programming note: Signal handlers have strict restrictions. Use only async-signal-safe functions inside a handler. Avoid functions such as printf() in a signal handler. For production POSIX programs, prefer sigaction() and carefully manage shared state.

13. Understanding sigaction()

sigaction() is the preferred POSIX interface for installing signal handlers because it provides more control over signal handling.

Basic Syntax

int sigaction( int signum, const struct sigaction *act, struct sigaction *oldact );

Important Structure Members

Member Purpose
sa_handler Specifies a simple signal handler or special disposition.
sa_sigaction Specifies a handler that receives additional information when SA_SIGINFO is used.
sa_mask Specifies additional signals to block while the handler executes.
sa_flags Specifies options that control signal handling.
Important: sigaction() is commonly used in systems programming because it provides more predictable and configurable signal-handling behaviour than the traditional signal() interface.

14. Signals and Process Management Commands

Linux provides several commands for selecting processes and sending signals.

Command Purpose Example
kill Sends a signal using PID or shell job specification. kill -TERM 2450
killall Sends a signal to matching process names. killall -TERM sleep
pkill Selects processes using names or patterns. pkill -TERM sleep
ps Displays process information. ps -ef
pgrep Finds PIDs by process name or pattern. pgrep sleep

15. Practical Lab 1 – Send SIGTERM to a Process

Objective: Start a process and terminate it using SIGTERM.

Step 1: Start a Background Process

sleep 300 &

Step 2: Store Its PID

PID=$!

Step 3: Check the Process

ps -p "$PID"

Step 4: Send SIGTERM

kill -TERM "$PID"

Step 5: Verify

ps -p "$PID"
Expected Result:

The test process should terminate gracefully and disappear from the process listing once it has exited.

16. Practical Lab 2 – Stop and Continue a Process

Objective: Understand SIGSTOP and SIGCONT.

Step 1: Start a Background Process

sleep 300 & PID=$!

Step 2: Stop the Process

kill -STOP "$PID"

Step 3: Check Its State

ps -o pid,stat,comm -p "$PID"

The process state should indicate that it is stopped, commonly using the T state.

Step 4: Continue the Process

kill -CONT "$PID"

Step 5: Check Its State Again

ps -o pid,stat,comm -p "$PID"

The process should return to a runnable or sleeping state, depending on its activity.

Step 6: Terminate the Test Process

kill -TERM "$PID"
Expected Result:

The process changes from running/sleeping to stopped, resumes after SIGCONT, and finally terminates after SIGTERM.

18. Important Points to Remember

  • A signal is an asynchronous notification delivered to a process or thread.
  • Signals can be generated by the kernel, terminal, another process or hardware-related events.
  • SIGINT is commonly generated by Ctrl+C.
  • SIGTSTP is commonly generated by Ctrl+Z.
  • SIGTERM requests graceful termination.
  • SIGKILL forces termination.
  • SIGSTOP stops a process.
  • SIGCONT resumes a stopped process.
  • SIGKILL and SIGSTOP cannot be caught, blocked or ignored.
  • Bash uses the trap builtin for shell signal handling.
  • C programs can use signal() or sigaction() to handle signals.
  • sigaction() is generally preferred for robust POSIX signal handling.

19. Interview Questions and Answers

Q1. What is a signal in Linux?

Answer: A signal is an asynchronous notification sent to a process or thread to indicate that an event has occurred or an action is required.

Q2. What is SIGINT?

Answer: SIGINT is an interrupt signal commonly generated when the user presses Ctrl+C in a terminal.

Q3. What is SIGTERM?

Answer: SIGTERM requests a process to terminate gracefully.

Q4. What is SIGKILL?

Answer: SIGKILL is a forceful termination signal that cannot be caught, blocked or ignored.

Q5. What is the difference between SIGSTOP and SIGCONT?

Answer: SIGSTOP stops a process, while SIGCONT resumes a stopped process.

Q6. Which signal is generated by Ctrl+C?

Answer: SIGINT.

Q7. Which signal is generated by Ctrl+Z in a typical terminal?

Answer: SIGTSTP.

Q8. What is the purpose of the trap command?

Answer: The Bash trap builtin registers commands to execute when the shell receives specified signals or shell events.

Q9. What is a signal handler?

Answer: A signal handler is a function registered by a program to handle a particular signal.

Q10. Which function is preferred for POSIX signal handling?

Answer: sigaction() is generally preferred because it provides more control over signal handling.

Q11. Can a program catch SIGKILL?

Answer: No. SIGKILL cannot be caught, blocked or ignored.

Q12. What is SIGCHLD?

Answer: SIGCHLD is sent to a parent process when a child process changes state, such as when it terminates or stops.

Q13. What is SIGSEGV?

Answer: SIGSEGV indicates an invalid memory access, commonly associated with a segmentation fault.

Q14. What is SIGPIPE?

Answer: SIGPIPE is generated when a process writes to a pipe or socket that has no reader.

Q15. Why should printf() generally be avoided inside a signal handler?

Answer: printf() is not async-signal-safe. Calling it from a signal handler can cause undefined or unreliable behaviour. Use only async-signal-safe operations inside handlers.
