jobs, bg and fg Commands

Managing Foreground, Background and Stopped Jobs

Home Linux Course Chapter 7

Learning Objectives

After completing this lesson, you will be able to:

  • Understand shell job control.
  • Use the jobs command to list shell jobs.
  • Understand job numbers and job specifications.
  • Use the bg command to resume stopped jobs in the background.
  • Use the fg command to bring jobs into the foreground.
  • Manage multiple jobs in one terminal session.
  • Understand the difference between a job and a process.
  • Apply job-control commands through practical exercises.

1. Introduction to Shell Job Control

Linux shells such as Bash provide job-control features that allow users to manage multiple jobs from one terminal.

A job may contain one process or multiple processes connected through a pipeline.

Using job control, a user can:

  • List running and stopped jobs.
  • Start commands in the background.
  • Suspend foreground jobs.
  • Resume stopped jobs in the background.
  • Bring background jobs into the foreground.
Definition: Job control is a shell feature that manages the execution and terminal relationship of foreground, background and stopped jobs.

2. Understanding Jobs and Job Numbers

When a command is started in the background or suspended, the shell can assign it a job number.

Example

sleep 200 &
[1] 2450
  • [1] is the shell job number.
  • 2450 is the process ID in this example.

Job Number vs Process ID

Job Number Process ID (PID)
Assigned by the current shell. Assigned by the Linux kernel.
Used by shell job-control commands. Used to identify a process system-wide.
Written using a percent sign, such as %1. Written as a numeric process ID.
Valid within the relevant shell session. Can be inspected using process-monitoring commands.
Important: A job may contain multiple processes, so its job number does not necessarily identify only one process.

3. jobs Command

The jobs command displays the jobs managed by the current shell.

Syntax

jobs [options] [job_spec]

Start a Background Job

sleep 200 &

List Jobs

jobs
[1]+  Running    sleep 200 &

Understanding the Output

Output Meaning
[1] Job number 1.
+ Current job in the shell.
- Previous job in the shell.
Running The job is executing.
Stopped The job is suspended.

Important jobs Options

Command Purpose
jobs List current shell jobs.
jobs -l List jobs with process IDs.
jobs -p Display process IDs of job process-group leaders.
jobs -r Display running jobs.
jobs -s Display stopped jobs.

List Jobs with Process IDs

jobs -l

List Only Running Jobs

jobs -r

List Only Stopped Jobs

jobs -s

4. Job Specifications

Shell job-control commands use job specifications to identify particular jobs.

Job Specification Meaning
%1 Job number 1.
%2 Job number 2.
%+ or %% Current job.
%- Previous job.
%string Job whose command line begins with string, when unambiguous.
%?string Job whose command line contains string, when unambiguous.
Note: Job specifications are shell features. Their exact behavior can vary between shells. The examples here follow Bash job-control conventions.

5. bg Command

The bg command resumes a stopped job in the background.

It allows a suspended job to continue execution without occupying the terminal's foreground job position.

Syntax

bg [job_spec]

Example: Suspend a Foreground Process

sleep 200

Press Ctrl+Z while the command is running.

^Z
[1]+  Stopped    sleep 200

Resume the Stopped Job in the Background

bg
[1]+ sleep 200 &
The stopped job resumes in the background.

Resume a Specific Job

bg %1

This resumes job number 1 in the background.

Important Points

  • bg is used to resume stopped jobs.
  • It does not normally terminate the process.
  • The shell prompt remains available.
  • The resumed job continues executing in the background.
Terminal input warning: A job resumed in the background may receive SIGTTIN if it attempts to read from its controlling terminal.

6. fg Command

The fg command brings a background or stopped job into the foreground.

After a job is brought to the foreground, the terminal gives it foreground control.

Syntax

fg [job_spec]

Example: Start a Background Job

sleep 200 &

Bring the Job into the Foreground

fg

The shell brings the current job into the foreground.

Bring a Specific Job into the Foreground

fg %1

This brings job number 1 into the foreground.

Expected Behavior

The terminal becomes occupied by the selected foreground job. The shell prompt normally returns after that job completes or is suspended.

Important Points

  • fg brings a selected job to the foreground.
  • It can resume a stopped job in the foreground.
  • The shell waits for the foreground job.
  • Ctrl+C and Ctrl+Z can be used to control the foreground job.

7. Difference Between jobs, bg and fg

Command Function
jobs Displays jobs managed by the current shell.
bg Resumes a stopped job in the background.
fg Brings a job into the foreground.
Remember:
  • jobs = List jobs.
  • bg = Continue in the background.
  • fg = Continue in the foreground.

8. Managing Multiple Jobs

A shell can manage multiple jobs at the same time. Each job can be selected using its job specification.

Example: Start Three Background Jobs

sleep 100 & sleep 200 & sleep 300 &

List All Jobs

jobs
[1]   Running    sleep 100 &
[2]-  Running    sleep 200 &
[3]+  Running    sleep 300 &

The job numbers and current/previous job indicators are illustrative. The shell assigns them according to its job-control state.

Bring Job 1 into the Foreground

fg %1

Resume Job 2 in the Background

bg %2

Check Jobs Again

jobs

9. Job Control Workflow

Step 1: Start a foreground process.
sleep 200
Step 2: Suspend it using Ctrl+Z. Step 3: List the job.
jobs
Step 4: Resume it in the background.
bg
Step 5: Bring it into the foreground.
fg
Step 6: Allow it to complete or interrupt it using Ctrl+C.

10. Important Limitations of Shell Job Control

  • Job numbers belong to the current shell.
  • Another terminal has its own separate job list.
  • Jobs may disappear from the list after completion.
  • Job-control commands require an appropriate interactive shell environment.
  • Background jobs may still depend on terminal input and output.
  • Closing a terminal can affect its jobs, depending on shell and session behavior.

What If You Need a Process to Continue After Logout?

Shell job control alone is not a reliable way to keep a process running after logout.

Linux provides other tools and approaches, including:

  • nohup for ignoring hangup signals.
  • disown in supported shells such as Bash.
  • tmux and screen for persistent terminal sessions.
  • systemd for managing services.
These tools are different from the basic jobs, bg and fg commands. They are useful when a process must survive terminal disconnection or be managed as a service.

11. Practical Lab

Lab 1: Start a Background Job

Objective: Start a process in the background.

Command:

sleep 200 &

Expected Result:

The shell displays a job number and process ID. The prompt returns immediately.

Lab 2: Display All Jobs

Objective: List jobs managed by the shell.

Command:

jobs

Expected Result:

The shell displays the current jobs and their states.

Lab 3: Suspend a Foreground Process

Objective: Suspend a running command.

Steps:

  1. Run sleep 200.
  2. Press Ctrl+Z.
  3. Run jobs.

Expected Result:

The sleep job appears with the Stopped state.

Lab 4: Resume a Stopped Job in the Background

Objective: Continue a suspended process in the background.

Command:

bg

Expected Result:

The stopped job resumes in the background.

Lab 5: Bring a Background Job into the Foreground

Objective: Move a background job into the foreground.

Command:

fg

Expected Result:

The selected job takes foreground terminal control.

Lab 6: Manage a Specific Job

Objective: Select a job using its job number.

Commands:

sleep 100 & sleep 200 & jobs fg %1

Expected Result:

Job number 1 is brought into the foreground.

Lab 7: List Running and Stopped Jobs Separately

Objective: Filter the current shell job list.

Commands:

jobs -r jobs -s

Expected Result:

The first command lists running jobs, and the second lists stopped jobs.
Lab cleanup: Use short-duration sleep commands for practice. They complete automatically. Do not terminate unrelated system or application processes.

12. Interview Questions and Answers

Q1. What is job control in Linux?

Answer: Job control is a shell feature used to manage foreground, background and stopped jobs.

Q2. What is the purpose of the jobs command?

Answer: It displays jobs managed by the current shell.

Q3. What is the purpose of the bg command?

Answer: It resumes a stopped job in the background.

Q4. What is the purpose of the fg command?

Answer: It brings a background or stopped job into the foreground.

Q5. What does %1 represent?

Answer: It represents job number 1 in the current shell.

Q6. What is the difference between a job number and a PID?

Answer: A job number is assigned by the shell, whereas a PID identifies a process in the kernel.

Q7. What does jobs -l display?

Answer: It displays jobs along with their process IDs.

Q8. What does jobs -r display?

Answer: It lists running jobs.

Q9. What does jobs -s display?

Answer: It lists stopped jobs.

Q10. Can bg resume a stopped process?

Answer: Yes. It resumes a stopped job in the background.

Q11. Can fg bring a stopped job into the foreground?

Answer: Yes. It resumes the selected stopped job in the foreground.

Q12. Are job numbers shared between terminals?

Answer: No. Job numbers are maintained separately by each shell.

Q1. Which command lists jobs in the current shell?

  3. top
  4. pwd

Correct Answer: B. jobs

Q2. Which command resumes a stopped job in the background?

  1. fg
  2. ps

  4. top

Correct Answer: C. bg

Q3. Which command brings a job into the foreground?

Correct Answer: B. fg

Q4. What does %2 represent?

  1. PID 2

Correct Answer: B. Job number 2

Q5. Which option displays job process IDs?

  1. jobs -l

Correct Answer: A. jobs -l

Q6. Which command lists only running jobs?

  1. jobs -s

Correct Answer: B. jobs -r

Q7. Which command lists only stopped jobs?

  1. jobs -r
  2. jobs -p
  3. jobs -s
  4. jobs -l

Correct Answer: C. jobs -s

Q8. Who assigns shell job numbers?

  1. BIOS
  2. Linux kernel
  3. Current shell
  4. CPU

Correct Answer: C. Current shell

Q9. Which symbol is used in a job specification?

  1. #
  2. %

  4. $

Correct Answer: B. %

Q10. Which command brings job number 1 into the foreground?

  1. bg %1

  3. fg %1

Correct Answer: C. fg %1

  • Job control manages shell jobs in a terminal session.
  • A job may contain one or multiple processes.
  • jobs lists the jobs managed by the current shell.
  • jobs -l displays job process IDs.
  • jobs -r lists running jobs.
  • jobs -s lists stopped jobs.
