Foreground and Background Processes

Understanding Process Execution and Shell Job Control

Home Linux Course Chapter 7

Learning Objectives

After completing this lesson, you will be able to:

  • Understand foreground and background processes.
  • Differentiate between foreground and background execution.
  • Run commands in the background using the ampersand operator.
  • Understand terminal control and process execution.
  • Use Ctrl+C and Ctrl+Z correctly.
  • Understand suspended and running jobs.
  • Manage multiple commands in a shell session.
  • Use background execution for long-running tasks.

1. Introduction to Foreground and Background Processes

Linux allows commands and processes to execute in two common ways: foreground and background.

  • Foreground process: A process that is attached to the terminal's foreground job and normally interacts with the user.
  • Background process: A process that runs without holding the terminal's foreground control.
Definition: Foreground and background execution describe how a shell manages jobs in relation to the terminal.

Why Are They Important?

  • Run long-running commands without blocking the shell prompt.
  • Perform multiple tasks from one terminal.
  • Monitor and manage running jobs.
  • Run compilation, backup and data-processing commands.
  • Understand Linux shell job control.

2. Foreground Process

A foreground process is a job currently controlled by the terminal's foreground process group.

When a foreground command is running, the shell normally waits for it to finish before displaying the next prompt.

Example

sleep 10

The sleep command pauses execution for 10 seconds. When executed without the background operator, it runs in the foreground. 

$ sleep 10
The terminal waits for the command to complete. The shell prompt returns after approximately 10 seconds.

Another Example

nano file.txt

The nano text editor normally runs in the foreground and receives keyboard input from the terminal.

Characteristics of Foreground Processes

  • Normally receive terminal keyboard input.
  • Can display output directly in the terminal.
  • Usually prevent the shell from accepting another command until completion.
  • Can be interrupted or suspended using terminal control keys.

3. Background Process

A background job executes without occupying the terminal's foreground job position.

The shell normally returns the prompt immediately, allowing the user to enter another command.

Syntax

command &

The ampersand (&) placed at the end of a shell command requests asynchronous background execution.

Example

sleep 100 &
[1] 2450
Explanation:
  • [1] represents the shell job number.
  • 2450 is an illustrative process ID.

The shell prompt becomes available immediately, while the sleep command continues running in the background.

Check the Process

ps

You can use ps to inspect processes, including the background sleep process.

Characteristics of Background Processes

  • Do not occupy the terminal's foreground job position.
  • Allow the shell prompt to return immediately.
  • Can run while other commands are entered.
  • Can be monitored using jobs and ps.
  • May still write output or errors to the terminal unless redirected.
Important: A background job is not necessarily independent of the terminal. It may still share the terminal's input and output streams.

4. Difference Between Foreground and Background Processes

Foreground Process Background Process
Runs as the terminal's foreground job. Runs without foreground terminal control.
Shell normally waits for completion. Shell normally returns the prompt immediately.
Can receive terminal input. Normally should not read from the terminal.
Started without a trailing ampersand. Commonly started with a trailing ampersand.
Can be interrupted using Ctrl+C. Can be managed using job-control commands.
Useful for interactive commands. Useful for tasks that can run while the shell remains available.

5. Running Commands in the Background Using &

The ampersand operator allows a shell to start a command asynchronously.

Example 1: Run sleep in the Background

sleep 60 &

Example 2: Run Multiple Background Commands

sleep 100 & sleep 200 & sleep 300 &

Each command is started as a separate background job.

Example 3: Run a Long-Running Command

find /usr -name "*.conf" &

This starts a file-search operation in the background. Its output may still appear in the terminal.

Tip: For commands that generate large amounts of output, redirect standard output and standard error to files to keep the terminal readable.

6. Redirecting Background Process Output

Background jobs can write output to the terminal. Redirection allows their output to be saved in files.

Redirect Standard Output

sleep 60 > output.txt &

This redirects standard output to output.txt.

Redirect Standard Error

command 2> error.txt &

Redirect Both Standard Output and Standard Error

command > output.txt 2>&1 &

Standard output and standard error are both redirected to output.txt.

Discard Output

command > /dev/null 2>&1 &

Both standard output and standard error are discarded.

Note: Output redirection controls where output goes; it does not by itself make a process independent of the terminal session.

7. Controlling Foreground Processes

Linux terminals provide keyboard shortcuts for controlling foreground jobs.

Ctrl+C: Interrupt a Foreground Process

Pressing Ctrl+C normally sends the SIGINT signal to the terminal's foreground process group.

sleep 100 Press Ctrl+C
^C
$
The foreground sleep process is normally interrupted, and the shell prompt returns.

Ctrl+Z: Suspend a Foreground Process

Pressing Ctrl+Z normally sends SIGTSTP to the terminal's foreground process group, suspending the job.

sleep 100 Press Ctrl+Z
^Z
[1]+  Stopped    sleep 100
$
Important distinction:
  • Ctrl+C normally interrupts a foreground job.
  • Ctrl+Z normally suspends a foreground job.
  • A suspended job is not the same as a terminated job.

8. Terminal Job Control

Job control is a shell feature that allows users to manage multiple jobs associated with a terminal session.

A job can contain one process or multiple processes connected through a pipeline.

Important Job States

State Description
Running The job is currently executing.
Stopped The job has been suspended.
Done The job has completed.
Terminated The job has ended due to a signal or other termination condition.

Shell Job Number and PID

A shell job number is different from a process ID. 

[2] 3100
  • 2 is the shell job number.
  • 3100 is the process ID in this example.
Note: Job numbers are assigned by the current shell. They are not system-wide process IDs.

9. Difference Between Background and Daemon Processes

Background processes and daemon processes are related concepts, but they are not identical.

Background Process Daemon Process
Runs without foreground terminal control. Runs as a service or background system process.
Can be started directly from a shell using &. Usually managed by a service manager such as systemd.
May remain associated with its terminal session. Normally operates independently of an interactive terminal.
May be temporary. Often provides a continuing service.

Examples of Daemon Services

  • SSH service.
  • Cron service.
  • Network management services.
  • Logging services.
Remember: A process started with & is a background job, but it does not automatically become a daemon.

10. Useful Commands

Command / Shortcut Purpose
command & Start a command in the background.
Ctrl+C Normally interrupt the foreground process group.
Ctrl+Z Normally suspend the foreground process group.
jobs List jobs in the current shell.
ps Display a process snapshot.
top Monitor processes interactively.
fg Bring a job to the foreground.
bg Resume a stopped job in the background.
kill Send a signal to a process or job target.

The fg and bg commands are explained in detail in the next lesson.

11. Practical Lab

Lab 1: Run a Foreground Process

Objective: Execute a process in the foreground.

Command:

sleep 20

Expected Result:

The terminal waits for approximately 20 seconds. The shell prompt returns after the command completes.

Lab 2: Run a Background Process

Objective: Execute a command without blocking the shell prompt.

Command:

sleep 100 &

Expected Result:

The shell displays a job number and process ID. The shell prompt returns immediately.

Lab 3: Run Multiple Background Jobs

Objective: Start multiple background jobs.

Commands:

sleep 100 & sleep 200 & sleep 300 &

Expected Result:

Three background jobs are started. Their job numbers and process IDs are displayed by the shell.

Lab 4: Suspend a Foreground Process

Objective: Suspend a running foreground process.

Steps:

  1. Run sleep 100.
  2. Press Ctrl+Z.
  3. Observe the stopped-job message.
  4. Run jobs to inspect the job.

Lab 5: Interrupt a Foreground Process

Objective: Interrupt a foreground process.

Steps:

  1. Run sleep 100.
  2. Press Ctrl+C.
  3. Observe that the shell prompt returns.

Lab 6: Redirect Background Output

Objective: Save command output in a file.

Command:

find /usr -name "*.conf" > search_output.txt 2>&1 &

Expected Result:

The search runs in the background. Its standard output and standard error are redirected to search_output.txt.

Lab 7: Check Background Processes

Objective: Inspect a running background process.

Commands:

sleep 100 & ps

Expected Result:

The process list displays the sleep process while it is running.
Lab cleanup: The sleep jobs used in these exercises finish automatically after their specified time. Do not terminate unrelated system processes during practice.

12. Interview Questions and Answers

Q1. What is a foreground process?

Answer: A foreground process is a job currently controlled by the terminal's foreground process group.

Q2. What is a background process?

Answer: A background process runs without occupying the terminal's foreground job position.

Q3. Which operator is used to start a background command?

Answer: The ampersand operator (&).

Q4. What happens when Ctrl+C is pressed?

Answer: The terminal normally sends SIGINT to the foreground process group.

Q5. What happens when Ctrl+Z is pressed?

Answer: The terminal normally sends SIGTSTP to suspend the foreground process group.

Q6. What is job control?

Answer: Job control is a shell feature for managing foreground, background and stopped jobs.

Q7. Does a background process always run independently of the terminal?

Answer: No. A background job may still depend on the terminal for input, output or error streams.

Q8. What is the difference between a background job and a daemon?

Answer: A background job is a shell-managed job without foreground control. A daemon is a service-like process that normally operates independently of an interactive terminal.

Q9. Can multiple background jobs run at the same time?

Answer: Yes. A shell can manage multiple background jobs in one terminal session.

Q10. What happens after a foreground command completes?

Answer: The shell normally displays the prompt and waits for the next command.

Q1. Which symbol is used to run a command in the background?

  1. |
  2. &

  4. ;

Correct Answer: B. &

Q2. Which shortcut normally interrupts a foreground process?

  1. Ctrl+C
  2. Ctrl+Z
  3. Ctrl+S
  4. Ctrl+D

Correct Answer: A. Ctrl+C

Q3. Which shortcut normally suspends a foreground process?

  1. Ctrl+C
  2. Ctrl+Z
  3. Ctrl+V
  4. Ctrl+P

Correct Answer: B. Ctrl+Z

Q4. Which command lists jobs in the current shell?

  1. pwd
  2. jobs
  3. mkdir
  4. chmod

  1. The shell exits.
  2. The command is deleted.
  3. The shell prompt returns immediately.

Correct Answer: C. The shell prompt returns immediately.

Q6. What does Ctrl+Z normally send?

  1. SIGKILL
  2. SIGTERM
  3. SIGTSTP
  4. SIGCONT

Correct Answer: C. SIGTSTP

Q7. Is every background process a daemon?

  1. Yes

  4. Only in root mode

Correct Answer: B. No

Q8. Which command starts a 60-second background job?

  1. sleep 60
  2. sleep 60 &

Correct Answer: B. sleep 60 &

Q9. Which command displays a process snapshot?

  2. mkdir

Q10. Can a background process still write output to the terminal?

14. Lesson Summary

  • Foreground processes use the terminal's foreground job control.
  • Background processes run without occupying the foreground job position.
  • The ampersand operator starts a command asynchronously.
  • Ctrl+C normally sends SIGINT to the foreground process group.
  • Ctrl+Z normally sends SIGTSTP to the foreground process group.
  • A suspended process is not necessarily terminated.
  • Background jobs may still produce terminal output.
  • Job control allows management of multiple shell jobs.
  • A background job is not automatically a daemon.
