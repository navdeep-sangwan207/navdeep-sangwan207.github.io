1. Introduction to the ps Command

The ps command stands for Process Status. It displays information about processes running in a Linux system.

It is commonly used by system administrators and developers to inspect processes, identify process IDs, check process states and investigate resource usage.

Definition: The ps command displays a snapshot of process information at the time the command is executed.

Why Use ps?

  • To identify running processes.
  • To find the PID and PPID of a process.
  • To inspect process states.
  • To identify which user owns a process.
  • To examine CPU and memory usage.
  • To troubleshoot applications and system services.

2. Basic Syntax of ps

Syntax

ps [options]

The options control which processes are displayed and which information appears in the output.

Basic Command

ps

Displays processes associated with the current terminal session.

Example Output

    PID TTY          TIME CMD
   1250 pts/0    00:00:00 bash
   1400 pts/0    00:00:00 ps
Column Meaning
PID Process ID.
TTY Controlling terminal associated with the process.
TIME Accumulated CPU time used by the process.
CMD Command name or command being executed.
Note: PID values and output vary according to the system and currently running processes.

3. Display All Processes

Command 1: ps -e

ps -e

The -e option selects all processes.

Command 2: ps -ef

ps -ef

Displays all processes using a full-format listing.

Example Output: 
UID       PID  PPID  C STIME TTY          TIME CMD
root        1     0  0 08:00 ?        00:00:02 /sbin/init
user     1250  1200  0 09:00 pts/0    00:00:00 bash
user     1400  1250  0 09:10 pts/0    00:00:00 ps -ef

Command 3: ps aux

ps aux

Displays a detailed process listing, including user, CPU usage, memory usage and process state.

Important: ps -ef uses the System V-style option format, while ps aux uses BSD-style options. They are different option conventions supported by common Linux ps implementations.

4. Understanding ps Output Columns

The output of ps contains several useful fields. Understanding them helps in process monitoring.

Column Description
USER / UID User who owns the process.
PID Process identification number.
PPID Parent process identification number.
%CPU CPU usage percentage as reported by ps.
%MEM Percentage of physical memory used.
VSZ Virtual memory size, generally in KiB.
RSS Resident memory size, generally in KiB.
STAT Process state and possible modifiers.
TTY Controlling terminal.
TIME Accumulated CPU time.
CMD Command name and possibly its arguments.
RSS vs VSZ: RSS represents physical memory currently resident in RAM. VSZ represents the process's virtual address-space size. They are not interchangeable.

5. Display Selected Process Information

The -o option allows you to choose the columns displayed by ps.

Display PID and Command

ps -eo pid,comm

Display PID, PPID and Command

ps -eo pid,ppid,comm

Display PID, State and Command

ps -eo pid,stat,comm

Display Detailed Process Information

ps -eo pid,ppid,user,%cpu,%mem,stat,comm
Example Output: 
PID    PPID USER     %CPU %MEM STAT COMMAND
1         0 root      0.0  0.2 Ss   systemd
850       1 root      0.0  0.1 S    sshd
1250    850 user      0.1  0.3 Ss   bash
1400   1250 user      0.0  0.1 R+   ps

The values above are illustrative. Your system may show different processes and resource values.

6. Display a Specific Process Using PID

The -p option selects one or more processes by their process IDs.

Syntax

ps -p PID

Example

ps -p 1250

Displays information about the process with PID 1250, if it exists and is visible to the user.

Display Specific Columns

ps -p 1250 -o pid,ppid,stat,comm

Display Multiple PIDs

ps -p 1250,1400,1500
Note: Replace these example PIDs with actual process IDs from your system.

7. Display Processes of a Specific User

The -u option can be used to select processes by effective user name or user ID.

Syntax

ps -u username

Example

ps -u $USER

Displays processes associated with the current user's effective user identity.

Alternative: Display User Processes with Full Format

ps -U $USER -u $USER -f
Difference: In procps-style ps, uppercase -U selects by real user ID, while lowercase -u selects by effective user ID. The command above selects both using the current username.

8. Search for a Process Using grep

You can combine ps with grep to search for processes containing a particular command name or text.

Example 1: Search for Bash

ps -ef | grep bash

Example 2: Search for SSH

ps aux | grep ssh

Example 3: Avoid Matching grep Itself

ps -ef | grep '[b]ash'

The bracket expression helps prevent grep from matching its own command-line text in this common pattern.

Alternative: Use pgrep

pgrep bash

The pgrep command searches process names and displays matching PIDs.

Important: grep searches displayed text, whereas pgrep is designed for process selection. Use pgrep -a bash when you also want matching command lines on systems that support this option.

9. Display Processes in a Hierarchical Format

Linux processes have parent-child relationships. The ps command can display this relationship using tree-style output.

Command

ps -ef --forest

Displays processes in a hierarchical format.

Alternative Command

ps axjf

Displays processes in a job-oriented hierarchical format using BSD-style options.

Example Structure

systemd
  |
  +---- sshd
  |       |
  |       +---- bash
  |               |
  |               +---- ps
  |
  +---- background service
Note: The displayed hierarchy depends on the processes running on the system.

10. Common ps Command Options

Option Purpose Example
-e Select all processes. ps -e
-f Full-format listing. ps -ef
-a Select processes associated with terminals, with BSD selection semantics. ps a
-u User-oriented format or effective-user selection, depending on context. ps -u $USER
-p Select process by PID. ps -p 1250
-o Select output columns. ps -o pid,comm
-x Include processes without a controlling terminal, with BSD selection semantics. ps aux
-C Select processes by command name. ps -C bash
--forest Display hierarchical process relationships. ps -ef --forest
Important: ps supports different option styles. Do not assume every option has identical meaning in every syntax. Refer to man ps for the implementation installed on your Linux system.

11. Difference Between ps and top

ps top
Displays a process snapshot. Continuously updates process information.
Normally runs once and exits. Runs interactively until the user exits.
Useful for scripts and command pipelines. Useful for real-time monitoring.
Supports custom output columns. Provides an interactive process-monitoring interface.

Example:

ps aux top

13. Interview Questions and Answers

Q1. What is the ps command?

Answer: ps stands for Process Status. It displays a snapshot of process information in Linux.

Q2. What is the difference between ps and top?

Answer: ps displays a process snapshot, whereas top continuously updates process information.

Q3. Which command displays all processes in full format?

Answer: ps -ef.

Q4. What does the -e option do?

Answer: It selects all processes.

Q5. What does the -f option do?

Answer: It displays processes in full-format listing.

Q6. What is the purpose of the -p option?

Answer: It selects a process using its PID.

Q7. What is the purpose of the -o option?

Answer: It allows the user to select specific output columns.

Q8. What does STAT represent?

Answer: STAT represents the process state and may include additional state modifiers.

Q9. What is RSS?

Answer: RSS stands for Resident Set Size. It represents the amount of physical memory currently resident for the process.

Q10. What is VSZ?

Answer: VSZ stands for Virtual Memory Size. It represents the process's virtual address-space size.

Q11. How can you display the process tree?

Answer: Use ps -ef --forest or pstree -p.

Q12. How can you search for a process by name?

Answer: Use pgrep process_name or combine ps with grep.
