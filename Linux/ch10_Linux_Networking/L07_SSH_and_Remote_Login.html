SSH and Remote Login in Linux

Learn secure remote access, SSH authentication and remote system management

Home Linux Course Chapter 10

Learning Objectives

After completing this lesson, you will be able to:

  • Understand SSH and remote login.
  • Explain SSH client-server architecture.
  • Understand the role of the SSH protocol and TCP port 22.
  • Install and configure an OpenSSH server in Ubuntu.
  • Connect to a remote Linux machine using SSH.
  • Use password-based and public-key authentication.
  • Generate and manage SSH keys.
  • Understand the SSH configuration files.
  • Troubleshoot common SSH connection problems.

1. Introduction to SSH

SSH stands for Secure Shell.

SSH is a network protocol used to securely access and manage another computer over an IP network.

It provides an encrypted communication channel between an SSH client and an SSH server.

Why Is SSH Used?

  • Remote login to Linux servers.
  • Executing commands on remote computers.
  • Managing servers without physical access.
  • Secure file transfer using related tools such as SCP and SFTP.
  • Remote administration and troubleshooting.
  • Secure tunnelling and port forwarding.

Example

ssh username@192.168.1.100

This command attempts to connect to the machine at the specified IP address using the given username.

Important: SSH encrypts the communication channel, protecting credentials and session data from being transmitted as ordinary readable text.

2. SSH Architecture

SSH follows a client-server architecture.

SSH Client

The SSH client is the program used to initiate a secure connection to a remote machine.

Example: ssh command in Ubuntu.

SSH Server

The SSH server listens for incoming SSH connections and provides authenticated remote access.

On Ubuntu, the OpenSSH server package provides the sshd service.

SSH Communication

+-----------------------+        +-----------------------+
|     SSH CLIENT        |        |      SSH SERVER       |
|                       |        |                       |
|  Local Linux System   |        |  Remote Linux System  |
|                       |        |                       |
|  ssh command          |------->|  sshd service          |
|                       |  SSH   |                       |
|                       |<-------|                       |
+-----------------------+        +-----------------------+
           Encrypted communication channel

Default SSH Port

TCP Port: 22

SSH normally uses TCP port 22 by default. Administrators can configure a different port.

3. OpenSSH

OpenSSH is a widely used open-source implementation of the SSH protocol.

Main OpenSSH Components

Component Purpose
ssh SSH client for remote login.
sshd SSH server daemon.
ssh-keygen Generates SSH key pairs.
ssh-copy-id Installs a public key on a remote account.
scp Copies files securely between systems.
sftp Provides interactive secure file transfer.
ssh-agent Manages private keys for authentication sessions.

4. Install the SSH Server in Ubuntu

To accept incoming SSH connections, the remote Ubuntu machine needs an SSH server.

Step 1: Update Package Lists

sudo apt update

Step 2: Install OpenSSH Server

sudo apt install openssh-server

Step 3: Check SSH Service Status

sudo systemctl status ssh

Step 4: Start the SSH Service

sudo systemctl start ssh

Step 5: Enable SSH at Boot

sudo systemctl enable ssh

Step 6: Verify the Listening Port

sudo ss -tlnp | grep ':22'

This command checks whether a process is listening on TCP port 22.

On Ubuntu, the service is commonly named ssh, while the server daemon executable is sshd. Service names may differ on other Linux distributions.

5. Display the IP Address of the SSH Server

Before connecting to a remote Linux machine, identify its reachable IP address.

Command

ip addr

Short Output

ip -br addr

Display IPv4 Addresses

hostname -I

Example output:

192.168.1.100

The example address is illustrative. Use the actual IP address assigned to the remote machine.

6. Connect to a Remote Linux Machine

The ssh command is used to establish a secure remote login session.

Basic Syntax

ssh username@hostname_or_ip

Example Using an IP Address

ssh student@192.168.1.100

Here:

  • ssh starts the SSH client.
  • student is the username on the remote machine.
  • 192.168.1.100 is the remote machine's IP address.

Example Using a Hostname

ssh student@linux-server

First-Time Connection

When connecting to a server for the first time, SSH may display a host authenticity warning and ask whether to continue connecting.

The authenticity of host '192.168.1.100' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?

Verify the server's host-key fingerprint through a trusted channel before accepting it. After acceptance, the server's host key is normally recorded in the client's ~/.ssh/known_hosts file.

Enter the Remote Account Password

If password authentication is enabled, SSH prompts for the remote user's password.

Password characters normally do not appear while typing in the terminal. This is expected behavior.

7. Execute Commands on a Remote Machine

SSH can execute a command remotely without opening an interactive shell session.

Basic Syntax

ssh username@remote_host command

Example: Display Remote Hostname

ssh student@192.168.1.100 hostname

Example: Display Remote Kernel Information

ssh student@192.168.1.100 uname -a

Example: List Remote Files

ssh student@192.168.1.100 ls -l

The command executes on the remote machine, and its output is returned to the local terminal.

8. Connect Using a Different SSH Port

SSH normally uses TCP port 22. If the server is configured to use another port, specify it with the uppercase -p option.

Syntax

ssh -p PORT username@remote_host

Example

ssh -p 2222 student@192.168.1.100
The SSH client option is uppercase -p for the port. Do not confuse it with the lowercase -p used by scp for the port.

9. Password-Based Authentication

Password-based authentication allows a user to log in by entering the password associated with the remote Linux account.

Authentication Process

  1. The client establishes an SSH connection with the server.
  2. The server identifies the requested user account.
  3. The server requests authentication.
  4. The user supplies the account password.
  5. The server verifies the credentials.
  6. If authentication succeeds, the user receives access according to account permissions.

Advantages

  • Easy to understand and configure.
  • Does not require manually generating SSH keys.
  • Useful for basic learning and testing.

Limitations

  • Passwords may be guessed or targeted by automated attacks.
  • Users may choose weak or reused passwords.
  • Repeated password entry can be inconvenient.
Use strong, unique passwords and follow the security policy of the server. Public-key authentication is generally preferred for many administrative and automated SSH workflows.

10. Public-Key Authentication

SSH public-key authentication uses a cryptographic key pair.

The key pair contains:

  • Private key: Kept securely on the client machine.
  • Public key: Installed in the remote user's authorized_keys file.

The client proves possession of the private key through a cryptographic authentication exchange. The private key itself is not sent to the server.

Key Authentication Process

SSH CLIENT                         SSH SERVER
-----------                        -----------
Private key                        Authorized public key
     |                                      |
     |---- Authentication request -------->|
     |                                      |
     |<--- Cryptographic challenge ---------|
     |                                      |
     |---- Proof using private key -------->|
     |                                      |
     |<--- Authentication accepted ---------|
     |                                      |
     |       Secure login session           |

Advantages

  • Reduces dependence on account passwords for SSH login.
  • Supports automated remote administration.
  • Private keys can be protected with a passphrase.
  • Can provide strong authentication when managed properly.

11. Generate SSH Keys Using ssh-keygen

The ssh-keygen command generates SSH key pairs.

Generate an Ed25519 Key Pair

ssh-keygen -t ed25519

During generation, the command asks for a location to save the key and optionally a passphrase.

Default Key Files

~/.ssh/id_ed25519 ~/.ssh/id_ed25519.pub
File Description
id_ed25519 Private key. Keep it secret and protected.
id_ed25519.pub Public key. This can be installed on remote systems.

Display the Public Key

cat ~/.ssh/id_ed25519.pub
Never share your private key file. Do not upload it to GitHub, email it to others or paste it into public websites. Share only the public key when setting up authentication.

12. Copy the Public Key to a Remote Server

The ssh-copy-id command installs the client's public key in the remote user's authorized_keys file.

Syntax

ssh-copy-id username@remote_host

Example

ssh-copy-id student@192.168.1.100

If the server allows password authentication, you may be asked to enter the remote account password during key installation.

Connect Using the Installed Key

ssh student@192.168.1.100

If the server accepts the installed key and the client can access the corresponding private key, authentication can proceed without entering the remote account password.

The SSH key may still require its own passphrase. ssh-agent can help manage keys during a session.

13. SSH Configuration Files

SSH uses configuration files on both the client and server sides.

File Purpose
/etc/ssh/sshd_config System-wide SSH server configuration.
/etc/ssh/ssh_config System-wide SSH client configuration.
~/.ssh/config Per-user SSH client configuration.
~/.ssh/authorized_keys Public keys allowed to authenticate to a particular user account.
~/.ssh/known_hosts Host keys recorded by the SSH client.
~/.ssh/id_ed25519 Example private key file.
~/.ssh/id_ed25519.pub Example public key file.

Display the Server Configuration

sudo nano /etc/ssh/sshd_config

Check the Server Configuration Syntax

sudo sshd -t

If the configuration is valid, this command normally produces no output.

Restart the SSH Service

sudo systemctl restart ssh
Before changing SSH server settings, keep an existing working session open and ensure you have another way to access the machine. A configuration error or incorrect firewall rule can lock you out of a remote server.

14. Important SSH Server Configuration Options

The following directives may be present in /etc/ssh/sshd_config.

Directive Purpose
Port Sets the SSH listening port.
ListenAddress Controls the local addresses on which sshd listens.
PermitRootLogin Controls direct root login through SSH.
PasswordAuthentication Controls password-based SSH authentication.
PubkeyAuthentication Controls public-key authentication.
AllowUsers Restricts SSH login to specified users.
MaxAuthTries Sets the maximum authentication attempts per connection.

Example Configuration Directives

Port 22 PubkeyAuthentication yes PasswordAuthentication yes PermitRootLogin no
These are example settings, not a complete replacement configuration. Some Ubuntu installations use additional configuration snippets under /etc/ssh/sshd_config.d/. Effective settings can depend on configuration order and included files.

15. SSH Client Configuration

The per-user SSH client configuration file is:

~/.ssh/config

It allows users to create shortcuts for frequently accessed servers.

Example Configuration

Host myserver HostName 192.168.1.100 User student Port 22 IdentityFile ~/.ssh/id_ed25519

Connect Using the Alias

ssh myserver

SSH uses the configuration associated with the alias myserver.

Protect SSH configuration and key files. A typical private SSH directory permission is 700, while private key files should normally be readable only by their owner.

16. SSH File and Directory Permissions

SSH checks file permissions to protect private keys and authentication data.

Set the SSH Directory Permission

chmod 700 ~/.ssh

Set Private Key Permission

chmod 600 ~/.ssh/id_ed25519

Set Public Key Permission

chmod 644 ~/.ssh/id_ed25519.pub

Set Authorized Keys Permission

chmod 600 ~/.ssh/authorized_keys

These are common secure permission settings. The correct ownership and permissions should also be checked on the remote account.

17. SSH Connection Troubleshooting

SSH connection problems can occur because of network configuration, service status, firewall rules, authentication failures or host-key mismatches.

1. Check Network Connectivity

ping -c 4 192.168.1.100

Use the actual remote IP address. ICMP may be blocked even when SSH is reachable.

2. Check SSH Service Status on the Server

sudo systemctl status ssh

3. Check Whether Port 22 Is Listening

sudo ss -tlnp | grep ':22'

4. Check Firewall Rules

sudo ufw status

5. Allow SSH Through UFW if Required

sudo ufw allow OpenSSH

6. Test the SSH Port From the Client

nc -vz 192.168.1.100 22

This checks TCP connectivity to port 22 if netcat is installed.

7. Use Verbose SSH Output

ssh -v student@192.168.1.100

For more diagnostic detail:

ssh -vvv student@192.168.1.100

8. Check Server Logs

sudo journalctl -u ssh -n 50

Common SSH Errors

Error Possible Cause
Connection refused SSH server is not listening on the target address and port, or a device actively rejected the connection.
Connection timed out Network path, firewall or server reachability problem.
Permission denied Incorrect credentials, unavailable key or authentication policy restriction.
Host key verification failed The saved host key differs from the key presented by the server, or the known_hosts entry is incorrect.
No route to host Routing, network or firewall problem.
Could not resolve hostname Hostname resolution problem or incorrect hostname.
If SSH reports a changed host key, do not blindly remove the old entry. First verify that the remote server's identity has legitimately changed. A changed host key can indicate a security risk.

18. SSH Port Forwarding

SSH supports port forwarding, which securely carries network traffic through an SSH connection.

Local Port Forwarding

Local forwarding maps a port on the client machine to a destination reachable from the SSH server.

Syntax

ssh -L LOCAL_PORT:DESTINATION_HOST:DESTINATION_PORT username@ssh_server

Example

ssh -L 8080:localhost:80 student@192.168.1.100

This creates a local listener on port 8080 and forwards its traffic through the SSH server to port 80 on the server's own localhost.

While the SSH session is active, a local application can connect to:

http://localhost:8080

Remote Port Forwarding

Remote forwarding exposes a port on the SSH server side and forwards traffic through the SSH connection to a destination reachable from the SSH client.

ssh -R 9000:localhost:3000 student@192.168.1.100
Port forwarding behavior depends on SSH server policy and network configuration. Use it only when authorized.

19. SSH vs Telnet

Feature SSH Telnet
Full Form Secure Shell Teletype Network
Default TCP Port 22 23
Encryption Encrypts the communication channel. Normally sends data without encryption.
Authentication Supports password and public-key authentication. Typically uses username/password without SSH-style encryption.
Security Suitable for secure remote administration when configured correctly. Insecure for sensitive remote administration.
Usage Remote administration and secure communication. Legacy remote terminal access and limited testing uses.
SSH is generally preferred over Telnet because it protects the communication channel with encryption.

21. Practical Lab: Connect to Your Ubuntu Virtual Machine

Objective: Practise SSH remote login using two Linux machines.

For a VirtualBox lab, use two Linux VMs or another Linux computer on a network that allows communication between them.

Step 1: Install OpenSSH Server on the Target VM

sudo apt update sudo apt install openssh-server

Step 2: Start the SSH Service

sudo systemctl enable --now ssh

Step 3: Find the Target VM IP Address

ip -br addr

Step 4: Find the Remote Username

whoami

Step 5: Connect From the Client VM

ssh username@TARGET_IP_ADDRESS

Step 6: Execute a Remote Command

ssh username@TARGET_IP_ADDRESS hostname

Step 7: Exit the Remote Session

exit
VirtualBox network mode matters. NAT, NAT Network, Bridged Adapter and Host-Only Adapter provide different connectivity. Two VMs using separate isolated NAT configurations may not be able to connect directly. Configure a suitable network mode before attempting remote login.

24. Interview Questions and Answers

Q1. What is SSH?

Answer: SSH is a secure network protocol used for encrypted remote login, command execution and other secure network operations.

Q2. What is the default SSH port?

Answer: TCP port 22 is the default SSH port.

Q3. What is the difference between ssh and sshd?

Answer: ssh is the client program used to initiate connections. sshd is the server daemon that accepts incoming SSH connections.

Q4. What is OpenSSH?

Answer: OpenSSH is an open-source implementation of the SSH protocol and its associated utilities.

Q5. How do you install an SSH server in Ubuntu?

Answer: Use sudo apt install openssh-server.

Q6. How do you connect to a remote Linux machine?

Answer: Use ssh username@remote_ip.

Q7. What is public-key authentication?

Answer: It is an authentication method using a private/public key pair. The client proves possession of the private key, and the server verifies the proof using the authorized public key.

Q8. What is the purpose of ssh-keygen?

Answer: It generates and manages SSH authentication keys.

Q9. What is the purpose of authorized_keys?

Answer: It contains public keys authorized to authenticate to a particular user account.

Q10. What is known_hosts?

Answer: It stores host keys that an SSH client has recorded for remote servers.

Q11. What is the difference between SSH and Telnet?

Answer: SSH encrypts the communication channel, whereas traditional Telnet does not provide equivalent encryption.

Q12. How do you check whether SSH is running?

Answer: Use sudo systemctl status ssh on Ubuntu.

Q13. How do you connect using a different port?

Answer: Use ssh -p PORT username@host.

Q14. What is ssh-copy-id?

Answer: It installs the client's public key in the remote account's authorized_keys file.

Q15. What is SSH port forwarding?

Answer: It securely forwards network connections through an SSH connection.
