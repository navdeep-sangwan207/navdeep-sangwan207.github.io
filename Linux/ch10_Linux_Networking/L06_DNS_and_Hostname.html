DNS and Hostname in Linux

Understand domain name resolution, DNS servers and hostname management

Home Linux Course Chapter 10

Learning Objectives

After completing this lesson, you will be able to:

  • Understand DNS and its role in computer networking.
  • Explain how domain names are translated into IP addresses.
  • Understand DNS servers and DNS record types.
  • Inspect and configure hostname information in Linux.
  • Understand the purpose of /etc/hosts and /etc/resolv.conf.
  • Use hostname, hostnamectl, getent, dig and nslookup.
  • Understand systemd-resolved and resolvectl.
  • Troubleshoot common DNS resolution problems.

1. Introduction to DNS

DNS stands for Domain Name System.

DNS is a distributed naming system that translates human-readable domain names into IP addresses and can provide other information about domain names.

Computers communicate across IP networks using IP addresses. However, people generally find domain names easier to remember.

Example

Domain Name: example.com IPv4 Address: 93.184.216.34

When a user accesses a domain name, the system performs name resolution to discover the corresponding network address.

Why Is DNS Required?

  • People can remember domain names more easily than IP addresses.
  • Applications can locate servers using domain names.
  • DNS supports email routing and service discovery.
  • DNS allows domain names to be associated with changing IP addresses.
  • DNS helps distributed systems locate network services.
Important: DNS is often described as the phonebook of the Internet because it helps translate names into network addresses.

2. Domain Name and IP Address

A domain name is a human-readable name used to identify an Internet resource or service.

An IP address is a numerical network address used to identify an endpoint on an IP network.

Examples

Domain Name Illustrative IP Address
example.com 93.184.216.34
localhost 127.0.0.1

Domain names may resolve to multiple IPv4 or IPv6 addresses. The returned addresses can also change over time.

IPv4 and IPv6 DNS Records

  • A record: Maps a hostname to an IPv4 address.
  • AAAA record: Maps a hostname to an IPv6 address.

3. How DNS Resolution Works

DNS resolution is the process of obtaining DNS information for a domain name.

Basic DNS Resolution Process

  1. A user enters a domain name in a browser or application.
  2. The operating system's name-resolution process checks configured sources, which may include local files and DNS caches.
  3. If a DNS query is required, it is sent to a configured DNS resolver.
  4. The resolver obtains the required DNS information, using its cache or querying other DNS servers.
  5. The resolver returns the result to the requesting system.
  6. The application uses the returned address to communicate with the destination.

DNS Resolution Flow

User enters a domain name
          |
          v
Application requests name resolution
          |
          v
Operating system checks configured sources
          |
          v
DNS resolver receives a query if needed
          |
          v
Resolver obtains DNS record
          |
          v
IP address is returned
          |
          v
Application connects to the destination

Important DNS Components

Component Function
Stub Resolver Client-side component that requests name resolution.
Recursive Resolver Finds DNS answers on behalf of a client, using caches and other DNS servers.
Root DNS Server Directs queries toward the appropriate top-level domain servers.
TLD DNS Server Provides information about authoritative servers for a top-level domain.
Authoritative DNS Server Provides DNS records for the domain it serves.

4. Common DNS Record Types

DNS stores different types of resource records.

Record Purpose
A Maps a hostname to an IPv4 address.
AAAA Maps a hostname to an IPv6 address.
CNAME Creates an alias pointing to another domain name.
MX Identifies mail servers for a domain.
NS Identifies authoritative name servers for a DNS zone.
PTR Used for reverse DNS lookup.
TXT Stores text information, often used for verification and email security policies.
SOA Contains administrative information about a DNS zone.
SRV Identifies servers providing particular services.

Example

example.com. IN A 93.184.216.34 example.com. IN AAAA 2001:db8::10 example.com. IN MX 10 mail.example.com.
The addresses above are illustrative. The IPv6 address uses the documentation prefix 2001:db8::/32 and is not a production destination.

5. What Is a Hostname?

A hostname is a name assigned to a computer or network device.

It helps identify a system on a network.

Example

ubuntu-pc linux-server web-server development-machine

Types of Hostnames

  • Static hostname: A configured hostname stored by the system.
  • Transient hostname: A temporary hostname that may be received from network configuration or other runtime sources.
  • Pretty hostname: A descriptive name that may contain spaces and is intended for display.

systemd-based Linux systems support these hostname types through hostnamectl.

6. Display the Hostname

Command 1: hostname

hostname

Displays the current system hostname.

Command 2: hostnamectl

hostnamectl

Displays hostname information and other system details managed by systemd.

Command 3: uname -n

uname -n

Displays the network node hostname reported by the kernel.

Example Output

Static hostname: ubuntu-pc
Icon name: computer-vm
Chassis: vm
Operating System: Ubuntu
Kernel: Linux
Architecture: x86-64

The exact output depends on your Linux distribution and system configuration.

7. Change the Hostname

On a system using systemd, hostnamectl is the standard command for managing the hostname.

Change the Static Hostname

sudo hostnamectl set-hostname linux-server

This sets the static hostname to linux-server.

Verify the New Hostname

hostname hostnamectl

Set a Pretty Hostname

sudo hostnamectl set-hostname "Linux Development Machine" --pretty

Display Hostname Information

hostnamectl status
Changing the hostname does not automatically update every application, DNS server or remote system. You may also need to review local hostname mappings and any network services that depend on the previous name.

8. The /etc/hostname File

The /etc/hostname file commonly stores the system's static hostname on Ubuntu and many other Linux distributions.

Display Its Contents

cat /etc/hostname

Example Output

ubuntu-pc

When you use hostnamectl to change the static hostname on a systemd-based Ubuntu installation, the system normally updates the relevant hostname configuration.

Avoid manually editing system hostname files unless you understand the configuration. Prefer hostnamectl for standard systemd-based installations.

9. The /etc/hosts File

The /etc/hosts file provides a local mapping between IP addresses and hostnames.

It can be used for local name resolution without querying an external DNS server.

Display the Hosts File

cat /etc/hosts

Illustrative Output

127.0.0.1       localhost
127.0.1.1       ubuntu-pc
::1             localhost ip6-localhost ip6-loopback

Hosts File Format

IP_ADDRESS HOSTNAME [ALIASES]

Example Mapping

192.0.2.10 test-server.example.test

This example maps the documentation IP address 192.0.2.10 to a local test hostname.

Test the Mapping

getent hosts test-server.example.test

Edit the Hosts File

sudo nano /etc/hosts

Add the mapping on a new line, save the file and test it with getent.

The /etc/hosts file is useful for local development, testing and temporary hostname mappings. Its entries are local to the machine unless separately configured on other systems.

10. The /etc/resolv.conf File

The /etc/resolv.conf file contains DNS resolver configuration information used by the system's name-resolution components.

Display the File

cat /etc/resolv.conf

Example Output

nameserver 127.0.0.53
options edns0 trust-ad
search example.local

Common Directives

Directive Purpose
nameserver Specifies a DNS server address.
search Specifies search domains used for certain unqualified names.
domain Specifies a local domain name; traditionally used as a search-domain setting.
options Controls resolver behavior.

Understanding 127.0.0.53

On many Ubuntu installations using systemd-resolved, 127.0.0.53 is a local DNS stub listener.

Applications send DNS requests to this local resolver. systemd-resolved then handles forwarding and DNS resolution using its configured DNS servers.

On Ubuntu, /etc/resolv.conf may be a symbolic link managed by systemd-resolved or NetworkManager. Do not overwrite it casually because automatic DNS configuration may be disrupted.

11. Understanding systemd-resolved

systemd-resolved is a system service that provides network name resolution for applications using supported system resolver interfaces.

Its Responsibilities Include

  • DNS name resolution.
  • DNS caching.
  • Managing DNS information associated with network links.
  • Supporting DNS-over-TLS when configured and supported.
  • Providing a local DNS stub listener when enabled.

Check the Service Status

systemctl status systemd-resolved

Start the Service

sudo systemctl start systemd-resolved

Enable the Service at Boot

sudo systemctl enable systemd-resolved

Restart the Service

sudo systemctl restart systemd-resolved
Not every Linux distribution uses systemd-resolved. These commands apply to systems where the service is installed and configured.

12. Using resolvectl

resolvectl is a command-line utility for inspecting and controlling systemd-resolved.

Display DNS Status

resolvectl status

Displays global and per-interface DNS settings, DNS servers and search domains.

Query a Domain

resolvectl query example.com

Requests name resolution for the specified domain.

Display DNS Statistics

resolvectl statistics

Displays DNS-related statistics maintained by systemd-resolved.

Flush the DNS Cache

sudo resolvectl flush-caches

Clears the DNS cache maintained by systemd-resolved.

The DNS cache is not necessarily maintained by systemd-resolved on every Linux system. Use resolvectl only when systemd-resolved is available and managing name resolution.

13. DNS Lookup Using getent

getent retrieves entries from system databases configured through the Name Service Switch (NSS).

It is useful because it tests the system's configured name-resolution path, which may include /etc/hosts and DNS.

Resolve a Hostname

getent hosts example.com

Resolve an IPv4 Address

getent ahostsv4 example.com

Resolve an IPv6 Address

getent ahostsv6 example.com

Check a Local Hostname Mapping

getent hosts localhost
Important: getent tests the operating system's configured name service lookup process. This is different from directly querying a particular DNS server.

14. DNS Lookup Using nslookup

nslookup stands for Name Server Lookup.

It is a DNS diagnostic utility used to query DNS records and DNS servers.

Check Installation

which nslookup

On Ubuntu, nslookup is commonly provided by the dnsutils package on older releases or bind9-dnsutils on newer releases.

Install the Utility

sudo apt update sudo apt install dnsutils

If the package name is unavailable on your release, check the package that provides nslookup in your configured repositories.

Basic DNS Lookup

nslookup example.com

Query a Specific DNS Server

nslookup example.com 1.1.1.1

This requests a DNS answer from the specified DNS server, subject to network access and server availability.

Query an MX Record

nslookup -type=MX example.com

Query an NS Record

nslookup -type=NS example.com

15. DNS Lookup Using dig

dig stands for Domain Information Groper.

It is a flexible DNS query tool commonly used by network administrators and system engineers.

Install dig

sudo apt install dnsutils

Basic DNS Query

dig example.com

Display Only the Answer Section

dig example.com +short

Query an A Record

dig example.com A

Query an AAAA Record

dig example.com AAAA

Query an MX Record

dig example.com MX

Query a Specific DNS Server

dig @1.1.1.1 example.com

Perform a Reverse DNS Lookup

dig -x 8.8.8.8

Useful dig Options

Option Purpose
+short Displays concise answer output.
+noall Suppresses the normal output sections.
+answer Displays the answer section.
+trace Performs iterative queries to trace delegation.
@server Queries a specified DNS server.

Example

dig example.com +noall +answer
example.com.  3600  IN  A  93.184.216.34

The example record is illustrative. Actual records, TTL values and answers can change.

16. DNS Server

A DNS server is a server that provides DNS information or performs DNS resolution for clients.

A client typically sends DNS queries to a recursive resolver configured by its network or administrator.

Common Public DNS Resolver Addresses

Provider IPv4 Address IPv6 Address
Google Public DNS 8.8.8.8, 8.8.4.4 2001:4860:4860::8888
Cloudflare DNS 1.1.1.1, 1.0.0.1 2606:4700:4700::1111

These are examples of public recursive DNS resolvers.

Query a Specific DNS Server

dig @8.8.8.8 example.com
Public DNS servers are not automatically the best choice for every network. Organizations may require internal DNS servers for private hostnames, security policies or split-DNS configurations.

17. DNS Cache

A DNS cache temporarily stores DNS query results to reduce repeated lookups and improve performance.

Benefits of DNS Caching

  • Reduces repeated DNS queries.
  • Can improve name-resolution response time.
  • Reduces unnecessary traffic to upstream DNS servers.

Time to Live (TTL)

TTL specifies how long a DNS record may be cached before it should be refreshed.

Example

example.com.  300  IN  A  93.184.216.34

Here, the TTL value is 300 seconds, or five minutes.

Flush systemd-resolved Cache

sudo resolvectl flush-caches
Flushing one DNS cache does not clear every cache in the network. Browser, application, local resolver and upstream resolver caches may be separate.

18. DNS Troubleshooting Commands

When a website or network service cannot be reached by its domain name, use the following commands to investigate.

1. Check Network Interface Configuration

ip -br addr

2. Check the Default Route

ip route

3. Test Connectivity to a Known IP Address

ping -c 4 1.1.1.1

4. Test Domain Name Resolution

getent hosts example.com

5. Query DNS Directly

dig example.com

6. Inspect Resolver Configuration

cat /etc/resolv.conf

7. Inspect systemd-resolved

resolvectl status

8. Check DNS Service Status

systemctl status systemd-resolved

Interpretation

Observation Possible Cause
IP connectivity works but domain lookup fails. DNS configuration or resolver problem.
Both IP connectivity and DNS fail. Network, gateway, firewall or broader connectivity problem.
Local hostname resolves but external names do not. External DNS resolution or Internet connectivity problem.
One DNS server works and another does not. Resolver-specific filtering, reachability or configuration issue.
Only one application fails to resolve names. Application-specific DNS behavior or configuration may be involved.
A successful ping to an IP address does not prove that DNS is working. A successful DNS lookup also does not guarantee that the destination application or service is reachable.

19. Common DNS Errors

1. Temporary Failure in Name Resolution

Possible causes include an unavailable resolver, network interruption or incorrect DNS configuration.

2. Name or Service Not Known

The requested name may not resolve through the configured name service sources.

3. Connection Timed Out During DNS Query

The DNS server may be unreachable, filtering requests or failing to respond in time.

4. NXDOMAIN

NXDOMAIN indicates that the DNS response says the queried domain name does not exist.

5. SERVFAIL

SERVFAIL indicates that the DNS server could not successfully complete the query. It does not necessarily mean the domain does not exist.

6. No Servers Could Be Reached

The selected DNS server may be unavailable or unreachable from the system.

Do not immediately replace DNS settings when an error appears. First inspect interface connectivity, routing, resolver configuration and DNS query results.

24. Interview Questions and Answers

Q1. What is DNS?

Answer: DNS is a distributed naming system that translates domain names into IP addresses and provides other domain-related information.

Q2. What is a DNS resolver?

Answer: A DNS resolver is a component or service that obtains DNS information for a client by using its cache or querying other DNS servers.

Q3. What is an authoritative DNS server?

Answer: It provides authoritative DNS records for the domain or zone it serves.

Q4. What is the difference between A and AAAA records?

Answer: A records map names to IPv4 addresses, while AAAA records map names to IPv6 addresses.

Q5. What is an MX record?

Answer: An MX record identifies mail servers responsible for receiving email for a domain.

Q6. What is a hostname?

Answer: A hostname is a name assigned to a computer or network device for identification.

Q7. How do you change a hostname in Ubuntu?

Answer: Use sudo hostnamectl set-hostname NEW_NAME on a systemd-based installation.

Q8. What is the purpose of /etc/hosts?

Answer: It stores local mappings between IP addresses and hostnames.

Q9. What is the purpose of /etc/resolv.conf?

Answer: It contains DNS resolver configuration, including nameserver entries and resolver options.

Q10. What is systemd-resolved?

Answer: It is a system service that provides DNS and other supported name-resolution functionality on systems using systemd.

Q11. What is resolvectl?

Answer: It is a command-line utility used to inspect and control systemd-resolved.

Q12. What is the difference between dig and nslookup?

Answer: Both are DNS query utilities. dig provides detailed DNS query output and advanced diagnostic options, while nslookup offers a simpler interactive or command-line lookup interface.

Q13. What is DNS caching?

Answer: DNS caching temporarily stores DNS query results to reduce repeated queries and improve performance.

Q14. What is TTL in DNS?

Answer: TTL is the time in seconds that a DNS record may be cached before it should be refreshed.

Q15. What does NXDOMAIN mean?

Answer: It means the DNS response indicates that the queried domain name does not exist.
