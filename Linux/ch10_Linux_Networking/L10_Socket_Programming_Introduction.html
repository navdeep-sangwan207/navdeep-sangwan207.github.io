1. Introduction to Socket Programming

Socket programming is a method of communication between two processes over a network. It allows applications running on the same computer or different computers to exchange data.

A socket is an endpoint of communication. Applications use sockets to send and receive information through a network.

Examples of Socket Programming Applications

  • Web browsers and web servers.
  • Chat and messaging applications.
  • File transfer applications.
  • Remote login systems such as SSH.
  • Online multiplayer games.
  • IoT devices and embedded systems.
  • Network monitoring applications.
Example: When a web browser communicates with a web server, network sockets provide the communication endpoints used to exchange HTTP data.

2. What Is a Socket?

A socket is a software communication endpoint that an application uses to send or receive data.

In Linux, a socket is represented by a file descriptor, which is an integer returned by the socket API.

Important Socket Components

Component Description
IP Address Identifies a network interface or host for IP communication.
Port Number Identifies a communication endpoint or service on a host.
Protocol Defines how data is transported, such as TCP or UDP.
Socket Provides an application communication endpoint.

Example

192.168.1.100:8080

Here:

  • 192.168.1.100 is the IP address.
  • 8080 is the port number.
An IP address identifies a network destination, while a port number identifies a transport-layer endpoint on that destination. A TCP connection is identified by its protocol and the source and destination IP addresses and port numbers.

3. Client-Server Architecture

Client-server architecture is a communication model in which one application provides a service and another application requests that service.

Client

  • Initiates a communication request.
  • Connects to a server.
  • Sends requests and receives responses.

Server

  • Waits for incoming requests.
  • Listens on a network address and port.
  • Accepts client connections.
  • Processes requests and sends responses.

Client-Server Communication Diagram

       CLIENT                         SERVER
   +------------+                 +------------+
   |            |                 |            |
   |  Client    | ---- Request -->|  Server    |
   | Application|                 | Application|
   |            |<--- Response ---|            |
   +------------+                 +------------+
          |                              |
          +--------- Network -----------+

Both client and server use sockets to exchange data.

5. Types of Network Sockets

Linux supports different socket types. Two important types used in network programming are stream sockets and datagram sockets.

1. Stream Socket – SOCK_STREAM

  • Commonly used with TCP.
  • Provides a reliable, ordered byte stream.
  • Establishes a connection before application data is exchanged.
  • Detects transmission errors and retransmits lost data at the transport layer.

2. Datagram Socket – SOCK_DGRAM

  • Commonly used with UDP.
  • Transfers independent messages called datagrams.
  • Does not establish a connection in the TCP sense.
  • Does not guarantee delivery or ordering.
  • Preserves message boundaries.

6. Difference Between TCP and UDP

Feature TCP UDP
Full Form Transmission Control Protocol User Datagram Protocol
Socket Type SOCK_STREAM SOCK_DGRAM
Connection Connection-oriented Connectionless
Reliability Reliable byte stream Best-effort datagram delivery
Ordering Preserves byte order Datagrams may arrive out of order
Message Boundaries Not preserved Preserved
Flow Control Available Not provided by UDP itself
Common Uses Web, SSH, file transfer DNS, streaming, real-time applications
Important: TCP provides a reliable ordered byte stream, not individual application messages. Applications using TCP must define their own message boundaries, for example through length fields or delimiters.

7. TCP Communication Process

TCP uses a three-way handshake to establish a connection.

Three-Way Handshake

        CLIENT                         SERVER
           |                              |
           | -------- SYN --------------> |
           |                              |
           | <------- SYN + ACK ---------- |
           |                              |
           | -------- ACK --------------> |
           |                              |
           |       CONNECTION             |
           |        ESTABLISHED           |

Handshake Steps

  1. SYN: The client requests a TCP connection.
  2. SYN-ACK: The server acknowledges the request and sends its own SYN.
  3. ACK: The client acknowledges the server's SYN.

After the handshake, both endpoints can exchange application data.

8. UDP Communication Process

UDP does not establish a TCP-style connection before sending data.

       CLIENT                         SERVER
          |                              |
          | -------- Datagram ---------> |
          |                              |
          | <------- Datagram ---------- |
          |                              |
          | -------- Datagram ---------> |
          |                              |

UDP sends independent datagrams. An application may implement its own acknowledgement, retry or sequencing mechanism when needed.

Common UDP Applications

  • DNS queries and responses.
  • Voice and video communication.
  • Online gaming.
  • Network discovery.
  • Some IoT communication protocols.

9. Linux Socket Programming API

Linux provides a socket API that C programs can use to create and manage network connections.

Important Socket Functions

Function Purpose
socket() Creates a socket and returns a file descriptor.
bind() Associates a socket with a local address and port.
listen() Marks a stream socket as passive and ready to accept connections.
accept() Accepts an incoming connection on a listening socket.
connect() Initiates a connection to a remote endpoint.
send() Sends data through a connected socket.
recv() Receives data from a connected socket.
sendto() Sends a datagram to a specified destination.
recvfrom() Receives a datagram and can report its source address.
close() Closes the socket file descriptor.

10. Basic TCP Server Workflow

A TCP server creates a socket, binds it to a local address and port, listens for incoming connections and accepts clients.

TCP Server Sequence

socket()
   |
   v
bind()
   |
   v
listen()
   |
   v
accept()
   |
   v
send() / recv()
   |
   v
close()

Explanation

  1. socket() creates the server socket.
  2. bind() associates it with a local IP address and port.
  3. listen() prepares it to accept connections.
  4. accept() waits for and accepts a client connection.
  5. send() and recv() exchange data.
  6. close() releases the file descriptor.
The listening socket and the connected socket returned by accept() are different file descriptors. A server normally keeps the listening socket open to accept additional clients.

11. Basic TCP Client Workflow

A TCP client creates a socket and uses connect() to establish a connection with a server.

TCP Client Sequence

socket()
   |
   v
connect()
   |
   v
send() / recv()
   |
   v
close()

Explanation

  1. socket() creates a client socket.
  2. connect() initiates the connection to the server.
  3. send() transmits application data.
  4. recv() receives application data.
  5. close() closes the socket.

13. Important Socket Structures

struct sockaddr_in

This structure stores an IPv4 socket address.

struct sockaddr_in server_address;

Important Members

Member Purpose
sin_family Address family, usually AF_INET for IPv4.
sin_port Port number in network byte order.
sin_addr IPv4 address.

Example Configuration

struct sockaddr_in server_address; server_address.sin_family = AF_INET; server_address.sin_port = htons(8080); server_address.sin_addr.s_addr = INADDR_ANY;

INADDR_ANY means the server listens on all suitable local IPv4 interfaces for that port.

htons() converts a 16-bit value from host byte order to network byte order.

14. Creating a TCP Server in C

Objective: Create a basic TCP server that listens on port 8080, accepts one client and sends a message.

File: server.c

#include <stdio.h> #include <stdlib.h> #include <string.h> #include <unistd.h> #include <sys/socket.h> #include <netinet/in.h> int main(void) { int server_fd, client_fd; struct sockaddr_in server_address; socklen_t address_length = sizeof(server_address); const char *message = "Hello from Linux TCP Server"; /* Create TCP socket */ server_fd = socket(AF_INET, SOCK_STREAM, 0); if (server_fd == -1) { perror("socket"); return EXIT_FAILURE; } /* Configure server address */ memset(&server_address, 0, sizeof(server_address)); server_address.sin_family = AF_INET; server_address.sin_port = htons(8080); server_address.sin_addr.s_addr = htonl(INADDR_ANY); /* Bind socket to local address and port */ if (bind(server_fd, (struct sockaddr *)&server_address, sizeof(server_address)) == -1) { perror("bind"); close(server_fd); return EXIT_FAILURE; } /* Start listening */ if (listen(server_fd, 5) == -1) { perror("listen"); close(server_fd); return EXIT_FAILURE; } printf("Server listening on port 8080...\n"); /* Accept one client */ client_fd = accept(server_fd, (struct sockaddr *)&server_address, &address_length); if (client_fd == -1) { perror("accept"); close(server_fd); return EXIT_FAILURE; } printf("Client connected.\n"); /* Send message to client */ if (send(client_fd, message, strlen(message), 0) == -1) { perror("send"); } close(client_fd); close(server_fd); return EXIT_SUCCESS; }

Compile the Server

gcc -Wall -Wextra server.c -o server

Run the Server

./server
Server listening on port 8080...

The server waits until a client connects. After accepting one client, it sends a message and exits.

15. Creating a TCP Client in C

Objective: Connect to the TCP server running on the same machine and receive its message.

File: client.c

#include <stdio.h> #include <stdlib.h> #include <string.h> #include <unistd.h> #include <sys/socket.h> #include <arpa/inet.h> int main(void) { int sock_fd; struct sockaddr_in server_address; char buffer[1024]; /* Create TCP socket */ sock_fd = socket(AF_INET, SOCK_STREAM, 0); if (sock_fd == -1) { perror("socket"); return EXIT_FAILURE; } /* Configure server address */ memset(&server_address, 0, sizeof(server_address)); server_address.sin_family = AF_INET; server_address.sin_port = htons(8080); if (inet_pton(AF_INET, "127.0.0.1", &server_address.sin_addr) != 1) { fprintf(stderr, "Invalid IPv4 address\n"); close(sock_fd); return EXIT_FAILURE; } /* Connect to server */ if (connect(sock_fd, (struct sockaddr *)&server_address, sizeof(server_address)) == -1) { perror("connect"); close(sock_fd); return EXIT_FAILURE; } /* Receive message */ ssize_t bytes_received = recv(sock_fd, buffer, sizeof(buffer) - 1, 0); if (bytes_received == -1) { perror("recv"); close(sock_fd); return EXIT_FAILURE; } if (bytes_received == 0) { printf("Server closed the connection.\n"); } else { buffer[bytes_received] = '\0'; printf("Message from server: %s\n", buffer); } close(sock_fd); return EXIT_SUCCESS; }

Compile the Client

gcc -Wall -Wextra client.c -o client

Run the Client

./client
Message from server: Hello from Linux TCP Server
Run the server first in one terminal. Run the client in a second terminal. Both programs use 127.0.0.1, which is the IPv4 loopback address. This example is designed for a local Linux machine.
This is a teaching example, not a production-ready server. Real applications must handle partial sends and receives, multiple clients, timeouts, interruptions, security and connection lifecycle management. TCP does not guarantee that one recv() call returns an entire application message.

17. Important Socket Programming Concepts

AF_INET

Specifies the IPv4 address family.

AF_INET6

Specifies the IPv6 address family.

SOCK_STREAM

Creates a stream socket, commonly used with TCP.

SOCK_DGRAM

Creates a datagram socket, commonly used with UDP.

IPPROTO_TCP

Identifies TCP as the transport protocol.

IPPROTO_UDP

Identifies UDP as the transport protocol.

htons()

Converts a 16-bit integer from host byte order to network byte order.

htonl()

Converts a 32-bit integer from host byte order to network byte order.

inet_pton()

Converts an IPv4 or IPv6 address from presentation format into binary network format.

inet_ntop()

Converts a binary IP address into readable text.

INADDR_ANY

Represents the IPv4 wildcard address used to bind to all local IPv4 interfaces.

18. TCP vs UDP Socket API

Operation TCP UDP
Create socket(AF_INET, SOCK_STREAM, 0) socket(AF_INET, SOCK_DGRAM, 0)
Server setup bind(), listen(), accept() Usually bind()
Client communication connect() sendto() or connect()
Send data send() or write() sendto() or send()
Receive data recv() or read() recvfrom() or recv()
Close close() close()
UDP servers do not use listen() or accept(). They typically bind a datagram socket and receive datagrams using recvfrom(). A UDP socket can also be connected to a default peer using connect(), but this does not create a TCP-style handshake.

21. Interview Questions and Answers

Q1. What is socket programming?

Answer: Socket programming enables applications to communicate and exchange data through network sockets.

Q2. What is a socket?

Answer: A socket is a communication endpoint used by an application to send or receive data.

Q3. What is client-server architecture?

Answer: It is a model in which a client requests a service and a server provides it.

Q4. What is the difference between TCP and UDP?

Answer: TCP provides a reliable ordered byte stream, while UDP provides connectionless datagram delivery without guaranteed delivery or ordering.

Q5. What does socket() do?

Answer: It creates a socket and returns a file descriptor.

Q6. What does bind() do?

Answer: It associates a socket with a local IP address and port.

Q7. What does listen() do?

Answer: It marks a stream socket as passive so it can accept incoming connections.

Q8. What does accept() do?

Answer: It accepts a pending connection and returns a new connected socket file descriptor.

Q9. What does connect() do?

Answer: It initiates a connection to a remote endpoint.

Q10. What is the purpose of htons()?

Answer: It converts a 16-bit value from host byte order to network byte order.

Q11. What is AF_INET?

Answer: It specifies the IPv4 address family.

Q12. What is SOCK_STREAM?

Answer: It specifies a stream socket, commonly used with TCP.

Q13. What is SOCK_DGRAM?

Answer: It specifies a datagram socket, commonly used with UDP.

Q14. What is the loopback address?

Answer: The IPv4 loopback address is 127.0.0.1. It allows a system to communicate with itself.

Q15. What is the purpose of accept() returning a new descriptor?

Answer: It provides a connected socket for communicating with that client while the original listening socket can continue accepting other connections.
