SCP and File Transfer in Linux

Learn secure file copying and remote file transfer using SSH

Home Linux Course Chapter 10

Learning Objectives

After completing this lesson, you will be able to:

  • Understand file transfer between Linux systems.
  • Explain SCP and its relationship with SSH.
  • Copy files from local to remote systems.
  • Copy files from remote to local systems.
  • Transfer files between two remote systems.
  • Copy directories recursively using SCP.
  • Use custom SSH ports and identity keys during transfers.
  • Understand SFTP and its commands.
  • Troubleshoot common file-transfer errors.

1. Introduction to File Transfer in Linux

File transfer is the process of moving or copying files between computers or storage locations.

In Linux networking, files can be transferred between local and remote systems using secure network protocols.

Common File Transfer Methods

Method Purpose
SCP Securely copies files between systems using SSH.
SFTP Provides interactive secure file transfer using SSH.
FTP Transfers files using the File Transfer Protocol; traditional FTP does not encrypt credentials or data.
rsync Synchronizes files and directories efficiently, including over SSH.
Important: SCP and SFTP use SSH for secure communication. They are commonly used for transferring files between Linux servers and client machines.

2. What Is SCP?

SCP stands for Secure Copy Protocol.

The scp command securely copies files between local and remote systems using SSH-based transport.

Features of SCP

  • Secure file transfer over an encrypted SSH connection.
  • Local-to-remote file copying.
  • Remote-to-local file copying.
  • Remote-to-remote file copying.
  • Recursive directory copying.
  • Support for SSH authentication and custom ports.

Basic Syntax

scp [OPTIONS] SOURCE DESTINATION

The source and destination can be local paths or remote paths.

Remote Path Format

username@hostname:/path/to/file

Example:

student@192.168.1.100:/home/student/file.txt

3. Check SCP Availability

SCP is normally installed as part of the OpenSSH client package.

Check Whether SCP Is Available

which scp

Display SCP Version Information

scp -V

Depending on the OpenSSH version, the version option may not be supported by scp. You can instead check:

ssh -V

Install the OpenSSH Client in Ubuntu

sudo apt update sudo apt install openssh-client
The OpenSSH client package provides utilities such as ssh, scp, sftp and ssh-keygen.

4. Copy a File From Local to Remote

This operation transfers a file from the local computer to a remote Linux machine.

Syntax

scp LOCAL_FILE username@REMOTE_HOST:/REMOTE_PATH/

Example

scp report.txt student@192.168.1.100:/home/student/

Explanation:

  • report.txt is the local file.
  • student is the remote username.
  • 192.168.1.100 is the remote system IP address.
  • /home/student/ is the destination directory.

Expected Result

report.txt       100%    2KB    1.2MB/s    00:00

The output is illustrative. Actual transfer speed and progress depend on file size and network conditions.

5. Copy a File From Remote to Local

This operation downloads a file from a remote Linux system to the local computer.

Syntax

scp username@REMOTE_HOST:/REMOTE_FILE LOCAL_PATH

Example

scp student@192.168.1.100:/home/student/report.txt .

The dot (.) represents the current local working directory.

Copy to a Specific Local Directory

scp student@192.168.1.100:/home/student/report.txt ~/Downloads/

The file will be copied into the local Downloads directory.

6. Copy a Directory Recursively

To copy an entire directory and its contents, use the recursive option -r.

Syntax

scp -r SOURCE_DIRECTORY username@REMOTE_HOST:/DESTINATION_PATH/

Example: Local to Remote

scp -r projects student@192.168.1.100:/home/student/

This copies the local projects directory and its contents to the remote home directory.

Example: Remote to Local

scp -r student@192.168.1.100:/home/student/projects ~/Downloads/

This copies the remote projects directory into the local Downloads directory.

The -r option is required when copying directories recursively. For a large directory tree or repeated synchronization, rsync may be more efficient.

7. Copy Multiple Files

SCP can copy multiple local files to the same remote destination.

Syntax

scp FILE1 FILE2 FILE3 username@REMOTE_HOST:/DESTINATION_PATH/

Example

scp file1.txt file2.txt notes.pdf student@192.168.1.100:/home/student/

All three files are copied to the remote directory.

Copy Matching Files Using a Wildcard

scp *.txt student@192.168.1.100:/home/student/documents/

This copies matching local .txt files to the remote directory. Shell wildcard expansion occurs on the local side for this command.

8. Copy Files Between Two Remote Systems

SCP can copy files from one remote machine to another.

Syntax

scp user1@HOST1:/SOURCE_FILE user2@HOST2:/DESTINATION_PATH/

Example

scp student1@192.168.1.100:/home/student1/report.txt student2@192.168.1.200:/home/student2/

Depending on the SCP implementation and options, the transfer may be relayed through the local client or performed through a direct remote-to-remote connection.

Remote-to-remote transfer can require authentication and connectivity from the relevant systems. Modern OpenSSH scp uses SFTP over SSH by default, and remote-to-remote behavior can differ from older SCP implementations.

9. Important SCP Options

Option Purpose
-r Copies directories recursively.
-P PORT Specifies the SSH port. The P is uppercase.
-i FILE Specifies the identity private key file.
-v Displays verbose diagnostic information.
-p Preserves modification times, access times and file mode bits where supported.
-C Enables compression during transfer.
-q Suppresses progress meter and warning messages.
-l LIMIT Limits bandwidth in Kbit/s.

Example: Use a Custom SSH Port

scp -P 2222 report.txt student@192.168.1.100:/home/student/

Example: Use a Specific Private Key

scp -i ~/.ssh/id_ed25519 report.txt student@192.168.1.100:/home/student/

Example: Enable Compression

scp -C report.txt student@192.168.1.100:/home/student/

Example: Preserve File Attributes

scp -p report.txt student@192.168.1.100:/home/student/

Example: Verbose Troubleshooting

scp -v report.txt student@192.168.1.100:/home/student/
Do not confuse the port options: the SSH client uses lowercase -p for a port, but SCP uses uppercase -P for a port. In SCP, lowercase -p preserves file attributes.

10. What Is SFTP?

SFTP stands for SSH File Transfer Protocol.

SFTP is a secure file-transfer protocol that operates over SSH. It provides an interactive interface for managing files on a remote system.

Features of SFTP

  • Secure file transfer.
  • Interactive remote file management.
  • Upload and download files.
  • Directory navigation.
  • File and directory management operations.
  • Support for SSH authentication methods.

Connect to a Remote SFTP Server

sftp student@192.168.1.100

After successful authentication, an SFTP prompt appears.

sftp>

11. Important SFTP Commands

Command Purpose
pwd Displays the remote working directory.
lpwd Displays the local working directory.
ls Lists remote directory contents.
lls Lists local directory contents.
cd Changes the remote working directory.
lcd Changes the local working directory.
get Downloads a remote file.
put Uploads a local file.
mkdir Creates a remote directory.
rmdir Removes an empty remote directory.
rm Removes a remote file.
rename Renames a remote file.
exit Closes the SFTP session.

Display the Remote Directory

sftp> pwd

Display the Local Directory

sftp> lpwd

List Remote Files

sftp> ls

Change the Remote Directory

sftp> cd /home/student/documents

Upload a File

sftp> put report.txt

Download a File

sftp> get report.txt

Upload a Directory Recursively

sftp> put -r projects

Download a Directory Recursively

sftp> get -r projects

Exit the Session

sftp> exit

12. SCP vs SFTP

Feature SCP SFTP
Full Form Secure Copy Protocol SSH File Transfer Protocol
Connection Uses SSH-based transport. Uses SSH transport.
Interface Primarily command-based copying. Interactive file-transfer session and command-based use.
File Upload Supported. Supported.
File Download Supported. Supported.
Remote File Management Limited copying functionality. Supports operations such as listing, renaming and deleting remote files.
Directory Transfer Uses -r. Supports recursive get and put operations.
Both tools are secure when properly configured. SFTP is often preferable when you need an interactive remote file-management session. SCP is convenient for straightforward copy operations.

13. What Is rsync?

rsync is a file synchronization and transfer utility.

It can copy files locally or between remote systems, often using SSH as its transport.

Basic Syntax

rsync [OPTIONS] SOURCE DESTINATION

Example: Copy a File to a Remote System

rsync -av report.txt student@192.168.1.100:/home/student/

Example: Synchronize a Directory

rsync -av projects/ student@192.168.1.100:/home/student/projects/

Common Options

Option Purpose
-a Archive mode; enables recursive transfer and preserves common file attributes.
-v Verbose output.
-z Compresses file data during transfer.
--progress Displays transfer progress.
--delete Deletes destination files that are absent from the source, within the synchronized scope.
-n Dry run; shows what would happen without making changes.
Use --delete carefully. It can remove destination files. Run a dry run with -n first and verify the source and destination paths.

14. Secure File Transfer Workflow

A typical file-transfer workflow between two Linux systems is:

Local Linux System
       |
       | 1. Identify the remote host
       |
       v
Remote Linux System
       |
       | 2. Verify SSH service and port
       |
       v
SSH Authentication
       |
       | 3. Verify user credentials or key
       |
       v
Secure SSH Connection
       |
       | 4. Transfer files using SCP/SFTP
       |
       v
Remote Destination Directory
       |
       | 5. Verify file and permissions
       |
       v
Transfer Completed

Verify a Transferred File

ls -lh report.txt file report.txt

Compare File Checksums

sha256sum report.txt

Run the checksum command on both systems and compare the output to verify that the files have matching SHA-256 checksums.

15. Common SCP and SFTP Errors

Error Possible Cause What to Check
Connection refused SSH server not listening on the requested port. Check SSH service and listening port.
Connection timed out Network or firewall issue. Check IP connectivity, routing and firewall rules.
Permission denied Authentication failure or insufficient file permissions. Check username, authentication method and destination permissions.
No such file or directory Incorrect source or destination path. Verify the full file path.
Host key verification failed Recorded host key differs from the presented key. Verify server identity before updating known_hosts.
Could not resolve hostname Hostname resolution problem. Check hostname, DNS and local host mappings.

Useful Troubleshooting Commands

# Check remote connectivity ping -c 4 192.168.1.100 # Check SSH service on the server sudo systemctl status ssh # Check SSH listening port on the server sudo ss -tlnp | grep ':22' # Test the remote SSH port from the client nc -vz 192.168.1.100 22 # Display verbose SCP diagnostics scp -v report.txt student@192.168.1.100:/home/student/
Ping may fail even when SSH is reachable because ICMP traffic can be filtered. Test the actual SSH port when diagnosing file-transfer connectivity.

16. Practical Lab: Copy a Local File to a Remote Machine

Objective: Transfer a file from one Linux machine to another using SCP.

Prerequisite: Two reachable Linux systems, an SSH server on the destination and a valid remote account.

Step 1: Create a Test File on the Local System

echo "Learning SCP in Linux" > report.txt

Step 2: Verify the File

cat report.txt

Step 3: Copy the File to the Remote System

scp report.txt username@REMOTE_IP:/home/username/

Step 4: Log In to the Remote System

ssh username@REMOTE_IP

Step 5: Verify the Transferred File

ls -l ~/report.txt cat ~/report.txt
Expected Result:

The remote system should contain report.txt with the same text that was created on the local machine.

17. Practical Lab: Download a Remote File

Objective: Download a file from a remote Linux system to the local machine.

Step 1: Create a File on the Remote System

echo "Remote file transfer practice" > remote.txt

Step 2: Exit the Remote Session

exit

Step 3: Download the File

scp username@REMOTE_IP:/home/username/remote.txt .

Step 4: Verify the Download

ls -l remote.txt cat remote.txt
Expected Result:

The remote.txt file should appear in the current local directory.

18. Practical Lab: Transfer a Directory

Objective: Copy an entire directory to a remote system.

Step 1: Create a Directory

mkdir linux_project

Step 2: Create Two Files

echo "Linux networking" > linux_project/networking.txt echo "SSH file transfer" > linux_project/ssh.txt

Step 3: Verify the Directory

ls -l linux_project

Step 4: Copy the Directory Recursively

scp -r linux_project username@REMOTE_IP:/home/username/

Step 5: Verify on the Remote System

ls -l ~/linux_project cat ~/linux_project/networking.txt
Expected Result:

The remote system should contain the linux_project directory and both files.

19. Practical Lab: SFTP File Transfer

Objective: Upload and download files using an interactive SFTP session.

Step 1: Connect to the Remote Server

sftp username@REMOTE_IP

Step 2: Display the Remote Directory

sftp> pwd sftp> ls

Step 3: Display the Local Directory

sftp> lpwd sftp> lls

Step 4: Upload a File

sftp> put report.txt

Step 5: Download a File

sftp> get remote.txt

Step 6: Exit SFTP

sftp> exit
Expected Result:

The upload and download operations should complete successfully. Verify the files on the relevant systems.

21. Interview Questions and Answers

Q1. What is SCP?

Answer: SCP is a secure file-copy utility that transfers files between local and remote systems using SSH-based transport.

Q2. What is the basic syntax of SCP?

Answer: scp [OPTIONS] SOURCE DESTINATION.

Q3. How do you copy a file from local to remote?

Answer: Use scp file.txt username@remote_host:/destination/.

Q4. How do you copy a file from remote to local?

Answer: Use scp username@remote_host:/path/file.txt ..

Q5. Which SCP option copies directories recursively?

Answer: The -r option.

Q6. Which SCP option specifies a custom SSH port?

Answer: Uppercase -P.

Q7. What is the purpose of the SCP -i option?

Answer: It specifies the identity private key file used for SSH authentication.

Q8. What is SFTP?

Answer: SFTP is the SSH File Transfer Protocol, which provides secure remote file access and transfer.

Q9. What is the difference between SCP and SFTP?

Answer: SCP is primarily used for direct copying, whereas SFTP provides an interactive file-management interface with commands for uploading, downloading, listing and managing files.

Q10. What does the SFTP get command do?

Answer: It downloads a file from the remote system to the local system.

Q11. What does the SFTP put command do?

Answer: It uploads a file from the local system to the remote system.

Q12. What is rsync?

Answer: rsync is a utility for synchronizing files and directories efficiently between systems.

Q13. How do you verify a transferred file?

Answer: Compare checksums, such as SHA-256 hashes, on both systems.

Q14. Why might SCP show Permission denied?

Answer: The username, password or key may be incorrect, or the account may lack permission to access the source or destination path.

Q15. Why is SSH required for SCP?

Answer: SCP uses SSH-based transport to establish an authenticated and encrypted connection for file transfer.
