Network Troubleshooting in Linux

Diagnose connectivity, DNS, routing, ports and network failures

After completing this lesson, you will be able to:

  • Understand common Linux network problems.
  • Check network interfaces and IP configuration.
  • Test network connectivity using ping.

1. Introduction to Network Troubleshooting

Network troubleshooting is the process of identifying, diagnosing and resolving problems that prevent computers and network services from communicating correctly.

Linux provides several command-line utilities to inspect network interfaces, test connectivity, examine routes, resolve hostnames and investigate network services.

Common Network Problems

Problem Description
No network connection The system cannot communicate with other devices.
Incorrect IP address The interface has an invalid or unexpected IP configuration.
Gateway failure The system cannot reach networks outside its local subnet.
DNS failure Domain names cannot be resolved into IP addresses.
Port blocked A firewall or network rule prevents access to a service.
Packet loss Some transmitted packets do not reach their destination.
High latency Network responses take longer than expected.

2. Basic Network Troubleshooting Workflow

Always investigate network problems systematically, starting with the local machine and moving toward the remote destination.

Check Network Interface

This is a useful diagnostic sequence, not an absolute rule. Some environments block ICMP traffic or use special routing and DNS configurations, so interpret each result in context.

3. Check Network Interfaces

The first step is to check whether the network interface exists and whether it is operational.

Display All Network Interfaces

ip link show

Display IP Addresses

ip addr show

Display a Short Interface Summary

ip -br addr

Check a Specific Interface

ip addr show eth0

Replace eth0 with the actual interface name shown on your system. Ubuntu systems may use names such as enp0s3 or ens33.

Important Interface States

State Meaning
UP The interface is administratively enabled.
DOWN The interface is administratively disabled.
LOWER_UP The lower-layer connection is reported as operational.
An interface marked UP does not automatically mean that internet access is available. You must also verify its IP address, routes and connectivity.

4. Check IP Address Configuration

An incorrect or missing IP address can prevent communication with other devices.

Display IPv4 and IPv6 Addresses

ip addr

Display Only IPv4 Addresses

ip -4 addr

Display Only IPv6 Addresses

ip -6 addr

Check Network Configuration

ip -br addr ip route

Check whether the interface has the expected address and whether the subnet matches the network configuration.

An address beginning with 169.254. is commonly an IPv4 link-local address. It can indicate that automatic DHCP configuration did not succeed, although the exact cause requires further investigation.

5. Test Network Connectivity Using ping

The ping command tests whether a destination responds to ICMP Echo Request messages.

Basic Syntax

ping DESTINATION

Example: Test a Public IP Address

ping 1.1.1.1

Send a Limited Number of Packets

ping -c 4 1.1.1.1

Test a Domain Name

ping -c 4 example.com

Important ping Options

Option Purpose
-c Specifies the number of packets to send.
-i Sets the interval between packets.
-W Sets the response timeout in seconds for each reply.
-s Sets the packet payload size.
-4 Uses IPv4.
-6 Uses IPv6.

Illustrative Output

64 bytes from 1.1.1.1: icmp_seq=1 ttl=57 time=20.4 ms
64 bytes from 1.1.1.1: icmp_seq=2 ttl=57 time=19.8 ms
64 bytes from 1.1.1.1: icmp_seq=3 ttl=57 time=21.1 ms
64 bytes from 1.1.1.1: icmp_seq=4 ttl=57 time=20.0 ms

--- 1.1.1.1 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss

Interpretation:

  • Packets transmitted: number of requests sent.
  • Packets received: number of replies received.
  • Packet loss: percentage of requests without a reply.
  • Time: approximate round-trip time.
A failed ping does not always mean the network is unavailable. Firewalls and remote systems may block ICMP while allowing SSH, HTTP or other services.

6. Check the Default Gateway and Routing Table

A default gateway forwards traffic to destinations outside the local network when no more specific route applies.

Display the Routing Table

ip route

Display Only the Default Route

ip route show default

Example Output

default via 192.168.1.1 dev enp0s3
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.10

In this example:

  • 192.168.1.1 is the default gateway.
  • enp0s3 is the network interface.
  • 192.168.1.10 is the local IP address.
  • 192.168.1.0/24 is the connected network.

Check the Route to a Destination

ip route get 1.1.1.1

Test the Gateway

ping -c 4 192.168.1.1
Use the gateway address shown by your own ip route command. Do not assume that every network uses 192.168.1.1.

7. Diagnose DNS Problems

DNS (Domain Name System) translates domain names into IP addresses.

If an IP address is reachable but a domain name cannot be resolved, investigate DNS configuration.

Test DNS Resolution Using getent

getent hosts example.com

Query DNS Using nslookup

nslookup example.com

Query DNS Using dig

dig example.com

Display DNS Resolver Configuration

cat /etc/resolv.conf

Check systemd-resolved Status

resolvectl status

Query a Domain Using systemd-resolved

resolvectl query example.com

Install DNS Diagnostic Utilities

sudo apt update sudo apt install dnsutils

On some Ubuntu releases, the relevant package may instead be named bind9-dnsutils.

Diagnostic example: If ping 1.1.1.1 works but getent hosts example.com fails, IP connectivity may be working while DNS resolution is failing. Continue by checking the configured resolver and DNS queries.
Do not edit /etc/resolv.conf blindly. It may be generated or managed by NetworkManager, systemd-resolved or another network service.

8. Check Open Ports and Listening Services

A service may be running but inaccessible because it is not listening on the expected port or is blocked by a firewall.

Display Listening TCP and UDP Sockets

sudo ss -tulnp

Display Listening TCP Sockets

sudo ss -tlnp

Display Listening UDP Sockets

sudo ss -ulnp

Check Whether SSH Is Listening on Port 22

sudo ss -tlnp | grep ':22'

Test a Remote TCP Port

nc -vz 192.168.1.100 22

Replace the IP address and port with the target server and service port.

Install netcat if Required

sudo apt install netcat-openbsd
A listening socket indicates that a service has bound to a local address and port. It does not prove that the service is reachable through the network firewall.

9. Trace the Network Path Using traceroute

The traceroute utility helps identify the network hops between a source system and a destination.

Install traceroute

sudo apt update sudo apt install traceroute

Trace a Route to a Domain

traceroute example.com

Trace a Route to an IP Address

traceroute 1.1.1.1

Use tracepath

tracepath example.com

Depending on the installation, tracepath may be available without installing the traceroute package.

Understanding the Output

traceroute to example.com
 1  192.168.1.1       2.1 ms  2.0 ms  2.2 ms
 2  10.10.0.1         8.5 ms  8.2 ms  8.6 ms
 3  * * *
 4  203.0.113.1      18.2 ms 18.5 ms 18.0 ms

Each numbered line represents a hop. Asterisks mean that probes did not receive a response within the timeout. They do not necessarily mean that the route is broken.

Traceroute probes and responses may be filtered or rate-limited. The path shown can also vary depending on routing and load balancing.

10. Check Network Statistics and Traffic

Display Interface Statistics

ip -s link

This command displays packet and error counters for network interfaces.

Display Detailed Interface Information

ip -details link show

Monitor Network Connections

ss -tunap

Monitor Live Network Traffic Using tcpdump

tcpdump captures packets for network analysis.

Install tcpdump

sudo apt install tcpdump

Capture Packets on an Interface

sudo tcpdump -i any

Capture Only a Limited Number of Packets

sudo tcpdump -i any -c 10

Capture Traffic for a Specific Host

sudo tcpdump -i any host 192.168.1.100

Capture Traffic on TCP Port 22

sudo tcpdump -i any tcp port 22
Packet captures may contain sensitive information such as IP addresses, hostnames and unencrypted application data. Capture only traffic you are authorized to inspect.

11. Diagnose Packet Loss and Latency

Packet loss occurs when transmitted packets fail to reach their destination or their responses are not received.

Latency is the time required for data to travel between endpoints and for a response to return when measuring round-trip time.

Check Packet Loss Using ping

ping -c 10 1.1.1.1

Check Network Path Quality Using mtr

MTR combines continuous ping-like measurements with route tracing.

Install MTR

sudo apt install mtr

Run MTR

mtr example.com

Run a Report

mtr -r -c 10 example.com

The report can show packet loss and latency measurements for individual hops.

Packet loss reported at an intermediate hop may be caused by ICMP rate limiting. If later hops show no loss, the intermediate hop may still be forwarding normal traffic correctly.

12. Check Firewall Configuration

A firewall controls incoming and outgoing network traffic according to configured rules.

Check UFW Status

sudo ufw status

Display Detailed UFW Rules

sudo ufw status verbose

Display Firewall Rules Using nftables

sudo nft list ruleset

Check Whether a Port Is Allowed by UFW

sudo ufw status numbered
Do not disable a firewall or change firewall rules just to test connectivity without understanding the security impact. If you are connected remotely, an incorrect rule can lock you out.

13. Common Network Troubleshooting Commands

Command Purpose
ip link Displays network interface states.
ip addr Displays IP addresses.
ip route Displays routing information.
ping Tests ICMP connectivity.
getent hosts Checks hostname resolution through the system name-service configuration.
nslookup Queries DNS records.
dig Performs detailed DNS queries.
ss Displays sockets and listening ports.
nc Tests TCP/UDP connectivity and can read or write network data.
traceroute Traces the network path.
tracepath Traces a path and can help investigate path MTU.
tcpdump Captures and analyzes network packets.
mtr Combines route tracing and repeated latency measurements.
ufw Manages the uncomplicated firewall.
ethtool Displays and manages supported Ethernet device settings.

Check Ethernet Link Information

sudo apt install ethtool sudo ethtool enp0s3

Replace enp0s3 with the actual interface name. Some virtual network adapters expose only limited physical-link information.

14. Common Network Problems and Solutions

Problem Diagnostic Step Possible Action
Interface is down ip link show Check the interface and network manager configuration.
No IP address ip addr Investigate DHCP or static IP configuration.
Gateway unreachable ip route and ping the gateway Check the subnet, gateway, virtual network and link.
External IP unreachable Ping a permitted external IP and inspect routes Check upstream connectivity and firewall rules.
Domain does not resolve getent hosts example.com Inspect resolver configuration and DNS service.
SSH connection refused nc -vz HOST 22 Check the SSH server and listening port.
Connection timed out Inspect routes, firewall and path Investigate packet filtering and network reachability.
High latency ping and mtr Investigate congestion, Wi-Fi and upstream links.

15. Practical Lab: Diagnose Internet Connectivity

Objective: Identify whether a Linux machine has an interface, IP address, gateway and external connectivity.

Step 1: Check Interfaces

ip -br link

Step 2: Check IP Addresses

ip -br addr

Step 3: Check the Default Gateway

ip route show default

Step 4: Test the Gateway

ping -c 4 YOUR_GATEWAY_IP

Replace YOUR_GATEWAY_IP with the gateway address displayed by your system.

Step 5: Test an External IP Address

ping -c 4 1.1.1.1

Step 6: Test DNS Resolution

getent hosts example.com

Step 7: Test the Result

Compare the results and identify the first step that fails. Record the command, output and likely cause.

Expected Learning Result:

You should be able to distinguish interface problems, IP configuration problems, gateway problems and DNS resolution problems.

16. Practical Lab: Diagnose an SSH Port

Objective: Check whether a remote SSH service is reachable.

Step 1: Check the Remote Host

ping -c 4 REMOTE_IP

Step 2: Test SSH Port 22

nc -vz REMOTE_IP 22

Step 3: Check SSH Service on the Remote Ubuntu Server

sudo systemctl status ssh

Step 4: Check Listening Port on the Remote Server

sudo ss -tlnp | grep ':22'

Step 5: Test an SSH Connection

ssh username@REMOTE_IP
The SSH service must be installed and running on the remote server. The client-side SSH command alone does not start the server.

17. Practical Lab: Diagnose DNS Resolution

Objective: Determine whether a domain-name resolution problem exists.

Step 1: Test External IP Connectivity

ping -c 4 1.1.1.1

Step 2: Test System Name Resolution

getent hosts example.com

Step 3: Query DNS Directly

dig example.com

Step 4: Inspect Resolver Configuration

cat /etc/resolv.conf resolvectl status

Step 5: Record Your Findings

  • Does the external IP respond?
  • Does the system resolve example.com?
  • Does the DNS query return an answer?
  • Which DNS server is configured?
Expected Learning Result:

You should be able to distinguish a general connectivity failure from a DNS resolution failure.

19. Interview Questions and Answers

Q1. What is network troubleshooting?

Answer: It is the process of diagnosing and resolving network communication problems.

Q2. Which command displays Linux network interfaces?

Answer: ip link show displays interface information, while ip addr show displays addresses.

Q3. What is the purpose of ping?

Answer: It sends ICMP Echo Request messages and measures the round-trip time of received replies.

Q4. What is packet loss?

Answer: Packet loss occurs when transmitted packets or their responses do not reach the expected endpoint.

Q5. What is a default gateway?

Answer: It is the router used to forward traffic when no more specific route matches the destination.

Q6. How do you check the Linux routing table?

Answer: Use ip route.

Q7. How do you troubleshoot DNS failures?

Answer: Use getent hosts, dig, nslookup and resolvectl status to inspect name resolution and resolver configuration.

Q8. What is the purpose of ss?

Answer: It displays socket information, including listening ports and active network connections.

Q9. What is the purpose of traceroute?

Answer: It identifies network hops along a path toward a destination.

Q10. What is tcpdump?

Answer: It is a command-line packet capture and analysis utility.

Q11. What is MTR?

Answer: MTR combines route tracing with repeated measurements of latency and packet loss.

Q12. What is the difference between latency and packet loss?

Answer: Latency measures the time taken for communication, while packet loss measures the proportion of packets that fail to receive a response.

Q13. Why can ping fail even when a service is reachable?

Answer: ICMP may be filtered by a firewall even though the required TCP or UDP service is allowed.

Q14. How do you check whether SSH is listening?

Answer: Use sudo ss -tlnp on the server and inspect the expected SSH port.

Q15. What is the purpose of UFW?

Answer: UFW is a simplified firewall management interface for configuring network access rules.
