ping Command in Linux

Test network connectivity, measure response time and identify packet loss

Learning Objectives

After completing this lesson, you will be able to:

  • Understand the purpose of the ping command.
  • Understand ICMP and echo request/reply messages.
  • Test connectivity to local and remote systems.
  • Control the number and interval of ping requests.
  • Interpret packet loss and round-trip time.
  • Use IPv4 and IPv6 ping commands.
  • Understand common ping errors and their causes.
  • Use ping as part of a basic network troubleshooting process.

1. Introduction to the ping Command

The ping command is a Linux networking utility used to test whether a destination system can be reached over an IP network.

It sends ICMP Echo Request messages to a destination and waits for ICMP Echo Reply messages.

The name ping comes from the sonar signal used to detect objects. In networking, it helps check whether a destination responds to network probes.

Why Is ping Used?

  • Test connectivity between two systems.
  • Check whether a server or network device responds.
  • Measure round-trip time (RTT).
  • Identify packet loss during testing.
  • Check basic connectivity to a gateway.
  • Help isolate network connectivity problems.

Basic Syntax

ping [OPTIONS] DESTINATION

The destination can be an IP address or a hostname.

Examples

ping 8.8.8.8 ping google.com ping 192.168.1.1

2. Understanding ICMP

ICMP (Internet Control Message Protocol) is a network-layer control protocol used by IP networks to communicate error information and diagnostic messages.

The ping utility commonly uses two ICMP message types:

ICMP Message Type Number Purpose
Echo Request 8 in IPv4 Requests a response from the destination.
Echo Reply 0 in IPv4 Responds to an Echo Request.

For ICMPv6, the corresponding message types are:

ICMPv6 Message Type Number
Echo Request 128
Echo Reply 129

How ping Works

  1. The source system creates an ICMP Echo Request.
  2. The request is carried inside an IP packet.
  3. The packet travels through the network to the destination.
  4. If the destination accepts and responds to the request, it sends an ICMP Echo Reply.
  5. The source receives the reply and calculates the round-trip time.
Important: ICMP is not TCP or UDP. It is a separate protocol carried directly inside IP packets.

3. Test Connectivity to an IP Address

Use ping followed by the destination IP address.

Command

ping 8.8.8.8

Here, 8.8.8.8 is an example of a public DNS resolver IP address.

Illustrative Output

PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=24.5 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=117 time=23.8 ms
64 bytes from 8.8.8.8: icmp_seq=3 ttl=117 time=24.1 ms

Understanding the Output

Field Meaning
PING 8.8.8.8 Destination being tested.
64 bytes Size of the received ICMP data payload reported by ping.
icmp_seq=1 Sequence number of the ICMP reply.
ttl=117 Remaining IPv4 Time To Live value in the received packet.
time=24.5 ms Measured round-trip time.
TTL is the remaining hop limit in an IPv4 packet. It is not the total number of hops travelled. The original TTL is not shown directly, so the exact path length cannot reliably be determined from this value alone.

4. Test Connectivity Using a Hostname

Instead of an IP address, you can provide a domain name.

Command

ping google.com

Linux first needs to resolve the hostname into an IP address. This generally involves DNS resolution.

Illustrative Output

PING google.com (142.250.183.14) 56(84) bytes of data.
64 bytes from 142.250.183.14: icmp_seq=1 ttl=116 time=25.2 ms

What Does This Test?

  • Hostname resolution, if the name is not already cached.
  • IP network reachability to the resolved address.
  • Whether ICMP Echo Replies are returned.
A successful ping to an IP address but a failed ping to a hostname may indicate a DNS resolution problem. A failed ping alone does not prove that a host is offline: firewalls and network policies may block ICMP while other services remain accessible.

5. Stop the ping Command

On Linux, ping normally continues sending requests until you stop it or use an option to limit the number of packets.

Start ping

ping google.com

Stop ping

Ctrl + C

Press Ctrl + C in the terminal to interrupt the command.

Illustrative Final Statistics

--- google.com ping statistics ---
4 packets transmitted, 4 received, 0% packet loss
rtt min/avg/max/mdev = 23.8/24.4/25.2/0.5 ms

After interruption, ping displays a summary of the test.

6. Send a Limited Number of Packets

The -c option specifies the number of Echo Request packets to send.

Syntax

ping -c COUNT DESTINATION

Example: Send Four Packets

ping -c 4 google.com

Example Output

4 packets transmitted, 4 received, 0% packet loss

This command sends four requests and exits after the test finishes, rather than continuing indefinitely.

Other Examples

ping -c 1 8.8.8.8 ping -c 5 192.168.1.1 ping -c 10 google.com

7. Change the Time Interval Between Packets

By default, Linux ping normally sends packets at intervals of approximately one second for an ordinary unprivileged invocation.

The -i option changes the interval between requests.

Syntax

ping -i INTERVAL DESTINATION

Example: One Packet Every Two Seconds

ping -i 2 -c 4 8.8.8.8

This sends four requests with approximately two seconds between transmissions.

Example: Half-Second Interval

ping -i 0.5 -c 4 8.8.8.8
Very short intervals may require elevated privileges and can generate unnecessary traffic. Use reasonable intervals during normal troubleshooting.

8. Set the Packet Size

The -s option specifies the number of data bytes in the ICMP Echo Request payload.

Syntax

ping -s SIZE DESTINATION

Example: Send 100 Bytes of ICMP Data

ping -s 100 -c 4 8.8.8.8

This requests an ICMP payload size of 100 bytes.

The size specified with -s is the ICMP data payload, not the complete IP packet size. IP and ICMP headers are additional.

9. Set a Timeout

The -w option specifies a deadline in seconds for the entire ping operation.

Example

ping -w 5 8.8.8.8

This makes ping exit after a total deadline of five seconds, even if the requested packet count has not been reached.

Limit the Wait Time for Replies

ping -W 2 -c 4 8.8.8.8

The -W option specifies the time, in seconds, to wait for a response to an individual request.

Option Purpose
-w Overall deadline for the ping command.
-W Individual response timeout.

10. IPv4 and IPv6 Ping

Linux ping supports both IPv4 and IPv6. The -4 and -6 options select the IP version.

Force IPv4

ping -4 -c 4 google.com

Force IPv6

ping -6 -c 4 google.com

Ping an IPv4 Address

ping -4 -c 4 8.8.8.8

Ping an IPv6 Address

ping -6 -c 4 2001:4860:4860::8888
IPv6 testing requires IPv6 connectivity and a usable IPv6 route. A failed IPv6 ping does not necessarily mean IPv4 connectivity is unavailable.

11. Understand Packet Loss

Packet loss occurs when transmitted packets do not reach their intended destination or their responses do not return to the source within the measurement period.

Ping calculates packet loss using the number of transmitted and received packets.

Example: No Packet Loss

5 packets transmitted, 5 received, 0% packet loss

All five requests received replies.

Example: Partial Packet Loss

5 packets transmitted, 4 received, 20% packet loss

One of the five requests did not receive a reply.

Example: Complete Packet Loss

5 packets transmitted, 0 received, 100% packet loss

No replies were received during the test.

Packet Loss Formula

Packet Loss (%) = ((Packets Transmitted - Packets Received) / Packets Transmitted) × 100

Calculation Example

Suppose 10 packets are transmitted and 8 replies are received.

Packet Loss = ((10 - 8) / 10) × 100 = 20%
Packet loss reported by ping can also result from ICMP filtering, rate limiting or temporary response delays. Use additional diagnostics before concluding that the network itself is faulty.

12. Understand Round-Trip Time (RTT)

Round-Trip Time (RTT) is the time taken for a packet to travel from the source to the destination and for the response to return to the source.

Ping reports RTT in milliseconds (ms).

Example

64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=24.5 ms

Here, the measured round-trip time is 24.5 milliseconds.

RTT Statistics

rtt min/avg/max/mdev = 20.1/24.5/30.2/3.1 ms
Metric Meaning
min Minimum measured RTT.
avg Average measured RTT.
max Maximum measured RTT.
mdev Mean deviation of measured RTT values.

High RTT may indicate network congestion, long physical distance, routing delays or processing delays.

13. Ping the Loopback Address

The loopback address is used to test the local TCP/IP networking stack without sending traffic to another physical system.

IPv4 Loopback Test

ping -c 4 127.0.0.1

Hostname-Based Loopback Test

ping -c 4 localhost

IPv6 Loopback Test

ping -6 -c 4 ::1

Purpose

  • Check basic local IP networking functionality.
  • Test the loopback interface.
  • Help distinguish local networking problems from external connectivity problems.

14. Ping the Default Gateway

A default gateway is the router or next-hop device used to reach destinations outside the local network when no more specific route matches.

Step 1: Display the Routing Table

ip route show

Example Output

default via 192.168.1.1 dev enp0s3

Step 2: Ping the Gateway

ping -c 4 192.168.1.1

Replace this example address with the actual gateway shown in your routing table.

Interpretation

  • If replies arrive, the gateway is responding to ICMP requests.
  • If replies do not arrive, check the interface, address configuration, local link and gateway policy.

15. Important ping Options

Option Purpose Example
-c Limit the number of requests. ping -c 4 8.8.8.8
-i Set the interval between requests. ping -i 2 8.8.8.8
-s Set ICMP data payload size. ping -s 100 8.8.8.8
-w Set the overall deadline. ping -w 5 8.8.8.8
-W Set the reply wait timeout. ping -W 2 -c 4 8.8.8.8
-4 Use IPv4. ping -4 google.com
-6 Use IPv6. ping -6 google.com
-n Numeric output; do not resolve addresses into hostnames. ping -n 8.8.8.8
-q Quiet output; show summary information. ping -q -c 5 8.8.8.8

16. Common ping Error Messages

1. Destination Host Unreachable

From 192.168.1.10 icmp_seq=1 Destination Host Unreachable

Possible causes:

  • No usable route to the destination.
  • Local gateway or neighbor resolution problem.
  • Destination network is unreachable.

2. Network Is Unreachable

connect: Network is unreachable

Possible cause: The system does not have a suitable route to the destination.

3. Temporary Failure in Name Resolution

ping: google.com: Temporary failure in name resolution

Possible cause: The hostname could not be resolved at that time. Check DNS configuration and connectivity.

4. 100% Packet Loss

4 packets transmitted, 0 received, 100% packet loss

Possible causes:

  • Destination is unavailable.
  • ICMP requests or replies are blocked.
  • Routing or firewall configuration is incorrect.
  • There is a network connectivity problem.

5. Operation Not Permitted

Some advanced ping operations may require elevated privileges or specific system permissions. Use ordinary ping options first and consult the command's manual for the operation involved.

A ping failure is not conclusive evidence that a remote server is down. Some servers intentionally ignore ICMP Echo Requests while continuing to provide web, SSH or other services.

17. Practical Lab: Network Connectivity Testing

Objective: Use ping to test local, gateway and external network connectivity from Ubuntu running in VirtualBox.

Step 1: Test the Loopback Address

ping -c 4 127.0.0.1

Step 2: Display Your IP Address

ip -br addr

Step 3: Display Your Default Gateway

ip route show

Step 4: Ping Your Gateway

Use the gateway address shown by the previous command.

ping -c 4 GATEWAY_IP

Step 5: Test an External IP Address

ping -c 4 8.8.8.8

Step 6: Test a Domain Name

ping -c 4 google.com

Step 7: Compare IPv4 and IPv6

ping -4 -c 4 google.com ping -6 -c 4 google.com

Step 8: Test Packet Loss and RTT

ping -c 10 8.8.8.8
Expected Result:

Record whether each test succeeds, the number of packets transmitted and received, packet loss percentage and average RTT. Results depend on your current network and whether the destination allows ICMP.

19. Interview Questions and Answers

Q1. What is ping in Linux?

Answer: ping is a network diagnostic utility that sends ICMP Echo Request messages and waits for Echo Replies to test IP reachability.

Q2. Which protocol does ping use?

Answer: It uses ICMP for IPv4 and ICMPv6 for IPv6.

Q3. What is an ICMP Echo Request?

Answer: It is a diagnostic message sent by a source system to request an Echo Reply from a destination.

Q4. What is RTT?

Answer: Round-trip time is the measured time taken for a request to reach a destination and its response to return.

Q5. What is packet loss?

Answer: Packet loss is the percentage of transmitted packets for which no corresponding response is received during the test.

Q6. How do you send only five ping requests?

Answer: Use ping -c 5 DESTINATION.

Q7. How do you stop ping?

Answer: Press Ctrl + C in the terminal.

Q8. What is the loopback address?

Answer: The IPv4 loopback address is 127.0.0.1. The IPv6 loopback address is ::1.

Q9. Does ping use TCP or UDP?

Answer: No. Standard ping uses ICMP or ICMPv6, not TCP or UDP.

Q10. What does 100% packet loss mean?

Answer: No Echo Replies were received during the test. The cause may be network failure, routing issues, filtering or destination policy.

Q11. Can ping test DNS resolution?

Answer: When a hostname is used, ping normally requires name resolution before sending requests. However, ping is not a complete DNS diagnostic tool.

Q12. What is the difference between ping and traceroute?

Answer: ping tests destination reachability and measures RTT. traceroute attempts to identify intermediate routing hops along a path.

Q13. What is the difference between -w and -W?

Answer: -w specifies an overall deadline for the command, while -W specifies the wait time for an individual reply.

Q14. Does successful ping guarantee that a website is working?

Answer: No. It only indicates that ICMP Echo Replies were received. The web server and its HTTP/HTTPS services must be tested separately.

Q15. Why can ping fail even when a server is working?

Answer: A firewall or network policy may block ICMP Echo Requests or Replies while allowing application traffic such as HTTP, HTTPS or SSH.

21. Lesson Summary

  • ping is a network diagnostic command used to test IP reachability.
  • It uses ICMP for IPv4 and ICMPv6 for IPv6.
  • Echo Request messages are sent to the destination.
  • Echo Reply messages indicate that the destination responded.
  • ping -c limits the number of requests.
  • ping -i changes the interval between requests.
  • ping -s sets the ICMP data payload size.
  • ping -4 selects IPv4.
  • ping -6 selects IPv6.
  • RTT measures the round-trip time of a request and response.
  • Packet loss indicates requests for which no reply was received.
  • A failed ping does not always mean that the destination is offline.
