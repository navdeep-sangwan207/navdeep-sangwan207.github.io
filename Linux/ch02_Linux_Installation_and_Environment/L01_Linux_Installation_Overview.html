Linux Installation Overview

1. Introduction to Linux Installation

Linux installation is the process of preparing a computer system to run a Linux operating system. It involves selecting a Linux distribution, preparing storage, configuring system settings and installing the required operating system files.

Linux can be installed directly on a computer, alongside another operating system, or inside a virtual machine. It can also be accessed through a Live USB, WSL or a remote cloud server.

Definition: Linux installation is the process of deploying a Linux distribution onto a physical or virtual computing environment so that the system can boot and operate using Linux.

Why Install Linux?

  • Programming: Develop applications using C, C++, Python and other languages.
  • System Programming: Learn processes, memory management, system calls and file operations.
  • Embedded Systems: Work with embedded Linux, device drivers and hardware interfaces.
  • Server Management: Configure web servers, databases and network services.
  • Cybersecurity: Study system security, permissions and network tools.
  • Open-Source Development: Explore and modify available software projects.

2. Linux Installation Methods

Linux provides several installation and usage methods. The appropriate method depends on hardware availability, learning requirements and whether Linux needs to replace or coexist with an existing operating system.

2.1 Bare-Metal Installation

Bare-metal installation means installing Linux directly on a physical computer without a host operating system running underneath it.

  • Linux uses the computer's physical hardware.
  • It can be the only operating system on the computer.
  • It provides direct access to hardware resources.
  • It is suitable for dedicated Linux computers and servers.
Example: Installing Ubuntu directly on a laptop after preparing its storage for Linux.

2.2 Dual-Boot Installation

Dual boot allows two operating systems to be installed on the same computer. The user selects which operating system to start when the computer boots.

  • Windows and Linux can coexist on one computer.
  • Each operating system normally uses its own partitions.
  • The bootloader provides an operating system selection menu.
  • Only one operating system runs at a time in a normal dual-boot setup.
Important: Dual-boot installation involves disk partitioning. Incorrect partition selection can erase existing data. Always create and verify a backup before modifying disk partitions.

2.3 Virtual Machine Installation

A virtual machine (VM) allows Linux to run as a guest operating system inside another operating system, called the host operating system.

Virtualization software creates virtual hardware such as a virtual CPU, RAM, storage device and network adapter. Linux uses these virtual resources as if they were physical hardware.

  • The existing operating system remains installed.
  • Linux runs inside a separate virtual environment.
  • Virtual disks can be created without repartitioning the host disk.
  • Snapshots can help restore an earlier VM state.
Example: Running Ubuntu inside Oracle VirtualBox on a Windows computer. Windows is the host OS, and Ubuntu is the guest OS.

Host OS vs Guest OS

Host Operating System Guest Operating System
Runs directly on the physical computer in a typical desktop VM setup. Runs inside a virtual machine.
Provides resources to virtualization software. Uses virtual resources assigned by the VM.
Example: Windows 11. Example: Ubuntu Linux.

2.4 Live USB

A Live USB is a bootable USB drive that contains a Linux distribution. It allows a computer to start and run Linux directly from the USB drive without necessarily installing it on the internal storage.

  • Useful for testing Linux before installation.
  • Can help troubleshoot an existing computer.
  • Can provide access to Linux utilities.
  • Changes may not be saved after restarting unless persistent storage is configured.

2.5 Windows Subsystem for Linux (WSL)

Windows Subsystem for Linux (WSL) allows users to run a Linux environment directly on Windows without setting up a traditional dual-boot installation.

  • Provides access to Linux command-line tools.
  • Supports Linux development workflows.
  • Can run distributions such as Ubuntu.
  • WSL 2 uses a lightweight virtualized Linux kernel.
Note: WSL is a Linux environment integrated with Windows. It is not the same as installing Linux as a separate operating system in a traditional dual-boot setup.

2.6 Cloud or Remote Linux Server

Linux can also run on a remote physical or virtual server. Users connect to it over a network, commonly through SSH (Secure Shell).

  • Useful for server administration.
  • Supports remote programming and development.
  • Commonly used for cloud computing and deployment.
  • Does not require installing Linux on the local computer.

4. Pre-Installation Planning

Before installing Linux, several factors must be checked to avoid installation errors and hardware compatibility problems.

4.1 Select a Linux Distribution

A Linux distribution is a complete operating system built around the Linux kernel and supplied with system utilities, software packages and applications.

Examples include:

  • Ubuntu
  • Debian
  • Fedora
  • Linux Mint
  • Arch Linux

4.2 Check Processor Architecture

Linux distributions provide installation images for different processor architectures.

Architecture Description
x86_64 / AMD64 64-bit architecture commonly used by desktop and laptop processors.
ARM64 / AArch64 64-bit ARM architecture used in many embedded and mobile platforms.
Important: AMD64 is the name commonly used for the 64-bit x86 architecture. It supports compatible Intel and AMD processors; it does not mean the image is only for AMD processors.

4.3 Check Hardware Compatibility

  • Processor compatibility and architecture.
  • Available RAM.
  • Free storage capacity.
  • Graphics hardware and display support.
  • Wi-Fi, Ethernet and Bluetooth compatibility.
  • Availability of required device drivers.

4.4 Understand BIOS and UEFI

BIOS and UEFI are firmware interfaces used to initialize hardware and start the operating system boot process.

BIOS UEFI
Older firmware interface. Modern firmware interface.
Commonly associated with MBR partitioning. Commonly used with GPT partitioning.
Uses a traditional boot process. Supports modern boot features, including Secure Boot.

Modern Linux installations commonly use UEFI with GPT-partitioned disks. BIOS with MBR is also supported by many Linux distributions and older systems.

4.5 Backup Important Data

Before changing partitions or installing an operating system, create a backup of important files.

  • Documents and personal files.
  • Photos and videos.
  • Source code and project files.
  • Important configuration files.
  • Recovery keys and required credentials.
Installation safety: Selecting the wrong disk or partition during installation can permanently erase data. Verify the target storage device and backup before proceeding.

5. ISO Images and Bootable Installation Media

5.1 What is an ISO Image?

An ISO image is a file that contains a complete filesystem image of an optical disc or installation medium. Linux distributions commonly provide ISO files for operating system installation.

Example: An Ubuntu Desktop ISO file contains the files needed to start the Ubuntu installer or run a Live environment.

5.2 What is a Bootable USB?

A bootable USB is a USB storage device prepared so that a computer can start an operating system or installer from it.

  1. Download the ISO image from the official distribution website.
  2. Check the downloaded file's checksum.
  3. Connect a suitable USB drive.
  4. Use a bootable USB creation tool.
  5. Select the ISO image and target USB device.
  6. Write the image to the USB drive.
  7. Safely eject the USB after completion.
Note: Writing an ISO image to a USB drive is different from simply copying the ISO file onto the USB. The creation tool prepares the USB so the computer can boot from it.

5.3 Verify ISO Integrity

A checksum is a calculated value used to verify whether a downloaded file matches the expected file. Linux distributions commonly publish SHA-256 checksums.

Example Windows CMD command:

certutil -hashfile ubuntu.iso SHA256

Compare the generated hash with the SHA-256 value published by the distribution provider.

6. Linux Disk Partitioning Overview

Disk partitioning divides a physical storage device into separate logical sections called partitions. Linux uses partitions to organize system files, user data and boot-related information.

Common Linux Partitions

Partition Purpose
EFI System Partition (ESP) Stores UEFI bootloader files.
Root (/) Contains the main Linux filesystem and system directories.
Home (/home) Stores user files and personal settings when configured separately.
Swap Provides disk-backed memory support and can support hibernation when configured appropriately.
Important: A separate swap partition is not mandatory. Linux can use a swap file instead. Partition requirements depend on the distribution and installation configuration.

Common Linux Filesystems

  • ext4: A widely used Linux filesystem and a common default choice.
  • Btrfs: Supports features such as snapshots and checksumming.
  • XFS: A high-performance filesystem commonly used for large files and server workloads.

7. Overall Linux Installation Workflow

The following steps represent a typical Linux installation process. The exact screens and options depend on the distribution and installation method.

  1. Select a distribution: Choose a suitable Linux distribution and release.
  2. Check system requirements: Verify processor architecture, RAM, storage and hardware compatibility.
  3. Download the ISO: Obtain the installation image from the official website.
  4. Verify the ISO: Compare its checksum with the published checksum.
  5. Prepare installation media: Create a bootable USB or configure a virtual machine.
  6. Start the installer: Boot the physical computer or start the virtual machine.
  7. Select language and keyboard: Configure basic regional and input settings.
  8. Configure network: Connect to a network if required.
  9. Select installation type: Choose the appropriate installation and storage configuration.
  10. Configure partitions: Select or create the required partitions carefully.
  11. Create a user account: Set the username, password and other account details.
  12. Install Linux: Allow the installer to copy and configure the operating system files.
  13. Install bootloader: Configure the system boot process as required by the installation method.
  14. Restart the system: Complete the installation and boot into Linux.
  15. Update the system: Install available updates and configure the development environment.

8. Secure Boot and Device Drivers

Secure Boot

Secure Boot is a UEFI firmware security feature that helps ensure that trusted boot components are loaded during system startup.

Many mainstream Linux distributions support Secure Boot through appropriately signed boot components.

Note: Do not disable Secure Boot by default. Check the distribution's documentation and hardware compatibility before changing firmware settings.

Device Drivers

Device drivers are software components that allow the operating system to communicate with hardware devices.

Examples include:

  • Graphics drivers.
  • Network interface drivers.
  • Wi-Fi and Bluetooth drivers.
  • Audio drivers.
  • Storage controller drivers.
Embedded Systems Connection: Linux device drivers provide an interface between the Linux kernel and hardware peripherals. Understanding drivers is important when studying embedded Linux and Linux kernel development.

11. Interview Questions

Q1. What is Linux installation?

Linux installation is the process of deploying a Linux distribution onto physical or virtual hardware so that the system can boot and operate using Linux.

Q2. What is dual boot?

Dual boot is a configuration in which two operating systems are installed on the same computer and the user selects one during startup.

Q3. What is a virtual machine?

A virtual machine is a software-based computer that provides virtual hardware resources to run a guest operating system.

Q4. What is the difference between a host OS and a guest OS?

The host OS is the operating system running on the physical computer in a typical desktop virtualization setup. The guest OS runs inside a virtual machine.

Q5. What is an ISO image?

An ISO image is a file containing a complete image of an installation disc or bootable installation medium.

Q6. What is a bootable USB?

A bootable USB is a USB storage device prepared to start an operating system or installer when the computer boots from it.

Q7. What is disk partitioning?

Disk partitioning is the process of dividing a physical storage device into separate logical sections called partitions.

Q8. What is the purpose of the root partition?

The root partition, represented by /, contains the main Linux filesystem and system directories.

Q9. What is Secure Boot?

Secure Boot is a UEFI security feature that helps verify trusted boot components during system startup.

Q10. Why is a virtual machine useful for learning Linux?

It provides an isolated environment for learning, testing and experimenting without requiring traditional repartitioning of the host disk.

12. Multiple Choice Questions (MCQs)

Q1. Which method allows Linux to run inside Windows using virtualization software?

  1. Bare-metal installation
  2. Virtual machine
  3. Dual boot
  4. Disk partitioning
Answer: B. Virtual machine

Q2. Which partition commonly stores UEFI bootloader files?

  1. Root partition
  2. Home partition
  3. EFI System Partition
  4. Swap partition
Answer: C. EFI System Partition

Q3. What does ISO commonly represent in Linux installation?

  1. A process
  2. A disk image file
  3. A device driver
  4. A Linux user account
Answer: B. A disk image file

Q4. Which architecture is commonly used by modern desktop PCs?

  1. AMD64 / x86_64
  2. AVR
  3. 8051
  4. 16-bit x86 only
Answer: A. AMD64 / x86_64

Q5. Which command calculates a SHA-256 hash in Windows CMD?

  1. dir
  2. ipconfig
  3. certutil -hashfile
  4. tasklist
Answer: C. certutil -hashfile
