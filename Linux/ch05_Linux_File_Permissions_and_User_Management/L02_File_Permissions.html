File Permissions in Linux

Understanding Ownership and Access Control for Files and Directories

Home Linux Course Chapter 5

Learning Objectives

After completing this lesson, you will be able to:

  • Understand the Linux file permission system.
  • Identify file owners and groups.
  • Understand the three permission categories.
  • Recognize read, write and execute permissions.
  • Interpret permission strings such as rwxr-xr--.
  • Understand how Linux checks access permissions.
  • Inspect file and directory permissions using Linux commands.

1. Introduction to File Permissions

Linux is a multi-user operating system. Multiple users can access the same system, but every user should not automatically have permission to access or modify every file.

Linux uses a file permission system to control who can read, modify or execute files and who can access directories.

File permissions are an important part of Linux security and system administration.

Why Are File Permissions Required?

  • To protect personal files and directories.
  • To prevent unauthorized modification.
  • To control program execution.
  • To support secure sharing of files.
  • To manage access among multiple users.
Example: A student may be allowed to read a shared document but may not be allowed to modify or delete it. Linux permissions help enforce this type of access control.

2. File Ownership in Linux

Every Linux file and directory has an owner and an associated group. These identities are used when determining which permission class applies to a user.

1. Owner

The owner is the user account associated with the file or directory.

2. Group

The group is the group associated with the file or directory. Users who belong to that group may receive the permissions assigned to the group class.

3. Others

Others means users who are neither the file owner nor members of the file's associated group for the purpose of permission selection.

Linux evaluates permissions using the owner, group and others categories. A user does not receive the union of all three categories; the applicable class is selected according to the user's identity and group membership.

3. Three Permission Categories

Linux divides basic file permissions into three categories.

Category Symbol Meaning
User / Owner u Permissions for the file owner.
Group g Permissions for members of the file's group.
Others o Permissions for other users.

Example

-rwxr-xr--

This permission string can be divided into the following sections:

- | rwx | r-x | r-- Owner Group Others
Section Permission
Owner Read, write and execute.
Group Read and execute.
Others Read only.
The first character is not part of the nine basic permission characters. It identifies the file type, such as a regular file or directory.

4. Types of Linux Permissions

Linux provides three basic permission types: read, write and execute.

1. Read Permission (r)

Read permission allows a user to read the contents of a file.

  • Symbol: r
  • Numeric value: 4
cat file.txt

If the user has the necessary read permission, the contents of the file can be displayed.

2. Write Permission (w)

Write permission allows a user to modify the contents of a file.

  • Symbol: w
  • Numeric value: 2
echo "Linux Learning" >> file.txt

This command appends text to a file when the user has the required write access.

3. Execute Permission (x)

Execute permission allows a user to execute a file as a program or script, subject to other system restrictions.

  • Symbol: x
  • Numeric value: 1
./script.sh

The file must have execute permission and a valid executable format or interpreter configuration.

5. File Permissions vs Directory Permissions

The meaning of read, write and execute permissions differs slightly between regular files and directories.

Permission Regular File Directory
Read (r) Read file contents. List directory entries, subject to other access requirements.
Write (w) Modify file contents. Create, delete or rename entries, subject to directory permissions and other restrictions.
Execute (x) Execute the file as a program or script when applicable. Search or traverse the directory and access entries when other permissions allow.
Important: Directory execute permission is commonly called search or traversal permission. It allows a user to access entries by name when the required permissions are available.

Example: Directory Access

mkdir project chmod 700 project

The directory owner receives read, write and execute permissions. Group members and others receive no permissions through the basic mode bits.

6. Understanding the Permission String

When you execute the ls -l command, Linux displays a long listing containing file type, permissions, ownership, size and modification time.

Command

ls -l

Example Output

-rw-r--r-- 1 navdeep navdeep 1200 Nov 5 10:30 notes.txt drwxr-xr-x 2 navdeep navdeep 4096 Nov 5 10:35 Documents

Understanding the First Entry

-rw-r--r--
Position Symbol Meaning
1 - Regular file.
2–4 rw- Owner can read and write.
5–7 r-- Group can read only.
8–10 r-- Others can read only.

Understanding File Types

Symbol File Type
- Regular file.
d Directory.
l Symbolic link.
c Character device.
b Block device.
p Named pipe (FIFO).
s Socket.

7. How Linux Checks Permissions

When a process attempts to access a file or directory, Linux checks the credentials of that process and the applicable permission rules.

The basic permission-selection process is:

  1. If the process's effective UID matches the file owner UID, owner permissions apply.
  2. Otherwise, if the process belongs to the file's group, group permissions apply.
  3. Otherwise, others permissions apply.
Example: A file belongs to user navdeep and group developers. If another user is a member of the developers group but is not the owner, the group permission class is used.
This describes the basic Unix permission selection model. Access Control Lists (ACLs), capabilities, mandatory access control systems and other security mechanisms can add further rules.

8. Inspecting File Permissions

1. Using ls -l

ls -l filename

Displays the permissions, owner, group and other details of a file.

2. Using ls -ld

ls -ld directory_name

Displays information about the directory itself instead of listing its contents.

3. Using stat

stat filename

Displays detailed file information, including permission modes and ownership.

Example

stat notes.txt
Example Output (format may vary):
File: notes.txt Size: 1200 Access: (0644/-rw-r--r--) Uid: (1000/navdeep) Gid: (1000/navdeep)

9. Practical Lab: Inspect File Permissions

Objective: To create files and directories and inspect their permission information.

Step 1: Create a Working Directory

mkdir permission_lab cd permission_lab

Step 2: Create a File

touch notes.txt

Step 3: Display File Permissions

ls -l notes.txt

Step 4: Display Detailed File Information

stat notes.txt

Step 5: Create a Directory

mkdir project

Step 6: Display Directory Permissions

ls -ld project

Step 7: Display All Entries

ls -la
Expected Result: You should be able to identify file types, permission strings, owners and groups from the command output.

10. Common Mistakes and Precautions

1. Confusing File and Directory Permissions

Read permission on a directory allows listing its entries, while execute permission allows traversal. These are different operations.

2. Assuming Write Permission Always Allows Deletion

Deleting a file normally depends on write and execute permissions on its parent directory, along with applicable restrictions.

3. Ignoring Ownership

A permission string cannot be interpreted correctly without also checking the file owner and group.

4. Confusing the Permission Classes

Owner, group and others are separate permission classes. Linux selects the applicable class according to the process identity.

Security Warning: Avoid granting broad permissions to important system files. Incorrect permissions can expose sensitive information or affect system security.

11. Interview Questions and Answers

Q1. What are file permissions in Linux?

File permissions control which users can read, modify or execute files and access directories.

Q2. What are the three permission categories?

Owner, group and others.

Q3. What are the three basic permission types?

Read (r), write (w) and execute (x).

Q4. What does the symbol r represent?

Read permission.

Q5. What does the symbol w represent?

Write permission.

Q6. What does the symbol x represent?

Execute permission for files and traversal permission for directories.

Q7. Which command displays detailed file permissions?

The ls -l command.

Q8. What does the first character in a permission string indicate?

It indicates the file type, such as a regular file or directory.

Q9. What does rw-r--r-- mean?

The owner can read and write. The group and others can read only.

Q10. Which command displays detailed file metadata?

The stat command.

13. Lesson Summary

  • Linux uses permissions to control access to files and directories.
  • Every file has an owner and an associated group.
  • The three permission categories are owner, group and others.
  • The three basic permissions are read, write and execute.
  • Read permission on a file allows reading its contents.
  • Write permission on a file allows modifying its contents.
  • Execute permission on a directory allows traversal.
  • ls -l displays detailed file information.
  • ls -ld displays information about a directory itself.
  • stat displays detailed file metadata.
  • Linux selects the applicable owner, group or others permission class.
Key Concept to Remember: Linux permissions define what an identified user can do with a file or directory. Always examine the file type, ownership and permission classes together.
