Understanding Default File and Directory Permissions

Learning Objectives

  • Understand the purpose of umask in Linux.
  • Explain default permissions for files and directories.

1. Introduction to umask

The umask command in Linux is used to control the default permissions assigned to newly created files and directories.

When a process creates a file or directory, Linux uses the requested creation permissions and applies the current umask to remove permission bits.

umask does not directly assign permissions. It defines which permission bits must be disabled from the requested default mode.

Why Is umask Important?

  • Helps protect newly created files.
  • Controls default access for other users.
  • Reduces accidental exposure of files.
  • Provides a consistent default permission policy.

2. Default Permissions in Linux

Linux normally uses these maximum requested permission modes when creating new objects:

Object Base Permission Mode Meaning
Regular file 666 Read and write for owner, group and others.
Directory 777 Read, write and execute for owner, group and others.
These are requested base modes used in the standard permission calculation. The actual result may also be affected by the application, filesystem, ACLs or other system policies.

Why Are New Files Not Created with 777?

Regular files commonly use 666 as their base mode because execute permission is not normally appropriate for a newly created data file.

Directories use 777 as their base mode because execute permission is needed to access and traverse a directory.

3. Understanding umask Calculation

The umask value removes permission bits from the base creation mode.

Example: umask 022

For a regular file:

Base file mode : 666 umask : 022 Result : 644

For a directory:

Base directory mode : 777 umask : 022 Result : 755
Effective Permissions:
  • New files: 644 (rw-r--r--)
  • New directories: 755 (rwxr-xr-x)

Meaning of 022

Digit Permission Class Bits Removed
0 Owner None
2 Group Write
2 Others Write

Therefore, the group and others do not receive write permission on newly created objects.

4. Understanding Octal Permission Values

Linux permission values use three bits: read, write and execute.

Permission Numeric Value
Read (r) 4
Write (w) 2
Execute (x) 1
No permission 0

Common umask Values

umask New File Mode New Directory Mode
000 666 777
022 644 755
027 640 750
077 600 700
002 664 775
The resulting modes shown here assume the standard base modes of 666 for regular files and 777 for directories.

5. Displaying the Current umask

Use the following command to display the current umask value:

umask
Example Output:
0022

This indicates that write permission is removed from the group and others when calculating standard default permissions.

Display Symbolic umask

umask -S

The -S option displays the umask in a human-readable symbolic form.

Example Output:
u=rwx,g=rx,o=rx

This describes the permissions retained for the owner, group and others.

6. Changing the umask Value

You can change the current shell's umask using the umask command.

Syntax

umask VALUE

Example 1: Set umask to 022

umask 022

Example 2: Set umask to 027

umask 027

Example 3: Set umask to 077

umask 077

The changed value applies to subsequently created files and directories by processes inheriting that shell's umask.

A umask change in one terminal normally affects that shell and its child processes. It does not automatically change the umask in every other open terminal.

7. Calculating Default File Permissions

Example 1: umask 022

Base mode : 666 umask : 022 Result : 644

The new file has read and write permission for the owner, and read permission for group and others.

Example 2: umask 077

Base mode : 666 umask : 077 Result : 600

Only the owner receives read and write permissions.

Example 3: umask 027

Base mode : 666 umask : 027 Result : 640

The owner receives read and write permissions, the group receives read permission, and others receive no permissions.

8. Symbolic umask Notation

umask can also be displayed or specified using symbolic permission notation.

Example

umask -S

Example output:

u=rwx,g=rx,o=rx

You can also set a symbolic umask:

umask u=rwx,g=rx,o=

This sets the retained permissions to full permissions for the owner, read and execute for the group, and no permissions for others. It corresponds to an octal umask of 027.

Symbolic umask notation describes permissions that are retained, unlike chmod notation, which describes permissions to assign.

9. Difference Between chmod and umask

Feature chmod umask
Purpose Changes existing file or directory permissions. Controls default permissions for newly created objects.
When applied After an object exists. When a new object is created.
Example chmod 644 file.txt umask 022
Direct effect Changes permission bits. Removes bits from requested creation permissions.
chmod modifies permissions of existing objects. umask influences the default permissions of newly created objects.

10. Practical Lab: Testing umask in Ubuntu

Objective: To observe how different umask values affect newly created files and directories.

Step 1: Check Current umask

umask

Step 2: Create a Lab Directory

mkdir umask_lab cd umask_lab

Step 3: Set umask to 022

umask 022

Step 4: Create a File and Directory

touch file_022.txt mkdir dir_022

Step 5: Check Permissions

ls -l
Expected Result:
  • file_022.txt: 644 (rw-r--r--)
  • dir_022: 755 (rwxr-xr-x)

Step 6: Set umask to 077

umask 077

Step 7: Create Another File and Directory

touch file_077.txt mkdir dir_077

Step 8: Check Permissions Again

ls -l
Expected Result:
  • file_077.txt: 600 (rw-------)
  • dir_077: 700 (rwx------)

Step 9: Display Symbolic umask

umask -S

Step 10: Verify Using stat

stat -c "%a %n" file_022.txt stat -c "%a %n" dir_022 stat -c "%a %n" file_077.txt stat -c "%a %n" dir_077

Step 11: Restore the Previous umask

If you recorded your original umask value in Step 1, restore it:

umask 022

Replace 022 with your original value if it was different.

This lab assumes standard file and directory creation modes. If an application explicitly requests more restrictive permissions or filesystem ACLs apply, the observed results may differ.

11. Common Errors and Important Notes

1. Incorrect umask Value

Use valid octal digits from 0 to 7 when specifying an octal umask.

2. Expecting Existing Files to Change

Changing umask does not modify permissions of files and directories that already exist.

3. Forgetting Shell Scope

A change made in one terminal generally applies to that shell and its child processes, not every running shell.

4. Assuming All Applications Use the Same Modes

Applications can request creation modes that are more restrictive than the standard base modes. ACLs and other security policies can also influence effective access.

Do not use umask 000 as a general security setting. It can allow overly broad default permissions when applications request them.

12. Interview Questions and Answers

Q1. What is umask?

umask is a command and process setting that controls which permission bits are removed from requested default creation modes.

Q2. What does umask stand for?

It means user file-creation mode mask.

Q3. What is the default base mode for a regular file?

666.

Q4. What is the default base mode for a directory?

777.

Q5. What is the result of umask 022 for a regular file?

644, assuming a base mode of 666.

Q6. What is the result of umask 022 for a directory?

755, assuming a base mode of 777.

Q7. Which command displays the current umask?

umask.

Q8. Which option displays symbolic umask notation?

umask -S.

Q9. Does umask modify existing file permissions?

No. It affects the permissions of newly created objects.

Q10. What does umask 077 normally produce?

New regular files get mode 600 and new directories get mode 700 under standard creation modes.

14. Lesson Summary

  • umask controls default permissions for newly created files and directories.
  • It removes permission bits from requested creation modes.
  • The standard base mode for regular files is 666.
  • The standard base mode for directories is 777.
  • umask 022 normally produces file mode 644 and directory mode 755.
  • umask 077 normally produces file mode 600 and directory mode 700.
  • Use umask to display the current value.
  • Use umask -S to display symbolic permissions.
  • Changing umask does not modify existing objects.
  • umask is different from chmod.
Key Concept to Remember: umask determines which permissions are withheld when new files and directories are created.
