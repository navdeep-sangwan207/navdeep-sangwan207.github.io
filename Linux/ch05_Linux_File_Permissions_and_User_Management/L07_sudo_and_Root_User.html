sudo and Root User

1. Introduction to the Root User

Linux is a multi-user operating system. Different users can have different permissions and levels of access.

The root user is the superuser account in Linux. It has unrestricted administrative privileges over the system, subject to kernel and security restrictions.

Root is the most privileged standard user account in Linux. It can perform administrative tasks such as managing users, changing system files, installing software and controlling system services.

Root User Details

Property Value
Username root
User ID (UID) 0
Primary group root
Privilege level Administrative / Superuser
Home directory /root

Check the Current User

whoami

To display user and group IDs:

id
Example output for a normal user:
uid=1000(user) gid=1000(user) groups=1000(user),27(sudo)

The UID is an example. Actual usernames, IDs and group memberships depend on the system.

2. Normal User vs Root User

Feature Normal User Root User
UID Usually 1000 or higher on many Linux systems 0
Privileges Limited by permissions Administrative privileges
System file modification Normally restricted Generally permitted
Software installation Usually requires elevated privileges Can install system software
User management Normally restricted Can manage user accounts
Home directory Usually /home/username /root
UID 0 identifies the superuser account. A username other than root can also have UID 0, although this is generally discouraged.

3. What Is sudo?

sudo stands for Superuser Do. It allows an authorized user to execute a command with the privileges of another user, commonly root.

Instead of logging in as root for every administrative task, a user can run only the required command with elevated privileges.

Syntax

sudo COMMAND

Example

sudo apt update

This runs the package-list update operation with administrative privileges.

sudo normally asks for the invoking user's password, not the root password. The exact authentication behavior depends on the sudoers policy and authentication settings.

4. Common sudo Commands

1. Update Package Lists

sudo apt update

Refreshes the package information from configured software repositories.

2. Upgrade Installed Packages

sudo apt upgrade

Installs available package upgrades.

3. Install a Package

sudo apt install tree

Installs the tree package, if available in the configured repositories.

4. Create a System Directory

sudo mkdir /opt/demo_directory

Creates a directory under /opt using administrative privileges.

5. Change File Ownership

sudo chown root:root example.txt

Changes the owner and group of the file to root, provided the file exists and the command is permitted.

6. Edit a System Configuration File

sudo nano /etc/hosts

Opens the hosts configuration file in the Nano text editor with elevated privileges.

5. Understanding sudo Password Authentication

When a user executes a sudo command, the system may request authentication.

Example

sudo apt update
Example terminal prompt:
[sudo] password for user:

Enter the password of the account running sudo.

While entering a password in a Linux terminal, characters and asterisks are usually not displayed. This is normal. Type the password and press Enter.

Check sudo Access

sudo -l

Displays the commands the current user is allowed to execute through sudo.

6. Understanding the su Command

The su command is used to switch to another user account.

Syntax

su USERNAME

Switch to Root

su -

This attempts to start a root login shell. On systems where the root account is locked or has no usable password, this may fail.

Switch to Another User

su - username

Starts a login shell for the specified user, if authentication is successful.

The hyphen in su - requests a login-style shell and loads the target user's login environment.

7. Difference Between sudo and su

Feature sudo su
Purpose Run commands as another user Switch to another user account
Authentication Usually authenticates the invoking user Usually authenticates as the target user
Command execution Can run a single elevated command Can start a shell as another user
Typical example sudo apt update su -
Permission control Controlled by sudoers policy Controlled by account authentication and system policy
sudo and su are not interchangeable. They provide different ways to obtain another user's privileges.

8. Opening a Root Login Shell with sudo

On Ubuntu, the following command commonly opens a root login shell:

sudo -i

This starts an interactive root login environment after successful sudo authentication.

Verify Root Access

whoami id
Example output:
root uid=0(root) gid=0(root) groups=0(root)

Exit the Root Shell

exit

This returns you to the previous shell.

Avoid remaining in a root shell longer than necessary. A mistaken command executed as root can damage the operating system or remove important data.

9. Understanding the sudoers File

The sudoers configuration file controls which users and groups can use sudo and which commands they can execute.

Main configuration file:

/etc/sudoers

View sudoers Configuration

sudo visudo

The visudo command opens the sudoers configuration using a safe editing process. It checks the syntax before saving changes.

Example sudoers Rule

username ALL=(ALL:ALL) ALL

Meaning:

  • username: The user receiving the rule.
  • First ALL: Applies on all hosts.
  • (ALL:ALL): Allows running as any user and group.
  • Final ALL: Allows all commands, subject to policy.

Ubuntu sudo Group

Ubuntu commonly uses the sudo group to grant administrative access.

groups getent group sudo

To add an existing user to the sudo group, an administrator can use:

sudo usermod -aG sudo username
Do not edit /etc/sudoers with an ordinary text editor. Use visudo to validate the configuration and reduce the risk of breaking sudo access.

10. Important sudo Options

Option Purpose Example
-l List permitted commands sudo -l
-i Start a login shell as the target user sudo -i
-u Run command as a specified user sudo -u username whoami
-k Invalidate cached authentication credentials sudo -k
-v Update or validate the authentication timestamp sudo -v

Run a Command as Another User

sudo -u username whoami

Runs whoami as the specified user, if the sudo policy permits it.

11. Common sudo Errors

1. User Is Not in the Sudoers File

user is not in the sudoers file

The account does not have the required sudo authorization.

2. Incorrect Password

Authentication fails when the entered password is incorrect.

3. Command Not Found

The requested command may not be installed or may not be available in the execution path.

4. Permission Denied

The command may still be restricted by filesystem permissions, security policies or other system controls.

sudo does not guarantee that every operation will succeed. The command itself must be valid and the system must permit the operation.

12. Practical Lab: Working with sudo

Objective: To practise checking sudo permissions, running administrative commands and verifying root access in Ubuntu.

Step 1: Check Current User

whoami id

Step 2: Check sudo Permissions

sudo -l

Step 3: Update Package Information

sudo apt update

Step 4: Create a Test Directory

sudo mkdir /opt/sudo_lab

Step 5: Verify the Directory

ls -ld /opt/sudo_lab
Expected observation: The directory should exist and normally be owned by root.

Step 6: Create a Test File

sudo touch /opt/sudo_lab/test.txt

Step 7: Check File Ownership

ls -l /opt/sudo_lab

Step 8: Open a Root Login Shell

sudo -i

Step 9: Verify Root Identity

whoami id
Expected observation: The username should be root and the UID should be 0.

Step 10: Exit Root Shell

exit

Step 11: Remove the Test Directory

sudo rm -r /opt/sudo_lab
This command recursively removes the test directory. Verify the path carefully before running any recursive deletion command.

13. Security Best Practices

  • Use sudo only when administrative privileges are required.
  • Prefer single-command sudo access over a permanent root shell.
  • Check command paths before executing destructive operations.
  • Never share your password with other users.
  • Use visudo when editing sudoers configuration.
  • Grant sudo access only to trusted accounts.
  • Avoid running unknown scripts with sudo.
  • Exit the root shell after completing administrative work.
The principle of least privilege means users should receive only the permissions required to perform their tasks.

14. Interview Questions and Answers

Q1. What is the root user in Linux?

Root is the superuser account with UID 0 and administrative privileges.

Q2. What is sudo?

sudo allows authorized users to execute commands with the privileges of another user.

Q3. What is the UID of root?

0.

Q4. What is the home directory of root?

/root.

Q5. Which command checks sudo permissions?

sudo -l.

Q6. What is the difference between sudo and su?

sudo runs commands with another user's privileges according to policy, while su switches to another user account.

Q7. Which command opens a root login shell on Ubuntu?

sudo -i.

Q8. What is the purpose of visudo?

It safely edits and validates the sudoers configuration.

Q9. Which group commonly grants sudo access in Ubuntu?

The sudo group.

Q10. Why should root access be used carefully?

Root commands can modify or delete critical system files and affect the entire operating system.

16. Lesson Summary

  • Root is the Linux superuser account.
  • The root account has UID 0.
  • The root home directory is /root.
  • sudo executes commands with another user's privileges.
  • sudo -l displays permitted sudo commands.
  • sudo -i opens a root login shell when permitted.
  • su switches to another user account.
  • /etc/sudoers controls sudo authorization.
  • visudo is used to safely edit sudoers.
  • Administrative privileges should be used carefully.
