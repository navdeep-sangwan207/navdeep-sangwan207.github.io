Linux Users and Groups

Understanding User Accounts, Groups and Identity Management

1. Introduction to Linux Users and Groups

Linux is a multi-user operating system. This means that multiple users can have separate accounts and access the same computer system while maintaining individual identities and permissions.

Each user can have their own files, directories, settings and access rights. Linux uses users and groups to manage system resources and control access to files.

Why Does Linux Use Users and Groups?

  • To provide separate accounts for different users.
  • To protect files and directories from unauthorized access.
  • To manage permissions efficiently.
  • To control access to system resources.
  • To support secure system administration.
Example: Suppose a Linux computer is shared by three users. Each user can have a separate home directory, personal files and individual access permissions.

2. What Is a User in Linux?

A user is an account that represents an individual or service on a Linux system. Every user account has a unique user ID (UID) used by the operating system to identify it.

A user account generally contains:

  • Username
  • User ID (UID)
  • Primary group ID (GID)
  • Home directory
  • Login shell
  • Account information and authentication configuration

Example of a Linux Username

navdeep

Here, navdeep is an example username. A username is a human-readable identity, while the operating system primarily uses the UID to identify the account.

Types of User Accounts

Account Type Description
Root User The special administrative account with UID 0.
Regular User An account generally used by a person for normal system activities.
System User An account generally used by system services and background processes.
System and regular users are distinguished by their purpose and configuration. UID ranges are distribution- and configuration-dependent; do not assume that every account with a particular UID range has the same role.

3. What Is a Group in Linux?

A group is a collection of user accounts. Groups make it easier to manage permissions for multiple users together.

Instead of assigning the same permissions separately to every user, an administrator can assign permissions to a group.

Example

Suppose a software development team contains three users:

user1 user2 user3

All three users can be members of a group named developers.

Concept: When a directory is assigned to the developers group, group permissions can provide shared access to its members.

Advantages of Groups

  • Manage permissions for multiple users together.
  • Reduce repetitive permission configuration.
  • Support collaboration between users.
  • Improve access control and administration.

4. User ID (UID)

UID stands for User Identifier. It is a numerical identity assigned to each user account.

Linux uses the UID internally to identify the user who owns a process or file.

Important UID Values

UID Meaning
0 Reserved for the root account.
Other UIDs Assigned to regular and system accounts according to system configuration.

Check the Current User ID

id -u
Example Output:
1000
This is an example UID for a regular user.

Check UID of a Specific User

id -u username

Replace username with the account name you want to check.

5. Group ID (GID)

GID stands for Group Identifier. It is a numerical identity assigned to a group in Linux.

Linux uses GIDs to identify group ownership and group membership associated with users and processes.

Check the Current User's Primary Group ID

id -g
Example Output:
1000

Check the GID of a Specific Group

getent group developers
Example Output:
developers:x:1002:user1,user2,user3
Here, 1002 is the GID of the developers group.

6. Primary and Supplementary Groups

Primary Group

Every user account has a primary group. It is the default group identity associated with the user's processes and commonly used when creating files, subject to directory settings and application behaviour.

Supplementary Groups

A user can also belong to additional groups called supplementary groups. These groups provide additional access rights.

Example

id
Example Output:
uid=1000(navdeep) gid=1000(navdeep) groups=1000(navdeep),27(sudo),1002(developers)

In this example:

  • uid=1000 represents the user's UID.
  • gid=1000 represents the primary GID.
  • 27(sudo) is a supplementary group.
  • 1002(developers) is another supplementary group.
Note: Group names and GID values shown here are examples. They can differ between Linux systems.

7. Important Linux User and Group Commands

Command Purpose
whoami Display the effective username.
id Display UID, GID and group membership information.
id -u Display the effective UID.
id -g Display the effective primary GID.
groups Display group memberships for the current user.
who Display users currently logged in.
users Display usernames of users currently logged in.
getent passwd Display user account entries from configured account databases.
getent group Display group entries from configured group databases.

8. The whoami Command

The whoami command displays the effective username associated with the current process.

Syntax

whoami

Example

whoami
Example Output:
navdeep

The output identifies the effective user for the current command environment.

9. The id Command

The id command displays the user's UID, primary GID and supplementary group information.

Syntax

id [OPTION] [USERNAME]

Example 1: Display Current User Information

id
Example Output:
uid=1000(navdeep) gid=1000(navdeep) groups=1000(navdeep),27(sudo),1002(developers)

Example 2: Display Only UID

id -u

Example 3: Display Only Primary GID

id -g

Example 4: Display Group Information

id -G

The -G option displays all group IDs associated with the user.

10. The groups Command

The groups command displays the group memberships of a user.

Syntax

groups [USERNAME]

Example 1: Display Current User Groups

groups
Example Output:
navdeep sudo developers

Example 2: Display Groups of Another User

groups username

Replace username with the account whose group membership you want to inspect.

11. The who Command

The who command displays information about users currently logged into the system, including their terminal and login time.

Syntax

who

Example

who
Example Output:
navdeep tty2 2026-11-05 09:30

The exact output depends on active login sessions and the Linux environment.

12. Important Linux User and Group Files

Linux maintains account and group information in important system configuration files.

File Purpose
/etc/passwd Stores user account information.
/etc/shadow Stores password hashes and password-aging information.
/etc/group Stores local group account information.
/etc/gshadow Stores protected group information.

1. /etc/passwd

The /etc/passwd file contains user account records. Each entry normally has seven colon-separated fields.

username:password:UID:GID:GECOS:home_directory:login_shell

Example Entry

navdeep:x:1000:1000:Navdeep:/home/navdeep:/bin/bash
Field Meaning
navdeep Username
x Password information is stored separately, commonly in /etc/shadow.
1000 User ID (UID)
1000 Primary Group ID (GID)
Navdeep GECOS or descriptive account information
/home/navdeep Home directory
/bin/bash Login shell

2. /etc/shadow

The /etc/shadow file stores password hashes and password-aging information. Access to its contents is restricted because it contains sensitive authentication data.

3. /etc/group

The /etc/group file stores local group information. Each entry contains four colon-separated fields.

group_name:password:GID:user_list

Example Entry

developers:x:1002:user1,user2,user3

Here, developers is the group name, 1002 is its GID and the final field lists supplementary members.

4. /etc/gshadow

The /etc/gshadow file stores protected group information, including group password-related data and administrative membership information.

Security Warning: Do not manually modify account and authentication files unless you understand their format and the consequences. Use appropriate user and group administration commands.

14. Common Errors and Precautions

1. Unknown User

If a username does not exist, commands such as id username may report that the user cannot be found.

2. Unknown Group

If a group name is incorrect or does not exist, getent group groupname may return no result.

3. Permission Denied

Some account information files have restricted access. Use supported commands such as id and getent instead of trying to read protected files directly.

4. UID and GID Are Different

A UID identifies a user account, whereas a GID identifies a group. They are separate numerical identifiers.

Practical Tip: Run id regularly while learning Linux permissions. It helps you understand how the current user and group identities relate to file access.

15. Interview Questions and Answers

Q1. What is a multi-user operating system?

A multi-user operating system allows multiple users to use the same computer system through separate accounts and access permissions.

Q2. What is a user in Linux?

A user is an account representing an individual or service on a Linux system.

Q3. What is a group in Linux?

A group is a collection of user accounts used to manage permissions for multiple users.

Q4. What is UID?

UID stands for User Identifier. It is a numerical identifier assigned to a user account.

Q5. What is GID?

GID stands for Group Identifier. It is a numerical identifier assigned to a group.

Q6. What is the UID of the root user?

The root account has UID 0.

Q7. What is a primary group?

It is the default group associated with a user account.

Q8. What is a supplementary group?

It is an additional group membership that provides the user with extra group-based access.

The whoami command.

The /etc/group file.

The id command.
