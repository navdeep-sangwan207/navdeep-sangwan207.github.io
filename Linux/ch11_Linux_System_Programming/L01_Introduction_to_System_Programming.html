Introduction to System Programming

Understand system-level software development, Linux architecture, kernel interfaces, system calls and the role of system programmers.

1. What Is System Programming?

System programming is the development of software that interacts closely with the operating system and provides services required by application programs.

A system programmer works with operating system interfaces, processes, memory, files, devices, communication mechanisms and other low-level resources.

Definition: System programming is the process of developing software that manages or accesses operating system resources through system calls, libraries and other system interfaces.

Examples of System Programs

  • Shells such as Bash.
  • File management utilities.
  • Process monitoring tools.
  • Device drivers.
  • System services and daemons.
  • Networking utilities.
  • System libraries.
  • Operating system components.

2. Application Programming vs System Programming

Application programming focuses on developing software for end users, whereas system programming focuses on operating system services and low-level resource management.

Application Programming System Programming
Develops user-oriented applications. Develops system-level software.
Uses high-level APIs and frameworks. Uses system calls and low-level APIs.
Examples: text editors, browsers and games. Examples: shells, utilities and system services.
Usually focuses on application features. Focuses on operating system resources.
May use languages such as JavaScript, Java and Python. Commonly uses C, C++ and assembly language.

3. Linux System Architecture

Linux uses a layered architecture. Applications execute in user space and request privileged operating system services through controlled interfaces.

Main Components

  1. User Applications: Programs such as browsers, editors and command-line tools.
  2. System Libraries: Libraries such as glibc that provide functions and interfaces used by application programs.
  3. System Call Interface: The interface through which user-space programs request services from the Linux kernel.
  4. Linux Kernel: The core of the operating system. It manages processes, memory, devices, filesystems and networking.
  5. Hardware: CPU, RAM, storage devices, network interfaces and peripherals.

Important: The Linux kernel operates in kernel mode, while normal applications execute in user mode. The system call mechanism provides controlled access to kernel services.

4. User Space and Kernel Space

User Space

User space is the memory area in which normal applications execute. An application generally cannot directly access protected kernel memory or execute privileged CPU operations.

Examples:

  • Bash shell.
  • Text editors.
  • Web browsers.
  • Programs written in C or C++.

Kernel Space

Kernel space is the protected memory area used by the Linux kernel. It contains operating system code and data structures that manage system resources.

Examples:

  • Process scheduler.
  • Memory management subsystem.
  • Filesystem implementations.
  • Device drivers.
  • Network stack.
User Space Kernel Space
Runs application programs. Runs kernel code.
Restricted hardware access. Privileged hardware access.
Limited permissions. Access to protected kernel resources.
Application failures are generally isolated. Kernel failures can affect the entire system.

5. What Is the Linux Kernel?

The Linux kernel is the central component of the Linux operating system. It acts as an interface between software and hardware.

Major Responsibilities

  • Process Management: Creates, schedules and terminates processes.
  • Memory Management: Manages physical memory and virtual address spaces.
  • Device Management: Communicates with hardware through device drivers.
  • Filesystem Management: Provides access to files and directories.
  • Networking: Implements networking protocols and socket interfaces.
  • Security: Enforces permissions and access controls.

6. What Is a System Call?

A system call is a controlled interface through which a user-space program requests a service from the operating system kernel.

For example, when a program needs to read a file, it can use the read() system call to request data from the kernel.

Common Linux System Calls

System Call Purpose
open() Opens a file and returns a file descriptor.
read() Reads data from a file descriptor.
write() Writes data to a file descriptor.
close() Closes a file descriptor.
fork() Creates a new process.
execve() Replaces the current process image with a new program.
waitpid() Waits for a specified child process.
getpid() Returns the calling process ID.
Remember: A library function and a system call are not necessarily the same thing. For example, printf() is a C library function. It commonly uses the write() system call internally when output is flushed.

7. System Calls, APIs and Library Functions

System Call

A kernel interface used to request operating system services. Examples include read(), write() and fork().

API (Application Programming Interface)

An API is a set of functions, definitions and rules that software uses to interact with another software component.

Library Function

A reusable function provided by a software library. Examples include printf(), strlen() and fopen().

Function Category
printf() C standard library function
strlen() C standard library function
fopen() C standard I/O library function
open() POSIX interface commonly implemented using a Linux system call
fork() POSIX process-creation interface implemented using a Linux system call

8. Why Is C Commonly Used for System Programming?

C is widely used for Linux system programming because it provides low-level memory access, efficient execution and direct access to operating system interfaces.

Advantages of C

  • Efficient execution.
  • Pointers and direct memory manipulation.
  • Bitwise operations.
  • Structures and unions.
  • Access to POSIX and Linux APIs.
  • Suitable for system utilities and low-level components.
  • Widely used in kernel and embedded development.
Career connection: Linux system programming is useful for embedded Linux, firmware, device-driver development, operating systems, networking software and systems software engineering.

9. Introduction to File Descriptors

A file descriptor (FD) is a non-negative integer used by a process to identify an open file or another I/O resource.

Linux represents many I/O resources through file descriptors, including regular files, terminals, pipes and sockets.

Standard File Descriptors

Descriptor Name Purpose
0 stdin Standard input
1 stdout Standard output
2 stderr Standard error

These standard descriptors are normally opened automatically for a process. 

0  → Standard Input  (stdin)
1  → Standard Output (stdout)
2  → Standard Error  (stderr)

10. Practical: First Linux System Programming Program

In this practical, we will write a C program that uses the write() system call to display a message.

Program: Using write()

#include <unistd.h>

int main(void)
{
    const char message[] =
        "Hello from Linux System Programming!\n";

    write(1, message, sizeof(message) - 1);

    return 0;
}

Explanation

  • #include <unistd.h> declares the POSIX write() interface.
  • main() is the entry point of the program.
  • message stores the text to display.
  • write() sends bytes to a file descriptor.
  • 1 represents standard output.
  • sizeof(message) - 1 excludes the terminating null character.

Compile the Program

gcc system_programming.c -o system_programming

Run the Program

./system_programming

Expected Output

Hello from Linux System Programming!
Programming note: For robust programs, check the return value of write(). It may write fewer bytes than requested or fail. This introductory example demonstrates the interface without implementing full error handling.

13. Interview Questions and Answers

Q1. What is system programming?

System programming is the development of software that interacts with operating system services and manages system resources.

Q2. What is the Linux kernel?

The Linux kernel is the core of the operating system. It manages processes, memory, devices, filesystems and networking.

Q3. What is a system call?

A system call is a controlled interface through which a user-space program requests a service from the kernel.

Q4. What is the difference between user space and kernel space?

User space is where normal applications execute with restricted privileges. Kernel space is where the operating system kernel executes with privileged access.

Q5. What is a file descriptor?

A file descriptor is a non-negative integer used by a process to identify an open file or I/O resource.

Q6. What are the three standard file descriptors?

0 represents standard input, 1 represents standard output and 2 represents standard error.

Q7. Is printf() a system call?

No. printf() is a C standard library function. It commonly uses the write() system call when buffered output is flushed.

Q8. Why is C used in system programming?

C provides efficient execution, pointers, memory manipulation, bitwise operations and access to low-level operating system interfaces.

Q9. What is the purpose of unistd.h?

It is a POSIX header that declares interfaces such as read(), write(), close() and fork().

Q10. What is the difference between an API and a system call?

An API is a programming interface offered by a software component. A system call is a specific interface for requesting kernel services.
