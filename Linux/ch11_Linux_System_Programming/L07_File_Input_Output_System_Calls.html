File Input Output System Calls

Understand low-level file input and output operations, file descriptors, Linux I/O system calls and error handling.

1. Introduction to File I/O

File Input/Output (I/O) refers to reading data from files and writing data into files.

Linux provides system calls that allow programs to interact with files and other I/O objects such as terminals, pipes and devices.

Definition: File I/O system calls are low-level operating-system interfaces used by programs to perform operations such as opening, reading, writing and closing files.

Common File I/O Operations

  • Open an existing file.
  • Create a new file.
  • Read data from a file.
  • Write data into a file.
  • Close an opened file.
  • Change the current file offset.
  • Retrieve file information.

2. Low-Level I/O vs High-Level I/O

Linux programming commonly uses two approaches for file operations.

Low-Level I/O High-Level I/O
Uses system-call interfaces. Uses C standard library functions.
Uses file descriptors. Uses FILE pointers.
Examples: open(), read(), write(), close(). Examples: fopen(), fread(), fwrite(), fclose().
Does not provide a C stdio stream buffer. Normally uses C standard I/O buffering.
Common in system programming. Common in application-level C programming.
Remember: Low-level file I/O works with file descriptors, while C standard I/O works with FILE pointers.

3. What Is a File Descriptor?

A file descriptor (FD) is a non-negative integer used by a process to identify an open file or another I/O resource.

When a process opens a file successfully, Linux returns a file descriptor that can be used for subsequent I/O operations.

Standard File Descriptors

File Descriptor Name Purpose
0 Standard Input (stdin) Reads input, usually from the keyboard.
1 Standard Output (stdout) Displays normal output, usually on the terminal.
2 Standard Error (stderr) Displays error messages, usually on the terminal.

Conceptual Diagram

          Linux Process
                |
        File Descriptor Table
                |
        +-------+-------+
        |       |       |
        v       v       v
       FD 0    FD 1    FD 2
        |       |       |
        v       v       v
      Input   Output   Error
                |
          FD 3, FD 4 ...
                |
          Opened Files

Newly opened files commonly receive descriptor numbers starting from 3, assuming the standard descriptors are already open. The actual number depends on the lowest available descriptor.

4. Header Files for File I/O

The following headers are commonly used for low-level Linux file operations.

Header Purpose
<unistd.h> Declares read(), write(), close() and other POSIX interfaces.
<fcntl.h> Declares open() and file access flags.
<sys/types.h> Defines types such as ssize_t and off_t.
<sys/stat.h> Defines file permission and status information.
<errno.h> Provides error-number information.
<stdio.h> Provides perror() and other standard I/O functions.

5. open() System Call

The open() function opens a file and returns a file descriptor. It can also create a file when the appropriate creation flag is supplied.

Header File

#include <fcntl.h>
#include <sys/types.h>
#include <sys/stat.h>

Syntax

int open(const char *pathname, int flags, ...);

The third argument, called mode, is required when O_CREAT is used.

Common Flags

Flag Purpose
O_RDONLY Open for reading only.
O_WRONLY Open for writing only.
O_RDWR Open for reading and writing.
O_CREAT Create the file if it does not exist.
O_TRUNC Truncate an existing regular file to zero length when opened for writing.
O_APPEND Append writes at the end of the file.
O_EXCL With O_CREAT, fail if the file already exists.

Example

int fd;

fd = open("sample.txt", O_RDONLY);

If successful, open() returns a file descriptor. If it fails, it returns -1.

6. File Permission Modes

When creating a file using O_CREAT, the mode argument specifies its requested permission bits.

Example

int fd;

fd = open(
    "sample.txt",
    O_WRONLY | O_CREAT,
    0644
);

Understanding 0644

Permission Octal Value Meaning
Owner 6 Read + Write
Group 4 Read only
Others 4 Read only
Important: The final permissions are affected by the process's umask. For example, mode 0644 with umask 0022 normally produces permissions 0644.

7. read() System Call

The read() function reads data from an open file descriptor into a memory buffer.

Header File

#include <unistd.h>

Syntax

ssize_t read(
    int fd,
    void *buffer,
    size_t count
);

Parameters

  • fd: File descriptor.
  • buffer: Memory area for received data.
  • count: Maximum number of bytes to read.

Return Values

Return Value Meaning
Positive value Number of bytes actually read.
0 End of file (EOF) for a regular file.
-1 Error occurred.
Important: read() may return fewer bytes than requested. A successful read does not guarantee that the entire requested buffer has been filled.

8. write() System Call

The write() function writes data from a memory buffer to an open file descriptor.

Syntax

ssize_t write(
    int fd,
    const void *buffer,
    size_t count
);

Parameters

  • fd: File descriptor.
  • buffer: Address of the data to write.
  • count: Number of bytes requested.

Return Values

  • Positive value: Number of bytes actually written.
  • 0: No bytes written.
  • -1: Error occurred.
Important: write() may write fewer bytes than requested. Programs that must write all data should handle partial writes.

9. close() System Call

The close() function releases an open file descriptor.

Header File

#include <unistd.h>

Syntax

int close(int fd);

Return Values

  • 0: Successful close.
  • -1: Error occurred.

Closing a file descriptor allows the process to reuse that descriptor number for another open file.

10. Complete File I/O Workflow

        Start Program
              |
              v
          open()
              |
        Get File Descriptor
              |
              v
       read() / write()
              |
              v
           close()
              |
              v
       Continue Program
              |
              v
            End

A typical low-level file operation opens a file, performs the required I/O and closes the descriptor when it is no longer needed.

11. Practical Program: Create and Write a File

This program creates a file named output.txt and writes a message into it.

Program

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    const char message[] = "Welcome to Linux System Programming\n";
    ssize_t bytes_written;

    fd = open(
        "output.txt",
        O_WRONLY | O_CREAT | O_TRUNC,
        0644
    );

    if (fd == -1)
    {
        perror("open");
        return 1;
    }

    bytes_written = write(
        fd,
        message,
        sizeof(message) - 1
    );

    if (bytes_written == -1)
    {
        perror("write");
        close(fd);
        return 1;
    }

    printf("Bytes written: %zd\n", bytes_written);

    if (close(fd) == -1)
    {
        perror("close");
        return 1;
    }

    printf("File operation completed\n");

    return 0;
}

Compile

gcc file_write.c -o file_write

Execute

./file_write

Possible Output

Bytes written: 36
File operation completed

Verify the File

cat output.txt

Expected File Content

Welcome to Linux System Programming

The program checks for an error from each main I/O operation. For production code, it should also handle partial writes by writing the remaining bytes.

12. Practical Program: Read Data from a File

This program opens an existing file and reads its content into a character buffer.

Program

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    char buffer[100];
    ssize_t bytes_read;

    fd = open("output.txt", O_RDONLY);

    if (fd == -1)
    {
        perror("open");
        return 1;
    }

    bytes_read = read(fd, buffer, sizeof(buffer) - 1);

    if (bytes_read == -1)
    {
        perror("read");
        close(fd);
        return 1;
    }

    buffer[bytes_read] = '\0';

    printf("File Content:\n%s", buffer);

    if (close(fd) == -1)
    {
        perror("close");
        return 1;
    }

    return 0;
}

Compile

gcc file_read.c -o file_read

Execute

./file_read

Expected Output

File Content:
Welcome to Linux System Programming

This example reads at most 99 bytes in one call. Larger files require a loop to read repeatedly until EOF or an error occurs.

13. Practical Program: Copy a File

This program copies data from one file to another using low-level read() and write() calls.

Program

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int source_fd;
    int destination_fd;

    char buffer[1024];
    ssize_t bytes_read;
    ssize_t bytes_written;
    ssize_t total_written;
    ssize_t i;

    source_fd = open("source.txt", O_RDONLY);

    if (source_fd == -1)
    {
        perror("source open");
        return 1;
    }

    destination_fd = open(
        "destination.txt",
        O_WRONLY | O_CREAT | O_TRUNC,
        0644
    );

    if (destination_fd == -1)
    {
        perror("destination open");
        close(source_fd);
        return 1;
    }

    while ((bytes_read = read(
                source_fd,
                buffer,
                sizeof(buffer))) > 0)
    {
        total_written = 0;

        while (total_written < bytes_read)
        {
            bytes_written = write(
                destination_fd,
                buffer + total_written,
                bytes_read - total_written
            );

            if (bytes_written == -1)
            {
                perror("write");
                close(source_fd);
                close(destination_fd);
                return 1;
            }

            if (bytes_written == 0)
            {
                fprintf(stderr, "No progress while writing\n");
                close(source_fd);
                close(destination_fd);
                return 1;
            }

            total_written += bytes_written;
        }
    }

    if (bytes_read == -1)
    {
        perror("read");
        close(source_fd);
        close(destination_fd);
        return 1;
    }

    if (close(source_fd) == -1)
    {
        perror("source close");
        close(destination_fd);
        return 1;
    }

    if (close(destination_fd) == -1)
    {
        perror("destination close");
        return 1;
    }

    printf("File copied successfully\n");

    return 0;
}

Compile

gcc file_copy.c -o file_copy

Create a Source File

echo "Learning Linux file I/O" > source.txt

Execute

./file_copy

Verify

cat destination.txt

Expected Output

File copied successfully
Learning Linux file I/O

The program handles partial writes and repeatedly reads until EOF. It is an introductory example; production utilities should also consider interrupted system calls, metadata preservation and special files.

14. Error Handling in File I/O

File operations can fail for several reasons. Programs should check return values and handle errors.

Error Possible Reason
ENOENT File or directory does not exist.
EACCES Insufficient permissions.
EMFILE Process has reached its file descriptor limit.
ENOSPC No space left on the device.
EBADF Invalid file descriptor.
EINTR Operation was interrupted by a signal.

Using perror()

if (fd == -1)
{
    perror("open");
}

perror() displays a descriptive message associated with the current errno value.

15. File Offset and lseek()

Linux maintains a current file offset for an open file description. The lseek() function changes that offset for seekable files.

Syntax

off_t lseek(
    int fd,
    off_t offset,
    int whence
);

Common whence Values

Value Purpose
SEEK_SET Offset is measured from the beginning of the file.
SEEK_CUR Offset is measured from the current position.
SEEK_END Offset is measured from the end of the file.

Example

off_t position;

position = lseek(fd, 0, SEEK_END);

This moves the file offset to the end of a seekable file. Pipes, FIFOs and sockets do not support ordinary seeking.

16. File I/O vs Standard I/O Functions

System Call Interface C Standard I/O Function
open() fopen()
read() fread()
write() fwrite()
close() fclose()
lseek() fseek()
Important: Do not casually mix low-level read()/write() calls with buffered stdio operations on the same underlying file. Buffering can cause unexpected ordering and file-position behaviour.

18. Interview Questions and Answers

Q1. What is a file descriptor?

A file descriptor is a non-negative integer used by a process to identify an open file or I/O resource.

Q2. What are the standard file descriptors?

0 is standard input, 1 is standard output and 2 is standard error.

Q3. Which function opens a file?

open().

Q4. What does read() return?

It returns the number of bytes read, zero at EOF for a regular file, or -1 on error.

Q5. What does write() return?

It returns the number of bytes actually written or -1 on error.

Q6. What is the purpose of close()?

It releases an open file descriptor.

Q7. What is O_CREAT?

It requests creation of a file if it does not exist.

Q8. What is O_APPEND?

It causes writes to be directed to the end of the file.

Q9. What is the difference between read() and fread()?

read() operates on a file descriptor, while fread() operates on a C standard I/O stream.

Q10. What is lseek()?

It changes the current file offset for a seekable open file description.
