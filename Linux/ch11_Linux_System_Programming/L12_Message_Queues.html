Message Queues

Understand interprocess communication using kernel-managed message queues in Linux.

1. Introduction to Message Queues

A message queue is an Interprocess Communication (IPC) mechanism that allows processes to exchange data in the form of messages.

Messages are stored in a queue maintained by the operating system. A sender places a message into the queue, and a receiver retrieves it.

Definition: A message queue is a kernel-managed IPC mechanism that allows processes to send and receive structured messages asynchronously.

Basic Architecture

       Process A                 Process B
      (Sender)                  (Receiver)
          |                         ^
          |                         |
          | msgsnd()                | msgrcv()
          v                         |
       +--------------------------------+
       |        MESSAGE QUEUE           |
       |                                |
       |  +--------------------------+  |
       |  | Message 1                |  |
       |  +--------------------------+  |
       |  | Message 2                |  |
       |  +--------------------------+  |
       |  | Message 3                |  |
       |  +--------------------------+  |
       +--------------------------------+
                  Kernel

2. Why Message Queues Are Used

  • Communication between independent processes.
  • Transfer of structured data.
  • Asynchronous message exchange.
  • Communication without sharing a common address space.
  • Prioritization or selection of messages by type in System V queues.

Applications

  • Embedded Linux applications.
  • Industrial monitoring systems.
  • Background processing systems.
  • Client-server applications.
  • Task communication between independent processes.

3. Types of Message Queues

Linux supports different message-queue interfaces. Two important interfaces are:

System V Message Queues POSIX Message Queues
Uses System V IPC functions. Uses POSIX message queue functions.
msgget() mq_open()
msgsnd() mq_send()
msgrcv() mq_receive()
msgctl() mq_close(), mq_unlink()

This lesson focuses primarily on System V message queues.

4. System V Message Queue Functions

Header Files

#include <sys/ipc.h>
#include <sys/msg.h>

Important Functions

Function Purpose
msgget() Creates or accesses a message queue.
msgsnd() Sends a message to the queue.
msgrcv() Receives a message from the queue.
msgctl() Controls or removes a message queue.

5. Message Structure

System V message queues use a message structure containing a message type and message data.

Example Structure

struct message
{
    long msg_type;
    char msg_text[100];
};

The first member must be a positive long integer representing the message type. The remaining members contain the message data.

The System V API expects the message type as the first member. The msgsz argument of msgsnd() and msgrcv() specifies the size of the message data after msg_type, not the size of the entire structure.

6. msgget() Function

The msgget() function creates a new message queue or accesses an existing queue.

Syntax

int msgget(key_t key, int msgflg);

Parameters

  • key: Identifies the message queue.
  • msgflg: Specifies creation flags and permissions.

Common Flags

Flag Purpose
IPC_CREAT Creates the queue if it does not exist.
IPC_EXCL With IPC_CREAT, fails if the queue already exists.
0666 Requests read/write permissions for owner, group and others, subject to umask and system permissions.

Example

int msgid;

msgid = msgget(1234, IPC_CREAT | 0666);

if (msgid == -1)
{
    perror("msgget");
}

On success, msgget() returns a message queue identifier. On failure, it returns -1.

7. msgsnd() Function

The msgsnd() function sends a message to a System V message queue.

Syntax

int msgsnd(int msqid,
           const void *msgp,
           size_t msgsz,
           int msgflg);

Parameters

  • msqid: Message queue identifier.
  • msgp: Pointer to the message structure.
  • msgsz: Size of message data excluding msg_type.
  • msgflg: Flags controlling send behaviour.

Common Flag

IPC_NOWAIT makes the send operation nonblocking if the queue does not have enough space.

Example

struct message
{
    long msg_type;
    char msg_text[100];
};

struct message msg;

msg.msg_type = 1;

strcpy(msg.msg_text, "Hello Receiver");

if (msgsnd(msgid, &msg,
           strlen(msg.msg_text) + 1, 0) == -1)
{
    perror("msgsnd");
}

If the queue is full, a blocking msgsnd() normally waits until sufficient space becomes available.

8. msgrcv() Function

The msgrcv() function receives a message from a System V message queue.

Syntax

ssize_t msgrcv(int msqid,
               void *msgp,
               size_t msgsz,
               long msgtyp,
               int msgflg);

Parameters

  • msqid: Message queue identifier.
  • msgp: Address of the receiving message structure.
  • msgsz: Maximum message data size excluding msg_type.
  • msgtyp: Selects the message type.
  • msgflg: Controls receiving behaviour.

Message Type Selection

msgtyp Meaning
0 Receives the first message in the queue.
Positive value Receives the first message having that exact type.
Negative value Receives the message with the lowest type not greater than the absolute value, if one exists.

Common Flags

  • IPC_NOWAIT: Returns immediately if no matching message is available.
  • MSG_NOERROR: Truncates a message if it is larger than the supplied buffer.

Example

struct message msg;

if (msgrcv(msgid, &msg, sizeof(msg.msg_text),
            1, 0) == -1)
{
    perror("msgrcv");
}
else
{
    printf("Received: %s\n", msg.msg_text);
}

9. msgctl() Function

The msgctl() function performs control operations on a System V message queue.

Syntax

int msgctl(int msqid, int cmd, struct msqid_ds *buf);

Common Commands

Command Purpose
IPC_STAT Retrieves queue information.
IPC_SET Changes certain queue attributes.
IPC_RMID Removes the message queue.

Example: Remove Queue

if (msgctl(msgid, IPC_RMID, NULL) == -1)
{
    perror("msgctl");
}
Remove a queue only when it is no longer needed. Removing a queue discards messages that are still stored in it and affects processes using that queue.

10. Practical Program: Message Queue Sender

This program creates a message queue and sends a message into it.

Program: message_sender.c

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/ipc.h>
#include <sys/msg.h>

struct message
{
    long msg_type;
    char msg_text[100];
};

int main(void)
{
    int msgid;
    struct message msg;

    msgid = msgget(1234, IPC_CREAT | 0666);

    if (msgid == -1)
    {
        perror("msgget");
        return 1;
    }

    msg.msg_type = 1;

    strcpy(msg.msg_text, "Hello from Sender Process");

    if (msgsnd(msgid, &msg,
               strlen(msg.msg_text) + 1, 0) == -1)
    {
        perror("msgsnd");
        return 1;
    }

    printf("Message sent successfully\n");

    return 0;
}

Compile

gcc message_sender.c -o sender

11. Practical Program: Message Queue Receiver

This program accesses the same message queue and receives a message of type 1.

Program: message_receiver.c

#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/msg.h>

struct message
{
    long msg_type;
    char msg_text[100];
};

int main(void)
{
    int msgid;
    struct message msg;
    ssize_t received;

    msgid = msgget(1234, IPC_CREAT | 0666);

    if (msgid == -1)
    {
        perror("msgget");
        return 1;
    }

    received = msgrcv(msgid, &msg,
                      sizeof(msg.msg_text),
                      1, 0);

    if (received == -1)
    {
        perror("msgrcv");
        return 1;
    }

    printf("Received Message: %s\n", msg.msg_text);

    return 0;
}

Compile

gcc message_receiver.c -o receiver

Execution Steps

  1. Open Terminal 1 and run ./receiver.
  2. The receiver waits for a message of type 1.
  3. Open Terminal 2 and run ./sender.
  4. The receiver displays the received message.

Expected Output

Terminal 1:

Received Message: Hello from Sender Process

Terminal 2:

Message sent successfully

The receiver consumes the message from the queue. It is no longer available for another receive operation.

The programs use a fixed key (1234) for learning. If an old queue with this key exists, it may contain stale messages. Inspect it with ipcs -q and remove only the intended test queue before repeating the lab.

12. Message Types and Priority

System V message queues support message selection using the msg_type field.

Example Messages

Message 1: Type = 1
Message 2: Type = 2
Message 3: Type = 3

A receiver can request a particular message type. This allows processes to separate different categories of messages within the same queue.

Message types can be used to implement priority-like selection, but they are not a complete priority scheduling system.

13. Blocking and Nonblocking Operations

Operation Default Behaviour With IPC_NOWAIT
msgsnd() Waits if queue is full. Returns immediately if there is insufficient space.
msgrcv() Waits if no matching message is available. Returns immediately if no matching message is available.

When a nonblocking operation cannot proceed, the call generally fails with errno set to ENOMSG for receive or EAGAIN for send.

14. Useful Linux Commands

List Message Queues

ipcs -q

Display Detailed Queue Information

ipcs -q -i MSGID

Remove a Message Queue

ipcrm -q MSGID

Replace MSGID with the actual message queue identifier. Do not remove queues that are being used by other applications.

15. Message Queue vs Pipe vs Shared Memory

Feature Pipe Shared Memory Message Queue
Data model Byte stream Common memory Separate messages
Message boundaries Not preserved Application-defined Preserved
Synchronization Blocking and EOF behaviour Usually needs separate synchronization Queue operations provide message coordination
Data access read()/write() Direct memory access after mapping Send/receive functions
Typical use Stream transfer Large shared data Structured message exchange

16. Common Errors

Error Meaning Possible Cause
EACCES Permission denied Insufficient permissions.
EEXIST Object already exists IPC_CREAT and IPC_EXCL used with an existing key.
ENOENT Object not found Queue does not exist and IPC_CREAT was not used.
ENOMSG No message available Nonblocking receive has no matching message.
EAGAIN Operation would block Nonblocking send cannot proceed because the queue is full.
E2BIG Message too large Message exceeds the receive buffer and MSG_NOERROR was not used.
EINVAL Invalid argument Invalid queue ID, size or parameter.

18. Interview Questions and Answers

Q1. What is a message queue?

A message queue is an IPC mechanism that stores messages in a kernel-managed queue for communication between processes.

Q2. Which function creates a System V message queue?

msgget().

Q3. Which function sends a message?

msgsnd().

Q4. Which function receives a message?

msgrcv().

Q5. Which function removes a message queue?

msgctl() with IPC_RMID.

Q6. What is msg_type?

It is a positive long integer used to identify and select message types.

Q7. Does a message queue preserve message boundaries?

Yes. Each send operation creates a distinct message, and receive operations retrieve messages.

Q8. What is IPC_NOWAIT?

It is a flag that makes a send or receive operation nonblocking when it cannot proceed immediately.

Q9. What is the difference between a pipe and a message queue?

A pipe transfers a byte stream without preserving application message boundaries. A message queue stores and retrieves separate messages.

Q10. Can unrelated processes communicate using message queues?

Yes. Processes can access the same queue using a shared key and appropriate permissions.

Q11. What does msgrcv() return?

It returns the number of message-data bytes received, excluding the message type, or -1 on failure.

Q12. Which command lists System V message queues?

ipcs -q.

20. Lesson Summary

  • Message queues are kernel-managed IPC mechanisms.
  • They allow processes to exchange structured messages.
  • System V message queues use msgget(), msgsnd(), msgrcv() and msgctl().
  • Every System V message has a positive message type.
  • Message boundaries are preserved.
  • IPC_NOWAIT enables nonblocking operations.
  • IPC_RMID removes a message queue.
  • ipcs -q displays System V message queues.
  • POSIX message queues use mq_open(), mq_send() and mq_receive().
