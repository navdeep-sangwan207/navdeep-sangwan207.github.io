exec() Family

Understand how Linux replaces a process image with another program using the exec() family of functions.

1. Introduction to exec()

The exec() family consists of functions that replace the current process image with a new program.

These functions are commonly used after fork(). A parent process creates a child using fork(), and the child uses an exec function to execute another program.

Definition: The exec() family replaces the calling process's program image with a new program. It does not create a new process.

Important Characteristics

  • Loads a new program into the current process.
  • Replaces the existing program code, data and stack.
  • Maintains the process ID.
  • Does not return on success.
  • Returns -1 on failure and sets errno.

2. Why Do We Need exec()?

A process may need to execute a different program without creating another independent process itself.

Common Uses

  • Executing Linux commands from C programs.
  • Implementing command-line shells.
  • Running external programs in child processes.
  • Building process-management applications.
  • Developing system utilities.
  • Executing scripts and other supported programs.
Example: A shell may create a child process using fork(). The child then executes a command such as ls using an exec function.

3. How Does exec() Work?

When an exec function succeeds, the operating system replaces the current process image with the requested program.

Execution Flow

        Parent Process
              |
              |
            fork()
              |
       +------+------+
       |             |
       v             v
     Parent        Child
       |             |
       |           exec()
       |             |
       |             v
       |       New Program
       |             |
       |          Executes
       |             |
       +-------------+
              |
        Same Process ID
        for Child Program

The parent and child are separate processes after fork(). The child replaces its program image through exec().

4. Different Functions in the exec() Family

The exec family provides several functions with different ways of specifying program paths and command-line arguments.

Function Purpose
execl() Uses a list of command-line arguments.
execv() Uses an array of command-line arguments.
execle() Uses a list of arguments and a specified environment.
execve() Uses argument and environment arrays.
execlp() Uses a list of arguments and searches PATH.
execvp() Uses an argument array and searches PATH.
execvpe() Uses argument and environment arrays and searches PATH; a GNU extension.
Remember the naming convention:
  • l: Arguments are supplied as a list.
  • v: Arguments are supplied as an array (vector).
  • p: Searches the PATH environment variable.
  • e: Uses an explicitly supplied environment.

5. execl() Function

execl() executes a program using a list of command-line arguments.

Syntax

int execl(
    const char *path,
    const char *arg,
    ...,
    (char *) NULL
);

Example

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    printf("Before execl()\n");

    execl("/bin/ls", "ls", "-l", (char *)NULL);

    perror("execl");

    return 1;
}

Explanation

  • /bin/ls is the executable path.
  • ls is the new program's argv[0].
  • -l is an argument passed to the program.
  • (char *)NULL terminates the argument list.

Possible Output

Before execl()
total  ...
-rwxr-xr-x ...
...

The directory listing depends on the current working directory. If execl() succeeds, the perror() and return statements are not executed.

6. execv() Function

execv() executes a program using an array of command-line argument strings.

Syntax

int execv(
    const char *path,
    char *const argv[]
);

Example

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    char *args[] = {
        "ls",
        "-l",
        "-a",
        NULL
    };

    printf("Executing ls command\n");

    execv("/bin/ls", args);

    perror("execv");

    return 1;
}

Explanation

  • args is an array of argument strings.
  • The first element represents argv[0].
  • The final element must be NULL.
  • /bin/ls specifies the executable path.

7. execlp() Function

execlp() executes a program using a list of arguments and searches for the executable using the PATH environment variable when the filename does not contain a slash.

Syntax

int execlp(
    const char *file,
    const char *arg,
    ...,
    (char *) NULL
);

Example

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    printf("Executing command using execlp()\n");

    execlp("ls", "ls", "-l", (char *)NULL);

    perror("execlp");

    return 1;
}

Explanation

  • ls is the executable name.
  • execlp() searches PATH for the executable.
  • -l is passed as an argument.
  • The argument list ends with NULL.
Difference: execl() requires a specified path. execlp() can search PATH when given a command name.

8. execvp() Function

execvp() executes a program using an argument array and searches the PATH environment variable.

Syntax

int execvp(
    const char *file,
    char *const argv[]
);

Example

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    char *args[] = {
        "pwd",
        NULL
    };

    execvp("pwd", args);

    perror("execvp");

    return 1;
}

Explanation

  • pwd is the executable name.
  • args contains the argument array.
  • NULL terminates the array.
  • PATH is searched for the executable.

9. execve() Function

execve() is the Linux system call interface for executing a new program image. It accepts an executable path, an argument array and an environment array.

Syntax

int execve(
    const char *pathname,
    char *const argv[],
    char *const envp[]
);

Example

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    char *args[] = {
        "ls",
        "-l",
        NULL
    };

    char *env[] = {
        "MY_VARIABLE=Linux",
        NULL
    };

    execve("/bin/ls", args, env);

    perror("execve");

    return 1;
}

Explanation

  • /bin/ls is the executable path.
  • args contains command-line arguments.
  • env provides the new program's environment.
  • The environment array must end with NULL.
Important: The example supplies only MY_VARIABLE in the new environment. It does not automatically inherit the parent's complete environment. The program also receives its argument array separately from its environment.

10. Difference Between exec() Functions

Function Argument Format PATH Search Custom Environment
execl() List No No
execv() Array No No
execle() List No Yes
execve() Array No Yes
execlp() List Yes No
execvp() Array Yes No
execvpe() Array Yes Yes

The execve() interface is the underlying system call on Linux. The other commonly used exec functions are library interfaces built around it.

11. Important Behaviour of exec()

1. Process ID Remains the Same

When exec() succeeds, the process ID does not change. The existing process executes a new program image.

2. Code and Data Are Replaced

The previous program's memory image is replaced with the new executable program image.

3. exec() Does Not Return on Success

Execution does not continue at the statement following exec() when the operation succeeds.

4. Error Handling

If exec() fails, it returns -1 and sets errno. The original program continues executing after the failed call.

5. File Descriptors

Open file descriptors generally remain open across exec(). However, descriptors marked with the close-on-exec flag are closed during a successful exec operation.

12. Practical: Using fork() and exec() Together

This is a common Linux programming pattern. The parent creates a child process, and the child executes another program using execlp().

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void)
{
    pid_t pid;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child: Executing ls command\n");
        fflush(stdout);

        execlp("ls", "ls", "-l", (char *)NULL);

        perror("execlp");
        _exit(1);
    }
    else
    {
        printf("Parent: Child process created\n");
    }

    return 0;
}

Compile

gcc fork_exec.c -o fork_exec

Execute

./fork_exec

Possible Output

Parent: Child process created
Child: Executing ls command
total ...
-rw-r--r-- ...
...

The parent and child may execute in different orders. The child executes ls if the exec operation succeeds. The parent does not wait for the child in this introductory example.

Programming note: _exit() terminates the child without running the normal C library exit handlers or flushing inherited stdio buffers. The explicit fflush() above ensures the child's message is displayed before exec().

13. Practical: Execute a Command Using execvp()

Create a program that executes the Linux date command using an argument array.

Program

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    char *args[] = {
        "date",
        NULL
    };

    printf("Executing date command\n");
    fflush(stdout);

    execvp("date", args);

    perror("execvp");

    return 1;
}

Compile

gcc execvp_example.c -o execvp_example

Execute

./execvp_example

Expected Output

Executing date command
Thu Nov  5 16:00:00 IST 2026

The date and time shown here are illustrative. Your terminal displays the actual system date and time.

15. Interview Questions and Answers

Q1. What is the exec() family?

It is a group of functions that replace the current process image with a new program.

Q2. Does exec() create a new process?

No. It replaces the program image of the calling process.

Q3. Does exec() return on success?

No. On success, execution continues in the new program. It returns -1 if execution fails.

Q4. What is the difference between fork() and exec()?

fork() creates a new process, while exec() replaces the current process image with another program.

Q5. What is the difference between execl() and execv()?

execl() accepts arguments as a list, while execv() accepts arguments through an array.

Q6. What does p represent in execlp()?

It indicates that the function searches the PATH environment variable when resolving the executable name.

Q7. What does e represent in execle()?

It indicates that a custom environment array is supplied.

Q8. What happens to the PID after exec()?

The PID remains the same because exec() replaces the program image without creating a new process.

Q9. Which function is the Linux exec system call interface?

execve().

Q10. Why are fork() and exec() commonly used together?

fork() creates a child process, and exec() allows that child to execute another program while the parent continues.

  3. Deletes a directory
  4. Allocates a file descriptor

Answer: B — Replaces the current process image

  1. It always changes.

Answer: B — It remains the same

Q6. Which function searches PATH and uses an argument array?

Answer: B — execvp()

Q7. What does exec() return when it fails?

  1. 0

Q8. Which function is the underlying Linux system call interface?

  1. execl()
  2. execvp()

Answer: C — execve()

Q9. What terminates an exec argument array?

  1. 0

Q10. Which combination is commonly used to create and execute a child program?

  1. read() and write()

17. Lesson Summary

  • The exec() family replaces the current process image.
  • exec() does not create a new process.
  • The process ID remains unchanged after successful exec().
  • Successful exec() calls do not return.
  • Failed exec() calls return -1 and set errno.
  • execl() uses a list of arguments.
  • execv() uses an argument array.
  • Functions ending in p search PATH.
  • Functions ending in e accept a custom environment.
  • fork() and exec() are commonly used together.
