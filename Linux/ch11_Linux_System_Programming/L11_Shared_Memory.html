Shared Memory

Learn how multiple Linux processes access a common memory region for fast interprocess communication.

1. Introduction to Shared Memory

Shared memory is an Interprocess Communication (IPC) mechanism that allows two or more processes to access the same region of physical memory through their virtual address spaces.

Instead of transferring data through a pipe or message queue, processes read and write directly to the shared memory region.

Definition: Shared memory is an IPC technique in which multiple processes map a common memory region into their address spaces to exchange data.

Basic Architecture

       Process A                 Process B
    +-------------+           +-------------+
    |             |           |             |
    |  Virtual    |           |  Virtual    |

2. Why Shared Memory Is Used

  • Fast data exchange between processes.
  • Efficient communication for large data blocks.
  • Reduces repeated data copying between processes.
  • Useful in multimedia and real-time applications.
  • Useful in embedded Linux and high-performance systems.

Examples of Applications

  • Industrial monitoring systems.
  • Multimedia processing.
  • High-speed data acquisition.
  • Database systems.
  • Interprocess communication in embedded Linux.

3. How Shared Memory Works

  1. A process creates or opens a shared memory object.
  2. The operating system provides a shared memory region.
  3. Each participating process attaches or maps the region.
  4. Processes read and write data in the shared region.
  5. Processes detach or unmap the region when finished.
  6. The shared memory object is removed when no longer needed.
Shared memory does not automatically synchronize processes. If multiple processes access shared data concurrently, use synchronization mechanisms such as semaphores or process-shared mutexes.

5. System V Shared Memory Functions

Header Files

#include <sys/ipc.h>
#include <sys/shm.h>

Important Functions

Function Purpose
shmget() Creates or obtains a shared memory segment.
shmat() Attaches the segment to the process address space.
shmdt() Detaches the segment from the process.
shmctl() Controls or removes the shared memory segment.

6. shmget() Function

The shmget() function creates a new System V shared memory segment or obtains an existing segment.

Syntax

int shmget(key_t key, size_t size, int shmflg);

Parameters

  • key: Identifies the shared memory segment.
  • size: Requested segment size in bytes.
  • shmflg: Flags and permission bits.

Common Flags

Flag Meaning
IPC_CREAT Create the segment if it does not exist.
IPC_EXCL With IPC_CREAT, fail if the segment already exists.
0666 Read and write permissions for owner, group and others, subject to system rules.

Example

int shmid;

shmid = shmget(1234, 1024, IPC_CREAT | 0666);

if (shmid == -1)
{
    perror("shmget");
}

On success, shmget() returns a shared memory identifier. On failure, it returns -1.

7. shmat() Function

The shmat() function attaches a shared memory segment to the calling process's address space.

Syntax

void *shmat(int shmid, const void *shmaddr, int shmflg);

Parameters

  • shmid: Shared memory identifier.
  • shmaddr: Preferred attachment address; NULL lets the kernel choose.
  • shmflg: Attachment flags, such as SHM_RDONLY.

Return Value

On success, returns the attached address. On failure, returns (void *) -1.

Example

void *ptr;

ptr = shmat(shmid, NULL, 0);

if (ptr == (void *) -1)
{
    perror("shmat");
}

The returned pointer can be used to access the shared memory region.

8. shmdt() Function

The shmdt() function detaches a shared memory segment from the calling process's address space.

Syntax

int shmdt(const void *shmaddr);

Example

if (shmdt(ptr) == -1)
{
    perror("shmdt");
}

Detaching a segment does not necessarily remove the shared memory object. Other processes may still be attached to it.

9. shmctl() Function

The shmctl() function performs control operations on a System V shared memory segment.

Syntax

int shmctl(int shmid, int cmd, struct shmid_ds *buf);

Common Command

Command Purpose
IPC_STAT Gets information about the segment.
IPC_SET Changes certain segment metadata and permissions.
IPC_RMID Marks the segment for removal.

Example: Remove Shared Memory

if (shmctl(shmid, IPC_RMID, NULL) == -1)
{
    perror("shmctl");
}
Remove a shared memory segment only when it is no longer required. IPC_RMID marks it for deletion; actual removal occurs after the relevant attachments are gone.

10. Practical Program: System V Shared Memory

This program creates a shared memory segment, attaches it, writes a message, reads the message, detaches the segment and marks it for removal.

Program: shared_memory.c

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/ipc.h>
#include <sys/shm.h>

int main(void)
{
    int shmid;
    char *shared_data;

    /* Create shared memory */

    shmid = shmget(IPC_PRIVATE, 1024, IPC_CREAT | 0600);

    if (shmid == -1)
    {
        perror("shmget");
        return 1;
    }

    /* Attach shared memory */

    shared_data = (char *)shmat(shmid, NULL, 0);

    if (shared_data == (char *) -1)
    {
        perror("shmat");
        shmctl(shmid, IPC_RMID, NULL);
        return 1;
    }

    /* Write data */

    strcpy(shared_data, "Hello from Shared Memory");

    printf("Written: %s\n", shared_data);

    /* Read data */

    printf("Read: %s\n", shared_data);

    /* Detach shared memory */

    if (shmdt(shared_data) == -1)
    {
        perror("shmdt");
        shmctl(shmid, IPC_RMID, NULL);
        return 1;
    }

    /* Remove shared memory */

    if (shmctl(shmid, IPC_RMID, NULL) == -1)
    {
        perror("shmctl");
        return 1;
    }

    printf("Shared memory removed successfully\n");

    return 0;
}

Compile

gcc shared_memory.c -o shared_memory

Execute

./shared_memory

Expected Output

Written: Hello from Shared Memory
Read: Hello from Shared Memory
Shared memory removed successfully
This first program demonstrates shared memory creation and access within one process. The next program demonstrates actual communication between two separate processes.

11. Practical Program: Parent and Child Shared Memory

In this program, the parent creates shared memory before fork(). The child writes a message into the shared region. The parent reads that message after the child exits.

Program: shared_parent_child.c

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <sys/ipc.h>
#include <sys/shm.h>

int main(void)
{
    int shmid;
    pid_t pid;
    char *shared_data;

    shmid = shmget(IPC_PRIVATE, 1024, IPC_CREAT | 0600);

    if (shmid == -1)
    {
        perror("shmget");
        return 1;
    }

    shared_data = (char *)shmat(shmid, NULL, 0);

    if (shared_data == (char *) -1)
    {
        perror("shmat");
        shmctl(shmid, IPC_RMID, NULL);
        return 1;
    }

    shared_data[0] = '\0';

    pid = fork();

    if (pid == -1)
    {
        perror("fork");
        shmdt(shared_data);
        shmctl(shmid, IPC_RMID, NULL);
        return 1;
    }

    if (pid == 0)
    {
        /* Child Process */

        strcpy(shared_data, "Message written by child");

        _exit(0);
    }
    else
    {
        /* Parent Process */

        waitpid(pid, NULL, 0);

        printf("Parent received: %s\n", shared_data);

        if (shmdt(shared_data) == -1)
        {
            perror("shmdt");
            shmctl(shmid, IPC_RMID, NULL);
            return 1;
        }

        if (shmctl(shmid, IPC_RMID, NULL) == -1)
        {
            perror("shmctl");
            return 1;
        }
    }

    return 0;
}

Compile

gcc shared_parent_child.c -o shared_demo

Execute

./shared_demo

Expected Output

Parent received: Message written by child

The child and parent access the same shared memory segment. waitpid() ensures that the child finishes writing before the parent reads the message.

12. POSIX Shared Memory

POSIX shared memory is another Linux IPC mechanism. It provides a named shared memory object that processes can open and map into their address spaces.

Important Functions

Function Purpose
shm_open() Creates or opens a shared memory object.
ftruncate() Sets the size of the shared memory object.
mmap() Maps the object into process memory.
munmap() Unmaps the memory region.
shm_unlink() Removes the shared memory object's name.

Header Files

#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

Basic Workflow

shm_open()
     |
     v
ftruncate()
     |
     v
mmap()
     |
     v
Read / Write Shared Data
     |
     v
munmap()
     |
     v
close()
     |
     v
shm_unlink()

POSIX shared memory is commonly backed by a tmpfs filesystem, often mounted at /dev/shm on Linux.

13. Shared Memory Synchronization

Multiple processes can access shared memory at the same time. This can create race conditions if they modify shared data without coordination.

Example: Race Condition

Suppose two processes update the same counter. Both may read the same old value and overwrite each other's updates. 

Shared Counter = 10

Process A reads 10
Process B reads 10

Process A writes 11
Process B writes 11

Final Counter = 11
Expected Counter = 12

Synchronization Mechanisms

  • System V semaphores.
  • POSIX semaphores.
  • Process-shared POSIX mutexes.
  • Other suitable interprocess synchronization primitives.
A normal process-private mutex is not automatically suitable for synchronization between unrelated processes. A POSIX mutex placed in shared memory must be initialized with the PTHREAD_PROCESS_SHARED attribute.

14. Shared Memory vs Pipe

Feature Shared Memory Pipe
Communication Common memory region Byte stream
Data transfer Direct memory access after mapping read() and write()
Speed Often faster for large data exchange Involves kernel-managed pipe buffering
Synchronization Must be managed separately Blocking and EOF provide some coordination
Typical use Large or frequent data sharing Stream communication

15. Useful Linux Commands

List System V Shared Memory Segments

ipcs -m

Display Detailed Shared Memory Information

ipcs -m -i SHMID

Remove a Shared Memory Segment

ipcrm -m SHMID

Display POSIX Shared Memory Objects

ls -l /dev/shm

Replace SHMID with the actual shared memory identifier. Do not remove a segment that is still required by another process.

18. Interview Questions and Answers

Q1. What is shared memory?

Shared memory is an IPC mechanism that allows multiple processes to access a common memory region.

Q2. Why is shared memory fast?

After mapping the shared region, processes can access the common memory directly without sending each data block through a pipe or message queue.

Q3. What are the two common types of Linux shared memory?

System V shared memory and POSIX shared memory.

Q4. Which function creates a System V shared memory segment?

shmget().

Q5. Which function attaches shared memory?

shmat().

Q6. Which function detaches shared memory?

shmdt().

Q7. Which function removes a System V shared memory segment?

shmctl() with the IPC_RMID command.

Q8. What is a race condition?

A race condition occurs when concurrent operations access or modify shared data and the result depends on their execution order.

Q9. Why is synchronization required?

Synchronization prevents conflicting concurrent operations and protects shared data consistency.

Q10. Which command lists System V shared memory segments?

ipcs -m.

Q11. What is POSIX shared memory?

It is a shared memory interface using functions such as shm_open(), ftruncate() and mmap().

Q12. What is the difference between shmdt() and shmctl()?

shmdt() detaches a segment from the calling process. shmctl() performs control operations, including marking a segment for removal.
