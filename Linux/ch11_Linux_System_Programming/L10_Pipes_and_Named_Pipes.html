Pipes and Named Pipes

Understand communication between Linux processes using unnamed pipes and named pipes (FIFOs).

1. Introduction to Pipes

A pipe is an Interprocess Communication (IPC) mechanism that allows one process to send data to another process.

A pipe transfers data as a byte stream. One process writes data into the pipe, and another process reads data from it.

Definition: A pipe is a unidirectional IPC communication channel that transfers a byte stream between processes.

Basic Pipe Communication

        Process A
             |
             | write()
             v
        +------------+
        |    PIPE    |
        +------------+
             |
             | read()
             v
        Process B
  • The writing process sends data.
  • The reading process receives data.
  • The pipe maintains data in a kernel-managed buffer.
  • Reading consumes the data from the pipe.

2. Types of Pipes in Linux

Linux provides two commonly used pipe types:

Unnamed Pipe Named Pipe
Also called an anonymous pipe. Also called a FIFO.
Does not have a filesystem pathname. Has a filesystem pathname.
Commonly used between related processes. Can be used by unrelated local processes.
Created using pipe(). Created using mkfifo() or mkfifo command.
Accessed through file descriptors. Opened through a pathname and accessed using file descriptors.

3. Unnamed Pipes

An unnamed pipe is a temporary communication channel without a name in the filesystem.

It is commonly created before fork(), allowing a parent and child process to inherit the pipe file descriptors.

Pipe Architecture

              Parent Process
                    |
               pipe(fd)
                    |
                 fork()
                    |
           +--------+--------+
           |                 |
           v                 v
      Parent Process    Child Process
           |                 |
        write(fd[1])      read(fd[0])
           |                 |
           +------ PIPE -----+

The pipe() function creates two file descriptors.

4. pipe() System Call

The pipe() function creates an unnamed pipe and returns two file descriptors.

Header File

#include <unistd.h>

Syntax

int pipe(int pipefd[2]);

Return Values

  • 0: Pipe created successfully.
  • -1: Error occurred.

File Descriptor Array

Array Element Purpose
pipefd[0] Read end.
pipefd[1] Write end.

Example

int fd[2];

if (pipe(fd) == -1)
{
    perror("pipe");
    return 1;
}

printf("Read FD: %d\n", fd[0]);
printf("Write FD: %d\n", fd[1]);

5. Communication Using fork() and pipe()

A common technique is to create a pipe before calling fork(). Both processes inherit descriptors referring to the same pipe.

Communication Flow

  1. Create a pipe using pipe().
  2. Create a child process using fork().
  3. Close unused pipe ends in each process.
  4. The writer uses write().
  5. The reader uses read().
  6. Close the remaining descriptors.
Important: Close unused pipe ends. EOF is delivered to a reader only after all descriptors referring to the pipe's write end have been closed and buffered data has been consumed.

6. Practical Program: Parent to Child Communication

This program sends a message from the parent process to the child process using an unnamed pipe.

Program

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <string.h>

int main(void)
{
    int fd[2];
    pid_t pid;
    char message[] = "Hello Child Process";
    char buffer[100];
    ssize_t n;

    if (pipe(fd) == -1)
    {
        perror("pipe");
        return 1;
    }

    pid = fork();

    if (pid == -1)
    {
        perror("fork");
        close(fd[0]);
        close(fd[1]);
        return 1;
    }

    if (pid > 0)
    {
        /* Parent Process */

        close(fd[0]);

        if (write(fd[1], message, sizeof(message)) == -1)
        {
            perror("write");
            close(fd[1]);
            wait(NULL);
            return 1;
        }

        close(fd[1]);

        wait(NULL);

        printf("Parent: Message sent\n");
    }
    else
    {
        /* Child Process */

        close(fd[1]);

        n = read(fd[0], buffer, sizeof(buffer) - 1);

        if (n == -1)
        {
            perror("read");
            close(fd[0]);
            _exit(1);
        }

        buffer[n] = '\0';

        printf("Child received: %s\n", buffer);

        close(fd[0]);

        _exit(0);
    }

    return 0;
}

Compile

gcc pipe_parent_child.c -o pipe_demo

Execute

./pipe_demo

Possible Output

Child received: Hello Child Process
Parent: Message sent

The parent closes the read end because it only writes. The child closes the write end because it only reads. wait() ensures the parent collects the child's exit status.

7. Unidirectional and Bidirectional Communication

A normal unnamed pipe is a unidirectional byte stream. For two-way communication, programs commonly use two pipes.

One Pipe

        Process A
             |
             | write()
             v
           PIPE
             |
             | read()
             v
        Process B

Two Pipes

        Process A                 Process B
            |                         |
            | write()                 | read()
            v                         ^
       +-----------+             +-----------+
       |  Pipe 1   | ----------> |           |
       +-----------+             |           |
                                 |           |
       +-----------+             |           |
       |  Pipe 2   | <---------- |           |
       +-----------+             +-----------+
            ^                         |
            | read()                  | write()
            |                         |
            +-------------------------+

One pipe transfers data from Process A to Process B. The second pipe transfers data in the reverse direction.

8. Named Pipes (FIFO)

A named pipe is a special filesystem object used for IPC between processes.

Unlike an unnamed pipe, a FIFO has a pathname. Independent processes can open the same FIFO and communicate without being related through fork().

FIFO Characteristics

  • Has a pathname in the filesystem.
  • Can be accessed by unrelated processes.
  • Transfers data as a byte stream.
  • Normally operates in one direction per communication channel.
  • Data is not stored as a regular persistent file.
  • Data is consumed when read.
A FIFO is called First In, First Out because data is read in the order in which it was written.

9. Creating a FIFO Using mkfifo Command

Linux provides the mkfifo command to create a named pipe.

Syntax

mkfifo fifo_name

Example

mkfifo myfifo

Verify the FIFO

ls -l myfifo

Example output:

prw-r--r-- 1 user user 0 Nov 5 10:00 myfifo

The first character p indicates that the filesystem object is a FIFO.

Remove a FIFO

rm myfifo

10. Creating a FIFO Using mkfifo() Function

C programs can create a named pipe using the mkfifo() function.

Header Files

#include <sys/types.h>
#include <sys/stat.h>

Syntax

int mkfifo(const char *pathname, mode_t mode);

Parameters

  • pathname: Name of the FIFO.
  • mode: Requested permission bits.

Return Values

  • 0: FIFO created successfully.
  • -1: Error occurred.

Example

#include <stdio.h>
#include <sys/types.h>
#include <sys/stat.h>

int main(void)
{
    if (mkfifo("myfifo", 0666) == -1)
    {
        perror("mkfifo");
        return 1;
    }

    printf("FIFO created successfully\n");

    return 0;
}

The requested permission bits are affected by the process umask.

11. Opening and Using a FIFO

A FIFO is opened using open(), just like a file. However, FIFO opening has special blocking behaviour.

Opening Mode Typical Behaviour
O_RDONLY Normally waits for a writer to open the FIFO.
O_WRONLY Normally waits for a reader to open the FIFO.
O_NONBLOCK | O_RDONLY Can open without waiting for a writer.
O_NONBLOCK | O_WRONLY Fails with ENXIO if no reader has the FIFO open.
Important: If one terminal waits while opening a FIFO for reading, start the writer in another terminal. The blocking behaviour is normal.

12. Practical Example: FIFO Communication Using Terminal

This example demonstrates communication between two unrelated processes using a named pipe.

Step 1: Create FIFO

mkfifo myfifo

Step 2: Terminal 1 – Receiver

cat myfifo

Step 3: Terminal 2 – Sender

echo "Hello from Terminal 2" > myfifo

Expected Output in Terminal 1

Hello from Terminal 2

Step 4: Remove FIFO

rm myfifo

13. Practical Program: FIFO Writer

This program opens an existing FIFO and writes a message into it.

Program: fifo_writer.c

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main(void)
{
    int fd;
    const char message[] = "Message from FIFO Writer";

    fd = open("myfifo", O_WRONLY);

    if (fd == -1)
    {
        perror("open");
        return 1;
    }

    if (write(fd, message, sizeof(message)) == -1)
    {
        perror("write");
        close(fd);
        return 1;
    }

    printf("Message sent successfully\n");

    if (close(fd) == -1)
    {
        perror("close");
        return 1;
    }

    return 0;
}

14. Practical Program: FIFO Reader

This program opens the FIFO for reading and receives the message from the writer.

Program: fifo_reader.c

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    char buffer[100];
    ssize_t n;

    fd = open("myfifo", O_RDONLY);

    if (fd == -1)
    {
        perror("open");
        return 1;
    }

    n = read(fd, buffer, sizeof(buffer) - 1);

    if (n == -1)
    {
        perror("read");
        close(fd);
        return 1;
    }

    buffer[n] = '\0';

    printf("Received Message: %s\n", buffer);

    if (close(fd) == -1)
    {
        perror("close");
        return 1;
    }

    return 0;
}

Compile Both Programs

gcc fifo_writer.c -o fifo_writer
gcc fifo_reader.c -o fifo_reader

Create FIFO

mkfifo myfifo

Terminal 1 – Run Reader

./fifo_reader

Terminal 2 – Run Writer

./fifo_writer

Expected Output

Terminal 1:

Received Message: Message from FIFO Writer

Terminal 2:

Message sent successfully

The reader and writer are separate programs. They do not need a parent-child relationship.

15. Pipe vs FIFO

Feature Unnamed Pipe Named Pipe (FIFO)
Filesystem name No Yes
Creation pipe() mkfifo()
Related processes Commonly used Not required
Data type Byte stream Byte stream
Read/write interface read()/write() open(), read(), write()
Persistent data No No; pathname persists until removed.

16. Important Pipe Concepts

1. Blocking Behaviour

A blocking read() normally waits when the pipe has no data and at least one writer remains open.

A blocking write() may wait when the pipe buffer has insufficient space.

2. EOF Condition

When all write descriptors referring to a pipe or FIFO are closed and all buffered data has been consumed, read() returns 0.

3. Broken Pipe

Writing to a pipe or FIFO with no readers causes SIGPIPE by default. If the signal is ignored or handled, write() fails with EPIPE.

4. PIPE_BUF

PIPE_BUF defines the maximum size of a write that is guaranteed to be atomic with respect to other writers to the same pipe or FIFO.

On Linux, PIPE_BUF is commonly 4096 bytes. The actual value can be queried for a particular pipe using fpathconf() with _PC_PIPE_BUF. PIPE_BUF is not the total pipe capacity.

17. Common Errors

Error Meaning Possible Cause
EEXIST File exists FIFO pathname already exists.
ENOENT No such file or directory FIFO pathname does not exist.
EACCES Permission denied Insufficient permissions.
ENXIO No such device or address Nonblocking FIFO write open has no reader.
EPIPE Broken pipe Writing when no reader exists and SIGPIPE is handled or ignored.
EMFILE Too many open files Process descriptor limit reached.

19. Interview Questions and Answers

Q1. What is a pipe in Linux?

A pipe is an IPC mechanism that transfers a byte stream between processes.

Q2. What are the two types of pipes?

Unnamed pipes and named pipes (FIFOs).

Q3. Which function creates an unnamed pipe?

pipe().

Q4. Which function creates a named pipe?

mkfifo().

Q5. What does pipefd[0] represent?

It represents the read end of the pipe.

Q6. What does pipefd[1] represent?

It represents the write end of the pipe.

Q7. Can unrelated processes communicate using an unnamed pipe?

An unnamed pipe is commonly shared through inherited descriptors, such as after fork(). FIFOs or sockets are more suitable for unrelated processes.

Q8. What is FIFO?

FIFO stands for First In, First Out. It is a named pipe represented by a filesystem object.

Q9. How can two processes communicate in both directions using pipes?

Use two pipes, one for each direction.

Q10. What happens when all pipe writers close their descriptors?

After buffered data is consumed, read() returns 0.

Q11. What is PIPE_BUF?

It is the maximum write size guaranteed to be atomic relative to other writers to the same pipe or FIFO.

Q12. What happens when a process writes to a pipe with no readers?

SIGPIPE is generated. If the signal is ignored or handled, write() fails with EPIPE.
