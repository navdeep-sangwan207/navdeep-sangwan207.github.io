LINUX SYSTEM PROGRAMMING • CHAPTER 11 • LESSON 8

open(), read(), write() and close()

Learn the four fundamental Linux file I/O interfaces through syntax, flags, return values and practical C programs.

1. Introduction

Linux provides low-level interfaces for opening files, reading data, writing data and closing files. These operations are fundamental to Linux system programming.

The four interfaces are:

  • open() – Opens or creates a file.
  • read() – Reads bytes from a file descriptor.
  • write() – Writes bytes to a file descriptor.
  • close() – Releases a file descriptor.
Important: These are POSIX interfaces commonly used in Linux programming. They operate using file descriptors rather than C standard I/O FILE pointers.

3. open() Interface

The open() interface opens an existing file or creates a new file when requested.

Syntax

int open(const char *pathname, int flags, ...);

Parameters

  • pathname: File path or filename.
  • flags: Specifies access mode and additional options.
  • mode: Permission bits, required when O_CREAT is specified.

Return Values

Return Meaning
0 or greater Successful file descriptor.
-1 Operation failed; errno indicates the error.

Common Access Modes

Flag Description
O_RDONLY Open for reading only.
O_WRONLY Open for writing only.
O_RDWR Open for reading and writing.

Additional Flags

Flag Purpose
O_CREAT Create the file if it does not exist.
O_TRUNC Truncate an existing regular file to zero length when opened for writing.
O_APPEND Position each write at the end of the file.
O_EXCL With O_CREAT, fail if the file already exists.
O_CLOEXEC Set close-on-exec for the returned descriptor.

Example 1: Open an Existing File

int fd;

fd = open("data.txt", O_RDONLY);

if (fd == -1)
{
    perror("open");
}

Example 2: Create a File

int fd;

fd = open(
    "data.txt",
    O_WRONLY | O_CREAT,
    0644
);

if (fd == -1)
{
    perror("open");
}

Example 3: Append Data

int fd;

fd = open(
    "data.txt",
    O_WRONLY | O_CREAT | O_APPEND,
    0644
);

Example 4: Truncate Existing File

int fd;

fd = open(
    "data.txt",
    O_WRONLY | O_CREAT | O_TRUNC,
    0644
);
Caution: O_TRUNC removes the existing contents of a regular file when opening it for writing. Do not use it when existing data must be preserved.

4. read() Interface

The read() interface transfers bytes from an open file descriptor into a memory buffer.

Syntax

ssize_t read(
    int fd,
    void *buffer,
    size_t count
);

Parameters

  • fd: Open file descriptor.
  • buffer: Memory location where data is stored.
  • count: Maximum number of bytes requested.

Return Values

Return Meaning
Positive number Number of bytes actually read.
0 End of file for a regular file.
-1 Error occurred.

Example

char buffer[100];
ssize_t n;

n = read(fd, buffer, sizeof(buffer) - 1);

if (n == -1)
{
    perror("read");
}
else
{
    buffer[n] = '\0';
    printf("%s", buffer);
}
Important: The return value tells you how many bytes were actually read. It may be smaller than the requested count. Never assume that read() fills the entire buffer.

5. write() Interface

The write() interface transfers bytes from a memory buffer to an open file descriptor.

Syntax

ssize_t write(
    int fd,
    const void *buffer,
    size_t count
);

Parameters

  • fd: Open file descriptor.
  • buffer: Memory address containing data.
  • count: Number of bytes requested for writing.

Return Values

  • Positive value: Number of bytes actually written.
  • 0: No bytes written.
  • -1: Error occurred.

Example

const char message[] = "Linux Programming";
ssize_t n;

n = write(
    fd,
    message,
    sizeof(message) - 1
);

if (n == -1)
{
    perror("write");
}

sizeof(message) - 1 excludes the terminating null character from the bytes written.

Important: A successful write() may write fewer bytes than requested. Check its return value and write the remaining data when complete transfer is required.

6. Handling Partial Writes

A partial write occurs when write() successfully transfers fewer bytes than requested. A robust program should continue writing the remaining bytes.

Reusable write_all() Function

#include <unistd.h>
#include <errno.h>
#include <stddef.h>

int write_all(int fd, const char *buffer, size_t count)
{
    size_t total = 0;
    ssize_t n;

    while (total < count)
    {
        n = write(
            fd,
            buffer + total,
            count - total
        );

        if (n == -1)
        {
            if (errno == EINTR)
                continue;

            return -1;
        }

        if (n == 0)
        {
            errno = EIO;
            return -1;
        }

        total += (size_t)n;
    }

    return 0;
}

This function continues until all requested bytes are written or an error occurs.

System programming concept: EINTR indicates that an operation was interrupted by a signal before it completed. Retrying is appropriate for write() when no bytes were transferred by that call.

7. close() Interface

The close() interface releases a file descriptor previously obtained from open() or another descriptor-producing operation.

Syntax

int close(int fd);

Return Values

Return Meaning
0 Successful close.
-1 Error occurred.

Example

if (close(fd) == -1)
{
    perror("close");
}
Linux-specific caution: Do not blindly retry close() after EINTR on Linux. The descriptor may already have been released and reused by another operation. Handle the error without accidentally closing an unrelated descriptor.

8. Complete Program: Write and Read a File

This program creates a file, writes a message, closes it, reopens it and reads the stored message.

Program

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    const char message[] = "Welcome to Linux File I/O\n";
    char buffer[100];
    ssize_t n;

    /* Create and open file */
    fd = open(
        "demo.txt",
        O_WRONLY | O_CREAT | O_TRUNC,
        0644
    );

    if (fd == -1)
    {
        perror("open for writing");
        return 1;
    }

    /* Write data */
    n = write(fd, message, sizeof(message) - 1);

    if (n == -1)
    {
        perror("write");
        close(fd);
        return 1;
    }

    if ((size_t)n != sizeof(message) - 1)
    {
        fprintf(stderr, "Partial write occurred\n");
        close(fd);
        return 1;
    }

    printf("Data written successfully\n");

    /* Close file */
    if (close(fd) == -1)
    {
        perror("close after writing");
        return 1;
    }

    /* Reopen file for reading */
    fd = open("demo.txt", O_RDONLY);

    if (fd == -1)
    {
        perror("open for reading");
        return 1;
    }

    /* Read data */
    n = read(fd, buffer, sizeof(buffer) - 1);

    if (n == -1)
    {
        perror("read");
        close(fd);
        return 1;
    }

    buffer[n] = '\0';

    printf("File Content:\n%s", buffer);

    /* Close file */
    if (close(fd) == -1)
    {
        perror("close after reading");
        return 1;
    }

    return 0;
}

Compile

gcc file_io.c -o file_io

Execute

./file_io

Expected Output

Data written successfully
File Content:
Welcome to Linux File I/O

Verify the File

cat demo.txt

9. Program: Append Data to a File

O_APPEND allows a program to add data at the end of an existing file without truncating its contents.

Program

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    const char message[] = "Second line added\n";
    ssize_t n;

    fd = open(
        "demo.txt",
        O_WRONLY | O_APPEND
    );

    if (fd == -1)
    {
        perror("open");
        return 1;
    }

    n = write(fd, message, sizeof(message) - 1);

    if (n == -1)
    {
        perror("write");
        close(fd);
        return 1;
    }

    if ((size_t)n != sizeof(message) - 1)
    {
        fprintf(stderr, "Partial write occurred\n");
        close(fd);
        return 1;
    }

    printf("Data appended successfully\n");

    if (close(fd) == -1)
    {
        perror("close");
        return 1;
    }

    return 0;
}

Compile and Execute

gcc append_file.c -o append_file
./append_file

Verify

cat demo.txt

Expected file content after the previous program:

Welcome to Linux File I/O
Second line added

13. Interview Questions and Answers

Q1. What is open()?

open() opens a file or creates it when O_CREAT is specified. It returns a file descriptor on success.

Q2. What is the purpose of O_CREAT?

It requests creation of a file if the specified file does not exist.

Q3. What is the difference between O_TRUNC and O_APPEND?

O_TRUNC removes existing file contents when opening for writing. O_APPEND directs writes to the end of the file.

Q4. What does read() return at EOF?

It returns zero when no more data is available from a regular file.

Q5. Can read() return fewer bytes than requested?

Yes. A successful read() can return a short read. The application must inspect the actual return value.

Q6. Can write() return fewer bytes than requested?

Yes. A successful write() may perform a partial write. The program should handle the remaining data if complete transfer is required.

Q7. What is ssize_t?

ssize_t is a signed integer type used by interfaces such as read() and write() to represent byte counts and the error value -1.

Q8. Why is close() important?

It releases the file descriptor so it can be reused and helps ensure that resources are not unnecessarily held by the process.

Q9. What does perror() do?

It prints a descriptive error message associated with the current errno value.

Q10. What is the difference between a file descriptor and FILE pointer?

A file descriptor is an integer used by low-level I/O interfaces. A FILE pointer represents a C standard I/O stream managed by the C library.

15. Lesson Summary

  • open() opens or creates a file.
  • O_RDONLY opens for reading.
  • O_WRONLY opens for writing.
  • O_RDWR opens for reading and writing.
  • O_CREAT creates a file when necessary.
  • O_APPEND directs writes to the end.
  • O_TRUNC truncates an existing regular file.

  • write() transfers bytes from a buffer.
  • close() releases the file descriptor.
