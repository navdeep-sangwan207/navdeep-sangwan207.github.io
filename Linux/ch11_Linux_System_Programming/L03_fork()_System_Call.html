fork() System Call

Learn how Linux creates new processes using fork(), and understand parent processes, child processes, process IDs and execution flow.

1. Introduction to fork()

The fork() system call is used to create a new process in Linux and other POSIX-compatible operating systems.

The process that calls fork() is called the parent process. The newly created process is called the child process.

Definition: fork() creates a new process by duplicating the calling process. The parent and child continue execution from the point immediately after the fork operation.

Header File

#include <unistd.h>

Function Prototype

pid_t fork(void);

The return type pid_t represents a process ID type defined by the system.

2. Why Is fork() Used?

Operating systems use processes to execute programs. Sometimes a running program needs to create another process to perform an additional task.

Uses of fork()

  • Creating child processes.
  • Running tasks concurrently.
  • Implementing command-line shells.
  • Developing client-server applications.
  • Executing multiple independent tasks.
  • Building process-based applications.
Example: A command-line shell can create a child process to execute an external command while the shell remains available as the parent process.

3. Parent Process and Child Process

Parent Process

The parent process is the process that calls fork() to create a new process.

Child Process

The child process is the newly created process returned by the successful execution of fork(). 

             Parent Process
                   |
                   |
                fork()
                   |
          +--------+--------+
          |                 |
          v                 v
     Parent Process     Child Process
          |                 |
          v                 v
      Continues          Continues
      execution          execution

Both processes continue executing the instructions that follow the fork() call.

4. Return Values of fork()

The return value of fork() is important because it allows the program to identify whether it is executing in the parent or child process.

Return Value Meaning
Greater than 0 Execution is in the parent process. The value is the child PID.
0 Execution is in the child process.
-1 Process creation failed. No child was created.
Remember: Parent process → positive return value. Child process → zero. Failure → -1.

5. Process ID and Parent Process ID

Every process in Linux has a unique process identifier while it exists.

Process ID (PID)

PID is the identification number assigned to a process by the operating system.

Parent Process ID (PPID)

PPID identifies the parent process of a process.

Functions

Function Purpose
getpid() Returns the calling process ID.
getppid() Returns the parent process ID.

Header File

#include <unistd.h>

6. First fork() Program

The following program creates a child process and prints a message from both the parent and child.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void)
{
    pid_t pid;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child Process\n");
    }
    else
    {
        printf("Parent Process\n");
    }

    return 0;
}

Explanation

  1. fork() creates a child process.
  2. If the return value is -1, process creation failed.
  3. If the return value is 0, execution is in the child.
  4. If the return value is positive, execution is in the parent.
  5. Both processes execute their respective print statements.

Compile

gcc fork_example.c -o fork_example

Execute

./fork_example

Possible Output

Parent Process
Child Process

The output order is not guaranteed. The child may print before the parent depending on process scheduling.

7. Display PID and PPID Using fork()

This program displays the process ID and parent process ID of both processes.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void)
{
    pid_t pid;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }

    if (pid == 0)
    {
        printf("Child Process\n");
        printf("Child PID  : %ld\n", (long)getpid());
        printf("Child PPID : %ld\n", (long)getppid());
    }
    else
    {
        printf("Parent Process\n");
        printf("Parent PID : %ld\n", (long)getpid());
        printf("Child PID  : %ld\n", (long)pid);
    }

    return 0;
}

Possible Output

Parent Process
Parent PID : 2500
Child PID  : 2501
Child Process
Child PID  : 2501
Child PPID : 2500
Important: The process IDs shown above are illustrative. Actual PIDs vary on each execution. If the parent terminates before the child calls getppid(), the child may be reparented and report a different PPID.

8. Memory Behaviour After fork()

After a successful fork(), the child process receives a separate virtual address space initially containing the same logical memory contents as the parent.

Modern Linux systems generally use a technique called Copy-on-Write (COW).

What Is Copy-on-Write?

Copy-on-Write allows parent and child processes to share physical memory pages initially. When either process modifies a shared page, the operating system creates a private copy as needed.

Advantages

  • Reduces unnecessary memory copying.
  • Improves process creation efficiency.
  • Allows independent memory changes.
  • Maintains separate process address spaces.
Important: Parent and child have separate process memory spaces. A normal variable changed by the child does not directly change the corresponding variable in the parent.

9. Demonstrating Separate Variables

This program demonstrates that changes to a normal variable in one process do not directly affect the other process.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void)
{
    int value = 10;

    pid_t pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        value = 20;
        printf("Child value  = %d\n", value);
    }
    else
    {
        value = 30;
        printf("Parent value = %d\n", value);
    }

    return 0;
}

Possible Output

Parent value = 30
Child value  = 20

The output order may change, but the parent and child maintain their own variable values.

10. Number of Processes Created by fork()

Each successful fork() creates one additional process.

Example 1: One fork()

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    fork();

    printf("Hello\n");

    return 0;
}

Number of processes: 2

Expected number of Hello lines: 2

Example 2: Two fork() Calls

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    fork();
    fork();

    printf("Hello\n");

    return 0;
}

Number of processes: 4

Expected number of Hello lines: 4

Process Count Formula

Total processes = 2^n

Here, n represents the number of successful unconditional fork() calls executed by every process.

fork() Calls Total Processes
0 1
1 2
2 4
3 8
4 16
Note: The formula assumes every process executes every fork() successfully. Conditional execution, loop placement, failures and resource limits can change the process count.

11. fork() and Process Scheduling

After fork(), the parent and child are independently scheduled by the Linux scheduler.

  • The parent may execute first.
  • The child may execute first.
  • Both processes may execute concurrently on different CPU cores.
  • Execution order is not guaranteed without synchronization.

If a program needs the parent to wait for the child, it can use wait() or waitpid(). These functions are covered in a later lesson.

12. fork() Failure Conditions

The fork() system call may fail when the operating system cannot create another process.

Common Reasons

  • Process or user process limits are reached.
  • Insufficient system resources.
  • Kernel resource limits prevent process creation.

Error Handling

pid_t pid = fork();

if (pid == -1)
{
    perror("fork failed");
}

Always check the return value of fork() before using the child or parent execution branches.

13. Practical Linux Commands

Command Purpose

15. Interview Questions and Answers

Q1. What is fork()?

fork() is a system call used to create a new process by duplicating the calling process.

Q2. What is a parent process?

The parent process is the process that calls fork() to create another process.

Q3. What is a child process?

A child process is the newly created process resulting from a successful fork() operation.

Q4. What does fork() return in the parent?

It returns the PID of the newly created child process.

Q5. What does fork() return in the child?

It returns zero.

Q6. What does fork() return on failure?

It returns -1 and sets errno.

Q7. What is Copy-on-Write?

Copy-on-Write is a memory-management technique that allows parent and child to share physical memory pages until a process modifies a shared page.

Q8. How many processes are created after two unconditional fork() calls?

Four total processes, assuming both calls succeed in every process.

Q9. Is the execution order of parent and child guaranteed?

No. Their execution order depends on process scheduling.

Q10. Which functions return process information?

getpid() returns the current process ID and getppid() returns the parent process ID.

17. Lesson Summary

  • fork() creates a new child process.
  • The calling process becomes the parent.
  • A successful fork returns the child PID to the parent and zero to the child.
  • A failed fork returns -1.
  • getpid() returns the current PID.
  • getppid() returns the parent PID.
  • Linux commonly uses Copy-on-Write to optimize memory after fork.
  • Parent and child execute independently.
  • Process execution order is not guaranteed.
