Signals and Semaphores

Learn how Linux processes handle asynchronous events and coordinate access to shared resources.

1. Introduction to Signals

A signal is a software notification sent to a process or thread to inform it that a particular event has occurred.

Signals provide a mechanism for notifying processes about events such as user interrupts, illegal memory access, termination requests and timer expiration.

Definition: A signal is an asynchronous notification delivered to a process or thread to indicate that an event requires attention.

Examples

  • Pressing Ctrl+C in a terminal.
  • Requesting a process to terminate.
  • Detecting an invalid memory access.
  • Handling timer expiration.
  • Detecting a child process state change.

2. How Signals Work

        Event Occurs
              |
              v
       Signal Generated
              |
              v
       Signal Delivered
              |
              v
       Process Handles Signal
              |
       +------+------+
       |             |
       v             v
  Default Action  Custom Handler
       |             |
       v             v
  Terminate,      Execute
  Stop, etc.      Handler

A signal may be generated by the kernel, a user command, another process or the process itself.

3. Common Linux Signals

Signal Number on Linux Purpose
SIGINT 2 Interrupt from keyboard, usually Ctrl+C.
SIGQUIT 3 Quit request, usually Ctrl+\.
SIGKILL 9 Force termination; cannot be caught or ignored.
SIGSEGV 11 Invalid memory access.
SIGPIPE 13 Write to a pipe or socket with no reader.
SIGALRM 14 Alarm timer expiration.
SIGTERM 15 Termination request.
SIGCHLD 17 Child process state change on typical Linux architectures.
SIGSTOP 19 Stop process execution.
SIGCONT 18 Continue a stopped process.
Signal numbers are architecture-dependent. Use signal names such as SIGTERM and SIGINT in portable programs instead of hardcoding numbers. SIGKILL and SIGSTOP cannot be caught, blocked or ignored.

4. Default Signal Actions

Every signal has a default action defined by the operating system.

Action Description
Terminate Terminates the process.
Core dump Terminates the process and may generate a core dump.
Stop Stops process execution.
Continue Resumes a stopped process.
Ignore Discards the signal.

A process can change the disposition of many signals using signal-handling functions, but SIGKILL and SIGSTOP are exceptions.

5. Sending Signals Using kill Command

The Linux kill command sends a signal to a process. Despite its name, it can send signals other than termination signals.

Syntax

kill [OPTIONS] PID

Send SIGTERM

kill -TERM 1234

Send SIGKILL

kill -KILL 1234

Send SIGSTOP

kill -STOP 1234

Send SIGCONT

kill -CONT 1234

List Signal Names

kill -l
Prefer SIGTERM for normal process shutdown. SIGKILL should be a last resort because it does not allow the process to perform its normal cleanup.

6. kill() System Call

The kill() system call sends a signal to a process or process group.

Header File

#include <sys/types.h>
#include <signal.h>

Syntax

int kill(pid_t pid, int sig);

Parameters

  • pid: Target process or process group identifier.
  • sig: Signal number or signal name.

Return Value

  • Returns 0 on success.
  • Returns -1 on failure and sets errno.

Example

#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <signal.h>

int main(void)
{
    pid_t pid;

    printf("Enter process ID: ");
    scanf("%d", &pid);

    if (kill(pid, SIGTERM) == -1)
    {
        perror("kill");
        return 1;
    }

    printf("SIGTERM sent successfully\n");

    return 0;
}

This program requests termination of the specified process. The operating system enforces process permission rules.

7. signal() Function

The signal() function installs a signal handler for a particular signal.

Header File

#include <signal.h>

Syntax

void (*signal(int signum,
              void (*handler)(int)))(int);

Example: Handling SIGINT

#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void handle_signal(int sig)
{
    printf("\nReceived signal: %d\n", sig);
}

int main(void)
{
    signal(SIGINT, handle_signal);

    printf("Press Ctrl+C to generate SIGINT\n");

    while (1)
    {
        sleep(1);
    }

    return 0;
}

Expected Behaviour

Press Ctrl+C to generate SIGINT

Received signal: 2

The handler runs when SIGINT is delivered. Since the handler does not terminate the process, execution can continue.

signal() is a simple interface for introductory examples. For more predictable control of signal masks and handler behaviour, prefer sigaction(). Avoid calling non-async-signal-safe functions such as printf() from production signal handlers.

8. sigaction() Function

sigaction() provides a more reliable and flexible interface for installing signal handlers.

Header File

#include <signal.h>

Syntax

int sigaction(int signum,
              const struct sigaction *act,
              struct sigaction *oldact);

Important Structure Members

Member Purpose
sa_handler Specifies a simple signal handler.
sa_sigaction Specifies an extended signal handler.
sa_mask Signals to block while the handler executes.
sa_flags Controls handler behaviour.

Example Program

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>

volatile sig_atomic_t signal_received = 0;

void handle_signal(int sig)
{
    signal_received = sig;
}

int main(void)
{
    struct sigaction sa;

    sa.sa_handler = handle_signal;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    if (sigaction(SIGINT, &sa, NULL) == -1)
    {
        perror("sigaction");
        return 1;
    }

    printf("Press Ctrl+C to generate SIGINT\n");

    while (!signal_received)
    {
        pause();
    }

    printf("Signal received: %d\n", signal_received);

    return 0;
}

The handler only sets a sig_atomic_t variable. The main program performs normal processing after the signal is received.

Important: pause() returns when a caught signal is delivered. For production code requiring robust waiting, consider sigsuspend() or an appropriate event loop.

9. raise() Function

raise() sends a signal to the calling process.

Syntax

int raise(int sig);

Example

#include <stdio.h>
#include <signal.h>

int main(void)
{
    printf("Generating SIGINT internally\n");

    raise(SIGINT);

    printf("Program continues if SIGINT is handled or ignored\n");

    return 0;
}

If SIGINT has its default disposition, the process normally terminates before the final message.

10. alarm() Function

alarm() schedules delivery of SIGALRM after a specified number of seconds.

Syntax

unsigned int alarm(unsigned int seconds);

Example

#include <stdio.h>
#include <signal.h>
#include <unistd.h>

volatile sig_atomic_t timeout = 0;

void handle_alarm(int sig)
{
    timeout = 1;
}

int main(void)
{
    signal(SIGALRM, handle_alarm);

    printf("Waiting for 5 seconds...\n");

    alarm(5);

    while (!timeout)
    {
        pause();
    }

    printf("Timer expired\n");

    return 0;
}

Expected Output

Waiting for 5 seconds...
Timer expired

alarm(5) requests SIGALRM after approximately five seconds. It is not a precision real-time timer.

11. pause() Function

pause() suspends the calling process until a signal is caught by a signal handler.

Syntax

int pause(void);

Example

#include <stdio.h>
#include <unistd.h>
#include <signal.h>

void handler(int sig)
{
    printf("Signal received\n");
}

int main(void)
{
    signal(SIGINT, handler);

    printf("Process waiting for a signal...\n");

    pause();

    printf("Process resumed\n");

    return 0;
}

When the process catches SIGINT, pause() returns with -1 and errno set to EINTR.

12. Signal Masking and Blocking

Signal blocking temporarily prevents selected signals from being delivered to a thread. A blocked signal may remain pending until it is unblocked.

Important Functions

Function Purpose
sigemptyset() Initializes an empty signal set.
sigfillset() Initializes a set containing all blockable signals.
sigaddset() Adds a signal to a set.
sigdelset() Removes a signal from a set.
sigprocmask() Examines or changes the calling thread's signal mask in a single-threaded process.

Example: Block SIGINT

#include <stdio.h>
#include <signal.h>
#include <unistd.h>

int main(void)
{
    sigset_t set;

    sigemptyset(&set);
    sigaddset(&set, SIGINT);

    sigprocmask(SIG_BLOCK, &set, NULL);

    printf("SIGINT is blocked for 10 seconds\n");
    sleep(10);

    sigprocmask(SIG_UNBLOCK, &set, NULL);

    printf("SIGINT unblocked\n");

    return 0;
}

If SIGINT is generated while blocked, it may remain pending and be delivered after unblocking. Standard signals do not queue multiple instances in the same way as real-time signals.

13. Introduction to Semaphores

A semaphore is a synchronization mechanism used to control access to shared resources by multiple processes or threads.

Definition: A semaphore is a synchronization object that maintains a counter and coordinates access to shared resources through wait and post operations.

Why Semaphores Are Used

  • Prevent race conditions.
  • Coordinate process execution.
  • Control access to shared memory.
  • Manage limited resources.
  • Synchronize producer and consumer operations.

14. Types of Semaphores

Binary Semaphore Counting Semaphore
Used for two-state synchronization, typically 0 or 1. Maintains a nonnegative count representing available resources.
Often used for mutual exclusion or event coordination. Used when multiple instances of a resource are available.
Example: protect a single shared resource. Example: manage five available connections.

Basic Operations

Operation Meaning
wait / P Decrements the semaphore or waits until it can do so.
post / V Increments the semaphore and may wake a waiting process.

15. POSIX Semaphore Functions

POSIX semaphores are available through the semaphore API defined in the semaphore header.

Header File

#include <semaphore.h>

Important Functions

Function Purpose
sem_init() Initializes an unnamed semaphore.
sem_wait() Decrements the semaphore or waits.
sem_trywait() Attempts to decrement without blocking.
sem_post() Increments the semaphore.
sem_getvalue() Gets an approximate current semaphore value.
sem_destroy() Destroys an unnamed semaphore.
sem_open() Opens or creates a named semaphore.
sem_close() Closes a named semaphore handle.
sem_unlink() Removes a named semaphore.

16. Practical Program: Semaphore with Threads

This program uses a POSIX unnamed semaphore to coordinate two threads. The semaphore starts at zero. The worker waits until the main thread posts it.

Program: semaphore_thread.c

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

sem_t sem;

void *worker(void *arg)
{
    printf("Worker: Waiting for semaphore...\n");

    if (sem_wait(&sem) == -1)
    {
        perror("sem_wait");
        return NULL;
    }

    printf("Worker: Semaphore received\n");

    return NULL;
}

int main(void)
{
    pthread_t thread;

    if (sem_init(&sem, 0, 0) == -1)
    {
        perror("sem_init");
        return 1;
    }

    if (pthread_create(&thread, NULL, worker, NULL) != 0)
    {
        perror("pthread_create");
        sem_destroy(&sem);
        return 1;
    }

    sleep(2);

    printf("Main: Posting semaphore\n");

    if (sem_post(&sem) == -1)
    {
        perror("sem_post");
        pthread_join(thread, NULL);
        sem_destroy(&sem);
        return 1;
    }

    pthread_join(thread, NULL);

    sem_destroy(&sem);

    return 0;
}

Compile

gcc semaphore_thread.c -o semaphore_thread -pthread

Execute

./semaphore_thread

Expected Output

Worker: Waiting for semaphore...
Main: Posting semaphore
Worker: Semaphore received

The worker thread remains blocked at sem_wait() until the main thread calls sem_post().

17. System V Semaphores

Linux also supports System V semaphores. These are useful for synchronization between independent processes.

Header Files

#include <sys/ipc.h>
#include <sys/sem.h>

Important Functions

Function Purpose
semget() Creates or accesses a semaphore set.
semop() Performs semaphore operations.
semctl() Controls a semaphore set.

Basic Workflow

semget()
    |
    v
Initialize Semaphore
    |
    v
semop()
    |
    v
Coordinate Processes
    |
    v
semctl(IPC_RMID)

System V semaphores can be organized into sets. semop() performs one or more operations on a set.

18. Signals vs Semaphores

Feature Signals Semaphores
Purpose Event notification Synchronization
Data Signal identifier and optional information Counter or synchronization state
Typical use Notify a process of an event Coordinate resource access
Examples SIGINT, SIGTERM, SIGALRM sem_wait(), sem_post()

19. Signals and Semaphores in Embedded Linux

Signals and semaphores are useful in embedded Linux systems where multiple processes and threads cooperate to perform hardware-related tasks.

Example: Industrial Monitoring System

  • A sensor process collects measurement data.
  • A signal notifies a monitoring process of an event.
  • A semaphore coordinates access to shared measurement data.
  • A logging process records the measurements.
  • A control process evaluates thresholds and responds.
Signals are suitable for asynchronous event notification. Semaphores are suitable for coordinating access to shared resources and controlling execution order.

21. Interview Questions and Answers

Q1. What is a signal in Linux?

A signal is an asynchronous notification that informs a process or thread about an event.

Q2. What is SIGINT?

SIGINT is an interrupt signal commonly generated when a user presses Ctrl+C.

Q3. What is SIGTERM?

SIGTERM requests normal process termination. A process may handle or ignore it.

Q4. What is SIGKILL?

SIGKILL forcibly terminates a process and cannot be caught, blocked or ignored.

Q5. What is the difference between SIGTERM and SIGKILL?

SIGTERM allows a process to handle a shutdown request. SIGKILL terminates it without allowing normal cleanup.

Q6. What is a signal handler?

A signal handler is a function executed when a process receives a signal for which a handler has been installed.

Q7. What is sigaction()?

sigaction() installs or examines a signal disposition with greater control than signal().

Q8. What is alarm()?

alarm() schedules delivery of SIGALRM after a specified number of seconds.

Q9. What is a semaphore?

A semaphore is a synchronization mechanism used to coordinate processes or threads.

Q10. What are binary and counting semaphores?

A binary semaphore is typically used for two-state coordination, while a counting semaphore tracks multiple available resource instances.

Q11. What is sem_wait()?

sem_wait() decrements a semaphore or blocks until the operation can be performed.

Q12. What is sem_post()?

sem_post() increments the semaphore and may wake a thread or process waiting on it.

Q13. What is the difference between a signal and a semaphore?

A signal notifies a process about an event. A semaphore coordinates access to resources and execution between concurrent activities.

Q14. Which functions are used for System V semaphores?

semget(), semop() and semctl().
