Interprocess Communication (IPC)

Learn how Linux processes exchange data, synchronize activities and communicate using IPC mechanisms.

1. Introduction to IPC

Interprocess Communication (IPC) is a collection of mechanisms that allow two or more processes to exchange information and coordinate their execution.

Normally, each process has its own virtual address space. One process cannot directly access another process's private memory. IPC provides controlled ways to communicate between processes.

Definition: IPC is the mechanism through which independent processes exchange data and synchronize their operations.

Why Is IPC Required?

  • Exchange data between processes.
  • Share information between applications.
  • Coordinate tasks performed by multiple processes.
  • Build client-server applications.
  • Support parallel and distributed processing.
  • Separate application components into independent processes.

2. What Is a Process?

A process is an instance of a running program. Each process has its own execution state and virtual address space.

Typical Process Memory Layout

        +----------------------+
        |        Stack         |
        +----------------------+
        |                      |
        |     Free Space       |
        |                      |
        +----------------------+
        |        Heap          |
        +----------------------+
        |    BSS Segment       |
        +----------------------+
        |    Data Segment     |
        +----------------------+
        |    Text Segment     |
        +----------------------+

Since processes have separate address spaces, they need IPC mechanisms to exchange information safely and efficiently.

3. Basic IPC Architecture

Process Communication

        +------------------+
        |    Process A     |
        +------------------+
                 |
                 | Send Data
                 v
        +------------------+
        |    IPC Channel   |
        +------------------+
                 |
                 | Receive Data
                 v
        +------------------+
        |    Process B     |
        +------------------+

Process A sends information through an IPC mechanism. Process B receives that information through the same communication mechanism.

IPC may provide data transfer, synchronization, or both. Some mechanisms are designed mainly for communication, while others coordinate access to shared resources.

4. Types of IPC Mechanisms in Linux

Linux supports several IPC mechanisms. Each mechanism has different performance, synchronization and communication characteristics.

IPC Mechanism Purpose
Unnamed Pipes Communication between related processes, commonly parent and child.
Named Pipes (FIFO) Communication through a filesystem-named FIFO.
Message Queues Exchange messages through a managed queue.
Shared Memory Allow multiple processes to access the same memory region.
Semaphores Coordinate access to shared resources.
Signals Notify a process that an event has occurred.
Sockets Communicate between processes on the same or different machines.

5. IPC Through Pipes

A pipe is a unidirectional byte stream used to transfer data between processes.

An unnamed pipe is commonly created by a parent process before calling fork(). The parent and child inherit file descriptors referring to the pipe.

Pipe Architecture

        Parent Process
              |
              | write()
              v
        +-------------+
        |    Pipe     |
        +-------------+
              |
              | read()
              v
        Child Process

Pipe System Call

#include <unistd.h>

int pipe(int pipefd[2]);

On success, pipe() returns 0 and places two file descriptors in the array.

Descriptor Purpose
pipefd[0] Read end of the pipe.
pipefd[1] Write end of the pipe.

Detailed pipe programming is covered in the next lesson.

6. IPC Through Named Pipes (FIFO)

A named pipe, also called a FIFO, is a special filesystem object used for communication between processes.

Unlike an unnamed pipe, a FIFO has a name in the filesystem. Unrelated processes can open the same FIFO to communicate.

Create a FIFO

mkfifo myfifo

Check the FIFO

ls -l myfifo

The first character of its file-type information is p, indicating a FIFO.

Example Communication

Terminal 1 – Read from FIFO:

cat myfifo

Terminal 2 – Write to FIFO:

echo "Hello from another process" > myfifo
A FIFO transfers a byte stream. It does not preserve separate message boundaries like a message queue.

7. IPC Through Message Queues

A message queue allows processes to exchange structured messages through a queue managed by the operating system.

A sending process places a message in the queue, and a receiving process retrieves it.

Message Queue Architecture

        +------------------+
        |    Process A     |
        +------------------+
                 |
                 | Send Message
                 v
        +------------------+
        |   Message Queue  |
        +------------------+
                 |
                 | Receive Message
                 v
        +------------------+
        |    Process B     |
        +------------------+

Linux supports System V message queues and POSIX message queues.

System V Message Queue Functions

Function Purpose
msgget() Create or access a message queue.
msgsnd() Send a message.
msgrcv() Receive a message.
msgctl() Control or remove a message queue.

Message queue programming is covered in a later lesson.

8. IPC Through Shared Memory

Shared memory allows multiple processes to access the same memory region.

It is generally a high-performance IPC technique because processes can exchange data through memory without repeatedly copying it through a separate message-transfer mechanism.

Shared Memory Architecture

        +------------------+
        |    Process A     |
        +------------------+
                 |
                 |
                 v
        +------------------+
        |  Shared Memory   |
        |      Region      |
        +------------------+
                 ^
                 |
                 |
        +------------------+
        |    Process B     |
        +------------------+

System V Shared Memory Functions

Function Purpose
shmget() Create or access a shared memory segment.
shmat() Attach a shared memory segment.
shmdt() Detach a shared memory segment.
shmctl() Control or remove a shared memory segment.
Important: Shared memory does not automatically protect data from simultaneous access. Synchronization mechanisms such as semaphores or mutexes are needed when processes access shared data concurrently.

9. IPC Through Semaphores

A semaphore is a synchronization mechanism used to coordinate access to shared resources.

It helps prevent race conditions when multiple processes or threads access shared data.

Common Semaphore Operations

  • Wait (P): Decrements or waits on the semaphore.
  • Signal (V): Increments the semaphore and may wake a waiting process.

Semaphore Concept

       Process A
            |
            v
       Wait Operation
            |
            v
     Shared Resource
            ^
            |
       Signal Operation
            |
       Process B

Linux provides POSIX semaphores and System V semaphore facilities.

A semaphore controls access to resources. It is not itself a general-purpose data-transfer channel.

10. IPC Through Signals

Signals are asynchronous notifications sent to a process to indicate that an event has occurred.

Examples include:

Signal Description
SIGINT Interrupt signal, commonly generated by Ctrl+C.
SIGTERM Termination request.
SIGKILL Forceful termination; cannot be caught or ignored.
SIGSTOP Stop process execution; cannot be caught or ignored.
SIGCHLD Child process state change notification.
SIGUSR1 User-defined signal 1.

Signals are useful for notifications and process control, but they are not suitable for transferring large amounts of arbitrary data.

11. IPC Through Sockets

Sockets provide communication endpoints that allow processes to exchange data.

They can be used for communication:

  • Between processes on the same computer.
  • Between processes on different computers.
  • Between client and server applications.

Common Socket Types

Socket Type Description
SOCK_STREAM Reliable, connection-oriented byte stream, commonly using TCP.
SOCK_DGRAM Datagram-based communication, commonly using UDP.

Linux also supports UNIX domain sockets for communication between local processes.

12. IPC Comparison

Mechanism Data Transfer Typical Use
Pipe Byte stream Related processes.
FIFO Byte stream Unrelated local processes.
Message Queue Messages Structured message exchange.
Shared Memory Shared memory region High-speed data sharing.
Semaphore Synchronization Resource coordination.
Signal Event notification Process notification and control.
Socket Stream or datagram Local and network communication.

13. Synchronization and Race Conditions

When multiple processes access shared resources concurrently, their operations may interfere with each other.

What Is a Race Condition?

A race condition occurs when the result of a program depends on the unpredictable timing or ordering of concurrent operations.

Example

Suppose two processes increment the same shared counter at the same time. 

Shared Counter = 10

Process A reads 10
Process B reads 10

Process A calculates 11
Process B calculates 11

Process A writes 11
Process B writes 11

Final Counter = 11

The expected result was 12, but one increment was lost.

Methods to Prevent Race Conditions

  • Semaphores.
  • Mutex locks.
  • File locking.
  • Atomic operations.
  • Carefully designed synchronization protocols.

14. IPC in Embedded and Systems Programming

IPC concepts are important in systems software, embedded Linux and industrial applications.

Practical Applications

  • Communication between independent services.
  • Sensor data sharing between processes.
  • Communication between monitoring and control applications.
  • Client-server communication in Linux devices.
  • Coordination between data acquisition and processing tasks.
  • Communication between hardware management and application software.
Embedded Linux example: One process may collect sensor readings while another process processes the data. IPC can transfer the readings between these processes.

16. Interview Questions and Answers

Q1. What is IPC?

IPC stands for Interprocess Communication. It allows processes to exchange data and synchronize their activities.

Q2. Why is IPC required?

It is required when independent processes need to exchange information or coordinate their operations.

Q3. Name common Linux IPC mechanisms.

Pipes, FIFOs, message queues, shared memory, semaphores, signals and sockets.

Q4. What is a pipe?

A pipe is a unidirectional byte stream used for communication between processes.

Q5. What is a FIFO?

A FIFO is a named pipe represented by a special filesystem object.

Q6. What is shared memory?

Shared memory is a memory region that multiple processes can access.

Q7. What is a message queue?

A message queue is a kernel-managed communication mechanism that stores messages for receiving processes.

Q8. What is a semaphore?

A semaphore is a synchronization mechanism used to coordinate access to shared resources.

Q9. What is a race condition?

It is a condition where the result depends on the timing or ordering of concurrent operations.

Q10. Which IPC mechanism is useful for high-speed data sharing?

Shared memory is commonly used for high-speed data sharing, but synchronization is required when processes access shared data concurrently.

Q11. Can sockets communicate between different computers?

Yes. Network sockets support communication between processes running on different computers.

Q12. What is the difference between a pipe and a message queue?

A pipe transfers a byte stream, while a message queue transfers separately managed messages.
