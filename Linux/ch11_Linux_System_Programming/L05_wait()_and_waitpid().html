wait() and waitpid()

Understand how parent processes wait for child processes, collect termination status and manage zombie processes.

1. Introduction to wait() and waitpid()

In Linux, a parent process can create child processes using fork(). After creating a child, the parent may need to wait until the child terminates.

Linux provides wait() and waitpid() for this purpose.

Definition: wait() and waitpid() are system-call interfaces used by a parent process to collect the termination status of its child processes.

Why Are They Required?

  • To synchronize parent and child processes.
  • To collect the child's exit status.
  • To release the child's remaining process-table resources.
  • To prevent unreaped zombie processes.
  • To control the execution sequence of processes.

2. Understanding Parent and Child Processes

A parent process creates a child using fork(). Both processes execute independently. The parent can use wait() to collect the child's termination status.

Process Flow

          Parent Process
                |
              fork()
                |
          +-----+-----+
          |           |
          v           v
        Parent      Child
          |           |
          |         Executes
          |           |
          |        Terminates
          |           |
          |           v
          |      Exit Status
          |           |
          +---- wait()+
                |
          Parent Continues

The parent may continue executing other instructions while the child is running. If it calls wait(), it blocks until an eligible child changes state and can be collected.

3. wait() Function

The wait() function makes the calling process wait until one of its child processes terminates and its status is collected.

Header File

#include <sys/types.h>
#include <sys/wait.h>

Syntax

pid_t wait(int *status);

Parameters

  • status: Pointer to an integer where the child's status information is stored.
  • Pass NULL if the status information is not required.

Return Value

  • Returns the PID of the child whose status was collected.
  • Returns -1 if an error occurs or no eligible child exists.
Important: wait() normally blocks until a child terminates. It may also report a child state change if the process is being traced or the appropriate options are used through waitpid().

4. Practical Program Using wait()

This program creates a child process using fork(). The parent waits until the child terminates.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid;
    int status;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child process is running\n");
        printf("Child PID: %d\n", (int)getpid());

        sleep(2);

        printf("Child process is terminating\n");

        return 5;
    }
    else
    {
        printf("Parent is waiting for child\n");

        if (wait(&status) == -1)
        {
            perror("wait");
            return 1;
        }

        printf("Child process completed\n");
    }

    return 0;
}

Compile

gcc wait_example.c -o wait_example

Execute

./wait_example

Possible Output

Parent is waiting for child
Child process is running
Child PID: 2450
Child process is terminating
Child process completed

The PID is system-dependent. The parent waits until the child terminates, so the final parent message appears after the child has completed.

5. Understanding Child Exit Status

The wait() function stores status information in the integer variable passed through its status pointer. This integer is encoded; it should be examined using the macros provided in <sys/wait.h>.

Important Status Macros

Macro Purpose
WIFEXITED(status) Checks whether the child terminated normally.
WEXITSTATUS(status) Returns the child's exit code if it terminated normally.
WIFSIGNALED(status) Checks whether the child terminated because of a signal.
WTERMSIG(status) Returns the signal number that terminated the child.
WIFSTOPPED(status) Checks whether the child is currently stopped.
WSTOPSIG(status) Returns the signal that stopped the child.
Important: Use WEXITSTATUS(status) only after confirming that WIFEXITED(status) is true. Do not treat the raw status integer as the child's exit code.

6. Practical Program to Read Exit Status

The child process exits with status code 5. The parent collects and displays that exit code.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid;
    int status;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child process running\n");
        return 5;
    }
    else
    {
        wait(&status);

        if (WIFEXITED(status))
        {
            printf("Child exited normally\n");
            printf("Exit status: %d\n",
                   WEXITSTATUS(status));
        }
        else if (WIFSIGNALED(status))
        {
            printf("Child terminated by signal %d\n",
                   WTERMSIG(status));
        }
    }

    return 0;
}

Compile

gcc exit_status.c -o exit_status

Execute

./exit_status

Expected Output

Child process running
Child exited normally
Exit status: 5

7. waitpid() Function

The waitpid() function provides more control than wait(). It allows the parent to wait for a particular child process or to check child status without blocking.

Syntax

pid_t waitpid(
    pid_t pid,
    int *status,
    int options
);

Parameters

Parameter Description
pid Specifies which child process or group to wait for.
status Pointer to the child's status information.
options Controls blocking and which child state changes are reported.

Common pid Values

  • pid > 0: Wait for the child with that specific process ID.
  • pid == -1: Wait for any child process; this is the behaviour of wait().
  • pid == 0: Wait for a child in the same process group as the caller.
  • pid < -1: Wait for a child in the process group whose ID is -pid.

8. waitpid() Options

Option Purpose
0 Wait using the default blocking behaviour.
WNOHANG Return immediately if no requested child has a reportable state change.
WUNTRACED Also report stopped children that have not been reported.
WCONTINUED Also report children that have resumed after being stopped.
Remember: WNOHANG makes waitpid() non-blocking when no requested child has a reportable state change.

9. Practical Program Using waitpid()

This program waits for a specific child process using its PID.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid;
    pid_t result;
    int status;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child process running\n");

        sleep(2);

        printf("Child process terminating\n");

        return 10;
    }
    else
    {
        printf("Parent is waiting for PID: %d\n",
               (int)pid);

        result = waitpid(pid, &status, 0);

        if (result == -1)
        {
            perror("waitpid");
            return 1;
        }

        printf("Collected child PID: %d\n",
               (int)result);

        if (WIFEXITED(status))
        {
            printf("Exit status: %d\n",
                   WEXITSTATUS(status));
        }
    }

    return 0;
}

Compile

gcc waitpid_example.c -o waitpid_example

Execute

./waitpid_example

Possible Output

Parent is waiting for PID: 2510
Child process running
Child process terminating
Collected child PID: 2510
Exit status: 10

The PID shown is illustrative. The parent waits for the specific child whose PID was returned by fork().

10. Non-Blocking waitpid() Using WNOHANG

Normally, waitpid() blocks until the requested child has a reportable state change. With WNOHANG, the parent can check the child's status and continue if the child has not finished.

Return Values with WNOHANG

  • Positive PID: A child state change was collected.
  • Zero: No requested child has a reportable state change.
  • -1: An error occurred.

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid;
    pid_t result;
    int status;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        sleep(3);
        printf("Child process completed\n");
        return 0;
    }
    else
    {
        while (1)
        {
            result = waitpid(pid, &status, WNOHANG);

            if (result == -1)
            {
                perror("waitpid");
                return 1;
            }

            if (result == 0)
            {
                printf("Child is still running\n");
                sleep(1);
            }
            else
            {
                printf("Child process collected\n");
                break;
            }
        }
    }

    return 0;
}

Compile

gcc wnohang_example.c -o wnohang_example

Execute

./wnohang_example

Possible Output

Child is still running
Child is still running
Child is still running
Child process completed
Child process collected

Exact output timing depends on process scheduling. The parent periodically checks whether the child has terminated.

11. Difference Between wait() and waitpid()

Feature wait() waitpid()
Child selection Any eligible child Can select a particular child or process group
Blocking Normally blocks Can block or use WNOHANG
Options No options parameter Supports options
Specific child PID No Yes
Non-blocking check No direct option Yes, using WNOHANG

12. What Is a Zombie Process?

A zombie process is a child process that has terminated but whose termination status has not yet been collected by its parent.

The process has finished executing, but a small amount of process-table information remains so that the parent can collect its exit status.

How Does a Zombie Occur?

        Parent Process
              |
            fork()
              |
          Child Process
              |
          Terminates
              |
        Becomes Zombie
              |
       Parent has not yet
       collected its status
              |
        Parent calls wait()
              |
       Zombie entry is reaped

How to Check Zombie Processes

ps -el

Look for a process state containing Z. Another useful command is: 

ps aux | grep ' Z '
Important: A zombie is already terminated. Sending it another termination signal does not remove it. Its parent must collect its status using wait() or waitpid(). If the parent exits, the child is adopted by a system reaper process, which can collect it.

13. What Is an Orphan Process?

An orphan process is a child process whose parent terminates while the child is still running.

Linux reparents an orphan to an appropriate system process, commonly a process acting as a subreaper or the init/system manager.

Difference Between Zombie and Orphan

Zombie Process Orphan Process
Child has terminated. Child is still running.
Parent has not collected its status. Original parent has terminated.
Needs to be reaped. Gets adopted by another process.
Usually appears with state Z. May be running or sleeping.

15. Interview Questions and Answers

Q1. What is wait()?

wait() allows a parent process to wait for an eligible child state change and collect the child's termination status.

Q2. What is waitpid()?

waitpid() provides control over which child or process group the parent waits for and supports options such as WNOHANG.

Q3. What is a zombie process?

A terminated child whose status has not yet been collected by its parent.

Q4. What is an orphan process?

A child process whose original parent has terminated while the child is still running.

Q5. What is WNOHANG?

It makes waitpid() return immediately if no requested child has a reportable state change.

Q6. What does WIFEXITED() check?

It checks whether a child terminated normally.

Q7. What does WEXITSTATUS() return?

It extracts the child's exit code after normal termination.

Q8. What is the main difference between wait() and waitpid()?

wait() waits for any eligible child, whereas waitpid() can select a particular child or process group and supports additional options.

Q9. Can a zombie process execute instructions?

No. A zombie has already terminated and cannot execute further instructions.

Q10. How can a parent prevent zombie processes?

It should collect terminated child statuses using wait() or waitpid(), or use an appropriate child-reaping strategy.

  2. wait()

  4. open()

Answer: B — WNOHANG

Q4. What is a zombie process?

  1. A running process
  2. A terminated child not yet reaped

Q7. What is an orphan process?

  1. A child whose parent terminates while it is still running
  2. A child that has already been reaped
  3. A process that cannot execute
  4. A process with no PID

Answer: A — A child whose parent terminates while it is still running

Q8. Which header declares wait() and waitpid()?

Q9. What does waitpid() return when WNOHANG is used and no requested child has a reportable state change?

17. Lesson Summary

  • wait() allows a parent to collect an eligible child status.
  • waitpid() provides more control over child selection.
  • waitpid() supports non-blocking checks using WNOHANG.
  • WIFEXITED() checks normal termination.
  • WEXITSTATUS() extracts the normal exit code.
  • A zombie is terminated but not yet reaped.
  • An orphan is still running after its original parent terminates.
  • Parents should properly collect child-process statuses.
