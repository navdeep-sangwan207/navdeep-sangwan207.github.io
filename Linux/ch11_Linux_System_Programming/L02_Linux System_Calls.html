Linux System Calls

Understand how user-space programs request services from the Linux kernel using system calls and how to handle system call errors.

1. Introduction to System Calls

A system call is a programming interface that allows a user-space application to request a service from the Linux kernel.

Applications cannot directly perform privileged kernel operations. They use system calls to access resources such as files, processes, memory and devices.

Definition: A system call is a controlled mechanism through which a user-space process requests a service from the operating system kernel.

Examples

  • read() – reads data.
  • write() – writes data.
  • open() – opens a file.
  • close() – closes a file descriptor.
  • fork() – creates a process.
  • execve() – executes a new program image.
  • waitpid() – waits for a child process.
  • getpid() – obtains the process ID.

2. Why Do We Need System Calls?

The Linux kernel manages system resources. Applications need a safe and standardized method to access these resources. System calls provide that method.

Major Reasons

  • Access files and storage devices.
  • Create and manage processes.
  • Allocate and manage memory.
  • Communicate with other processes.
  • Access networking facilities.
  • Obtain system information.
  • Interact with supported device interfaces.
Example: A program cannot simply read protected disk hardware directly. It requests file data through an operating system interface, which performs the required operations.

3. How Does a System Call Work?

A system call involves communication between user space and kernel space.

Execution Steps

  1. A user application calls a library or system interface.
  2. The system call number and arguments are prepared.
  3. A processor system-call instruction transfers execution to the kernel.
  4. The kernel identifies and executes the requested service.
  5. The kernel returns a result or error indication.
  6. Execution continues in user space.

Important: On modern x86-64 Linux systems, the syscall instruction is commonly used for system call entry. Other processor architectures use their own mechanisms.

4. Categories of Linux System Calls

Linux system calls can be grouped according to the services they provide.

Category Purpose Examples
Process Control Create and manage processes. fork(), execve(), waitpid(), exit()
File Management Access and modify files. open(), read(), write(), close()
Memory Management Manage virtual memory. mmap(), munmap(), brk()
Device Management Access device interfaces. ioctl(), read(), write()
Information Maintenance Obtain process and system information. getpid(), uname(), getuid()
Communication Exchange information between processes. pipe(), socket(), sendto(), recvfrom()
Protection Manage permissions and credentials. chmod(), chown(), setuid()

5. System Call Numbers

The Linux kernel identifies a system call using a system call number. The number is architecture-specific and is used by the system call entry mechanism.

On x86-64 Linux, the system call number is commonly placed in the RAX register before executing the syscall instruction.

Other arguments are passed using architecture-defined registers or conventions.

Note: Do not assume system call numbers are identical across architectures or Linux versions. Use documented interfaces rather than hardcoding system call numbers in normal programs.

6. System Call Parameters and Return Values

System calls receive arguments that describe the requested operation. They return a result that indicates success or failure.

Example: write()

ssize_t write(int fd, const void *buf, size_t count);
Parameter Meaning
fd File descriptor.
buf Address of the data to write.
count Maximum number of bytes to write.

Return Value

  • Returns the number of bytes successfully written.
  • May return fewer bytes than requested.
  • Returns -1 on error and sets errno.

Example: read()

ssize_t read(int fd, void *buf, size_t count);
  • Returns the number of bytes read.
  • Returns 0 when end-of-file is reached.
  • Returns -1 on error and sets errno.

7. Error Handling in System Calls

System calls can fail due to invalid arguments, missing permissions, unavailable resources or other operating system conditions.

Many system call interfaces indicate failure by returning -1 and setting the global error variable errno.

Common Error Codes

Error Meaning
ENOENT File or directory does not exist.
EACCES Permission denied.
EBADF Invalid file descriptor.
EEXIST File already exists.
ENOMEM Insufficient memory.
EINVAL Invalid argument.

Using perror()

The perror() library function prints a descriptive error message based on the current value of errno. 

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;

    fd = open("missing.txt", O_RDONLY);

    if (fd == -1)
    {
        perror("open");
        return 1;
    }

    close(fd);

    return 0;
}

Possible Output

open: No such file or directory

The exact error message can vary depending on the system and locale. The output assumes that missing.txt does not exist in the current working directory.

8. Difference Between System Calls and Library Functions

System Call Interface Library Function
Provides access to kernel services. Provides reusable programming functionality.
May cause a transition to kernel mode. May execute entirely in user space.
Examples: read(), write(), fork(). Examples: printf(), strlen(), fopen().
Failure conventions are defined by the system call interface. Return and error conventions depend on the library function.
Remember: A library function may call one or more system calls, but not every library function requires kernel interaction.

9. Practical: Using the write() System Call

Write a C program that displays a message using the write() interface and checks its return value.

Program

#include <unistd.h>
#include <stdio.h>

int main(void)
{
    const char message[] =
        "Learning Linux System Calls!\n";

    ssize_t result;

    result = write(1, message, sizeof(message) - 1);

    if (result == -1)
    {
        perror("write");
        return 1;
    }

    if ((size_t)result != sizeof(message) - 1)
    {
        fprintf(stderr, "Partial write occurred\n");
        return 1;
    }

    return 0;
}

Compile

gcc system_call_write.c -o system_call_write

Execute

./system_call_write

Expected Output

Learning Linux System Calls!

10. Practical: Observing System Calls with strace

strace is a Linux diagnostic utility that traces system calls and signals used by a process.

Install strace

sudo apt update
sudo apt install strace

Trace a Command

strace ls

This displays system calls performed while the ls command executes.

Trace File Operations

strace -e trace=openat,read,write,close ls

Trace a Program

strace ./system_call_write

Save Trace Output

strace -o trace.txt ./system_call_write

View the Trace

cat trace.txt
Learning tip: Observe calls such as write(), openat(), close() and exit_group(). Modern Linux programs may use openat() rather than the older open() interface internally.

13. Interview Questions and Answers

Q1. What is a system call?

A system call is a controlled interface through which a user-space program requests a service from the kernel.

Q2. Why are system calls required?

They provide controlled access to operating system resources such as files, processes, memory and devices.

Q3. What happens during a system call?

The processor transfers execution from user mode to the kernel through an architecture-specific mechanism. The kernel performs the requested operation and returns a result.

Q4. What is errno?

errno is a thread-local error indicator used by many C library and POSIX interfaces to provide additional information when an operation fails.

Q5. What does perror() do?

It prints a descriptive error message corresponding to the current value of errno.

Q6. What is strace?

strace is a diagnostic utility that traces system calls and signals associated with a process.

Q7. Name four process-control system calls.

fork(), execve(), waitpid() and getpid().

Q8. What is the difference between read() and write()?

read() receives bytes from a file descriptor, while write() sends bytes to a file descriptor.

Q9. What does a return value of zero from read() indicate?

For a regular file or stream, it normally indicates end-of-file. Some other descriptor types can have different semantics.

Q10. Are all library functions system calls?

No. Library functions provide reusable functionality. Some invoke system calls, while others execute entirely in user space.
