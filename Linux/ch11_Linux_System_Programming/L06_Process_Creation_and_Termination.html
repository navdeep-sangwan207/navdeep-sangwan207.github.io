Process Creation and Termination

Understand how Linux creates processes, executes programs, manages process lifecycles and handles process termination.

1. Introduction to Process Creation

A process is an instance of a program that is currently executing. Linux creates processes to run applications, commands, services and system tasks.

Each process has its own process ID (PID), execution context, virtual address space and other operating-system resources.

Definition: Process creation is the operating-system operation of creating a new process that can execute a program independently of its parent process.

Why Are Processes Created?

  • To execute user applications.
  • To run Linux commands and utilities.
  • To start background services and daemons.
  • To perform multiple tasks concurrently.
  • To execute another program from an existing application.
  • To support client-server applications.

2. Process Creation in Linux

Linux commonly uses fork() to create a child process. The child is initially created from the calling process.

The child may continue executing the same program or use an exec function to replace its program image with another executable.

Basic Process Creation Flow

       Existing Process
              |
            fork()
              |
       +------+------+
       |             |
       v             v
     Parent        Child
       |             |
       |          exec()
       |             |
       |             v
       |       New Program
       |             |
       +-------------+
              |
        Process Management
              |
          Termination

3. fork() System Call

The fork() function creates a new child process. The child begins as a copy of the calling process, with its own process identity.

Header Files

#include <sys/types.h>
#include <unistd.h>

Syntax

pid_t fork(void);

Return Values

Return Value Meaning
Positive PID Returned to the parent process; identifies the child.
0 Returned to the child process.
-1 Indicates that process creation failed.
Important: After a successful fork(), both parent and child continue execution from the statement following the fork() call.

4. Practical Program: Create a Child Process

Program

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void)
{
    pid_t pid;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child process\n");
        printf("Child PID: %d\n", (int)getpid());
        printf("Parent PID: %d\n", (int)getppid());
    }
    else
    {
        printf("Parent process\n");
        printf("Parent PID: %d\n", (int)getpid());
        printf("Child PID: %d\n", (int)pid);
    }

    return 0;
}

Compile

gcc process_creation.c -o process_creation

Execute

./process_creation

Possible Output

Parent process
Parent PID: 2500
Child PID: 2501
Child process
Child PID: 2501
Parent PID: 2500

The process IDs are illustrative. The actual output and message order depend on process scheduling.

5. Process Image and Address Space

A process has a virtual address space containing different memory regions.

Memory Region Purpose
Text Segment Contains executable instructions.
Data Segment Contains initialized global and static variables.
BSS Segment Contains uninitialized or zero-initialized static storage.
Heap Supports dynamic memory allocation.
Stack Stores function call information and local automatic variables.

Memory Layout (Conceptual)

       High Memory Address
       +------------------+
       |      Stack       |
       |        |         |
       |        v         |
       |                  |
       |        ^         |
       |        |         |
       |       Heap       |
       +------------------+
       |       BSS        |
       +------------------+
       |      Data        |
       +------------------+
       |      Text        |
       +------------------+
       Low Memory Address

This is a simplified conceptual layout. Actual process address-space layouts vary with the architecture, executable format, shared libraries and memory randomization.

6. Copy-on-Write (COW)

After fork(), Linux does not normally copy every memory page immediately. Instead, it uses a technique called Copy-on-Write (COW).

Parent and child initially share physical memory pages where possible. When either process modifies a shared page, the operating system creates a separate copy for the modifying process.

Advantages

  • Reduces unnecessary memory copying.
  • Improves process creation efficiency.
  • Uses physical memory more efficiently.
  • Works well with the fork() and exec() pattern.
Remember: Copy-on-Write allows parent and child processes to share physical memory pages until a modification requires a private copy.

7. Executing a New Program Using exec()

After fork(), a child process can execute another program using an exec function.

A successful exec replaces the current process image. It does not create another process, so the PID remains unchanged.

Example

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void)
{
    pid_t pid;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child executing date command\n");
        fflush(stdout);

        execlp("date", "date", (char *)NULL);

        perror("execlp");
        _exit(1);
    }
    else
    {
        printf("Parent continues execution\n");
    }

    return 0;
}

Compile

gcc fork_exec.c -o fork_exec

Execute

./fork_exec

The child executes the date program if execlp() succeeds. The parent continues independently. Output ordering is not guaranteed.

8. Process Termination

Process termination means ending the execution of a process. A process may terminate normally or because of an error or signal.

Common Reasons for Termination

  • The program completes its execution.
  • The program calls exit().
  • The program calls _exit().
  • An error causes the program to terminate.
  • A signal terminates the process.
  • The process is terminated by an external action.

9. exit() Function

The exit() function terminates the calling process normally and performs C library cleanup.

Header File

#include <stdlib.h>

Syntax

void exit(int status);

Example

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    printf("Program started\n");

    exit(0);

    printf("This statement will not execute\n");

    return 0;
}

Output

Program started

Explanation

  • exit(0) indicates successful termination.
  • exit(nonzero) conventionally indicates an error or unsuccessful result.
  • Registered atexit() handlers are executed.
  • Open C standard I/O streams are flushed and closed.
  • The process terminates.

10. _exit() Function

The _exit() function terminates the calling process immediately without performing normal C library cleanup.

Header File

#include <unistd.h>

Syntax

void _exit(int status);

Example

#include <unistd.h>

int main(void)
{
    _exit(0);

    return 0;
}

Important Characteristics

  • Terminates the calling process.
  • Does not run atexit() handlers.
  • Does not flush C standard I/O streams.
  • Closes the process's file descriptors as part of termination.
  • Does not return to the caller.
Important: Use _exit() carefully. Output buffered by printf() may not appear because _exit() does not flush standard I/O buffers.

11. Difference Between exit() and _exit()

exit() _exit()
C standard library function POSIX process-termination function
Runs atexit() handlers Does not run atexit() handlers
Flushes and closes C standard I/O streams Does not flush C standard I/O streams
Performs normal C library cleanup Terminates without normal C library cleanup
Declared in stdlib.h Declared in unistd.h
Practical use: In a child process, after fork(), if an exec() call fails, _exit() is commonly used to terminate the child without running inherited C library exit handlers.

12. return from main() vs exit()

Returning from the main() function terminates the program normally. In a hosted C program, returning from main() is equivalent to calling exit() with the returned status value. 

#include <stdio.h>

int main(void)
{
    printf("Program completed\n");

    return 0;
}

The above program terminates with status code 0.

13. atexit() Function

The atexit() function registers a function that will be called during normal process termination through exit() or return from main().

Header File

#include <stdlib.h>

Syntax

int atexit(void (*function)(void));

Example

#include <stdio.h>
#include <stdlib.h>

void cleanup(void)
{
    printf("Cleanup function executed\n");
}

int main(void)
{
    atexit(cleanup);

    printf("Main function running\n");

    return 0;
}

Output

Main function running
Cleanup function executed

Registered handlers are executed in reverse order of registration.

14. Child Process Termination and Parent Cleanup

When a child terminates, its parent should collect the child's termination status using wait() or waitpid().

Example

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid;
    int status;

    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        return 1;
    }
    else if (pid == 0)
    {
        printf("Child is terminating\n");
        return 3;
    }
    else
    {
        wait(&status);

        if (WIFEXITED(status))
        {
            printf("Child exit code: %d\n",
                   WEXITSTATUS(status));
        }

        printf("Parent process completed\n");
    }

    return 0;
}

Possible Output

Child is terminating
Child exit code: 3
Parent process completed

17. Interview Questions and Answers

Q1. What is process creation?

Process creation is the operation of creating a new process to execute a program or task.

Q2. Which function commonly creates a child process in Linux?

fork().

Q3. What is Copy-on-Write?

It is a memory-management technique in which parent and child initially share physical memory pages until a modification requires a separate copy.

Q4. What does exec() do?

It replaces the current process image with a new program.

Q5. What is process termination?

It is the operation of ending a process's execution.

Q6. What is the difference between exit() and _exit()?

exit() performs normal C library cleanup, whereas _exit() terminates without running normal C library exit handlers or flushing standard I/O streams.

Q7. What is atexit()?

It registers a function to execute during normal process termination.

Q8. What happens when a child process terminates?

Its termination status becomes available for its parent to collect using wait() or waitpid().

Q9. What is a zombie process?

A terminated child process whose status has not yet been collected by its parent.

Q10. Why are fork() and exec() used together?

fork() creates a separate child process, and exec() allows the child to execute a different program.

19. Lesson Summary

  • Linux uses fork() to create child processes.
  • Parent and child continue independently after fork().
  • Copy-on-Write improves memory efficiency.
  • exec() replaces the current process image.
  • exit() performs normal C library cleanup.
  • _exit() terminates without normal C library cleanup.
  • atexit() registers normal-termination handlers.
  • wait() and waitpid() collect child-process status.
  • Correct child cleanup prevents unreaped zombie processes.
