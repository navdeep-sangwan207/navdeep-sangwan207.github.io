1. Introduction to Linux Architecture

Linux architecture describes how different components of a Linux operating system work together to manage hardware and execute user programs.

Linux is commonly described using a layered architecture. Each layer performs specific responsibilities and interacts with other layers through defined interfaces.

The major components include:

  • Hardware
  • Linux Kernel
  • System Call Interface
  • System Libraries and Runtime
  • Shell and System Utilities
  • System Services and User Applications
Important: This layered representation is a conceptual model. Real Linux systems have several interacting components, and not every interaction follows one strictly vertical path.

2. Linux Architecture Diagram

The following diagram illustrates the major conceptual layers of a Linux system.

+----------------------------------------------+ | USER APPLICATIONS | | Editors | Browsers | Compilers | Tools | +----------------------------------------------+ | SHELL AND SYSTEM UTILITIES | | Bash | ls | cp | ps | systemctl | +----------------------------------------------+ | SYSTEM LIBRARIES / RUNTIME | | glibc | Dynamic Linker | +----------------------------------------------+ | SYSTEM CALL INTERFACE | | open | read | write | fork | execve | +----------------------------------------------+ | LINUX KERNEL | | | | Process Management | Memory Management | | File Systems | Device Drivers | | Networking | IPC | Security | +----------------------------------------------+ | HARDWARE | | CPU | RAM | Storage | Devices | +----------------------------------------------+

How the layers work together

  1. The user interacts with an application or command.
  2. The application may use system libraries to perform an operation.
  3. When kernel services are required, the program requests them through the system call interface.
  4. The kernel performs the requested operation.
  5. The kernel communicates with hardware when necessary.
  6. The result is returned to the application.

3. Hardware Layer

The hardware layer consists of the physical components of a computer or embedded system.

Hardware Component Function
CPU Executes instructions and performs calculations.
RAM Stores currently running programs and working data.
Storage Stores the operating system, applications, and files.
Network Interface Card Provides network communication.
Input/Output Devices Provide communication with external devices.
Hardware Buses Transfer data and control signals between components.

Examples in Embedded Systems

  • UART for serial communication.
  • I2C for communication with sensors and peripheral ICs.
  • SPI for high-speed communication with external devices.
  • GPIO for digital input and output.
  • CAN for communication in automotive and industrial systems.
Embedded Systems Connection: Linux device drivers provide software interfaces through which the kernel can control and communicate with supported hardware peripherals.

4. Linux Kernel

The Linux kernel is the central component of the Linux operating system. It manages hardware resources and provides essential services to user-space programs.

The kernel operates with elevated privileges and controls access to important system resources.

Major Functions of the Linux Kernel

Kernel Component Responsibility
Process Management Creates, schedules, and terminates processes.
Memory Management Allocates memory and manages virtual memory.
File System Management Provides access to files and directories through the VFS.
Device Drivers Control and communicate with hardware devices.
Networking Manages network protocols and packet transmission.
Inter-Process Communication Provides mechanisms for processes to exchange information.
Security Enforces permissions and other security controls.

4.1 Process Management

The kernel manages running programs as processes. It assigns CPU time, handles process states, and coordinates process execution.

Important process-related operations include:

  • Process creation.
  • Process scheduling.
  • Context switching.
  • Process termination.

4.2 Memory Management

The kernel manages physical memory and provides virtual memory to processes.

  • Allocates and releases memory.
  • Manages virtual address spaces.
  • Provides memory protection.
  • Manages paging and memory mapping.

4.3 File System Management

Linux supports multiple file systems, including ext4, XFS, Btrfs, and others.

The Virtual File System (VFS) provides a common interface for accessing different file system implementations.

4.4 Device Drivers

A device driver is software that allows the operating system to communicate with a particular hardware device or device class.

Examples include:

  • UART drivers.
  • USB drivers.
  • Network drivers.
  • Storage drivers.
  • GPIO and I2C drivers.

4.5 Networking

The kernel implements networking functionality such as TCP/IP protocol processing, routing, and network device management.

5. Kernel Space and User Space

Linux separates program execution into two major privilege areas: kernel space and user space.

5.1 Kernel Space

Kernel space is the privileged execution environment where the Linux kernel operates.

  • Has access to privileged CPU operations.
  • Manages system resources.
  • Handles hardware access and interrupts.
  • Executes kernel code and kernel modules.

5.2 User Space

User space is where ordinary applications and user programs execute with restricted privileges.

  • Applications cannot directly perform privileged hardware operations.
  • Each process normally has its own virtual address space.
  • Programs request kernel services through system calls.
  • Memory protection helps isolate applications.
Kernel Space User Space
Privileged execution. Restricted execution.
Runs the Linux kernel. Runs applications and user programs.
Manages hardware and system resources. Requests services from the kernel.
Kernel memory is protected from ordinary user access. Processes have protected virtual address spaces.
Interview Concept: User-space programs cannot directly execute privileged kernel operations. They use controlled interfaces, especially system calls, to request kernel services.

6. System Call Interface

A system call is a controlled mechanism through which a user-space program requests a service from the operating system kernel.

For example, when a program needs to read a file, it requests the operation through the appropriate system call interface.

Common Linux System Calls

System Call Purpose
open() Opens a file or device.
read() Reads data from a file descriptor.
write() Writes data to a file descriptor.
close() Closes a file descriptor.
fork() Creates a new process.
execve() Replaces the current process image with a new program.
mmap() Creates a memory mapping.
socket() Creates a communication endpoint.

How a System Call Works

  1. A user-space program requests an operation.
  2. A library wrapper or system call interface prepares the request.
  3. The CPU enters kernel mode through the architecture-specific system call mechanism.
  4. The kernel performs the requested operation.
  5. The kernel returns a result or error.
  6. Execution continues in user space.

Example: Reading a File in C

#include <fcntl.h> #include <unistd.h> #include <stdio.h> int main(void) { int fd; char buffer[100]; ssize_t bytes; fd = open("sample.txt", O_RDONLY); if (fd == -1) { perror("open"); return 1; } bytes = read(fd, buffer, sizeof(buffer) - 1); if (bytes == -1) { perror("read"); close(fd); return 1; } buffer[bytes] = '\0'; printf("%s", buffer); close(fd); return 0; }
Explanation:
  • open() requests access to the file.
  • read() requests data from the file descriptor.
  • close() releases the file descriptor.
  • perror() is a C library function that displays an error message.
The functions open(), read(), and close() are commonly provided as C library interfaces to the corresponding kernel system calls.
Compile and execute this program on a Linux system. Create a file named sample.txt in the same directory before running it.

7. System Libraries and Runtime

System libraries provide reusable functions that applications use to perform common operations.

They help application developers avoid implementing low-level operations repeatedly.

Important Components

  • glibc: The GNU C Library, widely used by Linux applications. It provides standard C library functions and wrappers for many system calls.
  • Dynamic Linker: Loads shared libraries required by dynamically linked programs.
  • Shared Libraries: Reusable compiled code that multiple applications can use.
  • Runtime Libraries: Support program execution and language-specific operations.

Library Function vs System Call

Library Function System Call
Provided by a user-space library. Provided by the kernel interface.
May perform processing entirely in user space. Requests a kernel service.
Example: printf() Example: write()
Example: strlen() Example: read()
Important: Not every library function makes a system call. For example, strlen() normally operates entirely in user space. A function such as printf() may eventually use a system call such as write() when output is flushed.

8. Shell

A shell is a command interpreter that provides an interface between the user and the operating system.

It accepts commands, interprets them, and launches programs or performs built-in operations.

Popular Linux Shells

Shell Description
Bash Bourne Again Shell; widely used in Linux.
sh Traditional Unix shell interface.
Zsh Interactive shell with extensive customization.
Ksh Korn Shell.
Fish Friendly Interactive Shell.

Example Shell Commands

pwd ls mkdir projects cd projects touch main.c cat main.c
Remember: The shell is not the Linux kernel. Bash is a user-space program that accepts commands and launches other programs.

9. System Utilities and Daemons

9.1 System Utilities

System utilities are programs that help users and administrators manage the operating system.

Command Purpose
ls Lists files and directories.
cp Copies files and directories.
mv Moves or renames files.
ps Displays process information.
top Displays running processes and resource usage.
df Displays file system disk usage.

9.2 Daemons and Services

A daemon is a background process that provides a service or performs a system task.

Examples include:

  • SSH service for remote access.
  • Network management services.
  • Logging services.
  • Scheduling services.

9.3 systemd

systemd is a widely used Linux init system and service manager. On systems that use systemd, it commonly runs as PID 1 and manages system startup and services.

systemctl status systemctl list-units systemctl status ssh
Not every Linux distribution or embedded Linux system uses systemd. Other init systems and service-management approaches are also available.

10. User Applications

User applications are programs that perform tasks requested by users.

Examples include:

  • Web browsers.
  • Text editors.
  • Media players.
  • Compilers such as GCC.
  • Development tools.
  • Database applications.

Applications generally execute in user space and use libraries and system calls to access operating system services.

11. Linux Boot Process

The Linux boot process describes how a computer starts and loads the Linux operating system.

Stages of the Boot Process

  1. Power On: The computer receives power and begins startup.
  2. Firmware: BIOS or UEFI initializes hardware and selects a boot device.
  3. Bootloader: A bootloader such as GRUB loads the Linux kernel and usually an initramfs image.
  4. Kernel Initialization: The kernel initializes essential subsystems, detects hardware, and prepares memory and device management.
  5. Initramfs: A temporary early userspace environment helps load required drivers and locate or mount the real root filesystem.
  6. Root File System: The kernel switches to the real root filesystem.
  7. Init Process: The first userspace process starts, normally with PID 1. It may be systemd or another init implementation.
  8. Services: The init system starts required services and other system processes.
  9. Login Interface: The system provides a terminal login or graphical login environment.
Power On | v BIOS / UEFI | v Bootloader (GRUB) | v Linux Kernel + initramfs | v Kernel Initialization | v Real Root File System | v Init Process (PID 1) | v System Services | v Login / Desktop Environment
The exact boot sequence depends on the hardware, bootloader, distribution, init system, and system configuration.

12. How a Linux Command Interacts with Hardware

Consider the command:

cat file.txt

The following steps explain a simplified execution path:

  1. The user enters the command in the shell.
  2. The shell locates and launches the cat program.
  3. The program uses library interfaces to request file access.
  4. The system call interface transfers the request to the kernel.
  5. The kernel uses the Virtual File System (VFS) to handle the file operation.
  6. The relevant file system and storage driver handle the underlying access as required.
  7. The data is returned to the program.
  8. The program displays the contents using standard output.
Key Concept: Applications do not normally access storage hardware directly. They request file operations through operating system interfaces, and the kernel manages the required operations.

13. Device Drivers and Embedded Linux

Device drivers are an important part of the Linux kernel architecture. They provide the software interface between the kernel and supported hardware.

Examples of Hardware Interfaces

Interface Typical Application
UART Serial communication and debugging.
I2C Temperature sensors, EEPROMs, and peripheral ICs.
SPI Displays, flash memory, and high-speed peripherals.
GPIO LED control, switches, and digital signals.
CAN Automotive and industrial communication.

How a Device Driver Works

  1. A user application requests an operation.
  2. The request reaches the kernel through an appropriate interface.
  3. The kernel invokes the relevant driver operation.
  4. The driver communicates with the hardware using the platform's supported mechanisms.
  5. The driver reports the result to the kernel.
  6. The result is made available to the application through the relevant interface.
Career Relevance: Understanding kernel architecture, device drivers, system calls, and hardware interfaces is essential for Linux system programming and embedded Linux development.

14. Inter-Process Communication (IPC)

Inter-Process Communication (IPC) refers to mechanisms that allow separate processes to exchange information and coordinate their activities.

IPC Mechanism Purpose
Pipes Transfer data between related processes or through named pipes.
Signals Notify processes about events.
Shared Memory Allow processes to access a common memory region.
Message Queues Exchange structured messages between processes.
Sockets Enable communication between processes locally or over a network.

Example: Pipe Communication

ls | grep ".c"

Here, the output of ls is passed as input to grep through a pipe.

17. Interview Questions and Answers

Q1. What is Linux architecture?

Linux architecture is the organization of components such as hardware, kernel, system calls, libraries, shell, utilities, and applications that work together to provide operating system functionality.

Q2. What is the Linux kernel?

The Linux kernel is the core component responsible for process management, memory management, device drivers, file systems, networking, and other system services.

Q3. What is the difference between kernel space and user space?

Kernel space is a privileged execution environment for the kernel, while user space is a restricted environment for ordinary applications.

Q4. What is a system call?

A system call is a controlled interface through which a user-space program requests a service from the kernel.

Q5. Is Bash a kernel?

No. Bash is a user-space shell that interprets commands and launches programs.

Q6. What is a device driver?

A device driver is software that allows the operating system kernel to communicate with and control supported hardware devices.

Q7. What is VFS?

VFS stands for Virtual File System. It provides a common interface for accessing different file system implementations.

Q8. What is the purpose of system libraries?

System libraries provide reusable functions and interfaces that applications use to perform common operations and access operating system services.

Q9. What is systemd?

systemd is a commonly used Linux init system and service manager responsible for starting and managing services and other system components.

Q10. What is IPC?

IPC stands for Inter-Process Communication. It provides mechanisms such as pipes, signals, shared memory, message queues, and sockets for communication between processes.
