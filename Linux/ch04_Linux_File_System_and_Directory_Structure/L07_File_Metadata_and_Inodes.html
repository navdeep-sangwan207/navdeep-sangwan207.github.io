File Metadata and Inodes

Understanding file information, inode numbers and Linux filesystem structures

Home Linux Course Chapter 4

Learning Objectives

After completing this lesson, you will be able to:

  • Understand file metadata in Linux.
  • Identify common file attributes.
  • Understand inode numbers and their purpose.
  • Display inode numbers using ls -i.
  • Inspect file metadata using stat.
  • Understand the relationship between filenames and inodes.
  • Check inode usage using df -i.
  • Understand file timestamps and permissions.

1. Introduction to File Metadata

Metadata means data about data. In Linux, file metadata contains information that describes a file or directory. It provides details about the file without necessarily displaying the actual contents.

Linux filesystems maintain metadata to manage files, permissions, ownership, storage and access information.

Examples of file metadata

  • File type.
  • File permissions.
  • Owner and group.
  • File size.
  • Inode number.
  • Number of hard links.
  • Access, modification and status-change timestamps.
  • Filesystem-specific information.
Example: A file named notes.txt may contain study notes. Its metadata describes its size, ownership, permissions, timestamps and inode number.

2. Important File Attributes

Linux stores several attributes that help the operating system manage files and directories.

Attribute Description
File type Identifies whether an object is a regular file, directory, symbolic link or another supported type.
Permissions Defines read, write and execute access.
Owner User account associated with the file.
Group Group associated with the file.
File size Logical size of the file in bytes.
Inode number Identifies the file's inode within its filesystem.
Link count Number of directory entries referring to the inode.
Timestamps Record access, content modification and metadata status-change times.

3. What Is an Inode?

An inode, short for index node, is a filesystem data structure that stores metadata about a file or directory.

In traditional Unix-style filesystems, an inode stores information such as file type, permissions, ownership, file size, timestamps, link count and references to the file's data blocks.

The filename itself is generally stored in a directory entry, which associates the filename with an inode number.

Information associated with an inode

  • File type.
  • Permissions.
  • User ID (UID).
  • Group ID (GID).
  • File size.
  • Hard-link count.
  • Access time.
  • Modification time.
  • Status-change time.
  • References to data blocks or file data.
The exact inode structure depends on the filesystem. Not every filesystem stores all metadata in precisely the same way.

4. Relationship Between Filename and Inode

A filename and an inode are related, but they are not the same thing.

A directory contains entries that associate filenames with inode numbers. The inode identifies the underlying filesystem object.

Conceptual example

Directory | |-- notes.txt --------> Inode 1050 | |-- program.c --------> Inode 1051 | |-- report.pdf --------> Inode 1052

In this example, each filename refers to an inode. The inode contains metadata and references to the file's stored data.

Important: A filename is a directory entry name. An inode represents the filesystem object. Multiple filenames can refer to the same inode through hard links.

5. Displaying Inode Numbers Using ls -i

The ls command supports the -i option to display the inode number associated with each directory entry.

Command

ls -i
Example output:
1050 notes.txt 1051 program.c 1052 report.pdf 1053 Documents

The number before each filename is its inode number in the filesystem containing that entry.

Display inode numbers with detailed information

ls -li

This combines long-format listing with inode numbers.

Display inode numbers for hidden entries

ls -ia

This displays inode numbers for visible and hidden directory entries.

Display inode numbers for a particular file

ls -i notes.txt
Inode numbers are meaningful within their filesystem. Two different filesystems can contain different files with the same inode number.

6. Inspecting Metadata Using stat

The stat command displays detailed information about a file or filesystem object.

Command syntax

stat filename

Example

touch notes.txt stat notes.txt
Illustrative output:
File: notes.txt Size: 0 Blocks: 0 IO Block: 4096 regular empty file Device: 8,1 Inode: 1050 Links: 1 Access: (0644/-rw-r--r--) Uid: (1000/user) Gid: (1000/user) Access: 2026-11-05 06:00:00 Modify: 2026-11-05 06:00:00 Change: 2026-11-05 06:00:00

Actual values, device identifiers, timestamps and formatting depend on the filesystem and system.

Important stat fields

Field Meaning
File Name or path of the inspected object.
Size Logical file size in bytes.
Blocks Number of filesystem blocks allocated or reported.
IO Block Preferred or reported block size for I/O.
Inode Inode number.
Links Hard-link count.
Access Permissions and their symbolic representation.
Uid / Gid Numeric user and group identifiers, often with names.

Display only the inode number

stat -c "%i" notes.txt

Display file size and inode number

stat -c "Size: %s bytes | Inode: %i" notes.txt

7. Understanding File Timestamps

Linux filesystems commonly expose three important timestamps for files.

Timestamp Meaning
atime Last access time. Indicates when file contents were last accessed, subject to filesystem and mount behaviour.
mtime Last modification time of file contents.
ctime Last status-change time of inode metadata.

Access time (atime)

atime records the last time the file was accessed. Actual updates may depend on filesystem mount options.

Modification time (mtime)

mtime changes when file contents are modified.

Status-change time (ctime)

ctime changes when inode metadata changes, such as permissions, ownership or link count. It is not the file creation time.

Do not confuse ctime with creation time. On Linux, ctime normally represents metadata status-change time. Birth or creation time is a separate attribute and may not be available on every filesystem.

View timestamps

stat notes.txt

Update access and modification timestamps

touch notes.txt

The touch command normally updates access and modification timestamps. If the file does not exist, it creates an empty file.

8. Understanding Inode Numbers with Hard Links

A hard link is another directory entry that refers to the same inode as an existing file.

Both filenames refer to the same underlying filesystem object. Changes made through either name affect the same file contents.

Creating a hard link

touch original.txt ln original.txt hardlink.txt

Compare inode numbers

ls -i original.txt hardlink.txt
Illustrative output:
1050 original.txt 1050 hardlink.txt

Both names have the same inode number because they refer to the same filesystem object.

Check the hard-link count

stat original.txt

The Links field shows the number of hard links referring to the inode.

Hard links generally cannot cross filesystem boundaries. Creating a hard link to a directory is normally restricted for ordinary users.

9. Difference Between Inode and File Contents

An inode contains metadata and references to the data blocks used by a file. It does not normally contain the entire contents of an ordinary file.

Filename: program.c | v Directory Entry | v Inode | |-- Permissions |-- Ownership |-- File size |-- Timestamps |-- Data block references | v File Data Blocks
Inode File Data
Stores filesystem metadata. Stores the actual file contents.
Contains references to data blocks. Contains bytes belonging to the file.
Identified by an inode number within a filesystem. Accessed through the filesystem's data structures.

10. Checking Inode Usage Using df -i

Linux filesystems manage a supply of inodes. A filesystem can run out of available inodes even when it still has free storage space for file data.

The df command with the -i option displays inode usage for mounted filesystems.

Command

df -i
Illustrative output:
Filesystem Inodes IUsed IFree IUse% Mounted on /dev/sda1 1000000 50000 950000 5% / tmpfs 250000 120 249880 1% /run

Understanding the columns

Column Description
Filesystem Filesystem or storage source.
Inodes Total number of inodes available or reported.
IUsed Number of inodes used.
IFree Number of free inodes.
IUse% Percentage of inode usage.
Mounted on Filesystem mount point.

Check inode usage in human-readable storage context

df -ih
Important: df -h reports storage capacity in human-readable units. df -i reports inode availability and usage. They measure different resources.

11. Checking File Type and Metadata

The file command identifies the type of a file by examining its contents and other information.

Command

file notes.txt
Example output:
notes.txt: ASCII text

Inspect metadata

ls -l notes.txt ls -i notes.txt stat notes.txt file notes.txt

These commands provide different views of the same filesystem object.

12. Important Commands Summary

Command Purpose
ls -i Display inode numbers.
ls -li Display inode numbers and detailed listing.
stat filename Display detailed file metadata.
stat -c "%i" filename Display only the inode number.
df -i Display inode usage of mounted filesystems.
df -ih Display inode usage in human-readable format where applicable.
file filename Identify file type.
touch filename Create a file or update timestamps.
ln source link Create a hard link.

13. Practical Lab Exercises

Lab 1: Create a practice directory and file

Objective: Create a file for metadata inspection.

mkdir ~/inode_practice cd ~/inode_practice echo "Linux filesystem practice" > notes.txt

Expected Result: A directory named inode_practice containing notes.txt is created.

Lab 2: Display inode number

Objective: Identify the inode number of notes.txt.

ls -i notes.txt

Expected Result: The inode number and filename are displayed.

Lab 3: Display detailed metadata

Objective: Inspect the file's metadata.

stat notes.txt

Expected Result: The terminal displays file size, permissions, ownership, inode number, link count and timestamps.

Lab 4: Display only the inode number

Objective: Extract the inode number using stat.

stat -c "%i" notes.txt

Expected Result: Only the inode number is displayed.

Lab 5: Create a hard link

Objective: Create another filename for the same inode.

ln notes.txt hardlink.txt ls -i notes.txt hardlink.txt

Expected Result: Both filenames display the same inode number.

Lab 6: Check link count

Objective: Verify the number of hard links.

stat notes.txt

Expected Result: The Links field should show 2, assuming only the original file and newly created hard link refer to this inode.

Lab 7: Modify file contents

Objective: Observe the file size and modification timestamp.

echo "Second line" >> notes.txt stat notes.txt

Expected Result: The file size and modification time should reflect the content change. The inode number remains the same.

Lab 8: Check filesystem inode usage

Objective: Inspect inode usage.

df -i

Expected Result: Inode usage information for mounted filesystems is displayed.

Lab 9: Identify file type

Objective: Identify the type of notes.txt.

file notes.txt

Expected Result: The terminal identifies the file as a text file.

Lab 10: Remove the hard link and inspect link count

Objective: Understand how removing a hard-link name affects the link count.

14. Common Errors and Troubleshooting

Problem Possible Cause Solution
stat: cannot stat Incorrect filename or path. Verify the filename and current directory.
Permission denied Insufficient permissions. Check file ownership and access permissions.
Inode numbers differ Files are different filesystem objects. Check whether they are hard links to the same inode.
Inode usage is high Many filesystem objects are consuming inodes. Investigate directories containing large numbers of files.
df -i output is unexpected Filesystem type or mount configuration differs. Check the filesystem and mount points.

15. Interview Questions

Q1. What is file metadata?

File metadata is information describing a file, such as permissions, ownership, size, timestamps and inode number.

Q2. What is an inode in Linux?

An inode is a filesystem data structure containing metadata about a file or directory and references to its stored data.

Q3. Does an inode normally store the filename?

No. The filename is stored in a directory entry that associates the name with an inode number.

Q4. Which command displays inode numbers?

ls -i.

Q5. Which command displays detailed file metadata?

stat filename.

Q6. What is the difference between atime, mtime and ctime?

atime is access time, mtime is content modification time, and ctime is inode status-change time.

Q7. Can two filenames refer to the same inode?

Yes. Multiple hard links can refer to the same inode.

Q8. Can two different filesystems have the same inode number?

Yes. Inode numbers are interpreted within their respective filesystems.

Q9. What does df -i display?

It displays inode availability and usage for mounted filesystems.

Q10. Is ctime the file creation time?

No. ctime records the last status change of inode metadata.

Q11. What happens to the inode when a hard link is created?

The new directory entry refers to the existing inode, and the inode's hard-link count increases.

Q12. What happens when a file is renamed within the same filesystem?

Normally, the directory entry name changes while the underlying inode remains the same.

17. Lesson Summary

  • Metadata describes a file or directory.
  • An inode stores filesystem metadata and references to file data.
  • Directory entries associate filenames with inode numbers.
  • ls -i displays inode numbers.
  • stat displays detailed file metadata.
  • atime represents access time.
  • mtime represents content modification time.
  • ctime represents inode status-change time.
  • Hard links can refer to the same inode.
  • df -i displays inode usage.
  • Inode numbers are interpreted within their filesystem.
