LINUX PROGRAMMING • CHAPTER 4 • LESSON 6

Hidden Files and Directories

Understanding hidden files, configuration files and directory visibility

Home Linux Course Chapter 4

Learning Objectives

After completing this lesson, you will be able to:

  • Understand hidden files and directories in Linux.
  • Identify hidden files using the dot (.) naming convention.
  • Display hidden files using ls -a and ls -la.
  • Create and manage hidden files and directories.
  • Understand common Linux configuration files.
  • Rename ordinary files into hidden files.
  • Search for hidden files using Linux commands.

1. Introduction to Hidden Files

Hidden files are files that are not displayed by default in a normal directory listing. Linux commonly identifies hidden files by a filename that begins with a dot (.).

Hidden files are frequently used to store application settings, user preferences, shell configuration, environment information and other configuration data.

Examples of hidden files

.bashrc .profile .bash_history .gitconfig .vimrc

Examples of hidden directories

.config/ .cache/ .ssh/ .local/ .git/
Important Concept: In Linux, a filename beginning with a dot is treated as hidden by common directory-listing tools unless hidden entries are explicitly requested.

2. Why Are Files Hidden in Linux?

Hidden files help keep directory listings organized by preventing configuration and application-support files from appearing alongside ordinary user documents.

Common purposes

  • Store user-specific application settings.
  • Maintain shell configuration.
  • Store command history.
  • Keep version-control information.
  • Store application cache and support data.
  • Maintain user preferences and environment settings.

Example home directory

/home/user/ ├── Documents/ ├── Downloads/ ├── Pictures/ ├── notes.txt ├── .bashrc ├── .profile ├── .config/ └── .cache/

A normal directory listing may display Documents, Downloads, Pictures and notes.txt while omitting the dot-prefixed entries.

3. How Linux Identifies Hidden Files

Linux uses a naming convention for hidden files: their names begin with a dot (.).

Filename Hidden? Reason
notes.txt No Does not begin with a dot.
.notes.txt Yes Begins with a dot.
Documents No Does not begin with a dot.
.Documents Yes Begins with a dot.
config.backup No Does not begin with a dot.
.config Yes Begins with a dot.
A hidden file is not automatically protected or secure. Its hidden status is primarily a naming convention. Permissions determine who can access or modify it.

4. Displaying Hidden Files Using ls -a

The ls command lists directory contents. By default, it does not display dot-prefixed hidden entries.

Normal directory listing

ls

This displays ordinary visible entries in the current directory.

Display all entries, including hidden files

ls -a
Example output:
. .. .bash_history .bashrc .cache .config .profile Documents Downloads notes.txt

The -a option displays all entries, including hidden entries and the special directory entries . and ...

Display hidden entries without . and ..

ls -A

The -A option displays hidden entries but excludes the special entries . and ...

Command Purpose
ls Displays ordinary visible entries.
ls -a Displays all entries, including . and ..
ls -A Displays hidden entries except . and ..

5. Displaying Hidden Files Using ls -la

The -l option displays directory entries in long format. Combining -l with -a displays detailed information about hidden and visible entries.

Command

ls -la
Example output:
drwxr-xr-x 15 user user 4096 Nov 5 06:00 . drwxr-xr-x 3 root root 4096 Nov 5 05:00 .. -rw-r--r-- 1 user user 220 Nov 5 06:00 .bashrc -rw-r--r-- 1 user user 807 Nov 5 06:00 .profile drwxr-xr-x 2 user user 4096 Nov 5 06:00 .config drwxr-xr-x 2 user user 4096 Nov 5 06:00 Documents -rw-r--r-- 1 user user 50 Nov 5 06:00 notes.txt

Understanding the output

  • The first column displays permissions and file type.
  • The next value displays the hard-link count.
  • The owner and group identify ownership.
  • The size column displays the entry size.
  • The date and time indicate modification information.
  • The final column displays the filename.
Remember: ls -la is one of the most useful commands for inspecting hidden files and their permissions.

6. Creating Hidden Files

A hidden file can be created by giving it a filename that begins with a dot.

Method 1: Using touch

touch .secret.txt

This creates an empty hidden file named .secret.txt in the current working directory if it does not exist.

Method 2: Using echo

echo "This is a hidden file" > .hidden_notes.txt

This creates the hidden file and writes text into it.

Verify hidden file creation

ls ls -a
Example:
ls: Documents Downloads notes.txt ls -a: . .. Documents Downloads .hidden_notes.txt .secret.txt notes.txt

7. Creating Hidden Directories

A hidden directory is created by using a directory name that begins with a dot.

Creating a hidden directory

mkdir .private

Creating a hidden directory with a subdirectory

mkdir -p .private/Documents

The -p option creates the required parent directory if it does not already exist.

Viewing hidden directories

ls -la
Example output:
drwxr-xr-x 3 user user 4096 Nov 5 06:00 .private

Entering a hidden directory

cd .private pwd

A hidden directory works like an ordinary directory. Its hidden status does not prevent normal navigation.

8. Renaming Visible Files to Hidden Files

An existing file can be made hidden by renaming it so that its name begins with a dot.

Example

touch notes.txt mv notes.txt .notes.txt

The mv command changes the filename from notes.txt to .notes.txt.

Verify the renamed file

ls ls -a

The file will no longer appear in the normal listing, but it will appear in the hidden-entry listing.

Make a hidden file visible again

mv .notes.txt notes.txt

Removing the leading dot makes the filename visible in a normal ls listing.

Renaming a file does not change its file contents. It changes the filename and therefore its visibility in ordinary directory listings.

9. Common Hidden Configuration Files

Linux users commonly have hidden configuration files and directories inside their home directories.

File / Directory Purpose
.bashrc Interactive Bash shell configuration.
.profile Login-shell environment configuration.
.bash_history Stores saved Bash command history.
.gitconfig Stores Git configuration settings.
.vimrc Stores Vim editor configuration.
.ssh/ Contains SSH configuration and key-related files.
.config/ Contains application configuration data.
.cache/ Contains application cache data.
.local/ Contains user-specific application data and executables.

Viewing the Bash configuration file

cat ~/.bashrc

This displays the contents of the current user's Bash configuration file.

Viewing Git configuration

cat ~/.gitconfig

This displays the user's Git configuration if the file exists.

Do not delete or modify system and application configuration files without understanding their purpose. Changes can affect shell behaviour, application settings or access.

10. Searching for Hidden Files

Linux provides commands that can search for hidden files and directories.

Using find to locate hidden files

find ~ -type f -name ".*"

This searches the home directory tree for regular files whose names begin with a dot.

Find hidden directories

find ~ -type d -name ".*"

This searches for directories whose names begin with a dot.

Find all hidden entries in the current directory tree

find . -name ".*"

This searches from the current directory and can return hidden files and hidden directories.

Search only in the current directory

find . -maxdepth 1 -name ".*"

The -maxdepth 1 option limits the search to the current directory level.

11. Accessing Hidden Files

Hidden files can be opened, read, copied, moved, renamed and deleted just like ordinary files.

Read a hidden file

cat .secret.txt

Copy a hidden file

cp .secret.txt secret_backup.txt

Move a hidden file

mv .secret.txt Documents/

Delete a hidden file

rm .secret.txt

Remove an empty hidden directory

rmdir .private
Hidden status does not change how these commands operate. The exact filename must still be supplied.

12. Hidden Files in Linux and Git

Git repositories commonly contain a hidden directory named .git.

This directory stores repository metadata, including information about commits, branches, references and repository configuration.

Example

mkdir git_practice cd git_practice git init ls ls -a
Possible output of ls -a:
. .. .git

The .git directory is hidden because its name begins with a dot.

Deleting .git removes the repository's local version-control metadata. Do not delete it unless you intentionally want to remove that repository metadata.

14. Common Errors and Troubleshooting

Problem Possible Cause Solution
Hidden file not visible Using normal ls command. Use ls -a or ls -la.
No such file or directory Incorrect hidden filename or path. Check the exact filename using ls -a.
Permission denied Insufficient access permissions. Check ownership and permissions.
Cannot remove directory The directory is not empty. Inspect its contents before removing it.
Configuration changed unexpectedly A hidden configuration file was modified. Restore a backup or correct the configuration.

Useful troubleshooting commands

pwd ls -a ls -la stat .filename file .filename find . -name ".*"

15. Interview Questions

Q1. What are hidden files in Linux?

Hidden files are files whose names begin with a dot. They are not displayed by default in a normal ls listing.

Q2. How do you display hidden files?

Use ls -a.

Q3. What is the difference between ls -a and ls -A?

ls -a displays all entries, including . and ... ls -A displays hidden entries but excludes . and ...

Q4. How do you display hidden files with detailed information?

Use ls -la.

Q5. How do you create a hidden file?

Use a command such as touch .secret.txt.

Q6. How do you create a hidden directory?

Use mkdir .private.

Q7. How can you make a visible file hidden?

Rename it so its name begins with a dot, using mv.

Q8. Are hidden files protected from unauthorized access?

No. Hidden status is not a security mechanism. File permissions and access controls determine access.

Q9. What is the purpose of .bashrc?

It stores configuration commands and settings for interactive non-login Bash shells.

Q10. What is the purpose of the .git directory?

It stores Git repository metadata and version-control information.

  1. #
  2. @
  3. .

Correct Answer: C. .

Q2. Which command displays hidden files?

  1. ls
  2. ls -a
  3. pwd
  4. cd

Correct Answer: B. ls -a

Q3. Which command displays hidden files in long format?

  1. ls -l
  2. ls -A

Correct Answer: C. ls -la

Q4. Which of the following is a hidden file?

  1. notes.txt

Correct Answer: C. .bashrc

Q5. Which command creates a hidden directory?

  1. mkdir .private

  1. -l

17. Lesson Summary

  • Hidden files and directories begin with a dot (.).
  • Normal ls listings do not display hidden entries.
  • ls -a displays all entries, including . and ...
  • ls -A excludes the special entries . and ...
  • ls -la displays hidden and visible entries with details.
  • touch can create hidden files.
  • mkdir can create hidden directories.
  • mv can rename visible files into hidden files and vice versa.
  • Linux configuration files are commonly stored as hidden files.
  • find can search for hidden files and directories.
  • Hidden status does not provide file security.
Key Concept: In Linux, a filename beginning with a dot is hidden from ordinary directory listings. Use ls -a or ls -la to display hidden files and directories.
