LINUX PROGRAMMING • CHAPTER 4 • LESSON 8

Hard Links and Soft Links

Understanding File Linking and Inode Relationships in Linux

Home Linux Course Chapter 4

Learning Objectives

After completing this lesson, you will be able to:

  • Understand links in the Linux file system.
  • Explain hard links and symbolic (soft) links.
  • Understand the relationship between files, links and inodes.
  • Create hard links using the ln command.
  • Create symbolic links using the ln -s command.
  • Inspect and remove links safely.
  • Identify the differences between hard links and soft links.

1. Introduction to Links in Linux

In Linux, a link is a way to access a file or directory through another name or path. Links allow users to access the same file using multiple names or locations.

Linux supports two major types of links:

  • Hard Link: An additional directory entry that refers to the same inode as the original file.
  • Soft Link: A symbolic link that stores a pathname pointing to another file or directory.
Important Concept: A hard link shares the target file's inode. A symbolic link has its own inode and stores the target's pathname.

2. Understanding Inodes and Links

An inode is a data structure used by a Linux file system to store information about a file. It contains metadata such as file permissions, ownership, timestamps, file size and pointers to the file's data blocks.

A directory stores the relationship between a filename and its inode number. A hard link creates another directory entry referring to the same inode.

Example: Suppose file1.txt and file2.txt are hard links to the same file. Both names refer to the same inode and the same underlying file data.

Checking Inode Numbers

ls -i file1.txt file2.txt
Example Output:
105432 file1.txt 105432 file2.txt
Both filenames have the same inode number in this example.

The inode number is meaningful within its file system. Inode numbers are not globally unique across all mounted file systems.

3. Hard Links

Definition

A hard link is an additional filename (directory entry) that points to the same inode as an existing file. Both filenames access the same underlying file data.

Creating a Hard Link

Command Syntax:

ln TARGET LINK_NAME

Here, TARGET is the existing file and LINK_NAME is the new hard-link filename.

Example

echo "Linux Programming" > original.txt ln original.txt hardlink.txt ls -li original.txt hardlink.txt
Example Output:
105432 -rw-r--r-- 2 user user 18 Nov 5 10:00 original.txt 105432 -rw-r--r-- 2 user user 18 Nov 5 10:00 hardlink.txt
The inode number is the same for both filenames. The link count is 2 in this example.

Understanding the Link Count

The link count indicates how many hard-link directory entries refer to the inode.

  • Initially, a regular file commonly has a link count of 1.
  • Creating one hard link increases the count to 2.
  • Creating another hard link increases it to 3.
  • Removing one hard link decreases the count by 1.

What Happens When the Original Filename Is Deleted?

If original.txt is removed, the data remains accessible through hardlink.txt. The file's storage is released only when its last hard link is removed and no process is still keeping it open.

rm original.txt cat hardlink.txt
Output:
Linux Programming
The content is still accessible through the remaining hard link.

Important Characteristics of Hard Links

  • Hard links share the same inode.
  • They refer to the same underlying file data.
  • Changes made through one name are visible through the other.
  • They normally cannot cross file-system boundaries.
  • Creating hard links to directories is generally restricted to prevent file-system loops.
  • Removing one filename does not remove the data if another hard link remains.

4. Soft Links (Symbolic Links)

Definition

A soft link, also called a symbolic link or symlink, is a special file that stores the pathname of another file or directory.

Unlike a hard link, a symbolic link has its own inode. It points to a target using a pathname rather than sharing the target's inode.

Creating a Soft Link

Command Syntax:

ln -s TARGET LINK_NAME

The -s option tells Linux to create a symbolic link.

Example

echo "Welcome to Linux" > original.txt ln -s original.txt softlink.txt ls -l original.txt softlink.txt
Example Output:
-rw-r--r-- 1 user user 18 Nov 5 10:00 original.txt lrwxrwxrwx 1 user user 11 Nov 5 10:01 softlink.txt -> original.txt
The arrow indicates that softlink.txt points to original.txt.

Reading the Target of a Symbolic Link

readlink softlink.txt
Output:
original.txt

To resolve a symbolic link to an absolute canonical path where possible, use:

readlink -f softlink.txt

Accessing the File Through a Soft Link

cat softlink.txt
Output:
Welcome to Linux

When the target exists, opening the symbolic link normally accesses the target file.

What Happens When the Target Is Deleted?

If the target file is removed or renamed, the symbolic link may no longer point to an existing file. Such a link is called a dangling or broken symbolic link.

rm original.txt ls -l softlink.txt cat softlink.txt
Important: The symbolic link itself may still exist, but accessing its missing target normally produces a No such file or directory error.

Important Characteristics of Soft Links

  • A symbolic link has its own inode.
  • It stores the pathname of its target.
  • It can point to files and directories.
  • It can cross file-system boundaries.
  • It can use absolute or relative target paths.
  • It can become dangling if its target is removed or moved.
  • Deleting the symbolic link does not delete the target.

5. Absolute and Relative Symbolic Link Paths

Absolute Path Symbolic Link

An absolute symbolic link stores a target path beginning from the root directory /.

ln -s /home/user/documents/report.txt report_link

The link points to the target using its absolute path.

Relative Path Symbolic Link

A relative symbolic link stores a target path relative to the directory containing the symbolic link.

ln -s ../documents/report.txt report_link
Important: A relative symbolic-link target is resolved relative to the directory where the symbolic link is located, not relative to the shell's current working directory.

Relative links are useful when a directory structure is moved while keeping the relative relationship between the link and its target unchanged.

6. Difference Between Hard Links and Soft Links

Inode Shares the target's inode Has its own inode

Directories Generally not allowed for ordinary users Can point to directories

7. Important Commands Related to Links

Command Purpose
ln file1 file2 Create a hard link.
ln -s file1 file2 Create a symbolic link.
ls -l Display detailed file information and symbolic-link targets.
ls -i Display inode numbers.
stat filename Display file metadata, including inode and link count.
readlink linkname Display the target stored in a symbolic link.
readlink -f linkname Resolve a symbolic link to a canonical path where possible.
rm linkname Remove the specified link.
Note: When you use rm on a symbolic link, it removes the link itself, not the target file.

8. Practical Lab 1: Creating a Hard Link

Objective: To create and verify a hard link.

Step 1: Create a file

echo "This is a hard link experiment" > file1.txt

Step 2: Create a hard link

ln file1.txt file2.txt

Step 3: Check inode numbers

ls -li file1.txt file2.txt

Step 4: Check link count

stat file1.txt

Step 5: Modify the file through the second name

echo "Additional content" >> file2.txt cat file1.txt
Expected Result:
This is a hard link experiment Additional content
Both names refer to the same underlying file data.

9. Practical Lab 2: Creating a Soft Link

Objective: To create and verify a symbolic link.

Step 1: Create a file

echo "This is a symbolic link experiment" > source.txt

Step 2: Create a symbolic link

ln -s source.txt shortcut.txt

Step 3: Display link details

ls -l shortcut.txt

Step 4: Read the target path

readlink shortcut.txt

Step 5: Access the content

cat shortcut.txt
Expected Result:
This is a symbolic link experiment

Step 6: Remove the symbolic link

rm shortcut.txt cat source.txt
Expected Result:
This is a symbolic link experiment
The original file remains available because only the symbolic link was removed.

10. Common Errors and Precautions

1. File Already Exists

If the link name already exists, the command normally reports an error instead of replacing it.

2. Cross-File-System Hard Link

Creating a hard link to a file on another file system normally fails with an error such as Invalid cross-device link.

3. Dangling Symbolic Link

A symbolic link may point to a target that no longer exists. Check it using ls -l and readlink.

4. Incorrect Relative Path

A relative symbolic-link target is interpreted from the directory containing the link. An incorrect relative path can produce a dangling link.

Safety Precaution: Be careful when removing files and links. Check the target with ls -l before deleting anything.

11. Interview Questions and Answers

Q1. What is a hard link in Linux?

A hard link is an additional directory entry that refers to the same inode as an existing file.

Q2. What is a soft link?

A soft link is a special file that stores the pathname of another file or directory.

Q3. Which command creates a hard link?

The ln command creates a hard link.

Q4. Which command creates a soft link?

The ln -s command creates a symbolic link.

Q5. Do hard links have the same inode number?

Yes. Hard links to the same file share the same inode number.

Q6. Does a symbolic link have its own inode?

Yes. A symbolic link is a separate file-system object with its own inode.

Q7. Can a hard link cross file-system boundaries?

No. A hard link normally cannot refer to an inode on another file system.

Q8. Can a symbolic link point to a directory?

Yes. Symbolic links can point to both files and directories.

Q9. What happens when a symbolic link's target is deleted?

The symbolic link may become dangling because its target pathname no longer resolves to an existing file.

Q10. How can you check the inode number of a file?

Use ls -i filename or inspect the file with stat filename.

12. Multiple Choice Questions (MCQs)

Q1. Which command creates a symbolic link?

A. cp
B. mv
C. ln -s
D. mkdir

Correct Answer: C. ln -s

Q2. Hard links share which file-system structure?

A. Process ID
B. Inode
C. Shell
D. Terminal

Correct Answer: B. Inode

Q3. Which command displays inode numbers?

A. ls -i
B. pwd
C. cd
D. clear

Correct Answer: A. ls -i

Q4. Which link can normally point to a directory?

A. Hard link only
B. Soft link
C. Neither
D. Both are always prohibited

Correct Answer: B. Soft link

Q5. What happens when one hard-link filename is deleted?

A. The data is always deleted immediately
B. All other links are deleted
C. The link count decreases
D. The inode number changes immediately

Correct Answer: C. The link count decreases

Q6. What is a dangling symbolic link?

A. A link with an existing target
B. A link whose target cannot be found
C. A hard link to a directory
D. A hidden file

Correct Answer: B. A link whose target cannot be found

13. Lesson Summary

  • Linux supports hard links and symbolic links.
  • A hard link is another filename referring to the same inode.
  • A symbolic link stores the pathname of its target.
  • Hard links share the target's inode; symbolic links have their own inode.
  • Use ln to create hard links.
  • Use ln -s to create symbolic links.
  • Use ls -i to inspect inode numbers.
  • Use readlink to display a symbolic link's target.
  • A symbolic link can become dangling when its target is removed or moved.
  • Removing a symbolic link does not remove its target.
Key Concept to Remember: Hard links share an inode, whereas symbolic links store a pathname and have their own inode.
