File Types in Linux

Understanding regular files, directories, links and special files

Home Linux Course Chapter 4

Learning Objectives

After completing this lesson, you will be able to:

  • Understand the concept of file types in Linux.
  • Identify the seven traditional Unix file types.
  • Differentiate between regular files and directories.
  • Understand symbolic links and device files.
  • Identify file types using the ls -l command.
  • Use the file command to identify file contents.
  • Create and inspect basic Linux file types.

1. Introduction to File Types in Linux

Linux uses a file-based system to organize and manage information and system resources. Files are not limited to documents and images. Directories, device interfaces, communication endpoints and other objects are also represented as file types.

Linux follows the Unix concept that many resources can be accessed through file-like interfaces. Different file types have different purposes and behaviours.

Important Concept: A Linux file type describes the kind of file-system object, not simply the extension of its name.

Examples

notes.txt Documents/ image.png shortcut /dev/null /tmp/example_pipe

These examples represent different kinds of objects. Their actual file types can be checked using Linux commands.

2. Seven Traditional Linux File Types

Linux and Unix systems commonly describe seven traditional file types.

File Type Symbol Purpose Example
Regular file - Stores data and program contents. notes.txt
Directory d Organizes files and directories. /home/user
Symbolic link l Points to another path. shortcut
Character device c Provides character-oriented device access. /dev/null
Block device b Provides block-oriented device access. /dev/sda
FIFO / Named pipe p Supports inter-process communication. my_pipe
Socket s Supports communication between processes. Application socket
The symbols in the table are the file-type indicators displayed as the first character in a long-format ls -l listing.

3. Regular Files (-)

A regular file is used to store ordinary data. It may contain text, source code, executable programs, images, audio, videos or other information.

Examples

notes.txt program.c photo.jpg data.csv application.sh

Creating a regular file

touch notes.txt

The touch command creates an empty file if it does not already exist.

Writing content into a file

echo "Welcome to Linux" > notes.txt

This command writes text into notes.txt. The redirection operator > creates the file if necessary and replaces its existing contents.

Displaying file contents

cat notes.txt
Output:
Welcome to Linux

Checking the file type

ls -l notes.txt
Example output:
-rw-r--r-- 1 user user 18 Nov 5 06:00 notes.txt

The first character is a hyphen (-), indicating a regular file.

4. Directories (d)

A directory is a file-system object used to organize and reference files and other directories.

Directories make it possible to arrange data in a hierarchical structure.

Example structure

home/ └── user/ ├── Documents/ ├── Downloads/ └── notes.txt

Creating a directory

mkdir Documents

Listing directory details

ls -ld Documents
Example output:
drwxr-xr-x 2 user user 4096 Nov 5 06:00 Documents

The first character is d, indicating a directory.

Viewing directory contents

ls Documents
A directory is a special file-system object that stores associations between names and file-system entries. It is not simply an ordinary text file containing files.

5. Symbolic Links (l)

A symbolic link, also called a soft link, is a special file that contains a path reference to another file or directory.

It provides an alternative path for accessing the referenced object.

Creating a symbolic link

touch original.txt ln -s original.txt shortcut

The ln -s command creates a symbolic link named shortcut that points to original.txt.

Viewing the symbolic link

ls -l shortcut
Example output:
lrwxrwxrwx 1 user user 12 Nov 5 06:00 shortcut -> original.txt

The first character l indicates a symbolic link. The arrow shows its stored target path.

Accessing the target through the link

echo "Linux Learning" > original.txt cat shortcut
Output:
Linux Learning
If the target of a symbolic link is removed or its stored path no longer resolves, the link may become a broken or dangling symbolic link.

6. Character Device Files (c)

Character device files provide access to devices that transfer data as a stream of characters or bytes.

They are commonly found in the /dev directory.

Examples

Device File Purpose
/dev/null Discards data written to it.
/dev/zero Provides a stream of zero-valued bytes.
/dev/tty Represents the controlling terminal of a process.
/dev/random Provides random data.

Checking a character device

ls -l /dev/null file /dev/null
Typical ls -l output:
crw-rw-rw- 1 root root 1, 3 Nov 5 06:00 /dev/null

The first character c indicates a character device. The numbers identify its major and minor device numbers.

Example: Discarding output

echo "This text will be discarded" > /dev/null

The text is written to /dev/null and discarded. It is not saved as a normal document.

Character device files provide an interface to device drivers. They do not necessarily represent physical hardware; some provide virtual device functionality.

7. Block Device Files (b)

Block device files provide access to devices that transfer data in blocks. Storage devices commonly use block-device interfaces.

Examples

/dev/sda /dev/sda1 /dev/nvme0n1 /dev/nvme0n1p1

These are examples of device naming conventions. Actual names depend on the hardware and system configuration.

Checking block devices

ls -l /dev/sda lsblk

The lsblk command displays information about available block devices and their partitions.

Example lsblk output:
NAME MAJ:MIN RM SIZE TYPE sda 8:0 0 100G disk ├─sda1 8:1 0 50G part └─sda2 8:2 0 50G part

The first character in an ls -l listing of a block device is b.

Do not write directly to block device files unless you fully understand the operation. Incorrect commands can destroy data or damage a file system.

8. FIFO / Named Pipes (p)

FIFO stands for First In, First Out. A named pipe is a special file used for communication between processes.

Data written into a FIFO can be read by another process. Data is generally read in the same order in which it was written.

Creating a named pipe

mkfifo my_pipe

Checking its file type

ls -l my_pipe file my_pipe
Example output:
prw-r--r-- 1 user user 0 Nov 5 06:00 my_pipe

The first character p indicates a FIFO or named pipe.

Practical communication example

Open two terminal windows in the same directory.

Terminal 1: Read from the pipe

cat my_pipe

Terminal 2: Write to the pipe

echo "Message from another process" > my_pipe
Terminal 1 output:
Message from another process

The reading command waits until data is available. After the message is written, it receives the data.

A FIFO provides communication through a file-system name. An unnamed pipe can also connect processes, but it is not represented as a named file-system entry.

9. Socket Files (s)

A socket is a communication endpoint used by processes to exchange data.

Unix domain sockets allow processes on the same system to communicate using a file-system path.

Example socket paths

/run/docker.sock /run/systemd/private /tmp/application.sock

These are examples of Unix domain socket paths. Their availability depends on the applications running on the system.

Checking a socket file

ls -l /run/docker.sock file /run/docker.sock
Example ls -l output:
srw-rw---- 1 root docker 0 Nov 5 06:00 /run/docker.sock

The first character s indicates a socket.

Embedded and Systems Software Connection: Sockets are important in Linux application development, system services, networking and inter-process communication.

10. Identifying File Types Using ls -l

The ls -l command displays files and directories in long format. Its first character indicates the file type.

Example command

ls -l

Example output

-rw-r--r-- 1 user user 120 notes.txt drwxr-xr-x 2 user user 4096 Documents lrwxrwxrwx 1 user user 12 shortcut -> notes.txt crw-rw-rw- 1 root root 1, 3 null prw-r--r-- 1 user user 0 my_pipe srw-rw---- 1 root docker 0 docker.sock

Understanding the first character

First Character File Type
- Regular file
d Directory
l Symbolic link
c Character device
b Block device
p FIFO / Named pipe
s Socket
The remaining characters in the first field describe permissions. For example, in -rw-r--r--, the initial hyphen identifies the file type, while the remaining characters represent permission bits.

11. Identifying File Types Using the file Command

The file command examines a file and reports information about its contents and format.

It uses file-system information and content patterns to identify the type of data.

Syntax

file filename

Examples

file notes.txt file /bin/ls file /dev/null
Possible output:
notes.txt: ASCII text /bin/ls: ELF 64-bit LSB pie executable /dev/null: character special

Important options

Option Purpose
-b Displays the result without the file name.
-i Displays the MIME type and encoding.
-L Follows symbolic links to examine their targets.
-z Attempts to look inside compressed files.

Example using -i

file -i notes.txt
Possible output:
notes.txt: text/plain; charset=us-ascii
The file command identifies the contents or format of a file. It is not the same as reading only the filename extension. A file named notes.txt could contain data that is not actually plain text.

12. File Extension vs File Type

A file extension is the part of a filename that usually follows the final dot. It is commonly used to indicate the expected format of a file.

However, Linux does not determine the actual file type solely from the extension.

Filename Common Expected Format
notes.txt Text file
program.c C source code
program.cpp C++ source code
image.png PNG image
archive.zip ZIP archive
script.sh Shell script

Example

touch example.txt file example.txt

The file command may identify the empty file as empty, rather than reporting it as ordinary text simply because its name ends in .txt.

Remember: A filename extension is a naming convention. The actual file-system type and the file's content format are separate concepts.

13. Practical Lab Exercises

Lab 1: Create and identify a regular file

Objective: Create a regular file and inspect its type.

cd ~ touch regular_file.txt ls -l regular_file.txt file regular_file.txt

Expected Result: The file is created. The first character in ls -l is -.

Lab 2: Create and identify a directory

Objective: Create a directory and inspect its type.

mkdir Linux_Directory ls -ld Linux_Directory file Linux_Directory

Expected Result: The first character in ls -ld is d.

Lab 3: Create a symbolic link

Objective: Create a symbolic link to a regular file.

touch original.txt ln -s original.txt my_link ls -l my_link file my_link

Expected Result: The first character in ls -l is l.

Lab 4: Create a named pipe

Objective: Create and inspect a FIFO.

mkfifo practice_pipe ls -l practice_pipe file practice_pipe

Expected Result: The first character in ls -l is p.

Lab 5: Inspect a character device

Objective: Identify the file type of /dev/null.

ls -l /dev/null file /dev/null

Expected Result: The first character in ls -l is c.

Lab 6: Inspect block devices

Objective: Display block devices available on the system.

lsblk

Expected Result: The command displays available storage devices and their partitions. Actual results depend on your VirtualBox Ubuntu configuration.

Lab 7: Identify file content format

Objective: Use the file command to identify a file's format.

echo "Linux File Types" > sample.txt file sample.txt file -i sample.txt

Expected Result: The file command identifies the content as text and displays MIME information with -i.

Lab 8: Clean up practice files

Objective: Remove the practice objects created in this lesson.

rm -f regular_file.txt original.txt my_link rm -f sample.txt rm -f practice_pipe rmdir Linux_Directory

Expected Result: The practice files, symbolic link, FIFO and empty directory are removed.

Run the cleanup commands only in the directory where you created these practice objects. Do not use broad deletion commands on important directories.

14. Common Errors and Troubleshooting

Problem Possible Cause Solution
File command not found The file utility may not be installed. Install the file package using your distribution's package manager.
File exists A file or directory with the same name already exists. Choose another name or inspect the existing object.
Broken symbolic link The target path no longer resolves. Check the target using ls -l.
Permission denied Insufficient permissions. Check ownership and permissions.
Device file not found The device name is different or unavailable. Inspect available devices using lsblk or ls /dev.

Useful diagnostic commands

ls -l ls -ld directory_name file filename stat filename lsblk find . -maxdepth 1 -type f

These commands help inspect file types, metadata, storage devices and regular files.

15. Interview Questions

Q1. How many traditional Unix file types are commonly identified?

Seven: regular files, directories, symbolic links, character devices, block devices, FIFOs and sockets.

Q2. What is a regular file?

A regular file stores ordinary data such as text, source code, images and executable program contents.

Q3. What does d represent in ls -l?

It indicates a directory.

Q4. What is a symbolic link?

It is a special file containing a path reference to another file or directory.

Q5. What is the difference between character and block devices?

Character devices provide character-oriented data access, while block devices provide block-oriented storage access.

Q6. What is a FIFO?

FIFO is a named pipe used for communication between processes. Data is generally read in the order it is written.

Q7. What is a socket file?

It is a communication endpoint used by processes to exchange data.

Q8. Which command identifies file contents?

The file command.

Q9. What is the difference between a file extension and a file type?

An extension is part of a filename, whereas a file type describes the file-system object. Content format is another separate property.

Q10. What does the first character in -rw-r--r-- indicate?

The hyphen indicates that the object is a regular file.

17. Lesson Summary

  • Linux supports seven traditional Unix file types.
  • Regular files store ordinary data and program contents.
  • Directories organize file-system entries.
  • Symbolic links store references to other paths.
  • Character devices provide character-oriented access.
  • Block devices provide block-oriented storage access.
  • FIFOs support named-pipe communication.
  • Socket files provide communication endpoints.
  • The ls -l command displays file-type indicators.
  • The file command examines file contents and format.
  • File extensions do not necessarily determine actual file type.
Key Concept: The first character in the long-format ls -l output identifies the file-system object type. The file command provides additional information about the file's contents.
