System Monitoring Commands in Linux

Monitor CPU, memory, processes, load average and disk I/O

Home Linux Course Chapter 9

Learning Objectives

After completing this lesson, you will be able to:

  • Monitor RAM and swap memory using free.
  • Understand system uptime and load average.
  • Monitor processes, CPU and memory activity.
  • Use vmstat to inspect virtual memory and system performance.
  • Monitor CPU and disk I/O using iostat, mpstat and sar.
  • Identify basic system performance problems using Linux commands.

1. Introduction to System Monitoring

System monitoring is the process of observing a computer's performance and resource utilization. It helps administrators understand whether a Linux system is operating normally or experiencing performance problems.

System monitoring commonly involves checking:

  • CPU: Processor utilization and workload.
  • RAM: Physical memory usage.
  • Swap: Disk space used as additional virtual memory.
  • Processes: Running programs and their resource consumption.
  • Disk I/O: Read and write activity on storage devices.
  • Load average: System workload over different time intervals.
Why is system monitoring important?

It helps identify high CPU usage, insufficient memory, excessive swapping, disk bottlenecks and overloaded systems.

2. free Command – Memory Monitoring

The free command displays information about physical memory (RAM), used memory, available memory and swap space.

Syntax

free [options]

Common Commands

free free -h free -m free -g free -s 2
CommandPurpose
freeDisplays memory information in default units.
free -hDisplays human-readable memory values.
free -mDisplays values in megabytes.
free -gDisplays values in gigabytes.
free -s 2Refreshes memory information every 2 seconds.

Example Output

total used free shared buff/cache available Mem: 7.6Gi 2.1Gi 1.8Gi 250Mi 3.7Gi 5.0Gi Swap: 2.0Gi 0B 2.0Gi

Understanding Memory Columns

ColumnMeaning
totalTotal physical memory or swap space.
usedMemory currently in use, as calculated by the command.
freeMemory that is currently unused.
sharedMemory mainly used by tmpfs and shared memory.
buff/cacheMemory used for buffers and filesystem cache.
availableEstimate of memory available for new applications without swapping.
Important: Do not judge memory shortage only by the free column. Linux uses available RAM for caching. The available column is generally more useful when estimating how much memory applications can use.

3. uptime Command – System Uptime and Load Average

The uptime command displays how long the system has been running, the number of logged-in users and the system load averages.

Syntax

uptime

Example Output

14:30:20 up 5 days, 3:25, 2 users, load average: 0.45, 0.60, 0.75

Understanding the Output

InformationMeaning
14:30:20Current system time.
up 5 days, 3:25System has been running for 5 days and 3 hours 25 minutes.
2 usersNumber of logged-in user sessions.
0.451-minute load average.
0.605-minute load average.
0.7515-minute load average.

What is Load Average?

Load average represents the average number of tasks that are either runnable or waiting in uninterruptible sleep, commonly due to I/O operations.

  • First value: Average workload over 1 minute.
  • Second value: Average workload over 5 minutes.
  • Third value: Average workload over 15 minutes.
Important: Load average is not a CPU utilization percentage. Interpret it in relation to the number of logical CPUs.

Check Logical CPU Count

nproc
Example output:
4
This indicates that 4 processing units are available to the command.

On a system with 4 logical CPUs, a sustained load average around 4 indicates a workload roughly equivalent to the available CPU capacity. A much higher value may indicate CPU contention or tasks waiting for I/O. Interpretation depends on the workload and system state.

4. vmstat Command – Virtual Memory Statistics

The vmstat command reports information about processes, memory, swap, I/O, system activity and CPU utilization.

Syntax

vmstat [options] [delay] [count]

Examples

vmstat vmstat 1 vmstat 1 5 vmstat -s
CommandPurpose
vmstatDisplays a summary of system statistics.
vmstat 1Displays updated statistics every second.
vmstat 1 5Displays reports at one-second intervals, with five interval reports after the initial since-boot report.
vmstat -sDisplays memory and system statistics in summary form.

Example Output

procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu----- r b swpd free buff cache si so bi bo in cs us sy id wa st 1 0 0 800000 50000 900000 0 0 5 10 100 200 10 2 87 1 0

Important Columns

ColumnMeaning
rRunnable processes waiting for CPU time.
bProcesses in uninterruptible sleep.
swpdAmount of virtual memory used as swap.
freeUnused physical memory.
siMemory swapped in from disk.
soMemory swapped out to disk.
biBlocks received from block devices.
boBlocks sent to block devices.
usCPU time spent executing user processes.
syCPU time spent executing kernel processes.
idCPU idle time.
waCPU time waiting for I/O.
The first report from vmstat 1 5 represents averages since the last boot. Subsequent reports represent activity during the specified intervals.

5. Installing sysstat Tools

Some advanced monitoring commands, including iostat, mpstat and sar, are provided by the sysstat package on Ubuntu.

Install sysstat

sudo apt update sudo apt install sysstat

Verify Installation

iostat -V mpstat -V sar -V
These commands may not be available on a fresh Ubuntu installation until the package is installed. Historical system activity collection may also require separate configuration.

6. iostat Command – CPU and Disk I/O Monitoring

The iostat command displays CPU utilization and input/output statistics for storage devices.

Syntax

iostat [options] [interval] [count]

Examples

iostat iostat -c iostat -d iostat -x iostat -xz 1 3
OptionPurpose
-cDisplays CPU statistics.
-dDisplays device I/O statistics.
-xDisplays extended device statistics.
-zOmits devices with no activity in the report.

Important Disk I/O Metrics

MetricMeaning
r/sRead requests per second.
w/sWrite requests per second.
rkB/sKilobytes read per second.
wkB/s Kilobytes written per second.
awaitAverage time for I/O requests, in milliseconds.
%utilPercentage of elapsed time during which the device had I/O in progress.
Practical interpretation:

High I/O wait or high request latency may indicate storage performance problems. A high %util can indicate a busy device, but it should not be treated as a universal saturation measurement, particularly for modern parallel storage devices.

7. mpstat Command – CPU Utilization Monitoring

The mpstat command reports processor utilization. It can display statistics for individual CPUs or all available CPUs.

Syntax

mpstat [options] [interval] [count]

Examples

mpstat mpstat 1 mpstat 1 5 mpstat -P ALL 1 3
CommandPurpose
mpstatDisplays CPU utilization statistics.
mpstat 1Refreshes CPU statistics every second.
mpstat 1 5Displays five interval reports at one-second intervals.
mpstat -P ALL 1 3Displays statistics for all CPUs at one-second intervals.

Important CPU Metrics

  • %usr – CPU time spent executing user applications.
  • %sys – CPU time spent executing kernel code.
  • %idle – Percentage of time the CPU is idle.
  • %iowait – Percentage of time the CPU is idle while I/O is outstanding.
  • %steal – CPU time taken by the hypervisor for other virtual CPUs.

8. sar Command – System Activity Reporter

The sar command collects, reports and analyzes system activity information. It can monitor CPU, memory, device I/O and other system statistics.

Syntax

sar [options] [interval] [count]

Common Examples

sar -u 1 3 sar -r 1 3 sar -d 1 3 sar -n DEV 1 3
CommandPurpose
sar -u 1 3Reports CPU utilization.
sar -r 1 3Reports memory utilization.
sar -d 1 3Reports block device activity.
sar -n DEV 1 3Reports network interface activity.

Historical Monitoring

When system activity collection is enabled, sar can read previously collected statistics. On Ubuntu systems using the standard sysstat configuration, check whether collection is enabled in:

/etc/default/sysstat

Look for the setting:

ENABLED="true"

If collection is disabled, change the setting to true using an administrator-approved text editor, then restart the service:

sudo systemctl restart sysstat systemctl status sysstat

To enable the service at startup when the service unit is available:

sudo systemctl enable --now sysstat
Historical reports are not automatically available on every Ubuntu installation. Collection must be enabled, and the system needs time to accumulate activity data.

9. lscpu Command – CPU Information

The lscpu command displays information about the CPU architecture, processor model, CPU count, cores and threads.

Syntax

lscpu

Example Output

Architecture: x86_64 CPU op-mode(s): 32-bit, 64-bit CPU(s): 4 Thread(s) per core: 1 Core(s) per socket: 4 Socket(s): 1 Vendor ID: GenuineIntel

Useful Related Commands

nproc lscpu lscpu -e
  • nproc – Displays the number of processing units available to the current process.
  • lscpu – Displays detailed CPU architecture information.
  • lscpu -e – Displays CPU information in a table.

10. Other Useful System Monitoring Commands

top – Real-Time Process Monitoring

top

Displays running processes, CPU usage, memory usage and system activity in real time.

ps – Process Information

ps ps aux ps -ef

Displays information about running processes.

uname – Kernel and System Information

uname -a uname -r

uname -a displays general kernel and system information. uname -r displays the kernel release.

watch – Repeated Command Execution

watch free -h watch -n 2 uptime watch -n 1 df -h

The watch command repeatedly executes another command and refreshes its output.

12. Practical Linux Exercises

Exercise 1: Check Memory Usage

free -h

Task: Identify total RAM, used RAM, available RAM and swap usage.

Exercise 2: Check System Uptime

uptime

Task: Identify how long the system has been running and read all three load-average values.

Exercise 3: Find the Number of CPUs

nproc lscpu

Task: Compare the number reported by nproc with the CPU details from lscpu.

Exercise 4: Monitor Virtual Memory

vmstat 1 5

Task: Observe runnable processes, free memory, swap activity and CPU idle percentage.

Exercise 5: Monitor CPU Utilization

sudo apt install sysstat mpstat -P ALL 1 3

Task: Observe CPU utilization and compare the individual CPU reports.

Exercise 6: Monitor Disk I/O

iostat -xz 1 3

Task: Observe read/write activity, request latency and device utilization.

Exercise 7: Monitor System Activity

sar -u 1 3 sar -r 1 3

Task: Compare CPU and memory statistics across the reports.

Exercise 8: Monitor Memory Continuously

watch -n 2 free -h

Task: Observe how memory values change while applications are running. Press Ctrl + C to stop.

These exercises are intended for observation. Do not intentionally overload your system or modify storage devices to test monitoring commands.

13. Common Troubleshooting Situations

Situation 1: High Memory Usage

Check memory availability:

free -h top

Look for processes consuming unusually large amounts of memory.

Situation 2: High System Load

Check load average and CPU count:

uptime nproc top

Investigate whether processes are competing for CPU time or waiting for I/O.

Situation 3: High Disk I/O Activity

Check device statistics:

iostat -xz 1 3 vmstat 1 5

Investigate high I/O wait, request latency and storage activity.

Situation 4: High CPU Utilization

Use process and CPU monitoring tools:

top mpstat -P ALL 1 3 ps aux --sort=-%cpu | head

Identify processes consuming significant CPU resources.

14. Interview Questions and Answers

Q1. What is system monitoring in Linux?

Answer: System monitoring is the process of observing CPU, memory, processes, disk I/O and other system resources to evaluate performance and detect problems.

Q2. What is the purpose of the free command?

Answer: It displays RAM and swap memory usage, including total, used, free and available memory.

Q3. What is load average?

Answer: Load average represents the average number of runnable and uninterruptible tasks over 1, 5 and 15 minutes.

Q4. Is load average the same as CPU utilization?

Answer: No. Load average measures system workload, while CPU utilization measures how processor time is being used.

Q5. What is the purpose of vmstat?

Answer: It reports information about processes, memory, swap, I/O, system activity and CPU utilization.

Q6. What is the purpose of iostat?

Answer: It monitors CPU statistics and storage-device input/output activity.

Q7. What is the purpose of mpstat?

Answer: It reports CPU utilization statistics, including individual processor statistics.

Q8. What is sar?

Answer: System Activity Reporter is a tool for collecting and reporting system performance statistics.

Q9. Which package provides iostat and mpstat on Ubuntu?

Answer: The sysstat package.

Q10. What is the purpose of lscpu?

Answer: It displays CPU architecture, processor count, cores, threads and related CPU information.
