LINUX SYSTEM ADMINISTRATION • CHAPTER 9 • LESSON 8

Linux Boot Process

Understand BIOS/UEFI, bootloaders, kernel initialization and system startup

Home Linux Course Chapter 9

Learning Objectives

After completing this lesson, you will be able to:

  • Understand what happens when a Linux computer starts.
  • Explain the roles of BIOS and UEFI firmware.
  • Understand the bootloader and GRUB.
  • Explain Linux kernel loading and initialization.
  • Understand the role of initramfs and the root filesystem.
  • Understand systemd and the startup of services.
  • Inspect boot time, boot logs and system startup information.

1. Introduction to the Linux Boot Process

The Linux boot process is the sequence of operations performed when a computer is switched on or restarted. It prepares the hardware, loads the Linux kernel and starts the user-space environment.

During startup, the computer moves from firmware initialization to operating system initialization and finally to a usable login environment.

Basic Boot Sequence

Power On | v BIOS / UEFI Firmware | v Bootloader (GRUB) | v Linux Kernel | v initramfs / initrd | v Root Filesystem | v systemd (PID 1) | v System Services and Targets | v Login Screen / Terminal
Important: This is a simplified sequence. The exact details depend on the firmware, bootloader configuration, distribution and Linux system setup.

2. Power-On and Hardware Initialization

When the power button is pressed, the computer's processor begins executing firmware instructions stored on the motherboard.

The firmware performs initial hardware checks and prepares the system for booting.

Major Activities

  • Initializes the processor and basic hardware.
  • Checks memory and essential hardware components.
  • Initializes storage devices and other peripherals.
  • Identifies available boot devices.
  • Transfers control to the selected bootloader or boot entry.

3. BIOS and UEFI

BIOS and UEFI are firmware interfaces responsible for initializing hardware and starting the operating system boot process.

BIOS – Basic Input/Output System

BIOS is the traditional firmware interface used by older computers.

  • Performs hardware initialization.
  • Uses a boot-device selection process.
  • Typically loads boot code from a disk's boot sector.
  • Commonly works with MBR-partitioned disks.

UEFI – Unified Extensible Firmware Interface

UEFI is the modern firmware interface used by most current computers.

  • Provides a more flexible boot environment.
  • Supports GPT partitioned disks.
  • Can load EFI applications from an EFI System Partition.
  • Supports Secure Boot on compatible systems.
  • Maintains boot entries and boot order information.

BIOS vs UEFI

BIOSUEFI
Traditional firmware interfaceModern firmware interface
Typically uses legacy boot codeLoads EFI applications
Commonly associated with MBRCommonly associated with GPT
More limited boot environmentMore flexible boot environment
Does not provide UEFI Secure BootCan support Secure Boot

Check Whether Linux Was Booted Using UEFI

ls /sys/firmware/efi
Interpretation:
  • If the directory exists and contains entries, the system was booted using UEFI.
  • If the directory does not exist, the system may have been booted using legacy BIOS mode.

Check UEFI Boot Entries

sudo efibootmgr -v

This command displays UEFI boot entries and boot-order information when the system supports UEFI and the required utility is installed.

efibootmgr may need to be installed separately on Ubuntu. It is not applicable to a system booted in legacy BIOS mode.

4. Bootloader – GRUB

A bootloader is a program that loads the operating system kernel into memory and transfers control to it.

GRUB stands for GRand Unified Bootloader. GRUB 2 is commonly used by Ubuntu and many other Linux distributions.

Functions of GRUB

  • Displays a boot menu when configured to do so.
  • Allows selection between available operating systems or kernels.
  • Loads the Linux kernel.
  • Passes kernel command-line parameters.
  • Can load an initial RAM filesystem image.

Common GRUB Files and Directories

PathPurpose
/boot/grub/Contains GRUB configuration and supporting files on many installations.
/etc/default/grubContains user-configurable GRUB settings.
/etc/grub.d/Contains scripts used to generate the GRUB configuration.
/boot/grub/grub.cfgGenerated GRUB configuration on many Ubuntu installations.

View GRUB Configuration

cat /etc/default/grub

Regenerate GRUB Configuration

sudo update-grub
Do not manually edit the generated /boot/grub/grub.cfg file. Configure GRUB through the appropriate source files and regenerate the configuration using sudo update-grub.

5. Linux Kernel Loading

The Linux kernel is the core component of the operating system. It manages hardware resources and provides essential services to user-space applications.

After the bootloader loads the kernel into memory, the kernel begins its initialization process.

Major Kernel Responsibilities

  • Initializes processor-related functionality.
  • Detects and initializes hardware.
  • Initializes memory management.
  • Initializes device drivers and kernel subsystems.
  • Prepares process scheduling.
  • Mounts the initial root filesystem environment.
  • Starts the first user-space process.

Check the Running Kernel Version

uname -r

Display Detailed Kernel Information

uname -a

View Kernel Messages

dmesg dmesg | less

The dmesg command displays kernel ring-buffer messages, which can help identify hardware initialization and driver-related information.

6. initramfs – Initial RAM Filesystem

initramfs stands for initial RAM filesystem. It is a temporary root filesystem loaded into memory during the early stages of Linux startup.

It provides the tools and drivers needed to prepare the actual root filesystem.

Why Is initramfs Needed?

  • Loads essential storage drivers.
  • Supports storage devices that require additional initialization.
  • Helps identify and prepare the real root filesystem.
  • Supports configurations involving LVM, RAID or encrypted storage when required.
  • Transfers control to the actual root filesystem.

Common initramfs Files

ls /boot

On Ubuntu, you may see files similar to:

vmlinuz-... initrd.img-... config-... System.map-...
FilePurpose
vmlinuzCompressed Linux kernel image.
initrd.imgInitial RAM filesystem image, commonly used for initramfs.
configKernel configuration information.
System.mapKernel symbol address information.
The exact filenames include kernel version numbers and vary between installations.

7. Root Filesystem Mounting

After the initial RAM filesystem has prepared the required devices and storage, the system locates and mounts the actual root filesystem.

The root filesystem is represented by /. It contains the directory hierarchy required by Linux.

Important Activities

  • Identifies the root filesystem using the boot configuration.
  • Prepares the required storage and filesystem components.
  • Mounts the actual root filesystem.
  • Switches from the temporary initial environment to the real root environment.
  • Continues the user-space startup process.

Check the Root Filesystem

findmnt / df -h / ls /
The root filesystem is different from the root user. The root filesystem is the top-level directory of the Linux filesystem hierarchy, whereas the root user is the administrative user account.

8. systemd – The First User-Space Process

After the kernel has initialized the system and prepared the real root environment, it starts the first user-space process. On modern Ubuntu systems, this is normally systemd.

Its process ID is normally PID 1.

Functions of systemd

  • Starts and manages system services.
  • Handles system initialization.
  • Manages service dependencies.
  • Supports system targets.
  • Provides logging integration through journald.
  • Manages system and service states.

Check PID 1

ps -p 1 -o pid,comm,args
Example output:
PID COMMAND COMMAND 1 systemd /sbin/init

Check the Init System

ps -p 1 -o comm=

On a typical Ubuntu installation using systemd, the output is:

systemd

9. Systemd Targets

Systemd uses targets to group units and define system operating states. Targets help determine which services and resources should be started.

Common Systemd Targets

TargetPurpose
poweroff.targetShuts down the system.
rescue.targetStarts a basic rescue environment.
multi-user.targetStarts a multi-user, non-graphical environment.
graphical.targetStarts a graphical login environment along with multi-user services.
reboot.targetRestarts the system.

Check the Default Target

systemctl get-default

List Active Targets

systemctl list-units --type=target

Set the Default Target

sudo systemctl set-default multi-user.target

To set the graphical target as default:

sudo systemctl set-default graphical.target
Changing the default target affects how the system starts after reboot. Perform this only when you understand the effect. The commands above change the default; they do not immediately change the current session.

10. Linux Boot Logs and Diagnostics

Linux provides several commands for inspecting boot-related messages and identifying startup problems.

journalctl -b

Displays logs from the current boot.

journalctl -b

View Previous Boot Logs

journalctl -b -1

Displays logs from the previous boot, if those logs are available and retained.

View Kernel Messages from Current Boot

journalctl -k -b

View Boot Errors

journalctl -b -p err

View Failed Services

systemctl --failed

View Boot Time Analysis

systemd-analyze

View Service Startup Time

systemd-analyze blame

View Critical Boot Chain

systemd-analyze critical-chain
systemd-analyze blame reports the time units spent activating, but it does not necessarily show the complete critical path. Use critical-chain to inspect important startup dependencies.

11. Common Linux Boot Problems

Problem 1: GRUB Menu Does Not Appear

Possible causes:

  • Incorrect bootloader configuration.
  • Firmware boot-order problems.
  • Bootloader installation issues.

Possible investigation: inspect UEFI boot entries when applicable and review GRUB configuration from a recovery environment.

Problem 2: Kernel Panic

A kernel panic is a serious error from which the kernel cannot safely continue normal operation.

Possible causes include kernel bugs, incompatible drivers, hardware failures or filesystem-related problems.

Problem 3: Emergency Mode

Linux may enter emergency mode when a critical startup requirement fails, such as a required filesystem mount.

Investigate using:

journalctl -xb systemctl --failed findmnt --verify

Problem 4: A Service Fails During Startup

Inspect failed services and their logs:

systemctl --failed systemctl status service-name journalctl -u service-name -b
Do not randomly edit GRUB settings, delete boot files or change filesystem configuration to fix startup problems. First identify the actual error and keep a recovery option available.

13. Interview Questions and Answers

Q1. What is the Linux boot process?

Answer: It is the sequence of operations that initializes hardware, loads the bootloader and kernel, prepares the root filesystem and starts user-space services.

Q2. What is BIOS?

Answer: BIOS is traditional firmware that initializes computer hardware and starts the boot process.

Q3. What is UEFI?

Answer: UEFI is a modern firmware interface that initializes hardware and loads EFI applications, including bootloaders.

Q4. What is GRUB?

Answer: GRUB is a bootloader commonly used by Linux distributions to load the Linux kernel and pass boot parameters.

Q5. What is the Linux kernel?

Answer: The kernel is the core of the operating system. It manages CPU scheduling, memory, hardware, device drivers and system resources.

Q6. What is initramfs?

Answer: It is an initial RAM filesystem used during early startup to provide tools and drivers needed to prepare the real root filesystem.

Q7. What is systemd?

Answer: Systemd is an initialization and service-management system used by many modern Linux distributions.

Q8. What is PID 1?

Answer: PID 1 is the first user-space process started by the kernel. On a typical Ubuntu system, it is systemd.

Q9. What is the purpose of journalctl?

Answer: It is used to view and filter logs collected by the systemd journal.

Q10. What is the purpose of systemd-analyze?

Answer: It analyzes system startup performance and helps identify service activation times and critical boot dependencies.

15. Lesson Summary

  • The Linux boot process begins when the computer is powered on.
  • BIOS or UEFI initializes hardware and starts the boot process.
  • GRUB loads the Linux kernel and passes boot parameters.
  • The kernel initializes hardware, memory and other subsystems.
  • initramfs prepares the environment required to mount the real root filesystem.
  • The kernel starts the first user-space process, normally systemd on Ubuntu.
  • Systemd starts services and reaches the configured system target.
  • journalctl and systemd-analyze help investigate boot logs and startup performance.
Practical Skill:

You should be able to explain the Linux boot sequence and use basic commands to inspect the kernel, boot files, systemd, startup logs and failed services.
