Linux Services and systemctl

Manage system services, service states, startup configuration and systemd units

Home Linux Course Chapter 9

Learning Objectives

After completing this lesson, you will be able to:

  • Understand Linux services and background processes.
  • Understand systemd and systemd units.
  • Use systemctl to start, stop and restart services.
  • Enable and disable services at system startup.
  • Check service status and identify failed services.
  • Understand service dependencies and targets.
  • Inspect service logs using journalctl.
  • Perform basic service troubleshooting.

1. Introduction to Linux Services

A Linux service is a program or background process that provides a particular function to the operating system or other applications.

Services commonly run without requiring continuous interaction from the user.

Examples of Linux Services

ServicePurpose
SSHProvides secure remote login and command execution.
CronRuns scheduled tasks.
ApacheProvides web server functionality.
NetworkManagerManages network connections.
BluetoothManages Bluetooth functionality.
systemd-journaldCollects system and service logs.

Characteristics of Services

  • They can run in the background.
  • They provide functionality to users or applications.
  • They may start automatically during system startup.
  • They can be controlled by service-management tools.
  • They may depend on other services or system resources.
Example:

An SSH service allows a user to connect to a Linux computer remotely using an SSH client.

2. What Is systemd?

systemd is a system and service manager used by many modern Linux distributions, including Ubuntu.

It normally runs as the first user-space process with process ID 1.

Main Responsibilities of systemd

  • Starts system services during boot.
  • Manages running services.
  • Handles service dependencies.
  • Controls system targets.
  • Monitors and manages service processes.
  • Supports socket, timer, mount and other units.

Check Whether systemd Is PID 1

ps -p 1 -o pid,comm,args

Check systemd Version

systemctl --version
On a typical Ubuntu installation, PID 1 is systemd.

3. Introduction to systemctl

systemctl is the command-line utility used to communicate with the systemd system and service manager.

Syntax

systemctl [OPTIONS] COMMAND [UNIT]

Here:

  • OPTIONS: Optional command-line settings.
  • COMMAND: The operation to perform.
  • UNIT: The service or other systemd unit to manage.

Common systemctl Commands

CommandPurpose
systemctl statusDisplays overall system or manager status.
systemctl list-unitsLists units currently loaded by systemd.
systemctl list-unit-filesLists installed unit files and their enablement states.
systemctl --failedLists failed units.
systemctl daemon-reloadReloads systemd unit configuration files.

4. Checking Service Status

The status command displays information about a service, including whether it is active, inactive or failed.

Syntax

systemctl status service-name

Example

systemctl status cron

Possible Service States

StateMeaning
active (running)The service is running.
active (exited)The unit completed its startup action and remains active according to its unit configuration, although its process may have exited.
inactive (dead)The service is not currently active.
failedThe service encountered an error or failed to start.
activatingThe service is in the process of starting.
deactivatingThe service is in the process of stopping.

Check Only the Active State

systemctl is-active cron

Check Whether a Service Is Enabled

systemctl is-enabled cron
A service being active and being enabled are different conditions. Active describes its current runtime state; enabled describes whether it is configured to start automatically through the relevant startup dependencies.

5. Starting a Service

The start command starts a service immediately.

Syntax

sudo systemctl start service-name

Example

sudo systemctl start cron

Verify the Service

systemctl status cron systemctl is-active cron
Explanation:

Starting a service changes its current runtime state. It does not necessarily configure the service to start automatically after a future reboot.

6. Stopping a Service

The stop command stops a currently running service.

Syntax

sudo systemctl stop service-name

Example

sudo systemctl stop cron

Verify

systemctl status cron
Stopping an important service can interrupt system functionality. Do not stop services such as networking, storage or remote-access services unless you understand the consequences.

7. Restarting a Service

The restart command stops and starts a service again.

Syntax

sudo systemctl restart service-name

Example

sudo systemctl restart cron

When Is Restart Used?

  • After changing certain service configuration files.
  • When a service needs to be restarted to recover from an issue.
  • When an application requires a fresh service process.

8. Reloading a Service

The reload command asks a service to reload its configuration without performing a full service restart, if that service supports reloading.

Syntax

sudo systemctl reload service-name

Restart vs Reload

restartreload
Stops and starts the service again.Requests configuration reload without a full restart.
May interrupt existing connections.May avoid interruption, depending on the service.
Generally supported by service units.Only works when the service supports reload.

Reload Example

sudo systemctl reload apache2
This example requires Apache to be installed and its service unit to support reload. If the service does not support reload, systemctl reports an error.

9. Enabling a Service at Startup

The enable command configures a service to start automatically through its systemd startup dependencies.

Syntax

sudo systemctl enable service-name

Example

sudo systemctl enable cron

Enable and Start Immediately

sudo systemctl enable --now cron

The --now option also starts the service immediately.

Check Enablement State

systemctl is-enabled cron
Remember:
  • start – Starts the service now.
  • enable – Configures automatic startup.
  • enable --now – Enables and starts the service.

10. Disabling a Service at Startup

The disable command removes the service's automatic-start configuration from the relevant systemd startup dependencies.

Syntax

sudo systemctl disable service-name

Example

sudo systemctl disable cron

Disable and Stop Immediately

sudo systemctl disable --now cron

The --now option also stops the service immediately.

Disabling a service does not necessarily stop it immediately. Use disable --now when both actions are intended.

11. Masking and Unmasking Services

Masking a service prevents it from being started manually or automatically through normal systemd activation. It is stronger than disabling a service.

Mask a Service

sudo systemctl mask service-name

Unmask a Service

sudo systemctl unmask service-name

Example

sudo systemctl mask example.service sudo systemctl unmask example.service
OperationMeaning
DisableRemoves automatic-start links created by enablement.
MaskPrevents normal activation by linking the unit to /dev/null.
UnmaskRemoves the mask and allows normal activation again.
Masking critical system services can make a system unusable or prevent important functionality. Use masking only when you understand the service and its dependencies.

12. Listing Services

Systemd provides commands for listing loaded service units and installed service unit files.

List Loaded Service Units

systemctl list-units --type=service

List Running Services

systemctl list-units --type=service --state=running

List Installed Service Unit Files

systemctl list-unit-files --type=service

List Failed Units

systemctl --failed
list-units displays units currently loaded into systemd's manager. list-unit-files displays installed unit files and their enablement states. These lists are not identical.

13. Understanding Systemd Unit Files

A systemd unit file describes a resource or object managed by systemd. It defines configuration, dependencies and behavior.

Common Systemd Unit Types

ExtensionPurpose
.serviceManages a service or process.
.socketManages a socket for communication or activation.
.targetGroups units to represent a system state.
.mountManages a filesystem mount point.
.automountManages automatic activation of a mount.
.timerSchedules activation of units.
.pathActivates units when specified filesystem paths change.
.sliceGroups processes for resource management.
.scopeManages externally created process groups.

Common Locations of Unit Files

DirectoryPurpose
/usr/lib/systemd/system/Vendor-provided unit files on many distributions.
/lib/systemd/system/Vendor-provided unit files on some systems, including systems using merged directories.
/etc/systemd/system/System administrator configuration and local unit files.

Inspect a Service Unit

systemctl cat cron

Display Unit Properties

systemctl show cron

Show the Unit File Path

systemctl show -p FragmentPath cron

14. Basic Structure of a Service Unit File

A systemd service unit file commonly contains sections such as [Unit], [Service] and [Install].

Example Service Unit

[Unit] Description=My Example Service After=network.target [Service] Type=simple ExecStart=/usr/bin/sleep infinity Restart=on-failure [Install] WantedBy=multi-user.target

Explanation of Sections

SectionPurpose
[Unit]Contains description and dependency relationships.
[Service]Defines how the service process is started and managed.
[Install]Defines how the unit is connected to startup targets when enabled.

Important Directives

DirectivePurpose
DescriptionProvides a human-readable description.
AfterDefines ordering relative to another unit.
WantsDefines a weaker dependency relationship.
RequiresDefines a stronger dependency relationship.
TypeDefines how systemd determines service startup completion.
ExecStartSpecifies the command used to start the service.
RestartDefines restart behavior.
WantedByDefines the target relationship used when enabling the unit.
After=network.target establishes ordering; it does not by itself require or start the network target. Dependency directives such as Wants= and Requires= serve different purposes.

15. Creating a Simple Custom Service

In this exercise, you will create a simple systemd service that runs the sleep command. This is a demonstration of service management, not a production application.

Step 1: Create the Service File

sudo nano /etc/systemd/system/my-example.service

Step 2: Add This Configuration

[Unit] Description=My Example Linux Service [Service] Type=simple ExecStart=/usr/bin/sleep infinity Restart=on-failure [Install] WantedBy=multi-user.target

Step 3: Reload systemd Configuration

sudo systemctl daemon-reload

Step 4: Start the Service

sudo systemctl start my-example.service

Step 5: Check Its Status

systemctl status my-example.service

Step 6: Enable It at Startup

sudo systemctl enable my-example.service

Step 7: Stop and Disable It

sudo systemctl disable --now my-example.service

Step 8: Remove the Demonstration Service

sudo rm /etc/systemd/system/my-example.service sudo systemctl daemon-reload
Follow the steps in order. This demonstration creates a system-wide service file and requires administrator privileges. Remove the demonstration service after completing the exercise.

16. Viewing Service Logs

Systemd integrates with the journal logging system. The journalctl command is used to inspect service-related logs.

View All Current Boot Logs

journalctl -b

View Logs for a Particular Service

journalctl -u cron

View Current Boot Logs for a Service

journalctl -u cron -b

Follow Service Logs in Real Time

journalctl -u cron -f

View Recent Logs

journalctl -u cron -n 50

View Logs Since a Specific Time

journalctl -u cron --since "1 hour ago"

Press q to exit the journal pager, or Ctrl + C to stop following logs.

17. Troubleshooting Services

Problem 1: Service Fails to Start

Check its current status:

systemctl status service-name

Inspect its logs:

journalctl -u service-name -b

Problem 2: Service Is Not Found

List matching unit files:

systemctl list-unit-files --type=service | grep service-name

Check whether the application or service package is installed.

Problem 3: Service Is Masked

Inspect its state:

systemctl status service-name systemctl is-enabled service-name

If appropriate, remove the mask:

sudo systemctl unmask service-name

Problem 4: Changes to a Unit File Are Not Applied

Reload systemd configuration:

sudo systemctl daemon-reload

Then restart the service if required:

sudo systemctl restart service-name

Problem 5: A Service Is Enabled but Not Running

Check both properties:

systemctl is-enabled service-name systemctl is-active service-name systemctl status service-name

Remember that enabled does not mean currently running.

19. Interview Questions and Answers

Q1. What is a Linux service?

Answer: A Linux service is a program or background process that provides a particular function to the operating system or applications.

Q2. What is systemd?

Answer: systemd is a system and service manager responsible for system initialization and management of services and other units.

Q3. What is systemctl?

Answer: It is a command-line utility used to manage systemd units and services.

Q4. What is the difference between start and enable?

Answer: Start runs a service immediately, whereas enable configures it to start automatically through the relevant startup dependencies.

Q5. What is the difference between restart and reload?

Answer: Restart stops and starts a service again. Reload asks the service to reload its configuration without a full restart, if supported.

Q6. What is the difference between disable and mask?

Answer: Disable removes automatic-start links created by enablement. Mask prevents normal activation of the unit.

Q7. How do you check a service status?

Answer: Use systemctl status service-name.

Q8. How do you list failed services?

Answer: Use systemctl --failed.

Q9. What is daemon-reload?

Answer: It makes systemd reload unit configuration files after changes have been made.

Q10. How do you view service logs?

Answer: Use journalctl -u service-name.

21. Lesson Summary

  • Linux services provide background functionality to the operating system and applications.
  • systemd manages system startup, services and other units.
  • systemctl is the command-line tool for managing systemd.
  • start, stop, restart and reload control runtime service behavior.
  • enable and disable configure automatic startup.
  • mask prevents normal service activation.
  • Unit files define service configuration and dependencies.
  • journalctl helps inspect service logs.
  • systemctl --failed identifies failed units.
Practical Skill:

You should be able to inspect, start, stop, restart, enable and troubleshoot Linux services using systemctl.
