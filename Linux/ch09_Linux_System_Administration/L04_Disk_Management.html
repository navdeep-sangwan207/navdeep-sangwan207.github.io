Disk Management

Understanding Disks, Partitions and Storage Utilization in Linux

  • Understand disk names and partition naming.

1. Introduction to Disk Management

Disk management is the process of identifying, organizing, partitioning, formatting and monitoring storage devices in a computer system.

Linux provides several command-line utilities for managing storage devices, partitions and filesystems.

Why is disk management important?

  • Identify connected storage devices.
  • Organize storage into partitions.
  • Create filesystems for storing data.
  • Monitor available and used disk space.
  • Identify storage-capacity problems.
  • Manage additional hard disks and SSDs.
  • Prepare storage devices for mounting.
Example: A computer may contain an SSD for the operating system and another storage device for documents, applications and backup files.

2. Types of Storage Devices

Device Description
HDD Hard Disk Drive that stores data on rotating magnetic disks.
SSD Solid State Drive that uses flash memory for data storage.
USB Drive Portable flash storage connected through a USB interface.
NVMe SSD High-speed solid-state storage using the NVMe protocol, commonly over PCIe.
Virtual Disk A storage device presented by virtualization software.

Common storage interfaces

  • SATA
  • NVMe
  • USB
  • SCSI
  • VirtIO for virtual machines
Linux can manage both physical storage devices and virtual disks. The device names depend on the storage controller and driver.

3. Linux Disk Device Naming

Linux represents storage devices as special device files inside the /dev directory.

Common device names

Device name Description
/dev/sda First disk commonly detected through the SCSI disk driver interface.
/dev/sdb Second disk using the same naming scheme.
/dev/sda1 First partition of /dev/sda.
/dev/sda2 Second partition of /dev/sda.
/dev/nvme0n1 First NVMe namespace on the first NVMe controller.
/dev/nvme0n1p1 First partition of that NVMe namespace.
/dev/vda First virtual disk commonly presented through VirtIO.

View device files

ls /dev/sd*

For NVMe devices:

ls /dev/nvme*
Not every Linux system uses /dev/sda. Device naming depends on the storage hardware, controller and drivers.

4. Understanding Disk Partitions

A partition is a logically defined section of a physical storage device.

A single disk can contain multiple partitions. Each partition can be used for a filesystem, swap space or another storage purpose.

Example disk layout

Physical Disk: /dev/sda | |-- /dev/sda1 → EFI System Partition |-- /dev/sda2 → Linux filesystem |-- /dev/sda3 → Swap partition (if configured)

This is an illustrative layout. Actual systems may use different partition arrangements.

Common partition purposes

Partition Purpose
EFI System Partition Stores boot files used by UEFI firmware.
Root partition (/) Contains the main Linux filesystem hierarchy.
Home partition (/home) Stores user files and personal data when configured separately.
Swap partition Provides disk-backed swap space.
Data partition Stores additional application or user data.

5. MBR and GPT Partition Tables

A partition table stores information about the partitions present on a disk.

MBR (Master Boot Record)

  • Traditional partitioning scheme.
  • Uses a partition table stored in the first sector.
  • Supports up to four primary partition entries.
  • Extended and logical partitions can be used to create additional partitions.
  • Has practical disk-size limitations around 2 TiB with conventional 512-byte logical sectors.

GPT (GUID Partition Table)

  • Modern partitioning scheme.
  • Supports large storage devices.
  • Supports many partitions, depending on implementation.
  • Stores redundant partition-table information.
  • Commonly used with UEFI-based systems.
MBR GPT
Older partitioning standard. Modern partitioning standard.
Four primary partition entries. Supports many partitions.
Limited conventional disk addressing. Supports very large disks.
Has no equivalent redundant partition-table arrangement. Stores primary and backup partition-table structures.
GPT is generally preferred for modern computers and large-capacity storage devices.

6. Viewing Disks Using lsblk

The lsblk command displays information about block devices such as hard disks, SSDs and partitions.

Basic syntax

lsblk

Typical output

NAME   MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   100G  0 disk
├─sda1   8:1    0   512M  0 part /boot/efi
└─sda2   8:2    0  99.5G  0 part /
sr0     11:0    1  1024M  0 rom
Illustrative output; device names and sizes vary.

Important columns

Column Meaning
NAME Block device name.
MAJ:MIN Major and minor device numbers.
RM Removable device indicator.
SIZE Device or partition size.
RO Read-only indicator.
TYPE Device type, such as disk, part or rom.
MOUNTPOINTS Mount locations associated with the device.

Display filesystem information

lsblk -f

This displays filesystem types, labels, UUIDs and mount points where available.

Display selected columns

lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

7. Viewing Disk Information Using fdisk

fdisk is a command-line utility used to inspect and manage disk partition tables.

Display partition information

sudo fdisk -l

The -l option lists detected disks and their partition information.

Inspect a particular disk

sudo fdisk -l /dev/sda

Replace /dev/sda with the actual disk device name on your system.

Important fdisk operations

Command Purpose
fdisk -l List disk and partition information.
fdisk /dev/sda Open the interactive partition editor for a disk.
m Display help inside the interactive utility.
p Print the partition table.
n Create a new partition.
d Delete a partition.
w Write changes to disk and exit.
q Quit without saving changes.
The interactive fdisk commands can modify the partition table. Do not use n, d or w on your main system disk during practice. Start with inspection commands only.

8. Monitoring Disk Space Using df

The df command displays available and used space on mounted filesystems.

Basic syntax

df

Human-readable output

df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        99G   35G   59G  38% /
tmpfs           2.0G  1.2M  2.0G   1% /run
Illustrative output; actual usage depends on your system.

Important columns

Column Description
Filesystem Filesystem or storage source.
Size Total filesystem size.
Used Space currently used.
Avail Available space.
Use% Percentage of space used.
Mounted on Filesystem mount point.

Display filesystem types

df -Th

Check a particular directory's filesystem

df -h /home
Important: df reports filesystem space, not the total size of individual files or directories.

9. Checking Directory Sizes Using du

The du command estimates the disk space used by files and directories.

Basic syntax

du directory-name

Display sizes in human-readable format

du -h

Display total size of a directory

du -sh /home

The -s option displays a summary, while -h displays sizes in readable units.

Display sizes of immediate subdirectories

du -h --max-depth=1 /home

Check the current directory size

du -sh .
Example output: 
4.2G    /home
Example only; actual directory size varies.

Difference between df and du

df du
Reports filesystem space usage. Estimates space used by files and directories.
Useful for checking available disk space. Useful for identifying large directories.
Works with mounted filesystems. Examines directory contents.

10. Viewing Disk Usage with ncdu

ncdu stands for NCurses Disk Usage. It is an interactive terminal-based disk-usage analyzer.

Install ncdu

sudo apt update sudo apt install ncdu

Analyze the home directory

ncdu /home

It displays directories and files in an interactive interface, making large storage consumers easier to identify.

ncdu is an optional utility. You can perform basic disk-usage analysis using du without installing it.

11. Formatting a Disk and Creating a Filesystem

Before a partition can normally be used to store files, it needs a filesystem. Creating a filesystem is commonly called formatting.

Common Linux filesystems

Filesystem Description
ext4 Widely used Linux journaling filesystem.
ext3 Older Linux journaling filesystem.
ext2 Older Linux filesystem without journaling.
XFS High-performance journaling filesystem.
Btrfs Modern copy-on-write filesystem with advanced features.
FAT32 Common filesystem for removable storage devices.
NTFS Filesystem commonly used by Windows.

Example: Create an ext4 filesystem

sudo mkfs.ext4 /dev/sdb1

This command creates an ext4 filesystem on the specified partition.

Critical safety warning: mkfs.ext4 can destroy existing filesystem structures and make existing data inaccessible. Never run it on your main system partition or an unknown device. Verify the exact device name, back up important data and use a disposable virtual disk for practice.

12. Understanding Storage in VirtualBox

When Ubuntu runs inside VirtualBox, it normally sees a virtual hard disk rather than directly managing your computer's physical SSD.

The virtual disk is presented to the guest operating system as a block device.

Inspect the virtual disk

lsblk df -h sudo fdisk -l

Virtual disk storage formats

Format Description
VDI VirtualBox native virtual disk format.
VHD Virtual hard disk format.
VMDK Virtual disk format commonly associated with VMware.
For your Ubuntu VirtualBox environment, use lsblk, df and du to practise disk inspection without modifying the physical SSD of your Windows laptop.

13. Important Disk Management Commands

Command Purpose
lsblk Display block devices and partitions.
lsblk -f Display filesystem information.
sudo fdisk -l List disks and partition tables.
df -h Display filesystem space in readable units.
df -Th Display filesystem types and usage.
du -sh directory Display total directory size.
du -h --max-depth=1 directory Display immediate subdirectory sizes.
sudo blkid Display block device filesystem types and UUIDs.
findmnt Display mounted filesystems.
sudo parted -l List disks and partition information using parted.
sudo mkfs.ext4 device Create an ext4 filesystem on a specified device.

15. Interview Questions and Answers

Q1. What is disk management in Linux?

Disk management involves identifying, partitioning, formatting, mounting and monitoring storage devices.

Q2. What is a block device?

A block device stores and transfers data in fixed-size blocks. Hard disks, SSDs and many virtual disks are examples.

Q3. What is a partition?

A partition is a logically defined section of a storage device.

Q4. What is the difference between MBR and GPT?

MBR is an older partitioning scheme with practical addressing limitations. GPT is a modern scheme that supports large disks and redundant partition-table structures.

Q5. What is the purpose of lsblk?

It displays block devices, partitions, sizes and mount-point information.

Q6. What is the purpose of fdisk?

fdisk is used to inspect and manage disk partition tables.

Q7. What is the difference between df and du?

df displays filesystem space usage, whereas du estimates disk usage by files and directories.

Q8. What is a filesystem?

A filesystem is a method of organizing and managing data stored on a storage device.

Q9. What is mkfs.ext4?

It creates an ext4 filesystem on a specified block device or partition.

Q10. What is a UUID?

A UUID is a unique identifier used to identify a filesystem or other system object.

Q11. What is an EFI System Partition?

It is a special partition containing boot files used by UEFI firmware.

Q12. What is the purpose of findmnt?

It displays information about mounted filesystems and their mount points.

17. Lesson Summary

  • Disk management organizes and monitors storage devices.
  • Linux represents block devices through device files.
  • Partitions divide a storage device into logical sections.
  • MBR and GPT are partition-table schemes.
  • lsblk displays block devices and partitions.
  • fdisk -l lists disk and partition information.
  • df -h displays available filesystem space.
  • du -sh displays directory disk usage.
  • mkfs.ext4 creates an ext4 filesystem.
  • blkid displays filesystem identifiers.
  • findmnt displays mounted filesystems.
  • Disk formatting and partition modification can destroy data.
Practical recommendation: First become comfortable with lsblk, df, du, fdisk -l and findmnt. These inspection commands provide the foundation for safe Linux storage administration.
