Mounting and Unmounting in Linux

Understanding how Linux accesses storage devices and filesystems

Home Linux Course Chapter 9

Learning Objectives

After completing this lesson, you will be able to:

  • Understand mounting and unmounting in Linux.
  • Explain mount points and filesystem access.
  • Identify storage devices and partitions.
  • Use the mount and umount commands.
  • View currently mounted filesystems.
  • Understand the purpose of /etc/fstab.
  • Mount and unmount a USB drive or virtual disk safely.

1. Introduction to Mounting

Linux uses a single directory hierarchy that begins at the root directory /. Storage devices such as hard disks, partitions, USB drives and virtual disks must be connected to this directory hierarchy before their files can be accessed through the normal filesystem.

This process is called mounting.

Mounting: Attaching a filesystem to a directory in the Linux directory hierarchy so that its contents can be accessed.

For example, a USB drive may be mounted at /mnt/usb. After mounting, its files can be accessed through that directory.

2. What Is a Mount Point?

A mount point is an existing directory where another filesystem is attached.

Common mount point directories include:

Mount Point Purpose
/mnt Common location for temporary manual mounts.
/media Common location for removable media mounted by desktop systems.
/home May be a separate filesystem containing user directories.
/boot May be a separate filesystem containing boot files.

Example

sudo mkdir -p /mnt/usb

This command creates a directory that can be used as a mount point. The -p option creates missing parent directories and does not report an error if the directory already exists.

A mount point is a directory, not the storage device itself. The device provides the filesystem; the mount point provides its location in the directory hierarchy.

3. What Is Unmounting?

Unmounting means detaching a mounted filesystem from the Linux directory hierarchy.

After unmounting, the filesystem is no longer accessible through that mount point until it is mounted again.

Always unmount removable storage before physically disconnecting it. This helps ensure that pending write operations are completed.

4. Understanding Linux Storage Device Names

Linux represents storage devices using special device files, commonly found under the /dev directory.

Device Name Description
/dev/sda First detected SATA/SCSI-style disk.
/dev/sda1 First partition on that disk.
/dev/sda2 Second partition on that disk.
/dev/sdb Another detected disk.
/dev/nvme0n1 First NVMe storage device.
/dev/nvme0n1p1 First partition on that NVMe device.

Display Block Devices

lsblk
Example output: 
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   40G  0 disk
├─sda1   8:1    0   39G  0 part /
└─sda2   8:2    0    1G  0 part [SWAP]
sdb      8:16   1    8G  0 disk
└─sdb1   8:17   1    8G  0 part

This is illustrative output. Actual device names, sizes and mount points depend on the system.

  • disk indicates a whole storage device.
  • part indicates a partition.
  • RM indicates whether the device is removable.
  • MOUNTPOINTS shows where a filesystem is mounted.

5. The mount Command

The mount command attaches a filesystem to a specified directory.

Syntax

sudo mount [options] DEVICE MOUNT_POINT

Example:

sudo mount /dev/sdb1 /mnt/usb

Explanation:

  • sudo runs the command with administrative privileges.
  • mount is the mounting command.
  • /dev/sdb1 represents the partition to mount.
  • /mnt/usb is the mount point.
The device name /dev/sdb1 is only an example. Always identify the correct device using lsblk before mounting.

Mount a Filesystem with a Specific Type

sudo mount -t ext4 /dev/sdb1 /mnt/usb

The -t option specifies the filesystem type. Here, ext4 is used as the filesystem type.

Mount a Filesystem as Read-Only

sudo mount -o ro /dev/sdb1 /mnt/usb

The -o ro option requests a read-only mount. Files cannot normally be modified through this mount.

Mount with Multiple Options

sudo mount -o ro,noexec /dev/sdb1 /mnt/usb

This example requests a read-only mount and prevents execution of programs from that mounted filesystem.

6. View Mounted Filesystems

Command 1: mount

mount

Displays mounted filesystems and their mount options.

Command 2: findmnt

findmnt

Displays mounted filesystems in a tree-like format.

Command 3: df -h

df -h

Displays filesystem disk-space usage in human-readable units.

Check a Specific Mount Point

findmnt /mnt/usb

Displays information about the filesystem mounted at /mnt/usb, if one is mounted there.

7. The umount Command

The umount command detaches a mounted filesystem. Notice that the command is spelled umount, not unmount.

Syntax

sudo umount DEVICE_OR_MOUNT_POINT

Unmount Using the Mount Point

sudo umount /mnt/usb

Unmount Using the Device Name

sudo umount /dev/sdb1

Both approaches can be used to identify the mounted filesystem. Using the mount point is often convenient.

Do not disconnect a USB drive while it is mounted and in use. Unmount it first and wait for the command to complete.

8. Understanding Busy Filesystems

Sometimes Linux refuses to unmount a filesystem because it is currently being used by a process.

Example error:

umount: /mnt/usb: target is busy.

Possible reasons include:

  • A terminal is currently working inside the mount point.
  • A file stored on the filesystem is open.
  • A program is accessing files on the filesystem.
  • A process is using the mount point as its current directory.

Find Processes Using the Mount Point

sudo fuser -vm /mnt/usb

This displays processes using the specified mount point.

Alternative: lsof

sudo lsof +f -- /mnt/usb

Lists open files associated with the specified filesystem path. The command may not be installed by default.

Resolve the Problem

  1. Close files and applications accessing the filesystem.
  2. Move the terminal outside the mount point.
  3. Check for remaining processes using fuser.
  4. Try the normal umount command again.
cd ~ sudo umount /mnt/usb
Avoid forceful or lazy unmounting as a routine solution. These options can create problems if applications are still using the filesystem.

9. Automatic Mounting with /etc/fstab

Linux uses the /etc/fstab file to define filesystems that should be mounted automatically or made available through the system's filesystem configuration.

The name fstab means filesystem table.

View the File

cat /etc/fstab

Common Fields in /etc/fstab

Field Meaning
Filesystem Device, UUID or other filesystem source.
Mount Point Directory where the filesystem is mounted.
Type Filesystem type, such as ext4 or vfat.
Options Mounting options such as defaults or noauto.
Dump Backup utility field, commonly set to 0.
Pass Filesystem check order used by fsck.

Example Entry

UUID=1234-abcd /mnt/data ext4 defaults 0 2

This is an illustrative entry. The UUID and filesystem type must match the actual storage device.

Find a Filesystem UUID

sudo blkid

The blkid command displays filesystem information, including UUIDs for detected block devices.

Test fstab Entries

sudo mount -a

Attempts to mount filesystems configured in /etc/fstab that are not already mounted, subject to their options.

Incorrect entries in /etc/fstab can cause boot or mounting problems. Back up the file before editing it. Verify device UUIDs and test changes carefully.

10. Important Mount Options

Option Purpose
defaults Uses a standard set of default mount options.
ro Mounts the filesystem read-only.
rw Requests read-write access.
noexec Prevents execution of programs from the filesystem.
nosuid Disables set-user-ID and set-group-ID effects.
nodev Prevents interpretation of device special files.
noauto Prevents automatic mounting by mount -a.
user Allows a user to mount the filesystem under the applicable mount rules.

11. Practical Example: Mounting a USB Drive

Follow this general workflow when working with a USB drive.

Step 1: Identify the Device

lsblk -f

Identify the correct USB partition and its filesystem type.

Step 2: Create a Mount Point

sudo mkdir -p /mnt/usb

Step 3: Mount the Partition

sudo mount /dev/sdb1 /mnt/usb

Replace /dev/sdb1 with the actual partition identified on your system.

Step 4: Verify the Mount

findmnt /mnt/usb df -h /mnt/usb

Step 5: Access the Files

ls -la /mnt/usb

Step 6: Unmount the USB Drive

cd ~ sudo umount /mnt/usb

Step 7: Verify Unmounting

findmnt /mnt/usb

If the filesystem is no longer mounted there, the command will not show a mounted filesystem for that path.

Command Purpose

14. Common Errors and Troubleshooting

Error or Problem Possible Cause Suggested Action
Mount point does not exist The target directory is missing. Create it using mkdir -p.
Special device does not exist The device name is incorrect or unavailable. Check lsblk.
Wrong filesystem type The specified filesystem type does not match the device. Check with lsblk -f or blkid.
Permission denied Administrative privileges may be required. Use sudo where appropriate.
Target is busy A process is accessing the filesystem. Check with fuser and close the applications.
Read-only filesystem The filesystem is mounted read-only or has entered a protective state. Inspect mount options and filesystem health.

15. Interview Questions and Answers

Q1. What is mounting in Linux?

Mounting is the process of attaching a filesystem to a directory in the Linux directory hierarchy so that its files can be accessed.

Q2. What is a mount point?

A mount point is a directory where a filesystem is attached.

Q3. Which command is used to mount a filesystem?

The mount command is used.

Q4. Which command is used to unmount a filesystem?

The umount command is used.

Q5. What is the purpose of /etc/fstab?

It stores filesystem configuration entries used for mounting filesystems, including automatic mounts.

Q6. What is the difference between mount and umount?

mount attaches a filesystem to the directory hierarchy, whereas umount detaches it.

Q7. How can you list mounted filesystems?

Commands include mount, findmnt and df -h. They display different aspects of mounted filesystem information.

Q8. Why should a USB drive be unmounted before removal?

Unmounting helps complete pending write operations and reduces the risk of data loss or filesystem corruption.

Q9. What does a busy filesystem mean?

It means one or more processes are using the filesystem, preventing a normal unmount operation.

Q10. What is the purpose of the UUID?

A UUID is a unique identifier for a filesystem. It can be used in configuration files such as /etc/fstab instead of relying on a device name that may change.

17. Lesson Summary

  • Mounting attaches a filesystem to the Linux directory hierarchy.
  • A mount point is the directory where a filesystem is attached.
  • The mount command mounts filesystems.
  • The umount command detaches filesystems.
  • lsblk helps identify disks and partitions.
  • findmnt displays mounted filesystem information.
  • /etc/fstab stores filesystem mount configuration.
  • Unmount removable storage before physically disconnecting it.
  • Use UUIDs when stable filesystem identification is required.
Key Concept: Linux must mount a filesystem before its contents can be accessed through the normal directory hierarchy. Unmounting safely detaches that filesystem.
