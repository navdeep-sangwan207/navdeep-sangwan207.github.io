Logs and Log Management in Linux

Understand system logs, log files, journalctl, troubleshooting and log rotation

Home Linux Course Chapter 9

Learning Objectives

After completing this lesson, you will be able to:

  • Understand logging and its importance in Linux.
  • Identify common Linux log directories and files.
  • View and monitor log files using command-line tools.
  • Use journalctl to inspect systemd journal logs.
  • Filter logs by time, service and priority.
  • Understand rsyslog and system logging.
  • Understand log rotation using logrotate.
  • Use logs to troubleshoot Linux system problems.

1. Introduction to Linux Logging

Logging is the process of recording events and activities that occur in an operating system or application.

Linux records information about system operations, application activity, errors, warnings, authentication attempts and other important events.

Why Are Logs Important?

  • Troubleshooting: Help identify the cause of system and application errors.
  • Security: Record authentication attempts and other security-related events.
  • Monitoring: Help administrators observe system activity.
  • Auditing: Provide records that can support investigation and compliance.
  • Performance analysis: Help investigate service failures and system behavior.
Example:

If an SSH login fails, authentication-related logs may help identify whether the username, password, account or connection caused the problem.

2. Linux Log Directory

Many Linux system logs are stored in the /var/log directory.

Explore the Log Directory

ls /var/log ls -lh /var/log

Important Log Files and Directories

PathPurpose
/var/log/syslogGeneral system messages on many Debian/Ubuntu installations.
/var/log/auth.logAuthentication and authorization-related messages on many Debian/Ubuntu installations.
/var/log/kern.logKernel-related messages on systems configured to store them separately.
/var/log/dpkg.logPackage installation, removal and related dpkg activity.
/var/log/apt/APT package-management logs.
/var/log/apache2/Apache web server logs, when Apache is installed.
/var/log/journal/Persistent systemd journal storage, when configured.
/var/log/wtmpBinary login and logout history data.
/var/log/btmpBinary failed-login history data.
Log filenames and locations depend on the Linux distribution and logging configuration. Some logs may not exist on a minimal Ubuntu installation.

3. Viewing Log Files

Linux provides several commands for reading and inspecting text-based log files.

cat – Display Log Contents

cat /var/log/syslog

Displays the complete contents of the specified file. Large log files can produce too much output for convenient reading.

less – Read Logs Page by Page

less /var/log/syslog

Allows you to move through a log file page by page. Press q to exit.

head – Display the First Lines

head /var/log/syslog head -n 20 /var/log/syslog

Displays the first 10 lines by default, or the number specified with -n.

tail – Display the Last Lines

tail /var/log/syslog tail -n 20 /var/log/syslog

Displays the last 10 lines by default, or the number specified with -n.

Follow a Log File in Real Time

tail -f /var/log/syslog

Displays new lines as they are appended to the file. Press Ctrl + C to stop following.

Follow a Log Through File Rotation

tail -F /var/log/syslog

The -F option retries when a file is replaced or recreated, which is useful when log rotation occurs.

4. Searching Logs Using grep

The grep command searches for specific text or patterns inside log files.

Search for an Error

grep "error" /var/log/syslog

Case-Insensitive Search

grep -i "error" /var/log/syslog

Display Line Numbers

grep -n "failed" /var/log/auth.log

Search for Multiple Keywords

grep -Ei "error|warning|failed" /var/log/syslog

Count Matching Lines

grep -ic "error" /var/log/syslog

Combine tail and grep

tail -f /var/log/syslog | grep -i "error"
Practical use:

When troubleshooting an application, searching its log for words such as error, failed and denied can help locate relevant messages quickly.

5. Understanding Log Message Priorities

System logs often include severity levels that indicate the importance of a message.

Common Syslog Severity Levels

Numeric LevelNameMeaning
0EmergencySystem is unusable.
1AlertImmediate action is required.
2CriticalCritical conditions.
3ErrorError conditions.
4WarningWarning conditions.
5NoticeNormal but significant conditions.
6InformationalInformational messages.
7DebugDebugging messages.

Why Severity Levels Matter

  • Emergency and alert messages require urgent attention.
  • Error messages indicate failures that may need investigation.
  • Warning messages indicate potentially problematic conditions.
  • Informational messages record normal system activity.
  • Debug messages provide detailed information useful during development and troubleshooting.

6. systemd Journal and journalctl

On systems using systemd, systemd-journald collects system and service log messages in the systemd journal.

The journalctl command is used to query and display these journal entries.

Display All Available Journal Entries

journalctl

Display Logs from the Current Boot

journalctl -b

Display Logs from the Previous Boot

journalctl -b -1

Display Kernel Logs

journalctl -k

Display Logs for a Specific Service

journalctl -u cron

Display Service Logs from Current Boot

journalctl -u cron -b

Display Recent Journal Entries

journalctl -n 50

Follow Journal Entries in Real Time

journalctl -f

Press q to exit the pager or Ctrl + C to stop following live entries.

7. Filtering Logs by Time

journalctl supports time-based filtering, allowing administrators to inspect messages from a particular period.

Logs from the Last Hour

journalctl --since "1 hour ago"

Logs from the Last 30 Minutes

journalctl --since "30 minutes ago"

Logs Since a Specific Date and Time

journalctl --since "2026-11-05 09:00:00"

Logs Between Two Times

journalctl --since "2026-11-05 09:00:00" --until "2026-11-05 10:00:00"

Logs for the Current Day

journalctl --since today
Replace example dates and times with the actual period you want to investigate. Journal timestamps are interpreted using the system's time settings.

8. Filtering Logs by Priority

Use the -p option to display journal messages at a particular severity level or higher priority.

Display Error Messages

journalctl -p err

Display Warning Messages and More Severe Messages

journalctl -p warning

Display Critical Messages

journalctl -p crit

Display Emergency Messages

journalctl -p emerg

Combine Priority and Boot Filters

journalctl -b -p err
Important:

Priority filtering includes the specified severity and more severe levels. For example, -p warning includes warning, error, critical, alert and emergency messages.

9. rsyslog – System Logging Service

rsyslog is a widely used system logging service. It can receive, process, filter and store log messages.

Functions of rsyslog

  • Collects log messages from applications and system components.
  • Processes and filters messages based on rules.
  • Writes messages to configured log files.
  • Can forward logs to remote logging servers.
  • Supports centralized logging configurations.

Check rsyslog Service Status

systemctl status rsyslog

Start rsyslog

sudo systemctl start rsyslog

Enable rsyslog at Startup

sudo systemctl enable rsyslog

Restart rsyslog

sudo systemctl restart rsyslog

Check Whether rsyslog Is Installed

dpkg -l rsyslog
rsyslog is not guaranteed to be installed or enabled on every Ubuntu installation. systemd-journald can collect journal messages without rsyslog. The two services can also work together.

10. Understanding Logrotate

Log files can grow over time. Large log files consume disk space and can make administration difficult.

logrotate manages log files by rotating, compressing, deleting or retaining older logs according to configured rules.

Why Is Log Rotation Needed?

  • Prevents log files from growing indefinitely.
  • Controls disk-space usage.
  • Maintains historical log files for a defined period.
  • Can compress older log files.
  • Helps organize log storage.

Important Logrotate Paths

PathPurpose
/etc/logrotate.confMain logrotate configuration file.
/etc/logrotate.d/Directory containing application-specific logrotate rules.
/var/lib/logrotate/statusTracks the last rotation time for logs on many installations.

Check Whether Logrotate Is Installed

logrotate --version

View Main Configuration

cat /etc/logrotate.conf

List Application-Specific Rules

ls /etc/logrotate.d/

11. Logrotate Configuration Example

A logrotate rule defines how a particular log file should be managed.

Example Configuration

/var/log/myapp.log { daily rotate 7 compress missingok notifempty }

Explanation of Directives

DirectiveMeaning
dailyRotate the log daily.
weeklyRotate the log weekly.
monthlyRotate the log monthly.
rotate 7Retain seven rotated log files.
compressCompress rotated logs.
missingokDo not report an error if the log file is missing.
notifemptyDo not rotate an empty log file.
copytruncateCopy the log and truncate the original file instead of renaming it.
delaycompressDelay compression until the next rotation cycle.

Test a Configuration Without Rotating

sudo logrotate -d /etc/logrotate.conf

Force Rotation

sudo logrotate -f /etc/logrotate.conf
The -f option forces rotation and can change log files. Do not use it casually on production systems. Use the debug option first to inspect what would happen.

12. Binary Login History Logs

Some Linux login history files are stored in binary format rather than as ordinary readable text files.

wtmp – Login History

The wtmp database records login and logout activity and system events.

last

btmp – Failed Login History

The btmp database records failed login attempts.

sudo lastb

Display the Current Logged-In Users

who

Display User and Login Information

w
Access to failed-login history may require administrator privileges. These files may be absent or empty depending on system configuration and activity.

13. Monitoring Disk Usage of Log Files

Log files can consume significant disk space. Administrators should periodically check log directory usage.

Check Total Log Directory Size

sudo du -sh /var/log

Check Sizes of Individual Log Files

sudo du -ah /var/log | sort -hr | head -20

Check Filesystem Free Space

df -h /var/log

Find Large Log Files

sudo find /var/log -type f -size +100M -ls
Do not manually delete active log files to solve disk-space problems. Investigate the cause, use logrotate or the appropriate journal maintenance mechanism, and follow the system's retention policy.

14. Managing systemd Journal Disk Usage

The systemd journal can use disk space. The journalctl command provides options to inspect and manage its storage.

Check Journal Disk Usage

journalctl --disk-usage

Remove Archived Journal Files Older Than a Period

sudo journalctl --vacuum-time=7d

Limit Archived Journal Files by Size

sudo journalctl --vacuum-size=500M

Limit Archived Journal Files by Count

sudo journalctl --vacuum-files=5
Vacuum operations remove archived journal files, not necessarily the currently active journal file. Use retention limits according to your troubleshooting, audit and storage requirements.

16. Common Log Troubleshooting Scenarios

Scenario 1: A Service Fails to Start

Inspect its status and journal entries:

systemctl status service-name journalctl -u service-name -b

Scenario 2: Authentication Failure

On Ubuntu installations that use this file, inspect authentication messages:

sudo tail -n 50 /var/log/auth.log

Scenario 3: Disk Space Is Running Low

Inspect log-directory and journal usage:

sudo du -sh /var/log journalctl --disk-usage df -h

Scenario 4: Kernel-Related Error

Inspect kernel messages:

journalctl -k -b dmesg | less

Scenario 5: Application Error

Inspect the application's configured log location and search for errors:

grep -i "error" /path/to/application.log tail -f /path/to/application.log
Troubleshooting approach:
  1. Identify the time when the problem occurred.
  2. Identify the affected application or service.
  3. Inspect its relevant logs.
  4. Search for errors, warnings and failed operations.
  5. Correlate log messages with system events.
  6. Apply a corrective action and verify the result.

17. Interview Questions and Answers

Q1. What are Linux logs?

Answer: Linux logs are records of system, application, security and service events.

Q2. Where are Linux log files commonly stored?

Answer: Many traditional Linux log files are stored in the /var/log directory.

Q3. What is journalctl?

Answer: It is a command-line utility used to query and display logs collected by systemd-journald.

Q4. What is rsyslog?

Answer: rsyslog is a system logging service that collects, processes, filters, stores and forwards log messages.

Q5. What is logrotate?

Answer: Logrotate manages log files by rotating, compressing and retaining them according to configured rules.

Q6. What is the purpose of tail -f?

Answer: It continuously displays new lines appended to a log file.

Q7. What is the difference between syslog and auth.log?

Answer: On many Ubuntu installations, syslog contains general system messages, while auth.log contains authentication and authorization-related messages.

Q8. How do you view logs from the current boot?

Answer: Use journalctl -b.

Q9. How do you view logs for a particular service?

Answer: Use journalctl -u service-name.

Q10. How do you check systemd journal disk usage?

Answer: Use journalctl --disk-usage.

Q11. What is the purpose of /var/log/wtmp?

Answer: It stores binary login and logout history information used by commands such as last.

Q12. Why is log rotation important?

Answer: It controls log-file growth, manages disk usage and maintains older logs according to retention requirements.
