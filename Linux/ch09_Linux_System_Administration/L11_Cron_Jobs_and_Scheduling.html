Automate recurring tasks using cron, crontab and systemd timers

1. Introduction to Task Scheduling

Task scheduling is the process of automatically executing commands or programs at specified times or intervals.

Linux provides scheduling tools that help administrators automate routine tasks without manually executing them every time.

Examples of Scheduled Tasks

  • Taking automatic backups every day.
  • Cleaning temporary files periodically.
  • Generating system reports.
  • Running database maintenance scripts.
  • Synchronizing files at scheduled intervals.
  • Monitoring system resources.
Example:

An administrator can schedule a backup script to run every day at 2:00 AM using cron.

2. What Is Cron?

Cron is a time-based job scheduler in Unix-like operating systems. It executes commands and scripts automatically according to a schedule.

What Is a Cron Job?

A cron job is a scheduled command or script that cron executes at a specified time or interval.

What Is crontab?

crontab stands for cron table. It contains scheduling entries that define when commands should run.

What Is the Cron Daemon?

The cron daemon is a background service that checks scheduled entries and starts jobs when their scheduled times arrive.

Check Cron Service Status

systemctl status cron

Start Cron Service

sudo systemctl start cron

Enable Cron at Startup

sudo systemctl enable cron

Restart Cron Service

sudo systemctl restart cron
On Ubuntu, the service is generally named cron. Other Linux distributions may use a service named crond.

3. Understanding Crontab Commands

The crontab command manages scheduled jobs for users.

View Current User's Cron Jobs

crontab -l

Lists the current user's crontab entries.

Edit Current User's Crontab

crontab -e

Opens the current user's crontab in a text editor so you can add, modify or remove scheduled jobs.

Remove Current User's Crontab

crontab -r
Important: crontab -r removes the current user's entire crontab. It does not merely remove one job. Always inspect and back up important entries before using it.

List Another User's Crontab (Administrator)

sudo crontab -u username -l

Edit Another User's Crontab (Administrator)

sudo crontab -u username -e

List Root User's Crontab

sudo crontab -l
A user's personal crontab is separate from root's crontab. A job that requires administrator privileges should be scheduled in an appropriately privileged context.

4. Cron Expression Syntax

A standard user crontab entry contains five time fields followed by the command to execute.

* * * * * command

The Five Fields of Cron

FieldAllowed ValuesMeaning
Minute0–59Minute of the hour.
Hour0–23Hour of the day.
Day of Month1–31Day of the month.
Month1–12Month of the year.
Day of Week0–7Day of the week; both 0 and 7 generally represent Sunday.

Visual Representation

┌───────────── Minute (0–59) │ ┌─────────── Hour (0–23) │ │ ┌───────── Day of Month (1–31) │ │ │ ┌─────── Month (1–12) │ │ │ │ ┌───── Day of Week (0–7) │ │ │ │ │ * * * * * command
Remember:

The first five fields define the schedule. The remaining part of the line contains the command or script that cron executes.

5. Special Characters in Cron

Cron expressions use special characters to define schedules.

SymbolMeaningExample
*Every possible value in the field.* * * * *
,Specific multiple values.0 9,17 * * *
-A range of values.0 9-17 * * *
/Step values or intervals.*/5 * * * *

Example 1: Every Minute

* * * * * command

Example 2: Every 5 Minutes

*/5 * * * * command

Example 3: At Minute 0 and 30

0,30 * * * * command

Example 4: Every Hour Between 9 AM and 5 PM

0 9-17 * * * command

Example 5: Every 10 Minutes During Business Hours

*/10 9-17 * * * command

6. Practical Cron Job Examples

Example 1: Run Every Minute

* * * * * /home/user/script.sh

Runs the script once every minute.

Example 2: Run Every Day at 2:00 AM

0 2 * * * /home/user/backup.sh

Example 3: Run Every Day at 6:30 AM

30 6 * * * /home/user/report.sh

Example 4: Run Every Sunday at 8:00 AM

0 8 * * 0 /home/user/weekly_backup.sh

Example 5: Run on the First Day of Every Month

0 0 1 * * /home/user/monthly_report.sh

Example 6: Run Every 15 Minutes

*/15 * * * * /home/user/monitor.sh

Example 7: Run Every Monday to Friday at 9:00 AM

0 9 * * 1-5 /home/user/workday.sh

Example 8: Run at 11:30 PM Every Day

30 23 * * * /home/user/night_task.sh

Example 9: Run Every Hour at Minute 15

15 * * * * /home/user/hourly_task.sh

Example 10: Run at 8:00 AM on the 1st and 15th of Every Month

0 8 1,15 * * /home/user/report.sh

7. Special Cron Scheduling Strings

Cron supports special strings that represent commonly used schedules.

Special StringMeaning
@rebootRun when the cron daemon starts the user's scheduled jobs after system startup.
@yearlyRun once a year.
@annuallySame as yearly.
@monthlyRun once a month.
@weeklyRun once a week.
@dailyRun once a day.
@midnightSame as daily.
@hourlyRun once an hour.

Example: Run a Script at Reboot

@reboot /home/user/startup.sh

Example: Run a Backup Daily

@daily /home/user/backup.sh

Example: Run a Report Weekly

@weekly /home/user/weekly_report.sh
The @reboot entry is associated with the cron daemon's startup processing. It is not a precise guarantee that a job runs at the exact instant the operating system finishes booting.

8. Creating and Scheduling a Shell Script

Let's create a simple Bash script and schedule it using cron.

Step 1: Create a Script

nano ~/hello_cron.sh

Step 2: Add the Following Code

#!/bin/bash echo "Cron job executed at: $(date)" >> "$HOME/cron_log.txt"

Step 3: Save and Exit

In nano:

  • Press Ctrl + O to save.
  • Press Enter to confirm.
  • Press Ctrl + X to exit.

Step 4: Make the Script Executable

chmod +x ~/hello_cron.sh

Step 5: Test the Script Manually

~/hello_cron.sh cat ~/cron_log.txt
Example Output:
Cron job executed at: Thu Nov 5 10:00:00 IST 2026

The displayed date and time will depend on when you execute the script.

Step 6: Open Crontab

crontab -e

Step 7: Add This Entry

*/5 * * * * /bin/bash /home/username/hello_cron.sh

Replace username with your actual Linux username.

Step 8: Verify the Crontab

crontab -l

Step 9: Check the Log File

cat ~/cron_log.txt

After the scheduled executions, the file should contain timestamp entries.

9. Cron Environment and Output Redirection

Cron jobs run in a limited environment. They should not depend on interactive terminal settings or shell configuration files.

Use Absolute Paths

0 2 * * * /home/user/backup.sh

Using absolute paths makes scheduled commands more reliable.

Redirect Standard Output to a File

0 2 * * * /home/user/backup.sh >> /home/user/backup.log

Redirect Standard Output and Standard Error

0 2 * * * /home/user/backup.sh >> /home/user/backup.log 2>&1

Discard All Output

0 2 * * * /home/user/backup.sh > /dev/null 2>&1

Set Environment Variables in Crontab

SHELL=/bin/bash PATH=/usr/local/bin:/usr/bin:/bin 0 2 * * * /home/user/backup.sh
Understanding redirection:
  • > redirects standard output and overwrites a file.
  • >> appends standard output to a file.
  • 2>&1 sends standard error to the same destination as standard output.
  • /dev/null discards output.

10. System-Wide Cron Scheduling

Linux also supports system-wide scheduled jobs that are not limited to an individual user's personal crontab.

Important System Cron Locations

PathPurpose
/etc/crontabSystem-wide crontab file with an additional username field.
/etc/cron.d/Directory containing additional system-wide cron entries.
/etc/cron.hourly/Scripts intended to run hourly.
/etc/cron.daily/Scripts intended to run daily.
/etc/cron.weekly/Scripts intended to run weekly.
/etc/cron.monthly/Scripts intended to run monthly.

View System Crontab

cat /etc/crontab

View Scheduled Script Directories

ls -l /etc/cron.hourly/ ls -l /etc/cron.daily/ ls -l /etc/cron.weekly/ ls -l /etc/cron.monthly/
Unlike a personal user crontab, entries in /etc/crontab and /etc/cron.d/ include an extra username field after the five time fields.

System-Wide Crontab Example

30 2 * * * root /usr/local/bin/backup.sh

This example runs the backup script as the root user at 2:30 AM every day when placed in an appropriate system-wide crontab file.

11. One-Time Scheduling Using at

The at command schedules a command or job to run once at a specified future time. It is different from cron, which is commonly used for recurring jobs.

Schedule a Command

at 10:30

After entering the command, type the command you want to execute:

echo "One-time task executed" >> "$HOME/at_log.txt"

Press Ctrl + D to submit the job.

Schedule a Job for Tomorrow

at tomorrow

Schedule a Job for a Specific Time

at 6:00 PM

List Pending at Jobs

atq

Remove a Scheduled at Job

atrm job_number
The at command requires the relevant scheduling service, commonly atd, to be installed and running. Availability and accepted time formats can vary.

Check atd Service Status

systemctl status atd

12. Understanding systemd Timers

Systemd timers provide another way to schedule tasks on Linux systems that use systemd.

A systemd timer is a unit that activates another systemd unit according to a configured time schedule or system event.

Advantages of systemd Timers

  • Integrate with systemd services.
  • Can schedule jobs relative to system startup or other events.
  • Can use calendar-based schedules.
  • Support logging through the systemd journal.
  • Provide service dependencies and management features.

List Systemd Timers

systemctl list-timers

List All Timers

systemctl list-timers --all

Check a Timer's Status

systemctl status timer-name.timer

Inspect a Timer Configuration

systemctl cat timer-name.timer
Important:

Unlike a cron entry, a systemd timer generally works with a separate service unit. The timer controls when the service is activated.

13. Cron vs at vs systemd Timers

Featurecronatsystemd Timer
PurposeRecurring jobsOne-time jobsScheduled systemd units
ScheduleTime-based expressionsSpecified future timeCalendar or monotonic time
Recurring executionYesNormally noYes, when configured
Service integrationLimitedLimitedNative systemd integration
LogsDepends on system logging and configurationDepends on system configurationAvailable through journal when configured
Selection guide:
  • Use cron for straightforward recurring tasks.
  • Use at for a task that should run once in the future.
  • Use systemd timers when you need systemd service integration, dependencies or timer-specific behavior.

14. Troubleshooting Cron Jobs

Problem 1: Cron Job Is Not Executing

Check whether the cron service is running:

systemctl status cron

Problem 2: Script Does Not Have Execute Permission

Check permissions:

ls -l ~/backup.sh

Make it executable if necessary:

chmod +x ~/backup.sh

Problem 3: Incorrect Script Path

Use the full path to the script:

0 2 * * * /home/user/backup.sh

Problem 4: Command Works Manually but Fails in Cron

  • Use absolute paths for commands.
  • Set required environment variables.
  • Do not rely on interactive shell settings.
  • Check script permissions and ownership.
  • Redirect output and errors to a log file.

Problem 5: Inspect Cron Logs

On Ubuntu systems using systemd, inspect cron service messages:

journalctl -u cron -b

On systems that log cron activity to a traditional syslog file, you can also try:

sudo grep CRON /var/log/syslog

Problem 6: Check the User's Crontab

crontab -l
Cron does not normally provide the same environment as an interactive terminal. Always test scripts manually, use absolute paths, and record output when diagnosing failures.

16. Interview Questions and Answers

Q1. What is cron in Linux?

Answer: Cron is a time-based job scheduler used to execute commands and scripts automatically at specified times or intervals.

Q2. What is a cron job?

Answer: A cron job is a command or script scheduled for automatic execution by cron.

Q3. What is crontab?

Answer: Crontab is the configuration table that contains a user's scheduled cron entries.

Q4. What are the five fields of a cron expression?

Answer: Minute, hour, day of month, month and day of week.

Q5. What does */5 * * * * mean?

Answer: It schedules a task to run every five minutes.

Q6. What is the purpose of crontab -l?

Answer: It displays the current user's crontab entries.

Q7. What is the purpose of crontab -e?

Answer: It opens the current user's crontab for editing.

Q8. What is the difference between cron and at?

Answer: Cron is commonly used for recurring schedules, while at schedules one-time future jobs.

Q9. What is @reboot?

Answer: It is a special cron string used to schedule a job when cron processes its startup entries after the daemon starts.

Q10. Why should absolute paths be used in cron jobs?

Answer: Cron runs with a limited environment and may not have the same PATH as an interactive shell. Absolute paths reduce command and script lookup problems.

Q11. What are systemd timers?

Answer: Systemd timers are scheduling units that activate other systemd units at specified times or intervals.

Q12. How do you check cron service status?

Answer: Use systemctl status cron on Ubuntu.
