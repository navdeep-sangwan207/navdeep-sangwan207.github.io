1. Introduction to Software Installation in Linux

Linux software is distributed in different formats and can be installed using package managers, local package files, application stores or other installation methods.

In Ubuntu, APT is commonly used to install and remove software from configured repositories.

Common software installation methods

Method Description
APT Installs software from configured Debian-based repositories.
DPKG Installs and manages local DEB package files.
Snap Installs applications distributed as Snap packages.
Flatpak Installs applications distributed as Flatpak packages.
Source code Builds software from its source code using appropriate development tools.
This lesson primarily focuses on APT and DPKG because they are fundamental to Ubuntu and Debian-based system administration.

2. Installing Software Using APT

The apt install command installs a software package from configured repositories.

General syntax

sudo apt install package-name

The sudo command provides administrative privileges required for system-wide software installation.

Example 1: Install curl

sudo apt update sudo apt install curl

The first command refreshes repository package information. The second command installs curl.

Example 2: Install wget

sudo apt install wget

Example 3: Install Git

sudo apt install git

Example 4: Install multiple packages

sudo apt install curl wget git

Multiple package names can be provided in the same installation command.

Typical installation process: 
Reading package lists... Done
Building dependency tree... Done
The following NEW packages will be installed:
  curl
Do you want to continue? [Y/n]
Illustrative output; actual packages and messages vary.

Enter Y and press Enter to continue when you have reviewed the proposed changes.

3. Installing Software Without Confirmation

APT normally asks for confirmation before making changes. The -y option automatically answers yes to confirmation prompts.

Syntax

sudo apt install -y package-name

Example

sudo apt install -y curl
Use -y carefully. It can automatically approve package installation and other proposed changes. For learning and system administration, reviewing the proposed changes before confirming is generally safer.

4. Installing a Local DEB Package

A DEB file is a Debian software package format used by Ubuntu and other Debian-based Linux distributions.

A local DEB package may be downloaded from a software provider's website or obtained from another source.

Method 1: Install using APT

sudo apt install ./package.deb

APT can install a local DEB file and attempt to resolve its dependencies using configured repositories.

Example

sudo apt install ./example.deb

Method 2: Install using DPKG

sudo dpkg -i package.deb

The DPKG command installs a local DEB package but does not automatically download missing dependencies.

Repair missing dependencies after DPKG installation

sudo apt --fix-broken install

This asks APT to resolve broken package dependencies where possible using configured repositories.

APT is generally more convenient for installing local DEB files because it can handle dependencies using configured repositories.

Compare APT and DPKG installation

APT DPKG
sudo apt install ./file.deb sudo dpkg -i file.deb
Can resolve dependencies from configured repositories. Does not automatically download missing dependencies.
Works with repository-based package management. Works directly with local DEB package files.

5. Verifying Software Installation

After installing software, verify that the package is installed and that its command is available.

Method 1: Check the installed package list

apt list --installed

Method 2: Filter for a particular package

apt list --installed 2>/dev/null | grep '^curl/'

Method 3: Check using DPKG

dpkg -l curl

This displays package information and its installation status.

Method 4: Check the installed version

curl --version

Method 5: Find the executable path

command -v curl
Example output: 
/usr/bin/curl
The actual path can vary depending on the system.
Important distinction: A package can be installed even if you do not know its executable command. Package verification and executable verification are related but different checks.

6. Removing Installed Software

Software can be removed when it is no longer needed. APT provides different removal commands.

Method 1: Remove a package

sudo apt remove package-name

This removes the installed package but generally leaves its system-wide configuration files managed by the package.

Example

sudo apt remove curl

Method 2: Purge a package

sudo apt purge package-name

Purge removes the package and its system-wide configuration files managed by the package.

Example

sudo apt purge curl

Method 3: Remove automatically installed unused dependencies

sudo apt autoremove

This removes automatically installed packages that are no longer required as dependencies.

Method 4: Remove a package using DPKG

sudo dpkg -r package-name

The -r option removes the package while retaining its configuration files where applicable.

Remove and purge using DPKG

sudo dpkg -P package-name

The -P option purges the package.

Package removal can affect other software that depends on the package. Always read APT's proposed removal list before confirming the operation.

7. Understanding Package Dependencies

A dependency is another software package required by a program to function correctly.

For example, an application may require libraries, runtime components or other utilities.

Types of dependencies

Dependency type Description
Required dependency A package needed for the software to work correctly.
Recommended package Additional software recommended for normal functionality.
Suggested package Optional software that may provide additional features.

View package dependencies

apt depends curl

View reverse dependencies

apt rdepends curl

Reverse dependencies are packages that depend on the specified package.

View package information

apt show curl
APT automatically resolves many dependency requirements during installation. This reduces the need to install every required library manually.

8. Fixing Broken Package Dependencies

Sometimes package installation fails because of missing dependencies, interrupted installations or inconsistent package states.

Command to fix broken dependencies

sudo apt --fix-broken install

This asks APT to resolve broken dependencies using the available package information and repositories.

Configure unpacked packages using DPKG

sudo dpkg --configure -a

This attempts to configure packages that have been unpacked but not completely configured.

Refresh package information

sudo apt update
These commands address different situations. Read the error message first and choose the appropriate repair command rather than running every repair command without understanding the problem.

9. Common Software Installation Errors

Error 1: Unable to locate package

E: Unable to locate package package-name

Possible causes:

  • Incorrect package name.
  • Package lists are outdated.
  • Required repository is not enabled.
  • Package is not available for the configured distribution.

Possible solution:

sudo apt update apt search package-name

Error 2: Unmet dependencies

Some packages could not be installed.
You have unmet dependencies.

Possible solution:

sudo apt --fix-broken install

Error 3: Could not get lock

Could not get lock /var/lib/dpkg/lock-frontend

This can happen when another package-management process is already running.

Possible solution:

  • Wait for the other package operation to finish.
  • Check whether another software updater is running.
  • Retry the command after the package operation completes.
Do not delete APT or DPKG lock files blindly. A lock protects the package database from simultaneous package-management operations.

Error 4: Permission denied

Installing or removing system-wide packages normally requires administrative privileges.

Solution:

sudo apt install package-name

10. Package Installation Workflow

A typical software installation workflow in Ubuntu is:

# Step 1: Update package information sudo apt update # Step 2: Search for the package apt search curl # Step 3: Inspect package information apt show curl # Step 4: Install the package sudo apt install curl # Step 5: Verify the installation curl --version # Step 6: Check the executable location command -v curl
This workflow helps you understand what you are installing, where the package comes from and whether the installation was successful.

12. Interview Questions and Answers

Q1. How do you install software in Ubuntu?

Use the command:

sudo apt install package-name

Q2. What is a DEB package?

A DEB package is a software package format used by Debian-based Linux distributions.

Q3. What is the difference between apt remove and apt purge?

apt remove removes the package but generally leaves its system-wide configuration files. apt purge also removes those managed configuration files.

Q4. How do you install a local DEB package?

sudo apt install ./package.deb

Q5. What is the difference between APT and DPKG?

APT manages repository-based installations and dependencies. DPKG manages Debian package files at a lower level.

Q6. What is a package dependency?

A dependency is another package or component required by software to function correctly.

Q7. How do you fix broken package dependencies?

sudo apt --fix-broken install

Q8. How do you check whether a package is installed?

dpkg -l package-name

Q9. What does dpkg --configure -a do?

It attempts to configure packages that were unpacked but have not completed configuration.

Q10. Why should lock files not be deleted manually?

Package lock files prevent simultaneous package operations from interfering with the package database.

14. Lesson Summary

  • Linux software can be installed using package managers and other methods.
  • APT is commonly used to install software in Ubuntu.
  • sudo apt install installs software.
  • sudo apt remove removes a package.
  • sudo apt purge removes a package and its managed system configuration.
  • sudo apt autoremove removes unused automatically installed dependencies.

  • dpkg -i installs a local DEB package.
  • apt depends displays package dependencies.
