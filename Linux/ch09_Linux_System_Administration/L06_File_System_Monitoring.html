File System Monitoring in Linux

Monitor disk usage, directory sizes, filesystem capacity and inodes

Learning Objectives

After completing this lesson, you will be able to:

  • Understand filesystem monitoring in Linux.
  • Check available and used disk space.
  • Use the df command to monitor filesystems.
  • Use the du command to measure directory sizes.
  • Understand inodes and monitor inode usage.
  • Identify directories consuming large amounts of storage.
  • Investigate common disk-space problems.

1. Introduction to File System Monitoring

File system monitoring is the process of checking storage capacity, used space, available space, directory sizes and inode usage in a Linux system.

System administrators monitor filesystems to prevent storage exhaustion and maintain reliable system operation.

Filesystem monitoring: Observing storage utilization and filesystem health to identify capacity problems before they affect system operation.

Why Is It Important?

  • Prevents the root filesystem from becoming full.
  • Helps identify large files and directories.
  • Detects inode exhaustion.
  • Supports server and application reliability.
  • Helps administrators plan additional storage.
  • Prevents applications from failing because they cannot write data.

2. Understanding Disk Space

A filesystem uses storage space to store files, directories, metadata and other filesystem information.

Important storage terms:

Term Meaning
Total Space The total capacity available to the filesystem.
Used Space Storage currently occupied by filesystem data and metadata.
Available Space Space available for new data according to filesystem rules.
Filesystem Usage The percentage of filesystem capacity currently used.
Mount Point The directory where a filesystem is attached.
Filesystem-reported available space may be smaller than the difference between total and used space because some filesystems reserve blocks for privileged operations and internal requirements.

3. The df Command

The df command displays information about filesystem disk-space usage.

Syntax

df [OPTIONS] [FILE]

Display Disk Space

df

Displays filesystem capacity and usage using default output units.

Human-Readable Output

df -h

The -h option displays sizes in readable units such as KB, MB, GB and TB.

Example output: 
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        40G   18G   20G  48% /
tmpfs           1.0G  2.0M  1.0G   1% /run
/dev/sdb1       100G   45G   50G  48% /mnt/data

This is illustrative output. Actual values depend on the system.

Understanding the Columns

Column Description
Filesystem The filesystem or storage source.
Size Total filesystem capacity.
Used Space currently used.
Avail Available space.
Use% Percentage of filesystem space used.
Mounted on Filesystem mount point.

Display Disk Usage in MB

df -m

Displays filesystem sizes in megabytes.

Display Disk Usage in Bytes

df -B1

Displays sizes using one-byte blocks.

Display Filesystem Type

df -T -h

The -T option displays the filesystem type, such as ext4, tmpfs or vfat.

Check a Specific Directory

df -h /home

Displays information about the filesystem containing /home.

Exclude Certain Filesystem Types

df -h -x tmpfs

Excludes filesystems of type tmpfs from the output.

4. The du Command

The du command estimates the disk space occupied by files and directories.

Syntax

du [OPTIONS] [FILE_OR_DIRECTORY]

Display Directory Usage

du /home

Displays disk usage for the specified directory and its subdirectories.

Human-Readable Directory Usage

du -h /home

Displays directory sizes using readable units.

Display Only the Total Size

du -sh /home

Options:

  • -s displays a summary instead of listing every subdirectory.
  • -h displays human-readable sizes.
Example output: 
2.4G    /home

This means the estimated disk usage of /home is approximately 2.4 GB.

Display All Files and Directories

du -ah /home

Displays sizes for files as well as directories under /home.

Display Immediate Subdirectory Totals

du -h --max-depth=1 /home

Displays the sizes of /home and its immediate subdirectories without listing every nested directory.

Sort Directories by Size

du -h --max-depth=1 /home | sort -h

The sort -h command sorts human-readable size values from smaller to larger.

Find the Largest Directories First

du -h --max-depth=1 /home | sort -hr

The -r option reverses the sort order so the largest sizes appear first.

5. Difference Between df and du

Both commands monitor storage, but they provide different information.

df du
Displays filesystem space usage. Estimates file and directory disk usage.
Reports total, used and available space. Reports the space occupied by selected paths.
Works at the filesystem level. Examines files and directories.
Useful for checking filesystem capacity. Useful for finding large directories.
Example: df -h Example: du -sh /home
Remember: Use df -h to check available filesystem space. Use du -sh to check how much disk space a particular directory occupies.

6. Understanding Inodes

An inode is a filesystem data structure that stores metadata about a file or directory.

In Linux filesystems such as ext4, inode information commonly includes:

  • File type and permissions.
  • Owner user ID and group ID.
  • File size.
  • Timestamps.
  • Link count.
  • References to the file's data blocks.
An inode does not normally store the filename itself. Directory entries associate filenames with inode numbers.

Why Are Inodes Important?

Filesystems have a finite number of inodes. If all available inodes are consumed, the system may be unable to create new files even when free disk space remains.

Example

Imagine a filesystem with:

  • 100 GB total storage.
  • 20 GB used storage.
  • 80 GB available storage.
  • All inodes already allocated.

In this situation, creating additional files may fail despite the availability of storage capacity.

7. The df -i Command

The df -i command displays inode utilization instead of normal disk-space utilization.

df -i
Example output: 
Filesystem     Inodes   IUsed   IFree IUse% Mounted on
/dev/sda1     2500000  500000 2000000   20% /
/dev/sdb1     6000000 5500000  500000   92% /mnt/data

Understanding the columns:

Column Meaning
Inodes Total inode count.
IUsed Number of inodes used.
IFree Number of free inodes.
IUse% Percentage of inodes used.

Check Inodes for a Specific Filesystem

df -i /home

Displays inode usage for the filesystem containing /home.

8. Find Large Files and Directories

Administrators often investigate large files and directories when disk usage becomes high.

Find Large Directories

sudo du -h --max-depth=1 /var

Displays the disk usage of immediate subdirectories under /var.

Find Large Files

find /home -type f -size +100M

Explanation:

  • find searches for files and directories.
  • /home is the search location.
  • -type f selects regular files.
  • -size +100M selects files larger than 100 MB.

Display File Sizes

find /home -type f -size +100M -exec ls -lh {} \;

Displays matching files with human-readable file sizes.

Find the Largest Files in a Directory

du -ah /home | sort -hr | head -n 10

Displays up to the first ten largest entries reported by du under /home.

Searching the entire filesystem with administrative privileges may produce many permission messages and take time. Start with specific directories such as /home or /var.

9. Monitor Disk Usage with watch

The watch command repeatedly executes another command and refreshes its output.

Monitor Disk Space Every Two Seconds

watch -n 2 df -h

The -n 2 option refreshes the displayed information every two seconds.

Monitor Inode Usage

watch -n 2 df -i

Monitor a Directory's Size

watch -n 5 du -sh /var/log

This checks the estimated size of /var/log every five seconds.

Press Ctrl + C to stop the watch command.

10. Common Causes of High Disk Usage

Cause Description Investigation
Large log files Application and system logs consume storage. du -sh /var/log
Package cache Downloaded package files occupy space. du -sh /var/cache/apt
Temporary files Temporary data accumulates over time. du -sh /tmp
User data Downloads, videos and backups consume storage. du -sh /home/*
Application data Databases and application files grow over time. Inspect application directories.
Too many small files Inodes may be exhausted. df -i

11. Basic Disk Space Troubleshooting

When a Linux filesystem becomes nearly full, follow a systematic troubleshooting process.

Step 1: Check Filesystem Usage

df -h

Step 2: Check Inode Usage

df -i

Step 3: Identify Large Directories

sudo du -h --max-depth=1 /var

Step 4: Investigate Large Files

sudo find /var -type f -size +100M

Step 5: Inspect the Files Carefully

Identify whether the files are old logs, temporary files, backups or application data.

Step 6: Take Appropriate Action

  • Remove unnecessary files only after confirming they are safe to delete.
  • Archive or move old data when appropriate.
  • Configure log rotation for growing log files.
  • Clean package caches using supported package-management commands.
  • Extend storage when additional capacity is required.
Never delete files blindly from system directories such as /var, /usr or /etc. First identify what the file is used for and whether an application or service depends on it.

12. Practical Lab Exercises

Lab 1: Check Filesystem Capacity

Objective: Display disk usage in human-readable form.

df -h

Expected Result: You should see total, used and available space for mounted filesystems.

Lab 2: Check Filesystem Types

Objective: Display filesystem types and capacity.

df -Th

Expected Result: The output should include filesystem types such as ext4 or tmpfs where applicable.

Lab 3: Check Home Directory Size

Objective: Calculate the total disk usage of your home directory.

du -sh ~

Expected Result: One summary line showing the estimated size of your home directory.

Lab 4: Display Subdirectory Sizes

Objective: Identify which immediate subdirectories occupy the most space.

du -h --max-depth=1 ~

Expected Result: A size report for your home directory and its immediate subdirectories.

Lab 5: Sort Directories by Size

Objective: Display the largest directories first.

du -h --max-depth=1 ~ | sort -hr

Expected Result: Directories should be listed from larger to smaller reported sizes.

Lab 6: Check Inode Usage

Objective: Monitor inode utilization.

df -i

Expected Result: You should see total, used and free inode counts for mounted filesystems.

Lab 7: Find Large Files

Objective: Find files larger than 50 MB in your home directory.

find ~ -type f -size +50M

Expected Result: The command lists matching files. It may display no results if no files meet the condition.

Lab 8: Monitor Disk Usage Continuously

Objective: Observe filesystem usage in real time.

watch -n 2 df -h

Expected Result: The disk usage display refreshes every two seconds. Press Ctrl+C to stop.

These exercises use inspection commands. They do not require deleting files or modifying partitions. Practise them in your Ubuntu VirtualBox environment.

14. Interview Questions and Answers

Q1. What is filesystem monitoring?

Filesystem monitoring is the process of checking storage capacity, usage, available space and inode utilization.

Q2. Which command displays filesystem disk usage?

The df command displays filesystem disk-space usage.

Q3. What is the purpose of df -h?

It displays filesystem sizes in human-readable units such as MB and GB.

Q4. What is the purpose of the du command?

It estimates the disk space occupied by files and directories.

Q5. What is the difference between df and du?

df reports filesystem-level usage, while du estimates the usage of files and directories.

Q6. What is an inode?

An inode is a filesystem data structure containing metadata about a file or directory.

Q7. What happens when all inodes are used?

The filesystem may be unable to create additional files, even when free data blocks remain.

Q8. Which command checks inode usage?

The df -i command displays inode utilization.

Q9. How do you check the size of a directory?

Use du -sh directory_name to display its summarized disk usage.

Q10. How can you find files larger than 100 MB?

Use find /path -type f -size +100M.

Q11. What is inode exhaustion?

Inode exhaustion occurs when a filesystem has no free inodes available for creating new files.

Q12. Why can df and du show different usage values?

They measure usage differently. Differences can result from filesystem metadata, reserved blocks, open files that have been deleted, and other filesystem-specific behavior.
