1. Introduction

Linux supports a wide variety of hardware devices, including keyboards, storage devices, network adapters, USB peripherals, sensors, displays and communication controllers.

These devices do not all operate in the same way. Some transfer data as streams of bytes, some transfer data in blocks, and others exchange network packets or communicate over hardware buses.

Linux therefore provides different driver models and subsystems to support different categories of hardware.

2. Classification of Linux Device Drivers

A useful high-level classification is based on the type of device and the kernel subsystem used to manage it.

Bus and peripheral drivers include USB, I2C, SPI, platform and other subsystem-specific drivers. These categories are not all mutually exclusive: a device may participate in more than one layer of the kernel device model.

3. Character Device Drivers

3.1 Definition

A character device driver provides an interface for devices that commonly transfer data as a stream of bytes or through file-like operations.

Applications commonly access character devices using operations such as open(), read(), write() and close().

3.2 Examples

  • Serial ports.
  • Terminal devices.
  • Some sensor interfaces.
  • Input devices.
  • Custom character devices.

4. Block Device Drivers

4.1 Definition

A block device driver supports devices that store or retrieve data in addressable blocks. Block devices are commonly used for persistent storage.

4.2 Examples

  • Hard disk drives (HDDs).
  • Solid-state drives (SSDs).
  • USB mass-storage devices.
  • Memory cards.
  • Virtual block devices.

4.3 Architecture

User Application
↓
Filesystem and VFS
↓
Block Layer
↓
Block Device Driver
↓
Storage Controller and Device

4.4 Characteristics

  • Designed for storage operations.
  • Supports block-oriented I/O requests.
  • Works with the Linux block layer.
  • Can support random access to storage locations.
  • Often integrates with filesystems and storage management tools.

5. Network Device Drivers

5.1 Definition

A network device driver connects a network interface controller or virtual network interface to the Linux networking subsystem.

Unlike ordinary character drivers, network drivers primarily operate on network packets rather than exposing a simple byte-stream device interface.

5.2 Examples

  • Ethernet network adapters.
  • Wi-Fi adapters.
  • Virtual network interfaces.
  • Some cellular network interfaces.

5.3 Architecture

Network Application
↓

↓

5.4 Main Responsibilities

  • Transmit network packets.
  • Receive network packets.
  • Configure network hardware.
  • Handle device interrupts and data transfer.
  • Report interface status and statistics.

6. USB Device Drivers

6.1 Definition

USB drivers support communication with devices connected through the Universal Serial Bus.

6.2 Examples

  • USB keyboards and mice.
  • USB storage devices.
  • USB-to-serial adapters.
  • USB cameras.
  • USB communication devices.

6.3 Architecture

The USB core provides common USB functionality, while host controller drivers manage the host-side hardware.

7. I2C Device Drivers

7.1 Definition

I2C drivers support devices connected through the Inter-Integrated Circuit (I2C) bus.

7.2 Examples

  • Temperature sensors.
  • EEPROM devices.
  • Real-time clock modules.
  • GPIO expanders.
  • Some display controllers.

8. SPI Device Drivers

8.1 Definition

SPI drivers support devices connected through the Serial Peripheral Interface (SPI) bus.

8.2 Examples

  • SPI flash memory.
  • Display controllers.
  • ADC and DAC devices.
  • Communication modules.
  • Some sensors.

9. Platform Device Drivers

9.1 Definition

Platform drivers support devices that are typically integrated into a system-on-chip (SoC) and are not discovered through traditional plug-and-play buses such as USB or PCI.

9.2 Examples

  • SoC-integrated UART controllers.
  • SoC-integrated GPIO controllers.
  • Timer controllers.
  • Watchdog controllers.
  • Some memory-mapped peripheral controllers.

9.3 Important Components

Component Purpose
platform_device Represents a platform device.
platform_driver Represents a driver for platform devices.
probe() Initializes a matched device.
remove() Releases resources when the device is removed or unbound.
Device Tree Describes hardware information for supported systems.

10. Input Device Drivers

Input drivers support devices that provide user input to the operating system.

Examples

  • Keyboard.
  • Mouse.
  • Touchscreen.
  • Touchpad.
  • Joystick.

Linux provides the input subsystem, which standardizes how supported input devices report events to the operating system.

11. Graphics and Display Drivers

Graphics drivers manage graphics hardware and display-related functionality.

Examples

  • GPU drivers.
  • Display controller drivers.
  • Framebuffer drivers.
  • DRM/KMS drivers.

The Linux Direct Rendering Manager (DRM) subsystem provides infrastructure for graphics devices, memory management and display modesetting.

12. Audio Device Drivers

Audio drivers manage sound hardware and provide interfaces for recording and playback.

Examples

  • Sound cards.
  • Audio codecs.
  • Integrated audio controllers.
  • USB audio devices.

Linux commonly uses the Advanced Linux Sound Architecture (ALSA) framework for audio support.

14. How to Identify a Device Driver in Linux

Linux provides several commands and filesystem interfaces for inspecting devices and their associated drivers.

14.1 Display PCI Devices and Drivers

lspci -nnk

14.2 Display USB Devices

lsusb

14.3 Display Loaded Kernel Modules

lsmod

14.4 Display Device Information

udevadm info --query=all --name=/dev/null

14.5 Inspect Device Entries

ls -l /dev

14.6 Inspect Driver Bindings

ls /sys/bus/usb/drivers
Not every driver appears as a separately loaded module. Some drivers are compiled directly into the kernel, and some device interfaces are managed by higher-level kernel subsystems.

15. Choosing the Correct Driver Model

Selecting the correct driver model is one of the first steps in Linux device driver development.

Hardware Requirement Likely Driver Model
Custom byte-oriented device interface Character device
Storage device with block I/O Block device
Ethernet controller Network device
USB peripheral USB driver
I2C-connected sensor I2C client driver
SPI-connected display SPI device driver
SoC-integrated UART controller Platform driver, often integrated with serial subsystem

The correct choice depends on the hardware interface and the Linux subsystem responsible for that device. A developer should check whether an appropriate existing kernel subsystem already provides the required functionality.

17. Summary

  • Linux supports multiple categories of device drivers.
  • Character drivers commonly provide stream-like or file-like access.
  • Block drivers manage block-oriented storage operations.
  • Network drivers handle packet-based communication.
  • USB, I2C and SPI drivers use their respective bus subsystems.
  • Platform drivers support many SoC-integrated devices.
  • Input, graphics and audio drivers use specialized kernel frameworks.
  • Choosing the correct subsystem is essential for driver development.
