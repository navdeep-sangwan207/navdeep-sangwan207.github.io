1. Definition of a Device Driver

A device driver is a specialized software component that enables an operating system to communicate with and control a hardware device.

Every hardware device has its own operating characteristics. It may use specific registers, communication protocols, commands, interrupts and data formats. The driver implements the device-specific operations required by the operating system.

In Linux, many device drivers are implemented as part of the kernel. Some are built directly into the kernel, while others can be compiled as loadable kernel modules.

Example: A UART controller contains registers used to configure baud rate, transmit data and receive data. A UART driver understands how to configure and operate that controller through the appropriate Linux serial subsystem.

2. Device Driver as an Interface

A device driver provides an interface between the operating system and a hardware device. It translates higher-level operations into device-specific actions.

For example, an application does not normally need to know the register addresses of a storage controller. It requests a file operation, and the filesystem, block layer and storage driver coordinate the request.

Important: The driver is not always the only component between an application and hardware. Linux kernel subsystems often provide common interfaces and coordinate requests before they reach a particular driver.

3. Hardware and Software Relationship

A computer system contains several layers of hardware and software. A device driver connects the operating system's software architecture to the capabilities of a hardware device.

Hardware Components

  • CPU and memory controller
  • UART and serial communication controllers
  • GPIO controllers
  • ADC and DAC peripherals
  • Timers and counters
  • I2C and SPI controllers
  • Storage and network controllers

Software Components

  • Applications
  • Libraries
  • System calls
  • Linux kernel subsystems
  • Device drivers
  • Device firmware, where applicable

The driver uses suitable kernel interfaces to interact with the device. Depending on the hardware, this can involve memory-mapped registers, I/O ports, DMA, interrupts or bus communication.

4. How Does a Device Driver Communicate with Hardware?

A driver communicates with hardware using mechanisms supported by the processor, platform and Linux kernel. The exact mechanism depends on the device.

4.1 Memory-Mapped I/O (MMIO)

In memory-mapped I/O, device registers are assigned addresses in the processor's address space. A driver accesses these registers through appropriate kernel I/O access functions.

Common Linux access functions include:

  • ioremap() - maps a device memory resource.
  • readl() - reads a 32-bit value from an I/O address.
  • writel() - writes a 32-bit value to an I/O address.

4.2 Interrupts

A hardware device can generate an interrupt to notify the processor that an event requires attention. A driver registers an interrupt handler to process the event according to the device and kernel design.

4.3 Direct Memory Access (DMA)

DMA allows a device to transfer data to or from memory without requiring the CPU to copy every data item. Linux drivers use the DMA API to manage DMA mappings and buffers correctly.

4.4 Bus Communication

Peripheral devices may communicate through interfaces such as I2C, SPI, USB or PCIe. Linux provides dedicated subsystems and APIs for many of these interfaces.

Interrupts Notify CPU of device events Receive-data event

5. Example: UART Device Driver

A UART (Universal Asynchronous Receiver/Transmitter) is a hardware peripheral used for serial communication. It transmits and receives data using TX and RX signals.

UART Driver Responsibilities

  • Configure the UART controller.
  • Set the baud rate and communication parameters.
  • Configure transmission and reception.
  • Handle transmit and receive events.
  • Manage interrupts where required.
  • Integrate with the Linux serial subsystem.
User Application
↓
TTY / Serial Subsystem
↓
UART Driver
↓
UART Hardware Registers
↓
TX and RX Pins

In Linux, UART controller drivers commonly integrate with the serial core. Applications can then access serial interfaces through device nodes such as /dev/ttyS0 or /dev/ttyUSB0, depending on the hardware and driver.

The actual device name depends on the platform and connected hardware. Not every UART device appears as /dev/ttyS0.

6. Types of Device Driver Software

Linux drivers can be organized according to the type of device they support and the kernel subsystem through which they operate.

  • Character drivers: Support character-oriented device interfaces.
  • Block drivers: Support block-based storage devices.
  • Network drivers: Support network interfaces and packet transmission.
  • USB drivers: Support USB devices and interfaces.
  • Platform drivers: Support devices integrated into a system platform.
  • I2C drivers: Support peripherals connected through the I2C subsystem.
  • SPI drivers: Support peripherals connected through the SPI subsystem.

These categories are not all mutually exclusive. For example, an I2C sensor driver may expose data through a subsystem such as IIO rather than directly implementing a character device interface.

7. Device Driver in Linux Kernel Space

Most Linux kernel device drivers execute in kernel space. Kernel space has access to kernel services and privileged hardware-management facilities.

A kernel driver can use kernel APIs for memory allocation, synchronization, interrupt handling, device registration and resource management.

Some hardware-related software also operates in user space. These include device-management services, hardware access frameworks and user-space drivers for particular architectures.

Remember: A Linux device driver is not necessarily a standalone program. It commonly participates in a kernel subsystem and follows the subsystem's driver model.

8. Kernel Module Example

The following is a simple Linux kernel module. It demonstrates how kernel code can be initialized and cleaned up. It is not yet a hardware device driver.

Source Code: hello.c

#include <linux/module.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello: Kernel module loaded\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello: Kernel module removed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic Linux kernel module example");

Explanation

  • linux/module.h provides module-related definitions.
  • linux/init.h provides initialization and exit annotations.
  • hello_init() executes when the module is loaded.
  • hello_exit() executes when the module is removed.
  • module_init() registers the initialization function.
  • module_exit() registers the cleanup function.
  • pr_info() writes an informational kernel log message.
  • MODULE_LICENSE() declares the module's license.
This example is a kernel module foundation, not a complete device driver. Device registration and hardware operations will be introduced in later lessons.

9. Device Driver vs Firmware

Device Driver Firmware
Software that enables OS communication with hardware. Low-level software stored in or loaded onto a device.
Often executes as part of the operating system. Executes on the device processor or controller, depending on the design.
Uses OS and kernel interfaces. Controls device-specific behavior and internal operations.
Example: Linux UART driver. Example: Firmware running inside a network adapter.

A device may require both firmware and an operating system driver. The driver communicates with the device, while the firmware may control internal device operations.

10. Advantages of Device Drivers

  • Provide a standard interface for hardware operations.
  • Reduce hardware-specific complexity for applications.
  • Support device initialization and configuration.
  • Enable efficient data transfer mechanisms.
  • Allow hardware-specific functionality to integrate with kernel subsystems.
  • Support device error handling and resource management.
  • Enable reuse of common operating-system interfaces.

11. Lesson Summary

  • A device driver is software that controls or communicates with hardware through an operating system.
  • Drivers translate operating-system requests into device-specific operations.
  • Linux provides kernel subsystems and APIs for driver development.
  • Drivers may use MMIO, interrupts, DMA and communication buses.
  • Most kernel device drivers execute in kernel space.
  • Linux supports built-in drivers and loadable kernel modules.
  • Firmware and device drivers have different roles.
