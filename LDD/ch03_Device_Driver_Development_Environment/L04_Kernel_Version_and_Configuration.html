1. Introduction

Before developing a Linux device driver, it is important to understand which Linux kernel version is running on the system and how that kernel has been configured.

The kernel version identifies a particular kernel release. Kernel configuration determines which features, subsystems, drivers and capabilities are enabled or disabled when the kernel is built.

These details are important because kernel module compilation and driver compatibility depend on the target kernel's version, configuration and available interfaces.

2. What Is a Linux Kernel Version?

A Linux kernel version identifies a specific release of the Linux kernel.

Kernel releases contain improvements, bug fixes, security updates, new hardware support and changes to internal interfaces.

Different Linux distributions may use different kernel versions depending on their release and update policy.

Example kernel release

6.8.0-xx-generic

This is an illustrative format. The actual version on your Ubuntu system may be different.

3. Understanding Kernel Version Components

A kernel release string can contain several components.

ComponentExampleMeaning
Upstream version6.8.0Identifies the upstream kernel release.
Distribution revision-xxIdentifies a distribution-specific build revision.
Flavor-genericIdentifies a kernel build variant.

The exact naming convention depends on the Linux distribution and its packaging system.

Important: The kernel release string is not necessarily the same as the complete upstream kernel version. Distribution vendors may apply additional patches and package revisions.

4. Checking the Running Kernel Version

The uname command displays system and kernel information.

Command 1: Display kernel release

uname -r

This displays the release string of the currently running kernel.

Command 2: Display complete system information

uname -a

This displays the kernel name, hostname, kernel release, kernel version, machine architecture and other information.

Command 3: Display kernel name

uname -s

On a standard Linux system, the output is:

Linux

Command 4: Display machine architecture

uname -m

Examples include x86_64 and aarch64.

5. Kernel Version vs Kernel Build Version

There are two related but different pieces of information:

  • Kernel release: The release identifier used in paths such as /lib/modules/.
  • Kernel version: Additional build information, often including the build number, compiler and build date.

Use the following command to inspect the kernel version information:

cat /proc/version

Example output may contain the Linux kernel release, compiler information and build details.

6. What Is Kernel Configuration?

Kernel configuration is a collection of settings that determines which features are included or enabled in a kernel build.

It controls options such as:

  • Supported processor architectures.
  • Device driver support.
  • Filesystem support.
  • Networking features.
  • Power management.
  • Kernel debugging options.
  • Loadable module support.
  • Hardware interface subsystems.

Kernel configuration is generally selected before building the kernel.

7. Understanding Kernel Configuration Options

Kernel configuration options commonly have three states:

Configuration stateMeaning
yFeature is built directly into the kernel.
mFeature is built as a loadable kernel module, when modular support is available.
nFeature is disabled.

Example

CONFIG_MODULES=y
CONFIG_SOME_DRIVER=m
CONFIG_SOME_FEATURE=n

In this illustrative example:

  • Loadable module support is enabled.
  • A particular driver is configured as a module.
  • A particular feature is disabled.

Actual configuration option names depend on the kernel version and selected subsystem.

8. Where Is the Kernel Configuration Stored?

On many Linux systems, the kernel configuration used to build the running kernel is available at:

/boot/config-$(uname -r)

Check whether the file exists:

ls -l /boot/config-$(uname -r)

To inspect the configuration:

less /boot/config-$(uname -r)

Search for a particular configuration option:

grep CONFIG_MODULES /boot/config-$(uname -r)

Typical output when loadable module support is enabled:

CONFIG_MODULES=y

The file may not be present on every system. Some distributions provide the configuration through other mechanisms or package locations.

9. Understanding the /proc/config.gz File

Some kernel builds provide the running kernel configuration through a compressed file:

/proc/config.gz

Check whether it exists:

ls -l /proc/config.gz

If available, inspect a configuration option with:

zcat /proc/config.gz | grep CONFIG_MODULES

This interface depends on the kernel configuration option CONFIG_IKCONFIG_PROC. It may not be enabled on every system.

10. Important Kernel Configuration Options for Driver Development

Configuration optionPurpose
CONFIG_MODULESEnables loadable kernel module support.
CONFIG_MODULE_UNLOADEnables unloading of supported modules.
CONFIG_DEBUG_KERNELEnables various kernel debugging facilities.
CONFIG_KALLSYMSProvides kernel symbol information useful for diagnostics.
CONFIG_PROC_FSEnables the proc filesystem.
CONFIG_SYSFSEnables the sysfs filesystem.
CONFIG_I2CEnables the I2C subsystem.
CONFIG_SPIEnables the SPI subsystem.
CONFIG_GPIOLIBEnables GPIO library support.

These options are examples of configuration settings relevant to different driver development tasks. Not every driver requires all of them.

11. What Is the .config File?

The .config file stores the selected configuration options used during a kernel build.

It is commonly located in the root directory of a kernel source tree.

linux-source/
|
|-- .config
|-- Makefile
|-- Kbuild
|-- arch/
|-- drivers/
|-- include/
|-- kernel/

The kernel build system uses these configuration choices to determine which parts of the kernel should be built.

For an external module developer, the prepared build directory must contain the appropriate configuration and generated build information.

12. Kernel Configuration Tools

The Linux kernel provides several configuration interfaces.

ToolDescription
make menuconfigText-based menu interface for selecting kernel options.
make nconfigAlternative text-based configuration interface.
make xconfigGraphical configuration interface, when required graphical dependencies are installed.
make oldconfigUpdates an existing configuration for a newer kernel source tree.
make defconfigGenerates a default configuration for the selected architecture.

These commands are generally used when configuring a kernel source tree for a kernel build. They are not required for every external module compilation task.

13. Kernel Version Compatibility and Device Drivers

Kernel versions can differ in their internal APIs, structures and function interfaces. A driver written for one kernel version may need modifications to compile or work correctly on another.

Compatibility depends on factors such as:

  • Kernel API changes.
  • Kernel configuration.
  • Available exported symbols.
  • Processor architecture.
  • Compiler and build environment.
  • Module signature and security policies.

Important: Matching the kernel release and build configuration is essential, but it does not guarantee that every driver will be compatible. The driver must also use valid APIs and exported symbols.

14. Checking Kernel Module Support

Before developing external modules, check whether loadable module support is enabled.

Check the kernel configuration

grep CONFIG_MODULES /boot/config-$(uname -r)

Expected result when module support is enabled:

CONFIG_MODULES=y

Check the module directory

ls /lib/modules/$(uname -r)/

List currently loaded modules

lsmod

The lsmod command displays currently loaded kernel modules. It does not display every driver built directly into the kernel.

15. Kernel Configuration and External Module Development

For external module development, the kernel build environment must be prepared using the appropriate configuration and generated files.

The kernel build directory normally contains or references:

  • Kernel configuration information.
  • Generated headers.
  • Architecture-specific definitions.
  • Kernel build scripts.
  • Makefiles and Kbuild rules.
  • Symbol version information, when configured.

These components allow Kbuild to compile an external module against the selected kernel build.

For Ubuntu, the prepared build directory is usually accessed through:

/lib/modules/$(uname -r)/build

17. Common Problems and Troubleshooting

Problem 1: Configuration file not found

Possible reason: The distribution may not have installed the kernel configuration file at the expected path.

Solution: Check whether /proc/config.gz is available or consult the distribution's kernel package.

Problem 2: CONFIG_MODULES is not enabled

Possible reason: The kernel was built without loadable module support.

Solution: A kernel with module support is required for loading external modules. Use an appropriate kernel build with module support enabled.

Problem 3: Kernel headers do not match

Possible reason: The build environment belongs to another kernel release.

Solution: Verify the running kernel version and the target build directory.

Problem 4: Configuration option is not found

Possible reason: The option may not exist in that kernel version, may have a different name or may be unavailable in the installed configuration.

Solution: Check the relevant kernel source tree and configuration for the target version.

18. Important Points to Remember

  • uname -r displays the running kernel release.
  • uname -a displays detailed kernel and system information.
  • Kernel configuration determines which kernel features are enabled.
  • y means built into the kernel, m means built as a module and n means disabled.
  • The .config file stores kernel build configuration.
  • CONFIG_MODULES=y enables loadable module support.
  • Kernel configuration can affect which driver interfaces are available.
  • External modules should be built against the correct prepared kernel build environment.
