1. Introduction

Linux device driver development involves compiling C source files into kernel modules. As projects become larger, manually compiling every source file becomes difficult.

GNU Make and Makefiles automate the compilation process. The Linux kernel uses a specialized build system called Kbuild, which works with Make to compile kernel source code and external kernel modules.

In this lesson, we will understand Makefile syntax, targets, dependencies, variables and the Kbuild process used for Linux device driver development.

2. What Is GNU Make?

GNU Make is a build automation utility. It reads instructions from a file called a Makefile and executes the required commands.

It helps automate tasks such as:

  • Compiling source files.
  • Building object files.
  • Linking programs.
  • Managing file dependencies.
  • Removing generated files.
  • Rebuilding files when their dependencies change.

Check Make installation

make --version

3. What Is a Makefile?

A Makefile is a text file containing instructions used by GNU Make to build a project.

A Makefile normally contains rules made up of a target, prerequisites and commands.

General syntax

target: prerequisites
	command
ElementMeaning
TargetThe file or task to be built.
PrerequisitesFiles required to build the target.
CommandInstruction executed by Make.

Important: A command line under a traditional Makefile rule must begin with a tab character, not ordinary spaces.

4. Simple Makefile Example

Consider a simple C program.

Source file: hello.c

#include <stdio.h>

int main(void)
{
    printf("Hello from Makefile\n");
    return 0;
}

Makefile

CC = gcc
CFLAGS = -Wall

hello: hello.c
	$(CC) $(CFLAGS) hello.c -o hello

clean:
	rm -f hello

Build the program

make

Run the program

./hello

Expected output:

Hello from Makefile

Clean generated files

make clean

This example demonstrates GNU Make for a normal user-space application. Kernel module Makefiles use Kbuild-specific conventions.

5. Understanding Makefile Variables

Variables allow developers to store values that can be reused in Makefile rules.

Example

CC = gcc
CFLAGS = -Wall -Wextra
TARGET = program
SOURCE = main.c

$(TARGET): $(SOURCE)
	$(CC) $(CFLAGS) $(SOURCE) -o $(TARGET)

Explanation

  • CC stores the compiler command.
  • CFLAGS stores compiler options.
  • TARGET stores the output filename.
  • SOURCE stores the source filename.
  • $(VARIABLE) accesses a Makefile variable.

6. Makefile Targets

A target identifies the task that Make should perform.

Common targets include:

TargetPurpose
allBuilds the default set of project outputs.
cleanRemoves generated files.
installInstalls a project when installation rules are provided.
modulesUsed by the kernel build system to build modules.

Targets such as all, clean and install are conventions rather than mandatory names in every project.

7. Makefile Dependencies

Dependencies describe which files are required to build a target.

Example

program: main.o math.o
	gcc main.o math.o -o program

main.o: main.c
	gcc -c main.c -o main.o

math.o: math.c
	gcc -c math.c -o math.o

In this example:

  • program depends on main.o and math.o.
  • main.o depends on main.c.
  • math.o depends on math.c.

Make checks timestamps and rebuilds targets when required prerequisites have changed.

8. What Is Kbuild?

Kbuild is the Linux kernel build system. It provides the rules and configuration required to compile the Linux kernel and external kernel modules.

It coordinates:

  • Compiler invocation.
  • Kernel header paths.
  • Architecture-specific settings.
  • Generated configuration headers.
  • Object file creation.
  • Module linking and preparation.
  • Kernel symbol information.

9. Kbuild vs Ordinary Makefile

Ordinary MakefileKernel Kbuild Makefile
Used for general software builds.Used for Linux kernel and module builds.
Usually specifies compiler commands directly.Uses kernel-defined build rules.
Uses normal application compilation settings.Uses kernel-specific compilation settings.
Builds ordinary executables and libraries.Builds kernel objects and loadable modules.
Does not automatically provide kernel build configuration.Uses the selected kernel build environment.

Both systems use Makefile syntax, but their build responsibilities are different.

10. External Kernel Module Makefile

An external kernel module is developed outside the main Linux kernel source tree.

A basic external module Makefile can contain:

obj-m += my_driver.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Explanation

StatementPurpose
obj-m += my_driver.oRequests Kbuild to build the external module object.
all:Defines the default Make target.
-CChanges to the kernel build directory before running Make.
$(shell uname -r)Runs the shell command and inserts the running kernel release.
M=$(PWD)Specifies the external module source directory.
modulesRequests external module compilation.
cleanInvokes the kernel build system's cleanup target for this module directory.

Note: The Makefile uses a tab before each command line. The exact kernel build directory must exist and be prepared for the target kernel.

11. Understanding obj-m

obj-m is a Kbuild variable used to identify external modules that should be built as loadable kernel modules.

Example

obj-m += my_driver.o

This tells Kbuild to build my_driver.o as a loadable module target.

The resulting module is generally named:

my_driver.ko

The source file is normally my_driver.c, which Kbuild compiles as part of the module build.

12. Building a Module from Multiple Source Files

A driver may contain multiple source files. Kbuild supports combining these files into a single module.

Example project structure

my_driver/
|
|-- Makefile
|-- main.c
|-- hardware.c
|-- hardware.h

Makefile

obj-m += my_driver.o

my_driver-y := main.o hardware.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Here, my_driver-y identifies the component object files that Kbuild combines into the module.

Other Kbuild composition variables exist for specialized cases, but this is a common pattern for a multi-file external module.

13. Understanding the M Variable

The M variable identifies the directory containing the external module source and its Kbuild Makefile.

Example

make -C /lib/modules/$(uname -r)/build M=$PWD modules

If the current directory is:

/home/user/my_driver

then $PWD expands to that directory path.

Kbuild uses this location to find the external module's Makefile and source files.

14. Building an External Module Using Kbuild

Once the module source file and Makefile are ready, execute:

make -C /lib/modules/$(uname -r)/build M=$PWD modules

To remove generated files:

make -C /lib/modules/$(uname -r)/build M=$PWD clean

The first command invokes Kbuild to compile the module. The second invokes its cleanup rules.

Successful compilation normally produces a .ko file along with intermediate build files.

15. Dry Run and Verbose Build

GNU Make provides options that help developers inspect build operations.

Dry run

make -n

Displays the commands Make would execute without running them.

Verbose kernel module build

make V=1 -C /lib/modules/$(uname -r)/build M=$PWD modules

The V=1 option requests more detailed build command output from the kernel build system.

This is useful when investigating compiler flags and build failures.

16. Common Make and Kbuild Errors

Problem 1: No rule to make target

Possible reason: The requested target or prerequisite is missing or incorrectly named.

Solution: Check the Makefile target names and required source files.

Problem 2: Missing kernel build directory

Possible reason: Matching kernel headers are not installed.

Solution:

sudo apt install linux-headers-$(uname -r)

Problem 3: Missing separator

Possible reason: A command line in the Makefile begins with spaces instead of a tab.

Solution: Replace the leading spaces with a tab character.

Problem 4: Module source file not found

Possible reason: The source filename in the Kbuild variable does not match the actual file.

Solution: Verify the source filename and Makefile entries.

Problem 5: Compiler errors

Possible reason: Incorrect kernel API usage, missing headers or incompatible source code.

Solution: Examine the first meaningful compiler error and verify the target kernel interfaces.

17. Practical Exercise: Create a Kernel Module Makefile

Objective: Create an external kernel module Makefile and understand how Kbuild is invoked.

Step 1: Create a project directory

mkdir ~/my_first_module
cd ~/my_first_module

Step 2: Create the source file

nano my_driver.c

Enter the following code:

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init my_driver_init(void)
{
    pr_info("My driver: module loaded\n");
    return 0;
}

static void __exit my_driver_exit(void)
{
    pr_info("My driver: module unloaded\n");
}

module_init(my_driver_init);
module_exit(my_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic external kernel module");

Step 3: Create the Makefile

nano Makefile

Enter the following contents:

obj-m += my_driver.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Step 4: Compile the module

make

Here, the default all target invokes Kbuild.

Step 5: Inspect generated files

ls -l

After a successful build, look for:

my_driver.ko

Step 6: Clean generated files

make clean

Expected Result: Kbuild should compile the source file and generate my_driver.ko, provided the matching headers and required build tools are installed.

Safety note: This exercise only builds a module. Loading it into the kernel is covered in a later lesson. Kernel modules execute with kernel privileges, so only load code you understand and trust.

18. Important Points to Remember

  • GNU Make automates software compilation.
  • A Makefile contains targets, prerequisites and commands.
  • Traditional Makefile command lines must begin with a tab.
  • Kbuild is the Linux kernel build system.
  • obj-m identifies external loadable module targets.
  • M specifies the external module directory.
  • modules requests module compilation.
  • clean removes generated build files.
  • V=1 enables more detailed build output.
  • Kernel modules should be compiled using Kbuild.
