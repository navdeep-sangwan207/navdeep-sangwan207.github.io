1. Introduction

Linux device drivers interact directly with the Linux kernel. To develop a kernel module or device driver, a developer needs access to the kernel interfaces, data structures, function declarations and configuration information.

Linux kernel headers provide the declarations and definitions required to compile code that interacts with the kernel. The complete Linux kernel source code contains the implementation of kernel subsystems, internal functions, architecture-specific code and device driver frameworks.

Understanding the difference between kernel headers and kernel source is an important step in preparing a Linux device driver development environment.

2. What Are Linux Kernel Headers?

Linux kernel headers are files that contain declarations, definitions, macros, data types and structures used by kernel-related programs.

They provide the compiler with information about kernel interfaces used by a module.

Examples of kernel header files

Header filePurpose
linux/module.hKernel module initialization, cleanup and metadata.
linux/kernel.hCommon kernel definitions and utility macros.
linux/init.hInitialization and cleanup annotations.
linux/fs.hFilesystem and file operation interfaces.
linux/slab.hKernel memory allocation interfaces.
linux/uaccess.hUser-space and kernel-space data transfer functions.
linux/interrupt.hInterrupt handling interfaces.

These headers are used according to the functionality required by a particular driver.

3. What Is Linux Kernel Source Code?

The Linux kernel source code is the complete collection of source files used to build the Linux kernel.

It contains the implementation of:

  • Process scheduling and process management.
  • Memory management.
  • Device driver frameworks.
  • Filesystem implementations.
  • Networking subsystems.
  • Interrupt handling.
  • Architecture-specific operations.
  • Kernel synchronization mechanisms.

The source code is useful when studying kernel internals, understanding driver APIs, debugging driver behavior and building or modifying a kernel.

Example

The implementation of a particular subsystem can be studied by examining its source files. For example, character device infrastructure is implemented in the kernel source tree under the relevant character-device and filesystem code.

4. Kernel Headers vs Kernel Source

Kernel Headers Kernel Source
Contain declarations and definitions needed for compilation. Contain the broader implementation of the Linux kernel.
Usually installed as a development package. Obtained from a kernel source tree or source package.
Used to compile external kernel modules. Used for kernel development, source study and kernel builds.
Smaller in scope. Much larger and includes headers and implementation files.

Important: For building an external kernel module, the matching kernel build directory and its prepared headers are generally sufficient. You do not always need to download and compile the entire kernel source tree.

6. Understanding the include Directory

The include/ directory contains many of the kernel header files. It is important for driver developers because it exposes declarations and interfaces used by kernel code.

Some important subdirectories are:

  • include/linux/ – General Linux kernel headers.
  • include/uapi/ – Headers intended for user-space interfaces.
  • include/asm-generic/ – Generic architecture-related header definitions.
  • include/trace/ – Tracing-related interfaces.

Architecture-specific headers may also be provided through architecture directories and generated header paths.

7. Kernel Headers Required for External Modules

An external kernel module is a module developed outside the main kernel source tree. It is compiled separately and loaded into a running kernel when supported.

For successful compilation, the build environment must provide headers and build configuration that match the target kernel.

Kernel Module Source
↓
Matching Kernel Build Headers
↓
Kernel Build System (Kbuild)
↓
Compiled .ko Module

A mismatch between the running kernel and the headers used for compilation can cause compatibility problems or prevent the module from loading.

8. Checking the Running Kernel Version

Before installing or using kernel headers, identify the running kernel version.

uname -r

Example output:

6.x.x-xx-generic

The exact output depends on the installed Ubuntu kernel.

To display additional kernel information, use:

uname -a

This command displays the kernel name, hostname, kernel release, kernel version, machine architecture and other information.

9. Checking Installed Kernel Headers

On Ubuntu, kernel headers are commonly installed through APT packages.

Check whether the build directory for the running kernel exists:

ls -l /lib/modules/$(uname -r)/build

The build entry usually points to the kernel header/build directory associated with the running kernel.

You can also inspect installed header packages:

dpkg -l | grep linux-headers

To inspect the current kernel's module directory:

ls /lib/modules/$(uname -r)/

10. Installing Matching Kernel Headers in Ubuntu

For Ubuntu systems, the following commands install the build tools and headers for the currently running kernel.

sudo apt update

sudo apt install build-essential

sudo apt install linux-headers-$(uname -r)

Explanation

  • sudo apt update refreshes package information.
  • build-essential installs common development tools, including GCC and Make.
  • linux-headers-$(uname -r) requests the headers matching the running kernel release.

If the exact headers package is unavailable, check whether the system is using a custom kernel, an unsupported repository configuration or a kernel version whose headers are not available from the configured package sources.

11. Understanding the Kernel Build Directory

External modules commonly use the kernel build directory through the Makefile.

/lib/modules/$(uname -r)/build

This path generally refers to the prepared kernel build environment. It provides the required build configuration, generated headers and build scripts.

To inspect the path:

readlink -f /lib/modules/$(uname -r)/build

The resolved path may point to a directory under /usr/src/.

12. Introduction to Kernel Header Files in a Module

Consider a simple kernel module that uses the module and kernel logging interfaces.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init my_driver_init(void)
{
    pr_info("My driver: module loaded\n");
    return 0;
}

static void __exit my_driver_exit(void)
{
    pr_info("My driver: module unloaded\n");
}

module_init(my_driver_init);
module_exit(my_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Linux Driver Developer");
MODULE_DESCRIPTION("Simple example kernel module");

Header file explanation

HeaderPurpose in this example
linux/module.hModule macros and metadata declarations.
linux/kernel.hKernel utility definitions and logging interfaces.
linux/init.hInitialization and exit annotations.

Note: This is kernel-space code. It is not a normal user-space C program and should be compiled using the kernel build system rather than a command such as gcc module.c.

13. Kernel Headers and User-Space Headers

Linux has different header interfaces for user-space applications and kernel-space development.

User-space headersKernel development headers
Used by normal applications.Used by kernel code and external modules.
Commonly located under /usr/include/.Provided through kernel source and prepared build directories.
Support application programming interfaces such as standard C and POSIX interfaces.Provide kernel interfaces, data structures and build definitions.
Compiled as user-space programs.Compiled using the kernel build system.

Do not assume that installing the standard C development headers is sufficient for kernel module development. Kernel module compilation requires the appropriate kernel build headers.

14. Common Problems and Troubleshooting

Problem 1: Build directory does not exist

ls /lib/modules/$(uname -r)/build

Possible cause: matching kernel headers are not installed.

Solution: install the matching headers package where available.

Problem 2: Kernel version mismatch

Possible cause: the module is being built against headers for a different kernel version.

Solution: compare uname -r with the kernel build directory being used.

Problem 3: Missing header file

Possible cause: an incorrect include statement, incomplete build environment or use of an unavailable internal header.

Solution: verify the header path and the kernel version's available interfaces.

Problem 4: Module loads unsuccessfully

Possible cause: kernel ABI or symbol compatibility problems, missing dependencies, module signature enforcement or an initialization error.

Solution: inspect the kernel log with:

sudo dmesg | tail -30

15. Practical Exercise: Inspect Kernel Headers

Objective: Identify the running kernel version and inspect the matching kernel header/build directory in Ubuntu.

Commands

# Step 1: Check the running kernel
uname -r

# Step 2: Check system architecture
uname -m

# Step 3: Check the module directory
ls /lib/modules/$(uname -r)/

# Step 4: Check the kernel build directory
ls -l /lib/modules/$(uname -r)/build

# Step 5: Resolve the build directory path
readlink -f /lib/modules/$(uname -r)/build

# Step 6: List installed kernel headers
dpkg -l | grep linux-headers

Expected Result

  • The running kernel release is displayed.
  • The system architecture is displayed.
  • The kernel module directory is listed.
  • The build directory is identified if matching headers are installed.
  • Installed kernel header packages are displayed.

If the build directory is missing, install the matching headers before attempting the external module compilation exercise in the next lessons.

16. Important Points to Remember

  • Kernel headers provide declarations and definitions required for kernel development.
  • Kernel source code contains the implementation of Linux kernel subsystems.
  • The include/ directory contains important kernel headers.
  • The drivers/ directory contains kernel device driver implementations.
  • External modules require a suitable prepared kernel build environment.
  • Kernel headers should match the target kernel version and configuration.
  • Kernel modules must be compiled using Kbuild.
  • User-space headers and kernel development headers serve different purposes.
