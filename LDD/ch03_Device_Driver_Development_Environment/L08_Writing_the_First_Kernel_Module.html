1. Introduction

A Linux kernel module is a piece of code that can be dynamically loaded into the running Linux kernel and removed when it is no longer required.

Kernel modules extend kernel functionality without requiring the entire kernel to be rebuilt and rebooted for every change.

Examples include:

  • Device drivers.
  • Filesystem support.
  • Network-related modules.
  • Hardware interface modules.
  • Kernel extensions and utilities.

In this lesson, we will write our first Linux kernel module using C, compile it as a .ko file and understand its initialization and cleanup functions.

2. What Is a Kernel Module?

A kernel module is compiled kernel code that can be loaded into the Linux kernel at runtime.

Unlike a normal user-space application, a kernel module executes in kernel space and can access kernel services and interfaces.

Normal application vs kernel module

Normal C ApplicationKernel Module
Runs in user space.Runs in kernel space.
Usually compiled into an executable.Compiled into a loadable .ko file.
Uses standard C library functions.Uses kernel APIs and headers.
Uses main() as its entry point.Uses registered initialization and cleanup functions.
Can use ordinary application I/O.Uses kernel logging and kernel interfaces.

Important: Kernel modules must follow kernel programming rules. They cannot use ordinary user-space library functions such as printf() or malloc() in the same way as a normal application.

4. Structure of a Basic Kernel Module

A simple kernel module normally contains:

  1. Required kernel header files.
  2. Initialization function.
  3. Cleanup function.
  4. Module initialization registration.
  5. Module cleanup registration.
  6. Module metadata.

General structure

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

/* Initialization function */
static int __init my_init(void)
{
    return 0;
}

/* Cleanup function */
static void __exit my_exit(void)
{
}

module_init(my_init);
module_exit(my_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Author Name");
MODULE_DESCRIPTION("Basic Linux Kernel Module");

5. Kernel Header Files

Kernel modules include kernel header files to access kernel declarations and APIs.

Header FilePurpose
linux/module.hProvides module-related declarations and metadata macros.
linux/kernel.hProvides commonly used kernel declarations and utilities.
linux/init.hProvides initialization and exit annotations.

Header inclusion example

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

These are kernel headers, not standard C library headers.

6. Initialization Function

The initialization function executes when the module is successfully loaded into the kernel.

It is commonly used to:

  • Initialize module data.
  • Register a device driver.
  • Allocate required resources.
  • Register interfaces with kernel subsystems.
  • Display an initialization message.

Example

static int __init my_init(void)
{
    pr_info("My module loaded successfully\n");
    return 0;
}

Explanation

  • static limits the function's visibility to its source file.
  • int is the return type.
  • __init marks initialization code.
  • my_init() is the function name.
  • pr_info() writes an informational message to the kernel log.
  • return 0 indicates successful initialization.

If initialization fails, the function can return a negative error code. The module will not be successfully loaded.

7. Cleanup Function

The cleanup function executes when a module is successfully removed from the kernel.

It is used to release resources and undo registrations made during initialization.

Example

static void __exit my_exit(void)
{
    pr_info("My module removed successfully\n");
}

Common cleanup responsibilities

  • Unregistering a device driver.
  • Releasing allocated memory.
  • Freeing interrupt registrations.
  • Removing device interfaces.
  • Releasing resources owned by the module.

A cleanup function is essential when the module can be unloaded. It must correctly reverse the resources and registrations established during initialization.

8. Understanding __init and __exit

__init and __exit are kernel annotations used to identify initialization and cleanup code.

AnnotationPurpose
__initMarks initialization code. For built-in kernel code, its memory can be reclaimed after initialization.
__exitMarks exit code. For built-in code, it may be discarded because built-in kernel code is not unloaded.

For a loadable module, the exit function is needed when the module is removed, so its cleanup code must remain available while the module is loaded.

9. module_init() Macro

The module_init() macro identifies the function that should be called when a loadable module is initialized.

Syntax

module_init(function_name);

Example

static int __init my_init(void)
{
    pr_info("Module initialization\n");
    return 0;
}

module_init(my_init);

When the module is loaded, the kernel invokes the registered initialization function.

10. module_exit() Macro

The module_exit() macro identifies the cleanup function for a loadable module.

Syntax

module_exit(function_name);

Example

static void __exit my_exit(void)
{
    pr_info("Module cleanup\n");
}

module_exit(my_exit);

When the module is removed, the kernel invokes the registered cleanup function, provided the module can be safely unloaded.

11. Kernel Logging with pr_info()

Kernel modules do not normally use the user-space printf() function. Instead, they use kernel logging functions.

pr_info() writes a message at informational log level.

Example

pr_info("Hello Linux Kernel\n");

Other commonly used logging functions include:

FunctionPurpose
pr_emerg()Emergency message.
pr_alert()Alert message.
pr_crit()Critical message.
pr_err()Error message.
pr_warn()Warning message.
pr_notice()Notice message.
pr_info()Informational message.
pr_debug()Debug message.

Kernel messages can be inspected using:

sudo dmesg

12. Module Metadata

Module metadata describes the module and provides information to kernel module management utilities.

Common metadata macros

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("First Linux Kernel Module");
MODULE_VERSION("1.0");
MacroPurpose
MODULE_LICENSE()Declares the module's license.
MODULE_AUTHOR()Specifies the author.
MODULE_DESCRIPTION()Provides a short description.
MODULE_VERSION()Specifies a module version string.

Use an accurate license declaration that matches the actual licensing of the source code. The license also affects how the kernel treats the module's access to GPL-only exported symbols.

13. Complete First Kernel Module Program

Now combine all the concepts into a complete kernel module.

File: hello_module.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello Module: Initialization started\n");
    pr_info("Hello Module: Module loaded successfully\n");

    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello Module: Cleanup started\n");
    pr_info("Hello Module: Module removed successfully\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("My First Linux Kernel Module");
MODULE_VERSION("1.0");

Program explanation

  1. Kernel header files are included.
  2. hello_init() is defined as the initialization function.
  3. Informational messages are written to the kernel log.
  4. The initialization function returns zero to indicate success.
  5. hello_exit() is defined as the cleanup function.
  6. module_init() registers the initialization function.
  7. module_exit() registers the cleanup function.
  8. Module metadata is declared.

14. Create the Makefile

Create a file named Makefile in the same directory as hello_module.c.

obj-m += hello_module.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The Makefile instructs Kbuild to compile the source file as an external kernel module.

15. Compile the First Kernel Module

Step 1: Create the project directory

mkdir -p ~/Linux_Driver_Projects/hello_module
cd ~/Linux_Driver_Projects/hello_module

Step 2: Create the source file

nano hello_module.c

Enter the complete program from Section 13.

Step 3: Create the Makefile

nano Makefile

Enter the Makefile from Section 14.

Step 4: Compile

make

Step 5: Verify the output

ls -l hello_module.ko

Expected result: the compiled module file hello_module.ko should be present if compilation succeeds.

Step 6: Inspect metadata

modinfo hello_module.ko

16. Load the Kernel Module

After successful compilation, the module can be loaded into the running kernel.

Load the module

sudo insmod hello_module.ko

insmod attempts to insert the specified module file into the kernel.

Check whether it is loaded

lsmod | grep hello_module

View initialization messages

sudo dmesg | tail -n 20

Expected messages include:

Hello Module: Initialization started
Hello Module: Module loaded successfully

The exact displayed output may include timestamps and other kernel log information.

17. Remove the Kernel Module

To remove the module, execute:

sudo rmmod hello_module

Then inspect the kernel log:

sudo dmesg | tail -n 20

Expected cleanup messages include:

Hello Module: Cleanup started
Hello Module: Module removed successfully

Finally, verify that the module is no longer listed:

lsmod | grep hello_module

If the module is no longer loaded, the command normally produces no matching output.

19. Important Safety Rules

  • Kernel modules execute with kernel privileges.
  • A faulty module can crash the operating system.
  • Test experimental modules in a virtual machine whenever possible.
  • Keep a recoverable VM snapshot before risky experiments.
  • Never load unknown or untrusted kernel modules.
  • Always release resources correctly in cleanup paths.
  • Do not access hardware registers without understanding the relevant hardware and kernel subsystem.
  • Compile against the intended kernel build environment.

20. Common Errors

Compilation error: missing linux/module.h

Cause: Missing or incorrectly configured kernel headers/build tree.

Solution: Install and verify the matching kernel headers.

Invalid module format

Cause: The module does not match the running kernel's build or ABI requirements.

Solution: Rebuild against the intended kernel build tree.

Unknown symbol

Cause: A required symbol is unavailable or a module dependency is missing.

Solution: Inspect kernel logs and module dependencies.

Operation not permitted

Cause: Insufficient privileges or a system security restriction.

Solution: Check privileges, Secure Boot and module-signing policy.

Module is in use

Cause: The module is being used or has a nonzero reference count.

Solution: Identify and release the dependent resource before attempting removal.
