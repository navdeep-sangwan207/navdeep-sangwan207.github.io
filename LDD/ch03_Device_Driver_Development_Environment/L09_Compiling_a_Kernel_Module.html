1. Introduction

After writing a Linux kernel module, the next step is to compile it into a loadable kernel object file.

Unlike an ordinary C program, a kernel module must be compiled using the Linux kernel build system called Kbuild. Kbuild applies the correct kernel configuration, compiler options, include paths and module-linking rules.

In this lesson, we will study the complete compilation process, understand generated files, inspect compiler output and troubleshoot common build errors.

2. What Is Kernel Module Compilation?

Kernel module compilation is the process of converting kernel module source code written in C into a loadable kernel module file.

The resulting file generally has the extension:

.ko

.ko stands for Kernel Object.

Compilation process

Source Code (.c)
↓
Preprocessing
↓
Compilation
↓
Object Files (.o)
↓
Module Linking
↓
Kernel Module (.ko)

Kbuild coordinates these operations and performs additional kernel-specific build steps.

3. Requirements for Compilation

Before compiling an external kernel module, ensure that the following components are available:

ComponentPurpose
Kernel source codeContains kernel implementation and build information; a complete source checkout is not always required for ordinary external module builds.
Kernel headersProvide declarations required by module source code.
Prepared kernel build treeProvides the configuration and build rules used by Kbuild.
GCCCompiles C source code.
GNU MakeExecutes build instructions.
KbuildCoordinates kernel module compilation.

Check the kernel version

uname -r

Check GCC

gcc --version

Check Make

make --version

Check kernel build directory

ls -l /lib/modules/$(uname -r)/build

4. Install Required Packages on Ubuntu

Update the package information:

sudo apt update

Install the development tools:

sudo apt install build-essential

Install the matching kernel headers:

sudo apt install linux-headers-$(uname -r)

These commands are appropriate for standard Ubuntu kernels available through the configured repositories. For custom kernels, use the prepared build tree and matching headers supplied by that kernel's build process.

5. Create the Kernel Module Source File

We will compile a simple module named hello_module.

Create the project directory

mkdir -p ~/Linux_Driver_Projects/hello_module
cd ~/Linux_Driver_Projects/hello_module

Create the source file

nano hello_module.c

Source code: hello_module.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello Module: Module initialized\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello Module: Module cleanup completed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic Hello World Kernel Module");
MODULE_VERSION("1.0");

This source file contains the initialization function, cleanup function and module metadata.

6. Create the External Module Makefile

Kbuild needs instructions describing which module to compile.

Create the Makefile

nano Makefile

Makefile contents

obj-m += hello_module.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Explanation

ExpressionMeaning
obj-mDeclares an external loadable module target.
hello_module.oNames the module object target.
-CRuns Make from the kernel build directory.
$(shell uname -r)Obtains the running kernel release.
M=$(PWD)Identifies the external module directory.
modulesRequests module compilation.
cleanRemoves generated build files.

Important: Use a tab character before the two command lines under all and clean.

7. Compile the Module Using Make

Ensure that you are inside the project directory.

cd ~/Linux_Driver_Projects/hello_module

Execute:

make

The default all target invokes the kernel build system.

What happens during compilation?

  1. GNU Make reads the external module Makefile.
  2. Make changes to the selected kernel build directory.
  3. Kbuild reads the external module configuration.
  4. Kbuild invokes the compiler with kernel-specific options.
  5. Source code is compiled into object files.
  6. The module build process links the required objects.
  7. Kernel module metadata and symbol information are processed.
  8. The final hello_module.ko file is generated.
make
↓
External Makefile
↓
Kernel Build Directory
↓
Kbuild Compilation
↓
hello_module.ko

9. Verify the Compiled Module

Check the module file

ls -l hello_module.ko

Identify the file type

file hello_module.ko

Display module metadata

modinfo hello_module.ko

Typical metadata includes:

  • Module name.
  • Module description.
  • Module author.
  • Module license.
  • Module version.
  • Kernel version information, when available.

10. Verbose Compilation

Sometimes it is necessary to understand which compiler commands and options are being used.

Kbuild supports verbose output using V=1.

make V=1 -C /lib/modules/$(uname -r)/build M=$PWD modules

This displays more detailed commands used during the build process.

Verbose compilation is useful for:

  • Debugging build failures.
  • Inspecting compiler flags.
  • Checking include paths.
  • Understanding linking operations.
  • Investigating kernel configuration issues.

11. Compile a Module with Multiple Source Files

A device driver may contain several source files. Kbuild allows multiple object files to be combined into one module.

Project structure

my_driver/
|
|-- Makefile
|-- main.c
|-- hardware.c
|-- hardware.h

Makefile

obj-m += my_driver.o

my_driver-y := main.o hardware.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Here:

  • obj-m declares the loadable module target.
  • my_driver-y lists the component object files.
  • main.o and hardware.o are linked into the module.
  • The final module is named my_driver.ko.

The source files should contain valid kernel code and appropriate declarations in shared header files.

12. Understanding Module Compilation Errors

Error 1: Missing kernel headers

fatal error: linux/module.h: No such file or directory

Cause: The selected kernel build environment is missing or incorrectly configured.

Solution:

sudo apt install linux-headers-$(uname -r)

Error 2: Missing build directory

/lib/modules/.../build: No such file or directory

Cause: Matching headers or the prepared kernel build tree are unavailable.

Solution:

ls -l /lib/modules/$(uname -r)/build

Install the correct headers or prepare the appropriate target kernel build tree.

Error 3: Missing separator

Cause: A Makefile command starts with spaces instead of a tab.

Solution: Correct the indentation of the command line.

Error 4: Undefined reference or unresolved symbol

Cause: A required function or symbol is unavailable, incorrectly declared or not exported for module use.

Solution: Verify the kernel API, exported symbols and required dependencies.

Error 5: Compiler version warning

Cause: The compiler used for the module differs from the compiler used to build the target kernel.

Solution: Check the kernel compiler information and use a compatible compiler toolchain when required.

13. Clean the Build Directory

During compilation, Kbuild creates object files and other intermediate files.

To remove generated files, run:

make clean

Then inspect the directory:

ls -la

The source file and Makefile remain, while generated build files are removed according to the kernel build system's cleanup rules.

Cleaning is useful when:

  • Starting a fresh compilation.
  • Changing source code or build configuration.
  • Removing stale intermediate files.
  • Preparing a project for distribution.

14. Understanding Compilation vs Loading

Compilation and loading are two separate operations.

CompilationLoading
Converts source code into a module file.Inserts the compiled module into the running kernel.
Uses Make and Kbuild.Uses tools such as insmod or modprobe.
Produces a .ko file.Runs the module initialization function.
Does not normally execute the module's initialization function.Executes the initialization function when loading succeeds.

A successfully compiled module is not automatically loaded into the kernel.

16. Important Points to Remember

  • Kernel modules are compiled using Kbuild.
  • The output file normally has a .ko extension.
  • Matching kernel headers and a prepared build tree are required.
  • obj-m declares external module targets.
  • M=$PWD identifies the external module directory.
  • make starts the build using the Makefile.
  • V=1 displays detailed build commands.
  • modinfo displays module metadata.
  • make clean removes generated build files.
  • Compilation and loading are separate operations.
