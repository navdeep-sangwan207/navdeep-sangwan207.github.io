1. Introduction

Before writing a Linux device driver, we need a properly configured development environment. Kernel module development requires a compiler, kernel headers or a prepared kernel build tree, GNU Make and other build utilities.

A kernel module is a piece of code that can be loaded into or removed from a running Linux kernel. External modules are developed separately from the main kernel source tree and compiled against a particular kernel build.

This lesson explains how to prepare an Ubuntu environment for writing, compiling and testing Linux kernel modules.

3. Identify the Running Kernel Version

The first step is to identify the Linux kernel version currently running on Ubuntu.

uname -r

Example output:

6.x.x-generic

The exact version depends on the installed Ubuntu kernel.

To display additional kernel information:

uname -a

Why is this important?

  • Kernel modules must be built for the intended target kernel.
  • Kernel headers should match the target kernel build.
  • Kernel APIs can change between kernel versions.
  • A module compiled for a different kernel may fail to load.

4. Install Development Tools

Ubuntu provides a package group called build-essential, which installs common software development tools.

Update package information

sudo apt update

Install build tools

sudo apt install build-essential

This package group includes commonly used tools such as GCC, G++, GNU Make and development utilities.

Verify GCC

gcc --version

Verify Make

make --version

If both commands display version information, the basic compiler and build tools are available.

5. Install Matching Linux Kernel Headers

Kernel headers provide the declarations and build information needed to compile external kernel modules against a particular kernel.

For the currently running Ubuntu kernel, use:

sudo apt install linux-headers-$(uname -r)

The command substitutes the running kernel release into the package name.

Check the kernel build directory

ls -l /lib/modules/$(uname -r)/build

This path normally points to the prepared kernel build directory used by external module compilation.

It is often a symbolic link to a directory under /usr/src.

Inspect the headers directory

ls /usr/src/

Depending on the installed packages, you may see directories containing kernel header files and build information.

Important: Installing headers for the running kernel is the usual approach for an external module intended to run on that kernel. If you are building for another kernel, use that kernel's corresponding prepared build tree instead.

6. Understand the Kernel Build Directory

The path /lib/modules/$(uname -r)/build is an important part of external module development.

It points to the kernel build environment associated with the selected kernel release.

Inspect the path

readlink -f /lib/modules/$(uname -r)/build

Check whether the directory exists

test -d /lib/modules/$(uname -r)/build && echo "Build directory found" || echo "Build directory missing"

Expected output when available:

Build directory found

Why is it needed?

  • It provides kernel build rules.
  • It provides required kernel headers.
  • It supplies configuration information.
  • It allows Kbuild to compile external modules.

7. Create a Dedicated Project Directory

It is good practice to keep each kernel module project in a separate directory.

Create a project directory

mkdir -p ~/Linux_Driver_Projects/hello_module

Move into the directory

cd ~/Linux_Driver_Projects/hello_module

Check the current location

pwd

Example output:

/home/user/Linux_Driver_Projects/hello_module

Recommended project structure

hello_module/
|
|-- Makefile
|
|-- hello_module.c
|
|-- README.md

For a larger project, additional source files and header files can be organized into subdirectories.

8. Create the First Kernel Module Source File

Create a source file named hello_module.c.

nano hello_module.c

Enter the following program:

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello Module: Module loaded\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello Module: Module unloaded\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("First Linux kernel module");

Program explanation

ElementPurpose
linux/module.hProvides module-related declarations.
linux/kernel.hProvides kernel utility declarations.
linux/init.hProvides initialization and exit annotations.
hello_init()Runs when the module is loaded.
hello_exit()Runs when the module is removed.
pr_info()Writes an informational message to the kernel log.
module_init()Registers the module initialization function.
module_exit()Registers the module cleanup function.
MODULE_LICENSE()Declares the module license.

This source file is a simple loadable kernel module. It does not yet implement a hardware device interface.

9. Create the External Module Makefile

Create a file named exactly Makefile in the same directory.

nano Makefile

Enter the following contents:

obj-m += hello_module.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Remember that each command under all and clean must begin with a tab character.

Makefile explanation

  • obj-m tells Kbuild to build a loadable module.
  • $(shell uname -r) obtains the running kernel release.
  • -C directs Make to use the kernel build directory.
  • M=$(PWD) identifies the external module directory.
  • modules starts the module build.
  • clean removes generated build files.

10. Compile the Kernel Module

Ensure that the terminal is inside the project directory.

cd ~/Linux_Driver_Projects/hello_module

Run the build command:

make

Make invokes Kbuild, which compiles the source file using the selected kernel build environment.

Check the generated files

ls -l

After a successful build, the main output should include:

hello_module.ko

Other generated files may include:

  • hello_module.o
  • hello_module.mod
  • hello_module.mod.c
  • hello_module.mod.o
  • Module.symvers
  • modules.order

The exact intermediate files depend on the kernel build process and version.

11. Inspect the Generated Kernel Module

After compilation, use the following commands to inspect the output.

Check the module file

file hello_module.ko

Display module information

modinfo hello_module.ko

This displays metadata such as the module name, description, author, license and supported kernel information when available.

Check the module file size

ls -lh hello_module.ko

These commands inspect the compiled module without loading it into the kernel.

12. Load and Test the Module: Preview

Loading and removing modules are covered in detail in later chapters. The following commands provide an initial preview.

Load the module

sudo insmod hello_module.ko

Check the kernel log

sudo dmesg | tail -n 20

Expected message:

Hello Module: Module loaded

Remove the module

sudo rmmod hello_module

Check the kernel log again

sudo dmesg | tail -n 20

Expected message:

Hello Module: Module unloaded

Note: Loading kernel modules requires appropriate privileges and may be restricted by Secure Boot or system security policies. Only load modules you trust. The module must be compatible with the running kernel.

13. Development in Ubuntu VirtualBox

Kernel module development can be performed inside an Ubuntu virtual machine running under VirtualBox.

The guest operating system has its own Linux kernel. Therefore, compile the module against the Ubuntu guest's kernel headers, not the Windows host operating system.

Windows Host
↓
VirtualBox
↓
Ubuntu Guest OS
↓
Guest Linux Kernel
↓
External Kernel Module

Important limitations

  • Ordinary kernel module development and testing can be performed in a VM.
  • VirtualBox does not automatically expose physical GPIO, I2C or SPI controllers to the guest.
  • USB devices may be passed through when VirtualBox USB support and suitable host configuration are available.
  • Hardware-specific driver testing requires suitable hardware access or an appropriate emulator.
  • A virtual machine snapshot can help recover from experimental system changes.

14. Common Setup Problems

Problem 1: Kernel headers package not found

Possible reason: The required package is unavailable in the configured repositories or the running kernel is not a standard repository-provided kernel.

Check:

uname -r
apt search linux-headers

Verify the kernel package source and install the matching headers or prepared build tree.

Problem 2: Build directory does not exist

Check:

ls -l /lib/modules/$(uname -r)/build

Install the matching headers and verify the path again.

Problem 3: Invalid module format

Possible reason: The module was compiled for a different kernel build or has incompatible module metadata.

Check:

uname -r
modinfo hello_module.ko

Rebuild the module against the intended target kernel build tree.

Problem 4: Operation not permitted while loading

Possible reason: The command lacks privileges or kernel module loading is restricted by system security policy.

Check:

sudo insmod hello_module.ko
sudo dmesg | tail -n 30

Review the kernel log and the system's Secure Boot or module-signing configuration.

Problem 5: Unknown symbol during module loading

Possible reason: A required kernel symbol is unavailable or a dependency has not been satisfied.

Check:

sudo dmesg | tail -n 30
modinfo hello_module.ko

Verify the target kernel, exported symbols and required module dependencies.

15. Recommended Development Directory Structure

For multiple driver projects, use a dedicated directory structure.

Linux_Driver_Projects/
|
|-- hello_module/
|   |-- Makefile
|   |-- hello_module.c
|
|-- character_driver/
|   |-- Makefile
|   |-- character_driver.c
|   |-- character_driver.h
|
|-- gpio_driver/
|   |-- Makefile
|   |-- gpio_driver.c
|
|-- i2c_driver/
    |-- Makefile
    |-- i2c_driver.c

This organization makes it easier to maintain source files, build rules and documentation for each project.

17. Important Points to Remember

  • Kernel module development requires a suitable kernel build environment.
  • GCC and GNU Make are essential build tools.
  • Kernel headers must match the target kernel build.
  • /lib/modules/$(uname -r)/build is a common external module build path.
  • External modules use a Kbuild-compatible Makefile.
  • The .ko file is the compiled loadable kernel module.
  • modinfo displays module metadata.
  • Ubuntu inside VirtualBox can be used for basic kernel module development.
  • Hardware-specific driver testing requires suitable hardware access or emulation.
