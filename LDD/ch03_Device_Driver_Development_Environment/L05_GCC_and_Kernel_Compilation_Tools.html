1. Introduction

Linux device drivers are primarily written in the C programming language. Before a driver can run inside the Linux kernel, its source code must be compiled and prepared as a kernel module.

Several tools participate in this process, including GCC, the assembler, linker, GNU Make and the Linux kernel build system (Kbuild).

This lesson explains the role of these tools, how compilation works and why kernel modules must be built using the kernel's build environment.

2. What Is GCC?

GCC stands for GNU Compiler Collection. It is a compiler toolchain that supports languages such as C and C++.

Linux kernel development primarily uses C. GCC translates C source code into lower-level object code that can be linked into a kernel or module.

Check GCC installation

gcc --version

Find GCC executable

which gcc

Display GCC target information

gcc -dumpmachine

The output identifies the target architecture and platform for which the compiler is configured.

3. Role of GCC in Kernel Development

GCC is responsible for compiling C source files. However, kernel module compilation requires more than simply invoking GCC on a source file.

The Linux kernel has specific requirements involving:

  • Kernel-specific compiler options.
  • Architecture-specific settings.
  • Kernel header files.
  • Generated configuration headers.
  • Compiler compatibility requirements.
  • Kernel symbol and module information.

Kbuild coordinates these requirements and invokes the appropriate compiler commands.

4. Stages of C Program Compilation

A traditional C program passes through several stages before becoming an executable program.

C Source File (.c)
↓
Preprocessor
↓
Compiler
↓
Assembler
↓
Object File (.o)
↓
Linker
↓
Executable File

Stage 1: Preprocessing

The preprocessor handles directives such as:

  • #include
  • #define
  • #ifdef
  • #ifndef

Stage 2: Compilation

The compiler translates preprocessed C code into assembly language or an intermediate representation before generating assembly output.

Stage 3: Assembly

The assembler converts assembly instructions into machine-code object files.

Stage 4: Linking

The linker combines object files and resolves references to symbols, libraries or other required components.

Kernel module distinction: An external kernel module is not linked like an ordinary user-space executable. Kbuild produces a relocatable module object and prepares it as a .ko file, resolving kernel symbols according to kernel module rules.

5. GCC Compilation Commands

GCC provides different options to perform individual compilation stages.

Preprocessing only

gcc -E program.c -o program.i

Generates preprocessed source code.

Compile to assembly

gcc -S program.c -o program.s

Generates assembly code.

Generate an object file

gcc -c program.c -o program.o

Compiles and assembles the source file without linking it into an executable.

Generate an executable

gcc program.c -o program

Compiles and links a simple user-space C program.

These commands are useful for understanding C compilation. They are not the recommended method for building Linux kernel modules.

6. What Is an Object File?

An object file contains machine-code instructions and related information generated by the compiler and assembler.

Object files generally use the .o extension.

Example:

driver.o

An object file is not necessarily a complete executable. It may contain unresolved references that are resolved during a later linking stage.

7. What Is a Linker?

A linker combines object files and resolves symbol references between them.

For Linux kernel modules, the kernel build system performs the required module linking steps and prepares the module for loading.

On Linux systems, the GNU linker is commonly available through the Binutils toolchain.

Check linker version

ld --version

Locate the linker

which ld

Kernel builds may use linker-related tools and options specific to the kernel version, architecture and compiler toolchain.

8. GNU Binutils

GNU Binutils is a collection of tools used for working with object files, executables, symbols and binary formats.

ToolPurpose

readelfDisplays ELF file headers, sections and other information.

Check installed tools

objdump --version
readelf --version
nm --version
as --version

9. What Is GNU Make?

GNU Make automates software builds by reading instructions from a Makefile.

It can determine which files need to be rebuilt based on their dependencies and timestamps.

Check Make

make --version

Simple Makefile example

CC = gcc
CFLAGS = -Wall

hello: hello.c
	$(CC) $(CFLAGS) hello.c -o hello

clean:
	rm -f hello

This example builds an ordinary user-space C program. The tab before the command lines is required by traditional Makefile syntax.

10. What Is Kbuild?

Kbuild is the Linux kernel build system. It manages compilation of the kernel and external kernel modules.

It supplies the correct compiler flags, header paths, architecture settings and other build information required by the kernel.

External Driver Source
↓
External Module Makefile
↓
GNU Make
↓
Kernel Build System (Kbuild)
↓
Compiler and Linker Tools
↓
Kernel Module (.ko)

Kbuild is important because kernel modules must be compiled using the correct kernel-specific build settings.

11. Why Not Compile Kernel Modules Directly with GCC?

Consider a kernel module source file that includes kernel headers and uses kernel functions.

Running a command such as:

gcc -c driver.c

is generally not sufficient to build a kernel module.

Direct GCC compilation does not automatically provide the complete kernel build environment, architecture-specific flags, generated headers or module preparation steps.

Instead, use the kernel build system:

make -C /lib/modules/$(uname -r)/build M=$PWD modules

This invokes Kbuild using the prepared build directory associated with the running kernel.

12. Understanding Cross-Compilation

Cross-compilation means building software on one computer for execution on a different target architecture.

For example, a developer may use an x86-64 Ubuntu computer to build a kernel module for an ARM-based embedded Linux board.

Development PC (x86-64)
↓
Cross Compiler (ARM)
↓
ARM Kernel Module
↓
ARM Embedded Linux Device

Cross-compiling a kernel module requires:

  • A suitable cross-compiler toolchain.
  • The target kernel source or prepared build directory.
  • The correct target architecture configuration.
  • Matching kernel headers and configuration.
  • Appropriate Kbuild settings.

For example, an ARM64 toolchain may use a compiler named aarch64-linux-gnu-gcc. The actual toolchain must match the target architecture and kernel build requirements.

13. Compiler and Architecture Compatibility

Kernel builds may depend on compiler capabilities and architecture-specific options.

Important considerations include:

  • Compiler version supported by the target kernel.
  • Target processor architecture.
  • 32-bit or 64-bit compilation mode.
  • Kernel configuration and generated headers.
  • Architecture-specific compiler flags.
  • Kernel source and build directory compatibility.

When building an external module, use the toolchain and build environment appropriate for the target kernel.

14. Inspecting Object Files and Kernel Modules

Compilation tools can help inspect the output generated during module development.

Display object file information

file driver.o

Display ELF information

readelf -h driver.o

Display symbols

nm driver.o

Display object file sections and instructions

objdump -h driver.o
objdump -d driver.o

These commands help examine the structure and symbols of compiled object files.

Some symbols in a kernel module remain unresolved until the module is loaded and its references are resolved against available kernel symbols.

15. Checking the Development Toolchain

Use the following commands to verify the main compilation tools.

# GCC compiler
gcc --version

# Make utility
make --version

# Linker
ld --version

# Assembler
as --version

# Object file inspection
objdump --version

# ELF inspection
readelf --version

# Symbol inspection

# Running kernel release

These checks help identify whether the basic compilation toolchain is installed.

17. Common Compilation Problems

Problem 1: GCC command not found

Solution:

sudo apt install build-essential

Problem 2: Missing header file

Possible cause: The required header package or include path is missing.

Solution: Identify whether the source requires user-space or kernel headers and install or configure the correct development environment.

Problem 3: Undefined reference during linking

Possible cause: A required function or symbol is not available to the linker.

Solution: Check the source files, linked libraries and symbol declarations.

Problem 4: Architecture mismatch

Possible cause: The compiler target does not match the target kernel architecture.

Solution: Use the appropriate native or cross-compilation toolchain.

Problem 5: Kernel module compilation failure

Possible cause: Incorrect kernel headers, unsupported API usage, missing build configuration or incompatible compiler settings.

Solution: Inspect the Kbuild output and verify the target kernel build environment.

18. Important Points to Remember

  • GCC is a compiler toolchain used for C and other languages.
  • C compilation involves preprocessing, compilation, assembly and linking.
  • Object files commonly use the .o extension.
  • GNU Binutils provides tools for inspecting and processing binary files.
  • GNU Make automates build operations.
  • Kbuild is the Linux kernel build system.
  • Kernel modules should be compiled through Kbuild rather than direct GCC commands.
  • Cross-compilation builds software for a different target architecture.
  • Kernel module compilation requires the correct target kernel build environment.
