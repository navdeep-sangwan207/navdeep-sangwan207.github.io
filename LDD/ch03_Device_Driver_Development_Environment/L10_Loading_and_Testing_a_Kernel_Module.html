1. Introduction

After compiling a Linux kernel module, the next step is to load it into the running kernel and verify that it works correctly.

A compiled module is normally stored as a .ko file. It is not automatically active simply because compilation succeeds.

Linux provides utilities such as insmod, modprobe, lsmod, rmmod and modinfo to manage kernel modules.

In this lesson, we will load a module, inspect its status, examine kernel log messages, test its initialization and cleanup functions, and remove it safely.

2. Understanding the Kernel Module Lifecycle

A loadable kernel module follows a lifecycle consisting of compilation, loading, execution and removal.

Write Module Source Code
↓
Compile Using Kbuild
↓
Generate .ko File
↓
Load Module
↓
Initialization Function Runs
↓
Module Active in Kernel
↓
Remove Module
↓
Cleanup Function Runs

Each stage has a specific purpose. The initialization function is executed when the module loads successfully, while the cleanup function is executed when the module is removed successfully.

3. Kernel Module Management Commands

CommandPurpose
insmodInserts a specified module file into the kernel.
rmmodRemoves a loaded module by module name.
lsmodDisplays currently loaded modules.
modprobeLoads or removes modules while handling dependencies.
modinfoDisplays information about a module.
dmesgDisplays kernel ring-buffer messages.

These commands are commonly used during device driver development and troubleshooting.

4. Prepare a Kernel Module for Testing

We will use the Hello World kernel module developed in the previous lesson.

Project directory

cd ~/Linux_Driver_Projects/hello_module

Check source and Makefile

ls -l

Compile the module

make

Verify the module file

ls -l hello_module.ko

Ensure that compilation succeeds before attempting to load the module.

5. Inspect Module Information Using modinfo

The modinfo command displays metadata associated with a kernel module.

Syntax

modinfo module_name.ko

Example

modinfo hello_module.ko

Common information includes:

FieldDescription
filenameLocation of the module file.
descriptionDescription of the module.
authorModule author.
licenseDeclared module license.
versionModule version, if supplied.
dependsDeclared module dependencies.
vermagicKernel build compatibility information.

Important: modinfo inspects module metadata. It does not load the module.

6. Loading a Module Using insmod

The insmod command inserts a module file into the running Linux kernel.

Syntax

sudo insmod module_name.ko

Example

sudo insmod hello_module.ko

If the operation succeeds, the module is inserted into the kernel and its initialization function is executed.

Important characteristics

  • insmod uses a specified module file path.
  • It does not automatically resolve and load module dependencies in the same way as modprobe.
  • It generally requires administrative privileges.
  • The module must be compatible with the running kernel.
  • Kernel security policies may restrict module loading.

7. Verify Module Loading Using lsmod

The lsmod command displays the modules currently loaded into the kernel.

Syntax

lsmod

Search for a specific module

lsmod | grep hello_module

A matching line indicates that the module appears in the loaded module list.

Understanding lsmod output

ColumnMeaning
ModuleName of the loaded module.
SizeModule size in memory, as reported by the utility.
Used byReference count and dependent modules information.

The exact output depends on the kernel and module state.

8. View Kernel Messages Using dmesg

The dmesg command displays messages from the kernel ring buffer.

Kernel modules often use logging functions such as pr_info() to display messages during initialization and cleanup.

Display kernel messages

sudo dmesg

Display the latest messages

sudo dmesg | tail -n 20

Filter messages for a module

sudo dmesg | grep "Hello Module"

Depending on the distribution's permissions and logging configuration, reading kernel messages may require administrative privileges.

9. Testing the Initialization Function

When a module is successfully loaded, the kernel calls the function registered through module_init().

Our example module contains:

static int __init hello_init(void)
{
    pr_info("Hello Module: Module initialized\n");
    return 0;
}

Load the module:

sudo insmod hello_module.ko

Check the latest kernel messages:

sudo dmesg | tail -n 20

Expected message:

Hello Module: Module initialized

This confirms that the initialization function executed and its informational message was written to the kernel log.

10. Removing a Module Using rmmod

The rmmod command requests removal of a loaded module from the running kernel.

Syntax

sudo rmmod module_name

Example

sudo rmmod hello_module

Notice that the module name is used without the .ko extension.

When removal succeeds, the cleanup function registered using module_exit() is executed.

Check the cleanup message

sudo dmesg | tail -n 20

Expected message:

Hello Module: Module cleanup completed

11. Verify Module Removal

After removing a module, check whether it is still listed.

lsmod | grep hello_module

If the module has been removed successfully, this command normally produces no matching output.

You can also inspect the kernel module directory:

ls /lib/modules/$(uname -r)/

Note: The module file in your project directory is not automatically deleted by rmmod. Removing a loaded module from the kernel and deleting its compiled file are separate operations.

12. Difference Between insmod and modprobe

Both commands can load kernel modules, but they handle dependencies differently.

insmodmodprobe
Loads a specified module file.Loads a module by name using module information installed in the system.
Does not automatically resolve module dependencies.Can automatically handle dependencies.
Commonly used with a local .ko file during development.Commonly used for system-installed modules.
Uses a module file path.Uses a module name or configured module alias.

Example using modprobe

sudo modprobe module_name

For a newly built external module, additional installation and dependency-index steps may be needed before it can be loaded by name through modprobe.

13. Using modprobe with an External Module

For a module that should be managed by modprobe, it is common to install it into the appropriate module directory and update the dependency information.

Install the module

sudo install -D -m 644 hello_module.ko /lib/modules/$(uname -r)/extra/hello_module.ko

Update module dependency information

sudo depmod -a

Load by module name

sudo modprobe hello_module

Remove by module name

sudo modprobe -r hello_module

This is a simplified development example. Production installation should use an appropriate packaging or deployment process and account for Secure Boot signing requirements where applicable.

14. Check Module Dependencies

Some kernel modules require other modules to be loaded before they can operate.

Use modinfo to inspect declared dependency information:

modinfo hello_module.ko

Look for the depends field.

For installed modules, the dependency database is maintained using:

sudo depmod -a

To inspect dependency information for a module:

modprobe --show-depends hello_module

This command displays the dependency-related loading information known to the module management system.

15. Common Loading and Removal Errors

Error 1: Operation not permitted

Possible cause: Insufficient privileges or a kernel security restriction.

Check:

sudo insmod hello_module.ko
sudo dmesg | tail -n 30

Review Secure Boot, module-signing policy and kernel security settings.

Error 2: Invalid module format

Possible cause: The module was built against an incompatible kernel build.

Check:

uname -r
modinfo hello_module.ko

Recompile against the correct target kernel build tree.

Error 3: Unknown symbol

Possible cause: A required symbol is unavailable or a dependency is missing.

Check:

sudo dmesg | tail -n 30

Check symbol exports and module dependencies.

Error 4: Module is in use

Possible cause: The module has active references or is being used by another kernel component.

Solution: Release the resources and dependencies that prevent removal.

Error 5: Module not found

Possible cause: Incorrect module name or unavailable module file.

Check:

lsmod | grep module_name
find /lib/modules/$(uname -r) -name 'module_name.ko*'

16. Complete Practical: Load and Test Hello Module

Objective: Compile, load, inspect and remove a Linux kernel module.

Step 1: Open the project directory

cd ~/Linux_Driver_Projects/hello_module

Step 2: Compile

make

Step 3: Inspect the module

modinfo hello_module.ko

Step 4: Load the module

sudo insmod hello_module.ko

Step 5: Verify its presence

lsmod | grep hello_module

Step 6: Inspect initialization messages

sudo dmesg | tail -n 20

Step 7: Remove the module

sudo rmmod hello_module

Step 8: Inspect cleanup messages

sudo dmesg | tail -n 20

Step 9: Verify removal

lsmod | grep hello_module

Step 10: Clean the project

make clean

Expected Result

The module should compile successfully, appear in the loaded module list after insertion, display its initialization message in the kernel log and disappear from the loaded module list after successful removal.

The cleanup message should also appear in the kernel log.

17. Testing Checklist

  • Verify the running kernel version.
  • Verify matching kernel headers.
  • Compile the module successfully.
  • Confirm that the .ko file exists.
  • Inspect metadata using modinfo.
  • Load the module using insmod.
  • Verify its presence using lsmod.
  • Check initialization messages using dmesg.
  • Remove the module using rmmod.
  • Check cleanup messages using dmesg.
  • Verify that the module is no longer loaded.
  • Clean generated build files.

18. Safety Precautions

  • Only load modules that you have written or reviewed and trust.
  • Kernel modules execute with kernel privileges.
  • A faulty module can crash the operating system.
  • Use a virtual machine for initial experiments where possible.
  • Take a recoverable VM snapshot before risky testing.
  • Do not force-remove a module that is actively in use.
  • Release allocated resources before module removal.
  • Check kernel logs when module operations fail.

19. Important Points to Remember

  • insmod inserts a specified module file.
  • rmmod removes a loaded module.
  • lsmod lists loaded modules.
  • modprobe handles module dependencies.
  • modinfo displays module metadata.
  • dmesg displays kernel log messages.
  • Loading invokes the module initialization function.
  • Successful removal invokes the cleanup function.
  • Compilation and loading are separate operations.
  • Kernel module testing should be performed carefully.
