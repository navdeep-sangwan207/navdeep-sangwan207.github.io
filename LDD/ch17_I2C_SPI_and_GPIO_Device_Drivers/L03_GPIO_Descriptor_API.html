2. Introduction to GPIO Descriptor API

The Linux GPIO descriptor API is the modern interface used by kernel drivers to request and control GPIO lines.

It represents a GPIO line using a descriptor rather than requiring the consumer driver to depend on a global GPIO number.

The descriptor type is:

struct gpio_desc;

A driver normally obtains a descriptor through the GPIO subsystem and uses GPIO APIs to configure or operate the line.

Why Use the Descriptor API?

  • Provides a hardware-independent interface.
  • Avoids dependence on global GPIO numbering.
  • Supports Device Tree and ACPI-based GPIO lookup.
  • Supports active-low configuration.
  • Supports device-managed resource handling.
  • Improves portability across embedded platforms.

3. Legacy GPIO API vs Descriptor API

Older Linux drivers may use the legacy integer-based GPIO interface.

Legacy GPIO API GPIO Descriptor API
Uses integer GPIO numbers. Uses struct gpio_desc pointers.
Examples: gpio_request(), gpio_get_value(). Examples: gpiod_get(), gpiod_get_value().
Often depends on global numbering. Uses consumer-oriented GPIO lookup.
Legacy interface. Preferred interface for new kernel drivers.
New GPIO consumer drivers should normally use the descriptor API. Avoid introducing legacy integer GPIO APIs into new driver code.

4. Required Header File

GPIO descriptor APIs are declared through the GPIO consumer header.

#include <linux/gpio/consumer.h>

For a platform driver, commonly used headers include:

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/platform_device.h>
#include <linux/gpio/consumer.h>
#include <linux/of.h>

5. GPIO Descriptor Declaration

A GPIO descriptor is stored using a pointer to struct gpio_desc.

struct gpio_desc *led;
struct gpio_desc *button;

In this example:

  • led represents an LED control GPIO.
  • button represents a button input GPIO.

The descriptor is obtained through a GPIO lookup operation. A driver should not create a descriptor manually.

6. Obtaining a GPIO Descriptor

The gpiod_get() function obtains a GPIO descriptor for a device.

Function Concept

struct gpio_desc *gpiod_get(
    struct device *dev,
    const char *con_id,
    enum gpiod_flags flags
);

Important parameters:

Parameter Description
dev Device requesting the GPIO.
con_id Consumer connection identifier.
flags Initial direction and value configuration.

Example

struct gpio_desc *led;

led = gpiod_get(
    dev,
    "led",
    GPIOD_OUT_LOW
);

if (IS_ERR(led))
    return PTR_ERR(led);

The descriptor is requested using the connection ID "led".

7. Device-Managed GPIO Descriptor

The device-managed version is commonly used in platform and peripheral drivers.

Function

devm_gpiod_get()

It requests a GPIO descriptor and associates its lifetime with the device.

Example

struct gpio_desc *led;

led = devm_gpiod_get(
    &pdev->dev,
    "led",
    GPIOD_OUT_LOW
);

if (IS_ERR(led))
    return PTR_ERR(led);

When the device is detached, the managed GPIO descriptor is automatically released.

Other Managed Functions

devm_gpiod_get_optional()
devm_gpiod_get_index()
devm_gpiod_get_index_optional()

The optional form is useful when a GPIO connection may legitimately be absent.

8. GPIO Direction Configuration

A GPIO line can be configured as input or output.

Configure Input

int ret;

ret = gpiod_direction_input(button);

if (ret)
    return ret;

Configure Output

int ret;

ret = gpiod_direction_output(led, 0);

if (ret)
    return ret;

The second argument to gpiod_direction_output() specifies the initial logical output value.

When obtaining a descriptor with GPIOD_IN, GPIOD_OUT_LOW or GPIOD_OUT_HIGH, the initial direction and output state are configured as part of the acquisition. Explicit direction functions are useful when direction must be changed later.

9. Reading GPIO Values

The GPIO descriptor API provides functions for reading the current logical value of an input line.

Non-Sleeping Read

int value;

value = gpiod_get_value(button);

if (value < 0)
    return value;

Sleeping Read

int value;

value = gpiod_get_value_cansleep(button);

if (value < 0)
    return value;

The return value is normally:

Return Value Meaning
0 Logical LOW.
1 Logical HIGH.
Negative value Error.

The _cansleep version must be used when the GPIO controller may require a sleepable operation, such as some GPIO expanders connected over I2C or SPI.

10. Writing GPIO Values

GPIO output values can be changed through descriptor APIs.

Non-Sleeping Output

gpiod_set_value(led, 1);

Sleepable Output

gpiod_set_value_cansleep(led, 1);

To set the logical output LOW:

gpiod_set_value_cansleep(led, 0);

The function returns void; it does not provide a success or error return value.

11. Understanding Active-High and Active-Low GPIO

GPIO descriptors support logical signal polarity.

Active-High

A logical value of 1 represents an asserted signal, normally corresponding to a physical HIGH level.

Active-Low

A logical value of 1 represents an asserted signal, but the physical GPIO level is LOW.

Logical Value Active-High Physical Level Active-Low Physical Level
0 LOW HIGH
1 HIGH LOW

Device Tree Active-Low Example

reset-gpios = <&gpio0 5 GPIO_ACTIVE_LOW>;

When the driver uses the descriptor API, logical values are interpreted according to the active-low flag.

Use logical GPIO values in consumer drivers. Do not manually invert values when the descriptor already contains active-low configuration.

12. Device Tree GPIO Properties

A consumer driver can obtain GPIO descriptors through Device Tree properties.

Illustrative Device Tree Node

#include <dt-bindings/gpio/gpio.h>

demo-device {
    compatible = "demo,gpio-consumer";

    led-gpios = <&gpio0 12 GPIO_ACTIVE_HIGH>;
    button-gpios = <&gpio0 13 GPIO_ACTIVE_LOW>;

    status = "okay";
};

The property names are related to the consumer connection identifiers.

Device Tree Property Consumer Connection ID
led-gpios "led"
button-gpios "button"

Request the LED GPIO

led = devm_gpiod_get(
    dev,
    "led",
    GPIOD_OUT_LOW
);

Request the Button GPIO

button = devm_gpiod_get(
    dev,
    "button",
    GPIOD_IN
);
The controller phandle, line offset, flags and property names must match the actual hardware and binding. The values above are illustrative.

13. Optional GPIO Descriptors

Some hardware designs may not include every optional GPIO signal.

The optional descriptor API allows a driver to handle this situation.

Function

devm_gpiod_get_optional()

Example

struct gpio_desc *reset;

reset = devm_gpiod_get_optional(
    dev,
    "reset",
    GPIOD_OUT_HIGH
);

if (IS_ERR(reset))
    return PTR_ERR(reset);

if (!reset) {
    dev_info(dev, "Optional reset GPIO not available\n");
}

Possible outcomes:

  • A valid descriptor is returned when the GPIO exists.
  • NULL is returned when the optional GPIO is absent.
  • An error pointer is returned when acquisition fails.

This is why the driver checks both IS_ERR() and the NULL case.

14. GPIO Descriptor Release

When a driver uses a non-managed GPIO acquisition function, it must release the descriptor.

Non-Managed Acquisition

led = gpiod_get(dev, "led", GPIOD_OUT_LOW);

Release

gpiod_put(led);

For device-managed acquisition:

led = devm_gpiod_get(
    dev,
    "led",
    GPIOD_OUT_LOW
);

The descriptor is automatically released when the device-managed resources are cleaned up.

15. GPIO-to-IRQ Conversion

Some GPIO lines can be used as interrupt sources.

The descriptor API provides:

int gpiod_to_irq(const struct gpio_desc *desc);

Example

int irq;

irq = gpiod_to_irq(button);

if (irq < 0)
    return irq;

The resulting IRQ number can be used with an appropriate interrupt registration API.

The driver must also configure suitable interrupt trigger behavior and implement a correct interrupt handler.

16. Complete Example: GPIO Consumer Platform Driver

Objective: Create a basic platform driver that obtains an LED GPIO descriptor and controls its initial logical output state.

Source File: gpio_consumer.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/platform_device.h>
#include <linux/gpio/consumer.h>
#include <linux/of.h>

struct gpio_demo_data {
    struct gpio_desc *led;
};

static int gpio_demo_probe(struct platform_device *pdev)
{
    struct gpio_demo_data *data;

    data = devm_kzalloc(
        &pdev->dev,
        sizeof(*data),
        GFP_KERNEL
    );

    if (!data)
        return -ENOMEM;

    data->led = devm_gpiod_get(
        &pdev->dev,
        "led",
        GPIOD_OUT_LOW
    );

    if (IS_ERR(data->led))
        return dev_err_probe(
            &pdev->dev,
            PTR_ERR(data->led),
            "Failed to obtain LED GPIO\n"
        );

    platform_set_drvdata(pdev, data);

    dev_info(&pdev->dev,
             "GPIO consumer driver initialized\n");

    return 0;
}

static void gpio_demo_remove(struct platform_device *pdev)
{
    dev_info(&pdev->dev,
             "GPIO consumer driver removed\n");
}

static const struct of_device_id gpio_demo_match[] = {
    { .compatible = "demo,gpio-consumer" },
    { }
};

MODULE_DEVICE_TABLE(of, gpio_demo_match);

static struct platform_driver gpio_demo_driver = {
    .probe = gpio_demo_probe,
    .remove = gpio_demo_remove,

    .driver = {
        .name = "gpio-consumer-demo",
        .of_match_table = gpio_demo_match,
    },
};

module_platform_driver(gpio_demo_driver);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("GPIO Descriptor API Demonstration");

Code Explanation

  1. gpio/consumer.h provides the GPIO descriptor API.
  2. gpio_demo_data stores the LED descriptor.
  3. devm_kzalloc() allocates private driver data.
  4. devm_gpiod_get() obtains the LED GPIO.
  5. GPIOD_OUT_LOW configures the initial logical output LOW.
  6. IS_ERR() checks whether descriptor acquisition failed.
  7. dev_err_probe() reports probe errors and handles deferred-probe reporting appropriately.
  8. platform_set_drvdata() stores the private data.
  9. module_platform_driver() registers the platform driver.
This example initializes the GPIO but does not implement a userspace control interface or periodically change the LED. A matching platform device and valid GPIO controller must exist for probe to succeed.

Probe returns -EPROBE_DEFER GPIO controller is not ready Check controller driver and dependencies.
GPIO is already in use Another driver owns the line Inspect GPIO line ownership.
LED behavior is inverted Active-low configuration Check Device Tree polarity flags.
GPIO operation may sleep GPIO expander or sleepable controller Use the appropriate _cansleep API.

19. Practical Exercise: GPIO Descriptor API

Objective: Understand GPIO descriptor acquisition and logical input/output operations.

Exercise 1: Request an Output GPIO

Exercise 2: Request an Input GPIO

Expected Outcome

20. Important Programming Rules

  • Use descriptor APIs for new GPIO consumer drivers.
  • Include linux/gpio/consumer.h.
  • Check descriptor acquisition with IS_ERR().
  • Handle NULL when using optional GPIO functions.
  • Use logical values and respect active-low configuration.
  • Use _cansleep APIs when the controller may sleep.
  • Do not call sleepable GPIO operations from atomic or interrupt context.
  • Use managed acquisition where appropriate.
  • Do not assume GPIO offsets or physical pin numbers are universal.
  • Validate Device Tree properties against the hardware binding.

21. Ubuntu VirtualBox and LPC2129 Notes

Ubuntu in VirtualBox

Your Ubuntu virtual machine is useful for:

  • Studying GPIO descriptor API source code.
  • Compiling GPIO consumer modules.
  • Learning error handling.
  • Understanding Device Tree GPIO properties.
  • Using GPIO tools if a supported GPIO controller is exposed.

A typical x86 VirtualBox guest does not expose a physical embedded GPIO controller. The module can compile, but a real GPIO consumer probe requires a matching device and available GPIO controller.

LPC2129 with Keil uVision

For LPC2129 bare-metal work, GPIO configuration uses the microcontroller's hardware registers and pin functions.

The Linux descriptor API is not used in the Keil simulator. It belongs to the Linux kernel environment.
