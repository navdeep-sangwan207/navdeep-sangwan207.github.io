2. Introduction to the Linux GPIO Subsystem

The Linux GPIO subsystem provides a standard framework for controlling General Purpose Input/Output pins.

Different SoCs and embedded boards may have different GPIO controller hardware. Linux provides a common interface so that device drivers can request and control GPIO lines without directly manipulating controller registers.

Common GPIO Applications

  • LED control.
  • Push-button input.
  • Reset signals.
  • Enable signals.
  • Chip-select control.
  • Digital sensor signals.
  • Interrupt-generating input lines.

3. GPIO Controller

A GPIO controller is a hardware block that manages a group of GPIO lines.

It may be integrated into:

  • An application processor.
  • A microcontroller.
  • A system-on-chip.
  • An external GPIO expander connected through I2C or SPI.

Typical GPIO Controller Features

  • Input and output direction control.
  • Input value reading.
  • Output value setting.
  • Pull-up and pull-down configuration where supported.
  • Interrupt generation where supported.
  • Pin configuration and multiplexing support through related pin-control facilities.

The exact capabilities depend on the GPIO controller hardware.

4. GPIO Controller Driver

A GPIO controller driver is a kernel driver that registers a hardware GPIO controller with the Linux GPIO subsystem.

It translates standard GPIO subsystem operations into controller-specific register operations.

Example Responsibilities

  • Register the GPIO chip.
  • Configure GPIO direction.
  • Read GPIO input values.
  • Set GPIO output values.
  • Configure supported interrupt functionality.
  • Handle controller-specific register operations.

The controller driver normally uses the GPIO chip infrastructure provided by the kernel.

5. GPIO Consumer Driver

A GPIO consumer is a driver that uses one or more GPIO lines for its own device functionality.

Examples include:

  • An LED driver using a GPIO output.
  • A button driver using a GPIO input.
  • A sensor driver using a reset GPIO.
  • A peripheral driver using an enable GPIO.
GPIO Controller Driver
↓ Registers GPIO Chip

LED Consumer / Button Consumer / Sensor Consumer
A GPIO controller driver manages the GPIO hardware. A GPIO consumer driver uses GPIO lines for a particular device. These are different responsibilities.

6. GPIO Chip and GPIO Lines

Linux represents a GPIO controller using the GPIO chip infrastructure.

A GPIO chip commonly represents a controller that provides a group of GPIO lines.

Example

Suppose a GPIO controller provides 32 lines.

Line Offset Illustrative Purpose
0LED output
1Push-button input
2Peripheral reset
3Peripheral enable
4–31Other GPIO functions

These offsets are relative to the GPIO chip. They are not universal pin numbers.

GPIO Chip Device Nodes

ls /dev/gpiochip*

On systems using the GPIO character-device interface, devices may appear as:

/dev/gpiochip0
/dev/gpiochip1
The names and number of GPIO chips depend on the target system. Do not assume that gpiochip0 corresponds to a particular physical connector or SoC port.

7. GPIO Descriptor-Based API

Modern Linux GPIO consumer drivers generally use the GPIO descriptor-based API.

A descriptor is represented by:

struct gpio_desc;

The descriptor identifies a GPIO line obtained through the GPIO subsystem.

Common Descriptor APIs

API Purpose
devm_gpiod_get() Obtain a GPIO descriptor associated with a device.
gpiod_get() Obtain a GPIO descriptor without automatic device-managed cleanup.
gpiod_put() Release a descriptor obtained with non-managed APIs.
gpiod_direction_input() Configure a GPIO as input.
gpiod_direction_output() Configure a GPIO as output.
gpiod_get_value_cansleep() Read a GPIO value when the controller may sleep.
gpiod_set_value_cansleep() Set a GPIO value when the controller may sleep.

The descriptor API helps keep consumer drivers independent of controller-specific numbering.

8. GPIO Input and Output Direction

Input Direction

An input GPIO reads the logic state supplied by an external circuit.

ret = gpiod_direction_input(button);

if (ret)
    return ret;

Output Direction

An output GPIO drives a logic state, subject to the electrical limits of the controller.

ret = gpiod_direction_output(led, 0);

if (ret)
    return ret;

Reading an Input

int value;

value = gpiod_get_value_cansleep(button);

if (value < 0)
    return value;

Setting an Output

gpiod_set_value_cansleep(led, 1);
GPIO logical values account for active-low configuration. A logical value of 1 does not necessarily mean a physical HIGH voltage when the GPIO is configured as active-low.

9. Device Tree Integration with GPIO

Device Tree can describe GPIO connections between a consumer device and a GPIO controller.

Illustrative Device Tree

led-device {
    compatible = "demo,gpio-led";
    led-gpios = <&gpio0 12 0>;
    status = "okay";
};

button-device {
    compatible = "demo,gpio-button";
    button-gpios = <&gpio0 13 0>;
    status = "okay";
};

In this example:

  • &gpio0 references a GPIO controller node.
  • 12 and 13 are illustrative line offsets.
  • The final cell represents GPIO flags as defined by the binding.
  • led-gpios and button-gpios describe consumer connections.

A consumer driver can request a descriptor by using the corresponding connection ID.

devm_gpiod_get(&pdev->dev,
               "led",
               GPIOD_OUT_LOW);
Real Device Tree nodes must follow the binding for the GPIO controller and consumer device. The controller phandle, line offset, flags and compatible strings must be valid for the target hardware.

10. GPIO Interrupt Support

Some GPIO controllers can generate interrupts when an input line changes state.

Common interrupt trigger types include:

  • Rising edge.
  • Falling edge.
  • Both edges.
  • High level.
  • Low level.

A GPIO descriptor can be converted into an IRQ number using:

int irq;

irq = gpiod_to_irq(button);

if (irq < 0)
    return irq;

The returned IRQ can then be requested using the appropriate IRQ API.

GPIO-to-IRQ support depends on the controller and its interrupt configuration. Not every GPIO line supports interrupt generation.

11. GPIO Access from User Space

Linux provides a GPIO character-device interface for user-space access.

The modern GPIO character-device API is commonly used through libgpiod tools and libraries.

List GPIO Chips

gpiodetect

Display GPIO Lines

gpioinfo

Request and Read a Line

On systems with a compatible libgpiod command-line tool, commands can request a line and read its value. Exact command syntax varies between libgpiod versions.

For example, the libgpiod v2 command family includes:

gpioget --help
gpioset --help
Older tutorials may use the deprecated GPIO sysfs interface under /sys/class/gpio. New development should generally use the GPIO character-device interface and the descriptor API in kernel drivers.

12. GPIO Controller Registration

A GPIO controller driver registers its GPIO chip with the kernel GPIO subsystem.

The GPIO chip infrastructure is represented by struct gpio_chip.

Conceptual Structure

struct gpio_chip {
    const char *label;
    int base;
    unsigned int ngpio;

    int (*get_direction)(struct gpio_chip *gc,
                         unsigned int offset);

    int (*direction_input)(struct gpio_chip *gc,
                           unsigned int offset);

    int (*direction_output)(struct gpio_chip *gc,
                            unsigned int offset,
                            int value);

    int (*get)(struct gpio_chip *gc,
               unsigned int offset);

    int (*set)(struct gpio_chip *gc,
               unsigned int offset,
               int value);
};

This is a simplified conceptual illustration. The actual kernel structure contains additional members, and exact callback signatures or registration details can vary across kernel versions.

Common Registration Function

devm_gpiochip_add_data(dev, gc, data);

This registers a GPIO chip with device-managed lifetime handling. It is commonly used by GPIO controller drivers.

Peripheral consumer drivers should not normally register a GPIO chip. They request GPIO descriptors from an existing controller. GPIO chip registration is the responsibility of the controller driver.

13. GPIO Subsystem and Pin Control

GPIO control and pin multiplexing are related but distinct concepts.

GPIO Subsystem

Manages digital input and output operations on GPIO lines.

Pin Control Subsystem

Manages pin multiplexing and electrical configuration where supported.

A physical SoC pin may support several functions, such as:

  • GPIO.
  • UART transmit or receive.
  • I2C clock or data.
  • SPI clock or data.
  • PWM output.

The pin-control configuration selects the required pin function. The GPIO subsystem then manages the line when it is configured for GPIO use.

14. GPIO Kernel APIs: Managed and Non-Managed

Managed API Non-Managed API
devm_gpiod_get() gpiod_get()
Automatically released when the device is detached. Must be released using gpiod_put().
Useful in many platform and peripheral drivers. Useful when the driver needs explicit lifetime control.

Managed resources reduce cleanup code, but they do not remove the need to stop hardware activity and handle interrupts correctly before device removal.

15. Common GPIO Subsystem Errors

Problem Possible Cause Investigation
GPIO descriptor request fails Missing or incorrect GPIO property Check Device Tree and consumer connection ID.
GPIO line is busy Another consumer owns the line Inspect GPIO line information.
Direction configuration fails Controller limitation or invalid configuration Check controller documentation and error code.
Output does not change Pin mux, wiring or hardware configuration issue Inspect pinctrl and electrical connections.
GPIO interrupt does not occur Unsupported line or incorrect trigger configuration Check IRQ mapping and controller support.
GPIO chip is missing Controller driver not loaded or probe failed Inspect kernel logs and device configuration.

16. Practical Exercise: Inspect the GPIO Subsystem

Objective: Inspect GPIO controller information and available GPIO lines in Linux.

Step 1: Check GPIO Device Nodes

ls -l /dev/gpiochip*

Step 2: Install GPIO Tools

sudo apt update
sudo apt install gpiod

Step 3: Detect GPIO Controllers

gpiodetect

Step 4: Inspect GPIO Lines

gpioinfo

Step 5: Inspect Kernel Messages

sudo dmesg | grep -i gpio

Expected Result

On a supported Linux system, GPIO tools should display available GPIO chips and line information.

If no GPIO controllers are available in the virtual machine, the commands may report that no chips were found. This does not mean the Linux GPIO subsystem is missing; it may mean the virtual hardware does not expose a GPIO controller.

17. Ubuntu VirtualBox and LPC2129 Notes

Ubuntu in VirtualBox

Your Ubuntu virtual machine can be used to study:

  • GPIO subsystem architecture.
  • GPIO kernel APIs.
  • GPIO character-device tools.
  • Driver source code and compilation.
  • GPIO Device Tree concepts.

A standard x86 virtual machine may not provide a physical GPIO controller or GPIO lines. Actual GPIO operation requires suitable hardware or an emulator that implements the required controller.

LPC2129 with Keil uVision

Your LPC2129 bare-metal work uses the microcontroller's GPIO-related registers and pin configuration.

For example, LPC2129 firmware may configure direction and output registers to control an LED or read a switch.

Linux GPIO descriptor APIs are different: they are kernel interfaces used by Linux drivers on supported Linux hardware.
