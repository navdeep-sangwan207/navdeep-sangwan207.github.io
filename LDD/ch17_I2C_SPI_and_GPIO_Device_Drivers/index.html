Chapter Overview

Embedded Linux systems communicate with hardware peripherals through interfaces such as GPIO, I2C and SPI. Linux provides dedicated subsystems and driver frameworks that allow developers to control these peripherals using standardized kernel APIs.

This chapter explains GPIO management, I2C bus architecture, I2C client drivers, SPI communication, SPI device drivers and peripheral communication. You will learn how to develop basic Linux peripheral drivers using the appropriate kernel frameworks.

Important Kernel Structures and APIs

  • GPIO subsystem: Linux framework for managing general-purpose input/output pins.
  • struct gpio_desc: Represents a GPIO descriptor.
  • gpiod_get(): Obtains a GPIO descriptor for a device.
  • gpiod_direction_input(): Configures a GPIO as input.
  • gpiod_direction_output(): Configures a GPIO as output.
  • gpiod_get_value(): Reads a GPIO value.
  • gpiod_set_value(): Sets a GPIO output value.
  • struct i2c_adapter: Represents an I2C bus controller.
  • struct i2c_client: Represents an I2C peripheral connected to an adapter.
  • struct i2c_driver: Defines an I2C device driver.
  • i2c_transfer(): Performs I2C message transfers.
  • struct spi_device: Represents a peripheral connected to an SPI controller.
  • struct spi_driver: Defines an SPI device driver.
  • spi_sync(): Performs a synchronous SPI transfer.
  • spi_async(): Initiates an asynchronous SPI transfer.

Hardware Interface Comparison

  • GPIO: General-purpose digital input and output, commonly used for LEDs, buttons and control signals.
  • I2C: Two-wire serial bus using SDA and SCL, supporting addressed communication with multiple peripherals.
  • SPI: Synchronous serial interface commonly using SCLK, MOSI, MISO and chip-select signals.
