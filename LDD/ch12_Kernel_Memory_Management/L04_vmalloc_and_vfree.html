Chapter: Kernel Memory Management

Lesson: 4 – vmalloc() and vfree()

Prerequisites: C pointers, virtual memory, kmalloc(), kfree() and kernel memory allocation fundamentals.

Objective: Understand virtually contiguous kernel memory, allocate larger virtual memory regions and release them safely.

1. Introduction to vmalloc()

vmalloc() is a Linux kernel memory allocation function that allocates a memory region which is contiguous in the kernel virtual address space.

The physical pages backing this virtual region do not need to be adjacent in physical memory.

It is useful when a kernel component needs a relatively large virtually contiguous memory region and physical contiguity is not required.

Common Applications

  • Large kernel buffers.
  • Memory regions used for software processing.
  • Some internal kernel data structures.
  • Large temporary memory regions.
vmalloc() is not automatically the best choice for every large allocation. Consider memory pressure, performance, allocation context and whether a specialized allocator is more suitable.

2. Syntax of vmalloc()

#include <linux/vmalloc.h>

void *vmalloc(unsigned long size);

Parameter

ParameterDescription
size Number of bytes to allocate.

Return Value

  • Returns a pointer to the allocated virtual memory region on success.
  • Returns NULL if the allocation fails.

Basic Example

char *buffer;

buffer = vmalloc(4096);

if (!buffer) {
    pr_err("vmalloc failed\n");
    return -ENOMEM;
}

The returned pointer can be used by kernel code to access the allocated virtual memory region.

3. Understanding Virtual Contiguity

Virtual memory allows the kernel to map separate physical memory pages into a continuous virtual address range.

Kernel Virtual Address Space

Virtual Page 1
Virtual Page 2
Virtual Page 3
Virtual Page 4

Continuous virtual address range

↓ Page-table mappings ↓

Physical Memory

Physical Page A
Physical Page C
Physical Page B
Physical Page D

Physical pages may be located at different addresses

The kernel's page tables map the virtual pages to their corresponding physical pages.

Therefore, the kernel sees one continuous virtual region even though the physical pages may be scattered.

4. kmalloc() vs vmalloc()

Feature kmalloc() vmalloc()
Virtual contiguity Yes Yes
Physical contiguity Yes Not necessarily
Typical use Small and moderate allocations. Relatively large virtual regions.
Allocation infrastructure Slab-family allocator and, depending on size, page allocation mechanisms. Virtual memory area and backing physical pages.
Release function kfree() vfree()
DMA suitability Not automatically DMA-ready. Not automatically DMA-ready.
Use kmalloc() when physical contiguity is required by the kernel operation. Use vmalloc() when virtual contiguity is sufficient. For device DMA, use the Linux DMA API.

5. Introduction to vfree()

vfree() releases a memory region previously allocated using vmalloc() or a compatible vmalloc-family allocation interface.

Syntax

void vfree(const void *addr);

Example

char *buffer;

buffer = vmalloc(4096);

if (!buffer)
    return -ENOMEM;

/* Use the allocated memory */

vfree(buffer);
buffer = NULL;

After vfree() releases the allocation, the pointer must not be used to access the old memory region.

vfree() may defer some freeing work internally. Do not assume that the physical pages are synchronously returned at the exact instant the function is called.

6. Initializing vmalloc() Memory

Memory returned by vmalloc() should be initialized before it is used.

Using memset()

char *buffer;

buffer = vmalloc(4096);

if (!buffer)
    return -ENOMEM;

memset(buffer, 0, 4096);

Using vzalloc()

vzalloc() is a related function that allocates virtually contiguous memory and zero-initializes it.

#include <linux/vmalloc.h>

buffer = vzalloc(4096);

if (!buffer)
    return -ENOMEM;

Memory allocated using vzalloc() is released using vfree().

7. Allocation Constraints

vmalloc() is generally intended for contexts in which sleeping is allowed. It may perform operations that can block.

Execution Context vmalloc() Usage
Normal process context Generally suitable when sleeping is permitted.
Hard interrupt context Not suitable because it may sleep.
While holding a spinlock Not suitable if the operation can sleep.
Atomic context Not suitable.
Do not call vmalloc() from an interrupt handler or while holding a spinlock. Allocate memory in advance if an interrupt-time operation needs a buffer.

8. Why vmalloc() Is Not a DMA Allocation Function

DMA stands for Direct Memory Access. It allows a hardware device to transfer data to or from memory without requiring the CPU to copy every byte.

A device may use a DMA address that differs from the CPU's virtual address and may also differ from the physical address.

Consequently, a vmalloc() pointer must not be treated as a DMA address.

CPU Virtual Address
↓
Kernel Page Tables
↓
Physical Memory Pages
↓
DMA API / IOMMU Mapping
↓
Device DMA Address

For DMA-capable devices, use suitable interfaces such as:

  • dma_alloc_coherent() for coherent DMA allocations.
  • dma_map_single() or other streaming DMA mapping functions for suitable existing buffers.

The DMA API handles device addressing and architecture-specific mapping requirements.

9. Practical Example: vmalloc() and vfree() Module

Create a source file named vmalloc_demo.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/vmalloc.h>
#include <linux/string.h>

#define BUFFER_SIZE (64 * 1024)

static char *buffer;

static int __init vmalloc_demo_init(void)
{
    buffer = vmalloc(BUFFER_SIZE);

    if (!buffer) {
        pr_err("vmalloc: allocation failed\n");
        return -ENOMEM;
    }

    memset(buffer, 0, BUFFER_SIZE);

    snprintf(buffer, BUFFER_SIZE,
             "Linux vmalloc demonstration");

    pr_info("vmalloc: allocated %d bytes\n",
            BUFFER_SIZE);

    pr_info("Buffer content: %s\n", buffer);

    return 0;
}

static void __exit vmalloc_demo_exit(void)
{
    vfree(buffer);
    buffer = NULL;

    pr_info("vmalloc: memory released\n");
}

module_init(vmalloc_demo_init);
module_exit(vmalloc_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("vmalloc and vfree demonstration");

Code Explanation

  1. The module requests a 64 KB virtual memory region.
  2. vmalloc() allocates a virtually contiguous region.
  3. The NULL check handles allocation failure.
  4. memset() initializes the memory.
  5. snprintf() stores a message in the buffer.
  6. pr_info() displays the message in the kernel log.
  7. vfree() releases the allocation during module cleanup.

10. Makefile

Create a Makefile in the same directory.

obj-m += vmalloc_demo.o

KDIR := /lib/modules/$(shell uname -r)/build
PWD := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

Use actual tab characters before the two recipe commands.

12. Common Errors

Error Problem Correct Practice
Using kfree() on vmalloc() memory Incorrect allocator pairing. Use vfree().
Not checking NULL Possible NULL pointer dereference. Check the allocation result.
Not releasing memory Memory leak. Release the allocation during cleanup.
Using memory after vfree() Use-after-free error. Manage references and object lifetime.
Using vmalloc() in interrupt context Potential sleeping in atomic context. Preallocate memory in a sleepable context.
Using vmalloc() memory directly for DMA Invalid assumption about device addressing and physical layout. Use the DMA API.

13. Kernel Memory Inspection Tools

Linux provides several tools for observing memory usage.

Command Purpose
free -h Displays system memory usage in human-readable form.
cat /proc/meminfo Displays detailed system memory statistics.
slabtop Displays slab allocator usage.
sudo dmesg | tail Displays recent kernel ring-buffer messages.

These tools provide system-level information. They do not directly prove that a particular vmalloc() allocation belongs to a specific module.

14. Lesson Summary

  • vmalloc() allocates virtually contiguous kernel memory.
  • The backing physical pages do not need to be contiguous.
  • vfree() releases vmalloc() memory.
  • vmalloc() may sleep and is unsuitable for atomic contexts.
  • vmalloc() memory is not automatically suitable for DMA.
  • vzalloc() provides zero-initialized virtually contiguous memory.
  • Always check allocation results and release memory correctly.
