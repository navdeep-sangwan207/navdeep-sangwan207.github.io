Chapter: Kernel Memory Management

Lesson: 5 – kzalloc() and kcalloc()

Prerequisites: C pointers, arrays, kmalloc(), kfree() and vmalloc().

Objective: Understand zero-initialized kernel memory allocation and learn to allocate individual objects and arrays safely.

1. Introduction

When a kernel module allocates memory, the contents of that memory are not necessarily initialized to zero.

Using uninitialized memory can cause unpredictable behavior, incorrect calculations and accidental exposure of data.

Linux provides two useful allocation functions:

  • kzalloc() – allocates a memory block and initializes all its bytes to zero.
  • kcalloc() – allocates an array of elements and initializes the allocated memory to zero.

Both functions belong to the kmalloc-family allocation interfaces and their allocations are released using kfree().

2. Understanding kzalloc()

kzalloc() is used when a driver requires a single zero-initialized memory block.

Syntax

#include <linux/slab.h>

void *kzalloc(size_t size, gfp_t flags);

Parameters

ParameterDescription
size Number of bytes to allocate.
flags Allocation flags specifying the permitted allocation behavior.

Return Value

  • Returns a pointer to the allocated memory on success.
  • Returns NULL if allocation fails.

Example

char *buffer;

buffer = kzalloc(256, GFP_KERNEL);

if (!buffer) {
    pr_err("Memory allocation failed\n");
    return -ENOMEM;
}

All 256 bytes are initialized to zero before the pointer is returned.

3. Why Is Zero Initialization Important?

Consider a driver structure containing several fields.

struct device_data {
    int device_id;
    int status;
    char name[32];
    unsigned long counter;
};

If the structure is allocated using kmalloc(), its fields may contain old or unpredictable values until they are explicitly initialized.

Using kzalloc() initializes the entire allocated object to zero.

struct device_data *dev;

dev = kzalloc(sizeof(*dev), GFP_KERNEL);

if (!dev)
    return -ENOMEM;
kzalloc()

Zero initialization is useful, but it does not replace validation or initialization of fields that require meaningful nonzero values.

4. kmalloc() vs kzalloc()

kmalloc() kzalloc()
Allocates the requested memory. Allocates the requested memory and zero-initializes it.
Memory contents are uninitialized. All allocated bytes are initialized to zero.
Requires manual initialization when needed. Zero initialization is performed automatically.
Released using kfree(). Released using kfree().

Equivalent Initialization Concept

The following illustrates the difference:

/* Allocation without automatic zeroing */
buffer = kmalloc(256, GFP_KERNEL);

if (!buffer)
    return -ENOMEM;

memset(buffer, 0, 256);

Using kzalloc() combines allocation and zero initialization:

buffer = kzalloc(256, GFP_KERNEL);

if (!buffer)
    return -ENOMEM;

5. Introduction to kcalloc()

kcalloc() is used to allocate memory for an array of elements.

Instead of calculating the total number of bytes manually, the caller supplies:

  • Number of elements.
  • Size of each element.
  • Allocation flags.

Syntax

#include <linux/slab.h>

void *kcalloc(size_t n, size_t size, gfp_t flags);

Parameters

ParameterDescription
n Number of array elements.
size Size of each element in bytes.
flags Allocation flags.

Conceptually, the total allocation size is:

Total size = n × size

kcalloc() also checks for multiplication overflow when determining the allocation size.

6. Example of kcalloc() with an Integer Array

Suppose a driver requires an array of 10 integers.

int *values;

values = kcalloc(10, sizeof(*values), GFP_KERNEL);

if (!values) {
    pr_err("Array allocation failed\n");
    return -ENOMEM;
}

The allocation contains space for 10 integer elements, with the allocated bytes initialized to zero.

values[0] = 0
values[1] = 0
values[2] = 0
...
values[9] = 0

Access the array using normal C array indexing:

values[0] = 100;
values[1] = 200;

pr_info("First value: %d\n", values[0]);
pr_info("Second value: %d\n", values[1]);

Release the array using:

kfree(values);

7. kmalloc() vs kzalloc() vs kcalloc()

Function Purpose Zero Initialization Release
kmalloc() Allocate a memory block. No kfree()
kzalloc() Allocate one zero-initialized memory block. Yes kfree()
kcalloc() Allocate a zero-initialized array. Yes kfree()

When to Use Each Function

  • Use kmalloc() when you want to allocate memory and will initialize the required contents yourself.
  • Use kzalloc() when allocating an individual structure or buffer that should start with zeroed bytes.
  • Use kcalloc() when allocating an array of elements with zero initialization.

8. Allocation Flags

Both kzalloc() and kcalloc() accept GFP allocation flags.

GFP_KERNEL

buffer = kzalloc(256, GFP_KERNEL);

if (!buffer)
    return -ENOMEM;

Used when the current execution context permits sleeping.

GFP_ATOMIC

buffer = kzalloc(128, GFP_ATOMIC);

Used for certain allocations in atomic contexts where sleeping is not allowed. Such allocations can fail more readily and should be used carefully.

Neither kzalloc() nor kcalloc() makes a sleepable allocation safe inside an interrupt handler. Select flags based on the execution context and consider preallocation for time-critical paths.

9. Practical Example: kzalloc() for a Device Structure

Create a file named kzalloc_demo.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/slab.h>

struct device_data {
    int device_id;
    int status;
    char name[32];
};

static struct device_data *dev;

static int __init kzalloc_demo_init(void)
{
    dev = kzalloc(sizeof(*dev), GFP_KERNEL);

    if (!dev) {
        pr_err("kzalloc failed\n");
        return -ENOMEM;
    }

    dev->device_id = 1;
    dev->status = 1;

    snprintf(dev->name, sizeof(dev->name),
             "Demo Device");

    pr_info("Device ID: %d\n", dev->device_id);
    pr_info("Device Status: %d\n", dev->status);
    pr_info("Device Name: %s\n", dev->name);

    return 0;
}

static void __exit kzalloc_demo_exit(void)
{
    kfree(dev);
    dev = NULL;

    pr_info("Device structure released\n");
}

module_init(kzalloc_demo_init);
module_exit(kzalloc_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("kzalloc demonstration");

Explanation

  1. A device_data structure is declared.
  2. kzalloc() allocates memory for one structure.
  3. All bytes are initialized to zero.
  4. The driver assigns meaningful values to selected fields.
  5. The module exit function releases the structure using kfree().

10. Practical Example: kcalloc() for an Array

Create a file named kcalloc_demo.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/slab.h>

#define ARRAY_SIZE 5

static int *numbers;

static int __init kcalloc_demo_init(void)
{
    int i;

    numbers = kcalloc(
        ARRAY_SIZE,
        sizeof(*numbers),
        GFP_KERNEL
    );

    if (!numbers) {
        pr_err("kcalloc failed\n");
        return -ENOMEM;
    }

    pr_info("Initial array values:\n");

    for (i = 0; i < ARRAY_SIZE; i++) {
        pr_info("numbers[%d] = %d\n",
                i, numbers[i]);
    }

    for (i = 0; i < ARRAY_SIZE; i++) {
        numbers[i] = (i + 1) * 10;
    }

    pr_info("Updated array values:\n");

    for (i = 0; i < ARRAY_SIZE; i++) {
        pr_info("numbers[%d] = %d\n",
                i, numbers[i]);
    }

    return 0;
}

static void __exit kcalloc_demo_exit(void)
{
    kfree(numbers);
    numbers = NULL;

    pr_info("Array memory released\n");
}

module_init(kcalloc_demo_init);
module_exit(kcalloc_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("kcalloc array allocation demonstration");

Expected Illustrative Output

Initial array values:
numbers[0] = 0
numbers[1] = 0
numbers[2] = 0
numbers[3] = 0
numbers[4] = 0

Updated array values:
numbers[0] = 10
numbers[1] = 20
numbers[2] = 30
numbers[3] = 40
numbers[4] = 50

13. Common Programming Mistakes

Mistake Problem Correct Practice
Not checking NULL Possible NULL pointer dereference. Check every allocation result.
Using the wrong element size Incorrect array allocation size. Use sizeof(*pointer) where appropriate.
Not freeing memory Memory leak. Use kfree() in the cleanup path.
Accessing after kfree() Use-after-free. Stop all users before releasing memory.
Assuming zero means fully configured Required nonzero fields may remain unset. Initialize every field according to its purpose.
Using GFP_KERNEL in atomic context Potential sleeping in an invalid context. Use an appropriate allocation strategy.

14. Lesson Summary

  • kzalloc() allocates one zero-initialized memory block.
  • kcalloc() allocates an array of zero-initialized elements.
  • Both functions belong to the kmalloc-family allocation interfaces.
  • Both allocations are released using kfree().
  • kcalloc() checks for multiplication overflow when calculating the allocation size.
  • Allocation results must be checked for NULL.
  • Zero initialization does not eliminate the need for proper field initialization and validation.
