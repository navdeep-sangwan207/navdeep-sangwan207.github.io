Lesson: 2 – Kernel Memory Allocation

Prerequisites: C pointers, dynamic memory allocation, Linux kernel architecture and Lesson 1.

Objective: Understand how the Linux kernel allocates memory, select appropriate allocation interfaces, handle allocation failures and release memory safely in device drivers.

1. Introduction

Kernel memory allocation is the process of requesting memory from resources managed by the Linux kernel.

Unlike ordinary user-space programs, kernel modules cannot directly use standard C library functions such as malloc() and free().

Linux provides kernel-specific allocation functions to manage memory for:

  • Device-driver data structures.
  • Character-driver buffers.
  • Network packet processing.
  • Device configuration information.
  • Temporary data and internal objects.
  • Hardware communication buffers.

2. Why Is Kernel Memory Allocation Required?

Consider a character device driver that receives data from a user application.

User Application
↓ write()
Character Driver
↓ copy_from_user()
Kernel Memory Buffer

The driver requires its own kernel-space buffer to store the received data.

Kernel memory allocation provides the memory needed for this operation.

Common Requirements

Requirement Example
Fixed-size buffer 256-byte device data buffer.
Variable-size buffer Buffer size selected according to a runtime request.
Device structure Structure storing device configuration and status.
Array allocation Storage for multiple device entries.
Large memory region Large virtual buffer for software processing.

3. Kernel Memory Allocation Interfaces

Linux provides several memory allocation interfaces. The correct choice depends on the size, physical layout and usage requirements.

Function Purpose Release Function
kmalloc() Allocates physically contiguous memory. kfree()
kzalloc() Allocates zero-initialized memory. kfree()
kcalloc() Allocates a zero-initialized array. kfree()
vmalloc() Allocates virtually contiguous memory. vfree()
alloc_pages() Allocates physical pages. __free_pages()

The next lessons examine these functions individually.

4. Dynamic Memory Allocation in the Kernel

Dynamic allocation is useful when the required memory size is determined during runtime.

General Syntax

pointer = kmalloc(size, flags);

Parameters:

  • size specifies the requested number of bytes.
  • flags specifies allocation behavior and constraints.
  • The returned pointer refers to the allocated kernel memory, or is NULL if allocation fails.

Example

char *buffer;

buffer = kmalloc(256, GFP_KERNEL);

if (!buffer) {
    return -ENOMEM;
}

/* Use allocated buffer */

kfree(buffer);

The memory must be released with the corresponding kernel deallocation function when it is no longer needed.

5. Understanding Allocation Flags

Allocation flags tell the kernel how an allocation request may be satisfied.

GFP_KERNEL

GFP_KERNEL is commonly used in normal process context. The allocation may sleep while the kernel attempts to obtain memory.

buffer = kmalloc(512, GFP_KERNEL);

GFP_ATOMIC

GFP_ATOMIC is used when the allocation must not sleep, such as in certain atomic or interrupt contexts. It has more restrictive allocation behavior and may fail when memory reserves are unavailable.

buffer = kmalloc(128, GFP_ATOMIC);

Comparison

GFP_KERNEL GFP_ATOMIC
May sleep. Must not sleep.
Suitable for normal process context. Suitable for certain atomic contexts.
Can use reclaim mechanisms that may block. Uses more restrictive allocation behavior.
Generally preferred when sleeping is permitted. Should be used only when non-sleeping allocation is required.
Never use GFP_KERNEL in interrupt context or while holding a spinlock. Prefer preallocation where possible instead of allocating memory in time-critical paths.

6. Physical Contiguity and Virtual Contiguity

Memory allocation functions differ in the physical layout of the memory they return.

Physically Contiguous Memory

Physically contiguous memory occupies adjacent physical addresses.

Physical Block 1
Physical Block 2
Physical Block 3

Adjacent physical memory blocks

kmalloc() provides physically contiguous memory for the requested allocation.

Virtually Contiguous Memory

Virtually contiguous memory appears as one continuous address range in the kernel's virtual address space, even when its physical pages are not adjacent.

Virtual Address Range
↓
Physical Page A
Physical Page C
Physical Page B

Physical pages need not be adjacent

vmalloc() provides virtually contiguous memory.

Virtual contiguity does not mean physical contiguity. A virtually contiguous buffer is not automatically suitable for direct DMA by a device.

7. Allocation Failure Handling

Kernel memory allocation can fail because sufficient suitable memory is unavailable.

Every allocation result must be checked before the pointer is used.

char *buffer;

buffer = kmalloc(1024, GFP_KERNEL);

if (!buffer) {
    pr_err("Memory allocation failed\n");
    return -ENOMEM;
}

/* Safe to use allocated memory here */

kfree(buffer);

Returning -ENOMEM informs the calling code that memory allocation failed.

Why Allocation Can Fail

  • Insufficient available memory.
  • Memory fragmentation.
  • Large physically contiguous allocation requirements.
  • Allocation restrictions imposed by the execution context.
  • System memory pressure.

8. Memory Initialization

Memory allocated using kmalloc() is not automatically initialized to zero.

If the driver uses uninitialized memory, it may read unpredictable values or expose information unintentionally.

Manual Initialization

char *buffer;

buffer = kmalloc(256, GFP_KERNEL);

if (!buffer) {
    return -ENOMEM;
}

memset(buffer, 0, 256);

Zero-Initialized Allocation

char *buffer;

buffer = kzalloc(256, GFP_KERNEL);

if (!buffer) {
    return -ENOMEM;
}

kzalloc() performs allocation and zero initialization together.

9. Releasing Allocated Memory

Allocated memory must be released when it is no longer required.

For kmalloc-family Allocations

buffer = kmalloc(256, GFP_KERNEL);

/* Use buffer */

kfree(buffer);

For vmalloc Allocations

buffer = vmalloc(4096);

/* Use buffer */

vfree(buffer);

Always use the appropriate release function for the allocation mechanism.

Do not call kfree() on a vmalloc() allocation. Similarly, do not call vfree() on a kmalloc() allocation.

A driver should also define clear ownership of each allocation. Every allocation should have a known lifetime and a corresponding cleanup path.

11. Practical Example: Allocate and Release Memory

Create a kernel module named memory_allocation.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/slab.h>

#define BUFFER_SIZE 512

static char *device_buffer;

static int __init memory_init(void)
{
    device_buffer = kmalloc(
        BUFFER_SIZE,
        GFP_KERNEL
    );

    if (!device_buffer) {
        pr_err("Memory allocation failed\n");
        return -ENOMEM;
    }

    memset(device_buffer, 0, BUFFER_SIZE);

    snprintf(
        device_buffer,
        BUFFER_SIZE,
        "Linux Kernel Memory Allocation"
    );

    pr_info("Allocated buffer: %s\n", device_buffer);

    return 0;
}

static void __exit memory_exit(void)
{
    kfree(device_buffer);

    device_buffer = NULL;

    pr_info("Kernel memory released\n");
}

module_init(memory_init);
module_exit(memory_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Kernel Memory Allocation Demonstration");

Makefile

obj-m += memory_allocation.o

KDIR := /lib/modules/$(shell uname -r)/build
PWD := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

Compile the Module

make

Load the Module

sudo insmod memory_allocation.ko

View Kernel Messages

sudo dmesg | tail -n 10

Illustrative output:

Allocated buffer: Linux Kernel Memory Allocation

Remove the Module

sudo rmmod memory_allocation

The module cleanup function releases the allocated memory.

12. Common Memory Allocation Mistakes

Mistake Problem Correct Practice
Not checking allocation result Null pointer dereference. Check for NULL before use.
Not releasing memory Memory leak. Release memory on every appropriate cleanup path.
Using GFP_KERNEL in interrupt context Sleeping in an atomic context. Use preallocation or an appropriate non-sleeping strategy.
Using uninitialized memory Unpredictable data and possible information exposure. Initialize memory before use.
Using the wrong release function Invalid memory deallocation. Match the release function to the allocator.
Using memory after release Use-after-free error. Manage references and object lifetime.

13. Lesson Summary

  • Kernel memory allocation provides memory to kernel components and device drivers.
  • kmalloc() allocates physically contiguous memory.
  • kzalloc() allocates zero-initialized memory.
  • kcalloc() allocates zero-initialized arrays.
  • vmalloc() allocates virtually contiguous memory.
  • GFP_KERNEL may sleep and is used in suitable process contexts.
  • GFP_ATOMIC is used for certain non-sleeping allocation requirements.
  • Allocation results must always be checked.
  • Memory must be initialized when necessary and released correctly.
