Chapter: Kernel Memory Management

Lesson: 1 – Introduction to Kernel Memory Management

Prerequisites: C programming, pointers, structures, Linux kernel architecture and kernel programming fundamentals.

Objective: Understand how Linux manages memory in kernel space and why memory allocation, protection, mapping and deallocation are essential in device-driver development.

1. Introduction

Memory management is one of the most important responsibilities of an operating system. Linux must manage memory resources for user applications, kernel subsystems and device drivers.

A Linux device driver frequently needs memory to:

  • Store device configuration and status information.
  • Maintain buffers for data transfer.
  • Store structures representing devices.
  • Manage incoming and outgoing data.
  • Maintain queues and internal driver objects.
  • Prepare memory for hardware communication.

Kernel memory management provides interfaces that allow drivers to request, use and release memory safely.

Kernel memory allocation is different from ordinary user-space allocation. Kernel code cannot simply use the C library's malloc() and free() functions.

2. What Is Memory Management?

Memory management is the process of controlling how memory is allocated, accessed, protected and released during program execution.

The Linux kernel manages several memory-related responsibilities:

  • Allocating memory to kernel components.
  • Managing physical memory pages.
  • Maintaining virtual memory mappings.
  • Providing memory protection.
  • Managing memory shared with hardware devices.
  • Reclaiming memory when it is no longer required.

Basic Memory Management Operations

Operation Description
Allocation Obtaining memory for a required purpose.
Access Reading or writing allocated memory.
Mapping Establishing an address translation between memory spaces.
Protection Controlling which code can access particular memory regions.
Deallocation Releasing memory when it is no longer needed.

3. User-Space and Kernel-Space Memory

Linux provides separate virtual address spaces for user applications and kernel execution.

User Space

Application memory, stack, heap and shared mappings

System Call Interface ↓
Kernel Space

Kernel code, kernel data, driver memory and kernel-managed objects

User-Space Memory

User-space memory is used by ordinary applications. A process normally cannot directly access arbitrary kernel memory.

Common user-space allocation functions include:

malloc()
calloc()
realloc()
free()

Kernel-Space Memory

Kernel-space memory is used by the operating system and kernel modules.

Common kernel memory functions include:

kmalloc()
kfree()
kzalloc()
kcalloc()
vmalloc()
vfree()
Kernel pointers and user pointers belong to different address-space contexts. A driver must use appropriate user-memory access functions such as copy_to_user() and copy_from_user() when transferring data.

4. Why Do Device Drivers Need Memory?

Device drivers interact with hardware or software-defined devices. They often need memory for temporary and persistent data.

Example: Character Device Driver

A character driver may maintain a buffer that stores data written by an application.

User Application
write() ↓
Character Driver
copy_from_user() ↓
Kernel Buffer

The kernel buffer stores data independently of the application's user-space buffer.

Other Examples

Driver Type Memory Requirement
Character driver Read/write buffers and device state.
Network driver Packet buffers and transmission queues.
Block driver Request and block I/O structures.
USB driver Transfer buffers and USB request structures.
I2C/SPI driver Communication buffers and device configuration.

5. Physical Memory and Virtual Memory

Physical Memory

Physical memory is the actual RAM installed in a computer or virtual machine.

Virtual Memory

Virtual memory provides an address space that is translated into physical memory by the processor's memory-management hardware and operating-system page tables.

Virtual Address
↓ Address Translation
Page Tables / MMU
↓
Physical Memory

The Memory Management Unit (MMU) performs address translation using page-table information configured by the operating system.

Virtual memory allows processes and kernel components to use virtual addresses without needing to know the physical location of every memory page.

6. Kernel Memory Allocation

Kernel memory allocation means requesting memory from kernel-managed memory resources.

Linux provides different allocation interfaces depending on the size, layout and purpose of the memory.

Function Purpose
kmalloc() Allocates physically contiguous memory for the requested size.
kfree() Releases memory allocated by compatible kmalloc-family allocators.
kzalloc() Allocates memory and initializes it to zero.
kcalloc() Allocates an array and initializes the allocated memory to zero.
vmalloc() Allocates virtually contiguous memory that need not be physically contiguous.
vfree() Releases memory allocated by vmalloc().

These functions are explored in detail in the following lessons.

7. Kernel Memory Allocation Lifecycle

Request Memory
↓
Check Allocation Result
↓
Initialize Memory
↓
Use Memory
↓
Release Memory

A driver should follow this lifecycle:

  1. Request the required memory.
  2. Check whether allocation succeeded.
  3. Initialize the memory if necessary.
  4. Use the allocated memory safely.
  5. Release it when it is no longer required.

Forgetting to release memory can cause a kernel memory leak.

8. Static and Dynamic Memory Allocation

Static Allocation

Static memory allocation reserves storage as part of a variable's fixed storage duration.

static int device_status;
static char device_buffer[256];

The storage exists for the lifetime of the module or program containing the variable.

Dynamic Allocation

Dynamic allocation requests memory while the code is executing.

char *buffer;

buffer = kmalloc(256, GFP_KERNEL);

if (!buffer) {
    return -ENOMEM;
}

/* Use buffer */

kfree(buffer);

Dynamic allocation is useful when the required size is known only at runtime.

Static Allocation Dynamic Allocation
Storage size is fixed at declaration. Size can be selected at runtime.
No explicit allocation call is required. Requires an allocation function.
Lifetime is determined by storage duration. Lifetime is managed by allocation and release.
Suitable for fixed-size data. Suitable for variable-size requirements.

9. Memory Allocation in Different Execution Contexts

Kernel memory allocation must consider the execution context in which the request occurs.

Process Context

Process context is associated with a task executing in the kernel on behalf of a process or thread.

Some allocation requests using GFP_KERNEL may sleep while the kernel obtains memory.

Interrupt Context

Interrupt context executes in response to an interrupt. It cannot perform operations that sleep.

Allocation in interrupt context must use an appropriate non-sleeping allocation strategy, such as a suitable GFP_ATOMIC request when necessary. Preallocation is often preferable.

Never use a potentially sleeping allocation request such as GFP_KERNEL in interrupt context or while holding a spinlock.

10. Memory Management and DMA

Some device drivers transfer data directly between hardware and memory using Direct Memory Access (DMA).

DMA allows a device to transfer data without requiring the CPU to copy every byte individually.

CPU / Driver
↓ Configure DMA
DMA Controller / Device
↔
Memory Buffer

DMA memory management has additional requirements:

  • Device-accessible memory addresses.
  • DMA address mapping.
  • Cache-coherency considerations.
  • Appropriate buffer alignment and size.
  • Correct synchronization between CPU and device.

Linux provides DMA APIs for these requirements. Ordinary kmalloc() or vmalloc() allocation alone does not guarantee that a buffer is suitable for DMA.

11. Common Kernel Memory Management Problems

Problem Description Prevention
Memory leak Allocated memory is never released. Release memory on every appropriate exit path.
Null pointer dereference Code accesses an unsuccessful allocation result. Check allocation results before use.
Use-after-free Code accesses memory after it has been released. Manage object lifetime and references.
Double free The same allocation is released more than once. Use clear ownership rules.
Buffer overflow Code accesses beyond allocated memory. Validate all sizes and offsets.
Fragmentation Free memory is divided into smaller blocks. Choose appropriate allocation interfaces and sizes.
Race condition Concurrent execution accesses shared memory unsafely. Use suitable synchronization.

12. Kernel Memory Management in Device Drivers

A device driver must select the correct allocation mechanism based on its requirements.

Example: Memory-Backed Device Buffer

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/slab.h>

#define BUFFER_SIZE 256

static char *device_buffer;

static int __init memory_driver_init(void)
{
    device_buffer = kmalloc(
        BUFFER_SIZE,
        GFP_KERNEL
    );

    if (!device_buffer) {
        pr_err("Memory allocation failed\n");
        return -ENOMEM;
    }

    pr_info("Memory allocated successfully\n");

    return 0;
}

static void __exit memory_driver_exit(void)
{
    kfree(device_buffer);

    pr_info("Memory released\n");
}

module_init(memory_driver_init);
module_exit(memory_driver_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Kernel Memory Allocation Example");

This simple module demonstrates the allocation lifecycle:

  • kmalloc() requests memory.
  • GFP_KERNEL permits a sleepable allocation context.
  • The result is checked before use.
  • kfree() releases the allocated memory during cleanup.
This example is intended for process-context module initialization and cleanup. Do not copy the same allocation strategy into interrupt context without considering its sleeping behavior.

13. Important Linux Memory Management Terms

Term Meaning
MMU Memory Management Unit; hardware that performs address translation and memory protection.
Page A basic unit of memory management in Linux.
Page Table Data structure used for virtual-to-physical address translation.
Slab Allocator Kernel allocation infrastructure optimized for frequently used objects.
GFP Flags Flags describing the allocation behavior and constraints.
DMA Direct Memory Access; device data transfer without CPU copying every byte.
Fragmentation Division of available memory into separate free regions.
Memory Leak Memory that remains allocated after it is no longer needed.

14. Lesson Summary

  • Kernel memory management controls allocation, access, mapping and release of memory.
  • User space and kernel space have separate memory-access rules.
  • Device drivers need memory for buffers, state and internal structures.
  • kmalloc() and vmalloc() provide different memory allocation behavior.
  • Allocated memory must be checked, initialized and released correctly.
  • Allocation flags determine whether an allocation may sleep.
  • Interrupt context cannot perform sleeping operations.
  • DMA requires appropriate Linux DMA APIs.
  • Memory leaks, use-after-free and buffer overflows must be prevented.
