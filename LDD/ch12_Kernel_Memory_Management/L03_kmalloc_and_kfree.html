Objective: Understand how to allocate and release physically contiguous kernel memory using kmalloc() and kfree().

1. Introduction to kmalloc()

kmalloc() is a Linux kernel function used to allocate a requested number of bytes from kernel-managed memory.

It is commonly used in Linux device drivers to allocate:

  • Character-driver data buffers.
  • Device-specific data structures.
  • Temporary kernel data.
  • Small arrays and objects.
  • Internal driver management structures.

Unlike the standard C library function malloc(), kmalloc() is designed for kernel-space allocation and accepts allocation flags that specify the permitted allocation behavior.

2. Syntax of kmalloc()

#include <linux/slab.h>

void *kmalloc(size_t size, gfp_t flags);

Parameters

ParameterDescription
size Number of bytes requested by the caller.
flags Allocation flags describing the context and permitted allocation behavior.

Return Value

  • Returns a pointer to allocated kernel memory when successful.
  • Returns NULL when allocation fails.
char *buffer;

buffer = kmalloc(256, GFP_KERNEL);

if (buffer == NULL) {
    pr_err("Allocation failed\n");
    return -ENOMEM;
}
The returned pointer is a kernel virtual address. It must not be directly dereferenced from user space.

3. How kmalloc() Works

Linux kernel memory allocation uses multiple layers of memory management.

For many relatively small allocations, kmalloc() obtains memory through the kernel's slab allocator infrastructure. SLUB is the default slab allocator on many Linux configurations.

For larger requests, the implementation may use page-level allocation mechanisms. The exact internal path depends on the kernel version, configuration and requested size.

Important Properties

  • Returns memory that is virtually contiguous.
  • Provides physical contiguity for the requested allocation.
  • Suitable for many ordinary driver data structures and buffers.
  • Does not automatically initialize the returned memory.
  • Does not automatically make the memory DMA-safe.

4. Physically Contiguous Memory

Physical contiguity means that the allocated memory occupies adjacent physical addresses.

Conceptual sequence of adjacent physical memory units

For example, a driver requests a 1024-byte allocation. kmalloc() provides a suitable contiguous region for that request.

Physical contiguity alone does not guarantee that a device can access the memory. DMA-capable devices may use different address spaces, IOMMUs and architecture-specific mappings. Use the Linux DMA API for DMA buffers.

5. Understanding GFP_KERNEL

The second argument of kmalloc() specifies allocation flags.

buffer = kmalloc(256, GFP_KERNEL);

GFP_KERNEL is the common choice when allocation occurs in a context where sleeping is permitted.

The allocation may trigger memory reclaim or other operations that can block the current task.

Where Can GFP_KERNEL Be Used?

  • Module initialization routines, when the surrounding operation permits sleeping.
  • Ordinary process-context driver operations.
  • Driver callbacks that execute in sleepable context and do not hold incompatible locks.

Where Must It Not Be Used?

  • Hard interrupt handlers.
  • While holding a spinlock.
  • Other atomic contexts where sleeping is forbidden.

For non-sleeping contexts, an appropriate strategy may use GFP_ATOMIC, but preallocating buffers before the critical path is often preferable.

6. Introduction to kfree()

kfree() releases memory that was previously allocated using kmalloc-family functions.

Syntax

void kfree(const void *objp);

Example

char *buffer;

buffer = kmalloc(256, GFP_KERNEL);

if (!buffer)
    return -ENOMEM;

/* Use the allocated memory */

kfree(buffer);
buffer = NULL;

After kfree() releases the allocation, the memory must no longer be accessed through the old pointer.

Setting a pointer to NULL after freeing it can help prevent accidental reuse through that particular pointer. It does not fix other pointers that may still refer to the freed allocation.

This lifecycle is important in kernel modules because memory allocated during initialization may need to remain available until the module is unloaded.

8. Practical Example: Basic kmalloc() and kfree() Module

Create a source file named kmalloc_demo.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/slab.h>
#include <linux/string.h>

#define BUFFER_SIZE 256

static char *buffer;

static int __init kmalloc_demo_init(void)
{
    buffer = kmalloc(BUFFER_SIZE, GFP_KERNEL);

    if (!buffer) {
        pr_err("kmalloc: allocation failed\n");
        return -ENOMEM;
    }

    memset(buffer, 0, BUFFER_SIZE);

    snprintf(buffer, BUFFER_SIZE,
             "Hello from kmalloc");

    pr_info("kmalloc: allocated %d bytes\n",
            BUFFER_SIZE);

    pr_info("Buffer content: %s\n", buffer);

    return 0;
}

static void __exit kmalloc_demo_exit(void)
{
    kfree(buffer);
    buffer = NULL;

    pr_info("kmalloc: memory released\n");
}

module_init(kmalloc_demo_init);
module_exit(kmalloc_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("kmalloc and kfree demonstration");

Explanation

  1. buffer is a pointer to the allocated memory.
  2. kmalloc() requests 256 bytes.
  3. GFP_KERNEL permits a sleepable allocation.
  4. The NULL check handles allocation failure.
  5. memset() initializes the buffer.
  6. snprintf() writes a string within the specified buffer size.
  7. kfree() releases the memory during module cleanup.

9. Makefile

Create a file named Makefile in the same directory.

obj-m += kmalloc_demo.o

KDIR := /lib/modules/$(shell uname -r)/build
PWD := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

Ensure the recipe lines begin with actual tab characters.

10. Compile and Test in Ubuntu

Step 1: Install Build Dependencies

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Step 2: Compile the Module

make

Successful compilation produces kmalloc_demo.ko.

Step 3: Load the Module

sudo insmod kmalloc_demo.ko

Step 4: Check Kernel Messages

sudo dmesg | tail -n 20

Illustrative output:

Step 5: Remove the Module

Kernel messages shown above are illustrative. Actual output may include timestamps, log-level prefixes and messages from other kernel components.

11. Common Errors in kmalloc() and kfree()

Error Explanation Prevention
NULL pointer dereference Using the pointer after allocation failure. Check the return value of kmalloc().
Memory leak Allocated memory is never released. Free allocations on all applicable cleanup paths.
Double free Releasing the same allocation more than once. Maintain clear ownership and release exactly once.
Use-after-free Accessing memory after kfree(). Ensure no active users remain before freeing memory.
Buffer overflow Writing beyond the allocated size. Validate lengths and use bounded operations.
Wrong allocator pairing Passing a vmalloc() pointer to kfree(). Use the matching deallocation function.

12. kmalloc() vs malloc()

kmalloc() malloc()
Used in kernel space. Used in user space through the C library.
Declared through kernel headers such as linux/slab.h. Declared in stdlib.h.
Accepts allocation flags. Does not accept GFP allocation flags.
Released using kfree(). Released using free().
Returns a kernel virtual address. Returns a user-space virtual address.
Never call the user-space free() function on a kernel allocation. Likewise, kernel kfree() is not a user-space memory deallocator.

13. When Should You Use kmalloc()?

Use kmalloc() when:

  • The requested allocation is reasonably sized.
  • Physical contiguity is required by the kernel operation.
  • The allocation is not required to be zero-initialized automatically.
  • The calling context permits the selected allocation flags.
  • The buffer does not require a different specialized allocation API.

Consider alternatives when:

  • A large virtually contiguous buffer is needed: consider vmalloc().
  • Zero-initialized memory is required: consider kzalloc().
  • A zero-initialized array is needed: consider kcalloc().
  • DMA memory is required: use the DMA API.

14. Lesson Summary

  • kmalloc() dynamically allocates kernel memory.
  • It returns physically contiguous memory for the requested allocation.
  • GFP_KERNEL is commonly used in sleepable process context.
  • Allocation failure is indicated by NULL.
  • kmalloc() memory is not automatically zero-initialized.
  • kfree() releases kmalloc-family allocations.
  • Memory must not be accessed after it is freed.
  • Every allocation needs a clear ownership and cleanup strategy.
