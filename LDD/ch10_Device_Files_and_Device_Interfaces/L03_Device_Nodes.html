1. Introduction to Device Nodes

A device node is a special filesystem entry that represents a character or block device interface. Device nodes are commonly located in the Linux /dev directory.

A user-space application can open a device node and use supported system calls to communicate with the corresponding kernel device interface.

A device node contains information such as:

  • Device type: character or block.
  • Major device number.
  • Minor device number.
  • Ownership and permission information.

The device node identifies an interface; the driver or relevant kernel subsystem implements the operations.

2. What Is a Device Node?

A device node is not an ordinary file containing application data. It is a special filesystem object whose metadata identifies a device interface.

For example, /dev/null is a character device node. Writing to it discards the supplied data, while reading from it returns end-of-file.

Important characteristics

  • Device nodes are filesystem entries.
  • They can represent physical or virtual devices.
  • They are associated with device numbers.
  • They have ownership and permission bits.
  • They provide a route to kernel-managed device operations.
Important: A device node alone does not implement hardware functionality. The corresponding driver or kernel subsystem must be registered and operational.

3. Types of Device Nodes

3.1 Character Device Node

A character device node represents a character-device interface. Such interfaces commonly transfer data as streams of bytes or support device-specific operations.

Examples include:

  • /dev/null
  • /dev/tty
  • /dev/ttyS0, when a corresponding serial interface exists.
  • Custom character-device nodes created by drivers.

In the output of ls -l, the first character is c.

3.2 Block Device Node

A block device node represents a block-oriented storage interface. The Linux block layer manages storage requests and related I/O operations.

Examples include:

  • /dev/sda, when a disk uses this naming scheme.
  • /dev/nvme0n1, for a possible NVMe namespace.
  • /dev/loop0, for a loop device when present.

In the output of ls -l, the first character is b.

4. Major and Minor Numbers

Each character or block device node has a device number containing two components.

Major number

The major number identifies a registered device-number range associated with a driver or device subsystem.

Minor number

The minor number distinguishes device instances or interfaces within the major-number range.

Device Number
↓
Major Number
Minor Number

Major: registered device-number range

Minor: particular device instance or interface

In kernel code, the combined device number is represented by dev_t.

#include <linux/types.h>
#include <linux/kdev_t.h>

dev_t dev;

unsigned int major_number = MAJOR(dev);
unsigned int minor_number = MINOR(dev);

MAJOR() and MINOR() extract the corresponding components from a device number.

A major number does not necessarily identify one physical hardware model. A driver can manage multiple instances using different minor numbers.

6. Device Node Creation and Driver Registration

Creating a device node and registering a driver are separate operations.

StepOperationPurpose
1alloc_chrdev_region()Allocates a device-number range.
2cdev_init()Initializes a character-device object and associates file operations.
3cdev_add()Registers the character device with the kernel.
4device_create()Creates a device-model object.
5devtmpfs/udev or mknodProvides the corresponding filesystem device node.
Do not confuse these operations: cdev_add() does not create a device node. device_create() creates a device-model object; devtmpfs and/or udev normally make the corresponding node available under /dev.

The exact behavior of automatic node creation depends on the kernel and user-space device-management configuration.

7. Creating a Device Node with mknod

The mknod command can manually create a character or block device node.

General syntax

sudo mknod PATH TYPE MAJOR MINOR

Where:

  • PATH is the desired device-node path.
  • TYPE is c for character or b for block.
  • MAJOR is the major number.
  • MINOR is the minor number.

Illustrative example

sudo mknod /dev/mydevice c 240 0

This requests a character device node with major number 240 and minor number 0.

The numbers are examples only. Use the actual numbers allocated and registered by the driver. Arbitrary numbers do not create a working driver interface.

Verify the node

ls -l /dev/mydevice
stat /dev/mydevice

These commands inspect the newly created node and its metadata.

8. Device Node Permissions

Device nodes use standard Linux ownership and permission mechanisms. These determine which users and groups can access the device interface.

Permission categories include:

  • Owner: Permissions for the file owner.
  • Group: Permissions for members of the assigned group.
  • Others: Permissions for all other users.

Common permission symbols are:

PermissionMeaning
rRead access.
wWrite access.
xExecute/search permission where applicable.
-Permission not granted.

Inspect permissions:

ls -l /dev/tty
stat /dev/tty

Device access can also be affected by security policies and driver-specific checks, not just the filesystem permission bits.

9. How Applications Use Device Nodes

A user-space application generally opens a device node to obtain a file descriptor. It then uses supported operations to communicate with the device interface.

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;

    fd = open("/dev/null", O_WRONLY);

    if (fd < 0)
    {
        perror("open");
        return 1;
    }

    if (write(fd, "Device node test", 16) < 0)
    {
        perror("write");
        close(fd);
        return 1;
    }

    close(fd);

    printf("Write operation completed\n");

    return 0;
}

Compile and execute

gcc node_test.c -o node_test
./node_test

Expected output

Write operation completed

The example writes to /dev/null, which discards the data. The application message confirms that its write call completed without reporting an error.

10. Device Nodes and the Virtual Filesystem

Linux uses the Virtual Filesystem (VFS) to provide a common interface to different filesystem and device operations.

When a process opens a device node:

  1. The application calls open().
  2. The VFS resolves the path and identifies the special filesystem entry.
  3. The device number and device type identify the relevant device interface.
  4. The kernel routes the operation through the corresponding device infrastructure.
  5. The driver or subsystem handles the requested operation.

The precise routing mechanism depends on the device type and the kernel subsystem involved.

11. Device Nodes in Virtual Machines

Ubuntu running inside VirtualBox also contains device nodes. These can represent virtual hardware and kernel-provided interfaces.

For example:

  • Virtual storage devices.
  • Terminal and pseudo-terminal devices.
  • Virtual serial interfaces, when configured.
  • Kernel-provided devices such as /dev/null.

However, a device node for a physical GPIO, I2C or SPI controller will not necessarily be available inside a virtual machine.

For physical peripheral driver exercises, suitable hardware access, USB passthrough, supported host interfaces or hardware emulation may be required.

14. Summary

  • A device node is a special filesystem entry representing a device interface.
  • Device nodes are commonly located in /dev.
  • Character device nodes begin with c in long-listing output.
  • Block device nodes begin with b.
  • Device numbers contain major and minor components.
  • Device nodes have ownership and permissions.
  • mknod creates a node but does not register a driver.
  • cdev_add() registers a character device but does not create its filesystem node.
  • VFS and the relevant device subsystem route operations to the appropriate driver interface.
