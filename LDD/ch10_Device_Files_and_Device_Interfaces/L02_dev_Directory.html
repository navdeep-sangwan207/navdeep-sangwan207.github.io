Lesson: 2 – /dev Directory

Level: Beginner to Intermediate

Prerequisites: Device files, character and block devices, major and minor numbers.

Learning Goal: Understand the purpose, organization and management of the Linux /dev directory.

1. Introduction to the /dev Directory

Linux provides a special directory named /dev that contains device nodes used to access device interfaces.

Applications and system utilities use entries inside this directory to communicate with kernel-managed devices and virtual interfaces.

Examples include:

  • /dev/null – discards data written to it.
  • /dev/zero – provides zero-valued bytes when read.
  • /dev/tty – accesses the controlling terminal.
  • /dev/sda – a possible name for a disk device.
  • /dev/nvme0n1 – a possible name for an NVMe storage device.

The /dev directory provides a standard location for device nodes. It does not contain the driver source code or the physical devices themselves.

2. Why Is the /dev Directory Required?

Without a standard device interface, applications would need different mechanisms to communicate with different types of devices.

Linux uses device nodes to provide a common filesystem-based interface.

Major purposes

  • Standard access: Applications can use familiar file operations.
  • Device identification: Device nodes contain device type and device-number information.
  • Hardware abstraction: Applications do not generally need to manipulate hardware registers directly.
  • Permission management: Ownership and permission bits control access.
  • Dynamic device management: Device nodes can be created and managed as devices appear and disappear.
  • Uniform interface: Similar system calls can be used across many device interfaces.

3. Understanding the Contents of /dev

The contents of /dev vary according to the hardware, kernel configuration and running system.

To list its contents:

ls /dev

To display detailed information:

ls -l /dev

Typical entries may include the following categories:

Category Example Purpose
Null device /dev/null Discards written data.
Zero device /dev/zero Returns zero-valued bytes.
Random interface /dev/random Provides access to the kernel random-number interface.
Terminal interface /dev/tty Represents the controlling terminal.
Serial interface /dev/ttyS0 A possible serial-port device name.
USB serial interface /dev/ttyUSB0 A possible USB-to-serial device name.
Storage interface /dev/sda A possible disk device name.
NVMe storage /dev/nvme0n1 A possible NVMe namespace device name.
These are examples, not a guaranteed list. A particular computer or virtual machine may not contain every entry.

4. Device Nodes Inside /dev

A device node is a special filesystem entry that represents a character or block device interface.

Each device node contains metadata that identifies its type and device number.

Character device node

Character device nodes are commonly used for stream-oriented interfaces.

ls -l /dev/null

Typical output:

crw-rw-rw- 1 root root 1, 3 Nov 12 06:00 /dev/null

The first character c identifies a character special file.

Block device node

Block device nodes represent block-oriented storage interfaces.

ls -l /dev/sda

If that device exists, its output begins with b, identifying a block special file.

A virtual machine may expose its virtual disk using a name such as /dev/sda or another name. Do not assume a particular disk name.

5. Major and Minor Numbers in /dev

Device nodes contain a device number consisting of a major number and a minor number.

  • Major number: Identifies the registered device-number range associated with a driver or subsystem.
  • Minor number: Distinguishes device instances or interfaces within that range.

For example, a typical /dev/null entry displays major number 1 and minor number 3.

ls -l /dev/null

The relevant portion of the output is:

1, 3

These numbers are stored as a device number and can be examined in kernel code using:

MAJOR(dev)
MINOR(dev)

The corresponding kernel type is dev_t.

6. How Is /dev Managed?

Modern Linux systems commonly use a combination of devtmpfs and udev to manage device nodes.

6.1 devtmpfs

devtmpfs is a kernel-provided filesystem designed to provide device nodes for registered devices.

When supported and mounted, it provides a dynamic device-node environment under /dev.

6.2 udev

udev is a user-space device manager. It receives device events from the kernel and can apply rules to manage device nodes.

Common udev responsibilities include:

  • Setting device-node permissions.
  • Setting device-node ownership and group.
  • Creating useful symbolic links.
  • Applying naming rules.
  • Processing device-add and device-remove events.

7. Understanding /dev and /sys

Both /dev and /sys expose information related to devices, but they serve different purposes.

Feature /dev /sys
Filesystem purpose Provides device nodes for accessing device interfaces. Exposes kernel device-model and subsystem information.
Typical contents Character and block device nodes. Device, bus, class and driver information.
Common access open(), read(), write(), ioctl(). Reading and writing supported sysfs attributes.
Management devtmpfs, udev and device-node mechanisms. Kernel device model and sysfs.

Example commands:

ls /dev
ls /sys
ls /sys/class
ls /sys/bus

For example, /sys/class organizes devices by device class, while /dev contains device nodes used for access where applicable.

8. Inspecting /dev in Ubuntu

Step 1: List device entries

ls /dev

Step 2: Display detailed information

ls -l /dev

Step 3: Inspect a character device

ls -l /dev/null
stat /dev/null

Step 4: Inspect terminal devices

ls -l /dev/tty
ls -l /dev/pts

/dev/pts commonly contains pseudo-terminal device nodes used by terminal emulators and remote sessions.

Step 5: Inspect storage devices

ls -l /dev/sd*
ls -l /dev/nvme*

If no matching device exists, the shell may report that the pattern did not match. This is not necessarily an error with the Linux installation.

Step 6: Check whether devtmpfs is mounted

findmnt /dev

This displays mount information for /dev. On systems using devtmpfs, the output commonly identifies devtmpfs as its filesystem.

9. Device Files in a Virtual Machine

When Ubuntu runs inside VirtualBox, Linux still provides a /dev directory with device nodes.

These may represent:

  • Virtual disks presented to the guest operating system.
  • Virtual terminal interfaces.
  • Virtual serial ports, if configured.
  • Virtual console and pseudo-terminal devices.
  • Kernel-provided interfaces such as /dev/null and /dev/zero.

However, the presence of /dev does not mean that the guest has direct access to every physical device attached to the host computer.

Hardware limitation: Physical GPIO, I2C and SPI peripherals generally require suitable hardware access, USB passthrough, a supported interface or device emulation. A normal VirtualBox Ubuntu installation does not automatically expose the host computer's physical GPIO/I2C/SPI controllers to Linux.

10. Common Mistakes When Working with /dev

  1. Assuming every entry is a regular file: Many entries are special device nodes, symbolic links or directories.
  2. Assuming /dev contains driver code: Driver code resides in kernel code or loadable modules, not in device nodes.
  3. Assuming mknod registers a driver: It creates a node but does not register the corresponding driver.
  4. Assuming every device is physical: Linux also provides virtual and software-based device interfaces.
  5. Assuming device names never change: Device names and numbering can vary between systems and configurations.
  6. Changing device permissions carelessly: Incorrect permissions can expose sensitive device interfaces or prevent legitimate access.

12. Summary

  • /dev is the standard directory for Linux device nodes.
  • Device nodes provide filesystem-based access to device interfaces.
  • Character and block device nodes are identified by their file types.
  • Major and minor numbers identify the registered device-number range and device instance.
  • devtmpfs and udev commonly participate in device-node management.
  • /sys exposes kernel device-model information, while /dev provides device access nodes.
  • Virtual machines provide virtual device interfaces but do not automatically expose all physical host peripherals.
