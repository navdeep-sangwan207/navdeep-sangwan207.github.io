Chapter: Device Files and Device Interfaces

Lesson: 5 – Major and Minor Number Mapping

Prerequisites: Device Nodes, Creating Device Nodes Using mknod, Character Device Registration.

Objective: Understand how Linux identifies device nodes using major and minor numbers and how drivers reserve and manage device-number ranges.

1. Introduction

Linux uses major and minor device numbers to identify special device files. These numbers allow the kernel to associate a device node with the appropriate registered device interface.

When a user-space application accesses a device file, the Virtual File System (VFS) uses the device identifier stored in that node to route the operation to the appropriate device driver.

For example, a character device node may contain:

crw-rw---- 1 root dialout 188, 0 Nov 12 10:30 /dev/example0

In this example:

  • 188: Major number.
  • 0: Minor number.
  • c: Indicates a character device.
Major and minor numbers are part of the device identifier. They are not ordinary file contents and are not the same as a device's physical address.

2. What Is a Major Number?

A major number identifies a registered device-number range associated with a device driver or device interface.

When a driver registers a range of device numbers, the kernel assigns or reserves a major number and a range of minor numbers.

For example, suppose a driver receives this illustrative allocation:

Major number: 240
Minor number range: 0 to 3

The driver can use this range to identify up to four device instances or interfaces, depending on its design.

A major number does not necessarily identify one physical hardware model. It identifies a registered device-number range, and the driver defines how that range is used.

3. What Is a Minor Number?

A minor number distinguishes individual device instances or interfaces within an allocated device-number range.

For example, one driver may manage four logical devices:

Device Node Major Minor Illustrative Meaning
/dev/example0 240 0 First device instance
/dev/example1 240 1 Second device instance
/dev/example2 240 2 Third device instance
/dev/example3 240 3 Fourth device instance

All four nodes use the same major number, but their minor numbers are different.

The meaning of a minor number is driver-specific. A driver may use it to select a device instance, channel, port, or another logical interface.

The major and minor fields together form a device identifier represented in kernel code by the dev_t type.

The kernel uses this identifier to connect a device node to the registered device interface. The driver can then interpret the minor number to determine which logical device or instance is being accessed.

5. The dev_t Data Type

Linux kernel code uses the dev_t type to represent a device number.

It stores the combined device identifier, including the major and minor components.

Kernel code should use the standard macros to extract or construct these values rather than manually packing bits.

Important Device Number Macros

Macro Purpose
MAJOR(dev) Extracts the major number from a device identifier.
MINOR(dev) Extracts the minor number from a device identifier.
MKDEV(major, minor) Constructs a device identifier from major and minor values.

Kernel code commonly includes:

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/kdev_t.h>

Example: Constructing a Device Number

dev_t dev;

dev = MKDEV(240, 2);

pr_info("Major: %u\n", MAJOR(dev));
pr_info("Minor: %u\n", MINOR(dev));

This is an illustrative macro example. It constructs an identifier with major 240 and minor 2. It does not reserve that device number or register a driver.

MKDEV() constructs an identifier. It does not allocate a major number, register a character device, or create a device node.

6. Mapping Device Numbers to Multiple Devices

A driver may manage multiple device instances by reserving a range of consecutive minor numbers.

Suppose a driver needs four device instances. It can reserve four numbers starting from minor number zero.

Major: M
↓
Minor 0 → Device 0
Minor 1 → Device 1
Minor 2 → Device 2
Minor 3 → Device 3

For each instance, the driver can construct its device identifier using:

dev_t device_number;

device_number = MKDEV(MAJOR(dev), MINOR(dev) + i);

Here, i represents the instance index, provided it stays within the reserved range.

The driver must also maintain its own data structures to associate each minor number with the corresponding device state.

7. Allocating Device Number Ranges

Before registering a character device, a driver normally reserves a device-number range. Linux provides two commonly used functions.

7.1 alloc_chrdev_region()

alloc_chrdev_region() dynamically allocates a device-number range.

It is generally preferred for new drivers because the kernel chooses an available major number.

int alloc_chrdev_region(
    dev_t *dev,
    unsigned baseminor,
    unsigned count,
    const char *name
);
Parameter Description
dev Address where the allocated device identifier is stored.
baseminor First minor number in the requested range.
count Number of consecutive device numbers to reserve.
name Name associated with the registered device-number range.

Return value:

  • 0 – Successful allocation.
  • Negative error code – Allocation failed.

Example: Dynamic Allocation

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/kdev_t.h>

static dev_t dev;
static int ret;

static int __init example_init(void)
{
    ret = alloc_chrdev_region(&dev, 0, 4, "example_device");

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    pr_info("Major number: %u\n", MAJOR(dev));
    pr_info("First minor number: %u\n", MINOR(dev));

    return 0;
}

static void __exit example_exit(void)
{
    unregister_chrdev_region(dev, 4);
    pr_info("Device number range released\n");
}

module_init(example_init);
module_exit(example_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Dynamic device number allocation example");

This example reserves four device numbers and releases them when the module is removed. It does not yet register a struct cdev or create any device nodes.

7.2 register_chrdev_region()

register_chrdev_region() reserves a device-number range using a major and starting minor number already selected by the driver developer.

int register_chrdev_region(
    dev_t from,
    unsigned count,
    const char *name
);

Example:

dev_t dev;

dev = MKDEV(240, 0);

int ret = register_chrdev_region(
    dev,
    4,
    "example_device"
);

if (ret < 0) {
    pr_err("Static device number registration failed\n");
    return ret;
}

This is an illustrative static allocation request. It succeeds only if the requested range is available. A driver should not assume that an arbitrary major number is free.

8. Dynamic vs Static Device Number Allocation

Feature Dynamic Allocation Static Allocation
Function alloc_chrdev_region() register_chrdev_region()
Major number Chosen by the kernel Selected by the driver developer
Availability Kernel finds an available range Requested range must be available
Typical use Most new driver development Cases requiring a known device number
For most new Linux character drivers, dynamic allocation with alloc_chrdev_region() is the recommended approach.

9. Releasing Device Number Ranges

When a driver no longer needs its reserved device-number range, it must release it.

Linux provides:

unregister_chrdev_region(dev_t from, unsigned count);

Example:

unregister_chrdev_region(dev, 4);

The starting identifier and count must match the range that was reserved.

Device-number allocation and character-device registration are separate operations. Releasing a device-number range does not replace the required cleanup of a registered cdev.

10. Device Number Allocation vs cdev Registration

Reserving device numbers does not automatically register a character device's file operations.

A typical character driver performs these operations in sequence:

1. Allocate Device Numbers
↓
2. Initialize struct cdev
↓
3. Register cdev Using cdev_add()
↓
4. Create Device Interface / Node
↓
5. User-Space Application Access
Operation Purpose
alloc_chrdev_region() Reserves device numbers dynamically.
cdev_init() Initializes a cdev and associates file operations.
cdev_add() Makes the character-device registration available.
device_create() Creates a device-model object; devtmpfs or udev normally provides the corresponding device node.
unregister_chrdev_region() Releases the reserved device-number range.

All required driver state and file operations should be initialized before calling cdev_add(), because the device can become accessible immediately after registration.

11. Viewing Major Numbers in Linux

Linux provides several ways to inspect device numbers.

11.1 View Registered Character and Block Device Majors

cat /proc/devices

This file lists registered major numbers and associated names for character and block devices.

It does not list every minor number or every device node.

11.2 Inspect a Device Node

ls -l /dev/null
ls -l /dev/tty
ls -l /dev/zero

For a device node, the output displays its major and minor numbers.

11.3 Inspect Device Metadata

stat /dev/null

The stat command displays metadata, including the device identifier for a special file.

12. Reading Device Numbers from User Space

A user-space C program can inspect a device node using stat().

The st_rdev field stores the device identifier for a character or block special file. The st_dev field instead identifies the filesystem device containing the file.

On Linux, the major and minor extraction macros are available through <sys/sysmacros.h>.

Example C Program

#include <stdio.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>

int main(void)
{
    struct stat info;

    if (stat("/dev/null", &info) == -1) {
        perror("stat");
        return 1;
    }

    printf("Major number: %u\n",
           major(info.st_rdev));

    printf("Minor number: %u\n",
           minor(info.st_rdev));

    return 0;
}

Compile and Run

gcc device_info.c -o device_info
./device_info

The program displays the major and minor numbers of /dev/null on the system where it is executed. The actual values depend on that system.

13. Important Precautions

  • Do not assume a particular major number is available.
  • Prefer dynamic allocation for new drivers.
  • Use MAJOR(), MINOR(), and MKDEV() instead of manually encoding device numbers.
  • Reserve enough minor numbers for all intended device instances.
  • Keep the device-number range and cdev registration conceptually separate.
  • Release the reserved range during cleanup.
  • Do not assume that creating a device node registers a driver.
  • Do not open arbitrary device nodes simply because their major and minor numbers appear valid.
A manually created device node with an arbitrary major/minor pair does not become a working device. The corresponding device interface must be registered and implemented by a driver.

14. Lesson Summary

  • Major and minor numbers identify Linux device nodes.
  • The major number identifies a registered device-number range.
  • The minor number distinguishes instances or interfaces within that range.
  • dev_t represents a combined device identifier.
  • MAJOR() extracts the major number.
  • MINOR() extracts the minor number.
  • MKDEV() constructs a device identifier.
  • alloc_chrdev_region() dynamically allocates a range.
  • register_chrdev_region() reserves a specified range.
  • unregister_chrdev_region() releases the range.
  • Device-number allocation is separate from cdev registration and device-node creation.
