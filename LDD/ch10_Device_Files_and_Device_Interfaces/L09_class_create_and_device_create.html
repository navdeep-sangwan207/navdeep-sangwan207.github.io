Lesson: 9 – class_create() and device_create()

Prerequisites: Character Device Registration, cdev_init(), cdev_add(), Device Nodes, devtmpfs and udev.

Objective: Understand how a character driver creates a device class and device-model object to support automatic device-node management.

1. Introduction

Linux character drivers commonly use two important functions to integrate their devices with the Linux device model:

  • class_create()
  • device_create()

These functions help organize devices into classes and create device-model objects associated with device numbers.

On systems using devtmpfs and udev, registering the device-model object normally causes a corresponding device node to become available under /dev.

These functions do not replace alloc_chrdev_region(), cdev_init(), or cdev_add(). They serve a different purpose in device-model integration and device-node management.

2. What Is a Device Class?

A device class is a logical grouping of devices that provide similar functionality or belong to a common device category.

Examples of device categories include:

  • Input devices.
  • Graphics devices.
  • Sound devices.
  • USB devices.
  • Various system and character-device interfaces.

Classes help organize devices independently of the physical bus or hardware connection through which they are discovered.

Example

A driver may create a class named:

example_class

Devices registered under this class can be represented in the device model under the corresponding class hierarchy in sysfs.

3. What Is class_create()?

class_create() creates a device class and returns a pointer to the resulting struct class object.

The driver can use this class when creating one or more device-model objects with device_create().

Linux Kernel 6.4 and Newer

struct class *class_create(const char *name);

Example:

static struct class *my_class;

my_class = class_create("my_class");

if (IS_ERR(my_class)) {
    return PTR_ERR(my_class);
}

Older Kernel Versions

Older kernel versions use the two-argument form:

struct class *class_create(
    struct module *owner,
    const char *name
);

Example for an older kernel:

my_class = class_create(THIS_MODULE, "my_class");

if (IS_ERR(my_class)) {
    return PTR_ERR(my_class);
}
The API changed in Linux kernel 6.4. Always check the kernel headers used for compilation. Do not mix the old and new signatures.

4. Return Value of class_create()

The function returns a pointer to a struct class object on success.

If an error occurs, it returns an error-encoded pointer.

Therefore, use:

if (IS_ERR(my_class)) {
    return PTR_ERR(my_class);
}
Function or Macro Purpose
IS_ERR() Checks whether a pointer represents an encoded error.
PTR_ERR() Extracts the negative error code from an error pointer.

Do not use IS_ERR() to check an integer return value. It is intended for error-encoded pointers.

5. What Is device_create()?

device_create() creates a device-model object associated with a specified class and device number.

Common declaration:

struct device *device_create(
    struct class *class,
    struct device *parent,
    dev_t devt,
    void *drvdata,
    const char *fmt,
    ...
);

Parameters

Parameter Description
class The device class under which the device is created.
parent Parent device, or NULL if no parent is specified.
devt The device number associated with the device.
drvdata Optional driver-specific data associated with the device object.
fmt Format string used to construct the device name.
... Optional arguments used by the format string.

6. Example of device_create()

Consider a character driver that has already allocated a device number and registered its cdev.

static struct device *my_device;

my_device = device_create(
    my_class,
    NULL,
    dev,
    NULL,
    "mydevice"
);

if (IS_ERR(my_device)) {
    return PTR_ERR(my_device);
}

Explanation:

  1. my_class identifies the device class.
  2. NULL means no parent device is specified.
  3. dev supplies the registered device number.
  4. The second NULL means no driver-specific data is supplied.
  5. "mydevice" is the device name.

On a system with the usual devtmpfs and udev configuration, a device node will normally be provided as:

/dev/mydevice
The device node is provided by the system's device-node management mechanism. device_create() creates a device-model object; it does not itself implement the driver's read/write operations.

7. Relationship Between cdev, class_create() and device_create()

These functions perform different tasks during character-device registration.

alloc_chrdev_region()
↓
cdev_init()
↓
cdev_add()
↓
class_create()
↓
device_create()
↓
devtmpfs / udev Device Node Management
↓
/dev/mydevice
Function Main Responsibility
alloc_chrdev_region() Allocates device numbers.
cdev_init() Initializes the cdev and associates file operations.
cdev_add() Registers the character device with the kernel.
class_create() Creates a logical device class.
device_create() Creates a device-model object associated with the class and device number.

All required driver state and file operations should be initialized before the cdev becomes available through cdev_add().

8. Complete Character Driver Registration Example

The following example demonstrates the complete registration and cleanup sequence using a single character device.

It does not implement read or write callbacks. Its purpose is to demonstrate device registration and automatic device-node management.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>

#define DEVICE_NAME "mydevice"

static dev_t dev;
static struct cdev my_cdev;
static struct class *my_class;
static struct device *my_device;

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
};

static int __init my_driver_init(void)
{
    int ret;

    /* Allocate one device number */
    ret = alloc_chrdev_region(&dev, 0, 1, DEVICE_NAME);
    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    /* Initialize cdev */
    cdev_init(&my_cdev, &my_fops);
    my_cdev.owner = THIS_MODULE;

    /* Register cdev */
    ret = cdev_add(&my_cdev, dev, 1);
    if (ret < 0) {
        pr_err("cdev_add failed\n");
        goto err_unregister;
    }

    /* Create device class: Linux 6.4+ */
    my_class = class_create("my_class");
    if (IS_ERR(my_class)) {
        ret = PTR_ERR(my_class);
        pr_err("class_create failed\n");
        goto err_cdev;
    }

    /* Create device-model object */
    my_device = device_create(
        my_class,
        NULL,
        dev,
        NULL,
        DEVICE_NAME
    );

    if (IS_ERR(my_device)) {
        ret = PTR_ERR(my_device);
        pr_err("device_create failed\n");
        goto err_class;
    }

    pr_info("Device registered successfully\n");
    pr_info("Major: %d Minor: %d\n",
            MAJOR(dev), MINOR(dev));

    return 0;

err_class:
    class_destroy(my_class);

err_cdev:
    cdev_del(&my_cdev);

err_unregister:
    unregister_chrdev_region(dev, 1);
    return ret;
}

static void __exit my_driver_exit(void)
{
    device_destroy(my_class, dev);
    class_destroy(my_class);
    cdev_del(&my_cdev);
    unregister_chrdev_region(dev, 1);

    pr_info("Device unregistered successfully\n");
}

module_init(my_driver_init);
module_exit(my_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Character Driver Using class_create and device_create");

Important Explanation

  • dev stores the allocated device number.
  • my_cdev represents the character-device registration.
  • my_class represents the device class.
  • my_device represents the device-model object.
  • MAJOR(dev) and MINOR(dev) extract the device-number components.
  • Error handling releases previously allocated resources in reverse order.
Kernel APIs can change between releases. This example uses the Linux 6.4+ one-argument class_create() API. Compile against matching kernel headers.

9. Cleanup Functions

When a module is unloaded, resources created during initialization must be released.

Creation or Registration Cleanup
device_create() device_destroy()
class_create() class_destroy()
cdev_add() cdev_del()
alloc_chrdev_region() unregister_chrdev_region()

Correct Cleanup Order

device_destroy(my_class, dev);
class_destroy(my_class);
cdev_del(&my_cdev);
unregister_chrdev_region(dev, 1);

Cleanup should reverse the order of successful resource creation so that dependent objects are removed before the resources they rely on.

cdev_del() prevents new opens through that cdev registration, but it does not automatically terminate existing open file descriptions. A real driver must manage active users and device-resource lifetime correctly.

10. Building the Driver in Ubuntu

Save the source code as:

my_driver.c

Makefile

obj-m += my_driver.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Use a real tab character before each recipe command in the Makefile.

Compile

make

Load the Module

sudo insmod my_driver.ko

Check the Device Node

ls -l /dev/mydevice

Inspect Device Numbers

cat /proc/devices

View Kernel Messages

dmesg | tail -n 20

Unload the Module

sudo rmmod my_driver

After successful cleanup, the device-model object is removed and the automatically managed node should normally disappear.

11. Common Errors

Error Possible Cause Solution
class_create compilation error Incorrect function signature for the kernel version. Check whether the kernel requires one or two arguments.
Invalid class pointer Class creation failed. Check with IS_ERR() and extract the error using PTR_ERR().
Device node missing Device creation failed or device-node management is unavailable. Check return values, devtmpfs, udev, and kernel logs.
Module unload fails Module is in use or cleanup/lifetime constraints prevent unloading. Check active users and kernel messages.
Device number conflict Static device number is already reserved. Prefer dynamic allocation with alloc_chrdev_region().

12. Important Differences

Function Creates Does Not Create
class_create() A device class. A cdev registration or individual device node.
device_create() A device-model object. A cdev registration or file-operation implementation.
cdev_add() A registered character-device interface. A device class or a /dev node.
mknod A filesystem device node. A kernel driver or device-model object.

13. Lesson Summary

  • class_create() creates a device class.
  • device_create() creates a device-model object.
  • The device-model object is associated with a device number.
  • devtmpfs and udev commonly provide the corresponding device node.
  • cdev_add() separately registers the character-device interface.
  • Both class and device creation functions require error checking.
  • Cleanup uses device_destroy(), class_destroy(), cdev_del(), and unregister_chrdev_region().
  • The class_create() API differs between older kernels and Linux 6.4+.
