Chapter Overview

Linux exposes many hardware devices and driver interfaces through special files. These device files are commonly available in the /dev directory and provide user-space applications with a standard way to communicate with device drivers.

This chapter explains device nodes, major and minor numbers, device file permissions, the mknod command, and automatic device management using udev. It also introduces the kernel APIs class_create() and device_create() for exposing character devices through the device model.

Important Linux Concepts and APIs

  • /dev: Directory containing device nodes.
  • Device node: Special filesystem entry used to access a device through its driver.
  • Major number: Identifies the device driver associated with a device node.
  • Minor number: Identifies a particular device or instance managed by that driver.
  • mknod: Command used to create a device node manually.
  • udev: User-space device manager that handles device events and device-node management.
  • class_create(): Creates a device class in the Linux device model. Its API signature varies across kernel versions.
  • device_create(): Creates and registers a device associated with a device class.
  • device_destroy(): Removes a device created through the device model.
  • class_destroy(): Removes a device class created by the driver.

Device Node Creation Workflow

  • Register a device-number range in the kernel.
  • Initialize and register the character device.
  • Create a device class when appropriate.
  • Create a device object using device_create().
  • The device-management system makes the device node available in /dev.
  • Set appropriate device permissions and ownership.
  • Test the device through a user-space application.
  • Remove the device object, class and device-number range during cleanup.

Practical Applications

  • Inspect device nodes using ls -l /dev.
  • Identify device major and minor numbers.
  • Explore device information using lsblk and stat.
  • Create a test device node using mknod in a controlled environment.
  • Inspect device events and rules managed by udev.
  • Implement a character driver that creates its own device node.
  • Test device access using shell commands and a user-space C program.
  • Verify device cleanup after unloading the driver.
