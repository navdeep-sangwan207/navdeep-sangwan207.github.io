Chapter: 10 – Device Files and Device Interfaces

Lesson: 1 – Introduction to Device Files

Level: Beginner to Intermediate

Prerequisites: Character devices, major and minor numbers, character device registration, file_operations and read/write callbacks.

Learning Goal: Understand how user-space applications access kernel-managed device interfaces through device files.

1. Introduction to Device Files

Linux provides a unified way for user-space applications to communicate with devices. Many device interfaces are exposed through special filesystem entries called device files.

Device files are commonly found inside the /dev directory. Applications can use familiar file-related system calls such as open(), read(), write() and ioctl() to communicate with the corresponding device interface.

For example, a terminal application interacts with terminal device interfaces, while a storage utility may access a block device through its device file.

User Application
↓ open(), read(), write(), ioctl()
Device File in /dev
↓
Virtual Filesystem (VFS)
↓
Kernel Device Driver
↓
Device or Software Interface

This is a conceptual representation of the access path. The exact kernel path depends on the device subsystem and driver implementation.

2. What Is a Device File?

A device file is a special filesystem entry that represents a device interface and allows user-space programs to access it through the Linux filesystem interface.

A device file is not normally the physical hardware itself. It is also not the driver binary. Instead, it contains metadata, including a device type and device number, that allows the kernel to identify the relevant device interface.

Important characteristics

  • Device files are commonly located in /dev.
  • They provide a familiar file-oriented interface to device operations.
  • They are associated with major and minor device numbers.
  • They can represent physical devices or virtual/software devices.
  • The kernel driver or subsystem implements the actual device operations.
Remember: Creating a device file does not automatically create a driver or make hardware functional. The corresponding driver or kernel subsystem must also be available and properly registered.

3. Types of Device Files

Linux traditionally provides two major categories of device special files:

3.1 Character Device Files

Character device files provide access to devices that commonly exchange data as a stream of bytes or through device-specific operations.

Examples include:

  • Serial terminal interfaces.
  • Virtual terminal devices.
  • Some sensor and peripheral interfaces.
  • Character-based interfaces implemented by custom drivers.

Character device drivers commonly use a struct cdev object and a struct file_operations structure to register operations.

3.2 Block Device Files

Block device files represent devices that support block-oriented storage operations. They are commonly associated with disks and other storage devices.

Examples include:

  • Hard disk partitions.
  • SSD devices.
  • Virtual block devices.
  • Some removable storage devices.

Block devices are managed through the Linux block layer, which provides request processing and storage I/O infrastructure.

Feature Character Device Block Device
Data model Often stream-oriented Block-oriented storage
Typical use Terminals, serial interfaces, custom device interfaces Disks, SSDs and storage devices
Kernel subsystem Character device infrastructure Block I/O subsystem
File type shown by ls -l c b

4. Major and Minor Device Numbers

Linux uses a device number to identify a device interface associated with a device special file. This number contains two logical components:

  • Major number: Identifies the driver or device-number range associated with a device interface.
  • Minor number: Identifies a particular device or instance handled within that major-number range.
Device Number
↓
Major Number
Minor Number

Major: identifies the registered device-number range

Minor: distinguishes device instances within that range

In kernel programming, the device number is represented by the type dev_t.

Linux provides macros to extract the two components:

#include <linux/types.h>
#include <linux/kdev_t.h>

dev_t dev;

unsigned int major_number = MAJOR(dev);
unsigned int minor_number = MINOR(dev);

The MAJOR() macro extracts the major number, while MINOR() extracts the minor number.

Device numbers can be allocated dynamically using alloc_chrdev_region() or registered using register_chrdev_region() when a suitable range is already selected.

The major number is not necessarily a unique identifier for one physical hardware model. It identifies a registered device-number range. A driver can manage multiple device instances using different minor numbers.

5. How Linux Identifies a Device File

When a process opens a device file, the Virtual Filesystem (VFS) participates in resolving the file operation. For a device special file, its type and device number help the kernel route operations through the relevant device infrastructure.

  1. The application calls open() with a device-file path.
  2. The VFS resolves the filesystem entry.
  3. The kernel identifies the special file and its device number.
  4. The appropriate device subsystem and registered driver operations are used.
  5. Subsequent operations such as read() and write() are handled by the relevant interface.
Application: open("/dev/example")
↓
VFS resolves device special file
↓
Device type and device number
↓
Registered device interface
↓
Driver operation

For a character driver, the registered character-device infrastructure associates the device number with the character device and its file operations. The VFS and character-device core handle the routing details.

6. Relationship Between Device Files and Driver Registration

Device-number registration, character-device registration and creation of a visible device node are related but separate operations.

Operation Purpose Typical API or mechanism
Allocate device numbers Reserve a major/minor number range alloc_chrdev_region()
Initialize character device Associate a cdev with file operations cdev_init()
Register character device Make the character device available to the kernel cdev_add()
Create device-model object Publish device information in the device model device_create()
Create device node Provide a filesystem entry under /dev devtmpfs, udev or mknod
Important distinction: cdev_add() registers a character device with the kernel. It does not create a /dev filesystem node. Likewise, device_create() creates a device-model object; devtmpfs and/or udev normally provide the corresponding device node on modern Linux systems.

7. Examples of Device Files in Linux

Linux systems commonly contain device files such as:

Device File Purpose
/dev/null Discards data written to it and returns end-of-file when read.
/dev/zero Provides a stream of zero-valued bytes when read.
/dev/random Provides access to the kernel random-number interface.
/dev/tty Represents the controlling terminal of the current process, when available.
/dev/sda A possible name for a SCSI/SATA-style disk device.
/dev/nvme0n1 A possible name for an NVMe storage device.

Device names depend on the hardware, kernel configuration and device-management environment. For example, an NVMe disk may appear as /dev/nvme0n1 rather than /dev/sda.

8. Inspecting Device Files Using Linux Commands

8.1 List Device Files

ls /dev

Displays entries available inside the /dev directory.

8.2 Display Device File Details

ls -l /dev/null
ls -l /dev/zero
ls -l /dev/tty

Example output format:

crw-rw-rw- 1 root root 1, 3 Nov 12 06:00 /dev/null

Important fields:

  • c indicates a character special file.
  • rw-rw-rw- represents permission bits.
  • root root indicates owner and group.
  • 1 is the major number.
  • 3 is the minor number.

The example values shown are typical for /dev/null, but permissions and ownership can vary by system.

8.3 Display Device File Information

stat /dev/null
file /dev/null

stat displays filesystem metadata, including device type and device numbers. The file command identifies the file type.

8.4 View Registered Character and Block Devices

cat /proc/devices

This displays registered character and block device major numbers and associated names. It does not list every device node present under /dev.

8.5 Inspect Device Information in Sysfs

ls /sys/dev/char
ls /sys/dev/block

These directories expose device-model information through sysfs for character and block devices, respectively, when corresponding entries exist.

9. Device Files and User-Space System Calls

User applications generally interact with device interfaces using standard system calls.

System Call Purpose
open() Opens a device file and obtains a file descriptor.
read() Requests data from the device interface.
write() Sends data to the device interface.
ioctl() Performs device-specific control operations.
close() Releases the application's file descriptor.

Example user-space program that opens a standard device file:

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;

    fd = open("/dev/null", O_WRONLY);

    if (fd < 0)
    {
        perror("open");
        return 1;
    }

    write(fd, "Linux Device Driver", 19);

    close(fd);

    printf("Data written to /dev/null\n");

    return 0;
}

Compile and execute:

gcc device_test.c -o device_test
./device_test

Expected output:

Data written to /dev/null

The message is printed by the application. The data written to /dev/null is discarded rather than stored.

10. How Device Nodes Are Created

There are several ways to make device nodes available under /dev.

Manual Creation Using mknod

The mknod command creates a special filesystem node using a specified device type and major/minor numbers.

sudo mknod /dev/mydevice c 240 0

This requests creation of a character device node with major number 240 and minor number 0.

The numbers above are illustrative only. They must match a device-number range actually registered by the intended driver. Creating a node with arbitrary numbers does not register a driver or guarantee that the device can be opened successfully.

Dynamic Device Management

Modern Linux systems commonly use devtmpfs and udev for device-node management.

  • devtmpfs: A kernel-provided filesystem that can provide device nodes for registered devices.
  • udev: A user-space device manager that processes device events and can apply rules to manage device-node names, permissions, ownership and symbolic links.

The exact arrangement depends on the Linux distribution and system configuration.

Later lessons explain the /dev directory, device nodes, mknod, udev and automatic device-node creation in detail.

11. Important Concepts to Remember

  • A device file is a special filesystem entry, not the physical device itself.
  • Device files are commonly found under /dev.
  • Character and block devices are two major device-file categories.
  • Major and minor numbers identify a device-number range and an instance within it.
  • dev_t represents a device number in kernel code.
  • cdev_add() registers a character device but does not create its device node.
  • device_create() creates a device-model object; devtmpfs/udev normally handles the visible node.
  • mknod can manually create a device node when the correct device number is known.
  • Applications use standard system calls to interact with device interfaces.
