Chapter: 10 – Device Files and Device Interfaces

Lesson: 4 – Creating Device Nodes Using mknod

Level: Beginner to Intermediate

Prerequisites: Device nodes, /dev directory, character and block devices, major and minor numbers.

Learning Goal: Learn to create, inspect and remove device nodes using the Linux mknod command.

1. Introduction to mknod

Linux provides the mknod command to create special filesystem nodes, including character and block device nodes.

A device node represents a device interface using a device type and a major/minor device number.

In character-device driver development, mknod is often used during testing when a driver has registered its device number and a corresponding device node has not been created automatically.

↓ device number

↓

↓

Important: The mknod command creates a filesystem node. It does not load a kernel module, register a driver, allocate device numbers or implement device operations.

2. Syntax of the mknod Command

The general syntax is:

mknod [OPTIONS] NAME TYPE [MAJOR MINOR]
ArgumentDescription
NAMEPath and name of the node to create.
TYPEc for character device or b for block device.
MAJORMajor device number.
MINORMinor device number.
OPTIONSOptional command-line settings supported by the installed implementation.

Root privileges are normally required to create device nodes in protected locations such as /dev.

3. Creating a Character Device Node

Use the letter c to specify a character device node.

Example

sudo mknod /dev/mychar c 240 0

This command requests creation of:

  • Path: /dev/mychar
  • Type: Character device
  • Major number: 240
  • Minor number: 0

Verify the node:

ls -l /dev/mychar
stat /dev/mychar
file /dev/mychar

The long listing should begin with c, indicating a character special file. The device number should show the selected major and minor values.

The major number 240 is illustrative. Never select arbitrary device numbers for an actual driver. Use the range allocated and registered by the driver.

4. Creating a Block Device Node

Use the letter b to specify a block device node.

Example syntax

sudo mknod /dev/myblock b 240 0

This requests a block device node with major number 240 and minor number 0.

Verify the node:

ls -l /dev/myblock
stat /dev/myblock

The first character of the long listing should be b.

This command only creates the node. A suitable block-device registration and implementation must exist for the node to provide a working device interface.

5. Understanding Major and Minor Numbers

The major and minor numbers are essential for identifying a device interface.

Major number

The major number identifies a registered device-number range associated with a driver or subsystem.

Minor number

The minor number identifies a particular device instance or interface within that range.

For example:

sudo mknod /dev/mychar c 240 0
sudo mknod /dev/mychar1 c 240 1

Both nodes use major number 240 but have different minor numbers.

NodeTypeMajorMinor
/dev/mycharCharacter2400
/dev/mychar1Character2401

Whether these nodes correspond to usable device instances depends on the registered driver and its implementation.

6. How to Obtain the Correct Device Number

When developing a character driver, the driver may dynamically allocate a device-number range using alloc_chrdev_region().

Example kernel code:

static dev_t dev;

ret = alloc_chrdev_region(&dev, 0, 1, "mydevice");

if (ret < 0)
{
    pr_err("Device number allocation failed\n");
    return ret;
}

pr_info("Major = %d, Minor = %d\n",
        MAJOR(dev), MINOR(dev));

The driver can display the allocated numbers in the kernel log.

Inspect recent messages using:

sudo dmesg | tail -n 30

Use the actual major and minor values reported by the running driver when creating a manual device node.

A dynamically allocated major number may change between module loads. Do not assume a previously observed value remains valid.

8. Practical Example in Ubuntu

This section demonstrates creating a harmless illustrative device node. It does not create or register a working driver.

Step 1: Create a test directory

mkdir -p ~/device_node_lab
cd ~/device_node_lab

Step 2: Create a character device node

sudo mknod ./testchar c 240 0

Step 3: Inspect the node

ls -l ./testchar
stat ./testchar
file ./testchar

Step 4: Check its device number

Look for the major and minor numbers in the ls -l output.

Step 5: Remove the test node

sudo rm ./testchar
Do not open or write to this arbitrary test node. It may not have a corresponding registered device driver. The exercise is limited to learning how the node is created and inspecting its metadata.

9. Setting Permissions and Ownership

After creating a device node, its permissions and ownership may need to be configured for the intended application.

Change permissions

sudo chmod 660 /dev/mychar

This grants read and write permissions to the owner and group, and no permissions to others.

Change ownership

sudo chown root:dialout /dev/mychar

This example assigns ownership to root and the group dialout. The correct group depends on the device and distribution.

Inspect the result:

ls -l /dev/mychar
Manual permission changes may not survive device-node removal and recreation. udev rules are commonly used for persistent device permissions and ownership.

10. Removing a Device Node

A manually created device node can be removed using the rm command.

sudo rm /dev/mychar

Removing a device node does not unload the driver or unregister its device-number range.

Driver cleanup is a separate operation performed by the kernel module's cleanup function or the relevant subsystem's removal procedure.

OperationEffect
rm /dev/mycharRemoves the filesystem node.
cdev_del()Removes the character-device registration.
unregister_chrdev_region()Releases a previously registered device-number range.
rmmod module_nameRequests removal of a loadable kernel module.

These operations are not interchangeable. Driver resources and active users must be handled safely during cleanup.

12. mknod vs Automatic Device-Node Creation

Linux can provide device nodes through manual creation or automatic device-management mechanisms.

Featuremknoddevtmpfs and udev
MethodManual commandKernel and user-space device management
Node creationAdministrator creates the nodeNormally created as devices are registered and events are processed
PermissionsCan be set or changed manuallyCan be managed through udev rules
Device namingChosen in the commandCan be managed by device events and rules
Typical useTesting and specialized manual setupNormal modern Linux device management

For many modern systems, automatic device-node management is preferred. Manual mknod remains useful for learning, controlled testing and specialized environments.

13. Safety Considerations

  • Do not create device nodes over existing system entries.
  • Do not guess major and minor numbers for real hardware interfaces.
  • Do not change permissions of sensitive device nodes without understanding the security impact.
  • Do not assume a node is functional just because it exists.
  • Do not remove system device nodes as part of routine practice.
  • Use a dedicated test directory for introductory exercises.

15. Summary

  • mknod creates special filesystem nodes.
  • c specifies a character device node.
  • b specifies a block device node.
  • Major and minor numbers identify the device-number range and instance.
  • The correct device numbers must come from the actual driver or subsystem.
  • Creating a node does not register or load a driver.
  • chmod and chown can change permissions and ownership.
  • rm removes the node but does not unregister the driver.
  • devtmpfs and udev commonly automate device-node management.
