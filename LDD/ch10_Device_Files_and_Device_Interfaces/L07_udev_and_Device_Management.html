Lesson: 7 – udev and Device Management

Prerequisites: Device Nodes, Major and Minor Number Mapping, Device File Permissions.

Objective: Understand how udev receives device events, evaluates rules, and manages device nodes and related device information in user space.

1. Introduction to udev

udev is the Linux user-space device manager. It receives device events from the kernel and processes rules to manage device-node properties and related device information.

When a device is detected, the kernel makes device information available through the device model and sends an event to user space. The udev system can process this event and apply matching rules.

Depending on the device and system configuration, udev can:

  • Set device-node ownership.
  • Set device-node permissions.
  • Create symbolic links.
  • Set device-related properties.
  • Trigger configured helper programs.
  • Maintain consistent device names using device properties.
udev operates in user space. It does not replace the kernel driver and does not implement the hardware communication itself.

2. Why Is udev Required?

Linux systems may detect devices dynamically. Examples include USB storage devices, serial adapters, input devices, and other hot-plug hardware.

Without a device-management system, administrators would need to manage device-node details manually or rely on other mechanisms.

udev helps automate this work by reacting to kernel device events.

Example: USB Device Connection

When a USB serial adapter is connected:

  1. The USB subsystem detects the device.
  2. The relevant kernel driver binds to the device if a suitable driver is available.
  3. The kernel registers the device with the device model and exposes device information through sysfs.
  4. The kernel sends a device event to user space.
  5. udev evaluates applicable rules.
  6. Device-node properties and symbolic links are configured according to those rules and system policy.

The resulting device interface may appear under a path such as /dev/ttyUSB0, depending on the driver and device.

Device Node and Symbolic Link Management

The kernel is responsible for detecting and representing devices through its subsystems and device model. udev processes the resulting events in user space.

On many modern systems, devtmpfs provides the initial device nodes while udev applies additional configuration such as permissions, ownership, and symbolic links.

4. What Is a uevent?

A uevent is a notification generated by the kernel when a device-related event occurs.

Common device actions include:

Action Meaning
add A device is added or registered.
remove A device is removed or unregistered.
change Device-related properties or state change.
bind A driver is bound to a device.
unbind A driver is unbound from a device.

udev receives relevant events and evaluates rules based on the information supplied by the kernel.

A uevent is a notification, not the device driver itself. The event informs user space about a device-related change.

5. udev Rules

udev rules are configuration statements used to match device properties and apply actions.

Rules are commonly stored in files ending with .rules.

Common Rule Directories

/etc/udev/rules.d/
/usr/lib/udev/rules.d/

Some distributions also use other vendor-specific rule directories.

Directory Purpose
/etc/udev/rules.d/ Local administrator rules.
/usr/lib/udev/rules.d/ Rules supplied by installed software and system packages on many distributions.

Local rules are generally placed in /etc/udev/rules.d/ so they can be managed independently of vendor-supplied files.

6. Structure of a udev Rule

A udev rule contains matching conditions and assignments.

Example:

SUBSYSTEM=="tty", KERNEL=="ttyUSB0", \
    GROUP="dialout", MODE="0660"

Explanation:

Rule Component Meaning
SUBSYSTEM=="tty" Matches a device in the tty subsystem.
KERNEL=="ttyUSB0" Matches a device whose kernel device name is ttyUSB0.
GROUP="dialout" Assigns the device node to the dialout group.
MODE="0660" Requests owner and group read/write permissions.

Matching and Assignment Operators

Operator Purpose
== Tests whether a value matches a specified condition.
!= Tests whether a value does not match.
= Assigns a value.
+= Adds a value to a list-type assignment.
:= Assigns a final value and prevents later rule changes to that key where supported.

Rule syntax and supported keys depend on the installed udev version. Always validate rules against the actual device properties.

7. Important udev Rule Keys

Key Description
KERNEL Matches the kernel device name.
SUBSYSTEM Matches the device subsystem.
DRIVER Matches the driver associated with the device.
ATTR Matches or assigns a sysfs attribute of the current device.
ATTRS Matches a sysfs attribute in the device's parent hierarchy.
ENV Matches or assigns an event environment property.
NAME Historically associated with device-node naming; modern systems generally use devtmpfs for node creation and udev rules for links and properties.
SYMLINK Adds a symbolic link for a device node.
OWNER Sets the device-node owner.
GROUP Sets the device-node group.
MODE Sets device-node permission bits.

8. Understanding Device Properties

udev uses device information exposed by the kernel and its device model.

For example, a USB device may expose properties such as:

  • Subsystem name.
  • Kernel device name.
  • Vendor ID.
  • Product ID.
  • Serial number, if available.
  • Driver name.
  • Device path in the sysfs hierarchy.

These properties allow rules to identify a device more reliably than relying only on a changing device-node number.

Inspect Device Information

udevadm info --query=all --name=/dev/null

This command displays available udev information for the specified device node.

Inspect the Device Path

udevadm info --query=path --name=/dev/null

The result identifies the corresponding device path within the sysfs hierarchy.

9. Creating a Symbolic Link Using udev

Device names such as /dev/ttyUSB0 can change depending on device discovery order.

A udev rule can create a more descriptive symbolic link using a stable property, such as a device serial number.

Illustrative Rule

SUBSYSTEM=="tty", KERNEL=="ttyUSB*", \
    ATTRS{idVendor}=="1234", \
    ATTRS{idProduct}=="5678", \
    SYMLINK+="my_serial_device"

If the conditions match a real device, udev requests a symbolic link such as:

/dev/my_serial_device

The vendor and product identifiers above are placeholders. Replace them with actual values obtained from the target device.

If several connected devices share the same vendor and product identifiers, additional matching properties, such as a serial number or physical device path, may be required to distinguish them.

10. Important udevadm Commands

The udevadm command is used to inspect and control aspects of the udev system.

Command Purpose
udevadm info Displays device information and properties.
udevadm monitor Monitors kernel and udev events.
udevadm control --reload-rules Reloads rule files into the udev daemon.
udevadm trigger Requests device events for selected existing devices.
udevadm settle Waits for the current udev event queue to become empty.
udevadm test Tests rule processing for a specified sysfs device path.

Monitor Device Events

sudo udevadm monitor

Keep the command running, then connect or disconnect a supported device. The terminal displays relevant event activity.

Press Ctrl + C to stop monitoring.

Reload Rules

sudo udevadm control --reload-rules

Reloading makes updated rule files available to the daemon. It does not necessarily reprocess every already-present device.

Trigger Device Events

sudo udevadm trigger

This requests events for existing devices. It can cause device rules and configured actions to run again.

Use udevadm trigger carefully on production systems. Prefer a targeted trigger for a specific device when testing a new rule.

11. udev and devtmpfs

udev and devtmpfs work together, but they have different responsibilities.

Feature devtmpfs udev
Type Kernel-managed virtual filesystem. User-space device manager.
Device nodes Provides device nodes for registered devices on systems using devtmpfs. Applies rules and manages device-related configuration.
Permissions Provides initial device-node metadata. Can adjust ownership and permissions using rules.
Symbolic links Not its primary device-management role. Can create useful device symbolic links.
Execution location Kernel. User space.

The exact division of work depends on the Linux distribution and system configuration.

12. udev and sysfs

sysfs exposes the Linux device model and related kernel objects to user space through the /sys directory.

udev uses device information exposed through sysfs to evaluate matching rules and manage device-related configuration.

Example commands:

ls /sys/class/
ls /sys/bus/
ls /sys/devices/

Inspect a device node's sysfs path:

udevadm info --query=path --name=/dev/null

The sysfs hierarchy is useful for identifying device relationships, attributes, buses, classes, and driver associations.

13. Practical Exercise in Ubuntu VirtualBox

This exercise uses existing virtual and software device interfaces. It does not require a physical USB serial adapter.

Step 1: Check udev Service Status

systemctl status systemd-udevd

On Ubuntu systems using systemd, this displays the udev daemon service status.

Step 2: Inspect a Device

udevadm info --query=all --name=/dev/null

Step 3: Monitor Device Events

sudo udevadm monitor

Leave the monitor running and perform a device-related action available in your virtual machine. If no new hardware event occurs, the command may simply wait.

Step 4: Inspect Rule Directories

ls -l /etc/udev/rules.d/
ls -l /usr/lib/udev/rules.d/

Step 5: Inspect Device Subsystems

ls /sys/class/
ls /sys/bus/

Step 6: Check the Event Queue

sudo udevadm settle

This waits for pending udev events to be processed.

VirtualBox does not automatically expose every physical device to Ubuntu. USB passthrough or suitable hardware emulation may be needed for hardware-specific udev exercises.

14. Common Problems and Troubleshooting

Problem Possible Cause Diagnostic Approach
Device node is missing Driver did not register the device or device-node management did not complete. Inspect kernel logs, sysfs, and device registration.
udev rule does not match Incorrect subsystem, kernel name, or attribute. Inspect properties using udevadm info.
Permissions are incorrect Rule does not match or another configuration affects the node. Inspect the rule and run a targeted rule test.
Symbolic link is missing Rule conditions are incorrect or device event was not processed. Check rule syntax and device properties.
Device name changes Discovery order or device enumeration changes. Use stable identifying properties for a symbolic link.

Useful Diagnostic Commands

journalctl -u systemd-udevd
dmesg
udevadm info --query=all --name=/dev/null
systemctl status systemd-udevd

journalctl -u systemd-udevd displays service logs retained by the system journal. dmesg displays the kernel ring buffer, which is a separate source of kernel messages.

15. Best Practices

  • Use stable device properties when writing matching rules.
  • Keep custom rules in the administrator rule directory.
  • Use restrictive permissions and appropriate groups.
  • Test rule conditions against actual device properties.
  • Use symbolic links when stable device names are required.
  • Avoid unnecessary external helper programs in rules.
  • Reload rules after modifying rule files.
  • Use targeted event triggering during troubleshooting.
  • Do not confuse udev device management with kernel driver implementation.

16. Lesson Summary

  • udev is a user-space device manager.
  • The kernel generates device-related events called uevents.
  • udev receives events and evaluates matching rules.
  • Rules can configure ownership, permissions, and symbolic links.
  • udev uses device information exposed through the Linux device model and sysfs.
  • devtmpfs and udev commonly work together to manage device nodes.
  • udevadm info inspects device properties.
  • udevadm monitor monitors device events.
  • udevadm control --reload-rules reloads rule files.
  • udev does not replace the kernel device driver.
