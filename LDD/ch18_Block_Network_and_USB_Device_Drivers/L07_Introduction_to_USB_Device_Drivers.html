1. Introduction

USB stands for Universal Serial Bus. It is a widely used communication standard that allows computers and embedded systems to communicate with external devices.

USB provides a standardized interface for connecting peripherals such as keyboards, mice, storage devices, printers, cameras and communication adapters.

Linux supports USB devices through its USB subsystem. The subsystem provides common interfaces for USB host controllers, USB devices, interfaces and device drivers.

Examples of USB devices include:

  • USB flash drives.
  • USB keyboards and mice.
  • USB-to-serial adapters.
  • USB webcams.
  • USB Wi-Fi adapters.
  • USB printers.
  • USB audio devices.
  • USB network adapters.

2. What Is a USB Device Driver?

A USB device driver is software that enables the Linux kernel to communicate with a particular USB device or USB device interface.

It uses the Linux USB subsystem to identify devices, communicate with endpoints and transfer data.

Its responsibilities may include:

  • Identifying supported USB devices.
  • Binding to the appropriate USB interface.
  • Initializing device-specific functionality.
  • Communicating with USB endpoints.
  • Submitting USB transfer requests.
  • Processing completed transfers.
  • Handling device disconnection.
  • Releasing allocated resources.
Example: When a USB-to-serial adapter is connected, Linux identifies the device and loads a suitable driver. The driver provides a serial interface that applications can access through a device file such as /dev/ttyUSB0.

3. USB Architecture

USB communication follows a host-controlled architecture. The host system manages communication with connected USB devices.

+--------------------------------------+ | User Applications | +--------------------------------------+ | v +--------------------------------------+ | Linux Kernel Drivers | +--------------------------------------+ | v +--------------------------------------+ | Linux USB Core | +--------------------------------------+ | v +--------------------------------------+ | USB Host Controller Driver | +--------------------------------------+ | v +--------------------------------------+ | USB Bus | +--------------------------------------+ | v +--------------------------------------+ | USB Device | +--------------------------------------+

Main Components

  1. USB device: The connected peripheral.
  2. USB host: The computer or embedded system controlling USB communication.
  3. USB core: Common Linux USB subsystem.
  4. Host controller driver: Controls the USB host controller hardware.
  5. USB device driver: Implements device-specific communication.

4. USB Host and USB Device

USB Host

The USB host controls communication on the USB bus. A desktop computer, laptop or embedded Linux board can act as a USB host.

The host is responsible for:

  • Detecting connected devices.
  • Performing device enumeration.
  • Assigning USB addresses.
  • Managing USB transfers.
  • Controlling bus communication.

USB Device

A USB device is a peripheral connected to the host. It responds to communication initiated by the host.

Examples include:

  • Keyboard.
  • Mouse.
  • Flash drive.
  • Webcam.
  • USB serial adapter.
A USB peripheral normally does not independently initiate a conventional USB bus transaction. The host schedules communication with the device.

5. USB Host Controller

The USB host controller is the hardware component that manages USB bus communication.

Linux uses a host controller driver, also called an HCD, to communicate with this hardware.

Common Host Controller Standards

Controller Description
UHCI Universal Host Controller Interface, historically used for USB 1.x.
OHCI Open Host Controller Interface, used for USB 1.x.
EHCI Enhanced Host Controller Interface, associated with USB 2.0 high-speed operation.
xHCI Extensible Host Controller Interface, commonly used for USB 3.x and also supporting USB 2.0 and USB 1.x devices.

The host controller driver handles hardware-specific scheduling, transfer processing and controller management.

6. Linux USB Subsystem

Linux provides a USB subsystem that separates common USB operations from device-specific driver implementation.

The major components include:

  • USB core.
  • USB host controller drivers.
  • USB device drivers.
  • USB device and interface structures.
  • USB transfer management.
+-------------------------------------+ | Application Layer | +-------------------------------------+ | v +-------------------------------------+ | Device-Specific Driver | +-------------------------------------+ | v +-------------------------------------+ | USB Core | +-------------------------------------+ | v +-------------------------------------+ | Host Controller Driver | +-------------------------------------+ | v +-------------------------------------+ | USB Controller | +-------------------------------------+ | v +-------------------------------------+ | USB Bus | +-------------------------------------+

The USB core provides shared functionality such as device enumeration, interface management and transfer handling.

7. USB Device Enumeration

Enumeration is the process through which a USB host detects and configures a newly connected USB device.

Enumeration Steps

  1. A USB device is connected to the host.
  2. The host detects the connection.
  3. The host communicates with the device using endpoint zero.
  4. The host reads device descriptors.
  5. The host assigns a USB address.
  6. The host reads configuration information.
  7. The host selects an appropriate configuration.
  8. The USB subsystem identifies matching interfaces.
  9. An appropriate device driver binds to the interface.
USB Device Connected | v Connection Detection | v Device Descriptor Read | v USB Address Assignment | v Configuration Descriptors | v Configuration Selection | v Interface Matching | v Driver Binding | v Device Ready
Enumeration is managed by the USB core and host controller infrastructure. A normal USB device driver does not manually perform the entire enumeration process.

8. USB Device Descriptors

USB descriptors contain information describing a USB device and its supported functionality.

Important Descriptor Types

Descriptor Purpose
Device Descriptor Describes the overall USB device.
Configuration Descriptor Describes a device configuration.
Interface Descriptor Describes a functional interface.
Endpoint Descriptor Describes an endpoint and its properties.
String Descriptor Provides human-readable device information.

Device Descriptor Information

  • Vendor ID (VID).
  • Product ID (PID).
  • USB device version.
  • Device class information.
  • Manufacturer string index.
  • Product string index.
  • Serial number string index.

Vendor ID and Product ID are important for identifying devices and matching drivers.

9. USB Vendor ID and Product ID

Each USB device can provide a Vendor ID and Product ID through its device descriptor.

  • VID: Identifies the vendor.
  • PID: Identifies a particular product or product family assigned by the vendor.

Linux commands can display these identifiers:

lsusb

Example output:

Bus 001 Device 004: ID 1234:5678 Example USB Device

In this illustrative output:

  • 1234 is the Vendor ID.
  • 5678 is the Product ID.
The example identifiers are illustrative. Real VID and PID values depend on the connected device.

10. USB Device and Interface

A USB device can contain one or more configurations. A configuration can contain one or more interfaces. An interface represents a particular functional part of the device.

For example, a USB composite device may provide:

  • Keyboard functionality.
  • Mouse functionality.
  • Audio functionality.

Each function can be represented by a separate interface or group of interfaces.

+----------------------------------+ | USB Device | +----------------------------------+ | v +----------------------------------+ | Configuration | +----------------------------------+ | | v v +----------------+ +----------------+ | Interface 0 | | Interface 1 | | | | | | Keyboard | | Audio | | Function | | Function | +----------------+ +----------------+

In Linux, USB drivers commonly bind to USB interfaces rather than taking control of an entire composite device.

11. USB Endpoints

An endpoint is a communication endpoint provided by a USB device.

Endpoints are used to transfer data between the host and device.

Endpoint Directions

  • IN: Data travels from the device to the host.
  • OUT: Data travels from the host to the device.

Endpoint zero is the default control endpoint used for device setup and control communication.

Endpoint Information

  • Endpoint address.
  • Transfer type.
  • Direction.
  • Maximum packet size.
  • Polling interval where applicable.
Endpoint direction is defined from the USB host's perspective. An IN endpoint sends data toward the host; an OUT endpoint receives data from the host.

12. USB Transfer Types

USB defines four main transfer types. Each type is designed for different communication requirements.

Transfer Type Purpose Example
Control Device configuration and control. Reading descriptors.
Bulk Reliable data transfer without guaranteed latency. USB storage.
Interrupt Periodic or bounded-latency transfer service. Keyboard and mouse.
Isochronous Time-sensitive streaming with reserved bus bandwidth. USB audio and video.

12.1 Control Transfer

Control transfers are used for device management, configuration and commands.

12.2 Bulk Transfer

Bulk transfers are used for large amounts of data where reliable delivery is important but a fixed latency is not guaranteed.

12.3 Interrupt Transfer

Interrupt transfers support periodic or bounded-latency communication for devices that need timely service.

12.4 Isochronous Transfer

Isochronous transfers are used for time-sensitive data streams. They reserve bus bandwidth but do not provide the same retry-based delivery guarantee as bulk transfers.

13. USB Request Block (URB)

Linux USB drivers use USB Request Blocks, commonly called URBs, to submit USB transfer requests.

An URB describes a transfer that the USB subsystem must perform through the host controller.

URB information includes:

  • Target USB device.
  • Target endpoint pipe.
  • Transfer buffer.
  • Transfer length.
  • Transfer type.
  • Completion callback.
  • Transfer status and actual length.

Important URB Functions

usb_alloc_urb()
usb_free_urb()
usb_submit_urb()
usb_kill_urb()
usb_unlink_urb()

The driver prepares and submits URBs. The USB subsystem and host controller process the transfers and report completion.

URBs are central to asynchronous USB communication. A driver must manage URB lifetime, transfer buffers, completion callbacks and disconnect cleanup correctly.

14. Linux USB Driver Framework

Linux provides a standard USB driver framework. A USB driver registers with the USB core and specifies which USB interfaces it supports.

A USB driver commonly uses:

  • struct usb_driver
  • struct usb_device_id
  • probe() callback.
  • disconnect() callback.

The USB core compares device and interface information against the driver's ID table.

When a matching interface is found, the driver's probe callback is invoked.

15. USB Device Driver vs USB Host Controller Driver

USB Device Driver USB Host Controller Driver
Controls a particular USB device or interface. Controls USB host controller hardware.
Uses USB core APIs. Implements host-controller operations.
Handles device-specific functionality. Manages controller-level transfers and scheduling.
Example: USB serial driver. Example: xHCI host controller driver.

16. USB Device Driver Lifecycle

The USB driver lifecycle begins when the USB core identifies a matching device interface.

Lifecycle Stages

  1. USB device is connected.
  2. USB enumeration is performed.
  3. Descriptors are read.
  4. The USB core identifies matching interfaces.
  5. The driver's probe callback is invoked.
  6. The driver initializes the interface.
  7. The driver communicates with the device.
  8. The device is disconnected.
  9. The disconnect callback is invoked.
  10. The driver releases its resources.
USB Device Connected | v USB Enumeration | v ID Table Matching | v Driver Probe | v Device Initialization | v USB Communication | v Device Disconnected | v Driver Disconnect | v Resource Cleanup

18. USB Inspection Commands in Ubuntu

1. List Connected USB Devices

lsusb

2. Display Detailed USB Information

lsusb -v

3. Display USB Device Tree

lsusb -t

4. View USB Kernel Messages

dmesg | grep -i usb

5. Display USB Device Information

ls -l /sys/bus/usb/devices/

6. List USB Driver Modules

lsmod | grep -i usb

These commands help identify USB devices, interfaces, host controllers and drivers available in the system.

19. USB in Embedded Linux

USB is widely used in embedded Linux systems for connecting external peripherals and communication devices.

Examples include:

  • USB host ports for external storage.
  • USB serial interfaces for debugging.
  • USB Ethernet adapters.
  • USB cameras.
  • USB communication with industrial equipment.

Embedded systems may operate as USB hosts, USB devices (gadgets), or dual-role systems, depending on their controller and hardware configuration.

A Linux USB host driver and a Linux USB gadget driver serve different roles. Host drivers manage attached peripherals; gadget drivers implement USB device-side functionality.

21. Important Points to Remember

  • The Linux USB core manages common USB operations.
  • HCD means Host Controller Driver.

  • VID identifies the vendor and PID identifies a product.
  • A USB device can contain multiple configurations and interfaces.

  • struct usb_driver represents a registered USB driver.

  • disconnect() handles device removal.

23. Lesson Summary

USB is a standardized communication interface used to connect external peripherals to computers and embedded systems.

Linux manages USB devices through its USB subsystem. Important concepts include USB enumeration, descriptors, interfaces, endpoints, transfer types and URBs.

The USB driver framework provides mechanisms for matching, initializing, communicating with and removing USB devices.

Understanding these concepts provides the foundation for studying USB device architecture and implementing USB drivers in Linux.
