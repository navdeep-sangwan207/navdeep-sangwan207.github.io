Chapter Overview

Linux supports several categories of device drivers for different hardware interfaces. Block drivers manage storage devices, network drivers manage network interfaces, and USB drivers communicate with devices connected through the Universal Serial Bus.

This chapter introduces the architecture and fundamental concepts of block, network and USB device drivers. It explains how these driver frameworks differ from character device drivers and how Linux manages their communication with hardware.

Important Kernel Structures and Concepts

  • Block layer: Kernel subsystem responsible for managing block-oriented storage I/O.
  • struct bio: Represents block I/O operations and associated data segments.
  • struct request: Represents a block I/O request.
  • blk-mq: Modern multi-queue block I/O infrastructure.
  • struct gendisk: Represents a disk in the Linux block layer.
  • struct block_device_operations: Defines supported block-device operations.
  • struct net_device: Represents a Linux network interface.
  • net_device_ops: Defines network device operations.
  • register_netdev(): Registers a network device with the networking subsystem.
  • struct usb_driver: Defines a USB device driver.
  • struct usb_device_id: Describes USB device identifiers used for matching.
  • usb_register(): Registers a USB driver.
  • probe(): Called when a matching USB device is connected to the driver.
  • disconnect(): Called when the USB device is disconnected.
  • URB: USB Request Block used to describe USB data transfers.

Device Driver Subsystem Comparison

  • Character drivers: Handle byte-oriented data and device-specific operations.
  • Block drivers: Handle block-oriented storage operations.
  • Network drivers: Handle packet transmission and reception.
  • USB drivers: Handle communication with USB devices through the USB subsystem.

Practical Applications

  • Explore storage devices using lsblk.
  • Inspect block devices under /sys/block/.
  • Study block I/O request processing.
  • Inspect network interfaces using ip link.
  • Explore network device information using ethtool.
  • Inspect network driver information using lspci -k where applicable.
  • List connected USB devices using lsusb.
  • Inspect USB device information using lsusb -v.
  • Study USB driver binding under /sys/bus/usb/drivers/.
  • Understand USB probe and disconnect callbacks through a sample driver.
