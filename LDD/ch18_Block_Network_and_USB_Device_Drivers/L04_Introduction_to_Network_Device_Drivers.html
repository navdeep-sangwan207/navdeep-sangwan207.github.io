1. Introduction

A network device driver is a Linux kernel driver that enables the operating system to communicate with network hardware. It connects the Linux networking subsystem to devices such as Ethernet controllers and Wi-Fi adapters.

Network devices transmit and receive data in the form of packets. The driver manages communication between the kernel and the network controller.

Network device drivers are essential for:

  • Internet connectivity.
  • Communication between computers.
  • Local area networks (LANs).
  • Wireless networking.
  • Embedded networking applications.
  • Industrial communication systems.
Example: When Ubuntu sends data to a website, the networking subsystem prepares packets. The Ethernet or Wi-Fi driver passes the packets to the network controller, which transmits them through the network interface.

2. What Is a Network Device?

A network device is a hardware or virtual interface used to send and receive network data.

It provides connectivity between a computer and other network devices.

Examples

  • Ethernet Network Interface Cards (NICs).
  • Wi-Fi adapters.
  • USB Ethernet adapters.
  • PCIe network cards.
  • Virtual network interfaces.
  • Loopback interface.

Linux represents network interfaces using names such as: 

eth0
enp3s0
wlan0
wlp2s0
lo

The actual naming scheme depends on the system and its network configuration.

3. What Is a Network Device Driver?

A network device driver is software that controls a network interface and connects it to the Linux networking subsystem.

Its main responsibilities include:

  • Initializing network hardware.
  • Configuring the network controller.
  • Transmitting network packets.
  • Receiving incoming packets.
  • Managing transmit and receive queues.
  • Handling hardware interrupts.
  • Managing DMA operations.
  • Reporting link status and errors.
  • Managing device initialization and removal.

4. Network Device Driver Architecture

Linux provides a networking subsystem that separates network protocol processing from hardware-specific operations.

+-----------------------------------+ | User Applications | +-----------------------------------+ | v +-----------------------------------+ | Socket API / System Calls | +-----------------------------------+ | v +-----------------------------------+ | Linux Network Stack | | TCP / UDP / IP | +-----------------------------------+ | v +-----------------------------------+ | Network Device Layer | | net_device | +-----------------------------------+ | v +-----------------------------------+ | Network Device Driver | +-----------------------------------+ | v +-----------------------------------+ | Network Controller | +-----------------------------------+ | v +-----------------------------------+ | Ethernet / Wi-Fi Medium | +-----------------------------------+

Architecture Components

  1. User application: Uses network sockets to communicate with other systems.
  2. Socket interface: Provides user-space networking operations.
  3. Network stack: Handles protocols such as TCP, UDP and IP.
  4. Network device layer: Provides common interfaces for network drivers.
  5. Network driver: Controls the hardware and manages packet transfers.
  6. Network controller: Performs hardware-level transmission and reception.

5. Types of Network Devices

5.1 Ethernet Devices

Ethernet devices provide wired network connectivity using Ethernet technology.

Examples include:

  • PCIe Ethernet cards.
  • Integrated motherboard Ethernet controllers.
  • USB-to-Ethernet adapters.
  • Embedded Ethernet controllers.

5.2 Wireless Network Devices

Wireless network devices provide communication through radio-frequency signals, commonly using Wi-Fi technology.

Examples include:

  • PCIe Wi-Fi adapters.
  • USB Wi-Fi adapters.
  • Integrated laptop wireless controllers.

5.3 Virtual Network Devices

Virtual network interfaces are software-created interfaces used for internal communication, virtualization and network configuration.

Examples include:

  • Loopback interface (lo).
  • Virtual Ethernet pairs (veth).
  • Bridge interfaces.
  • Tunnel interfaces.

A network interface is generally not accessed as an ordinary character or block device node. It is registered with the Linux networking subsystem and managed through network interfaces and networking APIs.

7. Network Packets

Network communication is performed using packets or frames. A packet contains control information and payload data.

For example, an Ethernet frame contains:

  • Destination MAC address.
  • Source MAC address.
  • EtherType or length information.
  • Payload.
  • Frame check sequence at the physical link layer.

At higher networking layers, packet headers contain additional information such as IP addresses, transport protocols and port numbers.

+------------------------------+ | Destination MAC Address | +------------------------------+ | Source MAC Address | +------------------------------+ | EtherType / Length | +------------------------------+ | Payload | +------------------------------+ | Frame Check Sequence | +------------------------------+

The exact frame format depends on the network technology. The network driver works with the hardware-specific frame transmission and reception mechanisms.

8. Transmission and Reception

A network driver must support both outgoing and incoming packet processing.

Transmit Operation

  1. An application sends data using a socket.
  2. The networking stack processes the data.
  3. The packet reaches the network device layer.
  4. The driver receives the packet for transmission.
  5. The driver prepares the hardware descriptor.
  6. The controller transmits the packet.
  7. The driver processes transmission completion.

Receive Operation

  1. The network controller receives a frame.
  2. The controller stores packet data in memory using an appropriate DMA mechanism where supported.
  3. The driver detects the received packet.
  4. The driver processes the receive descriptor.
  5. The packet is passed to the networking subsystem.
  6. The networking stack processes the packet.
  7. The data reaches the appropriate application.

9. The net_device Structure

The Linux kernel uses struct net_device to represent a network interface.

It contains information and state associated with the network device.

Important concepts include:

  • Interface name.
  • Hardware address.
  • Maximum transmission unit (MTU).
  • Network interface state.
  • Transmit queue information.
  • Driver-specific private data.
  • Network operation callbacks.

The network driver allocates and configures a net_device instance and registers it with the kernel networking subsystem.

The exact fields and helper functions available for struct net_device can change between kernel versions. Drivers should use the interfaces supported by their target kernel.

10. Network Device Operations

Network drivers provide callback functions through the network-device operations interface.

The operations structure is commonly known as struct net_device_ops.

Important Operations

Operation Purpose
ndo_open Starts or opens the network interface.
ndo_stop Stops or closes the network interface.
ndo_start_xmit Handles outgoing packet transmission.
ndo_set_mac_address Handles MAC address configuration when supported.
ndo_get_stats64 Provides network statistics.

These callbacks allow the networking subsystem to request hardware-specific operations from the driver.

11. sk_buff Structure

The Linux networking subsystem uses struct sk_buff, commonly called an skb, to represent network packet data and associated metadata.

An skb is used throughout many parts of the networking stack and is an important structure for network driver development.

It provides information such as:

  • Packet data.
  • Packet length.
  • Network protocol information.
  • Header offsets.
  • Checksum-related metadata.
  • Packet-processing information.

The driver uses networking APIs to prepare, transmit and submit received packet buffers.

12. Network Interface Registration

A network driver must register its interface with the Linux networking subsystem before it can be managed as a network interface.

A simplified registration process includes:

  1. Detect and initialize the network hardware.
  2. Allocate a net_device structure.
  3. Initialize the device's required properties.
  4. Set the appropriate network operation callbacks.
  5. Configure hardware resources and queues.
  6. Register the interface with the networking subsystem.
  7. Make the interface available for network configuration.

Common kernel helpers include: 

alloc_etherdev()
register_netdev()
unregister_netdev()
free_netdev()
These are examples of commonly used networking APIs. A real driver must follow the correct initialization, error handling and cleanup sequence for its device and kernel version.

13. DMA in Network Drivers

Network controllers commonly use DMA to transfer packet data between system memory and the hardware.

Transmit DMA

The driver prepares packet data and maps the appropriate memory for device access. The controller reads the packet data and transmits it.

Receive DMA

The driver provides receive buffers to the controller. The controller places incoming packet data into memory and reports completion.

+-----------------------+ | CPU | +-----------------------+ | | Configure Descriptors v +-----------------------+ | Network Controller | +-----------------------+ | | DMA Transfer v +-----------------------+ | System RAM | +-----------------------+

Linux DMA mapping APIs are used to make memory accessible to the device. Drivers must correctly manage DMA mappings, buffer ownership and synchronization.

14. Interrupt Handling in Network Drivers

Network controllers use interrupts to notify the driver about events such as packet reception, transmission completion and hardware errors.

Common interrupt events include:

  • Receive packet available.
  • Transmit operation completed.
  • Receive buffer condition.
  • Link status change.
  • Controller error.

The interrupt handler should perform only the work suitable for interrupt context. More extensive packet processing can be deferred.

15. NAPI - New API

NAPI is a Linux networking mechanism that combines interrupt notification with polling-based packet processing.

It is designed to improve network performance when a large number of packets arrive in a short period.

Basic NAPI Operation

  1. A network interrupt indicates that packets are available.
  2. The driver schedules NAPI processing.
  3. Further receive interrupts may be temporarily suppressed for that processing context.
  4. The kernel invokes the driver's polling callback.
  5. The driver processes packets up to the specified budget.
  6. If more packets remain, polling continues.
  7. When processing is complete, NAPI is completed and interrupt processing is re-enabled as appropriate.
Packet Arrives | v Hardware Interrupt | v Schedule NAPI | v NAPI Poll Function | v Process Received Packets | v More Packets? / \ Yes No | | v v Continue Complete NAPI Polling and Re-enable Interrupts

NAPI is especially important for high-speed Ethernet drivers.

16. Network Interface Naming

Linux network interfaces may use different naming schemes. The names depend on the system's configuration and device discovery.

Name Meaning
lo Loopback interface.
eth0 Traditional Ethernet interface name.
enp3s0 Predictable Ethernet interface name.
wlan0 Traditional wireless interface name.
wlp2s0 Predictable wireless interface name.

The name does not necessarily identify the physical driver. It identifies the network interface exposed to the networking subsystem.

17. Important Network Commands

Linux provides several commands for inspecting and configuring network interfaces.

1. List Network Interfaces

ip link show

2. Display IP Addresses

ip addr show

3. Display Interface Statistics

ip -s link show

4. Display Network Routes

ip route show

5. Display Network Controller Information

sudo lshw -class network

6. Display Driver Information

sudo ethtool -i enp3s0

Replace enp3s0 with the interface name on your system.

7. View Network-Related Kernel Messages

dmesg | grep -i -E "ethernet|network|wifi|firmware"

18. Network Drivers in VirtualBox

When Ubuntu runs inside VirtualBox, the guest operating system normally sees a virtual network adapter rather than the host's physical Ethernet or Wi-Fi controller.

The VirtualBox virtual network adapter may use a virtualized device model such as Intel PRO/1000 or another configured model. The guest Linux driver communicates with that virtual adapter.

To inspect the guest interface, use:

ip link show

ip addr show

sudo lshw -class network

dmesg | grep -i -E "network|ethernet|e1000|virtio"
The exact driver depends on the virtual adapter model selected in VirtualBox. The physical Wi-Fi or Ethernet hardware on the Windows host is generally managed by the host operating system, not directly by the Ubuntu guest.

19. Network Driver Development Workflow

A simplified network driver development workflow includes:

  1. Study the network controller datasheet.
  2. Identify hardware resources and communication interfaces.
  3. Initialize the controller.
  4. Allocate the network device structure.
  5. Configure network operation callbacks.
  6. Initialize transmit and receive queues.
  7. Configure DMA descriptors and buffers if required.
  8. Configure interrupts and NAPI if supported.
  9. Register the network interface.
  10. Test packet transmission and reception.
  11. Implement error handling and cleanup.
A production network driver requires hardware-specific implementation. A virtual network interface is useful for studying networking behavior but does not provide direct access to the physical controller's registers.

21. Important Points to Remember

  • Network drivers connect hardware to the Linux networking subsystem.
  • Network devices transfer packets rather than storage blocks.
  • struct net_device represents a network interface.
  • struct sk_buff represents packet data and metadata.
  • struct net_device_ops provides driver callbacks.
  • ndo_start_xmit handles packet transmission.
  • DMA is commonly used for efficient packet transfers.
  • Interrupts notify the driver about hardware events.
  • NAPI supports efficient packet reception.
  • Network interfaces are managed through the networking subsystem.

24. Lesson Summary

A Linux network device driver connects Ethernet, Wi-Fi and other network controllers to the kernel networking subsystem. It manages packet transmission, reception, hardware resources, DMA, interrupts and interface operations.

Important concepts include struct net_device, struct sk_buff, network device operations, DMA and NAPI.

Understanding these concepts provides the foundation for studying network interface architecture and the internal structure of Linux network drivers.
