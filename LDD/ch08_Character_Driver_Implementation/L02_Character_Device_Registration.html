Lesson 2: Character Device Registration
Level: Intermediate
Prerequisites: struct cdev, dev_t, major and minor numbers, file_operations and device-number allocation.
Objective: Understand the complete process of registering a character device with the Linux kernel.

1. Introduction

Character-device registration is the process of making a character driver known to the Linux kernel.

A driver must reserve a device-number range and register a corresponding struct cdev object.

The cdev connects the device-number range with the driver's file_operations.

Once registration succeeds, the kernel can route operations on the associated device numbers to the driver's callbacks, provided a suitable device interface is available.

2. Components Required for Registration

A typical character-device registration involves the following components:

Component Purpose
dev_t Stores the encoded device number.
alloc_chrdev_region() Reserves a device-number range dynamically.
struct cdev Represents the character device in the kernel.
struct file_operations Contains the driver's operation callbacks.
cdev_init() Initializes the cdev and associates file operations.
cdev_add() Registers the cdev with the kernel.
device_create() Creates a device-model object that normally leads to a device node through devtmpfs or udev.

3. Character Device Registration Architecture

The kernel uses the registered character-device mapping to connect operations on the device number to the driver.

4. Step 1: Allocate Device Numbers

Before registering a cdev, the driver must reserve a device-number range.

The recommended approach for most new drivers is dynamic allocation using alloc_chrdev_region(). 

static dev_t dev;

ret = alloc_chrdev_region(
    &dev,
    0,
    1,
    "my_char_device"
);

if (ret < 0) {
    pr_err("Device number allocation failed\n");
    return ret;
}

Parameters

  • &dev: Receives the allocated starting device number.
  • 0: Starting minor number.
  • 1: Number of device numbers to reserve.
  • "my_char_device": Name associated with the reserved range.

Display the allocated major and minor numbers: 

pr_info("Major: %u\n", MAJOR(dev));
pr_info("Minor: %u\n", MINOR(dev));

5. Step 2: Declare the cdev Structure

The driver needs a struct cdev object to represent its character device. 

#include <linux/cdev.h>

static struct cdev my_cdev;

This declares a cdev object with static storage duration.

The object will be initialized before it is registered with the kernel.

6. Step 3: Define file_operations

The file_operations structure defines which operations the driver supports. 

#include <linux/fs.h>

static int my_open(struct inode *inode,
                   struct file *file)
{
    pr_info("Device opened\n");
    return 0;
}

static int my_release(struct inode *inode,
                      struct file *file)
{
    pr_info("Device closed\n");
    return 0;
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .release = my_release,
};

In this example, the driver supports open and release operations.

Read, write and other callbacks can be added when their implementations are ready.

7. Step 4: Initialize the cdev

Use cdev_init() to initialize the cdev and associate it with the file operations. 

cdev_init(&my_cdev, &my_fops);

my_cdev.owner = THIS_MODULE;

The first parameter is the address of the cdev object. The second parameter is the file_operations structure.

cdev_init() initializes the object, but does not register it with the kernel. Registration happens later through cdev_add().

8. Step 5: Register the cdev

The driver calls cdev_add() to register the initialized character device. 

ret = cdev_add(
    &my_cdev,
    dev,
    1
);

if (ret < 0) {
    pr_err("cdev_add failed\n");
    unregister_chrdev_region(dev, 1);
    return ret;
}

Function Parameters

Parameter Explanation
&my_cdev Pointer to the initialized cdev.
dev Starting device number.
1 Number of consecutive device numbers covered.

The function returns zero on success or a negative error code on failure.

cdev_add() makes the character-device registration available to the kernel immediately. Initialize the driver state and callbacks before calling it.

9. Step 6: Create a Device Interface

Registering a cdev does not automatically create a named file such as /dev/mydevice.

A device-model interface can be created using a class and device_create().

A simplified example is: 

static struct class *my_class;
static struct device *my_device;

my_class = class_create("my_class");

my_device = device_create(
    my_class,
    NULL,
    dev,
    NULL,
    "mydevice"
);

This is a conceptual sequence. Production code must check the return values and unwind resources on failure.

Kernel API signatures can differ between versions. In particular, class_create() changed in Linux 6.4. The one-argument form shown above applies to newer kernels; older kernels commonly use class_create(THIS_MODULE, "my_class"). Always check the headers for your target kernel.

When devtmpfs or udev is configured, the device-model event normally leads to creation of the corresponding device node.

10. Complete Character Device Registration Example

This example demonstrates a complete basic registration sequence, including device-number allocation, cdev registration and device-model interface creation.

File: char_register.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>
#include <linux/init.h>

#define DEVICE_NAME "mydevice"
#define CLASS_NAME  "myclass"

static dev_t dev;
static struct cdev my_cdev;
static struct class *my_class;
static struct device *my_device;

static int my_open(struct inode *inode,
                   struct file *file)
{
    pr_info("Device opened\n");
    return 0;
}

static int my_release(struct inode *inode,
                      struct file *file)
{
    pr_info("Device released\n");
    return 0;
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .release = my_release,
};

static int __init char_register_init(void)
{
    int ret;

    /* Allocate device number */
    ret = alloc_chrdev_region(
        &dev,
        0,
        1,
        DEVICE_NAME
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    /* Initialize cdev */
    cdev_init(&my_cdev, &my_fops);
    my_cdev.owner = THIS_MODULE;

    /* Register cdev */
    ret = cdev_add(&my_cdev, dev, 1);

    if (ret < 0) {
        pr_err("cdev registration failed\n");
        goto err_unregister_region;
    }

    /* Create device class */
    my_class = class_create(CLASS_NAME);

    if (IS_ERR(my_class)) {
        ret = PTR_ERR(my_class);
        pr_err("Class creation failed\n");
        goto err_cdev_del;
    }

    /* Create device */
    my_device = device_create(
        my_class,
        NULL,
        dev,
        NULL,
        DEVICE_NAME
    );

    if (IS_ERR(my_device)) {
        ret = PTR_ERR(my_device);
        pr_err("Device creation failed\n");
        goto err_class_destroy;
    }

    pr_info("Character device registered\n");
    pr_info("Major: %u Minor: %u\n",
            MAJOR(dev), MINOR(dev));

    return 0;

err_class_destroy:
    class_destroy(my_class);

err_cdev_del:
    cdev_del(&my_cdev);

err_unregister_region:
    unregister_chrdev_region(dev, 1);

    return ret;
}

static void __exit char_register_exit(void)
{
    device_destroy(my_class, dev);
    class_destroy(my_class);

    cdev_del(&my_cdev);
    unregister_chrdev_region(dev, 1);

    pr_info("Character device unregistered\n");
}

module_init(char_register_init);
module_exit(char_register_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Character Device Registration Example");
This example uses the one-argument class_create() API for Linux 6.4 and newer. For older kernels, replace it with the appropriate older signature. Check your target kernel headers before compiling.

Understanding Error Handling

The goto labels provide reverse-order cleanup.

Failure Point Resources Released
Device-number allocation No resource from this sequence needs releasing.
cdev registration Device-number range.
Class creation cdev and device-number range.
Device creation Class, cdev and device-number range.
Normal module removal Device object, class, cdev and device-number range.

Step 8: Test Opening the Device

Use a small user-space program to open the device. 

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;

    fd = open("/dev/mydevice", O_RDONLY);

    if (fd < 0) {
        perror("open");
        return 1;
    }

    printf("Device opened successfully\n");

    close(fd);

    return 0;
}

Compile the user-space program:

gcc test_device.c -o test_device

Run it:

./test_device

Expected output:

Device opened successfully

Check kernel messages again: 

sudo dmesg | tail -20

Expected driver messages include:

Character device registered
Device opened
Device released

Step 10: Clean Build Files

make clean

13. Important Registration Rules

  • Allocate the device-number range before registering the cdev.
  • Initialize the cdev before calling cdev_add().
  • Associate the correct file_operations structure.
  • Check every registration function's return value.
  • Make driver state ready before cdev_add(), because access may begin immediately after registration.
  • Create the device-model interface separately if a managed device node is required.
  • Use reverse-order cleanup when initialization fails.
  • Remove the device interface before destroying the class.
  • Remove the cdev before releasing its device-number range.
  • Manage active file references and device data lifetime carefully.

14. Summary

  • Character-device registration connects a device-number range to driver operations.
  • alloc_chrdev_region() reserves device numbers.
  • struct cdev represents the character device.
  • cdev_init() initializes the cdev.
  • cdev_add() registers the cdev.
  • class_create() creates a device class.
  • device_create() creates a device-model object.
  • Device-node creation is separate from cdev registration.
  • cdev_del() removes the cdev registration.
  • unregister_chrdev_region() releases the device-number range.
