Lesson 6: Character Device Unregistration
Level: Intermediate
Prerequisites: Device numbers, struct cdev, cdev_init(), cdev_add() and cdev_del().
Objective: Understand the complete process of removing a character-device registration and releasing associated resources safely.

1. Introduction

A Linux character-device driver must manage the complete lifecycle of its device registration.

During initialization, the driver allocates device numbers, initializes a cdev object and registers it with the kernel.

During cleanup, these registrations and allocated resources must be released in an appropriate order.

This process is known as character-device unregistration.

2. What Is Character Device Unregistration?

Character-device unregistration is the process of removing a registered character-device interface from the Linux kernel and releasing the associated device-number reservation.

It generally involves two important operations: 

cdev_del(&my_cdev);

unregister_chrdev_region(dev, count);
Function Purpose
cdev_del() Removes the character-device registration.
unregister_chrdev_region() Releases the reserved device-number range.
These functions are not interchangeable. Removing a cdev registration does not release its device numbers, and releasing device numbers does not remove a cdev registration.

3. Why Is Unregistration Necessary?

When a kernel module is unloaded or a character device is removed, the driver must stop exposing the corresponding interface.

Main Reasons

  • Prevent new opens through the removed cdev registration.
  • Remove the device's registration from the kernel.
  • Release reserved major and minor device numbers.
  • Prevent stale device registrations.
  • Support safe module unloading.
  • Allow device numbers to be reused after release.

5. unregister_chrdev_region() Function

Linux provides unregister_chrdev_region() to release a previously reserved character-device number range.

Header file:

#include <linux/fs.h>

Function prototype:

void unregister_chrdev_region(
    dev_t from,
    unsigned int count
);

Function Parameters

Parameter Description
from Starting device number of the reserved range.
count Number of device numbers to release.

Example

unregister_chrdev_region(dev, 1);

This releases one previously reserved device number beginning at dev.

The starting device number and count must correspond to the range that the driver previously allocated or reserved.

6. Difference Between cdev_del() and unregister_chrdev_region()

Feature cdev_del() unregister_chrdev_region()
Purpose Removes cdev registration. Releases device-number reservation.
Input struct cdev pointer. dev_t and count.
Return type void void
Removes cdev registration Yes No
Releases major/minor range No Yes

Correct Cleanup Sequence

cdev_del(&my_cdev);

unregister_chrdev_region(dev, count);

7. Device Model Cleanup

Some character drivers also create device-model objects using class_create() and device_create().

These objects require their own cleanup operations.

Creation Function Cleanup Function
device_create() device_destroy()
class_create() class_destroy()
cdev_add() cdev_del()
alloc_chrdev_region() unregister_chrdev_region()

Example Cleanup

device_destroy(my_class, dev);

class_destroy(my_class);

cdev_del(&my_cdev);

unregister_chrdev_region(dev, 1);

The exact cleanup order depends on the resources and dependencies created by the driver. The example removes the device-model interface before removing the cdev registration.

device_destroy() removes the device-model object. A /dev node normally created through devtmpfs or udev is removed as part of the corresponding device-node management. It is not a substitute for cdev_del().

8. Existing Open Files and Safe Unregistration

Removing a cdev registration does not automatically close existing file descriptors.

A process that opened a device before unregistration may still hold a reference to the file and may attempt further operations.

Important Considerations

  • Prevent new opens through the removed registration.
  • Manage existing open-file references.
  • Do not free buffers still used by callbacks.
  • Synchronize asynchronous work and hardware operations.
  • Ensure the device state remains valid until its users are finished.
cdev_del() is not a synchronization mechanism for all active driver operations. Production drivers need suitable reference counting, synchronization and lifetime handling before freeing device state.

9. Complete Practical Example

This module demonstrates allocation, registration and unregistration of one character-device number.

File: char_unregister_demo.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/init.h>

#define DEVICE_NAME "char_unregister_demo"

static dev_t dev;
static struct cdev my_cdev;

static int demo_open(struct inode *inode,
                     struct file *file)
{
    pr_info("Device opened\n");
    return 0;
}

static int demo_release(struct inode *inode,
                        struct file *file)
{
    pr_info("Device released\n");
    return 0;
}

static const struct file_operations demo_fops = {
    .owner = THIS_MODULE,
    .open = demo_open,
    .release = demo_release,
};

static int __init demo_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        1,
        DEVICE_NAME
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    cdev_init(&my_cdev, &demo_fops);

    my_cdev.owner = THIS_MODULE;

    ret = cdev_add(&my_cdev, dev, 1);

    if (ret < 0) {
        pr_err("cdev registration failed: %d\n", ret);
        unregister_chrdev_region(dev, 1);
        return ret;
    }

    pr_info("Character device registered\n");
    pr_info("Major: %u Minor: %u\n",
            MAJOR(dev), MINOR(dev));

    return 0;
}

static void __exit demo_exit(void)
{
    cdev_del(&my_cdev);

    pr_info("Character device registration removed\n");

    unregister_chrdev_region(dev, 1);

    pr_info("Device-number range released\n");
}

module_init(demo_init);
module_exit(demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Character Device Unregistration Demonstration");

Program Explanation

  1. Allocate one device number dynamically.
  2. Initialize the cdev object.
  3. Associate file operations with the cdev.
  4. Register the cdev using cdev_add().
  5. During module cleanup, remove the cdev using cdev_del().
  6. Release the device-number range using unregister_chrdev_region().
This example does not create a /dev node or device-model class. It focuses on the kernel-side registration and unregistration process.

12. Common Mistakes

Mistake Correct Approach
Releasing device numbers without removing the cdev Remove the cdev registration first.
Calling cleanup on resources that were never created Track successful initialization stages and clean up only acquired resources.
Forgetting device_destroy() Remove device-model objects if they were created.
Forgetting class_destroy() Destroy the class if the driver created one.
Freeing active device data immediately Wait until active users and operations no longer reference the data.
Assuming cdev_del() closes all open files Handle existing file descriptors and references safely.

13. Summary

  • Character-device unregistration removes the kernel registration and releases reserved device numbers.
  • cdev_del() removes the cdev registration.
  • unregister_chrdev_region() releases device numbers.
  • device_destroy() removes a device-model object.
  • class_destroy() removes a device class.
  • Existing open file descriptors require careful lifetime management.
  • Cleanup should release resources according to their initialization dependencies.
