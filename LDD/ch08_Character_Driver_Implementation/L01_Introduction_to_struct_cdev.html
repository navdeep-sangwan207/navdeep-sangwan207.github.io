Lesson 1: Introduction to struct cdev
Level: Intermediate
Prerequisites: Character-device architecture, major and minor numbers, dev_t, device-number allocation and file_operations.
Objective: Understand the purpose, structure and role of struct cdev in registering character devices with the Linux kernel.

1. Introduction

Linux uses the character-device infrastructure to connect user-space applications with character-device drivers.

One of the important kernel structures used in this process is struct cdev.

The cdev structure represents a character device within the kernel. It connects a device-number range with the driver's file operations.

A driver generally performs the following operations:

  1. Allocate a device-number range.
  2. Initialize a struct cdev.
  3. Associate file operations with the cdev.
  4. Register the cdev using cdev_add().
  5. Remove the cdev during cleanup.

2. What Is struct cdev?

struct cdev is a kernel data structure defined in the Linux kernel headers.

It represents a character device and associates that device with its file-operation callbacks and device numbers.

The structure is declared in: 

#include <linux/cdev.h>

The cdev infrastructure enables the kernel to route operations on an associated character-device number to the appropriate driver.

3. Why Is struct cdev Required?

Allocating a device number alone does not make a character driver operational.

The kernel also needs a registered character-device object that associates the device-number range with the driver's operations.

Without cdev Registration

  • The driver may have a reserved device-number range.
  • However, that reservation alone does not register a character-device handler.
  • There is no cdev registration connecting that range to the driver's file operations.

With cdev Registration

  • The cdev is initialized with file operations.
  • The cdev is associated with a device-number range.
  • The kernel can route relevant device operations to the registered driver.
Device-number allocation and cdev registration are separate operations. Both are required in the usual modern character-driver registration approach.

4. Understanding the cdev Structure

The Linux kernel defines struct cdev in its character-device subsystem headers.

Its internal implementation can vary between kernel versions. The following is a conceptual representation, not a complete copy of the kernel declaration. 

struct cdev {
    struct kobject kobj;
    struct module *owner;
    const struct file_operations *ops;
    struct list_head list;
    dev_t dev;
    unsigned int count;
};

Important Members

Member Purpose
kobj Provides kernel object and reference-counting infrastructure.
owner Identifies the module that owns the cdev.
ops Points to the associated file_operations structure.
list Supports internal kernel list management.
dev Stores the associated starting device number.
count Represents the number of device numbers covered by the cdev registration.
Driver developers normally use the kernel-provided cdev helper functions instead of directly modifying internal members such as kobj, list, dev or count. The exact internal structure should be checked against the target kernel source.

5. Relationship Between cdev and file_operations

The file_operations structure contains function pointers for operations that a driver supports.

Examples include:

Callback Purpose
open Called when a device file is opened.
read Handles supported read requests.
write Handles supported write requests.
release Handles closing of an opened file.
unlocked_ioctl Handles supported device-control commands.
poll Supports polling and readiness notification.

Example file_operations

#include <linux/fs.h>

static int my_open(struct inode *inode,
                   struct file *file)
{
    return 0;
}

static int my_release(struct inode *inode,
                      struct file *file)
{
    return 0;
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .release = my_release,
};

This structure is associated with the cdev using cdev_init().

6. Initializing struct cdev

The kernel provides the cdev_init() function to initialize a cdev and associate it with a file_operations structure.

Function prototype:

void cdev_init(
    struct cdev *cdev,
    const struct file_operations *fops
);

Parameters

Parameter Meaning
cdev Pointer to the cdev structure to initialize.
fops Pointer to the file_operations structure.

Example

static struct cdev my_cdev;

cdev_init(&my_cdev, &my_fops);

This initializes the cdev and associates the specified file operations with it. It does not by itself register the cdev with the kernel.

7. Setting the Module Owner

After initializing a cdev, drivers commonly set its owner to the current kernel module: 

my_cdev.owner = THIS_MODULE;

This associates the cdev with the module that implements the driver. It helps the kernel manage module references while the character device is in use.

The file_operations structure also commonly specifies: 

.owner = THIS_MODULE
Setting the owner in both the cdev and file_operations structures is a common pattern in module-based character drivers.

8. Registering a cdev

After initialization, the driver registers the cdev using cdev_add().

Function prototype: 

int cdev_add(
    struct cdev *p,
    dev_t dev,
    unsigned count
);
Parameter Meaning
p Pointer to the initialized cdev.
dev Starting device number.
count Number of consecutive device numbers covered.

The function returns zero on success or a negative error code on failure. 

ret = cdev_add(
    &my_cdev,
    dev,
    1
);

if (ret < 0) {
    pr_err("cdev registration failed\n");
}
Once cdev_add() succeeds, the character device can be accessed through its registered device-number range if an appropriate device node or interface is available. The cdev may be accessed immediately, so the driver must be ready to handle operations at that point.

9. Removing a cdev

The kernel provides cdev_del() to remove a registered cdev.

Function prototype:

void cdev_del(struct cdev *p);

Example:

cdev_del(&my_cdev);

This prevents new opens through that cdev registration. It does not automatically release the allocated device-number range.

The driver must release the range separately: 

unregister_chrdev_region(dev, 1);
Removing a cdev does not mean that every previously opened file has automatically stopped using the driver. A robust driver must manage active operations and device data lifetime carefully before freeing resources.

11. Practical Kernel Module Example

The following example demonstrates how to allocate a device number, initialize a cdev, register it and remove it safely.

It does not implement read or write operations and does not create a device node.

File: cdev_intro.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/init.h>

#define DEVICE_NAME "cdev_intro"

static dev_t dev;
static struct cdev my_cdev;

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
};

static int __init cdev_intro_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        1,
        DEVICE_NAME
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    pr_info("Major: %u Minor: %u\n",
            MAJOR(dev), MINOR(dev));

    cdev_init(&my_cdev, &my_fops);
    my_cdev.owner = THIS_MODULE;

    ret = cdev_add(&my_cdev, dev, 1);

    if (ret < 0) {
        pr_err("cdev_add failed\n");
        unregister_chrdev_region(dev, 1);
        return ret;
    }

    pr_info("cdev registered successfully\n");

    return 0;
}

static void __exit cdev_intro_exit(void)
{
    cdev_del(&my_cdev);

    unregister_chrdev_region(dev, 1);

    pr_info("cdev removed successfully\n");
}

module_init(cdev_intro_init);
module_exit(cdev_intro_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Introduction to struct cdev");

Program Explanation

  1. dev_t dev stores the allocated device number.
  2. struct cdev my_cdev declares the character-device object.
  3. my_fops defines the file operations supported by this example.
  4. alloc_chrdev_region() reserves one device number.
  5. cdev_init() initializes the cdev.
  6. cdev_add() registers the cdev with the kernel.
  7. cdev_del() removes the cdev during module cleanup.
  8. unregister_chrdev_region() releases the reserved number.

12. Makefile

Create a file named Makefile in the same directory. 

obj-m += cdev_intro.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all: and clean: must begin with a tab character.

13. Compile and Test in Ubuntu

Step 1: Install Dependencies

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Step 2: Compile the Module

make

Step 3: Inspect Module Information

modinfo cdev_intro.ko

Step 4: Load the Module

sudo insmod cdev_intro.ko

Step 5: Inspect Kernel Messages

sudo dmesg | tail -20

Example output:

Major: 240 Minor: 0
cdev registered successfully

The allocated major number may differ on your system.

Step 6: Inspect Registered Device Numbers

cat /proc/devices

Step 7: Remove the Module

sudo rmmod cdev_intro

Step 8: Check Cleanup Messages

sudo dmesg | tail -20

Step 9: Clean Build Files

make clean
This is a software-only cdev registration exercise and can be performed in Ubuntu running inside VirtualBox. It does not require physical GPIO, I2C or SPI hardware.

14. Common Mistakes

Mistake Correct Approach
Calling cdev_add() before initialization Initialize the cdev using cdev_init() first.
Using an unallocated device number Reserve the device-number range before cdev registration.
Ignoring cdev_add() return value Check the return value and handle failure.
Forgetting cdev_del() Remove the cdev during cleanup.
Forgetting to release device numbers Call unregister_chrdev_region() after removing the cdev.
Assuming cdev_add() creates /dev entries Create a device node or use the device model separately.
Freeing active device resources too early Coordinate removal with active users and resource lifetime.

15. Summary

  • struct cdev represents a registered character device.
  • It associates a device-number range with file operations.
  • cdev_init() initializes the cdev.
  • cdev_add() registers the cdev.
  • cdev_del() removes the cdev registration.
  • dev_t represents the associated device number.
  • Device-number allocation and cdev registration are separate operations.
  • Device-node creation is another separate operation.
  • Proper cleanup is essential for reliable kernel-module development.
