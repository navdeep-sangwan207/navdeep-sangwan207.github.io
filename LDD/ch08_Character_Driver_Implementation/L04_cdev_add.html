Lesson 4: cdev_add() Function
Level: Intermediate
Prerequisites: struct cdev, file_operations, cdev_init() and device-number allocation.
Objective: Understand how cdev_add() registers a character device with the Linux kernel.

1. Introduction

After initializing a character-device object using cdev_init(), the driver must register it with the kernel.

Linux provides the cdev_add() function for this purpose.

Registration connects a character device number range with the initialized cdev object and its associated file operations.

Once registration succeeds, the kernel can use the driver's operations when a matching device number is accessed through the character-device interface.

2. What Is cdev_add()?

cdev_add() is a Linux kernel helper function that adds an initialized character-device object to the kernel's character-device infrastructure.

Header file:

#include <linux/cdev.h>

Function prototype:

int cdev_add(
    struct cdev *p,
    dev_t dev,
    unsigned int count
);

Important Characteristics

  • Registers an initialized cdev object.
  • Associates the cdev with a device-number range.
  • Uses the file operations previously associated through cdev_init().
  • Returns 0 on success.
  • Returns a negative error code on failure.
  • Makes the registered device available immediately.
A successful cdev_add() call does not automatically create a visible device node such as /dev/mydevice. Device-node creation is a separate operation.

3. Function Parameters

Parameter Description
p Pointer to the initialized struct cdev object.
dev Starting device number for the registration range.
count Number of consecutive minor device numbers to register.

Example

ret = cdev_add(&my_cdev, dev, 1);

Explanation:

  • &my_cdev is the address of the cdev object.
  • dev is the allocated starting device number.
  • 1 registers one device number.
  • ret stores the function's return value.

4. Understanding the Device Number Range

Linux represents a device number using the dev_t type. It contains a major number and a minor number.

The major number identifies the driver association, while the minor number distinguishes devices or instances handled through that association.

Example: Registering One Device

ret = cdev_add(&my_cdev, dev, 1);

If the starting device number has major number 240 and minor number 0, this registration covers:

Major Minor Registered Device Number
240 0 240:0

Example: Registering Four Devices

ret = cdev_add(&my_cdev, dev, 4);

If dev starts at major 240, minor 0, the registered range is:

Major Minor
2400
2401
2402
2403
The count parameter specifies the number of consecutive device numbers handled by this cdev registration. The corresponding device-number range must already have been allocated or reserved by the driver.

5. Relationship Between cdev_init() and cdev_add()

These functions perform different tasks and are normally used in sequence.

6. Return Value and Error Handling

Unlike cdev_init(), the cdev_add() function returns an integer.

Return Value Meaning
0 Registration succeeded.
Negative value Registration failed; the value represents an error code.

Example

ret = cdev_add(&my_cdev, dev, 1);

if (ret < 0) {
    pr_err("cdev_add failed: %d\n", ret);
    unregister_chrdev_region(dev, 1);
    return ret;
}

If registration fails, the driver must release resources that were successfully acquired earlier.

cdev_add() makes the device available immediately. Initialize all data, locks, buffers and other resources required by callbacks before calling it. Do not assume there is a delay between registration and the first possible access.

7. Complete Practical Example

The following module demonstrates device-number allocation, cdev initialization and cdev registration.

File: cdev_add_demo.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/init.h>

#define DEVICE_NAME "cdev_add_demo"

static dev_t dev;
static struct cdev my_cdev;

static int demo_open(struct inode *inode,
                     struct file *file)
{
    pr_info("Device opened\n");
    return 0;
}

static int demo_release(struct inode *inode,
                        struct file *file)
{
    pr_info("Device released\n");
    return 0;
}

static const struct file_operations demo_fops = {
    .owner = THIS_MODULE,
    .open = demo_open,
    .release = demo_release,
};

static int __init demo_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        1,
        DEVICE_NAME
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    pr_info("Allocated major: %u minor: %u\n",
            MAJOR(dev), MINOR(dev));

    cdev_init(&my_cdev, &demo_fops);

    my_cdev.owner = THIS_MODULE;

    ret = cdev_add(&my_cdev, dev, 1);

    if (ret < 0) {
        pr_err("cdev_add failed: %d\n", ret);
        unregister_chrdev_region(dev, 1);
        return ret;
    }

    pr_info("cdev registered successfully\n");

    return 0;
}

static void __exit demo_exit(void)
{
    cdev_del(&my_cdev);

    unregister_chrdev_region(dev, 1);

    pr_info("Character device unregistered\n");
}

module_init(demo_init);
module_exit(demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("cdev_add Function Demonstration");

Program Explanation

  1. Declare a device number and cdev object.
  2. Define open and release callbacks.
  3. Create a file_operations structure.
  4. Allocate one device number using alloc_chrdev_region().
  5. Initialize the cdev using cdev_init().
  6. Set the cdev owner.
  7. Register the cdev using cdev_add().
  8. Check the registration return value.
  9. Remove the cdev and release the device number during cleanup.
This example registers a character device but does not create a /dev node. It demonstrates kernel-side registration, not complete user-space device-file access.

10. Important Notes About cdev_del()

The cdev_del() function removes a previously registered character-device object. 

cdev_del(&my_cdev);

It prevents new opens through that cdev registration. However, it does not automatically terminate existing open file descriptors.

A driver must manage the lifetime of its data structures and resources carefully when existing operations may still be active.

The usual cleanup order is: remove the cdev registration first, then release its device-number range. Additional synchronization and lifetime handling may be necessary for a driver with active users.

11. Common Mistakes

Mistake Correct Approach
Calling cdev_add() before cdev_init() Initialize the cdev before registration.
Using an unallocated device-number range Allocate or reserve the range first.
Ignoring the return value Check for negative error codes.
Initializing driver state after cdev_add() Prepare all callback-required state before registration.
Assuming cdev_add() creates /dev entries Use a separate device-node or device-model creation mechanism.
Forgetting cdev_del() Remove the registration during cleanup.
Releasing device numbers before removing cdev Remove the cdev before releasing its number range.

12. Summary

  • cdev_add() registers a character-device object.
  • It accepts a cdev pointer, starting device number and count.
  • The device-number range must already be allocated or reserved.
  • It returns 0 on success and a negative error code on failure.
  • The cdev must be initialized before registration.
  • Driver state must be ready before cdev_add() is called.
  • Registration does not automatically create a /dev node.
  • cdev_del() removes the cdev registration.
