Chapter Overview

A Linux character device driver connects a device-number range with a set of driver operations. The kernel uses the character device infrastructure to associate device files with the appropriate driver implementation.

This chapter explains the struct cdev data structure, character device registration, the file_operations structure and the basic callbacks used when a device file is opened and closed. It concludes with the architecture of a basic character device driver.

Important Kernel Structures and APIs

  • struct cdev: Represents a character device within the Linux kernel.
  • struct file_operations: Defines callbacks for operations on an open device file.
  • cdev_init(): Initializes a character device structure and associates its operations.
  • cdev_add(): Adds the character device to the kernel.
  • cdev_del(): Removes the character device from the kernel.
  • register_chrdev_region(): Registers a specified device-number range.
  • alloc_chrdev_region(): Dynamically allocates a device-number range.
  • unregister_chrdev_region(): Releases the registered device-number range.
  • THIS_MODULE: Commonly used to associate file operations with the owning module.

Character Driver Registration Sequence

  • Allocate or register a device-number range.
  • Initialize the struct cdev object.
  • Associate the file_operations callbacks.
  • Add the character device using cdev_add().
  • Provide a device node through the appropriate device-management mechanism.
  • Implement cleanup by removing the cdev and releasing the device-number range.
