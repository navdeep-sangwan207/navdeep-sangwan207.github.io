  • Understand access restrictions and process visibility.

2. Introduction to the /proc Directory

The /proc directory is the standard mount point for the Linux Procfs filesystem.

It contains two broad categories of information:

  1. System-wide and kernel-related information.
  2. Information associated with individual processes.

Unlike an ordinary directory on a disk, entries in /proc are provided by the kernel and can represent live runtime information.

Display the contents

ls /proc

Display directories and files

ls -l /proc

You will see numeric directory names such as 1, 2, 1000 and other entries such as cpuinfo, meminfo and version.

3. Organization of the /proc Filesystem

The /proc filesystem can be understood using the following simplified structure.

/proc
↓
System Information
Process Directories
Kernel Interfaces
↓
cpuinfo, meminfo, interrupts
/proc/1, /proc/1000
/proc/sys

Main categories

Category Examples Purpose
System information cpuinfo, meminfo, uptime Provides system statistics.
Process information /proc/1, /proc/1000 Provides information about individual processes.
Kernel interfaces /proc/sys Exposes selected kernel parameters.

4. System-Wide Information Files

System-wide Procfs entries provide information about the running Linux system.

4.1 /proc/cpuinfo

Provides processor information such as processor model, architecture-related details, features and CPU identifiers. 

cat /proc/cpuinfo

4.2 /proc/meminfo

Provides memory statistics such as total memory, available memory, free memory, buffers and cached memory. 

cat /proc/meminfo

4.3 /proc/uptime

Contains the system uptime and accumulated idle time, expressed in seconds. 

cat /proc/uptime

4.4 /proc/version

Provides information about the running kernel version and its build environment. 

cat /proc/version

4.5 /proc/loadavg

Provides load averages over 1, 5 and 15 minutes, along with additional process-related information. 

cat /proc/loadavg

4.6 /proc/stat

Contains CPU and other kernel statistics, including information used by system monitoring tools. 

cat /proc/stat

5. Process-Specific Directories

Each running process has a directory under /proc identified by its process ID (PID).

For example: 

/proc/1/
/proc/1000/
/proc/2500/

The actual directories depend on the processes currently running on the system.

Find the current shell PID

echo $$

Inspect the current shell directory

ls /proc/$$

The $$ shell variable expands to the PID of the current shell.

Inspect process information

cat /proc/$$/status

6. Important Entries Inside /proc/PID

Entry Description
cmdline Command-line arguments used to start the process.
comm Process command name.
status Human-readable process status and resource information.
stat Detailed process statistics in a compact format.
maps Memory regions mapped into the process address space.
fd Symbolic links for open file descriptors.
cwd Symbolic link to the current working directory.
exe Symbolic link to the executable file.
task Information about threads belonging to the process.
environ Environment variables supplied to the process at startup.
Access to some process entries depends on user permissions, system security settings and the relationship between the requesting process and the target process.

7. Understanding /proc/PID/status

The status entry provides a human-readable overview of a process.

Command

cat /proc/$$/status

Common fields include:

Field Meaning
Name Process name.
State Current process state.
Pid Process ID.
PPid Parent process ID.
Uid User IDs associated with the process.
Gid Group IDs associated with the process.
VmSize Virtual memory size.
VmRSS Resident set size information.
Threads Number of threads in the process.

This information is useful for process monitoring and system troubleshooting.

8. Understanding /proc/PID/maps

The maps entry describes the virtual memory regions mapped into a process.

Command

cat /proc/$$/maps

The output generally includes:

  • Start and end virtual addresses.
  • Memory permissions.
  • File offset.
  • Device and inode information.
  • Associated pathname, when applicable.

Memory permissions

Permission Meaning
r Readable memory.
w Writable memory.
x Executable memory.
p Private mapping.
s Shared mapping.

This entry is useful when studying process memory management and debugging memory-related problems.

9. Understanding /proc/PID/fd

The fd directory contains symbolic links representing the open file descriptors of a process.

Command

ls -l /proc/$$/fd

Common file descriptor numbers include:

Descriptor Conventional purpose
0 Standard input.
1 Standard output.
2 Standard error.

Additional descriptors may represent files, pipes, sockets or other kernel-managed objects.

Example

ls -l /proc/self/fd

Here, /proc/self refers to the process accessing that Procfs path. When a command opens this path, it refers to that command's process.

10. The /proc/sys Directory

The /proc/sys directory exposes selected kernel parameters that can be inspected and, where permitted, modified at runtime.

These parameters are commonly known as sysctl parameters.

Explore the directory

ls /proc/sys

Inspect network parameters

ls /proc/sys/net

Read a kernel parameter

cat /proc/sys/kernel/hostname

The exact contents depend on the running kernel and system configuration.

Related sysctl command

sysctl -a

The sysctl utility provides a convenient interface for reading many kernel parameters.

Do not modify kernel parameters casually. Incorrect values can affect networking, security or system stability. Study the documented meaning of a parameter before changing it.

11. Process Visibility and Permissions

Not every user can necessarily inspect every process. Linux applies access-control checks to sensitive process information.

The visibility of process directories may also be restricted using the hidepid mount option on Procfs.

For example, a system administrator may configure Procfs to restrict visibility of other users' process directories. The precise behavior depends on the selected mount option and system configuration.

Check current mount options

findmnt -no OPTIONS /proc
A permission-denied message when reading another process's Procfs entry does not necessarily indicate a filesystem problem. It may be an intentional security restriction.

12. How Applications Access Procfs

User-space programs access Procfs through ordinary filesystem operations.

User Application
↓
open("/proc/meminfo")
↓
read()
↓
VFS and Procfs
↓
Kernel Memory Information
↓
Data Returned to Application

The application does not need to directly access kernel memory. The kernel exposes the permitted information through Procfs operations.

The same general file-access model is used by shell commands such as cat, less and programs that use the standard file APIs.

14. Procfs and Linux Device Drivers

For device-driver developers, several Procfs entries are particularly useful during development and debugging.

Procfs entry Driver development relevance
/proc/interrupts Inspect interrupt activity and interrupt counts.
/proc/modules Inspect currently loaded loadable modules.
/proc/devices Inspect registered character and block device major numbers.
/proc/iomem Inspect the system's I/O memory resource map.
/proc/ioports Inspect allocated I/O port regions where applicable.
/proc/misc Inspect registered miscellaneous character devices.

These entries help developers understand aspects of the running kernel and registered devices. They do not replace driver-specific debugging tools or subsystem interfaces.

15. Important Points to Remember

  • /proc is the normal mount point for Procfs.
  • Numeric directories represent process IDs.
  • System-wide files expose kernel and system information.
  • /proc/PID/status provides process status details.
  • /proc/PID/maps describes process memory mappings.
  • /proc/PID/fd represents open file descriptors.
  • /proc/sys exposes selected kernel parameters.
  • Access to process information can be restricted.
  • Procfs is a kernel-provided interface, not ordinary disk storage.

16. Lesson Summary

The /proc filesystem is an important interface between user-space applications and the Linux kernel.

It provides two major categories of information: system-wide kernel information and process-specific information.

By inspecting entries such as cpuinfo, meminfo, interrupts, modules, status, maps and fd, developers can understand the runtime behavior of Linux systems.
