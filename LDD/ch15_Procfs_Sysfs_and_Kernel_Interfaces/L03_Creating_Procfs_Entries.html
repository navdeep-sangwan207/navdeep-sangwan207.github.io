2. Introduction to Creating Procfs Entries

Linux provides Procfs as a kernel-managed virtual filesystem. Kernel modules can use it to expose selected information to user-space applications.

For example, a driver may want to provide information about:

  • Driver status.
  • Device statistics.
  • Interrupt counts.
  • Diagnostic information.
  • Selected configuration values.

A kernel module can create a custom entry under /proc using the proc_create() function.

Example entry

/proc/my_driver_status

A user-space application can access the entry using ordinary file operations such as open() and read().

3. Architecture of a Custom Procfs Entry

Linux Kernel Module
↓
proc_create()
↓
Procfs Entry
↓
/proc/my_driver_status
↓
User-Space Application

The module creates the entry and associates it with operations that define how the entry behaves.

When a user-space program accesses the entry, the corresponding callbacks handle the requested operation.

4. proc_create() Function

The proc_create() function creates a file-like entry in Procfs and associates it with a set of operations.

Function declaration

struct proc_dir_entry *proc_create(
    const char *name,
    umode_t mode,
    struct proc_dir_entry *parent,
    const struct proc_ops *proc_ops
);

Parameters

Parameter Description
name Name of the Procfs entry.
mode Permission bits for the entry.
parent Parent Procfs directory.
proc_ops Pointer to the Procfs operations structure.

Return value

The function returns a pointer to a struct proc_dir_entry when creation succeeds. It returns NULL if creation fails.

Example

proc_create(
    "my_driver_status",
    0444,
    NULL,
    &my_proc_ops
);

This creates a root-level entry: 

/proc/my_driver_status

The mode 0444 gives read permission to the owner, group and others, with no write permission.

5. Understanding the Parent Directory

The parent parameter determines where the new entry will be created.

Creating an entry directly under /proc

proc_create(
    "my_driver_status",
    0444,
    NULL,
    &my_proc_ops
);

When the parent is NULL, the entry is created directly under the Procfs root directory.

Creating a directory and an entry inside it

A driver can create a directory using proc_mkdir(), then create an entry inside it. 

struct proc_dir_entry *my_dir;

my_dir = proc_mkdir("my_driver", NULL);

if (!my_dir) {
    pr_err("Unable to create Procfs directory\n");
    return -ENOMEM;
}

proc_create("status", 0444, my_dir, &my_proc_ops);

The resulting path is: 

/proc/my_driver/status
The code above illustrates directory and file creation. A complete module must also check the result of proc_create() and remove any successfully created entries during error handling and module cleanup.

6. Understanding struct proc_ops

Modern Linux kernels use the struct proc_ops structure to define operations for Procfs entries.

It contains callback function pointers for operations such as opening, reading, writing and releasing an entry.

Simplified structure

struct proc_ops {
    unsigned int proc_flags;

    int (*proc_open)(struct inode *, struct file *);
    ssize_t (*proc_read)(
        struct file *,
        char __user *,
        size_t,
        loff_t *
    );
    ssize_t (*proc_write)(
        struct file *,
        const char __user *,
        size_t,
        loff_t *
    );
    loff_t (*proc_lseek)(
        struct file *,
        loff_t,
        int
    );
    int (*proc_release)(
        struct inode *,
        struct file *
    );
};

This is a simplified illustration of the interface. The exact structure definition is provided by the kernel headers for the target kernel version.

Callback Purpose
proc_open Called when the entry is opened.
proc_read Handles reading data from the entry.
proc_write Handles writing data to the entry.
proc_lseek Handles file-position changes.
proc_release Handles release of the open file description.

7. Kernel Version Compatibility

The Procfs operation interface has changed across Linux kernel versions.

Kernel interface Usage
struct proc_ops Modern interface introduced in Linux 5.6.
struct file_operations Used by older kernel versions for Procfs operations.
The examples in this lesson use struct proc_ops, targeting modern Linux kernels. If your Ubuntu kernel is older than Linux 5.6, the Procfs callbacks may need to be adapted to the older interface.

8. proc_remove() Function

When a kernel module is unloaded, its custom Procfs entries must be removed.

The proc_remove() function removes a Procfs entry created by the module.

Function declaration

void proc_remove(struct proc_dir_entry *de);

Parameter

  • de: Pointer to the Procfs entry to remove.

Example

proc_remove(proc_entry);

The pointer returned by proc_create() is typically stored and passed to proc_remove() during module cleanup.

A module must not be unloaded while its callbacks can still execute. Procfs removal and module lifetime management must be handled correctly. Do not manually free a Procfs entry returned by proc_create().

9. Complete Practical Example: Creating a Procfs Entry

The following module creates a read-only entry named my_driver_status under /proc.

The example uses proc_create() to create the entry and a read callback to provide information.

Source file: proc_demo.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/proc_fs.h>
#include <linux/seq_file.h>

#define PROC_NAME "my_driver_status"

static struct proc_dir_entry *proc_entry;

/* Display information through seq_file */
static int proc_show(struct seq_file *m, void *v)
{
    seq_puts(m, "Linux Device Driver Procfs Demo\n");
    seq_puts(m, "Driver Status: Active\n");
    seq_puts(m, "Interface: Procfs\n");

    return 0;
}

/* Open callback */
static int proc_open(struct inode *inode,
                     struct file *file)
{
    return single_open(file, proc_show, NULL);
}

/* Procfs operations */
static const struct proc_ops my_proc_ops = {
    .proc_open    = proc_open,
    .proc_read    = seq_read,
    .proc_lseek   = seq_lseek,
    .proc_release = single_release,
};

/* Module initialization */
static int __init proc_demo_init(void)
{
    proc_entry = proc_create(
        PROC_NAME,
        0444,
        NULL,
        &my_proc_ops
    );

    if (!proc_entry) {
        pr_err("Unable to create /proc/%s\n", PROC_NAME);
        return -ENOMEM;
    }

    pr_info("Procfs entry created successfully\n");

    return 0;
}

/* Module cleanup */
static void __exit proc_demo_exit(void)
{
    proc_remove(proc_entry);

    pr_info("Procfs entry removed\n");
}

module_init(proc_demo_init);
module_exit(proc_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Simple Procfs Entry Example");

Explanation of the program

  1. linux/proc_fs.h provides Procfs functions and declarations.
  2. linux/seq_file.h provides the sequential file interface.
  3. proc_entry stores the pointer returned by proc_create().
  4. proc_show() generates the information displayed to the user.
  5. proc_open() initializes the single_open() interface.
  6. my_proc_ops connects Procfs operations to their callbacks.
  7. proc_create() creates the entry during module initialization.
  8. proc_remove() removes it during module cleanup.
This example uses the seq_file interface to generate output safely and conveniently. The next lesson will examine how Procfs entries handle reading and writing in greater detail.

10. Understanding the seq_file Interface

The seq_file interface is a kernel facility for generating sequential output through virtual files.

It is useful when a Procfs entry needs to display text or a sequence of records.

Important functions

Function Purpose
single_open() Connects an open operation to a single show callback.
seq_read() Provides reading through the seq_file interface.
seq_lseek() Handles seeking in sequential output.
single_release() Releases resources allocated by single_open().
seq_puts() Writes a string into the seq_file output buffer.

Using seq_file avoids manually managing many details associated with generating sequential output.

11. Makefile for the Procfs Module

Create a Makefile in the same directory as proc_demo.c. 

obj-m += proc_demo.o

KDIR := /lib/modules/$(shell uname -r)/build
PWD  := $(shell pwd)

all:
	make -C $(KDIR) M=$(PWD) modules

clean:
	make -C $(KDIR) M=$(PWD) clean

The Makefile uses the running kernel's build directory to compile the external kernel module.

The Makefile recipe lines beginning with make must start with a TAB character, not spaces.

12. Compiling and Testing the Module

Step 1: Install build dependencies

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Step 2: Compile the module

make

If compilation succeeds, a kernel module named proc_demo.ko should be generated.

Step 3: Load the module

sudo insmod proc_demo.ko

Step 4: Check the kernel log

sudo dmesg | tail

Step 5: Verify the Procfs entry

ls -l /proc/my_driver_status

Step 6: Read the entry

cat /proc/my_driver_status

Expected output

Linux Device Driver Procfs Demo
Driver Status: Active
Interface: Procfs

Step 7: Remove the module

sudo rmmod proc_demo

Step 8: Verify removal

ls /proc/my_driver_status

The entry should no longer exist after successful module removal.

Kernel modules execute with kernel privileges. Test only code you understand in your Ubuntu virtual machine. Keep important data backed up and avoid experiments intended to crash the kernel.

13. Error Handling in Procfs Entry Creation

The return value of proc_create() must always be checked.

Incorrect approach

proc_create(
    "my_driver_status",
    0444,
    NULL,
    &my_proc_ops
);

/* Continuing without checking the result */

Correct approach

proc_entry = proc_create(
    "my_driver_status",
    0444,
    NULL,
    &my_proc_ops
);

if (!proc_entry) {
    pr_err("Procfs entry creation failed\n");
    return -ENOMEM;
}

If creation fails, the module initialization function must return an appropriate negative error code.

Cleanup principle

If a module creates multiple Procfs entries and a later creation fails, it must remove any entries that were successfully created before returning the error.

14. Deprecated Procfs APIs

Older Linux kernel examples may contain APIs that are not appropriate for modern kernel development.

API Status
create_proc_entry() Legacy API removed from modern Linux kernels.
proc_create() Current approach for creating many Procfs entries.
proc_remove() Used to remove Procfs entries.
struct proc_ops Modern Procfs operations interface.
Always check the target kernel's headers and documentation when developing out-of-tree modules. Kernel APIs can change between releases.

15. Best Practices

  • Use meaningful Procfs entry names.
  • Check the return value of proc_create().
  • Remove created entries during module cleanup.
  • Use appropriate file permissions.
  • Validate all data received from user space.
  • Protect shared driver data using appropriate synchronization.
  • Use seq_file for suitable sequential text output.
  • Avoid exposing sensitive device or kernel information.
  • Prefer Sysfs or established subsystem interfaces for new device attributes.
  • Follow the API supported by the target kernel version.

16. Lesson Summary

  • Procfs entries can be created by Linux kernel modules.
  • proc_create() creates a Procfs entry.
  • proc_remove() removes a Procfs entry.
  • struct proc_ops defines modern Procfs callbacks.
  • The parent parameter determines the entry's location.
  • proc_mkdir() can create a directory under Procfs.
  • The seq_file interface simplifies sequential output.
  • Creation failures must be handled correctly.
  • Procfs entries must be removed as part of module cleanup.
