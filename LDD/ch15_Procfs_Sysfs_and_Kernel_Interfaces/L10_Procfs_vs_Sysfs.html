2. Introduction

Linux provides several virtual filesystems that allow user-space applications to interact with kernel information and functionality.

Two important virtual filesystems are:

  1. Procfs: Process and kernel information filesystem.
  2. Sysfs: Structured representation of kernel objects and the device model.

Both provide file-based interfaces, but they have different design purposes and organizational models.

3. What Is Procfs?

Procfs is a virtual filesystem commonly mounted at: 

/proc

It provides information about processes and various kernel subsystems.

Procfs does not normally store ordinary files on a disk. Its entries are generated by kernel code when user space accesses them.

Examples of Procfs entries

File Purpose
/proc/cpuinfo Processor information.
/proc/meminfo Memory statistics.
/proc/uptime System uptime information.
/proc/version Kernel version information.
/proc/modules Information about loaded modules.
/proc/interrupts Interrupt statistics.
/proc/mounts Mounted filesystem information.

Process-specific information

Procfs also contains directories associated with process IDs. 

/proc/1/
/proc/1000/
/proc/2500/

For example: 

/proc/1/status
/proc/1/cmdline
/proc/1/maps

The actual process directories depend on which processes are running and the permissions of the user accessing them.

4. What Is Sysfs?

Sysfs is a virtual filesystem commonly mounted at: 

/sys

It exposes the kernel object hierarchy and provides a structured interface to devices, buses, drivers, classes and other kernel objects.

Sysfs is closely integrated with the Linux device model and kobject infrastructure.

Important Sysfs directories

Directory Purpose
/sys/devices Device hierarchy.
/sys/bus Bus types, devices and drivers.
/sys/class Device classes and their interfaces.
/sys/block Block device information.
/sys/module Information about kernel modules.
/sys/firmware Firmware-related interfaces.

5. Fundamental Difference Between Procfs and Sysfs

The most important difference is their organizational purpose.

Procfs

Procfs provides process-related and kernel-related information through virtual files.

Sysfs

Sysfs represents kernel objects in a structured hierarchy and exposes their attributes.

Procfs
/proc

Process and kernel information

Sysfs
/sys

Kernel objects and device model

8. How Procfs Works

When a user-space application reads a Procfs entry, the kernel handles the access through the corresponding Procfs implementation.

Example

cat /proc/meminfo

The shell starts the cat program. The program opens the file and reads its contents. The kernel provides the memory information through the Procfs interface.

9. How Sysfs Works

Sysfs exposes attributes associated with kernel objects. These attributes are commonly represented as files containing textual information.

Example

cat /sys/class/net/lo/mtu

The kernel provides the MTU value associated with the loopback network device.

When a user-space process reads the attribute, the corresponding Sysfs and driver-model callback mechanisms provide the value.

10. Reading Procfs Information

Procfs is commonly used to inspect kernel and process information.

CPU information

cat /proc/cpuinfo

Displays processor information available to the kernel.

Memory information

cat /proc/meminfo

Displays memory statistics.

Kernel version

cat /proc/version

Displays kernel version and build information.

Loaded modules

cat /proc/modules

Displays information about currently loaded modules.

Interrupt statistics

cat /proc/interrupts

Displays interrupt statistics maintained by the kernel.

11. Reading Sysfs Information

Sysfs is commonly used to inspect devices and their properties.

Network interfaces

ls /sys/class/net

Lists network interfaces.

Loopback MTU

cat /sys/class/net/lo/mtu

Loopback operational state

cat /sys/class/net/lo/operstate

Inspect device path

readlink -f /sys/class/net/lo

Inspect available bus types

ls /sys/bus

Inspect available drivers

find /sys/bus -maxdepth 4 -type d -path '*/drivers/*'

12. Writing to Procfs and Sysfs

Some Procfs and Sysfs interfaces support write operations. However, not every entry is writable.

Procfs write example

Some kernel interfaces accept configuration values through Procfs. Their accepted format and permissions depend on the specific interface.

Sysfs write example

Some Sysfs attributes allow configuration of device properties. 

echo 1500 | sudo tee /sys/class/net/lo/mtu

This command requests an MTU change for the loopback interface. Whether a particular operation is accepted depends on kernel support and permissions.

Do not write arbitrary values to kernel interfaces. A write operation can change system configuration or device behavior. Always understand the attribute and its accepted values before modifying it.

13. When Should a Device Driver Use Procfs?

Procfs may be appropriate for certain process-oriented or subsystem-oriented information interfaces.

However, for newly developed device-driver interfaces, Sysfs is generally preferred when the information represents a device-model object or one of its attributes.

Possible Procfs applications

  • Subsystem-specific diagnostic information.
  • Kernel information interfaces.
  • Existing process-related interfaces.
  • Interfaces maintained by established kernel subsystems.
Procfs is not a general-purpose replacement for device attributes. Follow the conventions of the subsystem being developed.

14. When Should a Device Driver Use Sysfs?

Sysfs is generally appropriate for exposing simple properties of kernel objects and devices.

Typical applications

  • Reading device status.
  • Reading sensor measurements.
  • Reading device configuration.
  • Changing supported device operating modes.
  • Exposing driver or device attributes.

Example

/sys/class/net/lo/mtu
/sys/class/net/lo/operstate

These attributes represent properties associated with a network device.

Important design rule

Sysfs attributes should generally be simple, human-readable text values. They should not be used as a mechanism for transferring large amounts of binary data or implementing complex communication protocols.

15. Procfs, Sysfs and Debugfs

Linux also provides Debugfs, commonly mounted at: 

/sys/kernel/debug

Debugfs is intended for kernel and driver debugging. It is not intended to provide a stable userspace ABI.

Feature Procfs Sysfs Debugfs
Mount point /proc /sys /sys/kernel/debug
Main purpose Process and kernel information Kernel objects and device model Debugging
Stable userspace ABI Depends on interface Expected for documented interfaces Not guaranteed
Typical use System statistics Device attributes Internal diagnostics
Driver development Specific interfaces Preferred for device properties Debugging facilities
Debugfs is useful during development, but applications should not depend on its files as permanent interfaces.

16. Important Kernel APIs

Procfs-related APIs

proc_create()
proc_remove()
seq_file
seq_printf()

These are commonly used for creating and managing Procfs interfaces. The seq_file interface helps generate sequential text output.

Sysfs-related APIs

DEVICE_ATTR_RO()
DEVICE_ATTR_RW()
device_create_file()
device_remove_file()

DRIVER_ATTR_RO()
DRIVER_ATTR_RW()
driver_create_file()
driver_remove_file()

sysfs_create_group()
sysfs_remove_group()

These APIs support the creation and management of Sysfs attributes and groups.

17. Practical Lab: Inspect Procfs and Sysfs

Objective

To examine the virtual filesystem interfaces in Ubuntu and identify differences between Procfs and Sysfs.

Step 1: Verify Procfs

mount | grep ' on /proc '

Step 2: Verify Sysfs

mount | grep ' on /sys '

Step 3: Inspect Procfs

ls /proc
cat /proc/meminfo
cat /proc/uptime

Step 4: Inspect Sysfs

ls /sys
ls /sys/class
ls /sys/bus

Step 5: Inspect a network device

ls /sys/class/net/lo
cat /sys/class/net/lo/mtu
cat /sys/class/net/lo/operstate

Step 6: Compare the results

Observe that Procfs provides process and kernel information, while Sysfs organizes kernel objects and their attributes.

Expected observations

  • Procfs is accessible through /proc.
  • Sysfs is accessible through /sys.
  • /proc contains system and process information.
  • /sys contains device, bus, class and module information.
  • Both filesystems expose kernel-managed information without ordinary disk-backed files.

18. Important Design and Security Considerations

  • Use Sysfs for simple device-model properties.
  • Use established Procfs interfaces for their intended purposes.
  • Do not create unnecessary duplicate interfaces.
  • Validate all values written by user-space applications.
  • Apply suitable file permissions.
  • Protect shared driver data against concurrent access.
  • Do not expose sensitive kernel information unnecessarily.
  • Document interfaces that userspace applications depend on.
  • Use Debugfs for debugging rather than permanent application interfaces.

19. Common Interview Questions

Q1. What is Procfs?

Procfs is a virtual filesystem that exposes process and kernel-related information through the /proc directory.

Q2. What is Sysfs?

Sysfs is a virtual filesystem that exposes kernel objects and their attributes through the /sys directory.

Q3. What is the main difference between Procfs and Sysfs?

Procfs primarily exposes process and kernel information, whereas Sysfs represents the kernel object hierarchy and device-model attributes.

Q4. Which filesystem is generally preferred for new device attributes?

Sysfs is generally preferred for simple attributes associated with device-model objects.

Q5. What is the purpose of Debugfs?

Debugfs provides interfaces for kernel and driver debugging and does not guarantee a stable userspace ABI.

Q6. Are Procfs and Sysfs normal disk filesystems?

No. They are virtual filesystems that expose kernel-managed information and interfaces.

Q7. Can a user-space program access Procfs and Sysfs?

Yes. Applications can access permitted entries using normal file operations such as open(), read() and write().
