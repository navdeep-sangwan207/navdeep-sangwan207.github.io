2. Introduction to Sysfs

Sysfs is a virtual filesystem provided by the Linux kernel. It exposes information about kernel objects and the Linux device model through a structured directory hierarchy.

Sysfs is normally mounted at: 

/sys

It allows user-space applications and system utilities to inspect selected kernel objects, devices, drivers, buses and their attributes.

Examples of information exposed through Sysfs

  • Device information.
  • Driver associations.
  • Bus information.
  • Device class information.
  • Hardware attributes.
  • Selected configurable device properties.
  • Kernel object relationships.
Sysfs is not a normal disk-based filesystem. Its entries represent kernel objects and attributes rather than ordinary files stored on a disk.

3. Why Is Sysfs Required?

Linux supports many hardware devices and kernel subsystems. A structured mechanism is needed to represent their relationships and expose selected information to user space.

Before Sysfs became established, various interfaces were used to expose kernel information. Sysfs provides a consistent representation of the Linux device model.

Major purposes

  1. Expose kernel object information.
  2. Represent device hierarchy.
  3. Show relationships between devices and drivers.
  4. Provide device attributes.
  5. Support selected device configuration operations.
  6. Allow system utilities to inspect device information.

4. Architecture of Sysfs

Sysfs is closely connected to the Linux device model. The device model represents devices, drivers, buses and classes as kernel objects.

User-Space Applications
↓
Sysfs Filesystem (/sys)
↓
Kernel Object Model (kobject / kset)
↓
Linux Device Model
↓
Devices, Drivers, Buses and Classes

The kernel device model maintains the objects and their relationships. Sysfs provides a filesystem representation of those objects.

User-space applications can inspect the exposed attributes using ordinary file operations.

5. Important Characteristics of Sysfs

Characteristic Description
Virtual filesystem Does not store ordinary file data on disk.
Structured hierarchy Organizes kernel objects into directories.
Device model integration Represents devices, drivers, buses and classes.
Attribute-based interface Exposes object information through attributes.
User-space access Applications can read and write permitted attributes.
Dynamic representation Entries reflect kernel object registration and removal.

6. Understanding the /sys Directory

The /sys directory is the normal mount point of Sysfs. It contains several important directories.

Common Sysfs directories

/sys
├── block
├── bus
├── class
├── dev
├── devices
├── firmware
├── fs
├── kernel
└── module
Directory Purpose
/sys/block Block device information.
/sys/bus Bus types and associated devices and drivers.
/sys/class Device classes such as network and input.
/sys/dev Device-number-based links for registered devices.
/sys/devices Device hierarchy.
/sys/firmware Selected firmware-related information and interfaces.
/sys/fs Kernel filesystem-related interfaces.
/sys/kernel Kernel-related objects and interfaces.
/sys/module Information about loaded and built-in modules.
The exact contents of /sys depend on the kernel configuration, running kernel, hardware and registered devices. Not every system will show identical entries.

7. Devices in Sysfs

The /sys/devices directory represents the device hierarchy maintained by the Linux device model.

It may contain information about:

  • System devices.
  • PCI devices.
  • USB devices.
  • Platform devices.
  • Storage devices.
  • Other registered devices.

Example exploration

ls /sys/devices

To explore further: 

find /sys/devices -maxdepth 2 -type d | head -n 30

The command displays a sample of the device directory hierarchy. The exact results depend on the system.

8. Drivers in Sysfs

The /sys/bus hierarchy provides information about buses and their associated drivers.

For example, the following directory may contain information about PCI drivers: 

/sys/bus/pci/drivers

A driver entry may expose:

  • Driver name.
  • Devices associated with the driver.
  • Driver binding information.
  • Supported attributes.

Explore available buses

ls /sys/bus

Explore PCI drivers, if available

ls /sys/bus/pci/drivers
Driver directories and their attributes depend on the buses and drivers supported by the running kernel.

9. Device Classes in Sysfs

The /sys/class directory groups devices according to their functional class rather than only their physical bus location.

Examples include:

  • Network interfaces.
  • Input devices.
  • LED devices.
  • Thermal devices.
  • Graphics devices.
  • Power supply devices.

Explore device classes

ls /sys/class

Explore network interfaces

ls /sys/class/net

This directory commonly contains symbolic links representing network interfaces.

Inspect an interface

ls -l /sys/class/net

You can inspect attributes of an available interface: 

cat /sys/class/net/lo/operstate

The loopback interface is commonly available, although the exact attributes and output depend on the system.

10. Attributes in Sysfs

An attribute is a file-like representation of information associated with a kernel object.

Attributes are commonly used to expose simple values such as:

  • Device name.
  • Device state.
  • Configuration values.
  • Device identifiers.
  • Selected measurements.

Example

/sys/class/net/lo/mtu

Read the MTU value using: 

cat /sys/class/net/lo/mtu

The result is a numeric value representing the maximum transmission unit configured for that interface.

Read and write attributes

Depending on the attribute and its permissions:

  • Reading retrieves an attribute value.
  • Writing may request a configuration change.
Do not write arbitrary values to Sysfs attributes. Only use documented attributes and valid values. A writable attribute may change device or system behavior.

11. Sysfs and Kernel Objects

Sysfs represents kernel objects through directories and attributes. The central object mechanism is based on the kobject infrastructure.

A kobject provides common object-management facilities, including:

  • Object naming.
  • Reference counting.
  • Parent-child relationships.
  • Sysfs representation.
  • Object lifecycle management.

A kobject is often embedded inside a higher-level kernel structure. It is not normally used as a complete device driver object by itself.

The next lessons examine the Sysfs filesystem and kernel object infrastructure in greater detail.

12. Sysfs Communication Model

Sysfs provides a controlled way for user space to interact with selected kernel attributes.

User Application
↓ Read / Write
Sysfs Attribute
↓
Kernel Attribute Callback
↓
Kernel Object or Device State

When an attribute is read or written, the associated kernel callbacks handle the operation.

A read callback typically formats an attribute value for user space. A write callback parses and validates the supplied value before applying an allowed change.

13. Difference Between Sysfs, Procfs and Debugfs

Feature Sysfs Procfs Debugfs
Mount point /sys /proc /sys/kernel/debug
Main purpose Kernel object and device model representation Process and kernel information and established interfaces Kernel debugging
Organization Structured object hierarchy Process and kernel-oriented entries Developer-defined debugging hierarchy
Typical use Device attributes Process and system information Diagnostic information
Stable userspace ABI Documented interfaces should be maintained Depends on the specific interface Not guaranteed to be stable

When to use each interface

  • Use Sysfs for simple attributes of kernel objects and devices.
  • Use Procfs for established process and kernel interfaces.
  • Use Debugfs for development and debugging information.

14. Practical: Exploring Sysfs in Ubuntu

The following exercises can be performed inside your Ubuntu virtual machine without additional hardware.

Step 1: Verify the Sysfs mount

findmnt /sys

This displays mount information for /sys.

Step 2: List the main directories

ls /sys

Step 3: Explore device classes

ls /sys/class

Step 4: Explore network devices

ls /sys/class/net

Step 5: Read the loopback MTU

cat /sys/class/net/lo/mtu

Step 6: Read loopback operational state

cat /sys/class/net/lo/operstate

Step 7: Inspect block devices

ls /sys/block

Step 8: Explore kernel modules

ls /sys/module | head

Step 9: Inspect a device directory

find /sys/devices -maxdepth 2 -type d | head -n 30

Step 10: Inspect a Sysfs symbolic link

ls -l /sys/class/net
These commands demonstrate that Sysfs exposes information about kernel objects through an organized filesystem hierarchy.

15. Sysfs in Linux Device Driver Development

Sysfs is particularly important in device driver development. A driver can expose selected attributes associated with a device or driver.

Example: Temperature sensor driver

A temperature sensor driver may expose a temperature attribute through an established device subsystem interface. 

/sys/class/thermal/thermal_zone0/temp

The value can be inspected using: 

cat /sys/class/thermal/thermal_zone0/temp

The actual availability and meaning of thermal attributes depend on the hardware, kernel configuration and thermal subsystem.

Other possible driver attributes

  • Device operating state.
  • Sensor measurement.
  • Supported operating mode.
  • Device configuration.
  • Driver-specific status.
For standard hardware functions, prefer an existing kernel subsystem interface such as hwmon, thermal, power supply or LED class rather than inventing a separate device interface.

16. Advantages of Sysfs

  • Provides a structured representation of kernel objects.
  • Exposes device information to user space.
  • Organizes devices, drivers and buses.
  • Supports simple attribute-based communication.
  • Integrates with the Linux device model.
  • Helps user-space utilities inspect device information.
  • Supports device management and configuration through documented attributes.

17. Limitations and Precautions

  • Sysfs is not intended for transferring large amounts of data.
  • Attributes should generally represent simple values.
  • Access permissions must be designed carefully.
  • Writable attributes require strict input validation.
  • Driver data must be synchronized correctly.
  • Kernel objects must be removed safely during teardown.
  • New interfaces should follow documented kernel ABI conventions.
A Sysfs attribute is a user-space interface to kernel functionality. Incorrect write handling or unsafe object lifetime management can create security, stability and data-integrity problems.

18. Lesson Summary

  • Sysfs is a virtual filesystem mounted at /sys.
  • It exposes kernel objects and device-model information.
  • Its hierarchy represents devices, buses, drivers and classes.
  • The /sys/devices directory represents the device hierarchy.
  • The /sys/bus directory represents bus-related objects.
  • The /sys/class directory groups devices by functional class.
  • Attributes provide information about kernel objects.
  • Some attributes support controlled write operations.
  • Sysfs is closely integrated with the kobject infrastructure.
  • Sysfs, Procfs and Debugfs serve different purposes.
