1. Linux Device Driver Fundamentals

Q1. What is a device driver?

Answer: A device driver is software that enables the operating system to communicate with and control a hardware device. In Linux, many drivers run in kernel space and interact with hardware through kernel subsystems and device-specific interfaces.

Q2. Why are device drivers required?

Answer: Hardware devices have different registers, communication protocols and operating requirements. Drivers provide a standardized software interface so applications and kernel subsystems can use those devices.

Q3. What is the Linux kernel?

Answer: The Linux kernel is the core of the operating system. It manages processes, memory, scheduling, device access, filesystems, networking and system calls.

Q4. What is the difference between user space and kernel space?

Answer: User space is where ordinary applications execute with restricted privileges. Kernel space is where the kernel and kernel modules execute with privileged access to kernel resources and hardware interfaces.

Q5. What are the major types of Linux device drivers?

Answer:

  • Character device drivers.
  • Block device drivers.
  • Network device drivers.
  • Platform drivers.
  • Bus-specific drivers such as I2C and SPI drivers.

Q6. What is a loadable kernel module?

Answer: A loadable kernel module is code that can be loaded into or removed from a running Linux kernel without rebuilding or rebooting the entire kernel, provided the module is compatible with that kernel.

Q7. What is the difference between a built-in driver and a loadable module?

Answer: A built-in driver is compiled into the kernel image. A loadable module is a separate module that can be inserted and removed at runtime.

2. Kernel Module Programming

Q8. What are module_init() and module_exit()?

Answer: module_init() specifies the initialization function. module_exit() specifies the cleanup function for a loadable module.

Q9. What is the purpose of MODULE_LICENSE()?

Answer: It declares the module's license metadata. License declarations affect kernel compatibility and whether the module is considered GPL-compatible for certain kernel interfaces.

Q10. How do you compile a Linux kernel module?

Answer: A typical external-module Makefile uses the kernel build system.

obj-m += hello.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Compile using:

make

Q11. Which commands are used to load and unload modules?

Answer:

sudo insmod hello.ko
lsmod
sudo rmmod hello
modinfo hello.ko

Q12. What is the difference between insmod and modprobe?

Answer: insmod inserts a specified module file directly. modprobe uses module metadata and dependency information to load modules and their dependencies.

Q13. How do you print messages from a kernel module?

Answer: Use kernel logging functions such as pr_info(), pr_err(), pr_warn() and pr_debug(). Inspect messages using dmesg or the system journal.

Q14. What is vermagic?

Answer: Vermagic is module metadata describing kernel build characteristics used for compatibility checking when loading a module.

3. Character Device Drivers

Q15. What is a character device?

Answer: A character device provides byte-oriented input/output through operations such as open(), read(), write() and release().

Q16. What are major and minor numbers?

Answer: The major number identifies the device driver or device-number range associated with it. The minor number distinguishes individual devices or instances handled by that driver.

Q17. What is dev_t?

Answer: dev_t is a kernel type used to represent a device number containing major and minor components.

Q18. What is alloc_chrdev_region()?

Answer: It dynamically allocates a range of character-device numbers.

Q19. What is struct cdev?

Answer: struct cdev represents a character device within the kernel and connects device numbers with file operations.

Q20. What is cdev_add()?

Answer: It adds a character device to the kernel, making it available for operations associated with its registered device numbers. It does not itself create a /dev device node.

Q21. What is the purpose of file_operations?

Answer: struct file_operations contains function pointers for operations supported by a device, such as open, read, write, release, unlocked_ioctl and poll.

Q22. What is the difference between read() and write() in a driver?

Answer: read() transfers data from kernel space to user space. write() transfers data from user space to kernel space.

Q23. Why are copy_to_user() and copy_from_user() used?

Answer: They transfer data safely across the user/kernel address-space boundary. They return the number of bytes that could not be copied, so the driver must check the return value.

Q24. What is the purpose of device_create()?

Answer: It creates a device object associated with a device class. With the appropriate device-management support, this normally leads to a device node being created by userspace device management.

4. Block and Network Device Drivers

Q25. What is a block device?

Answer: A block device handles data in addressable blocks and supports random access. Storage devices such as hard disks and SSDs are common examples.

Q26. What is a network device driver?

Answer: It connects network hardware to the Linux networking subsystem and handles operations such as packet transmission and reception.

5. IOCTL Programming

Q28. What is IOCTL?

Answer: IOCTL means input/output control. It provides a mechanism for applications to send device-specific control commands to a driver.

Q29. What are _IO, _IOR, _IOW and _IOWR?

Answer:

  • _IO: command without an encoded data-transfer direction.
  • _IOR: command describing data read from the driver.
  • _IOW: command describing data written to the driver.
  • _IOWR: command describing bidirectional data transfer.

Q30. What is unlocked_ioctl()?

Answer: It is the common ioctl callback in struct file_operations for handling device-specific control requests.

Q31. Why should IOCTL commands be validated?

Answer: Validation prevents unsupported commands, invalid parameters and unsafe memory access from causing incorrect device behavior or kernel faults.

6. Procfs and Sysfs

Q32. What is procfs?

Answer: procfs is a virtual filesystem, usually mounted at /proc, that exposes process and kernel information and selected control interfaces.

Q33. What is sysfs?

Answer: sysfs is a virtual filesystem, usually mounted at /sys, that exposes kernel objects, devices, drivers and their attributes.

Q34. What is the difference between procfs and sysfs?

Q35. What is debugfs?

Answer: debugfs is a filesystem intended for kernel and driver debugging. It is not intended as a stable userspace ABI.

7. Device Tree and Platform Drivers

Q36. What is Device Tree?

Answer: Device Tree is a data structure that describes hardware components, their resources and connections to the operating system. It is widely used on embedded Linux systems.

Q37. What is a Device Tree Source file?

Answer: A Device Tree Source file uses the .dts extension and describes hardware in a human-readable format. Included files commonly use .dtsi.

Q38. What is a platform driver?

Answer: A platform driver manages devices that are typically integrated into a system-on-chip and are not discovered through an enumerating bus such as USB or PCI.

Q39. What are probe() and remove()?

Answer: probe() initializes a device when it is matched with a driver. remove() releases resources when the device is detached or the driver is removed.

Q40. What is the purpose of of_match_table?

Answer: It provides Device Tree compatible strings used to match a device with a driver.

8. GPIO, I2C and SPI Drivers

Q41. What is GPIO?

Answer: General Purpose Input/Output is a programmable digital pin that can be configured as an input or output.

Q42. What is the modern Linux GPIO API?

Answer: The descriptor-based GPIO consumer API uses struct gpio_desc and functions such as gpiod_get(), gpiod_put() and gpiod_set_value_cansleep().

Q43. What is I2C?

Answer: I2C is a synchronous serial bus using SDA and SCL lines. It commonly supports multiple addressed devices on the same bus.

Q44. What is an I2C address?

Answer: It identifies a target device on an I2C bus. Many devices use 7-bit addresses, although 10-bit addressing is also supported.

Q45. What is SPI?

Answer: SPI is a synchronous serial interface commonly using SCLK, MOSI, MISO and chip-select signals.

Q46. What are CPOL and CPHA?

Answer: CPOL defines the clock's idle polarity. CPHA defines the clock edge on which data is sampled relative to the clock phase.

9. Interrupts and Concurrency

Q48. What is an interrupt?

Answer: An interrupt is an event that causes the processor to suspend its current execution flow and invoke an interrupt-handling mechanism.

Q49. What is an IRQ?

Answer: IRQ means Interrupt Request. It identifies an interrupt source or interrupt line managed by the system's interrupt controller.

Q50. What is request_irq()?

Answer: It registers an interrupt handler for a specified IRQ.

Q51. What is the difference between top half and bottom half?

Answer: The top half performs urgent interrupt-context work. Deferred work is performed later using mechanisms such as threaded IRQs, workqueues or tasklets where appropriate.

Q52. What is a workqueue?

Answer: A workqueue schedules deferred work in process context, where sleeping is generally permitted subject to the specific context and locking rules.

Q53. What is a mutex?

Answer: A mutex is a sleeping lock used to protect shared data when the caller is allowed to sleep.

Q54. What is a spinlock?

Answer: A spinlock protects shared data using busy waiting. It is suitable for short critical sections and contexts where sleeping is not allowed.

Q55. What is a race condition?

Answer: A race condition occurs when concurrent operations access shared data and the result depends on their execution timing or ordering.

Q56. What is a wait queue?

Answer: A wait queue allows tasks to sleep until a condition or event becomes true and another execution context wakes them.

10. Kernel Memory Management

Q57. What is kmalloc()?

Answer: kmalloc() allocates physically contiguous kernel memory suitable for many small and medium allocations.

Q58. What is kzalloc()?

Answer: kzalloc() allocates kernel memory and initializes it to zero.

Q59. What is vmalloc()?

Answer: vmalloc() allocates virtually contiguous memory that may not be physically contiguous.

Q60. What is the difference between kmalloc() and vmalloc()?

Answer: kmalloc() provides physically contiguous memory, whereas vmalloc() provides virtually contiguous memory. Their suitability depends on the device and API requirements.

Q61. What is DMA?

Answer: Direct Memory Access allows a device to transfer data to or from memory without requiring the CPU to copy every data item. Linux drivers should use the kernel DMA mapping API rather than assuming CPU virtual or physical addresses are directly usable by hardware.

11. Debugging and Kernel Errors

Q62. What is a kernel oops?

Answer: A kernel oops is a report of a serious kernel error, such as an invalid memory access. The kernel may continue running in a degraded state, depending on the fault.

Q63. What is a kernel panic?

Answer: A kernel panic is a critical failure where the kernel cannot safely continue execution.

Q64. How do you debug a kernel module?

Answer: Common methods include:

  • pr_info(), pr_err() and dynamic debug.
  • dmesg and journalctl.
  • debugfs.
  • Kernel logs and call traces.
  • Kernel sanitizers and lockdep.
  • KGDB or other supported debugging tools.

Q65. What is KASAN?

Answer: Kernel Address Sanitizer detects memory-safety errors such as out-of-bounds accesses and use-after-free bugs in supported configurations.

Q66. What is KCSAN?

Answer: Kernel Concurrency Sanitizer detects data races in supported kernel configurations.

Q67. What is lockdep?

Answer: Lock dependency validation detects potential locking problems such as lock-order inversions and certain incorrect locking patterns.

12. Practical Scenario-Based Interview Questions

Q68. Your kernel module compiles successfully but fails to load. What will you check?

Answer:

  1. Check the exact error from insmod.
  2. Inspect dmesg for kernel messages.
  3. Verify kernel version compatibility and vermagic.
  4. Check unresolved symbols and module dependencies.
  5. Check module signature enforcement where applicable.
  6. Inspect initialization code and resource allocation failures.

Q69. A character device node is missing from /dev. What will you investigate?

Answer:

  • Check whether the module loaded successfully.
  • Check device-number registration.
  • Check cdev_add().
  • Check class_create() and device_create() if used.
  • Inspect kernel logs and userspace device-management behavior.

Q70. A read() system call returns no data. What could be the reason?

Answer: Possible reasons include an empty device buffer, incorrect file offset handling, an incorrect read implementation, a buffer-copy error or end-of-file behavior.

Q71. Your driver crashes when two processes access it simultaneously. What will you do?

Answer: Inspect shared data access, identify race conditions and use an appropriate synchronization mechanism such as mutexes, spinlocks or atomic operations based on execution context.

Q72. Why should a driver avoid sleeping inside an interrupt handler?

Answer: A hard interrupt handler runs in atomic context. Sleeping operations are not permitted there. Defer work to an appropriate threaded or process-context mechanism.

Q73. An I2C sensor is not detected. What will you check?

Answer: Verify power, ground, SDA/SCL wiring, pull-up resistors, address, bus number, pin configuration, Device Tree description and driver matching.

Q74. An SPI device returns incorrect values. What will you check?

Answer: Check SPI mode, clock frequency, chip-select polarity, word length, transfer length, wiring and the peripheral's command protocol.

Q75. How would you prevent a memory leak in a driver?

Answer: Track every allocation, release resources on all error paths, use managed resource APIs where appropriate and verify cleanup during module removal and device detach.

13. Coding Interview Questions

Q77. How do you allocate and release kernel memory?

void *buffer;

buffer = kmalloc(1024, GFP_KERNEL);

if (!buffer)
    return -ENOMEM;

/* Use the allocated buffer */

kfree(buffer);

Q78. How do you protect a shared buffer using a mutex?

static DEFINE_MUTEX(buffer_lock);

/* In a process-context operation */
mutex_lock(&buffer_lock);

/* Access shared buffer */

mutex_unlock(&buffer_lock);

Q79. How do you register a character device number dynamically?

dev_t dev;

if (alloc_chrdev_region(&dev, 0, 1, "demo") < 0)
    return -1;

/* Save and use dev */

unregister_chrdev_region(dev, 1);

This is a simplified registration fragment; a complete driver must also initialize and add its cdev and handle cleanup correctly.

Q80. How do you transfer data from kernel space to user space?

if (copy_to_user(user_buffer, kernel_buffer, count))
    return -EFAULT;

The complete read implementation must also handle file offsets, valid byte counts and end-of-file behavior.

14. Advanced Interview Topics

Q81. What is the Linux device model?

Answer: It is the kernel framework that represents devices, drivers, buses, classes and their relationships. It supports device discovery, driver binding, resource management and userspace representation.

Q82. What is deferred probing?

Answer: A driver can return -EPROBE_DEFER from probe() when a required dependency is not ready. The kernel can retry probing later.

Q83. What is devm_kzalloc()?

Answer: It allocates zero-initialized device-managed memory that is automatically released when the associated device resources are detached.

Q84. What is the difference between request_irq() and devm_request_irq()?

Answer: request_irq() requires explicit release using free_irq(). devm_request_irq() associates IRQ resource cleanup with the device-managed resource lifecycle.

Q85. What is poll() in a device driver?

Answer: The poll file operation allows applications to wait for device readiness using interfaces such as poll(), select() and epoll().

Q86. What is DMA coherent memory?

Answer: Coherent DMA memory provides CPU and device views that remain coherent according to the DMA API's guarantees. It is allocated using suitable DMA APIs such as dma_alloc_coherent().

Q87. What is the Linux IIO subsystem?

Answer: Industrial I/O (IIO) provides a framework for ADCs, DACs, sensors and other measurement devices. It avoids creating unnecessary custom interfaces for standard measurement hardware.

Q88. What is the input subsystem?

Answer: It provides a standard framework for input devices such as keyboards, mice, touchscreens and buttons.

Q89. What is the difference between a bus driver and a device driver?

Answer: A bus driver manages the bus controller and its transactions or enumeration. A device driver manages a peripheral's functionality through the relevant bus or subsystem APIs.

Q90. What is kernel ABI?

Answer: An ABI defines binary-level interfaces. Linux does not promise a stable in-kernel driver ABI across kernel versions, so external modules may need adaptation and rebuilding for different kernels.
