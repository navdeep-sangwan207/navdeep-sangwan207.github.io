1. Introduction to Interrupts

An interrupt is a signal that informs the CPU that an event needs attention. Instead of continuously checking a device's status, the processor can respond when the device generates an interrupt.

Interrupts are commonly generated by:

  • GPIO pins and external hardware.
  • Timers.
  • UART communication controllers.
  • Network interface controllers.
  • Storage controllers.
  • ADC and other peripheral devices.

4. Types of Interrupts

4.1 Hardware Interrupt

Generated by an external hardware device or interrupt controller.

4.2 Software Interrupt

Generated by software mechanisms, such as system calls or architecture-specific software interrupt instructions. Modern Linux system-call entry mechanisms are architecture-dependent.

4.3 Shared Interrupt

Multiple devices can share an IRQ line when the hardware and interrupt controller support it. Each registered handler must determine whether its own device generated the interrupt.

4.4 Edge-Triggered Interrupt

Triggered by a signal transition, such as a rising or falling edge.

4.5 Level-Triggered Interrupt

Triggered while the interrupt signal remains at its active level.

5. Linux Interrupt Handler

The Linux kernel provides the request_irq() function to register an interrupt handler.

int request_irq(
    unsigned int irq,
    irq_handler_t handler,
    unsigned long flags,
    const char *name,
    void *dev
);
ParameterDescription
irqInterrupt number.
handlerInterrupt service routine.
flagsIRQ configuration flags.
nameInterrupt name shown in system information.
devDevice-specific identifier, especially important for shared IRQs.

To release an interrupt:

free_irq(irq, dev);

6. Interrupt Handler Prototype

static irqreturn_t my_interrupt_handler(
    int irq,
    void *dev_id)
{
    /* Identify and acknowledge device event */

    return IRQ_HANDLED;
}

Return values:

  • IRQ_HANDLED: The interrupt was handled by this device.
  • IRQ_NONE: The interrupt was not generated by this device.
  • IRQ_WAKE_THREAD: Requests execution of the threaded IRQ handler when one is registered.

7. Top Half and Bottom Half

Interrupt processing is commonly divided into two stages.

Top Half

  • Executes in interrupt context.
  • Should perform minimal processing.
  • Identifies and acknowledges the device interrupt.
  • Schedules deferred work when required.
  • Must not sleep.

Bottom Half

  • Performs deferred processing.
  • Can handle operations that should not run in the hard IRQ handler.
  • Implementation options include workqueues, threaded IRQs and tasklets in applicable kernel code.
Tasklets are a legacy mechanism and are deprecated in modern Linux kernel development. Prefer threaded IRQs or workqueues for new drivers where appropriate.

9. Project Introduction

We will develop a character driver that receives a software-triggered test event through a kernel work item. The work item updates an event counter and wakes a user-space process waiting on a wait queue.

This project demonstrates the event-notification architecture used by interrupt-driven drivers.

This virtual project does not claim to generate a physical hardware IRQ. It simulates the event flow using a delayed work item so it can be tested inside a VirtualBox Ubuntu environment. A real hardware IRQ requires a device and a valid interrupt resource.

11. Complete Interrupt Event Character Driver

Create the source file:

nano interrupt_driver.c

File: interrupt_driver.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>
#include <linux/uaccess.h>
#include <linux/wait.h>
#include <linux/workqueue.h>
#include <linux/mutex.h>
#include <linux/poll.h>

#define DEVICE_NAME "irq_event"
#define CLASS_NAME  "irq_event_class"

static dev_t dev_number;
static struct cdev irq_cdev;
static struct class *irq_class;
static struct device *irq_device;

static DECLARE_WAIT_QUEUE_HEAD(event_wait_queue);
static DEFINE_MUTEX(event_lock);

static struct delayed_work event_work;

static unsigned int event_count;
static bool event_available;

/* Deferred event processing */
static void event_work_handler(struct work_struct *work)
{
    mutex_lock(&event_lock);

    event_count++;
    event_available = true;

    pr_info("irq_event: event count = %u\n",
            event_count);

    mutex_unlock(&event_lock);

    wake_up_interruptible(&event_wait_queue);
}

/* Device open */
static int irq_open(struct inode *inode,
                    struct file *file)
{
    pr_info("irq_event: device opened\n");
    return 0;
}

/* Device read */
static ssize_t irq_read(struct file *file,
                        char __user *buffer,
                        size_t length,
                        loff_t *offset)
{
    char data[64];
    int len;
    unsigned int count;
    int ret;

    if (length == 0)
        return 0;

    ret = wait_event_interruptible(
        event_wait_queue,
        READ_ONCE(event_available)
    );

    if (ret)
        return ret;

    mutex_lock(&event_lock);

    count = event_count;
    event_available = false;

    mutex_unlock(&event_lock);

    len = scnprintf(
        data,
        sizeof(data),
        "Event count: %u\n",
        count
    );

    if (length < len)
        return -EINVAL;

    if (copy_to_user(buffer, data, len))
        return -EFAULT;

    return len;
}

/* Device poll */
static __poll_t irq_poll(struct file *file,
                         poll_table *wait)
{
    __poll_t mask = 0;

    poll_wait(file, &event_wait_queue, wait);

    if (READ_ONCE(event_available))
        mask |= EPOLLIN | EPOLLRDNORM;

    return mask;
}

/* Device release */
static int irq_release(struct inode *inode,
                       struct file *file)
{
    pr_info("irq_event: device closed\n");
    return 0;
}

/* File operations */
static const struct file_operations irq_fops = {
    .owner = THIS_MODULE,
    .open = irq_open,
    .read = irq_read,
    .poll = irq_poll,
    .release = irq_release,
};

/* Module initialization */
static int __init irq_event_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev_number,
        0,
        1,
        DEVICE_NAME
    );

    if (ret)
        return ret;

    cdev_init(&irq_cdev, &irq_fops);
    irq_cdev.owner = THIS_MODULE;

    ret = cdev_add(&irq_cdev, dev_number, 1);

    if (ret)
        goto unregister_region;

    irq_class = class_create(CLASS_NAME);

    if (IS_ERR(irq_class)) {
        ret = PTR_ERR(irq_class);
        goto delete_cdev;
    }

    irq_device = device_create(
        irq_class,
        NULL,
        dev_number,
        NULL,
        DEVICE_NAME
    );

    if (IS_ERR(irq_device)) {
        ret = PTR_ERR(irq_device);
        goto destroy_class;
    }

    INIT_DELAYED_WORK(
        &event_work,
        event_work_handler
    );

    /*
     * Generate one demonstration event
     * after module initialization.
     */
    schedule_delayed_work(
        &event_work,
        msecs_to_jiffies(2000)
    );

    pr_info("irq_event: driver initialized\n");

    return 0;

destroy_class:
    class_destroy(irq_class);

delete_cdev:
    cdev_del(&irq_cdev);

unregister_region:
    unregister_chrdev_region(dev_number, 1);

    return ret;
}

/* Module cleanup */
static void __exit irq_event_exit(void)
{
    cancel_delayed_work_sync(&event_work);

    device_destroy(irq_class, dev_number);
    class_destroy(irq_class);

    cdev_del(&irq_cdev);
    unregister_chrdev_region(dev_number, 1);

    pr_info("irq_event: driver removed\n");
}

module_init(irq_event_init);
module_exit(irq_event_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Interrupt Event Character Driver Demonstration");
MODULE_VERSION("1.0");
Kernel compatibility: This example uses the modern class_create("name") API and __poll_t poll return type. Older kernels may require different declarations. Check the target kernel headers before compiling.

12. Understanding the Driver

12.1 Wait Queue

static DECLARE_WAIT_QUEUE_HEAD(event_wait_queue);

The wait queue allows a process to sleep until an event becomes available.

12.2 Deferred Work

INIT_DELAYED_WORK(
    &event_work,
    event_work_handler
);

This initializes the delayed work item. The handler executes in workqueue context, where sleeping operations are permitted.

12.3 Wake Up the User Process

wake_up_interruptible(&event_wait_queue);

This wakes processes waiting for an event.

12.4 Blocking Read

wait_event_interruptible(
    event_wait_queue,
    READ_ONCE(event_available)
);

The user-space read operation sleeps until the event condition becomes true or the wait is interrupted by a signal.

12.5 Poll Support

The poll() file operation allows applications to wait for data using interfaces such as poll() or select().

17. Test with a C User-Space Program

Create a test application:

nano test_irq.c

File: test_irq.c

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>

int main(void)
{
    int fd;
    char buffer[64];
    ssize_t bytes;

    fd = open("/dev/irq_event", O_RDONLY);

    if (fd < 0) {
        perror("open");
        return 1;
    }

    printf("Waiting for event...\n");

    bytes = read(fd, buffer, sizeof(buffer) - 1);

    if (bytes < 0) {
        perror("read");
        close(fd);
        return 1;
    }

    buffer[bytes] = '\0';

    printf("Received: %s", buffer);

    close(fd);

    return 0;
}

18. Real Hardware IRQ Registration

For a real device, the IRQ number should normally be obtained from a platform, PCI, USB or other device resource rather than hard-coded.

For a platform device, a common approach is:

int irq;

irq = platform_get_irq(pdev, 0);

if (irq < 0)
    return irq;

ret = devm_request_irq(
    &pdev->dev,
    irq,
    my_interrupt_handler,
    0,
    "my_device_irq",
    my_device
);

if (ret)
    return ret;

The exact resource source depends on the device bus and driver architecture.

A real interrupt handler must identify and acknowledge the device interrupt correctly. The device must also be configured to generate the interrupt. Merely registering an IRQ does not create hardware events.

19. Threaded Interrupt Handler

Linux supports threaded IRQs using request_threaded_irq().

static irqreturn_t my_irq_top(
    int irq,
    void *dev_id)
{
    /*
     * Check interrupt status.
     * Acknowledge or mask the device
     * as required by its hardware design.
     */

    return IRQ_WAKE_THREAD;
}

static irqreturn_t my_irq_thread(
    int irq,
    void *dev_id)
{
    /*
     * Perform deferred processing.
     * Sleeping operations are permitted
     * in this threaded context.
     */

    return IRQ_HANDLED;
}

Registration:

ret = request_threaded_irq(
    irq,
    my_irq_top,
    my_irq_thread,
    IRQF_ONESHOT,
    "my_device_irq",
    dev_id
);

IRQF_ONESHOT keeps the interrupt line masked while the threaded handler runs, where supported by the IRQ flow.

21. VirtualBox Testing Limitations

The demonstration project uses delayed work, not a physical hardware interrupt. It can be compiled and tested in Ubuntu running inside VirtualBox.

To practise real IRQ handling, use:

  • A compatible embedded Linux development board.
  • A GPIO pin connected to an external interrupt source.
  • A correct Device Tree interrupt configuration.
  • A driver that obtains and registers the actual IRQ resource.

24. Lesson Summary

  • Interrupts notify the CPU about hardware events.
  • Linux provides IRQ registration and management APIs.
  • Hard IRQ handlers should execute quickly and must not sleep.
  • Deferred processing can use workqueues or threaded IRQs.
  • Wait queues allow user-space processes to wait for driver events.
  • Character drivers can expose event notifications to applications.
  • Real hardware IRQ testing requires a physical device and a valid IRQ resource.
