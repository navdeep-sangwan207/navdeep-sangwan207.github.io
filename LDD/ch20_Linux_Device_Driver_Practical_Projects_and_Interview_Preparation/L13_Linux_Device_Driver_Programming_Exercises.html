Lesson: L13 – Linux Device Driver Programming Exercises
Level: Beginner to Advanced
Practice Type: Programming, Debugging and Driver Development

1. Introduction

This lesson provides a structured set of practical exercises to strengthen Linux device driver programming skills.

The exercises cover:

  • Linux kernel modules.
  • Character device drivers.
  • Kernel memory management.
  • File operations.
  • IOCTL interfaces.
  • Procfs and sysfs.
  • GPIO, I2C and SPI.
  • Interrupt handling.
  • Synchronization and debugging.

2. Exercise Environment

Recommended environment:

  • Ubuntu Linux.
  • GCC compiler.
  • Linux kernel headers matching the running kernel.
  • GNU Make.
  • Terminal and text editor.
  • VirtualBox or a physical Linux machine.

Install basic development packages:

sudo apt update

sudo apt install build-essential linux-headers-$(uname -r)

Check the kernel version:

uname -r

Check the compiler:

gcc --version
make --version

3. Exercise Set A – Linux Kernel Modules

Exercise 1: Hello World Kernel Module

Objective: Create a basic kernel module.

Requirements:

  • Implement module_init().
  • Implement module_exit().
  • Print messages using pr_info().
  • Load and unload the module.

Expected result: Initialization and cleanup messages appear in kernel logs.

Exercise 2: Module Parameters

Objective: Pass parameters to a kernel module.

Requirements:

  • Define an integer parameter.
  • Define a string parameter.
  • Use module_param().
  • Display values during module initialization.

Hint:

module_param(value, int, 0644);
module_param(name, charp, 0644);

Exercise 3: Module Information

Display module information using modinfo and inspect loaded modules using lsmod.

lsmod
modinfo hello.ko
sudo insmod hello.ko
sudo rmmod hello

Exercise 4: Module Dependency

Create two kernel modules where one module exports a function using EXPORT_SYMBOL_GPL() and another module uses it.

4. Exercise Set B – Character Device Drivers

Exercise 5: Dynamic Major and Minor Allocation

Write a module that allocates a device number using alloc_chrdev_region() and releases it during cleanup.

Exercise 6: Character Device Registration

Implement:

  • struct cdev
  • cdev_init()
  • cdev_add()
  • cdev_del()
  • unregister_chrdev_region()

Exercise 7: Device Node Creation

Create a character device with a device class and device_create(). Verify the device node under /dev.

Exercise 8: Open and Release Operations

Implement open() and release() callbacks and print messages whenever the device is opened or closed.

Exercise 9: Character Driver Read Operation

Implement read() to transfer data from a kernel buffer to user space using copy_to_user().

Exercise 10: Character Driver Write Operation

Implement write() to receive data from user space using copy_from_user(). Validate buffer length and handle errors.

Exercise 11: Combined Read and Write Driver

Create a memory-backed character driver supporting open, read, write and release operations.

5. Exercise Set C – Kernel Memory Management

Exercise 12: kmalloc() and kfree()

Allocate memory using kmalloc() and release it using kfree(). Handle allocation failure.

Exercise 13: kzalloc()

Allocate a zero-initialized buffer using kzalloc() and verify its initial contents.

Exercise 14: vmalloc()

Study vmalloc() and vfree(). Compare virtually contiguous allocations with physically contiguous kmalloc allocations.

Exercise 15: Memory Leak Prevention

Create a module with multiple allocation paths. Ensure every successful allocation is released on every error and cleanup path.

6. Exercise Set D – IOCTL Programming

Exercise 16: Basic IOCTL Commands

Implement the following commands:

  • Clear the device buffer.
  • Get buffer size.
  • Set a configuration value.
  • Get a configuration value.

Exercise 17: IOCTL Data Transfer

Pass a structure between user space and kernel space using copy_to_user() and copy_from_user().

Exercise 18: IOCTL Validation

Validate command numbers, input ranges and pointer access. Return suitable negative error codes for invalid requests.

7. Exercise Set E – Procfs and Sysfs

Exercise 19: Procfs Interface

Create a /proc entry and implement read functionality using struct proc_ops and proc_create().

Exercise 20: Procfs Read/Write

Extend the procfs interface to accept user input and display the stored value.

Exercise 21: Sysfs Attribute

Create a read-only sysfs attribute using DEVICE_ATTR_RO() and a show callback.

Exercise 22: Read/Write Sysfs Attribute

Implement show() and store() callbacks for a configurable device value.

8. Exercise Set F – Synchronization

Exercise 23: Mutex

Protect a shared device buffer using mutex_lock() and mutex_unlock().

Exercise 24: Spinlock

Protect a shared counter using spin_lock() and spin_unlock(). Study the restrictions on sleeping while holding a spinlock.

Exercise 25: Atomic Variables

Implement a shared counter using atomic_t and compare its behavior with a mutex-protected counter.

Exercise 26: Wait Queue

Implement a blocking read operation using wait_event_interruptible() and wake_up_interruptible().

Exercise 27: Concurrent Access

Run multiple user-space processes against the same character device and verify that shared data remains consistent.

9. Exercise Set G – GPIO Drivers

Exercise 28: GPIO Input

Write a driver that obtains a GPIO descriptor using gpiod_get() and reads an input pin.

Exercise 29: GPIO Output

Control an LED using gpiod_direction_output() and gpiod_set_value_cansleep() where appropriate.

Exercise 30: GPIO Button

Read a push-button input and handle the active-low or active-high configuration correctly.

Exercise 31: GPIO Interrupt

Convert a GPIO descriptor to an IRQ using gpiod_to_irq() and register an interrupt handler.

10. Exercise Set H – I2C Drivers

Exercise 32: I2C Device Detection

Use i2cdetect and i2c-tools to identify a connected I2C device on a supported hardware board.

Exercise 33: I2C Driver Registration

Implement struct i2c_driver with probe and remove callbacks.

Exercise 34: I2C Register Read

Read a device register using an appropriate SMBus helper or i2c_transfer().

Exercise 35: I2C Register Write

Write a configuration value to a sensor register and verify its effect.

Exercise 36: Temperature Sensor Driver

Implement an I2C driver for a temperature sensor and expose its reading using the appropriate subsystem interface.

11. Exercise Set I – SPI Drivers

Exercise 37: SPI Driver Registration

Implement a struct spi_driver with Device Tree matching.

Exercise 38: SPI Read and Write

Use spi_message, spi_transfer and spi_sync() to communicate with a peripheral.

Exercise 39: SPI ADC Driver

Read a conversion result from an MCP3008 ADC and calculate the corresponding input voltage.

Exercise 40: SPI Mode Configuration

Study CPOL, CPHA, SPI modes and maximum clock-frequency configuration.

12. Exercise Set J – Interrupt Handling

Exercise 41: IRQ Registration

Register a hardware interrupt using request_irq() or devm_request_irq() with a valid device resource.

Exercise 42: Interrupt Counter

Maintain a counter that increments when the device generates an interrupt. Use suitable synchronization.

Exercise 43: Threaded Interrupt

Implement request_threaded_irq() and divide interrupt handling between the primary and threaded handlers.

Exercise 44: Deferred Processing

Schedule a work item from an interrupt handler and process the event in workqueue context.

13. Exercise Set K – Debugging and Testing

Exercise 45: printk and pr_info

Add useful kernel log messages and inspect them using dmesg.

Exercise 46: Dynamic Debug

Enable dynamic debug for selected source files or modules.

Exercise 47: Debugfs

Create a debugfs entry to inspect internal driver state.

Exercise 48: Kernel Oops Analysis

Study a controlled kernel fault in a disposable virtual machine or test kernel. Identify the faulting instruction and call trace.

Exercise 49: Kernel Sanitizers

Study available debugging configurations such as KASAN, KCSAN, lockdep and UBSAN.

Exercise 50: Driver Stress Testing

Repeatedly open, read, write and close the device while monitoring kernel logs and resource usage.

14. Exercise Set L – Complete Projects

Project 1: Memory-Based Character Driver

Implement dynamic registration, read/write, IOCTL, synchronization and a user-space application.

Project 2: GPIO LED and Button Driver

Control an LED and detect button events using GPIO descriptors.

Project 3: I2C Temperature Monitoring

Communicate with a temperature sensor and expose readings through an appropriate kernel subsystem interface.

Project 4: SPI ADC Driver

Read ADC channels and provide voltage measurements through the IIO subsystem.

Project 5: Interrupt-Based Event Driver

Implement hardware event handling, deferred processing, wait queues and user-space notification.

16. Recommended Practice Sequence

  1. Complete Exercises 1–4 before starting character drivers.
  2. Complete Exercises 5–11 to understand character-device programming.
  3. Complete Exercises 12–18 for memory management and IOCTL.
  4. Complete Exercises 19–27 for kernel interfaces and synchronization.
  5. Complete Exercises 28–40 when suitable hardware is available.
  6. Complete Exercises 41–50 for interrupts, debugging and testing.
  7. Build all five complete projects independently.

17. Important Development Rules

  • Never test unstable kernel modules on a production machine.
  • Use a virtual machine or disposable development board for experiments.
  • Keep kernel headers and running kernel versions compatible.
  • Always inspect dmesg after loading and unloading a module.
  • Check every allocation and API return value.
  • Do not sleep in atomic context.
  • Follow the relevant hardware datasheet and kernel subsystem documentation.
  • Prefer established kernel subsystems such as IIO, input and GPIO over unnecessary custom interfaces.
