1. Introduction to Procfs

Procfs is a virtual filesystem provided by the Linux kernel. It is normally mounted at /proc.

Unlike a conventional filesystem, procfs primarily exposes information generated dynamically by the kernel and its subsystems.

Examples of standard procfs entries include:

  • /proc/cpuinfo – CPU information.
  • /proc/meminfo – Memory statistics.
  • /proc/uptime – System uptime.
  • /proc/modules – Loaded kernel modules.
  • /proc/devices – Registered device major numbers.

A kernel module can create its own procfs entry to expose information or provide a simple user-space control interface.

2. Project Objectives

  • Understand the purpose of procfs.
  • Create a procfs entry using proc_create().
  • Implement read and write callbacks.
  • Understand the modern struct proc_ops interface.

  • Remove procfs entries safely when unloading the module.

4.1 Modern proc_ops Structure

static const struct proc_ops my_proc_ops = {
    .proc_read  = my_proc_read,
    .proc_write = my_proc_write,
};
Kernel version note: Modern Linux kernels use struct proc_ops. Older kernel versions used struct file_operations for procfs callbacks. This project targets kernels supporting proc_ops.

6. Complete Procfs Driver Source Code

Create the source file:

nano proc_driver.c

File: proc_driver.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/proc_fs.h>
#include <linux/uaccess.h>
#include <linux/mutex.h>
#include <linux/string.h>
#include <linux/errno.h>

#define PROC_NAME "my_driver"
#define BUFFER_SIZE 256

static struct proc_dir_entry *proc_entry;

static char device_message[BUFFER_SIZE] =
    "Linux Procfs Driver Ready\n";

static DEFINE_MUTEX(proc_mutex);

/* Procfs read callback */
static ssize_t my_proc_read(
    struct file *file,
    char __user *user_buffer,
    size_t count,
    loff_t *offset)
{
    ssize_t ret;

    if (mutex_lock_interruptible(&proc_mutex))
        return -ERESTARTSYS;

    ret = simple_read_from_buffer(
        user_buffer,
        count,
        offset,
        device_message,
        strlen(device_message)
    );

    mutex_unlock(&proc_mutex);

    return ret;
}

/* Procfs write callback */
static ssize_t my_proc_write(
    struct file *file,
    const char __user *user_buffer,
    size_t count,
    loff_t *offset)
{
    size_t bytes_to_copy;
    char temporary_buffer[BUFFER_SIZE];
    ssize_t ret;

    if (count == 0)
        return 0;

    bytes_to_copy = min(count, (size_t)BUFFER_SIZE - 1);

    if (copy_from_user(temporary_buffer,
                       user_buffer,
                       bytes_to_copy))
        return -EFAULT;

    temporary_buffer[bytes_to_copy] = '\0';

    if (mutex_lock_interruptible(&proc_mutex))
        return -ERESTARTSYS;

    strscpy(device_message,
            temporary_buffer,
            sizeof(device_message));

    mutex_unlock(&proc_mutex);

    pr_info("proc_driver: Received %zu bytes\n",
            bytes_to_copy);

    ret = bytes_to_copy;
    return ret;
}

/* Procfs operations */
static const struct proc_ops my_proc_ops = {
    .proc_read  = my_proc_read,
    .proc_write = my_proc_write,
};

/* Module initialization */
static int __init proc_driver_init(void)
{
    proc_entry = proc_create(
        PROC_NAME,
        0666,
        NULL,
        &my_proc_ops
    );

    if (!proc_entry) {
        pr_err("proc_driver: Failed to create proc entry\n");
        return -ENOMEM;
    }

    pr_info("proc_driver: /proc/%s created\n", PROC_NAME);

    return 0;
}

/* Module cleanup */
static void __exit proc_driver_exit(void)
{
    proc_remove(proc_entry);

    pr_info("proc_driver: Procfs entry removed\n");
}

module_init(proc_driver_init);
module_exit(proc_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Procfs Based Device Interface Driver");
MODULE_VERSION("1.0");

7. Understanding the Driver Code

7.1 Creating a Procfs Entry

proc_entry = proc_create(
    PROC_NAME,
    0666,
    NULL,
    &my_proc_ops
);

This creates /proc/my_driver.

  • PROC_NAME specifies the entry name.
  • 0666 specifies the requested permissions.
  • NULL selects the root of procfs as the parent directory.
  • my_proc_ops provides the callbacks.

7.2 Reading Data

The read callback uses simple_read_from_buffer() to copy the current message to user space while managing the file offset.

7.3 Writing Data

The write callback copies user data into a temporary kernel buffer, adds a terminating null character and updates the driver's stored message.

7.4 Removing the Entry

proc_remove(proc_entry);

This removes the procfs entry when the module is unloaded.

11. Read Data from Procfs

Use the cat command:

cat /proc/my_driver

Expected output:

Linux Procfs Driver Ready

12. Write Data to Procfs

Send a message to the driver:

echo "Hello from user space" | sudo tee /proc/my_driver

Read the updated message:

cat /proc/my_driver

Expected output:

Hello from user space

Check kernel messages:

sudo dmesg | tail -20

Expected message:

proc_driver: Received 23 bytes

The exact byte count depends on the message and its newline character.

13. Test with Different Messages

Each write replaces the previously stored message.

ls /proc/my_driver

Clean the project:

19. Lesson Summary

  • Procfs is a virtual filesystem mounted at /proc.
  • Kernel modules can create custom procfs entries.
  • proc_create() creates an entry and proc_remove() removes it.
  • Modern kernels use struct proc_ops for procfs callbacks.
  • Read and write callbacks enable user/kernel communication.
  • simple_read_from_buffer() simplifies buffered read handling.
