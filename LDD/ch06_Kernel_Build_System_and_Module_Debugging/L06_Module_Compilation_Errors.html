Lesson 6: Module Compilation Errors
Level: Beginner to Intermediate
Prerequisites: Kernel modules, C programming, GNU Make, Kbuild and kernel build directories.
Objective: Identify, understand and troubleshoot common errors encountered while compiling Linux kernel modules.

1. Introduction

Kernel module development involves writing C source code and compiling it using the Linux kernel build system. During compilation, developers may encounter errors caused by incorrect code, missing headers, incompatible kernel interfaces, Makefile mistakes or missing build tools.

Unlike ordinary user-space applications, kernel modules must be compiled against a suitable kernel build environment.

Understanding compilation errors is an important skill for Linux device driver development because even a small mistake can prevent a module from being generated.

2. What Is a Module Compilation Error?

A module compilation error occurs when the build process cannot successfully compile or link the source code into a kernel module.

Common stages include:

  • Preprocessing.
  • C compilation.
  • Object-file generation.
  • Module linking.
  • Module metadata and symbol processing.

An error can occur at any of these stages.

Kernel Module Source Code (.c)
↓
Preprocessing
↓
Compilation
↓
Object and Module Linking
↓
Final Module (.ko)

If a stage fails, the build may stop and the expected .ko file may not be generated.

3. Common Causes of Compilation Errors

Cause Description
Missing kernel headers The required kernel header package or prepared build tree is unavailable.
Incorrect kernel version The module is being built against an unsuitable kernel build tree.
Missing header files The source code includes an unavailable or incorrectly named header.
Syntax errors The C source contains invalid syntax.
Incorrect function usage A kernel API is called with incorrect arguments or types.
Makefile errors Kbuild declarations or Makefile commands are incorrect.
Compiler incompatibility The compiler or its configuration is unsuitable for the target build.
Missing build tools Required utilities such as GCC, Make or linker tools are unavailable.

4. Error: Kernel Build Directory Not Found

One common error occurs when the kernel build directory is missing. 

make: *** /lib/modules/.../build: No such file or directory. Stop.

Possible Causes

  • Matching kernel headers are not installed.
  • The build directory symbolic link is missing.
  • The running kernel version does not match the installed headers.

Step 1: Check Kernel Version

uname -r

Step 2: Install Matching Headers

sudo apt update
sudo apt install linux-headers-$(uname -r)

Step 3: Verify Build Directory

ls -l /lib/modules/$(uname -r)/build

Step 4: Rebuild Module

make
Always verify that the build directory corresponds to the kernel version for which you intend to build the module.

5. Error: No Such File or Directory

This error commonly appears when a required header file or source file cannot be found.

Example:

fatal error: linux/module.h: No such file or directory

Possible Causes

  • Kernel headers are missing.
  • The kernel build environment is incomplete.
  • An include path or header name is incorrect.
  • The source file references a file that does not exist.

Solution

First verify that the matching kernel headers are installed: 

sudo apt install linux-headers-$(uname -r)

Then check the required header path and rebuild the module.

Do not solve kernel header errors by copying random header files into the project directory. Use the correct kernel build environment.

6. Error: Implicit Declaration of Function

This error occurs when the compiler encounters a function call without a visible declaration.

Example of incorrect code:

#include <linux/module.h>

static int __init hello_init(void)
{
    pr_info("Module loaded\n");
    unknown_function();
    return 0;
}

If unknown_function() has no declaration or valid definition, the compiler reports an error.

Solution

  • Verify the function name.
  • Include the correct kernel header if one declares the function.
  • Check whether the API exists in the target kernel version.
  • Implement the function if it is a project-specific function.
  • Check whether the function is available to modules.
Adding an arbitrary function declaration is not a valid fix. The declaration, function signature and implementation must match the actual API.

7. Error: Incompatible Pointer Type

This error occurs when a function receives a pointer of a type different from the type expected by its declaration.

Example concept:

int value = 10;
char *ptr;

ptr = &value;

The pointer type does not match the address of the integer variable.

Solution

  • Check the expected parameter type.
  • Use the correct structure or pointer type.
  • Read the kernel API declaration.
  • Avoid unnecessary pointer casts that hide type errors.

In kernel programming, incorrect pointer types can cause serious runtime problems even if a warning is ignored.

8. Error: Too Many Arguments or Too Few Arguments

Kernel functions can have different signatures across kernel versions. Calling a function with the wrong number of arguments can produce a compilation error.

Example of a generic function declaration:

int example_function(int value);

Incorrect call:

example_function(10, 20);

The function expects one argument, but two are supplied.

Solution

  • Inspect the function declaration.
  • Check the API documentation for the target kernel.
  • Compare the function signature with the source code.
  • Use version-appropriate APIs.
Kernel APIs can change over time. For example, interfaces such as class_create() have changed signatures across kernel versions. Use the signature provided by the headers for your target kernel.

9. Error: Makefile and Kbuild Problems

A module can fail to compile because its Makefile contains incorrect Kbuild declarations or commands.

Incorrect Kbuild Declaration

obj-m += hello.c

For a source file named hello.c, the normal declaration is: 

obj-m += hello.o

Incorrect Recipe Indentation

GNU Make requires recipe commands to begin with a tab character by default.

Example:

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Other Common Makefile Problems

  • Incorrect source or object filenames.
  • Incorrect external module directory.
  • Missing modules target.
  • Wrong kernel build directory.
  • Using spaces instead of tabs for recipe indentation.

10. Error: Unknown Symbol During Module Build

A module may reference a kernel symbol that is not available to it.

Depending on the build and kernel configuration, symbol-related problems may appear during compilation, module linking or later module loading.

Examples of possible causes:

  • The function or variable is not exported to modules.
  • The required module dependency is missing.
  • The symbol is unavailable in the target kernel.
  • The build tree or symbol version information is incorrect.

Useful Inspection Commands

grep -w "symbol_name" /lib/modules/$(uname -r)/build/Module.symvers

Replace symbol_name with the actual symbol being investigated. The file may not be present in every build environment.

Also inspect the relevant kernel header and exported symbol declarations.

11. Error: Compiler or Build Tool Not Found

The kernel module build requires suitable compiler and build utilities.

Example error:

gcc: command not found

Another possible error:

make: command not found

Install Build Tools in Ubuntu

sudo apt update
sudo apt install build-essential

Verify GCC

gcc --version

Verify Make

make --version

A suitable compiler and toolchain are necessary for building kernel modules.

12. Understanding Warnings and Errors

Compiler output may contain warnings as well as errors. They are not identical.

Warning Error
Indicates a potential problem or questionable code. Indicates a problem that prevents the affected compilation step from succeeding.
May allow compilation to continue. Normally stops the affected build step.
Should be investigated and corrected. Must be resolved before a successful build can complete.

Example warning:

warning: unused variable 'value'

Example error:

error: expected ';' before 'return'
Some kernel builds treat selected warnings as errors because of compiler flags. Therefore, do not assume that every warning will always be harmless.

13. Reading Compilation Output

When a build fails, read the compiler output carefully. The most useful information is often near the first actual compiler error.

Example:

hello.c: In function 'hello_init':
hello.c:8:5: error: expected ';' before 'return'
    return 0;
    ^~~~~~
make[2]: *** [scripts/Makefile.build:...] Error 1
make[1]: *** [Makefile:...] Error 2
make: *** [Makefile:...] Error 2

Interpretation:

  • hello.c identifies the source file.
  • In function 'hello_init' identifies the function.
  • hello.c:8:5 identifies the approximate line and column.
  • expected ';' describes the syntax problem.
  • The later Make errors report that the build failed because an earlier command failed.

Start with the earliest meaningful compiler diagnostic rather than trying to fix every later Make error separately.

14. Useful Commands for Compilation Troubleshooting

Command Purpose
uname -r Displays the running kernel version.
gcc --version Displays the GCC version.
make --version Displays the GNU Make version.
ls -l /lib/modules/$(uname -r)/build Checks the kernel build directory.
ls /usr/src/ Lists installed source and header directories.
make V=1 Requests verbose output from many Kbuild operations.
make clean Removes generated build artifacts for the module.
modinfo hello.ko Displays metadata from a successfully generated module.

The exact verbose output depends on the kernel build system and the build stage.

15. A Systematic Troubleshooting Workflow

Follow a consistent procedure instead of changing several things at once.

Start Module Compilation
↓
Read the First Meaningful Error
↓
Check Kernel Version and Build Directory
↓
Check Headers, Compiler and Makefile
↓
Correct Source Code or API Usage
↓
Clean and Rebuild
↓
Verify the .ko Output

Recommended Procedure

  1. Read the complete build output.
  2. Identify the first meaningful compiler error.
  3. Check the line number and source file.
  4. Verify kernel version and headers.
  5. Inspect the Makefile and Kbuild declarations.
  6. Correct the source code or API usage.
  7. Run make clean when appropriate.
  8. Run make again.
  9. Confirm that the expected module file was generated.

16. Practical Project: Debug a Compilation Error

In this exercise, intentionally introduce a syntax error and observe the compiler output.

Step 1: Create the Project Directory

mkdir module_error_practice
cd module_error_practice

Step 2: Create hello.c

#include <linux/module.h>
#include <linux/kernel.h>

static int __init hello_init(void)
{
    pr_info("Hello module loaded\n")
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello module unloaded\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");

Notice that the first pr_info() statement is missing a semicolon.

Step 3: Create the Makefile

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Step 4: Compile

make

The compiler should report a syntax error near the missing semicolon.

Step 5: Correct the Source Code

Change the incorrect statement to: 

pr_info("Hello module loaded\n");

Step 6: Rebuild

make clean
make

Step 7: Verify the Module

ls -l hello.ko
modinfo hello.ko
This exercise demonstrates the difference between a source-code compilation error and a successful kernel module build.

17. Compilation Errors vs Module Loading Errors

Compilation errors and module loading errors occur at different stages of driver development.

Compilation Error Module Loading Error
Occurs during module build. Occurs when attempting to load a built module.
May prevent creation of the .ko file. The .ko file may already exist.
Investigated through compiler and Make output. Investigated through loader output and kernel logs.
Common causes include syntax, headers and API errors. Common causes include unknown symbols, version mismatch, signature restrictions and initialization failure.

A successful compilation does not guarantee successful module loading.

18. Best Practices

  • Use the correct kernel headers for the target kernel.
  • Read the first meaningful compiler error carefully.
  • Check the kernel API declarations before calling functions.
  • Keep source filenames and Makefile declarations consistent.
  • Use tabs for Makefile recipe commands.
  • Do not ignore compiler warnings.
  • Use verbose build output when necessary.
  • Clean generated files when troubleshooting stale build artifacts.
  • Make one correction at a time and rebuild.
  • Never test experimental modules on a critical production system.

19. Summary

  • Compilation errors prevent successful module generation.
  • Missing kernel headers can prevent module compilation.
  • Kernel version compatibility is important.
  • C syntax and type errors must be corrected.
  • Kernel API signatures can change across versions.
  • Makefile and Kbuild mistakes can stop the build.
  • Compiler output identifies the source file and approximate error location.
  • make V=1 helps inspect verbose build commands.
  • A successfully compiled module still needs separate loading and runtime testing.
