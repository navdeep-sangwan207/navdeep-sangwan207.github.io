Lesson 3: Compiling Modules Using Make
Level: Beginner to Intermediate
Prerequisites: Linux kernel modules, GNU Make, Makefiles and Kbuild.
Objective: Learn how to compile external Linux kernel modules using Make and understand the build process and its output.

1. Introduction

After writing a Linux kernel module, the next step is to compile it into a loadable kernel module file.

Linux device drivers are not normally compiled like ordinary user-space C applications. They must be built using the kernel build system so that the correct kernel headers, configuration and compilation rules are applied.

GNU Make provides the command interface, while Kbuild performs the kernel-specific build operations.

In this lesson, we will compile a simple external kernel module using Ubuntu and understand each stage of the process.

2. Requirements for Module Compilation

Before compiling a kernel module, make sure the following are available:

Requirement Purpose
Linux kernel The target kernel for which the module is being built.
Kernel headers/build tree Provides the kernel interfaces and build information required for compilation.
GCC compiler Compiles C source code.
GNU Make Processes Makefiles and coordinates the build.
Kbuild Provides kernel-specific compilation rules.
Module source code Contains the implementation of the kernel module.

Install Build Dependencies in Ubuntu

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

The build-essential package provides common development tools, including GCC and GNU Make.

The kernel headers package provides the matching build environment for the running Ubuntu kernel.

Verify GNU Make

make --version

Verify GCC

gcc --version

Check Kernel Version

uname -r

3. Understanding the Compilation Process

When you execute make in an external module directory, GNU Make reads the Makefile and invokes the kernel build system.

Kernel Module Source Code (.c)
↓
External Module Makefile
↓
GNU Make
↓
Linux Kernel Build System (Kbuild)
↓
Compiler and Linker Operations
↓
Generated Kernel Module (.ko)

The main stages are:

  1. Read the module Makefile.
  2. Identify the module objects declared for building.
  3. Enter the kernel build directory.
  4. Compile the module source code.
  5. Perform the required linking and module preparation.
  6. Generate the final .ko file.

4. Create a Kernel Module Project

We will create a project named hello_module.

Step 1: Create the Project Directory

mkdir hello_module
cd hello_module

Step 2: Create the Source File

Create a file named hello.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello! Kernel module loaded.\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Goodbye! Kernel module unloaded.\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Linux Device Drivers Student");
MODULE_DESCRIPTION("Hello World kernel module");

Understanding the Source Code

Code Purpose
linux/module.h Provides module-related declarations and macros.
linux/kernel.h Provides various kernel definitions and interfaces.
linux/init.h Provides initialization and exit annotations.
__init Marks initialization code that can be discarded after initialization in applicable builds.
__exit Marks exit code used for module cleanup where applicable.
pr_info() Writes an informational message to the kernel log.
module_init() Registers the module initialization function.
module_exit() Registers the module cleanup function.
MODULE_LICENSE() Declares module license information.

The initialization function returns zero when initialization succeeds. If initialization fails, it should return an appropriate negative error code.

The cleanup function has a void return type.

5. Create the External Module Makefile

Create a file named exactly Makefile in the same directory as hello.c. 

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Explanation:

  • obj-m += hello.o declares the loadable module object.
  • all is the default build target in this example.
  • $(MAKE) invokes GNU Make recursively.
  • -C selects the kernel build directory.
  • M=$(PWD) identifies the external module directory.
  • modules requests module compilation.
  • clean removes generated build files.
Important: The recipe commands under all: and clean: must begin with an actual tab character. Do not replace the tabs with spaces.

6. Verify the Kernel Build Directory

Before compiling, check whether the matching kernel build directory is available. 

ls -l /lib/modules/$(uname -r)/build

If the directory is missing, install the matching headers: 

sudo apt install linux-headers-$(uname -r)

If Ubuntu cannot find the exact package, check whether the running kernel has a corresponding package available for your distribution and repositories.

7. Compile the Kernel Module

Once the source file and Makefile are ready, execute: 

make

GNU Make reads the external Makefile. The default all target invokes Kbuild, which compiles the module.

The final output should include a module file named: 

hello.ko

The build output may show compiler and linker operations, module metadata generation and other intermediate steps.

Successful build: The appearance of hello.ko indicates that the module file has been generated. It does not mean that the module has been loaded into the running kernel.

8. Inspect the Generated Files

Execute:

ls -l

Depending on the kernel version and build process, you may see files similar to: 

hello.c
hello.o
hello.ko
hello.mod
hello.mod.c
hello.mod.o
Makefile
Module.symvers
modules.order
File Description
hello.c Original C source code.
hello.o Compiled object file.
hello.ko Final loadable kernel module.
hello.mod.c Generated module-related source information in applicable builds.
hello.mod.o Compiled module metadata object in applicable builds.
Module.symvers Symbol version information generated or used during module builds.
modules.order Records module build ordering information.

Do not expect every intermediate file to appear in exactly the same form on every Linux kernel version.

9. Inspect the Module Information

After compilation, use the file command to identify the generated module: 

file hello.ko

Use modinfo to inspect its metadata: 

modinfo hello.ko

The output may include the module filename, license, author, description, dependencies and other available metadata.

10. Load and Test the Compiled Module

Compilation and module loading are two separate operations. After building the module, it can be tested on a suitable Linux system.

Step 1: Load the Module

sudo insmod hello.ko

Step 2: Check Whether It Is Loaded

lsmod | grep hello

Step 3: View Kernel Messages

dmesg | tail -n 20

Expected initialization message:

Hello! Kernel module loaded.

Step 4: Remove the Module

sudo rmmod hello

Step 5: Check the Cleanup Message

dmesg | tail -n 20

Expected cleanup message:

Goodbye! Kernel module unloaded.
Module loading may be blocked by Secure Boot, signature enforcement or other kernel security settings. If loading fails, inspect the kernel log and follow the system's module-signing requirements rather than assuming compilation failed.

11. Cleaning the Build Directory

After testing or changing the source code, you may want to remove generated build artifacts. 

make clean

The kernel build system processes the clean target and removes generated files from the external module directory.

You can then rebuild the module using: 

make

Remember that cleaning build files does not unload a module already loaded into the kernel.

12. Verbose Compilation

Sometimes the normal Make output does not show enough detail to identify a compilation problem.

Use the V=1 option to request verbose output: 

make V=1

This displays more of the commands executed by the kernel build system, including compiler and other build operations.

Verbose output is useful when investigating incorrect include paths, compiler flags, build commands and configuration issues.

13. Common Compilation Errors

Error or Symptom Possible Reason Recommended Check
Build directory not found Matching kernel headers are missing. Check the build directory and install the correct headers.
Missing separator Makefile recipe uses spaces instead of a tab. Correct the recipe indentation.
Compilation error Incorrect C code or incompatible kernel API. Read the compiler error and verify API compatibility.
No rule to make target Incorrect object or source filename. Check the obj-m declaration and filenames.
Invalid module format Module does not match the running kernel or its configuration. Check the target kernel version and build environment.
Operation not permitted while loading Security policy or module-signing restriction. Inspect Secure Boot and kernel log messages.

Useful Diagnostic Commands

uname -r
make V=1
modinfo hello.ko
dmesg | tail -n 30

15. Summary

  • GNU Make coordinates external module compilation.
  • Kbuild performs kernel-specific compilation and linking.
  • Matching kernel headers or a prepared build tree are required.
  • The external Makefile declares module objects using Kbuild variables.
  • The make command starts the build process.
  • The final module file normally has the .ko extension.
  • modinfo displays module metadata.
  • insmod loads a module; compilation alone does not.
  • make clean removes generated build artifacts.
  • make V=1 provides more detailed build output.
