Home Course Chapter 6
Lesson 7: Module Loading Errors
Level: Beginner to Intermediate
Prerequisites: Linux kernel modules, insmod, modprobe, rmmod and module compilation.
Objective: Understand common kernel module loading failures and learn how to diagnose and resolve them.

1. Introduction

After successfully compiling a Linux kernel module, the next step is to load it into the running kernel. A compiled module usually has the extension .ko, which stands for kernel object.

A module may compile successfully but still fail during loading. This can happen because of kernel version mismatch, missing symbols, unresolved dependencies, invalid module metadata, security restrictions or errors during module initialization.

Module loading errors must be investigated carefully because kernel modules execute in kernel space.

2. What Happens When a Module Is Loaded?

When a module is loaded, the Linux kernel checks and prepares the module before executing its initialization function.

User Executes insmod or modprobe
↓
Kernel Module Loader
↓
Module Format and Compatibility Checks
↓
Symbol Resolution and Relocation
↓
Module Initialization Function
↓
Module Becomes Active (if initialization succeeds)

If a required check fails, or the initialization function returns an error, the module may not become active.

3. Loading a Kernel Module

Using insmod

The insmod command inserts a specified module file into the running kernel. 

sudo insmod hello.ko

Using modprobe

The modprobe command loads modules from the installed module tree and can automatically resolve dependencies using the module dependency database. 

sudo modprobe module_name
insmod modprobe
Loads a specified module file. Loads a module by name from the installed module tree.
Does not automatically resolve module dependencies. Can load required dependencies.
Useful for testing a locally built module file. Useful for managing installed modules.
A locally compiled .ko file is not automatically available to modprobe. It generally needs to be installed into the appropriate /lib/modules/ tree, followed by updating the dependency database with depmod.

4. Error: Invalid Module Format

One common loading error is: 

insmod: ERROR: could not insert module hello.ko:
Invalid module format

This error commonly indicates that the module is incompatible with the running kernel.

Possible Causes

  • The module was compiled against a different kernel version.
  • The module was built using an incompatible kernel configuration.
  • Module version information does not match.
  • The module was built for a different architecture.

Step 1: Check Running Kernel

uname -r

Step 2: Check Module Information

modinfo hello.ko

Step 3: Inspect Kernel Logs

dmesg | tail -30

Step 4: Rebuild Against the Correct Kernel

make clean
make
Build the module against the correct kernel build directory for the target kernel. Matching the kernel release is essential, although configuration, architecture and symbol compatibility can also matter.

5. Error: Unknown Symbol

A module may depend on a function or variable that the kernel cannot resolve during loading.

Example:

insmod: ERROR: could not insert module example.ko:
Unknown symbol example_function (err -2)

Possible Causes

  • The required symbol is not exported to modules.
  • A dependent module has not been loaded.
  • The module was compiled against an incompatible kernel build.
  • The required provider module is missing.
  • Symbol version information is incompatible.

Useful Commands

modinfo example.ko
lsmod
dmesg | tail -30

The modinfo command can display a module's declared dependencies through its metadata.

Solution

  • Identify which module provides the missing symbol.
  • Verify that the symbol is exported.
  • Check the required module dependency.
  • Rebuild against the appropriate kernel build tree.
  • Use modprobe when loading installed modules with dependencies.

6. Error: Required Module Dependency Missing

Some kernel modules depend on other modules. If a required module is not available, loading may fail.

Conceptual dependency:

Module A
↓ depends on
Module B
↓ depends on
Module C

If Module A requires a symbol exported by Module B, Module B must be available before Module A can successfully use that symbol.

Using insmod

sudo insmod module_b.ko
sudo insmod module_a.ko

With insmod, the developer must handle dependency loading order.

Using modprobe

sudo modprobe module_a

If the modules are correctly installed and their dependency information is available, modprobe can load the required modules automatically.

7. Error: Module Initialization Failed

A module can pass format and symbol checks but still fail when its initialization function executes.

The function registered through module_init() normally returns:

  • 0 when initialization succeeds.
  • A negative error code when initialization fails.

Example

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/errno.h>

static int __init example_init(void)
{
    pr_info("Initialization started\n");

    pr_err("Example initialization failed\n");

    return -EINVAL;
}

static void __exit example_exit(void)
{
    pr_info("Module exit called\n");
}

module_init(example_init);
module_exit(example_exit);

MODULE_LICENSE("GPL");

This example intentionally returns -EINVAL, indicating that initialization failed because of an invalid argument or condition.

The module does not become successfully active. The cleanup function registered with module_exit() is not called as a normal unload operation for this failed initialization.

If initialization allocates resources and later fails, it must release resources already acquired before returning the error. Do not assume the normal module-exit function will clean up partial initialization.

8. Error: Operation Not Permitted

A module-loading attempt may fail with: 

insmod: ERROR: could not insert module hello.ko:
Operation not permitted

This can indicate a security or permission restriction.

Possible Causes

  • The command was executed without sufficient privileges.
  • Kernel module loading is restricted.
  • Secure Boot or module-signing enforcement rejected the module.
  • The system is running under a restricted container or environment.
  • System security policy prevents module insertion.

Check Privileges

sudo insmod hello.ko

Inspect Kernel Logs

sudo dmesg | tail -30

Check Secure Boot Status on Ubuntu

mokutil --sb-state

If Secure Boot is enabled, the kernel may enforce module signature requirements depending on the system configuration.

Do not disable security protections as the first troubleshooting step. Identify the actual rejection reason and follow the appropriate module-signing procedure for the system.

9. Error: Module Already Loaded

Trying to insert a module that is already loaded can produce an error similar to: 

insmod: ERROR: could not insert module hello.ko:
File exists

The module may already be present in the running kernel.

Check Loaded Modules

lsmod | grep hello

Remove the Module

sudo rmmod hello

Load Again

sudo insmod hello.ko

The module name passed to rmmod is generally the module name, not the filename with the .ko extension.

10. Error: Module Is in Use

A module may not be removable while it is being used by another component or while its reference count is non-zero.

Example:

rmmod: ERROR: Module example is in use

Check Module Status

lsmod | grep example

The output includes a usage count and may list modules that depend on the module.

Dependency-Aware Removal

sudo modprobe -r example

This command attempts dependency-aware removal of the installed module.

Do not force removal of an active module simply to bypass an error. It can cause system instability or data corruption.

11. Error: Module Signature Verification Failed

Linux supports module signing to help verify the authenticity and integrity of kernel modules.

On systems enforcing signature verification, an unsigned module or a module signed by an untrusted key may be rejected.

Possible kernel log messages include:

module verification failed: signature and/or required key missing

Inspect Module Information

modinfo hello.ko | grep -E 'signer|sig_key|sig_hashalgo'

Check Secure Boot

mokutil --sb-state

Possible Solutions

  • Follow the distribution's kernel module signing procedure.
  • Use a trusted signing key enrolled according to system policy.
  • Verify the signature and signing certificate.
  • Check the kernel logs for the exact rejection reason.

Module signing is a security mechanism and should not be bypassed casually.

12. Using dmesg to Diagnose Loading Errors

The dmesg command displays messages from the kernel ring buffer. It is one of the most useful tools for investigating module loading problems.

Display Recent Kernel Messages

sudo dmesg | tail -30

Search for Module-Related Messages

sudo dmesg | grep -i hello

Follow Kernel Messages

sudo dmesg -w

Keep this command running in one terminal while loading a test module from another terminal. Press Ctrl+C to stop following the messages.

On some systems, access to kernel logs is restricted. Use sudo when necessary.

13. Important Commands for Module Troubleshooting

Command Purpose
uname -r Displays the running kernel version.
lsmod Lists currently loaded loadable modules.
modinfo hello.ko Displays module metadata and dependency information.
sudo insmod hello.ko Attempts to insert a specified module file.
sudo modprobe hello Loads an installed module by name and resolves dependencies.
sudo rmmod hello Attempts to remove a loaded module.
sudo modprobe -r hello Attempts dependency-aware module removal.
sudo dmesg | tail -30 Displays recent kernel messages.
sudo depmod -a Regenerates module dependency and symbol maps for installed modules.

14. Systematic Module Loading Troubleshooting

Follow this procedure whenever a kernel module fails to load.

Attempt to Load Module
↓
Read the insmod or modprobe Error
↓
Inspect dmesg Output
↓
Check Kernel Version and Module Metadata
↓
Check Symbols and Dependencies
↓
Check Permissions and Signature Policy
↓
Correct the Problem and Retry

Recommended Checklist

  1. Confirm that the module file exists.
  2. Verify that it was built for the intended kernel.
  3. Inspect metadata using modinfo.
  4. Check whether the module is already loaded.
  5. Read the kernel log for the detailed reason.
  6. Check unresolved symbols and dependencies.
  7. Check Secure Boot and module-signing restrictions.
  8. Verify that the initialization function succeeds.
  9. Retry loading and verify with lsmod.

15. Practical Project: Load and Diagnose a Kernel Module

This practical exercise uses a simple kernel module to demonstrate loading, verification and removal.

Step 1: Create Project Directory

mkdir module_loading_practice
cd module_loading_practice

Step 2: Create hello.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello module: initialization successful\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello module: cleanup successful\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Simple module loading practice");

Step 3: Create Makefile

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Step 4: Compile

make

Step 5: Inspect Module

ls -l hello.ko
modinfo hello.ko

Step 6: Load Module

sudo insmod hello.ko

Step 7: Verify Loading

lsmod | grep hello

Step 8: Inspect Kernel Messages

sudo dmesg | tail -20

Step 9: Remove Module

sudo rmmod hello

Step 10: Verify Removal

lsmod | grep hello
sudo dmesg | tail -20
Expected behavior: the module loads, its initialization message appears in the kernel log, and its cleanup message appears after successful removal.
Perform this exercise in your Ubuntu VirtualBox environment only if module loading is permitted. Kernel version, headers, Secure Boot policy and virtualization restrictions can affect the result.

16. Compilation Errors vs Loading Errors

Compilation Errors Loading Errors
Occur while building the module. Occur while inserting the module into the kernel.
May prevent creation of the .ko file. The .ko file may already exist.
Common causes include syntax errors and missing headers. Common causes include version mismatch and unresolved symbols.
Investigated using compiler and Make output. Investigated using insmod, modprobe and kernel logs.

17. Best Practices

  • Always verify the target kernel version.
  • Use matching kernel headers and build files.
  • Inspect module metadata before loading.
  • Use dmesg to investigate kernel-side failures.
  • Use modprobe for installed modules with dependencies.
  • Use insmod when testing a specific local module file.
  • Check module-signing requirements.
  • Handle initialization failures and partial resource allocation correctly.
  • Avoid force-removing modules that are in use.
  • Test experimental modules in a disposable virtual machine.

18. Summary

  • A compiled module can still fail during loading.
  • Invalid module format often indicates compatibility problems.
  • Unknown symbols indicate unresolved kernel or module symbols.
  • Module dependencies must be available.
  • The initialization function can reject module loading.
  • Secure Boot and module-signing policy can restrict insertion.
  • lsmod verifies currently loaded loadable modules.
  • modinfo displays module metadata.
  • dmesg helps identify kernel-side loading errors.
  • rmmod and modprobe -r support module removal.
