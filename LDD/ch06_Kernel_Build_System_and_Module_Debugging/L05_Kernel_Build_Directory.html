Lesson 5: Kernel Build Directory
Level: Beginner to Intermediate
Prerequisites: Linux kernel modules, kernel headers, GNU Make and Kbuild.
Objective: Understand the Linux kernel build directory, its location, important files and its role in external module compilation.

1. Introduction

Linux kernel modules require a special build environment. This environment contains kernel headers, configuration information, generated files and build rules required to compile modules.

The kernel build directory provides access to this environment. It is commonly used when compiling external Linux device drivers.

On Ubuntu, the build directory for the running kernel is commonly accessed through: 

/lib/modules/$(uname -r)/build

This path usually points to the installed kernel headers and prepared build tree for the corresponding kernel version.

2. What Is the Kernel Build Directory?

The kernel build directory is the directory through which the Linux kernel build system provides the files and rules needed to build kernel components and external modules.

It typically provides access to:

  • Linux kernel header files.
  • Generated kernel configuration headers.
  • Kernel build Makefiles.
  • Kbuild scripts and build rules.
  • Architecture-specific build information.
  • Symbol version information when configured and available.

3. Location of the Kernel Build Directory

Linux maintains kernel module directories under: 

/lib/modules/

Each installed kernel version normally has its own module directory.

For example:

/lib/modules/6.x.x-generic/

The exact version depends on the kernel installed on your Ubuntu system.

Check the Running Kernel Version

uname -r

Check the Module Directory

ls /lib/modules/$(uname -r)

Check the Build Directory

ls -l /lib/modules/$(uname -r)/build

The build entry is commonly a symbolic link to the installed kernel headers or prepared build tree.

4. Understanding the Build Symbolic Link

A symbolic link is a filesystem reference that points to another file or directory.

The kernel build path commonly uses a symbolic link so that external module Makefiles can use a consistent location without knowing the physical header directory.

Check the link using:

ls -l /lib/modules/$(uname -r)/build

Another useful command is:

readlink -f /lib/modules/$(uname -r)/build

The readlink -f command displays the resolved target path.

Example Conceptual Structure

/lib/modules/
|
|-- 6.x.x-generic/
    |
    |-- build -> /usr/src/linux-headers-6.x.x-generic
    |
    |-- source -> /usr/src/linux-headers-6.x.x
    |
    |-- kernel/
    |-- modules.dep
    |-- modules.alias
The exact directory structure and symbolic-link targets vary by distribution, kernel version and package layout. Do not assume every system uses identical paths.

5. Kernel Headers and Their Importance

Kernel header files provide declarations, data structures, macros and interfaces required when compiling kernel code.

A device driver uses kernel interfaces to communicate with the Linux kernel.

Examples of commonly used kernel headers include:

Header File Purpose
linux/module.h Kernel module definitions and macros.
linux/kernel.h General kernel definitions and interfaces.
linux/init.h Initialization and cleanup annotations.
linux/fs.h Filesystem and file-operation interfaces.
linux/cdev.h Character device registration interfaces.
linux/slab.h Kernel memory allocation interfaces.
linux/interrupt.h Interrupt handling interfaces.

These headers are used by kernel source files and module source files as appropriate.

Kernel headers are not the same as ordinary user-space C library headers. Kernel modules must use kernel interfaces rather than relying on user-space libraries such as glibc.

6. Install Kernel Headers in Ubuntu

For external module development, install the headers corresponding to the running kernel.

Step 1: Update Package Information

sudo apt update

Step 2: Install Build Tools and Headers

sudo apt install build-essential linux-headers-$(uname -r)

Step 3: Verify Installation

ls /usr/src/

Step 4: Check the Build Path

test -e /lib/modules/$(uname -r)/build \
    && echo "Kernel build directory found" \
    || echo "Kernel build directory missing"

If the matching header package is unavailable, check the kernel version, Ubuntu repositories and installed kernel packages.

7. Important Directories and Files

The kernel build environment contains many files. Some are generated during kernel configuration and preparation.

File or Directory Purpose
Makefile Top-level build instructions for the kernel build tree.
include/ Kernel header files and related include directories.
arch/ Architecture-specific kernel code and build information in a full source tree.
scripts/ Build scripts and helper tools in a full source tree or prepared build environment.
.config Kernel configuration file when provided by the build tree.
include/generated/ Generated headers used by the build.
Module.symvers Symbol version information used by module builds when available.
A distribution's installed header package may contain only the prepared subset needed for external module compilation. It does not necessarily contain the complete Linux kernel source tree.

8. Kernel Build Directory vs Kernel Source Directory

These two terms are related but do not always refer to the same physical directory.

Kernel Build Directory Kernel Source Directory
Provides the prepared build environment. Contains the kernel source code.
Used to compile external modules. Used for kernel development and source inspection.
May point to an installed headers package. May contain the complete kernel source tree.
Typically accessed through the build path. Often located in a source directory such as /usr/src/linux or a developer workspace.

A kernel can also be built using a separate output directory with Kbuild's out-of-tree kernel build mechanism. In that case, source and build files are intentionally separated.

9. How External Module Compilation Uses the Build Directory

Consider the standard external module command: 

make -C /lib/modules/$(uname -r)/build M=$PWD modules

Explanation:

Part Meaning
make Starts GNU Make.
-C Changes to the specified directory before processing its Makefile.
/lib/modules/$(uname -r)/build Selects the build tree for the running kernel.
M=$PWD Identifies the external module source directory.
modules Requests the external module build target.

The kernel build system then reads the external module's Kbuild declarations and performs the required compilation.

10. Why Kernel Version Matching Is Important

Linux kernel interfaces and configuration can change between kernel versions.

Therefore, an external module should normally be built against the prepared build tree corresponding to the kernel in which it will run.

Check the Running Kernel

uname -r

Check the Installed Header Packages

dpkg -l 'linux-headers*'

Check the Build Directory

ls -ld /lib/modules/$(uname -r)/build

Building against a different kernel version may cause compilation errors, symbol version mismatches or module loading failures.

Best practice: For a module intended for the currently running Ubuntu kernel, use its matching installed headers and build directory.

11. Understanding the .config File

The .config file contains configuration choices used when building a Linux kernel.

It determines which kernel features and components are enabled, disabled or selected as modules.

Example configuration values:

CONFIG_MODULES=y
CONFIG_SOME_DRIVER=m
CONFIG_ANOTHER_FEATURE=y
# CONFIG_UNUSED_FEATURE is not set

Meaning:

  • CONFIG_MODULES=y enables loadable module support.
  • CONFIG_SOME_DRIVER=m selects a supported component as a module.
  • CONFIG_ANOTHER_FEATURE=y selects a component as built-in.
  • A feature marked as not set is excluded from that configuration.

These are illustrative configuration entries. Actual option names depend on the kernel source and configuration.

12. Troubleshooting a Missing Build Directory

A common problem during module compilation is: 

/lib/modules/$(uname -r)/build: No such file or directory

Possible causes include:

  • Matching kernel headers are not installed.
  • The system was upgraded but the corresponding headers were not installed.
  • The running kernel version does not have a matching package in the configured repositories.
  • The expected symbolic link is missing or broken.

Step 1: Check the Running Kernel

uname -r

Step 2: Check Installed Headers

ls /usr/src/

Step 3: Install Matching Headers

sudo apt update
sudo apt install linux-headers-$(uname -r)

Step 4: Verify the Build Link

ls -l /lib/modules/$(uname -r)/build

Step 5: Retry Compilation

make
Do not manually create a symbolic link to an arbitrary kernel source directory. The target must be a correctly prepared build tree matching the intended kernel.

14. Summary

  • The kernel build directory provides the prepared environment for kernel compilation.
  • External modules commonly use /lib/modules/$(uname -r)/build.
  • The build entry commonly points to installed kernel headers or a prepared build tree.
  • Kernel headers provide declarations and interfaces needed for compilation.
  • The build environment also uses generated configuration information and Kbuild rules.
  • The kernel build directory and full kernel source directory are related but not necessarily identical.
  • External modules should normally be compiled against the matching target kernel build tree.
  • A missing or incorrect build directory can prevent module compilation.
