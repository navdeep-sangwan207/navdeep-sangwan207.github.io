Lesson 2: Structure of a Kernel Module Makefile
Level: Beginner to Intermediate
Prerequisites: Basic GNU Make, Linux commands, C programming and introduction to Kbuild.
Objective: Understand the structure, variables, targets and commands used in an external kernel module Makefile.

1. Introduction

A Makefile is a text file containing instructions used by the GNU Make utility to automate compilation and other build tasks.

In Linux device driver development, a Makefile tells the kernel build system which source files should be compiled and which build targets should be executed.

An external kernel module Makefile usually contains two important parts:

  1. Kbuild declarations describing the kernel objects to build.
  2. GNU Make targets that invoke the kernel build system.

Understanding this structure is essential before developing larger character, GPIO, I2C or SPI drivers.

2. What Is a Makefile?

A Makefile contains rules that describe how files should be generated or updated.

A basic GNU Make rule has this structure:

target: prerequisites
	command
Element Description
Target The file or task that Make should build or execute.
Prerequisites Files or targets required before the target can be processed.
Command The instruction executed to build or update the target.

Example of an ordinary Makefile:

hello: hello.c
	gcc hello.c -o hello

This example compiles an ordinary user-space C program. It is not the normal method for compiling a Linux kernel module.

Important: Makefile recipe commands must begin with a tab character by default. Spaces in place of the required tab can cause a "missing separator" error.

3. Basic Kernel Module Makefile

Consider the following Makefile for a simple external kernel module named hello. 

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

This Makefile contains three main sections:

  1. obj-m declaration.
  2. all target.
  3. clean target.
External Module Makefile
↓
obj-m += hello.o
↓
all target → Build the module
↓
clean target → Remove generated build files

4. Understanding obj-m

The declaration obj-m is a Kbuild variable used to specify an object that should be built as a loadable kernel module. 

obj-m += hello.o

Here:

  • obj-m identifies a loadable module object.
  • hello.o is the object name associated with the source file hello.c.
  • The Kbuild system uses this declaration to build the module.

The resulting loadable module is normally named hello.ko.

Multiple Modules

An external module directory can describe multiple independent modules: 

obj-m += hello.o
obj-m += goodbye.o

Kbuild will build both modules, assuming the corresponding source files and any required dependencies are available.

The detailed difference between obj-m and obj-y is covered in Lesson 4.

5. Understanding the all Target

In a typical external module Makefile, the all target is used as the default build target. 

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

When you execute make without specifying a target, GNU Make normally processes the first ordinary target in the Makefile. In this example, that target is all.

Understanding $(MAKE)

$(MAKE) invokes GNU Make recursively. It is preferred to writing a plain make command inside a Makefile because GNU Make can preserve relevant command-line options and recognize recursive build operations.

Understanding $(shell uname -r)

The shell function executes a shell command and returns its output. 

$(shell uname -r)

This obtains the running kernel release, such as a version ending in -generic on many Ubuntu installations.

Understanding $(PWD)

$(PWD) represents the current working directory in this common external module build pattern. It identifies the location of the module source and Makefile.

6. Understanding the -C Option

The -C option tells GNU Make to change into a specified directory before reading and processing the Makefile located there. 

$(MAKE) -C /lib/modules/$(shell uname -r)/build

The directory specified here is the kernel build directory associated with the running kernel.

It contains the prepared headers and build information required for compiling external modules.

The build directory is commonly a symbolic link to the matching kernel headers or prepared build tree.

7. Understanding M=$(PWD)

The M= parameter tells the kernel build system where the external module source directory is located. 

M=$(PWD)

For example, if your module project is located at: 

/home/student/hello_kbuild

The parameter identifies that directory as the external module source location.

Kbuild then reads the external module's build declarations and processes the source files.

Remember: The kernel build directory and the external module source directory are different locations. The -C option selects the former; M= identifies the latter.

8. Understanding the modules Target

The modules target instructs the kernel build system to build the external kernel modules declared in the module Makefile. 

modules

When Kbuild processes this target, it applies the kernel's compilation and linking rules.

The final output for a module named hello is normally: 

hello.ko

This file can later be inspected or loaded separately.

9. Understanding the clean Target

The clean target removes generated build files from the external module directory using the kernel build system's cleanup rules. 

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Execute the cleanup operation using: 

make clean

This is useful when you want to rebuild a module from a clean state after changing source code or build declarations.

The clean target removes generated build artifacts. It does not uninstall an already installed module from /lib/modules/ or automatically unload a module currently running in the kernel.

10. Complete Practical Example

Let us create a complete project to understand how the source file and Makefile work together.

Step 1: Create a Directory

mkdir my_kernel_module
cd my_kernel_module

Step 2: Create hello.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Kernel module initialized\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Kernel module removed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Student");
MODULE_DESCRIPTION("Example kernel module using Kbuild");

Step 3: Create Makefile

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Step 4: Install Build Requirements

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Step 5: Compile the Module

make

Step 6: Inspect the Generated Module

ls -l
file hello.ko
modinfo hello.ko

Step 7: Clean the Build

make clean

After this operation, generated build files are cleaned from the project directory.

11. Makefile for a Multi-Source Kernel Module

A kernel module can be made from multiple C source files. Kbuild supports composite modules, where several object files are linked into one module.

Consider this project structure:

my_driver/
|
|-- Makefile
|-- main.c
|-- helper.c
|-- helper.h

Example Makefile:

obj-m += my_driver.o

my_driver-y := main.o helper.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Explanation:

  • obj-m += my_driver.o declares the module to be built.
  • my_driver-y lists the component object files that form the composite module.
  • main.o is generated from main.c.
  • helper.o is generated from helper.c.

Kbuild combines the specified objects to create my_driver.ko.

In Kbuild, the composite module's object name and the module declaration must correspond. Do not confuse this composite module pattern with declaring two independent modules.

12. Common Makefile Errors

Error Possible Cause Solution
Missing separator Recipe line starts with spaces instead of a tab. Use a tab before each recipe command.
No rule to make target Incorrect source or object filename. Check the filenames and Kbuild declarations.
Build directory not found Matching kernel headers are not installed. Install the appropriate kernel headers.
Unknown symbol or unresolved symbol Module dependency or symbol availability issue. Review dependencies, exported symbols and target kernel.
Module not generated Incorrect target or Kbuild declaration. Check obj-m and the build output.

Useful Diagnostic Commands

uname -r
ls -l /lib/modules/$(uname -r)/build
make V=1
dmesg | tail -n 30

make V=1 requests more detailed build output, helping you inspect the commands used during compilation.

13. Important Makefile Concepts

Concept Purpose
Makefile Contains build instructions.
obj-m Declares loadable module objects.
obj-y Declares objects built into the kernel in an in-tree build.
all Common default build target.
clean Removes generated build artifacts.
$(MAKE) Runs recursive Make.
-C Changes to the kernel build directory.
M= Identifies the external module directory.
modules Builds external modules.

14. Summary

  • A kernel module Makefile describes how an external module is built.
  • Kbuild declarations identify the objects to compile.
  • obj-m declares loadable modules.
  • The all target commonly invokes the kernel build system.
  • $(MAKE) runs GNU Make recursively.
  • -C selects the kernel build directory.
  • M= identifies the external module source directory.
  • The modules target builds the module.
  • The clean target removes generated build files.
  • Composite modules can combine multiple source files.
