Objective: Understand the complete development lifecycle of a Linux kernel module, from planning and coding to compilation, testing, debugging and maintenance.

1. Introduction

Kernel module development is a systematic process used to create, compile, load, test, debug and maintain loadable kernel components.

A kernel module may implement a device driver, filesystem functionality, a network feature or another kernel extension.

A reliable development workflow helps developers detect errors early, manage resources correctly and maintain compatibility with the target kernel.

In this lesson, we will follow the complete process of developing a simple Linux kernel module.

3. Step 1: Requirement Analysis

Before writing code, understand what the module must do and which kernel interfaces it needs.

Questions to Consider

  • What problem will the module solve?
  • Will it interact with a hardware device?
  • Does it need to register a character device?
  • Will it communicate with user-space applications?
  • Does it need interrupt handling?
  • Will it use memory allocation or synchronization?
  • Which kernel version and configuration are targeted?

Example Requirement

Develop a simple loadable kernel module that:

  1. Loads successfully into the Linux kernel.
  2. Displays an initialization message.
  3. Displays a cleanup message when removed.
  4. Can be compiled using the Kbuild system.

This is a basic learning requirement. A real device driver will have additional hardware and interface requirements.

4. Step 2: Development Environment Setup

A suitable development environment must be prepared before compiling a kernel module.

Check Linux Kernel Version

uname -r

This displays the currently running kernel release.

Install Build Tools on Ubuntu

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Check Kernel Build Directory

ls -l /lib/modules/$(uname -r)/build

This path normally points to the kernel build directory associated with the installed headers.

Check GCC and Make

gcc --version
make --version
Kernel modules should be built against the appropriate kernel build tree and configuration. A module compiled for one kernel release may not load into another.

5. Step 3: Create the Project Directory

Create a separate directory for each module project. This keeps source files, Makefiles and build outputs organized. 

mkdir hello_module
cd hello_module

Project Structure

hello_module/
|
|-- hello.c
|
|-- Makefile
|
|-- hello.ko
|
|-- hello.o
|
|-- hello.mod.c
|
|-- Module.symvers
|
|-- modules.order

The source file and Makefile are created by the developer. Other files are generated during the kernel module build process.

6. Step 4: Write the Kernel Module Source Code

The source code contains the module functionality. A basic module normally defines initialization and cleanup functions.

File: hello.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("hello_module: module loaded\n");

    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("hello_module: module removed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic Linux kernel module");

Explanation

Element Purpose
module.h Provides module-related definitions.
kernel.h Provides kernel utility declarations.
init.h Provides initialization-related macros.
hello_init() Runs when the module is successfully initialized.
hello_exit() Runs when the module is unloaded.
module_init() Registers the initialization function.
module_exit() Registers the cleanup function.
MODULE_LICENSE() Declares the module license.

7. Step 5: Create the Kernel Module Makefile

Kbuild is the Linux kernel build system. It provides the rules and configuration needed to compile external kernel modules.

File: Makefile

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Explanation

  • obj-m += hello.o identifies the module object to build.
  • $(MAKE) invokes the make program.
  • -C changes to the specified kernel build directory.
  • M=$(PWD) identifies the external module source directory.
  • modules requests external module compilation.
  • clean removes generated build files from the external module directory.
Makefile recipe lines must begin with a real tab character, not spaces.

8. Step 6: Compile the Kernel Module

Run the following command from the project directory: 

make

Kbuild processes the source code and generates the loadable kernel module.

Important Build Output

File Description
hello.o Compiled object file.
hello.ko Loadable kernel module.
hello.mod.c Generated module metadata source.
Module.symvers Symbol version information used during module builds.
modules.order Records module build ordering information.

Verify the Module File

ls -l hello.ko
file hello.ko

9. Step 7: Inspect the Compiled Module

Before loading the module, inspect its metadata and verify that it was built for the intended kernel environment.

Display Module Information

modinfo hello.ko

This command can display information such as:

  • Module filename.
  • Module description.
  • Author.
  • License.
  • Supported aliases, if present.
  • Dependencies, if present.
  • Version information, if available.

Check Kernel Version

uname -r

Compare the target kernel release with the build environment. Also consider module signing and Secure Boot restrictions where applicable.

10. Step 8: Load the Kernel Module

After compilation and inspection, load the module into the running Linux kernel. 

sudo insmod hello.ko

insmod loads the specified module file. It does not automatically resolve dependencies in the way that modprobe does.

Verify Module Loading

lsmod | grep hello

Inspect Kernel Messages

sudo dmesg | tail -20

The expected message is: 

hello_module: module loaded
A module may fail to load because of an invalid module format, unresolved symbols, incompatible kernel interfaces, signature restrictions or an error returned by its initialization function.

11. Step 9: Test the Kernel Module

Testing verifies that the module behaves according to its requirements.

Basic Testing Checklist

  1. Verify that the module loads successfully.
  2. Confirm that the module appears in lsmod.
  3. Inspect the initialization log message.
  4. Check for unexpected kernel warnings or errors.
  5. Verify that the module can be removed safely.
  6. Check the cleanup log message.

Monitor Kernel Messages

sudo dmesg -w

This command displays new messages as they are added to the kernel ring buffer.

12. Step 10: Remove the Kernel Module

When testing is complete, remove the module from the running kernel. 

sudo rmmod hello

The module name is used without the .ko extension.

Verify Removal

lsmod | grep hello

If the module has been removed successfully, it should no longer appear in the loaded module list.

Check Cleanup Message

sudo dmesg | tail -20

Expected message:

hello_module: module removed

13. Step 11: Debug and Correct Errors

If compilation, loading or testing fails, identify the stage where the problem occurred.

Problem Possible Investigation
Compilation error Check source code, headers, compiler output and Makefile.
Invalid module format Check kernel release, module compatibility and vermagic information.
Unknown symbol Check symbol availability, dependencies and kernel configuration.
Permission denied Check privileges and security restrictions.
Initialization failure Inspect the initialization function and kernel log.
Module busy Check whether the module is in use or has active references.
Unexpected kernel warning Inspect the warning message and associated stack trace.

Useful Debugging Commands

sudo dmesg | tail -50
sudo journalctl -k -b
lsmod
modinfo hello.ko

Correct the problem, rebuild the module and repeat the test cycle.

14. Step 12: Clean the Build Directory

After testing, remove generated build files using the Kbuild clean target. 

make clean

This removes generated build artifacts from the external module directory. It does not remove the source code or Makefile.

Remove the module from the running kernel before cleaning or replacing its build files. Do not confuse build cleanup with module unloading.

15. Installing a Kernel Module

During development, modules are commonly loaded directly from the project directory using insmod.

For installation into the system module tree, Kbuild provides the modules_install target.

Install the Module

sudo make modules_install

External modules are normally installed under a directory associated with the current kernel release, often below: 

/lib/modules/$(uname -r)/updates/

Update Module Dependency Information

sudo depmod -a

This rebuilds dependency and symbol map information for installed modules.

Load the Installed Module

sudo modprobe hello

Unlike insmod, modprobe uses the installed module database and can automatically load required dependencies.

Installing a module does not guarantee that it will load on every kernel. Compatibility, signing, dependency and security requirements still apply.

16. Source Code Control and Documentation

Professional kernel development should maintain source code history and technical documentation.

Version Control

Git can be used to track source code changes. 

git init
git add hello.c Makefile
git commit -m "Add basic Linux kernel module"

Useful Project Documentation

  • Module purpose and requirements.
  • Supported kernel versions.
  • Build instructions.
  • Loading and unloading instructions.
  • Known limitations.
  • Testing results.
  • Debugging notes.
  • Installation and removal procedure.

17. Kernel Module Development Best Practices

  • Understand the requirements before writing code.
  • Use the correct kernel headers and build configuration.
  • Follow Linux kernel coding conventions.
  • Use appropriate kernel APIs.
  • Check every memory allocation result.
  • Release resources correctly.
  • Keep initialization and cleanup logic consistent.
  • Use kernel logging carefully.
  • Test error paths as well as successful paths.
  • Use a safe development environment.
  • Maintain source code and build documentation.
  • Test against each supported target kernel.

18. Development Environment for This Course

The practical exercises in this course can be performed using Ubuntu running inside VirtualBox, provided the required kernel headers and build tools are installed.

Recommended Development Setup

20. Summary

  • Kernel module development begins with requirement analysis.
  • The development environment must match the target kernel.
  • Module source code contains initialization and cleanup functions.
  • Kbuild and Makefiles control external module compilation.
  • The generated .ko file is the loadable kernel module.
  • modinfo helps inspect module metadata.
  • insmod loads a specified module file.
  • lsmod verifies loaded modules.
  • dmesg and journalctl help investigate kernel messages.
  • rmmod removes a loadable module.
  • modules_install and depmod support system installation.
  • Testing, debugging and documentation are essential parts of development.
