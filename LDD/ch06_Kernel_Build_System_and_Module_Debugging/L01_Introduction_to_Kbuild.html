Lesson 1: Introduction to Kbuild
Level: Beginner to Intermediate
Prerequisites: Linux kernel modules, C programming, Makefiles and basic Linux commands.
Objective: Understand the Linux kernel build system and learn how Kbuild compiles external kernel modules.

1. Introduction

Linux device drivers are generally written in C and execute inside kernel space. Unlike ordinary user-space programs, kernel modules cannot normally be compiled using a simple standalone GCC command.

They must be compiled using the Linux kernel's build system, known as Kbuild.

Kbuild is responsible for managing kernel compilation rules, configuration settings, source files, dependencies and module generation.

When developing an external Linux kernel module, we use Kbuild to compile our source code against the appropriate kernel headers and build files.

2. What Is Kbuild?

Kbuild is the Linux kernel build system. It is a collection of Makefiles, scripts, configuration information and build rules used to compile the Linux kernel and its components.

Kbuild supports two major types of compilation:

  1. Building the Linux kernel and its in-tree components.
  2. Building external kernel modules.

Why Is Kbuild Required?

Kernel code depends on kernel-specific data structures, headers, configuration options and compilation rules. A normal user-space compilation process does not automatically provide these.

Kbuild helps by:

  • Using the correct kernel header files.
  • Applying kernel-specific compilation flags.
  • Handling kernel configuration settings.
  • Managing dependencies between source files.
  • Building kernel object files and loadable modules.
  • Generating module-related metadata and intermediate files.

3. Kbuild and GNU Make

Kbuild uses GNU Make as its execution engine, but it is not simply an ordinary Makefile-based application build.

The kernel provides its own Makefiles, variables, scripts and compilation rules. GNU Make processes these rules and coordinates the build.

Difference Between GNU Make and Kbuild

GNU Make Kbuild
General-purpose build automation tool. Linux kernel-specific build system.
Processes instructions written in Makefiles. Provides kernel-specific Makefiles and build rules.
Can build ordinary applications. Builds the Linux kernel and kernel modules.
Does not automatically understand kernel configuration. Integrates with kernel configuration and generated build information.

4. Different Types of Kernel Builds

4.1 Building the Complete Linux Kernel

A complete kernel build compiles the configured Linux kernel source tree. It produces a kernel image and other required components depending on the architecture and configuration.

A typical kernel source build may involve commands such as: 

make menuconfig
make -j$(nproc)

The first command opens a configuration interface when the required configuration tools are installed. The second starts the build using multiple available processing jobs.

4.2 Building In-Tree Kernel Components

In-tree components are maintained inside the Linux kernel source tree. Kbuild uses the kernel's configuration and Makefiles to decide which components should be compiled as built-in objects and which should be built as modules.

4.3 Building External Kernel Modules

External modules are developed outside the main Linux kernel source tree. A device driver developer can maintain a separate directory containing the module's source code and Makefile.

The external module is then compiled by asking the kernel build system to process that directory.

5. Kernel Build Directory

Linux provides a build directory containing the headers and build information required for compiling modules against a particular kernel version.

For the currently running kernel, the conventional location is: 

/lib/modules/$(uname -r)/build

This path is commonly a symbolic link to the corresponding kernel headers or prepared kernel build tree.

Check the Running Kernel Version

uname -r

Example output:

6.x.x-xx-generic

The exact version depends on the Ubuntu kernel installed on the system.

Check the Kernel Build Directory

ls -l /lib/modules/$(uname -r)/build

If the required build directory is missing, install the matching kernel headers. 

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)
Important: The headers and build tree must match the kernel version against which the module is intended to be compiled. Installing headers for a different kernel version can cause compilation or module compatibility problems.

6. Basic External Module Compilation Command

The standard command pattern for building an external Linux kernel module is: 

make -C /lib/modules/$(uname -r)/build M=$PWD modules

Understand each part of this command:

Command Part Meaning
make Starts GNU Make.
-C Changes to the specified directory before processing the build.
/lib/modules/$(uname -r)/build Specifies the kernel build directory for the running kernel.
M=$PWD Identifies the external module source directory. Here, PWD represents the current working directory.
modules Requests the kernel build system to build the external modules.

Understanding -C

The -C option instructs Make to change into the specified directory before reading and processing its build instructions.

Understanding M=

The M= parameter tells Kbuild where the external module source directory is located.

Understanding modules

The modules target requests compilation of the external kernel module or modules described by the external module Makefile.

7. Creating a Simple External Kernel Module

Let us create a basic Hello World kernel module to understand the Kbuild compilation process.

Step 1: Create a Project Directory

mkdir hello_kbuild
cd hello_kbuild

Step 2: Create the Source File

Create a file named hello.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello from Kbuild module!\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Goodbye from Kbuild module!\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Linux Device Drivers Student");
MODULE_DESCRIPTION("A simple external kernel module");

Step 3: Create the Makefile

Create a file named Makefile.

obj-m += hello.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The command lines below all: and clean: must begin with a tab character, not spaces.

Step 4: Compile the Module

make

GNU Make reads the external Makefile. It then invokes the kernel build system, which applies Kbuild rules to compile the module.

Step 5: Check the Generated Files

ls

A successful build commonly generates: 

hello.c
hello.o
hello.ko
hello.mod
hello.mod.c
hello.mod.o
Makefile
Module.symvers
modules.order

The exact intermediate files depend on the kernel version and build configuration. Some files may not appear in every build.

Step 6: Clean the Build Files

make clean

This invokes the kernel build system's clean target for the external module directory.

Remember: Kbuild compiles the module and generates the .ko file. It does not automatically load the module into the running kernel.

8. Important Kbuild Variables and Targets

Variable / Target Purpose
obj-m Specifies objects to build as loadable modules.
obj-y Specifies objects built into the kernel in an in-tree build.
M= Specifies the external module source directory.
modules Builds external kernel modules.
clean Removes generated build files from the module build directory.
$(MAKE) Invokes Make recursively while preserving relevant Make options.
$(PWD) Represents the current working directory in this Makefile pattern.

The detailed use of obj-m and obj-y will be covered in Lesson 4.

9. Kbuild Output: What Is a .ko File?

A kernel module is commonly distributed as a file with the .ko extension. The extension stands for kernel object.

The generated module contains compiled kernel code and the information required for the kernel's module-loading process.

After successful compilation, a module can be examined with:

file hello.ko
modinfo hello.ko

The file command identifies the file type, while modinfo displays available module metadata.

If you want to test loading the module, use the appropriate module-loading commands with administrative privileges. Module loading is a separate operation from compilation. 

sudo insmod hello.ko
lsmod | grep hello
sudo rmmod hello
dmesg | tail
Security note: Secure Boot and kernel module signature enforcement may prevent an unsigned module from loading. A successful build does not guarantee that the running kernel will accept the module.

10. Kbuild Version Compatibility

Kernel modules are closely connected to the kernel version and configuration for which they are built.

For reliable results, compile an external module against the matching kernel headers or prepared build tree for its target kernel.

Useful commands include:

uname -r
ls /lib/modules/$(uname -r)/
ls -l /lib/modules/$(uname -r)/build

Kernel APIs and configuration details can change between kernel versions. A module that compiles against one version may require changes for another.

Important: Do not assume that a module compiled against arbitrary kernel headers will work with the currently running kernel. Match the build environment to the target kernel.

11. Common Kbuild Problems

Problem Possible Cause What to Check
Build directory not found Matching kernel headers are missing. Install the headers for the target kernel.
Compilation errors Incorrect source code or incompatible kernel API. Review compiler output and kernel API compatibility.
Makefile errors Incorrect syntax or spaces instead of tabs. Check target names and recipe indentation.
Invalid module format Module was built for a different kernel or incompatible configuration. Check uname -r and kernel build information.
Module loading denied Secure Boot or signature enforcement. Inspect kernel logs and module-signing requirements.

To inspect kernel messages after a build or module-loading attempt, use: 

dmesg | tail -n 30

12. Kbuild in Your Ubuntu Virtual Machine

You can learn Kbuild using Ubuntu installed inside VirtualBox. A basic external kernel module can be compiled and tested without a physical development board.

Recommended preparation:

  1. Start the Ubuntu virtual machine.
  2. Open the terminal.
  3. Check the running kernel version using uname -r.
  4. Install build-essential and matching kernel headers.
  5. Create the external module directory.
  6. Write the C source file and Makefile.
  7. Compile the module using make.
  8. Inspect the generated .ko file.

Simple kernel-module compilation and loading can be practiced inside the VM, subject to kernel configuration and security restrictions.

Physical GPIO, I2C and SPI peripheral exercises require suitable hardware access or an appropriate emulation environment. A standard VirtualBox Ubuntu installation does not automatically expose physical embedded-board peripherals.

13. Summary

  • Kbuild is the Linux kernel's build system.
  • It uses GNU Make together with kernel-specific build rules and scripts.
  • Kbuild supports complete kernel, in-tree and external module builds.
  • External modules are built against a suitable kernel build directory.
  • The -C option selects the kernel build directory.
  • The M= parameter identifies the external module source directory.
  • The modules target builds external modules.
  • The generated .ko file can be loaded separately.
  • Kernel headers must match the intended target kernel.
  • Secure Boot and module-signing rules can affect module loading.
