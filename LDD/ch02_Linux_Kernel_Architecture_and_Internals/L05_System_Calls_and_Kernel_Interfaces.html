1. Introduction

User applications cannot directly execute privileged kernel operations whenever they want. Instead, they request services from the Linux kernel through controlled interfaces.

A system call is the controlled mechanism through which a user-space program requests a service from the operating-system kernel.

System calls are essential for file access, process creation, memory management, networking and communication with device drivers.

For Linux device driver development, understanding system calls helps explain how a user application communicates with a kernel driver.

2. What Is a System Call?

A system call is an interface between user space and kernel space. It allows a user application to request an operation that requires kernel services or privileges.

Examples

System Call Purpose
open() Opens a file or device.
read() Reads data using a file descriptor.
write() Writes data using a file descriptor.
close() Closes a file descriptor.
fork() Creates a child process.
execve() Replaces the current process image with a new program.
mmap() Creates a memory mapping.
ioctl() Performs device-specific or file-specific control operations.

3. Why Are System Calls Required?

Modern operating systems separate user applications from privileged kernel operations. This separation helps protect the system and control access to hardware and resources.

Main Reasons

  • Protection: Prevents applications from freely accessing privileged kernel memory.
  • Controlled hardware access: Applications use kernel-managed interfaces to access devices.
  • Resource management: The kernel manages CPU, memory and I/O resources.
  • Security: The kernel checks permissions and credentials.
  • Standardization: Applications use common interfaces instead of implementing hardware-specific operations.
User space and kernel space are protection and execution environments. A system call provides a controlled transition between them; it is not simply an ordinary function call.

5. How Does a System Call Work?

A typical system call begins in a user application and enters the kernel through a processor-supported system call mechanism.

System Call Execution Steps

  1. A user application calls a library function or system call wrapper.
  2. The wrapper prepares the system call number and arguments according to the architecture's calling convention.
  3. A processor instruction initiates the system call transition.
  4. The CPU enters the appropriate privileged execution context.
  5. The kernel identifies and dispatches the requested system call.
  6. The kernel validates arguments and performs the requested operation.
  7. The kernel returns a result or error indication.
  8. Execution resumes in user space.

6. System Calls and C Library Functions

Many programs use functions from the C standard library rather than invoking the low-level system call mechanism directly.

A library function may wrap one or more system calls, perform additional user-space processing, or operate entirely in user space.

Library Function Related System Call Explanation
open() openat() on modern Linux implementations Opens a file or device.
read() read Reads data from a file descriptor.
write() write Writes data to a file descriptor.
close() close Closes a file descriptor.
printf() No single direct system call Formats output in user space and may eventually use write().
malloc() May use brk() or mmap() Manages user-space memory and may request memory from the kernel.
Library functions and system calls are not identical. For example, printf() is a formatted-output library function, not a Linux system call.

9. Kernel Interfaces

A kernel interface is a defined mechanism through which user-space applications or other kernel components interact with kernel functionality.

Major Types of Kernel Interfaces

Interface Purpose Example
System Call Interface Requests kernel services. read(), write()
Device File Interface Provides file-like access to devices. /dev/tty
Procfs Exposes process and kernel information. /proc
Sysfs Exposes device model objects and attributes. /sys
IOCTL Interface Provides device-specific control operations. ioctl()
Netlink Provides structured communication between user space and kernel networking or other supported kernel facilities. Routing configuration

10. Device Files as Kernel Interfaces

Linux represents many devices through special files located in the /dev directory.

Examples

/dev/null
/dev/zero
/dev/tty
/dev/random
/dev/urandom

Applications can use standard file operations to interact with many device interfaces.

Example

#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    char data[20];

    fd = open("/dev/zero", O_RDONLY);

    if (fd < 0)
        return 1;

    read(fd, data, sizeof(data));

    close(fd);

    return 0;
}

The /dev/zero device supplies zero-valued bytes when read. This example demonstrates a standard device-file interface.

11. Return Values and Error Handling

System calls communicate success or failure through their return values.

Typical Conventions

  • read() returns the number of bytes read, zero at end of file, or -1 on error.
  • write() returns the number of bytes written or -1 on error.
  • open() returns a file descriptor or -1 on error.
  • close() returns zero on success or -1 on error.

When a library wrapper reports an error using -1, the global variable errno indicates the corresponding error code.

Example

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>

int main(void)
{
    int fd;

    fd = open("/dev/example", O_RDONLY);

    if (fd == -1) {
        printf("Open failed: %s\n", strerror(errno));
        return 1;
    }

    close(fd);

    return 0;
}

This program checks whether the device file can be opened and displays a descriptive error if the operation fails.

12. User-Space and Kernel-Space Data Transfer

A device driver often transfers data between a user application and kernel memory.

The kernel cannot safely assume that a user-space pointer refers to valid, accessible memory. Special functions are provided for transferring data across this boundary.

Important Functions

Function Purpose
copy_to_user() Copies data from kernel space to user space.
copy_from_user() Copies data from user space to kernel space.

These functions return the number of bytes that could not be copied. A return value of zero means the complete requested copy succeeded. They are not ordinary memory-copy functions.

13. Practical Program: Using read() and write()

Objective

Understand how user-space programs use file-related system calls.

Program

#include <stdio.h>
#include <unistd.h>

int main(void)
{
    char buffer[100];
    ssize_t count;

    write(STDOUT_FILENO,
          "Enter a message: ",
          17);

    count = read(STDIN_FILENO,
                 buffer,
                 sizeof(buffer));

    if (count < 0) {
        perror("read");
        return 1;
    }

    write(STDOUT_FILENO,
          "You entered: ",
          13);

    if (count > 0) {
        write(STDOUT_FILENO,
              buffer,
              count);
    }

    return 0;
}

Compile

gcc system_call_demo.c -o system_call_demo

Run

./system_call_demo

Expected Output

Enter a message: Hello Linux
You entered: Hello Linux

The program uses read() and write() to communicate with the terminal through file descriptors.

For production programs, check for partial writes and handle input that fills the buffer without a newline.

14. Practical Exploration Using strace

The strace utility traces system calls made by a program and displays their arguments and return values.

Install strace

sudo apt update
sudo apt install strace

Trace a Command

strace ls

Trace File Operations

strace -e trace=openat,read,write,close ls

Trace a Program

strace ./system_call_demo

Observe how the program uses system calls such as read(), write() and openat().

strace observes system calls made by a process. It is a diagnostic tool, not a replacement for kernel debugging.

15. System Call vs Kernel Function vs Library Function

Feature System Call Kernel Function Library Function
Execution Requests a kernel service through the system call mechanism. Executes inside kernel code. Usually executes in user space.
Purpose Provides access to kernel services. Implements internal kernel functionality. Provides reusable programming functionality.
Example read() kmalloc() printf()
Privilege Enters kernel execution through a controlled mechanism. Runs with kernel privileges. Does not automatically have kernel privileges.

17. Summary

  • A system call provides controlled access to kernel services.
  • System calls connect user space and kernel space.
  • The CPU performs a privileged transition to enter the kernel.
  • Linux provides system calls for files, processes, memory and networking.
  • Device applications commonly use open, read, write, ioctl and close.
  • VFS connects file operations to registered device interfaces.
  • copy_to_user() and copy_from_user() transfer data across the user-kernel boundary.
  • strace helps observe system calls made by applications.
