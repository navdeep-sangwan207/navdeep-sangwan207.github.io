1. Introduction

The Linux kernel is a large software project containing millions of lines of source code. It supports different processor architectures, memory management, process scheduling, filesystems, networking, hardware interfaces and device drivers.

To manage this complexity, the Linux kernel source code is divided into directories. Each directory contains source files and related components responsible for particular kernel functionality.

Understanding this directory structure is important for Linux device driver developers because driver source code, kernel headers and subsystem implementations are located in different parts of the source tree.

2. What Is the Linux Kernel Source Tree?

A kernel source tree is the complete directory structure containing Linux kernel source code, header files, build scripts, documentation and configuration files.

The root directory of the source tree contains several important directories and files.

Example Directory Structure

3. Important Kernel Directories

Directory Purpose

crypto/ Kernel cryptographic algorithms and interfaces.
Documentation/ Kernel documentation and development guides.
drivers/ Device driver implementations.
fs/ Filesystem implementations and VFS-related code.
include/ Kernel header files and interface definitions.

scripts/ Build scripts and development utilities.
security/ Security frameworks and kernel security mechanisms.
sound/ Audio subsystem and sound drivers.
tools/ Supporting tools used for kernel development and testing.
virt/ Virtualization-related kernel code.

4. The arch Directory

The arch/ directory contains architecture-specific kernel code. Different processor architectures have different startup procedures, interrupt controllers, memory management details and low-level hardware interfaces.

Example Structure

arch/
|
|-- arm/
|-- arm64/
|-- x86/
|-- powerpc/
|-- riscv/
|-- mips/
|-- s390/

Purpose

  • Processor-specific initialization.
  • Architecture-specific memory management.
  • Interrupt and exception handling.
  • Low-level processor operations.
  • Architecture-specific system call entry code.

For example, Linux kernel support for ARM64 processors is implemented in the arch/arm64/ directory.

6. The include Directory

The include/ directory contains header files used by different parts of the Linux kernel. Header files provide declarations, data structures, macros, constants and function interfaces.

Example Structure

include/
|
|-- acpi/
|-- asm-generic/
|-- clocksource/
|-- crypto/
|-- drm/
|-- dt-bindings/
|-- keys/
|-- linux/
|-- memory/
|-- net/
|-- rdma/
|-- scsi/
|-- sound/
|-- trace/
|-- uapi/

Important Header Locations

Header Location Purpose
include/linux/ Many internal kernel interfaces and declarations.
include/uapi/ Userspace API header definitions.
include/asm-generic/ Generic architecture-related header definitions.
include/dt-bindings/ Device Tree binding constants and definitions.

Example Kernel Headers

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/slab.h>

These headers provide interfaces commonly used in kernel module and device driver development.

7. The kernel Directory

The kernel/ directory contains important core kernel functionality.

Major Areas

  • Process scheduling.
  • Task management.
  • Kernel synchronization.
  • Timers and time management.
  • Kernel-level resource management.
  • Core system call implementation and support.

Device driver developers interact with many interfaces supported by the core kernel, including scheduling, synchronization and timer facilities.

8. The mm Directory

The mm/ directory contains Linux kernel memory management implementation.

Major Responsibilities

  • Physical memory management.
  • Virtual memory management.
  • Page allocation and management.
  • Memory mapping.
  • Page reclaim and memory pressure handling.
  • Memory-related kernel interfaces.

Device drivers use memory management APIs such as kmalloc(), kfree(), vmalloc() and related allocation functions.

9. The fs Directory

The fs/ directory contains filesystem implementations and code related to the Virtual Filesystem Switch (VFS).

The exact filesystems included depend on the kernel release and configuration.

Important Concepts

  • VFS provides a common interface for filesystem operations.
  • Individual filesystem implementations provide filesystem-specific behavior.
  • Device drivers may interact with filesystem and device-node interfaces.

10. The net Directory

The net/ directory contains the Linux networking stack and protocol implementations.

Major Areas

  • IPv4 and IPv6 networking.
  • TCP and UDP protocols.
  • Network routing.
  • Socket interfaces.
  • Network protocol families.
  • Networking-related kernel infrastructure.

Network device drivers connect physical or virtual network interfaces with the Linux networking subsystem.

11. The Documentation Directory

The Documentation/ directory contains official Linux kernel documentation.

It includes explanations of kernel subsystems, development processes, driver interfaces, coding conventions and hardware-specific topics.

Useful Documentation Areas

  • Documentation/driver-api/ – Driver API documentation.
  • Documentation/devicetree/ – Device Tree documentation.
  • Documentation/core-api/ – Core kernel APIs.
  • Documentation/filesystems/ – Filesystem documentation.
  • Documentation/networking/ – Networking documentation.
  • Documentation/process/ – Kernel development process.

Search Documentation

find Documentation -iname '*driver*'

This command searches for documentation paths containing the word "driver".

12. Important Files in the Kernel Root Directory

File Purpose
Makefile Main entry point for kernel compilation.
Kbuild Build-system rules used by Kbuild.
Kconfig Configuration definitions and menu structure.
COPYING Kernel licensing information.
README General information and build guidance.

Makefile

The top-level Makefile coordinates kernel compilation and invokes the Kbuild system.

Kconfig

Kconfig files define configuration options, their dependencies and their organization in configuration interfaces such as menuconfig.

Kbuild

Kbuild is the Linux kernel build infrastructure. It processes build rules and coordinates compilation of kernel components and modules.

13. Understanding the Kconfig and Kbuild Relationship

Kconfig and Kbuild perform different but related jobs.

Kconfig Files
↓
Configuration Selection
↓
.config File
↓
Kbuild Rules and Makefiles
↓
Compilation of Selected Components
Kconfig Kbuild
Defines configuration options. Defines build rules.
Controls feature selection. Controls compilation and linking.
Creates configuration choices. Builds selected source components.

14. Exploring Kernel Source Code Using Linux Commands

Developers can use standard Linux commands to navigate and inspect the kernel source tree.

Display Current Directory

pwd

List Root Directory Contents

ls

List Driver Directories

ls drivers/

Explore I2C Driver Directory

ls drivers/i2c/

Search for Module Source Files

find drivers -name '*.c'

Search for a Kernel Header

find include -name 'module.h'

Search for a Function Definition or Use

grep -R -n 'module_init' drivers/

For large source trees, targeted searches are generally faster and easier to interpret than searching every file.

15. How Device Driver Developers Use the Source Tree

A Linux device driver developer needs to understand where relevant subsystem interfaces and driver implementations are located.

Example: I2C Driver Development

  • Explore drivers/i2c/ for I2C subsystem implementation.
  • Inspect relevant headers under include/linux/.
  • Study existing I2C client drivers in the kernel source tree.
  • Read the I2C documentation under Documentation/.

Example: GPIO Driver Development

  • Explore drivers/gpio/.
  • Study GPIO-related kernel headers.
  • Review the GPIO subsystem documentation.
  • Understand the GPIO descriptor API.

Example: Character Driver Development

  • Study character-device registration interfaces.
  • Inspect include/linux/cdev.h.
  • Understand file operations interfaces.
  • Review suitable existing character-device implementations.
Existing kernel drivers are valuable learning references. However, do not copy code blindly. Check the kernel version, subsystem conventions, API documentation and licensing requirements.

16. Practical Exercise: Explore the Linux Kernel Source Tree

Objective

Explore the organization of a Linux kernel source tree and identify important directories used in device driver development.

Procedure

  1. Obtain a Linux kernel source tree.
  2. Open the source directory in Ubuntu terminal.
  3. List the top-level directories.
  4. Explore the drivers/ directory.
  5. Locate the I2C and SPI driver directories.
  6. Inspect the include/linux/ directory.
  7. Locate the kernel Makefile and Kconfig files.
  8. Explore the driver API documentation.

Commands

pwd

ls

ls drivers/

ls drivers/spi/

ls Documentation/driver-api/

find drivers -name '*.c' | head

Expected Result

You should be able to identify the main kernel source directories and locate the code, headers and documentation relevant to device driver development.

17. Common Mistakes While Exploring Kernel Source

  • Assuming every device driver is stored in drivers/char/.
  • Confusing kernel source headers with userspace application headers.
  • Assuming directory structures are identical in every kernel release.
  • Ignoring the official kernel documentation.
  • Copying an old driver implementation without checking API compatibility.
  • Confusing Kconfig configuration rules with Kbuild compilation rules.
  • Searching the entire source tree when a targeted search would be sufficient.

18. Summary

  • The Linux kernel source tree organizes kernel code into directories.
  • arch/ contains architecture-specific code.
  • drivers/ contains hardware driver implementations.
  • include/ contains kernel headers and interfaces.
  • kernel/ contains core kernel functionality.
  • mm/ contains memory management implementation.
  • fs/ contains filesystem implementations.
  • net/ contains networking subsystem code.
  • Documentation/ contains kernel documentation.
  • Kconfig defines configuration options.
  • Kbuild manages compilation of kernel components.
  • Understanding the source tree helps developers study and modify device drivers.
