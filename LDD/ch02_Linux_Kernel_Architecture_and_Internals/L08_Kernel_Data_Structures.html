1. Introduction

The Linux kernel manages processes, memory, devices, filesystems, interrupts and many other system resources. To organize and manage this information efficiently, the kernel uses specialized data structures.

Kernel data structures are fundamental building blocks used to store, organize, search and manipulate information inside the kernel.

Device driver developers frequently work with kernel structures such as:

  • struct task_struct
  • struct file
  • struct inode
  • struct file_operations
  • struct cdev
  • struct device
  • struct list_head
  • struct mutex
  • struct work_struct

2. What Is a Kernel Data Structure?

A data structure is a method of organizing data so that it can be accessed and modified efficiently.

In the Linux kernel, data structures are implemented primarily using C structures, pointers, arrays and specialized kernel programming techniques.

Basic C Structure Example

struct device_info
{
    int device_id;
    int status;
    unsigned int speed;
};

This structure groups related device information into one logical object.

Creating a Structure Variable

struct device_info uart_device;

uart_device.device_id = 1;
uart_device.status = 1;
uart_device.speed = 9600;

Device drivers use similar structures to maintain hardware configuration, device state, buffers and resource information.

3. Why Does the Linux Kernel Use Data Structures?

  • To organize system information.
  • To manage multiple processes and threads.
  • To represent hardware devices.
  • To maintain memory-management information.
  • To organize file and filesystem information.
  • To manage linked lists of objects.
  • To implement synchronization.
  • To support efficient searching and scheduling.

5. Process Management – task_struct

Linux represents each task using a structure called struct task_struct.

It contains information needed by the kernel to manage task execution and scheduling.

Information Associated with task_struct

  • Process or task identification.
  • Task execution state.
  • Scheduling information.
  • Parent and child relationships.
  • Memory-management references.
  • File descriptor table information.
  • Signal-handling information.

Current Task

The kernel provides the current macro to access the task structure associated with the currently executing task. 

#include <linux/sched.h>

pr_info("Current PID: %d\n", current->pid);

The current macro is useful in process context, but its meaning must be understood carefully in interrupt-related code. It does not identify the interrupted process as the owner of the interrupt.

6. File Management – struct file

The Linux kernel uses struct file to represent an open file instance.

When an application opens a file or device file, the kernel creates and manages an associated file object.

Important Information

  • File position.
  • File status and mode information.
  • File operation callbacks.
  • Reference information.
  • Private driver data pointer.

Driver Example

static int demo_open(struct inode *inode,
                     struct file *file)
{
    pr_info("Device opened\n");

    return 0;
}

static int demo_release(struct inode *inode,
                        struct file *file)
{
    pr_info("Device closed\n");

    return 0;
}

The kernel passes the relevant file object to driver callbacks. A driver can use file->private_data to associate per-open state with an open file instance.

7. Filesystem Management – struct inode

An inode represents a filesystem object and stores metadata about that object.

Typical Inode Information

  • File type.
  • File permissions.
  • Ownership information.
  • File size.
  • Timestamp information.
  • Filesystem-specific metadata.

In a character device driver, the inode supplied to the open callback can provide information about the device node, including its device number. 

static int demo_open(struct inode *inode,
                     struct file *file)
{
    dev_t device_number = inode->i_rdev;

    pr_info("Device number: %u:%u\n",
            MAJOR(device_number),
            MINOR(device_number));

    return 0;
}

This is useful when a driver supports multiple devices or multiple minor numbers.

8. File Operations – struct file_operations

The struct file_operations structure contains function pointers that connect file operations to driver callbacks.

Common Members

Member Purpose
owner Typically used to identify the module owning the operations.
open Called when a device file is opened.
read Handles read requests.
write Handles write requests.
release Handles closing of an open file instance.
unlocked_ioctl Handles ioctl requests.
llseek Handles file-position changes.

Example

static const struct file_operations demo_fops =
{
    .owner   = THIS_MODULE,
    .open    = demo_open,
    .release = demo_release,
};

This structure associates the driver's open and release callbacks with the corresponding file operations.

9. Character Device – struct cdev

The Linux character-device framework uses struct cdev to represent a character device and associate it with its file operations.

Important Functions

Function Purpose
cdev_init() Initializes a cdev object with file operations.
cdev_add() Adds the character device to the kernel.
cdev_del() Removes the character device from the system.

Example

#include <linux/cdev.h>

static struct cdev demo_cdev;

static void setup_cdev(dev_t dev_number)
{
    cdev_init(&demo_cdev, &demo_fops);

    demo_cdev.owner = THIS_MODULE;

    cdev_add(&demo_cdev, dev_number, 1);
}
This is an illustrative fragment. A complete driver must check the return value of cdev_add(), allocate device numbers and clean up resources correctly.

10. Generic Linked Lists – list_head

Linux provides a generic doubly linked list implementation through struct list_head.

It is widely used throughout the kernel to connect objects dynamically.

Doubly Linked List Structure

Node A
↔
Node B
↔
Node C

Each list node links to the previous and next node.

Basic List Structure

#include <linux/list.h>

struct device_info
{
    int device_id;
    struct list_head list;
};

Declaring a List Head

static LIST_HEAD(device_list);

Adding an Entry

struct device_info *dev;

dev = kzalloc(sizeof(*dev), GFP_KERNEL);

if (dev) {
    dev->device_id = 1;
    INIT_LIST_HEAD(&dev->list);
    list_add(&dev->list, &device_list);
}

Traversing a List

struct device_info *entry;

list_for_each_entry(entry, &device_list, list) {
    pr_info("Device ID: %d\n",
            entry->device_id);
}

The kernel list API provides many operations, including insertion, deletion and safe traversal.

11. Kernel Queues and Buffers

Device drivers frequently need to store data temporarily. For example, a UART driver may buffer received characters until an application reads them.

Common Data Organization Methods

  • Arrays.
  • Linked lists.
  • Ring buffers.
  • Kernel-specific FIFO structures.
  • Queues used by individual kernel subsystems.

12. Kernel Device Model – struct device

Linux provides a device model to represent devices, organize their relationships and connect them to drivers and buses.

The central device-model structure is struct device.

Important Concepts

  • Buses.
  • Device classes.
  • Parent-child relationships.

13. Synchronization Data Structures

Kernel synchronization mechanisms also use data structures to represent locks and coordination objects.

Structure Purpose
struct mutex Provides mutual exclusion for sleepable code.
spinlock_t Provides spinlock synchronization.
struct semaphore Provides semaphore-based synchronization.
wait_queue_head_t Represents a wait queue head.
struct completion Represents a completion synchronization object.

Mutex Example

#include <linux/mutex.h>

static DEFINE_MUTEX(device_mutex);

static void update_device(void)
{
    mutex_lock(&device_mutex);

    /* Access shared device data */

    mutex_unlock(&device_mutex);
}

This example illustrates mutual exclusion. The function must execute in a context where sleeping is permitted.

14. Kernel Workqueue Data Structure

A workqueue allows kernel code to schedule operations for execution by worker threads.

A work item is represented using struct work_struct.

Example

#include <linux/workqueue.h>

static struct work_struct demo_work;

static void demo_work_handler(struct work_struct *work)
{
    pr_info("Work item executed\n");
}

static int __init demo_init(void)
{
    INIT_WORK(&demo_work, demo_work_handler);

    schedule_work(&demo_work);

    return 0;
}

static void __exit demo_exit(void)
{
    cancel_work_sync(&demo_work);
}

module_init(demo_init);
module_exit(demo_exit);

MODULE_LICENSE("GPL");

The work structure contains the information required to manage the scheduled work item.

15. Kernel Data Structure Header Files

Linux provides header files containing definitions and APIs for common kernel structures.

Header File Common Use
linux/sched.h Task and scheduling-related definitions.
linux/fs.h Filesystem and file-operation structures.
linux/cdev.h Character device definitions.
linux/device.h Linux device model definitions.
linux/list.h Linked list implementation.
linux/slab.h Kernel memory allocation interfaces.
linux/mutex.h Mutex definitions and functions.
linux/spinlock.h Spinlock definitions and functions.
linux/workqueue.h Workqueue definitions and functions.
Kernel headers and structure definitions can change between kernel versions. Use the headers corresponding to the target kernel when developing modules.
