1. Introduction

The Linux kernel is configurable and can be compiled according to the requirements of a particular system. Kernel configuration determines which features, subsystems, drivers and options are included in the kernel build.

Kernel compilation is the process of converting kernel source code into executable kernel components.

Device driver developers need to understand kernel configuration and compilation because they may need to build modules against a particular kernel version, enable required features or prepare a custom kernel for testing.

2. What Is Linux Kernel Configuration?

Kernel configuration is the process of selecting which kernel features and components should be enabled, disabled or built as separate modules.

Configuration options are generally represented through the kernel configuration system and stored in a configuration file named .config.

Examples of Configurable Features

  • Processor architecture support.
  • Memory management options.
  • Filesystem support.
  • Networking features.
  • USB device support.
  • Device driver support.
  • Power management.
  • Debugging facilities.

3. What Is the .config File?

The .config file contains the selected configuration options used by the Linux kernel build system.

It is generally located in the root directory of the kernel source tree.

Example Configuration Entries

CONFIG_MODULES=y
CONFIG_USB_SUPPORT=y
CONFIG_NET=y
CONFIG_EXT4_FS=m
# CONFIG_DEBUG_INFO is not set

Meaning of Configuration Values

Value Meaning
y Feature is built into the kernel.
m Feature is built as a loadable kernel module, if supported.
n Feature is disabled.
Not every configuration option supports all three values. Some options are boolean, while others are tristate or use different value types.

4. Built-in Kernel Features vs Loadable Modules

Linux supports two important ways of including functionality in the kernel.

A. Built-in Features

A built-in feature is compiled directly into the kernel image. It is available as part of the kernel after the kernel boots.

B. Loadable Kernel Modules

A loadable kernel module is compiled separately and can be loaded into or removed from a running kernel, subject to dependency, configuration and security restrictions.

Feature Built-in (y) Module (m)
Compilation Included in kernel image Compiled as a separate module
Loading Available during kernel operation Can be loaded dynamically
Removal Cannot be unloaded independently Can be removed when safe and permitted
Typical use Essential kernel functionality Optional drivers and features

5. Kernel Configuration Methods

Linux provides several interfaces for modifying kernel configuration options.

1. make config

Provides a text-based interface that asks configuration questions one after another. 

make config

2. make menuconfig

Provides a menu-based text interface for selecting kernel configuration options. 

make menuconfig

3. make nconfig

Provides an alternative text-based configuration interface with navigation and search features. 

make nconfig

4. make xconfig

Provides a graphical configuration interface. It requires the appropriate graphical development dependencies. 

make xconfig

Comparison

Command Interface
make config Sequential text questions
make menuconfig Menu-based text interface
make nconfig Enhanced text interface
make xconfig Graphical interface

6. Kernel Source Code and Build Requirements

Before compiling a Linux kernel, the required source code and development tools must be available.

Common Requirements

  • Linux kernel source code.
  • GCC compiler.
  • GNU Make.
  • Binutils.
  • Flex and Bison.
  • OpenSSL development libraries for relevant configurations.
  • Other build dependencies required by the selected kernel version.

Ubuntu Build Dependencies

sudo apt update

sudo apt install build-essential \
    libncurses-dev bison flex \
    libssl-dev libelf-dev bc \
    dwarves

The exact dependency list varies with kernel version, architecture and enabled features.

7. Downloading Linux Kernel Source Code

Kernel source code can be obtained from the official Linux kernel source repositories.

The official source website is:

https://www.kernel.org/

Example: Extracting a Downloaded Source Archive

tar -xf linux-source.tar.xz

cd linux-source

The archive name depends on the downloaded kernel release.

Inspect Kernel Source Directory

ls

Common directories include arch, drivers, fs, include, kernel, mm and net.

8. Understanding the Kernel Build Process

The kernel build system processes source code, configuration settings and architecture-specific instructions to generate kernel components.

Kernel Source Code
↓
Configuration (.config)
↓
Kbuild and Make
↓
Compiler and Linker
↓
Kernel Image and Modules

Main Build Stages

  1. Read kernel configuration.
  2. Prepare generated headers and build information.
  3. Compile source files into object files.
  4. Link object files into kernel components.
  5. Build loadable modules when configured.
  6. Generate the final kernel image and supporting artifacts.

9. Important Kernel Build Commands

Prepare Default Configuration

make defconfig

Generates a default configuration for the selected architecture and kernel source tree.

Prepare Configuration from the Running Kernel

cp /boot/config-$(uname -r) .config

Copies the configuration file associated with the currently running Ubuntu kernel, if available.

Update Configuration

make olddefconfig

Uses the existing configuration and assigns default values to newly introduced configuration options.

Prepare Build System

make prepare

Performs preparation steps required for kernel compilation and external module development.

Build Kernel

make -j$(nproc)

Compiles the configured kernel using multiple jobs. The number of jobs is based on the available processing units reported by nproc.

Build Kernel Modules

make modules -j$(nproc)

Install Kernel Modules

sudo make modules_install
Building a complete kernel can consume substantial disk space, memory and CPU time. Do not replace your working Ubuntu kernel unless you understand the installation and recovery process.

10. Kernel Architecture and Cross Compilation

Linux supports multiple processor architectures, including x86, x86-64, ARM and ARM64.

Cross compilation means building software on one architecture for execution on another architecture.

Example

A developer may use an x86-64 Ubuntu computer to compile a Linux kernel for an ARM-based embedded board.

Important Build Variables

Variable Purpose
ARCH Specifies the target kernel architecture.
CROSS_COMPILE Specifies the cross-compiler toolchain prefix.

Example: ARM64 Cross Compilation

make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- defconfig

make ARCH=arm64 \
     CROSS_COMPILE=aarch64-linux-gnu- \
     -j$(nproc)

This example assumes that the appropriate ARM64 cross-compilation toolchain is installed.

The LPC2129 ARM7 microcontroller work in Keil is bare-metal embedded development. It is different from compiling the Linux kernel for an ARM Linux processor.

11. Building an External Kernel Module

Device driver developers frequently build an external module without rebuilding the complete kernel.

External modules must be built against the appropriate configured kernel build tree or prepared kernel headers.

Example Module Makefile

obj-m += hello.o

KDIR := /lib/modules/$(shell uname -r)/build

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

Compile the Module

make

Load the Module

sudo insmod hello.ko

View Kernel Messages

dmesg | tail

Remove the Module

sudo rmmod hello

This workflow uses the running kernel's build directory. The corresponding headers and build configuration must be installed.

12. Kernel Configuration Options for Device Drivers

Several kernel configuration options are particularly important when working with Linux device drivers.

Configuration Option Purpose
CONFIG_MODULES Enables loadable kernel module support.
CONFIG_MODULE_UNLOAD Enables unloading of supported modules.
CONFIG_DEBUG_INFO Enables debug information where supported.
CONFIG_USB Enables USB subsystem support.
CONFIG_I2C Enables I2C subsystem support.
CONFIG_SPI Enables SPI subsystem support.
CONFIG_GPIOLIB Enables GPIO library and subsystem support.
CONFIG_PROC_FS Enables procfs support.
CONFIG_SYSFS Enables sysfs support.

The exact availability and dependencies of these options depend on the kernel version and architecture.

13. Checking the Running Kernel Configuration

Ubuntu systems may expose the running kernel configuration through the /boot directory or through the kernel configuration interface.

Check Kernel Version

uname -r

Check Configuration File

ls /boot/config-$(uname -r)

Search for Module Support

grep CONFIG_MODULES /boot/config-$(uname -r)

Search for I2C Support

grep CONFIG_I2C /boot/config-$(uname -r)

Search for USB Support

grep CONFIG_USB /boot/config-$(uname -r)

If the configuration file is unavailable, check whether the kernel exposes /proc/config.gz. 

zcat /proc/config.gz | grep CONFIG_MODULES
Access to /proc/config.gz requires the appropriate kernel configuration support. It is not available on every distribution.

14. Kernel Compilation Errors

Kernel compilation can fail for several reasons.

Error Possible Cause Action
Missing header files Incomplete dependencies or source tree Install required packages and check the source tree.
Compiler not found GCC or cross-compiler is missing Install the appropriate compiler.
Configuration error Invalid or incomplete configuration Run an appropriate configuration target.
Out of memory Too many parallel build jobs Reduce the number of jobs.
Undefined references Missing symbols or configuration dependencies Check configuration and source dependencies.
Module version mismatch Module built against incompatible kernel headers Build against the target kernel's matching build tree.

15. Practical Exercise in Ubuntu

Objective

Explore the running kernel configuration and understand the steps required to prepare a kernel module build.

Procedure

  1. Open the Ubuntu terminal.
  2. Run uname -r to identify the running kernel.
  3. Check the matching configuration file under /boot.
  4. Search for CONFIG_MODULES.
  5. Check whether the kernel build directory exists.
  6. Inspect the available kernel headers.
  7. Study make menuconfig and the .config file.
  8. Build a simple external module using the matching kernel headers.

Useful Commands

uname -r

ls /boot/config-$(uname -r)

grep CONFIG_MODULES /boot/config-$(uname -r)

ls -l /lib/modules/$(uname -r)/build

ls /usr/src

Expected Result

You should be able to identify the running kernel, inspect its configuration and understand the prerequisites for compiling an external device driver.

16. Important Precautions

  • Always use the correct kernel source or headers.
  • Keep a working kernel available before installing a custom kernel.
  • Verify the target architecture before cross compilation.
  • Check disk space and memory before starting a full kernel build.
  • Do not mix headers from different kernel versions.
  • Test custom kernels in a virtual machine or suitable development system first.
  • Understand Secure Boot and module-signing requirements when loading external modules.

17. Summary

  • Kernel configuration selects kernel features and options.
  • The .config file stores configuration settings.
  • y means built-in, m means module and n means disabled.
  • make menuconfig provides a menu-based configuration interface.
  • GCC, Make and other tools are required for kernel compilation.
  • Kbuild manages kernel compilation.
  • Kernel compilation generates kernel images and modules.
  • Cross compilation targets a different processor architecture.
  • External modules must use compatible kernel build headers.
  • Correct configuration is essential for device driver development.
