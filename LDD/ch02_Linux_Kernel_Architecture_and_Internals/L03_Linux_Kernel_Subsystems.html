1. Introduction

The Linux kernel is a large software system containing many components. To organize its functionality, the kernel is divided into logical groups called kernel subsystems.

Each subsystem is responsible for a particular area of operating-system functionality. Examples include process scheduling, memory management, filesystems, networking and device management.

Linux device drivers interact with several of these subsystems to provide a standard interface between the operating system and hardware.

2. What Is a Kernel Subsystem?

A kernel subsystem is a collection of related kernel components, functions and data structures that work together to provide a specific service.

Examples

  • Process Management: Creates and schedules processes and threads.
  • Memory Management: Manages virtual memory and physical memory.
  • Filesystem Subsystem: Provides access to files and directories.
  • Networking Subsystem: Implements network protocols and socket interfaces.
  • Device Management: Organizes devices, drivers and device models.
  • Block I/O Subsystem: Handles block-oriented storage requests.
  • Interrupt Management: Handles hardware and software interrupt mechanisms.

3. Process Management Subsystem

The process management subsystem manages the execution of processes and threads in the Linux operating system.

Main Responsibilities

  • Process creation and termination.
  • Process scheduling.
  • Context switching.
  • Thread management.
  • Process state management.
  • Inter-process communication support.

Process States

State Description
Running The task is currently executing on a CPU.
Runnable The task is ready to execute and waiting for CPU time.
Interruptible Sleep The task is waiting and can be awakened by a signal.
Uninterruptible Sleep The task is waiting for an event and does not normally wake because of ordinary signals.
Stopped The task has been stopped.
Zombie The task has exited, but its exit status has not yet been collected by its parent.

Useful Linux Commands

ps aux
top
htop

Device drivers may interact with process context, wait queues and scheduling mechanisms. These topics become important when implementing blocking read and write operations.

4. Memory Management Subsystem

The memory management subsystem manages how memory is allocated, mapped, protected and released.

Main Responsibilities

  • Virtual memory management.
  • Physical memory allocation.
  • Page management.
  • Memory mapping.
  • Page fault handling.
  • Memory protection.
  • Kernel memory allocation.

Memory Management in Device Drivers

Device drivers often need memory for buffers, device state structures and data exchanged with hardware.

Common kernel memory allocation functions include:

kmalloc()
kzalloc()
kcalloc()
vmalloc()
kfree()
vfree()
These are kernel-space interfaces. They are not ordinary replacements for user-space functions such as malloc() and free(). Kernel memory allocation is covered in Chapter 12.

5. Filesystem Subsystem

The filesystem subsystem provides a common interface for accessing files, directories and other filesystem objects.

Virtual Filesystem Switch (VFS)

VFS is an abstraction layer that allows applications and kernel components to work with different filesystem implementations through common interfaces.

Examples of Filesystems

  • ext4
  • XFS
  • Btrfs
  • FAT and exFAT
  • procfs
  • sysfs
  • tmpfs

Not every filesystem uses a block device. For example, procfs and sysfs expose kernel information and interfaces rather than ordinary disk-backed file contents.

6. Networking Subsystem

The networking subsystem provides network communication facilities and implements networking protocols.

Main Responsibilities

  • IP packet handling.
  • Network routing.
  • Packet transmission and reception.
  • Network device management.

7. Device Management Subsystem

The device management subsystem provides a framework for representing and managing devices and their relationships within the Linux kernel.

Important Concepts

  • Device model.
  • Device drivers.
  • Device classes.
  • Bus types.
  • Device registration.
  • Driver binding and unbinding.
  • Device attributes.

Example

When an I2C sensor is detected on an I2C bus, the kernel can match the device with a suitable registered driver. The driver's probe callback is then used to initialize the device.

8. Block I/O Subsystem

The block I/O subsystem manages block-oriented input and output operations, commonly used by storage devices.

Examples of Block Devices

  • Hard disk drives.
  • Solid-state drives.
  • USB mass-storage devices.
  • Memory cards.

Main Responsibilities

  • Managing block I/O requests.
  • Scheduling and merging requests where appropriate.
  • Coordinating storage operations.
  • Communicating with storage drivers.

The block layer provides common infrastructure between filesystems and block device drivers.

9. Interrupt Management Subsystem

Interrupt management allows the kernel to respond to events that require attention from the CPU.

Examples of Interrupt Sources

  • UART data reception.
  • Timer expiration.
  • Network packet arrival.
  • GPIO state changes.
  • Storage controller events.

Basic Interrupt Flow

Hardware Generates Interrupt
↓
CPU Receives Interrupt
↓
Linux Interrupt Handling Framework
↓
Registered Interrupt Handler
↓
Deferred Work if Required

Linux drivers can register interrupt handlers using interfaces such as request_irq() and release them using free_irq().

Interrupt context has restrictions. For example, a driver must not perform operations that can sleep inside a hard-interrupt handler.

10. Inter-Process Communication Subsystem

Inter-process communication (IPC) mechanisms allow processes to exchange information and coordinate their activities.

Common IPC Mechanisms

Mechanism Purpose
Pipes Transfer data between related or connected processes.
Signals Notify a process that an event has occurred.
Shared Memory Allow processes to access a shared memory region.
Message Queues Exchange messages between processes.
Semaphores Coordinate access to shared resources.
Sockets Enable communication between processes, including across systems.

Device drivers may expose interfaces that user applications use to communicate with hardware through system calls and device-specific operations.

11. How Kernel Subsystems Work Together

Kernel subsystems are not independent operating-system components. They cooperate to complete operations.

Example: Reading from a Character Device

  1. A user application calls open() on a device file.
  2. The VFS identifies the registered character device interface.
  3. The character driver's open callback may be invoked.
  4. The application calls read().
  5. The driver's read callback processes the request.
  6. The driver may copy data from kernel space to user space.
  7. The read operation returns a result to the application.

↓ open() / read()

↓
VFS
↓

↓

This example demonstrates how the filesystem and device driver interfaces work together.

12. Important Kernel Subsystem Source Directories

Linux kernel source code is organized into directories. The following table lists several important locations.

Directory General Purpose
kernel/ Core kernel facilities, including scheduling-related code.
mm/ Memory management implementation.
fs/ Filesystem and VFS implementation.
net/ Networking stack implementation.
drivers/ Device driver implementations.
block/ Block I/O subsystem code.
include/ Kernel header files and interfaces.
arch/ Architecture-specific kernel code.
ipc/ Inter-process communication implementation.
security/ Security framework and related implementations.
Directory contents can change between kernel versions. These directories identify broad areas of responsibility, not rigid boundaries for every subsystem.

14. Practical Exercise

Objective

Explore Linux kernel subsystems through standard Ubuntu system interfaces.

Procedure

  1. Run uname -r and record the kernel version.
  2. Run lsmod and inspect loaded modules.
  3. Run lsblk to identify block devices.
  4. Run ip link to inspect network interfaces.
  5. Run ps aux to inspect running processes.
  6. Run ls /sys/class to explore device classes.
  7. Inspect kernel messages using sudo dmesg.
  8. Prepare a table mapping each command to the subsystem it helps you explore.

Expected Result

You should be able to identify examples of process, storage, networking, device management and kernel module functionality in a running Linux system.

15. Summary

  • Linux is organized into multiple logical kernel subsystems.
  • Each subsystem provides a specific group of kernel services.
  • Process management handles task execution and scheduling.
  • Memory management controls memory allocation and mapping.
  • VFS provides a common interface for filesystem operations.
  • The networking subsystem handles network communication.
  • The device model organizes devices, buses and drivers.
  • Block I/O manages storage requests.
  • Interrupt management handles hardware events.
  • Subsystems cooperate to provide complete operating-system services.
