1. Introduction

Linux kernel programming is the process of developing software that executes inside the Linux kernel. Unlike ordinary application programs, kernel programs operate with privileged access to system resources and interact directly with kernel subsystems and hardware-management facilities.

Device drivers, kernel modules, filesystem components, networking components and other kernel subsystems are examples of software developed using kernel programming techniques.

Linux kernel development primarily uses the C programming language, along with selected architecture-specific assembly code and other supported tooling.

2. What Is Kernel Programming?

Kernel programming means writing code that runs as part of the operating system kernel or as a loadable kernel module.

The Linux kernel manages important system resources such as:

  • CPU scheduling and process management.
  • Physical and virtual memory.
  • Hardware devices and device drivers.
  • Filesystems and storage operations.
  • Networking and communication.
  • Interrupt handling and synchronization.

3. Why Is Kernel Programming Required?

Application programs cannot directly perform every operation required by an operating system. Sensitive operations must be controlled by the kernel.

Kernel programming is required to:

  • Develop drivers for hardware devices.
  • Implement low-level operating system functionality.
  • Manage device communication.
  • Handle hardware interrupts.
  • Provide kernel interfaces to user applications.
  • Improve or extend kernel functionality.
  • Develop specialized embedded Linux systems.

4. User-Space Programming vs Kernel-Space Programming

Linux separates application execution from privileged kernel execution. This separation helps protect the operating system and its resources.

Feature User-Space Programming Kernel-Space Programming
Execution location User space Kernel space
Privilege Restricted privileges Privileged kernel execution
Typical language C, C++, Python and others Primarily C
Standard C library Normally available Not used as the normal userspace libc
Memory access Restricted to process address space Uses kernel-managed memory and APIs
Error impact Usually affects the application Can affect the entire operating system
Examples Shell, editor, browser Device drivers, kernel modules
Kernel space is privileged execution context, not simply another name for the root user's environment. Running a program with sudo does not turn it into kernel code.

5. Role of the C Programming Language

C is the primary language used for Linux kernel development. It provides low-level control over memory, data structures, pointers and hardware-oriented operations.

Important C concepts for kernel programming include:

  • Variables and data types.
  • Pointers and pointer arithmetic.
  • Structures and unions.
  • Arrays and strings.
  • Functions and function pointers.
  • Bitwise operators.
  • Dynamic memory concepts.
  • Preprocessor directives and macros.

Example: C Structure

struct device_info {
    int device_id;
    int status;
};

int main(void)
{
    struct device_info dev;

    dev.device_id = 10;
    dev.status = 1;

    return 0;
}

Structures are important in kernel programming because kernel APIs use structures to represent devices, files, processes, memory areas and many other objects.

This is an ordinary userspace C example. Kernel code uses kernel-provided types, headers and APIs rather than assuming that all userspace C library facilities are available.

6. Important Characteristics of Kernel Programming

6.1 Privileged Execution

Kernel code executes with privileges required to manage system resources. Incorrect operations can affect the whole system.

6.2 Hardware Interaction

Kernel code can interact with hardware through appropriate kernel subsystems, device drivers and architecture-specific interfaces.

6.3 Concurrency

Kernel code may execute in different contexts, including process context and interrupt context. Multiple CPUs may also access shared data concurrently.

6.4 Memory Management

Kernel programs use kernel memory-management APIs such as kmalloc(), kzalloc() and vmalloc(), according to the requirements of the operation.

6.5 Error Handling

Kernel functions commonly report errors through negative error codes. Developers must check return values and release resources correctly.

6.6 Limited Execution Environment

Kernel code cannot freely use ordinary userspace facilities such as printf(), malloc() or standard file I/O functions. It must use suitable kernel APIs.

8. Introduction to a Kernel Module

A kernel module is a piece of code that can be loaded into or removed from a running Linux kernel, subject to kernel configuration and security restrictions.

Loadable modules allow functionality to be added without rebuilding and rebooting the entire kernel for every change.

Common examples include:

  • Device drivers.
  • Filesystem modules.
  • Network-related modules.
  • Other optional kernel components.

9. Kernel Programming vs Ordinary C Programming

Operation Userspace C Kernel Programming
Print messages printf() printk() or pr_info()
Allocate memory malloc() kmalloc(), kzalloc()
Release allocated memory free() kfree()
Module initialization Usually main() is the program entry point module_init() registers initialization
Module cleanup Program exits through normal process termination module_exit() registers cleanup
Build process GCC or another userspace build toolchain Kernel build system (Kbuild)

The kernel APIs are designed for kernel execution contexts and must be used according to their documented restrictions.

10. First Kernel Module Example

The following example introduces the basic structure of a Linux kernel module.

Source File: hello_kernel.c

#include <linux/module.h>
#include <linux/init.h>

static int __init hello_kernel_init(void)
{
    pr_info("Hello Kernel: Module loaded\n");
    return 0;
}

static void __exit hello_kernel_exit(void)
{
    pr_info("Hello Kernel: Module removed\n");
}

module_init(hello_kernel_init);
module_exit(hello_kernel_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("First Linux kernel module");
MODULE_VERSION("1.0");

Explanation

  • linux/module.h provides module-related declarations and macros.
  • linux/init.h provides initialization and exit annotations.
  • hello_kernel_init() runs when the module is loaded.
  • hello_kernel_exit() runs when the module is removed.
  • pr_info() writes an informational message to the kernel log.
  • module_init() registers the initialization function.
  • module_exit() registers the cleanup function.
  • MODULE_LICENSE() declares the module license.

Makefile

obj-m += hello_kernel.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all and clean must begin with a tab character.

Compile the Module

make

Load the Module

sudo insmod hello_kernel.ko

Check Kernel Messages

sudo dmesg | tail -n 10

Remove the Module

sudo rmmod hello_kernel

Verify Removal Message

sudo dmesg | tail -n 10
Only load test modules on a development system or virtual machine. Kernel code executes with high privileges, and programming errors can crash or destabilize the system.

11. Kernel Programming Execution Contexts

Kernel code can execute in different contexts. Understanding these contexts is essential for writing correct device drivers.

Process Context

Process context is associated with a task or process. Certain operations may sleep or wait when the API and execution conditions permit it.

Interrupt Context

Interrupt context is entered when the kernel handles an interrupt. Code running in hard interrupt context must not perform operations that can sleep.

Softirq and Deferred Work Contexts

Linux also provides mechanisms such as softirqs and workqueues to defer work from interrupt handling. Their execution rules differ, and the appropriate mechanism depends on the operation.

Do not assume every kernel function can be called from every execution context. Always check whether an API may sleep and whether the current context permits it.

12. Safety and Best Practices

  • Test new modules in a virtual machine or dedicated development system.
  • Use kernel APIs instead of ordinary userspace library functions.
  • Check return values from kernel functions.
  • Release allocated resources on error paths and during cleanup.
  • Avoid accessing invalid pointers or memory outside valid objects.
  • Use appropriate synchronization for shared data.
  • Do not sleep in atomic or interrupt context.
  • Follow Linux kernel coding style.
  • Inspect kernel logs during development.
  • Build modules against the intended kernel version and configuration.

14. Lesson Summary

  • Kernel programming develops software that executes inside the Linux kernel.
  • Linux kernel development primarily uses C.
  • Kernel code operates with privileged access to system resources.
  • Device drivers are an important application of kernel programming.
  • Kernel code uses kernel-specific APIs and headers.
  • Kernel modules can be loaded and removed dynamically when supported.
  • Kernel programming requires careful memory, concurrency and error management.
  • Kernel logs are important for debugging.
