1. Introduction

Linux kernel programming uses several specialized data types in addition to the basic C language types. These types help developers write portable and architecture-aware kernel code.

Kernel data types are important when working with memory addresses, device registers, process identifiers, file operations, hardware resources and kernel interfaces.

Many kernel types are defined in Linux kernel headers. They provide consistent meanings across supported architectures and kernel subsystems.

2. Why Does the Linux Kernel Use Special Data Types?

Different processor architectures can have different word sizes and alignment requirements. For example, a 32-bit architecture and a 64-bit architecture do not necessarily represent pointers and machine-sized values in the same number of bits.

Kernel-specific data types help with:

  • Portability across processor architectures.
  • Predictable integer widths.
  • Safe representation of addresses and offsets.
  • Device and hardware resource management.
  • Consistent interfaces between kernel subsystems.
  • Reducing errors caused by incorrect type selection.

3. Standard C Data Types in Kernel Programming

Linux kernel code is written primarily in C, so familiar C data types are still used where appropriate.

Data Type Typical Purpose
char Character or small integer values.
int General integer calculations and return values.
unsigned int Non-negative integer values within its range.
long Integer values whose width is architecture-dependent.
size_t Object sizes and memory lengths.
void * Generic object pointers.

The exact width of types such as int and long depends on the target architecture and ABI. Do not assume every C type has the same width on every Linux system.

4. Fixed-Width Integer Data Types

Linux provides fixed-width integer types for situations where the number of bits matters.

These types are declared in kernel headers such as <linux/types.h>.

Data Type Width Meaning Typical Range
u8 8 bits Unsigned integer 0 to 255
s8 8 bits Signed integer -128 to 127
u16 16 bits Unsigned integer 0 to 65,535
s16 16 bits Signed integer -32,768 to 32,767
u32 32 bits Unsigned integer 0 to 4,294,967,295
s32 32 bits Signed integer -2,147,483,648 to 2,147,483,647
u64 64 bits Unsigned integer 0 to 264 - 1
s64 64 bits Signed integer -263 to 263 - 1

Example

#include <linux/module.h>
#include <linux/init.h>
#include <linux/types.h>

static int __init datatype_init(void)
{
    u8 small_value = 100;
    u16 medium_value = 5000;
    u32 large_value = 100000;
    u64 wide_value = 123456789ULL;

    pr_info("u8 value = %u\n", small_value);
    pr_info("u16 value = %u\n", medium_value);
    pr_info("u32 value = %u\n", large_value);
    pr_info("u64 value = %llu\n",
            (unsigned long long)wide_value);

    return 0;
}

static void __exit datatype_exit(void)
{
    pr_info("Data type module removed\n");
}

module_init(datatype_init);
module_exit(datatype_exit);

MODULE_LICENSE("GPL");

This example demonstrates fixed-width integer declarations and informational kernel logging.

5. Signed and Unsigned Data Types

Signed integer types represent both negative and positive values. Unsigned integer types represent only non-negative values.

Type 8-bit Example Range
Signed s8 -128 to 127
Unsigned u8 0 to 255

Example

s8 temperature = -20;
u8 register_value = 200;

A signed type is appropriate when negative values are meaningful. An unsigned type is useful when the value represents a non-negative quantity, such as a bit field or hardware register value.

Be careful when comparing signed and unsigned values. C's integer conversion rules can produce unexpected results if the types are mixed.

6. size_t Data Type

size_t is an unsigned integer type used to represent the size of an object or the number of bytes in a memory region.

Common uses include:

  • Buffer sizes.
  • Array lengths.
  • Memory allocation sizes.
  • Number of bytes transferred.

Example

#include <linux/module.h>
#include <linux/init.h>
#include <linux/types.h>

static int __init size_demo_init(void)
{
    size_t buffer_size = 1024;

    pr_info("Buffer size: %zu bytes\n", buffer_size);

    return 0;
}

static void __exit size_demo_exit(void)
{
    pr_info("Size demo removed\n");
}

module_init(size_demo_init);
module_exit(size_demo_exit);

MODULE_LICENSE("GPL");

The %zu format specifier is used to print a size_t value with compatible kernel formatting support.

7. ssize_t Data Type

ssize_t is a signed type used for values representing byte counts where an error may also need to be returned.

It is commonly associated with read and write operations. A successful operation may return a non-negative byte count, while an error is represented by a negative value.

Example Concept

ssize_t result;

result = 128;

/* A successful operation transferred 128 bytes. */

result = -EFAULT;

/* An error occurred while accessing user memory. */

Kernel file-operation callbacks such as read() and write() commonly use ssize_t as their return type.

8. pid_t Data Type

pid_t is a type used to represent process identifiers in Linux interfaces.

A process identifier uniquely identifies a process within the relevant PID namespace.

Example

#include <linux/types.h>

pid_t process_id;

Kernel code uses process-related interfaces to obtain information about tasks. The exact API depends on the operation being performed.

9. dev_t Data Type

dev_t represents a device number in Linux. It contains major and minor device-number information.

  • Major number: Identifies the driver or device-number range associated with a device.
  • Minor number: Distinguishes devices or instances handled within that major-number range.

Example

#include <linux/types.h>

dev_t device_number;

Kernel drivers commonly use helper macros such as MAJOR(), MINOR() and MKDEV() to work with device numbers. 

dev_t dev_number;

dev_number = MKDEV(240, 1);

pr_info("Major: %u\n", MAJOR(dev_number));
pr_info("Minor: %u\n", MINOR(dev_number));
The major and minor values in this example are illustrative. A real driver should normally obtain or register a suitable device-number range instead of assuming that a number is free.

10. uintptr_t and phys_addr_t

uintptr_t

uintptr_t is an unsigned integer type capable of representing a converted pointer value when the type is provided by the relevant environment.

phys_addr_t

phys_addr_t is a kernel type used to represent physical addresses. Its width is architecture-dependent.

Physical addresses and ordinary virtual pointers are different concepts. A physical address should not be treated as an ordinary pointer or dereferenced directly. 

#include <linux/types.h>

phys_addr_t physical_address;
Use the kernel's memory-management and I/O mapping APIs when accessing hardware resources. Do not directly dereference arbitrary physical addresses.

11. Kernel-Specific Types and Their Applications

Data Type Typical Application
u8 Byte values and 8-bit register data.
u16 16-bit device values.
u32 32-bit register values and counters.
u64 64-bit counters and values.
size_t Memory and buffer sizes.
ssize_t Byte counts with negative error returns.
pid_t Process identifiers.
dev_t Device numbers.
phys_addr_t Physical memory addresses.
loff_t File offsets and large position values in kernel interfaces.

12. Boolean Data Type in Kernel Programming

The Linux kernel provides the bool type through its headers for Boolean values.

A Boolean variable represents a true or false condition.

Example

#include <linux/types.h>

bool device_ready = true;

if (device_ready) {
    pr_info("Device is ready\n");
}

Boolean values are useful for flags such as device status, initialization state and operation completion.

13. Data Types Used in Device Drivers

Device drivers work with hardware registers, memory buffers, device identifiers and file operations. Appropriate data types must be selected for each purpose.

Example: Register Value

u32 register_value;

register_value = 0x12345678;

Example: Buffer Size

size_t buffer_length = 256;

Example: Device Number

dev_t device_number;

Example: Read Callback Return Type

static ssize_t driver_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *offset
)
{
    return 0;
}

This is an illustrative callback declaration. A complete driver must implement correct data transfer, offset handling and error reporting.

14. Important Rules for Selecting Kernel Data Types

  • Use fixed-width types when an exact bit width is required.
  • Use size_t for object sizes and buffer lengths.
  • Use ssize_t for signed byte counts where errors may be returned.
  • Use dev_t for Linux device numbers.
  • Use pid_t for process identifiers.
  • Use phys_addr_t for physical addresses.
  • Avoid assuming that long has the same width on all architectures.
  • Use appropriate format specifiers when printing values.
  • Check signed and unsigned conversions carefully.
  • Follow the type requirements of the kernel API being used.

15. Common Programming Mistakes

Mistake Why It Is a Problem Better Practice
Using an incorrect integer width May cause truncation or overflow. Choose an appropriate fixed-width type.
Mixing signed and unsigned values Can produce unexpected comparisons. Use compatible types and explicit checks.
Using int for every size May not represent large object sizes correctly. Use size_t for sizes.
Treating physical addresses as pointers Can cause invalid memory access. Use appropriate mapping APIs.
Using incorrect format specifiers Can produce incorrect output. Use format specifiers appropriate to the type.

17. Lesson Summary

  • Linux kernel programming uses standard C types and kernel-specific types.
  • Fixed-width types include u8, u16, u32 and u64.
  • Signed variants include s8, s16, s32 and s64.
  • size_t represents object sizes.
  • ssize_t represents signed byte counts and error results.
  • pid_t represents process identifiers.
  • dev_t represents device numbers.
  • phys_addr_t represents physical addresses.
  • Correct data type selection improves portability and reliability.
