1. Introduction

Header files are an essential part of Linux kernel programming. They provide declarations, data types, function prototypes, macros, constants and structures required by kernel source code.

Linux kernel development uses its own collection of header files. These headers expose kernel-specific interfaces that are not provided by the standard C library.

When developing a kernel module, the programmer includes the appropriate kernel headers to access module initialization, memory management, logging, device structures and other kernel facilities.

2. What Is a Header File?

A header file is a file that contains declarations and definitions that can be included in source files. In C programming, header files normally use the .h extension.

Header files may contain:

  • Function declarations and prototypes.
  • Structure and union definitions.
  • Data type declarations.
  • Macros and constants.
  • Enumeration definitions.
  • Other header-file inclusions.

Simple C Example

Header file: math_demo.h

int add_numbers(int a, int b);

Source file: main.c

#include "math_demo.h"

int add_numbers(int a, int b)
{
    return a + b;
}

The declaration in the header allows source code to use the function with the correct prototype.

3. Why Does the Linux Kernel Have Its Own Header Files?

The Linux kernel operates in a different execution environment from ordinary userspace applications. It requires specialized interfaces for managing hardware, memory, processes, interrupts and devices.

Kernel headers provide:

  • Kernel-specific data types.
  • Kernel function declarations.
  • Module initialization and cleanup interfaces.
  • Memory allocation interfaces.
  • Logging and debugging facilities.
  • Device driver structures and APIs.
  • Architecture-specific definitions where required.

4. Kernel Headers vs Standard C Library Headers

Userspace C programs commonly include standard library headers such as stdio.h and stdlib.h. Kernel modules instead use kernel-provided interfaces.

Userspace Header Common Userspace Purpose Kernel-Space Alternative or Interface
stdio.h Standard input and output printk(), pr_info() and related kernel logging APIs
stdlib.h General utilities and memory allocation Kernel memory APIs such as kmalloc() and kfree()
string.h String and memory operations Kernel string and memory interfaces, commonly declared in linux/string.h
stdint.h Fixed-width integer types Kernel types such as u8, u16, u32 and u64
Kernel programming does not use the normal userspace C library as its runtime. Do not include userspace headers in kernel modules simply because they are familiar from ordinary C programming.

5. Important Linux Kernel Header Files

The following headers are frequently encountered during kernel module and device driver development.

Header File Purpose
linux/module.h Kernel module declarations and module-related macros.
linux/init.h Initialization and exit annotations and related definitions.
linux/kernel.h Common kernel definitions and utility macros.
linux/types.h Kernel data types.
linux/printk.h Kernel logging declarations.
linux/slab.h Slab-based kernel memory allocation interfaces.
linux/string.h Kernel string and memory utility declarations.
linux/fs.h Filesystem and file-operation interfaces used by drivers.
linux/cdev.h Character device registration interfaces.
linux/device.h Device model and device-class interfaces.
linux/errno.h Kernel error-code definitions.
linux/uaccess.h User-space and kernel-space data transfer interfaces.
linux/interrupt.h Interrupt handling interfaces.
linux/io.h Memory-mapped I/O and related access functions.
linux/platform_device.h Platform device and platform driver interfaces.

Not every driver needs all these headers. Include only the headers required by the APIs and types used in the source file.

6. Module Header: linux/module.h

The linux/module.h header provides declarations and macros required for loadable kernel modules.

It is commonly used for:

  • module_init()
  • module_exit()
  • MODULE_LICENSE()
  • MODULE_AUTHOR()
  • MODULE_DESCRIPTION()
  • MODULE_VERSION()

Example

#include <linux/module.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Kernel module example");

7. Initialization Header: linux/init.h

The linux/init.h header provides annotations and definitions associated with kernel initialization and cleanup.

Commonly encountered annotations include:

  • __init – identifies initialization code.
  • __exit – identifies exit or cleanup code.

Example

#include <linux/module.h>
#include <linux/init.h>

static int __init demo_init(void)
{
    pr_info("Module initialized\n");
    return 0;
}

static void __exit demo_exit(void)
{
    pr_info("Module cleanup\n");
}

module_init(demo_init);
module_exit(demo_exit);

MODULE_LICENSE("GPL");

The annotations allow the kernel build system to handle initialization and exit sections appropriately. They do not replace the module lifecycle macros.

8. Data Type Header: linux/types.h

The linux/types.h header defines many fundamental types used throughout kernel interfaces.

Examples include:

  • u8, u16, u32 and u64.
  • s8, s16, s32 and s64.
  • Other types used in kernel interfaces.

Example

#include <linux/module.h>
#include <linux/types.h>

static int __init type_demo_init(void)
{
    u8 status = 1;
    u32 counter = 1000;

    pr_info("Status: %u\n", status);
    pr_info("Counter: %u\n", counter);

    return 0;
}

static void __exit type_demo_exit(void)
{
    pr_info("Type demo removed\n");
}

module_init(type_demo_init);
module_exit(type_demo_exit);

MODULE_LICENSE("GPL");

9. Logging Header: linux/printk.h

The linux/printk.h header provides kernel logging interfaces.

Common logging functions and macros include:

  • printk()
  • pr_info()
  • pr_err()
  • pr_warn()
  • pr_debug()

Example

#include <linux/module.h>
#include <linux/printk.h>

static int __init logging_demo_init(void)
{
    pr_info("Informational message\n");
    pr_warn("Warning message\n");
    pr_err("Error message example\n");

    return 0;
}

static void __exit logging_demo_exit(void)
{
    pr_info("Logging demo removed\n");
}

module_init(logging_demo_init);
module_exit(logging_demo_exit);

MODULE_LICENSE("GPL");

These messages are written to the kernel log buffer and can be inspected using dmesg or appropriate system logging tools.

10. Memory Allocation Header: linux/slab.h

The linux/slab.h header declares commonly used slab allocator interfaces.

Important functions include:

  • kmalloc()
  • kzalloc()
  • kcalloc()
  • kfree()

Example

#include <linux/module.h>
#include <linux/slab.h>

static int __init memory_demo_init(void)
{
    int *value;

    value = kmalloc(sizeof(*value), GFP_KERNEL);

    if (!value)
        return -ENOMEM;

    *value = 100;

    pr_info("Allocated value: %d\n", *value);

    kfree(value);

    return 0;
}

static void __exit memory_demo_exit(void)
{
    pr_info("Memory demo removed\n");
}

module_init(memory_demo_init);
module_exit(memory_demo_exit);

MODULE_LICENSE("GPL");

The allocation is released before initialization returns. If memory were retained for the lifetime of the module, the cleanup function would need to release it.

11. Filesystem Header: linux/fs.h

The linux/fs.h header contains important declarations used by filesystem code and device drivers.

It includes interfaces and structures such as:

  • struct file
  • struct inode
  • struct file_operations
  • Filesystem-related definitions.

Example Declaration

#include <linux/fs.h>

static const struct file_operations driver_fops = {
    .owner = THIS_MODULE,
};

This is only a partial file-operations structure. A complete character driver defines the callbacks required by its interface.

12. User Access Header: linux/uaccess.h

User applications and kernel code operate in different address spaces. A driver must use appropriate kernel interfaces when transferring data between them.

The linux/uaccess.h header provides interfaces such as:

  • copy_to_user()
  • copy_from_user()

Example Declaration

#include <linux/uaccess.h>

/* Copy data from a kernel buffer to a userspace buffer. */
copy_to_user(user_buffer, kernel_buffer, length);

/* Copy data from a userspace buffer to a kernel buffer. */
copy_from_user(kernel_buffer, user_buffer, length);
These functions return the number of bytes that could not be copied. A return value of zero means the complete requested transfer succeeded. Always check the result.

13. Character Device Header: linux/cdev.h

The linux/cdev.h header provides interfaces for registering and managing character devices.

Important interfaces include:

  • struct cdev
  • cdev_init()
  • cdev_add()
  • cdev_del()

Example Declaration

#include <linux/cdev.h>

struct cdev my_cdev;

These interfaces will be studied in detail in the character device driver chapters.

14. Interrupt Header: linux/interrupt.h

The linux/interrupt.h header provides declarations for interrupt handling facilities.

Common interfaces include:

  • request_irq()
  • free_irq()
  • Interrupt handler definitions and related flags.

Example Handler Declaration

#include <linux/interrupt.h>

static irqreturn_t my_interrupt_handler(
    int irq,
    void *dev_id
)
{
    pr_info("Interrupt received\n");

    return IRQ_HANDLED;
}

This is an illustrative handler declaration. Registering an interrupt requires a valid IRQ resource and correct device-specific setup.

15. I/O Header: linux/io.h

The linux/io.h header provides interfaces for accessing memory-mapped I/O resources.

Common interfaces include:

  • ioremap()
  • iounmap()
  • readb(), readw() and readl().
  • writeb(), writew() and writel().

These functions are used for controlled access to device I/O memory. Drivers should normally obtain and map hardware resources through the appropriate subsystem and resource-management interfaces.

Do not treat an ordinary RAM pointer as an I/O memory pointer. Device register access has specific ordering and mapping requirements.

16. How to Find Kernel Header Files in Ubuntu

Kernel headers are installed in version-specific directories on a typical Ubuntu system.

Check the Running Kernel

uname -r

Check Installed Kernel Headers

ls /usr/src/

Inspect the Kernel Build Directory

ls -l /lib/modules/$(uname -r)/build

Locate a Specific Header

find /usr/src -name module.h

Inspect the Kernel Header Tree

ls /usr/src/linux-headers-$(uname -r)/include/linux/

The exact directory layout depends on the installed kernel packages and distribution.

17. How Header Files Are Used During Module Compilation

When a kernel module is compiled, the compiler processes the source file and includes the declarations from required kernel headers.

Kernel Module Source
↓ #include directives
Kernel Header Files
↓ Kbuild and Compiler
Object File
↓ Module Build Process
Kernel Module (.ko)

Kbuild supplies the required kernel build configuration and include paths. External modules should normally be compiled against the build tree corresponding to the target kernel.

Example Makefile

obj-m += header_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all and clean must begin with a tab character.

18. Practical: Creating a Module Using Kernel Headers

Step 1: Create Source File

Create header_demo.c.

#include <linux/module.h>
#include <linux/init.h>
#include <linux/kernel.h>
#include <linux/types.h>
#include <linux/printk.h>

static int __init header_demo_init(void)
{
    u32 count = 500;

    pr_info("Header Demo: Module loaded\n");
    pr_info("Count = %u\n", count);

    return 0;
}

static void __exit header_demo_exit(void)
{
    pr_info("Header Demo: Module removed\n");
}

module_init(header_demo_init);
module_exit(header_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Demonstration of kernel header files");
MODULE_VERSION("1.0");

Step 2: Create Makefile

obj-m += header_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Step 3: Compile

make

Step 4: Load the Module

sudo insmod header_demo.ko

Step 5: Check Kernel Messages

sudo dmesg | tail -n 10

Step 6: Remove the Module

sudo rmmod header_demo

Step 7: Clean Build Files

make clean

Expected Kernel Log Messages

Header Demo: Module loaded
Count = 500
Header Demo: Module removed

These are the messages generated by the example module. Kernel timestamps and other log details may also appear.

19. Common Header File Errors

Error Possible Cause Solution
Header file not found Missing or incorrect kernel headers. Install matching kernel headers and check the build directory.
Unknown type name Required type declaration is unavailable. Include the appropriate kernel header.
Implicit function declaration Missing declaration or incorrect API use. Check the API and include the correct header.
Incompatible pointer type Incorrect pointer or structure type. Check the function prototype and data types.
API signature mismatch Code uses an API signature from a different kernel version. Check the installed kernel headers and current API declaration.

20. Best Practices for Using Kernel Headers

  • Include only the headers required by the source file.
  • Use kernel headers instead of userspace standard-library headers.
  • Compile against the intended kernel build tree.
  • Check API declarations when changing kernel versions.
  • Avoid manually modifying installed kernel headers.
  • Do not assume that every kernel API is available to modules.
  • Use documented kernel interfaces rather than private implementation details.
  • Keep header dependencies clear and organized.
