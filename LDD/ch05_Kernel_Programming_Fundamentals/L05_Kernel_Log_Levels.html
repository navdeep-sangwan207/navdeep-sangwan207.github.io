1. Introduction

Linux kernel logging is used to report information about kernel operations, device drivers, hardware events and system errors. Not all messages have the same importance.

For example, a successful module initialization is an informational event, whereas a failed memory allocation is an error condition.

Linux provides different kernel log levels to classify messages according to their severity and importance. These levels help developers and system administrators understand and filter kernel messages.

2. What Are Kernel Log Levels?

Kernel log levels are priority values associated with messages generated by the Linux kernel.

A log level indicates how important or severe a message is. Higher-priority messages generally represent more serious conditions.

3. Linux Kernel Log Level Constants

Linux defines kernel log levels using constants such as KERN_EMERG, KERN_ALERT and KERN_INFO.

Numeric Priority Constant Meaning
0 KERN_EMERG System is unusable.
1 KERN_ALERT Action must be taken immediately.
2 KERN_CRIT Critical conditions.
3 KERN_ERR Error conditions.
4 KERN_WARNING Warning conditions.
5 KERN_NOTICE Normal but significant conditions.
6 KERN_INFO Informational messages.
7 KERN_DEBUG Debugging messages.
The numeric priorities range from 0 (highest severity) to 7 (lowest severity). The lower the number, the higher the priority.

4. KERN_EMERG – Emergency Level

KERN_EMERG is used for extremely serious conditions where the system is unusable.

It is the highest-priority standard kernel log level. 

printk(KERN_EMERG "Emergency kernel condition\n");

This level is reserved for exceptional system-critical situations, not ordinary driver errors.

5. KERN_ALERT – Alert Level

KERN_ALERT indicates that immediate action is required to address a serious condition. 

printk(KERN_ALERT "Immediate action required\n");

It should be used only when a condition genuinely requires urgent attention.

6. KERN_CRIT – Critical Level

KERN_CRIT is used for critical conditions that may seriously affect system operation. 

printk(KERN_CRIT "Critical driver condition detected\n");

It is more severe than an ordinary error and should be reserved for major failures.

7. KERN_ERR – Error Level

KERN_ERR is used to report errors encountered during kernel or driver execution.

Examples include:

  • Memory allocation failure.
  • Device initialization failure.
  • Hardware communication failure.
  • Invalid device configuration.
printk(KERN_ERR "Device initialization failed\n");

For ordinary driver errors, the pr_err() convenience macro is also commonly used.

8. KERN_WARNING – Warning Level

KERN_WARNING reports a condition that may cause a problem but does not necessarily indicate that an operation has failed. 

printk(KERN_WARNING "Device operating with reduced capability\n");

Warnings can help identify abnormal conditions before they become serious failures.

9. KERN_NOTICE – Notice Level

KERN_NOTICE is used for normal but significant conditions that administrators may want to know about. 

printk(KERN_NOTICE "Driver configuration changed\n");

It is less severe than warning and error messages.

10. KERN_INFO – Information Level

KERN_INFO is used for informational messages that describe normal kernel or driver activity.

Examples include:

  • Driver loaded successfully.
  • Device detected.
  • Configuration initialized.
printk(KERN_INFO "Device driver loaded successfully\n");

The convenience macro pr_info() is commonly used for this purpose.

11. KERN_DEBUG – Debug Level

KERN_DEBUG is intended for detailed diagnostic messages used during development and troubleshooting. 

printk(KERN_DEBUG "Entering device read function\n");

Debug messages can help developers trace the execution flow of a driver.

Debug messages may not be visible in every kernel configuration or logging setup. Kernel dynamic debug provides additional control over selected debug messages.

12. Using Log Levels with printk()

A log level is supplied as a prefix to the message passed to printk().

Example

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>

static int __init loglevel_demo_init(void)
{
    printk(KERN_INFO "Module initialized\n");
    printk(KERN_WARNING "This is a warning message\n");
    printk(KERN_ERR "This is an error message example\n");
    printk(KERN_DEBUG "This is a debug message\n");

    return 0;
}

static void __exit loglevel_demo_exit(void)
{
    printk(KERN_INFO "Module removed\n");
}

module_init(loglevel_demo_init);
module_exit(loglevel_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Kernel log levels demonstration");

This example demonstrates how different priorities can be assigned to messages. The messages are recorded through the kernel logging infrastructure, subject to the active kernel logging configuration.

13. Convenience Logging Macros

Linux provides shorter macros for common logging priorities. These macros make kernel source code easier to read.

Macro Equivalent Log Level Purpose
pr_emerg() Emergency System unusable condition.
pr_alert() Alert Immediate action required.
pr_crit() Critical Critical condition.
pr_err() Error Error reporting.
pr_warn() Warning Warning reporting.
pr_notice() Notice Significant normal event.
pr_info() Information Normal informational output.
pr_debug() Debug Development diagnostics.

Example Using Convenience Macros

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>

static int __init macro_demo_init(void)
{
    pr_info("Driver initialized\n");
    pr_warn("Example warning message\n");
    pr_err("Example error message\n");
    pr_debug("Debugging information\n");

    return 0;
}

static void __exit macro_demo_exit(void)
{
    pr_info("Driver removed\n");
}

module_init(macro_demo_init);
module_exit(macro_demo_exit);

MODULE_LICENSE("GPL");

14. Kernel Console Log Level

Linux maintains a console log-level setting that determines which kernel messages are eligible to be printed to the system console.

This setting is separate from the priority attached to an individual log message.

View Current Console Log Levels

cat /proc/sys/kernel/printk

This command normally displays four integer values:

Position Meaning
First value Current console log level.
Second value Default message log level.
Third value Minimum console log level.
Fourth value Default console log level.

Example Output

4    4    1    7

The values shown on a particular Ubuntu installation may differ.

15. Changing the Console Log Level

The console log level can be changed using the /proc/sys/kernel/printk interface.

Example: Set Console Log Level to 7

sudo dmesg -n 7

This changes the console log-level setting for the running system. It does not delete existing messages or change the priority assigned to individual messages.

Alternative: sysctl

sudo sysctl -w kernel.printk=7
These commands change kernel console logging behavior. Use them carefully on production systems. The setting may be reset by a reboot or another system configuration.

16. Viewing Kernel Messages with dmesg

The dmesg command reads messages from the kernel ring buffer.

Display All Available Messages

dmesg

Display Messages with Human-Readable Priority Labels

sudo dmesg --level=err,warn

Display Messages with Timestamps

dmesg -T

Follow New Messages

sudo dmesg -w

Access restrictions on kernel logs vary by system configuration. Some commands may require sudo.

17. Practical: Kernel Log Level Demonstration

Step 1: Create Source File

Create loglevel_demo.c.

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>

static int __init loglevel_demo_init(void)
{
    pr_info("LogLevel Demo: Information message\n");
    pr_warn("LogLevel Demo: Warning message\n");
    pr_err("LogLevel Demo: Error message\n");
    pr_debug("LogLevel Demo: Debug message\n");

    return 0;
}

static void __exit loglevel_demo_exit(void)
{
    pr_info("LogLevel Demo: Module removed\n");
}

module_init(loglevel_demo_init);
module_exit(loglevel_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Kernel log level practical");

Step 2: Create Makefile

obj-m += loglevel_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Each recipe line in the Makefile must begin with a tab character.

Step 3: Compile

make

Step 4: Load Module

sudo insmod loglevel_demo.ko

Step 5: Inspect Messages

sudo dmesg | tail -n 20

Step 6: Remove Module

sudo rmmod loglevel_demo

Step 7: Clean Build Files

make clean

18. Common Mistakes

Mistake Correction
Using emergency level for normal messages. Choose a priority that reflects the actual severity.
Assuming every message appears on the console. Inspect the kernel log buffer using dmesg.
Confusing message priority with console log level. Understand that message priority and console visibility are separate.
Using debug messages for production information. Use appropriate informational or warning macros.
Logging every repeated operation. Reduce unnecessary logging to avoid excessive output.
Assuming pr_debug() always prints. Check the applicable debug configuration or dynamic debug controls.

19. Best Practices

  • Choose log levels according to the severity of the event.
  • Use pr_info() for normal informational messages.
  • Use pr_err() for genuine errors.
  • Use pr_warn() for abnormal but recoverable conditions.
  • Reserve emergency and alert levels for exceptional situations.
  • Use debug messages for development and troubleshooting.
  • Avoid excessive messages in interrupt handlers and high-frequency paths.
  • Provide enough context to identify the device or operation involved.
  • Do not expose passwords, secrets or sensitive data in logs.

20. Lesson Summary

  • Kernel log levels classify messages by severity.
  • Linux defines eight standard priority levels, from 0 to 7.
  • Priority 0 represents the highest severity.
  • KERN_ERR is used for errors.
  • KERN_WARNING is used for warnings.
  • KERN_INFO is used for informational messages.
  • KERN_DEBUG is used for debugging.
  • Convenience macros include pr_info(), pr_err() and pr_warn().
  • The console log level controls which messages are printed to the console.
  • dmesg is used to inspect kernel log messages.
