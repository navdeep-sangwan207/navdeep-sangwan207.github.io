1. Introduction

Return values and error codes are fundamental concepts in Linux kernel programming. Kernel functions use return values to communicate whether an operation completed successfully or failed.

Device drivers depend on this mechanism to report the status of operations such as:

  • Module initialization.
  • Memory allocation.
  • Device registration.
  • Hardware communication.
  • File operations.
  • Resource acquisition and release.

Understanding return-value conventions helps developers write reliable drivers and correctly interpret failures.

2. What Is a Return Value?

A return value is the value sent back by a function to the code that called it.

Example in C

int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    int result;

    result = add(10, 20);

    printf("Result = %d\n", result);

    return 0;
}

Output:

Result = 30

In kernel programming, return values are also used to report success, failure, byte counts and other operation-specific results.

3. Success and Failure Conventions in Kernel Functions

Many kernel functions that return an integer status follow this common convention:

Return Value Meaning
0 Operation completed successfully.
< 0 Operation failed; the value represents a negative error code.
> 0 May represent a valid result, count or another function-specific status.
This is a common convention, not a universal rule for every kernel API. Always check the documentation and return-value contract of the specific function.

4. How Negative Error Codes Work

Linux defines standard error numbers. Kernel code commonly returns their negative values to indicate failures.

For example, the standard error number for invalid arguments is EINVAL. Kernel code normally reports this failure as -EINVAL. 

#include <linux/errno.h>

static int check_value(int value)
{
    if (value < 0)
        return -EINVAL;

    return 0;
}

The caller can check the result and decide what action to take. 

int ret;

ret = check_value(-5);

if (ret < 0)
    pr_err("Invalid value\n");
else
    pr_info("Valid value\n");

5. Common Linux Kernel Error Codes

Error Code Meaning Example
-EINVAL Invalid argument Unsupported parameter.
-ENOMEM Out of memory Allocation failure.
-ENODEV No such device Required device unavailable.
-EBUSY Device or resource busy Resource already in use.
-EIO Input/output error Failed hardware I/O.
-EFAULT Bad address Invalid userspace address.
-ETIMEDOUT Operation timed out Hardware did not respond in time.
-ENOENT No such entry Requested object not found.
-EACCES Permission denied Access is not permitted.
-EEXIST Already exists Duplicate resource or entry.
-ENOSPC No space left Insufficient capacity for an operation.

Error codes allow different kernel components to communicate failures consistently.

6. Returning Error Codes from Module Initialization

A module initialization function returns an integer. It returns zero when initialization succeeds and a negative error code when initialization fails.

Example

#include <linux/module.h>
#include <linux/init.h>
#include <linux/errno.h>
#include <linux/printk.h>

static int __init return_demo_init(void)
{
    int status = -1;

    if (status < 0) {
        pr_err("Initialization failed\n");
        return -EINVAL;
    }

    pr_info("Initialization successful\n");

    return 0;
}

static void __exit return_demo_exit(void)
{
    pr_info("Module removed\n");
}

module_init(return_demo_init);
module_exit(return_demo_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Return value demonstration");

Since the demonstration condition is true, initialization returns -EINVAL. The module will not be successfully loaded.

7. Checking Return Values of Kernel Functions

A driver should inspect the return value of an operation before proceeding to the next step.

Example: Checking a Memory Allocation

char *buffer;

buffer = kmalloc(256, GFP_KERNEL);

if (!buffer) {
    pr_err("Memory allocation failed\n");
    return -ENOMEM;
}

pr_info("Memory allocation successful\n");

kfree(buffer);

The pointer-returning kmalloc() API uses NULL to indicate allocation failure. It does not return a negative integer error code.

8. Return Values in Character Device Operations

Character device drivers implement callbacks through the file_operations structure. Different callbacks have different return-value conventions.

Callback Return-Value Meaning
open() Zero on success; negative error code on failure.
release() Zero on success; negative error code on failure.
read() Number of bytes read; zero indicates end-of-file; negative value indicates an error.
write() Number of bytes written; negative value indicates an error.
unlocked_ioctl() Operation-specific result, commonly zero on success and negative on failure.
llseek() New file position on success; negative error code on failure.
Return values must follow the contract of each callback. For example, a successful read callback normally returns the number of bytes transferred, not simply zero.

9. Return Values in read() and write() Operations

The read and write operations use byte counts to communicate transfer progress.

Read Operation

  • Positive value: number of bytes successfully read.
  • Zero: end-of-file or no more data currently available, according to the interface.
  • Negative value: error code.

Write Operation

  • Positive value: number of bytes successfully written.
  • Zero: no bytes were written.
  • Negative value: error code.

A callback may transfer fewer bytes than requested. This is called a partial transfer. Userspace programs should be prepared to handle it.

Userspace Requests 100 Bytes
↓
Driver Transfers 60 Bytes
↓
Callback Returns 60

10. Return Values from copy_to_user() and copy_from_user()

These functions transfer data between userspace and kernel-space memory.

Function Direction
copy_to_user() Kernel space to userspace.
copy_from_user() Userspace to kernel space.

Both functions return the number of bytes that were not copied. A return value of zero indicates that the entire requested transfer succeeded.

Example

unsigned long not_copied;

not_copied = copy_to_user(user_buffer,
                          kernel_buffer,
                          length);

if (not_copied != 0) {
    pr_err("Unable to copy all requested data\n");
    return -EFAULT;
}

In a real read callback, a partial copy may require more careful handling so that the number of bytes actually transferred is reported correctly.

11. Error Codes and Userspace Applications

Kernel error values and userspace error reporting are related, but they are not identical.

When a system call fails, userspace generally sees a return value indicating failure and the positive error number is made available through errno.

Kernel Convention Userspace Convention
-EINVAL System call fails and errno is set to EINVAL.
-ENOMEM System call fails and errno is set to ENOMEM.
-EFAULT System call fails and errno is set to EFAULT.

Userspace C Example

#include <stdio.h>
#include <fcntl.h>
#include <errno.h>
#include <string.h>
#include <unistd.h>

int main(void)
{
    int fd;

    fd = open("/dev/example", O_RDONLY);

    if (fd < 0) {
        printf("Open failed: %s\n", strerror(errno));
        return 1;
    }

    close(fd);

    return 0;
}

This example demonstrates userspace error reporting. It requires a corresponding device node and a driver that implements the relevant file operations.

12. Special Return-Value Conventions

Not every kernel API returns a simple zero or negative error code. Some functions return pointers, counts, flags or encoded error pointers.

12.1 Pointer-Returning Functions

Functions such as kmalloc() return a pointer. A NULL pointer indicates failure. 

buffer = kmalloc(128, GFP_KERNEL);

if (!buffer)
    return -ENOMEM;

12.2 Functions Returning Counts

Functions such as read() and write() callbacks commonly return byte counts on success.

12.3 Error Pointers

Some kernel APIs return pointers that may encode error values. Kernel code uses helper macros such as IS_ERR() and PTR_ERR() to test and extract these errors. 

#include <linux/err.h>

ptr = some_kernel_function();

if (IS_ERR(ptr)) {
    ret = PTR_ERR(ptr);
    return ret;
}
some_kernel_function() is a placeholder, not a real API. Use error-pointer checks only for functions documented to return error pointers. Do not assume every invalid pointer is an encoded error pointer.

13. Difference Between NULL and Negative Error Codes

Feature NULL Negative Error Code
Type Null pointer value. Negative integer.
Common use Pointer-returning functions. Integer-returning functions.
Example kmalloc() failure. -ENOMEM, -EINVAL.
Check if (!ptr) if (ret < 0)

Always use the error-reporting convention specified by the function being called.

14. Practical Kernel Module Example

This example demonstrates returning success or failure from a module initialization function.

Source Code: return_codes.c

#include <linux/module.h>
#include <linux/init.h>
#include <linux/slab.h>
#include <linux/errno.h>
#include <linux/printk.h>

static char *buffer;

static int __init return_codes_init(void)
{
    buffer = kmalloc(128, GFP_KERNEL);

    if (!buffer) {
        pr_err("Allocation failed\n");
        return -ENOMEM;
    }

    pr_info("Memory allocation successful\n");

    return 0;
}

static void __exit return_codes_exit(void)
{
    kfree(buffer);
    buffer = NULL;

    pr_info("Memory released\n");
}

module_init(return_codes_init);
module_exit(return_codes_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Return values and error codes example");

Makefile

obj-m += return_codes.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Use a tab character before each recipe command in the Makefile.

Compile and Load

make
sudo insmod return_codes.ko
sudo dmesg | tail -n 15

Remove the Module

sudo rmmod return_codes
sudo dmesg | tail -n 15

Expected Messages

Memory allocation successful
Memory released

The allocation failure message appears only if allocation fails. The exact kernel log also contains timestamps and other system messages.

15. Best Practices

  • Understand the return-value contract of every kernel API.
  • Check return values before using operation results.
  • Use appropriate negative error codes.
  • Do not return zero when an operation has failed.
  • Distinguish pointer failures from integer error returns.
  • Handle partial read and write transfers correctly.
  • Release resources when initialization fails.
  • Use IS_ERR() and PTR_ERR() only for error-pointer APIs.
  • Report useful diagnostic messages.
  • Follow the documented callback return conventions.

16. Lesson Summary

  • A return value communicates a function's result.
  • Many kernel functions use zero for success and negative values for failure.
  • Negative error codes describe specific failure conditions.
  • Pointer-returning functions may use NULL or error pointers to report failure.
  • Character driver callbacks have operation-specific return conventions.
  • Read and write callbacks commonly return byte counts.
  • copy_to_user() and copy_from_user() return bytes not copied.
  • Userspace normally receives errors through errno.
