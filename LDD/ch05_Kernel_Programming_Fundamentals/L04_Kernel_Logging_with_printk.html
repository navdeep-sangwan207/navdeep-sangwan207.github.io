1. Introduction

Logging is an important part of Linux kernel and device driver development. Developers need a way to report information about module loading, device initialization, hardware operations, errors and unexpected conditions.

In userspace C programming, developers commonly use printf() to display messages on the terminal. Kernel code cannot use the ordinary userspace printf() function.

Linux provides the printk() function for writing messages to the kernel log buffer.

2. What Is printk()?

printk() is a kernel logging function. It allows kernel code and loadable kernel modules to record messages in the kernel log buffer.

It is useful for:

  • Reporting module initialization and cleanup.
  • Displaying device initialization information.
  • Reporting errors and warnings.
  • Debugging kernel module execution.
  • Tracking driver operations.
  • Recording hardware and resource-related events.

Basic Syntax

printk("Message\n");

The newline character \n terminates the message line. It is normally included in logging messages.

3. printk() vs printf()

Feature printf() printk()
Environment Userspace applications Linux kernel
Purpose Formatted output Kernel logging
Output destination Usually standard output Kernel log buffer
Header stdio.h Kernel logging declarations
Typical use Application messages Kernel and driver messages
Kernel messages do not automatically appear in the terminal where a module was loaded. Use tools such as dmesg or the system journal to inspect them.

4. Header Files Required for Kernel Logging

Kernel logging interfaces are declared through kernel headers. A module commonly includes: 

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>
  • linux/module.h provides module-related declarations and macros.
  • linux/init.h provides initialization and exit annotations.
  • linux/printk.h provides kernel logging declarations.

Other kernel headers may expose logging macros indirectly. Explicitly including the appropriate header makes the source dependencies clearer.

5. First Kernel Module Using printk()

The following example prints a message when the module is loaded and another message when it is removed.

Source Code: printk_demo.c

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>

static int __init printk_demo_init(void)
{
    printk("printk Demo: Module loaded\n");

    return 0;
}

static void __exit printk_demo_exit(void)
{
    printk("printk Demo: Module removed\n");
}

module_init(printk_demo_init);
module_exit(printk_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic printk logging example");

Explanation

  1. linux/module.h provides module-related definitions.
  2. linux/init.h provides initialization and exit annotations.
  3. printk() writes a message to the kernel log.
  4. module_init() registers the initialization function.
  5. module_exit() registers the cleanup function.
  6. MODULE_LICENSE() declares the module license.

6. Kernel Log Buffer

Kernel messages are recorded in a kernel-managed log buffer. This buffer stores messages generated by kernel subsystems, drivers and modules.

Kernel Module
↓
printk()
↓
Kernel Log Buffer
↓
dmesg / System Journal

The dmesg command displays messages from the kernel ring buffer. System logging services may also collect and store kernel messages.

View Kernel Messages

dmesg

Display Recent Messages

sudo dmesg | tail -n 20

Follow New Kernel Messages

sudo dmesg -w

7. Formatted Output Using printk()

printk() supports formatted output using format specifiers, similar to the familiar formatting style used in C.

Specifier Purpose
%d Signed decimal integer.
%u Unsigned decimal integer.
%x Unsigned hexadecimal integer.
%o Unsigned octal integer.
%c Character.
%s String.
%p Pointer representation.
%zu size_t value.
%lld Signed long long integer.

Example

int temperature = 35;
unsigned int counter = 100;
char status = 'A';

printk("Temperature = %d\n", temperature);
printk("Counter = %u\n", counter);
printk("Status = %c\n", status);

The format specifier must match the type of the corresponding argument. Incorrect formatting can produce warnings or incorrect output.

8. Printing Integer Values

Integer values are frequently used in device drivers to represent counters, register values, device states and error information.

Example

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>

static int __init integer_demo_init(void)
{
    int signed_value = -25;
    unsigned int unsigned_value = 250;
    unsigned int register_value = 0xAB;

    printk("Signed value = %d\n", signed_value);
    printk("Unsigned value = %u\n", unsigned_value);
    printk("Register value = 0x%X\n", register_value);

    return 0;
}

static void __exit integer_demo_exit(void)
{
    printk("Integer demo removed\n");
}

module_init(integer_demo_init);
module_exit(integer_demo_exit);

MODULE_LICENSE("GPL");

9. Printing Strings

Kernel logging can also display string information, such as device names, driver states and messages.

Example

char device_name[] = "VirtualDevice";

printk("Device name: %s\n", device_name);

Ensure that the string pointer is valid and that the string is properly terminated before using it in a logging statement.

10. Printing Pointer Values

The %p format specifier is used for pointer representations in kernel logging.

Example

int value = 100;
int *ptr = &value;

printk("Pointer address: %p\n", ptr);

Kernel pointer formatting has additional conventions and security-related restrictions. For example, ordinary pointer output may be restricted or hashed. Use specialized format specifiers for particular kernel objects when required.

11. printk() Return Value

printk() returns an integer value indicating the number of characters printed, with kernel-specific details about the returned count.

In ordinary driver logging, developers generally use it to record messages rather than relying on its return value for application-style output processing. 

int result;

result = printk("Kernel logging example\n");

12. printk() in Device Driver Development

Device drivers use logging to report important events throughout their lifecycle.

Driver Stage Example Log Message
Module loading Driver module loaded.
Device initialization Device initialized successfully.
Resource allocation Memory allocation failed.
Open operation Device file opened.
Read operation Read request received.
Write operation Write request received.
Cleanup Device resources released.

Logging should be useful and selective. Repeated messages in frequently executed paths can create excessive log output and affect system performance.

13. printk() vs pr_info() and Other Logging Macros

Linux provides convenient logging macros built around the kernel logging infrastructure.

Logging Interface Typical Purpose
printk() General kernel logging with an explicit log-level prefix when needed.
pr_info() Informational messages.
pr_err() Error messages.
pr_warn() Warning messages.
pr_debug() Debug messages, subject to kernel debug configuration.

These macros are commonly preferred because their names communicate the intended severity of the message. The next lesson studies kernel log levels in detail.

14. Practical: Create a Kernel Logging Module

Step 1: Create Source File

Create logging_demo.c.

#include <linux/module.h>
#include <linux/init.h>
#include <linux/printk.h>

static int __init logging_demo_init(void)
{
    int device_id = 10;
    unsigned int register_value = 0x55;

    printk("Logging Demo: Module loaded\n");
    printk("Device ID = %d\n", device_id);
    printk("Register value = 0x%X\n", register_value);

    return 0;
}

static void __exit logging_demo_exit(void)
{
    printk("Logging Demo: Module removed\n");
}

module_init(logging_demo_init);
module_exit(logging_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Kernel printk demonstration");

Step 2: Create Makefile

obj-m += logging_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Use a tab character at the beginning of each recipe line in the Makefile.

Step 3: Compile the Module

make

Step 4: Load the Module

sudo insmod logging_demo.ko

Step 5: View Kernel Messages

sudo dmesg | tail -n 10

Step 6: Remove the Module

sudo rmmod logging_demo

Step 7: Clean the Build Directory

make clean

Expected Messages

Logging Demo: Module loaded
Device ID = 10
Register value = 0x55
Logging Demo: Module removed

Kernel timestamps and additional system messages may appear around these lines.

15. Common printk() Problems

Problem Possible Reason Solution
Message not visible Looking at the wrong output destination or insufficient log visibility. Inspect using dmesg or system journal.
Incorrect printed value Wrong format specifier. Match the format specifier to the argument type.
Too many messages Logging inside a frequently executed path. Reduce logging frequency and use suitable log levels.
Compilation warning Incorrect format string or argument type. Check compiler diagnostics and format requirements.
Debug message absent Debug logging may not be enabled. Check dynamic debug and relevant kernel configuration.

16. Best Practices for Kernel Logging

  • Use pr_info() for normal informational messages.
  • Use pr_err() for actual errors.
  • Use pr_warn() for warning conditions.
  • Use debug logging for detailed development diagnostics.
  • Include useful context such as device identifiers where appropriate.
  • Avoid logging repeatedly in high-frequency operations.
  • Do not expose sensitive information in kernel logs.
  • Use correct format specifiers for all arguments.
  • Remove unnecessary diagnostic messages before production deployment.
  • Do not treat a log message as a substitute for proper error handling.

17. Lesson Summary

  • printk() is a kernel logging function.
  • It records messages in the kernel log buffer.
  • Kernel modules use logging to report initialization, errors and driver activity.
  • printk() supports formatted output.
  • Format specifiers must match the argument types.
  • dmesg can display kernel log messages.
  • pr_info(), pr_err() and pr_warn() provide convenient logging interfaces.
  • Excessive logging should be avoided.
