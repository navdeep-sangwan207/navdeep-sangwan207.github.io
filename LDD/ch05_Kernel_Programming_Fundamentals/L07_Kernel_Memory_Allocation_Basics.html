1. Introduction

Memory management is an important part of Linux kernel and device driver development. A driver often needs memory to store device information, configuration parameters, buffers, counters and other runtime data.

In userspace C programming, dynamic memory is commonly allocated using malloc() and released using free().

Kernel code cannot use the ordinary userspace malloc() and free() functions. Linux provides its own memory allocation interfaces for kernel components.

2. What Is Kernel Memory Allocation?

Kernel memory allocation is the process of reserving memory for kernel components during system operation.

Device drivers may require memory for:

  • Device-specific data structures.
  • Temporary data buffers.
  • Communication packets.
  • Device configuration information.
  • Internal driver state.
  • Data received from or transmitted to hardware.

3. Userspace vs Kernel-Space Memory Allocation

Feature Userspace Kernel Space
Common allocation API malloc() kmalloc()
Memory release free() kfree()
Zero-initialized allocation calloc() kzalloc() or kcalloc()
Execution environment Userspace process Kernel code
Memory management Userspace allocator and virtual memory system Kernel memory management subsystem
Never call userspace malloc() or free() directly from kernel module code.

4. Why Do Device Drivers Need Dynamic Memory?

Some drivers cannot determine their complete memory requirements at compile time. The amount of memory required may depend on device configuration or runtime conditions.

Example Situations

  • A driver allocates a buffer based on a device's reported capacity.
  • A character driver stores data in a dynamically allocated buffer.
  • A driver creates an internal structure for each detected device.
  • A communication driver manages variable-sized data.

Dynamic allocation allows a driver to request memory when needed and release it when it is no longer required.

5. Kernel Memory Allocation Functions

Linux provides several memory allocation interfaces. Different functions are suitable for different requirements.

Function Purpose
kmalloc() Allocates physically contiguous memory for a requested small allocation.
kfree() Releases memory allocated using compatible kernel allocation APIs.
kzalloc() Allocates memory and initializes it to zero.
kcalloc() Allocates an array and initializes the allocated memory to zero.
vmalloc() Allocates virtually contiguous memory that may not be physically contiguous.
vfree() Releases memory allocated using vmalloc().

The following lessons and the dedicated Kernel Memory Management chapter will examine these functions in greater detail.

6. What Is kmalloc()?

kmalloc() is a commonly used kernel function for allocating a block of memory.

Syntax

void *kmalloc(size_t size, gfp_t flags);
Parameter Description
size Number of bytes requested.
flags Allocation behavior and memory-reclaim constraints.

kmalloc() returns a pointer to the allocated memory when successful. It returns NULL if allocation fails.

Example

char *buffer;

buffer = kmalloc(100, GFP_KERNEL);

if (!buffer) {
    pr_err("Memory allocation failed\n");
    return -ENOMEM;
}

The returned memory must be released when it is no longer required.

7. What Is GFP_KERNEL?

GFP stands for Get Free Pages. GFP allocation flags describe the conditions under which the kernel should attempt to allocate memory.

GFP_KERNEL is a common allocation flag for normal kernel allocations made in contexts where sleeping is permitted. 

buffer = kmalloc(256, GFP_KERNEL);

An allocation using GFP_KERNEL may sleep while the kernel attempts to obtain memory.

Do not use GFP_KERNEL in atomic contexts, such as an ordinary interrupt handler, where sleeping is not allowed. Allocation flags are studied in detail in Chapter 12 – Kernel Memory Management.

8. What Is kfree()?

kfree() releases memory that was previously allocated using a compatible kernel allocation API.

Syntax

void kfree(const void *objp);

Example

char *buffer;

buffer = kmalloc(100, GFP_KERNEL);

if (!buffer) {
    return -ENOMEM;
}

/* Use the allocated memory. */

kfree(buffer);
buffer = NULL;

Setting the pointer to NULL after releasing memory is a useful local programming practice. It does not replace proper lifetime management.

9. Memory Allocation Failure

Kernel memory allocation can fail. A driver must always check the returned pointer before accessing allocated memory.

Incorrect Approach

char *buffer;

buffer = kmalloc(100, GFP_KERNEL);

buffer[0] = 'A';

This code does not check whether the allocation succeeded. If kmalloc() returns NULL, accessing the pointer can cause a kernel fault.

Correct Approach

char *buffer;

buffer = kmalloc(100, GFP_KERNEL);

if (!buffer) {
    pr_err("Unable to allocate memory\n");
    return -ENOMEM;
}

buffer[0] = 'A';

kfree(buffer);

11. Memory Leak in Kernel Programming

A memory leak occurs when allocated memory is no longer needed but is not released.

Example of a Memory Leak

static int __init leak_demo_init(void)
{
    char *buffer;

    buffer = kmalloc(1024, GFP_KERNEL);

    if (!buffer)
        return -ENOMEM;

    /* Memory is not released. */

    return 0;
}

If the module loads successfully, the allocated memory remains reserved even though the driver has no remaining need for it.

Correct Resource Management

static char *buffer;

static int __init memory_demo_init(void)
{
    buffer = kmalloc(1024, GFP_KERNEL);

    if (!buffer)
        return -ENOMEM;

    pr_info("Memory allocated successfully\n");

    return 0;
}

static void __exit memory_demo_exit(void)
{
    kfree(buffer);
    buffer = NULL;

    pr_info("Memory released\n");
}

The example stores the pointer in module-level state so the cleanup function can release the allocation.

12. Kernel Memory Allocation vs Stack Allocation

Feature Stack Allocation Dynamic Kernel Allocation
Allocation Automatic when entering a function or scope. Requested through kernel allocation APIs.
Lifetime Limited by function or scope lifetime. Managed explicitly by the driver.
Typical use Small temporary local variables. Runtime data structures and buffers.
Risk Stack overflow if excessive stack space is used. Leaks or allocation failure if not managed correctly.
Kernel stacks are limited. Avoid large local arrays and large automatic structures in kernel functions.

13. Basic Kernel Memory Allocation Example

This module allocates a buffer during initialization, uses it to store a message and releases it during module cleanup.

Source Code: memory_basic.c

#include <linux/module.h>
#include <linux/init.h>
#include <linux/slab.h>
#include <linux/printk.h>
#include <linux/errno.h>
#include <linux/string.h>

static char *buffer;

static int __init memory_basic_init(void)
{
    buffer = kmalloc(100, GFP_KERNEL);

    if (!buffer) {
        pr_err("Memory allocation failed\n");
        return -ENOMEM;
    }

    strcpy(buffer, "Linux Kernel Memory");

    pr_info("Allocated memory: %s\n", buffer);

    return 0;
}

static void __exit memory_basic_exit(void)
{
    kfree(buffer);
    buffer = NULL;

    pr_info("Allocated memory released\n");
}

module_init(memory_basic_init);
module_exit(memory_basic_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic kernel memory allocation example");

Explanation

  1. linux/slab.h provides slab allocator interfaces including kmalloc() and kfree().
  2. kmalloc() requests 100 bytes of memory.
  3. GFP_KERNEL specifies a normal sleepable allocation context.
  4. The returned pointer is checked against NULL.
  5. strcpy() stores a message in the allocated buffer.
  6. The cleanup function releases the memory using kfree().
The example uses a fixed, short source string that fits within the allocated buffer. In production code, use bounded operations and validate all lengths when handling variable input.

14. Makefile for the Practical

Create a file named Makefile in the same directory as memory_basic.c.

obj-m += memory_basic.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

Use a tab character at the beginning of each recipe line in the Makefile.

Compile the Module

make

Load the Module

sudo insmod memory_basic.ko

Inspect Kernel Messages

sudo dmesg | tail -n 15

Remove the Module

sudo rmmod memory_basic

Clean the Build Directory

make clean

After loading the module, the kernel log should contain a message similar to:

After removing the module, the log should contain:

Actual output may include timestamps and unrelated kernel messages.

16. Important Memory Management Rules

  • Always check whether an allocation succeeded.
  • Release memory when it is no longer required.
  • Do not free the same allocation twice.
  • Do not access memory after it has been freed.
  • Do not use an uninitialized pointer.
  • Use the correct release function for each allocation API.
  • Consider execution context before choosing allocation flags.
  • Keep track of ownership and lifetime of allocated memory.
  • Avoid unnecessarily large allocations.
  • Handle partial initialization failures correctly.

17. Common Errors and Their Solutions

Error Cause Solution
NULL pointer access Allocation result was not checked. Check the returned pointer before using it.
Memory leak Allocated memory was not released. Release resources in the cleanup path.
Double free The same allocation was released more than once. Maintain clear ownership and release exactly once.
Use-after-free Accessing memory after it was released. Stop using the pointer after release and coordinate concurrent access.
Allocation failure Insufficient suitable memory or allocation constraints. Handle failure and return an appropriate error.
Sleeping in atomic context Using a sleepable allocation flag in a non-sleepable context. Choose an appropriate allocation strategy for that context.

18. Lesson Summary

  • Kernel memory allocation reserves memory for kernel components.
  • Kernel code uses kernel allocation APIs instead of userspace malloc().
  • kmalloc() allocates a memory block.
  • kfree() releases compatible allocations.
  • GFP_KERNEL is commonly used in sleepable contexts.
  • Allocation failure must always be handled.
  • Memory leaks occur when allocated memory is not released.
  • Drivers must manage memory ownership and lifetime correctly.
