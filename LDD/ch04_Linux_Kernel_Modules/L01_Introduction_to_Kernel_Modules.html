1. Introduction

The Linux kernel provides the core services required by an operating system, including process management, memory management, device management, file systems and networking.

However, it is not practical to compile every possible device driver and optional kernel feature directly into the kernel. Linux therefore supports a mechanism called Loadable Kernel Modules (LKMs).

A kernel module is a piece of code that can be loaded into the running Linux kernel when required and removed when it is no longer needed.

Kernel modules are widely used to implement device drivers and extend kernel functionality without rebuilding the entire kernel.

2. What Is a Kernel Module?

A kernel module is an object file containing code and metadata that the Linux kernel can load dynamically.

It executes in kernel space and has access to kernel facilities and interfaces. Unlike an ordinary user-space application, a kernel module operates with kernel-level privileges.

Example

A USB device driver may be provided as a kernel module. When a compatible USB device is connected, the relevant driver can be loaded so that the kernel can communicate with the device.

3. Why Are Kernel Modules Needed?

Kernel modules provide flexibility in managing kernel functionality.

Major reasons

  • Dynamic functionality: Features can be added while the kernel is running.
  • Memory efficiency: Unneeded optional modules do not have to remain loaded.
  • Hardware support: Drivers can be loaded when compatible hardware is detected.
  • Maintainability: Certain kernel features can be developed and distributed separately.
  • Reduced rebuild requirements: Many driver changes can be tested without rebuilding the entire kernel.
  • Modular design: Kernel functionality can be divided into independently managed components.

4. Where Do Kernel Modules Execute?

Linux provides two major execution environments:

User SpaceKernel Space
Runs ordinary applications.Runs the kernel and kernel modules.
Uses restricted privileges.Runs with kernel privileges.
Cannot directly access protected kernel memory.Can access kernel memory according to kernel rules.
Uses system calls to request kernel services.Provides system calls and kernel services.
Application crashes are generally isolated to the process.Faults can crash or destabilize the entire system.

A kernel module is not a user-space program. It executes inside the kernel's privileged environment.

5. Kernel Module File Format

Kernel modules are commonly distributed as files with the .ko extension.

The extension stands for Kernel Object.

Example

hello_module.ko
usb_storage.ko
e1000e.ko

A .ko file is a relocatable object file containing compiled kernel code, symbol information and module metadata. It is not simply a normal executable program.

Inspect a module file

file hello_module.ko

Display module metadata

modinfo hello_module.ko

6. Static and Dynamic Kernel Functionality

Kernel functionality can be built directly into the kernel image or provided as a loadable module.

Built-in kernel functionality

  • Compiled directly into the kernel image.
  • Available as part of the kernel after boot.
  • Cannot be independently unloaded like a loadable module.

Loadable kernel functionality

  • Compiled separately as a module.
  • Can be loaded after the kernel has started.
  • Can often be removed when it is not in use.

The detailed comparison between static and dynamic modules is covered in Lesson 2.

7. Kernel Module Architecture

A typical loadable kernel module has three important elements:

  1. Initialization function.
  2. Module functionality.
  3. Cleanup function.

↓
Module Loader
↓
Initialization Function
↓
Active Module Functionality

Cleanup Function

The initialization function prepares the module for operation. The cleanup function releases resources when the module is successfully removed.

These functions are commonly registered using module_init() and module_exit().

8. Simple Kernel Module Example

The following example demonstrates a minimal Linux kernel module.

Source code: hello_module.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello: Kernel module loaded\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello: Kernel module removed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic Linux Kernel Module");

Explanation

ElementPurpose
linux/module.hProvides module-related declarations and macros.
linux/kernel.hProvides kernel facilities, including logging interfaces.
linux/init.hProvides initialization and cleanup annotations.
hello_init()Runs when the module is successfully initialized.
hello_exit()Runs when the module is successfully removed.
pr_info()Writes an informational message to the kernel log.
module_init()Registers the module initialization function.
module_exit()Registers the module cleanup function.
MODULE_LICENSE()Declares the module's license.

Important: This is a minimal demonstration module. A real device driver must also implement the appropriate device registration, resource management and hardware or subsystem operations.

9. How a Kernel Module Is Loaded

The kernel module loading process involves several stages.

  1. The developer writes the module source code.
  2. The source code is compiled against the appropriate kernel build environment.
  3. A .ko module file is generated.
  4. A module management command requests insertion.
  5. The kernel checks module compatibility and required symbols.
  6. The module is prepared and relocated for the running kernel.
  7. The module initialization function is executed.
  8. If initialization succeeds, the module becomes active.

Example command

sudo insmod hello_module.ko

If initialization fails, the kernel rejects the load and reports an error. The module must not be treated as successfully active in that case.

10. Where Are Kernel Modules Stored?

Installed kernel modules are normally stored under:

/lib/modules/$(uname -r)/

The uname -r command displays the release version of the running kernel.

Display the running kernel version

uname -r

List installed module directories

ls /lib/modules/$(uname -r)/

Common subdirectories include:

  • kernel/ – Kernel-provided module files.
  • updates/ – Some externally supplied or updated modules.
  • extra/ – Often used for additional external modules.
  • build – Commonly a link to the kernel build directory or headers.
  • source – Commonly a link to the kernel source tree.

The exact directory contents depend on the Linux distribution and installation method.

12. Advantages of Kernel Modules

  • Flexible loading and unloading of supported functionality.
  • Reduced need to include every optional feature in the kernel image.
  • Independent development of many device drivers.
  • Convenient testing of external driver code.
  • Support for dynamically detected hardware.
  • Modular organization of kernel functionality.

13. Limitations and Risks of Kernel Modules

  • Modules execute with kernel privileges.
  • Programming errors can cause kernel crashes.
  • Modules must be compatible with the target kernel.
  • Symbol dependencies must be satisfied.
  • Kernel configuration and security policies can restrict loading.
  • Module interfaces may change between kernel versions.
  • Incorrect resource cleanup can cause memory leaks or system instability.

Kernel module development requires careful testing and debugging. Initial experiments should preferably be performed in a virtual machine with a recoverable snapshot.

14. Kernel Modules and Device Driver Development

Kernel modules and device drivers are closely related, but they are not identical concepts.

A kernel module is a mechanism for extending kernel functionality. A device driver is software that controls or provides access to a hardware device or device interface.

A device driver may be implemented as a loadable kernel module or built directly into the kernel.

Linux Kernel
↓

↓

↓

For example, a character device driver can be implemented as a loadable module and registered with the Linux character device subsystem.

16. Important Points to Remember

  • A kernel module extends the functionality of the Linux kernel.
  • Loadable modules can be inserted into a running kernel.
  • Modules generally use the .ko extension.
  • Kernel modules execute in kernel space.
  • A module commonly has initialization and cleanup functions.
  • module_init() registers the initialization function.
  • module_exit() registers the cleanup function.
  • Device drivers can be implemented as kernel modules.
  • Modules must be compatible with the target kernel.
  • Faulty kernel modules can affect the entire operating system.
