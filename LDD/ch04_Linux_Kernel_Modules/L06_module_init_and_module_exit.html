1. Introduction

Linux kernel modules need entry and cleanup points so that the kernel knows which functions to execute when a module is loaded or removed.

Linux provides two important macros for this purpose: module_init() and module_exit().

  • module_init() registers the module initialization function.
  • module_exit() registers the module cleanup function.

These macros connect the programmer-defined functions to the Linux kernel module lifecycle.

2. What Is module_init()?

module_init() is a Linux kernel macro used to identify the initialization entry point of a module.

It associates a programmer-defined initialization function with the kernel's module initialization mechanism.

Syntax

module_init(function_name);

Example

static int __init my_init(void)
{
    pr_info("Module initialized\n");

    return 0;
}

module_init(my_init);

Here, my_init() is the initialization function. When the module is loaded, the kernel invokes this registered entry point.

3. What Is module_exit()?

module_exit() is a Linux kernel macro used to register the cleanup function of a loadable module.

The registered function executes when the module is successfully unloaded.

Syntax

module_exit(function_name);

Example

static void __exit my_exit(void)
{
    pr_info("Module cleanup executed\n");
}

module_exit(my_exit);

Here, my_exit() is registered as the module's cleanup function.

4. Working Relationship Between Both Macros

Both macros define the lifecycle entry points of a loadable kernel module.

module_init(my_init)
↓
Kernel registers initialization entry point
↓
Module loading invokes my_init()
module_exit(my_exit)
↓
Kernel registers cleanup entry point
↓
Module removal invokes my_exit()

5. Complete Kernel Module Example

The following program demonstrates both macros in one loadable kernel module.

Source Code: lifecycle_demo.c

#include <linux/module.h>
#include <linux/init.h>

static int __init lifecycle_init(void)
{
    pr_info("Lifecycle: Module loaded successfully\n");

    return 0;
}

static void __exit lifecycle_exit(void)
{
    pr_info("Lifecycle: Module removed successfully\n");
}

module_init(lifecycle_init);
module_exit(lifecycle_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Demonstration of module_init and module_exit");

Code Explanation

  1. linux/module.h provides module-related definitions.
  2. linux/init.h provides initialization and exit annotations.
  3. lifecycle_init() is the initialization function.
  4. lifecycle_exit() is the cleanup function.
  5. module_init(lifecycle_init) registers the initialization function.
  6. module_exit(lifecycle_exit) registers the cleanup function.
  7. MODULE_LICENSE("GPL") declares the module license.

6. Compiling and Testing the Module

Save the program as lifecycle_demo.c. Create the following Makefile in the same directory.

Makefile

obj-m += lifecycle_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The command lines under all and clean must begin with a tab character.

Terminal Commands

# Compile the module
make

# Load the module
sudo insmod lifecycle_demo.ko

# Check the loaded module
lsmod | grep lifecycle_demo

# View the initialization message
sudo dmesg | tail

# Remove the module
sudo rmmod lifecycle_demo

# View the cleanup message
sudo dmesg | tail

# Clean generated files
make clean

Expected Kernel Log Messages

Lifecycle: Module loaded successfully
Lifecycle: Module removed successfully

The initialization message appears after loading. The cleanup message appears after successful removal.

7. Return Values and Function Requirements

Feature Initialization Function Exit Function
Typical declaration static int __init my_init(void) static void __exit my_exit(void)
Registration macro module_init() module_exit()
Return value 0 on success, negative error on failure No return value
Purpose Prepare resources and register interfaces Release resources and unregister interfaces
Execution When module loading succeeds in reaching initialization When a loadable module is successfully removed

8. Important Difference: Loadable and Built-in Code

The behavior of these macros depends on how the code is built into the kernel.

Loadable Kernel Module

  • module_init() identifies the module's load-time entry point.
  • module_exit() identifies its unload-time cleanup function.
  • The module can be loaded and, if permitted, removed at runtime.

Built-in Kernel Code

  • The initialization function is treated as a kernel initialization entry point.
  • It runs during kernel boot initialization.
  • There is no runtime module removal operation for built-in code.
  • The exit function is not used as a runtime unload callback.
Important: A built-in component cannot be independently unloaded using rmmod. The __exit annotation allows exit-only code to be discarded when it is not needed for built-in kernel code.

9. Common Programming Mistakes

Mistake Correct Approach
Forgetting module_init() Register the initialization entry point.
Forgetting module_exit() Register cleanup for an unloadable module.
Using an incorrect initialization return type Use int.
Using an incorrect exit return type Use void.
Using printf() Use kernel logging functions such as pr_info().
Leaving resources allocated Release resources during error handling and cleanup.

10. Practical Applications in Device Drivers

The two macros are used in many Linux driver subsystems. For example, a character device driver may register its device during initialization and unregister it during cleanup. 

static int __init driver_init(void)
{
    /* Register character device */

    return 0;
}

static void __exit driver_exit(void)
{
    /* Unregister character device */
}

module_init(driver_init);
module_exit(driver_exit);

This is a structural illustration. A working character driver must also implement the required registration, error-handling and cleanup operations.

11. Lesson Summary

  • module_init() registers the module initialization function.
  • module_exit() registers the module cleanup function.
  • The initialization function returns an integer.
  • The exit function returns void.
  • These macros establish module lifecycle entry points.
  • Loadable modules use both entry points for loading and removal.
  • Built-in kernel code follows boot-time initialization rather than runtime module unloading.
