1. Introduction

Linux kernel modules contain executable kernel code, but they can also include descriptive information about the module. This information is called module metadata.

Metadata helps administrators and developers identify a module, understand its purpose, determine its author and inspect its declared license.

Linux provides predefined macros such as MODULE_LICENSE(), MODULE_AUTHOR() and MODULE_DESCRIPTION() to declare this information.

2. What Is Module Metadata?

Module metadata is descriptive information embedded in a compiled kernel module. It is stored in special sections of the module file and can be inspected using the modinfo command.

Typical metadata includes:

  • Module name
  • Author information
  • Module description
  • License declaration
  • Supported device aliases
  • Module parameters
  • Version information
  • Dependencies and other module information

3. Common Module Metadata Macros

Macro Purpose
MODULE_LICENSE() Declares the module's license identifier.
MODULE_AUTHOR() Specifies the module author.
MODULE_DESCRIPTION() Provides a short description of the module.
MODULE_VERSION() Declares the module version.
MODULE_ALIAS() Defines an additional module alias.
MODULE_DEVICE_TABLE() Exports device identification information used for device matching and module aliases.
MODULE_FIRMWARE() Declares firmware files that the module may request.

4. MODULE_LICENSE()

MODULE_LICENSE() declares the license associated with a kernel module. The declaration is used by the kernel to determine whether the module is considered GPL-compatible for certain kernel interfaces.

Syntax

MODULE_LICENSE("GPL");

Example

#include <linux/module.h>

MODULE_LICENSE("GPL");

The license declaration is important because Linux kernel code uses licensing information to determine whether a module is compatible with GPL-only exported symbols.

Important: Declaring a license string does not automatically make software legally compliant with that license. The actual source code and its distribution must comply with the applicable license terms.

5. Common License Identifiers

License Identifier Description
GPL Declares the GNU General Public License.
GPL v2 Declares GPL version 2.
Dual BSD/GPL Indicates dual licensing under BSD or GPL terms.
Dual MIT/GPL Indicates dual licensing under MIT or GPL terms.
Proprietary Indicates a proprietary module declaration and is not GPL-compatible.

Use a license identifier that accurately reflects the module's actual licensing terms. Do not choose a license string merely to bypass kernel restrictions.

6. MODULE_AUTHOR()

MODULE_AUTHOR() specifies the author or development team responsible for the module.

Syntax

MODULE_AUTHOR("Author Name");

Example

MODULE_AUTHOR("NS Learning Hub");

Author information is descriptive metadata. It does not affect the execution of the module.

7. MODULE_DESCRIPTION()

MODULE_DESCRIPTION() provides a brief explanation of what the module does.

Syntax

MODULE_DESCRIPTION("Short module description");

Example

MODULE_DESCRIPTION("Simple character device driver");

This information helps administrators identify the purpose of a module when inspecting installed modules.

8. MODULE_VERSION()

MODULE_VERSION() declares a version string associated with the module.

Syntax

MODULE_VERSION("1.0");

Example

MODULE_VERSION("2.1.0");

A version string is useful for development, maintenance and module identification. It does not by itself implement version compatibility checking.

9. MODULE_ALIAS()

MODULE_ALIAS() declares an additional name or alias for a module. Aliases can be used by module-loading tools when resolving a module request.

Syntax

MODULE_ALIAS("example_alias");

Device drivers commonly use device identifiers and aliases generated from device tables so that the system can identify an appropriate driver for a device.

Note: A manually declared alias is not a substitute for implementing the correct device matching mechanism in a real driver.

10. Complete Kernel Module with Metadata

The following example combines module lifecycle functions with commonly used metadata macros.

Source Code: metadata_demo.c

#include <linux/module.h>
#include <linux/init.h>

static int __init metadata_init(void)
{
    pr_info("Metadata Demo: Module loaded\n");

    return 0;
}

static void __exit metadata_exit(void)
{
    pr_info("Metadata Demo: Module unloaded\n");
}

module_init(metadata_init);
module_exit(metadata_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Demonstration of Linux module metadata");
MODULE_VERSION("1.0");
MODULE_ALIAS("ns_metadata_demo");

Code Explanation

  • metadata_init() executes during module loading.
  • metadata_exit() executes during successful module removal.
  • MODULE_LICENSE() declares the license identifier.
  • MODULE_AUTHOR() specifies the author.
  • MODULE_DESCRIPTION() describes the module.
  • MODULE_VERSION() specifies the version.
  • MODULE_ALIAS() declares an additional alias.

11. Compiling the Module

Save the source file as metadata_demo.c. Create a Makefile in the same directory.

Makefile

obj-m += metadata_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The command lines under all and clean must begin with a tab character.

Compilation Command

make

After successful compilation, the directory should contain the generated metadata_demo.ko module file.

12. Viewing Metadata Using modinfo

The modinfo command displays information embedded in a kernel module file.

Command

modinfo metadata_demo.ko

Illustrative Output

filename:       metadata_demo.ko
license:        GPL
author:         NS Learning Hub
description:    Demonstration of Linux module metadata
version:        1.0
alias:          ns_metadata_demo
depends:
name:           metadata_demo
vermagic:       kernel-version information

The exact output and field ordering can vary with the kernel version and build configuration.

Useful modinfo Commands

# Display all available module information
modinfo metadata_demo.ko

# Display the module license
modinfo -F license metadata_demo.ko

# Display the module author
modinfo -F author metadata_demo.ko

# Display the module description
modinfo -F description metadata_demo.ko

# Display the module version
modinfo -F version metadata_demo.ko

13. Why Module Metadata Is Important

  • Identifies the purpose and author of a module.
  • Provides licensing information.
  • Helps administrators inspect modules.
  • Supports module management and troubleshooting.
  • Provides version information for maintenance.
  • Supports automatic module selection through aliases and device matching.

14. Common Mistakes

Mistake Correct Approach
Forgetting MODULE_LICENSE() Declare the actual module license.
Using an inaccurate license identifier Use an identifier consistent with the actual licensing terms.
Assuming metadata changes module behavior Understand that most metadata is descriptive.
Confusing module version with kernel version They represent different version information.
Using an alias instead of proper device matching Implement the appropriate subsystem matching mechanism.

15. Lesson Summary

  • Module metadata provides descriptive information about a kernel module.
  • MODULE_LICENSE() declares the module license.
  • MODULE_AUTHOR() identifies the author.
  • MODULE_DESCRIPTION() describes the module.
  • MODULE_VERSION() declares a version string.
  • MODULE_ALIAS() declares an additional module alias.
  • modinfo displays module metadata.
  • Metadata improves identification, inspection and module management.
