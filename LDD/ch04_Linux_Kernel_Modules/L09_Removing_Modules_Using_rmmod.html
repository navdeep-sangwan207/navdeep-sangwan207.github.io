1. Introduction

Linux allows kernel modules to be dynamically inserted into and removed from a running kernel. After testing or using a module, it may be necessary to remove it without rebooting the system.

The rmmod command is used to request removal of a loaded kernel module.

During normal removal, the kernel executes the module's registered exit function. This function releases resources that the module acquired during initialization.

2. What Is rmmod?

rmmod is a Linux command-line utility used to remove a loadable kernel module from the running kernel.

Basic Syntax

sudo rmmod module_name

Example

sudo rmmod hello

Notice that the module name is normally specified without the .ko extension.

Administrative privileges are normally required because module removal changes the running kernel.

3. Why Are Kernel Modules Removed?

  • To stop functionality that is no longer required.
  • To test a modified version of a kernel module.
  • To release resources allocated by a driver.
  • To troubleshoot driver development problems.
  • To unload an unused driver from the running kernel.

For example, while developing a character device driver, a developer may repeatedly load, test and remove the module during debugging.

4. How rmmod Works

When rmmod is executed, it requests the kernel to remove the specified module.

  1. The user specifies the name of a loaded module.
  2. The utility requests module removal from the kernel.
  3. The kernel checks whether the module can be removed.
  4. The kernel checks module usage and dependency constraints.
  5. The module's exit function is executed during normal removal.
  6. The kernel releases the module's code and associated resources.
User executes rmmod
↓
Kernel receives removal request
↓
Removal eligibility checked
↓
Module exit function executes
↓
Module removed from kernel

If the module is in use or cannot safely be removed, the kernel may reject the request.

5. Role of the Module Exit Function

The module exit function is responsible for releasing resources and reversing the setup performed during module initialization.

It is commonly declared using the __exit annotation and registered using module_exit().

Example

#include <linux/module.h>
#include <linux/init.h>

static int __init demo_init(void)
{
    pr_info("Demo module loaded\n");
    return 0;
}

static void __exit demo_exit(void)
{
    pr_info("Demo module cleanup started\n");
    pr_info("Demo module removed\n");
}

module_init(demo_init);
module_exit(demo_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Demonstration of module removal");

When the module is successfully removed through the normal module-removal mechanism, the kernel invokes demo_exit().

Important: The exit function must not be treated as an ordinary application function. It runs in kernel context and must obey kernel API and execution context rules.

6. Complete Practical: Load and Remove a Module

Step 1: Create Source File

Create a file named rmmod_demo.c.

#include <linux/module.h>
#include <linux/init.h>

static int __init rmmod_demo_init(void)
{
    pr_info("rmmod_demo: Module loaded successfully\n");
    return 0;
}

static void __exit rmmod_demo_exit(void)
{
    pr_info("rmmod_demo: Cleanup function executed\n");
}

module_init(rmmod_demo_init);
module_exit(rmmod_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Demonstration of rmmod command");
MODULE_VERSION("1.0");

Step 2: Create Makefile

obj-m += rmmod_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all and clean must begin with a tab character.

Step 3: Compile the Module

make

Successful compilation should produce rmmod_demo.ko.

Step 4: Load the Module

sudo insmod rmmod_demo.ko

Step 5: Verify the Module

lsmod | grep rmmod_demo

Step 6: Remove the Module

sudo rmmod rmmod_demo

Step 7: Check the Kernel Log

sudo dmesg | tail -n 20

Expected messages include:

rmmod_demo: Module loaded successfully
rmmod_demo: Cleanup function executed

Step 8: Verify Removal

lsmod | grep rmmod_demo

If the module was removed successfully, there should be no matching entry in the output.

7. Checking Whether a Module Is in Use

A module may be prevented from unloading while other kernel components depend on it or while it is actively referenced.

Use the following command:

lsmod

The output includes a Used by column, which can provide information about module usage and dependent modules.

You can also inspect a particular module: 

lsmod | grep module_name

A module's reference count and dependency information help the kernel determine whether safe removal is possible.

A reference count of zero does not prove that unloading is always safe. The kernel also considers dependencies, module state and other conditions.

8. Common Errors While Using rmmod

Error or Symptom Possible Cause Suggested Action
Module not found The module is not loaded or the name is incorrect. Check with lsmod.
Module is in use Other components or active references depend on it. Stop using the device and investigate dependencies.
Operation not permitted Insufficient privileges or security restrictions. Check privileges and system security policy.
Module remains loaded The removal request may have failed. Inspect the command output and kernel logs.
Unexpected device behavior Driver cleanup may be incomplete or incorrect. Review the module exit function and resource management.

Check Kernel Logs

sudo dmesg | tail -n 30

Kernel logs can help identify why a removal request was rejected or whether the cleanup function ran.

9. Difference Between rmmod and modprobe -r

Linux provides both rmmod and modprobe -r for module removal.

Feature rmmod modprobe -r
Purpose Requests removal of a named loaded module. Removes a module using dependency-aware module management.
Dependencies Does not automatically manage dependent modules. Can remove unused dependencies when appropriate.
Typical use Direct module removal. System module management.

Examples

# Remove one loaded module
sudo rmmod my_driver

# Remove a module using modprobe
sudo modprobe -r my_driver

Dependency removal is subject to the module dependency database and whether the dependent modules are actually safe to unload.

10. Why Force Removal Is Dangerous

The rmmod utility supports a force option on some configurations, but forcing removal is dangerous. 

sudo rmmod -f module_name

Force removal may bypass normal safety protections when the running kernel and module configuration permit it. It can cause memory corruption, kernel crashes or unpredictable system behavior.

Development rule: Do not use force removal as a routine solution to an "in use" error. Find and resolve the dependency or active-use condition instead.

11. Resource Cleanup in Device Drivers

Real device drivers may allocate memory, register devices, request interrupts and create interfaces. These resources must be released correctly during module removal.

Resource Acquired During Initialization Typical Cleanup Operation
Kernel memory allocated with kmalloc() kfree()
Registered character device cdev_del()
Allocated device number unregister_chrdev_region()
Requested interrupt free_irq()
Created device interface Corresponding device/interface cleanup API
Registered device class Corresponding class cleanup API

The exact cleanup operations depend on which resources the driver acquired and which kernel APIs it used. Cleanup should generally reverse the initialization sequence.

12. Important Points About Module Removal

  • rmmod removes a loadable module by name.
  • The module's exit function runs during normal successful removal.
  • A module cannot normally be removed while it is in use.
  • Dependencies must be handled before removal can succeed.
  • Built-in kernel components cannot be independently unloaded.
  • Correct resource cleanup is essential for reliable drivers.
  • Force removal can destabilize the system and should be avoided.

13. Lesson Summary

  • rmmod requests removal of a loaded kernel module.
  • The module name is normally supplied without the .ko extension.
  • The module exit function performs cleanup.
  • lsmod helps check whether a module is loaded.
  • modprobe -r provides dependency-aware removal.
  • Modules that are in use may not be removable.
  • Proper resource cleanup prevents driver-related problems.
