1. Introduction

Linux kernel modules contain executable kernel code, metadata and information required for module management. Before loading or troubleshooting a module, developers often need to inspect its properties.

The modinfo command displays information about a Linux kernel module.

It is useful for checking module descriptions, authors, licenses, parameters, dependencies, aliases and kernel compatibility information.

2. What Is modinfo?

modinfo is a command-line utility provided by the kmod tools on modern Linux distributions. It reads metadata associated with a kernel module.

Basic Syntax

modinfo module_name

Example

modinfo e1000

This requests metadata for the module named e1000, if it is available in the installed module directories.

You can also inspect a compiled module file directly: 

modinfo ./my_driver.ko

3. Why Is modinfo Important?

  • To identify the purpose of a kernel module.
  • To inspect the module author and description.
  • To identify the module license.
  • To check available module parameters.
  • To inspect dependency information.
  • To check kernel version compatibility metadata.
  • To troubleshoot module loading problems.

For Linux device driver development, this command helps verify that a compiled module contains the expected metadata.

4. Understanding modinfo Output

A typical module information output may look like this: 

filename:       /lib/modules/example/kernel/drivers/net/e1000.ko
license:        GPL
description:    Intel(R) PRO/1000 Network Driver
author:         Intel Corporation
version:        7.3.21-k8-NAPI
depends:
vermagic:       6.x.x-generic SMP mod_unload modversions

This is illustrative output. Actual values depend on the module and the installed kernel.

Meaning of Common Fields

Field Description
filename Location of the module file.
license Module license declaration.
description Brief description of the module.
author Module author information.
version Module version metadata, if provided.
depends Dependency information recorded for the module.
vermagic Kernel version and build characteristics associated with the module.
parm Information about declared module parameters.
alias Module aliases used for module matching and discovery.

5. Understanding Module Metadata

Module metadata is commonly added to source code using macros provided by the Linux kernel.

Example

#include <linux/module.h>
#include <linux/init.h>

static int __init metadata_init(void)
{
    pr_info("Metadata module loaded\n");
    return 0;
}

static void __exit metadata_exit(void)
{
    pr_info("Metadata module removed\n");
}

module_init(metadata_init);
module_exit(metadata_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Example module for modinfo");
MODULE_VERSION("1.0");

The metadata macros describe the module and make information available to tools such as modinfo.

Macro Purpose
MODULE_LICENSE() Declares the module's license.
MODULE_AUTHOR() Declares author information.
MODULE_DESCRIPTION() Describes the module.
MODULE_VERSION() Provides module version metadata.

6. Displaying Module Parameters

A kernel module can define parameters that users can supply when loading the module.

The modinfo command can display information about parameters declared in the module.

Example Source Code

#include <linux/module.h>
#include <linux/init.h>

static int count = 10;
static char *name = "Linux";

module_param(count, int, 0444);
MODULE_PARM_DESC(count, "Number of test operations");

module_param(name, charp, 0444);
MODULE_PARM_DESC(name, "Name displayed by the module");

static int __init parameter_init(void)
{
    pr_info("Parameter module loaded\n");
    pr_info("count = %d\n", count);
    pr_info("name = %s\n", name);
    return 0;
}

static void __exit parameter_exit(void)
{
    pr_info("Parameter module removed\n");
}

module_init(parameter_init);
module_exit(parameter_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Module parameter demonstration");

Inspect Parameters

modinfo parameter_demo.ko

Look for the parm entries in the output. They describe the declared parameters.

Load with Parameters

sudo insmod parameter_demo.ko count=25 name="Ubuntu"

The supplied values are assigned before the module's initialization function executes.

7. Displaying Only Selected Fields

The -F option can display a selected metadata field.

Examples

# Display module description
modinfo -F description e1000

# Display module author
modinfo -F author e1000

# Display module license
modinfo -F license e1000

# Display module filename
modinfo -F filename e1000

# Display kernel compatibility information
modinfo -F vermagic e1000

Replace e1000 with the name of a module available on your system.

8. Inspecting a Local Kernel Module

During driver development, the module may exist in the current project directory rather than in the system's installed module directory.

You can inspect that module directly using its path. 

modinfo ./my_driver.ko

This is particularly useful before inserting a newly compiled module with insmod.

9. Understanding vermagic

The vermagic field contains compatibility information associated with the kernel against which the module was built.

It may include information such as:

  • Kernel release version.
  • SMP configuration.
  • Preemption-related build characteristics.
  • Module unloading support information.
  • Module versioning information.

Check the Running Kernel

uname -r

Check Module vermagic

modinfo -F vermagic my_driver.ko

This helps investigate module compatibility, although matching vermagic alone does not guarantee that the module will load successfully.

10. Understanding Module Dependencies

Some modules require symbols exported by other modules. The depends field can provide dependency information recorded for a module.

Example

modinfo -F depends my_driver

If dependency metadata is available, the command displays the recorded module dependencies.

This information is useful when investigating why a module may require another module to be loaded first.

The dependency field may be empty. An empty field does not mean that the module has no references to kernel symbols; many symbols are provided by the kernel itself.

11. Difference Between lsmod and modinfo

Feature lsmod modinfo
Main purpose Lists currently loaded modules. Displays module metadata.
Loaded status Shows currently loaded modules. Does not establish whether a module is currently loaded.
Author and description Not normally displayed. Can display these fields when present.
Module parameters Not normally displayed. Can display declared parameter information.
Dependency metadata Shows usage/dependency-related information for loaded modules. Can display recorded dependency metadata.

Examples

# List loaded modules
lsmod

# Display information about a module
modinfo my_driver

12. Practical: Create and Inspect a Kernel Module

Step 1: Create Source File

Create modinfo_demo.c.

#include <linux/module.h>
#include <linux/init.h>

static int value = 100;

module_param(value, int, 0444);
MODULE_PARM_DESC(value, "Example integer parameter");

static int __init modinfo_demo_init(void)
{
    pr_info("modinfo_demo loaded: value=%d\n", value);
    return 0;
}

static void __exit modinfo_demo_exit(void)
{
    pr_info("modinfo_demo removed\n");
}

module_init(modinfo_demo_init);
module_exit(modinfo_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Practical demonstration of modinfo");
MODULE_VERSION("1.0");

Step 2: Create Makefile

obj-m += modinfo_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all and clean must begin with a tab character.

Step 3: Compile

make

Step 4: Display Complete Module Information

modinfo modinfo_demo.ko

Step 5: Display Specific Metadata

modinfo -F author modinfo_demo.ko
modinfo -F description modinfo_demo.ko
modinfo -F license modinfo_demo.ko
modinfo -F version modinfo_demo.ko
modinfo -F vermagic modinfo_demo.ko

Step 6: Inspect Parameter Information

modinfo -F parm modinfo_demo.ko

Step 7: Load the Module with a Parameter

sudo insmod modinfo_demo.ko value=250

Step 8: Verify Loading and Logs

lsmod | grep modinfo_demo
sudo dmesg | tail -n 10

Step 9: Remove the Module

sudo rmmod modinfo_demo

Step 10: Clean Build Files

make clean

13. Common Problems and Troubleshooting

Problem Possible Reason Suggested Check
Module not found Incorrect module name or unavailable module file. Check the path and installed module directories.
No metadata field displayed The module may not define that metadata field. Inspect complete output using modinfo.
Cannot inspect local file Incorrect path or missing compiled module. Check with ls -l.
Module fails to load Compatibility, dependency, signature or initialization issue. Inspect dmesg and module metadata.
Parameter not shown Parameter declaration or metadata is missing. Check module_param() and rebuild.

Useful Diagnostic Commands

# Check kernel version
uname -r

# Inspect module metadata
modinfo ./my_driver.ko

# Display parameter information
modinfo -F parm ./my_driver.ko

# Display dependency information
modinfo -F depends ./my_driver.ko

# Display recent kernel messages
sudo dmesg | tail -n 30

14. Lesson Summary

  • modinfo displays kernel module metadata.
  • It can inspect installed modules and local .ko files.
  • It displays fields such as author, license and description.
  • MODULE_LICENSE() and other metadata macros define module information.
  • module_param() declares module parameters.
  • The -F option displays a selected metadata field.
  • vermagic provides kernel build compatibility information.
  • modinfo is useful for module inspection and troubleshooting.
