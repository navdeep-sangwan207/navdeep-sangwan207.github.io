1. Introduction

A Linux kernel module is a piece of code that can be loaded into the running Linux kernel. When a module is loaded, the kernel must perform certain initialization operations before the module can begin its intended work.

The module initialization function is the function responsible for performing these operations. It is executed when the module is successfully requested for loading.

Initialization may include allocating memory, registering a device driver, creating a device interface, initializing data structures, or registering callbacks.

2. What Is a Module Initialization Function?

A module initialization function is a function that executes when a loadable kernel module is inserted into the kernel. It prepares the module and its resources for operation.

In Linux kernel programming, the initialization function is commonly defined using the static keyword and returns an integer. 

static int __init my_module_init(void)
{
    /* Initialization code */

    return 0;
}

The __init annotation identifies initialization code. For built-in kernel code, the kernel can discard initialization sections after initialization is complete. For loadable modules, the initialization code is released after the module has been initialized.

3. Syntax of the Initialization Function

static int __init function_name(void)
{
    /* Statements */

    return 0;
}
Component Description
static Restricts the function's visibility to the current source file.
int Return type of the initialization function.
__init Marks the function as initialization code.
function_name Name chosen for the initialization function.
void Indicates that the function accepts no arguments.
return 0 Indicates successful initialization.

4. How the Initialization Function Is Executed

A loadable module's initialization function is invoked by the kernel's module-loading mechanism. A user typically requests module insertion using a command such as insmod or modprobe.

User runs insmod
↓
Kernel receives module request
↓
Kernel loads and prepares module
↓
Initialization function executes
↓
Success or error returned

If initialization succeeds, the module becomes active. If initialization returns an error, the kernel rejects the module load and performs module-loading cleanup.

5. Return Value of the Initialization Function

The initialization function returns an integer. Its return value tells the kernel whether the initialization operation was successful.

Return value Meaning
0 Initialization completed successfully.
-EINVAL Invalid argument or configuration.
-ENOMEM Insufficient memory.
-EBUSY Resource or device is busy.
-ENODEV Required device or resource is unavailable.

These negative error codes are defined by kernel headers, commonly including <linux/errno.h>. A module should return an appropriate negative error code when initialization cannot be completed. 

#include <linux/module.h>
#include <linux/init.h>
#include <linux/errno.h>

static int __init my_module_init(void)
{
    pr_info("Initialization started\n");

    return -EINVAL;
}

This example deliberately returns an error. It is useful for understanding failure handling, but it is not a successful initialization example.

6. Writing a Basic Initialization Function

The following example prints a kernel log message when the module initialization function executes.

Source Code: hello_init.c

#include <linux/module.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello: Module initialization executed\n");

    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello: Module cleanup executed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic module initialization example");

Code Explanation

  • linux/module.h provides module-related definitions.
  • linux/init.h provides initialization and exit annotations.
  • hello_init() executes when the module is loaded.
  • pr_info() writes an informational message to the kernel log.
  • return 0 indicates successful initialization.
  • hello_exit() is the cleanup function used when the module is removed.
  • module_init() registers the initialization entry point.
  • module_exit() registers the cleanup entry point.
Important: The initialization function is registered using module_init(). Its name does not have to be hello_init; the programmer can choose another valid function name.

7. Compiling and Loading the Module

Save the source code as hello_init.c and create the following Makefile in the same directory.

Makefile

obj-m += hello_init.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The command lines under all and clean must begin with a tab character.

Commands

# Compile the kernel module
make

# Load the module
sudo insmod hello_init.ko

# Check whether the module is loaded
lsmod | grep hello_init

# View kernel log messages
sudo dmesg | tail

# Remove the module
sudo rmmod hello_init

# Clean generated files
make clean

Expected Kernel Log Messages

Hello: Module initialization executed
Hello: Module cleanup executed

The first message appears during module loading. The second appears when the module is successfully removed.

Environment note: These commands assume Ubuntu has matching kernel headers and build tools installed. Run kernel module experiments in a virtual machine or test environment, not on a production system. Kernel modules execute with kernel privileges.

8. Initialization with Resource Allocation

A real device driver may need to allocate memory or reserve resources during initialization. If a later operation fails, resources acquired earlier must be released before returning an error. 

#include <linux/module.h>
#include <linux/init.h>
#include <linux/slab.h>

static int *device_buffer;

static int __init example_init(void)
{
    device_buffer = kmalloc(sizeof(*device_buffer), GFP_KERNEL);

    if (!device_buffer) {
        pr_err("Memory allocation failed\n");
        return -ENOMEM;
    }

    *device_buffer = 100;

    pr_info("Buffer initialized with value %d\n",
            *device_buffer);

    return 0;
}

static void __exit example_exit(void)
{
    kfree(device_buffer);
    device_buffer = NULL;

    pr_info("Buffer released\n");
}

module_init(example_init);
module_exit(example_exit);

MODULE_LICENSE("GPL");

In this example, kmalloc() allocates memory. If allocation fails, the initialization function returns -ENOMEM. If allocation succeeds, the module stores a value in the allocated memory.

The exit function releases the memory using kfree().

Resource-management rule: If initialization acquires several resources and a later step fails, release all resources already acquired before returning the error. Returning an error does not automatically free arbitrary resources allocated by the module.

9. Common Mistakes in Initialization Functions

Mistake Correct Approach
Using an incorrect return type Use an integer return type for module initialization.
Forgetting to return a value Return 0 on success or a negative error code on failure.
Not registering the function Use module_init() to register the entry point.
Ignoring memory allocation failure Check allocation results before using the memory.
Not releasing acquired resources after failure Implement proper error-handling and cleanup paths.
Using user-space functions such as printf() Use kernel logging functions such as pr_info().

10. Applications in Device Driver Development

Initialization functions are important in almost every loadable device driver. Typical operations include:

  • Allocating kernel memory for driver data.
  • Registering a character device.
  • Registering a platform driver.
  • Initializing locks and synchronization objects.
  • Registering interrupt handlers.
  • Creating device classes and device interfaces.
  • Initializing communication-related data structures.

The exact operations depend on the device type and the Linux subsystem used by the driver.

11. Lesson Summary

  • The initialization function executes when a loadable module is loaded.
  • It prepares the module for operation.
  • It normally has an integer return type.
  • The __init annotation marks initialization code.
  • module_init() registers the initialization function.
  • Return 0 when initialization succeeds.
  • Return a negative error code when initialization fails.
  • Check every resource allocation and handle failures correctly.
  • Release resources acquired before a failed initialization.
