1. Introduction

Linux supports loadable kernel modules that can be dynamically inserted into and removed from the running kernel. During driver development and system administration, it is important to identify which modules are currently loaded.

The lsmod command displays information about modules that are currently loaded into the Linux kernel.

It is especially useful when checking whether a driver has loaded successfully or investigating module dependencies.

2. What Is lsmod?

lsmod is a Linux command-line utility that displays the current list of loadable kernel modules.

Basic Syntax

lsmod

The command reads information exposed by the kernel, typically through /proc/modules, and formats it into a readable table.

Example

lsmod

The output contains module names, memory usage and reference or dependency information.

3. Understanding lsmod Output

A typical lsmod output looks similar to this: 

Module                  Size  Used by
nvidia_uvm            1232896  0
nvidia_drm              86016  4
nvidia_modeset        1359872  3 nvidia_drm
snd_hda_intel           65536  2
snd_hda_codec          204800  1 snd_hda_intel

This is illustrative output. Actual module names, sizes and usage information depend on the system.

Meaning of Each Column

Column Description
Module Name of the loaded kernel module.
Size Memory size information for the module, generally displayed in bytes.
Used by Reference count and, when applicable, names of modules depending on it.
Important: The Used by column is not a count of active hardware operations. It provides module reference and dependency information.

4. Understanding Module Reference Count

A module reference count indicates how many references currently prevent the module from being unloaded. The kernel uses reference management to protect modules from being removed while they are still needed.

For example, consider this illustrative output: 

Module          Size    Used by
example_driver  16384   2

The value 2 indicates two module references according to the module's reference-count information. It does not necessarily mean that exactly two other modules depend on it.

When the reference count is zero, the module may be eligible for removal, provided no other kernel constraints prevent unloading.

5. Understanding Module Dependencies

A kernel module may depend on symbols or services exported by another module. The required module must be available for the dependent module to work.

Module A
↓ depends on
Module B
↓ depends on
Module C

In this simplified example, Module A depends on Module B, and Module B depends on Module C.

The Used by information can help identify some of these relationships. The exact information depends on the module reference and dependency state.

A module that is required by another loaded module generally cannot be removed until its dependents have been removed or no longer require it.

6. Listing a Particular Module

To check whether a particular module appears in the loaded module list, combine lsmod with grep.

Example

lsmod | grep e1000

This searches the displayed module list for a name containing e1000.

For your own test module: 

lsmod | grep insmod_demo

If the module is loaded and its name matches, a corresponding line should appear.

7. Understanding /proc/modules

The /proc filesystem exposes information about running kernel and system state. The file /proc/modules provides information about currently loaded modules.

Display Module Information Directly

cat /proc/modules

The output is similar in content to the information displayed by lsmod, although its formatting is intended for programmatic or system use.

Relationship Between lsmod and /proc/modules

Running Linux Kernel
↓
/proc/modules
↓
lsmod
↓
Readable Module List

lsmod presents module information in a human-readable table using the kernel's module listing information.

8. Important lsmod Commands

Command Purpose
lsmod Display all currently loaded modules.
lsmod | head Display the first few lines.
lsmod | grep usb Search for module names containing usb.
cat /proc/modules Read raw module information from procfs.
watch lsmod Periodically refresh the displayed module list.

To stop the watch command, press Ctrl + C.

9. lsmod Does Not Show Every Kernel Component

An important limitation of lsmod is that it displays loadable modules currently loaded into the kernel. It does not provide a complete list of every component built into the kernel.

Loadable Module Built-in Kernel Component
Can generally be inserted dynamically. Already compiled into the kernel image.
May be removed when safe and supported. Cannot be independently unloaded using rmmod.
Normally appears in lsmod when loaded. Does not appear as a loadable module in lsmod.

Kernel configuration information can help identify whether a feature was compiled as built-in or as a loadable module.

10. Practical: Verify a Kernel Module Using lsmod

In this practical, you will compile, load, inspect and remove a simple kernel module.

Step 1: Create Source File

Create lsmod_demo.c.

#include <linux/module.h>
#include <linux/init.h>

static int __init lsmod_demo_init(void)
{
    pr_info("lsmod_demo: Module loaded\n");
    return 0;
}

static void __exit lsmod_demo_exit(void)
{
    pr_info("lsmod_demo: Module removed\n");
}

module_init(lsmod_demo_init);
module_exit(lsmod_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Demonstration of lsmod command");
MODULE_VERSION("1.0");

Step 2: Create Makefile

obj-m += lsmod_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all and clean must begin with a tab character.

Step 3: Compile the Module

make

Step 4: Load the Module

sudo insmod lsmod_demo.ko

Step 5: List Loaded Modules

lsmod

Step 6: Search for Your Module

lsmod | grep lsmod_demo

Step 7: Inspect Raw Module Information

cat /proc/modules | grep lsmod_demo

Step 8: Remove the Module

sudo rmmod lsmod_demo

Step 9: Verify Removal

lsmod | grep lsmod_demo

No matching line should appear after successful removal.

11. Using lsmod for Driver Troubleshooting

During Linux device driver development, a developer may use lsmod to investigate whether a module is loaded and whether it has visible dependencies.

Example Troubleshooting Workflow

# Check whether the driver is loaded
lsmod | grep my_driver

# Inspect module details
modinfo my_driver

# Check recent kernel messages
sudo dmesg | tail -n 30

# Check the raw module list
cat /proc/modules | grep my_driver

These commands provide complementary information:

  • lsmod checks loaded module status.
  • modinfo displays available module metadata.
  • dmesg displays kernel log messages.
  • /proc/modules exposes loaded module information.

12. Limitations of lsmod

  • It does not list built-in kernel components.
  • It does not explain every internal dependency or symbol relationship.
  • It does not provide detailed module source code or implementation.
  • It does not show whether a physical device is functioning correctly.
  • It does not replace kernel logs or detailed debugging tools.
Remember: A module appearing in lsmod confirms that it is listed as loaded. It does not by itself prove that the associated hardware or driver operations are working correctly.

13. Lesson Summary

  • lsmod lists currently loaded kernel modules.
  • It reads module information exposed by the kernel through procfs.
  • The output contains module name, size and usage information.
  • The Used by column provides reference and dependency information.
  • /proc/modules provides raw module-list information.
  • Built-in kernel components are not listed as loadable modules.
  • lsmod is useful for driver development and troubleshooting.
