1. Introduction

A Linux kernel module may need to release resources and unregister interfaces when it is removed from the running kernel. This work is performed by the module exit function.

The exit function is the cleanup routine associated with a loadable kernel module. It reverses the operations performed during initialization, where applicable.

For example, if a module allocates memory during initialization, its exit function should release that memory. If it registers a device interface, the exit function should unregister it.

2. What Is a Module Exit Function?

A module exit function is a function that executes when a loadable kernel module is successfully removed from the kernel. It performs cleanup operations before the module's code and data are unloaded.

A typical exit function is defined using the static and __exit keywords. 

static void __exit my_module_exit(void)
{
    /* Cleanup operations */
}

Unlike the initialization function, an exit function has a void return type because it does not return a success or failure status to the module removal mechanism.

3. Syntax of the Exit Function

static void __exit function_name(void)
{
    /* Release resources */
}
Component Description
static Restricts function visibility to the current source file.
void Indicates that the function does not return a value.
__exit Marks the function as module exit or cleanup code.
function_name The programmer-defined name of the cleanup function.
void parameter list Indicates that the function accepts no arguments.

4. When Does the Exit Function Execute?

For a loadable module, the exit function is invoked when the module is successfully unloaded. A user typically requests removal using the rmmod command.

User runs rmmod
↓
Kernel checks whether removal is permitted
↓
Module exit function executes
↓
Resources and interfaces are cleaned up
↓
Module is unloaded

A module generally cannot be removed while it is in use or while dependencies prevent unloading. If removal is rejected, the exit function is not executed.

5. Responsibilities of the Exit Function

The exit function releases resources and reverses registrations made by the module. Common cleanup operations include:

  • Freeing dynamically allocated memory.
  • Unregistering character devices.
  • Removing device nodes and device interfaces created by the driver.
  • Unregistering platform, I2C, SPI or other drivers.
  • Releasing hardware resources owned by the module.
  • Stopping timers and cancelling work where required.
  • Releasing resources associated with interrupt handling.
Important: Cleanup must follow the resource ownership and API requirements of the subsystem. For example, an interrupt handler must be safely released using the appropriate kernel API before its associated data or code can disappear.

6. Writing a Basic Exit Function

The following example displays a message when a module is removed from the kernel.

Source Code: hello_exit.c

#include <linux/module.h>
#include <linux/init.h>

static int __init hello_init(void)
{
    pr_info("Hello: Module loaded\n");

    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Hello: Module removed\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic module exit function example");

Code Explanation

  • hello_init() executes during module loading.
  • hello_exit() executes during successful module removal.
  • pr_info() writes messages to the kernel log.
  • module_init() registers the initialization function.
  • module_exit() registers the cleanup function.
  • MODULE_LICENSE() declares the module's license.

7. Compiling and Testing the Module

Save the source code as hello_exit.c. Create a Makefile in the same directory.

Makefile

obj-m += hello_exit.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The commands under all and clean must begin with a tab character.

Terminal Commands

# Compile the module
make

# Load the module
sudo insmod hello_exit.ko

# Check module status
lsmod | grep hello_exit

# Display the initialization message
sudo dmesg | tail

# Remove the module
sudo rmmod hello_exit

# Display the cleanup message
sudo dmesg | tail

# Clean generated files
make clean

Expected Kernel Log Messages

Hello: Module loaded
Hello: Module removed

The first message is generated during initialization. The second message is generated when the exit function executes during successful removal.

Run these experiments in your Ubuntu VirtualBox environment with matching kernel headers installed. Kernel modules execute with kernel privileges, so test unfamiliar modules in a controlled virtual machine.

8. Releasing Dynamically Allocated Memory

A common responsibility of the exit function is releasing memory allocated during initialization. 

#include <linux/module.h>
#include <linux/init.h>
#include <linux/slab.h>

static int *buffer;

static int __init memory_init(void)
{
    buffer = kmalloc(sizeof(*buffer), GFP_KERNEL);

    if (!buffer) {
        pr_err("Memory allocation failed\n");
        return -ENOMEM;
    }

    *buffer = 250;

    pr_info("Allocated buffer: %d\n", *buffer);

    return 0;
}

static void __exit memory_exit(void)
{
    kfree(buffer);
    buffer = NULL;

    pr_info("Allocated memory released\n");
}

module_init(memory_init);
module_exit(memory_exit);

MODULE_LICENSE("GPL");

The initialization function allocates memory using kmalloc(). The exit function releases the allocated memory using kfree().

Setting the pointer to NULL after freeing memory is a useful defensive programming practice, although it does not replace correct lifetime and concurrency management.

9. Initialization and Exit Function Comparison

Feature Initialization Function Exit Function
Purpose Prepare the module for operation. Clean up the module before removal.
Return type int void
Annotation __init __exit
Registration module_init() module_exit()
Execution During module loading. During successful module unloading.
Typical operations Allocate memory, register devices. Free memory, unregister devices.

10. Important Points About Module Removal

  • The exit function is relevant to unloadable modules.
  • Built-in kernel code cannot be independently removed using rmmod.
  • A module in use may not be removable.
  • Other modules may depend on the module being removed.
  • Cleanup should release all resources owned by the module.
  • Cleanup must prevent outstanding work from accessing unloaded module code or freed data.
Kernel safety: Never unload a module while its callbacks, timers, work items, interrupt handlers or other execution paths can still access its resources. Correct synchronization and teardown ordering are essential.

11. Lesson Summary

  • The module exit function performs cleanup during module removal.
  • It normally uses the void return type.
  • The __exit annotation marks exit code.
  • module_exit() registers the cleanup function.
  • The rmmod command requests module removal.
  • Memory and registered interfaces must be cleaned up correctly.
  • Modules cannot always be unloaded immediately if they are in use.
