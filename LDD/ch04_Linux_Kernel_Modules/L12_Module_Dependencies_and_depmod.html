1. Introduction

Linux kernel modules are often dependent on other modules. A module may use functions or symbols exported by another module to perform its operations.

The kernel module management system must understand these dependencies so that modules are loaded and unloaded in a safe order.

Linux provides the depmod utility to analyze module symbol dependencies and generate dependency information used by tools such as modprobe.

2. What Are Kernel Module Dependencies?

A module dependency exists when one kernel module requires symbols exported by another module.

Consider two modules:

  • Module A: Uses a function exported by Module B.
  • Module B: Provides that function.

Module B must be available before Module A can be successfully loaded.

Module A (Dependent)
↓ requires symbols from
Module B (Provider)

In this example, Module A depends on Module B. The dependency determines the correct loading order.

3. Why Are Module Dependencies Required?

  • To resolve symbols required by a module.
  • To ensure that required modules are loaded first.
  • To prevent removal of modules that are still required.
  • To support automatic dependency handling.
  • To simplify kernel module management.

Without correct dependency information, a module may fail to load because a required symbol is unavailable.

4. What Is depmod?

depmod is a Linux utility that analyzes kernel module files and generates dependency and symbol-related metadata.

It is normally used for modules installed under /lib/modules/ for a particular kernel version.

Basic Syntax

sudo depmod

This generates dependency information for the running kernel version, using the corresponding module directory.

Specify a Kernel Version

sudo depmod 6.x.x-generic

Replace the example version with the actual target kernel release.

5. How depmod Works

The depmod utility scans module files, examines symbol information and builds dependency metadata for the selected kernel release.

Installed Kernel Modules
↓
depmod
↓
Analyze Module Symbols
↓
Generate Dependency Metadata
↓
modprobe Uses Metadata

The generated information helps the module-loading utilities identify which modules must be loaded first.

6. Important Files Generated by depmod

The module dependency database is maintained inside the module directory for a particular kernel version.

Common files include:

File Purpose
modules.dep Records module dependency relationships.
modules.dep.bin Binary dependency database used by module tools.
modules.alias Contains module alias information.
modules.alias.bin Binary alias database.
modules.symbols Symbol alias information for module lookup.
modules.symbols.bin Binary symbol alias database.

The exact set of generated files can vary with the kmod version and distribution.

View the Module Directory

ls /lib/modules/$(uname -r)/

Inspect Dependency Information

cat /lib/modules/$(uname -r)/modules.dep

7. Understanding modules.dep

The modules.dep file contains dependency relationships between installed kernel modules.

An illustrative entry may look like this:

kernel/example/module_a.ko: kernel/example/module_b.ko

This indicates that Module A depends on Module B. Module B must be loaded before Module A.

A module with no listed module dependencies may have an entry with an empty dependency list.

Important: This file is generated metadata. Do not manually edit it. Run depmod to regenerate dependency information after installing or changing modules.

8. Difference Between depmod and modprobe

These commands are related but perform different tasks.

Feature depmod modprobe
Main purpose Generates module dependency and symbol metadata. Loads or removes modules using module management information.
Dependency role Analyzes and records dependencies. Uses dependency information to load required modules.
Typical operation Updates module dependency databases. Loads a module and its required dependencies.
Typical use After installing or updating modules. When managing installed modules.

Examples

# Generate dependency information
sudo depmod

# Load a module and its required dependencies
sudo modprobe my_driver

# Remove a module
sudo modprobe -r my_driver

9. Understanding insmod and modprobe Dependency Handling

The insmod command inserts a specified module file directly. It does not automatically resolve and load the module's dependencies.

The modprobe command uses the installed module dependency database to load required modules.

Command Dependency Handling
insmod module.ko Does not automatically load dependencies.
modprobe module_name Uses dependency information to load required modules.
depmod Generates dependency information for installed modules.

10. Installing an External Kernel Module

When an external module is built and intended to be managed by the normal system module tools, it can be installed into the appropriate module directory.

Step 1: Check Kernel Version

uname -r

Step 2: Build the Module

make

Step 3: Install the Module

sudo install -D -m 644 my_driver.ko \
/lib/modules/$(uname -r)/extra/my_driver.ko

This example copies the compiled module into the extra directory under the running kernel's module tree.

Step 4: Regenerate Dependency Information

sudo depmod -a

The -a option requests dependency processing for the selected kernel release.

Step 5: Load the Installed Module

sudo modprobe my_driver

Step 6: Verify Loading

lsmod | grep my_driver

Step 7: Remove the Module

sudo modprobe -r my_driver
This installation procedure is intended for a test environment. For production systems, use a proper packaging or DKMS workflow where appropriate.

11. Important depmod Options

Option Description
depmod Generate dependency metadata for the default kernel release.
depmod -a Analyze modules and generate dependency information.
depmod -n Write generated dependency information to standard output instead of the normal output files.
depmod -A Update only when module files are newer than the dependency information.
depmod -b basedir Use an alternative base directory for module processing.

Always check man depmod on your distribution for the options supported by its installed version.

12. Practical: Working with depmod

This practical demonstrates how to install an external module into the module directory and update dependency information.

Step 1: Create Source File

Create depmod_demo.c.

#include <linux/module.h>
#include <linux/init.h>

static int __init depmod_demo_init(void)
{
    pr_info("depmod_demo: Module loaded\n");
    return 0;
}

static void __exit depmod_demo_exit(void)
{
    pr_info("depmod_demo: Module removed\n");
}

module_init(depmod_demo_init);
module_exit(depmod_demo_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Demonstration of depmod utility");
MODULE_VERSION("1.0");

Step 2: Create Makefile

obj-m += depmod_demo.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The recipe lines under all and clean must begin with a tab character.

Step 3: Compile

make

Step 4: Install the Module

sudo install -D -m 644 depmod_demo.ko \
/lib/modules/$(uname -r)/extra/depmod_demo.ko

Step 5: Generate Dependency Information

sudo depmod -a

Step 6: Inspect the Installed Module

modinfo depmod_demo

Step 7: Load Using modprobe

sudo modprobe depmod_demo

Step 8: Verify

lsmod | grep depmod_demo
sudo dmesg | tail -n 10

Step 9: Remove the Module

sudo modprobe -r depmod_demo

Step 10: Remove the Installed File

sudo rm /lib/modules/$(uname -r)/extra/depmod_demo.ko
sudo depmod -a

This removes the test module file and regenerates dependency information so that the module database no longer refers to the removed file.

13. Common Errors and Troubleshooting

Problem Possible Cause Suggested Solution
Module not found by modprobe Module is not installed in the correct directory. Check the module path and kernel release.
Dependency information is outdated depmod was not run after installation. Run sudo depmod -a.
Unknown symbol error Required symbol is unavailable or dependency is missing. Inspect dependencies, exported symbols and kernel logs.
Invalid module format Module is incompatible with the target kernel. Rebuild against the appropriate kernel headers.
Module file missing Incorrect installation path or filename. Check using find or ls.

Useful Diagnostic Commands

# Check running kernel
uname -r

# Check module directory
ls /lib/modules/$(uname -r)/

# Inspect module metadata
modinfo my_driver

# Inspect dependency database
grep my_driver /lib/modules/$(uname -r)/modules.dep

# Regenerate dependency information
sudo depmod -a

# Check kernel logs
sudo dmesg | tail -n 30

14. Important Points About Module Dependencies

  • One module may depend on symbols exported by another module.
  • Required modules must be available before dependent modules are loaded.
  • depmod analyzes installed modules and generates dependency metadata.
  • modules.dep stores dependency relationships.
  • modprobe uses dependency information to manage module loading.
  • insmod does not automatically resolve module dependencies.
  • Dependency information should be regenerated after installing or removing module files.

15. Lesson Summary

  • Module dependencies describe relationships between kernel modules.
  • depmod generates module dependency and symbol metadata.
  • modules.dep contains dependency relationships.
  • modprobe uses dependency information for automatic module loading.
  • External modules can be installed under the appropriate kernel module directory.
  • sudo depmod -a refreshes dependency information.
  • Correct dependency management is important for reliable device drivers.
