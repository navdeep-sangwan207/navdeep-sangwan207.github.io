Chapter Overview

Read and write operations provide the basic mechanism for transferring data between user-space applications and device drivers. However, many devices also require configuration and control operations that cannot be conveniently represented as ordinary data transfers.

Linux provides the IOCTL (Input/Output Control) mechanism for implementing device-specific commands. This chapter explains IOCTL command encoding, the unlocked_ioctl() callback, data exchange through IOCTL and the development of a practical character driver with device-control functionality.

Important Kernel Concepts and APIs

  • IOCTL: Mechanism for sending device-specific control commands to a driver.
  • ioctl(): User-space system call used to issue a control request.
  • unlocked_ioctl(): Common file-operation callback for handling IOCTL requests.
  • _IO: Defines a command that does not transfer a data argument through the encoded command type.
  • _IOR: Defines a command that reads data from the driver into user space.
  • _IOW: Defines a command that writes data from user space to the driver.
  • _IOWR: Defines a command that transfers data in both directions.
  • copy_to_user(): Copies data from kernel space to user space.
  • copy_from_user(): Copies data from user space to kernel space.
  • -ENOTTY: Common error returned for an unsupported IOCTL command.

Typical IOCTL Communication Sequence

  • Define IOCTL command identifiers in a shared header file.
  • Open the device file from a user-space application.
  • Call ioctl() with the command and required argument.
  • The kernel dispatches the request to the driver's unlocked_ioctl() callback.
  • The driver validates the command and safely handles any user-space data.
  • The driver performs the requested control operation.
  • The callback returns a success value or an appropriate negative error code.
