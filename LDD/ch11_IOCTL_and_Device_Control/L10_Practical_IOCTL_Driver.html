Chapter: IOCTL and Device Control

Lesson: 10 – Practical IOCTL Driver

Prerequisites: Character driver registration, file operations, IOCTL commands, user-kernel data transfer and error handling.

Objective: Develop, compile, load and test a complete memory-backed character driver that supports reset, set-value and get-value IOCTL operations.

Development Environment: Ubuntu Linux running in VirtualBox, GCC and matching Linux kernel headers.

1. Project Introduction

In this practical project, we will develop a character device driver that accepts control commands from a user-space application through the IOCTL interface.

The driver will maintain an integer value in kernel memory and provide three operations:

Command Operation Purpose
DEVICE_RESET Reset Set the stored value to zero.
SET_DEVICE_VALUE Write Transfer an integer from user space to kernel space.
GET_DEVICE_VALUE Read Transfer the stored integer from kernel space to user space.

This project demonstrates the complete path from application command to driver execution.

2. Project Architecture

User-Space Application
↓ ioctl()
Linux System Call Interface
↓
Character Device Driver
↓
unlocked_ioctl()
↓
Kernel Device Value

The user application sends IOCTL commands through a device file such as /dev/mydevice.

The kernel routes each request to the driver's unlocked_ioctl() callback. The callback identifies the command and performs the requested operation.

4. Create the Shared IOCTL Header

Create my_device_ioctl.h.

#ifndef MY_DEVICE_IOCTL_H
#define MY_DEVICE_IOCTL_H

#ifdef __KERNEL__
#include <linux/ioctl.h>
#include <linux/types.h>
typedef __s32 my_device_s32;
#else
#include <sys/ioctl.h>
#include <stdint.h>
typedef int32_t my_device_s32;
#endif

#define MY_DEVICE_MAGIC 'N'

#define DEVICE_RESET \
    _IO(MY_DEVICE_MAGIC, 1)

#define SET_DEVICE_VALUE \
    _IOW(MY_DEVICE_MAGIC, 2, my_device_s32)

#define GET_DEVICE_VALUE \
    _IOR(MY_DEVICE_MAGIC, 3, my_device_s32)

#endif

Explanation

  • MY_DEVICE_MAGIC identifies this device's IOCTL command group.
  • DEVICE_RESET performs a command without a data argument.
  • SET_DEVICE_VALUE transfers an integer from user space to the driver.
  • GET_DEVICE_VALUE transfers an integer from the driver to user space.
  • The conditional includes provide kernel and user-space definitions of the same fixed-width data type.
Keep this header in a location included by both builds. The kernel Makefile and user-space compiler must use the same header file so that command definitions cannot drift apart.

5. Implement the Kernel Driver

Create ioctl_driver.c.

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/init.h>
#include <linux/uaccess.h>
#include <linux/mutex.h>
#include <linux/err.h>

#include "my_device_ioctl.h"

#define DEVICE_NAME "mydevice"

static dev_t device_number;
static struct cdev my_cdev;

static DEFINE_MUTEX(device_lock);
static my_device_s32 device_value = 0;

/* Open callback */

static int my_open(
    struct inode *inode,
    struct file *file)
{
    pr_info("mydevice: opened\n");
    return 0;
}

/* Release callback */

static int my_release(
    struct inode *inode,
    struct file *file)
{
    pr_info("mydevice: closed\n");
    return 0;
}

/* IOCTL callback */

static long my_ioctl(
    struct file *file,
    unsigned int cmd,
    unsigned long arg)
{
    my_device_s32 value;
    long ret = 0;

    switch (cmd) {

    case DEVICE_RESET:

        mutex_lock(&device_lock);

        device_value = 0;

        mutex_unlock(&device_lock);

        pr_info("mydevice: value reset\n");
        break;

    case SET_DEVICE_VALUE:

        if (copy_from_user(
                &value,
                (my_device_s32 __user *)arg,
                sizeof(value))) {
            return -EFAULT;
        }

        if (value < 0 || value > 1000) {
            return -EINVAL;
        }

        mutex_lock(&device_lock);

        device_value = value;

        mutex_unlock(&device_lock);

        pr_info("mydevice: value updated\n");
        break;

    case GET_DEVICE_VALUE:

        mutex_lock(&device_lock);

        value = device_value;

        mutex_unlock(&device_lock);

        if (copy_to_user(
                (my_device_s32 __user *)arg,
                &value,
                sizeof(value))) {
            return -EFAULT;
        }

        pr_info("mydevice: value read\n");
        break;

    default:
        ret = -ENOTTY;
        break;
    }

    return ret;
}

/* File operations */

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .release = my_release,
    .unlocked_ioctl = my_ioctl
};

/* Module initialization */

static int __init my_driver_init(void)
{
    int ret;

    /* Allocate device number */

    ret = alloc_chrdev_region(
        &device_number,
        0,
        1,
        DEVICE_NAME);

    if (ret < 0) {
        pr_err("mydevice: device number allocation failed\n");
        return ret;
    }

    /* Initialize character device */

    cdev_init(&my_cdev, &my_fops);
    my_cdev.owner = THIS_MODULE;

    /* Add character device */

    ret = cdev_add(
        &my_cdev,
        device_number,
        1);

    if (ret < 0) {
        pr_err("mydevice: cdev_add failed\n");
        unregister_chrdev_region(device_number, 1);
        return ret;
    }

    pr_info("mydevice: driver registered\n");
    pr_info("mydevice: major = %u, minor = %u\n",
            MAJOR(device_number),
            MINOR(device_number));

    return 0;
}

/* Module cleanup */

static void __exit my_driver_exit(void)
{
    cdev_del(&my_cdev);

    unregister_chrdev_region(device_number, 1);

    pr_info("mydevice: driver unregistered\n");
}

module_init(my_driver_init);
module_exit(my_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Practical IOCTL Character Device Driver");

Important Driver Concepts

  • alloc_chrdev_region() dynamically allocates a device number.
  • cdev_init() associates the character device with file operations.
  • cdev_add() makes the character-device registration available.
  • unlocked_ioctl() handles IOCTL requests.
  • copy_from_user() receives input data.
  • copy_to_user() returns output data.
  • mutex protects the shared device value from concurrent access.
This is a teaching driver. It registers a character device but does not create a /dev node automatically. The device node will be created manually in this exercise using the actual major and minor numbers printed by the driver.

6. Create the Kernel Module Makefile

Create a file named Makefile.

obj-m += ioctl_driver.o

KDIR := /lib/modules/$(shell uname -r)/build
PWD := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

The Makefile instructs Kbuild to compile ioctl_driver.c into a loadable kernel module.

The recipe lines beginning with $(MAKE) must start with actual tab characters, not spaces.

7. Implement the User-Space Test Program

Create test_ioctl.c.

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>

#include "my_device_ioctl.h"

int main(void)
{
    int fd;
    my_device_s32 value;

    fd = open("/dev/mydevice", O_RDWR);

    if (fd == -1) {
        perror("open");
        return EXIT_FAILURE;
    }

    printf("Device opened successfully\n");

    /* Reset */

    if (ioctl(fd, DEVICE_RESET) == -1) {
        perror("DEVICE_RESET");
        goto error;
    }

    printf("Device reset successful\n");

    /* Set value */

    value = 250;

    if (ioctl(fd, SET_DEVICE_VALUE, &value) == -1) {
        perror("SET_DEVICE_VALUE");
        goto error;
    }

    printf("Value sent to driver: %d\n", value);

    /* Get value */

    value = 0;

    if (ioctl(fd, GET_DEVICE_VALUE, &value) == -1) {
        perror("GET_DEVICE_VALUE");
        goto error;
    }

    printf("Value received from driver: %d\n", value);

    close(fd);

    return EXIT_SUCCESS;

error:
    close(fd);
    return EXIT_FAILURE;
}

Application Workflow

  1. Open the device file.
  2. Send the reset command.
  3. Send the integer 250 to the driver.
  4. Request the stored integer.
  5. Display the returned value.
  6. Close the device file.

8. Install Required Build Tools

Open Ubuntu terminal and update the package information.

sudo apt update

Install the compiler and required build tools:

sudo apt install build-essential linux-headers-$(uname -r)

Verify the running kernel version:

uname -r

Verify that the kernel build directory exists:

ls -l /lib/modules/$(uname -r)/build

The headers must match the running kernel. If matching headers are unavailable, use a kernel version for which Ubuntu provides the corresponding headers.

9. Compile the Kernel Driver

Move into the project directory:

cd practical_ioctl

Build the module:

make

If compilation succeeds, the module file should be generated:

ls -l ioctl_driver.ko

The .ko extension identifies a Linux kernel module.

10. Load the Kernel Module

Insert the module:

sudo insmod ioctl_driver.ko

Check whether it is loaded:

lsmod | grep ioctl_driver

Inspect recent kernel messages:

sudo dmesg | tail -n 20

Look for the driver's registration message and its dynamically allocated major/minor numbers.

mydevice: driver registered
mydevice: major = <actual-major>, minor = 0

The numbers above are placeholders. Use the actual values printed by your driver.

11. Create the Device Node

The driver in this project does not call device_create(). Therefore, create a device node manually.

Use the major and minor numbers reported in the kernel log:

sudo mknod /dev/mydevice c <actual-major> 0

Replace <actual-major> with the actual major number. Do not type the placeholder literally.

Set temporary permissions for this controlled exercise:

sudo chmod 666 /dev/mydevice

Verify the node:

ls -l /dev/mydevice
stat /dev/mydevice
mknod creates a device-file entry; it does not load the module or register the character driver. The device number must match the registered driver. The broad permissions above are for a temporary lab exercise only; production devices should use appropriately restricted ownership and permissions.

12. Compile the User-Space Application

Compile the application separately from the kernel module:

gcc -Wall -Wextra test_ioctl.c -o test_ioctl

Verify the executable:

ls -l test_ioctl

The user-space application uses GCC directly. It is not compiled through Kbuild.

13. Execute the IOCTL Test Program

Run the application:

sudo ./test_ioctl

Illustrative expected output:

Device opened successfully
Device reset successful
Value sent to driver: 250
Value received from driver: 250

The value returned by the driver should be 250 because that is the value sent by the application.

Verify Kernel Messages

sudo dmesg | tail -n 20

Depending on the driver's logging and system configuration, you may see messages for device opening, resetting, updating and reading.

14. Test Invalid Input

The driver accepts integer values from 0 through 1000. Modify the test application temporarily:

value = 5000;

if (ioctl(fd, SET_DEVICE_VALUE, &value) == -1) {
    perror("SET_DEVICE_VALUE");
}

The driver should reject this value with -EINVAL. The application should report an error similar to:

SET_DEVICE_VALUE: Invalid argument

This verifies that validation is performed inside the kernel driver.

15. Test an Unsupported IOCTL Command

For an additional test, temporarily add an unsupported request to the application:

#define INVALID_COMMAND _IO('N', 99)

if (ioctl(fd, INVALID_COMMAND) == -1) {
    perror("INVALID_COMMAND");
}

The driver's default switch case should return -ENOTTY.

Expected error text is typically:

INVALID_COMMAND: Inappropriate ioctl for device

16. Debugging with strace

strace can trace system calls made by the user-space application.

Install it if necessary:

sudo apt install strace

Trace the application's device operations:

strace -e openat,ioctl,close ./test_ioctl

To inspect an application that requires elevated permissions:

sudo strace -e openat,ioctl,close ./test_ioctl

The trace helps identify:

  • Whether the application opens the expected device path.
  • Which IOCTL requests are issued.
  • Whether a system call succeeds or fails.
  • Which error is returned to user space.

Request codes may appear as numeric values or symbolic names depending on the tracing tool's decoding support.

17. Unload the Driver and Clean Up

Close the test application before unloading the module.

Remove the device node:

sudo rm /dev/mydevice

Unload the module:

sudo rmmod ioctl_driver

Verify that it has been removed:

lsmod | grep ioctl_driver

Clean generated build files:

make clean
Do not unload the module while applications are still using it. The file-operations owner reference normally prevents unloading while active file operations hold module references. Device and resource lifetime still need careful management in more complex drivers.

19. Important Practical Notes

  • This driver is memory-backed and does not control physical hardware.
  • The stored value is shared kernel state protected by a mutex.
  • The shared header ensures matching IOCTL command definitions.
  • The device node must use the actual registered major/minor numbers.
  • The driver returns negative kernel error codes; user space sees -1 and checks errno.
  • The project should be tested against the exact kernel version for which the module was built.
  • Secure Boot or module-signing policy may prevent loading an unsigned module on some Ubuntu installations.
Run experimental kernel modules inside your Ubuntu virtual machine. A programming mistake in kernel space can crash or destabilize the guest operating system. Save your work before testing.
