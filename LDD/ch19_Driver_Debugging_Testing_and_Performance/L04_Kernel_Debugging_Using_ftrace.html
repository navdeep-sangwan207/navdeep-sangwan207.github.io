1. Introduction to ftrace

ftrace is a Linux kernel tracing framework used to analyze kernel execution and investigate performance and debugging problems.

It allows developers to observe function calls, trace selected kernel events, investigate scheduling activity and examine execution timing.

Unlike printk(), which records messages explicitly added by a developer, ftrace can trace kernel activities using facilities built into the kernel.

Common Applications

  • Tracing kernel function calls.
  • Understanding driver execution flow.
  • Investigating interrupt activity.
  • Analyzing scheduler behaviour.
  • Measuring function execution time.
  • Identifying unexpected kernel activity.
  • Investigating performance bottlenecks.
Example: If a device driver's probe() function takes too long to complete, function tracing can help identify the functions called during initialization.

2. ftrace Architecture

ftrace collects tracing information in kernel-managed buffers. Developers configure tracing through tracefs and inspect the resulting data.

3. Tracefs Filesystem

ftrace is commonly controlled through the tracefs virtual filesystem.

Its usual mount location is:

/sys/kernel/tracing

Check Whether Tracefs Is Mounted

mount | grep tracefs

Mount Tracefs

sudo mount -t tracefs tracefs /sys/kernel/tracing

List Tracing Files

ls /sys/kernel/tracing

Important Files

FilePurpose
available_tracersLists supported tracers.
current_tracerSelects the active tracer.
tracing_onControls recording.
traceDisplays collected trace data.

set_ftrace_notraceExcludes selected functions.
tracing_cpumaskControls CPUs included in tracing.

4. Available ftrace Tracers

Different tracers provide different information. The exact list depends on kernel configuration.

Check Available Tracers

cat /sys/kernel/tracing/available_tracers
TracerPurpose
nopNo active tracer; default inactive mode.
functionRecords kernel function calls.
function_graphRecords function entry and return relationships.
irqsoffInvestigates long periods with interrupts disabled.
preemptoffInvestigates long periods with preemption disabled.
preemptirqsoffInvestigates latency involving disabled preemption or interrupts.
wakeupMeasures certain task wake-up latency behaviour.
wakeup_rtAnalyzes wake-up latency for real-time tasks where supported.

Not every kernel provides all these tracers.

5. Function Tracing

Function tracing records kernel functions as they are executed.

Step 1: Navigate to Tracefs

cd /sys/kernel/tracing

Step 2: Select Function Tracer

echo function | sudo tee current_tracer

Step 3: Enable Tracing

echo 1 | sudo tee tracing_on

Step 4: View Trace Output

sudo cat trace

Step 5: Stop Tracing

echo 0 | sudo tee tracing_on

Step 6: Disable the Tracer

echo nop | sudo tee current_tracer
The trace output depends on kernel activity and available tracing support. The trace file is a snapshot; trace_pipe is used for streaming records.

6. Function Filtering

Function filtering limits tracing to selected functions. This is useful because tracing every kernel function can produce a large amount of data.

List Available Traceable Functions

cat /sys/kernel/tracing/available_filter_functions

Trace a Specific Function

cd /sys/kernel/tracing

echo my_driver_probe | sudo tee set_ftrace_filter
echo function | sudo tee current_tracer
echo 1 | sudo tee tracing_on

View the Result

sudo cat trace

Clear the Filter

echo | sudo tee set_ftrace_filter

Replace my_driver_probe with an actual traceable function name. Some functions may not be available because of compiler optimization, tracing configuration or other kernel restrictions.

7. Function Graph Tracing

Function graph tracing records function entry and return relationships. It helps developers understand nested function calls.

Select Function Graph Tracer

cd /sys/kernel/tracing

echo function_graph | sudo tee current_tracer

Enable Tracing

echo 1 | sudo tee tracing_on

View the Trace

sudo cat trace

Stop Tracing

echo 0 | sudo tee tracing_on

Reset

echo nop | sudo tee current_tracer

Function graph output can show nested function execution and timing information when supported.

8. Event Tracing

Event tracing records selected events generated by kernel subsystems.

Examples include:

  • Scheduler events.
  • Interrupt events.
  • Block I/O events.
  • System-call events.
  • Network events.
  • Power-management events.

List Available Events

cat /sys/kernel/tracing/available_events

List Scheduler Events

ls /sys/kernel/tracing/events/sched

Enable a Scheduler Event

echo 1 | sudo tee \
/sys/kernel/tracing/events/sched/sched_switch/enable

Start Recording

echo 1 | sudo tee /sys/kernel/tracing/tracing_on

View the Trace

sudo cat /sys/kernel/tracing/trace

Disable the Event

echo 0 | sudo tee \
/sys/kernel/tracing/events/sched/sched_switch/enable

9. Trace Buffer

ftrace uses kernel-managed buffers to store tracing records.

Important concepts include:

  • Per-CPU trace buffers.
  • Buffer size.
  • Trace record format.
  • Buffer overwrite behaviour.
  • Trace snapshots.

Check Buffer Size

cat /sys/kernel/tracing/buffer_size_kb

Change Buffer Size

echo 2048 | sudo tee \
/sys/kernel/tracing/buffer_size_kb

The value represents the buffer size in kilobytes per CPU.

Increasing the buffer size consumes additional kernel memory. Choose a suitable value for the system and tracing workload.

10. trace and trace_pipe

InterfacePurpose
traceDisplays the current contents of the trace buffer.
trace_pipeProvides a streaming interface that consumes trace records as they are read.

Read a Trace Snapshot

sudo cat /sys/kernel/tracing/trace

Follow Trace Output

sudo cat /sys/kernel/tracing/trace_pipe

trace_pipe waits for new records when no data is immediately available.

11. Tracing Driver Execution

ftrace can help investigate how a driver interacts with kernel subsystems.

Consider a platform device driver with these important functions:

  • module initialization.
  • platform driver registration.
  • probe().
  • device resource initialization.
  • remove().
  • module cleanup.

By tracing selected functions, developers can investigate the sequence of operations and identify where an unexpected delay or failure occurs.

Example Function Filter

echo 'my_platform_probe' | sudo tee \
/sys/kernel/tracing/set_ftrace_filter

echo function | sudo tee \
/sys/kernel/tracing/current_tracer

echo 1 | sudo tee \
/sys/kernel/tracing/tracing_on

Only functions present in the available traceable function list can be selected successfully.

12. Measuring Function Execution Time

Function graph tracing can display timing information for function execution.

Enable Function Graph Tracing

cd /sys/kernel/tracing

echo function_graph | sudo tee current_tracer
echo 1 | sudo tee tracing_on

View Results

sudo cat trace

The trace may display function durations and nested calls, depending on the tracing configuration and available clock source.

This information can help identify:

  • Slow driver callbacks.
  • Unexpectedly long function execution.
  • Expensive initialization paths.
  • Functions contributing to latency.

16. Best Practices

  1. Start with a clear debugging objective.
  2. Check available tracers before selecting one.
  3. Use function filters to reduce unnecessary records.
  4. Use event tracing for specific subsystem activity.
  5. Monitor trace buffer size.
  6. Stop tracing after collecting the required data.
  7. Reset the tracer when testing is complete.
  8. Use function graph tracing for nested function analysis.
  9. Record kernel version and configuration.
  10. Consider tracing overhead when measuring performance.

17. Important Points to Remember

  • ftrace is a Linux kernel tracing framework.
  • Tracefs provides the main control interface.
  • Function tracer records kernel function calls.
  • Function graph tracer shows nested execution.
  • Event tracing records selected kernel events.
  • set_ftrace_filter limits function tracing.
  • trace displays collected records.
  • trace_pipe provides streaming output.
  • ftrace can help analyze driver execution and latency.
  • Tracing overhead and buffer usage should be considered.

19. Lesson Summary

ftrace is a powerful Linux kernel tracing framework used to understand kernel execution, investigate device-driver behaviour and analyze performance problems.

Its function tracer, function graph tracer and event tracing facilities provide different views of kernel activity. Tracefs allows developers to configure tracing and inspect collected records.

By selecting appropriate functions and events, developers can investigate driver initialization, function execution, scheduling behaviour and latency in a structured manner.
