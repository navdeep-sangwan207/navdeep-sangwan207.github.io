2. Introduction to Kernel Performance Profiling

Kernel performance profiling is the process of measuring and analyzing the execution behavior of the Linux kernel and its components.

It helps developers understand how much system resources are consumed by kernel functions, device drivers and other operations.

Why profiling is important

  • Identify slow kernel functions.
  • Find CPU-intensive operations.
  • Detect excessive interrupt processing.
  • Investigate scheduling delays.
  • Analyze memory and I/O bottlenecks.
  • Improve device-driver efficiency.

3. Performance Metrics

Performance profiling uses several measurements to evaluate system behavior.

MetricDescription
CPU UsagePercentage of processor time being used.
Execution TimeTime required to execute a function or operation.
LatencyDelay between an event and its completion or response.
ThroughputAmount of work completed per unit of time.
Context SwitchesNumber of times CPU execution switches between tasks.
Cache MissesMemory accesses that cannot be served by the relevant CPU cache.
Interrupt RateFrequency of interrupt events.
Memory UsageAmount of memory consumed by the system or component.

4. Understanding Performance Bottlenecks

A performance bottleneck is a component or operation that limits overall system performance.

Common kernel bottlenecks

  • CPU-intensive loops.
  • Excessive interrupt handling.
  • Long critical sections.
  • Frequent memory allocation.
  • Unnecessary context switching.
  • Slow device I/O operations.
  • Lock contention between CPUs.

Example

Suppose a driver performs a large amount of unnecessary processing inside an interrupt handler. This can increase interrupt latency and reduce the time available for other tasks.

Profiling helps identify where the execution time is being spent so the developer can optimize the appropriate part of the driver.

5. Introduction to the perf Tool

perf is a Linux performance analysis tool that uses kernel performance events and hardware performance monitoring facilities where available.

It can analyze applications, kernel functions, CPU activity and selected system events.

Major capabilities

  • CPU performance profiling.
  • Function-level analysis.
  • Hardware and software event monitoring.
  • Call-graph recording.
  • Scheduler activity analysis.
  • Kernel and application profiling.

Install perf on Ubuntu

sudo apt update
sudo apt install linux-tools-common
sudo apt install linux-tools-$(uname -r)

Package availability varies by Ubuntu release and kernel. If the exact versioned package is unavailable, install the matching distribution-provided tools package.

7. Measuring Performance Using perf stat

perf stat collects performance counter statistics while a command executes.

Example

perf stat ls -R /usr

The output may include:

  • Task-clock time.
  • Context switches.
  • CPU migrations.
  • Page faults.
  • CPU cycles.
  • Instructions executed.
  • Branch instructions and branch misses.

Example with selected events

perf stat -e cycles,instructions,cache-misses ls -R /usr
The availability of hardware events depends on the processor, kernel, hypervisor and permissions. Some events may be unsupported in VirtualBox.

8. CPU Profiling Using perf record

perf record collects profiling samples for later analysis.

Example

perf record -g ls -R /usr

The -g option requests call-graph information where supported and configured.

View the recorded report

perf report

The report identifies functions that consumed significant sampled CPU time.

Typical report fields

  • Overhead percentage.
  • Command name.
  • Shared object or kernel image.
  • Symbol or function name.
  • Call-chain information, if recorded.

9. Live Performance Monitoring Using perf top

perf top displays a continuously updated view of sampled performance hotspots.

Command

sudo perf top

It can help identify functions that are consuming a significant amount of CPU time while the system is running.

Useful applications

  • Finding CPU-intensive kernel functions.
  • Monitoring system activity during driver tests.
  • Observing changes after a driver optimization.
  • Identifying unexpected execution hotspots.

10. Function-Level Performance Analysis

Function-level profiling helps determine which functions consume the most CPU time.

For example, a device driver may contain these functions:

my_driver_open()
my_driver_read()
my_driver_write()
my_driver_interrupt()
my_driver_ioctl()

Profiling can help determine whether a particular callback or interrupt handler is a performance hotspot.

Example kernel profiling command

sudo perf record -a -g
sudo perf report

The first command records system-wide profiling data until it is stopped, usually with Ctrl+C. The second opens the recorded report.

System-wide recording can produce substantial data and may require elevated permissions. Use a controlled test workload and limit the recording duration.

11. Understanding Call Graphs

A call graph represents the relationships between functions during execution.

Example

A call graph helps identify which functions are called by other functions and where sampled execution time is concentrated.

Why call graphs are useful

  • Identify expensive function chains.
  • Understand driver callback execution.
  • Locate repeated function calls.
  • Investigate performance overhead.

12. Scheduler Performance Analysis

The Linux scheduler manages CPU time among runnable tasks.

Scheduler performance analysis helps developers understand task scheduling delays, context switches and CPU utilization.

Useful perf commands

sudo perf sched record
sudo perf sched latency
sudo perf sched timehist

These commands can help investigate scheduling behavior in a controlled workload. Available subcommands and output depend on the perf version.

Important scheduler metrics

  • Scheduling latency.
  • Task wait time.
  • Context-switch frequency.
  • CPU migration.
  • Runnable task behavior.

13. Interrupt Performance Analysis

Interrupt handling is important in device-driver performance because interrupt handlers execute in response to hardware events.

Excessive interrupt processing can reduce CPU availability for other tasks.

Useful commands

cat /proc/interrupts
watch -n 1 cat /proc/interrupts

/proc/interrupts displays interrupt counts for available CPUs and interrupt sources.

What to investigate

  • Unexpectedly high interrupt counts.
  • Interrupt distribution across CPUs.
  • Repeated interrupts without useful work.
  • Long-running interrupt processing.
  • Excessive deferred work.

14. Memory and Cache Performance Analysis

Memory behavior can influence kernel and driver performance.

Common issues

  • Frequent memory allocation and deallocation.
  • Cache misses.
  • Unnecessary memory copying.
  • Poor data locality.
  • Memory bandwidth limitations.

Example command

perf stat -e cache-references,cache-misses \
ls -R /usr

Where supported, cache events can help investigate memory-access behavior.

Cache-event names and availability are hardware-specific. Virtual machines may not expose all physical processor performance counters.

16. Profiling a Device Driver

Consider a character driver that processes data in its read callback.

Example driver callback

static ssize_t my_read(struct file *file,
                       char __user *buffer,
                       size_t count,
                       loff_t *offset)
{
    unsigned int i;

    for (i = 0; i < 100000; i++) {
        /* Example processing workload */
    }

    return 0;
}

This example contains a loop that performs unnecessary work. A profiling session can help determine whether this callback consumes excessive CPU time.

Profiling workflow

  1. Build and load the test driver.
  2. Run a controlled application that invokes the read callback.
  3. Record performance samples.
  4. Inspect the perf report.
  5. Identify expensive functions.
  6. Optimize the relevant code.
  7. Repeat the same workload and compare results.
A real read callback must also implement correct user-space data transfer, return-value handling and end-of-file behavior. The code above is only a profiling illustration.

17. Practical Exercise – Basic CPU Profiling

Objective: Use perf to collect basic performance statistics in Ubuntu.

Step 1: Install perf

sudo apt update
sudo apt install linux-tools-common
sudo apt install linux-tools-$(uname -r)

Step 2: Check perf

perf --version

Step 3: Run a test command

perf stat ls -R /usr

Step 4: Record profiling information

perf record -g ls -R /usr

Step 5: Display the report

perf report

Expected Result: You should see performance statistics and a profiling report for the test command. Exact event counts depend on your CPU, kernel, permissions and virtual-machine configuration.

18. Practical Exercise – Monitoring System Activity

Objective: Observe CPU hotspots and interrupt activity.

Step 1: Monitor CPU hotspots

sudo perf top

Step 2: Inspect interrupt counts

cat /proc/interrupts

Step 3: Observe changes

watch -n 1 cat /proc/interrupts

Step 4: Stop monitoring

Press Ctrl+C to stop the monitoring commands.

Expected Result: You should be able to observe sampled CPU activity and changes in interrupt counters.

19. Performance Optimization Best Practices

  • Measure performance before making changes.
  • Identify the actual bottleneck instead of guessing.
  • Keep interrupt handlers short.
  • Reduce unnecessary memory copies.
  • Avoid excessive locking and lock contention.
  • Use suitable buffering strategies.
  • Avoid unnecessary allocations in frequently executed paths.
  • Compare measurements using the same workload.
  • Consider latency as well as average throughput.
  • Validate that optimizations do not introduce synchronization or memory errors.
