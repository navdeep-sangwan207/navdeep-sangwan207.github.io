Lesson 7: dev_t Data Type
Level: Intermediate
Prerequisites: Major and minor numbers, device-number allocation and basic kernel C programming.
Objective: Understand how Linux represents device numbers using dev_t and how to construct, extract and use device-number values.

1. Introduction to dev_t

Linux identifies registered devices using device numbers. A device number contains two logical components:

  • Major number: Identifies the driver registration or associated device-number range.
  • Minor number: Identifies a particular device or instance within that range.

The Linux kernel provides a special data type called dev_t to represent a device number. 

dev_t dev;

A driver commonly uses a dev_t variable to store the starting device number returned by alloc_chrdev_region() or to construct a fixed device number using MKDEV().

2. Why Is dev_t Required?

A major number and a minor number are separate logical values. The kernel needs a standard representation to pass and manage them together.

The dev_t type provides this representation.

Device Number
↓
dev_t
↓

Major Number

Identifies the registered driver range.

Minor Number

Identifies a device instance within the range.

Important Uses

  • Storing a device number in a kernel driver.
  • Passing a device number to registration functions.
  • Extracting major and minor values.
  • Creating device nodes with the correct device number.
  • Associating a character-device inode with its device number.

3. Declaration of dev_t

The Linux kernel defines dev_t as an integer-based type used to represent device numbers.

It is defined through Linux kernel type definitions, commonly made available through headers such as <linux/types.h>.

Example

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/types.h>

static dev_t device_number;

The variable device_number can store a complete device number containing both major and minor components.

Do not assume that dev_t is simply a major number or a minor number. It represents the combined device-number value. Use the kernel helper macros to construct and extract its components.

4. MKDEV() Macro

The MKDEV() macro constructs a device number from a major number and a minor number.

Syntax

MKDEV(major, minor)

Example

dev_t dev;

dev = MKDEV(240, 0);

This creates a device-number value with:

Component Value
Major number 240
Minor number 0

Another example: 

dev_t dev;

dev = MKDEV(250, 5);

The resulting device number represents major 250 and minor 5.

MKDEV() only constructs a device-number value. It does not reserve the number or register a character device. Use the appropriate registration function to reserve the range.

5. MAJOR() Macro

The MAJOR() macro extracts the major number from a dev_t value.

Syntax

MAJOR(dev)

Example

dev_t dev;

dev = MKDEV(240, 5);

pr_info("Major number: %u\n", MAJOR(dev));

Expected output:

Major number: 240

6. MINOR() Macro

The MINOR() macro extracts the minor number from a dev_t value.

Syntax

MINOR(dev)

Example

dev_t dev;

dev = MKDEV(240, 5);

pr_info("Minor number: %u\n", MINOR(dev));

Expected output:

Minor number: 5

8. Using dev_t with Dynamic Allocation

A common use of dev_t is storing the starting device number returned by alloc_chrdev_region().

Example

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/kdev_t.h>
#include <linux/init.h>

static dev_t dev;

static int __init dev_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        4,
        "mydevice"
    );

    if (ret < 0) {
        pr_err("Allocation failed\n");
        return ret;
    }

    pr_info("Allocated major: %u\n", MAJOR(dev));
    pr_info("Starting minor: %u\n", MINOR(dev));

    return 0;
}

static void __exit dev_exit(void)
{
    unregister_chrdev_region(dev, 4);

    pr_info("Device numbers released\n");
}

module_init(dev_init);
module_exit(dev_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("dev_t Data Type Example");

Explanation

  1. static dev_t dev declares a device-number variable.
  2. alloc_chrdev_region() requests four consecutive numbers.
  3. The kernel stores the starting device number in dev.
  4. MAJOR(dev) extracts the allocated major number.
  5. MINOR(dev) extracts the starting minor number.
  6. unregister_chrdev_region() releases the range during module removal.

9. dev_t in Character Device Structures

The device number is also important when working with character-device structures.

struct inode

A device node opened by a user-space application is represented through the kernel's VFS structures. For device files, the inode contains a device number in its i_rdev member. 

dev_t dev;

dev = inode->i_rdev;

The driver can extract the major and minor values from this device number. 

unsigned int major_num;
unsigned int minor_num;

major_num = MAJOR(inode->i_rdev);
minor_num = MINOR(inode->i_rdev);

struct cdev

A character device is represented by struct cdev. The kernel associates its registered device-number range with this character-device object.

The cdev_add() function receives a starting dev_t value and a count when registering the character device. 

cdev_add(&my_cdev, dev, 4);

This registers the character-device object for the specified range, assuming the device-number range has already been reserved.

10. Device Number vs Device Node

A device number and a device node are related but different concepts.

Device Number Device Node
A kernel identifier represented by dev_t. A special filesystem entry, usually located under /dev.
Contains major and minor components. Stores a device number that identifies the associated device.
Used by kernel device registration and lookup mechanisms. Provides a user-space pathname for accessing a device.
Can be reserved without creating a device node. Can exist as a node without guaranteeing that a working driver is registered.

Example

ls -l /dev/null

Typical output includes: 

crw-rw-rw- 1 root root 1, 3 ... /dev/null

Here, the device number is major 1 and minor 3. The c at the beginning identifies a character device.

11. Practical Commands in Ubuntu

Step 1: Inspect a Character Device

ls -l /dev/null

Step 2: Display Device Information

stat /dev/null

Step 3: Display Major and Minor Numbers

stat -c 'Major: %t, Minor: %T' /dev/null

The %t and %T format specifiers display hexadecimal major and minor values.

Step 4: Inspect Character Device Entries

find /dev -type c | head -20

Step 5: Inspect Registered Device Information

ls -l /sys/dev/char/

The entries under /sys/dev/char/ provide kernel sysfs information for registered character devices.

12. Common Mistakes

Mistake Correct Understanding
Using a plain integer instead of dev_t for device numbers. Use the kernel-provided dev_t type.
Assuming MKDEV() reserves a number. It only constructs the device-number value.
Using MAJOR() to obtain the minor number. Use MINOR() for the minor component.
Assuming allocation creates a device node. Allocation, cdev registration and device-node creation are separate operations.
Using an arbitrary major number for a real driver. Prefer dynamic allocation unless a fixed number is specifically required.

13. Summary

  • dev_t is the Linux kernel type used to represent device numbers.
  • A device number contains major and minor components.
  • MKDEV() constructs a device number.
  • MAJOR() extracts the major number.
  • MINOR() extracts the minor number.
  • alloc_chrdev_region() can store an allocated starting number in a dev_t variable.
  • inode->i_rdev provides the device number associated with a device-file inode.
  • cdev_add() uses a device number and count when registering a character device.
