Chapter 7: Character Device Driver Fundamentals

Home Course Chapter 7
Lesson 3: Character Devices vs Network Devices
Level: Intermediate
Prerequisites: Character devices, block devices, Linux kernel architecture and basic networking.
Objective: Understand how Linux character-device interfaces differ from network-device interfaces and how network drivers interact with the kernel networking subsystem.

1. Introduction

Linux supports several device categories, including character devices, block devices and network devices. Each category provides a different interface between the kernel and hardware.

Character devices commonly provide byte-oriented input and output through device files. Network devices provide packet-oriented communication through the Linux networking subsystem.

A network interface is not normally accessed as a conventional character device. Instead, applications use networking interfaces such as sockets, while the network driver communicates with the networking subsystem.

2. What Is a Character Device?

A character device is a device registered with the Linux character-device subsystem. It commonly transfers data as a stream of bytes.

Examples

  • Serial ports.
  • USB-to-serial interfaces.
  • Terminal devices.
  • Input event devices.
  • Null and random devices.

Example Device Nodes

/dev/ttyS0
/dev/ttyUSB0
/dev/tty
/dev/null
/dev/input/event0

Applications commonly access these interfaces using system calls such as open(), read(), write() and ioctl().

3. What Is a Network Device?

A network device is an interface used to send and receive network packets. It may represent physical hardware, such as an Ethernet adapter or Wi-Fi adapter, or a virtual network interface.

Examples

  • Ethernet network interfaces.
  • Wi-Fi network interfaces.
  • Virtual Ethernet interfaces.
  • Loopback interface.
  • Virtual interfaces used by containers and virtual machines.

Example Network Interface Names

eth0
enp3s0
wlan0
wlp2s0
lo
veth0

Actual interface names depend on the system, hardware and network configuration.

4. Character Device Architecture

A character driver commonly registers a struct cdev object and associates it with a set of file operations.

User Application
↓
System Calls: open(), read(), write(), ioctl()
↓
Virtual File System (VFS)
↓
Character Device Subsystem
↓
Character Device Driver
↓
Device or Kernel-Managed Interface

Important Structures

  • dev_t – represents a device number.
  • struct cdev – represents a character device registration.
  • struct file_operations – contains operation callbacks.
  • struct file – represents an open file instance in the kernel.

5. Network Device Architecture

Linux network drivers integrate with the networking subsystem. They use network-device interfaces rather than the conventional character-device registration model.

Network Application
↓
Socket API
↓
Linux Networking Stack
↓
Network Device Interface
↓
Network Driver
↓
Ethernet / Wi-Fi Hardware

Important Concepts

  • struct net_device – represents a network interface.
  • struct net_device_ops – contains network-device operation callbacks.
  • sk_buff – represents a network packet buffer.
  • Socket API – allows applications to communicate through network protocols.
  • NAPI – supports efficient packet processing, particularly under high network load.

A network driver registers and manages its network interface using the Linux networking APIs appropriate to the target kernel.

6. Major Differences

Feature Character Device Network Device
Primary purpose Device-specific input and output. Network packet transmission and reception.
Data model Generally byte-stream oriented. Packet-oriented.
Kernel subsystem Character-device subsystem. Networking subsystem.
Common user interface Device file operations. Socket API and network configuration interfaces.
Typical device representation Device node under /dev. Network interface such as eth0 or lo.
Main kernel structure struct cdev struct net_device
Operation interface struct file_operations struct net_device_ops
Data buffer Driver-defined buffers and user-space transfer helpers. Commonly uses struct sk_buff.
Examples Serial port, terminal and input event interface. Ethernet, Wi-Fi and virtual network interface.

7. How Character Device Data Is Transferred

Consider a serial device connected through a USB-to-serial adapter.

An application opens the corresponding device node and uses read or write operations to exchange bytes with the device. 

int fd;

fd = open("/dev/ttyUSB0", O_RDWR);

if (fd < 0) {
    perror("open");
    return 1;
}

/* Application performs read() or write(). */

close(fd);

This is a simplified example. Real serial applications generally configure baud rate, parity, data bits and other terminal settings.

A USB-to-serial adapter may involve both USB and serial subsystems internally. The device node shown to the application is commonly a character-device interface.

8. How Network Data Is Transferred

Network applications commonly use sockets to communicate with remote systems.

For example, a TCP client uses socket operations to establish a connection and exchange data. The networking stack handles protocol processing and passes packets toward the network interface.

Application Data
↓
TCP / UDP Socket
↓
Transport and Network Layers
↓
Link Layer
↓
Network Driver
↓
Network Hardware

On reception, the network driver passes received packets into the networking stack, where protocol processing eventually makes data available to the appropriate socket.

9. Important Network Driver Concepts

9.1 struct net_device

The struct net_device structure represents a network interface within the Linux networking subsystem.

It contains information and references required to manage the interface.

9.2 struct net_device_ops

This structure contains callbacks for operations performed on a network interface.

Examples include:

  • ndo_open – opens or starts the interface.
  • ndo_stop – stops the interface.
  • ndo_start_xmit – handles packet transmission requests.
  • ndo_set_rx_mode – configures receive filtering behavior.

9.3 sk_buff

The struct sk_buff structure, commonly called an skb, represents a network packet buffer in the Linux networking stack.

It stores packet data and metadata needed during network processing.

9.4 NAPI

NAPI (New API) is a mechanism used by Linux network drivers to manage packet reception efficiently.

It combines interrupt notification with polling-based packet processing to reduce interrupt overhead under heavy traffic.

10. Can a Network Device Be a Character Device?

A conventional Ethernet or Wi-Fi network interface is managed through the Linux networking subsystem, not registered as an ordinary character device.

However, Linux may expose additional device-specific control or diagnostic interfaces through device nodes, sysfs, debugfs, netlink or other mechanisms.

Therefore, a network-related device can have a character-device interface for a particular purpose, but that does not replace the normal network interface architecture.

Do not confuse a network interface such as eth0 with a device node such as /dev/ttyUSB0. They are managed through different kernel interfaces.

11. Practical: Inspect Network and Character Devices

Step 1: Display Network Interfaces

ip link show

Step 2: Display Network Addresses

ip addr show

Step 3: Display Network Statistics

ip -s link show

Step 4: List Character Device Nodes

find /dev -type c | head -20

Step 5: Inspect a Character Device

ls -l /dev/null
stat /dev/null

Step 6: Display Network Interface Details

ip -details link show

Step 7: Display Kernel Network Messages

journalctl -k -n 30

These commands inspect network interfaces, character device nodes and kernel messages. They do not require writing a kernel driver.

Ubuntu running inside VirtualBox commonly exposes virtual Ethernet interfaces. These are useful for studying Linux networking, even without a physical Ethernet adapter directly assigned to the virtual machine.

12. Choosing the Correct Driver Model

Requirement Appropriate Linux Interface
UART serial communication Serial subsystem and its device interface.
Ethernet communication Network-device subsystem.
Wi-Fi communication Wireless networking stack and network driver.
Simple custom byte-stream device Character-device subsystem, when appropriate.
SSD or HDD storage Block-device subsystem.
Keyboard and mouse input Input subsystem.
I2C sensor I2C subsystem and an appropriate device-class interface.

Linux provides specialized frameworks for many device categories. A driver developer should normally use the framework designed for the hardware rather than creating an unrelated custom character interface.

13. Summary

  • Character devices generally provide byte-stream-oriented access.
  • Network devices provide packet-oriented communication.
  • Character drivers use the character-device subsystem.
  • Network drivers integrate with the Linux networking subsystem.
  • struct cdev is important in character-device registration.
  • struct net_device represents a network interface.
  • struct file_operations defines character-device callbacks.
  • struct net_device_ops defines network-device operations.
  • sk_buff represents network packet buffers.
  • Applications commonly use sockets for network communication.
  • Specialized Linux subsystems should be used where appropriate.
