Lesson 6: Device Number Allocation
Level: Intermediate
Prerequisites: Major and minor device numbers, dev_t and character-device architecture.
Objective: Learn how Linux reserves device-number ranges for character drivers using static and dynamic allocation methods.

1. Introduction

Every registered Linux character device uses a device-number range consisting of major and minor numbers.

Before registering a character device with the kernel, a driver must obtain an appropriate device-number range.

Linux provides two commonly used methods:

  • Static allocation: The driver requests a specific, predetermined device-number range.
  • Dynamic allocation: The kernel selects an available device-number range for the driver.

Dynamic allocation is generally preferred for new drivers because it avoids conflicts caused by independently selecting fixed major numbers.

2. Why Is Device Number Allocation Required?

Linux may contain many character-device drivers. Each registered driver needs a device-number range that does not conflict with another registration.

Reasons for Allocation

  • To reserve a unique device-number range.
  • To associate device numbers with a driver.
  • To support multiple device instances using minor numbers.
  • To avoid conflicts between drivers.
  • To allow device nodes to identify the correct registered device.

3. Static Device Number Allocation

Static allocation means the driver requests a specific major number and starting minor number.

Linux provides the following function: 

register_chrdev_region()

Function Prototype

int register_chrdev_region(
    dev_t from,
    unsigned count,
    const char *name
);

Parameters

Parameter Description
from Starting device number, constructed using MKDEV().
count Number of consecutive device numbers to reserve.
name Name associated with the reserved range, used for identification in kernel bookkeeping.

Return Value

  • Returns 0 when the requested range is successfully reserved.
  • Returns a negative error code if registration fails.

Example

dev_t dev;

dev = MKDEV(240, 0);

ret = register_chrdev_region(
    dev,
    4,
    "mydevice"
);

This requests four consecutive device numbers beginning with major 240 and minor 0.

The requested range is:

Device Major Minor
Device 02400
Device 12401
Device 22402
Device 32403
Major number 240 is only an illustrative value. A driver should not assume that a particular major number is available. The kernel rejects overlapping reservations.

4. Dynamic Device Number Allocation

Dynamic allocation allows the kernel to choose an available device-number range.

Linux provides: 

alloc_chrdev_region()

Function Prototype

int alloc_chrdev_region(
    dev_t *dev,
    unsigned baseminor,
    unsigned count,
    const char *name
);

Parameters

Parameter Description
dev Pointer where the allocated starting device number is returned.
baseminor Starting minor number for the requested range.
count Number of consecutive device numbers to allocate.
name Name associated with the device-number range.

Return Value

  • Returns 0 on successful allocation.
  • Returns a negative error code on failure.

Example

dev_t dev;
int ret;

ret = alloc_chrdev_region(
    &dev,
    0,
    4,
    "mydevice"
);

if (ret < 0) {
    pr_err("Device number allocation failed\n");
    return ret;
}

pr_info("Major: %u\n", MAJOR(dev));
pr_info("Minor: %u\n", MINOR(dev));

If allocation succeeds, the kernel returns the starting device number through dev.

The driver can then use: 

MAJOR(dev)
MINOR(dev)

to obtain the allocated major and starting minor numbers.

5. Static vs Dynamic Allocation

Feature Static Allocation Dynamic Allocation
Function register_chrdev_region() alloc_chrdev_region()
Major number Specified by the driver. Selected by the kernel.
Starting minor Specified as part of from. Specified using baseminor.
Conflict handling Fails if the requested range is unavailable. Kernel searches for an available range.
Typical use Drivers requiring a predetermined number. New drivers and general module development.
For most new character-driver projects, dynamic allocation using alloc_chrdev_region() is the recommended starting point.

6. Releasing an Allocated Device Number Range

Device-number ranges must be released when the driver is unloaded or when the registration is no longer required.

Linux provides: 

unregister_chrdev_region()

Function Prototype

void unregister_chrdev_region(
    dev_t from,
    unsigned count
);

Parameters

  • from: Starting device number of the reserved range.
  • count: Number of device numbers to release.

Example

unregister_chrdev_region(dev, 4);

This releases the four-number range beginning at dev.

The starting device number and count supplied during release must match the range that was successfully reserved.

7. Complete Kernel Module: Dynamic Device Number Allocation

The following example demonstrates how to allocate and release a device-number range in a simple kernel module.

Source Code: device_number.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/kdev_t.h>
#include <linux/init.h>

#define DEVICE_COUNT 4

static dev_t dev;

static int __init device_number_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        DEVICE_COUNT,
        "mydevice"
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    pr_info("Device numbers allocated\n");
    pr_info("Major number: %u\n", MAJOR(dev));
    pr_info("Starting minor: %u\n", MINOR(dev));

    return 0;
}

static void __exit device_number_exit(void)
{
    unregister_chrdev_region(
        dev,
        DEVICE_COUNT
    );

    pr_info("Device numbers released\n");
}

module_init(device_number_init);
module_exit(device_number_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Dynamic Device Number Allocation Example");

Explanation

  1. dev_t dev stores the allocated device number.
  2. DEVICE_COUNT specifies four device numbers.
  3. alloc_chrdev_region() requests the range.
  4. The return value is checked before using the allocation.
  5. MAJOR() and MINOR() display the starting device number.
  6. The exit function releases the reserved range.
This module allocates device numbers only. It does not create a struct cdev, register file operations or create a /dev device node.

8. Makefile for the Example

Create a file named Makefile in the same directory as device_number.c.

obj-m += device_number.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The command lines under all: and clean: must begin with a tab character.

9. Compile and Test in Ubuntu

Use an Ubuntu VirtualBox environment with matching kernel headers installed.

Step 1: Install Build Dependencies

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Step 2: Compile the Module

make

Step 3: Inspect the Module

modinfo device_number.ko

Step 4: Load the Module

sudo insmod device_number.ko

Step 5: View Kernel Messages

sudo dmesg | tail -20

Example message: 

Device numbers allocated
Major number: 240
Starting minor: 0

The actual major number is selected by the kernel and may differ.

Step 6: Remove the Module

sudo rmmod device_number

Step 7: Verify Cleanup Messages

sudo dmesg | tail -20

Step 8: Clean Build Files

make clean
This is a software-only kernel module exercise. Ubuntu in VirtualBox is suitable for this allocation test; physical GPIO, I2C or SPI exercises require appropriate hardware access or emulation.

10. Common Errors During Allocation

Error or Problem Possible Cause
-EBUSY The requested static device-number range is already reserved.
Allocation failure No suitable range is available or another allocation error occurred.
Incorrect cleanup The driver releases a different starting number or count from the one allocated.
Invalid device-node mapping The node uses numbers that do not match the registered driver range.
Initialization failure The return value is not checked or acquired resources are not released on a later failure.

Best Practices

  • Check all allocation return values.
  • Prefer dynamic allocation for ordinary new drivers.
  • Store the allocated starting device number.
  • Use the same count during cleanup.
  • Release successfully allocated resources if later initialization steps fail.
  • Do not create device nodes with guessed major numbers.

12. Summary

  • Character drivers require a device-number range.
  • Static allocation uses register_chrdev_region().
  • Dynamic allocation uses alloc_chrdev_region().
  • Dynamic allocation allows the kernel to select an available major number.
  • The dev_t variable stores the starting device number.
  • MAJOR() and MINOR() extract its components.
  • unregister_chrdev_region() releases the reserved range.
  • Device-number allocation is separate from cdev registration and device-node creation.
  • Drivers must handle allocation failures and clean up resources correctly.
