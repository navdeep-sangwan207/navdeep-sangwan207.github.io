Lesson 8: alloc_chrdev_region() Function
Level: Intermediate
Prerequisites: Major and minor numbers, dev_t, MKDEV(), MAJOR() and MINOR().
Objective: Learn how to dynamically allocate a device-number range using alloc_chrdev_region() and release it correctly.

1. Introduction

A Linux character device driver needs a device-number range before it can register its character-device interface.

A device-number range contains a major number and one or more minor numbers.

The kernel provides alloc_chrdev_region() to dynamically allocate an available range. 

alloc_chrdev_region()

The kernel selects an available major number and reserves the requested number of consecutive device numbers.

Dynamic allocation is generally preferred for new character-device drivers because the driver does not need to assume that a particular major number is free.

2. Function Prototype

The function is declared in the Linux kernel headers, commonly through <linux/fs.h>. 

int alloc_chrdev_region(
    dev_t *dev,
    unsigned baseminor,
    unsigned count,
    const char *name
);

It returns an integer status code and stores the allocated starting device number through the dev pointer.

3. Understanding the Parameters

Parameter 1: dev_t *dev

This is a pointer to a dev_t variable. The kernel stores the allocated starting device number in this variable. 

dev_t dev;

alloc_chrdev_region(&dev, 0, 4, "mydevice");

The address operator & passes the address of the variable so that the function can write the allocated value.

Parameter 2: unsigned baseminor

Specifies the starting minor number for the allocated range. 

alloc_chrdev_region(&dev, 0, 4, "mydevice");

Here, the requested range begins at minor number 0.

Parameter 3: unsigned count

Specifies how many consecutive device numbers should be reserved. 

alloc_chrdev_region(&dev, 0, 4, "mydevice");

Here, four device numbers are requested.

Parameter 4: const char *name

Provides a name associated with the allocated device-number range. 

"mydevice"

This name is used for identification in the kernel's device-number bookkeeping.

Parameter Example Purpose
dev &dev Receives the allocated starting device number.
baseminor 0 Starting minor number.
count 4 Number of consecutive device numbers.
name "mydevice" Range identification name.

4. How Dynamic Allocation Works

Driver Calls alloc_chrdev_region()
↓
Kernel Searches for an Available Major Number
↓
Kernel Reserves the Requested Range
↓
Allocated Starting dev_t Is Returned
↓
Driver Extracts Major and Minor Numbers

Suppose a driver requests four device numbers with a starting minor number of 0. If the kernel allocates major number 240, the range will be:

Device Instance Major Minor
Device 02400
Device 12401
Device 22402
Device 32403

The major number 240 is only an illustrative example. The actual value is selected by the kernel.

5. Return Value and Error Handling

The function returns an integer status.

Return Value Meaning
0 Device-number allocation succeeded.
Negative error code Allocation failed.

Correct Error Handling

int ret;

ret = alloc_chrdev_region(
    &dev,
    0,
    4,
    "mydevice"
);

if (ret < 0) {
    pr_err("Device number allocation failed\n");
    return ret;
}

The driver must check the return value before using the allocated device number.

Never assume that allocation always succeeds. Initialization should stop if the function returns a negative error code.

6. Extracting the Allocated Major and Minor Numbers

After successful allocation, the starting device number is stored in the supplied dev_t variable.

Use the following macros: 

MAJOR(dev)
MINOR(dev)

Example

pr_info("Major number: %u\n", MAJOR(dev));
pr_info("Starting minor: %u\n", MINOR(dev));

If the kernel allocated major 240 and starting minor 0, the output would be: 

Major number: 240
Starting minor: 0

7. Releasing the Allocated Device Numbers

A driver must release its reserved device-number range when it is no longer needed.

Use: 

unregister_chrdev_region()

Function Prototype

void unregister_chrdev_region(
    dev_t from,
    unsigned count
);

Example

unregister_chrdev_region(dev, 4);

This releases the four device numbers beginning at the starting value stored in dev.

Use the same starting device number and count that were successfully allocated. Releasing the range does not automatically remove a registered cdev or destroy a device node; those resources need their own cleanup.

8. Complete Kernel Module Example

This example demonstrates dynamic device-number allocation and release.

File: alloc_device.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/kdev_t.h>
#include <linux/init.h>

#define DEVICE_COUNT 4

static dev_t dev;

static int __init alloc_device_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        DEVICE_COUNT,
        "mydevice"
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    pr_info("Device number allocation successful\n");
    pr_info("Major number: %u\n", MAJOR(dev));
    pr_info("Starting minor: %u\n", MINOR(dev));

    return 0;
}

static void __exit alloc_device_exit(void)
{
    unregister_chrdev_region(
        dev,
        DEVICE_COUNT
    );

    pr_info("Device number range released\n");
}

module_init(alloc_device_init);
module_exit(alloc_device_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("alloc_chrdev_region Example");

Program Explanation

  1. DEVICE_COUNT defines the number of device numbers to allocate.
  2. dev_t dev stores the starting device number.
  3. alloc_chrdev_region() requests an available range.
  4. The return value is checked for errors.
  5. MAJOR() and MINOR() display the allocated values.
  6. The exit function releases the reserved range.
This example demonstrates device-number allocation only. It does not yet implement file operations or register a struct cdev.

9. Makefile

Create a file named Makefile in the same directory. 

obj-m += alloc_device.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The commands below all: and clean: must begin with a tab character.

11. Multiple Device Instances

One driver may manage multiple device instances. The count parameter reserves consecutive minor numbers for these instances.

Example

alloc_chrdev_region(
    &dev,
    0,
    5,
    "sensor_device"
);

If the kernel assigns major number 240, the reserved range is:

Instance Major Minor
Sensor 02400
Sensor 12401
Sensor 22402
Sensor 32403
Sensor 42404

The driver can later associate each minor number with a separate device instance or data structure.

12. Common Mistakes and Best Practices

Common Mistake Correct Practice
Passing dev instead of &dev. Pass the address of the dev_t variable.
Not checking the return value. Check for a negative error code before continuing.
Assuming the kernel always assigns the same major. Read the assigned number using MAJOR(dev).
Using a different count during cleanup. Release the exact range that was reserved.
Assuming allocation registers a character device. Use cdev registration separately.
Forgetting cleanup after a later initialization failure. Release previously acquired resources on every failure path.

13. Summary

  • alloc_chrdev_region() dynamically allocates a device-number range.
  • The kernel chooses an available major number.
  • The dev pointer receives the starting device number.
  • baseminor specifies the starting minor number.
  • count specifies the number of consecutive device numbers.
  • name identifies the reserved range in kernel bookkeeping.
  • MAJOR() and MINOR() extract the allocated values.
  • unregister_chrdev_region() releases the reserved range.
  • Device-number allocation is separate from cdev registration and device-node creation.
