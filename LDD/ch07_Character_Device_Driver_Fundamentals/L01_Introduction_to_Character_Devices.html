Lesson 1: Introduction to Character Devices
Level: Intermediate
Prerequisites: Linux kernel architecture, kernel modules, device driver basics and C programming.
Objective: Understand character devices, their characteristics, working principles and role in Linux device driver development.

1. Introduction

Linux supports different categories of devices, each requiring an appropriate interface for communication between user applications and hardware or kernel-managed functionality.

A character device is a device interface that generally provides data access as a stream of bytes or characters.

Character devices are commonly used for devices where data is transferred sequentially or through device-specific operations.

Examples include serial ports, terminal devices, many sensor interfaces and simple communication devices.

In Linux, character device drivers are commonly implemented using kernel structures and interfaces such as struct cdev and struct file_operations.

2. What Is a Character Device?

A character device is a device represented through the Linux character-device subsystem.

Its interface typically allows applications to exchange data through operations such as:

  • Open a device file.
  • Read data from the device.
  • Write data to the device.
  • Close the device file.
  • Perform device-specific control operations.

Example

Consider a serial communication device. An application may open its device file, read incoming bytes and write outgoing bytes. 

/dev/ttyS0

The path above is a common example of a serial device file. Its availability depends on the system hardware and configuration.

3. Why Are Character Devices Required?

Applications should not need to know the hardware-specific details of every device. Linux device drivers provide a standard interface between user applications and device-specific implementation.

Without a Device Driver Interface

  • Applications would need hardware-specific access logic.
  • Device handling would become difficult to standardize.
  • Code reuse would be reduced.
  • Hardware access would be harder to manage securely.

With a Character Device Driver

  • Applications can use standard file operations.
  • The driver manages device-specific operations.
  • The kernel controls access to device interfaces.
  • Applications can interact with devices through device files.

4. Examples of Character Devices

These are examples of device nodes commonly associated with character-device interfaces. The exact device files available depend on the running Linux system.

5. Character Device Communication Architecture

A user-space application communicates with a character device through its device file. The Linux Virtual Filesystem and character-device subsystem route operations to the appropriate driver.

User-Space Application
↓ open(), read(), write(), ioctl()
Device File in /dev
↓
Virtual Filesystem (VFS)
↓
Character Device Subsystem
↓
Character Device Driver
↓
Hardware or Kernel-Managed Device

Working Explanation

  1. The application opens a device file.
  2. The VFS processes the file operation.
  3. The character-device subsystem identifies the registered device.
  4. The kernel dispatches the operation to the driver's callback.
  5. The driver performs the requested operation.
  6. The result is returned to the application.

6. Important Components of a Character Device Driver

A. Device Number

Every registered character device is associated with a device number represented by the dev_t type.

A device number contains two components:

  • Major number.
  • Minor number.

These numbers help the kernel identify the registered character-device implementation and a particular device instance.

B. struct cdev

The struct cdev structure represents a character device within the kernel's character-device subsystem.

It connects a device number range with the driver's file operations.

C. struct file_operations

This structure contains function pointers for operations supported by the driver.

Common callbacks include:

  • open
  • read
  • write
  • release
  • unlocked_ioctl
  • poll

D. Device File

A device node in the /dev directory provides a user-space entry point for accessing the registered device.

7. Character Device Read and Write Operations

Character devices commonly support data exchange through read and write operations.

Read Operation

The read operation transfers data from the device or driver to a user-space application. 

read(fd, buffer, count);

Parameters:

  • fd: File descriptor.
  • buffer: User-space destination buffer.
  • count: Maximum number of bytes requested.

Write Operation

The write operation transfers data from a user-space application to the device or driver. 

write(fd, buffer, count);

Parameters:

  • fd: File descriptor.
  • buffer: User-space source buffer.
  • count: Number of bytes requested for writing.
The user-space read() and write() system calls are not the same functions as the driver's read and write callbacks. The VFS routes operations to the appropriate driver callbacks.

8. Character Devices and Device Files

Linux represents many devices using special files under the /dev directory. These are called device nodes.

View Device Files

ls -l /dev

A character device node is commonly identified by the letter c at the beginning of its long-format listing.

Example

crw-rw---- 1 root dialout 4, 64 ... /dev/ttyS0

In this example:

  • c identifies a character device.
  • 4 is the major number.
  • 64 is the minor number.
  • The permissions determine which users can access the node.
The example is illustrative. Actual device numbers and permissions vary between systems.

9. Character Device Driver Development in Linux

A basic character device driver usually follows these development stages:

  1. Define the device requirements.
  2. Allocate or reserve device numbers.
  3. Initialize a struct cdev object.
  4. Associate file operations with the character device.
  5. Add the character device to the kernel.
  6. Create a device node or register a device interface.
  7. Implement the required callbacks.
  8. Test access from user space.
  9. Remove the device and release resources during cleanup.

Represents stored file data. Represents an interface to a character device.

11. Advantages of Character Device Drivers

  • Provide a standard interface for device access.
  • Allow applications to use familiar file operations.
  • Separate hardware-specific logic from application code.
  • Support access control through device permissions.
  • Allow multiple device instances to be represented.
  • Integrate with the Linux VFS and kernel device model.

12. Limitations and Design Considerations

  • Driver code executes with kernel privileges.
  • Incorrect memory handling can affect system stability.
  • Concurrent access requires suitable synchronization.
  • Read and write operations must handle partial transfers correctly.
  • User-space pointers must be accessed through appropriate kernel APIs.
  • Device removal must account for active users and references.
  • Hardware-specific timing and communication requirements must be considered.

13. Practical: Explore Character Devices in Ubuntu

In this exercise, inspect existing character-device nodes on your Ubuntu system.

Step 1: Open Terminal

Start the Ubuntu terminal in your VirtualBox environment.

Step 2: List Device Files

ls -l /dev

Step 3: Display Character Device Entries

find /dev -type c | head -20

Step 4: Inspect a Common Character Device

ls -l /dev/null

Step 5: Display Device Type

stat /dev/null

Step 6: Inspect Device Numbers

stat -c 'Type: %F, Major: %t, Minor: %T' /dev/null

Step 7: Examine Device Information

ls -l /dev/tty

Expected Result

You should be able to identify character device nodes and inspect their type, permissions, major number and minor number.

This practical examines existing device nodes. It does not create or load a new character device driver.

14. Summary

  • A character device provides a byte-oriented device interface.
  • Character devices are represented by device nodes.
  • Device nodes commonly exist under /dev.
  • Each registered character device uses a device number.
  • Device numbers contain major and minor numbers.
  • struct cdev represents a character device in the kernel.
  • struct file_operations defines supported driver callbacks.
  • Applications commonly access character devices using open, read, write and close.
  • The VFS and character-device subsystem route operations to drivers.
  • Correct resource management and synchronization are important.
