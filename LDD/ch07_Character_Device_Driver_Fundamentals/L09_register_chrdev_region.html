Lesson 9: register_chrdev_region() Function
Level: Intermediate
Prerequisites: dev_t, major and minor numbers, MKDEV(), MAJOR(), MINOR() and dynamic device-number allocation.
Objective: Understand how to reserve a predetermined device-number range using register_chrdev_region().

1. Introduction

Linux character-device drivers need a device-number range before registering their character-device interface.

Linux provides two commonly used methods for reserving device numbers:

  • alloc_chrdev_region() – dynamically selects an available major number.
  • register_chrdev_region() – requests a specific, predetermined device-number range.

In this lesson, we study register_chrdev_region().

This function is useful when a driver has a known major number that it is expected to use.

Static allocation does not mean that the driver can force the kernel to accept an already occupied number. The requested range must be available.

2. Function Prototype

The function is declared in the Linux kernel headers, commonly through <linux/fs.h>. 

int register_chrdev_region(
    dev_t from,
    unsigned count,
    const char *name
);

The function reserves a specific range beginning at the supplied device number.

3. Understanding the Parameters

Parameter 1: dev_t from

Specifies the starting device number of the requested range.

The MKDEV() macro is commonly used to construct this value. 

dev_t dev;

dev = MKDEV(240, 0);

This represents major number 240 and minor number 0.

Parameter 2: unsigned count

Specifies the number of consecutive device numbers to reserve. 

register_chrdev_region(dev, 4, "mydevice");

This requests four consecutive device numbers beginning at dev.

Parameter 3: const char *name

Specifies the name associated with the reserved device-number range. 

"mydevice"
Parameter Example Purpose
from MKDEV(240, 0) Starting major and minor number.
count 4 Number of consecutive device numbers.
name "mydevice" Range identification name.

4. Working of register_chrdev_region()

The driver supplies the desired starting device number and range size. The kernel checks whether the complete requested range is available.

Driver Selects Major and Starting Minor
↓
Driver Calls register_chrdev_region()
↓
Kernel Checks the Requested Range
↓
Is the Entire Range Available?
↓

Yes

Kernel reserves the range and returns 0.

No

Kernel returns a negative error code.

5. Example of Static Device Number Allocation

Suppose a driver requests four device numbers beginning with major 240 and minor 0.

Code

dev_t dev;

dev = MKDEV(240, 0);

ret = register_chrdev_region(
    dev,
    4,
    "mydevice"
);

If the complete range is available, the kernel reserves:

Device Instance Major Minor
Device 02400
Device 12401
Device 22402
Device 32403
Major 240 is an illustrative value only. A driver must not assume that this number is free on every Linux system.

6. Return Value and Error Handling

register_chrdev_region() returns an integer status code.

Return Value Meaning
0 The requested range was successfully reserved.
Negative error code The requested range could not be reserved.

Example

ret = register_chrdev_region(
    dev,
    4,
    "mydevice"
);

if (ret < 0) {
    pr_err("Device number registration failed\n");
    return ret;
}

A common error is -EBUSY, which indicates that the requested device-number range is already reserved.

Always check the return value. Do not continue with character-device registration if device-number reservation has failed.

7. Releasing the Reserved Range

When the driver is removed, it must release the device-number range.

Use: 

unregister_chrdev_region()

Function Prototype

void unregister_chrdev_region(
    dev_t from,
    unsigned count
);

Example

unregister_chrdev_region(dev, 4);

The starting device number and count must match the reserved range.

Releasing device numbers is only one part of driver cleanup. If a driver has registered a cdev, created a class or created device objects, those resources must also be removed in the correct order.

8. Complete Kernel Module Example

The following module demonstrates static device-number allocation and cleanup.

File: static_device.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/kdev_t.h>
#include <linux/init.h>

#define DEVICE_MAJOR 240
#define DEVICE_MINOR 0
#define DEVICE_COUNT 4

static dev_t dev;

static int __init static_device_init(void)
{
    int ret;

    dev = MKDEV(
        DEVICE_MAJOR,
        DEVICE_MINOR
    );

    ret = register_chrdev_region(
        dev,
        DEVICE_COUNT,
        "mydevice"
    );

    if (ret < 0) {
        pr_err("Device number reservation failed\n");
        return ret;
    }

    pr_info("Device number range reserved\n");
    pr_info("Major number: %u\n", MAJOR(dev));
    pr_info("Starting minor: %u\n", MINOR(dev));

    return 0;
}

static void __exit static_device_exit(void)
{
    unregister_chrdev_region(
        dev,
        DEVICE_COUNT
    );

    pr_info("Device number range released\n");
}

module_init(static_device_init);
module_exit(static_device_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Static Device Number Allocation Example");

Program Explanation

  1. DEVICE_MAJOR defines the requested major number.
  2. DEVICE_MINOR defines the starting minor number.
  3. DEVICE_COUNT specifies four consecutive numbers.
  4. MKDEV() constructs the starting device number.
  5. register_chrdev_region() requests the fixed range.
  6. The return value is checked before continuing.
  7. The exit function releases the reserved range.
This example may fail if major 240 and the requested minor range are already reserved. That failure is expected behavior for a fixed-number request.

9. Makefile

Create a file named Makefile in the same directory. 

obj-m += static_device.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The commands under all: and clean: must begin with a tab character.

10. Compile and Test in Ubuntu

Step 1: Install Dependencies

sudo apt update
sudo apt install build-essential linux-headers-$(uname -r)

Step 2: Compile the Module

make

Step 3: Inspect Module Information

modinfo static_device.ko

Step 4: Load the Module

sudo insmod static_device.ko

If the requested range is free, the module loads successfully.

If the range is already reserved, module initialization fails and the kernel reports an error.

Step 5: View Kernel Messages

sudo dmesg | tail -20

Example success output:

Device number range reserved
Major number: 240
Starting minor: 0

Step 6: Remove the Module

sudo rmmod static_device

Step 7: Verify Cleanup

sudo dmesg | tail -20

Step 8: Clean Build Files

make clean
This is a software-only exercise and can be tested in Ubuntu VirtualBox. It does not require a physical character device.

11. Static vs Dynamic Allocation

Feature Static Allocation Dynamic Allocation
Function register_chrdev_region() alloc_chrdev_region()
Major number Specified by the driver. Selected by the kernel.
Starting minor Encoded in the starting dev_t. Supplied through baseminor.
Conflict behavior Fails if the requested range is unavailable. Kernel searches for an available range.
Typical use Known, predetermined device-number assignments. General-purpose new drivers.

Which Method Should Be Used?

For most new character-device drivers, dynamic allocation is the preferred approach.

Static allocation is appropriate when a predetermined major number is required and its availability is managed.

12. Common Mistakes and Best Practices

Mistake Correct Practice
Assuming a fixed major number is always free. Check the return value and handle conflicts.
Using an incorrect starting minor number. Construct the intended starting number using MKDEV().
Not checking the function's return value. Stop initialization if reservation fails.
Releasing a different range. Use the original starting device number and count.
Assuming reservation creates a device node. Handle device-node creation separately.
Forgetting resource cleanup after a later initialization failure. Release the range if a subsequent initialization step fails.

13. Summary

  • register_chrdev_region() reserves a predetermined device-number range.
  • The driver specifies the starting device number using dev_t.
  • MKDEV() constructs the starting number from major and minor values.
  • The count parameter specifies the number of consecutive device numbers.
  • The function returns 0 on success and a negative error code on failure.
  • -EBUSY commonly indicates an overlapping reservation.
  • unregister_chrdev_region() releases the reserved range.
  • Static allocation should be used only when a fixed number is appropriate and available.
