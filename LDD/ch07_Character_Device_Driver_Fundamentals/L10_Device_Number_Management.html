Lesson 10: Device Number Management
Level: Intermediate
Prerequisites: Major and minor numbers, dev_t, MKDEV(), alloc_chrdev_region() and register_chrdev_region().
Objective: Understand how Linux drivers allocate, use, inspect and release device-number ranges throughout the character-device lifecycle.

1. Introduction

Device-number management is an important part of Linux character-device driver development.

Every registered character-device number range is identified by a major number and a minor number.

The driver must reserve an appropriate range before registering its character device with the kernel.

Device-number management includes:

  • Choosing a device-number allocation method.
  • Reserving a major/minor number range.
  • Extracting and using major and minor values.
  • Managing multiple device instances.
  • Registering the character-device interface.
  • Releasing the range during cleanup.

2. Device Number Structure

Linux represents a device number using the kernel data type dev_t.

It contains the major and minor number information in an encoded form.

Device Number (dev_t)
↓

Major Number

Identifies the registered device-number range associated with a driver or device interface.

Minor Number

Distinguishes individual devices or instances within the major-number range.

Important Macros

Macro Purpose
MKDEV(major, minor) Constructs an encoded device number.
MAJOR(dev) Extracts the major number.
MINOR(dev) Extracts the minor number.

Example

dev_t dev;

dev = MKDEV(240, 0);

pr_info("Major: %u\n", MAJOR(dev));
pr_info("Minor: %u\n", MINOR(dev));

Illustrative output:

Major: 240
Minor: 0

This example constructs a device number. It does not reserve the number with the kernel.

3. Static and Dynamic Allocation

Linux provides two principal functions for reserving character-device number ranges.

Static Allocation

register_chrdev_region()

The driver requests a specific major and starting minor number.

Dynamic Allocation

alloc_chrdev_region()

The kernel selects an available major number for the requested range.

Static Allocation Example

dev_t dev;

dev = MKDEV(240, 0);

ret = register_chrdev_region(
    dev,
    4,
    "mydevice"
);

Dynamic Allocation Example

dev_t dev;

ret = alloc_chrdev_region(
    &dev,
    0,
    4,
    "mydevice"
);
Feature Static Dynamic
Function register_chrdev_region() alloc_chrdev_region()
Major number Specified by driver Selected by kernel
Availability check Requested range must be free Kernel finds an available range
Typical use Known fixed assignments Most new drivers
Dynamic allocation is generally the preferred method for new character-device drivers.

4. Managing Multiple Minor Numbers

A single driver may control several device instances.

For example, a driver may manage four independent sensor interfaces. 

alloc_chrdev_region(
    &dev,
    0,
    4,
    "sensor_driver"
);

Suppose the kernel allocates major number 240. The resulting range is:

Device Major Minor
Sensor 02400
Sensor 12401
Sensor 22402
Sensor 32403

The driver can identify the device instance using the minor number.

Extracting an Instance Number

unsigned int minor;

minor = MINOR(dev);

In actual file operations, a driver commonly obtains the device number from the inode associated with the opened device file: 

unsigned int minor;

minor = iminor(inode);

The minor number can then be used to select the corresponding device data structure.

5. Device Number Allocation and cdev Registration

Reserving a device-number range does not automatically register a functional character device.

The driver must separately initialize and register a struct cdev.

Important Functions

Function Purpose
alloc_chrdev_region() Dynamically reserves device numbers.
register_chrdev_region() Reserves a specified device-number range.
cdev_init() Initializes a cdev and associates file operations.
cdev_add() Adds the character device to the kernel.
cdev_del() Removes the cdev from the kernel.
unregister_chrdev_region() Releases the reserved device-number range.
A device number, a registered cdev and a device node are three different things. Do not treat their creation and cleanup as the same operation.

6. Inspecting Device Numbers in Linux

Linux provides several ways to inspect device numbers from user space.

Command 1: List Device Files

ls -l /dev

Command 2: Inspect a Character Device

ls -l /dev/null

Example output:

crw-rw-rw- 1 root root 1, 3 ... /dev/null

The leading c identifies a character device. The values 1, 3 represent its major and minor numbers.

Command 3: Inspect Device Type and Numbers

stat /dev/null

Command 4: Display Major and Minor in Hexadecimal

stat -c 'Type: %F Major: %t Minor: %T' /dev/null
The %t and %T format specifiers display hexadecimal major and minor values. The familiar ls -l output displays decimal values.

Command 5: Inspect Registered Character Devices

cat /proc/devices

This file lists registered character and block device major numbers and their associated names.

Command 6: Inspect sysfs Device Entries

ls -l /sys/dev/char/

The sysfs directory contains entries for registered device numbers that have corresponding kernel device objects.

For example, inspect the device corresponding to major 1, minor 3: 

cat /sys/dev/char/1:3/uevent

7. Device Node and Device Number Relationship

A device node is a special file that allows user-space applications to access a device interface.

Its metadata contains the device type and associated major/minor numbers.

Example: Creating a Device Node

sudo mknod /dev/mydevice c 240 0

The command creates a character-device node with major 240 and minor 0.

Inspect it using: 

ls -l /dev/mydevice
Only use the actual major and minor numbers allocated and registered by your driver. The illustrative command above does not reserve a device number or register a cdev.

In production drivers, device-node creation is commonly integrated with the device model and udev through interfaces such as class_create() and device_create().

8. Complete Device Number Management Example

This example demonstrates dynamic allocation, cdev registration and proper cleanup.

It registers a basic character device with a single minor number. Device-node creation is not included.

File: managed_device.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/kdev_t.h>
#include <linux/init.h>

#define DEVICE_NAME "managed_device"
#define DEVICE_COUNT 1

static dev_t dev;
static struct cdev my_cdev;

static int device_open(struct inode *inode,
                       struct file *file)
{
    pr_info("Device opened\n");
    return 0;
}

static int device_release(struct inode *inode,
                          struct file *file)
{
    pr_info("Device closed\n");
    return 0;
}

static const struct file_operations fops = {
    .owner = THIS_MODULE,
    .open = device_open,
    .release = device_release,
};

static int __init managed_device_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev,
        0,
        DEVICE_COUNT,
        DEVICE_NAME
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    pr_info("Allocated major: %u\n", MAJOR(dev));
    pr_info("Allocated minor: %u\n", MINOR(dev));

    cdev_init(&my_cdev, &fops);
    my_cdev.owner = THIS_MODULE;

    ret = cdev_add(&my_cdev, dev, DEVICE_COUNT);

    if (ret < 0) {
        pr_err("cdev registration failed\n");
        unregister_chrdev_region(dev, DEVICE_COUNT);
        return ret;
    }

    pr_info("Character device registered\n");

    return 0;
}

static void __exit managed_device_exit(void)
{
    cdev_del(&my_cdev);

    unregister_chrdev_region(
        dev,
        DEVICE_COUNT
    );

    pr_info("Character device unregistered\n");
}

module_init(managed_device_init);
module_exit(managed_device_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Device Number Management Example");

Program Explanation

  1. dev_t dev stores the allocated device number.
  2. alloc_chrdev_region() reserves one device number.
  3. MAJOR() and MINOR() display its components.
  4. cdev_init() initializes the character-device object.
  5. cdev_add() registers the cdev with the kernel.
  6. If cdev registration fails, the allocated number is released.
  7. During module removal, cdev_del() removes the cdev.
  8. unregister_chrdev_region() releases the reserved number.
This example registers a cdev but does not create a /dev node. To open it from user space, a suitable device node must also be created using the actual allocated major and minor numbers, or through the Linux device model.

9. Makefile

Create a file named Makefile in the same directory. 

obj-m += managed_device.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean

The commands below all: and clean: must begin with a tab character.

11. Common Errors in Device Number Management

Error or Mistake Explanation / Solution
Requested major number is busy Choose another available range or use dynamic allocation.
Allocation return value ignored Check the return value before using dev.
Incorrect count during cleanup Release exactly the range that was reserved.
cdev registration fails Release the previously allocated device-number range.
Device node has wrong major/minor Use the values associated with the registered driver.
Device node exists but driver is unavailable Check whether the corresponding cdev is registered and the driver is loaded.
Device numbers released too early Remove the cdev and other dependent interfaces before releasing the range.

12. Best Practices

  • Prefer dynamic allocation for new drivers unless a fixed major number is required.
  • Always check allocation and registration return values.
  • Use dev_t instead of manually manipulating encoded device numbers.
  • Use MKDEV(), MAJOR() and MINOR() for device-number operations.
  • Keep the allocated starting number and count available for cleanup.
  • Remove registered cdev objects before releasing their device-number range.
  • Use unique and meaningful device names.
  • Do not assume that reserving device numbers creates a device node.
  • Handle partial initialization failures carefully.
  • Test kernel modules in a virtual machine before deploying them on production systems.

13. Summary

  • dev_t represents an encoded device number.
  • The major number identifies the registered device-number range.
  • The minor number distinguishes device instances.
  • alloc_chrdev_region() dynamically allocates a range.
  • register_chrdev_region() reserves a predetermined range.
  • cdev_init() initializes a character-device object.
  • cdev_add() registers the character device.
  • cdev_del() removes the registered cdev.
  • unregister_chrdev_region() releases the device-number range.
  • Device-number allocation, cdev registration and device-node creation are separate operations.
