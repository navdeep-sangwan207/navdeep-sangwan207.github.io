2. Introduction to User Space and Kernel Space

Linux uses privilege separation to protect the operating system and applications. User applications normally execute with restricted privileges, while the kernel executes with elevated privileges.

User Space

  • Contains application programs and their process memory.
  • Applications cannot directly access arbitrary kernel memory.
  • Applications request kernel services using system calls.
  • Examples include terminal programs, text editors and device-control applications.

Kernel Space

  • Contains the Linux kernel and loaded kernel modules.
  • Manages memory, processes, hardware and device drivers.
  • Provides controlled interfaces through system calls and kernel subsystems.
  • Device drivers execute with kernel privileges.

Linux Memory and Execution Domains

↓ System Calls

↓
Kernel Subsystems and Device Drivers
↓

The user/kernel boundary is important because an application and a driver do not simply share unrestricted access to each other's memory.

5. Data Transfer Using read()

The user-space read() system call requests data from a file or device.

Data Direction

Kernel Buffer
copy_to_user()
User Application Buffer

Kernel Space → User Space

User-Space Example

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main(void)
{
    int fd;
    char buffer[100];

    fd = open("/dev/mychardev", O_RDONLY);

    if (fd < 0) {
        perror("open");
        return 1;
    }

    ssize_t bytes = read(fd, buffer, sizeof(buffer) - 1);

    if (bytes < 0) {
        perror("read");
        close(fd);
        return 1;
    }

    buffer[bytes] = '\0';

    printf("Received: %s\n", buffer);

    close(fd);
    return 0;
}

Kernel-Space read() Callback

static ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position)
{
    size_t bytes;
    unsigned long not_copied;

    if (*position >= data_size)
        return 0;

    bytes = min(count, data_size - (size_t)*position);

    not_copied = copy_to_user(
        buffer,
        kernel_buffer + *position,
        bytes
    );

    bytes -= not_copied;

    if (bytes == 0)
        return -EFAULT;

    *position += bytes;

    return bytes;
}

The callback transfers data from the kernel buffer into the application-provided user buffer.

6. Data Transfer Using write()

The user-space write() system call sends data to a file or device.

Data Direction

User Application Buffer
copy_from_user()
Kernel Buffer

User Space → Kernel Space

User-Space Example

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main(void)
{
    int fd;
    const char message[] = "Hello Linux Driver";

    fd = open("/dev/mychardev", O_WRONLY);

    if (fd < 0) {
        perror("open");
        return 1;
    }

    ssize_t bytes = write(
        fd,
        message,
        strlen(message)
    );

    if (bytes < 0) {
        perror("write");
        close(fd);
        return 1;
    }

    printf("Bytes sent: %zd\n", bytes);

    close(fd);
    return 0;
}

Kernel-Space write() Callback

static ssize_t my_write(
    struct file *file,
    const char __user *buffer,
    size_t count,
    loff_t *position)
{
    size_t bytes;
    unsigned long not_copied;

    if (*position >= BUFFER_SIZE)
        return -ENOSPC;

    bytes = min(count, BUFFER_SIZE - (size_t)*position);

    not_copied = copy_from_user(
        kernel_buffer + *position,
        buffer,
        bytes
    );

    bytes -= not_copied;

    if (bytes == 0)
        return -EFAULT;

    *position += bytes;

    return bytes;
}

The driver receives application data and stores it in kernel memory before processing it.

7. copy_to_user() Function

copy_to_user() transfers data from kernel space to user space.

Prototype

unsigned long copy_to_user(
    void __user *to,
    const void *from,
    unsigned long n
);
ParameterMeaning
toUser-space destination.
fromKernel-space source.
nRequested number of bytes.

Example

char kernel_message[] = "Hello from Kernel";
char __user *user_buffer;

if (copy_to_user(
        user_buffer,
        kernel_message,
        sizeof(kernel_message))) {
    return -EFAULT;
}

Return value: Number of bytes not copied. Zero indicates complete success.

Both functions use the same return-value convention: they return the number of bytes not copied, not a negative errno. Drivers commonly return -EFAULT if no bytes were successfully transferred.

10. Data Transfer Using IOCTL

IOCTL provides a mechanism for sending device-specific commands and exchanging structured data between applications and drivers.

Example: Application Sends Configuration

User Configuration Structure
ioctl() / copy_from_user()
Kernel Configuration Structure

Example: Driver Returns Device Status

Kernel Status Structure
copy_to_user() / ioctl()
User Application Structure

Shared Structure

struct device_info {
    int status;
    int temperature;
};

Kernel Callback Example

static long my_ioctl(
    struct file *file,
    unsigned int cmd,
    unsigned long arg)
{
    struct device_info info;

    switch (cmd) {

    case MY_IOCTL_GET_INFO:

        info.status = 1;
        info.temperature = 35;

        if (copy_to_user(
                (struct device_info __user *)arg,
                &info,
                sizeof(info))) {
            return -EFAULT;
        }

        break;

    case MY_IOCTL_SET_INFO:

        if (copy_from_user(
                &info,
                (struct device_info __user *)arg,
                sizeof(info))) {
            return -EFAULT;
        }

        /* Validate and process received values */

        break;

    default:
        return -ENOTTY;
    }

    return 0;
}

This example illustrates the two directions of data exchange. In an actual driver, the IOCTL command definitions, structure layout, compatibility requirements and validation must be implemented consistently.

11. What Is __user?

The __user annotation marks a pointer that refers to user-space memory.

Example

char __user *buffer;

This annotation:

  • Documents the expected address space of the pointer.
  • Helps static analysis tools such as Sparse identify incorrect pointer usage.
  • Makes kernel APIs and callback declarations easier to understand.
__user is not a runtime memory-protection mechanism by itself. It is an annotation used by kernel code and analysis tools. Use the appropriate user-access functions to transfer data.

12. Why Direct Pointer Access Is Unsafe

A driver must not assume that a pointer supplied by an application is valid or accessible.

Incorrect Example

char value;

value = *user_pointer;

Directly dereferencing an arbitrary user-space pointer from kernel code is unsafe.

Correct Example

char value;

if (copy_from_user(
        &value,
        user_pointer,
        sizeof(value))) {
    return -EFAULT;
}

The user-access API handles the required access checks and fault handling for the transfer.

13. Understanding Partial Data Transfer

Both copy_to_user() and copy_from_user() can transfer fewer bytes than requested.

Example

Requested bytes: 100
Successfully copied: 75
Not copied: 25

Calculation:

copied = requested - not_copied;

A driver must:

  • Check the returned uncopied-byte count.
  • Calculate the number of successfully transferred bytes.
  • Update file positions using actual progress.
  • Update buffer metadata consistently.
  • Return a positive byte count if partial progress is reported, or an appropriate error if no bytes were transferred.
Do not report the entire requested byte count when only part of the data was transferred. Incorrect return values can cause applications and drivers to disagree about the data that was actually exchanged.

14. Sleepable Context and Synchronization

User-access functions may fault while accessing user memory and may sleep. Therefore, they must be used in an appropriate execution context.

Important Rules

  • Do not call copy_to_user() or copy_from_user() from hard interrupt context.
  • Do not call them while holding a spinlock.
  • They are normally used from process context in read(), write() and IOCTL callbacks.
  • A mutex can protect shared driver data when used in a sleepable context.
  • Keep buffer sizes and file offsets within valid bounds.
  • Consider concurrent access from multiple application processes.
A useful design pattern is to protect shared kernel state with a mutex, prepare or access the data safely, perform the user-memory transfer in sleepable context, and update metadata consistently.

19. Lesson Summary

  • Linux separates user space and kernel space.
  • Applications communicate with drivers through kernel interfaces.
  • read() commonly transfers data from a driver to an application.
  • write() commonly transfers data from an application to a driver.
  • copy_to_user() copies kernel data into user memory.
  • copy_from_user() copies user data into kernel memory.
  • Both functions return the number of bytes not copied.
  • IOCTL supports device-specific control and structured data exchange.
  • User-supplied data must be validated before processing.
  • User-memory copying must take place in a suitable sleepable context.
  • Buffer boundaries, file positions and synchronization must be managed carefully.
