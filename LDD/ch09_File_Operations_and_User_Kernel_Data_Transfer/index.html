Chapter Overview

File operations define how user-space applications interact with a Linux device driver through device files. When an application performs operations such as open, read, write or close, the kernel invokes the corresponding callbacks registered by the driver.

This chapter explains the major file operation callbacks, including open(), read(), write(), release(), llseek(), poll() and unlocked_ioctl(). It also covers safe data transfer between user space and kernel space using copy_to_user() and copy_from_user().

Important Kernel Structures and Functions

  • struct file_operations: Contains callbacks implemented by a device driver.
  • struct file: Represents an open file within the kernel.
  • struct inode: Represents a filesystem object and provides associated metadata.
  • open(): System call used by applications to open a device file.
  • read(): Requests data from a device file.
  • write(): Sends data to a device file.
  • release(): Driver callback invoked when the open file reference is released.
  • copy_to_user(): Copies data from kernel memory to user memory.
  • copy_from_user(): Copies data from user memory to kernel memory.
  • unlocked_ioctl(): Handles device-specific control requests.

User-Space and Kernel-Space Data Transfer

  • User applications execute in user space.
  • Linux device drivers generally execute in kernel space.
  • Directly dereferencing an arbitrary user-space pointer in kernel code is unsafe.
  • copy_to_user() transfers data from kernel space to user space.
  • copy_from_user() transfers data from user space to kernel space.
  • Both functions return the number of bytes that could not be copied, so drivers must check their return values.
  • Driver callbacks should validate buffer sizes and handle partial transfers appropriately.
