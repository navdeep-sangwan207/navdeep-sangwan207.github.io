Lesson 3: read() and Driver Read Callback
Level: Intermediate
Prerequisites: VFS, struct file, file_operations, open() callback and user-kernel memory concepts.
Objective: Understand the read() system call, implement the driver's .read callback and transfer data safely from kernel space to user space.

1. Introduction

The read() system call is used by a user-space application to receive data from an opened file or device.

In a character-device driver, the kernel invokes the driver's .read callback when a read operation is performed on the device file.

The driver typically obtains data from a device, internal kernel buffer or another data source and transfers it to the user-space application.

Common Applications

  • Reading sensor measurements.
  • Receiving data from a serial device.
  • Reading buffered data from a character device.
  • Retrieving device status information.
  • Reading data received through an interrupt-driven interface.

2. What Is the read() System Call?

The read() system call requests data from an opened file descriptor.

Header File

#include <unistd.h>

Function Prototype

ssize_t read(int fd,
             void *buffer,
             size_t count);

Parameters

Parameter Description
fd File descriptor returned by open().
buffer User-space memory address where received data will be stored.
count Maximum number of bytes requested.

Return Value

Return Value Meaning
Positive value Number of bytes successfully read.
Zero End of file (EOF) for an ordinary file-like read operation.
-1 System-call failure; errno describes the error.

3. Basic read() Example in User Space

#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

int main(void)
{
    int fd;
    char buffer[100];
    ssize_t bytes;

    fd = open("/dev/mychardev", O_RDONLY);

    if (fd < 0) {
        perror("open failed");
        return 1;
    }

    bytes = read(fd, buffer, sizeof(buffer) - 1);

    if (bytes < 0) {
        perror("read failed");
        close(fd);
        return 1;
    }

    buffer[bytes] = '\0';

    printf("Received data: %s\n", buffer);

    close(fd);

    return 0;
}

Compile

gcc read_test.c -o read_test

Execute

sudo ./read_test

The application opens the character device, requests data, displays the received bytes and closes the device.

The code above assumes the device returns text data. For binary data, use the returned byte count rather than treating the buffer as a null-terminated string.

4. Driver Read Callback

A character driver implements the read operation using the .read member of struct file_operations.

Function Prototype

static ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position
);

Parameters

Parameter Description
file Represents the open-file description.
buffer User-space destination buffer.
count Maximum number of bytes requested.
position Pointer to the current file offset.

Return Value

  • Positive value: number of bytes transferred.
  • Zero: end of available data.
  • Negative value: error code.

5. What Is char __user *buffer?

The __user annotation identifies a pointer that refers to user-space memory. 

char __user *buffer

The driver must not normally access this pointer by directly dereferencing it.

Instead, Linux provides special functions to transfer data between kernel space and user space. 

copy_to_user()
copy_from_user()

In a read callback, the driver generally uses copy_to_user() because data moves from kernel memory into the application's buffer.

6. Understanding copy_to_user()

copy_to_user() copies data from a kernel-space source buffer to a user-space destination buffer.

Header File

#include <linux/uaccess.h>

Function Prototype

unsigned long copy_to_user(
    void __user *to,
    const void *from,
    unsigned long n
);

Parameters

Parameter Description
to Destination address in user space.
from Source address in kernel space.
n Number of bytes to copy.

Return Value

The function returns the number of bytes that could not be copied.

Return Value Meaning
0 All requested bytes were copied.
Nonzero Some bytes were not copied.
copy_to_user() does not return a negative errno value. A driver commonly converts a nonzero return into -EFAULT.

7. Basic Read Callback Example

Consider a driver that stores a fixed message in kernel memory. 

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/uaccess.h>
#include <linux/string.h>

static const char message[] =
    "Hello from Linux Kernel Driver\n";

static ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position
)
{
    size_t message_size;
    size_t bytes_to_copy;

    message_size = sizeof(message) - 1;

    if (*position < 0)
        return -EINVAL;

    if (*position >= message_size)
        return 0;

    bytes_to_copy = min(
        count,
        message_size - (size_t)*position
    );

    if (copy_to_user(
            buffer,
            message + (size_t)*position,
            bytes_to_copy)) {
        return -EFAULT;
    }

    *position += bytes_to_copy;

    return bytes_to_copy;
}

Explanation

  1. The message is stored in kernel memory.
  2. The driver checks the current file position.
  3. If the position reaches the message size, it returns zero.
  4. The driver calculates how many bytes can be copied.
  5. copy_to_user() transfers data to the application.
  6. The file position is updated.
  7. The callback returns the number of bytes transferred.

8. Understanding the File Position

The position parameter points to the current offset in the open-file description.

It allows a driver to support reading data in multiple operations.

Example

Assume the kernel buffer contains: 

LINUXDRIVER

The application requests four bytes per read operation.

Read Operation Starting Position Data Returned New Position
1 0 LINU 4
2 4 XDRI 8
3 8 VER 11
4 11 EOF 11

After the final byte is read, the driver returns zero to indicate EOF.

9. Understanding count and Partial Reads

The count parameter specifies the maximum number of bytes requested by the application.

A driver is not required to return the entire requested amount in one operation. It can return fewer bytes.

Example

bytes_to_copy = min(count, remaining);

This ensures that the driver never copies more than the requested amount or the remaining available data.

Partial reads are normal in Linux. Applications should process the number of bytes actually returned by read(), not assume that the entire request was satisfied.

11. Handling Errors in the Read Callback

A read callback must validate its arguments and handle transfer failures.

Error Code Possible Reason
-EFAULT User-space destination could not be accessed or data could not be copied completely.
-EINVAL Invalid file position or unsupported argument.
-EIO Device-related input/output failure.
-ERESTARTSYS An interruptible operation was interrupted and the kernel may restart the system call.

Example

if (copy_to_user(buffer, kernel_buffer, bytes)) {
    return -EFAULT;
}

12. Complete Read Callback with a Character Driver

The following example demonstrates a simple character driver that returns a fixed message. 

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/uaccess.h>
#include <linux/string.h>

#define DEVICE_NAME "readchardev"

static dev_t dev;
static struct cdev my_cdev;

static const char message[] =
    "Linux Device Driver Read Example\n";

static int my_open(struct inode *inode,
                   struct file *file)
{
    pr_info("readchardev: opened\n");
    return 0;
}

static ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position
)
{
    size_t message_size;
    size_t bytes_to_copy;

    message_size = sizeof(message) - 1;

    if (*position < 0)
        return -EINVAL;

    if (*position >= message_size)
        return 0;

    bytes_to_copy = min(
        count,
        message_size - (size_t)*position
    );

    if (copy_to_user(
            buffer,
            message + (size_t)*position,
            bytes_to_copy)) {
        return -EFAULT;
    }

    *position += bytes_to_copy;

    pr_info("readchardev: read %zu bytes\n",
            bytes_to_copy);

    return bytes_to_copy;
}

static int my_release(struct inode *inode,
                      struct file *file)
{
    pr_info("readchardev: released\n");
    return 0;
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open = my_open,
    .read = my_read,
    .release = my_release,
};

static int __init my_driver_init(void)
{
    int ret;

    ret = alloc_chrdev_region(&dev, 0, 1,
                              DEVICE_NAME);

    if (ret < 0)
        return ret;

    cdev_init(&my_cdev, &my_fops);
    my_cdev.owner = THIS_MODULE;

    ret = cdev_add(&my_cdev, dev, 1);

    if (ret < 0) {
        unregister_chrdev_region(dev, 1);
        return ret;
    }

    pr_info("readchardev: registered\n");
    pr_info("readchardev: major=%u minor=%u\n",
            MAJOR(dev), MINOR(dev));

    return 0;
}

static void __exit my_driver_exit(void)
{
    cdev_del(&my_cdev);
    unregister_chrdev_region(dev, 1);

    pr_info("readchardev: unloaded\n");
}

module_init(my_driver_init);
module_exit(my_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Basic Character Driver Read Example");
This example registers a cdev but does not create a /dev node. Create a temporary device node using the major number printed in the kernel log before testing.

16. Why Does cat Stop Reading?

The cat command repeatedly reads data until the read operation indicates end of file.

In our example, the driver checks the file position: 

if (*position >= message_size)
    return 0;

Once the entire message has been read, the next read returns zero. This tells cat that no more data is currently available from this file position.

17. Common Mistakes in Read Callbacks

Mistake Correct Approach
Directly dereferencing a user-space pointer. Use copy_to_user() for kernel-to-user transfers.
Copying more bytes than available. Calculate the remaining data size.
Ignoring the file position. Track and update *position correctly.
Returning zero before data is consumed. Return zero only when the current read reaches EOF or the device's defined no-data condition.
Returning count without copying data. Return the actual number of bytes transferred.
Ignoring copy_to_user() failures. Handle incomplete copies, commonly by returning -EFAULT.
Writing beyond the kernel buffer. Validate offsets and available capacity.

18. Summary

  • read() is a user-space system call used to receive data.
  • The driver's .read callback implements device read behavior.
  • The callback receives file, user buffer, count and file position.
  • copy_to_user() transfers data from kernel space to user space.
  • The return value indicates the number of bytes transferred.
  • Zero from read indicates EOF for the current read position.
  • Partial reads are valid and common.
  • The file position must be updated correctly.
  • Drivers must validate buffer boundaries and handle transfer errors.
