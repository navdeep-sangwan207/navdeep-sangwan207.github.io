2. Introduction to User Space and Kernel Space

Linux separates application execution from kernel execution into two main privilege domains.

User Space

  • Applications execute in user space.
  • Applications use system calls to request kernel services.
  • Application memory is managed within the process address space.

Kernel Space

  • The Linux kernel and device drivers execute in kernel space.
  • Kernel code manages hardware and system resources.
  • Kernel code must carefully validate memory accesses involving user applications.

User Space and Kernel Space

↓

↓
Kernel Space
↓
Device Driver / Kernel Buffer

A driver often needs to return information from a kernel buffer to a user application. This transfer must use suitable kernel APIs.

3. What Is copy_to_user()?

copy_to_user() is a Linux kernel function used to copy data from kernel memory into a user-space memory region.

It is commonly used in:

  • Character driver's read() callback.
  • IOCTL commands that return information.
  • Device status reporting.
  • Kernel interfaces that return data to applications.

Header File

#include <linux/uaccess.h>

Function Prototype

unsigned long copy_to_user(
    void __user *to,
    const void *from,
    unsigned long n
);

Parameters

ParameterDescription
toDestination address in user space.
fromSource address in kernel space.
nNumber of bytes requested to be copied.
The __user annotation identifies a pointer that refers to user-space memory. It helps tools such as Sparse detect incorrect address-space usage.

4. Direction of Data Transfer

The name copy_to_user() describes the destination: data is copied to user space.

Kernel-to-User Data Transfer

Kernel Buffer
copy_to_user()
User Buffer

Direction: Kernel Space → User Space

Example

char kernel_data[] = "Linux Driver";

copy_to_user(user_buffer,
             kernel_data,
             sizeof(kernel_data));

The kernel buffer is the source, and the user buffer is the destination.

5. Return Value of copy_to_user()

This is one of the most important concepts in kernel programming.

copy_to_user() returns the number of bytes that were not copied.

Return ValueMeaning
0All requested bytes were copied successfully.
NonzeroSome bytes were not copied.

Example

unsigned long not_copied;

not_copied = copy_to_user(
    user_buffer,
    kernel_buffer,
    100
);

if (not_copied == 0) {
    pr_info("Copy successful\n");
} else {
    pr_err("Copy incomplete\n");
}
Important: copy_to_user() does not return a negative error code. It returns the number of bytes not copied. A driver commonly translates an incomplete copy into -EFAULT when no bytes can safely be reported as transferred.

6. Why Not Use memcpy()?

The standard C function memcpy() is designed for ordinary memory-to-memory copying. It is not the correct API for accessing user-space memory from kernel code.

Incorrect Approach

memcpy(user_buffer,
       kernel_buffer,
       count);

Directly dereferencing or copying through an arbitrary user-space pointer is unsafe.

Correct Approach

if (copy_to_user(user_buffer,
                 kernel_buffer,
                 count)) {
    return -EFAULT;
}
memcpy()copy_to_user()
Copies between ordinary accessible memory regions.Copies from kernel memory to user memory.
Does not provide user-memory access handling.Uses kernel mechanisms to handle user-memory access.
Not suitable for arbitrary user pointers.Designed for kernel-to-user transfer.

7. Using copy_to_user() in a read() Callback

A character driver's read() callback commonly uses copy_to_user() to return data to an application.

Read Callback Prototype

ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position
);

The buffer parameter is a user-space destination address.

Basic Example

#include <linux/uaccess.h>
#include <linux/fs.h>

static char message[] = "Linux Device Driver";

static ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position)
{
    size_t data_size = sizeof(message) - 1;
    size_t bytes_to_copy;
    unsigned long not_copied;

    if (*position < 0)
        return -EINVAL;

    if (*position >= data_size)
        return 0;

    bytes_to_copy = min(
        count,
        data_size - (size_t)*position
    );

    not_copied = copy_to_user(
        buffer,
        message + *position,
        bytes_to_copy
    );

    if (not_copied == bytes_to_copy)
        return -EFAULT;

    bytes_to_copy -= not_copied;

    *position += bytes_to_copy;

    return bytes_to_copy;
}

Explanation

  1. Check that the file position is valid.
  2. Return zero when the end of the message is reached.
  3. Calculate the number of bytes available to read.
  4. Use copy_to_user() to transfer the data.
  5. If no bytes are copied, return -EFAULT.
  6. Account for any successfully copied bytes.
  7. Update the file position and return the number of bytes transferred.
This example demonstrates partial-copy handling. Linux read() operations may return fewer bytes than requested. User-space applications should be prepared to handle partial reads.

8. Understanding Partial Copy

A user-space memory region may not be fully accessible. Therefore, a copy operation may transfer some bytes and fail to copy the remaining bytes.

Example

Requested bytes = 100

Bytes successfully copied = 70

Bytes not copied = 30

The driver can calculate the successfully copied amount:

copied = requested - not_copied;

For a read callback, the driver can return the successfully transferred byte count if it is nonzero, and update the file position accordingly.

If no bytes were copied, the driver can return -EFAULT.

The driver must keep its file-position and buffer-management logic consistent with the actual number of bytes copied, not merely the requested number.

9. Using copy_to_user() in IOCTL

IOCTL commands can return device information from kernel space to user space.

Kernel Callback Example

#include <linux/uaccess.h>

static int device_status = 1;

static long my_ioctl(
    struct file *file,
    unsigned int cmd,
    unsigned long arg)
{
    int status;

    switch (cmd) {

    case MY_IOCTL_GET_STATUS:

        status = device_status;

        if (copy_to_user(
                (int __user *)arg,
                &status,
                sizeof(status))) {
            return -EFAULT;
        }

        break;

    default:
        return -ENOTTY;
    }

    return 0;
}

User-Space Application

int status;

if (ioctl(fd, MY_IOCTL_GET_STATUS, &status) == -1) {
    perror("ioctl");
} else {
    printf("Device status: %d\n", status);
}

The driver copies the current status into the application's variable.

10. Complete Simple Character Driver Example

The following example demonstrates a basic memory-backed character device that returns a message to user space through copy_to_user().

File: copy_to_user_driver.c

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/init.h>
#include <linux/uaccess.h>

#define DEVICE_NAME "mychardev"

static dev_t dev_num;
static struct cdev my_cdev;

static const char device_message[] =
    "Linux Device Driver using copy_to_user\n";

static int my_open(
    struct inode *inode,
    struct file *file)
{
    pr_info("Device opened\n");
    return 0;
}

static ssize_t my_read(
    struct file *file,
    char __user *buffer,
    size_t count,
    loff_t *position)
{
    size_t message_size;
    size_t bytes_to_copy;
    unsigned long not_copied;

    message_size = sizeof(device_message) - 1;

    if (*position < 0)
        return -EINVAL;

    if (*position >= message_size)
        return 0;

    bytes_to_copy = min(
        count,
        message_size - (size_t)*position
    );

    not_copied = copy_to_user(
        buffer,
        device_message + *position,
        bytes_to_copy
    );

    if (not_copied == bytes_to_copy)
        return -EFAULT;

    bytes_to_copy -= not_copied;

    *position += bytes_to_copy;

    return bytes_to_copy;
}

static int my_release(
    struct inode *inode,
    struct file *file)
{
    pr_info("Device closed\n");
    return 0;
}

static const struct file_operations my_fops = {
    .owner   = THIS_MODULE,
    .open    = my_open,
    .read    = my_read,
    .release = my_release,
};

static int __init my_driver_init(void)
{
    int ret;

    ret = alloc_chrdev_region(
        &dev_num, 0, 1, DEVICE_NAME
    );

    if (ret < 0) {
        pr_err("Device number allocation failed\n");
        return ret;
    }

    cdev_init(&my_cdev, &my_fops);
    my_cdev.owner = THIS_MODULE;

    ret = cdev_add(&my_cdev, dev_num, 1);

    if (ret < 0) {
        unregister_chrdev_region(dev_num, 1);
        pr_err("cdev_add failed\n");
        return ret;
    }

    pr_info("Device registered: major=%d minor=%d\n",
            MAJOR(dev_num), MINOR(dev_num));

    return 0;
}

static void __exit my_driver_exit(void)
{
    cdev_del(&my_cdev);
    unregister_chrdev_region(dev_num, 1);

    pr_info("Device driver removed\n");
}

module_init(my_driver_init);
module_exit(my_driver_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NS Learning Hub");
MODULE_DESCRIPTION("Character Driver using copy_to_user");
This example registers a character device but does not automatically create a /dev node. Create the node using the actual major and minor numbers reported in the kernel log. For a production driver, also consider device-model integration and appropriate resource lifetime management.

Returning requested count after incomplete copyReturn the number of bytes actually transferred.
Updating file position incorrectlyAdvance position only by successfully transferred bytes.
Invalid user-space addressHandle incomplete transfer and return -EFAULT when appropriate.

Incorrect pointer directionRemember that the first argument is the user-space destination.

14. Important Technical Considerations

  • copy_to_user() is intended for use in a context where sleeping is permitted.
  • Do not call it from hard interrupt context or other atomic contexts where sleeping is forbidden.
  • It may fault while accessing user memory and can sleep.
  • Use the correct __user pointer annotations.
  • Do not assume a user-space pointer is valid simply because an application supplied it.
  • Protect shared kernel buffers when concurrent access is possible.
  • Do not hold a spinlock across copy_to_user().
  • Use suitable mutex or other synchronization strategies around shared state.
  • Return accurate byte counts from read callbacks.
For a read callback, copy_to_user() transfers the data. The VFS and driver also need consistent file-position management so that subsequent reads continue at the correct offset.

16. Lesson Summary

  • copy_to_user() copies data from kernel space to user space.
  • It is declared through the Linux uaccess interface.
  • The first argument is the user-space destination.
  • The second argument is the kernel-space source.
  • The third argument specifies the requested number of bytes.
  • It returns the number of bytes not copied.
  • It is commonly used in read() callbacks and IOCTL operations.
  • Partial copies must be handled correctly.
  • It may sleep and must not be called from interrupt context.
  • It must not be replaced with memcpy() for arbitrary user pointers.
