Chapter Overview

Platform device drivers are commonly used for devices integrated into a System-on-Chip (SoC), such as memory-mapped peripherals, controllers and other hardware blocks.

This chapter explains the Linux platform bus model, platform devices, platform drivers, driver registration, probe and remove callbacks, and Device Tree fundamentals. You will learn how Linux matches hardware descriptions with platform drivers and initializes devices.

Important Kernel Structures and APIs

  • struct platform_device: Represents a platform device in the Linux device model.
  • struct platform_driver: Defines a platform driver and its callbacks.
  • platform_driver_register(): Registers a platform driver.
  • platform_driver_unregister(): Unregisters a platform driver.
  • probe(): Callback invoked when a matching device is bound to the driver.
  • remove(): Callback used when a device is detached from the driver.
  • platform_get_resource(): Retrieves a platform resource.
  • platform_get_irq(): Retrieves an IRQ associated with a platform device.
  • devm_kzalloc(): Allocates zero-initialized memory managed by the device lifecycle.
  • of_match_table: Provides Device Tree compatible-string matching information.
  • compatible: Device Tree property used to identify compatible hardware.
  • DTS and DTB: Device Tree Source and compiled Device Tree Blob formats.

Platform Driver Binding Sequence

  • Describe the hardware through platform data or Device Tree.
  • Register the platform device with the kernel.
  • Register the platform driver.
  • The platform bus attempts to match the device with the driver.
  • When a match is found, the driver's probe callback is invoked.
  • The driver obtains resources such as memory regions and IRQs.
  • The driver initializes the hardware and registers its interfaces.
  • When the device is detached, the remove callback performs cleanup.

Important Device Tree Properties

  • compatible: Identifies the hardware type and driver compatibility.
  • reg: Describes address and size information for hardware resources.
  • interrupts: Describes interrupt information.
  • status: Indicates whether a device node is enabled or disabled.
  • clocks: References clock inputs required by a device.
  • resets: References reset controls where applicable.
  • pinctrl: References pin-control configurations where supported.
