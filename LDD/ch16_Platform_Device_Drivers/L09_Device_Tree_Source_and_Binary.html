2. Device Tree File Formats

Linux uses different file formats to describe hardware configuration.

Extension Full Form / Meaning Purpose
.dts Device Tree Source Human-readable board-level hardware description.
.dtsi Device Tree Source Include Reusable hardware descriptions included by other source files.
.dtb Device Tree Blob Compiled binary representation passed to the kernel.
.dtbo Device Tree Blob Overlay Compiled overlay that modifies or extends a base Device Tree.

The source files are generally edited by developers. The compiled DTB is commonly used by boot firmware or a bootloader when starting Linux.

3. DTS – Device Tree Source

A DTS file contains the human-readable description of a particular board or system.

It describes hardware components and their relationships using nodes and properties.

Example: demo-board.dts

/dts-v1/;

/ {
    model = "Demo Embedded Board";
    compatible = "demo,embedded-board";

    #address-cells = <1>;
    #size-cells = <1>;

    memory@80000000 {
        device_type = "memory";
        reg = <0x80000000 0x10000000>;
    };
};

This file is readable and editable using a text editor.

Characteristics of DTS

  • Human-readable text format.
  • Contains nodes and properties.
  • Can include other Device Tree source files.
  • Can be compiled into a DTB file.
  • Usually describes a specific board or system.

4. DTSI – Device Tree Source Include

A DTSI file contains reusable Device Tree definitions.

It is commonly used to describe hardware shared by multiple boards, such as:

  • CPU cores.
  • Memory controllers.
  • UART controllers.
  • I2C and SPI controllers.
  • Interrupt controllers.
  • GPIO controllers.

For example, multiple development boards may use the same SoC but have different external peripherals and pin connections.

The common SoC description can be placed in a DTSI file, while each board has its own DTS file.

Example: demo-soc.dtsi

/ {
    soc {
        #address-cells = <1>;
        #size-cells = <1>;
        ranges;

        uart0: serial@40000000 {
            compatible = "demo,soc-uart";
            reg = <0x40000000 0x1000>;
            status = "disabled";
        };
    };
};

Including the DTSI File

/dts-v1/;

#include "demo-soc.dtsi"

/ {
    model = "Demo Development Board";
    compatible = "demo,development-board";
};

&uart0 {
    status = "okay";
};

The board-specific DTS includes the common SoC description and enables the UART node.

This is an illustrative example. A real board DTS must follow the target SoC's address, interrupt, clock, pin-control and binding requirements.

5. DTS and DTSI: Main Difference

DTS DTSI
Usually represents a board or complete system. Usually contains reusable hardware definitions.
Commonly selected as a final board description for compilation. Usually included by another DTS or DTSI file.
Contains board-specific model and configuration. Often contains common SoC or peripheral information.
Can include DTSI files. Can include other DTSI files.

A typical source organization looks like this:

Board DTS
↓ includes
SoC DTSI
↓ may include
Common Peripheral DTSI Files
↓ compilation
Board DTB

6. DTB – Device Tree Blob

A DTB file is the compiled binary representation of a Device Tree description.

It is designed for efficient processing by the Linux kernel and firmware.

Important Characteristics

  • Binary format rather than readable source text.
  • Contains nodes, properties and their values.
  • Can be loaded by a bootloader.
  • Can be passed to the Linux kernel during boot.
  • Can be decompiled into a DTS representation for inspection.
demo-board.dts
↓ DTC Compiler
demo-board.dtb
↓ Bootloader / Firmware
Linux Kernel

7. DTBO – Device Tree Overlay

A Device Tree Overlay is used to modify or extend an existing base Device Tree.

It can add hardware descriptions or change selected properties without requiring a completely separate full Device Tree source.

Common Uses

  • Enabling an additional peripheral.
  • Adding a hardware module connected through an expansion interface.
  • Changing pin configuration.
  • Adding an I2C or SPI peripheral.
  • Changing selected hardware properties.

Illustrative Overlay Source

/dts-v1/;
/plugin/;

/ {
    fragment@0 {
        target = <&uart0>;

        __overlay__ {
            status = "okay";
        };
    };
};

This example targets a node labelled uart0 and changes its status to enabled.

The overlay source can be compiled into a DTBO file.

Overlay application requires support from the bootloader, firmware or kernel configuration mechanism. A standalone DTBO file is not automatically applied merely because it exists on the filesystem.

8. Device Tree Compiler (DTC)

The Device Tree Compiler converts Device Tree Source into a binary blob and can also convert a DTB back into a source representation.

The commonly used command-line utility is named dtc.

Install DTC on Ubuntu

sudo apt update
sudo apt install device-tree-compiler

Check DTC Version

dtc --version

Display Help

dtc --help

9. Compiling DTS into DTB

Use the following command to compile a Device Tree source file.

dtc -I dts -O dtb -o demo-board.dtb demo-board.dts
Option Meaning
-I dts Specifies Device Tree Source as the input format.
-O dtb Specifies Device Tree Blob as the output format.
-o Specifies the output filename.
demo-board.dts Input source file.
demo-board.dtb Generated binary file.

Verify the Generated DTB

file demo-board.dtb
ls -lh demo-board.dtb

If the source file is valid for the compiler, it produces the binary output. Compiler warnings should still be reviewed.

10. Decompiling DTB into DTS

A DTB file can be converted back into a readable Device Tree source representation.

Command

dtc -I dtb -O dts -o output.dts demo-board.dtb

Here:

  • -I dtb specifies binary input.
  • -O dts specifies readable source output.
  • output.dts is the generated source file.
  • demo-board.dtb is the input binary.

View the Output

cat output.dts

Decompilation is useful for inspecting a DTB supplied by a bootloader or firmware.

Decompilation does not necessarily restore the original source formatting, comments, include-file organization or labels exactly. The output is a reconstructed source representation of the compiled data.

11. Compiling Device Tree Files in the Linux Kernel

Linux kernel source trees contain many Device Tree source files for supported boards and SoCs.

These files are generally located under:

arch/arm/boot/dts/
arch/arm64/boot/dts/

Exact directories vary with kernel version and architecture.

Build Device Tree Blobs

make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- dtbs

For an ARM64 target, a corresponding build may use:

make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- dtbs

The kernel build system selects the relevant Device Tree files and invokes the required compilation steps.

Important Kernel Build Commands

Command Purpose
make dtbs Builds configured Device Tree blobs for the target architecture and kernel tree.
make dtbs_check Validates Device Tree source against available binding schemas, subject to required dependencies and configuration.
make help Displays available build targets.
For production kernel development, use the kernel's build system and binding validation workflow. Direct DTC compilation is useful for learning, isolated examples and specific inspection tasks, but it does not replace the complete kernel build and validation process.

12. Device Tree Include Processing

A board DTS may depend on several included files.

For example:

demo-board.dts
    |
    +-- demo-soc.dtsi
    |       |
    |       +-- demo-clocks.dtsi
    |       |
    |       +-- demo-interrupts.dtsi
    |
    +-- demo-board-pinctrl.dtsi

The compiler or kernel build system processes the source and its included definitions to generate the final compiled Device Tree.

Include files improve maintainability and reduce duplication across boards that share hardware.

13. Device Tree Overlay Compilation

Overlay source files can also be compiled using DTC.

Example Command

dtc -@ -I dts -O dtb \
    -o demo-overlay.dtbo demo-overlay.dts

The -@ option requests symbol information useful for overlay references and application workflows.

Some overlay workflows require symbol information in the base DTB as well. The exact requirements depend on the bootloader or overlay application mechanism.

Check the Output

file demo-overlay.dtbo

14. Inspecting the Live Device Tree

When Linux is running with Device Tree support, the live hardware description is commonly exposed through:

/sys/firmware/devicetree/base

On many systems, /proc/device-tree provides another view of the same information.

List Root Properties and Nodes

ls /sys/firmware/devicetree/base

Read Board Model

cat /sys/firmware/devicetree/base/model

Read Compatible Information

hexdump -C /sys/firmware/devicetree/base/compatible

String properties are often stored as NUL-terminated strings. Some properties contain binary cells and are better inspected using tools such as hexdump or xxd.

Find Peripheral Nodes

find /sys/firmware/devicetree/base -maxdepth 3 -type d
The live Device Tree is platform-dependent. An x86 Ubuntu installation running in VirtualBox may use ACPI rather than Device Tree, so these paths may not contain a useful hardware description or may not exist.

15. DTS and DTB: Complete Comparison

Feature DTS DTB
Format Text Binary
Human readable Yes No, not directly
Typical use Development and source maintenance Boot-time hardware description
Edited directly Yes Normally no
Compiler Input to DTC Output from DTC
Inspection Text editor DTC decompilation or binary inspection

16. Practical Exercise: DTS to DTB and Back

Objective: Create a Device Tree source file, compile it into a DTB file and decompile it back into DTS format.

Step 1: Install DTC

sudo apt update
sudo apt install device-tree-compiler

Step 2: Create a Source File

nano demo.dts

Step 3: Enter the Following Code

/dts-v1/;

/ {
    model = "NS Learning Hub Demo Board";
    compatible = "nslearninghub,demo-board";

    #address-cells = <1>;
    #size-cells = <1>;

    memory@80000000 {
        device_type = "memory";
        reg = <0x80000000 0x10000000>;
    };
};

Step 4: Compile the DTS File

dtc -I dts -O dtb -o demo.dtb demo.dts

Step 5: Check the Binary

file demo.dtb

Step 6: Decompile the DTB File

dtc -I dtb -O dts -o demo-output.dts demo.dtb

Step 7: Display the Decompiled Source

cat demo-output.dts

Expected Result

The DTC compiler should produce demo.dtb. The decompilation command should then generate demo-output.dts, containing a readable representation of the compiled hardware description.

This exercise tests the source-to-binary conversion process. It does not configure the actual memory of your Ubuntu computer and must not be used as a replacement system DTB.

17. Troubleshooting Common Errors

Error / Problem Possible Cause and Solution
dtc: command not found Install the Device Tree Compiler package.
Syntax error Check braces, semicolons, property syntax and node definitions.
Input file not found Check the current directory and source filename.
Include file not found Check include paths and kernel build include configuration.
Overlay references unresolved Check labels, symbols and overlay compilation requirements.
Binding validation failure Check the YAML binding and required hardware properties.
Driver probe does not occur Check device population, compatible matching, status and resource configuration.

18. Device Tree in Your Development Environment

Ubuntu in VirtualBox

You can use Ubuntu in VirtualBox to:

  • Install and run DTC.
  • Create DTS files.
  • Compile and decompile DTB files.
  • Study Linux kernel Device Tree source code.
  • Read Device Tree bindings and schemas.

However, a typical x86 virtual machine uses ACPI and virtual hardware. It does not automatically provide the Device Tree description or physical SoC peripherals of an embedded development board.

LPC2129 and Keil uVision

Your LPC2129 bare-metal development environment is different from the Linux Device Tree workflow.

  • Keil uVision simulator executes LPC2129 firmware.
  • Peripheral registers are accessed directly by bare-metal C code.
  • Linux Device Tree describes hardware to a Linux kernel.
  • The LPC2129 Keil simulator does not provide a Linux DTB or OF platform-driver environment.
Learn Device Tree compilation and source structure in Ubuntu. For actual Linux platform-driver testing, use a supported embedded Linux board or a suitable architecture emulator with Device Tree support.
