Chapter Overview

Linux device drivers may be accessed concurrently by multiple processes, kernel threads, interrupt handlers and other execution contexts. When these execution paths access shared data without proper coordination, race conditions and data corruption can occur.

This chapter introduces kernel synchronization mechanisms such as atomic operations, spinlocks, mutexes, semaphores, wait queues, completions and read-write locks. It also explains critical sections, deadlocks and synchronization techniques used to develop reliable device drivers.

Important Kernel Synchronization Mechanisms

  • Atomic operations: Provide indivisible operations on supported variables.
  • Spinlocks: Protect shared data using busy-wait locking; suitable for short critical sections.
  • Mutexes: Sleeping locks used when the calling task may wait for access to a resource.
  • Semaphores: Synchronization primitives that can control access to a limited number of resources.
  • Wait queues: Allow tasks to sleep until a specified condition becomes true.
  • Completions: Provide a mechanism for one execution context to wait for an event signaled by another.
  • Read-write locks: Allow multiple readers or an exclusive writer.
  • Critical section: A section of code that accesses shared resources and requires appropriate protection.

Synchronization Guidelines

  • Identify every shared resource accessed by multiple execution contexts.
  • Choose a synchronization primitive according to the execution context.
  • Keep spinlock-protected critical sections short.
  • Do not sleep while holding a spinlock.
  • Do not acquire a mutex from interrupt context.
  • Use consistent lock ordering to reduce deadlock risk.
  • Protect shared driver buffers and state variables.
  • Release locks on every applicable error and cleanup path.
