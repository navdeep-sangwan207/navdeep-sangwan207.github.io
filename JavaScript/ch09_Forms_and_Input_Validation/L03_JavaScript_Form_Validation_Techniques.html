2. Introduction to Form Validation

Form validation is the process of checking whether user-entered data satisfies specified requirements before it is accepted or submitted.

Common validation requirements include:

  • Required fields must not be empty.
  • Email addresses must follow an acceptable format.
  • Passwords must satisfy minimum security requirements.
  • Phone numbers must contain an appropriate number of digits.
  • Numeric values must fall within specified limits.
  • Confirmation fields must match their corresponding values.

Types of Form Validation

Type Description
HTML Validation Uses built-in attributes such as required, min, max and pattern.
JavaScript Validation Uses JavaScript conditions and functions to validate input.
Server-Side Validation Validates submitted data on the server before processing or storing it.
Important: Client-side validation improves user experience but cannot guarantee data security. Always validate submitted data on the server because browser-side validation can be bypassed.

3. Required Field Validation

Required-field validation ensures that users provide mandatory information before submitting a form.

Example 1: Checking an Empty Field

const username = document.getElementById("username");

if (username.value.trim() === "") {
    console.log("Username is required.");
} else {
    console.log("Username is valid.");
}

The trim() method removes whitespace from the beginning and end of a string.

Example 2: Validating Multiple Required Fields

function validateRequiredFields() {

    const name = document.getElementById("name").value.trim();
    const email = document.getElementById("email").value.trim();
    const city = document.getElementById("city").value.trim();

    if (name === "") {
        return false;
    }

    if (email === "") {
        return false;
    }

    if (city === "") {
        return false;
    }

    return true;
}

console.log(validateRequiredFields());

The function returns true only when all three fields contain non-whitespace values.

Using HTML required Attribute

<input type="text" id="username" required>
<input type="email" id="email" required>

The browser performs built-in validation when the form is submitted normally.

4. Email Validation

Email validation checks whether an entered value follows an acceptable email address format.

Approach 1: Using HTML Email Input

<input type="email" id="email" required>

The browser checks whether the value has a valid email-like format according to its built-in validation rules.

Approach 2: Using JavaScript Validity Properties

const email = document.getElementById("email");

if (email.value.trim() === "") {
    console.log("Email is required.");
} else if (!email.validity.valid) {
    console.log("Enter a valid email address.");
} else {
    console.log("Email format is valid.");
}

Approach 3: Using a Regular Expression

function validateEmail(email) {

    const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

    return pattern.test(email);
}

console.log(validateEmail("user@example.com")); 
console.log(validateEmail("userexample.com"));

Expected Output:

true
false
Practical note: Email format validation does not prove that an email account exists or belongs to the user. Email verification generally requires a confirmation link or code sent to that address.

5. Phone Number Validation

Phone number validation checks whether a number contains an acceptable number of digits and follows the application's expected format.

Example 3: Validating a 10-Digit Number

function validatePhone(phone) {

    const pattern = /^[0-9]{10}$/;

    return pattern.test(phone);
}

console.log(validatePhone("9876543210"));
console.log(validatePhone("12345"));

Expected Output:

true
false

This example accepts exactly ten digits. It is a simplified application-specific check, not a complete international telephone number validation system.

6. Password Validation

Password validation checks whether a password satisfies the application's password requirements.

A sample password policy might require:

  • At least eight characters.
  • At least one uppercase letter.
  • At least one lowercase letter.
  • At least one digit.
  • At least one special character.

Example 4: Password Validation Function

function validatePassword(password) {

    const minLength = password.length >= 8;
    const hasUppercase = /[A-Z]/.test(password);
    const hasLowercase = /[a-z]/.test(password);
    const hasNumber = /[0-9]/.test(password);
    const hasSpecial = /[^A-Za-z0-9]/.test(password);

    return (
        minLength &&
        hasUppercase &&
        hasLowercase &&
        hasNumber &&
        hasSpecial
    );
}

console.log(validatePassword("Hello@123"));
console.log(validatePassword("hello123"));

Expected Output:

true
false

Example 5: Confirm Password Validation

function validateConfirmPassword(password, confirmPassword) {

    return password === confirmPassword;
}

console.log(
    validateConfirmPassword("Hello@123", "Hello@123")
);

console.log(
    validateConfirmPassword("Hello@123", "Hello123")
);

Expected Output:

true
false
Interview Tip: Password confirmation is a consistency check. It does not replace the actual password-strength validation.

7. Numeric Validation and Range Checking

Numeric validation checks whether a value is a valid number and falls within the required range.

Example 6: Checking Numeric Input

function validateAge(age) {

    const value = Number(age);

    if (age.trim() === "" || !Number.isFinite(value)) {
        return false;
    }

    return value >= 18 && value <= 60;
}

console.log(validateAge("25"));
console.log(validateAge("15"));
console.log(validateAge("abc"));

Expected Output:

true
false
false

Why Number.isFinite()?

Number.isFinite() checks whether a value is a finite number. It rejects NaN, Infinity and -Infinity.

HTML Numeric Constraints

<input
    type="number"
    id="age"
    min="18"
    max="60"
    required
>

The browser can enforce the specified numeric range during normal form validation.

Avoid using parseInt() alone as a complete numeric validator. For example, parseInt("25abc") returns 25 even though the original input contains non-numeric characters.

8. Reusable Custom Validation Functions

Reusable validation functions reduce duplicated code and make form validation easier to maintain.

Example 7: Reusable Required-Field Validator

function isRequired(value) {
    return value.trim() !== "";
}

console.log(isRequired("Rahul"));
console.log(isRequired("   "));

Expected Output:

true
false

Example 8: Reusable Minimum-Length Validator

function hasMinimumLength(value, minLength) {
    return value.length >= minLength;
}

console.log(hasMinimumLength("JavaScript", 5));
console.log(hasMinimumLength("JS", 5));

Expected Output:

true
false

Example 9: Combining Multiple Validation Rules

function validateUser(username, email, password) {

    const errors = [];

    if (!isRequired(username)) {
        errors.push("Username is required.");
    }

    if (!validateEmail(email)) {
        errors.push("Email format is invalid.");
    }

    if (!validatePassword(password)) {
        errors.push("Password does not meet requirements.");
    }

    return errors;
}

const errors = validateUser(
    "Rahul",
    "rahul@example.com",
    "Hello@123"
);

console.log(errors);

Expected Output:

[]

An empty array indicates that none of the validation rules generated an error.

9. HTML Constraint Validation API

The Constraint Validation API provides browser methods and properties for checking whether form controls satisfy their validation constraints.

Important Properties

Property Purpose
validity.valid True when the element satisfies its constraints.
validity.valueMissing True when a required field is empty.
validity.typeMismatch True when the entered value does not match the expected type.
validity.tooShort True when the value is shorter than minlength.
validity.tooLong True when the value exceeds maxlength.
validity.rangeUnderflow True when a numeric value is below min.
validity.rangeOverflow True when a numeric value is above max.
validity.patternMismatch True when a value does not match pattern.
validity.customError True when a custom validation error has been set.

Important Methods

Method Purpose
checkValidity() Checks whether the element or form satisfies validation constraints.
reportValidity() Checks validity and asks the browser to display validation feedback.
setCustomValidity() Sets a custom validation error message.
willValidate Property indicating whether the element participates in constraint validation.

Example 10: Using checkValidity()

<input type="email" id="email" required>

<script>
const email = document.getElementById("email");

console.log(email.checkValidity());
</script>

If the field is empty or contains an invalid email format, the result is false.

Example 11: Using reportValidity()

const email = document.getElementById("email");

email.reportValidity();

The browser checks the field and displays its validation feedback if it is invalid.

Example 12: Custom Validation With setCustomValidity()

<input type="text" id="username" required>
<button id="checkButton">Validate</button>

<script>
const username = document.getElementById("username");
const button = document.getElementById("checkButton");

button.addEventListener("click", function() {

    if (username.value.trim().length < 5) {

        username.setCustomValidity(
            "Username must contain at least 5 characters."
        );

    } else {

        username.setCustomValidity("");

    }

    username.reportValidity();

});
</script>
Important: An empty string passed to setCustomValidity() clears the custom error. If a non-empty message remains set, the field continues to be invalid.

10. HTML Validation Attributes

Attribute Purpose Example
required Makes a field mandatory. required
minlength Sets minimum text length. minlength="8"
maxlength Sets maximum text length. maxlength="20"
min Sets minimum numeric or date value. min="18"
max Sets maximum numeric or date value. max="60"
step Defines allowed numeric increments. step="0.5"
pattern Defines a regular-expression constraint. pattern="[A-Za-z]+"

Example 13: Combining HTML Constraints

<form id="profileForm">

    <input
        type="text"
        name="username"
        required
        minlength="5"
        maxlength="15"
    >

    <input
        type="email"
        name="email"
        required
    >

    <input
        type="number"
        name="age"

        max="60"
        required
    >

    <button type="submit">Submit</button>

</form>

The browser applies these constraints when the form is submitted normally.

11. Complete Practical Example: Validated Registration Form

This example combines multiple validation techniques to validate a registration form before allowing submission.

Complete HTML and JavaScript Code

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Registration Form Validation</title>

    <style>
        body {
            font-family: Arial, sans-serif;
        }

        form {
            max-width: 400px;
            display: grid;
            gap: 10px;
        }

        input {
            padding: 10px;
        }

        .error {
            color: red;
        }

        .success {
            color: green;
        }
    </style>
</head>
<body>

    <h2>Student Registration</h2>

    <form id="registrationForm" novalidate>

        <label for="username">Username</label>
        <input type="text" id="username" required>
        <small id="usernameError" class="error"></small>

        <label for="email">Email</label>
        <input type="email" id="email" required>
        <small id="emailError" class="error"></small>

        <label for="password">Password</label>
        <input type="password" id="password" required>
        <small id="passwordError" class="error"></small>

        <label for="confirmPassword">Confirm Password</label>
        <input type="password" id="confirmPassword" required>
        <small id="confirmError" class="error"></small>

        <button type="submit">Register</button>

    </form>

    <p id="result"></p>

    <script>
    const form = document.getElementById("registrationForm");

    const username = document.getElementById("username");
    const email = document.getElementById("email");
    const password = document.getElementById("password");
    const confirmPassword = document.getElementById("confirmPassword");

    const usernameError = document.getElementById("usernameError");
    const emailError = document.getElementById("emailError");
    const passwordError = document.getElementById("passwordError");
    const confirmError = document.getElementById("confirmError");
    const result = document.getElementById("result");

    function validateUsername() {

        if (username.value.trim().length < 3) {
            usernameError.textContent =
                "Username must contain at least 3 characters.";
            return false;
        }

        usernameError.textContent = "";
        return true;
    }

    function validateEmail() {

        if (email.value.trim() === "" || !email.validity.valid) {
            emailError.textContent =
                "Enter a valid email address.";
            return false;
        }

        emailError.textContent = "";
        return true;
    }

    function validatePassword() {

        const value = password.value;

        const valid =
            value.length >= 8 &&
            /[A-Z]/.test(value) &&
            /[a-z]/.test(value) &&
            /[0-9]/.test(value);

        if (!valid) {
            passwordError.textContent =
                "Use 8 characters with uppercase, lowercase and a number.";
            return false;
        }

        passwordError.textContent = "";
        return true;
    }

    function validateConfirmPassword() {

        if (
            confirmPassword.value === "" ||
            confirmPassword.value !== password.value
        ) {
            confirmError.textContent =
                "Passwords do not match.";
            return false;
        }

        confirmError.textContent = "";
        return true;
    }

    form.addEventListener("submit", function(event) {

        event.preventDefault();

        const isUsernameValid = validateUsername();
        const isEmailValid = validateEmail();
        const isPasswordValid = validatePassword();
        const isConfirmValid = validateConfirmPassword();

        const isFormValid =
            isUsernameValid &&
            isEmailValid &&
            isPasswordValid &&
            isConfirmValid;

        if (!isFormValid) {
            result.textContent = "Please correct the errors.";
            result.className = "error";
            return;
        }

        result.textContent =
            "Registration details passed client-side validation.";

        result.className = "success";

        form.reset();

    });
    </script>

</body>
</html>

Expected Behavior

  • Username must contain at least three characters.
  • Email must have an acceptable email format.
  • Password must contain at least eight characters, an uppercase letter, a lowercase letter and a digit.
  • Confirm password must match the password.
  • Invalid submissions display field-specific errors.
  • Valid submissions display a confirmation message and reset the form.
This example demonstrates client-side validation only. It does not create an account or send data to a server.

12. Common Mistakes and Debugging

Mistake Correct Approach
Checking only whether a field is empty. Also validate its format and business rules.
Using Number() without checking empty input. Check the trimmed input before conversion.
Using parseInt() as complete validation. Use strict conversion and Number.isFinite() where appropriate.
Forgetting to clear custom validity messages. Call setCustomValidity("") when the value becomes valid.
Checking password strength but not confirmation. Compare the password and confirmation values.
Relying only on client-side validation. Repeat validation on the server.
Using innerHTML for untrusted error text. Use textContent to display plain text safely.

Debugging Example

const email = document.getElementById("email");

console.log(email.value);
console.log(email.validity.valid);
console.log(email.validity.typeMismatch);
console.log(email.validity.valueMissing);

These properties help identify why an email field is considered invalid.

13. Placement Interview Questions and Answers

Q1. What is form validation?

Form validation checks whether user input satisfies predefined requirements before processing or submission.

Q2. What is the difference between client-side and server-side validation?

Client-side validation occurs in the browser and provides immediate feedback. Server-side validation occurs on the server and is essential for security and data integrity.

Q3. What is the purpose of the required attribute?

It prevents a form from passing normal browser constraint validation when the required field is empty.

Q4. What is Number.isFinite()?

It checks whether a value is a finite number and rejects NaN, Infinity and -Infinity.

Q5. What is the Constraint Validation API?

It is a browser API that provides methods and properties for checking HTML form control constraints.

Q6. What is the difference between checkValidity() and reportValidity()?

checkValidity() checks whether constraints are satisfied and returns a Boolean. reportValidity() performs the check and also asks the browser to display validation feedback.

Q7. What does setCustomValidity() do?

It sets a custom validation message. A non-empty message makes the control invalid; an empty string clears that custom error.

Q8. Why should confirm password be validated?

It ensures that the confirmation field contains exactly the same value as the original password.

Q9. Why is trim() useful in form validation?

It removes leading and trailing whitespace so that a whitespace-only value is not mistakenly treated as meaningful input.

Q10. Can HTML validation replace JavaScript validation?

HTML validation handles common constraints, but JavaScript is needed for more complex custom rules and interactive validation workflows.

Q11. Can client-side validation be bypassed?

Yes. Users can disable JavaScript, modify browser requests or submit requests directly. Server-side validation is therefore mandatory.

Q12. What is novalidate?

The novalidate attribute disables the browser's automatic form validation during normal submission. It is useful when implementing a custom validation interface with JavaScript.
