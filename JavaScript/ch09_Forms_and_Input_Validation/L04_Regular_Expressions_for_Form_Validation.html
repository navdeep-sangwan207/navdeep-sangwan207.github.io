2. What Is a Regular Expression?

A regular expression, commonly called regex or regexp, is a sequence of characters that defines a search pattern. JavaScript uses regular expressions to search, match, extract and validate strings.

Common Applications

  • Validating email address formats.
  • Checking phone number formats.
  • Validating usernames and passwords.
  • Finding specific words inside text.
  • Extracting numbers and patterns from strings.
  • Replacing unwanted characters.

Creating a Regular Expression

JavaScript supports two common ways to create regex patterns.

Method 1: Regular Expression Literal

const pattern = /hello/;

console.log(pattern.test("hello world"));

Output:

true

Method 2: RegExp Constructor

const pattern = new RegExp("hello");

console.log(pattern.test("hello world"));

Output:

true
Interview Tip: Regex literals are convenient for fixed patterns. The RegExp constructor is useful when a pattern must be created dynamically from a string.

3. Basic Regex Characters

Regular expressions use special characters to describe matching rules.

Symbol Meaning Example
. Matches any character except line terminators by default. /a.b/
^ Matches the beginning of input or line. /^Hello/
$ Matches the end of input or line. /world$/
* Matches zero or more repetitions. /ab*/
+ Matches one or more repetitions. /ab+/
? Matches zero or one occurrence. /colou?r/
\ Escapes a special character or introduces a special sequence. /\./
| Alternation (OR). /cat|dog/

Example 1: Matching a Word

const pattern = /JavaScript/;

console.log(pattern.test("I am learning JavaScript"));
console.log(pattern.test("I am learning Python"));

Output:

true
false

Example 2: Using the Dot Character

const pattern = /c.t/;

console.log(pattern.test("cat"));
console.log(pattern.test("cut"));
console.log(pattern.test("coat"));

Output:

true
true
false

4. Character Classes and Character Ranges

Character classes define which characters are allowed at a particular position in a pattern.

Pattern Meaning
[abc] Matches a, b or c.
[^abc] Matches any character except a, b or c.
[a-z] Matches lowercase English letters.
[A-Z] Matches uppercase English letters.
[0-9] Matches digits from 0 to 9.
[A-Za-z] Matches uppercase or lowercase English letters.
[A-Za-z0-9] Matches English letters or digits.

Example 3: Matching Digits

const pattern = /[0-9]/;

console.log(pattern.test("Hello123"));
console.log(pattern.test("Hello"));

Output:

true
false

Example 4: Matching a Specific Character Range

const pattern = /^[A-Z]+$/;

console.log(pattern.test("HELLO"));
console.log(pattern.test("Hello"));
console.log(pattern.test("HELLO123"));

Output:

true
false
false

The pattern accepts one or more uppercase English letters and requires the entire input to match.

5. Shorthand Character Classes

JavaScript regex provides shorthand sequences for frequently used character classes.

Pattern Meaning
\d Matches an ASCII digit from 0 to 9.
\D Matches a non-digit character.
\w Matches ASCII letters, digits and underscore.
\W Matches a character other than those matched by \w.
\s Matches whitespace characters.
\S Matches non-whitespace characters.

Example 5: Checking for Digits

const pattern = /\d+/;

console.log(pattern.test("Room 25"));
console.log(pattern.test("Room A"));

Output:

true
false

Example 6: Checking Whitespace

const pattern = /\s/;

console.log(pattern.test("Hello World"));
console.log(pattern.test("HelloWorld"));

Output:

true
false
Important: In JavaScript, \w is not a universal Unicode letter matcher. For international usernames and names, consider Unicode property escapes such as \p{L} with the Unicode flag.

6. Quantifiers

Quantifiers specify how many times a character, group or character class can occur.

Quantifier Meaning
* Zero or more occurrences.
+ One or more occurrences.
? Zero or one occurrence.
{n} Exactly n occurrences.
{n,} At least n occurrences.
{n,m} Between n and m occurrences.

Example 7: At Least One Digit

const pattern = /\d+/;

console.log(pattern.test("ABC123"));
console.log(pattern.test("ABC"));

Output:

true
false

Example 8: Exactly Ten Digits

const pattern = /^\d{10}$/;

console.log(pattern.test("9876543210"));
console.log(pattern.test("987654321"));

Output:

true
false

Example 9: Between Five and Fifteen Characters

const pattern = /^[A-Za-z0-9]{5,15}$/;

console.log(pattern.test("Rahul123"));
console.log(pattern.test("abc"));
console.log(pattern.test("VeryLongUsername123"));

Output:

true
false
false

7. Anchors: Beginning and End of Input

Anchors specify the position where a pattern must match. They do not consume characters.

Anchor Meaning
^ Beginning of input or line.
$ End of input or line.

Example 10: Matching the Beginning

const pattern = /^Hello/;

console.log(pattern.test("Hello World"));
console.log(pattern.test("Say Hello"));

Output:

true
false

Example 11: Matching the End

const pattern = /JavaScript$/;

console.log(pattern.test("Learning JavaScript"));
console.log(pattern.test("JavaScript is useful"));

Output:

true
false

Example 12: Matching the Entire Input

const pattern = /^[0-9]{4}$/;

console.log(pattern.test("2026"));
console.log(pattern.test("Year 2026"));
console.log(pattern.test("20265"));

Output:

true
false
false
For form validation, use anchors when the entire input must satisfy a rule. Without anchors, test() can return true because only a portion of the string matches.

8. Groups and Alternation

Capturing Groups

Parentheses create a group that can capture part of a match. 

const pattern = /(Java)(Script)/;

const result = "JavaScript".match(pattern);

console.log(result[0]);
console.log(result[1]);
console.log(result[2]);

Output:

JavaScript
Java
Script

Non-Capturing Groups

A non-capturing group uses (?:...). It groups pattern components without storing a separate captured result. 

const pattern = /(?:cat|dog)/;

console.log(pattern.test("cat"));
console.log(pattern.test("dog"));

Output:

true
true

Alternation

The pipe symbol | works like logical OR between alternatives. 

const pattern = /^(cat|dog)$/;

console.log(pattern.test("cat"));
console.log(pattern.test("dog"));
console.log(pattern.test("cow"));

Output:

true
true
false

Example 13: Matching Multiple File Extensions

const pattern = /\.(jpg|jpeg|png)$/i;

console.log(pattern.test("photo.jpg"));
console.log(pattern.test("image.PNG"));
console.log(pattern.test("document.pdf"));

Output:

true
true
false

9. Regex Flags

Flags modify how a regular expression performs matching.

Flag Name Purpose
i Case-insensitive Ignores letter case during matching.
g Global Finds all matches instead of stopping at the first match.
m Multiline Makes ^ and $ work at line boundaries.
s DotAll Allows dot to match line terminators.
u Unicode Enables Unicode-aware regex behavior.
y Sticky Matches at the current lastIndex position.

Example 14: Case-Insensitive Matching

const pattern = /javascript/i;

console.log(pattern.test("JavaScript"));
console.log(pattern.test("JAVASCRIPT"));
console.log(pattern.test("javascript"));

Output:

true
true
true

Example 15: Global Matching

const pattern = /\d+/g;

const result = "Room 101, Floor 2".match(pattern);

console.log(result);

Output:

["101", "2"]

Example 16: Multiline Matching

const text = "First line\nSecond line";

const pattern = /^Second/m;

console.log(pattern.test(text));

Output:

true

10. JavaScript Methods for Regular Expressions

JavaScript provides methods on RegExp and String objects for working with regular expressions.

1. test()

Returns true or false depending on whether a match exists. 

const pattern = /\d+/;

console.log(pattern.test("Room 25"));

Output:

true

2. exec()

Returns detailed information about a match, or null when no match is found. 

const pattern = /\d+/;

const result = pattern.exec("Room 25");

console.log(result[0]);
console.log(result.index);

Output:

25
5

3. match()

Returns matching results from a string. 

const text = "I have 10 books and 5 pens";

console.log(text.match(/\d+/g));

Output:

["10", "5"]

4. matchAll()

Returns an iterator containing detailed information about all matches. It requires a global regex. 

const text = "Room 101 and Room 202";

const matches = text.matchAll(/\d+/g);

for (const match of matches) {
    console.log(match[0], match.index);
}

Output:

101 5
202 17

5. replace()

Replaces matched text with another value. 

const text = "My phone is 9876543210";

const result = text.replace(/\d/g, "*");

console.log(result);

Output:

My phone is **********

6. split()

Splits a string wherever the regular expression matches. 

const text = "HTML,CSS;JavaScript Python";

const result = text.split(/[,;\s]+/);

console.log(result);

Output:

["HTML", "CSS", "JavaScript", "Python"]

7. search()

Returns the index of the first matching substring, or -1 when no match exists. 

const text = "Learn JavaScript";

console.log(text.search(/Java/));
console.log(text.search(/Python/));

Output:

6
-1

11. Practical Regex Patterns for Form Validation

Example 17: Username Validation

Requirements:

  • Between 5 and 15 characters.
  • Only English letters, digits and underscores.
const usernamePattern = /^[A-Za-z0-9_]{5,15}$/;

console.log(usernamePattern.test("rahul_123"));
console.log(usernamePattern.test("abc"));
console.log(usernamePattern.test("rahul@123"));

Output:

true
false
false

Example 18: Email Format Validation

const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

console.log(emailPattern.test("user@example.com"));
console.log(emailPattern.test("userexample.com"));
console.log(emailPattern.test("user@domain"));

Output:

true
false
false

This is a practical basic format check, not a complete implementation of every valid email address specification.

Example 19: Ten-Digit Phone Number

const phonePattern = /^\d{10}$/;

console.log(phonePattern.test("9876543210"));
console.log(phonePattern.test("987654321"));
console.log(phonePattern.test("98765432101"));

Output:

true
false
false

Example 20: Strong Password Validation

Requirements:

  • At least eight characters.
  • At least one uppercase letter.
  • At least one lowercase letter.
  • At least one digit.
  • At least one special character.
const passwordPattern =
    /^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}$/;

console.log(passwordPattern.test("Hello@123"));
console.log(passwordPattern.test("hello123"));
console.log(passwordPattern.test("HELLO@123"));

Output:

true
false
false

Understanding the Password Pattern

Part Meaning
^ Beginning of input.
(?=.*[A-Z]) Requires at least one uppercase letter.
(?=.*[a-z]) Requires at least one lowercase letter.
(?=.*\d) Requires at least one digit.
(?=.*[^A-Za-z0-9]) Requires at least one non-ASCII-alphanumeric character.
.{8,} Requires at least eight characters, excluding line terminators by default.
$ End of input.
Placement Tip: The (?=...) syntax is called a positive lookahead. It checks whether a condition exists ahead without consuming characters. Lookaheads are frequently used in password validation.

12. Practical Example: Live Regex Validation

The following example validates a username, email and password as the user types.

Complete HTML and JavaScript Code

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Regex Form Validation</title>

    <style>
        body {
            font-family: Arial, sans-serif;
        }

        form {
            max-width: 400px;
            display: grid;
            gap: 10px;
        }

        input {
            padding: 10px;
        }

        .error {
            color: red;
        }

        .success {
            color: green;
        }
    </style>
</head>

<body>

    <h2>Registration Form</h2>

    <form id="form" novalidate>

        <label for="username">Username</label>
        <input type="text" id="username">
        <small id="usernameMessage"></small>

        <label for="email">Email</label>
        <input type="text" id="email">
        <small id="emailMessage"></small>

        <label for="password">Password</label>
        <input type="password" id="password">
        <small id="passwordMessage"></small>

        <button type="submit">Register</button>

    </form>

    <p id="result"></p>

    <script>
    const form = document.getElementById("form");

    const username = document.getElementById("username");
    const email = document.getElementById("email");
    const password = document.getElementById("password");

    const usernameMessage =
        document.getElementById("usernameMessage");

    const emailMessage =
        document.getElementById("emailMessage");

    const passwordMessage =
        document.getElementById("passwordMessage");

    const result = document.getElementById("result");

    const usernamePattern = /^[A-Za-z0-9_]{5,15}$/;

    const emailPattern =
        /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

    const passwordPattern =
        /^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}$/;

    function validateField(input, pattern, messageElement, message) {

        if (!pattern.test(input.value)) {

            messageElement.textContent = message;
            messageElement.className = "error";

            return false;
        }

        messageElement.textContent = "Valid input.";
        messageElement.className = "success";

        return true;
    }

    username.addEventListener("input", function() {

        validateField(
            username,
            usernamePattern,
            usernameMessage,
            "Use 5-15 letters, digits or underscores."
        );

    });

    email.addEventListener("input", function() {

        validateField(
            email,
            emailPattern,
            emailMessage,
            "Enter a valid email format."
        );

    });

    password.addEventListener("input", function() {

        validateField(
            password,
            passwordPattern,
            passwordMessage,
            "Use 8+ characters with uppercase, lowercase, digit and special character."
        );

    });

    form.addEventListener("submit", function(event) {

        event.preventDefault();

        const isUsernameValid = validateField(
            username,
            usernamePattern,
            usernameMessage,
            "Invalid username."
        );

        const isEmailValid = validateField(
            email,
            emailPattern,
            emailMessage,
            "Invalid email."
        );

        const isPasswordValid = validateField(
            password,
            passwordPattern,
            passwordMessage,
            "Invalid password."
        );

        if (
            isUsernameValid &&
            isEmailValid &&
            isPasswordValid
        ) {
            result.textContent =
                "All fields passed client-side validation.";
            result.className = "success";
        } else {
            result.textContent =
                "Please correct the errors.";
            result.className = "error";
        }

    });
    </script>

</body>
</html>

Expected Behavior

  • Username must contain 5–15 allowed characters.
  • Email must satisfy the basic email format pattern.
  • Password must satisfy all five password requirements.
  • Feedback updates while the user types.
  • Submission is accepted only when all three patterns match.
This is a client-side demonstration. A production application must validate all submitted data on the server as well.

13. Common Regex Mistakes

Mistake Correct Approach
Forgetting ^ and $. Use anchors when the complete input must match.
Using * when at least one character is required. Use + for one or more occurrences.
Using \w as a complete international letter matcher. Use Unicode property escapes where appropriate.
Forgetting to escape special characters. Use a backslash for literal special characters, such as \.
Assuming an email regex proves an account exists. Use a verification process to confirm ownership.
Using overly complicated patterns. Keep validation rules readable and maintainable.
Using a global regex repeatedly with test(). Be aware that global regexes maintain lastIndex.

Important: Global Regex and test()

const pattern = /hello/g;

console.log(pattern.test("hello"));
console.log(pattern.test("hello"));
console.log(pattern.test("hello"));

Expected Output:

true
false
true

The global flag causes test() to update the regex lastIndex property. Repeated calls can therefore produce different results.

For simple validation, avoid the global flag unless it is specifically required.

14. Placement Interview Questions and Answers

Q1. What is a regular expression?

A regular expression is a pattern used to search, match, extract or validate strings.

Q2. What is the difference between a regex literal and RegExp constructor?

A literal uses slash delimiters, while the RegExp constructor creates a regex from a string and supports dynamically generated patterns.

Q3. What is the difference between * and +?

The * quantifier matches zero or more occurrences. The + quantifier matches one or more occurrences.

Q4. What is the purpose of ^ and $?

They are anchors that match the beginning and end of the input or line, depending on regex flags.

Q5. What is a character class?

A character class defines a set or range of characters that can match at a particular position.

Q6. What is a capturing group?

A capturing group uses parentheses to group a pattern and store the matched substring for later access.

Q7. What is a positive lookahead?

It checks whether a pattern exists ahead without consuming characters. It is commonly used for password rules.

Q8. What is the difference between test() and exec()?

test() returns a Boolean. exec() returns detailed match information or null.

Q9. What is the difference between match() and matchAll()?

match() returns matching results according to the regex flags. matchAll() returns an iterator containing detailed information for every match and requires a global regex.

Q10. What is the purpose of the i flag?

It performs case-insensitive matching.

Q11. What is the purpose of the g flag?

It enables global matching, allowing multiple matches rather than stopping at the first match.

Q12. Why should regex validation use anchors?

Anchors ensure that the complete input satisfies the pattern instead of allowing only a substring to match.

Q13. Can regex completely validate an email address?

A simple regex can check a practical email format, but complete email validation is more complex. Ownership must be verified separately.

Q14. What is lastIndex in JavaScript regex?

It is a property that tracks the position for the next match when using global or sticky regular expressions.
