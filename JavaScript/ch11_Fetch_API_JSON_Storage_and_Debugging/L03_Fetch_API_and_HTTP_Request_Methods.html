Fetch API and HTTP Request Methods

JavaScript Course | Chapter 11: Fetch API, JSON, Storage and Debugging

Lesson 3

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand the Fetch API and browser-based API communication.
  • Send HTTP GET, POST, PUT, PATCH and DELETE requests.
  • Configure requests using the Fetch options object.
  • Send JSON data using request headers and JSON.stringify().
  • Read server responses using json(), text() and blob().
  • Construct URLs with query parameters using URLSearchParams.
  • Understand Promise-based request handling and request cancellation.
  • Recognize common Fetch API mistakes and browser CORS restrictions.

2. What Is the Fetch API?

The Fetch API is a modern JavaScript browser API used to make HTTP requests and communicate with servers. It allows a frontend application to retrieve data from an API and send data to a backend without reloading the entire webpage.

Common applications include:

  • Loading user profiles from a backend.
  • Retrieving product information from an e-commerce API.
  • Submitting registration and login forms.
  • Updating user information.
  • Deleting records from a database through a backend API.
  • Building dynamic dashboards and search interfaces.

Basic Syntax

fetch(url)
    .then(response => {
        // Process the response
    })
    .catch(error => {
        // Handle network-level errors
    });

The Fetch API returns a Promise.

  • The Promise fulfills with a Response object when an HTTP response is received.
  • The response body can then be read using methods such as response.json().
  • The Promise rejects for network-level failures, request errors such as an abort, and similar failures.
Important: An HTTP 404 or 500 response does not automatically reject the Fetch Promise. You must inspect response.ok or response.status. This is covered in detail in Lesson 4.

3. Understanding the Request-Response Cycle

A typical Fetch API request follows this sequence:

  1. JavaScript creates an HTTP request.
  2. The browser sends the request to the API server.
  3. The server processes the request.
  4. The server sends an HTTP response.
  5. Fetch provides a Response object.
  6. JavaScript reads and processes the response body.
  7. The application displays or uses the returned data.
Frontend JavaScript
        |
        | fetch("https://api.example.com/users")
        v
    HTTP Request
        |
        v
     API Server
        |
        | Processes request
        v
    HTTP Response
        |
        v
    Response Object
        |
        | response.json()
        v
    JavaScript Data
        |
        v
    Application UI
Practical understanding: Fetch handles HTTP communication. Your JavaScript application handles the returned data and decides how to display or use it.

4. The Fetch API Options Object

The first argument specifies the request URL. The optional second argument specifies request configuration. 

fetch(url, options);

Example:

fetch("https://api.example.com/users", {
    method: "GET",
    headers: {
        "Accept": "application/json"
    }
});

Common Fetch Options

Option Purpose
method Specifies the HTTP method, such as GET or POST.
headers Specifies HTTP request headers.
body Contains request data, commonly JSON.
mode Controls request mode, such as cors or same-origin.
credentials Controls whether cookies and other credentials are included.
signal Connects an AbortController to cancel a request.
cache Controls browser HTTP cache behavior.

Request Headers

Headers provide additional information about an HTTP request.

Header Meaning
Content-Type Describes the format of the request body.
Accept Indicates the response media types the client can accept.
Authorization Can carry authentication credentials or tokens. 
headers: {
    "Content-Type": "application/json",
    "Accept": "application/json"
}
Remember: When sending JSON in a request body, use Content-Type: application/json. The Accept header describes the response format you prefer.

5. HTTP Request Methods

HTTP methods describe the operation a client wants a server to perform on a resource.

Method Purpose Typical Usage
GET Retrieve data. Get users or products.
POST Submit data, commonly to create a resource. Create a new user.
PUT Replace a resource representation. Update a complete user record.
PATCH Apply a partial update. Change only a user's email.
DELETE Request deletion of a resource. Delete a user record.

Important Differences

  • GET is used to retrieve resources and should not have a request body.
  • POST commonly creates a resource or submits data for processing.
  • PUT conventionally replaces the target resource representation.
  • PATCH applies partial changes to a resource.
  • DELETE requests removal of a resource.
The exact behavior of PUT, PATCH and DELETE depends on the backend API contract. Do not assume every server implements them identically.

6. GET Request Using Fetch

GET retrieves information from an API. It is one of the most frequently used methods in frontend development.

Example: Retrieve Users

fetch("https://jsonplaceholder.typicode.com/users")
    .then(response => response.json())
    .then(users => {
        console.log(users);
        console.log(users[0].name);
        console.log(users[0].email);
    })
    .catch(error => {
        console.error("Request failed:", error);
    });

Explanation

  1. fetch() sends a GET request by default.
  2. The first then() receives the Response object.
  3. response.json() reads and parses the JSON response body.
  4. The next then() receives the parsed JavaScript data.
  5. catch() handles rejected Promises.
Illustrative output: 
[
    {
        id: 1,
        name: "Leanne Graham",
        username: "Bret",
        email: "Sincere@example.com"
    },
    ...
]

Leanne Graham
Sincere@example.com

The exact response is supplied by the demo API. The example assumes the request succeeds and returns the expected data.

7. POST Request Using Fetch

POST is commonly used to send new information to a backend, such as submitting a registration form.

Example: Create a User

const newUser = {
    name: "Navdeep",
    username: "navdeep123",
    email: "navdeep@example.com"
};

fetch("https://jsonplaceholder.typicode.com/users", {
    method: "POST",

    headers: {
        "Content-Type": "application/json",
        "Accept": "application/json"
    },

    body: JSON.stringify(newUser)
})
.then(response => response.json())
.then(data => {
    console.log("Created user:", data);
})
.catch(error => {
    console.error("Error:", error);
});

Important Concepts

  • method: "POST" selects the POST method.
  • headers specifies the JSON media type.
  • JSON.stringify() converts a JavaScript object into a JSON string.
  • body contains the serialized request data.
Illustrative response: 
{
    name: "Navdeep",
    username: "navdeep123",
    email: "navdeep@example.com",
    id: 11
}
JSONPlaceholder is a demonstration API. It simulates write operations and does not permanently save the submitted record to a real user database.

8. PUT Request Using Fetch

PUT conventionally replaces the target resource representation. A backend may require the complete set of fields expected for that resource.

Example: Update a Post

const updatedPost = {
    id: 1,
    title: "Updated JavaScript Guide",
    body: "Learning Fetch API with practical examples",
    userId: 1
};

fetch("https://jsonplaceholder.typicode.com/posts/1", {
    method: "PUT",

    headers: {
        "Content-Type": "application/json"
    },

    body: JSON.stringify(updatedPost)
})
.then(response => response.json())
.then(data => {
    console.log("Updated post:", data);
})
.catch(error => {
    console.error("Error:", error);
});
Illustrative response: 
{
    id: 1,
    title: "Updated JavaScript Guide",
    body: "Learning Fetch API with practical examples",
    userId: 1
}

9. PATCH Request Using Fetch

PATCH is used when only selected fields of an existing resource need to be changed.

Example: Update Only the Post Title

const changes = {
    title: "Updated Title Only"
};

fetch("https://jsonplaceholder.typicode.com/posts/1", {
    method: "PATCH",

    headers: {
        "Content-Type": "application/json"
    },

    body: JSON.stringify(changes)
})
.then(response => response.json())
.then(data => {
    console.log("Partially updated:", data);
})
.catch(error => {
    console.error("Error:", error);
});
PUT vs PATCH: PUT conventionally replaces a resource representation, while PATCH applies partial modifications. The server defines the actual update behavior.

10. DELETE Request Using Fetch

DELETE requests the removal of a resource identified by its URL.

Example: Delete a Post

fetch("https://jsonplaceholder.typicode.com/posts/1", {
    method: "DELETE"
})
.then(response => {
    console.log("HTTP Status:", response.status);
    console.log("Delete request completed.");
})
.catch(error => {
    console.error("Error:", error);
});
Possible response: 
HTTP Status: 200
Delete request completed.
Some APIs return HTTP 204 No Content for a successful DELETE. Such a response has no body, so do not automatically call response.json() on every DELETE response.

11. Reading Different Response Formats

The Response object provides methods to read the response body. These methods return Promises.

Method Purpose
response.json() Reads and parses a JSON response into JavaScript data.
response.text() Reads the response body as text.
response.blob() Reads the response body as a Blob, useful for files and images.
response.arrayBuffer() Reads the response body as binary data.

Example: Read Text Response

fetch("https://example.com")
    .then(response => response.text())
    .then(html => {
        console.log(html);
    })
    .catch(error => {
        console.error(error);
    });

Example: Read an Image as Blob

fetch("https://example.com/image.png")
    .then(response => response.blob())
    .then(imageBlob => {
        const imageURL = URL.createObjectURL(imageBlob);

        const image = document.createElement("img");
        image.src = imageURL;
        image.alt = "Downloaded image";

        document.body.appendChild(image);
    })
    .catch(error => {
        console.error("Image request failed:", error);
    });
Important: A response body is generally consumable only once. Calling response.json() and then response.text() on the same response will normally fail because the body has already been consumed.

12. URL Parameters Using URLSearchParams

Many APIs accept query parameters for searching, filtering, sorting and pagination.

Example URL:

https://api.example.com/products?category=electronics&page=2

JavaScript provides URLSearchParams to construct and encode query parameters safely.

Example

const params = new URLSearchParams({
    userId: "1",
    _limit: "5"
});

const url =
    `https://jsonplaceholder.typicode.com/posts?${params}`;

console.log(url);

fetch(url)
    .then(response => response.json())
    .then(posts => {
        console.log(posts);
    })
    .catch(error => {
        console.error(error);
    });
Generated URL: 
https://jsonplaceholder.typicode.com/posts?userId=1&_limit=5

Useful URLSearchParams Methods

Method Purpose
append() Adds another parameter value.
set() Sets a parameter, replacing existing values for that key.
get() Returns the first value for a parameter.
has() Checks whether a parameter exists.
delete() Removes a parameter.
toString() Returns the encoded query string.

13. Promise Chaining with Fetch

Fetch is Promise-based. You can use then() to process fulfilled Promises and catch() to handle rejected Promises. 

fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => {
        return response.json();
    })
    .then(user => {
        console.log("Name:", user.name);
        console.log("Email:", user.email);
    })
    .catch(error => {
        console.error("Request failed:", error);
    });

How Promise Chaining Works

  1. fetch() returns a Promise for the HTTP response.
  2. The first then() receives the Response object.
  3. response.json() returns another Promise.
  4. The next then() receives the parsed data.
  5. catch() handles rejected Promises in the chain.
The next lesson focuses on handling HTTP status codes, response validation and errors correctly. The following lesson covers async/await and rendering fetched data in the DOM.

14. Cancelling Requests with AbortController

Sometimes a request should be cancelled, for example when a user changes a search query before the previous request has finished.

The AbortController API provides a way to cancel a Fetch request.

Example

const controller = new AbortController();

fetch("https://jsonplaceholder.typicode.com/posts", {
    signal: controller.signal
})
.then(response => response.json())
.then(posts => {
    console.log(posts);
})
.catch(error => {
    if (error.name === "AbortError") {
        console.log("Request was cancelled.");
    } else {
        console.error("Request failed:", error);
    }
});

// Cancel the request
controller.abort();

Important Points

  • Create an AbortController for the request.
  • Pass its signal through the Fetch options.
  • Call abort() to cancel the request.
  • An aborted Fetch Promise rejects with an AbortError.
In a real application, calling abort() immediately after starting a request may cancel it before the response arrives. The example demonstrates the API rather than guaranteeing a particular network result.

15. CORS and Same-Origin Policy

Browsers apply the Same-Origin Policy to restrict how scripts from one origin access resources from another origin.

An origin consists of the scheme, hostname and port. If these differ, the origins are different.

Example

URL Origin comparison
https://example.com/page1 Same origin as the next URL.
https://example.com/api Same scheme, host and port.
http://example.com/api Different scheme.
https://api.example.com Different hostname.

What Is CORS?

Cross-Origin Resource Sharing (CORS) is a browser-enforced mechanism that allows a server to specify which cross-origin requests may access its responses.

  • The browser sends a cross-origin request.
  • The server provides appropriate CORS response headers.
  • The browser checks whether access is allowed.
  • If the required permission is missing, JavaScript cannot read the response.
Important interview point: mode: "no-cors" is not a general CORS workaround. It produces an opaque response for cross-origin requests, which prevents JavaScript from reading the response body and most response details.

CORS must be configured correctly on the server. A frontend developer should verify the API's allowed origins and response headers when debugging cross-origin failures.

16. Fetch API vs XMLHttpRequest

XMLHttpRequest (XHR) is an older browser API for making HTTP requests. Fetch provides a more modern Promise-based interface.

Feature Fetch API XMLHttpRequest
Programming style Promise-based Event and callback-based
Syntax Generally simpler More verbose
Response handling Response object methods Response properties and events
Cancellation AbortController xhr.abort()
Progress events No equivalent built-in upload/download progress event interface Supports progress events

Fetch is commonly preferred for modern frontend API requests. XMLHttpRequest remains useful in applications that require its progress-event capabilities or existing XHR integrations.

17. Important Fetch API Rules

  • Fetch uses GET by default.
  • Use method to specify another HTTP method.
  • Use JSON.stringify() when sending a JavaScript object as JSON.
  • Use Content-Type: application/json for a JSON request body.
  • GET and HEAD requests should not include request bodies.
  • response.json() returns a Promise.
  • Response body methods generally consume the body once.
  • Fetch does not reject just because the server returns 404 or 500.
  • Use AbortController when a request needs cancellation.
  • CORS permission must be provided by the server.

18. Common Mistakes and Debugging

Mistake 1: Forgetting JSON.stringify()

// Incorrect
body: {
    name: "Navdeep"
}

// Correct
body: JSON.stringify({
    name: "Navdeep"
})

A JSON request body must be serialized into a string. The object itself is not a valid JSON request body.

Mistake 2: Missing Content-Type

// Recommended when sending JSON
headers: {
    "Content-Type": "application/json"
}

Without the correct content type, the backend may not interpret the request body as JSON.

Mistake 3: Assuming response.json() Is Immediate

// Incorrect
const data = response.json();
console.log(data.name);

// Correct
response.json().then(data => {
    console.log(data.name);
});

response.json() returns a Promise. The parsed data becomes available after that Promise fulfills.

Mistake 4: Assuming HTTP Errors Automatically Enter catch()

// This does not automatically reject on HTTP 404
fetch("/api/users/999")
    .then(response => response.json())
    .catch(error => console.error(error));

Check the HTTP status and response.ok explicitly. Lesson 4 covers the correct pattern.

Mistake 5: Parsing an Empty Response as JSON

// Avoid unconditional JSON parsing
fetch("/api/users/1", {
    method: "DELETE"
})
.then(response => {
    if (response.status === 204) {
        console.log("No response body.");
        return;
    }

    return response.json();
});

Some successful requests return no response body. Check the API's response contract before parsing.

Debugging Checklist

  1. Open Chrome Developer Tools using F12.
  2. Select the Network tab.
  3. Trigger the Fetch request.
  4. Find the request in the Network list.
  5. Inspect the request URL, method and headers.
  6. Inspect the request payload and response.
  7. Check the HTTP status code.
  8. Check the Console for JavaScript errors.

19. Placement Interview Questions and Answers

Q1. What is the Fetch API?

Answer: Fetch is a browser API used to make HTTP requests and communicate with servers. It returns a Promise that fulfills with a Response object when an HTTP response is received.

Q2. What does fetch() return?

Answer: It returns a Promise that fulfills with a Response object or rejects when a network-level failure or another request-level failure occurs.

Q3. Which HTTP method does Fetch use by default?

Answer: GET.

Q4. What is the difference between GET and POST?

Answer: GET retrieves a resource, whereas POST submits data to a server and commonly creates a resource.

Q5. What is the difference between PUT and PATCH?

Answer: PUT conventionally replaces a resource representation, while PATCH applies partial modifications.

Q6. Why is JSON.stringify() used in Fetch?

Answer: It converts a JavaScript value, commonly an object, into a JSON string suitable for transmission in an HTTP request body.

Q7. What is the purpose of response.json()?

Answer: It reads the response body and parses the JSON data into a JavaScript value. It returns a Promise.

Q8. What is the purpose of the Content-Type header?

Answer: It identifies the media type of the request body. For JSON data, use application/json.

Q9. What is the difference between Accept and Content-Type?

Answer: Accept describes the response formats the client can handle. Content-Type describes the media type of the message body being sent.

Q10. Does Fetch reject for HTTP 404?

Answer: No. Fetch normally fulfills with a Response object for HTTP error statuses. The developer must inspect response.ok or response.status.

Q11. What is CORS?

Answer: Cross-Origin Resource Sharing is a browser-enforced mechanism that uses server-provided headers to control access to cross-origin responses.

Q12. How can a Fetch request be cancelled?

Answer: Use AbortController, pass its signal in the Fetch options, and call controller.abort().

Q13. Can response.json() and response.text() be called one after another?

Answer: Not normally on the same response body. Reading methods consume the body, so it cannot generally be consumed twice.

Q14. What is URLSearchParams used for?

Answer: It helps create, read, update, delete and encode URL query parameters.

Q15. What is the difference between Fetch and XMLHttpRequest?

Answer: Fetch is Promise-based and has a modern interface. XMLHttpRequest uses events and callbacks and provides built-in progress events.

21. Practical Coding Exercises

  1. Fetch Users: Retrieve all users from https://jsonplaceholder.typicode.com/users and print their names and email addresses.
  2. Fetch a Single User: Retrieve user with ID 1 and print the name, username and email.
  3. Create a Post: Send a POST request to https://jsonplaceholder.typicode.com/posts with title, body and userId.
  4. Update a Post: Use PUT to update the title, body and userId of post 1.
  5. Partial Update: Use PATCH to change only the title of post 1.
  6. Delete a Post: Send a DELETE request for post 1 and inspect the response status.
  7. Search with Query Parameters: Use URLSearchParams to retrieve posts belonging to userId 2.
  8. Cancel a Request: Create an AbortController, pass its signal to Fetch and cancel the request.
  9. Read a Text Response: Retrieve a text-based resource using response.text().
  10. Compare HTTP Methods: Write separate Fetch requests demonstrating GET, POST, PUT, PATCH and DELETE.
Practice environment: Use Chrome Developer Tools or a local HTML file with an external JavaScript file. The demonstration API requires an internet connection. JSONPlaceholder simulates write operations rather than permanently storing your changes.

22. Lesson Summary

  • Fetch API is used for browser-based HTTP communication.
  • Fetch returns a Promise.
  • GET retrieves data; POST commonly creates or submits data.
  • PUT conventionally replaces a resource representation.
  • PATCH applies partial updates.
  • DELETE requests resource deletion.
  • Request options configure methods, headers, body and other behavior.
  • JSON.stringify() serializes JavaScript data for JSON requests.
  • response.json(), response.text() and response.blob() read response bodies.
  • URLSearchParams simplifies query-string construction.
  • AbortController cancels requests.
  • CORS controls browser access to cross-origin responses.
  • HTTP error statuses must be checked explicitly.

You should now be able to make practical API requests from JavaScript using different HTTP methods and understand how to configure and read their responses.
