2. What Is Debugging?

Debugging is the systematic process of finding, analyzing and correcting errors in a program.

During development, JavaScript code may not work as expected because of incorrect syntax, invalid operations, unexpected data or incorrect program logic.

Why Is Debugging Important?

  • Identifies the cause of application failures.
  • Improves code reliability.
  • Helps locate incorrect calculations and logic.
  • Detects API and network problems.
  • Improves application performance.
  • Helps developers understand unfamiliar code.
  • Reduces production defects.

Example: A Program with an Error

const price = 100;
const quantity = 5;

const total = price + quantity;

console.log(total);
Actual output: 105

The intended operation is multiplication, but the code uses addition.

Corrected Code

const price = 100;
const quantity = 5;

const total = price * quantity;

console.log(total);
Correct output: 500

This is a logical error: the program runs without a JavaScript exception, but produces an incorrect result.

3. Types of JavaScript Errors

JavaScript applications commonly encounter syntax errors, runtime errors and logical errors.

3.1 Syntax Errors

Syntax errors occur when JavaScript code does not follow the language's grammatical rules. 

// Missing closing parenthesis

console.log("Hello World";

The JavaScript engine cannot parse this statement correctly.

Correct code:

console.log("Hello World");

3.2 Runtime Errors

Runtime errors occur while JavaScript code is executing. 

const user = null;

console.log(user.name);

Accessing a property of null causes a TypeError.

Typical error: TypeError: Cannot read properties of null

Correct approach:

const user = null;

if (user !== null) {
    console.log(user.name);
} else {
    console.log("User not available");
}

3.3 Logical Errors

Logical errors occur when the program executes successfully but produces incorrect results. 

const marks = 80;

if (marks > 90) {
    console.log("Pass");
} else {
    console.log("Fail");
}

If the passing requirement is 40, the condition is incorrect.

Correct code:

const marks = 80;

if (marks >= 40) {
    console.log("Pass");
} else {
    console.log("Fail");
}
Output: Pass

Error Comparison

Error Type Meaning Example
Syntax Error Invalid JavaScript syntax. Missing bracket or invalid declaration.
Runtime Error Failure during execution. Accessing a property on null.
Logical Error Program executes but produces incorrect results. Using addition instead of multiplication.

6. Debugging with Breakpoints

A breakpoint pauses JavaScript execution at a selected line. Developers can inspect variables and understand the program's execution flow.

Example Program

function calculateTotal(price, quantity) {

    const subtotal = price * quantity;

    const tax = subtotal * 0.18;

    const total = subtotal + tax;

    return total;
}

const result = calculateTotal(1000, 2);

console.log(result);

How to Set a Breakpoint in Chrome

  1. Open the webpage in Chrome.
  2. Press F12 to open Developer Tools.
  3. Select the Sources panel.
  4. Open the JavaScript source file.
  5. Click the line number where execution should pause.
  6. Trigger the function or reload the page.
  7. Inspect variables and the call stack.

Important Debugging Controls

Control Purpose
Resume Continue execution until the next breakpoint or pause.
Step Over Execute the current line without entering called functions.
Step Into Enter a function call to inspect its execution.
Step Out Finish the current function and return to its caller.
Restart Frame Restart the selected stack frame where supported.
Deactivate Breakpoints Temporarily disable breakpoints.

7. The debugger Statement

The debugger statement can pause execution when Developer Tools are open and debugging is enabled.

Example

function calculate(a, b) {

    debugger;

    const result = a + b;

    return result;
}

console.log(calculate(10, 20));

When execution reaches debugger, the browser pauses and allows inspection of local variables.

Remove debugger statements before production deployment unless they are intentionally required for development tooling.

8. Understanding the Call Stack

The call stack tracks function calls during JavaScript execution. It follows the Last In, First Out (LIFO) principle.

Example

function first() {
    second();
}

function second() {
    third();
}

function third() {
    console.log("Inside third");
}

first();

When first() calls second(), and second() calls third(), each function is added to the call stack.

Conceptual Call Stack

During execution of third():

| third()  |  <-- Top
| second() |
| first()  |
| global   |
------------

After third() finishes, it is removed from the stack. Execution returns to second(), then first().

Stack Overflow Example

function repeat() {
    repeat();
}

repeat();

This function calls itself indefinitely without a termination condition.

Typical error: RangeError: Maximum call stack size exceeded

Correct approach:

function repeat(count) {

    if (count === 0) {
        return;
    }

    console.log(count);

    repeat(count - 1);
}

repeat(5);
Output: 
5
4
3
2
1

9. The try, catch and finally Statements

JavaScript provides try, catch and finally for handling exceptions.

try Block

Contains code that may produce an exception.

catch Block

Handles an exception thrown from the associated try block.

finally Block

Executes after the try/catch processing, whether an exception occurred or not, subject to normal control-flow completion.

Basic Syntax

try {

    // Code that may throw an error

} catch (error) {

    // Handle the error

} finally {

    // Cleanup or final operation

}

Example Without an Error

try {

    console.log("Inside try");

} catch (error) {

    console.log("Error occurred");

} finally {

    console.log("Finally executed");

}
Output: 
Inside try
Finally executed

Example With an Error

try {

    const result = 10 / 0;

    console.log(result);

    throw new Error("Something went wrong");

} catch (error) {

    console.log("Error:", error.message);

} finally {

    console.log("Execution completed");

}
Output: 
Infinity
Error: Something went wrong
Execution completed
Division of a JavaScript number by zero produces Infinity; it does not automatically throw an exception. The example explicitly throws an Error afterward.

10. Throwing Custom Errors

The throw statement allows developers to generate exceptions when application-specific conditions are not satisfied.

Example: Age Validation

function validateAge(age) {

    if (age < 18) {

        throw new Error(
            "Age must be at least 18"
        );
    }

    return "Access granted";
}

try {

    console.log(validateAge(16));

} catch (error) {

    console.log(error.message);
}
Output: Age must be at least 18

Example: Custom Error Class

class ValidationError extends Error {

    constructor(message) {
        super(message);
        this.name = "ValidationError";
    }
}

function validateUsername(username) {

    if (!username || username.length < 3) {

        throw new ValidationError(
            "Username must contain at least 3 characters"
        );
    }

    return true;
}

try {

    validateUsername("AB");

} catch (error) {

    console.log(error.name);

    console.log(error.message);
}
Output: 
ValidationError
Username must contain at least 3 characters

Common Built-in Error Types

Error Meaning
SyntaxError Invalid JavaScript syntax or invalid parsing input.
ReferenceError Invalid access to an unresolved identifier.
TypeError An operation is incompatible with a value's type.
RangeError A value is outside an allowed range.
URIError Incorrect use of URI encoding or decoding functions.
EvalError Historically associated with eval-related errors; rarely encountered in modern code.

12. Error Handling in Asynchronous JavaScript

Errors in asynchronous operations must be handled according to the mechanism used to perform the operation.

12.1 Handling Errors with Promises

const promise = new Promise((resolve, reject) => {

    reject(new Error("Request failed"));

});

promise
    .then(result => {
        console.log(result);
    })
    .catch(error => {
        console.error(error.message);
    });
Output: Request failed

12.2 Handling Errors with async/await

function getData() {

    return Promise.reject(
        new Error("Unable to load data")
    );
}

async function loadData() {

    try {

        const result = await getData();

        console.log(result);

    } catch (error) {

        console.error(error.message);

    }
}

loadData();
Output: Unable to load data

12.3 Handling Fetch Errors

Fetch rejects its Promise for certain network-level failures, but HTTP error responses such as 404 or 500 normally still resolve to a Response object. 

async function loadUser() {

    try {

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users/1"
        );

        if (!response.ok) {

            throw new Error(
                `HTTP Error: ${response.status}`
            );
        }

        const user = await response.json();

        console.log(user);

    } catch (error) {

        console.error(
            "Unable to load user:",
            error.message
        );
    }
}

loadUser();

This example checks the HTTP response status before processing the JSON response.

Do not assume that fetch() automatically rejects for every unsuccessful HTTP status. Always check response.ok or response.status when appropriate.

13. Handling Errors in Event Listeners

Exceptions thrown inside an event listener are reported by the browser. A try/catch inside the listener can handle expected failures locally.

Example

const button = document.getElementById("submitButton");

button.addEventListener("click", () => {

    try {

        const age = Number(
            document.getElementById("age").value
        );

        if (!Number.isFinite(age) || age <= 0) {
            throw new Error("Enter a valid age");
        }

        console.log("Age:", age);

    } catch (error) {

        console.error(error.message);
    }
});

This pattern is useful for validating user input and handling application-specific operations.

14. Debugging the DOM

Many frontend problems occur because JavaScript selects the wrong HTML element or executes before the element exists.

Example: Missing Element

const button =
    document.getElementById("submitBtn");

button.addEventListener("click", () => {
    console.log("Clicked");
});

If no element with id="submitBtn" exists, button will be null and calling addEventListener() will cause a TypeError.

Debugging Approach

const button =
    document.getElementById("submitBtn");

console.log("Selected element:", button);

if (button) {

    button.addEventListener("click", () => {
        console.log("Clicked");
    });

} else {

    console.error("Button element not found");
}

Another Solution: DOMContentLoaded

document.addEventListener(
    "DOMContentLoaded",
    () => {

        const button =
            document.getElementById("submitBtn");

        button.addEventListener("click", () => {
            console.log("Clicked");
        });

    }
);

DOMContentLoaded fires after the HTML document has been parsed and the DOM has been constructed.

16. Debugging Performance Problems

A JavaScript application may work correctly but still feel slow. Performance debugging helps identify expensive operations.

Common Causes of Poor Performance

  • Unnecessary DOM updates.
  • Large synchronous JavaScript operations.
  • Repeated expensive calculations.
  • Unoptimized images and resources.
  • Memory leaks.
  • Excessive event listeners.
  • Long-running JavaScript tasks.

Using the Performance Panel

  1. Open Developer Tools.
  2. Select Performance.
  3. Start recording.
  4. Perform the slow operation.
  5. Stop recording.
  6. Inspect the recorded activity.
  7. Look for long tasks and expensive functions.

Measuring a Function

function calculateSum() {

    let sum = 0;

    for (let i = 0; i < 1000000; i++) {
        sum += i;
    }

    return sum;
}

console.time("Calculation");

const result = calculateSum();

console.timeEnd("Calculation");

console.log(result);

The Console reports the execution duration and calculated sum.

Expected sum: 499999500000

18. Error Handling Best Practices

  1. Handle expected failures: Validate input and check network responses.
  2. Use meaningful error messages: Explain what went wrong without exposing sensitive internal details.
  3. Avoid empty catch blocks: Do not silently ignore errors.
  4. Use specific error types: Create custom error classes when they improve error identification and handling.
  5. Handle asynchronous failures: Use catch() or try/catch with await.
  6. Clean up resources: Use finally for operations such as releasing locks or resetting loading indicators.
  7. Do not expose sensitive information: Avoid displaying internal stack traces or confidential data to end users.
  8. Remove debugging code: Remove temporary logs and debugger statements when preparing production builds.
  9. Use structured logging: Include useful context when reporting failures.
  10. Test failure scenarios: Test invalid input, unavailable APIs, timeouts and unexpected responses.

This project uses Fetch and async/await to load user information and handle network or HTTP errors.

<!DOCTYPE html>
<html lang="en">
<head>

<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">

    font-family: Arial, sans-serif;
    margin: 30px;

    padding: 10px 18px;
    cursor: pointer;
}

#status {
    margin: 15px 0;

#users {
    padding: 0;
}

#users li {
    list-style: none;
    padding: 12px;
    margin: 8px 0;
    background: #edf2f7;
}

.error {
    color: red;
}

.success {
    color: green;
}

</style>

</head>

<body>

<h1>API Debugging Dashboard</h1>

<button id="loadButton">Load Users</button>

<p id="status"></p>

<ul id="users"></ul>

<script>

const loadButton =
    document.getElementById("loadButton");

const statusMessage =
    document.getElementById("status");

const usersList =
    document.getElementById("users");

async function loadUsers() {

    statusMessage.textContent = "Loading users...";

    statusMessage.className = "";

    usersList.replaceChildren();

    loadButton.disabled = true;

    try {

        console.log("Starting API request");

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users"
        );

        console.log("HTTP Status:", response.status);

        if (!response.ok) {

            throw new Error(
                `HTTP Error: ${response.status}`
            );
        }

        const users = await response.json();

        console.table(users);

        if (!Array.isArray(users) || users.length === 0) {

            statusMessage.textContent =
                "No users available";

            return;
        }

        users.forEach(user => {

            const li = document.createElement("li");

            li.textContent =
                `${user.name} - ${user.email}`;

            usersList.append(li);

        });

        statusMessage.textContent =
            "Users loaded successfully";

        statusMessage.className = "success";

    } catch (error) {

        console.error("API request failed:", error);

        statusMessage.textContent =
            `Unable to load users: ${error.message}`;

        statusMessage.className = "error";

    } finally {

        loadButton.disabled = false;

        console.log("API request completed");

    }
}

loadButton.addEventListener("click", loadUsers);

</script>

</body>
</html>

Expected Behavior

  1. Click Load Users.
  2. The page displays a loading message.
  3. The application sends a GET request.
  4. Successful responses are displayed as a user list.
  5. HTTP or network failures are displayed as errors.
  6. The button is enabled again after processing.
  7. Console displays request and response debugging information.
This project uses a public demonstration API. Network availability and external service behavior can vary. If the request fails, inspect the Network and Console panels.

21. Systematic Debugging Workflow

Professional developers follow a structured process instead of randomly changing code.

  1. Reproduce the problem: Identify the exact steps that cause the failure.
  2. Read the error message: Check the error type, message and stack trace.
  3. Identify the affected code: Find the relevant source file and line.
  4. Inspect variable values: Use Console logs or breakpoints.
  5. Check data flow: Verify input, intermediate values and output.
  6. Inspect external dependencies: Check API requests, storage and DOM elements.
  7. Find the root cause: Determine why the failure occurs.
  8. Apply the correction: Fix the actual cause instead of hiding the symptom.
  9. Retest: Verify normal and failure scenarios.
  10. Remove temporary debugging code: Clean up logs and breakpoints where appropriate.

22. Placement Interview Questions and Answers

Q1. What is debugging?

Answer: Debugging is the process of identifying, analyzing and correcting software errors.

Q2. What are the three common types of errors?

Answer: Syntax errors, runtime errors and logical errors.

Q3. What is a syntax error?

Answer: An error caused by JavaScript code that violates language syntax rules.

Q4. What is a runtime error?

Answer: An error that occurs during program execution.

Q5. What is a logical error?

Answer: An error in program logic that produces an incorrect result even though the program executes.

Q6. What are browser Developer Tools?

Answer: Built-in browser utilities used to inspect HTML, CSS, JavaScript, network activity and application performance.

Q7. What is the purpose of console.log()?

Answer: It displays debugging information in the browser Console.

Q8. What is the difference between console.log() and console.error()?

Answer: console.log() displays general information, while console.error() reports error messages.

Q9. What is a breakpoint?

Answer: A breakpoint pauses program execution at a selected location for inspection.

Q10. What is the debugger statement?

Answer: It can pause JavaScript execution when browser debugging is active.

Q11. What is a call stack?

Answer: The call stack tracks active function calls using the Last In, First Out principle.

Q12. What causes a stack overflow?

Answer: Excessive function calls, often caused by recursion without a proper termination condition.

Q13. What is try/catch?

Answer: It is a JavaScript exception-handling mechanism that allows errors from a try block to be handled in a catch block.

Q14. What is the purpose of finally?

Answer: It executes after try/catch processing and is commonly used for cleanup operations.

Q15. What is the throw statement?

Answer: It explicitly generates an exception.

Q16. What is a custom error?

Answer: An application-specific error created by extending the built-in Error class or by constructing an Error with a suitable message.

Q17. What is the difference between throw and return?

Answer: return exits a function normally and provides a value. throw raises an exception and transfers control to an appropriate exception handler.

Q18. Does Fetch reject its Promise for HTTP 404?

Answer: Normally no. Fetch resolves with a Response object, so the application must inspect response.ok or response.status.

Q19. Which Developer Tools panel is used to inspect API requests?

Answer: The Network panel.

Q20. Which Developer Tools panel is used to inspect LocalStorage?

Answer: The Application panel in Chrome.

Q21. What is a memory leak?

Answer: A memory leak occurs when memory that is no longer needed remains reachable and cannot be reclaimed by garbage collection.

Q22. What is the purpose of console.table()?

Answer: It displays structured data in a table format in the Console.

Q23. What is the purpose of console.time()?

Answer: It measures elapsed time between a matching console.time() and console.timeEnd() call.

Q24. Why should empty catch blocks be avoided?

Answer: They silently hide errors and make failures difficult to identify and investigate.

Q25. How do you debug a JavaScript application?

Answer: Reproduce the issue, inspect Console errors, set breakpoints, examine variables and call stacks, check network requests, identify the root cause and retest the correction.

  1. Error Identification: Write programs containing syntax, runtime and logical errors. Identify and correct them.

  5. Exception Handling: Build a division function that throws an error when the divisor is zero.

  8. Fetch Debugging: Build an API application that handles network and HTTP errors separately.
  9. DOM Debugging: Create a page that safely handles missing DOM elements.
