2. What Are JavaScript Modules?

A JavaScript module is a reusable and independent unit of JavaScript code. Modules allow developers to divide a large application into smaller files.

Each module can contain variables, functions, classes and other declarations. It can expose selected functionality using export and use functionality from another module using import.

Why Are Modules Needed?

  • Organize large applications into smaller files.
  • Reuse functions and variables across files.
  • Reduce unnecessary global variables.
  • Improve code maintainability.
  • Make application testing easier.
  • Separate application responsibilities.
  • Support collaborative development.

Example: Without Modules

// One large JavaScript file

function add(a, b) {
    return a + b;
}

function subtract(a, b) {
    return a - b;
}

function calculateTax(amount) {
    return amount * 0.18;
}

function displayMessage(message) {
    console.log(message);
}

As an application grows, placing every function in one file makes maintenance difficult.

Example: With Modules

project/
│
├── index.html
│
├── main.js
│
├── math.js
│
├── tax.js
│
└── message.js

Each file has a specific responsibility and can share functionality through imports and exports.

3. JavaScript Script vs Module

JavaScript supports traditional scripts and ECMAScript modules (ES Modules).

Feature Traditional Script JavaScript Module
HTML usage <script src="app.js"> <script type="module" src="app.js">
Import/export Not supported as ES module syntax Supported
Scope Top-level declarations can affect global scope depending on declaration type Module scope
Strict mode Not automatic Automatically enabled
Loading Normal script execution rules Deferred by default in HTML
Top-level this Usually global object in classic browser scripts undefined

Using a Module in HTML

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Module Example</title>
</head>
<body>

    <h1>JavaScript Modules</h1>

    <script type="module" src="main.js"></script>

</body>
</html>
The type="module" attribute tells the browser to interpret the JavaScript file as an ES module. Module scripts are deferred automatically and execute after HTML parsing.

4. Named Exports

Named exports allow a module to export multiple declarations. The importing module uses their exported names to access them.

Method 1: Export During Declaration

File: math.js

export function add(a, b) {
    return a + b;
}

export function subtract(a, b) {
    return a - b;
}

export const PI = 3.14159;

The export keyword makes these declarations available to other modules.

Method 2: Export at the End

File: math.js

function multiply(a, b) {
    return a * b;
}

function divide(a, b) {
    return a / b;
}

const TAX_RATE = 0.18;

export {
    multiply,
    divide,
    TAX_RATE
};

This approach allows declarations to be defined first and exported together.

5. Named Imports

The import keyword allows one module to use declarations exported by another module.

Importing Named Exports

File: main.js

import { add, subtract, PI } from "./math.js";

console.log(add(10, 5));

console.log(subtract(10, 5));

console.log(PI);
Expected output: 
15
5
3.14159

Importing Multiple Functions

import {
    multiply,
    divide,
    TAX_RATE
} from "./math.js";

console.log(multiply(5, 4));

console.log(divide(20, 4));

console.log(TAX_RATE);
Expected output: 
20
5
0.18
Named imports must normally use the same exported names. Curly braces are required for named imports.

6. Renaming Named Imports and Exports

The as keyword allows developers to assign another name to an exported or imported declaration.

Renaming During Export

File: math.js

function addNumbers(a, b) {
    return a + b;
}

export {
    addNumbers as add
};

File: main.js

import { add } from "./math.js";

console.log(add(20, 30));
Output: 50

Renaming During Import

File: math.js

export function add(a, b) {
    return a + b;
}

File: main.js

import { add as calculateSum } from "./math.js";

console.log(calculateSum(10, 20));
Output: 30

7. Default Export

A module can have one default export. It is commonly used when a module has one primary function, class or value to provide.

Example: Default Function Export

File: calculator.js

export default function add(a, b) {
    return a + b;
}

Importing a Default Export

File: main.js

import add from "./calculator.js";

console.log(add(10, 20));
Output: 30
Unlike named imports, a default import does not require curly braces. The importing module can choose its local name.

Default Export of a Class

File: Employee.js

export default class Employee {

    constructor(name, salary) {
        this.name = name;
        this.salary = salary;
    }

    display() {
        console.log(this.name, this.salary);
    }
}

File: main.js

import Employee from "./Employee.js";

const emp = new Employee("Aman", 40000);

emp.display();
Output: Aman 40000

8. Default Export vs Named Export

Feature Named Export Default Export
Number per module Multiple One
Import syntax Curly braces normally required No curly braces
Import name Must match exported name unless aliased Can choose a local name
Typical use Several related utilities One main module value

Combining Named and Default Exports

File: user.js

export const role = "Developer";

export function getUser() {
    return {
        name: "Rahul",
        age: 25
    };
}

export default function greet() {
    return "Welcome to the application";
}

File: main.js

import greet, {
    role,
    getUser
} from "./user.js";

console.log(greet());

console.log(role);

console.log(getUser());
Expected output: 
Welcome to the application
Developer
{ name: "Rahul", age: 25 }

9. Namespace Imports

Namespace imports allow all named exports from a module to be accessed through one object-like namespace.

File: math.js

export function add(a, b) {
    return a + b;
}

export function subtract(a, b) {
    return a - b;
}

export const PI = 3.14;

File: main.js

import * as MathUtils from "./math.js";

console.log(MathUtils.add(10, 5));

console.log(MathUtils.subtract(10, 5));

console.log(MathUtils.PI);
Expected output: 
15
5
3.14

Namespace imports are useful when a module provides multiple related functions.

10. Re-Exporting Modules

A module can export declarations that originate from another module. This is useful for creating a central entry point for related functionality.

Example Folder Structure

project/
│
├── main.js
│
├── math.js
│
├── string.js
│
└── utils.js

File: math.js

export function add(a, b) {
    return a + b;
}

export function subtract(a, b) {
    return a - b;
}

File: string.js

export function capitalize(text) {
    return text.charAt(0).toUpperCase() +
           text.slice(1);
}

File: utils.js

export * from "./math.js";

export * from "./string.js";

File: main.js

import {
    add,
    subtract,
    capitalize
} from "./utils.js";

console.log(add(10, 5));

console.log(subtract(10, 5));

console.log(capitalize("javascript"));
Expected output: 
15
5
Javascript
export * re-exports named exports. It does not automatically re-export the original module's default export.

11. Importing and Re-Exporting with Aliases

A module can selectively re-export declarations and rename them at the same time.

File: math.js

export function add(a, b) {
    return a + b;
}

File: utils.js

export {
    add as calculateSum
} from "./math.js";

File: main.js

import { calculateSum } from "./utils.js";

console.log(calculateSum(15, 25));
Output: 40

12. Module Scope

Every ES module has its own scope. Variables and functions declared at the top level are not automatically added to the global object.

Example

File: app.js

const username = "Aman";

function greet() {
    console.log("Hello", username);
}

greet();

console.log(window.username);

The function can access the module-level variable, but the variable is not automatically attached to window.

Expected output: 
Hello Aman
undefined

Module Strict Mode

ES modules automatically execute in strict mode. Therefore, certain unsafe JavaScript behaviors are rejected. 

// Module code

"use strict"; // Not required in an ES module

x = 10; // ReferenceError: x is not defined
The "use strict" directive is unnecessary in ES modules because strict mode is automatic.

13. How JavaScript Modules Are Loaded

JavaScript modules use a dependency graph. When a module imports another module, the browser resolves and loads its dependencies.

Example Dependency Structure

index.html
    |
    v
main.js
    |
    +------> math.js
    |
    +------> user.js
                |
                +------> config.js

The browser resolves the dependency relationships and evaluates the modules according to the module loading and execution rules.

Important Module Characteristics

  • Modules are automatically in strict mode.
  • Module scope is separate from the global scope.
  • Modules are deferred by default when used in HTML.
  • Module dependencies are loaded before dependent module evaluation.
  • Modules are evaluated once per module identity within a module map.
  • Imports are read-only live bindings to exported declarations.

14. Live Bindings in JavaScript Modules

Named imports are live bindings. This means the importing module observes updates to an exported variable when the exporting module changes it.

Example

File: counter.js

export let count = 0;

export function increment() {
    count++;
}

File: main.js

import {
    count,
    increment
} from "./counter.js";

console.log(count);

increment();

console.log(count);

increment();

console.log(count);
Expected output: 
0
1
2
Imported bindings cannot be reassigned by the importing module. Their values can still reflect changes made by the exporting module.

15. Dynamic Import

Static imports are declared at the top level of a module. Dynamic import() allows a module to be loaded when needed during application execution.

It returns a Promise that resolves to a module namespace object.

Example

File: calculator.js

export function add(a, b) {
    return a + b;
}

export function multiply(a, b) {
    return a * b;
}

File: main.js

async function loadCalculator() {

    try {

        const calculator =
            await import("./calculator.js");

        console.log(calculator.add(10, 20));

        console.log(calculator.multiply(5, 4));

    } catch (error) {

        console.error("Module loading failed:", error);

    }
}

loadCalculator();
Expected output: 
30
20

Common Uses of Dynamic Import

  • Loading code only when a feature is required.
  • Reducing initial JavaScript loading work.
  • Loading rarely used application modules.
  • Implementing route-based code splitting.

16. Module Paths and File Extensions

Import paths tell the browser where a module can be found.

Path Meaning
./math.js File in the current directory.
../utils.js File in the parent directory.
./modules/user.js File inside a subdirectory.
/scripts/app.js Path relative to the website origin root.

Example Folder Structure

project/
│
├── index.html
│
├── main.js
│
└── modules/
    ├── math.js
    ├── user.js
    └── message.js

Importing from a subdirectory:

import { add } from "./modules/math.js";

import { getUser } from "./modules/user.js";
For browser-based ES modules, use valid module specifiers and include the file extension in relative imports, such as ./math.js. Bare package specifiers such as "react" require an appropriate package environment or import map.

17. CommonJS vs ES Modules

JavaScript has different module systems. CommonJS is widely associated with Node.js, while ES Modules are the standard JavaScript module system used by browsers and supported by Node.js.

Feature CommonJS ES Modules
Export module.exports or exports export
Import require() import
Loading model Traditionally synchronous in Node.js Static dependency graph with asynchronous loading in browsers
Dynamic loading require() import()
Primary environment Node.js and compatible tooling Browsers and Node.js

CommonJS Example

File: math.cjs

function add(a, b) {
    return a + b;
}

module.exports = {
    add
};

File: main.cjs

const math = require("./math.cjs");

console.log(math.add(10, 20));

ES Module Example

File: math.js

export function add(a, b) {
    return a + b;
}

File: main.js

import { add } from "./math.js";

console.log(add(10, 20));
In Node.js, module interpretation depends on file extensions and package configuration. For example, .mjs explicitly indicates an ES module and .cjs explicitly indicates CommonJS.

19. Practical Project: Modular Employee Management App

Build a small application using separate modules for employee data, salary calculations and the main application logic.

Project Folder Structure

employee-app/
│
├── index.html
│
├── main.js
│
└── modules/
    ├── employee.js
    └── salary.js

File 1: modules/employee.js

export const employees = [
    {
        id: 101,
        name: "Aman",
        salary: 30000
    },
    {
        id: 102,
        name: "Rahul",
        salary: 40000
    },
    {
        id: 103,
        name: "Priya",
        salary: 35000
    }
];

export function getEmployeeById(id) {

    return employees.find(
        employee => employee.id === id
    );
}

export function getAllEmployees() {
    return employees;
}

File 2: modules/salary.js

export function calculateBonus(salary) {
    return salary * 0.10;
}

export function calculateTotalSalary(salary) {

    const bonus = calculateBonus(salary);

    return salary + bonus;
}

File 3: main.js

import {
    getAllEmployees,
    getEmployeeById
} from "./modules/employee.js";

import {
    calculateBonus,
    calculateTotalSalary
} from "./modules/salary.js";

const employeeList =
    document.getElementById("employeeList");

const searchButton =
    document.getElementById("searchButton");

const searchInput =
    document.getElementById("employeeId");

const searchResult =
    document.getElementById("searchResult");

function displayEmployees() {

    employeeList.replaceChildren();

    const employees = getAllEmployees();

    employees.forEach(employee => {

        const li = document.createElement("li");

        const bonus =
            calculateBonus(employee.salary);

        const total =
            calculateTotalSalary(employee.salary);

        li.textContent =
            `${employee.name} | Salary: ${employee.salary} | ` +
            `Bonus: ${bonus} | Total: ${total}`;

        employeeList.append(li);
    });
}

searchButton.addEventListener("click", () => {

    const id = Number(searchInput.value);

    const employee = getEmployeeById(id);

    if (!employee) {

        searchResult.textContent =
            "Employee not found";

        return;
    }

    searchResult.textContent =
        `${employee.name} - Salary: ${employee.salary}`;
});

displayEmployees();

File 4: index.html

<!DOCTYPE html>
<html lang="en">
<head>

    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <title>Employee Management</title>

    <style>

        body {
            font-family: Arial, sans-serif;
            margin: 30px;
        }

        li {
            margin: 12px 0;
        }

        input, button {
            padding: 9px;
        }

    </style>

</head>

<body>

    <h1>Employee Management System</h1>

    <h2>Employee List</h2>

    <ul id="employeeList"></ul>

    <h2>Search Employee</h2>

    <input
        type="number"
        id="employeeId"
        placeholder="Enter employee ID"
    >

    <button id="searchButton">Search</button>

    <p id="searchResult"></p>

    <script type="module" src="./main.js"></script>

</body>
</html>

20. Common Module Errors and Debugging

1. Missing type="module"

<script src="main.js"></script>

If main.js contains import or export declarations, it must be loaded as a module in a browser.

Correction:

<script type="module" src="main.js"></script>

2. Incorrect Import Path

import { add } from "./math.js";

Check that math.js exists at the specified location. File names and capitalization must match.

3. Incorrect Named Import

Export:

export function add(a, b) {
    return a + b;
}

Incorrect import:

import { sum } from "./math.js";

The module does not export a named declaration called sum.

Correction:

import { add } from "./math.js";

4. Mixing Default and Named Import Syntax

// Default export
export default function greet() {
    return "Hello";
}

// Correct import
import greet from "./message.js";

Do not use curly braces for a default import.

5. Loading Modules Through file://

Browsers may block module loading or module dependencies when the page is opened directly from the file system. Use an HTTP development server or GitHub Pages.

6. MIME Type or Server Errors

The server must serve JavaScript module files with a suitable JavaScript MIME type. Inspect the Network tab and Console when module loading fails.

7. Circular Dependencies

A circular dependency occurs when module A imports module B and module B imports module A. Some circular dependencies work, but they can produce difficult initialization-order problems.

Avoid unnecessary circular dependencies by restructuring shared functionality into a separate module.

21. Placement Interview Questions and Answers

Q1. What are JavaScript modules?

Answer: Modules are independent JavaScript files that can export functionality and import functionality from other files.

Q2. Why do we use modules?

Answer: They improve code organization, reusability, maintainability and separation of responsibilities.

Q3. What is the difference between import and export?

Answer: export exposes declarations from a module, while import allows another module to use those declarations.

Q4. What is a named export?

Answer: A named export exposes a declaration using its specified exported name. A module can have multiple named exports.

Q5. What is a default export?

Answer: A default export is the primary exported value of a module. A module can have only one default export.

Q6. Can a module have multiple named exports?

Answer: Yes. A module can export multiple functions, variables and classes by name.

Q7. Can a module have multiple default exports?

Answer: No. An ES module can have only one default export.

Q8. What is the difference between named and default imports?

Answer: Named imports normally use curly braces and match exported names. Default imports do not use curly braces and can choose their local identifier.

Q9. What is the purpose of the as keyword?

Answer: It renames imported or exported declarations.

Q10. What is a namespace import?

Answer: It imports all named exports from a module under a single namespace object using import * as.

Q11. What is dynamic import?

Answer: Dynamic import() loads a module on demand and returns a Promise.

Q12. What is module scope?

Answer: Module scope means top-level declarations belong to the module rather than automatically becoming global variables.

Q13. Are JavaScript modules automatically in strict mode?

Answer: Yes. ES modules always execute in strict mode.

Q14. What is a live binding?

Answer: An imported binding reflects updates made to the corresponding exported binding.

Q15. What is the purpose of type="module"?

Answer: It tells the browser to treat the script as an ES module, enabling import and export syntax.

Q16. What is the difference between CommonJS and ES Modules?

Answer: CommonJS commonly uses require() and module.exports, whereas ES Modules use import and export.

Q17. Can ES Modules be used in Node.js?

Answer: Yes. Node.js supports ES Modules using .mjs files or suitable package configuration for .js files.

Q18. Why should modules be served over HTTP?

Answer: Browser module loading follows security and origin rules. Serving files through HTTP avoids common file:// restrictions.

Q19. What is a circular dependency?

Answer: It occurs when two or more modules depend on one another directly or indirectly.

Q20. Does export * include the default export?

Answer: No. export * re-exports named exports, not the default export.

24. Lesson Summary

  • JavaScript modules divide applications into reusable files.
  • ES Modules use import and export.
  • Named exports allow multiple declarations to be shared.
  • Default exports provide one primary export per module.
  • The as keyword supports aliases.
  • Namespace imports group named exports under one identifier.
  • Re-exports provide a central module entry point.
  • ES Modules have their own scope.
  • ES Modules automatically use strict mode.
  • Dynamic import() loads modules on demand.
  • CommonJS uses require() and module.exports.
  • Browser modules should be served through an HTTP server.
  • Modular architecture improves maintainability and code reuse.

You should now be able to structure a frontend application using multiple JavaScript files and share functionality through ES Modules.
