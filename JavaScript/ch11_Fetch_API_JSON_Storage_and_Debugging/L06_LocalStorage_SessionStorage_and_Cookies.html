2. What Is Browser Storage?

Browser storage allows a web application to store data on the user's device. The stored information can be used later without requesting the same data from the server every time.

Common use cases include:

  • Remembering user preferences.
  • Saving shopping cart information.
  • Maintaining temporary form data.
  • Storing theme preferences such as light or dark mode.
  • Remembering recently viewed items.
  • Maintaining application state between page reloads.

Three Common Browser Storage Mechanisms

Storage Purpose
LocalStorage Stores data that normally remains available across browser sessions.
SessionStorage Stores data for a particular browser tab's page session.
Cookies Stores small pieces of data that can be associated with HTTP requests.

3. Understanding LocalStorage

LocalStorage is part of the Web Storage API. It allows a website to store key-value pairs in the browser.

Important characteristics:

  • Data is stored as strings.
  • Data normally remains after closing and reopening the browser.
  • Data is associated with the website's origin.
  • Storage is accessible through JavaScript.
  • It is synchronous and should not be used for large datasets.

Basic Syntax

// Store data
localStorage.setItem("username", "Aman");

// Retrieve data
const name = localStorage.getItem("username");

// Remove one item
localStorage.removeItem("username");

// Remove all items for the current origin
localStorage.clear();

Example: Store and Retrieve a Username

localStorage.setItem("username", "Aman");

const username = localStorage.getItem("username");

console.log(username);
Output: Aman

The value remains available after a page reload, provided the browser has not cleared the stored data.

4. LocalStorage Methods and Properties

Method / Property Description
setItem(key, value) Stores a key-value pair.
getItem(key) Returns the value associated with a key, or null if absent.
removeItem(key) Removes a specific key-value pair.
clear() Removes all entries for the current origin.
key(index) Returns the key at a particular storage index.
length Returns the number of stored entries.

Example: Multiple LocalStorage Operations

localStorage.setItem("name", "Rahul");
localStorage.setItem("course", "JavaScript");
localStorage.setItem("level", "Beginner");

console.log(localStorage.getItem("name"));

console.log(localStorage.length);

console.log(localStorage.key(0));

localStorage.removeItem("level");

console.log(localStorage.length);

The exact key returned by key(0) should not be relied upon as a meaningful ordering guarantee.

Illustrative output: 
Rahul
3
name
2

Checking Whether a Key Exists

const value = localStorage.getItem("username");

if (value !== null) {
    console.log("Username exists:", value);
} else {
    console.log("Username not found");
}
getItem() returns null when the key does not exist. An empty string is a valid stored value, so checking only whether the returned value is truthy can be misleading.

5. LocalStorage Stores Strings

LocalStorage stores values as strings. If a number or boolean is passed, it is converted to a string. 

localStorage.setItem("age", 25);
localStorage.setItem("isStudent", true);

console.log(localStorage.getItem("age"));
console.log(typeof localStorage.getItem("age"));

console.log(localStorage.getItem("isStudent"));
console.log(typeof localStorage.getItem("isStudent"));
Output: 
25
string
true
string

If an application needs the original data types, it must convert the values after retrieving them. 

localStorage.setItem("age", "25");

const age = Number(localStorage.getItem("age"));

console.log(age);
console.log(typeof age);
Output: 
25
number

6. Storing Objects and Arrays Using JSON

JavaScript objects and arrays cannot be stored directly in LocalStorage as their original structures. JSON.stringify() converts them into strings.

Storing an Object

const user = {
    name: "Aman",
    age: 24,
    course: "JavaScript"
};

// Convert object into JSON string
const jsonData = JSON.stringify(user);

// Store JSON string
localStorage.setItem("user", jsonData);

// Retrieve stored string
const storedData = localStorage.getItem("user");

// Convert JSON string back into object
const retrievedUser = JSON.parse(storedData);

console.log(retrievedUser.name);
console.log(retrievedUser.age);
Output: 
Aman
24

Shorter Object Storage Example

const product = {
    id: 101,
    name: "Laptop",
    price: 55000
};

localStorage.setItem(
    "product",
    JSON.stringify(product)
);

const savedProduct = JSON.parse(
    localStorage.getItem("product")
);

console.log(savedProduct);

Storing an Array

const courses = [
    "C Programming",
    "C++",
    "JavaScript",
    "Embedded Systems"
];

localStorage.setItem(
    "courses",
    JSON.stringify(courses)
);

const savedCourses = JSON.parse(
    localStorage.getItem("courses")
);

console.log(savedCourses);
console.log(savedCourses[2]);
Output: 
[
  "C Programming",
  "C++",
  "JavaScript",
  "Embedded Systems"
]

JavaScript
Remember the sequence: object or array → JSON.stringify() → LocalStorage → getItem() → JSON.parse() → JavaScript object or array.

7. Updating Objects Stored in LocalStorage

LocalStorage does not provide a direct method to update a property inside a stored object. Retrieve the object, modify it and save the updated object again. 

const user = {
    name: "Aman",
    age: 24,
    city: "Delhi"
};

localStorage.setItem("user", JSON.stringify(user));

// Retrieve object
const savedUser = JSON.parse(
    localStorage.getItem("user")
);

// Update property
savedUser.age = 25;
savedUser.city = "Chandigarh";

// Save updated object
localStorage.setItem(
    "user",
    JSON.stringify(savedUser)
);

console.log(
    JSON.parse(localStorage.getItem("user"))
);
Expected output: 
{
    name: "Aman",
    age: 25,
    city: "Chandigarh"
}

8. Understanding SessionStorage

SessionStorage is another part of the Web Storage API. It stores key-value pairs for a particular page session.

Important characteristics:

  • Stores data as strings.
  • Data survives page reloads in the same tab.
  • Data is normally cleared when the tab or window session ends.
  • Different tabs have separate SessionStorage areas.
  • It is associated with the website's origin and page session.

Basic Syntax

// Store data
sessionStorage.setItem("sessionUser", "Rahul");

// Retrieve data
const user = sessionStorage.getItem("sessionUser");

// Remove one item
sessionStorage.removeItem("sessionUser");

// Clear session storage
sessionStorage.clear();

Example

sessionStorage.setItem("course", "JavaScript");

const course = sessionStorage.getItem("course");

console.log(course);
Output: JavaScript
SessionStorage is associated with a page session, not simply every individual page navigation. Same-tab navigation within the same origin normally retains it. A duplicated tab can initially receive a copy of the original tab's session storage, after which the sessions are separate.

9. LocalStorage vs SessionStorage

Feature LocalStorage SessionStorage
Storage API Web Storage API Web Storage API
Data format Strings Strings
Lifetime Normally persists across browser sessions Page session lifetime
Page reload Data remains Data remains
Tab isolation Shared by same-origin tabs Separate session storage areas per tab
Server transmission Not automatically sent with HTTP requests Not automatically sent with HTTP requests
JavaScript access Accessible to same-origin scripts Accessible to same-origin scripts

When to Use LocalStorage

  • Theme preferences.
  • Language preferences.
  • Non-sensitive user interface settings.
  • Remembering a shopping cart on the same device.

When to Use SessionStorage

  • Temporary form progress.
  • Temporary filters for a tab.
  • Multi-step workflows within a tab session.
  • Short-lived interface state.

10. Understanding Cookies

Cookies are small pieces of data stored by the browser and associated with a website. They are commonly used for session management, preferences and other HTTP state-management requirements.

Unlike LocalStorage and SessionStorage, cookies can automatically be included in matching HTTP requests, depending on their attributes and browser policies.

Creating a Cookie

document.cookie = "username=Aman";

console.log(document.cookie);
Illustrative output: username=Aman

Setting Cookie Expiration

const expiryDate = new Date();

expiryDate.setDate(expiryDate.getDate() + 7);

document.cookie =
    "username=Aman; expires=" +
    expiryDate.toUTCString() +
    "; path=/";

This creates a cookie with an expiration date approximately seven days in the future.

Using max-age

document.cookie =
    "theme=dark; max-age=604800; path=/";

max-age specifies the cookie lifetime in seconds. Here, 604800 seconds represents seven days.

11. Cookie Attributes

Attribute Purpose
Expires Specifies an absolute expiration date.
Max-Age Specifies the cookie lifetime in seconds.
Path Controls the URL path for which the cookie is sent.
Domain Controls which domain can receive the cookie.
Secure Restricts cookie transmission to secure HTTPS connections, subject to browser rules.
HttpOnly Prevents JavaScript from accessing the cookie.
SameSite Controls cross-site cookie sending behavior.

Example Cookie

document.cookie =
    "theme=dark; max-age=3600; path=/; SameSite=Lax; Secure";

Secure cookies require HTTPS, except for certain localhost development behavior supported by browsers.

HttpOnly cannot be set through document.cookie. It must be configured by the server using the Set-Cookie HTTP response header.

12. Reading Cookies with JavaScript

document.cookie returns a string containing cookies visible to the current document. It does not return an object automatically.

Example

document.cookie = "username=Aman; path=/";
document.cookie = "theme=dark; path=/";

console.log(document.cookie);

The browser may return a string similar to:

username=Aman; theme=dark

Extracting a Particular Cookie

function getCookie(name) {

    const cookies = document.cookie.split("; ");

    for (const cookie of cookies) {

        const [key, ...valueParts] = cookie.split("=");

        if (key === name) {
            return decodeURIComponent(valueParts.join("="));
        }
    }

    return null;
}

console.log(getCookie("username"));

This is a basic cookie-reading helper. Production applications should use carefully tested cookie handling and server-side security controls.

13. Updating and Deleting Cookies

Updating a Cookie

Setting a cookie again with the same name, domain and path replaces its existing value. 

document.cookie = "theme=light; path=/";

document.cookie = "theme=dark; path=/";

console.log(document.cookie);
Output: theme=dark

Deleting a Cookie

A cookie can be removed by setting its expiration in the past or its Max-Age to zero. The matching name, domain and path must be used. 

document.cookie =
    "theme=; max-age=0; path=/";
Cookies with HttpOnly cannot be deleted or modified through document.cookie. The server must manage them.

14. LocalStorage vs SessionStorage vs Cookies

Feature LocalStorage SessionStorage Cookies
Storage type Key-value strings Key-value strings Name-value pairs
Typical size Several MB, browser-dependent Several MB, browser-dependent About 4 KB per cookie in common browser implementations
Lifetime Normally persistent Page session Session or configured expiration
Sent automatically with HTTP requests No No Yes, when applicable
JavaScript access Yes Yes Usually, unless HttpOnly
Security controls Origin isolation; no HttpOnly attribute Origin and session isolation Secure, HttpOnly and SameSite attributes
Typical use Preferences and persistent UI state Temporary tab state Server-managed sessions and preferences
There is no universally best storage mechanism. Choose based on lifetime, server communication, security requirements and the type of data.

15. Browser Storage Events

The storage event is fired in other documents when a storage area changes. It is particularly useful for synchronizing LocalStorage changes between tabs.

Example: Listen for LocalStorage Changes

window.addEventListener("storage", event => {

    console.log("Storage changed");

    console.log("Key:", event.key);

    console.log("Old value:", event.oldValue);

    console.log("New value:", event.newValue);

    console.log("Storage area:", event.storageArea);

});

If another same-origin tab changes a LocalStorage value, this listener can receive the event.

The storage event is not fired in the same document that made the change. For LocalStorage, it can be received by other same-origin documents. For SessionStorage, it is limited to same-origin documents within the same top-level browsing context, such as applicable same-tab frames.

16. Storage Security and Best Practices

1. Do Not Store Sensitive Data in LocalStorage

LocalStorage is accessible to JavaScript running on the same origin. If an attacker exploits an XSS vulnerability, malicious script may read stored data.

2. Understand HttpOnly Cookies

HttpOnly cookies cannot be read through JavaScript. They are useful for server-managed authentication sessions, but they do not eliminate all security risks.

3. Use Secure Cookies

Secure cookies should be used for sensitive session cookies so that they are sent only over secure HTTPS connections.

4. Configure SameSite Appropriately

SameSite helps control when cookies are sent in cross-site contexts and can reduce certain CSRF risks.

5. Validate Retrieved Data

Stored data may be outdated, malformed or modified by the user. Validate it before using it.

6. Handle Storage Exceptions

Storage may be unavailable or quota limits may be reached. Use try/catch where appropriate.

7. Avoid Storing Large Datasets

Web Storage is synchronous and designed for relatively small amounts of data. IndexedDB is more appropriate for larger structured datasets and asynchronous storage.

Never store passwords, private keys, access tokens or other sensitive authentication secrets in LocalStorage as a general practice. Prefer secure server-managed sessions and carefully configured cookies.

17. Handling Storage Errors

Storage operations can fail due to browser restrictions, quota limits or security policies.

Example: Safe LocalStorage Write

function saveData(key, value) {

    try {

        localStorage.setItem(key, JSON.stringify(value));

        console.log("Data saved successfully.");

    } catch (error) {

        console.error(
            "Unable to save data:",
            error.message
        );
    }
}

saveData("settings", {
    theme: "dark",
    language: "en"
});

Example: Safe JSON Retrieval

function readData(key) {

    try {

        const storedValue = localStorage.getItem(key);

        if (storedValue === null) {
            return null;
        }

        return JSON.parse(storedValue);

    } catch (error) {

        console.error(
            "Unable to read stored data:",
            error.message
        );

        return null;
    }
}

const settings = readData("settings");

console.log(settings);
JSON.parse() can throw a SyntaxError when stored content is not valid JSON. Catch parsing errors separately when necessary.

18. Practical Project: Persistent Theme Switcher

This project allows users to switch between light and dark themes. Their preference is saved in LocalStorage and restored after reloading the page.

Complete HTML, CSS and JavaScript

<!DOCTYPE html>
<html lang="en">
<head>

<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">

<title>Theme Switcher</title>

<style>

body {
    font-family: Arial, sans-serif;
    padding: 30px;
    background: white;
    color: #222;
    transition: 0.3s;
}

body.dark {
    background: #202124;
    color: white;
}

button {
    padding: 10px 18px;
    cursor: pointer;
}

</style>

</head>

<body>

<h1>Theme Switcher</h1>

<p>Select your preferred theme.</p>

<button id="themeButton">Toggle Theme</button>

<script>

const themeButton =
    document.getElementById("themeButton");

function applyTheme(theme) {

    document.body.classList.toggle(
        "dark",
        theme === "dark"
    );

    themeButton.textContent =
        theme === "dark"
            ? "Switch to Light Theme"
            : "Switch to Dark Theme";
}

// Restore saved theme
const savedTheme =
    localStorage.getItem("theme") || "light";

applyTheme(savedTheme);

// Toggle theme
themeButton.addEventListener("click", () => {

    const newTheme =
        document.body.classList.contains("dark")
            ? "light"
            : "dark";

    applyTheme(newTheme);

    localStorage.setItem("theme", newTheme);
});

</script>

</body>
</html>

Expected Behavior

  1. Initially, the page loads the saved theme or uses light mode.
  2. Clicking the button changes the theme.
  3. The selected theme is saved in LocalStorage.
  4. Reloading the page restores the selected theme.

19. Practical Project: Persistent Shopping Cart

This project demonstrates how an application can save a shopping cart in LocalStorage.

Complete Example

<h2>Shopping Cart</h2>

<button id="addBtn">Add Laptop</button>

<button id="clearBtn">Clear Cart</button>

<ul id="cartList"></ul>

<p id="total"></p>

<script>

const addBtn = document.getElementById("addBtn");
const clearBtn = document.getElementById("clearBtn");
const cartList = document.getElementById("cartList");
const total = document.getElementById("total");

let cart = [];

function loadCart() {

    try {

        const savedCart = localStorage.getItem("cart");

        cart = savedCart ? JSON.parse(savedCart) : [];

        if (!Array.isArray(cart)) {
            cart = [];
        }

    } catch (error) {

        console.error("Invalid cart data:", error.message);

        cart = [];
    }
}

function saveCart() {

    try {

        localStorage.setItem("cart", JSON.stringify(cart));

    } catch (error) {

        console.error("Unable to save cart:", error.message);
    }
}

function displayCart() {

    cartList.replaceChildren();

    let totalPrice = 0;

    cart.forEach(item => {

        const li = document.createElement("li");

        li.textContent =
            `${item.name} - Rs. ${item.price}`;

        cartList.append(li);

        totalPrice += item.price;
    });

    total.textContent =
        `Total: Rs. ${totalPrice}`;
}

addBtn.addEventListener("click", () => {

    cart.push({
        name: "Laptop",
        price: 55000
    });

    saveCart();

    displayCart();
});

clearBtn.addEventListener("click", () => {

    cart = [];

    saveCart();

    displayCart();
});

loadCart();

displayCart();

</script>

Expected Behavior

  • Click Add Laptop to add an item.
  • The cart updates immediately.
  • The cart is saved in LocalStorage.
  • Reloading the page restores the cart.
  • Click Clear Cart to remove all items.
This is a frontend learning example. In a real shopping application, the server must validate product prices, inventory and order details. Never trust prices or totals calculated only in browser storage.

20. Common Mistakes

Mistake 1: Storing an Object Directly

const user = { name: "Aman" };

localStorage.setItem("user", user);

This converts the object to an ordinary string such as [object Object], losing its structure.

Correct approach:

localStorage.setItem("user", JSON.stringify(user));

Mistake 2: Forgetting JSON.parse()

const user = localStorage.getItem("user");

console.log(user.name);

getItem() returns a string, not the original object.

Correct approach:

const user = JSON.parse(
    localStorage.getItem("user")
);

console.log(user.name);

Mistake 3: Treating Missing Data as an Empty Object

const settings = JSON.parse(
    localStorage.getItem("settings")
);

console.log(settings.theme);

If the key is missing, getItem() returns null. Accessing theme on null causes an error.

Correct approach:

const storedSettings =
    localStorage.getItem("settings");

const settings = storedSettings
    ? JSON.parse(storedSettings)
    : {};

console.log(settings.theme);

Mistake 4: Assuming SessionStorage Is Shared Across Tabs

SessionStorage is scoped to a page session. Do not use it when multiple independent tabs must share the same stored state.

Mistake 5: Storing Authentication Secrets in LocalStorage

JavaScript running on the same origin can read LocalStorage. XSS can therefore expose stored secrets. Use an appropriate server-managed authentication design.

21. Placement Interview Questions and Answers

Q1. What is LocalStorage?

Answer: LocalStorage is a browser storage mechanism that stores string key-value pairs and normally persists data across browser sessions.

Q2. What is SessionStorage?

Answer: SessionStorage stores string key-value pairs for a particular page session and normally clears them when that session ends.

Q3. What is the difference between LocalStorage and SessionStorage?

Answer: LocalStorage normally persists across browser sessions, while SessionStorage is scoped to a page session and is isolated between tabs.

Q4. What data types can LocalStorage store directly?

Answer: LocalStorage stores strings. Other values are converted to strings.

Q5. How do you store an object in LocalStorage?

Answer: Use JSON.stringify() to convert the object into a JSON string before storing it.

Q6. How do you retrieve an object from LocalStorage?

Answer: Retrieve the string using getItem() and convert it back using JSON.parse().

Q7. What does getItem() return if a key does not exist?

Answer: It returns null.

Q8. What is the difference between removeItem() and clear()?

Answer: removeItem() removes one key, whereas clear() removes all entries for the current storage area.

Q9. What are cookies?

Answer: Cookies are small pieces of browser-stored data that can be included in matching HTTP requests.

Q10. What is an HttpOnly cookie?

Answer: It is a cookie that cannot be accessed through JavaScript APIs such as document.cookie.

Q11. What is a Secure cookie?

Answer: It is a cookie restricted to secure HTTPS connections, subject to browser rules.

Q12. What is the SameSite attribute?

Answer: It controls whether cookies are sent in cross-site request contexts.

Q13. Are LocalStorage values sent automatically to the server?

Answer: No. LocalStorage values are accessed through JavaScript and are not automatically included in HTTP requests.

Q14. What is the storage event?

Answer: It is an event fired in applicable other documents when a storage area changes.

Q15. Why should passwords not be stored in LocalStorage?

Answer: Same-origin JavaScript can access LocalStorage. An XSS vulnerability can expose its contents.

Q16. What is IndexedDB?

Answer: IndexedDB is an asynchronous browser database designed for larger amounts of structured data.

24. Lesson Summary

  • Browser storage allows client-side data persistence.
  • LocalStorage normally persists across browser sessions.
  • SessionStorage is scoped to a page session.
  • Both Web Storage mechanisms store strings.
  • JSON.stringify() converts objects and arrays into strings.
  • JSON.parse() reconstructs JavaScript values from JSON strings.
  • Cookies can be included automatically in matching HTTP requests.
  • HttpOnly prevents JavaScript access to a cookie.
  • Secure restricts cookie transmission to secure connections.
  • SameSite controls cross-site cookie behavior.
  • The storage event helps synchronize applicable documents.
  • Never treat browser storage as a secure database.
  • IndexedDB is suitable for larger structured browser-side data.

You should now be able to choose appropriate browser storage mechanisms and implement persistent frontend features such as preferences, forms and shopping carts.
