2. What Is Asynchronous JavaScript?

JavaScript normally executes statements sequentially. However, certain operations take time, such as:

  • Fetching information from a server.
  • Reading files.
  • Waiting for timers.
  • Accessing external services.

If the browser had to wait synchronously for every network operation, the user interface could become unresponsive. Asynchronous programming allows JavaScript to continue executing other work while waiting for such operations.

Synchronous Example

console.log("First");

console.log("Second");

console.log("Third");
Output: 
First
Second
Third

Asynchronous Example

console.log("Start");

setTimeout(() => {
    console.log("Delayed task");
}, 2000);

console.log("End");
Output: 
Start
End
Delayed task

The timer callback executes later. JavaScript does not stop the entire program while waiting for the timer.

3. Understanding async and await

async and await provide a cleaner way to write asynchronous JavaScript code. They make Promise-based operations easier to read.

async Keyword

The async keyword declares an asynchronous function. An async function always returns a Promise. 

async function greet() {
    return "Hello JavaScript";
}

greet().then(message => {
    console.log(message);
});
Output: Hello JavaScript

Async Function Returning a Promise

async function getNumber() {
    return 100;
}

const result = getNumber();

console.log(result);

The result is a Promise fulfilled with the value 100, not the number 100 directly.

await Keyword

The await keyword pauses execution of the surrounding async function until the awaited Promise settles. If fulfilled, await evaluates to its fulfillment value. If rejected, it throws the rejection reason. 

function getData() {
    return new Promise(resolve => {
        setTimeout(() => {
            resolve("Data received");
        }, 2000);
    });
}

async function displayData() {

    console.log("Waiting...");

    const result = await getData();

    console.log(result);
}

displayData();
Output: 
Waiting...
Data received
Important: await is normally used inside async functions. Modern JavaScript also supports top-level await in modules.

4. How async/await Works Internally

Consider the following code: 

async function loadData() {

    console.log("Step 1");

    const result = await fetchData();

    console.log("Step 2");

    console.log(result);
}

function fetchData() {
    return Promise.resolve("Data loaded");
}

loadData();

console.log("Step 3");
Expected output: 
Step 1
Step 3
Step 2
Data loaded

When the function reaches await, the async function suspends until the Promise settles. The remaining synchronous JavaScript can execute.

Once the Promise fulfills, the async function resumes through the JavaScript microtask mechanism.

Interview concept: await does not block the entire JavaScript thread. It suspends the current async function while other JavaScript work can continue.

5. Promise Chaining vs async/await

Both approaches can handle asynchronous operations. async/await often makes multi-step workflows easier to read.

Using Promise Chaining

fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => {

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
        }

        return response.json();
    })
    .then(user => {
        console.log(user.name);
    })
    .catch(error => {
        console.error(error.message);
    });

Using async/await

async function getUser() {

    try {

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users/1"
        );

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
        }

        const user = await response.json();

        console.log(user.name);

    } catch (error) {

        console.error(error.message);

    }
}

getUser();
Promise Chaining async/await
Uses then() and catch(). Uses await and try/catch.
Can become difficult to follow in long chains. Often reads like sequential code.
Useful for concise Promise pipelines. Useful for multi-step asynchronous workflows.
Returns chained Promises. Async functions always return Promises.

6. Error Handling with try, catch and finally

Asynchronous operations may fail because of network problems, unsuccessful HTTP statuses, invalid JSON or other runtime errors.

try and catch

async function loadUser() {

    try {

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users/1"
        );

        if (!response.ok) {
            throw new Error(
                `HTTP Error: ${response.status}`
            );
        }

        const user = await response.json();

        console.log(user);

    } catch (error) {

        console.error("Failed:", error.message);

    }
}

loadUser();

finally Block

The finally block executes after the try/catch operation settles. It is useful for cleanup and resetting loading indicators. 

async function loadData() {

    try {

        console.log("Loading data...");

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users"
        );

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
        }

        const data = await response.json();

        console.log(data);

    } catch (error) {

        console.error(error.message);

    } finally {

        console.log("Request completed.");

    }
}

loadData();
finally runs whether the operation succeeds or fails. It is useful for hiding loading indicators and releasing resources.

8. Understanding DOM Rendering

DOM rendering means creating or updating HTML elements dynamically using JavaScript.

API responses often contain arrays of objects. JavaScript can iterate over these objects and create HTML elements to display the information.

Important DOM Methods

Method / Property Purpose
document.getElementById() Selects an element using its ID.
document.querySelector() Selects the first matching CSS selector.
document.createElement() Creates a new HTML element.
append() Inserts nodes or text into an element.
replaceChildren() Replaces all existing child nodes.
textContent Reads or updates an element's text.
innerHTML Reads or updates HTML markup.

9. Rendering API Data Using createElement()

The following example retrieves users and creates HTML elements dynamically.

Complete Example

<h2>User List</h2>

<button id="loadUsers">Load Users</button>

<ul id="userList"></ul>

<p id="message"></p>

<script>

const loadButton = document.getElementById("loadUsers");
const userList = document.getElementById("userList");
const message = document.getElementById("message");

async function loadUsers() {

    message.textContent = "Loading users...";
    userList.replaceChildren();

    try {

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users"
        );

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
        }

        const users = await response.json();

        users.forEach(user => {

            const li = document.createElement("li");

            li.textContent =
                `${user.name} - ${user.email}`;

            userList.append(li);
        });

        message.textContent =
            `${users.length} users loaded.`;

    } catch (error) {

        message.textContent =
            `Error: ${error.message}`;

    }
}

loadButton.addEventListener("click", loadUsers);

</script>

13. Search and Filter API Data

Search and filtering are common frontend requirements. A user may retrieve a collection once and filter it locally based on input.

Example: Search Users by Name

<h2>Search Users</h2>

<input
    type="text"
    id="searchInput"
    placeholder="Enter user name"

<button id="searchBtn">Search</button>

<ul id="results"></ul>

<script>

const searchInput = document.getElementById("searchInput");
const searchBtn = document.getElementById("searchBtn");
const results = document.getElementById("results");

let users = [];

async function loadUsers() {

    try {

        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users"
        );

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);

    const searchText =
        searchInput.value.trim().toLowerCase();

  • Use trim() to remove unnecessary whitespace.
  • Use toLowerCase() for case-insensitive matching.
  • Use filter() to find matching records.
  • Use replaceChildren() before rendering updated results.

14. Sequential vs Parallel API Requests

Sometimes an application needs data from multiple API endpoints. The requests can be executed sequentially or concurrently.

Sequential Requests

async function loadSequentially() {

    const usersResponse = await fetch(
        "https://jsonplaceholder.typicode.com/users"
    );

    const users = await usersResponse.json();

    const postsResponse = await fetch(
        "https://jsonplaceholder.typicode.com/posts"
    );

    const posts = await postsResponse.json();

    console.log("Users:", users);
    console.log("Posts:", posts);
}

loadSequentially();

The second request starts only after the first response has been processed.

Parallel Requests Using Promise.all()

async function loadInParallel() {

    try {

        const [usersResponse, postsResponse] =
            await Promise.all([

                fetch("https://jsonplaceholder.typicode.com/users"),

                fetch("https://jsonplaceholder.typicode.com/posts")

            ]);

        if (!usersResponse.ok || !postsResponse.ok) {
            throw new Error("One or more API requests failed.");
        }

        const [users, posts] = await Promise.all([

            usersResponse.json(),

            postsResponse.json()

        ]);

        console.log("Users:", users);
        console.log("Posts:", posts);

    } catch (error) {

        console.error(error.message);

    }
}

loadInParallel();

Comparison

Sequential Parallel
Requests execute one after another. Requests are started without waiting for each other.
Useful when one request depends on another. Useful when requests are independent.
May take longer for independent requests. Can reduce total waiting time.
Promise.all() rejects if any input Promise rejects. It does not cancel the other requests automatically. Also, a Fetch Promise fulfills for HTTP 404 or 500, so inspect every response's ok property explicitly.

15. Promise.allSettled() for Multiple Requests

Promise.allSettled() waits for all input Promises to settle, whether fulfilled or rejected. 

async function loadMultipleResources() {

    const results = await Promise.allSettled([

        fetch("https://jsonplaceholder.typicode.com/users"),

        fetch("https://jsonplaceholder.typicode.com/posts"),

        fetch("https://invalid-domain-example.test/data")

    ]);

    results.forEach((result, index) => {

        if (result.status === "fulfilled") {
            console.log(`Request ${index + 1}: fulfilled`);
        } else {
            console.log(
                `Request ${index + 1}:`,
                result.reason.message
            );
        }
    });
}

loadMultipleResources();
A fulfilled Fetch Promise may still contain an HTTP error response. Promise.allSettled() reports Promise settlement, not whether the HTTP status represents success.

16. Pagination with API Data

Pagination divides a large collection into smaller groups of records. It is useful for product listings, user directories and dashboards.

Example: Fetch Posts with Pagination Parameters

async function loadPosts(page = 1, limit = 10) {

    const params = new URLSearchParams({
        _page: String(page),
        _limit: String(limit)
    });

    const url =
        `https://jsonplaceholder.typicode.com/posts?${params}`;

    try {

        const response = await fetch(url);

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
        }

        const posts = await response.json();

        console.log(`Page ${page}:`, posts);

    } catch (error) {

        console.error(error.message);

    }
}

loadPosts(1, 10);
loadPosts(2, 10);

The API supports pagination parameters. The frontend can request another page when the user selects Next or Previous.

Pagination Concepts

  • Page number identifies the requested page.
  • Page size specifies the number of records per page.
  • Offset indicates how many records to skip in offset-based APIs.
  • Some APIs use cursor-based pagination instead.

17. Preventing Race Conditions in Search Requests

In a live-search interface, multiple requests may be started while the user types. An older request can finish after a newer request and overwrite the latest results.

This is a request race condition.

Example: Cancel the Previous Search Request

let searchController = null;

async function searchUsers(query) {

    if (searchController) {
        searchController.abort();
    }

    searchController = new AbortController();

    const params = new URLSearchParams({
        q: query
    });

    try {

        const response = await fetch(
            `/api/users?${params}`,
            {
                signal: searchController.signal
            }
        );

        if (!response.ok) {
            throw new Error(`HTTP ${response.status}`);
        }

        const users = await response.json();

        console.log(users);

    } catch (error) {

        if (error.name === "AbortError") {
            console.log("Previous search cancelled.");
        } else {
            console.error(error.message);
        }
    }
}

This example assumes the backend provides a search endpoint at /api/users that accepts a query parameter named q.

Cancelling obsolete requests is useful for search suggestions, autocomplete and rapidly changing filters.

19. Placement Interview Questions and Answers

Q1. What is async in JavaScript?

Answer: async is a keyword used to declare an asynchronous function. An async function always returns a Promise.

Q2. What is await?

Answer: await waits for an awaited Promise to settle and evaluates to its fulfillment value. If the Promise rejects, await throws the rejection reason.

Q3. Does await block the JavaScript thread?

Answer: No. It suspends the current async function while other JavaScript work can continue.

Q4. What does an async function return?

Answer: It always returns a Promise. A returned value fulfills that Promise, while a thrown error rejects it.

Q5. What is the purpose of try/catch in async functions?

Answer: It handles errors thrown inside the try block, including rejected Promises awaited there.

Q6. What is the purpose of finally?

Answer: It executes after try/catch completes, regardless of success or failure, and is commonly used for cleanup.

Q7. What is DOM rendering?

Answer: DOM rendering is the process of creating or updating webpage elements using JavaScript.

Q8. What is the difference between textContent and innerHTML?

Answer: textContent handles content as text, while innerHTML parses the assigned value as HTML markup.

Q9. Why is createElement() useful?

Answer: It creates DOM elements programmatically, allowing safe and structured construction of dynamic interfaces.

Q10. What is Promise.all()?

Answer: It returns a Promise that fulfills when all input Promises fulfill, or rejects when one of them rejects.

Q11. What is Promise.allSettled()?

Answer: It waits for every input Promise to settle and returns the fulfillment or rejection result of each one.

Q12. What is a race condition in API search?

Answer: It occurs when multiple requests overlap and an older response can arrive after a newer response, causing outdated results to replace current data.

Q13. How can API search race conditions be handled?

Answer: AbortController can cancel obsolete requests. A request sequence identifier can also prevent stale responses from updating the interface.

Q14. What is the purpose of replaceChildren()?

Answer: It replaces all existing child nodes of an element with the supplied nodes. Calling it without arguments clears the element.

Q15. Why should untrusted API data not be inserted directly into innerHTML?

Answer: Untrusted content may contain malicious markup or scripts, potentially causing XSS. Use textContent and safe DOM methods for ordinary text.

22. Lesson Summary

  • async functions always return Promises.
  • await simplifies working with Promise-based operations.
  • await suspends the current async function, not the entire JavaScript thread.
  • Use try/catch to handle asynchronous errors.
  • Use finally for cleanup and resetting UI state.
  • Fetch and async/await work together for API communication.
  • DOM rendering displays API data dynamically.
  • Use createElement() and textContent for safe text rendering.
  • Promise.all() handles independent concurrent operations.
  • Promise.allSettled() reports the outcome of every input Promise.
  • Search and pagination are common API-driven frontend features.
  • AbortController can cancel obsolete requests.

You should now be able to build frontend interfaces that retrieve API data asynchronously, handle different request states and render dynamic content.
