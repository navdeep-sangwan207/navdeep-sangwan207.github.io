Lecture 2: Comparison and Equality Operators

Level: Beginner to Intermediate | Placement Preparation

1. Learning Objectives

After completing this lecture, you should be able to:

  • Understand JavaScript comparison operators.
  • Compare numeric values and strings.
  • Differentiate loose equality (==) and strict equality (===).
  • Understand implicit type conversion in comparisons.
  • Use inequality and relational operators correctly.
  • Compare primitive values and objects.
  • Apply comparisons in conditional statements.
  • Solve placement-oriented output-prediction questions.

2. What Are Comparison Operators?

Comparison operators compare two values and return a Boolean result: either true or false. 

let a = 10;

let b = 20;

console.log(a < b);

console.log(a > b);
Expected Output: 
true
false

Comparison operators are frequently used in:

  • if and else conditions
  • Loops and filtering
  • Form validation
  • User authentication checks
  • Sorting and searching logic
  • Frontend application business rules

4. Equality Operators

JavaScript provides two main equality operators:

  • == Loose equality
  • === Strict equality

4.1 Loose Equality (==)

The loose equality operator compares values after applying type conversion when required. 

console.log(10 == 10);

console.log(10 == "10");

console.log(0 == false);

console.log(1 == true);
Expected Output: 
true
true
true
true

In these examples, JavaScript converts compatible values before comparing them.

4.2 Strict Equality (===)

Strict equality checks both value and type. It does not perform the usual coercion used by loose equality. 

console.log(10 === 10);

console.log(10 === "10");

console.log(0 === false);

console.log(1 === true);
Expected Output: 
true
false
false
false

Loose Equality vs Strict Equality

Feature == ===
Name Loose equality Strict equality
Type conversion May occur Not performed for ordinary differing types
Value comparison Yes Yes
Type sensitivity Less strict Strict
Common usage Specific coercion cases Preferred in most application code
In normal application development, prefer === and !== unless you intentionally need loose equality behavior.

5. Inequality Operators

5.1 Loose Inequality (!=)

Returns true when two values are not equal after the type conversion rules used by loose equality. 

console.log(10 != 20);

console.log(10 != "10");

console.log(0 != false);
Expected Output: 
true
false
false

5.2 Strict Inequality (!==)

Returns true when values differ or their types differ. 

console.log(10 !== 20);

console.log(10 !== "10");

console.log(0 !== false);
Expected Output: 
true
true
true

6. Type Conversion in Loose Equality

Loose equality follows JavaScript's abstract equality comparison rules. These rules can produce results that surprise beginners.

6.1 Number and String

console.log(5 == "5");

console.log(100 == "100");

console.log(5 === "5");
Expected Output: 
true
true
false

6.2 Boolean and Number

console.log(true == 1);

console.log(false == 0);

console.log(true === 1);
Expected Output: 
true
true
false

In loose equality, Boolean values are converted to numbers for comparison:

  • true converts to 1.
  • false converts to 0.

6.3 Null and Undefined

console.log(null == undefined);

console.log(null === undefined);

console.log(null == 0);

console.log(undefined == 0);
Expected Output: 
true
false
false
false
A special rule of loose equality makes null and undefined equal to each other, but not equal to ordinary values such as 0 or an empty string.

6.4 Empty String and Zero

console.log("" == 0);

console.log("" === 0);

console.log(" " == 0);

console.log("0" == false);
Expected Output: 
true
false
true
true

7. Comparing Strings

JavaScript compares strings lexicographically using their UTF-16 code units. This is not the same as comparing their numeric-looking content.

7.1 Alphabetical Comparison

console.log("Apple" < "Banana");

console.log("Cat" > "Bat");

console.log("apple" === "Apple");
Expected Output: 
true
true
false

7.2 String Length Does Not Determine Order

console.log("20" < "3");

console.log(20 < 3);
Expected Output: 
true
false

When both operands are strings, relational comparison is lexicographical. The first character of "20" is compared with the first character of "3".

7.3 Case-Sensitive Comparison

console.log("apple" === "APPLE");

console.log("a" < "A");

console.log("A" < "a");
Expected Output: 
false
false
true
String comparisons are case-sensitive. When case-insensitive comparison is required, normalize both strings, for example with toLowerCase().

8. Comparing Arrays and Objects

Arrays and objects are reference types. Strict equality compares whether two variables refer to the same object, not whether their contents look identical.

8.1 Comparing Two Separate Arrays

let a = [1, 2, 3];

let b = [1, 2, 3];

console.log(a === b);
Expected Output: 
false

Each array is a separately created object.

8.2 Comparing Two References to the Same Array

let a = [1, 2, 3];

let b = a;

console.log(a === b);
Expected Output: 
true

8.3 Comparing Objects

let user1 = { name: "Amit" };

let user2 = { name: "Amit" };

let user3 = user1;

console.log(user1 === user2);

console.log(user1 === user3);
Expected Output: 
false
true
Two objects with identical properties are not automatically equal using ===. Deep comparison requires a separate comparison strategy.

10. Common Mistakes and Debugging

Mistake 1: Using == Instead of ===

let age = "25";

console.log(age == 25);

console.log(age === 25);
Output: 
true
false

Prefer strict equality when the data type should also match.

Mistake 2: Confusing Assignment and Equality

let number = 10;

console.log(number = 20);

console.log(number === 20);
Output: 
20
true

The first expression assigns 20 to number. It does not compare the two values.

Mistake 3: Comparing Numeric Strings

console.log("100" < "20");

console.log(Number("100") < Number("20"));
Output: 
true
false

Convert user-provided numeric strings to numbers when numeric comparison is intended.

Mistake 4: Comparing Objects by Content

console.log({ value: 10 } === { value: 10 });
Output: 
false

These are two different object references.

11. Important Interview Questions

Q1. What is the difference between == and ===?

Answer: == permits type conversion according to loose equality rules. === compares without that coercion and requires matching types for ordinary primitive values.

Q2. What is the output of 5 == "5"?

Answer: true. Loose equality converts the string to a number in this comparison.

Q3. What is the output of 5 === "5"?

Answer: false. One operand is a number and the other is a string.

Q4. What is the result of null == undefined?

Answer: true, because loose equality has a special rule for this pair.

Q5. Is null === undefined true?

Answer: No. They are different types.

Q6. What does !== mean?

Answer: Strict inequality. It returns true when the operands are not strictly equal.

Q7. Why are two identical arrays not equal?

Answer: Arrays are objects. Strict equality compares their references, not their contents.

Q8. Is JavaScript string comparison case-sensitive?

Answer: Yes. Uppercase and lowercase characters have different code-unit values.

Q9. What is the output of "10" < "2"?

Answer: true, because both operands are strings and are compared lexicographically.

Q10. Which equality operator should normally be preferred?

Answer: Strict equality (===) is generally preferred because it avoids unexpected type coercion.

14. Lecture Summary

  • Comparison operators return Boolean values.
  • Relational operators compare relative values.
  • == performs loose equality comparison.
  • === performs strict equality comparison.
  • != and !== are inequality operators.
  • Loose equality may perform type conversion.
  • String comparisons are lexicographical.
  • Strict equality compares object references.
  • Strict equality is generally preferred in application code.
  • Comparison operators are fundamental to conditional logic.
