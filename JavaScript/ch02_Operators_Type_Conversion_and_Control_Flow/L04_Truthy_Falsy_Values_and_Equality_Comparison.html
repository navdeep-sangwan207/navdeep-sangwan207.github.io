2. What Are Truthy and Falsy Values?

JavaScript evaluates values in Boolean contexts, such as conditions inside if, while and logical expressions.

A value that behaves like true in a Boolean context is called truthy. A value that behaves like false is called falsy.

JavaScript does not require every condition to contain an actual Boolean value. It automatically evaluates the truthiness of the supplied value.

Example

if ("JavaScript") {
    console.log("Condition is truthy");
}

if (0) {
    console.log("This will not execute");
}
Expected Output: 
Condition is truthy

6. What Is Type Conversion?

Type conversion means changing a value from one data type to another.

JavaScript supports two broad forms:

  1. Explicit type conversion
  2. Implicit type conversion (type coercion)

6.1 Explicit Type Conversion

Explicit conversion happens when the programmer deliberately converts a value using a function or conversion method. 

let value = "100";

let numberValue = Number(value);

console.log(numberValue);

console.log(typeof numberValue);
Expected Output: 
100
number

6.2 Implicit Type Conversion

Implicit conversion happens automatically when JavaScript converts operands to perform an operation. 

let result = "10" + 5;

console.log(result);

console.log(typeof result);
Expected Output: 
105
string

In this example, the number is converted into a string and concatenated with the first operand.

Function Purpose Example Result

parseFloat() Parses a decimal number from the beginning. parseFloat("25.5px") → 25.5
When using parseInt() for predictable numeric parsing, specify the radix when appropriate: parseInt("101", 2) returns 5.

13. Implicit Type Coercion in Comparisons

Some comparison operators perform type conversion when comparing values of different types.

13.1 Equality Comparison

console.log(5 == "5");

console.log(0 == false);

console.log(null == undefined);

console.log(5 === "5");
Expected Output: 
true
true
true
false

The == operator permits type coercion in many cases, whereas === compares without performing this type conversion.

13.2 Relational Comparison

console.log("10" > 5);

console.log("20" < "3");

console.log("10" > "5");
Expected Output: 
true
true
false

When both operands are strings, relational comparisons use lexicographical ordering based on their string values.

Prefer strict equality (===) in normal application code unless type coercion is deliberately required. Detailed equality behavior is covered in the comparison operators lecture.

14. Type Coercion with Arrays and Objects

Arrays and objects can be converted to primitive values during operations. This can produce surprising results.

14.1 Array with +

console.log([] + []);

console.log([] + 5);

console.log([1, 2] + [3, 4]);

console.log([10] + 5);
Expected Output: 

5
1,23,4
105

Arrays are converted to strings in these examples, so + performs string concatenation.

14.2 Object with +

console.log({} + "Hello");

console.log([1, 2] + " items");
Expected Output: 
[object Object]Hello
1,2 items
Avoid relying on complicated implicit conversions involving arrays and objects. Convert values explicitly when the intended result matters.

15. Practical Frontend Applications

Example 1: Convert Form Input to a Number

Values obtained from HTML input elements are generally strings. Convert numeric input before performing calculations. 

let priceInput = "250";

let quantityInput = "3";

let price = Number(priceInput);

let quantity = Number(quantityInput);

let total = price * quantity;

console.log(total);
Expected Output: 
750

Example 2: Validate a Numeric Input

let input = "125";

let value = Number(input);

if (input.trim() !== "" && Number.isFinite(value)) {
    console.log("Valid number");
} else {
    console.log("Invalid number");
}
Expected Output: 
Valid number

The empty-string check prevents Number("") from being accepted as zero when an actual input is required.

Example 3: Set a Default Display Name

let username = "";

let displayName = username || "Guest";

console.log(displayName);
Expected Output: 
Guest

Example 4: Check Whether a User Entered a Value

let email = "user@example.com";

if (email) {
    console.log("Email provided");
} else {
    console.log("Email required");
}
Expected Output: 
Email provided

For actual form validation, trim whitespace and validate the email format separately. A string containing only spaces is truthy.

16. Common Mistakes and Debugging

Mistake 1: Assuming "0" Is Falsy

if ("0") {
    console.log("Executed");
}
Expected Output: 
Executed

A non-empty string is truthy, even when it contains the character zero.

Mistake 2: Assuming Empty Arrays Are Falsy

if ([]) {
    console.log("Array is truthy");
}
Expected Output: 
Array is truthy

Mistake 3: Using Number() Without Validating Empty Input

let input = "";

console.log(Number(input));
Expected Output: 
0

If empty input should be rejected, check it before converting the value.

Mistake 4: Confusing Number() with parseInt()

console.log(Number("50px"));

console.log(parseInt("50px", 10));
Expected Output: 
NaN
50

Mistake 5: Using + for Numeric Addition of Strings

let first = "10";

let second = "20";

console.log(first + second);

console.log(Number(first) + Number(second));
Expected Output: 
1020
30

Mistake 6: Treating NaN as Equal to Itself

let result = Number("Hello");

console.log(result === NaN);

console.log(Number.isNaN(result));
Expected Output: 
false
true

Use Number.isNaN() to check whether a value is the numeric NaN value.

17. Important Interview Questions

Q1. What are truthy and falsy values?

Answer: Truthy values behave like true in Boolean contexts, while falsy values behave like false.

Q2. List the falsy values in JavaScript.

Answer: false, 0, -0, 0n, "", null, undefined and NaN. The legacy document.all value is an unusual additional browser-specific case.

Q3. Is an empty array truthy or falsy?

Answer: Truthy. All ordinary JavaScript objects, including arrays, are truthy.

Q4. Is an empty object truthy or falsy?

Answer: Truthy.

Q5. What is type coercion?

Answer: Type coercion is the automatic conversion of a value from one type to another during JavaScript operations.

Q6. What is the difference between explicit and implicit conversion?

Answer: Explicit conversion is requested by the programmer, for example Number("10"). Implicit conversion happens automatically during an operation.

Q7. What is the difference between Number() and parseInt()?

Answer: Number() attempts to convert the complete value into a number. parseInt() parses an integer from the beginning of a string.

Q8. What is the output of "5" + 2?

Answer: "52", because + performs string concatenation in this expression.

Q9. What is the output of "5" - 2?

Answer: 3, because subtraction converts the string operand into a number.

Q10. What is the result of Number(null)?

Answer: 0.

Q11. What is the result of Number(undefined)?

Answer: NaN.

Q12. Why is Boolean("false") true?

Answer: Because "false" is a non-empty string. Its textual meaning does not affect its truthiness.

Q13. How can you convert a value into Boolean?

Answer: Use Boolean(value) or !!value.

Q14. What does NaN mean?

Answer: Not-a-Number. It is a special numeric value representing an invalid or undefined numeric result.

Q15. Why should frontend developers convert input values?

Answer: HTML form inputs generally provide strings. Explicit conversion is needed for reliable numeric calculations and validation.

20. Lecture Summary

  • Truthy values behave like true in Boolean contexts.
  • Falsy values behave like false in Boolean contexts.
  • Empty arrays and empty objects are truthy.
  • Boolean() and !! perform Boolean conversion.
  • Explicit conversion is controlled by the programmer.
  • Implicit conversion happens automatically.
  • Number() converts complete values into numbers when possible.
  • String() converts values into strings.
  • parseInt() extracts an integer from the start of a string.
  • parseFloat() extracts a floating-point number from the start of a string.
  • Arithmetic operators can trigger numeric conversion.
  • The + operator may perform addition or concatenation.
  • NaN should be checked using Number.isNaN().
  • Explicit conversion helps prevent frontend calculation errors.
