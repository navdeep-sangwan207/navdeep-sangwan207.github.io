2. Understanding Truthy and Falsy Values

JavaScript evaluates values in Boolean contexts. A value is classified as either truthy or falsy.

  • Truthy: A value that behaves like true when converted to Boolean.
  • Falsy: A value that behaves like false when converted to Boolean.

These classifications are important when writing if statements, loops, logical expressions and conditional rendering in frontend applications.

Basic Example

if ("JavaScript") {
    console.log("Truthy value");
}

if (0) {
    console.log("This will not execute");
}
Expected Output: 
Truthy value

A falsy value can cause a conditional block to be skipped.

    console.log("Username available");

An empty string has no characters and is falsy. A string containing even one space is non-empty and therefore truthy.

Empty arrays and empty objects are truthy. Do not use if (array) to check whether an array contains elements. Use array.length instead.

7. Equality Operators

Equality operators compare two values and return a Boolean result.

The four important equality operators are:

Operator Name Behavior
== Loose Equality Allows type coercion.
=== Strict Equality Does not coerce different primitive types.
!= Loose Inequality Allows coercion before checking inequality.
!== Strict Inequality Checks inequality without coercing different primitive types.

7.1 Loose Equality (==)

Loose equality can convert operands before comparison when their types differ. 

console.log(10 == "10");

console.log(0 == false);

console.log(1 == true);

console.log(null == undefined);
Expected Output: 
true
true
true
true

7.2 Strict Equality (===)

Strict equality compares types as well as values. Different primitive types do not become equal through coercion. 

console.log(10 === "10");

console.log(0 === false);

console.log(1 === true);

console.log(10 === 10);
Expected Output: 
false
false
false
true

7.3 Loose Inequality (!=)

console.log(10 != "10");

console.log(10 != "20");

console.log(0 != false);
Expected Output: 
false
true
false

7.4 Strict Inequality (!==)

console.log(10 !== "10");

console.log(10 !== 10);

console.log(0 !== false);
Expected Output: 
true
false
true
In normal application development, prefer === and !== unless you specifically need loose equality semantics.

console.log("100" === 100);

console.log("100" != 100);

Expected Output: 
true
false

8.4 Object Equality

Objects and arrays are compared by reference, not by checking whether their contents are identical. 

let a = { name: "Alex" };
let b = { name: "Alex" };

console.log(a == b);
console.log(a === b);

let c = a;

console.log(a === c);
Expected Output: 
false
false
true

Variables a and b refer to two different objects. Variable c refers to the same object as a.

8.5 Array Equality

let first = [1, 2, 3];
let second = [1, 2, 3];

console.log(first === second);

let third = first;

console.log(first === third);
Expected Output: 
false
true

9. Practical Frontend Applications

9.1 Checking Whether a Search Input Is Empty

let searchText = "";

if (searchText.trim()) {
    console.log("Start search");
} else {
    console.log("Search field is empty");
}
Expected Output: 
Search field is empty

trim() removes leading and trailing whitespace. This prevents a string containing only spaces from being treated as meaningful input.

9.2 Checking Whether a User Is Logged In

let user = {
    username: "navdeep",
    isLoggedIn: true
};

if (user && user.isLoggedIn) {
    console.log("Welcome", user.username);
} else {
    console.log("Please log in");
}
Expected Output: 
Welcome navdeep

9.3 Checking Whether an Array Contains Data

let products = [];

if (products.length === 0) {
    console.log("No products available");
} else {
    console.log("Products found");
}
Expected Output: 
No products available

9.4 Checking an Optional Numeric Value

A numeric value of zero may be valid data. Do not use a truthiness check when zero is a meaningful value. 

let quantity = 0;

if (quantity !== null && quantity !== undefined) {
    console.log("Quantity:", quantity);
} else {
    console.log("Quantity not provided");
}
Expected Output: 
Quantity: 0

9.5 Strict Status Comparison

let responseStatus = 200;

if (responseStatus === 200) {
    console.log("Request successful");
} else {
    console.log("Request failed");
}
Expected Output: 
Request successful

10. Common Mistakes and Debugging

Mistake 1: Assuming "0" Is Falsy

console.log(Boolean("0"));

console.log(Boolean(0));
Expected Output: 
true
false

Mistake 2: Assuming Empty Arrays Are Falsy

let data = [];

if (data) {
    console.log("Data exists");
}
Expected Output: 
Data exists

Check data.length when you need to determine whether an array contains elements.

Mistake 3: Using Truthiness to Check a Numeric Value

let score = 0;

if (score) {
    console.log("Score available");
} else {
    console.log("Score is zero or missing");
}
Expected Output: 
Score is zero or missing

If zero is a valid score, use an explicit null or undefined check instead.

Mistake 4: Using Loose Equality Without Understanding It

console.log(false == 0);

console.log(false === 0);
Expected Output: 
true
false

Mistake 5: Comparing Two Separate Objects

console.log({} === {});

console.log([] === []);
Expected Output: 
false
false

Mistake 6: Treating a String Containing Spaces as Empty

let input = "   ";

console.log(Boolean(input));

console.log(Boolean(input.trim()));
Expected Output: 
true
false

11. Placement Interview Questions

Q1. What are truthy and falsy values?

Answer: Truthy values behave like true in Boolean contexts. Falsy values behave like false.

Q2. Name the important falsy values in JavaScript.

Answer: false, 0, -0, 0n, empty string, null, undefined and NaN. document.all is a browser-specific legacy exception.

Q3. Is an empty array truthy or falsy?

Answer: Truthy.

Q4. Is an empty object truthy or falsy?

Answer: Truthy.

Q5. Is the string "false" truthy or falsy?

Answer: Truthy, because it is a non-empty string.

Q6. What is the difference between == and ===?

Answer: == permits type coercion during comparison, whereas === compares without coercing different primitive types.

Q7. What is the difference between != and !==?

Answer: != performs loose inequality comparison with possible coercion. !== performs strict inequality comparison.

Q8. Why does null == undefined return true?

Answer: JavaScript specifically defines null and undefined as loosely equal to each other.

Q9. Why does NaN === NaN return false?

Answer: NaN is unequal to every value, including itself.

Q10. How do you check whether a value is truthy?

Answer: Use Boolean(value) or !!value.

Q11. How are objects compared using ===?

Answer: Objects are compared by reference identity. Two separate objects are not equal even when their properties match.

Q12. Why is if ([]) true?

Answer: All arrays are objects, and objects are truthy, including empty arrays.

Q13. How do you check whether an array is empty?

Answer: Check whether array.length === 0.

Q14. Why should strict equality generally be preferred?

Answer: It avoids unexpected type coercion and makes comparisons more predictable.

Q15. What is the difference between 0 and "0" in a condition?

Answer: Numeric zero is falsy. The non-empty string "0" is truthy.

14. Lecture Summary

  • Truthy values behave like true in Boolean contexts.
  • Falsy values behave like false in Boolean contexts.
  • Important falsy values include false, 0, -0, 0n, empty string, null, undefined and NaN.
  • Non-empty strings are truthy, including "0" and "false".
  • Empty arrays and objects are truthy.
  • Boolean() and !! convert values into Boolean equivalents.
  • == permits type coercion during comparison.
  • === performs strict comparison.
  • != and !== are the corresponding inequality operators.
  • NaN is unequal to itself.
  • Objects and arrays are compared by reference.
  • Use explicit checks when zero or empty collections are valid application values.
