1. Learning Objectives

After completing this lecture, you should be able to:

  • Understand JavaScript type conversion and type coercion.
  • Convert values explicitly using Number(), String() and Boolean().
  • Use parseInt() and parseFloat() correctly.

  • Predict results of mixed-type expressions.
  • Understand NaN and common conversion edge cases.
  • Avoid common type-conversion bugs in frontend applications.
  • Answer placement interview questions involving type coercion.

2. Introduction to Type Conversion

JavaScript is a dynamically typed language. A variable can hold values of different data types during program execution. 

let value = 100;

console.log(typeof value);

value = "JavaScript";

console.log(typeof value);

value = true;

console.log(typeof value);
Expected Output: 
number
string
boolean

Sometimes an application needs to convert a value from one type to another. For example, an HTML input commonly provides its value as a string, even when the user enters a number.

Example: HTML Input Values

let quantity = "10";
let price = "50";

console.log(quantity + price);
Expected Output: 
1050

Both values are strings, so the + operator performs string concatenation instead of numeric addition.

3. Explicit Type Conversion

Explicit type conversion means deliberately converting a value from one data type to another using JavaScript functions or constructors.

The most commonly used conversion functions are:

  • Number()
  • String()
  • Boolean()
  • parseInt()
  • parseFloat()

3.1 Number() Conversion

The Number() function converts a value into a number when a valid numeric conversion exists. If conversion is not possible, it returns NaN. 

console.log(Number("100"));

console.log(Number("45.5"));

console.log(Number(true));

console.log(Number(false));

console.log(Number(null));

console.log(Number("JavaScript"));
Expected Output: 
100
45.5
1
0
0
NaN

3.2 Number() with Empty and Whitespace Strings

console.log(Number(""));

console.log(Number("   "));

console.log(Number("  25  "));

console.log(Number("25px"));
Expected Output: 
0
0
25
NaN
An empty string converts to 0 using Number(). Do not assume that an empty input means a valid numeric value in your application.

3.3 String() Conversion

String() converts a value into its string representation. 

console.log(String(100));

console.log(String(45.5));

console.log(String(true));

console.log(String(false));

console.log(String(null));

console.log(String(undefined));
Expected Output: 
100
45.5
true
false
null
undefined

3.4 Boolean() Conversion

Boolean() converts a value into true or false according to JavaScript truthiness rules. 

console.log(Boolean(1));

console.log(Boolean(0));

console.log(Boolean("Hello"));

console.log(Boolean(""));

console.log(Boolean(null));

console.log(Boolean(undefined));

console.log(Boolean(NaN));
Expected Output: 
true
false
true
false
false
false
false

The complete list of important truthy and falsy values is covered in Lecture 4.

4. parseInt() and parseFloat()

These functions parse numeric values from strings. They are useful when extracting a number from text that begins with a numeric portion.

4.1 parseInt()

parseInt() reads an integer from the beginning of a string and stops when it reaches a character that cannot be part of the number. 

console.log(parseInt("100"));

console.log(parseInt("45.99"));

console.log(parseInt("25px"));

console.log(parseInt("JavaScript25"));
Expected Output: 
100
45
25
NaN

4.2 parseFloat()

parseFloat() reads a floating-point number from the beginning of a string. 

console.log(parseFloat("45.75"));

console.log(parseFloat("25.5px"));

console.log(parseFloat("100"));

console.log(parseFloat("Hello25.5"));
Expected Output: 
45.75
25.5
100
NaN

4.3 Number() vs parseInt() vs parseFloat()

Expression Number() parseInt() parseFloat()
"25" 25 25 25
"25.75" 25.75 25 25.75
"25px" NaN 25 25
"25.5px" NaN 25 25.5
"" 0 NaN NaN
Number() attempts to convert the complete value. parseInt() and parseFloat() parse a numeric prefix. Choose the function according to the validation rules of your application.

4.4 parseInt() with Radix

The second argument of parseInt() specifies the number base, also called the radix. 

console.log(parseInt("1010", 2));

console.log(parseInt("17", 8));

console.log(parseInt("FF", 16));

console.log(parseInt("25", 10));
Expected Output: 
10
15
255
25

Common radix values include 2 for binary, 8 for octal, 10 for decimal and 16 for hexadecimal.

5. Implicit Type Conversion (Type Coercion)

Implicit type conversion, commonly called type coercion, occurs when JavaScript automatically converts values during an operation.

This commonly occurs with arithmetic operators, comparison operators and conditional expressions.

5.1 String Coercion with +

If one operand is a string, the + operator commonly performs string concatenation. 

console.log(10 + "20");

console.log("Hello" + 10);

console.log(10 + 20 + "30");

console.log("10" + 20 + 30);
Expected Output: 
1020
Hello10
3030
102030

The + operator evaluates from left to right. Once string concatenation occurs, subsequent values may also be converted to strings.

5.2 Numeric Coercion with Other Arithmetic Operators

The subtraction, multiplication, division and remainder operators generally convert string operands to numbers. 

console.log("20" - 5);

console.log("10" * 2);

console.log("20" / 4);

console.log("10" % 3);
Expected Output: 
15
20
5
1

5.3 Boolean Coercion in Arithmetic

console.log(true + 1);

console.log(false + 1);

console.log(true * 5);

console.log(false - 2);
Expected Output: 
2
1
5
-2

In numeric operations, true is converted to 1 and false is converted to 0.

6. Type Coercion in Comparison Operations

6.1 Equality Operator (==)

The loose equality operator == may convert operands to compatible types before comparing their values. 

console.log(5 == "5");

console.log(0 == false);

console.log(null == undefined);

console.log(10 == "10");
Expected Output: 
true
true
true
true

6.2 Strict Equality Operator (===)

The strict equality operator compares values without performing type coercion between different primitive types. 

console.log(5 === "5");

console.log(0 === false);

console.log(10 === 10);

console.log("Hello" === "Hello");
Expected Output: 
false
false
true
true
Prefer === and !== in most application code. They make type differences explicit and reduce unexpected comparison results.

6.3 Relational Comparison

When both operands are strings, relational operators compare strings lexicographically. Otherwise, numeric conversion may occur. 

console.log("10" > "2");

console.log("10" > 2);

console.log(10 > "2");

console.log("20" < "100");
Expected Output: 
false
true
true
true

In string comparison, characters are compared according to their Unicode code point values, not their numeric meaning.

7. NaN (Not a Number)

NaN is a special numeric value representing an invalid or unrepresentable numeric result. Its type is still number. 

let result = Number("Hello");

console.log(result);

console.log(typeof result);

console.log(Number.isNaN(result));
Expected Output: 
NaN
number
true

7.1 NaN Is Not Equal to Itself

console.log(NaN === NaN);

console.log(Number.isNaN(NaN));
Expected Output: 
false
true

7.2 isNaN() vs Number.isNaN()

The global isNaN() function first converts its argument to a number. Number.isNaN() checks whether the value itself is NaN without coercion. 

console.log(isNaN("Hello"));

console.log(isNaN("123"));

console.log(Number.isNaN("Hello"));

console.log(Number.isNaN(NaN));
Expected Output: 
true
false
false
true
Use Number.isNaN() when you need to determine whether a value is specifically the numeric NaN value without implicit conversion.

8. Practical Frontend Applications

8.1 Converting Form Input to a Number

Values received from HTML input elements are generally strings. Convert them before performing numeric calculations. 

let quantityInput = "5";
let priceInput = "100";

let quantity = Number(quantityInput);
let price = Number(priceInput);

let total = quantity * price;

console.log("Total:", total);
Expected Output: 
Total: 500

8.2 Validating Numeric Input

let input = "250";

let value = Number(input);

if (input.trim() !== "" && Number.isFinite(value)) {
    console.log("Valid number:", value);
} else {
    console.log("Invalid input");
}
Expected Output: 
Valid number: 250

Number.isFinite() checks whether a value is a finite number without converting it. The explicit empty-string check prevents an empty input from being accepted as zero.

8.3 Calculating Product Price

let productPrice = "499.50";
let discount = "50";

let finalPrice = Number(productPrice) -
                 Number(discount);

console.log("Final Price:", finalPrice);
Expected Output: 
Final Price: 449.5

8.4 Converting API Response Values

let apiResponse = {
    productName: "Keyboard",
    price: "799",
    stock: "25"
};

let price = Number(apiResponse.price);
let stock = Number(apiResponse.stock);

console.log(price + 100);
console.log(stock - 5);
Expected Output: 
899
20

Applications should validate external data rather than assuming that API values always have the expected types.

9. Common Type Conversion Mistakes

Mistake 1: Using + for Numeric Addition with Strings

let a = "10";
let b = "20";

console.log(a + b);

// Correct numeric addition:
console.log(Number(a) + Number(b));
Expected Output: 
1020
30

Mistake 2: Assuming Number() and parseInt() Behave the Same

console.log(Number("25px"));

console.log(parseInt("25px", 10));
Expected Output: 
NaN
25

Mistake 3: Assuming an Empty String Is NaN

console.log(Number(""));

console.log(parseInt(""));
Expected Output: 
0
NaN

Mistake 4: Using == Without Understanding Coercion

console.log(0 == false);

console.log(0 === false);
Expected Output: 
true
false

Mistake 5: Forgetting That NaN Has Type number

let value = Number("abc");

console.log(typeof value);

console.log(Number.isNaN(value));
Expected Output: 
number
true

Mistake 6: Treating parseFloat() as Full Validation

console.log(parseFloat("12.5abc"));

console.log(Number("12.5abc"));
Expected Output: 
12.5
NaN

parseFloat() can successfully parse a numeric prefix even when extra characters follow it. It should not be treated as complete input validation.

10. Placement Interview Questions

Q1. What is type conversion in JavaScript?

Answer: Type conversion is changing a value from one data type to another. It can be explicit or implicit.

Q2. What is the difference between type conversion and type coercion?

Answer: Explicit conversion is performed intentionally by the programmer. Type coercion is automatic conversion performed by JavaScript during certain operations.

Q3. What does Number("100") return?

Answer: 100 as a number.

Q4. What does Number("Hello") return?

Answer: NaN.

Q5. What is the difference between parseInt() and parseFloat()?

Answer: parseInt() parses an integer, whereas parseFloat() parses a floating-point number.

Q6. What is the difference between Number() and parseInt()?

Answer: Number() attempts to convert the entire value. parseInt() reads an integer from the beginning of the input.

Q7. Why does "10" + 20 return "1020"?

Answer: The + operator performs string concatenation when string conversion applies to the operands.

Q8. Why does "10" - 5 return 5?

Answer: The subtraction operator converts the string "10" to the number 10 before subtraction.

Q9. What is NaN?

Answer: NaN means Not a Number. It is a special numeric value used to represent an invalid or unrepresentable numeric result.

Q10. What is the type of NaN?

Answer: number.

Q11. Why is NaN === NaN false?

Answer: NaN is defined to be unequal to every value, including itself. Use Number.isNaN() to test for it.

Q12. What is the difference between == and ===?

Answer: == allows type coercion during comparison. === compares without coercing different primitive types.

Q13. What does Boolean("false") return?

Answer: true, because a non-empty string is truthy, regardless of the text it contains.

Q14. What is the difference between isNaN() and Number.isNaN()?

Answer: isNaN() converts its argument to a number before checking. Number.isNaN() checks without coercion.

Q15. Why should form input values be converted before calculations?

Answer: HTML input values are generally strings. Conversion ensures numeric operations behave as intended.

13. Lecture Summary

  • Type conversion changes a value from one type to another.
  • Explicit conversion is performed intentionally by the programmer.
  • Implicit conversion is performed automatically by JavaScript.
  • Number() converts values into numbers when possible.
  • String() converts values into strings.
  • Boolean() converts values into Boolean values.
  • parseInt() extracts an integer from the beginning of a string.
  • parseFloat() extracts a floating-point number from the beginning of a string.
  • The + operator can perform concatenation or numeric addition.
  • Other arithmetic operators commonly perform numeric coercion.
  • == allows coercion; === avoids coercion between different primitive types.
  • NaN represents an invalid or unrepresentable numeric result.
  • Number.isNaN() checks for NaN without coercion.
  • Validate user input before using converted values.
