Chapter 2 – Lecture 5

If, Else, Switch and Conditional Statements

Make decisions in JavaScript using conditions, branches and control-flow statements.

1. Learning Objectives

After completing this lecture, you will be able to:

  • Use if and if...else statements.
  • Implement multiple conditions using an else if ladder.
  • Understand and write nested conditional statements.
  • Use switch, case, break and default.
  • Choose between if...else and switch.
  • Apply conditional logic to frontend development problems.
  • Predict program output and solve interview-style problems.

2. Introduction to Conditional Statements

Conditional statements control the execution of a program based on whether a specified condition evaluates to true or false.

For example, an application may need to:

  • Allow a user to log in only when credentials are valid.
  • Display a discount when an order meets a minimum amount.
  • Show a different message depending on examination marks.
  • Display an error when a form contains invalid information.
Important: Conditional statements use Boolean conditions. Comparisons such as age >= 18 produce Boolean results that determine which block executes.

3. The if Statement

The if statement executes a block of code only when its condition evaluates to true.

Syntax

if (condition) {
    // Code executes when condition is true
}

Example 1: Checking Voting Eligibility

let age = 22;

if (age >= 18) {
    console.log("Eligible to vote");
}

console.log("Program completed");
Expected Output: 
Eligible to vote
Program completed

Since age >= 18 evaluates to true, the statement inside the if block executes.

Example 2: Checking Product Availability

let stock = 12;

if (stock > 0) {
    console.log("Product is available");
}
Expected Output: 
Product is available

When the Condition Is False

let temperature = 15;

if (temperature > 30) {
    console.log("High temperature");
}

console.log("Check completed");
Expected Output: 
Check completed

4. The if...else Statement

The if...else statement provides two alternative execution paths. One executes when the condition is true, and the other executes when it is false.

Syntax

if (condition) {
    // Executes when condition is true
} else {
    // Executes when condition is false
}

Example 1: Even or Odd Number

let number = 17;

if (number % 2 === 0) {
    console.log("Even number");
} else {
    console.log("Odd number");
}
Expected Output: 
Odd number

The remainder operator checks whether the number is divisible by 2. A remainder of zero indicates an even number.

Example 2: Login Validation

let username = "admin";
let password = "admin123";

if (username === "admin" && password === "admin123") {
    console.log("Login successful");
} else {
    console.log("Invalid username or password");
}
Expected Output: 
Login successful
Practical note: This is only a demonstration of conditional logic. Real authentication must be implemented securely on a backend and must not rely on hardcoded credentials in frontend JavaScript.

5. The else if Ladder

An else if ladder is used when multiple conditions must be checked in sequence.

Syntax

if (condition1) {
    // First condition
} else if (condition2) {
    // Second condition
} else if (condition3) {
    // Third condition
} else {
    // Default block
}

JavaScript evaluates conditions from top to bottom. Once a condition is true, its associated block executes and the remaining branches are skipped.

Example 1: Student Grade Calculator

let marks = 82;

if (marks < 0 || marks > 100) {
    console.log("Invalid marks");
} else if (marks >= 90) {
    console.log("Grade A");
} else if (marks >= 80) {
    console.log("Grade B");
} else if (marks >= 70) {
    console.log("Grade C");
} else if (marks >= 60) {
    console.log("Grade D");
} else {
    console.log("Grade F");
}
Expected Output: 
Grade B

The order of conditions matters. Checking marks >= 60 before marks >= 90 would incorrectly classify higher marks as Grade D.

Example 2: Shipping Charges

let orderAmount = 1500;

if (orderAmount < 0) {
    console.log("Invalid order amount");
} else if (orderAmount >= 2000) {
    console.log("Free shipping");
} else if (orderAmount >= 1000) {
    console.log("Shipping charge: Rs. 50");
} else {
    console.log("Shipping charge: Rs. 100");
}
Expected Output: 
Shipping charge: Rs. 50

Example 3: Employee Access Status

let status = "pending";

if (status === "active") {
    console.log("Employee account is active");
} else if (status === "pending") {
    console.log("Account approval is pending");
} else if (status === "blocked") {
    console.log("Account is blocked");
} else {
    console.log("Unknown account status");
}
Expected Output: 
Account approval is pending

6. Nested if Statements

A nested if statement is an if statement placed inside another conditional block.

Syntax

if (condition1) {
    if (condition2) {
        // Executes when both conditions are true
    }
}

Example 1: Login and Role-Based Access

let isLoggedIn = true;
let role = "admin";

if (isLoggedIn) {
    console.log("User is logged in");

    if (role === "admin") {
        console.log("Access granted to admin dashboard");
    } else {
        console.log("Access granted to user dashboard");
    }
} else {
    console.log("Please log in first");
}
Expected Output: 
User is logged in
Access granted to admin dashboard

Example 2: Job Eligibility

let age = 23;
let qualification = "B.Tech";

if (age >= 18) {
    if (qualification === "B.Tech") {
        console.log("Eligible for this technical role");
    } else {
        console.log("Required qualification not available");
    }
} else {
    console.log("Minimum age requirement not met");
}
Expected Output: 
Eligible for this technical role

When Should You Avoid Nested if?

Excessive nesting makes code difficult to read, debug and maintain. For simple combined conditions, logical operators may provide a cleaner solution.

Nested approach:

let age = 25;
let hasID = true;

if (age >= 18) {
    if (hasID) {
        console.log("Entry allowed");
    }
}

Combined-condition approach:

let age = 25;
let hasID = true;

if (age >= 18 && hasID) {
    console.log("Entry allowed");
}
Output: 
Entry allowed

7. The switch Statement

The switch statement selects one execution path from multiple alternatives by comparing an expression against different case values.

Syntax

switch (expression) {
    case value1:
        // Statements
        break;

    case value2:
        // Statements
        break;

    default:
        // Default statements
}

Important Components

Component Purpose
switch Evaluates the expression.
case Defines a value to compare against the expression.
break Exits the switch statement.
default Executes when no case matches.

Example 1: Day of the Week

let day = 3;

switch (day) {
    case 1:
        console.log("Monday");
        break;

    case 2:
        console.log("Tuesday");
        break;

    case 3:
        console.log("Wednesday");
        break;

    case 4:
        console.log("Thursday");
        break;

    case 5:
        console.log("Friday");
        break;

    default:
        console.log("Invalid day");
}
Expected Output: 
Wednesday

Example 2: Multiple Cases Sharing One Block

Multiple case labels can share the same execution block. This is useful when several values require identical behavior. 

let day = "Saturday";

switch (day) {
    case "Saturday":
    case "Sunday":
        console.log("Weekend");
        break;

    case "Monday":
    case "Tuesday":
    case "Wednesday":
    case "Thursday":
    case "Friday":
        console.log("Working day");
        break;

    default:
        console.log("Invalid day");
}
Expected Output: 
Weekend

Example 3: Simple Calculator

let a = 20;
let b = 5;
let operator = "*";

switch (operator) {
    case "+":
        console.log(a + b);
        break;

    case "-":
        console.log(a - b);
        break;

    case "*":
        console.log(a * b);
        break;

    case "/":
        if (b !== 0) {
            console.log(a / b);
        } else {
            console.log("Cannot divide by zero");
        }
        break;

    default:
        console.log("Invalid operator");
}
Expected Output: 
100

7.1 Why Is break Important?

The break statement prevents execution from continuing into subsequent case blocks. Without it, JavaScript may execute later case statements even when their labels do not match. This behavior is called fall-through. 

let value = 1;

switch (value) {
    case 1:
        console.log("One");

    case 2:
        console.log("Two");

    case 3:
        console.log("Three");
        break;

    default:
        console.log("Other");
}
Expected Output: 
One
Two
Three

The first case matches. Since there is no break after it, execution continues through the following statements until a break is reached.

7.2 The default Case

The default block executes when none of the case values matches. It is conventionally written last, although JavaScript permits it elsewhere. 

let operation = "power";

switch (operation) {
    case "add":
        console.log("Addition");
        break;

    case "subtract":
        console.log("Subtraction");
        break;

    default:
        console.log("Unsupported operation");
}
Expected Output: 
Unsupported operation

7.3 switch Uses Strict Comparison

A switch statement compares the expression with case values using strict equality semantics. Therefore, both value and type must match. 

let value = "10";

switch (value) {
    case 10:
        console.log("Number ten");
        break;

    case "10":
        console.log("String ten");
        break;

    default:
        console.log("No match");
}
Expected Output: 
String ten
Interview point: The string "10" does not match the number 10 in a switch case.

8. if...else vs switch

Feature if...else switch
Primary purpose Evaluate conditions. Match an expression against case values.
Ranges Suitable for ranges. Not directly suitable for ranges.
Complex conditions Supports relational and logical operators. Uses exact case-value matching.
Comparison Depends on the operators used. Strict equality semantics.
Fall-through No case fall-through behavior. Possible when break is omitted.
Best use Eligibility, validation, ranges. Menu choices, status values, fixed options.

Use if...else for Ranges

let salary = 45000;

if (salary < 20000) {
    console.log("Entry-level range");
} else if (salary <= 50000) {
    console.log("Mid-level range");
} else {
    console.log("Higher salary range");
}
Expected Output: 
Mid-level range

Use switch for Exact Values

let orderStatus = "shipped";

switch (orderStatus) {
    case "placed":
        console.log("Order placed");
        break;

    case "shipped":
        console.log("Order is on the way");
        break;

    case "delivered":
        console.log("Order delivered");
        break;

    case "cancelled":
        console.log("Order cancelled");
        break;

    default:
        console.log("Unknown order status");
}
Expected Output: 
Order is on the way

9. Conditional Logic in Frontend Development

Conditional statements are used extensively in frontend applications to control what users see and how the interface responds to application state.

Example 1: Loading, Error and Success States

let status = "loading";

if (status === "loading") {
    console.log("Loading data...");
} else if (status === "error") {
    console.log("Something went wrong");
} else if (status === "success") {
    console.log("Data loaded successfully");
} else {
    console.log("Unknown status");
}
Expected Output: 
Loading data...

Example 2: Form Validation

let email = "user@example.com";
let password = "pass1234";

if (email === "" || password === "") {
    console.log("All fields are required");
} else if (!email.includes("@")) {
    console.log("Invalid email address");
} else if (password.length < 8) {
    console.log("Password must contain at least 8 characters");
} else {
    console.log("Form validation successful");
}
Expected Output: 
Form validation successful

This demonstrates basic client-side validation. Production applications should also validate data on the server.

Example 3: Product Stock Status

let stock = 0;

if (stock > 10) {
    console.log("In stock");
} else if (stock > 0) {
    console.log("Limited stock");
} else {
    console.log("Out of stock");
}
Expected Output: 
Out of stock

Example 4: Role-Based UI Message

let userRole = "editor";

switch (userRole) {
    case "admin":
        console.log("Show admin dashboard");
        break;

    case "editor":
        console.log("Show content editor");
        break;

    case "viewer":
        console.log("Show read-only dashboard");
        break;

    default:
        console.log("Show guest page");
}
Expected Output: 
Show content editor

10. Best Practices and Common Mistakes

10.1 Always Use Braces

Prefer braces even when a block contains only one statement.

// Recommended
if (isLoggedIn) {
    console.log("Welcome");
}

// Avoid in production code
if (isLoggedIn)
    console.log("Welcome");

10.2 Use Comparison Operators Correctly

let age = 20;

// Correct
if (age === 20) {
    console.log("Age is 20");
}

// Incorrect for comparison
// if (age = 20) {
//     console.log("Age is 20");
// }

A single = assigns a value. It does not perform equality comparison. Use === when strict equality is intended.

10.3 Arrange Range Conditions Carefully

let marks = 95;

// Correct order
if (marks >= 90) {
    console.log("A");
} else if (marks >= 75) {
    console.log("B");
} else if (marks >= 50) {
    console.log("C");
} else {
    console.log("Fail");
}

10.4 Use Guard Clauses to Reduce Nesting

A guard clause handles invalid or exceptional conditions early, allowing the main logic to remain less nested. 

function processOrder(order) {
    if (!order) {
        console.log("Order is missing");
        return;
    }

    if (order.quantity <= 0) {
        console.log("Invalid quantity");
        return;
    }

    console.log("Processing order");
}

processOrder({ quantity: 2 });
Expected Output: 
Processing order

The return statement exits the function when a guard condition is met. It prevents the remaining function statements from executing.

10.5 Avoid Unnecessary Deep Nesting

Use logical operators where they make the condition easier to understand. Keep complex business rules separated into well-named functions when appropriate.

10.6 Do Not Forget break in switch

Missing break may cause unintended fall-through. Omit it only when fall-through is deliberate and clearly documented.

11. Placement Interview Questions and Answers

Q1. What are conditional statements in JavaScript?

Conditional statements control program execution based on Boolean conditions. Common conditional statements include if, if...else, else if and switch.

Q2. What is the difference between if and if...else?

An if statement executes a block only when its condition is true. An if...else statement provides an alternative block when the condition is false.

Q3. What is an else if ladder?

It checks multiple conditions sequentially. The first true condition determines which block executes.

Q4. What is a nested if statement?

It is an if statement placed inside another if or conditional block.

Q5. What is the purpose of switch?

It selects a block of code by comparing an expression against multiple exact case values.

Q6. Why is break used in switch?

It exits the switch statement and prevents execution from falling through into subsequent cases.

Q7. What happens if break is omitted?

Execution continues into the following case statements until a break or the end of the switch is reached. This is called fall-through.

Q8. Is default mandatory in switch?

No. It is optional, but recommended when an unmatched value needs to be handled.

Q9. Does switch use loose or strict equality?

Switch case matching uses strict equality semantics. For example, the number 10 does not match the string "10".

Q10. Can default appear before other cases?

Yes. JavaScript allows default to appear anywhere inside the switch. However, it is conventionally placed last. If execution reaches default without a break, subsequent statements may execute.

Q11. When should you use if...else instead of switch?

Use if...else for relational comparisons, ranges and compound logical conditions. Use switch for multiple discrete exact values.

Q12. What is a guard clause?

A guard clause checks an invalid or exceptional condition early and exits the function, reducing unnecessary nesting.

13. Coding Exercises

Write and test the following programs independently.

Exercise 1: Positive, Negative or Zero

Accept a number and determine whether it is positive, negative or zero using an if...else if ladder.

Exercise 2: Largest of Three Numbers

Compare three numbers and print the largest. Also handle the possibility that two or more numbers are equal.

Exercise 3: Leap Year Checker

A year is a leap year if it is divisible by 400, or if it is divisible by 4 but not divisible by 100.

Exercise 4: Electricity Bill Calculator

Calculate an electricity bill using these sample slabs:

  • First 100 units: Rs. 2 per unit.
  • Next 100 units: Rs. 3 per unit.
  • Above 200 units: Rs. 5 per unit.

Apply each rate only to the units within its slab. Reject negative unit values.

Exercise 5: Menu-Driven Calculator

Use switch to perform addition, subtraction, multiplication and division based on an operator variable. Handle division by zero.

Exercise 6: Login and Role Access

Use nested conditions to check whether a user is logged in and whether their role is admin, editor or viewer.

Exercise 7: Order Status Manager

Use switch to display suitable messages for placed, confirmed, shipped, delivered and cancelled orders. Handle unknown status values.

Exercise 8: Form Validation

Validate name, email and password. Check empty fields, basic email format and minimum password length.

14. Lecture Summary

  • if executes code when a condition is true.
  • if...else provides two execution paths.
  • else if checks multiple conditions sequentially.
  • Nested conditions handle dependent decisions.
  • switch matches an expression against exact case values.
  • break prevents unintended fall-through.
  • default handles unmatched switch values.
  • Use if/else for ranges and complex conditions.
  • Use switch for discrete values and fixed options.
  • Guard clauses help reduce unnecessary nesting.
