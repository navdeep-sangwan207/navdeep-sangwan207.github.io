Symbols, Iterators and Generators Basics

Understand unique Symbol values, well-known symbols, JavaScript iteration protocols, custom iterable objects and generator functions through practical examples and placement-oriented coding problems.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Understand Symbol as a primitive data type.
  • Create unique Symbol values.
  • Use Symbols as object property keys.
  • Understand Symbol.for() and Symbol.keyFor().
  • Identify important well-known Symbols.
  • Understand iterable and iterator protocols.
  • Use Symbol.iterator to create custom iterables.
  • Understand generator functions and the yield keyword.
  • Use yield* to delegate iteration.
  • Apply iterators and generators to practical coding problems.

2. Introduction to Symbol

2.1 What Is a Symbol?

Symbol is a primitive data type in JavaScript introduced in ECMAScript 2015 (ES6).

Every Symbol created using Symbol() is unique, even when the same description is supplied.

Syntax:

const id = Symbol();
const idWithDescription = Symbol("userId");

2.2 Creating Symbols

const first = Symbol();
const second = Symbol();

console.log(typeof first);
console.log(first === second);
Expected Output: 
symbol
false

2.3 Symbols with the Same Description

const symbol1 = Symbol("user");
const symbol2 = Symbol("user");

console.log(symbol1 === symbol2);
console.log(symbol1.description);
console.log(symbol2.description);
Expected Output: 
false
user
user

A Symbol description is only a debugging label. It does not determine the identity of the Symbol.

3. Symbol as an Object Property Key

3.1 Creating Symbol Properties

const userId = Symbol("id");

const user = {
    name: "Rahul",
    [userId]: 101
};

console.log(user.name);
console.log(user[userId]);
Expected Output: 
Rahul
101

3.2 Adding Symbol Properties Later

const accountId = Symbol("accountId");

const account = {
    name: "Amit"
};

account[accountId] = 5001;

console.log(account[accountId]);
Expected Output: 
5001

3.3 Why Use Symbol Keys?

Symbol keys help avoid accidental property-name collisions when multiple libraries or parts of an application add properties to the same object. 

const internalId = Symbol("id");

const user = {
    id: 101,
    name: "Rahul",
    [internalId]: "INTERNAL-USER-101"
};

console.log(user.id);
console.log(user[internalId]);
Expected Output: 
101
INTERNAL-USER-101
Important: Symbol properties are not automatically private or inaccessible. Code that obtains the Symbol key can access the property.

4. Accessing Symbol Properties

4.1 Object.keys()

const id = Symbol("id");

const user = {
    name: "Rahul",
    age: 22,
    [id]: 101
};

console.log(Object.keys(user));
Expected Output: 
["name", "age"]

Object.keys() returns enumerable string-keyed property names. It does not return Symbol keys.

4.2 Object.getOwnPropertySymbols()

const id = Symbol("id");

const user = {
    name: "Rahul",
    [id]: 101
};

const symbols = Object.getOwnPropertySymbols(user);

console.log(symbols.length);
console.log(symbols[0] === id);
console.log(user[symbols[0]]);
Expected Output:

true

4.3 Reflect.ownKeys()

const id = Symbol("id");

const user = {
    name: "Rahul",
    age: 22,
    [id]: 101
};

console.log(Reflect.ownKeys(user));
Expected Output: 
["name", "age", Symbol(id)]

Reflect.ownKeys() returns all own string and Symbol property keys, including non-enumerable properties.

5. Global Symbol Registry

5.1 Symbol.for()

Symbol.for() searches for a Symbol using a key in the global Symbol registry. If one exists, it returns that Symbol. Otherwise, it creates and registers a new one. 

const first = Symbol.for("applicationId");
const second = Symbol.for("applicationId");

console.log(first === second);
Expected Output: 
true

5.2 Symbol.keyFor()

Symbol.keyFor() returns the registry key associated with a globally registered Symbol. 

const id = Symbol.for("userId");

console.log(Symbol.keyFor(id));
Expected Output: 
userId

5.3 Local Symbol vs Registered Symbol

const localSymbol = Symbol("local");
const globalSymbol = Symbol.for("global");

console.log(Symbol.keyFor(localSymbol));
console.log(Symbol.keyFor(globalSymbol));
Expected Output: 
undefined
global

6. Well-Known Symbols

JavaScript provides built-in Symbols called well-known Symbols. They allow developers to customize certain built-in language behaviours.

Symbol Purpose
Symbol.iterator Defines the default iterator for an object.
Symbol.toPrimitive Customizes object-to-primitive conversion.
Symbol.toStringTag Customizes the tag used by Object.prototype.toString().
Symbol.hasInstance Customizes instanceof behaviour.
Symbol.isConcatSpreadable Controls whether an object is flattened by concat().
Symbol.match Customizes behaviour of String.prototype.match().
Symbol.replace Customizes behaviour of String.prototype.replace().
Symbol.search Customizes behaviour of String.prototype.search().
Symbol.split Customizes behaviour of String.prototype.split().
Symbol.species Controls the constructor used by certain derived objects.
Symbol.toStringTag Controls the built-in object tag.

6.1 Symbol.toStringTag

const user = {
    [Symbol.toStringTag]: "User"
};

console.log(Object.prototype.toString.call(user));
Expected Output: 
[object User]

6.2 Symbol.hasInstance

class EvenNumber {
    static [Symbol.hasInstance](value) {
        return Number.isInteger(value) && value % 2 === 0;
    }
}

console.log(4 instanceof EvenNumber);
console.log(5 instanceof EvenNumber);
Expected Output: 
true
false

6.3 Symbol.toPrimitive

const product = {
    price: 100,

    [Symbol.toPrimitive](hint) {
        if (hint === "number") {
            return this.price;
        }

        if (hint === "string") {
            return "Product Price";
        }

        return this.price;
    }
};

console.log(+product);
console.log(String(product));
console.log(product + 50);
Expected Output: 
100
Product Price
150
Placement Focus: Understand Symbol uniqueness, Symbol.for(), Symbol.keyFor() and Symbol.iterator particularly well. Know that well-known Symbols customize built-in JavaScript behaviour.

7. Introduction to Iteration

7.1 What Is Iteration?

Iteration means accessing elements of a collection one at a time. JavaScript supports iteration through loops and the iterable protocol. 

const numbers = [10, 20, 30];

for (const number of numbers) {
    console.log(number);
}
Expected Output: 
10
20
30

7.2 Common Iterables

  • Arrays
  • Strings
  • Maps
  • Sets
  • Typed arrays
  • Some DOM collections, such as NodeList in modern browsers
  • Custom objects implementing the iterable protocol

7.3 Iterable vs Non-Iterable

Value Iterable?
Array Yes
String Yes
Map Yes
Set Yes
Plain object No, by default
Number No
Boolean No 
const user = {
    name: "Rahul",
    age: 22
};

for (const value of user) {
    console.log(value);
}

Result:

TypeError: user is not iterable

A plain object does not implement the iterable protocol automatically. Object.keys(), Object.values() and Object.entries() can be used to obtain arrays for iteration.

8. Iterable Protocol and Iterator Protocol

8.1 Iterable Protocol

An object is iterable when it provides a method under the key Symbol.iterator. Calling that method must return an iterator object.

8.2 Iterator Protocol

An iterator is an object that provides a next() method. Each call to next() returns an object containing:

  • value — the current yielded value.
  • done — indicates whether iteration has finished.

Typical result:

{
    value: 10,
    done: false
}

8.3 Getting an Array Iterator

const numbers = [10, 20, 30];

const iterator = numbers[Symbol.iterator]();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
Expected Output: 
{ value: 10, done: false }
{ value: 20, done: false }
{ value: 30, done: false }
{ value: undefined, done: true }

8.4 Understanding next()

const values = ["A", "B"];

const iterator = values[Symbol.iterator]();

const first = iterator.next();
const second = iterator.next();
const third = iterator.next();

console.log(first.value);
console.log(first.done);

console.log(second.value);
console.log(second.done);

console.log(third.value);
console.log(third.done);
Expected Output: 
A
false
B
false
undefined

9. Creating a Custom Iterator

9.1 Manual Iterator Implementation

A custom iterator can be created by defining a next() method that returns the required iterator result object. 

const numberIterator = {
    current: 1,
    last: 3,

    next() {
        if (this.current <= this.last) {
            return {
                value: this.current++,
                done: false
            };
        }

        return {
            value: undefined,
            done: true
        };
    }
};

console.log(numberIterator.next());
console.log(numberIterator.next());
console.log(numberIterator.next());
console.log(numberIterator.next());
Expected Output: 
{ value: 1, done: false }
{ value: 2, done: false }
{ value: 3, done: false }
{ value: undefined, done: true }

9.2 Important Limitation

The previous object is an iterator, but it is not automatically iterable. It does not provide Symbol.iterator.

To use it directly with for...of, it must also implement the iterable protocol. 

const numberIterator = {
    current: 1,
    last: 3,

    next() {
        if (this.current <= this.last) {
            return {
                value: this.current++,
                done: false
            };
        }

        return {
            value: undefined,
            done: true
        };
    },

    [Symbol.iterator]() {
        return this;
    }
};

for (const number of numberIterator) {
    console.log(number);
}
Expected Output: 
1
2
3

10. Creating Custom Iterable Objects

10.1 Implementing Symbol.iterator

We can make a custom object iterable by implementing Symbol.iterator and returning an iterator. 

const range = {
    start: 1,
    end: 5,

    [Symbol.iterator]() {
        let current = this.start;
        const end = this.end;

        return {
            next() {
                if (current <= end) {
                    return {
                        value: current++,
                        done: false
                    };
                }

                return {
                    value: undefined,
                    done: true
                };
            }
        };
    }
};

for (const number of range) {
    console.log(number);
}
Expected Output: 
1
2
3
4
5

10.2 Using a Custom Iterable with Spread

const range = {
    start: 1,
    end: 4,

    [Symbol.iterator]() {
        let current = this.start;
        const end = this.end;

        return {
            next() {
                return current <= end
                    ? { value: current++, done: false }
                    : { value: undefined, done: true };
            }
        };
    }
};

const numbers = [...range];

console.log(numbers);
Expected Output: 
[1, 2, 3, 4]

10.3 Using a Custom Iterable with Array.from()

const letters = {
    [Symbol.iterator]() {
        let index = 0;
        const values = ["A", "B", "C"];

        return {
            next() {
                if (index < values.length) {
                    return {
                        value: values[index++],
                        done: false
                    };
                }

                return {
                    value: undefined,
                    done: true
                };
            }
        };
    }
};

console.log(Array.from(letters));
Expected Output: 
["A", "B", "C"]

11. Generator Functions

11.1 What Is a Generator?

A generator is a special function that can pause execution and later resume from where it stopped.

Generator functions use the function* syntax and the yield keyword.

Syntax:

function* generatorName() {
    yield value1;
    yield value2;
}

11.2 Creating a Generator

function* generateNumbers() {
    yield 10;
    yield 20;
    yield 30;
}

const generator = generateNumbers();

console.log(generator.next());
console.log(generator.next());
console.log(generator.next());
console.log(generator.next());
Expected Output: 
{ value: 10, done: false }
{ value: 20, done: false }
{ value: 30, done: false }
{ value: undefined, done: true }

11.3 Generator Execution Is Lazy

function* testGenerator() {
    console.log("First step");

    yield 1;

    console.log("Second step");

    yield 2;

    console.log("Finished");
}

const generator = testGenerator();

console.log("Generator created");

console.log(generator.next());
console.log(generator.next());
console.log(generator.next());
Expected Output: 
Generator created
First step
{ value: 1, done: false }
Second step
{ value: 2, done: false }
Finished
{ value: undefined, done: true }

Calling a generator function creates a generator object. The function body does not execute until next() is called.

12. Understanding the yield Keyword

12.1 Pausing Execution with yield

The yield keyword produces a value and pauses the generator until the next request. 

function* demo() {
    console.log("A");

    yield 100;

    console.log("B");

    yield 200;

    console.log("C");
}

const gen = demo();

gen.next();
gen.next();
gen.next();
Expected Output: 
A
B
C

12.2 Returning a Value from a Generator

function* numbers() {
    yield 10;
    yield 20;
    return 30;
}

const gen = numbers();

console.log(gen.next());
console.log(gen.next());
console.log(gen.next());
console.log(gen.next());
Expected Output: 
{ value: 10, done: false }
{ value: 20, done: false }
{ value: 30, done: true }
{ value: undefined, done: true }
Important Interview Point: A value returned using return() or a generator's return statement has done: true. Standard for...of iteration does not include that final return value.

12.3 Passing Values into a Generator

The value passed to next() becomes the result of the currently suspended yield expression. 

function* calculator() {
    const first = yield "Enter first value";

    const second = yield "Enter second value";

    return first + second;
}

const gen = calculator();

console.log(gen.next());
console.log(gen.next(10));
console.log(gen.next(20));
Expected Output: 
{ value: "Enter first value", done: false }
{ value: "Enter second value", done: false }
{ value: 30, done: true }

The first next() starts the generator and reaches the first yield. Its argument, if supplied, is not used as the value of that first yield expression.

13. Generator Objects Are Iterators and Iterables

A generator object implements both the iterator and iterable protocols. Its Symbol.iterator method returns the generator object itself. 

function* colors() {
    yield "Red";
    yield "Green";
    yield "Blue";
}

const generator = colors();

console.log(generator[Symbol.iterator]() === generator);

for (const color of generator) {
    console.log(color);
}
Expected Output: 
true
Red
Green
Blue

13.1 Converting Generator Output into an Array

function* numbers() {
    yield 1;
    yield 2;
    yield 3;
}

const result = [...numbers()];

console.log(result);
Expected Output: 
[1, 2, 3]

14. yield* Delegation

14.1 What Is yield*?

yield* delegates iteration to another iterable or generator. It allows one generator to produce values from another iterable. 

function* first() {
    yield 1;
    yield 2;
}

function* second() {
    yield* first();
    yield 3;
}

console.log([...second()]);
Expected Output: 
[1, 2, 3]

14.2 Delegating to an Array

function* generateValues() {
    yield* [10, 20, 30];
}

console.log([...generateValues()]);
Expected Output: 
[10, 20, 30]

14.3 Delegating to a String

function* generateLetters() {
    yield* "ABC";
}

console.log([...generateLetters()]);
Expected Output: 
["A", "B", "C"]

14.4 Delegating to Another Generator

function* numbers() {
    yield 1;
    yield 2;
}

function* allValues() {
    yield 0;
    yield* numbers();
    yield 3;
}

for (const value of allValues()) {
    console.log(value);
}
Expected Output: 
0
1
2
3

15. Generator Methods: next(), return() and throw()

15.1 next()

next() resumes generator execution and returns an iterator result object. 

function* values() {
    yield 10;
    yield 20;
}

const gen = values();

console.log(gen.next());
console.log(gen.next());
Expected Output: 
{ value: 10, done: false }
{ value: 20, done: false }

15.2 return()

return() terminates the generator and returns the supplied value as a completed iterator result. 

function* values() {
    yield 10;
    yield 20;
    yield 30;
}

const gen = values();

console.log(gen.next());
console.log(gen.return("Stopped"));
console.log(gen.next());
Expected Output: 
{ value: 10, done: false }
{ value: "Stopped", done: true }
{ value: undefined, done: true }

15.3 throw()

throw() injects an exception at the suspended yield expression. The generator can catch the exception using try...catch. 

function* task() {
    try {
        yield "Task started";
        yield "Task running";
    } catch (error) {
        yield "Handled: " + error.message;
    }
}

const gen = task();

console.log(gen.next());
console.log(gen.throw(new Error("Task failed")));
console.log(gen.next());
Expected Output: 
{ value: "Task started", done: false }
{ value: "Handled: Task failed", done: false }
{ value: undefined, done: true }

16. Practical Applications of Generators

16.1 Generate a Number Range

function* range(start, end) {
    for (let number = start; number <= end; number++) {
        yield number;
    }
}

console.log([...range(1, 5)]);
Expected Output: 
[1, 2, 3, 4, 5]

16.2 Generate Even Numbers

function* evenNumbers(limit) {
    for (let number = 2; number <= limit; number += 2) {
        yield number;
    }
}

for (const number of evenNumbers(10)) {
    console.log(number);
}
Expected Output: 
2
4
6
8
10

16.3 Generate Fibonacci Numbers

function* fibonacci(count) {
    let first = 0;
    let second = 1;

    for (let index = 0; index < count; index++) {
        yield first;

        const next = first + second;

        first = second;
        second = next;
    }
}

console.log([...fibonacci(7)]);
Expected Output: 
[0, 1, 1, 2, 3, 5, 8]

16.4 Generate Unique IDs

function* idGenerator() {
    let id = 1;

    while (true) {
        yield id++;
    }
}

const ids = idGenerator();

console.log(ids.next().value);
console.log(ids.next().value);
console.log(ids.next().value);
Expected Output: 
1
2
3
Important: Infinite generators should be consumed carefully. Do not pass an infinite generator directly to operations such as spread or Array.from(), because those operations attempt to consume the entire iterable.

16.5 Process Data in Batches

function* batches(array, batchSize) {
    for (let index = 0; index < array.length; index += batchSize) {
        yield array.slice(index, index + batchSize);
    }
}

const records = [1, 2, 3, 4, 5, 6, 7];

for (const batch of batches(records, 3)) {
    console.log(batch);
}
Expected Output: 
[1, 2, 3]
[4, 5, 6]
[7]

Creation Manually creates an object with next(). Uses function* syntax.

Complexity More implementation code. Usually simpler for sequential value production.

18. Common Mistakes and Debugging

Mistake 1: Expecting Symbols with the Same Description to Match

const a = Symbol("id");
const b = Symbol("id");

console.log(a === b);

Output:

false

Use Symbol.for() when you intentionally need to retrieve the same registered Symbol by key.

Mistake 2: Using Object.keys() to Find Symbol Properties

const id = Symbol("id");

const user = {
    [id]: 101
};

console.log(Object.keys(user));

Output:

[]

Use Object.getOwnPropertySymbols() or Reflect.ownKeys() to inspect Symbol keys.

Mistake 3: Using for...of on a Plain Object

const user = {
    name: "Rahul"
};

for (const value of user) {
    console.log(value);
}

Result:

TypeError: user is not iterable

Use Object.entries(user), or implement Symbol.iterator when custom iteration is required.

Mistake 4: Expecting a Generator to Run Immediately

function* test() {
    console.log("Running");
    yield 1;
}

const gen = test();

console.log("Created");

Output:

Created

Call next() to begin executing the generator body.

Mistake 5: Expecting return() Values in for...of

function* values() {
    yield 1;
    return 2;
}

console.log([...values()]);

Output:

[1]

for...of and spread consume yielded values but do not include a generator's final return value.

Mistake 6: Consuming an Infinite Generator Completely

function* numbers() {
    let number = 1;

    while (true) {
        yield number++;
    }
}

// Do not execute:
// const values = [...numbers()];

An infinite generator never finishes naturally. Consume a limited number of values instead.

19. Placement Interview Questions and Answers

Q1. What is Symbol in JavaScript?

Symbol is a primitive data type that provides unique values. It is commonly used as an object property key to avoid accidental naming collisions.

Q2. Are two Symbols with the same description equal?

No. Symbol() creates a new unique Symbol every time.

Q3. What is Symbol.for()?

It retrieves or creates a Symbol in the global Symbol registry using a specified key.

Q4. What is Symbol.keyFor()?

It returns the registry key of a registered Symbol. It returns undefined for a locally created Symbol.

Q5. What is Symbol.iterator?

It is a well-known Symbol used to define the method that returns an iterator for an iterable object.

Q6. What is an iterable?

An object that implements the iterable protocol by providing a Symbol.iterator method.

Q7. What is an iterator?

An object that implements next() and returns iterator result objects containing value and done properties.

Q8. What is the difference between iterable and iterator?

An iterable provides an iterator through Symbol.iterator. An iterator produces values through next().

Q9. What is a generator function?

A generator function is declared using function* and produces a generator object that can pause and resume execution using yield.

Q10. What is yield?

yield produces a value and suspends generator execution until the next request.

Q11. What is the difference between yield and return?

yield pauses a generator and allows it to continue later. return completes the generator.

Q12. What is yield*?

yield* delegates value production to another iterable or generator.

Q13. Are generators iterable?

Yes. Generator objects implement both iterator and iterable protocols.

Q14. Does a generator execute when it is created?

No. Its body starts executing when next() is called.

Q15. Can a generator receive values?

Yes. Values passed to subsequent next() calls become the results of suspended yield expressions.

Q16. What happens when a generator finishes?

It returns an iterator result with done: true. Further next() calls normally return value: undefined and done: true.

Q17. Can a plain object be used with for...of?

Not by default. It must implement the iterable protocol or be converted into an iterable representation.

Q18. What is the advantage of generators?

Generators provide lazy value production, automatic state management and convenient pause-and-resume execution.

Problem 3: Create a Custom Iterable for an Array-Like Object

const collection = {
    items: ["HTML", "CSS", "JavaScript"],

    [Symbol.iterator]() {
        let index = 0;
        const items = this.items;

        return {
            next() {
                if (index < items.length) {
                    return {
                        value: items[index++],
                        done: false
                    };
                }

                return {
                    value: undefined,
                    done: true
                };
            }
        };
    }
};

console.log([...collection]);
Expected Output: 
["HTML", "CSS", "JavaScript"]

Problem 6: Create a Generator for Batch Processing

function* splitIntoBatches(items, size) {
    for (let i = 0; i < items.length; i += size) {
        yield items.slice(i, i + size);
    }
}

const tasks = [1, 2, 3, 4, 5, 6, 7, 8];

for (const batch of splitIntoBatches(tasks, 3)) {
    console.log(batch);
}
Expected Output: 
[1, 2, 3]
[4, 5, 6]
[7, 8]
