Enhanced Object Literals and Computed Properties

Learn modern JavaScript object creation techniques including property shorthand, method shorthand, computed property names, dynamic keys and practical object configuration patterns.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Understand enhanced object literals introduced in ES6.
  • Use property shorthand when variable names match property names.
  • Define methods using concise method syntax.
  • Create computed property names using expressions.
  • Generate object keys dynamically.
  • Understand property name evaluation.
  • Use object literals for reusable configuration and data structures.
  • Apply these techniques in frontend development and coding interviews.

2. Introduction to Object Literals

An object literal is a way to create an object directly using curly braces {}. It stores data in key-value pairs and can also contain methods. 

const employee = {
    name: "Rahul",
    age: 25,
    department: "Development"
};

console.log(employee.name);
console.log(employee.age);
Expected Output: 
Rahul
25

Before ES6, developers often repeated property names and variable names while creating objects. ES6 introduced enhanced object literal features to reduce unnecessary syntax.

3. Property Shorthand

3.1 Traditional Object Property Syntax

Consider a situation where variables are used as object property values. 

const name = "Rahul";
const age = 25;
const city = "Chandigarh";

const employee = {
    name: name,
    age: age,
    city: city
};

console.log(employee);
Expected Output: 
{
    name: "Rahul",
    age: 25,
    city: "Chandigarh"
}

The property name and variable name are identical. Repeating the same name is unnecessary.

3.2 ES6 Property Shorthand Syntax

const name = "Rahul";
const age = 25;
const city = "Chandigarh";

const employee = {
    name,
    age,
    city
};

console.log(employee);
Expected Output: 
{
    name: "Rahul",
    age: 25,
    city: "Chandigarh"
}

JavaScript automatically uses each variable name as the corresponding property name.

3.3 Mixing Shorthand and Normal Properties

const name = "Amit";
const age = 26;

const employee = {
    name,
    age,
    department: "Testing",
    salary: 45000
};

console.log(employee);
Expected Output: 
{
    name: "Amit",
    age: 26,
    department: "Testing",
    salary: 45000
}

3.4 Property Shorthand in Functions

function createEmployee(name, role, salary) {
    return {
        name,
        role,
        salary
    };
}

const employee = createEmployee(
    "Rahul",
    "Frontend Developer",
    50000
);

console.log(employee.name);
console.log(employee.role);
console.log(employee.salary);
Expected Output: 
Rahul
Frontend Developer
50000
Placement Tip: Property shorthand is frequently used in functions that construct objects from function parameters.

4. Method Shorthand

4.1 Traditional Method Definition

An object can contain functions as property values. Traditionally, methods were defined using the function expression syntax. 

const employee = {
    name: "Rahul",

    displayDetails: function() {
        console.log("Employee: " + this.name);
    }
};

employee.displayDetails();
Expected Output: 
Employee: Rahul

4.2 ES6 Method Shorthand

ES6 allows methods to be written without the function keyword and colon. 

const employee = {
    name: "Rahul",

    displayDetails() {
        console.log("Employee: " + this.name);
    }
};

employee.displayDetails();
Expected Output: 
Employee: Rahul

4.3 Methods with Parameters

const calculator = {
    add(a, b) {
        return a + b;
    },

    subtract(a, b) {
        return a - b;
    },

    multiply(a, b) {
        return a * b;
    }
};

console.log(calculator.add(10, 5));
console.log(calculator.subtract(10, 5));
console.log(calculator.multiply(10, 5));
Expected Output: 
15
5
50

4.4 Method Shorthand with this

const product = {
    name: "Laptop",
    price: 55000,
    quantity: 2,

    getTotal() {
        return this.price * this.quantity;
    }
};

console.log(product.getTotal());
Expected Output: 
110000

In a method called as product.getTotal(), this refers to the object before the dot: product.

Important: Concise object methods have their own dynamic this binding. They are not arrow functions. Their behaviour differs from arrow functions, which inherit this lexically.

5. Computed Property Names

5.1 What Are Computed Property Names?

Computed property names allow JavaScript expressions to determine object property names dynamically.

The expression is written inside square brackets [] in an object literal.

5.2 Basic Computed Property Example

const propertyName = "name";

const employee = {
    [propertyName]: "Rahul"
};

console.log(employee.name);
Expected Output: 
Rahul

JavaScript evaluates propertyName and uses its value, "name", as the property key.

5.3 Dynamic Property Names

const key1 = "firstName";
const key2 = "lastName";

const employee = {
    [key1]: "Rahul",
    [key2]: "Sharma"
};

console.log(employee.firstName);
console.log(employee.lastName);
Expected Output: 
Rahul
Sharma

5.4 Computed Property Names Using Expressions

const prefix = "employee";

const data = {
    [prefix + "Id"]: 101,
    [prefix + "Name"]: "Amit"
};

console.log(data.employeeId);
console.log(data.employeeName);
Expected Output: 
101
Amit

5.5 Computed Property Names Using Template Literals

const section = "user";
const field = "Name";

const data = {
    [`${section}${field}`]: "Rahul"
};

console.log(data.userName);
Expected Output: 
Rahul

5.6 Computed Property Names with Arithmetic Expressions

const index = 2;

const scores = {
    ["score" + index]: 95,
    ["score" + (index + 1)]: 88
};

console.log(scores.score2);
console.log(scores.score3);
Expected Output: 
95
88

6. Dynamic Object Property Creation

6.1 Creating Properties from Variables

function createRecord(key, value) {
    return {
        [key]: value
    };
}

const result = createRecord("status", "Active");

console.log(result.status);
Expected Output: 
Active

6.2 Dynamic Object Keys in a Loop

const fields = ["name", "age", "city"];
const values = ["Rahul", 25, "Delhi"];

const employee = {};

for (let i = 0; i < fields.length; i++) {
    employee[fields[i]] = values[i];
}

console.log(employee);
Expected Output: 
{
    name: "Rahul",
    age: 25,
    city: "Delhi"
}

6.3 Creating an Object with Dynamic Keys Using reduce()

const fields = ["name", "role", "city"];
const values = ["Amit", "Developer", "Chandigarh"];

const employee = fields.reduce((result, field, index) => {
    result[field] = values[index];
    return result;
}, {});

console.log(employee);
Expected Output: 
{
    name: "Amit",
    role: "Developer",
    city: "Chandigarh"
}

6.4 Updating a Dynamic Property

const property = "salary";

const employee = {
    name: "Rahul",
    salary: 40000
};

const updatedEmployee = {
    ...employee,
    [property]: 55000
};

console.log(updatedEmployee);
Expected Output: 
{
    name: "Rahul",
    salary: 55000
}

7. Combining Enhanced Object Literal Features

Property shorthand, method shorthand and computed property names can be combined in a single object.

7.1 Combined Example

const name = "Rahul";
const age = 25;
const property = "department";

const employee = {
    name,
    age,

    [property]: "Development",

    displayDetails() {
        return `${this.name} works in ${this.department}`;
    }
};

console.log(employee);
console.log(employee.displayDetails());
Expected Output: 
{
    name: "Rahul",
    age: 25,
    department: "Development",
    displayDetails: function
}

Rahul works in Development

7.2 Dynamic Method Names

Computed property names can also be used to define methods. 

const action = "display";

const employee = {
    name: "Amit",

    [action]() {
        console.log(`Employee: ${this.name}`);
    }
};

employee.display();
Expected Output: 
Employee: Amit

7.3 Multiple Dynamic Methods

const actionOne = "start";
const actionTwo = "stop";

const machine = {
    status: "Idle",

    [actionOne]() {
        this.status = "Running";
    },

    [actionTwo]() {
        this.status = "Stopped";
    }
};

machine.start();
console.log(machine.status);

machine.stop();
console.log(machine.status);
Expected Output: 
Running
Stopped

8. Practical Frontend Development Applications

8.1 Creating User Objects

function createUser(name, email, role) {
    return {
        name,
        email,
        role,

        getProfile() {
            return `${this.name} (${this.role})`;
        }
    };
}

const user = createUser(
    "Rahul",
    "rahul@example.com",
    "Developer"
);

console.log(user.getProfile());
Expected Output: 
Rahul (Developer)

8.2 Dynamic Form Data

A form can contain field names that are determined at runtime. Computed properties can be used to construct an object from those field names. 

const fieldName = "email";
const fieldValue = "user@example.com";

const formData = {
    [fieldName]: fieldValue
};

console.log(formData);
Expected Output: 
{
    email: "user@example.com"
}

8.3 Creating Configuration Objects

const theme = "dark";
const language = "en";

const configuration = {
    theme,
    language,

    getDescription() {
        return `Theme: ${this.theme}, Language: ${this.language}`;
    }
};

console.log(configuration.getDescription());
Expected Output: 
Theme: dark, Language: en

8.4 Dynamic API Response Mapping

function createResponse(key, data) {
    return {
        success: true,
        [key]: data,
        timestamp: Date.now()
    };
}

const response = createResponse(
    "user",
    { id: 101, name: "Rahul" }
);

console.log(response.success);
console.log(response.user.name);
Expected Output: 
true
Rahul

The timestamp is generated at runtime, so its exact numerical value varies.

8.5 Creating Action Objects

const actionType = "LOGIN";

const action = {
    type: actionType,
    payload: {
        username: "rahul"
    },

    describe() {
        return `Action: ${this.type}`;
    }
};

console.log(action.describe());
console.log(action.payload.username);
Expected Output: 
Action: LOGIN
rahul

9. Important Rules and Common Mistakes

Rule 1: Property shorthand requires a matching variable

const name = "Rahul";

const user = {
    name
};

console.log(user.name);

The property name is taken from the variable name. If the variable is not declared, JavaScript throws a ReferenceError.

Rule 2: Computed properties require square brackets

const key = "name";

const user = {
    [key]: "Amit"
};

console.log(user.name);
Expected Output: 
Amit

Without square brackets, the property would literally be named key.

Rule 3: Property shorthand and computed properties are different

const key = "name";

const first = {
    key: "Rahul"
};

const second = {
    [key]: "Rahul"
};

console.log(first.key);
console.log(second.name);
Expected Output: 
Rahul
Rahul

In the first object, the property is literally named key. In the second, JavaScript evaluates the variable and uses name as the property key.

Rule 4: Concise methods are not arrow functions

const user = {
    name: "Rahul",

    display() {
        return this.name;
    }
};

console.log(user.display());
Expected Output: 
Rahul

Rule 5: Duplicate property names overwrite earlier values

const user = {
    name: "Rahul",
    name: "Amit"
};

console.log(user.name);
Expected Output: 
Amit
Debugging Tip: When an object contains unexpected property names, inspect whether the key was written as a normal identifier or as a computed expression inside square brackets.

10. Placement Interview Questions and Answers

Q1. What are enhanced object literals?

Enhanced object literals are ES6 features that simplify object creation using property shorthand, concise methods and computed property names.

Q2. What is property shorthand?

It allows a variable to be used as both the object property name and its value when their names are identical.

Q3. What is method shorthand?

It allows methods to be defined inside object literals without writing the function keyword and colon.

Q4. What are computed property names?

They allow expressions inside square brackets to determine object property names dynamically.

Q5. What is the difference between obj.key and obj[key]?

obj.key accesses the property literally named key. obj[key] evaluates the variable or expression and uses its resulting value as the property name.

Q6. Can methods have computed property names?

Yes. Computed property names can be used when defining methods inside object literals.

Q7. Can shorthand and normal properties be mixed?

Yes. An object literal can contain shorthand properties, normal properties, methods and computed properties together.

Q8. Why are enhanced object literals useful in frontend development?

They make it easier to create user objects, configuration objects, form data, action objects and API-related data.

Q9. What happens when two properties have the same key?

The later property definition determines the final value for that key.

Q10. Do concise object methods have their own this binding?

Yes. Their this value is determined by how the method is called. They are not arrow functions.

13. Quick Revision

Concept Syntax Purpose
Property shorthand { name } Uses a variable name as the property name and value.
Method shorthand { display() {} } Defines concise object methods.
Computed property { [key]: value } Creates a property using an evaluated expression.
Dynamic method { [methodName]() {} } Defines a method with a dynamic name.
Property access obj[key] Accesses a property using a variable or expression.

Enhanced object literals make JavaScript objects shorter, clearer and easier to construct dynamically. These features are especially useful in frontend applications that work with user data, forms, configurations and API responses.
