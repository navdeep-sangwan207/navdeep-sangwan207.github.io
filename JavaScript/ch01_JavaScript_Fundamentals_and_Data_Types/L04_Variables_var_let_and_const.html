After completing this lecture, you should be able to:

  • Understand variables and their purpose.
  • Differentiate declaration, initialization and assignment.
  • Understand var, let and const.

  • Understand variable redeclaration and reassignment.

  • Predict outputs of variable-related interview programs.

2. What Is a Variable?

A variable is a named binding used to store or refer to a value during program execution. JavaScript variables can hold different kinds of values, including numbers, strings, booleans, arrays and objects.

Example

let studentName = "Rahul";

let age = 22;

let marks = 85;

console.log(studentName);
console.log(age);
console.log(marks);
Expected Output: 
Rahul
22
85

Here, studentName, age and marks are variable names. Their values are used by the program.

3. Declaration, Initialization and Assignment

3.1 Variable Declaration

Declaration introduces a variable binding into the program. 

let age;

The variable has been declared but not explicitly initialized.

3.2 Initialization

Initialization gives a variable its initial value. 

let age = 22;

3.3 Assignment

Assignment stores a value in an already declared variable. 

let age;

age = 22;

age = 25;

console.log(age);
Expected Output: 
25
Term Meaning Example
Declaration Creating a variable binding. let x;
Initialization Providing the initial value. let x = 10;
Assignment Assigning or updating a value. x = 20;

4. The var Keyword

var is the traditional keyword for declaring variables in JavaScript. It has function scope or global scope, depending on where it is declared.

4.1 Declaration and Initialization

var age = 22;

console.log(age);
Expected Output: 
22

4.2 Reassignment

var age = 22;

age = 25;

console.log(age);
Expected Output: 
25

4.3 Redeclaration

A variable declared using var can be redeclared in the same scope. 

var city = "Delhi";

var city = "Chandigarh";

console.log(city);
Expected Output: 
Chandigarh
Redeclaration with var may cause accidental overwriting of existing variables in larger programs.

5. The let Keyword

let declares a block-scoped variable. It can be reassigned but cannot be redeclared in the same scope.

5.1 Declaration and Initialization

let salary = 30000;

console.log(salary);
Expected Output: 
30000

5.2 Reassignment

let salary = 30000;

salary = 35000;

console.log(salary);
Expected Output: 
35000

5.3 Redeclaration in the Same Scope

let age = 22;

// This causes a SyntaxError:
// let age = 25;

Declaring the same let variable twice in one scope causes a SyntaxError.

5.4 Redeclaration in a Different Block

let value = 10;

{
    let value = 20;
    console.log(value);
}

console.log(value);
Expected Output: 
20
10

The inner block has its own variable binding. It does not replace the outer variable.

6. The const Keyword

const declares a block-scoped binding that must be initialized when declared and cannot be reassigned.

6.1 Declaration and Initialization

const PI = 3.14159;

console.log(PI);
Expected Output: 
3.14159

6.2 Reassignment Is Not Allowed

const MAX_USERS = 100;

// This causes a TypeError:
// MAX_USERS = 200;

6.3 Declaration Without Initialization

// Invalid:
const age;

A const declaration must include an initializer.

6.4 Object Mutation with const

const prevents reassignment of the variable binding. It does not make an object deeply immutable. 

const student = {
    name: "Rahul",
    age: 22
};

student.age = 23;

console.log(student.age);
Expected Output: 
23

The object property can be changed because the object itself is still mutable.

6.5 Reassigning the Object Is Not Allowed

const student = {
    name: "Rahul"
};

// Invalid:
// student = { name: "Amit" };
Interview distinction: const does not mean that every property of an object or element of an array becomes immutable. It prevents reassignment of the binding.

7. Comparison of var, let and const

Feature var let const
Scope Function/global Block Block
Reassignment Allowed Allowed Not allowed
Same-scope redeclaration Allowed Not allowed Not allowed
Initialization required at declaration No No Yes
Hoisting behavior Initialized to undefined TDZ TDZ
Modern JavaScript practice: Prefer const when a binding does not need reassignment. Use let when reassignment is required. Avoid var in most modern application code.

8. Scope of Variables

Scope determines where a variable can be accessed in a program. JavaScript has global scope, function scope and block scope.

8.1 Global Scope

A variable declared at the top level of a script is generally accessible throughout that script, subject to the execution environment and module rules. 

let company = "ABC Technologies";

function displayCompany() {
    console.log(company);
}

displayCompany();

console.log(company);
Expected Output: 
ABC Technologies
ABC Technologies

8.2 Function Scope with var

A var variable declared inside a function is accessible within that function, including nested blocks. 

function test() {
    var message = "Hello";

    console.log(message);
}

test();

// Outside the function, message is not accessible.
// console.log(message);
Expected Output: 
Hello

8.3 Block Scope with let

A block is a group of statements enclosed in curly braces. A let variable declared inside a block is accessible only within that block and its nested scopes. 

{
    let marks = 90;

    console.log(marks);
}

// marks is not accessible here.
Expected Output: 
90

8.4 var Is Not Block-Scoped

if (true) {
    var city = "Panipat";
}

console.log(city);
Expected Output: 
Panipat

The var declaration is not restricted to the if block. It is scoped to the containing function or global scope.

8.5 let Is Block-Scoped

if (true) {
    let city = "Panipat";

    console.log(city);
}

// console.log(city); // ReferenceError
Expected Output: 
Panipat

8.6 Scope Inside a Function

let count = 10;

function showCount() {
    let count = 20;

    console.log(count);
}

showCount();

console.log(count);
Expected Output: 
20
10

9. Variable Hoisting

Hoisting describes how JavaScript processes declarations during the creation of an execution context before executing statements in that context.

Different declaration types have different initialization behavior.

9.1 Hoisting with var

console.log(value);

var value = 100;
Expected Output: 
undefined

Conceptually, the declaration is processed before execution, and the var binding is initialized to undefined.

Conceptual equivalent:

var value;

console.log(value);

value = 100;

9.2 Hoisting with let

console.log(age);

let age = 25;

This produces a ReferenceError because the variable cannot be accessed before its declaration is evaluated.

9.3 Hoisting with const

console.log(PI);

const PI = 3.14;

This also produces a ReferenceError because the const binding is in its Temporal Dead Zone before initialization.

Hoisting does not mean that JavaScript physically moves every declaration to the top of the source code. It describes declaration processing and binding behavior.

10. Temporal Dead Zone (TDZ)

The Temporal Dead Zone is the period between entering a scope and the point at which a let or const declaration is initialized. Accessing the binding during this period causes a ReferenceError.

Example

{
    // Temporal Dead Zone begins for 'name'.

    // console.log(name); // ReferenceError

    let name = "Rahul";

    console.log(name);
}
Expected Output: 
Rahul

Another Example

function display() {
    console.log(number);

    let number = 50;
}

display();

This program throws a ReferenceError before the console statement can successfully read number.

var vs let and const During Hoisting

Declaration Before Declaration Is Executed
var Binding is initialized to undefined.
let Binding exists but is uninitialized; access causes ReferenceError.
const Binding exists but is uninitialized; access causes ReferenceError.

11. Multiple Variable Declarations

JavaScript allows multiple variables to be declared in a single declaration statement. 

let firstName = "Amit",
    lastName = "Sharma",
    age = 24;

console.log(firstName);
console.log(lastName);
console.log(age);
Expected Output: 
Amit
Sharma
24

Although multiple declarations are valid, separate declarations can improve readability in many projects.

12. Practical Program: Employee Salary

Objective

Create an employee salary calculation program using var, let and const.

Complete JavaScript Code

// Employee salary calculation

const EMPLOYEE_NAME = "Amit Sharma";

let basicSalary = 25000;

let allowance = 5000;

let deduction = 2000;

// Calculate gross and net salary
let grossSalary = basicSalary + allowance;

let netSalary = grossSalary - deduction;

// Display employee details
console.log("Employee:", EMPLOYEE_NAME);

console.log("Basic Salary:", basicSalary);

console.log("Allowance:", allowance);

console.log("Gross Salary:", grossSalary);

console.log("Deduction:", deduction);

console.log("Net Salary:", netSalary);

Expected Output

Employee: Amit Sharma
Basic Salary: 25000
Allowance: 5000
Gross Salary: 30000
Deduction: 2000
Net Salary: 28000

Concepts Applied

  • const for a binding that is not reassigned.
  • let for values used in calculations.
  • Variable initialization.
  • Arithmetic expressions.
  • Console output.

13. Placement Interview Questions and Answers

Q1. What is a variable in JavaScript?

Answer: A variable is a named binding used to store or refer to a value in a program.

Q2. What is the difference between var, let and const?

Answer: var is function-scoped or globally scoped and permits same-scope redeclaration. let and const are block-scoped. let permits reassignment, while const does not permit reassignment and requires initialization at declaration.

Q3. Can we redeclare a let variable?

Answer: Not in the same scope. A separate nested scope can declare another variable with the same name.

Q4. Can we change an object declared using const?

Answer: Yes. Object properties can be modified, but the variable binding cannot be reassigned to another object.

Q5. What is block scope?

Answer: Block scope restricts access to a variable to the block in which it is declared and its nested scopes.

Q6. What is function scope?

Answer: Function scope means a variable is accessible within the function in which it is declared.

Q7. What is hoisting?

Answer: Hoisting describes how declarations are processed before execution of statements in their scope. var is initialized to undefined, while let and const remain uninitialized until their declaration is evaluated.

Q8. What is the Temporal Dead Zone?

Answer: It is the period during which a let or const binding exists but cannot be accessed before initialization.

Q9. Why is var generally avoided in modern JavaScript?

Answer: Its function-scoping and redeclaration behavior can cause unexpected bugs. let and const provide more predictable block-scoped behavior.

Q10. What happens when a const variable is declared without a value?

Answer: JavaScript throws a SyntaxError because const requires an initializer.

Q11. What is the output of this program?

var x = 10;

{
    var x = 20;
}

console.log(x);

Answer: 20. The var declaration is not restricted to the block.

Q12. What is the output of this program?

let x = 10;

{
    let x = 20;
}

console.log(x);

Answer: 10. The inner let variable belongs to a separate block scope.

15. Important Placement Revision Points

  • Use const by default when reassignment is unnecessary.
  • Use let when a variable must be reassigned.
  • Avoid var in modern JavaScript application code.
  • var is function-scoped, not block-scoped.
  • let and const are block-scoped.
  • var can be redeclared in the same scope.
  • let and const cannot be redeclared in the same scope.
  • const must be initialized at declaration.
  • const prevents reassignment, not object mutation.
  • var is initialized to undefined during declaration processing.
  • let and const are inaccessible during the TDZ.
  • Understand scope and hoisting output-prediction questions.
