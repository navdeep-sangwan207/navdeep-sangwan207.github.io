Lesson 06: DOM Traversal – Parent, Child and Sibling Nodes

Learn how to navigate the DOM tree using parent, child, and sibling relationships to select and manipulate elements efficiently.

1. Learning Objectives

  • Understand DOM tree relationships.
  • Access parent elements and parent nodes.
  • Navigate child elements and child nodes.
  • Access first and last child elements.
  • Navigate previous and next siblings.
  • Understand the difference between elements and nodes.
  • Use closest() to find matching ancestors.
  • Use matches() to test CSS selectors.
  • Build practical DOM traversal solutions.

2. Understanding the DOM Tree

The Document Object Model represents an HTML document as a hierarchical tree of objects called nodes. Elements, text, comments, and the document itself are represented as different types of nodes.

Example HTML

<div id="container">
    <h2>Frontend Development</h2>
    <p>Learn JavaScript</p>
    <ul>
        <li>HTML</li>
        <li>CSS</li>
        <li>JavaScript</li>
    </ul>
</div>

DOM Hierarchy

DIV (container)
|
|-- H2
|   |-- Text: Frontend Development
|
|-- P
|   |-- Text: Learn JavaScript
|
|-- UL
    |
    |-- LI
    |   |-- Text: HTML
    |
    |-- LI
    |   |-- Text: CSS
    |
    |-- LI
        |-- Text: JavaScript

In this structure:

  • DIV is the parent of H2, P, and UL.
  • H2, P, and UL are children of DIV.
  • H2 and P are siblings.
  • The three LI elements are siblings.
  • Each LI contains a text node.

3. Node vs Element

Every HTML element is a node, but not every node is an element.

Node Type Description Example
Document node Represents the entire HTML document. document
Element node Represents an HTML element. div, p, h1
Text node Represents text inside an element. Hello World
Comment node Represents an HTML comment. <!-- Comment -->

This distinction is important because some DOM properties return all node types, while others return only element nodes.

4. Accessing Parent Elements

parentElement

The parentElement property returns the parent of an element, provided that the parent is itself an element.

Syntax

element.parentElement;

Example

<div id="container">
    <p id="message">Hello JavaScript</p>
</div>

<script>
    const message = document.getElementById("message");

    const parent = message.parentElement;

    console.log(parent.id);
    console.log(parent.tagName);
</script>
Expected Console Output: 
container
DIV

parentNode

The parentNode property returns the parent node, which may be an element, document, or document fragment. 

const message = document.getElementById("message");

console.log(message.parentNode);

parentElement vs parentNode

Feature parentElement parentNode
Returns Parent element only. Parent node of any node type.
Return type Element or null. Node or null.
Typical usage Traversing HTML element hierarchy. General DOM node traversal.
The parentNode of document is null. The document's parentElement is also null.

5. Accessing Child Elements Using children

The children property returns a live HTMLCollection containing only the child elements of an element.

Syntax

element.children;

Example

<div id="container">
    <h2>Heading</h2>
    <p>Paragraph</p>
    <button>Click Me</button>
</div>

<script>
    const container = document.getElementById("container");

    console.log(container.children.length);

    console.log(container.children[0].tagName);

    console.log(container.children[1].tagName);

    console.log(container.children[2].tagName);
</script>
Expected Console Output: 
3
H2
P
BUTTON

Looping Through Children

const children = container.children;

for (let i = 0; i < children.length; i++) {
    console.log(children[i].tagName);
}
Expected Console Output: 
H2
P
BUTTON

6. Accessing Child Nodes Using childNodes

The childNodes property returns a live NodeList containing all child nodes, including element nodes, text nodes, and comment nodes.

Example

<div id="container">
    <h2>Heading</h2>
    <p>Paragraph</p>
</div>

<script>
    const container = document.getElementById("container");

    console.log(container.childNodes.length);

    container.childNodes.forEach(function (node) {
        console.log(node.nodeType, node.nodeName);
    });
</script>

The whitespace and line breaks between HTML elements can create text nodes. Therefore, childNodes may contain more entries than children.

Do not assume childNodes[0] is always an HTML element. It may be a whitespace text node.

7. children vs childNodes

Feature children childNodes
Returns HTMLCollection NodeList
HTML elements Included Included
Text nodes Excluded Included
Comment nodes Excluded Included
Collection type Live Live

Example

<div id="box">
    <p>First</p>
    <p>Second</p>
</div>

<script>
    const box = document.getElementById("box");

    console.log(box.children.length);

    console.log(box.childNodes.length);
</script>

The children collection contains two paragraph elements. The childNodes collection also includes whitespace text nodes generated by the formatting in the HTML.

8. firstElementChild and lastElementChild

These properties return the first and last child elements of a parent element.

firstElementChild

parent.firstElementChild;

lastElementChild

parent.lastElementChild;

Example

<ul id="skills">
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ul>

<script>
    const skills = document.getElementById("skills");

    console.log(skills.firstElementChild.textContent);

    console.log(skills.lastElementChild.textContent);
</script>
Expected Console Output: 
HTML
JavaScript

firstChild and lastChild

These properties return the first and last child nodes, including text and comment nodes. 

console.log(skills.firstChild);

console.log(skills.lastChild);

With formatted HTML, these may return whitespace text nodes instead of li elements.

9. firstChild vs firstElementChild

Property Returns
firstChild First child node, including text or comments.
firstElementChild First child element only.
lastChild Last child node, including text or comments.
lastElementChild Last child element only.
For most frontend element-navigation tasks, firstElementChild and lastElementChild are more predictable than firstChild and lastChild.

10. Accessing Previous and Next Siblings

nextElementSibling

Returns the next sibling element. It skips text and comment nodes. 

element.nextElementSibling;

previousElementSibling

Returns the previous sibling element. It skips text and comment nodes. 

element.previousElementSibling;

Example

<ul id="skills">
    <li id="html">HTML</li>
    <li id="css">CSS</li>
    <li id="js">JavaScript</li>
</ul>

<script>
    const css = document.getElementById("css");

    console.log(css.previousElementSibling.textContent);

    console.log(css.nextElementSibling.textContent);
</script>
Expected Console Output: 
HTML
JavaScript

11. nextSibling and previousSibling

These properties return the next and previous sibling nodes, including text and comment nodes.

Syntax

element.nextSibling;

element.previousSibling;

Example

<div id="container">
    <p id="first">First Paragraph</p>
    <p id="second">Second Paragraph</p>
</div>

<script>
    const first = document.getElementById("first");

    console.log(first.nextSibling.nodeType);

    console.log(first.nextElementSibling.textContent);
</script>

The nextSibling may be a whitespace text node because of the newline between the paragraph elements.

Expected Console Output: 
3
Second Paragraph
Node type 3 represents a text node.

12. Sibling Navigation Comparison

Property Returns
nextSibling Next node of any type.
nextElementSibling Next element only.
previousSibling Previous node of any type.
previousElementSibling Previous element only.

13. closest() – Finding the Nearest Matching Ancestor

The closest() method searches the element itself and then its ancestors until it finds the nearest element matching a specified CSS selector.

Syntax

element.closest("CSS selector");

Example

<div class="container">
    <div class="card">
        <button id="action">Click Me</button>
    </div>
</div>

<script>
    const button = document.getElementById("action");

    const card = button.closest(".card");

    const container = button.closest(".container");

    console.log(card.className);

    console.log(container.className);
</script>
Expected Console Output: 
card
container

If no matching element is found, closest() returns null.

Important Characteristics

  • Search starts from the current element.
  • The current element itself can be returned.
  • Search continues upward through ancestors.
  • It accepts a CSS selector.
  • It returns the nearest matching element or null.

14. matches() – Checking an Element Against a Selector

The matches() method checks whether an element matches a specified CSS selector.

Syntax

element.matches("CSS selector");

Example

<button id="submit" class="btn primary">
    Submit
</button>

<script>
    const button = document.getElementById("submit");

    console.log(button.matches(".btn"));

    console.log(button.matches("button"));

    console.log(button.matches(".danger"));
</script>
Expected Console Output: 
true
true
false

matches() is useful when checking the type, class, or other selector-based characteristics of an element.

15. hasAttribute() and hasChildNodes()

hasAttribute()

Checks whether an element has a specified attribute. 

element.hasAttribute("id");

hasChildNodes()

Checks whether an element has any child nodes, including text and comment nodes. 

element.hasChildNodes();

Example

<div id="container" data-type="panel">
    <p>Information</p>
</div>

<script>
    const container = document.getElementById("container");

    console.log(container.hasAttribute("data-type"));

    console.log(container.hasAttribute("class"));

    console.log(container.hasChildNodes());
</script>
Expected Console Output: 
true
false
true

16. Practical Example: Navigate a Product Card

This example demonstrates navigating from a button to its parent card and accessing the card's child elements. 

<div class="product-card">
    <h2>Laptop</h2>
    <p class="price">₹55,000</p>
    <button class="details">View Details</button>
</div>

<script>
    const button = document.querySelector(".details");

    const card = button.closest(".product-card");

    const title = card.querySelector("h2");

    const price = card.querySelector(".price");

    console.log(title.textContent);

    console.log(price.textContent);
</script>
Expected Console Output: 
Laptop
₹55,000

This pattern is useful when multiple product cards share the same HTML structure.

17. Practical Example: Navigate Between List Items

<ul id="languages">
    <li>C</li>
    <li id="current">JavaScript</li>
    <li>Python</li>
</ul>

<script>
    const current = document.getElementById("current");

    const previous = current.previousElementSibling;

    const next = current.nextElementSibling;

    console.log("Previous:", previous.textContent);

    console.log("Current:", current.textContent);

    console.log("Next:", next.textContent);
</script>
Expected Console Output: 
Previous: C
Current: JavaScript
Next: Python

18. Live Collections and Static NodeLists

Some DOM collections automatically reflect changes in the document, while others represent a snapshot taken when the query was executed.

Collection / Method Result Behavior
children HTMLCollection Live
childNodes NodeList Live
getElementsByTagName() HTMLCollection Live
querySelectorAll() NodeList Static

Example: Live HTMLCollection

<ul id="list">
    <li>HTML</li>
    <li>CSS</li>
</ul>

<script>
    const list = document.getElementById("list");

    const items = list.children;

    console.log(items.length);

    const newItem = document.createElement("li");

    newItem.textContent = "JavaScript";

    list.appendChild(newItem);

    console.log(items.length);
</script>
Expected Console Output: 
2
3

Example: Static NodeList

const list = document.getElementById("list");

const items = list.querySelectorAll("li");

console.log(items.length);

const newItem = document.createElement("li");

newItem.textContent = "React";

list.appendChild(newItem);

console.log(items.length);
Expected Console Output: 
3
3
The NodeList returned by querySelectorAll() does not automatically include the newly inserted item.

19. Common Mistakes and Debugging

Mistake 1: Confusing childNodes with children

childNodes includes text and comment nodes, while children includes only element nodes.

Mistake 2: Assuming nextSibling is an element

nextSibling may return a whitespace text node. Use nextElementSibling when an element is required.

Mistake 3: Accessing a missing parent or sibling

const next = element.nextElementSibling;

if (next) {
    console.log(next.textContent);
}

A first or last element may not have a previous or next sibling. Always check for null.

Mistake 4: Modifying a live collection while iterating

Removing elements while moving forward through a live HTMLCollection can cause elements to be skipped because the collection updates immediately.

Safer approach:

const items = Array.from(parent.children);

items.forEach(function (item) {
    item.remove();
});

Mistake 5: Using closest() without checking the result

const card = button.closest(".product-card");

if (card) {
    console.log(card.textContent);
}

closest() can return null when no matching ancestor or current element exists.

Mistake 6: Confusing parentElement with closest()

parentElement returns only the immediate parent. closest() searches upward until a matching selector is found.

20. Placement Interview Questions and Answers

Q1. What is DOM traversal?

Answer: DOM traversal is the process of navigating between related nodes and elements in the DOM tree.

Q2. What is the difference between parentNode and parentElement?

Answer: parentNode returns the parent node of any node type. parentElement returns the parent only when it is an element.

Q3. What is the difference between children and childNodes?

Answer: children returns only element children in a live HTMLCollection. childNodes returns all child nodes in a live NodeList.

Q4. What is the difference between firstChild and firstElementChild?

Answer: firstChild returns the first node, which may be text or a comment. firstElementChild returns the first HTML element.

Q5. What is the difference between nextSibling and nextElementSibling?

Answer: nextSibling returns the next node of any type. nextElementSibling skips text and comment nodes.

Q6. What does closest() do?

Answer: It searches the current element and its ancestors for the nearest element matching a CSS selector.

Q7. What does matches() do?

Answer: It checks whether an element matches a specified CSS selector and returns a Boolean.

Q8. What is an HTMLCollection?

Answer: It is a collection of HTML elements. Collections such as children are live and automatically reflect DOM changes.

Q9. Is querySelectorAll() live or static?

Answer: It returns a static NodeList. Later DOM changes do not automatically update that particular NodeList.

Q10. What is the difference between a NodeList and an HTMLCollection?

Answer: HTMLCollection contains elements only. NodeList can contain different node types. Their live or static behavior depends on the API that creates them.

Q11. What happens if closest() finds no matching element?

Answer: It returns null.

Q12. What does hasChildNodes() check?

Answer: It checks whether an element has any child nodes, including text and comment nodes.

Q13. How do you access the second child element?

Answer: Use element.children[1], because indexing starts at zero.

Q14. How can you find the nearest parent with a specific class?

Answer: Use element.closest(".className").

22. Lesson Summary

  • DOM traversal navigates the hierarchical DOM tree.
  • parentElement returns the immediate parent element.
  • parentNode returns the immediate parent node.
  • children returns a live collection of child elements.
  • childNodes returns all child nodes.
  • firstElementChild and lastElementChild access element boundaries.
  • firstChild and lastChild include text and comment nodes.
  • nextElementSibling and previousElementSibling navigate sibling elements.
  • nextSibling and previousSibling navigate sibling nodes.
  • closest() finds the nearest matching ancestor or current element.
  • matches() checks whether an element matches a CSS selector.
  • hasAttribute() checks for an HTML attribute.
  • hasChildNodes() checks for the presence of child nodes.
  • children and childNodes are live collections.
  • querySelectorAll() returns a static NodeList.
