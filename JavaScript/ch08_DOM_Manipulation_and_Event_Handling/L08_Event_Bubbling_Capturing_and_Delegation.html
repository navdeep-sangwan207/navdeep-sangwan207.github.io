Lesson 8: Event Bubbling, Capturing and Delegation

Understand event propagation, capturing, bubbling, event delegation and efficient event handling in frontend applications.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand event propagation in the DOM.
  • Explain event capturing and event bubbling.
  • Understand the three phases of event propagation.
  • Register capturing and bubbling event listeners.
  • Use event delegation to handle multiple child elements.
  • Understand event.target and event.currentTarget.
  • Use closest() and matches() in delegated event handlers.
  • Apply event delegation in dynamic user interfaces.

2. What Is Event Propagation?

Event propagation describes how an event travels through the DOM tree when an event occurs on an element.

Consider the following nested HTML structure: 

<div id="parent">
    <div id="child">
        <button id="button">Click Me</button>
    </div>
</div>

When the button is clicked, the click event can travel through its ancestors.

Event propagation has three phases:

  1. Capturing phase
  2. Target phase
  3. Bubbling phase
Event propagation is important when multiple nested elements have event listeners. It determines the order in which those listeners execute.

3. Three Phases of Event Propagation

3.1 Capturing Phase

During capturing, the event travels from the outermost relevant ancestor toward the target element.

Direction:

Document

3.2 Target Phase

The event reaches the element on which the event actually occurred. This element is called the event target.

3.3 Bubbling Phase

After reaching the target, an event that supports bubbling travels back through its ancestors toward the document.

Direction:

Target Element
    ↑
Child
    ↑
Parent
    ↑
Body
    ↑
HTML
    ↑
Document

The target phase occurs between capturing and bubbling. Event listeners on the target can participate in both capturing and non-capturing registrations.

4. Event Bubbling

Event bubbling is the process in which an event travels from the target element upward through its ancestors.

For most commonly used UI events, bubbling is the default behavior when addEventListener() is used without the capture option.

Example: Bubbling

<div id="parent">
    Parent
    <div id="child">
        Child
        <button id="button">Click Me</button>
    </div>
</div>

<script>
    const parent = document.getElementById("parent");
    const child = document.getElementById("child");
    const button = document.getElementById("button");

    parent.addEventListener("click", function () {
        console.log("Parent clicked");
    });

    child.addEventListener("click", function () {
        console.log("Child clicked");
    });

    button.addEventListener("click", function () {
        console.log("Button clicked");
    });
</script>

Expected Output When Button Is Clicked

Button clicked
Child clicked
Parent clicked

The button's handler executes first. The event then bubbles to the child and parent elements.

5. Event Capturing

Event capturing is the process in which an event travels from outer ancestors toward the target element.

To register an event listener for the capturing phase, set the capture option to true.

Example

parent.addEventListener("click", function () {
    console.log("Parent capturing");
}, true);

child.addEventListener("click", function () {
    console.log("Child capturing");
}, true);

button.addEventListener("click", function () {
    console.log("Button clicked");
}, true);

Expected Output

Parent capturing
Child capturing
Button clicked

The parent listener executes before the child listener because the event travels from outer ancestors toward the target.

Using the Options Object

parent.addEventListener("click", handler, {
    capture: true
});

6. Bubbling vs Capturing

Feature Capturing Bubbling
Direction Outer ancestor to target Target to outer ancestor
Execution order Parent before child Child before parent
Registration capture: true capture: false or omitted
Common use Handling events before they reach descendants Event delegation and ancestor-level handling

Example: Both Capturing and Bubbling Listeners

parent.addEventListener("click", function () {
    console.log("Parent capture");
}, true);

parent.addEventListener("click", function () {
    console.log("Parent bubble");
}, false);

child.addEventListener("click", function () {
    console.log("Child capture");
}, true);

child.addEventListener("click", function () {
    console.log("Child bubble");
}, false);

button.addEventListener("click", function () {
    console.log("Button target");
});

Assuming the button is the target and all listeners are registered on the shown ancestor chain, the expected output is: 

Parent capture
Child capture
Button target
Child bubble
Parent bubble
The precise target-phase ordering can depend on listener registration and capture settings. In this example, the button has only a non-capturing listener.

7. event.target vs event.currentTarget

These two properties are frequently used in event handling and event delegation.

7.1 event.target

event.target identifies the element on which the event originally occurred.

7.2 event.currentTarget

event.currentTarget identifies the element whose event listener is currently executing.

Example

<div id="parent">
    Parent
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.getElementById("parent");

    parent.addEventListener("click", function (event) {
        console.log("Target:", event.target);
        console.log("Current Target:", event.currentTarget);
    });
</script>

When the Button Is Clicked

Target: button element
Current Target: parent div element
Property Meaning
event.target Original event target.
event.currentTarget Element currently handling the event.
event.currentTarget refers to the element whose listener is executing. It is not necessarily the element that originally received the event.

8. What Is Event Delegation?

Event delegation is a technique in which a single event listener is attached to a common parent to handle events from multiple child elements.

It works primarily through event bubbling.

Without Event Delegation

<ul>
    <li class="item">Item 1</li>
    <li class="item">Item 2</li>
    <li class="item">Item 3</li>
</ul>

<script>
    const items = document.querySelectorAll(".item");

    items.forEach(function (item) {
        item.addEventListener("click", function () {
            console.log(item.textContent);
        });
    });
</script>

A separate event listener is registered for each list item.

With Event Delegation

<ul id="itemList">
    <li>Item 1</li>
    <li>Item 2</li>
    <li>Item 3</li>
</ul>

<script>
    const itemList = document.getElementById("itemList");

    itemList.addEventListener("click", function (event) {
        if (event.target.matches("li")) {
            console.log(event.target.textContent);
        }
    });
</script>

Only one listener is attached to the parent ul element. When a list item is clicked, the event bubbles to the parent.

Event delegation reduces the number of individual listeners and is particularly useful for dynamically created elements.

9. Event Delegation with closest()

The closest() method searches the element itself and then its ancestors for the nearest element matching a CSS selector.

It is useful when a child element contains nested elements that users can click.

Example

<ul id="productList">
    <li class="product">
        Product 1
        <span>View details</span>
    </li>

    <li class="product">
        Product 2
        <span>View details</span>
    </li>
</ul>

<script>
    const productList = document.getElementById("productList");

    productList.addEventListener("click", function (event) {
        const product = event.target.closest(".product");

        if (product && productList.contains(product)) {
            console.log("Selected:", product.textContent.trim());
        }
    });
</script>

If the user clicks the span, closest(".product") finds its nearest product list item.

matches() vs closest()

Method Purpose
matches() Checks whether the element itself matches a CSS selector.
closest() Finds the nearest matching element, including the element itself.

10. Event Delegation for Dynamic Elements

Consider a list where new items are added after the page loads.

If listeners are attached individually only to the initial list items, newly created items will not automatically receive those listeners.

Complete Example

  • Existing Item 1
  • Existing Item 2

Click any item to see its name. 

<button id="addItemButton">Add New Item</button>

<ul id="dynamicList">
    <li>Existing Item 1</li>
    <li>Existing Item 2</li>
</ul>

<script>
    const addButton =
        document.getElementById("addItemButton");

    const list =
        document.getElementById("dynamicList");

    let count = 2;

    // One delegated listener for all list items
    list.addEventListener("click", function (event) {
        const item = event.target.closest("li");

        if (item && list.contains(item)) {
            console.log("Clicked:", item.textContent);
        }
    });

    // Add new list items
    addButton.addEventListener("click", function () {
        count++;

        const newItem = document.createElement("li");

        newItem.textContent = "New Item " + count;

        list.appendChild(newItem);
    });
</script>

Expected Result

  1. The page initially displays two list items.
  2. Click Add New Item to create another item.
  3. Click any existing or newly created item.
  4. The delegated parent listener handles the click.

No additional event listener is required for each new item.

11. Advantages and Limitations of Event Delegation

Advantages

  • Fewer individual event listeners.
  • Automatically handles matching dynamically added descendants.
  • Centralizes event handling logic.
  • Useful for lists, tables, menus and product grids.
  • Can simplify management of large interfaces.

Limitations

  • Requires an event that bubbles for the usual delegation approach.
  • Event handlers must identify the intended child element correctly.
  • Complex nested structures may require closest() and additional checks.
  • Delegation may be inappropriate when each element needs highly specialized event behavior.
Not every event bubbles. For example, focus and blur do not bubble. Their focusin and focusout counterparts do bubble and can be used for delegated focus handling.

13. Common Mistakes and Debugging

Mistake 1: Assuming Every Event Bubbles

Some events do not bubble. Check the event's behavior before implementing delegation.

Mistake 2: Using event.target Without Checking the Element

// Risky
list.addEventListener("click", function (event) {
    console.log(event.target.textContent);
});

The target might be a nested span or another descendant, rather than the intended list item.

Improved approach:

list.addEventListener("click", function (event) {
    const item = event.target.closest("li");

    if (item && list.contains(item)) {
        console.log(item.textContent);
    }
});

Mistake 3: Confusing target and currentTarget

In a delegated handler, target is usually the clicked descendant, while currentTarget is the parent holding the listener.

Mistake 4: Registering Multiple Parent Listeners Accidentally

Repeatedly initializing a component may register the same listener more than once. Keep initialization under control.

Mistake 5: Incorrect Capturing Configuration

// Capturing
element.addEventListener("click", handler, true);

// Bubbling
element.addEventListener("click", handler, false);

The third argument controls the capture setting when a Boolean is supplied.

14. Placement Interview Questions and Answers

Q1. What is event propagation?

Event propagation is the process through which an event travels through the DOM tree. It includes capturing, target and bubbling phases.

Q2. What is event bubbling?

Event bubbling occurs when an event travels from the target element upward through its ancestors.

Q3. What is event capturing?

Event capturing occurs when an event travels from outer ancestors toward the target element.

Q4. What are the three phases of event propagation?

Capturing phase, target phase and bubbling phase.

Q5. What is event delegation?

Event delegation is a technique in which one listener on a common parent handles events from multiple child elements through event propagation.

Q6. Why is event delegation useful for dynamic elements?

A listener attached to a parent can handle matching descendant elements added later, provided the event bubbles to that parent.

Q7. What is the difference between event.target and event.currentTarget?

target identifies the original event target, while currentTarget identifies the element whose listener is currently executing.

Q8. How do you enable event capturing?

Pass true as the third argument to addEventListener(), or use an options object with capture: true.

Q9. Does every JavaScript event bubble?

No. Some events, such as focus and blur, do not bubble. Alternatives such as focusin and focusout support bubbling.

Q10. What is the difference between matches() and closest()?

matches() checks whether the current element matches a selector. closest() searches the current element and its ancestors for the nearest matching element.

Q11. Can event delegation be used with dynamically added buttons?

Yes. Attach a click listener to a common parent and identify the clicked button using matches() or closest().

Q12. Why is event delegation commonly used in frontend development?

It centralizes event handling, reduces the need for individual listeners and supports dynamically generated interface elements.

16. Lesson Summary

  • Event propagation describes how events travel through the DOM.
  • Capturing travels from ancestors toward the target.
  • Bubbling travels from the target toward ancestors.
  • The target phase occurs between capturing and bubbling.
  • event.target identifies the original event target.
  • event.currentTarget identifies the element handling the event.
  • Event delegation uses a parent listener to handle descendant events.
  • matches() and closest() help identify the intended child element.
  • Event delegation is particularly useful for dynamic interfaces.
