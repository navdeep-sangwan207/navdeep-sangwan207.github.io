2. What Is a Prototype?

JavaScript is a prototype-based language. Objects can inherit properties and methods from other objects through a mechanism called the prototype chain.

Every ordinary JavaScript object has an internal [[Prototype]] reference. This reference points to another object or to null.

When JavaScript cannot find a property directly on an object, it checks the object's prototype. If the property is not found there, it continues searching up the prototype chain.

Example

const employee = {
    name: "Rahul",
    department: "Development"
};

console.log(employee.name);
console.log(employee.toString);
Expected Output: 
Rahul
[Function: toString]

Function display formatting can vary between JavaScript environments.

The name property belongs directly to the employee object. The toString() method is inherited through its prototype chain.

3. Understanding the Prototype Relationship

Consider an object created using an object literal: 

const user = {
    name: "Aman"
};

console.log(Object.getPrototypeOf(user));
console.log(Object.getPrototypeOf(user) === Object.prototype);
Expected Output: 
[Object: null prototype] {}
true

The console's representation of Object.prototype differs across browsers and runtimes.

An object created using an object literal normally inherits from Object.prototype.

3.1 Object.getPrototypeOf()

Use Object.getPrototypeOf() to retrieve an object's prototype. 

const product = {
    name: "Laptop"
};

const prototype = Object.getPrototypeOf(product);

console.log(prototype === Object.prototype);
Expected Output: 
true

3.2 Object.prototype.isPrototypeOf()

This method checks whether an object exists in another object's prototype chain. 

const parent = {
    greet() {
        return "Hello";
    }
};

const child = Object.create(parent);

console.log(parent.isPrototypeOf(child));
Expected Output: 
true

4. Prototype-Based Inheritance

Inheritance allows one object to access properties and methods provided by another object.

In JavaScript, this can be achieved by linking one object's prototype to another object.

Example

const person = {
    greet() {
        console.log("Hello from Person");
    }
};

const student = Object.create(person);

student.name = "Rahul";

student.greet();

console.log(student.name);
Expected Output: 
Hello from Person
Rahul

The student object does not contain its own greet() method. It accesses the method through its prototype, which is the person object.

5. Creating Objects Using Object.create()

Object.create() creates a new object with the specified object as its prototype.

Syntax:

const newObject = Object.create(prototypeObject);

Example 1: Basic Object Creation

const vehicle = {
    start() {
        return "Vehicle started";
    }
};

const car = Object.create(vehicle);

car.brand = "Toyota";

console.log(car.brand);
console.log(car.start());
Expected Output: 
Toyota
Vehicle started

Example 2: Object with No Prototype

Passing null creates an object without a prototype. 

const dictionary = Object.create(null);

dictionary.language = "JavaScript";

console.log(dictionary.language);
console.log(Object.getPrototypeOf(dictionary));
Expected Output: 
JavaScript
null
An object created with Object.create(null) does not inherit methods such as toString() from Object.prototype. This can be useful for dictionary-like data structures with externally supplied keys.

6. Understanding the Prototype Chain

The prototype chain is the sequence of objects JavaScript follows when searching for a property or method.

Example

const grandparent = {
    country: "India"
};

const parent = Object.create(grandparent);
parent.state = "Haryana";

const child = Object.create(parent);
child.city = "Panipat";

console.log(child.city);
console.log(child.state);
console.log(child.country);
Expected Output: 
Panipat
Haryana
India

Property lookup follows this sequence:

  1. Search the child object.
  2. If the property is not found, search the parent object.
  3. If still not found, search the grandparent object.
  4. Continue until the property is found or the chain reaches null.

Prototype Chain Diagram

child
  |
  v
parent
  |
  v
grandparent
  |
  v
Object.prototype
  |
  v
null

The actual chain depends on how an object was created. For example, an object created with Object.create(null) has no prototype.

7. Own Properties vs Inherited Properties

An own property belongs directly to an object. An inherited property is obtained from its prototype chain.

Example

const parent = {
    department: "IT"
};

const employee = Object.create(parent);

employee.name = "Priya";

console.log(employee.name);
console.log(employee.department);

console.log(
    Object.hasOwn(employee, "name")
);

console.log(
    Object.hasOwn(employee, "department")
);
Expected Output: 
Priya
IT
true
false

7.1 Object.hasOwn()

Object.hasOwn() checks whether a property belongs directly to an object. 

const user = {
    name: "Aman"
};

console.log(Object.hasOwn(user, "name"));
console.log(Object.hasOwn(user, "age"));
Expected Output: 
true
false

7.2 The in Operator

The in operator checks whether a property exists on the object or anywhere in its prototype chain. 

const parent = {
    role: "Developer"
};

const employee = Object.create(parent);

employee.name = "Rahul";

console.log("name" in employee);
console.log("role" in employee);
console.log("toString" in employee);
Expected Output: 
true
true
true

7.3 Comparison

Object.hasOwn() in Operator
Checks own properties only. Checks own and inherited properties.
Does not search the prototype chain. Searches the prototype chain.
Returns true for an own property. Returns true if the property exists anywhere in the chain.

8. Method Sharing Through Prototypes

Prototype methods can be shared by multiple objects. Instead of creating a separate copy of a method for every object, objects can inherit the same method.

Example

const userMethods = {
    login() {
        return `${this.name} logged in`;
    }
};

const user1 = Object.create(userMethods);
user1.name = "Rahul";

const user2 = Object.create(userMethods);
user2.name = "Priya";

console.log(user1.login());
console.log(user2.login());

console.log(user1.login === user2.login);
Expected Output: 
Rahul logged in
Priya logged in
true

Both objects inherit the same login() function. The value of this depends on how the method is called.

9. Property Shadowing

Property shadowing occurs when an object defines an own property with the same name as a property inherited from its prototype.

Example

const parent = {
    role: "User"
};

const child = Object.create(parent);

console.log(child.role);

child.role = "Admin";

console.log(child.role);
console.log(parent.role);

console.log(Object.hasOwn(child, "role"));
Expected Output: 
User
Admin
User
true

The child object's own role property takes precedence during property lookup. The parent's property remains unchanged.

10. Object.prototype and Built-in Methods

Many methods available on ordinary objects are inherited from Object.prototype.

Common Methods

Method Purpose
toString() Returns a string representation.
hasOwnProperty() Checks whether a property is an own property.
isPrototypeOf() Checks whether an object exists in another object's prototype chain.
propertyIsEnumerable() Checks whether an own property is enumerable.

Example

const employee = {
    name: "Aman"
};

console.log(employee.toString());
console.log(employee.hasOwnProperty("name"));
console.log(employee.hasOwnProperty("age"));
Expected Output: 
[object Object]
true
false
For checking own properties, prefer Object.hasOwn(object, property) in modern JavaScript. It also works safely with objects that do not inherit from Object.prototype.

11. The __proto__ Property and Modern Alternatives

__proto__ is a legacy accessor that exposes or changes an object's prototype in environments that support it. It is not the same as the internal [[Prototype]] mechanism itself.

Example

const parent = {
    greet() {
        return "Hello";
    }
};

const child = {};

Object.setPrototypeOf(child, parent);

console.log(child.greet());
console.log(Object.getPrototypeOf(child) === parent);
Expected Output: 
Hello
true

Prefer these standard methods:

  • Object.getPrototypeOf() to inspect a prototype.
  • Object.create() to create an object with a chosen prototype.
  • Object.setPrototypeOf() to change a prototype when genuinely necessary.
Changing an object's prototype after creation can negatively affect performance. Prefer establishing the prototype when creating the object.

12. Practical Application: Shared Employee Methods

Consider a basic employee system. Multiple employee objects can share common methods through a prototype. 

const employeeMethods = {
    getDetails() {
        return `${this.name} works in ${this.department}`;
    },

    changeDepartment(newDepartment) {
        this.department = newDepartment;
    }
};

const employee1 = Object.create(employeeMethods);

employee1.name = "Rahul";
employee1.department = "Testing";

const employee2 = Object.create(employeeMethods);

employee2.name = "Priya";
employee2.department = "Development";

console.log(employee1.getDetails());
console.log(employee2.getDetails());

employee1.changeDepartment("Embedded Systems");

console.log(employee1.getDetails());
console.log(employee2.getDetails());

console.log(
    employee1.getDetails === employee2.getDetails
);
Expected Output: 
Rahul works in Testing
Priya works in Development
Rahul works in Embedded Systems
Priya works in Development
true

The employee objects share methods but maintain their own data properties.

13. Common Mistakes and Debugging

Mistake 1: Confusing a Prototype with a Constructor's prototype Property

An object's internal prototype is not the same thing as a function's prototype property. The latter is relevant when a function is used as a constructor with new.

Mistake 2: Assuming Inherited Properties Are Own Properties

A property can be accessible on an object without belonging directly to it. Use Object.hasOwn() to check.

Mistake 3: Forgetting the Prototype Chain

A property lookup does not stop at the current object. JavaScript continues searching its prototype chain.

Mistake 4: Modifying a Shared Prototype Carelessly

Changing a shared prototype can affect every object that inherits from it. Avoid adding application-specific mutable state to shared prototypes.

Mistake 5: Using Object.setPrototypeOf() Unnecessarily

Establish the prototype during object creation where possible. Repeatedly changing prototypes can harm performance.

Mistake 6: Assuming Every Object Inherits from Object.prototype

Objects created with Object.create(null) have no prototype and do not inherit Object.prototype methods.

14. Placement Interview Questions and Answers

Q1. What is a prototype in JavaScript?

Answer: A prototype is an object from which another object can inherit properties and methods through the prototype chain.

Q2. What is the prototype chain?

Answer: It is the sequence of prototype objects JavaScript searches when resolving a property or method.

Q3. What is prototype-based inheritance?

Answer: It is an inheritance mechanism in which objects inherit directly from other objects through prototype links.

Q4. What does Object.create() do?

Answer: It creates a new object with the specified object as its prototype.

Q5. What is Object.prototype?

Answer: It is the common prototype object inherited by many ordinary objects created using object literals or constructors.

Q6. How do you get an object's prototype?

Answer: Use Object.getPrototypeOf(object).

Q7. What is the difference between an own property and an inherited property?

Answer: An own property is defined directly on the object. An inherited property is found on one of its prototypes.

Q8. What is the difference between Object.hasOwn() and in?

Answer: Object.hasOwn() checks only own properties, whereas in also checks inherited properties.

Q9. What is property shadowing?

Answer: It occurs when an object defines an own property with the same name as an inherited property.

Q10. Can multiple objects share the same prototype?

Answer: Yes. Multiple objects can inherit from the same prototype and share its methods.

Q11. What does Object.create(null) do?

Answer: It creates an object without a prototype.

Q12. What happens when a property is not found in the prototype chain?

Answer: The property lookup returns undefined.

Q13. What is the difference between [[Prototype]] and prototype?

Answer: [[Prototype]] is an object's internal prototype link. A constructor function's prototype property is the object that instances created using new will inherit from.

16. Coding Exercises

Exercise 1: Create an Inheritance Relationship

  • Own properties belong directly to an object.
  • Inherited properties are obtained from prototype objects.
  • Object.hasOwn() checks own properties only.
  • The in operator checks both own and inherited properties.
