Lesson 3: Object Destructuring and Property Operations

JavaScript Programming Course

Chapter 6: Objects and Object-Oriented JavaScript

Placement-Oriented Learning

1. Learning Objectives

After completing this lesson, you will be able to:

  • Extract object properties into variables using destructuring.
  • Rename extracted properties using aliases.
  • Assign default values during destructuring.
  • Use nested object destructuring.
  • Collect remaining properties using the rest syntax.
  • Understand optional chaining and nullish coalescing.
  • Check whether properties exist in objects.
  • Use property descriptors and control property behavior.

2. What Is Object Destructuring?

Object destructuring is an ES6 feature that allows properties of an object to be extracted and assigned to variables using a concise syntax.

Without Destructuring

const employee = {
    name: "Rahul",
    age: 25,
    department: "Engineering"
};

const name = employee.name;
const age = employee.age;
const department = employee.department;

console.log(name);
console.log(age);
console.log(department);

With Destructuring

const employee = {
    name: "Rahul",
    age: 25,
    department: "Engineering"
};

const { name, age, department } = employee;

console.log(name);
console.log(age);
console.log(department);
Expected Output: 
Rahul
25
Engineering

The variable names match the property names. JavaScript automatically extracts the corresponding values.

General Syntax:

const { property1, property2 } = objectName;

3. Destructuring with Different Variable Names

Sometimes, you may want to assign an object property to a variable with a different name. This is done using an alias.

Syntax:

const { propertyName: variableName } = objectName;

Example

const student = {
    name: "Priya",
    marks: 92
};

const { name: studentName, marks: score } = student;

console.log(studentName);
console.log(score);
Expected Output: 
Priya
92

Here, name is assigned to studentName, and marks is assigned to score.

Important: The alias becomes the local variable name. Destructuring does not rename the original object property.

4. Default Values in Object Destructuring

A default value is used when a property is missing or its value is undefined.

Syntax:

const { property = defaultValue } = objectName;

Example 1: Missing Property

const employee = {
    name: "Amit",
    department: "IT"
};

const { name, salary = 30000 } = employee;

console.log(name);
console.log(salary);
Expected Output: 
Amit
30000

Example 2: Existing Property with undefined

const user = {
    name: "Neha",
    city: undefined
};

const { name, city = "Delhi" } = user;

console.log(name);
console.log(city);
Expected Output: 
Neha
Delhi

Example 3: Existing null Value

const user = {
    city: null
};

const { city = "Delhi" } = user;

console.log(city);
Expected Output: 
null

Default values apply to undefined, not to null, zero, false or an empty string.

5. Combining Aliases and Default Values

You can rename a property and assign a default value in the same destructuring expression. 

const employee = {
    name: "Rohit",
    department: "Software"
};

const {
    name: employeeName,
    department: team = "General",
    salary: monthlySalary = 25000
} = employee;

console.log(employeeName);
console.log(team);
console.log(monthlySalary);
Expected Output: 
Rohit
Software
25000

The original property is written first, followed by a colon and the variable name. A default value can then be specified using =.

6. Nested Object Destructuring

Nested destructuring extracts properties from objects contained inside another object.

Example

const employee = {
    name: "Karan",
    department: {
        name: "Development",
        location: "Chandigarh"
    }
};

const {
    name,
    department: {
        name: departmentName,
        location
    }
} = employee;

console.log(name);
console.log(departmentName);
console.log(location);
Expected Output: 
Karan
Development
Chandigarh

The nested department object is destructured directly. The alias departmentName avoids conflicting with the employee's name variable.

Nested destructuring requires the nested object to exist. If department is undefined or null, the expression above throws a TypeError.

Safe Nested Destructuring with a Default Object

const employee = {
    name: "Karan"
};

const {
    department: {
        name: departmentName = "Not Assigned"
    } = {}
} = employee;

console.log(departmentName);
Expected Output: 
Not Assigned

7. Rest Properties in Object Destructuring

The object rest syntax (...) collects all remaining enumerable own properties that have not already been extracted into a new object.

Syntax:

const { property1, ...remainingProperties } = objectName;

Example

const employee = {
    name: "Rahul",
    age: 26,
    department: "IT",
    salary: 45000
};

const { name, ...otherDetails } = employee;

console.log(name);
console.log(otherDetails);
Expected Output: 
Rahul
{
  age: 26,
  department: 'IT',
  salary: 45000
}

The name property is extracted separately. All remaining enumerable own properties are collected into otherDetails.

Practical Example: Excluding Sensitive Information

const user = {
    id: 101,
    name: "Aman",
    email: "aman@example.com",
    password: "secret123"
};

const { password, ...publicProfile } = user;

console.log(publicProfile);
Expected Output: 
{
  id: 101,
  name: 'Aman',
  email: 'aman@example.com'
}
This example demonstrates excluding a property from an object. It is not a substitute for proper security controls or server-side protection of sensitive data.

8. Destructuring Function Parameters

Object destructuring can be used directly in function parameters. This is especially useful when a function accepts configuration objects or structured data.

Example

function displayEmployee({ name, department, salary }) {
    console.log("Name:", name);
    console.log("Department:", department);
    console.log("Salary:", salary);
}

const employee = {
    name: "Priya",
    department: "Testing",
    salary: 40000
};

displayEmployee(employee);
Expected Output: 
Name: Priya
Department: Testing
Salary: 40000

Using Default Values in Function Parameters

function createUser({
    name,
    role = "User",
    active = true
} = {}) {
    console.log(name);
    console.log(role);
    console.log(active);
}

createUser({ name: "Aman" });
createUser();
Expected Output: 
Aman
User
true
undefined
User
true

The = {} provides a default empty object when the entire argument is omitted or explicitly undefined. The individual defaults handle missing or undefined properties.

9. Optional Chaining (?.)

Optional chaining allows you to safely access properties of objects that may be null or undefined.

Syntax:

object?.property
object?.[expression]
object.method?.()

Example 1: Without Optional Chaining

const user = {
    name: "Rahul"
};

console.log(user.address.city);
Result: 
TypeError: Cannot read properties of undefined (reading 'city')

Example 2: With Optional Chaining

const user = {
    name: "Rahul"
};

console.log(user.address?.city);
console.log(user.name);
Expected Output: 
undefined
Rahul

Example 3: Optional Chaining with Nested Properties

const employee = {
    name: "Neha",
    address: {
        city: "Mohali"
    }
};

console.log(employee.address?.city);
console.log(employee.contact?.phone);
Expected Output: 
Mohali
undefined

Example 4: Optional Chaining with Arrays

const company = {
    employees: [
        { name: "Aman" },
        { name: "Priya" }
    ]
};

console.log(company.employees?.[0]?.name);
console.log(company.departments?.[0]?.name);
Expected Output: 
Aman
undefined

Example 5: Optional Method Calls

const user = {
    name: "Ravi"
};

user.display?.();

console.log("Program continues");
Expected Output: 
Program continues

The optional call skips the invocation when display is null or undefined.

Optional chaining does not make every invalid operation safe. If a property exists but is not callable, attempting to call it with ?.() still throws a TypeError.

10. Nullish Coalescing Operator (??)

The nullish coalescing operator provides a fallback value only when the left-hand expression is null or undefined.

Syntax:

const result = value ?? defaultValue;

Example

const user1 = {
    name: "Aman",
    city: null
};

const user2 = {
    name: "Priya",
    city: ""
};

console.log(user1.city ?? "Delhi");
console.log(user2.city ?? "Delhi");
Expected Output: 
Delhi

The second output is an empty string, so the second line appears blank.

Difference Between || and ??

console.log(0 || 100);
console.log(0 ?? 100);

console.log(false || true);
console.log(false ?? true);

console.log("" || "Default");
console.log("" ?? "Default");
Expected Output: 
100
0
true
false
Default

The final output is an empty string.

"Hello""Hello""Hello"

Use ?? when zero, false or an empty string are valid values that should not be replaced.

11. Checking Whether an Object Has a Property

JavaScript provides several ways to check whether a property exists in an object. These methods do not all behave identically.

11.1 The in Operator

The in operator checks whether a property exists either directly on the object or anywhere in its prototype chain. 

const employee = {
    name: "Rahul",
    salary: 35000
};

console.log("name" in employee);
console.log("age" in employee);
Expected Output: 
true
false

11.2 Object.hasOwn()

Object.hasOwn() checks whether a property exists directly on the object, not on its prototype chain. 

const employee = {
    name: "Priya"
};

console.log(Object.hasOwn(employee, "name"));
console.log(Object.hasOwn(employee, "age"));
Expected Output: 
true
false

11.3 hasOwnProperty()

This method also checks whether a property is an own property of an object. 

const employee = {
    name: "Aman"
};

console.log(employee.hasOwnProperty("name"));
console.log(employee.hasOwnProperty("age"));
Expected Output: 
true
false

11.4 Difference Between the Property Checks

const parent = {
    department: "IT"
};

const employee = Object.create(parent);
employee.name = "Rahul";

console.log("name" in employee);
console.log("department" in employee);

console.log(Object.hasOwn(employee, "name"));
console.log(Object.hasOwn(employee, "department"));
Expected Output: 
true
true
true
false
Method Checks own property Checks prototype chain
in Yes Yes
Object.hasOwn() Yes No
hasOwnProperty() Yes No
Interview tip: Prefer Object.hasOwn(object, property) for a direct own-property check. It also works safely with objects that do not inherit from Object.prototype.

12. Property Descriptors

Object properties have attributes that control how they behave. These attributes are called property descriptors.

For a normal data property, the main attributes are:

  • value: The value stored in the property.
  • writable: Whether the value can be changed.
  • enumerable: Whether the property appears in common enumeration operations.
  • configurable: Whether the property can be deleted or its descriptor changed.

12.1 Object.getOwnPropertyDescriptor()

const employee = {
    name: "Rahul"
};

const descriptor =
    Object.getOwnPropertyDescriptor(employee, "name");

console.log(descriptor);

Typical Result:

{
    value: "Rahul",
    writable: true,
    enumerable: true,
    configurable: true
}

12.2 Object.defineProperty()

This method allows you to define a property with custom descriptor attributes. 

const user = {};

Object.defineProperty(user, "id", {
    value: 101,
    writable: false,
    enumerable: true,
    configurable: false
});

console.log(user.id);
Expected Output: 
101

The property cannot be reassigned or deleted under these descriptor settings.

12.3 Testing a Non-Writable Property

"use strict";

const user = {};

Object.defineProperty(user, "id", {
    value: 101,
    writable: false
});

user.id = 202;
Expected Result: 
TypeError: Cannot assign to read only property 'id'

In strict mode, assigning a new value to a non-writable property throws a TypeError.

When descriptor attributes are omitted in Object.defineProperty(), they default to false for a newly defined property. This differs from properties created through ordinary object-literal syntax, whose data-property attributes are normally true.

13. Object.freeze(), Object.seal() and Object.preventExtensions()

These methods control whether an object can be modified, extended or have its properties deleted.

13.1 Object.preventExtensions()

Prevents new properties from being added to an object. Existing properties may still be modified or deleted, subject to their descriptors. 

const user = {
    name: "Aman"
};

Object.preventExtensions(user);

user.age = 25;
user.name = "Rahul";

console.log(user.name);
console.log(user.age);
console.log(Object.isExtensible(user));
Expected Output: 
Rahul
undefined
false

13.2 Object.seal()

Prevents adding or deleting properties. Existing writable data properties can still be updated. 

const user = {
    name: "Aman",
    age: 25
};

Object.seal(user);

user.name = "Rahul";
delete user.age;
user.city = "Delhi";

console.log(user);
console.log(Object.isSealed(user));
Expected Output: 
{ name: 'Rahul', age: 25 }
true

13.3 Object.freeze()

Prevents adding, deleting or changing existing own properties. It is stronger than sealing for ordinary data properties. 

const user = {
    name: "Priya",
    age: 24
};

Object.freeze(user);

user.name = "Neha";
user.city = "Pune";

console.log(user);
console.log(Object.isFrozen(user));
Expected Output: 
{ name: 'Priya', age: 24 }
true
Operation preventExtensions() seal() freeze()
Add new properties No No No
Delete existing properties Yes, if configurable No No
Update writable properties Yes Yes No
Prevent extensions Yes Yes Yes
Important: These operations are shallow. Freezing an object does not automatically freeze nested objects. A nested object can still be modified unless it is frozen separately.

14. Practical Example: Processing API Response Data

Frontend applications frequently receive objects from APIs. Destructuring and optional chaining help extract data safely. 

const apiResponse = {
    status: "success",
    data: {
        user: {
            id: 101,
            name: "Priya",
            email: "priya@example.com"
        },
        address: {
            city: "Chandigarh"
        }
    }
};

const {
    status,
    data: {
        user: {
            id,
            name,
            email
        },
        address
    }
} = apiResponse;

console.log("Status:", status);
console.log("User ID:", id);
console.log("Name:", name);
console.log("Email:", email);
console.log("City:", address?.city);
Expected Output: 
Status: success
User ID: 101
Name: Priya
Email: priya@example.com
City: Chandigarh

Concepts applied:

  • Nested object destructuring.
  • Property extraction and aliases.
  • Optional chaining.
  • Working with structured API response data.

15. Common Mistakes and Debugging

Mistake 1: Using the Wrong Variable Name

const user = {
    name: "Aman"
};

const { username } = user;

console.log(username);

Result: undefined, because the object contains name, not username.

Correction:

const { name: username } = user;

console.log(username);

Mistake 2: Destructuring a Null or Undefined Object

const user = undefined;

const { name } = user;

Problem: Destructuring null or undefined throws a TypeError.

Correction:

const user = undefined;

const { name } = user || {};

console.log(name);

Mistake 3: Assuming Default Values Replace null

const user = {
    age: null
};

const { age = 18 } = user;

console.log(age);

Output: null.

Use nullish coalescing when both null and undefined should trigger a fallback: 

const age = user.age ?? 18;

console.log(age);

Mistake 4: Accessing Nested Properties Without Checking

const user = {
    name: "Aman"
};

console.log(user.address.city);

Problem: The address property does not exist, so accessing city throws an error.

Correction:

console.log(user.address?.city);

Mistake 5: Confusing in with Object.hasOwn()

The in operator includes inherited properties, whereas Object.hasOwn() checks only properties directly owned by the object.

16. Placement Interview Questions and Answers

Q1. What is object destructuring?

Answer: Object destructuring is an ES6 feature used to extract object properties into variables using a concise syntax.

Q2. How do you rename a property during destructuring?

Answer: Use an alias with a colon: const { name: employeeName } = employee;.

Q3. When are default values used in destructuring?

Answer: When the extracted property is undefined. They do not replace null.

Q4. What is nested destructuring?

Answer: It extracts properties from nested objects directly within a destructuring pattern.

Q5. What is the purpose of the rest property?

Answer: It collects the remaining enumerable own properties into a new object after specified properties have been extracted.

Q6. What is optional chaining?

Answer: Optional chaining (?.) safely accesses properties or calls methods when an intermediate value may be null or undefined.

Q7. What is the difference between || and ???

Answer: || uses the fallback for any falsy value. ?? uses it only for null or undefined.

Q8. What is the difference between in and Object.hasOwn()?

Answer: in checks own and inherited properties. Object.hasOwn() checks only own properties.

Q9. What is a property descriptor?

Answer: It defines property attributes such as value, writable, enumerable and configurable for data properties.

Q10. What is the difference between Object.seal() and Object.freeze()?

Answer: A sealed object cannot have properties added or deleted, but writable existing properties can be changed. A frozen object also prevents changing existing data-property values.

Q11. Does Object.freeze() freeze nested objects?

Answer: No. It is shallow and affects only the object's own properties. Nested objects need separate freezing.

Q12. Can object destructuring be used in function parameters?

Answer: Yes. It is useful for extracting named options and configuration values directly inside a function.

18. Coding Exercises

Exercise 1: Employee Destructuring

Create an employee object containing name, age, salary and department. Extract its properties using destructuring. Rename salary to monthlySalary.

Exercise 2: Default Values

Create a user object with name and email. Extract name, email and city, assigning "Not Provided" as the default city.

Exercise 3: Nested Destructuring

Create a student object containing a nested address object with city and state. Extract the student's name, city and state.

Exercise 4: Rest Properties

Create a product object with id, name, price, category and stock. Extract id and name separately and collect the remaining properties into another object.

Exercise 5: Function Parameter Destructuring

Write a function that accepts an employee object and displays name, department and salary using parameter destructuring.

Exercise 6: Safe API Data Access

Create a nested API response object. Use optional chaining to access user name, address city and contact number safely.

Exercise 7: Property Verification

Create an object using Object.create() with an inherited property. Add an own property and compare in with Object.hasOwn().

Exercise 8: Property Descriptors

Define an object property using Object.defineProperty() with writable: false. Inspect its descriptor and test reassignment in strict mode.

Exercise 9: Object Protection

Create three separate objects and apply Object.preventExtensions(), Object.seal() and Object.freeze(). Test adding, deleting and updating properties.

19. Lesson Summary

  • Object destructuring extracts properties into variables.
  • Aliases allow properties to be assigned to differently named variables.
  • Default values apply when a destructured property is undefined.
  • Nested destructuring extracts values from nested objects.
  • Rest properties collect remaining enumerable own properties.
  • Functions can destructure their object parameters.
  • Optional chaining safely accesses potentially nullish values.
  • Nullish coalescing provides fallbacks for null and undefined.
  • in checks own and inherited properties.
  • Object.hasOwn() checks only own properties.
  • Property descriptors control property behavior.
  • Object.preventExtensions(), seal() and freeze() restrict object modifications at different levels.
