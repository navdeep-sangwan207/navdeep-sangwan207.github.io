Lesson 1: Synchronous and Asynchronous Execution

Understand how JavaScript executes statements, why long-running operations can block execution, and how asynchronous operations allow applications to remain responsive.

1. Learning Objectives

  • Understand how JavaScript executes code.
  • Explain synchronous and asynchronous execution.
  • Differentiate blocking and non-blocking operations.
  • Understand the single-threaded nature of JavaScript execution.
  • Identify operations that commonly use asynchronous APIs.
  • Predict the output of basic synchronous and asynchronous programs.
  • Understand why asynchronous programming is important in frontend development.

2. How JavaScript Executes Code

JavaScript normally executes application code on a single main thread in a browser. Statements are processed one at a time, following the order in which they are encountered, unless the program uses control-flow mechanisms or asynchronous scheduling.

The JavaScript engine uses a call stack to keep track of the functions currently being executed. When a function is called, its execution context is pushed onto the stack. When the function finishes, its context is removed.

Example: Sequential JavaScript Execution

console.log("Start");

let a = 10;
let b = 20;

let sum = a + b;

console.log("Sum:", sum);
console.log("End");
Expected Output: 
Start
Sum: 30
End

Each statement executes in sequence. The next statement runs after the current synchronous statement has completed.

3. Synchronous Execution

Synchronous execution means that operations execute in sequence. A later operation must wait until the current synchronous operation finishes.

This execution model makes program flow straightforward because each statement completes before the next statement begins.

Example 1: Synchronous Function Calls

function first() {
    console.log("First function");
}

function second() {
    console.log("Second function");
}

console.log("Program started");

first();
second();

console.log("Program finished");
Expected Output: 
Program started
First function
Second function
Program finished

Example 2: A Function That Delays Execution

function calculate() {
    let total = 0;

    for (let i = 0; i < 1000000; i++) {
        total += i;
    }

    console.log("Calculation completed");
}

console.log("Start");

calculate();

console.log("End");
Expected Output Order: 
Start
Calculation completed
End

The loop executes synchronously. The final message cannot be printed until the function returns.

4. Blocking Operations

A blocking operation prevents the current JavaScript execution thread from continuing until that operation completes.

Long-running synchronous calculations, expensive loops, and synchronous APIs can block the browser's main thread.

Example: Blocking the Main Thread

console.log("Task 1 started");

const start = Date.now();

// Artificially block the main thread for approximately 3 seconds.
while (Date.now() - start < 3000) {
    // Busy waiting
}

console.log("Task 1 completed");
console.log("Task 2 started");
Expected Output Order: 
Task 1 started
(Approximately 3 seconds pass)
Task 1 completed
Task 2 started

During the busy-wait loop, the JavaScript main thread cannot process other JavaScript tasks. In a browser, this can make the page unresponsive.

Important: Busy waiting is used here only to demonstrate blocking. It should not be used for normal application delays because it wastes CPU time and blocks the main thread.

5. Asynchronous Execution

Asynchronous execution allows certain operations to be handled without requiring the JavaScript main thread to wait for the entire operation to finish.

Browsers provide APIs for operations such as timers, network requests, and user events. When an asynchronous operation is ready, its callback or Promise reaction can be scheduled for JavaScript execution.

The current synchronous code continues running instead of waiting for the asynchronous operation to finish.

Example: setTimeout()

console.log("Start");

setTimeout(function () {
    console.log("Timer callback executed");
}, 2000);

console.log("End");
Expected Output Order: 
Start
End
(After approximately 2 seconds)
Timer callback executed

The timer callback is not executed immediately. The synchronous statements continue first. Once the timer becomes eligible and the JavaScript environment can process its callback, it runs.

Important: The delay passed to setTimeout() is a minimum scheduling threshold, not a guarantee that the callback will execute at exactly that time.

Example: Simulating a Network Operation

console.log("Request started");

setTimeout(function () {
    console.log("Server response received");
}, 1500);

console.log("Other work continues");
Expected Output Order: 
Request started
Other work continues
(After approximately 1.5 seconds)
Server response received

This example simulates delayed work using a timer. It demonstrates the execution order, but it is not an actual HTTP network request.

6. Non-Blocking Operations

A non-blocking operation allows JavaScript to continue executing other code instead of waiting synchronously for the operation to complete.

For example, a browser can initiate a network request and continue processing other work while the request is in progress. Its result is handled later through a Promise or callback.

Example: Using fetch()

console.log("Before request");

fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(function (response) {
        if (!response.ok) {
            throw new Error("HTTP error: " + response.status);
        }

        return response.json();
    })
    .then(function (user) {
        console.log("User:", user.name);
    })
    .catch(function (error) {
        console.log("Request failed:", error.message);
    });

console.log("After request");

Expected Output Order:

Before request
After request
User: (name returned by the API)

The actual user name depends on the server response. If the request fails, the catch handler displays an error instead.

The browser handles the network operation outside the normal synchronous JavaScript execution flow. The Promise handlers execute later when the operation settles.

Interview Point: fetch() normally rejects for network-level failures, but an HTTP error response such as 404 or 500 does not automatically reject the Promise. Check response.ok to handle unsuccessful HTTP statuses.

7. Synchronous vs Asynchronous Execution

Basis Synchronous Asynchronous
Execution Operations execute in sequence. Some operations complete later while other work continues.
Waiting Later statements wait for the current synchronous operation. The main thread does not need to wait for the asynchronous operation.
Blocking Long-running work can block the main thread. Asynchronous APIs can avoid blocking while waiting for external work.
Execution flow Usually straightforward and sequential. Requires handling completion and errors.
Examples Arithmetic, normal function calls, loops. Timers, network requests, event callbacks, Promise reactions.
Typical use Calculations and immediate operations. API requests, delayed tasks, and user-driven events.

8. Is JavaScript Single-Threaded?

JavaScript application code in a browser normally runs on the main thread, which executes one piece of JavaScript at a time. This is why JavaScript is commonly described as single-threaded.

However, the browser environment provides additional capabilities for handling operations such as networking, timers, rendering, and user input. These facilities allow asynchronous operations to progress without blocking the main JavaScript execution flow.

JavaScript also supports Web Workers, which can run JavaScript in separate worker threads for suitable background tasks. A Web Worker does not share the main thread's normal JavaScript execution context.

Important Distinction

  • JavaScript language execution and browser APIs are different concepts.
  • The call stack executes JavaScript functions.
  • Browser APIs provide facilities such as timers and network operations.
  • The Event Loop coordinates when scheduled callbacks and Promise reactions can run.
  • Web Workers can perform suitable JavaScript work in separate threads.

The Event Loop, call stack, and task queues are explained in detail in Lesson 7.

9. Real-World Applications

Frontend Development

  • Fetching user information from a backend API.
  • Loading product data on an e-commerce website.
  • Submitting forms without reloading the entire page.
  • Displaying search suggestions while a user types.
  • Handling button clicks and other user interactions.
  • Loading images and other resources.

Example: Button Click and Delayed Operation

<button id="loadBtn">Load Data</button>
<p id="message">Click the button to start.</p>

<script>
    const button = document.getElementById("loadBtn");
    const message = document.getElementById("message");

    button.addEventListener("click", function () {
        message.textContent = "Loading...";

        setTimeout(function () {
            message.textContent = "Data loaded successfully!";
        }, 2000);
    });
</script>

When the user clicks the button, the page displays a loading message immediately. After the timer becomes eligible, the message changes. The page remains available for other interactions while waiting.

10. Common Mistakes

  1. Assuming setTimeout() blocks execution: It schedules a callback; it does not make the current synchronous code wait.
  2. Assuming a timer runs at an exact time: Its callback may run later if the main thread is busy or other scheduling conditions delay it.
  3. Calling all asynchronous operations parallel: Asynchronous execution does not automatically mean that every operation runs simultaneously.
  4. Assuming JavaScript never uses multiple threads: Web Workers and browser internals provide additional threading capabilities.
  5. Confusing asynchronous execution with non-blocking computation: An expensive synchronous loop still blocks the main thread even if other asynchronous APIs exist.
  6. Assuming fetch() returns the final response data immediately: It returns a Promise that must be handled asynchronously.

11. Placement Interview Questions

Q1. What is synchronous execution in JavaScript?

Answer: Synchronous execution means statements execute in sequence. The next synchronous operation waits until the current operation completes.

Q2. What is asynchronous execution?

Answer: Asynchronous execution allows operations such as timers and network requests to progress without requiring the JavaScript main thread to wait for their completion. Their results are handled later.

Q3. Is JavaScript single-threaded?

Answer: JavaScript code in a browser normally executes on a single main thread. However, browser facilities and Web Workers provide additional ways to handle work outside that main JavaScript execution thread.

Q4. What is the difference between blocking and non-blocking operations?

Answer: A blocking operation prevents the current execution thread from continuing until it completes. A non-blocking operation allows other work to continue while the operation is being handled.

Q5. Does setTimeout() execute its callback exactly after the specified delay?

Answer: No. The delay is a minimum scheduling threshold. The callback runs when it becomes eligible and the JavaScript environment can process it.

Q6. Does asynchronous JavaScript always mean parallel execution?

Answer: No. Asynchronous execution means the program does not synchronously wait for an operation to complete. Parallel execution means multiple operations actually execute at the same time, generally using multiple threads or processors.

Q7. Why is asynchronous programming important in frontend development?

Answer: It allows applications to handle network requests, timers, and user interactions without unnecessarily blocking the main JavaScript thread, helping maintain responsive user interfaces.

Q8. Does fetch() block JavaScript execution?

Answer: No. fetch() initiates a network request and returns a Promise. JavaScript can continue executing other synchronous statements while the request is in progress.

12. Output-Based Interview Questions

Question 1: Predict the output.

console.log("A");

setTimeout(function () {
    console.log("B");
}, 0);

console.log("C");

Expected Output:

A
C
B

Explanation: The timer callback is scheduled for later execution. The synchronous statements print A and C before the callback runs.

Question 2: Predict the output.

function showMessage() {
    console.log("Inside function");
}

console.log("Start");

showMessage();

console.log("End");

Expected Output:

Start
Inside function
End

Explanation: The function call is synchronous. It completes before execution moves to the final statement.

Question 3: Predict the output.

console.log("One");

setTimeout(function () {
    console.log("Two");
}, 1000);

console.log("Three");

setTimeout(function () {
    console.log("Four");
}, 0);

console.log("Five");

Expected Output Order:

One
Three
Five
Four
(After approximately 1 second)
Two

Explanation: All synchronous statements execute first. Both timer callbacks are scheduled. The zero-delay timer becomes eligible before the one-second timer, so Four appears before Two, assuming the page is able to process the callbacks.

14. Lesson Summary

  • JavaScript executes synchronous statements in sequence.
  • Long-running synchronous operations can block the main thread.
  • Asynchronous APIs allow certain operations to progress without blocking JavaScript execution.
  • Timers and network requests are common examples of asynchronous operations.
  • JavaScript uses a call stack to manage function execution.
  • The browser environment provides APIs that work with JavaScript's asynchronous execution model.
  • Asynchronous execution does not necessarily mean parallel execution.
  • The Event Loop coordinates the execution of scheduled callbacks and Promise reactions.
