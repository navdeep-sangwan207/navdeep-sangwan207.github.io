Chapter 10: Asynchronous JavaScript, Promises and Event Loop

Lesson 5: Then, Catch and Finally Methods

Handle Promise fulfillment and rejection, understand error propagation, and execute cleanup logic using Promise handlers.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Use the .then() method to handle fulfillment.
  • Handle rejected Promises using .catch().
  • Execute cleanup logic using .finally().
  • Understand how Promise handlers return new Promises.
  • Trace rejection propagation through a Promise chain.
  • Recover from errors and continue a Promise chain.
  • Understand how errors thrown inside handlers are propagated.
  • Apply Promise handling to practical frontend scenarios.

2. Overview of Promise Handling Methods

A Promise provides methods to handle its eventual fulfillment or rejection.

Method Purpose Handler behavior
.then() Handles fulfillment and optionally rejection. Receives the fulfillment value or rejection reason through the corresponding handler.
.catch() Handles rejection. Receives the rejection reason.
.finally() Runs cleanup logic after settlement. Does not receive the fulfillment value or rejection reason as arguments.

General syntax

promise
    .then(onFulfilled, onRejected)
    .catch(onRejected)
    .finally(onFinally);
All three methods return a new Promise. This is what makes Promise chaining possible.

3. then() Method

The then() method attaches handlers to a Promise. Its first argument is an optional fulfillment handler, and its second argument is an optional rejection handler.

Syntax

promise.then(onFulfilled);

promise.then(onFulfilled, onRejected);

3.1 Handling fulfillment

const promise = Promise.resolve("Data loaded");

promise.then(result => {
    console.log(result);
});

Expected output:

Data loaded

3.2 Handling rejection using the second argument

const promise = Promise.reject("Server unavailable");

promise.then(
    result => {
        console.log("Success:", result);
    },
    error => {
        console.log("Failure:", error);
    }
);

Expected output:

Failure: Server unavailable

The fulfillment handler is skipped because the Promise is rejected. The rejection handler receives the rejection reason.

3.3 then() returns a new Promise

const originalPromise = Promise.resolve(10);

const newPromise = originalPromise.then(value => {
    return value * 2;
});

newPromise.then(result => {
    console.log(result);
});
20

The original Promise remains unchanged. The Promise returned by then() fulfills with the handler's returned value.

4. catch() Method

The catch() method attaches a rejection handler to a Promise. It is commonly used to handle errors from asynchronous operations.

Syntax

promise.catch(errorHandler);

Calling catch(handler) is equivalent to calling then(undefined, handler).

4.1 Basic rejection handling

const promise = new Promise((resolve, reject) => {
    reject(new Error("Unable to load data"));
});

promise.catch(error => {
    console.log("Error:", error.message);
});
Error: Unable to load data

4.2 Handling errors from a Promise chain

Promise.resolve(10)
    .then(value => {
        console.log("Initial value:", value);

        throw new Error("Processing failed");
    })
    .then(value => {
        console.log("Processed value:", value);
    })
    .catch(error => {
        console.log("Caught:", error.message);
    });

Expected output:

Initial value: 10
Caught: Processing failed

When a handler throws an error, the Promise returned by that handler becomes rejected. The next fulfillment handler is skipped until a rejection handler handles the error.

4.3 Error recovery using catch()

A catch handler can recover from a failure by returning an ordinary value or another Promise. The resulting Promise can then fulfill, allowing the next fulfillment handler to run. 

Promise.reject(new Error("Network error"))
    .catch(error => {
        console.log("Handled:", error.message);

        return "Fallback data";
    })
    .then(result => {
        console.log("Result:", result);
    });

Expected output:

Handled: Network error
Result: Fallback data
Returning a fallback value from catch() converts the resulting chain into a fulfilled Promise, unless the handler throws an error or returns a rejected Promise.

5. finally() Method

The finally() method executes a callback after a Promise settles, regardless of whether it fulfills or rejects. It is commonly used for cleanup operations.

Syntax

promise.finally(() => {
    // Cleanup operation
});

5.1 finally() after successful completion

Promise.resolve("File uploaded")
    .then(result => {
        console.log(result);
    })
    .finally(() => {
        console.log("Upload process finished");
    });
File uploaded
Upload process finished

5.2 finally() after failure

Promise.reject(new Error("Upload failed"))
    .catch(error => {
        console.log(error.message);
    })
    .finally(() => {
        console.log("Upload process finished");
    });
Upload failed
Upload process finished

5.3 finally() does not receive the result

Promise.resolve("Payment successful")
    .finally(value => {
        console.log("Finally value:", value);
    })
    .then(result => {
        console.log("Result:", result);
    });

Expected output:

Finally value: undefined
Result: Payment successful

The callback passed to finally() does not receive the fulfillment value or rejection reason as an argument. If it completes normally, the original outcome is passed through to the next Promise.

5.4 finally() preserves the original outcome

Promise.resolve(100)
    .finally(() => {
        console.log("Cleanup completed");
    })
    .then(value => {
        console.log("Value:", value);
    });
Cleanup completed
Value: 100

A normally completed finally() callback does not replace the original fulfillment value.

5.5 When finally() throws an error

Promise.resolve("Original result")
    .finally(() => {
        throw new Error("Cleanup failed");
    })
    .then(value => {
        console.log("Success:", value);
    })
    .catch(error => {
        console.log("Error:", error.message);
    });
Error: Cleanup failed

If the finally callback throws an error, the Promise returned by finally() becomes rejected with that error.

5.6 When finally() returns a rejected Promise

Promise.resolve("Original result")
    .finally(() => {
        return Promise.reject(new Error("Cleanup rejected"));
    })
    .catch(error => {
        console.log(error.message);
    });
Cleanup rejected

If the finally callback returns a Promise, the Promise returned by finally() waits for it to settle. A rejection from that returned Promise overrides the original outcome.

6. Difference Between then(), catch() and finally()

Feature then() catch() finally()
Primary purpose Handle fulfillment and optionally rejection. Handle rejection. Perform cleanup after settlement.
Receives fulfillment value Yes, in fulfillment handler. No. No.
Receives rejection reason Yes, in optional rejection handler. Yes. No.
Returns a Promise Yes Yes Yes
Can recover from rejection Yes, using a rejection handler. Yes, by returning a normal value or fulfilled Promise. Not intended for recovery.
Typical use Process returned data. Handle errors. Hide loading indicators or release resources.

7. Promise Error Propagation

Promise rejection propagates through a chain until a rejection handler handles it. A missing fulfillment handler does not prevent rejection from continuing through the chain.

Example: Error propagating through multiple handlers

Promise.resolve(5)
    .then(value => {
        console.log("Step 1:", value);
        return value + 5;
    })
    .then(value => {
        console.log("Step 2:", value);
        throw new Error("Step 3 failed");
    })
    .then(value => {
        console.log("Step 3:", value);
    })
    .then(value => {
        console.log("Step 4:", value);
    })
    .catch(error => {
        console.log("Caught:", error.message);
    })
    .then(() => {
        console.log("Chain completed");
    });

Expected output:

Step 1: 5
Step 2: 10
Caught: Step 3 failed
Chain completed

The thrown error skips the subsequent fulfillment handlers. The catch handler handles the rejection and returns normally. Therefore, the final .then() runs.

Example: Error propagation without recovery

Promise.reject(new Error("Request failed"))
    .then(value => {
        console.log("Success:", value);
    })
    .then(value => {
        console.log("Next:", value);
    })
    .catch(error => {
        console.log("Handled:", error.message);
        throw new Error("Recovery failed");
    })
    .then(value => {
        console.log("Final success:", value);
    })
    .catch(error => {
        console.log("Final error:", error.message);
    });

Expected output:

Handled: Request failed
Final error: Recovery failed

The first catch handles the original rejection but throws a new error. The new rejection propagates to the final catch.

8. Practical Example: Fetch API with Promise Handling

The Fetch API returns a Promise that fulfills with a Response object when a response is received. An HTTP error status such as 404 does not automatically reject the Fetch Promise, so check response.ok. 

fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => {
        if (!response.ok) {
            throw new Error("HTTP error: " + response.status);
        }

        return response.json();
    })
    .then(user => {
        console.log("Name:", user.name);
        console.log("Email:", user.email);
    })
    .catch(error => {
        console.log("Request failed:", error.message);
    })
    .finally(() => {
        console.log("Request completed");
    });

Expected output when the request succeeds:

Name: Leanne Graham
Email: Sincere@april.biz
Request completed

The exact output depends on the server response and network availability. If the request fails, the catch handler displays an error and finally still executes.

Frontend development practice: Always check response.ok when using Fetch. A response with an HTTP error status is still a fulfilled Fetch Promise unless a separate error is thrown.

9. Practical Example: Loading Indicator Cleanup

A common frontend requirement is to show a loading indicator while an API request is in progress and hide it after the request succeeds or fails. 

function fetchUser() {
    console.log("Loading indicator: ON");

    return fetch("https://jsonplaceholder.typicode.com/users/1")
        .then(response => {
            if (!response.ok) {
                throw new Error("Unable to fetch user");
            }

            return response.json();
        })
        .then(user => {
            console.log("User:", user.name);
            return user;
        })
        .catch(error => {
            console.log("Error:", error.message);
            throw error;
        })
        .finally(() => {
            console.log("Loading indicator: OFF");
        });
}

fetchUser().catch(error => {
    console.log("Request ended with an error");
});

The loading indicator is turned off whether the request succeeds or fails. In a real application, the finally() callback would update the DOM or application state.

The example rethrows the error after logging it. This keeps the returned Promise rejected, allowing the calling code to handle the failure as well.

10. Common Mistakes and Debugging

Mistake 1: Using then() without returning a value

Promise.resolve(10)
    .then(value => {
        value * 2;
    })
    .then(result => {
        console.log(result);
    });

Problem: The second handler receives undefined.

Correction:

Promise.resolve(10)
    .then(value => {
        return value * 2;
    })
    .then(result => {
        console.log(result);
    });

Mistake 2: Throwing an error without a rejection handler

Promise.resolve()
    .then(() => {
        throw new Error("Something failed");
    });

Problem: The resulting Promise is rejected without a handler. This can produce an unhandled rejection warning.

Correction:

Promise.resolve()
    .then(() => {
        throw new Error("Something failed");
    })
    .catch(error => {
        console.log(error.message);
    });

Mistake 3: Assuming finally() receives the result

Promise.resolve("Success")
    .finally(result => {
        console.log(result);
    });

Problem: The callback receives undefined.

Correction: Use then() when the fulfillment value is needed. Use finally() for cleanup that does not depend on the result.

Mistake 4: Swallowing an error unintentionally

fetch("/api/user")
    .catch(error => {
        console.log(error);
    })
    .then(() => {
        console.log("This can run after the error was handled");
    });

Explanation: The catch handler returns normally, so the chain becomes fulfilled with undefined. The following fulfillment handler can execute.

If the calling code must know that the operation failed, rethrow the error or return a rejected Promise.

11. Placement Interview Questions and Answers

Q1. What does the then() method do?

It attaches fulfillment and optionally rejection handlers to a Promise and returns a new Promise.

Q2. What is the purpose of catch()?

It attaches a rejection handler to a Promise. It is equivalent to then(undefined, onRejected).

Q3. What is the purpose of finally()?

It executes cleanup logic after a Promise settles, whether fulfilled or rejected.

Q4. Does finally() receive the Promise result?

No. Its callback does not receive the fulfillment value or rejection reason as arguments.

Q5. Does finally() change the original Promise result?

If its callback completes normally, the original fulfillment value or rejection reason is preserved. If the callback throws or returns a rejected Promise, the resulting Promise is rejected with that new error or rejection reason.

Q6. What happens when an error is thrown inside then()?

The Promise returned by that then() call becomes rejected. The rejection propagates until a rejection handler handles it.

Q7. Can catch() recover from an error?

Yes. Returning a normal value or fulfilled Promise from catch() recovers the chain. Throwing an error or returning a rejected Promise keeps the chain rejected.

Q8. Is catch() equivalent to then(null, errorHandler)?

Yes. catch(errorHandler) is equivalent to then(undefined, errorHandler).

Q9. What happens if a rejection handler returns a value?

The Promise returned by that handler fulfills with the returned value, allowing subsequent fulfillment handlers to execute.

Q10. Can finally() be used for loading indicator cleanup?

Yes. It is useful for hiding loading indicators or performing cleanup after either success or failure.

Q11. What is error propagation in Promise chaining?

It is the process by which a rejection moves through subsequent Promise handlers until a rejection handler handles it or the rejection remains unhandled.

Q12. Does a catch() handler always make the chain fulfilled?

No. It fulfills the resulting Promise only if it completes normally or returns a fulfilled value. If it throws or returns a rejected Promise, the resulting Promise remains rejected.

14. Lesson Summary

  • .then() handles Promise fulfillment and can optionally handle rejection.
  • .catch() handles Promise rejection.
  • .finally() executes cleanup logic after settlement.
  • All three methods return new Promises.
  • Errors thrown inside handlers cause rejection.
  • Rejections propagate through the chain until handled.
  • Returning a value from catch can recover the chain.
  • Throwing inside catch creates a new rejection.
  • A normally completed finally callback preserves the original outcome.
  • A throwing or rejected finally callback overrides the original outcome.
  • Fetch requires checking response.ok for HTTP errors.
Placement preparation focus: Master Promise chaining, error propagation, error recovery, the difference between catch and finally, and output-based questions involving multiple handlers. These concepts are essential before learning async/await.
