Chapter 10: Asynchronous JavaScript, Promises and Event Loop

Lesson 6: Async, Await and Asynchronous Error Handling

Write readable asynchronous JavaScript using async functions and await, handle rejected Promises with try...catch, and apply asynchronous programming to practical frontend tasks.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand async functions and their return values.
  • Use the await keyword with Promises.
  • Convert Promise chains into async/await code.
  • Handle asynchronous errors using try...catch.
  • Use finally for cleanup in asynchronous functions.
  • Understand sequential and concurrent asynchronous execution.
  • Use async/await with the Fetch API.
  • Identify common async/await mistakes in coding interviews.

2. What Is async/await?

Async/await is JavaScript syntax built on Promises. It allows asynchronous code to be written in a style that resembles sequential programming.

It consists of two main keywords:

  • async: declares an asynchronous function.
  • await: waits for a Promise's outcome before continuing the async function.

Example: Basic async function

async function greet() {
    return "Hello JavaScript";
}

greet().then(message => {
    console.log(message);
});

Expected output:

Hello JavaScript

An async function always returns a Promise. Returning an ordinary value causes the returned Promise to fulfill with that value.

Important: Even when an async function returns a normal string, number or object, its caller receives a Promise.

3. Understanding async Functions

3.1 async function returning a value

async function getNumber() {
    return 100;
}

getNumber().then(value => {
    console.log(value);
});
100

3.2 async function returning a Promise

async function getData() {
    return Promise.resolve("Data received");
}

getData().then(result => {
    console.log(result);
});
Data received

The async function's returned Promise adopts the state of the Promise returned by the function.

3.3 async function throwing an error

async function getUser() {
    throw new Error("User not found");
}

getUser().catch(error => {
    console.log(error.message);
});
User not found

An error thrown inside an async function causes the Promise returned by that function to reject.

4. Understanding the await Keyword

The await keyword is used inside an async function to wait for a Promise to settle. If the Promise fulfills, await evaluates to its fulfillment value. If it rejects, await throws the rejection reason into the async function.

Syntax

async function functionName() {
    const result = await somePromise;

    // Continue after the Promise settles
}

4.1 Using await with Promise.resolve()

async function displayMessage() {
    const message = await Promise.resolve("Welcome");

    console.log(message);
}

displayMessage();
Welcome

4.2 Using await with a timer-based Promise

function delay(milliseconds) {
    return new Promise(resolve => {
        setTimeout(resolve, milliseconds);
    });
}

async function runTask() {
    console.log("Task started");

    await delay(1000);

    console.log("Task completed");
}

runTask();

Expected output:

Task started
Task completed
The second message appears after approximately one second or later.

The async function pauses at await. After the Promise settles, its continuation is scheduled to resume.

Important distinction: Await does not block the entire JavaScript thread. Other JavaScript tasks can run while the async function is suspended.

5. Promise Chaining vs async/await

The same asynchronous operation can be written using either Promise chaining or async/await.

Promise chaining approach

function getUser() {
    return Promise.resolve({
        id: 101,
        name: "Amit"
    });
}

function getOrders(userId) {
    return Promise.resolve([
        "Order 1",
        "Order 2"
    ]);
}

getUser()
    .then(user => {
        console.log(user.name);
        return getOrders(user.id);
    })
    .then(orders => {
        console.log(orders);
    });

Equivalent async/await approach

function getUser() {
    return Promise.resolve({
        id: 101,
        name: "Amit"
    });
}

function getOrders(userId) {
    return Promise.resolve([
        "Order 1",
        "Order 2"
    ]);
}

async function displayUserOrders() {
    const user = await getUser();

    console.log(user.name);

    const orders = await getOrders(user.id);

    console.log(orders);
}

displayUserOrders();

Expected output for both approaches:

Amit
["Order 1", "Order 2"]
Promise chaining async/await
Uses .then() handlers. Uses async and await.
Operations are connected through returned Promises. Operations can be written in a sequential style.
Errors can be handled using .catch(). Errors can be handled using try...catch.
Useful for direct Promise composition. Often easier to read for multi-step asynchronous logic.

6. Sequential Execution with await

When one asynchronous operation depends on the result of another, use await sequentially.

Example: Fetching user and then user details

function getUser() {
    return new Promise(resolve => {
        setTimeout(() => {
            console.log("User fetched");

            resolve({
                id: 101,
                name: "Amit"
            });
        }, 1000);
    });
}

function getUserDetails(userId) {
    return new Promise(resolve => {
        setTimeout(() => {
            console.log("User details fetched");

            resolve({
                userId: userId,
                city: "Delhi"
            });
        }, 1000);
    });
}

async function displayUser() {
    const user = await getUser();

    const details = await getUserDetails(user.id);

    console.log(user.name);
    console.log(details.city);
}

displayUser();

Expected output:

User fetched
User details fetched
Amit
Delhi
The two operations execute sequentially, taking approximately two seconds or longer in total.

The second operation needs the user ID returned by the first operation. Therefore, sequential execution is appropriate.

7. Concurrent Execution with Promise.all()

If multiple asynchronous operations are independent, they can be started together rather than waiting for each one sequentially.

Sequential approach

async function loadData() {
    const users = await getUsers();
    const products = await getProducts();

    console.log(users);
    console.log(products);
}

Here, the second operation starts only after the first one fulfills.

Concurrent approach

async function loadData() {
    const [users, products] = await Promise.all([
        getUsers(),
        getProducts()
    ]);

    console.log(users);
    console.log(products);
}

Both operations are started before awaiting their combined result. Promise.all() fulfills when all supplied Promises fulfill, and rejects if any input rejects.

Use sequential await when operations depend on one another. Use Promise.all() when independent operations can run concurrently.

8. Error Handling with try...catch

The try...catch statement handles errors that occur while executing code inside the try block. It is especially useful with await because a rejected Promise awaited inside the try block throws into the surrounding catch block.

Syntax

async function functionName() {
    try {
        const result = await somePromise;

        // Process successful result
    } catch (error) {
        // Handle error
    }
}

8.1 Handling a rejected Promise

function getData() {
    return Promise.reject(new Error("Unable to fetch data"));
}

async function displayData() {
    try {
        const result = await getData();

        console.log(result);
    } catch (error) {
        console.log("Error:", error.message);
    }
}

displayData();
Error: Unable to fetch data

8.2 Handling errors thrown inside an async function

async function calculate() {
    try {
        throw new Error("Invalid calculation");
    } catch (error) {
        console.log(error.message);
    }
}

calculate();
Invalid calculation

8.3 Using try...catch...finally

async function loadUser() {
    try {
        console.log("Loading user");

        const user = await Promise.resolve({
            name: "Amit"
        });

        console.log("User:", user.name);
    } catch (error) {
        console.log("Error:", error.message);
    } finally {
        console.log("Loading process finished");
    }
}

loadUser();
Loading user
User: Amit
Loading process finished

The finally block runs after the try or catch block completes, making it suitable for cleanup operations.

9. Important Error-Handling Scenarios

9.1 Await inside try...catch

async function fetchData() {
    try {
        const result = await Promise.reject(
            new Error("Request failed")
        );

        console.log(result);
    } catch (error) {
        console.log("Caught:", error.message);
    }
}

fetchData();
Caught: Request failed

9.2 Returning a rejected Promise without awaiting it

async function fetchData() {
    try {
        return Promise.reject(
            new Error("Request failed")
        );
    } catch (error) {
        console.log("Caught:", error.message);
    }
}

fetchData().catch(error => {
    console.log("Outer catch:", error.message);
});
Outer catch: Request failed

The rejected Promise is returned from the async function without being awaited inside the try block. Therefore, the local catch does not catch its rejection.

Correction: If the local catch should handle the rejection, use return await inside the try block. 
async function fetchData() {
    try {
        return await Promise.reject(
            new Error("Request failed")
        );
    } catch (error) {
        console.log("Caught:", error.message);
    }
}

fetchData();
Caught: Request failed

9.3 Errors outside the async function

async function getData() {
    throw new Error("Data error");
}

getData().catch(error => {
    console.log(error.message);
});
Data error

Errors thrown by an async function reject its returned Promise. The caller must handle that rejection.

10. Practical Example: Fetch API with async/await

The Fetch API is commonly used in frontend development to communicate with backend services. 

async function getUser() {
    try {
        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users/1"
        );

        if (!response.ok) {
            throw new Error(
                "HTTP error: " + response.status
            );
        }

        const user = await response.json();

        console.log("Name:", user.name);
        console.log("Email:", user.email);

    } catch (error) {
        console.log("Request failed:", error.message);
    }
}

getUser();

Expected output when the request succeeds:

Name: Leanne Graham
Email: Sincere@april.biz

Actual output depends on the server response and network availability. If the network request fails or the HTTP response has an unsuccessful status, the catch block handles the resulting error.

Important frontend concept: Fetch normally fulfills when it receives an HTTP response, even for statuses such as 404 or 500. Always check response.ok when HTTP errors should be treated as failures.

11. Practical Example: Login Form Logic

This example simulates an asynchronous login operation and demonstrates success and error handling. 

function authenticate(username, password) {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            if (
                username === "admin" &&
                password === "1234"
            ) {
                resolve({
                    username: username,
                    message: "Login successful"
                });
            } else {
                reject(new Error("Invalid credentials"));
            }
        }, 1000);
    });
}

async function loginUser(username, password) {
    try {
        console.log("Authenticating...");

        const result = await authenticate(
            username,
            password
        );

        console.log(result.message);
        console.log("Welcome:", result.username);

    } catch (error) {
        console.log("Login failed:", error.message);
    } finally {
        console.log("Authentication process completed");
    }
}

loginUser("admin", "1234");

Expected output for the supplied credentials:

Authenticating...
Login successful
Welcome: admin
Authentication process completed

With incorrect credentials, the output becomes:

Authenticating...
Login failed: Invalid credentials
Authentication process completed
This is a frontend learning simulation, not secure authentication. Real applications must authenticate users on the backend and must not hardcode passwords in client code.

12. Common async/await Mistakes

Mistake 1: Forgetting await

async function getUser() {
    return Promise.resolve("Amit");
}

async function displayUser() {
    const user = getUser();

    console.log(user);
}

displayUser();

Problem: The variable contains a Promise, not the resolved string.

Correction:

async function displayUser() {
    const user = await getUser();

    console.log(user);
}

Mistake 2: Using await outside an async function

const result = await Promise.resolve(10);

Problem: This is invalid in a traditional script context. Top-level await is supported in JavaScript modules, but not in ordinary classic scripts.

Mistake 3: Forgetting to handle a rejected async function

async function getData() {
    throw new Error("Failed");
}

getData();

Problem: The returned Promise rejects, but the caller does not handle the rejection.

Correction:

getData().catch(error => {
    console.log(error.message);
});

Mistake 4: Using sequential await for independent operations

async function loadPage() {
    const users = await getUsers();
    const products = await getProducts();
    const orders = await getOrders();

    console.log(users, products, orders);
}

Problem: Each operation waits for the previous operation even though they may be independent.

Improved approach:

async function loadPage() {
    const [users, products, orders] = await Promise.all([
        getUsers(),
        getProducts(),
        getOrders()
    ]);

    console.log(users, products, orders);
}

Mistake 5: Assuming await blocks all JavaScript execution

Await suspends only the current async function's continuation. It does not freeze the browser or block unrelated JavaScript tasks.

13. Placement Interview Questions and Answers

Q1. What is an async function?

An async function is a function declared with the async keyword. It always returns a Promise.

Q2. What happens when an async function returns a normal value?

Its returned Promise fulfills with that value.

Q3. What happens when an async function throws an error?

The Promise returned by that function rejects with the thrown error.

Q4. What does await do?

It waits for a Promise's outcome and evaluates to its fulfillment value. If the Promise rejects, await throws the rejection reason.

Q5. Does await block the JavaScript thread?

No. It suspends the current async function's continuation, allowing other JavaScript work to proceed.

Q6. Can await be used outside an async function?

Yes, in supported JavaScript module contexts using top-level await. In a traditional classic script, await must be inside an async function.

Q7. How do you handle errors in async/await?

Use try...catch around awaited operations or attach .catch() to the Promise returned by the async function.

Q8. What is the purpose of finally in async/await?

It executes cleanup logic after the try or catch block, regardless of success or failure.

Q9. What is the difference between sequential and concurrent execution?

Sequential execution waits for one operation before starting the next. Concurrent execution starts independent operations without waiting for each one individually, often using Promise.all().

Q10. Does async/await replace Promises?

No. Async/await is syntax built on Promises. It makes Promise-based code easier to read and write.

Q11. What happens if you forget await?

The variable may contain a Promise instead of its resolved value. Operations that require the actual result may then behave incorrectly.

Q12. Why is Promise.all() useful with async/await?

It allows independent asynchronous operations to be started concurrently and waits for all of them to fulfill. It rejects when one of the supplied Promises rejects.

Q13. Does try...catch catch an un-awaited rejected Promise?

No. A rejection from a Promise that is not awaited inside the try block is not caught by that local catch. The Promise must be awaited there or handled separately.

Q14. What is return await used for?

It waits for the returned Promise inside the current function. This can be useful when a local try...catch must handle that Promise's rejection before the function returns.
