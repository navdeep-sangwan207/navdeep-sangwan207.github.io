Lesson 2: setTimeout(), setInterval() and Clear Methods

Learn how JavaScript schedules delayed and repeated operations using timers. Understand timer identifiers, cancellation, execution order, and practical timer-based application features.

1. Learning Objectives

  • Understand the purpose of JavaScript timer functions.
  • Use setTimeout() to schedule a callback once.
  • Use setInterval() to schedule repeated callbacks.
  • Cancel scheduled timers using clearTimeout() and clearInterval().
  • Understand timer identifiers and callback arguments.
  • Predict timer execution order in JavaScript programs.
  • Understand timer delays and their limitations.
  • Implement practical features such as countdowns and digital clocks.

2. JavaScript Timer Functions

JavaScript provides timer functions that allow code to execute after a specified delay or repeatedly at a specified interval. These functions are commonly used for notifications, countdowns, animations, polling, and other time-based features.

In browsers, these timer functions are provided by the Web API environment. They are not part of the core ECMAScript language specification.

Four Important Timer Methods

Method Purpose
setTimeout() Schedules a callback to run once after a delay.
setInterval() Schedules a callback to run repeatedly at an interval.
clearTimeout() Cancels a timeout that has not yet executed.
clearInterval() Cancels a repeating interval.

3. setTimeout() Method

The setTimeout() method schedules a function to execute once after a specified delay.

Syntax

setTimeout(callback, delay);

Parameters:

  • callback: The function to execute after the delay.
  • delay: The minimum delay in milliseconds before the callback becomes eligible to execute.

One second is equal to 1000 milliseconds.

Example 1: Basic setTimeout()

console.log("Start");

setTimeout(function () {
    console.log("Executed after 2 seconds");
}, 2000);

console.log("End");
Expected Output Order: 
Start
End
(After approximately 2 seconds)
Executed after 2 seconds

The timer schedules the callback. JavaScript does not wait for the timer before executing the next synchronous statement.

Example 2: Using an Arrow Function

setTimeout(() => {
    console.log("Welcome to JavaScript");
}, 1000);
Expected Output: 
(After approximately 1 second)
Welcome to JavaScript

Example 3: Passing Arguments to the Callback

Additional arguments supplied after the delay are passed to the callback when it executes. 

function greet(name, course) {
    console.log("Hello " + name);
    console.log("Course: " + course);
}

setTimeout(greet, 1000, "Student", "JavaScript");
Expected Output: 
(After approximately 1 second)
Hello Student
Course: JavaScript

Example 4: Storing the Timer Identifier

const timerId = setTimeout(function () {
    console.log("This message is scheduled");
}, 3000);

console.log("Timer ID:", timerId);

The return value of setTimeout() is a timer identifier. It can be passed to clearTimeout() to cancel the scheduled callback.

The exact representation of a timer identifier depends on the JavaScript environment.

4. clearTimeout() Method

The clearTimeout() method cancels a timeout scheduled using setTimeout(), provided the callback has not already started executing.

Syntax

clearTimeout(timerId);

Example 1: Cancel a Scheduled Timeout

const timerId = setTimeout(function () {
    console.log("This message will not appear");
}, 3000);

clearTimeout(timerId);

console.log("Timeout cancelled");
Expected Output: 
Timeout cancelled

The timeout is cancelled before its callback executes.

Example 2: Cancel a Timeout After One Second

const timerId = setTimeout(function () {
    console.log("Timeout callback executed");
}, 3000);

setTimeout(function () {
    clearTimeout(timerId);
    console.log("Original timeout cancelled");
}, 1000);
Expected Output Order: 
(After approximately 1 second)
Original timeout cancelled

The second timer cancels the first timer before its three-second delay expires.

Important: clearTimeout() cannot undo a callback that has already started executing.

5. setInterval() Method

The setInterval() method schedules a callback to execute repeatedly, using a specified interval.

Syntax

setInterval(callback, interval);

Parameters:

  • callback: The function to execute repeatedly.
  • interval: The minimum interval in milliseconds between scheduled executions.

Example 1: Basic setInterval()

let count = 1;

const intervalId = setInterval(function () {
    console.log("Count:", count);
    count++;
}, 1000);
Expected Output: 
(Approximately every second)
Count: 1
Count: 2
Count: 3
Count: 4
...

The callback continues to execute repeatedly until the interval is cancelled or the execution environment stops it.

Example 2: Passing Arguments to setInterval()

function displayMessage(message) {
    console.log(message);
}

const intervalId = setInterval(
    displayMessage,
    2000,
    "JavaScript is running"
);
Expected Output: 
(Approximately every 2 seconds)
JavaScript is running
JavaScript is running
JavaScript is running
...

The additional argument is passed to the callback each time it executes.

6. clearInterval() Method

The clearInterval() method stops a repeating interval created using setInterval().

Syntax

clearInterval(intervalId);

Example 1: Stop an Interval

let count = 1;

const intervalId = setInterval(function () {
    console.log("Count:", count);

    count++;

    if (count > 5) {
        clearInterval(intervalId);
        console.log("Interval stopped");
    }
}, 1000);
Expected Output Order: 
(Approximately every second)
Count: 1
Count: 2
Count: 3
Count: 4
Count: 5
Interval stopped

When the count becomes greater than five, the interval is cancelled. No further interval callbacks are scheduled.

Example 2: Stop an Interval Using a Separate Timeout

const intervalId = setInterval(function () {
    console.log("Repeated message");
}, 1000);

setTimeout(function () {
    clearInterval(intervalId);
    console.log("Interval cancelled");
}, 5000);

Expected Output Order:

Repeated message
Repeated message
Repeated message
Repeated message
Interval cancelled

The exact number of repeated messages can depend on timer scheduling. The interval is cancelled when the timeout callback executes.

7. setTimeout() vs setInterval()

Feature setTimeout() setInterval()
Execution Schedules one callback. Schedules repeated callbacks.
Parameters Callback and delay. Callback and interval.
Cancellation clearTimeout() clearInterval()
Common use Delayed notifications and one-time actions. Clocks, periodic updates, and polling.
Return value Timer identifier. Interval identifier.

8. Understanding Timer Delays

Timer delays do not guarantee exact execution times. A callback becomes eligible to execute after its delay, but it must wait until JavaScript can process it.

Example: A Busy Main Thread Delays a Timer

console.log("Start");

setTimeout(function () {
    console.log("Timer callback");
}, 0);

const start = Date.now();

while (Date.now() - start < 2000) {
    // Block the main thread temporarily
}

console.log("Synchronous work completed");
Expected Output Order: 
Start
(Approximately 2 seconds of blocking work)
Synchronous work completed
Timer callback

Although the timer delay is zero, its callback cannot execute while the main thread is busy running the synchronous loop.

Interview Point: A zero-millisecond timeout does not mean immediate execution. It schedules a callback for a later opportunity to run.

9. Recursive setTimeout() vs setInterval()

Repeated operations can be implemented using either setInterval() or recursive setTimeout(). They do not have identical scheduling behavior.

Using setInterval()

let count = 0;

const intervalId = setInterval(function () {
    count++;
    console.log("Execution:", count);

    if (count === 3) {
        clearInterval(intervalId);
    }
}, 1000);

Using Recursive setTimeout()

let count = 0;

function repeatTask() {
    count++;
    console.log("Execution:", count);

    if (count < 3) {
        setTimeout(repeatTask, 1000);
    }
}

setTimeout(repeatTask, 1000);

In the recursive version, the next timeout is scheduled only after the current callback finishes. This is useful when repeated work should not be scheduled until the previous execution has completed.

Comparison

setInterval() Recursive setTimeout()
Schedules repeated callbacks at a configured interval. Schedules the next callback after the current callback completes.
Can be unsuitable for work whose duration varies significantly. Provides more control over when the next execution is scheduled.
Useful for simple periodic tasks. Useful for controlled retries and repeated asynchronous work.
Important: setInterval() does not wait for an asynchronous operation started inside its callback to finish. If that operation takes longer than the interval, multiple operations may be in progress at the same time.

10. Practical Application: Countdown Timer

A countdown timer is a common example of combining setInterval() and clearInterval().

Complete HTML and JavaScript Example

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Countdown Timer</title>
</head>
<body>

    <h2 id="countdown">10</h2>

    <script>
        let remainingTime = 10;

        const display = document.getElementById("countdown");

        const timerId = setInterval(function () {
            remainingTime--;

            display.textContent = remainingTime;

            if (remainingTime <= 0) {
                clearInterval(timerId);
                display.textContent = "Time's up!";
            }
        }, 1000);
    </script>

</body>
</html>

Expected Behavior:

10
9
8
7
...
1
Time's up!

The displayed value decreases approximately once per second. When the countdown reaches zero, the interval is cancelled.

11. Practical Application: Digital Clock

The following example displays the current time and updates the display periodically. 

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Digital Clock</title>
</head>
<body>

    <h1 id="clock"></h1>

    <script>
        const clock = document.getElementById("clock");

        function updateClock() {
            const now = new Date();

            const hours = String(now.getHours()).padStart(2, "0");
            const minutes = String(now.getMinutes()).padStart(2, "0");
            const seconds = String(now.getSeconds()).padStart(2, "0");

            clock.textContent = hours + ":" + minutes + ":" + seconds;
        }

        updateClock();

        const clockId = setInterval(updateClock, 1000);
    </script>

</body>
</html>

Expected Behavior:

20:04:10
20:04:11
20:04:12
...

The displayed time depends on the computer's current local time.

Calling updateClock() before starting the interval ensures the clock displays immediately instead of waiting for the first interval callback.

12. Practical Application: Start and Stop Timer

This example demonstrates how a user can start and stop a repeating timer using buttons. 

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Start and Stop Timer</title>
</head>
<body>

    <h2 id="count">0</h2>

    <button id="startBtn">Start</button>
    <button id="stopBtn">Stop</button>

    <script>
        let count = 0;
        let intervalId = null;

        const display = document.getElementById("count");
        const startBtn = document.getElementById("startBtn");
        const stopBtn = document.getElementById("stopBtn");

        startBtn.addEventListener("click", function () {
            if (intervalId !== null) {
                return;
            }

            intervalId = setInterval(function () {
                count++;
                display.textContent = count;
            }, 1000);
        });

        stopBtn.addEventListener("click", function () {
            clearInterval(intervalId);
            intervalId = null;
        });
    </script>

</body>
</html>

Expected Behavior:

  • Click Start to begin counting.
  • The counter increases approximately once per second.
  • Click Stop to pause the counter.
  • Click Start again to continue from the current count.

Checking whether intervalId is already active prevents multiple intervals from being created by repeated clicks on the Start button.

13. Common Mistakes and Debugging

  1. Forgetting to store the timer identifier: Store the return value when you need to cancel a timer later.
  2. Using clearInterval() for a timeout: Use clearTimeout() for setTimeout() and clearInterval() for setInterval(). Browsers may accept either cancellation function for either timer type, but matching them improves code clarity.
  3. Creating multiple intervals accidentally: Check whether an interval is already running before starting another one.
  4. Expecting exact timer execution: Timer delays are minimum scheduling thresholds, not exact execution guarantees.
  5. Forgetting to stop an interval: A repeating interval continues until cancelled or the environment stops it.
  6. Using setInterval() for long-running asynchronous work: The next callback may start while work initiated by an earlier callback is still pending.
  7. Assuming clearTimeout() can cancel an executing callback: It only cancels a callback that has not already begun.

14. Placement Interview Questions

Q1. What is setTimeout() in JavaScript?

Answer: setTimeout() schedules a callback function to execute once after a specified minimum delay.

Q2. What is setInterval()?

Answer: setInterval() schedules a callback function to execute repeatedly at a specified interval.

Q3. What is the difference between setTimeout() and setInterval()?

Answer: setTimeout() schedules one execution, whereas setInterval() schedules repeated executions.

Q4. What is the purpose of clearTimeout()?

Answer: clearTimeout() cancels a timeout scheduled using setTimeout(), provided its callback has not started executing.

Q5. What is the purpose of clearInterval()?

Answer: clearInterval() stops a repeating timer created using setInterval().

Q6. What does setTimeout(callback, 0) mean?

Answer: It schedules the callback for a later execution opportunity. It does not execute the callback immediately or interrupt the current synchronous code.

Q7. Are timer delays exact?

Answer: No. The specified delay is a minimum threshold. The callback may execute later because of main-thread activity and browser scheduling.

Q8. Can setInterval() cause overlapping asynchronous operations?

Answer: Yes. If an interval callback starts an asynchronous operation that takes longer than the interval, another callback can start before the previous operation finishes.

Q9. How can repeated timer execution be stopped?

Answer: Store the identifier returned by setInterval() and pass it to clearInterval().

Q10. What is the difference between recursive setTimeout() and setInterval()?

Answer: setInterval() schedules repeated callbacks at a configured interval. Recursive setTimeout() schedules the next execution after the current callback completes, giving more control over scheduling.

17. Lesson Summary
