2. What Are Microtasks and Macrotasks?

JavaScript uses different scheduling mechanisms to process asynchronous work. Two important categories in the browser event-loop model are:

  • Microtasks: Higher-priority queued work processed at microtask checkpoints.
  • Tasks (often informally called macrotasks): Work scheduled by the host environment, such as timer callbacks and user interaction events.

Microtask examples

  • Promise .then() handlers.
  • Promise .catch() handlers.
  • Promise .finally() handlers.
  • queueMicrotask() callbacks.
  • MutationObserver callbacks in browsers.

Task examples

  • setTimeout() callbacks.
  • setInterval() callbacks.
  • Many DOM event callbacks, such as click handlers.
  • Other host-scheduled browser tasks.
Feature Microtasks Tasks / Macrotasks
Examples Promise handlers, queueMicrotask() Timers, many DOM events
Processing At microtask checkpoints Selected by the event loop
Typical order Drained before the next task Processed after the current task and its microtasks
Common use Promise continuation and deferred cleanup Timers and event-driven work
The term "macrotask" is commonly used in tutorials and interviews. Browser specifications generally refer to tasks and task queues. The browser can have multiple task sources with their own scheduling rules.

3. Understanding the Microtask Queue

When a Promise is fulfilled or rejected, its registered reaction handlers are scheduled as microtasks.

After the current JavaScript task completes, the browser performs a microtask checkpoint. Microtasks are processed until the queue is empty, including additional microtasks added while the queue is being processed.

Example: Promise microtask

console.log("Start");

Promise.resolve().then(() => {
    console.log("Promise callback");
});

console.log("End");

Expected output:

Start
End
Promise callback

The Promise callback does not interrupt synchronous execution. It runs after the current JavaScript task reaches the microtask checkpoint.

4. Understanding queueMicrotask()

The queueMicrotask() method schedules a callback to run as a microtask.

Syntax

queueMicrotask(callback);

Example

console.log("Start");

queueMicrotask(() => {
    console.log("Microtask executed");
});

console.log("End");

Expected output:

Start
End
Microtask executed

Promise.then() versus queueMicrotask()

console.log("Start");

Promise.resolve().then(() => {
    console.log("Promise microtask");
});

queueMicrotask(() => {
    console.log("queueMicrotask callback");
});

console.log("End");

Expected output:

Start
End
Promise microtask
queueMicrotask callback

Both callbacks are microtasks. In this example, they are enqueued in the order in which their scheduling operations occur, so they execute in that order.

Use queueMicrotask() when you need to schedule a microtask without creating a Promise solely for scheduling.

5. Microtasks Execute Before the Next Task

A key event-loop rule for browser interview questions is that the microtask queue is drained at the microtask checkpoint before the event loop proceeds to another task.

Example: Promise versus setTimeout()

console.log("A");

setTimeout(() => {
    console.log("B");
}, 0);

Promise.resolve().then(() => {
    console.log("C");
});

console.log("D");

Expected output:

A
D
C
B

Execution order:

  1. A executes synchronously.
  2. The timer callback is scheduled as a task.
  3. The Promise handler is scheduled as a microtask.
  4. D executes synchronously.
  5. The microtask runs.
  6. The timer task runs when eligible.

6. Nested Microtasks

A microtask can schedule another microtask. The newly scheduled microtask is processed during the same microtask checkpoint before the next task is selected.

Example

console.log("Start");

Promise.resolve().then(() => {
    console.log("Microtask 1");

    Promise.resolve().then(() => {
        console.log("Microtask 2");
    });
});

setTimeout(() => {
    console.log("Timer");
}, 0);

console.log("End");

Expected output:

Start
End
Microtask 1
Microtask 2
Timer

When Microtask 1 executes, it schedules Microtask 2. The microtask queue is drained before the timer task is processed.

7. Microtask Queue Starvation

Because microtasks are processed until the queue is empty, continuously scheduling new microtasks can delay other tasks and browser rendering opportunities.

Example: Repeated microtask scheduling

function repeatMicrotask() {
    queueMicrotask(() => {
        console.log("Microtask running");
        repeatMicrotask();
    });
}

setTimeout(() => {
    console.log("Timer callback");
}, 0);

repeatMicrotask();
Important: This example continuously adds microtasks and may prevent the browser from reaching the timer task or rendering opportunities. It is intentionally problematic; do not run it as a normal application example.

How to avoid this problem

  • Avoid endlessly scheduling microtasks.
  • Break large operations into manageable chunks.
  • Use task scheduling when work should yield to other tasks.
  • Use Web Workers for suitable CPU-intensive operations.

8. What Are Promise Combinators?

Promise combinators are static methods of the Promise constructor. They allow multiple Promises or values to be handled together.

The four important Promise combinators are:

Method Behavior Typical use
Promise.all() Fulfills when all inputs fulfill; rejects when an input rejects. All required requests must succeed.
Promise.allSettled() Fulfills after every input settles. Collect every operation's outcome.
Promise.race() Settles according to the first input to settle. First completion or timeout patterns.
Promise.any() Fulfills with the first fulfilled input; rejects if all reject. Try multiple alternatives.

These methods accept an iterable, commonly an array, of Promises or other values. Non-Promise values are treated as already fulfilled inputs.

9. Promise.all()

Promise.all() takes an iterable of inputs and returns a Promise that fulfills when all inputs fulfill. Its result is an array of fulfillment values in the original input order.

If any input rejects, the returned Promise rejects with that rejection reason. Other operations are not automatically cancelled.

Syntax

Promise.all([
    promise1,
    promise2,
    promise3
])
.then(results => {
    // All inputs fulfilled
})
.catch(error => {
    // At least one input rejected
});

Example: Multiple successful Promises

const promise1 = Promise.resolve("User Data");
const promise2 = Promise.resolve("Product Data");
const promise3 = Promise.resolve("Order Data");

Promise.all([
    promise1,
    promise2,
    promise3
])
.then(results => {
    console.log(results);
})
.catch(error => {
    console.log(error);
});

Expected output:

["User Data", "Product Data", "Order Data"]

Important: Result order

const first = new Promise(resolve => {
    setTimeout(() => resolve("First"), 300);
});

const second = new Promise(resolve => {
    setTimeout(() => resolve("Second"), 100);
});

const third = new Promise(resolve => {
    setTimeout(() => resolve("Third"), 200);
});

Promise.all([first, second, third])
.then(results => {
    console.log(results);
});

Expected output:

["First", "Second", "Third"]

The second Promise completes first, but Promise.all() preserves the original input order in its result array.

Example: Promise.all() rejection

const p1 = Promise.resolve("Success 1");

const p2 = Promise.reject("Request failed");

const p3 = Promise.resolve("Success 3");

Promise.all([p1, p2, p3])
.then(results => {
    console.log(results);
})
.catch(error => {
    console.log("Error:", error);
});

Expected output:

Error: Request failed
Placement point: Promise.all() is useful when several independent operations must all succeed before the application can continue.

10. Promise.allSettled()

Promise.allSettled() waits for every input Promise to settle, regardless of whether it fulfills or rejects.

It always fulfills with an array containing one outcome object for each input, in the original input order.

Syntax

Promise.allSettled([
    promise1,
    promise2,
    promise3
])
.then(results => {
    // Inspect every result
});

Example

const p1 = Promise.resolve("User loaded");

const p2 = Promise.reject("Payment failed");

const p3 = Promise.resolve("Products loaded");

Promise.allSettled([p1, p2, p3])
.then(results => {
    results.forEach(result => {
        console.log(result);
    });
});

Expected output:

{ status: "fulfilled", value: "User loaded" }
{ status: "rejected", reason: "Payment failed" }
{ status: "fulfilled", value: "Products loaded" }

Understanding the result object

Status Available property Meaning
fulfilled value The fulfilled Promise's result.
rejected reason The rejection reason.

Practical example: Process all outcomes

const requests = [
    Promise.resolve("Profile loaded"),
    Promise.reject("Settings unavailable"),
    Promise.resolve("Notifications loaded")
];

async function loadDashboard() {
    const results = await Promise.allSettled(requests);

    results.forEach((result, index) => {
        if (result.status === "fulfilled") {
            console.log(index, result.value);
        } else {
            console.log(index, result.reason);
        }
    });
}

loadDashboard();

Expected output:

0 Profile loaded
1 Settings unavailable
2 Notifications loaded

11. Promise.race()

Promise.race() returns a Promise that settles with the outcome of the first input Promise to settle.

The first input may fulfill or reject. The result depends on which input settles first, not necessarily which one fulfills first.

Syntax

Promise.race([
    promise1,
    promise2,
    promise3
])
.then(result => {
    // First settlement fulfilled
})
.catch(error => {
    // First settlement rejected
});

Example: First Promise to fulfill

const p1 = new Promise(resolve => {
    setTimeout(() => resolve("First"), 300);
});

const p2 = new Promise(resolve => {
    setTimeout(() => resolve("Second"), 100);
});

const p3 = new Promise(resolve => {
    setTimeout(() => resolve("Third"), 200);
});

Promise.race([p1, p2, p3])
.then(result => {
    console.log(result);
});

Expected output:

Second

Example: First settlement is a rejection

const p1 = new Promise((resolve, reject) => {
    setTimeout(() => reject("First request failed"), 100);
});

const p2 = new Promise(resolve => {
    setTimeout(() => resolve("Second request succeeded"), 200);
});

Promise.race([p1, p2])
.then(result => {
    console.log(result);
})
.catch(error => {
    console.log(error);
});

Expected output:

First request failed

Practical example: Request timeout

function fetchWithTimeout(url, timeout) {
    const request = fetch(url);

    const timer = new Promise((resolve, reject) => {
        setTimeout(() => {
            reject(new Error("Request timed out"));
        }, timeout);
    });

    return Promise.race([request, timer]);
}

fetchWithTimeout("/api/products", 5000)
    .then(response => {
        if (!response.ok) {
            throw new Error("HTTP error: " + response.status);
        }

        return response.json();
    })
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.error(error.message);
    });
Promise.race() does not cancel the losing operation. In the timeout example, the fetch request may continue after the timeout Promise wins. Use AbortController when the underlying fetch operation should actually be cancelled.

12. Promise.any()

Promise.any() fulfills as soon as the first input Promise fulfills.

Rejected inputs are ignored while other inputs remain pending. If every input rejects, Promise.any() rejects with an AggregateError.

Syntax

Promise.any([
    promise1,
    promise2,
    promise3
])
.then(result => {
    // First fulfilled value
})
.catch(error => {
    // All inputs rejected
});

Example: First fulfilled Promise

const p1 = new Promise((resolve, reject) => {
    setTimeout(() => reject("Server 1 failed"), 100);
});

const p2 = new Promise(resolve => {
    setTimeout(() => resolve("Server 2 succeeded"), 200);
});

const p3 = new Promise(resolve => {
    setTimeout(() => resolve("Server 3 succeeded"), 300);
});

Promise.any([p1, p2, p3])
.then(result => {
    console.log(result);
})
.catch(error => {
    console.log(error);
});

Expected output:

Server 2 succeeded

The first Promise rejects, but Promise.any() continues waiting. The second Promise fulfills, so its value is returned.

Example: All Promises reject

const p1 = Promise.reject("Server 1 failed");

const p2 = Promise.reject("Server 2 failed");

const p3 = Promise.reject("Server 3 failed");

Promise.any([p1, p2, p3])
.then(result => {
    console.log(result);
})
.catch(error => {
    console.log(error instanceof AggregateError);
    console.log(error.errors);
});

Expected output:

true
["Server 1 failed", "Server 2 failed", "Server 3 failed"]

An AggregateError groups the rejection reasons when Promise.any() has no fulfilled input.

13. Comparing All Four Promise Combinators

Method When does it settle? What does it return? Rejection behavior
Promise.all() All fulfill, or one rejects. Array of fulfillment values. Rejects when an input rejects.
Promise.allSettled() All inputs settle. Array of outcome objects. Individual rejections become result objects.
Promise.race() First input settles. First settled value or reason. Rejects if the first settlement is a rejection.
Promise.any() First input fulfills, or all reject. First fulfillment value. Rejects with AggregateError if all inputs reject.

Which method should you use?

  • Use Promise.all() when every operation must succeed.
  • Use Promise.allSettled() when every outcome matters.
  • Use Promise.race() when the first settlement determines the result.
  • Use Promise.any() when any successful alternative is sufficient.

14. Practical Frontend Example: Load Dashboard Data

A dashboard may need profile, products and notifications from separate API endpoints. If all three are required before rendering the dashboard, Promise.all() is appropriate. 

async function loadDashboard() {
    try {
        const [profileResponse, productsResponse, notificationsResponse] =
            await Promise.all([
                fetch("/api/profile"),
                fetch("/api/products"),
                fetch("/api/notifications")
            ]);

        const responses = [
            profileResponse,
            productsResponse,
            notificationsResponse
        ];

        for (const response of responses) {
            if (!response.ok) {
                throw new Error(
                    "HTTP error: " + response.status
                );
            }
        }

        const [profile, products, notifications] =
            await Promise.all(
                responses.map(response => response.json())
            );

        console.log("Profile:", profile);
        console.log("Products:", products);
        console.log("Notifications:", notifications);

    } catch (error) {
        console.error("Dashboard loading failed:", error.message);
    }
}

loadDashboard();

The independent network requests are initiated together. The application then processes the responses and their JSON bodies.

Fetch rejects for network-level failures, but HTTP error responses such as 404 and 500 normally fulfill with a Response object. Check response.ok when HTTP success is required.

15. Practical Example: Multiple Backup Servers

Suppose an application can retrieve the same information from several independent servers. It may accept the first successful response rather than waiting for every server. 

const server1 = fetch("/api/server1/data");

const server2 = fetch("/api/server2/data");

const server3 = fetch("/api/server3/data");

Promise.any([server1, server2, server3])
.then(response => {
    if (!response.ok) {
        throw new Error("The selected server returned an HTTP error");
    }

    return response.json();
})
.then(data => {
    console.log("Data received:", data);
})
.catch(error => {
    if (error instanceof AggregateError) {
        console.log("All servers failed");
    } else {
        console.log("Request processing failed:", error.message);
    }
});

Promise.any() selects the first fulfilled Fetch Promise. Note that an HTTP 500 response still fulfills the Fetch Promise; the response.ok check is performed after Promise.any() has selected a response.

If the requirement is to select the first HTTP-successful response, validate response.ok inside each individual request Promise before passing it to Promise.any().

16. Common Mistakes and Debugging

Mistake 1: Assuming timers execute before Promise handlers

In ordinary browser event-loop tracing, Promise microtasks are processed before the next timer task.

Mistake 2: Assuming Promise.all() cancels remaining operations

Promise.all() rejects when an input rejects, but it does not automatically cancel the other operations.

Mistake 3: Assuming Promise.race() returns the first fulfilled Promise

Promise.race() returns the outcome of the first settled Promise. That outcome can be fulfillment or rejection.

Mistake 4: Confusing Promise.any() with Promise.race()

Promise.any() waits for the first fulfillment, whereas Promise.race() responds to the first settlement.

Mistake 5: Assuming Promise.allSettled() rejects when an input rejects

Individual rejected inputs are represented by objects with status: "rejected". The returned Promise fulfills after all inputs settle.

Mistake 6: Ignoring AggregateError

When every input to Promise.any() rejects, the returned rejection reason is an AggregateError. Its errors property contains the individual reasons.

Mistake 7: Creating endless microtasks

Continuously scheduling microtasks can prevent the event loop from moving on to other tasks and rendering opportunities.

Mistake 8: Forgetting Fetch HTTP status handling

Fetch does not automatically reject for HTTP 404 or 500. Check response.ok before processing the response as successful.

17. Placement Interview Questions and Answers

Q1. What is a microtask?

A microtask is a unit of deferred work processed at a microtask checkpoint, such as a Promise reaction handler.

Q2. What is a macrotask?

It is a commonly used informal term for an event-loop task, such as a timer callback or many user interaction callbacks.

Q3. Which runs first: Promise.then() or setTimeout()?

When both are scheduled during the same ordinary task, the Promise handler runs at the microtask checkpoint before the timer task.

Q4. What is queueMicrotask()?

It schedules a callback as a microtask without requiring a Promise solely for scheduling.

Q5. Can a microtask schedule another microtask?

Yes. Newly scheduled microtasks are processed during the same microtask checkpoint before the next task.

Q6. What is Promise.all()?

It fulfills when all inputs fulfill and rejects when an input rejects. Its fulfillment array preserves input order.

Q7. What is Promise.allSettled()?

It fulfills after every input settles and returns an array describing each fulfillment or rejection.

Q8. What is Promise.race()?

It settles according to the first input Promise to settle, whether fulfilled or rejected.

Q9. What is Promise.any()?

It fulfills with the first fulfilled input. If all inputs reject, it rejects with AggregateError.

Q10. What is AggregateError?

It is an error type that groups multiple errors or rejection reasons. Promise.any() uses it when all inputs reject.

Q11. Does Promise.all() preserve input order?

Yes. Its result array follows the original input order, regardless of completion order.

Q12. Does Promise.race() cancel losing Promises?

No. It determines the returned Promise's outcome but does not automatically cancel the other operations.

Q13. When should Promise.allSettled() be preferred?

When an application must inspect the outcome of every independent operation, including failed operations.

Q14. Can microtasks delay browser rendering?

Yes. A long or continuously replenished microtask queue can delay the event loop from reaching rendering opportunities.

Q15. What is the difference between Promise.race() and Promise.any()?

Promise.race() responds to the first settlement. Promise.any() responds to the first fulfillment and ignores rejections until all inputs reject.
