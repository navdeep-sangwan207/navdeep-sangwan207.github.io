Chapter 10: Asynchronous JavaScript, Promises and Event Loop

Lesson 4: Promises, States, Creation and Chaining

Understand JavaScript Promises, create asynchronous operations, handle fulfillment and rejection, and organize asynchronous operations through Promise chaining.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Explain why Promises are used in asynchronous JavaScript.
  • Understand the three Promise states.
  • Create Promises using the Promise constructor.
  • Use resolve() and reject().
  • Understand Promise settlement and resolution.
  • Return values from Promise handlers.
  • Chain multiple asynchronous operations.
  • Predict the output of Promise-based JavaScript programs.

2. What Is a Promise?

A Promise is a JavaScript object that represents the eventual completion or failure of an asynchronous operation. It provides a structured way to handle a result that may become available in the future.

Common operations that use Promises include:

  • Fetching data from a server using fetch().
  • Reading data from APIs.
  • Database operations in supported environments.
  • Loading resources asynchronously.
  • Performing asynchronous application operations.

Example: A Promise representing a future result

const task = new Promise((resolve, reject) => {
    resolve("Task completed successfully");
});

console.log(task);

Possible console output:

Promise {<fulfilled>: "Task completed successfully"}
Exact console formatting depends on the browser's developer tools.

The Promise object represents the result. Its state and value can be observed through Promise handlers such as .then(), which is covered in the next lesson.

3. Why Do We Need Promises?

Callback-based asynchronous programming can become difficult to manage when several operations depend on one another. Deeply nested callbacks can make code harder to read, maintain and debug.

Callback-based approach

function getUser(callback) {
    setTimeout(() => {
        callback({ id: 101, name: "Amit" });
    }, 500);
}

function getOrders(userId, callback) {
    setTimeout(() => {
        callback(["Order 1", "Order 2"]);
    }, 500);
}

getUser(function(user) {
    getOrders(user.id, function(orders) {
        console.log(user.name);
        console.log(orders);
    });
});

Promise-based approach

function getUser() {
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve({ id: 101, name: "Amit" });
        }, 500);
    });
}

function getOrders(userId) {
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve(["Order 1", "Order 2"]);
        }, 500);
    });
}

getUser()
    .then(user => {
        console.log(user.name);
        return getOrders(user.id);
    })
    .then(orders => {
        console.log(orders);
    });
Output after the asynchronous operations:
Amit
["Order 1", "Order 2"]

Promise chaining allows dependent operations to be written in a sequential structure rather than deeply nested callbacks.

4. States of a Promise

A Promise has three possible states:

State Meaning
Pending The asynchronous operation has not settled yet.
Fulfilled The operation completed successfully with a fulfillment value.
Rejected The operation failed with a rejection reason.

A Promise is called settled when it becomes either fulfilled or rejected.

Promise state transition

                 Pending
                /       \
               /         \
          Fulfilled     Rejected
          (Success)     (Failure)
Important: A settled Promise cannot change its state again. Once fulfilled or rejected, it remains settled.

Example: Pending Promise

const pendingPromise = new Promise((resolve, reject) => {
    // Neither resolve nor reject is called.
});

console.log(pendingPromise);

Expected state:

Promise remains pending.
Browser console formatting may vary.

Example: Fulfilled Promise

const fulfilledPromise = new Promise((resolve, reject) => {
    resolve("Payment successful");
});

console.log(fulfilledPromise);

Expected state:

Promise is fulfilled with the value "Payment successful".

Example: Rejected Promise

const rejectedPromise = new Promise((resolve, reject) => {
    reject("Payment failed");
});

console.log(rejectedPromise);

Expected state:

Promise is rejected with the reason "Payment failed".
An unhandled rejection may also produce a browser console warning.

5. Creating a Promise

A Promise can be created using the built-in Promise constructor.

Syntax

const promise = new Promise((resolve, reject) => {
    // Asynchronous or other operation

    if (operationSuccessful) {
        resolve(result);
    } else {
        reject(error);
    }
});

The Promise constructor accepts an executor function with two parameters:

  • resolve: a function used to fulfill or resolve the Promise with a value or another Promise-like object.
  • reject: a function used to reject the Promise with a reason.
Important: The Promise executor function runs immediately and synchronously when the Promise is constructed. Asynchronous work inside the executor, such as a timer, completes later.

Example: Creating a successful Promise

const promise = new Promise((resolve, reject) => {
    console.log("Promise executor started");

    resolve("Data received");
});

console.log("After Promise creation");

Expected output:

Promise executor started
After Promise creation

The executor runs immediately. Calling resolve() settles the Promise, but it does not execute Promise handlers immediately. Promise handlers run asynchronously as microtasks.

6. Understanding resolve() and reject()

6.1 resolve()

The resolve() function is used to resolve a Promise. When given an ordinary value, it fulfills the Promise with that value. 

const promise = new Promise((resolve, reject) => {
    resolve("Operation successful");
});

promise.then(result => {
    console.log(result);
});
Operation successful

6.2 reject()

The reject() function rejects a Promise with a specified reason. 

const promise = new Promise((resolve, reject) => {
    reject("Something went wrong");
});

promise.catch(error => {
    console.log(error);
});
Something went wrong

6.3 A Promise settles only once

Calling resolve() or reject() after a Promise has already settled does not change its outcome. 

const promise = new Promise((resolve, reject) => {
    resolve("First result");
    reject("Second result");
    resolve("Third result");
});

promise.then(result => {
    console.log(result);
});
First result

The first settlement determines the outcome. Later calls to resolve() or reject() are ignored.

6.4 resolve() with another Promise

Resolving a Promise with another Promise does not necessarily fulfill it immediately. The outer Promise adopts the eventual state of the supplied Promise. 

const innerPromise = new Promise(resolve => {
    setTimeout(() => {
        resolve("Inner Promise completed");
    }, 500);
});

const outerPromise = new Promise(resolve => {
    resolve(innerPromise);
});

outerPromise.then(result => {
    console.log(result);
});
Inner Promise completed
Displayed after the inner Promise fulfills.

7. Promise Chaining

Promise chaining means connecting multiple Promise operations using .then(). Each .then() returns a new Promise, allowing another handler to be attached.

Basic syntax

promise
    .then(result => {
        // Process first result
        return nextResult;
    })
    .then(result => {
        // Process the returned result
        return anotherResult;
    })
    .then(result => {
        // Final processing
    });

Example: Chaining values

Promise.resolve(10)
    .then(number => {
        console.log(number);
        return number * 2;
    })
    .then(number => {
        console.log(number);
        return number + 5;
    })
    .then(number => {
        console.log(number);
    });

Expected output:

10
20
25

The first handler receives 10 and returns 20. The next handler receives 20 and returns 25. The final handler receives 25.

Example: Chaining asynchronous operations

function getUser() {
    return new Promise(resolve => {
        setTimeout(() => {
            resolve({ id: 101, name: "Amit" });
        }, 500);
    });
}

function getUserProfile(userId) {
    return new Promise(resolve => {
        setTimeout(() => {
            resolve({
                userId: userId,
                city: "Delhi"
            });
        }, 500);
    });
}

getUser()
    .then(user => {
        console.log("User:", user.name);

        return getUserProfile(user.id);
    })
    .then(profile => {
        console.log("City:", profile.city);
    });

Expected output:

User: Amit
City: Delhi

The second operation starts after the first Promise fulfills and its handler returns the profile Promise.

8. Returning Values and Promises from then()

A key concept in Promise chaining is understanding what a .then() handler returns.

Handler return Effect on the next Promise
Ordinary value The next handler receives that value.
Another Promise The next handler waits for that Promise to settle successfully before receiving its fulfillment value.
No return statement The next handler receives undefined.
Thrown error The next Promise becomes rejected.

Example 1: Returning an ordinary value

Promise.resolve(5)
    .then(value => {
        return value * 3;
    })
    .then(result => {
        console.log(result);
    });
15

Example 2: Not returning a value

Promise.resolve("JavaScript")
    .then(value => {
        console.log(value);
    })
    .then(result => {
        console.log(result);
    });
JavaScript
undefined

The first handler does not return anything explicitly, so its resulting Promise fulfills with undefined.

Example 3: Returning another Promise

Promise.resolve(10)
    .then(value => {
        return new Promise(resolve => {
            setTimeout(() => {
                resolve(value + 20);
            }, 500);
        });
    })
    .then(result => {
        console.log(result);
    });
30
Displayed after the returned Promise fulfills.

9. Promise Chaining with Errors

If a handler in a Promise chain throws an error, the Promise returned by that handler becomes rejected. The rejection propagates through subsequent handlers that do not handle it.

Example: Throwing an error in a chain

Promise.resolve(10)
    .then(value => {
        console.log("First:", value);

        throw new Error("Calculation failed");
    })
    .then(value => {
        console.log("Second:", value);
    })
    .catch(error => {
        console.log("Error:", error.message);
    });

Expected output:

First: 10
Error: Calculation failed

The second .then() has no rejection handler, so it is skipped for this rejected chain. The error reaches .catch().

Lesson boundary: This lesson introduces how errors propagate through a Promise chain. Detailed use of .then(), .catch() and .finally() will be covered in Lesson 5.

10. Practical Example: Simulating a Login Request

The following example simulates a login request using a Promise. It demonstrates how an asynchronous operation can fulfill or reject depending on the supplied credentials. 

function login(username, password) {
    return new Promise((resolve, reject) => {

        setTimeout(() => {

            if (username === "admin" && password === "1234") {
                resolve({
                    status: "success",
                    message: "Login successful",
                    username: username
                });
            } else {
                reject(new Error("Invalid username or password"));
            }

        }, 1000);
    });
}

// Successful login
login("admin", "1234")
    .then(response => {
        console.log(response.message);
        console.log("Welcome:", response.username);
    })
    .catch(error => {
        console.log(error.message);
    });

Expected output for the supplied credentials:

Login successful
Welcome: admin

If incorrect credentials are supplied, the rejection handler displays:

Invalid username or password
This is only a learning simulation. Real authentication must be performed securely on a server. Passwords should not be hardcoded or validated only in frontend JavaScript.

11. Promise.resolve() and Promise.reject()

JavaScript provides static methods for creating already-settled Promises.

Promise.resolve()

Creates a Promise resolved with the supplied value. If the supplied value is a Promise or thenable, its eventual state is adopted. 

const promise = Promise.resolve("Ready");

promise.then(value => {
    console.log(value);
});
Ready

Promise.reject()

Creates a Promise rejected with the supplied reason.

const promise = Promise.reject("Request failed");

promise.catch(error => {
    console.log(error);
});
Request failed

These methods are useful when a function needs to return a Promise even when it already has a value or error.

12. Common Mistakes and Debugging

Mistake 1: Forgetting to return a Promise

function getData() {
    new Promise(resolve => {
        resolve("Data received");
    });
}

getData().then(data => {
    console.log(data);
});

Problem: The function does not return the Promise.

Correction:

function getData() {
    return new Promise(resolve => {
        resolve("Data received");
    });
}

getData().then(data => {
    console.log(data);
});

Mistake 2: Forgetting to return a value in a chain

Promise.resolve(10)
    .then(value => {
        value * 2;
    })
    .then(result => {
        console.log(result);
    });

Problem: The first handler returns undefined.

Correction:

Promise.resolve(10)
    .then(value => {
        return value * 2;
    })
    .then(result => {
        console.log(result);
    });

Mistake 3: Calling resolve() and expecting immediate handler execution

const promise = new Promise(resolve => {
    resolve("Done");
});

promise.then(value => {
    console.log(value);
});

console.log("End");

Correct output:

End
Done

The Promise executor runs synchronously, but the .then() handler runs later as a microtask.

Mistake 4: Assuming resolve() always immediately fulfills with its argument

When resolve() receives another Promise or a thenable, the Promise adopts that object's eventual state. Therefore, resolution and fulfillment are not always the same immediate event.

13. Placement Interview Questions and Answers

Q1. What is a Promise in JavaScript?

A Promise is an object representing the eventual success or failure of an asynchronous operation. It provides a structured mechanism for handling future results.

Q2. What are the three states of a Promise?

Pending, fulfilled and rejected. A Promise is settled when it becomes fulfilled or rejected.

Q3. Can a settled Promise change its state?

No. A Promise can settle only once. Subsequent calls to resolve() or reject() do not change its settled outcome.

Q4. Does the Promise executor run synchronously or asynchronously?

The executor runs synchronously during Promise construction. Asynchronous operations started inside it may complete later.

Q5. What is Promise chaining?

Promise chaining connects multiple Promise operations using .then(). Each handler returns a new Promise, allowing the next operation to depend on its result.

Q6. What happens if a then() handler returns a value?

The Promise returned by .then() fulfills with that value, and the next handler receives it.

Q7. What happens if a then() handler returns another Promise?

The resulting Promise adopts the state of the returned Promise. The next fulfillment handler receives its fulfillment value.

Q8. What happens if a then() handler does not return anything?

Its resulting Promise fulfills with undefined, assuming the handler does not throw an error.

Q9. What is the difference between resolve() and reject()?

resolve() resolves a Promise with a value or Promise-like object. reject() rejects it with a rejection reason.

Q10. What is the difference between resolution and fulfillment?

Resolution means determining or adopting the eventual outcome of a Promise. Fulfillment is the successful settled state. Resolving with another Promise may leave the outer Promise pending until the inner Promise settles.

Q11. Why are Promises better than deeply nested callbacks?

They provide a chainable structure, make dependent asynchronous operations easier to organize and support centralized error propagation through the chain.

Q12. Does creating a Promise automatically make its executor asynchronous?

No. The executor runs synchronously. Only asynchronous work initiated inside it, and Promise reactions, execute later according to their respective scheduling mechanisms.

15. Practical Coding Exercises

  • Create a Promise using the Promise constructor.
  • Fulfill it with the message "Registration successful".

  • Start with the value 10 using Promise.resolve().
  • Add 5 to the value in the first handler.
  • Multiply the result by 2 in the second handler.
  • Subtract 10 in the third handler.
  • Display the final result.

16. Lesson Summary

  • A Promise represents the eventual outcome of an operation.
  • A Promise has pending, fulfilled and rejected states.
  • Fulfilled and rejected Promises are settled.
  • The Promise executor runs synchronously.
  • resolve() and reject() determine the Promise's outcome.
  • A Promise can settle only once.
  • Resolving with another Promise adopts its eventual state.
  • .then() returns a new Promise.
  • Returning a value passes it to the next fulfillment handler.
  • Returning another Promise connects asynchronous operations.
  • Throwing an error causes rejection and allows error propagation.
  • Promise chaining makes asynchronous workflows easier to organize.
Placement preparation focus: Be able to create Promises, identify their states, explain synchronous executor execution, trace Promise chains, predict output and understand how returned values and errors affect subsequent handlers.
