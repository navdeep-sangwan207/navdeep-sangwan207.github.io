2. What Is Pagination?

Pagination is a technique used to divide a large collection of records into smaller groups called pages. Instead of displaying every record at once, an application displays a limited number of records on each page.

For example, suppose an application contains 100 products and displays 10 products per page.

Page Records displayed
Page 1Records 1–10
Page 2Records 11–20
Page 3Records 21–30
......
Page 10Records 91–100

Why Is Pagination Important?

  • Prevents unnecessarily large lists from overwhelming the user.
  • Makes long tables and product listings easier to navigate.
  • Reduces the number of records rendered at one time.
  • Improves usability for dashboards, search results and admin panels.
  • Can reduce data transfer when implemented with server-side pagination.
Pagination improves the amount of data displayed at one time. Client-side pagination does not automatically reduce the amount of data already downloaded into the browser.

3. Client-Side vs Server-Side Pagination

Client-Side Pagination Server-Side Pagination
All required records are loaded into the browser first. The browser requests only a specific portion of records.
JavaScript divides the existing dataset into pages. The backend or API returns records for the requested page.
Suitable for relatively small datasets. Suitable for large datasets.
Page changes can happen without another network request. Page changes usually require an API request.

Example: Client-Side Pagination

const records = [/* all records */];

const pageSize = 5;
const currentPage = 1;

const startIndex = (currentPage - 1) * pageSize;

const pageRecords = records.slice(
    startIndex,
    startIndex + pageSize
);

Example: Server-Side Pagination

const page = 2;
const limit = 10;

fetch(`/api/products?page=${page}&limit=${limit}`)
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.error("Unable to load products:", error);
    });

In a real application, the backend reads the requested page and limit, retrieves the appropriate records from a database and returns the results.

4. Important Pagination Calculations

Assume the following values:

const totalRecords = 50;
const pageSize = 10;
const currentPage = 2;

4.1 Total Number of Pages

Use Math.ceil() to calculate the total number of pages.

const totalPages = Math.ceil(totalRecords / pageSize);

console.log(totalPages); // 5

Math.ceil() rounds a number upward to the next integer. This ensures that a partially filled final page is also counted.

4.2 Start Index

The starting array index for the selected page is:

const startIndex = (currentPage - 1) * pageSize;

console.log(startIndex); // 10

4.3 End Index

The end index is exclusive when using slice().

const endIndex = startIndex + pageSize;

console.log(endIndex); // 20

4.4 Extract Records for the Current Page

const pageRecords = records.slice(startIndex, endIndex);
Expression Result Purpose
Math.ceil(50 / 10) 5 Total pages
(2 - 1) * 10 10 Start index
10 + 10 20 Exclusive end index
slice(10, 20) 10 records Records for page 2
JavaScript array indexes start at zero, but users normally see page numbers starting at one. This is why the calculation uses currentPage - 1.

5. Understanding Array slice()

The slice() method returns a shallow copy of a selected portion of an array. It does not modify the original array. 

const numbers = [10, 20, 30, 40, 50, 60];

console.log(numbers.slice(0, 3));
// [10, 20, 30]

console.log(numbers.slice(3, 6));
// [40, 50, 60]

console.log(numbers);
// Original array remains unchanged.

slice() vs splice()

slice() splice()
Returns a selected portion of an array. Adds, removes or replaces array elements.
Does not modify the original array. Modifies the original array.
Commonly used for pagination. Commonly used for modifying array contents.

9. Understanding the JavaScript Logic

9.1 Application State

let currentPage = 1;
let pageSize = 6;
let filteredProducts = [...products];
  • currentPage stores the currently selected page.
  • pageSize stores the number of records per page.
  • filteredProducts stores the records after searching.

9.2 Calculate the Current Page Records

const startIndex = (currentPage - 1) * pageSize;

const pageProducts = filteredProducts.slice(
    startIndex,
    startIndex + pageSize
);

Only the records belonging to the current page are selected for rendering.

9.3 Render Records Dynamically

pageProducts.forEach(product => {
    const card = document.createElement("div");

    card.textContent = product.name;

    productList.appendChild(card);
});

document.createElement() creates a new DOM element. appendChild() inserts it into the document.

9.4 Navigate Between Pages

function goToPage(page) {
    const totalPages = Math.ceil(
        filteredProducts.length / pageSize
    );

    if (page < 1 || page > totalPages) {
        return;
    }

    currentPage = page;
    render();
}

The function validates the requested page, updates the application state and calls the main rendering function.

9.5 Search and Pagination Together

function filterProducts() {
    const searchTerm = searchInput.value
        .trim()
        .toLowerCase();

    filteredProducts = products.filter(product =>
        product.name.toLowerCase().includes(searchTerm)
    );

    currentPage = 1;
    render();
}
Always reset the current page after filtering or changing the page size. Otherwise, the selected page may no longer exist in the updated result set.

12. Common Mistakes and Debugging

Mistake 1: Incorrect Start Index

// Incorrect
const startIndex = currentPage * pageSize;

// Correct
const startIndex = (currentPage - 1) * pageSize;

The incorrect expression skips the first page and selects records from the wrong position.

Mistake 2: Forgetting That slice() Excludes the End Index

const result = products.slice(0, 5);

This returns five elements, with indexes 0 through 4. The element at index 5 is not included.

Mistake 3: Not Resetting the Current Page

// Recommended when search results change
currentPage = 1;
render();

Mistake 4: Not Handling Empty Results

if (pageProducts.length === 0) {
    productList.textContent = "No records found.";
    return;
}

Mistake 5: Forgetting to Clear Old DOM Elements

productList.innerHTML = "";

// Insert the new page records afterward.

Without clearing the old content, previous records may remain visible when a new page is rendered.

Mistake 6: Using Untrusted HTML in innerHTML

Avoid inserting user-provided or untrusted values directly into HTML strings. Prefer createElement() and textContent for displaying data safely.

13. Placement Interview Questions and Answers

Q1. What is pagination?

Pagination is the process of dividing a large dataset into smaller pages so users can navigate through records in manageable groups.

Q2. Why is pagination used in frontend applications?

It improves usability, limits the number of displayed records and can reduce browser rendering work.

Q3. What is the difference between client-side and server-side pagination?

Client-side pagination divides data already loaded into the browser. Server-side pagination requests only the required subset from the backend.

Q4. How do you calculate the total number of pages?

const totalPages = Math.ceil(totalRecords / pageSize);

Q5. Why is Math.ceil() used instead of Math.floor()?

Because even a partially filled final page must be counted. Math.floor() would discard that partial page.

Q6. How do you calculate the starting index of a page?

const startIndex = (currentPage - 1) * pageSize;

Q7. Why is slice() useful for pagination?

It extracts the required range of array elements without modifying the original array.

Q8. Does slice() modify the original array?

No. It returns a shallow copy of the selected portion.

Q9. What happens if the total number of records is zero?

The total page count becomes zero. The application should display an empty-state message and avoid generating invalid page buttons.

Q10. Why should the current page reset after searching?

Searching can reduce the number of available pages. Resetting to page one prevents the application from displaying an invalid page.

Q11. What is the difference between pageSize and totalPages?

pageSize is the maximum number of records displayed per page. totalPages is the number of pages required to display all matching records.

Q12. What is dynamic data rendering?

Dynamic data rendering means generating or updating DOM elements using JavaScript based on application data or user interaction.

Q13. How can pagination be combined with search?

First filter the original dataset, then calculate the page count and extract the current page from the filtered results.

Q14. What is the purpose of the spread operator in this project?

It creates a shallow copy of the original array, allowing the application to maintain a separate filtered dataset.

Q15. When should server-side pagination be preferred?

It is generally preferred when datasets are too large to load efficiently into the browser or when the backend should control filtering, sorting and data retrieval.

Q16. What is the difference between slice() and splice()?

slice() returns a portion without changing the original array. splice() modifies the original array by adding, removing or replacing elements.

Q17. Why should page navigation buttons be disabled at the boundaries?

The First and Previous buttons should be disabled on page one. The Next and Last buttons should be disabled on the final page. This prevents invalid navigation.

Q18. How would you optimize pagination for a very large dataset?

Use server-side pagination, database-level filtering and sorting, request only the required records, and consider cursor-based pagination where appropriate.

Q19. What is cursor-based pagination?

It uses a reference to the last record in the current result set to retrieve the next set of records. It can be more reliable than offset-based pagination when records are frequently inserted or deleted.

Q20. What is the difference between pagination and infinite scrolling?

Pagination provides explicit page navigation. Infinite scrolling loads additional content as the user approaches the end of the currently displayed content.
