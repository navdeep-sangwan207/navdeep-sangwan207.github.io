Lecture 06: Hoisting and Temporal Dead Zone

JavaScript Functions | Chapter 3

1. Learning Objectives

  • Understand JavaScript hoisting.
  • Understand how declarations are processed before execution.
  • Differentiate hoisting behavior of var, let and const.
  • Understand function declaration hoisting.
  • Understand function expression hoisting.
  • Learn the Temporal Dead Zone (TDZ).
  • Differentiate ReferenceError and undefined in hoisting examples.
  • Predict outputs of common interview programs.

2. What Is Hoisting?

Hoisting is the behavior in JavaScript where declarations are processed during the creation of an execution context before the code in that context is executed.

This can make certain identifiers accessible before the line where their declaration appears in the source code. However, different declaration types behave differently.

Example

console.log(name);

var name = "Rahul";

console.log(name);
Output: 
undefined
Rahul

The declaration of name is processed before execution, and its var binding is initialized with undefined. The assignment to "Rahul" occurs when execution reaches that line.

Important: Hoisting does not mean JavaScript physically moves source code declarations to the top. It describes how the language handles declarations and bindings during execution-context creation.

3. Hoisting with var

Variables declared with var are function-scoped or global-scoped. Their bindings are initialized to undefined when the relevant execution context is created.

Example 1: Access Before Declaration

console.log(age);

var age = 25;

console.log(age);
Output: 
undefined
25

Example 2: Multiple var Declarations

console.log(a);
console.log(b);

var a = 10;
var b = 20;

console.log(a + b);
Output: 
undefined
undefined
30

Conceptual Equivalent

The following illustrates the observable behavior of the previous example. It is not a literal transformation performed on the source code. 

var a;
var b;

console.log(a);
console.log(b);

a = 10;
b = 20;

console.log(a + b);

4. Hoisting with let

Variables declared with let are also registered before execution, but they are not initialized until their declaration is evaluated.

Accessing a let variable before its initialization results in a ReferenceError.

Example

console.log(age);

let age = 25;

console.log(age);
Result: The program throws a ReferenceError at the first console.log(age). The later statements do not execute.

Unlike var, let does not receive an initial value of undefined before its declaration is evaluated.

5. Hoisting with const

Variables declared with const are also registered before execution, but remain uninitialized until their declaration is evaluated.

Example

console.log(PI);

const PI = 3.14159;

console.log(PI);
Result: A ReferenceError occurs at the first console.log(PI). The declaration has not yet been initialized.

A const declaration must also include an initializer. 

const country;
Result: This produces a SyntaxError because a const declaration requires an initial value.

6. var vs let vs const: Hoisting Comparison

Feature var let const
Declaration processed before execution Yes Yes Yes
Initialized before declaration is evaluated Yes, with undefined No No
Access before initialization Returns undefined ReferenceError ReferenceError
Temporal Dead Zone No Yes Yes
Scope Function or global Block Block
Interview Rule: var is initialized to undefined during declaration processing. let and const remain uninitialized until their declaration is evaluated.

7. What Is the Temporal Dead Zone (TDZ)?

The Temporal Dead Zone is the period between entering the scope of a let or const declaration and the point where that declaration is initialized.

During this period, accessing the variable results in a ReferenceError.

Example

{
    // TDZ begins when this block is entered.

    // console.log(message); // ReferenceError

    let message = "Hello JavaScript";

    // TDZ has ended for message.
    console.log(message);
}
Output when the first console.log is commented out: 
Hello JavaScript

The TDZ is not simply the period before a line of code. It is tied to entering the relevant lexical scope and continues until the binding is initialized.

8. TDZ with Block Scope

Example 1: Accessing Before Initialization

let value = 100;

{
    // The inner value binding exists but is uninitialized.
    // console.log(value); // ReferenceError

    let value = 200;

    console.log(value);
}

console.log(value);
Output when the commented statement is omitted: 
200
100

The inner let value shadows the outer variable throughout the block. Before the inner declaration is initialized, accessing the identifier results in a ReferenceError rather than falling back to the outer variable.

Example 2: TDZ in an if Block

let status = "Available";

if (true) {
    // console.log(status); // ReferenceError

    let status = "Busy";

    console.log(status);
}

console.log(status);
Output when the commented statement is omitted: 
Busy
Available

9. Function Declaration Hoisting

Function declarations are hoisted with their function definitions. Therefore, a function declared using function declaration syntax can be called before its declaration appears in the source code.

Example

greet();

function greet() {
    console.log("Hello JavaScript");
}
Output: 
Hello JavaScript

The function declaration is available when execution reaches the function call.

Another Example

console.log(add(10, 20));

function add(a, b) {
    return a + b;
}
Output: 
30

10. Function Expression Hoisting

A function expression assigns a function to a variable. Its behavior before initialization depends on how the variable is declared.

Example 1: Function Expression with var

console.log(greet);

var greet = function() {
    console.log("Hello");
};

greet();
Output: 
undefined
Hello

The variable greet is initialized with undefined before the assignment is executed. The function value is assigned only when execution reaches the function expression.

Example 2: Calling a var Function Expression Too Early

greet();

var greet = function() {
    console.log("Hello");
};
Result: A TypeError occurs because greet is undefined when the call is attempted. An undefined value is not callable.

Example 3: Function Expression with let

greet();

let greet = function() {
    console.log("Hello");
};
Result: A ReferenceError occurs because greet is accessed while it is in the Temporal Dead Zone.

Example 4: Function Expression with const

greet();

const greet = function() {
    console.log("Hello");
};
Result: A ReferenceError occurs because greet has not yet been initialized.

11. Arrow Function Hoisting

Arrow functions are function expressions. Their availability before declaration depends on the variable declaration used to store them.

Example 1: Arrow Function with const

console.log(add);

const add = (a, b) => a + b;

console.log(add(10, 20));
Result: A ReferenceError occurs at the first console.log(add) because the binding is still in the Temporal Dead Zone.

Example 2: Arrow Function with var

console.log(add);

var add = (a, b) => a + b;

console.log(add(10, 20));
Result: The first statement prints undefined. The later call returns 30.
Remember: The function declaration itself and a variable holding a function expression are different declaration forms. Do not treat their hoisting behavior as identical.

12. Hoisting Inside Functions

Function declarations and variable declarations are processed within their respective execution contexts.

Example 1: Local var Hoisting

function display() {
    console.log(message);

    var message = "Inside function";

    console.log(message);
}

display();
Output: 
undefined
Inside function

Example 2: Function Declaration Inside a Function

function outer() {
    inner();

    function inner() {
        console.log("Inner function executed");
    }
}

outer();
Output: 
Inner function executed

13. Function Declaration vs Function Expression

Feature Function Declaration Function Expression
Syntax function greet() {} const greet = function() {}
Function definition available before declaration Yes, within its applicable scope No, the assigned function value is not available before initialization
Variable declaration involved Function binding Yes
Can be called before source declaration Yes Not safely before the variable is initialized

14. Common Hoisting Mistakes

Mistake 1: Assuming let Returns undefined

console.log(number);

let number = 10;

Correction: This throws a ReferenceError, not undefined.

Mistake 2: Calling a Function Expression Before Assignment

show();

var show = function() {
    console.log("Hello");
};

Correction: This throws a TypeError because show is undefined when called.

Mistake 3: Assuming const Is Not Hoisted

console.log(price);

const price = 500;

Correction: The binding is created during scope setup but remains uninitialized until its declaration is evaluated. Accessing it early throws a ReferenceError.

Mistake 4: Confusing Declaration with Initialization

var score;

console.log(score);

score = 90;

console.log(score);
Output: 
undefined
90

Declaration creates the binding; initialization and assignment determine the value available at a particular point in execution.

15. Placement Interview Questions

Q1. What is hoisting in JavaScript?

Answer: Hoisting describes how JavaScript processes declarations before executing statements in the relevant execution context.

Q2. Is var initialized during hoisting?

Answer: Yes. A var binding is initialized with undefined during execution-context setup.

Q3. Are let and const hoisted?

Answer: Their bindings are established before execution, but they remain uninitialized until their declarations are evaluated. They cannot be accessed during that period.

Q4. What is the Temporal Dead Zone?

Answer: The TDZ is the period from entering the scope of a lexical declaration until its binding is initialized.

Q5. What happens when a var variable is accessed before its declaration?

Answer: It returns undefined, provided the identifier resolves to that var binding.

Q6. What happens when a let variable is accessed before initialization?

Answer: JavaScript throws a ReferenceError.

Q7. Are function declarations hoisted?

Answer: Yes. Their function definitions are available within their applicable scope before the declaration appears in source code.

Q8. Are function expressions hoisted?

Answer: The variable declaration follows the behavior of var, let or const. The function value is assigned when execution reaches the function expression.

Q9. What is the difference between ReferenceError and TypeError in common hoisting examples?

Answer: A ReferenceError occurs when an identifier is accessed while its lexical binding is uninitialized or cannot be resolved. A TypeError can occur when a variable exists but its value, such as undefined, is called as a function.

Q10. Are arrow functions hoisted like function declarations?

Answer: No. Arrow functions are function expressions assigned to variables. Their availability depends on the variable declaration and initialization.

Q11. Does JavaScript physically move declarations to the top?

Answer: No. Hoisting is a conceptual description of declaration processing and binding initialization, not physical source-code movement.

Q12. Can a function declaration be called before its declaration?

Answer: Yes, because its function definition is available during execution-context setup.

18. Chapter Summary

  • Hoisting describes how declarations are processed before execution.
  • var bindings are initialized with undefined.
  • let and const remain uninitialized until their declaration is evaluated.
  • The TDZ causes a ReferenceError when an uninitialized lexical binding is accessed.
  • Function declarations can be called before their declaration appears.
  • Function expressions depend on the initialization of their assigned variables.
  • Arrow functions are function expressions, not function declarations.
  • A TypeError can occur when calling a variable whose value is undefined.
  • Hoisting behavior also applies within function execution contexts.
Placement Preparation: Practise predicting outputs involving declaration order, function declarations, function expressions and TDZ. Always identify whether the code produces a value, a ReferenceError or a TypeError.
