Lecture 04: Arrow Functions and this Behavior

JavaScript Functions | Chapter 3

1. Learning Objectives

  • Understand arrow function syntax.
  • Convert regular functions into arrow functions.
  • Understand implicit and explicit returns.
  • Use arrow functions with callbacks and array methods.
  • Understand how the this keyword works.
  • Understand lexical this in arrow functions.
  • Differentiate regular functions and arrow functions.
  • Identify situations where arrow functions should not be used.

2. What Are Arrow Functions?

Arrow functions are a shorter syntax for writing function expressions in JavaScript. They were introduced in ECMAScript 2015 (ES6).

An arrow function uses the arrow operator => between its parameter list and function body.

Regular Function Expression

const greet = function() {
    console.log("Hello JavaScript");
};

greet();

Equivalent Arrow Function

const greet = () => {
    console.log("Hello JavaScript");
};

greet();
Expected Output: 
Hello JavaScript

Both examples perform the same task, but the second uses arrow function syntax.

3. Arrow Function Syntax Variations

Example 1: No Parameters

const showMessage = () => {
    console.log("Welcome");
};

showMessage();
Output: 
Welcome

Example 2: One Parameter

Parentheses around a single parameter are optional. 

const greet = name => {
    console.log("Hello " + name);
};

greet("Rahul");
Output: 
Hello Rahul

Parentheses are also valid: (name) => { ... }.

Example 3: Multiple Parameters

const add = (a, b) => {
    console.log(a + b);
};

add(10, 20);
Output: 
30

Example 4: Single-Line Function Body

const square = number => number * number;

console.log(square(5));
Output: 
25

4. Implicit Return vs Explicit Return

An arrow function with an expression body automatically returns the result of that expression. This is called an implicit return.

Implicit Return

const multiply = (a, b) => a * b;

console.log(multiply(5, 4));
Output: 
20

Explicit Return

When an arrow function uses curly braces for its body, the return keyword is required if a value must be returned. 

const multiply = (a, b) => {
    return a * b;
};

console.log(multiply(5, 4));
Output: 
20

Common Mistake: Missing Return

const multiply = (a, b) => {
    a * b;
};

console.log(multiply(5, 4));
Output: 
undefined

The function calculates the expression but does not return its result.

Remember: Expression bodies return automatically. Block bodies using curly braces require an explicit return statement when a result is needed.

5. Returning Objects from Arrow Functions

When returning an object directly from an arrow function using an expression body, wrap the object in parentheses.

Correct Syntax

const createUser = (name, age) => ({
    name: name,
    age: age
});

console.log(createUser("Amit", 25));
Expected Output: 
{ name: 'Amit', age: 25 }

The browser console may display the object in an expandable format.

Incorrect Syntax

const createUser = (name, age) => {
    name: name,
    age: age
};

This is not an object-returning expression. Curly braces are interpreted as a function body, and the labels may be parsed as JavaScript labels rather than object properties.

6. Arrow Functions with Array Methods

Arrow functions are frequently used as callback functions with array methods such as map(), filter() and reduce().

Example 1: map()

The map() method creates a new array by applying a callback function to every element. 

const numbers = [1, 2, 3, 4, 5];

const squares = numbers.map(number => number * number);

console.log(squares);
Output: 
[1, 4, 9, 16, 25]

Example 2: filter()

The filter() method creates a new array containing elements that satisfy a condition. 

const numbers = [10, 15, 20, 25, 30];

const evenNumbers = numbers.filter(number => number % 2 === 0);

console.log(evenNumbers);
Output: 
[10, 20, 30]

Example 3: reduce()

The reduce() method processes array elements and combines them into a single accumulated result. 

const prices = [100, 200, 300];

const total = prices.reduce(
    (sum, price) => sum + price,
    0
);

console.log(total);
Output: 
600

Example 4: Sorting with an Arrow Function

const numbers = [40, 10, 30, 20];

numbers.sort((a, b) => a - b);

console.log(numbers);
Output: 
[10, 20, 30, 40]

7. Understanding the this Keyword

The this keyword refers to a value associated with the current function execution. Its value depends on how a regular function is called.

In regular functions, this is generally determined by the function's invocation context, not simply by where the function was written.

Example 1: Object Method

const user = {
    name: "Rahul",

    showName: function() {
        console.log(this.name);
    }
};

user.showName();
Output: 
Rahul

The method is called as user.showName(). Therefore, this refers to the user object.

Example 2: Regular Function Called Independently

function showThis() {
    console.log(this);
}

showThis();

In strict mode, this is undefined when a regular function is called independently. In non-strict mode, it is generally the global object.

Important: In browser scripts, the global object is generally window. In Node.js CommonJS modules, the top-level environment and function-call behavior differ. Do not assume browser and Node.js global contexts are identical.

8. How this Works in Arrow Functions

Arrow functions do not create their own this binding. Instead, they capture this lexically from the surrounding scope. This behavior is called lexical this.

Example 1: Regular Function vs Arrow Function

"use strict";

const user = {
    name: "Rahul",

    regularMethod: function() {
        console.log("Regular:", this.name);
    },

    arrowMethod: () => {
        console.log("Arrow:", this.name);
    }
};

user.regularMethod();
user.arrowMethod();

Expected behavior:

  • The regular method prints Rahul.
  • The arrow function does not use the user object as its this.
  • In this example, the arrow function captures the surrounding top-level this, which is not the user object.
The exact captured value depends on the execution environment. In a browser classic script, top-level this is generally window. In an ES module, it is undefined. The key point is that it is not automatically bound to user.

Example 2: Lexical this in a Nested Arrow Function

const user = {
    name: "Amit",

    showName: function() {
        const display = () => {
            console.log(this.name);
        };

        display();
    }
};

user.showName();
Output: 
Amit

The regular method receives user as its this value. The nested arrow function captures that same value from its surrounding method.

9. Regular Function vs Arrow Function: this

Example: setTimeout() Inside an Object Method

const user = {
    name: "Neha",

    showName: function() {
        setTimeout(() => {
            console.log(this.name);
        }, 1000);
    }
};

user.showName();
Expected Output after approximately 1 second: 
Neha

The arrow callback captures this from showName(), where it refers to the user object.

Compare with a Regular Callback

const user = {
    name: "Neha",

    showName: function() {
        setTimeout(function() {
            console.log(this.name);
        }, 1000);
    }
};

user.showName();

The regular callback receives its own this according to how the timer invokes it. In strict mode this is typically undefined; in a browser non-strict callback it is generally window.

Placement Concept: Arrow functions are useful for callbacks that should retain the surrounding method's this value.

10. call(), apply() and bind() with Arrow Functions

Regular functions can have their this value controlled using call(), apply() and bind().

Arrow functions do not have their own this. These methods cannot replace the lexical this captured by an arrow function.

Example

const person = {
    name: "Rahul"
};

function regularFunction() {
    console.log(this.name);
}

const arrowFunction = () => {
    console.log(this.name);
};

regularFunction.call(person);
arrowFunction.call(person);

Expected behavior:

  • regularFunction.call(person) uses person as its this.
  • arrowFunction.call(person) does not change the arrow function's lexical this.
Do not use call(), apply() or bind() to try to change an arrow function's this value.

11. Important Differences Between Regular and Arrow Functions

Feature Regular Function Arrow Function
Syntax function() {} () => {}
Own this Yes, determined by invocation. No, captures lexical this.
arguments object Available in traditional functions. No own arguments object.
Rest parameters Supported Supported
Constructor Constructible when suitable. Cannot be used as a constructor.
Prototype property Ordinary constructible functions have one. No own prototype property.
Implicit return No Yes, for expression bodies.
Generator syntax Can be declared as generator functions. Cannot be declared as generator functions.
Best use Object methods, constructors and dynamic this. Callbacks and lexical this behavior.

12. Why Arrow Functions Cannot Be Constructors

Regular constructible functions can be invoked with the new operator to create objects. Arrow functions are not constructible.

Regular Constructor Function

function Employee(name, salary) {
    this.name = name;
    this.salary = salary;
}

const employee = new Employee("Rahul", 30000);

console.log(employee.name);
console.log(employee.salary);
Output: 
Rahul
30000

Arrow Function Constructor Attempt

const Employee = (name, salary) => {
    this.name = name;
    this.salary = salary;
};

const employee = new Employee("Rahul", 30000);
Result: JavaScript throws a TypeError because an arrow function cannot be used with new.

13. When Should You Avoid Arrow Functions?

1. Object Methods Requiring Their Own this

const employee = {
    name: "Amit",

    showName() {
        console.log(this.name);
    }
};

employee.showName();
Output: 
Amit

A concise method definition or regular function expression is suitable when the method needs its own invocation-based this.

2. Constructor Functions

Use a regular constructible function or a class when objects must be created with new.

3. Dynamic this in Event Handlers

In traditional DOM event listeners, a regular function can receive the element as this. An arrow callback does not acquire that event-handler-specific this. 

// Regular function
button.addEventListener("click", function() {
    console.log(this); // The button element
});

// Arrow function
button.addEventListener("click", () => {
    console.log(this); // Lexical this, not automatically the button
});
Practical Advice: Use event.currentTarget when you need the element on which the event listener is registered, regardless of whether the callback is regular or arrow.

14. Common Mistakes and Debugging

Mistake 1: Missing Parentheses for No Parameters

// Incorrect
const greet = => "Hello";

// Correct
const greet = () => "Hello";

Mistake 2: Forgetting return in a Block Body

// Incorrect when a value is required
const add = (a, b) => {
    a + b;
};

// Correct
const add = (a, b) => {
    return a + b;
};

Mistake 3: Returning an Object Without Parentheses

// Correct
const getUser = () => ({
    name: "Rahul"
});

Mistake 4: Assuming Arrow Functions Have Their Own this

const user = {
    name: "Amit",

    show: () => {
        console.log(this.name);
    }
};

user.show();

The arrow function does not receive the object as this. Use a regular method if the method needs to access the object through this.

Mistake 5: Trying to Use new with an Arrow Function

const Person = name => {
    this.name = name;
};

// TypeError
const person = new Person("Amit");

Use a regular constructor function or a class instead.

15. Placement Interview Questions

Q1. What is an arrow function?

Answer: An arrow function is an ES6 function expression that uses the => syntax. It provides concise syntax and lexical this behavior.

Q2. What is an implicit return?

Answer: An implicit return occurs when an arrow function with an expression body automatically returns the expression's value without using return.

Q3. Do arrow functions have their own this?

Answer: No. Arrow functions capture this from their surrounding lexical scope.

Q4. What is lexical this?

Answer: Lexical this means that an arrow function uses the this value from the surrounding scope in which it was created.

Q5. Can arrow functions be used as constructors?

Answer: No. Arrow functions are not constructible and cannot be invoked with new.

Q6. Do arrow functions have an arguments object?

Answer: No. They do not have their own arguments object. Rest parameters can be used to collect arguments.

Q7. Can call(), apply() and bind() change an arrow function's this?

Answer: No. These methods cannot override the lexical this captured by an arrow function.

Q8. Can arrow functions be used as callbacks?

Answer: Yes. They are commonly used with array methods, timers, promises and event handlers.

Q9. What is the difference between a regular function and an arrow function?

Answer: A regular function has its own invocation-based this and can be constructible. An arrow function has lexical this and cannot be used as a constructor.

Q10. Why are arrow functions useful with setTimeout()?

Answer: An arrow callback preserves the surrounding this value, which is useful when accessing object properties inside asynchronous callbacks.

Q11. Can an arrow function return an object?

Answer: Yes. When using an expression body, wrap the object literal in parentheses to distinguish it from a function body.

Q12. Should every function be written as an arrow function?

Answer: No. Use arrow functions when concise syntax or lexical this is useful. Use regular functions or methods when their own this or constructor behavior is required.

17. Chapter Summary

  • Arrow functions were introduced in ES6.
  • They use the => syntax.
  • Parentheses can be omitted for a single parameter.
  • Expression bodies provide implicit returns.
  • Block bodies require an explicit return statement when a value is needed.
  • Object literals returned directly should be wrapped in parentheses.
  • Arrow functions are widely used as callbacks.
  • Arrow functions capture lexical this.
  • They do not have their own arguments object.
  • They cannot be used as constructors.
  • call(), apply() and bind() cannot change their lexical this.
  • Regular functions remain useful for object methods and constructors.
Placement Tip: Focus on output-based questions involving arrow functions, implicit returns, object methods, nested callbacks and lexical this. Be able to explain why an arrow callback behaves differently from a regular callback.
