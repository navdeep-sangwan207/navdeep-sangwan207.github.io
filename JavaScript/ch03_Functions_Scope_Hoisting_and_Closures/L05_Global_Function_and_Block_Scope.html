Lecture 05: Global, Function and Block Scope

JavaScript Functions | Chapter 3

1. Learning Objectives

  • Understand the meaning of scope in JavaScript.
  • Differentiate global, function and block scope.
  • Understand how var, let and const behave in different scopes.
  • Understand nested scopes and variable accessibility.
  • Learn lexical scope and scope lookup.
  • Understand variable shadowing.
  • Identify common scope-related errors.
  • Solve output-based placement interview questions.

2. What Is Scope?

Scope defines where a variable, function or other identifier can be accessed in a JavaScript program.

In simple terms, scope determines the visibility and accessibility of variables.

Example

let message = "Hello JavaScript";

function displayMessage() {
    console.log(message);
}

displayMessage();
console.log(message);
Output: 
Hello JavaScript
Hello JavaScript

The variable message is declared outside the function. It can be accessed both outside and inside the function, subject to the surrounding scope.

Core Concept: Scope is about where an identifier can be accessed. It is not the same as the lifetime of an object or variable.

3. Types of Scope in JavaScript

For placement preparation, understand these three primary scopes:

Scope Meaning Typical Declaration
Global scope Accessible throughout the relevant global environment. Declaration outside functions and blocks.
Function scope Accessible within the function where it is declared. var inside a function; also let and const within their function's enclosing block scopes.
Block scope Accessible within the block where it is declared. let and const.

JavaScript also has module scope, and functions can create nested lexical scopes. These are important in modern application development.

4. Global Scope

A variable declared in the global scope is accessible from code within its applicable global environment, unless another declaration shadows it.

Example 1: Global Variable

let company = "ABC Technologies";

function showCompany() {
    console.log(company);
}

function showMessage() {
    console.log("Welcome to " + company);
}

showCompany();
showMessage();
console.log(company);
Output: 
ABC Technologies
Welcome to ABC Technologies
ABC Technologies

Example 2: Updating a Global Variable

let count = 10;

function updateCount() {
    count = 20;
}

console.log(count);

updateCount();

console.log(count);
Output: 
10
20

The function updates the existing global variable because it does not declare a new local variable.

Global Scope and var, let, const

In a browser's classic script, top-level var declarations create properties on the global object, while top-level let and const declarations do not. 

// Browser classic script

var firstName = "Amit";
let age = 25;
const country = "India";

console.log(window.firstName);
console.log(window.age);
console.log(window.country);
Expected Output in a browser classic script: 
Amit
undefined
undefined
This example is specifically for a browser classic script. Top-level declarations in ES modules and Node.js modules have different global-object behavior.

5. Function Scope

Function scope means that a variable declared inside a function is accessible within that function, including its nested blocks, but not outside the function.

Example 1: Local Variable

function calculateSalary() {
    let salary = 30000;

    console.log(salary);
}

calculateSalary();

// console.log(salary); // ReferenceError
Output: 
30000

Accessing salary outside the function causes a ReferenceError because the identifier is not available in that scope.

Example 2: var Is Function-Scoped

function display() {
    var message = "Inside function";

    if (true) {
        var number = 100;
    }

    console.log(message);
    console.log(number);
}

display();

// console.log(message); // ReferenceError
// console.log(number);  // ReferenceError
Output: 
Inside function
100

The variable number is declared using var. Its scope is the entire function, not just the if block.

Example 3: let and const Are Also Limited by the Function

function employeeDetails() {
    let name = "Rahul";
    const department = "Development";

    console.log(name);
    console.log(department);
}

employeeDetails();

// console.log(name);       // ReferenceError
// console.log(department); // ReferenceError

let and const are block-scoped, but declarations inside a function are still inaccessible outside that function.

6. Block Scope

A block is a group of statements enclosed within curly braces { }, such as the body of an if, for or while statement.

Variables declared using let and const are limited to the block in which they are declared.

Example 1: let Inside a Block

{
    let message = "Block scope";
    console.log(message);
}

// console.log(message); // ReferenceError
Output: 
Block scope

Example 2: const Inside a Block

{
    const PI = 3.14159;
    console.log(PI);
}

// console.log(PI); // ReferenceError
Output: 
3.14159

Example 3: var Is Not Block-Scoped

if (true) {
    var a = 10;
    let b = 20;
    const c = 30;
}

console.log(a);

// console.log(b); // ReferenceError
// console.log(c); // ReferenceError
Output: 
10

The var declaration is accessible outside the block because it is not block-scoped. The let and const declarations remain inside the block.

7. Scope of var, let and const

Understanding the difference between these declarations is essential for JavaScript coding interviews.

Feature var let const
Scope Function or global Block Block
Redeclaration in same scope Allowed Not allowed Not allowed
Reassignment Allowed Allowed Not allowed
Initialization required at declaration No No Yes
Block-scoped No Yes Yes

Example: Redeclaration

var x = 10;
var x = 20;

console.log(x);
Output: 
20

Redeclaring a let or const identifier in the same scope produces a SyntaxError.

Example: Reassignment

let age = 20;
age = 25;

console.log(age);

const country = "India";

// country = "USA"; // TypeError
Output before the commented assignment: 
25
Important: const prevents reassignment of the binding. It does not automatically make an object or array immutable.

Example: const Object Can Be Modified

const employee = {
    name: "Amit",
    salary: 30000
};

employee.salary = 35000;

console.log(employee.salary);
Output: 
35000

8. Nested Scope

A nested scope occurs when one scope is created inside another scope. An inner scope can generally access identifiers from its outer lexical scopes.

Example 1: Accessing an Outer Variable

let company = "ABC";

function outerFunction() {
    let department = "Engineering";

    function innerFunction() {
        let employee = "Rahul";

        console.log(company);
        console.log(department);
        console.log(employee);
    }

    innerFunction();
}

outerFunction();
Output: 
ABC
Engineering
Rahul

The inner function can access variables from its own scope and the surrounding outer scopes.

Example 2: Outer Scope Cannot Access Inner Variables

function outer() {
    let outerValue = 10;

    function inner() {
        let innerValue = 20;
        console.log(innerValue);
    }

    inner();

    console.log(outerValue);

    // console.log(innerValue); // ReferenceError
}

outer();
Output: 
20
10

Scope accessibility is directional: inner scopes can access outer variables, but outer scopes cannot directly access variables declared only inside inner scopes.

9. Lexical Scope

Lexical scope means that variable accessibility is determined by the physical structure of the source code where functions and blocks are defined.

A function can access variables from the scope in which it was created, even if it is later called from somewhere else.

Example

let message = "Global message";

function outer() {
    let message = "Outer message";

    function inner() {
        console.log(message);
    }

    return inner;
}

const result = outer();

result();
Output: 
Outer message

The inner function was defined inside outer(). Therefore, it accesses the message variable from that lexical scope.

Placement Connection: Lexical scope is the foundation for understanding closures, which are covered in Lecture 07.

10. Scope Chain

When JavaScript encounters a variable reference, it first searches the current scope. If the variable is not found, it searches the enclosing lexical scope, continuing outward until it reaches the global environment.

This lookup process is commonly called the scope chain.

Example

let a = 10;

function first() {
    let b = 20;

    function second() {
        let c = 30;

        function third() {
            let d = 40;

            console.log(a);
            console.log(b);
            console.log(c);
            console.log(d);
        }

        third();
    }

    second();
}

first();
Output: 
10
20
30
40

The innermost function searches for each identifier in this order:

  1. Its own scope.
  2. The enclosing second() scope.
  3. The enclosing first() scope.
  4. The global scope.

If an identifier cannot be found in the applicable lexical environments, accessing it results in a ReferenceError.

11. Variable Shadowing

Variable shadowing occurs when a variable declared in an inner scope has the same name as a variable in an outer scope. The inner declaration takes precedence within its own scope.

Example 1: Basic Shadowing

let name = "Rahul";

function display() {
    let name = "Amit";

    console.log(name);
}

display();
console.log(name);
Output: 
Amit
Rahul

Inside display(), the local name shadows the global name.

Example 2: Block-Level Shadowing

let value = 100;

{
    let value = 200;
    console.log(value);
}

console.log(value);
Output: 
200
100

Example 3: Invalid Shadowing with let

let number = 10;

{
    // SyntaxError: Identifier 'number' has already
    // been declared in an overlapping lexical scope.
    // var number = 20;
}

A var declaration cannot redeclare an identifier that already exists as a let or const binding in an overlapping lexical scope.

Shadowing and redeclaration are different concepts. Shadowing uses a separate nested scope; redeclaration attempts to declare the same identifier again in the same scope.

12. Block Scope in Loops

The difference between var and let is particularly important in loops.

Example 1: var in a Loop with setTimeout()

for (var i = 1; i <= 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
Output after approximately 1 second: 
4
4
4

All callbacks refer to the same function-scoped i binding. By the time the callbacks execute, the loop has finished and i is 4.

Example 2: let in a Loop with setTimeout()

for (let i = 1; i <= 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
Output after approximately 1 second: 
1
2
3

A let declaration in a for loop creates a distinct per-iteration binding. Each callback captures the value associated with its iteration.

Interview Tip: This is a frequently tested question combining scope, closures and asynchronous callbacks.

13. Module Scope

JavaScript modules have their own top-level scope. Variables and functions declared at the top level of a module are not automatically global.

Example: math.js

const PI = 3.14159;

function add(a, b) {
    return a + b;
}

export { PI, add };

Example: app.js

import { PI, add } from "./math.js";

console.log(PI);
console.log(add(10, 20));
Output: 
3.14159
30

The export and import statements provide controlled access to declarations between modules.

ES module examples should be run in an environment that supports modules. In a browser, load the entry file with <script type="module" src="app.js"></script>.

14. Common Scope Errors

Error 1: ReferenceError Outside Scope

function test() {
    let message = "Hello";
}

test();

console.log(message);

Reason: message exists only inside the function.

Error 2: Accessing a Block-Scoped Variable Outside Its Block

if (true) {
    let score = 90;
}

console.log(score);

Reason: score is restricted to the if block.

Error 3: Redeclaring let in the Same Scope

let age = 25;

// SyntaxError
// let age = 30;

Reason: A lexical declaration cannot redeclare the same identifier in the same scope.

Error 4: Using a Variable Before Its Initialization

console.log(price);

let price = 100;

Reason: The variable is in its temporal dead zone before initialization. The detailed explanation is covered in Lecture 06.

15. Practical Example: Employee Data

This example combines global, function and block scope in a small application-style program. 

const company = "ABC Technologies";

function calculateEmployeeSalary(basicSalary, allowance) {
    const totalSalary = basicSalary + allowance;

    if (totalSalary >= 40000) {
        let category = "Senior Salary";

        console.log("Category:", category);
    } else {
        let category = "Standard Salary";

        console.log("Category:", category);
    }

    return totalSalary;
}

const salary = calculateEmployeeSalary(35000, 10000);

console.log("Company:", company);
console.log("Total Salary:", salary);
Output: 
Category: Senior Salary
Company: ABC Technologies
Total Salary: 45000

Scope analysis:

  • company is declared in the outermost scope.
  • basicSalary and allowance are function parameters.
  • totalSalary is local to the function.
  • category is block-scoped inside each branch.
  • salary is declared in the outermost scope.

16. Placement Interview Questions

Q1. What is scope in JavaScript?

Answer: Scope determines where variables, functions and other identifiers can be accessed in a JavaScript program.

Q2. What are the main types of scope?

Answer: Global scope, function scope and block scope are the primary scope categories commonly discussed in JavaScript interviews. Module scope is also important in modern JavaScript.

Q3. What is the difference between function scope and block scope?

Answer: Function-scoped declarations are accessible throughout their function. Block-scoped declarations are accessible only within their enclosing block.

Q4. Which declarations are block-scoped?

Answer: let and const are block-scoped. var is function-scoped or global-scoped depending on where it is declared.

Q5. Can a function access a global variable?

Answer: Yes. A function can access variables from its outer lexical environments, including the global environment, provided they are not shadowed.

Q6. Can an outer function access a variable declared inside an inner function?

Answer: No. The outer function cannot directly access a variable declared only in the inner function's scope.

Q7. What is lexical scope?

Answer: Lexical scope means that variable accessibility is determined by where functions and blocks are defined in the source code.

Q8. What is the scope chain?

Answer: It is the process through which JavaScript searches the current lexical scope and then its enclosing scopes to resolve an identifier.

Q9. What is variable shadowing?

Answer: Shadowing occurs when an identifier in an inner scope has the same name as an identifier in an outer scope. The inner binding takes precedence within its scope.

Q10. Why does var behave differently from let in a loop?

Answer: var creates one function-scoped binding, whereas let in a for loop creates a distinct per-iteration binding.

Q11. What is module scope?

Answer: Module scope means that top-level declarations inside an ES module belong to that module and are not automatically global.

Q12. Does const make an object immutable?

Answer: No. const prevents reassignment of the variable binding, but properties of the referenced object can still be modified unless additional measures are used.

18. Chapter Summary

  • Scope determines where identifiers can be accessed.
  • Global declarations belong to the relevant global environment.
  • Function scope limits declarations to a function.
  • var is function-scoped, not block-scoped.
  • let and const are block-scoped.
  • Nested functions can access variables in enclosing lexical scopes.
  • Outer scopes cannot directly access variables declared only in inner scopes.
  • Lexical scope is determined by source-code structure.
  • The scope chain is used to resolve identifiers.
  • Variable shadowing occurs when inner declarations hide outer declarations.
  • ES modules have their own top-level module scope.
  • Scope is a foundation for understanding closures.
