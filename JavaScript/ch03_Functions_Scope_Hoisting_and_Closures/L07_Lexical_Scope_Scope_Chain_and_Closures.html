Lesson 7: Lexical Scope, Scope Chain and Closures

Understand how JavaScript resolves variables and how functions retain access to their surrounding environment.

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand lexical scope in JavaScript.
  • Explain how the scope chain works.
  • Understand how inner functions access outer variables.
  • Explain closures and their practical applications.
  • Use closures to maintain private state.
  • Understand closures in loops and callbacks.
  • Identify common closure-related mistakes in coding interviews.

2. Understanding Lexical Scope

Lexical scope means that the accessibility of variables is determined by where functions and blocks are written in the source code.

A function can access variables declared in its own scope and in its surrounding outer scopes, subject to normal declaration and access rules.

Example 1: Accessing an Outer Variable

const company = "Tech Solutions";

function displayCompany() {
    console.log(company);
}

displayCompany();
Expected Output: 
Tech Solutions

The variable company is declared outside the function. Because of lexical scope, displayCompany() can access it.

Example 2: Nested Functions

function outerFunction() {
    const message = "Hello from outer function";

    function innerFunction() {
        console.log(message);
    }

    innerFunction();
}

outerFunction();
Expected Output: 
Hello from outer function

The inner function can access the variable declared in the outer function because it is lexically nested inside it.

Important: Lexical scope depends on where a function is defined, not where that function is called.

Example 3: Definition Location vs Calling Location

const value = "Global";

function showValue() {
    console.log(value);
}

function anotherFunction() {
    const value = "Local";
    showValue();
}

anotherFunction();
Expected Output: 
Global

Although showValue() is called inside anotherFunction(), it was defined in the global scope. Therefore, it resolves value using its lexical environment and finds the global variable.

3. Understanding the Scope Chain

When JavaScript encounters a variable reference, it searches for that variable in the current scope first. If it is not found, JavaScript searches the surrounding outer scope.

This process continues outward through the nested lexical environments until the variable is found or the outermost scope is reached.

This lookup mechanism is called the scope chain.

Example: Multiple Nested Scopes

const country = "India";

function outerFunction() {
    const state = "Haryana";

    function middleFunction() {
        const city = "Sonipat";

        function innerFunction() {
            const message = "Welcome";

            console.log(message);
            console.log(city);
            console.log(state);
            console.log(country);
        }

        innerFunction();
    }

    middleFunction();
}

outerFunction();
Expected Output: 
Welcome
Sonipat
Haryana
India

The lookup process for country is:

  1. Check the scope of innerFunction().
  2. Check the scope of middleFunction().
  3. Check the scope of outerFunction().
  4. Check the global scope.
  5. Find country in the global scope.

Example: Variable Not Found

function testFunction() {
    console.log(username);
}

testFunction();
Expected Result: 
ReferenceError: username is not defined

JavaScript searches the available outer scopes but cannot find username. Therefore, it throws a ReferenceError.

4. What Is a Closure?

A closure is created when a function retains access to variables from its surrounding lexical environment, even after the outer function has finished executing.

In practical terms, an inner function can continue using variables from the function in which it was created.

Example 1: Basic Closure

function outerFunction() {
    const message = "Hello JavaScript";

    function innerFunction() {
        console.log(message);
    }

    return innerFunction;
}

const myFunction = outerFunction();

myFunction();
Expected Output: 
Hello JavaScript

Understand what happens:

  1. outerFunction() creates the variable message.
  2. It creates and returns innerFunction.
  3. The outer function finishes executing.
  4. myFunction refers to the returned inner function.
  5. When called, the inner function can still access message.

The inner function retains access to its surrounding lexical environment. This is a closure.

Example 2: Closure with a Counter

function createCounter() {
    let count = 0;

    return function () {
        count++;
        console.log(count);
    };
}

const counter = createCounter();

counter();
counter();
counter();
Expected Output: 
1
2
3

The returned function retains access to count. Each call updates the same captured variable.

Interview concept: A closure retains access to variable bindings, not necessarily frozen copies of their values. Changes to a captured variable can be observed by the closure.

Example 3: Multiple Independent Closures

function createCounter() {
    let count = 0;

    return function () {
        count++;
        return count;
    };
}

const counterA = createCounter();
const counterB = createCounter();

console.log(counterA());
console.log(counterA());
console.log(counterB());
console.log(counterA());
console.log(counterB());
Expected Output: 
1
2
1
3
2

Every call to createCounter() creates a separate lexical environment. Therefore, counterA and counterB maintain independent counter values.

5. Practical Applications of Closures

5.1 Data Privacy and Encapsulation

Closures can be used to keep variables private and expose only selected operations. 

function createBankAccount(initialBalance) {
    let balance = initialBalance;

    return {
        deposit(amount) {
            if (amount > 0) {
                balance += amount;
            }
        },

        withdraw(amount) {
            if (amount > 0 && amount <= balance) {
                balance -= amount;
            } else {
                console.log("Invalid withdrawal");
            }
        },

        getBalance() {
            return balance;
        }
    };
}

const account = createBankAccount(5000);

account.deposit(2000);
account.withdraw(1000);

console.log(account.getBalance());
console.log(account.balance);
Expected Output: 
6000
undefined

The balance variable is not directly accessible through the returned object. The account methods can access and modify it through their shared closure.

5.2 Function Factory

A function factory returns another function configured with a particular value. 

function createMultiplier(multiplier) {
    return function (number) {
        return number * multiplier;
    };
}

const double = createMultiplier(2);
const triple = createMultiplier(3);

console.log(double(10));
console.log(triple(10));
Expected Output: 
20
30

5.3 Memoization

Memoization is an optimization technique that stores previously calculated results so that repeated inputs can reuse them. Closures can retain the cache between function calls. 

function memoizedSquare() {
    const cache = {};

    return function (number) {
        if (Object.hasOwn(cache, number)) {
            console.log("From cache");
            return cache[number];
        }

        console.log("Calculating");
        const result = number * number;
        cache[number] = result;

        return result;
    };
}

const square = memoizedSquare();

console.log(square(5));
console.log(square(5));
console.log(square(8));
Expected Output: 
Calculating
25
From cache
25
Calculating
64

The cache remains available because the returned function retains access to the cache object.

5.4 Maintaining State in Callbacks

function createClickHandler() {
    let clicks = 0;

    return function () {
        clicks++;
        console.log("Button clicked:", clicks);
    };
}

const handleClick = createClickHandler();

handleClick();
handleClick();
handleClick();
Expected Output: 
Button clicked: 1
Button clicked: 2
Button clicked: 3

This pattern is useful when event handlers need to maintain information between executions.

6. Closures Inside Loops

A common JavaScript interview question involves creating functions inside loops using var and let.

Example 1: The var Problem

var functions = [];

for (var i = 0; i < 3; i++) {
    functions.push(function () {
        console.log(i);
    });
}

functions[0]();
functions[1]();
functions[2]();
Expected Output: 
3
3
3

The var declaration is function-scoped, not block-scoped. All three functions close over the same i binding.

After the loop finishes, i has the value 3. Each function reads that same final value when called.

Example 2: Using let

const functions = [];

for (let i = 0; i < 3; i++) {
    functions.push(function () {
        console.log(i);
    });
}

functions[0]();
functions[1]();
functions[2]();
Expected Output: 
0
1
2

With let in a for loop, each iteration has its own iteration binding. The functions retain access to their respective iteration values.

Example 3: Using an IIFE with var

An Immediately Invoked Function Expression (IIFE) can create a separate function scope for each iteration. 

var functions = [];

for (var i = 0; i < 3; i++) {
    (function (value) {
        functions.push(function () {
            console.log(value);
        });
    })(i);
}

functions[0]();
functions[1]();
functions[2]();
Expected Output: 
0
1
2

Each IIFE receives the current value of i as value. The inner function closes over that separate parameter binding.

Placement tip: Be able to explain why var produces the final loop value and how let provides a separate binding for each iteration.

7. Common Mistakes and Debugging

Mistake 1: Assuming a Closure Stores a Frozen Value

function outer() {
    let count = 10;

    const showCount = function () {
        console.log(count);
    };

    count = 20;

    return showCount;
}

const result = outer();
result();
Expected Output: 
20

The closure accesses the same captured binding. It does not automatically preserve the initial value of 10.

Mistake 2: Trying to Access an Inner Variable from Outside

function outer() {
    let secret = "Hidden";
}

outer();

console.log(secret);
Expected Result: 
ReferenceError: secret is not defined

The variable secret belongs to the local scope of outer(). It cannot be accessed directly from outside.

Mistake 3: Unintended Memory Retention

A long-lived closure can keep references to objects in its surrounding environment. Those objects may remain reachable while the closure is reachable.

This can contribute to unnecessary memory retention if an application keeps closures or event handlers alive longer than needed.

Good practices include:

  • Remove event listeners when they are no longer required.
  • Avoid unnecessarily retaining large objects in long-lived closures.
  • Release references to obsolete callbacks and objects.
  • Use browser developer tools to investigate memory usage.
A closure does not automatically cause a memory leak. Memory becomes a concern when objects remain reachable unnecessarily.

8. Lexical Scope vs Scope Chain vs Closure

Concept Meaning Purpose
Lexical Scope Variable accessibility is determined by where code is written. Defines the scope relationships.
Scope Chain Identifier lookup proceeds from inner scope to outer scopes. Resolves variable references.
Closure A function retains access to its surrounding lexical environment. Allows functions to preserve access to state.

9. Placement Interview Questions and Answers

Q1. What is lexical scope in JavaScript?

Answer: Lexical scope is the rule that determines variable accessibility based on where functions and blocks are defined in the source code.

Q2. What is the scope chain?

Answer: The scope chain is the mechanism through which JavaScript searches the current lexical scope and then surrounding outer scopes to resolve an identifier.

Q3. What is a closure?

Answer: A closure is a function together with access to its surrounding lexical environment. It allows the function to use outer variables even after the outer function has returned.

Q4. Why are closures useful?

Answer: Closures are useful for data privacy, maintaining state, function factories, memoization, callbacks and event handlers.

Q5. Can an inner function access variables of its outer function?

Answer: Yes. An inner function can access variables in its outer lexical scopes, provided those variables are available under JavaScript's declaration and access rules.

Q6. Can an outer function access variables declared inside an inner function?

Answer: No. Variables declared inside an inner function are local to that function and are not directly accessible from the outer function.

Q7. Does a closure retain a copy of a variable?

Answer: Not generally. A closure retains access to the variable binding in its lexical environment. If that binding changes, the closure can observe the updated value.

Q8. Why do functions created inside a var loop often print the same value?

Answer: Because all functions refer to the same function-scoped var binding. When called after the loop, they observe its final value.

Q9. How does let solve the loop closure problem?

Answer: A let declaration in a for loop creates a separate iteration binding, allowing each closure to retain its corresponding iteration value.

Q10. Can closures cause memory leaks?

Answer: Closures can contribute to memory retention when they keep references to objects that are no longer needed. This becomes a problem when those references remain reachable unnecessarily.

var callbacks = [];

for (var i = 0; i < 3; i++) {
    callbacks.push(function () {
        console.log(i);
    });

callbacks.forEach(function (callback) {
    callback();
});

11. Lesson Summary

  • Lexical scope is determined by the location where code is defined.
  • The scope chain searches from the current scope toward outer scopes.
  • Inner functions can access variables from their outer lexical scopes.
  • Closures retain access to their surrounding lexical environment.
  • Closures can maintain private state between function calls.
  • Closures are useful for callbacks, function factories and memoization.
  • let provides separate iteration bindings in a traditional for loop.
  • Unnecessary retained references can cause memory-management problems.

These concepts are frequently tested in JavaScript interviews, especially in questions involving nested functions, callbacks, event handlers and asynchronous code.
