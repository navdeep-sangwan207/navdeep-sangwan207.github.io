8.1 Introduction to Polymorphism

Polymorphism means "many forms." In C++, it allows the same interface or operation to behave differently depending on the arguments or the object involved.

Types of polymorphism

  • Compile-time polymorphism: Function overloading, operator overloading and templates.
  • Runtime polymorphism: Virtual functions and function overriding through a base-class interface.

8.2 Function Overloading

Function overloading allows multiple functions to share a name when their parameter lists differ. Return type alone cannot distinguish overloaded functions.

Program 1: Function Overloading

#include <iostream>
using namespace std;

int add(int a, int b)
{
    return a + b;
}

double add(double a, double b)
{
    return a + b;
}

int main()
{
    cout << add(10, 20) << endl;
    cout << add(2.5, 3.5) << endl;

    return 0;
}

Expected Output

30
6

The compiler selects the appropriate overload based on the arguments.

8.3 Operator Overloading

Operator overloading lets a class define how supported operators behave for its objects.

Program 2: Overload the + Operator

#include <iostream>
using namespace std;

class Complex
{
private:
    int real;
    int imag;

public:
    Complex(int r, int i) : real(r), imag(i) {}

    Complex operator+(const Complex& other) const
    {
        return Complex(real + other.real, imag + other.imag);
    }

    void display() const
    {
        cout << real;
        if (imag >= 0)
            cout << " + " << imag << "i" << endl;
        else
            cout << " - " << -imag << "i" << endl;
    }
};

int main()
{
    Complex c1(2, 3);
    Complex c2(4, 5);

    Complex c3 = c1 + c2;
    c3.display();

    return 0;
}

Expected Output

6 + 8i

Operator overloading cannot change an operator's precedence, associativity or number of operands.

8.4 Function Overriding

Function overriding occurs when a derived class provides its own implementation of an inherited virtual function with a matching signature.

Program 3: Function Overriding

#include <iostream>
using namespace std;

class Animal
{
public:
    virtual void sound() const
    {
        cout << "Animal makes a sound" << endl;
    }

    virtual ~Animal() = default;
};

class Dog : public Animal
{
public:
    void sound() const override
    {
        cout << "Dog barks" << endl;
    }
};

int main()
{
    Dog d;
    d.sound();

    return 0;
}

Expected Output

Dog barks

The override keyword asks the compiler to verify that the function overrides a virtual function in the base class.

8.5 Virtual Functions

A virtual function enables runtime dispatch when called through a base-class pointer or reference. The implementation selected depends on the object's dynamic type.

Program 4: Runtime Polymorphism

#include <iostream>
using namespace std;

class Shape
{
public:
    virtual void draw() const
    {
        cout << "Drawing a shape" << endl;
    }

    virtual ~Shape() = default;
};

class Circle : public Shape
{
public:
    void draw() const override
    {
        cout << "Drawing a circle" << endl;
    }
};

class Rectangle : public Shape
{
public:
    void draw() const override
    {
        cout << "Drawing a rectangle" << endl;
    }
};

int main()
{
    Circle circle;
    Rectangle rectangle;

    Shape* shape = &circle;
    shape->draw();

    shape = &rectangle;
    shape->draw();

    return 0;
}

Expected Output

Drawing a circle
Drawing a rectangle

Although the pointer type is Shape*, each call invokes the implementation associated with the actual object.

8.6 Pure Virtual Functions and Abstract Classes

A pure virtual function is declared by assigning = 0 in its declaration. A class with at least one pure virtual function is abstract and cannot be instantiated directly.

Program 5: Abstract Class

#include <iostream>
using namespace std;

class Payment
{
public:
    virtual void pay(double amount) = 0;
    virtual ~Payment() = default;
};

class UpiPayment : public Payment
{
public:
    void pay(double amount) override
    {
        cout << "UPI payment: " << amount << endl;
    }
};

int main()
{
    UpiPayment payment;
    payment.pay(500);

    return 0;
}

Expected Output

UPI payment: 500

Abstract classes are useful for defining common interfaces that different derived classes implement.

8.7 Virtual Destructors

If an object of a derived class is deleted through a base-class pointer, the base class generally needs a virtual destructor to ensure proper destruction of the derived object.

Program 6: Virtual Destructor

#include <iostream>
using namespace std;

class Base
{
public:
    virtual ~Base()
    {
        cout << "Base destructor" << endl;
    }
};

class Derived : public Base
{
public:
    ~Derived() override
    {
        cout << "Derived destructor" << endl;
    }
};

int main()
{
    Base* ptr = new Derived();
    delete ptr;

    return 0;
}

Expected Output

Derived destructor
Base destructor

A virtual destructor is important for safe polymorphic cleanup. In production code, prefer automatic resource management such as smart pointers where appropriate.

8.8 Overloading vs Overriding

  • Overloading: Same function name with different parameter lists; resolved during overload resolution.
  • Overriding: A derived class supplies a matching implementation of a base-class virtual function.
  • Overloading does not require inheritance.
  • Overriding requires inheritance and a virtual base-class function for runtime polymorphism.

8.9 Early Binding vs Late Binding

  • Early binding: The function call is selected at compile time, as with ordinary non-virtual calls.
  • Late binding: A virtual call through a base pointer or reference selects the implementation using the object's dynamic type at runtime.

8.10 Advantages of Polymorphism

  • Improves code flexibility and extensibility.
  • Allows different derived classes to share a common interface.
  • Reduces dependence on concrete implementation details.
  • Supports maintainable designs, including device and driver interfaces.
