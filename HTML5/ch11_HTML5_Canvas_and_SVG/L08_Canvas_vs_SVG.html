Lesson 8: Canvas vs SVG

Chapter 11: HTML5 Canvas and SVG

Understand the differences between raster-based Canvas graphics and vector-based SVG graphics.

1. Introduction

HTML5 provides two important technologies for creating graphics directly in web browsers: Canvas and SVG. Both can create shapes, diagrams, illustrations, charts, and interactive visual content.

However, Canvas and SVG use different rendering models and are suitable for different types of applications.

Canvas

HTML5 Canvas is a drawing surface used to render graphics through JavaScript. It uses a pixel-based drawing model.

SVG

Scalable Vector Graphics is an XML-based vector graphics format. SVG represents graphics through individual elements such as circles, rectangles, paths, and text.

Fundamental Difference: Canvas draws graphics onto a pixel-based bitmap surface, whereas SVG represents graphics as individual vector elements in a document structure.

2. What is HTML5 Canvas?

Canvas provides a rectangular drawing area in an HTML document. JavaScript is used to draw shapes, lines, images, text, and other graphics.

Basic Canvas Structure

<canvas id="myCanvas" width="400" height="200"> Your browser does not support Canvas. </canvas> <script> const canvas = document.getElementById("myCanvas"); const ctx = canvas.getContext("2d"); ctx.fillStyle = "blue"; ctx.fillRect(50, 40, 200, 100); </script>

Explanation

  • canvas creates the drawing surface.
  • id identifies the Canvas element.
  • width defines its bitmap width.
  • height defines its bitmap height.
  • getContext("2d") obtains the 2D drawing context.
  • fillStyle defines the fill color.
  • fillRect() draws a filled rectangle.
Expected Result: A blue rectangle appears inside the Canvas drawing area.
Canvas is not supported.

3. What is SVG?

SVG stands for Scalable Vector Graphics. It defines graphical objects using XML-based markup.

SVG graphics are represented by elements such as rect, circle, ellipse, line, polygon, and path.

Basic SVG Structure

<svg width="400" height="200" xmlns="http://www.w3.org/2000/svg"> <rect x="50" y="40" width="200" height="100" fill="blue" /> </svg>

Explanation

  • svg defines the SVG viewport.
  • width and height define its displayed dimensions.
  • rect creates a rectangle.
  • x and y define its position.
  • fill defines the interior color.
Expected Result: A blue rectangle appears inside the SVG viewport.

4. Rendering Model: Canvas vs SVG

4.1 Canvas Rendering Model

Canvas uses an immediate-mode drawing model. JavaScript drawing commands directly modify the bitmap associated with the Canvas element.

Once a shape is drawn, Canvas does not automatically retain it as an independent graphical object. The application must maintain its own information about objects when it needs to update or interact with them.

4.2 SVG Rendering Model

SVG uses a retained-mode graphical model. Individual SVG shapes are represented as elements in the document structure.

Each shape can be selected, styled, modified, or manipulated through JavaScript and CSS.

Canvas is commonly described as immediate-mode rendering, while SVG is commonly described as retained-mode rendering.

6. Pixel-Based Graphics vs Vector Graphics

6.1 Pixel-Based Graphics

Canvas uses a bitmap drawing surface. A bitmap consists of pixels arranged in rows and columns.

Each pixel stores color information. The Canvas bitmap has a defined resolution determined by its intrinsic width and height.

Enlarging a bitmap beyond its original resolution can expose individual pixels and reduce visual quality.

6.2 Vector Graphics

SVG describes shapes using mathematical geometry, coordinates, paths, and curves.

The browser renders these vector descriptions at the required display size. This allows SVG to scale without the same resolution-dependent pixelation associated with bitmap images.

Canvas is not inherently low quality. High-resolution Canvas rendering is possible by using an appropriately sized bitmap and scaling the drawing context.

7. Drawing the Same Shape Using Canvas and SVG

Both technologies can draw the same rectangle. The following examples demonstrate the difference in implementation.

7.1 Rectangle Using Canvas

<canvas id="rectangleCanvas" width="300" height="160"> </canvas> <script> const canvas = document.getElementById("rectangleCanvas"); const ctx = canvas.getContext("2d"); ctx.fillStyle = "orange"; ctx.strokeStyle = "black"; ctx.lineWidth = 3; ctx.fillRect(40, 30, 200, 90); ctx.strokeRect(40, 30, 200, 90); </script>

7.2 Rectangle Using SVG

<svg width="300" height="160" xmlns="http://www.w3.org/2000/svg"> <rect x="40" y="30" width="200" height="90" fill="orange" stroke="black" stroke-width="3" /> </svg>

8. Interactivity: Canvas vs SVG

8.1 Canvas Interactivity

Canvas does not automatically provide separate DOM elements for the shapes drawn on it. To detect which shape the user selects, JavaScript generally handles pointer events and performs hit testing.

<canvas id="interactiveCanvas" width="350" height="160" style="border:1px solid black;"> </canvas> <p id="canvasMessage">Click the rectangle.</p> <script> const canvas = document.getElementById("interactiveCanvas"); const ctx = canvas.getContext("2d"); ctx.fillStyle = "blue"; ctx.fillRect(50, 30, 200, 90); canvas.addEventListener("click", function(event) { const rect = canvas.getBoundingClientRect(); const scaleX = canvas.width / rect.width; const scaleY = canvas.height / rect.height; const x = (event.clientX - rect.left) * scaleX; const y = (event.clientY - rect.top) * scaleY; if (x >= 50 && x <= 250 && y >= 30 && y <= 120) { document.getElementById("canvasMessage") .textContent = "Rectangle selected!"; } else { document.getElementById("canvasMessage") .textContent = "Outside the rectangle."; } }); </script>

The application calculates the pointer position relative to the Canvas bitmap and checks whether the coordinates fall inside the rectangle.

Expected Result: Clicking inside the blue rectangle displays "Rectangle selected!". Clicking outside displays "Outside the rectangle."

Click the blue rectangle.

8.2 SVG Interactivity

SVG shapes can be selected directly using JavaScript because inline SVG elements are part of the document structure.

<svg width="350" height="160" xmlns="http://www.w3.org/2000/svg"> <rect id="myRectangle" x="50" y="30" width="200" height="90" fill="blue" /> </svg> <p id="svgMessage">Click the rectangle.</p> <script> const rectangle = document.getElementById("myRectangle"); rectangle.addEventListener("click", function() { rectangle.setAttribute("fill", "orange"); document.getElementById("svgMessage") .textContent = "Rectangle selected!"; }); </script>
Expected Result: Clicking the SVG rectangle changes its color from blue to orange and displays a message.

Click the blue rectangle.

SVG interactivity is generally more straightforward when individual shapes need separate event handlers. Canvas can also support sophisticated interactivity, but the application must implement the object model and hit testing.

9. Animation: Canvas vs SVG

9.1 Canvas Animation

Canvas animation typically uses JavaScript to update graphical state and redraw the drawing surface repeatedly. The requestAnimationFrame() method is commonly used to schedule animation frames.

const canvas = document.getElementById("myCanvas"); const ctx = canvas.getContext("2d"); let x = 10; function animate() { ctx.clearRect(0, 0, canvas.width, canvas.height); ctx.fillStyle = "red"; ctx.fillRect(x, 50, 50, 50); x += 2; if (x > canvas.width) { x = -50; } requestAnimationFrame(animate); } animate();

9.2 SVG Animation

SVG elements can be animated through CSS animations and JavaScript. SVG also defines declarative animation elements, although support and use cases should be considered when choosing an implementation.

<svg width="350" height="150" xmlns="http://www.w3.org/2000/svg"> <circle cx="50" cy="75" r="25" fill="blue"> <animate attributeName="cx" from="50" to="300" dur="3s" repeatCount="indefinite" /> </circle> </svg>
Both Canvas and SVG can produce animations. The better choice depends on the number of objects, update frequency, interaction requirements, and rendering workload.

10. Performance Considerations

Neither Canvas nor SVG is always faster. Performance depends on the application, browser, hardware, graphical complexity, and implementation.

Canvas Performance

  • Suitable for frequent pixel updates.
  • Useful for rendering large numbers of graphical objects.
  • Does not create a DOM node for every drawn shape.
  • Requires application-level object management for complex interaction.
  • Large bitmap dimensions increase memory consumption.

SVG Performance

  • Suitable for graphics with individually selectable elements.
  • Works naturally with CSS and DOM events.
  • Many complex SVG elements can increase DOM and rendering costs.
  • Vector graphics remain resolution-independent.
  • Efficient for diagrams, icons, maps, and many charts.
Avoid choosing a technology based only on a fixed object-count threshold. Benchmark the actual workload on representative browsers and devices.

11. Advantages of Canvas

  • Suitable for pixel-oriented drawing applications.
  • Useful for games and interactive simulations.
  • Supports image manipulation and pixel processing.
  • Provides a JavaScript-based drawing API.
  • Does not create an individual DOM element for every shape.
  • Can efficiently redraw a frequently changing scene when implemented well.

12. Limitations of Canvas

  • Graphics may become pixelated when enlarged beyond bitmap resolution.
  • Individual drawn shapes are not automatically represented as DOM elements.
  • Hit testing and object management require application logic.
  • Text drawn into Canvas is not naturally exposed as individual document text.
  • Accessibility requires additional design and alternative content.

13. Advantages of SVG

  • Resolution-independent graphics.
  • Scales without bitmap-style pixelation.
  • Individual shapes are represented as elements in inline SVG.
  • Supports CSS styling and JavaScript interaction.
  • Suitable for diagrams, maps, icons, and charts.
  • Supports titles and descriptions for accessibility.
  • Can be searched and inspected as structured markup.

14. Limitations of SVG

  • Very complex graphics can create a large DOM tree.
  • Large numbers of frequently changing SVG elements may become expensive to update.
  • Not designed as a direct replacement for pixel-level image processing.
  • Complex SVG markup can become difficult to maintain.
  • Some external SVG embedding methods limit direct DOM access.

15. Applications of Canvas

  • Browser-based games.
  • Image editing applications.
  • Drawing and painting applications.
  • Real-time data visualization.
  • Physics and engineering simulations.
  • Interactive graphical experiments.
  • Pixel-level image processing.

16. Applications of SVG

  • Website icons and logos.
  • Technical diagrams and circuit illustrations.
  • Geographical maps.
  • Scalable charts and graphs.
  • Flowcharts and block diagrams.
  • Engineering illustrations.
  • Interactive user-interface graphics.

17. Canvas vs SVG: Application Selection

18. Can Canvas and SVG Be Used Together?

Yes. Canvas and SVG can be used together in the same web application. They are complementary technologies.

For example, an engineering application may use:

  • SVG for circuit symbols, labels, and selectable components.
  • Canvas for frequently updated waveforms and signal visualization.
  • HTML for the application layout and controls.
  • CSS for visual styling.
  • JavaScript for application logic and interaction.

Example Application Architecture

Engineering Visualization Application | |-- HTML | |-- Application layout | |-- Controls | |-- CSS | |-- Styling | |-- SVG | |-- Circuit symbols | |-- Component labels | |-- Interactive diagrams | |-- Canvas | |-- Voltage waveforms | |-- Current waveforms | |-- Real-time plots | |-- JavaScript |-- Calculations |-- Event handling |-- Simulation logic
Practical Example: A power electronics simulator could use SVG to draw a rectifier circuit and Canvas to display the changing input and output voltage waveforms.

19. Important Technical Concepts

19.1 Canvas Bitmap Resolution

The width and height HTML attributes of Canvas define its intrinsic bitmap dimensions. CSS width and height control its displayed size.

Changing only its CSS size does not increase the underlying bitmap resolution.

19.2 High-DPI Canvas

High-density displays may require a larger bitmap than the CSS display dimensions to produce sharper graphics.

const canvas = document.getElementById("myCanvas"); const ctx = canvas.getContext("2d"); const dpr = window.devicePixelRatio || 1; const cssWidth = 400; const cssHeight = 200; canvas.style.width = cssWidth + "px"; canvas.style.height = cssHeight + "px"; canvas.width = cssWidth * dpr; canvas.height = cssHeight * dpr; ctx.scale(dpr, dpr); ctx.fillStyle = "blue"; ctx.fillRect(30, 30, 200, 100);

The bitmap resolution is increased according to the device pixel ratio, while drawing coordinates remain expressed in CSS-pixel-sized units after scaling.

19.3 SVG ViewBox

The SVG viewBox defines the coordinate system and visible user-space rectangle mapped into the SVG viewport.

<svg width="400" height="200" viewBox="0 0 200 100" xmlns="http://www.w3.org/2000/svg"> <rect x="10" y="10" width="180" height="80" fill="blue" /> </svg>

In this example, the internal coordinate system is 200 by 100 units, while the displayed viewport is 400 by 200 CSS pixels.

20. Canvas and SVG Accessibility

Canvas Accessibility

  • Provide fallback content inside the canvas element.
  • Provide equivalent text descriptions or data tables.
  • Use accessible HTML controls outside Canvas when appropriate.
  • Do not rely only on color to communicate information.

SVG Accessibility

  • Use title to provide a short accessible name.
  • Use desc to provide a longer description.
  • Use meaningful labels for interactive graphical controls.
  • Ensure sufficient color contrast.

Accessible SVG Example

<svg width="300" height="160" xmlns="http://www.w3.org/2000/svg" role="img" aria-labelledby="diagramTitle diagramDescription"> <title id="diagramTitle"> Voltage Diagram </title> <desc id="diagramDescription"> A blue rectangle representing a voltage source. </desc> <rect x="50" y="30" width="200" height="100" fill="lightblue" stroke="blue" /> </svg>

21. Common Mistakes

  • Confusing Canvas and SVG: Canvas is bitmap-based, while SVG is vector-based.
  • Assuming Canvas shapes are DOM elements: Canvas drawing commands do not create individual DOM nodes for shapes.
  • Assuming SVG always performs better: Performance depends on the workload and implementation.
  • Ignoring Canvas resolution: A low-resolution bitmap can look blurry when enlarged.
  • Ignoring SVG complexity: A large number of SVG elements can increase rendering and DOM costs.
  • Ignoring accessibility: Both technologies need accessibility planning.

22. Lesson Summary

  • Canvas and SVG are two major web graphics technologies.
  • Canvas uses a pixel-based bitmap drawing surface.
  • SVG uses scalable vector graphics.
  • Canvas generally follows an immediate-mode drawing model.
  • SVG generally follows a retained-mode graphical model.
  • Canvas drawing is controlled through JavaScript.
  • SVG graphics are described using markup, CSS, and JavaScript.
  • Canvas is useful for games, simulations, and image processing.
  • SVG is useful for diagrams, maps, logos, and icons.
  • Canvas requires application logic for shape hit testing.
  • SVG elements can receive individual DOM events.
  • Both technologies support animation and interaction.
  • Canvas and SVG can be combined in one application.

24. Interview Questions and Answers

Q1. What is Canvas in HTML5?
Canvas is an HTML element that provides a bitmap drawing surface controlled using JavaScript.
Q2. What is SVG?
SVG stands for Scalable Vector Graphics. It is an XML-based vector graphics format.
Q3. What is the main difference between Canvas and SVG?
Canvas draws into a bitmap, whereas SVG represents graphics as vector elements.
Q4. Is Canvas resolution-independent?
No. Canvas uses a bitmap with intrinsic dimensions. High-resolution rendering is possible by increasing the bitmap resolution appropriately.
Q5. Why is SVG called scalable?
SVG describes vector geometry, allowing the browser to render graphics at different sizes without bitmap-style pixelation.
Q6. What is an immediate-mode drawing model?
It is a drawing model in which drawing commands update the rendering surface directly rather than retaining each shape as an independent DOM object.
Q7. What is a retained-mode graphics model?
It retains graphical objects and their properties as elements that can be independently modified.
Q8. Which technology is suitable for browser-based games?
Canvas is often suitable for games with frequently changing graphical scenes.
Q9. Which technology is suitable for scalable logos?
SVG is generally suitable because it provides resolution-independent vector graphics.
Q10. Can SVG elements receive click events?
Yes. Inline SVG elements can receive standard DOM events such as click, pointerdown, and mouseover.
Q11. How is Canvas interactivity implemented?
JavaScript handles pointer events and performs coordinate calculations and hit testing.
Q12. Can Canvas and SVG be used together?
Yes. An application can use SVG for diagrams and Canvas for frequently updated graphical content.
Q13. What is requestAnimationFrame()?
It schedules an animation callback before the browser's next repaint.
Q14. What is the purpose of SVG viewBox?
It defines the SVG's internal coordinate system and the region mapped into its viewport.
Q15. Which technology is better for an interactive circuit diagram?
SVG is often a good choice because individual components and connections can be selected, styled, and manipulated as elements.
