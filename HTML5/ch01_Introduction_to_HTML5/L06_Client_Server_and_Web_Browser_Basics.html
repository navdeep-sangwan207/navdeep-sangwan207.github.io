2. What is a Client?

A client is a device or software application that requests services or resources from another computer or application.

In web development, a web browser commonly acts as the client.

Examples of Clients

  • Google Chrome
  • Mozilla Firefox
  • Microsoft Edge
  • Apple Safari
  • Mobile web browsers

When a user enters a website address in a browser, the browser sends a request to the appropriate server.

3. What is a Server?

A server is a computer or software application that provides resources or services to clients over a network.

A web server receives HTTP requests and returns appropriate HTTP responses.

Examples of Web Server Software

  • Apache HTTP Server
  • Nginx
  • Microsoft IIS
  • Caddy
Important: A server is not necessarily a special physical computer. Server software can run on a physical machine, virtual machine or cloud infrastructure.

4. What is Client-Server Architecture?

Client-server architecture is a network model in which a client requests services and a server processes those requests and provides responses.

Basic Architecture

CLIENT
Web Browser
↓ HTTP Request
SERVER
Web Server
↑ HTTP Response

The client receives the response and displays the requested web content.

Working Steps

  1. The user opens a web browser.
  2. The user enters a website URL.
  3. The browser identifies the destination server.
  4. The browser sends an HTTP request.
  5. The server processes the request.
  6. The server sends an HTTP response.
  7. The browser processes and displays the response.

5. What is a Web Browser?

A web browser is a software application used to access, retrieve and display web pages and other resources available on the Internet or local networks.

Functions of a Web Browser

  • Accepts website URLs from users.
  • Sends HTTP and HTTPS requests.
  • Receives HTML documents and other resources.
  • Parses HTML and constructs the DOM.
  • Processes CSS and calculates page layout.
  • Executes JavaScript.
  • Displays text, images, audio and video.
  • Manages cookies, cache and browser storage.

Examples of Web Browsers

7. What is a Web Server?

A web server is software that accepts HTTP requests from clients and returns HTTP responses.

Functions of a Web Server

  • Receives requests from web browsers.
  • Serves static files such as HTML, CSS and JavaScript.
  • Can forward requests to application software.
  • Returns images, documents and other resources.
  • Handles connections and HTTP responses.
  • Can provide HTTPS using TLS configuration.

Types of Web Content

Static Content Dynamic Content
Content is served as stored. Content is generated or assembled when requested.
HTML, CSS, images and files. Personalized pages and database-driven results.
Usually requires no application processing. May involve server-side application logic.

8. What is HTTP?

HTTP stands for HyperText Transfer Protocol. It is an application-layer protocol used for communication between web clients and servers.

HTTP follows a request-response model. The client sends a request and the server returns a response.

Common HTTP Methods

Method Purpose
GET Retrieves a resource.
POST Submits data for processing or resource creation.
PUT Creates or replaces a resource at a specified URI.
PATCH Applies a partial modification to a resource.
DELETE Requests deletion of a resource.
HEAD Retrieves response headers without the response body.

9. What is HTTPS?

HTTPS stands for HyperText Transfer Protocol Secure. It is HTTP communication protected using TLS (Transport Layer Security).

TLS helps provide confidentiality, integrity and server authentication.

HTTP HTTPS
Communication is not encrypted by HTTP itself. Communication is protected using TLS.
Common default port: 80. Common default port: 443.
Uses http:// URLs. Uses https:// URLs.
Remember: HTTPS protects data during transport. It does not automatically make a website trustworthy or guarantee that its application is secure.

10. What is a URL?

URL stands for Uniform Resource Locator. It specifies the address used to locate a resource.

Example URL

https://www.example.com:443/courses/html5.html?id=10#lesson

URL Components

Component Example Meaning
Scheme https Communication scheme.
Host www.example.com Server hostname.
Port 443 Network service port.
Path /courses/html5.html Resource path.
Query ?id=10 Additional parameters.
Fragment #lesson Identifies a section within a resource.

11. What is a Domain Name?

A domain name is a human-readable name used to identify an Internet resource.

Examples:

  • google.com
  • microsoft.com
  • github.com
  • example.com

Domain names are easier to remember than numerical IP addresses.

12. What is an IP Address?

An IP address is a numerical identifier assigned to a network interface for communication using the Internet Protocol.

IPv4 Example

192.168.1.10

IPv6 Example

2001:db8::1
IPv4 IPv6
32-bit address. 128-bit address.
Usually written in dotted-decimal format. Written in hexadecimal groups separated by colons.
Example: 192.168.1.10 Example: 2001:db8::1

13. What is DNS?

DNS stands for Domain Name System. It translates domain names into IP addresses and provides other naming-related information.

Example

www.example.com
        |
        | DNS Lookup
        v
93.184.216.34

The address shown is an illustrative example. Actual DNS results can vary.

DNS Resolution Steps

  1. The user enters a domain name.
  2. The browser or operating system checks available caches.
  3. A DNS resolver obtains the required DNS record if needed.
  4. The resolver may contact DNS root, TLD and authoritative servers.
  5. The IP address is returned to the client.
  6. The browser can then connect to the destination server.

14. What Happens When You Enter a URL?

When a user enters a URL into a browser, several operations take place before the web page is displayed.

1. Enter URL
↓
2. DNS Resolution
↓
3. Establish Connection
↓
4. Send HTTP Request
↓
5. Server Processes Request
↓
6. HTTP Response
↓
7. Browser Renders Page

Step-by-Step Explanation

Step 1: User Enters URL

The user enters a website address such as https://example.com.

Step 2: DNS Resolution

The browser uses DNS resolution to obtain the IP address associated with the hostname, if it is not already available in a suitable cache.

Step 3: Establish Connection

The client establishes a connection to the server. HTTP/1.1 and HTTP/2 commonly use TCP, while HTTP/3 uses QUIC over UDP.

For HTTPS, TLS security is established as part of the connection process.

Step 4: Send HTTP Request

The browser sends an HTTP request asking for the required resource.

Step 5: Server Processes Request

The server identifies the requested resource and may retrieve data or execute application logic.

Step 6: Server Sends Response

The server returns an HTTP response containing a status code, headers and, when applicable, a response body.

Step 7: Browser Renders the Page

The browser processes the received HTML, CSS, JavaScript, images and other resources to display the web page.

15. HTTP Request and Response Example

Example HTTP Request

GET /index.html HTTP/1.1
Host: example.com
Accept: text/html

Example HTTP Response

HTTP/1.1 200 OK
Content-Type: text/html

<!DOCTYPE html>
<html>
<body>
    <h1>Welcome</h1>
</body>
</html>

This is a simplified HTTP/1.1 example. Actual browser requests and responses contain additional headers and may use other HTTP versions.

16. Common HTTP Status Codes

Status Code Meaning
200 OK Request succeeded.
201 Created Resource was created successfully.
301 Moved Permanently Resource has a permanent redirect.
302 Found Temporary redirect.
400 Bad Request Server cannot process the request due to a client error.
401 Unauthorized Authentication is required or has failed.
403 Forbidden Server refuses the request.
404 Not Found Requested resource was not found.
500 Internal Server Error Unexpected server-side error.
503 Service Unavailable Server is temporarily unable to handle the request.

17. How Does a Browser Render HTML?

After receiving an HTML document, the browser parses it and constructs an internal representation of the document.

Important Rendering Stages

  1. HTML Parsing: Browser parses HTML and builds the DOM tree.
  2. CSS Processing: Browser parses CSS and builds the CSSOM.
  3. Render Tree: Browser combines relevant DOM and CSS information.
  4. Layout: Browser calculates element positions and dimensions.
  5. Painting: Browser paints visual elements.
  6. Compositing: Browser combines layers to produce the displayed page.
Important Terms:
  • DOM: Document Object Model.
  • CSSOM: CSS Object Model.
  • Render Tree: Information used to determine what is rendered.
  • Layout: Calculation of element geometry.
  • Painting: Drawing visual content.

18. Client-Server vs Peer-to-Peer Architecture

Client-Server Peer-to-Peer
Uses dedicated server roles to provide services. Devices can communicate directly as peers.
Clients request services from servers. Peers can act as both service providers and consumers.
Centralized management is common. Management is often distributed.
Example: A browser accessing a website. Example: A peer-to-peer file-sharing system.

19. Practical Exercises

Exercise 1: Identify Browser Components

Open Chrome or Firefox and identify the address bar, navigation buttons, tabs, menus and developer tools.

Exercise 2: Inspect an HTTP Request

  1. Open a website in Chrome.
  2. Press F12 to open Developer Tools.
  3. Select the Network tab.
  4. Reload the page.
  5. Select a request.
  6. Inspect its request URL, method, status code and response headers.

Exercise 3: Understand DNS

Open Windows Command Prompt and execute:

nslookup example.com

Observe the DNS server and the returned IP address.

Exercise 4: Check Network Connectivity

ping example.com

Observe the response time and packet statistics. Note that some servers block ICMP ping requests.

Exercise 5: Identify IP Configuration

Execute the following Windows command:

ipconfig

Identify the IPv4 address, subnet mask and default gateway of your network interface.

20. Interview Questions and Answers

Q1. What is client-server architecture?

It is a network architecture in which clients request resources or services and servers process those requests and provide responses.

Q2. What is a web browser?

A web browser is software that retrieves, processes and displays web content.

Q3. What is a web server?

A web server is software that accepts HTTP requests and returns HTTP responses.

Q4. What is HTTP?

HTTP is an application-layer protocol used for communication between web clients and servers.

Q5. What is HTTPS?

HTTPS is HTTP communication secured using TLS.

Q6. What is DNS?

DNS translates domain names into IP addresses and provides other domain-related records.

Q7. What is a URL?

A URL identifies the location of a resource and the method or scheme used to access it.

Q8. What is the DOM?

The Document Object Model is a programming interface that represents an HTML document as a tree of objects.

Q9. What is the difference between a browser and a search engine?

A browser is software used to access websites. A search engine is a service used to find information on the web.

Q10. What is the difference between a domain name and an IP address?

A domain name is a human-readable identifier, while an IP address identifies a network interface for IP communication.
