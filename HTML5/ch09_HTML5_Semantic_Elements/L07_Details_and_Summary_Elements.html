Details and Summary Elements

HTML5 – Chapter 9: HTML5 Semantic Elements | Lesson 7

1. Introduction

HTML5 provides two useful elements for creating expandable and collapsible content:

  • <details> – creates a disclosure widget that users can open or close.
  • <summary> – provides the visible heading or label for the details widget.

These elements allow users to show or hide additional information without requiring JavaScript.

Common applications include:

  • Frequently Asked Questions (FAQs)
  • Course descriptions
  • Technical explanations
  • Product specifications
  • Additional instructions
  • Expandable menus of information

2. The details Element

The <details> element creates an interactive disclosure widget. Users can expand it to view hidden content or collapse it to hide that content.

Syntax

<details>
    Hidden content goes here.
</details>

Example

<details>
    <p>
        HTML stands for HyperText Markup Language.
    </p>
</details>

The content is initially collapsed when the details element does not have the open attribute.

The details element provides built-in browser interaction. No JavaScript is required for basic expand and collapse behavior.

3. The summary Element

The <summary> element provides a visible label for the details disclosure widget.

It should be the first child of a details element.

Syntax

<details>

    <summary>What is HTML5?</summary>

    <p>
        HTML5 is the modern version of HTML
        used to structure webpages.
    </p>

</details>

The summary text is displayed even when the details content is collapsed.

5. The open Attribute

The open attribute makes a details element expanded by default when the page loads.

Example: Initially Expanded

<details open>

    <summary>What is CSS?</summary>

    <p>
        CSS is used to style HTML webpages.
    </p>

</details>

Browser Preview

What is CSS?

CSS stands for Cascading Style Sheets. It controls the presentation and layout of webpages.

The open attribute is a Boolean attribute. Its presence means the details widget is initially open. Removing it makes the widget initially closed.

7. Multiple Details Elements

A webpage can contain multiple independent details elements. Each element can be expanded or collapsed separately.

Example

<section>

    <h2>Programming Courses</h2>

    <details>
        <summary>C Programming</summary>
        <p>Learn basic C programming.</p>
    </details>

    <details>
        <summary>C++ Programming</summary>
        <p>Learn object-oriented programming.</p>
    </details>

    <details>
        <summary>Linux Programming</summary>
        <p>Learn Linux commands and scripting.</p>
    </details>

</section>

8. The name Attribute

The name attribute can be used to create an exclusive group of details elements.

When multiple details elements have the same non-empty name value, they behave like an exclusive group in supporting browsers: opening one closes another in that group.

Example

<details name="course-faq">
    <summary>What is HTML?</summary>
    <p>HTML structures webpages.</p>
</details>

<details name="course-faq">
    <summary>What is CSS?</summary>
    <p>CSS styles webpages.</p>
</details>

<details name="course-faq">
    <summary>What is JavaScript?</summary>
    <p>JavaScript adds interactivity.</p>
</details>
All three details elements share the same name. Opening one closes the other members of the group. This is useful for accordion-style interfaces.

9. Styling details and summary Using CSS

CSS can be used to customize the appearance of details and summary elements.

Example CSS

details {
    background: #f5f7fa;
    border: 1px solid #ccc;
    border-radius: 6px;
    padding: 12px;
    margin-bottom: 12px;
}

summary {
    color: #174ea6;
    font-weight: bold;
    cursor: pointer;
}

details[open] {
    border-left: 4px solid #e76f00;
}

details p {
    padding-top: 10px;
}

Important CSS Selectors

Selector Purpose
details Selects all details elements.
summary Selects summary elements.
details[open] Selects details elements that are currently open.
summary:hover Applies styles when the pointer is over summary.
The browser provides the disclosure marker by default. Its appearance can vary between browsers. CSS can customize it when necessary.

10. Difference Between details and summary

details summary
Creates the disclosure widget. Provides the visible label for the widget.
Contains the expandable content. Identifies the content to the user.
Can have the open attribute. Should be the first child of details.
Controls the expanded or collapsed state. Provides the interactive heading.

11. HTML5 details vs JavaScript Accordion

HTML details JavaScript Accordion
Built-in browser interaction. Requires JavaScript for custom interaction.
Simple to implement. Requires additional scripting.
Provides native disclosure behavior. Behavior depends on implementation.
Suitable for FAQs and basic expandable content. Suitable for complex custom interactions.
Details is not a complete replacement for every accordion design. Complex interfaces may require additional HTML, CSS and JavaScript.

12. Accessibility and Best Practices

  • Use summary as the first child of details.
  • Write clear and descriptive summary text.
  • Keep expandable content relevant to its summary.
  • Use native details behavior instead of unnecessary JavaScript.
  • Do not use details when the content must always remain visible.
  • Ensure custom CSS preserves a visible indication of the disclosure state.
  • Test keyboard interaction and screen-reader behavior.
  • Use the name attribute when an exclusive group is appropriate.

13. Common Mistakes

  1. Using summary outside a details element.
  2. Placing summary after other content inside details.
  3. Assuming details requires JavaScript to open and close.
  4. Using unclear summary text.
  5. Assuming every details element must be closed initially.
  6. Using the same name attribute unintentionally on unrelated details elements.
  7. Removing visual disclosure indicators without providing an alternative.
  8. Using details for content that should always be visible.
