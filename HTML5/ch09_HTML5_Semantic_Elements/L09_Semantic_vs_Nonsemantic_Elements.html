Semantic vs Non-Semantic Elements

HTML5 – Chapter 9: HTML5 Semantic Elements | Lesson 9

1. Introduction

HTML elements can be classified according to whether they communicate the meaning or purpose of their content.

Two important categories are:

  • Semantic elements: Elements that convey meaningful information about the structure or purpose of their content.
  • Non-semantic elements: Generic elements that do not describe the meaning of their content by themselves.

Semantic HTML helps browsers, developers, search engines and assistive technologies understand webpage structure.

2. What Are Semantic Elements?

Semantic HTML elements clearly describe the purpose or role of the content they contain.

Common Semantic Elements

Element Purpose
<header> Introductory content or a header for a page or section.
<nav> Major navigation section.
<main> Dominant content of the document.
<section> Thematic grouping of content.
<article> Independent, self-contained composition.
<aside> Supplementary content.
<footer> Footer for a page or section.
<figure> Self-contained content such as an illustration or diagram.
<figcaption> Caption for a figure.
<details> Expandable disclosure widget.
<summary> Visible label for a details element.

3. What Are Non-Semantic Elements?

Non-semantic elements do not communicate a specific content role by themselves.

They are mainly used as generic containers for grouping, styling and scripting.

Common Non-Semantic Elements

Element Purpose
<div> Generic container for grouping flow content.
<span> Generic inline container.

Example

<div class="course-card">
    <h2>HTML5 Course</h2>
    <p>Learn HTML5 concepts.</p>
</div>

<p>
    Course Level:
    <span class="level">Beginner</span>
</p>

The div groups the course card, while span identifies the word Beginner. Neither element describes the content's semantic purpose by itself.

4. Semantic vs Non-Semantic Elements

Feature Semantic Elements Non-Semantic Elements
Meaning Communicate a defined content role. Do not define a specific content role.
Purpose Describe document structure and content. Group content generically.
Examples main, article, nav, section. div, span.
Accessibility Can expose useful semantic information and landmarks. Do not provide a specific semantic role by default.
Search engines Help clarify document structure. Provide no specific content meaning by themselves.
Styling Can be styled using CSS. Can be styled using CSS.

5. Example: Non-Semantic HTML Structure

A webpage can be built entirely with generic div elements. However, the HTML does not clearly describe the purpose of each major content area.

HTML Code

<div class="header">
    <h1>My Learning Portal</h1>
</div>

<div class="navigation">
    <a href="#home">Home</a>
    <a href="#courses">Courses</a>
</div>

<div class="main-content">

    <div class="article">
        <h2>HTML5 Course</h2>
        <p>Learn HTML5.</p>
    </div>

    <div class="sidebar">
        <h3>Related Courses</h3>
    </div>

</div>

<div class="footer">
    <p>Copyright 2026</p>
</div>
This structure can still be displayed and styled correctly. The limitation is that the generic div elements do not communicate the intended page structure.

6. Example: Semantic HTML Structure

Semantic elements describe the role of different webpage areas directly in the HTML.

HTML Code

<header>
    <h1>My Learning Portal</h1>
</header>

<nav aria-label="Main navigation">
    <a href="#home">Home</a>
    <a href="#courses">Courses</a>
</nav>

<main id="home">

    <article id="courses">
        <h2>HTML5 Course</h2>
        <p>Learn HTML5.</p>
    </article>

    <aside aria-label="Related courses">
        <h3>Related Courses</h3>
    </aside>

</main>

<footer>
    <p>Copyright 2026</p>
</footer>

Browser Preview

HEADER

My Learning Portal

NAVIGATION

Home | Courses | Projects

MAIN CONTENT
ARTICLE

HTML5 Course – Learn HTML5.

SECTION

Course topics and lessons.

ASIDE

Related courses and resources.

FOOTER

Copyright 2026

7. Accessibility Benefits

Semantic HTML provides meaningful information about document structure. Assistive technologies such as screen readers can use this information to help users navigate webpages.

Important Benefits

  • Provides meaningful document structure.
  • Helps screen-reader users navigate page landmarks.
  • Improves understanding of content relationships.
  • Reduces the need for unnecessary ARIA roles.
  • Helps developers maintain accessible HTML.

Example: Navigation Landmark

<nav aria-label="Main navigation">
    <a href="index.html">Home</a>
    <a href="courses.html">Courses</a>
    <a href="contact.html">Contact</a>
</nav>
Native semantic HTML should generally be preferred over adding ARIA roles to generic elements when an appropriate HTML element already exists.

8. SEO Benefits of Semantic HTML

Semantic elements help search engines interpret the structure and organization of webpage content.

Important Practices

  • Use appropriate heading elements to organize topics.
  • Use main for the primary page content.
  • Use article for independent compositions.
  • Use nav for major navigation sections.
  • Use descriptive link text.
  • Provide meaningful alternative text for informative images.
  • Write useful and relevant content.
Semantic HTML alone does not guarantee better search rankings. SEO depends on many factors, including content quality, accessibility, performance, metadata and technical structure.

9. Semantic Elements and Accessibility Roles

Some semantic HTML elements expose implicit accessibility roles to assistive technologies.

HTML Element Typical Accessibility Role
<main> main
<nav> navigation
<header> banner in appropriate page-level context
<footer> contentinfo in appropriate page-level context
<aside> complementary in appropriate context
<article> article

The exact exposed role can depend on the element's context and accessibility mapping.

10. When to Use Semantic and Non-Semantic Elements

Use Semantic Elements When:

  • You are creating the main content area.
  • You are grouping related topics into a section.
  • You are creating an independent article.
  • You are defining major website navigation.
  • You are creating headers and footers.
  • You are representing supplementary information.

Use Non-Semantic Elements When:

  • You need a generic layout container.
  • You need to group content for CSS styling.
  • You need an inline wrapper for a specific word or phrase.
  • No suitable semantic element describes the content.
A good HTML document uses semantic elements for meaningful structure and div or span for generic grouping where needed.

11. Complete Practical Example

The following example combines semantic and non-semantic elements in one webpage. 

<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Learning Portal</title>

    <style>
        .course-card {
            background: #eaf3ff;
            padding: 15px;
            margin: 10px 0;
            border-radius: 6px;
        }

        .level {
            color: green;
            font-weight: bold;
        }
    </style>
</head>

<body>

    <header>
        <h1>NS Learning Hub</h1>
    </header>

    <nav aria-label="Main navigation">
        <a href="#home">Home</a>
        <a href="#courses">Courses</a>
    </nav>

    <main id="home">

        <section id="courses">
            <h2>Available Courses</h2>

            <div class="course-card">
                <h3>HTML5</h3>
                <p>
                    Level:
                    <span class="level">Beginner</span>
                </p>
            </div>

            <div class="course-card">
                <h3>Linux</h3>
                <p>
                    Level:
                    <span class="level">Intermediate</span>
                </p>
            </div>

        </section>

        <aside aria-label="Additional resources">
            <h2>Additional Resources</h2>
            <p>Explore programming tutorials.</p>
        </aside>

    </main>

    <footer>
        <p>NS Learning Hub</p>
    </footer>

</body>
</html>

In this example:

  • header, nav, main, section, aside and footer provide semantic structure.
  • div groups each course card.
  • span identifies the course level text.

12. Common Mistakes

  1. Using div for every webpage section.
  2. Confusing visual appearance with semantic meaning.
  3. Assuming semantic elements automatically improve search rankings.
  4. Using section only for CSS styling when div is more appropriate.
  5. Using article for content that is not an independent composition.
  6. Using nav for every group of links rather than major navigation sections.
  7. Adding unnecessary ARIA roles to native semantic elements.
  8. Ignoring proper heading hierarchy and document structure.

14. Interview Questions and Answers

Q1. What are semantic HTML elements?

They are elements that communicate the purpose or role of their content.

Q2. What are non-semantic HTML elements?

They are generic elements that do not describe the specific meaning of their content.

Q3. Give examples of semantic elements.

header, nav, main, section, article, aside and footer.

Q4. Give examples of non-semantic elements.

div and span.

Q5. What is the main benefit of semantic HTML?

It provides meaningful structure that helps developers, browsers and assistive technologies understand webpage content.

Q6. Does div have semantic meaning?

No. Div is a generic container.

Q7. Which element represents the primary content of a webpage?

The main element.

Q8. How does semantic HTML help accessibility?

It provides meaningful structure and native landmarks that assistive technologies can expose to users.

Q9. Does semantic HTML guarantee higher SEO rankings?

No. It helps clarify document structure, but rankings depend on many factors.

Q10. Should developers completely avoid div and span?

No. They are useful generic containers when no appropriate semantic element describes the content.
