Lesson 1: Introduction to Web Accessibility

Chapter 14: HTML Accessibility

Understand web accessibility, inclusive design, accessibility barriers, assistive technologies and the principles used to make websites accessible.

1. What is Web Accessibility?

Web accessibility is the practice of designing and developing websites, web applications and digital content so that people with different abilities can perceive, understand, navigate and interact with them.

An accessible website should support people who use different devices and interaction methods, including keyboards, screen readers, voice input and magnification tools.

Example

Consider an image that displays a warning symbol. A person who cannot see the image should still be able to understand its meaning through appropriate alternative text.

<img src="warning.png" alt="Warning: High voltage">

A screen reader can use the alternative text to communicate the image's meaning.

Accessibility is not limited to people with permanent disabilities. It can also help users with temporary limitations, situational difficulties and different ways of accessing information.

2. Why is Web Accessibility Important?

Websites are used by people with different physical, sensory and cognitive abilities. Accessibility helps ensure that digital services are usable by a wider range of people.

Major Benefits

  • Inclusive access: More people can use websites and online services.
  • Better usability: Clear structures and controls help all users.
  • Keyboard support: Users can navigate without a mouse.
  • Screen reader support: Content can be interpreted by assistive technology.
  • Mobile usability: Well-structured pages are easier to navigate on smaller screens.
  • Improved content structure: Semantic HTML makes information easier to understand.
  • Legal and policy compliance: Accessibility may be required by applicable laws, regulations or organizational policies.

3. Understanding Different Accessibility Needs

Accessibility considerations include different types of disabilities and situations that can affect how people use websites.

Accessibility Need Possible Barrier Helpful Solution
Visual Images without descriptions or low contrast Alt text, sufficient contrast and screen reader support
Hearing Audio or video without captions Captions and transcripts
Motor Controls requiring precise mouse movement Keyboard navigation and large interactive targets
Cognitive Complex instructions and confusing layouts Clear language and consistent page structure
Speech Interfaces requiring voice communication Alternative input methods and non-voice interaction
These categories are useful for understanding common accessibility barriers. Individual needs vary, so websites should support multiple ways of accessing and interacting with content.

4. Types of Accessibility Barriers

4.1 Visual Barriers

Visual barriers affect users who have difficulty seeing content or distinguishing visual information.

Examples:

  • Images without meaningful alternative text.
  • Text with insufficient color contrast.
  • Information communicated only through color.
  • Small text without suitable zoom support.

4.2 Hearing Barriers

Hearing barriers occur when important information is available only through sound.

Examples:

  • Videos without captions.
  • Audio instructions without transcripts.
  • Notifications communicated only through sound.

4.3 Motor Barriers

Motor barriers can make it difficult to use a mouse, touch screen or other pointing device.

Examples:

  • Buttons that cannot receive keyboard focus.
  • Menus that require mouse hover only.
  • Controls requiring precise pointer movement.

4.4 Cognitive Barriers

Cognitive barriers can make complex or confusing information difficult to understand.

Examples:

  • Unclear instructions.
  • Inconsistent navigation.
  • Unexpected page behavior.
  • Long, complicated forms.

5. Assistive Technologies

Assistive technologies are tools and software that help people interact with computers and digital content.

5.1 Screen Readers

A screen reader reads or communicates information from a web page using synthesized speech or other output methods such as braille displays.

Examples:

  • NVDA
  • JAWS
  • VoiceOver
  • TalkBack

5.2 Screen Magnifiers

Screen magnification tools enlarge parts of the screen to make content easier to see.

5.3 Speech Recognition Software

Speech recognition tools allow users to control a computer and interact with applications through voice commands.

5.4 Alternative Input Devices

Some users interact with computers through specialized keyboards, switches, eye-tracking systems or other input devices.

Accessible HTML provides meaningful information and interaction semantics that assistive technologies can interpret.

6. The Four Principles of Web Accessibility (POUR)

The Web Content Accessibility Guidelines (WCAG) organize accessibility around four fundamental principles: Perceivable, Operable, Understandable and Robust.

6.1 Perceivable

Information and user interface components must be presented in ways users can perceive.

Examples:

  • Provide alternative text for meaningful images.
  • Provide captions for videos with speech.
  • Ensure sufficient text contrast.
  • Do not communicate information using color alone.

6.2 Operable

User interface components and navigation must be operable by users.

Examples:

  • Support keyboard navigation.
  • Provide visible keyboard focus.
  • Avoid keyboard traps.
  • Give users enough time to complete tasks.

6.3 Understandable

Information and interface operation must be understandable.

Examples:

  • Use clear and simple instructions.
  • Keep navigation consistent.
  • Provide understandable form labels.
  • Explain input errors clearly.

6.4 Robust

Content must be robust enough to work with different browsers, user agents and assistive technologies.

Examples:

  • Use valid and well-structured HTML.
  • Use semantic elements correctly.
  • Provide appropriate accessible names and roles.
  • Avoid unnecessary or incorrect ARIA attributes.
POUR Summary:
  • P – Perceivable
  • O – Operable
  • U – Understandable
  • R – Robust

7. Introduction to WCAG

WCAG stands for Web Content Accessibility Guidelines. It is a set of internationally recognized guidelines developed by the World Wide Web Consortium (W3C) through its Web Accessibility Initiative (WAI).

WCAG provides recommendations for making web content more accessible to people with disabilities.

WCAG Conformance Levels

Level Description
A Basic accessibility requirements.
AA Addresses a broader range of accessibility needs and is a common target for organizational conformance.
AAA More extensive and demanding accessibility criteria.

WCAG Versions

  • WCAG 2.0
  • WCAG 2.1
  • WCAG 2.2

WCAG 2.2 extends the WCAG 2.1 requirements with additional success criteria.

WCAG conformance levels describe how well a website meets the guidelines. They are not separate technologies or HTML versions.

8. Introduction to Accessible HTML

HTML provides built-in elements and attributes that help developers create accessible content.

8.1 Semantic Elements

Semantic elements describe the meaning and purpose of page content.

<header> <h1>My Learning Portal</h1> </header> <nav aria-label="Main navigation"> <a href="index.html">Home</a> <a href="courses.html">Courses</a> </nav> <main> <h2>Available Courses</h2> <p>Explore our learning materials.</p> </main> <footer> <p>Learning Portal</p> </footer>

8.2 Alternative Text

<img src="circuit-diagram.png" alt="Circuit diagram showing a voltage regulator">

8.3 Form Labels

<label for="email"> Email Address: </label> <input type="email" id="email" name="email">

8.4 Keyboard-Friendly Controls

<button type="button"> Submit </button> <a href="courses.html"> View Courses </a>
Native HTML buttons and links already provide keyboard interaction. Prefer these elements over clickable div elements when building interactive controls.

9. Accessible vs Inaccessible HTML

Example 1: Image Accessibility

Inaccessible example:

<img src="logo.png">

Improved example:

<img src="logo.png" alt="NS Learning Hub logo">

Example 2: Form Accessibility

Inaccessible example:

<input type="text" placeholder="Enter your name">

Improved example:

<label for="username"> Enter your name: </label> <input type="text" id="username" name="username">

Example 3: Navigation Accessibility

Improved semantic structure:

<nav aria-label="Main navigation"> <ul> <li><a href="index.html">Home</a></li> <li><a href="about.html">About</a></li> <li><a href="courses.html">Courses</a></li> </ul> </nav>

10. Accessibility Testing Tools

Accessibility testing helps identify problems that may prevent users from accessing or interacting with web content.

Tool or Method Purpose
WAVE Identifies common accessibility issues on web pages.
axe DevTools Helps detect accessibility problems in web interfaces.
Lighthouse Provides automated accessibility audits and other page audits.
NVDA Screen reader testing on supported desktop environments.
Keyboard testing Checks whether users can operate controls without a mouse.
Browser zoom Checks whether content remains usable when enlarged.
Automated tools cannot identify every accessibility problem. Manual keyboard testing and testing with assistive technologies are also important.

11. Common Accessibility Mistakes

Mistake Improvement
Images without appropriate alt text Provide meaningful alternative text when needed.
Using headings only for visual size Use headings to represent document structure.
Forms without labels Associate labels with their controls.
Keyboard-inaccessible controls Use native interactive HTML elements.
Low text contrast Use sufficient foreground and background contrast.
Unclear link text Use descriptive link names.
Using ARIA unnecessarily Prefer native HTML semantics.
Testing only with a mouse Test keyboard and assistive technology access.

13. Interview Questions and Answers

Q1. What is web accessibility?
Web accessibility is the practice of making websites and web applications usable by people with different abilities.
Q2. Why is web accessibility important?
It improves inclusive access, usability and compatibility with assistive technologies.
Q3. What is WCAG?
WCAG stands for Web Content Accessibility Guidelines. It provides recommendations for accessible web content.
Q4. What does POUR stand for?
Perceivable, Operable, Understandable and Robust.
Q5. What is a screen reader?
A screen reader is assistive software that communicates screen content through synthesized speech or braille output.
Q6. What is alternative text?
Alternative text is a textual description provided through the alt attribute of an image element.
Q7. What are semantic HTML elements?
Semantic elements describe the meaning and purpose of content, such as header, nav, main, article and footer.
Q8. What are the three WCAG conformance levels?
Level A, Level AA and Level AAA.
Q9. What is keyboard accessibility?
It means users can navigate and operate website controls using a keyboard without depending on a mouse.
Q10. What is ARIA?
ARIA stands for Accessible Rich Internet Applications. It provides attributes that communicate roles, states and properties to assistive technologies.
Q11. What is the purpose of the label element?
It provides a label for a form control and helps communicate the control's purpose to users and assistive technology.
Q12. Name some accessibility testing tools.
WAVE, axe DevTools, Lighthouse and screen readers such as NVDA.
Q13. What is inclusive design?
Inclusive design considers different user needs and abilities when designing products and experiences.
Q14. Does automated accessibility testing find every issue?
No. Automated tools detect many common issues, but manual testing is also necessary.
Q15. What is the relationship between HTML and accessibility?
Correct semantic HTML provides structure, names and interaction behavior that help browsers and assistive technologies interpret web content.
