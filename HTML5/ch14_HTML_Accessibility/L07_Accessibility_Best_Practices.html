Lesson 7: Accessibility Best Practices

Chapter 14: HTML Accessibility

Learn practical accessibility guidelines, testing methods, common mistakes and techniques for developing inclusive, accessible and user-friendly websites.

1. Introduction to Accessibility Best Practices

Web accessibility means designing and developing websites so that people with different abilities can perceive, understand, navigate and interact with web content.

Accessibility should be considered throughout the development process rather than added only after a website has been completed.

Why Are Accessibility Best Practices Important?

  • Make websites usable by people with disabilities.
  • Improve keyboard navigation.
  • Support screen readers and assistive technologies.
  • Improve content structure and readability.
  • Provide better usability across different devices.
  • Help organizations meet accessibility requirements.
  • Improve the overall user experience.
Accessibility is not only about screen readers. It also includes keyboard users, users with low vision, users with hearing impairments and people with temporary or situational limitations.

2. Follow the POUR Principles

The Web Content Accessibility Guidelines (WCAG) organize accessibility requirements around four fundamental principles called POUR.

Four Principles of Accessibility

Principle Meaning Example
Perceivable Information must be available to users in ways they can perceive. Provide alternative text for meaningful images.
Operable Interface components must be usable through available interaction methods. Support keyboard navigation.
Understandable Information and operation of the interface must be understandable. Use clear instructions and labels.
Robust Content must work reliably with different browsers and assistive technologies. Use valid, semantic HTML.

Example: Applying POUR

<main> <h1>Electronics Learning Course</h1> <img src="circuit.png" alt="Basic electronic circuit diagram"> <p> Learn electronic circuits step by step. </p> <a href="courses.html"> Explore Courses </a> </main>
  • Perceivable: The image has alternative text.
  • Operable: The link can be accessed using a keyboard.
  • Understandable: The heading and link text are descriptive.
  • Robust: Semantic HTML elements are used.

3. Use Semantic HTML

Semantic HTML elements communicate the meaning and structure of web content to browsers, assistive technologies and developers.

Important Semantic Elements

Element Purpose
<header> Introductory content or page-level header.
<nav> Navigation links.
<main> Main content of the document.
<section> Thematic grouping of content.
<article> Self-contained content.
<aside> Supporting or complementary content.
<footer> Footer information.
<button> Interactive button control.

Good Practice

<header> <h1>NS Learning Hub</h1> </header> <nav aria-label="Main navigation"> <a href="index.html">Home</a> <a href="courses.html">Courses</a> </nav> <main> <section> <h2>Available Courses</h2> <p>Explore technical courses.</p> </section> </main> <footer> <p>Learning Portal</p> </footer>
Avoid using generic div elements for every part of a page when a meaningful semantic element is available.

4. Maintain Proper Heading Structure

Headings organize content into a meaningful hierarchy. Screen reader users can use headings to understand the page structure and navigate directly to sections.

Heading Elements

  • <h1> – Main heading.
  • <h2> – Major section heading.
  • <h3> – Subsection heading.
  • <h4> – Lower-level heading.
  • <h5> – Further subsection.
  • <h6> – Lowest heading level.

Correct Heading Structure

<h1>HTML Accessibility</h1> <h2>Semantic HTML</h2> <h3>Semantic Elements</h3> <h3>Document Structure</h3> <h2>Keyboard Accessibility</h2> <h3>Keyboard Navigation</h3>
Do not choose heading levels only for their visual size. Use CSS to change appearance. Avoid unnecessary jumps in heading hierarchy. A document is not invalid merely because it contains more than one h1 element.

5. Provide Alternative Text for Images

Alternative text describes the purpose or meaningful content of an image for users who cannot see it.

Informative Image

<img src="solar-panel.jpg" alt="Solar panels installed on a rooftop">

Decorative Image

<img src="decoration.png" alt="">

Functional Image

<a href="courses.html"> <img src="course-icon.png" alt="Explore courses"> </a>

Complex Image

<figure> <img src="voltage-chart.png" alt="Voltage increases linearly over time"> <figcaption> The graph shows voltage rising from 0 V to 12 V over 6 seconds. </figcaption> </figure>
Every img element should have an alt attribute. Use meaningful text for informative images and alt="" for decorative images. Do not use filenames or unnecessary phrases such as "image of" in alternative text.

6. Ensure Keyboard Accessibility

Many users navigate websites without a mouse. They may use a keyboard, switch device, voice control or another alternative input method.

Important Keyboard Keys

Key Typical Function
Tab Moves focus to the next focusable element.
Shift + Tab Moves focus to the previous focusable element.
Enter Activates links and buttons in their usual interaction patterns.
Space Activates buttons and toggles supported controls.
Arrow Keys Navigate within many composite widgets and controls.
Escape Often closes dialogs, menus or popups when supported.

Use Native Interactive Elements

<button type="button"> Open Settings </button> <a href="courses.html"> View Courses </a> <input type="text" name="username" aria-label="Username">

Visible Focus Indicator

:focus-visible { outline: 3px solid #e76f00; outline-offset: 3px; }
Never remove keyboard focus indicators without providing a visible alternative. Do not create positive tabindex values to force a custom focus order.

7. Use Sufficient Color Contrast

Color contrast is the difference in brightness between foreground content and its background. Sufficient contrast helps users read text and identify interface elements.

WCAG Contrast Requirements

Content Minimum Contrast Ratio (AA)
Normal text 4.5:1
Large text 3:1
Meaningful graphical objects and UI components 3:1

Large text generally means at least 18 pt (24 CSS pixels) or 14 pt (approximately 18.67 CSS pixels) when bold.

Example: Good Contrast

body { background-color: #ffffff; color: #222222; } button { background-color: #174ea6; color: #ffffff; }

Example: Poor Practice

/* Avoid relying on very light text against a light background. */ p { color: #dddddd; background-color: #ffffff; }
Do not communicate information using color alone. For example, identify errors using text or icons in addition to a red color indicator.

8. Create Accessible Forms

Forms should provide clear labels, instructions, appropriate input types and understandable error messages.

Best Practices

  • Associate each form control with a label.
  • Use fieldset and legend for related controls.
  • Provide clear instructions.
  • Identify required fields visibly and programmatically.
  • Provide useful error messages.
  • Do not rely only on placeholder text.
  • Preserve entered data when validation fails where possible.

Example

<form action="/register" method="post"> <label for="email"> Email Address: </label> <input type="email" id="email" name="email" required aria-describedby="email-help"> <p id="email-help"> Enter a valid email address. </p> <button type="submit"> Register </button> </form>
This form demonstrates markup only. A real application must also provide server-side validation and a working submission endpoint.

9. Make Links and Buttons Descriptive

Link and button text should clearly communicate the destination or action.

Good Link Text

<a href="html5/index.html"> Explore the HTML5 Course </a>

Avoid Unclear Link Text

<a href="html5/index.html"> Click Here </a>

Good Button Text

<button type="submit"> Submit Registration </button>

Descriptive names help screen reader users understand the purpose of controls.

10. Provide Captions and Transcripts

Audio and video content should be made accessible to people who cannot hear or understand the audio.

Captions

Captions include spoken dialogue and relevant non-speech audio information.

Example: Video with Captions

<video controls width="600"> <source src="lesson.mp4" type="video/mp4"> <track src="captions.vtt" kind="captions" srclang="en" label="English" default> Your browser does not support HTML video. </video>

Transcript

A transcript provides the textual content of audio or video. It is especially useful for users who prefer reading or cannot access the audio.

Captions and transcripts serve different purposes. Captions are synchronized with media playback, while transcripts provide a separate text version. Audio description may also be needed when important visual information is not conveyed through the soundtrack.

11. Make Tables Accessible

HTML tables should represent tabular data. Correct table structure helps assistive technologies communicate relationships between headers and data cells.

Accessible Table Example

<table> <caption> Electronics Course Modules </caption> <thead> <tr> <th scope="col">Module</th> <th scope="col">Duration</th> </tr> </thead> <tbody> <tr> <th scope="row">HTML5</th> <td>4 Weeks</td> </tr> <tr> <th scope="row">CSS3</th> <td>3 Weeks</td> </tr> </tbody> </table>
  • Use caption to describe the table.
  • Use th for header cells.
  • Use scope to identify row or column headers.
  • Use thead, tbody and tfoot where appropriate.
  • Use id and headers for complex header relationships.

12. Use ARIA Carefully

ARIA adds accessibility information when native HTML semantics are insufficient. Incorrect ARIA can make a page less accessible.

Best Practices

  • Prefer native HTML elements.
  • Use ARIA roles only when necessary.
  • Provide accessible names for controls.
  • Keep ARIA states synchronized with the interface.
  • Do not hide focusable elements from assistive technologies.
  • Implement keyboard interaction for custom widgets.
  • Test with screen readers and browsers.

Example

<button type="button" aria-expanded="false" aria-controls="info"> Show Information </button> <div id="info" hidden> Additional information. </div>
The button's aria-expanded value must be updated when the panel opens or closes. ARIA attributes should describe the actual interface state, not a state that developers intend to implement later.

13. Set the Document Language

The lang attribute identifies the primary language of a document. Screen readers can use it to select appropriate pronunciation and language rules.

Example

<html lang="en">

For a Hindi-language document:

<html lang="hi">

For content in another language within an English page, identify the language of that specific passage.

<p> Welcome to our learning portal. <span lang="hi"> नमस्ते </span> </p>
Set the correct language on the html element and identify language changes within content when needed.

14. Make Websites Responsive and Zoom-Friendly

Accessible websites should work across different screen sizes, orientations and zoom levels.

Viewport Configuration

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Responsive Layout Example

.container { width: 90%; max-width: 1100px; margin: auto; } img { max-width: 100%; height: auto; } @media (max-width: 600px) { .container { width: 100%; } }

Content should reflow without unnecessary horizontal scrolling for ordinary text at narrow viewport widths, subject to WCAG exceptions for content that requires two-dimensional layout.

15. Avoid Accessibility Barriers

Accessibility Barrier Better Practice
Images without alternative text. Provide appropriate alt text.
Forms without labels. Use associated label elements.
Mouse-only interaction. Support keyboard operation.
Low color contrast. Meet applicable contrast requirements.
Unclear link names. Use descriptive link text.
Videos without captions. Provide synchronized captions.
Missing document language. Set the lang attribute.
Improper heading hierarchy. Organize headings logically.
Unexpected keyboard focus movement. Maintain predictable focus behavior.
Automatic movement without controls. Allow users to pause, stop or hide qualifying moving content.

16. Accessibility Testing Tools

Accessibility testing helps identify problems before a website is released. Testing should combine automated checks and manual evaluation.

Common Tools

Tool Purpose
WAVE Identifies many accessibility issues in web pages.
axe DevTools Automated accessibility testing and developer guidance.
Lighthouse Includes accessibility audits in browser developer tools.
NVDA Screen reader for Windows.
JAWS Screen reader for Windows.
VoiceOver Screen reader for Apple devices.
TalkBack Screen reader for Android.
Browser Accessibility Inspector Inspects accessible names, roles, states and relationships.

Manual Testing Checklist

  1. Navigate the entire page using only the keyboard.
  2. Check the visible focus indicator.
  3. Verify all images have appropriate alt attributes.
  4. Check form labels and error messages.
  5. Inspect heading hierarchy.
  6. Check text and interface contrast.
  7. Test the page with a screen reader.
  8. Zoom the page and check for content loss.
  9. Check captions and media alternatives.
  10. Verify that interactive controls work correctly.
Automated testing does not prove that a website is fully accessible. Human evaluation is necessary to assess usability, context and interaction.

17. WCAG Accessibility Standards

WCAG stands for Web Content Accessibility Guidelines. It provides internationally recognized recommendations for making web content more accessible.

WCAG Conformance Levels

Level Description
A Basic accessibility requirements.
AA Addresses a broader range of accessibility barriers and is a common target for organizations.
AAA More extensive accessibility requirements; not achievable or appropriate for every type of content.

Important WCAG Versions

  • WCAG 2.0 – Published in 2008.
  • WCAG 2.1 – Published in 2018.
  • WCAG 2.2 – Published in 2023.

WCAG 2.2 extends WCAG 2.1 and retains its conformance model. Organizations should identify the applicable standard and version required by their project or regulations.

The following example combines several accessibility practices into one HTML page.

Expected Result

  • A semantic web page with header, navigation, main and footer.
  • A meaningful page title and document language.
  • Descriptive alternative text for the image.

19. Accessibility Project Checklist

Use this checklist when reviewing a website or completing an accessibility project.

  • Use a meaningful page title.
  • Set the correct document language.
  • Use semantic HTML elements.
  • Maintain a logical heading structure.
  • Provide alternative text for images.
  • Provide labels for all form controls.
  • Ensure keyboard navigation works.
  • Show a visible focus indicator.
  • Maintain sufficient color contrast.
  • Use descriptive link and button text.
  • Provide captions and transcripts where required.
  • Use ARIA only when necessary.
  • Keep dynamic accessibility states accurate.
  • Test at different screen sizes and zoom levels.
  • Perform automated and manual accessibility testing.

21. Interview Questions and Answers

Q1. What is web accessibility?
Web accessibility means designing websites so that people with different abilities can use web content and functionality.
Q2. What are the four POUR principles?
Perceivable, Operable, Understandable and Robust.
Q3. What is semantic HTML?
Semantic HTML uses elements that describe the meaning and structure of web content.
Q4. Why is alternative text important?
It communicates meaningful image content to users who cannot see the image.
Q5. What is keyboard accessibility?
It means users can navigate and operate the interface using a keyboard without depending on a mouse.
Q6. What is WCAG?
WCAG is a set of international guidelines for making web content more accessible.
Q7. What are WCAG conformance levels?
Level A, Level AA and Level AAA.
Q8. What is a screen reader?
A screen reader is assistive technology that communicates digital content through speech or other output.
Q9. What is color contrast?
Color contrast is the difference in relative luminance between foreground and background colors.
Q10. What is the minimum WCAG AA contrast ratio for normal text?
4.5:1.
Q11. Why should forms have labels?
Labels identify form controls and communicate their purpose to users and assistive technologies.
Q12. What is the purpose of captions?
Captions provide synchronized text for spoken dialogue and relevant non-speech audio information.
Q13. What is the purpose of the lang attribute?
It identifies the language of document content so browsers and assistive technologies can process it appropriately.
Q14. Name some accessibility testing tools.
WAVE, axe DevTools, Lighthouse, NVDA, JAWS and VoiceOver.
Q15. Is automated accessibility testing sufficient?
No. Automated tools should be combined with manual keyboard, screen reader and usability testing.
