Lesson 2: Web Storage Introduction

Chapter 12: HTML5 APIs and Browser Features

Learn how web applications store and retrieve information inside a browser.

1. Introduction to Web Storage

Web applications often need to remember information between user interactions or page visits.

For example, an online learning portal may need to remember a user's theme preference, selected course, or temporary application settings.

Web Storage is a browser feature that allows JavaScript applications to store key-value data on the user's device.

The Web Storage API provides two main storage mechanisms:

  • localStorage – stores data without a fixed session expiry.
  • sessionStorage – stores data for a particular page session.
Web Storage is designed for relatively small amounts of string-based data. It is not a replacement for a full database.

2. Why is Web Storage Required?

Without client-side storage, information entered by a user may be lost when a webpage is refreshed or closed, unless the application saves it elsewhere.

Web Storage can help an application:

  • Remember user preferences.
  • Save temporary form information.
  • Maintain simple client-side application state.
  • Remember selected display settings.
  • Store small amounts of data between page visits.
  • Reduce repeated requests for certain non-sensitive data.

Example Applications

  • Saving dark mode or light mode preference.
  • Remembering the selected language.
  • Saving a shopping cart identifier or simple cart state.
  • Remembering a recently selected course.
  • Temporarily saving a form draft.

3. Traditional Cookies vs Web Storage

Before Web Storage became widely available, cookies were commonly used to store small pieces of information in the browser.

Web Storage provides a simpler key-value storage interface for client-side data.

Feature Cookies Web Storage
Storage format Name-value pairs Key-value pairs
Typical capacity Small, commonly around 4 KB per cookie Usually several MB per origin
Server communication Matching cookies are sent with applicable HTTP requests Not automatically sent with HTTP requests
JavaScript access Through document.cookie, unless HttpOnly Through the Storage API
Expiration Can have an explicit expiry or be session-based localStorage has no fixed expiry; sessionStorage is session-scoped
Common use Server-managed session identifiers and preferences Client-side preferences and application state
Cookies and Web Storage serve different purposes. Authentication and session management often require carefully configured cookies, such as Secure, HttpOnly, and SameSite attributes.

4. Types of Browser Storage

Modern browsers provide several ways to store application data.

4.1 localStorage

localStorage stores data associated with a web origin. The data normally remains available after the browser is closed and reopened, until it is cleared or removed.

Example: Remembering a user's theme preference.

4.2 sessionStorage

sessionStorage stores data for a particular top-level browsing context's page session. The data is normally removed when that page session ends.

Example: Maintaining temporary state while a user navigates within a tab.

4.3 IndexedDB

IndexedDB is a browser database API designed to store larger amounts of structured data.

Example: Storing offline application records or structured datasets.

4.4 Cookies

Cookies store small pieces of information that can be included in applicable HTTP requests.

Example: Server-managed session identifiers.

Storage Comparison

Storage Type Data Type Lifetime Typical Use
localStorage Strings Until removed or cleared Persistent preferences
sessionStorage Strings Page session Temporary page state
IndexedDB Structured data Until removed or cleared Large client-side datasets
Cookies Small text values Session or configured expiry HTTP session management

5. Understanding Key-Value Storage

Web Storage uses a key-value model. Each stored item consists of a key and its corresponding value.

For example:

username = "Student" course = "HTML5" theme = "dark" language = "English"

Here:

  • Key: A name used to identify the stored item.
  • Value: The information associated with that key.

Example Using localStorage

localStorage.setItem("username", "Student"); localStorage.setItem("course", "HTML5"); localStorage.setItem("theme", "dark");

Three key-value pairs are stored in the browser's localStorage.

Retrieving Stored Values

const username = localStorage.getItem("username"); const course = localStorage.getItem("course"); console.log(username); console.log(course);
Expected Console Output: 
Student
HTML5
Web Storage stores keys and values as strings. Objects and arrays must be converted into strings before storage, commonly using JSON.stringify().

6. The Storage API

The Web Storage API exposes a Storage interface through which JavaScript can manage stored data.

The two main objects are:

  • window.localStorage
  • window.sessionStorage

Common Storage Methods and Properties

Method / Property Purpose
setItem(key, value) Stores a key-value pair.
getItem(key) Retrieves the value associated with a key.
removeItem(key) Removes a particular key-value pair.
clear() Removes all entries in that storage area.
key(index) Returns the key at a specified index.
length Returns the number of stored entries.

These methods are available on both localStorage and sessionStorage.

8. Storing Arrays and Objects

Web Storage stores strings, not JavaScript objects or arrays directly.

JSON.stringify() converts an object or array into a JSON string.

Example: Store an Object

const student = { name: "Rahul", course: "HTML5", year: 2026 }; // Convert object into JSON string const studentData = JSON.stringify(student); // Store JSON string localStorage.setItem("student", studentData);

Retrieve an Object

const storedData = localStorage.getItem("student"); // Convert JSON string back into object const studentObject = JSON.parse(storedData); console.log(studentObject.name); console.log(studentObject.course);
Expected Console Output: 
Rahul
HTML5
JSON.parse() can throw an error if the stored text is not valid JSON. Production code should handle parsing errors.

9. Storage Capacity and Limitations

Browser storage has limits. The available capacity varies by browser, device, storage type, and browser policies.

Important Limitations

  • Web Storage stores strings only.
  • Storage capacity is limited.
  • localStorage and sessionStorage operations are synchronous.
  • Storage is associated with an origin.
  • Users can clear browser storage.
  • Private browsing modes may apply different storage behavior.
  • Storage access can fail because of browser policies or quota restrictions.

What is an Origin?

An origin is generally defined by three components:

  • Scheme or protocol.
  • Hostname.
  • Port.

For example:

https://example.com:443

Storage is separated by origin. A different hostname, scheme, or port generally means a different storage area.

10. Security Considerations

Browser storage is accessible to JavaScript executing within the relevant origin.

If an application has a Cross-Site Scripting (XSS) vulnerability, malicious scripts may be able to read or modify Web Storage data.

Security Best Practices

  • Do not store passwords in localStorage.
  • Do not store private authentication secrets in Web Storage.
  • Validate data retrieved from browser storage.
  • Protect applications against XSS attacks.
  • Use HTTPS to protect data in transit.
  • Store only information that the application actually needs.
HTTPS protects communication between the browser and server. It does not make localStorage itself encrypted or safe from malicious scripts.

11. Browser Developer Tools

Modern browsers provide Developer Tools that allow developers to inspect stored data.

How to Inspect localStorage in Chrome

  1. Open your webpage in Google Chrome.
  2. Press F12 or Ctrl + Shift + I.
  3. Open the Application tab.
  4. Find Storage in the left panel.
  5. Select Local Storage.
  6. Select the webpage's origin.
  7. Inspect the stored keys and values.

Inspect sessionStorage

  1. Open Developer Tools.
  2. Select the Application tab.
  3. Open Session Storage.
  4. Select the relevant webpage origin.
  5. View the stored entries.
Developer Tools are useful for debugging, but users can also clear or modify client-side storage. Never trust stored values as authoritative server data.

12. Web Storage vs Database

Feature Web Storage Database
Location Browser Server or client device
Data model Simple key-value pairs Relational or other structured models
Typical use Preferences and small state Persistent application records
Sharing Usually limited to the relevant browser origin Can support multiple users and clients
Query capability Basic key-based access Can support complex queries

For larger structured client-side data, IndexedDB is generally more appropriate than Web Storage. For shared application data, a server-side database is commonly required.

13. Common Mistakes

  • Assuming localStorage stores objects directly.
  • Using localStorage for passwords.
  • Assuming all browsers provide identical storage limits.
  • Forgetting to handle missing keys.
  • Calling JSON.parse() without considering invalid data.
  • Using Web Storage for large files or datasets.
  • Assuming data can be shared across unrelated origins.
  • Assuming localStorage and sessionStorage have identical lifetimes.

14. Lesson Summary

  • Web Storage allows browser-side data storage.

  • localStorage normally persists until removed or cleared.
  • sessionStorage is scoped to a page session.
  • IndexedDB stores larger structured datasets.
  • Cookies can be included in applicable HTTP requests.
  • Web Storage stores strings.
  • JSON.stringify() converts objects into JSON strings.
  • JSON.parse() converts JSON strings back into JavaScript values.
  • Web Storage is associated with an origin.
  • Web Storage operations are synchronous.
  • Sensitive secrets should not be stored in Web Storage.

16. Interview Questions and Answers

Q1. What is Web Storage?
Web Storage is a browser API that allows JavaScript applications to store key-value data on the user's device.
Q2. What are the two main types of Web Storage?
localStorage and sessionStorage.
Q3. What is localStorage?
localStorage stores data associated with an origin and normally retains it until it is removed or cleared.
Q4. What is sessionStorage?
sessionStorage stores data for a particular page session in a browsing context.
Q5. What is the difference between localStorage and sessionStorage?
localStorage normally persists across browser restarts, while sessionStorage is associated with a particular page session.
Q6. What type of data does Web Storage store?
Web Storage stores keys and values as strings.
Q7. Can we store JavaScript objects in localStorage?
Objects can be converted to JSON strings using JSON.stringify() and restored using JSON.parse().
Q8. What is IndexedDB?
IndexedDB is a browser database API for storing larger amounts of structured client-side data.
Q9. Are localStorage operations asynchronous?
No. localStorage operations are synchronous.
Q10. What is the purpose of removeItem()?
It removes a particular key-value entry from storage.
Q11. What does clear() do?
It removes all entries from the relevant localStorage or sessionStorage area.
Q12. Are cookies automatically sent to the server?
Matching cookies are sent with applicable HTTP requests according to their scope and attributes. Web Storage values are not automatically sent.
Q13. Why should passwords not be stored in localStorage?
JavaScript running in the same origin can access localStorage. An XSS vulnerability may expose stored sensitive information.
Q14. What is an origin in browser storage?
An origin is defined by the scheme, hostname, and port. Browser storage is generally separated by origin.
Q15. When should IndexedDB be preferred?
IndexedDB is preferable when an application needs to store larger amounts of structured client-side data or perform database-style operations.
