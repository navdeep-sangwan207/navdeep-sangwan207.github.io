Lesson 4: SessionStorage

Chapter 12: HTML5 APIs and Browser Features

Learn how to store temporary browser data for an individual page session.

1. Introduction to sessionStorage

sessionStorage is a browser storage mechanism provided by the Web Storage API. It allows JavaScript applications to store key-value data for a particular browsing context.

Unlike localStorage, sessionStorage is designed for data that should remain available during a page session rather than being retained as long-term application storage.

Examples of session-specific information include:

  • Temporary form data.
  • Current step in a multi-step form.
  • Temporary shopping or booking progress.
  • Page-specific user interface state.
  • Temporary navigation information.
sessionStorage is scoped to an origin and a particular top-level browsing context. It normally remains available after page reloads but is cleared when that page session ends.

2. Characteristics of sessionStorage

  • Stores data as key-value pairs.
  • Both keys and values are strings.
  • Data is associated with an origin and browsing context.
  • Data normally survives page reloads.
  • Separate tabs generally have separate sessionStorage areas.
  • Data is normally removed when the tab or page session ends.
  • Storage operations are synchronous.
  • Data is not automatically sent to the server.

Example

sessionStorage.setItem("username", "Rahul"); console.log( sessionStorage.getItem("username") );
Expected Output: 
Rahul

3. Accessing sessionStorage

The sessionStorage object is available through the browser's window object.

window.sessionStorage

The shorter form is:

sessionStorage

Checking Availability

if ("sessionStorage" in window) { console.log("sessionStorage is available."); } else { console.log("sessionStorage is not available."); }

The existence of the API does not guarantee that every storage operation will succeed. Browser policies and storage restrictions can cause errors.

4. setItem() Method

The setItem() method stores a key-value pair in sessionStorage.

Syntax

sessionStorage.setItem(key, value);

Example

sessionStorage.setItem("username", "Rahul"); sessionStorage.setItem("course", "HTML5"); sessionStorage.setItem("status", "Learning");
Stored Data: 
username = Rahul
course = HTML5
status = Learning

5. getItem() Method

The getItem() method retrieves a value using its associated key.

Syntax

sessionStorage.getItem(key);

Example

sessionStorage.setItem("course", "HTML5"); const course = sessionStorage.getItem("course"); console.log(course);
Expected Output: 
HTML5

Missing Key

const result = sessionStorage.getItem("email"); console.log(result);
Expected Output: 
null

6. Updating Stored Data

Calling setItem() with an existing key replaces its previous value.

Example

sessionStorage.setItem("course", "C"); sessionStorage.setItem("course", "HTML5"); console.log( sessionStorage.getItem("course") );
Expected Output: 
HTML5

7. removeItem() Method

The removeItem() method removes one specified key-value pair from sessionStorage.

Syntax

sessionStorage.removeItem(key);

Example

sessionStorage.setItem("username", "Rahul"); sessionStorage.removeItem("username"); console.log( sessionStorage.getItem("username") );
Expected Output: 
null

8. clear() Method

The clear() method removes all key-value entries from the sessionStorage area for the current origin and browsing context.

Syntax

sessionStorage.clear();

Example

sessionStorage.setItem("username", "Rahul"); sessionStorage.setItem("course", "HTML5"); sessionStorage.setItem("city", "Chandigarh"); sessionStorage.clear(); console.log(sessionStorage.length);
Expected Output: 
0

9. length Property

The length property returns the number of key-value entries currently stored.

Example

sessionStorage.setItem("name", "Rahul"); sessionStorage.setItem("course", "HTML5"); sessionStorage.setItem("city", "Chandigarh"); console.log(sessionStorage.length);
Expected Output: 
3

10. key() Method

The key() method returns the key name at a specified storage index.

Syntax

sessionStorage.key(index);

Example

sessionStorage.setItem("username", "Rahul"); sessionStorage.setItem("course", "HTML5"); console.log(sessionStorage.key(0)); console.log(sessionStorage.key(1));
Possible Output: 
username
course

Do not depend on key ordering for application sorting or priority logic.

11. Complete sessionStorage Methods

Method / Property Purpose Example
setItem() Stores or updates a value. setItem("name", "Rahul")
getItem() Retrieves a value. getItem("name")
removeItem() Removes one entry. removeItem("name")
clear() Removes all entries for this session. clear()
key() Gets a key by index. key(0)
length Gets the number of entries. sessionStorage.length

12. Storing Numbers and Boolean Values

sessionStorage stores string values. Convert retrieved values when the application requires numbers or Boolean values.

Example: Number

sessionStorage.setItem("marks", 85); const marks = Number( sessionStorage.getItem("marks") ); console.log(marks); console.log(typeof marks);
Expected Output: 
85
number

Example: Boolean

sessionStorage.setItem("isActive", true); const isActive = sessionStorage.getItem("isActive") === "true"; console.log(isActive); console.log(typeof isActive);
Expected Output: 
true
boolean

13. Storing JavaScript Objects

Objects must be converted into JSON strings before they can be stored.

Store an Object

const student = { name: "Rahul", course: "HTML5", marks: 85 }; sessionStorage.setItem( "student", JSON.stringify(student) );

Retrieve an Object

const storedData = sessionStorage.getItem("student"); const studentObject = JSON.parse(storedData); console.log(studentObject.name); console.log(studentObject.course); console.log(studentObject.marks);
Expected Output: 
Rahul
HTML5
85

Handling Invalid JSON

const storedData = sessionStorage.getItem("student"); try { const student = JSON.parse(storedData); console.log(student); } catch (error) { console.log("Invalid stored JSON."); }

JSON.parse() throws an error when the stored string is not valid JSON. A missing key returns null, which JSON.parse() accepts as a null value.

14. Practical Program: Temporary Form Data

This example stores a student's name and selected course in sessionStorage. The data can be restored after a page reload within the same page session.

Complete HTML Program

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>Temporary Student Form</title> </head> <body> <h2>Student Form</h2> <input type="text" id="name" placeholder="Enter name"> <input type="text" id="course" placeholder="Enter course"> <button onclick="saveForm()"> Save Temporarily </button> <button onclick="restoreForm()"> Restore Data </button> <button onclick="clearFormData()"> Clear Session Data </button> <p id="result"></p> <script> function saveForm() { const name = document.getElementById("name").value; const course = document.getElementById("course").value; sessionStorage.setItem("studentName", name); sessionStorage.setItem("studentCourse", course); document.getElementById("result").textContent = "Form data saved for this session."; } function restoreForm() { const name = sessionStorage.getItem("studentName"); const course = sessionStorage.getItem("studentCourse"); if (name === null || course === null) { document.getElementById("result").textContent = "No saved form data found."; return; } document.getElementById("name").value = name; document.getElementById("course").value = course; document.getElementById("result").textContent = "Form data restored."; } function clearFormData() { sessionStorage.removeItem("studentName"); sessionStorage.removeItem("studentCourse"); document.getElementById("result").textContent = "Session form data cleared."; } // Restore previously saved data when the page loads. window.addEventListener("DOMContentLoaded", restoreForm); </script> </body> </html>
Expected Result:
  1. Enter a student name and course.
  2. Click Save Temporarily.
  3. Reload the page.
  4. The saved values are restored in the same session.
  5. Click Clear Session Data to remove them.

16. Understanding Tab-Specific Storage

sessionStorage is separated by top-level browsing context. Two independently opened tabs generally have separate sessionStorage areas, even when they display the same website.

Example Scenario

Browser Tab Stored Value
Tab 1 username = Rahul
Tab 2 username = Amit

If the two tabs are independent browsing contexts, changing the value in one normally does not change the value in the other.

A newly opened page with an opener can initially receive a copy of the opener's sessionStorage. The two storage areas are then separate; later changes are not synchronized. Browsers and link settings can affect opener behavior.

17. localStorage vs sessionStorage

Both localStorage and sessionStorage are provided by the Web Storage API. They share the same Storage interface but have different lifetimes and storage scopes.

Feature localStorage sessionStorage
Storage API Web Storage API Web Storage API
Data format Strings Strings
Scope Origin Origin and browsing context
Lifetime Normally persists until removed or cleared Normally lasts for the page session
Page reload Data remains Data remains
Browser restart Normally remains Normally cleared when the session ends
Independent tabs Same origin can share storage Generally separate storage areas
Methods Same Storage methods Same Storage methods

Choosing the Correct Storage

  • Use localStorage for non-sensitive preferences that should remain available between visits.
  • Use sessionStorage for temporary state tied to a particular page session.
  • Use IndexedDB for larger or more complex structured client-side data.

18. Security and Limitations

Security Considerations

  • Scripts running in the same origin can access sessionStorage.
  • XSS vulnerabilities can expose stored information.
  • Users can inspect and modify stored values.
  • Data is not automatically encrypted.
  • Client-side data should not be trusted as authoritative.

Limitations

  • Storage capacity is limited.
  • Operations are synchronous.
  • Data is generally not shared between independent tabs.
  • Browser settings can restrict storage access.
  • Data normally does not survive the end of the page session.
Do not store passwords, private authentication secrets, or other sensitive information in sessionStorage. Session-specific storage does not make data secure against same-origin scripts.

19. Common Mistakes

  • Assuming sessionStorage is shared across all tabs.
  • Assuming data is removed after every page reload.
  • Forgetting that values are stored as strings.
  • Trying to store JavaScript objects without JSON conversion.
  • Using clear() when only one key should be removed.
  • Assuming sessionStorage provides encryption.
  • Ignoring possible storage exceptions.

22. Interview Questions and Answers

Q1. What is sessionStorage?
sessionStorage is a browser storage mechanism that stores key-value data for a particular browsing context and page session.
Q2. Which API provides sessionStorage?
The Web Storage API.
Q3. How do you store data in sessionStorage?
Use sessionStorage.setItem(key, value).
Q4. How do you retrieve data?
Use sessionStorage.getItem(key).
Q5. Does sessionStorage survive a page reload?
Yes. It normally remains available after a reload within the same page session.
Q6. What happens when the page session ends?
Its sessionStorage data is normally cleared.
Q7. Is sessionStorage shared between independent tabs?
Generally no. Each top-level browsing context has its own sessionStorage area.
Q8. Can sessionStorage store objects directly?
No. Convert objects to JSON strings using JSON.stringify() before storing them.
Q9. What does getItem() return for a missing key?
It returns null.
Q10. What is the difference between localStorage and sessionStorage?
localStorage normally persists until removed, whereas sessionStorage is normally limited to a particular page session and browsing context.
Q11. Are sessionStorage operations asynchronous?
No. The Storage interface operations are synchronous.
Q12. Is sessionStorage encrypted?
No. It does not automatically encrypt stored data.
Q13. Which method removes one entry?
removeItem().
Q14. Which method removes all entries in the current session area?
clear().
Q15. Give one practical use of sessionStorage.
Preserving temporary form progress while a user navigates or reloads pages within the same browsing session.
