Lesson 8: History and Navigation API

Chapter 12: HTML5 APIs and Browser Features

Learn how browsers manage session history and how JavaScript can control navigation without requiring a full page reload.

1. Introduction to Browser History

Browser history is the record of pages or navigation entries visited within a browser tab or browsing context.

When a user opens a page, follows a link, or navigates to another URL, the browser maintains a session history for that tab.

Users can navigate through this history using the browser's Back and Forward buttons.

Examples

  • Opening a website.
  • Moving from one page to another.
  • Clicking the browser Back button.
  • Returning to a previously visited page.
  • Using JavaScript to update the current URL.

2. What is the History API?

The History API is a browser interface that allows JavaScript to interact with the session history of the current browsing context.

It is available through the browser's window.history object.

Syntax

window.history

The window object is generally available in a normal web page's JavaScript environment.

The History API manages session history entries. It does not provide unrestricted access to the browser's complete browsing history.

3. History Object Properties

The history object provides properties and methods for working with session history.

length

The length property returns the number of entries in the session history.

console.log(history.length);

state

The state property returns the state object associated with the current history entry.

console.log(history.state);

scrollRestoration

This property controls automatic restoration of the scroll position during history navigation.

console.log(history.scrollRestoration);

Its commonly used values are:

  • auto: Browser manages scroll restoration.
  • manual: The application manages scroll restoration.

4. History API Methods

Method Purpose
back() Moves to the previous session history entry.
forward() Moves to the next session history entry.
go() Moves a specified number of entries.
pushState() Adds a new history entry.
replaceState() Updates the current history entry.

5. back() Method

The back() method moves the browser to the previous entry in the session history.

Syntax

history.back();

It performs an operation similar to clicking the browser's Back button.

Example

document.getElementById("backButton") .addEventListener("click", function() { history.back(); });
If there is no previous entry, back() does not navigate to a different page.

6. forward() Method

The forward() method moves to the next entry in the session history, if one exists.

Syntax

history.forward();

Example

document.getElementById("forwardButton") .addEventListener("click", function() { history.forward(); });

7. go() Method

The go() method navigates to a specific position relative to the current history entry.

Syntax

history.go(number);

Examples

// Move one entry backward history.go(-1); // Move one entry forward history.go(1); // Move two entries backward history.go(-2); // Reload the current page history.go(0);
Interpretation:
  • Negative value: Move backward.
  • Positive value: Move forward.
  • Zero: Reload the current page.

8. pushState() Method

The pushState() method adds a new entry to the current browsing context's session history.

It can update the visible URL without immediately loading a new document.

Syntax

history.pushState(state, unused, url);

Parameters

  • state: Data associated with the new history entry.
  • unused: Reserved parameter, traditionally an empty string.
  • url: Optional new URL for the entry.

Example

history.pushState( { page: "about" }, "", "?page=about" );

The browser creates a new history entry and changes the displayed URL to include the query parameter.

The URL must be same-origin with the current document. pushState() does not itself fetch or load the new URL.

9. replaceState() Method

The replaceState() method modifies the current session history entry instead of creating a new entry.

Syntax

history.replaceState(state, unused, url);

Example

history.replaceState( { page: "dashboard" }, "", "?page=dashboard" );

The current URL and associated state are updated, but the history stack does not gain a new entry.

10. pushState() vs replaceState()

Feature pushState() replaceState()
New entry Creates a new history entry. Does not create a new entry.
Current entry Leaves the previous entry intact. Replaces the current entry's state and URL.
Back navigation Can return to the previous entry. Does not add an extra entry to return from.
Typical use Navigate to a new application view. Correct or update the current URL state.

11. popstate Event

The popstate event is fired when the active history entry changes through certain session history traversal operations.

For example, it is commonly used when a user clicks the browser Back or Forward button after the application has created entries using pushState().

Syntax

window.addEventListener("popstate", function(event) { console.log(event.state); });

Example

window.addEventListener("popstate", function(event) { const state = event.state; console.log("Current state:", state); });
Calling pushState() or replaceState() does not immediately fire a popstate event. The event is associated with history traversal.

12. Practical Program: Simple Navigation Using History API

This program demonstrates navigation between Home, About and Contact views without loading separate HTML documents.

File: index.html

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>History API Navigation</title> </head> <body> <h2>History API Navigation</h2> <button onclick="navigate('home')">Home</button> <button onclick="navigate('about')">About</button> <button onclick="navigate('contact')">Contact</button> <button onclick="history.back()">Back</button> <button onclick="history.forward()">Forward</button> <hr> <div id="content"></div> <script> const content = document.getElementById("content"); const pages = { home: "<h3>Home Page</h3><p>Welcome to Home.</p>", about: "<h3>About Page</h3><p>About this website.</p>", contact: "<h3>Contact Page</h3><p>Contact information.</p>" }; function renderPage(page) { if (!Object.prototype.hasOwnProperty.call(pages, page)) { page = "home"; } content.innerHTML = pages[page]; } function navigate(page) { const url = "?page=" + page; history.pushState( { page: page }, "", url ); renderPage(page); } window.addEventListener("popstate", function(event) { const page = event.state && event.state.page ? event.state.page : "home"; renderPage(page); }); const initialPage = new URLSearchParams(window.location.search).get("page") || "home"; renderPage(initialPage); history.replaceState( { page: initialPage }, "", window.location.href ); </script> </body> </html>
Expected Behavior:
  1. Click Home to display the Home view.
  2. Click About to display the About view.
  3. Click Contact to display the Contact view.
  4. Click Back to return to the previous view.
  5. Click Forward to move to the next view.

The application updates its URL and session history while rendering the selected view.

This is a teaching example. For production applications, render untrusted data using textContent or safe DOM construction instead of inserting arbitrary strings with innerHTML. Also configure the server to handle direct requests to application routes.

14. URL API and URLSearchParams

The URL interface provides a structured way to read and manipulate URL components. URLSearchParams helps work with query parameters.

Creating a URL Object

const url = new URL( "https://example.com/products?category=electronics" ); console.log(url.hostname); console.log(url.pathname); console.log(url.search);

Reading Query Parameters

const params = new URLSearchParams( window.location.search ); const category = params.get("category"); console.log(category);

Adding a Query Parameter

const params = new URLSearchParams( window.location.search ); params.set("category", "electronics"); console.log(params.toString());

URL and URLSearchParams are separate browser interfaces that are useful alongside the History API.

15. Navigation Without Page Reload

A traditional navigation normally loads a new document. In a single-page application, JavaScript can update the visible content and history entry without replacing the document.

Traditional Navigation

<a href="about.html">About</a>

The browser navigates to another document.

History API Navigation

history.pushState( { page: "about" }, "", "/about" );

JavaScript then updates the visible application content to match the new route.

pushState() changes the history entry and URL; it does not automatically render a new page. The application must update its own interface.

16. History API Security and Restrictions

  • pushState() and replaceState() generally require a same-origin URL.
  • They cannot be used to change the URL to an unrelated origin.
  • The state value must be serializable using the structured clone algorithm.
  • Browsers may impose limits on how frequently history entries can be added.
  • Directly loading a client-side route requires appropriate server-side routing or fallback.
  • Avoid placing sensitive information in URLs because URLs can appear in logs and history.

17. History API vs Location API

Feature History API Location API
Purpose Manages session history entries. Reads and changes the current URL.
Access window.history window.location
Navigation back(), forward(), go() assign(), replace(), reload()
URL updates pushState(), replaceState() href and other URL properties.
Typical use Single-page application navigation. Loading or inspecting a URL.

Location API Examples

// Read the current URL console.log(location.href); // Navigate to another URL location.assign("https://example.com"); // Replace the current document location.replace("https://example.com"); // Reload the current document location.reload();

18. Applications of the History API

  • Single-page applications (SPAs).
  • Dynamic website navigation.
  • Back and Forward navigation.
  • Client-side routing.
  • Maintaining application state in URLs.
  • Updating query parameters without reloading.
  • Browser navigation in web dashboards.

19. Common Mistakes

  1. Assuming pushState() automatically loads the new page.
  2. Forgetting to update application content after changing the URL.
  3. Not handling the popstate event.
  4. Using a cross-origin URL with pushState().
  5. Assuming pushState() fires popstate immediately.
  6. Forgetting to support direct loading of client-side routes on the server.
  7. Storing sensitive information in the URL.

20. Lesson Summary

  • The History API manages the current browsing context's session history.
  • It is available through window.history.
  • history.length reports the number of session history entries.
  • history.state returns the current entry's state.
  • back() moves to the previous entry.
  • forward() moves to the next entry.
  • go() navigates by a relative history offset.
  • pushState() adds a new history entry.
  • replaceState() updates the current entry.
  • popstate handles certain history traversal events.
  • URLSearchParams helps manage query parameters.
  • Location API provides access to the current URL and navigation methods.
  • Client-side routing requires application logic and appropriate server configuration.

22. Interview Questions and Answers

Q1. What is the History API?
It is a browser API that allows JavaScript to interact with the current browsing context's session history.
Q2. Which object provides the History API?
The window.history object.
Q3. What is the purpose of history.length?
It returns the number of entries in the current session history.
Q4. What does pushState() do?
It adds a new session history entry and can update the visible URL without loading a new document.
Q5. What does replaceState() do?
It updates the current history entry's state and URL without adding another entry.
Q6. What is the difference between pushState() and replaceState()?
pushState() creates a new history entry, while replaceState() modifies the current one.
Q7. What is popstate?
It is an event associated with certain changes to the active session history entry.
Q8. Does pushState() fire popstate?
No. pushState() does not immediately fire the popstate event.
Q9. What is history.go(0)?
It reloads the current page.
Q10. What is the Location API?
It provides access to the current URL and methods for navigating or reloading documents.
Q11. Can pushState() change the URL to another origin?
No. The supplied URL must be same-origin with the current document.
Q12. What is client-side routing?
It is the process of changing application views and managing URLs using JavaScript without necessarily loading a new document.
Q13. What is URLSearchParams?
It is an interface for reading and modifying URL query parameters.
Q14. What is history.state?
It returns the state object associated with the current history entry.
Q15. Why is popstate important in SPAs?
It allows an application to update its displayed view when users navigate using browser Back and Forward controls.
