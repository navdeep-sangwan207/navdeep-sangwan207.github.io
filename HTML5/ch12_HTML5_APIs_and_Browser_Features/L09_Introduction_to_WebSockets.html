Lesson 9: Introduction to WebSockets

Chapter 12: HTML5 APIs and Browser Features

Learn how WebSockets provide persistent, bidirectional communication between web browsers and servers.

1. Introduction to WebSockets

WebSocket is a communication protocol that provides full-duplex communication between a client and a server over a single TCP connection.

It allows the browser and server to send messages to each other independently after the connection has been established.

Unlike traditional request-response communication, the server does not need to wait for a new client request before sending data.

Applications of WebSockets

  • Real-time chat applications.
  • Live notifications.
  • Online multiplayer games.
  • Live stock market updates.
  • Real-time monitoring dashboards.
  • Collaborative editing applications.
  • Live device and sensor monitoring.

2. What is Real-Time Communication?

Real-time communication means exchanging information with very little delay between communicating systems.

For example, when a user sends a chat message, the server can immediately deliver it to another connected user.

Example

User A
   |
   | Sends message
   v
WebSocket Server
   |
   | Forwards message
   v
User B

WebSockets are useful when an application needs frequent updates or communication in both directions.

3. What is the WebSocket Protocol?

WebSocket is a standardized protocol identified by the URI schemes:

  • ws:// — WebSocket communication without TLS.
  • wss:// — WebSocket communication protected by TLS.

Example URLs

ws://example.com/socket wss://example.com/socket

The WebSocket protocol is standardized in RFC 6455.

Use wss:// for production communication over HTTPS websites. Browsers generally block insecure mixed content when an HTTPS page attempts to connect to an insecure WebSocket endpoint.

4. WebSocket Architecture

A WebSocket application usually contains three main components:

  1. Client: A browser or application that initiates the connection.
  2. Server: The system that accepts connections and processes messages.
  3. WebSocket connection: The persistent communication channel.

5. How WebSocket Communication Works

A WebSocket connection begins with an HTTP-based opening handshake.

Connection Steps

  1. The client creates a WebSocket connection request.
  2. The browser sends an HTTP request containing an Upgrade header.
  3. The server checks whether it supports the WebSocket upgrade.
  4. The server responds with HTTP 101 Switching Protocols if the handshake succeeds.
  5. The connection changes to the WebSocket protocol.
  6. Client and server exchange messages over the connection.
  7. Either side can initiate a closing handshake.

Handshake Request Example

GET /chat HTTP/1.1 Host: example.com Upgrade: websocket Connection: Upgrade Sec-WebSocket-Key: exampleKey Sec-WebSocket-Version: 13

Successful Handshake Response

HTTP/1.1 101 Switching Protocols Upgrade: websocket Connection: Upgrade Sec-WebSocket-Accept: calculated-value
The browser generates and validates the handshake details. Application developers normally use the WebSocket API rather than manually constructing these HTTP headers.

6. Full-Duplex Communication

Full-duplex communication allows both sides to transmit data independently over the same connection.

WebSocket Communication

Client  ----------------->  Server
        Client Message

Client  <-----------------  Server
        Server Message

Client  ----------------->  Server
        Another Message

The client and server can send messages without requiring a new HTTP request for each message.

Communication Types

Communication Description
Simplex Communication in one direction only.
Half-duplex Both sides can communicate, but not simultaneously.
Full-duplex Both sides can communicate independently at the same time.

7. Creating a WebSocket Connection

JavaScript provides the WebSocket interface for creating and managing a connection.

Syntax

const socket = new WebSocket( "wss://example.com/socket" );

Example

const socket = new WebSocket( "wss://example.com/socket" ); console.log(socket);

The constructor starts the connection process. The connection is asynchronous, so it may not be open immediately.

8. WebSocket Ready States

The readyState property indicates the current state of a WebSocket connection.

Constant Value Meaning
CONNECTING 0 Connection is being established.
OPEN 1 Connection is open and communication is possible.
CLOSING 2 Connection is closing.
CLOSED 3 Connection is closed or could not be opened.

Example

console.log(socket.readyState); if (socket.readyState === WebSocket.OPEN) { console.log("Connection is open"); }

9. WebSocket Events

WebSocket provides events to monitor connection activity.

Event Purpose
open Fired when the connection is established.
message Fired when a message is received.
error Fired when an error occurs.
close Fired when the connection closes.

Example

socket.addEventListener("open", function(event) { console.log("Connected"); }); socket.addEventListener("message", function(event) { console.log("Received:", event.data); }); socket.addEventListener("error", function(event) { console.log("WebSocket error", event); }); socket.addEventListener("close", function(event) { console.log("Connection closed"); });

10. send() Method

The send() method transmits data to the server through an open WebSocket connection.

Syntax

socket.send(data);

Sending Text Data

socket.send("Hello Server");

Sending JSON Data

const message = { username: "User1", text: "Hello" }; socket.send(JSON.stringify(message));
Always check that readyState is OPEN before calling send(). Sending when the connection is not open can throw an InvalidStateError.

11. Receiving Messages

The message event is triggered when the server sends data to the client.

Example

socket.addEventListener("message", function(event) { console.log("Server message:", event.data); });

The received data can be text or another supported data representation, depending on what the server sends.

Receiving JSON Data

socket.addEventListener("message", function(event) { const message = JSON.parse(event.data); console.log(message.username); console.log(message.text); });
Validate received data before using it. JSON.parse() can throw an exception if the received text is not valid JSON.

12. close() Method

The close() method begins the WebSocket closing handshake.

Syntax

socket.close();

Example with Code and Reason

socket.close(1000, "Normal closure");

The first parameter is a closing status code, and the second parameter is an optional reason.

Code 1000 indicates normal closure. Application-defined codes generally use the permitted range 3000–4999. Certain protocol codes cannot be supplied directly to the close() method.

13. WebSocket Object Properties

Property Description
readyState Returns the current connection state.
url Returns the URL used to create the connection.
protocol Returns the selected subprotocol.
extensions Returns the negotiated extensions.
bufferedAmount Returns the number of bytes queued by send() but not yet transmitted.
binaryType Controls the format used for received binary data.

Example

console.log(socket.url); console.log(socket.protocol); console.log(socket.readyState); console.log(socket.bufferedAmount);

14. Text and Binary Data

WebSockets support text messages and binary messages.

Text Data

socket.send("Hello Server");

Binary Data Using ArrayBuffer

const buffer = new ArrayBuffer(8); const values = new Uint8Array(buffer); values[0] = 10; values[1] = 20; socket.send(buffer);

Setting binaryType

socket.binaryType = "arraybuffer";

The binaryType property controls how incoming binary messages are represented. Supported values include "blob" and "arraybuffer".

15. First WebSocket Client Program

The following program demonstrates the client-side JavaScript code. It requires a working WebSocket server.

File: index.html

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>WebSocket Client</title> </head> <body> <h2>WebSocket Client</h2> <input type="text" id="message" placeholder="Enter message"> <button id="sendButton">Send</button> <button id="closeButton">Disconnect</button> <p id="status">Connecting...</p> <div id="output"></div> <script> const socket = new WebSocket( "wss://example.com/socket" ); const status = document.getElementById("status"); const output = document.getElementById("output"); socket.addEventListener("open", function() { status.textContent = "Connected to server"; }); socket.addEventListener("message", function(event) { const message = document.createElement("p"); message.textContent = "Server: " + event.data; output.appendChild(message); }); socket.addEventListener("error", function() { status.textContent = "Connection error"; }); socket.addEventListener("close", function() { status.textContent = "Disconnected"; }); document.getElementById("sendButton") .addEventListener("click", function() { if (socket.readyState === WebSocket.OPEN) { const value = document.getElementById("message").value; socket.send(value); } else { status.textContent = "Connection is not open."; } }); document.getElementById("closeButton") .addEventListener("click", function() { socket.close(1000, "User disconnected"); }); </script> </body> </html>
Replace wss://example.com/socket with the URL of an actual WebSocket server. The example domain is a placeholder and does not provide a working chat service.

16. Practical Server Program Using Node.js

A WebSocket client needs a server to accept connections and exchange messages.

The following example uses Node.js and the popular ws package.

Step 1: Install Node.js

Install Node.js from its official website:

Node.js Official Website

Step 2: Create a Project Folder

mkdir websocket-demo cd websocket-demo

Step 3: Initialize the Project

npm init -y

Step 4: Install the ws Package

npm install ws

Step 5: Create server.js

const WebSocket = require("ws"); const server = new WebSocket.Server({ port: 8080 }); server.on("connection", function(socket) { console.log("Client connected"); socket.send("Welcome to WebSocket Server"); socket.on("message", function(data) { const message = data.toString(); console.log("Client:", message); socket.send("Server received: " + message); }); socket.on("close", function() { console.log("Client disconnected"); }); }); console.log("WebSocket server running on port 8080");

Step 6: Run the Server

node server.js
Expected Terminal Output: 
WebSocket server running on port 8080
Client connected
Client: Hello Server
This is a basic learning server. It does not implement authentication, authorization, production security controls or robust connection management.

17. Practical Chat Application

A simple chat application can be created by combining a browser WebSocket client and a WebSocket server.

File: client.html

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>WebSocket Chat</title> </head> <body> <h2>WebSocket Chat Application</h2> <input type="text" id="username" placeholder="Enter username"> <input type="text" id="message" placeholder="Enter message"> <button id="send">Send Message</button> <div id="chat"></div> <script> const socket = new WebSocket( "ws://localhost:8080" ); const chat = document.getElementById("chat"); socket.addEventListener("message", function(event) { const item = document.createElement("p"); item.textContent = event.data; chat.appendChild(item); }); document.getElementById("send") .addEventListener("click", function() { if (socket.readyState !== WebSocket.OPEN) { return; } const username = document.getElementById("username").value; const message = document.getElementById("message").value; if (!username.trim() || !message.trim()) { return; } socket.send(JSON.stringify({ username: username, message: message })); document.getElementById("message").value = ""; }); </script> </body> </html>

File: server.js

const WebSocket = require("ws"); const server = new WebSocket.Server({ port: 8080 }); server.on("connection", function(socket) { console.log("New user connected"); socket.on("message", function(data) { let message; try { message = JSON.parse(data.toString()); } catch (error) { socket.send("Invalid message format"); return; } const response = message.username + ": " + message.message; console.log(response); // Broadcast to every connected client server.clients.forEach(function(client) { if (client.readyState === WebSocket.OPEN) { client.send(response); } }); }); socket.on("close", function() { console.log("User disconnected"); }); }); console.log("Chat server running on port 8080");

Run the Application

  1. Start the server using node server.js.
  2. Open client.html in a browser through a local development server.
  3. Open the same client page in another tab.
  4. Enter a username and message.
  5. Click Send Message.
  6. Observe the message in both connected clients.
This is a basic demonstration, not a production chat system. Production systems need authentication, message validation, rate limiting, origin checks, authorization, connection cleanup and secure transport.

18. WebSockets vs HTTP

Feature HTTP WebSocket
Communication Request-response model. Full-duplex communication.
Connection Requests are handled through HTTP connections. Persistent connection after handshake.
Server Initiated Data Normally requires a client request or another mechanism. Server can send messages independently.
Overhead HTTP headers are used for each request. Frames have relatively small protocol overhead.
Typical Use Web pages, REST APIs and file transfer. Chat, live updates and interactive applications.

19. WebSockets vs Polling

Polling

Polling is a technique in which a client repeatedly sends requests to the server to check whether new information is available.

setInterval(function() { fetch("/check-updates") .then(response => response.json()) .then(data => console.log(data)); }, 5000);

WebSockets

WebSockets maintain a persistent connection through which either side can send messages.

Feature Polling WebSockets
Connection Repeated requests. Persistent connection.
Server Updates Client checks periodically. Server can push messages.
Overhead Repeated HTTP request overhead. Less repeated protocol overhead.
Use Case Occasional update checks. Frequent real-time communication.

20. WebSockets vs Server-Sent Events (SSE)

Server-Sent Events provide a mechanism for a server to send event updates to a browser over an HTTP connection.

Feature WebSockets Server-Sent Events
Communication Bidirectional. Server to client.
Protocol WebSocket protocol. HTTP.
Data Text and binary messages. Text-based event stream.
Browser API WebSocket. EventSource.
Typical Use Chat and interactive communication. Live feeds and notifications.

21. WebSocket Security

WebSocket applications need security controls because they maintain long-lived connections and exchange data continuously.

  • Use wss:// for encrypted communication.
  • Authenticate users before allowing protected operations.
  • Validate and sanitize incoming messages.
  • Check the Origin header on the server.
  • Apply authorization to individual operations.
  • Limit message sizes and message frequency.
  • Handle connection timeouts and cleanup.
  • Avoid exposing sensitive information in messages.
  • Log security events without recording secrets.
WebSocket connections do not automatically provide application-level authentication or authorization. These must be implemented by the application and server.

22. WebSocket Limitations

  • Requires a WebSocket-capable server.
  • Long-lived connections consume server resources.
  • Connection management is more complex than simple HTTP requests.
  • Network interruptions can close connections.
  • Applications may need reconnection logic.
  • Security controls must be implemented carefully.
  • Scaling to many simultaneous connections requires planning.

23. Common WebSocket Mistakes

  1. Calling send() before the connection opens.
  2. Ignoring the close event.
  3. Not handling errors.
  4. Using ws:// on an HTTPS production website.
  5. Assuming a WebSocket server is available without implementing one.
  6. Not validating incoming messages.
  7. Forgetting to close connections when no longer required.
  8. Assuming every message contains JSON.
  9. Not handling reconnection after network failure.

26. Interview Questions and Answers

Q1. What is WebSocket?
WebSocket is a protocol that enables full-duplex communication between a client and server over a persistent connection.
Q2. What is full-duplex communication?
It allows both communicating sides to send data independently at the same time.
Q3. What is the difference between ws and wss?
ws is the non-TLS WebSocket scheme, while wss provides TLS-protected WebSocket communication.
Q4. How does a WebSocket connection begin?
It begins with an HTTP opening handshake that requests a protocol upgrade.
Q5. What does HTTP status 101 indicate?
It indicates that the server is switching protocols, such as upgrading the connection to WebSocket.
Q6. Which JavaScript constructor creates a WebSocket?
The WebSocket constructor: new WebSocket(url).
Q7. What is readyState?
It indicates whether the WebSocket is connecting, open, closing or closed.
Q8. What is the purpose of send()?
It sends data to the server through an open WebSocket connection.
Q9. Which event handles received messages?
The message event.
Q10. What does close() do?
It begins the WebSocket closing handshake.
Q11. Can WebSockets transmit binary data?
Yes. WebSockets support text and binary messages, including ArrayBuffer and Blob.
Q12. What is the difference between WebSockets and polling?
Polling repeatedly sends requests to check for updates, whereas WebSockets maintain a persistent bidirectional connection.
Q13. What is Server-Sent Events?
SSE is an HTTP-based mechanism that allows a server to push event updates to a browser.
Q14. Why is wss recommended for production?
It protects WebSocket communication using TLS, providing encryption and server authentication.
Q15. Give examples of WebSocket applications.
Chat systems, online games, live dashboards, notifications, collaborative editing and real-time monitoring.
