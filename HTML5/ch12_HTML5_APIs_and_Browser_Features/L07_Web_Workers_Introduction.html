Lesson 7: Web Workers Introduction

Chapter 12: HTML5 APIs and Browser Features

Learn how JavaScript can perform background tasks without blocking the main user interface thread.

1. Introduction to Web Workers

A Web Worker is a browser feature that allows JavaScript code to execute in a background thread, separate from the main execution thread of a web page.

Normally, JavaScript running in the main thread handles user interactions, page updates, event processing and other tasks.

If a long-running calculation occupies the main thread, the browser may become unresponsive. Web Workers help move suitable computational tasks away from the main thread.

Applications of Web Workers

  • Large mathematical calculations.
  • Processing large datasets.
  • Image and data processing.
  • Background parsing of data.
  • Cryptographic computations.
  • Complex application calculations.
A Web Worker does not automatically make every application faster. It is useful when a suitable task can run independently of the user interface.

2. Understanding the Main Thread

The main thread is responsible for important browser activities such as:

  • Processing user interactions.
  • Executing ordinary page JavaScript.
  • Updating the DOM.
  • Handling many browser events.
  • Coordinating visual rendering.

JavaScript normally executes one task at a time on a particular thread. A long synchronous operation can prevent the browser from responding promptly to user interactions.

Example of a Blocking Task

function calculate() { let total = 0; for (let i = 0; i < 1000000000; i++) { total += i; } console.log(total); } calculate();

A sufficiently large loop can keep the main thread busy and delay page interaction.

3. Main Thread vs Web Worker

Feature Main Thread Web Worker
Execution Runs page JavaScript. Runs JavaScript in a separate worker thread.
DOM Access Can access the page DOM. Cannot directly access the page DOM.
User Interface Handles page interaction and updates. Does not directly update the page DOM.
Communication Uses normal JavaScript execution. Communicates through messages and supported shared-memory mechanisms.
Typical Tasks UI events and DOM operations. Calculations and independent processing.

4. Types of Web Workers

1. Dedicated Worker

A Dedicated Worker is associated with the script or browsing context that created it. It is commonly used by a single page or application context.

2. Shared Worker

A Shared Worker can be accessed by multiple browsing contexts, such as pages from the same origin that connect to the same worker.

3. Service Worker

A Service Worker is an event-driven worker that can act as a programmable network proxy. It is commonly used for offline support, caching and background-related web features.

Dedicated Workers, Shared Workers and Service Workers have different purposes and lifecycle rules. A Service Worker is not simply another type of calculation worker.

5. Creating a Web Worker

A dedicated Web Worker is created using the Worker constructor.

Syntax

const worker = new Worker("worker.js");

The worker.js file contains the JavaScript code that executes in the worker context.

Example Project Structure

6. Worker Communication

The main thread and a worker communicate using message-passing methods.

Main Thread Methods

  • postMessage(): Sends a message to the worker.
  • onmessage: Handles messages received from the worker.
  • addEventListener("message"): Registers a message event listener.

Worker Methods

  • postMessage(): Sends a message to the main thread.
  • onmessage: Handles messages received from the main thread.
  • close(): Terminates the worker's own execution.

7. First Web Worker Program

This example sends a message from the main page to a worker. The worker processes the message and sends a response.

File 1: index.html

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>First Web Worker</title> </head> <body> <h2>Web Worker Example</h2> <button id="sendButton">Send Message</button> <p id="result">Waiting for worker...</p> <script> const worker = new Worker("worker.js"); document.getElementById("sendButton") .addEventListener("click", function() { worker.postMessage("Hello Worker"); }); worker.onmessage = function(event) { document.getElementById("result").textContent = event.data; }; worker.onerror = function(event) { document.getElementById("result").textContent = "Worker error: " + event.message; }; </script> </body> </html>

File 2: worker.js

onmessage = function(event) { const receivedMessage = event.data; const response = "Worker received: " + receivedMessage; postMessage(response); };
Expected Output: 
Worker received: Hello Worker

When the user clicks the button, the main thread sends a message. The worker receives it and returns a response.

8. postMessage() Method

postMessage() is used to send data between the main thread and a worker.

Main Thread to Worker

worker.postMessage("Hello Worker");

Worker to Main Thread

postMessage("Hello Main Thread");

Messages are normally structured-cloned. Many JavaScript values can be transferred through this mechanism, but functions and DOM nodes cannot be cloned as ordinary message data.

Some objects support transfer rather than ordinary copying. Transferable objects such as ArrayBuffer can move ownership to the receiving context.

9. onmessage Event

The message event occurs when a message is received from another context.

Main Thread Example

worker.onmessage = function(event) { console.log("Response:", event.data); };

Worker Example

onmessage = function(event) { console.log("Received:", event.data); };

10. Worker Error Handling

Worker errors can be handled using the error event.

Example

worker.onerror = function(event) { console.error("Worker error:", event.message); };

The addEventListener() approach can also be used.

worker.addEventListener("error", function(event) { console.error(event.message); });

Error handling is important when a worker performs complex calculations or loads external resources.

11. Terminating a Web Worker

A worker can be stopped using terminate() from the main thread.

Example

worker.terminate();

terminate() immediately stops the worker. It does not give the worker an opportunity to finish its current task.

Worker Self-Termination

A worker can also stop itself by calling close().

close();
Method Called From Purpose
terminate() Main thread Immediately stops the worker.
close() Worker Stops the worker's own execution.

12. Practical Program: Background Calculation

This example calculates the sum of numbers from 1 to a user-provided limit in a worker.

File 1: index.html

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>Background Calculation</title> </head> <body> <h2>Background Calculation</h2> <input type="number" id="limit" value="1000000" min="1"> <button id="calculate">Calculate Sum</button> <p id="result">Result will appear here.</p> <script> const worker = new Worker("sum-worker.js"); document.getElementById("calculate") .addEventListener("click", function() { const limit = Number( document.getElementById("limit").value ); if (!Number.isSafeInteger(limit) || limit < 1 || limit > 100000000) { document.getElementById("result").textContent = "Enter a safe integer from 1 to 100000000."; return; } document.getElementById("result").textContent = "Calculating..."; worker.postMessage(limit); }); worker.onmessage = function(event) { document.getElementById("result").textContent = "Sum = " + event.data; }; worker.onerror = function(event) { document.getElementById("result").textContent = "Calculation failed: " + event.message; }; </script> </body> </html>

File 2: sum-worker.js

onmessage = function(event) { const limit = event.data; let sum = 0; for (let i = 1; i <= limit; i++) { sum += i; } postMessage(sum); };
Expected Output for limit = 100: 
Sum = 5050

The calculation takes place in the worker. The main thread remains available to handle page interactions.

14. Importing JavaScript Files into a Worker

A classic worker can load additional scripts using importScripts().

Syntax

importScripts("helper.js");

Multiple scripts can be loaded in one call.

importScripts("math.js", "utility.js");

Example

File: math.js

function square(number) { return number * number; }

File: worker.js

importScripts("math.js"); onmessage = function(event) { const result = square(event.data); postMessage(result); };
importScripts() is available in classic workers. Module workers use JavaScript module imports instead.

15. Dedicated Worker vs Shared Worker

Feature Dedicated Worker Shared Worker
Connection Associated with its creating context. Can serve multiple connected contexts.
Creation Worker constructor. SharedWorker constructor.
Communication postMessage() and message events. Communication through connected ports.
Use Case Background task for one application context. Shared functionality across pages.

Shared Worker Creation

const sharedWorker = new SharedWorker("shared-worker.js"); sharedWorker.port.start(); sharedWorker.port.postMessage("Hello Shared Worker"); sharedWorker.port.onmessage = function(event) { console.log(event.data); };

Shared Worker File: shared-worker.js

onconnect = function(event) { const port = event.ports[0]; port.onmessage = function(messageEvent) { port.postMessage( "Received: " + messageEvent.data ); }; };

Shared Workers communicate with connected pages through MessagePort objects.

17. Web Workers and Shared Memory

By default, Web Workers communicate through message passing. They can also use certain shared-memory mechanisms.

SharedArrayBuffer

SharedArrayBuffer allows multiple execution contexts to access shared memory.

Atomics

The Atomics object provides operations for safely coordinating access to shared memory.

const sharedBuffer = new SharedArrayBuffer(4); const sharedArray = new Int32Array(sharedBuffer); Atomics.store(sharedArray, 0, 100); const value = Atomics.load(sharedArray, 0); console.log(value);
SharedArrayBuffer is subject to browser security requirements. In modern browsers, it generally requires a secure, cross-origin-isolated context. Shared memory needs careful synchronization.

18. Limitations of Web Workers

  • Cannot directly manipulate the page DOM.
  • Cannot directly access the window object.
  • Communication introduces message-handling overhead.
  • Creating too many workers can waste resources.
  • Workers require additional lifecycle management.
  • Some browser APIs are unavailable inside workers.
  • Worker creation and resource loading can fail.

19. Browser Support and Execution Requirements

Web Workers are supported by modern browsers. However, the exact features available can depend on browser support and worker type.

  • Use a supported browser.
  • Keep worker files at valid URLs.
  • Serve worker scripts from permitted origins.
  • Use a local development server for testing.
  • Handle worker loading and runtime errors.
Some browsers restrict workers when HTML is opened directly using the file:// protocol. For reliable testing, use localhost or a web server such as GitHub Pages.

20. Web Workers vs setTimeout()

Feature Web Worker setTimeout()
Execution Runs in a separate worker thread. Schedules a callback on the current event loop.
CPU-intensive work Can move suitable work off the main thread. Does not move computation off the main thread.
DOM access No direct access to page DOM. Can access DOM when executed in the main thread.
Communication Uses messages. Uses normal JavaScript variables and callbacks.
Typical use Background computation. Delayed execution.

23. Interview Questions and Answers

Q1. What is a Web Worker?
A Web Worker executes JavaScript in a separate background thread, allowing suitable tasks to run without blocking the main thread.
Q2. Why are Web Workers used?
They are used for computationally intensive or independent background tasks that could otherwise block the user interface.
Q3. What is the main thread?
It is the browser thread that runs page JavaScript and handles DOM-related work and user interface operations.
Q4. How do you create a Web Worker?
Use the Worker constructor: new Worker("worker.js").
Q5. What is postMessage()?
It sends data between the main thread and a worker.
Q6. What is the onmessage event?
It handles messages received from another execution context.
Q7. Can Web Workers access the DOM?
No. Standard workers cannot directly access the document or page DOM.
Q8. How can a worker be terminated?
The main thread calls terminate(), or the worker calls close() to stop itself.
Q9. What is a Dedicated Worker?
It is a worker associated with the context that created it.
Q10. What is a Shared Worker?
It is a worker that can be connected to by multiple browsing contexts.
Q11. What is a Service Worker?
It is an event-driven worker commonly used for network interception, caching and offline application functionality.
Q12. What is importScripts()?
It loads external JavaScript files into a classic worker.
Q13. What is SharedArrayBuffer?
It provides memory that can be shared between supported execution contexts.
Q14. What is the Atomics object?
It provides atomic operations for coordinating shared-memory access.
Q15. Does setTimeout() create a new thread?
No. It schedules a callback on the relevant event loop. It does not move CPU-intensive JavaScript computation to a worker thread.
