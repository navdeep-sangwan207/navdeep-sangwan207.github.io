After completing this lesson, you will be able to:

2. Introduction to HTML Errors

HTML errors are mistakes in the structure, syntax or usage of HTML elements and attributes. These mistakes may cause unexpected rendering, accessibility problems, broken links, or validation failures.

Browsers use error-recovery algorithms to parse many incorrect HTML documents. Therefore, a webpage may still appear even when its source contains errors.

Important: A browser displaying a webpage successfully does not prove that the HTML document is conforming or accessible.

3. Missing Closing Tags

Some HTML elements require closing tags. Forgetting a required closing tag can produce unexpected document structure.

Incorrect Example

<h1>Welcome to HTML
<p>Learn HTML5 programming.

Correct Example

<h1>Welcome to HTML</h1>

<p>Learn HTML5 programming.</p>
Always close elements that require end tags. Void elements such as img, br, hr and input do not have closing tags.

4. Incorrect Element Nesting

HTML elements must follow their content model rules. Incorrect nesting can produce invalid markup and unexpected browser parsing.

Incorrect Example

<p>
    This is a paragraph.
    <div>This is a division.</div>
</p>

A paragraph cannot contain a division element. The browser automatically closes the paragraph before the division.

Correct Example

<p>This is a paragraph.</p>

<div>This is a division.</div>

Another Incorrect Example

<b>
    <i>HTML Programming
</b>
    </i>

Correct Example

<b>
    <i>HTML Programming</i>
</b>
Rule: Close nested elements in the reverse order in which they were opened, while also respecting the HTML content model.

5. Incorrect DOCTYPE Declaration

The DOCTYPE declaration tells the browser which document type is being used. Modern HTML documents should use the HTML5 declaration.

Incorrect Examples

<DOCTYPE html>

<!DOCTYPE HTML5>

<html doctype="html">

Correct Declaration

<!DOCTYPE html>

Place the declaration at the beginning of the document, before the html element.

6. Missing or Incorrect HTML Attributes

Attributes provide additional information about HTML elements. Incorrect attribute names or values can cause unexpected behavior or validation errors.

Incorrect Example

<img scr="photo.jpg">

<a href="about.html" target="_blank">
    About
</a>

<input type="emial">

Problems:

  • scr should be src.
  • The new-tab link does not specify a purpose-related issue, but modern practice should include an appropriate rel value when needed.
  • emial is not a valid input type; it should be email.

Correct Example

<img src="photo.jpg" alt="Profile photograph">

<a href="about.html"
   target="_blank"
   rel="noopener noreferrer">
    About
</a>

<input type="email" name="email">

7. Duplicate Attributes

An HTML element must not contain the same attribute more than once.

Incorrect Example

<img src="photo.jpg"
     alt="Student"
     alt="Profile Image">

Correct Example

<img src="photo.jpg"
     alt="Student profile photograph">
Duplicate attributes are a markup conformance error. Do not depend on browser behavior to determine which duplicate value will be used.

8. Incorrect Heading Structure

HTML provides six heading levels, from h1 to h6. They represent the hierarchy of document sections.

Problematic Example

<h1>HTML Course</h1>

<h4>Introduction</h4>

<h2>HTML Basics</h2>

The heading levels do not reflect a logical hierarchy. Skipping levels can make the document outline harder to understand.

Improved Example

<h1>HTML Course</h1>

<h2>Introduction</h2>

<h3>HTML Basics</h3>
Heading levels should reflect the content hierarchy. Skipping a level is not automatically an HTML syntax error, but a logical heading structure improves accessibility and navigation.

9. Broken Hyperlinks and Incorrect Paths

A hyperlink may fail when its URL is incorrect, the target file does not exist, or the path is not relative to the current document.

Incorrect Example

<a href="abotu.html">About</a>

If the actual file is named about.html, the misspelled filename causes a broken link.

Correct Example

<a href="about.html">About</a>

Understanding Relative Paths

website/
│
├── index.html
├── about.html
│
└── courses/
    ├── index.html
    └── html.html

From the root index.html:

<a href="about.html">About</a>

<a href="courses/index.html">Courses</a>

From courses/html.html:

<a href="../about.html">About</a>

<a href="index.html">Course Home</a>
GitHub Pages paths are case-sensitive. For example, About.html and about.html may refer to different paths.

10. Image Errors

Image problems commonly occur because of incorrect filenames, incorrect folder paths, missing files or missing alternative text.

Incorrect Example

<img scr="images/profile.jpg">

Correct Example

<img
    src="images/profile.jpg"
    alt="Profile photograph"
    width="200"
    height="200">

Common Image Problems

  • Incorrect src attribute.
  • Misspelled image filename.
  • Incorrect image directory.
  • Incorrect filename extension.
  • Missing image file.
  • Missing or unsuitable alternative text.
Use an empty alt="" for decorative images that should be ignored by assistive technology. Use descriptive alternative text for meaningful images.

11. Form-Related HTML Errors

Incorrect form controls and missing labels can create usability, accessibility and data-submission problems.

Incorrect Example

<form>

    <input type="text">

    <input type="email" required>

    <button>Submit</button>

</form>

Problems:

  • Inputs do not have associated labels.
  • Controls do not have useful names for form submission.
  • The form does not specify a submission destination.

Improved Example

<form action="/submit" method="post">

    <label for="username">Username:</label>
    <input type="text"
           id="username"
           name="username"
           required>

    <label for="email">Email:</label>
    <input type="email"
           id="email"
           name="email"
           required>

    <button type="submit">Submit</button>

</form>
The form action is illustrative. A real server-side endpoint must exist to process submitted data. HTML alone does not provide backend form processing.

12. Incorrect Use of Void Elements

Void elements cannot contain child elements and do not have closing tags in HTML.

Common Void Elements

  • area
  • base
  • br
  • col
  • embed
  • hr
  • img
  • input
  • link
  • meta
  • source
  • track
  • wbr

Incorrect Example

<img src="photo.jpg"></img>

<br></br>

Correct Example

<img src="photo.jpg" alt="Photograph">

<br>
In HTML, a trailing slash in a void element, such as <img />, is permitted but is not required. It does not make ordinary non-void elements self-closing.

13. Incorrect HTML Comments

HTML comments are written using <!-- and -->. Incorrect comment syntax may cause markup to be interpreted unexpectedly.

Incorrect Example

<!-- This is a comment

<p>Welcome to HTML</p>

Correct Example

<!-- This is a comment -->

<p>Welcome to HTML</p>
Do not put sensitive information, passwords or secret configuration details in HTML comments. Comments are visible in the page source.

14. Obsolete HTML Elements and Attributes

Older HTML documents may contain elements and attributes that are obsolete or non-conforming in modern HTML.

Obsolete Usage Modern Approach
<font> Use CSS for font styling.
<center> Use CSS text alignment or layout properties.
<big> Use CSS font-size.
<strike> Use CSS text-decoration or appropriate semantic markup.
bgcolor Use CSS background-color.
align for presentation Use CSS text-align or layout properties.

Old Style

<center>
    <font color="blue" size="5">
        Welcome to HTML
    </font>
</center>

Modern HTML Approach

<h1>Welcome to HTML</h1>

Use a CSS rule for presentation in a stylesheet. CSS is covered separately in the CSS3 course.

15. Incorrect Character Encoding

Character encoding defines how text characters are represented in a document. An incorrect or missing encoding declaration may cause some characters to display incorrectly.

Recommended Declaration

<head>
    <meta charset="UTF-8">
    <title>My Website</title>
</head>

UTF-8 supports a broad range of characters and is the recommended encoding for modern HTML documents.

17. How to Debug HTML Errors

Step-by-Step Debugging Process

  1. Open the HTML document in a code editor.
  2. Check the DOCTYPE declaration and document structure.
  3. Inspect opening and closing tags.
  4. Verify element nesting.
  5. Check attribute names and values.
  6. Verify image and hyperlink paths.
  7. Open the page in a browser.
  8. Use browser Developer Tools to inspect the DOM and related problems.
  9. Submit the HTML source to the W3C Validator.
  10. Correct errors and repeat the validation process.

Useful Browser Developer Tools

  • Elements/Inspector: Inspect the parsed DOM.
  • Console: Review browser-reported errors and warnings.
  • Network: Identify failed image, script and other resource requests.
  • Accessibility tools: Inspect accessible names and document structure.
Remember that the browser DOM inspector displays the parsed document. The browser may repair invalid source markup, so inspect the original source and use a validator as well.

18. Practical Lab Exercise

Objective

Identify and correct common HTML errors in a student information webpage.

Incorrect HTML Code

<DOCTYPE html>
<html>

<head>
    <title>Student Page</title>
</head>

<body>

    <h1>Student Information

    <p>Name: Rahul</p>

    <img scr="student.jpg">

    <a href="about.html">About

    <input type="emial">

    <div>
        <p>Student Details</div>
    </p>

</body>
</html>

Corrected HTML Code

<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Student Page</title>
</head>

<body>

    <h1>Student Information</h1>

    <p>Name: Rahul</p>

    <img src="student.jpg"
         alt="Student photograph">

    <a href="about.html">About</a>

    <input type="email" name="email">

    <div>
        <p>Student Details</p>
    </div>

</body>
</html>

Expected Result

  • A properly structured HTML document.
  • A valid HTML5 DOCTYPE declaration.
  • Correct heading and paragraph elements.
  • A correctly written image element.
  • A working About hyperlink if the target file exists.
  • A correctly specified email input.
  • Properly nested division and paragraph elements.
The image and About page must exist at the specified relative paths for those resources to load successfully.

19. Interview Questions and Answers

Q1. What are HTML errors?

HTML errors are mistakes in document syntax, structure or element and attribute usage.

Q2. What is incorrect nesting?

Incorrect nesting occurs when elements are placed inside other elements in a way that violates their content models.

Q3. What are void elements?

Void elements are elements that cannot contain child content and do not have closing tags, such as img, br and input.

Q4. What happens when a closing tag is missing?

The browser may recover by applying HTML parsing rules, but the resulting DOM may differ from the developer's intended structure.

Q5. Can an HTML element contain duplicate attributes?

No. Duplicate attributes make the markup non-conforming.

Q6. What is a broken hyperlink?

A broken hyperlink points to a missing, unavailable or incorrectly specified destination.

Q7. What is the purpose of the alt attribute?

It provides alternative text for an image, particularly useful for assistive technology and when the image cannot be displayed.

Q8. What is the difference between HTML syntax and accessibility errors?

Syntax errors violate markup rules. Accessibility problems prevent or make it difficult for people with disabilities to use the page. A page can be syntactically valid but inaccessible.

Q9. What is the purpose of the lang attribute?

It identifies the language of an element or document, supporting pronunciation and language processing.

Q10. Why should obsolete HTML elements be avoided?

They are outdated or non-conforming for modern authoring. Modern semantic HTML and CSS provide better alternatives.

Q11. How can a developer find broken image paths?

Check the image filename and relative path, inspect the browser Network panel and verify that the image file exists.

Q12. What is the purpose of browser Developer Tools?

They help inspect the DOM, debug resource-loading problems, view console messages and examine page behavior.

Q13. Why is UTF-8 used in HTML documents?

UTF-8 supports characters from many writing systems and is the recommended character encoding for modern web documents.

Q14. Does the browser automatically correct all HTML errors?

No. Browsers recover from many parsing errors, but they cannot guarantee the intended structure or behavior.

Q15. How can HTML errors be prevented?

Follow HTML standards, use an editor with syntax highlighting, check element nesting, validate source code and test the page.

21. Lesson Summary

  • HTML errors can occur in syntax, structure and attributes.
  • Required closing tags must be used correctly.
  • Elements must follow their content model and nesting rules.
  • Duplicate attributes are not allowed.
  • Correct paths are essential for images and hyperlinks.
  • Forms should use meaningful names and associated labels.
  • Void elements do not have closing tags.
  • Modern HTML should avoid obsolete presentational markup.
  • Browser Developer Tools help identify rendering and resource problems.
  • HTML validation helps detect markup conformance errors.
