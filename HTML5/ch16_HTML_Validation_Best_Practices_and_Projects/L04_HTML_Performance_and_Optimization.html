2. What is Website Performance?

Website performance refers to how quickly and efficiently a web page loads, displays content and responds to user interactions.

A well-optimized website provides a better user experience by reducing unnecessary waiting time and resource consumption.

Important Performance Factors

  • HTML document size.
  • Image and video file sizes.
  • CSS and JavaScript file sizes.
  • Number of HTTP requests.
  • Server response time.
  • Network bandwidth and latency.
  • Browser rendering and JavaScript execution.
  • Third-party resources and embedded content.
HTML is only one part of website performance. Network, server, CSS, JavaScript, images, fonts and browser rendering all contribute to the final loading experience.

3. Why is Performance Optimization Important?

Benefits

  • Faster page loading.
  • Improved user experience.
  • Better usability on mobile networks.
  • Reduced data consumption.
  • Lower resource requirements.
  • Improved accessibility for users with limited connectivity.
  • Potential improvements in search visibility.
  • Better performance on low-powered devices.

Example

Consider two websites:

Website A Website B
Large unoptimized images Compressed and appropriately sized images
Unnecessary scripts Only required scripts
Many unnecessary requests Efficient resource loading
Large page downloads Optimized page resources

Website B will generally transfer fewer bytes and may load faster, depending on network conditions and server behavior.

4. Optimize HTML Document Structure

Clean and efficient HTML helps browsers parse the document and makes it easier for developers to maintain the page.

Unnecessarily Complicated HTML

<div>
    <div>
        <div>
            <div>
                <p>Welcome to our website.</p>
            </div>
        </div>
    </div>
</div>

Simplified HTML

<p>Welcome to our website.</p>

Best Practices

  • Avoid unnecessary wrapper elements.
  • Use appropriate semantic elements.
  • Avoid deeply nested structures without a reason.
  • Remove unused elements.
  • Keep the document organized.
  • Use valid HTML markup.
Reducing unnecessary markup improves maintainability. The performance impact of removing a few elements is usually small compared with optimizing large images and scripts.

5. Image Optimization

Images often account for a significant portion of the data transferred when loading a website.

Image optimization means selecting suitable formats, dimensions and compression settings to reduce file size while maintaining acceptable visual quality.

Common Image Formats

Format Typical Usage
JPEG / JPG Photographs and complex images.
PNG Graphics requiring lossless quality or transparency.
WebP Web photographs and graphics with efficient compression.
AVIF Modern image delivery with high compression efficiency.
SVG Logos, icons and scalable vector graphics.
GIF Simple animations and limited-color graphics.

Example: Normal Image

<img src="large-photo.jpg"
     alt="Electronics laboratory">

Example: Optimized Image Dimensions

<img src="electronics-lab.webp"
     alt="Electronics laboratory"
     width="800"
     height="450">

Image Optimization Techniques

  • Use an appropriate image format.
  • Resize images to match their displayed dimensions.
  • Compress images before uploading.
  • Use modern formats where supported.
  • Provide meaningful alternative text.
  • Specify image width and height to reserve layout space.
  • Avoid unnecessarily large source images.
An image displayed at 400 pixels wide usually does not need a 5000-pixel-wide source file unless there is a specific high-resolution requirement.

6. Responsive Images

Responsive images allow the browser to select an appropriate image resource based on the device, viewport and display requirements.

Using srcset

<img
    src="image-800.jpg"
    srcset="
        image-400.jpg 400w,
        image-800.jpg 800w,
        image-1200.jpg 1200w
    "
    sizes="(max-width: 600px) 100vw,
           800px"
    alt="Electronics development board">

Explanation

  • src provides a fallback image URL.
  • srcset lists available image candidates.
  • sizes describes the expected rendered image width at different viewport conditions.
  • The browser selects an appropriate candidate using the available information and device characteristics.

Using the picture Element

<picture>

    <source
        srcset="electronics-board.avif"
        type="image/avif">

    <source
        srcset="electronics-board.webp"
        type="image/webp">

    <img
        src="electronics-board.jpg"
        alt="Electronics development board"
        width="800"
        height="500">

</picture>

The browser evaluates the source elements and uses the first suitable source it can display. The img element provides the fallback and alternative text.

7. Lazy Loading of Images

Lazy loading delays loading certain resources until they are close to being needed, rather than loading all resources immediately.

Normal Image Loading

<img src="course-image.jpg"
     alt="HTML course">

Lazy Loading

<img src="course-image.jpg"
     alt="HTML course"
     loading="lazy"
     width="600"
     height="350">

Loading Attribute Values

Value Meaning
lazy Browser may defer loading until the image approaches the viewport.
eager Load the resource without lazy-loading deferral.

When to Use Lazy Loading

  • Images far below the initial viewport.
  • Long article pages.
  • Large course catalogs.
  • Image galleries.
  • Pages containing many independent images.
Avoid lazy-loading the main image that is immediately visible and important for page display. It may delay the Largest Contentful Paint (LCP) element.

8. Eager Loading and Fetch Priority

Eager loading is appropriate when a resource is needed immediately during page loading.

Example

<img src="hero-image.webp"
     alt="HTML5 learning portal"
     width="1200"
     height="600"
     loading="eager"
     fetchpriority="high">

Fetch Priority Values

Value Meaning
high Indicates higher loading priority.
low Indicates lower loading priority.
auto Allows the browser to determine priority.
Fetch priority is a browser hint, not a guarantee of an exact loading order. Use it selectively for important resources.

9. Optimize Audio and Video Resources

Audio and video files can be significantly larger than ordinary HTML documents.

Video Optimization Example

<video
    controls
    width="640"
    height="360"
    preload="metadata"
    poster="video-thumbnail.jpg">

    <source
        src="html-course.mp4"
        type="video/mp4">

    Your browser does not support HTML video.

</video>

Audio Optimization Example

<audio controls preload="none">

    <source
        src="lesson-audio.mp3"
        type="audio/mpeg">

    Your browser does not support audio playback.

</audio>

Recommended Practices

  • Compress audio and video appropriately.
  • Select suitable media formats and codecs.
  • Use video poster images.
  • Use an appropriate preload value.
  • Avoid unnecessary autoplay.
  • Use streaming or external hosting for large media libraries when appropriate.
The preload attribute provides a hint to the browser. It does not guarantee exactly how much media will be downloaded.

10. Optimize CSS Resource Loading

CSS controls the presentation of HTML documents. Stylesheets can affect how quickly the browser displays the page.

External CSS Example

<head>

    <link rel="stylesheet"
          href="css/style.css">

</head>

Recommended Practices

  • Remove unused CSS rules.
  • Minify CSS for production.
  • Avoid loading unnecessary stylesheets.
  • Reuse shared styles across pages.
  • Use appropriate responsive CSS.
  • Load critical above-the-fold styles efficiently.

What is CSS Minification?

CSS minification removes unnecessary characters such as comments, whitespace and formatting characters without changing the stylesheet's intended behavior.

Before Minification

body {
    background-color: white;
    color: black;
}

h1 {
    font-size: 30px;
}

After Minification

body{background-color:white;color:black}h1{font-size:30px}

Minification can reduce transferred file size, especially when applied to large production stylesheets.

11. Optimize JavaScript Loading

JavaScript adds dynamic behavior and interaction to websites. However, unnecessary or poorly scheduled scripts can delay page rendering and user interaction.

Normal Script Loading

<script src="js/script.js"></script>

A classic script without async or defer can block HTML parsing while it is fetched and executed.

Using defer

<script src="js/script.js" defer></script>

A deferred classic external script downloads while HTML parsing continues and executes after parsing is complete, before the DOMContentLoaded event.

Using async

<script src="js/analytics.js" async></script>

An async classic external script executes as soon as it becomes available. It does not guarantee execution order relative to other async scripts.

Method Behavior
Normal Can block HTML parsing while fetching and executing.
defer Fetches in parallel and executes after document parsing, in document order.
async Fetches in parallel and executes when available; order is not guaranteed.
Use defer for many scripts that depend on the parsed document and require predictable document order. Use async for independent scripts when execution order is not important.

12. Reduce HTTP Requests

A browser may request HTML, CSS, JavaScript, images, fonts and other resources from servers.

Excessive resource requests can increase network overhead and page loading time.

Ways to Reduce Requests

  • Remove unused images and files.
  • Combine suitable small resources when beneficial.
  • Use efficient image formats.
  • Avoid unnecessary external libraries.
  • Reuse shared CSS and JavaScript files.
  • Remove duplicate resource references.
  • Limit unnecessary third-party embeds.
Combining files is not always beneficial with modern HTTP/2 and HTTP/3. Measure the actual result instead of assuming fewer requests always means better performance.

13. Browser Caching

Browser caching stores previously downloaded resources so they may be reused on subsequent visits.

Example

When a user visits a website, the browser may download its stylesheet, logo and JavaScript file. During a later visit, cached resources can be reused if their caching rules allow it.

Benefits

  • Reduces repeated downloads.
  • Can improve repeat-visit loading speed.
  • Reduces network data transfer.
  • Reduces repeated server requests.

Cache-Control Header Example

Cache-Control: public, max-age=31536000, immutable

This is an example of a long-lived caching policy suitable for versioned static assets that will not change at the same URL.

HTML cannot independently configure HTTP response caching policies. Cache-Control is an HTTP response header configured by the web server, CDN or hosting platform.

14. Compression of Web Resources

Compression reduces the amount of data transferred between a web server and a browser.

Common Compression Methods

Method Description
Gzip Widely used compression method for text-based resources.
Brotli Modern compression algorithm commonly used for web delivery.
Zstandard Compression method supported in some modern web delivery environments.

Benefits

  • Reduces transferred data size.
  • Can improve page loading on slower networks.
  • Reduces bandwidth consumption.
Compression is generally configured at the server or CDN level. HTML markup does not itself enable Gzip or Brotli.

15. Improve Font Loading

Web fonts affect typography and may delay text rendering or cause layout shifts if handled inefficiently.

Preload Important Fonts

<link
    rel="preload"
    href="fonts/site-font.woff2"
    as="font"
    type="font/woff2"
    crossorigin>

Font Optimization Practices

  • Use only required font families and weights.
  • Prefer efficient font formats such as WOFF2.
  • Use font subsetting where appropriate.
  • Preload only critical fonts.
  • Use appropriate fallback font families.
Preloading unnecessary fonts can compete with more important resources for network bandwidth. Use preload selectively.

16. Core Web Vitals

Core Web Vitals are Google's user-experience metrics used to evaluate important aspects of real-world page experience.

Metric Measures Good Threshold
LCP Loading performance 2.5 seconds or less
INP Interaction responsiveness 200 milliseconds or less
CLS Visual stability 0.1 or less

1. Largest Contentful Paint (LCP)

LCP measures how quickly the largest visible content element is rendered within the viewport.

2. Interaction to Next Paint (INP)

INP measures the responsiveness of a page to user interactions throughout a visit.

3. Cumulative Layout Shift (CLS)

CLS measures unexpected visual layout shifts during the page lifecycle.

Reserve image dimensions, avoid inserting unexpected content above existing content and optimize important resources to help improve loading and visual stability.

17. Avoid Layout Shifts

A layout shift occurs when visible page elements unexpectedly move during loading or interaction.

Problematic Image Example

<img src="course-image.jpg"
     alt="Course image">

Improved Image Example

<img src="course-image.jpg"
     alt="Course image"
     width="800"
     height="450">

Providing intrinsic dimensions allows the browser to calculate the image's aspect ratio and reserve layout space before the image finishes loading.

Other Techniques

  • Reserve space for advertisements and embeds.
  • Avoid injecting content above the current viewport unexpectedly.
  • Use stable image and video dimensions.
  • Use appropriate font-loading strategies.

18. Use Appropriate Resource Hints

Resource hints give the browser information that may help it prepare for important network operations.

Preconnect

<link rel="preconnect"
      href="https://example.com">

Preconnect allows the browser to establish an early connection to an important external origin.

DNS Prefetch

<link rel="dns-prefetch"
      href="//example.com">

DNS prefetch allows the browser to resolve a domain name before the resource is requested.

Preload

<link rel="preload"
      href="important-image.webp"
      as="image">

Preload tells the browser that a resource is important and may be needed soon.

Prefetch

<link rel="prefetch"
      href="next-page.html">

Prefetch indicates that a resource may be needed for a future navigation.

Resource hints are browser instructions or suggestions, not guarantees that a resource will be loaded at a particular time.

19. Performance Testing Tools

Performance should be measured rather than estimated. Browser developer tools and auditing services help identify performance problems.

Tool Purpose
Chrome DevTools Inspect network requests, rendering and performance traces.
Lighthouse Audit performance, accessibility, best practices and SEO.
PageSpeed Insights Analyze page performance using available lab and field data.
WebPageTest Analyze loading behavior under different test conditions.
Performance panel Investigate browser rendering and main-thread activity.

Browser Developer Tools

  1. Open a webpage in Google Chrome.
  2. Press F12.
  3. Open the Network tab.
  4. Reload the webpage.
  5. Inspect downloaded resources.
  6. Check file sizes and loading times.
  7. Identify unusually large or slow resources.

Useful Resources

  • Google PageSpeed Insights
  • Lighthouse Documentation
  • Web Vitals Documentation
  • Chrome DevTools Network Reference

20. Practical Lab Exercise

Objective

Create a performance-conscious HTML5 course page using optimized images, lazy loading, appropriate resource loading and semantic markup.

Complete Lab Code

<!DOCTYPE html>
<html lang="en">

<head>

    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Embedded Systems Learning Portal</title>

    <meta name="description"
          content="Explore embedded systems and electronics courses.">

    <link rel="stylesheet" href="css/style.css">

    <link rel="preconnect"
          href="https://example.com">

    <script src="js/script.js" defer></script>

</head>

<body>

    <header>

        <h1>Embedded Systems Learning Portal</h1>

        <p>
            Learn microcontrollers and embedded programming.
        </p>

    </header>

    <main>

        <section>

            <h2>Featured Course</h2>

            <img
                src="images/embedded-systems.webp"
                alt="Embedded systems development board"
                width="800"
                height="450"
                loading="eager"
                fetchpriority="high">

            <p>
                Explore microcontrollers, Embedded C and
                peripheral interfacing.
            </p>

        </section>

        <section>

            <h2>Additional Courses</h2>

            <img
                src="images/linux-course.webp"
                alt="Linux operating system course"
                width="600"
                height="350"
                loading="lazy">

            <img
                src="images/cpp-course.webp"
                alt="C++ programming course"
                width="600"
                height="350"
                loading="lazy">

            <img
                src="images/rtos-course.webp"
                alt="Real-time operating systems course"
                width="600"
                height="350"
                loading="lazy">

        </section>

    </main>

    <footer>

        <p>Copyright &copy; 2026 Learning Portal.</p>

    </footer>

</body>

</html>

Expected Result

  • A structured learning portal webpage.
  • A featured image with high loading priority.
  • Additional images using lazy loading.
  • An external stylesheet.
  • A deferred JavaScript file.
  • Semantic page structure.
The image paths, CSS file and JavaScript file are sample project resources. Create the corresponding files before testing the page. The example.com preconnect is illustrative; replace it with an origin actually used by your website or remove it.

21. Interview Questions and Answers

Q1. What is website performance?

It describes how quickly and efficiently a webpage loads, renders and responds to user interactions.

Q2. What is image optimization?

It is the process of reducing image file size while maintaining suitable visual quality.

Q3. What is lazy loading?

Lazy loading delays loading resources until they approach the point where they are needed.

Q4. What is eager loading?

Eager loading avoids lazy-loading deferral and is useful for resources needed immediately.

Q5. What is responsive image loading?

It allows browsers to select suitable image resources based on viewport and device requirements.

Q6. What is the purpose of srcset?

It provides multiple image candidates from which the browser can select an appropriate resource.

Q7. What is the purpose of the picture element?

It provides multiple image sources for different formats or art-direction requirements.

Q8. What is CSS minification?

It removes unnecessary characters from CSS files to reduce their transferred size.

Q9. What is the difference between async and defer?

Async executes an external script when it becomes available. Defer executes a classic external script after HTML parsing, preserving document order.

Q10. What is browser caching?

It stores resources so that the browser may reuse them instead of downloading them again.

Q11. What is resource compression?

It reduces the amount of data transferred between the server and browser.

Q12. What is LCP?

Largest Contentful Paint measures when the largest visible content element is rendered.

Q13. What is INP?

Interaction to Next Paint measures responsiveness to user interactions.

Q14. What is CLS?

Cumulative Layout Shift measures unexpected visual movement of page elements.

Q15. What is the purpose of preload?

Preload tells the browser that a resource is important and may be required soon.
