Building a Complete Multipage Website

HTML5 Complete Study Course | Chapter 16

1. Introduction

A multipage website is a collection of interconnected web pages that belong to the same website. Each page generally provides information about a particular topic or service.

For example, an educational website may contain separate pages for Home, About, Courses, Projects, and Contact.

Definition: A multipage website is a website consisting of multiple HTML documents connected through hyperlinks and navigation menus.

2. Single-Page vs Multipage Website

Single-Page Website Multipage Website
Most content is presented in one HTML document. Content is distributed across multiple HTML documents.
Navigation often uses sections and fragment links. Navigation commonly uses links to separate pages.
Suitable for simple portfolios and landing pages. Suitable for educational portals, business websites, and documentation.
May become difficult to maintain when content grows. Content can be organized into separate pages and sections.

3. Planning a Multipage Website

Before writing HTML, identify the purpose of the website, its target audience, required pages, and navigation structure.

Example: Educational Learning Portal

Home Page

Introduces the learning portal and provides access to its sections.

About Page

Explains the purpose, objectives, and background of the portal.

Courses Page

Displays available courses such as C++, Linux, and Embedded Systems.

Projects Page

Displays practical projects and their descriptions.

Contact Page

Provides contact information and an enquiry form.

5. Creating Website Navigation

The HTML5 <nav> element identifies a section containing major navigation links.

Example Navigation Menu

<nav aria-label="Main navigation">
    <ul>
        <li><a href="index.html">Home</a></li>
        <li><a href="about.html">About</a></li>
        <li><a href="courses.html">Courses</a></li>
        <li><a href="projects.html">Projects</a></li>
        <li><a href="contact.html">Contact</a></li>
    </ul>
</nav>

Each anchor element points to a different HTML document. Selecting a link opens the corresponding page.

6. Understanding Relative File Paths

Relative paths specify the location of a resource with respect to the current HTML document.

Path Meaning
about.html File in the same directory.
courses/cpp.html File inside the courses directory.
../index.html Move one directory level up.
../../index.html Move two directory levels up.
Common mistake: An incorrect relative path can cause a broken link or missing image. Check paths carefully, especially when deploying to GitHub Pages.

7. Creating the Home Page

The home page is generally the main entry point of the website. It introduces the website and directs visitors to important pages.

Example: index.html

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Home | Learning Portal</title>
</head>
<body>

    <header>
        <h1>My Learning Portal</h1>
        <p>Learn technology through practical lessons.</p>
    </header>

    <nav aria-label="Main navigation">
        <a href="index.html">Home</a> |
        <a href="about.html">About</a> |
        <a href="courses.html">Courses</a> |
        <a href="projects.html">Projects</a> |
        <a href="contact.html">Contact</a>
    </nav>

    <main>
        <h2>Welcome</h2>
        <p>
            Explore programming, electronics, and
            embedded systems courses.
        </p>

        <h2>Explore Our Courses</h2>
        <ul>
            <li><a href="courses/cpp.html">C++ Programming</a></li>
            <li><a href="courses/linux.html">Linux</a></li>
            <li><a href="courses/embedded.html">Embedded Systems</a></li>
        </ul>
    </main>

    <footer>
        <p>&copy; 2026 My Learning Portal</p>
    </footer>

</body>
</html>

11. Creating the Contact Page

A Contact page displays contact details and may include an enquiry form.

Example: contact.html

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Contact | Learning Portal</title>
</head>
<body>

    <header>
        <h1>Contact Us</h1>
    </header>

    <nav aria-label="Main navigation">
        <a href="index.html">Home</a> |
        <a href="about.html">About</a> |
        <a href="courses.html">Courses</a> |
        <a href="projects.html">Projects</a> |
        <a href="contact.html">Contact</a>
    </nav>

    <main>
        <h2>Send an Enquiry</h2>

        <form action="#" method="get">
            <label for="name">Name:</label>
            <input type="text" id="name" name="name"
                   required>
            <br><br>

            <label for="email">Email:</label>
            <input type="email" id="email" name="email"
                   required>
            <br><br>

            <label for="message">Message:</label>
            <br>
            <textarea id="message" name="message"
                      rows="5" required></textarea>
            <br><br>

            <button type="submit">Submit</button>
        </form>
    </main>

    <footer>
        <p>&copy; 2026 My Learning Portal</p>
    </footer>

</body>
</html>
Important: This is an HTML form demonstration, not a working enquiry processing system. The action="#" attribute does not send submissions to an application backend. A real form requires a server-side endpoint or a suitable form service. Do not use GET to submit confidential information.

12. Using a Common Stylesheet

A shared CSS file helps maintain a consistent design across all pages. CSS is separate from HTML, but is used here to demonstrate how a real website is organized.

Example link in each HTML document:

<link rel="stylesheet" href="css/style.css">

When all HTML pages are in the root directory, the path above points to the same stylesheet. For pages inside a subdirectory, the path may need to change, for example: 

<link rel="stylesheet" href="../css/style.css">
HTML provides the structure and content. CSS controls presentation and layout. JavaScript adds client-side behaviour.

13. Testing a Multipage Website

After creating all pages, test the website before publishing it.

  1. Open the home page in a browser.
  2. Click every navigation link.
  3. Verify that all pages open correctly.
  4. Check relative paths for images and stylesheets.
  5. Test forms and their validation behaviour.
  6. Check the website on desktop and mobile screens.
  7. Validate HTML using the W3C HTML Checker.
  8. Check for broken links and missing resources.

14. Publishing on GitHub Pages

GitHub Pages can host static websites containing HTML, CSS, JavaScript, images, and other supported static resources.

  1. Create a GitHub repository.
  2. Upload the website files and folders.
  3. Ensure that the main entry file is named index.html.
  4. Open repository Settings.
  5. Select Pages.
  6. Choose the deployment source and branch.
  7. Save the configuration.
  8. Open the published website URL.
GitHub Pages provides static hosting. It does not execute server-side PHP, Python, Java, or database operations. Features such as user authentication, database storage, and enquiry processing require suitable external services or a separate backend.

15. Common Mistakes

Mistake Correction
Incorrect file paths Verify the relative path from the current HTML file.
Missing index.html Provide the expected entry page for the website.
Different navigation on every page Maintain consistent navigation links.
Duplicate page titles Give every page a meaningful, descriptive title.
Missing image alternative text Provide appropriate alt text for informative images.
Broken links after deployment Check filenames, capitalization, and directory structure.
Assuming an HTML form stores data Connect it to a backend or form-processing service.

17. Interview Questions and Answers

Q1. What is a multipage website?

A website containing multiple HTML documents connected through hyperlinks and navigation menus.

Q2. What is the purpose of index.html?

It is commonly used as the default entry document for a website or directory.

Q3. What is a relative URL?

A URL that identifies a resource relative to the location of the current document.

Q4. What is the purpose of the nav element?

It identifies a section containing major navigation links.

Q5. Why should navigation be consistent?

Consistent navigation improves usability and helps visitors move between pages predictably.

Q6. What is the purpose of a shared CSS file?

It allows multiple HTML pages to use the same presentation rules and reduces duplicated styling.

Q7. What is a broken link?

A hyperlink that points to a missing, incorrect, or inaccessible resource.

Q8. Can HTML alone create a database-driven website?

No. HTML defines document structure. Database-driven functionality requires server-side processing and a database.

Q9. Can GitHub Pages host a multipage website?

Yes. It can host static multipage websites containing HTML, CSS, JavaScript, and static assets.

Q10. What is the difference between a frontend and backend?

The frontend is the user-facing part of an application. The backend handles server-side logic, data processing, authentication, and database operations.

Q11. Why is semantic HTML important?

It gives content meaningful structure and improves accessibility, maintainability, and machine interpretation.

Q12. What should be checked before deploying a website?

Check navigation, paths, HTML validity, responsive behaviour, image loading, page titles, and form functionality.

Q13. Does an HTML form automatically store submitted data?

No. A form needs a valid submission destination and a system that receives and processes the submitted data.

Q14. Why should each page have a descriptive title?

A descriptive title identifies the page in browser tabs, bookmarks, and search result presentations.

Q15. What is website deployment?

Deployment is the process of publishing a website so that users can access it through a hosting environment.

19. Lesson Summary

  • A multipage website consists of multiple connected HTML documents.
  • Website planning should identify pages and their relationships.
  • Folder structures organize HTML documents and supporting resources.
  • The anchor element creates links between pages.
  • Relative paths depend on the current document's location.
  • The nav element identifies major navigation sections.
  • A shared stylesheet provides consistent presentation.
  • Testing and validation help identify errors before deployment.
  • GitHub Pages can publish static multipage websites.
  • Server-side features require a backend or external service.
