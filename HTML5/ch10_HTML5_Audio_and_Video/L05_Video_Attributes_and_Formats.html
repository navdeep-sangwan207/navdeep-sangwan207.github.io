Lesson 5: Video Attributes and Formats

Controlling Video Playback and Understanding Video Compatibility

1. Introduction

The HTML5 <video> element supports several attributes that control how video content is loaded, displayed and played.

Video formats and codecs determine how video data is stored, compressed and decoded by browsers.

In this lesson, we will study:

  • Video playback attributes
  • Autoplay and muted behavior
  • Loop and preload attributes
  • Poster images
  • Video containers and codecs
  • MIME types
  • Multiple video sources
  • Responsive video considerations

2. Controls Attribute

The controls attribute displays the browser's built-in video playback interface.

Example

<video controls width="600"> <source src="video.mp4" type="video/mp4"> </video>

Controls may include:

  • Play and pause buttons
  • Volume control
  • Playback progress bar
  • Mute control
  • Fullscreen option
The controls interface is browser-dependent. Its exact appearance and available features can vary.

3. Autoplay Attribute

The autoplay attribute asks the browser to start playing the video automatically when possible.

Example

<video autoplay width="600"> <source src="video.mp4" type="video/mp4"> </video>

However, modern browsers commonly restrict automatic playback of videos containing audible sound.

Autoplay is not guaranteed. Browsers may block automatic playback depending on sound, user interaction, browser policy and other conditions.

4. Muted Attribute

The muted attribute specifies that the video should initially have its audio muted.

Example

<video controls muted width="600"> <source src="video.mp4" type="video/mp4"> </video>

Muted playback is commonly used for background videos and autoplay experiences.

Autoplay with Muted

<video autoplay muted playsinline> <source src="background.mp4" type="video/mp4"> </video>

Muting can help satisfy browser autoplay policies, but autoplay is still subject to browser restrictions.

5. Loop Attribute

The loop attribute causes the video to restart automatically after reaching its end.

Example

<video controls loop width="600"> <source src="demo.mp4" type="video/mp4"> </video>

Common applications include:

  • Short demonstrations
  • Animated backgrounds
  • Product displays
  • Repeated training demonstrations

6. Preload Attribute

The preload attribute provides the browser with a hint about how much video data should be loaded before the user starts playback.

It supports three common values:

Value Meaning
none Hints that the browser should avoid preloading video data.
metadata Hints that only metadata should be loaded.
auto Allows the browser to decide that downloading the video is appropriate.

Example: preload="none"

<video controls preload="none" width="600"> <source src="lecture.mp4" type="video/mp4"> </video>

Example: preload="metadata"

<video controls preload="metadata"> <source src="lecture.mp4" type="video/mp4"> </video>

Example: preload="auto"

<video controls preload="auto"> <source src="lecture.mp4" type="video/mp4"> </video>
Preload is a hint, not a command. Browser behavior, network conditions and autoplay policies can affect how much media is actually loaded.

7. Poster Attribute

The poster attribute specifies an image that represents the video before playback begins.

It is commonly used as a video thumbnail or preview image.

Example

<video controls width="600" poster="images/video-thumbnail.jpg"> <source src="tutorial.mp4" type="video/mp4"> </video>

The poster image may be displayed before the video starts playing. It is not a replacement for the video.

  • Improves the initial visual presentation.
  • Provides a preview of video content.
  • Can make a video player more informative.
Use a suitable image file and provide an accurate path in the poster attribute.

8. Width and Height Attributes

The width and height attributes specify the displayed dimensions of the video element.

Example

<video controls width="640" height="360"> <source src="video.mp4" type="video/mp4"> </video>

The dimensions should normally preserve the video's original aspect ratio.

Incorrect dimensions can distort the video. For responsive pages, CSS is often preferable.

9. Playsinline Attribute

The playsinline attribute indicates that video playback should remain inline within the webpage when supported, rather than automatically switching to fullscreen playback.

Example

<video controls playsinline width="600"> <source src="mobile-video.mp4" type="video/mp4"> </video>

This attribute is particularly useful when designing mobile-friendly video experiences.

10. Summary of Video Attributes

Attribute Purpose
controls Displays playback controls.
autoplay Requests automatic playback.
muted Initially mutes audio.
loop Restarts video after it ends.
preload Provides a hint about preloading.
poster Specifies a preview image.
width Sets displayed width.
height Sets displayed height.
playsinline Indicates inline playback behavior.

11. Understanding Video Containers and Codecs

A video file contains more than just moving pictures. It can contain video streams, audio streams, subtitles and metadata.

What is a Video Container?

A container is a file format that holds different media streams and related information.

What is a Codec?

A codec is used to encode and decode audio or video data. It may compress media to reduce file size.

A container and a codec are different concepts. For example, MP4 is a container, while H.264 is a video codec that is commonly stored inside it.

12. Common Video Formats

Container / Format Common Extension Characteristics
MP4 .mp4 Widely used container with broad browser support.
WebM .webm Web-oriented container commonly using VP8 or VP9.
Ogg .ogv Open container that may contain Theora video.

13. Common Video Codecs

Codec Characteristics
H.264 / AVC Widely supported video compression standard.
VP9 Video codec commonly used with WebM.
AV1 Modern, efficient video codec.
Theora Open video codec historically used with Ogg.
Browser support depends on the browser, operating system, hardware, codec implementation and sometimes licensing or installed components.

14. MIME Types for Video

A MIME type identifies the media type of a resource. It can be specified using the type attribute of source.

Video Format Common MIME Type
MP4 video/mp4
WebM video/webm
Ogg video video/ogg

Example

<video controls> <source src="movie.mp4" type="video/mp4"> <source src="movie.webm" type="video/webm"> <source src="movie.ogv" type="video/ogg"> </video>

15. Multiple Video Sources

Multiple source elements allow a browser to choose a resource that it can play.

Example

<video controls width="600" poster="thumbnail.jpg"> <source src="lecture.mp4" type="video/mp4"> <source src="lecture.webm" type="video/webm"> Your browser does not support HTML5 video. </video>

The browser considers the available resources and attempts to play a supported source.

Providing multiple formats does not guarantee playback. The actual codec inside each container must also be supported.

16. Responsive Video Using CSS

Responsive video adjusts to the width of its container on different screen sizes.

Example

<style> .responsive-video { width: 100%; max-width: 700px; height: auto; } </style> <video class="responsive-video" controls> <source src="tutorial.mp4" type="video/mp4"> </video>

The width property allows the video to fill the available width, while max-width limits its maximum size.

17. Practical Example: Complete Video Player

Create a file named video-attributes.html and use the following code.

Complete HTML Code

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Video Attributes Demo</title> <style> video { width: 100%; max-width: 700px; height: auto; } </style> </head> <body> <h1>HTML5 Video Attributes</h1> <video controls muted preload="metadata" poster="thumbnail.jpg"> <source src="videos/demo.mp4" type="video/mp4"> <source src="videos/demo.webm" type="video/webm"> Your browser does not support video playback. </video> </body> </html>

Expected Result

  • A video player appears on the webpage.
  • The poster image may appear before playback.
  • Playback controls are displayed.
  • The video initially starts muted.
  • The browser receives a metadata preload hint.
  • The video adapts to the available container width.
Replace the example video paths and thumbnail image with files that actually exist in your project.

18. Common Mistakes

  • Assuming autoplay always works.
  • Forgetting muted when designing an autoplay experience.
  • Using an incorrect poster image path.
  • Confusing video containers with codecs.
  • Using an incorrect MIME type.
  • Assuming all MP4 files use the same codec.
  • Providing multiple sources with unsupported codecs.
  • Using preload as a guaranteed download instruction.
  • Ignoring mobile and responsive behavior.
  • Using dimensions that distort the original aspect ratio.

20. Interview Questions and Answers

Q1. What is the purpose of the controls attribute?

It displays browser-provided video playback controls.

Q2. What does autoplay do?

It requests automatic playback when browser policies allow it.

Q3. What is the purpose of muted?

It specifies that the video's audio should initially be muted.

Q4. What does loop do?

It restarts video playback automatically after the video ends.

Q5. What is preload?

It provides a hint about how much media data should be loaded in advance.

Q6. What is the poster attribute?

It specifies an image to display as the video's preview before playback.

Q7. What is a video container?

It is a file format that holds media streams and related information.

Q8. What is a video codec?

It encodes and decodes video data, often using compression.

Q9. Name three common video codecs.

H.264, VP9 and AV1.

Q10. What is the MIME type for MP4 video?

video/mp4.
