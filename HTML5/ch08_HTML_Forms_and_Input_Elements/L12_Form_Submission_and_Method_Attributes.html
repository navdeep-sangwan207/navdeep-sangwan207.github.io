Chapter 8: HTML Forms and Input Elements

Lesson 12: Form Submission and Method Attributes

1. Introduction to Form Submission

Form submission is the process of sending data entered by a user from an HTML form to a specified destination.

When a user clicks a submit button, the browser collects the successful form controls and sends their data according to the form's configuration.

Basic Form Submission Workflow

  1. The browser displays an HTML form.
  2. The user enters information into form controls.
  3. The user activates the submit button.
  4. The browser performs applicable constraint validation.
  5. The browser constructs the form data.
  6. The browser sends a request to the destination.
  7. The server processes the submitted data.
  8. The server returns a response to the browser.

Basic Syntax

<form action="/register" method="post">

    <label for="name">Name:</label>
    <input type="text"
           id="name"
           name="username"
           required>

    <button type="submit">Register</button>

</form>
An HTML form defines how data is submitted. A server-side application is needed to receive and process the data meaningfully.

2. Form Submission Attributes

The form element provides several attributes that control how data is submitted.

Attribute Purpose
action Specifies the URL that receives the submitted data.
method Specifies the HTTP method used for submission.
enctype Specifies the encoding used for the submitted request body.
target Specifies where the response is displayed.
autocomplete Provides an autofill hint for form controls.
novalidate Disables interactive browser constraint validation on submission.
accept-charset Specifies the character encoding accepted for form submission.

Example

<form action="/submit"
      method="post"
      enctype="application/x-www-form-urlencoded"
      autocomplete="on"
      target="_self">

    <!-- Form controls -->

</form>

3. Action Attribute

The action attribute specifies the URL where the browser sends the form data.

Syntax

<form action="/register" method="post">

    <input type="text" name="username">

    <button type="submit">Register</button>

</form>

Different Action Values

Value Meaning
/register Submits to the specified root-relative route.
https://example.com/register Submits to an absolute URL.
process.php Submits to a relative URL.
Omitted Submits to the current document URL.
The destination must be able to handle the selected HTTP method and submitted data. An ordinary GitHub Pages static HTML page does not provide a server-side form-processing endpoint by itself.

4. Method Attribute

The method attribute specifies the HTTP method used when submitting a form.

The two commonly used methods are:

  • GET
  • POST

Syntax

<form action="/search" method="get">

    <input type="text" name="query">

    <button type="submit">Search</button>

</form>

If the method attribute is omitted, the default form submission method is GET.

5. GET Method

The GET method submits form data as query parameters in the URL.

Example

<form action="/search" method="get">

    <label for="search">Search:</label>

    <input type="text"
           id="search"
           name="query">

    <button type="submit">Search</button>

</form>

Example URL

https://example.com/search?query=HTML5

How GET Works

  1. The user enters a search term.
  2. The browser collects the named form value.
  3. The browser encodes it as a URL query parameter.
  4. The browser sends a GET request to the server.
  5. The server returns the requested response.

Characteristics of GET

  • Form data is included in the URL query string.
  • Useful for searches, filters, and retrieving resources.
  • URLs can be bookmarked and shared.
  • Query parameters may appear in browser history and server logs.
  • It is not suitable for sensitive information.
  • It should not be used for operations intended to change server state.
GET does not encrypt submitted information. HTTPS protects data in transit, but query parameters can still appear in browser history, logs, and other places.

6. POST Method

The POST method sends form data in the request body rather than placing the form values in the URL query string.

Example

<form action="/register" method="post">

    <label for="username">Username:</label>

    <input type="text"
           id="username"
           name="username"
           required>

    <label for="email">Email:</label>

    <input type="email"
           id="email"
           name="email"
           required>

    <button type="submit">Register</button>

</form>

Characteristics of POST

  • Form data is transmitted in the HTTP request body.
  • Useful for submitting registrations and other data changes.
  • Can submit larger amounts of data than a typical URL query string.
  • Can be used for file uploads with appropriate encoding.
  • Submitted data is not normally displayed in the URL.
  • POST does not provide encryption by itself.
POST is not automatically secure. Use HTTPS to protect data during transmission and apply appropriate server-side security controls.

7. Difference Between GET and POST

GET POST
Data is normally included in the URL query string. Data is normally included in the request body.
Primarily used to retrieve resources. Primarily used to submit data for processing.
Query parameters can be bookmarked and shared. Request body data is not included in the URL.
Not suitable for sensitive information. Can carry sensitive data when combined with HTTPS and appropriate security controls.
GET requests are intended to be safe and idempotent. POST requests are not generally guaranteed to be safe or idempotent.
Commonly used for searches and filters. Commonly used for registration and data submission.
URL length limits depend on browsers and servers. Request body size is subject to server and application limits.
GET and POST are HTTP methods, not encryption mechanisms. HTTPS is the standard way to protect HTTP communication against interception and modification in transit.

8. Enctype Attribute

The enctype attribute specifies how the browser encodes form data in the request body.

It is relevant when a form uses the POST method.

Three Common Encoding Types

Encoding Type Purpose
application/x-www-form-urlencoded Default encoding for ordinary form submissions.
multipart/form-data Used for submitting files and other form data in separate parts.
text/plain Submits form data as plain text with limited structure; rarely used for production forms.

Example 1: URL-Encoded Form

<form action="/submit"
      method="post"
      enctype="application/x-www-form-urlencoded">

    <input type="text" name="username">

    <button type="submit">Submit</button>

</form>

Example 2: File Upload Form

<form action="/upload"
      method="post"
      enctype="multipart/form-data">

    <label for="file">Select File:</label>

    <input type="file"
           id="file"
           name="document"
           required>

    <button type="submit">Upload</button>

</form>
For a traditional HTML file upload, use POST and multipart/form-data. The receiving server must be configured to process multipart requests.

9. Target Attribute

The target attribute specifies where the response to a form submission should be displayed.

Value Purpose
_self Displays the response in the current browsing context.
_blank Displays the response in a new tab or browsing context.
_parent Displays the response in the parent browsing context.
_top Displays the response in the top-level browsing context.

Example

<form action="/search"
      method="get"
      target="_blank">

    <input type="search"
           name="query">

    <button type="submit">Search</button>

</form>

10. Form Data and the Name Attribute

The name attribute identifies a form control when the browser constructs the submitted form data.

Example

<form action="/login" method="post">

    <input type="text"
           name="username"
           value="student123">

    <input type="password"
           name="password"
           value="example123">

    <button type="submit">Login</button>

</form>

The form data contains name-value pairs:

username=student123
password=example123

Important Points

  • Controls generally need a name to contribute a submitted value.
  • Controls without a name are normally omitted from the submitted form data.
  • Disabled controls are not submitted.
  • Unchecked checkboxes and unselected radio buttons are not submitted.
  • Only the activated submit button's name and value are included, if provided.
  • Multiple selected values may be submitted using the same name.
A control's id is used for document identification and label association. Its name is used as the form-data key. These attributes serve different purposes.

11. URL Query Parameters

When a GET form is submitted, the browser places form values into the URL query string.

Example Form

<form action="/search" method="get">

    <input type="text"
           name="course"
           value="HTML5">

    <input type="text"
           name="level"
           value="Beginner">

    <button type="submit">Search</button>

</form>

Resulting URL

/search?course=HTML5&level=Beginner

Understanding the URL

  • ? starts the query string.
  • course=HTML5 is the first parameter.
  • & separates parameters.
  • level=Beginner is the second parameter.

Special characters are encoded when necessary. For example, a space may be represented as + in form URL encoding or as %20 in URL percent encoding.

12. Submit Button Attributes

A submit button can override certain form attributes for its own submission.

Attribute Purpose
formaction Overrides the form's action URL.
formmethod Overrides the form's HTTP method.
formenctype Overrides the form's encoding type.
formtarget Overrides the form's target.
formnovalidate Bypasses interactive constraint validation for that submission.

Example

<form action="/register" method="post">

    <input type="text"
           name="username"
           required>

    <button type="submit">
        Register
    </button>

    <button type="submit"
            formaction="/save-draft"
            formmethod="post"
            formnovalidate>
        Save Draft
    </button>

</form>

The first button submits to /register. The second button overrides the destination and bypasses interactive browser validation.

16. Common Mistakes

  1. Forgetting the name attribute on form controls.
  2. Using GET to submit passwords or other sensitive values.
  3. Assuming POST automatically encrypts form data.
  4. Using multipart/form-data incorrectly for file uploads.
  5. Expecting a static HTML page to process server requests by itself.
  6. Forgetting to validate data on the server.
  7. Assuming disabled controls are included in submitted form data.
  8. Using the wrong action URL.
  9. Assuming every button inside a form is a general-purpose button; an unspecified button type normally acts as a submit button.
  10. Confusing id with name.

18. Interview Questions and Answers

Q1. What is form submission?

It is the process of sending form data from a browser to a specified destination.

Q2. What is the purpose of the action attribute?

It specifies the URL that receives the submitted form data.

Q3. What is the default form submission method?

GET.

Q4. What is the difference between GET and POST?

GET normally places data in the URL query string, while POST sends data in the request body.

Q5. Is POST encrypted?

No. HTTPS is needed to protect data in transit.

Q6. What is the purpose of enctype?

It specifies the encoding used for form data in the request body.

Q7. Which enctype is commonly used for file uploads?

multipart/form-data.

Q8. What is the purpose of the name attribute?

It identifies the form-data key associated with a control.

Q9. What does target="_blank" do?

It displays the form response in a new tab or browsing context.

Q10. Can GitHub Pages process a POST form by itself?

No. GitHub Pages serves static files and does not provide a built-in server-side form-processing application.

19. Multiple Choice Questions (MCQs)

1. Which attribute specifies the form destination?

A. method   B. action   C. target   D. enctype

Correct Answer: B. action

2. What is the default form method?

A. POST   B. PUT   C. GET   D. DELETE

Correct Answer: C. GET

3. Which method normally places submitted values in the URL query string?

A. POST   B. GET   C. PATCH   D. DELETE

Correct Answer: B. GET

4. Which method normally sends form data in the request body?

A. GET   B. POST   C. TRACE   D. HEAD

Correct Answer: B. POST

5. Which encoding is commonly used for file uploads?

A. application/json   B. text/html   C. multipart/form-data   D. image/jpeg

Correct Answer: C. multipart/form-data

6. Which attribute identifies a submitted form control?

A. id   B. name   C. class   D. style

Correct Answer: B. name

7. Which target value opens the response in a new browsing context?

A. _self   B. _parent   C. _blank   D. _top

Correct Answer: C. _blank

8. Which attribute overrides a form's action on a submit button?

A. formaction   B. formmethod   C. formtarget   D. formenctype

Correct Answer: A. formaction

9. Which protocol provides encryption for HTTP communication?

A. FTP   B. HTTPS   C. HTML   D. SMTP

Correct Answer: B. HTTPS

10. What is required to process submitted data on the server?

A. Only HTML   B. Only CSS   C. A server-side application or endpoint   D. Only a browser

Correct Answer: C. A server-side application or endpoint

20. Lesson Summary

  • Form submission transfers form data to a destination.
  • action defines the submission URL.
  • method defines the HTTP method.
  • GET normally places data in the URL query string.
  • POST normally places data in the request body.
  • enctype controls request-body encoding.
  • multipart/form-data is used for traditional file uploads.
  • target controls where the response is displayed.
  • The name attribute identifies submitted form values.
  • A backend is required to process form submissions on a server.
