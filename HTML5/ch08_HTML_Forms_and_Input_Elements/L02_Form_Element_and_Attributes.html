Form Element and Attributes

Chapter 8: HTML Forms and Input Elements

1. Introduction

The <form> element is the main container used to create an HTML form. It groups form controls and defines how the browser submits the information entered by the user.

The form element can contain input fields, labels, checkboxes, radio buttons, dropdown lists, textareas and buttons. 

<form action="/submit" method="post">

    <label for="username">Username:</label>
    <input type="text" id="username" name="username">

    <button type="submit">Submit</button>

</form>
The form element defines the submission context. Individual form controls collect the values that may be submitted.

2. Syntax of the Form Element

<form attribute="value">
    Form controls
</form>

The form element has:

  • Opening tag: Starts the form.
  • Attributes: Configure form submission and behavior.
  • Form controls: Collect user information.
  • Closing tag: Ends the form.

3. Important Attributes of the Form Element

HTML provides several attributes that control where and how form data is submitted.

3.1 action Attribute

The action attribute specifies the URL that processes the submitted form data. 

<form action="/register" method="post">
    <input type="text" name="username">
    <button type="submit">Register</button>
</form>

When the user submits the form, the browser sends the form data to the specified URL.

If action is omitted, the form is submitted to the current document's URL. The destination must be configured to handle the request if meaningful processing is required.

3.2 method Attribute

The method attribute specifies the HTTP method used to submit the form.

The two commonly used methods are:

  • GET: Appends form data to the URL as query parameters.
  • POST: Sends form data in the request body.
<!-- GET method -->
<form action="/search" method="get">
    <input type="text" name="keyword">
    <button type="submit">Search</button>
</form>

<!-- POST method -->
<form action="/register" method="post">
    <input type="text" name="username">
    <button type="submit">Register</button>
</form>
GET is generally suitable for retrieving or searching information. POST is commonly used when submitting data that may create or update server-side information.

3.3 target Attribute

The target attribute specifies where the response from form submission should be displayed.

  • _self – Displays the response in the current browsing context.
  • _blank – Displays the response in a new browsing context, usually a new tab.
  • _parent – Displays the response in the parent browsing context.
  • _top – Displays the response in the top-level browsing context.
<form action="/search" method="get" target="_blank">
    <input type="text" name="keyword">
    <button type="submit">Search</button>
</form>

3.4 autocomplete Attribute

The autocomplete attribute controls whether the browser may offer autofill suggestions for form fields.

Common values:

  • on – Allows autocomplete.
  • off – Requests that autocomplete be disabled.
<form autocomplete="on">
    <input type="text" name="fullname">
    <input type="email" name="email">
</form>
Browsers may still manage autofill behavior independently. The autocomplete attribute does not guarantee that all browser autofill features will be disabled.

3.5 enctype Attribute

The enctype attribute specifies how form data is encoded when the form uses the POST method.

Important values:

  • application/x-www-form-urlencoded – Default encoding for ordinary form submissions.
  • multipart/form-data – Used when uploading files through a form.
  • text/plain – Sends form data using a plain-text encoding format. 
<form action="/upload"
      method="post"
      enctype="multipart/form-data">

    <input type="file" name="document">

    <button type="submit">Upload</button>

</form>
For file uploads, use POST with enctype="multipart/form-data". The server must also support receiving and processing uploaded files.

3.6 novalidate Attribute

The novalidate attribute disables the browser's built-in constraint validation when the form is submitted. 

<form action="/submit" method="post" novalidate>
    <input type="email" name="email" required>
    <button type="submit">Submit</button>
</form>

Even though the email field is required, the browser does not block submission because the form has the novalidate attribute.

3.7 accept-charset Attribute

The accept-charset attribute specifies the character encoding used for form submission. 

<form action="/submit"
      method="post"
      accept-charset="UTF-8">

    <input type="text" name="fullname">
    <button type="submit">Submit</button>

</form>

UTF-8 supports a wide range of characters and is the standard encoding used by modern web applications.

4. Summary of Form Attributes

  • action: Specifies the form submission destination.
  • method: Specifies the HTTP submission method.
  • target: Specifies where the response is displayed.
  • autocomplete: Controls browser autofill hints.
  • enctype: Specifies POST form-data encoding.
  • novalidate: Disables built-in form validation on submission.
  • accept-charset: Specifies the submission character encoding.

5. GET vs POST Method

  • GET sends form data as URL query parameters.
  • POST sends form data in the request body.
  • GET requests can be bookmarked with their query parameters.
  • POST is commonly used for registration, uploads and data changes.
  • Neither method provides encryption by itself.
  • HTTPS protects data in transit when correctly configured.
Never rely on POST alone to protect passwords or sensitive information. Use HTTPS and appropriate server-side security controls.

6. Complete Example: Student Registration Form

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Student Registration</title>
</head>
<body>

    <h2>Student Registration Form</h2>

    <form action="/register"
          method="post"
          autocomplete="on">

        <label for="name">Full Name:</label>
        <input type="text"
               id="name"
               name="fullname"
               required>

        <br><br>

        <label for="email">Email:</label>
        <input type="email"
               id="email"
               name="email"
               required>

        <br><br>

        <label for="course">Course:</label>
        <select id="course" name="course">
            <option value="ece">Electronics</option>
            <option value="cse">Computer Science</option>
        </select>

        <br><br>

        <button type="submit">Register</button>

    </form>

</body>
</html>
Important: The endpoint /register is an example. This form requires a backend route to process the submitted information.

8. Common Mistakes

  • Using GET for sensitive information.
  • Forgetting to specify the correct form action.
  • Using multipart/form-data incorrectly for file uploads.
  • Assuming novalidate removes the need for server-side validation.
  • Assuming POST automatically encrypts submitted data.
  • Forgetting that the server must process the submitted request.
  • Using an incorrect HTTP method for the intended operation.

10. Interview Questions and Answers

Q1. What is the purpose of the form element?

It groups form controls and defines how their data is submitted.

Q2. What is the action attribute?

It specifies the URL that receives the submitted form data.

Q3. What is the method attribute?

It specifies the HTTP method used for form submission, commonly GET or POST.

Q4. What is the difference between GET and POST?

GET places submitted data in the URL query string, whereas POST sends it in the request body.

Q5. What is the target attribute?

It specifies the browsing context in which the server response is displayed.

Q6. What is the enctype attribute?

It specifies how POST form data is encoded before submission.

Q7. Which enctype value is used for file uploads?

multipart/form-data.

Q8. What does novalidate do?

It disables the browser's built-in constraint validation when the form is submitted.

Q9. What is the purpose of autocomplete?

It provides hints about whether the browser may offer autofill suggestions.

Q10. Does POST encrypt form data?

No. POST does not encrypt data. HTTPS is used to protect data during transmission.

11. Multiple Choice Questions (MCQs)

Q1. Which attribute specifies the form submission URL?

  2. action
  3. target

Answer: B — action

Q2. Which method sends form data in the request body?

  1. GET
  2. POST
  3. LINK

Q3. Which target value opens the response in a new browsing context?

Q4. Which encoding is commonly used for file uploads?

Q6. Which attribute controls browser autofill hints?

Answer: A — autocomplete

Q7. What is the default form method when method is omitted?

Q8. Which attribute specifies the character encoding for form submission?

Q10. Which attribute defines how POST data is encoded?

  1. action
  2. target
  3. enctype

12. Lesson Summary

  • The form element is the container for HTML form controls.
  • Action specifies the submission destination.
  • Method specifies the HTTP submission method.
  • Target specifies where the response is displayed.
  • Autocomplete provides browser autofill hints.
  • Enctype controls POST data encoding.
  • Novalidate disables built-in constraint validation on submission.
  • Accept-charset specifies the form submission character encoding.
  • Server-side processing is required to handle submitted information.
