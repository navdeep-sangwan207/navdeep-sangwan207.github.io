Chapter 8: HTML Forms and Input Elements

Lesson 11: HTML5 Form Validation

1. Introduction to HTML5 Form Validation

Form validation is the process of checking whether the information entered by a user satisfies specified rules before the form is submitted.

HTML5 provides built-in form validation features that allow browsers to check common input requirements without requiring JavaScript for every validation rule.

Why Is Form Validation Important?

  • Prevents incomplete form submissions.
  • Checks whether entered data follows expected formats.
  • Helps users identify incorrect information.
  • Improves the reliability of form data.
  • Reduces unnecessary requests to the server.

Example

<form>

    <label for="email">Email:</label>

    <input type="email"
           id="email"
           name="email"
           required>

    <button type="submit">Submit</button>

</form>

Here, the browser checks that the email field is not empty and that its value follows the expected email syntax.

HTML validation improves user experience, but it does not replace server-side validation. Data received by a server must always be checked independently.

2. Types of HTML5 Form Validation

HTML forms can use several validation mechanisms:

Validation Type Description
Required validation Checks whether a value has been entered.
Type validation Checks values according to input types such as email and URL.
Length validation Checks minimum and maximum text length.
Range validation Checks minimum and maximum numeric or date values.
Pattern validation Checks whether a value matches a regular expression.
Step validation Checks whether a value follows an allowed increment.
Custom validation Uses JavaScript to define additional validation rules.

3. Required Attribute

The required attribute specifies that the user must provide a value before normal form submission.

Syntax

<input type="text"
       name="username"
       required>

Example

Try submitting the form without entering a name. The browser displays a validation message.

Important Points

  • It is a Boolean attribute.
  • It can be used with supported input types, textarea, and select.
  • The field must satisfy the applicable value requirements.
  • It can also be used with radio-button groups and checkboxes, subject to their group and individual-control rules.

4. Minlength and Maxlength Attributes

These attributes specify the minimum and maximum number of characters permitted in a text value.

Attribute Purpose
minlength Specifies the minimum number of characters.
maxlength Specifies the maximum number of characters.

Example

<label for="username">Username:</label>

<input type="text"
       id="username"
       name="username"
       minlength="4"
       maxlength="12"
       required>

Output

These attributes apply to text-like input types and textarea. They are not general-purpose numeric range attributes.

5. Min and Max Attributes

The min and max attributes specify the allowed lower and upper boundaries for supported numeric and date/time controls.

Example: Age Validation

<label for="age">Age:</label>

<input type="number"
       id="age"
       name="age"
       min="18"
       max="60"
       required>

Output

Important Points

  • min specifies the minimum permitted value.
  • max specifies the maximum permitted value.
  • Useful with number, range, date, time, month, week, and datetime-local.
  • Values outside the specified range cause a range validation error.

6. Step Attribute

The step attribute specifies the permitted increment between valid values.

Example

<label for="quantity">Quantity:</label>

<input type="number"
       id="quantity"
       name="quantity"
       min="0"
       max="100"
       step="5">

Valid values include 0, 5, 10, 15, 20, and so on.

Output

Special Values

  • step="1": permits increments of one.
  • step="0.5": permits half-unit increments.
  • step="any": allows any value supported by the input type, subject to other constraints.
Step validity depends on the input type, its step base, and the specified step value. A value may fail step validation even when it is between min and max.

7. Pattern Attribute

The pattern attribute specifies a regular expression that a text-like input value must match.

Example: Student ID

<label for="student-id">Student ID:</label>

<input type="text"
       id="student-id"
       name="student_id"
       pattern="[A-Z]{2}[0-9]{4}"
       title="Enter two uppercase letters followed by four digits"
       required>

The pattern requires:

  • Two uppercase letters.
  • Four digits.
  • Example valid value: AB1234.

Output

Common Pattern Examples

Pattern Meaning Example
[0-9]{6} Exactly six digits. 123456
[A-Z]{3} Exactly three uppercase letters. ABC
[A-Za-z]+ One or more English letters. Navdeep
[0-9]{4,8} Four to eight digits. 123456
HTML pattern validation uses JavaScript-style regular expression syntax with HTML-defined behavior. The pattern is matched against the entire non-empty value. A pattern does not automatically make a field required; use required when an empty value must also be rejected.

8. Type-Based Validation

Some input types automatically validate the general format of entered values.

Input Type Validation
email Checks whether the value follows the expected email syntax.
url Checks whether the value follows the expected absolute URL syntax.
number Checks whether the entered value is a valid number.
date Accepts a valid date value.
time Accepts a valid time value.

Example

<form>

    <label for="email">Email:</label>
    <input type="email"
           id="email"
           required>

    <label for="website">Website:</label>
    <input type="url"
           id="website"
           required>

    <button type="submit">Submit</button>

</form>
Email validation checks syntax, not whether an inbox exists or belongs to the user. URL validation does not prove that a website is reachable.

9. Novalidate Attribute

The novalidate attribute disables the browser's interactive constraint validation when submitting a form.

Syntax

<form novalidate>

    <input type="email" required>

    <button type="submit">Submit</button>

</form>

Important Points

  • It is a Boolean attribute of the form element.
  • It prevents normal browser validation from blocking form submission.
  • It does not remove validation attributes from the controls.
  • JavaScript can still inspect validity and perform custom checks.
Disabling browser validation does not make invalid data safe. The server must still validate submitted data.

10. Constraint Validation API

The Constraint Validation API provides JavaScript properties and methods for checking and controlling form validation.

Important Properties

Property Purpose
validity Returns the ValidityState object.
valid Indicates whether the control satisfies its constraints.
validationMessage Returns the browser's validation message for the control.
willValidate Indicates whether the control participates in constraint validation.

Important Methods

Method Purpose
checkValidity() Checks whether the control or form satisfies constraints.
reportValidity() Checks validity and displays browser validation feedback when invalid.
setCustomValidity() Sets a custom validation error message.

Example: checkValidity()

<input type="email"
       id="email"
       required>

<button type="button"
        onclick="checkEmail()">
    Check Email
</button>

<script>
function checkEmail() {

    const email = document.getElementById("email");

    if (email.checkValidity()) {
        alert("Email is valid.");
    } else {
        alert("Please enter a valid email.");
    }
}
</script>

11. Custom Validation Using JavaScript

Sometimes built-in validation is not sufficient. JavaScript can implement additional rules using setCustomValidity().

Example: Password Validation

<label for="password">Password:</label>

<input type="password"
       id="password"
       minlength="8"
       required>

<label for="confirm">Confirm Password:</label>

<input type="password"
       id="confirm"
       required>

<script>
const password = document.getElementById("password");
const confirmPassword = document.getElementById("confirm");

function validatePassword() {

    if (confirmPassword.value !== password.value) {
        confirmPassword.setCustomValidity(
            "Passwords do not match."
        );
    } else {
        confirmPassword.setCustomValidity("");
    }
}

password.addEventListener("input", validatePassword);
confirmPassword.addEventListener("input", validatePassword);
</script>
Calling setCustomValidity("") clears the custom validation error. If a non-empty message is set, the control becomes invalid.

12. ValidityState Properties

The validity property provides detailed information about why a control is invalid.

Property Meaning
valueMissing A required value is missing.
typeMismatch The value does not match the expected type.
patternMismatch The value does not match the specified pattern.
tooShort The value is shorter than minlength.
tooLong The value exceeds maxlength.
rangeUnderflow The value is below min.
rangeOverflow The value is above max.
stepMismatch The value does not follow the permitted step.
badInput The browser cannot convert the user's input into the required value.
customError A custom validation error has been set.
valid Indicates whether all applicable constraints are satisfied.

Example

const age = document.getElementById("age");

if (age.validity.rangeUnderflow) {
    console.log("Age is below the minimum.");
}

if (age.validity.rangeOverflow) {
    console.log("Age is above the maximum.");
}

if (age.validity.valid) {
    console.log("Age is valid.");
}

14. Difference Between HTML and JavaScript Validation

HTML Validation JavaScript Validation
Uses built-in attributes. Uses JavaScript logic.
Requires less code. Can implement more complex rules.
Provides browser-generated feedback. Can provide customized feedback.
Suitable for common validation rules. Suitable for application-specific rules.
Can be bypassed by users. Client-side JavaScript can also be bypassed.
Both HTML and JavaScript validation happen on the client. Neither can replace server-side validation for security and data integrity.

15. Common Form Validation Mistakes

  1. Assuming required validates the format of every input.
  2. Using minlength and maxlength for numeric ranges.
  3. Forgetting that pattern does not make a field required.
  4. Assuming email validation confirms mailbox ownership.
  5. Using novalidate without implementing another validation strategy.
  6. Failing to clear a custom validity error.
  7. Relying only on client-side validation.
  8. Using a pattern that does not match the intended data format.
  9. Providing no useful instructions when validation fails.
  10. Ignoring accessibility when presenting error messages.

17. Interview Questions and Answers

Q1. What is form validation?

It is the process of checking whether entered form data satisfies specified requirements.

Q2. What is the purpose of required?

It requires the user to provide a value before normal form submission.

Q3. What is the difference between minlength and maxlength?

Minlength specifies the minimum text length, while maxlength specifies the maximum text length.

Q4. What is the purpose of min and max?

They specify lower and upper limits for supported numeric and date/time input types.

Q5. What is the pattern attribute?

It validates a non-empty value against a regular expression.

Q6. What is the purpose of step?

It defines permitted increments between valid values.

Q7. What does novalidate do?

It disables interactive constraint validation during normal form submission.

Q8. What is checkValidity()?

It checks whether a control or form satisfies its applicable validation constraints.

Q9. What is setCustomValidity()?

It sets a custom validation error message on a form control.

Q10. Why is server-side validation necessary?

Client-side checks can be bypassed, so the server must independently validate submitted data.

18. Multiple Choice Questions (MCQs)

1. Which attribute makes a form control mandatory?

A. validate   B. required   C. mandatory   D. checked

Correct Answer: B. required

2. Which attribute specifies minimum text length?

A. min   B. minlength   C. size   D. step

Correct Answer: B. minlength

3. Which attribute checks a regular expression?

A. pattern   B. format   C. regex   D. match

Correct Answer: A. pattern

4. Which attribute defines permitted increments?

A. range   B. max   C. step   D. increment

Correct Answer: C. step

5. Which attribute disables interactive form validation?

A. disabled   B. novalidate   C. readonly   D. noform

Correct Answer: B. novalidate

6. Which method checks validity without necessarily displaying validation feedback?

A. checkValidity()   B. setCustomValidity()   C. submit()   D. reset()

Correct Answer: A. checkValidity()

7. Which method sets a custom validation error?

A. setError()   B. setCustomValidity()   C. validate()   D. reportError()

Correct Answer: B. setCustomValidity()

8. Which ValidityState property indicates a missing required value?

A. typeMismatch   B. valueMissing   C. badInput   D. customError

Correct Answer: B. valueMissing

9. Which ValidityState property indicates that a value is above max?

A. rangeUnderflow   B. rangeOverflow   C. stepMismatch   D. tooLong

Correct Answer: B. rangeOverflow

10. Which validation must be performed independently by a backend?

A. Only required validation

B. Only pattern validation

C. All important validation rules

D. No validation

Correct Answer: C. All important validation rules

19. Lesson Summary

  • required checks whether a required value is supplied.
  • minlength and maxlength control text length.
  • min and max define supported value boundaries.
  • step defines valid increments.
  • pattern validates values using a regular expression.
  • Input types such as email and URL provide built-in type validation.
  • novalidate disables interactive form validation on submission.
  • The Constraint Validation API supports programmatic validation.
  • setCustomValidity() provides custom error messages.
  • Server-side validation is essential for secure applications.
