Text and Password Inputs

Chapter 8: HTML Forms and Input Elements

1. Introduction

The HTML <input> element is used to create different types of form controls. Its type attribute determines how the browser displays and handles the control.

Text and password inputs are two commonly used input types in web forms.

  • Text input: Collects ordinary single-line text.
  • Password input: Collects password information while masking the displayed characters.
<input type="text" name="username">

<input type="password" name="password">

2. Text Input

The type="text" input creates a single-line text field. It is commonly used to collect names, usernames, city names, titles and other ordinary text.

Syntax

<input type="text" name="fullname">

Example

<label for="fullname">Full Name:</label>
<input type="text"
       id="fullname"
       name="fullname">

Explanation

  • input creates the form control.
  • type="text" creates a single-line text field.
  • id uniquely identifies the element in the document.
  • name identifies the submitted data field.
The id attribute connects the input to its label through the label's for attribute. The name attribute identifies the field in submitted data.

3. Password Input

The type="password" input creates a single-line password field. Characters entered by the user are visually masked by the browser.

Syntax

<input type="password" name="password">

Example

<label for="password">Password:</label>
<input type="password"
       id="password"
       name="password">

Explanation

  • type="password" creates a password input field.
  • The browser visually masks the characters entered.
  • The actual value remains available to the form submission process.
  • The password is not automatically encrypted by this input type.
Security: Password masking only changes how characters are displayed. It does not encrypt the password. Use HTTPS and secure server-side password handling.

4. Important Attributes of Text and Password Inputs

4.1 name Attribute

The name attribute identifies the form control when its value is submitted. 

<input type="text" name="username">

4.2 id Attribute

The id attribute provides a unique identifier for an HTML element. 

<input type="text" id="username" name="username">

4.3 placeholder Attribute

The placeholder attribute displays a short hint inside an empty input field. 

<input type="text"
       name="username"
       placeholder="Enter your username">
Placeholder text is not a replacement for a proper label. Use a visible label to describe the purpose of each field.

4.4 value Attribute

The value attribute specifies the initial value of an input field. 

<input type="text"
       name="city"
       value="Chandigarh">

4.5 required Attribute

The required attribute indicates that the user must provide a value before the browser allows form submission. 

<input type="text"
       name="fullname"
       required>

4.6 maxlength Attribute

The maxlength attribute specifies the maximum number of characters the user can enter. 

<input type="text"
       name="username"
       maxlength="20">

4.7 minlength Attribute

The minlength attribute specifies the minimum number of characters required for a valid input value. 

<input type="text"
       name="username"
       minlength="4">

4.8 readonly Attribute

The readonly attribute makes an input field non-editable by the user. 

<input type="text"
       name="student_id"
       value="STU101"
       readonly>

A readonly field can generally receive focus and its value is included in form submission if it has a name.

4.9 disabled Attribute

The disabled attribute disables an input field. A disabled control cannot normally be edited or focused and is not included in form submission. 

<input type="text"
       name="username"
       value="admin"
       disabled>

4.10 size Attribute

The size attribute specifies the approximate visible width of a text or password input in characters. 

<input type="text"
       name="username"
       size="30">

4.11 pattern Attribute

The pattern attribute specifies a regular expression that the input value must match for constraint validation. 

<input type="text"
       name="username"
       pattern="[A-Za-z]{4,12}"
       title="Enter 4 to 12 letters">

This example accepts between 4 and 12 English letters, without spaces or numbers.

4.12 autocomplete Attribute

The autocomplete attribute provides a hint to the browser about whether and how it may autofill a field. 

<input type="text"
       name="username"
       autocomplete="username">

<input type="password"
       name="password"
       autocomplete="current-password">

Common autocomplete tokens include:

  • name – Full name.
  • username – Username.
  • current-password – Existing password.
  • new-password – New password.
  • off – Requests that autofill be disabled.

5. Difference Between Readonly and Disabled

Both attributes prevent users from editing an input field, but they behave differently during form submission.

  • readonly: The value is normally submitted with the form.
  • disabled: The value is not included in form submission.
  • readonly: The control can generally receive focus.
  • disabled: The control cannot normally receive focus.
<!-- Readonly input -->
<input type="text"
       name="student_id"
       value="STU101"
       readonly>

<!-- Disabled input -->
<input type="text"
       name="account"
       value="Active"
       disabled>
Readonly and disabled are not security controls. Never trust values received from a browser without validating them on the server.

6. Difference Between Text and Password Inputs

  • Text: Displays entered characters normally.
  • Password: Visually masks entered characters.
  • Both are single-line input controls.
  • Both support attributes such as name, id, placeholder and required.
  • Both can submit their values when they are successful form controls.
<label for="username">Username:</label>
<input type="text" id="username" name="username">

<label for="password">Password:</label>
<input type="password" id="password" name="password">

7. Complete Example: Login Form

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Login Form</title>
</head>
<body>

    <h2>User Login</h2>

    <form action="/login" method="post">

        <label for="username">Username:</label>
        <input type="text"
               id="username"
               name="username"
               placeholder="Enter username"
               required
               autocomplete="username">

        <br><br>

        <label for="password">Password:</label>
        <input type="password"
               id="password"
               name="password"
               placeholder="Enter password"
               required
               autocomplete="current-password">

        <br><br>

        <button type="submit">Login</button>

    </form>

</body>
</html>
The /login URL is a sample backend endpoint. A real login system requires server-side authentication, secure password storage and HTTPS.

9. Common Mistakes

  • Using a text input instead of a password input for passwords.
  • Forgetting the name attribute on controls that need to be submitted.
  • Using duplicate id values in the same document.
  • Using placeholder text instead of a visible label.
  • Confusing readonly with disabled.
  • Assuming password masking provides encryption.
  • Relying only on browser validation for security.
  • Using maxlength without considering appropriate input requirements.

11. Interview Questions and Answers

Q1. What is a text input?

A text input is a single-line form control created using <input type="text">.

Q2. What is a password input?

It is a single-line input created using <input type="password">. It visually masks the characters entered by the user.

Q3. Does a password input encrypt the entered password?

No. It only masks the displayed characters. HTTPS and secure server-side password handling are required.

Q4. What is the purpose of the placeholder attribute?

It displays a short hint inside an empty input field.

Q5. What is the purpose of maxlength?

It specifies the maximum number of characters a user can enter.

Q6. What is the difference between readonly and disabled?

Readonly fields are generally submitted with the form, whereas disabled fields are not submitted.

Q7. What is the purpose of the required attribute?

It indicates that the user must provide a value before the browser allows submission.

Q8. What is the purpose of the pattern attribute?

It specifies a regular expression that the input value must match for constraint validation.

Q9. Can text and password inputs use autocomplete?

Yes. The autocomplete attribute can provide hints such as username, current-password and new-password.

Q10. What is the purpose of the size attribute?

It specifies the approximate visible width of a text or password input in characters.

13. Lesson Summary

  • Text inputs collect ordinary single-line text.
  • Password inputs visually mask entered characters.
  • Name identifies submitted form data.
  • Id uniquely identifies an element in the document.
  • Placeholder displays a short hint.
  • Value specifies an initial input value.
  • Required, minlength and maxlength support validation.
  • Readonly prevents editing but normally allows submission.
  • Disabled prevents normal interaction and excludes the control from submission.
  • Pattern provides regular-expression-based constraint validation.
  • Autocomplete provides browser autofill hints.
