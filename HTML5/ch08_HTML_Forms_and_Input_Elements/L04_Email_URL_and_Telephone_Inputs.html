Email, URL and Telephone Inputs

Chapter 8: HTML Forms and Input Elements

1. Introduction

HTML5 introduced several specialized input types to collect different kinds of information. These input types help browsers provide appropriate input interfaces and basic validation.

Three commonly used input types are:

  • email: Collects email addresses.
  • url: Collects web addresses.
  • tel: Collects telephone numbers.
<input type="email" name="email">

<input type="url" name="website">

<input type="tel" name="phone">
These specialized input types improve user experience and can provide browser-level validation. They do not guarantee that an entered email address, website or telephone number actually exists.

2. Email Input

The type="email" input creates a field intended for entering an email address.

Syntax

<input type="email" name="email">

Example

<label for="email">Email Address:</label>

<input type="email"
       id="email"
       name="email"
       placeholder="example@gmail.com"
       required>

Features of Email Input

  • Designed for entering email addresses.
  • Provides basic browser validation of email syntax.
  • May display an email-optimized keyboard on mobile devices.
  • Supports attributes such as required, maxlength and autocomplete.

Email Validation Example

<form>
    <label for="user-email">Email:</label>

    <input type="email"
           id="user-email"
           name="email"
           required>

    <button type="submit">Submit</button>
</form>

If the user enters an invalid email format, the browser can prevent form submission and display a validation message.

Email input validation checks the format of the entered value. It does not verify that the mailbox exists or that the user owns the email address.

3. URL Input

The type="url" input creates a field intended for entering a web address or URL.

Syntax

<input type="url" name="website">

Example

<label for="website">Website URL:</label>

<input type="url"
       id="website"
       name="website"
       placeholder="https://example.com">

Features of URL Input

  • Designed for entering web addresses.
  • Provides basic browser validation of URL syntax.
  • May provide a URL-optimized keyboard on mobile devices.
  • Supports attributes such as required, placeholder and maxlength.

URL Validation Example

<form>
    <label for="portfolio">Portfolio URL:</label>

    <input type="url"
           id="portfolio"
           name="portfolio"
           placeholder="https://example.com"
           required>

    <button type="submit">Submit</button>
</form>

A URL input generally expects a valid absolute URL, including an appropriate scheme such as https://.

A URL input validates URL syntax. It does not check whether the website is reachable or whether the page actually exists.

4. Telephone Input

The type="tel" input creates a field intended for entering telephone numbers.

Syntax

<input type="tel" name="phone">

Example

<label for="phone">Phone Number:</label>

<input type="tel"
       id="phone"
       name="phone"
       placeholder="Enter phone number">

Features of Telephone Input

  • Designed for entering telephone numbers.
  • May display a telephone-optimized keyboard on mobile devices.
  • Does not have a universal built-in telephone number format validator.
  • Supports pattern, minlength, maxlength and other input attributes.

Telephone Input with Pattern

<label for="mobile">Mobile Number:</label>

<input type="tel"
       id="mobile"
       name="mobile"
       pattern="[0-9]{10}"
       maxlength="10"
       placeholder="Enter 10-digit number"
       required
       title="Enter exactly 10 digits">

The pattern above requires exactly ten digits when the value is validated. It is a simplified example for a ten-digit number without spaces or country code.

Telephone number formats vary between countries. The tel input does not automatically validate every country's numbering system. Choose a suitable validation strategy for the application.

5. Important Attributes

Email, URL and telephone inputs support many of the common input attributes.

5.1 required

Requires the user to provide a value before submission.

<input type="email" name="email" required>

5.2 placeholder

Displays a short hint inside the input field.

<input type="url"
       name="website"
       placeholder="https://example.com">

5.3 maxlength

Limits the maximum number of characters.

<input type="tel"
       name="phone"
       maxlength="15">

5.4 minlength

Specifies the minimum number of characters required for a valid value.

<input type="tel"
       name="phone"
       minlength="10">

5.5 pattern

Specifies a regular expression used for constraint validation.

<input type="tel"
       name="phone"
       pattern="[0-9]{10}">

5.6 autocomplete

Provides a hint about browser autofill behavior.

<input type="email"
       name="email"
       autocomplete="email">

<input type="tel"
       name="phone"
       autocomplete="tel">

5.7 multiple

The multiple attribute allows an email input to accept multiple comma-separated email addresses. 

<label for="recipients">Recipients:</label>

<input type="email"
       id="recipients"
       name="recipients"
       multiple
       placeholder="one@example.com, two@example.com">
The multiple attribute is supported by email inputs for accepting a list of email addresses. It is not a general multiple-value feature for URL or telephone inputs.

6. Difference Between Email, URL and Telephone Inputs

  • email: Intended for email addresses and provides basic email syntax validation.
  • url: Intended for web addresses and provides basic URL syntax validation.
  • tel: Intended for telephone numbers but has no universal built-in format validation.

Comparison Examples

<input type="email"
       name="email"
       placeholder="name@example.com">

<input type="url"
       name="website"
       placeholder="https://example.com">

<input type="tel"
       name="phone"
       placeholder="Enter phone number">

7. Complete Example: Contact Information Form

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Contact Information</title>
</head>
<body>

    <h2>Contact Information Form</h2>

    <form action="/contact" method="post">

        <label for="name">Full Name:</label>
        <input type="text"
               id="name"
               name="name"
               required>

        <br><br>

        <label for="email">Email Address:</label>
        <input type="email"
               id="email"
               name="email"
               placeholder="name@example.com"
               required>

        <br><br>

        <label for="website">Website:</label>
        <input type="url"
               id="website"
               name="website"
               placeholder="https://example.com">

        <br><br>

        <label for="phone">Telephone Number:</label>
        <input type="tel"
               id="phone"
               name="phone"
               placeholder="Enter phone number">

        <br><br>

        <button type="submit">Submit</button>

    </form>

</body>
</html>
The /contact URL is an example backend endpoint. The form requires a server-side application to process the submitted information.

9. Common Mistakes

  • Using text input when email input is more appropriate.
  • Assuming email validation verifies mailbox ownership.
  • Entering a URL without an appropriate scheme.
  • Assuming tel automatically validates every phone number.
  • Using an overly restrictive telephone pattern.
  • Forgetting labels for form controls.
  • Assuming browser validation replaces server-side validation.

11. Interview Questions and Answers

Q1. Which input type is used for email addresses?

<input type="email">.

Q2. Which input type is used for website addresses?

<input type="url">.

Q3. Which input type is used for telephone numbers?

<input type="tel">.

Q4. Does email input validate email syntax?

Yes. The browser performs basic email syntax validation.

Q5. Does URL input validate website syntax?

Yes. The browser checks whether the entered value follows the expected URL syntax.

Q6. Does telephone input automatically validate phone numbers?

No. It is intended for telephone numbers but does not provide universal phone-number format validation.

Q7. Which attribute can be used to validate a telephone number?

The pattern attribute can apply a regular expression for browser-side validation.

Q8. What is the purpose of the multiple attribute in email input?

It allows multiple comma-separated email addresses to be entered.

Q9. Can these input types display different mobile keyboards?

Yes. Browsers may display optimized keyboards depending on the input type and device.

Q10. Does browser validation guarantee that an email address exists?

No. It checks syntax, not mailbox existence or ownership.

13. Lesson Summary

  • Email input collects email addresses and checks basic syntax.
  • URL input collects web addresses and checks basic URL syntax.
  • Telephone input collects phone numbers but has no universal format validation.
  • Required makes a field mandatory.
  • Pattern supports regular-expression-based validation.
  • Multiple allows a list of email addresses in an email input.
  • Autocomplete provides browser autofill hints.
  • Browser validation does not replace server-side validation.
