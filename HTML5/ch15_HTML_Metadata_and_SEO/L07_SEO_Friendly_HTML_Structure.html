2. Introduction to SEO

SEO stands for Search Engine Optimization.

It is the process of improving a website's visibility in search engine results through technical improvements, useful content, website structure and other quality signals.

How search engines generally work

  1. Crawling: Search engine crawlers discover pages and retrieve their content.
  2. Indexing: Search engines analyze eligible content and may store information about it in their index.
  3. Ranking: Search engines select and order results for a user's search query.
Crawling, indexing and ranking are different processes. A well-structured HTML document helps search engines understand content, but does not guarantee indexing or a particular ranking.

3. Importance of HTML Structure in SEO

HTML defines the structure and meaning of web page content.

A well-organized HTML document helps browsers, assistive technologies and search engine crawlers interpret page information.

Important HTML SEO elements

HTML element SEO-related purpose
<title> Defines the document title, which may appear as the search result title.
<meta> Provides metadata such as description, character encoding and indexing directives.
<h1> to <h6> Organizes headings and content hierarchy.
<main> Identifies the primary content of the document.
<article> Identifies independently meaningful content.
<nav> Identifies major navigation links.
<section> Groups related content.
<img> Displays images; descriptive alternative text helps communicate image meaning.
<a> Creates links that help users and crawlers discover pages.

4. Use Semantic HTML Elements

Semantic HTML elements communicate the purpose of different parts of a web page.

Common semantic elements

<header>
    Website header
</header>

<nav>
    Main navigation
</nav>

<main>

    <article>
        Main article content
    </article>

    <aside>
        Related information
    </aside>

</main>

<footer>
    Website footer
</footer>

Benefits

  • Provides meaningful document structure.
  • Improves accessibility and navigation.
  • Makes HTML easier to maintain.
  • Helps machines interpret the purpose of page regions.
Semantic elements improve structure and accessibility, but simply replacing every div with semantic tags does not automatically improve search rankings.

5. Proper Heading Hierarchy

HTML provides six heading levels, from <h1> to <h6>.

Headings help organize content into meaningful sections.

Example of a logical hierarchy

<h1>Embedded Systems Course</h1>

<h2>Introduction to Embedded Systems</h2>

<h3>Microcontrollers</h3>

<h3>Microprocessors</h3>

<h2>Embedded C Programming</h2>

<h3>Data Types</h3>

<h3>Pointers</h3>

Heading levels

Heading Typical use
H1 Main page heading.
H2 Major sections.
H3 Subsections within H2.
H4 Subsections within H3.
H5 More detailed subsections.
H6 Lowest heading level.
Do not select heading levels only because of their visual size. Use CSS to control appearance and HTML heading levels to represent content hierarchy. A page can have more than one H1 when its structure justifies it, although a clear primary heading is generally easiest to maintain.

6. Optimize the Page Title

The <title> element defines the document title.

Search engines may use this title when displaying a result, although they can generate a different title based on the page and query.

Example

<title>
    HTML5 Complete Course – NS Learning Hub
</title>

Title best practices

  • Write a unique title for each important page.
  • Describe the page content accurately.
  • Use important topic words naturally.
  • Avoid repetitive keyword stuffing.
  • Keep the title concise and meaningful.

7. Write Useful Meta Descriptions

The meta description provides a summary of a page.

<meta name="description"
      content="Learn HTML5 from basic document structure to advanced APIs with practical examples.">

Search engines may use the description in search snippets, but they can generate a different snippet from page content.

Best practices

  • Write a unique description for each page.
  • Summarize the actual page content.
  • Make it useful and understandable.
  • Avoid keyword stuffing.
  • Do not treat it as a guaranteed ranking factor.

8. Create SEO-Friendly URLs

A URL identifies the location of a web resource.

Example of a descriptive URL

https://example.com/html5/html-forms/

Example of a less descriptive URL

https://example.com/page?id=12345

Query parameters are valid and often necessary. The objective is to use clear, stable URLs that accurately identify the resource.

URL best practices

  • Use meaningful words.
  • Separate words with hyphens.
  • Keep URL paths reasonably concise.
  • Avoid unnecessary parameters.
  • Maintain consistent lowercase naming where practical.
  • Use a consistent trailing-slash convention.
  • Update internal links when URLs change.
GitHub Pages URLs are case-sensitive in practice. Ensure the capitalization of every folder and file in a link matches the actual repository path.

9. Internal and External Links

Links connect web pages and allow users and crawlers to discover related resources.

9.1 Internal links

Internal links connect pages within the same website.

<a href="../html5/index.html">
    HTML5 Course
</a>

9.2 External links

External links point to resources on other websites.

<a href="https://developer.mozilla.org/">
    MDN Web Docs
</a>

9.3 Descriptive anchor text

Anchor text is the clickable text of a link.

<!-- Descriptive anchor text -->

<a href="html5/index.html">
    Learn HTML5
</a>

<!-- Less descriptive anchor text -->

<a href="html5/index.html">
    Click here
</a>

Descriptive anchor text helps users understand the destination before opening it.

9.4 Link relationship attributes

<a href="https://example.com/"
   rel="nofollow">
    External resource
</a>

<a href="https://example.com/"
   rel="sponsored">
    Sponsored resource
</a>

<a href="https://example.com/"
   rel="ugc">
    User-generated link
</a>

These values communicate different link relationships. They are not interchangeable.

10. Image Optimization for SEO

Images should be relevant, accessible and efficiently delivered.

Example

<img
    src="images/lpc2129-microcontroller.jpg"
    alt="LPC2129 ARM7 microcontroller development board"
    width="600"
    height="400"
    loading="lazy">

Important image attributes

Attribute Purpose
src Specifies the image file location.
alt Provides alternative text describing the image.
width Specifies the image's intrinsic display width.
height Specifies the image's intrinsic display height.
loading Can request lazy loading for offscreen images.

Image optimization practices

  • Use descriptive filenames.
  • Write meaningful alternative text where appropriate.
  • Use modern image formats where suitable.
  • Specify width and height to help reserve layout space.
  • Compress images without unacceptable quality loss.
  • Lazy-load images that are not immediately visible.
  • Avoid lazy-loading the main above-the-fold or likely LCP image.
Alternative text is primarily an accessibility feature. It can also help search engines understand image content, but should describe the image rather than contain unrelated keywords.

11. Use Proper HTML Lists and Tables

Lists

Use ordered lists for sequences and unordered lists for groups of related items.

<h2>Embedded C Topics</h2>

<ul>
    <li>Variables and Data Types</li>
    <li>Pointers</li>
    <li>Structures</li>
    <li>Bitwise Operators</li>
</ul>

Tables

Use tables for tabular information, not merely to arrange page layout.

<table>
    <caption>Microcontroller Comparison</caption>

    <thead>
        <tr>
            <th scope="col">Controller</th>
            <th scope="col">Architecture</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>LPC2129</td>
            <td>ARM7TDMI-S</td>
        </tr>
    </tbody>
</table>

12. Mobile-Friendly HTML Structure

Modern websites should work across desktop computers, tablets and smartphones.

The viewport meta element helps browsers set the layout viewport for mobile devices.

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

Responsive HTML practices

  • Include the viewport meta element.
  • Use logical HTML document structure.
  • Provide readable text and usable navigation.
  • Use responsive images.
  • Avoid unnecessary horizontal scrolling.
  • Test pages on different screen sizes.
Responsive layout is generally implemented with CSS. HTML provides the structure and viewport information needed by the browser.

13. Canonical URLs

A canonical link element indicates the preferred URL for a page when multiple URLs contain identical or substantially similar content.

Syntax

<link rel="canonical"
      href="https://example.com/html5/">

Why canonical URLs are useful

  • Help indicate the preferred URL.
  • Help search engines understand duplicate or similar pages.
  • Reduce ambiguity between URL variations.
  • Support consistent URL signals.
A canonical link is a hint, not an absolute command. Search engines may select a different canonical URL based on their assessment of the pages.

14. Structured Data and HTML

Structured data provides machine-readable information about page content.

One common method is JSON-LD, which is added to an HTML document using a script element.

Example: Course structured data

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Course",
  "name": "HTML5 Complete Course",
  "description": "A structured course covering HTML5.",
  "provider": {
    "@type": "Organization",
    "name": "NS Learning Hub"
  }
}
</script>

The example demonstrates the JSON-LD format and Schema.org vocabulary.

Common structured data formats

  • JSON-LD
  • Microdata
  • RDFa
Structured data must accurately describe visible or otherwise eligible page content and follow the search engine's guidelines. Adding markup does not guarantee a rich result.

15. XML Sitemap and Robots.txt

15.1 XML Sitemap

An XML sitemap lists important URLs that a website owner wants search engines to discover.

<?xml version="1.0" encoding="UTF-8"?>

<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">

    <url>
        <loc>https://example.com/</loc>
    </url>

    <url>
        <loc>https://example.com/html5/</loc>
    </url>

</urlset>

15.2 robots.txt

The robots.txt file gives crawler-specific instructions about which URL paths they may access.

User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml

Both files support website discovery and crawl management, but they serve different purposes.

File Purpose
sitemap.xml Lists URLs that a site wants search engines to discover.
robots.txt Provides crawler access instructions for URL paths.
Neither file guarantees indexing or removal from search results. robots.txt is not an access-control or security mechanism.

16. SEO-Friendly HTML Document Example

The following example combines several practices discussed in this lesson.

<!DOCTYPE html>
<html lang="en">

<head>

    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Embedded Systems Course | NS Learning Hub</title>

    <meta name="description"
          content="Learn embedded systems, microcontrollers and Embedded C programming.">

    <link rel="canonical"
          href="https://example.com/embedded-systems/">

</head>

<body>

    <header>
        <h1>Embedded Systems Course</h1>
    </header>

    <nav aria-label="Main navigation">
        <ul>
            <li><a href="../index.html">Home</a></li>
            <li><a href="../html5/index.html">HTML5</a></li>
            <li><a href="../cpp/index.html">C++</a></li>
        </ul>
    </nav>

    <main>

        <article>

            <h2>Introduction to Embedded Systems</h2>

            <p>
                Embedded systems combine hardware and software
                to perform dedicated functions.
            </p>

            <section>
                <h3>Microcontrollers</h3>

                <p>
                    Learn about microcontroller architecture,
                    peripherals and interfacing.
                </p>
            </section>

            <section>
                <h3>Embedded C Programming</h3>

                <p>
                    Study programming concepts used in
                    embedded applications.
                </p>
            </section>

            <figure>
                <img
                    src="../images/lpc2129.jpg"
                    alt="LPC2129 ARM7 microcontroller development board"
                    width="600"
                    height="400"
                    loading="lazy">

                <figcaption>
                    LPC2129 microcontroller development board
                </figcaption>
            </figure>

            <p>
                <a href="../cpp/index.html">
                    Explore the C++ programming course
                </a>
            </p>

        </article>

    </main>

    <footer>
        <p>NS Learning Hub</p>
    </footer>

</body>

</html>
This is a structural example. The image path and canonical URL must be updated to match the actual published repository and page.

17. SEO Best Practices Checklist

  • Use a valid HTML document structure.
  • Set the correct document language.
  • Provide a unique and descriptive page title.
  • Write a useful meta description.
  • Use logical heading hierarchy.
  • Use semantic HTML elements where appropriate.
  • Write descriptive internal link text.
  • Ensure important pages are reachable through links.
  • Provide meaningful image alternative text.
  • Use mobile-friendly page layouts.
  • Check internal and external links.
  • Use canonical URLs where appropriate.
  • Provide structured data only when relevant and accurate.
  • Maintain an XML sitemap when useful.
  • Configure robots.txt correctly.
  • Validate HTML and monitor search performance.

18. Useful SEO Testing Tools

  • Google Search Console – Monitor search performance, indexing information and page issues.
  • PageSpeed Insights – Analyze performance and Core Web Vitals.
  • W3C Markup Validation Service – Check HTML markup validity.
  • Google Rich Results Test – Test eligible structured data for rich result features.
  • Google Search Central Documentation – Official search documentation and SEO guidance.
  • MDN HTML Documentation – HTML reference and learning material.

20. Interview Questions and Answers

Q1. What is SEO?

SEO is the process of improving a website's visibility in organic search engine results.

Q2. What are the three major search engine processes?

Crawling, indexing and ranking.

Q3. Why is semantic HTML important?

It provides meaningful document structure that supports accessibility and helps machines interpret page content.

Q4. What is the purpose of the title element?

It defines the document title, which may be used in browser tabs and search result titles.

Q5. What is a meta description?

It is a short summary of a page that search engines may use in search snippets.

Q6. What is heading hierarchy?

It is the logical organization of page headings using H1 through H6.

Q7. What is anchor text?

Anchor text is the visible clickable text of a hyperlink.

Q8. What is an internal link?

A link that points to another page or resource on the same website.

Q9. What is a canonical URL?

It is the preferred URL indicated for a page when duplicate or similar URL versions exist.

Q10. What is an XML sitemap?

It is a structured file that lists URLs a website owner wants search engines to discover.

Q11. What is robots.txt?

It is a text file that provides crawler access instructions for URL paths.

Q12. What is structured data?

Structured data provides machine-readable information about the content of a web page.

Q13. What is JSON-LD?

JSON-LD is a JSON-based format for expressing linked data and is commonly used for structured data in web pages.

Q14. Why is the alt attribute important?

It provides alternative text for an image, supporting users who cannot see or load the image.

Q15. Does valid HTML guarantee a high search ranking?

No. Valid HTML is useful, but rankings depend on many factors, including relevance, content quality, technical accessibility and competition.
