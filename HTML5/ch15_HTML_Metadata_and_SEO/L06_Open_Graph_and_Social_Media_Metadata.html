2. Introduction to Social Media Metadata

When someone shares a website URL on a social media platform, the platform may display a preview containing:

  • Website or article title.
  • Description or summary.
  • Preview image.
  • Website URL or domain.

Social media platforms can extract this information from metadata in the HTML document.

3. What Is Open Graph?

Open Graph is a metadata protocol originally introduced by Facebook to help web pages become rich objects when shared on social platforms.

It allows website developers to describe how a page should appear when its URL is shared.

Open Graph properties are written using HTML <meta> elements inside the <head> section.

Basic syntax

<meta property="og:title"
      content="HTML5 Complete Course">

Notice the use of the property attribute rather than the name attribute in this Open Graph example.

Open Graph metadata describes a page for social sharing. It does not replace the normal HTML title, meta description or search-engine indexing directives.

4. Important Open Graph Properties

Property Purpose
og:title Specifies the title of the shared page.
og:type Describes the type of content, such as website or article.
og:image Specifies the image used in the social preview.
og:url Specifies the canonical URL of the page for Open Graph purposes.
og:description Provides a short description of the page.
og:site_name Specifies the overall website or brand name.
og:locale Specifies the language and regional locale of the content.

4.1 og:title

Defines the title shown in the social sharing preview.

<meta property="og:title"
      content="NS Learning Hub">

4.2 og:type

Describes the type of content being shared.

<meta property="og:type"
      content="website">

Common values include:

  • website – General website page.
  • article – Article or editorial content.
  • book – Book-related content.
  • profile – Profile-related content.
  • video.movie – Movie-related video content.

4.3 og:image

Specifies the image displayed in a social media preview.

<meta property="og:image"
      content="https://example.com/images/preview.jpg">

Use a publicly accessible absolute URL for the image.

4.4 og:url

Specifies the URL representing the page.

<meta property="og:url"
      content="https://example.com/html5/">

4.5 og:description

Provides a summary of the page.

<meta property="og:description"
      content="Learn HTML5 with practical lessons and examples.">

4.6 og:site_name

Identifies the website name.

<meta property="og:site_name"
      content="NS Learning Hub">

4.7 og:locale

Identifies the language and regional locale of the content.

<meta property="og:locale"
      content="en_IN">

5. Additional Open Graph Image Properties

Additional properties can describe the preview image.

5.1 og:image:width

<meta property="og:image:width"
      content="1200">

5.2 og:image:height

<meta property="og:image:height"
      content="630">

5.3 og:image:alt

<meta property="og:image:alt"
      content="NS Learning Hub course preview">

These properties provide additional information about the image.

A 1200 × 630 pixel image is a common landscape format for social sharing previews. Platform-specific requirements and display behavior can change.

6. Complete Open Graph Example

The following example shows how to configure Open Graph metadata for a website.

<!DOCTYPE html>
<html lang="en">
<head>

    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>NS Learning Hub</title>

    <meta name="description"
          content="Learn programming and electronics.">

    <meta property="og:title"
          content="NS Learning Hub">

    <meta property="og:type"
          content="website">

    <meta property="og:url"
          content="https://example.com/">

    <meta property="og:image"
          content="https://example.com/images/preview.jpg">

    <meta property="og:description"
          content="Learn programming and electronics with structured courses.">

    <meta property="og:site_name"
          content="NS Learning Hub">

    <meta property="og:locale"
          content="en_IN">

</head>

<body>

    <h1>Welcome to NS Learning Hub</h1>

    <p>Explore programming and electronics courses.</p>

</body>
</html>
Replace the example domain and image URL with the actual publicly accessible URLs of your website. An inaccessible image may not appear in social previews.

7. What Are Twitter/X Cards?

Twitter Cards were designed to provide rich previews when URLs are shared on Twitter, now known as X.

Card metadata is declared using HTML meta elements with names such as twitter:card, twitter:title and twitter:image.

Basic syntax

<meta name="twitter:card"
      content="summary_large_image">

The metadata helps describe how the shared URL should be presented when the platform supports and processes those tags.

Common Twitter/X Card values

Card type Description
summary A compact card with a small thumbnail and text.
summary_large_image A card with a prominent large image and supporting text.
Platform support and preview behavior can change. Test the published page on the target platform rather than assuming that every declared card type will be displayed identically.

8. Important Twitter/X Card Metadata

8.1 twitter:card

Specifies the card presentation type.

<meta name="twitter:card"
      content="summary_large_image">

8.2 twitter:title

Defines the title used for the card.

<meta name="twitter:title"
      content="HTML5 Complete Course">

8.3 twitter:description

Provides a short description.

<meta name="twitter:description"
      content="Learn HTML5 from beginner to advanced level.">

8.4 twitter:image

Specifies the image displayed in the card.

<meta name="twitter:image"
      content="https://example.com/images/course.jpg">

8.5 twitter:image:alt

Provides alternative text describing the image.

<meta name="twitter:image:alt"
      content="HTML5 course illustration">

8.6 twitter:site

Can identify the X account associated with a website.

<meta name="twitter:site"
      content="@example">

8.7 twitter:creator

Can identify the content creator's X account.

<meta name="twitter:creator"
      content="@creator">

9. Open Graph vs Twitter/X Card Metadata

Feature Open Graph Twitter/X Cards
Purpose Describes content for social sharing. Describes content for X card previews.
Attribute property name
Title og:title twitter:title
Description og:description twitter:description
Image og:image twitter:image
Card type og:type twitter:card
URL og:url No direct equivalent is normally required for basic card metadata.

Some platforms can use Open Graph properties as fallback information when platform-specific metadata is missing. Actual behavior varies by platform.

10. Combining Open Graph and Twitter/X Metadata

A website can include both types of metadata in the same HTML document.

<head>

    <title>NS Learning Hub</title>

    <meta name="description"
          content="Learn programming and electronics.">

    <!-- Open Graph Metadata -->

    <meta property="og:title"
          content="NS Learning Hub">

    <meta property="og:type"
          content="website">

    <meta property="og:url"
          content="https://example.com/">

    <meta property="og:image"
          content="https://example.com/preview.jpg">

    <meta property="og:description"
          content="Explore structured technical courses.">

    <meta property="og:site_name"
          content="NS Learning Hub">

    <!-- Twitter/X Card Metadata -->

    <meta name="twitter:card"
          content="summary_large_image">

    <meta name="twitter:title"
          content="NS Learning Hub">

    <meta name="twitter:description"
          content="Explore structured technical courses.">

    <meta name="twitter:image"
          content="https://example.com/preview.jpg">

</head>

Providing both sets of metadata gives supported platforms more information about the shared page.

11. Social Media Metadata for Individual Pages

Different pages on a website should have metadata that describes their own content.

Example: HTML5 course page

<meta property="og:title"
      content="HTML5 Complete Course">

<meta property="og:description"
      content="Study HTML5 with structured lessons and examples.">

<meta property="og:image"
      content="https://example.com/images/html5-course.jpg">

<meta property="og:url"
      content="https://example.com/html5/">

Example: C++ course page

<meta property="og:title"
      content="C++ Complete Course">

<meta property="og:description"
      content="Learn C++ programming from basics to advanced concepts.">

<meta property="og:image"
      content="https://example.com/images/cpp-course.jpg">

<meta property="og:url"
      content="https://example.com/cpp/">
Use a page-specific title, description, image and URL. Reusing identical social metadata on every page can produce misleading previews.

12. Best Practices for Social Media Metadata

  1. Write clear and descriptive page titles.
  2. Provide a concise and relevant description.
  3. Use a high-quality preview image.
  4. Use absolute image URLs that social crawlers can access publicly.
  5. Keep the image relevant to the actual page content.
  6. Set the correct og:url.
  7. Use appropriate values for og:type.
  8. Include alternative text for important preview images.
  9. Use page-specific metadata rather than copying the same values everywhere.
  10. Check that the page is publicly accessible to social crawlers.
  11. Test the preview after publishing changes.
  12. Allow time for social platforms to refresh cached preview data.

13. Testing and Troubleshooting Social Previews

After adding metadata, test the published page using the tools provided by the target platform when available.

Useful resources

  • Facebook Sharing Debugger – Inspect and refresh Facebook sharing information.
  • Twitter Card Validator – Historical validator link; its availability and support may have changed.
  • X Developer Documentation – Cards – Documentation about X Cards.
  • Open Graph Protocol – Official protocol documentation.

Common troubleshooting checks

  • Confirm that the HTML source contains the correct meta elements.
  • Verify that the preview image URL opens without authentication.
  • Check that the image server returns the correct image content type.
  • Check whether robots.txt or access restrictions prevent the social crawler from retrieving the page or image.
  • Check the canonical URL and Open Graph URL for accuracy.
  • Refresh the platform's cached preview if the platform provides that feature.
A browser displaying a page correctly does not guarantee that a social crawler can retrieve it. Social crawlers may have different access, rendering and caching behavior.

15. Common Mistakes

  1. Using name instead of property for Open Graph properties.
  2. Using property instead of name for standard Twitter/X Card metadata.
  3. Leaving the preview image URL empty or incorrect.
  4. Using a relative image URL instead of a publicly accessible absolute URL.
  5. Providing duplicate or contradictory metadata.
  6. Using the same image for unrelated pages.
  7. Forgetting to update metadata after changing a page title or content.
  8. Assuming social previews update immediately despite caching.
  9. Confusing Open Graph metadata with search engine ranking directives.
  10. Assuming all social platforms support exactly the same metadata properties.

17. Interview Questions and Answers

Q1. What is Open Graph?

Open Graph is a metadata protocol that helps describe web pages when their URLs are shared on social platforms.

Q2. Why is Open Graph used?

It helps social platforms generate rich link previews containing titles, descriptions, images and URLs.

Q3. Where is Open Graph metadata placed?

Inside the <head> element of an HTML document.

Q4. What is og:title?

It defines the title of the page for Open Graph sharing.

Q5. What is og:image?

It identifies the image used in the social sharing preview.

Q6. What is og:type?

It identifies the type of content, such as a website or article.

Q7. What is og:url?

It identifies the URL representing the shared page.

Q8. What are Twitter/X Cards?

They are metadata-based formats used to present richer URL previews on X when supported.

Q9. What is twitter:card?

It specifies the card type, such as summary or summary_large_image.

Q10. What is the difference between Open Graph and Twitter/X metadata?

Open Graph uses properties such as og:title, while X Card metadata uses names such as twitter:title.

Q11. Can both metadata systems be used together?

Yes. A page can contain both Open Graph and Twitter/X Card metadata.

Q12. Why should absolute image URLs be used?

Absolute URLs provide a complete resource address that social crawlers can retrieve independently of the page's relative path.

Q13. What is og:site_name?

It identifies the name of the overall website.

Q14. Does Open Graph directly guarantee higher Google rankings?

No. Open Graph primarily provides social sharing metadata; it is not a direct guarantee of improved search rankings.

Q15. Why might an old social preview still appear?

Social platforms may cache previously retrieved metadata and images. The preview may need to be refreshed using the platform's available tools.

19. Lesson Summary

  • Open Graph helps describe pages for social media sharing.
  • Open Graph metadata is placed inside the HTML head.
  • og:title specifies the shared page title.
  • og:description provides a summary.
  • og:image identifies the preview image.
  • og:url identifies the page URL.
  • Twitter/X Cards provide platform-specific preview metadata.
  • Open Graph and Twitter/X metadata can be used together.
  • Absolute, publicly accessible image URLs are important.
  • Social platforms may cache metadata and preview images.
