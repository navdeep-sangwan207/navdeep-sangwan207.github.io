Lesson 4: Meta Robots and Search Engine Indexing

HTML5 – Complete Study Course | Chapter 15: HTML Metadata and SEO

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand search engine crawling, indexing and ranking.
  • Explain the purpose of the meta robots tag.
  • Use index, noindex, follow and nofollow directives.
  • Understand Googlebot-specific instructions.
  • Differentiate meta robots from robots.txt.
  • Understand the X-Robots-Tag HTTP response header.
  • Apply indexing instructions to web pages correctly.

2. Introduction to Search Engine Indexing

Search engines such as Google discover web pages, analyze their content and store information about them in a searchable database called an index.

Three important processes are involved:

2.1 Crawling

Crawling is the process in which automated programs called crawlers or bots discover and access web pages.

Examples of search engine crawlers include:

  • Googlebot – Google's web crawler.
  • Bingbot – Microsoft's Bing crawler.

2.2 Indexing

Indexing is the process of analyzing discovered content and deciding whether and how to store information about a page in a search engine's index.

2.3 Ranking

Ranking is the process of ordering eligible indexed pages in response to a user's search query.

Crawling
→
Indexing
→
Ranking
Important: Crawling, indexing and ranking are different processes. A page can be crawled without being indexed. A page generally needs to be indexed to appear as a normal search result.

3. What Is the Meta Robots Tag?

The meta robots tag provides instructions to search engine crawlers about how they should handle a particular HTML page.

It is placed inside the <head> element.

Syntax

<meta name="robots" content="index, follow">

Explanation:

  • name="robots" identifies the instructions as applying to crawlers generally.
  • content contains one or more directives.
  • index permits the page to be considered for indexing.
  • follow permits crawlers to follow links on the page.
Example: 
<head>
    <title>Embedded Systems Course</title>
    <meta name="robots" content="index, follow">
</head>
This page does not request that search engines exclude it from their index.

4. Important Meta Robots Directives

Directive Meaning
index Allows the page to be considered for indexing.
noindex Requests that the page not be included in the search engine index.
follow Allows crawlers to follow links on the page.
nofollow Requests that crawlers not follow links on the page.
none Equivalent to noindex, nofollow for Google.
all Equivalent to index, follow for Google.
nosnippet Requests that Google not show a text snippet or video preview for the page.
notranslate Requests that Google not offer a translated version of the page in search results.
noarchive Historically requested that search engines not show a cached copy. Google no longer supports this directive.

4.1 Index Directive

<meta name="robots" content="index">

Indicates that the page may be considered for indexing.

4.2 Noindex Directive

<meta name="robots" content="noindex">

Requests that the page not appear in search engine results.

4.3 Follow Directive

<meta name="robots" content="follow">

Allows crawlers to follow links found on the page.

4.4 Nofollow Directive

<meta name="robots" content="nofollow">

Requests that crawlers do not follow links on the page.

4.5 Combining Directives

<meta name="robots" content="noindex, follow">

This requests that the page not be indexed while allowing crawlers to follow its links.

Technical note: Search engines may interpret some directives differently. Google treats nofollow as a hint rather than an absolute guarantee. Do not assume that every search engine supports every directive.

5. Additional Google Robots Directives

Google supports additional directives that control how content can appear in search results.

5.1 max-snippet

Controls the maximum number of characters that Google may use in a text snippet.

<meta name="robots" content="max-snippet:150">

5.2 max-image-preview

Controls the maximum size of image previews shown in search results.

<meta name="robots" content="max-image-preview:large">

Common values:

  • none – No image preview.
  • standard – A standard-sized image preview.
  • large – A larger image preview.

5.3 max-video-preview

Limits the maximum duration, in seconds, of a video preview.

<meta name="robots" content="max-video-preview:10">

5.4 unavailable_after

Specifies a date and time after which Google should stop showing a page in search results.

<meta name="robots"
      content="unavailable_after: 2027-01-31T23:59:00+00:00">
Note: These are search-engine-specific controls. Check the documentation of the search engine before relying on a particular directive.

6. Googlebot-Specific Meta Tag

The robots meta tag applies to crawlers generally. A website can also provide instructions specifically for Google's crawler using googlebot.

Syntax

<meta name="googlebot" content="noindex">

Example

<head>
    <title>Internal Course Page</title>

    <meta name="robots" content="index, follow">

    <meta name="googlebot" content="noindex">
</head>

The Googlebot-specific directive provides a more specific instruction for Google. In this example, Google is asked not to index the page.

Important: When both general and crawler-specific instructions exist, the more specific applicable instruction can control that crawler's behavior. Avoid contradictory directives unless you understand their interaction.

7. What Is robots.txt?

robots.txt is a plain-text file used to communicate crawling rules to automated crawlers.

It is normally placed at the root of a website.

Example location

https://example.com/robots.txt

Basic robots.txt example

User-agent: *
Disallow: /private/
Allow: /public/

Explanation:

  • User-agent: * – Applies the rules to all matching crawlers.
  • Disallow: /private/ – Requests that crawlers do not crawl URLs under this path.
  • Allow: /public/ – Explicitly permits crawling of the specified path where applicable.

7.1 Blocking a Directory

User-agent: *
Disallow: /admin/
Disallow: /drafts/

7.2 Allowing the Entire Website

User-agent: *
Allow: /

7.3 Blocking the Entire Website

User-agent: *
Disallow: /
Security warning: robots.txt is not an access-control mechanism. Anyone can open it and read its rules. It does not protect confidential files or prevent people from visiting URLs. Use authentication and server-side access controls for private content.

8. Meta Robots vs robots.txt

Feature Meta Robots robots.txt
Type HTML meta element Plain-text file
Location Inside the HTML head Website root directory
Purpose Provides indexing and link-following instructions. Provides crawling rules.
Page-specific control Yes Controls URL paths and crawler access rules.
Can request noindex? Yes No, not reliably through a standard robots.txt rule.
Applies to non-HTML files? No, it is an HTML element. Can control crawler access to URL paths for supported crawlers.
Critical distinction: If a URL is blocked by robots.txt, a crawler may be unable to read its HTML meta robots tag. Therefore, do not block a page in robots.txt if you need Google to crawl it and discover its noindex directive.

A blocked URL can sometimes still appear in search results if other pages link to it. The search engine may know the URL without being able to crawl its content.

9. X-Robots-Tag HTTP Header

The X-Robots-Tag is an HTTP response header that provides indexing instructions to search engine crawlers.

Unlike the HTML meta robots element, it can be used for non-HTML resources such as PDF files, images and other downloadable documents.

Example HTTP response

HTTP/1.1 200 OK
Content-Type: application/pdf
X-Robots-Tag: noindex

This tells supported crawlers not to index the PDF resource.

Example with Apache configuration

<FilesMatch "\.pdf$">
    Header set X-Robots-Tag "noindex"
</FilesMatch>

This is an Apache server configuration example. It requires the appropriate server module and configuration permissions; it is not HTML code.

Remember: GitHub Pages does not provide normal Apache configuration access. You cannot directly add an Apache .htaccess rule to a GitHub Pages site.

10. Canonical URL and Indexing

A canonical link identifies the preferred URL for a page when similar or duplicate content is available at multiple URLs.

<link rel="canonical"
      href="https://example.com/courses/html5/">

Canonicalization and indexing directives have different purposes:

  • canonical – Indicates the preferred URL among duplicate or similar pages.
  • noindex – Requests that a page not be included in search results.
  • robots.txt – Controls crawler access to URL paths.
A canonical declaration is a signal, not an absolute command. Search engines can choose a different canonical URL based on their analysis.

11. Practical Example – HTML5 Course Page

Suppose a website has a public HTML5 course page that should be available in search results.

HTML code

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>HTML5 Complete Course</title>

    <meta name="description"
          content="Learn HTML5 from basic to advanced level.">

    <meta name="robots"
          content="index, follow">

    <link rel="canonical"
          href="https://example.com/html5/">
</head>

<body>
    <h1>HTML5 Complete Course</h1>

    <p>Learn HTML5 with practical examples.</p>

    <a href="chapter1.html">Start Learning</a>
</body>
</html>

Example: Page that should not be indexed

<head>
    <title>Temporary Preview</title>
    <meta name="robots" content="noindex, nofollow">
</head>

The second example requests that crawlers not index the page and not follow its links.

12. Applying robots.txt to GitHub Pages

For your GitHub Pages learning portal, the robots.txt file should be placed at the root of the deployed website.

Example repository structure

repository-root/
│
├── index.html
├── about.html
├── style.css
├── script.js
├── robots.txt
│
├── html5/
│   └── index.html
│
└── cpp/
    └── index.html

Example robots.txt for a public learning portal

User-agent: *
Allow: /

Sitemap: https://navdeep-sangwan207.github.io/sitemap.xml

The sitemap line is appropriate only after you have created and published a valid sitemap at that URL. Otherwise, omit that line.

Important for GitHub Pages:
  • Use the exact lowercase filename robots.txt.
  • Place it at the deployed site's root, not inside the HTML5 course folder.
  • Check that the file is publicly accessible at https://navdeep-sangwan207.github.io/robots.txt.
  • Do not disallow your course pages if you want search engines to crawl and discover them.

13. Common Mistakes

  1. Placing the meta robots element outside the HTML <head>.
  2. Using noindex when the page should appear in search results.
  3. Blocking a page in robots.txt while expecting crawlers to read its noindex tag.
  4. Assuming robots.txt protects private information.
  5. Confusing crawling with indexing.
  6. Assuming nofollow is an absolute guarantee that links will never be followed.
  7. Using HTML meta robots for PDF indexing instructions instead of an appropriate HTTP header.
  8. Assuming that index, follow guarantees indexing or high search rankings.
  9. Adding conflicting general and crawler-specific directives.
  10. Using unsupported or obsolete directives without checking search-engine documentation.

15. Interview Questions and Answers

Q1. What is a search engine crawler?

A search engine crawler is an automated program that discovers and accesses web pages.

Q2. What is crawling?

Crawling is the process of discovering and fetching web pages using automated bots.

Q3. What is indexing?

Indexing is the process of analyzing page content and storing eligible information in a search engine's index.

Q4. What is the meta robots tag?

It is an HTML meta element that provides indexing and link-following instructions to crawlers.

Q5. Where is the meta robots tag placed?

Inside the <head> element of an HTML document.

Q6. What is the purpose of noindex?

It requests that a search engine not include the page in its search index.

Q7. What is the purpose of nofollow?

It requests that crawlers not follow links on the page. Google treats this directive as a hint.

Q8. What is robots.txt?

It is a plain-text file that communicates crawler access rules for a website.

Q9. What is the difference between robots.txt and meta robots?

robots.txt controls crawler access to URL paths, while meta robots provides page-level indexing and link-following instructions.

Q10. What is Googlebot?

Googlebot is Google's web crawling software.

Q11. What is the X-Robots-Tag?

It is an HTTP response header used to provide indexing instructions, including for non-HTML files.

Q12. Can robots.txt prevent a page from being indexed?

Not reliably. A blocked URL may still be indexed without its content if discovered through other links. Use an accessible noindex directive when appropriate.

Q13. Can meta robots protect confidential pages?

No. It provides crawler instructions, not access control. Confidential content requires authentication or authorization.

Q14. What does max-snippet do?

It controls the maximum number of characters Google may use in a search-result text snippet.

Q15. What is the difference between crawling and ranking?

Crawling discovers and fetches pages. Ranking orders eligible search results according to relevance and other search-system signals.

16. Multiple Choice Questions

1. Which HTML element provides indexing instructions?

A. <title>   B. <meta>   C. <footer>   D. <section>

Answer: B. <meta>

2. Which directive requests that a page not be indexed?

A. index   B. follow   C. noindex   D. all

Answer: C. noindex

3. Which file communicates crawler access rules?

A. index.html   B. robots.txt   C. style.css   D. script.js

Answer: B. robots.txt

4. Where is the meta robots tag placed?

A. Body   B. Footer   C. Head   D. Table

Answer: C. Head

5. Which crawler is associated with Google?

A. Bingbot   B. Googlebot   C. WebKit   D. Nodebot

Answer: B. Googlebot

6. Which directive requests that crawlers not follow page links?

A. follow   B. index   C. nofollow   D. allow

Answer: C. nofollow

7. Which HTTP header can control indexing of a PDF?

A. Content-Length   B. X-Robots-Tag   C. Host   D. Accept

Answer: B. X-Robots-Tag

8. Which directive controls the size of Google's image previews?

A. max-image-preview   B. nofollow   C. index   D. none

Answer: A. max-image-preview

9. Does robots.txt provide password protection?

A. Yes   B. No   C. Only for PDFs   D. Only for Google

Answer: B. No

10. Which is the correct order of the general search processes?

A. Ranking → Crawling → Indexing

B. Indexing → Ranking → Crawling

C. Crawling → Indexing → Ranking

Answer: C. Crawling → Indexing → Ranking

17. Lesson Summary

  • Search engines use crawlers to discover web pages.
  • Crawling, indexing and ranking are separate processes.
  • The meta robots tag provides page-level crawler instructions.
  • index and follow are permissive directives.
  • noindex and nofollow request restrictions.
  • Googlebot-specific instructions can target Google's crawler.
  • robots.txt communicates crawling rules for URL paths.
  • X-Robots-Tag provides indexing instructions through HTTP headers.
  • robots.txt and meta robots are not security mechanisms.
  • Canonical URLs and noindex directives serve different purposes.
