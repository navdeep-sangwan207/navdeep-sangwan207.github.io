Lesson 5: Favicon and Link Relationships

1. Learning Objectives

After completing this lesson, you will be able to:

  • Understand what a favicon is and why websites use it.
  • Add a favicon to an HTML document.
  • Identify common favicon image formats.
  • Understand the HTML <link> element.
  • Explain the purpose of the rel attribute.
  • Use stylesheet, icon, canonical, alternate and other link relationships.
  • Configure favicons for different devices and display contexts.

2. What Is a Favicon?

A favicon (short for favorite icon) is a small graphical icon associated with a website or web page.

It can appear in several browser and device locations:

  • Browser tabs.
  • Bookmarks and favorites.
  • Browser history.
  • Mobile home-screen shortcuts, when supported and configured.
  • Other browser interface locations.

Example of a favicon

N NS Learning Hub

This is a simplified illustration of a browser tab displaying a website icon.

A favicon helps users recognize a website quickly, especially when multiple browser tabs are open.

3. Common Favicon Formats

Format Extension Description
ICO .ico Traditional favicon format. Can contain multiple icon sizes and color depths.
PNG .png Raster image format supporting transparency.
SVG .svg Vector format that can scale to different sizes without losing sharpness. Browser support varies by context.
GIF .gif Can be used in some favicon contexts, although static PNG, ICO and SVG are more common choices.

Common icon sizes

  • 16 × 16 pixels – Small browser icon.
  • 32 × 32 pixels – Common browser icon size.
  • 48 × 48 pixels – Larger icon contexts.
  • 180 × 180 pixels – Common Apple touch icon size.
  • 192 × 192 pixels – Common Android/PWA icon size.
  • 512 × 512 pixels – Common large PWA icon size.
These are common asset sizes, not a requirement that every website must provide all of them. Actual selection depends on browser, operating system and installation context.

4. How to Add a Favicon in HTML

The favicon is declared using the HTML <link> element inside the document's <head>.

4.1 Using an ICO file

<head>
    <title>My Website</title>
    <link rel="icon" href="favicon.ico">
</head>

4.2 Using a PNG file

<link rel="icon"
      type="image/png"
      href="favicon.png">

4.3 Using an SVG file

<link rel="icon"
      type="image/svg+xml"
      href="favicon.svg">

4.4 Using an Apple Touch Icon

<link rel="apple-touch-icon"
      href="apple-touch-icon.png">

This declares an icon intended for Apple touch-device contexts.

5. Understanding the HTML Link Element

The <link> element defines a relationship between the current HTML document and an external resource.

It is commonly used for:

  • Connecting external CSS files.
  • Declaring favicons.
  • Identifying canonical URLs.
  • Providing alternate versions of content.
  • Preloading important resources.
  • Declaring other resource relationships.

Syntax

<link rel="relationship"
      href="resource-location">

Important attributes

Attribute Purpose
rel Specifies the relationship between the current document and the linked resource.
href Specifies the URL of the linked resource.
type Provides the resource's media type, such as text/css or image/png.
media Specifies the media condition for which the linked resource is intended.
sizes Specifies icon dimensions, commonly used with icon links.
hreflang Indicates the language of the linked resource when applicable.
crossorigin Configures cross-origin handling for applicable resource requests.
integrity Provides a Subresource Integrity hash for supported external resources.
referrerpolicy Controls the referrer information sent when fetching the resource.
Not every attribute is valid or meaningful for every link relationship. Use attributes according to the particular resource type and HTML specification.

6. Understanding the rel Attribute

The rel attribute is one of the most important attributes of the <link> element.

It identifies how the linked resource is related to the current page.

General syntax

<link rel="stylesheet" href="style.css">

In this example:

  • link – HTML element.
  • rel="stylesheet" – Declares the relationship as a stylesheet.
  • href="style.css" – Identifies the external CSS file.

7. Important Link Relationships

7.1 stylesheet

Connects an external CSS stylesheet to the HTML document.

<link rel="stylesheet" href="style.css">

7.2 icon

Declares a favicon for the page.

<link rel="icon" href="favicon.png" type="image/png">

7.3 canonical

Identifies the preferred URL for a page when duplicate or similar URLs exist.

<link rel="canonical"
      href="https://example.com/html5/">

7.4 alternate

Identifies an alternate version of the current document, such as a translated page or an RSS feed.

Example: alternate language version.

<link rel="alternate"
      hreflang="hi"
      href="https://example.com/hi/">

Example: RSS feed.

<link rel="alternate"
      type="application/rss+xml"
      title="Website RSS Feed"
      href="feed.xml">

7.5 author

Identifies a resource associated with the author of the document.

<link rel="author" href="about-author.html">
The author relationship is a historical HTML link type. It should not be treated as a modern SEO ranking signal or a substitute for visible author information.

7.6 help

Links to a resource that provides help for the current document.

<link rel="help" href="help.html">

7.7 license

Links to information about the license applicable to the current document.

<link rel="license" href="license.html">

7.8 next and prev

These link types historically identified the next and previous documents in a sequence.

<link rel="prev" href="chapter1.html">
<link rel="next" href="chapter3.html">
These relationships can describe document sequences, but Google no longer uses rel="next" and rel="prev" as pagination indexing signals.

8. Resource Loading Relationships

Some link relationships help browsers discover and load resources efficiently.

8.1 preload

Requests that the browser fetch an important resource early because it is needed soon by the current page.

<link rel="preload"
      href="main-font.woff2"
      as="font"
      type="font/woff2"
      crossorigin>

8.2 prefetch

Hints that a resource may be needed for a future navigation.

<link rel="prefetch"
      href="next-chapter.html">

8.3 preconnect

Allows the browser to establish an early connection to another origin.

<link rel="preconnect"
      href="https://fonts.googleapis.com">

8.4 dns-prefetch

Hints that the browser should perform DNS resolution for an external origin early.

<link rel="dns-prefetch"
      href="//example.com">

8.5 modulepreload

Requests early fetching and preparation of a JavaScript module.

<link rel="modulepreload"
      href="app.js">
Relationship Main purpose
preload Fetch an important resource needed by the current page.
prefetch Fetch a resource that may be needed in a future navigation.
preconnect Establish an early connection to an origin.
dns-prefetch Resolve an origin's domain name early.
modulepreload Fetch and prepare a JavaScript module early.
Resource hints are performance hints, not guarantees. Incorrect use of preload can waste bandwidth or compete with more important resources.

9. The sizes Attribute for Favicons

The sizes attribute describes the dimensions of an icon resource.

Example

<link rel="icon"
      href="favicon-32.png"
      type="image/png"
      sizes="32x32">

Multiple icon resources can be declared:

<link rel="icon"
      href="favicon-16.png"
      type="image/png"
      sizes="16x16">

<link rel="icon"
      href="favicon-32.png"
      type="image/png"
      sizes="32x32">

<link rel="icon"
      href="favicon.svg"
      type="image/svg+xml">

The browser can select a suitable icon based on its capabilities and the display context.

For scalable SVG favicons, the special value sizes="any" may be used to indicate that the icon is scalable.

10. Complete Favicon Configuration Example

The following example demonstrates several common icon declarations and link relationships in a single HTML document.

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>NS Learning Hub</title>

    <meta name="description"
          content="Learn programming and electronics.">

    <link rel="icon"
          href="favicon.ico">

    <link rel="icon"
          type="image/png"
          sizes="32x32"
          href="favicon-32.png">

    <link rel="icon"
          type="image/svg+xml"
          href="favicon.svg">

    <link rel="apple-touch-icon"
          href="apple-touch-icon.png">

    <link rel="stylesheet"
          href="style.css">

    <link rel="canonical"
          href="https://example.com/">

</head>

<body>
    <h1>Welcome to NS Learning Hub</h1>
    <p>Learn HTML, C++, Linux and Embedded Systems.</p>
</body>
</html>

Replace the example filenames and canonical URL with actual resources from your website.

11. Practical Application – NS Learning Hub

For your GitHub Pages learning portal, you can organize favicon assets at the repository root.

Suggested file structure

repository-root/
│
├── index.html
├── about.html
├── style.css
├── script.js
│
├── favicon.ico
├── favicon.svg
├── favicon-32.png
├── apple-touch-icon.png
│
├── html5/
│   └── index.html
│
└── cpp/
    └── index.html

Root page configuration

<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>NS Learning Hub</title>

    <link rel="icon"
          href="/favicon.ico">

    <link rel="icon"
          type="image/svg+xml"
          href="/favicon.svg">

    <link rel="apple-touch-icon"
          href="/apple-touch-icon.png">

    <link rel="stylesheet"
          href="/style.css">
</head>
GitHub Pages path consideration: A leading slash such as /favicon.ico points to the domain root. This is suitable for a user or organization site published at the domain root. For a project site published under a repository subpath, use the correct project path or a relative URL instead.

Testing your favicon

  1. Commit and push the favicon image files to GitHub.
  2. Add the appropriate <link rel="icon"> elements to your page head.
  3. Open the published website in a browser.
  4. Check the browser tab for the icon.
  5. If the old icon remains, try a hard refresh or clear the browser cache.
  6. Open the favicon file URL directly to confirm that it loads.

12. Common Mistakes

  1. Forgetting to add the favicon declaration inside the document head.
  2. Using an incorrect image filename or file extension.
  3. Providing an incorrect relative path to the icon.
  4. Using a low-resolution or poorly designed icon.
  5. Forgetting that file paths on GitHub Pages are case-sensitive.
  6. Using rel="icon" with a missing or incorrect href.
  7. Confusing rel="stylesheet" with the favicon relationship.
  8. Preloading resources that are not important to the initial page load.
  9. Assuming that every browser supports every icon format identically.
  10. Using an incorrect canonical URL.

14. Interview Questions and Answers

Q1. What is a favicon?

A favicon is a small icon associated with a website. It commonly appears in browser tabs and bookmarks.

Q2. What is the full form of favicon?

Favicon means favorite icon.

Q3. Which HTML element is used to add a favicon?

The <link> element with rel="icon".

Q4. Where is the favicon declaration placed?

Inside the <head> element.

Q5. Which file formats can be used for favicons?

Common formats include ICO, PNG and SVG. Browser support depends on the format and context.

Q6. What is the purpose of the link element?

It establishes a relationship between the current document and an external resource.

Q7. What is the purpose of the rel attribute?

It specifies the relationship between the current document and the linked resource.

Q8. What does rel="stylesheet" mean?

It identifies the linked resource as a stylesheet.

Q9. What does rel="canonical" mean?

It identifies the preferred URL for a page when duplicate or similar URLs exist.

Q10. What is rel="alternate" used for?

It identifies an alternate version of the current document, such as a translated version or a feed.

Q11. What is the purpose of the sizes attribute?

It describes the dimensions of an icon resource.

Q12. What is the difference between preload and prefetch?

Preload is used for resources needed by the current page, while prefetch hints that a resource may be needed for future navigation.

Q13. What is preconnect?

It allows the browser to establish an early connection to an external origin.

Q14. What is an Apple touch icon?

It is an icon resource declared for Apple touch-device contexts, commonly used when adding a website shortcut to a home screen.

Q15. Can a website have multiple favicon declarations?

Yes. Multiple declarations can provide different formats or sizes so browsers can select an appropriate icon.

16. Lesson Summary

  • A favicon is a small icon associated with a website.
  • The <link> element establishes relationships with external resources.
  • The rel attribute identifies the relationship type.
  • The href attribute specifies the resource location.
  • ICO, PNG and SVG are common favicon formats.
  • rel="stylesheet" connects an external CSS file.
  • rel="canonical" identifies a preferred URL.
  • rel="alternate" identifies alternate document versions.
  • preload, prefetch and preconnect provide resource-loading hints.
  • Correct file paths are important when publishing a website on GitHub Pages.
