Lesson 3: Character Encoding and Viewport

Chapter 15: HTML Metadata and SEO

Understand character encoding, UTF-8, the charset attribute, viewport metadata and how browsers display web pages across different devices.

1. Introduction

Every HTML document contains text. A browser needs to know how that text is encoded so it can correctly interpret and display characters.

Similarly, a browser needs information about the layout viewport to display a web page appropriately on mobile devices.

HTML provides two important metadata declarations:

  • charset – Declares character encoding.
  • viewport – Configures viewport behavior.
<meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0">

2. What Is Character Encoding?

Character encoding is a system that represents text characters using numerical values that can be stored and processed by computers.

Computers store data as binary values. Character encoding defines how characters are represented using those values.

Example

Consider the following text:

Hello World
नमस्ते दुनिया
Café
© 2026

A browser needs to interpret the document's character encoding correctly to display these characters as intended.

Why Is Character Encoding Important?

  • Displays letters and symbols correctly.
  • Supports multiple languages.
  • Prevents many text corruption problems.
  • Helps browsers interpret document text.
  • Supports international web content.

3. Common Character Encodings

Several character encoding systems have been used in computing and web development.

Encoding Description
ASCII A character encoding originally designed for basic English letters, digits and control characters.
ISO-8859-1 An older 8-bit encoding used for many Western European characters.
UTF-8 A Unicode encoding using one to four bytes per code point.
UTF-16 A Unicode encoding using one or two 16-bit code units per code point.
UTF-8 is the recommended character encoding for modern HTML documents. It supports characters from many writing systems and is compatible with ASCII.

4. What Is UTF-8?

UTF-8 stands for Unicode Transformation Format (8-bit). It is a variable-length character encoding for Unicode.

UTF-8 uses between one and four bytes to encode a Unicode code point.

UTF-8 Characteristics

  • Supports characters from many languages.
  • Supports symbols and special characters.
  • Uses one to four bytes per Unicode code point.
  • ASCII characters use the same byte values in UTF-8.
  • Widely used in web development.

Example Characters

English: Hello

Hindi: नमस्ते

French: Bonjour, café

German: Grüße

Symbol: © ® € ✓

Emoji: 😀 🚀 🌐

Some visible symbols, such as emoji, can consist of multiple Unicode code points. UTF-8 encodes each code point using its byte sequence.

5. The Charset Attribute

The charset attribute of the meta element declares the character encoding of an HTML document.

Syntax

<meta charset="UTF-8">

Explanation

  • meta – Defines document metadata.
  • charset – Declares the encoding type.
  • UTF-8 – Specifies the Unicode encoding.

Correct Placement

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>My HTML Page</title> </head> <body> <h1>Welcome</h1> </body> </html>
Place the charset declaration near the beginning of the head element so the browser can identify the encoding early. The HTML standard requires the declaration to be entirely within the first 1024 bytes of the document.

6. What Happens When Character Encoding Is Incorrect?

If the actual document encoding and the declared encoding do not match, text may be displayed incorrectly.

Example of Incorrect Display

Intended text: Café

Possible incorrect display: CafÃ©

This type of problem is commonly called character encoding corruption or mojibake.

Common Causes

  • Missing charset declaration.
  • Incorrect charset declaration.
  • Saving a file in an encoding different from the declared encoding.
  • Incorrect server response character encoding.
  • Incorrect processing of text by software.

Prevention

  1. Save HTML files using UTF-8.
  2. Declare UTF-8 using meta charset.
  3. Configure the server to send a matching charset when applicable.
  4. Test pages containing international characters.

7. What Is a Viewport?

A viewport is the area of a browser through which a web page is displayed.

Its dimensions depend on the browser window and the device.

Examples of Devices

  • Desktop computers.
  • Laptops.
  • Tablets.
  • Smartphones.

The viewport determines the visible area of a document. On mobile devices, browsers may use a layout viewport that differs from the physical width of the device screen.

Viewport metadata helps browsers configure the layout viewport. It does not automatically make a website responsive. Responsive CSS is also needed.

8. What Is Viewport Metadata?

Viewport metadata is defined using the meta element with name="viewport".

Syntax

<meta name="viewport" content="width=device-width, initial-scale=1.0">

This declaration tells the browser to use the device's viewport width as the layout viewport width and to start at the specified initial scale.

Explanation of Attributes

Property Meaning
name="viewport" Identifies viewport metadata.
width=device-width Sets the layout viewport width to the device width in CSS pixels.
initial-scale=1.0 Sets the initial zoom scale to 1.

9. Understanding Viewport Properties

1. width

Specifies the width of the layout viewport.

<meta name="viewport" content="width=device-width">

2. initial-scale

Specifies the initial zoom level when the page is first loaded.

<meta name="viewport" content="initial-scale=1.0">

3. minimum-scale

Specifies a lower zoom limit.

<meta name="viewport" content="minimum-scale=1.0">

4. maximum-scale

Specifies an upper zoom limit.

<meta name="viewport" content="maximum-scale=3.0">

5. user-scalable

Historically used to control whether users could zoom the page.

<meta name="viewport" content="user-scalable=no">
Avoid disabling user zoom or imposing restrictive minimum and maximum scale values. Users with low vision may need to enlarge content. Accessibility requires preserving user control over zoom.

10. Why Is Viewport Metadata Important?

Without an appropriate viewport declaration, some mobile browsers may use a wider layout viewport and scale the page down to fit the screen.

Benefits

  • Helps mobile browsers use the intended layout width.
  • Supports responsive page layouts.
  • Improves readability on smaller screens.
  • Helps CSS media queries work as intended.
  • Reduces unwanted initial scaling behavior.

Without Viewport Metadata

<head> <title>Mobile Page</title> </head>

A mobile browser may initially lay out the page using a wider virtual viewport, depending on its behavior.

With Viewport Metadata

<head> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Mobile Page</title> </head>

The browser is instructed to use the device width as the layout viewport width.

11. Viewport Metadata and Responsive Web Design

Responsive Web Design is an approach in which a website adapts its layout to different screen sizes and devices.

Viewport metadata is one part of responsive web development. CSS layout techniques are also required.

Complete Example

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Responsive Learning Page</title> <style> .container { max-width: 1000px; margin: auto; padding: 20px; } .course-grid { display: grid; grid-template-columns: repeat(2, 1fr); gap: 20px; } .course-card { background: #e8f0fe; padding: 20px; border-radius: 8px; } @media (max-width: 600px) { .course-grid { grid-template-columns: 1fr; } } </style> </head> <body> <div class="container"> <h1>Learning Portal</h1> <div class="course-grid"> <div class="course-card"> <h2>HTML5</h2> <p>Learn HTML5 fundamentals.</p> </div> <div class="course-card"> <h2>Linux</h2> <p>Learn Linux fundamentals.</p> </div> </div> </div> </body> </html>

Expected Result

  • On wider screens, the two course cards appear in two columns.
  • On screens up to 600 CSS pixels wide, the cards appear in one column.
  • The viewport declaration helps the browser use the device width for the layout viewport.

12. Difference Between Charset and Viewport Metadata

Charset Metadata Viewport Metadata
Defines character encoding. Configures viewport behavior.
Helps interpret document text. Helps determine the layout viewport.
Common value: UTF-8. Common values: width=device-width and initial-scale=1.0.
Prevents many character display problems. Supports mobile-friendly page layouts.

13. Common Mistakes and Best Practices

Common Mistake Best Practice
Missing charset declaration. Declare UTF-8 near the beginning of head.
Saving a file in a different encoding. Save the HTML file using UTF-8.
Incorrect viewport width. Use width=device-width for typical responsive pages.
Missing initial scale. Usually set initial-scale=1.0.
Disabling user zoom. Allow users to zoom the page.
Assuming viewport metadata creates responsive layouts. Use responsive CSS as well.
Placing charset too late. Declare it early in the head.

15. Interview Questions and Answers

Q1. What is character encoding?
Character encoding defines how characters are represented as numerical values and bytes for storage and processing.
Q2. What is UTF-8?
UTF-8 is a variable-length Unicode encoding that uses one to four bytes per code point.
Q3. What is the purpose of charset?
It declares the character encoding of an HTML document.
Q4. How do you declare UTF-8 in HTML?
Using <meta charset="UTF-8"> inside the head.
Q5. Why is UTF-8 recommended?
It supports a wide range of Unicode characters and is compatible with ASCII.
Q6. What is mojibake?
It is incorrectly displayed text caused by character encoding interpretation problems.
Q7. What is a viewport?
It is the browser's visible area through which a web document is displayed.
Q8. What is viewport metadata?
It is metadata used to configure the layout viewport and initial scale.
Q9. What does width=device-width mean?
It sets the layout viewport width to the device's width in CSS pixels.
Q10. What does initial-scale=1.0 mean?
It sets the initial zoom scale to 1.
Q11. Does viewport metadata alone make a website responsive?
No. Responsive CSS techniques such as flexible layouts, media queries and responsive images are also needed.
Q12. Why should user zoom not be disabled?
Users with low vision may need to enlarge content. Disabling zoom creates an accessibility barrier.
Q13. Where should charset metadata be placed?
Near the beginning of the head element, within the first 1024 bytes of the document.
Q14. What is the difference between UTF-8 and ASCII?
ASCII represents a limited set of characters. UTF-8 supports Unicode and preserves ASCII character byte values.
Q15. Which metadata is important for mobile layouts?
The viewport metadata, commonly declared with width=device-width and initial-scale=1.0.
