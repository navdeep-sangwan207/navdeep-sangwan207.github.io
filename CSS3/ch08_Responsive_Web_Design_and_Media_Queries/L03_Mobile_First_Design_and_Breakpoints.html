Lecture 3: Mobile-First Design and Breakpoints

Chapter 8 – Responsive Web Design and Media Queries

Learn to design for smaller screens first and progressively adapt layouts for larger screens.

1. Learning Objectives

  • Understand mobile-first responsive design.
  • Differentiate mobile-first and desktop-first approaches.
  • Understand CSS breakpoints.
  • Learn min-width and max-width media query strategies.
  • Understand progressive enhancement.
  • Choose breakpoints based on content requirements.
  • Build responsive layouts using Grid and Flexbox.
  • Debug breakpoint-related layout problems.

2. What Is Mobile-First Design?

Mobile-first design is a responsive development approach in which the initial layout is designed for smaller screens and then enhanced for larger screens.

The developer begins with the essential content and functionality required on a narrow viewport. Additional layout space and visual enhancements are introduced when the viewport becomes wider.

Typical Mobile-First Strategy

  1. Start with a simple single-column layout.
  2. Make content readable on narrow screens.
  3. Ensure controls are usable with touch input.
  4. Add additional columns for wider screens.
  5. Introduce desktop navigation and larger layouts where needed.
  6. Test intermediate viewport widths.
Mobile-first does not mean designing only for mobile devices. It means starting with the constraints of smaller screens and progressively enhancing the experience.

3. Why Use Mobile-First Design?

  • Encourages prioritization of important content.
  • Reduces unnecessary layout complexity.
  • Helps prevent horizontal overflow.
  • Encourages flexible component design.
  • Supports touch-friendly interfaces.
  • Provides a clear foundation for larger layouts.

Example: Course Website

A course portal may use a single-column layout on mobile, a two-column card layout on tablets and a three-column card layout on desktop.

4. Mobile-First vs Desktop-First Design

Feature Mobile-First Desktop-First
Starting point Smaller screens Larger screens
Common media query min-width max-width
Initial layout Simple and compact More complex and spacious
Enhancement direction Small to large Large to small
Typical use New responsive projects Adapting existing desktop-oriented projects
Both approaches can create responsive websites. Mobile-first is a useful default for new projects, but the correct approach depends on project requirements and existing architecture.

5. What Is a CSS Breakpoint?

A breakpoint is a viewport or container condition at which the layout or styling changes to improve usability.

For example, a navigation bar may display links in one horizontal row on wider screens and arrange them vertically on narrow screens.

Example

/* Default: mobile layout */

.navigation {
    display: flex;
    flex-direction: column;
}

/* Wider screens */

@media (min-width: 768px) {
    .navigation {
        flex-direction: row;
    }
}

Below 768 CSS pixels, the navigation uses a column direction. At 768 CSS pixels and above, it uses a row direction.

6. Common Breakpoint Ranges

The following values are illustrative starting points for responsive layouts. They are not mandatory industry standards.

Viewport Width Possible Layout
Below 600px Compact mobile layout
600px – 767px Large mobile or small tablet layout
768px – 899px Tablet-oriented layout
900px – 1199px Small desktop or laptop layout
1200px and above Wide desktop layout
Do not blindly use a breakpoint for every named device. Add a breakpoint when the content becomes cramped, spacing becomes excessive or the component needs a different arrangement.

7. Mobile-First Media Queries Using min-width

In a mobile-first stylesheet, the default CSS rules describe the smaller layout. Media queries using min-width progressively enhance the layout.

Syntax

@media (min-width: 768px) {
    /* Styles for viewports
       at least 768px wide */
}

Complete Example

.container {
    width: 100%;
    padding: 15px;
}

.cards {
    display: grid;
    grid-template-columns: 1fr;
    gap: 15px;
}

/* Tablet and wider */

@media (min-width: 600px) {
    .container {
        max-width: 900px;
        margin: auto;
    }

    .cards {
        grid-template-columns: repeat(2, 1fr);
    }
}

/* Desktop and wider */

@media (min-width: 900px) {
    .container {
        max-width: 1200px;
    }

    .cards {
        grid-template-columns: repeat(3, 1fr);
    }
}

Explanation

  • Below 600px: one column.
  • At 600px and above: two columns.
  • At 900px and above: three columns.

8. Desktop-First Media Queries Using max-width

In a desktop-first stylesheet, the default CSS describes the larger layout. Media queries using max-width adapt it for narrower screens.

Syntax

@media (max-width: 767px) {
    /* Styles for viewports
       up to 767px wide */
}

Complete Example

.cards {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}

/* Tablet and smaller */

@media (max-width: 899px) {
    .cards {
        grid-template-columns: repeat(2, 1fr);
    }
}

/* Mobile */

@media (max-width: 599px) {
    .cards {
        grid-template-columns: 1fr;
    }
}
Be careful when combining max-width and min-width rules. Overlapping conditions and source order can cause unexpected overrides.

9. Understanding Breakpoint Boundaries

Media query conditions determine whether the CSS rule applies at a particular viewport width.

Condition Meaning
min-width: 768px 768px and wider
max-width: 767px 767px and narrower
min-width: 600px 600px and wider
max-width: 899px 899px and narrower

Example of a Range

@media (min-width: 600px)
       and (max-width: 899px) {

    .container {
        padding: 30px;
    }
}

This rule applies when the viewport width is at least 600px and no more than 899px.

10. Progressive Enhancement

Progressive enhancement is a development strategy in which a website begins with essential content and functionality. Additional capabilities and visual improvements are introduced when the environment supports them.

In Responsive CSS

  1. Create a functional small-screen layout.
  2. Ensure essential content remains accessible.
  3. Add columns and wider navigation for larger screens.
  4. Enhance spacing and typography.
  5. Introduce advanced layout features where useful.

Example

/* Essential layout */

.content {
    display: block;
    padding: 15px;
}

/* Wider-screen enhancement */

@media (min-width: 768px) {
    .content {
        display: grid;
        grid-template-columns: 250px 1fr;
        gap: 25px;
    }
}

11. Practical Example: Responsive Course Grid

Problem Statement

Create a course-card layout with:

  • One column on mobile.
  • Two columns on tablet-sized viewports.
  • Three columns on desktop.

HTML

<section class="course-grid">

    <article class="course-card">
        <h3>C++ Programming</h3>
        <p>Programming fundamentals.</p>
    </article>

    <article class="course-card">
        <h3>Linux Systems</h3>
        <p>Linux commands and scripting.</p>
    </article>

    <article class="course-card">
        <h3>Embedded Systems</h3>
        <p>Embedded development.</p>
    </article>

    <article class="course-card">
        <h3>CSS3</h3>
        <p>Responsive web styling.</p>
    </article>

    <article class="course-card">
        <h3>JavaScript</h3>
        <p>Frontend programming.</p>
    </article>

    <article class="course-card">
        <h3>React.js</h3>
        <p>Component-based interfaces.</p>
    </article>

</section>

CSS

.course-grid {
    display: grid;
    grid-template-columns: 1fr;
    gap: 20px;
}

.course-card {
    background: #eef5ff;
    padding: 20px;
    border-radius: 8px;
}

/* Tablet */

@media (min-width: 600px) {
    .course-grid {
        grid-template-columns: repeat(2, 1fr);
    }
}

/* Desktop */

@media (min-width: 900px) {
    .course-grid {
        grid-template-columns: repeat(3, 1fr);
    }
}

12. Practical Example: Responsive Navigation

HTML

<nav class="navbar">

    <h2 class="logo">My Portal</h2>

    <ul class="nav-links">
        <li><a href="#">Home</a></li>
        <li><a href="#">Courses</a></li>
        <li><a href="#">Projects</a></li>
        <li><a href="#">Contact</a></li>
    </ul>

</nav>

CSS

.navbar {
    display: flex;
    flex-direction: column;
    gap: 15px;
    padding: 20px;
    background: #174ea6;
    color: white;
}

.nav-links {
    display: flex;
    flex-direction: column;
    gap: 12px;
    list-style: none;
    padding: 0;
    margin: 0;
}

.nav-links a {
    color: white;
    text-decoration: none;
}

/* Wider screens */

@media (min-width: 768px) {
    .navbar {
        flex-direction: row;
        justify-content: space-between;
        align-items: center;
    }

    .nav-links {
        flex-direction: row;
    }
}
This example changes the layout direction. It does not implement a collapsed hamburger menu. A functional mobile menu requires an interactive control and appropriate JavaScript or another accessible interaction mechanism.

13. Choosing Breakpoints Correctly

Breakpoints should be selected based on the behaviour of the content rather than a fixed list of device models.

Recommended Process

  1. Start with the smallest supported viewport.
  2. Inspect text wrapping and component widths.
  3. Increase viewport width gradually.
  4. Identify where the layout becomes cramped.
  5. Introduce a breakpoint at that point.
  6. Check that the new layout works beyond the breakpoint.
  7. Repeat for other major layout changes.

Useful Questions

  • Do navigation links fit comfortably?
  • Are card widths sufficient for their content?
  • Is the sidebar still useful on a narrow screen?
  • Does the heading wrap in an awkward way?
  • Are buttons and form controls easy to use?

14. Common Mobile-First and Breakpoint Mistakes

Mistake Correction
Using too many breakpoints. Use only where layout changes are necessary.
Choosing breakpoints only by device names. Choose them based on content behaviour.
Forgetting base mobile styles. Write the default small-screen layout first.
Conflicting min-width and max-width rules. Plan non-overlapping ranges or control source order.
Testing only at breakpoint values. Test immediately below and above each breakpoint.
Using fixed widths for all components. Use flexible sizing and suitable minimums and maximums.
Assuming mobile-first means mobile-only. Progressively enhance the same design for larger viewports.

15. Placement Interview Questions and Answers

Q1. What is mobile-first design?

Answer: It is an approach in which the initial layout is designed for smaller screens and enhanced for larger screens.

Q2. What is a breakpoint?

Answer: It is a viewport or container condition at which responsive styling changes.

Q3. What is the difference between min-width and max-width?

Answer: min-width applies when the viewport is at least the specified width. max-width applies when it is no wider than the specified width.

Q4. Which media query is commonly used in mobile-first design?

Answer: min-width is commonly used to progressively enhance layouts for larger screens.

Q5. What is desktop-first design?

Answer: It starts with larger-screen styles and adapts them for smaller screens, often using max-width queries.

Q6. What is progressive enhancement?

Answer: It is a strategy that begins with essential functionality and adds enhancements where the environment supports them.

Q7. Are 768px and 1024px mandatory breakpoints?

Answer: No. They are common reference values, but breakpoints should be chosen based on the layout and content.

Q8. Can mobile-first design use CSS Grid?

Answer: Yes. Grid can begin with one column and add columns at wider breakpoints.

Q9. Can Flexbox be used for responsive navigation?

Answer: Yes. Flexbox can change direction, wrapping and alignment according to available space.

Q10. What happens at min-width: 768px?

Answer: The media query applies at 768 CSS pixels and at wider viewport widths.

Q11. Why should breakpoints be content-driven?

Answer: Different layouts and content may need different widths. Content-driven breakpoints prevent unnecessary or ineffective layout changes.

Q12. How do you test a breakpoint?

Answer: Resize the browser or use Developer Tools to inspect the layout immediately below, at and above the breakpoint.

16. Practical Coding Challenges

Challenge 1: Responsive Course Grid

  • Create six course cards.
  • Use one column on mobile.
  • Use two columns at 600px.
  • Use three columns at 900px.

Challenge 2: Responsive Navigation

  • Create a navigation bar using Flexbox.
  • Stack links vertically on narrow screens.
  • Display links horizontally on wider screens.

Challenge 3: Sidebar Layout

  • Create a sidebar and main content section.
  • Stack both sections on mobile.
  • Display them side by side on desktop.

Challenge 4: Responsive Dashboard

  • Create dashboard cards and a sidebar.
  • Use CSS Grid.
  • Change the number of columns at suitable breakpoints.

Challenge 5: Debugging

  • Build a page with three breakpoints.
  • Inspect it at 599px, 600px, 899px and 900px.
  • Verify the layout at each boundary.

17. Quick Revision

  • Mobile-first begins with smaller-screen styles.
  • Desktop-first begins with larger-screen styles.
  • min-width is commonly used for mobile-first enhancement.
  • max-width is commonly used for desktop-first adaptation.
  • A breakpoint is a condition for changing responsive styles.
  • Breakpoints should depend on content requirements.
  • Progressive enhancement adds layout improvements progressively.
  • Grid and Flexbox are useful for responsive layouts.
  • Test just below and above every important breakpoint.
