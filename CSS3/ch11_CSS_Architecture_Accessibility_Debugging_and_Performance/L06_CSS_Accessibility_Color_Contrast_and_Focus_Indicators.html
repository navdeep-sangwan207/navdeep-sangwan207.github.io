Lecture 6: CSS Accessibility, Color Contrast and Focus Indicators

Learn how to create accessible interfaces using CSS, maintain readable color contrast, provide visible keyboard focus and support users with different interaction needs.

1. Learning Objectives

  • Understand web accessibility and the role of CSS.
  • Understand keyboard accessibility.
  • Use visible focus indicators correctly.
  • Understand :focus and :focus-visible.
  • Understand WCAG color contrast requirements.
  • Design accessible buttons, links and forms.
  • Use media queries for reduced motion and contrast preferences.
  • Understand accessible text sizing and reflow.
  • Identify common CSS accessibility mistakes.

2. What Is Web Accessibility?

Web accessibility means designing websites and applications so that people with different abilities can perceive, understand, navigate and interact with their content.

Accessibility considerations include:

  • Users navigating with a keyboard instead of a mouse.
  • Users with low vision who need readable text and contrast.
  • Users who rely on screen readers.
  • Users who need reduced motion.
  • Users who zoom or enlarge page content.
  • Users who have difficulty distinguishing certain colors.
CSS contributes to accessibility, but CSS alone cannot make an inaccessible HTML structure accessible. Semantic HTML, meaningful content, keyboard behavior and appropriate interaction design are also necessary.

3. CSS and Accessibility

CSS affects how users perceive and interact with page content. Poor styling can make an otherwise functional interface difficult or impossible to use.

CSS Concern Accessibility Impact
Low color contrast Text may be difficult to read.
Removing outlines Keyboard users may lose focus visibility.
Very small text Content may be difficult to perceive.
Color-only indicators Information may not be distinguishable by everyone.
Excessive animation Motion can cause discomfort for some users.
Fixed dimensions Zoomed or enlarged content may become clipped.
Hidden content Important information may become unavailable.

4. Keyboard Accessibility

Not every user operates a website with a mouse. Keyboard users commonly navigate through interactive elements using:

  • Tab: Move to the next focusable element.
  • Shift + Tab: Move to the previous focusable element.
  • Enter: Activate links and buttons in common cases.
  • Space: Activate buttons and toggle certain controls.
  • Arrow keys: Navigate within some controls and widgets.

Example of keyboard-accessible HTML

<a href="courses.html">View Courses</a>

<button type="button">
    Start Learning
</button>

<label for="email">Email Address</label>
<input type="email" id="email" name="email">

Native links, buttons and form controls provide built-in keyboard behavior. Prefer them over non-semantic elements such as clickable div or span.

Do not use CSS to make a non-interactive element merely look like a button. Use a real button for an action and a real link for navigation.

5. Focus States

Focus indicates which interactive element is currently selected for keyboard interaction.

:focus

The :focus pseudo-class matches an element when it has focus. 

button:focus {
    outline: 3px solid blue;
    outline-offset: 3px;
}

:focus-visible

The :focus-visible pseudo-class applies focus styling when the browser determines that a visible focus indicator is appropriate, commonly during keyboard navigation. 

button:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 3px;
}

Practical recommendation

:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 3px;
}

This provides a consistent focus indicator for elements that receive focus-visible matching.

Important: Never remove the browser's focus outline without providing a clearly visible replacement. Test focus visibility with keyboard navigation.

7. Color Contrast

Color contrast describes the difference in luminance between foreground content and its background.

Sufficient contrast helps users distinguish text, icons and important interface elements.

WCAG contrast ratio

Contrast ratio is expressed as a value between 1:1 and 21:1.

Ratio Meaning
1:1 No contrast difference.
3:1 Minimum contrast target for qualifying non-text graphical objects and large text under WCAG criteria.
4.5:1 Minimum contrast target for normal text at WCAG AA.
7:1 Minimum contrast target for normal text at WCAG AAA.
21:1 Maximum theoretical contrast ratio, black against white.

WCAG large text definition

Large text generally means at least 18pt regular text or 14pt bold text, approximately 24 CSS pixels or 18.67 CSS pixels respectively.

WCAG AA generally requires 3:1 contrast for large text and 4.5:1 for normal text.

8. Understanding Contrast Ratio

Contrast ratio is calculated from the relative luminance of two colors.

The formula is:

\[ \text{Contrast Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05} \]

Where:

  • L1 is the lighter color's relative luminance.
  • L2 is the darker color's relative luminance.
  • L1 is always greater than or equal to L2.

Relative luminance is calculated from the linearized sRGB color components using their respective weighting.

You do not need to calculate every contrast ratio manually during normal frontend development. Use a reliable contrast checker and verify the actual foreground and background colors.

10. Do Not Communicate Information Using Color Alone

Color should not be the only method used to communicate important information.

Less accessible example

<span class="error">Invalid input</span>

If the only difference is red text, some users may not recognize the error.

Better example

<p class="error-message">
    Error: Please enter a valid email address.
</p>
.error-message {
    color: #b42318;
    font-weight: bold;
    border-left: 4px solid #b42318;
    padding-left: 10px;
}

The explicit error message provides meaning beyond color. A real form should also associate the error with the relevant input and communicate validation state appropriately.

11. Accessible Form Styling

Forms should have clear labels, readable text, visible focus states and understandable error messages.

HTML

<form>
    <label for="username">Username</label>

    <input
        type="text"
        id="username"
        name="username"
        required
    >

    <button type="submit">
        Submit
    </button>
</form>

CSS

input {
    width: 100%;
    max-width: 350px;
    padding: 12px;
    border: 1px solid #667085;
    border-radius: 5px;
    font-size: 16px;
}

input:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 2px;
}

button {
    padding: 12px 20px;
    background: #174ea6;
    color: white;
    border: 0;
    border-radius: 5px;
    cursor: pointer;
}

button:focus-visible {
    outline: 3px solid #e59b18;
    outline-offset: 3px;
}

The label must be programmatically associated with the input. Placeholder text is not a substitute for a label.

12. Accessible Button and Link States

Interactive controls should provide clear visual feedback for normal, hover, active and focus states. 

.button {
    background: #174ea6;
    color: white;
    padding: 12px 18px;
    border: 0;
    border-radius: 6px;
    cursor: pointer;
}

.button:hover {
    background: #123b80;
}

.button:active {
    background: #0d2c61;
}

.button:focus-visible {
    outline: 3px solid #e59b18;
    outline-offset: 3px;
}

.button:disabled {
    opacity: 0.6;
    cursor: not-allowed;
}

Hover is not a replacement for focus. Keyboard users need an appropriate focus indicator.

13. Text Readability and Responsive Accessibility

Text should remain readable when users zoom the page or change their preferred text settings.

Use relative units

html {
    font-size: 100%;
}

body {
    font-size: 1rem;
    line-height: 1.6;
}

h1 {
    font-size: clamp(1.8rem, 4vw, 3rem);
}

Avoid fixed-height text containers

/* Risky for content that may wrap */
.card {
    height: 180px;
}

/* More flexible */
.card {
    min-height: 180px;
    height: auto;
}

Fixed heights can clip content when text wraps or is enlarged. Use flexible sizing when content length can vary.

Allow long content to wrap

.content {
    overflow-wrap: anywhere;
}

Test the page at narrow viewport widths and at increased zoom levels. Content should not require horizontal scrolling in ordinary reading layouts, except where a two-dimensional layout genuinely requires it.

14. Reduced Motion Preference

Some users prefer reduced motion because animations can cause discomfort or distraction.

The prefers-reduced-motion media feature allows a website to adapt to the user's operating-system preference. 

.card {
    transition: transform 0.25s ease;
}

.card:hover {
    transform: translateY(-5px);
}

@media (prefers-reduced-motion: reduce) {
    .card {
        transition: none;
    }

    .card:hover {
        transform: none;
    }
}

This preserves the component while removing the nonessential movement.

15. High Contrast and Forced Colors

Some users apply operating-system contrast settings that modify the colors used by websites.

The forced-colors media feature can help developers adapt selected visual details. 

@media (forced-colors: active) {
    .button {
        border: 1px solid ButtonText;
    }

    .card {
        border: 1px solid CanvasText;
    }
}

System colors such as ButtonText and CanvasText allow the browser to use colors appropriate to the active forced-colors environment.

Do not disable forced-color adjustments without a strong reason. Test important controls and information in the user's high-contrast environment.

16. Other Useful Accessibility Media Features

Media Feature Purpose
prefers-reduced-motion Detects a preference for reduced motion.
prefers-contrast Detects a user preference for more or less contrast.
forced-colors Detects a forced-color mode.
prefers-color-scheme Detects light or dark color-scheme preference.

Example: Dark mode preference

body {
    background: white;
    color: #222222;
}

@media (prefers-color-scheme: dark) {
    body {
        background: #121212;
        color: #f5f5f5;
    }
}

Example: Increased contrast preference

@media (prefers-contrast: more) {
    .card {
        border: 2px solid currentColor;
    }
}

17. Hiding Content: display, visibility and visually-hidden Techniques

Different CSS hiding methods have different effects.

Property Visual Result Accessibility Consideration
display: none Element is not rendered. Normally removes it from the accessibility tree.
visibility: hidden Element is hidden but retains layout space. Normally unavailable to assistive technology.
opacity: 0 Element becomes transparent. It may remain focusable and exposed to assistive technology.
Visually-hidden technique Content is visually concealed. Can remain available to screen readers when implemented correctly.

Visually-hidden utility class

.visually-hidden {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip-path: inset(50%);
    white-space: nowrap;
    border: 0;
}

This pattern is useful for text that should be available to screen-reader users but not displayed visually.

Do not use visually-hidden styling to conceal important information from sighted users who also need it. Choose hiding techniques according to the intended behavior.

18. Accessibility Testing Workflow

  1. Navigate the entire page using only the keyboard.
  2. Check whether focus indicators are visible.
  3. Verify that links and buttons are distinguishable.
  4. Check text and graphical contrast.
  5. Zoom the page and inspect text wrapping.
  6. Test narrow viewport widths.
  7. Enable reduced-motion preferences.
  8. Test forced-colors mode where available.
  9. Use a screen reader to test meaningful content and labels.
  10. Use accessibility auditing tools as supporting checks.

Automated tools can identify many issues, but manual keyboard and assistive-technology testing remain important.

19. Practical Project: Accessible Course Portal

Project requirement:

Improve the accessibility of a course portal containing navigation links, course cards, search fields and action buttons.

Tasks

  1. Provide visible keyboard focus indicators.
  2. Check text and background color contrast.
  3. Ensure buttons and links have clear visual states.
  4. Use readable font sizes and line heights.
  5. Allow content to expand without clipping.
  6. Support reduced-motion preferences.
  7. Check layout at increased zoom.
  8. Do not communicate course status through color alone.

Expected Result

A course portal that is easier to navigate using a keyboard, easier to read and more adaptable to user preferences.

20. Common Accessibility Mistakes

Mistake Correct Practice
Removing focus outlines. Provide a clearly visible replacement.
Using hover styles only. Provide keyboard focus feedback.
Using low-contrast text. Measure and improve contrast ratios.
Using color alone for errors. Include meaningful text or another indicator.
Using placeholder text as a label. Provide a visible, associated label.
Using fixed heights for variable content. Allow flexible content sizing.
Using excessive animation. Respect reduced-motion preferences.
Hiding content without understanding the effect. Choose the correct hiding technique.
Relying only on automated accessibility tools. Perform manual keyboard and screen-reader checks.

21. Placement Interview Questions and Answers

Q1. What is web accessibility?

Web accessibility means designing websites so that people with different abilities can perceive, navigate and interact with their content.

Q2. What is the purpose of :focus?

It selects an element that currently has focus.

Q3. What is the difference between :focus and :focus-visible?

:focus matches focused elements. :focus-visible matches focused elements when the browser determines that a visible focus indicator is appropriate.

Q4. Why should outlines not be removed?

Keyboard users need a visible indication of the currently focused interactive element.

Q5. What is color contrast?

Color contrast is the difference in relative luminance between foreground and background colors.

Q6. What is the WCAG AA contrast requirement for normal text?

The minimum contrast ratio is 4.5:1, subject to the applicable WCAG criteria and exceptions.

Q7. What is the contrast requirement for large text at WCAG AA?

The minimum contrast ratio is 3:1.

Q8. What is prefers-reduced-motion?

It is a CSS media feature that detects whether a user has requested reduced motion through their system settings.

Q9. What is forced-colors?

It is a media feature that detects an environment where the browser enforces a limited color palette.

Q10. Why should color not be the only way to show errors?

Some users may not distinguish the color difference. A meaningful text message or additional visual indicator provides another way to understand the error.

Q11. What is a visually-hidden class?

It is a CSS technique that visually conceals content while keeping it available to assistive technology when implemented appropriately.

Q12. Does CSS alone guarantee accessibility?

No. Accessibility also depends on semantic HTML, meaningful content, keyboard behavior, interaction design and testing.

Build a registration form containing name, email, password, course selection and a submit button.

Requirements:

  • Associate labels with all inputs.
  • Provide visible keyboard focus indicators.
  • Use readable colors and sufficient contrast.

Expected Result

A responsive registration form that can be navigated using a keyboard and provides clear visual feedback.

24. Key Takeaways

  • Accessibility must be considered during interface design.
  • Keyboard users need visible focus indicators.
  • :focus-visible supports appropriate focus styling.
  • Normal text generally needs a 4.5:1 contrast ratio for WCAG AA.
  • Large text generally needs a 3:1 contrast ratio for WCAG AA.
  • Do not communicate information through color alone.
  • Use flexible sizing to support zoom and text enlargement.
  • Respect reduced-motion and forced-color preferences.
  • Use semantic HTML and test with assistive technologies.
