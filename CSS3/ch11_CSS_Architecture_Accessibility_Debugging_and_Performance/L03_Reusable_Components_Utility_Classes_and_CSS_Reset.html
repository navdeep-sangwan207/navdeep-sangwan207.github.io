Lecture 3: Reusable Components, Utility Classes and CSS Reset

Learn to create reusable UI styles, apply utility-first styling concepts and establish consistent browser defaults using CSS reset and normalization techniques.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Explain reusable CSS components.
  • Identify repeated styling and extract shared rules.
  • Create reusable buttons, cards and form components.
  • Understand utility classes and their purpose.
  • Compare component classes and utility classes.
  • Explain CSS reset and normalization.
  • Build a practical reset stylesheet.
  • Combine reusable components and utility classes effectively.

2. What Are Reusable CSS Components?

A reusable CSS component is a group of HTML and CSS patterns designed to be used in multiple places without rewriting the same styling.

Common reusable components include:

  • Navigation bars
  • Buttons
  • Course cards
  • Login forms
  • Alert messages
  • Badges and labels
  • Modals and dialog boxes
  • Footer sections
Reusability reduces duplication and helps maintain a consistent interface. A change to a shared component style can update every instance that uses that component class.

3. Problem: Repeating the Same CSS

Consider a website with three buttons. A developer writes separate styles for each button.

Less maintainable approach

.login-button {
    background: #174ea6;
    color: white;
    padding: 10px 18px;
    border-radius: 5px;
}

.register-button {
    background: #174ea6;
    color: white;
    padding: 10px 18px;
    border-radius: 5px;
}

.submit-button {
    background: #174ea6;
    color: white;
    padding: 10px 18px;
    border-radius: 5px;
}

The same declarations are repeated. If the padding or color changes, the developer must update multiple rules.

Reusable approach

.button {
    background: #174ea6;
    color: white;
    padding: 10px 18px;
    border: 0;
    border-radius: 5px;
    cursor: pointer;
}

.login-button {
    /* Login-specific styles only */
}

.register-button {
    /* Registration-specific styles only */
}

HTML:

<button class="button login-button">
    Login
</button>

<button class="button register-button">
    Register
</button>

<button class="button">
    Submit
</button>

All three buttons share the base component style. Additional classes can provide specific variations where necessary.

4. Building Reusable Component Variations

A component should support controlled variations without duplicating its entire stylesheet.

Example: Button component

<button class="button button--primary">
    Save
</button>

<button class="button button--secondary">
    Cancel
</button>

<button class="button button--danger">
    Delete
</button>
.button {
    display: inline-block;
    padding: 10px 18px;
    border: 0;
    border-radius: 5px;
    font-size: 1rem;
    cursor: pointer;
}

.button--primary {
    background: #174ea6;
    color: white;
}

.button--secondary {
    background: #e5eaf2;
    color: #263238;
}

.button--danger {
    background: #c62828;
    color: white;
}

.button:focus-visible {
    outline: 3px solid #ffbf47;
    outline-offset: 3px;
}

The base class defines shared properties. Modifier classes define the variations.

6. What Are Utility Classes?

Utility classes are small, single-purpose CSS classes that apply a specific styling rule. They can be combined directly on HTML elements.

Examples

.text-center {
    text-align: center;
}

.text-primary {
    color: #174ea6;
}

.mt-16 {
    margin-top: 16px;
}

.p-20 {
    padding: 20px;
}

.rounded {
    border-radius: 8px;
}

.flex {
    display: flex;
}

These classes can be combined in HTML:

<div class="p-20 rounded">
    <h2 class="text-center text-primary">
        Welcome
    </h2>

    <p class="mt-16">
        Learn CSS utility classes.
    </p>
</div>
Utility classes are intentionally small and reusable. They are useful when the same styling operation is needed across many unrelated components.

7. Component Classes vs Utility Classes

Component Classes Utility Classes
Represent reusable UI components. Represent individual styling operations.
May contain several declarations. Usually contain one or a small group of related declarations.
Example: .course-card Example: .text-center
Define component structure and appearance. Can be combined across different components.
Useful for consistent interface patterns. Useful for quick, reusable styling adjustments.

Combining both approaches

<article class="course-card p-20 rounded">
    <h2 class="course-card__title text-primary">
        Embedded Systems
    </h2>
</article>

The component class defines the course card. Utility classes provide additional general-purpose styling.

8. Utility-First CSS Approach

Utility-first CSS is a styling approach in which developers compose interfaces by combining many small utility classes in HTML.

Frameworks such as Tailwind CSS use this approach. The same concept can also be implemented with custom CSS utility classes.

Custom utility-first example

<div class="flex items-center gap-16 p-20 rounded bg-white">
    <img src="course.jpg" alt="Course illustration">

    <div>
        <h2 class="text-primary text-large">
            Web Development
        </h2>
        <p class="text-muted">
            Learn frontend development.
        </p>
    </div>
</div>
.flex {
    display: flex;
}

.items-center {
    align-items: center;
}

.gap-16 {
    gap: 16px;
}

.p-20 {
    padding: 20px;
}

.rounded {
    border-radius: 8px;
}

.bg-white {
    background: white;
}

.text-primary {
    color: #174ea6;
}

.text-large {
    font-size: 1.25rem;
}

.text-muted {
    color: #667085;
}

Advantages

  • Fast composition of common styles.
  • Less need to create a new class for every small variation.
  • Consistent reusable styling rules.
  • Useful for rapid UI development.

Limitations

  • HTML can contain many class names.
  • Design consistency still requires shared conventions.
  • Arbitrary one-off utilities can create an unmanageable system.
  • Developers must understand the underlying CSS properties.

9. What Is a CSS Reset?

Browsers apply default styles to HTML elements. These are often called user-agent styles or browser default styles.

Examples include:

  • Default body margins.
  • Heading font sizes and margins.
  • List indentation and markers.
  • Default button and input appearance.
  • Default link colors and underlines.

A CSS reset is a collection of rules that removes or reduces selected browser defaults so developers can establish their own baseline styles.

A reset does not make every browser render every element identically. It provides a more controlled starting point for the developer's own stylesheet.

10. Basic CSS Reset Example

/* Basic reset */

* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

html {
    line-height: 1.5;
}

body {
    min-height: 100vh;
    font-family: Arial, sans-serif;
}

img {
    max-width: 100%;
    display: block;
}

button,
input,
textarea,
select {
    font: inherit;
}

This reset:

  • Removes default margins and padding from all elements.
  • Uses border-box sizing for predictable dimensions.
  • Establishes a line-height baseline.
  • Prevents images from exceeding their containers.
  • Ensures form controls inherit the surrounding font.
A universal reset also removes useful defaults such as list indentation and heading margins. Restore these styles where required. Do not remove semantic structure or focus indicators without providing suitable alternatives.

11. CSS Reset vs Normalize CSS

Both approaches help establish a consistent starting point, but their philosophies differ.

CSS Reset Normalize CSS
Removes or reduces selected default styles. Preserves useful defaults while making behavior more consistent.
Often establishes a nearly blank baseline. Provides a more conservative baseline.
Developers define many styles themselves. Developers retain more browser-default styling.
Can be highly customized. Focuses on correcting inconsistencies.

When to use a reset

  • When you want strong control over baseline styles.
  • When your project has a defined design system.
  • When you want to explicitly establish typography and spacing.

When to use normalization

  • When you want to preserve useful browser defaults.
  • When you need a conservative baseline across browsers.
  • When a full reset would remove too many useful defaults.
Choose one deliberate baseline strategy. Avoid combining multiple reset libraries without understanding their overlapping rules.

12. A More Practical Modern Reset

The following example provides a practical starting point for many frontend projects. 

/* Box sizing */

*,
*::before,
*::after {
    box-sizing: border-box;
}

/* Remove default body margin */

body {
    margin: 0;
    min-height: 100vh;
    line-height: 1.5;
    font-family: Arial, sans-serif;
}

/* Responsive media */

img,
picture,
video,
canvas,
svg {
    display: block;
    max-width: 100%;
}

/* Form controls */

input,
button,
textarea,
select {
    font: inherit;
}

/* Prevent text overflow */

h1,
h2,
h3,
p {
    overflow-wrap: break-word;
}

/* Inherit link color where desired */

a {
    color: inherit;
}

/* Remove list markers only when appropriate */

.navigation-list {
    list-style: none;
    padding: 0;
    margin: 0;
}

This approach does not globally remove every margin, padding or list marker. It provides useful defaults while allowing component-specific styling.

14. Common Mistakes and Best Practices

Common Mistake Better Practice
Duplicating the same component CSS. Extract shared styles into reusable classes.
Creating a utility class for every possible value. Maintain a controlled and consistent utility set.
Removing all browser defaults without review. Reset only what your design system needs.
Using component classes for unrelated styling tasks. Use suitable utility classes for general-purpose styling.
Using utility classes for every complex component. Use component classes when they improve clarity and reuse.
Removing focus outlines in a reset. Preserve or provide visible keyboard focus indicators.
Loading overlapping reset libraries unnecessarily. Choose one baseline strategy and understand its rules.

15. Placement Interview Questions and Answers

Q1. What is a reusable CSS component?

It is a reusable styling pattern for a UI element that can appear in multiple places, such as a card or button.

Q2. Why are reusable components important?

They reduce duplicated code, improve consistency and make maintenance easier.

Q3. What is a utility class?

A utility class is a small, single-purpose class that applies a specific styling operation, such as text alignment or padding.

Q4. What is utility-first CSS?

It is an approach in which interfaces are composed by combining small utility classes directly on HTML elements.

Q5. What is the difference between component and utility classes?

Component classes describe reusable UI elements, while utility classes describe individual styling operations.

Q6. What is a CSS reset?

A CSS reset removes or reduces selected browser default styles so developers can establish a consistent baseline.

Q7. What is Normalize CSS?

Normalize CSS aims to make default rendering more consistent across browsers while preserving useful defaults.

Q8. What is the difference between reset and normalize?

Reset generally removes selected defaults. Normalize generally preserves useful defaults while correcting inconsistencies.

Q9. Does a CSS reset remove all browser differences?

No. It only establishes a baseline for selected styles. Browser rendering and feature differences may still exist.

Q10. Can utility classes and BEM be used together?

Yes. BEM can name components and their elements, while utility classes can provide general-purpose styling adjustments.

Q11. Why use box-sizing: border-box in a reset?

It makes declared width and height include content, padding and border, simplifying element sizing calculations.

Q12. Should every button have a separate CSS class?

Not necessarily. A shared button class can define common styles, with modifier classes for different variations.

18. Key Takeaways

  • Reusable components reduce repeated CSS.
  • Base classes define shared component styles.
  • Modifiers provide component variations.
  • Utility classes provide small, reusable styling operations.
  • Utility-first CSS composes interfaces from small classes.
  • CSS reset establishes a controlled baseline.
  • Normalize CSS preserves useful defaults while improving consistency.
  • Use reset rules carefully to preserve usability and accessibility.
