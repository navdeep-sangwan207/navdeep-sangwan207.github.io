Lecture 7: Debugging CSS with Browser Developer Tools

Learn to inspect HTML elements, identify overridden CSS, examine computed styles, debug layout problems and test responsive designs using browser Developer Tools.

1. Learning Objectives

  • Understand browser Developer Tools.
  • Open and use Chrome DevTools.
  • Inspect HTML elements and applied CSS rules.
  • Understand the Styles and Computed panels.
  • Debug specificity and cascade conflicts.
  • Inspect the CSS box model.
  • Debug Flexbox and Grid layouts.
  • Test responsive layouts using device emulation.
  • Use Console and Network panels for related debugging.
  • Develop a systematic CSS debugging workflow.

2. What Are Browser Developer Tools?

Browser Developer Tools are built-in development utilities used to inspect, debug and analyze web applications.

They are available in browsers such as Google Chrome, Microsoft Edge, Firefox and Safari.

Common debugging tasks

  • Inspect the HTML structure of an element.
  • Identify which CSS rules are applied.
  • Find overridden or inactive declarations.
  • Modify CSS temporarily and preview changes.
  • Inspect margins, padding, borders and dimensions.
  • Test responsive layouts.
  • Investigate missing stylesheet resources.
  • Analyze rendering and performance problems.
Developer Tools changes are normally temporary. Editing a rule in DevTools does not automatically update the original CSS file in your GitHub repository.

3. Opening Chrome Developer Tools

Method Action
Keyboard shortcut F12
Keyboard shortcut Ctrl + Shift + I
Inspect element Right-click an element and select Inspect.
Browser menu Open More Tools and select Developer Tools.

You can open DevTools while viewing a local HTML file or a deployed GitHub Pages website.

Important panels

Panel Purpose

Console View errors, warnings and run JavaScript.
Sources Inspect loaded source files and debug scripts.
Network Inspect CSS, JavaScript, images and other requests.
Performance Analyze rendering and runtime performance.
Application Inspect storage, service workers and related resources.
Coverage Identify used and unused CSS and JavaScript.

4. Inspecting HTML Elements

The Elements panel displays the document structure. It allows you to inspect the hierarchy of HTML elements.

Example HTML

<div class="course-card">
    <h2 class="course-title">
        Embedded Systems
    </h2>

    <p class="course-description">
        Learn microcontrollers and embedded programming.
    </p>

    <button class="course-button">
        Start Learning
    </button>
</div>

How to inspect

  1. Open the webpage.
  2. Right-click the course title.
  3. Select Inspect.
  4. DevTools opens with the selected element highlighted.
  5. Inspect its parent, child and sibling elements.
  6. Check the associated CSS rules.

You can expand and collapse HTML elements to understand their relationship.

5. The Styles Panel

The Styles panel displays CSS declarations associated with the selected element.

Example CSS

.course-card {
    background: white;
    padding: 20px;
    border: 1px solid #ddd;
}

.course-title {
    color: #174ea6;
    font-size: 22px;
}

When you select the course title, DevTools can display rules affecting that title and inherited declarations.

What you can do

  • Enable or disable a declaration using its checkbox.
  • Edit property values.
  • Add a new CSS declaration.
  • Inspect the source stylesheet and line number.
  • Identify overridden declarations.
  • Test new selectors temporarily.
Use the Styles panel to experiment with fixes before updating the actual CSS source file.

6. Understanding Overridden CSS Rules

A declaration may be crossed out in DevTools when another declaration wins for the same property.

Example

.button {
    background: blue;
}

#login-form .button {
    background: green;
}

.button--danger {
    background: red;
}

If a button with classes button button--danger is inside #login-form, the ID-based selector has higher specificity than either class-only selector.

Specificity values:

  • .button = (0, 1, 0)
  • #login-form .button = (1, 1, 0)
  • .button--danger = (0, 1, 0)

The green declaration wins if cascade origin, importance and layer precedence do not change the result.

Debugging steps

  1. Select the affected element.
  2. Find the crossed-out declaration.
  3. Identify the winning declaration.
  4. Inspect the selectors and their specificity.
  5. Check cascade layers and source order.
  6. Correct the original stylesheet rather than adding random overrides.

7. The Computed Panel

The Computed panel shows the final computed CSS values for the selected element.

This is useful when several CSS rules, inheritance and browser defaults influence the final result.

Example

.title {
    font-size: 20px;
}

.content .title {
    font-size: 24px;
}

If both selectors apply and the second declaration wins, the computed font size is 24px.

Useful computed properties

  • color
  • background-color
  • font-size
  • display
  • position
  • width and height
  • margin and padding
  • overflow
  • z-index

Expand a computed property in DevTools to investigate the declaration responsible for its value.

8. Debugging the CSS Box Model

The box model is a frequent source of layout problems. DevTools provides a visual representation of the selected element's dimensions.

Box model components

  • Content
  • Padding
  • Border
  • Margin

Example CSS

.box {
    width: 300px;
    padding: 20px;
    border: 5px solid blue;
    margin: 10px;
    box-sizing: content-box;
}

The total horizontal space occupied, including margins, is 370px:

300 + 40 + 10 + 20 = 370px

DevTools displays the content, padding, border and margin dimensions separately.

Debugging procedure

  1. Select the element.
  2. Find the Box Model diagram.
  3. Inspect content width and height.
  4. Check padding and border dimensions.
  5. Inspect margins and possible margin collapse.
  6. Verify the computed box-sizing value.

9. Debugging Display and Positioning

Elements may appear in unexpected locations because of display, positioning, containing blocks or stacking contexts.

Example

.parent {
    position: relative;
}

.child {
    position: absolute;
    top: 10px;
    right: 10px;
}

Inspect the computed position, top, right and the ancestor elements that may establish the containing block.

Common debugging properties

Property What to Inspect
display Whether the element is block, flex, grid or hidden.
position Normal flow or positioned layout.
top/right/bottom/left Position offsets.
z-index Stacking order within the relevant stacking context.
overflow Clipping and scrolling behavior.
transform Visual transformations and possible containing-block effects.

10. Debugging Flexbox Layouts

DevTools can identify flex containers and display the relationship between flex items.

Example

.navigation {
    display: flex;
    justify-content: space-between;
    align-items: center;
    gap: 16px;
}

Inspect these properties

  • display: flex
  • flex-direction
  • justify-content
  • align-items
  • flex-wrap
  • flex-grow
  • flex-shrink
  • flex-basis
  • gap
  • min-width

Common issue: flex item does not shrink

.content {
    display: flex;
}

.main {
    flex: 1;
    min-width: 0;
}

The min-width: 0 declaration can allow a flex item to shrink below its automatic minimum content size.

11. Debugging CSS Grid Layouts

Grid overlays help visualize grid tracks, lines and item placement.

Example

.course-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}

Inspect these properties

  • grid-template-columns
  • grid-template-rows
  • grid-auto-flow
  • grid-column
  • grid-row
  • grid-template-areas
  • gap
  • minmax()

In Chrome DevTools, select the grid container and use the grid badge or Layout panel to display the grid overlay. The exact interface may vary by browser version.

12. Responsive Design Debugging

Responsive design problems can be investigated using the device toolbar in Chrome DevTools.

How to enable device mode

  1. Open Developer Tools.
  2. Click the Toggle Device Toolbar icon.
  3. Alternatively, press Ctrl + Shift + M.
  4. Select a device preset or enter custom dimensions.
  5. Inspect the page at different viewport widths.
  6. Observe media-query changes and element wrapping.

Example media query

.course-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}

@media (max-width: 768px) {
    .course-grid {
        grid-template-columns: repeat(2, 1fr);
    }
}

@media (max-width: 480px) {
    .course-grid {
        grid-template-columns: 1fr;
    }
}

Test at widths just above and below each breakpoint. A layout may work at a preset device width but fail at intermediate widths.

13. Debugging Media Queries

When a responsive rule does not work, inspect whether its media condition matches the current viewport. 

@media (max-width: 600px) {
    .navigation {
        flex-direction: column;
    }
}

Checklist

  • Is the media query written correctly?
  • Does the viewport actually meet the condition?
  • Is the stylesheet loaded?
  • Is the selector matching the intended element?
  • Is another declaration overriding the property?
  • Is the viewport meta tag present?

Viewport meta tag

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

Without an appropriate viewport configuration, mobile browsers may use a wider layout viewport and responsive behavior may not work as expected.

14. Debugging Missing CSS Files

A page may appear unstyled because the stylesheet was not loaded successfully.

Example HTML

<link rel="stylesheet" href="../../style.css">

Common causes

  • Incorrect relative file path.
  • Incorrect capitalization in the filename.
  • File not committed or pushed to GitHub.
  • Incorrect folder name.
  • Resource returned a 404 error.
  • Browser cache showing an older resource.

Network panel workflow

  1. Open DevTools and select Network.
  2. Reload the webpage.
  3. Filter requests by CSS.
  4. Find the expected stylesheet.
  5. Inspect its status code.
  6. Check the request URL and response.
  7. Correct the file path or deployment issue.
Status Meaning
200 Successful response.
304 Resource not modified; cached representation can be reused.
404 Requested resource not found.
403 Access to the resource is forbidden.
500 Server encountered an internal error.
GitHub Pages paths are case-sensitive. For example, style.css and Style.css are different filenames.

15. Debugging CSS Syntax Errors

Invalid CSS declarations may be ignored by the browser. This can make the page appear as if a rule is not working.

Incorrect CSS

.card {
    background-color blue;
    padding: 20px
    border-radius: 8px;
}

Problems:

  • Missing colon after background-color.
  • Missing semicolon after padding.

Correct CSS

.card {
    background-color: blue;
    padding: 20px;
    border-radius: 8px;
}

Inspect the Styles panel and Console for parsing warnings. Also verify the CSS source file directly.

16. Console Panel for Frontend Debugging

The Console panel displays JavaScript errors and warnings. These errors can explain why dynamically applied styles or class changes are not working.

Example JavaScript

const card = document.querySelector(".course-card");

if (card) {
    card.classList.add("active");
} else {
    console.error("Course card element not found");
}

Example CSS

.course-card.active {
    border: 2px solid #174ea6;
    background: #eef5ff;
}

If the JavaScript selector does not find the element, the class will not be added. The Console helps identify this problem.

A CSS problem is not always caused by CSS itself. Incorrect HTML, JavaScript errors or missing resources can also cause unexpected visual behavior.

17. Sources Panel and Editing CSS

The Sources panel allows you to inspect loaded source files. You can open stylesheets, examine their contents and navigate to relevant source locations.

Typical workflow

  1. Open Sources.
  2. Locate the website's stylesheet.
  3. Open the CSS file.
  4. Find the relevant selector.
  5. Inspect the declaration.
  6. Use the Styles panel to test a change.
  7. Update the original file in your editor or GitHub.
  8. Reload the webpage and verify the result.

Some browsers support local workspace mapping or filesystem integration, but ordinary DevTools edits should not be assumed to persist to your source files.

18. Debugging Performance Issues

The Performance panel helps investigate slow rendering, long tasks and layout activity.

Basic workflow

  1. Open the Performance panel.
  2. Start recording.
  3. Reload the page or perform the interaction.
  4. Stop recording.
  5. Inspect the timeline and main-thread activity.
  6. Look for repeated layout and paint operations.
  7. Compare results after making an optimization.

Related concepts

  • Style recalculation
  • Layout
  • Paint
  • Composite layers
  • Long tasks
  • Layout shifts

Use performance measurements to identify the actual bottleneck instead of assuming that a particular CSS property is responsible.

19. A Systematic CSS Debugging Workflow

Follow this sequence when a CSS problem occurs:
  1. Reproduce the problem consistently.
  2. Inspect the affected HTML element.
  3. Confirm the expected stylesheet has loaded.
  4. Check the Styles panel for matching selectors.
  5. Identify crossed-out declarations.
  6. Check computed styles.
  7. Inspect box model dimensions.
  8. Check layout and positioning properties.
  9. Test relevant viewport sizes.
  10. Inspect Console and Network for related errors.
  11. Make the correction in the source file.
  12. Reload and verify the fix.

This method avoids random CSS changes and helps identify the actual cause of the problem.

21. Common Debugging Mistakes

Mistake Better Practice
Changing CSS randomly. Inspect the element and identify the winning declaration.
Ignoring crossed-out declarations. Investigate specificity and cascade precedence.
Checking only the Styles panel. Use Computed and Box Model panels too.
Assuming a missing style is a CSS syntax issue. Check Network for missing resources.
Testing only at one screen size. Test breakpoints and intermediate viewport widths.
Assuming DevTools edits update source files. Make permanent changes in the actual source.
Ignoring JavaScript errors. Inspect the Console when dynamic styling is involved.

22. Placement Interview Questions and Answers

Q1. What are browser Developer Tools?

They are built-in browser utilities used to inspect, debug and analyze web pages and applications.

Q2. How do you open Chrome DevTools?

Press F12 or Ctrl + Shift + I, or right-click an element and select Inspect.

Q3. What is the Elements panel used for?

It is used to inspect the HTML DOM and associated CSS rules.

Q4. What is the Styles panel?

It displays CSS rules and declarations affecting the selected element.

Q5. What is the Computed panel?

It displays the final computed CSS values for the selected element.

Q6. Why is a CSS declaration crossed out?

It generally means another declaration wins for that property in the cascade.

Q7. How do you debug a box model issue?

Select the element and inspect the Box Model diagram to examine content, padding, border and margin.

Q8. How do you test responsive design in Chrome?

Use the Toggle Device Toolbar and test multiple viewport widths and device presets.

Q9. How do you find a missing CSS file?

Use the Network panel, filter CSS requests and inspect the resource URL and HTTP status.

Q10. What is the purpose of the Console panel?

It displays JavaScript errors, warnings and log messages and allows interactive JavaScript execution.

Q11. How do you debug a Flexbox layout?

Inspect the flex container and item properties such as direction, alignment, wrapping, grow, shrink and basis.

Q12. Do DevTools changes automatically update the CSS file?

Normally no. Changes made directly in DevTools are temporary unless a configured local workspace workflow is used.

Q13. What is the Network panel used for?

It displays resource requests and responses, including CSS files, images, scripts and fonts.

Q14. How do you debug an element that does not appear?

Inspect its DOM presence, display and visibility properties, dimensions, positioning, overflow, opacity and relevant ancestor styles.

24. Coding Challenge

Problem: Debug a broken responsive course page.

The page contains these problems:

  • Course cards overflow the viewport.
  • The navigation bar does not wrap.
  • A button background is unexpectedly overridden.
  • The stylesheet path is incorrect.
  • The card heading has unexpected spacing.

Use DevTools to:

  1. Identify the missing stylesheet request.
  2. Find the winning button background declaration.
  3. Inspect the box model of the overflowing card.
  4. Find the Flexbox property causing navigation overflow.
  5. Correct the source files.
  6. Test the result at multiple viewport widths.

Expected Result

A fully styled responsive page with corrected CSS conflicts, spacing and navigation behavior.

25. Key Takeaways

  • Developer Tools are essential for frontend debugging.
  • Elements helps inspect HTML and CSS.
  • Styles displays matching and overridden declarations.
  • Computed displays final property values.
  • Box Model helps investigate spacing and dimensions.
  • Flexbox and Grid overlays help diagnose layouts.
  • Device mode helps test responsive behavior.
  • Network helps identify missing stylesheet resources.
  • Console helps identify JavaScript errors.
  • Always verify fixes in the original source files.
