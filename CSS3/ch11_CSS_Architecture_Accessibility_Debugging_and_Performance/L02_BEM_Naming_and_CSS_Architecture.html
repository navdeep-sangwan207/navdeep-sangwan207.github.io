Lecture 2: BEM Naming and CSS Architecture

Learn the Block Element Modifier methodology, create predictable CSS class names and organize reusable components for scalable frontend applications.

1. Learning Objectives

After completing this lecture, you should be able to:

  • Explain the purpose of CSS naming conventions.
  • Understand the Block Element Modifier (BEM) methodology.
  • Identify blocks, elements and modifiers.
  • Write BEM class names in HTML and CSS.
  • Understand how BEM reduces selector conflicts.
  • Build reusable and independent CSS components.
  • Recognize common BEM naming mistakes.
  • Apply BEM to a practical frontend component.

2. What Is CSS Architecture?

CSS architecture is the way CSS code is structured, named and organized so that styles remain understandable and maintainable as a project grows.

A good CSS architecture aims to:

  • Reduce unintended style conflicts.
  • Make components reusable.
  • Keep class names predictable.
  • Reduce unnecessary selector specificity.
  • Make changes easier to understand and test.
  • Support collaboration among multiple developers.
CSS architecture is not a browser feature. It is a set of design and organization practices used by developers.

3. Problems with Unstructured CSS

Consider the following HTML:

<div class="box">
    <h2 class="title">C++ Programming</h2>
    <p class="text">Learn C++ fundamentals.</p>
    <button class="button">Start Learning</button>
</div>

<div class="box">
    <h2 class="title">Linux Programming</h2>
    <p class="text">Learn Linux fundamentals.</p>
    <button class="button">Start Learning</button>
</div>

The class names are generic. As the application grows, the developer may find it difficult to identify which title, text or button belongs to which component.

Possible problems include:

  • Unintended styling of unrelated elements.
  • Conflicting component styles.
  • Unclear ownership of CSS rules.
  • Difficulty reusing and modifying components safely.

4. What Is BEM?

BEM stands for Block Element Modifier. It is a CSS naming methodology that gives class names a predictable structure.

The three parts are:

Part Meaning Purpose
Block Independent component Represents a reusable UI component.
Element Part of a block Represents a component's internal part.
Modifier Variation or state Represents a different appearance or behavior-related state.

Standard BEM naming pattern

block
block__element
block--modifier
block__element--modifier
Remember: Double underscores separate a block from an element. Double hyphens introduce a modifier.

5. Block in BEM

A block is an independent and reusable component. It can exist on its own without depending on another component's internal structure.

Examples of blocks

  • header
  • navigation
  • course-card
  • search-form
  • button
  • sidebar
<div class="course-card">
    Course information
</div>
.course-card {
    padding: 20px;
    background: white;
    border: 1px solid #dce3ec;
    border-radius: 10px;
}

Here, course-card is the block. It represents an independent course-card component.

6. Element in BEM

An element is a part of a block. It does not represent an independent component in that naming relationship.

Examples

<article class="course-card">
    <h2 class="course-card__title">
        Embedded Systems
    </h2>

    <p class="course-card__description">
        Learn microcontrollers and embedded programming.
    </p>

    <a class="course-card__link" href="#">
        View Course
    </a>
</article>
.course-card {
    padding: 20px;
    border: 1px solid #ddd;
}

.course-card__title {
    color: #174ea6;
}

.course-card__description {
    color: #555;
}

.course-card__link {
    color: #007bff;
    font-weight: bold;
}

In this example:

  • course-card is the block.
  • course-card__title is an element.
  • course-card__description is an element.
  • course-card__link is an element.
An element's name is associated with its block. BEM does not require the HTML element to be a direct child of the block. Avoid encoding every level of DOM nesting into the class name.

7. Modifier in BEM

A modifier represents a variation of a block or element. It can change its appearance, size or visual state.

Block modifier example

<button class="button button--primary">
    Submit
</button>

<button class="button button--secondary">
    Cancel
</button>
.button {
    padding: 10px 18px;
    border: 0;
    border-radius: 5px;
    cursor: pointer;
}

.button--primary {
    background: #174ea6;
    color: white;
}

.button--secondary {
    background: #e5eaf2;
    color: #263238;
}

Element modifier example

<article class="course-card">
    <h2 class="course-card__title course-card__title--featured">
        Featured Course
    </h2>
</article>
.course-card__title {
    font-size: 1.3rem;
}

.course-card__title--featured {
    color: #007bff;
}

A modifier is generally used together with its base block or element class. This allows the component to retain its standard styles while applying a variation.

8. BEM Naming Rules and Best Practices

Rule Example
Use a descriptive block name. course-card
Use double underscores for elements. course-card__title
Use double hyphens for modifiers. course-card--featured
Keep class names meaningful. navigation__link
Avoid unnecessary nesting in names. card__title
Reuse the base class with modifiers. button button--primary

Incorrect or unclear naming

.card .title .text {
    color: blue;
}

#main .container .box h2 {
    font-size: 24px;
}

These selectors depend heavily on document structure and can become difficult to reuse.

More maintainable BEM-style naming

.course-card__title {
    color: blue;
}

.course-card__description {
    font-size: 16px;
}

9. Complete Practical Example: Course Card

The following example demonstrates a complete BEM-style course card with a featured variation and reusable button.

HTML

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>BEM Course Cards</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>

    <main class="course-list">

        <article class="course-card course-card--featured">
            <h2 class="course-card__title">
                Embedded Systems
            </h2>

            <p class="course-card__description">
                Learn microcontrollers, peripherals and Embedded C.
            </p>

            <a class="button button--primary" href="#">
                Start Learning
            </a>
        </article>

        <article class="course-card">
            <h2 class="course-card__title">
                Linux Programming
            </h2>

            <p class="course-card__description">
                Learn Linux commands and system programming.
            </p>

            <a class="button button--secondary" href="#">
                View Course
            </a>
        </article>

    </main>

</body>
</html>

CSS

:root {
    --primary-color: #174ea6;
    --accent-color: #007bff;
    --border-color: #dce3ec;
    --surface-color: #ffffff;
}

*,
*::before,
*::after {
    box-sizing: border-box;
}

body {
    margin: 0;
    padding: 30px;
    font-family: Arial, sans-serif;
    background: #f5f7fa;
}

.course-list {
    max-width: 850px;
    margin: auto;
    display: grid;
    grid-template-columns: repeat(2, minmax(0, 1fr));
    gap: 20px;
}

.course-card {
    padding: 22px;
    background: var(--surface-color);
    border: 1px solid var(--border-color);
    border-radius: 10px;
}

.course-card--featured {
    border: 2px solid var(--primary-color);
}

.course-card__title {
    color: var(--primary-color);
    margin-top: 0;
}

.course-card__description {
    color: #555;
    line-height: 1.6;
}

.button {
    display: inline-block;
    padding: 10px 16px;
    border-radius: 5px;
    text-decoration: none;
    font-weight: 600;
}

.button--primary {
    background: var(--primary-color);
    color: white;
}

.button--secondary {
    background: #e5eaf2;
    color: #263238;
}

.button:hover {
    opacity: 0.85;
}

@media (max-width: 600px) {
    .course-list {
        grid-template-columns: 1fr;
    }
}

Expected Result

Embedded Systems

Learn microcontrollers, peripherals and Embedded C.

Button: Start Learning

Linux Programming

Learn Linux commands and system programming.

Button: View Course

The first card has a highlighted border. Both cards use the same component structure and reusable button styles.

10. BEM vs Traditional CSS Naming

Traditional Naming BEM Naming
.title .course-card__title
.active-card .course-card--active
.card-text .course-card__description
.red-button .button button--danger

BEM provides a consistent naming structure. Traditional naming can also work in small projects, but inconsistent naming becomes harder to manage as the project grows.

11. Advantages and Limitations of BEM

Advantages

  • Predictable class naming.
  • Clear relationship between components and their elements.
  • Reduced dependence on deeply nested selectors.
  • Reusable component styles.
  • Improved collaboration and code readability.
  • Generally low and consistent selector specificity.

Limitations

  • Class names can become lengthy.
  • Strict naming may feel verbose in small projects.
  • It requires team consistency.
  • It does not automatically solve every CSS architecture problem.
  • It does not replace accessibility, testing or responsive design.
BEM is a naming methodology, not a complete component framework. It can be combined with CSS Modules, Sass, utility classes and other styling approaches.

12. Common BEM Mistakes

Mistake Recommended Approach
.course-card_title .course-card__title
.course-card-featured .course-card--featured
.course-card__body__title .course-card__title
Using only a modifier class without the base class. Use button button--primary.
Using a block name for an unrelated component. Give independent components their own block names.

13. Placement Interview Questions and Answers

Q1. What is BEM?

BEM stands for Block Element Modifier. It is a CSS naming methodology used to create predictable and maintainable class names.

Q2. What is a block in BEM?

A block is an independent and reusable component, such as a navigation bar, card or button.

Q3. What is an element in BEM?

An element is a part of a block. It is represented by the block name followed by a double underscore and its name.

Q4. What is a modifier in BEM?

A modifier represents a variation of a block or element, such as a primary button or featured card.

Q5. What is the difference between an element and a modifier?

An element identifies a part of a component. A modifier identifies a variation or state of that component or part.

Q6. Why does BEM use double underscores?

Double underscores distinguish an element name from its block name, making the relationship clear.

Q7. Why does BEM use double hyphens?

Double hyphens distinguish modifiers from the base block or element.

Q8. Does BEM require nested CSS selectors?

No. BEM generally encourages flat class selectors, such as .course-card__title, rather than depending on deep DOM nesting.

Q9. Can BEM be used with Flexbox and CSS Grid?

Yes. BEM controls naming and component organization. Flexbox and Grid control layout. They solve different problems.

Q10. Is BEM compulsory in every frontend project?

No. It is one widely used methodology. Projects may use other approaches, but consistent naming and component boundaries remain important.

Q11. Can two blocks be independent of each other?

Yes. Independent blocks should be reusable without depending on another block's internal implementation.

Q12. How does BEM help reduce CSS conflicts?

Descriptive component-specific class names reduce accidental selector overlap. Flat class selectors also help keep specificity relatively low and predictable.

15. Coding Challenge

Problem: Build a BEM-based navigation bar.

Create a responsive navigation bar containing:

  • A navigation block.
  • A logo element.
  • A menu element.
  • Individual menu-link elements.
  • An active link modifier.
  • A mobile layout using a media query.

Use BEM naming consistently. Do not use deeply nested selectors to identify menu elements.

Expected Result

A reusable navigation component with clearly named elements and an active-link variation. The layout should adapt to narrow screens.

16. Key Takeaways

  • BEM means Block Element Modifier.
  • A block is an independent component.
  • An element is a part of a block.
  • A modifier represents a variation or state.
  • Use __ to separate block and element.
  • Use -- to identify modifiers.
  • BEM improves naming consistency and component organization.
  • BEM is a methodology, not a mandatory CSS feature.
