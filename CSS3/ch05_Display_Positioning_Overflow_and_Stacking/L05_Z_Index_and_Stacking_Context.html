Lecture 5: Z-Index and Stacking Context

Chapter 5 – Display, Positioning, Overflow and Stacking

Understand how overlapping elements are layered and displayed.

1. Learning Objectives

  • Understand the CSS z-index property.
  • Understand stacking order.
  • Learn how stacking contexts work.
  • Understand positive, zero and negative z-index values.
  • Identify common stacking-context triggers.
  • Understand nested stacking contexts.
  • Debug elements appearing behind other elements.
  • Build practical modal and overlay layouts.

2. Introduction to Z-Index

When two or more elements overlap, the browser determines which element appears in front of the others. This is controlled by the CSS stacking and painting rules.

The z-index property can influence the stacking order of elements within the applicable stacking context.

Syntax

.box {
    position: relative;
    z-index: 5;
}

Common Values

Value Meaning
auto Automatic stacking behaviour.
0 Participates at the zero level in its stacking context.
1 Positive stacking level.
10 Higher positive stacking level than 1 in the same context.
-1 Negative stacking level.
A larger z-index does not guarantee that an element appears above every other element on the page. Stacking-context boundaries matter.

3. Understanding Stacking Order

Stacking order determines how overlapping elements are painted on the screen.

In a simple example where positioned elements belong to the same stacking context, an element with a higher z-index generally paints above one with a lower z-index.

Example

.box-one {
    position: absolute;
    z-index: 1;
}

.box-two {
    position: absolute;
    z-index: 2;
}

.box-three {
    position: absolute;
    z-index: 3;
}

Expected Result

Z-Index: 1
Z-Index: 2
Z-Index: 3

The green box with z-index 3 appears above the red box with z-index 2, which appears above the blue box with z-index 1.

4. Does Z-Index Work on Every Element?

The ordinary z-index behaviour applies to positioned elements and to flex and grid items in their relevant layout contexts.

A non-positioned block element in normal flow does not generally respond to z-index in the same way as a positioned element.

Example: Positioned Element

.box {
    position: relative;
    z-index: 5;
}

Example: Flex Item

.container {
    display: flex;
}

.item {
    z-index: 5;
}

A flex item can use z-index even when its position is static. Grid items have similar z-index behaviour.

Do not memorize the rule as "z-index only works with position." Flex and grid items are important exceptions.

5. Negative Z-Index

A negative z-index can place an element behind other content within its stacking context.

Example

.background-shape {
    position: absolute;
    z-index: -1;
}

Expected Result

Text displayed above the negative z-index element.

Negative z-index values can cause an element to appear behind its parent background or become difficult to see. Check the stacking context and painting order carefully.

6. What Is a Stacking Context?

A stacking context is an isolated group of elements that are stacked independently from elements outside that context.

Child elements are ordered within their own stacking context. Their z-index values do not directly compete with elements outside that context.

Important Characteristics

  • A stacking context creates an independent stacking group.
  • Child z-index values are resolved within their context.
  • The entire stacking context is stacked as a unit in its parent context.
  • A child cannot escape its parent's stacking context simply by using a very large z-index.

7. Common Properties That Create Stacking Contexts

Several CSS properties can create a new stacking context.

Property or Condition When It Creates a Stacking Context
Root element The document root establishes the root stacking context.
position + z-index A positioned element with a z-index other than auto.
position: fixed Fixed-position elements create stacking contexts.
position: sticky Sticky-positioned elements create stacking contexts.
opacity Opacity less than 1.
transform A transform value other than none.
filter A filter value other than none.
isolation isolation: isolate.
Flex and grid items A flex or grid item with z-index other than auto.
Other modern properties Properties such as perspective, certain containment values and container-type can establish stacking contexts.

Example

.card {
    opacity: 0.9;
}

.panel {
    transform: translateX(0);
}

.container {
    isolation: isolate;
}

Each of these declarations can create a stacking context under the applicable CSS rules.

8. Nested Stacking Contexts

One of the most important concepts in CSS debugging is nested stacking contexts.

Consider a parent stacking context with z-index 1. Its child has z-index 999. Another sibling stacking context has z-index 2.

The child with z-index 999 cannot escape its parent's stacking context to appear above the sibling context.

Example

.parent {
    position: absolute;
    z-index: 1;
}

.child {
    position: absolute;
    z-index: 999;
}

.sibling {
    position: absolute;
    z-index: 2;
}

Expected Result

Parent Context: 1
Child: 999
Sibling Context: 2

The green sibling stacking context can appear above the red child even though the child has z-index 999.

Think of stacking contexts as separate layers. First compare the parent contexts, then compare their children within their own contexts.

9. Z-Index and Isolation

The isolation property can explicitly create a new stacking context.

Syntax

.component {
    isolation: isolate;
}

This is useful when building reusable components whose internal layering should remain isolated from the surrounding page.

Example

.card {
    position: relative;
    isolation: isolate;
}

.card::before {
    content: "";
    position: absolute;
    inset: 0;
    z-index: -1;
    background: #eaf2ff;
}

The stacking context keeps the decorative pseudo-element's layering contained within the card.

10. Practical Example: Modal Overlay

A modal dialog normally appears above the page content, with a background overlay behind it.

Example

<div class="overlay"></div>

<div class="modal">
    <h2>Confirm Action</h2>
    <p>Do you want to continue?</p>
</div>
.overlay {
    position: absolute;
    inset: 0;
    background: rgba(0,0,0,0.5);
    z-index: 1;
}

.modal {
    position: relative;
    z-index: 2;
}

Expected Result

Confirm Action

Do you want to continue?

The overlay darkens the background, while the modal appears above it.

This is a visual layering example, not a complete accessible modal implementation. A production modal should also manage focus, keyboard interaction, dismissal and background interaction.

11. Practical Example: Dropdown Layering

Dropdown menus often need to appear above nearby page content.

Example

.navbar {
    position: relative;
    z-index: 10;
}

.dropdown-menu {
    position: absolute;
    z-index: 20;
}

The menu's z-index is useful within the relevant stacking context. However, a higher z-index cannot overcome a lower ancestor stacking context.

12. Z-Index vs Overflow

A high z-index does not necessarily allow an element to escape an ancestor's clipping boundary. 

.container {
    overflow: hidden;
}

.child {
    position: absolute;
    z-index: 9999;
}

The child may still be clipped by the container. Z-index controls stacking order; it does not cancel overflow clipping.

If a dropdown or tooltip is clipped, inspect ancestor overflow properties. A different component structure or a top-layer mechanism may be more appropriate.

13. Common Mistakes and Debugging

  1. Large z-index does not bring an element forward: Inspect ancestor stacking contexts.
  2. Child appears behind a sibling: Compare the parent stacking-context levels.
  3. Dropdown is clipped: Check overflow hidden, auto and clip on ancestors.
  4. Modal appears behind the header: Check the header's stacking context and modal's parent context.
  5. Unexpected stacking context: Inspect opacity, transform, filter, isolation and containment properties.
  6. Negative z-index element disappears: Inspect parent backgrounds and the relevant stacking context.
  7. Unmanageable z-index values: Establish a consistent component layering strategy.

Recommended Debugging Procedure

  1. Select the overlapping element in Developer Tools.
  2. Inspect its computed z-index.
  3. Check whether it participates in a stacking context.
  4. Inspect all ancestor elements.
  5. Identify properties creating stacking contexts.
  6. Compare the stacking levels of the relevant parent contexts.
  7. Check overflow clipping separately.

14. Placement Interview Questions and Answers

Q1. What is z-index?

Answer: It influences the stacking order of an element within its applicable stacking context.

Q2. What is a stacking context?

Answer: It is an isolated group of elements that are stacked independently from elements outside that context.

Q3. Does a higher z-index always appear on top?

Answer: No. Stacking-context boundaries and painting rules determine the final result.

Q4. What is a nested stacking context?

Answer: It is a stacking context created inside another stacking context.

Q5. Can a child with z-index 999 appear above every sibling?

Answer: No. It cannot escape its parent's stacking context.

Q6. Does opacity create a stacking context?

Answer: Yes, when opacity is less than 1.

Q7. Does transform create a stacking context?

Answer: Yes, when transform is not none.

Q8. What does isolation: isolate do?

Answer: It creates a new stacking context.

Q9. Does z-index work on flex items?

Answer: Yes. Flex items can use z-index even when their position is static.

Q10. Can overflow hidden clip an element with a high z-index?

Answer: Yes. Stacking order does not override overflow clipping.

Q11. What is the difference between z-index and stacking context?

Answer: Z-index influences stacking order, while a stacking context defines an independent stacking group.

Q12. How do you debug an element appearing behind another?

Answer: Inspect computed z-index, ancestor stacking contexts, positioning and overflow clipping.

15. Practical Coding Challenges

  1. Create three overlapping boxes with different z-index values.
  2. Change their z-index values and observe the result.
  3. Create a negative z-index background shape.
  4. Create a parent stacking context with z-index 1.
  5. Give its child z-index 999 and compare it with a sibling context at z-index 2.
  6. Create a modal overlay with a dialog above it.
  7. Build a dropdown menu with appropriate layering.
  8. Apply opacity to a parent and observe its stacking context.
  9. Apply transform to a parent and inspect the stacking behaviour.
  10. Debug a dropdown clipped by overflow hidden.

16. Quick Revision

  • Z-index influences stacking order.
  • Higher stacking levels generally paint above lower levels within the same context.
  • Stacking contexts isolate their child stacking order.
  • Nested contexts cannot be escaped with a larger child z-index.
  • Opacity below 1 creates a stacking context.
  • Transform can create a stacking context.
  • Isolation isolate explicitly creates a stacking context.
  • Flex and grid items can use z-index without positioning.
  • Overflow clipping is separate from stacking order.
  • Inspect ancestor contexts when z-index behaves unexpectedly.
