Lecture 2: Display None, Visibility and Normal Document Flow

Chapter 5 – Display, Positioning, Overflow and Stacking

Understand how CSS hides elements and controls their space in page layout.

1. Learning Objectives

  • Understand normal document flow.
  • Learn how block and inline elements participate in layout.
  • Understand display: none.
  • Understand visibility: hidden.
  • Understand opacity: 0.
  • Compare the layout behaviour of all three properties.
  • Understand how hidden elements affect surrounding elements.
  • Learn how visibility behaves with parent and child elements.
  • Apply these properties to practical UI components.
  • Debug common element visibility problems.

2. What Is Normal Document Flow?

Normal document flow is the default layout behaviour in which elements are arranged according to their formatting context and position in the HTML document.

In ordinary block flow, block-level elements are generally placed one after another vertically. Inline content flows horizontally and wraps when the available line space is exhausted.

Example

<div>First Element</div>
<div>Second Element</div>
<div>Third Element</div>
div {
    padding: 12px;
    margin: 8px 0;
    background: #dceaff;
}

Expected Result

First Element
Second Element
Third Element

Each block element occupies its position in the normal flow, so the next block normally appears after the preceding one.

3. How Elements Participate in Normal Flow

Block-Level Elements

  • Normally start on a new line.
  • Usually occupy available inline space.
  • Participate in block layout.

Inline Elements

  • Participate in inline formatting.
  • Flow within lines of text.
  • Wrap when line space is insufficient.

Elements Outside Normal Flow

Certain positioning methods remove elements from normal flow or change how they participate in layout.

  • Absolutely positioned elements.
  • Fixed-positioned elements.
  • Floated elements, which are taken out of normal block flow but still interact with surrounding inline content.
Relative and sticky positioned elements remain in normal flow. Their visual offsets do not remove their original space from the layout.

4. Understanding display: none

The display: none property prevents an element's principal box from being generated. The element therefore does not occupy layout space.

Syntax

.element {
    display: none;
}

Example

<div class="box">First Box</div>

<div class="hidden">Hidden Box</div>

<div class="box">Third Box</div>
.hidden {
    display: none;
}

Expected Result

First Box
Hidden Box
Third Box

The second box is not displayed, and the third box moves up because the hidden element occupies no layout space.

Important Characteristics

  • The element does not generate its normal layout box.
  • Its descendants are not displayed through that box.
  • It does not reserve its previous layout space.
  • It is normally absent from the accessibility tree.
  • It cannot receive ordinary pointer interaction while hidden this way.

5. Understanding visibility: hidden

The visibility: hidden property hides an element visually but preserves its layout space.

Syntax

.element {
    visibility: hidden;
}

Example

<div class="box">First Box</div>

<div class="hidden">Hidden Box</div>

<div class="box">Third Box</div>
.hidden {
    visibility: hidden;
}

Expected Result

First Box
Hidden Box
Third Box

The second box is invisible, but its layout space remains reserved. The third box does not move up.

Important Characteristics

  • The element remains in the layout.
  • Its box continues to occupy space.
  • It is not visually painted as a visible element.
  • It is normally not exposed in the accessibility tree while hidden.
  • Its descendants can explicitly override visibility in certain cases.

6. Understanding opacity: 0

The opacity property controls the transparency of an entire element and its contents.

Syntax

.element {
    opacity: 0;
}

Example

<div class="box">First Box</div>

<div class="hidden">Transparent Box</div>

<div class="box">Third Box</div>
.hidden {
    opacity: 0;
}

Expected Result

First Box
Transparent Box
Third Box

The second box is fully transparent, but its layout space remains reserved.

Important Characteristics

  • The element remains in the layout.
  • Its original layout space remains reserved.
  • It is visually transparent.
  • It can still receive pointer interaction.
  • It can remain keyboard-focusable and accessible.
  • An opacity value below 1 creates a stacking context.
opacity: 0 does not make an element non-interactive. If an invisible control should not be usable, manage pointer interaction, keyboard focus and accessibility separately.

7. Difference Between display: none, visibility: hidden and opacity: 0

Feature display: none visibility: hidden opacity: 0
Visually visible No No No
Layout space reserved No Yes Yes
Normal pointer interaction No No Usually yes
Normally in accessibility tree No No Yes
Creates stacking context No No Yes, when opacity is below 1
Typical use Remove from layout Hide but reserve space Fade visual appearance
Accessibility behaviour can depend on the element and surrounding accessibility state. For intentionally disabled controls, use the appropriate HTML or ARIA semantics rather than relying only on visual hiding.

8. Visibility and Parent-Child Behaviour

An element with visibility: hidden can contain a child whose visibility is explicitly set to visible.

Example

<div class="parent">
    Parent Content

    <div class="child">
        Visible Child
    </div>
</div>
.parent {
    visibility: hidden;
}

.child {
    visibility: visible;
}

Expected Result

Hidden Parent Content
Visible Child

The parent content is hidden, while the child can be explicitly made visible.

This behaviour is specific to visibility inheritance. It does not work the same way with display: none or opacity: 0.

9. Understanding Space Reservation

Space reservation determines whether surrounding elements move when an element becomes invisible.

With display: none

.box {
    display: none;
}

The hidden element generates no layout box, so surrounding elements can move into the space.

With visibility: hidden

.box {
    visibility: hidden;
}

The element remains in layout and retains its space.

With opacity: 0

.box {
    opacity: 0;
}

The element remains in layout and retains its space.

10. Practical Applications

Requirement Suitable Approach
Completely remove a section from layout display: none
Hide content but preserve its layout space visibility: hidden
Fade an element visually opacity
Show and hide a dropdown conditionally Depends on layout and interaction requirements
Animate a fade effect opacity with transition
Remove an inactive component from layout display: none or conditional rendering

11. Practical Example: Show and Hide a Notification

Use JavaScript to toggle a notification using display: none and display: block.

Complete HTML, CSS and JavaScript

<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Notification Toggle</title>

    <style>
        body {
            font-family: Arial, sans-serif;
            padding: 25px;
        }

        button {
            background: #174ea6;
            color: white;
            padding: 10px 18px;
            border: none;
            border-radius: 5px;
            cursor: pointer;
        }

        #notification {
            display: none;
            background: #eaf2ff;
            border-left: 4px solid #174ea6;
            padding: 15px;
            margin-top: 15px;
        }
    </style>
</head>

<body>

    <h2>Notification Example</h2>

    <button onclick="toggleNotification()">
        Show / Hide Notification
    </button>

    <div id="notification" role="status">
        Your course progress has been saved.
    </div>

    <script>
        function toggleNotification() {

            const notification =
                document.getElementById("notification");

            if (notification.style.display === "block") {
                notification.style.display = "none";
            } else {
                notification.style.display = "block";
            }
        }
    </script>

</body>
</html>

Expected Result

  • Notification is initially hidden.
  • Clicking the button displays it.
  • Clicking again hides it.
  • The notification does not reserve space while hidden.

12. Practical Example: Fade an Element

Use opacity and CSS transitions to create a fade effect.

Example

.card {
    opacity: 1;
    transition: opacity 0.3s ease;
}

.card:hover {
    opacity: 0.6;
}

The card gradually becomes transparent when the pointer moves over it.

A visual fade does not automatically disable interaction. If the element must become unavailable, manage its interaction and accessibility state as well.

13. Common Mistakes and Debugging

  1. Unexpected layout movement: Check whether display: none is removing an element's space.
  2. Invisible element still blocks clicks: Check opacity: 0. The element may still receive pointer events.
  3. Hidden element still occupies space: This is expected with visibility: hidden and opacity: 0.
  4. Child remains visible: Check whether the parent uses visibility: hidden and the child overrides it.
  5. Fade animation does not work: Check that opacity is transitioning between numeric values.
  6. Hidden control remains keyboard-accessible: Manage tabindex, focus and semantic state appropriately.
  7. Unexpected overlapping: Inspect stacking contexts and positioning.

Browser Debugging Steps

  1. Inspect the element in Developer Tools.
  2. Check computed display, visibility and opacity.
  3. Inspect its dimensions and layout space.
  4. Check whether a parent is hiding the element.
  5. Test pointer and keyboard interaction.
  6. Check accessibility information where relevant.

14. Placement Interview Questions and Answers

Q1. What is normal document flow?

Answer: It is the default layout behaviour in which elements are arranged according to their formatting context and document order.

Q2. What does display: none do?

Answer: It prevents the element's principal box from being generated, so it does not occupy normal layout space.

Q3. What does visibility: hidden do?

Answer: It hides the element visually but preserves its layout space.

Q4. What does opacity: 0 do?

Answer: It makes the element and its contents fully transparent while retaining its layout space.

Q5. What is the main difference between display: none and visibility: hidden?

Answer: Display: none removes the element's layout box, whereas visibility: hidden preserves its space.

Q6. Does opacity: 0 remove an element from the layout?

Answer: No. The element retains its layout space.

Q7. Can an opacity: 0 element receive clicks?

Answer: Yes. Transparency alone does not disable pointer interaction.

Q8. Can a hidden parent have a visible child?

Answer: Yes. A child can explicitly set visibility: visible when its parent has visibility: hidden.

Q9. Which property is suitable for completely hiding a component from layout?

Answer: display: none.

Q10. Which property can be used for fade effects?

Answer: opacity, usually combined with the CSS transition property.

Q11. Does visibility: hidden prevent keyboard focus?

Answer: A visibility-hidden element is normally not rendered or focusable. However, opacity: 0 does not automatically remove an element from keyboard navigation.

Q12. What happens to surrounding elements when display: none is applied?

Answer: They can move into the space because the hidden element no longer generates its normal layout box.

Q13. Does position: relative remove an element from normal flow?

Answer: No. A relatively positioned element retains its original layout space.

Q14. Does position: absolute participate in normal flow?

Answer: No. An absolutely positioned element is removed from normal flow.

Q15. What is the difference between hidden visibility and zero opacity?

Answer: Both retain layout space, but opacity: 0 can still receive pointer interaction and creates a stacking context. Visibility: hidden normally prevents ordinary pointer interaction and is not exposed in the accessibility tree.

15. Practical Coding Challenges

  1. Create three boxes and hide the middle box using display: none.
  2. Repeat the example using visibility: hidden.
  3. Repeat it using opacity: 0.
  4. Observe how the third box changes position in each case.
  5. Create a notification that can be shown and hidden.
  6. Create a card that fades on hover.
  7. Build a parent with visibility: hidden and a child with visibility: visible.
  8. Investigate whether an opacity: 0 button can still receive clicks.
  9. Compare the keyboard behaviour of hidden and transparent controls.
  10. Use Developer Tools to inspect the computed styles of all three hiding techniques.

16. Quick Revision

  • Normal document flow arranges elements according to their formatting context.
  • Block elements normally stack vertically.
  • Inline elements flow within lines of text.
  • display: none removes the normal layout box.
  • visibility: hidden preserves layout space.
  • opacity: 0 makes the element fully transparent.
  • Opacity does not automatically disable interaction.
  • Visibility can be overridden by a child element.
  • Absolute and fixed positioning remove elements from normal flow.
  • Relative and sticky positioning preserve their normal-flow space.
