2. Fixed Positioning

position: fixed removes an element from normal document flow and positions it relative to its fixed-position containing block.

In the common case, the fixed-position containing block is the viewport. Therefore, a fixed element generally remains at the same screen position while the document scrolls.

Syntax

.fixed-box {
    position: fixed;

    top: 0;
    right: 0;
}

Characteristics

  • Removed from normal flow.
  • Does not reserve its original layout space.
  • Usually positioned relative to the viewport.
  • Normally remains in the same viewport position while scrolling.
  • Can overlap other elements.
  • Can be layered using z-index, subject to stacking-context rules.

Example: Fixed Header

<header class="site-header">
    My Website
</header>

<main>
    Page Content
</main>
.site-header {
    position: fixed;

    top: 0;
    left: 0;
    right: 0;

    background: #174ea6;
    color: white;
    padding: 16px;
    z-index: 100;
}

main {
    padding-top: 70px;
}

Since the fixed header is removed from normal flow, the main content may need top padding or margin to prevent it from appearing underneath the header.

The padding value should account for the actual header height. A fixed element does not automatically reserve space for itself.

3. Fixed Positioning and the Viewport

When the viewport establishes the containing block, fixed positioning allows an element to remain in a consistent screen location.

Common Applications

  • Fixed navigation bars.
  • Floating help buttons.
  • Cookie notification banners.
  • Chat support buttons.
  • Persistent action controls.

Example: Floating Action Button

.help-button {
    position: fixed;

    right: 25px;
    bottom: 25px;

    background: #174ea6;
    color: white;

    padding: 14px 18px;
    border-radius: 30px;
}

This button normally remains at the bottom-right of the viewport when the page scrolls.

4. Sticky Positioning

position: sticky combines aspects of relative and fixed positioning.

A sticky element initially behaves like a normally positioned element in document flow. When its scroll position reaches a specified inset threshold, it sticks within the relevant scroll container.

Syntax

.sticky-header {
    position: sticky;
    top: 0;
}

Characteristics

  • Remains in normal flow.
  • Its original layout space is preserved.
  • Requires a non-auto inset threshold on the relevant axis.
  • Sticks within its relevant scroll container.
  • Its movement is constrained by its containing block.
  • It stops sticking when its containing block's boundary requires it to stop.

Example: Sticky Section Heading

.section-heading {
    position: sticky;
    top: 0;

    background: #174ea6;
    color: white;
    padding: 12px;
}

5. Sticky Positioning Requirements

Sticky positioning can fail when its layout constraints are not satisfied.

Important Requirements

  1. Specify an inset such as top: 0 for vertical sticky behaviour.
  2. The element must have enough scroll distance and room within its containing block to stick.
  3. Its relevant scroll container must be identified.
  4. Its size must allow the sticky behaviour to work within the available scrollport.
  5. Ancestor overflow and layout constraints must be checked.

Example

.sidebar {
    position: sticky;
    top: 20px;
}

The sidebar sticks 20 pixels from the top of its relevant scrollport when scrolling, subject to its containing block and other constraints.

A sticky element does not necessarily stick to the browser viewport. Its nearest relevant scroll container and containing-block constraints determine its behaviour.

6. Scroll Containers and Sticky Elements

A scroll container is an element whose content can be scrolled within its scrollport.

Overflow settings can affect which ancestor acts as the relevant scroll container for sticky positioning.

Example

.container {
    height: 300px;
    overflow-y: auto;
}

.heading {
    position: sticky;
    top: 0;
}

In this example, the sticky heading can stick to the top of the container's scrollport rather than necessarily to the browser viewport.

Common Overflow Values

Value Behaviour
visible Content can overflow without a scroll container being created by this value.
hidden Clips overflow and creates a scroll container, although user scrolling is not provided through ordinary scrollbars.
auto Provides scrolling when needed.
scroll Provides a scroll container with scrolling mechanisms.
clip Clips overflow without creating a scroll container.
For sticky-position debugging, inspect the overflow properties of every ancestor. An ancestor with overflow hidden or auto can change the relevant scrolling behaviour.

7. Containing Blocks for Fixed Elements

Fixed elements commonly use the viewport as their containing block. However, some ancestor properties can establish a different containing block for them.

One important example is the CSS transform property.

Example

.parent {
    transform: translateZ(0);
}

.child {
    position: fixed;
    top: 10px;
    right: 10px;
}

A transformed ancestor can establish a containing block for a fixed-position descendant. In this situation, the fixed child may be positioned relative to that ancestor instead of the viewport.

Other Properties to Check

  • Transform-related properties.
  • Perspective.
  • Filter in applicable containing-block rules.
  • Containment properties.
Do not assume that every fixed element is always viewport-relative. Inspect ancestor properties when a supposedly fixed element scrolls with a container or appears in an unexpected location.

8. Fixed vs Sticky Positioning

Feature Fixed Sticky
Normal flow Removed from normal flow Remains in normal flow
Original space Not reserved Preserved
Reference Fixed-position containing block Relevant scrollport and containing block
Scrolling Normally stays in viewport position Sticks after reaching its threshold
Movement constraint Containing block Scrollport and containing block
Typical use Floating support button Section heading or sidebar

9. Practical Application: Sticky Navigation Bar

A sticky navigation bar remains in normal flow initially and sticks to the top when the page is scrolled.

Complete Example

<header>
    Website Header
</header>

<nav class="navbar">
    <a href="#home">Home</a>
    <a href="#about">About</a>
    <a href="#services">Services</a>
    <a href="#contact">Contact</a>
</nav>

<main>
    Page content...
</main>
header {
    background: #eaf2ff;
    padding: 25px;
}

.navbar {
    position: sticky;
    top: 0;

    display: flex;
    gap: 20px;

    background: #174ea6;
    padding: 15px;

    z-index: 10;
}

.navbar a {
    color: white;
    text-decoration: none;
}

Expected Behaviour

  • The header appears first in normal flow.
  • The navigation appears below it.
  • When scrolling, the navigation sticks to the top.
  • The navigation remains constrained by its containing block.

10. Practical Application: Fixed Help Button

A help button can be fixed at the bottom-right of the viewport for quick access. 

<button class="help-button">
    Need Help?
</button>
.help-button {
    position: fixed;

    right: 20px;
    bottom: 20px;

    background: #174ea6;
    color: white;

    padding: 14px 18px;
    border: none;
    border-radius: 30px;

    cursor: pointer;
    z-index: 100;
}

In a production application, ensure the button does not obscure important content or overlap mobile navigation controls.

11. Common Mistakes and Debugging

  1. Sticky element does not stick: Check whether a non-auto inset such as top: 0 is specified.
  2. Sticky element sticks inside an unexpected area: Inspect ancestor overflow properties and scroll containers.
  3. Sticky element stops too early: Check the height and boundaries of its containing block.
  4. Fixed header covers page content: Add appropriate padding or margin to the content area.
  5. Fixed element moves with an ancestor: Check whether transform or another containing-block-establishing property is applied to an ancestor.
  6. Sticky element appears behind another element: Inspect z-index and stacking contexts.
  7. Sticky sidebar does not work as expected: Check available scroll space and whether the sidebar is too tall for its scrollport.

Developer Tools Checklist

  1. Inspect the computed position value.
  2. Check top, bottom, left and right values.
  3. Inspect ancestor overflow properties.
  4. Check transform and containment properties.
  5. Inspect the element's containing block.
  6. Check parent dimensions and layout constraints.
  7. Inspect stacking contexts when overlap occurs.

12. Placement Interview Questions and Answers

Q1. What is fixed positioning?

Answer: Fixed positioning removes an element from normal flow and positions it relative to its fixed-position containing block.

Q2. What is sticky positioning?

Answer: Sticky positioning keeps an element in normal flow but allows it to stick within its scroll container after reaching an inset threshold.

Q3. Does a fixed element reserve layout space?

Answer: No. It is removed from normal flow.

Q4. Does a sticky element reserve layout space?

Answer: Yes. It remains in normal flow and its original layout space is preserved.

Q5. What is the default reference for fixed positioning?

Answer: Usually the viewport, when no ancestor establishes another fixed-position containing block.

Q6. Why does position: sticky sometimes fail?

Answer: Common reasons include missing inset values, unexpected scroll containers, insufficient scroll space and containing-block constraints.

Q7. Can overflow affect sticky positioning?

Answer: Yes. Ancestor overflow settings can affect the relevant scroll container.

Q8. Can transform affect fixed positioning?

Answer: Yes. A transformed ancestor can establish a containing block for fixed descendants.

Q9. What is the difference between fixed and sticky?

Answer: Fixed elements are removed from normal flow, whereas sticky elements remain in normal flow and stick within scroll constraints.

Q10. How do you create a sticky header?

Answer: Apply position: sticky and top: 0 to the header or navigation element.

Q11. What is the purpose of z-index in sticky layouts?

Answer: It controls the stacking order of the sticky element relative to overlapping content, subject to stacking-context rules.

Q12. Can a sticky element move beyond its parent?

Answer: Its sticky movement is constrained by its containing block.
