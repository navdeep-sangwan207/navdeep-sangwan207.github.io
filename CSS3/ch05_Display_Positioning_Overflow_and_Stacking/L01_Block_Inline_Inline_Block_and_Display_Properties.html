Chapter 5 – Display, Positioning, Overflow and Stacking

Understand how CSS controls the layout behaviour of HTML elements.

1. Learning Objectives

  • Understand the CSS display property.
  • Differentiate block-level and inline elements.
  • Understand inline-block behaviour.
  • Control element dimensions and spacing using display.

2. What Is the CSS Display Property?

The CSS display property determines how an element participates in layout.

It controls whether an element behaves as a block, inline-level box, flex container, grid container or another layout type.

Syntax

selector {
    display: value;
}

Common display values

Value Purpose
block Creates a block-level box.
inline Creates an inline-level box.
inline-block Inline-level placement with block-like dimensions.
none Removes the element and its descendants from layout.
flex Creates a flex container.
grid Creates a grid container.
inline-flex Inline-level flex container.
inline-grid Inline-level grid container.
flow-root Creates a block box establishing a new block formatting context.
contents Causes the element's own principal box not to be generated.

3. Block-Level Elements

A block-level element normally starts on a new line in normal flow and occupies the available inline space of its containing block.

Common HTML block-level elements include:

  • div
  • p
  • h1 to h6
  • section
  • article
  • header
  • footer
  • ul and ol

Example

<div class="box">First Box</div>
<div class="box">Second Box</div>
<div class="box">Third Box</div>
.box {
    display: block;
    background: #174ea6;
    color: white;
    padding: 15px;
    margin: 10px 0;
}

Expected Result

First Block Element
Second Block Element
Third Block Element

Characteristics

  • Normally starts on a new line in normal flow.
  • Normally fills the available inline space.
  • Width and height can be specified.
  • Margins and padding can be applied.
  • Multiple block elements normally stack vertically.
The behaviour described here applies to ordinary block-level boxes in normal flow. Flexbox, Grid and positioning can change the layout behaviour.

4. Inline Elements

Inline elements participate in inline formatting and normally flow within a line of text.

Common inline HTML elements include:

  • span
  • a
  • strong
  • em
  • label
  • small

Example

<p>
    Learn
    <span class="highlight">HTML</span>,
    <span class="highlight">CSS</span>
    and JavaScript.
</p>
.highlight {
    display: inline;
    background: #dceaff;
    color: #174ea6;
    padding: 4px;
}

Expected Result

Learn HTML CSS and JavaScript.

Characteristics

  • Does not normally start a new line.
  • Flows with surrounding text.
  • Multiple inline elements can appear on one line.
  • Width and height generally do not apply to non-replaced inline elements.
  • Horizontal padding and margins can be applied.
  • Vertical margins do not affect the line layout in the same way as block boxes.
Replaced inline elements, such as images and form controls, have different sizing behaviour. Do not assume every inline element behaves identically.

5. Inline-Block Elements

inline-block combines characteristics of inline and block-level layout.

The element participates in inline formatting, but its box can have specified width and height.

Example

<span class="item">HTML</span>
<span class="item">CSS</span>
<span class="item">JavaScript</span>
.item {
    display: inline-block;
    width: 120px;
    height: 60px;
    padding: 15px;
    margin: 8px;
    background: #174ea6;
    color: white;
}

Expected Result

HTML CSS JavaScript

Characteristics

  • Does not normally force a new line.
  • Supports width and height.
  • Supports padding and margins on all sides.
  • Can be aligned with surrounding inline content.
  • Useful for buttons, badges and compact UI elements.

6. Difference Between Block, Inline and Inline-Block

Feature Block Inline Inline-Block
Starts new line Normally yes No No
Width and height Supported Generally not for non-replaced inline boxes Supported
Horizontal padding Yes Yes Yes
Vertical padding Yes Paints but does not expand line box in the same way Yes
Vertical margins Participate in block layout Do not affect line layout like block margins Supported
Typical use Sections and containers Text and links Buttons and badges

7. Changing the Default Display Behaviour

CSS can change the display behaviour of an HTML element without changing its HTML tag.

Example 1: Convert Inline to Block

span {
    display: block;
}

Example 2: Convert Block to Inline

div {
    display: inline;
}

Example 3: Convert Inline to Inline-Block

a {
    display: inline-block;
    width: 120px;
    padding: 10px;
}
Changing display affects visual layout behaviour, not the semantic meaning of the HTML element. Choose HTML elements according to their purpose and meaning.

8. Display Flex

The display: flex value creates a flex container. Its direct children become flex items.

Example

<div class="container">
    <div>One</div>
    <div>Two</div>
    <div>Three</div>
</div>
.container {
    display: flex;
    gap: 10px;
}

Flexbox is particularly useful for navigation bars, aligned controls, card rows and one-dimensional layouts.

9. Display Grid

The display: grid value creates a grid container. Its direct children become grid items.

Example

.container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 10px;

10. Other Useful Display Values

Display: inline-flex

Creates a flex container that participates as an inline-level box in its parent layout. 

.button-group {
    display: inline-flex;
    gap: 8px;
}

Display: inline-grid

Creates a grid container that participates as an inline-level box. 

.small-grid {
    display: inline-grid;
    grid-template-columns: repeat(2, 1fr);
}

Display: flow-root

Creates a block box that establishes a new block formatting context. 

.container {
    display: flow-root;
}

It can contain floated children and prevent certain margin-collapsing interactions.

Display: contents

The element's own principal box is not generated. Its children participate in the surrounding layout as if the wrapper box were absent. 

.wrapper {
    display: contents;
}
Use display: contents carefully. It changes box generation, not the DOM tree, and can have accessibility or browser-specific implications in some situations.

11. Practical Example: Navigation Bar

Create a horizontal navigation bar using inline-level links and Flexbox.

Complete HTML and CSS

<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Navigation Bar</title>

    <style>
        * {
            box-sizing: border-box;
        }

        body {
            margin: 0;
            font-family: Arial, sans-serif;
        }

        .navbar {
            display: flex;
            align-items: center;
            flex-wrap: wrap;
            gap: 10px;

            background: #174ea6;
            padding: 14px 20px;
        }

        .navbar a {
            display: inline-block;
            color: white;
            text-decoration: none;
            padding: 10px 14px;
            border-radius: 5px;
        }

        .navbar a:hover {
            background: #007bff;
        }

        .navbar a:focus-visible {
            outline: 2px solid white;
            outline-offset: 3px;
        }

        .content {
            padding: 25px;
        }
    </style>
</head>

<body>

    <nav class="navbar">
        <a href="#">Home</a>
        <a href="#">Courses</a>
        <a href="#">Projects</a>
        <a href="#">Contact</a>
    </nav>

    <main class="content">
        <h1>My Learning Portal</h1>
        <p>Welcome to the learning portal.</p>
    </main>

</body>
</html>

Expected Result

Home Courses Projects Contact
  • Horizontal navigation links.
  • Consistent spacing between links.
  • Blue navigation background.
  • Hover background effect.
  • Links wrap when space becomes limited.

12. Common Mistakes and Debugging

  1. Width does not work on span: A normal non-replaced inline element does not respond to width and height in the usual way. Use inline-block or block when dimensions are required.
  2. Elements unexpectedly appear on separate lines: Check whether they have block-level display behaviour.
  3. Inline elements overlap vertically: Inspect padding, line-height and surrounding line boxes.
  4. Inline-block elements have unexpected gaps: Whitespace between HTML elements can create visible spacing.
  5. Flexbox does not arrange nested elements: Flexbox affects direct children of the flex container.
  6. Grid layout does not apply: Confirm that the intended parent has display: grid.
  7. Element dimensions look incorrect: Check box-sizing, padding and borders.
  8. Semantic HTML becomes confusing: Do not choose HTML elements solely because of their default display value.

Debugging with Browser Developer Tools

  1. Right-click the element and choose Inspect.
  2. Open the Computed Styles panel.
  3. Find the computed display value.
  4. Inspect width, height, margin and padding.
  5. Temporarily change display values to observe layout behaviour.
  6. Check whether the parent uses Flexbox or Grid.

13. Placement Interview Questions and Answers

Q1. What is the CSS display property?

Answer: It determines how an element's box participates in layout.

Q2. What is a block-level element?

Answer: In normal flow, it normally starts on a new line and occupies the available inline space.

Q3. What is an inline element?

Answer: It participates in inline formatting and flows within surrounding text.

Q4. What is the difference between inline and inline-block?

Answer: Inline elements generally do not accept specified width and height, while inline-block elements support dimensions and block-like box sizing.

Q5. Can we apply width to a span element?

Answer: A normal span is inline, so width generally does not apply. Change its display to inline-block or block when required.

Q6. What is the difference between block and inline-block?

Answer: Block normally starts on a new line, whereas inline-block can sit alongside other inline-level content while supporting dimensions.

Q7. What does display: flex do?

Answer: It creates a flex container and establishes a flex formatting context for its direct children.

Q8. What does display: grid do?

Answer: It creates a grid container for arranging direct children in rows and columns.

Q9. What is display: flow-root?

Answer: It creates a block box that establishes a new block formatting context.

Q10. What is display: contents?

Answer: It suppresses the element's own principal box while its children participate in the surrounding layout.

Q11. What is the difference between inline-flex and flex?

Answer: Both create flex containers. Inline-flex makes the container participate as an inline-level box, while flex creates a block-level flex container in the usual block context.

Q12. Does changing display change HTML semantics?

Answer: No. CSS changes visual layout behaviour, not the semantic meaning of the HTML element.

Q13. Which display value is suitable for a horizontal navigation layout?

Answer: Flexbox is generally a suitable choice because it provides alignment, spacing and wrapping controls.

Q14. What is the difference between display: block and width: 100%?

Answer: Display controls the element's layout behaviour. Width controls its specified size. A block-level element in normal flow generally fills available inline space automatically.

Q15. What happens to direct children when a parent uses display: flex?

Answer: They become flex items and participate in the flex formatting context.

  • Display controls how an element participates in layout.
  • Block elements normally start on a new line.
  • Inline elements flow with surrounding text.
  • Inline-block supports dimensions while participating in inline layout.
  • Flex creates a flex container.
  • Grid creates a grid container.
  • Inline-flex and inline-grid create inline-level containers.
  • Flow-root establishes a new block formatting context.
  • Contents suppresses the element's own principal box.
  • CSS display does not change HTML semantics.
