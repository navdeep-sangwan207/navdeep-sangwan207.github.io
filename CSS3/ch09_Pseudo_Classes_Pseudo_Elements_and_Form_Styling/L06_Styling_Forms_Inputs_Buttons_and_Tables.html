  • Understand form layout and styling.
  • Style text, email, password and number inputs.
  • Style select menus and textareas.
  • Style checkboxes and radio buttons.

  • Understand native control styling limitations.
  • Style tables using CSS.
  • Create responsive tables.
  • Build a complete registration form and data table.

2. Why Form Styling Matters

Forms are a core part of frontend applications. They collect user information and support operations such as registration, login, search, feedback and data entry.

Professional form styling improves readability, consistency, usability and accessibility.

Common Form Components

  • Text input.
  • Email input.
  • Password input.
  • Number input.
  • Date input.
  • Select menu.
  • Textarea.
  • Checkbox and radio button.
  • Submit and reset buttons.

3. Styling Text Inputs

Text inputs are used to collect short text values such as names, usernames, search terms and addresses.

HTML

<label for="username">Username</label>

<input
    type="text"
    id="username"
    name="username"
    placeholder="Enter username"
>

CSS

input[type="text"] {
    width: 100%;
    padding: 11px;
    border: 1px solid #888;
    border-radius: 5px;
    font-size: 16px;
}

input[type="text"]:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 2px;
}

4. Styling Email, Password and Number Inputs

Attribute selectors allow developers to style individual input types.

CSS

input[type="email"],
input[type="password"],
input[type="number"] {
    width: 100%;
    padding: 11px;
    border: 1px solid #888;
    border-radius: 5px;
}

input[type="email"]:focus,
input[type="password"]:focus,
input[type="number"]:focus {
    border-color: #174ea6;
}

Live Demonstration

Important Input Properties

Property Purpose
width Controls input width.
padding Controls internal spacing.
border Defines the input boundary.
border-radius Rounds input corners.
font-size Controls text size.
background-color Controls input background.
outline Defines the focus indicator.

5. Styling Select Menus

The select element allows users to choose one or more options from a predefined list.

HTML

<label for="course">Select Course</label>

<select id="course" name="course">
    <option value="">Choose a course</option>
    <option value="html">HTML5</option>
    <option value="css">CSS3</option>
    <option value="js">JavaScript</option>
</select>

CSS

select {
    width: 100%;
    padding: 11px;
    border: 1px solid #888;
    border-radius: 5px;
    background: white;
    font-size: 16px;
}

Live Demonstration

Native select controls can look different across operating systems and browsers. Their popup menus are not always fully styleable with ordinary CSS.

6. Styling Textareas

A textarea is used to collect multi-line text such as comments, feedback and descriptions.

HTML

<label for="message">Message</label>

<textarea
    id="message"
    name="message"
    rows="5"
    placeholder="Enter your message"
></textarea>

CSS

textarea {
    width: 100%;
    min-height: 120px;
    padding: 11px;
    border: 1px solid #888;
    border-radius: 5px;
    font: inherit;
    resize: vertical;
}

Resize Property

Value Behavior
resize: none Disables resizing.
resize: both Allows horizontal and vertical resizing.
resize: horizontal Allows horizontal resizing.
resize: vertical Allows vertical resizing.

9. Styling Buttons

Buttons trigger actions such as submitting forms, resetting fields or executing application operations.

HTML

<button type="submit">
    Submit
</button>

<button type="reset">
    Reset
</button>

<button type="button">
    Cancel
</button>

CSS

button {
    padding: 11px 18px;
    background: #174ea6;
    color: white;
    border: none;
    border-radius: 5px;
    cursor: pointer;
    font-size: 16px;
}

button:hover {
    background: #007bff;
}

button:active {
    transform: translateY(1px);
}

button:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 3px;
}

button:disabled {
    background: #888;
    cursor: not-allowed;
}

10. Button States

State CSS Selector Purpose
Normal button Default appearance.
Hover :hover Pointer interaction.
Active :active While the control is being activated.
Focus :focus-visible Visible focus indication when appropriate.
Disabled :disabled Unavailable control state.

Practical Example

.submit-button {
    background: #174ea6;
    color: white;
}

.submit-button:hover {
    background: #007bff;
}

.submit-button:active {
    background: #123d80;
}

.submit-button:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 3px;
}

.submit-button:disabled {
    opacity: 0.5;
    cursor: not-allowed;
}
Do not use color alone to distinguish button states. Maintain visible focus indicators and ensure button text remains readable.

11. Styling Tables

HTML tables present structured information in rows and columns. CSS controls borders, spacing, alignment, colors and responsive presentation.

Basic HTML Table

<table>
    <thead>
        <tr>
            <th>Name</th>
            <th>Course</th>
            <th>Status</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>Aman</td>
            <td>CSS3</td>
            <td>Completed</td>
        </tr>
    </tbody>
</table>

Basic Table CSS

table {
    width: 100%;
    border-collapse: collapse;
}

th, td {
    border: 1px solid #ccc;
    padding: 12px;
    text-align: left;
}

th {
    background: #174ea6;
    color: white;
}

Important Table Properties

Property Purpose
border-collapse Controls whether adjacent cell borders collapse into a single border.
border-spacing Controls spacing between cell borders when borders are separate.
caption-side Positions the table caption.
empty-cells Controls display of borders and backgrounds on empty cells in separated-border tables.
table-layout Controls table column layout algorithm.
vertical-align Controls vertical alignment of inline-level content and table-cell content.

Zebra striping alternates row backgrounds to improve readability.

13. Responsive Tables

Wide tables can overflow on mobile screens. A common solution is to place the table inside a horizontally scrollable wrapper.

HTML

<div class="table-wrapper">
    <table>
        <!-- Table content -->
    </table>
</div>

CSS

.table-wrapper {
    width: 100%;
    overflow-x: auto;
}

.table-wrapper table {
    min-width: 600px;
}

Other Responsive Techniques

  • Reduce unnecessary columns.
  • Allow horizontal scrolling where appropriate.
  • Use readable text sizes.
  • Keep table headers meaningful.
  • Consider a card-based presentation for small screens when the data structure permits it.
Do not force all table content into a narrow screen if doing so makes it unreadable. Horizontal scrolling can be appropriate for genuinely tabular data.

15. Native Controls vs Custom Controls

Native Controls Custom Controls
Built-in keyboard behavior. Keyboard behavior must be implemented correctly.
Built-in accessibility semantics. Appropriate semantics and accessibility states must be provided.
Browser and operating system appearance may vary. More control over visual appearance.
Generally easier to maintain. Requires more testing and maintenance.

Prefer native controls unless a custom design or interaction genuinely requires additional implementation.

16. Common Mistakes and Debugging

Mistake Correct Practice
Using one generic selector for every input type without considering differences. Use appropriate type selectors and exclude checkbox and radio controls where necessary.
Removing outlines. Provide visible focus indicators.
Using buttons without a type inside a form. Specify button, submit or reset explicitly.
Using unrelated radio button names. Use a shared name for a single-choice group.
Making tables too wide for mobile. Use a responsive wrapper with horizontal scrolling when appropriate.
Using tables for page layout. Use Flexbox or Grid for layout; reserve tables for tabular data.
Ignoring label associations. Connect labels using matching for and id attributes.
Styling disabled buttons without disabling their behavior. Use the actual disabled attribute.

Debugging Checklist

  1. Inspect the input type and associated attributes.
  2. Check the selector specificity.
  3. Inspect computed width, padding and border values.
  4. Test keyboard focus indicators.
  5. Verify label and input associations.
  6. Test native validation.
  7. Check table overflow on narrow screens.
  8. Test in more than one browser.

17. Placement Interview Questions

Q1. How do you style an input field?

Answer: Use CSS properties such as width, padding, border, border-radius, background-color and font-size.

Q2. How do you select email inputs?

Answer: Use the attribute selector input[type="email"].

Q3. What is accent-color?

Answer: It specifies the accent color of supported native form controls, including checkboxes and radio buttons.

Q4. What is the purpose of textarea?

Answer: It collects multi-line text input.

Q5. What does resize: vertical do?

Answer: It allows a textarea or other supported resizable element to be resized vertically.

Q6. What is the difference between checkbox and radio button?

Answer: Checkboxes allow independent selections, while radio buttons in the same group allow one selected option.

Q7. What does border-collapse: collapse do?

Answer: It combines adjacent table cell borders into a shared border.

Q8. What is zebra striping?

Answer: It is alternating row background styling that improves table readability.

Q9. How do you make a table responsive?

Answer: Place the table inside a wrapper with overflow-x: auto and use suitable minimum table width where needed.

Q10. What is the difference between border-collapse and border-spacing?

Answer: border-collapse controls whether cell borders merge, while border-spacing controls spacing between cells when borders are separate.

Q11. Why should buttons have an explicit type?

Answer: A button inside a form defaults to submit behavior when no type is specified. Explicit types prevent unintended form submission.

Q12. Why should native controls be preferred?

Answer: They provide built-in semantics, keyboard interaction and accessibility behavior.

Q13. What is the difference between th and td?

Answer: th represents a header cell, while td represents a data cell.

Q14. What is the purpose of caption in a table?

Answer: It provides a title or description for the table.

Q15. Why should tables not be used for page layout?

Answer: Tables represent tabular relationships. Flexbox and Grid are more suitable for page layout and responsive design.

19. Lecture Summary

  • Attribute selectors can target specific input types.
  • Inputs, selects and textareas can share consistent styling.
  • accent-color customizes supported native controls.
  • Buttons should have explicit types.
  • Button states include hover, active, focus and disabled.
  • Tables should use semantic thead, tbody, th and td elements.
  • border-collapse controls table border behavior.
  • nth-child() supports alternating row styles.
  • overflow-x: auto helps handle wide tables on small screens.
  • Accessible labels and focus indicators are essential.
