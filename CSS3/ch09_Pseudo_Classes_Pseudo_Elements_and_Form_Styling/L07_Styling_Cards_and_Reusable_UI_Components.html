2. What Are Reusable UI Components?

A UI component is a self-contained interface element that performs a particular presentation or interaction role.

Reusable components share a common structure and styling. They can be used repeatedly across different pages and sections of an application.

Examples

  • Course cards.
  • Profile cards.
  • Product cards.
  • Dashboard widgets.
  • Navigation links.
  • Buttons.
  • Status badges.
  • Alert messages.

Why Reusability Matters

Benefit Explanation
Consistency Components share the same visual design.
Maintainability One CSS change can update many instances.
Efficiency Developers avoid rewriting the same styles.
Scalability New pages can reuse existing components.
Readability Meaningful class names make styles easier to understand.

4. Card Layout Using CSS Grid

CSS Grid is useful for arranging cards in responsive rows and columns.

HTML

<div class="card-grid">

    <article class="card">
        <h3>HTML5</h3>
        <p>Learn semantic HTML.</p>
    </article>

    <article class="card">
        <h3>CSS3</h3>
        <p>Learn modern styling.</p>
    </article>

    <article class="card">
        <h3>JavaScript</h3>
        <p>Learn programming for the web.</p>
    </article>

</div>

CSS

.card-grid {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(220px, 1fr));
    gap: 20px;
}
auto-fit creates as many tracks as fit and collapses empty repeated tracks. minmax() sets a minimum and maximum track size.

5. Styling Card Hover and Focus States

Interactive states provide feedback when users interact with components.

CSS

.card {
    transition:
        transform 0.2s ease,
        box-shadow 0.2s ease;
}

.card:hover {
    transform: translateY(-4px);
    box-shadow: 0 8px 18px rgba(0,0,0,0.12);
}

.card a:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 3px;
}

Important Properties

Property Purpose
transition Animates changes between property values.
transform Moves, rotates or scales an element.
box-shadow Creates a shadow around the component.
:hover Applies styles when a pointing device hovers over an element.
:focus-visible Provides a focus style when the browser determines it should be visible.
Do not make essential information available only on hover. Touchscreen users and keyboard users must also be able to access important content.

6. Reusable Button Components

A reusable button system can provide multiple visual variants using a shared base class.

HTML

<button class="btn btn-primary">
    Save
</button>

<button class="btn btn-secondary">
    Cancel
</button>

<button class="btn btn-danger">
    Delete
</button>

CSS

.btn {
    display: inline-block;
    padding: 10px 16px;
    border: none;
    border-radius: 5px;
    cursor: pointer;
    font: inherit;
    text-decoration: none;
}

.btn-primary {
    background: #174ea6;
    color: white;
}

.btn-secondary {
    background: #e5e7eb;
    color: #222;
}

.btn-danger {
    background: #b91c1c;
    color: white;
}

.btn:hover {
    filter: brightness(0.92);
}

.btn:focus-visible {
    outline: 3px solid #174ea6;
    outline-offset: 3px;
}

.btn:disabled {
    opacity: 0.5;
    cursor: not-allowed;
}

9. Using Pseudo-Elements in Components

Pseudo-elements can add decorative content without introducing additional markup.

Example: Required Field Indicator

.required-label::after {
    content: " *";
    color: #c62828;
}

Example: Featured Card Label

.featured-card {
    position: relative;
}

.featured-card::before {
    content: "FEATURED";
    position: absolute;
    top: 12px;
    right: 12px;
    padding: 4px 8px;
    background: #174ea6;
    color: white;
    font-size: 11px;
    border-radius: 4px;
}

Meaningful class names make stylesheets easier to understand and maintain.

11. Component Variants

A component can have different visual variants while retaining its common structure.

Example

.card {
    padding: 20px;
    border-radius: 10px;
    background: white;
}

.card--primary {
    border-top: 4px solid #174ea6;
}

.card--success {
    border-top: 4px solid #16834a;
}

.card--warning {
    border-top: 4px solid #e69b20;
}
Class Purpose
.card Base card component.
.card--primary Primary visual variant.
.card--success Success visual variant.
.card--warning Warning visual variant.

12. Responsive Component Layouts

Components should adapt to available screen space. Grid and Flexbox provide flexible layout systems.

Responsive Grid

.card-grid {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(220px, 1fr));
    gap: 20px;
}

Responsive Flexbox

.component-row {
    display: flex;
    flex-wrap: wrap;
    gap: 15px;
}

.component-item {
    flex: 1 1 220px;
}

Responsive Media Query

@media (max-width: 600px) {
    .component-row {
        flex-direction: column;
    }

    .course-card {
        width: 100%;
    }
}
Use Grid for two-dimensional card arrangements and Flexbox for one-dimensional component groups. Choose based on the layout requirement rather than using media queries automatically.

14. Common Mistakes and Debugging

Mistake Correct Practice
Repeating the same CSS for every card. Create a shared card class.
Using unclear class names. Use meaningful component names.
Adding too many unnecessary variants. Keep variants limited to real design requirements.
Using hover as the only interaction feedback. Provide focus-visible and other appropriate states.
Using fixed card widths everywhere. Use responsive Grid or Flexbox sizing.
Putting important text only in pseudo-elements. Keep meaningful content in HTML.
Using clickable div elements unnecessarily. Prefer semantic buttons and links.
Ignoring reduced-motion preferences. Respect prefers-reduced-motion for nonessential animation.

Reduced Motion Example

@media (prefers-reduced-motion: reduce) {
    .course-card {
        transition: none;
    }

    .course-card:hover {
        transform: none;
    }
}

Debugging Checklist

  1. Inspect shared component classes.
  2. Check whether variant classes override base styles correctly.
  3. Inspect Grid or Flexbox sizing.
  4. Test hover, active and focus-visible states.
  5. Check keyboard accessibility.
  6. Test components at narrow viewport widths.
  7. Verify that content remains readable without hover effects.
  8. Check for duplicate or conflicting CSS declarations.

15. Placement Interview Questions

Q1. What is a reusable UI component?

Answer: A reusable UI component is a consistently structured and styled interface element that can be used in multiple places.

Q2. What is a card component?

Answer: A card groups related information and actions inside a visually distinct container.

Q3. Why should CSS classes be reused?

Answer: Reusing classes improves consistency, reduces duplicated code and simplifies maintenance.

Q4. How do you create a responsive card grid?

Answer: Use CSS Grid with repeat(), auto-fit and minmax() to create columns that adapt to available space.

Q5. What is the difference between a base class and a modifier class?

Answer: A base class defines shared component styling. A modifier class changes a particular variant or state.

Q6. What is BEM?

Answer: BEM stands for Block, Element and Modifier. It is a CSS naming methodology that organizes component-related class names.

Q7. Why use semantic HTML for components?

Answer: Semantic elements communicate meaning and provide useful built-in browser and accessibility behavior.

Q8. How do you make a card interactive?

Answer: Use appropriate hover, focus-visible and active states, with links or buttons for actual actions.

Q9. What is the purpose of a status badge?

Answer: It displays short state information such as active, pending or completed.

Q10. Why should essential content not be placed only in ::before or ::after?

Answer: Generated content is not a reliable replacement for semantic HTML content and may not be exposed consistently to assistive technologies.

Q11. How can components be made responsive?

Answer: Use flexible sizing, Grid, Flexbox, suitable breakpoints and responsive typography.

Q12. What is the purpose of prefers-reduced-motion?

Answer: It detects a user's motion preference so unnecessary animation can be reduced or removed.
