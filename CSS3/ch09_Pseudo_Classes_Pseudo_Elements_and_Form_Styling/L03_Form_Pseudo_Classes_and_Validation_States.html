2. What Are Form Pseudo-Classes?

Form pseudo-classes select HTML form controls based on their current state or validation condition.

They allow developers to provide visual feedback without writing JavaScript for every styling change.

Syntax

input:pseudo-class {
    property: value;
}

Example

input:required {
    border-left: 3px solid blue;
}

input:disabled {
    background: #eee;
}
CSS pseudo-classes provide visual feedback. Actual form submission, server-side verification and business rules require appropriate HTML, JavaScript and backend handling.

3. :enabled and :disabled

These pseudo-classes select form controls according to whether they are enabled or disabled.

Pseudo-Class Meaning
:enabled Selects enabled form controls.
:disabled Selects disabled form controls.

Example

input:enabled {
    background: white;
}

input:disabled {
    background: #ddd;
    cursor: not-allowed;
}

Live Demonstration



Important Difference

  • An enabled control can normally receive user input.
  • A disabled control cannot normally be focused or edited.
  • Disabled controls are not submitted with the form.
  • Disabled controls are generally excluded from constraint validation.
The disabled attribute changes control behavior. A gray background alone does not disable a form control.

4. :required and :optional

These pseudo-classes select controls according to whether they have a required constraint.

Pseudo-Class Purpose
:required Selects controls with the required attribute.
:optional Selects supported controls without the required constraint.

Example

input:required {
    border-left: 4px solid #174ea6;
}

input:optional {
    border-left: 4px solid #888;
}

HTML

<form>

    <label for="name">Name</label>
    <input id="name" type="text" required>

    <label for="city">City</label>
    <input id="city" type="text">

</form>

Practical Applications

  • Indicating mandatory fields.
  • Separating optional fields visually.
  • Creating consistent form layouts.

5. :valid and :invalid

These pseudo-classes select form controls according to their constraint validation state.

Pseudo-Class Meaning
:valid Selects controls that satisfy their applicable validation constraints.
:invalid Selects controls that fail their applicable validation constraints.

Example

input:valid {
    border: 2px solid green;
}

input:invalid {
    border: 2px solid red;
}

HTML

<form>
    <label for="email">Email</label>

    <input
        type="email"
        id="email"
        required
        placeholder="name@example.com"
    >

    <button type="submit">Submit</button>
</form>

How It Works

  1. The required attribute makes the field mandatory.
  2. The email type applies email-format constraints.
  3. An empty required field is invalid.
  4. A non-empty value with an invalid email format is invalid.
  5. A value satisfying the applicable constraints matches :valid.
A browser's email input validation checks whether the value follows an acceptable email syntax. It does not prove that the email address exists or belongs to the user.

6. The :in-range and :out-of-range Pseudo-Classes

These pseudo-classes apply to controls with range constraints, such as number and date inputs.

Pseudo-Class Purpose
:in-range Selects a control whose value is within its applicable minimum and maximum constraints.
:out-of-range Selects a control whose value is outside its applicable range constraints.

Example

input:in-range {
    border: 2px solid green;
}

input:out-of-range {
    border: 2px solid red;
}

HTML

<label for="age">Age</label>

<input
    type="number"
    id="age"
    min="18"
    max="60"
    value="25"
>

Values from 18 to 60 satisfy the specified range. Values outside the range do not.

:in-range and :out-of-range are not substitutes for :valid and :invalid. A value outside the range is also generally invalid under constraint validation.

:checked selects checked checkboxes and selected radio buttons.

8. :placeholder-shown

:placeholder-shown selects an input or textarea while its placeholder text is displayed.

Example

input:placeholder-shown {
    background: #fffdf4;
}

input:not(:placeholder-shown) {
    background: #eef5ff;
}

HTML

<input
    type="text"
    placeholder="Enter your name"
>

Live Demonstration

When the placeholder is visible, the first rule applies. Entering a value normally causes the second rule to apply.

A placeholder is not a replacement for a visible label. It disappears when users enter text and may have insufficient contrast.

9. :read-only and :read-write

These pseudo-classes select elements according to whether their content is editable.

Pseudo-Class Meaning
:read-only Selects elements whose content is not editable by the user.
:read-write Selects elements whose content is editable by the user.

Example

input:read-only {
    background: #eee;
}

input:read-write {
    background: white;
}

HTML

<input type="text" value="Editable field">

<input
    type="text"
    value="Read only field"
    readonly
>

Difference Between readonly and disabled

readonly disabled
Value cannot be edited by the user. Control is disabled.
Can generally receive focus. Normally cannot receive focus.
Value is submitted with the form. Value is not submitted with the form.
Supported by text-like controls and certain other form controls. Supported by a broader range of form controls.

11. Combining Form Pseudo-Classes

Multiple pseudo-classes can be combined to select controls matching several conditions.

Example 1: Required and Invalid

input:required:invalid {
    border: 2px solid red;
}

Example 2: Enabled and Focused

input:enabled:focus {
    outline: 2px solid blue;
}

Example 3: Checked Checkbox

input[type="checkbox"]:checked {
    accent-color: green;
}

Example 4: Optional and Valid

input:optional:valid {
    background: #eef5ff;
}

Example 5: Disabled Button

button:disabled {
    opacity: 0.5;
    cursor: not-allowed;
}

12. CSS Validation vs HTML Validation vs JavaScript Validation

Technology Role
HTML validation Defines constraints using required, type, min, max, minlength and maxlength.
CSS validation Styles controls according to their validation state.
JavaScript validation Provides custom client-side validation logic and user feedback.
Server-side validation Verifies submitted data independently before processing or storing it.

HTML Example

<input
    type="text"
    minlength="3"
    maxlength="20"
    required
>

JavaScript Example

const form = document.querySelector("form");

form.addEventListener("submit", function(event) {
    if (!form.checkValidity()) {
        event.preventDefault();
        form.reportValidity();
    }
});
Browsers perform native constraint validation for applicable controls. JavaScript can customize the experience, but client-side validation must never replace server-side validation.

13. Common Mistakes and Debugging

Mistake Correct Understanding
Using :valid as proof that data is genuine. It only indicates that applicable browser validation constraints are satisfied.
Assuming :optional means a field is invalid. It only means the control does not have a required constraint.
Confusing readonly and disabled. Readonly values are submitted; disabled controls are normally excluded from submission.
Using placeholder instead of label. Provide a visible, associated label.
Assuming CSS validation prevents submission. CSS only styles the state; HTML constraint validation or application logic controls submission.
Using :out-of-range on a control without range constraints. Use appropriate min and max constraints on supported controls.

Debugging Checklist

  1. Inspect the input type.
  2. Check required, disabled and readonly attributes.
  3. Check min, max, minlength and maxlength.
  4. Inspect the current input value.
  5. Use browser Developer Tools to inspect matched CSS rules.
  6. Test the actual form submission behavior.

14. Placement Interview Questions

Q1. What are form pseudo-classes?

Answer: CSS pseudo-classes that select form controls based on states such as validity, selection, availability and editability.

Q2. What is the difference between :enabled and :disabled?

Answer: :enabled selects enabled controls, while :disabled selects disabled controls.

Q3. What does :required select?

Answer: Form controls that have the required constraint.

Q4. What does :optional select?

Answer: Applicable form controls that do not have the required constraint.

Q5. What is the difference between :valid and :invalid?

Answer: :valid selects controls satisfying their applicable constraints; :invalid selects controls failing them.

Q6. What is :in-range?

Answer: It selects supported controls whose values fall within their applicable minimum and maximum constraints.

Q7. What is :out-of-range?

Answer: It selects supported controls whose values fall outside their applicable range constraints.

Q8. What is :checked?

Answer: It selects checked checkboxes and selected radio buttons.

Q9. What is :placeholder-shown?

Answer: It selects an input or textarea while its placeholder is displayed.

Q10. What is the difference between readonly and disabled?

Answer: Readonly controls cannot be edited but are generally focusable and submitted. Disabled controls are normally not focusable and are excluded from form submission.

Q11. Does :valid guarantee that an email address exists?

Answer: No. It only indicates that the value satisfies the browser's applicable email input constraints.

Q12. Can CSS perform complete form validation?

Answer: No. CSS can style validation states. HTML provides native constraints, JavaScript can implement custom client-side logic, and the server must validate submitted data.

Q13. What does the required attribute do?

Answer: It makes a supported form control mandatory for native constraint validation.

Q14. Why is server-side validation important?

Answer: Client-side validation can be bypassed. Server-side validation independently checks data before accepting or processing it.

Q15. Does a disabled input submit its value?

Answer: No. Disabled form controls are normally excluded from form submission.
