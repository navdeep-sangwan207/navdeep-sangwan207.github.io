CSS3 Course | Chapter 1 | Lecture 06

Advanced Selectors and Selector Combinations

Learn how to combine CSS selectors, use logical selector functions and target complex HTML structures with maintainable CSS rules.

1. Learning Objectives

After completing this lecture, you will be able to:

  • Combine multiple CSS selector types.
  • Understand selector lists and complex selectors.
  • Use the :not() pseudo-class.
  • Use the :is() and :where() selector functions.
  • Understand the :has() relational pseudo-class.
  • Use selector lists inside logical functions.
  • Understand selector matching and specificity implications.
  • Write maintainable selectors for real-world interfaces.
  • Solve common selector-based coding problems.

2. Revising Basic Selector Types

CSS provides different selector types that can be combined to identify HTML elements precisely.

Selector Example Purpose
Element p Select elements by tag name
Class .card Select elements by class
ID #header Select an element by ID
Attribute input[required] Select elements by attributes
Descendant .card p Select nested elements
Child .card > p Select direct children
Adjacent sibling h2 + p Select immediate next sibling
General sibling h2 ~ p Select following siblings

Advanced selectors combine these patterns and add logical conditions for more precise targeting.

3. Combining Multiple Selector Types

A selector can combine element names, classes, IDs, attributes and combinators.

Example 1: Element and Class

p.highlight {
    color: red;
}

Selects paragraph elements having the highlight class.

Example 2: Multiple Classes

.card.featured {
    border: 2px solid blue;
}

Selects an element containing both classes.

Example 3: Class and Attribute

input.required-field[required] {
    border-color: red;
}

Selects input elements that have the required-field class and the required attribute.

Example 4: ID and Descendant

#login-form input {
    width: 100%;
}

Selects all input descendants of the login-form element.

Example 5: Multiple Combinators

.course-section > .course-list .course-card h3 {
    color: #174ea6;
}

Selects h3 elements inside course cards that are descendants of course-list, where course-list is inside a direct child of course-section.

4. Negation Pseudo-Class: :not()

The :not() pseudo-class selects elements that do not match the selector supplied inside its parentheses.

Syntax

selector:not(excluded-selector) {
    property: value;
}

Example 1: Excluding a Class

.button:not(.disabled) {
    cursor: pointer;
}

This selects buttons with the button class that do not have the disabled class.

HTML

<button class="button">Submit</button>

<button class="button disabled">Unavailable</button>

<button class="button">Continue</button>

Example 2: Excluding an Attribute

input:not([type="submit"]) {
    border: 1px solid #ccc;
}

Selects input elements whose type is not submit. An input without a type attribute also matches this selector.

Example 3: Excluding Multiple Conditions

.card:not(.featured, .disabled) {
    background: white;
}

Selects cards that have neither the featured class nor the disabled class.

Practical applications: Use :not() to style enabled buttons, exclude special cards, and apply default styles without affecting selected components.

5. :is() Selector Function

The :is() pseudo-class groups multiple selectors into one matching condition. It helps reduce repeated selector patterns.

Syntax

:is(selector1, selector2, selector3) {
    property: value;
}

Without :is()

header h1,
header h2,
header h3 {
    color: #174ea6;
}

With :is()

header :is(h1, h2, h3) {
    color: #174ea6;
}

Both approaches select h1, h2 and h3 elements inside a header.

Another Example

.card :is(h2, h3, p) {
    margin-bottom: 10px;
}

Selects h2, h3 and p descendants inside elements with the card class.

Practical Applications

  • Grouping multiple heading selectors.
  • Reducing repeated component selectors.
  • Applying common styles to different elements in a component.
Specificity note: The specificity of :is() is determined by the most specific selector in its argument list, not by the pseudo-class itself. Detailed calculations belong to Chapter 2.

6. :where() Selector Function

The :where() pseudo-class works like :is() for matching elements, but it always contributes zero specificity.

Syntax

:where(selector1, selector2) {
    property: value;
}

Example

:where(h1, h2, h3) {
    font-family: Arial, sans-serif;
    color: #174ea6;
}

This applies the declarations to all matching heading elements without adding selector specificity from the arguments.

Comparison: :is() and :where()

Feature :is() :where()
Matching behavior Groups selectors Groups selectors
Specificity Highest argument specificity Always zero
Use case Convenient selector grouping Low-specificity default styles

Practical Example

:where(.article, .blog-post) p {
    line-height: 1.7;
}

Paragraphs inside article and blog-post containers receive the same base styling with zero specificity contribution from the :where() function.

7. Relational Pseudo-Class: :has()

The :has() pseudo-class selects an element when it contains or is related to elements matching the selector inside its parentheses.

It is commonly described as a relational selector because it allows CSS to select an element based on its descendants or relative elements.

Syntax

parent:has(child-selector) {
    property: value;
}

Example 1: Card Containing an Image

.card:has(img) {
    border: 2px solid green;
}

Selects card elements that contain at least one image matching the selector.

HTML

<div class="card">
    <h2>Text Card</h2>
    <p>This card has no image.</p>
</div>

<div class="card">
    <img src="course.jpg" alt="Course">
    <h2>Image Card</h2>
</div>

Example 2: Form Containing an Invalid Input

.form-group:has(input:invalid) {
    border-left: 3px solid red;
}

Selects a form-group container that contains an input currently matching the :invalid pseudo-class.

Example 3: Navigation With a Submenu

.menu-item:has(.submenu) {
    position: relative;
}

Selects menu-item elements that contain a submenu descendant.

Practical applications: :has() can style cards based on their contents, form groups based on validation state and containers based on nested components.
Use :has() when it improves clarity. For simple reusable component states, a class controlled by the application may still be easier to understand and maintain.

8. Selector Lists Inside Logical Functions

Logical selector functions can be combined with combinators and other selectors to express more complex matching conditions.

Example 1: Grouping Headings Inside Multiple Containers

:is(.article, .blog, .documentation) :is(h1, h2, h3) {
    color: #174ea6;
}

Selects h1, h2 and h3 descendants inside article, blog or documentation containers.

Example 2: Excluding Special Buttons

button:not(.primary, .danger) {
    background: #e5e7eb;
    color: #222;
}

Selects buttons that do not have either the primary or danger class.

Example 3: Styling a Container Based on Its Contents

.course-card:has(:is(img, video)) {
    padding-top: 10px;
}

Selects course cards containing an image or video descendant.

Example 4: Combining :where() With Descendants

:where(.content, .sidebar) a {
    text-decoration: none;
}

Selects links inside either content or sidebar containers.

9. Practical Example: Advanced Course Cards

Complete HTML and CSS

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Advanced Selector Example</title>

    <style>
        * {
            box-sizing: border-box;
        }

        body {
            font-family: Arial, sans-serif;
            background: #f4f7fb;
            padding: 20px;
        }

        .course-grid {
            display: grid;
            grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
            gap: 15px;
        }

        .course-card {
            background: white;
            padding: 18px;
            border-radius: 10px;
            border: 1px solid #ddd;
        }

        .course-card:not(.disabled) {
            cursor: pointer;
        }

        .course-card.featured {
            border: 2px solid #174ea6;
        }

        .course-card :is(h2, h3) {
            color: #174ea6;
        }

        .course-card:has(img) {
            background: #eef5ff;
        }

        :where(.course-grid) > .course-card {
            min-width: 0;
        }

        .course-card.disabled {
            opacity: 0.5;
            cursor: not-allowed;
        }
    </style>
</head>

<body>

    <h1>Available Courses</h1>

    <div class="course-grid">

        <div class="course-card featured">
            <h2>C Programming</h2>
            <p>Learn programming fundamentals.</p>
        </div>

        <div class="course-card">
            <img src="course.jpg" alt="Course illustration"
                 width="100">
            <h2>CSS3</h2>
            <p>Learn modern website styling.</p>
        </div>

        <div class="course-card disabled">
            <h2>Advanced React</h2>
            <p>Coming soon.</p>
        </div>

    </div>

</body>
</html>

Expected Result

  • Course cards appear in a responsive grid.
  • The featured card receives a blue border.
  • Cards containing images receive a light-blue background.
  • Disabled cards appear faded.
  • Heading styles are shared through :is().
  • All cards receive consistent base styling.

10. Practical Example: Form Validation Styling

Complete HTML and CSS

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Form Selector Example</title>

    <style>
        body {
            font-family: Arial, sans-serif;
            background: #f4f7fb;
            padding: 20px;
        }

        .form-container {
            max-width: 450px;
            padding: 20px;
            background: white;
            border-radius: 10px;
        }

        .form-group {
            margin-bottom: 15px;
            padding: 8px;
        }

        .form-group:has(input:invalid) {
            border-left: 3px solid red;
        }

        .form-group:has(input:valid) {
            border-left: 3px solid green;
        }

        .form-group :is(input, textarea) {
            width: 100%;
            padding: 10px;
            margin-top: 6px;
        }

        .form-group input:not([type="submit"]) {
            border: 1px solid #aaa;
        }

        .submit-button {
            background: #174ea6;
            color: white;
            padding: 10px 20px;
            border: 0;
        }
    </style>
</head>

<body>

    <div class="form-container">

        <h2>Registration Form</h2>

        <div class="form-group">
            <label for="email">Email</label>
            <input id="email" type="email" required>
        </div>

        <div class="form-group">
            <label for="name">Name</label>
            <input id="name" type="text" required>
        </div>

        <button class="submit-button" type="button">
            Register
        </button>

    </div>

</body>
</html>

Expected Result

  • Form controls receive consistent styling.
  • Invalid required inputs cause their containing group to receive a red border.
  • Valid inputs cause their containing group to receive a green border.
  • Logical selectors reduce repeated CSS rules.

Note: A required empty field is invalid. An empty optional input may be valid, depending on its type and constraints.

11. Selector Specificity and Maintainability

Advanced selector functions can affect specificity differently. Understanding this helps prevent unexpected style conflicts.

Selector Specificity Contribution
:not(.active) Specificity of .active
:is(#main, .card) Highest specificity in the argument list
:where(#main, .card) Zero
.card:has(img) Class specificity plus argument specificity

For professional CSS:

  • Prefer readable selectors over unnecessarily complex chains.
  • Use reusable classes for component styling.
  • Use :where() for low-specificity defaults.
  • Use :is() when it reduces repeated selector lists.
  • Use :not() to express clear exclusions.
  • Use :has() when styling genuinely depends on nested content.
Specificity is only one part of the cascade. Origin, importance, cascade layers and source order also affect which declaration wins. Chapter 2 covers these rules in detail.

12. Browser Compatibility and Fallbacks

Modern selector functions are supported by current major browsers, but older browsers may not support every advanced selector. Check compatibility when supporting older environments.

Using @supports

.card {
    border: 1px solid #ccc;
}

/* Apply enhanced styling when :has() is supported */
@supports selector(.card:has(img)) {
    .card:has(img) {
        border-color: blue;
    }
}

The browser applies the enhanced rule only when it supports the selector feature being tested.

Fallback Strategy

  • Provide useful base styles that do not depend on advanced selectors.
  • Use classes when older browser support is required.
  • Test layouts in the browsers used by the target audience.
  • Use feature queries for optional enhancements.

13. Common Mistakes and Debugging

Mistake 1: Confusing :is() and :where()

/* Specificity comes from the most specific argument */
:is(#main, .card) p {
    color: blue;
}

/* :where() contributes zero specificity */
:where(#main, .card) p {
    color: blue;
}

Mistake 2: Incorrect Use of :not()

/* Excludes disabled buttons */
button:not(.disabled) {
    cursor: pointer;
}

This does not automatically disable a button's functionality. Use the HTML disabled attribute when a button must actually be disabled.

Mistake 3: Assuming :has() Selects the Child

/* Selects the card container */
.card:has(img) {
    border-color: green;
}

This styles the card itself, not the image inside it.

Mistake 4: Overcomplicated Selectors

body main section .container .card h2.title {
    color: blue;
}

A reusable class such as .card-title may be easier to maintain.

Mistake 5: Assuming Advanced Selectors Replace JavaScript

CSS selectors control styling and matching. They do not replace application logic, event handling, data validation or state management.

Debugging Procedure

  1. Inspect the target element in Developer Tools.
  2. Check the selector's matching conditions.
  3. Verify nested elements and attributes.
  4. Check whether a logical selector is supported.
  5. Inspect specificity and overridden declarations.
  6. Test a simpler selector to isolate the problem.

14. Placement Interview Questions and Answers

Q1. What is an advanced CSS selector?

An advanced selector combines basic selectors, combinators and pseudo-classes to target elements using more specific matching conditions.

Q2. What does :not() do?

It selects elements that do not match the selector supplied inside its parentheses.

Q3. What is the difference between :is() and :where()?

Both group selectors, but :is() takes the highest specificity among its arguments while :where() always contributes zero specificity.

Q4. What is :has() used for?

It selects an element based on whether it has a descendant or relative element matching the supplied selector.

Q5. Can :has() be used to style a parent based on its child?

Yes. For example, .card:has(img) selects cards containing an image.

Q6. What is the difference between :is() and selector grouping?

Both can reduce repeated selector patterns. :is() can be embedded inside a larger selector, while a selector list groups complete selectors separated by commas.

Q7. Does :not() add its own specificity?

No. Its specificity is determined by the most specific selector in its argument list.

Q8. Does :where() contribute specificity?

No. Its specificity is always zero, including the selectors inside its argument list.

Q9. How would you select cards that do not have a disabled class?

Use .card:not(.disabled).

Q10. How would you select headings inside multiple containers?

Use :is(.article, .blog) :is(h1, h2, h3).

Q11. How would you select a form group containing an invalid input?

Use .form-group:has(input:invalid).

Q12. Why should complex selectors be used carefully?

Overly complex selectors can make CSS harder to understand, debug and maintain. Reusable component classes are often clearer.

Q13. Can :has() be used with multiple conditions?

Yes. For example, .card:has(img, video) selects cards containing an image or video matching either selector.

Q14. What is the purpose of @supports selector()?

It allows CSS to apply enhanced rules conditionally when the browser supports a particular selector.

15. Practical Exercises

Exercise 1: Negation Selector

  • Create five buttons.
  • Give two buttons the disabled class.
  • Use :not() to style only the remaining buttons.

Exercise 2: :is() Selector

  • Create h1, h2 and h3 elements inside a card.
  • Use one :is() rule to style all three headings.
  • Compare it with a comma-separated selector list.

Exercise 3: :where() Selector

  • Create article and sidebar containers.
  • Use :where() to provide common paragraph styles.
  • Test how a more specific rule overrides the base style.

Exercise 4: :has() Selector

  • Create cards with and without images.
  • Use :has(img) to identify image-containing cards.
  • Apply a different border to matching cards.

Exercise 5: Combined Selectors

  • Create a registration form with multiple form groups.
  • Use :has(input:invalid) for invalid groups.
  • Use :is() to group form controls.
  • Use :not() to exclude submit buttons from input styling.

Build a course dashboard using advanced selectors. It must contain:

  • Featured and disabled course cards.

  • Headings grouped using :is().
