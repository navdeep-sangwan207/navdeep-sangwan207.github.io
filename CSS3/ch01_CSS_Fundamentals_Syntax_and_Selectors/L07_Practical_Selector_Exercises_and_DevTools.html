Practical Selector Exercises and DevTools

Apply CSS selectors to real frontend interfaces, inspect matching elements, debug styling problems and solve placement-oriented selector challenges.

1. Learning Objectives

After completing this lecture, you will be able to:

  • Apply CSS selectors to realistic HTML structures.
  • Combine element, class, ID and attribute selectors.
  • Use descendant, child and sibling combinators.
  • Apply pseudo-classes and pseudo-elements.
  • Use advanced selectors such as :not(), :is(), :where() and :has().
  • Inspect HTML elements using browser Developer Tools.
  • Identify why a CSS rule is not being applied.
  • Debug selector matching and specificity conflicts.
  • Complete practical frontend selector assignments.

2. Complete Selector Revision

Category Selector Purpose
Element p Select paragraph elements
Class .card Select elements with a class
ID #header Select an element by ID
Universal * Select all elements
Attribute input[required] Select by attribute
Descendant .card p Select nested paragraphs
Child .card > p Select direct child paragraphs
Adjacent sibling h2 + p Select immediate next paragraph
General sibling h2 ~ p Select following paragraph siblings

Pseudo-element p::first-line Style a portion of an element

3. Browser Developer Tools for CSS

Browser Developer Tools help frontend developers inspect HTML, test CSS rules and identify styling problems without repeatedly editing source files.

Opening Developer Tools

Method Action
Keyboard Press F12
Keyboard Press Ctrl + Shift + I
Context menu Right-click an element and select Inspect
Browser menu Open Developer Tools from browser settings

Important Developer Tools Panels

Panel Purpose
Elements Inspect and modify HTML structure
Styles Inspect matched CSS declarations
Computed View final computed CSS values
Console View errors and warnings
Network Inspect loaded CSS and other resources
Sources Inspect loaded source files

Inspecting a CSS Selector

  1. Open a webpage in Chrome or another browser.
  2. Right-click the element you want to inspect.
  3. Select Inspect.
  4. Locate the selected HTML element in the Elements panel.
  5. Inspect the matching rules in the Styles panel.
  6. Check whether a declaration is crossed out.
  7. Modify a property temporarily to test the result.
  8. Check the Computed panel for the final applied value.
Changes made directly in Developer Tools are temporary. They do not automatically update your original HTML or CSS file. Save permanent changes in your project source.

4. Practical Exercise 1: Course Card Selectors

Objective

Create a course card layout and apply different selectors to individual components.

HTML

<div class="course-container">

    <div class="course-card featured">
        <h2>C Programming</h2>
        <p class="description">
            Learn programming fundamentals.
        </p>
        <a href="#" class="course-link">Start Course</a>
    </div>

    <div class="course-card">
        <h2>CSS3</h2>
        <p class="description">
            Learn website styling.
        </p>
        <a href="#" class="course-link">Start Course</a>
    </div>

    <div class="course-card disabled">
        <h2>React.js</h2>
        <p class="description">
            Coming soon.
        </p>
        <a href="#" class="course-link">Unavailable</a>
    </div>

</div>

CSS

.course-container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}

.course-card {
    padding: 20px;
    border: 1px solid #ddd;
    border-radius: 10px;
    background: white;
}

.course-card.featured {
    border: 2px solid #174ea6;
}

.course-card h2 {
    color: #174ea6;
}

.course-card .description {
    color: #555;
}

.course-card:not(.disabled) {
    cursor: pointer;
}

.course-card.disabled {
    opacity: 0.5;
}

.course-card > .course-link {
    display: inline-block;
    margin-top: 10px;
    text-decoration: none;
}

.course-card h2 + p {
    margin-top: 5px;
}

Expected Result

  • Three course cards appear in a grid.
  • The featured card receives a blue border.
  • Course headings use the same color.
  • Disabled cards appear faded.
  • Course links are styled consistently.

Practice Questions

  1. How would you select only the featured course card?
  2. How would you select all paragraphs inside course cards?
  3. How would you select direct children of the course container?
  4. How would you exclude disabled cards?

6. Practical Exercise 3: Registration Form

HTML

<form class="registration-form">

    <div class="form-group">
        <label for="username">Username</label>
        <input id="username" type="text" required>
    </div>

    <div class="form-group">
        <label for="email">Email</label>
        <input id="email" type="email" required>
    </div>

    <div class="form-group">
        <label for="password">Password</label>
        <input id="password" type="password" required>
    </div>

    <button type="submit">Register</button>

</form>

CSS

.registration-form {
    max-width: 450px;
    padding: 20px;
    background: white;
}

.registration-form .form-group {
    margin-bottom: 15px;
}

.registration-form label {
    display: block;
    margin-bottom: 5px;
}

.registration-form input[required] {
    width: 100%;
    padding: 10px;
    border: 1px solid #aaa;
}

.registration-form input:focus {
    outline: 2px solid #007bff;
}

.registration-form input:invalid {
    border-color: red;
}

.registration-form input:valid {
    border-color: green;
}

.registration-form button:hover {
    background: #007bff;
    color: white;
}

.registration-form button:not(:disabled) {
    cursor: pointer;
}

Expected Result

  • Required fields receive consistent styling.
  • Focused fields display a visible outline.
  • Invalid values receive a red border.
  • Valid values receive a green border.
  • The button changes appearance on hover.
Browser validation depends on the input type and constraints. For example, an email input must contain a valid email format to match :valid when required.

7. Practical Exercise 4: Attribute Selectors

HTML

<div class="document-list">

    <a href="notes.pdf">Download Notes</a>

    <a href="https://example.com">External Website</a>

    <a href="chapter.html">Open Chapter</a>

    <input type="text" placeholder="Username">

    <input type="email" placeholder="Email">

</div>

CSS

/* Links ending in .pdf */
a[href$=".pdf"] {
    color: red;
}

/* Links beginning with https */
a[href^="https"] {
    color: green;
}

/* Elements having a placeholder */
input[placeholder] {
    padding: 10px;
}

/* Exact attribute value */
input[type="email"] {
    border: 2px solid blue;
}

/* Attribute value containing a word */
a[href*="chapter"] {
    font-weight: bold;
}

Exercise Tasks

  1. Style links that end with .pdf.
  2. Style external HTTPS links differently.
  3. Apply common styling to all inputs with placeholders.
  4. Style email inputs separately.
  5. Use attribute selectors to target links containing a particular word.

8. Practical Exercise 5: Advanced Selectors

HTML

<div class="product-list">

    <div class="product-card featured">
        <h2>Laptop</h2>
        <img src="laptop.jpg" alt="Laptop">
        <p>Available</p>
    </div>

    <div class="product-card">
        <h2>Keyboard</h2>
        <p>Available</p>
    </div>

    <div class="product-card disabled">
        <h2>Monitor</h2>
        <p>Unavailable</p>
    </div>

</div>

CSS

/* All product cards */
.product-card {
    padding: 20px;
    border: 1px solid #ddd;
}

/* Exclude disabled products */
.product-card:not(.disabled) {
    cursor: pointer;
}

/* Group heading elements */
.product-card :is(h2, h3) {
    color: #174ea6;
}

/* Select products containing images */
.product-card:has(img) {
    background: #eef5ff;
}

/* Low-specificity base styles */
:where(.product-list) {
    display: grid;
    gap: 15px;
}

Expected Result

  • All products receive a common border and padding.
  • Disabled products are excluded from the cursor rule.
  • Headings receive a common color.
  • Products containing images receive a different background.

9. CSS Debugging Using Developer Tools

Consider the following HTML and CSS.

HTML

<div class="card">
    <h2>Course Name</h2>
    <p class="description">Course details</p>
</div>

CSS With a Mistake

.card .title {
    color: blue;
}

.card > .description {
    color: green;
}

Problem

The heading does not turn blue because the HTML heading does not have a title class.

Correct CSS

.card h2 {
    color: blue;
}

.card > .description {
    color: green;
}

Debugging Steps

  1. Inspect the heading element.
  2. Check its actual class and tag name.
  3. Compare the HTML structure with the selector.
  4. Verify whether the selector matches the element.
  5. Correct the selector or HTML structure.

10. Common CSS Selector Problems

Problem Possible Cause Solution
Style not applied Incorrect selector Verify HTML tags and classes
Wrong elements styled Using descendant instead of child selector Check combinator usage
Rule crossed out Cascade conflict Inspect computed styles and cascade
Hover not working Incorrect pseudo-class or overlay Inspect the element and its state
Attribute selector not matching Incorrect attribute or value Inspect the actual HTML attribute
Advanced selector not working Browser compatibility issue Check support and test a fallback
CSS file not loading Incorrect stylesheet path Inspect Network panel and file path

14. Interview Questions and Answers

Q1. What is CSS selector matching?

Selector matching is the process by which the browser determines which HTML elements satisfy a CSS selector.

Q2. What is the difference between the Styles and Computed panels?

Styles displays CSS declarations and their cascade status. Computed displays the final calculated property values for the selected element.

Q3. How do you inspect a CSS element in Chrome?

Right-click the element, select Inspect and examine its HTML and CSS in the Elements panel.

Q4. Why might a CSS declaration appear crossed out?

It may be overridden by another declaration with higher cascade precedence or may not apply in the current context.

Q5. What is the difference between a class and an ID selector?

A class can be reused on multiple elements. An ID is intended to identify one unique element within a document.

Q6. How do you select all input elements except submit inputs?

Use input:not([type="submit"]).

Q7. How do you select a card containing an image?

Use .card:has(img).

Q8. How can you test a hover state in Developer Tools?

Inspect the element and use the browser's force-state controls to activate :hover.

Q9. Why should developers avoid overly complex selectors?

They can make styles difficult to maintain, debug and reuse.

Q10. How can you find out whether a stylesheet has loaded?

Inspect the Network panel and check the CSS resource request, response status and loaded content.

Q11. How do you identify the CSS rule responsible for a property?

Select the element, inspect the Styles panel and then verify the final value in the Computed panel.

Q12. What is the purpose of the Console panel?

It displays JavaScript errors, warnings and other diagnostic messages that help investigate application problems.
