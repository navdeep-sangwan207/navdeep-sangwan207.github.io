CSS Specificity and Specificity Calculation

Learn how browsers compare CSS selectors, calculate specificity and resolve competing style declarations.

1. Learning Objectives

  • Understand CSS selector specificity.
  • Learn the specificity hierarchy.
  • Calculate specificity using the ID-class-type model.
  • Compare selectors with different specificity values.
  • Understand compound and complex selector specificity.
  • Understand pseudo-class and pseudo-element specificity.
  • Learn the specificity behavior of :is(), :where(), :not() and :has().
  • Identify common specificity mistakes.
  • Solve CSS specificity interview questions.

2. What Is CSS Specificity?

CSS specificity is the selector-priority calculation used by the browser when competing declarations have reached the specificity stage of the cascade.

If two declarations target the same property and have equal priority in earlier cascade stages, the selector with higher specificity wins.

Example

p {
    color: red;
}

.text {
    color: blue;
}

#heading {
    color: green;
}

HTML:

<p id="heading" class="text">
    Welcome to CSS
</p>

All three selectors match the paragraph. The ID selector has the highest specificity among these three.

Expected result: Green text.

3. CSS Specificity Hierarchy

A commonly used specificity model represents selector weight using three main components:

  • ID selectors.
  • Class, attribute and pseudo-class selectors.
  • Type and pseudo-element selectors.
Selector category Specificity contribution Examples
ID selector 0, 1, 0, 0 #header
Class selector 0, 0, 1, 0 .container
Attribute selector 0, 0, 1, 0 [type="text"]
Pseudo-class 0, 0, 1, 0 :hover, :focus
Element selector 0, 0, 0, 1 div, p, h1
Pseudo-element 0, 0, 0, 1 ::before, ::after
The four-part notation is often written as (inline, ID, class/attribute/pseudo-class, type/pseudo-element). This is a comparison model, not a decimal number.

4. Universal Selector and Combinators

Universal Selector

* {
    color: black;
}

The universal selector (*) contributes zero specificity.

Combinators

div p {
    color: blue;
}

div > p {
    color: green;
}

h2 + p {
    color: red;
}

h2 ~ p {
    color: purple;
}

Descendant, child, adjacent sibling and general sibling combinators do not add specificity themselves.

Specificity is calculated from the selectors on either side of the combinators.

Spaces, greater-than signs, plus signs and tilde signs do not contribute specificity.

5. Specificity Calculation

Count the selectors in each category and compare the resulting tuple from left to right.

Example 1: Element Selector

p {
    color: red;
}

Specificity: (0, 0, 0, 1)

Example 2: Class Selector

.message {
    color: blue;
}

Specificity: (0, 0, 1, 0)

Example 3: ID Selector

#header {
    color: green;
}

Specificity: (0, 1, 0, 0)

Example 4: Combined Selectors

#main .card p {
    color: red;
}

Calculation:

  • One ID selector: 1
  • One class selector: 1
  • One element selector: 1

Specificity: (0, 1, 1, 1)

Example 5: Multiple Classes

.card.active.highlight {
    background: blue;
}

Calculation:

  • Three class selectors.
  • No IDs.
  • No element selectors.

Specificity: (0, 0, 3, 0)

6. Comparing Specificity Values

Specificity is compared column by column from left to right. A higher value in an earlier column takes priority over any number of values in later columns.

Example 1

#main {
    color: red;
}

.card.active {
    color: blue;
}
Selector Specificity
#main (0, 1, 0, 0)
.card.active (0, 0, 2, 0)

The ID selector wins because its ID column is higher.

Example 2: More Classes Do Not Beat an ID

#main {
    color: red;
}

.a.b.c.d.e.f {
    color: blue;
}

The ID selector still wins. Six class selectors do not outweigh one ID selector.

Do not treat specificity as an ordinary decimal number. For example, a large number of classes does not carry into the ID column.

7. Attribute Selectors and Pseudo-Classes

Attribute Selectors

input[type="text"] {
    border: 1px solid blue;
}

The selector contains one element selector and one attribute selector.

Specificity: (0, 0, 1, 1)

Pseudo-Classes

button:hover {
    background: blue;
}

input:focus {
    border-color: green;
}

li:first-child {
    font-weight: bold;
}

Each pseudo-class contributes to the class/attribute/ pseudo-class column.

Combined Example

form input[type="email"]:focus {
    border-color: blue;
}

Calculation:

  • form: one element.
  • input: one element.
  • [type="email"]: one attribute selector.
  • :focus: one pseudo-class.

Specificity: (0, 0, 2, 2)

8. Pseudo-Elements and Their Specificity

Pseudo-elements target a particular part of an element or generate content associated with it. 

p::before {
    content: "Note: ";
    color: blue;
}

p::first-letter {
    font-size: 30px;
}

.card::after {
    content: "";
    display: block;
}

A pseudo-element contributes one type-selector unit.

Selector Specificity
p::before (0, 0, 0, 2)
.card::after (0, 0, 1, 1)
#main::first-letter (0, 1, 0, 1)

9. Special Selector Functions

Some modern CSS selector functions have special specificity rules. These are frequently tested in frontend interviews.

1. :is()

The specificity of :is() is the specificity of the most specific selector in its argument list. 

:is(.card, #main) p {
    color: blue;
}

The highest argument specificity is from #main. The p selector also contributes one type unit.

Specificity: (0, 1, 0, 1)

2. :not()

:not() itself adds no specificity. Its most specific argument contributes to the calculation. 

p:not(.active) {
    color: red;
}

Specificity: (0, 0, 1, 1)

3. :has()

:has() takes the specificity of the most specific selector in its argument list. 

.card:has(#featured) {
    border: 2px solid blue;
}

Specificity: (0, 1, 1, 0)

4. :where()

:where() and all its arguments contribute zero specificity. 

:where(#main, .card) p {
    color: green;
}

Only the p element contributes to specificity.

Specificity: (0, 0, 0, 1)

Interview distinction: :is(), :not() and :has() use the most specific argument. :where() always contributes zero specificity.

10. The :nth-child() Specificity Rule

:nth-child() is a pseudo-class and contributes one class-level unit. If it uses an of-selector list, the most specific selector in that list also contributes. 

li:nth-child(2) {
    color: red;
}

Specificity: (0, 0, 1, 1)

Using an of-selector List

li:nth-child(2 of .item, #featured) {
    color: blue;
}

The pseudo-class contributes one class-level unit. The most specific selector in the of-list is #featured. The li element contributes one type unit.

Specificity: (0, 1, 1, 1)

11. Inline Styles and Specificity

Inline style declarations are commonly represented as (1, 0, 0, 0) in the four-part specificity comparison model. 

<p id="message" class="text"
   style="color: red;">
    Hello CSS
</p>

The inline declaration normally outranks normal author stylesheet declarations.

Inline styles are not a universal highest-priority rule. The origin and importance stages of the cascade are evaluated before specificity. Important declarations can change the result.

The complete !important and origin rules are covered in Lecture 5.

12. Practical Example: Course Card Styling

Consider a course card in a learning portal.

HTML

<div id="course" class="card featured">
    <h2 class="title">CSS3 Course</h2>
    <p>Learn responsive web design.</p>
</div>

CSS

h2 {
    color: black;
}

.title {
    color: blue;
}

.card .title {
    color: green;
}

#course .title {
    color: red;
}

Specificity comparison:

Selector Specificity
h2 (0, 0, 0, 1)
.title (0, 0, 1, 0)
.card .title (0, 0, 2, 0)
#course .title (0, 1, 1, 0)

The #course .title selector wins because it has one ID and one class.

Expected result: The course title is red.

13. Common Specificity Mistakes

Mistake Correct understanding
Counting combinators Combinators contribute zero specificity.
Counting * as an element The universal selector contributes zero.
Assuming many classes beat one ID The ID column is compared first.
Counting :not() as a pseudo-class unit Its argument contributes specificity.
Counting :where() arguments :where() and its arguments contribute zero.
Ignoring cascade layers Layer precedence is resolved before specificity.
Assuming specificity decides every conflict Earlier cascade factors may decide first.

14. Placement-Oriented Specificity Problems

Problem 1

p {
    color: red;
}

.text {
    color: blue;
}

Question: Which selector has higher specificity?

Answer: .text.

Problem 2

#box {
    color: red;
}

.container .item .title .text {
    color: blue;
}

Question: Which selector wins?

Answer: #box, because an ID selector outranks any number of class selectors.

Problem 3

div.card {
    color: red;
}

.card {
    color: blue;
}

Answer: div.card wins. Its specificity is (0, 0, 1, 1), compared with (0, 0, 1, 0).

Problem 4

:is(.card, #main) p {
    color: red;
}

.card p {
    color: blue;
}

Answer: The first selector wins. Its specificity is (0, 1, 0, 1), while the second is (0, 0, 1, 1).

Problem 5

:where(#main, .card) p {
    color: red;
}

.card p {
    color: blue;
}

Answer: .card p wins because :where() contributes zero specificity.

15. Interview Questions and Answers

Q1. What is CSS specificity?

It is the selector-priority calculation used to resolve competing declarations at the specificity stage of the cascade.

Q2. Which selector has higher specificity: ID or class?

An ID selector has higher specificity.

Q3. Do combinators affect specificity?

No. Combinators do not contribute specificity.

Q4. Does the universal selector have specificity?

No. The universal selector contributes zero.

Q5. What is the specificity of an attribute selector?

It contributes one class-level unit.

Q6. What is the specificity of a pseudo-class?

It normally contributes one class-level unit.

Q7. What is the difference between :is() and :where()?

:is() uses the most specific argument for its specificity. :where() always contributes zero specificity.

Q8. Does :not() contribute specificity?

The :not() pseudo-class itself does not add a unit. Its most specific argument contributes.

Q9. Can multiple classes beat one ID selector?

No, not under the standard specificity comparison.

Q10. What is the specificity of #main .card p?

(0, 1, 1, 1).

Q11. Does inline CSS always win?

No. Cascade origin and importance can override normal inline author declarations.

Q12. What should you check before comparing specificity?

Check whether the declarations are relevant and compare their origin, importance and cascade layer precedence first.

17. Lecture Summary

  • Specificity compares selectors competing for the same property.
  • ID selectors outrank class and type selectors.
  • Class, attribute and pseudo-class selectors share a category.
  • Element and pseudo-element selectors share a category.
  • Universal selectors and combinators add zero specificity.
  • :is(), :not() and :has() use their most specific argument.
  • :where() contributes zero specificity.
  • Specificity is compared from left to right.
  • Cascade priority is evaluated before specificity.
Placement takeaway: Practice calculating specificity without treating it as a decimal number. Always evaluate cascade priority before comparing selector weights.
