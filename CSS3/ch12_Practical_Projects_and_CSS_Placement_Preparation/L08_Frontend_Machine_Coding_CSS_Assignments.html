Lecture 8: Frontend Machine Coding CSS Assignments

Practice practical frontend layout tasks commonly used in fresher technical interviews, machine-coding rounds and frontend development assessments.

1. Learning Objectives

  • Understand frontend machine-coding assignments.
  • Convert a visual or written requirement into HTML and CSS.
  • Select Flexbox or Grid based on layout requirements.
  • Build common UI components independently.
  • Use responsive CSS without unnecessary breakpoints.
  • Debug layout and sizing problems efficiently.
  • Write maintainable and accessible CSS.
  • Complete assignments within a time limit.
  • Explain implementation decisions during an interview.

2. What Is a Frontend Machine-Coding Round?

A frontend machine-coding round evaluates whether a candidate can translate requirements into a working user interface using HTML, CSS and sometimes JavaScript.

Typical evaluation areas include:

  • HTML structure and semantic elements.
  • CSS layout and positioning.
  • Responsive behavior.
  • Visual accuracy and spacing.
  • Component reusability.
  • Accessibility and usability.
  • Code organization and debugging.
  • Ability to explain technical decisions.
The objective is not merely to make a page look correct at one screen size. The implementation should remain usable, understandable and maintainable.

3. A Practical Approach to Solving Assignments

Step 1: Understand the requirement

Identify the main components, their relationships, expected behavior and responsive requirements.

Step 2: Divide the interface into sections

For example, a dashboard may contain a header, sidebar, main content area, cards and a data table.

Step 3: Write semantic HTML

Use elements such as header, nav, main, section, article and footer where appropriate.

Step 4: Select the layout technique

Requirement Recommended CSS
Horizontal navigation Flexbox
Equal-width card collection CSS Grid
Sidebar and main content Grid or Flexbox
Center an item in two directions Flexbox or Grid
Overlapping badge or icon Positioning
Responsive image max-width and height

Step 5: Apply responsive behavior

Start with a usable narrow-screen layout, then enhance it for wider screens. Use content-driven breakpoints rather than choosing device names without considering the actual layout.

Step 6: Test and refine

Check spacing, alignment, text wrapping, overflow, keyboard focus and browser console errors.

4. Assignment 1 – Center a Card

Difficulty: Easy

Problem statement

Create a card positioned at the center of the viewport, both horizontally and vertically.

Requirements

  • Use the full viewport height.
  • Center the card in both directions.
  • Give the card a maximum width.
  • Maintain spacing on narrow screens.
  • Prevent the card from exceeding the viewport width.

Solution

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Centered Card</title>

    <style>
        * {
            box-sizing: border-box;
        }

        body {
            margin: 0;
            min-height: 100vh;
            display: grid;
            place-items: center;
            padding: 20px;
            font-family: Arial, sans-serif;
            background: #eef2f7;
        }

        .card {
            width: min(100%, 380px);
            padding: 28px;
            background: white;
            border-radius: 12px;
            box-shadow: 0 8px 25px
                rgba(0, 0, 0, 0.1);
            text-align: center;
        }

        .card h2 {
            color: #174ea6;
        }

        .card button {
            padding: 10px 20px;
            border: 0;
            border-radius: 6px;
            color: white;
            background: #174ea6;
            cursor: pointer;
        }

        .card button:focus-visible {
            outline: 3px solid #007bff;
            outline-offset: 3px;
        }
    </style>
</head>

<body>

    <main class="card">
        <h2>Welcome</h2>
        <p>This card is centered using CSS Grid.</p>
        <button type="button">Continue</button>
    </main>

</body>
</html>

Expected result

A white card appears at the center of the available viewport, with a heading, description and button.

Important CSS concepts

  • min-height: 100vh gives the body at least viewport height.
  • display: grid creates a grid container.
  • place-items: center centers the grid item on both axes.
  • width: min(100%, 380px) prevents excessive width.

7. Assignment 4 – Two-Column Layout

Difficulty: Intermediate

Create a layout with a main article area and a sidebar. On narrow screens, stack the sidebar below the article.

Solution

15. Common Mistakes in Machine-Coding Rounds

Mistake Better Approach
Using fixed widths everywhere. Use fluid sizing, max-width and minmax().
Using absolute positioning for the entire layout. Use Grid or Flexbox for primary structure.
Ignoring mobile screens. Test narrow and wide viewport sizes.
Duplicating CSS rules. Create reusable component classes.
Using div for every element. Use semantic HTML where appropriate.
Removing focus outlines. Provide visible keyboard focus styles.
Hiding layout overflow without investigation. Find the element causing the overflow.
Using too many arbitrary breakpoints. Choose breakpoints based on content needs.
Testing only one browser width. Test multiple viewport sizes.

16. Browser Developer Tools for Layout Debugging

Browser Developer Tools are essential during a machine-coding round.

  1. Open the page in the browser.
  2. Press F12 to open Developer Tools.
  3. Select an element using the element inspector.
  4. Inspect its computed width, height, margin and padding.
  5. Check the active Flexbox or Grid layout.
  6. Toggle CSS declarations to test changes.
  7. Use responsive device mode to test viewport sizes.
  8. Check Console and Network panels for errors.

Useful debugging questions

  • Is the parent element a Flexbox or Grid container?
  • Is the child constrained by min-width or max-width?
  • Is the content wider than its grid track?
  • Is the element affected by margin collapse?
  • Is a stacking context affecting z-index?
  • Is the media query actually matching the viewport?

17. Machine-Coding Interview Questions

Q1. When would you use Flexbox instead of Grid?

Use Flexbox primarily for one-dimensional alignment along a row or column. Use Grid when controlling rows and columns together is important.

Q2. How do you center an element horizontally and vertically?

One common approach is a Grid container with place-items: center. Flexbox with justify-content and align-items is another option.

Q3. What is the purpose of minmax()?

It defines a minimum and maximum size for a Grid track, allowing flexible track sizing.

Q4. What is the difference between auto-fit and auto-fill?

Both create repeated Grid tracks. Auto-fill retains empty tracks, while auto-fit collapses empty tracks after item placement.

Q5. Why use box-sizing: border-box?

It makes declared width and height include padding and borders, simplifying element size calculations.

Q6. How do you prevent a Grid or Flexbox child from forcing its container wider?

Check intrinsic content sizing and consider min-width: 0 on the relevant item. Also handle long unbreakable content appropriately.

Q7. How do you make images responsive?

A common rule is max-width: 100%; height: auto;. Use object-fit when controlling how an image fills a fixed-size box.

Q8. How do you debug horizontal overflow?

Inspect elements wider than their containing block, check fixed widths and long content, and examine Grid and Flexbox minimum sizing.

Q9. What is the difference between display: none and visibility: hidden?

display: none removes the element from layout. visibility: hidden hides it while preserving its layout space.

Q10. Why should you avoid using only hover effects?

Touchscreen users may not have hover behavior. Interactive controls should also provide appropriate focus and activation behavior.

  • HTML is valid and semantic.
  • CSS is organized and reusable.
  • Layout works at different viewport sizes.
  • No unintended horizontal overflow.
  • Spacing and alignment are consistent.
  • Keyboard focus is visible.
  • Images have appropriate alternative text.
  • Implementation decisions can be explained.

19. Final Practice Challenge

Build a Responsive Learning Portal Interface.

Required components:

  • Header with logo and navigation.
  • Hero section with a call-to-action.
  • Four course cards.
  • Two-column information section.
  • Student testimonial card.
  • Contact form layout.
  • Footer with useful links.

Technical requirements:

  • Use Flexbox for navigation and aligned content.
  • Use Grid for card collections.
  • Use CSS variables for theme colors.
  • Use responsive sizing and media queries.
  • Use semantic HTML and accessible focus styles.
  • Keep the CSS in an external stylesheet.

Suggested practice time: 60–90 minutes. Evaluate layout, responsiveness, code quality and accessibility.

20. Key Takeaways

  • Understand requirements before writing code.
  • Use semantic HTML for clear document structure.
  • Select Flexbox or Grid based on layout needs.
  • Use responsive sizing instead of fixed dimensions everywhere.
  • Build reusable components and consistent spacing.
  • Use Developer Tools to inspect and debug layout behavior.
  • Test keyboard usability and multiple viewport sizes.
  • Practice explaining your CSS decisions.
