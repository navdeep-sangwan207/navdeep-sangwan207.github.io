Lecture 7: Project – Multi-Page Responsive Website

Build a structured website containing multiple HTML pages with shared navigation, reusable CSS, consistent layouts and correctly managed relative paths.

1. Project Objectives

A multi-page website contains separate HTML documents connected through navigation links. Unlike a single-page website, each major page can have its own URL and content.

  • Plan a practical multi-page website structure.
  • Create multiple independent HTML documents.
  • Build a shared header, navigation and footer.
  • Reuse a common external stylesheet.
  • Understand absolute, relative and root-relative paths.
  • Maintain consistent typography, colors and spacing.
  • Identify the active navigation page.
  • Make each page responsive.
  • Debug broken links and missing CSS files.
  • Organize files for deployment on GitHub Pages.

2. Understand the Website Requirements

For this project, build a small technology learning website with the following pages:

Page Purpose Filename
Home Introduction and featured content. index.html
About Website information and purpose. about.html
Courses Display available learning courses. courses.html
Contact Contact details and enquiry form. contact.html

3. Recommended Folder Structure

│
├── index.html
├── about.html
├── courses.html
├── contact.html
│
├── css/
│   └── style.css
│
├── images/
│   ├── hero.jpg
│   ├── course-1.jpg
│   └── course-2.jpg
│
└── assets/
    └── resume.pdf

Keep the main HTML pages together at the project root. Place reusable CSS, images and downloadable documents in separate folders.

For a GitHub Pages project, paths are case-sensitive on the published site. A link to About.html is not necessarily equivalent to about.html.

4. Understand Relative File Paths

Relative paths are evaluated from the location of the current HTML document, not from the location of the website's homepage.

Common path patterns

Path Meaning
about.html File in the current directory.
css/style.css CSS file inside a child directory.
../index.html Move up one directory, then open index.html.
../../style.css Move up two directories, then find style.css.
images/hero.jpg Image inside the current directory's images folder.

Example

project/
│
├── index.html
├── about.html
│
└── pages/
    └── services.html

From pages/services.html:

<a href="../index.html">Home</a>
<a href="../about.html">About</a>

Both links move one directory upward before locating the target file.

Root-relative paths

<link rel="stylesheet" href="/css/style.css">

A path beginning with / starts from the website origin. On a GitHub Pages project site hosted under a repository subpath, such a path may point to the wrong location. Relative paths or an appropriately configured base path are often safer for portable projects.

11. How Shared CSS Works

Each HTML document contains the same stylesheet reference: 

<link rel="stylesheet" href="css/style.css">

When the browser loads a page, it requests the stylesheet using that page's relative URL. The same CSS rules can therefore style all pages.

Benefits of a shared stylesheet

  • Consistent visual design.
  • Less duplicated CSS.
  • Faster global design changes.
  • Easier debugging and maintenance.
  • Clear separation between structure and presentation.

12. Reusable Components and CSS Architecture

Common visual elements should use reusable classes. For example, the same .card class can style cards on both the Home and Courses pages. 

/* Shared component */

.card {
    padding: 22px;
    background: white;
    border: 1px solid #e1e8f0;
    border-radius: 9px;
}

/* Shared layout */

.card-grid {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(230px, 1fr));
    gap: 22px;
}

Prefer reusable component classes over copying slightly different declarations into every page. Add page-specific classes only when a page genuinely needs different styling.

13. Navigation and Active Page Indication

The navigation should show which page the visitor is currently viewing. Use aria-current="page" on exactly the current page link. 

<!-- On about.html -->

<a href="about.html" aria-current="page">
    About
</a>

Style the current link:

.nav-links a[aria-current="page"] {
    color: #007bff;
    text-decoration: underline;
    text-underline-offset: 5px;
}
A navigation link should normally be an anchor element because it navigates to another resource. Use a button for an action such as opening a menu or submitting a form.

14. Responsive Design Strategy

The shared stylesheet uses a mobile-friendly layout and adjusts the navigation and page spacing at smaller viewport widths. 

@media (max-width: 760px) {

    .navbar {
        flex-direction: column;
    }

    .nav-links {
        justify-content: center;
        gap: 12px 18px;
    }

    .container {
        padding: 30px 18px;
    }
}

The cards use Grid with auto-fit and minmax(), allowing the number of columns to adapt to available space without requiring a separate breakpoint for every card layout.

15. Testing and Debugging

Browser testing checklist

  • Open each HTML page directly.
  • Click every navigation link.
  • Check the active page indicator.
  • Verify that the stylesheet loads on every page.
  • Test all image paths.
  • Test at desktop, tablet and mobile widths.
  • Check for horizontal overflow.
  • Navigate through links using the keyboard.
  • Check browser console and Network panel for failed requests.

Common path errors

Symptom Likely Cause Fix
CSS not applied. Incorrect stylesheet path. Check the current HTML file's directory.
Page returns 404. Wrong filename or letter case. Match the actual filename exactly.
Image missing. Incorrect image directory or filename. Verify the relative image path.
Navigation opens wrong page. Incorrect href destination. Check the target file and directory.
Styles differ between pages. Different stylesheet references or conflicting page CSS. Use the shared CSS consistently.
Works locally but not on GitHub Pages. Case sensitivity or deployment path issue. Verify filenames, folder names and published URLs.

16. Deploying the Website with GitHub Pages

  1. Create a repository for the website.
  2. Upload the HTML files to the intended project root.
  3. Upload the css folder and its stylesheet.
  4. Upload images and other assets to their matching folders.
  5. Check the repository's default branch and Pages publishing configuration.
  6. Open the published homepage URL.
  7. Test every page and asset using the published website.
A website that works from a local file system may still fail after deployment because of incorrect case, missing files or incorrect repository paths. Always test the published version.

17. Placement Interview Questions

Q1. What is a multi-page website?

It is a website containing multiple HTML documents connected through navigation links.

Q2. What is the difference between a single-page and multi-page website?

A traditional multi-page website navigates between separate HTML documents. A single-page application commonly updates its content through client-side JavaScript routing without a full document navigation.

Q3. What is a relative path?

A relative path identifies a resource in relation to the directory of the current document.

Q4. What does ../ mean?

It refers to the parent directory of the current directory.

Q5. Why use an external stylesheet?

It allows multiple pages to share common styling, reduces duplication and simplifies maintenance.

Q6. What is the purpose of aria-current="page"?

It identifies the current item in a related set, such as the active page link in navigation.

Q7. Why can a website work locally but fail after deployment?

Possible causes include case-sensitive paths, missing assets, incorrect repository base paths and deployment configuration.

Q8. What is the difference between an absolute URL and a relative URL?

An absolute URL specifies a complete address, including its scheme and host. A relative URL is resolved against a base URL.

Q9. How can common page elements be reused?

Shared styles, reusable components and templating systems can reduce duplication. In a plain static HTML project, shared markup is often copied into each page unless a build or templating process is used.

Q10. Does CSS automatically share HTML components?

No. CSS shares presentation rules. It does not automatically insert shared HTML markup into separate documents.

21. Key Takeaways

  • Multi-page websites use separate HTML documents.
  • Navigation connects pages using anchor elements.
  • Relative paths depend on the current document's directory.
  • External CSS supports consistent styling across pages.
  • Reusable classes reduce duplicated styles.

  • Published websites must be tested for path and case errors.
