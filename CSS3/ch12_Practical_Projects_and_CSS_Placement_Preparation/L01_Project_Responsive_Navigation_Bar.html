Lecture 1: Project – Responsive Navigation Bar

Build a professional responsive navigation bar using semantic HTML, CSS Flexbox, responsive breakpoints, accessible interaction states and mobile-first styling.

1. Project Objectives

Navigation bars are common components in websites and frontend machine-coding assignments. This project develops a reusable navigation component suitable for a course portal, portfolio or business website.

  • Create a semantic navigation structure.
  • Align logo and navigation links using Flexbox.
  • Use spacing and alignment properties effectively.
  • Style hover, focus and active states.
  • Make the navigation responsive.
  • Implement a mobile menu without relying on JavaScript.
  • Support keyboard navigation.
  • Debug common navigation layout problems.

2. Understanding the Required Design

The navigation bar will contain:

  • Website logo or brand name.
  • Home link.
  • Courses link.
  • Projects link.
  • About link.
  • Contact link.

4. Step 1 – Create the HTML Structure

Use semantic HTML elements such as header, nav and ul to organize the navigation. 

<header class="site-header">
    <div class="navbar">

        <a href="#" class="logo">
            NS Learning Hub
        </a>

        <nav class="nav-menu">
            <ul class="nav-list">
                <li><a href="#">Home</a></li>
                <li><a href="#">Courses</a></li>
                <li><a href="#">Projects</a></li>
                <li><a href="#">About</a></li>
                <li><a href="#">Contact</a></li>
            </ul>
        </nav>

    </div>
</header>

Why use semantic elements?

  • header represents introductory page content.
  • nav identifies a navigation section.
  • ul groups navigation links.
  • li represents each navigation item.
  • a provides actual navigation behavior.

5. Step 2 – Apply Basic CSS

* {
    box-sizing: border-box;
}

body {
    margin: 0;
    font-family: Arial, sans-serif;
}

.site-header {
    background: #174ea6;
    color: white;
}

.navbar {
    max-width: 1200px;
    margin: auto;
    padding: 15px 24px;
}

The box-sizing: border-box rule makes element sizing easier to manage because padding and borders are included in the declared dimensions.

6. Step 3 – Use Flexbox for Desktop Navigation

.navbar {
    display: flex;
    justify-content: space-between;
    align-items: center;
}

.logo {
    color: white;
    font-size: 22px;
    font-weight: bold;
    text-decoration: none;
}

.nav-list {
    display: flex;
    align-items: center;
    gap: 24px;
    list-style: none;
    margin: 0;
    padding: 0;
}

.nav-list a {
    color: white;
    text-decoration: none;
}

Important properties

Property Purpose
display: flex Creates a flex formatting context.
justify-content: space-between Distributes free space between logo and menu.
align-items: center Aligns items along the cross axis.
gap Creates spacing between navigation links.
list-style: none Removes list markers.

7. Step 4 – Add Hover and Focus States

.nav-list a {
    display: inline-block;
    padding: 8px 4px;
    color: white;
    text-decoration: none;
    transition: color 0.2s ease;
}

.nav-list a:hover {
    color: #d6e7ff;
}

.nav-list a:focus-visible {
    outline: 3px solid white;
    outline-offset: 4px;
    border-radius: 3px;
}

Hover provides visual feedback for pointer users. Focus-visible provides a visible keyboard focus indicator.

Do not remove the browser's focus outline without providing a visible replacement.

8. Step 5 – Add a Mobile Menu Control

We will use a checkbox input to control the visibility of the mobile navigation menu through CSS. 

<input
    type="checkbox"
    id="menu-toggle"
    class="menu-toggle"
>

<label for="menu-toggle" class="menu-icon">
    Menu
</label>

The label activates the associated checkbox. CSS can then use the checked state to display the menu.

Mobile CSS

.menu-toggle {
    position: absolute;
    width: 1px;
    height: 1px;
    padding: 0;
    margin: -1px;
    overflow: hidden;
    clip-path: inset(50%);
    white-space: nowrap;
    border: 0;
}

.menu-icon {
    display: none;
    cursor: pointer;
    color: white;
    padding: 8px 12px;
}

@media (max-width: 768px) {
    .navbar {
        flex-wrap: wrap;
    }

    .menu-icon {
        display: block;
    }

    .nav-menu {
        display: none;
        width: 100%;
    }

    .nav-list {
        flex-direction: column;
        align-items: stretch;
        gap: 0;
    }

    .nav-list a {
        display: block;
        padding: 12px;
    }

    .menu-toggle:checked ~ .nav-menu {
        display: block;
    }
}

The checkbox and navigation menu must be siblings inside the same parent for the general sibling selector to work.

11. Responsive Testing

Viewport Width Expected Layout
1440px Full horizontal navigation.
1024px Horizontal navigation.
768px Mobile menu based on the specified breakpoint.
480px Vertical menu when expanded.
360px Compact mobile navigation without horizontal overflow.

Test the navigation at widths just above and below 768px. Also verify that the logo and menu control fit comfortably on narrow screens.

12. Common Problems and Debugging

Problem Possible Cause Correction
Links appear vertically on desktop. Flexbox not applied to the list. Apply display: flex to the list.
Logo and links are not separated. Incorrect parent alignment. Use justify-content: space-between.
Mobile menu does not open. Incorrect sibling structure or selector. Check checkbox and navigation placement.
Menu is inaccessible by keyboard. Control is hidden incorrectly. Keep the checkbox keyboard-accessible and provide a focus indicator.
Links overflow on mobile. Desktop layout remains active. Use the mobile media query.
Menu overlaps other content. Unexpected positioning or stacking. Inspect positioning and containing blocks.

13. Accessibility Considerations

  • Use a semantic navigation element.
  • Give the navigation a descriptive accessible label.
  • Use actual anchor elements for navigation links.
  • Ensure the mobile control is keyboard-operable.
  • Provide visible focus indicators.
  • Use sufficient text and focus contrast.
  • Do not communicate the active page using color alone.
The checkbox technique is useful for a small CSS-only demonstration, but it does not automatically provide the same accessibility semantics as a properly implemented disclosure button. For production use, prefer a button that updates aria-expanded and controls the navigation menu with JavaScript.

14. Placement Interview Questions

Q1. Why is Flexbox suitable for navigation bars?

Flexbox provides convenient one-dimensional alignment and spacing for the logo and navigation items.

Q2. What is the purpose of justify-content?

It distributes and aligns flex items along the main axis.

Q3. What does align-items: center do?

It aligns flex items along the cross axis.

Q4. What is a media query?

It conditionally applies CSS based on media features such as viewport width.

Q5. Why do we use flex-wrap?

It allows flex items to move onto additional lines when there is insufficient space.

Q6. What is the difference between gap and margin?

Gap creates spacing between items in layout containers. Margin creates space around individual elements.

Q7. Why use semantic HTML for navigation?

Semantic elements communicate document structure and improve navigation for assistive technologies.

Q8. How can you create a CSS-only mobile menu?

One demonstration approach uses a checkbox state and sibling selectors to control menu visibility.

Q9. Why is a focus indicator important?

It helps keyboard users identify which interactive element currently has focus.

Q10. How would you debug a navigation overflow issue?

Inspect the flex container, item widths, gap, padding, wrapping behavior and viewport breakpoint using DevTools.
