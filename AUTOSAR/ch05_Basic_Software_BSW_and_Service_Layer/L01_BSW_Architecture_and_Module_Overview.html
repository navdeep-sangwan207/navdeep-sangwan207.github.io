Chapter 5 – Basic Software (BSW) and Service Layer

1. Introduction to BSW

BSW stands for Basic Software. It is the software layer in AUTOSAR Classic Platform that provides common services and hardware access mechanisms required by application software components.

BSW separates application functionality from microcontroller and ECU-specific hardware implementation details.

Example: A motor-control application may request PWM output through configured software interfaces. The BSW and MCAL provide the lower-level driver functionality needed to control the microcontroller peripheral.

BSW is located below the RTE and provides the standardized software infrastructure used by the application.

3. Main Parts of BSW Architecture

A. Services Layer

The Services Layer provides common software services to application software and other BSW modules.

  • Operating System (OS).
  • ECU State Manager (EcuM).
  • BSW Mode Manager (BswM).
  • Diagnostic Event Manager (DEM).
  • Diagnostic Communication Manager (DCM).
  • Communication services.
  • Memory services.

B. ECU Abstraction Layer

ECU Abstraction hides ECU-specific hardware implementation details from higher software layers.

  • CAN Interface (CanIf).
  • CAN Transceiver Driver (CanTrcv).
  • Memory Hardware Abstraction.
  • I/O Hardware Abstraction.

C. Microcontroller Abstraction Layer (MCAL)

MCAL provides standardized access to microcontroller peripherals.

  • Port Driver.
  • DIO Driver.
  • ADC Driver.
  • PWM Driver.
  • GPT Driver.
  • SPI Driver.
  • CAN Driver.

D. Complex Drivers

Complex Drivers provide specialized functionality when standard BSW modules cannot meet particular hardware or timing requirements.

They are an optional architectural area, not a mandatory layer in every ECU.

7. Responsibilities of BSW

  • Provide operating system services.
  • Support ECU startup and shutdown.
  • Provide communication stack functionality.
  • Manage diagnostic events and communication.
  • Provide memory management services.
  • Abstract ECU-specific hardware.
  • Provide microcontroller peripheral drivers.
  • Support ECU software integration.

8. BSW vs RTE vs Application Layer

Layer Main Responsibility Examples
Application Layer Implements vehicle functions. Fan control, speed monitoring.
RTE Provides configured communication interfaces. Rte_Read, Rte_Write, Rte_Call.
BSW Provides common services and hardware access. OS, DEM, DCM, COM, MCAL.

9. Practical Automotive Example

Consider a vehicle cooling fan control ECU.

  1. Temperature-related application software obtains temperature information.
  2. The application logic determines the required fan state.
  3. The RTE provides configured communication and service interfaces.
  4. Relevant BSW modules provide the required services.
  5. The PWM MCAL driver controls the microcontroller PWM peripheral through its configured interface.
  6. The hardware output controls the fan driver circuit.
Key concept: Application logic decides what the ECU should do. BSW provides the standardized software infrastructure needed to carry out the configured operation.

10. Common BSW Integration Problems

  • Incorrect BSW module configuration.
  • Missing or incompatible module dependencies.
  • Incorrect MCAL configuration.
  • Communication stack configuration errors.
  • Incorrect memory block configuration.
  • OS task and interrupt configuration problems.
  • Version incompatibility between generated modules.

Troubleshooting normally involves reviewing configuration validation reports, generated code, compiler messages and ECU runtime logs.

11. Interview Questions and Answers

Q1. What is BSW in AUTOSAR?

BSW is Basic Software. It provides common services and hardware access infrastructure for AUTOSAR ECUs.

Q2. What are the main parts of BSW?

Services Layer, ECU Abstraction Layer, MCAL and the Complex Drivers area.

Q3. What is the role of MCAL?

MCAL provides standardized access to microcontroller peripherals.

Q4. What is ECU Abstraction?

It hides ECU-specific hardware details from higher software layers.

Q5. What is the difference between DEM and DCM?

DEM manages diagnostic events and fault information. DCM handles diagnostic communication services.

Q6. What is EcuM?

EcuM coordinates ECU startup, shutdown and relevant ECU state management.

Q7. What is BswM?

BswM coordinates configured BSW mode management actions and rules.

Q8. What is the function of COM?

COM handles configured signal and I-PDU communication.

Q9. What is PduR?

PduR routes Protocol Data Units between configured communication modules.

Q10. Is Fee part of MCAL?

No. Fee is part of the memory abstraction area above the low-level Flash driver.

Q11. What is the difference between BSW and RTE?

RTE provides configured interfaces between application components and the software environment. BSW provides common services and hardware access.

Q12. What is a Complex Driver?

It is a specialized driver area used when standard BSW modules do not meet particular hardware or timing needs.

12. Lesson Summary

  • BSW stands for Basic Software.
  • BSW provides services and hardware access infrastructure.
  • Services Layer provides OS, diagnostics, communication and memory services.
  • ECU Abstraction hides ECU-specific hardware details.
  • MCAL provides microcontroller peripheral drivers.
  • Complex Drivers support specialized requirements.
  • BSW works with the RTE and Application Layer.
Placement focus: Understand the BSW architecture, Services Layer, ECU Abstraction, MCAL, DEM, DCM, EcuM, BswM, COM, PduR and CanIf.
