Lesson 4: BSW Mode Manager (BswM)

AUTOSAR Basic Software – Mode Arbitration, Rules and Action Lists

1. Introduction to BswM

BswM stands for BSW Mode Manager. It is an AUTOSAR Basic Software module responsible for evaluating mode requests and coordinating configured actions when specified conditions are satisfied.

An automotive ECU operates in different modes depending on vehicle conditions and software requirements. For example, communication may need to be enabled during normal operation and disabled or placed into a low-power mode when the vehicle is parked.

BswM provides a configurable mechanism to manage these mode transitions using mode requests, arbitration rules and action lists.

BswM belongs to the BSW Services Layer. It coordinates configured mode-dependent actions involving BSW modules and, where configured, application-related mode behavior.

3. Why is BswM Required?

Different ECU modules need to change their behavior according to operating conditions. Without coordinated mode management, individual modules could make inconsistent decisions.

Examples include:

  • Enabling communication when the ECU enters normal operation.
  • Changing communication behavior during vehicle sleep preparation.
  • Coordinating ECU mode transitions.
  • Responding to diagnostic session or application mode changes.
  • Coordinating configured actions after a mode request.

4. Main Responsibilities of BswM

4.1 Mode Request Processing

BswM receives mode requests from configured software modules and evaluates their current values.

4.2 Mode Arbitration

It evaluates configured conditions and determines which arbitration rules are satisfied.

4.3 Rule Evaluation

Rules contain logical conditions based on mode requests and other configured information. Their results determine which actions should be executed.

4.4 Action List Execution

BswM executes configured action lists when the corresponding rule conditions are satisfied.

4.5 Mode Coordination

It coordinates mode-dependent behavior across configured BSW modules and application-related interfaces.

Basic working sequence:

  1. A configured module reports a mode request.
  2. BswM receives or evaluates the request.
  3. Configured arbitration rules are evaluated.
  4. The result determines the applicable action list.
  5. Configured actions are executed.

6. Mode Requests

A mode request communicates a requested operating mode to BswM. The request may originate from different BSW modules or configured application interfaces.

Request Source Example Information
EcuM ECU lifecycle-related state or shutdown coordination information.
ComM Communication mode request or current communication mode information.
Application through RTE Configured application mode request.
Diagnostic-related modules Diagnostic mode or session-related information where configured.
Other BSW modules Module-specific mode information supported by the configuration.

A request is an input to mode arbitration. It does not automatically mean that a requested action has already been completed.

7. Mode Arbitration

Mode arbitration is the process of evaluating mode requests and determining which configured rules or actions apply.

Example: Normal and Sleep Preparation

Condition Possible Configured Result
ECU requests normal operation Keep required communication and services active.
Sleep preparation requested Coordinate communication shutdown and other preparation actions.
Diagnostic activity is active Maintain the configured diagnostic communication behavior.

The actual result depends on the configured arbitration rules, request priorities and action lists.

8. Rules and Logical Conditions

A BswM rule evaluates one or more configured conditions. These conditions can use mode requests and logical operators.

Example logical conditions

        IF ECU_MODE == RUN
           AND COMMUNICATION_REQUEST == FULL_COMMUNICATION
        THEN
           Execute Normal Operation Actions
        
        IF ECU_MODE == SLEEP_PREPARATION
           AND NO_REQUIRED_RUN_REQUESTS
        THEN
           Execute Sleep Preparation Actions

These are conceptual examples to explain rule evaluation. Actual BswM rule expressions and available conditions are defined by the AUTOSAR configuration.

9. Action Lists

An action list contains configured actions that BswM executes when the associated rule condition is satisfied.

Examples of configured actions

  • Request a communication mode change through ComM.
  • Trigger configured BSW mode transitions.
  • Execute configured function calls.
  • Coordinate selected ECU operating-mode activities.
  • Perform configured application-related mode actions.

BswM does not directly perform every hardware or communication operation. It coordinates configured actions, often by requesting services from the responsible BSW modules.

11. BswM Configuration

BswM behavior is configured using AUTOSAR configuration descriptions and tools. Important configuration elements include:

  • Mode request sources.
  • Mode request values.
  • Arbitration rules.
  • Logical conditions.
  • Action lists.
  • Configured actions and their execution order.
  • Connections to relevant BSW modules and interfaces.

Typical configuration workflow

  1. Identify the ECU operating modes.
  2. Identify the modules that provide mode requests.
  3. Configure mode request interfaces.
  4. Define arbitration rules and conditions.
  5. Configure action lists.
  6. Generate the BSW configuration and source code.
  7. Integrate and test the configured behavior.

Common tools used in AUTOSAR projects include:

  • Vector DaVinci Configurator
  • Elektrobit EB tresos
  • ETAS ISOLAR

Tool support and configuration workflows vary by vendor, AUTOSAR release and project setup.

13. Common BswM Problems and Troubleshooting

Problem Possible Check

Incorrect communication mode Check BswM actions, ComM requests and channel configuration.

14. Placement-Oriented Interview Questions

Q1. What is BswM?

BswM is the AUTOSAR BSW Mode Manager. It evaluates configured mode requests and coordinates actions based on arbitration rules.

Q2. What is mode arbitration?

It is the process of evaluating configured mode requests and conditions to determine which rules and actions apply.

Q3. What is an action list?

An action list is a configured sequence of actions that BswM executes when its associated conditions are satisfied.

Q4. What is the difference between EcuM and BswM?

EcuM coordinates ECU lifecycle activities such as startup and shutdown. BswM evaluates mode requests and coordinates configured BSW actions.

Q5. How does BswM interact with ComM?

BswM can coordinate communication-related mode behavior through configured actions involving ComM.

Q6. What are BswM rules?

Rules are configured logical conditions that are evaluated using mode requests and other configured information.

Q7. Does BswM directly control CAN hardware?

No. BswM coordinates configured actions. CAN hardware communication is handled by the relevant communication stack and MCAL drivers.

Q8. Why is BswM configuration important?

Correct configuration ensures that mode requests, rules and action lists produce the intended ECU behavior.

Q9. Can BswM manage application-related modes?

Yes. It can coordinate configured application-related mode behavior through supported interfaces and actions.

Q10. What should you check if a BswM action is not executed?

Check the incoming mode request, arbitration rule, condition result, action-list association and relevant module configuration.

15. Lesson Summary

  • BswM stands for BSW Mode Manager.
  • It is part of the AUTOSAR BSW Services Layer.
  • It receives or evaluates configured mode requests.
  • It performs mode arbitration and rule evaluation.
  • It executes configured action lists.
  • It coordinates with modules such as EcuM and ComM.
  • Its behavior is defined by ECU-specific configuration.

BswM is an important AUTOSAR module for BSW configuration, ECU integration and automotive embedded software placement interviews.
