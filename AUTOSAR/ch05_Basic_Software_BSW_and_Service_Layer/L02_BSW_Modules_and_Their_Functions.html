Chapter 5 – Basic Software (BSW) and Service Layer

1. Introduction

AUTOSAR Basic Software consists of standardized software modules that provide services, communication, diagnostics, memory management and hardware access.

Each module has a defined responsibility and interacts with other modules through configured interfaces. Understanding these modules is important for AUTOSAR integration and embedded software placement interviews.

3. Operating System (OS)

AUTOSAR OS manages ECU software execution and provides real-time scheduling services. It is based on OSEK/VDX concepts and extended for AUTOSAR requirements.

  • Task scheduling and activation.
  • Interrupt handling.
  • Alarms and counters.
  • Events and resources.
  • Task synchronization.
Example: A periodic task may execute a sensor-reading runnable every 10 milliseconds, while another task handles slower background operations.

4. ECU State Manager (EcuM)

EcuM coordinates ECU startup, shutdown and relevant ECU state transitions. It participates in the initialization and deinitialization process.

  • Coordinates ECU startup.
  • Supports initialization sequencing.
  • Coordinates shutdown preparation.
  • Supports sleep and wakeup handling.

The exact startup sequence depends on the AUTOSAR release, ECU configuration and integration design.

5. BSW Mode Manager (BswM)

BswM coordinates configured mode-management behavior in the BSW. It evaluates mode requests and configured rules to trigger actions.

  • Evaluates configured mode conditions.
  • Coordinates BSW mode transitions.
  • Triggers configured actions.
  • Interacts with other BSW modules.
Example: A communication mode request can be used by configured BswM rules to coordinate communication-related actions.

6. Diagnostic Event Manager (DEM)

DEM manages diagnostic events reported by software components and BSW modules. It maintains event status and associated diagnostic information.

  • Receives diagnostic event reports.
  • Manages event status information.
  • Supports fault detection and confirmation strategies.
  • Manages configured event-related data.
  • Provides diagnostic information to other modules.
Example: If a temperature sensor signal is detected as invalid, the responsible software can report a diagnostic event to DEM according to the configured diagnostic design.

7. Diagnostic Communication Manager (DCM)

DCM handles diagnostic communication between an external diagnostic tester and the ECU.

  • Processes diagnostic requests.
  • Generates diagnostic responses.
  • Supports configured UDS services.
  • Manages diagnostic sessions and security access.
  • Coordinates diagnostic data and routines.
Example: A diagnostic tester sends a UDS request to read an ECU data identifier. DCM processes the request and provides the configured response.

DCM handles diagnostic communication; DEM manages diagnostic events. They are related but have different responsibilities.

8. Communication Modules: COM and PduR

COM Module

COM handles configured signal-level communication and I-PDU processing. It packs and unpacks signals into and from I-PDUs.

  • Signal packing and unpacking.
  • I-PDU transmission and reception handling.
  • Configured signal processing.
  • Transmission modes and update handling.

PDU Router (PduR)

PduR routes Protocol Data Units between configured communication modules and interfaces.

  • Routes I-PDUs and other PDUs.
  • Connects communication modules.
  • Supports configured routing paths.

9. CAN Interface (CanIf) and CAN Driver

CanIf provides a standardized interface between higher communication modules and the CAN driver.

The CAN MCAL driver controls the microcontroller's CAN controller hardware.

CanIf CAN Driver
Part of ECU Abstraction. Part of MCAL.
Hides CAN hardware-specific details from upper modules. Controls the CAN controller peripheral.
Provides standardized CAN interface services. Provides low-level controller operations.

  • NvM: Manages configured non-volatile data blocks.
  • MemIf: Provides a common interface to memory abstraction modules.
  • Fee: Provides EEPROM emulation using Flash memory.
  • Ea: Provides EEPROM abstraction.
  • Fls: Low-level Flash memory driver.
  • Eep: Low-level EEPROM driver where supported.

11. Watchdog Manager (WdgM)

WdgM supervises configured software execution behavior and supports detection of certain software execution failures.

  • Alive supervision.
  • Deadline supervision.
  • Logical supervision.
  • Reporting supervision status.
  • Coordination with watchdog-related modules.

WdgM is not the physical watchdog hardware driver. The watchdog driver and hardware perform the low-level watchdog operations.

12. Important Module Comparisons

Comparison Difference
DEM vs DCM DEM manages diagnostic events; DCM handles diagnostic communication.
COM vs PduR COM processes signals and I-PDUs; PduR routes PDUs.
CanIf vs CAN Driver CanIf abstracts the CAN hardware interface; CAN Driver controls the controller.
EcuM vs BswM EcuM coordinates ECU lifecycle and startup/shutdown; BswM coordinates configured BSW modes.
NvM vs MemIf NvM manages non-volatile blocks; MemIf provides a common memory abstraction interface.
WdgM vs Wdg Driver WdgM performs software supervision; the driver accesses watchdog hardware.

13. Interview Questions and Answers

Q1. What is the function of AUTOSAR OS?

It manages tasks, interrupts, alarms, events and scheduling.

Q2. What is EcuM?

It coordinates ECU startup, shutdown and related state management.

Q3. What is BswM?

It evaluates configured mode conditions and coordinates BSW mode actions.

Q4. What is DEM?

DEM manages diagnostic events and associated fault information.

Q5. What is DCM?

DCM processes diagnostic tester requests and ECU responses.

Q6. What is the function of COM?

COM handles configured signal packing, unpacking and I-PDU processing.

Q7. What is PduR?

PduR routes PDUs between configured communication modules.

Q8. What is CanIf?

CanIf provides a standardized interface to CAN hardware drivers.

Q9. What is NvM?

NvM manages configured non-volatile memory blocks.

Q10. What is WdgM?

WdgM supervises configured software execution behavior.

Q11. What is the difference between COM and PduR?

COM processes signals and I-PDUs, whereas PduR routes PDUs between modules.

Q12. Which module manages diagnostic faults?

DEM manages diagnostic events and their status information.

14. Lesson Summary

  • OS manages ECU software execution.
  • EcuM coordinates ECU lifecycle activities.
  • BswM coordinates configured BSW mode behavior.
  • DEM manages diagnostic events.
  • DCM handles diagnostic communication.
  • COM processes signals and I-PDUs.
  • PduR routes PDUs.
  • CanIf abstracts CAN hardware access.
  • NvM manages non-volatile memory blocks.
  • WdgM supervises software execution.
Placement focus: Be able to explain the purpose of OS, EcuM, BswM, DEM, DCM, COM, PduR, CanIf, NvM and WdgM, and describe how the communication and memory stacks connect.
