Lesson 6: Diagnostic Communication Manager (DCM)

AUTOSAR Basic Software – UDS Services, Diagnostic Sessions and Tester Communication

1. Introduction to DCM

DCM stands for Diagnostic Communication Manager. It is an AUTOSAR Basic Software module responsible for processing diagnostic requests received from an external diagnostic tester and providing the corresponding diagnostic responses.

Automotive service centers and development engineers use diagnostic testers to communicate with vehicle ECUs. They retrieve fault codes, read ECU information, perform diagnostic routines and access other configured diagnostic functions.

Important DCM responsibilities include:

  • Receiving and processing diagnostic requests.
  • Supporting configured UDS diagnostic services.
  • Managing diagnostic sessions.
  • Handling security access.
  • Checking diagnostic request conditions.
  • Preparing positive and negative diagnostic responses.
  • Interacting with DEM for DTC-related services.

3. What is UDS?

UDS stands for Unified Diagnostic Services. It is an automotive diagnostic communication protocol standardized in ISO 14229.

UDS defines diagnostic services that allow a tester to communicate with an ECU.

Examples of UDS operations

  • Read ECU diagnostic information.
  • Read and clear Diagnostic Trouble Codes.
  • Change diagnostic sessions.
  • Perform security access.
  • Execute configured diagnostic routines.
  • Transfer data for supported programming operations.

DCM implements the configured diagnostic service handling within the AUTOSAR ECU.

Basic request-processing sequence:

  1. The diagnostic tester sends a request.
  2. The communication stack receives and routes the request.
  3. DCM identifies the requested diagnostic service.
  4. DCM checks session, security and configured conditions.
  5. The required operation is performed or delegated.
  6. DCM prepares a positive or negative response.
  7. The response is transmitted to the tester.

5. Important UDS Diagnostic Services

SID UDS Service Purpose
0x10 Diagnostic Session Control Changes the diagnostic session.
0x11 ECU Reset Requests a configured ECU reset.
0x14 Clear Diagnostic Information Requests clearing of diagnostic information.
0x19 Read DTC Information Reads configured diagnostic trouble code information.
0x22 Read Data By Identifier Reads data identified by a configured DID.
0x27 Security Access Performs configured security access procedures.
0x28 Communication Control Controls configured communication behavior.
0x2E Write Data By Identifier Writes data for supported configured identifiers.
0x2F Input Output Control By Identifier Controls configured input/output signals.
0x31 Routine Control Starts, stops or requests results of configured routines.
0x34 Request Download Initiates a supported download operation.
0x36 Transfer Data Transfers data during supported programming operations.
0x37 Request Transfer Exit Terminates a data transfer sequence.
0x3E Tester Present Indicates that the tester is still active.
The table lists important UDS service identifiers for placement preparation. Actual service availability and supported subfunctions depend on the ECU diagnostic configuration and vehicle requirements.

6. Diagnostic Sessions

A diagnostic session defines the diagnostic operating context of an ECU. Different services may be permitted depending on the active session.

Common UDS sessions

Session Subfunction Purpose
Default Session 0x01 Normal diagnostic operating session.
Programming Session 0x02 Supports configured ECU programming operations.
Extended Diagnostic Session 0x03 Enables additional configured diagnostic functions.

Session transition example

        Diagnostic Tester
               |
               v
        Default Session
               |
        Request 0x10 03
               |
               v
        Extended Session
               |
        Additional Diagnostic Services
               |
               v
        Return to Default Session

A session transition may require checks and timing management. The ECU can return to the default session after configured conditions such as diagnostic session timeout.

7. Security Access (UDS Service 0x27)

Security Access controls access to protected diagnostic functions. It helps prevent unauthorized execution of sensitive ECU operations.

Conceptual seed-key process

        Diagnostic Tester
               |

               |
               v

        Tester Calculates Key
               |
               v
        Tester Sends Key
               |

        ECU Validates Key
               |
          --------------
          |            |
        Valid        Invalid
          |            |
          v            v
        Access       Access

The actual security algorithm and key handling are manufacturer-specific and must follow the ECU security design.

Security Access is not encryption by itself. It is an authentication-related diagnostic mechanism. Strong implementations also need appropriate key protection, attempt control and security design.

8. Positive and Negative Diagnostic Responses

Positive response

A positive response indicates that the requested diagnostic service was processed successfully.

Negative response

A negative response indicates that the request could not be processed as requested. UDS uses a Negative Response Message with response service identifier 0x7F.

Common Negative Response Codes (NRCs)

NRC Name Meaning
0x10 General Reject Request rejected for a general reason.
0x11 Service Not Supported Requested service is not supported.
0x12 Subfunction Not Supported Requested subfunction is not supported.
0x13 Incorrect Message Length or Invalid Format Request length or format is invalid.
0x22 Conditions Not Correct Required operating conditions are not satisfied.
0x31 Request Out Of Range Requested parameter or value is outside the supported range.
0x33 Security Access Denied Required security access is not available.
0x35 Invalid Key Provided security key is invalid.
0x78 Response Pending Request is accepted for processing, but the final response is not ready.

A common negative response format is: 

        7F  [Original Request SID]  [NRC]

Example: A request for service 0x22 rejected because the service is unsupported may produce: 

        7F 22 11

Example: Read DTC Information

  1. The tester sends UDS service 0x19.
  2. The communication stack routes the request to DCM.
  3. DCM checks the request and relevant conditions.
  4. DCM obtains the configured diagnostic information through DEM interfaces.
  5. DCM prepares the diagnostic response.
  6. The response is sent to the tester.

10. DCM Communication with the AUTOSAR Stack

Diagnostic communication may use CAN, LIN, Ethernet or another configured transport. In a typical CAN-based diagnostic path, the communication stack handles message transmission and reception. 

        Diagnostic Tester
               |
              CAN
               |
             CAN Bus
               |
        CAN Controller
               |
            CAN Driver
               |
             CanIf
               |
             PduR
               |
             DCM

For CAN diagnostics, CanTp provides segmentation and reassembly of diagnostic messages that require transport protocol handling. PduR routes configured protocol data units between communication modules.

The exact communication path depends on the selected transport protocol and ECU configuration. Ethernet diagnostics use a different transport and communication arrangement from CAN diagnostics.

11. DCM Configuration

DCM is configured according to the diagnostic requirements of the ECU.

Important configuration elements

  • Supported UDS services and subfunctions.
  • Diagnostic session configuration.
  • Security access levels.
  • Data Identifiers (DIDs).
  • Routine Identifiers (RIDs).
  • Diagnostic timing parameters.
  • Diagnostic request and response handling.
  • DTC-related interfaces with DEM.
  • Communication and transport protocol configuration.

Typical configuration workflow

  1. Collect ECU diagnostic requirements.
  2. Identify required UDS services.
  3. Configure sessions and security levels.
  4. Configure DIDs and supported routines.
  5. Configure diagnostic timing and response behavior.
  6. Configure DEM interaction.
  7. Generate, integrate and test DCM configuration.

Common AUTOSAR configuration tools include:

  • Vector DaVinci Configurator
  • EB tresos
  • ETAS ISOLAR

12. Common DCM Problems and Troubleshooting

Problem Possible Cause / Check
No diagnostic response Check communication routing, addressing, transport protocol and DCM configuration.
Service not supported Check whether the requested UDS service is configured.
Incorrect response code Check request validation, session and security conditions.
Security access failure Check seed-key implementation and access-level configuration.
Read DID failure Check DID configuration and data access implementation.
Read DTC failure Check DCM-DEM interaction and diagnostic configuration.
Response timeout Check processing time, diagnostic timing and transport behavior.

13. Practical Placement Example

Scenario: Reading Battery Voltage through UDS

Suppose an ECU provides battery voltage through a configured Data Identifier (DID). A diagnostic tester wants to read the voltage. 

        Tester Request:
        22 F1 90

        22 = Read Data By Identifier
        F1 90 = Example DID

        ECU Positive Response:
        62 F1 90 [Data Bytes]

The example DID is illustrative. The actual DID and returned data format must be defined by the vehicle manufacturer's diagnostic specification.

Processing steps

  1. Tester sends the Read Data By Identifier request.
  2. Communication stack delivers it to DCM.
  3. DCM identifies the requested DID.
  4. DCM checks session and access conditions.
  5. The configured data provider supplies the value.
  6. DCM formats and sends the positive response.

14. Placement-Oriented Interview Questions

Q1. What is DCM in AUTOSAR?

DCM is the Diagnostic Communication Manager. It processes diagnostic requests from external testers and provides configured diagnostic responses.

Q2. What is UDS?

UDS is Unified Diagnostic Services, an automotive diagnostic protocol standardized in ISO 14229.

Q3. What is the difference between DEM and DCM?

DEM manages diagnostic events and DTC information. DCM handles diagnostic communication requests and provides configured UDS services.

Q4. What is Diagnostic Session Control?

It is UDS service 0x10, used to request a change in the ECU's diagnostic session.

Q5. What is Security Access?

It is UDS service 0x27, used to perform configured security access procedures for protected diagnostic functions.

Q6. What is a DID?

DID stands for Data Identifier. It identifies a configured data item that can be accessed through services such as Read Data By Identifier.

Q7. What is a negative response?

It is a diagnostic response indicating that a request could not be processed as requested. Its UDS response service identifier is 0x7F.

Q8. What does NRC 0x78 mean?

Response Pending. The request is still being processed, and the final response is not yet ready.

Q9. What is Tester Present?

It is UDS service 0x3E. It indicates that the diagnostic tester remains active and can help prevent diagnostic session timeout according to configured behavior.

Q10. How does DCM communicate with DEM?

DCM uses configured DEM interfaces to obtain or manage diagnostic information for supported diagnostic services.

Q11. What is the purpose of Routine Control?

UDS service 0x31 allows a tester to start, stop or request results from configured diagnostic routines.

Q12. What is the purpose of Read DTC Information?

UDS service 0x19 allows a diagnostic tester to request configured DTC information from the ECU.

15. Lesson Summary

  • DCM stands for Diagnostic Communication Manager.
  • It is part of the AUTOSAR BSW Services Layer.
  • It processes external diagnostic requests.
  • It supports configured UDS diagnostic services.
  • It manages diagnostic sessions and security access.
  • It prepares positive and negative diagnostic responses.
  • It interacts with DEM for DTC-related diagnostic services.
  • It uses the configured communication stack to exchange diagnostic messages.

DCM is an important module for automotive diagnostics, ECU testing, AUTOSAR BSW integration and embedded software placement interviews.
