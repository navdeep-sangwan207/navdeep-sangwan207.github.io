1. Project Introduction

Modern vehicles contain multiple Electronic Control Units (ECUs). These ECUs exchange information to coordinate functions such as engine control, body electronics, instrument clusters, cooling systems and vehicle diagnostics.

Controller Area Network (CAN) is a widely used communication protocol in automotive systems. In this project, we will study how two ECUs exchange temperature information using CAN and the AUTOSAR Classic communication stack.

1.1 Project Objective

  • Understand CAN-based communication between ECUs.
  • Study CAN frames and message identifiers.
  • Understand the AUTOSAR communication stack.
  • Study COM, PduR, CanIf and CAN Driver responsibilities.
  • Understand signal packing and unpacking.
  • Develop a simplified sender and receiver example.
  • Study CAN communication testing using CANoe.

3. CAN Fundamentals

CAN is a multi-master, message-oriented serial communication protocol. Nodes transmit messages identified by CAN identifiers. The identifier participates in bus arbitration and determines message priority.

3.1 CAN Features

  • Multi-master communication.
  • Message-based communication.
  • Priority-based arbitration.
  • Error detection and fault confinement.
  • Broadcast communication.
  • Robust communication for automotive applications.

3.2 CAN Classical and CAN FD

Feature Classical CAN CAN FD
Standard Identifier 11 bits 11 bits
Extended Identifier 29 bits 29 bits
Maximum Data Payload 8 bytes 64 bytes
Data Phase Bit Rate Same nominal bit rate Can be faster with bit-rate switching

3.3 CAN Frame Types

  • Data Frame – Carries application data.
  • Remote Frame – Requests data in Classical CAN.
  • Error Frame – Indicates a detected communication error.
  • Overload Frame – Provides additional delay in applicable Classical CAN operation.
Important: CAN identifiers identify messages, not individual ECUs. CAN is broadcast-oriented: nodes decide which received messages are relevant to them.

6.2 Responsibilities of Modules

Module Responsibility
RTE Provides configured communication between application components and BSW.
COM Packs and unpacks signals into and from I-PDUs.
PduR Routes PDUs between configured communication modules.
CanIf Provides a standardized interface to the CAN driver and related lower-layer modules.
CAN Driver Controls the configured CAN controller hardware.
CAN Transceiver Driver Controls the physical CAN transceiver where configured.
Important: The transceiver driver is separate from the CAN controller driver. The CAN controller handles frame transmission and reception, while the transceiver interfaces the controller signals with the physical CAN bus.

9. Standalone CAN Sender and Receiver Example

The following C program demonstrates the payload encoding and decoding logic. It simulates message transfer in software; it does not access a physical CAN controller or implement the AUTOSAR communication stack.

9.1 Sender and Receiver Demonstration

#include <stdio.h>
#include <stdint.h>

#define CAN_ID_TEMPERATURE  0x180U

int main(void)
{
    uint16_t temperature = 85U;

    uint8_t data[2];

    uint16_t receivedTemperature;

    /* Sender: encode temperature */
    data[0] = (uint8_t)(temperature & 0xFFU);
    data[1] = (uint8_t)((temperature >> 8U) & 0xFFU);

    printf("CAN ID: 0x%03X\n", CAN_ID_TEMPERATURE);
    printf("DLC: 2\n");

    printf("Transmitted Data: %02X %02X\n",
           data[0], data[1]);

    /* Receiver: decode temperature */
    receivedTemperature =
        (uint16_t)data[0] |
        ((uint16_t)data[1] << 8U);

    printf("Received Temperature: %u C\n",
           (unsigned int)receivedTemperature);

    if (receivedTemperature >= 80U)
    {
        printf("Cooling Fan: ON\n");
    }
    else
    {
        printf("Cooling Fan: OFF\n");
    }

    return 0;
}

11. CAN Physical Layer Basics

CAN communication normally uses a differential pair: CAN_H and CAN_L.

11.1 CAN Bus Connection

ECU 1                         ECU 2
+--------+                    +--------+
| CAN    |                    | CAN    |
| Trans- |                    | Trans- |
| ceiver |                    | ceiver |
+---+----+                    +----+---+
    |                              |
    +========== CAN_H =============+
    +========== CAN_L =============+
          |                  |
        120 ohm            120 ohm
       Terminator         Terminator

A properly terminated high-speed CAN bus normally has a 120-ohm termination resistor at each physical end of the bus. With two terminators and no other significant parallel paths, the resistance measured across CAN_H and CAN_L with the network powered down is approximately 60 ohms.

11.2 Physical Layer Checks

  • Check CAN_H and CAN_L wiring.
  • Verify common ground and transceiver supply requirements.
  • Check the configured nominal bit rate.
  • Verify termination resistance.
  • Inspect CAN controller error counters and bus state.

The following illustrative CAPL example periodically transmits the temperature message. The message and signal names must match the loaded CANoe database.

15. Important Technical Points

  • CAN is message-oriented and uses identifier-based arbitration.
  • CAN Classical supports up to 8 data bytes.
  • CAN FD supports up to 64 data bytes.
  • COM handles signal packing and unpacking.
  • PduR routes configured PDUs.
  • CanIf provides an interface to the CAN driver.
  • The CAN Driver controls the CAN controller.
  • The CAN transceiver connects controller signals to the physical bus.
  • DBC files describe message and signal layouts; they do not guarantee that the ECU implementation matches the database.
  • CANoe supports simulation, monitoring and test automation.

16. Placement Interview Questions and Answers

Q1. What is CAN?

CAN stands for Controller Area Network. It is a serial, message-oriented communication protocol widely used in automotive systems.

Q2. What is a CAN identifier?

It identifies a CAN message and participates in arbitration. A lower numerical identifier generally has higher priority when competing standard-format messages are compared.

Q3. What is the maximum Classical CAN payload?

Eight bytes.

Q4. What is the maximum CAN FD payload?

Sixty-four bytes.

Q5. What is the function of COM?

COM packs signals into I-PDUs for transmission and unpacks received I-PDUs into signals.

Q6. What is PduR?

PduR stands for PDU Router. It routes configured protocol data units between communication modules.

Q7. What is CanIf?

CanIf provides a standardized interface between upper communication modules and the CAN driver.

Q8. What is the role of the CAN transceiver?

It interfaces the CAN controller's transmit and receive signals with the physical CAN_H and CAN_L bus.

Q9. Why are termination resistors used?

They reduce signal reflections on the CAN bus. High-speed CAN networks normally use 120-ohm termination at both physical ends.

Q10. What is CAN bus-off?

Bus-off is an error-confinement state in which a CAN controller stops participating in bus communication after its transmit error counter reaches the specified bus-off condition.

Q11. What is a DBC file?

A DBC file describes CAN messages, identifiers, signals, their positions, scaling and related metadata.

Q12. What is CANoe?

CANoe is a Vector tool used for automotive network simulation, analysis, testing and test automation.
