1. Project Introduction

GPIO stands for General Purpose Input/Output. GPIO pins are used by microcontrollers to interface with external devices such as LEDs, switches, relays and other digital circuits.

In this project, we will study how an AUTOSAR application controls an LED using the AUTOSAR Classic Platform architecture.

1.1 Project Objective

  • Understand GPIO control in an automotive ECU.
  • Understand the AUTOSAR DIO and PORT drivers.
  • Study the relationship between application software and MCAL.
  • Understand the role of BSW and RTE.
  • Study GPIO configuration and initialization.
  • Develop a simplified LED control application.

2. GPIO Fundamentals

A GPIO pin can generally be configured as an input or output, subject to the capabilities of the selected microcontroller.

2.1 GPIO Input

An input pin reads a digital signal from an external device. For example, a push button can provide a digital input.

2.2 GPIO Output

An output pin drives a digital signal to an external device. For example, a GPIO output can control an LED through a suitable current-limiting circuit.

2.3 Basic GPIO Operation

       Microcontroller
      +----------------+
      |                |
      | GPIO Output    |------ Resistor ------ LED
      |                |
      +----------------+

The actual circuit polarity and pin configuration depend on the microcontroller and board design.

Important: DIO is an MCAL driver in the AUTOSAR Classic architecture. PORT is also an MCAL driver. The DIO driver provides digital input/output services, while the PORT driver configures port pins and their electrical and multiplexing-related settings supported by the MCU.

4. Understanding PORT and DIO Drivers

4.1 PORT Driver

The PORT driver configures microcontroller pins according to the ECU hardware design and configuration.

Typical configuration includes:

  • Pin direction, where supported by the MCU configuration.
  • Pin mode and alternate-function selection.
  • Pull-up or pull-down configuration, where supported.
  • Pin electrical characteristics supported by the device.

The PORT driver is generally initialized during ECU startup before dependent peripheral operations are used.

4.2 DIO Driver

The DIO driver provides services for reading and writing digital channels and ports.

Common AUTOSAR DIO APIs include:

API Purpose
Dio_ReadChannel() Reads the state of a configured digital channel.
Dio_WriteChannel() Writes a digital value to a configured channel.
Dio_ReadPort() Reads the state of a configured digital port.
Dio_WritePort() Writes a value to a configured digital port.
Dio_FlipChannel() Toggles the state of a configured channel.
DIO API availability and exact declarations depend on the AUTOSAR release and implementation. Use the vendor-provided headers and configuration for the target MCU.

7. GPIO Configuration Workflow

Before controlling a GPIO pin, the selected pin and channel must be configured for the target microcontroller.

7.1 Configuration Steps

  1. Identify the microcontroller GPIO pin connected to the LED.
  2. Check the MCU datasheet and board schematic.
  3. Configure the pin using the PORT module.
  4. Configure the digital channel in the DIO module.
  5. Configure the required BSW and application dependencies.
  6. Generate or integrate the required configuration artifacts.
  7. Initialize the configured drivers during ECU startup.
  8. Execute the application control logic.

8. PORT Driver Initialization

The PORT driver initializes configured microcontroller pins. The configuration data is generally generated by the selected AUTOSAR configuration tool.

8.1 Typical API

#include "Port.h"

int main(void)
{
    Port_Init(&Port_Config);

    /* Continue ECU initialization */

    while (1)
    {
        /* Main application or scheduler execution */
    }
}

This is an illustrative startup fragment. The configuration object name, initialization sequence and surrounding startup code depend on the MCU, AUTOSAR release and vendor integration.

9. DIO Driver API Usage

9.1 Header File

#include "Dio.h"

9.2 Write Digital Output

Dio_WriteChannel(LED_CHANNEL, STD_HIGH);

9.3 Turn LED OFF

Dio_WriteChannel(LED_CHANNEL, STD_LOW);

9.4 Read Digital Input

Dio_LevelType buttonState;

buttonState = Dio_ReadChannel(BUTTON_CHANNEL);

The symbolic channel identifiers must be defined by the generated DIO configuration. Do not assume that the names above exist in every AUTOSAR project.

10. Application Runnable

The application runnable determines the required LED state. The actual mechanism used to access the output depends on the ECU software architecture and configured interfaces.

10.1 Simplified Runnable Logic

void LedControlRunnable(void)
{
    boolean ledCommand;

    /* Obtain command through configured application interface */

    if (ledCommand == TRUE)
    {
        /* Request LED ON */
    }
    else
    {
        /* Request LED OFF */
    }
}
The above is pseudocode, not a complete generated AUTOSAR runnable. In a real implementation, use the generated RTE interfaces or an approved BSW service interface. Application SWCs should not directly call MCAL APIs as a general design practice.

11. Simplified C Demonstration Using DIO APIs

The following example demonstrates DIO channel control in a simplified driver-level application. It is not a complete AUTOSAR SWC implementation. 

#include "Std_Types.h"
#include "Port.h"
#include "Dio.h"

#define LED_CHANNEL     DioConf_DioChannel_LED

int main(void)
{
    Port_Init(&Port_Config);

    /* Initialize the DIO module if required
       by the vendor-specific integration. */

    while (1)
    {
        Dio_WriteChannel(LED_CHANNEL, STD_HIGH);

        /* Delay is represented as a placeholder. */

        Dio_WriteChannel(LED_CHANNEL, STD_LOW);

        /* Delay is represented as a placeholder. */
    }

    return 0;
}

A real AUTOSAR project normally uses the configured ECU startup and scheduler. Avoid implementing blocking delays in an application runnable unless the system design explicitly permits them.

15. Important Technical Points

  • PORT and DIO are MCAL modules in AUTOSAR Classic.
  • PORT configures pin characteristics and modes.
  • DIO reads and writes digital input/output channels.
  • RTE provides configured communication between application components and software infrastructure.
  • Application software should normally be separated from direct hardware register access.
  • GPIO channel identifiers are generally generated from the project configuration.
  • Hardware polarity and pin capabilities must be checked in the MCU datasheet.

16. Placement Interview Questions and Answers

Q1. What is GPIO?

GPIO stands for General Purpose Input/Output. It allows a microcontroller to interface with external digital devices.

Q2. What is the PORT driver in AUTOSAR?

The PORT driver configures microcontroller pins, including their supported modes and electrical settings.

Q3. What is the DIO driver?

DIO provides services to read and write digital input/output channels and ports.

Q4. Are PORT and DIO part of MCAL?

Yes. Both are Microcontroller Abstraction Layer drivers in the AUTOSAR Classic Platform.

Q5. What is Dio_WriteChannel()?

It is a DIO service used to write a digital level to a configured channel.

Q6. What is Dio_ReadChannel()?

It is a DIO service used to read the digital level of a configured channel.

Q7. What is the difference between PORT and DIO?

PORT configures pin characteristics and modes. DIO performs digital input/output operations on configured channels.

Q8. Can an application SWC directly access GPIO registers?

Normally, AUTOSAR application software is designed to use configured software interfaces rather than directly accessing hardware registers.

Q9. Why is PORT initialization important?

The microcontroller pins must be configured correctly before they are used for their intended digital or peripheral functions.

Q10. What happens if the GPIO pin is configured incorrectly?

The pin may not operate as expected. For example, an intended output may remain configured as an input or use the wrong alternate function.

Q11. What is a DIO channel?

A DIO channel is a configured digital input/output channel that identifies a particular MCU digital pin through the DIO configuration.

Q12. Why should blocking delays be avoided in runnable code?

Blocking delays can occupy a task and interfere with scheduling and timing requirements. OS alarms, schedule tables or suitable non-blocking mechanisms are generally preferred.
