Lesson 3: Diagnostic Trouble Codes (DTCs) and Fault Management

Chapter 9 – Diagnostics and Error Management

1. Learning Objectives

  • Understand Diagnostic Trouble Codes (DTCs).
  • Understand the relationship between diagnostic events and DTCs.
  • Learn the purpose of DTC status information.
  • Understand pending, confirmed and stored fault concepts.
  • Learn fault confirmation, healing and aging concepts.
  • Understand DTC storage and clearing in AUTOSAR DEM.
  • Prepare for automotive diagnostics placement interviews.

2. What Is a Diagnostic Trouble Code (DTC)?

A Diagnostic Trouble Code (DTC) is an identifier assigned to a diagnostic fault condition. It allows an ECU and diagnostic tester to refer to a fault using a defined code.

DTCs help technicians identify problems in sensors, actuators, communication networks, power supplies and ECU internal functions.

Examples of Fault Categories

  • Sensor circuit faults.
  • Actuator circuit faults.
  • Communication faults.
  • Voltage supply faults.
  • Internal ECU faults.
  • Performance or plausibility faults.
A DTC identifies a diagnostic trouble condition. It does not necessarily identify the exact physical root cause. Further troubleshooting may be required.

3. Diagnostic Event vs DTC

In AUTOSAR, the application or monitoring software reports a diagnostic event to DEM. The ECU diagnostic configuration can associate that event with a DTC.

4. DTC Format

Diagnostic trouble codes may use standardized or manufacturer-defined formats. For many OBD-related powertrain DTCs, a familiar five-character format is used.

Example: P0301

Character Meaning
P Powertrain category
0 Generic code designation in this example
3 Ignition system or misfire-related category
01 Specific fault identifier: cylinder 1 misfire detected

Other familiar OBD DTC category prefixes include:

  • P – Powertrain
  • B – Body
  • C – Chassis
  • U – Network and communication
The five-character OBD representation is not the same thing as the raw DTC value transmitted in every UDS implementation. AUTOSAR diagnostic configuration and the applicable diagnostic standard determine the DTC representation and encoding.

5. DTC Status Byte

UDS provides a DTC status byte that represents diagnostic status information. The status byte contains eight defined bit positions. The availability of individual status bits is indicated through the DTC status availability mask.

Bit Name Meaning
0 TestFailed The diagnostic test has failed.
1 TestFailedThisOperationCycle The test has failed during the current operation cycle.
2 PendingDTC The DTC has met the pending status criteria.
3 ConfirmedDTC The DTC has met the configured confirmation criteria.
4 TestNotCompletedSinceLastClear The test has not completed since the last clearing operation.
5 TestFailedSinceLastClear The test has failed at least once since the last clearing operation.
6 TestNotCompletedThisOperationCycle The test has not completed in the current operation cycle.
7 WarningIndicatorRequested A warning indicator request is active according to the diagnostic configuration.
These are the UDS DTC status-bit concepts. Their support and reporting depend on the status availability mask, diagnostic configuration and applicable implementation.

6. Pending DTC

A pending DTC indicates that a diagnostic fault has been detected and has reached the applicable pending-status criteria, but it may not yet satisfy the configured confirmed-DTC criteria.

Example

An ECU detects an intermittent sensor fault during a monitoring cycle. The fault may become pending while the ECU continues monitoring to determine whether the fault meets confirmation criteria.

7. Confirmed DTC

A confirmed DTC indicates that the diagnostic fault has met the configured confirmation criteria.

Depending on the ECU and diagnostic requirements, confirmation may involve repeated failures, operation-cycle logic or other configured qualification rules.

A confirmed DTC does not necessarily mean the fault is currently present. The current test status and confirmed status are separate pieces of diagnostic information.

8. Fault Confirmation

Fault confirmation determines whether a detected abnormal condition qualifies as a confirmed diagnostic fault.

Simplified Example

    Monitoring cycle 1:
        Fault detected
        Pending status may be set

    Monitoring cycle 2:
        Fault detected again
        Confirmation criteria may be reached

    Result:
        Confirmed DTC status may be set

This example illustrates a possible confirmation strategy only. Actual confirmation rules depend on the diagnostic configuration and applicable vehicle requirements.

9. Fault Healing

Fault healing refers to the process by which diagnostic status information is updated after the monitored condition returns to normal and the configured healing criteria are satisfied.

Example

  1. A sensor fault is detected.
  2. DEM records the diagnostic condition according to configuration.
  3. The sensor signal returns to the valid range.
  4. The application reports a passing result.
  5. Configured healing rules determine how the diagnostic status changes.

10. DTC Aging

Aging is a diagnostic process used to determine when certain historical fault information can be removed or its status changed after the fault has stopped recurring for a configured number of qualifying cycles.

Aging behavior is governed by diagnostic requirements and ECU configuration. It should not be confused with immediate fault healing or a diagnostic clear request.

Concept Purpose
Healing Updates fault status after the monitor reports normal operation and configured criteria are met.
Aging Handles the lifecycle of historical diagnostic information after qualifying fault-free operation.
Clearing Performs an explicit diagnostic clearing operation when permitted.

11. DTC Storage in AUTOSAR DEM

DEM manages diagnostic event memory according to the ECU's configuration. Depending on requirements, diagnostic memory may contain:

  • DTC-related status information.
  • Freeze frame records.
  • Extended data records.
  • Occurrence-related information.
  • Configured event memory metadata.

DEM may use configured primary or other event memory classes, depending on the AUTOSAR version and project requirements.

12. Reading and Clearing DTCs Using UDS

ReadDTCInformation – SID 0x19

The UDS ReadDTCInformation service allows a diagnostic tester to request supported DTC information from an ECU.

ClearDiagnosticInformation – SID 0x14

The UDS ClearDiagnosticInformation service requests clearing of supported diagnostic information for the selected DTC group.

13. Practical Example – Battery Undervoltage Fault

System Description

An ECU monitors its battery supply voltage using an ADC or another configured voltage-monitoring mechanism.

Fault Processing

  1. The battery voltage falls below the configured threshold.
  2. The monitoring software detects the undervoltage condition.
  3. The application reports the associated diagnostic event to DEM.
  4. DEM applies the configured debouncing mechanism.
  5. The event status is updated when the applicable criteria are met.
  6. The associated DTC status is updated according to configuration.
  7. The diagnostic tester can request supported DTC information using UDS.

Recovery

When the battery voltage returns to the valid range, the monitoring software reports a passing result. DEM then applies configured healing and status-management rules.

14. Placement Interview Questions and Answers

Q1. What is a DTC?

A DTC is a Diagnostic Trouble Code used to identify a diagnostic fault condition.

Q2. What is the difference between an Event ID and a DTC?

An Event ID identifies a diagnostic event internally within the ECU, whereas a DTC identifies the associated diagnostic trouble condition for diagnostic reporting.

Q3. What is a pending DTC?

It indicates that the fault has reached the applicable pending status criteria but may not yet be confirmed.

Q4. What is a confirmed DTC?

It indicates that the configured fault-confirmation criteria have been met.

Q5. What is the UDS service identifier for ReadDTCInformation?

0x19.

Q6. What is the UDS service identifier for ClearDiagnosticInformation?

0x14.

Q7. What is a DTC status byte?

It is an eight-bit field used to represent diagnostic test and DTC status information.

Q8. What is fault healing?

It is the configured process of updating diagnostic status after the monitored condition returns to normal.

Q9. What is DTC aging?

It is a process for handling historical fault information after configured fault-free operation criteria are satisfied.

Q10. Which AUTOSAR module manages DTC-related diagnostic information?

DEM manages diagnostic event and associated DTC-related information.

  • The DTC status byte represents diagnostic status information.
