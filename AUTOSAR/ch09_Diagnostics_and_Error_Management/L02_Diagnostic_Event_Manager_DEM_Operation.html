Lesson 2: Diagnostic Event Manager (DEM)

Chapter 9 – Diagnostics and Error Management

1. Learning Objectives

  • Understand the purpose and architecture of DEM.
  • Understand diagnostic events and event IDs.
  • Learn how software reports faults to DEM.
  • Understand event debouncing and event status.
  • Understand DTC association and diagnostic event memory.
  • Prepare for AUTOSAR DEM placement interview questions.

2. What Is DEM?

DEM stands for Diagnostic Event Manager. It is an AUTOSAR Classic Platform Basic Software module responsible for managing diagnostic events reported by application software and other configured software modules.

DEM processes event reports, maintains event status, supports configured debouncing mechanisms and manages diagnostic information such as DTC status, event memory, freeze frame data and extended data.

DEM does not directly detect every physical fault. The application or another monitoring module generally detects an abnormal condition and reports the corresponding diagnostic event to DEM.

4. Diagnostic Event

A diagnostic event represents a monitored condition that may indicate a malfunction in the ECU or vehicle system.

Examples

Event Monitored Condition
Engine temperature sensor fault Sensor voltage outside the configured valid range.
Battery undervoltage Battery voltage remains below a configured threshold.
CAN communication timeout Expected message is not received within the configured time.
Motor overtemperature Motor temperature exceeds the configured limit.
Memory error A configured memory diagnostic detects an abnormal condition.

5. Event ID and DTC Association

Event ID

An Event ID is a configured identifier used by DEM to identify a diagnostic event within the ECU.

DTC Association

A diagnostic event can be associated with a Diagnostic Trouble Code (DTC) through ECU diagnostic configuration. The DTC is the identifier that can be exposed through supported diagnostic services. 

    Example:

    Event ID:  10
    Event:     Engine Temperature Sensor Fault
    DTC:       Configured manufacturer or standard DTC
    Status:    Updated according to monitoring results
Event IDs are ECU configuration identifiers. They should not be confused with UDS DTC values. The event-to-DTC relationship is defined through diagnostic configuration.

6. Reporting Diagnostic Events to DEM

The application monitors a signal or operating condition. When it detects a fault or a return to normal operation, it reports the appropriate event status to DEM.

Common Reporting Concept

    Fault detected:
        Dem_SetEventStatus(EventId, DEM_EVENT_STATUS_FAILED);

    Fault no longer detected:
        Dem_SetEventStatus(EventId, DEM_EVENT_STATUS_PASSED);

These calls illustrate the reporting concept. In a real AUTOSAR project, the application may use configured RTE interfaces, generated operations or other supported reporting mechanisms. The exact API and generated identifiers depend on the AUTOSAR release and implementation.

Event Status Values

Status Meaning
DEM_EVENT_STATUS_PASSED The monitored test has passed.
DEM_EVENT_STATUS_FAILED The monitored test has failed.
DEM_EVENT_STATUS_PREPASSED Intermediate pre-passed report used with supported debouncing.
DEM_EVENT_STATUS_PREFAILED Intermediate pre-failed report used with supported debouncing.
DEM_EVENT_STATUS_FDC_THRESHOLD_REACHED Reports a fault-detection-counter threshold condition where supported.

7. Event Debouncing

Debouncing is used to prevent temporary signal fluctuations from being immediately treated as confirmed faults.

Why Is Debouncing Required?

Consider a temperature sensor whose signal briefly crosses a fault threshold because of electrical noise. If every short fluctuation were treated as a confirmed fault, unnecessary diagnostic entries could be generated.

Common Debouncing Methods

7.1 Counter-Based Debouncing

A fault-detection counter is increased or decreased according to reported test results. Configured thresholds determine when the event is considered passed or failed. 

    Simplified concept:

    Counter = 0

    If fault is detected:
        Counter = Counter + 1

    If normal condition is detected:
        Counter = Counter - 1

    If Counter reaches failure threshold:
        Event is considered failed

    If Counter reaches pass threshold:
        Event is considered passed

7.2 Time-Based Debouncing

The fault condition must remain present for a configured duration before the event is treated as failed. A corresponding pass condition may also be configured.

7.3 Monitor-Internal Debouncing

The application or monitoring component performs its own fault qualification and reports the resulting status to DEM.

These are conceptual examples. Actual counter behavior, thresholds, timing and reporting configuration are project-dependent.

8. Diagnostic Event Status

DEM maintains diagnostic event status information. This information helps determine whether a fault has been detected, whether it is currently present and whether it has met configured confirmation conditions.

Important Status Concepts

  • Test failed: the monitored test has reported a failure.
  • Test failed this operation cycle: a failure occurred in the current configured cycle.
  • Pending DTC: a fault has been detected but may not yet meet confirmation criteria.
  • Confirmed DTC: the configured confirmation criteria have been met.
  • Test not completed: the relevant diagnostic test has not completed under applicable conditions.
DEM event status and UDS DTC status are related but distinct representations. DCM can expose configured DTC status information to a diagnostic tester.

9. Operation Cycle

An operation cycle represents a configured period during which diagnostic monitoring is performed. It helps DEM manage diagnostic status across defined vehicle or ECU operating periods.

Example

  • ECU starts and the configured operation cycle begins.
  • Diagnostic monitors execute when their enable conditions are satisfied.
  • Faults and passing results are reported to DEM.
  • DEM updates the relevant diagnostic status.
  • The operation cycle ends according to the ECU configuration.

Operation cycles are configured for the ECU application. They are not necessarily identical to an ignition cycle in every vehicle.

10. Diagnostic Event Memory

DEM manages configured diagnostic event memory used to retain diagnostic information. Depending on configuration, stored information can include DTC-related records, freeze frame data and extended data.

Freeze Frame Data

Freeze frame data stores selected operating parameters associated with a diagnostic occurrence.

Example parameters:

  • Engine speed
  • Coolant temperature
  • Battery voltage
  • Vehicle speed
  • Sensor voltage

Extended Data

Extended data stores additional configured diagnostic information, such as occurrence-related or fault-counter information.

Freeze frame and extended data are different data categories. Their contents, storage triggers and retention behavior depend on ECU diagnostic configuration.

11. Clearing Diagnostic Information

A diagnostic tester can request clearing of supported diagnostic information using the UDS ClearDiagnosticInformation service (SID 0x14).

DCM processes the diagnostic request and coordinates the applicable diagnostic handling with DEM. Whether information can be cleared depends on the request, configured DTC groups and ECU implementation.

12. Practical Example – Engine Temperature Sensor Fault

System Description

An ECU monitors an engine temperature sensor. The application checks whether the sensor signal is within its configured valid range.

Fault Processing

  1. The sensor voltage becomes abnormally high.
  2. The application detects the out-of-range signal.
  3. The application reports a failed diagnostic event.
  4. DEM applies the configured debouncing mechanism.
  5. The event status is updated when the configured criteria are met.
  6. Associated DTC information and diagnostic data are handled according to configuration.
  7. A technician uses a diagnostic tester to request the stored DTC information.

Recovery

When the sensor signal returns to the valid range, the application reports a passing result. DEM updates the event status according to the configured monitoring, confirmation and healing behavior.

13. Placement Interview Questions and Answers

Q1. What is DEM in AUTOSAR?

DEM stands for Diagnostic Event Manager. It manages diagnostic events, event status, configured debouncing and diagnostic event memory.

Q2. Does DEM detect physical faults directly?

Usually, application software or another monitoring component detects the abnormal condition and reports the corresponding diagnostic event to DEM.

Q3. What is an Event ID?

It is a configured identifier used by DEM to identify a diagnostic event within an ECU.

Q4. What is event debouncing?

Debouncing qualifies diagnostic reports to avoid treating temporary signal fluctuations as confirmed faults.

Q5. Name three debouncing methods.

Counter-based, time-based and monitor-internal debouncing.

Q6. What is the difference between an Event ID and a DTC?

An Event ID identifies an internal diagnostic event, while a DTC identifies a diagnostic trouble condition for diagnostic reporting.

Q7. What is freeze frame data?

It is a configured snapshot of selected ECU operating parameters associated with a diagnostic occurrence.

Q8. What is an operation cycle?

It is a configured period used by DEM to manage diagnostic monitoring and status information.

Q9. Which UDS service is used to clear diagnostic information?

ClearDiagnosticInformation, service identifier 0x14.

Q10. What is the relationship between DEM and DCM?

DEM manages diagnostic event and DTC-related information. DCM handles external diagnostic requests and accesses the relevant diagnostic information through configured interfaces.
