2. What Is an AUTOSAR System Description?

An AUTOSAR System Description represents the relevant vehicle system architecture. It describes how software components, ECUs, communication networks and system signals are organized and connected.

Typical Information

  • Software component descriptions.
  • Software component ports and interfaces.
  • System-level component connections.
  • ECU instances and allocation.
  • Communication signals and I-PDUs.
  • Network topology and communication relationships.
  • Relevant data types and system mappings.

4. What Is ECU Allocation?

ECU allocation assigns software components or system functions to specific Electronic Control Units.

Example

Software Component Allocated ECU
TemperatureSensorSWC Engine ECU
EngineControlSWC Engine ECU
DoorControlSWC Body ECU
DisplaySWC Instrument ECU

Why Is Allocation Important?

  • Identifies where software components execute.
  • Supports ECU-specific software configuration.
  • Helps determine communication between ECUs.
  • Supports memory and processing-resource planning.
  • Provides information for integration activities.

5. What Is an ECU Extract?

An ECU Extract is an ECU-specific description derived from system-level information. It contains the relevant parts of the system model required for configuration of a selected ECU.

Typical Information in an ECU Extract

  • Software components allocated to the ECU.
  • Relevant ports and interfaces.
  • Required communication information.
  • Relevant system signals and I-PDUs.
  • ECU instance and network relationships.
  • Information needed for ECU configuration.
An ECU Extract is not simply a copy of the entire System Description. It is a selected, ECU-specific view of the relevant system information.

6. System Description vs ECU Extract

System Description ECU Extract
Represents system-level architecture. Represents information relevant to a selected ECU.
Can describe multiple ECUs. Focuses on one ECU's configuration scope.
Supports system design and allocation. Supports ECU-specific configuration.
Contains broader system relationships. Contains selected relevant relationships.
Used in system-level development. Used as an input to ECU-level activities.

7. What Is ECU Configuration?

ECU configuration defines how the AUTOSAR software stack is configured for a particular ECU and its target hardware.

It includes the configuration of required BSW modules, RTE settings, communication paths, hardware drivers and operating system resources.

Typical Configuration Areas

  • Microcontroller and MCAL configuration.
  • Operating System configuration.
  • RTE configuration.
  • Communication stack configuration.
  • Diagnostic configuration.
  • Memory stack configuration.
  • ECU state management.
  • Watchdog and hardware-related services where applicable.

10. Communication Configuration at ECU Level

Communication configuration defines how an ECU sends and receives information through an automotive network.

Typical Configuration Information

  • CAN controller and channel assignment.
  • CAN identifiers and communication parameters.
  • Signals and I-PDU mapping.
  • COM transmission and reception settings.
  • PDU routing paths.
  • Transport protocol connections.
  • Network management configuration.

12. Common ECU Configuration Errors

Error Possible Cause
Missing software component Component not included in the ECU-specific model.
Incorrect ECU allocation Component assigned to the wrong ECU.
Unresolved interface reference Referenced interface is missing or incorrectly defined.
Invalid communication mapping Signal, I-PDU or network mapping is inconsistent.
Missing MCAL parameter Required hardware configuration is incomplete.
RTE generation failure Component or ECU configuration is inconsistent.
BSW validation error Invalid module parameters or incompatible settings.

13. Practical Example – Engine ECU Configuration

Project Requirement

An Engine ECU must read engine temperature, control a cooling fan and transmit temperature information to the Instrument ECU.

System-Level Activities

  1. Define the temperature monitoring software component.
  2. Define the cooling fan control component.
  3. Define the temperature communication interface.
  4. Allocate the components to the Engine ECU.
  5. Define communication with the Instrument ECU.

ECU Extract Activities

  1. Select the Engine ECU from the system model.
  2. Include its allocated software components.
  3. Include relevant interfaces and communication information.
  4. Prepare the ECU-specific description for configuration.

ECU Configuration Activities

  1. Configure ADC and required MCAL resources.
  2. Configure the OS tasks and scheduling.
  3. Configure RTE connections and runnable execution.
  4. Configure COM, PduR and CAN communication.
  5. Configure DEM and DCM if diagnostics are required.
  6. Validate and generate the required software artifacts.
  7. Integrate, build and test the ECU software.

Expected Result

The Engine ECU has an ECU-specific AUTOSAR configuration supporting sensor acquisition, fan control, CAN communication and configured diagnostic functions.

14. Placement Interview Questions and Answers

Q1. What is a System Description?

It represents the system-level AUTOSAR architecture, including software components, communication relationships and ECU allocation.

Q2. What is an ECU Extract?

It is an ECU-specific description derived from the system model and used as input for ECU configuration activities.

Q3. What is ECU allocation?

It assigns software components or functions to specific ECUs.

Q4. What is ECU configuration?

It defines the ECU-specific configuration of RTE, BSW modules and hardware-related software resources.

Q5. What is the difference between System Description and ECU Extract?

System Description represents broader system architecture, while ECU Extract contains the relevant information for a selected ECU.

Q6. Why is ECU allocation important?

It determines where software components execute and helps establish ECU-specific configuration and communication needs.

Q7. Which modules are configured at ECU level?

Examples include OS, RTE, COM, PduR, CanIf, CanTp, DCM, DEM and MCAL modules.

Q8. What happens after ECU configuration?

The configuration is validated, required software artifacts are generated, and the ECU software is integrated, built and tested.

Q9. What is the purpose of ECU Extract?

It provides the ECU-specific subset of system information required for ECU-level development.

Q10. What can cause ECU configuration errors?

Missing references, incorrect component allocation, invalid communication mapping and incomplete BSW parameters are common causes.

16. Lesson Summary

  • System Description represents the broader AUTOSAR system architecture.
  • ECU allocation assigns software components to ECUs.
  • ECU Extract contains information relevant to a selected ECU.
  • ECU configuration defines the software stack for the target ECU.
  • RTE, OS, communication, diagnostic and MCAL modules may require configuration.
  • Configuration tools validate and generate ECU software artifacts.
  • Generated software is integrated, built and tested.
