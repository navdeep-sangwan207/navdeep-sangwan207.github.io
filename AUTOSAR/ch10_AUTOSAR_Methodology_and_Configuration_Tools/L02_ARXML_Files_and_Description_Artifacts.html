2. What Is ARXML?

ARXML stands for AUTOSAR XML. It is an XML-based exchange format used to describe AUTOSAR software components, system architecture, communication interfaces and ECU configurations.

ARXML allows different AUTOSAR-compatible tools and development teams to exchange structured information.

Why Is ARXML Used?

  • To describe AUTOSAR software components.
  • To define ports and interfaces.
  • To describe runnable entities and data elements.
  • To represent system architecture.
  • To describe ECU allocation and communication.
  • To exchange ECU configuration information.
  • To support automated configuration and code generation.
ARXML is a model-description and exchange format. It is not the executable ECU firmware or ordinary C source code.

3. What Is XML?

XML stands for Extensible Markup Language. It stores structured information using elements, attributes and nested relationships.

Basic XML Example

<?xml version="1.0" encoding="UTF-8"?>

<Vehicle>
    <ECU>
        <Name>EngineECU</Name>
        <Type>ClassicPlatform</Type>
    </ECU>
</Vehicle>

Explanation

  • <?xml ... ?> – XML declaration.
  • <Vehicle> – Root element in this example.
  • <ECU> – Child element.
  • <Name> – Nested element containing text.
  • </ECU> – Closing element.

XML elements must be properly nested and closed. Attribute values must be quoted.

4. Basic Structure of an ARXML File

An ARXML document commonly contains an AUTOSAR root element and one or more packages containing AUTOSAR model elements.

Simplified ARXML Example

<?xml version="1.0" encoding="UTF-8"?>

<AUTOSAR
    xmlns="http://autosar.org/schema/r4.0"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://autosar.org/schema/r4.0
    AUTOSAR_00050.xsd">

    <AR-PACKAGES>

        <AR-PACKAGE>
            <SHORT-NAME>VehicleSystem</SHORT-NAME>

            <ELEMENTS>

                <APPLICATION-SW-COMPONENT-TYPE>
                    <SHORT-NAME>TemperatureSensor</SHORT-NAME>
                </APPLICATION-SW-COMPONENT-TYPE>

            </ELEMENTS>
        </AR-PACKAGE>

    </AR-PACKAGES>

</AUTOSAR>
This is a structural teaching illustration, not a guaranteed schema-valid production ARXML file. Real AUTOSAR elements require release-specific mandatory subelements, valid references and schema-compliant content.

5. Important ARXML Elements

Element Purpose
AUTOSAR Root element of an AUTOSAR XML document.
AR-PACKAGES Contains top-level AUTOSAR packages.
AR-PACKAGE Groups related AUTOSAR model elements.
SHORT-NAME Defines the short name of an element.
ELEMENTS Contains elements owned by a package.
SHORT-NAME path Forms part of the identification path of an element.
REF elements Represent references to other AUTOSAR objects.

6. AR-PACKAGE and Package Hierarchy

AR-PACKAGE is used to organize AUTOSAR model elements into logical groups. Packages can contain subpackages.

Example Package Hierarchy

AUTOSAR
   |
   +-- AR-PACKAGES
          |
          +-- VehicleSystem
          |      |
          |      +-- SoftwareComponents
          |      |
          |      +-- Interfaces
          |      |
          |      +-- DataTypes
          |
          +-- ECUConfiguration
          |
          +-- Communication

This is a conceptual organization. Actual package names and hierarchy are defined by the project and AUTOSAR model.

Why Use Packages?

  • Organize large AUTOSAR models.
  • Separate software components and interfaces.
  • Improve model navigation.
  • Support reuse and exchange of model elements.
  • Make references easier to manage.

7. SHORT-NAME and Fully Qualified Names

AUTOSAR elements commonly have a SHORT-NAME. The short name identifies the element within its package context.

A fully qualified path identifies an element through its package hierarchy.

Example

/VehicleSystem/SoftwareComponents/TemperatureSensor

The final segment identifies the TemperatureSensor element. Its full path provides the package context.

A SHORT-NAME is not necessarily globally unique by itself. The package context and reference path are important when identifying AUTOSAR objects.

8. AUTOSAR References

AUTOSAR models contain relationships between different objects. References connect an element to another element, such as a software component to an interface or a port to a data element.

Example Reference Concept

<PROVIDED-INTERFACE-TREF
    DEST="SENDER-RECEIVER-INTERFACE">
/VehicleSystem/Interfaces/TemperatureInterface
</PROVIDED-INTERFACE-TREF>

In this illustration:

  • PROVIDED-INTERFACE-TREF represents a reference element.
  • DEST identifies the expected destination element type.
  • The text contains the referenced AUTOSAR path.
Reference element names and DEST values are specific to the AUTOSAR metamodel. They must match the applicable schema and release. Do not copy an illustrative fragment directly into a production ARXML file.

9. Common AUTOSAR ARXML Description Types

Description Type Information Represented

12. ARXML Validation

ARXML validation checks whether a document follows the required XML syntax, AUTOSAR schema and applicable model constraints.

Common Validation Checks

  • XML syntax and well-formedness.
  • Correct AUTOSAR namespace and schema version.
  • Valid element structure.
  • Required attributes and subelements.
  • Correct reference paths.
  • Compatible referenced object types.
  • Consistency across related ARXML files.
  • Compatibility with the selected tool and AUTOSAR release.

Common Errors

Error Possible Cause
XML parsing error Missing closing tag or malformed XML.
Schema validation error Incorrect element structure or schema mismatch.
Unresolved reference Referenced object does not exist or path is incorrect.
Invalid DEST value Reference target type does not match the expected type.
Duplicate short name Conflicting elements in the same package context.
Version incompatibility ARXML model and tool support different releases or schemas.

13. Practical Example – Temperature Sensor Component

Requirement

An ECU must represent a temperature sensor software component and its communication interface in an AUTOSAR model.

Modeling Activities

  1. Create a software component model.
  2. Assign the component a short name.
  3. Define the required port.
  4. Associate the port with a suitable interface.
  5. Define the temperature data element and data type.
  6. Define the component's runnable behavior.
  7. Connect the component to the relevant system model.
  8. Save or export the model as ARXML.
  9. Import the ARXML into the ECU configuration tool.
  10. Validate the model and resolve errors.

Expected Result

The AUTOSAR tool can interpret the component description and use the model information in subsequent ECU configuration and RTE generation activities.

14. Placement Interview Questions and Answers

Q1. What is ARXML?

ARXML is an XML-based format used to represent AUTOSAR software, system and ECU configuration descriptions.

Q2. What is the purpose of AR-PACKAGE?

It organizes related AUTOSAR model elements into logical packages and subpackages.

Q3. What is SHORT-NAME?

It is the short identifier assigned to an AUTOSAR model element within its package context.

Q4. What is a fully qualified path?

It identifies an AUTOSAR element through its package hierarchy.

Q5. What is an ARXML reference?

It represents a relationship from one AUTOSAR model element to another element.

Q6. Is ARXML executable code?

No. It describes AUTOSAR models and configuration information. Tools use this information to configure or generate software artifacts.

Q7. What is the difference between XML and ARXML?

XML is a general markup language. ARXML uses XML syntax together with AUTOSAR-specific schemas and modeling rules.

Q8. What causes an unresolved reference error?

A referenced element may be missing, incorrectly named or unavailable in the imported model.

Q9. What is schema validation?

It checks whether an XML document follows the structure and constraints defined by its applicable schema.

Q10. Why is ARXML important in AUTOSAR?

It enables standardized exchange of software and system descriptions between compatible AUTOSAR tools and development teams.
