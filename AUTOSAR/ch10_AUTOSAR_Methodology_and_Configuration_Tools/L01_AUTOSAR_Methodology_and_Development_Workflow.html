2. What Is AUTOSAR Methodology?

AUTOSAR methodology defines a standardized process for describing, configuring and integrating automotive ECU software.

It provides a common development approach for OEMs, Tier-1 suppliers and software developers. Different organizations can exchange standardized descriptions of software components, communication interfaces and ECU configurations.

Main Objectives

  • Standardize automotive software architecture.
  • Improve software reuse across vehicle platforms.
  • Separate application software from hardware-dependent software.
  • Support integration between different suppliers.
  • Reduce development complexity.
  • Improve configuration and testing consistency.

4. Major Development Phases

4.1 Requirements Analysis

Engineers identify the functional and non-functional requirements of the ECU and vehicle system.

  • Sensor monitoring requirements.
  • Actuator control requirements.
  • Communication requirements.
  • Diagnostic requirements.
  • Timing and safety requirements.

4.2 System Architecture Design

The system architecture describes how functions are divided into software components and how those components communicate.

  • Identify software components.
  • Define ports and interfaces.
  • Define data elements and operations.
  • Describe communication between components.
  • Allocate components to ECUs.

4.3 Software Component Development

Application software is divided into reusable AUTOSAR Software Components (SWCs). Each component has defined interfaces and behavior.

4.4 System Configuration

The system is described using AUTOSAR models. Communication, component connections and ECU allocation are represented in the system-level descriptions.

4.5 ECU Configuration

The ECU-specific configuration identifies the software components, communication requirements and required Basic Software modules for an individual ECU.

4.6 Code Generation

Configuration tools generate software artifacts such as RTE implementation and configured BSW code, depending on the toolchain.

4.7 Integration and Testing

Generated software, application code and hardware-specific components are integrated, built and tested.

5. System-Level Development vs ECU-Level Development

System-Level Development ECU-Level Development
Describes the complete vehicle system. Focuses on one ECU or its assigned software.
Defines system architecture. Configures ECU-specific software.
Defines software component connections. Configures RTE and BSW for the ECU.
Allocates components to ECUs. Integrates and builds ECU software.
Produces system-level descriptions. Uses ECU-specific descriptions and configurations.

6. Role of ARXML in AUTOSAR Methodology

ARXML stands for AUTOSAR XML. It is an XML-based exchange format used to represent AUTOSAR software and system descriptions.

ARXML Can Describe

  • Software components.
  • Ports and interfaces.
  • Data types and implementation types.
  • Runnable entities.
  • System architecture.
  • ECU allocation.
  • Communication configuration.
  • ECU-specific configuration.
ARXML is not executable application code. It describes AUTOSAR models and configuration information that compatible tools can import, validate, transform or use for code generation.

7. System Description and ECU Extract

System Description

A System Description represents the relevant vehicle or network system architecture, including software components, communication relationships and ECU allocation.

ECU Extract

An ECU Extract is a description derived for a particular ECU. It contains the system information relevant to that ECU and is used as an input to ECU-specific configuration activities.

System Description ECU Extract
System-wide view. ECU-specific view.
Includes relationships across the system. Contains information relevant to a selected ECU.
Supports system design and allocation. Supports ECU configuration.

9. Role of RTE and BSW Generation

RTE Generation

The RTE generator creates the Runtime Environment implementation based on software component descriptions, connections, ECU allocation and relevant configuration.

BSW Generation

BSW configuration tools generate or configure module-specific artifacts according to the selected ECU architecture and supplier implementation.

Generated Artifacts May Include

  • RTE source and header files.
  • BSW configuration source and header files.
  • Module configuration structures.
  • Generated ECU configuration data.
  • Integration-related descriptions and reports.
Not every tool generates every artifact. Some BSW implementation source code is supplied by the vendor, while the configuration tool generates project-specific configuration and integration files.

11. Example – Temperature Monitoring ECU

System Requirement

An ECU must monitor engine temperature and send the temperature value to another ECU through CAN communication.

Development Steps

  1. Define the temperature monitoring requirement.
  2. Create a temperature sensor software component.
  3. Define the component's ports and interfaces.
  4. Define its runnable entity and execution requirements.
  5. Connect the component to the required system interfaces.
  6. Allocate the component to the target ECU.
  7. Prepare the relevant ECU-specific description.
  8. Configure ADC, RTE and communication-related BSW modules.
  9. Generate the configured RTE and BSW artifacts.
  10. Integrate application and generated software.
  11. Build and test the ECU software.

13. Placement Interview Questions and Answers

Q1. What is AUTOSAR methodology?

It is a standardized process for describing, configuring and integrating AUTOSAR-based automotive ECU software.

Q2. What is ARXML?

ARXML is an XML-based format used to represent AUTOSAR software, system and configuration descriptions.

Q3. What is a System Description?

It describes the relevant system architecture, including software components, communication relationships and ECU allocation.

Q4. What is an ECU Extract?

It is an ECU-specific description derived from system-level information for use in ECU configuration activities.

Q5. What is the purpose of an AUTOSAR configuration tool?

It helps configure AUTOSAR modules, validate configuration parameters and generate required software artifacts.

Q6. What is RTE generation?

It creates the Runtime Environment implementation that connects application software components with each other and with configured BSW services.

Q7. What is BSW configuration?

It defines the parameters and relationships required by Basic Software modules for a particular ECU.

Q8. What is the difference between system-level and ECU-level configuration?

System-level configuration describes the overall vehicle architecture, while ECU-level configuration focuses on the software and hardware requirements of an individual ECU.

Q9. Name some AUTOSAR tools.

Vector DaVinci Developer, DaVinci Configurator, EB tresos Studio and ETAS ISOLAR are examples.

Q10. Why is configuration validation important?

It helps identify missing parameters, invalid references, incompatible settings and other configuration problems before software integration and testing.

  • Software components are modeled with defined interfaces.
