Lesson 6: AUTOSAR Tools and Configuration Workflow

AUTOSAR Methodology and Configuration Tools

Placement-Oriented Embedded Automotive Software Training

1. Introduction

AUTOSAR development requires specialized software tools to design Software Components, configure Basic Software modules, generate RTE and BSW configuration code, integrate ECU software and perform testing and debugging.

These tools help automotive software engineers manage complex configuration descriptions, maintain consistency between modules and generate code for the target ECU.

Important: There is no single mandatory tool that performs every AUTOSAR development activity. Different tools are used for system design, SWC development, BSW configuration, code generation, compilation, debugging and testing.

3. AUTOSAR Configuration and Development Tools

3.1 Vector DaVinci Developer

Vector DaVinci Developer is used in AUTOSAR application software development and architecture-related configuration activities. Its capabilities depend on the product version and licensed features.

Typical activities can include:

  • Software Component design.
  • Port and interface configuration.
  • Runnable and event configuration.
  • Application architecture development.
  • ARXML-based exchange of AUTOSAR descriptions.

3.2 Vector DaVinci Configurator

DaVinci Configurator is used for configuring AUTOSAR BSW and integrating ECU configuration information in supported workflows.

Typical activities can include:

  • BSW module configuration.
  • ECU configuration management.
  • Module dependency validation.
  • Configuration consistency checks.
  • Generation of configuration artifacts.

3.3 Elektrobit EB tresos Studio

EB tresos Studio is an automotive software configuration environment used for AUTOSAR ECU development, particularly BSW and MCAL configuration when supported by the selected packages.

Typical activities:

  • MCAL configuration.
  • BSW module configuration.
  • ECU configuration validation.
  • Code generation.
  • Integration with supported software packages.

3.4 ETAS ISOLAR

ETAS ISOLAR is a tool environment used for AUTOSAR development. Depending on the installed product and version, it can support software architecture, configuration and integration activities.

Possible activities include:

  • Software Component modeling.
  • System and ECU description handling.
  • BSW configuration workflows.
  • ARXML import and export.
  • Configuration and integration support.
The exact functionality of DaVinci, EB tresos and ISOLAR depends on the product edition, release, licenses, vendor packages and project integration environment.

5. ARXML in AUTOSAR Tools

ARXML is the XML-based exchange format used to describe AUTOSAR software and system configuration information.

AUTOSAR tools import, export and process ARXML descriptions to exchange configuration information between development activities.

5.1 Typical ARXML Content

  • Software Component descriptions.
  • Port and interface definitions.
  • Runnable entities and internal behavior.
  • System and ECU descriptions.
  • Communication and mapping information.
  • BSW module configuration descriptions.

6. Configuration Workflow

A typical AUTOSAR ECU configuration workflow includes the following activities. The precise order can vary depending on the development methodology and project toolchain.

Step 1: Define ECU Requirements

  • Identify ECU functionality.
  • Identify microcontroller and hardware resources.
  • Define communication requirements.
  • Define diagnostic and safety requirements.

Step 2: Design Software Components

  • Create SWC architecture.
  • Define ports and interfaces.
  • Define runnable entities.
  • Configure events and data access.

Step 3: Create System and ECU Descriptions

  • Define ECU instances.
  • Configure component allocation.
  • Define communication connections.
  • Prepare ECU-specific configuration information.

Step 4: Configure BSW and MCAL

  • Configure OS and EcuM.
  • Configure communication modules.
  • Configure diagnostic modules.
  • Configure memory services.
  • Configure microcontroller drivers.

Step 5: Generate RTE and BSW Configuration

  • Validate configuration descriptions.
  • Resolve module dependencies.
  • Generate RTE artifacts.
  • Generate BSW configuration artifacts.

Step 6: Compile and Link

  • Integrate generated and vendor-supplied source files.
  • Configure compiler settings.
  • Build the ECU software.
  • Resolve compilation and linker errors.

Step 7: Test and Debug

  • Perform software unit testing.
  • Perform integration testing.
  • Verify communication behavior.
  • Test diagnostic services.
  • Debug ECU software on target hardware or a suitable simulation environment.

7. CANoe and CANalyzer

7.1 Vector CANoe

CANoe is an automotive network development and test environment. It is commonly used to simulate, test and analyze communication between ECUs.

Typical applications:

  • CAN network simulation.
  • ECU communication testing.
  • Diagnostic testing.
  • Restbus simulation.
  • Test automation.
  • Analysis of network behavior.

7.2 Vector CANalyzer

CANalyzer is primarily used to observe and analyze automotive communication networks.

Typical applications:

  • Monitoring CAN traffic.
  • Viewing CAN messages and signals.
  • Analyzing communication timing.
  • Investigating bus errors.
  • Recording and reviewing network traffic.

7.3 CANoe vs CANalyzer

Feature CANoe CANalyzer

8. Compiler, Linker and Debugger

8.1 Compiler

A compiler translates C or C++ source code into object code or another intermediate representation for the target processor.

Examples of automotive embedded compiler toolchains include:

  • GCC-based embedded toolchains.
  • Green Hills compiler.
  • Tasking compiler.
  • Arm Compiler.

8.2 Linker

The linker combines object files and libraries, resolves symbol references and produces the final executable image according to the target memory layout.

8.3 Debugger

A debugger helps engineers investigate software behavior during execution.

Common debugging operations:

  • Set breakpoints.
  • Execute code step by step.
  • Inspect variables.
  • Monitor registers and memory.
  • Investigate stack and task behavior.
  • Analyze runtime faults.

9. Version Compatibility and Integration

AUTOSAR projects use multiple software packages and tools. Their versions must be compatible with the selected AUTOSAR release and project configuration.

9.1 Compatibility Areas

  • AUTOSAR release compatibility.
  • ARXML schema and description compatibility.
  • BSW and MCAL package versions.
  • RTE and BSW generator versions.
  • Compiler and linker compatibility.
  • Microcontroller derivative support.
  • Vendor-specific integration requirements.
A configuration that works with one tool version or MCAL package may not work unchanged with another. Check the supplier's supported version matrix and project integration documentation.

10. Validation and Code Generation

Configuration validation checks whether the AUTOSAR descriptions are structurally and logically consistent according to the tool's rules.

10.1 Common Validation Checks

  • Missing mandatory configuration parameters.
  • Invalid references between configuration objects.
  • Incompatible ports and interfaces.
  • Unresolved module dependencies.
  • Unsupported hardware configurations.
  • Inconsistent communication mappings.
  • Invalid or unsupported configuration variants.

10.2 Code Generation

After successful validation, the relevant tools generate configured software artifacts.

11. Practical Example: Temperature Monitoring ECU Tool Workflow

Consider an ECU that reads temperature, controls a cooling fan and reports sensor faults through diagnostic communication.

11.1 Required Software Components

  • Temperature Sensor SWC.
  • Fan Control SWC.
  • Diagnostic Monitoring SWC.

11.2 Required BSW Modules

  • ADC and PWM MCAL drivers.
  • OS and EcuM.
  • DEM and DCM.
  • Required communication modules.

11.3 Tool-Based Workflow

Development Activity Example Tool Category
SWC modeling DaVinci Developer or supported ISOLAR tools
BSW configuration DaVinci Configurator or EB tresos
MCAL configuration Supported MCAL configuration environment
RTE generation Configured AUTOSAR RTE generator
Compilation and linking Target compiler and linker
CAN communication testing CANoe or CANalyzer
Runtime debugging Target debugger

11.4 Expected Development Result

The final ECU executable should:

  • Read the configured temperature input.
  • Execute fan-control logic.
  • Update the configured PWM output.
  • Detect and report configured sensor faults.
  • Support the required diagnostic communication.
  • Execute within the configured task and timing architecture.

13. Placement Interview Questions and Answers

Q1. What is an AUTOSAR toolchain?

It is a collection of development tools used for SWC design, BSW configuration, code generation, compilation, integration and testing.

Q2. What is DaVinci Developer used for?

It supports AUTOSAR application architecture and Software Component development activities.

Q3. What is DaVinci Configurator used for?

It supports AUTOSAR ECU and BSW configuration and related integration activities.

Q4. What is EB tresos Studio?

It is an automotive configuration environment used for supported AUTOSAR BSW and MCAL configuration workflows.

Q5. What is ETAS ISOLAR?

It is a tool environment that supports AUTOSAR development activities such as software modeling and configuration, depending on the installed products.

Q6. What is ARXML?

ARXML is the XML-based description and exchange format used to represent AUTOSAR system and software configuration information.

Q7. What is CANoe?

CANoe is used for automotive network simulation, testing, diagnostics and communication analysis.

Q8. What is CANalyzer?

CANalyzer is mainly used to monitor and analyze automotive network communication.

Q9. What is the difference between a compiler and a linker?

A compiler translates source code into object code, while a linker combines object files and libraries to create an executable.

Q10. Why is AUTOSAR version compatibility important?

Different tool, ARXML, BSW and MCAL versions may use different schemas, parameters or interfaces. Compatibility prevents configuration and integration problems.

Q11. What is configuration validation?

It is the process of checking configuration descriptions for missing parameters, invalid references and inconsistencies.

Q12. What is RTE generation?

It is the generation of ECU-specific Runtime Environment artifacts from AUTOSAR software and ECU configuration descriptions.

Q13. What is MCAL configuration?

It is the configuration of microcontroller drivers according to the target hardware and ECU requirements.

Q14. Why are CANoe and CANalyzer useful?

They help engineers investigate CAN communication, monitor messages, simulate networks and test automotive ECUs.

Q15. What happens after AUTOSAR code generation?

Generated artifacts are integrated with the supplied software, compiled, linked and tested on the target ECU or an appropriate simulation environment.

15. Lesson Summary

  • AUTOSAR development uses multiple specialized tools.
  • DaVinci, EB tresos and ISOLAR support different configuration and development workflows.
