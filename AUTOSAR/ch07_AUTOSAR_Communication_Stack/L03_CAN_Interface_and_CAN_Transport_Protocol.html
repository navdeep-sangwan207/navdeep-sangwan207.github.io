Lesson 3: CAN Interface and CAN Transport Protocol

AUTOSAR – Chapter 7: AUTOSAR Communication Stack

Focus: CanIf, CanTp, CAN PDU Handling and Segmentation

1. Introduction

AUTOSAR provides dedicated modules for communication between upper software layers and CAN hardware.

Two important modules are:

  • CanIf: CAN Interface.
  • CanTp: CAN Transport Protocol.

CanIf provides a standardized interface to CAN hardware drivers, while CanTp transfers longer messages over CAN by segmenting and reassembling data.

2. What is CanIf?

CanIf stands for CAN Interface. It is an AUTOSAR ECU Abstraction module that provides a standardized interface between upper communication modules and CAN hardware drivers.

Responsibilities of CanIf

  • Provides a common interface to the CAN Driver.
  • Handles configured CAN transmit and receive requests.
  • Manages configured CAN hardware object associations.
  • Provides controller mode and PDU mode interfaces.
  • Processes CAN reception indications and transmission confirmations.
  • Supports configured CAN identifier filtering and routing information.

CanIf is above the CAN Driver. PduR routes communication PDUs between modules; it is not part of the CAN hardware. Exact upper-layer paths depend on the configured communication use case.

4. Important CanIf Functions

Function / Interface Purpose
CanIf_Init Initializes the CanIf module.
CanIf_Transmit Requests transmission of a CAN-related I-PDU.
CanIf_SetControllerMode Requests a CAN controller mode change.
CanIf_GetControllerMode Reads the current controller mode.
CanIf_SetPduMode Sets the configured PDU communication mode.
CanIf_RxIndication Receives notification from the CAN Driver about a received frame.
CanIf_TxConfirmation Receives notification that a transmission has completed at the driver/controller interface.

These names represent common AUTOSAR interfaces. Availability, signatures and configuration requirements depend on the AUTOSAR release and implementation.

5. CanIf Transmit Flow

Consider an ECU transmitting a configured CAN message.

  1. An upper communication module requests transmission.
  2. The request reaches CanIf through the configured routing path.
  3. CanIf identifies the configured CAN transmit PDU and hardware object.
  4. CanIf calls the CAN Driver transmit interface.
  5. The CAN Driver submits the frame to the CAN controller.
  6. The controller transmits the frame on the bus through the transceiver.
  7. The driver reports transmission completion to CanIf.
  8. CanIf notifies the configured upper layer.
Upper Layer
↓
CanIf_Transmit
↓
CAN Driver
↓
CAN Controller
↓
CAN Bus

6. CanIf Receive Flow

  1. The CAN controller receives a frame from the bus.
  2. The CAN Driver processes the received frame.
  3. The driver calls the configured CanIf reception indication.
  4. CanIf identifies the corresponding receive PDU.
  5. CanIf forwards the received information to the configured upper layer.
  6. The upper layer processes the data.

7. What is CanTp?

CanTp stands for CAN Transport Protocol. It provides transport services for transferring messages that may exceed the payload capacity of an individual CAN frame.

Its main responsibilities include:

  • Segmentation of longer messages.
  • Reassembly of received message segments.
  • Flow control between communicating nodes.
  • Sequence management for consecutive frames.
  • Handling transport protocol timing requirements.
  • Supporting configured diagnostic communication over CAN.

8. Why is CanTp Required?

Classical CAN supports up to 8 payload bytes in one data frame. However, diagnostic requests and responses may contain more data than can fit in one frame.

CanTp divides the larger message into smaller transport protocol frames and reassembles them at the receiving ECU.

ISO-TP, specified by ISO 15765-2, is commonly used for diagnostic transport over CAN.

9. ISO-TP Frame Types

Frame Type Purpose
Single Frame (SF) Carries a complete message that fits into one transport frame.
First Frame (FF) Starts a multi-frame message and indicates its total length.
Consecutive Frame (CF) Carries subsequent segments of the message.
Flow Control Frame (FC) Controls the sender's transmission of consecutive frames.

10. Segmentation and Reassembly

Segmentation divides a long message into smaller pieces. Reassembly combines those pieces into the original message.

Example: Sending a 20-byte Message

Assume Classical CAN with a configured addressing format and a conventional ISO-TP payload arrangement.

Original Message: 20 Bytes
↓
First Frame (FF): Initial Data + Total Length
↓
Flow Control (FC): Receiver Grants Permission
↓
Consecutive Frame (CF): Remaining Data
↓
Receiver Reassembles Message
↓
Complete 20-byte Message

The exact number of frames and payload bytes depends on CAN type, addressing format and transport protocol settings.

11. Flow Control Parameters

Parameter Meaning
Block Size (BS) Maximum number of consecutive frames allowed before another flow control response is required.
Separation Time (STmin) Minimum separation time between consecutive frames.
Flow Status (FS) Indicates whether transmission may continue, should wait or must stop due to overflow.

Common Flow Status values:

  • CTS – Continue To Send.
  • WT – Wait.
  • OVFLW – Overflow.

13. Diagnostic Communication Example

A diagnostic tester sends a request to an ECU to read vehicle identification data.

  1. The tester creates a diagnostic request.
  2. CanTp segments the request if required.
  3. PduR routes the transport protocol data.
  4. CanIf passes CAN frames to the CAN Driver.
  5. The CAN controller transmits frames onto the bus.
  6. The target ECU receives and reassembles the request.
  7. DCM processes the diagnostic service.
  8. The response is transported back through the configured stack.
Diagnostic Tester
↓
CAN Frames
↓
CanIf → PduR → CanTp
↓
DCM
↓
Diagnostic Response

This is a simplified view. Exact module routing and direction of calls depend on the ECU's configured diagnostic architecture.

14. Common CanIf and CanTp Problems

Problem Possible Cause
CanIf transmission failure Invalid PDU ID, controller state or driver configuration.
CAN frame not received Incorrect CAN ID filter or receive configuration.
Multi-frame timeout Missing Flow Control or Consecutive Frame.
Incorrect reassembly Sequence number or message-length mismatch.
Transport overflow Insufficient receive buffer capacity.
Unexpected wait response Receiver is not ready to accept more consecutive frames.

15. Common Placement Interview Questions

Q1. What is CanIf?

Answer: CanIf is an AUTOSAR ECU Abstraction module that provides a standardized interface between upper communication modules and CAN hardware drivers.

Q2. What is CanTp?

Answer: CanTp is the CAN Transport Protocol module that supports segmentation and reassembly of longer messages over CAN.

Q3. Why is CanTp needed?

Answer: It is needed to transfer messages that cannot fit into a single CAN frame.

Q4. What is segmentation?

Answer: Segmentation is the process of dividing a larger message into smaller transport protocol frames.

Q5. What is reassembly?

Answer: Reassembly combines received message segments into the original complete message.

Q6. Name the four ISO-TP frame types.

Answer: Single Frame, First Frame, Consecutive Frame and Flow Control Frame.

Q7. What is Block Size?

Answer: It specifies how many consecutive frames a sender may transmit before another Flow Control frame is required.

Q8. What is STmin?

Answer: It specifies the minimum separation time between consecutive frames.

Q9. What is the difference between CanIf and CanTp?

Answer: CanIf provides the CAN hardware interface, whereas CanTp provides transport protocol services for multi-frame communication.

Q10. Which protocol is commonly used for diagnostics over CAN?

Answer: ISO 15765-2, commonly known as ISO-TP.

16. Lesson Summary

  • CanIf provides a standardized interface to CAN hardware drivers.
  • CanTp provides transport protocol services over CAN.
  • CanIf handles configured CAN transmission and reception.
  • CanTp supports segmentation and reassembly.
  • ISO-TP defines Single, First, Consecutive and Flow Control frames.
  • Block Size and STmin control multi-frame transmission behavior.
  • CanTp is commonly used for diagnostic communication over CAN.
