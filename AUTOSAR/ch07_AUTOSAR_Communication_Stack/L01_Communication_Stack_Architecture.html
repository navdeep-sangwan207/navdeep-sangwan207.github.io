Lesson 1: Communication Stack Architecture

AUTOSAR – Chapter 7: AUTOSAR Communication Stack

Focus: Communication Layers, Modules and Data Flow

1. Introduction

The AUTOSAR Communication Stack is a collection of Basic Software modules responsible for exchanging information between software components and electronic control units (ECUs).

It provides standardized communication services and abstracts lower-level communication hardware from application software.

Common communication technologies include:

  • CAN – Controller Area Network.
  • CAN FD – Controller Area Network Flexible Data-Rate.
  • LIN – Local Interconnect Network.
  • FlexRay – A deterministic automotive communication network.
  • Ethernet – High-bandwidth automotive networking.

2. Why is the Communication Stack Required?

  • Enables communication between different ECUs.
  • Provides standardized interfaces for application software.
  • Separates application logic from communication hardware.
  • Handles signal packing and unpacking.
  • Routes communication data to appropriate destinations.
  • Supports diagnostic and network communication services.
  • Improves software reuse and integration across vehicle platforms.

6. Signal, I-PDU and CAN Frame

Signal

A signal represents an individual item of application data, such as vehicle speed, engine temperature or battery voltage.

I-PDU

An Interaction Layer Protocol Data Unit (I-PDU) is a data container used by AUTOSAR communication modules. It can carry one or more signals.

CAN Frame

A CAN frame is the bus-level message transmitted by a CAN controller. It contains an identifier, control information, data and error-checking information.

7. Transmit Communication Flow

Consider an ECU transmitting vehicle speed to another ECU.

  1. The application software calculates vehicle speed.
  2. The SWC writes the signal through an RTE interface.
  3. COM processes the signal and packs it into an I-PDU.
  4. PduR routes the I-PDU to the configured lower communication module.
  5. CanIf forwards the request to the CAN Driver.
  6. The CAN Driver configures the controller for transmission.
  7. The CAN controller transmits the frame through the transceiver.
  8. The frame travels over the CAN bus.

8. Receive Communication Flow

When another ECU transmits a CAN message, the receiving ECU processes the message through its configured stack.

  1. The CAN transceiver receives the electrical bus signal.
  2. The CAN controller receives and validates the CAN frame.
  3. The CAN Driver reports the received data to CanIf.
  4. CanIf identifies the configured reception path.
  5. PduR routes the received I-PDU to the appropriate destination.
  6. COM extracts the configured signals from the I-PDU.
  7. The RTE makes the received data available to the application SWC.

The exact callbacks and routing sequence depend on the configured communication stack and selected protocol.

9. Communication Modules: Important Differences

Comparison Difference
COM vs PduR COM handles signals and I-PDU processing; PduR routes PDUs.
PduR vs CanIf PduR routes PDUs; CanIf provides the CAN-specific interface.
CanIf vs CAN Driver CanIf abstracts CAN hardware access; CAN Driver controls the CAN controller.
CanTp vs COM CanTp handles transport protocol segmentation and reassembly; COM processes configured signals and I-PDUs.
CanNm vs CanSM CanNm handles CAN network management messaging; CanSM coordinates CAN network mode management.

11. Common Placement Interview Questions

Q1. What is the AUTOSAR Communication Stack?

Answer: It is a collection of BSW modules that provide standardized communication services between software components and ECUs.

Q2. What is the function of COM?

Answer: COM handles signal-level processing, including packing signals into I-PDUs and unpacking received I-PDUs.

Q3. What is PduR?

Answer: PduR routes protocol data units between configured communication modules.

Q4. What is CanIf?

Answer: CanIf provides a standardized CAN interface between upper communication modules and the CAN hardware driver.

Q5. What is CanTp?

Answer: CanTp provides transport protocol services over CAN, including segmentation and reassembly of messages.

Q6. What is the difference between a signal and an I-PDU?

Answer: A signal represents an individual data item, while an I-PDU is a container that can carry one or more signals.

Q7. What is the difference between CanNm and CanSM?

Answer: CanNm manages CAN network management communication, while CanSM coordinates the CAN network's communication modes.

Q8. Which module controls the CAN controller?

Answer: The CAN Driver in MCAL controls the CAN controller hardware.

Q9. What is the role of a CAN transceiver?

Answer: It converts between the CAN controller's logic-level signals and the differential electrical signals on the CAN bus.

Q10. Explain the CAN transmit path in AUTOSAR.

Answer: A typical path is SWC → RTE → COM → PduR → CanIf → CAN Driver → CAN Controller → Transceiver → CAN Bus.

12. Lesson Summary

  • The Communication Stack enables standardized ECU communication.
  • COM processes signals and I-PDUs.
  • PduR routes I-PDUs between modules.
  • CanIf provides the CAN hardware interface.
  • CanTp provides transport protocol services over CAN.
  • CanNm and CanSM support network management and mode coordination.
  • The CAN Driver controls the CAN controller hardware.
  • Transmit and receive paths use configured communication modules.
