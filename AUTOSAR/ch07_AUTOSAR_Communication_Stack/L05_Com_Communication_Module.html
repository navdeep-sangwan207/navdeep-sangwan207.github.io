Lesson 5: COM Communication Module

AUTOSAR – Chapter 7: AUTOSAR Communication Stack

Focus: COM, Signals, I-PDUs, Signal Packing and Communication APIs

1. Introduction to AUTOSAR COM

The AUTOSAR COM module is responsible for handling signal-based communication between software components and the lower communication stack.

It converts application-level signals into configured Interaction Layer Protocol Data Units (I-PDUs) for transmission and extracts signals from received I-PDUs.

COM provides an abstraction so that application software can work with signals without directly handling CAN frame fields.

COM handles signal-level processing. PduR routes I-PDUs between configured communication modules. CanIf provides the interface to the CAN hardware driver.

3. Main Responsibilities of COM

  • Reads signal values from configured application interfaces.
  • Packs signals into I-PDUs for transmission.
  • Extracts signals from received I-PDUs.
  • Handles configured signal update information.
  • Supports transmission modes and periodic or event-driven transmission.
  • Supports configured signal filtering.
  • Provides timeout monitoring for configured received signals.
  • Provides signal invalidation and notification mechanisms where configured.

4. What is a Signal?

A signal is a logical data value exchanged between automotive software components or ECUs.

Examples include:

  • Vehicle speed
  • Engine temperature
  • Battery voltage
  • Accelerator pedal position
  • Door status
  • Motor speed

Each configured signal has properties such as data type, bit length, position, byte order and initial value.

5. What is an I-PDU?

I-PDU stands for Interaction Layer Protocol Data Unit. It is a configured data container used by communication modules to exchange signals or other communication data.

Multiple signals can be packed into a single I-PDU. The I-PDU is then passed through the configured communication stack.

I-PDU
┌───────────────────────────────────┐
│ Signal A │ Signal B │ Signal C │
└───────────────────────────────────┘
↓
Configured Communication Stack

An I-PDU is not itself a physical CAN frame. For CAN communication, the configured lower layers map the I-PDU to a CAN frame. Classical CAN supports up to 8 data bytes; CAN FD supports up to 64 data bytes.

6. Signal Packing

Signal packing means placing individual signal values into defined bit positions within an I-PDU.

Example: Vehicle Information I-PDU

Signal Example Length Purpose
Vehicle Speed 16 bits Vehicle speed information
Engine Temperature 8 bits Temperature information
Door Status 4 bits Door open/closed information
Reserved Bits 4 bits Unused or reserved positions

The example uses 32 bits in total, so the payload occupies 4 bytes. Actual signal positions and byte order are defined by the communication configuration.

9. Important COM APIs

API Purpose
Com_Init() Initializes the COM module.
Com_SendSignal() Updates a configured signal value for transmission.
Com_ReceiveSignal() Reads a configured received signal value.
Com_SendSignalGroup() Updates a configured signal group.
Com_ReceiveSignalGroup() Reads a configured signal group.
Com_TriggerIPDUSend() Requests transmission of a configured I-PDU.
Com_IpduGroupStart() Starts a configured I-PDU group.
Com_IpduGroupStop() Stops a configured I-PDU group.

These are standard-style COM API names. Exact availability, signatures and usage depend on the AUTOSAR release and generated configuration.

10. Transmission Modes

COM supports configured I-PDU transmission behavior. Common transmission modes include:

Mode Description
Periodic The I-PDU is transmitted at configured time intervals.
Direct Transmission is triggered by configured signal changes or events.
Mixed Combines periodic and event-triggered transmission behavior.

Transmission behavior may also use configured minimum delay times, repetition settings and filtering conditions.

11. Signal Update Bit

An update bit can indicate whether a signal has been updated since the previous transmission or reception according to the configured communication design.

It helps the receiving software identify updated signal information without assuming that every signal changes during every I-PDU transmission.

12. Signal Timeout Monitoring

COM can monitor configured received signals or I-PDUs for missing updates.

Example:

  1. An ECU receives vehicle speed periodically.
  2. COM monitors the configured reception deadline.
  3. If the expected update does not arrive within the configured time, a timeout condition is detected.
  4. A configured notification or replacement action may be performed.
  5. The application can respond using its configured error-handling logic.

Timeout behavior, notification callbacks and replacement values must be configured. COM timeout detection is not the same as the diagnostic event processing performed by DEM.

13. Signal Groups

A signal group is a collection of related signals that are handled together within a configured I-PDU.

Example: A motor status group may contain:

  • Motor speed
  • Motor temperature
  • Motor operating state
  • Motor fault status

Signal groups can support consistent handling of related data using configured group operations.

14. COM vs PduR vs CanIf

Module Main Responsibility
COM Signal packing, unpacking and I-PDU handling.
PduR Routes I-PDUs between configured communication modules.
CanIf Provides the interface between upper communication modules and CAN hardware drivers.
CAN Driver Controls the microcontroller CAN controller hardware through its driver interface.

15. Practical Example: Vehicle Speed Transmission

Consider an ECU that measures vehicle speed and transmits it to another ECU.

  1. The application calculates the vehicle speed.
  2. The SWC updates the configured speed signal through the RTE.
  3. COM stores the updated signal value.
  4. COM packs the value into its configured I-PDU.
  5. PduR routes the I-PDU to the CAN interface.
  6. CanIf and the CAN Driver handle transmission through the controller.
  7. The receiving ECU obtains the frame and delivers the I-PDU to COM.
  8. Receiving COM extracts the vehicle speed signal.
  9. The receiving SWC reads the value through the RTE.

16. Common COM Configuration and Debugging Issues

Problem Possible Cause
Signal value is incorrect Incorrect bit position, length, byte order or data conversion.
I-PDU is not transmitted I-PDU group stopped, routing issue or transmission condition not met.
Receiver gets an incorrect value Sender and receiver signal layouts do not match.
Signal timeout occurs Missing I-PDU, incorrect timing or incorrect timeout configuration.
Signal update is not detected Incorrect update-bit or signal configuration.
Signal group data is inconsistent Incorrect signal-group handling or configuration.

17. Common Placement Interview Questions

Q1. What is AUTOSAR COM?

Answer: COM is a BSW communication module that handles signal-based communication and I-PDU packing and unpacking.

Q2. What is a signal?

Answer: A signal is a logical data value, such as vehicle speed or engine temperature, exchanged between software components or ECUs.

Q3. What is an I-PDU?

Answer: An I-PDU is a configured data container used to carry communication data, including signals.

Q4. What is signal packing?

Answer: Signal packing places configured signal values into defined bit positions within an I-PDU.

Q5. What is the difference between COM and PduR?

Answer: COM handles signals and I-PDU contents, whereas PduR routes I-PDUs between communication modules.

Q6. What is the purpose of Com_SendSignal()?

Answer: It updates a configured signal value for transmission through COM.

Q7. What is the purpose of Com_ReceiveSignal()?

Answer: It reads a configured received signal value from COM.

Q8. What is signal timeout monitoring?

Answer: It detects when a configured received signal or I-PDU is not updated within its expected time.

Q9. What is a signal group?

Answer: It is a configured collection of related signals handled together.

Q10. Does COM directly transmit CAN frames?

Answer: No. COM handles signals and I-PDUs. Lower layers such as PduR, CanIf and the CAN Driver handle routing and hardware transmission.

18. Lesson Summary

  • COM is responsible for signal-based communication.
  • A signal represents logical application data.
  • An I-PDU carries configured communication data.
  • COM packs signals for transmission and extracts them during reception.
  • PduR routes I-PDUs between communication modules.
  • CanIf provides the CAN hardware interface.
  • COM supports configured transmission modes and timeout monitoring.
  • Signal groups organize related signal data.
