Lesson 4: CAN Network Management

AUTOSAR – Chapter 7: AUTOSAR Communication Stack

Focus: CanNm, CanSM, Network States, Sleep and Wakeup

1. Introduction

CAN Network Management (CanNm) is an AUTOSAR communication service used to coordinate the communication state of ECUs connected to a CAN network.

In a vehicle, many ECUs communicate over shared networks. When communication is no longer required, the network may be prepared for sleep to reduce power consumption.

Network Management helps ECUs coordinate communication activity, prepare for sleep and respond to wakeup conditions.

2. Why is Network Management Required?

  • Coordinates communication activity between network nodes.
  • Supports controlled transition toward network sleep.
  • Helps avoid premature shutdown while communication is needed.
  • Supports wakeup coordination.
  • Helps reduce unnecessary network activity and power consumption.
  • Provides communication-state information to other BSW modules.

4. Important Network Management Modules

Module Responsibility
CanNm Handles CAN-specific network management communication and state behavior.
ComM Coordinates communication requests from users and manages communication modes.
CanSM Coordinates CAN network communication modes and bus-off recovery.
Nm Interface (Nm) Provides a common interface to network management modules.
EcuM Coordinates ECU startup, shutdown and wakeup management.
BswM Arbitrates configured BSW mode requests and triggers configured actions.

5. CAN Network Management States

CanNm uses defined communication states to coordinate network activity.

State Description
Repeat Message State Supports network startup and repeated NM message transmission.
Normal Operation State Supports normal network communication and NM message activity.
Ready Sleep State Indicates that the node is ready to prepare for network sleep if conditions allow.
Prepare Bus-Sleep State Provides a preparation period before entering bus sleep.
Bus-Sleep Mode The network is in its sleep condition and normal NM communication is stopped.

These are CanNm-specific state concepts. Other modules, such as ComM and CanSM, have their own state machines and communication modes.

7. Repeat Message State

Repeat Message State is commonly used during network startup or when a node needs to announce its presence.

  • NM messages are transmitted according to configuration.
  • Other network nodes can detect active communication.
  • Repeat-message timing is controlled by configured timers.
  • The node can transition to normal operation after the required conditions are met.

8. Normal Operation State

In Normal Operation State, the ECU participates in normal network management communication.

  • Communication requests are maintained.
  • NM messages are transmitted according to configuration.
  • Other active network nodes are monitored.
  • The ECU remains active while communication is required.

9. Ready Sleep and Prepare Bus-Sleep

Ready Sleep State

This state indicates that the ECU can move toward network sleep when no active communication request or other configured condition prevents it.

Prepare Bus-Sleep State

This is a preparation phase before the network enters Bus-Sleep Mode. It allows coordinated transition and completion of required network management activities.

10. Network Wakeup

A sleeping ECU or network may need to wake up when a vehicle function becomes active or a valid wakeup event is detected.

Possible wakeup sources include:

  • CAN bus wakeup supported by the transceiver.
  • Local ECU wakeup request.
  • Ignition or vehicle power-state change.
  • Other configured hardware or software wakeup sources.

11. Communication Requests and Sleep Coordination

ComM receives communication requests from configured software users and coordinates communication modes.

When communication is required, the network is requested to remain available. When all relevant communication requests are released, the system may prepare for sleep.

12. CanNm vs CanSM vs ComM

Module Main Role
CanNm Handles CAN network management messages and network management state behavior.
CanSM Coordinates CAN network communication modes, including bus-off recovery.
ComM Coordinates communication requests and communication modes for network users.

13. Automotive Example

Vehicle Door Unlocking

Consider a vehicle that has been parked and its ECUs have entered a low-power state.

  1. The driver presses the remote unlock button.
  2. A configured wakeup mechanism activates the required ECU or network.
  3. EcuM handles the wakeup process.
  4. Communication modules become operational.
  5. CanNm coordinates network startup where configured.
  6. ComM coordinates the communication request.
  7. The body control function receives the required message.
  8. The door unlocking operation is performed.

14. Common Network Management Problems

Problem Possible Cause
ECU does not enter sleep Active communication request or missing sleep coordination.
ECU does not wake up Wakeup source, transceiver or EcuM configuration issue.
Continuous NM messages Network request remains active or configuration prevents sleep.
Unexpected network shutdown Incorrect communication request handling or state coordination.
Bus-off recovery problem CAN physical-layer fault or CanSM recovery configuration issue.

15. Common Placement Interview Questions

Q1. What is CAN Network Management?

Answer: It coordinates network communication activity and supports controlled sleep and wakeup behavior between ECUs.

Q2. What is CanNm?

Answer: CanNm is the AUTOSAR module responsible for CAN-specific network management communication.

Q3. What is ComM?

Answer: ComM coordinates communication requests from software users and manages communication modes.

Q4. What is CanSM?

Answer: CanSM coordinates CAN network communication modes and bus-off recovery.

Q5. Name the main CanNm states.

Answer: Repeat Message, Normal Operation, Ready Sleep, Prepare Bus-Sleep and Bus-Sleep Mode.

Q6. What is the purpose of Repeat Message State?

Answer: It supports network startup by allowing the ECU to transmit repeated NM messages.

Q7. Why is Bus-Sleep Mode required?

Answer: It helps reduce unnecessary network activity and vehicle power consumption when communication is no longer required.

Q8. What is network wakeup?

Answer: It is the process of activating the ECU or network when a configured wakeup event occurs.

Q9. What is the difference between CanNm and CanSM?

Answer: CanNm manages network management messaging and state behavior, while CanSM coordinates CAN communication modes and bus-off recovery.

Q10. What happens when communication is no longer required?

Answer: After relevant requests are released and configured conditions are satisfied, the network can transition through sleep preparation toward Bus-Sleep Mode.

16. Lesson Summary

  • CanNm coordinates CAN-specific network management communication.
  • ComM coordinates communication requests from software users.
  • CanSM manages CAN network communication modes and recovery.
  • Network management supports sleep and wakeup coordination.
  • Repeat Message and Normal Operation support active communication.
  • Ready Sleep and Prepare Bus-Sleep support transition toward sleep.
  • Bus-Sleep Mode helps reduce unnecessary network activity.
  • Actual behavior depends on ECU configuration and hardware support.
