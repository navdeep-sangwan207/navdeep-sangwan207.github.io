Lesson 2: CAN Communication in AUTOSAR

AUTOSAR – Chapter 7: AUTOSAR Communication Stack

Focus: CAN Protocol, ECU Communication and AUTOSAR Integration

1. Introduction to CAN

CAN stands for Controller Area Network. It is a serial, message-based communication protocol widely used in automotive electronic control units.

CAN allows multiple ECUs to communicate over a shared communication bus without requiring a separate direct communication wire between every pair of ECUs.

Examples of automotive ECUs using CAN:

  • Engine Control Unit (ECU).
  • Transmission Control Unit (TCU).
  • Body Control Module (BCM).
  • Anti-lock Braking System (ABS) ECU.
  • Instrument Cluster ECU.
  • Battery Management System (BMS).

2. Why is CAN Used in Automotive Systems?

  • Reliable communication between multiple ECUs.
  • Message-based communication using identifiers.
  • Built-in error detection and fault confinement.
  • Priority-based bus arbitration.
  • Reduced wiring compared with separate point-to-point links.
  • Support for real-time control applications when appropriately designed.

CAN is a multi-master bus. Any node can attempt transmission when the bus is available. Arbitration determines which message proceeds when multiple nodes start transmitting together.

4. CAN Controller and CAN Transceiver

CAN Controller

The CAN controller implements the CAN protocol at the controller level. It handles frame transmission, reception, arbitration, error detection and protocol timing.

CAN Transceiver

The CAN transceiver converts logic-level signals from the CAN controller into differential electrical signals on CAN_H and CAN_L, and converts received bus signals back into logic-level signals.

CAN Controller CAN Transceiver
Implements CAN protocol functions. Provides the electrical bus interface.
Usually integrated into an MCU or provided as a separate controller. Typically an external physical-layer device.
Handles message arbitration and frame processing. Handles differential signal transmission and reception.

5. CAN Bus Signals

  • CAN_H: High-side differential bus signal.
  • CAN_L: Low-side differential bus signal.
Bus State Typical CAN_H Typical CAN_L
Recessive Approximately 2.5 V Approximately 2.5 V
Dominant Approximately 3.5 V Approximately 1.5 V

These are typical high-speed Classical CAN values, not universal guaranteed voltages. Actual levels depend on the transceiver and network conditions.

6. CAN Frame Format

A CAN frame contains control and data fields used to transmit information between nodes.

Important CAN Frame Fields

Field Purpose
SOF Start of Frame.
Identifier Identifies the message and determines arbitration priority.
Control Field Contains control information, including data length information.
Data Field Contains the transmitted payload.
CRC Supports error detection.
ACK Allows receivers to acknowledge correct frame reception at the protocol level.
EOF End of Frame.

Standard and Extended CAN Identifiers

  • Standard CAN identifier: 11 bits.
  • Extended CAN identifier: 29 bits.

Classical CAN supports up to 8 payload bytes per data frame. CAN FD supports a larger payload, up to 64 bytes.

7. CAN Arbitration

CAN uses non-destructive bitwise arbitration. A dominant bit overwrites a recessive bit on the bus.

  • Dominant bit = logical 0.
  • Recessive bit = logical 1.
  • Lower numerical identifier generally has higher arbitration priority when comparing frames with the same format.
ECU A transmits ID 0x100
ECU B transmits ID 0x200
↓
Both attempt transmission
↓
CAN Arbitration
↓
ECU A wins arbitration
↓
ECU B waits and retries

Arbitration priority is determined by the transmitted arbitration field, not by an ECU's physical importance. Identifier comparisons must account for standard/extended frame format and the complete arbitration field.

10. Example: Vehicle Speed Communication

Consider an engine ECU transmitting vehicle speed to an instrument cluster ECU.

  1. The engine ECU calculates vehicle speed.
  2. The application SWC updates the vehicle speed signal.
  3. COM packs the signal into an I-PDU.
  4. PduR routes the I-PDU to the CAN communication path.
  5. CanIf passes the transmission request to the CAN Driver.
  6. The CAN controller transmits the CAN frame.
  7. The transceiver places the differential signal on the bus.
  8. The instrument cluster ECU receives and processes the frame.
  9. Its COM module extracts the vehicle speed signal.
  10. The RTE provides the received value to the instrument cluster SWC.

11. CAN Termination

High-speed CAN networks generally use two termination resistors, one at each physical end of the main bus.

  • Typical termination resistor: 120 ohms.
  • Two 120-ohm resistors appear in parallel when measured across the bus with the network powered down and correctly connected.
  • Expected equivalent resistance is approximately 60 ohms.

The resistance check is a useful troubleshooting test, but the expected reading depends on network topology and whether other devices or termination arrangements are connected.

13. Common Placement Interview Questions

Q1. What is CAN?

Answer: CAN is a serial, message-based communication protocol widely used for communication between automotive ECUs.

Q2. What is the difference between CAN controller and CAN transceiver?

Answer: The controller handles CAN protocol functions, while the transceiver provides the electrical interface to the CAN bus.

Q3. What is the standard CAN identifier length?

Answer: 11 bits.

Q4. What is the extended CAN identifier length?

Answer: 29 bits.

Q5. What is CAN arbitration?

Answer: It is the process by which multiple transmitting nodes resolve bus access using bitwise priority comparison without destroying the winning frame.

Q6. What is a dominant bit?

Answer: A dominant bit represents logical 0 and overrides a recessive bit on the CAN bus.

Q7. What is the typical CAN termination resistance?

Answer: Two 120-ohm termination resistors are commonly used, producing approximately 60 ohms measured across CAN_H and CAN_L when powered down.

Q8. What is the role of CanIf?

Answer: CanIf provides a standardized interface between upper communication modules and CAN hardware drivers.

Q9. What is a CAN bus-off condition?

Answer: It is an error-confinement state entered by a CAN controller after its transmit error counter exceeds the protocol-defined threshold.

Q10. Explain CAN communication in AUTOSAR.

Answer: A typical transmit path is SWC → RTE → COM → PduR → CanIf → CAN Driver → CAN Controller → Transceiver → CAN Bus.

14. Lesson Summary

  • CAN is a message-based automotive communication protocol.
  • Multiple ECUs share the CAN bus.
  • CAN uses dominant and recessive bus states.
  • Standard and extended identifiers are 11-bit and 29-bit respectively.
  • CAN arbitration resolves simultaneous transmission attempts.
  • The CAN controller handles protocol functions.
  • The transceiver provides the electrical bus interface.
  • AUTOSAR uses COM, PduR, CanIf and CAN Driver modules for communication.
