Lesson 1: Three-Layered AUTOSAR Architecture

Chapter 2 – AUTOSAR Classic Platform Architecture

Application Layer | RTE | Basic Software

1. Introduction

AUTOSAR Classic Platform uses a layered software architecture to organize automotive ECU software. Each layer has a defined responsibility and interacts with other layers through standardized interfaces.

The three major layers are:

  • Application Layer
  • Runtime Environment (RTE)
  • Basic Software (BSW)

The microcontroller hardware is located below the software architecture and is accessed through appropriate BSW modules and drivers.

3. Application Layer

The Application Layer contains Software Components responsible for implementing vehicle functions.

Examples of Application Components

  • Engine control component
  • Vehicle speed monitoring component
  • Temperature monitoring component
  • Headlamp control component
  • Wiper control component
  • Battery monitoring component

Important Characteristics

  • Application logic is divided into modular SWCs.
  • SWCs communicate using ports and interfaces.
  • SWCs use RTE interfaces to access communication and services.
  • Application functionality is separated from low-level hardware drivers.
Example: A temperature-control SWC receives temperature data and determines whether the cooling fan should be switched ON or OFF.

4. Runtime Environment (RTE)

RTE acts as the communication infrastructure between Application Software Components and the underlying Basic Software.

Functions of RTE

  • Provides communication between SWCs.
  • Connects sender-receiver ports.
  • Supports client-server communication.
  • Provides generated APIs for SWCs.
  • Connects application components with configured BSW services.
  • Supports communication across software component boundaries.
Example: A temperature-monitoring SWC sends a temperature value to a fan-control SWC through a configured sender-receiver communication interface provided by the RTE.

5. Basic Software (BSW)

BSW provides the system services, communication functionality and hardware abstraction needed to operate the ECU.

Main BSW Areas

A. Services Layer

  • Operating System
  • Diagnostic Services
  • Communication Services
  • Memory Services
  • ECU State Management

B. ECU Abstraction Layer

Provides interfaces that abstract ECU-specific hardware devices from upper software layers.

C. Microcontroller Abstraction Layer (MCAL)

Provides standardized drivers for microcontroller peripherals such as ADC, DIO, PWM, SPI and CAN.

D. Complex Drivers

Supports specialized hardware functionality that cannot be conveniently implemented using standard BSW modules.

6. Role of Microcontroller Hardware

The microcontroller executes the ECU software and provides the hardware peripherals needed for sensing, processing and communication.

  • CPU executes program instructions.
  • Flash stores program code and non-volatile data.
  • RAM stores temporary data and runtime variables.
  • ADC converts analog signals into digital values.
  • GPIO controls and reads digital signals.
  • Timers provide timing and counting functions.
  • CAN peripherals support vehicle network communication.

8. Comparison of the Three Main Layers

Layer Purpose Examples
Application Layer Implements vehicle functions. Temperature control, headlamp control
RTE Provides communication and interfaces. SWC communication, generated APIs
BSW Provides system services and hardware abstraction. OS, diagnostics, MCAL, communication drivers

9. Advantages of Layered Architecture

  • Modularity: Software is divided into manageable components.
  • Reusability: Application components can be reused across suitable ECU projects.
  • Hardware abstraction: Application software is less dependent on specific hardware details.
  • Maintainability: Individual modules can be modified and tested more independently.
  • Standardization: Common interfaces support integration across suppliers.
  • Scalability: Architecture can support different ECU configurations.

10. Interview Questions and Answers

Q1. What are the three main layers of AUTOSAR Classic?

Application Layer, Runtime Environment and Basic Software.

Q2. What is the purpose of the Application Layer?

It contains Software Components that implement vehicle application functions.

Q3. What is the purpose of RTE?

RTE provides communication between SWCs and access to configured BSW services.

Q4. What does BSW stand for?

BSW stands for Basic Software.

Q5. Which layer contains MCAL?

MCAL is part of the Basic Software layer.

Q6. What is the function of MCAL?

MCAL provides standardized access to microcontroller peripherals through drivers.

Q7. Does RTE directly control hardware pins?

No. RTE provides software interfaces. Hardware control is performed through the configured BSW and driver path.

Q8. Why is AUTOSAR divided into layers?

To separate responsibilities, support modularity, improve reusability and reduce hardware dependency.

Q9. What is the difference between ECU Abstraction and MCAL?

MCAL abstracts microcontroller peripherals, whereas ECU Abstraction provides interfaces for ECU-specific hardware devices.

Q10. What is a Software Component?

A SWC is a modular application software unit with defined ports, interfaces and behavior.

11. Lesson Summary

  • AUTOSAR Classic follows a layered software architecture.
  • Application Layer contains vehicle-function SWCs.
  • RTE provides communication and service interfaces.
  • BSW contains services and hardware abstraction modules.
  • MCAL provides microcontroller peripheral drivers.
  • ECU Abstraction handles ECU-specific hardware interfaces.
  • Layering supports modularity, reusability and integration.
