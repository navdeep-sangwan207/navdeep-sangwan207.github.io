1. Introduction to MCAL

MCAL stands for Microcontroller Abstraction Layer. It is a part of the AUTOSAR Basic Software (BSW) that provides standardized software drivers for microcontroller peripherals.

MCAL hides many microcontroller-specific register and hardware details from upper software layers. It provides standardized interfaces to access supported microcontroller peripherals.

Main Responsibilities

  • Provide drivers for microcontroller peripherals.
  • Abstract hardware register-level operations.
  • Support hardware-independent upper software interfaces.
  • Provide configured peripheral initialization.
  • Support communication, timing and signal acquisition.

MCAL is the lowest standard BSW abstraction layer above the microcontroller hardware. Some hardware functions may instead use Complex Drivers.

3. Why is MCAL Required?

Different microcontrollers have different registers, peripheral architectures and hardware implementations. Directly accessing these details from application software would make software difficult to reuse.

MCAL helps by:

  • Providing standardized driver interfaces.
  • Reducing direct register-level dependencies.
  • Supporting migration between compatible microcontroller platforms.
  • Improving software modularity.
  • Supporting configuration-based development.
  • Making peripheral access easier to integrate.
Example: An application uses configured software interfaces instead of directly writing to a microcontroller's ADC control registers.

4. Important MCAL Drivers

A. Port Driver

The Port Driver configures microcontroller pins for their required functions.

Typical configuration includes:

  • Pin direction and pin mode, where supported.
  • Pin multiplexing.
  • Electrical configuration options supported by the MCU.
  • Peripheral pin assignment.
Automotive example: Configure microcontroller pins for CAN communication, PWM output or digital input.

B. Digital Input Output (DIO) Driver

DIO provides digital input and output operations for configured microcontroller pins and channels.

Typical functions include:

  • Read a digital input.
  • Write a digital output.
  • Read a configured port.
  • Write a configured port.
  • Toggle an output channel where supported.
Automotive example: Read a door switch input or control a digital output connected to an indicator circuit.

C. ADC Driver

ADC stands for Analog-to-Digital Converter. The ADC driver controls configured ADC hardware and supports acquisition of analog signals.

Applications include:

  • Temperature sensor measurement.
  • Battery voltage monitoring.
  • Pressure sensor measurement.
  • Analog pedal sensor acquisition.
Example: An analog sensor voltage is converted into a digital value using the microcontroller ADC.

D. PWM Driver

PWM stands for Pulse Width Modulation. The PWM driver configures and controls supported PWM hardware channels.

Applications include:

  • Cooling fan speed control.
  • Motor control.
  • LED brightness control.
  • Actuator control.

E. General Purpose Timer (GPT) Driver

GPT provides access to configured general-purpose timer hardware.

Typical uses include:

  • Timer initialization.
  • Starting and stopping timers.
  • Reading timer values.
  • Timer notification and timeout handling.

F. SPI Driver

SPI stands for Serial Peripheral Interface. The SPI driver manages configured SPI hardware communication.

Typical applications include communication with:

  • External memory devices.
  • Sensor ICs.
  • Peripheral controllers.
  • Other SPI-compatible devices.

G. CAN Driver

The CAN driver provides access to the microcontroller's CAN controller hardware.

Typical functions include:

  • CAN controller initialization.
  • CAN message transmission.
  • CAN message reception.
  • Controller state management.
  • CAN interrupt handling.
Automotive example: An engine ECU transmits vehicle information through the CAN network.

6. MCAL Configuration and Initialization

MCAL drivers are configured according to the microcontroller, peripheral requirements and ECU design.

Typical Development Steps

  1. Select the supported microcontroller and development platform.
  2. Configure required peripheral drivers.
  3. Set pin assignments and peripheral parameters.
  4. Configure required clocks and interrupt settings.
  5. Generate driver configuration files.
  6. Integrate MCAL with the remaining BSW modules.
  7. Compile and build the ECU software.
  8. Test peripheral functionality on the target hardware.

Generated configuration files and initialization functions vary by MCAL vendor and development tool.

8. MCAL vs ECU Abstraction

MCAL ECU Abstraction
Abstracts microcontroller peripherals. Abstracts ECU-specific hardware devices.
Provides drivers for internal MCU peripherals. Provides interfaces for external or ECU-specific devices.
Examples: ADC, DIO, PWM, SPI, CAN. Examples: external memory and external watchdog interfaces.
Located close to microcontroller hardware. Located above MCAL in the BSW architecture.

9. Practical C Example: Digital Output

The following is a generic embedded C example illustrating digital output control. It is not an AUTOSAR MCAL API implementation. 

#include <stdio.h>

int main(void)
{
    int led = 0;

    led = 1;

    if (led == 1)
    {
        printf("LED ON\n");
    }

    return 0;
}

Expected Output

LED ON

In an AUTOSAR project, a configured DIO driver would be used for the actual microcontroller digital output operation.

10. Interview Questions and Answers

Q1. What is MCAL?

MCAL stands for Microcontroller Abstraction Layer. It provides standardized drivers for microcontroller peripherals.

Q2. Where is MCAL located?

MCAL is part of the Basic Software layer and is located close to microcontroller hardware.

Q3. What is the function of the DIO driver?

It provides digital input and output operations for configured microcontroller pins and channels.

Q4. What is the function of the ADC driver?

It provides access to the microcontroller's configured analog-to-digital conversion hardware.

Q5. What is the purpose of the PWM driver?

It configures and controls supported PWM hardware channels.

Q6. What is the GPT driver?

GPT provides access to general-purpose timer hardware for timing operations.

Q7. What is the function of the SPI driver?

It manages configured SPI peripheral communication.

Q8. What is the function of the CAN driver?

It provides software access to the microcontroller's CAN controller.

Q9. Why is MCAL important?

It reduces hardware-specific dependencies and supports standardized peripheral access.

Q10. What is the difference between MCAL and ECU Abstraction?

MCAL abstracts microcontroller peripherals, while ECU Abstraction provides interfaces for ECU-specific hardware devices.

11. Lesson Summary

  • MCAL means Microcontroller Abstraction Layer.
  • It is part of AUTOSAR Basic Software.
  • It provides standardized microcontroller drivers.
  • Important drivers include Port, DIO, ADC, PWM, GPT, SPI and CAN.
  • MCAL hides many low-level peripheral implementation details.
  • Driver configuration is specific to the microcontroller and ECU project.
  • ECU Abstraction is located above MCAL.
