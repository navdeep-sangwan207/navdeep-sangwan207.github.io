1. Introduction to Basic Software

BSW stands for Basic Software. It is the lower software layer of the AUTOSAR Classic Platform and provides the infrastructure required for application software to operate.

BSW provides standardized services, communication functionality, memory management, diagnostic functionality and hardware abstraction.

Main Responsibilities

  • Provide operating system services.
  • Manage ECU initialization and operating modes.
  • Provide communication stack functionality.
  • Support diagnostic communication and fault management.
  • Provide memory services.
  • Abstract microcontroller and ECU-specific hardware.
  • Provide drivers for hardware peripherals.

3. Main BSW Sublayers

A. Services Layer

The Services Layer provides common system services required by application software and other BSW modules.

Important services include:

  • Operating System (OS)
  • ECU State Manager (EcuM)
  • BSW Mode Manager (BswM)
  • Diagnostic Event Manager (DEM)
  • Diagnostic Communication Manager (DCM)
  • Communication Services
  • Memory Services

B. ECU Abstraction Layer

ECU Abstraction provides interfaces that hide details of ECU-specific hardware devices.

Examples include:

  • External EEPROM abstraction
  • External flash memory abstraction
  • External watchdog abstraction
  • Interfaces for other ECU-specific hardware

C. Microcontroller Abstraction Layer (MCAL)

MCAL provides standardized drivers for the microcontroller's internal peripherals.

Examples include:

  • Port Driver
  • DIO Driver
  • ADC Driver
  • PWM Driver
  • GPT Driver
  • SPI Driver
  • CAN Driver

D. Complex Drivers

Complex Drivers support special hardware functions that cannot be conveniently implemented using standard BSW modules.

4. Important BSW Modules

A. Operating System (OS)

The AUTOSAR OS manages task execution, scheduling, alarms, counters, events, resources and interrupt handling according to the configured OS model.

B. ECU State Manager (EcuM)

EcuM manages ECU initialization, startup and shutdown sequences, as well as related ECU state transitions.

C. BSW Mode Manager (BswM)

BswM coordinates mode-related requests and executes configured rules and actions to coordinate BSW module behavior.

D. Diagnostic Event Manager (DEM)

DEM manages diagnostic events, event status information and diagnostic trouble code information according to configuration.

E. Diagnostic Communication Manager (DCM)

DCM handles diagnostic communication requests from external diagnostic clients and provides configured diagnostic services, including UDS.

F. Communication Modules

Communication modules support vehicle network communication such as CAN-based data exchange. Examples include COM, PDU Router, CAN Interface and CAN Transport Protocol.

G. Memory Modules

Memory services manage access to configured non-volatile memory and support storage of application and diagnostic data.

7. Example: ECU Startup Sequence

Consider an ECU that starts after the vehicle ignition is switched ON.

  1. The microcontroller begins execution after reset.
  2. Startup code performs required low-level initialization.
  3. ECU Manager coordinates configured initialization activities.
  4. Required BSW modules are initialized.
  5. The operating system starts scheduling configured tasks.
  6. Application software begins executing through configured runnable activation.
  7. The ECU performs its required vehicle functions.
Important: The exact startup sequence depends on ECU configuration, startup code, EcuM configuration and BSW integration.

8. MCAL vs ECU Abstraction vs Services

BSW Area Responsibility Example
Services Layer Provides common system services. OS, DEM, DCM, EcuM
ECU Abstraction Abstracts ECU-specific hardware. External memory device interface
MCAL Abstracts microcontroller peripherals. ADC, DIO, PWM, SPI, CAN
Complex Drivers Provides specialized hardware functionality. Special-purpose hardware driver

9. Advantages of BSW

  • Provides standardized system services.
  • Reduces direct hardware dependency in application software.
  • Supports communication between ECUs.
  • Provides diagnostic and fault-management capabilities.
  • Supports memory and operating system services.
  • Improves modularity and integration.
  • Supports reuse of compatible software modules.

10. Interview Questions and Answers

Q1. What is BSW in AUTOSAR?

BSW stands for Basic Software. It provides system services, communication functionality and hardware abstraction.

Q2. What are the major BSW areas?

Services Layer, ECU Abstraction Layer, MCAL and Complex Drivers.

Q3. What is the purpose of EcuM?

It manages ECU startup, initialization, shutdown and related state transitions.

Q4. What is BswM?

BswM coordinates mode-related requests and executes configured rules and actions.

Q5. What is DEM?

DEM manages diagnostic events and related diagnostic trouble code information.

Q6. What is DCM?

DCM handles diagnostic communication between an external diagnostic client and the ECU.

Q7. What is the role of COM?

COM handles configured signal-level communication and mapping to I-PDUs.

Q8. What is PduR?

PduR routes Protocol Data Units between configured communication modules.

Q9. Which BSW area contains the CAN driver?

The CAN driver is part of MCAL.

Q10. What is the difference between MCAL and ECU Abstraction?

MCAL provides drivers for microcontroller peripherals, whereas ECU Abstraction provides interfaces for ECU-specific hardware.

11. Lesson Summary

  • BSW is the infrastructure layer of AUTOSAR Classic.
  • Services Layer provides OS, diagnostics, communication and memory services.
  • EcuM manages ECU startup and shutdown activities.
  • BswM coordinates configured BSW mode behavior.
  • DEM manages diagnostic events and DTC information.
  • DCM handles diagnostic communication.
  • ECU Abstraction hides ECU-specific hardware details.
  • MCAL provides microcontroller peripheral drivers.
  • Complex Drivers support specialized hardware functions.
