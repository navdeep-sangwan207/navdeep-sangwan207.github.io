1. Introduction

The Application Layer is the top software layer of the AUTOSAR Classic Platform. It contains application software responsible for implementing vehicle functions.

Application functionality is divided into modular units called Software Components (SWCs). These components communicate through defined ports and interfaces using the Runtime Environment (RTE).

Examples of application functions include:

  • Engine temperature monitoring
  • Vehicle speed calculation
  • Headlamp control
  • Wiper control
  • Battery monitoring
  • Cooling fan control

3. Software Components (SWCs)

A Software Component is a modular unit of AUTOSAR application software. It contains application behavior and communicates through defined interfaces.

Characteristics of SWCs

  • Represent specific application functionality.
  • Have defined ports and interfaces.
  • Contain one or more runnable entities.
  • Communicate through RTE mechanisms.
  • Can be configured and integrated into an ECU.
  • Can be reused when their interfaces and dependencies are compatible.

Examples of SWCs

Temperature Monitoring SWC: Receives temperature data and determines whether the engine temperature is within an acceptable range.
Fan Control SWC: Receives a cooling request and determines the required fan operating state.
Vehicle Speed SWC: Processes vehicle speed information and provides the calculated speed to other application components.

4. Types of Software Components

A. Application Software Component

Implements a particular vehicle function, such as engine control, temperature monitoring or lighting control.

B. Sensor/Actuator Software Component

Represents an application-level abstraction of sensor or actuator functionality. It helps separate application behavior from hardware-specific details.

C. Composition Software Component

Groups multiple software components into a larger logical structure. It describes how the contained components are connected.

D. Service Software Component

Represents application-level access to certain services, where supported by the AUTOSAR model and system design.

Note: These are common component concepts. Exact component classifications and available interfaces depend on the AUTOSAR specification and project configuration.

5. Ports in AUTOSAR

A port is an interaction point through which a Software Component communicates with other components or accesses required functionality.

Two important port types are:

A. Provide Port (P-Port)

A Provide Port offers an interface or functionality to another component.

B. Require Port (R-Port)

A Require Port requests or consumes functionality provided by another component.

6. Interfaces in AUTOSAR

An interface defines the communication contract between software components. It specifies what information or operations are exchanged.

A. Sender-Receiver Interface

Used to exchange data between software components. One component sends data and another receives it.

Example: A temperature-monitoring SWC sends an engine temperature value to a fan-control SWC.

B. Client-Server Interface

Used when one component requests an operation from another component.

Example: A client component requests a diagnostic-related operation from a server component through a configured client-server interface.

Comparison

Sender-Receiver Client-Server
Exchanges data elements. Invokes operations.
Sender provides data. Client requests an operation.
Receiver consumes data. Server provides the requested operation.
Example: temperature value. Example: request a calculation or service.

7. Runnables and Runnable Entities

A Runnable Entity is an executable unit of behavior inside a Software Component. It contains the application code that performs a particular task.

Runnable entities are executed when configured events trigger them. Their execution is mapped to operating system tasks during ECU configuration.

Common Runnable Activation Events

  • Timing Event: Activates a runnable periodically or at a configured time interval.
  • Data Received Event: Activates a runnable when configured data is received.
  • Operation Invoked Event: Activates a runnable when a client-server operation is invoked.
  • Init Event: Activates initialization behavior.
Example: A temperature-monitoring runnable may execute every 100 milliseconds to process the latest temperature data.

9. Simple Application Logic Example in C

The following is a conceptual example of application logic. It illustrates the decision-making performed by a temperature-control component; it is not a complete AUTOSAR-generated RTE application. 

#include <stdio.h>

void FanControl(float temperature)
{
    if (temperature >= 90.0f)
    {
        printf("Cooling Fan: ON\n");
    }
    else
    {
        printf("Cooling Fan: OFF\n");
    }
}

int main(void)
{
    float engineTemperature = 95.0f;

    FanControl(engineTemperature);

    return 0;
}

Expected Output

Cooling Fan: ON

In a real AUTOSAR project, the application component would use generated RTE interfaces rather than directly implementing the complete hardware-control path.

10. Why is the Application Layer Important?

  • Separates vehicle functionality from hardware drivers.
  • Supports modular application development.
  • Allows reuse of suitable software components.
  • Defines standardized communication interfaces.
  • Supports integration of components from different suppliers.
  • Improves software maintenance and testing.

11. Interview Questions and Answers

Q1. What is the AUTOSAR Application Layer?

It is the top software layer containing Software Components that implement vehicle functions.

Q2. What is an SWC?

A Software Component is a modular application software unit with defined interfaces and behavior.

Q3. What is a port?

A port is an interaction point through which an SWC communicates with other components or accesses functionality.

Q4. What is the difference between P-Port and R-Port?

A P-Port provides functionality, while an R-Port requires or consumes functionality.

Q5. What is a Sender-Receiver Interface?

It is an interface used for data exchange between software components.

Q6. What is a Client-Server Interface?

It allows a client component to request an operation provided by a server component.

Q7. What is a Runnable Entity?

It is an executable unit of behavior inside an SWC that runs when configured events trigger it.

Q8. What is a Timing Event?

It activates a runnable according to a configured time schedule.

Q9. How do two SWCs communicate?

They communicate through configured ports and interfaces using RTE mechanisms.

Q10. Does an SWC normally access hardware registers directly?

No. Application components normally use RTE interfaces and configured BSW services to access required functionality.

12. Lesson Summary

  • Application Layer contains Software Components.
  • SWCs implement automotive application functionality.
  • Ports define interaction points.
  • P-Ports provide functionality; R-Ports require functionality.
  • Interfaces define communication contracts.
  • Sender-Receiver interfaces exchange data.
  • Client-Server interfaces support operation requests.
  • Runnable Entities contain executable application behavior.
  • RTE provides configured communication between SWCs.
