Lesson 5: AUTOSAR ECU Software Architecture

Chapter 1 – Introduction to AUTOSAR

Classic AUTOSAR Software Architecture

1. Introduction to ECU Software Architecture

An Electronic Control Unit (ECU) is an embedded computing system used to monitor and control specific vehicle functions. It consists of hardware and software working together.

AUTOSAR Classic defines a standardized software architecture that separates application functionality from hardware-dependent implementation.

The architecture makes use of three major software layers:

  • Application Layer
  • Runtime Environment (RTE)
  • Basic Software (BSW)

The RTE separates application components from the underlying BSW implementation through generated communication and service interfaces.

3. Application Layer

The Application Layer contains Software Components (SWCs) responsible for implementing vehicle functions.

Examples include:

  • Engine temperature monitoring
  • Vehicle speed calculation
  • Headlamp control
  • Wiper control
  • Battery monitoring
  • Motor control logic

Software Components (SWCs)

A Software Component is a modular unit of application software with defined interfaces and behavior.

SWCs communicate through ports and interfaces. They do not normally access hardware registers directly.

Example: A temperature-monitoring SWC receives temperature data, checks whether it exceeds a configured limit and sends a fan-control request through its defined interface.

4. Runtime Environment (RTE)

The Runtime Environment is the communication layer between application software components and the underlying Basic Software.

Functions of RTE

  • Provides communication between software components.
  • Connects SWC ports to corresponding interfaces.
  • Provides access to required BSW services.
  • Supports sender-receiver communication.
  • Supports client-server communication.
  • Provides generated APIs for application components.
Example: A sensor-processing SWC sends a temperature value to another SWC through a sender-receiver interface. The RTE provides the configured communication mechanism.

5. Basic Software (BSW)

Basic Software provides infrastructure services and hardware abstraction required by application software.

It is organized into major functional areas:

A. Services Layer

Provides common system services required by the ECU.

  • Operating System
  • Diagnostic Services
  • Communication Services
  • Memory Services
  • ECU State Management

B. ECU Abstraction Layer

Provides standardized interfaces to ECU hardware devices that are not part of the microcontroller itself, helping hide hardware-specific details.

Examples include interfaces for:

  • External EEPROM
  • External flash memory
  • External watchdog devices
  • Other ECU-specific hardware devices

C. Microcontroller Abstraction Layer (MCAL)

MCAL provides standardized access to microcontroller peripherals.

Common driver examples include:

  • Port and DIO drivers
  • ADC driver
  • PWM driver
  • GPT driver
  • SPI driver
  • CAN driver

D. Complex Drivers

Complex Drivers provide special hardware access or functionality that cannot be conveniently implemented using standard BSW modules.

They may access hardware through specialized interfaces and can have different integration requirements.

6. Microcontroller Hardware

The microcontroller is the processing unit of the ECU. It executes the embedded software and controls the connected hardware peripherals.

Typical microcontroller components include:

  • CPU core
  • Flash memory
  • RAM
  • GPIO
  • ADC
  • Timers and PWM
  • UART, SPI and I2C
  • CAN controller
  • Interrupt controller

The MCAL drivers provide software interfaces to supported microcontroller peripherals.

7. How the AUTOSAR Layers Work Together

Consider an ECU that monitors engine temperature and controls a cooling fan.

  1. An analog temperature sensor produces an electrical signal.
  2. The MCAL ADC driver performs the configured analog-to-digital conversion.
  3. The BSW and RTE provide the configured data access path.
  4. The temperature-monitoring SWC processes the temperature value.
  5. The application decides whether the cooling fan should operate.
  6. A fan-control SWC communicates the requested operating state.
  7. The configured BSW and MCAL output path controls the hardware.
Important: This is a conceptual flow. Actual sensor acquisition, data conversion, SWC communication and actuator control depend on the ECU configuration and system design.

8. Comparison of AUTOSAR Software Layers

Layer Main Responsibility

9. Interview Questions and Answers

Q1. What are the three major layers of AUTOSAR Classic?

Application Layer, Runtime Environment (RTE) and Basic Software (BSW).

Q2. What is the responsibility of the Application Layer?

It implements vehicle functions using modular Software Components.

Q3. What is the function of RTE?

RTE provides communication between SWCs and access to configured Basic Software services.

Q4. What is BSW?

BSW is the Basic Software layer that provides common services, communication functionality and hardware abstraction.

Q5. What is the difference between MCAL and ECU Abstraction?

MCAL abstracts microcontroller peripherals, whereas ECU Abstraction provides interfaces to ECU-specific hardware devices.

Q6. What are Complex Drivers?

They are specialized drivers used when particular hardware functionality cannot be conveniently implemented using standard BSW modules.

Q7. Does the Application Layer directly access microcontroller registers?

Normally, no. It uses configured RTE interfaces and BSW services to access required functionality.

Q8. Which layer contains the ADC driver?

The ADC driver is part of the Microcontroller Abstraction Layer (MCAL).

Q9. Where is the AUTOSAR OS located?

It is part of the Basic Software Services Layer.

Q10. Why is AUTOSAR architecture layered?

Layering separates software responsibilities, reduces direct hardware dependency and supports modular development and integration.

10. Lesson Summary

  • AUTOSAR Classic uses Application, RTE and BSW layers.
  • Application software is organized into SWCs.
  • RTE provides communication and service interfaces.
  • BSW provides system services and hardware abstraction.
  • MCAL provides access to microcontroller peripherals.
  • ECU Abstraction handles ECU-specific hardware interfaces.
  • Complex Drivers support specialized hardware functionality.
  • The microcontroller executes the ECU firmware and controls peripherals.
