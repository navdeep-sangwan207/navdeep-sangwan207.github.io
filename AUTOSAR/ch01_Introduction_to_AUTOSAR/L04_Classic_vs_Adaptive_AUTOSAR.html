Lesson 4: Classic vs Adaptive AUTOSAR

Chapter 1 – Introduction to AUTOSAR

Automotive Software Platform Comparison

1. Introduction

AUTOSAR provides two major platform families: Classic Platform and Adaptive Platform.

Both platforms provide standardized software architectures for automotive systems, but they address different hardware, software and application requirements.

  • Classic Platform: Designed primarily for deeply embedded, resource-constrained and real-time ECU applications.
  • Adaptive Platform: Designed for high-performance automotive computing systems that require dynamic applications and flexible software deployment.

2. Classic AUTOSAR

Classic AUTOSAR is designed for automotive ECUs that typically execute embedded software with predictable timing and resource requirements.

Important Characteristics

  • Designed for deeply embedded systems.
  • Supports real-time operation.
  • Uses a layered software architecture.
  • Uses Software Components (SWCs).
  • Uses the Runtime Environment (RTE).
  • Uses Basic Software (BSW) modules.
  • Supports standardized hardware abstraction through MCAL.
  • Uses an AUTOSAR OS based on OSEK concepts.

  • Engine control units
  • Transmission control units

  • Powertrain ECUs
  • Battery management controllers

3. Adaptive AUTOSAR

Adaptive AUTOSAR is designed for high-performance automotive computing systems that need more flexible application execution and communication.

Important Characteristics

  • Designed for high-performance computing platforms.
  • Supports dynamically deployed applications.
  • Uses a POSIX-based operating system environment.
  • Uses service-oriented communication concepts.
  • Provides standardized APIs for platform services.
  • Supports application lifecycle management.
  • Supports dynamic application deployment and updates.
  • Commonly uses C++ for application development.

Applications

  • High-performance computing ECUs
  • Advanced Driver Assistance Systems (ADAS)

  • Connected vehicle applications
  • Central vehicle computing platforms
  • Infotainment and other high-performance applications

4. Classic vs Adaptive AUTOSAR – Comparison

These are typical characteristics, not absolute restrictions. Actual hardware, languages, operating systems and communication technologies depend on the implementation and project.

5. Communication in Classic and Adaptive AUTOSAR

Classic Platform

Classic AUTOSAR supports communication using mechanisms such as Sender-Receiver and Client-Server interfaces. Its communication stack can handle technologies such as CAN, LIN, FlexRay and Ethernet, depending on the ECU and configured platform.

Adaptive Platform

Adaptive AUTOSAR emphasizes service-oriented communication. Applications can offer services or discover and consume services provided by other applications or systems.

Service-oriented communication commonly uses SOME/IP over automotive Ethernet, although the exact communication technology depends on the system design.

6. Real Automotive Examples

Example A: Engine Control ECU

An engine control ECU reads sensor inputs, calculates engine parameters and controls actuators under strict real-time requirements.

Classic AUTOSAR is commonly suitable for this type of deeply embedded control application.

Example B: ADAS Computing Platform

An ADAS computing platform may process camera, radar and other sensor information using high-performance processors and complex software applications.

Adaptive AUTOSAR can provide a suitable software architecture for this type of system.

Remember: A vehicle may contain ECUs using different AUTOSAR platforms. Classic and Adaptive systems can coexist and communicate through appropriately designed vehicle networks and interfaces.

7. Important Technical Terms

  • SWC: Software Component used in Classic AUTOSAR.
  • RTE: Runtime Environment in Classic AUTOSAR.
  • BSW: Basic Software layer in Classic AUTOSAR.
  • MCAL: Microcontroller Abstraction Layer.
  • ARA: AUTOSAR Runtime for Adaptive Applications.
  • POSIX: Standard interface family for operating-system services.
  • SOME/IP: Scalable service-Oriented MiddlewarE over IP.
  • ECU: Electronic Control Unit.

8. Interview Questions and Answers

Q1. What are the two major AUTOSAR platforms?

Classic Platform and Adaptive Platform.

Q2. What is Classic AUTOSAR?

It is an AUTOSAR platform designed mainly for deeply embedded, resource-constrained and real-time automotive ECUs.

Q3. What is Adaptive AUTOSAR?

It is an AUTOSAR platform designed for high-performance automotive computing systems with flexible application execution and deployment.

Q4. What is the difference between RTE and ARA?

RTE is the Runtime Environment used in Classic AUTOSAR. ARA is the AUTOSAR Runtime for Adaptive Applications.

Q5. Which platform is commonly used for engine control ECUs?

Classic AUTOSAR is commonly used for deeply embedded real-time engine control ECUs.

Q6. Which operating system environment does Adaptive AUTOSAR use?

It uses a POSIX-based operating system environment.

Q7. What is service-oriented communication?

It is a communication approach in which applications offer and consume services through defined interfaces.

Q8. Can Classic and Adaptive AUTOSAR coexist in one vehicle?

Yes. Different ECUs can use different AUTOSAR platforms and communicate through suitable vehicle network architectures and gateways.

Q9. Which language is commonly used in Classic AUTOSAR?

Embedded C is commonly used for application and BSW development.

Q10. Which language is commonly used in Adaptive AUTOSAR?

C++ is commonly used for Adaptive Applications.

9. Lesson Summary

  • AUTOSAR provides Classic and Adaptive platform families.
  • Classic AUTOSAR targets deeply embedded real-time ECUs.
  • Adaptive AUTOSAR targets high-performance automotive computing.
  • Classic uses SWCs, RTE and BSW.
  • Adaptive uses Adaptive Applications and ARA.
  • Classic uses an AUTOSAR OS based on OSEK concepts.
  • Adaptive uses a POSIX-based OS environment.
  • Both platforms can coexist within a vehicle architecture.
