Lesson 3: AUTOSAR Standards and Partnership

Chapter 1 – Introduction to AUTOSAR

Automotive Software Standardization

1. Introduction to AUTOSAR Partnership

AUTOSAR is a worldwide development partnership involving organizations from the automotive industry, including vehicle manufacturers, automotive suppliers, semiconductor companies and software technology providers.

Its purpose is to develop and maintain standardized automotive software architectures, interfaces, methodologies and specifications.

AUTOSAR stands for Automotive Open System Architecture.

Example: An automotive OEM may define ECU application requirements, a semiconductor company may provide microcontroller-related software, and a software supplier may develop BSW modules. AUTOSAR specifications help these organizations work with common architectural concepts and interfaces.

2. Why Was the AUTOSAR Partnership Formed?

  • To establish common automotive software standards.
  • To reduce fragmentation in ECU software architectures.
  • To improve software component reuse.
  • To support collaboration between OEMs and suppliers.
  • To manage increasing automotive software complexity.
  • To define common interfaces and development methodology.

AUTOSAR specifications are developed collaboratively rather than being controlled by a single vehicle manufacturer or software supplier.

3. AUTOSAR Partnership Members

The AUTOSAR partnership includes different types of organizations that contribute to automotive software standardization.

A. Vehicle Manufacturers (OEMs)

Original Equipment Manufacturers develop and sell vehicles. They define vehicle-level requirements and ECU functionality.

Examples include BMW, Mercedes-Benz, Toyota and Volkswagen.

B. Automotive Suppliers

Suppliers develop automotive electronic systems, ECUs, sensors, actuators and embedded software.

C. Semiconductor Manufacturers

These organizations provide microcontrollers, processors and related development technologies used in automotive ECUs.

D. Software and Tool Providers

These organizations develop AUTOSAR software platforms, configuration tools, compilers, testing tools and integration environments.

Important distinction: AUTOSAR membership categories and organizational roles have evolved over time. The examples above describe industry roles, not a complete or current membership list.

4. AUTOSAR Standards and Specifications

AUTOSAR publishes technical specifications that define software architecture, module behavior, interfaces, configuration parameters and development methodology.

Important specification areas include:

  • Classic Platform specifications
  • Adaptive Platform specifications
  • Software Component descriptions
  • Runtime Environment specifications
  • Basic Software module specifications
  • Communication stack specifications
  • Diagnostic specifications
  • Methodology and XML schema specifications

Engineers use these specifications to configure, implement, integrate and validate AUTOSAR-based automotive software.

5. Important AUTOSAR Documents

1. Software Component Description

Describes software components, their ports, interfaces, data elements and communication requirements.

2. System Description

Describes the vehicle-level or system-level architecture, including ECUs, communication networks and system signals.

3. ECU Extract

Contains the relevant subset of system information needed for a particular ECU's development and configuration.

4. ECU Configuration Description

Contains ECU-specific configuration information for software modules and platform integration.

5. AUTOSAR XML (ARXML)

AUTOSAR uses XML-based descriptions to exchange architectural and configuration information between compatible tools.

Example: An ARXML description may define a software component, its sender-receiver interface, data elements and communication properties. An AUTOSAR tool can use this information during configuration and code generation.

6. AUTOSAR Development Workflow

  1. Define vehicle and ECU requirements.
  2. Create the system architecture.
  3. Define software components and their interfaces.
  4. Describe architecture and configuration using ARXML.
  5. Configure the RTE and BSW modules.
  6. Generate required software artifacts.
  7. Integrate software with the ECU hardware.
  8. Perform testing, debugging and validation.

The exact workflow and artifact exchange depend on the project, AUTOSAR platform, toolchain and organization.

7. AUTOSAR vs Proprietary Software Architecture

AUTOSAR Architecture Proprietary Architecture
Based on published AUTOSAR specifications. Based on organization-specific design.
Defines standardized architectural interfaces. Interfaces may be project-specific.
Supports interoperability between compatible implementations. Integration may require organization-specific adaptation.
Uses AUTOSAR methodology and artifacts. Uses the organization's own methodology and artifacts.

Proprietary architectures can also be modular, reusable and efficient. AUTOSAR's main distinction is its standardized automotive architecture and methodology.

8. Where to Find AUTOSAR Specifications

The official AUTOSAR website provides platform information, specifications, releases and partnership information.

Official website: https://www.autosar.org/

Engineers should use the specification release applicable to their project because module interfaces, configuration parameters and platform features can change between releases.

9. Interview Questions and Answers

Q1. What is the AUTOSAR partnership?

It is a worldwide automotive development partnership that creates and maintains standardized automotive software architectures and specifications.

Q2. Who participates in AUTOSAR?

Vehicle manufacturers, automotive suppliers, semiconductor companies and software and tool providers.

Q3. What is an AUTOSAR specification?

It is a technical document that defines architectural concepts, software interfaces, module behavior or development requirements.

Q4. What is ARXML?

ARXML is the AUTOSAR XML-based format used to describe and exchange software architecture and configuration information.

Q5. What is an ECU Extract?

It is a subset of system description information relevant to a particular ECU.

Q6. What is a System Description?

It describes the system-level architecture, including ECUs, communication networks and relevant system communication information.

Q7. Why are AUTOSAR specifications important?

They provide common technical definitions that help developers configure, implement and integrate compatible AUTOSAR software.

Q8. Is AUTOSAR a software company?

No. AUTOSAR is a development partnership that publishes specifications. Different member organizations develop tools and software implementations.

10. Lesson Summary

  • AUTOSAR is a worldwide automotive development partnership.
  • Its participants come from different areas of the automotive industry.
  • It develops and maintains automotive software specifications.
  • Important artifacts include Software Component Descriptions, System Descriptions and ECU Extracts.
  • ARXML is used to describe and exchange AUTOSAR information.
  • Developers follow AUTOSAR specifications and project-specific workflows.
  • Engineers should use the correct AUTOSAR release for their project.
