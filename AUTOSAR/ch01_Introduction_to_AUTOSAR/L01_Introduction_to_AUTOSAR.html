Lesson 1: Introduction to AUTOSAR

Chapter 1 – Introduction to AUTOSAR

Automotive Embedded Software Development

1. What is AUTOSAR?

AUTOSAR stands for Automotive Open System Architecture. It is a worldwide development partnership that provides standardized software architectures, interfaces and methodology for automotive electronic control units (ECUs).

AUTOSAR specifications help automotive manufacturers and suppliers develop reusable, scalable and interoperable automotive software.

It separates application software from hardware-dependent software through standardized interfaces and architectural layers.

Example: An automotive manufacturer can develop an engine-control application using AUTOSAR interfaces. A supplier can provide the underlying ECU hardware and basic software implementation. The application can be integrated with less dependence on the specific microcontroller, provided the required interfaces, configuration and platform compatibility are maintained.

2. Why is AUTOSAR Used in Automotive Systems?

Modern vehicles contain many ECUs responsible for different functions. Examples include:

  • Engine control unit
  • Transmission control unit
  • Anti-lock braking system (ABS)
  • Airbag control unit
  • Body control module (BCM)
  • Battery management system (BMS)
  • Advanced driver assistance systems (ADAS)

Developing each ECU using completely different software architectures increases development complexity. AUTOSAR provides common architectural concepts and standardized interfaces to help manage this complexity.

3. Main Features of AUTOSAR

  • Standardization: Provides common software architecture and interfaces.
  • Reusability: Supports reuse of software components across projects.
  • Scalability: Supports different ECU configurations and vehicle platforms.
  • Modularity: Organizes software into components and modules.
  • Portability: Reduces hardware dependency through abstraction layers.
  • Interoperability: Supports integration of software from different suppliers when compatible specifications and configurations are followed.

4. AUTOSAR Platforms

AUTOSAR provides two major platform families:

A. Classic Platform

The Classic Platform is designed mainly for deeply embedded, resource-constrained and real-time automotive ECUs.

Examples of application areas:

  • Engine and transmission control
  • Body control modules
  • Electronic braking systems
  • Powertrain control systems

B. Adaptive Platform

The Adaptive Platform is designed for high-performance automotive computing systems that require dynamic applications and more flexible software deployment.

Examples of application areas:

  • High-performance computing ECUs
  • Advanced driver assistance systems
  • Automotive gateways
  • Connected vehicle applications

Classic and Adaptive AUTOSAR are different platforms with different architectural concepts and execution environments.

5. Basic AUTOSAR Classic Architecture

The AUTOSAR Classic Platform is commonly explained using three major software layers:

Application Layer
↓
Runtime Environment (RTE)
↓
Basic Software (BSW)
↓
Microcontroller Hardware
  • Application Layer: Contains application software components that implement vehicle functions.
  • RTE: Provides communication between software components and access to platform services.
  • BSW: Provides standardized infrastructure, services, communication and hardware abstraction.

MCAL is a part of the BSW architecture. It provides standardized access to microcontroller peripherals.

The detailed architecture and responsibilities of each layer will be covered in Chapter 2.

6. AUTOSAR in a Real Automotive Example

Consider an ECU that controls an automotive cooling fan.

  1. A sensor provides temperature information.
  2. An application software component processes the temperature.
  3. The application determines the required fan operation.
  4. The RTE provides communication between software components and platform services.
  5. BSW and MCAL provide access to the required hardware resources.
  6. The microcontroller controls the fan through an appropriate driver circuit.
Important: AUTOSAR defines software architecture and interfaces. The actual fan power circuit, electrical protection and hardware design remain part of the ECU hardware implementation.

7. Important AUTOSAR Terminology

  • ECU: Electronic Control Unit.
  • SWC: Software Component.
  • RTE: Runtime Environment.
  • BSW: Basic Software.
  • MCAL: Microcontroller Abstraction Layer.
  • ARXML: XML-based format used for AUTOSAR descriptions and configuration artifacts.
  • OEM: Original Equipment Manufacturer.
  • UDS: Unified Diagnostic Services.

8. Interview Questions and Answers

Q1. What is AUTOSAR?

AUTOSAR is a worldwide automotive development partnership that provides standardized software architectures, interfaces and methodology for automotive ECUs.

Q2. What is the full form of AUTOSAR?

Automotive Open System Architecture.

Q3. Why is AUTOSAR required?

It helps manage automotive software complexity through standardization, modularity, reuse and defined interfaces.

Q4. What are the two major AUTOSAR platforms?

Classic Platform and Adaptive Platform.

Q5. What are the three major layers of AUTOSAR Classic?

Application Layer, Runtime Environment and Basic Software.

Q6. What is an ECU?

An Electronic Control Unit is an embedded computing system that controls or monitors specific vehicle functions.

Q7. What is MCAL?

MCAL is the Microcontroller Abstraction Layer. It provides standardized software interfaces to microcontroller peripherals.

Q8. Does AUTOSAR eliminate hardware dependency completely?

No. It reduces hardware dependency through abstraction and standardized interfaces, but hardware-specific configuration and integration are still required.

9. Lesson Summary

  • AUTOSAR means Automotive Open System Architecture.
  • It is a worldwide automotive development partnership.
  • It provides standardized software architecture and interfaces.
  • Classic and Adaptive are its major platform families.
  • Classic AUTOSAR uses Application, RTE and BSW layers.
  • MCAL provides access to microcontroller peripherals.
  • AUTOSAR supports reusable and scalable ECU software development.
