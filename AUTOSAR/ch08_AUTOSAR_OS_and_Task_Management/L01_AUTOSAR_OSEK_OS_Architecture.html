Lesson 1: AUTOSAR OS Architecture and Overview

Chapter 8 – AUTOSAR OS and Task Management

Understand the operating system architecture used in AUTOSAR Classic ECUs and its role in real-time automotive software.

1. Introduction to AUTOSAR OS

AUTOSAR OS is the operating system module used by the AUTOSAR Classic Platform to manage the execution of software tasks, interrupts, timing services and shared resources inside an Electronic Control Unit (ECU).

It provides a predictable execution environment for automotive embedded applications that must respond to events within specified time limits.

Why is an OS required in an automotive ECU?

  • Multiple software functions must execute on the same microcontroller.
  • Tasks require different execution priorities.
  • Time-critical operations must execute within deadlines.
  • Interrupts must be handled in a controlled manner.
  • Shared resources must be protected from conflicting access.
  • Software components require coordinated execution.

For example, an engine control ECU may need to process crankshaft sensor signals, calculate fuel injection timing, monitor engine temperature and communicate diagnostic information. These activities cannot all execute without an organized scheduling mechanism.

2. AUTOSAR OS and OSEK/VDX

AUTOSAR Classic OS is based on the concepts and services of the OSEK/VDX operating system standard.

OSEK/VDX was developed to provide a standardized real-time operating system interface for automotive electronic control units.

Important characteristics

  • Designed for embedded automotive systems.
  • Supports priority-based task scheduling.
  • Provides task and interrupt management.
  • Supports alarms, counters, events and resources.
  • Uses configuration-based system setup.
  • Designed for predictable real-time execution.
Placement note: AUTOSAR Classic OS is not equivalent to a general-purpose operating system such as desktop Windows or Linux. It is designed for resource-constrained, real-time automotive ECUs.

4. Main Responsibilities of AUTOSAR OS

1. Task Management

Creates and manages the execution of tasks. Tasks represent units of software execution scheduled by the OS.

2. Task Scheduling

Selects which ready task should execute based on configured scheduling rules and priorities.

3. Interrupt Management

Provides controlled handling of hardware and software interrupts.

4. Event Management

Allows extended tasks to wait for and respond to configured events.

5. Resource Management

Provides mechanisms for controlled access to shared resources and helps prevent priority-related synchronization problems.

6. Alarm and Counter Management

Provides timing mechanisms to activate tasks or set events after configured time intervals or counter conditions.

7. Schedule Table Management

Supports time-driven execution through predefined schedules containing expiry points and associated actions.

8. Error and Protection Management

Provides OS error handling and, where supported and configured, mechanisms for access control and protection of OS applications.

5. Main Components of AUTOSAR OS

Component Purpose
Tasks Execute application and Basic Software functions.
ISRs Handle hardware or software interrupt requests.
Counters Provide time bases for alarms and schedule tables.
Alarms Trigger task activation or event setting based on timing.
Events Allow extended tasks to wait for specific conditions.
Resources Control access to shared resources.
Schedule Tables Execute configured actions at defined expiry points.
OS Applications Group OS objects and support configured access protection where implemented.

These components are configured according to the ECU software architecture and the capabilities of the selected AUTOSAR OS implementation.

6. Static Configuration of AUTOSAR OS

AUTOSAR Classic OS is generally configured before the ECU software is built and deployed.

The configuration describes the OS objects and their relationships, such as:

  • Task names and priorities.
  • Task activation limits.
  • Task scheduling properties.
  • Interrupt configuration.
  • Alarm and counter definitions.
  • Events and resources.
  • Application-to-task mappings.
  • OS application access permissions, where supported.

10. Important OS Terminology

  • Task: A schedulable unit of execution.
  • Ready State: A task is eligible to execute when selected by the scheduler.
  • Running State: A task is currently executing.
  • Waiting State: An extended task is waiting for an event.
  • ISR: Interrupt Service Routine.
  • Priority: Scheduling importance assigned to an OS task or interrupt according to configuration.
  • Preemption: Interruption of a running task so another eligible higher-priority task can execute.
  • Resource: An OS mechanism for controlled access to shared resources.
  • Alarm: A timing object that triggers a configured action.
  • Counter: A time base used by timing services.

11. Placement-Oriented Interview Questions

Q1. What is AUTOSAR OS?

Answer: AUTOSAR OS is the real-time operating system module in the AUTOSAR Classic Platform. It manages tasks, scheduling, interrupts, events, resources and timing services.

Q2. Which OS standard is AUTOSAR Classic OS based on?

Answer: It is based on OSEK/VDX concepts and services.

Q3. In which AUTOSAR layer is OS located?

Answer: It is part of the Basic Software Services Layer.

Q4. What is the main purpose of task scheduling?

Answer: To select and execute eligible tasks according to configured scheduling rules and priorities.

Q5. What is the difference between RTE and OS?

Answer: RTE provides communication and runnable activation mechanisms for software components. OS manages task scheduling, interrupts and operating system services.

Q6. What is a real-time operating system?

Answer: An RTOS is designed to provide predictable responses to events and support execution within specified timing constraints.

Q7. What is static configuration in AUTOSAR OS?

Answer: It means OS objects and their properties are typically defined during configuration and generated before the ECU software is deployed.

Q8. Does AUTOSAR OS directly control hardware peripherals?

Answer: No. Peripheral control is generally provided by MCAL drivers and other configured BSW modules. The OS schedules the software that uses those services.

Q9. What is an ISR?

Answer: An ISR is an Interrupt Service Routine that executes in response to an interrupt request.

Q10. Why is AUTOSAR OS important in automotive ECUs?

Answer: It provides structured task execution, predictable scheduling, interrupt handling and synchronization for multiple real-time software functions.

12. Lesson Summary

  • AUTOSAR OS is part of the Classic Platform Basic Software Services Layer.
  • It is based on OSEK/VDX concepts.
  • It manages tasks, scheduling, interrupts, events and resources.
  • Alarms, counters and schedule tables provide timing services.
  • OS configuration is typically performed before software generation and deployment.
  • RTE coordinates runnable activation and communication; OS schedules tasks.
  • Its main purpose is predictable execution in automotive embedded systems.
