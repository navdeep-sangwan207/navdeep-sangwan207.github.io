Lesson 2: Tasks, Alarms and Counters

Chapter 8 – AUTOSAR OS and Task Management

Understand task types, task activation, alarm mechanisms and counter-based timing services in AUTOSAR Classic OS.

1. Introduction to Tasks

A task is a schedulable unit of execution managed by the AUTOSAR Operating System.

Tasks provide execution contexts for application and Basic Software activities. The OS scheduler determines when eligible tasks receive processor time.

Why are tasks required?

  • To execute multiple software activities on one microcontroller.
  • To organize periodic and event-driven processing.
  • To assign priorities to different activities.
  • To separate time-critical and non-time-critical functions.
  • To coordinate application and Basic Software execution.

Automotive example

An engine control ECU may execute separate activities for sensor acquisition, engine control calculations, CAN communication and diagnostic processing.

2. Types of AUTOSAR OS Tasks

AUTOSAR Classic OS provides two main task types:

Basic Task

A Basic Task does not support the OS event-waiting mechanism. It becomes ready when activated, executes when scheduled and terminates or is suspended according to its configured behavior.

Extended Task

An Extended Task supports OS events. It can wait for one or more events and become ready again when the required event condition is satisfied.

Feature Basic Task Extended Task
Event support No event waiting Supports event waiting
WaitEvent() Not permitted Supported
Waiting state Does not enter event-based WAITING state Can enter WAITING state
Typical use Periodic processing Event-driven processing
Scheduling Priority-based OS scheduling Priority-based OS scheduling
Placement point: The main distinction is event-based waiting. Basic Tasks cannot wait for OS events, whereas Extended Tasks can use WaitEvent() and related event services.

3. Task States

AUTOSAR OS task management uses four important task states:

State Description
SUSPENDED The task is inactive and has no pending activation.
READY The task is eligible to execute but is waiting for processor allocation.
RUNNING The task is currently executing.
WAITING An Extended Task is waiting for an event.

4. Important Task Management Services

OS Service Purpose
ActivateTask() Requests activation of a task.
TerminateTask() Terminates the calling task's current activation.
ChainTask() Terminates the calling task and activates another task as a chained operation.
Schedule() Provides a scheduling point according to OS scheduling rules.
GetTaskState() Retrieves the state of a specified task.
WaitEvent() Waits for configured events in an Extended Task.
SetEvent() Sets one or more events for an Extended Task.
ClearEvent() Clears specified events of the calling Extended Task.
GetEvent() Retrieves the current event mask of an Extended Task.

Conceptual task example

TASK(TemperatureTask)
{
    ReadTemperature();
    ProcessTemperature();

    TerminateTask();
}

This is illustrative AUTOSAR OS-style code. Actual task declarations, generated configuration and driver interfaces depend on the OS supplier and ECU project.

5. Introduction to OS Counters

A counter is an AUTOSAR OS timing object that maintains a count of ticks. Counters provide the time base used by alarms and schedule tables.

Purpose of counters

  • Provide a time reference for OS timing services.
  • Support periodic task activation.
  • Support delayed task activation.
  • Trigger configured events.
  • Provide timing information to schedule tables.

Types of counters

Counter Type Description
Hardware Counter Its progress is driven by a hardware timer or another configured hardware time base.
Software Counter Its progress is maintained through software-controlled counter increments.

The counter's tick duration, maximum allowed value and supported properties are defined in the OS configuration.

6. Counter Properties

Important counter configuration parameters include:

Parameter Meaning
MaxAllowedValue Maximum counter value before the counter wraps around.
TicksPerBase Number of hardware or software ticks associated with a counter base, according to the counter configuration.
MinCycle Minimum permitted cycle value for cyclic alarm operation.
Tick Duration Time represented by one counter tick.

7. Introduction to OS Alarms

An alarm is an AUTOSAR OS timing object associated with a counter. It triggers a configured action when its expiration condition is reached.

Alarm actions

An alarm can be configured to perform an action such as:

  • Activate a task.
  • Set an event for an Extended Task.

The alarm is linked to a counter and uses that counter's time base.

8. Relative and Absolute Alarms

Relative Alarm

A relative alarm is configured using a delay from the counter's current value.

Example: Set an alarm to expire after 100 counter ticks.

SetRelAlarm(
    TemperatureAlarm,
    100,
    0
);

Here:

  • TemperatureAlarm is the configured alarm.
  • 100 is the relative starting offset in ticks.
  • 0 indicates a one-shot alarm with no cyclic repetition.

Absolute Alarm

An absolute alarm is configured against a specified counter value.

SetAbsAlarm(
    TemperatureAlarm,
    500,
    0
);

The alarm is set to expire at the configured absolute counter value, subject to counter wraparound and OS rules.

Relative vs Absolute Alarm

Feature Relative Alarm Absolute Alarm
Reference Current counter value Specified counter value
Purpose Delay-based activation Activation at a particular counter reading
Typical example Activate after 100 ticks Activate at counter value 500
Note: The exact permitted offsets, cycle values and boundary conditions are defined by the applicable OS specification and counter configuration.

12. Common Errors and Troubleshooting

Problem Possible Cause
Task is not activated Alarm is not active or configured action is incorrect.
Alarm does not expire Associated counter is not progressing or alarm settings are invalid.
Alarm activation fails Alarm is already active or parameters violate configured limits.
Unexpected activation interval Incorrect tick duration or counter configuration.
Repeated activation fails Task activation limit or scheduling configuration issue.
Alarm cannot be cancelled Alarm identifier or alarm state is incorrect.

Debugging checklist

  • Verify the counter configuration and tick duration.
  • Check the alarm-to-counter association.
  • Verify the initial offset and cycle values.
  • Check the configured alarm action.
  • Inspect task activation limits and task state.
  • Check OS error hooks and debugging traces.

13. Placement-Oriented Interview Questions

Q1. What is a task in AUTOSAR OS?

Answer: A task is a schedulable unit of execution managed by the AUTOSAR OS.

Q2. What are the two main types of tasks?

Answer: Basic Tasks and Extended Tasks.

Q3. What is the difference between Basic and Extended Tasks?

Answer: Extended Tasks support event-based waiting, while Basic Tasks do not support the OS event-waiting mechanism.

Q4. What is an OS counter?

Answer: A counter maintains a count of ticks and provides the time base for alarms and schedule tables.

Q5. What is an OS alarm?

Answer: An alarm is a timing object associated with a counter that triggers a configured action when its expiration condition is reached.

Q6. Which service sets a relative alarm?

Answer: SetRelAlarm().

Q7. Which service sets an absolute alarm?

Answer: SetAbsAlarm().

Q8. What is the difference between relative and absolute alarms?

Answer: A relative alarm uses an offset from the current counter value, while an absolute alarm uses a specified counter value.

Q9. What is a cyclic alarm?

Answer: A cyclic alarm repeatedly triggers its configured action at a specified cycle interval.

Q10. What is the purpose of CancelAlarm()?

Answer: It cancels an active alarm.

Q11. Can an alarm activate a task?

Answer: Yes. An alarm can be configured to activate a task or set an event for an Extended Task.

Q12. What happens if a task reaches its activation limit?

Answer: Further activation requests may fail with an OS status indicating that the activation limit has been reached.

14. Lesson Summary

  • Tasks are schedulable units of execution in AUTOSAR OS.
  • Basic Tasks do not support event waiting.
  • Extended Tasks support event-based waiting.
  • Tasks move through SUSPENDED, READY, RUNNING and, for Extended Tasks, WAITING states.
  • Counters provide the time base for OS timing services.
  • Alarms trigger configured actions based on counter values.
  • SetRelAlarm() configures a relative alarm.
  • SetAbsAlarm() configures an absolute alarm.
  • One-shot alarms execute once; cyclic alarms repeat.
  • Alarms can activate tasks or set events.
