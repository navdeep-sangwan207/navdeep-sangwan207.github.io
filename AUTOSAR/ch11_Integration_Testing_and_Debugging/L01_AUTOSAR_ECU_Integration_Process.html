1. Introduction to ECU Integration

ECU integration is the process of combining individual software components, generated RTE code, Basic Software modules, microcontroller drivers and application software into a complete ECU software system.

AUTOSAR software is developed in separate layers and modules. These elements must be correctly configured, connected, compiled, linked and tested before the ECU can perform its intended functions.

Typical integration elements include:

  • Application Software Components (SWCs).
  • Runtime Environment (RTE).
  • Basic Software (BSW).
  • Microcontroller Abstraction Layer (MCAL).
  • AUTOSAR Operating System.
  • Generated configuration files.
  • Compiler, linker and startup software.
Important: Integration is more than compiling source files. It includes checking interfaces, configuration consistency, dependencies, execution behavior, communication and hardware interaction.

3. Main Objectives of ECU Integration

  • Combine independently developed software modules.
  • Verify compatibility between software interfaces.
  • Ensure correct RTE and BSW integration.
  • Verify MCAL driver configuration.
  • Resolve compilation and linking problems.
  • Verify communication between software components.
  • Check task scheduling and timing behavior.
  • Validate ECU functionality against requirements.

6. Software Component Integration

Application software components are integrated using their configured ports, interfaces, connections and execution behavior.

6.1 SWC Integration Activities

  • Import the required SWC descriptions.
  • Check provided and required ports.
  • Verify interface compatibility.
  • Check sender-receiver connections.
  • Check client-server connections.
  • Verify runnable entities and activation events.
  • Check component allocation to the ECU.

6.2 Example: Temperature and Fan Control

Temperature Sensor SWC
          |
          | Temperature Data
          v
     Fan Control SWC
          |
          | Fan Command
          v
     Fan Actuator SWC

The temperature component supplies temperature information. The fan-control component processes the received value and produces a fan command. The actuator component uses the configured output path to control the fan.

The communication between SWCs is configured through their interfaces and connections. The generated RTE provides the corresponding ECU-specific communication mechanisms.

7. RTE Integration

The Runtime Environment connects application software components with other configured software components and the BSW environment.

7.1 RTE Integration Activities

  • Check SWC descriptions and interfaces.
  • Verify component connections and ECU mappings.
  • Configure runnable activation events.
  • Verify runnable-to-task mappings.
  • Generate ECU-specific RTE files.
  • Integrate generated headers and source files.
  • Resolve generated API and build dependencies.

7.2 RTE Communication Example

       v

The exact generated API names and signatures depend on the configured ports, interfaces, data elements and RTE generator.

8. BSW Integration

BSW integration ensures that the required services, communication modules, diagnostic modules, memory services and operating-system components are configured and connected correctly.

8.1 Common BSW Modules

Module Integration Responsibility
OS Task scheduling, events, resources and alarms.
EcuM ECU initialization and shutdown coordination.
COM Signal and I-PDU handling.
PduR Protocol Data Unit routing.
CanIf CAN interface abstraction.
DEM Diagnostic event management.
DCM Diagnostic communication services.
NvM Non-volatile memory management.

8.2 BSW Integration Checks

  • Verify module dependencies.
  • Check configuration parameters.
  • Verify initialization order and module startup requirements.
  • Check generated configuration source files.
  • Verify required module interfaces.
  • Check compiler and linker dependencies.

9. MCAL Integration

MCAL provides the low-level drivers needed to access the microcontroller's internal peripherals.

9.1 Common MCAL Drivers

  • DIO – Digital Input/Output.
  • PORT – Pin configuration.
  • ADC – Analog-to-Digital Converter.
  • PWM – Pulse Width Modulation.
  • SPI – Serial Peripheral Interface.
  • CAN – Controller Area Network driver.
  • GPT – General Purpose Timer.

9.2 MCAL Integration Activities

  1. Confirm the target microcontroller derivative.
  2. Obtain the compatible MCAL software package.
  3. Configure required peripheral drivers.
  4. Configure clocks, pins and hardware resources.
  5. Generate configuration artifacts.
  6. Integrate driver source and header files.
  7. Verify driver initialization and hardware behavior.
MCAL packages are microcontroller-specific. A driver package for one MCU derivative cannot automatically be assumed compatible with another.

10. Compiler and Linker Integration

After integrating the application, RTE, BSW and MCAL software, the project must be compiled and linked.

10.1 Compiler Responsibilities

  • Compile C source files.
  • Check syntax and data types.
  • Generate object files.
  • Apply target-specific compiler options.
  • Report warnings and errors.

10.2 Linker Responsibilities

  • Combine object files and libraries.
  • Resolve external symbol references.
  • Assign code and data to memory regions.
  • Use the configured linker script or memory description.
  • Generate the final executable image.

10.3 Common Build Errors

Error Possible Cause
Header file not found Incorrect include directory.
Undefined reference Missing source file or library.
Multiple definition Duplicate symbol definitions.
Incompatible declaration Header and implementation mismatch.
Memory overflow Code or data exceeds configured memory region.

12. ECU Integration Testing

After successful compilation and linking, the integrated software must be tested to verify that its components work together correctly.

12.1 Main Testing Activities

  • Verify ECU startup and initialization.
  • Verify SWC communication.
  • Check runnable activation and execution timing.
  • Test BSW service functionality.
  • Verify MCAL peripheral operations.
  • Test CAN communication.
  • Check diagnostic fault handling.
  • Verify expected outputs under normal and fault conditions.

12.2 Testing Environments

Environment Purpose
SIL Tests software behavior in a simulated environment.
HIL Tests ECU hardware using simulated external signals and systems.
Target ECU Tests integrated software on actual ECU hardware.
CANoe Environment Simulates and tests configured automotive communication.

  • OS.

13.3 Example Application Logic

Read temperature

If sensor fault is detected:
    Report diagnostic event
    Apply configured safe fan command

Else if temperature >= 90:
    Fan duty = 100%

Else if temperature >= 75:
    Fan duty = 60%

Else:
    Fan duty = 0%

Update fan command

The thresholds are illustrative. A production ECU uses requirements defined by the vehicle and system design.

13.4 Integration Verification

  1. Verify ADC configuration and sensor input.
  2. Verify temperature data is available to the application.
  3. Verify the fan-control runnable executes correctly.
  4. Verify the configured RTE communication.
  5. Verify PWM output duty cycle.
  6. Inject a sensor fault and verify DEM event reporting.
  7. Review the test results and record defects.

Driver not working Incorrect MCAL or hardware configuration Check pins, clocks and driver initialization.
CAN communication failure Incorrect PDU or controller configuration Inspect communication stack and bus traffic.

15. Placement Interview Questions and Answers

Q1. What is ECU integration?

ECU integration is the process of combining application software, RTE, BSW, MCAL and other required software elements into a working ECU software system.

Q2. What are the main AUTOSAR software layers?

Application Software, RTE and Basic Software. BSW includes Services, ECU Abstraction and MCAL layers.

Q3. Why is RTE required during integration?

RTE provides ECU-specific communication and execution infrastructure between configured software components and their software environment.

Q4. What is the purpose of MCAL integration?

It integrates microcontroller-specific drivers required to access peripherals such as ADC, PWM, SPI, DIO and CAN.

Q5. What is the difference between compilation and linking?

Compilation translates source files into object code. Linking combines object files and libraries into the final executable.

Q6. What is a generated RTE file?

It is an ECU-specific source or header artifact produced by an AUTOSAR RTE generator based on configured descriptions.

Q7. What is BSW integration?

It is the process of configuring and integrating required Basic Software modules and their dependencies.

Q8. What is ECU startup initialization?

It is the sequence of startup activities that prepares the microcontroller, drivers, OS, BSW and application environment for normal operation.

Q9. What is SIL testing?

Software-in-the-Loop testing verifies software behavior in a simulated environment without requiring the final physical ECU.

Q10. What is HIL testing?

Hardware-in-the-Loop testing uses real ECU hardware connected to a system that simulates external inputs and vehicle behavior.

Q11. What causes an RTE integration error?

Possible causes include incompatible interfaces, incorrect connections, missing generated files or inconsistent ECU mappings.

Q12. What is the role of DEM in ECU integration?

DEM manages configured diagnostic events and associated fault information reported by application or BSW components.

Q13. Why is task mapping important?

It determines the execution context of runnable entities and supports correct scheduling and timing behavior.

Q14. What is the purpose of ECU integration testing?

It verifies that integrated software components and layers work together and satisfy the required ECU functionality.

Q15. What is the difference between integration and validation?

Integration combines software elements and checks their interactions. Validation evaluates whether the resulting system meets its intended requirements and use cases.

17. Lesson Summary

  • ECU integration combines AUTOSAR software layers and modules.
  • SWCs communicate through configured ports and interfaces.
  • RTE provides ECU-specific communication infrastructure.
  • BSW modules provide services and hardware abstraction.
  • MCAL drivers provide microcontroller peripheral access.
  • Compiler and linker tools build the ECU executable.
  • Integration testing verifies interactions between software elements.
  • SIL, HIL and target ECU testing support different validation activities.
