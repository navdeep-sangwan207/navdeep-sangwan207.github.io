1. Introduction

In AUTOSAR, a Runnable Entity is a unit of executable application behavior inside a software component (SWC).

An event specifies a condition that triggers the execution of a runnable entity.

The RTE supports the activation of runnable entities according to the configured events and execution model.

Automotive example: A temperature-monitoring runnable executes periodically to check engine temperature. If the temperature exceeds a configured threshold, it can request the cooling fan to turn ON.

2. What is a Runnable Entity?

A Runnable Entity is an executable part of an AUTOSAR software component. It contains application logic and is executed when its associated activation condition is met.

Examples include:

  • Read sensor data.
  • Calculate vehicle speed.
  • Monitor engine temperature.
  • Control a cooling fan.
  • Process diagnostic information.

Important Characteristics

  • Defined within an AUTOSAR software component.
  • Contains executable application behavior.
  • Can access configured data through RTE APIs.
  • Can be activated by different event types.
  • Is mapped to an OS task or execution context through configuration.

4. What is an AUTOSAR Event?

An AUTOSAR event is a configured activation mechanism associated with a runnable entity. It determines when that runnable should execute.

Important event types include:

  • Timing Event
  • Data Received Event
  • Operation Invoked Event
  • Mode Switch Event
  • Init Event
  • External Trigger Occurred Event

5. Important Types of AUTOSAR Events

A. Timing Event

A Timing Event activates a runnable periodically according to its configured period.

Example: A temperature-monitoring runnable executes every 100 milliseconds.

B. Data Received Event

A Data Received Event activates a runnable when new data is received through a configured Sender-Receiver data element.

Example: A dashboard runnable is activated when updated vehicle-speed data becomes available.

C. Operation Invoked Event

An Operation Invoked Event activates a server runnable when a configured Client-Server operation is invoked.

Example: A diagnostic service runnable executes when a client requests a diagnostic operation.

D. Mode Switch Event

A Mode Switch Event is associated with a mode change. It can activate a runnable when the configured mode condition is met.

Example: A runnable executes when the ECU changes from normal operation mode to a diagnostic mode.

E. Init Event

An Init Event activates an initialization runnable during the configured initialization sequence.

Example: An application runnable initializes internal software variables during startup.

F. External Trigger Occurred Event

This event activates a runnable when a configured external trigger occurs.

Example: A runnable processes an event generated by an external trigger source.

7. Runnable Execution Using Conceptual C Code

The following example illustrates the application logic of a temperature-monitoring runnable. 

void TemperatureMonitoringRunnable(void)
{
    uint16 temperature;

    if (Rte_Read_TemperatureData_Temperature(&temperature)
        == RTE_E_OK)
    {
        if (temperature > 90)
        {
            Rte_Write_FanCommand_FanState(1);
        }
        else
        {
            Rte_Write_FanCommand_FanState(0);
        }
    }
}

This is illustrative AUTOSAR-style code. The actual runnable declaration, RTE API names, data types and generated headers depend on the project configuration.

8. Runnable-to-Task Mapping

Runnable entities are associated with OS execution contexts through the AUTOSAR configuration and RTE generation process.

Multiple runnable entities may be mapped to an OS task, depending on the application and scheduling requirements.

10. Runnable Configuration Workflow

  1. Create an AUTOSAR software component.
  2. Define its required and provided ports.
  3. Create runnable entities.
  4. Implement application logic for each runnable.
  5. Define the activation events.
  6. Configure event properties and timing where applicable.
  7. Map runnable entities to OS tasks or execution contexts.
  8. Configure RTE communication and generation.
  9. Integrate generated code with application code.
  10. Build, debug and test the ECU software.

12. Interview Questions and Answers

Q1. What is a Runnable Entity?

A Runnable Entity is an executable unit of application behavior inside an AUTOSAR software component.

Q2. What is an AUTOSAR event?

An event defines a condition that activates an associated runnable entity.

Q3. What is a Timing Event?

It activates a runnable periodically according to its configured period.

Q4. What is a Data Received Event?

It activates a runnable when configured Sender-Receiver data is received.

Q5. What is an Operation Invoked Event?

It activates a server runnable when its configured Client-Server operation is invoked.

Q6. What is an Init Event?

It activates a runnable for initialization during the configured startup sequence.

Q7. Can multiple runnables be mapped to one OS task?

Yes. Multiple runnable entities can be mapped to an OS task according to the configured execution model.

Q8. What is the role of RTE in runnable execution?

The RTE provides configured runnable activation and communication support between application software and the underlying execution environment.

Q9. What is the difference between a runnable and an OS task?

A runnable contains application logic, whereas an OS task provides an execution context scheduled by the operating system.

Q10. What is runnable-to-task mapping?

It is the configuration that associates runnable entities with OS tasks or execution contexts.

13. Lesson Summary

  • A Runnable Entity contains executable application logic.
  • An event defines when a runnable is activated.
  • Timing Events support periodic activation.
  • Data Received Events respond to configured data reception.
  • Operation Invoked Events activate server runnables.
  • Mode Switch Events respond to configured mode changes.
  • Init Events support application initialization.
  • Runnable entities are mapped to OS execution contexts.
  • The RTE supports configured runnable activation.
