Lesson 3: Sender-Receiver Communication

Chapter 3 – Software Components and Interfaces

1. Introduction

Sender-Receiver (S/R) communication is an AUTOSAR communication mechanism used to exchange data between software components.

A sender provides data through a provided port, while a receiver accesses that data through a required port. The RTE supports the configured communication between the components.

Automotive example: A Vehicle Speed SWC sends vehicle speed data to a Dashboard Display SWC. The dashboard receives the value and displays it.

2. Why is Sender-Receiver Communication Used?

  • Allows software components to exchange data.
  • Reduces direct dependencies between components.
  • Provides standardized communication interfaces.
  • Supports component reuse and modularity.
  • Allows one sender to provide data to multiple receivers.
  • Supports configured communication across ECU software.

The RTE provides the generated communication interfaces. The actual implementation may use local data access, inter-task communication or other configured mechanisms.

4. Important Elements of Sender-Receiver Communication

A. Sender

The sender is the software component that provides data to another component.

B. Receiver

The receiver is the software component that accesses data provided by a sender.

C. Provided Port (P-Port)

A P-Port provides an interface through which a software component makes data available.

D. Required Port (R-Port)

An R-Port requires an interface through which a software component accesses data from another component.

E. Sender-Receiver Interface

The Sender-Receiver Interface defines the data elements that can be exchanged.

F. Data Element

A data element represents a data item exchanged through the interface, such as vehicle speed, engine temperature or battery voltage.

6. Sender-Receiver Communication Modes

A. Explicit Communication

In explicit communication, the runnable uses generated RTE APIs to read or write data.

Typical APIs include:

  • Rte_Write() – writes data through a configured sender port.
  • Rte_Read() – reads data through a configured receiver port.

B. Implicit Communication

In implicit communication, data is accessed through generated runnable-specific APIs. The RTE provides data access using configured implicit communication semantics, typically involving a consistent data snapshot for the runnable execution.

Typical APIs include:

  • Rte_IRead() – reads implicit input data.
  • Rte_IWrite() – writes implicit output data.

Exact API availability and signatures depend on the SWC and RTE configuration.

7. Data Flow Using RTE APIs

Sender Example

Std_ReturnType result;

uint16 vehicleSpeed = 80;

result = Rte_Write_SpeedData_VehicleSpeed(vehicleSpeed);

Receiver Example

Std_ReturnType result;

uint16 vehicleSpeed;

result = Rte_Read_SpeedData_VehicleSpeed(&vehicleSpeed);

if (result == RTE_E_OK)
{
    /* Process vehicle speed */
}

These are illustrative generated API examples. Actual names, data types and function signatures are determined by the configured SWC interfaces and generated RTE headers.

8. Communication Properties

A. Data Type

Each data element has a configured data type, such as an unsigned integer, signed integer, floating-point value or structured data type.

B. Data Update

A sender can update the data value, and a receiver can access the available data according to the configured communication semantics.

C. Data Consistency

The RTE configuration and communication semantics help manage consistent data access. The design must still account for timing, data age and concurrent execution requirements.

D. Multiple Receivers

One sender can provide data to multiple receivers when the component connections and interface configuration permit it.

10. Interview Questions and Answers

Q1. What is Sender-Receiver communication?

It is an AUTOSAR communication mechanism used to exchange data between software components.

Q2. What is a sender?

A sender is the component that provides data through a configured interface.

Q3. What is a receiver?

A receiver is the component that accesses data provided by a sender.

Q4. What is a P-Port?

A Provided Port makes an interface available to other components.

Q5. What is an R-Port?

A Required Port allows a component to use an interface provided by another component.

Q6. What is a data element?

It is an individual data item defined within a Sender-Receiver Interface.

Q7. What is the purpose of Rte_Write()?

It writes data through a configured Sender-Receiver output interface.

Q8. What is the purpose of Rte_Read()?

It reads data through a configured Sender-Receiver input interface.

Q9. What is the difference between explicit and implicit communication?

Explicit communication uses explicit read and write operations. Implicit communication uses runnable-specific data access semantics provided by the RTE.

Q10. Can one sender communicate with multiple receivers?

Yes. A sender can provide data to multiple receivers through configured connections.

11. Lesson Summary

  • Sender-Receiver is used for data exchange between SWCs.
  • The sender provides data through a P-Port.
  • The receiver accesses data through an R-Port.
  • The interface defines the exchanged data elements.
  • The RTE supports configured data communication.
  • Rte_Write() and Rte_Read() are common explicit communication APIs.
  • Rte_IRead() and Rte_IWrite() support implicit communication.
  • Sender-Receiver communication is different from Client-Server communication.
