Lesson 4: Client-Server Communication

Chapter 3 – Software Components and Interfaces

Operations | Ports | Arguments | RTE APIs

1. Introduction

Client-Server communication is an AUTOSAR communication mechanism in which one software component requests an operation from another software component.

  • Client: Requests an operation.
  • Server: Provides and executes the operation.
Automotive example: An Engine Control SWC requests a diagnostic calculation from a Diagnostic Service SWC. The server executes the operation and returns the result.

2. Why is Client-Server Communication Used?

  • Provides a structured way to request services.
  • Supports reusable software operations.
  • Separates service implementation from the client.
  • Allows parameters to be passed to operations.
  • Supports return values and operation results.
  • Helps organize modular automotive software.

The RTE provides the communication interface between the client and server according to the configured AUTOSAR design.

4. Important Elements

A. Client

The client is the software component that requests an operation from a server.

B. Server

The server is the software component that provides and implements the requested operation.

C. Client-Server Interface

It defines the operations that a server makes available to clients. It also specifies the operation arguments and return type.

D. Operation

An operation represents a service or function that can be requested by a client.

E. Arguments

Arguments carry information between the client and server. Depending on their configured direction, they can be input, output or input-output arguments.

F. Return Value

An operation can return a result to the client using its configured return type.

G. Ports

  • R-Port: Required port used by the client.
  • P-Port: Provided port used by the server.

5. Practical Example: Battery Voltage Monitoring

Consider two software components:

  • Battery Monitoring SWC – requests voltage analysis.
  • Voltage Analysis SWC – performs the requested calculation.

The client uses the server's defined interface without needing to know the internal implementation of the voltage analysis.

6. Operation Arguments and Return Values

A Client-Server operation can be configured with different argument directions.

Argument Direction Purpose Example
IN Passes input data to the server. Battery voltage
OUT Provides output data from the server. Calculated status
INOUT Allows input and output data. Updated calculation value

An operation may also define a return type, such as an integer, Boolean value or an application-specific data type.

7. Synchronous and Asynchronous Communication

A. Synchronous Client-Server Communication

In synchronous communication, the client waits for the operation result before continuing its execution.

Example: A client requests a calculation and waits for the server to return the result.

B. Asynchronous Client-Server Communication

In asynchronous communication, the client initiates a request and can continue executing without waiting for the final result. The result is obtained later using the configured asynchronous communication mechanism.

Example: A client starts a longer diagnostic operation and continues other processing while the operation is being handled.

The exact behavior depends on the AUTOSAR configuration, operation properties and generated RTE interface.

8. RTE APIs for Client-Server Communication

The RTE generates operation-call interfaces for configured Client-Server connections.

Rte_Call()

Rte_Call() is a common generated API pattern used by a client to invoke a server operation. 

Std_ReturnType result;
uint16 voltage = 12000;
uint8 status;

result = Rte_Call_VoltageService_RequestVoltageStatus(
    voltage,
    &status
);

if (result == RTE_E_OK)
{
    /* Process returned status */
}

This example is illustrative. The generated API name, argument list, return type and parameter directions depend on the configured Client-Server Interface.

Server Operation Implementation

void RequestVoltageStatus(
    uint16 voltage,
    uint8 *status
)
{
    if (voltage < 11000)
    {
        *status = 1;  /* Low voltage */
    }
    else
    {
        *status = 0;  /* Normal voltage */
    }
}

This is conceptual C logic, not a complete generated AUTOSAR server implementation. Actual runnable declarations and operation signatures are generated from the configuration.

9. Client-Server Configuration Workflow

  1. Create the client and server software components.
  2. Define a Client-Server Interface.
  3. Declare the required operations.
  4. Configure operation arguments and return types.
  5. Assign an R-Port to the client component.
  6. Assign a P-Port to the server component.
  7. Connect compatible ports in the composition.
  8. Configure operation invocation and execution behavior.
  9. Generate the RTE and integrate the software components.
  10. Build and test the ECU application.

AUTOSAR configuration descriptions are commonly represented using ARXML files.

10. Sender-Receiver vs Client-Server

11. Interview Questions and Answers

Q1. What is Client-Server communication in AUTOSAR?

It is a communication mechanism in which a client requests an operation provided by a server component.

Q2. What is a client?

A client is the component that invokes an operation using a required interface.

Q3. What is a server?

A server provides and executes operations requested by clients.

Q4. What is a Client-Server Interface?

It defines the operations, arguments and return types available to clients.

Q5. What is Rte_Call()?

It is a generated RTE API pattern used by a client to invoke a configured server operation.

Q6. What is synchronous communication?

The client waits for the operation result before continuing.

Q7. What is asynchronous communication?

The client can continue processing after initiating a request and obtain the result later through the configured mechanism.

Q8. What is the difference between IN and OUT arguments?

IN arguments pass data to the server. OUT arguments provide data from the server to the client.

Q9. Can multiple clients use one server?

Yes. Multiple clients can use a server through compatible configured interfaces and connections.

Q10. What is the role of RTE?

The RTE provides the generated interfaces and communication mechanisms between configured client and server components.

12. Lesson Summary

  • Client-Server communication is used for operation requests.
  • The client uses an R-Port.
  • The server provides operations through a P-Port.
  • The interface defines operations and arguments.
  • Operations can have IN, OUT and INOUT arguments.
  • Operations can define return values.
  • Rte_Call() is a common generated client API pattern.
  • Communication can be synchronous or asynchronous.
  • The RTE supports communication between configured components.
