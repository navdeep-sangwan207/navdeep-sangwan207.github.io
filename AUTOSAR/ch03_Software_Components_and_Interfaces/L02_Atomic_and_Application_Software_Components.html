Lesson 2: Atomic and Application Software Components

Chapter 3 – Software Components and Interfaces

Atomic SWCs | Composition SWCs | Component Reuse

1. Introduction

AUTOSAR application software is organized into software components. These components can be classified according to how they are structured and how they participate in the application design.

Two important concepts are Atomic Software Components and Composition Software Components. Understanding these concepts helps engineers design modular and reusable automotive software.

2. What is an Atomic Software Component?

An Atomic Software Component is an SWC that represents an indivisible unit at the software component composition level.

It is treated as a single component in the AUTOSAR composition model. Its internal implementation may contain multiple runnable entities and other internal elements.

Characteristics

  • Represents a single component unit in a composition.
  • Can contain runnable entities.
  • Can have provided and required ports.
  • Communicates through configured interfaces.
  • Can be connected to other components.
  • Supports modular application design.
Example: A Vehicle Speed Calculation SWC receives wheel speed information and calculates vehicle speed. It can be represented as an atomic component.

3. What is a Composition Software Component?

A Composition Software Component groups multiple software components into a higher-level logical structure.

It describes how its contained components are connected and interact. A composition organizes the application architecture but does not itself represent an atomic executable software component.

Characteristics

  • Contains references to other software components.
  • Defines component connections.
  • Organizes complex application functionality.
  • Supports hierarchical software architecture.
  • Can contain other compositions.
  • Helps manage large ECU applications.
Example: A Vehicle Control Composition may contain vehicle speed, braking, steering and display software components.

4. Atomic SWC vs Composition SWC

Atomic SWC Composition SWC
Represents an indivisible component in a composition. Groups multiple software components.
Can contain runnable entities. Organizes component instances and connections.
Implements application functionality. Defines a higher-level application structure.
Can provide and require interfaces. Can expose and delegate interfaces of contained components.
Used as an individual component unit. Used to organize complex component architectures.

5. Application Software Components

Application Software Components implement vehicle-specific functions. They contain the application logic that performs tasks required by the vehicle or ECU.

Examples of Application SWCs

  • Engine Control SWC
  • Vehicle Speed Calculation SWC
  • Cooling Fan Control SWC
  • Door Lock Control SWC
  • Brake Monitoring SWC
  • Battery Monitoring SWC
  • Dashboard Display SWC

These are examples of application functionality, not a separate formal category that replaces the AUTOSAR SWC classification.

6. Example: Vehicle Control Composition

Consider a vehicle control application that contains multiple atomic software components.

VEHICLE CONTROL COMPOSITION
Vehicle Speed SWC
Calculates vehicle speed
Brake Monitoring SWC
Monitors braking information
Steering Control SWC
Processes steering information
Dashboard Display SWC
Displays vehicle information

The composition defines how these components are organized and connected through compatible ports and interfaces.

7. Component Connections and Delegation

A. Assembly Connector

An assembly connector connects a required port of one component to a compatible provided port of another component within a composition.

Example: A Dashboard Display SWC requires vehicle speed data. A Vehicle Speed SWC provides that data. Their compatible ports can be connected using an assembly connector.

B. Delegation Connector

A delegation connector connects a composition's external port to a port of one of its contained components.

Example: A Vehicle Control Composition can expose an input port that delegates incoming data to an internal Vehicle Speed SWC.

8. Component Reusability

AUTOSAR component-based development supports reuse of software components across compatible ECU projects and vehicle platforms.

Benefits

  • Reduces repeated software development.
  • Supports common application functionality.
  • Improves maintainability.
  • Supports multiple ECU variants.
  • Enables independent component development.
  • Improves software integration practices.
Example: A reusable battery monitoring component may be integrated into different ECU projects when its interfaces, hardware dependencies, timing and configuration requirements are met.

9. Typical Component Development Workflow

  1. Identify the required vehicle functionality.
  2. Divide the functionality into software components.
  3. Define component ports and interfaces.
  4. Design atomic and composition components.
  5. Define component connections.
  6. Implement runnable entities and application logic.
  7. Configure the RTE and generate required code.
  8. Integrate and test the application software.

10. Interview Questions and Answers

Q1. What is an Atomic SWC?

It is a software component treated as an indivisible unit at the component composition level. It can contain runnable entities.

Q2. What is a Composition SWC?

It groups multiple software components and defines their organization and connections.

Q3. What is the difference between atomic and composition components?

An atomic component is an individual component unit, while a composition organizes multiple components into a higher-level structure.

Q4. Can a composition contain another composition?

Yes. AUTOSAR supports hierarchical compositions.

Q5. What is an assembly connector?

It connects compatible required and provided ports of components within a composition.

Q6. What is a delegation connector?

It connects an external composition port to a port of a contained component.

Q7. What is the benefit of component reuse?

It reduces repeated development and supports consistent software integration across compatible ECU projects.

Q8. Does a composition component contain runnable entities?

A composition primarily organizes other components and their connections. Executable application logic is implemented in its contained atomic components.

11. Lesson Summary

  • Atomic SWCs represent individual component units.
  • Composition SWCs organize multiple components.
  • Application SWCs implement vehicle-specific functionality.
  • Compositions can contain nested compositions.
  • Assembly connectors link compatible component ports.
  • Delegation connectors expose internal component ports externally.
  • Component reuse supports modular automotive software development.
