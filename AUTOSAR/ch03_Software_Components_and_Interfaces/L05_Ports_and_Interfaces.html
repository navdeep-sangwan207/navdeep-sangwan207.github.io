Lesson 5: Ports and Interfaces

Chapter 3 – Software Components and Interfaces

P-Port | R-Port | Interfaces | Connectors | Communication

1. Introduction

In AUTOSAR, ports and interfaces define how software components communicate with each other and access services.

A port represents a communication point of a software component. An interface defines the information or operations available through that port.

Example: A Vehicle Speed SWC provides vehicle speed data through a P-Port. A Dashboard SWC receives that data through an R-Port.

2. What is a Port?

A port is an interaction point defined for an AUTOSAR software component.

Ports are mainly classified into:

  • Provided Port (P-Port)
  • Required Port (R-Port)

A. Provided Port (P-Port)

A P-Port provides an interface to other components. It makes data or operations available to connected components.

B. Required Port (R-Port)

An R-Port requires an interface from another component. It allows the component to consume data or request operations.

3. P-Port and R-Port Architecture

Vehicle Speed SWC
P-Port
Provides SpeedData Interface
↓ Compatible Connection
Dashboard SWC
R-Port
Requires SpeedData Interface

The connected ports must have compatible interface definitions and communication properties.

4. What is an AUTOSAR Interface?

An interface specifies the communication contract between software components. It defines what data or operations are available, rather than implementing the application behavior itself.

Important interface types include:

  • Sender-Receiver Interface
  • Client-Server Interface
  • Mode-Switch Interface
  • Parameter Interface
  • Trigger Interface
  • NV-Data Interface

The interfaces used depend on the AUTOSAR platform and the software component design.

5. Sender-Receiver Interface

A Sender-Receiver Interface defines data elements exchanged between software components.

Example: Interface name: VehicleSpeedInterface
Data element: VehicleSpeed
Data type: uint16
Sender: Vehicle Speed SWC
Receiver: Dashboard SWC

The sender writes data and the receiver reads the available value using configured RTE APIs.

6. Client-Server Interface

A Client-Server Interface defines operations that a server component provides to client components.

Example: Interface name: BatteryServiceInterface
Operation: GetBatteryStatus
Input argument: BatteryVoltage
Return value: BatteryStatus

A client invokes the operation through its configured R-Port, while the server provides the operation through its P-Port.

7. Other Important Interface Types

A. Mode-Switch Interface

Used to distribute or access mode information, such as vehicle operating modes or ECU states.

B. Parameter Interface

Used to define calibration or configuration parameters that a software component can access.

C. Trigger Interface

Used to represent trigger-based interaction between software components.

D. NV-Data Interface

Used to describe access to non-volatile data in supported AUTOSAR configurations.

8. Port Prototypes and Interface Definitions

A port prototype is a port defined as part of a software component description. It references an interface definition.

For example:

  • Port name: SpeedDataPort
  • Port type: P-Port or R-Port
  • Interface: VehicleSpeedInterface
  • Data element: VehicleSpeed
  • Data type: uint16

The port and interface descriptions are represented in AUTOSAR XML (ARXML) artifacts.

9. Connectors in AUTOSAR

Connectors define communication relationships between ports in a software composition.

A. Assembly Connector

An assembly connector connects a required port of one component to a compatible provided port of another component within a composition.

Component A
P-Port
↓ Assembly Connector
Component B
R-Port

B. Delegation Connector

A delegation connector connects an external port of a composition component to a port of one of its contained components.

Composition SWC
External Port
↓ Delegation Connector
Contained SWC
Internal Port

Assembly and delegation connectors help organize communication in hierarchical AUTOSAR software compositions.

10. Port and Interface Configuration Workflow

  1. Create the software component.
  2. Define the required communication interface.
  3. Configure the data elements or operations.
  4. Create a P-Port or R-Port.
  5. Associate the port with the interface.
  6. Configure compatible connections.
  7. Use assembly or delegation connectors where required.
  8. Generate the RTE and integrate the components.
  9. Validate the communication configuration.

AUTOSAR configuration tools represent these definitions and relationships in ARXML files.

11. Difference Between Port and Interface

Port Interface
Represents a component interaction point. Defines the communication contract.
Can be provided or required. Defines data elements, operations or modes.
References an interface. Can be referenced by compatible ports.
Example: SpeedDataPort. Example: VehicleSpeedInterface.

12. Interview Questions and Answers

Q1. What is a port in AUTOSAR?

A port is a communication point through which a software component interacts with other components or services.

Q2. What is a P-Port?

A P-Port provides an interface to other software components.

Q3. What is an R-Port?

An R-Port requires an interface from another software component.

Q4. What is an AUTOSAR interface?

It defines the data, operations or other communication elements available through a port.

Q5. What is a Sender-Receiver Interface?

It defines data elements exchanged between software components.

Q6. What is a Client-Server Interface?

It defines operations that a server provides to client components.

Q7. What is an assembly connector?

It connects compatible required and provided ports of components within a composition.

Q8. What is a delegation connector?

It connects a composition's external port to a port of a contained component.

Q9. What is a port prototype?

It is a port defined in a software component description and associated with an interface.

Q10. What is ARXML?

ARXML is the AUTOSAR XML-based format used to describe software components, interfaces, ports and configuration artifacts.

13. Lesson Summary

  • Ports define interaction points of software components.
  • P-Port provides an interface.
  • R-Port requires an interface.
  • Interfaces define data, operations or modes.
  • Sender-Receiver interfaces define data elements.
  • Client-Server interfaces define operations.
  • Assembly connectors connect compatible component ports.
  • Delegation connectors connect composition ports to contained component ports.
  • ARXML describes AUTOSAR component and interface configurations.
