Lesson 5: CAN Driver and CAN Transceiver

AUTOSAR – Chapter 6: MCAL and Microcontroller Drivers

Focus: Automotive CAN Communication and Hardware Interface

1. Introduction to CAN

CAN stands for Controller Area Network. It is a robust, message-based serial communication protocol widely used in automotive electronic control units (ECUs).

CAN allows multiple ECUs to exchange messages over a shared communication bus without requiring a separate communication wire for every pair of ECUs.

  • Engine Control Unit (ECU).
  • Transmission Control Unit.
  • Body Control Module.
  • Instrument Cluster.
  • Anti-lock Braking System (ABS).

3. What is the CAN Driver?

The AUTOSAR CAN Driver is an MCAL module that provides software interfaces for controlling the microcontroller's CAN controller hardware.

Main Responsibilities

  • Initialize the CAN controller.
  • Configure controller operation modes.
  • Configure CAN controller hardware resources.
  • Transmit CAN frames through configured hardware objects.
  • Receive CAN frames from the controller.
  • Support transmit and receive notifications.
  • Report relevant controller and communication errors.

The CAN Driver does not directly generate the electrical CAN bus signal. That is the role of the physical-layer transceiver.

4. What is a CAN Transceiver?

A CAN transceiver is a physical-layer interface device between the CAN controller and the CAN bus.

It converts:

  • Logic-level transmit signals from the controller into differential CAN bus signals.
  • Differential CAN bus signals into logic-level receive signals for the controller.

5. CAN Bus Differential Signalling

High-speed CAN commonly uses differential signalling. The receiver interprets the voltage difference between CANH and CANL.

Bus State Typical CANH Typical CANL Difference
Recessive Approximately 2.5 V Approximately 2.5 V Approximately 0 V
Dominant Approximately 3.5 V Approximately 1.5 V Approximately 2 V

These are illustrative typical values for a conventional high-speed CAN bus. Actual voltage levels depend on the transceiver, loading, supply and network conditions.

6. CAN Termination

High-speed CAN networks commonly use 120-ohm termination resistors at the two physical ends of the bus.

120 Ω
↓
ECU ───── CANH / CANL Bus ───── ECU
↓
120 Ω

The two end terminations help reduce signal reflections and maintain signal integrity.

With the network powered down and isolated appropriately, measuring resistance between CANH and CANL on a correctly terminated conventional network often gives approximately 60 ohms because the two 120-ohm resistors are in parallel.

These APIs belong to the AUTOSAR CAN Driver interface. Exact availability and behavior depend on the AUTOSAR release and implementation.

9. CAN Communication Workflow

Transmission

  1. Application provides the data through configured interfaces.
  2. COM processes the configured signal and I-PDU.
  3. PduR routes the I-PDU to the CAN Interface.
  4. CanIf selects the configured CAN transmit hardware object.
  5. CAN Driver requests transmission from the CAN controller.
  6. CAN Transceiver drives the physical CAN bus.

Reception

  1. CAN Transceiver detects bus activity.
  2. CAN Controller receives and validates the frame.
  3. CAN Driver handles the configured receive event.
  4. CanIf processes the received CAN frame.
  5. PduR routes the I-PDU to the appropriate upper module.
  6. COM makes configured signals available to the application.

10. CAN Controller vs CAN Transceiver

CAN Controller CAN Transceiver
Implements CAN protocol functions. Provides the physical electrical bus interface.
Usually integrated into the MCU or provided as a separate controller. Usually an external physical-layer device.

CAN Driver CanIf

12. Common CAN Troubleshooting Checks

  • Check CANH and CANL wiring.
  • Verify correct termination at the two bus ends.
  • Confirm that all nodes use compatible bit timing.
  • Check transceiver supply and operating mode.
  • Verify CAN controller initialization.
  • Check configured CAN identifiers and hardware objects.
  • Inspect error counters and controller status.
  • Use a CAN analyzer or oscilloscope to inspect bus activity.

13. Common Placement Interview Questions

Q1. What is CAN?

Answer: Controller Area Network is a message-based serial communication protocol widely used in automotive systems.

Q2. What is the function of a CAN Driver?

Answer: It provides software interfaces to control the microcontroller's CAN controller.

Q3. What is a CAN Transceiver?

Answer: It converts logic-level signals to differential CAN bus signals and converts received bus signals back to logic levels.

Q4. What are CANH and CANL?

Answer: They are the two differential signal lines of a CAN bus.

Q5. Why are 120-ohm resistors used?

Answer: They provide bus termination at the two physical ends of a conventional high-speed CAN network to reduce reflections.

Q6. What is the typical resistance measured across a correctly terminated CAN bus?

Answer: Approximately 60 ohms, with the network powered down, because two 120-ohm terminations are in parallel.

Q7. What is CanIf?

Answer: CAN Interface is an ECU Abstraction module that provides a standardized interface between upper communication layers and CAN drivers.

Q8. What is a CAN Hardware Object?

Answer: It is a configured transmit or receive hardware object used by the CAN controller.

Q9. What is the difference between a CAN Controller and a CAN Transceiver?

Answer: The controller handles CAN protocol operations, while the transceiver handles the physical electrical bus interface.

Q10. Is the CAN Driver part of MCAL?

Answer: Yes. The CAN Driver is part of AUTOSAR MCAL.

14. Lesson Summary

  • CAN is widely used for communication between automotive ECUs.
  • CAN Driver controls the CAN controller hardware.
  • CAN Transceiver provides the physical bus interface.
  • CANH and CANL carry differential signals.
  • Conventional high-speed CAN networks use termination at both ends.
  • CanIf connects upper communication modules to the CAN Driver.
  • CAN Driver belongs to MCAL.
