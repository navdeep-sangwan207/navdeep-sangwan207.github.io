Lesson 6: MCAL Configuration and Integration

AUTOSAR – Chapter 6: MCAL and Microcontroller Drivers

Focus: Configuration, Code Generation and ECU Integration

1. Introduction

MCAL configuration is the process of selecting and configuring microcontroller peripheral drivers according to the requirements of an automotive ECU.

MCAL integration involves incorporating the configured drivers, generated configuration files and required dependencies into the AUTOSAR Basic Software project.

Examples of configurable MCAL drivers include:

  • Port and DIO.
  • ADC.
  • PWM and GPT.
  • SPI.
  • CAN.
  • Watchdog and other supported peripheral drivers.

2. Why is MCAL Configuration Required?

  • Every ECU uses a specific microcontroller.
  • Peripheral requirements differ between ECU designs.
  • Pin assignments and peripheral channels must be configured.
  • Interrupts and notifications need suitable configuration.
  • Drivers need to match the selected hardware and software versions.
  • Upper BSW modules depend on correctly configured lower-level drivers.

4. Important MCAL Configuration Parameters

Driver Typical Configuration
Port Pin direction, pin mode, pull-up/pull-down and supported electrical settings.
DIO Channel IDs, port IDs and channel group definitions.
ADC Channels, groups, resolution, conversion mode and result buffer.
PWM Channels, period, polarity and duty-cycle settings.
GPT Timer channels, tick configuration and notifications.
SPI Channels, jobs, sequences, baud rate and clock settings.
CAN Controllers, baud rate, hardware objects and filter configuration.

Actual parameter names and available options depend on the AUTOSAR release, microcontroller and MCAL vendor package.

5. MCAL Configuration Tools

MCAL configuration is commonly performed using vendor-supported configuration tools.

Tool Typical Use
EB tresos Studio Configuration and generation of supported AUTOSAR BSW and MCAL modules.
Vector DaVinci Configurator Configuration of supported AUTOSAR BSW modules and ECU software.
ETAS ISOLAR AUTOSAR ECU software configuration and development workflows.
MCU Vendor Tools Microcontroller-specific configuration and software integration.

Tool support is package-dependent. Not every tool supports every microcontroller or every vendor's MCAL implementation.

6. ARXML Configuration

ARXML stands for AUTOSAR XML. It is an XML-based format used to describe AUTOSAR system, software and ECU configuration information.

ARXML descriptions may contain:

  • ECU hardware and software configuration information.
  • MCAL module parameters.
  • Peripheral channel and resource assignments.
  • Communication configuration.
  • Software component and interface descriptions.

Configuration tools use relevant ARXML descriptions to validate configurations and generate software artifacts.

7. MCAL Code Generation

After configuring the required modules, the configuration tool generates source files, header files and configuration data required by the MCAL implementation.

Typical Generated Artifacts

Artifact Purpose
Driver source files Contain driver implementation code supplied by the MCAL package.
Configuration source files Contain generated configuration data.
Header files Provide declarations, types and configuration interfaces.
ARXML files Store AUTOSAR configuration descriptions.
Make/build files May define compilation and integration settings.

Generated filenames and folder structures vary by MCAL vendor and configuration tool. Do not assume that every project generates identical files.

8. MCAL Integration Workflow

  1. Select the target microcontroller and compatible MCAL package.
  2. Check compiler, AUTOSAR release and tool compatibility.
  3. Configure required peripheral drivers.
  4. Validate the configuration and resolve tool errors.
  5. Generate configuration source and header files.
  6. Integrate MCAL sources and generated files into the build.
  7. Configure dependencies, memory sections and startup requirements.
  8. Build and link the ECU software.
  9. Initialize drivers in the required startup sequence.
  10. Test peripheral functionality and integration.

9. Driver Initialization and Dependency Management

MCAL drivers must be initialized according to their dependencies and the ECU startup design.

Typical considerations include:

  • Microcontroller clock configuration.
  • Port and pin configuration.
  • Peripheral driver initialization.
  • Interrupt controller and interrupt configuration.
  • Operating system and BSW initialization dependencies.
  • Transceiver and external hardware readiness.

There is no single universal initialization order for all MCAL modules. Follow the selected AUTOSAR release, vendor integration manual and ECU startup configuration.

10. MCAL Testing and Validation

Driver Example Test
DIO Verify digital input and output states.
ADC Apply known input voltages and verify conversion results.
PWM Measure output frequency and duty cycle.
GPT Verify timer duration and notification behavior.
SPI Verify transmitted and received data using a peripheral or test setup.
CAN Verify frame transmission, reception and controller status.

Testing may include unit testing, driver-level testing, integration testing, hardware-in-the-loop testing and target ECU validation.

11. Common MCAL Integration Problems

Problem Possible Cause
Compilation error Missing header, incorrect compiler settings or incompatible source files.
Linker error Missing source files or unresolved symbols.
Peripheral not working Incorrect pin, clock or peripheral configuration.
ADC result incorrect Wrong channel, reference voltage or conversion configuration.
PWM output missing Incorrect pin multiplexing, timer setup or channel configuration.
CAN communication failure Incorrect bit timing, transceiver mode, wiring or termination.
Driver initialization failure Incorrect startup order or invalid configuration.

13. Common Placement Interview Questions

Q1. What is MCAL configuration?

Answer: It is the process of configuring microcontroller peripheral drivers according to ECU hardware and software requirements.

Q2. What is ARXML?

Answer: ARXML is an XML-based format used to describe AUTOSAR system, software and ECU configuration information.

Q3. Why is code generation required?

Answer: It produces configuration data and software artifacts needed to integrate configured AUTOSAR modules.

Q4. Name some MCAL configuration tools.

Answer: EB tresos Studio, supported Vector DaVinci tools, ETAS ISOLAR and microcontroller-vendor tools.

Q5. What is MCAL integration?

Answer: It is the process of incorporating MCAL drivers and their generated configuration into the ECU software build.

Q6. Why is driver initialization important?

Answer: It prepares peripheral hardware and software drivers for correct operation.

Q7. What causes MCAL compilation errors?

Answer: Missing headers, incompatible compiler settings, incorrect configuration or source-file integration problems.

Q8. What is MCAL validation?

Answer: It verifies that configured drivers operate correctly and satisfy ECU hardware and software requirements.

Q9. Can generated configuration files be manually modified?

Answer: Normally, configuration should be changed through the configuration tool and regenerated. Manual changes to generated files may be overwritten or cause inconsistencies.

Q10. What is the final goal of MCAL integration?

Answer: To provide correctly configured and tested microcontroller peripheral drivers within the ECU software architecture.

14. Lesson Summary

  • MCAL configuration adapts drivers to ECU hardware requirements.
  • ARXML stores AUTOSAR configuration descriptions.
  • Configuration tools generate required software artifacts.
  • MCAL integration connects drivers with the BSW project.
  • Initialization must follow the ECU startup design.
  • Driver validation checks peripheral operation and integration.
  • Common problems include configuration, compilation, linking and hardware issues.
