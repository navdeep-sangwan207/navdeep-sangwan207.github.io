Lesson 4: SPI and I2C Driver Concepts

AUTOSAR – Chapter 6: MCAL and Microcontroller Drivers

Focus: Serial Communication and Peripheral Interfacing

1. Introduction

SPI and I2C are serial communication protocols used to exchange data between a microcontroller and external peripheral devices.

  • SPI: Serial Peripheral Interface.
  • I2C: Inter-Integrated Circuit.

In AUTOSAR Classic, the SPI driver is a standard MCAL module. I2C controller support is implementation- and MCU-dependent; it is not a universally standardized MCAL module in the AUTOSAR Classic driver list.

2. SPI – Serial Peripheral Interface

SPI is a synchronous serial communication protocol commonly used for communication between a controller and one or more peripheral devices.

SPI Features

  • Synchronous serial communication.
  • Separate transmit and receive data lines.
  • Full-duplex data transfer is supported.
  • Uses a clock generated by the controller.
  • Typically uses a separate chip-select signal for each selected device.
  • Supports different clock modes and bit-order configurations.

3. SPI Clock Modes

SPI uses two important configuration parameters: Clock Polarity (CPOL) and Clock Phase (CPHA).

Mode CPOL CPHA
SPI Mode 000
SPI Mode 101
SPI Mode 210
SPI Mode 311
  • CPOL: Defines the idle level of the clock.
  • CPHA: Defines the clock edge used for sampling data.

The controller and peripheral must use compatible SPI clock settings.

4. AUTOSAR SPI Driver

The AUTOSAR SPI driver provides standardized interfaces for accessing the microcontroller's SPI hardware.

Important SPI Concepts

  • SPI Channel: Defines a data channel and its buffer configuration.
  • SPI Job: Groups channel transfers executed under a common sequence of device and communication settings.
  • SPI Sequence: Groups one or more jobs for execution.
  • External Device: Represents a configured SPI peripheral.
  • Buffer: Stores transmit and receive data.

SPI Driver API Names

API Purpose
Spi_Init() Initializes the SPI driver.
Spi_WriteIB() Writes data to an internal transmit buffer.
Spi_ReadIB() Reads data from an internal receive buffer.
Spi_SetupEB() Sets up external transmit and receive buffers.
Spi_AsyncTransmit() Starts asynchronous sequence transmission.
Spi_SyncTransmit() Performs synchronous sequence transmission.
Spi_GetSequenceResult() Checks the result of a configured sequence.

5. I2C – Inter-Integrated Circuit

I2C is a synchronous serial communication protocol that uses two main signal lines to communicate with multiple addressed devices on a bus.

Signal Function
SDA Serial Data line.
SCL Serial Clock line.
Microcontroller I2C Controller
↓
SDA – Serial Data
SCL – Serial Clock
↓
Shared I2C Bus
↓
EEPROM / Sensor / Other I2C Devices

I2C Features

  • Uses two communication lines.
  • Supports addressed communication.
  • Supports multiple controllers and targets, subject to system design.
  • Uses start and stop conditions.
  • Supports acknowledge and not-acknowledge responses.
  • Devices share the SDA and SCL bus lines.

I2C lines are normally open-drain or open-collector and require suitable pull-up resistors. Pull-up values depend on bus capacitance, supply voltage and selected bus speed.

6. I2C Communication Process

  1. The controller generates a START condition.
  2. The controller sends the target address and read/write bit.
  3. The addressed target responds with ACK or NACK.
  4. Data bytes are transferred with acknowledgement handling.
  5. The controller generates a STOP condition when the transfer ends.

Often used for high-throughput peripheral communication. Often used for addressed communication with sensors and memory devices.

9. Conceptual SPI API Example

The following fragment illustrates a configured asynchronous SPI sequence. It requires generated configuration and project-specific buffers. 

#include "Spi.h"

void Start_SPI_Communication(void)
{
    Spi_AsyncTransmit(SPI_SEQUENCE_ID);
}

The application or configured notification mechanism can check the sequence result after transmission.

10. I2C Support in Automotive Microcontrollers

I2C is commonly used to connect low-speed peripherals such as EEPROMs, temperature sensors and monitoring devices.

In AUTOSAR Classic projects, I2C access may be implemented through vendor-specific drivers, Complex Drivers or other configured integration approaches, depending on the microcontroller and software package.

Do not assume that every AUTOSAR Classic MCAL package provides a standardized I2C driver API.

11. Automotive Applications

  • SPI-connected sensor modules.
  • External EEPROM communication.
  • Battery monitoring peripherals.
  • Temperature and pressure sensor interfaces.
  • External ADC and DAC devices.
  • Vehicle monitoring and control electronics.

12. Common Placement Interview Questions

Q1. What is SPI?

Answer: SPI is a synchronous serial communication protocol used to connect a controller with peripheral devices.

Q2. What are the four common SPI signals?

Answer: MOSI, MISO, SCLK and CS/SS.

Q3. What is I2C?

Answer: I2C is a synchronous, addressed serial communication protocol that uses SDA and SCL.

Q4. What are the two I2C lines?

Answer: SDA for data and SCL for clock.

Q5. What is the difference between SPI and I2C?

Answer: SPI generally uses separate data lines and chip-select signals, while I2C uses a shared two-wire addressed bus.

Q6. What is CPOL?

Answer: Clock Polarity defines the idle level of the SPI clock.

Q7. What is CPHA?

Answer: Clock Phase defines which clock edge is used for data sampling.

Q8. What is an SPI sequence?

Answer: It is a configured group of one or more SPI jobs executed by the SPI driver.

Q9. Why are pull-up resistors used in I2C?

Answer: They pull the open-drain SDA and SCL lines to the HIGH logic level when no device is pulling them LOW.

Q10. Is SPI a standard AUTOSAR MCAL driver?

Answer: Yes. SPI is a standardized MCAL driver in AUTOSAR Classic.

13. Lesson Summary

  • SPI and I2C are synchronous serial communication protocols.
  • SPI uses MOSI, MISO, SCLK and chip-select signals.
  • I2C uses SDA and SCL.
  • SPI supports full-duplex communication.
  • I2C uses addressed communication and ACK/NACK responses.
  • SPI is a standard AUTOSAR Classic MCAL driver.
  • I2C driver availability depends on the MCU and vendor implementation.
