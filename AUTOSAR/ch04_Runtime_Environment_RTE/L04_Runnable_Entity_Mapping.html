1. Introduction

A Runnable Entity is an executable part of an AUTOSAR Software Component (SWC). It contains application logic that is executed when its associated activation conditions are satisfied.

Runnable-to-task mapping associates runnable entities with operating system tasks or execution contexts so that they can be executed by the ECU.

Example: A temperature monitoring runnable reads temperature data every 10 milliseconds. It is mapped to an OS task configured to support its periodic execution.

2. What is a Runnable Entity?

A runnable entity represents a specific execution unit inside an AUTOSAR SWC. It performs a defined application function.

Examples:

  • Read sensor data.
  • Calculate vehicle speed.
  • Monitor battery voltage.
  • Control cooling fan operation.
  • Update dashboard information.
/* Illustrative runnable function */

void TemperatureMonitorRunnable(void)
{
    uint16 temperature;

    /* Read configured temperature data */
    /* Process temperature */
    /* Update application status */
}

The actual runnable implementation and generated interfaces depend on the SWC design and configuration.

3. What is an OS Task?

An Operating System task is an execution context managed by the AUTOSAR OS. It provides the environment in which configured runnable entities are executed.

Tasks can be configured with different properties:

  • Task priority.
  • Task activation type.
  • Scheduling behavior.
  • Timing requirements.
  • Stack allocation.
Important: A runnable is an application-level execution unit. An OS task is an operating-system scheduling entity. They are related, but they are not the same thing.

5. Why is Runnable Mapping Required?

  • Defines where runnable entities execute.
  • Supports periodic and event-driven execution.
  • Helps satisfy real-time requirements.
  • Associates application execution with OS scheduling.
  • Supports resource and execution-time planning.
  • Helps separate application logic from OS details.

6. Types of Runnable Activation

A. Timing-Based Activation

A runnable is activated periodically according to a configured timing event.

Example: A temperature monitoring runnable executes every 10 ms.

B. Data-Received Activation

A runnable is activated when configured data reception conditions are satisfied.

Example: A dashboard runnable processes newly received vehicle speed data.

C. Operation-Invoked Activation

A server runnable is activated when a configured Client-Server operation is invoked.

D. Initialization Activation

An initialization runnable executes during the configured initialization sequence.

E. Mode-Switch Activation

A runnable may be activated when a configured mode transition occurs.

8. Runnable Mapping and Scheduling

After mapping, the AUTOSAR OS schedules configured tasks according to their priorities and scheduling rules.

Important scheduling concepts:

  • Priority: Determines task scheduling precedence.
  • Activation: Makes a task ready for execution.
  • Preemption: Allows a higher-priority task to interrupt a lower-priority task when permitted.
  • Execution Time: Time required by a task to execute.
  • Period: Time interval between periodic activations.
  • Deadline: Time by which the required work must finish.
Example: A 5 ms task and a 20 ms task may have different priorities depending on their timing requirements and system design. A shorter period does not automatically mean higher priority.

9. Runnable Mapping Configuration Workflow

  1. Create the software component and runnable entities.
  2. Define runnable activation events.
  3. Configure timing requirements.
  4. Define OS tasks and their properties.
  5. Map runnable entities to appropriate tasks.
  6. Configure task priorities and scheduling.
  7. Generate RTE and relevant OS configuration code.
  8. Build and test the ECU software.

12. Interview Questions and Answers

Q1. What is a Runnable Entity?

It is an executable unit inside an AUTOSAR software component.

Q2. What is runnable-to-task mapping?

It associates runnable entities with configured OS tasks or execution contexts.

Q3. What is the difference between a runnable and a task?

A runnable contains application logic, while an OS task provides an execution context managed by the operating system.

Q4. What is periodic runnable activation?

It is activation based on a configured timing event at regular intervals.

Q5. What is event-driven runnable activation?

It is activation when a configured event, such as data reception or operation invocation, occurs.

Q6. What is task priority?

It is a scheduling property used by the OS to determine task execution precedence.

Q7. Can multiple runnables map to one task?

Yes. Multiple runnable entities can be associated with the same task, depending on the configuration and execution design.

Q8. Who schedules the OS tasks?

The AUTOSAR Operating System schedules tasks according to configured scheduling rules and task properties.

Q9. What happens if a runnable is not mapped correctly?

It may not execute as expected, or RTE/OS configuration validation and generation may report errors.

Q10. Why is runnable mapping important in automotive ECUs?

It helps organize application execution and satisfy real-time timing requirements.

13. Lesson Summary

  • A runnable is an executable unit inside an SWC.
  • An OS task provides an execution context.
  • Runnable mapping connects application execution with OS scheduling.
  • Run­nables can be activated by timing and other configured events.
  • Task priorities and execution times affect scheduling.
  • RTE and OS configuration must be consistent.
  • Correct mapping is important for real-time ECU behavior.
