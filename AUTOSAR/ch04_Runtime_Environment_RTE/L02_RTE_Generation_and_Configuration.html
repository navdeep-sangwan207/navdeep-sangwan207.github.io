Chapter 4 – Runtime Environment (RTE)

1. Introduction

RTE generation is the process of creating Runtime Environment interfaces and supporting implementation code from AUTOSAR software component descriptions and ECU configuration.

The generated RTE connects application software components with each other and with configured Basic Software services.

Example: A Vehicle Speed SWC needs to send speed data to a Dashboard SWC. The RTE generator creates the required communication interfaces based on the configured ports and connections.

2. Why is RTE Generation Required?

  • Creates communication interfaces for SWCs.
  • Generates configured RTE API implementations.
  • Connects software components through configured ports.
  • Supports runnable activation and execution integration.
  • Supports access to configured BSW services.
  • Reduces the need for manually writing repetitive communication code.
  • Helps maintain consistency between software descriptions and implementation.

3. Inputs Required for RTE Generation

A. Software Component Description

Describes application software components, ports, interfaces, runnable entities and events.

B. System Description

Describes the overall system architecture, including ECUs, communication networks and system-level component allocation.

C. ECU Extract

Contains the information relevant to a particular ECU, extracted from the system-level description.

D. ECU Configuration Description

Contains ECU-specific configuration information required for software integration, including relevant RTE and BSW configuration.

E. Basic Software Configuration

Provides the configured BSW module information required for integration with application software.

5. Step-by-Step RTE Generation Process

Step 1: Create Software Components

Define the application software components required for the ECU.

Step 2: Define Ports and Interfaces

Configure P-Ports, R-Ports, Sender-Receiver interfaces and Client-Server interfaces.

Step 3: Define Runnable Entities

Create runnable entities and associate appropriate activation events.

Step 4: Configure Component Connections

Connect compatible ports within software compositions and define the required communication relationships.

Step 5: Prepare ECU Configuration

Assign components to the ECU and configure relevant RTE, OS and BSW information.

Step 6: Validate Configuration

Check interface compatibility, component connections, data types and execution configuration.

Step 7: Generate RTE Code

Run the RTE generator to produce the configured RTE source and header files.

Step 8: Integrate and Build

Integrate generated RTE code with application and BSW code, then compile and test the ECU software.

7. Example of Generated RTE API

Suppose a Vehicle Speed SWC sends vehicle speed data to a Dashboard SWC.

Sender Application Code

#include "Rte_VehicleSpeed.h"

void VehicleSpeedRunnable(void)
{
    uint16 speed = 80;

    Rte_Write_SpeedPort_VehicleSpeed(speed);
}

Receiver Application Code

#include "Rte_Dashboard.h"

void DashboardRunnable(void)
{
    uint16 speed;

    if (Rte_Read_SpeedPort_VehicleSpeed(&speed)
        == RTE_E_OK)
    {
        /* Update dashboard display */
    }
}

The header names, API names and function signatures are illustrative. They must match the files generated for the actual ECU project.

8. RTE Configuration Parameters

  • SWC Mapping: Associates software components with ECU resources.
  • Port Configuration: Defines required and provided interfaces.
  • Runnable Mapping: Associates runnable entities with execution contexts.
  • Event Configuration: Defines runnable activation conditions.
  • Communication Configuration: Defines configured data and operation connections.
  • OS Configuration: Defines relevant task and scheduling information.
  • BSW Service Configuration: Defines required interaction with BSW modules.

9. Role of ARXML in RTE Generation

ARXML stands for AUTOSAR XML. It is the XML-based format used to represent AUTOSAR software descriptions and configuration artifacts.

ARXML can describe:

  • Software component descriptions.
  • Ports and interfaces.
  • Runnable entities and events.
  • Software compositions and connectors.
  • System and ECU descriptions.
  • ECU-specific configuration information.
Important: ARXML is a configuration and description format. It is not the generated executable application code.

12. Interview Questions and Answers

Q1. What is RTE generation?

It is the process of generating RTE interfaces and supporting code from AUTOSAR software and ECU configuration.

Q2. What are the inputs required for RTE generation?

Software component descriptions, system and ECU descriptions, and relevant configuration information are important inputs.

Q3. What is the role of ARXML?

ARXML represents AUTOSAR software descriptions and configuration artifacts.

Q4. What does an RTE generator produce?

It produces configured RTE interfaces, source code, headers and supporting integration artifacts.

Q5. Why is RTE code generated?

To provide configured communication and execution support between application components and the ECU software environment.

Q6. What is runnable mapping?

It associates runnable entities with OS tasks or execution contexts.

Q7. Name some AUTOSAR configuration tools.

Vector DaVinci, EB tresos Studio, ETAS ISOLAR and dSPACE tools are examples.

Q8. What causes RTE generation errors?

Incompatible ports, incorrect data types, incomplete configuration and missing runnable mappings are common causes.

Q9. Is ARXML executable code?

No. ARXML describes AUTOSAR components and configuration. Code generators use these descriptions to produce implementation artifacts.

Q10. What happens after RTE generation?

The generated code is integrated with application and BSW software, compiled, tested and debugged.

13. Lesson Summary

  • RTE generation creates configured RTE implementation code.
  • SWC descriptions provide component, port and runnable information.
  • ECU configuration provides ECU-specific integration information.
  • ARXML represents AUTOSAR descriptions and configuration artifacts.
  • The RTE generator produces interfaces, headers and supporting source code.
  • Generated code must be integrated with application and BSW software.
  • Configuration validation helps identify integration errors.
  • Automotive tools automate RTE configuration and generation.
