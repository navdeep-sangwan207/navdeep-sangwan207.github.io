6. Representative C11 Coding Problems

Problem 1: Count Set Bits

Count the number of bits set to 1 in an unsigned integer using Brian Kernighan's algorithm.

#include <stdio.h> unsigned int countSetBits(unsigned int n) { unsigned int count = 0; while (n != 0) { n &= n - 1; count++; } return count; } int main(void) { unsigned int number = 29; printf("Set bits = %u\n", countSetBits(number)); return 0; }
Set bits = 4

Time: O(k), where k is the number of set bits. Auxiliary space: O(1).

Problem 2: Move All Zeros to the End

Maintain the relative order of nonzero elements.

#include <stdio.h> void moveZeros(int arr[], int n) { int position = 0; for (int i = 0; i < n; i++) { if (arr[i] != 0) arr[position++] = arr[i]; } while (position < n) arr[position++] = 0; } int main(void) { int arr[] = {0, 1, 0, 3, 12}; int n = sizeof(arr) / sizeof(arr[0]); moveZeros(arr, n); for (int i = 0; i < n; i++) printf("%d ", arr[i]); printf("\n"); return 0; }
1 3 12 0 0

Time: O(n). Auxiliary space: O(1).

Problem 3: Check Whether Two Strings Are Anagrams

This version supports case-sensitive strings containing English letters A–Z and a–z. Other characters are rejected.

#include <stdio.h> int charIndex(char ch) { if (ch >= 'a' && ch <= 'z') return ch - 'a'; if (ch >= 'A' && ch <= 'Z') return ch - 'A' + 26; return -1; } int areAnagrams(const char a[], const char b[]) { int frequency[52] = {0}; for (int i = 0; a[i] != '\0'; i++) { int index = charIndex(a[i]); if (index == -1) return 0; frequency[index]++; } for (int i = 0; b[i] != '\0'; i++) { int index = charIndex(b[i]); if (index == -1) return 0; frequency[index]--; } for (int i = 0; i < 52; i++) { if (frequency[i] != 0) return 0; } return 1; } int main(void) { char first[] = "listen"; char second[] = "silent"; printf("%s\n", areAnagrams(first, second) ? "Anagrams" : "Not anagrams"); return 0; }
Anagrams

Time: O(n + m). Auxiliary space: O(52), effectively O(1).

Problem 4: Find the First Non-Repeating Character

Return the first character that appears exactly once. This version supports byte-oriented strings.

#include <stdio.h> int main(void) { char str[] = "swiss"; int frequency[256] = {0}; for (int i = 0; str[i] != '\0'; i++) { unsigned char ch = (unsigned char)str[i]; frequency[ch]++; } int found = 0; for (int i = 0; str[i] != '\0'; i++) { unsigned char ch = (unsigned char)str[i]; if (frequency[ch] == 1) { printf("First unique character = %c\n", ch); found = 1; break; } } if (!found) printf("No unique character\n"); return 0; }
First unique character = w

Time: O(n + 256). Auxiliary space: O(256).

Problem 5: Find the First and Last Occurrence Using Binary Search

Given a sorted array with duplicates, find the first and last indexes of a target.

#include <stdio.h> int firstOccurrence(const int arr[], int n, int target) { int low = 0, high = n - 1; int answer = -1; while (low <= high) { int mid = low + (high - low) / 2; if (arr[mid] == target) { answer = mid; high = mid - 1; } else if (arr[mid] < target) low = mid + 1; else high = mid - 1; } return answer; } int lastOccurrence(const int arr[], int n, int target) { int low = 0, high = n - 1; int answer = -1; while (low <= high) { int mid = low + (high - low) / 2; if (arr[mid] == target) { answer = mid; low = mid + 1; } else if (arr[mid] < target) low = mid + 1; else high = mid - 1; } return answer; } int main(void) { int arr[] = {1, 2, 2, 2, 3, 4, 5}; int n = sizeof(arr) / sizeof(arr[0]); int target = 2; printf("First index = %d\n", firstOccurrence(arr, n, target)); printf("Last index = %d\n", lastOccurrence(arr, n, target)); return 0; }
First index = 1 Last index = 3

Time: O(log n). Auxiliary space: O(1).

9. Technical Interview Questions

Q1. What is the difference between service-based and product-based coding preparation?

Both require strong fundamentals. Service-based fresher assessments often emphasize basic programming and implementation, while many product-oriented interviews place additional emphasis on algorithmic depth, complexity and problem-solving.

Q2. Is knowing C enough for DSA interviews?

C is sufficient for implementing fundamental data structures and algorithms. The important requirement is understanding pointers, memory management, algorithms and complexity.

Q3. Why are pointers important in embedded interviews?

Pointers are central to memory access, arrays, structures, linked data structures, buffers and hardware register programming.

Q4. What is the difference between a stack and heap in memory management?

The call stack stores function activation records and automatic storage. The heap is a region used for dynamic memory allocation, such as with malloc and free. These are different from the abstract stack and heap data structures.

Q5. Why is XOR useful in bit manipulation?

XOR can toggle bits, identify differing bits and support selected bitwise algorithms. It is not a universal replacement for temporary variables or safe swapping.

Q6. What should you do if you cannot solve a coding question?

Clarify the constraints, discuss a brute-force approach, test a small example and then identify opportunities to optimize. Explain your reasoning rather than remaining silent.

Q7. Should you memorize company-specific questions?

No. Learn the algorithmic pattern and practice variations. This prepares you for changed inputs and unfamiliar problem statements.

11. Preparation Roadmap

  1. Foundation: C syntax, loops, functions, arrays, strings and pointers.
  2. Core algorithms: Searching, sorting, recursion and complexity.
  3. Data structures: Linked lists, stacks, queues, trees, heaps and hashing.
  4. Problem-solving patterns: Two pointers, sliding window, prefix sum and monotonic stack.
  5. Advanced DSA: Graphs, greedy algorithms, backtracking and dynamic programming.
  6. Company practice: Solve timed sets and explain your solutions aloud.
  7. Interview preparation: Revise C fundamentals, memory management and project explanations.

13. Lesson Summary

  • Company-wise preparation should be based on role requirements and problem patterns.
  • Service-based assessments often emphasize programming fundamentals and implementation.
  • Product-oriented preparation should include deeper algorithmic problem solving.

  • Practice representative questions under timed conditions.
  • Explain correctness, complexity and edge cases in every interview solution.
