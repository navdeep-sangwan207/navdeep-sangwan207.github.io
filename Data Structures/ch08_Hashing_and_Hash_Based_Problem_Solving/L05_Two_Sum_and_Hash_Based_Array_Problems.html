2. The Two Sum Problem

Problem: Given an integer array and a target value, find the indices of two distinct elements whose sum equals the target.

Example:

Array  = {2, 7, 11, 15}
Target = 9

Since:

2 + 7 = 9

The answer is indices 0 and 1.

Important interview condition: You must use two different array positions. The same element cannot be used twice.

3. Approach 1 – Brute Force

Check every possible pair using two nested loops.

Complete C11 Program

#include <stdio.h>
#include <stdbool.h>

bool two_sum_brute_force(
    const int arr[],
    int n,
    long long target,
    int *index1,
    int *index2)
{
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {

            if ((long long)arr[i] + arr[j] == target) {
                *index1 = i;
                *index2 = j;
                return true;
            }
        }
    }

    return false;
}

int main(void)
{
    int arr[] = {2, 7, 11, 15};
    int n = sizeof(arr) / sizeof(arr[0]);

    long long target = 9;
    int i, j;

    if (two_sum_brute_force(arr, n, target, &i, &j)) {
        printf("Pair Found\n");
        printf("Indices: %d, %d\n", i, j);
        printf("Values: %d, %d\n", arr[i], arr[j]);
    } else {
        printf("No valid pair found.\n");
    }

    return 0;
}

Expected Output

Pair Found
Indices: 0, 1
Values: 2, 7

Complexity

  • Time: O(n²)
  • Auxiliary space: O(1)

4. Approach 2 – Two Sum Using Hashing

Instead of checking every pair, calculate the complement of the current element.

The formula is:

complement = target - current_element

For every element:

  1. Calculate the complement.
  2. Search for the complement in the hash table.
  3. If found, return the stored index and current index.
  4. Otherwise, insert the current element and its index.

Dry Run

Array  = {2, 7, 11, 15}
Target = 9
IterationCurrentComplementHash TableAction
127EmptyInsert 2 → 0
2722 → 0Found 2

Result: indices 0 and 1.

5. Complete Two Sum Implementation Using C11

This implementation uses separate chaining. Each hash node stores an integer key and its original array index.

#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

#define TABLE_SIZE 101

typedef struct Node {
    int key;
    int index;
    struct Node *next;
} Node;

typedef struct {
    Node *bucket[TABLE_SIZE];
} HashTable;

void ht_init(HashTable *ht)
{
    for (int i = 0; i < TABLE_SIZE; i++) {
        ht->bucket[i] = NULL;
    }
}

unsigned int hash_function(int key)
{
    uint32_t value = (uint32_t)key;

    value ^= value >> 16;
    value *= 0x7feb352dU;
    value ^= value >> 15;
    value *= 0x846ca68bU;
    value ^= value >> 16;

    return value % TABLE_SIZE;
}

bool ht_search(
    HashTable *ht,
    int key,
    int *index)
{
    unsigned int position = hash_function(key);
    Node *current = ht->bucket[position];

    while (current != NULL) {
        if (current->key == key) {
            *index = current->index;
            return true;
        }

        current = current->next;
    }

    return false;
}

bool ht_insert(
    HashTable *ht,
    int key,
    int index)
{
    unsigned int position = hash_function(key);

    Node *newNode = malloc(sizeof(Node));

    if (newNode == NULL) {
        return false;
    }

    newNode->key = key;
    newNode->index = index;
    newNode->next = ht->bucket[position];

    ht->bucket[position] = newNode;

    return true;
}

void ht_destroy(HashTable *ht)
{
    for (int i = 0; i < TABLE_SIZE; i++) {
        Node *current = ht->bucket[i];

        while (current != NULL) {
            Node *temp = current;
            current = current->next;
            free(temp);
        }

        ht->bucket[i] = NULL;
    }
}

bool two_sum(
    const int arr[],
    int n,
    long long target,
    int *index1,
    int *index2)
{
    HashTable ht;
    ht_init(&ht);

    for (int i = 0; i < n; i++) {

        long long complement =
            target - (long long)arr[i];

        /*
         * This hash table stores int keys.
         * A complement outside the int range
         * cannot match any array element.
         */
        if (complement >= INT32_MIN
            && complement <= INT32_MAX) {

            int foundIndex;

            if (ht_search(
                    &ht,
                    (int)complement,
                    &foundIndex)) {

                *index1 = foundIndex;
                *index2 = i;

                ht_destroy(&ht);
                return true;
            }
        }

        if (!ht_insert(&ht, arr[i], i)) {
            ht_destroy(&ht);
            return false;
        }
    }

    ht_destroy(&ht);
    return false;
}

int main(void)
{
    int arr[] = {2, 7, 11, 15};
    int n = sizeof(arr) / sizeof(arr[0]);

    long long target = 9;
    int i, j;

    if (two_sum(arr, n, target, &i, &j)) {
        printf("Two Sum Pair Found\n");
        printf("Indices: %d and %d\n", i, j);
        printf("Values: %d and %d\n", arr[i], arr[j]);
        printf("Sum: %lld\n",
               (long long)arr[i] + arr[j]);
    } else {
        printf("No valid pair found.\n");
    }

    return 0;
}

Expected Output

Two Sum Pair Found
Indices: 0 and 1
Values: 2 and 7
Sum: 9
Implementation note: This example uses the C standard's int32_t and INT32_MIN/INT32_MAX limits for a 32-bit integer hash key. The C implementation requires an implementation providing these exact-width integer types. The target is long long to avoid overflow during addition and complement calculation.

Complexity

  • Expected time: O(n)
  • Worst-case time: O(n²) with severe collisions
  • Auxiliary space: O(n)

6. Count Pairs with a Given Sum

Problem: Count the number of index pairs (i, j), where i is less than j, such that:

arr[i] + arr[j] = target

Unlike Two Sum, this problem asks for the total number of valid pairs.

Example

Array  = {1, 5, 7, -1, 5}
Target = 6

Valid pairs by indices are:

  • (1, 5) using indices 0 and 1
  • (1, 5) using indices 0 and 4
  • (7, -1) using indices 2 and 3

Answer = 3 pairs.

Complete C11 Program

#include <stdio.h>
#include <limits.h>
#include <stdbool.h>

long long count_pairs(
    const int arr[],
    int n,
    long long target)
{
    long long count = 0;

    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if ((long long)arr[i] + arr[j] == target) {
                count++;
            }
        }
    }

    return count;
}

int main(void)
{
    int arr[] = {1, 5, 7, -1, 5};
    int n = sizeof(arr) / sizeof(arr[0]);

    long long target = 6;

    printf("Number of valid pairs: %lld\n",
           count_pairs(arr, n, target));

    return 0;
}

Expected Output

Number of valid pairs: 3

Complexity: O(n²) time and O(1) auxiliary space.

Interview follow-up: Optimize this using a frequency hash table. For each value x, add the frequency of target - x seen so far, then increment the frequency of x. This counts each index pair exactly once. The expected time becomes O(n).

7. Find Pairs with a Given Difference

Problem: Given an array and a difference k, determine whether there are two distinct positions whose values differ by k.

For example:

Array = {5, 20, 3, 2, 50, 80}
k = 78

Since 80 - 2 = 78, a valid pair exists.

Complete C11 Program – Brute Force

#include <stdio.h>
#include <stdbool.h>

bool has_difference(
    const int arr[],
    int n,
    long long k)
{
    if (k < 0) {
        k = -k;
    }

    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {

            long long difference =
                (long long)arr[i] - arr[j];

            if (difference < 0) {
                difference = -difference;
            }

            if (difference == k) {
                return true;
            }
        }
    }

    return false;
}

int main(void)
{
    int arr[] = {5, 20, 3, 2, 50, 80};
    int n = sizeof(arr) / sizeof(arr[0]);

    long long k = 78;

    if (has_difference(arr, n, k)) {
        printf("Pair with given difference exists.\n");
    } else {
        printf("No such pair exists.\n");
    }

    return 0;
}

Expected Output

Pair with given difference exists.

Complexity: O(n²) time and O(1) auxiliary space.

Hashing optimization: For each value x, search for x + k or x - k in a hash set. Insert the current value after checking. Use a wider integer type for the arithmetic and ensure the hash table can represent the searched values.

8. Intersection of Two Arrays

Problem: Find the distinct elements common to two arrays.

Example

A = {1, 2, 2, 3, 4}
B = {2, 3, 5}

Distinct intersection:

{2, 3}

Hashing can store the elements of one array and check whether elements of the other array are present.

Important: Clarify whether the interview question expects a set intersection (distinct values) or a multiset intersection (respecting duplicate counts). They are different problems.

Approach

  1. Insert all values from the first array into a hash set.
  2. Scan the second array.
  3. If a value is present in the set and has not already been printed, report it.
  4. Mark it as reported to avoid duplicate output.

Expected time is O(n + m), with O(n) extra space, using a suitable hash set.

9. Longest Consecutive Sequence

Problem: Find the length of the longest sequence of consecutive integer values in an unsorted array.

Example

Array = {100, 4, 200, 1, 3, 2}

The longest consecutive sequence is:

1, 2, 3, 4

Answer = 4.

Hashing Approach

  1. Insert all array values into a hash set.
  2. For each value x, check whether x - 1 exists.
  3. If x - 1 does not exist, x is the beginning of a sequence.
  4. Continue checking x + 1, x + 2, and so on.
  5. Track the maximum sequence length.
When implementing this problem, guard against integer overflow when evaluating x - 1 and x + 1 at the limits of the int range. Duplicate values should not increase the sequence length.

Expected complexity: O(n) time and O(n) extra space with a well-distributed hash set.

12. Important Edge Cases

  • Empty array or arrays containing one element.
  • Negative numbers and zero.
  • Repeated values, such as {3, 3} with target 6.
  • No valid pair exists.
  • Several valid pairs exist.
  • Target or difference calculations exceed the int range.
  • Hash collisions occur.
  • Dynamic memory allocation fails.
  • Very large arrays require table resizing.

13. Placement Interview Questions and Answers

Q1. What is the complement technique in Two Sum?

Answer: For a current value x and target T, calculate T - x. If that complement is already stored in the hash table, the required pair has been found.

Q2. Why should we insert the current value after searching for its complement?

Answer: This prevents using the same array position twice. It also correctly handles duplicate values such as {3, 3} with target 6.

Q3. What is the expected time complexity of Two Sum using hashing?

Answer: O(n), because each array element is processed with an expected O(1) hash search and insertion.

Q4. How is Two Sum different from Count Pairs with a Given Sum?

Answer: Two Sum usually returns one valid pair or its indices. Count Pairs calculates the total number of valid index pairs.

Q5. Can Two Sum be solved without extra space?

Answer: Yes. Sorting followed by the two-pointer technique can solve it in O(n log n) time. However, sorting may change the original positions, so preserve indices if the question requires them.

Q6. Why is hashing useful for the longest consecutive sequence problem?

Answer: A hash set provides expected O(1) membership checks, allowing us to identify sequence beginnings and extend each sequence efficiently.

Q7. What is the difference between set intersection and multiset intersection?

Answer: Set intersection reports each common value once. Multiset intersection preserves the minimum occurrence count from the two input arrays.

Q8. Does a hash table guarantee O(1) lookup?

Answer: No. O(1) is expected under suitable hashing and load-factor conditions. Worst-case lookup can be O(n) due to collisions.

16. Lesson Summary

  • Two Sum uses the complement technique.
  • Hashing reduces many pair-searching problems to O(n) expected time.
  • Frequency maps help count pairs without double-counting index pairs.
  • Hash sets provide efficient membership checks.
  • Always account for duplicates, integer overflow, collisions and memory management.
