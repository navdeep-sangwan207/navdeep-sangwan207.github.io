2. What Is Hashing?

Hashing is a technique used to transform a key into an index of a table using a mathematical function called a hash function.

The calculated index helps us store and retrieve data efficiently.

Example

Suppose we want to store the following employee IDs:

Employee IDs: 101 102 103 104

Instead of searching the entire collection, we can calculate an index for each ID and store the corresponding record at that location.

Basic Hashing Flow

Input Key | v Hash Function | v Hash Value | v Table Index | v Store / Search
Important: Hashing is designed to make insertion, searching and deletion efficient. Its average-case performance can be O(1) under suitable assumptions, but worst-case performance can be O(n).

3. What Is a Hash Function?

A hash function is a function that converts a key into a numerical hash value or table index.

For a hash table of size m, a common requirement is:

0 <= h(key) < m

Here:

  • key is the input value.
  • h() is the hash function.
  • m is the size of the hash table.
  • h(key) is the resulting table index.

Example

Consider the hash function:

h(key) = key % 10

For key = 123:

h(123) = 123 % 10 = 3

The key 123 maps to index 3.

4. Hash Value and Hash Table Index

A hash value is the output of a hash function. A table index is the position used to access the hash table.

Some hash functions directly produce a valid table index. Others produce a larger hash value that must be reduced to the table's valid index range.

Example

Table size = 7 Hash function: h(key) = key % 7 Key = 25 h(25) = 25 % 7 = 4 Table index = 4
Index:  0   1   2   3   4   5   6
                    |
                    v
                 Key: 25

5. Direct Addressing vs Hashing

Direct Addressing

In direct addressing, the key itself is used as the array index.

For example:

array[100] = employeeRecord;

This approach is practical when the key range is small and manageable.

Hashing

Hashing maps a potentially large key space into a smaller table.

Direct Addressing: Key 100 -> Index 100 Hashing: Key 100 -> Hash Function -> Index 4

Comparison

Direct AddressingHashing
Key is used directly as index.Hash function calculates the index.
Can require a very large array.Uses a comparatively smaller table.
No collisions for distinct valid keys.Collisions can occur.
Useful for small key ranges.Useful for larger key spaces.

6. Properties of a Good Hash Function

1. Deterministic

The same key should produce the same hash value when the hash function and its configuration remain unchanged.

2. Uniform Distribution

Keys should be distributed reasonably evenly across the table.

3. Fast Computation

The hash function should be efficient to calculate.

4. Low Collision Rate

Different keys should map to the same index as infrequently as practical.

5. Valid Index Range

The resulting index must be within the valid table range.

A good hash function reduces clustering and improves practical performance, but it cannot guarantee that collisions will never occur when the key space is larger than the table.

7. Division Method

The division method is one of the simplest hash-function techniques.

h(key) = key % table_size

Example

Table size = 11 Key = 25 h(25) = 25 % 11 = 3

Therefore, key 25 maps to index 3.

Another Example

Key = 38 Table size = 11 h(38) = 38 % 11 = 5

C Program: Division Hash Function

#include <stdio.h>

#define TABLE_SIZE 11

int hashFunction(int key)
{
    int index = key % TABLE_SIZE;

    if (index < 0)
        index += TABLE_SIZE;

    return index;
}

int main(void)
{
    int key = 25;

    printf("Key: %d\n", key);
    printf("Hash index: %d\n",
           hashFunction(key));

    return 0;
}

Expected Output

Key: 25 Hash index: 3

8. Multiplication Method

The multiplication method uses a constant fractional value to calculate the hash index.

A common formula is:

h(key) = floor(m * fractional_part(key * A))

Where:

  • m = table size.
  • A = a constant between 0 and 1.
  • fractional_part(x) = fractional part of x.

Example

Let:

key = 25 m = 10 A = 0.6180339887

Then:

key * A = 25 * 0.6180339887 = 15.4508497175 Fractional part = 0.4508497175 h(25) = floor(10 * 0.4508497175) = 4

Therefore, the calculated index is 4.

The multiplication method is another way to distribute keys across a table. In production systems, the hash function should be chosen based on the key type, expected input distribution and threat model.

9. Hashing Negative Integer Keys

In C, the remainder operator can produce a negative result when the dividend is negative.

Example

-15 % 10 = -5

A negative array index is invalid.

Safe Index Calculation

int hashFunction(int key, int tableSize)
{
    int index = key % tableSize;

    if (index < 0)
        index += tableSize;

    return index;
}

This assumes that tableSize is positive.

Example

Key = -15 Table size = 10 -15 % 10 = -5 Corrected index: -5 + 10 = 5
Final hash index: 5

10. String Hashing

Hashing is not restricted to integer keys. Strings can also be converted into hash values.

A simple string hash function adds the character codes of all characters.

Example

String = "CAT" ASCII: C = 67 A = 65 T = 84 Hash value = 67 + 65 + 84 = 216

For a table of size 10:

Index = 216 % 10 = 6
A simple character-sum hash function is suitable only for demonstrating the concept. It produces many collisions because anagrams such as CAT and ACT have the same sum.

C Program: Simple String Hash Function

#include <stdio.h>

#define TABLE_SIZE 10

unsigned int stringHash(const char str[])
{
    unsigned int hash = 0;

    for (size_t i = 0; str[i] != '\0'; i++)
    {
        hash += (unsigned char)str[i];
    }

    return hash % TABLE_SIZE;
}

int main(void)
{
    const char name[] = "CAT";

    printf("String: %s\n", name);
    printf("Hash index: %u\n",
           stringHash(name));

    return 0;
}

Expected Output

String: CAT Hash index: 6

11. A Better Simple String Hash Function

A polynomial rolling-style hash uses character order and multiplication.

hash = (hash * base + character) % table_size

C Program

#include <stdio.h>

#define TABLE_SIZE 101
#define BASE 31

unsigned int stringHash(const char str[])
{
    unsigned int hash = 0;

    for (size_t i = 0; str[i] != '\0'; i++)
    {
        hash = (
            hash * BASE +
            (unsigned char)str[i]
        ) % TABLE_SIZE;
    }

    return hash;
}

int main(void)
{
    const char str[] = "CAT";

    printf("String: %s\n", str);
    printf("Hash index: %u\n",
           stringHash(str));

    return 0;
}

Expected Output

String: CAT Hash index: 36

This example illustrates how character order influences the hash. It is still a simplified educational function, not a cryptographic hash or a universal production hash-table design.

12. What Is a Hash Collision?

A collision occurs when two different keys produce the same hash table index.

Example

Hash function: h(key) = key % 10 Key 25: 25 % 10 = 5 Key 35: 35 % 10 = 5

Both keys map to index 5.

A collision does not mean that the keys are identical. It means that different keys have mapped to the same table position.

Why Do Collisions Occur?

  • The key space can be much larger than the table.
  • Multiple keys can produce the same remainder.
  • Hash functions compress many possible keys into a limited number of indexes.

How Are Collisions Handled?

  • Separate Chaining
  • Linear Probing
  • Quadratic Probing
  • Double Hashing

These techniques will be studied in detail in Lesson 2.

13. What Is Load Factor?

Load factor measures how full a hash table is.

Load Factor (α) = Number of stored elements ------------------------- Table size

Example

Number of stored elements = 7 Table size = 10 Load factor = 7 / 10 = 0.7

Therefore, the load factor is 0.7 or 70%.

Why Is Load Factor Important?

  • It indicates how full a hash table is.
  • A high load factor can increase collisions.
  • It helps determine when resizing or rehashing may be needed.
  • It influences average lookup performance.
A common implementation strategy is to resize a hash table when its load factor crosses a chosen threshold. The threshold depends on the collision-handling method and implementation.

14. Hashing Operations

OperationPurpose
InsertionStore a key-value pair.
SearchingFind a key and retrieve its value.
DeletionRemove a stored key-value pair.
UpdatingChange the value associated with a key.

Under suitable assumptions and a well-distributed hash function, these operations can have average O(1) time complexity.

In the worst case, operations can take O(n) time when many keys collide.

15. Applications of Hashing

  • Database indexing and lookup structures.
  • Compiler symbol tables.
  • Cache implementations.
  • Duplicate detection.
  • Frequency counting.
  • Fast membership testing.
  • File integrity verification using cryptographic hash functions.
  • Hash-based data structures and associative arrays.
  • Finding pairs and subarrays efficiently.
Hash-table hash functions and cryptographic hash functions serve different purposes. A hash function designed for table indexing should not automatically be used for password storage, digital signatures or security verification.

18. Common Mistakes

  1. Assuming every key gets a unique index.
  2. Ignoring collision handling.
  3. Using a negative hash index for an array.
  4. Choosing a poor hash function.
  5. Ignoring load factor.
  6. Assuming hash-table operations are always O(1).
  7. Confusing hash values with original keys.
  8. Using a simple educational string hash in security-sensitive applications.

19. Placement Interview Questions and Answers

Q1. What is hashing?

Hashing maps a key to a table index using a hash function to support efficient storage and retrieval.

Q2. What is a hash function?

A function that calculates a hash value or table index from a key.

Q3. What is a hash table?

A data structure that stores keys or key-value pairs using hash-based indexing.

Q4. What is a collision?

A collision occurs when different keys map to the same hash table index.

Q5. What is a good hash function?

It is deterministic, fast, distributes keys reasonably uniformly and maps keys into valid table positions.

Q6. What is the division method?

It calculates the index using the remainder of a key divided by the table size.

Q7. What is the multiplication method?

It multiplies the key by a fractional constant and uses the fractional part to calculate an index.

Q8. What is load factor?

The ratio of the number of stored elements to the number of table slots.

Q9. What happens when the load factor increases?

Depending on the collision strategy and key distribution, collisions and lookup costs may increase.

Q10. What is rehashing?

Rehashing means rebuilding a hash table, commonly with a new capacity, and reinserting its existing entries.

Q11. What is the average searching complexity of hashing?

O(1), under suitable distribution and load-factor assumptions.

Q12. What is the worst-case searching complexity?

O(n), when many keys collide or form a long search sequence.

Q13. Can strings be used as hash keys?

Yes. A string hash function converts the characters into a hash value.

Q14. Can two different strings have the same hash value?

Yes. This is a hash collision.

Q15. Is hashing better than Binary Search?

It depends on the requirement. Hashing offers average O(1) lookup, while Binary Search offers O(log n) lookup on sorted data and supports ordered operations.

Q16. What is direct addressing?

It uses the key itself as the array index.

Q17. Why is modulo used in the division method?

It reduces a key to a valid index range from 0 to table size minus one.

Q18. Can hashing be used for duplicate detection?

Yes. Store previously encountered values and check whether a value is already present.

Q19. What is the difference between a hash function and a hash table?

A hash function calculates an index; a hash table is the data structure that stores entries using those indexes.

Q20. What is the difference between cryptographic hashing and hash-table hashing?

Cryptographic hashing is designed for security properties such as collision resistance. Hash-table hashing is designed primarily for efficient indexing and distribution.
