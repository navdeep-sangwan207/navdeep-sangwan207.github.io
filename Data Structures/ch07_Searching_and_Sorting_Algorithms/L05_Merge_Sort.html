2. What Is Merge Sort?

Merge Sort is a comparison-based sorting algorithm that uses the Divide and Conquer technique.

It divides an array into smaller subarrays until each subarray contains one element. It then merges these smaller sorted subarrays to produce a completely sorted array.

Key concept: Divide the problem into smaller problems, solve them recursively, and combine their results.

Three Main Steps

  1. Divide: Split the array into two approximately equal halves.
  2. Conquer: Recursively sort both halves.
  3. Combine: Merge the two sorted halves into one sorted array.

3. Understanding Divide and Conquer

Suppose the input array is:

38 27 43 3 9 82 10

Merge Sort repeatedly divides the array.

[38 27 43 3 9 82 10] / \ [38 27 43 3] [9 82 10] / \ / \ [38 27] [43 3] [9 82] [10] / \ / \ / \ [38][27] [43][3] [9][82]

Each single-element subarray is already sorted.

Now the merging process begins:

[38] + [27] → [27 38] [43] + [3] → [3 43] [9] + [82] → [9 82] [27 38] + [3 43] → [3 27 38 43] [9 82] + [10] → [9 10 82] [3 27 38 43] + [9 10 82] Final: [3 9 10 27 38 43 82]

4. The Merge Operation

The merge operation combines two already sorted portions of an array into one sorted portion.

Example

Two sorted arrays:

Array A: 2 5 8 Array B: 1 3 9 Merged: 1 2 3 5 8 9

Merge Logic

  1. Maintain one index for each sorted portion.
  2. Compare the elements at both indexes.
  3. Copy the smaller element into the temporary array.
  4. Advance the index of the selected portion.
  5. Repeat until one portion is exhausted.
  6. Copy the remaining elements from the other portion.
  7. Copy the merged result back into the original array.
Interview point: The merge operation takes O(n) time for a combined subarray containing n elements.

5. Merge Sort Algorithm

Pseudocode

MERGE_SORT(arr, left, right) IF left < right mid = left + (right - left) / 2 MERGE_SORT(arr, left, mid) MERGE_SORT(arr, mid + 1, right) MERGE(arr, left, mid, right)

Merge Pseudocode

MERGE(arr, left, mid, right) Copy left and right portions into temporary storage. Compare the current elements from both portions. Copy the smaller element into the output. Copy remaining elements. Copy merged elements back into arr.

6. Complete C11 Program: Merge Sort

This implementation uses one dynamically allocated temporary array for the entire sorting operation. It avoids creating a separate variable-length array at every recursive level.

#include <stdio.h>
#include <stdlib.h>

void merge(int arr[], int temp[],
           int left, int mid, int right)
{
    int i = left;
    int j = mid + 1;
    int k = left;

    /* Merge the two sorted portions */
    while (i <= mid && j <= right)
    {
        if (arr[i] <= arr[j])
        {
            temp[k++] = arr[i++];
        }
        else
        {
            temp[k++] = arr[j++];
        }
    }

    /* Copy remaining elements from left portion */
    while (i <= mid)
    {
        temp[k++] = arr[i++];
    }

    /* Copy remaining elements from right portion */
    while (j <= right)
    {
        temp[k++] = arr[j++];
    }

    /* Copy merged elements back into original array */
    for (i = left; i <= right; i++)
    {
        arr[i] = temp[i];
    }
}

void mergeSort(int arr[], int temp[],
               int left, int right)
{
    if (left < right)
    {
        int mid = left + (right - left) / 2;

        /* Sort left half */
        mergeSort(arr, temp, left, mid);

        /* Sort right half */
        mergeSort(arr, temp, mid + 1, right);

        /* Merge sorted halves */
        merge(arr, temp, left, mid, right);
    }
}

int main(void)
{
    int arr[] = {38, 27, 43, 3, 9, 82, 10};

    int n = (int)(sizeof(arr) / sizeof(arr[0]));

    int *temp = malloc((size_t)n * sizeof(*temp));

    if (temp == NULL)
    {
        printf("Memory allocation failed.\n");
        return 1;
    }

    printf("Before sorting: ");

    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }

    printf("\n");

    mergeSort(arr, temp, 0, n - 1);

    printf("After sorting: ");

    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }

    printf("\n");

    free(temp);

    return 0;
}

Expected Output

Before sorting: 38 27 43 3 9 82 10 After sorting: 3 9 10 27 38 43 82
Memory management: The temporary array is allocated using malloc() and released using free(). Always check whether memory allocation succeeded.

7. Complete Dry Run

Input:

38 27 43 3

Step 1: Division

[38 27 43 3] / \ [38 27] [43 3] / \ / \ [38][27] [43][3]

Step 2: First Merging

[38] + [27] = [27 38] [43] + [3] = [3 43]

Step 3: Final Merging

[27 38] + [3 43] Compare 27 and 3: Copy 3. Compare 27 and 43: Copy 27. Compare 38 and 43: Copy 38. Copy remaining: 43. Final: 3 27 38 43

Dry Run Table

StageOperationResult
1Divide original array[38, 27] and [43, 3]
2Divide left portion[38], [27]
3Divide right portion[43], [3]
4Merge left portion[27, 38]
5Merge right portion[3, 43]
6Final merge[3, 27, 38, 43]

8. Time Complexity Analysis

Merge Sort divides the array into two halves and performs a linear-time merge operation.

Its recurrence relation is:

T(n) = 2T(n/2) + O(n)

Using the Master Theorem:

a = 2 b = 2 f(n) = O(n) n^(log_b(a)) = n^(log_2(2)) = n Therefore: T(n) = O(n log n)

Complexity Table

CaseTime Complexity
Best caseO(n log n)
Average caseO(n log n)
Worst caseO(n log n)

Merge Sort maintains O(n log n) time complexity for all input arrangements.

9. Space Complexity

The implementation uses:

  • Temporary array: O(n)
  • Recursive call stack: O(log n)

Total auxiliary space is O(n), because O(n) dominates O(log n).

Interview answer: Merge Sort has O(n log n) time complexity in all cases and O(n) auxiliary space for array-based implementation.

10. Is Merge Sort Stable?

Yes. Merge Sort can be stable when equal elements are handled correctly during merging.

In this implementation, the condition is:

if (arr[i] <= arr[j])

When both values are equal, the element from the left portion is selected first. This preserves the relative order of equal elements from the original input.

Example

Original records: (80, A) (70, B) (80, C) (60, D) Stable sorted result: (60, D) (70, B) (80, A) (80, C)

11. Advantages of Merge Sort

  • Guaranteed O(n log n) time complexity.
  • Stable sorting algorithm.
  • Suitable for large datasets.
  • Works well with linked lists.
  • Useful for external sorting when data is too large for memory.
  • Predictable performance regardless of initial input order.

12. Disadvantages of Merge Sort

  • Requires O(n) additional memory for arrays.
  • Recursive implementation uses call-stack space.
  • For small arrays, simpler algorithms such as Insertion Sort may be faster.
  • Array merging requires copying elements.

14. Merge Sort Applications

  • Sorting large datasets.
  • External sorting of files that cannot fit entirely into RAM.
  • Sorting linked lists.
  • Counting inversions in an array using a modified merge operation.
  • Combining multiple sorted datasets.
  • Stable sorting of records using multiple fields.

15. Common Programming Mistakes

  • Using an incorrect middle index.
  • Forgetting the base condition left < right.
  • Using incorrect boundaries when merging.
  • Forgetting to copy remaining elements from either half.
  • Forgetting to copy merged values back into the original array.
  • Using a strict less-than comparison instead of less-than-or-equal when stability is required.
  • Forgetting to free dynamically allocated memory.
  • Allocating temporary memory without checking malloc() results.

16. Frequently Asked Placement Interview Questions

Q1. What is Merge Sort?

Merge Sort is a stable comparison-based sorting algorithm that uses Divide and Conquer.

Q2. What is Divide and Conquer?

It is an algorithm design technique that divides a problem into smaller subproblems, solves them and combines their results.

Q3. What is the time complexity of Merge Sort?

O(n log n) in best, average and worst cases.

Q4. Why is Merge Sort O(n log n)?

There are O(log n) levels of division, and each level performs O(n) total merging work.

Q5. What is the space complexity of array-based Merge Sort?

O(n) auxiliary space.

Q6. Is Merge Sort stable?

Yes, when equal elements are merged in their original relative order.

Q7. Is Merge Sort in-place?

The standard array implementation is not in-place because it requires an additional temporary array.

Q8. What is the base condition of Merge Sort?

The recursion stops when the subarray has zero or one element, represented by left >= right.

Q9. What is the purpose of the merge() function?

It combines two sorted portions into one sorted portion.

Q10. Can Merge Sort be used for linked lists?

Yes. It is particularly suitable for linked lists because merging can be performed by rearranging links without requiring array-style random access.

Q11. What is the recurrence relation?

T(n) = 2T(n/2) + O(n).

Q12. What is the advantage of Merge Sort over Bubble Sort?

Merge Sort has O(n log n) worst-case time complexity, while Bubble Sort has O(n²).

Q13. Why do we use a temporary array?

It stores the merged elements before copying them back into the original array.

Q14. Why is the comparison arr[i] <= arr[j] important for stability?

It selects the left-side element first when equal values are encountered, preserving their original relative order.

Q15. What happens if the input array has only one element?

The array is already sorted. The recursive base condition prevents further division.

Q16. What is the maximum recursion depth?

O(log n), because the array is repeatedly divided into approximately equal halves.

Q17. Can Merge Sort sort data stored in files?

Yes. External Merge Sort is used to sort datasets that are too large to fit into main memory.

Q18. Which is better for a large array: Merge Sort or Insertion Sort?

Merge Sort is generally better because it has O(n log n) time complexity, while Insertion Sort has O(n²) average and worst-case complexity.

Q19. What is an inversion in an array?

An inversion is a pair of indices (i, j) where i < j but arr[i] > arr[j].

Q20. Can Merge Sort be used to count inversions?

Yes. During merging, whenever an element from the right portion is placed before remaining elements in the left portion, those remaining left elements contribute inversions.

19. Lesson Summary
