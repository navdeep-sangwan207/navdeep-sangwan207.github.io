2. Introduction to Bitwise Operators

Bitwise operators operate on corresponding bits of integer operands.

OperatorNameExample
&Bitwise ANDa & b
|Bitwise ORa | b
^Bitwise XORa ^ b
~Bitwise NOT~a

For the following examples, consider:

a = 12 = 1100
b = 10 = 1010

The binary values are shown using four relevant bits to make the calculations easier to understand.

3. Bitwise AND (&)

The bitwise AND operator produces 1 only when both corresponding bits are 1.

Truth table

ABA & B
000
010
100
111

Example: 12 & 10

  1100
& 1010
------
  1000

1000₂ = 8₁₀.

Result: 12 & 10 = 8

Program 1: Bitwise AND

#include <stdio.h>

int main(void)
{
    unsigned int a = 12;
    unsigned int b = 10;

    unsigned int result = a & b;

    printf("a = %u\n", a);
    printf("b = %u\n", b);
    printf("AND result = %u\n", result);

    return 0;
}
Expected output: 
a = 12
b = 10
AND result = 8

Important uses of AND

  • Checking whether a particular bit is set.
  • Extracting selected bits using a mask.
  • Clearing selected bits using an appropriate mask.
  • Checking whether an unsigned integer is even or odd.

Example: Check whether a number is odd.

#include <stdio.h>

int main(void)
{
    unsigned int number = 15;

    if (number & 1U)
        printf("Odd number\n");
    else
        printf("Even number\n");

    return 0;
}
Expected output: 
Odd number

The least significant bit of an odd number is 1, while that of an even number is 0.

6. Bitwise NOT (~)

The bitwise NOT operator inverts every bit of its integer operand:

  • 0 becomes 1.
  • 1 becomes 0.

Example using an 8-bit unsigned value

Let a = 00001100.

Original: 00001100
NOT:      11110011

For an 8-bit unsigned value, the result is 243.

In C, ~ is applied after integer promotions. A uint8_t operand is typically promoted to int before the operation. Therefore, ~a does not necessarily produce an 8-bit result.

Program 4: Bitwise NOT with an explicit 8-bit mask

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint8_t a = 12;

    uint8_t result = (uint8_t)(~a);

    printf("Original value = %u\n", (unsigned int)a);
    printf("NOT result     = %u\n", (unsigned int)result);

    return 0;
}
Expected output: 
Original value = 12
NOT result     = 243

The explicit conversion to uint8_t keeps only the low eight bits of the promoted result. This exact-width type is available when supported by the implementation.

7. Combined Bitwise Operations

Multiple bitwise operators can be combined in a single expression. Parentheses should be used to make the intended order clear.

Example

unsigned int a = 12;
unsigned int b = 10;
unsigned int c = 6;

unsigned int result = (a & b) | c;

Step 1: Calculate a & b.

  1100
& 1010
------

Step 2: Calculate 1000 | 0110.

  1000
| 0110

Final result = 14.

Expected output: 
Result = 14

8. Practical Program: Apply All Four Operators

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint8_t a = 12;
    uint8_t b = 10;

    uint8_t and_result = (uint8_t)(a & b);
    uint8_t or_result  = (uint8_t)(a | b);
    uint8_t xor_result = (uint8_t)(a ^ b);
    uint8_t not_result = (uint8_t)(~a);

    printf("AND = %u\n", (unsigned int)and_result);
    printf("OR  = %u\n", (unsigned int)or_result);
    printf("XOR = %u\n", (unsigned int)xor_result);
    printf("NOT = %u\n", (unsigned int)not_result);

    return 0;
}
Expected output: 
AND = 8
OR  = 14
XOR = 6
NOT = 243

9. Common Applications in Coding Interviews

9.1 Check even or odd

Check the least significant bit using AND.

if ((number & 1U) == 0U)
    printf("Even");
else
    printf("Odd");

Time complexity: O(1).

9.2 Find the unique element

Given an array where every value appears twice except one, XOR all elements. Equal values cancel each other.

#include <stdio.h>

int main(void)
{
    int arr[] = {4, 1, 2, 1, 2};
    int n = (int)(sizeof(arr) / sizeof(arr[0]));

    int result = 0;

    for (int i = 0; i < n; i++)
    {
        result ^= arr[i];
    }

    printf("Unique element = %d\n", result);

    return 0;
}
Expected output: 
Unique element = 4

Dry run:

StepElementRunning XOR
144
215
327
416
524

Time complexity: O(n).

Extra space complexity: O(1).

9.3 Find the missing number from 0 to N

Given N distinct numbers from the range 0 to N, exactly one number is missing. XOR can be used to find it.

#include <stdio.h>

int main(void)
{
    int arr[] = {3, 0, 1};
    int n = (int)(sizeof(arr) / sizeof(arr[0]));

    int result = n;

    for (int i = 0; i < n; i++)
    {
        result ^= i;
        result ^= arr[i];
    }

    printf("Missing number = %d\n", result);

    return 0;
}
Expected output: 
Missing number = 2

Why it works: Every number that appears both in the complete range and in the array cancels itself through XOR. Only the missing number remains.

Time complexity: O(n).

Extra space complexity: O(1).

11. Common Mistakes

  1. Using logical AND (&&) instead of bitwise AND (&).
  2. Confusing XOR with OR.
  3. Forgetting that NOT operates on the promoted integer type.
  4. Assuming that the result of NOT is always an 8-bit value.
  5. Using signed integers for operations that require predictable bit patterns.
  6. Ignoring integer promotions and conversion rules.
  7. Writing complex expressions without parentheses.
  8. Assuming XOR can identify a unique element when values do not satisfy the required occurrence pattern.

13. Placement Interview Questions and Answers

Q1. What is bitwise AND?

Answer: It compares corresponding bits and produces 1 only when both bits are 1.

Q2. What is bitwise OR?

Answer: It produces 1 if at least one of the corresponding bits is 1.

Q3. What is XOR?

Answer: XOR produces 1 when corresponding bits are different.

Q4. What is the result of a ^ a?

Answer: Zero, because every bit is XORed with itself.

Q5. What is the result of a ^ 0?

Answer: The original value a.

Q6. How can you check whether a number is odd using bitwise AND?

Answer: Check whether number & 1U is nonzero.

Q7. How is XOR useful for finding a unique element?

Answer: Duplicate pairs cancel out, leaving the element that occurs once, provided all other elements occur exactly twice.

Q8. What is the result of 12 & 10?

Answer: 8, because 1100 AND 1010 produces 1000.

Q9. What is the result of 12 | 10?

Answer: 14, because 1100 OR 1010 produces 1110.

Q10. What is the result of 12 ^ 10?

Answer: 6, because 1100 XOR 1010 produces 0110.

Q11. What does the NOT operator do?

Answer: It inverts all bits of its promoted integer operand.

Q12. Why should unsigned values be preferred for bitwise operations?

Answer: Unsigned arithmetic and bit operations have more predictable, well-defined behavior for bit manipulation.

Q13. Can XOR be used to find a missing number?

Answer: Yes, if the array contains distinct values from a known complete range with exactly one missing value.

Q14. What is the difference between OR and XOR?

Answer: OR produces 1 when either or both bits are 1. XOR produces 1 only when the bits differ.

Q15. Does bitwise NOT always return a value between 0 and 255?

Answer: No. Integer promotions apply. Use an explicit conversion or mask when an 8-bit result is required.

14. Coding Practice Questions

  1. Write a C program to perform AND, OR, XOR and NOT on two integers.
  2. Check whether an integer is even or odd using bitwise AND.
  3. Find the unique element in an array where every other element appears twice.
  4. Find the missing number from a range of 0 to N using XOR.
  5. Swap two integer variables using XOR. Explain the limitations of this technique and why a temporary variable is generally preferred.
  6. Count how many bit positions differ between two unsigned integers using XOR and a bit-counting method.
  7. Determine which bits are set in both of two unsigned integers.
  8. Write a function that returns the bitwise complement restricted to the lowest eight bits.

16. Lesson Summary

  • AND returns 1 only when both bits are 1.
  • OR returns 1 when at least one bit is 1.
  • XOR returns 1 when the bits differ.
  • NOT inverts every bit of the promoted operand.
  • XOR is useful for unique-element and missing-number problems.
  • AND can check the least significant bit for even/odd classification.
  • Use unsigned types and explicit masks when working with fixed-width bit patterns.
