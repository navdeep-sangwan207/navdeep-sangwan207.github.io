Lesson 6: Best, Average and Worst Case Analysis

Analyze algorithm performance for different input arrangements. Learn operation counting, input distributions and interview-focused complexity analysis using C.

1. Introduction to Case Analysis

An algorithm may perform differently depending on the arrangement or values of its input. Case analysis studies this variation.

The three commonly studied cases are:

  • Best-case analysis
  • Average-case analysis
  • Worst-case analysis
Placement Definition: Best, average and worst cases describe the minimum, expected and maximum operation counts for inputs of a particular size, respectively.

2. Best-Case Analysis

Best-case analysis determines the minimum number of operations an algorithm requires among all valid inputs of size n.

Example: Linear Search

Consider this array:

int arr[] = {10, 20, 30, 40, 50};

Suppose we search for 10. The first comparison finds the key.

  • Number of comparisons: 1
  • Time Complexity: Θ(1)

Therefore, the best case for linear search is Θ(1).

When Does Best Case Occur?

  • The required element is found immediately.
  • An early termination condition is satisfied.
  • The input arrangement allows minimum work.

3. Worst-Case Analysis

Worst-case analysis determines the maximum number of operations an algorithm may perform for any valid input of size n.

Example: Linear Search

Consider searching for 50 in: 

int arr[] = {10, 20, 30, 40, 50};

The algorithm checks every element before finding the key.

  • Number of comparisons: 5
  • Time Complexity: Θ(n)

If the key is absent, all n elements must also be checked.

Worst-case analysis is especially important when a system must guarantee an upper limit on its execution work.

4. Average-Case Analysis

Average-case analysis calculates the expected number of operations over a specified probability distribution of possible inputs.

Example: Linear Search with a Present Key

Assume the key is equally likely to appear at any of the n positions.

The number of comparisons can be: 

Position 1  -> 1 comparison
Position 2  -> 2 comparisons
Position 3  -> 3 comparisons
...
Position n  -> n comparisons

The expected number of comparisons is:

Average comparisons:

(1 + 2 + 3 + ... + n) / n

= n(n + 1) / 2n

= (n + 1) / 2

Therefore, the average-case time complexity is Θ(n).

This average assumes the key is present and its position is uniformly distributed. If the key may be absent, the probability model must also account for absent-key searches.

5. Comparison of Three Cases

For linear search in an array of n elements, assuming the key is present:

Case Input Situation Comparisons Complexity
Best Key is at first position 1 Θ(1)
Average Key is equally likely at any position (n + 1) / 2 Θ(n)
Worst Key is at last position n Θ(n)

6. C Program: Count Linear Search Comparisons

The following program demonstrates how the number of comparisons changes according to the key's position. 

#include <stdio.h>

int linear_search(const int arr[], int n, int key,
                  int *comparisons)
{
    *comparisons = 0;

    for (int i = 0; i < n; i++)
    {
        (*comparisons)++;

        if (arr[i] == key)
        {
            return i;
        }
    }

    return -1;
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    int n = sizeof(arr) / sizeof(arr[0]);

    int comparisons;
    int key = 10;

    int result = linear_search(
        arr, n, key, &comparisons
    );

    if (result != -1)
    {
        printf("Element found at index %d\n", result);
    }
    else
    {
        printf("Element not found\n");
    }

    printf("Comparisons = %d\n", comparisons);

    return 0;
}
Expected Output: 
Element found at index 0
Comparisons = 1

Change key to 50 to observe five comparisons. Change key to 100 to observe five comparisons with an unsuccessful search.

Complexity

  • Best case: Θ(1)
  • Average case for uniformly distributed present keys: Θ(n)
  • Worst case: Θ(n)
  • Auxiliary space: O(1)

7. Case Analysis of Binary Search

Binary search works on a sorted array. It compares the target with the middle element and eliminates approximately half of the remaining search range after each unsuccessful comparison. 

#include <stdio.h>

int binary_search(const int arr[], int n, int key)
{
    int low = 0;
    int high = n - 1;

    while (low <= high)
    {
        int mid = low + (high - low) / 2;

        if (arr[mid] == key)
        {
            return mid;
        }
        else if (arr[mid] < key)
        {
            low = mid + 1;
        }
        else
        {
            high = mid - 1;
        }
    }

    return -1;
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50, 60, 70};
    int n = sizeof(arr) / sizeof(arr[0]);

    int key = 40;

    int result = binary_search(arr, n, key);

    printf("Index = %d\n", result);

    return 0;
}
Expected Output: 
Index = 3

Case Analysis

  • Best case: The middle element is the target on the first comparison. Θ(1).
  • Average case: The search range is repeatedly reduced by half. Θ(log n).
  • Worst case: The algorithm continues until the target is found or the search range becomes empty. Θ(log n).
Binary search requires sorted data and efficient access to the middle element. Its usual O(log n) array implementation is not directly suitable for a singly linked list.

8. Case Analysis of Insertion Sort

Insertion sort builds a sorted portion of an array by inserting each new element into its correct position. 

#include <stdio.h>

void insertion_sort(int arr[], int n)
{
    for (int i = 1; i < n; i++)
    {
        int key = arr[i];
        int j = i - 1;

        while (j >= 0 && arr[j] > key)
        {
            arr[j + 1] = arr[j];
            j--;
        }

        arr[j + 1] = key;
    }
}

int main(void)
{
    int arr[] = {5, 4, 3, 2, 1};
    int n = sizeof(arr) / sizeof(arr[0]);

    insertion_sort(arr, n);

    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }

    return 0;
}
Expected Output: 
1 2 3 4 5
Case Input Arrangement Time Complexity
Best Already sorted Θ(n)
Average Random arrangement Θ(n²)
Worst Reverse sorted Θ(n²)

In the best case, the inner while loop does not shift elements. In the worst case, each new element may need to be moved across the sorted portion.

Auxiliary Space: O(1)

9. Comparison of Common Algorithms

Linear Search Θ(1) Θ(n) Θ(n)
Binary Search Θ(1) Θ(log n) Θ(log n)
Bubble Sort (optimized) Θ(n) Θ(n²) Θ(n²)
Insertion Sort Θ(n) Θ(n²) Θ(n²)
Merge Sort Θ(n log n) Θ(n log n) Θ(n log n)

The optimized bubble sort listed here stops early if a complete pass performs no swaps.

10. Average-Case Analysis Using Probability

Average-case analysis can be expressed using expected value.

If an algorithm can receive possible inputs I₁, I₂, ..., Iₖ with probabilities P₁, P₂, ..., Pₖ, its expected operation count is:

Expected Operations:

E[T(n)] = Σ Pᵢ × T(Iᵢ)

The probabilities must sum to 1.

Example

Suppose an algorithm performs:

  • 10 operations with probability 0.5.
  • 20 operations with probability 0.3.
  • 30 operations with probability 0.2.

Expected operations:

E[T] = (0.5 × 10) + (0.3 × 20) + (0.2 × 30)

E[T] = 5 + 6 + 6 = 17 operations.

Average-case analysis depends on the probability distribution of inputs. A different distribution can produce a different average-case result.

11. Best, Average and Worst Case: Key Differences

Feature Best Case Average Case Worst Case
Meaning Minimum operations Expected operations Maximum operations
Input Most favorable Based on a probability model Least favorable
Use Understand ideal performance Understand expected performance Understand performance guarantees

12. Common Mistakes in Case Analysis

  • Assuming best case always means O(1). Some algorithms have linear best-case complexity.
  • Assuming average case is always the arithmetic mean of best and worst cases.
  • Ignoring the input distribution when calculating average-case complexity.
  • Assuming binary search works on unsorted arrays.
  • Confusing asymptotic notation with case analysis.
  • Ignoring early termination in optimized algorithms.

13. Placement Interview Questions and Answers

Q1. What is best-case analysis?

It determines the minimum number of operations for inputs of a particular size.

Q2. What is worst-case analysis?

It determines the maximum number of operations for inputs of a particular size.

Q3. What is average-case analysis?

It calculates the expected number of operations under a specified probability distribution of inputs.

Q4. What is the best-case complexity of linear search?

Θ(1), when the key is at the first position.

Q5. What is the worst-case complexity of linear search?

Θ(n), when the key is last or absent.

Q6. What is the average-case complexity of linear search?

Θ(n), under the usual uniform-position model for a present key.

Q7. What is the best-case complexity of binary search?

Θ(1), when the target matches the first middle element checked.

Q8. What is the worst-case complexity of binary search?

Θ(log n).

Q9. Why is worst-case analysis important?

It helps determine the maximum work an algorithm may require, which is important for performance guarantees.

Q10. Is average-case complexity always halfway between best and worst?

No. It depends on the input probability distribution and the operation counts.

Q11. What is the best case of insertion sort?

Θ(n), when the array is already sorted.

Q12. What is the worst case of insertion sort?

Θ(n²), typically when the array is sorted in reverse order.

Q13. What is an expected operation count?

It is the sum of each possible operation count multiplied by its probability.

Q14. Can best-case and worst-case complexities be the same?

Yes. Merge sort has Θ(n log n) time in its best, average and worst cases.

Q15. Which case is commonly used to describe algorithm scalability guarantees?

Worst-case analysis is commonly used because it describes the maximum operation count for inputs of a given size.
