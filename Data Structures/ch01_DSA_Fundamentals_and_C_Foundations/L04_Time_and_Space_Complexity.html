Lesson 4: Time and Space Complexity

Analyze algorithm performance by measuring execution growth and additional memory usage. Learn to calculate complexity using practical C programming examples.

1. What is Algorithm Complexity?

Algorithm complexity describes the resources required by an algorithm as its input size increases. The two major resources are:

  • Time Complexity: Growth in the number of operations performed.
  • Space Complexity: Growth in memory requirements.

Complexity analysis helps compare algorithms independently of a particular computer's processor speed or programming language.

Interview Definition: Time complexity describes how the operation count of an algorithm grows with input size. Space complexity describes how its memory requirements grow with input size.

2. What is Input Size?

Input size represents the amount of data processed by an algorithm. It is commonly represented by n.

Examples:

  • For an array, n is the number of elements.
  • For a string, n is the number of characters.
  • For a matrix, input size may depend on rows and columns.
  • For a graph, complexity may depend on vertices V and edges E.
Always identify the input size before calculating complexity. For a graph, using only n may be insufficient because both V and E matter.

3. What is Time Complexity?

Time complexity measures how the number of fundamental operations grows as the input size increases.

It is not normally measured by actual seconds. Instead, we count operations such as comparisons, assignments or loop iterations.

Example 1: Constant Number of Operations

#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    int sum = a + b;

    printf("%d\n", sum);

    return 0;
}

The number of operations does not grow with an external input size.

Time Complexity: O(1)

Example 2: Single Loop

#include <stdio.h>

int main(void)
{
    int n = 5;

    for (int i = 0; i < n; i++)
    {
        printf("%d ", i);
    }

    return 0;
}

The loop executes n times. If n doubles, the number of loop iterations also doubles.

Time Complexity: O(n)

Example 3: Nested Loops

#include <stdio.h>

int main(void)
{
    int n = 4;

    for (int i = 0; i < n; i++)
    {
        for (int j = 0; j < n; j++)
        {
            printf("%d %d\n", i, j);
        }
    }

    return 0;
}

The outer loop executes n times, and for each outer iteration the inner loop executes n times.

Total iterations = n × n = n².

Time Complexity: O(n²)

4. Common Time Complexity Classes

Complexity Name Example
O(1) Constant Array element access
O(log n) Logarithmic Binary Search
O(n) Linear Linear Search
O(n log n) Linearithmic Merge Sort
O(n²) Quadratic Simple nested-loop comparison
O(n³) Cubic Three nested loops
O(2ⁿ) Exponential Naive subset enumeration
O(n!) Factorial Generating all permutations
Generally, algorithms with slower-growing complexity scale better for large inputs, although constants, input constraints and implementation details also matter.

5. How to Calculate Time Complexity

Case 1: Simple Statement

int a = 10;
int b = 20;
int c = a + b;

A fixed number of operations is performed.

Complexity: O(1)

Case 2: Single Loop

for (int i = 0; i < n; i++)
{
    printf("%d", i);
}

The loop executes n times.

Complexity: O(n)

Case 3: Two Independent Loops

for (int i = 0; i < n; i++)
{
    printf("%d ", i);
}

for (int j = 0; j < n; j++)
{
    printf("%d ", j);
}

Total iterations = n + n = 2n.

After ignoring constant factors: O(n).

Case 4: Nested Loops

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        printf("*");
    }
}

Total iterations = n × n = n².

Complexity: O(n²)

Case 5: Loop with Doubling

for (int i = 1; i < n; i = i * 2)
{
    printf("%d ", i);
}

The values of i are 1, 2, 4, 8, 16 and so on.

After k iterations, i = 2ᵏ. The loop stops when 2ᵏ is at least n.

Therefore, k grows proportionally to log₂(n).

Complexity: O(log n)

Case 6: Nested Loop with Different Bounds

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < i; j++)
    {
        printf("*");
    }
}

The inner loop executes 0, 1, 2, ..., n - 1 times.

Total iterations: 0 + 1 + 2 + ... + (n - 1) = n(n - 1) / 2.

Complexity: O(n²)

6. Time Complexity of Common Operations

Operation Typical Time Complexity
Access array element by index O(1)
Traverse an array O(n)
Linear search O(n) worst case
Binary search on sorted array O(log n)
Bubble sort O(n²) worst case
Merge sort O(n log n)
Access linked-list element by position O(n)
Insert at head of linked list O(1)

These are typical complexities under standard implementation assumptions. Actual performance depends on the operation and data structure design.

7. What is Space Complexity?

Space complexity describes how much memory an algorithm requires as input size increases.

Memory usage may include:

  • Input storage.
  • Variables and temporary storage.
  • Dynamic memory allocation.
  • Function call stack.
  • Auxiliary data structures.

Auxiliary Space vs Total Space

Auxiliary space refers to the extra memory used by an algorithm, excluding its input storage.

Total space complexity includes input storage and additional memory used during execution.

Interview distinction: If an algorithm receives an array of n elements and uses only three additional variables, its auxiliary space is O(1), while the input array occupies O(n) space.

8. Examples of Space Complexity

Example 1: Constant Auxiliary Space

#include <stdio.h>

int sum_array(const int arr[], int n)
{
    int sum = 0;

    for (int i = 0; i < n; i++)
    {
        sum += arr[i];
    }

    return sum;
}

int main(void)
{
    int arr[] = {10, 20, 30, 40};
    int n = sizeof(arr) / sizeof(arr[0]);

    printf("Sum = %d\n", sum_array(arr, n));

    return 0;
}

The function uses only a fixed number of additional variables.

Auxiliary Space: O(1)

Time Complexity: O(n)

Example 2: Linear Auxiliary Space

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n = 5;

    int *arr = malloc((size_t)n * sizeof(*arr));

    if (arr == NULL)
    {
        printf("Memory allocation failed\n");
        return 1;
    }

    for (int i = 0; i < n; i++)
    {
        arr[i] = (i + 1) * 10;
    }

    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }

    free(arr);

    return 0;
}
10 20 30 40 50

The dynamically allocated array contains n integers.

Additional Space: O(n)

Time Complexity: O(n)

9. Recursive Space Complexity

Recursive algorithms use function calls. Each active recursive call may require a stack frame containing local variables, parameters and return information.

Example: Recursive Factorial

#include <stdio.h>

long long factorial(int n)
{
    if (n <= 1)
    {
        return 1;
    }

    return n * factorial(n - 1);
}

int main(void)
{
    int n = 5;

    printf("Factorial = %lld\n", factorial(n));

    return 0;
}
Factorial = 120

The recursion depth is proportional to n.

  • Time Complexity: O(n)
  • Auxiliary Space: O(n), due to recursive call stack.
Recursive calls consume stack memory. Very deep recursion can cause stack overflow. Also, the factorial result must fit in long long; this implementation is intended for non-negative n values within the representable range.

10. Complexity Analysis of Searching Algorithms

Linear Search

Linear search checks each element sequentially until the target is found or the array ends. 

#include <stdio.h>

int linear_search(const int arr[], int n, int key)
{
    for (int i = 0; i < n; i++)
    {
        if (arr[i] == key)
        {
            return i;
        }
    }

    return -1;
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    int n = sizeof(arr) / sizeof(arr[0]);
    int key = 40;

    int result = linear_search(arr, n, key);

    if (result != -1)
    {
        printf("Found at index %d\n", result);
    }
    else
    {
        printf("Not found\n");
    }

    return 0;
}
Found at index 3

Worst-case Time Complexity: O(n)

Auxiliary Space: O(1)

Binary Search

Binary search repeatedly divides the search interval into two halves. The input array must be sorted. 

#include <stdio.h>

int binary_search(const int arr[], int n, int key)
{
    int low = 0;
    int high = n - 1;

    while (low <= high)
    {
        int mid = low + (high - low) / 2;

        if (arr[mid] == key)
        {
            return mid;
        }
        else if (arr[mid] < key)
        {
            low = mid + 1;
        }
        else
        {
            high = mid - 1;
        }
    }

    return -1;
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50, 60, 70};
    int n = sizeof(arr) / sizeof(arr[0]);
    int key = 50;

    int result = binary_search(arr, n, key);

    if (result != -1)
    {
        printf("Found at index %d\n", result);
    }
    else
    {
        printf("Not found\n");
    }

    return 0;
}
Found at index 4

Worst-case Time Complexity: O(log n)

Auxiliary Space: O(1)

Binary search is more efficient than linear search for large sorted arrays. It cannot be directly applied to an unsorted array.

11. Comparing Time Complexity Growth

Consider how the number of operations grows for different input sizes.

n O(1) O(log₂ n) O(n) O(n log₂ n) O(n²)
10 1 ≈ 3.32 10 ≈ 33.2 100
100 1 ≈ 6.64 100 ≈ 664 10,000
1,000 1 ≈ 9.97 1,000 ≈ 9,966 1,000,000

These values illustrate mathematical growth functions, not exact execution times or guaranteed operation counts for every algorithm.

12. Important Rules for Complexity Analysis

  1. Ignore constant factors when expressing Big O.
  2. Keep the fastest-growing term for polynomial expressions.
  3. Sequential loops generally add their operation counts.
  4. Nested loops generally multiply their iteration counts when bounds are independent.
  5. Halving or doubling a loop variable often produces logarithmic complexity.
  6. Identify recursive call depth when calculating auxiliary space.
  7. Consider all relevant input dimensions.

Examples

Operation Count Simplified Complexity
5n + 10 O(n)
3n² + 4n + 2 O(n²)
n log n + n O(n log n)
n³ + 100n² O(n³)

13. Common Mistakes to Avoid

  • Confusing actual execution time with time complexity.
  • Assuming every nested loop automatically means O(n²).
  • Ignoring different loop bounds.
  • Forgetting recursive call stack memory.
  • Confusing total space with auxiliary space.
  • Assuming binary search works on unsorted arrays.
  • Ignoring input constraints and possible integer overflow.
  • Ignoring multiple input dimensions such as rows and columns.

14. Placement Interview Questions and Answers

Q1. What is time complexity?

Time complexity describes how the number of operations performed by an algorithm grows with input size.

Q2. What is space complexity?

Space complexity describes how the memory requirements of an algorithm grow with input size.

Q3. What is the difference between time and space complexity?

Time complexity measures operation-count growth, whereas space complexity measures memory-usage growth.

Q4. What is O(1) complexity?

It represents constant growth: the operation count does not increase with input size.

Q5. What is O(n) complexity?

It represents linear growth. The operation count grows proportionally to the input size.

Q6. What is O(log n) complexity?

It represents logarithmic growth. It commonly occurs when the problem size is repeatedly divided by a constant factor.

Q7. What is the time complexity of binary search?

O(log n) in the worst case for a sorted array.

Q8. What is the time complexity of linear search?

O(n) in the worst case because every element may need to be examined.

Q9. What is auxiliary space?

Auxiliary space is the additional memory used by an algorithm, excluding its input storage.

Q10. What is the complexity of two nested loops?

If both loops independently execute n times, the total number of iterations is n² and complexity is O(n²).

Q11. Why is recursive factorial O(n) in space?

It creates approximately n active function calls in the call stack before reaching the base case.

Q12. What is the time complexity of merge sort?

O(n log n) in best, average and worst cases for standard merge sort implementations.

Q13. Does O(1) always mean one operation?

No. It means a constant number of operations with respect to input size. The constant may be greater than one.

Q14. Why do we ignore constant factors in Big O?

Big O describes asymptotic growth. Constant factors do not change the growth class as input size becomes large.

Q15. Can an algorithm have O(n) time and O(1) auxiliary space?

Yes. For example, finding the maximum element in an array requires one traversal and only a fixed number of additional variables.
