Lesson 3: Algorithms and Pseudocode

Learn how to design step-by-step solutions, write pseudocode, understand flowcharts and convert problem-solving logic into C programs.

1. What is an Algorithm?

An algorithm is a finite sequence of well-defined instructions used to solve a particular problem or perform a computational task.

Before writing a program, a programmer should understand the problem and design a logical sequence of operations.

Example: Adding Two Numbers

  1. Start.
  2. Read two numbers A and B.
  3. Calculate SUM = A + B.
  4. Display SUM.
  5. Stop.
Placement Tip: In coding interviews, first explain your approach clearly. Then write the code and analyze its time and auxiliary space complexity.

2. Characteristics of a Good Algorithm

  1. Input: Accepts zero or more input values.
  2. Output: Produces at least one meaningful result.
  3. Definiteness: Every instruction must be clear and unambiguous.
  4. Finiteness: Must terminate after a finite number of steps.
  5. Effectiveness: Each operation must be sufficiently basic and executable.
  6. Correctness: Produces the expected result for all valid inputs within the problem specification.

3. What is Pseudocode?

Pseudocode is an informal, language-independent way of representing an algorithm using simple statements that resemble programming logic.

It helps programmers understand the solution before implementing it in a programming language.

Common Pseudocode Keywords

Keyword Purpose
START Begins the algorithm.
INPUT / READ Accepts input values.
OUTPUT / PRINT Displays a result.
IF / ELSE Performs conditional decisions.
FOR Repeats instructions a known number of times.
WHILE Repeats instructions while a condition is true.
RETURN Returns a result from a procedure or function.
STOP Ends the algorithm.

Example: Pseudocode to Find the Larger Number

START

    READ A, B

    IF A > B THEN
        PRINT A
    ELSE IF B > A THEN
        PRINT B
    ELSE
        PRINT "Both numbers are equal"
    END IF

STOP
Pseudocode does not have one compulsory syntax. The goal is to express the logic clearly and consistently.

4. What is a Flowchart?

A flowchart is a graphical representation of an algorithm. It uses standard symbols connected by arrows to show the sequence of operations.

Common Flowchart Symbols

Symbol Name Purpose
Oval Terminal Start or end of a process.
Rectangle Process Calculation or instruction.
Parallelogram Input / Output Read or display information.
Diamond Decision Conditional branching.
Arrow Flow Line Shows execution direction.
Circle Connector Connects different flowchart sections.

Example: Flowchart Logic for Even or Odd

  1. Start.
  2. Read an integer N.
  3. Check whether N % 2 == 0.
  4. If true, display Even.
  5. Otherwise, display Odd.
  6. Stop.
The diamond represents the condition N % 2 == 0. The two outgoing paths represent the true and false outcomes.

5. Algorithm vs Pseudocode vs Flowchart vs Program

Term Meaning Representation
Algorithm Step-by-step problem-solving method. Logical instructions.
Pseudocode Informal description of algorithm logic. Structured statements.
Flowchart Graphical representation of logic. Symbols and arrows.
Program Executable implementation of the solution. C source code, for example.

6. Basic Control Structures in Algorithms

6.1 Sequence

Instructions execute one after another in the specified order. 

START
    READ A
    READ B
    SUM = A + B
    PRINT SUM
STOP

6.2 Selection

Selection allows an algorithm to choose a path based on a condition. 

START
    READ N

    IF N > 0 THEN
        PRINT "Positive"
    ELSE
        PRINT "Zero or Negative"
    END IF

STOP

6.3 Iteration

Iteration repeats a set of instructions using loops such as FOR and WHILE. 

START

    FOR I = 1 TO 5
        PRINT I
    END FOR

STOP

7. Convert an Algorithm into a C Program

Problem: Find the Sum of N Natural Numbers

Given a positive integer N, calculate the sum of all integers from 1 to N.

Algorithm

  1. Start.
  2. Read N.
  3. Initialize SUM = 0.
  4. Repeat I from 1 to N.
  5. Add I to SUM.
  6. Display SUM.
  7. Stop.

Pseudocode

START

    READ N
    SUM = 0

    FOR I = 1 TO N
        SUM = SUM + I
    END FOR

    PRINT SUM

STOP

C Program

#include <stdio.h>

int main(void)
{
    int n;
    long long sum = 0;

    printf("Enter a positive integer: ");

    if (scanf("%d", &n) != 1 || n < 1)
    {
        printf("Invalid input\n");
        return 1;
    }

    for (int i = 1; i <= n; i++)
    {
        sum += i;
    }

    printf("Sum = %lld\n", sum);

    return 0;
}

Expected Output

Enter a positive integer: 5
Sum = 15

Dry Run

Iteration I SUM Before SUM After
1 1 0 1
2 2 1 3
3 3 3 6
4 4 6 10
5 5 10 15

Complexity Analysis

  • Time Complexity: O(n), because the loop executes n times.
  • Auxiliary Space Complexity: O(1), because only a fixed number of variables are used.

8. Algorithm Correctness

An algorithm is correct when it produces the expected output for every valid input within the problem specification.

Important Concepts

  • Precondition: A condition that must hold before execution.
  • Postcondition: A condition that should hold after successful execution.
  • Loop Invariant: A property that remains true before and after every loop iteration.
  • Termination: The algorithm must eventually finish.

Example: Loop Invariant for the Sum Program

After completing iteration I, the variable SUM contains the sum of all integers from 1 to I.

This property holds initially for I = 0, remains true after each addition and gives the required result when the loop terminates at N.

9. Common Algorithm Design Techniques

Technique Approach Example
Brute Force Try all possible candidates. Linear Search
Divide and Conquer Divide a problem into smaller subproblems. Merge Sort
Greedy Choose a locally optimal option at each step. Activity Selection
Dynamic Programming Reuse solutions to overlapping subproblems. Fibonacci with Memoization
Backtracking Explore choices and undo invalid paths. N-Queens

These techniques will be studied in greater detail in later chapters.

10. Common Mistakes in Algorithm Design

  • Ignoring invalid or boundary inputs.
  • Writing ambiguous pseudocode.
  • Using incorrect loop termination conditions.
  • Forgetting to initialize variables.
  • Not checking whether an algorithm terminates.
  • Ignoring integer overflow in calculations.
  • Assuming a solution works without testing it.
Important C Programming Note: Choose an integer type that can hold the maximum possible result. Even when using long long, check problem constraints to ensure overflow cannot occur.

11. Placement Interview Questions and Answers

Q1. What is an algorithm?

An algorithm is a finite sequence of well-defined steps used to solve a computational problem.

Q2. What is pseudocode?

Pseudocode is a language-independent description of an algorithm written using structured, human-readable statements.

Q3. What is a flowchart?

A flowchart graphically represents the steps and decisions of an algorithm using standard symbols and connecting arrows.

Q4. What are the three basic control structures?

Sequence, selection and iteration.

Q5. What is the difference between an algorithm and a program?

An algorithm describes the logical steps to solve a problem. A program implements those steps in a programming language.

Q6. Is pseudocode executable?

No. Pseudocode is a planning and communication tool, not a formal programming language.

Q7. What is a loop invariant?

It is a property that remains true at the beginning and end of every loop iteration. It helps reason about algorithm correctness.

Q8. What is brute-force problem solving?

It is a straightforward approach that examines possible candidates until a solution is found or all candidates have been checked.

Q9. Why should we perform a dry run?

A dry run manually traces an algorithm with sample input to verify variable updates, execution order and expected output.

Q10. What is algorithm correctness?

It means that an algorithm produces the specified correct output for all valid inputs and terminates as required.

Q11. What is the difference between syntax and logic errors?

Syntax errors violate programming language rules. Logic errors allow a program to execute but produce an incorrect result.

Q12. What is divide and conquer?

It is a design technique that divides a problem into smaller subproblems, solves them and combines their results.
