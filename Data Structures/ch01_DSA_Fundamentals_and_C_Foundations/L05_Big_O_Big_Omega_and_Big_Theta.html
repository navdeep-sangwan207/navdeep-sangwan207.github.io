Lesson 5: Big O, Big Omega and Big Theta

Understand asymptotic notations, upper bounds, lower bounds and tight bounds. Learn how to mathematically express algorithm growth for technical interviews and coding assessments.

1. What is Asymptotic Analysis?

Asymptotic analysis is a mathematical technique used to describe how an algorithm's resource requirements grow as the input size approaches infinity.

It focuses on the growth rate rather than the exact execution time or the performance of a particular computer.

Why Do We Need Asymptotic Notation?

  • To compare different algorithms.
  • To understand performance for large inputs.
  • To ignore machine-dependent execution times.
  • To express algorithm efficiency mathematically.
  • To estimate scalability before implementation.
Placement Definition: Asymptotic notation describes the growth rate of an algorithm's time or space requirements as its input size becomes large.

2. Three Major Asymptotic Notations

Notation Meaning Mathematical Interpretation
Big O Asymptotic upper bound Growth does not exceed a constant multiple of the bound eventually.
Big Omega (Ω) Asymptotic lower bound Growth is at least a constant multiple of the bound eventually.
Big Theta (Θ) Asymptotically tight bound Growth is bounded above and below by constant multiples.
Big O does not automatically mean worst-case, and Big Omega does not automatically mean best-case. They describe mathematical bounds. Best, average and worst cases describe input-dependent analysis.

3. Big O Notation – Upper Bound

Big O notation represents an asymptotic upper bound on a function's growth.

If an algorithm performs f(n) operations, we say f(n) = O(g(n)) when there are positive constants c and n₀ such that:

Mathematical Definition:

0 ≤ f(n) ≤ c × g(n), for all n ≥ n₀.

Here:

  • f(n): Function representing the operation count.
  • g(n): Candidate upper-bound function.
  • c: Positive constant multiplier.
  • n₀: Starting input size from which the bound holds.

Example 1

Consider the function:

f(n) = 3n + 5

We can establish that f(n) = O(n).

For n ≥ 1:

3n + 5 ≤ 8n

Therefore, choose c = 8 and n₀ = 1.

Result: 3n + 5 = O(n)

Example 2

f(n) = 4n² + 3n + 10

The dominant term is n². For n ≥ 1:

4n² + 3n + 10 ≤ 17n²

Therefore:

Result: f(n) = O(n²)

C Program Example: Linear Search

#include <stdio.h>

int linear_search(const int arr[], int n, int key)
{
    for (int i = 0; i < n; i++)
    {
        if (arr[i] == key)
        {
            return i;
        }
    }

    return -1;
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    int n = sizeof(arr) / sizeof(arr[0]);

    int result = linear_search(arr, n, 40);

    printf("Index = %d\n", result);

    return 0;
}
Index = 3

In the worst case, every element may be checked.

  • Worst-case Time Complexity: O(n)
  • Best-case Time Complexity: O(1)
  • Auxiliary Space: O(1)

4. Big Omega (Ω) – Lower Bound

Big Omega notation represents an asymptotic lower bound on a function's growth.

Mathematical Definition:

0 ≤ c × g(n) ≤ f(n), for all n ≥ n₀.

This means that f(n) grows at least as fast as a constant multiple of g(n), for sufficiently large n.

Example

Consider:

f(n) = 5n² + 2n + 7

For n ≥ 1:

5n² ≤ 5n² + 2n + 7

Choose c = 5 and n₀ = 1.

Result: f(n) = Ω(n²)

C Program Example: Finding Maximum Element

#include <stdio.h>

int find_maximum(const int arr[], int n)
{
    int max = arr[0];

    for (int i = 1; i < n; i++)
    {
        if (arr[i] > max)
        {
            max = arr[i];
        }
    }

    return max;
}

int main(void)
{
    int arr[] = {12, 45, 23, 67, 34};
    int n = sizeof(arr) / sizeof(arr[0]);

    printf("Maximum = %d\n", find_maximum(arr, n));

    return 0;
}
Maximum = 67

Every element must be examined to guarantee finding the maximum in an unsorted array.

  • Time Complexity: Θ(n)
  • Lower Bound: Ω(n)
  • Auxiliary Space: O(1)
The Omega bound of an algorithm is not necessarily its best-case time. For example, linear search has a best-case execution time of Θ(1), even though its worst-case execution requires Ω(n) operations.

5. Big Theta (Θ) – Tight Bound

Big Theta notation represents an asymptotically tight bound. It means the function is bounded both above and below by constant multiples of the same growth function.

Mathematical Definition:

0 ≤ c₁ × g(n) ≤ f(n) ≤ c₂ × g(n), for all n ≥ n₀.

Here:

  • c₁ and c₂ are positive constants.
  • n₀ is a positive starting input size.
  • g(n) represents the tight asymptotic growth rate.

Example

f(n) = 4n + 8

For n ≥ 1:

4n ≤ 4n + 8 ≤ 12n

Therefore, choose c₁ = 4, c₂ = 12 and n₀ = 1.

Result: f(n) = Θ(n)

C Program Example: Array Traversal

#include <stdio.h>

void display_array(const int arr[], int n)
{
    for (int i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    int n = sizeof(arr) / sizeof(arr[0]);

    display_array(arr, n);

    return 0;
}
10 20 30 40 50

Every array element is processed exactly once.

  • Time Complexity: Θ(n)
  • Auxiliary Space: O(1)

6. Difference Between O, Ω and Θ

Feature Big O Big Omega Big Theta
Symbol O Ω Θ
Bound Upper Lower Tight
Meaning At most this growth rate asymptotically At least this growth rate asymptotically Same asymptotic growth rate above and below
Typical use Expressing an upper bound Expressing a lower bound Expressing a tight bound

Simple Memory Trick

  • O: Upper bound.
  • Ω: Lower bound.
  • Θ: Both upper and lower bounds.

7. Mathematical Comparison Examples

Function Big O Big Omega Big Theta
5n + 10 O(n) Ω(n) Θ(n)
3n² + 2n + 1 O(n²) Ω(n²) Θ(n²)
2n³ + 5n² + 7 O(n³) Ω(n³) Θ(n³)
7 log n + 4 O(log n) Ω(log n) Θ(log n)
When a function is a polynomial with a positive leading coefficient, its highest-degree term determines its asymptotic tight bound.

8. Relationship Between Asymptotic Bounds and Cases

Three different concepts are often discussed together during interviews:

  • Best case: Minimum operations for inputs of a given size.
  • Average case: Expected operations under a specified input distribution.
  • Worst case: Maximum operations for inputs of a given size.

Big O, Ω and Θ describe bounds on the functions produced by these analyses.

Linear Search Example

Consider searching for a key in an array containing n elements.

Case Situation Complexity
Best Key is the first element. Θ(1)
Average Key position is uniformly distributed and key is present. Θ(n)
Worst Key is last or absent. Θ(n)
Do not memorize "Big O = worst case" and "Big Omega = best case" as universal rules. They are not equivalent definitions.

9. Important Asymptotic Growth Order

The following is the usual increasing order of growth for common complexity functions: 

O(1)
   <
O(log n)
   <
O(n)
   <
O(n log n)
   <
O(n²)
   <
O(n³)
   <
O(2^n)
   <
O(n!)

A function appearing later in this sequence generally grows faster for sufficiently large n.

In placement coding rounds, recognize whether an O(n²) solution can be improved to O(n log n) or O(n) using sorting, hashing, binary search or other suitable techniques.

10. Important Rules for Simplifying Complexity

Rule 1: Ignore Constant Multipliers

5n = Θ(n)

Rule 2: Ignore Lower-Order Terms

n² + 10n + 50 = Θ(n²)

Rule 3: Combine Sequential Operations

O(n) + O(n²) = O(n²)

Rule 4: Multiply Independent Nested Loops

O(n) × O(n) = O(n²)

Rule 5: Consider the Actual Loop Bounds

for (int i = 1; i < n; i *= 2)
{
    for (int j = 0; j < n; j++)
    {
        /* Constant-time work */
    }
}

The outer loop executes O(log n) times. The inner loop executes O(n) times.

Overall Complexity: O(n log n)

11. Placement Interview Questions and Answers

Q1. What is asymptotic analysis?

It is a mathematical method for analyzing algorithm growth as input size becomes large.

Q2. What does Big O represent?

Big O represents an asymptotic upper bound on a function's growth.

Q3. What does Big Omega represent?

Big Omega represents an asymptotic lower bound on a function's growth.

Q4. What does Big Theta represent?

Big Theta represents an asymptotically tight bound, providing both upper and lower bounds.

Q5. What is the difference between Big O and Big Theta?

Big O provides an upper bound, whereas Big Theta provides a tight bound using both upper and lower bounds.

Q6. Is Big O always worst-case complexity?

No. Big O is an upper-bound notation. It can describe the upper bound of best-case, average-case or worst-case functions.

Q7. Is Big Omega always best-case complexity?

No. Big Omega is a lower-bound notation. It does not automatically mean best case.

Q8. What is the Big Theta of 4n + 7?

Θ(n), because the linear term dominates for large n.

Q9. What is the Big O of 3n² + 5n + 10?

O(n²), because the quadratic term dominates.

Q10. Can a function belong to more than one Big O class?

Yes. For example, n is O(n), O(n²) and O(n³). However, Θ(n) is its tight asymptotic bound.

Q11. What is a tight asymptotic bound?

It is a bound that describes the function's growth rate from both above and below, up to constant factors.

Q12. Why do we ignore constant factors?

Because constant multipliers do not change the asymptotic growth class as input size becomes sufficiently large.

Q13. What is the complexity of n log n?

Θ(n log n) when the function itself is proportional to n log n.

Q14. What is the difference between worst case and Big O?

Worst case describes the maximum operation count across inputs of a given size. Big O describes an asymptotic upper bound on the function being analyzed.

Q15. Which notation is best for expressing a tight bound?

Big Theta (Θ).
