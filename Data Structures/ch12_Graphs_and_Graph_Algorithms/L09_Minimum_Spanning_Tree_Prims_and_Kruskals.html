Lesson 9: Minimum Spanning Tree – Prim's and Kruskal's Algorithms

Learn how to connect all vertices of a weighted graph with minimum total edge cost using Prim's and Kruskal's algorithms.

1. Learning Objectives

  • Understand spanning trees and minimum spanning trees.
  • Understand the properties of an MST.
  • Implement Prim's algorithm using C11.
  • Implement Kruskal's algorithm using C11.
  • Understand greedy edge selection.
  • Use sorting and DSU for cycle prevention.

2. What Is a Spanning Tree?

A spanning tree of a connected, undirected graph is a subgraph that:

  • Contains all vertices of the original graph.
  • Is connected.
  • Contains no cycle.
  • Has exactly V - 1 edges.

Example Graph

       1
  0 ------- 1
  | \       |
  |  \      |
  4   3     2
  |    \    |
  |     \   |
  2 ------- 3
       5

A spanning tree connects every vertex without creating a cycle. A graph can have multiple spanning trees.

A connected graph with V vertices has a spanning tree containing exactly V - 1 edges.

3. What Is a Minimum Spanning Tree?

A Minimum Spanning Tree (MST) is a spanning tree whose total edge weight is minimum among all possible spanning trees of a connected, weighted, undirected graph.

Example

Edges:

0 --1-- 1
0 --4-- 2
1 --2-- 2
1 --5-- 3
2 --3-- 3

One possible MST selects these edges: 

0 --1-- 1
1 --2-- 2
2 --3-- 3

Total weight:

1 + 2 + 3 = 6
An MST minimizes the total weight needed to connect all vertices. It does not necessarily minimize the shortest distance between every pair of vertices.

4. Properties of Minimum Spanning Trees

  1. An MST contains all vertices.
  2. An MST contains exactly V - 1 edges.
  3. An MST has no cycle.
  4. An MST is connected when the original graph is connected.
  5. There can be more than one MST if multiple edge combinations have the same minimum cost.
  6. Negative edge weights are allowed in MST algorithms.

Important Difference: MST vs Shortest Path Tree

Minimum Spanning Tree Shortest Path Tree
Minimizes total selected edge weight. Minimizes distance from a selected source.
Does not require a source vertex. Requires a source vertex.
Prim's and Kruskal's algorithms. Dijkstra and Bellman-Ford are common algorithms.

5. Prim's Algorithm

Prim's algorithm is a greedy algorithm that constructs an MST by growing a single tree, one vertex at a time.

Core Idea

Start from any vertex. Repeatedly select the minimum weight edge connecting a vertex already in the MST to a vertex outside the MST.

Algorithm Steps

  1. Select a starting vertex.
  2. Mark it as included in the MST.
  3. Find the minimum-weight edge connecting the current MST to an unvisited vertex.
  4. Add that edge and vertex to the MST.
  5. Repeat until all vertices are included.

Pseudocode

key[start] = 0

for every other vertex:
    key[vertex] = INFINITY

parent[vertex] = -1
inMST[vertex] = false

repeat V times:

    u = vertex not in MST with minimum key

    if u does not exist:
        stop

    inMST[u] = true

    for each adjacent vertex v:

        if v is not in MST and weight[u][v] < key[v]:

            key[v] = weight[u][v]
            parent[v] = u

7. Complete C11 Program: Prim's Algorithm

This implementation uses an adjacency matrix and selects the minimum key vertex through a linear scan. It supports negative edge weights and uses -1 to represent the absence of an edge. 

#include <stdio.h>
#include <limits.h>

#define V 4
#define INF LLONG_MAX

int minKey(long long key[V], int inMST[V])
{
    long long minimum = INF;
    int minIndex = -1;
    int i;

    for (i = 0; i < V; i++)
    {
        if (!inMST[i] && key[i] < minimum)
        {
            minimum = key[i];
            minIndex = i;
        }
    }

    return minIndex;
}

int primMST(int graph[V][V], int start)
{
    long long key[V];
    int parent[V];
    int inMST[V] = {0};
    int i, count, u, v;
    long long totalCost = 0;

    for (i = 0; i < V; i++)
    {
        key[i] = INF;
        parent[i] = -1;
    }

    key[start] = 0;

    for (count = 0; count < V; count++)
    {
        u = minKey(key, inMST);

        if (u == -1)
        {
            break;
        }

        inMST[u] = 1;

        for (v = 0; v < V; v++)
        {
            if (graph[u][v] != -1 &&
                !inMST[v] &&
                graph[u][v] < key[v])
            {
                key[v] = graph[u][v];
                parent[v] = u;
            }
        }
    }

    for (i = 0; i < V; i++)
    {
        if (!inMST[i])
        {
            printf("Graph is disconnected. No spanning tree exists.\n");
            return 0;
        }
    }

    printf("Edges in Minimum Spanning Tree:\n");

    for (i = 0; i < V; i++)
    {
        if (i != start)
        {
            printf("%d - %d : %lld\n", parent[i], i, key[i]);
            totalCost += key[i];
        }
    }

    printf("Total MST Cost = %lld\n", totalCost);

    return 1;
}

int main(void)
{
    int graph[V][V] =
    {
        {-1, 2, 6, 3},
        { 2,-1,-1, 5},
        { 6,-1,-1, 4},
        { 3, 5, 4,-1}
    };

    primMST(graph, 0);

    return 0;
}

Expected Output

Edges in Minimum Spanning Tree:
0 - 1 : 2
3 - 2 : 4
0 - 3 : 3
Total MST Cost = 9
The order in which edges are printed depends on the vertex iteration order. The selected MST and its total cost are what matter.

8. Prim's Algorithm Complexity

Implementation Time Complexity
Adjacency matrix + linear selection O(V²)
Adjacency list + binary min-heap O(E log V)
Adjacency list + Fibonacci heap (theoretical) O(E + V log V)

The adjacency matrix version is straightforward and useful for dense graphs. The heap-based version is generally preferred for sparse graphs.

9. Kruskal's Algorithm

Kruskal's algorithm is a greedy MST algorithm that sorts all edges by weight and selects the smallest edges while avoiding cycles.

Core Idea

Select edges in increasing order of weight, but do not select an edge if it creates a cycle.

Algorithm Steps

  1. Store all graph edges in an edge list.
  2. Sort edges in ascending order of weight.
  3. Initialize every vertex as a separate component.
  4. Examine edges from smallest to largest.
  5. If an edge connects two different components, select it.
  6. Merge those components using DSU.
  7. Stop after selecting V - 1 edges.

Pseudocode

sort all edges by increasing weight

initialize DSU

mstCost = 0
edgeCount = 0

for each edge (u, v, weight):

    if find(u) != find(v):

        select edge

        union(u, v)

        mstCost += weight

        edgeCount++

        if edgeCount == V - 1:
            break

11. Why Does Kruskal Need DSU?

Kruskal must determine whether adding an edge would create a cycle.

Disjoint Set Union (DSU), also called Union-Find, efficiently manages connected components.

Two Important Operations

Find(x)

Returns the representative or root of the component containing vertex x.

Union(a, b)

Merges the components containing a and b.

Cycle Check

if (find(u) == find(v))

    Adding edge u-v creates a cycle.

else

    Edge can be selected.
    union(u, v);
If two vertices already belong to the same DSU component, a path already connects them. Adding another edge between them creates a cycle.

12. Complete C11 Program: Kruskal's Algorithm

This implementation uses:

  • Edge list representation.
  • qsort() for sorting edges.
  • Path compression in Find.
  • Union by rank.
#include <stdio.h>
#include <stdlib.h>

#define V 4
#define E 5

typedef struct
{
    int src;
    int dest;
    int weight;
} Edge;

int parent[V];
int rankSet[V];

int compareEdges(const void *a, const void *b)
{
    const Edge *e1 = (const Edge *)a;
    const Edge *e2 = (const Edge *)b;

    if (e1->weight < e2->weight)
        return -1;

    if (e1->weight > e2->weight)
        return 1;

    return 0;
}

void makeSet(void)
{
    int i;

    for (i = 0; i < V; i++)
    {
        parent[i] = i;
        rankSet[i] = 0;
    }
}

int findSet(int x)
{
    if (parent[x] != x)
    {
        parent[x] = findSet(parent[x]);
    }

    return parent[x];
}

void unionSet(int a, int b)
{
    int rootA = findSet(a);
    int rootB = findSet(b);

    if (rootA == rootB)
    {
        return;
    }

    if (rankSet[rootA] < rankSet[rootB])
    {
        parent[rootA] = rootB;
    }
    else if (rankSet[rootA] > rankSet[rootB])
    {
        parent[rootB] = rootA;
    }
    else
    {
        parent[rootB] = rootA;
        rankSet[rootA]++;
    }
}

int kruskal(Edge edges[E])
{
    int i;
    int edgeCount = 0;
    long long totalCost = 0;

    qsort(edges, E, sizeof(Edge), compareEdges);

    makeSet();

    printf("Edges in Minimum Spanning Tree:\n");

    for (i = 0; i < E && edgeCount < V - 1; i++)
    {
        int u = edges[i].src;
        int v = edges[i].dest;

        if (findSet(u) != findSet(v))
        {
            printf("%d - %d : %d\n",
                   u, v, edges[i].weight);

            totalCost += edges[i].weight;

            unionSet(u, v);

            edgeCount++;
        }
    }

    if (edgeCount != V - 1)
    {
        printf("Graph is disconnected. No spanning tree exists.\n");
        return 0;
    }

    printf("Total MST Cost = %lld\n", totalCost);

    return 1;
}

int main(void)
{
    Edge edges[E] =
    {
        {0, 1, 2},
        {0, 2, 6},
        {0, 3, 3},
        {1, 3, 5},
        {2, 3, 4}
    };

    kruskal(edges);

    return 0;
}

Expected Output

0 - 1 : 2
0 - 3 : 3
2 - 3 : 4
Total MST Cost = 9

13. Kruskal's Algorithm Complexity

Operation Complexity
Sort E edges O(E log E)
DSU Find with path compression and union by rank Amortized O(α(V))
Process all edges O(E α(V))
Overall O(E log E)

Here α(V) is the inverse Ackermann function, which grows extremely slowly and is effectively constant for practical input sizes.

14. Prim's vs Kruskal's Algorithm

Feature Prim's Kruskal's
Strategy Grows one tree Selects edges in sorted order
Selection Minimum edge connecting tree to outside vertex Minimum remaining edge that does not form a cycle
Common data structure Priority queue / min-heap DSU / Union-Find
Graph representation Often adjacency list or matrix Usually edge list
Typical complexity O(E log V) with binary heap and adjacency list O(E log E)
Disconnected graph Can be adapted to produce a minimum spanning forest Naturally produces a minimum spanning forest
Both algorithms are greedy and produce a minimum spanning tree when the input graph is connected, undirected and weighted.

15. Important MST Concepts

Minimum Spanning Forest

If a graph is disconnected, a spanning tree covering all vertices does not exist. Instead, an MST for each connected component forms a minimum spanning forest.

Unique MST

If all edge weights are distinct, the MST is unique. If weights are repeated, multiple MSTs may exist.

Negative Edge Weights

Prim's and Kruskal's algorithms can work with negative edge weights. Unlike Dijkstra, MST algorithms do not require all edge weights to be non-negative.

Cut Property

For a cut of a weighted graph, a minimum-weight edge crossing that cut is safe to include in some MST. This property helps justify the greedy choices made by Prim's and Kruskal's algorithms.

Cycle Property

If an edge is the unique maximum-weight edge in a cycle, it cannot belong to an MST.

16. Real-World Applications

  • Designing low-cost computer networks.
  • Connecting cities through roads or railway lines.
  • Electrical power distribution network planning.
  • Telecommunication cable layout.
  • Water pipeline network design.
  • Clustering and network optimization.
Example: If several cities must be connected with minimum total cable length, an MST can help determine which connections to build.

17. Common Interview Mistakes

  1. Confusing MST with shortest path tree.
  2. Forgetting that an MST has exactly V - 1 edges.
  3. Adding an edge that creates a cycle in Kruskal.
  4. Forgetting to sort edges before Kruskal.
  5. Using DSU without path compression or union by rank/size in performance-sensitive implementations.
  6. Assuming MST algorithms cannot handle negative weights.
  7. Failing to check whether the graph is disconnected.
  8. Assuming every graph has a unique MST.
  9. Confusing Prim's key value with Dijkstra's shortest distance.

18. Placement Interview Questions

Q1. What is a spanning tree?

A connected, acyclic subgraph containing all vertices of a connected graph.

Q2. How many edges are present in a spanning tree?

V - 1 edges.

Q3. What is an MST?

A spanning tree having the minimum possible total edge weight.

Q4. Which strategy is used by Prim's algorithm?

Greedy vertex-based tree expansion.

Q5. Which strategy is used by Kruskal's algorithm?

Greedy edge selection in increasing order of weight.

Q6. Why does Kruskal use DSU?

To identify whether two endpoints already belong to the same connected component and prevent cycles.

Q7. Can an MST contain negative-weight edges?

Yes.

Q8. What happens if the graph is disconnected?

A spanning tree does not exist; a minimum spanning forest can be constructed.

Q9. What is the time complexity of Kruskal's algorithm?

O(E log E).

Q10. What is Prim's complexity using an adjacency matrix?

O(V²).

Q11. Can a graph have multiple MSTs?

Yes, when different edge selections have the same minimum total weight.

Q12. Is an MST always a shortest path tree?

No. An MST minimizes the total selected edge weight, whereas a shortest path tree minimizes distances from a particular source.
