2. Binary Tree Representation

A binary tree can be represented in memory using two commonly used methods:

  1. Linked representation.
  2. Array representation.
Linked representation is commonly used for general binary trees because nodes can be created dynamically and do not require a fixed-size array.

3. Linked Representation of a Binary Tree

In linked representation, every node contains three fields:

  • Data field – stores the value.
  • Left pointer – points to the left child.
  • Right pointer – points to the right child.

Node Structure in C

struct Node {
    int data;
    struct Node *left;
    struct Node *right;
};

The left and right pointers store addresses of child nodes. If a child does not exist, its pointer is set to NULL.

Example Binary Tree

                 10
                /  \
               20   30
              / \
             40  50

Conceptual Node Representation

Node 10:
+------+----------+----------+
| data | left     | right    |
+------+----------+----------+
|  10  | address20| address30|
+------+----------+----------+

Node 20:
+------+----------+----------+
| data | left     | right    |
+------+----------+----------+
|  20  | address40| address50|
+------+----------+----------+

Node 30:
+------+----------+----------+
| data | left     | right    |
+------+----------+----------+
|  30  | NULL     | NULL     |
+------+----------+----------+

The root pointer stores the address of the first node. Every other node is reached by following left and right pointers.

4. Creating a Binary Tree Node in C

Dynamic memory allocation allows us to create nodes at runtime using malloc().

Node Creation Function

struct Node *createNode(int value) {
    struct Node *newNode = malloc(sizeof *newNode);

    if (newNode == NULL) {
        return NULL;
    }

    newNode->data = value;
    newNode->left = NULL;
    newNode->right = NULL;

    return newNode;
}

Explanation

  1. malloc() allocates memory for one node.
  2. The returned address is stored in newNode.
  3. Memory allocation failure is checked.
  4. The data field is initialized.
  5. Both child pointers are initialized to NULL.
  6. The address of the new node is returned.
Always check whether malloc() returned NULL before accessing the allocated memory. Otherwise, the program may dereference an invalid pointer.

5. Manually Constructing a Binary Tree

We can create individual nodes and connect them using their left and right pointers.

Complete C11 Program

#include <stdio.h>
#include <stdlib.h>

struct Node {
    int data;
    struct Node *left;
    struct Node *right;
};

struct Node *createNode(int value) {
    struct Node *newNode = malloc(sizeof *newNode);

    if (newNode == NULL) {
        return NULL;
    }

    newNode->data = value;
    newNode->left = NULL;
    newNode->right = NULL;

    return newNode;
}

void preorder(const struct Node *root) {
    if (root == NULL) {
        return;
    }

    printf("%d ", root->data);
    preorder(root->left);
    preorder(root->right);
}

void freeTree(struct Node *root) {
    if (root == NULL) {
        return;
    }

    freeTree(root->left);
    freeTree(root->right);
    free(root);
}

int main(void) {
    struct Node *root = createNode(10);

    if (root == NULL) {
        printf("Memory allocation failed.\n");
        return 1;
    }

    root->left = createNode(20);

    if (root->left == NULL) {
        freeTree(root);
        printf("Memory allocation failed.\n");
        return 1;
    }

    root->right = createNode(30);

    if (root->right == NULL) {
        freeTree(root);
        printf("Memory allocation failed.\n");
        return 1;
    }

    root->left->left = createNode(40);

    if (root->left->left == NULL) {
        freeTree(root);
        printf("Memory allocation failed.\n");
        return 1;
    }

    root->left->right = createNode(50);

    if (root->left->right == NULL) {
        freeTree(root);
        printf("Memory allocation failed.\n");
        return 1;
    }

    printf("Preorder traversal: ");
    preorder(root);

    printf("\n");

    freeTree(root);

    return 0;
}

Tree Structure

                 10
                /  \
               20   30
              / \
             40  50

Expected Output

Preorder traversal: 10 20 40 50 30

Understanding the Connections

Statement Meaning
root = createNode(10) Creates the root node.
root->left = createNode(20) Creates the left child of 10.
root->right = createNode(30) Creates the right child of 10.
root->left->left = createNode(40) Creates the left child of 20.
root->left->right = createNode(50) Creates the right child of 20.

6. Array Representation of a Binary Tree

A binary tree can also be stored in an array. This approach is particularly useful for complete binary trees and heaps.

Example Binary Tree

                  10
                 /  \
                20   30
               / \   /
              40  50 60

Array Representation (0-Based Indexing)

Index:  0   1   2   3   4   5
Value: 10  20  30  40  50  60

When the array uses zero-based indexing, the relationships are calculated using the following formulas.

For a node at index i:
  • Left child = 2i + 1
  • Right child = 2i + 2
  • Parent = floor((i - 1) / 2), for i greater than 0

Example: Find the Children of Index 1

Given i = 1:

  • Left child = 2(1) + 1 = 3.
  • Right child = 2(1) + 2 = 4.

Therefore:

  • Index 3 contains 40.
  • Index 4 contains 50.

Example: Find the Parent of Index 5

Parent index = floor((5 - 1) / 2) = 2.

Therefore, the parent of node 60 is node 30.

7. Array Representation Using 1-Based Indexing

Some textbooks and implementations use an array starting at index 1.

For a node at index i:
  • Left child = 2i
  • Right child = 2i + 1
  • Parent = floor(i / 2), for i greater than 1
Array index:  1   2   3   4   5   6
Value:       10  20  30  40  50  60
Do not mix zero-based and one-based indexing formulas. Always identify the indexing convention first.

8. Complete C11 Program – Array Representation

This program stores a binary tree in a zero-based array and displays the children and parent of a selected node. 

#include <stdio.h>

#define SIZE 7

int main(void) {
    int tree[SIZE] = {
        10, 20, 30, 40, 50, 60, 70
    };

    int index;

    printf("Binary Tree Array:\n");

    for (int i = 0; i < SIZE; i++) {
        printf("Index %d = %d\n", i, tree[i]);
    }

    printf("\nEnter an index (0 to %d): ", SIZE - 1);

    if (scanf("%d", &index) != 1 ||
        index < 0 || index >= SIZE) {
        printf("Invalid index.\n");
        return 1;
    }

    int left = 2 * index + 1;
    int right = 2 * index + 2;

    printf("\nNode value = %d\n", tree[index]);

    if (left < SIZE) {
        printf("Left child = %d\n", tree[left]);
    } else {
        printf("Left child does not exist.\n");
    }

    if (right < SIZE) {
        printf("Right child = %d\n", tree[right]);
    } else {
        printf("Right child does not exist.\n");
    }

    if (index > 0) {
        int parent = (index - 1) / 2;
        printf("Parent = %d\n", tree[parent]);
    } else {
        printf("Root has no parent.\n");
    }

    return 0;
}

Sample Input

1

Expected Output

Binary Tree Array:
Index 0 = 10
Index 1 = 20
Index 2 = 30
Index 3 = 40
Index 4 = 50
Index 5 = 60
Index 6 = 70

Enter an index (0 to 6): 1

Node value = 20
Left child = 40
Right child = 50
Parent = 10

Complexity Analysis

  • Accessing a node: O(1).
  • Finding parent: O(1).
  • Finding left child: O(1).
  • Finding right child: O(1).
  • Displaying the entire array: O(n).
  • Space: O(n).

9. Limitations of Array Representation

Array representation works efficiently for complete or nearly complete binary trees, but it can waste memory for sparse or skewed trees.

Example: Right-Skewed Tree

    10
      \
       20
         \
          30
            \
             40

Using zero-based indexing:

  • 10 is stored at index 0.
  • 20 is stored at index 2.
  • 30 is stored at index 6.
  • 40 is stored at index 14.

Only four positions contain values, but an array must reserve positions up to index 14.

For a highly skewed tree, array representation can require exponentially more positions relative to the number of levels. Linked representation is generally more suitable for arbitrary tree shapes.

10. Dynamic Binary Tree Construction Using Recursion

Instead of manually connecting every node, we can create a binary tree recursively.

The construction process is:

  1. Read the value of the current node.
  2. If the input indicates no node, return NULL.
  3. Create a new node.
  4. Recursively construct its left subtree.
  5. Recursively construct its right subtree.
  6. Return the address of the created node.

Input Convention

We will use preorder input:

  • Root first.
  • Left subtree next.
  • Right subtree last.
  • -1 indicates a NULL child.

Example Input

10 20 40 -1 -1 50 -1 -1 30 -1 60 -1 -1

Tree Created

                 10
                /  \
               20   30
              / \     \
             40  50    60

Complete C11 Program

#include <stdio.h>
#include <stdlib.h>

struct Node {
    int data;
    struct Node *left;
    struct Node *right;
};

struct Node *createTree(void) {
    int value;

    if (scanf("%d", &value) != 1) {
        fprintf(stderr, "Invalid or incomplete tree input.\n");
        exit(EXIT_FAILURE);
    }

    if (value == -1) {
        return NULL;
    }

    struct Node *newNode = malloc(sizeof *newNode);

    if (newNode == NULL) {
        fprintf(stderr, "Memory allocation failed.\n");
        exit(EXIT_FAILURE);
    }

    newNode->data = value;
    newNode->left = NULL;
    newNode->right = NULL;

    printf("Enter left child of %d (-1 for NULL): ", value);
    newNode->left = createTree();

    printf("Enter right child of %d (-1 for NULL): ", value);
    newNode->right = createTree();

    return newNode;
}

void preorder(const struct Node *root) {
    if (root == NULL) {
        return;
    }

    printf("%d ", root->data);
    preorder(root->left);
    preorder(root->right);
}

void inorder(const struct Node *root) {
    if (root == NULL) {
        return;
    }

    inorder(root->left);
    printf("%d ", root->data);
    inorder(root->right);
}

void postorder(const struct Node *root) {
    if (root == NULL) {
        return;
    }

    postorder(root->left);
    postorder(root->right);
    printf("%d ", root->data);
}

void freeTree(struct Node *root) {
    if (root == NULL) {
        return;
    }

    freeTree(root->left);
    freeTree(root->right);
    free(root);
}

int main(void) {
    struct Node *root;

    printf("Enter root value (-1 for empty tree):\n");
    root = createTree();

    printf("\nPreorder traversal: ");
    preorder(root);

    printf("\nInorder traversal: ");
    inorder(root);

    printf("\nPostorder traversal: ");
    postorder(root);

    printf("\n");

    freeTree(root);

    return 0;
}
This example uses -1 as a NULL marker, so -1 cannot be used as a node value. A production implementation can use a separate token or another input format to support every possible integer value.

Sample Input

10 20 40 -1 -1 50 -1 -1 30 -1 60 -1 -1

Expected Traversal Output

Preorder traversal: 10 20 40 50 30 60
Inorder traversal: 40 20 50 10 30 60
Postorder traversal: 40 50 20 60 30 10

Dry Run

Input value Operation
10 Create root node 10.
20 Create left child of 10.
40 Create left child of 20.
-1, -1 Both children of 40 are NULL.
50 Create right child of 20.
-1, -1 Both children of 50 are NULL.
30 Create right child of 10.
-1 Left child of 30 is NULL.
60 Create right child of 30.
-1, -1 Both children of 60 are NULL.

Complexity Analysis

  • Construction time: O(n), where n is the number of nodes.
  • Recursive auxiliary space: O(h).
  • Tree storage: O(n).

11. Memory Management in Binary Trees

Binary tree nodes are commonly created using dynamic memory allocation.

Each successful malloc() allocation must eventually be released using free().

Why Postorder Freeing Is Used

A parent node contains pointers to its children. Therefore, we should release the child nodes before freeing the parent. 

void freeTree(struct Node *root) {
    if (root == NULL) {
        return;
    }

    freeTree(root->left);
    freeTree(root->right);

    free(root);
}

The sequence is:

  1. Free the left subtree.
  2. Free the right subtree.
  3. Free the current node.
This is postorder processing: Left subtree, Right subtree, then Root. It prevents losing access to child pointers before they are released.

12. Linked Representation vs Array Representation

Feature Linked Representation Array Representation
Memory allocation Dynamic Usually fixed or dynamically resized array
Storage Nodes connected through pointers Elements stored in consecutive array positions
Child access Through left and right pointers Using index formulas
Memory utilization Generally suitable for sparse trees Can waste space for sparse trees
Implementation Requires pointers and dynamic allocation Uses array indices
Best suited for General binary trees Complete binary trees and heaps
Parent lookup Requires traversal or an additional parent pointer O(1) using the index formula

13. Common Implementation Mistakes

  1. Not initializing child pointers: Set both left and right pointers to NULL when creating a node.
  2. Not checking malloc(): Always verify that memory allocation succeeded.
  3. Mixing array indexing formulas: Use zero-based or one-based formulas consistently.
  4. Incorrect tree construction order: Follow the required input convention when constructing recursively.
  5. Memory leaks: Free dynamically allocated nodes when the tree is no longer needed.
  6. Freeing the parent too early: Free child subtrees before freeing the parent.
  7. Assuming every binary tree is complete: General binary trees can have missing children at any position.

14. Time and Space Complexity

Operation Linked Representation Array Representation
Access root O(1) O(1)
Access child when parent is known O(1) O(1)
Find a value O(n) in a general binary tree O(n) in an unsorted tree array
Construct n nodes O(n) O(n) to populate n positions
Storage O(n) O(m), where m is allocated array capacity

For linked representation, the recursive construction and traversal stack generally requires O(h) auxiliary space, where h is the tree height.

15. Common Binary Tree Interview Questions

Q1. What are the two common representations of a binary tree?

Linked representation and array representation.

Q2. What does a binary tree node contain?

A data field, a left child pointer and a right child pointer.

Q3. Why is dynamic memory allocation used?

It allows nodes to be created at runtime without requiring a fixed maximum number of nodes.

Q4. What is the left child index in a zero-based array?

2i + 1.

Q5. What is the right child index in a zero-based array?

2i + 2.

Q6. What is the parent index in a zero-based array?

floor((i - 1) / 2), for a non-root node.

Q7. Why is array representation inefficient for sparse trees?

Many array positions may remain unused because child positions are determined by fixed index formulas.

Q8. Why is linked representation preferred for general trees?

Nodes can be allocated dynamically and connected according to the actual tree structure.

Q9. What is the purpose of NULL child pointers?

They indicate that a node does not have the corresponding child.

Q10. Why should memory be freed in postorder?

Because child subtrees should be released before their parent, preserving access to the child pointers during cleanup.

Q11. What is the time complexity of constructing a tree with n nodes?

O(n), assuming each node is created and connected once.

Q12. Which representation is commonly used for binary heaps?

Array representation, because a binary heap is a complete binary tree.

18. Lesson Summary

  • Binary trees can use linked or array representation.
  • Linked nodes contain data, left pointer and right pointer.
  • malloc() is used for dynamic node allocation.
  • Every newly created node should have initialized child pointers.
  • Zero-based array child indices are 2i + 1 and 2i + 2.
  • The zero-based parent index is floor((i - 1) / 2).
  • Array representation is particularly useful for heaps.
  • Linked representation is suitable for general binary trees.
  • Recursive construction can build a tree from preorder input with NULL markers.
  • Postorder freeing releases child subtrees before their parent.
