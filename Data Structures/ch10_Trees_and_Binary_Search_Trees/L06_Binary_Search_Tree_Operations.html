Chapter 10 – Lesson 6

Binary Search Tree Operations

Understand BST properties and implement fundamental operations using C11.

1. Learning Objectives

  • Understand the Binary Search Tree (BST) property.
  • Differentiate a binary tree from a BST.
  • Search for a key in a BST.
  • Insert a new node into a BST.
  • Find minimum and maximum values.
  • Perform inorder traversal.
  • Analyze BST operation complexity.
  • Understand balanced and skewed BST behavior.

2. What is a Binary Search Tree?

A Binary Search Tree is a binary tree that maintains an ordering property for every node.

BST Property:
  • All keys in the left subtree are smaller than the current node's key.
  • All keys in the right subtree are greater than the current node's key.
  • Both left and right subtrees must also satisfy the BST property.

This lesson uses a strict BST policy: duplicate keys are not inserted.

Example

              50
            /    \
           30     70
          / \    /  \
         20 40  60  80
  • Values smaller than 50 are in its left subtree.
  • Values greater than 50 are in its right subtree.
  • The same ordering rule applies recursively.

3. Binary Tree vs Binary Search Tree

Binary Tree Binary Search Tree
Each node has at most two children. Each node has at most two children and follows an ordering rule.
No ordering is required. Left keys are smaller and right keys are greater under our policy.
Searching may require O(n). Searching takes O(h), where h is tree height.
Inorder traversal is not necessarily sorted. Inorder traversal produces ascending order.

4. BST Node Structure in C

typedef struct Node {
    int data;
    struct Node *left;
    struct Node *right;
} Node;

Each node stores:

  • data: the key value.
  • left: pointer to the left child.
  • right: pointer to the right child.

Creating a Node

Node *createNode(int value)
{
    Node *newNode = malloc(sizeof(Node));

    if (newNode == NULL) {
        return NULL;
    }

    newNode->data = value;
    newNode->left = NULL;
    newNode->right = NULL;

    return newNode;
}

5. Searching in a BST

BST searching uses the ordering property to eliminate one subtree at each comparison.

Algorithm

  1. Start at the root.
  2. If the root is NULL, the key is not present.
  3. If the key matches the current node, return that node.
  4. If the key is smaller, move to the left child.
  5. If the key is greater, move to the right child.
  6. Repeat until the key is found or the search reaches NULL.

Example: Search for 60

              50
            /    \
           30     70
                 /
                60

    Search path: 50 → 70 → 60
    Comparisons: 3

Recursive Search Function

Node *searchRecursive(Node *root, int key)
{
    if (root == NULL || root->data == key) {
        return root;
    }

    if (key < root->data) {
        return searchRecursive(root->left, key);
    }

    return searchRecursive(root->right, key);
}

Iterative Search Function

Node *searchIterative(Node *root, int key)
{
    while (root != NULL) {
        if (key == root->data) {
            return root;
        }

        if (key < root->data) {
            root = root->left;
        } else {
            root = root->right;
        }
    }

    return NULL;
}
Iterative search avoids recursion stack usage. It is particularly useful when a BST may become highly skewed.

6. Insertion in a BST

Insertion places a new key at the correct NULL child position while preserving the BST property.

Algorithm

  1. If the current subtree is empty, create and return a new node.
  2. If the new key is smaller, insert into the left subtree.
  3. If the new key is greater, insert into the right subtree.
  4. If the key already exists, do not insert a duplicate.
  5. Return the current root after updating its child pointer.

Example

Insert 65 into the following BST:

              50
            /    \
           30     70
                 /
                60

Search path: 50 → 70 → 60 → right NULL.

After insertion:

              50
            /    \
           30     70
                 /
                60
                  \
                   65

Recursive Insertion Function

Node *insert(Node *root, int key)
{
    if (root == NULL) {
        return createNode(key);
    }

    if (key < root->data) {
        Node *child = insert(root->left, key);

        if (child != NULL) {
            root->left = child;
        }
    }
    else if (key > root->data) {
        Node *child = insert(root->right, key);

        if (child != NULL) {
            root->right = child;
        }
    }

    /* Duplicate keys are ignored. */
    return root;
}
This compact insertion function returns the existing root if allocation fails. For production code, use a status-returning interface so the caller can distinguish successful insertion, duplicate keys and allocation failure. A complete status-based implementation appears below.

7. Finding Minimum and Maximum Values

Minimum Value

The minimum value is found at the leftmost node of a BST.

Node *findMinimum(Node *root)
{
    if (root == NULL) {
        return NULL;
    }

    while (root->left != NULL) {
        root = root->left;
    }

    return root;
}

Maximum Value

The maximum value is found at the rightmost node.

Node *findMaximum(Node *root)
{
    if (root == NULL) {
        return NULL;
    }

    while (root->right != NULL) {
        root = root->right;
    }

    return root;
}

            /    \
           30     70
          / \    /  \
         20 40  60  80

    Minimum = 20
    Maximum = 80

8. Inorder Traversal of a BST

Inorder traversal follows:

    Left → Root → Right

For a valid BST with distinct keys, inorder traversal produces values in ascending order.

Function

void inorder(Node *root)
{
    if (root == NULL) {
        return;
    }

    inorder(root->left);
    printf("%d ", root->data);
    inorder(root->right);
}

For the example tree:

              50
            /    \
           30     70
          / \    /  \
         20 40  60  80
Inorder Output 
20 30 40 50 60 70 80

9. Complete C11 Program: BST Operations

This program implements insertion, searching, minimum, maximum, inorder traversal and memory cleanup. It also distinguishes duplicate insertion from memory allocation failure.

#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;
    struct Node *left;
    struct Node *right;
} Node;

typedef enum {
    INSERT_OK,
    INSERT_DUPLICATE,
    INSERT_NO_MEMORY
} InsertStatus;

Node *createNode(int value)
{
    Node *newNode = malloc(sizeof(Node));

    if (newNode == NULL) {
        return NULL;
    }

    newNode->data = value;
    newNode->left = NULL;
    newNode->right = NULL;

    return newNode;
}

InsertStatus insert(Node **root, int key)
{
    while (*root != NULL) {
        if (key == (*root)->data) {
            return INSERT_DUPLICATE;
        }

        if (key < (*root)->data) {
            root = &((*root)->left);
        } else {
            root = &((*root)->right);
        }
    }

    *root = createNode(key);

    if (*root == NULL) {
        return INSERT_NO_MEMORY;
    }

    return INSERT_OK;
}

Node *search(Node *root, int key)
{
    while (root != NULL) {
        if (key == root->data) {
            return root;
        }

        if (key < root->data) {
            root = root->left;
        } else {
            root = root->right;
        }
    }

    return NULL;
}

Node *findMinimum(Node *root)
{
    if (root == NULL) {
        return NULL;
    }

    while (root->left != NULL) {
        root = root->left;
    }

    return root;
}

Node *findMaximum(Node *root)
{
    if (root == NULL) {
        return NULL;
    }

    while (root->right != NULL) {
        root = root->right;
    }

    return root;
}

void inorder(Node *root)
{
    if (root == NULL) {
        return;
    }

    inorder(root->left);
    printf("%d ", root->data);
    inorder(root->right);
}

void freeTree(Node *root)
{
    if (root == NULL) {
        return;
    }

    freeTree(root->left);
    freeTree(root->right);
    free(root);
}

int main(void)
{
    Node *root = NULL;

    int values[] = {50, 30, 70, 20, 40, 60, 80};
    int count = sizeof(values) / sizeof(values[0]);

    for (int i = 0; i < count; i++) {
        InsertStatus status = insert(&root, values[i]);

        if (status == INSERT_NO_MEMORY) {
            printf("Memory allocation failed.\n");
            freeTree(root);
            return 1;
        }

        if (status == INSERT_DUPLICATE) {
            printf("Duplicate key: %d\n", values[i]);
        }
    }

    printf("Inorder traversal: ");
    inorder(root);
    printf("\n");

    int key = 60;

    if (search(root, key) != NULL) {
        printf("%d found in BST.\n", key);
    } else {
        printf("%d not found in BST.\n", key);
    }

    Node *minimum = findMinimum(root);
    Node *maximum = findMaximum(root);

    if (minimum != NULL) {
        printf("Minimum value: %d\n", minimum->data);
    }

    if (maximum != NULL) {
        printf("Maximum value: %d\n", maximum->data);
    }

    freeTree(root);

    return 0;
}
Expected Output 
Inorder traversal: 20 30 40 50 60 70 80
60 found in BST.
Minimum value: 20
Maximum value: 80

10. Understanding BST Complexity

The complexity of BST operations depends on the height of the tree.

Operation Average Case (Balanced) Worst Case (Skewed)
Search O(log n) O(n)
Insertion O(log n) O(n)
Find Minimum O(log n) O(n)
Find Maximum O(log n) O(n)
Inorder Traversal O(n) O(n)

Auxiliary space: Iterative search and min/max operations use O(1) auxiliary space. Recursive inorder traversal uses O(h) stack space.

11. Balanced BST vs Skewed BST

Balanced BST

              40
            /    \
           20     60
          / \    / \
         10 30  50 70

Its height is approximately O(log n), allowing efficient searching and insertion.

Skewed BST

        10
          \
           20
             \
              30
                \
                 40

This structure behaves like a linked list. Its height becomes O(n).

A normal BST does not automatically maintain balance. AVL trees and Red-Black trees address this limitation; they are covered separately in advanced tree topics.

12. Important BST Applications

  • Maintaining dynamically changing sorted data.
  • Implementing ordered sets and maps.
  • Searching and retrieving minimum or maximum keys.
  • Finding predecessor and successor values.
  • Range queries and ordered traversal.
  • Building the foundation for AVL and Red-Black trees.

13. Common Interview Mistakes

  • Assuming every binary tree is a BST.
  • Searching both subtrees instead of using the ordering property.
  • Forgetting to update the root pointer after inserting into an empty tree.
  • Ignoring duplicate-key policy.
  • Assuming every BST operation always takes O(log n).
  • Forgetting to free dynamically allocated nodes.
  • Assuming a node's immediate children alone establish the BST property; the entire left and right subtrees must satisfy the ordering constraints.

15. Common Interview Questions and Answers

Q1. What is a Binary Search Tree?

Answer: A binary tree in which every node maintains the ordering property: smaller keys are in the left subtree and greater keys are in the right subtree.

Q2. What is the average search complexity of a BST?

Answer: O(log n) when the tree is reasonably balanced.

Q3. What is the worst-case search complexity?

Answer: O(n), when the BST becomes skewed.

Q4. Which traversal gives sorted output from a BST?

Answer: Inorder traversal.

Q5. Where is the minimum value located?

Answer: At the leftmost node.

Q6. Where is the maximum value located?

Answer: At the rightmost node.

Q7. Does a BST allow duplicate keys?

Answer: It depends on the implementation policy. This lesson rejects duplicates.

Q8. Why can a BST become inefficient?

Answer: If inserted keys arrive in sorted order, an ordinary BST can become skewed and behave like a linked list.

Q9. What is the difference between BST and AVL tree?

Answer: A BST follows the ordering property but does not guarantee balance. An AVL tree is a self-balancing BST that maintains a height-balance condition.

Q10. What is the time complexity of inorder traversal?

Answer: O(n), because every node is visited once.

16. Multiple Choice Questions

Q1. Which traversal produces sorted values in a BST?

  1. Preorder
  2. Inorder
  3. Postorder
  4. Level order

Answer: B – Inorder

Q2. Where is the smallest key located?

  1. Root node
  2. Rightmost node
  3. Leftmost node
  4. Any leaf node

Answer: C – O(n)

Q5. Which condition is used to search for a smaller key?

Q6. A BST with values inserted in ascending order may become:

  1. Perfect
  2. Complete
  3. Right-skewed

Q7. Which data structure maintains ordering automatically through a balancing mechanism?

  1. Ordinary linked list
  2. AVL tree
  3. Stack
  4. Queue

Q8. What is the time complexity of visiting all BST nodes using inorder traversal?

  3. O(n)
  4. O(n²)

Answer: C – O(n)

17. Lesson Summary

  • A BST is an ordered binary tree.
  • Searching follows left or right pointers based on key comparison.
  • Insertion places a new key at the correct empty child position.
  • The minimum is the leftmost node.
  • The maximum is the rightmost node.
  • Inorder traversal produces ascending order for distinct BST keys.
  • Operation complexity is O(h), where h is the tree height.
  • A skewed BST can degrade to O(n) operations.
Placement priority: Practise BST insertion, searching, minimum/maximum and inorder traversal until you can write each operation without referring to notes. Understand why the worst case is O(n).
