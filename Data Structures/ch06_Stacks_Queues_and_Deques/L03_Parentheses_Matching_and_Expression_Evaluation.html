2. Parentheses Matching

Parentheses matching is the process of checking whether opening and closing brackets are correctly paired and nested.

Types of Brackets

OpeningClosing
()
{}
[]

Balanced Expressions

{[()]}       Balanced
((A+B)*C)    Balanced
[A+B*(C-D)]  Balanced

Unbalanced Expressions

[(])       Unbalanced
((A+B)     Unbalanced
A+B)       Unbalanced
{[}]       Unbalanced

A stack is suitable because the most recently opened bracket must be the first one closed. This is a LIFO requirement.

3. Algorithm for Balanced Parentheses

  1. Initialize an empty stack.
  2. Scan the expression from left to right.
  3. If an opening bracket is found, push it.
  4. If a closing bracket is found, check whether the stack is empty.
  5. If empty, the expression is unbalanced.
  6. Otherwise pop the opening bracket and check whether the pair matches.
  7. After scanning, the expression is balanced only if the stack is empty.

Dry Run: {[()]}

CharacterOperationStack
{Push {{
[Push [{ [
(Push ({ [ (
)Pop ({ [
]Pop [{
}Pop {Empty

All brackets match and the stack is empty. Therefore, the expression is balanced.

4. C Program: Balanced Parentheses Checking

This program checks (), [] and {} in an expression. Other characters are ignored.

#include <stdio.h>
#include <string.h>

#define MAX 1000

int isOpening(char ch)
{
    return ch == '(' || ch == '[' || ch == '{';
}

int isClosing(char ch)
{
    return ch == ')' || ch == ']' || ch == '}';
}

int isMatching(char open, char close)
{
    return (open == '(' && close == ')') ||
           (open == '[' && close == ']') ||
           (open == '{' && close == '}');
}

int isBalanced(const char expression[])
{
    char stack[MAX];
    int top = -1;

    for (int i = 0; expression[i] != '\0'; i++)
    {
        char ch = expression[i];

        if (isOpening(ch))
        {
            if (top == MAX - 1)
                return 0;

            stack[++top] = ch;
        }
        else if (isClosing(ch))
        {
            if (top == -1)
                return 0;

            char open = stack[top--];

            if (!isMatching(open, ch))
                return 0;
        }
    }

    return top == -1;
}

int main(void)
{
    char expression[MAX];

    printf("Enter an expression: ");

    if (fgets(expression, sizeof expression, stdin) == NULL)
        return 1;

    if (isBalanced(expression))
        printf("Balanced parentheses\n");
    else
        printf("Unbalanced parentheses\n");

    return 0;
}

Sample Output 1

Enter an expression: {[()]}
Balanced parentheses

Sample Output 2

Enter an expression: [(])
Unbalanced parentheses

Time complexity: O(n).

Auxiliary space: O(n) in the worst case.

5. What Is an Arithmetic Expression?

An arithmetic expression contains operands, operators and sometimes parentheses.

Example:

A + B * C
  • Operands: A, B, C
  • Operators: +, *
  • Parentheses: Used to control evaluation order.

Expressions can be represented using infix, postfix and prefix notations.

6. Infix Expression

In infix notation, the operator is placed between the operands.

A + B
A * B
A + B * C
(A + B) * C

This is the normal notation used in mathematical expressions.

7. Postfix Expression

In postfix notation, the operator is placed after its operands.

InfixPostfix
A + BAB+
A - BAB-
A * BAB*
A + B * CABC*+
(A + B) * CAB+C*

Postfix expressions do not require parentheses to indicate operator precedence.

8. Prefix Expression

In prefix notation, the operator is placed before its operands.

InfixPrefix
A + B+AB
A - B-AB
A * B*AB
A + B * C+A*BC
(A + B) * C*+ABC

11. Infix to Postfix Conversion

A stack stores operators and parentheses while operands are sent directly to the postfix output.

Conversion Rules

  1. If the character is an operand, add it to the output.
  2. If it is an opening parenthesis, push it.
  3. If it is a closing parenthesis, pop operators until the matching opening parenthesis is found.
  4. If it is an operator, pop higher-precedence operators from the stack.
  5. For left-associative operators of equal precedence, pop the existing operator first.
  6. Push the current operator.
  7. After scanning, pop the remaining operators.

Example

Infix:
A + B * C

Postfix:
ABC*+

Detailed Dry Run

InputOperator StackPostfix Output
AEmptyA
++A
B+AB
*+ *AB
C+ *ABC
EndEmptyABC*+

12. C Program: Infix to Postfix Conversion

This educational implementation accepts single-character alphanumeric operands and the operators +, -, *, / and parentheses. Spaces are ignored.

#include <stdio.h>
#include <ctype.h>
#include <string.h>

#define MAX 1000

int precedence(char op)
{
    if (op == '*' || op == '/')
        return 2;

    if (op == '+' || op == '-')
        return 1;

    return 0;
}

int isOperator(char ch)
{
    return ch == '+' || ch == '-' ||
           ch == '*' || ch == '/';
}

int infixToPostfix(const char infix[], char postfix[])
{
    char stack[MAX];
    int top = -1;
    int j = 0;

    for (int i = 0; infix[i] != '\0'; i++)
    {
        char ch = infix[i];

        if (isspace((unsigned char)ch))
            continue;

        if (isalnum((unsigned char)ch))
        {
            if (j >= MAX - 1)
                return 0;

            postfix[j++] = ch;
        }
        else if (ch == '(')
        {
            if (top == MAX - 1)
                return 0;

            stack[++top] = ch;
        }
        else if (ch == ')')
        {
            while (top >= 0 && stack[top] != '(')
            {
                if (j >= MAX - 1)
                    return 0;

                postfix[j++] = stack[top--];
            }

            if (top == -1)
                return 0;

            top--;
        }
        else if (isOperator(ch))
        {
            while (top >= 0 &&
                   isOperator(stack[top]) &&
                   precedence(stack[top]) >= precedence(ch))
            {
                if (j >= MAX - 1)
                    return 0;

                postfix[j++] = stack[top--];
            }

            if (top == MAX - 1)
                return 0;

            stack[++top] = ch;
        }
        else
        {
            return 0;
        }
    }

    while (top >= 0)
    {
        if (stack[top] == '(')
            return 0;

        if (j >= MAX - 1)
            return 0;

        postfix[j++] = stack[top--];
    }

    postfix[j] = '\0';

    return 1;
}

int main(void)
{
    char infix[MAX];
    char postfix[MAX];

    printf("Enter infix expression: ");

    if (fgets(infix, sizeof infix, stdin) == NULL)
        return 1;

    if (infixToPostfix(infix, postfix))
        printf("Postfix expression: %s\n", postfix);
    else
        printf("Invalid or unsupported expression\n");

    return 0;
}

Sample Output

Enter infix expression: A+B*C
Postfix expression: ABC*+

Another Example

Enter infix expression: (A+B)*C
Postfix expression: AB+C*
This converter performs operator and parenthesis conversion, but it does not fully validate mathematical syntax. It also does not support unary operators, multi-character operands, exponentiation or implicit multiplication.

Time complexity: O(n).

Auxiliary space: O(n).

13. Postfix Expression Evaluation

Postfix evaluation uses a stack to store operands.

Algorithm

  1. Scan the postfix expression from left to right.
  2. If an operand is encountered, push it onto the stack.
  3. If an operator is encountered, pop the right operand first.
  4. Pop the left operand next.
  5. Perform the operation as left operator right.
  6. Push the result back onto the stack.
  7. At the end, exactly one result should remain.

Example

Postfix:
23*54*+9-

Equivalent:
(2 * 3) + (5 * 4) - 9

Result:
17

Dry Run

SymbolOperationStack (Bottom to Top)
2Push 22
3Push 32, 3
*2 * 3 = 66
5Push 56, 5
4Push 46, 5, 4
*5 * 4 = 206, 20
+6 + 20 = 2626
9Push 926, 9
-26 - 9 = 1717

14. C Program: Postfix Expression Evaluation

This program evaluates single-digit operands and the operators +, -, * and /. It supports integer division.

#include <stdio.h>
#include <ctype.h>
#include <limits.h>

#define MAX 1000

int evaluatePostfix(const char expression[], int *result)
{
    int stack[MAX];
    int top = -1;

    for (int i = 0; expression[i] != '\0'; i++)
    {
        char ch = expression[i];

        if (isspace((unsigned char)ch))
            continue;

        if (isdigit((unsigned char)ch))
        {
            if (top == MAX - 1)
                return 0;

            stack[++top] = ch - '0';
        }
        else if (ch == '+' || ch == '-' ||
                 ch == '*' || ch == '/')
        {
            if (top < 1)
                return 0;

            int right = stack[top--];
            int left = stack[top--];
            int value;

            if (ch == '+')
                value = left + right;
            else if (ch == '-')
                value = left - right;
            else if (ch == '*')
                value = left * right;
            else
            {
                if (right == 0)
                    return 0;

                if (left == INT_MIN && right == -1)
                    return 0;

                value = left / right;
            }

            stack[++top] = value;
        }
        else
        {
            return 0;
        }
    }

    if (top != 0)
        return 0;

    *result = stack[top];

    return 1;
}

int main(void)
{
    char expression[MAX];
    int result;

    printf("Enter postfix expression: ");

    if (fgets(expression, sizeof expression, stdin) == NULL)
        return 1;

    if (evaluatePostfix(expression, &result))
        printf("Result: %d\n", result);
    else
        printf("Invalid postfix expression or division by zero\n");

    return 0;
}

Sample Output

Enter postfix expression: 23*54*+9-
Result: 17
The evaluator supports single-digit nonnegative operands only. It does not support multi-digit numbers, negative literals, unary operators or arithmetic overflow checking for addition, subtraction and multiplication. Those require a more robust tokenizer and checked arithmetic.

Time complexity: O(n).

Auxiliary space: O(n).

15. Prefix Expression Evaluation

Prefix expressions are evaluated by scanning from right to left.

Algorithm

  1. Scan the prefix expression from right to left.
  2. If an operand is encountered, push it.
  3. If an operator is encountered, pop the first operand.
  4. Pop the second operand.
  5. Perform the operation in the correct order.
  6. Push the result.
  7. Exactly one result should remain.

Example

Prefix:
- + * 2 3 * 5 4 9

Equivalent:
(2 * 3) + (5 * 4) - 9

Result:
17
Remember: postfix evaluation scans left to right, whereas prefix evaluation scans right to left.

17. Common Programming Mistakes

  1. Not checking whether the stack is empty before popping.
  2. Checking only the number of opening and closing brackets rather than their order.
  3. Ignoring mismatched bracket types.
  4. Forgetting to remove the opening parenthesis during conversion.
  5. Ignoring operator precedence.
  6. Ignoring operator associativity.
  7. Reversing the operand order during subtraction or division.
  8. Failing to detect division by zero.
  9. Accepting postfix expressions with extra operands.
  10. Assuming every expression contains only single-digit operands.

18. Placement Interview Questions and Answers

Q1. Why is a stack used for parentheses matching?

Answer: Because the most recently opened bracket must be closed first, which follows LIFO.

Q2. What is a balanced expression?

Answer: An expression in which every opening bracket has a matching closing bracket in the correct order.

Q3. What is infix notation?

Answer: Notation in which operators appear between operands, such as A+B.

Q4. What is postfix notation?

Answer: Notation in which operators appear after operands, such as AB+.

Q5. What is prefix notation?

Answer: Notation in which operators appear before operands, such as +AB.

Q6. Which data structure is used for infix-to-postfix conversion?

Answer: Stack.

Q7. Does postfix evaluation require operator precedence rules?

Answer: No. The operator positions already determine the evaluation order.

Q8. Which direction is used for postfix evaluation?

Answer: Left to right.

Q9. Which direction is used for prefix evaluation?

Answer: Right to left.

Q10. What is the postfix form of A+B*C?

Answer: ABC*+.

Q11. What is the postfix form of (A+B)*C?

Answer: AB+C*.

Q12. What is the prefix form of A+B*C?

Answer: +A*BC.

Q13. What is the time complexity of balanced parentheses checking?

Answer: O(n).

Q14. Why is operand order important during postfix evaluation?

Answer: Because subtraction and division are not commutative. The first popped value is the right operand.

Q15. What happens if a closing bracket appears when the stack is empty?

Answer: The expression is unbalanced.

Q16. What happens if the stack is not empty after scanning all brackets?

Answer: Some opening brackets do not have matching closing brackets.

Q17. What is associativity?

Answer: It determines the evaluation direction when operators have equal precedence.

Q18. What is the advantage of postfix notation?

Answer: It removes the need for parentheses and explicit precedence handling during evaluation.

Q19. What is the time complexity of infix-to-postfix conversion?

Answer: O(n), because each input symbol is processed a constant number of times.

Q20. Where are expression stacks used?

Answer: Compilers, calculators, interpreters, syntax analysis and expression evaluation systems.

21. Lesson Summary

  • Stacks are useful for bracket matching and expression processing.
  • Balanced parentheses require correct pairing and nesting.
  • Infix places operators between operands.
  • Postfix places operators after operands.
  • Prefix places operators before operands.
  • Infix-to-postfix conversion uses operator precedence and associativity.
  • Postfix evaluation scans from left to right.
  • Prefix evaluation scans from right to left.
  • These algorithms generally take O(n) time and O(n) auxiliary space.
