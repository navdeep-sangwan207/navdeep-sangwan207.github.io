Chapter 1: DSA Fundamentals and C++ STL

Lesson 4: Time and Space Complexity

Learn to measure algorithm efficiency, count operations and analyze memory usage for coding interviews.

1. Why Do We Analyze Algorithm Complexity?

Two programs may solve the same problem but require very different amounts of execution time and memory.

Algorithm complexity helps us estimate how resource requirements grow as the input size increases.

Example: Suppose two algorithms search for an element in an array:
  • Algorithm A checks elements one by one.
  • Algorithm B uses binary search on a sorted array.
Both can find the target, but their performance can differ significantly for large inputs.

Complexity analysis is important because placement coding problems frequently specify constraints such as N up to 100,000 or 1,000,000. These constraints help determine which algorithms are practical.

2. What Is Time Complexity?

Time complexity describes how the number of computational operations performed by an algorithm grows with input size.

It is commonly expressed using asymptotic notation such as O(N), O(N²) and O(log N).

Time complexity is not simply the actual number of seconds a program takes. Actual execution time depends on several factors:

  • Processor speed and architecture.
  • Programming language and compiler optimizations.
  • Memory hierarchy and cache behavior.
  • Operating system and system load.
  • Input characteristics.
Complexity analysis focuses on growth as input size increases, allowing algorithms to be compared independently of a particular machine.

3. What Is Input Size?

Input size is the amount of data an algorithm processes. It is usually represented by N, but other variables may be used when a problem has multiple inputs.

Problem Possible Input Size
Array traversal N = number of elements
Matrix processing R × C = number of rows and columns
String processing N = number of characters
Graph traversal V = vertices, E = edges
Two-array problem N and M = sizes of the two arrays

Always identify the input variables before analyzing an algorithm.

4. Counting Operations

A useful way to understand time complexity is to count how many times important statements execute.

Example 1: Constant Number of Operations

int a = 10;
int b = 20;
int sum = a + b;

cout << sum;

The number of operations does not depend on an input size N.

Time Complexity: O(1)

Example 2: Single Loop

for (int i = 0; i < n; i++)
{
    cout << i;
}

The loop executes N times.

Statement Approximate Executions
Initialization: i = 01
Condition: i < nN + 1
Loop bodyN
Increment: i++N

The total number of operations grows linearly with N.

Time Complexity: O(N)

Example 3: Two Consecutive Loops

for (int i = 0; i < n; i++)
{
    cout << i;
}

for (int j = 0; j < n; j++)
{
    cout << j;
}

First loop: N operations.

Second loop: N operations.

Total growth: N + N = 2N.

Time Complexity: O(N)

When simplifying asymptotic complexity, constant multipliers are ignored. Therefore, O(2N) is written as O(N).

5. Nested Loops

When one loop executes inside another, the total number of iterations often becomes the product of their iteration counts.

Example 1: Two Nested N Loops

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        cout << i << " " << j << endl;
    }
}

Outer loop executes N times. For each outer iteration, the inner loop executes N times.

Total executions = N × N = N².

Time Complexity: O(N²)

Example 2: Three Nested Loops

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        for (int k = 0; k < n; k++)
        {
            cout << i + j + k;
        }
    }
}

Total executions = N × N × N = N³.

Time Complexity: O(N³)

Example 3: Nested Loops With Different Input Sizes

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < m; j++)
    {
        cout << i << " " << j;
    }
}

The outer loop executes N times and the inner loop executes M times.

Time Complexity: O(N × M)

Do not automatically call every nested loop O(N²). Analyze the actual iteration counts and dependencies.

6. Logarithmic Time Complexity

An algorithm has logarithmic growth when the problem size is repeatedly reduced by a constant factor, commonly two.

Example: Repeatedly Divide by Two

int n = 64;

while (n > 1)
{
    n = n / 2;
}

Dry run:

Iteration Value of N
Initial64
132
216
38
44
52
61

After K divisions:

N / 2K = 1

Therefore:

K = log₂N

Time Complexity: O(log N)

Binary search is a common example of logarithmic time complexity because it eliminates approximately half of the remaining search space in each iteration.

7. Linearithmic Time Complexity: O(N log N)

Some efficient sorting algorithms divide a problem into smaller parts and perform linear work across logarithmic levels.

Example: Merge Sort

Merge sort divides an array into halves until individual elements remain. It then merges the sorted parts.

  • Number of division levels: approximately log₂N.
  • Work at each level: approximately N.
  • Total work: N × log₂N.

Time Complexity: O(N log N)

Other examples include heap sort and average-case quicksort.

8. Common Time Complexity Classes

Complexity Name Typical Example
O(1) Constant Array element access by index
O(log N) Logarithmic Binary search
O(N) Linear Array traversal
O(N log N) Linearithmic Merge sort
O(N²) Quadratic Two nested loops over N
O(N³) Cubic Three nested loops over N
O(2N) Exponential Some exhaustive recursive algorithms
O(N!) Factorial Generating all permutations

For sufficiently large N, the usual growth order from slower to faster is:

O(1)
  < O(log N)
  < O(N)
  < O(N log N)
  < O(N²)
  < O(N³)
  < O(2^N)
  < O(N!)
This ordering describes asymptotic growth for sufficiently large input sizes, not necessarily the actual runtime for every small input.

9. What Is Space Complexity?

Space complexity describes how an algorithm's memory requirements grow with input size.

It is useful to distinguish between:

  • Input space: Memory used to store the input data.
  • Auxiliary space: Additional memory used by the algorithm.
  • Total space: Input storage plus auxiliary memory and other relevant storage.

Example 1: Constant Auxiliary Space

int sum = 0;

for (int i = 0; i < n; i++)
{
    sum += arr[i];
}

Only a fixed number of extra variables are used.

Auxiliary Space: O(1)

Example 2: Additional Array

vector<int> copyArray(n);

for (int i = 0; i < n; i++)
{
    copyArray[i] = arr[i];
}

The new vector stores N elements.

Auxiliary Space: O(N)

Example 3: Two-Dimensional Matrix

vector<vector<int>> matrix(n, vector<int>(n));

The matrix contains N × N elements.

Auxiliary Space: O(N²)

Example 4: Recursive Function

int factorial(int n)
{
    if (n <= 1)
        return 1;

    return n * factorial(n - 1);
}

Each recursive call uses a stack frame. The maximum recursion depth is proportional to N.

Auxiliary Space: O(N)

Recursion uses the call stack even when no additional array or container is created.

10. Best, Average and Worst-Case Complexity

The execution cost of an algorithm may depend on the arrangement of input data.

Example: Linear Search

Array: [10, 20, 30, 40, 50]

Case Situation Comparisons Complexity
Best Target is the first element. 1 O(1)
Average Target is typically somewhere in the array. Approximately N/2 under a uniform successful-search assumption O(N)
Worst Target is last or absent. N O(N)

Best case: Minimum work for an input of a given size.

Average case: Expected work under a specified input distribution.

Worst case: Maximum work over inputs of a given size.

Average-case analysis requires assumptions about input distribution. It is not always correct to simply divide the worst-case operation count by two.

11. Analyzing Common C++ Code Patterns

Pattern 1: Direct Array Access

int value = arr[5];

Time: O(1) for ordinary array or vector indexing.

Pattern 2: Loop With Doubling

for (int i = 1; i < n; i *= 2)
{
    cout << i;
}

The value of i doubles each time.

Time: O(log N)

Pattern 3: Loop With Halving

for (int i = n; i > 0; i /= 2)
{
    cout << i;
}

Time: O(log N)

Pattern 4: Triangular Nested Loop

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < i; j++)
    {
        cout << i << " " << j;
    }
}

The inner loop executes:

0 + 1 + 2 + ... + (N - 1) times.

Total = N(N - 1) / 2.

Time: O(N²)

Pattern 5: Consecutive Linear and Quadratic Work

for (int i = 0; i < n; i++)
{
    cout << i;
}

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        cout << i + j;
    }
}

Total work = N + N².

The dominant term is N².

Time: O(N²)

12. Constraints and Choosing an Algorithm

In coding interviews, constraints provide important clues about the expected complexity.

Approximate Input Size Potentially Suitable Approaches
N up to 10 Exhaustive search or permutations may be feasible.
N up to 20 Some O(2N) approaches may be feasible.
N up to 100 O(N³) may be possible depending on operation cost and time limits.
N up to 1,000 O(N²) may be practical in many settings.
N up to 100,000 O(N log N) or O(N) is often preferred.
N up to 1,000,000 Usually seek O(N) or O(N log N), subject to constants and limits.
These are rough interview heuristics, not guaranteed limits. Actual feasibility depends on the time limit, hardware, implementation, memory limit and number of test cases.

13. Common Complexity Analysis Mistakes

  1. Assuming every nested loop has O(N²) complexity without checking its bounds.
  2. Adding complexities when independent consecutive operations should be combined and simplified by the dominant term.
  3. Multiplying complexities of consecutive loops instead of adding their work.
  4. Ignoring recursion stack memory.
  5. Confusing total space with auxiliary space.
  6. Assuming that O(N) always executes faster than O(N log N) for every small input.
  7. Ignoring input constraints and multiple test cases.
  8. Assuming every library operation has constant complexity.
Complexity of C++ STL operations depends on the container and operation. For example, vector indexing is O(1), while searching an unsorted vector using find is O(N).

16. Multiple-Choice Questions

Q1. What is the time complexity of accessing arr[5]?

  1. O(N)
  2. O(1)
  3. O(N²)
  4. O(log N)

Answer: B — O(1).

Q2. What is the time complexity of two nested loops, each executing N times?

  1. O(N)
  2. O(log N)
  3. O(N²)
  4. O(2N)

Answer: C — O(N²).

Q3. Which complexity is associated with binary search?

  1. O(N²)
  2. O(N)
  3. O(log N)
  4. O(N³)

Answer: C — O(log N).

Q4. What is the auxiliary space complexity of iterative array traversal using a fixed number of variables?

  1. O(N)
  2. O(N²)
  3. O(1)
  4. O(log N)

Answer: C — O(1).

Q5. Which is the time complexity of merge sort?

  1. O(N²)
  2. O(N log N)
  3. O(1)
  4. O(2N)

Answer: B — O(N log N).

Q6. What is the usual auxiliary space complexity of recursive factorial?

  1. O(1)
  2. O(N)
  3. O(N²)
  4. O(log N)

Answer: B — O(N).

17. Lesson Summary

  • Time complexity measures the growth of computational work.
  • Space complexity measures memory requirements.
  • Input size determines how complexity is expressed.
  • Consecutive operations are added; nested iteration counts are often multiplied.
  • Repeated division or multiplication by a constant commonly produces logarithmic complexity.
  • Auxiliary space excludes the original input storage.
  • Best, average and worst cases describe different input-dependent costs.
  • Input constraints help determine whether an algorithm is practical.
