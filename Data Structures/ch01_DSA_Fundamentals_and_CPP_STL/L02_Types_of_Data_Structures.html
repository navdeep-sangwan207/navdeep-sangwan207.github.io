Lesson 2: Types of Data Structures

Understand the classification of data structures, including primitive, non-primitive, linear and non-linear structures, with practical C++ examples.

1. Learning Objectives

  • Understand the classification of data structures.
  • Differentiate primitive and non-primitive data structures.
  • Understand linear and non-linear data structures.
  • Compare static and dynamic data structures.
  • Understand homogeneous and non-homogeneous data.
  • Identify suitable data structures for programming problems.
  • Implement basic examples using C++.

2. Classification of Data Structures

Data structures can be classified according to the type of data stored, the arrangement of elements and how memory is managed.

General Classification 
Data Structures
       |
       |---------------- Primitive
       |
       |---------------- Non-Primitive
                              |
                              |---- Linear
                              |
                              |---- Non-Linear

Other classifications:
- Static and Dynamic
- Homogeneous and Non-Homogeneous

These classifications describe different properties and are not mutually exclusive. For example, an array is a non-primitive, linear and typically static structure when declared with a fixed size.

3. Primitive Data Structures

Primitive data types are the fundamental built-in types supported directly by a programming language. They represent individual values.

Common C++ Primitive Types

Data Type Purpose Example
int Integer values int age = 25;
char Character values char grade = 'A';
float Single-precision floating point float price = 12.5f;
double Double-precision floating point double pi = 3.14159;
bool Boolean values bool status = true;
Important: Exact sizes of C++ fundamental types depend on the implementation and platform. Use sizeof() to inspect their sizes on your system.

4. Non-Primitive Data Structures

Non-primitive data structures organize multiple values or relationships between elements. They are generally constructed using primitive types or other data structures.

Examples

  • Array
  • Linked List
  • Stack
  • Queue
  • Tree
  • Graph
  • Hash Table

Non-primitive structures are commonly divided into linear and non-linear categories.

5. Linear Data Structures

A linear data structure arranges elements in a sequential logical order. Each element generally has a predecessor and successor, except at the ends.

5.1 Array

An array stores elements of the same type in contiguous memory locations. 

int arr[5] = {10, 20, 30, 40, 50};

Typical characteristics:

  • Index-based access.
  • Contiguous storage for built-in arrays.
  • Fixed size for a built-in array with a fixed bound.
  • Efficient random access.

5.2 Linked List

A linked list consists of nodes. Each node stores data and a link to another node. 

struct Node
{
    int data;
    Node* next;
};

Typical characteristics:

  • Nodes are dynamically allocated when needed.
  • Nodes need not occupy contiguous memory.
  • Sequential traversal is required for access by position.
  • Insertion and deletion can be efficient when the node position is known.

5.3 Stack

A stack follows the LIFO principle: Last In, First Out.

The last inserted element is the first element removed. Common operations are push, pop and top. 

Stack:
    Push 10
    Push 20
    Push 30

    Pop -> 30

5.4 Queue

A queue generally follows the FIFO principle: First In, First Out.

The first inserted element is normally the first removed. Common operations include enqueue and dequeue. 

Queue:
    Insert 10
    Insert 20
    Insert 30

    Remove -> 10

Linear Data Structure Comparison

Structure Arrangement Common Application
Array Indexed sequence Storing records
Linked List Linked nodes Dynamic collections
Stack LIFO Function calls and undo operations
Queue FIFO Task scheduling

6. Non-Linear Data Structures

Non-linear data structures organize elements hierarchically or through interconnected relationships. Elements are not restricted to a single sequential order.

6.1 Tree

A tree is a hierarchical data structure consisting of nodes connected through edges. 

          10
         /  \
        20   30
       /  \
      40   50

Common tree terminology:

  • Root: The topmost node.
  • Parent: A node that has child nodes.
  • Child: A node connected below another node.
  • Leaf: A node without children.
  • Subtree: A tree formed from a node and its descendants.
  • Height: The longest downward path measured in edges under the common convention.

6.2 Graph

A graph consists of vertices (nodes) and edges connecting those vertices. 

    A -------- B
    |          |
    |          |
    C -------- D

Common graph types:

  • Directed graph
  • Undirected graph
  • Weighted graph
  • Unweighted graph
  • Cyclic graph
  • Acyclic graph

Applications of Non-Linear Structures

Structure Application
Tree File systems and database indexing
Binary Search Tree Ordered searching and data management
Heap Priority-based scheduling
Graph Computer networks and navigation

7. Static and Dynamic Data Structures

7.1 Static Data Structures

A static data structure has a size that is fixed for its lifetime after creation. 

int arr[5] = {10, 20, 30, 40, 50};

This built-in array has room for exactly five integers. Its size cannot be changed after declaration.

7.2 Dynamic Data Structures

A dynamic data structure can grow or shrink during program execution, depending on its implementation. 

#include <iostream>
#include <vector>
using namespace std;

int main()
{
    vector<int> numbers;

    numbers.push_back(10);
    numbers.push_back(20);
    numbers.push_back(30);

    for(int value : numbers)
    {
        cout << value << " ";
    }

    return 0;
}

Expected Output

10 20 30

A C++ vector can automatically manage its storage as elements are added or removed.

Static Array Dynamic Vector
Fixed size Can grow and shrink
Built-in array declaration STL container
Size cannot change Size can change through operations
No automatic resizing Automatic capacity management
Important: A vector's size is the number of elements it currently contains. Its capacity is the amount of storage available before it needs to reallocate. Reallocation can invalidate pointers, references and iterators to its elements.

8. Homogeneous and Non-Homogeneous Data

8.1 Homogeneous Data

A homogeneous collection stores elements of the same type. 

int marks[4] = {75, 80, 90, 85};

All elements in this array are integers.

8.2 Non-Homogeneous Data

A non-homogeneous record can contain fields of different types. A C++ structure is a common example. 

#include <iostream>
using namespace std;

struct Student
{
    int rollNumber;
    string name;
    float marks;
};

int main()
{
    Student s1;

    s1.rollNumber = 101;
    s1.name = "Rahul";
    s1.marks = 85.5f;

    cout << s1.rollNumber << endl;
    cout << s1.name << endl;
    cout << s1.marks << endl;

    return 0;
}

Expected Output

101 Rahul 85.5

A structure groups related information under one record, even though its individual fields can have different data types.

10. How to Choose the Right Data Structure

Selecting a suitable data structure depends on the operations your application performs most frequently.

Requirement Possible Choice Reason
Fast index-based access Array / Vector Constant-time indexed access
Frequent insertions and deletions near known nodes Linked List No shifting of following elements
Last-in-first-out processing Stack LIFO operations
First-in-first-out processing Queue FIFO operations
Priority-based processing Heap Efficient access to highest or lowest priority
Fast average-case key lookup Hash Table Average constant-time lookup under suitable conditions
Hierarchical information Tree Parent-child relationships
Network relationships Graph Arbitrary connections between vertices
These are typical choices, not universal rules. Actual performance depends on the required operations, data size, implementation and memory constraints.

11. Placement Interview Questions

Q1. What are the main types of data structures?

Data structures are commonly classified as primitive and non-primitive. Non-primitive structures can be further classified as linear and non-linear.

Q2. What is the difference between linear and non-linear structures?

Linear structures arrange elements sequentially, whereas non-linear structures organize elements hierarchically or through network relationships.

Q3. Is an array a linear data structure?

Yes. An array stores elements in a sequential indexed order.

Q4. Is a linked list a static or dynamic data structure?

A conventional linked list is dynamic because nodes can be allocated and removed during program execution.

Q5. What is the difference between a stack and a queue?

A stack follows LIFO, whereas a queue generally follows FIFO.

Q6. Is a tree a linear data structure?

No. A tree is a non-linear hierarchical data structure.

Q7. What is a homogeneous data structure?

It stores elements of the same data type, such as an integer array.

Q8. What is a non-homogeneous data structure?

It groups fields of different data types, such as a C++ structure containing an integer, string and float.

Q9. Is a C++ vector a static or dynamic structure?

A vector is dynamically resizable. Its size can change as elements are inserted or removed.

Q10. Which data structure is used in recursion internally?

Function calls use the call stack to maintain information about active function invocations.

Q11. Which data structure is suitable for a priority scheduler?

A priority queue, commonly implemented using a heap, is suitable when tasks must be selected by priority.

Q12. Can a data structure be both linear and dynamic?

Yes. A linked list is a common example of a linear and dynamic data structure.

14. Lesson Summary

  • Primitive data types represent fundamental individual values.
  • Non-primitive structures organize multiple values and relationships.
  • Linear structures use a sequential logical arrangement.
  • Non-linear structures represent hierarchical or network relationships.
  • Static structures have a fixed size after creation.
  • Dynamic structures can change size during execution.
  • Homogeneous collections store elements of the same type.
  • Structures can group fields of different types.
