Lesson 3: Algorithms and Pseudocode

Learn how to convert a programming problem into a logical solution before implementing it in C++.

1. What Is an Algorithm?

An algorithm is a finite sequence of well-defined steps used to solve a problem or perform a computation.

In programming, an algorithm describes the logical procedure for transforming input into the required output.

Example: Find the larger of two numbers.
  1. Read two numbers A and B.
  2. Compare A and B.
  3. If A is greater than B, output A.
  4. Otherwise, output B.

The algorithm describes the solution independently of a particular programming language.

2. Characteristics of a Good Algorithm

2.1 Input

An algorithm accepts zero or more input values. For example, a searching algorithm receives an array and a target value.

2.2 Output

An algorithm produces at least one meaningful result. A searching algorithm may return the index of an element or indicate that it was not found.

2.3 Definiteness

Every instruction must be precise and unambiguous. The same instruction should not have different interpretations.

2.4 Finiteness

An algorithm must terminate after a finite number of steps for every valid input within its specified domain.

2.5 Effectiveness

Each operation should be sufficiently basic and executable in a finite amount of time.

2.6 Correctness

A correct algorithm produces the expected output for all inputs that satisfy its stated requirements.

2.7 Generality

A useful algorithm should solve a class of problems rather than only one specific example.

Placement concept: An algorithm that gives the correct answer for one test case is not necessarily correct. It must handle all valid cases defined by the problem.

3. Algorithm, Program, Pseudocode and Flowchart

Term Meaning
Algorithm Logical sequence of steps for solving a problem.
Pseudocode Informal, programming-style representation of an algorithm.
Flowchart Graphical representation of a process using standard symbols.
Program Executable implementation of an algorithm in a programming language.

For example, an algorithm for finding the maximum element can first be written as pseudocode and then implemented using C++.

Pseudocode does not have one universal syntax. Different books and companies may use slightly different conventions. Its main purpose is to communicate logic clearly.

4. Problem-Solving Workflow

Before writing code in a placement coding round, follow a systematic approach:

  1. Understand the problem: Identify exactly what must be calculated or returned.
  2. Identify input and output: Determine the data types and expected result.
  3. Check constraints: Understand the input size, value ranges and special conditions.
  4. Work through examples: Test a normal case and important edge cases manually.
  5. Select an approach: Choose a suitable data structure and algorithm.
  6. Write pseudocode: Express the solution as clear steps.
  7. Dry run: Execute the steps manually using sample input.
  8. Check correctness: Verify that the logic handles all valid cases.
  9. Analyze complexity: Estimate time and auxiliary space requirements.
  10. Implement and test: Write code and test it with multiple inputs.
Interview tip: Explain your initial approach, then discuss whether a more efficient solution exists. Interviewers often evaluate reasoning, not just the final code.

5. Basic Control Structures in Algorithms

5.1 Sequence

Instructions execute one after another in the specified order.

READ A
READ B
SUM = A + B
PRINT SUM

5.2 Selection

A condition determines which branch of instructions executes.

IF marks >= 40 THEN
    PRINT "Pass"
ELSE
    PRINT "Fail"
END IF

5.3 Iteration

A set of instructions repeats while a condition is satisfied or for a specified number of iterations.

FOR i = 1 TO 5
    PRINT i
END FOR

These three control structures form the foundation of most procedural algorithms.

6. Pseudocode Example: Find the Maximum of an Array

Problem: Given an array of N integers, find its maximum element.

Approach: Assume the first element is the maximum. Compare every remaining element with the current maximum and update it when a larger value is found.

Algorithm

  1. Read the array size N.
  2. If N is zero, report that no maximum exists.
  3. Initialize MAX with the first array element.
  4. Traverse the remaining elements.
  5. If the current element is greater than MAX, update MAX.
  6. Print MAX.

Pseudocode

ALGORITHM FindMaximum(A, N)

    IF N <= 0 THEN
        PRINT "Invalid array size"
        RETURN
    END IF

    MAX = A[0]

    FOR i = 1 TO N - 1
        IF A[i] > MAX THEN
            MAX = A[i]
        END IF
    END FOR

    PRINT MAX

END ALGORITHM

Dry Run

Input array: [12, 5, 28, 9, 35, 17]

Initial12—12

Output: 35

C++ Implementation

#include <iostream>
#include <vector>
using namespace std;

int main()
{
    int n;

    cout << "Enter array size: ";
    cin >> n;

    if (n <= 0)
    {
        cout << "Invalid array size";
        return 0;
    }

    vector<int> arr(n);

    cout << "Enter array elements: ";

    for (int i = 0; i < n; i++)
    {
        cin >> arr[i];
    }

    int maximum = arr[0];

    for (int i = 1; i < n; i++)
    {
        if (arr[i] > maximum)
        {
            maximum = arr[i];
        }
    }

    cout << "Maximum element = " << maximum;

    return 0;
}
Complexity preview: The algorithm examines each array element once. Its time complexity is O(N), and its auxiliary space complexity is O(1), excluding the input array.

7. Pseudocode Example: Linear Search

Problem: Find the position of a target value in an array. Return -1 if the target is absent.

Pseudocode

ALGORITHM LinearSearch(A, N, TARGET)

    FOR i = 0 TO N - 1

        IF A[i] == TARGET THEN
            RETURN i
        END IF

    END FOR

    RETURN -1

END ALGORITHM

Dry Run

Array: [10, 25, 30, 45, 50]

Target: 45

Index Array Element Comparison Result
01010 == 45False
12525 == 45False
23030 == 45False
34545 == 45True — Stop

Output: Index 3

C++ Implementation

#include <iostream>
using namespace std;

int main()
{
    int arr[] = {10, 25, 30, 45, 50};
    int n = sizeof(arr) / sizeof(arr[0]);
    int target = 45;

    int position = -1;

    for (int i = 0; i < n; i++)
    {
        if (arr[i] == target)
        {
            position = i;
            break;
        }
    }

    if (position != -1)
        cout << "Element found at index " << position;
    else
        cout << "Element not found";

    return 0;
}

Output: Element found at index 3

If duplicate values exist, this implementation returns the index of the first occurrence. If the target is not present, it returns -1.

8. Pseudocode Example: Sum of Array Elements

Problem: Calculate the sum of all elements in an array.

Pseudocode

ALGORITHM ArraySum(A, N)

    SUM = 0

    FOR i = 0 TO N - 1
        SUM = SUM + A[i]
    END FOR

    RETURN SUM

END ALGORITHM

9. Flowcharts and Their Symbols

A flowchart represents an algorithm visually. It helps explain the sequence of operations and decision-making logic.

Symbol Shape Name Purpose
Oval Terminator Start or end of a process.
Rectangle Process Calculation or processing instruction.
Parallelogram Input / Output Read input or display output.
Diamond Decision Evaluate a condition and branch.
Arrow Flow line Indicate the direction of execution.

Flow of a Simple Maximum-of-Two-Numbers Algorithm

       (START)
           |
       Input A, B
           |
       Is A > B?
        /     \
      Yes      No
       |        |
   Print A   Print B
       \        /
          |
        (END)

The diamond represents a decision. Its outgoing paths represent the possible results of the condition.

10. Correctness, Edge Cases and Common Mistakes

10.1 Correctness

An algorithm is correct if it produces the required result for every valid input.

For the maximum-element algorithm, the central reasoning is that after processing each element, MAX stores the largest value encountered so far. After the final iteration, it therefore stores the maximum of the entire array.

10.2 Important Edge Cases

  • Empty array: A maximum element does not exist. Handle this before accessing A[0].
  • Single element: The only element is the maximum.
  • Negative values: Initialize MAX with A[0], not zero.
  • Duplicate values: Ensure the algorithm behaves correctly when values repeat.
  • Target not found: Searching should return the specified failure value.
  • Large input values: Choose a data type capable of storing the result.

10.3 Common Programming Mistakes

Mistake Why It Is a Problem
Using i <= N instead of i < N May access an invalid array index.
Initializing maximum to zero Fails for arrays containing only negative values.
Forgetting to update a variable Can produce incorrect results or infinite loops.
Not checking empty input May access an element that does not exist.
Ignoring integer overflow Arithmetic results may exceed the selected data type's range.
Not testing duplicates May cause incorrect search or counting behavior.

11. Introduction to Algorithm Complexity

Before implementing an algorithm, we should consider the resources it uses.

Time Complexity

Time complexity describes how the number of computational operations grows with input size.

Space Complexity

Space complexity describes how memory requirements grow with input size. Auxiliary space refers to the extra memory used by the algorithm, excluding the input itself.

Algorithm Time Complexity Auxiliary Space
Array traversal O(N) O(1)
Linear search O(N) worst case O(1)
Finding maximum O(N) O(1)
Sum of array elements O(N) O(1)
These are introductory complexity examples. Detailed analysis of Big O, best case, average case, worst case and space complexity will be covered in the next lessons.

15. Lesson Summary

  • An algorithm is a finite sequence of well-defined steps to solve a problem.
  • Important properties include input, output, definiteness, finiteness and effectiveness.
  • Pseudocode expresses an algorithm in a readable, programming-style form.
  • Flowcharts represent algorithms graphically.
  • Sequence, selection and iteration are fundamental control structures.
  • Dry runs help verify the logic before implementation.
  • Correct algorithms must handle edge cases and valid input constraints.
  • Complexity analysis helps evaluate algorithm efficiency.
