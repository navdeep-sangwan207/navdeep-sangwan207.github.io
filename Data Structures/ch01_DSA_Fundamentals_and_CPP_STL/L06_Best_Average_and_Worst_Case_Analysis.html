Lesson 6: Best, Average and Worst Case Analysis

Chapter 1: DSA Fundamentals and C++ STL

Understand how algorithm performance changes with different inputs.

1. Introduction

The execution cost of an algorithm can depend on the actual input, not just the number of elements. Two inputs having the same size may cause an algorithm to perform different numbers of operations.

Best-case, average-case and worst-case analysis describe the algorithm's performance under different input conditions.

Example: Searching for a number in an array of 1,000 elements may require one comparison if the number is first, or 1,000 comparisons if it is last or absent.

2. Input-Dependent Running Time

Let x represent a particular input and let |x| = N represent its size. The actual operation count can be represented as: 

T(x) = Number of basic operations performed on input x

Since different inputs of the same size can have different costs, we define three case functions: 

Tbest(N)  = minimum cost among inputs of size N

Tworst(N) = maximum cost among inputs of size N

Tavg(N)   = expected cost over inputs of size N

Average-case analysis requires a probability distribution over the possible inputs. Without that assumption, an average-case value is not fully defined.

3. Best-Case Analysis

Best-case analysis measures the minimum number of operations performed by an algorithm among all valid inputs of size N.

Mathematical definition:

Tbest(N) = min { T(x) : |x| = N }

It describes the most favorable input for the algorithm.

Linear search example: If the target is at the first position, only one comparison is required. Therefore, the best-case time is Θ(1).

Limitation: Best-case performance alone does not tell us how the algorithm behaves on difficult or typical inputs.

4. Worst-Case Analysis

Worst-case analysis measures the maximum number of operations performed among all valid inputs of size N. 

Tworst(N) = max { T(x) : |x| = N }

It provides an upper performance guarantee for every input of that size, under the chosen operation-count model.

Linear search example: If the target is at the last position, or is absent, the algorithm may inspect all N elements. Its worst-case time is Θ(N).

Worst-case analysis is important when predictable performance and response-time guarantees matter.

5. Average-Case Analysis

Average-case analysis calculates the expected cost over possible inputs of size N according to a specified probability distribution. 

Tavg(N) = Σ P(x) × T(x)

Here, P(x) is the probability of input x. For a finite input set, the probabilities of all possible inputs must sum to 1.

Average case does not automatically mean the arithmetic average of best and worst case. The input distribution must be stated.

6. Linear Search: All Three Cases

Consider searching for a target in an array containing N elements.

#include <iostream>
using namespace std;

int linearSearch(int arr[], int n, int target) {
    for (int i = 0; i < n; i++) {
        if (arr[i] == target) {
            return i;
        }
    }
    return -1;
}

int main() {
    int arr[] = {10, 20, 30, 40, 50};
    int n = 5;
    int target = 30;

    int result = linearSearch(arr, n, target);

    if (result != -1)
        cout << "Found at index: " << result;
    else
        cout << "Not found";

    return 0;
}

Case 1: Best Case

Target is at the first position.

Array:  [10, 20, 30, 40, 50]
Target: 10

Comparisons = 1
Time = Θ(1)

Case 2: Worst Case

Target is at the last position or is absent.

Array:  [10, 20, 30, 40, 50]
Target: 50

Comparisons = 5
Time = Θ(N)

Case 3: Average Case

Assume the target is guaranteed to be present and each of the N positions is equally likely. 

Average comparisons
= (1 + 2 + 3 + ... + N) / N
= [N(N + 1) / 2] / N
= (N + 1) / 2

Time = Θ(N)

If the target may also be absent, the average depends on the probability of absence and the distribution of successful positions. For example, if the target is absent with probability q, and otherwise each position is equally likely, then: 

Expected comparisons
= (1 - q) × (N + 1) / 2 + q × N

7. Insertion Sort: Case Analysis

Insertion sort builds a sorted portion of an array by inserting each new element into its correct position. 

void insertionSort(int arr[], int n) {
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;

        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }

        arr[j + 1] = key;
    }
}

Best Case: Already Sorted

Input:  [1, 2, 3, 4, 5]

Each key needs only one comparison with
the preceding element.

Time = Θ(N)

Worst Case: Reverse Sorted

Input: [5, 4, 3, 2, 1]

Each new element shifts all preceding
elements in the sorted portion.

Comparisons grow approximately as:
1 + 2 + 3 + ... + (N - 1)

Time = Θ(N²)

Average Case

For randomly ordered permutations of distinct elements, the expected number of shifts and comparisons grows quadratically.

Average Time = Θ(N²)

8. Binary Search: Case Analysis

Binary search repeatedly halves the search interval. The input array must be sorted, and the implementation must maintain the correct search boundaries. 

int binarySearch(int arr[], int n, int target) {
    int low = 0;
    int high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (arr[mid] == target)
            return mid;
        else if (arr[mid] < target)
            low = mid + 1;
        else
            high = mid - 1;
    }

    return -1;
}
Case Input condition Time complexity
Best Target is at the first middle position checked Θ(1)
Average Typical successful or unsuccessful searches Θ(log N)
Worst Search continues through the maximum number of halvings Θ(log N)

The average-case statement assumes a reasonable distribution of search targets. Binary search remains logarithmic in the worst case.

9. Hash Table Lookup: Average vs Worst Case

Hash tables use a hash function to map keys to positions or buckets. In C++, unordered_map and unordered_set are common hash-based containers. 

#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    unordered_map<string, int> marks;

    marks["Aman"] = 85;
    marks["Riya"] = 92;
    marks["Karan"] = 78;

    auto it = marks.find("Riya");

    if (it != marks.end())
        cout << it->second;
    else
        cout << "Not found";

    return 0;
}
Case Expected behavior Complexity
Average Well-distributed hashes and controlled load factor Expected O(1)
Worst Many keys collide into the same bucket O(N)

Average constant-time lookup is conditional on suitable hashing and distribution. It is not a guaranteed worst-case bound.

10. Merge Sort: Similar Complexity Across Cases

Merge sort divides the array into halves, recursively sorts them, and merges the sorted halves. 

void mergeSort(int arr[], int left, int right) {
    if (left >= right)
        return;

    int mid = left + (right - left) / 2;

    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);

    // Merge the two sorted halves here.
}

For the standard merge sort implementation, dividing and merging require Θ(N log N) time across best, average and worst cases.

Time: Θ(N log N)

Auxiliary space: O(N)

The exact space usage depends on the implementation and whether the recursion stack is included. Standard array-based merge sort uses an additional merge buffer of O(N), plus O(log N) recursion stack space.

12. Big O, Big Omega and Big Theta in Case Analysis

Best, average and worst case describe which inputs are being considered. Big O, Big Omega and Big Theta describe asymptotic bounds on the resulting case functions.

Notation Meaning
O(g(N)) Asymptotic upper bound
Ω(g(N)) Asymptotic lower bound
Θ(g(N)) Asymptotically tight bound

For example, linear search has:

  • Best-case function: Θ(1)
  • Average-case function under the stated assumptions: Θ(N)
  • Worst-case function: Θ(N)
Big O does not inherently mean worst case, and Big Omega does not inherently mean best case. You can apply asymptotic notation to any case function.

13. Why Worst-Case Analysis Is Important

  • It provides a bound on the maximum work for an input size.
  • It helps evaluate algorithms under difficult input conditions.
  • It is important for predictable response-time requirements.
  • It helps identify algorithms that may degrade badly.
  • It is commonly used when comparing algorithms in interviews.

However, worst-case analysis does not describe every practical workload. Average-case analysis can be useful when the input distribution is understood and representative.

14. Amortized Analysis: Introduction

Amortized analysis studies the average cost per operation over a sequence of operations, even when individual operations have different costs.

Unlike average-case analysis, amortized analysis does not require a probability distribution over inputs.

Example: C++ vector push_back()

#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> values;

    for (int i = 1; i <= 10; i++) {
        values.push_back(i);

        cout << "Size: " << values.size()
             << ", Capacity: " << values.capacity()
             << endl;
    }

    return 0;
}

A vector occasionally allocates a larger memory block and moves or copies existing elements when its capacity is exhausted. That individual insertion may cost O(N).

Across a sequence of insertions, the total cost is O(N) under the usual geometric-growth strategy, giving amortized O(1) per push_back().

Remember: Individual worst-case cost can be O(N), while amortized cost per insertion is O(1).

15. How to Explain Case Analysis in an Interview

Use this sequence when an interviewer asks for algorithm complexity:

  1. Identify the input size, such as N.
  2. Identify the basic operation being counted.
  3. Describe the input that produces minimum work.
  4. Describe the input that produces maximum work.
  5. State the assumptions used for average-case analysis.
  6. Give the resulting asymptotic complexity.
  7. Mention important space complexity separately.
Interview example: For linear search, the best case is Θ(1) when the first element matches. The worst case is Θ(N) when the target is last or absent. If the target is guaranteed to be present and equally likely at every position, the expected number of comparisons is (N + 1) / 2, giving Θ(N) average time.

  1. Implement linear search and count the number of comparisons.
  2. Implement binary search and count the number of iterations.
  3. Implement insertion sort and count comparisons and shifts.
  4. Compare insertion sort on sorted, reverse-sorted and random arrays.

  6. Use unordered_map to count the frequency of array elements.
  7. Use vector to observe size and capacity changes during insertion.

For each program, test at least three input patterns: favorable, unfavorable and representative. Record operation counts rather than relying only on stopwatch measurements for small inputs.

18. Multiple-Choice Questions

1. Linear search best-case complexity is:

A) O(N)   B) O(log N)   C) O(1)   D) O(N²)

Answer: C) O(1)

2. Linear search worst-case complexity is:

A) O(1)   B) O(N)   C) O(log N)   D) O(N log N)

Answer: B) O(N)

3. Insertion sort best-case complexity is:

A) Θ(N)   B) Θ(N²)   C) Θ(log N)   D) Θ(1)

Answer: A) Θ(N)

4. Binary search requires:

A) Unsorted data   B) Sorted data   C) A linked list only   D) A hash table

Answer: B) Sorted data

5. Average-case analysis requires:

A) Only the largest input   B) A probability distribution   C) No input assumptions   D) Only recursion

Answer: B) A probability distribution

6. Standard merge sort time complexity is:

A) Θ(N²)   B) Θ(log N)   C) Θ(N log N)   D) Θ(1)

Answer: C) Θ(N log N)

7. Average hash-table lookup is commonly:

A) Expected O(1)   B) O(N²)   C) O(log N)   D) Always O(N)

Answer: A) Expected O(1)

8. Amortized vector push_back() complexity is:

A) O(N²)   B) O(log N)   C) O(1)   D) Always O(N)

Answer: C) O(1)

19. Lesson Summary

  • Best case measures minimum cost for inputs of size N.
  • Worst case measures maximum cost for inputs of size N.
  • Average case measures expected cost under a specified distribution.
  • Linear search has Θ(1) best and Θ(N) worst time.
  • Insertion sort has Θ(N) best and Θ(N²) average and worst time.
  • Binary search has Θ(log N) worst-case time on sorted data.
  • Hash-table lookup is expected O(1) on average under suitable assumptions.
  • Merge sort has Θ(N log N) time across the standard cases.
  • Amortized analysis evaluates operation sequences without requiring probabilities.
