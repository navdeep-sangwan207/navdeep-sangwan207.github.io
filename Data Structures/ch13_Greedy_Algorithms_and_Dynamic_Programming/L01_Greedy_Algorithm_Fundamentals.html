2. What Is a Greedy Algorithm?

A Greedy Algorithm is an algorithmic technique that constructs a solution step by step by selecting the best available choice at each stage according to a specified rule.

It makes a locally optimal choice with the intention of obtaining a globally optimal solution.

Definition: A greedy algorithm makes an immediate choice that appears best at the current stage and does not reconsider earlier decisions.

Real-Life Example

Suppose you need to select the maximum number of non-overlapping activities. A useful strategy is to select the activity that finishes earliest, then continue selecting compatible activities.

Basic Greedy Process

  1. Identify the available choices.
  2. Define a selection rule.
  3. Select the locally best choice.
  4. Check whether the choice is feasible.
  5. Update the current solution.
  6. Repeat until the solution is complete.

3. Characteristics of Greedy Algorithms

CharacteristicExplanation
Local optimization Selects the best available choice at each step.
Irrevocable decisions Normally does not undo a previously selected choice.
Feasibility Every selected choice must satisfy problem constraints.
Optimal substructure An optimal solution can be built from optimal solutions to smaller subproblems.
Greedy-choice property A locally optimal choice can be part of a globally optimal solution.

4. Greedy-Choice Property

The greedy-choice property means that an optimal solution exists which begins with the choice selected by the greedy strategy.

Example: Activity Selection

Suppose the activities are:

ActivityStart TimeFinish Time
A13
B25
C46
D68
E59

The greedy rule is to choose the compatible activity with the earliest finishing time.

One optimal selection is:

A → C → D

The selected activities do not overlap, and three activities are scheduled.

5. Optimal Substructure

A problem has optimal substructure when an optimal solution can be constructed using optimal solutions to its smaller subproblems.

Example: Minimum Spanning Tree

When Kruskal's algorithm selects a minimum-weight edge connecting two different components, it combines components while preserving the possibility of constructing a minimum spanning tree.

Optimal substructure is important in both Greedy Algorithms and Dynamic Programming.

Optimal substructure alone does not prove that a greedy strategy is correct. A greedy-choice property or another correctness argument is also required.

6. Greedy Algorithm vs Dynamic Programming

Greedy AlgorithmDynamic Programming
Makes a locally optimal choice. Evaluates and combines subproblem results.
Usually does not reconsider decisions. Stores results and compares alternatives.
Often uses less memory. Often uses a table or memoization cache.
Requires a valid greedy-choice argument. Uses recurrence relations and state transitions.
Examples: Activity Selection, Kruskal. Examples: 0/1 Knapsack, LCS, Fibonacci.

Important Example: Coin Change

Consider denominations 1, 3 and 4, and a target amount of 6.

Greedy selection:

4 + 1 + 1 = 6

Number of coins = 3

Optimal selection:

3 + 3 = 6

Number of coins = 2

Greedy does not always produce the optimal answer. For arbitrary coin denominations, Dynamic Programming can be used to find the minimum number of coins.

Always verify that the greedy strategy is correct for the specific problem and constraints. Do not assume that choosing the largest, smallest or earliest value is automatically optimal.

7. General Greedy Algorithm Structure

The following pseudocode describes a common greedy pattern:

GREEDY(problem):

    solution = empty

    sort or organize available choices

    for each choice:
        if choice is feasible:
            select choice
            update solution

    return solution

Sorting is common in greedy algorithms, but not mandatory. Some greedy algorithms use priority queues or repeatedly select the currently best candidate.

8. C11 Example 1 – Minimum Number of Coins

For this example, use Indian-style denominations: 10, 5, 2 and 1. The greedy strategy selects the largest denomination that does not exceed the remaining amount.

Example

Amount = 28

10 + 10 + 5 + 2 + 1

Number of coins = 5

Algorithm

  1. Start with the largest denomination.
  2. Take as many coins of that denomination as possible.
  3. Subtract their value from the remaining amount.
  4. Continue with the next denomination.

Complete C11 Program

#include <stdio.h>

#define N 4

int main(void)
{
    int coins[N] = {10, 5, 2, 1};
    int amount = 28;
    int count = 0;

    printf("Coin selection:\n");

    for (int i = 0; i < N; i++)
    {
        int number = amount / coins[i];

        if (number > 0)
        {
            printf("%d coin(s) of value %d\n",
                   number, coins[i]);

            count += number;
            amount %= coins[i];
        }
    }

    printf("Minimum coins (for this denomination system) = %d\n",
           count);

    return 0;
}
Coin selection:
2 coin(s) of value 10
1 coin(s) of value 5
1 coin(s) of value 2
1 coin(s) of value 1
Minimum coins (for this denomination system) = 5

Time Complexity: O(N), where N is the number of denominations.

Space Complexity: O(1).

This greedy solution is valid for the demonstrated denomination system and amount. It is not a general solution for arbitrary coin denominations.

9. C11 Example 2 – Maximum Number of Compatible Activities

Given activities with start and finish times, select the maximum number of non-overlapping activities.

Greedy Rule

Sort activities by finishing time and repeatedly choose the next activity whose start time is greater than or equal to the finish time of the last selected activity.

Complete C11 Program

#include <stdio.h>
#include <stdlib.h>

#define N 6

typedef struct
{
    int start;
    int finish;
    int id;
} Activity;

int compareActivities(const void *a, const void *b)
{
    const Activity *x = a;
    const Activity *y = b;

    if (x->finish != y->finish)
    {
        return (x->finish > y->finish) -
               (x->finish < y->finish);
    }

    return (x->start > y->start) -
           (x->start < y->start);
}

int main(void)
{
    Activity activities[N] =
    {
        {1, 3, 1},
        {2, 5, 2},
        {4, 6, 3},
        {6, 8, 4},
        {5, 9, 5},
        {8, 10, 6}
    };

    qsort(activities, N, sizeof(Activity),
          compareActivities);

    int selected = 0;
    int lastFinish = 0;

    printf("Selected activities:\n");

    for (int i = 0; i < N; i++)
    {
        if (selected == 0 ||
            activities[i].start >= lastFinish)
        {
            printf("Activity %d: (%d, %d)\n",
                   activities[i].id,
                   activities[i].start,
                   activities[i].finish);

            lastFinish = activities[i].finish;
            selected++;
        }
    }

    printf("Maximum activities selected = %d\n",
           selected);

    return 0;
}
Selected activities:
Activity 1: (1, 3)
Activity 3: (4, 6)
Activity 4: (6, 8)
Activity 6: (8, 10)
Maximum activities selected = 4

Time Complexity: O(N log N), dominated by sorting.

Space Complexity: O(log N) typical sorting-stack space for the C library qsort implementation; its exact implementation is unspecified by C.

This example uses the convention that one activity may start exactly when the previous activity finishes. If the problem requires a strict gap, change the comparison from >= to >.

10. How to Prove a Greedy Algorithm Correct

A greedy solution should not be accepted merely because it works for a few examples. Its selection rule must be justified.

Common Proof Techniques

TechniqueIdea
Exchange Argument Show that an optimal solution can be modified to include the greedy choice without becoming worse.
Greedy Stays Ahead Show that after each step, the greedy solution is at least as good as any competing solution.
Mathematical Induction Prove the greedy decision is valid at the first step and remains valid for the remaining subproblem.

Activity Selection: Exchange Argument

  1. Let G be the activity that finishes earliest.
  2. Let O be the first activity in an optimal schedule.
  3. Because G finishes no later than O, replacing O with G cannot reduce the time available for the remaining activities.
  4. Therefore, there exists an optimal schedule that starts with G.
  5. Apply the same argument to the remaining compatible activities.

This justifies the earliest-finish-time greedy rule.

12. Greedy Algorithm vs Brute Force

GreedyBrute Force
Makes decisions using a selection rule. Explores possible candidate solutions.
Often avoids exploring all possibilities. May examine exponentially many possibilities.
Requires a correctness proof for the greedy rule. Can obtain an optimum by exhaustive search if all possibilities are covered.

13. Common Mistakes

  1. Assuming every locally optimal choice gives a globally optimal solution.
  2. Using greedy without proving the selection rule.
  3. Confusing optimal substructure with greedy-choice property.
  4. Ignoring feasibility constraints.
  5. Sorting by the wrong attribute.
  6. Using a coin-change greedy strategy for arbitrary denominations.
  7. Forgetting equal start or finish-time boundary conditions.
  8. Using an integer comparator based on subtraction, which can overflow.

14. Placement Interview Questions

Q1. What is a Greedy Algorithm?

An algorithm that repeatedly selects a locally optimal feasible choice according to a defined strategy.

Q2. What is the greedy-choice property?

It means that some globally optimal solution can begin with the choice made by the greedy strategy.

Q3. What is optimal substructure?

An optimal solution can be constructed from optimal solutions to smaller subproblems.

Q4. Does every problem with optimal substructure support greedy?

No. The greedy-choice property or an equivalent correctness argument is also needed.

Q5. Why is activity selection solved by sorting finish times?

Selecting the earliest-finishing compatible activity leaves the maximum possible remaining time for later activities.

Q6. Is Greedy always faster than Dynamic Programming?

No. Complexity depends on the problem and the chosen implementation. Greedy solutions are often simpler, but they are not universally faster.

Q7. What is an exchange argument?

A proof technique that replaces a choice in an optimal solution with the greedy choice while preserving optimality.

Q8. Give examples of greedy algorithms.

Activity Selection, Kruskal's MST, Prim's MST, Dijkstra's algorithm for nonnegative weights, and Huffman Coding.

17. Lesson Summary

  • Greedy algorithms make locally optimal feasible choices.
  • Decisions are normally not reconsidered.
  • Greedy-choice property is central to correctness.
  • Optimal substructure is shared by Greedy and DP.
  • Exchange arguments can prove greedy correctness.
  • Activity Selection is a classic greedy problem.
  • Greedy does not work for every optimization problem.
