2. What Is Dynamic Programming?

Dynamic Programming (DP) is an algorithmic technique that solves a complex problem by breaking it into smaller subproblems and storing their results so that repeated calculations can be avoided.

Definition: Dynamic Programming solves problems with overlapping subproblems by storing previously computed results and reusing them instead of calculating them repeatedly.

Why Is DP Needed?

Consider calculating the Fibonacci sequence using ordinary recursion. The same Fibonacci values are calculated multiple times.

For example:

fib(5)
       |
     fib(4) + fib(3)
       |        |
  fib(3)+fib(2) ...
       |
  Repeated calculations

Dynamic Programming stores calculated values and reuses them.

3. Two Main Properties of Dynamic Programming

3.1 Overlapping Subproblems

A problem has overlapping subproblems when the same smaller problems are solved repeatedly during the computation.

Example: Fibonacci recurrence

F(n) = F(n - 1) + F(n - 2)

F(5) = F(4) + F(3)
F(4) = F(3) + F(2)

F(3) is calculated more than once in the recursive tree. DP avoids repeating that calculation.

3.2 Optimal Substructure

A problem has optimal substructure when an optimal solution can be constructed using optimal solutions to smaller subproblems.

For example, in the shortest-path problem, if a shortest path from A to C passes through B, then the path from A to B must also be shortest under the usual shortest-path assumptions.

Overlapping subproblems and optimal substructure are common DP indicators, but they do not automatically define a complete solution. A correct state, recurrence, base cases and evaluation order must still be established.

4. Fibonacci – Recursive Approach

The Fibonacci sequence is defined as: 

F(0) = 0
F(1) = 1

F(n) = F(n - 1) + F(n - 2), n >= 2

Complete C11 Program – Recursion

#include <stdio.h>

unsigned long long fibonacci(int n)
{
    if (n <= 1)
        return (unsigned long long)n;

    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main(void)
{
    int n = 10;

    printf("Fibonacci number at position %d = %llu\n",
           n, fibonacci(n));

    return 0;
}
Fibonacci number at position 10 = 55

Time Complexity: O(2n) as a simple upper bound.

Auxiliary Space: O(n) recursion stack depth.

This recursive implementation is inefficient for larger n because it repeats subproblems. The unsigned result can also overflow for sufficiently large n. We will use checked arithmetic in the DP implementations below.

5. Fibonacci – Dynamic Programming Approach

Instead of recalculating previous Fibonacci values, store each result in an array.

DP State

dp[i] = Fibonacci number at position i

Base Cases

dp[0] = 0
dp[1] = 1

State Transition

dp[i] = dp[i - 1] + dp[i - 2]

Complete C11 Program – Tabulation

#include <stdio.h>

#define N 50

int main(void)
{
    unsigned long long dp[N + 1];

    int n = 10;

    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; i++)
    {
        dp[i] = dp[i - 1] + dp[i - 2];
    }

    printf("Fibonacci number at position %d = %llu\n",
           n, dp[n]);

    return 0;
}
Fibonacci number at position 10 = 55

Time Complexity: O(N).

Space Complexity: O(N).

6. Fibonacci – Space Optimized DP

To calculate the next Fibonacci number, only the previous two values are needed. The entire DP array is unnecessary.

State Transition

current = previous1 + previous2

Complete C11 Program

#include <stdio.h>

int main(void)
{
    int n = 10;

    unsigned long long previous2 = 0;
    unsigned long long previous1 = 1;
    unsigned long long current = 0;

    if (n == 0)
    {
        printf("Fibonacci = 0\n");
        return 0;
    }

    for (int i = 2; i <= n; i++)
    {
        current = previous1 + previous2;

        previous2 = previous1;
        previous1 = current;
    }

    printf("Fibonacci number at position %d = %llu\n",
           n, previous1);

    return 0;
}
Fibonacci number at position 10 = 55

Time Complexity: O(N).

Space Complexity: O(1).

7. Understanding DP States

A DP state represents the information needed to describe a subproblem.

Examples:

ProblemPossible DP State
Fibonacci dp[i] = Fibonacci value at index i
Climbing Stairs dp[i] = ways to reach stair i
0/1 Knapsack dp[i][w] = maximum value using first i items and capacity w
Longest Common Subsequence dp[i][j] = LCS length for two prefixes
Grid Unique Paths dp[i][j] = number of ways to reach cell (i,j)
Choosing the correct state is one of the most important steps in solving a DP problem.

8. State Transition

A state transition describes how the current DP state is calculated using previously solved states.

Fibonacci Example

dp[i] = dp[i - 1] + dp[i - 2]

Climbing Stairs Example

If one can climb either one or two steps at a time, the number of ways to reach step i is: 

dp[i] = dp[i - 1] + dp[i - 2]

Minimum Cost Example

Suppose a person can reach a position from the previous one or from two positions earlier. If each position has a cost, a possible recurrence is: 

dp[i] = cost[i] + min(dp[i - 1], dp[i - 2])

The exact recurrence depends on the problem's starting conditions and what the DP state represents.

9. Base Cases

Base cases are the smallest subproblems whose answers are known directly.

Fibonacci

dp[0] = 0
dp[1] = 1

Climbing Stairs

One common definition is:

dp[0] = 1
dp[1] = 1

Here dp[0] represents one way to stay at the ground position without taking a step.

0/1 Knapsack

dp[0][w] = 0
dp[i][0] = 0

With no available items or zero capacity, the maximum achievable value is zero when item values are nonnegative.

10. Recurrence Relation

A recurrence relation defines a problem in terms of smaller versions of itself.

Fibonacci

F(n) = F(n - 1) + F(n - 2)

Climbing Stairs

dp[n] = dp[n - 1] + dp[n - 2]

0/1 Knapsack

dp[i][w] = max(
    dp[i - 1][w],
    value[i] + dp[i - 1][w - weight[i]]
)

The second choice is considered only when the current item fits in the remaining capacity.

Longest Common Subsequence

if (a[i - 1] == b[j - 1])
    dp[i][j] = 1 + dp[i - 1][j - 1];
else
    dp[i][j] = max(
        dp[i - 1][j],
        dp[i][j - 1]
    );

11. DP Problem-Solving Framework

Use the following sequence during placement coding rounds:

  1. Identify the problem type: Determine whether it involves counting, optimization, reachability or sequence matching.
  2. Check for overlapping subproblems: Look for repeated calculations.
  3. Define the state: Explain exactly what dp[i] or dp[i][j] means.
  4. Identify choices: Determine the possible decisions at each state.
  5. Write the recurrence: Express the state using smaller states.
  6. Set base cases: Handle the smallest subproblems.
  7. Choose evaluation order: Ensure dependencies are computed before use.
  8. Determine the answer location: It may be dp[n], dp[n][m] or an optimum over multiple states.
  9. Analyze complexity: Count the states and work performed per state.
  10. Optimize space: Retain only the previous states when possible.

12. Brute Force vs Recursion vs Dynamic Programming

TechniqueApproachTypical Characteristics
Brute Force Enumerates possible solutions. May have exponential time complexity.
Recursion Breaks a problem into recursive subproblems. May repeat calculations.
Memoization Recursion with cached results. Top-down DP.
Tabulation Computes states iteratively. Bottom-up DP.
Space Optimized DP Stores only required previous states. Reduces auxiliary memory.

13. When Should Dynamic Programming Be Used?

Look for these problem characteristics:

  • Find the maximum or minimum possible value.
  • Count the number of valid ways.
  • Determine whether a target can be achieved.
  • Find the longest or shortest sequence under constraints.
  • Repeatedly solve the same smaller problem.
  • Make choices whose results depend on previously solved states.

14. Complexity Analysis in DP

A useful general formula is: 

Time Complexity =
Number of DP states × Work per state

Examples:

ProblemStatesTypical Time
Fibonacci N + 1 O(N)
0/1 Knapsack (N + 1)(W + 1) O(NW)
LCS (N + 1)(M + 1) O(NM)
Grid Unique Paths R × C O(RC)
O(NW) for 0/1 Knapsack is pseudo-polynomial, not polynomial in the bit-length of the input. W is a numeric capacity, and its binary representation uses only O(log W) bits.

15. Common DP Mistakes

  1. Defining a DP state without explaining its meaning.
  2. Writing an incorrect recurrence relation.
  3. Forgetting base cases.
  4. Accessing invalid array indices.
  5. Using an incorrect iteration order.
  6. Using uninitialized DP array elements.
  7. Confusing the final answer state with an intermediate state.
  8. Ignoring integer overflow.
  9. Assuming every recursive problem requires DP.
  10. Optimizing space before the recurrence is correct.

16. Placement Interview Questions

Q1. What is Dynamic Programming?

An algorithmic technique that solves overlapping subproblems and stores their results for reuse.

Q2. What are the two main properties commonly associated with DP?

Overlapping subproblems and optimal substructure.

Q3. What is a DP state?

A state is a precise representation of a subproblem whose result is stored and reused.

Q4. What is a state transition?

A formula that calculates a DP state from previously computed states.

Q5. What is a base case?

A smallest subproblem whose answer is directly known.

Q6. Why is ordinary recursive Fibonacci inefficient?

It recalculates the same Fibonacci values many times.

Q7. What is the time complexity of Fibonacci using tabulation?

O(N).

Q8. What is space optimization in DP?

Reducing stored states when the recurrence depends only on a limited number of previous states.

Q9. Is every problem with optimal substructure a DP problem?

No. A problem must also have a suitable decomposition and reusable subproblems for the standard DP approach.

Q10. What is the difference between Greedy and DP?

Greedy commits to a locally optimal choice, while DP evaluates and combines subproblem results to obtain an optimal solution.

19. Lesson Summary

  • Dynamic Programming avoids repeated calculations.
  • Overlapping subproblems are a key DP characteristic.
  • Optimal substructure helps build larger solutions.
  • A DP solution requires states, transitions and base cases.
  • Memoization is top-down DP.
  • Tabulation is bottom-up DP.
  • Fibonacci can be optimized from O(N) space to O(1) space.
  • DP complexity depends on the number of states and work per state.
