Chapter 13 – Lesson 05

Memoization and Tabulation

Master the two fundamental techniques used to optimize recursive solutions with Dynamic Programming.

1. Learning Objectives

  • Understand memoization and tabulation.
  • Differentiate top-down and bottom-up DP.
  • Convert recursive solutions into memoized solutions.
  • Build iterative DP solutions using tabulation.
  • Understand DP initialization and dependency ordering.
  • Analyze time and space complexity.
  • Solve placement-oriented problems using C11.

2. Why Do We Need Memoization and Tabulation?

Consider the Fibonacci recurrence:

F(n) = F(n-1) + F(n-2)

With ordinary recursion, the same Fibonacci values are calculated repeatedly.

fib(5) ├── fib(4) │ ├── fib(3) │ │ ├── fib(2) │ │ └── fib(1) │ └── fib(2) └── fib(3) ├── fib(2) └── fib(1)

For example, fib(3) and fib(2) are evaluated multiple times.

Dynamic Programming avoids repeated calculations by storing the results of previously solved subproblems.
TechniqueApproach
MemoizationCalculate recursively and store results.
TabulationCalculate iteratively and store results in a table.

3. Memoization – Top-Down Dynamic Programming

Memoization is a technique in which a recursive function stores the result of each solved subproblem in a cache.

Working Procedure

  1. Define the recursive recurrence.
  2. Create a cache array.
  3. Check whether the required result is already stored.
  4. If stored, return the cached result.
  5. Otherwise, calculate the result recursively.
  6. Store the result before returning it.

Example: Fibonacci Using Memoization

We use an array initialized with -1 to indicate that a state has not yet been calculated.

#include <stdio.h> #define MAX_N 90 unsigned long long memo[MAX_N + 1]; unsigned long long fibonacci(int n) { if (n <= 1) return (unsigned long long)n; if (memo[n] != ULLONG_MAX) return memo[n]; memo[n] = fibonacci(n - 1) + fibonacci(n - 2); return memo[n]; } int main(void) { int n; int i; printf("Enter n (0 to 90): "); if (scanf("%d", &n) != 1 || n < 0 || n > MAX_N) { printf("Invalid input.\n"); return 1; } for (i = 0; i <= MAX_N; i++) memo[i] = ULLONG_MAX; printf("Fibonacci(%d) = %llu\n", n, fibonacci(n)); return 0; }
Add #include <limits.h> to this program. The cache uses ULLONG_MAX as its uncomputed marker. The Fibonacci value at n = 94 exceeds the range of unsigned long long, so this lesson deliberately limits n to 90.

Correct Complete Program

#include <stdio.h> #include <limits.h> #define MAX_N 90 unsigned long long memo[MAX_N + 1]; unsigned long long fibonacci(int n) { if (n <= 1) return (unsigned long long)n; if (memo[n] != ULLONG_MAX) return memo[n]; memo[n] = fibonacci(n - 1) + fibonacci(n - 2); return memo[n]; } int main(void) { int n; int i; printf("Enter n (0 to 90): "); if (scanf("%d", &n) != 1 || n < 0 || n > MAX_N) { printf("Invalid input.\n"); return 1; } for (i = 0; i <= MAX_N; i++) memo[i] = ULLONG_MAX; printf("Fibonacci(%d) = %llu\n", n, fibonacci(n)); return 0; }

Expected Output

Enter n (0 to 90): 10 Fibonacci(10) = 55

Complexity Analysis

  • Time Complexity: O(n), because each state is calculated once.
  • Cache Space: O(n).
  • Recursive Call Stack: O(n).

4. Tabulation – Bottom-Up Dynamic Programming

Tabulation solves smaller subproblems first and stores their results in a table. It then uses those results to calculate larger subproblems.

Working Procedure

  1. Create a DP array.
  2. Initialize the base cases.
  3. Start from the smallest subproblem.
  4. Calculate each subsequent state using previously computed states.
  5. Return the required final state.

Example: Fibonacci Using Tabulation

#include <stdio.h> #define MAX_N 90 int main(void) { int n; int i; unsigned long long dp[MAX_N + 1]; printf("Enter n (0 to 90): "); if (scanf("%d", &n) != 1 || n < 0 || n > MAX_N) { printf("Invalid input.\n"); return 1; } dp[0] = 0; if (n >= 1) dp[1] = 1; for (i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2]; printf("Fibonacci(%d) = %llu\n", n, dp[n]); return 0; }

Expected Output

Enter n (0 to 90): 10 Fibonacci(10) = 55

Fibonacci DP Table for n = 7

Index01234567
Value011235813

Each value is calculated using the two previous values.

Complexity Analysis

  • Time Complexity: O(n).
  • Space Complexity: O(n) for the DP array.
  • No recursive call stack is required.

5. Memoization vs Tabulation

FeatureMemoizationTabulation
ApproachTop-downBottom-up
ImplementationUsually recursiveUsually iterative
Starting pointRequired final stateBase states
CalculationOn demandIn dependency order
Call stackUses recursion stackNo recursion stack
StorageCacheDP table
Unneeded statesMay remain uncomputedOften computes all states in its table range
RiskDeep recursionIncorrect iteration order
Both approaches can have the same asymptotic time complexity. Choose based on the problem, state dependencies, memory requirements and recursion depth.

6. Converting Recursion into Memoization

Consider the Fibonacci recurrence:

F(n) = F(n-1) + F(n-2)

Step 1: Write the recursive function

unsigned long long fib(int n) { if (n <= 1) return n; return fib(n - 1) + fib(n - 2); }

Step 2: Introduce a cache

unsigned long long memo[91];

Step 3: Check the cache

if (memo[n] != ULLONG_MAX) return memo[n];

Step 4: Store the calculated result

memo[n] = fib(n - 1) + fib(n - 2); return memo[n];

The recursive structure remains the same, but repeated calculations are eliminated.

7. Converting Recursion into Tabulation

For a bottom-up solution, identify the smallest states and build the result in dependency order.

Step 1: Identify the recurrence

dp[n] = dp[n-1] + dp[n-2]

Step 2: Initialize base cases

dp[0] = 0 and dp[1] = 1.

Step 3: Build the table

for (i = 2; i <= n; i++) { dp[i] = dp[i - 1] + dp[i - 2]; }

Step 4: Return the answer

dp[n] contains the required Fibonacci number.

8. Placement Problem: Climbing Stairs

Problem: You are climbing a staircase with n steps. You can climb either one step or two steps at a time. Find the number of distinct ways to reach the top.

Example

For n = 4, the possible sequences are:

  • 1 + 1 + 1 + 1
  • 1 + 1 + 2
  • 1 + 2 + 1
  • 2 + 1 + 1
  • 2 + 2

Answer = 5.

Recurrence

dp[n] = dp[n-1] + dp[n-2]

Base cases: dp[0] = 1 and dp[1] = 1.

Complete C11 Program – Tabulation

#include <stdio.h> #define MAX_N 90 int main(void) { int n; int i; unsigned long long dp[MAX_N + 1]; printf("Enter number of stairs (0 to 90): "); if (scanf("%d", &n) != 1 || n < 0 || n > MAX_N) { printf("Invalid input.\n"); return 1; } dp[0] = 1; if (n >= 1) dp[1] = 1; for (i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2]; printf("Number of ways = %llu\n", dp[n]); return 0; }

Expected Output

Enter number of stairs (0 to 90): 4 Number of ways = 5

Complexity

  • Time: O(n).
  • Space: O(n).
The unsigned long long result can overflow for sufficiently large n. The input limit above is a simple bound for this example, not a universal limit for all DP problems.

9. Placement Problem: Minimum Cost to Climb Stairs

Problem: Each stair has an associated cost. You can start at stair 0 or stair 1. From a stair, you can climb one or two positions. Find the minimum cost to reach beyond the last stair.

For an array cost[], define:

dp[i] = minimum cost required to reach position i.

For positions i from 2 onward:

dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])

Complete C11 Program

#include <stdio.h> #define MAX_N 100 int main(void) { int cost[MAX_N]; long long dp[MAX_N + 1]; int n; int i; printf("Enter number of stairs: "); if (scanf("%d", &n) != 1 || n < 2 || n > MAX_N) { printf("Enter a value from 2 to %d.\n", MAX_N); return 1; } printf("Enter stair costs:\n"); for (i = 0; i < n; i++) { if (scanf("%d", &cost[i]) != 1 || cost[i] < 0) { printf("Invalid cost.\n"); return 1; } } dp[0] = 0; dp[1] = 0; for (i = 2; i <= n; i++) { long long oneStep = dp[i - 1] + cost[i - 1]; long long twoSteps = dp[i - 2] + cost[i - 2]; dp[i] = (oneStep < twoSteps) ? oneStep : twoSteps; } printf("Minimum cost = %lld\n", dp[n]); return 0; }

Expected Output

Enter number of stairs: 3 Enter stair costs: 10 15 20 Minimum cost = 15

The solution uses O(n) time and O(n) auxiliary space. With a rolling-state implementation, the auxiliary space can be reduced to O(1).

10. Space Optimization in Tabulation

Some DP recurrences depend only on a small number of previous states. In such cases, the entire DP array may not be necessary.

Fibonacci – Space Optimized C11 Program

#include <stdio.h> #include <limits.h> #define MAX_N 90 int main(void) { int n; int i; unsigned long long prev2 = 0; unsigned long long prev1 = 1; unsigned long long current; printf("Enter n (0 to 90): "); if (scanf("%d", &n) != 1 || n < 0 || n > MAX_N) { printf("Invalid input.\n"); return 1; } if (n == 0) { printf("Fibonacci(0) = 0\n"); return 0; } for (i = 2; i <= n; i++) { current = prev1 + prev2; prev2 = prev1; prev1 = current; } printf("Fibonacci(%d) = %llu\n", n, prev1); return 0; }

Expected Output

Enter n (0 to 90): 10 Fibonacci(10) = 55

Recursive FibonacciO(2^n)O(n) stack
MemoizationO(n)O(n) cache + stack
TabulationO(n)O(n) table
Space optimizedO(n)O(1)

11. DP Initialization and Cache Design

Correct initialization is essential because the DP algorithm depends on knowing whether a state has already been computed.

Method 1: Sentinel Value

int memo[100]; for (int i = 0; i < 100; i++) memo[i] = -1;

This is useful when every valid answer is guaranteed to be non-negative.

Method 2: Separate Visited Array

int memo[100]; int visited[100] = {0}; if (visited[n]) return memo[n]; memo[n] = calculate(n); visited[n] = 1;

This method is useful when -1 or another sentinel could itself be a valid answer.

Method 3: Zero Initialization

Zero initialization is suitable only when zero cannot be confused with a valid but not-yet-computed result.

Do not automatically initialize every DP array to zero. First decide what each state means and how an uncomputed state will be represented.

12. Understanding DP State Dependencies

Tabulation must calculate states in an order that ensures all dependencies are already available.

Fibonacci Dependencies

dp[i] depends on: dp[i - 1] dp[i - 2]

Therefore, calculate states from smaller indices to larger indices.

0/1 Knapsack Dependencies

A typical two-dimensional recurrence is:

dp[i][w] = max(dp[i-1][w], value[i-1] + dp[i-1][w-weight[i-1]])

Here, row i depends on row i-1. The item count and capacity dimensions must be initialized and iterated consistently.

Grid DP Dependencies

If a cell depends on the cell above and the cell to its left, a common valid traversal is top-to-bottom and left-to-right.

Before writing tabulation code, draw the dependency relationships. This helps determine the correct loop order and avoid reading uninitialized states.

13. Common Dynamic Programming Mistakes

  1. Incorrectly defining the DP state.
  2. Forgetting base cases.
  3. Using an incorrect recurrence relation.
  4. Reading a DP state before initializing it.
  5. Choosing the wrong iteration order.
  6. Using a sentinel that can also be a valid answer.
  7. Confusing the number of ways with minimum or maximum cost.
  8. Ignoring integer overflow.
  9. Assuming memoization eliminates recursion stack usage.
  10. Optimizing space before confirming the recurrence is correct.

14. Interview Questions and Answers

Q1. What is memoization?

Memoization is a top-down DP technique that stores results of recursive subproblems to avoid recalculating them.

Q2. What is tabulation?

Tabulation is a bottom-up DP technique that iteratively computes and stores subproblem results in a table.

Q3. What is the main difference between memoization and tabulation?

Memoization starts with the required state and solves dependencies recursively. Tabulation starts from base states and builds toward the required state.

Q4. Which approach avoids recursion stack overhead?

Tabulation normally avoids recursion stack overhead because it uses iteration.

Q5. Can memoization and tabulation have the same time complexity?

Yes. Both can solve the same set of states in O(n) time for Fibonacci.

Q6. What is a DP state?

A DP state represents a subproblem whose answer is stored and reused.

Q7. What is a base case?

A base case is a state whose answer is directly known and does not require further decomposition.

Q8. What is space optimization?

Space optimization reduces memory usage by retaining only the previous states needed to calculate the next state.

Q9. Does memoization always calculate every possible state?

No. It calculates only the states reached during the recursive execution.

Q10. Why is iteration order important in tabulation?

Because every state must be calculated only after the states it depends on have been computed.

17. Lesson Summary

  • Memoization is top-down dynamic programming.
  • Tabulation is bottom-up dynamic programming.
  • Both techniques store subproblem results.
  • Memoization uses recursion and a cache.
  • Tabulation uses iteration and a DP table.
  • Correct state definition, base cases and recurrence are essential.
  • Space optimization can reduce memory usage when only a few previous states are required.
