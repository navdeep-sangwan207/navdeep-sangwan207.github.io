Chapter 13 – Lesson 06

One-Dimensional Dynamic Programming

Learn how to solve placement-oriented problems using a one-dimensional DP array and optimized state transitions.

1. Learning Objectives

  • Understand one-dimensional DP states and transitions.
  • Identify overlapping subproblems in array and sequence problems.
  • Design DP arrays and initialize base cases correctly.
  • Solve minimum coin change and coin combination problems.
  • Solve the Decode Ways problem.
  • Understand maximum product subarray using two DP states.
  • Optimize DP space where previous states are sufficient.
  • Analyze time and space complexity for coding interviews.

2. What Is One-Dimensional Dynamic Programming?

One-dimensional Dynamic Programming stores the answers to subproblems in a single-dimensional array, commonly named dp[].

Each index represents a state. The value stored at that index represents the answer to a smaller problem.

General Form

dp[i] = result calculated using previous DP states

For example, a recurrence might depend on the previous one or two states:

dp[i] = dp[i - 1] + dp[i - 2];

Typical One-Dimensional DP Workflow

  1. Define what dp[i] represents.
  2. Identify the smaller states needed to solve state i.
  3. Write the recurrence relation.
  4. Initialize the base cases.
  5. Choose a valid iteration order.
  6. Return the required state or aggregate result.
A one-dimensional DP array does not necessarily mean the problem has only one variable. It means the chosen state representation can be stored using one array dimension.

3. Recognizing One-Dimensional DP Problems

Look for these characteristics in coding-round questions:

  • The problem asks for the minimum or maximum cost.
  • The problem asks for the number of ways to reach a target.
  • The current answer depends on previously solved prefixes.
  • There are repeated calculations in a recursive solution.
  • The input is a sequence, array, string or numeric target.

4. Problem 1 – Minimum Coin Change

Problem: Given coin denominations and a target amount, find the minimum number of coins required to make that amount. Each denomination can be used unlimited times.

Example

Coins = {1, 2, 5}, Amount = 11

One optimal solution is:

5 + 5 + 1 = 11

Minimum number of coins = 3.

DP State

dp[x] represents the minimum number of coins required to make amount x.

Base Case

dp[0] = 0, because zero coins are needed to make amount zero.

Transition

For every coin that does not exceed the current amount:

dp[x] = min(dp[x], dp[x - coin] + 1);

Initialize other states to an unreachable value such as amount + 1.

Dry Run

Coins = {1, 2, 5}, Amount = 11.

Complete C11 Program

#include <stdio.h> #include <stdlib.h> #define MAX_COINS 100 #define MAX_AMOUNT 100000 int minCoinChange(const int coins[], int n, int amount) { int *dp; int i, j; int answer; if (amount < 0 || amount > MAX_AMOUNT) return -1; dp = malloc(((size_t)amount + 1) * sizeof(*dp)); if (dp == NULL) return -1; for (i = 0; i <= amount; i++) dp[i] = amount + 1; dp[0] = 0; for (i = 1; i <= amount; i++) { for (j = 0; j < n; j++) { if (coins[j] > 0 && coins[j] <= i) { int candidate = dp[i - coins[j]] + 1; if (candidate < dp[i]) dp[i] = candidate; } } } answer = (dp[amount] > amount) ? -1 : dp[amount]; free(dp); return answer; } int main(void) { int coins[] = {1, 2, 5}; int n = (int)(sizeof(coins) / sizeof(coins[0])); int amount = 11; int result; result = minCoinChange(coins, n, amount); if (result == -1) printf("Amount cannot be formed or an error occurred.\n"); else printf("Minimum coins required = %d\n", result); return 0; }

Expected Output

Minimum coins required = 3

Complexity Analysis

  • Time Complexity: O(amount × number of denominations).
  • Space Complexity: O(amount).
The function uses -1 for both an unreachable amount and an allocation or input error. A production API should use a separate status return and output parameter to distinguish these cases.

5. Problem 2 – Coin Change: Count Combinations

Problem: Given coin denominations and a target amount, count the number of different combinations that make the target. Each denomination can be used unlimited times.

Order does not matter. For example, 1 + 2 and 2 + 1 represent the same combination.

Example

Coins = {1, 2, 5}, Amount = 5.

Combinations:

  • 1 + 1 + 1 + 1 + 1
  • 1 + 1 + 1 + 2
  • 1 + 2 + 2
  • 5

Answer = 4.

DP State

dp[x] stores the number of combinations that form amount x using the denominations processed so far.

Initialization

dp[0] = 1;

There is exactly one way to make amount zero: choose no coins.

Transition

for each coin: for amount from coin to target: dp[amount] += dp[amount - coin];
The outer loop over coins prevents different orders of the same combination from being counted separately. The inner loop moves forward because each denomination can be reused unlimited times.

Complete C11 Program

#include <stdio.h> #include <stdlib.h> #define MAX_COINS 100 #define MAX_AMOUNT 100000 int main(void) { int coins[] = {1, 2, 5}; int n = (int)(sizeof(coins) / sizeof(coins[0])); int amount = 5; unsigned long long *dp; int i, j; if (amount < 0 || amount > MAX_AMOUNT) { printf("Invalid amount.\n"); return 1; } for (i = 0; i < n; i++) { if (coins[i] <= 0) { printf("Invalid coin denomination.\n"); return 1; } } dp = calloc((size_t)amount + 1, sizeof(*dp)); if (dp == NULL) { printf("Memory allocation failed.\n"); return 1; } dp[0] = 1; for (i = 0; i < n; i++) { for (j = coins[i]; j <= amount; j++) { if (ULLONG_MAX - dp[j] < dp[j - coins[i]]) { printf("Combination count overflow.\n"); free(dp); return 1; } dp[j] += dp[j - coins[i]]; } } printf("Number of combinations = %llu\n", dp[amount]); free(dp); return 0; }

Add #include <limits.h> to this program for ULLONG_MAX.

Expected Output

Number of combinations = 4

Complexity

  • Time: O(number of coins × amount).
  • Space: O(amount).

6. Problem 3 – Decode Ways

Problem: A message containing digits can be decoded using the mapping:

1 -> A 2 -> B ... 26 -> Z

Given a digit string, count the number of valid ways to decode it.

Example

Input: "226"

Possible decodings:

  • 2, 2, 6 → BBF
  • 22, 6 → VF
  • 2, 26 → BZ

Answer = 3.

DP State

dp[i] represents the number of ways to decode the first i characters.

Base Case

dp[0] = 1, representing one way to decode an empty prefix for recurrence purposes.

Transitions

  • If the current digit is not zero, add dp[i-1].
  • If the last two digits form a number from 10 to 26, add dp[i-2].

Complete C11 Program

#include <stdio.h> #include <string.h> #include <limits.h> #define MAX_LENGTH 1000 int main(void) { char s[MAX_LENGTH + 1]; unsigned long long *dp; size_t n, i; int overflow = 0; printf("Enter digit string: "); if (scanf("%1000s", s) != 1) { printf("Input error.\n"); return 1; } n = strlen(s); for (i = 0; i < n; i++) { if (s[i] < '0' || s[i] > '9') { printf("Invalid input: digits only.\n"); return 1; } } dp = calloc(n + 1, sizeof(*dp)); if (dp == NULL) { printf("Memory allocation failed.\n"); return 1; } dp[0] = 1; for (i = 1; i <= n; i++) { if (s[i - 1] != '0') { if (ULLONG_MAX - dp[i] < dp[i - 1]) { overflow = 1; break; } dp[i] += dp[i - 1]; } if (i >= 2) { int twoDigit = (s[i - 2] - '0') * 10 + (s[i - 1] - '0'); if (twoDigit >= 10 && twoDigit <= 26) { if (ULLONG_MAX - dp[i] < dp[i - 2]) { overflow = 1; break; } dp[i] += dp[i - 2]; } } } if (overflow) printf("Decoding count exceeds unsigned long long range.\n"); else printf("Number of decoding ways = %llu\n", dp[n]); free(dp); return 0; }

7. Problem 4 – Maximum Product Subarray

Problem: Given an integer array, find the contiguous subarray with the maximum product and return that product.

Example

Array = {2, 3, -2, 4}

Maximum product subarray = {2, 3}

Answer = 6.

Why Do We Need Two DP States?

A negative number can change the sign of a product. Therefore, the smallest product ending at the previous position may become the largest product after multiplication by a negative number.

Maintain:

  • maxEnding: maximum product of a subarray ending at the current position.
  • minEnding: minimum product of a subarray ending at the current position.

Transition

For current value x, consider:

x x * previousMax x * previousMin

Then update both maximum and minimum ending products.

Complete C11 Program

#include <stdio.h> #include <limits.h> #define MAX_N 100000 int main(void) { int arr[MAX_N]; int n, i; long long maxEnding; long long minEnding; long long answer; printf("Enter number of elements: "); if (scanf("%d", &n) != 1 || n <= 0 || n > MAX_N) { printf("Invalid array size.\n"); return 1; } printf("Enter array elements:\n"); for (i = 0; i < n; i++) { if (scanf("%d", &arr[i]) != 1) { printf("Invalid input.\n"); return 1; } } maxEnding = arr[0]; minEnding = arr[0]; answer = arr[0]; for (i = 1; i < n; i++) { long long x = arr[i]; long long candidate1 = x; long long candidate2; long long candidate3; long long newMax; long long newMin; if (maxEnding != 0 && (maxEnding > LLONG_MAX / x || maxEnding < LLONG_MIN / x)) { if (x != 0) { printf("Product exceeds supported range.\n"); return 1; } } candidate2 = maxEnding * x; if (minEnding != 0 && x != 0) { if ((x > 0 && minEnding < LLONG_MIN / x) || (x < 0 && minEnding < LLONG_MAX / x)) { printf("Product exceeds supported range.\n"); return 1; } } candidate3 = minEnding * x; newMax = candidate1; if (candidate2 > newMax) newMax = candidate2; if (candidate3 > newMax) newMax = candidate3; newMin = candidate1; if (candidate2 < newMin) newMin = candidate2; if (candidate3 < newMin) newMin = candidate3; maxEnding = newMax; minEnding = newMin; if (maxEnding > answer) answer = maxEnding; } printf("Maximum product subarray = %lld\n", answer); return 0; }
The multiplication checks in the illustrative program are not a complete portable checked-arithmetic implementation for every signed integer boundary case. For interview constraints where products are guaranteed to fit in long long, the usual three-candidate transition is sufficient. If arbitrary full-range integer inputs must be supported, use a carefully verified checked-multiplication helper before multiplying.

  • Time: O(n).
  • Auxiliary Space: O(1).

8. Loop Direction in One-Dimensional DP

Loop direction can change the meaning of a DP solution. This is especially important when an item or denomination can be used either once or multiple times.

Unlimited Use – Coin Change Combinations

for (int coinIndex = 0; coinIndex < n; coinIndex++) { for (int amount = coins[coinIndex]; amount <= target; amount++) { dp[amount] += dp[amount - coins[coinIndex]]; } }

Single Use – 0/1 Knapsack-Style Transition

for (int item = 0; item < n; item++) { for (int capacity = target; capacity >= weight[item]; capacity--) { dp[capacity] = max( dp[capacity], dp[capacity - weight[item]] + value[item] ); } }
In 0/1 DP, iterating capacity backward prevents the current item from being reused in the same iteration. In unlimited-use DP, forward iteration allows reuse. The exact loop order depends on the recurrence and state definition.

9. One-Dimensional DP and Space Optimization

ProblemTypical TimeTypical Space
Minimum Coin ChangeO(n × amount)O(amount)
Coin Change CombinationsO(n × amount)O(amount)
Decode WaysO(n)O(n), reducible to O(1)
Maximum Product SubarrayO(n)O(1)

Space optimization is possible when the transition needs only a limited number of previous states. However, it is not always possible to remove the entire DP array.

For example, coin change needs access to many earlier amounts, while maximum product subarray only needs the previous maximum and minimum products.

10. Common Mistakes

  1. Failing to define the meaning of each DP state.
  2. Using incorrect base cases.
  3. Confusing the number of combinations with the number of permutations.
  4. Using the wrong loop direction for 0/1 and unlimited-use problems.
  5. Forgetting that zero is invalid as a standalone decoded digit.
  6. Tracking only the maximum product and ignoring the minimum product.
  7. Using an unreachable-state sentinel without checking its arithmetic.
  8. Ignoring overflow in counts and products.
  9. Returning the wrong DP state for the requested answer.
  10. Optimizing space before validating the full DP recurrence.

11. Interview Questions and Answers

Q1. What is one-dimensional DP?

It is a DP representation in which subproblem answers are stored in a single-dimensional array or an equivalent set of variables.

Q2. What does dp[i] represent?

Its meaning depends on the problem. It may represent a minimum cost, maximum value, number of ways or another subproblem result.

Q3. Why is dp[0] often initialized to 1 in counting problems?

Because there is one way to form a zero target: select nothing. This acts as the starting state for later transitions.

Q4. Why is coin change combination counting different from permutation counting?

Combination counting treats different orders of the same denominations as one result. The coin-outer loop prevents duplicate orderings.

Q5. Why does Decode Ways need a two-digit check?

Because two adjacent digits may represent a single letter from 10 through 26.

Q6. Why does Maximum Product Subarray track minimum and maximum products?

A negative value can turn a previous minimum product into a new maximum product.

Q7. What is the difference between 0/1 and unbounded knapsack?

In 0/1 knapsack each item can be selected at most once. In unbounded knapsack an item may be selected multiple times.

Q8. When can a DP array be reduced to O(1) space?

When each new state depends only on a fixed number of previous states and older states are no longer needed.

Q9. Can a one-dimensional DP problem have multiple state variables?

Yes. For example, maximum product subarray maintains both a maximum and minimum value for the current position.

Q10. What is the most important step in solving a DP problem?

Defining a precise state and deriving a correct recurrence relation.

14. Lesson Summary

  • One-dimensional DP stores subproblem results in a single array.
  • Define the state before writing the recurrence.
  • Minimum Coin Change uses a minimum transition.
  • Coin Change Combinations uses a counting transition.
  • Decode Ways considers valid one-digit and two-digit decodings.
  • Maximum Product Subarray tracks both maximum and minimum ending products.
  • Loop direction determines whether an item can be reused.
  • Space optimization is possible when only a limited number of earlier states are required.
