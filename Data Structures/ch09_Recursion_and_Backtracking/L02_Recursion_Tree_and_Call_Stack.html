Chapter 9 - Lesson 2

Recursion Tree and Call Stack

Data Structures and Algorithms Using C

Placement-Oriented Learning | C11

1. Introduction

When a function calls itself, each call creates a new active function invocation. The program must keep track of the current function's parameters, local variables and return location.

Two important concepts help us understand recursive execution:

  • Call stack: Tracks active function calls.
  • Recursion tree: Represents how recursive calls branch into smaller subproblems.
Placement Importance: Interviewers frequently ask candidates to trace recursive programs, draw recursion trees, identify the maximum recursion depth and calculate time and auxiliary space complexity.

2. What is a Call Stack?

A call stack is a memory structure used by the program execution environment to manage active function calls. It generally follows the Last In, First Out (LIFO) principle.

Each active function call has an associated stack frame.

A Stack Frame Typically Contains

  • Function parameters.
  • Local variables.
  • Return address or equivalent control-flow information.
  • Saved machine state and other implementation-specific data.
A stack frame is an implementation concept. The C language standard does not require every implementation to use a physical stack in exactly the same way.

3. Understanding the Call Stack with Factorial

Consider the following recursive function:

#include <stdio.h>

int factorial(int n)
{
    if (n == 1)
        return 1;

    return n * factorial(n - 1);
}

int main(void)
{
    printf("%d\n", factorial(4));

    return 0;
}

Expected Output

24

Function Calls

factorial(4)
    |
    +--> factorial(3)
              |
              +--> factorial(2)
                        |
                        +--> factorial(1)
                                  |
                                  +--> return 1

Call Stack During Recursive Calls

Stage Active Calls (Bottom to Top)
1 factorial(4)
2 factorial(4), factorial(3)
3 factorial(4), factorial(3), factorial(2)
4 factorial(4), factorial(3), factorial(2), factorial(1)

Stack Unwinding

factorial(1) returns 1
       |
factorial(2) = 2 * 1 = 2
       |
factorial(3) = 3 * 2 = 6
       |
factorial(4) = 4 * 6 = 24
Key Concept: When the base case returns, the most recently called function finishes first. Earlier calls then resume in reverse order.

4. What is Stack Unwinding?

Stack unwinding is the process in which completed function calls return to their callers. As each function returns, its active stack frame is no longer needed.

Consider this program:

#include <stdio.h>

void display(int n)
{
    if (n == 0)
        return;

    printf("Entering %d\n", n);

    display(n - 1);

    printf("Returning %d\n", n);
}

int main(void)
{
    display(3);

    return 0;
}

Expected Output

Entering 3
Entering 2
Entering 1
Returning 1
Returning 2
Returning 3

Explanation

  1. display(3) prints Entering 3.
  2. It calls display(2).
  3. display(2) prints Entering 2.
  4. It calls display(1).
  5. display(1) prints Entering 1.
  6. display(0) reaches the base case and returns.
  7. The pending calls print their returning messages.

5. What is a Recursion Tree?

A recursion tree is a visual representation of the recursive calls made by an algorithm.

Each node represents a function call or subproblem. Its children represent the recursive calls made by that function.

Recursion trees are especially useful for analyzing algorithms that make multiple recursive calls, such as Fibonacci, Merge Sort and divide-and-conquer algorithms.

6. Recursion Tree Example: Fibonacci

The Fibonacci sequence is defined as:

fib(n) = fib(n - 1) + fib(n - 2)

Base cases: fib(0) = 0 and fib(1) = 1

Complete C11 Program

#include <stdio.h>

int fibonacci(int n)
{
    if (n == 0)
        return 0;

    if (n == 1)
        return 1;

    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main(void)
{
    int n = 5;

    printf("Fibonacci(%d) = %d\n", n, fibonacci(n));

    return 0;
}

Expected Output

Fibonacci(5) = 5

Recursion Tree for fibonacci(4)

                         fib(4)
                       /        \
                  fib(3)        fib(2)
                 /     \        /    \
             fib(2)  fib(1)  fib(1) fib(0)
             /   \
         fib(1) fib(0)

Number of Function Calls

Function Number of Calls
fib(4) 1
fib(3) 1
fib(2) 2
fib(1) 3
fib(0) 2
Total 9 calls

Complexity Analysis

  • Time Complexity: O(2n) as a simple upper bound.
  • Auxiliary Space Complexity: O(n), due to maximum recursion depth.
This simple recursive Fibonacci implementation repeats many calculations. It is useful for understanding recursion trees, but it is not an efficient way to calculate large Fibonacci numbers.

7. Linear Recursion vs Multiple Recursion

Linear Recursion Multiple Recursion
Each call makes at most one recursive call. A call may make two or more recursive calls.
Often forms a chain of calls. Often forms a branching recursion tree.
Example: Factorial. Example: Naive Fibonacci.
Factorial time complexity: O(n). Naive Fibonacci time complexity: O(2n) upper bound.

8. Recursion Depth

Recursion depth is the maximum number of simultaneously active recursive function calls during execution.

For example, consider:

void count(int n)
{
    if (n == 0)
        return;

    count(n - 1);
}

For an initial input of n, the function makes calls for n, n-1, ..., 1 and 0. Therefore, the maximum number of active calls is n + 1.

Auxiliary Space Complexity: O(n)

Factors Affecting Recursion Depth

  • Input size.
  • Recursive reduction step.
  • Number of recursive branches.
  • Available stack resources and implementation details.

9. Tail Recursion

A recursive function is tail-recursive when its recursive call is the final operation performed by that function.

Example

#include <stdio.h>

void printNumbers(int n)
{
    if (n == 0)
        return;

    printf("%d ", n);

    printNumbers(n - 1);
}

int main(void)
{
    printNumbers(5);

    return 0;
}

Expected Output

5 4 3 2 1

The recursive call is the final operation in the function. There is no additional calculation after it returns.

C11 does not guarantee tail-call optimization. A tail-recursive function may still consume stack space proportional to its recursion depth.

10. Recursion Tree and Call Stack in Binary Search

Recursive binary search divides the search interval into approximately half at every step.

Complete C11 Program

#include <stdio.h>

int binarySearch(const int arr[], int low, int high, int key)
{
    if (low > high)
        return -1;

    int mid = low + (high - low) / 2;

    if (arr[mid] == key)
        return mid;

    if (key < arr[mid])
        return binarySearch(arr, low, mid - 1, key);

    return binarySearch(arr, mid + 1, high, key);
}

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50, 60, 70};
    int n = (int)(sizeof(arr) / sizeof(arr[0]));
    int key = 60;

    int result = binarySearch(arr, 0, n - 1, key);

    if (result != -1)
        printf("Element found at index %d\n", result);
    else
        printf("Element not found\n");

    return 0;
}

Expected Output

Element found at index 5

Call Sequence

binarySearch(0, 6)
       |
       +-- mid = 3, arr[3] = 40
                    |
                    +-- Search right half
                              |
                       binarySearch(4, 6)
                              |
                       mid = 5, arr[5] = 60
                              |
                         Element found

Complexity Analysis

  • Time Complexity: O(log n).
  • Auxiliary Space Complexity: O(log n).
Binary search requires a sorted array. Its recursive depth grows logarithmically because the search interval is approximately halved at each call.

11. Complexity Comparison of Recursive Algorithms

Algorithm Time Complexity Auxiliary Space
Factorial O(n) O(n)
Sum of n natural numbers O(n) O(n)
Linear recursive traversal O(n) O(n)
Recursive binary search O(log n) O(log n)
Naive Fibonacci O(2n) upper bound O(n)

12. Placement Interview Questions and Answers

Q1. What is a call stack?

It is the mechanism generally used to manage active function calls and their execution state.

Q2. What is a stack frame?

A stack frame contains the information needed to manage an active function invocation, such as parameters, local variables and return information.

Q3. What is stack unwinding?

It is the process of returning from completed function calls and resuming their callers.

Q4. What is a recursion tree?

It is a tree representation of the recursive calls generated by an algorithm.

Q5. What is recursion depth?

It is the maximum number of simultaneously active recursive calls.

Q6. Why is naive Fibonacci inefficient?

It repeatedly computes the same Fibonacci values, resulting in exponential time complexity.

Q7. What is tail recursion?

Tail recursion occurs when the recursive call is the final operation of the function.

Q8. Does C guarantee tail-call optimization?

No. The C standard does not require implementations to perform tail-call optimization.

Q9. What is the auxiliary space of recursive binary search?

O(log n), because the search interval is halved at each recursive call.

Q10. What can cause stack overflow?

Excessive recursion depth, infinite recursion or unusually large stack-frame requirements can exhaust available stack resources.

14. Multiple Choice Questions

Q1. Which principle does the call stack follow?

A. FIFO

B. LIFO

C. Random access

D. Priority order

Answer: B. LIFO

Q2. What happens when a recursive base case returns?

A. The oldest call returns first.

B. The most recent active call returns to its caller.

C. All calls are removed at once.

D. The program always exits.

Answer: B

Q3. Which representation is useful for analyzing multiple recursive calls?

A. Queue

B. Hash table

C. Recursion tree

D. Linked list only

Answer: C. Recursion tree

Q4. What is the maximum recursion depth of factorial(n)?

A. O(1)

B. O(log n)

C. O(n)

D. O(n²)

Answer: C. O(n)

Q5. What is the time complexity of naive recursive Fibonacci?

A. O(1)

B. O(log n)

C. O(n)

D. O(2n) as an upper bound

Answer: D

Q6. Which algorithm has logarithmic recursion depth?

A. Factorial

B. Recursive binary search

C. Linear recursive traversal

D. Recursive sum

Answer: B. Recursive binary search

Q7. Does C11 guarantee tail-call optimization?

A. Yes

B. No

C. Only for void functions

D. Only for integer functions

Answer: B. No

15. Lesson Summary

  • The call stack manages active function calls.
  • Each active function invocation has an associated execution state.
  • Stack unwinding occurs when recursive calls return.
  • A recursion tree represents branching recursive calls.
  • Recursion depth determines maximum active call depth.
  • Naive Fibonacci repeats calculations.
  • Tail recursion does not guarantee stack optimization in C11.
  • Recursive binary search has logarithmic depth.
