2. What Is Recursion?

Recursion is a programming technique in which a function calls itself to solve a problem by reducing it into smaller instances of the same problem.

A recursive function continues calling itself until it reaches a condition that stops further recursive calls.

Simple Example

#include <stdio.h>

void display(void)
{
    printf("Hello\n");
    display();
}

int main(void)
{
    display();
    return 0;
}

This function calls itself repeatedly.

Important: The above program has no stopping condition. It will continue making recursive calls until the program exhausts available call-stack resources. It is an illustration of recursion, not a safe program to execute.

3. Recursive Function Structure

A well-designed recursive function generally has two important parts:

1. Base Case

The base case is the stopping condition. It prevents the function from making further recursive calls.

2. Recursive Case

The recursive case reduces the problem and calls the same function with a smaller or simpler input.

General Structure in C

return_type function_name(parameters)
{
    if (base_condition) {
        return base_result;
    }

    return function_name(smaller_input);
}
Remember: Every recursive path must eventually reach a base case. A base case alone is not sufficient if the recursive input does not make progress toward it.

4. First Recursive Program – Countdown

Display numbers from n down to 1 using recursion.

Complete C11 Program

#include <stdio.h>

void countdown(int n)
{
    if (n == 0) {
        return;
    }

    printf("%d\n", n);

    countdown(n - 1);
}

int main(void)
{
    int n = 5;

    countdown(n);

    return 0;
}

Expected Output

5
4
3
2
1

Explanation

  • Initially, countdown(5) is called.
  • It prints 5 and calls countdown(4).
  • It prints 4 and calls countdown(3).
  • This continues until countdown(0).
  • At n == 0, the function returns without another recursive call.

5. How Recursive Calls Work

Consider this program:

#include <stdio.h>

void fun(int n)
{
    if (n == 0) {
        return;
    }

    printf("%d ", n);

    fun(n - 1);
}

int main(void)
{
    fun(3);
    return 0;
}

Call Sequence

fun(3)
   |
   v
fun(2)
   |
   v
fun(1)
   |
   v
fun(0)
   |
   v
return

Expected output:

3 2 1

Each call creates a new active function invocation with its own parameters and automatic local variables.

6. What Is the Function Call Stack?

The call stack is a runtime mechanism used to manage active function calls. When a function calls another function, information needed to resume the earlier function is retained.

A typical stack frame contains information such as:

  • Function parameters.
  • Automatic local variables.
  • Return information.
  • Other implementation-specific execution state.

When a function call is made, a new activation record is created. When that function returns, its activation record is removed.

Example: fun(3)

While fun(0) is executing, the active calls conceptually look like this:

        TOP
     +---------+
     | fun(0)  |
     +---------+
     | fun(1)  |
     +---------+
     | fun(2)  |
     +---------+
     | fun(3)  |
     +---------+
        BOTTOM

The most recently called function is at the top of the conceptual call stack.

Key concept: Function calls follow LIFO behaviour (Last In, First Out). The most recent active call returns first.

8. Recursion – Call Phase and Return Phase

Recursive execution can be understood in two phases.

Phase What Happens?
Calling phase Functions call themselves with smaller inputs.
Returning phase Functions resume execution after their recursive calls return.

Example

#include <stdio.h>

void print_numbers(int n)
{
    if (n == 0) {
        return;
    }

    printf("Call: %d\n", n);

    print_numbers(n - 1);

    printf("Return: %d\n", n);
}

int main(void)
{
    print_numbers(3);
    return 0;
}

Expected Output

Call: 3
Call: 2
Call: 1
Return: 1
Return: 2
Return: 3

9. Factorial Using Recursion

The factorial of a positive integer n is the product of all positive integers from 1 through n.

Mathematical definition:

n! = n × (n - 1)!

0! = 1

Recursive Logic

factorial(5)
    = 5 × factorial(4)
    = 5 × 4 × factorial(3)
    = 5 × 4 × 3 × factorial(2)
    = 5 × 4 × 3 × 2 × factorial(1)
    = 5 × 4 × 3 × 2 × 1
    = 120

Complete C11 Program

#include <stdio.h>

unsigned long long factorial(unsigned int n)
{
    if (n == 0 || n == 1) {
        return 1;
    }

    return n * factorial(n - 1);
}

int main(void)
{
    unsigned int n = 5;

    printf("Factorial of %u = %llu\n",
           n, factorial(n));

    return 0;
}

Expected Output

Factorial of 5 = 120

Complexity Analysis

  • Time complexity: O(n)
  • Auxiliary call-stack space: O(n)
The factorial value grows rapidly. For an unsigned long long result, the largest generally representable factorial is 20! on systems providing a 64-bit unsigned long long. This demonstration uses n = 5.

10. Sum of First N Natural Numbers Using Recursion

Find the sum:

1 + 2 + 3 + ... + n

Recursive Formula

sum(n) = n + sum(n - 1)

sum(0) = 0

Complete C11 Program

#include <stdio.h>

long long sum_n(int n)
{
    if (n == 0) {
        return 0;
    }

    return n + sum_n(n - 1);
}

int main(void)
{
    int n = 5;

    printf("Sum = %lld\n", sum_n(n));

    return 0;
}

Expected Output

Sum = 15

Complexity

  • Time: O(n)
  • Auxiliary space: O(n)

11. Direct Recursion and Indirect Recursion

Direct Recursion

A function directly calls itself.

void fun(int n)
{
    if (n == 0) {
        return;
    }

    fun(n - 1);
}

Indirect Recursion

Two or more functions call one another in a cycle.

#include <stdio.h>

void functionB(int n);

void functionA(int n)
{
    if (n <= 0) {
        return;
    }

    printf("A: %d\n", n);

    functionB(n - 1);
}

void functionB(int n)
{
    if (n <= 0) {
        return;
    }

    printf("B: %d\n", n);

    functionA(n - 1);
}

int main(void)
{
    functionA(4);
    return 0;
}

Expected Output

A: 4
B: 3
A: 2
B: 1
Direct RecursionIndirect Recursion
A function calls itself.Functions call one another.
One function is sufficient.Two or more functions participate.
Example: factorial.Example: functionA and functionB.

12. Tail Recursion and Non-Tail Recursion

Tail Recursion

A recursive call is in tail position when it is the final operation performed by the function before returning. 

void print_down(int n)
{
    if (n == 0) {
        return;
    }

    printf("%d ", n);

    print_down(n - 1);
}

Non-Tail Recursion

A function is non-tail recursive when it has work remaining after the recursive call returns. 

int factorial(int n)
{
    if (n == 0) {
        return 1;
    }

    return n * factorial(n - 1);
}

The multiplication happens after the recursive call returns.

Tail RecursionNon-Tail Recursion
Recursive call is the final operation.Additional work remains after the call.
May be suitable for tail-call optimization.Generally requires pending work on return.
Example: print_down().Example: factorial().
C11 does not guarantee tail-call optimization. Do not assume that tail-recursive code automatically uses constant stack space.

13. Recursion vs Iteration

Many problems can be solved using either recursion or loops.

Feature Recursion Iteration
Execution Function calls itself Uses loops
Termination Base case Loop condition
Memory Uses call-stack space Often O(1) auxiliary space
Code structure Can be concise for recursive problems Often straightforward for repetition
Risk Stack overflow Infinite loop

Factorial Using Iteration

#include <stdio.h>

unsigned long long factorial(int n)
{
    unsigned long long result = 1;

    for (int i = 2; i <= n; i++) {
        result *= (unsigned long long)i;
    }

    return result;
}

int main(void)
{
    int n = 5;

    printf("Factorial = %llu\n", factorial(n));

    return 0;
}

Expected Output

Factorial = 120

Both recursive and iterative versions take O(n) time for factorial. The iterative version uses O(1) auxiliary space, while the recursive version uses O(n) call-stack space.

14. What Is Stack Overflow in Recursion?

Stack overflow occurs when a program requires more call-stack space than the available runtime resources provide.

Common causes include:

  • Missing base case.
  • Incorrect base condition.
  • Recursive calls that do not reduce the problem.
  • Very deep recursion.
  • Large automatic local variables in recursive functions.

Incorrect Recursive Function

void fun(int n)
{
    if (n == 0) {
        return;
    }

    fun(n);
}

The input never changes, so the function never approaches its base case when called with a nonzero value.

Corrected Function

void fun(int n)
{
    if (n == 0) {
        return;
    }

    fun(n - 1);
}
Always verify that each recursive call makes measurable progress toward a terminating condition.

15. How to Trace a Recursive Program in an Interview

Use this systematic approach:

  1. Identify the initial function call.
  2. Write down the argument values for every recursive call.
  3. Identify the base case.
  4. Trace when the function starts returning.
  5. Record operations performed after recursive calls.
  6. Determine the final return value or printed output.

Practice Program

#include <stdio.h>

int fun(int n)
{
    if (n == 1) {
        return 1;
    }

    return n + fun(n - 1);
}

int main(void)
{
    printf("%d\n", fun(4));
    return 0;
}

Dry Run

fun(4)
= 4 + fun(3)
= 4 + 3 + fun(2)
= 4 + 3 + 2 + fun(1)
= 4 + 3 + 2 + 1
= 10

Expected Output

10

17. Common Mistakes

  1. Forgetting to write a base case.
  2. Writing a base condition that is never reached.
  3. Not reducing the recursive input.
  4. Confusing the calling phase with the returning phase.
  5. Assuming every recursive function is automatically efficient.
  6. Ignoring call-stack memory usage.
  7. Assuming C guarantees tail-call optimization.
  8. Ignoring integer overflow in recursive calculations.

18. Placement Interview Questions and Answers

Q1. What is recursion?

Answer: Recursion is a programming technique in which a function calls itself to solve smaller instances of a problem.

Q2. What are the two essential components of recursion?

Answer: A base case that terminates recursion and a recursive case that reduces the problem.

Q3. What is a call stack?

Answer: It is a runtime structure that manages active function calls and retains the information required to resume them.

Q4. What is a stack frame?

Answer: A stack frame is the runtime information associated with a particular active function invocation, including parameters, automatic local variables and return information.

Q5. What is direct recursion?

Answer: Direct recursion occurs when a function calls itself directly.

Q6. What is indirect recursion?

Answer: Indirect recursion occurs when two or more functions call one another in a cycle.

Q7. What is tail recursion?

Answer: Tail recursion occurs when the recursive call is the final operation performed by the function.

Q8. What is stack overflow?

Answer: It occurs when a program exceeds available call-stack resources, often due to excessive or non-terminating recursive calls.

Q9. Is recursion always better than iteration?

Answer: No. Recursion can make certain algorithms easier to express, but iteration may use less memory and avoid call-stack exhaustion.

Q10. What is the difference between calling and returning phases?

Answer: During the calling phase, recursive calls are created. During the returning phase, those calls resume and complete their pending operations.

20. Multiple Choice Questions

Q1. Which condition stops a recursive function?

  • A. Loop condition
  • B. Base case
  • C. Pointer
  • D. Function prototype

Answer: B. Base case

Q2. Which data structure manages active recursive function calls?

  • A. Queue
  • B. Stack
  • C. Heap
  • D. Graph

Answer: B. Stack

Q3. Which recursion has the recursive call as its final operation?

  • A. Indirect recursion
  • B. Non-tail recursion
  • C. Tail recursion
  • D. Infinite recursion

Answer: C. Tail recursion

Q4. What is the time complexity of recursive factorial?

  • A. O(1)
  • B. O(log n)
  • C. O(n)
  • D. O(n²)

Answer: C. O(n)

Q5. What happens if recursive calls never reach a base case?

  • A. Binary search
  • B. Stack overflow may occur
  • C. Automatic sorting
  • D. Constant-time execution

Answer: B. Stack overflow may occur

Q6. Which statement about C tail recursion is correct?

  • A. C11 guarantees tail-call optimization.
  • B. Tail recursion always uses O(1) stack space.
  • C. C11 does not guarantee tail-call optimization.
  • D. Tail recursion cannot have a base case.

Answer: C. C11 does not guarantee tail-call optimization.

21. Lesson Summary

  • Recursion allows a function to solve smaller instances of a problem by calling itself.
  • A base case terminates recursive execution.
  • The recursive case must make progress toward the base case.
  • The call stack manages active function invocations.
  • Operations after a recursive call execute during the return phase.
  • Recursion may consume additional call-stack memory.
  • Tail-call optimization is not guaranteed by C11.
  • Understanding recursion is essential before learning backtracking.
Placement readiness check: You should be able to write factorial and sum-of-N recursively, trace the call stack, distinguish tail and non-tail recursion, and explain the time and space complexity of each solution.
