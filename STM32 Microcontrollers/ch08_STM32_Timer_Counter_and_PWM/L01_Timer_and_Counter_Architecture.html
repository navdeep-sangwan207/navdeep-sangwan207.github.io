2. What Is a Timer?

A timer is a hardware peripheral inside a microcontroller that counts clock pulses to measure time or generate events at specified intervals.

Instead of continuously executing software delay loops, a hardware timer can operate independently of the CPU.

Example

Suppose an STM32 application needs to toggle an LED every 1 second. A timer can generate a periodic update event, allowing the firmware to toggle the LED at regular intervals.

3. What Is a Counter?

A counter is a hardware mechanism that counts incoming pulses or events. In STM32 general-purpose timers, the counter register is commonly named CNT.

Counting Example

Consider a timer configured in up-counting mode. Its counter may progress as follows: 


CNT = 0
CNT = 1
CNT = 2
CNT = 3
CNT = 4
CNT = 5
...

When the counter reaches its configured auto-reload limit, an update event can occur and the counter restarts from zero in the usual up-counting configuration.

4. Timer vs Counter

Timer Counter
Commonly counts internal clock pulses. Commonly counts external events or pulses.
Used for time measurement and periodic events. Used for event or pulse counting.
Can generate delays, interrupts and PWM. Can count rotations, objects or external pulses.

A hardware timer can also operate as an event counter. The distinction describes its configuration and application, not necessarily two separate peripherals.

5. STM32 Timer Types

STM32 microcontrollers provide different timer implementations depending on the selected family and device.

5.1 Basic Timers

Basic timers primarily provide time-base functionality and can generate update events. Some devices also support DMA requests from basic timers.

Applications:

  • Periodic time-base generation.
  • Regular interrupt events.
  • Triggering other peripherals where supported.

5.2 General-Purpose Timers

General-purpose timers commonly support several functions:

  • Up, down and center-aligned counting modes.
  • Input capture.
  • Output compare.
  • PWM generation.
  • Timer interrupts.
  • External event counting.

5.3 Advanced-Control Timers

Advanced-control timers provide additional features for applications such as motor control and power electronics.

  • Complementary PWM outputs.
  • Programmable dead-time insertion.
  • Break input and emergency output control.
  • Synchronization features.
  • Advanced PWM modes.

5.4 Low-Power Timers

Low-power timers are available on selected STM32 devices. They can support timing and counting functions in low-power operating conditions, depending on the clock source and device design.

Timer Type Comparison

Timer Type Typical Application
Basic Periodic time-base and trigger generation
General-purpose Input capture, output compare and PWM
Advanced-control Motor control and complementary PWM
Low-power Timing and counting in low-power applications

7. Timer Clock Sources

A timer requires a clock source to advance its counter. Common sources include:

  • Internal peripheral timer clock.
  • External clock input.
  • Internal trigger from another timer or peripheral.
  • External trigger input, where supported.

Internal Timer Clock

In a common STM32 configuration, a timer receives its clock from an APB peripheral clock domain.

On many STM32F4 devices, when the APB prescaler is 1, the timer clock equals the APB clock. When the APB prescaler is greater than 1, the timer clock is commonly twice the APB clock.

Example:

If PCLK1 = 42 MHz and the APB1 prescaler is greater than 1 on a typical STM32F4 configuration:

Timer clock = 2 × 42 MHz = 84 MHz

This timer-clock multiplication rule is not universal. Some STM32 families have selectable timer kernel clocks or different clock-tree arrangements. Verify the actual timer clock in the selected device's reference manual and clock configuration.

8. Timer Counting Modes

8.1 Up-Counting Mode

The counter increments from zero toward the auto-reload value. 


0 -> 1 -> 2 -> 3 -> 4 -> 5 -> ...

When the configured terminal count is reached, an update event can occur and the counter reloads.

8.2 Down-Counting Mode

The counter decrements from the auto-reload value toward zero. 


5 -> 4 -> 3 -> 2 -> 1 -> 0

8.3 Center-Aligned Mode

In center-aligned mode, the counter counts upward and downward between its limits. 


0 -> 1 -> 2 -> 3 -> 4
                    |
4 <- 3 <- 2 <- 1 <- 0

Center-aligned counting is commonly used for PWM applications where symmetrical switching patterns are useful.

9. Timer Counter Resolution

Timer resolution depends on the counter width. Common counter widths include 16 bits and 32 bits.

16-Bit Counter

A 16-bit unsigned counter can represent values from 0 to 65,535.

Maximum number of distinct counter values:

216 = 65,536

32-Bit Counter

A 32-bit unsigned counter can represent values from 0 to 4,294,967,295.

232 = 4,294,967,296

Counter width depends on the particular timer instance and STM32 model. Not every timer on a device has the same counter width.

11. STM32 HAL Timer Initialization Example

STM32 HAL provides timer APIs that simplify configuration and operation.

Example: Start a Basic Timer

#include "main.h"

TIM_HandleTypeDef htim2;

void MX_TIM2_Init(void)
{
    htim2.Instance = TIM2;

    htim2.Init.Prescaler = 8399;
    htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
    htim2.Init.Period = 9999;

    htim2.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
    htim2.Init.AutoReloadPreload =
        TIM_AUTORELOAD_PRELOAD_DISABLE;

    if (HAL_TIM_Base_Init(&htim2) != HAL_OK)
    {
        Error_Handler();
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_TIM2_Init();

    HAL_TIM_Base_Start(&htim2);

    while (1)
    {
        uint32_t count = __HAL_TIM_GET_COUNTER(&htim2);

        (void)count;
    }
}
This is an illustrative STM32F4-style example. The timer clock, peripheral clock enable, HAL configuration and device support must match the selected STM32. Interrupt and PWM operation require their corresponding configuration and start APIs.

13. Placement-Oriented Interview Questions

Q1. What is a timer in a microcontroller?

A timer is a hardware peripheral that counts clock pulses to measure time or generate timed events.

Q2. What is the difference between a timer and a counter?

A timer commonly counts internal clock pulses, whereas a counter commonly counts external events. The same timer peripheral can often perform both roles.

Q3. What is the purpose of the PSC register?

PSC divides the timer input clock to produce the counter clock.

Q4. What is the purpose of the CNT register?

CNT stores the current timer counter value.

Q5. What is the purpose of the ARR register?

ARR defines the auto-reload value used to control the timer counting period.

Q6. What is an update event?

It is a timer event commonly associated with counter overflow or underflow and update operations.

Q7. What are basic timers?

Basic timers primarily provide time-base and update-event functionality.

Q8. What are general-purpose timers?

They provide features such as counting, input capture, output compare and PWM generation.

Q9. What are advanced-control timers?

They provide advanced PWM and motor-control features, including complementary outputs and dead-time insertion on supported devices.

Q10. What is center-aligned counting?

The counter repeatedly counts upward and downward between configured limits.

Q11. What is input capture?

Input capture records the timer counter value when a selected input event occurs.

Q12. What is output compare?

Output compare compares the counter with a programmed compare value and generates an event or output action.

Q13. What is PWM?

Pulse Width Modulation controls the proportion of time a digital output remains active within each period.

Q14. Why are hardware timers preferred over software delays?

Hardware timers provide more predictable timing and can operate without continuously occupying the CPU in delay loops.
