2. What Is a Timer Interrupt?

A timer interrupt is a processor interrupt request generated when a configured timer event occurs and the corresponding interrupt source is enabled.

A timer can generate periodic update events after the counter reaches its configured limit. When update interrupt generation is enabled, the timer can request CPU service.

Example

Suppose an STM32 application must toggle an LED every 500 milliseconds. A timer can generate an update interrupt at a suitable frequency, and the callback can signal the main program to toggle the LED.

4. Requirements for Timer Interrupt Generation

A timer interrupt generally requires the following configuration steps:

  1. Enable the timer peripheral clock.
  2. Configure the timer prescaler and auto-reload value.
  3. Enable the timer update interrupt source.
  4. Configure the corresponding NVIC interrupt.
  5. Start the timer in interrupt mode.
  6. Implement the correct interrupt handler and callback.
Enabling the timer peripheral alone does not automatically enable its update interrupt. The peripheral interrupt source and NVIC must both be configured.

5. Timer Interrupt Registers

Register Purpose
PSC Sets the timer prescaler.
ARR Sets the auto-reload value.
CNT Stores the current counter value.
DIER Enables timer interrupt and DMA request sources.
SR Contains timer status flags, including UIF on common timers.
CR1 Controls timer operation, including counter enable.

Important Bits

  • UIE: Update interrupt enable bit in DIER.
  • UIF: Update interrupt/status flag in SR.
  • CEN: Counter enable bit in CR1.

These names are common in STM32 timer implementations. Verify register availability and flag-clearing behavior for the selected timer.

6. Timer Interrupt Frequency Calculation

For a typical up-counting timer time base:

Update frequency = Timer clock / [(PSC + 1) × (ARR + 1)]

Example: 1 ms Timer Interrupt

Timer clock = 84 MHz

PSC = 83

ARR = 999

Update frequency = 84,000,000 / (84 × 1000)

Update frequency = 1000 Hz

Update period = 1 ms

If the callback is executed once for every update interrupt, it will run approximately 1000 times per second, assuming no interrupt events are suppressed or otherwise affected by configuration.

8. STM32 HAL Timer Interrupt Programming

Step 1: Declare Timer Handle

#include "main.h"

TIM_HandleTypeDef htim2;

volatile uint8_t timer_event = 0;

Step 2: Initialize Timer

void MX_TIM2_Init(void)
{
    htim2.Instance = TIM2;

    htim2.Init.Prescaler = 83;
    htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
    htim2.Init.Period = 999;

    htim2.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;

    htim2.Init.AutoReloadPreload =
        TIM_AUTORELOAD_PRELOAD_DISABLE;

    if (HAL_TIM_Base_Init(&htim2) != HAL_OK)
    {
        Error_Handler();
    }
}

Step 3: Start Timer in Interrupt Mode

HAL_TIM_Base_Start_IT(&htim2);

Step 4: Implement the HAL Callback

void HAL_TIM_PeriodElapsedCallback(
    TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        timer_event = 1;
    }
}

Step 5: Process Event in Main Loop

while (1)
{
    if (timer_event != 0)
    {
        timer_event = 0;

        HAL_GPIO_TogglePin(
            GPIOA,
            GPIO_PIN_5
        );
    }
}
This flag-based example can coalesce multiple timer events into one pending event. If every timer event must be accounted for, use an appropriate counter or queue and protect shared data where necessary.

9. Timer IRQ Handler

The timer IRQ handler is the interrupt service routine associated with the timer's interrupt vector.

Example: TIM2 Interrupt Handler

void TIM2_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim2);
}

The HAL handler processes the timer interrupt condition and dispatches the appropriate callback.

Typical HAL Interrupt Flow


TIM2 Update Event
       |
       v
TIM2_IRQHandler()
       |
       v
HAL_TIM_IRQHandler()
       |
       v
HAL_TIM_PeriodElapsedCallback()
       |
       v
Application Event Handling
When using HAL, let HAL manage the timer interrupt flag according to its driver implementation. Do not independently clear the same flag without understanding the handler's behavior.

10. NVIC Configuration

The Nested Vectored Interrupt Controller (NVIC) controls the enabling, priority and handling of processor interrupts.

HAL Configuration Example

HAL_NVIC_SetPriority(TIM2_IRQn, 2, 0);

HAL_NVIC_EnableIRQ(TIM2_IRQn);

The priority values must be valid for the selected STM32 device and its implemented priority bits.

CMSIS Configuration Example

NVIC_SetPriority(TIM2_IRQn, 2);

NVIC_EnableIRQ(TIM2_IRQn);

11. Practical Project: LED Blinking Using Timer Interrupt

Objective

Generate a periodic timer interrupt and toggle an LED every 500 milliseconds.

Configuration

Parameter Value
Timer TIM2
Timer clock 84 MHz
Prescaler 8399
Auto-reload 4999
Update frequency 2 Hz
Update period 500 ms

Calculation

Counter frequency = 84 MHz / 8400 = 10 kHz

Update frequency = 10,000 / 5000 = 2 Hz

Application Code

volatile uint8_t led_event = 0;

void HAL_TIM_PeriodElapsedCallback(
    TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        led_event = 1;
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_TIM2_Init();

    if (HAL_TIM_Base_Start_IT(&htim2) != HAL_OK)
    {
        Error_Handler();
    }

    while (1)
    {
        if (led_event != 0)
        {
            led_event = 0;

            HAL_GPIO_TogglePin(
                GPIOA,
                GPIO_PIN_5
            );
        }
    }
}
The GPIO pin must be configured as an output. The timer clock must be 84 MHz for these example values. Configure TIM2's NVIC interrupt and interrupt handler as described above. The example assumes the LED is connected to the selected pin.

12. Polling vs Timer Interrupt

Polling Timer Interrupt
CPU repeatedly checks a condition. CPU responds when an interrupt is accepted.
Can waste CPU time in continuous checks. Can allow the CPU to perform other work between events.
Timing depends on polling loop behavior. Hardware timer provides a defined event interval.
Simple for basic applications. Useful for periodic and event-driven applications.

13. Common Timer Interrupt Problems

Problem Possible Cause Solution
Callback not executing Timer interrupt not enabled. Check Start_IT and timer interrupt source.
IRQ handler not reached NVIC disabled or incorrect vector. Check NVIC and IRQ handler name.
Wrong interrupt interval Incorrect timer clock or PSC/ARR. Recalculate using actual timer clock.
Repeated interrupt Interrupt condition not handled correctly. Inspect timer status and HAL dispatch.
LED does not toggle GPIO configuration or application flag issue. Check GPIO output and callback execution.
Unexpected timing Long ISR or higher-priority interrupt activity. Measure execution time and review priorities.

14. Placement-Oriented Interview Questions

Q1. What is a timer interrupt?

It is an interrupt request generated by a timer event when the corresponding interrupt source is enabled.

Q2. What is the purpose of HAL_TIM_Base_Start_IT()?

It starts the timer in interrupt mode.

Q3. What is HAL_TIM_PeriodElapsedCallback()?

It is a HAL callback invoked when the timer's period-elapsed condition is processed.

Q4. What is TIM2_IRQHandler()?

It is the interrupt handler associated with the TIM2 interrupt vector on devices that provide it.

Q5. What is the role of NVIC?

NVIC manages processor interrupt enabling, priorities and interrupt handling.

Q6. Why must both the timer source and NVIC be enabled?

The timer generates the interrupt request, while NVIC controls whether the processor can accept the corresponding interrupt.

Q7. Can a timer generate periodic interrupts?

Yes. The timer can generate repeated update events at a frequency determined by its clock, prescaler and auto-reload value.

Q8. Why should lengthy operations be avoided in callbacks?

Long callback execution increases interrupt latency and can delay other time-critical events.

Q9. What is the difference between Start and Start_IT?

Start enables timer operation without enabling the corresponding HAL interrupt-based operation. Start_IT starts the timer with update interrupt handling enabled.

Q10. How do you debug a timer interrupt?

Inspect timer configuration, update flags, interrupt enable bits, NVIC settings, IRQ handler and callback execution.

16. Lesson Summary

  • Timer update events can generate interrupt requests.
  • Timer interrupt source and NVIC must be configured.
  • HAL_TIM_Base_Start_IT() starts timer interrupt operation.
  • The IRQ handler forwards the interrupt to HAL.
  • HAL callback provides an application-level event hook.
  • Keep interrupt callbacks short and predictable.
  • Use flags or queues to defer application processing.
  • Correct timer clock and PSC/ARR values determine timing.
