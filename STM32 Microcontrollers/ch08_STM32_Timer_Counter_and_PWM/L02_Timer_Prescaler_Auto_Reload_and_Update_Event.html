2. Timer Clock and Counter Operation

An STM32 timer receives a clock from its selected timer clock source. The prescaler divides this clock before it reaches the counter.

The prescaler controls how quickly the counter increments or decrements.

3. Prescaler Register (PSC)

The prescaler divides the timer input clock before it is applied to the counter.

For the common STM32 timer prescaler implementation, the division factor is PSC + 1.

Counter Clock Formula

Counter frequency = Timer clock / (PSC + 1)

Example:

Timer clock = 84 MHz

PSC = 83

Counter frequency = 84,000,000 / (83 + 1)

Counter frequency = 1 MHz

One counter increment therefore takes 1 microsecond.

Prescaler Values

PSC Value Division Factor Counter Frequency for 84 MHz Input
0 1 84 MHz
7 8 10.5 MHz
83 84 1 MHz
839 840 100 kHz
8399 8400 10 kHz
The prescaler register is buffered on many STM32 timers. A newly written prescaler value may take effect after an update event. Initialization and preload behavior should be checked for the selected timer and device.

4. Auto-Reload Register (ARR)

The auto-reload register defines the counter's terminal value in the common up-counting mode.

When the counter reaches the configured limit, an update event is generated under the applicable timer configuration and the counter restarts.

Since the counter includes zero, the number of counter ticks in an up-counting period is ARR + 1.

Counter Period Formula

Counter ticks per period = ARR + 1

5. Timer Update Frequency Formula

The timer update frequency depends on the timer input clock, prescaler and auto-reload value.

Update frequency = Timer clock / [(PSC + 1) × (ARR + 1)]

Update period = 1 / Update frequency

Example 1: Generate a 1 kHz Update Event

Timer clock = 84 MHz

PSC = 83

ARR = 999

Update frequency = 84,000,000 / [84 × 1000]

Update frequency = 1000 Hz

Update period = 1 ms

Example 2: Generate a 1 Hz Update Event

Timer clock = 84 MHz

PSC = 8399

ARR = 9999

Update frequency = 84,000,000 / [8400 × 10000]

Update frequency = 1 Hz

Update period = 1 second

6. Step-by-Step Timer Calculation

Suppose an STM32 timer has an input clock of 72 MHz and you need an update event every 10 ms.

Step 1: Select Counter Frequency

Choose a counter frequency of 10 kHz.

Step 2: Calculate Prescaler

PSC = (Timer clock / Counter frequency) - 1

PSC = (72,000,000 / 10,000) - 1

PSC = 7199

Step 3: Calculate Counter Ticks

Required period = 10 ms = 0.01 seconds.

Counter ticks = 10,000 × 0.01 = 100

Step 4: Calculate ARR

ARR = Counter ticks - 1

ARR = 99

Final Configuration

Parameter Value
Timer clock 72 MHz
PSC 7199
Counter frequency 10 kHz
ARR 99
Update frequency 100 Hz
Update period 10 ms

7. Update Event and Overflow

An update event is a timer event associated with counter overflow or underflow and update operations. Its exact behavior depends on timer configuration.

Typical Up-Counting Sequence


CNT = 0
CNT = 1
CNT = 2
CNT = 3
...
CNT = ARR
    |
    v
Overflow / Update Event
    |
    v
Counter restarts

Update Event Uses

  • Generate periodic interrupts.
  • Update buffered timer registers.
  • Trigger DMA requests where supported and configured.
  • Synchronize timer operations.
  • Provide periodic timing for firmware.
An update event and an update interrupt are not identical. The update event can occur without the CPU executing an ISR. The update interrupt must be enabled separately.

8. Update Interrupt Enable

The timer update interrupt is commonly controlled by the update interrupt enable bit (UIE) in the DIER register.

The update interrupt flag (UIF) in the SR register indicates an update condition on many STM32 timer implementations.

Conceptual Register Configuration


TIMx->DIER |= TIM_DIER_UIE;

This enables the timer's update interrupt source. The corresponding NVIC interrupt must also be configured for the CPU to execute its handler.

9. STM32 HAL Timer Configuration Example

The following example configures a timer to generate a 1 kHz update event using a timer clock of 84 MHz. 

#include "main.h"

TIM_HandleTypeDef htim2;

void MX_TIM2_Init(void)
{
    htim2.Instance = TIM2;

    /* 84 MHz / (83 + 1) = 1 MHz */
    htim2.Init.Prescaler = 83;

    htim2.Init.CounterMode = TIM_COUNTERMODE_UP;

    /* 1 MHz / (999 + 1) = 1 kHz */
    htim2.Init.Period = 999;

    htim2.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;

    htim2.Init.AutoReloadPreload =
        TIM_AUTORELOAD_PRELOAD_DISABLE;

    if (HAL_TIM_Base_Init(&htim2) != HAL_OK)
    {
        Error_Handler();
    }
}

Start Timer Without Interrupt

HAL_TIM_Base_Start(&htim2);

Start Timer With Interrupt

HAL_TIM_Base_Start_IT(&htim2);

Update Callback

void HAL_TIM_PeriodElapsedCallback(
    TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        /* Runs when TIM2 update interrupt is handled */
    }
}
The timer clock must actually be 84 MHz for these values to produce 1 kHz. Configure the peripheral clock, timer interrupt vector and NVIC according to the selected STM32 device.

10. Important Timer Configuration Parameters

Parameter Meaning
Prescaler Divides the timer input clock.
Counter Mode Selects up, down or center-aligned counting.
Period Sets the auto-reload value through ARR.
Clock Division Controls the timer sampling clock division where applicable.
Auto-Reload Preload Controls buffering of ARR updates.

Note that the timer's Clock Division configuration is not the same as the PSC counter-clock division. It is used for timer sampling-clock functions on supported timer implementations.

11. Common Timer Calculation Mistakes

  • Using PSC instead of PSC + 1.
  • Using ARR instead of ARR + 1 for up-counting periods.
  • Assuming PCLK is always equal to the timer clock.
  • Ignoring APB prescaler effects.
  • Using an incorrect timer clock frequency.
  • Forgetting to enable the timer peripheral clock.
  • Confusing an update event with an update interrupt.
  • Ignoring timer counter width and register limits.

12. Placement-Oriented Interview Questions

Q1. What is a prescaler?

A prescaler divides the timer input clock before it reaches the counter.

Q2. What is the PSC + 1 rule?

For the common STM32 timer prescaler, the division factor is the programmed PSC value plus one.

Q3. What is ARR?

ARR is the auto-reload register that defines the counter's terminal value.

Q4. Why do we use ARR + 1 in timer calculations?

In up-counting mode, the counter includes zero and the terminal value, resulting in ARR + 1 ticks.

Q5. What is the timer update frequency formula?

Update frequency = Timer clock / [(PSC + 1) × (ARR + 1)] for the usual up-counting time-base configuration.

Q6. What is an update event?

It is a timer event associated with overflow, underflow and update operations.

Q7. What is the difference between an update event and interrupt?

An update event is generated by the timer. An update interrupt requests CPU service when the interrupt source and NVIC are enabled.

Q8. What is the purpose of the UIF flag?

It indicates a timer update condition on timer implementations that provide this status flag.

Q9. How can you generate a 1-second timer period?

Select PSC and ARR so their combined division produces an update frequency of 1 Hz, while respecting the timer's register limits.

Q10. What happens when ARR is changed?

The effect depends on the auto-reload preload configuration. With preload enabled, the new value generally takes effect at an update event.

14. Lesson Summary

  • PSC divides the timer input clock.
  • The counter frequency is Timer clock / (PSC + 1).
  • ARR defines the counter's auto-reload value.
  • Up-counting periods normally contain ARR + 1 ticks.
  • Update frequency depends on timer clock, PSC and ARR.
  • Update events can occur without CPU interrupt execution.
  • Update interrupt and NVIC configuration are separate steps.
  • Correct timer clock identification is essential for accurate timing.
