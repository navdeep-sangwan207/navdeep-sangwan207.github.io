2. UART Configuration Parameters

UART communication requires the transmitter and receiver to use compatible communication settings. If the configuration does not match, received data may be corrupted or communication may fail.

Parameter Purpose
Baud rate Defines the serial symbol rate.
Word length Defines the configured frame data length.
Parity Provides optional simple error detection.
Stop bits Defines the stop interval at the end of a frame.
Oversampling Controls receiver sampling and baud-rate generation on supported USARTs.
Flow control Can coordinate transmission using RTS/CTS hardware signals.
A common configuration is 115200 baud, 8 data bits, no parity and 1 stop bit (115200, 8-N-1).

3. Baud Rate Fundamentals

Baud rate is the number of symbols transmitted per second. In conventional binary UART signalling, one symbol represents one bit, so the baud rate is numerically equal to the bit rate.

Bit Duration

The duration of one bit is the reciprocal of the bit rate: 

Bit Duration = 1 / Baud Rate

Example: 9600 Baud

Bit Duration = 1 / 9600
             = 0.00010417 seconds
             = 104.17 microseconds

Example: 115200 Baud

Bit Duration = 1 / 115200
             = 8.68 microseconds approximately
At a higher baud rate, each bit occupies less time. The receiver must sample the incoming signal at the correct time to decode the data reliably.

4. UART Baud Rate Generation

An STM32 UART peripheral derives its baud-rate timing from a peripheral kernel clock. The clock source and divider implementation depend on the particular STM32 family and USART instance.

A simplified conceptual relationship is: 

Baud Rate = UART Clock / Baud-Rate Divider

The actual divider formula and register encoding depend on the USART implementation and oversampling mode. Always use the reference manual and the HAL/CubeMX configuration for the selected STM32.

5. Baud Rate Calculation Example

Consider a simplified USART divider example with:

  • USART peripheral clock = 16 MHz
  • Desired baud rate = 9600
Divider = 16,000,000 / 9,600

        = 1666.67 approximately

The hardware must encode a supported divider value. Rounding and the USART's divider format determine the actual baud rate.

Actual Baud Rate and Percentage Error

Baud Error (%) =
((Actual Baud Rate - Desired Baud Rate)
 / Desired Baud Rate) × 100

A small baud-rate error is normally acceptable, but the total mismatch between both communication endpoints must remain within the receiver's timing tolerance.

The simplified divider calculation is useful for understanding the concept. It is not a universal STM32 BRR register formula. Some STM32 USARTs support oversampling by 16 or 8 and use specific divider encoding rules.

6. Oversampling by 16 and 8

Oversampling allows the receiver to sample the incoming signal multiple times within a bit period to determine the data value and improve sampling robustness.

Mode General Description
Oversampling by 16 Uses a 16-times sampling clock relationship for the receiver.
Oversampling by 8 Uses an 8-times sampling clock relationship and may support higher baud rates for a given clock.

On many STM32 USART implementations, the oversampling selection changes the baud-rate divider calculation and the interpretation of the baud-rate register.

The exact supported oversampling modes and their restrictions are device-specific. Check the selected STM32 reference manual.

7. Word Length

Word length determines the configured data frame length. UART data is commonly transmitted using 8-bit payloads.

Some STM32 HAL versions describe the UART word length as the total frame data field, including the parity bit when parity is enabled. Therefore, the number of actual payload bits can differ from the selected word-length setting.

Configuration concept Description
8-bit data, no parity 8 payload bits
8-bit data, parity enabled On common STM32 HAL configurations, the parity bit occupies one configured word-length bit, leaving 7 payload bits.
9-bit frame, no parity Can provide 9 payload bits on supported peripherals.
Check the HAL documentation for the selected STM32 family. Do not assume that selecting a HAL word length always means that many payload bits when parity is enabled.

8. Parity Configuration

Parity is an optional error-detection mechanism. It adds a parity bit to the data frame.

Even Parity

The total number of logic-1 bits in the data and parity field is even.

Odd Parity

The total number of logic-1 bits in the data and parity field is odd.

No Parity

No parity bit is transmitted. This is common in 8-N-1 communication.

Parity can detect some single-bit errors, but it cannot identify the incorrect bit or detect every possible multi-bit error.

9. Stop Bit Configuration

Stop bits indicate the end of a UART frame. The receiver uses the stop interval to complete frame reception and synchronize with the next start bit.

Stop Bit Setting Description
1 stop bit Common setting for embedded serial communication.
2 stop bits Provides a longer stop interval.

The available stop-bit options depend on the particular STM32 USART.

10. UART Peripheral Clock

UART baud-rate generation depends on the clock supplied to the UART peripheral.

On many STM32 devices, UART instances are connected to APB buses. However, newer STM32 families may provide separate peripheral kernel clock selections.

Important Clock Sources

  • APB1 peripheral clock
  • APB2 peripheral clock
  • System clock-derived sources
  • HSI or other selectable kernel clock sources on supported devices
Never assume that every USART uses the same clock. Verify the clock tree and UART kernel clock selection for the exact STM32 device.

12. STM32 HAL UART Initialization Example

The following is an illustrative configuration for USART2. CubeMX normally generates the initialization function and configures the GPIO alternate functions and peripheral clocks. 

UART_HandleTypeDef huart2;

void MX_USART2_UART_Init(void)
{
    huart2.Instance = USART2;

    huart2.Init.BaudRate = 115200;
    huart2.Init.WordLength = UART_WORDLENGTH_8B;
    huart2.Init.StopBits = UART_STOPBITS_1;
    huart2.Init.Parity = UART_PARITY_NONE;
    huart2.Init.Mode = UART_MODE_TX_RX;

    huart2.Init.HwFlowCtl = UART_HWCONTROL_NONE;

    huart2.Init.OverSampling = UART_OVERSAMPLING_16;

    if (HAL_UART_Init(&huart2) != HAL_OK)
    {
        Error_Handler();
    }
}

Explanation

  • Instance selects the USART peripheral.
  • BaudRate specifies the required baud rate.
  • WordLength selects the configured data field length.
  • StopBits configures the stop interval.
  • Parity enables or disables parity checking.
  • Mode enables transmission and reception.
  • HwFlowCtl selects hardware flow control.
  • OverSampling selects the supported oversampling mode.
  • HAL_UART_Init() initializes the peripheral.
This example uses common STM32 HAL field names. Exact available fields and supported settings vary by STM32 family and HAL version. GPIO, clock and MSP initialization must also be implemented.

13. Baud Rate Mismatch

Baud-rate mismatch occurs when the transmitter and receiver operate at significantly different bit rates.

Possible Symptoms

  • Unreadable characters.
  • Incorrect data reception.
  • Framing errors.
  • Intermittent communication.
  • Missing data.

Possible Causes

  • Incorrect peripheral clock configuration.
  • Wrong baud-rate setting.
  • Clock source not configured as expected.
  • Excessive clock tolerance between endpoints.
  • Incorrect terminal settings.

Solutions

  • Verify both baud-rate settings.
  • Check the actual UART kernel clock.
  • Verify the clock tree and prescalers.
  • Use a suitable clock source.
  • Check the receiver's framing and error flags.

14. Placement Interview Questions and Answers

Q1. What is baud rate?

Baud rate is the number of symbols transmitted per second. For conventional binary UART, it equals the bit rate numerically.

Q2. What is the bit duration at 9600 baud?

Approximately 104.17 microseconds.

Q3. What is the bit duration at 115200 baud?

Approximately 8.68 microseconds.

Q4. What does 8-N-1 mean?

Eight data bits, no parity and one stop bit.

Q5. What is oversampling?

It is a receiver sampling technique that uses multiple sampling-clock intervals per bit period to determine the incoming data value.

Q6. What is the function of a parity bit?

It provides simple error detection by checking whether the number of logic-1 bits follows the selected parity rule.

Q7. What happens if baud rates do not match?

The receiver may sample data at incorrect times, causing corrupted data or framing errors.

Q8. What is the purpose of a UART peripheral clock?

It provides the timing reference used by the UART hardware for baud-rate generation and operation.

Q9. What is hardware flow control?

It coordinates data transfer using signals such as RTS and CTS, where supported and configured.

Q10. What is oversampling by 16?

It is a USART sampling mode based on a 16-times sampling-clock relationship.

Q11. How do you configure UART in STM32CubeMX?

Select the USART peripheral, enable the required mode, assign GPIO pins and configure baud rate, word length, parity, stop bits and optional interrupts.

Q12. Why should the UART clock be checked?

Because an incorrect clock assumption can produce an incorrect actual baud rate even when the configured baud-rate value appears correct.
