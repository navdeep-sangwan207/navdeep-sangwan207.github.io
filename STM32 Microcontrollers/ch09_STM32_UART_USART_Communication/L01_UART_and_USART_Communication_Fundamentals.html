2. What is Serial Communication?

Serial communication is a method of transferring data between electronic devices one bit at a time over a communication channel.

A microcontroller can communicate with computers, sensors, communication modules and other controllers using serial communication interfaces.

Example

An STM32 microcontroller sends the message Hello to a computer through a UART interface. A serial terminal displays the received characters.

3. What is UART?

UART stands for Universal Asynchronous Receiver/Transmitter.

It is a hardware communication peripheral that converts parallel data from a processor into serial data for transmission and converts received serial data back into parallel data.

UART Main Functions

  • Serial data transmission.
  • Serial data reception.
  • Start-bit and stop-bit handling.
  • Optional parity generation and checking.
  • Baud-rate timing control.
  • Error detection, such as framing and overrun errors.
Important: UART is asynchronous because the transmitter and receiver do not share a separate clock signal for each transmitted bit. Both sides must agree on compatible communication settings.

4. What is USART?

USART stands for Universal Synchronous/ Asynchronous Receiver/Transmitter.

It supports asynchronous communication and, on devices that implement the relevant features, synchronous communication using a clock signal.

USART Operating Modes

Mode Description
Asynchronous Data transfer without a shared clock signal.
Synchronous Data transfer coordinated by a clock signal.
Many STM32 devices provide USART peripherals with asynchronous UART-compatible operation. The available synchronous features depend on the particular STM32 family and peripheral instance.

5. Difference Between UART and USART

Feature UART USART
Full form Universal Asynchronous Receiver/Transmitter Universal Synchronous/Asynchronous Receiver/Transmitter
Asynchronous mode Supported Supported
Synchronous mode Not supported Supported when implemented
Clock signal No separate shared clock May use a clock in synchronous mode
Typical signals TX, RX, GND TX, RX, and optionally CK
Applications Serial terminals and modules UART-compatible links and synchronous serial links

6. UART Communication Signals

TX – Transmit Pin

TX is the output signal used to transmit serial data from a microcontroller to another device.

RX – Receive Pin

RX is the input signal used to receive serial data from another device.

GND – Ground

A common ground provides a shared voltage reference for a typical non-isolated UART connection.

Connection rule: Connect TX of one device to RX of the other, RX to TX, and GND to GND. Check voltage levels before connecting. STM32 GPIO UART pins are commonly 3.3 V logic and must not be assumed to tolerate 5 V.

7. Asynchronous UART Communication

In asynchronous communication, the transmitter and receiver use their own clock sources. They coordinate data transfer through a predefined baud rate and start/stop bits.

Basic Working

  1. UART line remains HIGH in its idle state for common non-inverted UART.
  2. Transmitter sends a LOW start bit.
  3. Data bits are transmitted, normally least significant bit first.
  4. An optional parity bit may follow.
  5. One or more HIGH stop bits complete the frame.
  6. Receiver detects the frame and reconstructs the data.

8. UART Frame Format

A typical UART frame contains one start bit, data bits, an optional parity bit and one or more stop bits.

Field Function
Start bit Indicates the beginning of a frame; normally LOW.
Data bits Carry the actual information, commonly 7, 8 or 9 bits depending on configuration.
Parity bit Optional bit used for simple error detection.
Stop bit Marks the end of the frame; normally HIGH.

A commonly used configuration is 8-N-1:

  • 8 data bits
  • N = No parity
  • 1 stop bit

9. Baud Rate

Baud rate is the number of symbols transmitted per second. In ordinary binary UART signalling, each symbol represents one bit, so the numerical baud rate equals the bit rate.

Common Baud Rates

Baud Rate Typical Usage
9600 Basic serial communication
19200 Low-to-medium speed communication
38400 Embedded serial devices
57600 Faster serial communication
115200 Common development and debugging baud rate
Example: At 9600 baud, a binary UART interface with one bit per symbol transmits 9600 bits per second. The useful payload data rate is lower because each frame also contains start, stop and possibly parity bits.

10. UART Communication Types

1. Polling-Based Communication

The processor checks the UART status or waits for a HAL operation to complete. This is straightforward but can occupy CPU time while waiting.

2. Interrupt-Based Communication

The UART peripheral generates an interrupt when a configured event occurs. The CPU handles the event through an interrupt service routine or HAL callback.

3. DMA-Based Communication

Direct Memory Access transfers data between memory and the UART peripheral with reduced CPU involvement. It is useful for larger or continuous data transfers.

11. UART Applications in Embedded Systems

  • Communication between STM32 and a PC.
  • GPS module interfacing.
  • Bluetooth serial modules.
  • GSM and cellular communication modules.
  • Debugging and firmware log output.
  • Communication between microcontrollers.
  • Industrial equipment and serial instruments.
  • Bootloader and firmware update interfaces.

12. Basic STM32 HAL UART Example

The following example transmits a message through USART2 using STM32 HAL. It assumes CubeMX has generated a valid UART configuration and initialized huart2. 

#include "main.h"
#include <string.h>

extern UART_HandleTypeDef huart2;

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();

    uint8_t message[] = "Hello from STM32\r\n";

    while (1)
    {
        HAL_UART_Transmit(
            &huart2,
            message,
            strlen((char *)message),
            HAL_MAX_DELAY
        );

        HAL_Delay(1000);
    }
}

Explanation

  • huart2 identifies the configured UART handle.
  • HAL_UART_Transmit() sends the message.
  • strlen() calculates the message length.
  • HAL_MAX_DELAY allows the blocking call to wait for completion.
  • HAL_Delay(1000) adds a one-second delay between messages.
The example assumes the required CubeMX-generated functions and UART handle are available. The UART TX pin, alternate function, clock, baud rate and terminal settings must match the actual board configuration.

14. Placement Interview Questions and Answers

Q1. What is UART?

UART is a hardware peripheral that converts parallel processor data into serial data for transmission and converts received serial data back into parallel data.

Q2. What is the full form of USART?

Universal Synchronous/Asynchronous Receiver/Transmitter.

Q3. What is the difference between UART and USART?

UART supports asynchronous communication. USART can support both synchronous and asynchronous modes, depending on the implemented peripheral features.

Q4. What are TX and RX?

TX is the transmit signal and RX is the receive signal.

Q5. Why are TX and RX crossed?

The transmitter output of one device must connect to the receiver input of the other device.

Q6. What is baud rate?

Baud rate is the number of symbols transmitted per second. For ordinary binary UART, it corresponds numerically to the bit rate.

Q7. What is 8-N-1?

It means 8 data bits, no parity and 1 stop bit.

Q8. Why is UART called asynchronous?

Because the transmitter and receiver do not share a separate clock signal for each data bit.

Q9. Is UART full-duplex?

A conventional UART with separate TX and RX signals can transmit and receive simultaneously, so it supports full-duplex communication.

Q10. What is the purpose of a parity bit?

It provides simple error detection by checking the parity of the transmitted data bits. It cannot detect every possible error.

Q11. What happens if baud rates do not match?

The receiver may sample bits incorrectly, producing corrupted data or framing errors.

Q12. What is the purpose of a stop bit?

It marks the end of a UART frame and returns the line to its idle HIGH state in common non-inverted UART.

Q13. What is the role of a common ground?

It provides a shared voltage reference for the logic-level signals in a typical non-isolated UART link.

Q14. Can UART communicate with a computer?

Yes. A USB-to-UART adapter can connect an STM32 UART to a computer's USB port, provided the voltage levels and serial settings are compatible.

Q15. What are the common UART communication methods?

Polling, interrupt-based communication and DMA-based communication.

16. Lesson Summary

  • UART is an asynchronous serial communication peripheral.
  • USART can support synchronous and asynchronous modes.
  • TX and RX are the main data communication signals.
  • UART frames contain start, data, optional parity and stop bits.
  • Baud rate controls the serial symbol transmission rate.
  • STM32 supports polling, interrupt and DMA-based UART operation.
  • UART is widely used for debugging and peripheral communication.
