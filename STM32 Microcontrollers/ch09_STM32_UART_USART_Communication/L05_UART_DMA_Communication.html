2. What is DMA?

DMA stands for Direct Memory Access. It is a hardware mechanism that transfers data between memory and peripherals, or between memory locations, without requiring the CPU to move every individual data element.

Basic DMA Operation

  1. CPU configures the DMA transfer.
  2. CPU specifies source, destination and transfer length.
  3. A peripheral or software request triggers the transfer.
  4. DMA transfers the data.
  5. DMA can generate an interrupt when a configured event occurs.
  6. CPU processes the completed data or continues application work.
DMA reduces CPU involvement in data movement. The CPU is still responsible for configuring the transfer, managing buffers and handling completion or error events.

3. Why Use DMA with UART?

In polling, the CPU waits for UART transfer progress. In interrupt-based operation, the CPU services transfer events. With DMA, hardware moves a block of data between memory and the UART data register.

Benefits

  • Reduced CPU involvement during data movement.
  • Efficient transfer of larger data buffers.
  • Useful for continuous or high-rate communication.
  • Allows the CPU to perform other application tasks.
  • Supports circular reception on compatible DMA implementations.

For transmission, DMA reads data from memory and supplies it to the UART peripheral. For reception, DMA transfers received data from the UART peripheral into a memory buffer.

DMA request routing, channel or stream selection, transfer width and supported modes vary across STM32 families. Consult the device reference manual.

5. DMA-Based UART Transmission

The HAL function HAL_UART_Transmit_DMA() starts a DMA-based UART transmission.

Function Syntax

HAL_StatusTypeDef HAL_UART_Transmit_DMA(
    UART_HandleTypeDef *huart,
    const uint8_t *pData,
    uint16_t Size
);

Example Program

#include "main.h"
#include <string.h>

extern UART_HandleTypeDef huart2;

uint8_t tx_message[] = "STM32 UART DMA Transmission\r\n";

volatile uint8_t tx_done = 0;

void UART_DMA_Transmit_Start(void)
{
    tx_done = 0;

    if (HAL_UART_Transmit_DMA(
            &huart2,
            tx_message,
            sizeof(tx_message) - 1) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        tx_done = 1;
    }
}

Explanation

  • The message is stored in memory.
  • DMA reads the message from the transmit buffer.
  • DMA supplies the data to the UART peripheral.
  • UART serializes the data and sends it through TX.
  • The completion callback indicates that the DMA-backed UART transfer has completed.
Keep the transmit buffer valid and unchanged until the transfer completes. Do not start another transfer on the same UART handle while it is busy.

6. DMA-Based UART Reception

The HAL function HAL_UART_Receive_DMA() starts DMA-based reception into a memory buffer.

Function Syntax

HAL_StatusTypeDef HAL_UART_Receive_DMA(
    UART_HandleTypeDef *huart,
    uint8_t *pData,
    uint16_t Size
);

Example Program

#include "main.h"

extern UART_HandleTypeDef huart2;

uint8_t rx_buffer[10];

volatile uint8_t rx_done = 0;

void UART_DMA_Receive_Start(void)
{
    rx_done = 0;

    if (HAL_UART_Receive_DMA(
            &huart2,
            rx_buffer,
            sizeof(rx_buffer)) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        rx_done = 1;
    }
}

The callback occurs after the configured number of data elements has been received successfully.

Normal-mode DMA reception is a fixed-length transfer. After completion, firmware generally processes the buffer and starts another receive operation.

7. Normal Mode and Circular Mode

Feature Normal Mode Circular Mode
Transfer behavior Stops after the configured transfer length Reloads and continues transferring
Typical use Known-length data blocks Continuous or repeated data streams
Buffer handling Process and restart as needed Track completed portions and prevent overwrite
Application example Receive a fixed packet Continuous serial data collection
Circular DMA does not automatically provide application-level packet boundaries. Firmware must track the producer position and consume data before DMA overwrites it.

8. UART Reception Using Circular DMA

Circular DMA is useful when data arrives continuously and the firmware cannot predict the exact message length. DMA repeatedly fills the configured buffer.

Example Configuration Concept

uint8_t rx_dma_buffer[128];

void UART_DMA_Circular_Start(void)
{
    if (HAL_UART_Receive_DMA(
            &huart2,
            rx_dma_buffer,
            sizeof(rx_dma_buffer)) != HAL_OK)
    {
        Error_Handler();
    }
}

Configure the corresponding RX DMA channel or stream for circular mode in CubeMX. The exact setup depends on the STM32 family.

Finding the Current DMA Position

uint16_t position;

position = sizeof(rx_dma_buffer)
         - __HAL_DMA_GET_COUNTER(huart2.hdmarx);

The result represents the current write position relative to the start of the buffer. The application must compare it with the previous read position and handle wraparound correctly.

Reading the DMA counter once does not provide a complete thread-safe buffer-management system. Production code must account for wraparound, concurrent updates and possible data overwrite.

9. UART Receive-to-IDLE with DMA

Some STM32 HAL versions provide HAL_UARTEx_ReceiveToIdle_DMA(). It starts DMA reception and allows the application to receive a callback when the receiver detects an idle condition after incoming data.

Example

#include "main.h"

extern UART_HandleTypeDef huart2;

uint8_t rx_buffer[128];

void UART_ReceiveToIdle_Start(void)
{
    if (HAL_UARTEx_ReceiveToIdle_DMA(
            &huart2,
            rx_buffer,
            sizeof(rx_buffer)) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UARTEx_RxEventCallback(
    UART_HandleTypeDef *huart,
    uint16_t Size)
{
    if (huart->Instance == USART2)
    {
        // Size indicates the received data length
        // reported by this callback event.

        // Process or copy the received bytes.
        // Restart reception when using a mode that
        // requires rearming.
    }
}

Important Notes

  • Receive-to-IDLE can help identify bursts of incoming data.
  • The callback reports the received size or event position according to the HAL implementation.
  • In circular mode, reception may continue after half-transfer, transfer-complete or idle events.
  • In normal mode, reception generally needs to be restarted after completion.
  • Idle detection is not a substitute for a complete application protocol.
Receive-to-IDLE availability and exact callback behavior depend on the STM32 HAL version and selected peripheral. Check the relevant HAL documentation and examples.

10. DMA Configuration Using STM32CubeMX

  1. Open the STM32CubeIDE project.
  2. Enable the required USART peripheral.
  3. Configure the TX and RX pins.
  4. Open the DMA Settings section for the USART.
  5. Add a DMA request for UART transmission.
  6. Add a DMA request for UART reception if required.
  7. Select normal or circular mode as appropriate.
  8. Configure peripheral and memory data widths.
  9. Enable the required DMA interrupts.
  10. Enable the USART global interrupt if required by the HAL implementation.
  11. Generate and build the project.
CubeMX configures the DMA request mapping and initialization code for the selected device. Verify that the generated configuration matches the intended transfer direction and buffer behavior.

12. DMA Memory and Buffer Considerations

  • Use buffers that remain valid throughout the DMA operation.
  • Do not modify a transmit buffer while DMA is reading it.
  • Do not process a receive buffer while DMA is overwriting the same data.
  • Check the DMA transfer length and data width.
  • Handle transfer-complete and error events.
  • Consider memory alignment and accessibility restrictions.
  • Use cache maintenance on cache-equipped MCUs where required.
On STM32 devices with a data cache, DMA coherency must be handled according to the memory system. Clean cache lines before DMA reads CPU-written transmit data, and invalidate appropriate cache lines before the CPU reads DMA-written receive data. Follow device-specific cache and alignment requirements.

13. Common UART DMA Errors

ProblemPossible Solution
DMA transfer does not start Check DMA request mapping and initialization.
Completion callback does not execute Check DMA IRQ handler and NVIC configuration.
Incorrect received data Verify baud rate, data width and buffer handling.
HAL_BUSY status Check whether the previous transfer is still active.
DMA overrun or lost data Ensure data is consumed quickly enough and buffer capacity is adequate.
Cache-related corruption Apply the required cache maintenance operations.
Transfer stops unexpectedly Check normal/circular mode and error recovery.

14. Placement Interview Questions and Answers

Q1. What is DMA?

DMA is a hardware mechanism that transfers data between memory and peripherals with reduced CPU involvement.

Q2. Why is DMA used with UART?

DMA is used to transfer larger or continuous data buffers efficiently without requiring the CPU to handle every data element.

Q3. Which HAL function starts UART DMA transmission?

HAL_UART_Transmit_DMA().

Q4. Which HAL function starts UART DMA reception?

HAL_UART_Receive_DMA().

Q5. What is circular DMA mode?

It is a DMA mode in which the transfer restarts automatically from the beginning of the configured buffer after reaching its end.

Q6. What is normal DMA mode?

It is a mode in which DMA stops after the configured number of data elements has been transferred.

Q7. What is UART Receive-to-IDLE?

It is a reception technique supported by some STM32 HAL versions that reports received data when an idle condition is detected.

Q8. What is the advantage of DMA over interrupt-based transfer?

DMA moves data directly between memory and the peripheral, reducing the number of CPU data-handling operations.

Q9. Why must a DMA buffer remain valid?

DMA accesses the buffer independently of the normal program flow. Invalid or modified memory can corrupt the transfer.

Q10. What is DMA circular buffer overrun?

It occurs when DMA overwrites data that the application has not yet consumed.

Q11. What is the purpose of a DMA completion callback?

It notifies the application that the configured transfer has completed.

Q12. What is cache coherency in DMA?

It means ensuring that the CPU cache and memory contain consistent data when DMA accesses memory independently of the CPU cache.

16. Lesson Summary

  • DMA transfers data with reduced CPU involvement.
  • UART TX DMA transfers memory data to the UART peripheral.
  • UART RX DMA transfers peripheral data into memory.
  • Normal mode stops after the configured transfer.
  • Circular mode repeatedly uses the same buffer.
  • Receive-to-IDLE can help handle variable-length data bursts.
  • Buffer lifetime, memory access and cache coherency matter.
  • DMA is useful for efficient high-volume serial communication.
