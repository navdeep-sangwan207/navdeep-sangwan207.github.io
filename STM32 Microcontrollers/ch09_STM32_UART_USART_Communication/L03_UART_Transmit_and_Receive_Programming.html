2. UART Data Transmission

UART transmission sends data from the STM32 microcontroller to another device through the TX pin. The UART peripheral converts the data into a serial frame containing start, data, optional parity and stop bits.

Transmission Flow

  1. Application prepares data in a buffer.
  2. Firmware calls the UART transmit function.
  3. UART peripheral serializes the data.
  4. Bits are transmitted through the TX pin.
  5. The receiver reconstructs the transmitted data.
UART HAL transmit and receive functions operate on byte buffers. The UART peripheral handles the serial framing and bit timing.

3. HAL_UART_Transmit()

HAL_UART_Transmit() transmits a buffer using a blocking polling operation. The function normally waits until the requested transfer completes or the timeout expires.

Function Syntax

HAL_StatusTypeDef HAL_UART_Transmit(
    UART_HandleTypeDef *huart,
    const uint8_t *pData,
    uint16_t Size,
    uint32_t Timeout
);

Parameters

ParameterDescription
huartPointer to the UART handle.
pDataPointer to the transmit buffer.
SizeNumber of data elements to transmit.
TimeoutMaximum permitted waiting time in milliseconds.

Example: Transmit a String

#include "main.h"
#include <string.h>

extern UART_HandleTypeDef huart2;

void UART_Transmit_Message(void)
{
    uint8_t message[] = "Hello STM32\r\n";

    HAL_UART_Transmit(
        &huart2,
        message,
        strlen((char *)message),
        1000
    );
}

The function sends the message through the UART instance represented by huart2.

4. UART Data Reception

UART reception receives serial data through the RX pin and stores the reconstructed data in a memory buffer.

Reception Flow

  1. A transmitting device sends serial data.
  2. STM32 UART detects the start bit.
  3. The peripheral samples and reconstructs the data.
  4. Received data becomes available to the processor.
  5. Firmware reads the data from the receive buffer.

5. HAL_UART_Receive()

HAL_UART_Receive() receives a specified number of data elements using a blocking polling operation.

Function Syntax

HAL_StatusTypeDef HAL_UART_Receive(
    UART_HandleTypeDef *huart,
    uint8_t *pData,
    uint16_t Size,
    uint32_t Timeout
);

Example: Receive One Character

uint8_t received_char;

void UART_Receive_Character(void)
{
    HAL_StatusTypeDef status;

    status = HAL_UART_Receive(
        &huart2,
        &received_char,
        1,
        HAL_MAX_DELAY
    );

    if (status == HAL_OK)
    {
        // Character successfully received.
    }
}
With HAL_MAX_DELAY, this blocking call can wait indefinitely for the requested data. Use a finite timeout or interrupt/DMA reception when the application must continue other work.

6. UART Transmit and Receive Together

A simple application can receive one character and transmit the same character back to the sender. This is called an echo application.

UART Echo Program

#include "main.h"

extern UART_HandleTypeDef huart2;

int main(void)
{
    uint8_t received_char;

    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();

    while (1)
    {
        if (HAL_UART_Receive(
                &huart2,
                &received_char,
                1,
                HAL_MAX_DELAY) == HAL_OK)
        {
            HAL_UART_Transmit(
                &huart2,
                &received_char,
                1,
                1000
            );
        }
    }
}

HelloHello

Each received character is transmitted back to the terminal. This is a useful first test of a UART link.

7. UART Buffering

A buffer is a memory area used to temporarily store transmitted or received data.

Transmit Buffer

Contains the data that firmware wants to send through the UART peripheral.

Receive Buffer

Stores data received from the UART peripheral.

Example

uint8_t tx_buffer[] = "STM32 UART";
uint8_t rx_buffer[20];

HAL_UART_Transmit(
    &huart2,
    tx_buffer,
    sizeof(tx_buffer) - 1,
    1000
);

HAL_UART_Receive(
    &huart2,
    rx_buffer,
    5,
    1000
);
The receive call above waits for exactly five data elements. It does not automatically detect the end of a variable-length string. A protocol must define message length, a delimiter, or another framing method.

8. Receiving a String Using a Delimiter

A simple command interface can receive characters until a newline character is detected. The following example uses blocking reception and a finite timeout for each character. 

#include "main.h"
#include <string.h>

extern UART_HandleTypeDef huart2;

uint8_t rx_buffer[32];

HAL_StatusTypeDef UART_Receive_Line(void)
{
    uint8_t ch;
    uint16_t index = 0;

    while (index < sizeof(rx_buffer) - 1)
    {
        if (HAL_UART_Receive(
                &huart2, &ch, 1, 1000) != HAL_OK)
        {
            return HAL_TIMEOUT;
        }

        if (ch == '\r' || ch == '\n')
        {
            break;
        }

        rx_buffer[index++] = ch;
    }

    rx_buffer[index] = '\0';

    return HAL_OK;
}

Explanation

  • One character is received at a time.
  • Characters are stored in the receive buffer.
  • Carriage return or newline terminates the input.
  • The buffer is null-terminated to form a C string.
  • The buffer size is checked to prevent overflow.
This is a basic blocking example. Production command interfaces should also handle timeout recovery, incomplete messages, buffer reset and input validation.

9. HAL UART Function Comparison

Function Purpose Operation
HAL_UART_Transmit() Transmit data Blocking
HAL_UART_Receive() Receive data Blocking
HAL_UART_Transmit_IT() Interrupt-based transmission Non-blocking after start
HAL_UART_Receive_IT() Interrupt-based reception Non-blocking after start
HAL_UART_Transmit_DMA() DMA-based transmission Non-blocking after start
HAL_UART_Receive_DMA() DMA-based reception Non-blocking after start

10. UART Full-Duplex Communication

Full-duplex UART communication allows transmission and reception to occur simultaneously because separate TX and RX signal lines are used. 

STM32 TX  -------->  Device RX
STM32 RX  <--------  Device TX
STM32 GND ----------  Device GND

Whether simultaneous transmit and receive operations can be started through a particular HAL handle depends on the peripheral and HAL implementation. Use the relevant non-blocking or DMA APIs for concurrent application operation.

11. Common UART Programming Errors

ErrorPossible Solution
Wrong UART handle Verify the selected USART instance.
Incorrect buffer length Check the actual number of elements.
Missing null terminator Reserve space and terminate C strings correctly.
Blocking reception Use timeout, interrupt or DMA as appropriate.
Buffer overflow Check buffer capacity before writing.
Wrong TX/RX wiring Cross TX and RX connections.
Incorrect baud rate Match terminal and STM32 settings.
Missing GPIO alternate function Check pin configuration and peripheral mapping.

13. Placement Interview Questions and Answers

Q1. Which HAL function is used for UART transmission?

HAL_UART_Transmit() is used for blocking transmission.

Q2. Which HAL function is used for UART reception?

HAL_UART_Receive() is used for blocking reception.

Q3. What is a UART buffer?

A buffer is a memory area used to temporarily store data before transmission or after reception.

Q4. What is blocking communication?

The calling function waits for the requested operation to complete or for its timeout condition.

Q5. What is an echo program?

It receives data and transmits the same data back to the sender.

Q6. Why is buffer size important?

An incorrect buffer size can cause incomplete data transfer or memory corruption.

Q7. Why is a null terminator needed?

C string functions expect a null character to mark the end of a string.

Q8. Can UART transmit and receive simultaneously?

Yes. A full-duplex UART can transmit and receive simultaneously through separate TX and RX lines.

Q9. What is the difference between polling and interrupt-based UART?

Polling waits for peripheral status, while interrupt operation allows the CPU to perform other work until a configured UART event occurs.

Q10. What is the purpose of a receive timeout?

It prevents a blocking receive operation from waiting indefinitely when the expected data does not arrive.

Q11. Why should a UART receive buffer be checked?

To prevent writes beyond its allocated memory and avoid buffer overflow.

Q12. What does HAL_OK indicate?

It indicates that the HAL operation completed successfully.
