2. What is Interrupt-Based UART Communication?

Interrupt-based UART communication allows the CPU to perform other application tasks while the UART peripheral handles data transmission or reception. When a configured UART event occurs, the peripheral requests CPU attention through an interrupt.

Basic Working

  1. Firmware starts a UART interrupt operation.
  2. The CPU continues executing other instructions.
  3. The UART peripheral transmits or receives data.
  4. A UART event generates an interrupt request.
  5. The NVIC forwards the enabled interrupt to the CPU.
  6. The interrupt handler processes the UART event.
  7. The HAL callback notifies the application when appropriate.
Interrupt-based HAL functions are non-blocking after the transfer has been successfully started. The application must still handle completion and errors.

3. Polling vs Interrupt-Based UART

Feature Polling Interrupt-Based
CPU operation Waits or repeatedly checks status Can execute other tasks while waiting
CPU efficiency Can be lower when waiting Often better for asynchronous applications
Implementation Relatively simple Requires interrupt configuration and callbacks
Timing Depends on polling and blocking behavior Responds to configured peripheral events
Applications Simple short transfers Responsive embedded applications

4. HAL_UART_Receive_IT()

HAL_UART_Receive_IT() starts an interrupt-based reception operation.

Function Syntax

HAL_StatusTypeDef HAL_UART_Receive_IT(
    UART_HandleTypeDef *huart,
    uint8_t *pData,
    uint16_t Size
);

Parameters

ParameterDescription
huartUART handle.
pDataReceive buffer address.
SizeNumber of data elements to receive.

Unlike the polling function, this function returns after starting the operation rather than waiting for all requested data to arrive.

5. Interrupt-Based UART Reception Example

This example receives one character through USART2 and stores it in a variable. After reception, the callback sets an event flag and rearms reception. 

#include "main.h"

extern UART_HandleTypeDef huart2;

uint8_t rx_char;
volatile uint8_t uart_rx_event = 0;

void UART_Start_Receive(void)
{
    if (HAL_UART_Receive_IT(&huart2, &rx_char, 1) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        uart_rx_event = 1;

        // Rearm one-byte reception.
        HAL_UART_Receive_IT(&huart2, &rx_char, 1);
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();

    UART_Start_Receive();

    while (1)
    {
        if (uart_rx_event)
        {
            uart_rx_event = 0;

            // Process the received character here.
            // Example: update application state.
        }
    }
}

Explanation

  • HAL_UART_Receive_IT() starts reception.
  • HAL_UART_RxCpltCallback() is called after the requested reception completes successfully.
  • uart_rx_event informs the main loop that a character has arrived.
  • The receive operation is started again for the next character.
The callback executes in interrupt context. Keep it short. Check the return value when rearming reception in production code and handle UART errors separately. The buffer must remain valid for the duration of the transfer.

6. UART Interrupt Handler

The MCU interrupt vector directs the UART interrupt to its corresponding interrupt handler. The STM32 HAL handler processes the peripheral status and advances the transfer state.

Example: USART2 Interrupt Handler

void USART2_IRQHandler(void)
{
    HAL_UART_IRQHandler(&huart2);
}

This handler is commonly generated in the stm32xx_it.c file by STM32CubeMX. The exact file name depends on the selected STM32 family.

Do not create a duplicate interrupt handler if CubeMX has already generated one. Ensure the correct IRQ handler and vector are enabled for the selected USART instance.

7. NVIC Configuration

The Nested Vectored Interrupt Controller (NVIC) controls interrupt enabling and priority for the processor.

HAL Configuration Example

HAL_NVIC_SetPriority(USART2_IRQn, 5, 0);
HAL_NVIC_EnableIRQ(USART2_IRQn);

Important Steps

  1. Configure the UART peripheral.
  2. Enable the UART interrupt source through the HAL operation.
  3. Set the NVIC priority.
  4. Enable the USART IRQ in the NVIC.
  5. Provide the correct interrupt handler.

CubeMX can generate much of this configuration when the USART global interrupt is enabled in the NVIC settings.

8. HAL_UART_Transmit_IT()

HAL_UART_Transmit_IT() starts interrupt-based transmission.

Function Syntax

HAL_StatusTypeDef HAL_UART_Transmit_IT(
    UART_HandleTypeDef *huart,
    const uint8_t *pData,
    uint16_t Size
);

Example

#include "main.h"
#include <string.h>

extern UART_HandleTypeDef huart2;

uint8_t tx_message[] = "STM32 interrupt transmission\r\n";
volatile uint8_t tx_complete = 0;

void UART_Start_Transmit(void)
{
    tx_complete = 0;

    if (HAL_UART_Transmit_IT(
            &huart2,
            tx_message,
            sizeof(tx_message) - 1) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        tx_complete = 1;
    }
}

The transmit buffer must remain valid and unchanged until transmission has completed. The completion callback signals that the requested transfer is done.

9. UART Reception Using a Fixed-Length Buffer

Interrupt reception can receive multiple data elements into a fixed-length buffer. 

#include "main.h"

extern UART_HandleTypeDef huart2;

uint8_t rx_buffer[8];
volatile uint8_t message_received = 0;

void UART_Start_Buffer_Receive(void)
{
    message_received = 0;

    if (HAL_UART_Receive_IT(
            &huart2,
            rx_buffer,
            sizeof(rx_buffer)) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        message_received = 1;
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();

    UART_Start_Buffer_Receive();

    while (1)
    {
        if (message_received)
        {
            message_received = 0;

            // Process all eight received data elements.

            UART_Start_Buffer_Receive();
        }
    }
}
This example expects exactly eight data elements before the receive-complete callback occurs. It does not automatically detect a variable-length message or newline delimiter.

10. Sharing Data Between ISR and Main Loop

Data shared between an interrupt callback and the main program must be handled carefully.

Using a Volatile Event Flag

volatile uint8_t uart_event = 0;

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        uart_event = 1;
    }
}

int main(void)
{
    while (1)
    {
        if (uart_event)
        {
            uart_event = 0;

            // Handle the UART event.
        }
    }
}
volatile tells the compiler that a variable can change outside the normal program flow. It does not make compound operations atomic and does not provide a complete synchronization mechanism.

Important Considerations

  • Use short ISR callbacks.
  • Do not perform lengthy processing inside callbacks.
  • Use a queue or ring buffer when several bytes or events must be retained.
  • Protect shared multi-byte data when atomic access is required.
  • Handle buffer overflow explicitly.

11. UART Error Callback

STM32 HAL provides an error callback for UART communication errors. 

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        uint32_t error = HAL_UART_GetError(huart);

        // Record the error and schedule recovery
        // outside interrupt context.
        (void)error;
    }
}

Possible errors include parity, noise, framing and overrun errors. Available error conditions and recovery requirements depend on the peripheral and HAL version.

12. Interrupt-Based UART Design Rules

  • Keep interrupt callbacks short and predictable.
  • Avoid blocking delays inside interrupt callbacks.
  • Avoid blocking UART transmit or receive calls inside a UART callback.
  • Do not use long loops or lengthy string processing in an ISR.
  • Use persistent buffers rather than short-lived local buffers for asynchronous operations.
  • Check the return value when starting or restarting transfers.
  • Use DMA or ring buffers for high-volume continuous data.
  • Handle UART errors and reception recovery.

13. Common Problems and Troubleshooting

ProblemPossible Cause or Solution
Callback never executes Check NVIC enable, IRQ handler and peripheral interrupt configuration.
Only first character is received Rearm reception after completing the previous transfer.
Incorrect received data Check baud rate, frame format and wiring.
HAL_BUSY returned Check whether the UART handle is already handling a transfer.
Data overwritten Use suitable buffers and process received data before reuse.
Repeated UART errors Inspect clock configuration, signal quality and error recovery.

14. Placement Interview Questions and Answers

Q1. What is interrupt-based UART communication?

It is a communication method in which UART peripheral events generate interrupts to notify the processor about transmission or reception progress.

Q2. Which HAL function starts interrupt-based reception?

HAL_UART_Receive_IT().

Q3. Which HAL function starts interrupt-based transmission?

HAL_UART_Transmit_IT().

Q4. What is HAL_UART_RxCpltCallback()?

It is the HAL callback invoked when the requested interrupt-based reception completes successfully.

Q5. What is HAL_UART_TxCpltCallback()?

It is the HAL callback invoked when the requested interrupt-based transmission completes successfully.

Q6. What is the role of NVIC?

NVIC controls interrupt enabling, pending state, priorities and delivery to the processor.

Q7. Why should an ISR be short?

A short ISR reduces interrupt latency for other events and helps maintain predictable system timing.

Q8. Why must an interrupt receive operation be restarted?

A normal fixed-length HAL interrupt receive operation completes after the requested number of data elements. Another operation must be started to receive more data.

Q9. Is volatile sufficient for sharing data?

No. Volatile affects compiler access behavior but does not guarantee atomicity or synchronization.

Q10. What is a UART overrun error?

It occurs when new received data arrives before previously received data has been read or handled as required by the peripheral.

Q11. What is the difference between polling and interrupt UART?

Polling repeatedly checks peripheral status, while interrupt-based operation allows the processor to perform other tasks until an enabled event occurs.

Q12. When should DMA be preferred?

DMA is useful for larger, continuous or high-rate data transfers where reducing CPU involvement is important.

16. Lesson Summary

  • Interrupt-based UART operation reduces the need for continuous polling.
  • HAL_UART_Receive_IT() starts interrupt-based reception.
  • HAL_UART_Transmit_IT() starts interrupt-based transmission.
  • HAL callbacks report transfer completion.
  • NVIC and the correct IRQ handler are essential.
  • Reception must be rearmed for subsequent fixed-length transfers.
  • Shared data and buffers require careful management.
  • ISRs should remain short and predictable.
