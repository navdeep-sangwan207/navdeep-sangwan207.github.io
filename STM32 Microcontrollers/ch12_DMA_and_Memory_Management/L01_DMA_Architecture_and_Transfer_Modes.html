2. What is DMA?

DMA stands for Direct Memory Access. It is a hardware mechanism that transfers data between memory and peripherals, or between memory regions, with reduced CPU involvement.

Without DMA, the CPU commonly reads data from a peripheral register and writes it into memory. With DMA, a configured DMA controller performs the transfer. 

Without DMA:

Peripheral
    |
    v
   CPU
    |
    v
  Memory


With DMA:

Peripheral
    |
    v
   DMA
    |
    v
  Memory

CPU configures DMA and processes data.

3. Why is DMA Required?

Embedded applications often receive or generate large amounts of data. Requiring the CPU to handle every individual transfer can consume processing time.

Advantages of DMA

  • Reduces CPU workload for repetitive transfers.
  • Supports high-rate peripheral data movement.
  • Allows CPU processing to overlap with data transfers.
  • Supports continuous data acquisition.
  • Can reduce the number of CPU interrupts.
  • Improves overall firmware efficiency when configured correctly.

Typical Applications

  • ADC sensor data acquisition.
  • UART communication.
  • SPI data transfer.
  • Audio data processing.
  • Memory-to-memory copying.
  • Display and communication interfaces.

4. DMA Controller Architecture

A DMA controller manages data transfers between configured source and destination addresses. It may contain multiple channels, streams or request lines depending on the STM32 family.

             +------------------+
             |   DMA Controller |

             | Address Control  |
             | Transfer Counter |

                      |

             v                  v
      +------------+      +------------+
      | Peripheral |      |   Memory   |
      | Registers  |      |   SRAM     |
      +------------+      +------------+

Main Components

  • DMA Controller: Manages configured transfers.
  • DMA Channel/Stream: Provides a transfer path or configuration context.
  • Source Address: Address from which data is read.
  • Destination Address: Address to which data is written.
  • Transfer Counter: Tracks the remaining number of transfer items.
  • Priority Control: Helps arbitrate competing DMA requests.
  • Interrupt Logic: Reports configured transfer events or errors.
STM32 DMA architecture is family-specific. Some devices use channels, others use streams and channels, and newer devices may use DMAMUX request routing. Always consult the selected MCU reference manual.

5. DMA Transfer Directions

DMA transfer direction describes the movement of data between the source and destination.

5.1 Peripheral-to-Memory

Data is read from a peripheral data register and stored in memory.

Data is read from memory and written to a peripheral data register.

Data is transferred from one memory region to another, if the DMA controller supports that transfer mode.

Not every STM32 DMA controller supports every transfer direction. Memory-to-memory support and restrictions must be checked for the selected DMA controller.

7. Peripheral and Memory Increment

DMA can be configured to increment the source or destination address after each transfer. This is important when reading or writing arrays and peripheral registers.

7.1 Memory Increment Enabled

The memory address advances after each transferred item. This allows data to be stored in consecutive buffer locations. 

Memory Buffer:

Address 0x20000000 -> Data 1
Address 0x20000002 -> Data 2
Address 0x20000004 -> Data 3
Address 0x20000006 -> Data 4

Example assumes 16-bit transfer width.

7.2 Peripheral Increment Disabled

The peripheral address normally remains fixed when repeatedly accessing a single peripheral data register. 

Peripheral Data Register
          |
          v
       DMA Read
          |
          v
      Memory[0]
      Memory[1]
      Memory[2]
      Memory[3]
For ADC data acquisition, a common configuration is fixed peripheral address and incrementing memory address. Exact settings depend on the peripheral and transfer design.

8. DMA Data Width and Alignment

DMA data width determines how much data is transferred in each item.

Data Width Transfer Size
Byte 8 bits
Half-word 16 bits
Word 32 bits

Peripheral and memory data widths must be selected according to the peripheral register, buffer type and DMA capabilities.

Example

uint8_t  uart_buffer[20];

uint16_t adc_buffer[10];

uint32_t data_buffer[8];
  • UART byte transfers commonly use byte width.
  • 12-bit ADC results are often stored in 16-bit memory elements.
  • 32-bit data transfers use word width where appropriate.
Do not assume that the C variable type alone determines DMA configuration. Verify peripheral width, memory width, alignment and the exact HAL configuration.

9. DMA Priority

When multiple DMA requests compete for transfer resources, priority and arbitration determine which request is serviced.

Common Priority Levels

  • Low
  • Medium
  • High
  • Very High

A high-priority DMA transfer can receive preferential service over a lower-priority transfer within the DMA controller's arbitration scheme.

DMA priority is separate from NVIC interrupt priority. DMA transfer arbitration controls DMA service, while NVIC priority controls CPU exception handling.

11. DMA and CPU Comparison

Data movement CPU copies each item DMA hardware moves data

12. DMA Limitations and Design Considerations

  • DMA configuration is device-specific.
  • DMA and CPU may contend for memory buses.
  • Incorrect transfer widths can corrupt data.
  • Buffer ownership must be managed correctly.
  • Some DMA engines cannot access every memory region.
  • Cache maintenance may be required on cache-equipped MCUs.
  • DMA does not eliminate the need for error handling.
  • Transfer timing must meet peripheral requirements.
On cache-equipped STM32 devices, DMA-written memory may not immediately match the CPU's cached view. Cache invalidation, alignment and memory-region requirements must be handled according to the MCU documentation. Volatile alone does not solve cache coherency.

13. Placement Interview Questions and Answers

Q1. What is DMA?

DMA is a hardware mechanism that transfers data between peripherals and memory with reduced CPU involvement.

Q2. Why is DMA used in embedded systems?

It reduces CPU workload during repetitive data transfers and supports efficient high-rate data movement.

Q3. What are the main DMA transfer directions?

Peripheral-to-memory, memory-to-peripheral and, where supported, memory-to-memory.

Q4. What is normal DMA mode?

DMA performs the configured transfer and stops after completion.

Q5. What is circular DMA mode?

DMA automatically reloads the transfer configuration and repeatedly uses the configured buffer.

Q6. What is memory increment?

It advances the memory address after each transfer item.

Q7. Why is peripheral increment commonly disabled?

A peripheral data register normally has a fixed address, so DMA repeatedly accesses the same register.

Q8. What is DMA transfer complete?

It is an event indicating that the configured number of transfer items has been moved.

Q9. What is the difference between DMA priority and NVIC priority?

DMA priority controls arbitration between DMA transfers. NVIC priority controls preemption and servicing of CPU interrupts.

Q10. Can DMA work without CPU involvement?

Once configured and started, DMA can move data without the CPU handling each item. The CPU is still responsible for setup, synchronization and error handling.

Q11. What is a DMA half-transfer interrupt?

It indicates that half of the configured transfer has completed.

Q12. Does DMA always improve performance?

No. DMA has configuration and bus-arbitration overhead. It is most useful when transfer size, frequency or CPU workload justify it.

15. Lesson Summary

  • DMA transfers data with reduced CPU involvement.
  • DMA supports peripheral and memory transfers.
  • Normal mode stops after the configured transfer.
  • Circular mode repeatedly uses the configured buffer.
  • Address increment controls source and destination progression.
  • Transfer width determines the size of each data item.
  • DMA priority and NVIC priority serve different purposes.
  • Half-transfer, complete-transfer and error events support application handling.
  • Buffer synchronization and memory accessibility are essential.
