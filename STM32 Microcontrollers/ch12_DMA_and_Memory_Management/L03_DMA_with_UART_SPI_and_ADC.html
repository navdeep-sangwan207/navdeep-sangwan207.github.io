2. Why Use DMA with Peripherals?

UART, SPI and ADC peripherals generate or consume data. The CPU can handle each item through polling or interrupts, but this can become inefficient when data rates or transfer sizes increase.

DMA moves data between a peripheral data register and a memory buffer after the transfer has been configured. 

             +----------------+
             |      CPU       |
             |                |
             | Configure DMA  |
             | Process Buffer |
             +--------+-------+
                      |
                      v
             +----------------+
             | DMA Controller |
             +--------+-------+
                      |
           +----------+----------+
           |          |          |
           v          v          v
         UART        SPI        ADC
           |          |          |
           +----------+----------+
                      |
                      v
                   Memory
                   Buffer

Benefits

  • Reduces CPU involvement in repetitive data movement.
  • Supports continuous ADC sampling.
  • Improves efficiency for large UART and SPI transfers.
  • Allows processing to overlap with data acquisition.
  • Supports half-buffer and full-buffer processing techniques.

3. UART Communication Using DMA

UART DMA allows data to be transmitted from a memory buffer to the UART peripheral or received from UART into a memory buffer.

3.1 UART DMA Transmission

Memory TX Buffer
       |
       v
 DMA Controller
       |
       v
 UART Data Register
       |
       v
     TX Pin

HAL API

HAL_UART_Transmit_DMA(
    &huart2,
    tx_buffer,
    tx_length
);

Example: UART DMA Transmission

#include "main.h"
#include <string.h>

extern UART_HandleTypeDef huart2;

uint8_t tx_buffer[] = "STM32 UART DMA\r\n";

volatile uint8_t uart_tx_done = 0;
volatile uint8_t uart_tx_error = 0;

void UART_DMA_Send(void)
{
    uart_tx_done = 0;
    uart_tx_error = 0;

    if (HAL_UART_Transmit_DMA(
            &huart2,
            tx_buffer,
            sizeof(tx_buffer) - 1U) != HAL_OK)
    {
        uart_tx_error = 1;
    }
}

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2)
    {
        uart_tx_done = 1;
    }
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2)
    {
        uart_tx_error = 1;
    }
}

The completion callback indicates that the DMA-driven UART transfer has completed. UART transmission completion and DMA memory transfer completion are related but distinct hardware events; the HAL UART callback is the application-level completion notification.

3.2 UART DMA Reception

UART DMA reception stores incoming bytes in a memory buffer. 

UART RX Pin
     |
     v
UART Data Register
     |
     v
DMA Controller
     |
     v
RX Memory Buffer

Example: Fixed-Length UART Reception

#define RX_SIZE 16

uint8_t rx_buffer[RX_SIZE];

volatile uint8_t uart_rx_done = 0;

void UART_DMA_Receive_Start(void)
{
    uart_rx_done = 0;

    if (HAL_UART_Receive_DMA(
            &huart2,
            rx_buffer,
            RX_SIZE) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2)
    {
        uart_rx_done = 1;
    }
}
This example receives exactly RX_SIZE bytes. Variable-length reception requires an appropriate method such as UART IDLE-line detection, receive-to-idle DMA where supported, or a protocol with delimiters and timeouts.

UART DMA Applications

  • GPS data reception.
  • Modem communication.
  • Serial command interfaces.
  • High-volume logging.
  • Communication with external controllers.

4.1 SPI DMA Transmission

HAL_SPI_Transmit_DMA(
    &hspi1,
    tx_buffer,
    DATA_SIZE
);

4.2 SPI DMA Reception

HAL_SPI_Receive_DMA(
    &hspi1,
    rx_buffer,
    DATA_SIZE
);

4.3 SPI Full-Duplex DMA Example

#include "main.h"
#include <stdint.h>

extern SPI_HandleTypeDef hspi1;

#define SPI_DATA_SIZE 4

uint8_t spi_tx_buffer[SPI_DATA_SIZE] =
{
    0x9F, 0x00, 0x00, 0x00
};

uint8_t spi_rx_buffer[SPI_DATA_SIZE];

volatile uint8_t spi_transfer_done = 0;
volatile uint8_t spi_transfer_error = 0;

void SPI_DMA_Transfer_Start(void)
{
    spi_transfer_done = 0;
    spi_transfer_error = 0;

    HAL_GPIO_WritePin(
        SPI_CS_GPIO_Port,
        SPI_CS_Pin,
        GPIO_PIN_RESET
    );

    if (HAL_SPI_TransmitReceive_DMA(
            &hspi1,
            spi_tx_buffer,
            spi_rx_buffer,
            SPI_DATA_SIZE) != HAL_OK)
    {
        HAL_GPIO_WritePin(
            SPI_CS_GPIO_Port,
            SPI_CS_Pin,
            GPIO_PIN_SET
        );

        spi_transfer_error = 1;
    }
}

void HAL_SPI_TxRxCpltCallback(SPI_HandleTypeDef *hspi)
{
    if (hspi == &hspi1)
    {
        HAL_GPIO_WritePin(
            SPI_CS_GPIO_Port,
            SPI_CS_Pin,
            GPIO_PIN_SET
        );

        spi_transfer_done = 1;
    }
}

void HAL_SPI_ErrorCallback(SPI_HandleTypeDef *hspi)
{
    if (hspi == &hspi1)
    {
        HAL_GPIO_WritePin(
            SPI_CS_GPIO_Port,
            SPI_CS_Pin,
            GPIO_PIN_SET
        );

        spi_transfer_error = 1;
    }
}
The example assumes an active-LOW chip-select signal and a four-byte exchange. The command and dummy bytes are device-specific. Some SPI devices require additional command, address, dummy-clock or CS timing rules. Check the peripheral datasheet and HAL behavior for the selected STM32 family.

SPI DMA Applications

  • SPI Flash memory communication.
  • Display data transfer.
  • High-speed sensor data exchange.
  • External ADC and DAC communication.
  • Wireless module communication.

5. ADC Data Acquisition Using DMA

ADC DMA is commonly used to collect repeated analog samples into a memory buffer without requiring the CPU to read every conversion result.

ADC DMA Architecture

Analog Sensor
      |
      v
ADC Conversion
      |
      v
ADC Data Register
      |
      v
DMA Controller
      |
      v
SRAM Sample Buffer
      |
      v
CPU Processing

5.1 ADC DMA HAL Function

HAL_ADC_Start_DMA(
    &hadc1,
    (uint32_t *)adc_buffer,
    ADC_BUFFER_SIZE
);

5.2 ADC DMA Example

#include "main.h"
#include <stdint.h>

extern ADC_HandleTypeDef hadc1;

#define ADC_BUFFER_SIZE 16

uint16_t adc_buffer[ADC_BUFFER_SIZE];

volatile uint8_t adc_conversion_done = 0;
volatile uint8_t adc_half_done = 0;

void ADC_DMA_Start(void)
{
    adc_conversion_done = 0;
    adc_half_done = 0;

    if (HAL_ADC_Start_DMA(
            &hadc1,
            (uint32_t *)adc_buffer,
            ADC_BUFFER_SIZE) != HAL_OK)
    {
        Error_Handler();
    }
}

void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc == &hadc1)
    {
        adc_half_done = 1;
    }
}

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc == &hadc1)
    {
        adc_conversion_done = 1;
    }
}

This example assumes the ADC and DMA have already been configured and that the selected ADC mode produces the expected sequence of conversions.

5.3 Convert ADC Samples into Voltage

For an ideal N-bit ADC with reference voltage VREF, a common approximation is: 

Voltage = (ADC_Code / (2^N - 1)) * VREF

For a 12-bit ADC and a 3.3 V reference:

float ADC_To_Voltage(uint16_t adc_value)
{
    return ((float)adc_value * 3.3f) / 4095.0f;
}

Example: an ADC result of 2048 corresponds to approximately 1.65 V.

Use the actual reference voltage and resolution for the selected device. ADC calibration, input settling time and analog front-end design affect measurement accuracy.

6. Circular DMA and Continuous Data Acquisition

Circular DMA is useful when a peripheral continuously produces or receives data. The DMA controller repeatedly fills the configured memory buffer. 

DMA Buffer

+-----------------------+
| First Half            |
|                       |
+-----------------------+
| Second Half           |
|                       |
+-----------------------+

Half Transfer:
CPU processes first half
while DMA fills second half.

Transfer Complete:
CPU processes second half
while DMA returns to first half.

Example Buffer

#define BUFFER_SIZE 100

uint16_t adc_buffer[BUFFER_SIZE];

With circular mode and suitable interrupt configuration, the half-transfer callback indicates that the first half is ready, while the complete-transfer callback indicates that the second half is ready.

Half-Transfer Callback

void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc == &hadc1)
    {
        /* First half is available for processing. */
    }
}

Complete-Transfer Callback

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc == &hadc1)
    {
        /* Second half is available for processing
           in circular DMA mode. */
    }
}
A callback should not perform lengthy calculations or blocking operations. Signal the main loop or a task to process the completed buffer region. Processing must finish before DMA overwrites that region. Use a suitable ownership or synchronization scheme.

7. Normal DMA vs Circular DMA in Peripheral Applications

Feature Normal Mode Circular Mode
Transfer Finite transfer Repeated transfer
Completion Stops after completion Reloads and continues
UART use Fixed message or block Continuous receive where supported
SPI use Finite device transaction Repeated streaming where supported
ADC use Finite sample collection Continuous sampling

8. DMA Configuration Checklist

  • Enable the peripheral clock.
  • Configure the required GPIO alternate function or analog mode.
  • Select the correct DMA request mapping.
  • Configure the transfer direction.
  • Set correct peripheral and memory data widths.
  • Set peripheral and memory increment appropriately.
  • Choose normal or circular mode.
  • Configure the DMA interrupt and NVIC if required.
  • Link DMA handles to the peripheral HAL handle.
  • Check the buffer address, size and lifetime.
  • Check DMA-accessible memory regions.
  • Check cache coherency on applicable MCUs.
  • Handle transfer completion and errors.

9. DMA Troubleshooting

Problem Possible Cause Solution
UART data missing Wrong DMA request or UART configuration. Verify request, baud rate and peripheral setup.
UART reception stops Normal mode completed or buffer full. Restart reception or use suitable circular/receive-to-idle operation.
SPI data incorrect Wrong CPOL, CPHA, data size or CS timing. Check the slave datasheet and SPI configuration.
ADC samples repeat ADC sequence or DMA mode is incorrect. Check conversion sequence and DMA configuration.
DMA callback missing IRQ, callback or interrupt configuration issue. Check NVIC, IRQ handler and HAL setup.
Buffer values corrupted CPU/DMA access conflict or cache issue. Coordinate buffer access and cache maintenance.

10. Important Technical Considerations

Buffer Lifetime

DMA can continue accessing memory after the function that started the transfer has returned. Keep the buffer valid until the operation completes or is stopped.

Buffer Ownership

During a receive operation, DMA owns the active buffer region while it is writing. The CPU should process only regions that are known to be complete and not currently being overwritten.

Data Alignment

Match DMA transfer widths and memory element types. For example, a 12-bit ADC result is often stored in a 16-bit buffer.

Cache Coherency

On cache-equipped MCUs, CPU cache maintenance may be required before or after DMA transfers. Volatile does not make cached data coherent.

DMA Throughput

The configured DMA rate must be sufficient for the peripheral data rate. Bus contention, memory access restrictions and conversion timing can limit throughput.

DMA request mapping, channel/stream selection, transfer widths, ADC sequence behavior and HAL callback signatures vary across STM32 families and HAL versions. Use CubeMX-generated code and the exact reference manual as the starting point for a real project.

11. Placement Interview Questions and Answers

Q1. Why is DMA used with UART?

It transfers UART data between the peripheral and memory without requiring the CPU to handle every byte.

Q2. Which HAL function starts UART transmission using DMA?

HAL_UART_Transmit_DMA().

Q3. Which HAL function starts UART reception using DMA?

HAL_UART_Receive_DMA().

Q4. Why is DMA useful with SPI?

It efficiently transfers larger SPI data blocks and can support simultaneous transmit and receive operations.

Q5. Which HAL function starts full-duplex SPI DMA?

HAL_SPI_TransmitReceive_DMA().

Q6. Why is ADC DMA commonly used?

It collects repeated ADC conversion results into memory with reduced CPU involvement.

Q7. Which HAL function starts ADC DMA?

HAL_ADC_Start_DMA().

Q8. What is circular DMA?

It repeatedly uses the configured buffer by reloading the transfer count after reaching the end.

Q9. What is half-transfer callback?

It notifies the application that half of the configured DMA transfer has completed.

Q10. What is double-buffer or ping-pong processing?

It uses two buffers or buffer regions so one can be processed while another receives new data. Hardware double-buffer support depends on the DMA controller.

Q11. Why should DMA callbacks be short?

Long callback execution increases interrupt latency and can delay other real-time work.

Q12. What can cause ADC DMA buffer corruption?

Incorrect transfer width, buffer ownership conflicts, invalid memory placement, cache coherency issues or incorrect DMA configuration.
