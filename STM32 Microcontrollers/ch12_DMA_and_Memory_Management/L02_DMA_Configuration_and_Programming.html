2. DMA Configuration Overview

3. Important DMA Configuration Parameters

Parameter Description
Request Selection Selects the peripheral request or DMA routing.
Direction Defines the direction of data movement.
Peripheral Address Address of the peripheral register.
Memory Address Address of the memory buffer.
Peripheral Increment Controls peripheral address advancement.
Memory Increment Controls memory address advancement.
Peripheral Data Width Size of each peripheral transfer item.
Memory Data Width Size of each memory transfer item.
Mode Normal or circular, where supported.
Priority DMA arbitration priority.

4. DMA Configuration Using STM32CubeMX

Step 1: Open the STM32 Project

Open the project in STM32CubeIDE and launch the MCU configuration view.

Step 2: Enable the Peripheral

Select the peripheral that will use DMA, such as ADC, UART, SPI or another supported peripheral.

Step 3: Open DMA Settings

Locate the DMA configuration section for the selected peripheral.

Step 4: Add the DMA Request

Select the required DMA request. Depending on the MCU, the request may be assigned through a channel, stream/channel combination or DMAMUX.

Step 5: Configure Transfer Parameters

  • Direction
  • Mode
  • Peripheral increment
  • Memory increment
  • Peripheral and memory data width
  • Priority

Step 6: Configure Interrupts

Enable the required DMA interrupt handling for half-transfer, transfer-complete or error events.

Step 7: Generate Code

Generate the project code and inspect the DMA initialization and peripheral setup.

CubeMX configuration options and generated code differ across STM32 families. Confirm the generated request mapping against the selected MCU documentation.

5. DMA Initialization Structure

Many STM32 HAL generations use a DMA initialization structure to configure transfer properties.

Illustrative HAL configuration:

DMA_HandleTypeDef hdma_usart2_tx;

void MX_DMA_Init(void)
{
    /* Enable the DMA clock using the
       family-specific RCC macro. */

    hdma_usart2_tx.Init.Direction =
        DMA_MEMORY_TO_PERIPH;

    hdma_usart2_tx.Init.PeriphInc =
        DMA_PINC_DISABLE;

    hdma_usart2_tx.Init.MemInc =
        DMA_MINC_ENABLE;

    hdma_usart2_tx.Init.PeriphDataAlignment =
        DMA_PDATAALIGN_BYTE;

    hdma_usart2_tx.Init.MemDataAlignment =
        DMA_MDATAALIGN_BYTE;

    hdma_usart2_tx.Init.Mode =
        DMA_NORMAL;

    hdma_usart2_tx.Init.Priority =
        DMA_PRIORITY_MEDIUM;

    /* Set Instance, request mapping,
       initialize handle and link it
       to the peripheral as required. */
}
This is an illustrative parameter example, not a complete portable initialization routine. The DMA instance, request selection, clock enable, initialization function, IRQ setup and handle linking are family-specific. CubeMX-generated code is usually the safest starting point.

6. Important STM32 HAL DMA Functions

Function Purpose
HAL_DMA_Init() Initializes a DMA handle.
HAL_DMA_Start() Starts a basic DMA transfer.
HAL_DMA_Start_IT() Starts a transfer with interrupt handling.
HAL_DMA_PollForTransfer() Waits for a configured DMA transfer event.
HAL_DMA_Abort() Aborts a DMA transfer.
HAL_DMA_DeInit() Deinitializes a DMA handle.

Peripheral-specific HAL functions such as HAL_UART_Transmit_DMA() and HAL_ADC_Start_DMA() are generally preferred when transferring data through a peripheral.

7. Memory-to-Memory DMA Transfer

This example copies a block of data from one memory buffer to another using DMA. It assumes that the selected STM32 DMA controller supports memory-to-memory transfers.

Source and Destination Buffers

#include "main.h"
#include <stdint.h>

#define BUFFER_SIZE 8

uint32_t source_buffer[BUFFER_SIZE] =
{
    10, 20, 30, 40,
    50, 60, 70, 80
};

uint32_t destination_buffer[BUFFER_SIZE] = {0};

DMA_HandleTypeDef hdma_memcpy;

volatile uint8_t dma_transfer_done = 0;
volatile uint8_t dma_transfer_error = 0;

DMA Completion Callback

void HAL_DMA_XferCpltCallback(DMA_HandleTypeDef *hdma)
{
    if (hdma == &hdma_memcpy)
    {
        dma_transfer_done = 1;
    }
}

DMA Error Callback

void HAL_DMA_XferErrorCallback(DMA_HandleTypeDef *hdma)
{
    if (hdma == &hdma_memcpy)
    {
        dma_transfer_error = 1;
    }
}

Start Transfer

void Start_Memory_DMA_Transfer(void)
{
    dma_transfer_done = 0;
    dma_transfer_error = 0;

    if (HAL_DMA_Start_IT(
            &hdma_memcpy,
            (uint32_t)source_buffer,
            (uint32_t)destination_buffer,
            BUFFER_SIZE) != HAL_OK)
    {
        Error_Handler();
    }
}

Verify Transfer

uint8_t Verify_DMA_Transfer(void)
{
    for (uint32_t i = 0; i < BUFFER_SIZE; i++)
    {
        if (source_buffer[i] != destination_buffer[i])
        {
            return 0;
        }
    }

    return 1;
}
Before using this example, configure and initialize a valid memory-to-memory DMA handle, including its DMA instance, direction, word alignment, memory increment, interrupt and IRQ handler. The DMA transfer count is the number of transfer items, not the number of bytes. Address casts and HAL APIs should match the selected toolchain and STM32 HAL version.

8. DMA Interrupt Handler

The DMA interrupt handler forwards the interrupt to the HAL DMA handler when using the HAL interrupt mechanism. 

void DMAx_Streamy_IRQHandler(void)
{
    HAL_DMA_IRQHandler(&hdma_memcpy);
}

Replace the example handler name with the exact IRQ handler generated for the selected STM32 DMA controller.

  • Enable the relevant DMA interrupt sources.
  • Enable the corresponding NVIC IRQ.
  • Use the correct DMA handle in the handler.
  • Check transfer-complete and error callbacks.

9. Peripheral DMA vs Direct DMA API

A direct DMA API starts a transfer using a DMA handle. A peripheral-specific HAL API also coordinates the peripheral operation with its associated DMA handle.

API Example Typical Use
Direct DMA HAL_DMA_Start_IT() Standalone supported DMA transfer.
UART DMA HAL_UART_Transmit_DMA() UART transmission.
ADC DMA HAL_ADC_Start_DMA() ADC sample acquisition.
SPI DMA HAL_SPI_TransmitReceive_DMA() SPI data exchange.
Use the peripheral-specific API for normal peripheral communication. It coordinates peripheral state, DMA operation and callbacks through the relevant HAL driver.

10. DMA Buffer Management

A DMA buffer stores data being transferred. The buffer must remain valid and accessible until the transfer is complete or safely stopped.

Example

uint8_t tx_buffer[] = "STM32 DMA Example";

void Start_UART_DMA(void)
{
    HAL_UART_Transmit_DMA(
        &huart2,
        tx_buffer,
        sizeof(tx_buffer) - 1U
    );
}

Important Buffer Rules

  • Do not use a local stack buffer that goes out of scope before transfer completion.
  • Do not modify a transmit buffer while DMA is reading it.
  • Do not process a receive buffer while DMA is writing the same region.
  • Use correct buffer length and data width.
  • Handle half-transfer and complete-transfer events when required.
  • Use suitable alignment and memory regions for the selected DMA engine.

11. DMA Error Handling

DMA errors can result from invalid addresses, transfer configuration problems, unsupported memory regions or peripheral timing issues.

Problem Possible Cause Action
No transfer DMA not enabled or wrong request. Check initialization and request routing.
Wrong data Incorrect width or increment. Verify data alignment and addresses.
Callback missing IRQ not enabled or handler incorrect. Check NVIC and HAL handler forwarding.
Transfer error Invalid access or unsupported memory. Check memory map and DMA access restrictions.
Corrupted buffer CPU and DMA access conflict. Coordinate buffer ownership.

12. Debugging DMA in STM32CubeIDE

  1. Build the project and resolve compilation errors.
  2. Set a breakpoint before starting DMA.
  3. Inspect the DMA handle configuration.
  4. Verify source and destination addresses.
  5. Check the transfer count and data widths.
  6. Start the transfer and inspect the DMA status.
  7. Set breakpoints in completion and error callbacks.
  8. Inspect the destination buffer after completion.
  9. Check the relevant DMA and NVIC registers if needed.
A debugger memory view can help verify buffer contents. On cache-equipped STM32 devices, account for cache coherency before interpreting CPU-visible memory values.

13. Placement Interview Questions and Answers

Q1. What are the main DMA configuration parameters?

Request selection, direction, source and destination addresses, transfer count, data widths, increment settings, mode and priority.

Q2. What is DMA initialization?

It is the process of configuring the DMA controller and its handle before starting a transfer.

Q3. Which HAL function initializes DMA?

HAL_DMA_Init().

Q4. Which HAL function starts a DMA transfer?

HAL_DMA_Start() or HAL_DMA_Start_IT().

Q5. Why is memory increment enabled?

It allows successive transfer items to be stored in consecutive memory locations.

Q6. Why is peripheral increment commonly disabled?

Because a peripheral data register usually remains at one fixed address.

Q7. What is DMA transfer count?

It specifies the number of data items to transfer, subject to the DMA controller's transfer-count definition.

Q8. Why are peripheral-specific DMA APIs useful?

They coordinate DMA with the peripheral driver, including its state and callback handling.

Q9. Why must a DMA buffer remain valid?

DMA accesses the memory buffer independently of the lifetime of the function that started the transfer.

Q10. How do you debug a DMA transfer?

Check configuration, request routing, addresses, transfer count, IRQ setup, callbacks and destination memory.

Q11. What is the difference between HAL_DMA_Start and HAL_DMA_Start_IT?

The interrupt version enables configured DMA interrupt events and callback handling. The exact behavior depends on the HAL implementation and configuration.

Q12. What is a DMA transfer error?

It is an error reported by the DMA controller when a transfer cannot complete correctly.

15. Lesson Summary

  • DMA requires configuration before transfer.
  • CubeMX helps configure DMA request routing and parameters.
  • Data width and address increment must match the application.
  • HAL provides direct and peripheral-specific DMA APIs.
  • Buffers must remain valid throughout transfers.
  • Interrupts support transfer completion and error handling.
  • Memory accessibility and cache coherency matter on applicable MCUs.
  • STM32CubeIDE helps debug DMA configuration and buffer contents.
