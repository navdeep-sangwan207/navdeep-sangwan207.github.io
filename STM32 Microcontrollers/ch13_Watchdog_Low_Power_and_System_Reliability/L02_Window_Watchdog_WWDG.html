2. What Is a Window Watchdog?

The Window Watchdog (WWDG) is a hardware watchdog peripheral available on selected STM32 microcontrollers. It requires the application to refresh its counter during a permitted time window.

Unlike a simple timeout watchdog, WWDG can detect two types of incorrect behavior:

  • Early refresh: The application refreshes before the permitted window opens.
  • Late refresh: The application fails to refresh before the counter reaches its timeout condition.

WWDG is useful when the firmware must demonstrate that its execution timing is within an expected range, not merely that it eventually refreshes the watchdog.

4. WWDG Counter and Window Value

In common STM32 implementations, the WWDG counter starts in the range 0x40 to 0x7F. The window value determines the earliest permitted counter value for refreshing.

Example

Assume:

  • Initial counter value = 0x7F
  • Window value = 0x60

The counter decreases over time. Refreshing is permitted only after the counter has reached the allowed window.

In common STM32 WWDG implementations, refreshing while the counter is greater than the programmed window value causes a reset. The counter must also be refreshed before it reaches the reset boundary.

5. WWDG Registers

A common STM32 WWDG implementation uses the following registers.

Register Purpose
WWDG_CR Control register containing the counter and activation bit.
WWDG_CFR Configuration register containing prescaler, window value and interrupt enable.
WWDG_SR Status register, including the Early Wakeup Interrupt flag.

Important Fields

  • T[6:0]: Seven-bit watchdog counter.
  • WDGA: Watchdog activation bit in common implementations.
  • W[6:0]: Window value.
  • WDGTB: Prescaler selection field.
  • EWI: Early Wakeup Interrupt enable.

The exact bit positions and register definitions must be checked in the reference manual for the selected STM32.

6. WWDG Timeout Calculation

In common STM32 WWDG implementations, the counter clock is derived from PCLK1.

Counter Clock Formula

WWDG Counter Clock =
PCLK1 / (4096 x Prescaler Division Factor)

Timeout Formula

Timeout =
(Counter Start - Counter End)
--------------------------------
       WWDG Counter Clock

For a common STM32 implementation, the counter starts from the programmed value and reset occurs when the counter reaches the 0x3F boundary.

Calculation Example

Assume:

  • PCLK1 = 42 MHz
  • Prescaler division factor = 8
  • Counter start = 0x7F = 127
  • Counter end boundary = 0x3F = 63
Counter Clock =
42,000,000 / (4096 x 8)

Counter Clock = 1281.25 Hz

Timeout =
(127 - 63) / 1281.25

Timeout = 0.04995 seconds

Timeout ≈ 49.95 ms
This is a nominal example based on a common STM32 WWDG counter model. Check the exact counter decrement and reset conditions in the selected device reference manual. The allowed refresh interval also depends on the window value.

7. Refresh Window Operation

WWDG refresh must occur after the counter enters the permitted window and before it reaches the reset boundary.

Refresh Condition Result
Counter greater than window value Early refresh; reset is generated.
Counter within permitted window Refresh is accepted.
Counter reaches reset boundary Watchdog reset is generated.

9. WWDG Programming Using STM32 HAL

The following example uses a common STM32 HAL configuration style. The selected device and HAL version must support the shown WWDG fields and functions.

Step 1: Declare the Handle

WWDG_HandleTypeDef hwwdg;

Step 2: Initialize WWDG

void MX_WWDG_Init(void)
{
    hwwdg.Instance = WWDG;

    hwwdg.Init.Prescaler = WWDG_PRESCALER_8;
    hwwdg.Init.Window = 0x60;
    hwwdg.Init.Counter = 0x7F;

    if (HAL_WWDG_Init(&hwwdg) != HAL_OK)
    {
        Error_Handler();
    }
}

Step 3: Refresh WWDG

void WWDG_Refresh(void)
{
    if (HAL_WWDG_Refresh(&hwwdg) != HAL_OK)
    {
        Error_Handler();
    }
}

Step 4: Main Application Concept

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_WWDG_Init();

    while (1)
    {
        Application_Task();

        if (Application_Health_Check())
        {
            /*
             * Refresh only when the counter
             * has entered the permitted window.
             */
            WWDG_Refresh();
        }
    }
}
The example shows the initialization and refresh APIs, not a complete timing solution. A production application must schedule the refresh inside the actual permitted window. An unconditional or too-early refresh can cause an immediate reset.

10. Early Wakeup Interrupt (EWI)

Some STM32 WWDG implementations provide an Early Wakeup Interrupt. It can notify the application shortly before the watchdog reaches its reset condition.

Purpose of EWI

  • Provide an early warning of an impending watchdog reset.
  • Record diagnostic information where time permits.
  • Update a fault indicator.
  • Support controlled diagnostic actions.

HAL Callback Example

void HAL_WWDG_EarlyWakeupCallback(
    WWDG_HandleTypeDef *hwwdg)
{
    /*
     * Keep this callback short.
     * Set a diagnostic flag or record
     * minimal fault information.
     */
    fault_warning = 1U;
}

The interrupt handler must call the appropriate HAL WWDG handler for the selected device.

EWI timing and callback support vary by device and HAL version. Do not depend on lengthy processing or blocking operations before the impending reset.

11. IWDG vs WWDG

Feature IWDG WWDG
Full Name Independent Watchdog Window Watchdog
Typical Clock LSI PCLK1-derived clock
Refresh Rule Refresh before timeout Refresh within permitted window
Early Refresh Detection Not normally provided Yes
Late Refresh Detection Yes Yes
Clock Independence Independent of main clock on typical implementations Typically derived from peripheral clock
Typical Use General software recovery Monitoring execution timing

Both watchdogs improve reliability, but their clock sources and refresh behavior make them suitable for different application requirements.

14. Placement Interview Questions and Answers

Q1. What is WWDG?

WWDG is a Window Watchdog that requires the application to refresh its counter within a permitted timing window.

Q2. Why is it called a Window Watchdog?

Because the counter can only be refreshed during a defined window of time.

Q3. What happens if WWDG is refreshed too early?

In common STM32 implementations, an early refresh causes a watchdog reset.

Q4. What happens if WWDG is not refreshed?

The counter reaches its reset boundary and the microcontroller is reset.

Q5. What clock is commonly used by WWDG?

WWDG commonly derives its counter clock from PCLK1.

Q6. What is the purpose of the window register?

It defines the counter threshold at which refreshing becomes permitted.

Q7. What is EWI?

EWI stands for Early Wakeup Interrupt. It can provide an interrupt before the watchdog reset condition.

Q8. What is the main difference between IWDG and WWDG?

IWDG normally checks whether the application refreshes before timeout. WWDG additionally checks that refreshing does not occur too early.

Q9. Why must PCLK1 be calculated correctly?

Because the WWDG counter clock is commonly derived from PCLK1, so an incorrect clock assumption produces an incorrect timeout.

Q10. Where is WWDG useful?

It is useful in embedded applications where firmware execution must remain within expected timing limits.

16. Lesson Summary

  • WWDG is a hardware watchdog with a refresh window.
  • Refreshing too early can generate a reset.
  • Failing to refresh before timeout also generates a reset.
  • The window register controls the permitted refresh threshold.
  • WWDG commonly uses a clock derived from PCLK1.
  • EWI can provide an early warning interrupt.
  • WWDG availability and features vary across STM32 devices.
  • Refresh timing must be designed and tested carefully.
