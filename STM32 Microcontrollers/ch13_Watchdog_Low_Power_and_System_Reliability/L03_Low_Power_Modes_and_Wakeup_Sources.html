2. Introduction to Low Power Design

Low-power design is the process of reducing the electrical power consumed by an embedded system while maintaining the required functionality and response time.

Battery-powered devices must minimize energy consumption to increase operating time. Examples include wireless sensors, wearable devices, portable instruments and remote monitoring systems.

Why Is Low Power Important?

  • Reduces heat generation.

3. STM32 Low Power Modes

Many STM32 microcontrollers provide three major low-power modes: Sleep, Stop and Standby. Some families also provide additional modes, such as Shutdown.

1. Sleep Mode

In Sleep mode, the CPU core stops executing instructions, while clocks and peripherals may continue operating depending on the clock configuration.

  • CPU execution stops.
  • Peripheral operation may continue.
  • Interrupts can wake the CPU.
  • Wakeup is generally fast.
  • It is useful during short periods of inactivity.

2. Stop Mode

In Stop mode, the CPU and many clock sources are stopped to reduce power consumption. SRAM and register contents are generally retained in supported Stop configurations.

  • CPU execution stops.
  • High-speed clocks are generally stopped.
  • SRAM and peripheral register retention depend on the device and mode.
  • Selected interrupts or events can wake the MCU.
  • Clock restoration may be required after wakeup.

3. Standby Mode

Standby mode provides much lower power consumption than ordinary Sleep operation. Most of the device is powered down, while selected backup or wakeup resources remain active.

  • Main CPU execution stops.
  • Most SRAM and peripheral state is lost on many devices.
  • Selected backup resources may remain powered.
  • Wakeup commonly causes a reset-like startup sequence.
  • It is useful for long idle periods.
Exact low-power modes, retained memory, available wakeup sources and clock behavior vary significantly across STM32 families. Always consult the reference manual and datasheet for the selected part.

5. Cortex-M Sleep Instruction

ARM Cortex-M processors provide the WFI and WFE instructions to enter a sleep state.

WFI – Wait For Interrupt

WFI suspends instruction execution until an eligible interrupt or event causes the processor to resume, according to the core's interrupt and event rules. 

while (1)
{
    /* Perform application work. */

    __WFI();
}

WFE – Wait For Event

WFE suspends execution until an event occurs. Events can be generated by supported interrupt/event mechanisms or software event signaling. 

while (1)
{
    /* Wait for an event. */

    __WFE();
}

WFI vs WFE

WFI WFE
Wait For Interrupt Wait For Event
Responds to eligible interrupt conditions. Responds to event-register and event signaling conditions.
Commonly used for interrupt-driven idle loops. Useful for event-driven synchronization.
WFI and WFE are processor instructions. Entering a deeper STM32 Stop or Standby mode also requires the relevant power-control configuration. The instructions alone do not configure every low-power peripheral or wakeup requirement.

6. Wakeup Sources

A wakeup source is an event or signal that causes a microcontroller to leave a low-power state.

Common Wakeup Sources

  • External GPIO interrupt or wakeup pin.
  • RTC alarm.
  • RTC wakeup timer.
  • Timer event, where supported in the selected mode.
  • Communication peripheral event, where supported.
  • Watchdog or reset-related event, depending on device behavior.

External GPIO Wakeup

A button or external signal can be configured to generate an interrupt or wakeup event on a supported pin.

RTC Wakeup

The Real-Time Clock can generate an alarm or periodic wakeup event. This is useful when the MCU must remain asleep for a defined time interval.

Not every GPIO, timer or communication peripheral can wake every STM32 low-power mode. Check the device wakeup-source table and the required pin configuration.

7. Sleep Mode Programming Using HAL

The following example demonstrates a basic Sleep-mode entry using the Cortex-M WFI instruction. 

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        /*
         * Perform application work.
         */

        /*
         * Enter processor Sleep state.
         */
        HAL_SuspendTick();

        HAL_PWR_EnterSLEEPMode(
            PWR_MAINREGULATOR_ON,
            PWR_SLEEPENTRY_WFI
        );

        HAL_ResumeTick();
    }
}

In this example, the SysTick interrupt is suspended before Sleep entry and restored after wakeup.

HAL_PWR_EnterSLEEPMode parameters and behavior depend on the HAL family and version. Suspending SysTick changes HAL timekeeping during Sleep. Ensure another suitable wakeup source is configured if the application needs periodic wakeup.

8. Stop Mode Programming Using HAL

Stop mode can reduce power by stopping high-speed clocks and placing the CPU into a deeper low-power state.

Typical Configuration Sequence

  1. Complete current application work.
  2. Save any required application state.
  3. Configure a supported wakeup source.
  4. Disable unnecessary peripherals.
  5. Configure the power-control registers.
  6. Enter Stop mode.
  7. Wait for the wakeup event.
  8. Restore the required system clock configuration.
  9. Resume application execution.

Illustrative HAL Code

void Enter_Stop_Mode(void)
{
    /*
     * Configure an appropriate wakeup source
     * before entering Stop mode.
     */

    HAL_SuspendTick();

    HAL_PWR_EnterSTOPMode(
        PWR_LOWPOWERREGULATOR_ON,
        PWR_STOPENTRY_WFI
    );

    /*
     * Execution resumes after wakeup.
     * Restore the required system clock.
     */
    SystemClock_Config();

    HAL_ResumeTick();
}
This is an illustrative pattern for HAL families that provide this API. The exact Stop mode, regulator selection, wakeup configuration and clock restoration sequence are device-specific. Do not assume the system clock automatically returns to its previous frequency.

9. Standby Mode Programming Using HAL

Standby mode is intended for very low-power operation. On many STM32 devices, a wakeup event causes a reset-like restart rather than returning to the instruction immediately after the Standby entry call.

Typical Configuration Sequence

  1. Save essential information in a retained location if supported.
  2. Configure a valid Standby wakeup source.
  3. Clear any stale wakeup flags as required by the device.
  4. Enter Standby mode.
  5. Wait for the selected wakeup source.
  6. After wakeup, execute startup code again.
  7. Inspect reset and wakeup flags.
  8. Restore the application state if required.

Illustrative HAL Code

void Enter_Standby_Mode(void)
{
    /*
     * Configure the required Standby
     * wakeup source before this function.
     */

    HAL_PWR_EnterSTANDBYMode();

    /*
     * On common STM32 implementations,
     * normal execution does not continue
     * beyond this point after wakeup.
     */
}
Standby wakeup configuration and flag handling vary by STM32 family. Do not assume the same HAL wakeup-pin or RTC APIs work on every STM32 device.

10. Real-Time Clock (RTC) Wakeup

RTC is a low-power timekeeping peripheral that can maintain time and generate scheduled events using an appropriate low-speed clock source.

RTC Applications

  • Periodic sensor data collection.
  • Scheduled system wakeup.
  • Time and date tracking.
  • Battery-powered monitoring systems.
  • Low-power data logging.

RTC clock sources commonly include LSE or LSI, depending on the selected device and accuracy requirements.

RTC wakeup support depends on the selected low-power mode and MCU. An RTC event may wake some modes but not necessarily every mode or every STM32 variant.

11. Low Power Design Techniques

  • Use Sleep mode during short idle periods.
  • Use Stop or Standby when longer inactivity is expected.
  • Disable unused peripheral clocks.
  • Configure GPIO pins to suitable low-leakage states.
  • Reduce unnecessary CPU clock frequency.
  • Use DMA to reduce CPU activity when appropriate.
  • Use RTC events instead of continuous polling for scheduled tasks.
  • Choose suitable regulator and voltage-scaling options where supported.
  • Reduce unnecessary LED and external circuit current.
  • Measure actual current consumption on the target board.
Floating GPIO pins, external pull resistors, debug interfaces, regulator configuration and board-level components can significantly affect measured current. MCU datasheet current values are not the same as complete development-board current.

12. Low Power Application Example

Project: Periodic Sensor Monitoring

A battery-powered sensor node measures temperature periodically and transmits the reading before returning to a low-power state.

Operating Sequence

  1. Initialize the STM32 and RTC.
  2. Wait in a supported low-power mode.
  3. RTC generates a scheduled wakeup event.
  4. STM32 resumes execution or restarts, depending on the mode.
  5. Read the temperature sensor.
  6. Transmit the measured value.
  7. Update the required application state.
  8. Configure the next wakeup.
  9. Enter low-power mode again.
while (1)
{
    Read_Temperature();

    Process_Sensor_Data();

    Transmit_Data();

    Configure_Next_Wakeup();

    Enter_Selected_Low_Power_Mode();
}

This is a high-level application sequence. A real Standby implementation may restart from startup after wakeup and must restore its application state appropriately.

14. Placement Interview Questions and Answers

Q1. Why are low-power modes required?

They reduce energy consumption and increase battery life in portable and remote embedded systems.

Q2. What are the major STM32 low-power modes?

Common modes include Sleep, Stop and Standby. Some STM32 families also provide Shutdown and additional low-power variants.

Q3. What is Sleep mode?

Sleep mode stops CPU execution while allowing selected clocks and peripherals to continue operating.

Q4. What is Stop mode?

Stop mode stops the CPU and many clock sources to reduce power while retaining selected device state.

Q5. What is Standby mode?

Standby is a deeper low-power mode in which most of the device is powered down. Wakeup commonly causes a startup sequence.

Q6. What is the difference between WFI and WFE?

WFI means Wait For Interrupt, while WFE means Wait For Event. They are processor instructions used to suspend execution until the appropriate interrupt or event condition occurs.

Q7. What is a wakeup source?

A wakeup source is an interrupt, event or hardware signal that causes the microcontroller to leave a low-power state.

Q8. What is RTC?

RTC stands for Real-Time Clock. It maintains time and can generate alarms or scheduled wakeup events.

Q9. Does Standby preserve SRAM?

Many STM32 Standby implementations do not retain ordinary SRAM. Retention behavior must be checked for the specific device.

Q10. Why is clock restoration required after Stop mode?

Some high-speed clock sources stop during Stop mode. After wakeup, the application may need to reconfigure the clock tree to restore its intended operating frequency.

Q11. How can battery life be improved?

Use appropriate low-power modes, disable unused peripherals, reduce unnecessary CPU activity and measure system current.

Q12. Which low-power mode should be selected?

Select the mode based on required current consumption, wakeup latency, state retention, available wakeup sources and application response-time requirements.
