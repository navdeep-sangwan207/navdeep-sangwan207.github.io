Lesson 4: STM32 Nucleo Boards and Development Boards

Board Architecture, Hardware Components, ST-LINK and Practical Setup

1. Learning Objectives

  • Understand the purpose of STM32 development boards.
  • Identify STM32 Nucleo board features.
  • Understand the role of the onboard ST-LINK debugger.
  • Identify important board connectors, pins and components.
  • Understand GPIO headers and peripheral connections.
  • Learn the basic process of programming an STM32 board.
  • Understand important hardware precautions.

2. What is an STM32 Development Board?

An STM32 development board is a ready-to-use hardware platform containing an STM32 microcontroller and supporting circuitry. It allows developers to write, test, program and debug firmware without designing a complete custom PCB first.

Typical Board Components

  • STM32 microcontroller.
  • Power supply and voltage regulation circuitry.
  • USB connector.
  • Programming and debugging interface.
  • GPIO expansion headers.
  • User LEDs and push buttons.
  • Reset circuit.
  • Clock source, where provided.

3. What is an STM32 Nucleo Board?

STM32 Nucleo boards are development platforms from STMicroelectronics designed to make STM32 evaluation and application development easier.

Many Nucleo boards include an onboard ST-LINK debugger/programmer, expansion headers and a user LED and button. Exact features depend on the particular board model.

Advantages of Nucleo Boards

  • Convenient STM32 development platform.
  • Onboard programming and debugging on many models.
  • GPIO access through expansion headers.
  • Support for STM32CubeIDE and STM32CubeMX workflows.
  • Useful for peripheral experiments and prototype development.
  • Many boards support compatible expansion shields.

5. Important Components on a Nucleo Board

1. STM32 Microcontroller

The main IC that executes firmware and controls the board's peripherals.

2. ST-LINK Debugger/Programmer

The ST-LINK interface communicates with a compatible STM32 device for firmware programming and debugging. Depending on the board, it can connect to the target through SWD or another supported debug interface.

3. USB Connector

Used for power, programming/debugging communication or other USB functions depending on the board design.

4. GPIO Expansion Headers

These headers provide access to selected MCU pins so external sensors, displays and modules can be connected.

5. User LED

A board-mounted LED can be controlled by configuring its connected GPIO pin as an output.

6. User Push Button

A push button is commonly connected to a GPIO input and can be used to test polling or interrupt-based input.

7. Reset Button

The reset button resets the target microcontroller and restarts its program execution.

8. Clock Source

The board may contain an external oscillator or crystal used as a clock source. The exact clock arrangement depends on the board design and MCU.

6. Understanding GPIO Headers

GPIO headers expose selected microcontroller pins for connecting external devices. A header pin may support several alternate functions.

Pin Function Purpose
GPIO Digital input and output.
UART TX/RX Serial communication.
I2C SDA/SCL Two-wire serial communication.
SPI MOSI/MISO/SCK Synchronous serial communication.
ADC Input Analog voltage measurement.
PWM Output Timer-based pulse-width modulation.
GND Ground reference.
Power Pin Board or external circuit supply, subject to board specifications.
Important: A physical pin may have several alternate functions, but they cannot all be used simultaneously. Check the exact board pinout and MCU datasheet before connecting external hardware.

Nucleo Development Board Custom PCB
Ready-to-use development platform. Designed for a specific product or application.

9. Basic Hardware Setup

Required Equipment

  • STM32 Nucleo development board.
  • Compatible USB cable.
  • Computer with STM32CubeIDE installed.
  • External LED and resistor for an optional GPIO exercise.
  • Jumper wires and breadboard for external connections.
  • Digital multimeter for basic voltage checks.

Setup Procedure

  1. Identify the exact Nucleo board model.
  2. Download its user manual and schematic.
  3. Install STM32CubeIDE.
  4. Connect the board using the designated USB connector.
  5. Check that the board is detected by the computer.
  6. Create a project for the exact MCU or board.
  7. Build and program a basic test application.
  8. Use the debugger to verify program execution.

10. Practical Example – Blinking an Onboard LED

A basic GPIO test is to blink the user LED on a Nucleo board. First, identify the LED pin from the board user manual.

Example HAL Code

#include "main.h"

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        HAL_GPIO_TogglePin(
            LD2_GPIO_Port,
            LD2_Pin
        );

        HAL_Delay(500);
    }
}

The symbolic names LD2_GPIO_Port and LD2_Pin must exist in the selected project's generated board configuration. They are not universal across all STM32 boards.

Expected Result

  • The onboard user LED changes state repeatedly.
  • The LED toggles approximately every 500 milliseconds.
  • The application runs continuously inside the while loop.

11. Hardware Safety Precautions

  • Check the board's allowed supply voltage before powering it.
  • Never assume all GPIO pins are 5V tolerant.
  • Verify the maximum input voltage for each MCU pin.
  • Connect external circuit ground to board ground when required by the interface.
  • Use current-limiting resistors for LEDs.
  • Avoid short circuits between power and ground.
  • Disconnect power before changing external wiring.
  • Check the pinout before connecting sensors or modules.
  • Use suitable level shifting when interfacing incompatible logic voltages.
Practical warning: A Nucleo board's 3.3V GPIO must not be assumed to tolerate 5V signals. Check the datasheet's pin-specific electrical limits and board documentation.

12. STM32 Placement Interview Questions and Answers

Q1. What is an STM32 Nucleo board?

It is an STM32 development platform that provides a microcontroller and supporting hardware for firmware development, testing and debugging.

Q2. What is ST-LINK?

ST-LINK is a programming and debugging interface used to communicate with supported STM32 microcontrollers.

Q3. Why are GPIO headers provided?

They expose selected MCU pins so external sensors, displays and other hardware can be connected.

Q4. What is the function of a reset button?

It resets the microcontroller and restarts program execution.

Q5. What is the difference between a Nucleo board and a custom PCB?

A Nucleo board is a general-purpose development platform, while a custom PCB is designed for the requirements of a particular product.

Q6. What is SWD?

Serial Wire Debug is a two-wire ARM debug interface commonly used for programming and debugging Cortex-M microcontrollers.

Q7. Can all Nucleo boards use the same pin configuration?

No. Pin assignments, peripherals, board components and alternate functions vary between board models.

Q8. What is the purpose of a user LED?

It provides a simple visual output for testing GPIO configuration and firmware execution.

Q9. Why should the board user manual be checked?

It provides board-specific information such as pin assignments, power configuration, connectors, jumpers and onboard components.

Q10. What is the first practical test on a new STM32 board?

A common initial test is to create, program and debug a simple GPIO LED blinking application.

14. Lesson Summary

  • STM32 development boards simplify firmware development and testing.
