Lesson 2: STM32 Family and Microcontroller Selection

Understanding STM32 Series, Features, Specifications and Device Selection

1. Learning Objectives

  • Understand the different STM32 product families.
  • Identify the major STM32 series and their applications.
  • Understand processor core, clock speed and memory specifications.
  • Learn how to read an STM32 part number.
  • Understand how to select an appropriate STM32 microcontroller.
  • Identify the importance of datasheets and reference manuals.

2. Why Does STM32 Have Different Families?

Different embedded applications have different requirements. A simple sensor node may need low power and a small memory, whereas an industrial controller may require higher processing performance, communication interfaces and advanced timers.

To address these requirements, STMicroelectronics provides multiple STM32 product families with different processor cores, memory capacities, peripherals, performance levels and power characteristics.

Example: A battery-powered sensor may use a low-power STM32L device, while a high-performance control application may use an STM32H device.

3. Major STM32 Product Families

STM32F4 High-performance mainstream MCUs Robotics, audio and industrial systems

Placement tip: Remember the broad distinctions: F1/F4 are familiar mainstream families, G4 is useful for motor control and digital power, L/U focus on low-power applications, and H7 targets high-performance applications. Exact capabilities vary by individual part number.

The processor core influences instruction execution, performance, available instruction-set features and processing capabilities. The complete MCU specification also depends on its memory, clock configuration and peripherals.

5. Understanding STM32 Part Numbers

STM32 part numbers contain information about the product family and device variant. Consider this example:

STM32F103C8T6 is a commonly used example. Its part-number elements can be broadly interpreted as follows:

Part Meaning in This Example
STM32 STMicroelectronics 32-bit microcontroller family.
F1 STM32F1 product series.
03 Specific product line within the series.
C Pin-count/package code; for this device, 48 pins.
8 Memory-density code; this device has 64 KB Flash.
T Package code; for this part, LQFP.
6 Temperature-range code.
Important: Part-number decoding conventions are product-specific and can change between families. Use the official ordering information and datasheet rather than applying this example to every STM32 device.

6. Important Specifications for MCU Selection

1. Processor Core

Identify whether the application needs Cortex-M0+, M3, M4, M7 or another supported core.

2. Operating Frequency

The maximum supported clock frequency influences processing performance. Actual operating frequency depends on device specifications, clock configuration and operating conditions.

3. Flash Memory

Flash stores the firmware. Select sufficient capacity for application code, libraries, bootloader and stored data.

4. SRAM

SRAM stores variables, buffers, stacks and other runtime data. Communication-heavy applications may require larger buffers.

5. GPIO Pins

Check the number of available GPIOs, alternate functions, voltage tolerance and pin electrical characteristics.

6. Communication Interfaces

Verify the availability and number of UART/USART, SPI, I2C, CAN, USB, Ethernet or other required interfaces.

7. Analog Peripherals

Check ADC resolution, channel count, sampling performance, reference-voltage requirements and DAC availability.

8. Timers

Applications involving PWM, motor control, input capture and accurate timing need suitable timer peripherals.

9. Power Consumption

Battery-powered products need suitable sleep modes, low-power peripherals and efficient wake-up mechanisms.

10. Package and Cost

Consider the physical package, PCB design complexity, availability, operating temperature and product cost.

7. Example – Selecting an STM32 for Different Applications

Application Important Requirements Selection Consideration
LED and sensor controller GPIO, ADC, UART and basic timers Entry-level STM32G0 or suitable F0 device
Industrial controller Communication, timers, ADC and reliable operation Suitable STM32F4 or G4 device
Motor control PWM, advanced timers and ADC STM32G4 or another motor-control-capable device
Battery-powered sensor Low power, ADC and wireless options if required Suitable STM32L or U device
Advanced processing system High CPU performance and memory bandwidth Suitable STM32H device
These are family-level suggestions, not final component selections. Confirm exact peripheral availability, package, electrical limits and lifecycle status for the chosen part.

8. Datasheet and Reference Manual

Two essential documents are used when developing STM32 firmware:

Datasheet

  • Electrical characteristics.
  • Pin configuration and alternate functions.
  • Memory size and device specifications.
  • Operating voltage and temperature range.
  • Package and ordering information.

Reference Manual

  • Peripheral architecture.
  • Register descriptions and bit fields.
  • GPIO, timers, ADC and communication configuration.
  • Clock and reset control.
  • Interrupt and DMA configuration.

Official resource: STMicroelectronics – STM32 Microcontrollers

9. Practical Selection Exercise

Assume you need to design a temperature monitoring system with the following requirements:

  • One analog temperature sensor.
  • One UART interface for serial monitoring.
  • One I2C interface for an optional display.
  • GPIO pins for status LEDs.
  • Enough Flash and SRAM for the firmware.

Selection Procedure

  1. List all required peripherals.
  2. Check the number of ADC channels.
  3. Verify UART and I2C availability.
  4. Check GPIO count and alternate-function mapping.
  5. Estimate Flash and SRAM requirements.
  6. Check package, supply voltage and development-board availability.
  7. Verify the final selection using the datasheet and reference manual.

10. STM32 Placement Interview Questions and Answers

Q1. Why are there different STM32 families?

Different families address different requirements such as processing performance, power consumption, memory capacity, peripheral features and application cost.

Q2. What is the difference between STM32F1 and STM32F4?

STM32F1 is an older mainstream family commonly based on Cortex-M3 cores, while STM32F4 devices commonly use Cortex-M4 cores and offer enhanced processing features. Exact specifications vary by device.

Q3. Which STM32 family is suitable for low-power applications?

STM32L and STM32U families are designed for low-power applications, although the exact device should be selected according to the power and peripheral requirements.

Q4. Which STM32 family is useful for motor control?

STM32G4 is particularly relevant because selected devices provide advanced timers and analog peripherals for motor control and digital power applications.

Q5. What is the difference between Flash and SRAM?

Flash is non-volatile memory generally used for firmware storage. SRAM is volatile memory used for runtime data.

Q6. What is the purpose of an STM32 datasheet?

It provides device specifications, pin configuration, electrical characteristics, memory information and ordering details.

Q7. What is a reference manual?

A reference manual describes the internal operation of peripherals and their registers, configuration fields and programming procedures.

Q8. How do you select an STM32 microcontroller?

By evaluating processing requirements, memory, peripherals, GPIO count, power consumption, package, cost, availability and development support.

Q9. What does the C8 in STM32F103C8T6 indicate?

C indicates the package/pin-count code and 8 indicates the Flash memory-density code. For this specific device, C corresponds to 48 pins and 8 corresponds to 64 KB Flash.

Q10. Can all STM32 devices use the same firmware?

No. Firmware may require changes because devices have different cores, registers, pin mappings, peripherals, memory sizes and clock configurations.

12. Lesson Summary

  • STM32 has multiple product families for different applications.
  • F1, F4, G4, H7, L and U families have different design priorities.
  • Processor core, memory, clock, GPIO and peripherals are important selection factors.
  • Part numbers provide device identification information.
  • Datasheets and reference manuals are essential development documents.
  • Always verify exact device specifications before hardware design.
