Understand external interrupts, EXTI lines, edge detection, NVIC configuration and interrupt-based GPIO programming in STM32 microcontrollers.

2. What Is a GPIO Interrupt?

A GPIO interrupt is an event generated when a configured GPIO input detects a specified signal transition. The processor temporarily pauses its normal execution and executes an Interrupt Service Routine (ISR).

Example

Consider a push button connected to an STM32 GPIO input. When the button is pressed, the input changes from LOW to HIGH. This transition can generate an interrupt.

  • Button press generates an external interrupt.
  • Processor enters the corresponding interrupt handler.
  • Application code processes the event.
  • Processor returns to the interrupted program.

3. Polling vs Interrupt-Based GPIO

Polling Interrupt
CPU repeatedly checks the input. Hardware signals the CPU when an event occurs.
Can waste CPU time while waiting. CPU can perform other work while waiting.
Simple to implement. Requires interrupt configuration.
Detection depends on polling frequency. Responds to configured hardware events.

Polling Example

while (1)
{
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_SET)
    {
        HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);
    }
}

Interrupt-Based Approach

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        /* Handle button event */
    }
}

4. What Is EXTI?

EXTI stands for External Interrupt/Event Controller. It detects configured external signal transitions and generates interrupt or event requests.

On many STM32 families, GPIO pins are connected to EXTI lines through a port-selection mechanism. The exact EXTI architecture and register organization vary by family.

Basic EXTI Operation

  1. Configure a GPIO pin as an input.
  2. Select the GPIO port connected to the EXTI line.
  3. Configure rising-edge or falling-edge detection.
  4. Enable the EXTI interrupt request.
  5. Enable the corresponding interrupt in NVIC.
  6. Execute the ISR when the event occurs.

5. EXTI Lines and GPIO Mapping

In the common STM32F4 architecture, EXTI lines 0 to 15 correspond to GPIO pin numbers 0 to 15.

EXTI Line Possible GPIO Sources
EXTI0 PA0, PB0, PC0, etc.
EXTI1 PA1, PB1, PC1, etc.
EXTI2 PA2, PB2, PC2, etc.
EXTI3 PA3, PB3, PC3, etc.
EXTI4 PA4, PB4, PC4, etc.
EXTI5 to EXTI9 Corresponding pin numbers on selectable ports.
EXTI10 to EXTI15 Corresponding pin numbers on selectable ports.
On STM32F4, a given EXTI line can select one GPIO port source at a time. For example, EXTI0 cannot independently select both PA0 and PB0 simultaneously. Consult the selected MCU reference manual for exact mapping and available lines.

6. Rising Edge and Falling Edge Detection

Rising Edge

A rising edge occurs when a digital signal changes from LOW to HIGH. 

LOW  ______
          |
          |________ HIGH

Falling Edge

A falling edge occurs when a digital signal changes from HIGH to LOW. 

HIGH ______
           |
           |________ LOW

Both-Edge Detection

Some applications require detection of both rising and falling transitions. STM32 EXTI implementations commonly provide separate rising and falling trigger configuration.

  • Rising edge: useful for active-high button events.
  • Falling edge: useful for active-low button events.
  • Both edges: useful for monitoring transitions.

7. Important EXTI Registers

The following register names describe the common STM32F4 EXTI architecture. Newer STM32 families may use a different register organization.

Register Purpose
IMR Interrupt mask register.
EMR Event mask register.
RTSR Rising trigger selection register.
FTSR Falling trigger selection register.
PR Pending register.

EXTI Interrupt Mask

The interrupt mask controls whether an EXTI line is allowed to generate an interrupt request.

Rising and Falling Trigger Selection

These registers select which signal transitions can generate an EXTI request.

Pending Register

The pending register records a detected interrupt condition. On STM32F4, pending bits are cleared by writing one to the corresponding bit.

8. NVIC and EXTI Relationship

EXTI detects the external event, while NVIC controls the interrupt request at the processor level.

Interrupt Flow

  1. GPIO input changes state.
  2. EXTI detects the configured edge.
  3. EXTI generates an interrupt request.
  4. NVIC accepts the enabled interrupt according to priority and masking.
  5. Processor executes the associated interrupt handler.
  6. Pending condition is acknowledged or cleared as required.
  7. Processor returns to normal execution.
Configuring EXTI alone is not sufficient. The corresponding NVIC interrupt must also be enabled, and the GPIO/EXTI source must be configured correctly.

9. GPIO External Interrupt Using STM32 HAL

STM32 HAL provides functions and callbacks for handling GPIO external interrupts.

Step 1: Configure GPIO in STM32CubeMX

  1. Select the required GPIO pin.
  2. Choose GPIO_EXTI mode.
  3. Select rising, falling or both-edge trigger.
  4. Configure the internal pull-up or pull-down if required.
  5. Enable the corresponding EXTI interrupt in NVIC settings.
  6. Generate the project code.

Step 2: HAL GPIO Initialization Example

GPIO_InitTypeDef GPIO_InitStruct = {0};

/* Enable GPIOA clock */
__HAL_RCC_GPIOA_CLK_ENABLE();

/* Configure PA0 as external interrupt input */
GPIO_InitStruct.Pin = GPIO_PIN_0;
GPIO_InitStruct.Mode = GPIO_MODE_IT_RISING;
GPIO_InitStruct.Pull = GPIO_PULLDOWN;

HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

/* Configure EXTI0 interrupt priority */
HAL_NVIC_SetPriority(EXTI0_IRQn, 2, 0);

/* Enable EXTI0 interrupt */
HAL_NVIC_EnableIRQ(EXTI0_IRQn);
This example assumes an STM32F4 device and a button circuit that produces a LOW-to-HIGH transition on PA0. The pin, pull configuration and IRQ name must match the selected MCU and board.

10. Interrupt Handler and HAL Callback

The EXTI interrupt handler calls the HAL EXTI handler. HAL then processes the interrupt and invokes the GPIO EXTI callback.

Step 1: Interrupt Handler

void EXTI0_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0);
}

Step 2: HAL Callback

volatile uint8_t button_event = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        button_event = 1;
    }
}

Step 3: Process the Event in Main

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        if (button_event != 0)
        {
            button_event = 0;

            HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        }
    }
}
MX_GPIO_Init() and SystemClock_Config() are generated or application-defined initialization functions. The button_event flag is volatile because it is shared between interrupt and main execution contexts. Volatile does not make compound operations atomic.

11. Push Button Interrupt Application

Consider a push button connected to PA0 and an LED connected to PA5 on a compatible STM32F4 development board.

Working Principle

  1. Configure PA0 as an external interrupt input.
  2. Configure PA5 as a digital output.
  3. Enable rising-edge detection for PA0.
  4. Pressing the button generates an interrupt.
  5. The callback sets an event flag.
  6. The main loop detects the flag and toggles the LED.
Expected Result: Each valid button press causes the LED to change its state. Mechanical switch bounce may cause multiple events unless debouncing is implemented.

12. Switch Debouncing

Mechanical push buttons do not always produce a clean transition. Their contacts can rapidly open and close for a short time after pressing or releasing.

This behavior is called switch bouncing.

Problems Caused by Switch Bounce

  • Multiple interrupts from one physical press.
  • Unexpected LED toggling.
  • Incorrect button event counting.
  • Unreliable user-interface behavior.

Common Debouncing Techniques

  • Software time-based debouncing.
  • Timer-based input validation.
  • Hardware RC filtering.
  • Dedicated switch-debouncing circuits.
Avoid using long blocking delays inside an ISR for debouncing. Record the event or timestamp and validate the input in the main loop or a timer-driven task.

13. Direct Register-Level EXTI Configuration

The following is a simplified STM32F4 example showing the main configuration steps for PA0 external interrupt. 

#include "stm32f4xx.h"

void EXTI0_Init(void)
{
    /* Enable GPIOA clock */
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

    /* Configure PA0 as input */
    GPIOA->MODER &= ~(3U << 0U);

    /* Configure PA0 pull-down */
    GPIOA->PUPDR &= ~(3U << 0U);
    GPIOA->PUPDR |=  (2U << 0U);

    /* Enable SYSCFG clock */
    RCC->APB2ENR |= RCC_APB2ENR_SYSCFGEN;

    /* Map EXTI0 to GPIOA */
    SYSCFG->EXTICR[0] &= ~(0xFU << 0U);

    /* Select rising-edge trigger */
    EXTI->RTSR |= (1U << 0U);

    /* Disable falling-edge trigger */
    EXTI->FTSR &= ~(1U << 0U);

    /* Unmask EXTI0 interrupt */
    EXTI->IMR |= (1U << 0U);

    /* Enable EXTI0 in NVIC */
    NVIC_SetPriority(EXTI0_IRQn, 2);
    NVIC_EnableIRQ(EXTI0_IRQn);
}

void EXTI0_IRQHandler(void)
{
    if (EXTI->PR & (1U << 0U))
    {
        /* Clear pending bit by writing one */
        EXTI->PR = (1U << 0U);

        /* Handle event */
    }
}

int main(void)
{
    EXTI0_Init();

    while (1)
    {
        /* Main application */
    }
}
This register-level example is specific to the common STM32F4 EXTI/SYSCFG register architecture. Check the exact device reference manual and CMSIS header before using it. The example assumes PA0 is connected to a circuit that produces a rising edge.

14. Interrupt Service Routine Best Practices

  • Keep interrupt handlers short and predictable.
  • Acknowledge or clear the interrupt source correctly.
  • Avoid blocking delays inside an ISR.
  • Avoid lengthy calculations inside an ISR.
  • Use flags, queues or task notifications to communicate with main code or RTOS tasks.
  • Use appropriate synchronization for shared data.
  • Understand interrupt priority and nesting behavior.
  • Do not assume volatile guarantees atomic access.

15. Common GPIO Interrupt Problems

Problem Possible Cause
Interrupt does not occur Incorrect EXTI mapping or disabled NVIC interrupt.
Interrupt occurs on wrong pin Incorrect GPIO-to-EXTI source selection.
Multiple interrupts per press Mechanical switch bouncing.
Unexpected interrupt events Floating input or incorrect trigger selection.
Program gets stuck Incorrect ISR or interrupt flag handling.
Callback does not execute Missing HAL EXTI handler call or incorrect pin argument.

16. Placement-Oriented Interview Questions

Q1. What is a GPIO interrupt?

It is an interrupt generated when a GPIO input detects a configured signal transition or event.

Q2. What is EXTI?

EXTI is the external interrupt/event controller that detects configured external signal transitions.

Q3. What is the difference between rising and falling edges?

Rising edge is LOW-to-HIGH; falling edge is HIGH-to-LOW.

Q4. What is NVIC?

NVIC is the Nested Vectored Interrupt Controller. It manages interrupt enabling, priority and exception handling.

Q5. Can two GPIO ports use the same EXTI line number simultaneously?

In the common STM32F4 architecture, each EXTI line selects one GPIO port source at a time.

Q6. What is an ISR?

An Interrupt Service Routine is a function executed in response to an interrupt.

Q7. Why should an ISR be short?

A long ISR increases interrupt latency and can delay other time-critical processing.

Q8. What is switch debouncing?

It is the process of eliminating unwanted transitions caused by mechanical switch contact bouncing.

Q9. What is the purpose of EXTI pending register?

It records pending external interrupt conditions.

Q10. How does HAL handle an EXTI interrupt?

The IRQ handler calls HAL_GPIO_EXTI_IRQHandler(), which processes the interrupt and invokes the HAL GPIO EXTI callback.

Q11. Why is volatile used for an ISR-shared flag?

It prevents the compiler from treating accesses as ordinary unchanging memory values. It does not provide atomicity.

Q12. What is the difference between polling and interrupts?

Polling repeatedly checks an input, while interrupt-based handling responds to a configured hardware event.
