Lesson 5: Reset Sources and System Clock Configuration

Understand STM32 reset mechanisms, reset flags, startup behavior, system clock selection and practical clock configuration using STM32 HAL.

2. What Is a Microcontroller Reset?

A reset is an operation that places the microcontroller into a defined startup state.

During reset, the processor begins its startup sequence and initializes the system according to the device's reset architecture.

Why Is Reset Required?

  • To start the microcontroller after power is applied.
  • To recover from certain system failures.
  • To restart firmware after a watchdog timeout.
  • To apply a software-requested restart.
  • To establish defined peripheral and processor states.

3. Common STM32 Reset Sources

Reset Source Description
Power-On Reset (POR) Occurs when the device is powered on.
Power-Down Reset (PDR) Associated with the supply voltage falling below a specified level.
Brownout Reset (BOR) Resets the device when supply voltage falls below a configured or specified threshold.
External Reset Triggered through the external reset pin, commonly NRST.
Software Reset Requested by software through the system reset mechanism.
Independent Watchdog Reset Occurs when the IWDG is not refreshed within its timeout.
Window Watchdog Reset Occurs when the WWDG refresh conditions are violated.
Low-Power Reset Reset associated with specified low-power or power-control conditions on supported devices.
Exact reset sources, naming and reset-flag behavior vary by STM32 family. Some devices combine or distinguish particular power reset conditions differently.

4. Power-On Reset (POR)

Power-On Reset occurs when power is applied to the microcontroller and the supply voltage rises through the required operating threshold.

Basic Operation

  1. Power is applied to the board.
  2. The supply voltage begins to rise.
  3. The reset circuitry monitors the supply.
  4. The MCU is held in reset until reset-release conditions are met.
  5. The processor begins its startup sequence.

Applications

  • Initial startup after power is connected.
  • Establishing a known hardware startup state.
  • Supporting reliable power-up behavior.

5. Brownout Reset (BOR)

Brownout Reset protects the microcontroller when the supply voltage falls below a specified threshold.

Operating a microcontroller below its required voltage range can cause unpredictable behavior.

Example Scenario

Suppose a system operates from a nominal 3.3 V supply. If the supply drops significantly because of a power fault, the brownout mechanism may reset the MCU.

Why Is BOR Important?

  • Prevents operation outside specified voltage conditions.
  • Improves system reliability during supply disturbances.
  • Helps avoid execution with an invalid supply voltage.
The actual BOR thresholds and configuration options depend on the STM32 device. Do not assume one fixed threshold for all STM32 microcontrollers.

6. External Reset Using NRST

NRST is the external reset pin available on many STM32 microcontrollers.

An external reset circuit or push button can drive the reset input to restart the microcontroller.

Common Applications

  • Manual board restart.
  • External supervisor circuit.
  • Reset control by another system component.
  • Debugging and development.

Follow the electrical requirements and recommended reset circuitry in the selected STM32 datasheet.

7. Software Reset

A software reset allows firmware to request a complete system restart through the processor's system-control mechanism.

CMSIS Example

#include "stm32f4xx.h"

void Restart_System(void)
{
    NVIC_SystemReset();
}

NVIC_SystemReset() is a CMSIS function that requests a system reset using the processor's system reset mechanism.

Applications

  • Recovering from selected firmware errors.
  • Restarting after a configuration update.
  • Controlled firmware restart.
  • System recovery procedures.
A software reset does not necessarily reset every backup-domain or external device state. Check the reset-domain behavior of the exact MCU.

8. Watchdog Reset

A watchdog timer monitors firmware execution. If software fails to refresh the watchdog within the required time, the watchdog can reset the MCU.

Independent Watchdog (IWDG)

  • Commonly clocked from LSI.
  • Operates independently of the main system clock on supported devices.
  • Used to recover from software hangs.

Window Watchdog (WWDG)

  • Uses a clock derived from a peripheral clock domain on many devices.
  • Requires refresh within a defined time window.
  • Can detect refresh attempts that are too early or too late.
Example:

If firmware enters an infinite loop and stops refreshing the IWDG, the watchdog timeout can trigger a reset.

9. Reset Flags and Identifying Reset Causes

STM32 devices provide reset-status flags that help firmware identify why the previous reset occurred.

Common Reset Status Indicators

  • Power-on or power-down reset flag.
  • Brownout reset flag, where supported.
  • Software reset flag.
  • Independent watchdog reset flag.
  • Window watchdog reset flag.
  • External reset flag.

HAL Example – Read Reset Flags

#include "stm32f4xx_hal.h"

void Check_Reset_Cause(void)
{
    if (__HAL_RCC_GET_FLAG(RCC_FLAG_PORRST))
    {
        /* Power-on or power-related reset flag */
    }

    if (__HAL_RCC_GET_FLAG(RCC_FLAG_SFTRST))
    {
        /* Software reset detected */
    }

    if (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST))
    {
        /* Independent watchdog reset detected */
    }

    if (__HAL_RCC_GET_FLAG(RCC_FLAG_WWDGRST))
    {
        /* Window watchdog reset detected */
    }

    if (__HAL_RCC_GET_FLAG(RCC_FLAG_PINRST))
    {
        /* External reset pin flag detected */
    }

    __HAL_RCC_CLEAR_RESET_FLAGS();
}
This example uses common STM32F4 HAL flag names. Available flags differ by family. Read and record the reset cause before clearing the flags. Multiple flags can be set, so reset cause analysis should consider the complete status register.

10. STM32 System Clock Configuration

System clock configuration determines the clock source used by the processor and the frequencies distributed to the bus and peripheral domains.

Available System Clock Sources

  • HSI – High-Speed Internal oscillator.
  • HSE – High-Speed External clock source.
  • PLL – Phase-Locked Loop output.

The available sources and their routing depend on the selected STM32 device.

Typical System Clock Startup Sequence

  1. Reset occurs and the MCU enters its startup state.
  2. The initial clock source is selected by hardware.
  3. The startup code initializes the runtime environment.
  4. Firmware enables and configures the required oscillator.
  5. Firmware waits for oscillator readiness.
  6. Firmware configures the PLL if required.
  7. Firmware waits for PLL readiness.
  8. Firmware configures bus prescalers and Flash latency.
  9. Firmware selects the required system clock source.
  10. Firmware continues peripheral initialization.

11. HAL System Clock Configuration Example

The following example illustrates a common STM32F4 configuration using an 8 MHz HSE reference and a 168 MHz PLL system clock. 

void SystemClock_Config(void)
{
    RCC_OscInitTypeDef RCC_OscInitStruct = {0};
    RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

    __HAL_RCC_PWR_CLK_ENABLE();

    __HAL_PWR_VOLTAGESCALING_CONFIG(
        PWR_REGULATOR_VOLTAGE_SCALE1
    );

    /* Configure HSE and PLL */
    RCC_OscInitStruct.OscillatorType =
        RCC_OSCILLATORTYPE_HSE;

    RCC_OscInitStruct.HSEState = RCC_HSE_ON;

    RCC_OscInitStruct.PLL.PLLState = RCC_PLL_ON;
    RCC_OscInitStruct.PLL.PLLSource = RCC_PLLSOURCE_HSE;
    RCC_OscInitStruct.PLL.PLLM = 8;
    RCC_OscInitStruct.PLL.PLLN = 336;
    RCC_OscInitStruct.PLL.PLLP = RCC_PLLP_DIV2;
    RCC_OscInitStruct.PLL.PLLQ = 7;

    if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
    {
        Error_Handler();
    }

    /* Configure system and bus clocks */
    RCC_ClkInitStruct.ClockType =
        RCC_CLOCKTYPE_SYSCLK |
        RCC_CLOCKTYPE_HCLK |
        RCC_CLOCKTYPE_PCLK1 |
        RCC_CLOCKTYPE_PCLK2;

    RCC_ClkInitStruct.SYSCLKSource =
        RCC_SYSCLKSOURCE_PLLCLK;

    RCC_ClkInitStruct.AHBCLKDivider =
        RCC_SYSCLK_DIV1;

    RCC_ClkInitStruct.APB1CLKDivider =
        RCC_HCLK_DIV4;

    RCC_ClkInitStruct.APB2CLKDivider =
        RCC_HCLK_DIV2;

    if (HAL_RCC_ClockConfig(
            &RCC_ClkInitStruct,
            FLASH_LATENCY_5) != HAL_OK)
    {
        Error_Handler();
    }
}

Expected Clock Frequencies

Clock Frequency
HSE 8 MHz
PLL VCO 336 MHz
SYSCLK 168 MHz
HCLK 168 MHz
PCLK1 42 MHz
PCLK2 84 MHz
This example is for compatible STM32F4 devices only. Confirm the exact MCU's maximum frequency, PLL input and VCO limits, voltage scaling, Flash wait states and APB limits before using it. Other STM32 families require different configuration values and may use different clock architecture.

12. Clock Configuration Failure Handling

Clock initialization should include error handling. If an oscillator or PLL fails to start, firmware should not blindly continue with assumptions about the system frequency.

Common Failure Causes

  • Incorrect external crystal frequency.
  • HSE oscillator circuit problems.
  • Invalid PLL parameters.
  • Incorrect Flash latency.
  • Supply voltage outside the required range.
  • Unsupported bus clock frequency.
  • Incorrect clock-source selection.

Recommended Debugging Steps

  1. Verify the MCU part number.
  2. Check the oscillator hardware and configuration.
  3. Inspect oscillator-ready status flags.
  4. Verify PLL input and output calculations.
  5. Check Flash latency and voltage requirements.
  6. Verify SYSCLK and bus prescaler settings.
  7. Use the clock configuration tools and debugger.

13. Placement-Oriented Interview Questions

Q1. What is a reset in a microcontroller?

Reset places the microcontroller into a defined startup state and initiates its startup sequence.

Q2. What is POR?

Power-On Reset is associated with the application of power to the microcontroller.

Q3. What is BOR?

Brownout Reset resets the microcontroller when supply voltage falls below a specified threshold.

Q4. What is NRST?

NRST is the external reset input available on many STM32 devices.

Q5. What is a software reset?

It is a reset requested by firmware through the processor's system reset mechanism.

Q6. What is the purpose of a watchdog?

A watchdog detects a failure to refresh within the required timing conditions and can reset the microcontroller.

Q7. How can firmware identify the reset cause?

By reading the reset-status flags provided by the RCC or reset-control hardware.

Q8. What is SYSCLK?

SYSCLK is the selected system clock source distributed to the system clock tree.

Q9. Why must PLL readiness be checked?

Because the PLL requires time to stabilize before it can be used as the system clock source.

Q10. What happens if Flash latency is incorrect?

The processor may fail to access Flash reliably at the configured system clock frequency.

Q11. Does a software reset clear every STM32 peripheral and backup domain?

Not necessarily. Reset effects depend on the reset source and the device's reset-domain architecture.

Q12. Why is clock configuration performed early in firmware?

Because peripheral timing, communication rates and timer operation depend on the configured system and peripheral clocks.

15. Lesson Summary

  • Reset places the microcontroller into a defined startup state.
  • Common reset sources include POR, BOR, NRST, software and watchdog reset.
  • Reset flags help identify previous reset conditions.
  • CMSIS provides NVIC_SystemReset().
  • SYSCLK can be selected from supported oscillator or PLL sources.
  • Oscillator and PLL readiness must be checked.
  • Flash latency and bus limits must match the clock configuration.
  • System clock setup is essential for reliable peripheral timing.
