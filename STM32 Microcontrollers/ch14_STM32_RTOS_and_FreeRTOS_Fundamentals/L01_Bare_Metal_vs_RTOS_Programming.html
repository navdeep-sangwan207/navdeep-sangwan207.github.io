2. What Is Bare-Metal Programming?

Bare-metal programming is a method of developing firmware that runs directly on the microcontroller without a general purpose operating system or RTOS kernel.

The application directly controls peripherals, interrupts, timers and program execution.

Characteristics

  • No RTOS scheduler is required.
  • Application controls the execution flow.
  • Direct peripheral access is common.
  • Small memory footprint is possible.
  • Suitable for simple and focused applications.

3. Super-Loop Architecture

A super-loop is a common bare-metal architecture in which application functions are repeatedly executed inside an infinite loop.

Example: STM32 Bare-Metal Super-Loop

#include "main.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        Read_Sensor();
        Process_Data();
        Update_LED();
    }
}

The functions execute sequentially. A slow or blocking function can delay the execution of functions that follow it.

Advantages

  • Simple architecture.
  • Easy to understand and debug for small systems.
  • Low overhead.
  • No task scheduler configuration.

Limitations

  • Blocking operations can delay other functions.
  • Application complexity can grow quickly.
  • Timing coordination becomes difficult.
  • Multiple independent activities are harder to organize.

4. Polling-Based Programming

Polling means repeatedly checking the status of a peripheral or input to determine whether an event has occurred.

Example: Button Polling

while (1)
{
    if (HAL_GPIO_ReadPin(
            GPIOC,
            GPIO_PIN_13) == GPIO_PIN_RESET)
    {
        HAL_GPIO_WritePin(
            GPIOA,
            GPIO_PIN_5,
            GPIO_PIN_SET);
    }
    else
    {
        HAL_GPIO_WritePin(
            GPIOA,
            GPIO_PIN_5,
            GPIO_PIN_RESET);
    }
}

Advantages

  • Easy to implement.
  • Simple control flow.
  • Useful for infrequent or simple checks.

Limitations

  • CPU repeatedly checks peripheral status.
  • Events may be detected late.
  • Frequent polling can waste processing time.

5. Interrupt-Driven Programming

Interrupt-driven programming allows a peripheral or external event to request processor attention. The processor executes an interrupt service routine (ISR).

Interrupt Execution Flow

       MAIN PROGRAM
            |
            v
       NORMAL EXECUTION
            |
            v
      INTERRUPT OCCURS
            |
            v
       SAVE CPU CONTEXT
            |
            v
       EXECUTE ISR
            |
            v
      RESTORE CPU CONTEXT
            |
            v
       RESUME MAIN PROGRAM

Example: GPIO Interrupt Callback

volatile uint8_t button_event = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        button_event = 1;
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        if (button_event != 0)
        {
            button_event = 0;

            /* Process button event. */
            HAL_GPIO_TogglePin(
                GPIOA,
                GPIO_PIN_5);
        }
    }
}
Keep ISRs short. The example uses a simple flag for demonstration. If multiple events can arrive before the main loop handles them, a flag may lose event counts. Use a counter, queue or suitable event mechanism when every event must be preserved.

6. What Is an RTOS?

RTOS stands for Real-Time Operating System. It is an operating system designed to manage application activities while providing scheduling behavior intended to meet timing requirements.

An RTOS kernel manages tasks, priorities, scheduling, timing and synchronization.

Important RTOS Components

  • Tasks or threads.
  • Scheduler.
  • Task priorities.
  • System tick.
  • Queues.
  • Semaphores.
  • Mutexes.
  • Task notifications.

RTOS Execution Concept

7. What Is a Task?

A task is an independent thread of execution managed by the RTOS scheduler. Each task has its own execution context and typically its own stack.

Example Application Tasks

Task Responsibility
Sensor Task Read sensor data.
UART Task Handle communication.
Control Task Process control logic.
Display Task Update display information.

Tasks can be blocked while waiting for a delay, queue message, semaphore or another event. The scheduler can then run another ready task.

8. What Is a Scheduler?

The scheduler selects which ready task should execute according to the RTOS scheduling policy and task priorities.

Common Scheduling Concepts

  • Priority-based scheduling: Tasks have assigned priorities.
  • Preemptive scheduling: A higher-priority ready task can interrupt a lower-priority task.
  • Cooperative scheduling: A running task gives up execution voluntarily or reaches a scheduling point.
  • Time slicing: Equal-priority ready tasks can share CPU time where configured.
FreeRTOS commonly uses priority-based preemptive scheduling when configured for it. Actual scheduling behavior also depends on configuration and API usage.

9. What Is Context Switching?

A context switch occurs when the processor stops executing one task and begins executing another task.

The RTOS saves the outgoing task's execution context and restores the context of the selected task.

Context Switch Sequence

  1. A scheduling event occurs.
  2. The processor saves the current task context.
  3. The scheduler selects a ready task.
  4. The selected task context is restored.
  5. Execution continues in the selected task.

Why Is Context Switching Required?

  • To support multitasking.
  • To run higher-priority ready tasks.
  • To allow blocked tasks to wait efficiently.
  • To share CPU execution among tasks.

10. Bare-Metal vs RTOS Comparison

Feature Bare-Metal RTOS
Execution control Application-controlled Kernel scheduler-controlled
Tasks Usually functions in a main loop Independent scheduled tasks
Memory usage Usually lower overhead Kernel and task stacks require memory
Scheduling Programmer-managed Kernel-managed
Synchronization Flags and application logic Queues, semaphores and mutexes
Complexity Simple for small applications Requires RTOS design knowledge
Typical use Small control applications Complex multitasking applications

11. When Should You Use an RTOS?

Use Bare-Metal Programming When:

  • The application is small and simple.
  • There are few independent activities.
  • Memory resources are very limited.
  • A straightforward super-loop meets timing needs.

Use an RTOS When:

  • Multiple activities need independent execution.
  • Application complexity is high.
  • Tasks need structured synchronization.
  • Different activities require different priorities.
  • Communication, control and sensing must be coordinated.
An RTOS does not automatically guarantee that every deadline will be met. Real-time performance depends on task design, priorities, execution times, interrupt latency, resource contention and system load.

12. Practical Application: Sensor Monitoring System

Bare-Metal Design

A single main loop reads a sensor, processes the result and sends data through UART. A slow communication operation can delay the next sensor read.

RTOS Design

Separate tasks can be used for sensor acquisition, data processing and UART communication. A queue can transfer sensor readings between tasks. 

        SENSOR HARDWARE

               v
          SENSOR TASK

             QUEUE

               v
         PROCESSING TASK
               |
               v
             QUEUE
               |
               v
           UART TASK
               |

        SERIAL TERMINAL

This design separates responsibilities and makes each software component easier to maintain and test.

13. Placement Interview Questions and Answers

Q1. What is bare-metal programming?

Bare-metal programming runs firmware directly on the microcontroller without an RTOS kernel managing application tasks.

Q2. What is a super-loop?

A super-loop is an infinite loop that repeatedly executes application functions.

Q3. What is polling?

Polling is repeatedly checking a peripheral or input to detect an event.

Q4. What is interrupt-driven programming?

It uses interrupts to notify the processor when an event occurs, allowing an ISR to respond to that event.

Q5. What is an RTOS?

An RTOS is an operating system designed to manage tasks and scheduling for applications with timing requirements.

Q6. What is a task?

A task is an independent execution thread managed by the RTOS scheduler.

Q7. What is a scheduler?

A scheduler selects the next ready task to execute according to the scheduling policy.

Q8. What is context switching?

It is the process of saving one task's execution context and restoring another's.

Q9. What is preemptive scheduling?

It allows a higher-priority ready task to take CPU execution from a lower-priority running task.

Q10. Does an RTOS guarantee real-time deadlines?

No. Meeting deadlines depends on correct scheduling, bounded execution times, resource management and system design.

Q11. What is the advantage of an RTOS?

It provides structured multitasking, scheduling, synchronization and inter-task communication.

Q12. Can STM32 run without an RTOS?

Yes. STM32 microcontrollers can run bare-metal firmware using a main loop, interrupts and peripheral drivers.

  • Bare-metal firmware runs without an RTOS kernel.
  • A super-loop repeatedly executes application functions.
