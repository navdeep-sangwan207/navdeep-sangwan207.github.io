Lesson 2: FreeRTOS Architecture and Kernel Fundamentals

STM32 RTOS and FreeRTOS Fundamentals

1. Learning Objectives

  • Understand FreeRTOS and its role in embedded systems.
  • Identify the major components of the FreeRTOS kernel.
  • Understand tasks, scheduler, queues, semaphores and software timers.
  • Learn how FreeRTOS manages task execution and context switching.
  • Understand the relationship between FreeRTOS and STM32 hardware.

2. What is FreeRTOS?

FreeRTOS is a real-time operating system kernel designed for microcontrollers and embedded systems. It allows an application to be divided into multiple independent tasks that can execute according to scheduling rules.

FreeRTOS provides services such as task management, scheduling, inter-task communication, synchronization and software timers.

Applications

  • Industrial automation systems
  • Automotive electronic controllers
  • IoT devices and sensor nodes
  • Medical and monitoring equipment
  • Robotics and motor control systems
  • Consumer electronics

3. FreeRTOS Kernel Architecture

The FreeRTOS kernel manages task execution and provides communication and synchronization services to application tasks.

The application creates tasks and uses kernel APIs to coordinate their execution. The kernel interacts with the processor through a port layer that is specific to the target architecture.

4. Major Components of FreeRTOS

4.1 Tasks

A task is an independent unit of application execution. Each task has its own stack and task control information.

Examples:

  • Sensor reading task
  • UART communication task
  • LED status task
  • Motor control task

4.2 Scheduler

The scheduler selects which eligible task should execute. FreeRTOS commonly uses priority-based scheduling. With preemptive scheduling enabled, a higher-priority ready task can preempt a lower-priority running task.

4.3 Queues

Queues allow tasks and, where permitted, interrupt service routines to exchange data safely.

4.4 Semaphores and Mutexes

Semaphores are synchronization mechanisms. Mutexes provide mutual exclusion when tasks share a resource.

4.5 Software Timers

Software timers allow functions to be scheduled after a specified number of RTOS ticks or periodically, without dedicating a hardware timer to every application timing requirement.

4.6 Event Groups

Event groups allow tasks to wait for one or more event bits. They are useful when an application needs to coordinate multiple conditions.

5. FreeRTOS Task States

A task commonly moves through the following states:

  • Running: The task is currently executing.
  • Ready: The task can execute but is not currently selected.
  • Blocked: The task is waiting for an event or time delay.
  • Suspended: The task has been explicitly suspended.

A blocked task does not consume processor time while it waits. A suspended task does not become ready automatically when a timeout expires; it must be resumed.

6. FreeRTOS Scheduler

The scheduler determines which ready task gets CPU execution. Task priorities are normally configured when tasks are created.

Important Scheduling Concepts

  • Priority: Determines the relative importance of ready tasks.
  • Preemption: A higher-priority ready task can interrupt a lower-priority running task when preemptive scheduling is enabled.
  • Time slicing: Equal-priority ready tasks may share CPU time when the relevant configuration is enabled.
  • Task blocking: A task can wait for a delay, queue data or synchronization event.

FreeRTOS scheduling behavior depends on configuration options, including configUSE_PREEMPTION and configUSE_TIME_SLICING.

7. FreeRTOS on STM32 Cortex-M

STM32 microcontrollers commonly use ARM Cortex-M processors. FreeRTOS provides a Cortex-M port that connects the kernel scheduler to processor-specific exception and interrupt mechanisms.

Important Cortex-M Exceptions

  • SysTick: Commonly provides the RTOS tick interrupt.
  • PendSV: Commonly performs the deferred task context switch.
  • SVC: Used by some FreeRTOS Cortex-M ports for privileged kernel operations.

Exact exception usage and port implementation depend on the Cortex-M core and FreeRTOS port. Interrupt priorities must be configured according to the port's requirements.

8. FreeRTOS Configuration

The FreeRTOSConfig.h file contains configuration settings for the kernel and application.

Common Configuration Options


#define configUSE_PREEMPTION              1
#define configUSE_TIME_SLICING            1
#define configCPU_CLOCK_HZ                SystemCoreClock
#define configTICK_RATE_HZ                1000
#define configMAX_PRIORITIES              5
#define configMINIMAL_STACK_SIZE          128
#define configTOTAL_HEAP_SIZE             (10 * 1024)
#define configUSE_MUTEXES                 1
#define configUSE_TIMERS                  1

These values are illustrative, not universal settings. The stack-size unit, heap configuration and required interrupt priority definitions must match the selected FreeRTOS port and STM32 project.

Important Configuration Parameters

  • configTICK_RATE_HZ – RTOS tick frequency.
  • configMAX_PRIORITIES – Number of available task priority levels.
  • configTOTAL_HEAP_SIZE – Heap size when using a heap implementation that requires this setting.
  • configUSE_MUTEXES – Enables mutex functionality.
  • configUSE_TIMERS – Enables software timer services.

9. FreeRTOS API Overview

API Purpose
xTaskCreate() Create a task dynamically.
vTaskStartScheduler() Start the scheduler.
vTaskDelay() Block a task for a specified number of ticks.
vTaskSuspend() Suspend a task.
vTaskResume() Resume a suspended task.
uxTaskGetStackHighWaterMark() Measure the minimum remaining task stack observed.

Some APIs have static-allocation alternatives, and exact availability depends on FreeRTOS configuration.

10. Basic FreeRTOS Program Structure

The following example demonstrates two tasks. It assumes an STM32 project with FreeRTOS configured and an LED GPIO pin initialized before the scheduler starts. 


#include "main.h"
#include "FreeRTOS.h"
#include "task.h"

void LED_Task(void *argument);
void Monitor_Task(void *argument);

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    xTaskCreate(
        LED_Task,
        "LED",
        128,
        NULL,
        1,
        NULL
    );

    xTaskCreate(
        Monitor_Task,
        "Monitor",
        128,
        NULL,
        2,
        NULL
    );

    vTaskStartScheduler();

    while (1)
    {
        /* Normally not reached if scheduler starts successfully. */
    }
}

void LED_Task(void *argument)
{
    for (;;)
    {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void Monitor_Task(void *argument)
{
    for (;;)
    {
        /* Perform periodic monitoring work. */
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

Program Explanation

  1. HAL and system clock are initialized.
  2. GPIO is configured before tasks begin using it.
  3. xTaskCreate() creates two tasks.
  4. vTaskStartScheduler() starts task scheduling.
  5. The LED task toggles the LED every 500 milliseconds.
  6. The monitor task performs its work every 1000 milliseconds.

The example uses illustrative stack depths and task priorities. Check the selected port's stack-size units, available heap, GPIO assignment and FreeRTOS configuration. Check task-creation return values in production code.

11. FreeRTOS Heap Management

FreeRTOS uses heap memory for kernel objects and dynamically created tasks when dynamic allocation is enabled.

Common Heap Implementations

  • heap_1: Allocation only; memory cannot be freed.
  • heap_2: Supports allocation and freeing but does not coalesce adjacent free blocks.
  • heap_3: Uses the C library's malloc and free.
  • heap_4: Supports allocation and freeing with adjacent free-block coalescing.
  • heap_5: Supports multiple non-contiguous memory regions.

Only one FreeRTOS heap implementation is normally included in a project. Availability and behavior should be checked against the FreeRTOS version being used.

Static allocation is another option. It allows application code to provide memory for kernel objects and can make memory usage more predictable.

12. Common FreeRTOS Errors

  • Insufficient task stack size.
  • Insufficient FreeRTOS heap memory.
  • Incorrect interrupt priority configuration.
  • Blocking operations inside interrupt service routines.
  • Incorrect task priority assignment.
  • Using a task handle before it has been initialized.
  • Calling RTOS APIs from an ISR that do not have ISR-safe variants.
  • Sharing data without suitable synchronization.

Use FreeRTOS-aware debugging tools, stack high-water marks, allocation-failure hooks and runtime statistics where supported to diagnose application problems.

13. Placement-Oriented Interview Questions and Answers

Q1. What is FreeRTOS?

FreeRTOS is a real-time operating system kernel for embedded systems that provides task scheduling, synchronization and communication services.

Q2. What is a kernel?

A kernel is the central software component that manages system resources and provides essential services to application code.

Q3. What is a task in FreeRTOS?

A task is an independently scheduled unit of execution with its own stack and task control information.

Q4. What is the purpose of the scheduler?

The scheduler selects a ready task for execution according to the configured scheduling policy and task priorities.

Q5. What is context switching?

Context switching is the process of saving the execution context of one task and restoring the context of another task.

Q6. What is the difference between Ready and Blocked states?

A Ready task can execute when selected by the scheduler. A Blocked task is waiting for a specified event or timeout.

Q7. What is the purpose of SysTick?

SysTick is a Cortex-M system timer that can generate periodic interrupts and is commonly used as the FreeRTOS tick source.

Q8. What is PendSV used for?

Many Cortex-M FreeRTOS ports use PendSV to perform task context switching at a controlled exception priority.

Q9. What is FreeRTOSConfig.h?

It is the application configuration header that defines kernel features, priorities, tick frequency and memory settings.

Q10. What is the difference between dynamic and static allocation?

Dynamic allocation obtains memory at runtime from a heap. Static allocation uses memory supplied by the application, usually with more predictable memory requirements.

Q11. Can FreeRTOS guarantee that every task meets its deadline?

No. Meeting deadlines depends on correct task design, priorities, execution times, interrupt latency, resource sharing and system-load analysis.

Q12. Why should an ISR be short in an RTOS application?

A short ISR reduces interrupt latency and minimizes interference with task scheduling. Longer processing should normally be deferred to a task.

  • FreeRTOS is a real-time kernel used in embedded applications.
  • Tasks are independent units of scheduled execution.
  • The scheduler selects ready tasks for CPU execution.
  • Queues, semaphores, mutexes and event groups support communication and synchronization.

  • FreeRTOSConfig.h controls kernel configuration.
  • Correct stack, heap and interrupt-priority configuration is essential.
