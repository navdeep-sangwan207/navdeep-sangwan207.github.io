Lesson 3: Tasks and Task Scheduling

STM32 RTOS and FreeRTOS Fundamentals

1. Learning Objectives

  • Understand FreeRTOS task creation and deletion.
  • Learn task priorities and scheduling behavior.
  • Understand task states and state transitions.
  • Learn task delays, suspension and resumption.
  • Understand task stack management and task handles.
  • Implement multiple tasks on an STM32 microcontroller.

2. What is a Task?

A task is an independent unit of execution managed by the FreeRTOS scheduler. Each task performs a specific application function and has its own stack and task control block.

Examples of Embedded Tasks

  • Task 1: Read temperature sensor.
  • Task 2: Transmit sensor data through UART.
  • Task 3: Control LED indicators.
  • Task 4: Monitor system status.
  • Task 5: Control motor speed.

3. Task Control Block (TCB)

FreeRTOS maintains task information in a Task Control Block. The TCB stores the information needed by the kernel to manage and schedule a task.

Typical TCB Information

  • Task stack pointer.
  • Task priority.
  • Task state and scheduling information.
  • Task name.
  • Task stack and memory information.
  • Other kernel-specific task management data.

The exact TCB layout is internal to FreeRTOS and can vary between kernel versions and configurations.

4. Task Creation

The xTaskCreate() API dynamically creates a task using memory allocated through the configured FreeRTOS heap.

Function Syntax


BaseType_t xTaskCreate(
    TaskFunction_t pvTaskCode,
    const char * const pcName,
    configSTACK_DEPTH_TYPE usStackDepth,
    void *pvParameters,
    UBaseType_t uxPriority,
    TaskHandle_t *pxCreatedTask
);

Parameters

Parameter Description
pvTaskCode Function executed by the task.
pcName Human-readable task name.
usStackDepth Task stack depth, commonly specified in words.
pvParameters Parameter passed to the task function.
uxPriority Task priority.
pxCreatedTask Optional pointer to receive the task handle.

Check the exact API type and stack-depth unit for the FreeRTOS version and port used in the project.

5. Task Function Structure

A FreeRTOS task function normally contains an infinite loop because the task is expected to continue executing until it is explicitly deleted or otherwise terminated. 


void TaskFunction(void *argument)
{
    for (;;)
    {
        /* Task application code */

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

The task should block or yield when it has no immediate work. This allows other ready tasks to use the processor.

6. Task Priority

Task priority determines the relative importance of a task when the scheduler selects among ready tasks.

  • A higher numerical priority represents a higher priority in FreeRTOS.
  • A lower-priority task can execute when higher-priority tasks are blocked or not ready.
  • Equal-priority tasks may share CPU time when time slicing is enabled.
  • Priority levels are limited by configMAX_PRIORITIES.

Example


xTaskCreate(
    Sensor_Task,
    "Sensor",
    256,
    NULL,
    3,
    NULL
);

xTaskCreate(
    Display_Task,
    "Display",
    256,
    NULL,
    1,
    NULL
);

In this example, Sensor_Task has higher priority than Display_Task. If both are ready and preemptive scheduling is enabled, Sensor_Task is selected first.

Do not assign the highest priority to every task. Priorities should reflect timing requirements and be supported by schedulability analysis.

7. Task States

7.1 Running State

The task is currently executing on the processor.

7.2 Ready State

The task is eligible to execute but is waiting for the scheduler to select it.

7.3 Blocked State

The task is waiting for a time period or an event such as queue data or semaphore availability.

7.4 Suspended State

The task has been explicitly suspended and will not become ready until it is resumed.

8. Task Delay Functions

8.1 vTaskDelay()

vTaskDelay() blocks the calling task for a specified number of RTOS ticks measured from the time the function is called. 


void LED_Task(void *argument)
{
    for (;;)
    {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

8.2 vTaskDelayUntil()

vTaskDelayUntil() is used for periodic execution. It schedules the next wake-up relative to an intended periodic time, helping reduce accumulated timing drift. 


void Sensor_Task(void *argument)
{
    TickType_t lastWakeTime;
    const TickType_t period = pdMS_TO_TICKS(100);

    lastWakeTime = xTaskGetTickCount();

    for (;;)
    {
        /* Read sensor and process data */

        vTaskDelayUntil(&lastWakeTime, period);
    }
}

Difference Between Delay APIs

Function Purpose
vTaskDelay() Blocks relative to the time the call is made.
vTaskDelayUntil() Schedules periodic execution using an absolute tick reference.

The periodic task must complete its work within the intended period if it is to maintain the expected execution schedule. Tick resolution and scheduling latency also affect timing.

9. Task Suspension and Resumption

A task can be suspended using vTaskSuspend() and resumed using vTaskResume(). 


TaskHandle_t SensorTaskHandle = NULL;

void Sensor_Task(void *argument)
{
    for (;;)
    {
        /* Sensor processing */

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void Control_Task(void *argument)
{
    for (;;)
    {
        /* Application control logic */

        vTaskSuspend(SensorTaskHandle);

        vTaskDelay(pdMS_TO_TICKS(1000));

        vTaskResume(SensorTaskHandle);
    }
}

This is a basic demonstration only. In a real application, suspending a task that owns a resource or is responsible for system progress can cause problems. Queues, notifications or other synchronization mechanisms are often better choices.

10. Task Deletion

The vTaskDelete() function removes a task from the scheduler. 


void Temporary_Task(void *argument)
{
    /* Perform one-time operation */

    vTaskDelete(NULL);
}

Passing NULL deletes the calling task. Dynamically allocated task memory is reclaimed by the FreeRTOS idle task in the usual dynamic-allocation model. Applications should not assume deletion immediately frees all associated memory.

11. Task Stack Management

Every task has its own stack. The stack stores local variables, function call information, saved registers and other execution context.

Common Causes of Stack Overflow

  • Large local arrays.
  • Deep function call chains.
  • Excessive nested function calls.
  • Large local structures.
  • Recursive functions.
  • Insufficient task stack allocation.

Stack Monitoring API


UBaseType_t remainingStack;

remainingStack =
    uxTaskGetStackHighWaterMark(NULL);

The high-water mark reports the minimum unused stack observed since task creation. Interpret its unit according to the selected FreeRTOS port and configuration.

12. Complete STM32 Multiple-Task Example

This example creates an LED task and a monitoring task. It assumes CubeMX-generated HAL initialization and an initialized GPIOA pin 5 connected to an LED. 


#include "main.h"
#include "FreeRTOS.h"
#include "task.h"

TaskHandle_t ledTaskHandle;
TaskHandle_t monitorTaskHandle;

void LED_Task(void *argument);
void Monitor_Task(void *argument);

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    if (xTaskCreate(
            LED_Task,
            "LED",
            256,
            NULL,
            1,
            &ledTaskHandle
        ) != pdPASS)
    {
        Error_Handler();
    }

    if (xTaskCreate(
            Monitor_Task,
            "Monitor",
            256,
            NULL,
            2,
            &monitorTaskHandle
        ) != pdPASS)
    {
        Error_Handler();
    }

    vTaskStartScheduler();

    Error_Handler();

    while (1)
    {
    }
}

void LED_Task(void *argument)
{
    for (;;)
    {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void Monitor_Task(void *argument)
{
    for (;;)
    {
        /* Add system monitoring operations here. */

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

Expected Operation

  • LED task toggles the LED every 500 ms.
  • Monitor task executes once every 1000 ms.
  • Monitor task has higher priority than LED task.
  • When the monitor task blocks, the LED task can execute.

The stack depths are example values, not guaranteed safe sizes. Verify available heap, actual task stack usage, FreeRTOS port settings and the board's LED pin before running.

13. Common Task Scheduling Problems

  • Starvation: A low-priority task gets little or no CPU time because higher-priority tasks remain ready.
  • Priority inversion: A high-priority task is delayed because a lower-priority task holds a shared resource.
  • Stack overflow: A task uses more stack than allocated.
  • Excessive blocking: A task waits longer than its application timing requirement.
  • CPU overload: Total processing demand exceeds available processor capacity.
  • Incorrect delay selection: Periodic tasks accumulate timing drift when relative delays are used without considering execution time.

14. Placement-Oriented Interview Questions and Answers

Q1. What is a task in FreeRTOS?

A task is an independently scheduled unit of execution with its own stack and control information.

Q2. What is a Task Control Block?

A TCB stores kernel information required to manage and schedule a task.

Q3. Which API creates a task dynamically?

xTaskCreate() creates a task using the configured FreeRTOS heap.

Q4. What is task priority?

Task priority determines the relative importance of a ready task during scheduling.

Q5. Does a higher numerical priority mean higher priority in FreeRTOS?

Yes. A higher numerical value represents a higher task priority.

Q6. What is the difference between vTaskDelay and vTaskDelayUntil?

vTaskDelay() blocks relative to the call time, while vTaskDelayUntil() supports periodic execution using a reference wake-up time.

Q7. What is a task handle?

A task handle is a reference used by application code to identify and operate on a task.

Q8. What is starvation?

Starvation occurs when a task is continually prevented from executing because other tasks receive CPU time.

Q9. What is the purpose of a task stack?

It stores task execution context, function call information, local variables and saved registers.

Q10. How can task stack usage be monitored?

Use uxTaskGetStackHighWaterMark() and appropriate stack overflow checking.

Q11. What happens when vTaskDelete(NULL) is called?

It deletes the task that calls the function.

Q12. What is priority inversion?

Priority inversion occurs when a high-priority task is delayed by a lower-priority task holding a shared resource.
