Lesson 1: STM32 Board Setup and Hardware Validation

STM32 Practical Projects, Debugging and Troubleshooting

1. Learning Objectives

  • Understand STM32 development board components.
  • Learn hardware inspection and power supply checks.
  • Understand ST-LINK and SWD programming interfaces.
  • Install and configure STM32CubeIDE.
  • Create and program a basic STM32 project.
  • Validate GPIO, clock and UART operation.
  • Identify common board setup problems.

2. STM32 Development Board Overview

An STM32 development board is a hardware platform used to develop, program and test applications based on STM32 microcontrollers from STMicroelectronics.

Common development boards include:

  • STM32 Nucleo boards
  • STM32 Discovery boards
  • STM32 Evaluation boards
  • Custom STM32 development boards

Common Board Components

  • STM32 microcontroller
  • ST-LINK debugger and programmer, when integrated
  • USB connector
  • Power supply circuitry
  • Reset push button
  • User push button
  • User LEDs
  • GPIO expansion headers
  • Crystal or oscillator, where fitted

4. Hardware Inspection Before Power-On

Inspect the development board before connecting it to a power source.

Inspection Checklist

  • Check the PCB for visible damage.
  • Inspect USB connectors and expansion headers.
  • Check for loose components or solder bridges.
  • Identify the exact STM32 MCU part number.
  • Locate the board's power input and ground connections.
  • Identify reset and user buttons.
  • Check the board schematic and user manual.

Important Precautions

  • Never apply an unknown voltage to a GPIO pin.
  • Do not assume every STM32 GPIO is 5 V tolerant.
  • Do not connect external supplies with conflicting power sources.
  • Check jumper positions and power selection before applying power.
  • Use ESD precautions when handling the board.

5. Power Supply Validation

The STM32 microcontroller requires a valid supply voltage within the limits specified in its datasheet.

Power Supply Checks

  1. Identify the board's supported power input.
  2. Connect the USB or approved external supply.
  3. Check the power indicator LED, if available.
  4. Measure the regulated supply rail at an approved test point.
  5. Compare the measured value with the board documentation.
  6. Check for unexpected heating or abnormal current consumption.

Example

Many STM32 development boards use a regulated 3.3 V supply for the MCU. The actual allowed voltage range must be checked for the selected device and board.

A multimeter can be used to check the supply rail and ground connection. Avoid shorting adjacent pins while measuring.

6. ST-LINK Programmer and Debugger

ST-LINK is a programming and debugging tool used to communicate with supported STM32 microcontrollers.

ST-LINK Functions

  • Download firmware to STM32 Flash memory.
  • Start and stop program execution during debugging.
  • Set breakpoints and inspect variables.
  • Read and modify supported core and peripheral registers.
  • Reset the target microcontroller.

ST-LINK Interfaces

  • SWD – Serial Wire Debug.
  • JTAG – Joint Test Action Group, where supported.

Many Nucleo boards contain an integrated ST-LINK interface. Other boards may require an external ST-LINK programmer.

7. SWD Interface and Connections

Serial Wire Debug is a two-wire debug interface commonly used to program and debug STM32 microcontrollers.

Signal Purpose
SWDIO Bidirectional debug data
SWCLK Debug clock
GND Common reference ground
VTref Target voltage reference
NRST Optional reset connection

The exact connector pinout must be verified using the ST-LINK and target-board documentation. VTref is a voltage reference input on common debug connectors, not a general target power output.

8. STM32CubeIDE Installation and Configuration

STM32CubeIDE is an integrated development environment for STM32 firmware development.

Typical Development Tools

  • STM32CubeIDE – project creation, editing, building and debugging.
  • STM32CubeMX – graphical MCU configuration, integrated into the IDE or available separately.
  • GNU Arm Embedded Toolchain – compilation and linking.
  • ST-LINK software and drivers – device programming and debugging support.

Installation Procedure

  1. Download STM32CubeIDE from the official STMicroelectronics website.
  2. Run the installer for your operating system.
  3. Follow the installation instructions.
  4. Install or update the required ST-LINK drivers when prompted.
  5. Launch STM32CubeIDE.
  6. Choose a workspace directory.
  7. Check that the IDE recognizes the available toolchain.

9. Creating an STM32 Project

Project Creation Steps

  1. Open STM32CubeIDE.
  2. Select File → New → STM32 Project.
  3. Select the target MCU or development board.
  4. Enter the project name.
  5. Configure the clock and required peripherals.
  6. Configure GPIO pins and their functions.
  7. Generate the project code.
  8. Write the application in the generated source files.
  9. Build the project.
  10. Connect to the target and program the firmware.

Always select the exact MCU or board model. Incorrect device selection can produce wrong pin assignments, clock settings and peripheral configurations.

10. First STM32 Application: LED Blink

The LED blink program is a basic hardware validation project. It checks that the board can execute firmware and control a configured GPIO output.

HAL Program


#include "main.h"

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        HAL_GPIO_TogglePin(
            LED_GPIO_Port,
            LED_Pin
        );

        HAL_Delay(500);
    }
}

Program Explanation

  • HAL_Init() initializes the HAL library.
  • SystemClock_Config() configures the system clock.
  • MX_GPIO_Init() initializes the configured GPIO pin.
  • HAL_GPIO_TogglePin() changes the output state.
  • HAL_Delay(500) waits approximately 500 ms using the HAL time base.

The LED pin and polarity are board-specific. The LED may be active-high or active-low. Use the pin definitions and initialization generated for the selected board.

11. UART Communication Validation

UART can be used to verify serial communication between the STM32 board and a computer.

Example HAL Code


#include "main.h"
#include 

extern UART_HandleTypeDef huart2;

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();
    MX_USART2_UART_Init();

    uint8_t message[] =
        "STM32 UART Test\r\n";

    while (1)
    {
        HAL_UART_Transmit(
            &huart2,
            message,
            sizeof(message) - 1,
            100
        );

        HAL_Delay(1000);
    }
}

Validation Procedure

  1. Configure the UART peripheral in CubeMX.
  2. Set the baud rate, for example 115200.
  3. Configure the correct TX and RX alternate-function pins.
  4. Connect using the board's virtual COM port or an appropriate USB-UART adapter.
  5. Open a serial terminal.
  6. Select matching baud rate, data bits, parity and stop bits.
  7. Verify the transmitted message.

The UART instance and physical connection depend on the board. Some Nucleo boards route a USART peripheral through the integrated ST-LINK virtual COM port.

12. Clock Configuration Validation

Correct clock configuration is essential for reliable peripheral operation.

Clock Validation Methods

  • Inspect the clock configuration in STM32CubeIDE.
  • Check the configured oscillator source.
  • Verify PLL parameters and system clock frequency.
  • Check AHB and APB bus clock frequencies.
  • Verify peripheral clock source selection.
  • Measure a configured timer output or clock output pin when supported.

Incorrect clock settings can cause UART baud-rate errors, incorrect timer periods, ADC timing problems and unexpected system behavior.

14. Common Hardware and Programming Problems

Problem 1: ST-LINK Cannot Detect the MCU

Possible causes:

  • Target power is missing.
  • Incorrect SWD wiring.
  • Missing common ground.
  • Incorrect debug interface configuration.
  • Device is held in reset.

Solution: Check target supply, SWDIO, SWCLK, GND, reset and the selected connection settings.

Problem 2: LED Does Not Blink

Possible causes:

  • Incorrect GPIO pin selection.
  • GPIO clock not enabled.
  • Incorrect output configuration.
  • Incorrect LED polarity.
  • Firmware not programmed successfully.

Solution: Verify the board schematic, generated GPIO configuration and firmware execution.

Problem 3: UART Output Is Incorrect

Possible causes:

  • Incorrect baud rate.
  • Wrong TX pin or alternate function.
  • Missing ground reference.
  • Wrong serial terminal settings.
  • Incorrect UART clock configuration.

Solution: Verify UART configuration, clock source, pin mapping and terminal settings.

Problem 4: Firmware Does Not Start

Possible causes:

  • Incorrect Flash programming.
  • Wrong MCU target configuration.
  • Fault during initialization.
  • Incorrect boot configuration.
  • Watchdog reset or repeated fault.

Solution: Connect the debugger, reset the MCU, halt execution and inspect the program counter and fault status.

15. Placement-Oriented Interview Questions and Answers

Q1. What is an STM32 development board?

A hardware platform used to develop and test applications based on STM32 microcontrollers.

Q2. What is ST-LINK?

ST-LINK is a programming and debugging tool for supported STM32 microcontrollers.

Q3. What is SWD?

Serial Wire Debug is a two-wire interface used to program and debug ARM Cortex-M-based microcontrollers.

Q4. What are the main SWD signals?

SWDIO and SWCLK are the main debug signals. Ground and target-voltage reference are also commonly connected.

Q5. What is STM32CubeIDE?

It is an integrated development environment used for STM32 project configuration, coding, building, programming and debugging.

Q6. Why is hardware validation important?

It confirms that the board, power supply, debug interface and basic peripherals work before more complex development begins.

Q7. What is the purpose of HAL_Init()?

It initializes the STM32 HAL library and its required system services, including the HAL time base setup.

Q8. Why is SystemClock_Config() required?

It configures the system clock and associated clock sources and prescalers for the application.

Q9. Why might an LED fail to blink?

Possible causes include incorrect pin configuration, missing GPIO clock, wrong LED polarity or firmware execution problems.

Q10. How do you verify UART communication?

Configure matching UART parameters, connect the serial interface and inspect transmitted data using a terminal.

Q11. What is the purpose of a debugger?

A debugger helps inspect program execution, variables, registers and faults to identify firmware problems.

Q12. What is the difference between programming and debugging?

Programming transfers firmware to the target memory, while debugging allows controlled execution and inspection of the running program.
