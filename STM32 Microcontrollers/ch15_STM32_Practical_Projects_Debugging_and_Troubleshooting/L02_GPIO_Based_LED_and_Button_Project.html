Lesson 2: GPIO-Based LED and Button Project

STM32 Practical Projects, Debugging and Troubleshooting

1. Learning Objectives

  • Understand GPIO-based project architecture.
  • Configure STM32 GPIO pins as inputs and outputs.
  • Interface an LED with an STM32 microcontroller.
  • Interface a push button using pull-up and pull-down resistors.
  • Implement polling-based button detection.
  • Implement interrupt-based button detection using EXTI.
  • Understand switch debouncing.

2. Project Overview

In this project, an STM32 microcontroller controls an LED using a push button. When the user presses the button, the firmware detects the input and changes the LED state.

Project Requirements

  • STM32 development board.
  • One user LED or external LED.
  • One push button.
  • Current-limiting resistor for an external LED.
  • STM32CubeIDE and STM32CubeMX configuration.
  • USB cable and ST-LINK programmer/debugger.

LED Configuration

  4. Configure it as GPIO_Output.
  5. Select an appropriate output type and speed.
  6. Set the initial output state.

Button Configuration

  1. Select the button pin, for example PC13.
  2. Configure it as GPIO_Input.
  3. Select Pull-Up if the button connects the pin to ground when pressed.
  4. Generate the code.

The correct pin mode and pull configuration must match the actual electrical circuit.

7. Project 1: LED Blinking

First verify that the selected GPIO output can control the LED.

Program


#include "main.h"

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        HAL_GPIO_TogglePin(
            GPIOA,
            GPIO_PIN_5
        );

        HAL_Delay(500);
    }
}

Program Explanation

  1. Initialize the HAL library.
  2. Configure the system clock.
  3. Initialize GPIO.
  4. Toggle the LED output.
  5. Wait approximately 500 ms before the next toggle.

Expected Result

The LED changes state approximately every 500 ms, giving a complete ON-OFF cycle of approximately one second.

8. Project 2: Button-Controlled LED Using Polling

Polling continuously checks the button input in the main loop. When a press is detected, the LED state changes.

Program


#include "main.h"

int main(void)
{
    GPIO_PinState buttonState;
    GPIO_PinState previousState = GPIO_PIN_SET;

    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        buttonState = HAL_GPIO_ReadPin(
            GPIOC,
            GPIO_PIN_13
        );

        if (previousState == GPIO_PIN_SET &&
            buttonState == GPIO_PIN_RESET)
        {
            HAL_GPIO_TogglePin(
                GPIOA,
                GPIO_PIN_5
            );

            HAL_Delay(30);
        }

        previousState = buttonState;
    }
}

Program Explanation

  • The button uses an active-LOW pull-up arrangement.
  • Released state is HIGH.
  • Pressed state is LOW.
  • The HIGH-to-LOW transition is detected.
  • The LED toggles when a press is detected.

This is a basic teaching example. A fixed delay after detecting an edge is not a complete debounce algorithm. A robust design should confirm that the input remains stable for a defined interval and should detect release before accepting another press.

9. Switch Debouncing

Mechanical push buttons can produce multiple rapid electrical transitions when their contacts open or close. This is called switch bounce.

Without Debouncing

Button Signal:

HIGH ─────┐  ┌─┐ ┌──┐
          └──┘ └─┘  └────
             Contact bounce

With Debouncing

Button Signal:

HIGH ─────┐
          |
          |
LOW  ─────└────────────────
        Stable transition

Common Debouncing Methods

  • Software delay and stable-state verification.
  • Periodic sampling with a counter.
  • Timer-based debounce state machine.
  • Hardware RC filtering.
  • Dedicated debounce circuits.

Periodic Sampling Example


#include "main.h"

#define DEBOUNCE_SAMPLES 5

int main(void)
{
    uint8_t stableCount = 0;
    GPIO_PinState rawState;
    GPIO_PinState stableState = GPIO_PIN_SET;

    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        rawState = HAL_GPIO_ReadPin(
            GPIOC,
            GPIO_PIN_13
        );

        if (rawState == GPIO_PIN_RESET)
        {
            if (stableCount < DEBOUNCE_SAMPLES)
            {
                stableCount++;
            }
        }
        else
        {
            stableCount = 0;
        }

        if (stableCount == DEBOUNCE_SAMPLES &&
            stableState == GPIO_PIN_SET)
        {
            stableState = GPIO_PIN_RESET;

            HAL_GPIO_TogglePin(
                GPIOA,
                GPIO_PIN_5
            );
        }

        if (rawState == GPIO_PIN_SET)
        {
            stableState = GPIO_PIN_SET;
        }

        HAL_Delay(10);
    }
}

Five consecutive samples at 10 ms intervals provide approximately 50 ms of confirmation. This example detects a stable press and rearms after release. For more demanding applications, use a dedicated debounce state machine and validate timing against the button's actual behavior.

10. Project 3: Button-Controlled LED Using EXTI Interrupt

An external interrupt allows the STM32 to respond to a button transition without continuously polling the input.

Configuration

  1. Select the button pin in STM32CubeMX.
  2. Configure the pin as GPIO_EXTI.
  3. Select the falling edge for an active-LOW button.
  4. Enable the corresponding EXTI interrupt in NVIC.
  5. Generate the code.

HAL Callback Example


#include "main.h"

volatile uint8_t buttonEvent = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_13)
    {
        buttonEvent = 1;
    }
}

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        if (buttonEvent != 0)
        {
            buttonEvent = 0;

            HAL_GPIO_TogglePin(
                GPIOA,
                GPIO_PIN_5
            );
        }
    }
}

The callback runs in interrupt context. It only sets an event flag; the main loop performs the LED operation. The interrupt handler generated by CubeMX must call HAL_GPIO_EXTI_IRQHandler() for the relevant pin.

This simple flag can merge multiple button events if they arrive before the main loop processes them. Use a counter or RTOS queue when every event must be preserved. The flag is volatile for compiler visibility, not because volatile guarantees atomicity or synchronization.

13. Common Troubleshooting

LED Does Not Turn ON

  • Check the selected GPIO pin.
  • Verify output mode and GPIO clock.
  • Check LED polarity and current-limiting resistor.
  • Confirm whether the board LED is active-high or active-low.

Button Input Is Always HIGH

  • Check the button connection to ground.
  • Verify pull-up configuration.
  • Confirm the correct GPIO pin.
  • Check the electrical connection using a multimeter.

LED Toggles Multiple Times

  • Mechanical contact bounce may be present.
  • Implement software or hardware debouncing.
  • Check whether the firmware detects both press and release edges.

EXTI Does Not Work

  • Verify EXTI line configuration.
  • Check the selected edge trigger.
  • Enable the corresponding NVIC interrupt.
  • Check the generated IRQ handler.
  • Verify that the HAL callback receives the expected pin.

14. Placement-Oriented Interview Questions and Answers

Q1. What is GPIO?

GPIO stands for General Purpose Input/Output. It allows a microcontroller to interface with external digital signals.

Q2. What is the difference between GPIO input and output?

An input reads an external logic state, while an output drives a configured logic state.

Q3. What is a pull-up resistor?

A pull-up resistor connects an input to a positive logic supply through resistance, giving it a defined HIGH state when no external signal pulls it LOW.

Q4. What is switch debouncing?

Debouncing prevents multiple detections caused by rapid electrical transitions from mechanical switch contacts.

Q5. What is EXTI?

EXTI is the external interrupt/event controller used to detect configured signal transitions on supported STM32 pins.

Q6. What is the difference between rising-edge and falling-edge detection?

Rising-edge detection responds to LOW-to-HIGH transitions; falling-edge detection responds to HIGH-to-LOW transitions.

Q7. Why should an ISR be short?

A short ISR reduces interrupt latency and allows the processor to return quickly to normal execution.

Q8. Why is a current-limiting resistor required for an LED?

It limits current to protect the LED and microcontroller output from excessive current.

Q9. What is polling?

Polling is repeatedly checking a peripheral or input state in software.

Q10. Why use an interrupt instead of polling?

Interrupts allow the processor to respond to events without continuously checking the input.

Q11. What does HAL_GPIO_ReadPin() do?

It reads the logic state of a specified GPIO pin.

Q12. What does HAL_GPIO_TogglePin() do?

It changes the output latch state of a specified GPIO pin.

16. Lesson Summary

  • GPIO supports digital input and output interfacing.
  • LEDs require appropriate current limiting.
  • Pull-up and pull-down resistors establish defined input states.
  • Polling repeatedly checks input states.
  • EXTI supports event-driven input detection.
  • Switch debouncing prevents false button events.
  • ISRs should perform minimal work and defer processing.
