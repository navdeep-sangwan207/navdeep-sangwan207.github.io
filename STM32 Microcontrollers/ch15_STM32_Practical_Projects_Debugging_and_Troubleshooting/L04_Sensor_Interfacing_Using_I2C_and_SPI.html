2. Project Overview

Sensors convert physical quantities such as temperature, pressure, acceleration and light into electrical signals. Digital sensors communicate with microcontrollers through protocols such as I2C and SPI.

Example Sensors

  • Temperature sensors
  • Humidity sensors
  • Pressure sensors
  • Accelerometers
  • Gyroscopes
  • Light sensors

This lesson demonstrates the general firmware structure used to communicate with a digital sensor. The register addresses and data formats in a real application must come from the selected sensor's datasheet.

4. I2C Communication for Sensors

I2C is a synchronous serial communication protocol that uses two signal lines.

Signal Purpose
SDA Serial data
SCL Serial clock

I2C Characteristics

  • Uses two communication lines.
  • Supports multiple addressed devices on a bus.
  • Uses device addresses.
  • Uses ACK and NACK responses.
  • Typically uses open-drain signaling with pull-up resistors.
  • Supports standard, fast and other speed modes depending on the device.

Example I2C Connection

STM32 Board              I2C Sensor
-----------              ----------
SDA  ------------------- SDA
SCL  ------------------- SCL
GND  ------------------- GND
3.3V ------------------- VDD

Check the sensor supply and I/O voltage requirements. Pull-up resistors must be suitable for the bus voltage, capacitance and speed. Some modules already contain pull-up resistors.

5. SPI Communication for Sensors

SPI is a synchronous serial protocol commonly used for high-speed communication with sensors, displays and memory devices.

Signal Purpose
MOSI Master Out, Slave In
MISO Master In, Slave Out
SCLK Serial clock
CS / NSS Slave selection

Example SPI Connection

STM32 Board              SPI Sensor
-----------              ----------
MOSI ------------------- MOSI
MISO ------------------- MISO
SCLK ------------------- SCLK
GPIO ------------------ CS
GND  ------------------- GND
3.3V ------------------- VDD

The sensor datasheet specifies the required clock polarity, clock phase, bit order, chip-select polarity and timing. These must match the STM32 configuration.

6. I2C vs SPI

Feature I2C SPI
Signal lines Two Typically four
Device selection Address Chip select
Clock SCL SCLK
Data direction Shared SDA line Separate MOSI and MISO
Typical topology Shared bus Shared bus with separate CS lines
Speed Depends on I2C mode Often higher, device-dependent
Pull-ups Normally required Not normally required for standard SPI signals

7. Configure I2C Using STM32CubeMX

  1. Open the STM32CubeIDE project.
  2. Select a supported I2C peripheral.
  3. Enable I2C mode.
  4. Configure SDA and SCL alternate-function pins.
  5. Select an appropriate timing configuration.
  6. Configure the peripheral clock source if required.
  7. Generate the project code.

Some STM32 families use a timing-register configuration, while older peripherals use clock-speed and duty-cycle settings. Use CubeMX and the reference manual for the selected device.

8. I2C Sensor Register Read Operation

Many digital sensors contain internal registers. A microcontroller writes a register address and then reads its contents.

Typical Register Read Sequence

1. START condition
2. Send sensor address + Write
3. Receive ACK
4. Send register address
5. Receive ACK
6. Repeated START
7. Send sensor address + Read
8. Receive ACK
9. Read register data
10. Master sends NACK
11. STOP condition

The exact sequence can vary by sensor. Follow the device datasheet for register addressing and transaction format.

9. I2C Programming Using STM32 HAL

Example Configuration


#include "main.h"

extern I2C_HandleTypeDef hi2c1;

#define SENSOR_ADDRESS  (0x48U << 1)
#define SENSOR_REG      0x00U

uint8_t sensorData[2];

HAL_StatusTypeDef Read_Sensor_Register(void)
{
    return HAL_I2C_Mem_Read(
        &hi2c1,
        SENSOR_ADDRESS,
        SENSOR_REG,
        I2C_MEMADD_SIZE_8BIT,
        sensorData,
        2,
        100
    );
}

This example uses a hypothetical 7-bit sensor address of 0x48 and an 8-bit register address of 0x00. The HAL address argument is shifted left by one bit in common STM32 HAL implementations. Verify the API and address convention for the HAL version in use.

Reading Sensor Data


if (Read_Sensor_Register() == HAL_OK)
{
    uint16_t rawData =
        ((uint16_t)sensorData[0] << 8) |
        sensorData[1];

    /* Convert rawData according to the sensor datasheet. */
}
else
{
    /* Handle communication error. */
}

The byte order, signedness, scaling and meaning of the received data are sensor-specific. The example assumes a big-endian 16-bit value only for illustration.

10. SPI Sensor Register Read Operation

In SPI, the master selects the sensor using chip select and generates clock pulses while transmitting and receiving data.

Typical SPI Read Sequence

  1. Set CS LOW.
  2. Transmit the sensor read command and register address.
  3. Transmit dummy data if required to generate clock pulses.
  4. Receive the sensor response.
  5. Set CS HIGH after the transaction.

The read command bit, register address format, dummy bytes and CS timing depend on the sensor datasheet.

11. SPI Programming Using STM32 HAL

Example HAL Code


#include "main.h"

extern SPI_HandleTypeDef hspi1;

#define SENSOR_CS_LOW() \
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_RESET)

#define SENSOR_CS_HIGH() \
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_SET)

HAL_StatusTypeDef SPI_Read_Example(
    uint8_t registerAddress,
    uint8_t *receivedData,
    uint16_t length)
{
    HAL_StatusTypeDef status;
    uint8_t command = registerAddress | 0x80U;

    SENSOR_CS_LOW();

    status = HAL_SPI_Transmit(
        &hspi1,
        &command,
        1,
        100
    );

    if (status == HAL_OK)
    {
        status = HAL_SPI_Receive(
            &hspi1,
            receivedData,
            length,
            100
        );
    }

    SENSOR_CS_HIGH();

    return status;
}

This is an illustrative transaction pattern, not a universal sensor driver. The read bit mask, address format, dummy bytes and full-duplex behavior must be adapted to the actual sensor protocol.

For many SPI peripherals, receiving data requires transmitting dummy bytes to generate clock pulses. A device-specific implementation may therefore use HAL_SPI_TransmitReceive() or a transmit followed by a receive operation.

13. Sensor Initialization and Validation

  1. Read the sensor datasheet.
  2. Check the supply voltage and logic levels.
  3. Identify the I2C address or SPI chip-select connection.
  4. Configure the STM32 peripheral.
  5. Check whether the sensor responds.
  6. Read its identification register if available.
  7. Write the required configuration registers.
  8. Wait for the specified startup or conversion time.
  9. Read measurement registers.
  10. Convert raw data using the sensor's documented formula.

A successful communication transaction does not by itself prove that the measurement is valid. Check sensor status, conversion readiness, calibration and data format.

14. Common Sensor Communication Problems

I2C Sensor Not Detected

  • Incorrect 7-bit address.
  • Missing or unsuitable pull-up resistors.
  • Incorrect SDA or SCL pin mapping.
  • Sensor not powered correctly.
  • Incorrect I2C timing configuration.

I2C Communication Timeout

  • Check whether the bus is stuck LOW.
  • Check the sensor supply and ground.
  • Inspect pull-up resistor values.
  • Check for an incorrect address or unsupported transaction.

SPI Sensor Returns Incorrect Data

  • Check SPI clock polarity and phase.
  • Verify the bit order.
  • Check CS polarity and timing.
  • Verify the read command and register address format.
  • Check dummy-byte requirements.

Measurement Values Are Incorrect

  • Check byte order.
  • Check signed and unsigned data interpretation.
  • Verify the sensor conversion formula.
  • Check calibration and operating range.
  • Verify that the correct data registers were read.

15. Practical Testing and Debugging Tools

  • Multimeter: Check supply voltage and ground.
  • Oscilloscope: Inspect clock and data waveforms.
  • Logic analyzer: Decode I2C and SPI transactions.
  • STM32CubeIDE debugger: Inspect variables, buffers and program flow.
  • Datasheet: Verify electrical characteristics and register definitions.
  • Reference manual: Verify STM32 peripheral configuration.

16. Placement-Oriented Interview Questions and Answers

Q1. What is a digital sensor?

A sensor that provides measurement information in digital form through a digital interface or digital output.

Q2. What is I2C?

I2C is a synchronous serial bus that normally uses SDA and SCL lines for communication.

Q3. What is SPI?

SPI is a synchronous serial communication protocol commonly using MOSI, MISO, SCLK and chip-select signals.

Q4. Why are pull-up resistors used in I2C?

I2C devices commonly use open-drain outputs, so pull-up resistors establish the HIGH bus level.

Q5. What is an I2C address?

It identifies a device on the I2C bus. Common addressing uses 7-bit addresses, with 10-bit addressing also supported.

Q6. What is ACK in I2C?

ACK is a LOW response on the ninth clock pulse indicating that the receiver acknowledged the byte.

Q7. What is chip select in SPI?

It selects the SPI slave device that should participate in the transaction.

Q8. What are SPI clock modes?

They are combinations of clock polarity (CPOL) and clock phase (CPHA) that define clock idle level and data sampling edge.

Q9. Why is a sensor datasheet important?

It provides the sensor's electrical limits, register map, timing requirements and data conversion rules.

Q10. What is a register map?

It is a documented list of sensor registers and their addresses, fields and functions.

Q11. Why might an I2C sensor return NACK?

Possible causes include an incorrect address, missing power, wiring problems or an unsupported transaction.

Q12. How can SPI communication be debugged?

Inspect CS, SCLK, MOSI and MISO signals with a logic analyzer or oscilloscope and compare the transaction with the datasheet.
