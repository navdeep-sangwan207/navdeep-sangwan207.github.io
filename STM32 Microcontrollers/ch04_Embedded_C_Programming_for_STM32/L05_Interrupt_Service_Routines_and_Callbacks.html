Lesson 5: Interrupt Service Routines and Callbacks

Learn how STM32 firmware responds to hardware events using interrupt handlers, ISR design principles and HAL callbacks.

← Back to Chapter 4 | STM32 Course Home

1. Learning Objectives

  • Understand interrupts and interrupt service routines.
  • Differentiate polling and interrupt-based programming.
  • Understand interrupt vectors and handler functions.
  • Learn how to write efficient ISRs.
  • Understand shared variables and volatile qualification.
  • Learn STM32 HAL interrupt callbacks.
  • Understand interrupt priorities and nested interrupts.
  • Identify common interrupt programming errors.

2. What is an Interrupt?

An interrupt is an event that causes the processor to temporarily suspend its current execution and transfer control to an interrupt handler.

Common STM32 interrupt sources include:

  • GPIO external interrupt (EXTI).
  • Timer update or capture/compare event.
  • UART receive or transmit event.
  • ADC conversion completion.
  • DMA transfer completion.
  • System exceptions such as SysTick.
Example: When a UART byte is received, the peripheral can request an interrupt. The processor executes the corresponding handler to process the receive event.

3. What is an Interrupt Service Routine (ISR)?

An Interrupt Service Routine is a function executed in response to an interrupt request. In STM32 firmware, the handler name must match the interrupt vector provided by the startup file and device configuration.

Basic ISR Structure

void EXTI0_IRQHandler(void)
{
    /* Handle EXTI0 interrupt */
}

This is an illustrative handler. A real handler must also acknowledge or clear the relevant interrupt condition according to the peripheral's requirements.

4. Polling vs Interrupt-Based Programming

Polling Interrupt-Based
CPU repeatedly checks a status flag. Hardware notifies the processor through an interrupt.
Can waste CPU time while waiting. Allows the CPU to perform other work between events.
Simple to implement. Requires interrupt configuration and handler design.
Response depends on polling frequency. Response depends on interrupt latency and priority.

Polling Example

while ((USART2->SR & USART_SR_RXNE) == 0U)
{
    /* Wait for received data */
}

This register example is specific to STM32 families that implement the shown USART status register. Other families may use different register names and flags.

Interrupt-Based Concept

void USART2_IRQHandler(void)
{
    /* Handle UART receive event */
}

5. Interrupt Vector Table

The interrupt vector table contains addresses of exception and interrupt handler functions. The processor uses this table to locate the handler when an exception occurs.

Important Entries

  • Initial Main Stack Pointer.
  • Reset Handler.
  • NMI Handler.
  • HardFault Handler.
  • SysTick Handler.
  • Peripheral interrupt handlers.

The startup file supplies the vector table and default handler definitions for the selected STM32 device.

6. Interrupt Handling Sequence

  1. A peripheral or system event generates an interrupt request.
  2. The interrupt controller evaluates enable and priority settings.
  3. The processor completes the current instruction as required by the architecture.
  4. The processor stacks the exception context.
  5. The processor enters Handler mode and executes the ISR.
  6. The handler services the event and acknowledges the source as required.
  7. The processor returns from the exception and resumes execution.
Interrupt entry and return are managed by the Cortex-M exception mechanism. The exact stacking behavior can vary with processor features, including floating-point support.

7. Writing an Efficient ISR

An ISR should execute quickly and predictably. Long-running processing should normally be performed outside the ISR.

Recommended Practices

  • Keep the handler short.
  • Clear or acknowledge the interrupt source correctly.
  • Avoid blocking delays.
  • Avoid waiting for UART or other peripheral operations.
  • Avoid lengthy calculations.
  • Use flags or buffers to defer processing.
  • Protect shared data appropriately.
  • Measure worst-case execution time when timing matters.

Example: Set a Flag in an ISR

#include <stdint.h>

volatile uint8_t interrupt_flag = 0U;

void EXTI0_IRQHandler(void)
{
    /* Clear the EXTI pending condition using
       the device-specific register mechanism. */

    interrupt_flag = 1U;
}

int main(void)
{
    while (1)
    {
        if (interrupt_flag != 0U)
        {
            interrupt_flag = 0U;

            /* Perform longer processing here */
        }
    }
}
This example illustrates the flag technique only. A production EXTI handler must clear the correct pending bit using the selected STM32 family's documented mechanism. If the event can occur again before the flag is processed, a single flag may lose event counts; use a counter or queue where required.

8. Shared Variables and Volatile

A variable accessed by both normal code and an ISR may need volatile qualification so the compiler does not assume that its value remains unchanged between accesses.

Example

#include <stdint.h>

volatile uint8_t data_ready = 0U;

void Example_IRQHandler(void)
{
    data_ready = 1U;
}

int main(void)
{
    while (1)
    {
        if (data_ready != 0U)
        {
            data_ready = 0U;

            /* Process the event */
        }
    }
}
volatile does not make an operation atomic, prevent race conditions, or provide general thread synchronization. Multi-byte shared data, read-modify-write operations and data shared with DMA or an RTOS may require additional synchronization and memory-ordering considerations.

9. Interrupt Priorities and Nested Interrupts

The Nested Vectored Interrupt Controller (NVIC) manages interrupt enabling, pending state and priority.

  • Lower numerical priority values represent higher priority.
  • Higher-priority interrupts can preempt lower-priority handlers.
  • Equal-priority interrupts do not preempt one another.
  • Priority grouping determines the split between preemption priority and subpriority.
  • The number of implemented priority bits depends on the device.

CMSIS Example

#include "stm32f4xx.h"

void configure_interrupt(void)
{
    NVIC_SetPriority(EXTI0_IRQn, 5U);
    NVIC_EnableIRQ(EXTI0_IRQn);
}

The peripheral's own interrupt source and GPIO/EXTI configuration must also be enabled. NVIC configuration alone is not sufficient.

10. HAL Interrupt Programming

STM32 HAL provides functions to start interrupt-based peripheral operations. When the operation completes or a configured event occurs, HAL calls an application callback.

UART Receive Interrupt Example

#include "main.h"

uint8_t rx_data;

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();

    HAL_UART_Receive_IT(&huart2, &rx_data, 1U);

    while (1)
    {
        /* Main application */
    }
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        /* Process the received byte or set a flag */

        HAL_UART_Receive_IT(&huart2, &rx_data, 1U);
    }
}

Explanation

  • HAL_UART_Receive_IT() starts an interrupt-based receive operation.
  • The UART peripheral receives the requested data.
  • The UART interrupt handler invokes the HAL IRQ handler.
  • HAL processes the event and calls the receive-complete callback.
  • The callback rearms reception for the next byte.
The generated interrupt handler must call HAL_UART_IRQHandler(&huart2) for this UART. CubeMX-generated startup and IRQ configuration normally provide the required structure. Verify the selected USART instance, NVIC settings and generated code.

11. Common STM32 HAL Callbacks

Callback Purpose
HAL_UART_RxCpltCallback() UART receive operation completed.
HAL_UART_TxCpltCallback() UART transmit operation completed.
HAL_GPIO_EXTI_Callback() GPIO external interrupt event handled by HAL.
HAL_TIM_PeriodElapsedCallback() Timer period elapsed event.
HAL_ADC_ConvCpltCallback() ADC conversion operation completed.
HAL_SPI_RxCpltCallback() SPI receive operation completed.

Callback availability and signatures depend on the HAL driver and STM32 family. Use the HAL documentation and header files for the selected device.

12. GPIO External Interrupt Callback

Example

#include "main.h"

volatile uint8_t button_event = 0U;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_13)
    {
        button_event = 1U;
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        if (button_event != 0U)
        {
            button_event = 0U;

            /* Handle button event outside callback */
        }
    }
}

This example assumes the selected board and CubeMX configuration assign the button to the corresponding EXTI-capable pin. GPIO mode, pull configuration, EXTI routing and NVIC must be configured correctly.

13. Interrupt Latency

Interrupt latency is the time between an interrupt event and the beginning of execution of its handler.

Factors Affecting Latency

  • Current processor instruction and execution state.
  • Interrupt masking and priority.
  • Higher-priority interrupt activity.
  • Memory wait states and bus activity.
  • Exception entry and context stacking.

Low and predictable interrupt latency is important in real-time embedded applications.

14. Common Interrupt Programming Errors

Error Possible Cause or Correction
ISR never executes Check peripheral source, NVIC enable, vector name and configuration.
Interrupt occurs repeatedly Check whether the source or pending condition is correctly cleared.
Unexpected variable values Review shared data access, volatile use and synchronization.
System becomes unresponsive Check for long-running ISR code or interrupt storms.
UART callback not called Check receive start, IRQ handler and HAL IRQ dispatch.
Unexpected nested interrupts Review NVIC priorities and priority grouping.

15. Placement-Oriented Interview Questions and Answers

Q1. What is an interrupt?

An interrupt is an event that causes the processor to execute a handler instead of continuing normal program flow.

Q2. What is an ISR?

An ISR is a function executed when the corresponding interrupt or exception is accepted by the processor.

Q3. Why should an ISR be short?

A short ISR reduces interrupt blocking, latency for other events and the risk of missing time-critical work.

Q4. What is the NVIC?

The Nested Vectored Interrupt Controller manages external interrupt enabling, pending state and priority on Cortex-M processors.

Q5. What is interrupt latency?

It is the time between an interrupt event and the start of its handler execution.

Q6. What is a callback function?

A callback is a function invoked by a software component or driver when a particular event or operation occurs.

Q7. What is the difference between an ISR and a HAL callback?

The ISR is the interrupt handler connected to the vector table. A HAL callback is an application-level function called by the HAL driver while processing the interrupt event.

Q8. Why is volatile used for ISR-shared variables?

It tells the compiler that accesses must account for changes that can occur outside the normal flow of code.

Q9. Does volatile make a variable atomic?

No. Volatile does not guarantee atomic access or synchronization.

Q10. What is a nested interrupt?

It occurs when a higher-priority interrupt preempts an interrupt handler that is already executing.

Q11. What happens if an interrupt flag is not cleared?

The interrupt may remain pending or be generated again, depending on the peripheral's interrupt mechanism.

Q12. What is the purpose of HAL_UART_RxCpltCallback()?

It allows application code to respond when a HAL interrupt-based UART receive operation completes.

17. Lesson Summary

  • Interrupts allow event-driven processor execution.
  • ISRs handle hardware and system events.
  • The vector table maps exceptions and interrupts to handlers.
  • NVIC manages external interrupt priorities and enabling.
  • ISRs should be short and predictable.
  • Shared variables may require volatile and additional synchronization.
  • HAL callbacks provide application-level event handling.
  • Interrupt configuration requires both peripheral and NVIC setup.
