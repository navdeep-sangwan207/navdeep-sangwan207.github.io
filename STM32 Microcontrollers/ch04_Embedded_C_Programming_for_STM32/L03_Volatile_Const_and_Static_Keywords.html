Lesson 3: Volatile, Const and Static Keywords

Understand how C storage duration, object qualification, and compiler optimization affect STM32 firmware.

← Back to Chapter 4 | STM32 Course Home

1. Learning Objectives

  • Understand the volatile keyword.
  • Learn why hardware registers use volatile.
  • Understand const and read-only objects.
  • Learn the static storage duration and linkage concepts.
  • Understand local static and global static variables.
  • Study const and volatile pointer combinations.
  • Apply these keywords in STM32 firmware.

2. Why Are These Keywords Important?

Embedded firmware interacts with hardware, interrupts, peripheral registers, and shared data. The compiler optimizes code to improve performance and reduce memory use.

The keywords volatile, const, and static help express important properties of program objects and their storage.

Keyword Main Purpose
volatile Requires observable accesses to an object to be respected by the compiler.
const Prevents modification of an object through that const-qualified access.
static Controls storage duration or linkage, depending on where it is declared.

3. What is Volatile?

The volatile keyword tells the compiler that accesses to an object are significant and that its value may change in ways not represented by ordinary program flow.

This is particularly important when working with:

  • Hardware peripheral registers.
  • Variables modified by interrupt service routines.
  • Memory locations updated by DMA.
  • Memory-mapped hardware status flags.

Syntax

volatile int flag;

Example Without Volatile

int flag = 0;

int main(void)
{
    while (flag == 0)
    {
        /* Wait for flag */
    }

    while (1)
    {
    }
}

If the compiler can determine that flag is never changed through the visible program flow, it may optimize the loop in a way that does not repeatedly read the variable.

Example With Volatile

volatile int flag = 0;

int main(void)
{
    while (flag == 0)
    {
        /* Wait for flag */
    }

    while (1)
    {
    }
}

The volatile qualification requires the compiler to perform the observable accesses to flag as specified by the C implementation.

4. Volatile in Interrupt Programming

An interrupt service routine may modify a variable while the main program is executing.

Example

#include <stdint.h>

volatile uint32_t interrupt_count = 0;

void EXTI0_IRQHandler(void)
{
    interrupt_count++;

    /* Clear the relevant EXTI pending flag here,
       according to the selected STM32 family. */
}

int main(void)
{
    while (1)
    {
        if (interrupt_count >= 10U)
        {
            /* Process interrupt count */
            interrupt_count = 0U;
        }
    }
}

Explanation

  • The interrupt handler updates interrupt_count.
  • The main program reads the same variable.
  • Volatile prevents the compiler from treating the value as unchanged between required accesses.
Volatile does not make an operation atomic and does not provide general synchronization. If a shared variable requires atomic access, use an appropriate atomic type, critical section, or interrupt-safe design for the target.

5. Volatile with Hardware Registers

Hardware registers can change independently of normal program execution. For example, a timer status register may be updated by the peripheral.

Illustrative Example

#include <stdint.h>

#define STATUS_REGISTER_ADDRESS  0x40000000UL

#define STATUS_REG \
    (*(volatile uint32_t *)STATUS_REGISTER_ADDRESS)

int main(void)
{
    while ((STATUS_REG & (1U << 0)) == 0U)
    {
        /* Wait for status flag */
    }

    while (1)
    {
    }
}
The address is illustrative only. Use the correct device-specific register address and bit definition. CMSIS device headers normally provide suitable register definitions already qualified for hardware access.

6. What is Const?

The const keyword qualifies an object so that it cannot be modified through that const-qualified access.

Syntax

const int value = 100;

Example

#include <stdint.h>

int main(void)
{
    const uint32_t system_frequency = 80000000U;

    /* Reading the constant is allowed */
    uint32_t copy = system_frequency;

    /* system_frequency = 100000000U; */
    /* This modification is not allowed */

    while (1)
    {
        (void)copy;
    }
}

Applications in Embedded Systems

  • Fixed configuration values.
  • Lookup tables.
  • Calibration constants.
  • Function parameters that should not be modified.
  • Read-only data structures.

7. Const Lookup Tables

Lookup tables store predefined values that firmware reads during execution.

Example

#include <stdint.h>

const uint16_t adc_reference_table[] =
{
    0U,
    1000U,
    2000U,
    3000U,
    4095U
};

int main(void)
{
    uint16_t value = adc_reference_table[3];

    while (1)
    {
        (void)value;
    }
}

The array is const-qualified, so the program cannot modify its elements through this array expression.

A const object is not guaranteed by the C language to be stored in Flash. Its placement depends on the compiler, linker script, and target memory model.

8. What is Static?

The static keyword has different effects depending on whether it is used inside a function or at file scope.

Local Static Variable

A local static variable retains its value between function calls. It has static storage duration but block scope. 

#include <stdint.h>

uint32_t get_count(void)
{
    static uint32_t count = 0U;

    count++;

    return count;
}

int main(void)
{
    uint32_t a = get_count();
    uint32_t b = get_count();
    uint32_t c = get_count();

    while (1)
    {
        (void)a;
        (void)b;
        (void)c;
    }
}

Values returned:

a = 1
b = 2
c = 3

9. Static Global Variables

At file scope, static gives an object internal linkage. This means its name is available only within that source file.

Example

#include <stdint.h>

static uint32_t system_counter = 0U;

void update_counter(void)
{
    system_counter++;
}

uint32_t get_counter(void)
{
    return system_counter;
}

Other source files cannot access system_counter by declaring it as an ordinary external variable.

Static Function

static void internal_function(void)
{
    /* Function is limited to this source file */
}

A static function at file scope also has internal linkage.

10. Static vs Automatic Local Variables

Feature Automatic Local Static Local
Storage duration Automatic Static
Lifetime During the function block execution Entire program execution
Default initialization Indeterminate if not initialized Zero-initialized if not explicitly initialized
Retains value between calls No Yes

Automatic Variable Example

void function(void)
{
    int count = 0;

    count++;
}

Each call creates a new automatic count variable initialized to zero.

11. Const and Volatile Together

An object can be both const-qualified and volatile-qualified. This is useful when hardware updates a register that software must only read.

Example

const volatile uint32_t *status_register;

This declares a pointer to a volatile object that is const through this access path. Software can read the pointed-to value but cannot modify it through this pointer.

Applications

  • Read-only hardware status registers.
  • Hardware-updated status fields.
  • Memory locations that change independently of software.

12. Const and Volatile Pointer Combinations

Declaration Meaning
const int *p; Pointer to a const-qualified integer.
int *const p = &x; Const pointer to a modifiable integer.
const int *const p = &x; Const pointer to a const-qualified integer.
volatile int *p; Pointer to a volatile integer.
const volatile int *p; Pointer to a const volatile integer.

Example

int value = 10;

int *const pointer = &value;

*pointer = 20;

/* pointer = another_address; */
/* Not allowed: pointer itself is const */

13. Practical STM32 Example: Interrupt Flag

A common embedded pattern is to use an interrupt to set a flag and let the main loop process the event. 

#include "main.h"
#include <stdint.h>

volatile uint8_t button_event = 0U;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        button_event = 1U;
    }
}

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        if (button_event != 0U)
        {
            button_event = 0U;

            /* Process button event */
        }
    }
}

Working

  1. GPIO external interrupt is configured in the project.
  2. The HAL callback runs when the configured interrupt is handled.
  3. The callback sets button_event.
  4. The main loop detects and processes the event.
This example assumes the selected GPIO pin and EXTI line are configured correctly. If events can arrive faster than the main loop processes them, a single flag may lose events. Use a counter, queue, or another suitable event mechanism when every event must be preserved.

14. Common Mistakes

Mistake Correct Understanding
Using volatile to make code thread-safe Volatile does not provide atomicity or synchronization.
Assuming const always means Flash memory Memory placement depends on the implementation and linker configuration.
Assuming static always means global Static local variables have block scope and static storage duration.
Using an uninitialized automatic variable Initialize variables before reading them.
Using static unnecessarily Choose storage duration and linkage according to the design.
Confusing const pointer and pointer to const Check which part of the declaration is qualified.

15. Placement-Oriented Interview Questions and Answers

Q1. What is volatile in C?

Volatile tells the compiler that accesses to an object are significant and that its value may change outside ordinary program flow.

Q2. Why is volatile used in an ISR-shared variable?

Because an interrupt can modify the variable independently of the main program, so the compiler must respect the required accesses to it.

Q3. Does volatile guarantee atomicity?

No. Volatile does not guarantee atomic access or thread safety.

Q4. What is const?

Const qualifies an object so that it cannot be modified through that const-qualified access.

Q5. What is static local variable?

It is a local variable with static storage duration that retains its value between function calls.

Q6. What is the purpose of static at file scope?

It gives a file-scope variable or function internal linkage, restricting its name to the current source file.

Q7. What is the difference between static and global variables?

A file-scope variable normally has external linkage unless declared static. A static file-scope variable has internal linkage. Both have static storage duration.

Q8. What is const volatile?

It describes an object that must be accessed as volatile but cannot be modified through the const-qualified access.

Q9. Can a const variable be changed?

It cannot be modified through a const-qualified lvalue. Attempting to modify a defined const object through a cast that removes const qualification results in undefined behavior.

Q10. Why are hardware registers volatile?

Hardware can change register values independently of normal program execution, and software accesses to those registers must be preserved.

Q11. What is the lifetime of a static variable?

Its storage duration lasts for the entire execution of the program.

Q12. What is the difference between const int *p and int *const p?

The first is a pointer to a const-qualified integer. The second is a const pointer to a modifiable integer.

17. Lesson Summary

  • Volatile preserves required accesses to objects that may change independently.
  • Const prevents modification through a const-qualified access.
  • Static local variables retain values between function calls.
  • Static at file scope provides internal linkage.
  • Hardware registers commonly use volatile-qualified definitions.
  • Const volatile is useful for read-only hardware status registers.
  • Volatile does not replace atomic operations or synchronization.
  • Correct use of these keywords improves embedded firmware design.
