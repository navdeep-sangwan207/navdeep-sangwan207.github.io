Lesson 2: STM32CubeMX Configuration and Code Generation

Configure STM32 pins, clocks, peripherals, and generate initialization code.

2. What is STM32CubeMX?

STM32CubeMX is a graphical configuration tool from STMicroelectronics. It helps developers configure STM32 microcontrollers and generate initialization code.

It is integrated into the STM32CubeIDE workflow and can also be used as a standalone configuration tool, depending on the installed software version.

Main Functions

  • MCU and development-board selection.
  • Pin assignment and GPIO configuration.
  • Clock-tree configuration.
  • Peripheral configuration.
  • Middleware and software-component configuration where supported.
  • HAL initialization-code generation.
  • Project configuration and code-generation settings.

4. Understanding the Pinout and Configuration View

The Pinout view displays the selected STM32 device and its available pins. Developers can assign pins to GPIO functions or alternate peripheral functions.

Common Pin Functions

Pin Function Purpose
GPIO_Input Reads digital input signals.
GPIO_Output Controls digital output signals.
USART_TX Transmits serial data.
USART_RX Receives serial data.
I2C_SCL Provides the I2C clock signal.
I2C_SDA Transfers I2C data.
SPI_SCK Provides the SPI clock signal.
ADC_IN Accepts an analog input for ADC conversion.
TIMx_CHy Provides timer channel functions such as PWM or input capture.
A pin may support multiple alternate functions, but only compatible functions can be assigned at the same time. Pin availability depends on the selected STM32 device.

5. Configuring GPIO Pins

GPIO configuration determines how a pin interacts with external digital signals.

Common GPIO Parameters

Parameter Description
Mode Input, output, alternate function, or analog.
Output Type Push-pull or open-drain, where applicable.
Pull-up/Pull-down Configures an internal pull-up or pull-down resistor.
Speed Configures the GPIO output transition-speed setting.
User Label Assigns a meaningful name to a pin in generated code.

Example: LED GPIO Configuration

  1. Open the Pinout view.
  2. Select the GPIO pin connected to the LED.
  3. Set its mode to GPIO_Output.
  4. Choose the required output type.
  5. Configure pull-up or pull-down if required by the circuit.
  6. Assign a user label such as LED_STATUS.
  7. Save the project configuration.
The LED pin, polarity, and electrical connection must be checked using the development-board schematic. A user label does not automatically determine the physical pin connection.

6. Clock Configuration

STM32 microcontrollers use clock sources and clock-distribution circuits to provide timing signals to the CPU, buses, and peripherals.

Common Clock Sources

  • HSI: High-speed internal oscillator.
  • HSE: High-speed external oscillator or clock source.
  • LSI: Low-speed internal oscillator.
  • LSE: Low-speed external oscillator, commonly used with a 32.768 kHz crystal.
  • PLL: Phase-locked loop used to generate derived clock frequencies.

Clock Configuration Workflow

  1. Open the Clock Configuration view.
  2. Choose an available clock source.
  3. Configure the PLL if required.
  4. Set the system clock source.
  5. Configure bus prescalers.
  6. Check the resulting clock frequencies.
  7. Resolve any clock validation errors.

Clock trees differ across STM32 families. Always use the oscillator specifications, voltage range, Flash wait-state requirements, and maximum clock limits of the selected MCU.

7. Peripheral Configuration

STM32CubeMX provides configuration options for peripherals such as UART, SPI, I2C, timers, ADC, DMA, and other device-specific hardware blocks.

Peripheral Important Configuration Parameters
UART / USART Baud rate, word length, parity, stop bits, TX/RX pins.
I2C Timing, addressing mode, clock speed, SCL/SDA pins.
SPI Master/slave mode, clock polarity, phase, data size, prescaler.
Timer Prescaler, auto-reload value, counter mode, channel settings.
ADC Resolution, channels, sampling time, trigger source.
DMA Direction, data width, increment settings, transfer mode.

Example: UART Configuration

  1. Open the connectivity peripheral configuration section.
  2. Enable a suitable USART instance.
  3. Assign the TX and RX pins.
  4. Set the required baud rate.
  5. Configure word length, parity, and stop bits.
  6. Enable interrupt or DMA settings if required.
  7. Save the configuration.

8. NVIC and Interrupt Configuration

The Nested Vectored Interrupt Controller (NVIC) manages interrupt enablement and priority for supported Cortex-M processors.

In STM32CubeMX, interrupt settings can be configured through the NVIC configuration area for supported peripherals.

Typical Configuration Steps

  1. Enable the required peripheral interrupt source.
  2. Open the NVIC settings.
  3. Enable the corresponding interrupt request.
  4. Configure its priority where required.
  5. Generate the project code.
  6. Implement the required interrupt callback or handler logic.
Enabling an NVIC interrupt alone is not always sufficient. The peripheral's own interrupt source and status flags must also be configured and handled correctly.

9. Understanding the .ioc File

The .ioc file stores the STM32CubeMX configuration associated with a project.

It can include information about:

  • Selected STM32 microcontroller or board.
  • GPIO pin assignments.
  • Clock configuration.
  • Peripheral settings.
  • Interrupt configuration.
  • DMA configuration.
  • Project and code-generation settings.
Example: 
STM32_LED_Project/
    STM32_LED_Project.ioc
    Core/
    Drivers/
    startup_stm32xxxx.s
    STM32xxxx_FLASH.ld
The .ioc file allows the configuration tool to reopen and modify the project's hardware configuration.

10. Code Generation

After configuring the pins, clocks, and peripherals, STM32CubeMX can generate initialization code for the project.

Code Generation Procedure

  1. Complete the required pin and peripheral configuration.
  2. Review the clock configuration.
  3. Open Project Manager.
  4. Set the project name and toolchain or IDE.
  5. Review the code-generation options.
  6. Save the .ioc configuration.
  7. Select Generate Code.
  8. Open or update the generated project in STM32CubeIDE.

Examples of Generated Functions

void SystemClock_Config(void);
static void MX_GPIO_Init(void);
static void MX_USART2_UART_Init(void);
static void MX_ADC1_Init(void);

These functions initialize the selected system clock, GPIO, and peripheral configurations. Their names and contents depend on the selected MCU and project settings.

11. User Code and Generated Code

STM32CubeMX generates initialization code and may regenerate selected files when the configuration changes.

To protect application logic, place user-written code inside the designated USER CODE sections when provided by the generated source files. 

/* USER CODE BEGIN WHILE */
while (1)
{
    // Add application logic here
}
/* USER CODE END WHILE */
Code written outside protected user-code sections may be overwritten or affected when code is regenerated. Always review the generated changes and maintain a backup or version-control history.

12. Common Configuration Problems

Problem Possible Cause / Solution
Pin conflict Two functions require the same pin. Select compatible alternative pins.
Clock configuration error Check oscillator frequency, PLL settings, prescalers, and device limits.
Peripheral unavailable Verify that the selected MCU supports the peripheral instance.
Wrong UART output Check TX/RX pin assignments, baud rate, clock configuration, and terminal settings.
Generated code does not match hardware Verify the selected device, board configuration, pinout, and peripheral settings.
User code disappears Place application code inside protected USER CODE sections or separate application files.
Code generation fails Check configuration errors, installed firmware packages, project settings, and toolchain selection.

13. Placement-Oriented Interview Questions and Answers

Q1. What is STM32CubeMX?

STM32CubeMX is a graphical tool used to configure STM32 microcontrollers and generate initialization code.

Q2. What is the purpose of the Pinout view?

It is used to assign GPIO and alternate peripheral functions to the available MCU pins.

Q3. What is a clock tree?

A clock tree is the arrangement of clock sources, PLLs, prescalers, and distribution paths that provide clock signals to the processor, buses, and peripherals.

Q4. What is the purpose of the .ioc file?

It stores the project's MCU, pin, clock, peripheral, and code-generation configuration.

Q5. What is code generation?

Code generation creates source files and initialization functions based on the selected hardware configuration.

Q6. What is an alternate function pin?

It is a GPIO pin configured to connect to a peripheral function such as UART, SPI, I2C, or a timer channel.

Q7. Why is clock configuration important?

Clock configuration determines processor and peripheral operating frequencies and affects timing, communication, and power consumption.

Q8. What is the purpose of NVIC configuration?

It controls the enabling and priority configuration of interrupt requests handled by the Cortex-M processor.

Q9. What happens when code is regenerated?

The configuration tool updates generated source files according to the current project configuration. User code should be placed in protected sections or separate files.

Q10. What is the difference between HAL and LL?

HAL provides higher-level peripheral APIs, while LL (Low-Layer) provides more direct, lower-overhead peripheral access functions. Both are provided for supported STM32 device families.

Q11. Can STM32CubeMX configure DMA?

Yes. For supported devices and peripherals, it can configure DMA requests, transfer direction, data width, and other transfer settings.

Q12. Why should pin conflicts be checked?

A physical pin cannot generally perform two incompatible alternate functions simultaneously. Pin conflicts can prevent the intended hardware configuration.

14. Practical Exercises

  1. Open an STM32 project in STM32CubeIDE.
  2. Open its .ioc configuration file.
  3. Identify the Pinout and Configuration views.
  4. Configure a suitable GPIO pin as an output.
  5. Inspect the available clock sources and clock tree.
  6. Enable a supported UART peripheral.
  7. Configure its baud rate and TX/RX pins.
  8. Inspect the NVIC settings for the selected peripheral.
  9. Generate the initialization code.
  10. Locate and inspect the generated initialization functions.
No-hardware practice: You can inspect pin assignments, configure clocks and peripherals, generate code, and build the project without connecting an STM32 board. Actual peripheral communication and signal verification require suitable hardware.

15. Lesson Summary

  • STM32CubeMX configures STM32 hardware resources graphically.
  • The Pinout view assigns GPIO and peripheral functions.
  • The Clock Configuration view defines clock sources and frequencies.
  • Peripheral settings control UART, SPI, I2C, ADC, timers, DMA, and other modules.
  • The .ioc file stores project configuration.
  • Code generation creates initialization source files.
  • User-code sections help protect application logic during regeneration.
