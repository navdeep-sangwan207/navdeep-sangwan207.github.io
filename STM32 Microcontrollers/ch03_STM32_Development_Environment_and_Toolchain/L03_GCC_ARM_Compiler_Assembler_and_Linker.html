Lesson 3: GCC ARM Compiler, Assembler and Linker

Understand how embedded C source code becomes executable STM32 firmware.

1. Learning Objectives

  • Understand the ARM GNU toolchain used in STM32 development.
  • Explain preprocessing, compilation, assembly, and linking.
  • Understand the roles of the compiler, assembler, and linker.
  • Identify common object and executable file formats.
  • Understand the purpose of linker scripts.
  • Recognize common compiler and linker errors.

2. What is a Toolchain?

A toolchain is a collection of software tools used to convert source code into an executable program for a target processor.

STM32CubeIDE commonly uses the GNU Arm Embedded Toolchain, based on GCC, for compiling and linking C/C++ applications targeting supported ARM Cortex-M microcontrollers.

Major Toolchain Components

  • Preprocessor: Processes macros, header files, and conditional compilation.
  • Compiler: Translates C/C++ source code into assembly or an intermediate representation.
  • Assembler: Converts assembly instructions into machine-code object files.
  • Linker: Combines object files and libraries into an executable image.
  • Debugger: Helps inspect program execution and diagnose errors.
  • Binary utilities: Inspect, convert, and manipulate executable and object files.

4. Preprocessor

The C preprocessor handles instructions beginning with the # symbol before normal compilation.

Common Preprocessor Directives

Directive Purpose
#include Includes header-file contents.
#define Defines macros and symbolic constants.
#ifdef Checks whether a macro is defined.
#ifndef Checks whether a macro is not defined.
#if Performs conditional compilation.
#endif Ends a conditional-compilation block.

Example

#include <stdint.h>

#define LED_PIN 5

int main(void)
{
    uint32_t status = LED_PIN;

    return 0;
}

The preprocessor handles the header inclusion and replaces the macro LED_PIN with its defined value.

5. ARM GCC Compiler

GCC stands for GNU Compiler Collection. In STM32 development, the ARM-targeted GCC compiler translates C/C++ source code into instructions for the selected ARM Cortex-M target.

Compiler Responsibilities

  • Checks source-code syntax and types.
  • Performs code optimization.
  • Generates target-specific assembly or object code.
  • Reports compilation errors and warnings.
  • Supports different optimization and debugging options.

Common Optimization Levels

Option Description
-O0 Minimal optimization; useful during initial debugging.
-O1 Basic optimization.
-O2 More extensive optimization for performance.
-Os Optimizes for code size.
-Og Optimization level intended to work well with debugging.
Compiler optimization can change instruction ordering and remove unnecessary code. Debugging behavior can therefore differ between optimization levels.

6. Target Architecture and Compiler Options

The compiler must generate instructions compatible with the selected STM32 processor.

Important Target Options

Option Purpose
-mcpu Selects the target CPU, such as Cortex-M0, Cortex-M3, Cortex-M4, or Cortex-M7.
-mthumb Generates Thumb instruction-set code used by Cortex-M processors.
-mfpu Selects an applicable floating-point hardware unit.
-mfloat-abi Controls floating-point procedure calling and hardware/software floating-point use.
-g Includes debugging information.
Exact compiler options depend on the STM32 core, FPU availability, firmware configuration, and toolchain version. Floating-point ABI settings must be consistent across application code and linked libraries.

7. Assembler

The assembler converts assembly-language instructions into machine-code object files.

Example Assembly Instructions

    MOVS R0, #5
    ADDS R0, R0, #3
    BX   LR

These instructions demonstrate:

  • MOVS loads a small immediate value into a register.
  • ADDS adds an immediate value to a register.
  • BX LR branches to the address held in the link register.

The exact instruction availability and encoding depend on the selected Cortex-M architecture.

8. Object Files

An object file contains compiled machine code and related information that is used during linking.

Common Object File Contents

  • Machine-code sections.
  • Read-only data sections.
  • Symbol-table information.
  • Relocation information.
  • Debugging information, when enabled.

The common object-file format used by ARM GCC toolchains is ELF (Executable and Linkable Format).

9. Linker

The linker combines object files and libraries, resolves references between them, and creates the final executable image.

Main Responsibilities

  • Combines multiple object files.
  • Resolves external symbols and function references.
  • Links required libraries.
  • Places program sections into memory regions.
  • Reports undefined references and memory overflow errors.

Example

main.o
gpio.o
uart.o
system_stm32xxxx.o
startup_stm32xxxx.o
       |
       v
     Linker
       |
       v
  STM32_Project.elf

10. Linker Script

A linker script defines the memory regions and section placement rules used by the linker.

STM32 linker scripts typically describe Flash and RAM memory regions based on the selected microcontroller.

Typical STM32 Memory Sections

Section Purpose
.text Contains executable instructions.
.rodata Contains read-only data and constants.
.data Contains initialized global and static variables, normally copied into RAM at startup.
.bss Contains uninitialized or zero-initialized global and static variables.
.isr_vector Contains the interrupt vector table when used by the startup configuration.

Conceptual Memory Layout

STM32 Flash
+-------------------------+
| Interrupt Vector Table  |
+-------------------------+
| Program Instructions    |
| .text                   |
+-------------------------+
| Read-only Data          |
| .rodata                 |
+-------------------------+

STM32 SRAM
+-------------------------+
| Initialized Data        |
| .data                   |
+-------------------------+
| Zero-initialized Data   |
| .bss                    |
+-------------------------+
| Heap (if configured)    |
+-------------------------+
| Stack                   |
+-------------------------+
This is a conceptual layout. Actual section addresses, alignment, heap and stack placement, and memory sizes depend on the device and linker script. The linker script must match the selected MCU's memory specifications.

11. ELF, HEX and BIN Files

File Format Description Common Use
ELF Executable and Linkable Format with program and optional debug information. Debugging and programming workflows.
HEX Text-based Intel HEX representation of address and data records. Firmware programming and exchange.
BIN Raw binary image containing firmware bytes. Programming tools that accept raw binary data.
MAP Linker-generated report of symbols and memory placement. Memory-usage analysis and debugging.
ELF, HEX, and BIN are not interchangeable in every programming workflow. A raw BIN file does not normally contain the load address information carried by an ELF file or encoded in Intel HEX records. The programming tool may require an explicit start address for a BIN image.

12. Common GCC Toolchain Commands

These commands illustrate common ARM GCC toolchain operations. They are examples rather than a complete STM32 build command.

Compile a C Source File

arm-none-eabi-gcc -c main.c -o main.o

Generate Assembly Output

arm-none-eabi-gcc -S main.c -o main.s

Inspect ELF Information

arm-none-eabi-readelf -h firmware.elf

Inspect Symbols

arm-none-eabi-nm firmware.elf

Generate Intel HEX from ELF

arm-none-eabi-objcopy -O ihex firmware.elf firmware.hex

Generate Raw Binary from ELF

arm-none-eabi-objcopy -O binary firmware.elf firmware.bin
A complete STM32 build also needs target CPU options, include paths, device definitions, startup code, libraries, and the correct linker script. STM32CubeIDE normally manages these project settings for you.

13. Compiler and Linker Errors

Error Possible Cause / Solution
Syntax error Check missing semicolons, braces, or invalid statements.
Undefined reference Check missing function definitions, source files, and libraries.
Multiple definition Check duplicate global definitions across source files.
Cannot find linker script Check the linker-script path and project configuration.
Region RAM overflowed Reduce RAM usage or review memory configuration and linker sections.
Region FLASH overflowed Reduce firmware size or verify the selected device and Flash memory settings.
Wrong instruction or architecture Check the target CPU and instruction-set compiler options.

14. Placement-Oriented Interview Questions and Answers

Q1. What is GCC?

GCC is the GNU Compiler Collection. It supports compiling C and C++ programs for multiple target architectures.

Q2. What is a cross-compiler?

A cross-compiler runs on one computer architecture but generates executable code for a different target architecture.

Q3. What is ARM GCC?

ARM GCC is a GCC toolchain configured to generate code for supported ARM processors, including Cortex-M microcontrollers.

Q4. What is the difference between a compiler and an assembler?

A compiler translates high-level source code into lower-level code, while an assembler converts assembly instructions into machine-code object files.

Q5. What is the function of a linker?

A linker combines object files and libraries, resolves symbols, and creates the final executable image.

Q6. What is an object file?

An object file contains compiled machine code, sections, symbols, and relocation information used during linking.

Q7. What is a linker script?

It defines memory regions and determines where program sections are placed in the target memory.

Q8. What is the difference between .data and .bss?

The .data section contains initialized global and static variables, while .bss contains uninitialized or zero-initialized global and static variables.

Q9. What is the purpose of the ELF file?

ELF stores executable and linking information and can include debugging symbols used by development tools.

Q10. What is the difference between HEX and BIN?

HEX is a text-based format containing address and data records, whereas BIN is a raw sequence of firmware bytes.

Q11. What does -O0 mean?

It selects minimal compiler optimization, which can make source-level debugging easier.

Q12. What causes an undefined reference error?

It commonly occurs when a required function or variable definition is missing from the linked object files or libraries.

15. Practical Exercises

  1. Open an STM32CubeIDE project.
  2. Locate the compiler and linker settings.
  3. Build the project and identify the generated object files.
  4. Locate the ELF file in the build directory.
  5. Generate or locate the HEX and BIN files if enabled.
  6. Inspect the ELF header using arm-none-eabi-readelf.
  7. Inspect the linker map file and identify memory sections.
  8. Compare Debug and Release build configurations.
  9. Identify the CPU and floating-point compiler options used by your project.
No-hardware practice: All compiler, assembler, linker, and file-inspection exercises can be performed without an STM32 board. Hardware is needed only for programming and testing the firmware on a physical microcontroller.

16. Lesson Summary

  • The ARM GCC toolchain converts source code into STM32 firmware.
  • The preprocessor handles macros and header files.
  • The compiler translates C/C++ code into target-specific code.
  • The assembler converts assembly instructions into object files.
  • The linker combines objects and libraries into an executable.
  • The linker script defines memory regions and section placement.
  • ELF, HEX, BIN, and MAP files serve different development purposes.
  • Correct CPU and memory configuration is essential for reliable firmware builds.
