Lesson 1: STM32CubeIDE Installation and Project Creation

2. What is STM32CubeIDE?

STM32CubeIDE is an integrated development environment (IDE) provided by STMicroelectronics for developing applications based on STM32 microcontrollers.

It combines source-code editing, project management, compilation, programming, and debugging facilities in one development environment.

Main Features

  • Project creation and source-code editing.
  • STM32 device and board selection.
  • Integration with STM32CubeMX configuration tools.
  • ARM GCC compiler toolchain.
  • Firmware building and linking.
  • ST-LINK programming and debugging support.
  • Peripheral and variable inspection during debugging.

3. STM32 Development Tools

Tool Purpose
STM32CubeIDE Integrated environment for creating, building, and debugging projects.
STM32CubeMX Configures MCU pins, clocks, peripherals, and generates initialization code.
ARM GCC Compiles C/C++ source code for supported ARM Cortex-M targets.
ST-LINK Programs and debugs STM32 devices through supported debug interfaces.
CMSIS Provides standardized interfaces and definitions for Cortex-M processors and devices.
STM32 HAL Provides hardware abstraction APIs for STM32 peripheral programming.

4. STM32CubeIDE Installation

Download STM32CubeIDE from the official STMicroelectronics website. Select the installer compatible with your operating system and follow the installation instructions.

Installation Procedure

  1. Open the official STMicroelectronics website.
  2. Navigate to the STM32CubeIDE software download page.
  3. Select the appropriate installer for your operating system.
  4. Review the applicable license and download requirements.
  5. Run the installer.
  6. Follow the installation wizard.
  7. Complete the installation and launch STM32CubeIDE.

Official software information: STM32CubeIDE - STMicroelectronics

Important: Installation screens, package names, and bundled components can vary between software releases and operating systems. Follow the instructions for the version you install.

5. Understanding the Workspace

A workspace is a directory used by the IDE to organize project information, settings, and related development resources.

When STM32CubeIDE starts for the first time, it may ask you to select or create a workspace directory.

Example Workspace

D:\STM32_Workspace\
    STM32_LED_Project\
    UART_Communication_Project\
    ADC_Project\
    PWM_Project\

Each project is maintained separately inside the selected workspace.

Keep your workspace in a directory where you have permission to create and modify files. Avoid moving project folders while the IDE is using them.

6. Creating a New STM32 Project

STM32CubeIDE supports creating projects for individual STM32 microcontrollers as well as supported development boards.

Step-by-Step Procedure

  1. Launch STM32CubeIDE.
  2. Select the workspace directory.
  3. Open the File menu and select New → STM32 Project.
  4. Choose the MCU/MPU Selector or Board Selector.
  5. Search for your exact STM32 microcontroller part number or board.
  6. Select the correct device or board.
  7. Proceed to the project configuration screen.
  8. Enter a meaningful project name, such as STM32_LED_Project.
  9. Review the project settings and select the required firmware package if prompted.
  10. Finish the project creation process.
Device selection matters: Different STM32 devices have different Flash sizes, RAM sizes, peripheral availability, pin assignments, and clock capabilities. Always select the exact part number printed on the MCU or specified for your development board.

7. MCU Selector vs Board Selector

MCU Selector Board Selector
Selects an individual STM32 microcontroller. Selects a supported development board.
Useful for custom PCB and hardware development. Useful when developing with a supported evaluation or Nucleo board.
Requires you to configure the required pins and peripherals. Can provide board-specific configuration and peripheral information.

8. Understanding the STM32 Project Structure

A typical STM32CubeIDE project contains source files, header files, device support files, startup code, and build configuration files.

Typical Project Directory

STM32_LED_Project/
│
├── Core/
│   ├── Inc/
│   │   ├── main.h
│   │   └── stm32xxxx_it.h
│   │
│   └── Src/
│       ├── main.c
│       ├── stm32xxxx_it.c
│       └── system_stm32xxxx.c
│
├── Drivers/
│   ├── CMSIS/
│   └── STM32xxxx_HAL_Driver/
│
├── STM32_LED_Project.ioc
├── startup_stm32xxxx.s
├── STM32xxxx_FLASH.ld
└── Debug/

The exact names and folders depend on the selected STM32 family, firmware package, and project configuration.

Important Files and Folders

File / Folder Purpose
Core/Inc Contains application header files.
Core/Src Contains application source files.
main.c Contains the main application entry point.
main.h Contains application declarations and definitions.
Drivers/CMSIS Contains CMSIS core and device support components.
STM32 HAL Driver Contains STM32 peripheral HAL source and header files.
.ioc Stores STM32CubeMX project configuration.
startup_stm32xxxx.s Contains startup assembly code and the interrupt vector table.
STM32xxxx_FLASH.ld Linker script defining the device memory layout and linker sections.
Debug/ Common build-output directory for a Debug configuration.

9. Understanding main.c

The main.c file normally contains the main application function and the initialization sequence.

Typical STM32 HAL Application Structure

#include "main.h"

int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();

    while (1)
    {
        // Application code
    }
}

Explanation

  • HAL_Init() initializes the HAL and its required system services.
  • SystemClock_Config() configures the system clock according to the generated project configuration.
  • MX_GPIO_Init() initializes GPIO settings generated by the configuration tools.
  • while(1) runs the main application loop continuously.
This is an illustrative application structure. The actual generated project may include additional initialization, error-handling, and peripheral functions. GPIO pins and clock settings must be configured for the selected device or board.

10. Building the Project

Building converts the source code into firmware output files suitable for programming the STM32 device.

Build Procedure

  1. Open the STM32 project in the Project Explorer.
  2. Save any modified source files.
  3. Select the project.
  4. Choose Build Project from the Project menu or use the build toolbar button.
  5. Inspect the Console and Problems views.
  6. Resolve any compilation or linking errors.

Common Build Outputs

File Extension Meaning
.o Compiled object file.
.elf Executable and Linkable Format file containing program and debugging information.
.hex Intel HEX representation of firmware data, when generated.
.bin Raw binary firmware image, when generated.
.map Linker map file showing memory allocation and symbol information, when enabled.

11. First Project: LED Blinking Application

A GPIO LED blinking application is a common first embedded programming exercise. It verifies the development environment, project configuration, build process, and hardware programming.

Basic Application Logic

while (1)
{
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    HAL_Delay(500);
}

This example toggles GPIOA pin 5 every 500 milliseconds. It is suitable only when that pin is configured as an output and is connected to an LED on the selected board.

Board-specific note: Do not assume that PA5 controls the onboard LED on every STM32 board. Check the board schematic or user manual, configure the correct GPIO pin, and ensure the generated GPIO initialization code matches it.

Required Steps

  1. Select the correct MCU or development board.
  2. Configure the LED GPIO pin as an output.
  3. Generate or update the initialization code.
  4. Add the toggle and delay statements inside the main loop.
  5. Build the project.
  6. Connect the board using a supported ST-LINK interface.
  7. Program the firmware and verify LED operation.

12. Common Development Problems

Problem Possible Cause / Solution
Project creation fails Check device selection, installed firmware packages, workspace permissions, and project settings.
Header file not found Check include paths, device support files, and project configuration.
Compilation error Inspect the Console and Problems views; correct syntax, type, or configuration errors.
Linker error Check missing definitions, library settings, startup files, and linker configuration.
ST-LINK not detected Check USB connection, driver installation, debug interface, and board power.
LED does not blink Verify GPIO pin selection, output configuration, board wiring, and firmware execution.

13. Placement-Oriented Interview Questions and Answers

Q1. What is STM32CubeIDE?

STM32CubeIDE is an integrated development environment used to create, compile, program, and debug STM32 microcontroller applications.

Q2. What is a workspace?

A workspace is a directory used by the IDE to organize projects and associated development settings.

Q3. What is the purpose of STM32CubeMX?

STM32CubeMX configures STM32 pins, clocks, peripherals, and middleware and generates initialization code.

Q4. What is the purpose of the .ioc file?

It stores the STM32CubeMX configuration for a project, including selected pins, clocks, and peripheral settings.

Q5. What is the purpose of main.c?

It commonly contains the main application function and the initialization and application logic.

Q6. What is the purpose of the startup file?

It provides early processor startup code, the interrupt vector table, and the initial transfer of control to the application runtime.

Q7. What is a linker script?

A linker script defines memory regions and controls how program sections are placed in Flash, RAM, and other memory regions.

Q8. What is an ELF file?

ELF is an executable file format that can contain program sections, symbols, and debugging information.

Q9. What is ST-LINK?

ST-LINK is a programming and debugging tool used to communicate with supported STM32 microcontrollers through interfaces such as SWD.

Q10. What is the difference between MCU Selector and Board Selector?

MCU Selector is used to choose an individual microcontroller, while Board Selector is used to choose a supported development board with its board-specific configuration.

Q11. What happens during a project build?

Source files are compiled and assembled, and the linker combines the resulting object files and libraries into an executable firmware image.

Q12. Why must the exact STM32 part number be selected?

Different devices have different memory sizes, peripherals, pin mappings, and hardware capabilities. Incorrect selection can cause configuration and build problems.

14. Practical Exercises

  1. Install STM32CubeIDE on your computer.
  2. Create a workspace named STM32_Workspace.
  3. Create a project for an available STM32 MCU or development board.
  4. Identify the Core/Inc and Core/Src directories.
  5. Locate and inspect main.c and the .ioc file.
  6. Build the project and inspect the Console output.
  7. Identify the generated ELF file and other available build outputs.
  8. If a compatible board is available, configure and test an LED blinking application.
Simulator / no-hardware practice: You can practice project creation, source-code editing, compilation, and build-output inspection without a physical STM32 board. Actual ST-LINK programming and onboard LED verification require compatible hardware.

15. Lesson Summary

  • STM32CubeIDE provides an integrated STM32 development environment.
  • A workspace organizes development projects.
  • Projects can be created using MCU Selector or Board Selector.
  • STM32 projects contain source files, drivers, startup code, and linker configuration.
  • The main application commonly starts from main() in main.c.
  • The build process compiles, assembles, and links firmware.
  • ST-LINK can be used to program and debug supported STM32 devices.
