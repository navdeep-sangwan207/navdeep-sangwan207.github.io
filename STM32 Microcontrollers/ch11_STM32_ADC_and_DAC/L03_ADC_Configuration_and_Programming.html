2. STM32 ADC Configuration Overview

STM32 microcontrollers contain ADC peripherals that convert analog voltages into digital values. Before reading an analog signal, the ADC peripheral and its input pin must be configured.

Basic Configuration Steps

  1. Select an ADC-capable GPIO pin.
  2. Configure the GPIO pin in analog mode.
  3. Enable the required ADC peripheral clock.
  4. Select the ADC instance and channel.
  5. Configure resolution and sampling time.
  6. Select conversion mode and trigger source.
  7. Initialize the ADC peripheral.
  8. Start conversion and read the result.

3. ADC Configuration Using STM32CubeMX

STM32CubeMX is used to configure peripherals, clocks, GPIO pins and software settings. STM32CubeIDE integrates these configuration tools into the development workflow.

Configuration Procedure

  1. Open STM32CubeIDE.
  2. Create or open an STM32 project.
  3. Select the correct MCU or development board.
  4. Open the device configuration view.
  5. Select an available ADC-capable pin.
  6. Enable the required ADC channel.
  7. Configure resolution and sampling time.
  8. Select the conversion mode.
  9. Configure ADC clock and trigger settings as required.
  10. Generate or update the initialization code.
The exact CubeMX menu options depend on the STM32 family and the ADC peripheral generation.

6. ADC Polling Method

Polling means that the CPU waits for a conversion to complete by checking the peripheral status through a software API.

Typical HAL Functions

HAL_ADC_Start()
HAL_ADC_PollForConversion()
HAL_ADC_GetValue()
HAL_ADC_Stop()

Polling Sequence

  1. Start ADC conversion.
  2. Wait for conversion completion.
  3. Read the ADC data register through HAL.
  4. Stop conversion if required by the selected mode.
  5. Process the digital result.

7. STM32 ADC HAL Programming

The following example reads one ADC channel using blocking polling. It assumes CubeMX has generated and configured the ADC handle, GPIO analog mode and clock initialization.

ADC Read Function

#include "main.h"
#include <stdint.h>

extern ADC_HandleTypeDef hadc1;

uint16_t ADC_Read(void)
{
    uint16_t adc_value = 0;

    if (HAL_ADC_Start(&hadc1) != HAL_OK)
    {
        return 0;
    }

    if (HAL_ADC_PollForConversion(&hadc1, 100) == HAL_OK)
    {
        adc_value = (uint16_t)HAL_ADC_GetValue(&hadc1);
    }

    HAL_ADC_Stop(&hadc1);

    return adc_value;
}
Returning zero on an ADC error is ambiguous because zero can also be a valid measurement. Production code should return a HAL status separately from the ADC result.

Improved ADC Read Function

HAL_StatusTypeDef ADC_ReadValue(uint16_t *value)
{
    if (value == NULL)
    {
        return HAL_ERROR;
    }

    if (HAL_ADC_Start(&hadc1) != HAL_OK)
    {
        return HAL_ERROR;
    }

    HAL_StatusTypeDef status =
        HAL_ADC_PollForConversion(&hadc1, 100);

    if (status == HAL_OK)
    {
        *value = (uint16_t)HAL_ADC_GetValue(&hadc1);
    }

    HAL_ADC_Stop(&hadc1);

    return status;
}

8. Complete Example: Reading an Analog Voltage

This example reads an analog input and converts the ADC result into an approximate voltage.

Assumptions

  • STM32 ADC configured for 12-bit resolution.
  • Effective ADC reference voltage is 3.3 V.
  • One ADC channel is configured.
  • ADC handle is named hadc1.
  • GPIO analog configuration is generated by CubeMX.
#include "main.h"
#include <stdint.h>

extern ADC_HandleTypeDef hadc1;

uint16_t adc_value;
float voltage;

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_ADC1_Init();

    while (1)
    {
        if (HAL_ADC_Start(&hadc1) == HAL_OK)
        {
            if (HAL_ADC_PollForConversion(&hadc1, 100) == HAL_OK)
            {
                adc_value =
                    (uint16_t)HAL_ADC_GetValue(&hadc1);

                voltage =
                    ((float)adc_value / 4095.0f) * 3.3f;
            }

            HAL_ADC_Stop(&hadc1);
        }

        HAL_Delay(100);
    }
}

Input Voltage Approximate ADC Code
0.0 V 0
0.825 V 1024
1.65 V 2048
2.475 V 3071
3.3 V 4095

Values are ideal approximations. Actual measurements depend on reference voltage, ADC characteristics and circuit conditions.

9. Sampling Time Configuration

Sampling time determines how long the ADC input circuit acquires the analog signal before conversion.

Why is Sampling Time Important?

  • Allows the ADC input capacitor to settle.
  • Helps achieve accurate measurements.
  • Is especially important with high-impedance sources.
  • Affects the maximum achievable sampling rate.

A very short sampling time may produce inaccurate readings when the sensor or source impedance is too high.

Select sampling time using the STM32 datasheet, ADC clock, source impedance and required conversion accuracy. There is no single sampling-time setting suitable for every sensor.

10. ADC Calibration

Some STM32 ADC peripherals provide hardware calibration features to reduce certain conversion errors.

A calibration function may be available through the HAL library, depending on the STM32 family. 

/* Illustrative HAL call.
   Availability and parameters depend on STM32 family. */

if (HAL_ADCEx_Calibration_Start(&hadc1) != HAL_OK)
{
    Error_Handler();
}
Calibration support, sequence, single-ended or differential calibration options and API signatures vary across STM32 families. Check the exact HAL driver documentation.

11. Common ADC Programming Errors

Problem Possible Cause Solution
ADC always reads zero Wrong channel or pin configuration. Verify ADC channel and analog GPIO mode.
ADC reads maximum value Input exceeds range or wrong connection. Check input voltage and reference.
Unstable readings Noise or unsuitable sampling time. Improve filtering and acquisition settings.
Polling timeout ADC not configured or conversion not triggered. Check initialization and trigger configuration.
Incorrect voltage Wrong reference or scaling calculation. Verify actual reference and resolution.
Unexpected channel data Incorrect channel sequence. Check scan configuration and conversion order.

12. Placement Interview Questions and Answers

Q1. Which HAL function starts ADC conversion?

HAL_ADC_Start() starts a polling-based ADC conversion.

Q2. Which function waits for conversion completion?

HAL_ADC_PollForConversion().

Q3. Which function reads the ADC result?

HAL_ADC_GetValue().

Q4. What is ADC polling?

Polling is a method in which the CPU waits for the ADC conversion to complete.

Q5. What is continuous conversion mode?

It allows the ADC to perform repeated conversions after being started or triggered, according to the peripheral configuration.

Q6. What is scan conversion mode?

It allows a configured ADC sequence to convert multiple channels.

Q7. Why is sampling time important?

It allows the ADC input circuit to acquire the voltage sufficiently before conversion.

Q8. What is ADC calibration?

It is a hardware-supported procedure on certain devices to reduce specified ADC errors.

Q9. What is the difference between ADC polling and interrupt?

Polling waits for completion in software, whereas interrupt-based conversion notifies the CPU when a configured event occurs.

Q10. Why should ADC input voltage limits be checked?

To prevent incorrect conversion and avoid violating the MCU's electrical ratings.

  • ADC configuration and calibration features are device-specific.
