2. ADC Conversion Methods

STM32 ADC conversions can be managed using polling, interrupts or DMA. The appropriate method depends on data rate, CPU workload and application requirements.

Method Working Principle Typical Use
Polling CPU waits for conversion completion. Simple measurements.
Interrupt ADC notifies CPU when a configured event occurs. Event-driven measurements.
DMA Transfers ADC data to memory automatically. Repeated or high-rate sampling.

3. What is ADC Interrupt?

ADC interrupt programming allows the ADC peripheral to notify the processor when a conversion event occurs.

The CPU does not need to continuously check the conversion status. Instead, it can execute other application code until the interrupt is generated.

4. ADC Interrupt Configuration

STM32CubeMX Configuration

  1. Select an ADC peripheral.
  2. Enable the required ADC channel.
  3. Configure the conversion mode.
  4. Enable the ADC interrupt in NVIC if required by the device configuration.
  5. Configure the ADC clock and sampling time.
  6. Generate the initialization code.
The ADC interrupt request must be enabled in the peripheral, and the corresponding NVIC interrupt must also be enabled. CubeMX usually configures the required interrupt settings.

5. ADC Interrupt HAL Functions

Function Purpose
HAL_ADC_Start_IT() Starts ADC conversion using interrupt mode.
HAL_ADC_IRQHandler() Processes the ADC interrupt in the HAL driver.
HAL_ADC_ConvCpltCallback() User callback for conversion completion.
HAL_ADC_Stop_IT() Stops interrupt-based ADC operation.

6. ADC Interrupt Programming Example

This example starts a single ADC conversion using interrupt mode. The ADC handle and peripheral interrupt handler are assumed to be configured by CubeMX.

Global Variables

#include "main.h"
#include <stdint.h>

extern ADC_HandleTypeDef hadc1;

volatile uint16_t adc_value = 0;
volatile uint8_t adc_ready = 0;

Start ADC Interrupt Conversion

void Start_ADC_Interrupt(void)
{
    adc_ready = 0;

    if (HAL_ADC_Start_IT(&hadc1) != HAL_OK)
    {
        Error_Handler();
    }
}

ADC Conversion Complete Callback

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc->Instance == ADC1)
    {
        adc_value = (uint16_t)HAL_ADC_GetValue(hadc);
        adc_ready = 1;
    }
}

Main Loop

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_ADC1_Init();

    Start_ADC_Interrupt();

    while (1)
    {
        if (adc_ready)
        {
            adc_ready = 0;

            /* Process adc_value here. */

            Start_ADC_Interrupt();
        }

        /* Other application tasks can run here. */
    }
}
This is a single-conversion example. The ADC IRQ handler must call the appropriate HAL handler, commonly HAL_ADC_IRQHandler(). Do not block or perform lengthy calculations inside the callback. For a production design, handle error conditions and synchronization carefully.

7. What is DMA?

DMA stands for Direct Memory Access. It is a hardware mechanism that transfers data between peripherals and memory without requiring the CPU to copy each individual data item.

Why is DMA Useful?

  • Reduces CPU involvement in repetitive data transfers.
  • Supports continuous data acquisition.
  • Allows the CPU to perform other tasks.
  • Can reduce interrupt frequency when using buffers.
  • Is useful for ADC, UART, SPI and other peripherals.

8. ADC with DMA Working Principle

  1. Configure the ADC peripheral.
  2. Configure DMA for the ADC data register.
  3. Allocate a memory buffer.
  4. Start ADC conversion with DMA.
  5. ADC generates conversion results.
  6. DMA transfers the results into the buffer.
  7. DMA completion or half-completion event notifies software.
  8. The CPU processes the buffered samples.

9. ADC DMA Configuration Using CubeMX

  1. Enable the ADC peripheral.
  2. Select the required ADC channel or sequence.
  3. Configure the conversion mode.
  4. Open the DMA settings for the ADC.
  5. Add the required DMA request.
  6. Select the appropriate DMA direction.
  7. Configure peripheral and memory data alignment.
  8. Configure transfer mode and priority.
  9. Enable DMA interrupt handling if required.
  10. Generate the code.
DMA request routing, stream/channel selection, transfer widths, cache behavior and circular mode support vary across STM32 families. Follow the selected MCU reference manual.

10. ADC DMA HAL Functions

Function Purpose
HAL_ADC_Start_DMA() Starts ADC conversion with DMA.
HAL_ADC_Stop_DMA() Stops ADC DMA operation.
HAL_ADC_ConvHalfCpltCallback() Notifies software when the first buffer half is complete.
HAL_ADC_ConvCpltCallback() Notifies software when the configured transfer is complete.
HAL_ADC_ErrorCallback() Handles ADC errors.

11. ADC DMA Programming Example

This example uses a buffer of 10 ADC samples. It assumes CubeMX has configured the ADC, DMA request, data alignment and interrupt handling for the selected MCU.

Global Variables

#include "main.h"
#include <stdint.h>

#define ADC_BUFFER_SIZE 10

extern ADC_HandleTypeDef hadc1;

uint16_t adc_buffer[ADC_BUFFER_SIZE];

volatile uint8_t adc_dma_complete = 0;
volatile uint8_t adc_dma_error = 0;

Start ADC DMA

void Start_ADC_DMA(void)
{
    adc_dma_complete = 0;
    adc_dma_error = 0;

    if (HAL_ADC_Start_DMA(
            &hadc1,
            (uint32_t *)adc_buffer,
            ADC_BUFFER_SIZE) != HAL_OK)
    {
        Error_Handler();
    }
}

DMA Completion Callback

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc->Instance == ADC1)
    {
        adc_dma_complete = 1;
    }
}

DMA Error Callback

void HAL_ADC_ErrorCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc->Instance == ADC1)
    {
        adc_dma_error = 1;
    }
}

Main Loop

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_DMA_Init();
    MX_ADC1_Init();

    Start_ADC_DMA();

    while (1)
    {
        if (adc_dma_complete)
        {
            adc_dma_complete = 0;

            /* Process adc_buffer here. */

            Start_ADC_DMA();
        }

        if (adc_dma_error)
        {
            adc_dma_error = 0;

            /* Handle the DMA or ADC error. */
        }
    }
}
This example is intended for a finite DMA transfer. For continuous sampling, configure circular DMA where supported and process half-complete and complete callbacks. Do not restart DMA blindly while a transfer is still active.

12. Circular DMA Mode

In circular DMA mode, the DMA controller automatically returns to the beginning of the buffer after reaching its end.

| Sample 1             |
| Sample 2             |
| Sample 3             |
| ...                  |
| Sample N             |
+----------------------+
     |
     v
Return to Buffer Start
     |
     +---------- Repeat

Double-Half Buffer Processing

A circular buffer can be divided into two halves. While DMA fills one half, the CPU processes the other half, provided processing finishes before that half is overwritten.

  • Half-transfer callback: first half is available.
  • Transfer-complete callback: second half is available.
  • DMA continues filling the buffer in circular mode.
Circular DMA requires careful synchronization. The CPU must not read a buffer region while DMA is modifying it. Cache-equipped STM32 devices may also require cache maintenance and suitable memory placement.

14. Common ADC Interrupt and DMA Problems

Problem Possible Cause Solution
Callback not executed NVIC or peripheral interrupt not enabled. Check interrupt configuration and IRQ handler.
DMA buffer unchanged Incorrect DMA request or ADC start. Check DMA mapping and start status.
Only one sample received Wrong conversion or DMA mode. Check continuous conversion and transfer length.
Corrupted readings Buffer accessed while DMA writes. Use safe buffer ownership and synchronization.
DMA transfer error Wrong alignment or invalid configuration. Check data widths, request routing and memory.
Unexpected ADC data Incorrect sequence or buffer ordering. Verify ADC sequence and DMA configuration.

15. Placement Interview Questions and Answers

Q1. What is ADC interrupt mode?

It is a conversion method in which the ADC notifies the CPU when a configured conversion event occurs.

Q2. What is DMA?

Direct Memory Access is a hardware mechanism for transferring data between peripherals and memory with minimal CPU involvement.

Q3. What is the difference between ADC interrupt and ADC DMA?

With interrupt mode, the CPU typically reads the conversion result. With DMA, hardware transfers conversion data into memory.

Q4. Which HAL function starts ADC interrupt conversion?

HAL_ADC_Start_IT().

Q5. Which HAL function starts ADC DMA conversion?

HAL_ADC_Start_DMA().

Q6. What is circular DMA?

It is a transfer mode in which DMA repeatedly uses the same memory buffer.

Q7. What is a half-transfer callback?

It notifies the application when the first half of a DMA transfer buffer has been filled.

Q8. Why is DMA useful for continuous ADC sampling?

It transfers repeated conversion results into memory without requiring the CPU to read each sample individually.

Q9. Can the CPU process data while DMA is working?

Yes. The CPU can process data in a safe buffer region while DMA fills another region.

Q10. Why should DMA buffer synchronization be considered?

Because the CPU and DMA may access the same memory. Without proper ownership and synchronization, data can be overwritten or read inconsistently.

Q11. Does volatile make a DMA buffer cache coherent?

No. Volatile does not perform cache maintenance or guarantee synchronization. Cache-equipped devices may require explicit cache operations and suitable memory placement.

Q12. When should DMA be preferred?

DMA is useful for repeated, high-rate or multi-sample data transfers where reducing CPU overhead is important.

17. Lesson Summary

  • ADC interrupt mode notifies the CPU of conversion events.
  • NVIC and peripheral interrupt configuration must be correct.
  • DMA transfers ADC results directly into memory.
  • HAL provides polling, interrupt and DMA APIs.
  • Circular DMA supports repeated buffer transfers.
  • Half-transfer and transfer-complete callbacks support buffer processing.
  • Buffer synchronization is essential.
  • DMA configuration is device-specific.
