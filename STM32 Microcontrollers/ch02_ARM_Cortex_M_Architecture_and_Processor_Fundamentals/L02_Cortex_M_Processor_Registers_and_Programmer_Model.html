Lesson 2: Cortex-M Processor Registers and Programmer Model

General-Purpose Registers, Special Registers, PC, LR and xPSR

1. Learning Objectives

  • Understand the Cortex-M programmer model.
  • Identify the general-purpose registers R0-R12.
  • Understand the purpose of R13, R14 and R15.
  • Explain the Program Counter and Link Register.
  • Understand the Program Status Register.
  • Identify special-purpose processor registers.
  • Understand register usage in embedded C and assembly.

2. What is a Processor Register?

A processor register is a small, high-speed storage location inside the CPU. Registers temporarily hold data, addresses, instructions-related information and processor status.

The processor uses registers to perform arithmetic, logical operations, memory access and program control.

Why are Registers Important?

  • Provide fast access to data.
  • Store temporary calculation results.
  • Hold memory addresses.
  • Control program execution.
  • Maintain processor status information.

3. Cortex-M Programmer Model

The programmer model describes the registers and processor state visible to software when writing programs.

The diagram shows the main register groups. Additional special registers and floating-point registers may be available depending on the Cortex-M core.

4. General-Purpose Registers (R0-R12)

Cortex-M processors provide thirteen general-purpose registers, R0 through R12. These are 32-bit registers used for data processing and address calculations.

Register Common Purpose
R0-R3 Commonly used for function arguments and return values.
R4-R11 Commonly used for local data and values preserved across function calls.
R12 Intra-procedure scratch register.
Placement point: R0-R3 and R12 are generally caller-saved registers under the standard ARM procedure calling convention. R4-R11 are generally callee-saved. Exact use depends on the ABI and software context.

5. Special Registers: R13, R14 and R15

1. R13 – Stack Pointer (SP)

R13 is the Stack Pointer. It points to the current stack location used for storing temporary data, function information and exception context.

2. R14 – Link Register (LR)

R14 is the Link Register. It typically stores the return address when a function is called using a branch-with-link instruction.

3. R15 – Program Counter (PC)

R15 is the Program Counter. It represents the program instruction address used for instruction execution.

Register Name Function
R13 SP Stack management.
R14 LR Function return address.
R15 PC Program instruction address.

6. Stack Pointer: MSP and PSP

Cortex-M processors provide two stack pointer selections:

  • MSP: Main Stack Pointer.
  • PSP: Process Stack Pointer.

R13 represents the currently selected stack pointer. The processor's CONTROL register and execution mode determine which stack is used in relevant contexts.

The detailed operation of MSP, PSP and processor modes is covered in Lesson 3.

7. Link Register and Function Calls

When a function is called, the processor commonly uses the Link Register to hold the return address.

Assembly Example

BL  FUNCTION

; Execution returns here after FUNCTION

FUNCTION:
    MOVS R0, #10
    BX   LR

Explanation:

  • BL branches to the function.
  • The return address is stored in LR.
  • BX LR returns to the caller.
A function that calls another function may need to save its existing LR value, because another BL instruction can overwrite it. The compiler normally manages this according to the calling convention.

8. Program Status Register (xPSR)

The xPSR is the combined view of three status-register fields in Cortex-M:

  • APSR – Application Program Status Register.
  • IPSR – Interrupt Program Status Register.
  • EPSR – Execution Program Status Register.
Field Purpose
APSR Contains condition flags such as N, Z, C and V.
IPSR Indicates the currently active exception number.
EPSR Contains execution-state information, including the Thumb state.

Condition Flags

Flag Meaning
N Negative result.
Z Zero result.
C Carry or no-borrow indication, depending on the operation.
V Signed overflow.

Example

MOVS R0, #5
SUBS R1, R0, #5

The subtraction result is zero, so the Z flag is set by the instruction.

9. Other Important Special-Purpose Registers

Register Function
CONTROL Controls privilege level and stack selection in Thread mode.
PRIMASK Can mask configurable-priority exceptions.
BASEPRI Sets a priority threshold for masking interrupts on supported cores.
FAULTMASK Masks all exceptions except NMI on supported cores.
MSP Main Stack Pointer.
PSP Process Stack Pointer.
VTOR Vector Table Offset Register on cores that implement it.

The availability and behavior of some special registers depend on the Cortex-M processor version and configuration.

10. Register Usage in Embedded C

In embedded C, the compiler allocates processor registers to variables and intermediate calculations. Developers normally work with C variables rather than manually selecting R0, R1 or other registers.

Example C Program

#include <stdint.h>

int main(void)
{
    uint32_t a = 10;
    uint32_t b = 20;
    uint32_t result;

    result = a + b;

    while (1)
    {
    }
}

During compilation, the compiler may use general-purpose registers to hold the variables and calculation result. The exact register allocation depends on compiler settings, optimization and surrounding code.

11. Important Register Concepts for Debugging

  • Check PC to understand where the processor is executing.
  • Check LR when investigating function return problems.
  • Inspect SP when investigating stack corruption.
  • Inspect xPSR when examining condition flags and exception state.
  • Inspect R0-R12 to understand intermediate calculations.

Example Debugging Situation

If a program enters an unexpected location after a function call, inspect LR and the disassembly. If a function returns incorrectly, investigate whether the return address was preserved and whether the stack was corrupted.

12. Placement Interview Questions and Answers

Q1. How many general-purpose registers are present in the basic Cortex-M register model?

Thirteen general-purpose registers, R0 through R12.

Q2. What is R13?

R13 is the Stack Pointer (SP).

Q3. What is R14?

R14 is the Link Register (LR), commonly used to hold a function return address.

Q4. What is R15?

R15 is the Program Counter (PC).

Q5. What is the function of the Program Counter?

It represents the program instruction address used by the processor.

Q6. What is the purpose of the Link Register?

It stores a return address during a function call.

Q7. What is xPSR?

It is the combined view of APSR, IPSR and EPSR.

Q8. What are the N, Z, C and V flags?

They indicate negative, zero, carry and signed overflow conditions resulting from applicable operations.

Q9. What is the difference between MSP and PSP?

MSP is the Main Stack Pointer and PSP is the Process Stack Pointer. Cortex-M software can select between them in Thread mode.

Q10. What happens if LR is overwritten before a function returns?

The original return address may be lost, causing incorrect program flow unless it was saved elsewhere.

Q11. Which registers are commonly used for function arguments?

R0-R3 are commonly used for the first four word-sized arguments under the standard ARM procedure calling convention.

Q12. Why are processor registers important in debugging?

They reveal the processor's execution state, intermediate data, return address and stack information.

14. Lesson Summary

  • Registers are high-speed storage locations inside the processor.
  • R0-R12 are general-purpose registers.
  • R13 is SP, R14 is LR and R15 is PC.
  • xPSR contains APSR, IPSR and EPSR fields.
  • MSP and PSP provide two stack pointer selections.
  • Special registers support interrupt masking and processor control.
  • Register inspection is an important embedded debugging skill.
