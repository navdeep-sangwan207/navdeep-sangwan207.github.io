Lesson 5: NVIC Interrupt Priorities and Vectors

Nested Vectored Interrupt Controller, Priority Levels, Preemption and CMSIS Programming

1. Learning Objectives

  • Understand the purpose of the NVIC.
  • Understand interrupt enable and pending states.
  • Learn interrupt priority levels.
  • Differentiate preemption priority and subpriority.
  • Understand nested interrupts.
  • Learn the relationship between NVIC and the vector table.
  • Configure interrupts using CMSIS functions.
  • Understand interrupt priority grouping and practical considerations.

2. What is NVIC?

NVIC stands for Nested Vectored Interrupt Controller. It is an integral part of ARM Cortex-M processor interrupt handling architecture.

NVIC manages external interrupt requests, including enabling, disabling, pending status, priority assignment and interrupt preemption.

Main Functions of NVIC

  • Enable and disable external interrupts.
  • Maintain interrupt pending status.
  • Assign interrupt priorities.
  • Support nested interrupt handling.
  • Coordinate interrupt activation and exception entry.
  • Support software-triggered interrupts on applicable cores.
Important: NVIC manages external interrupts. System exceptions such as SysTick, PendSV and SVCall are controlled through their respective system control registers and priority registers, although they participate in the Cortex-M exception-priority architecture.

3. NVIC Architecture

Peripheral interrupt requests are routed to the NVIC. The NVIC evaluates their enable state, pending state and priority before the processor accepts an eligible interrupt.

4. Interrupt States

An external interrupt can have several important states.

State Meaning
Disabled The interrupt is not enabled in the NVIC.
Enabled The NVIC is permitted to activate the interrupt when eligible.
Pending An interrupt request is waiting to be serviced.
Active The processor is currently executing that interrupt handler.
Active and Pending The interrupt is active and another request is pending.
Enabling an interrupt in the NVIC does not necessarily configure the peripheral itself. The peripheral's interrupt source and interrupt flag must also be configured correctly.

5. Interrupt Priority

Interrupt priority determines which eligible exception is handled first and whether it can preempt another currently executing handler.

In Cortex-M NVIC priority numbering, a lower numerical value represents a higher priority.

Priority Value Priority Level
0 Highest configurable priority
1 Lower than priority 0
2 Lower than priority 1
3 Lower than priority 2
... ...
Interview point: Priority 0 is higher than priority 3 in Cortex-M. This is the opposite of the numbering convention some programmers expect.

6. Implemented Priority Bits

Cortex-M implementations do not necessarily implement every priority bit available in the NVIC priority registers. The number of implemented bits depends on the processor and device implementation.

For example, a device implementing four priority bits provides 16 configurable priority levels. 

Number of priority levels = 2^N

N = 4

Number of levels = 2^4 = 16

Priority values:
0 to 15

The priority values are stored in the most significant bits of the priority fields. Unimplemented low-order bits read as zero.

7. Preemption Priority and Subpriority

Where priority grouping is supported, implemented priority bits can be divided into two fields:

  • Preemption priority: Determines whether one exception can interrupt another.
  • Subpriority: Determines which pending exception is selected first when preemption priority is equal.

Example

Interrupt Preemption Priority Subpriority
UART 1 0
Timer 0 1
ADC 2 0

In this example, Timer has the highest preemption priority because its preemption value is 0. It can preempt the UART and ADC handlers when the processor architecture and current execution state permit it.

Subpriority does not allow an interrupt to preempt another interrupt. It only helps select among pending exceptions with equal preemption priority.

8. Nested Interrupts

Nested interrupts occur when a higher-priority interrupt interrupts the execution of a lower-priority interrupt handler.

Nested Interrupt Sequence

  1. Main program is executing.
  2. A low-priority interrupt is accepted.
  3. The low-priority ISR begins execution.
  4. A higher-priority interrupt arrives.
  5. The higher-priority ISR preempts the lower-priority ISR.
  6. The higher-priority ISR completes.
  7. The lower-priority ISR resumes.
  8. The processor eventually returns to the main program.

9. Vector Table and NVIC Relationship

The vector table contains the addresses of exception handlers. The NVIC controls the handling of external interrupt requests.

For an external interrupt, the interrupt number is associated with a vector-table exception number. 

Exception Number = 16 + External IRQ Number

Example:

External IRQ 0  -> Exception Number 16
External IRQ 1  -> Exception Number 17
External IRQ 2  -> Exception Number 18

Actual IRQ numbers and handler names depend on the selected STM32 microcontroller. The device startup file supplies the corresponding vector table entries.

10. NVIC Programming Using CMSIS

CMSIS provides standard functions for configuring Cortex-M NVIC features. The following example enables an external interrupt and assigns a priority. 

#include "stm32xxxx.h"

void Configure_Interrupt(void)
{
    NVIC_SetPriority(EXTI0_IRQn, 2);

    NVIC_EnableIRQ(EXTI0_IRQn);
}

Replace the device header and IRQ identifier with the correct definitions for the selected STM32 device.

Disable an Interrupt

NVIC_DisableIRQ(EXTI0_IRQn);

Set Interrupt Priority

NVIC_SetPriority(EXTI0_IRQn, 2);

Check Pending Status

if (NVIC_GetPendingIRQ(EXTI0_IRQn))
{
    // Interrupt is pending
}

Clear Pending Status

NVIC_ClearPendingIRQ(EXTI0_IRQn);
Important: CMSIS functions operate on NVIC state. They do not replace peripheral configuration. For example, an EXTI interrupt also requires correct GPIO, EXTI line, edge detection and peripheral interrupt setup.

11. Priority Grouping

Priority grouping controls how the implemented priority bits are divided between preemption priority and subpriority.

The available grouping options and their practical effects depend on the Cortex-M implementation. STM32 HAL projects commonly configure grouping using a function such as: 

HAL_NVIC_SetPriorityGrouping(
    NVIC_PRIORITYGROUP_4
);

In STM32 HAL, the grouping constants describe the allocation of priority bits. Verify the selected device's implemented priority bits and HAL documentation before choosing a grouping.

12. Practical Example: Configure an EXTI Interrupt

The following is a simplified CMSIS-style illustration of NVIC configuration. GPIO and EXTI peripheral setup must be completed separately. 

#include "stm32xxxx.h"

void EXTI0_IRQHandler(void)
{
    /*
       Check and clear the EXTI pending flag
       using the correct register/API for
       the selected STM32 family.
    */

    // Short interrupt-related processing
}

void Interrupt_Init(void)
{
    NVIC_SetPriority(EXTI0_IRQn, 2);

    NVIC_EnableIRQ(EXTI0_IRQn);
}

The exact EXTI pending-flag register and clearing mechanism vary across STM32 families. Some families use different EXTI register layouts.

14. Placement Interview Questions and Answers

Q1. What is NVIC?

NVIC is the Nested Vectored Interrupt Controller integrated into Cortex-M processors for managing external interrupts.

Q2. What does NVIC stand for?

Nested Vectored Interrupt Controller.

Q3. Which priority is highest in Cortex-M?

Priority 0 is the highest configurable priority.

Q4. What is interrupt nesting?

It occurs when a higher-priority interrupt preempts a lower-priority interrupt handler.

Q5. What is preemption priority?

It determines whether an exception can interrupt another currently executing exception handler.

Q6. What is subpriority?

It determines the order in which pending exceptions with equal preemption priority are selected.

Q7. What is a pending interrupt?

It is an interrupt request waiting for the processor to accept it.

Q8. What is an active interrupt?

It is an interrupt whose handler is currently executing.

Q9. How many priority levels are available with four implemented bits?

Sixteen priority levels, from 0 to 15.

Q10. What is the relationship between NVIC and the vector table?

NVIC manages external interrupt requests and priorities, while the vector table provides the handler addresses.

Q11. What does NVIC_EnableIRQ() do?

It enables the specified external interrupt in the NVIC.

Q12. Does enabling NVIC automatically configure a peripheral interrupt?

No. The peripheral and its interrupt source must also be configured correctly.

16. Lesson Summary

  • NVIC manages external interrupt requests.
  • It supports interrupt enabling, pending status and priority management.
  • Lower numerical priority values represent higher configurable priorities.
  • Preemption priority controls interrupt nesting.
  • Subpriority helps select among pending exceptions of equal preemption priority.
  • The vector table provides handler addresses.
  • CMSIS provides standard NVIC configuration functions.
  • Peripheral configuration is also required for a working interrupt.
