Lesson 4: Exceptions and Interrupt Handling Architecture

Exception Types, Vector Table, ISR Execution and Exception Return

1. Learning Objectives

  • Understand exceptions in ARM Cortex-M processors.
  • Differentiate exceptions and interrupts.
  • Identify important Cortex-M exception types.
  • Understand the exception vector table.
  • Explain exception entry and return.
  • Understand automatic context stacking.
  • Learn the purpose of an Interrupt Service Routine.
  • Understand fault exceptions and their debugging importance.

2. What is an Exception?

An exception is an event that causes the processor to temporarily suspend its normal program execution and transfer control to a specific exception handler.

The processor executes the handler to respond to the event. After handling the exception, it can return to the previously interrupted program when the exception handling completes normally.

Examples of Exceptions

  • Reset.
  • Non-Maskable Interrupt (NMI).
  • HardFault.
  • Memory Management Fault, when implemented.
  • BusFault, when implemented.
  • UsageFault, when implemented.
  • SysTick.
  • External peripheral interrupts.

3. Exception vs Interrupt

An interrupt is a type of exception generally generated by an external peripheral or hardware event. The term exception is broader and includes processor faults and system exceptions.

Exception Interrupt
Broad term for events that change normal execution. A type of exception triggered by an interrupt source.
Includes faults and system exceptions. Often generated by peripherals or external hardware.
May be synchronous or asynchronous. Usually asynchronous to the currently executing instruction stream.
Examples include Reset and HardFault. Examples include UART, timer and GPIO interrupts.

4. Cortex-M Exception Types

Cortex-M exception types include processor-defined system exceptions and device-specific external interrupts.

Exception Purpose
Reset Starts processor execution after reset.
NMI Handles a high-priority, non-maskable event.
HardFault Handles serious faults and escalated fault conditions.
MemManage Handles memory protection faults where implemented.
BusFault Handles certain instruction or data bus errors where implemented.
UsageFault Handles certain invalid instruction and execution conditions where implemented.
SVCall Provides a supervisor-call exception mechanism.
Debug Monitor Supports debug-monitor exception handling where implemented and enabled.
PendSV Often used for deferred processing and RTOS context switching.
SysTick Provides a system timer exception.
External IRQ Handles peripheral and external interrupt requests.
Important: Available fault exceptions and debug features vary by Cortex-M core and device configuration. For example, some Cortex-M0+ implementations have a more limited configurable fault architecture than Cortex-M3/M4.

5. Exception Number and Vector Table

Cortex-M uses an exception vector table to identify the handler address associated with each exception.

The vector table begins with the initial Main Stack Pointer value, followed by the Reset handler address and other exception handler addresses.

Conceptual Vector Table

Vector Position Entry Purpose
0 Initial MSP value Initial stack pointer.
1 Reset Handler Starts application initialization.
2 NMI Handler Handles NMI.
3 HardFault Handler Handles HardFault.
4 MemManage Handler Handles memory-management faults where supported.
5 BusFault Handler Handles bus faults where supported.
6 UsageFault Handler Handles usage faults where supported.
11 SVCall Handler Handles supervisor calls.
14 PendSV Handler Handles PendSV.
15 SysTick Handler Handles SysTick.
16 onward External IRQ handlers Handles device-specific interrupts.
Vector positions are shown for the standard Cortex-M exception layout. Some entries are reserved, and the availability of specific exceptions depends on the core. External interrupt numbers are device-specific.

7. Exception Entry Process

When an exception is accepted, the Cortex-M processor performs several operations automatically.

  1. Completes or handles the current instruction according to the architecture.
  2. Identifies the accepted exception.
  3. Pushes the basic exception stack frame onto the active stack.
  4. Updates processor execution state.
  5. Loads the handler address from the vector table.
  6. Starts executing the exception handler in Handler mode.

Basic Exception Stack Frame

Register Purpose
R0First general-purpose register saved.
R1General-purpose register.
R2General-purpose register.
R3General-purpose register.
R12General-purpose register.
LRLink Register.
PCProgram Counter.
xPSRProgram Status Register.

The basic frame contains eight 32-bit words, which occupy 32 bytes. Additional alignment padding or floating-point context can increase the actual stack space used.

8. Interrupt Service Routine (ISR)

An Interrupt Service Routine is a function that executes when a corresponding interrupt is accepted by the processor. It performs the immediate processing required by the event.

Example: Timer Interrupt Handler

#include "main.h"

volatile uint32_t timer_count = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_13)
    {
        timer_count++;
    }
}

This is an illustrative STM32 HAL callback for an external GPIO interrupt, not a timer ISR. The corresponding GPIO interrupt must be configured and enabled in the project.

Direct Interrupt Handler Example

void TIM2_IRQHandler(void)
{
    if (TIM2->SR & TIM_SR_UIF)
    {
        TIM2->SR &= ~TIM_SR_UIF;

        // Perform short interrupt-related operation
    }
}

This example is device-dependent. The timer clock, interrupt enable, vector name and flag-clearing procedure must match the selected STM32 family and reference manual.

9. Exception Return

When an exception handler completes, the processor restores the interrupted context and resumes execution.

Cortex-M uses a special EXC_RETURN value, commonly loaded into LR on exception entry, to control exception return behavior.

A handler typically returns using a suitable exception return sequence generated by the compiler or assembly code. The processor then restores the stacked context.

Interview point: Exception return is not the same as an ordinary function return. The processor recognizes the EXC_RETURN value and performs architectural exception-return processing.

10. Fault Exceptions

Fault exceptions indicate problems during instruction execution or memory and bus access.

HardFault

HardFault is a fault exception used for serious fault conditions and for certain faults that cannot be handled by a configurable fault handler.

Memory Management Fault

Can report memory access violations when the relevant memory protection mechanism is implemented and enabled.

BusFault

Can report certain instruction or data access errors associated with the processor bus interface.

UsageFault

Can report invalid instruction execution and other usage-related conditions, depending on the processor.

Fault Debugging Steps

  1. Stop execution at the fault handler.
  2. Inspect the stacked PC and LR values.
  3. Inspect xPSR and the active exception state.
  4. Check relevant fault status registers where implemented.
  5. Identify the instruction or memory access that caused the fault.
  6. Correct the firmware issue and test again.

11. Interrupt Handling Best Practices

  • Keep interrupt handlers short and efficient.
  • Avoid long delays inside an ISR.
  • Avoid blocking operations in an ISR.
  • Clear peripheral interrupt flags correctly.
  • Use appropriate shared-variable synchronization.
  • Use volatile for variables shared with an ISR when required, but do not treat it as a complete synchronization mechanism.
  • Defer lengthy processing to the main loop or an RTOS task.
  • Check interrupt priorities and nesting requirements.

12. Placement Interview Questions and Answers

Q1. What is an exception?

An exception is an event that changes normal processor execution to a corresponding handler.

Q2. What is the difference between an exception and an interrupt?

An interrupt is a type of exception. Exceptions also include faults and other processor-defined events.

Q3. What is an ISR?

An Interrupt Service Routine is a function executed to handle an accepted interrupt.

Q4. What is the vector table?

It is a table containing the initial stack pointer and exception handler addresses.

Q5. What happens when an interrupt is accepted?

The processor saves the required context, enters Handler mode and executes the corresponding handler.

Q6. Which registers are saved automatically in the basic exception stack frame?

R0-R3, R12, LR, PC and xPSR.

Q7. What is HardFault?

It is a fault exception used for serious faults and escalated fault conditions.

Q8. What is SysTick?

SysTick is a system timer that can generate periodic exceptions for timing and scheduling purposes.

Q9. What is PendSV commonly used for?

PendSV is commonly used by RTOS implementations for deferred processing and task context switching.

Q10. Why should an ISR be short?

A short ISR reduces interrupt latency, minimizes processor occupation and improves system responsiveness.

Q11. What is exception return?

It is the architectural process that restores the previously interrupted processor context.

Q12. How can a HardFault be debugged?

Inspect the stacked PC, LR, xPSR and available fault-status registers to identify the cause.

14. Lesson Summary

  • Exceptions temporarily change normal processor execution.
  • Interrupts are one category of exception.
  • The vector table provides exception handler addresses.
  • The processor automatically saves a basic exception stack frame.
  • ISRs handle interrupt events.
  • EXC_RETURN controls architectural exception return.
  • Fault handlers are important for firmware debugging.
  • Efficient ISR design improves real-time system behavior.
