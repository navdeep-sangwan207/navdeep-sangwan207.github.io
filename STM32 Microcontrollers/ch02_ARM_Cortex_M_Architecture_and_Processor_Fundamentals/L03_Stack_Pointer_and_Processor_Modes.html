Lesson 3: Stack Pointer and Processor Modes

Stack Operation, MSP, PSP, Thread Mode and Handler Mode

1. Learning Objectives

  • Understand the stack in embedded systems.
  • Explain the purpose of the Stack Pointer.
  • Understand push and pop operations.
  • Differentiate MSP and PSP.
  • Understand Thread mode and Handler mode.
  • Explain privileged and unprivileged execution.
  • Understand stack usage during function calls and interrupts.
  • Recognize stack overflow and corruption problems.

2. What is a Stack?

A stack is a memory area used by a program to store temporary data, function information, local variables and return addresses.

It follows the Last In, First Out (LIFO) principle. The last item stored is normally the first item retrieved.

Example

Suppose three values A, B and C are pushed onto a stack. The order of removal is C, B and then A.

3. What is the Stack Pointer?

The Stack Pointer (SP) is a processor register that identifies the current stack location. It is used to manage stack memory during program execution.

In Cortex-M processors, R13 is the Stack Pointer. The processor provides two stack pointer selections: Main Stack Pointer and Process Stack Pointer.

Functions of the Stack Pointer

  • Tracks the current stack location.
  • Supports function calls and returns.
  • Stores local variables and temporary data when needed.
  • Supports exception entry and return.
  • Helps preserve processor context.

4. Stack Growth Direction

Cortex-M software normally uses a full-descending stack. This means the stack grows toward lower memory addresses. The Stack Pointer generally points to the last occupied stack location.

Important: A full-descending stack is the conventional Cortex-M stack arrangement. Always distinguish the stack growth direction from the exact address stored in SP after a particular instruction.

5. PUSH and POP Instructions

PUSH

PUSH stores one or more register values onto the stack. On a descending stack, the stack pointer is adjusted toward lower addresses.

POP

POP retrieves register values from the stack and updates the stack pointer.

Assembly Example

PUSH {R0, R1}

; Perform other operations

POP  {R0, R1}

The PUSH instruction saves R0 and R1. The POP instruction restores the saved values.

The registers must be restored in a way consistent with the saved stack frame. Unbalanced PUSH and POP operations can corrupt program execution.

6. Main Stack Pointer (MSP)

MSP stands for Main Stack Pointer. It is the default stack pointer after reset on Cortex-M processors.

Common Uses

  • Used in Handler mode.
  • Used by many bare-metal applications in Thread mode.
  • Used during exception handling.
  • Can be used for operating-system kernel execution.

When an exception occurs, the processor uses the appropriate active stack pointer to save the exception context. Handler mode itself uses MSP.

7. Process Stack Pointer (PSP)

PSP stands for Process Stack Pointer. It provides an alternative stack for Thread mode execution.

Common Uses

  • Used for application tasks in an RTOS.
  • Provides separate stacks for different tasks.
  • Helps separate application execution from kernel execution.
  • Supports task context switching.
Placement point: An RTOS commonly uses PSP for task execution and MSP for kernel and exception handling. The actual arrangement depends on the RTOS port and configuration.

8. MSP vs PSP

Feature MSP PSP
Full Name Main Stack Pointer Process Stack Pointer
After Reset Selected by default Not selected by default
Handler Mode Always used Not used for Handler mode execution
Thread Mode Can be used Can be selected
RTOS Use Commonly used by kernel Commonly used by tasks

9. Cortex-M Processor Modes

Cortex-M processors have two execution modes:

1. Thread Mode

Thread mode is used for normal program execution. Application code and RTOS tasks generally execute in Thread mode.

2. Handler Mode

Handler mode is used when the processor executes an exception handler, such as an interrupt service routine or system exception handler.

10. Privileged and Unprivileged Execution

Cortex-M processors support privileged and unprivileged execution in Thread mode.

Privileged Execution

  • Can access privileged system-control resources.
  • Can execute privileged instructions.
  • Can configure important processor settings.

Unprivileged Execution

  • Has restricted access to privileged resources.
  • Cannot execute certain privileged instructions.
  • Can request privileged services through mechanisms such as SVC.

Handler mode always executes with privileged access. CONTROL register settings are used to manage Thread mode privilege and stack selection.

11. CONTROL Register

The CONTROL register determines important aspects of Thread mode execution.

Bit Name Function
Bit 0 nPRIV Controls privileged or unprivileged Thread mode execution.
Bit 1 SPSEL Selects MSP or PSP in Thread mode.
The exact availability and behavior of CONTROL bits depend on the Cortex-M architecture version. These two bits are common to the classic Cortex-M programmer model discussed in this lesson.

12. Stack Usage During Function Calls

During a function call, the compiler may use the stack to preserve registers, store local variables and maintain information needed to return to the calling function.

Example C Program

#include <stdint.h>

uint32_t add_numbers(uint32_t a, uint32_t b)
{
    uint32_t result;

    result = a + b;

    return result;
}

int main(void)
{
    uint32_t answer;

    answer = add_numbers(10, 20);

    while (1)
    {
    }
}

The compiler may use registers for arguments and return values and may use the stack for saved registers or other function data. Actual stack usage depends on compiler optimization and generated code.

13. Stack Usage During Interrupts

When a Cortex-M exception is accepted, the processor automatically saves a basic exception stack frame to the currently active stack.

On common Cortex-M implementations, the basic frame contains:

  • R0
  • R1
  • R2
  • R3
  • R12
  • LR
  • PC
  • xPSR

This automatic stacking allows the processor to restore the interrupted execution context when the exception handler finishes.

Floating-point context can require additional stacking on Cortex-M cores with an FPU. Stack alignment and lazy-stacking behavior can also affect the exact memory usage.

14. Stack Overflow and Stack Corruption

Stack Overflow

Stack overflow occurs when a program uses more stack memory than has been allocated. It can overwrite adjacent memory and cause unpredictable behavior.

Common Causes

  • Excessive nested function calls.
  • Deep recursion.
  • Large local arrays.
  • Insufficient RTOS task stack size.
  • Unexpected interrupt nesting or context requirements.

Stack Corruption

Stack corruption occurs when invalid memory writes, incorrect pointer operations or unbalanced stack manipulation damage stored stack data.

Prevention

  • Allocate suitable stack memory.
  • Avoid unnecessary recursion in embedded firmware.
  • Monitor RTOS task stack usage.
  • Use stack watermark or overflow checking where available.
  • Inspect memory and SP during debugging.

15. Placement Interview Questions and Answers

Q1. What is a stack?

A stack is a memory area that follows the Last In, First Out principle.

Q2. What is the function of SP?

SP points to the current stack location and supports stack memory management.

Q3. What are MSP and PSP?

MSP is the Main Stack Pointer and PSP is the Process Stack Pointer.

Q4. Which stack pointer is used in Handler mode?

Handler mode always uses MSP.

Q5. What are Thread and Handler modes?

Thread mode executes normal application code. Handler mode executes exception handlers.

Q6. In which direction does the Cortex-M stack normally grow?

It normally grows toward lower memory addresses.

Q7. What is the difference between PUSH and POP?

PUSH stores register values on the stack, while POP restores values from the stack.

Q8. Why does an RTOS use PSP?

PSP commonly provides a separate stack for each application task.

Q9. What is stack overflow?

It occurs when stack usage exceeds the allocated stack memory.

Q10. Which register controls Thread mode stack selection?

The SPSEL bit of the CONTROL register selects MSP or PSP in Thread mode.

Q11. Which mode is always privileged?

Handler mode.

Q12. What information is automatically stacked on exception entry?

The basic frame contains R0-R3, R12, LR, PC and xPSR.

17. Lesson Summary

  • A stack follows the LIFO principle.
  • R13 is the Stack Pointer.
  • Cortex-M provides MSP and PSP stack pointer selections.
  • Handler mode always uses MSP.
  • Thread mode can use MSP or PSP.
  • Thread mode is used for normal application execution.
  • Handler mode is used for exception handling.
  • Stack overflow can cause serious firmware failures.
