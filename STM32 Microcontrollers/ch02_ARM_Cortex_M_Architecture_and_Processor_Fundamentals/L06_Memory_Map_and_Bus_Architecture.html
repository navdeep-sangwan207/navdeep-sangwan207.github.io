Lesson 6: Memory Map and Bus Architecture

Address Space, Flash, SRAM, Peripheral Mapping and Processor Bus Systems

1. Learning Objectives

  • Understand the Cortex-M memory map.
  • Learn the concept of memory address space.
  • Differentiate Flash, SRAM and peripheral memory.
  • Understand memory-mapped I/O.
  • Learn the purpose of AHB and APB buses.

2. What is a Memory Map?

A memory map defines how the processor's address space is organized. It identifies the address ranges used for program memory, data memory, peripherals and other processor resources.

Every memory location and memory-mapped peripheral register is accessed using an address.

Example

Address: 0x08000000

A memory location in the Flash region
on many STM32 microcontrollers.
Important: The exact memory capacity, peripheral addresses and memory organization depend on the selected STM32 device. Always consult its datasheet and reference manual.

3. Cortex-M Memory Map Overview

Cortex-M processors use a defined architectural address map. The following is a simplified overview of the standard 4 GB address space.

Address Range Memory Region Typical Purpose
0x00000000 – 0x1FFFFFFF Code region Program code and related memory mapping.
0x20000000 – 0x3FFFFFFF SRAM region Data storage and RAM.
0x40000000 – 0x5FFFFFFF Peripheral region Memory-mapped peripheral registers.
0x60000000 – 0x9FFFFFFF External RAM region External memory interfaces where implemented.
0xA0000000 – 0xDFFFFFFF External device region External devices and memory interfaces where implemented.
0xE0000000 – 0xFFFFFFFF Private peripheral and system region Core system control, NVIC and debug resources.
These are architectural regions, not a statement that every STM32 device physically implements all of them. Device-specific memory is mapped into the relevant regions.

4. Flash Memory

Flash is non-volatile memory used to store firmware and other data that must remain available after power is removed.

Features

  • Retains data without power.
  • Stores the application program.
  • Stores constants and read-only data.
  • Can be erased and programmed according to device-specific rules.
  • Has finite erase/program endurance.

Typical STM32 Flash Address

0x08000000

Common Flash base address
on many STM32 microcontrollers.

Firmware is commonly programmed into internal Flash. The processor fetches instructions from the configured code memory mapping.

5. SRAM

SRAM is volatile memory used for temporary data storage during program execution.

Features

  • Fast read and write access.
  • Stores global and local variables.
  • Stores runtime stack data.
  • Stores dynamically allocated memory when a heap is used.
  • Normally loses its contents when power is removed.

Typical STM32 SRAM Base Address

0x20000000

Common SRAM base address
on many STM32 microcontrollers.

6. Peripheral Memory Region

Peripheral registers are mapped into the processor's address space. The CPU can access these registers using normal memory-access instructions.

Examples of STM32 Peripherals

  • GPIO
  • USART and UART
  • SPI
  • I2C
  • Timers
  • ADC
  • DMA

The peripheral region commonly begins at address 0x40000000 in the Cortex-M memory map.

7. Memory-Mapped I/O

Memory-mapped I/O is a technique in which peripheral control and status registers are assigned addresses within the processor's memory address space.

The processor reads or writes these addresses to control hardware peripherals.

Example: GPIO Register Access

#include "stm32xxxx.h"

void GPIO_Set_Pin(void)
{
    GPIOA->BSRR = GPIO_PIN_5;
}

This example sets GPIOA pin 5 on STM32 devices whose GPIO BSRR register uses this bit mapping. GPIO clock enable and pin configuration must be completed first.

Why is BSRR Useful?

  • Allows atomic GPIO set and reset operations on supported STM32 GPIO implementations.
  • Avoids a read-modify-write sequence for the corresponding pin operation.
  • Can reduce race conditions when multiple execution contexts access GPIO registers.

8. Bus Architecture

A bus is a communication pathway that transfers data, addresses and control information between processor components, memory and peripherals.

Main Bus Types in STM32 Systems

  • AHB – Advanced High-performance Bus.
  • APB – Advanced Peripheral Bus.

This is a conceptual bus diagram. Actual bus topology, bridges, bus matrices and peripheral connections differ among STM32 families.

9. AHB Bus

AHB stands for Advanced High-performance Bus. It is commonly used for high-speed communication between processor cores, memory systems, DMA and peripheral bridges.

Typical Characteristics

  • Designed for high-performance data transfer.
  • Supports memory and system interconnect communication.
  • Connects important system components.
  • May connect to APB through a bridge.

10. APB Bus

APB stands for Advanced Peripheral Bus. It is designed for relatively simple peripheral register access.

Typical APB Peripherals

  • UART and USART
  • SPI and I2C
  • GPIO, where connected through the relevant bus structure
  • Timers
  • Other low-bandwidth control peripherals
The exact APB allocation is device-dependent. Some STM32 peripherals reside on different bus domains, and modern STM32 families may use multiple AHB/APB domains.

11. AHB vs APB

AHB APB
Advanced High-performance Bus. Advanced Peripheral Bus.
Designed for higher-performance system communication. Designed for simpler peripheral communication.
Commonly connects CPU, memory and system interconnects. Commonly connects peripheral registers.
Can connect to APB through a bridge. Can be connected through an AHB-to-APB bridge.
Architecture and clocking vary by device. Architecture and clocking vary by device.

12. Memory Sections in Embedded C

An embedded C program is divided into sections that are placed into memory by the compiler and linker.

Section Purpose Typical Location
.text Program instructions. Flash
.rodata Read-only constants. Flash
.data Initialized global and static variables. RAM at runtime; initial values stored in Flash.
.bss Zero-initialized or uninitialized static-storage variables. RAM
Heap Dynamic memory allocation. RAM
Stack Function calls and local runtime data. RAM

Example

#include <stdint.h>

const uint32_t limit = 100;

uint32_t counter = 10;

uint32_t total;

int main(void)
{
    uint32_t local_value = 5;

    while (1)
    {
        counter += local_value;
    }
}

Typical placement:

  • limit: read-only data, often in Flash.
  • counter: initialized data, copied to RAM at startup.
  • total: zero-initialized data, normally in BSS.
  • local_value: typically stored in a register or on the stack, depending on compiler optimization.

13. Linker Script and Memory Layout

A linker script defines how program sections are placed into the target memory regions.

It commonly specifies:

  • Flash origin and length.
  • RAM origin and length.
  • Placement of code and constant data.
  • Placement of initialized and uninitialized data.
  • Stack and heap allocation boundaries.
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 128K
    RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 20K
}

This is only an illustrative linker memory definition. The sizes are not universal STM32 values. Use the selected device's actual memory capacity and linker configuration.

14. Common Memory Problems

Problem Possible Cause
HardFault during memory access Invalid address or unsupported access.
Stack overflow Excessive local variables or deep function calls.
Heap allocation failure Insufficient free RAM or fragmentation.
Firmware does not fit Flash usage exceeds available capacity.
Incorrect peripheral behavior Wrong register address or configuration.
Unexpected variable values Memory corruption or uninitialized data.

15. Placement Interview Questions and Answers

Q1. What is a memory map?

A memory map defines the address ranges assigned to memory and peripheral resources.

Q2. What is Flash memory?

Flash is non-volatile memory commonly used to store firmware and constants.

Q3. What is SRAM?

SRAM is volatile memory used for runtime data, variables and stack storage.

Q4. What is memory-mapped I/O?

It is a method of accessing peripheral registers through addresses in the processor's memory map.

Q5. What does AHB stand for?

Advanced High-performance Bus.

Q6. What does APB stand for?

Advanced Peripheral Bus.

Q7. What is the main difference between AHB and APB?

AHB is commonly used for high-performance system communication, while APB is used for simpler peripheral register access.

Q8. What is the .text section?

It contains executable program instructions.

Q9. What is the .bss section?

It contains zero-initialized and uninitialized static-storage variables.

Q10. What is a linker script?

It specifies how program sections are arranged in the target memory regions.

Q11. Why is memory-mapped I/O useful?

It allows the CPU to control hardware peripherals using normal memory-access instructions.

Q12. What causes stack overflow?

Excessive stack usage, deep function calls, recursion or large local variables can cause stack overflow.

  • The memory map organizes the processor address space.
  • Flash stores firmware and non-volatile data.
