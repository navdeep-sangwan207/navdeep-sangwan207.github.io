2. What Is NVIC?

NVIC stands for Nested Vectored Interrupt Controller. It is an interrupt controller integrated into ARM Cortex-M processors.

NVIC manages external interrupt requests and supports features such as interrupt enabling, pending status, priority configuration and nested interrupt handling.

Main Functions of NVIC

  • Enables and disables external interrupts.
  • Maintains interrupt pending and active states.
  • Supports interrupt priority configuration.
  • Supports nested interrupt handling.
  • Directs execution to the correct interrupt handler.
  • Works with the Cortex-M exception mechanism.
Example:

When an enabled STM32 timer generates an interrupt request, the NVIC determines whether the interrupt can be accepted based on its enable state, priority and the processor's current execution state.

3. NVIC Architecture

A typical external interrupt path in an STM32 system can be represented as follows: 


       STM32 Peripheral
       (Timer / UART / EXTI)
               |
               v
       Interrupt Request
               |
               v
              NVIC
       +------------------+
       | Enable / Disable |
       | Pending State    |
       | Priority         |
       | Active State     |
       +------------------+
               |
               v
        Cortex-M Processor
               |
               v
          Execute ISR
               |
               v
         Return to Program

The peripheral generates the request. NVIC manages the external interrupt request, and the processor executes the corresponding exception handler when the request is eligible.

Peripheral interrupt generation and NVIC interrupt enable are separate configuration steps. Enabling an NVIC interrupt alone does not necessarily enable the peripheral to generate that interrupt.

4. External Interrupts and Exception Numbers

Cortex-M processors have processor exceptions and external interrupt requests.

External interrupt IRQ numbers are assigned by the microcontroller vendor and documented in the device reference manual.

In the Cortex-M exception numbering scheme, external IRQ0 corresponds to exception number 16. Therefore: 

Exception Number = IRQ Number + 16
Exception Number Meaning
1 Reset
2 NMI
3 HardFault
11 SVCall
14 PendSV
15 SysTick
16 External IRQ0
17 External IRQ1

The exact external IRQ assignments depend on the STM32 device.

5. Interrupt Vector Table

The interrupt vector table is a table of addresses used by the processor to locate exception and interrupt handlers.

It normally contains the initial Main Stack Pointer value followed by the reset handler and exception handler addresses.

Conceptual Vector Table

Vector Entry Handler
0 Initial Stack Pointer
1 Reset_Handler
2 NMI_Handler
3 HardFault_Handler
11 SVC_Handler
14 PendSV_Handler
15 SysTick_Handler
16 onward External IRQ handlers

STM32 startup files normally provide the vector table and default handler definitions. The vector table location can be configured through the microcontroller's startup and system configuration.

The table above shows exception numbering, not actual byte offsets. Each vector entry occupies one word in a typical Cortex-M vector table.

6. NVIC Registers

NVIC provides memory-mapped registers for controlling interrupt states and priorities. CMSIS functions are generally preferred over direct register access.

Register Purpose
ISER Interrupt Set-Enable Register
ICER Interrupt Clear-Enable Register
ISPR Interrupt Set-Pending Register
ICPR Interrupt Clear-Pending Register
IABR Interrupt Active Bit Register
IPR Interrupt Priority Registers

Register Explanation

  • ISER: Writing a one to the corresponding bit enables an external interrupt.
  • ICER: Writing a one to the corresponding bit disables an external interrupt.
  • ISPR: Sets an interrupt as pending.
  • ICPR: Clears the pending state of an interrupt.
  • IABR: Indicates whether an external interrupt is active.
  • IPR: Stores external interrupt priority values.
NVIC register layout and implemented priority bits are defined by the Cortex-M implementation. The number of external interrupt lines varies by device.

7. NVIC Configuration Using CMSIS

CMSIS provides standard functions to configure NVIC interrupts.

Function Purpose
NVIC_EnableIRQ() Enables an external interrupt.
NVIC_DisableIRQ() Disables an external interrupt.
NVIC_SetPriority() Sets an interrupt priority.
NVIC_GetPriority() Reads an interrupt priority.
NVIC_SetPendingIRQ() Sets an external interrupt pending.
NVIC_ClearPendingIRQ() Clears an external interrupt pending state.

Example: Enabling a Timer Interrupt

#include "stm32f4xx.h"

void Configure_NVIC(void)
{
    NVIC_SetPriority(TIM2_IRQn, 2);

    NVIC_EnableIRQ(TIM2_IRQn);
}

This example configures the NVIC priority and enables the TIM2 interrupt.

This is an STM32F4 CMSIS example. The IRQ name and availability of TIM2 depend on the selected device. The timer peripheral must also be configured to generate the required interrupt.

8. NVIC Configuration Using STM32 HAL

STM32 HAL projects commonly use CMSIS NVIC functions in the MSP initialization code.

Example: TIM2 NVIC Setup

void HAL_TIM_Base_MspInit(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        HAL_NVIC_SetPriority(TIM2_IRQn, 2, 0);

        HAL_NVIC_EnableIRQ(TIM2_IRQn);
    }
}

The timer peripheral can then be started in interrupt mode: 

HAL_TIM_Base_Start_IT(&htim2);

The interrupt handler forwards processing to the HAL driver: 

void TIM2_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim2);
}

The timer callback can process the event: 

void HAL_TIM_PeriodElapsedCallback(
    TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        /* Timer period elapsed event */
    }
}
A complete working project also requires a valid TIM2 clock, timer period configuration, correct startup vector, correct IRQ handler and appropriate HAL initialization. The timer interrupt source must be enabled by the HAL start operation.

9. Enabling and Disabling Interrupts

Enable Interrupt

NVIC_EnableIRQ(TIM2_IRQn);

Disable Interrupt

NVIC_DisableIRQ(TIM2_IRQn);

Set Interrupt Priority

NVIC_SetPriority(TIM2_IRQn, 3);

Check Pending State

uint32_t status =
    NVIC_GetPendingIRQ(TIM2_IRQn);

Clear Pending State

NVIC_ClearPendingIRQ(TIM2_IRQn);

These functions operate on the NVIC state of external interrupts. They do not replace peripheral-specific status flag handling.

10. Interrupt Enable Sequence

A typical peripheral interrupt setup follows this sequence: 


        Start
          |
          v
   Enable Peripheral Clock
          |
          v
   Configure Peripheral
          |
          v
   Enable Peripheral IRQ Source
          |
          v
   Set NVIC Priority
          |
          v
   Enable NVIC Interrupt
          |
          v
   Execute Main Program
          |
          v
   Interrupt Event Occurs
          |
          v
       Execute ISR
          |
          v
    Process Event / Return

The exact initialization order can vary by peripheral and HAL driver. Ensure the peripheral and NVIC are configured before allowing the event to occur.

11. NVIC in STM32CubeMX

STM32CubeMX provides a graphical interface for configuring peripheral interrupts and NVIC settings.

General Configuration Steps

  1. Open the STM32CubeIDE project.
  2. Open the device configuration file.
  3. Select the required peripheral.
  4. Enable its interrupt in the peripheral settings.
  5. Open the NVIC settings section.
  6. Enable the corresponding interrupt.
  7. Configure the priority and subpriority where supported.
  8. Generate the project code.
  9. Inspect the generated IRQ handler and initialization code.
The configuration screens and available options vary with the STM32 family and CubeMX version.

12. Common NVIC Programming Errors

Error Possible Result
NVIC interrupt not enabled External interrupt handler does not execute.
Peripheral interrupt source disabled Peripheral does not request an interrupt.
Incorrect IRQ number Wrong interrupt is configured.
Incorrect handler name Expected handler may not be called.
Incorrect vector table Processor may branch to an unexpected handler.
Pending flag not handled Unexpected repeated interrupt behavior.
Incorrect priority assumptions Unexpected interrupt preemption behavior.

13. Placement-Oriented Interview Questions

Q1. What is NVIC?

NVIC stands for Nested Vectored Interrupt Controller. It manages external interrupt requests, priorities, enable states and pending states in Cortex-M processors.

Q2. What is the purpose of NVIC?

It controls interrupt enabling, pending status, priority and delivery to the processor.

Q3. What is an interrupt vector table?

It is a table containing the initial stack pointer and addresses of exception and interrupt handlers.

Q4. What is ISER?

ISER is the Interrupt Set-Enable Register. It is used to enable external interrupts.

Q5. What is ICER?

ICER is the Interrupt Clear-Enable Register. It is used to disable external interrupts.

Q6. What is ISPR?

ISPR is the Interrupt Set-Pending Register. It is used to set an external interrupt as pending.

Q7. What is ICPR?

ICPR is the Interrupt Clear-Pending Register. It clears an external interrupt's pending state.

Q8. What is the difference between pending and active?

Pending indicates that an interrupt is waiting to be serviced. Active indicates that its handler is currently being executed.

Q9. Which CMSIS function enables an interrupt?

NVIC_EnableIRQ() enables an external interrupt.

Q10. Which function sets interrupt priority?

NVIC_SetPriority() sets the priority of an interrupt or exception supported by the CMSIS implementation.

Q11. Does enabling NVIC automatically enable a peripheral interrupt?

No. The peripheral's interrupt source must also be configured and enabled.

Q12. What is the relationship between IRQ number and exception number?

For external interrupts, exception number equals IRQ number plus 16.

  • NVIC manages external interrupts in Cortex-M processors.
