Lesson 3: Interrupt Priority and Preemption

Understand NVIC priority levels, preemption, nested interrupts, priority grouping, subpriority and interrupt latency in STM32 microcontrollers.

1. Learning Objectives

  • Understand interrupt priority.
  • Learn how NVIC priority values work.
  • Understand preemption and nested interrupts.
  • Differentiate preemption priority and subpriority.
  • Configure interrupt priorities using CMSIS and HAL.
  • Understand interrupt latency and response time.
  • Identify common priority configuration mistakes.

2. What Is Interrupt Priority?

Interrupt priority determines the relative urgency of interrupt requests handled by the processor.

When multiple interrupts are pending, the NVIC uses priority information and processor execution state to determine which eligible interrupt should execute.

Example:

A motor protection fault may need faster handling than a periodic status LED update. The motor fault interrupt can be assigned a higher priority, subject to the application's safety and timing design.

3. NVIC Priority Numbering

In Cortex-M NVIC priority numbering, a lower numerical value represents a higher priority.

Priority Value Relative Priority
0 Highest configurable priority
1 High priority
2 Medium-high priority
3 Medium priority
5 Lower priority
10 Still lower priority
15 Lowest priority in a 4-bit implementation
The number of implemented priority bits varies between Cortex-M implementations and STM32 devices. The 0–15 example assumes four implemented priority bits. Always check the device documentation and CMSIS configuration.

4. What Is Preemption?

Preemption occurs when a higher-priority interrupt interrupts the execution of a lower-priority ISR.

The processor temporarily suspends the lower-priority ISR, executes the higher-priority ISR and then resumes the previously interrupted handler.

Preemption Example


       Main Program
            |
            v
       Low Priority ISR
            |
            v
    High Priority Interrupt
            |
            v
    Suspend Low Priority ISR
            |
            v
       High Priority ISR
            |
            v
     Return to Low Priority ISR
            |
            v
       Resume Main Program
Example:

Suppose a UART receive interrupt has priority 5 and a motor fault interrupt has priority 1. If the motor fault interrupt becomes eligible while the UART ISR is running, it can preempt the UART ISR.

5. What Are Nested Interrupts?

Nested interrupts occur when one interrupt handler is interrupted by another interrupt handler.

On Cortex-M processors, a higher-preemption-priority interrupt can normally preempt a lower-preemption-priority interrupt when both are enabled and eligible.

Nested Interrupt Example


       Main Program
            |
            v
        Timer ISR
            |
            v
       UART Interrupt
            |
            v
         UART ISR
            |
            v
      Return to Timer ISR
            |
            v
       Resume Timer ISR
            |
            v
       Return to Main

Nested interrupt handling allows urgent events to be serviced without waiting for a lower-priority ISR to finish.

Nested interrupts increase stack usage and system complexity. Each nested exception can require additional exception stacking. ISR execution time and stack size must be considered carefully.

6. Preemption Priority and Subpriority

Some Cortex-M NVIC implementations support priority grouping, which divides implemented priority bits into two fields:

  • Preemption priority: Determines whether one interrupt can preempt another.
  • Subpriority: Helps determine which pending interrupt is serviced first when preemption priorities are equal.
Feature Preemption Priority Subpriority
Purpose Controls preemption. Orders pending interrupts within the same preemption level.
Can cause preemption? Yes, when the new interrupt has higher preemption priority. No.
Used for Urgency and nesting. Selection among pending requests.
Subpriority does not cause one ISR to preempt another. If two interrupts have equal preemption priority, one cannot preempt the other merely because its subpriority is higher.

7. Priority Grouping

Priority grouping determines how the implemented priority bits are divided between preemption priority and subpriority.

The exact grouping options depend on the Cortex-M implementation and the priority bits implemented by the STM32 device.

Conceptual Example

Assume four priority bits are implemented. A conceptual grouping could allocate:

Grouping Preemption Bits Subpriority Bits
Example A 4 0
Example B 3 1
Example C 2 2
Example D 1 3
Example E 0 4

These are conceptual allocations. Actual valid configurations must be checked against the selected Cortex-M architecture and STM32 CMSIS implementation.

8. Configuring Priority Using CMSIS

CMSIS provides NVIC_SetPriority() to configure interrupt priority. 

#include "stm32f4xx.h"

void Configure_Interrupts(void)
{
    /* Higher priority: lower numerical value */
    NVIC_SetPriority(TIM2_IRQn, 1);

    /* Lower priority */
    NVIC_SetPriority(USART2_IRQn, 5);

    NVIC_EnableIRQ(TIM2_IRQn);
    NVIC_EnableIRQ(USART2_IRQn);
}

In this example, TIM2 has a higher configurable priority than USART2, assuming the same priority grouping and valid implemented priority values.

The IRQ names and peripheral availability depend on the selected STM32 device. Configure each peripheral interrupt source separately.

9. Configuring Priority Using STM32 HAL

STM32 HAL provides HAL_NVIC_SetPriority() for priority configuration. 

void Configure_NVIC(void)
{
    HAL_NVIC_SetPriority(
        TIM2_IRQn,
        1,
        0
    );

    HAL_NVIC_SetPriority(
        USART2_IRQn,
        5,
        0
    );

    HAL_NVIC_EnableIRQ(TIM2_IRQn);
    HAL_NVIC_EnableIRQ(USART2_IRQn);
}

The first priority argument represents the preemption priority and the second represents the subpriority, as interpreted under the configured priority grouping.

Priority Grouping Example

HAL_NVIC_SetPriorityGrouping(
    NVIC_PRIORITYGROUP_4
);

In STM32 HAL configurations where this grouping means all implemented priority bits are used for preemption priority, there are no subpriority bits.

HAL priority-grouping macros and their mapping must be checked for the particular STM32 HAL and Cortex-M device. Do not assume the same grouping behavior across all STM32 families.

10. Interrupt Latency

Interrupt latency is the time between an interrupt request becoming eligible and the start of its corresponding handler execution.

Factors Affecting Interrupt Latency

  • Processor clock frequency.
  • Current processor execution state.
  • Interrupt masking and disabled states.
  • Higher-priority interrupt activity.
  • Memory wait states and bus activity.
  • Exception entry and stacking overhead.
  • Processor architecture and implementation.
Example:

If a peripheral generates an interrupt while a higher-priority ISR is executing, the new interrupt may have to wait until it becomes eligible for service. This increases its response time.

11. Important Priority Programming Rules

  • Assign higher priority to time-critical events.
  • Keep interrupt service routines short.
  • Avoid unnecessary nested interrupt complexity.
  • Understand the configured priority grouping.
  • Use only implemented priority levels.
  • Consider interrupt masking and critical sections.
  • Account for worst-case response time.
  • Check stack usage when nested interrupts are possible.

Avoid assigning the highest priority to every interrupt. A well-designed priority scheme should reflect actual timing requirements.

12. Common Priority Configuration Errors

Error Possible Consequence
Assuming larger number means higher priority Incorrect interrupt urgency.
Using unsupported priority values Priority may be truncated or not behave as expected.
Misunderstanding priority grouping Unexpected preemption behavior.
Using long ISRs at high priority Lower-priority interrupts may be delayed.
Ignoring nested stack usage Possible stack overflow.
Assuming subpriority causes preemption Incorrect interrupt scheduling assumptions.

13. Placement-Oriented Interview Questions

Q1. What is interrupt priority?

Interrupt priority determines the relative urgency with which interrupt requests are handled.

Q2. Does a lower numerical priority value mean higher priority?

Yes. In the Cortex-M NVIC, lower numerical values represent higher configurable priorities.

Q3. What is preemption?

Preemption occurs when a higher-preemption-priority interrupt suspends a lower-priority ISR.

Q4. What are nested interrupts?

Nested interrupts occur when one ISR is interrupted by another eligible interrupt handler.

Q5. What is subpriority?

Subpriority determines the service order among pending interrupts with the same preemption priority.

Q6. Can subpriority cause preemption?

No. Subpriority does not determine whether one interrupt can preempt another.

Q7. What is priority grouping?

Priority grouping divides implemented NVIC priority bits into preemption priority and subpriority fields.

Q8. What is interrupt latency?

It is the time between an interrupt request becoming eligible and execution of its handler beginning.

Q9. Why should high-priority ISRs be short?

Long high-priority ISRs can delay other interrupts and increase system response time.

Q10. Which function sets interrupt priority in CMSIS?

NVIC_SetPriority() is the standard CMSIS function.

Q11. Which HAL function configures interrupt priority?

HAL_NVIC_SetPriority() configures interrupt priority using the STM32 HAL interface.

Q12. What can happen if too many interrupts are nested?

Stack consumption and execution overhead increase, potentially causing stack overflow or missed timing requirements.

14. Practical Exercises

  1. Explain why priority value 1 is higher than priority value 5.
  2. Configure two interrupts with different priorities.
  3. Demonstrate preemption using timer and UART interrupts.
  4. Explain the difference between preemption priority and subpriority.
  5. Configure a priority grouping in STM32CubeIDE.
  6. Measure interrupt response time using a GPIO pin and oscilloscope or logic analyzer.
  7. Analyze the effect of a long high-priority ISR.
  8. Estimate additional stack requirements for nested interrupts.

15. Lesson Summary

  • NVIC priority controls interrupt urgency.
  • Lower numerical values represent higher priorities.
  • Preemption allows urgent interrupts to interrupt lower-priority ISRs.
  • Nested interrupts involve multiple active exception levels.
  • Priority grouping divides priority bits into two fields.
  • Subpriority orders pending interrupts but does not cause preemption.
  • Interrupt latency affects response time.
  • Nested interrupts require careful stack and timing analysis.
