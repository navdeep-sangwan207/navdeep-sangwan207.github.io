Lesson 1: Interrupts and Polling Comparison

Understand interrupt-driven programming, polling, event handling, processor execution and the differences between polling and interrupts in STM32.

2. What Is an Interrupt?

An interrupt is a signal or event that requests the processor to temporarily suspend its normal program execution and execute a special routine called an Interrupt Service Routine (ISR).

After handling the interrupt, the processor normally resumes the interrupted program.

Why Are Interrupts Used?

  • To respond to external events.
  • To handle peripheral communication.
  • To detect timer events.
  • To process hardware status changes.
  • To avoid continuously checking peripheral flags.
Example:

When a push button connected to an STM32 GPIO pin is pressed, an external interrupt can notify the processor immediately, allowing firmware to respond to the event.

3. What Is Polling?

Polling is a programming technique in which the processor repeatedly checks the status of a device or peripheral to determine whether an event has occurred.

Polling Operation

  1. Processor executes the main program.
  2. Processor checks a peripheral status flag.
  3. If the event has occurred, the processor handles it.
  4. If the event has not occurred, the processor checks again.
  5. The process repeats.

Polling Flow


        Start
          |
          v
      Main Program
          |
          v
     Check Event Flag
          |
          v
       Event Occurred?
          |
       +--+--+
       |     |
      Yes    No
       |     |
       v     |
   Handle    |
    Event    |
       |     |
       +-----+
          |
          v
      Check Again

4. Polling Example Using STM32 HAL

The following example checks a push button repeatedly and turns on an LED while the button is pressed. 

#include "main.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        if (HAL_GPIO_ReadPin(
                GPIOA,
                GPIO_PIN_0) == GPIO_PIN_SET)
        {
            HAL_GPIO_WritePin(
                GPIOB,
                GPIO_PIN_0,
                GPIO_PIN_SET);
        }
        else
        {
            HAL_GPIO_WritePin(
                GPIOB,
                GPIO_PIN_0,
                GPIO_PIN_RESET);
        }
    }
}

In this example, the processor continuously reads the input pin and updates the LED output.

GPIO ports, pin numbers and input polarity are illustrative. Configure the actual pins, clock, electrical connections and GPIO modes for the selected STM32 board.

5. What Is Interrupt-Driven Programming?

Interrupt-driven programming allows the processor to respond to an event through an interrupt mechanism rather than continuously checking the event.

The peripheral or external signal generates an interrupt request. The processor then executes the corresponding ISR when the request is accepted.

Interrupt Execution Sequence

  1. Main program is executing.
  2. An interrupt event occurs.
  3. The peripheral generates an interrupt request.
  4. The interrupt controller evaluates the request.
  5. The processor accepts the interrupt when eligible.
  6. The processor enters the corresponding ISR.
  7. The ISR handles the event.
  8. The processor returns to the interrupted execution.

Interrupt Flow


          Start
            |
            v
       Main Program
            |
            v
     Interrupt Event Occurs
            |
            v
      Interrupt Request
            |
            v
       NVIC Processing
            |
            v
         Execute ISR
            |
            v
      Return from ISR
            |
            v
       Resume Program

6. Interrupt Service Routine (ISR)

An Interrupt Service Routine is a function executed in response to a particular interrupt.

The ISR performs the required event handling and then returns control to the interrupted program.

Example: Timer Interrupt Handler

void TIM2_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim2);
}

The STM32 HAL timer handler processes the timer interrupt and invokes the appropriate callback when the configured event occurs.

HAL Callback Example

volatile uint8_t timer_event = 0;

void HAL_TIM_PeriodElapsedCallback(
    TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        timer_event = 1;
    }
}

The main loop can process the event outside the ISR: 

while (1)
{
    if (timer_event != 0)
    {
        timer_event = 0;

        /* Process timer event here */
    }
}
The timer must be initialized and its interrupt enabled before this callback can execute. The IRQ handler must also call the appropriate HAL handler. A volatile flag ensures the compiler performs the required accesses, but does not make multi-step operations atomic.

7. Polling vs Interrupts

Feature Polling Interrupts
Operation Repeatedly checks device status. Responds to an interrupt request.
Processor usage Can spend time checking for events. Can perform other work between events.
Response Depends on polling interval and execution flow. Depends on interrupt latency and priority.
Implementation Generally simpler. Requires interrupt configuration and ISR design.
Complexity Usually lower. Can be higher due to concurrency and shared state.
CPU overhead Repeated status checks. Interrupt entry, execution and return overhead.
Typical use Simple and predictable status checking. Event-driven peripheral handling.

8. STM32 HAL Interrupt Example – GPIO Button

STM32 HAL provides an interrupt-based GPIO API. The following example illustrates a callback that records a button event.

Step 1: Configure GPIO Interrupt

In STM32CubeMX, configure the selected GPIO pin as an external interrupt input and select the required edge trigger.

Step 2: Enable the Corresponding NVIC Interrupt

Ensure that the appropriate EXTI interrupt is enabled in NVIC.

Step 3: Write the Callback

volatile uint8_t button_pressed = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        button_pressed = 1;
    }
}

Step 4: Process the Event in Main

while (1)
{
    if (button_pressed)
    {
        button_pressed = 0;

        HAL_GPIO_TogglePin(
            GPIOB,
            GPIO_PIN_0);
    }
}
This example assumes the corresponding EXTI IRQ handler calls HAL_GPIO_EXTI_IRQHandler() and that the GPIO pin and NVIC are correctly configured. Use the correct IRQ handler for the selected pin and STM32 family.

9. Advantages of Interrupts

  • Efficient handling of asynchronous events.
  • Reduces the need for continuous status checking.
  • Allows the processor to perform other tasks.
  • Supports responsive peripheral communication.
  • Useful for timers, GPIO, UART, ADC and DMA events.

10. Limitations of Interrupts

  • Requires careful interrupt configuration.
  • ISR execution adds processing overhead.
  • Shared data requires appropriate concurrency handling.
  • Long ISRs can delay other interrupt processing.
  • Incorrect priority configuration can affect responsiveness.
  • Interrupt-related bugs can be difficult to debug.

11. When Should Polling or Interrupts Be Used?

Application Suitable Approach
Checking a status register in a short initialization routine Polling
Detecting a push-button edge Interrupt
Handling periodic timer events Interrupt
Waiting for a peripheral during startup Polling with timeout
UART reception in an event-driven application Interrupt or DMA
Very simple short-duration control loop Polling

The best approach depends on event frequency, response requirements, processor workload and application architecture.

12. Common Interrupt Programming Mistakes

Mistake Consequence
NVIC interrupt not enabled ISR may never execute.
Peripheral interrupt source not enabled No interrupt request reaches the interrupt controller.
Incorrect vector or handler name Expected ISR does not execute.
Long delay inside ISR Other interrupts and main execution may be delayed.
Interrupt flag not cleared or acknowledged Interrupt may repeatedly occur.
Unsafe shared-variable access Race conditions or inconsistent data.
Incorrect edge selection Expected external event is not detected.

13. Placement-Oriented Interview Questions

Q1. What is an interrupt?

An interrupt is an event or signal that requests the processor to execute an ISR.

Q2. What is polling?

Polling is repeatedly checking a peripheral or device status to detect an event.

Q3. What is an ISR?

ISR stands for Interrupt Service Routine. It is the function executed to handle an interrupt.

Q4. What is the main difference between polling and interrupts?

Polling repeatedly checks status, whereas interrupts notify the processor when an event requests attention.

Q5. What is interrupt latency?

Interrupt latency is the time between an interrupt request becoming eligible and the start of its corresponding handler execution.

Q6. Can the processor execute the main program after an ISR?

Yes. After the ISR completes, the processor normally resumes the interrupted execution.

Q7. Why should an ISR be short?

A short ISR reduces interrupt blocking time and helps maintain system responsiveness.

Q8. Can polling be better than interrupts?

Yes. Polling can be simpler and appropriate when checking events frequently or during short, controlled operations.

Q9. What is interrupt-driven programming?

It is a programming approach in which events are handled through interrupt requests rather than continuous status checking.

Q10. Can an interrupt occur while another ISR is executing?

Yes, if the new interrupt is permitted to preempt the currently executing handler according to the processor and NVIC priority rules.

Q11. What is the role of NVIC?

NVIC manages interrupt enable, pending status, priorities and interrupt delivery for supported Cortex-M exceptions and external interrupts.

Q12. Does volatile make a shared variable thread-safe?

No. Volatile controls compiler treatment of accesses. It does not guarantee atomicity or provide complete synchronization.

15. Lesson Summary

  • Interrupts allow event-driven processor execution.
  • Polling repeatedly checks peripheral status.
  • ISR stands for Interrupt Service Routine.
  • NVIC manages interrupt requests and priorities.
  • HAL provides callbacks for many peripheral interrupts.
  • Interrupts can improve responsiveness.
  • ISRs should be short and efficient.
  • Volatile alone does not provide atomicity.
  • Polling remains useful for simple and controlled operations.
