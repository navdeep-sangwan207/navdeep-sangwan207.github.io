2. What Is EXTI?

EXTI stands for External Interrupt/Event Controller. It is a peripheral block in STM32 microcontrollers that detects selected signal transitions and can generate interrupt or event requests.

EXTI can be used to detect external GPIO changes, as well as certain internal peripheral or system events depending on the STM32 family.

Applications of EXTI

  • Push-button press detection.
  • Rotary encoder signal detection.
  • External sensor event detection.
  • Wake-up signal handling.
  • Digital fault and alarm signals.
  • External pulse detection.

3. EXTI Architecture

A GPIO external interrupt path generally includes GPIO configuration, EXTI edge detection, NVIC interrupt handling and processor execution. 


       External Signal

The EXTI controller detects the configured event. If interrupt generation is enabled, it requests service through the corresponding interrupt path.

4. EXTI Lines and GPIO Mapping

On STM32F4 devices, GPIO pins with the same pin number share an EXTI line. For example, PA0, PB0, PC0 and other available port-0 pins can be sources for EXTI line 0.

However, only one GPIO port source can be selected for a given EXTI line at a time.

GPIO Pin EXTI Line
PA0EXTI0
PB1EXTI1
PC2EXTI2
PA3EXTI3
PB4EXTI4
PC5EXTI5
The mapping principle above applies to common STM32F4 devices. Exact GPIO availability, EXTI lines and routing capabilities must be checked for the selected STM32 part and package.

5. Rising Edge and Falling Edge Detection

Rising Edge

A rising edge occurs when a digital signal changes from LOW to HIGH. 


LOW  __________
              |
              |________ HIGH

       Rising Edge

Falling Edge

A falling edge occurs when a digital signal changes from HIGH to LOW. 


HIGH __________
              |
              |________ LOW

       Falling Edge

Both-Edge Detection

Some EXTI configurations allow detection of both rising and falling transitions.

Trigger Signal Transition Typical Use
Rising edge LOW to HIGH Active-high event detection.
Falling edge HIGH to LOW Active-low button press.
Both edges LOW to HIGH and HIGH to LOW Transition or pulse monitoring.

6. Important EXTI Registers

The following register names are used in common STM32F4 EXTI implementations.

Register Function
IMR Interrupt Mask Register.
EMR Event Mask Register.
RTSR Rising Trigger Selection Register.
FTSR Falling Trigger Selection Register.
PR Pending Register.

Register Operation

  • IMR: Enables or masks interrupt requests from EXTI lines.
  • EMR: Enables or masks event requests from EXTI lines.
  • RTSR: Selects rising-edge triggers.
  • FTSR: Selects falling-edge triggers.
  • PR: Records pending EXTI events.
STM32 EXTI register names and pending-bit clearing behavior differ across families. On STM32F4, a pending bit is cleared by writing 1 to that bit. Do not use a read-modify-write operation to clear a pending bit.

7. Configuring EXTI Using STM32CubeMX

  1. Open the STM32CubeIDE project.
  2. Open the device configuration file.
  3. Select the required GPIO pin.
  4. Configure the pin as GPIO_EXTI.
  5. Select rising-edge, falling-edge or both-edge trigger.
  6. Configure the required GPIO pull-up or pull-down.
  7. Open NVIC settings.
  8. Enable the corresponding EXTI interrupt.
  9. Configure the interrupt priority.
  10. Generate the project code.
Select the electrical input mode and edge according to the actual circuit. For example, a button connected between an input pin and ground commonly uses a pull-up and falling-edge detection.

8. GPIO EXTI Programming Using STM32 HAL

Step 1: Configure GPIO

Configure the selected pin as an external interrupt input in STM32CubeMX or through HAL GPIO initialization.

Step 2: Define an Event Flag

#include "main.h"

volatile uint8_t button_event = 0;

Step 3: Write the EXTI Callback

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        button_event = 1;
    }
}

Step 4: Process the Event in Main

int main(void)
{
    HAL_Init();

    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        if (button_event != 0)
        {
            button_event = 0;

            HAL_GPIO_TogglePin(
                GPIOB,
                GPIO_PIN_0
            );
        }
    }
}

The callback records the event. The main loop performs the LED operation outside the ISR context.

The generated EXTI IRQ handler must call HAL_GPIO_EXTI_IRQHandler() with the correct pin mask. GPIO initialization and NVIC configuration must also be correct. The example assumes GPIOB pin 0 is configured as an output.

9. EXTI Interrupt Handler

In STM32 HAL projects, the IRQ handler forwards the interrupt to the HAL GPIO EXTI handler. 

void EXTI0_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0);
}

The HAL handler checks and clears the relevant EXTI pending condition, then invokes the user-defined callback.

For lines that share an IRQ handler, the handler may need to process more than one EXTI line.

IRQ handler names and shared-line groupings are device-specific. Use the startup file and device header to identify the correct handler.

10. Register-Level EXTI Configuration – STM32F4

The following is an illustrative STM32F4 example for configuring PA0 as a rising-edge EXTI input. 

#include "stm32f4xx.h"

void EXTI0_Init(void)
{
    /* Enable GPIOA and SYSCFG clocks */
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    RCC->APB2ENR |= RCC_APB2ENR_SYSCFGEN;

    /* Configure PA0 as input */
    GPIOA->MODER &= ~(3U << (0U * 2U));

    /* Select no pull-up or pull-down */
    GPIOA->PUPDR &= ~(3U << (0U * 2U));

    /* Route PA0 to EXTI0 */
    SYSCFG->EXTICR[0] &= ~(0xFU << 0U);

    /* Enable rising-edge trigger */
    EXTI->RTSR |= (1U << 0U);

    /* Disable falling-edge trigger */
    EXTI->FTSR &= ~(1U << 0U);

    /* Clear any previous pending condition */
    EXTI->PR = (1U << 0U);

    /* Unmask EXTI0 interrupt */
    EXTI->IMR |= (1U << 0U);

    /* Configure and enable NVIC */
    NVIC_SetPriority(EXTI0_IRQn, 2);
    NVIC_EnableIRQ(EXTI0_IRQn);
}

The corresponding interrupt handler: 

volatile uint8_t exti_event = 0;

void EXTI0_IRQHandler(void)
{
    if ((EXTI->PR & (1U << 0U)) != 0U)
    {
        /* Clear pending bit by writing 1 */
        EXTI->PR = (1U << 0U);

        exti_event = 1;
    }
}
This example is specific to the STM32F4 register model. Verify the exact device reference manual, clock configuration and EXTI routing before use. The input also requires a defined electrical level; use an appropriate pull-up, pull-down or external circuit. The event flag is illustrative and does not implement switch debouncing.

11. Push-Button Interfacing

A push button can be connected to a GPIO pin to generate an external interrupt.

Example: Pull-Up Button Connection


          STM32 GPIO Input
                 |
                 |
              [Button]
                 |
                 |
                GND

      Internal or external pull-up
      keeps the input HIGH when released.

With a pull-up arrangement:

  • Button released: input is HIGH.
  • Button pressed: input becomes LOW.
  • Falling edge can detect the press event.
Confirm the board's actual button wiring before selecting the trigger edge. Some development boards use different button circuits.

12. Switch Debouncing

Mechanical switches can generate multiple rapid electrical transitions during a single press or release. This behavior is called switch bounce.

Why Debouncing Is Needed

Without debouncing, a single button press may be interpreted as multiple interrupt events.

Common Debouncing Methods

  • Software time-based filtering.
  • Timer-based debounce checking.
  • State-machine-based button handling.
  • Hardware RC filtering.
  • Dedicated switch debounce circuits.

Recommended Firmware Approach

  1. Detect the initial EXTI event.
  2. Record the event or timestamp.
  3. Perform debounce processing outside the ISR.
  4. Confirm the stable input state.
  5. Generate one logical button event.
Avoid using HAL_Delay() or long blocking operations inside an EXTI ISR. Use a timer or main-loop state machine for debouncing.

14. Placement-Oriented Interview Questions

Q1. What is EXTI?

EXTI is the External Interrupt/Event Controller used to detect selected signal transitions and generate interrupt or event requests.

Q2. What is a rising edge?

A rising edge is a transition from LOW to HIGH.

Q3. What is a falling edge?

A falling edge is a transition from HIGH to LOW.

Q4. What is an EXTI line?

An EXTI line is an interrupt/event input channel associated with a GPIO pin number or another supported event source.

Q5. Can PA0 and PB0 independently use EXTI0 at the same time?

On common STM32F4 devices, only one GPIO port source can be selected for EXTI line 0 at a time.

Q6. What is the role of NVIC in EXTI?

NVIC controls the corresponding interrupt's enable state, priority and delivery to the processor.

Q7. What is switch debouncing?

Debouncing is the process of filtering rapid electrical transitions caused by mechanical switch contacts.

Q8. Why should HAL_Delay() not be used inside an ISR?

A blocking delay can keep the processor in the ISR for too long and delay other processing.

Q9. What does HAL_GPIO_EXTI_Callback() do?

It is a HAL callback invoked when the HAL EXTI handler processes the corresponding GPIO external interrupt.

Q10. How is an EXTI pending flag cleared on STM32F4?

The corresponding pending bit is cleared by writing 1 to that bit in the EXTI pending register.

Q11. What is the difference between EXTI and NVIC?

EXTI detects and manages external event sources, while NVIC manages interrupt requests, priorities and delivery to the Cortex-M processor.

Q12. Can EXTI be used to wake a microcontroller?

Yes, supported EXTI or wake-up sources can be used to wake the processor from certain low-power modes. The available sources depend on the STM32 device and selected low-power mode.

16. Lesson Summary

  • EXTI detects configured external signal transitions and events.
  • Rising edge means LOW to HIGH.
  • Falling edge means HIGH to LOW.
  • GPIO pins are routed to EXTI lines using device-specific mapping.
  • EXTI and NVIC must both be configured for interrupt handling.
  • HAL provides GPIO EXTI handlers and callbacks.
  • STM32F4 pending flags are cleared by writing 1.
  • Mechanical switches require debouncing.
  • ISRs should remain short and non-blocking.
