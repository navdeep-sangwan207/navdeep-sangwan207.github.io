2. What is SPI?

SPI stands for Serial Peripheral Interface. It is a synchronous serial communication protocol commonly used to connect a microcontroller with external peripheral devices.

Typical SPI devices include:

  • Flash memory.
  • SD cards.
  • Display controllers.
  • ADC and DAC devices.
  • Digital sensors.
  • Wireless communication modules.
SPI is commonly faster than I2C and supports simultaneous transmission and reception in its full-duplex configuration.

3. SPI Bus Architecture

          STM32 Microcontroller
             SPI Master
          +----------------+
          |                |
          | MOSI ----------+--------> Slave MOSI
          |                |
          | MISO <---------+--------- Slave MISO
          |                |
          | SCLK ----------+--------> Slave SCLK
          |                |
          | CS   ----------+--------> Slave CS
          +----------------+           |
                                       |
                                +-------------+
                                | SPI Slave   |
                                | Peripheral  |
                                +-------------+

The master generates the clock and controls the slave selection signal. The selected slave communicates with the master using the data lines.

4. SPI Communication Signals

Signal Full Form Function
MOSI Master Out Slave In Transfers data from master to slave.
MISO Master In Slave Out Transfers data from slave to master.
SCLK Serial Clock Provides synchronization clock.
NSS / CS Slave Select / Chip Select Selects the target slave.

Important Characteristics

  • MOSI carries master-to-slave data.
  • MISO carries slave-to-master data.
  • SCLK is normally generated by the master.
  • CS selects the slave for communication.
  • SPI has no universal device-address field like I2C.

5. SPI Master and Slave Operation

Master

  • Generates the serial clock.
  • Selects the target slave using CS/NSS.
  • Controls the communication sequence.
  • Provides data on MOSI.
  • Receives data on MISO.

Slave

  • Responds when selected.
  • Receives data through MOSI.
  • Transmits data through MISO.
  • Uses the master clock for synchronization.
In a typical single-master system, each slave has a separate chip-select signal. Some systems use daisy-chain or other device-specific selection arrangements.

6. SPI Full-Duplex Communication

Full-duplex communication allows data to be transmitted and received simultaneously. 

             SPI MASTER
                 |
       MOSI ------+------> SLAVE
                 |
       MISO <-----+------- SLAVE
                 |
       SCLK ------+------> SLAVE
                 |
       CS   ------+------> SLAVE

       Data transmission and reception
       can occur simultaneously.

When the master sends a bit on MOSI, it can simultaneously receive a bit on MISO.

Example

During an 8-bit transfer, the master transmits eight bits while receiving eight bits at the same time.

7. SPI Half-Duplex and Simplex Modes

Half-Duplex

Data communication takes place in both directions, but not simultaneously. Depending on the peripheral, one data line may be used for both directions.

Simplex

Data flows in only one direction.

Mode Data Direction
Full-Duplex Both directions simultaneously.
Half-Duplex Both directions, one at a time.
Simplex One direction only.

8. SPI Clock Polarity (CPOL)

CPOL stands for Clock Polarity. It defines the idle level of the SPI clock.

CPOL SCLK Idle State
0 LOW
1 HIGH

CPOL = 0

The clock remains LOW when no data transfer is taking place.

CPOL = 1

The clock remains HIGH when no data transfer is taking place.

9. SPI Clock Phase (CPHA)

CPHA stands for Clock Phase. It determines which clock edge is used to sample data.

CPHA Data Sampling
0 First clock edge.
1 Second clock edge.

The other clock edge is generally used for shifting or changing data. Exact signal timing must match the selected device's SPI requirements.

10. Four SPI Communication Modes

CPOL and CPHA together define four common SPI operating modes.

SPI Mode CPOL CPHA Clock Idle Sampling Edge
Mode 0 0 0 LOW Rising
Mode 1 0 1 LOW Falling
Mode 2 1 0 HIGH Falling
Mode 3 1 1 HIGH Rising
Mode 0 is commonly used in many SPI devices, but the correct mode must always be selected from the peripheral datasheet.

11. SPI Data Transmission

SPI transfers data in groups of bits. Eight-bit transfers are common, although many STM32 SPI peripherals support other data frame sizes.

Example: 8-Bit Transfer

Data = 0xA5

Binary:
10100101

Bit Sequence:
D7 D6 D5 D4 D3 D2 D1 D0
 1  0  1  0  0  1  0  1

The most-significant-bit-first or least-significant-bit-first order is selected according to the peripheral configuration and slave requirements.

Important SPI Parameters

  • Clock frequency.
  • Clock polarity.
  • Clock phase.
  • Data frame size.
  • Bit order.
  • Slave-select management.

12. SPI Chip Select (CS)

Chip Select identifies the slave that should participate in a transaction. 

              STM32
          +-------------+
          |             |
          | MOSI -------+------+---- Slave 1
          |             |      |
          | MISO -------+------+---- Slave 2
          |             |      |
          | SCLK -------+------+---- Shared Clock
          |             |
          | CS1 --------+---------- Slave 1 CS
          |             |
          | CS2 --------+---------- Slave 2 CS
          +-------------+
  • Many SPI slaves use active-LOW CS.
  • Only the selected slave should drive the shared MISO line.
  • CS timing requirements vary by device.
  • Some devices require CS to remain active across multiple bytes.
Do not assume every SPI peripheral uses active-LOW chip select or identical CS timing. Check its datasheet.

13. SPI vs I2C – Basic Comparison

Feature SPI I2C
Signal Lines Usually 4 2
Clock Master-generated Master-generated in normal master operation
Addressing Usually separate CS selection Device address
Duplex Full-duplex supported Half-duplex bus transactions
Speed Often higher, device-dependent Standardized speed modes
Pull-Up Resistors Not generally required on standard push-pull signals Required for open-drain SDA and SCL
Wiring More signals for multiple slaves Shared two-wire bus

14. SPI Applications in Embedded Systems

  • External Flash memory interfacing.
  • SD card communication.
  • Display and TFT controller interfacing.
  • High-speed ADC communication.
  • Digital-to-analog converter interfacing.
  • Wireless module communication.
  • Sensor data acquisition.

15. Placement Interview Questions and Answers

Q1. What is SPI?

SPI is a synchronous serial communication protocol used to connect microcontrollers with peripheral devices.

Q2. What are the four main SPI signals?

MOSI, MISO, SCLK and CS/NSS.

Q3. What is MOSI?

Master Out Slave In. It carries data from the master to the slave.

Q4. What is MISO?

Master In Slave Out. It carries data from the slave to the master.

Q5. What is CPOL?

CPOL defines the idle state of the SPI clock.

Q6. What is CPHA?

CPHA determines which clock edge is used to sample incoming data.

Q7. How many SPI modes are there?

Four common modes: Mode 0, Mode 1, Mode 2 and Mode 3.

Q8. What is full-duplex communication?

It allows transmission and reception simultaneously.

Q9. What is the purpose of CS?

It selects the target SPI slave for communication.

Q10. Does SPI use device addressing like I2C?

Standard SPI generally selects devices using chip-select signals rather than an I2C-style address field.

Q11. Why is SPI often faster than I2C?

SPI uses a direct clocked data interface without I2C address and acknowledgement overhead. Actual speed depends on the devices and system design.

Q12. Can multiple slaves share an SPI bus?

Yes. They can share MOSI, MISO and SCLK, usually with a separate CS signal for each slave.

  • SPI is a synchronous serial communication protocol.
  • MOSI and MISO carry data in opposite directions.
  • SCLK provides synchronization.
  • CS selects the target slave.
  • SPI supports full-duplex communication.
