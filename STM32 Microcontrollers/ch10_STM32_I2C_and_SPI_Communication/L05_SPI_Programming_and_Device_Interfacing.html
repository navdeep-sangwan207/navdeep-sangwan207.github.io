2. STM32 SPI Peripheral

STM32 microcontrollers contain SPI peripherals that provide synchronous serial communication with external devices.

Typical SPI Connections

          STM32                         SPI Device
      +-------------+                +-------------+
      |             |                |             |
      | SPI MOSI ---+----------------+--- MOSI     |
      |             |                |             |
      | SPI MISO ---+----------------+--- MISO     |
      |             |                |             |
      | SPI SCK ----+----------------+--- SCK      |
      |             |                |             |
      | GPIO CS ----+----------------+--- CS       |
      |             |                |             |
      | GND --------+----------------+--- GND      |
      +-------------+                +-------------+

The STM32 master generates SCK and controls CS. The slave communicates when selected.

3. SPI Configuration Using STM32CubeMX

  1. Open the STM32CubeIDE project.
  2. Open the device configuration file.
  3. Select an available SPI peripheral, such as SPI1.
  4. Configure the peripheral as Master.
  5. Select Full-Duplex Master mode if required.
  6. Configure the clock prescaler.
  7. Select CPOL and CPHA according to the slave datasheet.
  8. Select the data frame size.
  9. Configure MSB-first or LSB-first bit order.
  10. Configure GPIO alternate functions for SPI signals.
  11. Configure a GPIO output for software-controlled CS.
  12. Generate the initialization code.
SPI pin assignments and alternate functions depend on the STM32 device, package and board. Verify them in the datasheet and reference manual.

4. STM32 SPI HAL Functions

HAL Function Purpose
HAL_SPI_Transmit() Transmit data in blocking mode.
HAL_SPI_Receive() Receive data in blocking mode.
HAL_SPI_TransmitReceive() Transmit and receive simultaneously.
HAL_SPI_Transmit_IT() Transmit using interrupts.
HAL_SPI_Receive_IT() Receive using interrupts.
HAL_SPI_TransmitReceive_IT() Full-duplex transfer using interrupts.
HAL_SPI_Transmit_DMA() Transmit using DMA.
HAL_SPI_Receive_DMA() Receive using DMA.
HAL_SPI_TransmitReceive_DMA() Full-duplex transfer using DMA.

The functions use an SPI handle, such as hspi1, which is normally generated by CubeMX.

5. Software-Controlled Chip Select

Many applications use a normal GPIO output to control the slave's chip-select pin.

Example Macros

#define SPI_CS_LOW()  HAL_GPIO_WritePin( \
    SPI_CS_GPIO_Port, SPI_CS_Pin, GPIO_PIN_RESET)

#define SPI_CS_HIGH() HAL_GPIO_WritePin( \
    SPI_CS_GPIO_Port, SPI_CS_Pin, GPIO_PIN_SET)

For a common active-LOW slave, CS is driven LOW before a transaction and returned HIGH after the transaction.

These macros assume an active-LOW CS pin and CubeMX-generated GPIO definitions. The actual CS polarity and timing must follow the slave device datasheet.

6. SPI Data Transmission

The STM32 can transmit data using HAL_SPI_Transmit(). 

#include "main.h"

extern SPI_HandleTypeDef hspi1;

uint8_t tx_data[] = {
    0xA5,
    0x5A,
    0x12,
    0x34
};

HAL_StatusTypeDef SPI_Send_Data(void)
{
    HAL_StatusTypeDef status;

    SPI_CS_LOW();

    status = HAL_SPI_Transmit(
        &hspi1,
        tx_data,
        sizeof(tx_data),
        1000
    );

    SPI_CS_HIGH();

    return status;
}

Explanation

  • hspi1 identifies the SPI peripheral.
  • tx_data contains the transmitted bytes.
  • sizeof(tx_data) gives the number of data elements for this 8-bit transfer.
  • SPI_CS_LOW() selects the slave.
  • SPI_CS_HIGH() ends the transaction.
For a production driver, ensure CS is returned to its inactive state on every error path and observe the device's required CS setup, hold and inter-transfer timing.

7. SPI Data Reception

The STM32 can receive data using HAL_SPI_Receive(). 

uint8_t rx_data[4];

HAL_StatusTypeDef SPI_Receive_Data(void)
{
    HAL_StatusTypeDef status;

    SPI_CS_LOW();

    status = HAL_SPI_Receive(
        &hspi1,
        rx_data,
        sizeof(rx_data),
        1000
    );

    SPI_CS_HIGH();

    return status;
}

In master mode, the STM32 must generate clock pulses to receive data. The behavior of the HAL receive API in master mode depends on the STM32 SPI peripheral and HAL implementation; it may use transmitted dummy data internally.

Many SPI slaves require a command or register address before sending data. Use the device's specified transaction sequence.

8. Full-Duplex SPI Communication

Full-duplex SPI allows simultaneous data transmission and reception. 

uint8_t tx_buffer[3] = {
    0x9F, 0x00, 0x00
};

uint8_t rx_buffer[3];

HAL_StatusTypeDef SPI_Transfer(void)
{
    HAL_StatusTypeDef status;

    SPI_CS_LOW();

    status = HAL_SPI_TransmitReceive(
        &hspi1,
        tx_buffer,
        rx_buffer,
        sizeof(tx_buffer),
        1000
    );

    SPI_CS_HIGH();

    return status;
}

The STM32 transmits bytes from tx_buffer while simultaneously storing received bytes in rx_buffer.

In this example, 0x9F is only an illustrative command byte. The actual command and response format depend on the selected SPI device.

9. Reading an SPI Device Register

Many SPI peripherals use a command byte or register address followed by data bytes.

Generic Register Read

HAL_StatusTypeDef SPI_Read_Register(
    uint8_t command,
    uint8_t *value)
{
    HAL_StatusTypeDef status;
    uint8_t tx[2];
    uint8_t rx[2];

    if (value == NULL)
    {
        return HAL_ERROR;
    }

    tx[0] = command;
    tx[1] = 0x00;  // Dummy byte

    SPI_CS_LOW();

    status = HAL_SPI_TransmitReceive(
        &hspi1,
        tx,
        rx,
        2,
        1000
    );

    SPI_CS_HIGH();

    if (status == HAL_OK)
    {
        *value = rx[1];
    }

    return status;
}

This is a generic example. Some devices use a read bit in the command, some require a separate address phase, and others require a different number of dummy bytes.

10. Interfacing SPI Flash Memory

SPI Flash memory is commonly used to store firmware data, configuration parameters, logs and other non-volatile information.

Typical Operations

  • Read device identification.
  • Read stored data.
  • Write data to a page.
  • Erase a sector or block.
  • Check the status register.

Typical Read Transaction

CS LOW
   |
Read Command
   |
Address Byte 1
   |
Address Byte 2
   |
Address Byte 3
   |
Receive Data Bytes
   |
CS HIGH
SPI Flash devices commonly have write-enable, page-boundary, erase and busy-status requirements. Never assume that a write command immediately completes or that memory can be overwritten without an erase operation.

11. SPI Interrupt-Based Communication

Interrupt-based SPI communication allows firmware to perform other work while a transfer is in progress.

Transmit Using Interrupt

uint8_t tx_buffer[] = {
    0x10, 0x20, 0x30
};

HAL_SPI_Transmit_IT(
    &hspi1,
    tx_buffer,
    sizeof(tx_buffer)
);

Transmission Complete Callback

void HAL_SPI_TxCpltCallback(
    SPI_HandleTypeDef *hspi)
{
    if (hspi->Instance == SPI1)
    {
        // SPI transmission completed.
    }
}

Full-Duplex Interrupt Transfer

HAL_SPI_TransmitReceive_IT(
    &hspi1,
    tx_buffer,
    rx_buffer,
    sizeof(tx_buffer)
);
Configure the appropriate SPI interrupt and NVIC settings. The IRQ handler must call the corresponding HAL SPI IRQ handler. Buffers must remain valid until the callback occurs.

12. SPI DMA Communication

DMA can transfer SPI data between memory and the peripheral without requiring the CPU to process every data element.

Transmit Using DMA

HAL_SPI_Transmit_DMA(
    &hspi1,
    tx_buffer,
    sizeof(tx_buffer)
);

Full-Duplex DMA Transfer

HAL_SPI_TransmitReceive_DMA(
    &hspi1,
    tx_buffer,
    rx_buffer,
    sizeof(tx_buffer)
);

DMA Completion Callback

void HAL_SPI_TxRxCpltCallback(
    SPI_HandleTypeDef *hspi)
{
    if (hspi->Instance == SPI1)
    {
        // Full-duplex DMA transfer completed.
    }
}
  • DMA is useful for large or repeated transfers.
  • It reduces CPU workload.
  • DMA configuration is device-specific.
  • Buffers must remain valid during the transfer.
  • Cache maintenance may be required on cache-equipped STM32 devices.

13. SPI Communication Troubleshooting

Problem Possible Cause Check
No response from slave CS or wiring problem. Verify CS, SCLK, MOSI, MISO and ground.
Incorrect received data Wrong CPOL or CPHA. Check the slave's SPI mode.
Corrupted data Clock too fast or signal integrity issue. Reduce clock speed and inspect signals.
Transfer timeout Peripheral or configuration problem. Check SPI state, clocks and error flags.
Wrong bit sequence Bit order mismatch. Check MSB-first or LSB-first configuration.
DMA transfer fails Incorrect DMA mapping or setup. Check DMA request, stream/channel and IRQ setup.

14. Placement Interview Questions and Answers

Q1. Which HAL function transmits SPI data?

HAL_SPI_Transmit().

Q2. Which function receives SPI data?

HAL_SPI_Receive().

Q3. Which function performs full-duplex SPI communication?

HAL_SPI_TransmitReceive().

Q4. What is the purpose of chip select?

It selects the target slave for a communication transaction.

Q5. What is the difference between polling and interrupt-based SPI?

Polling waits for transfer completion in the calling code. Interrupt-based communication allows the CPU to execute other work while the transfer progresses.

Q6. What is SPI DMA?

It is a method of transferring SPI data using DMA hardware with reduced CPU involvement.

Q7. Why is the correct SPI mode important?

The master and slave must agree on clock polarity and sampling phase to transfer data correctly.

Q8. Why is CS usually controlled using GPIO?

GPIO control provides flexible timing and allows one SPI peripheral to select multiple external devices.

Q9. What is dummy data in SPI?

It is data transmitted by the master to generate clock pulses when it needs to receive data.

Q10. What is a common SPI debugging tool?

A logic analyzer or oscilloscope can be used to inspect CS, SCLK, MOSI and MISO signals.

16. Lesson Summary

  • STM32 provides hardware SPI peripherals.
  • HAL functions simplify SPI programming.
  • GPIO can control software chip select.
  • SPI supports transmit, receive and full-duplex transfers.
  • Register-based communication is common in sensors and memories.
  • Interrupts and DMA support non-blocking transfers.
  • Correct clock mode, bit order and CS timing are essential.
  • Logic analyzers help debug SPI communication.
