2. I2C Communication in STM32

STM32 microcontrollers provide dedicated I2C peripherals that allow communication with external sensors, memory devices and controllers.

The STM32 can operate as an I2C master or slave. In common embedded applications, STM32 is configured as the master and communicates with one or more peripheral devices.

Typical Connection

       STM32                         I2C Sensor
   +-------------+                +-------------+
   |             |                |             |
   | I2C_SCL ----+----------------+---- SCL      |
   |             |                |             |
   | I2C_SDA ----+----------------+---- SDA      |
   |             |                |             |
   | GND --------+----------------+---- GND      |
   +-------------+                +-------------+

         SDA and SCL require suitable pull-ups
         to a compatible bus voltage.

3. STM32 I2C HAL API

STM32 HAL provides functions for blocking, interrupt-based and DMA-based I2C communication.

Function Purpose
HAL_I2C_Master_Transmit() Transmit data to an I2C slave.
HAL_I2C_Master_Receive() Receive data from an I2C slave.
HAL_I2C_Mem_Write() Write to a slave memory/register address.
HAL_I2C_Mem_Read() Read from a slave memory/register address.
HAL_I2C_IsDeviceReady() Check whether a slave acknowledges its address.

I2C Handle

I2C_HandleTypeDef hi2c1;

The handle identifies the I2C peripheral and contains its configuration and runtime state. CubeMX normally generates the handle and initialization function.

4. Checking Whether a Device Is Connected

Before transferring data, firmware can check whether a device responds to its address. 

#include "main.h"

extern I2C_HandleTypeDef hi2c1;

#define SENSOR_ADDR (0x48U << 1)

HAL_StatusTypeDef Check_I2C_Device(void)
{
    return HAL_I2C_IsDeviceReady(
        &hi2c1,
        SENSOR_ADDR,
        3,
        100
    );
}

Function Parameters

  • &hi2c1: I2C peripheral handle.
  • SENSOR_ADDR: shifted address used by the HAL API.
  • 3: number of trials.
  • 100: timeout in milliseconds.
HAL_OK indicates that the device acknowledged the address. It does not verify the sensor's identity or data correctness.

5. Master Data Transmission

The STM32 master can send one or more bytes to a slave device using HAL_I2C_Master_Transmit(). 

#include "main.h"

extern I2C_HandleTypeDef hi2c1;

#define SENSOR_ADDR (0x48U << 1)

void I2C_Send_Data(void)
{
    uint8_t tx_data[2];

    tx_data[0] = 0x01;
    tx_data[1] = 0x55;

    HAL_StatusTypeDef status;

    status = HAL_I2C_Master_Transmit(
        &hi2c1,
        SENSOR_ADDR,
        tx_data,
        sizeof(tx_data),
        1000
    );

    if (status == HAL_OK)
    {
        // Data transmitted successfully.
    }
    else
    {
        // Handle transmission error.
    }
}

Explanation

  • tx_data stores the bytes to transmit.
  • The first byte may represent a command or register, depending on the slave protocol.
  • The second byte is example data.
  • sizeof(tx_data) gives the number of bytes.
  • The slave must support the exact transaction format.

6. Master Data Reception

The STM32 can receive data from an addressed slave using HAL_I2C_Master_Receive(). 

#include "main.h"

extern I2C_HandleTypeDef hi2c1;

#define SENSOR_ADDR (0x48U << 1)

uint8_t rx_data[2];

HAL_StatusTypeDef I2C_Receive_Data(void)
{
    return HAL_I2C_Master_Receive(
        &hi2c1,
        SENSOR_ADDR,
        rx_data,
        sizeof(rx_data),
        1000
    );
}

This example requests two bytes from the slave. The exact meaning of the returned bytes depends on the connected device's protocol.

A sensor may require a register address or command before returning data. In that case, use the device's specified transaction sequence rather than assuming a direct read will work.

7. Register-Based I2C Communication

Many sensors contain internal registers. The master writes a register address to select the required data or configuration register.

Typical Register Read Sequence

START
  |
Slave Address + Write
  |
Register Address
  |
Repeated START
  |
Slave Address + Read
  |
Receive Data
  |
NACK
  |
STOP

STM32 HAL provides memory read and write functions for common register-based devices.

Reading a Register

#include "main.h"

extern I2C_HandleTypeDef hi2c1;

#define SENSOR_ADDR (0x48U << 1)

uint8_t Read_Sensor_Register(uint8_t reg)
{
    uint8_t data = 0;

    HAL_StatusTypeDef status;

    status = HAL_I2C_Mem_Read(
        &hi2c1,
        SENSOR_ADDR,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        &data,
        1,
        1000
    );

    if (status != HAL_OK)
    {
        return 0;
    }

    return data;
}

Writing a Register

HAL_StatusTypeDef Write_Sensor_Register(
    uint8_t reg,
    uint8_t value)
{
    return HAL_I2C_Mem_Write(
        &hi2c1,
        SENSOR_ADDR,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        &value,
        1,
        1000
    );
}
Returning zero on a read error can be ambiguous because zero may be valid sensor data. Production code should return a HAL status separately and place the received value in an output parameter. Also confirm the sensor's register width and byte order from its datasheet.

8. Improved Register Read with Error Handling

A more robust function separates communication status from the returned sensor value. 

HAL_StatusTypeDef Read_Sensor_Register(
    uint8_t reg,
    uint8_t *value)
{
    if (value == NULL)
    {
        return HAL_ERROR;
    }

    return HAL_I2C_Mem_Read(
        &hi2c1,
        SENSOR_ADDR,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        value,
        1,
        1000
    );
}

Calling the Function

uint8_t sensor_value = 0;

if (Read_Sensor_Register(0x00, &sensor_value) == HAL_OK)
{
    // Use sensor_value.
}
else
{
    // Handle I2C error.
}

This approach avoids confusing a valid zero reading with a communication failure.

9. Practical Example: I2C Temperature Sensor

Consider a temperature sensor that provides a temperature register over I2C.

Block Diagram

       STM32 Microcontroller
       +-------------------+
       |                   |
       | I2C_SCL           |
       | I2C_SDA           |
       |                   |
       +----+---------+----+
            |         |
            |         |
       +----+---------+----+
       | I2C Temperature   |
       | Sensor            |
       |                   |
       | Temperature Reg.  |
       +-------------------+

Example Register Read

#define TEMP_REG 0x00

uint8_t raw_temperature = 0;

void Read_Temperature_Sensor(void)
{
    HAL_StatusTypeDef status;

    status = Read_Sensor_Register(
        TEMP_REG,
        &raw_temperature
    );

    if (status == HAL_OK)
    {
        // Convert raw data according to sensor datasheet.
    }
    else
    {
        // Handle sensor communication error.
    }
}
This is a generic register-read example. Actual temperature sensors may return 12-bit, 16-bit or other formats, sometimes with signed values and fractional resolution. Use the manufacturer's conversion formula.

10. Example: Reading a 16-Bit Sensor Register

Some sensors return a 16-bit value in two bytes. The byte order must be checked in the datasheet. 

uint8_t data[2];

HAL_StatusTypeDef Read_16Bit_Register(uint8_t reg,
                                      uint16_t *result)
{
    HAL_StatusTypeDef status;

    if (result == NULL)
    {
        return HAL_ERROR;
    }

    status = HAL_I2C_Mem_Read(
        &hi2c1,
        SENSOR_ADDR,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        data,
        2,
        1000
    );

    if (status == HAL_OK)
    {
        // Example: Most significant byte first.
        *result = ((uint16_t)data[0] << 8)
                | (uint16_t)data[1];
    }

    return status;
}

This example assumes big-endian register data. If the sensor uses little-endian order, the byte combination must be reversed.

11. Interfacing an I2C EEPROM

EEPROM devices store non-volatile data and commonly use I2C for communication.

Typical Applications

  • Storing device configuration.
  • Saving calibration values.
  • Maintaining user settings.
  • Storing small data records.

EEPROM Write Process

  1. Send the EEPROM device address.
  2. Send the memory address.
  3. Send the data byte or page.
  4. Wait for the internal write cycle.
  5. Check device readiness before the next operation.
EEPROM page size, address width, write-cycle time and page-boundary behavior vary by device. Follow the exact EEPROM datasheet.

12. STM32 I2C Interrupt-Based Communication

Blocking HAL functions wait for communication to complete. Interrupt-based APIs allow the CPU to perform other work while the transfer progresses.

Transmit Using Interrupt

uint8_t tx_buffer[] = {0x01, 0x55};

HAL_I2C_Master_Transmit_IT(
    &hi2c1,
    SENSOR_ADDR,
    tx_buffer,
    sizeof(tx_buffer)
);

Completion Callback

void HAL_I2C_MasterTxCpltCallback(
    I2C_HandleTypeDef *hi2c)
{
    if (hi2c->Instance == I2C1)
    {
        // Transmission completed.
    }
}

Receive Using Interrupt

uint8_t rx_buffer[2];

HAL_I2C_Master_Receive_IT(
    &hi2c1,
    SENSOR_ADDR,
    rx_buffer,
    sizeof(rx_buffer)
);
Interrupt-based transfers require the correct I2C event/error IRQ configuration and HAL IRQ handler forwarding. Buffers must remain valid until completion. Do not start a conflicting transfer on the same handle while it is busy.

13. STM32 I2C DMA Communication

DMA transfers data between memory and the I2C peripheral with reduced CPU involvement.

Transmit Using DMA

uint8_t tx_buffer[] = {0x01, 0x55};

HAL_I2C_Master_Transmit_DMA(
    &hi2c1,
    SENSOR_ADDR,
    tx_buffer,
    sizeof(tx_buffer)
);

Receive Using DMA

uint8_t rx_buffer[4];

HAL_I2C_Master_Receive_DMA(
    &hi2c1,
    SENSOR_ADDR,
    rx_buffer,
    sizeof(rx_buffer)
);
  • DMA is useful for larger or repeated transfers.
  • It reduces CPU involvement during data movement.
  • DMA requests and channel mappings vary by STM32 family.
  • Buffers must remain accessible and valid throughout the transfer.

14. Common I2C Troubleshooting

Problem Possible Cause Recommended Check
HAL_ERROR or NACK Incorrect slave address. Verify the 7-bit address and HAL address format.
HAL_TIMEOUT Bus stuck or timing issue. Check SDA, SCL and clock configuration.
No device response Power or wiring issue. Check supply, ground and connections.
Incorrect data Wrong register or byte order. Read the sensor datasheet.
Intermittent errors Pull-up or signal integrity issue. Inspect waveforms and bus capacitance.
Interrupt never completes IRQ handler or NVIC not configured. Check interrupt setup and callback flow.

15. Placement Interview Questions and Answers

Q1. Which HAL function is used to transmit I2C data?

HAL_I2C_Master_Transmit().

Q2. Which HAL function is used to receive I2C data?

HAL_I2C_Master_Receive().

Q3. What is register-based communication?

It is communication in which the master selects an internal register address before reading or writing device data.

Q4. What is the purpose of HAL_I2C_Mem_Read()?

It reads data from a specified memory or register address of an I2C slave.

Q5. What is the purpose of HAL_I2C_IsDeviceReady()?

It checks whether a slave responds to its address with an acknowledgement.

Q6. What is the difference between blocking and interrupt-based I2C?

Blocking functions wait for completion, while interrupt-based functions allow the CPU to execute other work during a transfer.

Q7. What is the role of DMA in I2C?

DMA transfers data between memory and the peripheral with reduced CPU involvement.

Q8. Why should sensor datasheets be checked?

They specify addresses, register maps, data formats, timing requirements and conversion formulas.

Q9. What causes an I2C NACK?

Common causes include an incorrect address, an unpowered device, wiring faults or a device that is not ready.

Q10. Why is byte order important?

It determines how multiple received bytes are combined into a numerical value.

Q11. Why should an interrupt transfer buffer remain valid?

The HAL continues accessing the buffer after the function returns and until the transfer completes.

Q12. Can STM32 communicate with multiple I2C sensors?

Yes. Multiple devices can share the bus if their addresses do not conflict and the electrical requirements are satisfied.
