2. I2C Protocol Overview

I2C stands for Inter-Integrated Circuit. It is a synchronous, address-based serial communication protocol that uses two main signal lines.

  • SDA: Serial Data.
  • SCL: Serial Clock.
             STM32 MASTER
             +----------+
             |          |
             | SDA      |
             | SCL      |
             +----+-----+
                  |
          +-------+-------+
          |               |
      +---+---+       +---+---+
      |Sensor1|       |Sensor2|
      +-------+       +-------+

       Shared SDA and SCL bus

Important Features

  • Two-wire communication.
  • Device addressing.
  • ACK and NACK support.
  • START and STOP conditions.
  • Open-drain SDA and SCL signals.
  • Multiple devices can share the bus.

3. SPI Protocol Overview

SPI stands for Serial Peripheral Interface. It is a synchronous serial protocol commonly used for fast communication between a microcontroller and peripheral devices.

  • MOSI: Master Out Slave In.
  • MISO: Master In Slave Out.
  • SCLK: Serial Clock.
  • CS: Chip Select.
             STM32 MASTER
             +----------+
             |          |
             | MOSI     |
             | MISO     |
             | SCLK     |
             | CS1      |
             | CS2      |
             +----+-----+
                  |
          +-------+-------+
          |               |
      +---+---+       +---+---+
      |Slave 1|       |Slave 2|
      +-------+       +-------+

Important Features

  • Clock-based synchronous communication.
  • Separate transmit and receive data lines.
  • Full-duplex operation is supported.
  • Slave selection commonly uses CS signals.
  • Clock polarity and phase are configurable.

4. I2C vs SPI Comparison

Feature I2C SPI
Full Form Inter-Integrated Circuit Serial Peripheral Interface
Signal Lines 2 Usually 4
Data Lines SDA MOSI and MISO
Clock Line SCL SCLK
Device Selection Address Usually CS
Communication Half-duplex bus transactions Full-duplex supported
Acknowledgement ACK/NACK No standard ACK mechanism
Electrical Interface Open-drain bus with pull-ups Usually push-pull signals
Multiple Devices Shared addressed bus Usually separate CS signals
Speed Standardized speed modes Often higher, device-dependent
Complexity Address and bus management CS and timing management
Common Applications Sensors, RTC, EEPROM Flash, displays, ADC and DAC
SPI is often selected when high throughput or simultaneous transmit and receive is required. I2C is useful when multiple low-to-moderate-speed peripherals must share only two bus wires.

5. Advantages and Disadvantages

I2C Advantages

  • Uses only two signal lines.
  • Supports addressed multi-device communication.
  • ACK/NACK provides basic transfer feedback.
  • Convenient for many low-speed peripherals.

I2C Disadvantages

  • Pull-up resistors are required.
  • Bus capacitance affects signal rise time.
  • Generally lower throughput than many SPI implementations.
  • Bus faults can affect multiple connected devices.

SPI Advantages

  • High data throughput is possible.
  • Full-duplex communication is supported.
  • Simple hardware transaction structure.
  • Useful for memory and display interfaces.

SPI Disadvantages

  • Requires more signal connections.
  • Usually needs a separate CS for each slave.
  • No standard device addressing or ACK mechanism.
  • Clock mode and CS timing must match the slave.

6. Choosing I2C or SPI

Application Common Choice Reason
Temperature sensor I2C or SPI Depends on sensor interface and performance.
RTC module I2C commonly Simple low-data-rate communication.
External Flash SPI commonly High-throughput memory access.
Display controller SPI commonly Efficient transfer of display data.
Multiple low-speed sensors I2C commonly Shared two-wire bus with device addresses.
High-speed ADC SPI commonly High-speed clocked data transfer.
These are common design choices, not fixed rules. Always check the peripheral interface, data rate, timing, electrical requirements and STM32 support.

7. STM32 Communication Error Handling

Reliable embedded firmware should check the return status of communication functions. A failed transfer should not be treated as valid sensor data.

I2C Error Handling

HAL_StatusTypeDef status;

status = HAL_I2C_Master_Transmit(
    &hi2c1,
    SENSOR_ADDR,
    tx_data,
    sizeof(tx_data),
    1000
);

if (status == HAL_OK)
{
    // Communication successful.
}
else
{
    // Record and handle the error.
}

SPI Error Handling

HAL_StatusTypeDef status;

SPI_CS_LOW();

status = HAL_SPI_Transmit(
    &hspi1,
    tx_data,
    sizeof(tx_data),
    1000
);

SPI_CS_HIGH();

if (status == HAL_OK)
{
    // Communication successful.
}
else
{
    // Record and handle the error.
}

HAL Status Values

Status Meaning
HAL_OK Operation completed successfully.
HAL_ERROR Operation failed.
HAL_BUSY Peripheral or handle is busy.
HAL_TIMEOUT Operation exceeded the timeout.

8. I2C Troubleshooting

Problem Possible Cause Solution
Address NACK Wrong address or device not responding. Check address, power and wiring.
SDA stuck LOW Slave holding the bus or short circuit. Inspect wiring and device state.
SCL stuck LOW Clock stretching or electrical fault. Check the slave and bus lines.
Incorrect data Wrong register or data format. Check the device datasheet.
Timeout Bus stuck or incorrect timing. Inspect waveforms and timing configuration.
Intermittent communication Weak pull-ups or excessive bus capacitance. Check pull-up values and wiring length.

I2C Bus Recovery

If a slave holds SDA LOW, some systems attempt bus recovery by generating SCL pulses and then a STOP condition. This must be done only when the bus is safe to take over.

Bus recovery is device- and system-dependent. Do not blindly toggle SCL while another master is active. Check the slave datasheet and the STM32 reference manual before implementing it.

9. SPI Troubleshooting

Problem Possible Cause Solution
No response Incorrect CS or wiring. Verify all SPI connections.
Incorrect data CPOL/CPHA mismatch. Select the correct SPI mode.
Bit order mismatch Wrong MSB/LSB configuration. Match the slave configuration.
Corrupted data Clock frequency too high. Reduce clock speed and inspect signals.
Transfer never completes Peripheral or interrupt configuration error. Check SPI state and IRQ handling.
Unexpected MISO level Slave not selected or bus contention. Check CS and other connected slaves.

10. Debugging Tools

1. Digital Multimeter

  • Check supply voltage.
  • Check ground connections.
  • Check continuity of signal wires.
  • Identify short circuits.

2. Oscilloscope

  • Observe clock frequency.
  • Inspect signal rise and fall times.
  • Observe noise and ringing.
  • Check timing relationships.

3. Logic Analyzer

  • Decode I2C addresses and data.
  • Identify ACK and NACK conditions.
  • Decode SPI commands and responses.
  • Inspect CS and clock timing.

4. STM32CubeIDE Debugger

  • Set breakpoints.
  • Inspect HAL return values.
  • Watch data buffers.
  • Inspect peripheral registers.
  • Trace error and callback functions.

11. Communication Reliability Best Practices

  1. Read the peripheral datasheet before programming.
  2. Verify supply voltage and logic-level compatibility.
  3. Check pin alternate-function configuration.
  4. Use suitable I2C pull-up resistors.
  5. Start with a conservative communication speed.
  6. Check HAL return values.
  7. Use sensible timeouts.
  8. Keep interrupt callbacks short.
  9. Validate received data before using it.
  10. Implement appropriate error recovery.
  11. Use a logic analyzer when debugging bus transactions.
  12. Test communication under expected operating conditions.

12. Placement Interview Questions and Answers

Q1. What is the main difference between I2C and SPI?

I2C uses a shared two-wire addressed bus, whereas SPI commonly uses separate data lines and chip-select signals for its slaves.

Q2. Which protocol supports full-duplex communication?

SPI supports full-duplex communication.

Q3. Why does I2C require pull-up resistors?

I2C uses open-drain or open-collector signaling. Pull-ups provide the HIGH bus level.

Q4. What is an I2C NACK?

NACK means the receiver did not acknowledge the transferred address or data byte.

Q5. What is SPI CPOL?

It defines the idle state of the SPI clock.

Q6. What is SPI CPHA?

It determines the clock edge used for data sampling.

Q7. How can I2C communication be debugged?

Check supply, wiring, pull-ups, addresses, timing and decoded bus transactions.

Q8. How can SPI communication be debugged?

Inspect CS, SCLK, MOSI and MISO signals, clock mode, bit order and transfer status.

Q9. What is the purpose of a timeout?

It prevents firmware from waiting indefinitely for a communication operation to complete.

Q10. Why is a logic analyzer useful?

It captures digital signal transitions and decodes communication protocol transactions.

Q11. When would you choose SPI over I2C?

When the peripheral requires higher throughput, full-duplex operation or a particular SPI interface.

Q12. When would you choose I2C over SPI?

When multiple addressed peripherals need to share a two-wire bus and the required data rate is supported.
