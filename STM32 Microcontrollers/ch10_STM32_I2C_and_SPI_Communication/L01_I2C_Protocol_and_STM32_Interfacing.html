2. What is I2C?

I2C stands for Inter-Integrated Circuit. It is a synchronous, serial communication protocol used to connect microcontrollers with sensors, displays, EEPROMs, RTCs and other peripheral devices.

I2C uses two main communication lines:

  • SDA: Serial Data Line.
  • SCL: Serial Clock Line.
I2C allows multiple devices to share the same two signal lines. Each addressed device can communicate on the bus according to the protocol.

3. I2C Bus Architecture

             STM32 Microcontroller
              I2C Master Device
              +-------------+
              |             |
              | SDA     SCL |
              +--+-------+--+
                 |       |
        =========+=======+========= I2C Bus
                 |       |
          +------+--+ +--+------+
          | Sensor  | | EEPROM  |
          | Slave 1 | | Slave 2 |
          +---------+ +---------+
                 |       |
          +------+-------+------+
          |      RTC Device      |
          |      Slave 3        |
          +---------------------+

All devices share the SDA and SCL lines. The master initiates communication and selects a slave through its address.

Main Components

  • Master: Initiates and controls bus transactions.
  • Slave: Responds when addressed.
  • SDA: Carries data.
  • SCL: Carries clock pulses.
  • Pull-up resistors: Establish the HIGH bus level.

4. SDA and SCL Signals

Signal Full Form Function
SDA Serial Data Transfers address and data bits.
SCL Serial Clock Provides synchronization for communication.

Important Characteristics

  • I2C is synchronous communication.
  • SDA carries data in both directions.
  • SCL provides clock synchronization.
  • Both lines are normally pulled HIGH.
  • Devices pull the lines LOW to communicate.

5. Open-Drain Output and Pull-Up Resistors

I2C uses open-drain or open-collector signaling. A device can pull a bus line LOW but does not actively drive it HIGH.

Basic Connection

             VDD
              |
          Pull-up R
              |
              +---------- SDA Bus
              |
        +-----+-----+
        |           |
      Master      Slave
      Open-Drain  Open-Drain

             VDD
              |
          Pull-up R
              |
              +---------- SCL Bus
              |
        +-----+-----+
        |           |
      Master      Slave

Why Pull-Up Resistors Are Required

  • They establish the HIGH state when no device pulls the line LOW.
  • They allow multiple devices to share the bus safely.
  • They support wired-AND bus behavior.
  • They affect signal rise time and bus reliability.
Do not assume an internal STM32 pull-up is sufficient for a practical I2C bus. External pull-up values must be selected according to bus capacitance, supply voltage, speed and device electrical limits.

6. I2C Master and Slave

Master Device

  • Initiates communication.
  • Generates the SCL clock in normal master operation.
  • Issues START and STOP conditions.
  • Addresses the target slave.
  • Controls read and write transactions.

Slave Device

  • Responds to its address.
  • Receives data during a write transaction.
  • Transmits data during a read transaction.
  • Provides ACK or NACK responses as appropriate.
I2C supports multi-master operation, although many embedded applications use one master and multiple slave devices.

7. I2C Communication Conditions

START Condition

A START condition occurs when SDA changes from HIGH to LOW while SCL remains HIGH.

STOP Condition

A STOP condition occurs when SDA changes from LOW to HIGH while SCL remains HIGH.

Repeated START

A repeated START allows the master to begin another transaction without first releasing the bus with a STOP condition.

8. I2C Addressing Fundamentals

A master selects a slave using its device address. Many I2C devices use a 7-bit address. Some devices and applications also support 10-bit addressing.

7-Bit Address Format

+-----------------------+-----+
|      7-Bit Address    | R/W |
+-----------------------+-----+
          7 Bits          1 Bit

The R/W bit indicates the transfer direction:

  • 0: Master writes to the slave.
  • 1: Master reads from the slave.
STM32 HAL address parameters are commonly supplied as a 7-bit device address shifted left by one bit for APIs using the address field in the transmitted address-byte position. Verify the exact HAL API and device documentation. Do not confuse the 7-bit address with the full address byte.

9. I2C Speed Modes

Mode Typical Maximum Clock
Standard Mode 100 kbit/s
Fast Mode 400 kbit/s
Fast Mode Plus 1 Mbit/s
High-Speed Mode 3.4 Mbit/s

Not every STM32 I2C peripheral supports every speed mode. The actual achievable speed depends on the MCU, connected devices, bus capacitance, pull-ups and timing configuration.

10. STM32 I2C Peripheral

STM32 microcontrollers contain dedicated I2C peripheral hardware. The peripheral handles bus signaling, addressing, data transfer and protocol-related events.

Typical STM32 I2C Pins

Signal Example Pin
I2C1_SCL PB6 or PB8 on some STM32 devices
I2C1_SDA PB7 or PB9 on some STM32 devices
These are examples, not universal pin assignments. Check the alternate-function table and pinout for the exact STM32 part and package.

11. Configuring I2C Using STM32CubeMX

  1. Open the STM32CubeIDE project.
  2. Open the device configuration.
  3. Select an available I2C peripheral.
  4. Enable the required SCL and SDA pins.
  5. Set the pins to the correct I2C alternate function.
  6. Configure the I2C timing or clock speed.
  7. Configure analog and digital filters where applicable.
  8. Enable interrupts if interrupt-based operation is required.
  9. Generate the initialization code.
  10. Build the project.

The exact configuration fields differ between STM32 families and CubeMX versions.

12. STM32 HAL I2C Functions

HAL Function Purpose
HAL_I2C_Master_Transmit() Transmit data to an addressed slave.
HAL_I2C_Master_Receive() Receive data from an addressed slave.
HAL_I2C_Mem_Write() Write data to a slave memory/register address.
HAL_I2C_Mem_Read() Read data from a slave memory/register address.
HAL_I2C_IsDeviceReady() Check whether a device acknowledges its address.

HAL Handle Example

I2C_HandleTypeDef hi2c1;

The handle stores configuration and state information for the selected I2C peripheral.

13. Basic STM32 I2C Master Transmission

The following example transmits one byte to an addressed I2C slave using the HAL polling API. 

#include "main.h"

extern I2C_HandleTypeDef hi2c1;

#define DEVICE_ADDRESS  (0x48U << 1)

uint8_t tx_data = 0x55;

void I2C_Transmit_Example(void)
{
    HAL_StatusTypeDef status;

    status = HAL_I2C_Master_Transmit(
        &hi2c1,
        DEVICE_ADDRESS,
        &tx_data,
        1,
        1000
    );

    if (status == HAL_OK)
    {
        // Transmission successful.
    }
    else
    {
        // Handle communication failure.
    }
}

Explanation

  • hi2c1 identifies the I2C peripheral handle.
  • DEVICE_ADDRESS represents the 7-bit address shifted for the HAL API.
  • tx_data contains the byte to transmit.
  • 1 is the transfer length in bytes.
  • 1000 is the timeout in milliseconds.
The slave address 0x48 is an example only. Replace it with the address specified by the actual connected device. Successful operation also requires correct I2C timing, pull-ups, wiring and slave protocol.

15. Placement Interview Questions and Answers

Q1. What is I2C?

I2C is a synchronous serial communication protocol that uses SDA and SCL lines to connect multiple devices.

Q2. What are the two I2C communication lines?

SDA carries data and SCL carries the clock signal.

Q3. Why does I2C require pull-up resistors?

I2C uses open-drain signaling. Pull-ups establish the HIGH bus level when devices release the lines.

Q4. What is the difference between a master and a slave?

The master initiates and controls a transaction. The addressed slave responds to the master.

Q5. What is an I2C START condition?

SDA changes from HIGH to LOW while SCL is HIGH.

Q6. What is an I2C STOP condition?

SDA changes from LOW to HIGH while SCL is HIGH.

Q7. How many signal wires are required for I2C?

Two signal wires: SDA and SCL, in addition to the required power and ground connections.

Q8. What is the common I2C addressing format?

Many devices use a 7-bit address, although 10-bit addressing is also defined.

Q9. What is the role of the I2C clock?

SCL synchronizes data transmission between communicating devices.

Q10. Name two STM32 HAL I2C functions.

HAL_I2C_Master_Transmit() and HAL_I2C_Master_Receive().

Q11. Can multiple devices share one I2C bus?

Yes. Multiple devices can share SDA and SCL using their individual addresses, provided the bus electrical and protocol requirements are satisfied.

Q12. What is clock stretching?

Clock stretching is a mechanism in which a device holds SCL LOW to delay the next clock pulse until it is ready.
